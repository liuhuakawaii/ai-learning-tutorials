# 05 状态管理——有状态 Server 的设计与会话管理

> 有些 MCP Server 需要维护状态，比如数据库连接、会话信息等。

## 场景引入

你的 MCP Server 需要连接 PostgreSQL 数据库。每次 tools/call 都新建连接、用完关闭，性能很差。你想用连接池复用连接，但连接池是 Server 级别的状态，怎么在多个 Tool 调用之间共享？更复杂的是，如果用户要执行一个多步事务（BEGIN → INSERT → COMMIT），三次 tools/call 必须用同一个数据库连接——这就是有状态 Server 要解决的问题。

## 二、会话管理

```python
from mcp.server import Server
from mcp.types import TextContent
import uuid

class SessionManager:
    """会话管理器"""
    
    def __init__(self):
        self.sessions = {}
    
    def create_session(self) -> str:
        """创建会话"""
        session_id = str(uuid.uuid4())
        self.sessions[session_id] = {
            "id": session_id,
            "created_at": datetime.now(),
            "data": {}
        }
        return session_id
    
    def get_session(self, session_id: str) -> dict:
        """获取会话"""
        return self.sessions.get(session_id)
    
    def update_session(self, session_id: str, data: dict):
        """更新会话"""
        if session_id in self.sessions:
            self.sessions[session_id]["data"].update(data)

class StatefulServer:
    """有状态 Server"""
    
    def __init__(self):
        self.server = Server("stateful-server")
        self.session_manager = SessionManager()
        self._register_tools()
    
    def _register_tools(self):
        """注册工具"""
        
        @self.server.tool()
        async def create_session() -> list[TextContent]:
            """创建会话"""
            session_id = self.session_manager.create_session()
            return [TextContent(type="text", text=session_id)]
        
        @self.server.tool()
        async def get_session_data(session_id: str) -> list[TextContent]:
            """获取会话数据"""
            session = self.session_manager.get_session(session_id)
            if session:
                return [TextContent(type="text", text=json.dumps(session["data"]))]
            return [TextContent(type="text", text="会话不存在")]
```

## 三、状态持久化

```python
import json

class PersistentStateManager:
    """持久化状态管理"""
    
    def __init__(self, storage_path: str):
        self.storage_path = storage_path
        self.state = self._load()
    
    def _load(self) -> dict:
        """加载状态"""
        try:
            with open(self.storage_path, "r") as f:
                return json.load(f)
        except FileNotFoundError:
            return {}
    
    def _save(self):
        """保存状态"""
        with open(self.storage_path, "w") as f:
            json.dump(self.state, f)
    
    def get(self, key: str) -> any:
        """获取状态"""
        return self.state.get(key)
    
    def set(self, key: str, value: any):
        """设置状态"""
        self.state[key] = value
        self._save()
```

class ConnectionPoolManager:
    """连接池管理"""
    
    def __init__(self):
        self.pools = {}
    
    async def get_pool(self, connection_string: str):
        """获取连接池"""
        if connection_string not in self.pools:
            self.pools[connection_string] = await asyncpg.create_pool(connection_string)
        return self.pools[connection_string]
    
    async def close_all(self):
        """关闭所有连接池"""
        for pool in self.pools.values():
            await pool.close()

## 常见误区

```
误区 1：有状态 Server 不能水平扩展
  把状态存在外部存储（Redis、数据库），Server 本身仍然无状态。
  这样可以水平扩展，每个实例共享同一份状态。

误区 2：会话状态越多越好
  只存储必要的上下文信息。过多的会话状态会占用内存，
  也会让调试变得困难——你不知道某个状态是哪次调用设置的。

误区 3：连接池不需要关闭
  Server shutdown 时必须优雅关闭所有连接池。
  不关闭连接池会导致数据库连接泄漏，最终耗尽连接数。

误区 4：状态持久化就是写文件
  文件持久化适合配置和小型数据，不适合高频更新的状态。
  高频状态用 Redis 或数据库，低频状态用文件。
```

## 工程建议

```
1. 连接池作为 Server 级别共享资源
  在 Server 初始化时创建连接池，所有 Tool 共享。
  不要在每个 Tool 内部创建和销毁连接。

2. 会话用 TTL 自动过期
  设置会话过期时间（如 30 分钟），过期自动清理。
  防止长时间不活跃的会话占用内存。

3. 事务状态用 session_id 关联
  多步事务通过 session_id 关联同一数据库连接。
  在 Tool 的参数中暴露 session_id，让 AI 能跨调用维持事务。

4. Server shutdown 要清理资源
  注册 shutdown hook，按顺序：停止接收新请求 → 等待进行中的请求完成 → 关闭连接池。
  不要直接 kill 进程，那会导致事务未提交、连接未释放。
```
