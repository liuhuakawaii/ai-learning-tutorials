# 03 嵌套调用——Tool 内部调用其他 Tool 的编排模式

> 有时候一个 Tool 需要调用其他 Tool 来完成复杂任务。

## 场景引入

用户对 AI 说"帮我查一下北京的天气，然后把结果发到 Slack 的 #weather 频道"。这需要两个步骤：调用天气 Tool 查询，再调用 Slack Tool 发送消息。如果让 AI 来编排这两个步骤，它需要先等天气结果返回，再构造 Slack 消息，中间还可能出错。你希望有一个"复合 Tool"能直接完成这个链式操作，内部自动调用其他 Tool。

## 一、嵌套调用概念

```
嵌套调用场景：

1. 复合操作
   - 一个操作需要多个步骤
   - 每个步骤可能是一个独立的 Tool

2. 数据转换
   - 获取数据 → 转换数据 → 存储数据
   - 每个步骤是一个 Tool

3. 编排模式
   - 顺序执行
   - 并行执行
   - 条件分支
```

## 二、实现

```python
from mcp.server import Server
from mcp.types import TextContent

server = Server("my-server")

@server.tool()
async def query_and_format(sql: str, format: str = "json") -> list[TextContent]:
    """查询并格式化"""
    
    # 调用查询 Tool
    query_result = await execute_query(sql)
    
    # 调用格式化 Tool
    formatted = await format_data(query_result, format)
    
    return [TextContent(type="text", text=formatted)]

@server.tool()
async def multi_step_operation(data: str) -> list[TextContent]:
    """多步骤操作"""
    
    # 步骤 1：验证
    validation = await validate_data(data)
    if not validation["valid"]:
        return [TextContent(type="text", text=f"验证失败：{validation['errors']}")]
    
    # 步骤 2：处理
    processed = await process_data(data)
    
    # 步骤 3：存储
    stored = await store_data(processed)
    
    return [TextContent(type="text", text=f"处理完成：{stored}")]
```

## 三、Tool 组合

```python
class ToolChain:
    """Tool 链"""
    
    def __init__(self):
        self.steps = []
    
    def add_step(self, tool_name: str, params: dict):
        """添加步骤"""
        self.steps.append({"tool": tool_name, "params": params})
    
    async def execute(self, server) -> list:
        """执行链"""
        results = []
        current_data = None
        
        for step in self.steps:
            # 调用 Tool
            result = await server.call_tool(step["tool"], step["params"])
            current_data = result
            results.append(result)
        
        return results
```

## 四、错误传播

```python
@server.tool()
async def resilient_chain(data: str) -> list[TextContent]:
    """带错误处理的链式调用"""
    
    try:
        # 步骤 1
        step1 = await step_one(data)
        
        # 步骤 2
        step2 = await step_two(step1)
        
        # 步骤 3
        step3 = await step_three(step2)
        
        return [TextContent(type="text", text=step3)]
    
    except Exception as e:
        # 返回部分结果或错误信息
        return [TextContent(type="text", text=f"处理失败：{str(e)}")]
```

## 常见误区

```
误区 1：嵌套调用就是递归调用自己
  嵌套调用是 Tool A 调用 Tool B，不是 Tool A 调用自己。
  递归调用没有终止条件会导致无限循环。

误区 2：嵌套调用的错误不需要特殊处理
  嵌套调用中任何一步失败，都需要决定是继续执行还是回滚。
  不处理错误会导致数据不一致。

误区 3：所有复合操作都应该做成嵌套调用
  如果复合操作的步骤是固定的，直接在一个 Tool 里实现更简单。
  嵌套调用适用于步骤可变、需要动态组合的场景。

误区 4：嵌套调用的权限和外层调用一样
  嵌套调用可能跨越不同的权限域。查询天气是公开操作，发送 Slack 消息需要写权限。
  每一层调用都要独立校验权限。
```

## 工程建议

```
1. 用 ToolChain 模式组织步骤
  把复合操作的步骤抽象为链，每个步骤是一个 Tool 调用。
  链支持顺序执行、条件分支、错误回滚。

2. 中间结果要类型安全
  Tool A 的输出是 Tool B 的输入。用类型系统确保数据格式兼容。
  不要依赖 JSON 字符串传递结构化数据。

3. 设置嵌套深度限制
  防止 A 调用 B、B 调用 C、C 又调用 A 的循环依赖。
  设置最大嵌套深度（如 5 层），超过直接报错。

4. 复合 Tool 的 description 要说明步骤
  "查询天气并发送到 Slack"比"天气 Slack"清晰得多。
  让 AI 知道这个 Tool 内部做了什么，避免重复调用子 Tool。
```

4. 错误传播要妥善处理
