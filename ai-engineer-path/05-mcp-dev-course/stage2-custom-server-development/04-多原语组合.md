# 04 多原语组合——一个 Server 同时提供 Tool + Resource + Prompt

> 实际项目中，一个 MCP Server 通常会同时提供多种原语。

## 场景引入

你已经分别学会了 Tool、Resource、Prompt 的开发。现在要为公司做一个完整的数据库 MCP Server，需要同时提供三种能力：Tool 让 AI 执行查询，Resource 让 AI 浏览表结构，Prompt 让 AI 生成 SQL。问题是，这三种原语怎么组织在一个 Server 里？它们之间怎么协作？比如 Prompt 生成的 SQL 怎么传给 Tool 执行？Resource 返回的表结构怎么注入到 Prompt 里？

---

## 学习目标

- 掌握多原语组合的设计方法
- 理解原语间的协作关系
- 学会实现一个完整的 MCP Server

## 一、组合设计

```python
from mcp.server import Server
from mcp.types import Tool, Resource, Prompt, TextContent, PromptMessage

server = Server("database-server")

# Tool：执行查询
@server.tool()
async def query(sql: str) -> list[TextContent]:
    """执行 SQL 查询"""
    results = await execute_sql(sql)
    return [TextContent(type="text", text=json.dumps(results))]

# Resource：表结构
@server.resource("database://tables")
async def list_tables() -> list[TextContent]:
    """获取表列表"""
    tables = await get_tables()
    return [TextContent(type="text", text=json.dumps(tables))]

# Prompt：查询助手
@server.prompt()
async def query_assistant(table: str, question: str) -> list[PromptMessage]:
    """查询助手 Prompt"""
    schema = await get_table_schema(table)
    return [
        PromptMessage(
            role="user",
            content=TextContent(
                type="text",
                text=f"""表 {table} 的结构：
{json.dumps(schema)}

问题：{question}

请生成 SQL 查询。"""
            )
        )
    ]
```

---

## 二、原语协作

```
原语协作模式：

1. Resource → Tool
   Resource 提供数据描述
   Tool 执行具体操作

2. Prompt → Tool
   Prompt 生成查询
   Tool 执行查询

3. Tool → Resource
   Tool 修改数据
   Resource 提供数据视图
```

## 三、完整 Server 示例

```python
class DatabaseMCPServer:
    """数据库 MCP Server"""
    
    def __init__(self):
        self.server = Server("database-server")
        self._register_tools()
        self._register_resources()
        self._register_prompts()
    
    def _register_tools(self):
        """注册工具"""
        
        @self.server.tool()
        async def query(sql: str) -> list[TextContent]:
            results = await self._execute_sql(sql)
            return [TextContent(type="text", text=json.dumps(results))]
        
        @self.server.tool()
        async def insert(table: str, data: dict) -> list[TextContent]:
            result = await self._insert_data(table, data)
            return [TextContent(type="text", text=json.dumps(result))]
    
    def _register_resources(self):
        """注册资源"""
        
        @self.server.resource("database://tables")
        async def list_tables() -> list[TextContent]:
            tables = await self._get_tables()
            return [TextContent(type="text", text=json.dumps(tables))]
        
        @self.server.resource("database://tables/{table}")
        async def table_schema(table: str) -> list[TextContent]:
            schema = await self._get_schema(table)
            return [TextContent(type="text", text=json.dumps(schema))]
    
    def _register_prompts(self):
        """注册提示"""
        
        @self.server.prompt()
        async def query_helper(table: str, question: str) -> list[PromptMessage]:
            schema = await self._get_schema(table)
            return [
                PromptMessage(
                    role="user",
                    content=TextContent(
                        type="text",
                        text=f"表结构：{json.dumps(schema)}\n\n问题：{question}"
                    )
                )
            ]
```

## 四、Server 组织

```
Server 组织建议：

1. 按领域分组
   - 数据库相关：query, insert, update, delete
   - 文件相关：read, write, list
   - API 相关：get, post, put

2. 命名规范
   - Tool：动词_名词（query_database）
   - Resource：名词复数（tables, files）
   - Prompt：名词_helper（query_helper）

3. 文档
   - 每个原语都要有清晰的描述
   - 参数要说明类型和用途
   - 提供使用示例
```

## 常见误区

```
误区 1：一个 Server 只能提供一种原语
  MCP Server 可以同时提供 Tool、Resource、Prompt，数量不限。
  把相关能力放在同一个 Server 里，比分散到多个 Server 更容易管理。

误区 2：原语之间不需要协作
  原语协作是 MCP 的核心价值。Resource 提供数据描述，Prompt 生成查询，Tool 执行操作。
  设计时要画出原语之间的数据流，明确协作关系。

误区 3：命名可以随意
  Tool 用动词（query、insert），Resource 用名词（tables、schemas），Prompt 用名词_helper（query_helper）。
  一致的命名让 AI 更容易理解每个原语的用途。

误区 4：注册顺序无所谓
  注册顺序可能影响 tools/list 的返回顺序。
  把最常用的 Tool 放在前面，AI 更容易发现和使用。
```

---

## 工程建议

```
1. 按领域组织原语
  数据库相关的 Tool、Resource、Prompt 放在同一个 Server。
  文件操作的放在另一个 Server。按领域划分，职责清晰。

2. 原语之间通过 Server 内部函数协作
  Prompt 生成 SQL 时，直接调用 Server 内部的 get_table_schema 函数获取表结构。
  不要通过 MCP 协议回调自己，那会增加不必要的延迟。

3. 提供完整的使用文档
  在每个原语的 description 中说明与其他原语的关系。
  例如：Prompt 的 description 可以写"生成 SQL 后用 query Tool 执行"。

4. 用类封装 Server 逻辑
  把 Tool、Resource、Prompt 的注册逻辑放在一个类中。
  共享的数据库连接、配置等作为类的属性，避免全局变量。
```

## 小结

1. 一个 Server 可以同时提供 Tool、Resource、Prompt
2. 原语间可以协作完成复杂任务
3. 按领域组织原语，保持命名一致
4. 提供清晰的文档和使用示例
