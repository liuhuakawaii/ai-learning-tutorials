# 04 共享工作空间——Agent 间的文件/数据共享机制

> 多 Agent 协作需要共享数据。工作空间是 Agent 们的"共享文件夹"。

## 场景引入

你的多 Agent 系统中，写作 Agent 生成了一份报告草稿，审核 Agent 需要读取这份草稿并给出修改意见。如果通过消息传递，数据格式可能不统一；如果通过函数调用，又增加了耦合。你需要一个"共享工作空间"，让 Agent 们像共用一个文件夹一样协作。

## 一、工作空间设计

```python
class Workspace:
    """共享工作空间"""
    
    def __init__(self, base_path: str):
        self.base_path = base_path
        os.makedirs(base_path, exist_ok=True)
    
    def write_file(self, path: str, content: str, author: str):
        """写入文件"""
        full_path = os.path.join(self.base_path, path)
        os.makedirs(os.path.dirname(full_path), exist_ok=True)
        
        with open(full_path, "w") as f:
            f.write(content)
        
        # 记录元数据
        self._log_operation("write", path, author)
    
    def read_file(self, path: str) -> str:
        """读取文件"""
        full_path = os.path.join(self.base_path, path)
        with open(full_path, "r") as f:
            return f.read()
    
    def list_files(self, directory: str = "") -> list:
        """列出文件"""
        full_path = os.path.join(self.base_path, directory)
        return os.listdir(full_path)
    
    def _log_operation(self, operation: str, path: str, author: str):
        """记录操作日志"""
        log_entry = {
            "operation": operation,
            "path": path,
            "author": author,
            "timestamp": datetime.now().isoformat()
        }
```

## 二、协作模式

```
协作模式：

1. 文件共享
   - Agent 读写共享文件
   - 简单直接

2. 数据库共享
   - Agent 读写共享数据库
   - 支持结构化数据

3. 消息队列
   - Agent 通过消息传递数据
   - 支持异步协作

4. 对象存储
   - Agent 读写对象存储
   - 适合大文件
```

## 四、LangGraph 中的工作空间

```python
class AgentState(TypedDict):
    workspace: Workspace
    current_file: str
    task: str

def writer_node(state: AgentState) -> AgentState:
    """写入文件"""
    workspace = state["workspace"]
    content = generate_content(state["task"])
    workspace.write_file("output/report.md", content, "writer")
    return {**state, "current_file": "output/report.md"}

def reader_node(state: AgentState) -> AgentState:
    """读取文件"""
    workspace = state["workspace"]
    content = workspace.read_file(state["current_file"])
    return {**state, "content": content}
```

## 常见误区

1. **文件操作没有并发控制**：两个 Agent 同时写入同一个文件，后写入的覆盖了先写入的。需要使用文件锁或乐观锁机制来避免写冲突。
2. **工作空间没有版本控制**：文件被修改后，无法追溯是谁在什么时候改了什么。应该记录每次操作的 author、timestamp 和 diff，支持回滚。
3. **工作空间路径没有隔离**：所有 Agent 共享同一个目录，Agent A 可能意外读取或覆盖 Agent B 的文件。应该为每个 Agent 或任务设置独立的工作目录。

## 工程建议

1. **从单 Agent 开始，按需演进**：先用单 Agent 验证核心逻辑，当遇到上下文瓶颈、能力稀释或需要并行处理时，再拆分为多 Agent。不要为了"看起来高级"而引入多 Agent 架构。
2. **为每个 Agent 定义清晰的职责边界**：每个 Agent 应该有单一、明确的职责（如"只负责搜索""只负责分析"），输入输出格式在设计阶段就确定下来，避免职责重叠和数据格式混乱。
3. **建立可观测性基础设施**：从第一版开始就为每个 Agent 添加结构化日志和追踪机制，记录输入、输出、耗时、错误。多 Agent 系统的调试难度远高于单 Agent，没有日志就是在"盲人摸象"。
4. **在关键决策节点加入人工审批**：涉及高风险操作（删除数据、发送消息、支付）和不可逆操作时，使用 Human-in-the-loop 机制暂停执行，等待人类确认后再继续。
