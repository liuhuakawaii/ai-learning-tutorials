# 05 冲突解决——多个 Agent 给出不同结果时的仲裁策略

> 多个 Agent 对同一问题给出不同答案，怎么办？

## 场景引入

你让三个 Agent 分别分析同一个问题，得到了三个不同的答案：Agent A 说"方案 1 最好"，Agent B 说"方案 2 最好"，Agent C 说"方案 3 最好"。这时候该怎么办？直接取多数票？让更权威的 Agent 做决定？还是用另一个 LLM 来仲裁？冲突解决是多 Agent 系统的核心难题之一。

## 一、冲突类型

```
冲突类型：

1. 事实冲突
   - Agent A 说"产品价格 99 元"
   - Agent B 说"产品价格 199 元"
   - 需要查证事实

2. 观点冲突
   - Agent A 说"方案 A 更好"
   - Agent B 说"方案 B 更好"
   - 需要综合评估

3. 方法冲突
   - Agent A 用方法 1 得出结果
   - Agent B 用方法 2 得出结果
   - 需要对比方法
```

## 二、解决策略

```python
class ConflictResolver:
    """冲突解决器"""
    
    def __init__(self, llm):
        self.llm = llm
    
    def resolve_by_voting(self, results: list) -> dict:
        """投票解决"""
        # 多数投票
        from collections import Counter
        votes = Counter([r["answer"] for r in results])
        winner = votes.most_common(1)[0]
        
        return {
            "answer": winner[0],
            "confidence": winner[1] / len(results),
            "method": "voting"
        }
    
    def resolve_by_weight(self, results: list, weights: dict) -> dict:
        """加权解决"""
        weighted_sum = sum(
            r["score"] * weights.get(r["agent"], 1.0)
            for r in results
        )
        total_weight = sum(weights.get(r["agent"], 1.0) for r in results)
        
        return {
            "answer": weighted_sum / total_weight,
            "method": "weighted"
        }
    
    def resolve_by_llm(self, task: str, results: list) -> dict:
        """LLM 仲裁"""
        results_text = "\n".join([
            f"Agent {r['agent']}: {r['answer']}"
            for r in results
        ])
        
        prompt = f"""多个 Agent 对同一问题给出了不同答案，请仲裁。

问题：{task}

各 Agent 的答案：
{results_text}

请选择最合理的答案，或综合生成一个更好的答案。"""
        
        response = self.llm.invoke(prompt)
        
        return {
            "answer": response.content,
            "method": "llm_arbitration"
        }
```

## 三、一致性检查

```python
class ConsistencyChecker:
    """一致性检查器"""
    
    def check(self, results: list, threshold: float = 0.8) -> dict:
        """检查结果一致性"""
        
        # 计算相似度
        similarities = []
        for i in range(len(results)):
            for j in range(i + 1, len(results)):
                sim = self._calculate_similarity(results[i]["answer"], results[j]["answer"])
                similarities.append(sim)
        
        avg_similarity = sum(similarities) / len(similarities)
        
        return {
            "consistent": avg_similarity >= threshold,
            "similarity": avg_similarity,
            "threshold": threshold
        }
```

## 四、最佳实践

```
冲突解决最佳实践：

1. 识别冲突类型
   - 事实冲突：查证
   - 观点冲突：综合
   - 方法冲突：对比

2. 选择合适的策略
   - 简单问题：投票
   - 复杂问题：LLM 仲裁
   - 专业问题：专家加权

3. 记录解决过程
   - 记录冲突内容
   - 记录解决方法
   - 记录最终结果

4. 持续优化
   - 分析冲突原因
   - 优化 Agent 能力
   - 调整解决策略
```

## 常见误区

1. **所有冲突都用投票解决**：投票适合事实性问题（"产品价格是多少"），但不适合需要推理的复杂问题。对于观点冲突，LLM 仲裁通常比简单投票更合理。
2. **一致性检查阈值设置不当**：阈值太高（如 0.95），大量正常差异被标记为冲突；阈值太低（如 0.5），真正的冲突被忽略。需要根据具体场景调整阈值。
3. **冲突解决后没有记录**：每次冲突的解决过程和结果都应该被记录下来，用于分析冲突模式和优化 Agent 能力。没有记录就无法改进。

---

## 工程建议

1. **从单 Agent 开始，按需演进**：先用单 Agent 验证核心逻辑，当遇到上下文瓶颈、能力稀释或需要并行处理时，再拆分为多 Agent。不要为了"看起来高级"而引入多 Agent 架构。
2. **为每个 Agent 定义清晰的职责边界**：每个 Agent 应该有单一、明确的职责（如"只负责搜索""只负责分析"），输入输出格式在设计阶段就确定下来，避免职责重叠和数据格式混乱。
3. **建立可观测性基础设施**：从第一版开始就为每个 Agent 添加结构化日志和追踪机制，记录输入、输出、耗时、错误。多 Agent 系统的调试难度远高于单 Agent，没有日志就是在"盲人摸象"。
4. **在关键决策节点加入人工审批**：涉及高风险操作（删除数据、发送消息、支付）和不可逆操作时，使用 Human-in-the-loop 机制暂停执行，等待人类确认后再继续。
