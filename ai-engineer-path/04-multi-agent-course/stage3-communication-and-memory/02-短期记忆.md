# 02 短期记忆——会话上下文在 Agent 间的传递策略

> 多 Agent 系统中，上下文如何在 Agent 间流转？

## 场景引入

你的多 Agent 对话系统已经运行了 20 轮，但新加入的"审核 Agent"完全不知道前 20 轮发生了什么。如果把所有对话历史都传给它，Token 消耗会爆炸；如果只传最后几轮，又可能丢失关键上下文。你需要一套短期记忆管理策略来平衡信息量和成本。

## 一、短期记忆设计

```python
class ShortTermMemory:
    """短期记忆"""
    
    def __init__(self, max_messages: int = 50):
        self.messages = []
        self.max_messages = max_messages
    
    def add(self, role: str, content: str, metadata: dict = None):
        """添加消息"""
        self.messages.append({
            "role": role,
            "content": content,
            "metadata": metadata or {},
            "timestamp": datetime.now().isoformat()
        })
        
        # 超过限制时裁剪
        if len(self.messages) > self.max_messages:
            self.messages = self.messages[-self.max_messages:]
    
    def get_context(self, max_tokens: int = 4000) -> str:
        """获取上下文（带 Token 限制）"""
        context = []
        total_tokens = 0
        
        for msg in reversed(self.messages):
            msg_tokens = count_tokens(msg["content"])
            if total_tokens + msg_tokens > max_tokens:
                break
            context.insert(0, msg)
            total_tokens += msg_tokens
        
        return "\n".join([f"{m['role']}: {m['content']}" for m in context])
```

## 二、上下文传递策略

```
上下文传递策略：

1. 全量传递
   - 将所有上下文传递给下一个 Agent
   - 简单，但可能超出 Token 限制

2. 摘要传递
   - 用 LLM 生成上下文摘要
   - 减少 Token 消耗，但可能丢失细节

3. 选择性传递
   - 只传递相关的上下文
   - 需要相关性判断

4. 分层传递
   - 不同 Agent 接收不同详细程度的上下文
   - 平衡信息量和 Token 消耗
```

## 三、上下文压缩

```python
class ContextCompressor:
    """上下文压缩器"""
    
    def __init__(self, llm):
        self.llm = llm
    
    def compress(self, messages: list, max_length: int = 500) -> str:
        """压缩上下文"""
        full_context = "\n".join([f"{m['role']}: {m['content']}" for m in messages])
        
        prompt = f"""请将以下对话历史压缩为简洁的摘要，保留关键信息。

对话历史：
{full_context}

要求：
1. 保留关键决策和结论
2. 去除冗余信息
3. 控制在 {max_length} 字以内

请输出压缩后的摘要。"""
        
        response = self.llm.invoke(prompt)
        return response.content
```

## 四、LangGraph 中的上下文管理

```python
class AgentState(TypedDict):
    messages: Annotated[list, add]  # 消息历史
    context: str  # 压缩后的上下文
    current_agent: str

def compress_context(state: AgentState) -> AgentState:
    """压缩上下文"""
    compressor = ContextCompressor(llm)
    context = compressor.compress(state["messages"])
    return {**state, "context": context}
```

## 常见误区

1. **全量传递上下文导致 Token 爆炸**：把所有历史消息都传给每个 Agent，Token 消耗随对话轮次线性增长。应该根据 Agent 的角色和当前任务，选择性地传递相关上下文。
2. **上下文压缩丢失关键信息**：用 LLM 压缩上下文时，可能把关键的数字、日期、人名压缩掉了。压缩后的摘要需要保留结构化信息（如关键决策、数值数据）。
3. **没有上下文长度监控**：不知道当前上下文已经消耗了多少 Token，直到超出模型限制才报错。应该在上下文管理器中添加 Token 计数和预警机制。

## 工程建议

1. **从单 Agent 开始，按需演进**：先用单 Agent 验证核心逻辑，当遇到上下文瓶颈、能力稀释或需要并行处理时，再拆分为多 Agent。不要为了"看起来高级"而引入多 Agent 架构。
2. **为每个 Agent 定义清晰的职责边界**：每个 Agent 应该有单一、明确的职责（如"只负责搜索""只负责分析"），输入输出格式在设计阶段就确定下来，避免职责重叠和数据格式混乱。
3. **建立可观测性基础设施**：从第一版开始就为每个 Agent 添加结构化日志和追踪机制，记录输入、输出、耗时、错误。多 Agent 系统的调试难度远高于单 Agent，没有日志就是在"盲人摸象"。
4. **在关键决策节点加入人工审批**：涉及高风险操作（删除数据、发送消息、支付）和不可逆操作时，使用 Human-in-the-loop 机制暂停执行，等待人类确认后再继续。
