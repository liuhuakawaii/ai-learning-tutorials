## 一、系统架构

```
内容生成系统架构：

用户输入
    │
    ▼
Supervisor ──→ 研究 Agent ──→ 写作 Agent ──→ 审核 Agent ──→ 人工审批
    │                                                           │
    └───────────────────── 最终输出 ←──────────────────────────┘
```

## 二、核心实现

```python
from langgraph.graph import StateGraph, END
from langgraph.checkpoint.memory import MemorySaver

class ContentGenerationState(TypedDict):
    messages: list
    topic: str
    research: str
    draft: str
    review: str
    approval_status: str
    final_content: str

def research_node(state: ContentGenerationState) -> ContentGenerationState:
    """研究节点"""
    llm = ChatOpenAI(model="gpt-4o")
    response = llm.invoke(f"研究以下主题：{state['topic']}")
    return {**state, "research": response.content}

def writing_node(state: ContentGenerationState) -> ContentGenerationState:
    """写作节点"""
    llm = ChatOpenAI(model="gpt-4o")
    response = llm.invoke(f"根据以下研究撰写内容：{state['research']}")
    return {**state, "draft": response.content}

def review_node(state: ContentGenerationState) -> ContentGenerationState:
    """审核节点"""
    llm = ChatOpenAI(model="gpt-4o")
    response = llm.invoke(f"审核以下内容：{state['draft']}")
    return {**state, "review": response.content}

def approval_node(state: ContentGenerationState) -> ContentGenerationState:
    """审批节点（中断点）"""
    return state

def publish_node(state: ContentGenerationState) -> ContentGenerationState:
    """发布节点"""
    return {**state, "final_content": state["draft"]}

# 构建图
graph = StateGraph(ContentGenerationState)
graph.add_node("research", research_node)
graph.add_node("writing", writing_node)
graph.add_node("review", review_node)
graph.add_node("approval", approval_node)
graph.add_node("publish", publish_node)

graph.set_entry_point("research")
graph.add_edge("research", "writing")
graph.add_edge("writing", "review")
graph.add_edge("review", "approval")
graph.add_conditional_edges("approval", lambda s: "publish" if s["approval_status"] == "approved" else END)
graph.add_edge("publish", END)

# 编译（带中断）
checkpointer = MemorySaver()
app = graph.compile(checkpointer=checkpointer, interrupt_before=["approval"])
```

## 三、运行流程

```python
def main():
    # 提交任务
    config = {"configurable": {"thread_id": "1"}}
    result = app.invoke({"topic": "AI 行业趋势", "approval_status": "pending"}, config)
    
    # 等待审批
    print("等待审批...")
    print(f"审核意见：{result['review']}")
    
    # 人工审批
    approval = input("是否批准？(y/n): ")
    
    if approval == "y":
        app.update_state(config, {"approval_status": "approved"})
        result = app.invoke(None, config)
        print(f"已发布：{result['final_content'][:100]}...")
    else:
        app.update_state(config, {"approval_status": "rejected"})
        print("已拒绝")
```

## 常见误区

1. **审批流设计过于刚性**：所有任务都走同一个审批流程，简单任务和高风险任务的审批体验一样。应该根据风险等级动态调整审批流程——低风险自动通过，高风险多级审批。
2. **反馈回路没有闭环**：收集了反馈但没有用于优化 Agent。反馈应该定期汇总分析，用于调整 Agent 的 Prompt 和决策逻辑。
3. **审批面板和后端没有实时同步**：审批者在面板上点了"批准"，但后端没有立即收到通知，导致任务继续等待。需要使用 WebSocket 或轮询机制实现实时同步。

## 工程建议

1. **从单 Agent 开始，按需演进**：先用单 Agent 验证核心逻辑，当遇到上下文瓶颈、能力稀释或需要并行处理时，再拆分为多 Agent。不要为了"看起来高级"而引入多 Agent 架构。
2. **为每个 Agent 定义清晰的职责边界**：每个 Agent 应该有单一、明确的职责（如"只负责搜索""只负责分析"），输入输出格式在设计阶段就确定下来，避免职责重叠和数据格式混乱。
3. **建立可观测性基础设施**：从第一版开始就为每个 Agent 添加结构化日志和追踪机制，记录输入、输出、耗时、错误。多 Agent 系统的调试难度远高于单 Agent，没有日志就是在"盲人摸象"。
4. **在关键决策节点加入人工审批**：涉及高风险操作（删除数据、发送消息、支付）和不可逆操作时，使用 Human-in-the-loop 机制暂停执行，等待人类确认后再继续。
