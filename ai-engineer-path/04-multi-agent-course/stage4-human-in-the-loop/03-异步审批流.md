# 03 异步审批流——长时间运行任务的人工介入机制

> 有些任务需要运行几小时甚至几天。异步审批让人类可以在任何时候介入。

## 场景引入

你提交了一个多 Agent 任务，系统说"预计运行 2 小时"。你不可能一直盯着屏幕等它完成。你需要系统在需要审批时通知你，你审批后它自动继续——这就是异步审批流的价值。任务在后台运行，人类在需要时介入。

## 一、异步审批架构

```
异步审批架构：

任务提交
    │
    ▼
任务队列 ──→ Agent 执行 ──→ 检查点 ──→ 继续执行
                │              │
                │              ▼
                │         等待审批
                │              │
                │              ▼
                │         人类介入
                │              │
                └──────────────┘
```

## 二、实现

```python
class AsyncTaskManager:
    """异步任务管理器"""
    
    def __init__(self):
        self.tasks = {}
        self.approval_queue = asyncio.Queue()
    
    async def submit_task(self, task: dict) -> str:
        """提交任务"""
        task_id = str(uuid.uuid4())
        self.tasks[task_id] = {
            "id": task_id,
            "task": task,
            "status": "running",
            "checkpoints": [],
            "created_at": datetime.now().isoformat()
        }
        
        # 启动异步执行
        asyncio.create_task(self._execute_task(task_id))
        
        return task_id
    
    async def _execute_task(self, task_id: str):
        """执行任务"""
        task = self.tasks[task_id]
        
        # 执行到检查点
        checkpoint = await self._run_to_checkpoint(task)
        
        if checkpoint["needs_approval"]:
            task["status"] = "waiting_approval"
            await self.approval_queue.put({
                "task_id": task_id,
                "checkpoint": checkpoint
            })
            
            # 等待审批
            approval = await self._wait_for_approval(task_id)
            
            if approval["approved"]:
                task["status"] = "running"
                await self._continue_execution(task_id)
            else:
                task["status"] = "rejected"
        else:
            task["status"] = "completed"
    
    async def approve_task(self, task_id: str, feedback: str = None):
        """批准任务"""
        task = self.tasks[task_id]
        task["approval_result"] = {"approved": True, "feedback": feedback}
        task["status"] = "approved"
    
    async def reject_task(self, task_id: str, reason: str):
        """拒绝任务"""
        task = self.tasks[task_id]
        task["approval_result"] = {"approved": False, "reason": reason}
        task["status"] = "rejected"
```

## 三、检查点设计

```python
class Checkpoint:
    """检查点"""
    
    def __init__(self, name: str, needs_approval: bool = False):
        self.name = name
        self.needs_approval = needs_approval
    
    def should_pause(self, state: dict) -> bool:
        """是否应该暂停"""
        if not self.needs_approval:
            return False
        
        # 检查是否需要人工介入
        if state.get("risk_level") == "high":
            return True
        if state.get("confidence", 1.0) < 0.7:
            return True
        
        return False
```

## 四、通知机制

```python
class ApprovalNotifier:
    """审批通知器"""
    
    def __init__(self):
        self.channels = []
    
    def add_channel(self, channel):
        self.channels.append(channel)
    
    async def notify(self, task_id: str, checkpoint: dict):
        """发送审批通知"""
        message = f"任务 {task_id} 需要审批：{checkpoint['name']}"
        
        for channel in self.channels:
            await channel.send(message)
```

## 常见误区

1. **异步任务没有超时设置**：任务提交后，如果审批者永远不响应，任务就永远挂在"等待审批"状态。需要设置审批超时，超时后自动执行降级策略。
2. **检查点暂停条件过于宽泛**：风险等级为"高"就暂停，但"高风险"的定义太模糊。应该用更具体的条件：如涉及删除操作、涉及金额超过阈值、Agent 置信度低于 0.7 等。
3. **通知渠道没有优先级**：所有审批通知都走同一个渠道（如邮件），紧急审批可能被淹没在邮件堆里。高风险审批应该走即时通讯（如 Slack、钉钉），低风险审批走邮件。

## 工程建议

1. **从单 Agent 开始，按需演进**：先用单 Agent 验证核心逻辑，当遇到上下文瓶颈、能力稀释或需要并行处理时，再拆分为多 Agent。不要为了"看起来高级"而引入多 Agent 架构。
2. **为每个 Agent 定义清晰的职责边界**：每个 Agent 应该有单一、明确的职责（如"只负责搜索""只负责分析"），输入输出格式在设计阶段就确定下来，避免职责重叠和数据格式混乱。
3. **建立可观测性基础设施**：从第一版开始就为每个 Agent 添加结构化日志和追踪机制，记录输入、输出、耗时、错误。多 Agent 系统的调试难度远高于单 Agent，没有日志就是在"盲人摸象"。
4. **在关键决策节点加入人工审批**：涉及高风险操作（删除数据、发送消息、支付）和不可逆操作时，使用 Human-in-the-loop 机制暂停执行，等待人类确认后再继续。
