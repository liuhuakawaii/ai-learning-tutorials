## 场景引入

你的 Agent 在测试环境表现优异，准备灰度上线。财务同事看了 API 账单后问了一个问题："每个用户请求平均花多少钱？"你答不上来。上线第一周，日活 500 人的 Agent 产生了每天 $200 的 API 费用——换算下来每个用户每天 $0.4，一个月就是 $12，远超产品定价的承受范围。同时用户反馈"太慢了"，你一查发现平均响应要 12 秒，其中 8 秒花在了不必要的重复 LLM 调用上。能用不代表好用，成本和延迟是 Agent 能否上线的硬指标。

## 一、Token 消耗追踪

### 1.1 基础追踪

```python
class TokenTracker:
    """Token 消耗追踪器"""
    
    def __init__(self):
        self.records = []
    
    def track(self, operation: str, input_tokens: int, output_tokens: int, model: str):
        """记录 Token 消耗"""
        self.records.append({
            "operation": operation,
            "input_tokens": input_tokens,
            "output_tokens": output_tokens,
            "total_tokens": input_tokens + output_tokens,
            "model": model,
            "timestamp": datetime.now().isoformat()
        })
    
    def get_summary(self) -> dict:
        """获取汇总"""
        if not self.records:
            return {}
        
        total_input = sum(r["input_tokens"] for r in self.records)
        total_output = sum(r["output_tokens"] for r in self.records)
        
        return {
            "total_calls": len(self.records),
            "total_input_tokens": total_input,
            "total_output_tokens": total_output,
            "total_tokens": total_input + total_output,
            "by_operation": self._group_by_operation()
        }
    
    def _group_by_operation(self) -> dict:
        """按操作分组"""
        groups = {}
        for r in self.records:
            op = r["operation"]
            if op not in groups:
                groups[op] = {"count": 0, "tokens": 0}
            groups[op]["count"] += 1
            groups[op]["tokens"] += r["total_tokens"]
        return groups
```

### 1.2 成本计算

```python
# 模型定价（2024）
PRICING = {
    "gpt-4o": {"input": 2.50, "output": 10.00},  # per 1M tokens
    "gpt-4o-mini": {"input": 0.15, "output": 0.60},
    "claude-3-5-sonnet": {"input": 3.00, "output": 15.00},
}

def calculate_cost(model: str, input_tokens: int, output_tokens: int) -> float:
    """计算 API 调用成本"""
    pricing = PRICING.get(model, PRICING["gpt-4o-mini"])
    
    input_cost = input_tokens * pricing["input"] / 1_000_000
    output_cost = output_tokens * pricing["output"] / 1_000_000
    
    return input_cost + output_cost
```

## 二、延迟分析

### 2.1 调用链路追踪

```python
class LatencyTracker:
    """延迟追踪器"""
    
    def __init__(self):
        self.spans = []
    
    def start_span(self, name: str) -> str:
        """开始一个 span"""
        span_id = str(uuid.uuid4())
        self.spans.append({
            "id": span_id,
            "name": name,
            "start_time": time.time(),
            "end_time": None,
            "duration": None
        })
        return span_id
    
    def end_span(self, span_id: str):
        """结束一个 span"""
        for span in self.spans:
            if span["id"] == span_id:
                span["end_time"] = time.time()
                span["duration"] = span["end_time"] - span["start_time"]
                break
    
    def get_summary(self) -> dict:
        """获取延迟汇总"""
        completed = [s for s in self.spans if s["duration"] is not None]
        
        if not completed:
            return {}
        
        total_duration = sum(s["duration"] for s in completed)
        
        return {
            "total_spans": len(completed),
            "total_duration": total_duration,
            "avg_duration": total_duration / len(completed),
            "by_name": self._group_by_name(completed)
        }
    
    def _group_by_name(self, spans: list) -> dict:
        """按名称分组"""
        groups = {}
        for s in spans:
            name = s["name"]
            if name not in groups:
                groups[name] = {"count": 0, "total_duration": 0}
            groups[name]["count"] += 1
            groups[name]["total_duration"] += s["duration"]
        return groups
```

### 3.2 成本预警

```python
class CostAlert:
    """成本预警"""
    
    def __init__(self, daily_limit: float, monthly_limit: float):
        self.daily_limit = daily_limit
        self.monthly_limit = monthly_limit
        self.daily_cost = 0.0
        self.monthly_cost = 0.0
    
    def add_cost(self, cost: float):
        """添加成本"""
        self.daily_cost += cost
        self.monthly_cost += cost
        
        if self.daily_cost > self.daily_limit * 0.8:
            self._send_alert("daily", self.daily_cost, self.daily_limit)
        
        if self.monthly_cost > self.monthly_limit * 0.8:
            self._send_alert("monthly", self.monthly_cost, self.monthly_limit)
    
    def _send_alert(self, period: str, current: float, limit: float):
        """发送预警"""
        print(f"⚠️ {period} 成本预警：${current:.2f} / ${limit:.2f}")
```

## 常见误区

1. **只看总 Token 数，不看输入/输出比例**：输入 Token（Prompt）和输出 Token（生成）的单价差异巨大。一个 Agent 如果 Prompt 设计臃肿导致输入 Token 暴涨，优化 Prompt 比换模型更有效。
2. **把平均延迟当唯一指标**：平均延迟 3 秒看起来不错，但 P99 延迟可能是 15 秒。用户体感由最慢的请求决定，必须关注尾部延迟。
3. **盲目上缓存不评估命中率**：缓存能省钱，但 Agent 的用户查询高度个性化，缓存命中率可能很低。投入精力做缓存但命中率不到 10%，不如把精力放在 Prompt 精简上。
4. **成本优化只在上线前做一次**：模型定价会变、用户行为会变、Agent 功能会迭代。成本监控和优化必须是持续的过程，不是一次性任务。

## 工程建议

1. **按用户请求维度统计成本**：不只看全局总费用，要算到每个请求的平均成本。建立"单次请求成本"指标，设阈值告警——比如单次请求超过 $0.05 就触发预警。
2. **延迟优化优先解决"最长的那一环"**：用链路追踪找到耗时最大的环节（通常是 LLM 调用或外部工具调用），针对性优化。并行化可以互相独立的工具调用，缓存高频重复查询。
3. **模型路由是成本优化的杀手锏**：简单任务用便宜模型（gpt-4o-mini），复杂任务用强模型（gpt-4o）。通过 query 复杂度分类器做自动路由，可以降低 40-60% 的成本而几乎不影响质量。
4. **建立成本看板并设周度 Review**：在 Grafana 或类似工具中展示每日/每周成本趋势、按功能模块的成本分布、单次请求成本的 P50/P95/P99。每周 Review 一次，及时发现异常增长。
