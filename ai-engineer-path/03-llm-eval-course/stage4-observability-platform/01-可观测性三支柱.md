> 看不见就修不了。可观测性是 AI 应用从"能跑"到"能运维"的关键跨越。

- 理解可观测性的三支柱模型

## 一、可观测性三支柱

```
┌─────────────────────────────────────────────────────────────┐
│                    可观测性三支柱                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Logs（日志）                                                │
│  ├── 记录离散事件                                            │
│  ├── 用于调试和审计                                          │
│  └── AI 应用：记录每次 LLM 调用的输入输出                     │
│                                                             │
│  Traces（追踪）                                              │
│  ├── 记录请求的完整链路                                      │
│  ├── 用于性能分析和问题定位                                  │
│  └── AI 应用：追踪从用户输入到最终回答的全链路                │
│                                                             │
│  Metrics（指标）                                             │
│  ├── 聚合的数值数据                                          │
│  ├── 用于监控趋势和告警                                      │
│  └── AI 应用：Token 消耗、延迟、成功率、成本                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 二、AI 应用的可观测性需求

### 2.1 传统应用 vs AI 应用

```
传统 Web 应用：
  请求 → 处理 → 响应
  监控：延迟、错误率、吞吐量

AI 应用：
  请求 → Prompt 构建 → LLM 调用 → 结果解析 → 后处理 → 响应
       → RAG 检索 → 上下文组装
       → 工具调用 → 结果整合
  
  额外需要监控：
  - Token 消耗（成本）
  - 模型幻觉（质量）
  - 检索质量（RAG）
  - 工具调用成功率（Agent）
```

## 三、日志设计

### 3.1 结构化日志

```python
import structlog

logger = structlog.get_logger()

def log_llm_call(
    request_id: str,
    model: str,
    input_tokens: int,
    output_tokens: int,
    latency: float,
    success: bool,
    error: str = None
):
    """记录 LLM 调用日志"""
    logger.info(
        "llm_call",
        request_id=request_id,
        model=model,
        input_tokens=input_tokens,
        output_tokens=output_tokens,
        total_tokens=input_tokens + output_tokens,
        latency=latency,
        success=success,
        error=error
    )
```

## 四、追踪设计

### 4.1 请求链路追踪

```python
from opentelemetry import trace

tracer = trace.get_tracer("ai-app")

def process_user_query(query: str):
    """处理用户查询（带追踪）"""
    with tracer.start_as_current_span("process_query") as span:
        span.set_attribute("user_query", query)
        
        # 1. RAG 检索
        with tracer.start_as_current_span("rag_retrieval"):
            contexts = retrieve_contexts(query)
            span.set_attribute("contexts_count", len(contexts))
        
        # 2. LLM 调用
        with tracer.start_as_current_span("llm_call"):
            answer = call_llm(query, contexts)
            span.set_attribute("model", "gpt-4o")
        
        # 3. 后处理
        with tracer.start_as_current_span("post_processing"):
            result = post_process(answer)
        
        return result
```

## 五、指标收集

### 5.1 Prometheus 指标

```python
from prometheus_client import Counter, Histogram, Gauge

# 请求计数
llm_requests = Counter(
    'llm_requests_total',
    'Total LLM requests',
    ['model', 'status']
)

# 延迟分布
llm_latency = Histogram(
    'llm_latency_seconds',
    'LLM request latency',
    ['model']
)

# Token 消耗
llm_tokens = Counter(
    'llm_tokens_total',
    'Total tokens consumed',
    ['model', 'type']  # type: input/output
)

# 成本
llm_cost = Gauge(
    'llm_cost_dollars',
    'LLM API cost in dollars',
    ['model']
)
```
