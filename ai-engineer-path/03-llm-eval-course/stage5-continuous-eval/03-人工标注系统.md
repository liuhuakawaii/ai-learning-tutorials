# 03 人工标注系统——标注任务管理、标注员一致性、反馈回路

> 自动评估有上限，人工标注是质量的终极保障。

## 场景引入

你的自动评估系统显示 RAG 应用的忠实度分数稳定在 0.85，看起来质量不错。但上线后用户频繁投诉"回答不对"。仔细排查发现，自动评估指标和用户实际体感之间存在巨大差距——自动评估无法捕捉到"回答虽然基于文档但答非所问"这类问题。这时候你需要人工标注系统来弥合自动评估的盲区，建立真正的质量反馈回路。

## 学习目标

## 一、标注系统设计

### 1.1 标注任务管理

```python
class AnnotationTask:
    """标注任务"""
    
    def __init__(self, task_id: str, data: dict):
        self.task_id = task_id
        self.data = data
        self.annotations = []
        self.status = "pending"  # pending / in_progress / completed
    
    def add_annotation(self, annotator_id: str, labels: dict):
        """添加标注"""
        self.annotations.append({
            "annotator_id": annotator_id,
            "labels": labels,
            "timestamp": datetime.now().isoformat()
        })
    
    def get_consensus(self) -> dict:
        """获取共识标注"""
        if not self.annotations:
            return None
        
        # 多数投票
        label_counts = {}
        for ann in self.annotations:
            for label, value in ann["labels"].items():
                if label not in label_counts:
                    label_counts[label] = {}
                label_counts[label][value] = label_counts[label].get(value, 0) + 1
        
        consensus = {}
        for label, counts in label_counts.items():
            consensus[label] = max(counts, key=counts.get)
        
        return consensus

class AnnotationManager:
    """标注管理器"""
    
    def __init__(self):
        self.tasks = {}
        self.annotators = {}
    
    def create_batch(self, items: list[dict], annotators_per_item: int = 2):
        """创建标注批次"""
        for i, item in enumerate(items):
            task_id = f"task_{i}"
            self.tasks[task_id] = AnnotationTask(task_id, item)
    
    def assign_tasks(self, annotator_id: str, count: int):
        """分配任务给标注员"""
        pending = [t for t in self.tasks.values() if t.status == "pending"]
        assigned = pending[:count]
        
        for task in assigned:
            task.status = "in_progress"
            # 记录分配
        
        return [t.task_id for t in assigned]
```

## 二、标注一致性

### 2.1 Cohen's Kappa

```python
def calculate_cohens_kappa(annotations_a: list, annotations_b: list) -> float:
    """计算 Cohen's Kappa 系数"""
    
    # 计算一致率
    agreements = sum(1 for a, b in zip(annotations_a, annotations_b) if a == b)
    po = agreements / len(annotations_a)
    
    # 计算期望一致率
    unique_labels = set(annotations_a + annotations_b)
    pe = 0
    for label in unique_labels:
        pa = annotations_a.count(label) / len(annotations_a)
        pb = annotations_b.count(label) / len(annotations_b)
        pe += pa * pb
    
    # 计算 Kappa
    kappa = (po - pe) / (1 - pe) if pe < 1 else 1.0
    
    return kappa

# Kappa 解读：
# < 0.2: 极差
# 0.2-0.4: 差
# 0.4-0.6: 中等
# 0.6-0.8: 良好
# > 0.8: 优秀
```

## 常见误区

1. **标注指南写得太笼统**：只告诉标注员"判断回答质量好不好"，不同人理解完全不同。标注指南必须有明确的评分标准、边界案例示例和判断流程，否则标注一致性极低。

2. **不计算标注一致性就直接用数据**：两个标注员对同一批数据的判断差异很大，说明标注标准有问题。必须先用 Cohen's Kappa 等指标检验一致性，达标后再大规模标注。

3. **把人工标注当成一次性任务**：标注不是做一次就完了。模型迭代后评估标准可能变化，标注数据也需要更新。建立持续的标注-反馈-迭代机制才是关键。

4. **标注员选择不当导致数据偏差**：让不了解业务领域的标注员标注专业问答，会导致大量误判。标注员的专业背景必须与标注任务匹配。

## 工程建议

1. **标注指南要配具体示例**：每个评分等级至少配 3 个边界案例示例，让标注员对"3 分和 4 分的区别"有统一理解。示例比文字描述有效得多。

2. **用"金标准"数据集校准标注员**：在正式标注前，先用已知正确答案的金标准数据测试标注员，Kappa 达标后再开放正式标注任务。这能及早发现理解偏差。

3. **反馈回路要与评估系统打通**：将人工标注结果自动写入评估系统的数据库，让人工标注的发现能直接用于更新自动评估的校准阈值，形成人机协同的质量保障体系。

4. **标注任务优先级与业务影响挂钩**：不要均匀标注所有用例，优先标注用户投诉多、评估分数低、业务影响大的用例，让有限的标注资源产生最大价值。
