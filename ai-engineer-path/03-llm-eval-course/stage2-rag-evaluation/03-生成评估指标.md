# 03 生成评估指标——Faithfulness / Answer Relevancy / Hallucination 检测

> 检索找到了正确的文档，但模型可能"视而不见"或"自由发挥"。生成质量评估就是抓这些问题。

## 场景引入

你的 RAG 系统检索到了正确的政策文档，但用户问"年假有几天"时，模型回答"年假为 10 天"，而文档里写的是"入职满一年后年假为 10 天"。模型省略了前提条件，生成了一个看似正确但实际不完整的回答。这类问题无法通过检索指标发现，必须在生成阶段单独评估忠实度和幻觉。

## 学习目标

- 深入理解三种生成评估指标的计算方法
- 掌握用 LLM-as-Judge 评估生成质量的技巧
- 学会设计高质量的评估 Prompt

## 一、Faithfulness（忠实度）

### 1.1 声明拆解法

```python
def extract_claims(answer: str, client) -> list[str]:
    """将回答拆解为独立的声明"""
    prompt = f"""请将以下回答拆解为独立的事实声明。

回答：{answer}

要求：
1. 每个声明应该是独立的、可验证的事实
2. 不要拆解主观判断或连接词
3. 保持声明的原始含义

请以 JSON 格式输出：
{{"claims": ["声明1", "声明2", ...]}}"""

    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        temperature=0,
        response_format={"type": "json_object"}
    )
    
    return json.loads(response.choices[0].message.content)["claims"]

def verify_claims(claims: list[str], contexts: list[str], client) -> dict:
    """验证每个声明是否有上下文支持"""
    context_text = "\n".join(contexts)
    
    prompt = f"""请检查以下声明是否能在参考资料中找到依据。

参考资料：
{context_text}

声明列表：
{json.dumps(claims, ensure_ascii=False)}

对每个声明，判断：
- "supported"：能在参考资料中找到直接依据
- "unsupported"：参考资料中没有相关信息
- "contradicted"：与参考资料矛盾

请以 JSON 格式输出：
{{"results": [{{"claim": "声明", "status": "supported/unsupported/contradicted", "evidence": "依据"}}]}}"""

    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        temperature=0,
        response_format={"type": "json_object"}
    )
    
    return json.loads(response.choices[0].message.content)

def compute_faithfulness(answer: str, contexts: list[str], client) -> dict:
    """计算忠实度"""
    claims = extract_claims(answer, client)
    verification = verify_claims(claims, contexts, client)
    
    supported = sum(1 for r in verification["results"] if r["status"] == "supported")
    total = len(verification["results"])
    
    return {
        "faithfulness_score": supported / total if total > 0 else 1.0,
        "total_claims": total,
        "supported": supported,
        "unsupported": total - supported,
        "details": verification["results"]
    }
```

## 二、Answer Relevancy（回答相关性）

### 2.1 反向问题生成法

```python
def answer_relevancy_by_regeneration(question: str, answer: str, client) -> dict:
    """通过反向生成问题评估相关性"""
    
    # 步骤 1：从回答中生成可能的问题
    prompt_gen = f"""根据以下回答，推测用户可能问了什么问题。

回答：{answer}

请生成 3 个最可能的问题。"""

    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt_gen}],
        temperature=0,
        response_format={"type": "json_object"}
    )
    generated_questions = json.loads(response.choices[0].message.content)["questions"]
    
    # 步骤 2：计算生成问题与原始问题的相似度
    prompt_sim = f"""请计算以下两个问题的语义相似度（0-1）。

问题 1：{question}
问题 2：{generated_questions[0]}

请只输出数字。"""

    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt_sim}],
        temperature=0
    )
    similarity = float(response.choices[0].message.content.strip())
    
    return {
        "relevancy_score": similarity,
        "generated_questions": generated_questions,
        "original_question": question
    }
```

```python
{{
  "hallucination_score": <0-1, 0=无幻觉, 1=全是幻觉>,
  "hallucinated_facts": ["幻觉1", "幻觉2"],

    response = client.chat.completions.create(
```

## 四、综合评估框架

### 4.1 RAG 生成评估器

```python
class RAGGenerationEvaluator:
    """RAG 生成质量综合评估器"""
    
    def __init__(self, client):
        self.client = client
    
    def evaluate(
        self,
        question: str,
        answer: str,
        contexts: list[str]
    ) -> dict:
        """综合评估生成质量"""
        
        results = {
            "question": question,
            "answer": answer,
            "faithfulness": {},
            "relevancy": {},
            "hallucination": {},
            "overall_score": 0.0
        }
        
        # 1. 忠实度评估
        results["faithfulness"] = compute_faithfulness(answer, contexts, self.client)
        
        # 2. 相关性评估
        results["relevancy"] = direct_answer_relevancy(question, answer, self.client)
        
        # 3. 幻觉检测
        results["hallucination"] = detect_hallucination(contexts, answer, self.client)
        
        # 4. 综合评分
        faith_score = results["faithfulness"]["faithfulness_score"]
        relev_score = results["relevancy"]["score"]
        halluc_score = 1 - results["hallucination"]["hallucination_score"]
        
        results["overall_score"] = (
            faith_score * 0.4 +
            relev_score * 0.3 +
            halluc_score * 0.3
        )
        
        return results
    
    def batch_evaluate(self, dataset: list[dict]) -> list[dict]:
        """批量评估"""
        results = []
        for i, item in enumerate(dataset):
            print(f"评估 {i+1}/{len(dataset)}: {item['question'][:30]}...")
            result = self.evaluate(
                question=item["question"],
                answer=item["answer"],
                contexts=item.get("contexts", [])
            )
            results.append(result)
        return results
```

## 五、评估结果分析

### 5.1 问题诊断

```
生成质量问题诊断：

问题 1：Faithfulness 低
  现象：回答不忠实于上下文
  原因：
    - Prompt 没有强调"基于参考资料回答"
    - 模型倾向于"自由发挥"
    - 上下文信息不够明确
  优化：
    - 在 Prompt 中明确要求"只使用参考资料中的信息"
    - 增加上下文的详细程度
    - 使用更强的模型

问题 2：Relevancy 低
  现象：回答不切题
  原因：
    - 模型没有理解问题的核心
    - 回答包含了过多无关信息
  优化：
    - 优化 Prompt，明确问题要求
    - 添加"如果没有相关信息，请说明"

问题 3：Hallucination 高
  现象：回答包含编造信息
  原因：
    - 模型倾向于补充"看起来合理"的信息
    - 上下文信息不足，模型"填补空白"
  优化：
    - 强调"不要编造信息"
    - 提供更充分的上下文
    - 使用幻觉检测作为后处理
```

## 常见误区

1. **把忠实度等同于正确性**：Faithfulness 只检查回答是否基于上下文，不检查上下文本身是否正确。如果检索到了错误文档，高忠实度也可能输出错误答案。

2. **幻觉检测只看"有没有编造"，不看类型**：完全编造（fabrication）和轻微夸大（exaggeration）的严重程度完全不同，不能用同一个分数衡量。

3. **评估 Prompt 设计得太模糊**：让 LLM 判断"回答好不好"这种模糊指令，评估结果一致性很差。必须给出明确的评分标准和示例。

4. **忽略评估模型本身的偏差**：GPT-4o 倾向于给偏长的回答更高分，也倾向于认为"措辞专业"的回答更忠实。需要用多模型交叉验证。

## 工程建议

1. **声明拆解要控制粒度**：拆得太细会增加评估成本，拆得太粗会漏检。建议每个回答拆成 3-8 个声明。

2. **设计评估 Prompt 时加入 few-shot 示例**：给评估模型 2-3 个标注好的示例，能显著提升评分一致性。

3. **对幻觉类型做加权评分**：fabrication 和 contradiction 权重设为 1.0，exaggeration 设为 0.5，interpolation 设为 0.3。

4. **建立评估结果的置信度机制**：当三个指标之间存在矛盾时（如忠实度高但幻觉也高），标记为"需要人工复核"。

## 小结

```
本课核心要点：

1. Faithfulness 用声明拆解法：拆解 → 验证 → 计算比例
2. Answer Relevancy 用反向问题生成法或直接评估法
3. Hallucination 检测基于上下文对比
4. 三种指标综合使用，加权计算总分
5. 低分指标指向具体的优化方向
```
