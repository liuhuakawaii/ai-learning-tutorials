# 04 模型合并——LoRA 权重与基础模型的合并导出

> 训练完成后，需要将 LoRA 权重合并到基础模型中。

## 场景引入

微调训练完成了，output 目录里有一堆 checkpoint 文件。你想用这个微调模型做推理，但加载时发现必须同时加载基座模型和 LoRA 权重，推理速度比原始模型慢了 20%。更麻烦的是，很多部署工具（如 Ollama、llama.cpp）根本不支持直接加载 LoRA 权重。你需要把 LoRA 权重合并到基础模型中，导出一个独立的、可以直接部署的模型文件。

---

## 学习目标

- 掌握 LoRA 权重的合并方法

## 一、模型合并

```python
from peft import PeftModel
from transformers import AutoModelForCausalLM

# 加载基础模型
base_model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-7B",
    torch_dtype=torch.float16
)

# 加载 LoRA 权重
model = PeftModel.from_pretrained(
    base_model,
    "./output/checkpoint-1000"
)

# 合并权重
merged_model = model.merge_and_unload()

# 保存合并后的模型
merged_model.save_pretrained("./merged_model")
```

## 二、模型导出格式

```
导出格式：

1. HuggingFace 格式
   - 最常用
   - 支持 Transformers
   - 目录结构：
     ├── config.json
     ├── pytorch_model.bin
     ├── tokenizer.json
     └── tokenizer_config.json

2. GGUF 格式
   - 用于 llama.cpp
   - 支持量化
   - 单文件

3. ONNX 格式
   - 跨平台
   - 推理优化
   - 需要转换
```

## 三、GGUF 导出

```bash
# 转换为 GGUF
python convert_hf_to_gguf.py ./merged_model --outfile model.gguf

# 量化
./llama-quantize model.gguf model-q4_k_m.gguf Q4_K_M
```

## 四、模型测试

```python
from transformers import AutoModelForCausalLM, AutoTokenizer

# 加载合并后的模型
model = AutoModelForCausalLM.from_pretrained("./merged_model")
tokenizer = AutoTokenizer.from_pretrained("./merged_model")

# 测试
input_text = "什么是高血压？"
inputs = tokenizer(input_text, return_tensors="pt")
outputs = model.generate(**inputs, max_length=200)
print(tokenizer.decode(outputs[0]))
```

## 常见误区

1. **合并后不做推理测试**：合并操作可能因为精度问题导致模型输出异常。合并后必须用相同的测试用例验证效果，确保和合并前一致。

2. **直接用合并前的 tokenizer**：合并后的模型目录应该包含完整的 tokenizer 文件。如果 tokenizer 和模型不匹配，推理时会输出乱码。

3. **保留太多 checkpoint 浪费磁盘**：checkpoint 文件每个都有几 GB，保留太多会占满磁盘。用 `save_total_limit=2` 只保留最近的 2 个 checkpoint。

4. **合并时精度不匹配**：基座模型用 float16 加载，但 LoRA 权重是 float32 训练的，合并时可能出现精度问题。统一用 float16 加载和合并。

---

## 工程建议

1. **合并是部署的必经步骤**：无论是用 vLLM、Ollama 还是其他部署工具，都应该先合并 LoRA 权重。合并后的模型推理无额外开销，兼容性最好。

2. **合并后做量化测试**：合并后的模型如果需要量化部署（GGUF/GPTQ/AWQ），先量化再测试效果，确认量化后质量可接受。

3. **保留 LoRA 权重作为备份**：合并后不要删除 LoRA 权重文件。如果需要重新合并（如换了基座模型版本），LoRA 权重是必需的。

4. **模型版本管理用语义化版本号**：`v1.0.0`（初始版本）、`v1.1.0`（数据更新）、`v1.1.1`（bug 修复），让团队成员一目了然地知道模型的变化。
