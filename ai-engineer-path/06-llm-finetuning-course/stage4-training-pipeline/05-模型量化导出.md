# 05 模型量化导出——将微调模型导出为 GGUF / GPTQ 格式

> 量化让模型更小、更快，适合部署到资源受限的环境。

## 场景引入

你的微调模型合并后有 14GB（FP16），要在边缘服务器上部署，但这台服务器只有 8GB 内存，没有 GPU。直接部署肯定不行。你需要把模型量化压缩到 4GB 以下，同时尽量保持质量不下降。GGUF、GPTQ、AWQ 这么多量化格式，哪个适合你的场景？量化级别 Q4_K_M 和 Q8_0 的差距到底有多大？

---

## 学习目标

- 掌握模型量化的方法和工具
- 理解不同量化格式的特点
- 学会导出量化模型

## 一、量化方法

```
量化方法：

1. GGUF
   - 用于 llama.cpp
   - 支持多种量化级别
   - 单文件格式

2. GPTQ
   - GPU 友好
   - 推理速度快
   - 需要校准数据

3. AWQ
   - 激活感知量化
   - 质量损失小
   - GPU 友好
```

---

## 二、GGUF 导出

```bash
# 转换为 GGUF
python convert_hf_to_gguf.py ./merged_model --outfile model-f16.gguf

# 量化为 Q4_K_M
./llama-quantize model-f16.gguf model-q4_k_m.gguf Q4_K_M

# 量化为 Q8_0
./llama-quantize model-f16.gguf model-q8_0.gguf Q8_0
```

---

## 三、GPTQ 量化

```python
from transformers import AutoModelForCausalLM, GPTQConfig

# GPTQ 量化配置
gptq_config = GPTQConfig(
    bits=4,
    dataset="c4",
    group_size=128
)

# 量化模型
model = AutoModelForCausalLM.from_pretrained(
    "./merged_model",
    quantization_config=gptq_config
)

# 保存
model.save_pretrained("./model-gptq")
```

---

## 四、AWQ 量化

```python
from awq import AutoAWQForCausalLM

# 加载模型
model = AutoAWQForCausalLM.from_pretrained("./merged_model")

# 量化
model.quantize(
    tokenizer,
    quant_config={"zero_point": True, "q_group_size": 128}
)

# 保存
model.save_pretrained("./model-awq")
```

## 五、量化对比

```
量化对比：

| 格式 | 大小 | 速度 | 质量 | 适用场景 |
|------|------|------|------|----------|
| FP16 | 14GB | 基准 | 最好 | GPU 部署 |
| Q4_K_M | 4GB | 快 | 好 | CPU/边缘 |
| GPTQ | 4GB | 很快 | 好 | GPU 部署 |
| AWQ | 4GB | 很快 | 很好 | GPU 部署 |
```

## 六、部署选择

```
部署选择：

资源充足（GPU）→ GPTQ / AWQ
资源受限（CPU）→ GGUF Q4_K_M
边缘设备 → GGUF Q2_K / Q3_K_M
质量优先 → GGUF Q8_0 / FP16
```

## 常见误区

1. **量化后不测试直接部署**：量化会引入精度损失，在某些任务上可能退化严重。量化后必须在目标领域做质量回归测试，确认退化在可接受范围内。

2. **所有场景都用同一种量化格式**：GGUF 适合 CPU/边缘部署，GPTQ/AWQ 适合 GPU 部署。选错量化格式可能导致推理速度慢 10 倍。

3. **量化级别选最激进的**：Q2_K 虽然最小，但在推理任务上质量损失可能超过 10%。除非是极端资源受限的场景，否则不要低于 Q4_K_M。

4. **忽略校准数据对 GPTQ 的影响**：GPTQ 量化需要校准数据，校准数据的质量和分布直接影响量化后的模型质量。用随机数据做校准效果很差。

---

## 工程建议

1. **GPU 部署首选 AWQ**：AWQ 在推理速度和质量上通常优于 GPTQ，且 vLLM 原生支持。如果你的部署环境有 GPU，优先选择 AWQ。

2. **CPU/边缘部署首选 GGUF Q4_K_M**：这是体积、速度、质量的最佳平衡点。在大多数 CPU 设备上都能流畅运行，质量损失在 2% 以内。

3. **量化前后的 benchmark 要对比**：用 MMLU 或领域测试集分别评估量化前后的模型，量化出分数差异。差异超过 3% 就需要考虑更保守的量化级别。

4. **保留 FP16 原始模型**：量化模型是部署用的，FP16 模型是"母版"。如果需要重新量化（如换了量化工具或级别），FP16 模型是必需的。
