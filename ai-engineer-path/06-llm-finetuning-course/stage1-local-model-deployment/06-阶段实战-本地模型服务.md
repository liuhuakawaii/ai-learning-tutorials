## 一、部署方案选择

```
部署方案对比：

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| Ollama | 简单易用 | 性能一般 | 开发测试 |
| vLLM | 高性能 | 配置复杂 | 生产部署 |
| llama.cpp | 资源占用低 | 功能有限 | 边缘部署 |

推荐：
- 开发测试 → Ollama
- 生产部署 → vLLM
- 资源受限 → llama.cpp
```

## 二、完整部署流程

```bash
# 1. 安装 Ollama
curl -fsSL https://ollama.ai/install.sh | sh

# 2. 下载模型
ollama pull llama3

# 3. 启动服务
ollama serve

# 4. 测试
curl http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"llama3","messages":[{"role":"user","content":"你好"}]}'
```

## 五、性能测试

```python
import time

def benchmark_model(client, model: str, question: str, iterations: int = 10):
    """性能测试"""
    times = []
    
    for _ in range(iterations):
        start = time.time()
        response = client.chat.completions.create(
            model=model,
            messages=[{"role": "user", "content": question}]
        )
        times.append(time.time() - start)
    
    return {
        "avg_time": sum(times) / len(times),
        "min_time": min(times),
        "max_time": max(times)
    }
```

## 常见误区

1. **本地模型一定比云端便宜**：当请求量较低时（每月几千次），GPU 服务器的固定成本分摊下来可能比 API 调用更贵。需要做 TCO 分析再做决策。

2. **用简单问题测试就认为效果够好**：本地模型在简单问答上可能表现不错，但在复杂推理、长文本理解、代码生成等任务上与云端模型差距明显。测试集要覆盖业务场景的难度分布。

3. **不做性能基准测试就上线**：延迟、吞吐量、并发能力这些指标必须量化测试，不能凭"感觉还行"就上线。一个 P99 延迟 10 秒的服务是不可接受的。

4. **忽略模型更新维护**：开源模型更新很快，新版本通常有显著提升。部署后不关注模型迭代，半年后可能已经落后一个时代。

## 工程建议

1. **分场景选择部署方案**：开发测试用 Ollama（最简单），内部工具用 llama.cpp（资源占用低），面向用户的服务用 vLLM（高并发）。

2. **建立自动化评估流水线**：每次更换模型或调整配置后，自动跑一组测试用例对比效果，避免主观判断导致的退化。

3. **性能测试要模拟真实负载**：用压测工具（如 locust）模拟真实并发场景，测量 P50/P95/P99 延迟和吞吐量，而不是只测单条请求。

4. **预留云端降级方案**：本地服务不可用时自动降级到云端 API，确保业务连续性。通过模型路由器实现透明切换。
