# 03 对比评估——微调模型 vs 基础模型 vs API 模型的多维度对比

> 对比评估帮你做出合理的 build vs buy 决策。

## 场景引入

你的微调模型效果不错，但老板问了一个关键问题："我们自己微调的模型和直接用 GPT-4 API 相比，到底哪个更划算？"你发现这不只是质量对比的问题——还要考虑延迟、成本、数据隐私、维护难度等多个维度。一个全面的对比评估框架，能帮你做出最有说服力的 build vs buy 决策。

```

1. 质量
   - 准确率

   - 完整性

2. 性能
   - 延迟
   - 吞吐量
   - 并发能力

3. 成本
   - API 费用
   - 部署成本
   - 维护成本

4. 其他
   - 数据隐私
   - 定制化能力
   - 可用性
```

## 二、对比评估实现

```python
def compare_models(models: dict, eval_dataset: list) -> dict:
    """对比多个模型"""
    
    results = {}
    
    for model_name, model in models.items():
        model_results = {
            "quality": evaluate_quality(model, eval_dataset),
            "latency": measure_latency(model, eval_dataset),
            "cost": calculate_cost(model, eval_dataset)
        }
        results[model_name] = model_results
    
    return results
```

## 三、结果分析

```python
def analyze_comparison(results: dict) -> dict:
    """分析对比结果"""
    
    analysis = {
        "best_quality": max(results.items(), key=lambda x: x[1]["quality"]["accuracy"]),
        "best_latency": min(results.items(), key=lambda x: x[1]["latency"]["avg"]),
        "best_cost": min(results.items(), key=lambda x: x[1]["cost"]["total"])
    }
    
    return analysis
```

## 五、决策框架

```python
def make_decision(results: dict, priorities: dict) -> str:
    """做出决策"""
    
    scores = {}
    
    for model_name, model_results in results.items():
        score = 0
        for dimension, weight in priorities.items():
            score += model_results[dimension] * weight
        scores[model_name] = score
    
    return max(scores.items(), key=lambda x: x[1])[0]
```

## 六、报告生成

```python
def generate_comparison_report(results: dict) -> str:
    """生成对比报告"""
    
    report = "# 模型对比报告\n\n"
    
    for model_name, model_results in results.items():
        report += f"## {model_name}\n"
        report += f"- 质量：{model_results['quality']['accuracy']:.2%}\n"
        report += f"- 延迟：{model_results['latency']['avg']:.2f}s\n"
        report += f"- 成本：${model_results['cost']['total']:.2f}\n\n"
    
    return report
```

## 常见误区

1. **只对比质量不对比成本**：微调模型质量比 API 好 5%，但成本高 3 倍，这个提升值得吗？对比评估必须包含成本维度，做综合性价比分析。

2. **用不同 prompt 测试不同模型**：同一个问题用不同的 prompt 表述，模型输出可能差异很大。对比评估时所有模型必须用完全相同的输入。

3. **忽略延迟对用户体验的影响**：API 模型可能质量更好，但延迟 3 秒；本地模型延迟 0.5 秒。对于实时交互场景，延迟差异可能比质量差异更重要。

4. **对比评估只做一次就下结论**：模型的效果和成本会随着用量、数据分布、模型版本的变化而变化。对比评估应该定期重做。

---

## 工程建议

1. **决策矩阵要量化**：不要用"好/一般/差"这种模糊评价，要给每个维度打分（1-10），乘以权重后算总分。量化决策比主观判断更可靠。

2. **考虑隐性成本**：本地部署的隐性成本包括运维人力、GPU 闲置成本、故障恢复成本。API 的隐性成本包括供应商锁定、数据隐私风险。全面计算 TCO。

3. **先小规模试点再全面切换**：不要一次性把所有流量切到新模型。先用 10% 的流量做 A/B 测试，确认效果和稳定性后再逐步扩大。

4. **建立退出机制**：选择本地方案时要考虑退出成本——如果效果不达标或成本超预期，能否快速切回 API？预留回退路径。
