# 05 成本分析——API 调用 vs 本地部署的 TCO 对比与决策框架

> 选择 API 还是本地部署，成本是关键因素。

## 场景引入

你的微调模型已经部署上线，但月底一看账单：GPU 服务器月租 8000 元，电费 2000 元，运维人力成本另算。而如果直接用 GPT-4 API，同样的请求量只要 3000 元/月。本地部署真的比 API 划算吗？什么时候 API 更便宜？什么时候自建更省钱？你需要一个科学的成本分析框架来回答这些问题。

---

## 学习目标

- 掌握 TCO（总拥有成本）的计算方法
- 理解 API 和本地部署的成本结构
- 学会做出成本效益最优的决策

---

## 一、成本结构

```
API 调用成本：
- 按 Token 计费
- 无前期投入
- 成本随用量线性增长

本地部署成本：
- 硬件成本（GPU 服务器）
- 电力成本
- 运维成本
- 前期投入大，边际成本低
```

---

## 二、TCO 计算

```python
def calculate_api_cost(monthly_requests: int, avg_tokens: int, price_per_token: float) -> float:
    """计算 API 成本"""
    return monthly_requests * avg_tokens * price_per_token

def calculate_local_cost(
    hardware_cost: float,
    monthly_power_cost: float,
    monthly_maintenance_cost: float,
    months: int
) -> float:
    """计算本地部署成本"""
    return hardware_cost + (monthly_power_cost + monthly_maintenance_cost) * months
```

---

## 三、决策框架

```
决策框架：

月请求量 < 100K → API 调用
月请求量 100K-1M → 需要详细分析
月请求量 > 1M → 本地部署

其他因素：
- 数据隐私要求 → 倾向本地
- 延迟要求高 → 倾向本地
- 快速上线 → 倾向 API
- 预算有限 → 倾向 API
```

---

## 四、盈亏分析

```python
def breakeven_analysis(api_cost_per_month: float, local_cost_per_month: float) -> int:
    """盈亏平衡分析"""
    # 假设硬件成本
    hardware_cost = 10000  # $10,000
    
    # 计算多少个月后本地部署更划算
    monthly_savings = api_cost_per_month - local_cost_per_month
    
    if monthly_savings <= 0:
        return -1  # API 更划算
    
    return hardware_cost / monthly_savings
```

## 五、成本优化

```
成本优化策略：

API 调用：
- 使用更便宜的模型
- 优化 Prompt 减少 Token
- 缓存常见请求
- 批处理请求

本地部署：
- 使用量化模型
- 优化推理性能
- 合理规划资源
- 自动扩缩容
```

## 六、决策报告

```python
def generate_cost_report(api_cost: float, local_cost: float, breakeven_months: int) -> str:
    """生成成本报告"""
    
    report = f"""# 成本分析报告

## API 调用
- 月成本：${api_cost:.2f}
- 年成本：${api_cost * 12:.2f}

## 本地部署
- 月成本：${local_cost:.2f}
- 年成本：${local_cost * 12:.2f}

## 决策建议
- 盈亏平衡：{breakeven_months} 个月
- {'建议本地部署' if breakeven_months < 12 else '建议 API 调用'}
"""
    return report
```

## 常见误区

1. **只算 GPU 成本不算运维成本**：GPU 服务器需要人维护——监控、故障处理、版本升级、安全补丁。运维人力成本可能比 GPU 租金还高。

2. **用峰值成本做决策**：不应该按峰值请求量计算本地部署成本。低谷期 GPU 闲置也是成本。应该按平均利用率计算，或使用弹性伸缩。

3. **忽略数据传输成本**：API 调用的 Token 费用只是显性成本，网络带宽、数据存储、日志存储这些隐性成本也要计入。

4. **一次分析就做长期决策**：API 价格在持续下降，GPU 性能在持续提升。成本分析应该每季度更新一次，而不是一次决策用一年。

---

## 工程建议

1. **盈亏分析是决策的核心**：计算本地部署的固定成本（硬件）和可变成本（电力、运维），与 API 的按量费用对比，找到盈亏平衡点。

2. **低用量先用 API**：月请求量 < 100K 时，API 通常更划算。先用 API 验证业务可行性，等用量上来再考虑自建。

3. **混合方案是最优解**：核心业务用本地部署（保障数据隐私和低延迟），非核心业务用 API（降低成本和运维负担）。

4. **量化成本优化效果**：每次成本优化（如模型量化、Prompt 缩短、缓存命中率提升）都要量化节省的金额，用数据驱动优化决策。

```
本课核心要点：

1. TCO 包括硬件、电力、运维等所有成本

3. 本地部署适合高用量、数据隐私场景
4. 盈亏分析帮助做出决策
```
