# 02 领域评估——针对微调任务设计专属评估数据集

> 基准测试评估通用能力，领域评估评估专业能力。

## 场景引入

你的微调模型在 MMLU 上比基座模型低了 2 分，是不是微调失败了？不一定。你微调的是医疗问答模型，而 MMLU 测的是通用知识。微调让模型在医疗领域变得更强，但通用能力略有下降，这是正常的"遗忘"现象。你需要一套领域专属的评估方案，用你的业务数据来衡量微调是否真正达到了目标。

```python
def create_domain_eval_dataset(domain: str, size: int = 100) -> list:
    """创建领域评估数据集"""
    
    dataset = []
    
    for i in range(size):
        # 生成评估样本
        sample = {
            "id": f"eval_{i}",
            "question": generate_question(domain),
            "reference": generate_reference(domain),
            "category": categorize_question(domain),
            "difficulty": assign_difficulty()
        }
        dataset.append(sample)
    
    return dataset
```

## 二、评估指标

```
领域评估指标：

1. 准确率（Accuracy）
   - 回答是否正确
   - 适用于有标准答案的任务

2. 相关性（Relevancy）
   - 回答是否切题
   - 适用于开放性任务

3. 完整性（Completeness）
   - 回答是否完整
   - 适用于知识性任务

4. 专业性（Professionalism）
   - 回答是否专业
   - 适用于专业领域

5. 安全性（Safety）
   - 回答是否安全
   - 适用于医疗、法律等领域
```

## 三、自动评估

```python
def evaluate_domain(model, eval_dataset: list) -> dict:
    """领域评估"""
    
    results = {
        "accuracy": 0,
        "relevancy": 0,
        "completeness": 0
    }
    
    for sample in eval_dataset:
        # 生成回答
        answer = generate_answer(model, sample["question"])
        
        # 评估
        results["accuracy"] += check_accuracy(answer, sample["reference"])
        results["relevancy"] += check_relevancy(answer, sample["question"])
        results["completeness"] += check_completeness(answer, sample["reference"])
    
    # 计算平均值
    for key in results:
        results[key] /= len(eval_dataset)
    
    return results
```

## 四、人工评估

```python
def human_evaluation(eval_dataset: list, model) -> dict:
    """人工评估"""
    
    # 生成回答
    predictions = []
    for sample in eval_dataset:
        answer = generate_answer(model, sample["question"])
        predictions.append({
            "question": sample["question"],
            "answer": answer,
            "reference": sample["reference"]
        })
    
    # 保存供人工评估
    with open("human_eval.json", "w") as f:
        json.dump(predictions, f, ensure_ascii=False, indent=2)
    
    return predictions
```

```python
def generate_eval_report(results: dict) -> str:
```

## 常见误区

1. **评估集从训练数据中随机拆分**：这样会导致数据泄漏——模型可能在训练时见过类似的样本，评估结果虚高。评估集必须是独立收集的。

2. **评估指标选错**：分类任务用准确率，生成任务用 BLEU/ROUGE，问答任务用 F1。选错指标会导致评估结果没有参考价值。

3. **评估集太小没有统计意义**：20 条测试样本的评估结果波动很大，可能因为几条样本的变化就差 10%。评估集至少需要 50-100 条样本。

4. **只做自动评估不做人工评估**：自动评估能检查准确性，但回答的流畅度、专业性、安全性需要人工评估。两种评估应该结合使用。

---

## 工程建议

1. **评估集要覆盖难度分布**：简单、中等、困难问题都要有，比例要和业务场景匹配。全用简单问题会高估模型能力，全用困难问题会低估。

2. **评估流程要可复现**：评估脚本、测试数据、评估指标都要版本化，确保不同时间做的评估结果可以对比。

3. **用 LLM-as-Judge 做自动评估**：对于开放性问答，可以用 GPT-4 等强模型作为"裁判"评估回答质量。比简单的字符串匹配更准确。

4. **评估结果要分维度分析**：不要只看总分，要分维度（如按问题类型、按难度级别）分析，找到模型的薄弱环节，指导后续优化方向。
