# 04 模型部署——用 vLLM 部署微调模型并提供 OpenAI 兼容 API

> 训练好的模型需要部署才能产生价值。

## 场景引入

模型评估通过了，效果达标。但模型文件还躺在 output 目录里，怎么让用户用上？你需要把微调模型部署成一个稳定的服务，提供 OpenAI 兼容的 API 接口，支持高并发，有健康检查和监控，还要考虑容器化和负载均衡。从"模型文件"到"生产服务"，中间隔着一整套工程化的工作。

## 一、vLLM 部署

```bash
# 部署微调模型
python -m vllm.entrypoints.openai.api_server \
  --model ./merged_model \
  --host 0.0.0.0 \
  --port 8000
```

---

## 二、Docker 部署

```dockerfile
FROM vllm/vllm-openai:latest

COPY ./merged_model /model

CMD ["--model", "/model", "--host", "0.0.0.0", "--port", "8000"]
```

```yaml
version: '3.8'
services:
  model:
    build: .
    ports:
      - "8000:8000"
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1
              capabilities: [gpu]
```

## 三、API 使用

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8000/v1",
    api_key="not-needed"
)

response = client.chat.completions.create(
    model="./merged_model",
    messages=[{"role": "user", "content": "什么是高血压？"}]
)

print(response.choices[0].message.content)
```

## 常见误区

1. **不设超时就上线**：没有请求超时的服务是不可靠的。一个异常的长请求可能占用 GPU 资源数分钟，影响其他用户的正常使用。

2. **只部署一个实例不做高可用**：单实例部署时，模型重启或更新就会导致服务中断。生产环境至少部署 2 个实例，通过负载均衡实现高可用。

3. **不做版本管理就部署**：每次更新模型直接覆盖旧版本，出问题无法回滚。模型部署应该像代码部署一样，支持版本管理和灰度发布。

4. **忽略安全防护**：模型 API 暴露在公网上没有认证和限流，容易被滥用。必须配置 API Key 认证、请求限流、输入过滤。

---

## 工程建议

1. **Docker 部署是标准做法**：用 Docker 容器化部署，配合 docker-compose 或 K8s 管理。确保开发、测试、生产环境一致。

2. **健康检查和监控不能少**：`/health` 端点做存活检查，`/metrics` 端点暴露 Prometheus 指标。配置 Grafana 仪表盘实时监控服务状态。

3. **灰度发布降低风险**：新版本先部署到 10% 的流量，观察 24 小时无异常后再全量切换。出问题可以快速回滚到旧版本。

4. **预热请求避免冷启动**：模型服务刚启动时第一个请求会很慢（模型加载到 GPU）。部署后先发几个预热请求，确保服务进入热状态。
