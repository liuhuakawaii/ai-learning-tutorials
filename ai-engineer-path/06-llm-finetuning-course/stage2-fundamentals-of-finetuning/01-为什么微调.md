# 01 为什么微调——Prompt Engineering vs RAG vs Fine-tuning 的选型

> 不是所有问题都需要微调。选对方法比选对模型更重要。

## 学习目标

- 理解 Prompt Engineering、RAG、Fine-tuning 的区别
- 掌握三种方法的适用场景
- 学会根据需求选择合适的方法

---

## 一、三种方法对比

```
┌─────────────────────────────────────────────────────────────┐
│           Prompt Engineering vs RAG vs Fine-tuning          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Prompt Engineering                                         │
│  ├── 原理：通过提示词引导模型行为                            │
│  ├── 成本：低（无需训练）                                    │
│  ├── 效果：有限（受限于模型能力）                            │
│  └── 适用：简单任务、快速迭代                                │
│                                                             │
│  RAG（检索增强生成）                                         │
│  ├── 原理：检索外部知识辅助生成                              │
│  ├── 成本：中（需要构建知识库）                              │
│  ├── 效果：好（可以访问最新信息）                            │
│  └── 适用：知识密集型任务                                    │
│                                                             │
│  Fine-tuning（微调）                                        │
│  ├── 原理：用领域数据训练模型                                │
│  ├── 成本：高（需要数据和计算资源）                          │
│  ├── 效果：好（可以改变模型行为）                            │
│  └── 适用：特定领域、特定风格                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 二、选型决策树

```
选型决策树：

你的需求是什么？
├── 简单任务优化 → Prompt Engineering
│   ├── 调整输出格式
│   ├── 改变回答风格
│   └── 添加约束条件
│
├── 访问外部知识 → RAG
│   ├── 最新信息
│   ├── 私有数据
│   └── 专业知识
│
└── 改变模型行为 → Fine-tuning
    ├── 特定领域
    ├── 特定风格
    └── 特定任务
```

---

## 三、适用场景

```
适用场景：

Prompt Engineering：
- 快速原型开发
- 简单任务调整
- 成本敏感场景

RAG：
- 知识问答系统
- 文档检索
- 实时信息查询

Fine-tuning：
- 特定领域（医疗、法律、金融）
- 特定风格（正式、口语、专业）
- 特定任务（代码生成、文本分类）
```

---

## 四、组合使用

```
组合使用：

1. Prompt + RAG
   - 用 Prompt 引导 RAG 行为
   - 优化检索结果的使用

2. RAG + Fine-tuning
   - 微调模型更好地使用检索结果
   - 提高 RAG 的效果

3. Prompt + Fine-tuning
   - 微调后用 Prompt 进一步优化
   - 适应不同场景
```

---

## 五、决策矩阵

```
决策矩阵：

| 因素 | Prompt | RAG | Fine-tuning |
|------|--------|-----|-------------|
| 开发成本 | 低 | 中 | 高 |
| 维护成本 | 低 | 中 | 高 |
| 效果提升 | 有限 | 好 | 很好 |
| 灵活性 | 高 | 中 | 低 |
| 适用范围 | 广 | 中 | 窄 |
```

---

## 小结

```
本课核心要点：

1. Prompt Engineering：简单、低成本、快速迭代
2. RAG：访问外部知识、知识密集型任务
3. Fine-tuning：改变模型行为、特定领域
4. 根据需求选择合适的方法，可以组合使用
```
