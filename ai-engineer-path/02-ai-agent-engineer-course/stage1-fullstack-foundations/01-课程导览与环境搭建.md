## 为什么是这个技术栈

### 后端：为什么选 FastAPI

你可能会问：Python 后端框架那么多，Django、Flask、Tornado，为什么是 FastAPI？

| 框架 | 优势 | 劣势 | 适合场景 |
|------|------|------|----------|
| Django | 全家桶、生态成熟 | 笨重、异步支持弱 | 内容管理系统 |
| Flask | 轻量、灵活 | 缺少类型校验、性能一般 | 小型 API |
| **FastAPI** | **类型安全、自动文档、高性能、异步原生** | 生态比 Django 少 | **AI 应用后端** |

FastAPI 的三个杀手级特性：

1. **Pydantic 类型校验**：请求参数自动校验，不用手写 validation
2. **自动 API 文档**：访问 `/docs` 就有完整的 Swagger 文档
3. **异步原生**：`async/await` 天然支持，适合 LLM API 这种 IO 密集场景

```python
# 这几行代码就有了完整的 API + 文档 + 类型校验
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class ChatRequest(BaseModel):
    message: str
    session_id: str | None = None

@app.post("/api/chat")
async def chat(request: ChatRequest):
    return {"reply": f"你说的是：{request.message}"}
```

### 前端：为什么选 Vue 3

企业级中后台应用，Vue 3 + Naive UI 是国内最主流的组合之一：

- **组合式 API**：逻辑复用更灵活（比 Options API 更适合复杂组件）
- **TypeScript 支持**：类型安全，减少运行时错误
- **Naive UI**：企业级组件库，主题定制能力强，中文文档完善

如果你更熟悉 React，课程也提供 React 版代码示例，但主教程以 Vue 3 为主。

### 数据库：为什么是 PostgreSQL

PostgreSQL 不只是关系型数据库——它是一个数据平台：

- 原生支持 JSON（存 Agent 配置、Skill 参数）
- pgvector 扩展支持向量检索（RAG 知识库的核心）
- 事务安全、并发性能优秀
- 开源免费，社区活跃

### 缓存：为什么需要 Redis

Redis 在 AI 应用中不只是缓存：

- **会话缓存**：存储对话上下文，避免每次从数据库读
- **限流**：控制 API 调用频率
- **消息队列**：异步任务分发（Agent 执行、工作流调度）
- **发布订阅**：实时推送（对话流式输出）

## 环境搭建

### 1. 安装基础工具

**Windows 用户：**

```powershell
# 安装 scoop（包管理器）
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
Invoke-RestMethod -Uri https://get.scoop.sh | Invoke-Expression

# 安装基础工具
scoop install git nodejs python docker-desktop
```

**macOS 用户：**

```bash
# 安装 Homebrew（如果没有）
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# 安装基础工具
brew install git node python@3.12 docker
```

### 2. 验证安装

```bash
git --version        # >= 2.40
node --version       # >= 20.x
python --version     # >= 3.12
docker --version     # >= 24.x
docker compose version  # >= 2.x
```

### 3. 创建项目结构

```bash
mkdir ai-agent-platform && cd ai-agent-platform

# 后端
mkdir -p backend/app/{api,core,models,services,schemas}
mkdir -p backend/alembic/versions
touch backend/app/__init__.py
touch backend/app/main.py
touch backend/requirements.txt
touch backend/alembic.ini

# 前端
npm create vue@latest frontend -- --typescript --router --pinia
cd frontend
npm install naive-ui @vicons/ionicons5 axios
cd ..

# Docker
touch docker-compose.yml
touch .env.example
```

### 4. 配置 Docker Compose

创建 `docker-compose.yml`：

```yaml
services:
  postgres:
    image: pgvector/pgvector:pg16
    environment:
      POSTGRES_USER: agent
      POSTGRES_PASSWORD: agent123
      POSTGRES_DB: agent_platform
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"

volumes:
  pgdata:
```

### 5. 启动服务

```bash
docker compose up -d
```

验证服务运行：

```bash
# 测试 PostgreSQL
docker compose exec postgres psql -U agent -d agent_platform -c "SELECT version();"

# 测试 Redis
docker compose exec redis redis-cli ping
```

## 开发流程

1. **写后端 API**：定义 Schema → 写路由 → 写业务逻辑 → 测试
2. **写前端页面**：定义类型 → 封装 API → 写组件 → 写页面
3. **前后端联调**：用 Swagger 文档验证 API → 前端对接
4. **提交代码**：Git commit → Push → CI 自动测试

## 本节要点

- FastAPI 的类型安全和自动文档是企业级开发的加速器
- PostgreSQL + pgvector 是 AI 应用的最佳数据库选择
- Docker Compose 让开发环境一致性有保障
- 项目结构要从第一天就规划好，不要等代码乱了再重构

## 常见错误

| 错误 | 原因 | 解决 |
|------|------|------|
| `docker compose up` 报端口占用 | 本地已运行 PostgreSQL/Redis | 改端口或停掉本地服务 |
| FastAPI 启动报 `ModuleNotFoundError` | 没在虚拟环境 | `python -m venv venv && source venv/bin/activate` |
| 前端 `npm install` 失败 | Node 版本太低 | 升级到 Node 20+ |
| pgvector 扩展不可用 | 用错了 Docker 镜像 | 确保用 `pgvector/pgvector:pg16` |
