# 01 工作流引擎设计

> 工作流引擎是 AI 平台的"大脑"——让复杂的 AI 任务变得可编排、可复用、可监控。

## 学习目标

- 理解 DAG（有向无环图）工作流模型
- 设计节点类型和边的语义
- 理解工作流执行模型

## 核心概念

### DAG 模型

```python
# backend/app/workflow/models.py
from enum import Enum
from pydantic import BaseModel

class NodeType(str, Enum):
    LLM = "llm"                    # LLM 调用节点
    TOOL = "tool"                  # 工具调用节点
    CONDITION = "condition"        # 条件分支节点
    HUMAN = "human"                # 人工审批节点
    PARALLEL = "parallel"          # 并行执行节点
    INPUT = "input"                # 输入节点
    OUTPUT = "output"              # 输出节点

class NodeConfig(BaseModel):
    """节点配置"""
    id: str
    type: NodeType
    label: str
    config: dict                   # 节点特定配置
    position: dict                 # 画布位置 {x, y}

class Edge(BaseModel):
    """边（连接线）"""
    id: str
    source: str                    # 源节点 ID
    target: str                    # 目标节点 ID
    source_handle: str | None = None  # 源端口（条件分支用）
    label: str | None = None

class WorkflowDefinition(BaseModel):
    """工作流定义"""
    id: str
    name: str
    description: str
    nodes: list[NodeConfig]
    edges: list[Edge]
    variables: dict = {}           # 全局变量
    version: int = 1
```

### 节点类型定义

| 节点类型 | 功能 | 输入 | 输出 |
|----------|------|------|------|
| INPUT | 接收用户输入 | 用户消息 | 文本 |
| LLM | 调用大模型 | Prompt + 变量 | AI 回复 |
| TOOL | 调用工具 | 参数 | 工具结果 |
| CONDITION | 条件判断 | 条件表达式 | true/false 分支 |
| HUMAN | 人工审批 | 待审批内容 | 审批结果 |
| PARALLEL | 并行执行 | 多个分支 | 聚合结果 |
| OUTPUT | 输出结果 | 最终结果 | 返回给用户 |

## 练习

### 练习 1：模型设计

用 Pydantic 定义完整的工作流模型：

1. 节点配置（各类型的特定配置）
2. 边的定义（包括条件分支的 handle）
3. 工作流定义（包含变量和版本）

### 练习 2：DAG 验证

实现 DAG 验证逻辑：

1. 检测环路
2. 检测孤立节点
3. 检测缺失的输入/输出节点

## 本节要点

- 工作流 = DAG（节点 + 边）
- 节点类型决定执行逻辑，边决定执行顺序
- 验证是第一步——不合法的 DAG 不能执行
