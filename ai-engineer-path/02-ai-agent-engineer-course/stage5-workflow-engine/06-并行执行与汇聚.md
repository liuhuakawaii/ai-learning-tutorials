# 06 并行执行与汇聚

> 串行太慢——并行执行能让工作流速度提升数倍。

## 场景引入

你的 AI 数据分析平台有一个工作流：用户上传一份报告，需要同时调用三个外部 API——一个提取关键词、一个生成摘要、一个翻译成英文。如果串行执行，每个 API 调用需要 3 秒，总共要 9 秒。但这三个任务互不依赖，完全可以并行执行，总耗时只需要 3 秒。并行执行和结果汇聚是提升工作流性能的关键手段。

## 学习目标

- 实现并行执行（扇出/扇入）
- 设计结果汇聚和失败策略
- 处理并行执行的超时和错误

## 并行执行模型

```python
class ParallelNodeHandler:
    """并行执行节点"""
    
    async def execute(self, node, inputs, context):
        branches = node.config["branches"]  # 并行分支配置
        strategy = node.config.get("strategy", "wait_all")  # wait_all / wait_any / race
        
        tasks = []
        for branch in branches:
            sub_workflow = branch["workflow"]
            task = asyncio.create_task(
                self._execute_branch(sub_workflow, inputs, context)
            )
            tasks.append((branch["name"], task))
        
        if strategy == "wait_all":
            # 等待所有分支完成
            results = {}
            for name, task in tasks:
                try:
                    results[name] = await asyncio.wait_for(task, timeout=300)
                except asyncio.TimeoutError:
                    results[name] = {"error": "timeout"}
            return {"results": results}
        
        elif strategy == "wait_any":
            # 等待任意一个完成
            done, pending = await asyncio.wait(
                [t for _, t in tasks], return_when=asyncio.FIRST_COMPLETED
            )
            # 取消未完成的
            for task in pending:
                task.cancel()
            return {"result": done.pop().result()}
        
        elif strategy == "race":
            # 竞争：取最快的
            return await self._race(tasks)
```

## 结果汇聚

```python
class AggregatorNodeHandler:
    """结果汇聚节点"""
    
    async def execute(self, node, inputs, context):
        strategy = node.config.get("aggregation_strategy", "concatenate")
        
        if strategy == "concatenate":
            # 拼接所有结果
            all_results = []
            for key, value in inputs.items():
                if isinstance(value, dict) and "results" in value:
                    all_results.extend(value["results"])
            return {"aggregated": all_results}
        
        elif strategy == "merge":
            # 合并字典
            merged = {}
            for key, value in inputs.items():
                if isinstance(value, dict):
                    merged.update(value)
            return {"aggregated": merged}
        
        elif strategy == "llm_merge":
            # 用 LLM 合并结果
            prompt = f"请合并以下结果：\n\n{json.dumps(inputs, ensure_ascii=False)}"
            response = await self.llm.chat(
                messages=[{"role": "user", "content": prompt}],
                model="gpt-4o-mini",
            )
            return {"aggregated": response.content}
```

## 失败策略

```python
class FailureStrategy(str, Enum):
    FAIL_FAST = "fail_fast"          # 一个失败就全部失败
    CONTINUE = "continue"            # 忽略失败继续
    RETRY = "retry"                  # 重试失败的分支

async def execute_with_strategy(self, tasks, strategy, max_retries=3):
    if strategy == FailureStrategy.FAIL_FAST:
        # 任意一个失败就抛异常
        results = await asyncio.gather(*[t for _, t in tasks], return_exceptions=False)
        return dict(zip([n for n, _ in tasks], results))
    
    elif strategy == FailureStrategy.CONTINUE:
        # 忽略失败
        results = {}
        for name, task in tasks:
            try:
                results[name] = await task
            except Exception as e:
                results[name] = {"error": str(e)}
        return results
    
    elif strategy == FailureStrategy.RETRY:
        # 重试失败的
        results = {}
        for name, task in tasks:
            for attempt in range(max_retries):
                try:
                    results[name] = await task
                    break
                except Exception:
                    if attempt == max_retries - 1:
                        results[name] = {"error": "max retries exceeded"}
                    await asyncio.sleep(2 ** attempt)
        return results
```

### 练习 1：并行执行

实现并行执行节点：

1. 多个分支同时执行
2. 等待所有分支完成
3. 汇聚结果

### 练习 2：失败策略

实现三种失败策略：

1. 快速失败：一个失败就停止
2. 继续执行：忽略失败
3. 重试：失败后重试

## 常见误区

| 错误 | 原因 | 解决 |
|------|------|------|
| 结果丢失 | 没有汇聚节点 | 加入 Aggregator 节点 |
| 资源耗尽 | 并行太多 | 限制并发数 |
| 超时 | 分支执行太慢 | 设置分支超时 |

## 工程建议

- 并行分支数量要设上限，根据系统资源和下游服务承受能力合理控制并发度
- 每个并行分支都要设置独立的超时时间，避免一个慢分支拖住整个工作流
- 汇聚策略要根据业务场景选择——简单拼接适合日志收集，字典合并适合数据聚合，LLM 合并适合非结构化结果
- 并行执行的每个分支要有独立的执行 ID，方便追踪和排查单个分支的问题
