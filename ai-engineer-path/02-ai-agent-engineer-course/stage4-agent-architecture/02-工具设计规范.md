# 02 工具设计规范

> 好的工具设计，让 Agent 能用对工具；差的工具设计，让 Agent 越用越乱。

## 场景引入

你给 Agent 注册了十几个工具，但测试时发现它经常调错——想查订单却调了用户查询接口，参数格式也总是不对。问题不在 LLM，而在工具设计：描述含糊、参数定义不严格、返回格式不统一。工具是 Agent 的"手脚"，工具设计的质量直接决定了 Agent 能力的上限。

## 学习目标

- 设计规范的工具接口（输入 Schema、输出协议）
- 理解工具的幂等性和错误边界
- 实现工具注册和发现机制

## 前置要求

- 理解 Agent 的基本概念
- 熟悉 JSON Schema 和 Pydantic

## 工具设计原则

```python
# backend/app/agent/tools/base.py
from abc import ABC, abstractmethod
from pydantic import BaseModel, Field

class ToolParameter(BaseModel):
    """工具参数定义"""
    name: str
    type: str              # string / number / boolean / object / array
    description: str
    required: bool = True
    default: any = None

class ToolResult:
    """工具执行结果"""
    def __init__(
        self,
        success: bool,
        data: any = None,
        error: str | None = None,
        metadata: dict | None = None,
    ):
        self.success = success
        self.data = data
        self.error = error
        self.metadata = metadata or {}
    
    def to_observation(self) -> str:
        """转为 Agent 可读的观察结果"""
        if self.success:
            return str(self.data)
        else:
            return f"Error: {self.error}"

class BaseTool(ABC):
    """工具基类"""
    
    @property
    @abstractmethod
    def name(self) -> str:
        """工具名称，Agent 用这个名字调用"""
        ...
    
    @property
    @abstractmethod
    def description(self) -> str:
        """工具描述，帮助 Agent 决定是否使用"""
        ...
    
    @property
    @abstractmethod
    def parameters(self) -> dict:
        """JSON Schema 格式的参数定义"""
        ...
    
    @abstractmethod
    async def execute(self, **kwargs) -> ToolResult:
        """执行工具"""
        ...
    
    def to_openai_tool(self) -> dict:
        """转为 OpenAI Function Calling 格式"""
        return {
            "type": "function",
            "function": {
                "name": self.name,
                "description": self.description,
                "parameters": self.parameters,
            },
        }
```

# backend/app/agent/tools/search.py
class SearchTool(BaseTool):
    name = "search"
    description = "搜索知识库或互联网，获取相关信息"
    parameters = {
        "type": "object",
        "properties": {
            "query": {
                "type": "string",
                "description": "搜索关键词",
            },
            "source": {
                "type": "string",
                "enum": ["knowledge_base", "web"],
                "description": "搜索来源",
                "default": "knowledge_base",
            },
            "top_k": {
                "type": "integer",
                "description": "返回结果数量",
                "default": 5,
            },
        },
        "required": ["query"],
    }
    
    def __init__(self, retrieval_pipeline: RetrievalPipeline):
        self.retrieval = retrieval_pipeline
    
    async def execute(self, query: str, source: str = "knowledge_base", top_k: int = 5) -> ToolResult:
        try:
            results = await self.retrieval.retrieve(query, top_k=top_k)
            return ToolResult(
                success=True,
                data=[{"content": r["content"], "source": r["metadata"]["source"]} for r in results],
            )
        except Exception as e:
            return ToolResult(success=False, error=str(e))
```

# backend/app/agent/tools/database.py
class DatabaseQueryTool(BaseTool):
    name = "query_database"
    description = "查询数据库，获取订单、用户等业务数据"
    parameters = {
        "type": "object",
        "properties": {
            "query_type": {
                "type": "string",
                "enum": ["order_status", "user_info", "product_info"],
                "description": "查询类型",
            },
            "params": {
                "type": "object",
                "description": "查询参数",
            },
        },
        "required": ["query_type", "params"],
    }
    
    async def execute(self, query_type: str, params: dict) -> ToolResult:
        try:
            if query_type == "order_status":
                result = await self._query_order(params.get("order_id"))
            elif query_type == "user_info":
                result = await self._query_user(params.get("user_id"))
            else:
                return ToolResult(success=False, error=f"Unknown query type: {query_type}")
            
            return ToolResult(success=True, data=result)
        except Exception as e:
            return ToolResult(success=False, error=str(e))
```

## 工具注册表

```python
# backend/app/agent/tool_registry.py
class ToolRegistry:
    """工具注册表"""
    
    def __init__(self):
        self._tools: dict[str, BaseTool] = {}
    
    def register(self, tool: BaseTool):
        """注册工具"""
        self._tools[tool.name] = tool
    
    def get(self, name: str) -> BaseTool | None:
        """获取工具"""
        return self._tools.get(name)
    
    def list_tools(self) -> list[dict]:
        """列出所有工具"""
        return [
            {
                "name": t.name,
                "description": t.description,
                "parameters": t.parameters,
            }
            for t in self._tools.values()
        ]
    
    def to_openai_tools(self) -> list[dict]:
        """转为 OpenAI Function Calling 格式"""
        return [t.to_openai_tool() for t in self._tools.values()]

# 全局注册表
registry = ToolRegistry()
registry.register(SearchTool(retrieval_pipeline))

registry.register(FileOperationTool())
```

## 常见误区

| 误区 | 原因 | 解决 |
|------|------|------|
| 工具描述写得太简短 | 以为 LLM 能"猜到"用途 | 描述要包含用途、适用场景和限制条件 |
| 参数没有设 required 标记 | 偷懒没写 JSON Schema | 所有必填参数必须标记 required |
| 操作类工具没有确认机制 | 忘了区分查询和操作 | 高风险操作（删除、发送）必须有人工确认 |
| 工具返回结果格式不统一 | 各工具自行定义返回 | 统一用 ToolResult 封装，包含 success/data/error |

## 工程建议

- 工具描述是 Agent 选择工具的唯一依据，写得越精确 Agent 选得越准——包含"什么时候用"和"什么时候不该用"
- 查询类工具可以不加限制，但写入/删除/发送类工具必须有确认机制或权限控制
- 工具参数的 JSON Schema 要严格定义 enum、minimum、maximum 等约束，减少 LLM 传错参数的概率
- 新增工具后要用典型问题测试 Agent 是否能正确选择和调用，不要只测单个工具

## 本节要点

- 工具描述要清晰准确，这是 Agent 选择工具的唯一依据
- 工具参数用 JSON Schema 定义，保证类型安全
- 工具要幂等：相同输入多次执行结果一致
- 操作类工具必须有确认机制
