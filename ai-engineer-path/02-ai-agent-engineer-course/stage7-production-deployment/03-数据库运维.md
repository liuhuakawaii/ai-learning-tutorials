# 03 数据库运维

> 数据库是系统的命脉——迁移、备份、监控，一个都不能少。

## 场景引入

你的 AI Agent 平台上线一周后需要给 `agents` 表加几个字段。直接连数据库 `ALTER TABLE`？线上有百万条数据在跑，一个锁表操作可能让整个服务卡死几分钟。更糟的是如果改错了字段名，回滚要手动修数据。数据库迁移工具就是为了解决这个问题——让每一次结构变更都有版本、可追溯、可回滚。

## 学习目标

- 掌握 Alembic 迁移管理
- 实现数据库备份和恢复
- 理解连接池调优

## 迁移管理

```bash
# 创建迁移
alembic revision --autogenerate -m "add_agent_table"

# 执行迁移
alembic upgrade head

# 回滚
alembic downgrade -1

# 查看当前版本
alembic current

# 查看历史
alembic history
```

## 备份和恢复

```bash
# 备份
docker compose exec postgres pg_dump -U agent agent_platform > backup_$(date +%Y%m%d).sql

# 恢复
docker compose exec -T postgres psql -U agent agent_platform < backup_20250101.sql

# 自动备份脚本
#!/bin/bash
BACKUP_DIR="/backups"
DATE=$(date +%Y%m%d_%H%M%S)
docker compose exec postgres pg_dump -U agent agent_platform | gzip > "$BACKUP_DIR/backup_$DATE.sql.gz"
# 保留最近 30 天
find $BACKUP_DIR -name "backup_*.sql.gz" -mtime +30 -delete
```

## 连接池调优

```python
engine = create_async_engine(
    DATABASE_URL,
    pool_size=20,          # 核心连接数
    max_overflow=10,       # 最大溢出连接
    pool_pre_ping=True,    # 使用前检测连接
    pool_recycle=3600,     # 连接最大存活时间
    pool_timeout=30,       # 获取连接超时
)
```

## 常见误区

| 错误 | 原因 | 解决 |
|------|------|------|
| 迁移失败 | 模型和数据库不一致 | 先检查 diff，再执行 |
| 备份文件损坏 | 没验证备份 | 定期测试恢复 |
| 连接池耗尽 | 连接没归还 | 用 async with session |

## 工程建议

备份不做恢复测试等于没备份——至少每月做一次完整的恢复演练。Alembic 迁移脚本生成后务必人工审查，自动生成的 diff 可能遗漏数据迁移或错误删除列。连接池参数需要根据实际并发量调优，`pool_size` 设太大会耗尽数据库连接，设太小会排队等待，建议从 20 起步并监控连接使用率。

## 本节要点

- Alembic 迁移让数据库版本可控
- 定期备份是数据安全的最后防线
- 连接池配置影响系统并发能力
