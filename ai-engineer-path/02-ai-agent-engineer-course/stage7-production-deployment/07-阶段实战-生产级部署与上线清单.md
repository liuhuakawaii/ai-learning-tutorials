# 07 阶段实战：生产级部署与上线清单

> 从 localhost 到生产环境——这一步看似简单，实则处处是坑。

## 场景引入

你花了一个月开发的 AI Agent 平台终于要上线了。信心满满地执行部署脚本，结果数据库迁移忘跑了导致 API 全部报错；修好后发现 HTTPS 证书没配，用户看到"不安全"警告直接关掉页面；再修好后又发现监控没部署，半夜服务挂了都没人知道。上线不是一条命令的事，而是一套需要逐项检查的系统工程。

## 学习目标

- 整合阶段 7 所有技能，完成生产级部署
- 编写上线检查清单
- 验证系统在生产环境的稳定性

## 上线检查清单

### 安全检查

- [ ] 所有密钥已从代码中移除，使用环境变量
- [ ] HTTPS 已配置，HTTP 自动重定向
- [ ] 安全 Headers 已添加
- [ ] CORS 只允许指定域名
- [ ] 数据库不是默认密码
- [ ] Redis 已设置密码
- [ ] 提示注入检测已启用
- [ ] 敏感信息过滤已启用

### 性能检查

- [ ] 数据库索引已创建
- [ ] Redis 缓存已配置
- [ ] API 响应时间 < 200ms（不含 LLM 调用）
- [ ] 前端资源已压缩
- [ ] CDN 已配置

### 可靠性检查

- [ ] 健康检查端点已配置
- [ ] 数据库备份已配置
- [ ] 日志聚合已配置
- [ ] 告警规则已配置
- [ ] 错误追踪已集成

### 部署检查

- [ ] CI/CD 流水线正常
- [ ] 数据库迁移已执行
- [ ] Docker 镜像已推送
- [ ] 环境变量已配置
- [ ] 域名已解析

## 一键部署脚本

```bash
#!/bin/bash
# deploy.sh

set -e

echo "🚀 开始部署..."

# 1. 拉取最新代码
git pull origin main

# 2. 构建镜像
docker compose build

# 3. 执行数据库迁移
docker compose run --rm backend alembic upgrade head

# 4. 启动服务
docker compose up -d

# 5. 等待健康检查
echo "⏳ 等待服务启动..."
sleep 30

# 6. 检查服务状态
docker compose ps

# 7. 运行冒烟测试
curl -f http://localhost/health || exit 1

echo "✅ 部署完成！"
```

## 回滚脚本

```bash
#!/bin/bash
# rollback.sh

PREVIOUS_VERSION=$1

if [ -z "$PREVIOUS_VERSION" ]; then
    echo "Usage: ./rollback.sh <version>"
    exit 1
fi

echo "🔄 回滚到版本 $PREVIOUS_VERSION..."

# 拉取上一版本镜像
docker compose pull

# 回滚数据库（如果有迁移）
# docker compose run --rm backend alembic downgrade -1

# 重启服务
docker compose up -d

echo "✅ 回滚完成！"
```

## 验收标准

- [ ] `./deploy.sh` 一键部署成功
- [ ] 所有服务健康检查通过
- [ ] HTTPS 正常工作
- [ ] WebSocket/SSE 流式响应正常
- [ ] 监控看板显示正常
- [ ] 告警规则生效

## 常见误区

跳过上线检查清单直接部署是最大的隐患——每次"这次先跳过，下次补上"都会留下技术债务。回滚脚本没有提前测试过，等到真正需要回滚时才发现脚本跑不通。监控和告警在上线后才配置，导致上线初期出了问题只能被动响应用户投诉。

## 工程建议

上线前必须按清单逐项打勾，任何一项未通过都不应部署。回滚脚本要在 staging 环境验证过才能上线——紧急回滚时没有时间调试脚本。上线当天选择业务低峰期执行，并安排至少两个人在线，一人操作一人观察监控面板和日志。
