# 06 线上监控与告警

> 看不见问题就解决不了问题——监控是运维的眼睛。

## 场景引入

凌晨三点，用户反馈 AI Agent 回复超时。你登录服务器看了半天日志，发现是数据库连接池耗尽导致请求排队，但等到发现时已经影响了上百个用户。如果早点有监控看板和自动告警，在连接池使用率突破 80% 时就通知你，完全可以在用户感知前主动介入处理。

## 学习目标

- 部署 Prometheus + Grafana 监控
- 配置告警规则
- 实现日志聚合

## Docker Compose 添加监控

```yaml
  prometheus:
    image: prom/prometheus
    volumes:
      - ./prometheus/prometheus.yml:/etc/prometheus/prometheus.yml
    ports:
      - "9090:9090"

  grafana:
    image: grafana/grafana
    environment:
      GF_SECURITY_ADMIN_PASSWORD: ${GRAFANA_PASSWORD:-admin}
    ports:
      - "3001:3000"
    volumes:
      - grafanadata:/var/lib/grafana

  alertmanager:
    image: prom/alertmanager
    volumes:
      - ./alertmanager/alertmanager.yml:/etc/alertmanager/alertmanager.yml
    ports:
      - "9093:9093"
```

## Prometheus 配置

```yaml
# prometheus/prometheus.yml
global:
  scrape_interval: 15s

scrape_configs:
  - job_name: 'backend'
    static_configs:
      - targets: ['backend:8000']
    metrics_path: '/metrics'

  - job_name: 'postgres'
    static_configs:
      - targets: ['postgres-exporter:9187']

  - job_name: 'redis'
    static_configs:
      - targets: ['redis-exporter:9121']
```

## 告警规则

```yaml
# prometheus/alert_rules.yml
groups:
  - name: ai-platform
    rules:
      - alert: HighErrorRate
        expr: rate(http_requests_total{status=~"5.."}[5m]) > 0.05
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "错误率超过 5%"
      
      - alert: HighLatency
        expr: histogram_quantile(0.95, rate(http_request_duration_seconds_bucket[5m])) > 2
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "P95 延迟超过 2 秒"
      
      - alert: HighLLMCost
        expr: sum(rate(llm_cost_total[1h])) > 10
        for: 1h
        labels:
          severity: warning
        annotations:
          summary: "LLM 每小时成本超过 $10"
```

## 常见误区

| 错误 | 原因 | 解决 |
|------|------|------|
| 盲告警 | 阈值设太低 | 根据业务调整阈值 |
| 告警疲劳 | 太多不重要的告警 | 只告警需要人工介入的 |
| 监控数据丢失 | 存储不够 | 配置数据保留策略 |

## 工程建议

告警规则只覆盖需要人工介入的场景——如果一条告警触发后你什么都不用做，那它就不该存在。Prometheus 数据默认保留 15 天，生产环境建议根据磁盘空间调整为 30-90 天。AI 应用特有的指标（如 LLM 调用成本、Token 用量、模型延迟）必须纳入监控，这些是传统 Web 应用不会关注但直接影响运营成本的关键指标。

## 本节要点

- Prometheus + Grafana 是最流行的监控方案
- 告警规则要覆盖关键指标
- 日志聚合方便排查问题
