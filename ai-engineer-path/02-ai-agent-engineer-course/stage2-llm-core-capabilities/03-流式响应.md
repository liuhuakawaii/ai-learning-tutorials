# 03 流式响应

> 用户等 3 秒看到第一个字，比等 10 秒看到完整回答，体验好 10 倍。

## 场景引入

你的 AI 客服上线了，但用户反馈体验很差：点发送后要等 8-10 秒才看到回复，期间没有任何反馈，以为系统卡死了。相比之下，ChatGPT 打字机一样的逐字输出体验流畅得多。这就是流式输出的价值——不是让 AI 回答更快，而是让用户感知延迟从 10 秒降到 0.2 秒。但流式实现涉及 SSE 协议、前后端协同、中断处理等一系列工程问题。

## 学习目标

- 理解 SSE（Server-Sent Events）协议
- 实现后端流式输出
- 实现前端逐字渲染
- 处理流式中断、错误恢复、取消请求

## 前置要求

- 已完成后端 API 和前端对话界面
- 了解 HTTP 协议和异步编程

## 为什么需要流式

LLM 生成一个完整回答需要 5-30 秒。如果等生成完再返回，用户会以为系统卡死了。流式输出让用户看到 AI 一个字一个字"打出来"，感知延迟从 10 秒降到 0.2 秒。

```
非流式：用户等待 10 秒 → 突然出现一大段文字
流式：  用户等待 0.2 秒 → 看到第一个字 → 逐字出现 → 完成
```

## SSE 协议

SSE（Server-Sent Events）是 HTTP 的一部分，专门为"服务器向客户端推送数据"设计。

```
HTTP/1.1 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive

data: {"content": "你"}
data: {"content": "好"}
data: {"content": "，"}
data: {"content": "世界"}
data: [DONE]
```

## 后端流式实现

```python
# backend/app/api/v1/chat.py
from fastapi import APIRouter, Depends
from fastapi.responses import StreamingResponse
import json

@router.post("/sessions/{session_id}/messages/stream")
async def send_message_stream(
    session_id: str,
    request: SendMessageRequest,
    chat_service: ChatService = Depends(get_chat_service),
):
    """流式发送消息"""
    
    async def event_generator():
        try:
            # 1. 保存用户消息
            await chat_service.save_user_message(session_id, request.message)
            
            # 2. 构建上下文
            context = await chat_service.build_context(session_id, request.message)
            
            # 3. 流式调用 LLM
            full_content = ""
            async for chunk in chat_service.stream_llm_call(context):
                full_content += chunk
                # 发送 SSE 事件
                yield f"data: {json.dumps({'content': chunk}, ensure_ascii=False)}\n\n"
            
            # 4. 保存 AI 回复
            await chat_service.save_ai_message(session_id, full_content)
            
            # 5. 发送完成信号
            yield f"data: {json.dumps({'done': True, 'content': full_content}, ensure_ascii=False)}\n\n"
            
        except Exception as e:
            yield f"data: {json.dumps({'error': str(e)}, ensure_ascii=False)}\n\n"
    
    return StreamingResponse(
        event_generator(),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "Connection": "keep-alive",
            "X-Accel-Buffering": "no",  # 禁用 Nginx 缓冲
        },
    )
```

### 流式 LLM 调用

```python
# backend/app/services/llm_service.py
from openai import AsyncOpenAI

class LLMService:
    def __init__(self):
        self.client = AsyncOpenAI()
    
    async def stream_chat(
        self,
        messages: list[dict],
        model: str = "gpt-4o",
        **kwargs,
    ):
        """流式调用 LLM"""
        stream = await self.client.chat.completions.create(
            model=model,
            messages=messages,
            stream=True,
            stream_options={"include_usage": True},
            **kwargs,
        )
        
        async for chunk in stream:
            if chunk.choices and chunk.choices[0].delta.content:
                yield chunk.choices[0].delta.content
            
            # 最后一个 chunk 包含 usage 信息
            if chunk.usage:
                yield {
                    "type": "usage",
                    "input_tokens": chunk.usage.prompt_tokens,
                    "output_tokens": chunk.usage.completion_tokens,
                }
```

## 前端流式渲染

```typescript
// frontend/src/api/chat.ts
export const chatApi = {
  // ... 其他方法 ...
  
  /**
   * 流式发送消息
   * @returns AsyncGenerator，逐个返回 token
   */
  async *sendMessageStream(
    sessionId: string,
    message: string,
    signal?: AbortSignal,
  ): AsyncGenerator<{ content?: string; done?: boolean; error?: string }> {
    const response = await fetch(`/api/v1/chat/sessions/${sessionId}/messages/stream`, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${localStorage.getItem('token')}`,
      },
      body: JSON.stringify({ message }),
      signal,
    })
    
    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`)
    }
    
    const reader = response.body!.getReader()
    const decoder = new TextDecoder()
    let buffer = ''
    
    while (true) {
      const { done, value } = await reader.read()
      if (done) break
      
      buffer += decoder.decode(value, { stream: true })
      
      // 解析 SSE 事件
      const lines = buffer.split('\n')
      buffer = lines.pop() || ''  // 最后一个可能不完整
      
      for (const line of lines) {
        if (line.startsWith('data: ')) {
          const data = line.slice(6)
          if (data === '[DONE]') return
          
          try {
            yield JSON.parse(data)
          } catch {
            // 忽略解析错误
          }
        }
      }
    }
  },
}
```

### 对话页面集成流式

```vue
<!-- frontend/src/views/Chat.vue (关键部分) -->
<script setup lang="ts">
import { ref } from 'vue'
import { chatApi } from '@/api/chat'

const streamingContent = ref('')
const isStreaming = ref(false)
let abortController: AbortController | null = null

async function handleSend() {
  if (!inputText.value.trim() || !currentSessionId.value) return
  
  const userMessage = inputText.value
  inputText.value = ''
  
  // 乐观更新：显示用户消息
  messages.value.push({
    id: `temp-user-${Date.now()}`,
    role: 'user',
    content: userMessage,
    created_at: new Date().toISOString(),
    token_usage: 0,
  })
  
  // 添加空的 AI 消息占位
  const aiMessageId = `temp-ai-${Date.now()}`
  messages.value.push({
    id: aiMessageId,
    role: 'assistant',
    content: '',
    created_at: new Date().toISOString(),
    token_usage: 0,
  })
  
  // 开始流式接收
  isStreaming.value = true
  streamingContent.value = ''
  abortController = new AbortController()
  
  try {
    for await (const chunk of chatApi.sendMessageStream(
      currentSessionId.value,
      userMessage,
      abortController.signal,
    )) {
      if (chunk.error) {
        throw new Error(chunk.error)
      }
      if (chunk.content) {
        streamingContent.value += chunk.content
        // 更新消息列表中的 AI 消息
        const aiMsg = messages.value.find(m => m.id === aiMessageId)
        if (aiMsg) {
          aiMsg.content = streamingContent.value
        }
      }
      if (chunk.done) {
        break
      }
    }
  } catch (error) {
    if (error instanceof DOMException && error.name === 'AbortError') {
      // 用户取消
    } else {
      handleError(error)
    }
  } finally {
    isStreaming.value = false
    abortController = null
  }
}

function cancelStream() {
  abortController?.abort()
}
</script>
```

## 中断与恢复

用户可能在流式输出过程中刷新页面或关闭浏览器。需要处理：

1. **前端中断**：AbortController 取消请求
2. **后端中断检测**：检测客户端断开连接
3. **未完成回复处理**：标记为"中断"，支持重新生成

```python
# 后端检测客户端断开
from fastapi import Request

async def stream_with_disconnect_detection(request: Request):
    async def event_generator():
        async for chunk in llm_service.stream_chat(messages):
            # 检查客户端是否断开
            if await request.is_disconnected():
                # 客户端断开，停止生成
                break
            
            yield f"data: {json.dumps({'content': chunk})}\n\n"
    
    return StreamingResponse(event_generator(), media_type="text/event-stream")
```

## 本节要点

- SSE 是流式输出的标准协议，比 WebSocket 更简单
- 流式输出显著改善用户体验，感知延迟从 10 秒降到 0.2 秒
- 前端用 AsyncGenerator 处理流式数据，代码更干净
- 必须处理中断和取消，否则会浪费 LLM API 费用

## 常见误区

| 错误 | 原因 | 解决 |
|------|------|------|
| 流式不生效 | Nginx 缓冲了响应 | 加 `X-Accel-Buffering: no` 头 |
| 前端接收不到数据 | CORS 没配置 SSE | 确保 CORS 允许 `text/event-stream` |
| 内存泄漏 | 事件监听器没清理 | 在组件卸载时取消请求 |
| 重复消息 | 乐观更新后又收到了响应 | 用统一的消息 ID 去重 |

## 工程建议

- 生产环境如果有 Nginx 反向代理，必须配置 `proxy_buffering off` 和 `X-Accel-Buffering: no`，否则流式输出会被缓冲
- 前端要用 AbortController 实现请求取消，用户点"停止生成"时能立即断开连接，避免浪费 API 费用
- 流式输出过程中要记录 token 用量，最后一个 chunk 通常包含 usage 信息，不要遗漏
- 流式连接超时要合理设置（建议 120 秒），LLM 生成长回答时可能需要较长时间
- 前后端都要做断线检测：后端检查客户端是否断开，前端实现自动重连机制
