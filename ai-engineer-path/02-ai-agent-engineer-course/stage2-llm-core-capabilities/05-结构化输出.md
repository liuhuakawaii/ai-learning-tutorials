## 为什么需要结构化输出

AI 的自由文本输出适合聊天，但不适合应用。你的代码需要知道：

- 用户意图是什么？（分类）
- 提取了哪些实体？（字段）
- 评分是多少？（数字）
- 建议的操作是什么？（枚举）

```python
# 不好：自由文本
response = "用户想要退款，订单号是 12345，原因是商品质量问题"

# 好：结构化输出
response = {
    "intent": "refund_request",
    "order_id": "12345",
    "reason": "product_quality",
    "confidence": 0.95,
    "suggested_action": "transfer_to_refund_team"
}
```

## JSON Schema 定义

```python
# backend/app/schemas/structured.py
from pydantic import BaseModel, Field
from enum import Enum

class Intent(str, Enum):
    REFUND = "refund"
    INQUIRY = "inquiry"
    COMPLAINT = "complaint"
    ORDER_STATUS = "order_status"
    OTHER = "other"

class Sentiment(str, Enum):
    POSITIVE = "positive"
    NEUTRAL = "neutral"
    NEGATIVE = "negative"

class MessageAnalysis(BaseModel):
    """消息分析结果"""
    intent: Intent = Field(description="用户意图分类")
    sentiment: Sentiment = Field(description="用户情感")
    confidence: float = Field(ge=0, le=1, description="置信度")
    entities: dict[str, str] = Field(
        default_factory=dict,
        description="提取的实体，如 order_id, product_name",
    )
    summary: str = Field(max_length=200, description="一句话摘要")
    suggested_action: str = Field(description="建议的下一步操作")
```

## OpenAI 结构化输出

OpenAI 提供两种方式实现结构化输出：

### 方式 1：JSON Mode

```python
response = await client.chat.completions.create(
    model="gpt-4o",
    messages=[...],
    response_format={"type": "json_object"},
)
# 返回的是 JSON 字符串，需要手动解析
result = json.loads(response.choices[0].message.content)
```

### 方式 2：Structured Outputs（推荐）

```python
from openai.lib._pydantic import to_strict_json_schema

# 将 Pydantic 模型转为 JSON Schema
schema = to_strict_json_schema(MessageAnalysis)

response = await client.chat.completions.create(
    model="gpt-4o",
    messages=[...],
    response_format={
        "type": "json_schema",
        "json_schema": {
            "name": "message_analysis",
            "strict": True,
            "schema": schema,
        },
    },
)

# 直接解析为 Pydantic 模型
result = MessageAnalysis.model_validate_json(
    response.choices[0].message.content
)
```

### 方式 3：Function Calling 强制输出

```python
response = await client.chat.completions.create(
    model="gpt-4o",
    messages=[...],
    tools=[{
        "type": "function",
        "function": {
            "name": "analyze_message",
            "description": "分析用户消息",
            "parameters": to_strict_json_schema(MessageAnalysis),
        },
    }],
    tool_choice={"type": "function", "function": {"name": "analyze_message"}},
)

# 解析工具调用结果
tool_call = response.choices[0].message.tool_calls[0]
result = MessageAnalysis.model_validate_json(tool_call.function.arguments)
```

## 完整封装

```python
# backend/app/services/structured_service.py
from pydantic import BaseModel
from openai import AsyncOpenAI
from openai.lib._pydantic import to_strict_json_schema
import json

class StructuredLLMService:
    """结构化输出服务"""
    
    def __init__(self):
        self.client = AsyncOpenAI()
    
    async def extract[T: BaseModel](
        self,
        messages: list[dict],
        schema: type[T],
        model: str = "gpt-4o",
        max_retries: int = 3,
    ) -> T:
        """从 LLM 输出中提取结构化数据"""
        
        # 构建 schema
        json_schema = to_strict_json_schema(schema)
        
        for attempt in range(max_retries):
            try:
                response = await self.client.chat.completions.create(
                    model=model,
                    messages=messages,
                    response_format={
                        "type": "json_schema",
                        "json_schema": {
                            "name": schema.__name__,
                            "strict": True,
                            "schema": json_schema,
                        },
                    },
                )
                
                content = response.choices[0].message.content
                return schema.model_validate_json(content)
            
            except Exception as e:
                if attempt == max_retries - 1:
                    raise
                # 重试前在 Prompt 中加入错误信息
                messages.append({
                    "role": "assistant",
                    "content": content if 'content' in dir() else "",
                })
                messages.append({
                    "role": "user",
                    "content": f"输出格式错误：{e}。请重新输出正确的 JSON。",
                })
```

### 场景 2：工单生成

```python
class SupportTicket(BaseModel):
    title: str = Field(description="工单标题")
    description: str = Field(description="详细描述")
    priority: str = Field(description="优先级：low/medium/high/urgent")
    category: str = Field(description="分类：billing/technical/account/other")
    customer_sentiment: Sentiment
    suggested_assignee: str = Field(description="建议处理人或团队")

async def create_ticket_from_conversation(
    messages: list[dict],
) -> SupportTicket:
    """从对话历史自动生成工单"""
    conversation = "\n".join(
        f"{m['role']}: {m['content']}" for m in messages
    )
    
    return await structured_llm.extract(
        messages=[{
            "role": "user",
            "content": f"根据以下对话，生成一个客服工单：\n\n{conversation}",
        }],
        schema=SupportTicket,
    )
```

## 处理输出失败

LLM 的结构化输出不是 100% 可靠的。需要处理：

```python
async def safe_extract[T: BaseModel](
    messages: list[dict],
    schema: type[T],
    model: str = "gpt-4o",
    fallback: T | None = None,
) -> T | None:
    """安全的结构化提取，失败时返回 fallback"""
    try:
        return await structured_llm.extract(messages, schema, model)
    except Exception as e:
        logger.error(f"Structured extraction failed: {e}")
        
        # 尝试用更简单的 Prompt 重试
        try:
            simple_prompt = f"""
            请严格按以下 JSON 格式输出：
            {schema.model_json_schema()}
            
            用户输入：{messages[-1]['content']}
            """
            return await structured_llm.extract(
                [{"role": "user", "content": simple_prompt}],
                schema,
                model,
            )
        except Exception:
            return fallback
```

## 本节要点

- 结构化输出是 AI 从"聊天"到"应用"的关键桥梁
- Pydantic + JSON Schema = 类型安全的 AI 输出
- 输出失败是常态，必须有重试和降级机制
- 不同场景选择不同模型（分类用便宜模型，复杂提取用强模型）

## 常见错误

| 错误 | 原因 | 解决 |
|------|------|------|
| JSON 解析失败 | LLM 输出了非 JSON 内容 | 用 `response_format` 强制 JSON |
| 字段类型错误 | LLM 返回了错误类型 | 用 `strict: True` 模式 |
| 漏字段 | LLM 没有输出所有字段 | 在 Prompt 中强调"必须包含所有字段" |
| 输出太慢 | 用了太大的模型做简单分类 | 分类任务用 `gpt-4o-mini` |
