# 04 流式多模态输出——图文混排、语音流式输出的前端渲染

> 流式输出提升用户体验，多模态流式输出更复杂。

## 场景引入

你的多模态助手已经能处理文本、图片、语音、文档，但用户体验不好——每次点击"发送"后要等 5-8 秒才能看到完整回答，语音回答更是要等 10 秒以上。产品经理要求"边生成边显示"：文本逐字输出、图片嵌入到对应位置、语音流式播放。流式多模态输出的技术挑战在于：文本流、图片流、音频流三种不同类型的输出需要在前端协调渲染，任何一个流的延迟都会影响整体体验。

## 学习目标

- 掌握流式多模态输出的方法
- 理解图文混排的渲染
- 学会实现语音流式输出

## 一、流式文本输出

```python
async def stream_text_response(question: str):
    """流式文本输出"""
    stream = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": question}],
        stream=True
    )
    
    for chunk in stream:
        if chunk.choices[0].delta.content:
            yield chunk.choices[0].delta.content
```

## 二、流式语音输出

```python
async def stream_audio_response(text: str):
    """流式语音输出"""
    communicate = edge_tts.Communicate(text, "zh-CN-XiaoxiaoNeural")
    
    async for chunk in communicate.stream():
        if chunk["type"] == "audio":
            yield chunk["data"]
```

## 三、图文混排

```python
def render_multimodal_response(text: str, images: list) -> str:
    """渲染图文混排"""
    # Markdown 格式
    content = text
    
    for i, image in enumerate(images):
        content += f"\n\n![图片{i+1}]({image})"
    
    return content
```

## 五、流式渲染

```javascript
// 流式渲染
const response = await fetch('/api/stream', {
  method: 'POST',
  body: JSON.stringify({ question })
});

const reader = response.body.getReader();
const decoder = new TextDecoder();

while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  
  const text = decoder.decode(value);
  appendToChat(text);
}
```

## 常见误区

1. **只做文本流式输出不做多模态流式**：文本是流式的但图片和音频还是同步返回，用户体验仍然很差，需要三种流协调输出。
2. **不做流的同步和排序**：文本流、图片流、音频流各自独立输出，前端不知道图片应该插在哪里，需要统一的排序机制。
3. **忽略前端的渲染性能**：大量流式数据涌入会导致前端卡顿，需要做节流和批量渲染。
4. **不做流式输出的错误处理**：流式过程中某个环节失败（如图片生成失败），需要优雅降级而不是中断整个输出。

## 工程建议

1. **用 SSE 或 WebSocket 做流式传输**：SSE 适合单向推送，WebSocket 适合双向交互，根据场景选择合适的流式协议。
2. **定义统一的流式消息格式**：所有模态的流式输出用统一的消息格式（type, content, index, is_final），前端统一处理。
3. **前端做节流和批量渲染**：每 50-100ms 渲染一次，避免每次 chunk 都触发 DOM 更新导致卡顿。
4. **做流式中断和恢复**：用户可以随时中断流式输出，系统支持从断点恢复或重新生成。
