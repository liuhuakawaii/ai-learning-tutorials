# 05 性能与成本——多模态调用的 Token 计算、延迟优化、缓存策略

> 多模态应用的性能和成本优化是生产部署的关键。

## 场景引入

你的多模态 AI 助手上线一周后，财务告诉你：API 调用费用是预期的 3 倍，用户反馈延迟太高。分析后发现：一张 5MB 的图片直接传给 GPT-4o 消耗了 1000+ tokens，压缩到 500KB 后只需 85 tokens；很多用户的重复查询每次都要调 API，缓存命中率为 0；简单的文本分类任务用 GPT-4o 太浪费，用 GPT-4o-mini 效果一样但便宜 10 倍。多模态应用的性能和成本优化是上线后的第一要务。

## 学习目标

- 掌握多模态调用的成本计算
- 理解延迟优化的方法
- 学会设计缓存策略

## 一、成本计算

```
多模态 API 成本：

GPT-4o 图片处理：
- 每张图片约 85-170 tokens
- 取决于图片分辨率

GPT-4o 音频处理：
- 每分钟约 25-50 tokens
- 取决于音频质量

总成本 = 文本 tokens + 图片 tokens + 音频 tokens
```

## 二、Token 计算

```python
def calculate_multimodal_tokens(text: str, images: list, audio_duration: float) -> dict:
    """计算多模态 Token"""
    text_tokens = count_tokens(text)
    image_tokens = len(images) * 170  # 每张图片约 170 tokens
    audio_tokens = audio_duration * 50  # 每分钟约 50 tokens
    
    return {
        "text": text_tokens,
        "images": image_tokens,
        "audio": audio_tokens,
        "total": text_tokens + image_tokens + audio_tokens
    }
```

## 四、缓存策略

```python
class MultimodalCache:
    """多模态缓存"""
    
    def __init__(self):
        self.cache = {}
    
    def get(self, key: str):
        """获取缓存"""
        return self.cache.get(key)
    
    def set(self, key: str, value, ttl: int = 3600):
        """设置缓存"""
        self.cache[key] = {
            "value": value,
            "expires": time.time() + ttl
        }
    
    def get_or_compute(self, key: str, compute_fn):
        """获取或计算"""
        cached = self.get(key)
        if cached and cached["expires"] > time.time():
            return cached["value"]
        
        value = compute_fn()
        self.set(key, value)
        return value
```

## 六、监控

```python
class PerformanceMonitor:
    """性能监控"""
    
    def __init__(self):
        self.metrics = {
            "requests": 0,
            "tokens": 0,
            "latency": [],
            "cost": 0
        }
    
    def record(self, tokens: int, latency: float, cost: float):
        """记录指标"""
        self.metrics["requests"] += 1
        self.metrics["tokens"] += tokens
        self.metrics["latency"].append(latency)
        self.metrics["cost"] += cost
    
    def get_summary(self) -> dict:
        """获取摘要"""
        return {
            "total_requests": self.metrics["requests"],
            "avg_latency": sum(self.metrics["latency"]) / len(self.metrics["latency"]),
            "total_cost": self.metrics["cost"]
        }
```

## 常见误区

1. **不做 Token 估算就上线**：多模态 API 的 token 消耗远高于纯文本，不做成本预估就上线可能导致月度账单远超预算。
2. **所有任务都用最贵的模型**：简单的文本分类用 GPT-4o 是浪费，应该按任务复杂度分级使用模型。
3. **不做缓存**：相同查询每次都调 API，浪费大量成本和延迟，简单的缓存策略就能节省 50%+ 的 API 调用。
4. **只关注延迟不关注吞吐量**：优化了单次请求的延迟，但没有考虑并发场景下的吞吐量，高并发时系统会崩溃。

## 工程建议

1. **上线前做成本预算**：估算每种 API 调用的 token 消耗 × 单价 × 预期调用量，设置月度预算告警。
2. **按任务复杂度分级用模型**：简单任务用 GPT-4o-mini，复杂推理用 GPT-4o，代码任务用 Claude，按需选择最经济的模型。
3. **实现多级缓存**：内存缓存（热点数据）→ Redis 缓存（共享数据）→ 语义缓存（相似查询），逐级扩大缓存覆盖范围。
4. **建立性能监控看板**：实时监控 API 调用量、token 消耗、延迟分布、缓存命中率、错误率，设置告警阈值。
