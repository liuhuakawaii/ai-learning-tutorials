# 02 图文混合索引——将图片和文本存储到同一个向量空间

> 图文混合索引是多模态 RAG 的基础。

## 场景引入

你要为一个多模态知识库系统设计存储层：知识库中既有纯文本的技术文档，也有包含大量图表的产品手册，还有产品实拍图片。用户可能用文字查询（"安装步骤"），也可能用图片查询（上传一张零件照片找对应的说明书）。你需要把图片向量和文本向量存储在同一个向量数据库中，支持跨模态检索。选择 ChromaDB、Milvus 还是 pgvector？索引如何设计才能兼顾检索速度和准确率？这些都是构建多模态索引需要解决的核心问题。

## 学习目标

- 掌握图文混合索引的设计方法

## 二、ChromaDB 使用

```python
import chromadb

# 创建客户端
client = chromadb.Client()

# 创建集合
collection = client.create_collection(
    name="multimodal",
    metadata={"hnsw:space": "cosine"}
)

# 添加图片向量
collection.add(
    ids=["img_1", "img_2"],
    embeddings=[img_embedding_1, img_embedding_2],
    metadatas=[{"type": "image"}, {"type": "image"}]
)

# 添加文本向量
collection.add(
    ids=["txt_1", "txt_2"],
    embeddings=[txt_embedding_1, txt_embedding_2],
    metadatas=[{"type": "text"}, {"type": "text"}]
)
```

def multimodal_search(query: str, query_type: str = "text") -> list:
    """多模态检索"""
    if query_type == "text":
        query_embedding = get_text_embedding(query)
    else:
        query_embedding = get_image_embedding(query)
    
    results = search(query_embedding)

## 五、索引管理

```python
class MultimodalIndex:
    """多模态索引"""
    
    def __init__(self):
        self.client = chromadb.Client()
        self.collection = self.client.create_collection("multimodal")
    
    def add_image(self, image_path: str, metadata: dict = None):
        """添加图片"""
        embedding = get_image_embedding(image_path)
        self.collection.add(
            ids=[f"img_{hash(image_path)}"],
            embeddings=[embedding],
            metadatas=[{"type": "image", "path": image_path, **(metadata or {})}]
        )
    
    def add_text(self, text: str, metadata: dict = None):
        """添加文本"""
        embedding = get_text_embedding(text)
        self.collection.add(
            ids=[f"txt_{hash(text)}"],
            embeddings=[embedding],
            metadatas=[{"type": "text", "content": text, **(metadata or {})}]
        )
    
    def search(self, query: str, query_type: str = "text", top_k: int = 5):
        """检索"""
        if query_type == "text":
            embedding = get_text_embedding(query)
        else:
            embedding = get_image_embedding(query)
        
        return self.collection.query(
            query_embeddings=[embedding],
            n_results=top_k
        )
```

## 常见误区

1. **把所有向量存到一个 collection**：图片向量和文本向量的维度可能不同、检索策略不同，混存会导致检索效率低下，建议按模态分 collection 或加 metadata 标记。
2. **不做向量数据库的持久化**：默认的内存模式重启后数据丢失，生产环境必须配置持久化存储。
3. **忽略索引构建的时间成本**：百万级向量的索引构建可能需要几小时，需要做增量索引而不是全量重建。
4. **不做检索结果的去重和过滤**：同一张图片可能被多次索引，不做去重会返回重复结果。

## 工程建议

1. **原型用 ChromaDB，生产用 Milvus**：ChromaDB 简单易用适合快速验证，Milvus 高性能适合生产环境，pgvector 适合已有 PostgreSQL 的团队。
2. **用 metadata 做预过滤**：存储时给每个向量加 metadata（类型、来源、时间），检索时先用 metadata 过滤再做向量匹配，大幅提高检索效率。
3. **做增量索引**：新增内容只索引增量部分，不做全量重建，节省时间和计算资源。
4. **定期做索引质量评估**：用标准查询测试检索准确率，发现向量质量问题及时重新索引。
