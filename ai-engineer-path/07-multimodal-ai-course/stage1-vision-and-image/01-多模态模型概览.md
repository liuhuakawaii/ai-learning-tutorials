## 一、什么是多模态

```
模态（Modality）= 信息的类型

  文本模态：文字、代码、表格
  视觉模态：图片、视频、图表
  音频模态：语音、音乐、环境声
  文档模态：PDF、Word、扫描件

  单模态模型：只能处理一种类型
  多模态模型：能处理多种类型

  ┌─────────────────────────────────────────────────────────┐
  │                    多模态能力图谱                         │
  │                                                         │
  │  文本 ◄──────────────────────────────────────► 图片     │
  │    │          多模态大模型                    │         │
  │    │         ┌────────────┐                   │         │
  │    │         │  GPT-4o    │                   │         │
  │    │         │  Claude    │                   │         │
  │    │         │  Gemini    │                   │         │
  │    │         │  Qwen-VL   │                   │         │
  │    │         └────────────┘                   │         │
  │    │                                          │         │
  │    ▼                                          ▼         │
  │  音频 ◄──────────────────────────────────────► 视频     │
  │                                                         │
└─────────────────────────────────────────────────────────┘
```

## 二、主流多模态模型详解

### 2.1 GPT-4o（OpenAI）

```
GPT-4o 能力矩阵：

  ┌──────────────┬────────┬──────────────────────────────────┐
  │  模态        │ 支持   │ 具体能力                          │
  ├──────────────┼────────┼──────────────────────────────────┤
  │  文本输入     │ ✓      │ 自然语言、代码、表格              │
  │  文本输出     │ ✓      │ 自然语言、代码、JSON              │
  │  图片输入     │ ✓      │ 图片理解、OCR、图表分析           │
  │  图片生成     │ ✓      │ DALL-E 3 集成                    │
  │  音频输入     │ ✓      │ Whisper 语音识别                  │
  │  音频输出     │ ✓      │ TTS 语音合成                     │
  │  视频输入     │ ✗      │ 不直接支持（需抽帧为图片）         │
  │  文件输入     │ ✓      │ PDF、Word 等文档解析              │
  └──────────────┴────────┴──────────────────────────────────┘

  特点：
  - 能力最全面，文本/图片/音频全覆盖
  - 响应速度快（o 版本优化了延迟）
  - 生态最成熟，文档和社区支持最好
  - 价格中等

  局限：
  - 视频不直接支持
  - 图片理解有时会"编造"细节
  - 中文能力不如专门的中文模型
```

  │  文本输入     │ ✓      │ 自然语言、代码、表格              │
  │  文本输出     │ ✓      │ 自然语言、代码、JSON              │

  │  音频输出     │ ✗      │ 不支持                           │
  │  视频输入     │ ✗      │ 不支持                           │

## 四、API 调用示例

### 4.1 GPT-4o 图片理解

```python
from openai import OpenAI

client = OpenAI()

# 方式 1：URL 图片
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "这张图片里有什么？请详细描述。"},
                {
                    "type": "image_url",
                    "image_url": {
                        "url": "https://example.com/product.jpg"
                    }
                }
            ]
        }
    ]
)
print(response.choices[0].message.content)

# 方式 2：Base64 图片
import base64

with open("local_image.jpg", "rb") as f:
    image_base64 = base64.b64encode(f.read()).decode()

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "提取图片中的文字"},
                {
                    "type": "image_url",
                    "image_url": {
                        "url": f"data:image/jpeg;base64,{image_base64}"
                    }
                }
            ]
        }
    ]
)
```

### 4.2 Claude Vision 图片分析

```python
import anthropic

client = anthropic.Anthropic()

with open("chart.png", "rb") as f:
    image_base64 = base64.b64encode(f.read()).decode()

response = client.messages.create(
    model="claude-sonnet-4-20250514",
    max_tokens=1024,
    messages=[
        {
            "role": "user",
            "content": [
                {
                    "type": "image",
                    "source": {
                        "type": "base64",
                        "media_type": "image/png",
                        "data": image_base64,
                    }
                },
                {
                    "type": "text",
                    "text": "分析这个图表的趋势和关键数据点。"
                }
            ]
        }
    ]
)
print(response.content[0].text)
```

## 五、成本估算

```
多模态 API 的成本构成：

  文本：按 token 计费（与普通 LLM 相同）
  图片：按图片尺寸和分辨率计费
  音频：按音频时长计费
  视频：按视频时长计费（Gemini）

  ┌──────────────────────────────────────────────────────────┐
  │  GPT-4o 价格参考（2024 年）                               │
  ├──────────────────────────────────────────────────────────┤
  │  文本输入：$2.50 / 1M tokens                              │
  │  文本输出：$10.00 / 1M tokens                             │
  │  图片输入：$3.825 / 1M tokens（约 $0.005 / 张低分辨率）   │
  │  音频输入：$0.06 / 分钟                                   │
  │  音频输出：$0.24 / 分钟                                   │
  └──────────────────────────────────────────────────────────┘

  成本优化建议：
  1. 图片先压缩再传（降低分辨率可大幅降低成本）
  2. 音频先裁剪静音段再传
  3. 简单任务用小模型（GPT-4o-mini 比 GPT-4o 便宜 10 倍）
  4. 缓存重复请求的结果
```

## 六、常见误区

```
误区 1：多模态模型能"看懂"所有图片
  事实：模型对图片的理解有局限，特别是细节、文字、数字
  建议：关键信息用 OCR 提取，不要完全依赖模型的"视觉"

误区 2：所有多模态模型都一样
  事实：不同模型在不同任务上差异很大
  建议：用你的真实数据做对比测试

误区 3：多模态 API 很便宜
  事实：图片和音频的 token 消耗远高于文本
  建议：做好成本预算，使用缓存和压缩

误区 4：多模态 = 万能
  事实：每个模型都有能力边界
  建议：了解模型的局限，设计合理的 fallback 策略
```
