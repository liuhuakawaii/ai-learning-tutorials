你负责一个电商平台的"拍照找同款"功能：用户上传一张商品照片，系统需要自动识别商品类别、提取品牌和型号等关键信息，并生成一段吸引人的商品描述。产品经理给了你一周时间，你发现图片描述、分类、信息提取这三个能力看似简单，但每一步的 prompt 设计、输出格式控制和错误处理都有大量工程细节需要处理。

## 一、图片描述

```python
def describe_image(image_url: str) -> str:
    """图片描述"""
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {
                "role": "user",
                "content": [
                    {"type": "text", "text": "请详细描述这张图片的内容"},
                    {"type": "image_url", "image_url": {"url": image_url}}
                ]
            }
        ]
    )
    return response.choices[0].message.content
```

## 四、多图分析

```python
def compare_images(image_urls: list, question: str) -> str:
    """比较多张图片"""
    content = [{"type": "text", "text": question}]
    
    for url in image_urls:
        content.append({"type": "image_url", "image_url": {"url": url}})
    
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": content}]
    )
    return response.choices[0].message.content
```

## 常见误区

1. **把模型输出直接当数据库字段用**：Vision API 返回的描述是自然语言，不是结构化数据，直接存储会导致后续查询和分析困难，必须先做结构化转换。
2. **忽略图片分辨率对结果的影响**：低分辨率图片会大幅降低 OCR 和细节识别的准确率，上线前必须测试不同分辨率下的表现。
3. **一次性传太多图片**：多图对比虽然方便，但 token 消耗成倍增长，且模型注意力分散后准确率下降，建议控制单次请求的图片数量。
4. **不做输出格式校验**：模型返回的 JSON 可能格式错误或字段缺失，必须做严格的 schema 校验和异常处理。

## 工程建议

1. **优先使用结构化输出**：开启 `response_format={"type": "json_object"}` 强制 JSON 输出，再用 Pydantic 或 JSON Schema 做二次校验。
2. **图片预处理标准化**：统一裁剪、压缩、调整分辨率后再传给 API，既降低成本又提高一致性。
3. **建立评估数据集**：收集 50-100 张典型业务图片和人工标注结果，每次 prompt 调整后跑回归测试。
4. **异步批量处理**：大批量图片用异步并发请求，配合速率限制和重试机制，避免被 API 限流。
