## 二、核心实现

```python
class DocumentParser:
    """文档解析器"""
    
    def __init__(self):
        self.client = OpenAI()
    
    def parse_contract(self, doc_path: str) -> dict:
        """解析合同"""
        # 1. 文档解析
        text = self._extract_text(doc_path)
        
        # 2. 信息提取
        response = self.client.chat.completions.create(
            model="gpt-4o",
            messages=[{
                "role": "user",
                "content": f"""请从以下合同中提取关键信息：
- 合同双方
- 合同金额
- 合同期限
- 付款方式
- 违约条款

合同内容：
{text}

请以 JSON 格式输出。"""
            }],
            response_format={"type": "json_object"}
        )
        
        return json.loads(response.choices[0].message.content)
    
    def parse_invoice(self, doc_path: str) -> dict:
        """解析发票"""
        # 1. 文档解析
        text = self._extract_text(doc_path)
        
        # 2. 信息提取
        response = self.client.chat.completions.create(
            model="gpt-4o",
            messages=[{
                "role": "user",
                "content": f"""请从以下发票中提取关键信息：
- 发票号码
- 开票日期
- 购买方
- 销售方
- 金额
- 税额

发票内容：
{text}

请以 JSON 格式输出。"""
            }],
            response_format={"type": "json_object"}
        )
        
        return json.loads(response.choices[0].message.content)
    
    def _extract_text(self, doc_path: str) -> str:
        """提取文本"""
        elements = parse_document(doc_path)
        return "\n".join([e.text for e in elements])
```

## 四、批量处理

```python
def batch_parse(doc_paths: list, doc_type: str) -> list:
    """批量解析"""
    parser = DocumentParser()
    results = []
    
    for path in doc_paths:
        if doc_type == "contract":
            result = parser.parse_contract(path)
        elif doc_type == "invoice":
            result = parser.parse_invoice(path)
        results.append(result)
    
    return results
```

## 常见误区

1. **用一个 prompt 处理所有文档类型**：合同和发票的结构差异很大，用同一个提取 prompt 效果会很差，应该为每种文档类型设计专用的提取策略。
2. **不做提取结果的格式校验**：LLM 返回的 JSON 可能字段缺失或格式错误，必须做 schema 校验，关键字段（金额、日期）还要做格式验证。
3. **忽略 OCR 错误对下游的影响**：OCR 的识别错误会传递到信息提取环节，关键字段需要做多模型交叉验证或人工抽检。
4. **不做版本管理**：文档解析逻辑和 prompt 经常需要迭代，不做版本管理会导致回滚困难。

## 工程建议

1. **为每种文档类型建立专用 Pipeline**：合同解析和发票解析用不同的 prompt、不同的后处理逻辑，独立优化互不干扰。
2. **用 Pydantic 做输出校验**：定义严格的输出 schema，LLM 返回的结果必须通过 Pydantic 校验，不合格的自动重试或人工处理。
3. **建立质量监控看板**：统计每种文档类型的解析成功率、关键字段准确率、人工复核率，持续优化系统。
4. **保留人工复核环节**：关键文档（大额合同、重要发票）的解析结果必须经过人工复核，不能完全自动化。
