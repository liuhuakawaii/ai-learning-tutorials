# 05 文档问答——基于文档内容的智能问答系统

> 文档问答是文档处理的核心应用场景。

## 场景引入

你要为公司内部构建一个"智能 HR 问答系统"：员工上传员工手册后，可以用自然语言提问，如"年假有多少天？""试用期可以请假吗？""报销流程是什么？"系统需要从文档中找到相关内容并给出准确回答，同时标注引用来源。这看似简单的 RAG 应用，实际面临的问题包括：文档分块不合理导致检索不到相关内容、相似问题的表述差异大导致匹配失败、回答引用了错误的文档段落——文档问答的准确率直接取决于每个环节的工程质量。

## 学习目标

- 掌握文档问答系统的设计
- 理解检索增强生成（RAG）在文档问答中的应用
- 学会构建文档问答系统

## 一、系统架构

```
文档问答系统：

文档 → 解析 → 分块 → 向量化 → 存储
                                │
用户问题 → 向量化 → 检索 → LLM 生成 → 回答
```

## 二、核心实现

```python
class DocumentQA:
    """文档问答"""
    
    def __init__(self):
        self.chunks = []
        self.embeddings = []
        self.client = OpenAI()
    
    def add_document(self, doc_path: str):
        """添加文档"""
        # 解析文档
        elements = parse_document(doc_path)
        
        # 分块
        chunks = semantic_chunking(elements)
        
        # 向量化
        for chunk in chunks:
            embedding = self._get_embedding(chunk)
            self.chunks.append(chunk)
            self.embeddings.append(embedding)
    
    def ask(self, question: str) -> str:
        """提问"""
        # 检索相关块
        question_embedding = self._get_embedding(question)
        relevant_chunks = self._retrieve(question_embedding, top_k=3)
        
        # 生成答案
        context = "\n".join(relevant_chunks)
        answer = self._generate_answer(question, context)
        
        return answer
    
    def _get_embedding(self, text: str) -> list:
        """获取向量"""
        response = self.client.embeddings.create(
            model="text-embedding-3-small",
            input=text
        )
        return response.data[0].embedding
    
    def _retrieve(self, query_embedding: list, top_k: int) -> list:
        """检索"""
        similarities = []
        for i, emb in enumerate(self.embeddings):
            sim = cosine_similarity(query_embedding, emb)
            similarities.append((sim, i))
        
        similarities.sort(reverse=True)
        return [self.chunks[i] for _, i in similarities[:top_k]]
    
    def _generate_answer(self, question: str, context: str) -> str:
        """生成答案"""
        response = self.client.chat.completions.create(
            model="gpt-4o",
            messages=[{
                "role": "user",
                "content": f"基于以下文档内容回答问题：\n\n{context}\n\n问题：{question}"
            }]
        )
        return response.choices[0].message.content
```

## 四、引用溯源

```python
def ask_with_citation(qa: DocumentQA, question: str) -> dict:
    """带引用的问答"""
    # 检索相关块
    relevant_chunks = qa._retrieve(qa._get_embedding(question), top_k=3)
    
    # 生成答案
    answer = qa._generate_answer(question, "\n".join(relevant_chunks))
    
    return {
        "answer": answer,
        "sources": relevant_chunks
    }
```

## 五、Web 界面

```python
import gradio as gr

def document_qa_interface(file, question):
    qa = DocumentQA()
    qa.add_document(file.name)

    return result

demo = gr.Interface(
```

## 常见误区

1. **只用向量检索不用关键词检索**：纯向量检索对精确匹配（如"年假5天"中的"5天"）效果不好，混合检索（向量 + 关键词）能显著提高准确率。
2. **不做引用溯源**：用户需要知道回答来自文档的哪个段落，不做溯源会降低用户信任度，也无法验证回答的准确性。
3. **忽略查询改写**：用户的口语化问题（"请假咋办"）和文档中的书面表述（"请假流程"）差异大，不做查询改写会导致检索失败。
4. **top_k 设置不合理**：top_k 太小会漏掉相关段落，太大会引入噪音，需要根据文档特点调优。

## 工程建议

1. **实现混合检索**：向量检索 + BM25 关键词检索，用 RRF（Reciprocal Rank Fusion）合并结果，兼顾语义匹配和精确匹配。
2. **每个回答必须带引用**：标注回答来自哪个文档的哪个段落，方便用户验证和复核。
3. **做查询改写和扩展**：用 LLM 将用户的口语化问题改写为更接近文档表述的查询，或生成多个变体查询提高召回率。
4. **建立评估数据集**：收集典型问题和标准答案，定期评估问答准确率，发现和修复 bad case。
