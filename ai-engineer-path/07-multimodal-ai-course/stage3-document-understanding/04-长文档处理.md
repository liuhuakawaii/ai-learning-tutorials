# 04 长文档处理——大文档的分块策略与上下文管理

> 长文档处理需要特殊的策略来管理上下文。

## 场景引入

你要构建一个合同审阅系统，用户上传一份 50 页的合同 PDF，系统需要回答"这份合同的违约金条款是什么？"这类具体问题。直接把整份合同扔给 GPT-4o 会超出上下文限制，简单按字数分块又会把一个完整的条款切成两半导致语义断裂。你需要设计一套智能分块策略，让每个 chunk 既不超过 token 限制，又能保持语义完整性——这是长文档处理的核心挑战。

## 学习目标

- 掌握长文档的分块策略
- 理解上下文管理的方法
- 学会处理超长文档

## 一、分块策略

```
分块策略：

1. 固定长度分块
   - 按字符数或 Token 数分块
   - 简单但可能破坏语义

2. 语义分块
   - 按段落、章节分块
   - 保持语义完整性

3. 递归分块
   - 先按大块分，再按小块分
   - 灵活性高

4. 滑动窗口
   - 重叠分块
   - 保持上下文连续性
```

## 二、实现

```python
def semantic_chunking(elements: list, max_chunk_size: int = 1000) -> list:
    """语义分块"""
    chunks = []
    current_chunk = []
    current_size = 0
    
    for element in elements:
        element_size = len(element.text)
        
        if current_size + element_size > max_chunk_size and current_chunk:
            chunks.append("\n".join([e.text for e in current_chunk]))
            current_chunk = [element]
            current_size = element_size
        else:
            current_chunk.append(element)
            current_size += element_size
    
    if current_chunk:
        chunks.append("\n".join([e.text for e in current_chunk]))
    
    return chunks

def sliding_window_chunking(text: str, chunk_size: int = 1000, overlap: int = 200) -> list:
    """滑动窗口分块"""
    chunks = []
    start = 0
    
    while start < len(text):
        end = start + chunk_size
        chunks.append(text[start:end])
        start = end - overlap
    
    return chunks
```

## 三、上下文管理

```python
class ContextManager:
    """上下文管理器"""
    
    def __init__(self, max_context_size: int = 4000):
        self.max_context_size = max_context_size
        self.context = []
    
    def add_context(self, text: str):
        """添加上下文"""
        self.context.append(text)
        
        # 裁剪上下文
        total_size = sum(len(t) for t in self.context)
        while total_size > self.max_context_size:
            removed = self.context.pop(0)
            total_size -= len(removed)
    
    def get_context(self) -> str:
        """获取上下文"""
        return "\n".join(self.context)
```

## 五、摘要生成

```python
def generate_document_summary(document_path: str) -> str:
    """生成文档摘要"""
    # 1. 解析文档
    elements = parse_document(document_path)
    
    # 2. 分块处理
    chunks = semantic_chunking(elements)
    
    # 3. 生成各块摘要
    chunk_summaries = []
    for chunk in chunks:
        summary = generate_summary(chunk)
        chunk_summaries.append(summary)
    
    # 4. 生成总摘要
    final_summary = generate_summary("\n".join(chunk_summaries))
    
    return final_summary
```

## 常见误区

1. **按固定字数简单分块**：按 1000 字切分会导致段落、表格、列表被切断，语义完整性被破坏，下游检索和问答效果很差。
2. **忽略分块之间的上下文关系**：相邻 chunk 之间通常有上下文关联，不做重叠或上下文传递会导致每个 chunk 缺乏背景信息。
3. **分块大小不做调优**：chunk_size 没有通用最优值，取决于文档类型、模型上下文长度、检索粒度，需要通过实验找到最佳参数。
4. **摘要生成只做一次**：长文档的单次摘要会丢失大量细节，分层摘要（先各块摘要再总摘要）能保留更多关键信息。

## 工程建议

1. **优先用语义分块**：按标题、段落、章节等自然边界分块，比固定长度分块的语义完整性好得多。
2. **相邻 chunk 保留 10-20% 重叠**：滑动窗口的重叠区域可传递上下文，避免信息在边界处丢失。
3. **分块后做质量检查**：检查每个 chunk 是否完整（是否有断句、是否有未闭合的括号/引号），过滤掉质量差的 chunk。
4. **上下文管理器做滑动窗口**：对话场景中用上下文管理器维护最近 N 轮对话的摘要，避免上下文超长导致成本飙升。
