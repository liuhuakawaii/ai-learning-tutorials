# 01 语音识别概览——Whisper / SenseVoice / Azure ASR 的选型

> 语音识别让 AI 能听懂人说话。

## 场景引入

你的公司客服中心每天产生数千通录音，管理层希望从中提取关键信息：客户主要投诉哪些问题？哪些通话需要人工复核？平均通话时长是多少？你调研了 Whisper、SenseVoice、Azure Speech、Google Speech-to-Text 等方案，发现它们在中文识别准确率、实时处理能力、部署成本上差异巨大——选错方案可能导致识别错误率高达 20%，或者月度成本超出预算 10 倍。

## 学习目标

- 了解主流语音识别模型
- 掌握不同模型的特点和适用场景
- 学会根据需求选择合适的模型

## 一、主流语音识别模型

```
主流语音识别模型：

1. Whisper (OpenAI)
   - 开源、免费
   - 多语言支持
   - 准确率高
   - 适用：通用场景

2. SenseVoice (阿里)
   - 开源、免费
   - 中文优化
   - 实时识别
   - 适用：中文场景

3. Azure Speech (微软)
   - 商业服务
   - 实时识别
   - 功能丰富
   - 适用：企业场景

4. Google Speech-to-Text
   - 商业服务
   - 多语言支持
   - 准确率高
   - 适用：通用场景
```

```python
# Whisper API
def transcribe_audio(audio_path: str) -> str:
    """语音识别"""
    with open(audio_path, "rb") as audio_file:
        response = client.audio.transcriptions.create(
            model="whisper-1",
            file=audio_file
        )
    return response.text
```

## 常见误区

1. **认为 Whisper 对所有语言效果都一样好**：Whisper 在英文上表现优异，但中文识别效果取决于模型大小，tiny/base 模型的中文错误率较高，必须用 medium 或 large。
2. **忽略音频质量对识别结果的影响**：背景噪音、多人说话、麦克风质量差会大幅降低识别准确率，上线前必须在真实音频条件下测试。
3. **把实时识别和离线识别混为一谈**：Whisper 本身不支持实时流式识别，需要实时场景必须选择 Azure 或 Google 的流式 API。
4. **不做后处理直接使用识别结果**：语音识别的原始结果通常包含语气词、重复、断句错误，需要做清洗和标点修正后再使用。

## 工程建议

1. **按场景选择模型**：客服录音（中文为主）优先选 SenseVoice 或 Whisper large；多语言场景选 Whisper；实时交互选 Azure/Google 流式 API。
2. **建立音频预处理 Pipeline**：降噪 → 音量标准化 → 静音裁剪 → 格式转换，预处理质量直接影响识别准确率。
3. **做 A/B 测试量化对比**：用同一组真实音频测试不同模型，统计字符错误率（CER）和词错误率（WER），用数据驱动选型。
4. **预留模型升级接口**：语音识别模型迭代很快，抽象出统一的 ASR 接口，方便后续切换模型而不改动业务代码。
