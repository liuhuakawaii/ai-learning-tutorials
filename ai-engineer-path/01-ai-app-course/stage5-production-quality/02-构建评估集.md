# 第2课：构建评估集——事实性、引用、格式、拒答

> **课程定位**：准备高质量的测试数据
> **前置知识**：第 1 课的评估概念
> **预计时长**：45 分钟

## 场景引入

你决定为 AI 知识库助手构建评估集。一开始你写了 5 个问题，跑了一遍发现全部通过，觉得"质量不错"。但上线后用户反馈："为什么它不会拒答？我问了它一个文档里没有的问题，它编了一个答案。"你回头看评估集，发现 5 个问题全部是"文档里有答案"的场景，完全没有测试拒答能力。一个好的评估集，必须覆盖用户可能遇到的所有行为模式，而不仅仅是"回答正确"这一种。

---

## 学习目标

完成本课学习后，你将能够：

1. 设计评估集的结构
2. 编写不同类型的测试用例
3. 定义评估标准
4. 管理和维护评估集

## 一、评估集结构

### 1.1 评估用例格式

```typescript
// lib/evals/types.ts
interface EvalCase {
  id: string
  category: string           // 分类
  question: string           // 用户问题
  context?: string           // 相关上下文（用于 RAG）
  expectedAnswer?: string    // 期望答案
  expectedCitations?: string[]  // 期望引用
  expectedBehavior: 'answer' | 'refuse' | 'clarify'  // 期望行为
  tags: string[]             // 标签
  difficulty: 'easy' | 'medium' | 'hard'
}

interface EvalResult {
  caseId: string
  actualAnswer: string
  actualCitations: string[]
  scores: {
    relevancy: number        // 0-1
    faithfulness: number     // 0-1
    completeness: number     // 0-1
    citationAccuracy: number // 0-1
  }
  passed: boolean
  feedback?: string
}
```


## 三、运行评估

### 3.1 评估运行器

```typescript
// lib/evals/runner.ts
import { testCases } from './test-cases'
import { askQuestion } from '@/lib/rag'
import { evaluateAnswer } from './evaluator'

interface EvalRun {
  id: string
  timestamp: Date
  totalCases: number
  passed: number
  failed: number
  scores: {
    avgRelevancy: number
    avgFaithfulness: number
    avgCompleteness: number
    avgCitationAccuracy: number
  }
  results: EvalResult[]
}

export async function runEval(
  options: {
    categories?: string[]
    tags?: string[]
    difficulty?: string
  } = {}
): Promise<EvalRun> {
  let cases = testCases

  // 过滤
  if (options.categories) {
    cases = cases.filter(c => options.categories!.includes(c.category))
  }
  if (options.tags) {
    cases = cases.filter(c => c.tags.some(t => options.tags!.includes(t)))
  }
  if (options.difficulty) {
    cases = cases.filter(c => c.difficulty === options.difficulty)
  }

  const results: EvalResult[] = []

  for (const testCase of cases) {
    // 运行系统
    const response = await askQuestion(testCase.question)

    // 评估结果
    const evaluation = await evaluateAnswer(testCase, response)

    results.push(evaluation)
  }

  // 计算汇总
  const passed = results.filter(r => r.passed).length
  const avg = (key: keyof EvalResult['scores']) =>
    results.reduce((sum, r) => sum + r.scores[key], 0) / results.length

  return {
    id: `eval-${Date.now()}`,
    timestamp: new Date(),
    totalCases: cases.length,
    passed,
    failed: cases.length - passed,
    scores: {
      avgRelevancy: avg('relevancy'),
      avgFaithfulness: avg('faithfulness'),
      avgCompleteness: avg('completeness'),
      avgCitationAccuracy: avg('citationAccuracy'),
    },
    results,
  }
}
```

### 3.2 评估器

```typescript
// lib/evals/evaluator.ts
import OpenAI from 'openai'

const openai = new OpenAI()

export async function evaluateAnswer(
  testCase: EvalCase,
  response: { answer: string; citations: string[] }
): Promise<EvalResult> {
  // 使用模型评估
  const evalResponse = await openai.responses.create({
    model: 'gpt-5.5',
    input: [
      {
        role: 'system',
        content: `你是一个 AI 回答质量评估助手。请评估以下回答的质量。

评估标准：
1. relevancy（相关性）：回答是否与问题相关
2. faithfulness（忠实度）：回答是否基于提供的上下文，没有编造
3. completeness（完整性）：回答是否涵盖所有必要信息
4. citationAccuracy（引用准确性）：引用是否准确

输出 JSON：
{
  "relevancy": 0-1,
  "faithfulness": 0-1,
  "completeness": 0-1,
  "citationAccuracy": 0-1,
  "passed": boolean,
  "feedback": "评估说明"
}`,
      },
      {
        role: 'user',
        content: `问题：${testCase.question}

上下文：${testCase.context || '无'}

期望答案：${testCase.expectedAnswer || '无'}

实际回答：${response.answer}

引用：${response.citations.join(', ') || '无'}

期望行为：${testCase.expectedBehavior}`,
      },
    ],
    text: { format: { type: 'json_object' } },
    temperature: 0,
  })

  const scores = JSON.parse(evalResponse.output_text)

  return {
    caseId: testCase.id,
    actualAnswer: response.answer,
    actualCitations: response.citations,
    scores: {
      relevancy: scores.relevancy,
      faithfulness: scores.faithfulness,
      completeness: scores.completeness,
      citationAccuracy: scores.citationAccuracy,
    },
    passed: scores.passed,
    feedback: scores.feedback,
  }
}
```

## 四、评估结果展示

```typescript
// components/EvalResults.tsx
'use client'

interface EvalRun {
  id: string
  timestamp: string
  totalCases: number
  passed: number
  failed: number
  scores: {
    avgRelevancy: number
    avgFaithfulness: number
    avgCompleteness: number
    avgCitationAccuracy: number
  }
  results: EvalResult[]
}

export function EvalResults({ run }: { run: EvalRun }) {
  return (
    <div className="eval-results">
      <h2>评估结果</h2>

      <div className="summary">
        <div className="stat">
          <span className="label">通过率</span>
          <span className="value">{((run.passed / run.totalCases) * 100).toFixed(1)}%</span>
        </div>
        <div className="stat">
          <span className="label">通过</span>
          <span className="value">{run.passed}/{run.totalCases}</span>
        </div>
      </div>

      <div className="scores">
        <div className="score">
          <span>相关性</span>
          <span>{(run.scores.avgRelevancy * 100).toFixed(0)}%</span>
        </div>
        <div className="score">
          <span>忠实度</span>
          <span>{(run.scores.avgFaithfulness * 100).toFixed(0)}%</span>
        </div>
        <div className="score">
          <span>完整性</span>
          <span>{(run.scores.avgCompleteness * 100).toFixed(0)}%</span>
        </div>
        <div className="score">
          <span>引用准确性</span>
          <span>{(run.scores.avgCitationAccuracy * 100).toFixed(0)}%</span>
        </div>
      </div>

      <div className="details">
        {run.results.map(result => (
          <div key={result.caseId} className={`result ${result.passed ? 'passed' : 'failed'}`}>
            <h4>{result.caseId}</h4>
            <p><strong>回答：</strong>{result.actualAnswer}</p>
            {result.feedback && <p><strong>反馈：</strong>{result.feedback}</p>}
          </div>
        ))}
      </div>
    </div>
  )
}
```

## 常见误区

1. **评估用例太少**：只写 3-5 个用例就认为够了。实际上，每种行为模式（回答、拒答、澄清、引用）都需要多个用例才能暴露问题。建议至少 20 条。

2. **期望答案写得太死板**：把期望答案写成必须一字不差的匹配。AI 输出具有多样性，评估标准应该是"包含关键信息点"而非"完全一致"。

3. **忽略难度分层**：所有用例都是简单问题。实际使用中，用户会问模糊的、多义的、需要综合多个文档的问题，评估集必须包含不同难度等级。

4. **评估集建好就不更新**：知识库内容更新了，评估集还是旧的。评估用例必须和知识库保持同步，否则评估结果会失真。

## 工程建议

1. **用 TypeScript 接口定义评估用例结构**：明确每个用例的分类、问题、期望答案、期望行为、标签、难度。结构化的评估集才能被自动化工具消费。

2. **评估标准用 0-1 连续分而非布尔值**：相关性、忠实度、完整性这些维度用连续分值，能更精确地反映质量变化。布尔值（通过/不通过）会丢失大量信息。

3. **评估用例按分类管理**：事实性、引用、拒答、边界、安全——每类独立管理，方便按类别分析问题和制定改进策略。

4. **定期 Review 评估集**：每两周花 30 分钟审查评估集，删除过时用例，补充新发现的边界情况。评估集本身也需要迭代。

## 小结

本课的核心要点：

1. **评估集结构**：问题、上下文、期望答案、期望行为
