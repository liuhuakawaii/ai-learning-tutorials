## 一、传统测试 vs AI 评估

### 1.1 核心差异

```
传统应用测试：
  输入：2 + 2
  期望输出：4
  实际输出：4
  结果：✅ 通过

  输入相同 → 输出一定相同 → 可以用断言测试

AI 应用评估：
  输入："总结这篇文章"
  期望：涵盖 3 个要点
  实际输出 1："文章讨论了 A、B、C..."
  实际输出 2："本文主要探讨了 C、B、A..."
  实际输出 3："作者提出了三个观点..."

  输入相同 → 输出可能不同 → 不能用断言，需要用评估
```

### 1.2 为什么 AI 输出不确定

```
┌─────────────────────────────────────────────────────────────────┐
│                AI 输出不确定的原因                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 温度参数                                                    │
│     temperature > 0 时，每次输出可能不同                          │
│                                                                 │
│  2. 采样策略                                                    │
│     模型从概率分布中采样，不是确定性输出                          │
│                                                                 │
│  3. 上下文差异                                                  │
│     检索到的文档不同，输出也不同                                  │
│                                                                 │
│  4. 模型版本                                                    │
│     模型更新后，同样的输入可能得到不同的输出                      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 二、为什么必须评估

### 2.1 不评估的风险

```
不评估会怎样？

  场景 1：你修改了 System Prompt
    → 不知道改好了还是改坏了
    → 上线后用户投诉才发现问题

  场景 2：你更新了检索策略
    → 不知道召回率是否提升
    → 可能反而降低了回答质量

  场景 3：你切换了模型
    → 不知道新模型是否适合你的场景
    → 可能出现新的幻觉问题

  场景 4：你部署了新版本
    → 不知道是否引入了 bug
    → 线上故障才发现
```

### 2.2 评估的价值

```
┌─────────────────────────────────────────────────────────────────┐
│                    评估的价值                                     │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  质量保障                                                        │
│  ├── 上线前验证质量                                              │
│  ├── 发现潜在问题                                                │
│  └── 防止回归                                                    │
│                                                                 │
│  迭代依据                                                        │
│  ├── A/B 测试对比                                                │
│  ├── 量化改进效果                                                │
│  └── 指导优化方向                                                │
│                                                                 │
│  信任建立                                                        │
│  ├── 用户信任：有数据支撑                                        │
│  ├── 团队信任：有质量保证                                        │
│  └── 管理信任：有可度量的指标                                    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 三、评估维度

### 3.1 RAG 系统的评估维度

```
┌─────────────────────────────────────────────────────────────────┐
│                    RAG 评估维度                                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  检索质量                                                        │
│  ├── 召回率（Recall）：相关文档是否被检索到                       │
│  ├── 精确率（Precision）：检索到的文档是否相关                    │
│  └── 排序质量：最相关的是否排在前面                               │
│                                                                 │
│  生成质量                                                        │
│  ├── 忠实度（Faithfulness）：回答是否基于检索结果                 │
│  ├── 相关性（Relevancy）：回答是否与问题相关                     │
│  └── 完整性（Completeness）：回答是否涵盖所有信息                │
│                                                                 │
│  引用质量                                                        │
│  ├── 准确性：引用来源是否正确                                    │
│  ├── 可追溯性：用户能否找到原文                                  │
│  └── 有用性：引用是否帮助理解                                    │
│                                                                 │
│  安全性                                                          │
│  ├── 拒答能力：对不知道的问题是否拒答                            │
│  ├── 幻觉率：编造信息的比例                                      │
│  └── 敏感信息：是否泄露敏感内容                                  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 评估指标定义

```typescript
interface EvalMetrics {
  // 检索指标
  recall: number        // 召回率：检索到的相关文档 / 所有相关文档
  precision: number     // 精确率：相关文档 / 检索到的所有文档
  mrr: number           // 平均倒数排名：第一个相关结果的位置

  // 生成指标
  faithfulness: number  // 忠实度：回答基于检索结果的比例
  relevancy: number     // 相关性：回答与问题相关的比例
  completeness: number  // 完整性：回答涵盖信息的比例

  // 安全指标
  refusalRate: number   // 拒答率：对不知道的问题拒答的比例
  hallucinationRate: number  // 幻觉率：编造信息的比例
}
```

## 四、评估流程

```
┌─────────────────────────────────────────────────────────────────┐
│                    评估流程                                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 构建评估集                                                   │
│     准备测试问题和期望答案                                       │
│                                                                 │
│  2. 运行评估                                                     │
│     用评估集调用系统，收集实际输出                                │
│                                                                 │
│  3. 计算指标                                                     │
│     对比期望和实际，计算各项指标                                  │
│                                                                 │
│  4. 分析结果                                                     │
│     找出问题，制定改进方案                                        │
│                                                                 │
│  5. 迭代优化                                                     │
│     改进后重新评估，验证效果                                      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

---

## 小结

本课的核心要点：

1. **AI 输出不确定**：不能用断言测试，需要用评估
2. **必须评估**：防止质量回归，指导优化方向
3. **评估维度**：检索质量、生成质量、引用质量、安全性
4. **评估流程**：构建评估集 → 运行 → 计算指标 → 分析 → 迭代
