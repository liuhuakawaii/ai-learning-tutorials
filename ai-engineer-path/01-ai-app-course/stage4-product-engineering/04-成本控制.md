# 第4课：成本控制——token 统计、缓存、限流、降级

> **课程定位**：控制 AI 应用的运营成本
> **前置知识**：第 2 课的用户和配额
> **预计时长**：45 分钟

## 场景引入

你的 AI 应用上线一周后收到了 OpenAI 的账单：$487。你翻看日志发现，有个用户在一个下午重复问了同一个问题 30 多次（每次刷新页面就重新问），每次都是完整调用 GPT-4 API；另一个用户上传了 200 篇长文档，每次对话都把全部文档内容塞进 prompt，单次请求消耗 5 万 token。更可怕的是，如果这种使用模式持续下去，月账单可能突破 $5000。AI 应用的成本模型和传统应用完全不同——传统应用的服务器成本是固定的，而 AI 应用的成本和用户使用量线性相关，甚至可能因为一个恶意用户而指数增长。Token 统计、缓存、限流、降级，这四道防线缺一不可。

## 一、Token 统计

### 1.1 记录每次调用

```typescript
// lib/usage-tracker.ts
import { prisma } from './prisma'

interface UsageRecord {
  userId: string
  conversationId: string
  model: string
  promptTokens: number
  completionTokens: number
  totalTokens: number
  cost: number
  duration: number
}

// 模型与价格不要硬编码在业务逻辑里。
// 价格会变化，生产环境建议从配置中心或环境变量读取，并定期按官方价格页更新。
interface ModelCostConfig {
  model: string
  inputCostPer1M: number
  outputCostPer1M: number
}

const MODEL_CATALOG: Record<string, ModelCostConfig> = {
  primary: {
    model: process.env.OPENAI_PRIMARY_MODEL ?? 'your-primary-model',
    inputCostPer1M: Number(process.env.OPENAI_PRIMARY_INPUT_COST_PER_1M ?? 0),
    outputCostPer1M: Number(process.env.OPENAI_PRIMARY_OUTPUT_COST_PER_1M ?? 0),
  },
  fast: {
    model: process.env.OPENAI_FAST_MODEL ?? 'your-fast-model',
    inputCostPer1M: Number(process.env.OPENAI_FAST_INPUT_COST_PER_1M ?? 0),
    outputCostPer1M: Number(process.env.OPENAI_FAST_OUTPUT_COST_PER_1M ?? 0),
  },
}

function getModelConfig(modelKey: string): ModelCostConfig {
  return MODEL_CATALOG[modelKey] ?? MODEL_CATALOG.primary
}

export function calculateCost(
  modelKey: string,
  promptTokens: number,
  completionTokens: number
): number {
  const prices = getModelConfig(modelKey)
  return (
    (promptTokens * prices.inputCostPer1M +
      completionTokens * prices.outputCostPer1M) / 1000000
  )
}

export async function trackUsage(record: UsageRecord): Promise<void> {
  // 记录使用量
  await prisma.usageRecord.create({
    data: {
      userId: record.userId,
      conversationId: record.conversationId,
      model: record.model,
      promptTokens: record.promptTokens,
      completionTokens: record.completionTokens,
      totalTokens: record.totalTokens,
      cost: record.cost,
      duration: record.duration,
    },
  })

  // 更新用户本月使用量
  await prisma.user.update({
    where: { id: record.userId },
    data: {
      tokenUsed: { increment: record.totalTokens },
    },
  })
}
```

### 1.2 在 API 调用中记录

```typescript
// lib/chat.ts
export async function chat(
  userId: string,
  conversationId: string,
  input: any[],
  modelKey: string = 'primary'
) {
  const startTime = Date.now()
  const modelConfig = getModelConfig(modelKey)

  const response = await openai.responses.create({
    model: modelConfig.model,
    input,
  })

  const duration = Date.now() - startTime
  const usage = response.usage!

  const cost = calculateCost(modelKey, usage.input_tokens, usage.output_tokens)

  // 记录使用量
  await trackUsage({
    userId,
    conversationId,
    model: modelConfig.model,
    promptTokens: usage.input_tokens,
    completionTokens: usage.output_tokens,
    totalTokens: usage.total_tokens,
    cost,
    duration,
  })

  return response
}
```

## 二、使用统计查询

### 2.1 统计 API

```typescript
// app/api/usage/route.ts
export async function GET(req: NextRequest) {
  const user = await getCurrentUser()
  if (!user) {
    return Response.json({ error: '未登录' }, { status: 401 })
  }

  const period = req.nextUrl.searchParams.get('period') || 'month'

  // 计算时间范围
  const now = new Date()
  let startDate: Date

  switch (period) {
    case 'day':
      startDate = new Date(now.getFullYear(), now.getMonth(), now.getDate())
      break
    case 'week':
      startDate = new Date(now.getTime() - 7 * 24 * 60 * 60 * 1000)
      break
    case 'month':
    default:
      startDate = new Date(now.getFullYear(), now.getMonth(), 1)
  }

  // 查询使用量
  const stats = await prisma.usageRecord.aggregate({
    where: {
      userId: user.id,
      createdAt: { gte: startDate },
    },
    _sum: {
      totalTokens: true,
      cost: true,
      promptTokens: true,
      completionTokens: true,
    },
    _count: true,
    _avg: {
      duration: true,
    },
  })

  // 按模型分组
  const byModel = await prisma.usageRecord.groupBy({
    by: ['model'],
    where: {
      userId: user.id,
      createdAt: { gte: startDate },
    },
    _sum: {
      totalTokens: true,
      cost: true,
    },
    _count: true,
  })

  return Response.json({
    period,
    summary: {
      totalTokens: stats._sum.totalTokens || 0,
      totalCost: stats._sum.cost || 0,
      requestCount: stats._count,
      avgDuration: stats._avg.duration || 0,
    },
    byModel,
  })
}
```

## 三、缓存策略

### 3.1 相同请求缓存

```typescript
// lib/cache.ts
import crypto from 'crypto'

const cache = new Map<string, { data: any; expiry: number }>()

function getCacheKey(input: any[], model: string): string {
  const content = JSON.stringify({ input, model })
  return crypto.createHash('md5').update(content).digest('hex')
}

export function getCachedResponse(input: any[], model: string): any | null {
  const key = getCacheKey(input, model)
  const cached = cache.get(key)

  if (!cached) return null
  if (cached.expiry < Date.now()) {
    cache.delete(key)
    return null
  }

  return cached.data
}

export function setCachedResponse(
  input: any[],
  model: string,
  response: any,
  ttlMs: number = 5 * 60 * 1000  // 默认 5 分钟
): void {
  const key = getCacheKey(input, model)
  cache.set(key, {
    data: response,
    expiry: Date.now() + ttlMs,
  })
}
```

### 3.2 使用缓存

```typescript
export async function chatWithCache(
  input: any[],
  model: string
) {
  // 检查缓存
  const cached = getCachedResponse(input, model)
  if (cached) {
    console.log('Cache hit!')
    return cached
  }

  // 调用 API
  const response = await openai.responses.create({
    model,
    input,
  })

  // 缓存结果
  setCachedResponse(input, model, response)

  return response
}
```

## 四、限流策略

### 4.1 限流器实现

```typescript
// lib/rate-limiter.ts
class RateLimiter {
  private windows = new Map<string, { count: number; resetTime: number }>()

  constructor(
    private maxRequests: number,
    private windowMs: number
  ) {}

  check(key: string): { allowed: boolean; remaining: number; resetTime: number } {
    const now = Date.now()
    let window = this.windows.get(key)

    if (!window || window.resetTime < now) {
      window = { count: 0, resetTime: now + this.windowMs }
      this.windows.set(key, window)
    }

    const remaining = this.maxRequests - window.count

    if (window.count >= this.maxRequests) {
      return { allowed: false, remaining: 0, resetTime: window.resetTime }
    }

    window.count++
    return { allowed: true, remaining: remaining - 1, resetTime: window.resetTime }
  }
}

// 创建限流器
const chatLimiter = new RateLimiter(20, 60 * 1000)  // 每分钟 20 次
const searchLimiter = new RateLimiter(50, 60 * 1000)  // 每分钟 50 次
```

### 4.2 在 API 中使用

```typescript
export async function POST(req: NextRequest) {
  const user = await getCurrentUser()
```

### 5.1 模型降级

```typescript
// lib/fallback.ts
// 使用业务层级描述降级链，具体模型名由配置决定，避免把过期模型写死在代码里。
const MODEL_FALLBACK_CHAIN = ['primary', 'fast']

export async function chatWithFallback(
  input: any[],
  preferredModelKey: string
) {
  const startIndex = MODEL_FALLBACK_CHAIN.indexOf(preferredModelKey)
  const models = MODEL_FALLBACK_CHAIN.slice(startIndex >= 0 ? startIndex : 1)

  for (const modelKey of models) {
    try {
      const modelConfig = getModelConfig(modelKey)
      const response = await openai.responses.create({
        model: modelConfig.model,
        input,
      })
      return { response, model: modelConfig.model, modelKey }
    } catch (error) {
      console.warn(`Model tier ${modelKey} failed, trying next...`)
      continue
    }
  }

  throw new Error('所有模型都不可用')
}
```

## 常见误区

1. **把 token 统计放在应用层计算**：自己数 token 数，结果和 OpenAI 实际计费不一致。应该直接使用 API 返回的 `usage` 字段，那是官方的计量结果。
2. **缓存的 key 只用用户消息**：忽略了 system prompt 和模型选择对结果的影响。相同用户消息 + 不同 system prompt = 不同回答，缓存 key 必须包含所有影响输出的输入参数。
3. **限流只限频率不限 token**：每分钟 20 次请求看起来合理，但如果每次请求消耗 5 万 token，一分钟就是 100 万 token，成本依然很高。限流应该同时限频率和 token 总量。
4. **降级策略不通知用户**：悄悄把 GPT-4 换成 GPT-3.5，用户发现回答质量下降但不知道为什么，反而投诉增多。降级时应该在 UI 上明确提示"当前使用备用模型"。

## 工程建议

1. **token 统计异步写入**：记录使用量不要阻塞主请求流程。把 `trackUsage()` 放在 response 返回之后异步执行，或者用消息队列缓冲写入，避免数据库写入拖慢对话响应。
2. **缓存分两级**：第一级用进程内 Map 做 L1 缓存（TTL 5 分钟），第二级用 Redis 做 L2 缓存（TTL 1 小时）。相同请求先查 L1 再查 L2，命中率可以达到 30% 以上，直接省掉这部分 API 费用。
3. **限流用滑动窗口算法**：固定窗口（每分钟 0 秒重置）存在"临界突刺"问题——用户在第 59 秒发 20 次，第 60 秒再发 20 次，实际 2 秒内发了 40 次。滑动窗口可以避免这种情况。
4. **成本告警阈值分级**：设置日成本、周成本、月成本三级告警。日成本超过预算的 30% 时发 Slack 通知，超过 50% 时自动触发限流收紧，超过 80% 时暂停免费用户的访问。

## 小结

本课的核心要点：

1. **Token 统计**：记录每次调用的 token 和费用
2. **缓存**：相同请求直接返回，减少 API 调用
3. **限流**：保护系统不被过度使用
4. **降级**：高级模型不可用时自动切换到低级模型
5. **成本优化**：选模型、控长度、用缓存、压缩历史
