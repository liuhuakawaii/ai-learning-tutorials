# 第4课：多步骤任务——计划、执行、观察、修正

> **课程定位**：让模型完成复杂任务
> **前置知识**：第 1-3 课的工具调用基础
> **预计时长**：45 分钟

---

## 场景引入

用户对 AI 助手说："帮我查一下明天有哪几个会议，找到每个会议的相关文档，然后生成一份会议准备清单。"这个任务至少需要三步工具调用，而且步骤之间有依赖——不查到会议列表就无法搜索相关文档，没有文档内容就无法生成清单。如果让模型一次性输出所有工具调用，它不知道中间结果是什么，根本无法规划。多步骤任务的核心思想是：让模型像人一样"走一步看一步"——先行动，观察结果，再决定下一步。这就是 ReAct 模式的本质。

---

## 学习目标

完成本课学习后，你将能够：

1. 理解多步骤任务的工作原理
2. 实现计划-执行-观察-修正循环
3. 处理工具调用的链式依赖
4. 设置最大循环次数防止死循环

## 一、什么是多步骤任务

### 1.1 单步 vs 多步

```
单步任务：
  用户："今天天气怎么样？"
  模型：调用天气工具 → 返回结果 → 回答
  （1 次工具调用）

多步骤任务：
  用户："帮我准备明天的会议资料"
  模型：
    1. 查询明天的会议安排（调用日历工具）
    2. 获取会议参与人信息（调用用户工具）
    3. 搜索相关文档（调用搜索工具）
    4. 生成会议摘要（调用生成工具）
    5. 保存到文件（调用文件工具）
  （5 次工具调用，有依赖关系）
```

### 1.2 ReAct 模式

```
ReAct = Reasoning + Acting（推理 + 行动）

循环过程：
  1. Thought（思考）：分析当前状态，决定下一步
  2. Action（行动）：调用工具
  3. Observation（观察）：查看工具返回的结果
  4. 重复，直到任务完成

┌─────────────────────────────────────────────────────────────────┐
│                    ReAct 循环                                     │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌──────────┐                                                   │
│  │ Thought  │  "我需要先查询明天的会议安排"                       │
│  └────┬─────┘                                                   │
│       │                                                         │
│       ▼                                                         │
│  ┌──────────┐                                                   │
│  │ Action   │  调用 get_calendar_events(date: "明天")            │
│  └────┬─────┘                                                   │
│       │                                                         │
│       ▼                                                         │
│  ┌──────────┐                                                   │
│  │Observation│  返回：明天有 2 个会议...                         │
│  └────┬─────┘                                                   │
│       │                                                         │
│       ▼                                                         │
│  ┌──────────┐                                                   │
│  │ Thought  │  "我需要获取参与人信息"                            │
│  └────┬─────┘                                                   │
│       │                                                         │
│       ▼                                                         │
│      ...                                                        │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 二、实现多步骤调用

### 2.1 基础实现

```typescript
// lib/multi-step.ts
import OpenAI from 'openai'
import { toolRegistry } from './tool-registry'

const openai = new OpenAI()

const MAX_ITERATIONS = 10

interface StepResult {
  iteration: number
  thought?: string
  toolCalls: { name: string; args: any; result: any }[]
  finalAnswer?: string
}

export async function multiStepChat(
  userMessage: string,
  options: {
    maxIterations?: number
    onStep?: (step: StepResult) => void
  } = {}
): Promise<{ answer: string; steps: StepResult[] }> {
  const { maxIterations = MAX_ITERATIONS, onStep } = options

  const messages: ResponseInputMessage[] = [
    {
      role: 'system',
      content: `你是一个能够使用工具完成复杂任务的助手。

你可以调用多个工具来完成任务。每次调用工具后，观察结果，然后决定下一步。

如果任务完成，直接给出最终回答。
如果还需要更多信息，继续调用工具。`,
    },
    { role: 'user', content: userMessage },
  ]

  const tools = toolRegistry.getToolSchemas()
  const steps: StepResult[] = []

  for (let iteration = 0; iteration < maxIterations; iteration++) {
    // 调用模型
    const response = await openai.responses.create({
      model: 'gpt-5.5',
      input: messages,
      tools,
      tool_choice: 'auto',
    })

    const toolCalls = response.output.filter((item) => item.type === 'function_call')

    // 如果没有工具调用，说明任务完成
    if (toolCalls.length === 0) {
      const step: StepResult = {
        iteration,
        finalAnswer: response.output_text || '',
        toolCalls: [],
      }
      steps.push(step)
      onStep?.(step)

      return {
        answer: response.output_text || '',
        steps,
      }
    }

    // 执行工具调用
    messages.push(...response.output)

    const step: StepResult = {
      iteration,
      toolCalls: [],
    }

    for (const toolCall of toolCalls) {
      const args = JSON.parse(toolCall.arguments)
      const result = await toolRegistry.execute(toolCall.name, args)

      step.toolCalls.push({
        name: toolCall.name,
        args,
        result,
      })

      // 把工具结果加入消息
      messages.push({
        type: 'function_call_output',
        call_id: toolCall.call_id,
        output: JSON.stringify(result),
      })
    }

    steps.push(step)
    onStep?.(step)
  }

  // 达到最大循环次数
  return {
    answer: '任务未能在规定步骤内完成，请尝试简化任务。',
    steps,
  }
}
```

### 2.2 使用示例

```typescript
// 使用多步骤调用
const result = await multiStepChat(
  '帮我查询明天的会议安排，然后搜索相关文档，最后生成会议准备清单',
  {
    maxIterations: 10,
    onStep: (step) => {
      console.log(`步骤 ${step.iteration + 1}:`)
      for (const call of step.toolCalls) {
        console.log(`  调用 ${call.name}:`, call.args)
        console.log(`  结果:`, call.result)
      }
    },
  }
)

console.log('最终回答:', result.answer)
```

## 三、处理依赖关系

### 3.1 串行依赖

```
任务：查询用户订单，然后发送确认邮件

步骤 1：查询订单
  调用 query_orders(user_id: "123")
  返回：订单列表

步骤 2：发送邮件（依赖步骤 1 的结果）
  调用 send_email(to: "user@example.com", body: "您的订单...")
  返回：发送成功

  步骤 2 依赖步骤 1 的输出，必须串行执行。
```

### 3.2 并行执行

```typescript
// 检测可并行的工具调用
function detectParallelCalls(
  toolCalls: { name: string; args: any }[]
): { parallel: boolean; groups: number[][] } {
  // 简单策略：如果参数之间没有依赖，可以并行
  // 实际项目中可以用更复杂的依赖分析

  const groups: number[][] = []
  let currentGroup: number[] = []

  for (let i = 0; i < toolCalls.length; i++) {
    // 检查是否依赖前面的结果
    const argsStr = JSON.stringify(toolCalls[i].args)
    const dependsOnPrevious = toolCalls.slice(0, i).some(
      (prev, j) => argsStr.includes(`result_${j}`)
    )

    if (dependsOnPrevious || currentGroup.length >= 3) {
      if (currentGroup.length > 0) {
        groups.push(currentGroup)
      }
      currentGroup = [i]
    } else {
      currentGroup.push(i)
    }
  }

  if (currentGroup.length > 0) {
    groups.push(currentGroup)
  }

  return {
    parallel: groups.some(g => g.length > 1),
    groups,
  }
}
```

## 四、任务状态跟踪

### 4.1 状态定义

```typescript
enum TaskStatus {
  PENDING = 'pending',
  IN_PROGRESS = 'in_progress',
  COMPLETED = 'completed',
  FAILED = 'failed',
  CANCELLED = 'cancelled',
}

interface TaskStep {
  id: string
  name: string
  status: TaskStatus
  toolCall?: string
  result?: any
  error?: string
  startedAt?: Date
  completedAt?: Date
}

interface Task {
  id: string
  description: string
  status: TaskStatus
  steps: TaskStep[]
  createdAt: Date
  updatedAt: Date
}
```

### 4.2 任务管理器

```typescript
class TaskManager {
  private tasks = new Map<string, Task>()

  createTask(description: string): Task {
    const task: Task = {
      id: `task-${Date.now()}`,
      description,
      status: TaskStatus.PENDING,
      steps: [],
      createdAt: new Date(),
      updatedAt: new Date(),
    }
    this.tasks.set(task.id, task)
    return task
  }

  addStep(taskId: string, step: Omit<TaskStep, 'id' | 'status'>): TaskStep {
    const task = this.tasks.get(taskId)
    if (!task) throw new Error('Task not found')

    const newStep: TaskStep = {
      id: `step-${task.steps.length}`,
      status: TaskStatus.PENDING,
      ...step,
    }
    task.steps.push(newStep)
    task.updatedAt = new Date()
    return newStep
  }

  updateStep(taskId: string, stepId: string, update: Partial<TaskStep>) {
    const task = this.tasks.get(taskId)
    if (!task) return

    const step = task.steps.find(s => s.id === stepId)
    if (!step) return

    Object.assign(step, update)
    task.updatedAt = new Date()

    // 更新任务状态
    if (task.steps.every(s => s.status === TaskStatus.COMPLETED)) {
      task.status = TaskStatus.COMPLETED
    } else if (task.steps.some(s => s.status === TaskStatus.FAILED)) {
      task.status = TaskStatus.FAILED
    } else if (task.steps.some(s => s.status === TaskStatus.IN_PROGRESS)) {
      task.status = TaskStatus.IN_PROGRESS
    }
  }

  getTask(taskId: string): Task | undefined {
    return this.tasks.get(taskId)
  }
}

export const taskManager = new TaskManager()
```

## 五、错误恢复

### 5.1 重试策略

```typescript
async function executeWithRetry(
  toolName: string,
  args: any,
  maxRetries: number = 2
): Promise<ToolResult> {
  let lastError: ToolResult | null = null

  for (let attempt = 0; attempt <= maxRetries; attempt++) {
    const result = await toolRegistry.execute(toolName, args)

    if (result.success) {
      return result
    }

    lastError = result

    // 某些错误不重试
    if (result.error?.includes('权限') || result.error?.includes('不存在')) {
      break
    }

    // 等待后重试
    if (attempt < maxRetries) {
      await new Promise(r => setTimeout(r, 1000 * (attempt + 1)))
    }
  }

  return lastError!
}
```

## 常见误区

1. **不设置最大循环次数**：模型可能陷入"思考→调用→观察→再思考"的死循环，尤其是当工具返回模糊结果时。必须设置 `maxIterations`（建议 10 次），达到上限后强制终止并返回当前结果。
2. **把所有工具结果都塞进上下文**：每一步的工具返回都会累积在消息历史中。如果不做裁剪，5 步之后上下文就可能超过模型的 token 限制。每步只保留必要的结果字段。
3. **忽略步骤间的依赖关系**：第二步的参数依赖第一步的输出时，不能并行执行。要先检测依赖关系，串行依赖必须按顺序执行，无依赖的步骤才可并行。
4. **错误直接终止整个任务**：某一步搜索失败不代表整个研究任务要放弃。让模型看到错误信息，由它决定是重试、换参数还是跳过这一步继续。

---

## 工程建议

1. **为每一步记录状态**：用 `TaskStep` 对象记录每步的工具名、入参、出参、状态（pending/running/done/failed）、耗时。这是调试多步骤任务的唯一途径，也是前端展示进度的数据基础。
2. **实现指数退避重试**：工具调用失败后，不要立即重试。第一次等 1 秒，第二次等 2 秒，第三次等 4 秒。对于权限错误和资源不存在的错误，不重试，直接跳过。
3. **给模型提供"放弃"选项**：在 system prompt 中明确告诉模型"如果某个步骤反复失败，可以放弃该步骤并说明原因"。否则模型会一直重试同一个失败的操作。
4. **在前端实时展示执行步骤**：多步骤任务可能运行 30 秒以上。通过 WebSocket 或轮询把每一步的执行状态推送给前端，让用户知道 Agent 在做什么，而不是看到一个空白页面等待。
