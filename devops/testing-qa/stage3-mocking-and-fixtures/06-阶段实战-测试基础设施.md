# 阶段实战：测试基础设施

## 场景引入

项目规模增长到几十个页面、上百个组件时，每个测试文件都重复写着 `render(<Provider><Component /></Provider>)`、手写 mock 数据、用 `toBeTruthy()` 判断复杂结构——测试代码又长又难维护。本节课搭建完整的测试基础设施：自定义 render、全局 Mock、数据工厂、自定义 matcher，以及多环境配置和脚本组织。

## 学习目标

- 掌握自定义 render 函数包装 Provider 的设计
- 学会全局 Mock 配置（MSW）的组织方式
- 理解测试数据工厂模式和自定义 matcher
- 掌握多环境测试配置和脚本组织

## 自定义 render 函数

```typescript
// src/test-infrastructure/types.ts
import type { RenderOptions } from '@testing-library/react'

export interface CustomRenderOptions extends Omit<RenderOptions, 'wrapper'> {
  preloadedState?: Partial<RootState>
  locale?: string
  theme?: 'light' | 'dark'
}

export interface RootState {
  auth: { user: User | null; token: string | null }
  todos: { items: Todo[]; loading: boolean; error: string | null }
}

export interface User { id: string; email: string; name: string; role: 'admin' | 'user' }
export interface Todo { id: string; title: string; completed: boolean; priority: 'low' | 'medium' | 'high' }
```

```tsx
// src/test-infrastructure/render.tsx
import React, { type ReactElement, type ReactNode } from 'react'
import { render } from '@testing-library/react'
import { Provider } from 'react-redux'
import { BrowserRouter } from 'react-router-dom'
import { configureStore } from '@reduxjs/toolkit'
import { ThemeProvider, createTheme } from '@mui/material'
import { I18nextProvider } from 'react-i18next'
import i18n from '../i18n/test-i18n'
import { authReducer } from '../store/auth.slice'
import { todosReducer } from '../store/todos.slice'
import type { CustomRenderOptions, RootState } from './types'

function createWrapper(options: CustomRenderOptions = {}) {
  const { preloadedState, theme = 'light' } = options
  const store = configureStore({ reducer: { auth: authReducer, todos: todosReducer }, preloadedState: preloadedState as any })
  const muiTheme = createTheme({ palette: { mode: theme } })

  function Wrapper({ children }: { children: ReactNode }) {
    return (
      <Provider store={store}>
        <BrowserRouter>
          <I18nextProvider i18n={i18n}>
            <ThemeProvider theme={muiTheme}>{children}</ThemeProvider>
          </I18nextProvider>
        </BrowserRouter>
      </Provider>
    )
  }
  return { Wrapper, store }
}

export function customRender(ui: ReactElement, options: CustomRenderOptions = {}) {
  const { Wrapper, store } = createWrapper(options)
  return { ...render(ui, { wrapper: Wrapper }), store }
}

export function renderWithAuth(ui: ReactElement, userOverride?: Partial<RootState['auth']>) {
  return customRender(ui, {
    preloadedState: { auth: { user: { id: '1', email: 'test@example.com', name: '测试用户', role: 'user', ...userOverride?.user }, token: 'mock-token', ...userOverride } },
  })
}

export function renderWithTodos(ui: ReactElement, items: RootState['todos']['items'] = []) {
  return customRender(ui, { preloadedState: { todos: { items, loading: false, error: null } } })
}
```

```tsx
// 使用示例
test('显示任务列表', () => {
  renderWithTodos(<TodoList />, [createTodo({ title: '买咖啡' })])
  expect(screen.getByText('买咖啡')).toBeInTheDocument()
})
```

## 自定义 Matcher

```typescript
// src/test-infrastructure/matchers/index.ts
import { screen } from '@testing-library/react'

function toBeVisibleWithText(text: string | RegExp) {
  try {
    const el = screen.getByText(text)
    return { pass: el.offsetParent !== null, message: () => `期望元素包含 "${text}" 的可见性不匹配` }
  } catch { return { pass: false, message: () => `未找到包含 "${text}" 的元素` } }
}

function toHaveValidationError(message?: string | RegExp) {
  try {
    const errorEl = screen.getByRole('alert')
    if (!message) return { pass: true, message: () => '期望不存在验证错误' }
    const text = errorEl.textContent || ''
    const matches = typeof message === 'string' ? text.includes(message) : message.test(text)
    return { pass: matches, message: () => `期望验证错误匹配 "${message}"，实际为 "${text}"` }
  } catch { return { pass: false, message: () => '未找到验证错误提示' } }
}

expect.extend({ toBeVisibleWithText, toHaveValidationError })

declare module 'vitest' {
  interface Assertion { toBeVisibleWithText(text: string | RegExp): void; toHaveValidationError(message?: string | RegExp): void }
}
```

```tsx
// 使用示例
test('邮箱格式错误显示提示', async () => {
  render(<LoginForm />)
  await userEvent.type(screen.getByLabelText('邮箱'), 'bad')
  await userEvent.click(screen.getByRole('button', { name: '登录' }))
  expect(document.body).toHaveValidationError(/邮箱格式/)
})
```

## 常见误区

1. **每个测试文件重复 Provider**：自定义 render 的意义就是消除重复
2. **Mock 一切**：只 mock 外部依赖（API、浏览器 API），不 mock 被测组件内部
3. **工厂返回固定数据**：必须每次生成唯一数据，否则并行测试互相干扰
4. **自定义 matcher 不声明类型**：不写 `declare module` 扩展会报 TypeScript 错误
5. **全局 setup 做太多事**：只放 MSW server 和浏览器 API polyfill

## 工程建议

1. 自定义 render 参数用对象而非位置参数，扩展性更好
2. MSW handlers 按功能模块分组，超过 200 行就拆分
3. 工厂函数提供 `resetCounter()` 方法，`beforeEach` 中调用保证隔离
4. CI 配置 `bail: true`，第一个失败就停止
5. 新项目第一天就搭基础设施，越晚搭重构成本越高

## 小结

5 个核心模块：自定义 render（一行搞定 Provider）、全局 Mock（MSW 统一管理）、数据工厂（生成唯一测试数据）、自定义 matcher（简化复杂断言）、环境配置（dev/staging/CI 各有策略）。

### 练习二

```typescript
export function toHaveStoreState(store: any) {
  return function (key: string, expected: any) {
    const keys = key.split('.')
    let actual = store.getState()
    for (const k of keys) {
      if (actual == null) return { pass: false, message: () => `路径 "${key}" 在 "${k}" 处中断` }
      actual = actual[k]
    }
    const pass = JSON.stringify(actual) === JSON.stringify(expected)
    return { pass, message: () => pass
      ? `期望 store.${key} 不等于 ${JSON.stringify(expected)}`
      : `期望 store.${key} 等于 ${JSON.stringify(expected)}，实际为 ${JSON.stringify(actual)}`
    }
  }
}
```
