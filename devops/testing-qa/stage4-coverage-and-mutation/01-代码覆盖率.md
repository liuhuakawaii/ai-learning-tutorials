# 代码覆盖率

## 一个误导人的数字

你的团队维护支付核心模块，上线前要求"覆盖率 80%"。QA 跑完测试报告覆盖率 85%，达标了。但上线后还是出了 bug——某个边界条件下的手续费计算错误。

覆盖率 85% 意味着什么？哪些代码被覆盖了、哪些没有？这一课搞懂四种覆盖率指标、如何配置、如何解读，以及为什么覆盖率是必要不充分条件。

## 四种覆盖率指标

```typescript
export function divide(a: number, b: number): number {
  if (b === 0) {
    throw new Error('除数不能为零')  // 语句 1
  }
  return a / b                        // 语句 2
}
```

**语句覆盖率**：每条可执行语句是否至少执行了一次。只调用 `divide(10, 2)` 时，语句 1 没被执行，语句覆盖率 50%。

**分支覆盖率**：每个控制流分支是否都被走过。需要同时测试 `b === 0` 和 `b !== 0` 才能 100%。

**函数覆盖率**：每个函数是否至少被调用了一次。

**行覆盖率**：每行源代码是否至少执行了一行。

**分支覆盖率最有价值**——它能暴露控制流中的盲区。整体 85% 可能掩盖了某个关键模块只有 33% 分支覆盖率的事实。

## Vitest 覆盖率配置

```bash
npm install -D @vitest/coverage-v8
```

```typescript
// vitest.config.ts
import { defineConfig } from 'vitest/config'

export default defineConfig({
  test: {
    coverage: {
      provider: 'v8',
      reporter: ['text', 'html', 'lcov', 'json-summary'],
      reportsDirectory: './coverage',
      include: ['src/**/*.ts'],
      exclude: [
        'src/**/*.test.ts',
        'src/**/*.spec.ts',
        'src/**/index.ts',
        'src/**/types.ts',
      ],
      thresholds: {
        statements: 80,
        branches: 75,
        functions: 80,
        lines: 80,
        'src/core/**/*.ts': {
          statements: 90,
          branches: 85,
          functions: 90,
          lines: 90,
        },
      },
    },
  },
})
```

核心模块（`src/core/`）用更高阈值。阈值不达标时 Vitest 以非零退出码失败，天然适配 CI 门禁。

运行：`npx vitest run --coverage`

## 四种报告格式

**text（终端）**：快速查看，未达阈值的数字红色显示。

**HTML（`coverage/index.html`）**：逐文件查看哪些行被覆盖（绿色）、哪些未覆盖（红色）。日常开发最常用。

**LCOV（`coverage/lcov.info`）**：标准化格式，上传到 Codecov、Coveralls、SonarQube。

**json-summary（`coverage/coverage-summary.json`）**：适合被脚本或看板系统读取。

## CI 集成

```yaml
# .github/workflows/test.yml
name: Test & Coverage
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: npm ci
      - run: npx vitest run --coverage
      - name: Upload coverage to Codecov
        uses: codecov/codecov-action@v4
        with:
          files: ./coverage/lcov.info
          fail_ci_if_error: true
          token: ${{ secrets.CODECOV_TOKEN }}
```

## 三个最常见的误解

**"覆盖率高 = 测试质量高"**：一个测试调用了函数但没有任何 expect，也会被计入覆盖率。覆盖率只衡量"代码被执行了"，不衡量"断言有没有做"。

**"追求 100% 覆盖率"**：100% 成本极高且收益递减。合理目标是核心逻辑 90%+，整体 75-85%。

**"只关注整体数字"**：整体 85% 可能掩盖了支付模块只有 33% 分支覆盖率。应按目录设置不同阈值。

## 参考答案

### 练习一

```typescript
// vitest.config.ts
import { defineConfig } from 'vitest/config'

export default defineConfig({
  test: {
    coverage: {
      provider: 'v8',
      reporter: ['text', 'html', 'lcov'],
      exclude: ['**/*.test.ts', '**/types.ts'],
      thresholds: {
        statements: 80,
        branches: 70,
      },
    },
  },
})
```

### 练习二

优先级：
1. **payment.ts**（Stmts 45% / Branch 33%）——支付模块高风险，覆盖率最低
2. **auth.ts**（60% / 50%）——认证模块同样是高风险区域
3. **utils.ts**（95%）——已达标
4. **logger.ts**（100%）——无需操作

payment.ts 分支覆盖率 33%，意味着大量 if/else 路径未被测试，这是最危险的盲区。

### 练习三

```typescript
// scripts/check-coverage.ts
import { readFileSync } from 'fs'
import { join } from 'path'

const THRESHOLD = 80
const coveragePath = join(process.cwd(), 'coverage', 'coverage-summary.json')

try {
  const data = JSON.parse(readFileSync(coveragePath, 'utf-8'))
  let hasFailure = false

  for (const [file, metrics] of Object.entries(data) as [string, any][]) {
    if (file === 'total') continue
    const stmtPct = metrics.statements?.pct ?? 0
    if (stmtPct < THRESHOLD) {
      console.warn(`⚠️  ${file}: 语句覆盖率 ${stmtPct}% < ${THRESHOLD}%`)
      hasFailure = true
    }
  }

  const totalPct = data.total?.statements?.pct ?? 0
  console.log(`\n整体语句覆盖率: ${totalPct}%`)

  if (hasFailure) {
    console.error('\n❌ 存在未达阈值的模块')
    process.exit(1)
  } else {
    console.log('✅ 所有模块达标')
  }
} catch (err) {
  console.error('无法读取覆盖率报告，请先运行 vitest run --coverage')
  process.exit(1)
}
```
