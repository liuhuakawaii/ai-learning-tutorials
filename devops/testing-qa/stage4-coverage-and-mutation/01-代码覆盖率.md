# 代码覆盖率

## 场景引入

你的团队维护一个支付核心模块，上线前要求"测试覆盖率达到 80%"。QA 跑完测试后报告覆盖率 85%，看起来达标了。但上线后还是出了 bug——某个边界条件下的手续费计算错误。

覆盖率 85% 意味着什么？哪些代码被覆盖了、哪些没有？这一课我们搞懂四种覆盖率指标、如何在 Vitest 中配置覆盖率、解读报告，以及在 CI 中自动化检查。

## 学习目标

- 理解四种覆盖率指标（Statement / Branch / Function / Line）的含义与区别
- 掌握 Vitest 中 v8 coverage provider 的配置方法
- 学会解读 HTML、LCOV、text 格式的覆盖率报告
- 能够为项目设置合理的覆盖率阈值并在 CI 中执行

## 四种覆盖率指标

### 语句覆盖率（Statement Coverage）

每条可执行语句是否至少被执行了一次。

```typescript
// src/calculator.ts
export function divide(a: number, b: number): number {
  if (b === 0) {
    throw new Error('除数不能为零')  // 语句 1
  }
  return a / b                        // 语句 2
}
```

只调用 `divide(10, 2)` 时，语句 1 没被执行，语句覆盖率是 50%。

### 分支覆盖率（Branch Coverage）

每个控制流分支是否都被走过。`if`、`switch`、三元表达式各有 true / false 两个分支。上面的例子需要同时测试 `b === 0` 和 `b !== 0` 才能达到 100% 分支覆盖率。

### 函数覆盖率（Function Coverage）

每个函数是否至少被调用了一次。模块里从未被测试触碰的函数会拉低这个指标。

### 行覆盖率（Line Coverage）

每行源代码是否至少被执行了一行。一行可能包含多条语句（`const x = 1; const y = 2`），与语句覆盖率略有差异。

**关键区别**：分支覆盖率最有价值——它能暴露控制流中的盲区。

## Vitest 覆盖率配置

### 安装依赖

```bash
npm install -D @vitest/coverage-v8
```

### 完整配置

```typescript
// vitest.config.ts
import { defineConfig } from 'vitest/config'

export default defineConfig({
  test: {
    coverage: {
      provider: 'v8',
      reporter: ['text', 'html', 'lcov', 'json-summary'],
      reportsDirectory: './coverage',
      include: ['src/**/*.ts'],
      exclude: [
        'src/**/*.test.ts',
        'src/**/*.spec.ts',
        'src/**/index.ts',
        'src/**/types.ts',
      ],
      thresholds: {
        statements: 80,
        branches: 75,
        functions: 80,
        lines: 80,
        'src/core/**/*.ts': {
          statements: 90,
          branches: 85,
          functions: 90,
          lines: 90,
        },
      },
    },
  },
})
```

### 运行

```bash
npx vitest run --coverage
```

## 覆盖率报告解读

### text 报告（终端）

```
 % Coverage report from v8
 ---------------------------------------|---------|----------|---------|---------|
 File                                   | % Stmts | % Branch | % Funcs | % Lines |
 ---------------------------------------|---------|----------|---------|---------|
 src/                                   |   82.35 |    71.43 |   85.71 |   82.35 |
  calculator.ts                         |   100   |    100   |   100   |   100   |
  payment.ts                            |   75.00 |    50.00 |   66.67 |   75.00 |
 ---------------------------------------|---------|----------|---------|---------|
```

未达阈值的数字会以红色显示。

### HTML 报告

打开 `coverage/index.html`，逐文件查看哪些行被覆盖（绿色）、哪些未覆盖（红色）。这是日常开发中最常用的格式——直接定位未覆盖的代码行。

### LCOV 报告

`coverage/lcov.info` 是标准化格式，可上传到 Codecov、Coveralls、SonarQube 等平台。

### json-summary 报告

`coverage/coverage-summary.json` 适合被脚本或看板系统读取：

```json
{
  "total": {
    "statements": { "total": 170, "covered": 140, "pct": 82.35 },
    "branches": { "total": 42, "covered": 30, "pct": 71.43 },
    "functions": { "total": 35, "covered": 30, "pct": 85.71 },
    "lines": { "total": 170, "covered": 140, "pct": 82.35 }
  }
}
```

## CI 中的覆盖率集成

```yaml
# .github/workflows/test.yml
name: Test & Coverage

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20

      - run: npm ci
      - run: npx vitest run --coverage

      - name: Upload coverage to Codecov
        uses: codecov/codecov-action@v4
        with:
          files: ./coverage/lcov.info
          fail_ci_if_error: true
          token: ${{ secrets.CODECOV_TOKEN }}
```

Vitest 的 `thresholds` 配置天然适配 CI 门禁——不达标直接以非零退出码失败，无需额外脚本。

## 常见误区

**误区一：覆盖率高 = 测试质量高**

覆盖率只衡量"代码被执行了"，不衡量"断言有没有做"。一个测试调用了函数但没有任何 expect，也会被计入覆盖率。

**误区二：追求 100% 覆盖率**

100% 覆盖率成本极高且收益递减。合理目标是核心逻辑 90%+，整体 75-85%。

**误区三：只关注整体数字**

整体 85% 可能掩盖了某个关键模块只有 30% 覆盖率的事实。应按目录/模块设置不同阈值。

**误区四：覆盖率是唯一的质量指标**

覆盖率是必要不充分条件，还需结合变异测试、代码审查、静态分析等手段。

## 工程建议

1. **从低阈值起步，逐步提高**：新项目先设 60%，每季度提高 5%
2. **核心模块用更高阈值**：支付、权限等关键路径要求 90%+
3. **HTML 报告是日常开发利器**：红色未覆盖行一目了然
4. **CI 只检查 LCOV + 阈值**：不需要在 CI 中生成 HTML 报告
5. **增量覆盖率比整体覆盖率更有意义**：关注 PR 引入的新代码覆盖率

## 小结

- 四种覆盖率指标：语句、分支、函数、行。分支覆盖率对发现控制流盲区最有价值
- Vitest 通过 `@vitest/coverage-v8` 提供零配置的覆盖率收集，支持 text / HTML / LCOV 等格式
- 覆盖率阈值配合 CI 可以作为代码合入的硬性门禁
- 覆盖率是质量的必要不充分条件——高覆盖率不代表好测试，但低覆盖率一定说明测试不足

## 参考答案

### 练习一

```typescript
// vitest.config.ts
import { defineConfig } from 'vitest/config'

export default defineConfig({
  test: {
    coverage: {
      provider: 'v8',
      reporter: ['text', 'html', 'lcov'],
      exclude: ['**/*.test.ts', '**/types.ts'],
      thresholds: {
        statements: 80,
        branches: 70,
      },
    },
  },
})
```

运行 `npx vitest run --coverage`，需要提前安装 `@vitest/coverage-v8`。

### 练习二

优先级排序：
1. **payment.ts**（Stmts 45% / Branch 33%）——支付模块高风险，覆盖率最低
2. **auth.ts**（Stmts 60% / Branch 50%）——认证模块同样是高风险区域
3. **utils.ts**（95%）——已达标，按需补充
4. **logger.ts**（100%）——无需操作

payment.ts 的分支覆盖率只有 33%，意味着大量 if/else 路径未被测试，这是最危险的盲区。
