# 覆盖率陷阱

## 场景引入

团队把覆盖率阈值卡到了 80%，但上线后一个简单的空指针 bug 仍然逃过了测试。复盘发现：测试确实调用了那个函数（覆盖率达标），但没有对返回值做任何断言。

覆盖率达标 ≠ 测试有效。这一课我们拆解覆盖率的各种陷阱，学会区分"有效覆盖率"和"无效覆盖率"。

## 学习目标

- 识别常见的假测试模式（无断言、只测 happy path、测试实现细节）
- 理解 100% 覆盖率为什么不代表没有 bug
- 学会判断一个测试是否有真正的价值

## 陷阱一：无断言的假测试

测试调用了函数，代码被覆盖了，但没有任何验证。

```typescript
// src/discount.ts
export function calculateDiscount(price: number, rate: number): number {
  if (rate < 0 || rate > 1) {
    throw new Error('折扣率必须在 0 到 1 之间')
  }
  return price * (1 - rate)
}
```

```typescript
// ❌ 假测试：调用了函数但没断言
describe('calculateDiscount', () => {
  it('计算折扣', () => {
    calculateDiscount(100, 0.2) // 覆盖了函数，但没验证结果
  })
})
```

这个测试让覆盖率 100%，但函数即使返回 `NaN` 或 `undefined` 也会通过。

```typescript
// ✅ 真正的测试
describe('calculateDiscount', () => {
  it('按折扣率计算折后价', () => {
    expect(calculateDiscount(100, 0.2)).toBe(80)
  })

  it('折扣率超出范围时抛出错误', () => {
    expect(() => calculateDiscount(100, 1.5)).toThrow('折扣率必须在 0 到 1 之间')
  })
})
```

**判断标准**：每个测试至少要有一个 `expect`。

## 陷阱二：只测 Happy Path

```typescript
// src/parser.ts
export function parseAge(input: string): number {
  const trimmed = input.trim()
  if (trimmed === '') throw new Error('年龄不能为空')
  const num = Number(trimmed)
  if (isNaN(num)) throw new Error('年龄必须是数字')
  if (num < 0 || num > 150) throw new Error('年龄必须在 0-150 之间')
  return Math.floor(num)
}
```

```typescript
// ❌ 只测 happy path → 分支覆盖率只有 25%
describe('parseAge', () => {
  it('解析正常年龄', () => { expect(parseAge('25')).toBe(25) })
  it('解析带空格的年龄', () => { expect(parseAge(' 30 ')).toBe(30) })
})
```

```typescript
// ✅ 覆盖所有分支 → 分支覆盖率 100%
describe('parseAge', () => {
  it('解析正常年龄', () => { expect(parseAge('25')).toBe(25) })
  it('空字符串抛出错误', () => { expect(() => parseAge('')).toThrow('年龄不能为空') })
  it('非数字抛出错误', () => { expect(() => parseAge('abc')).toThrow('年龄必须是数字') })
  it('负数抛出错误', () => { expect(() => parseAge('-5')).toThrow('年龄必须在 0-150 之间') })
  it('超出上限抛出错误', () => { expect(() => parseAge('200')).toThrow('年龄必须在 0-150 之间') })
})
```

## 陷阱三：过度测试实现细节

测试不关注"函数做了什么"，而是关注"函数内部怎么做的"。重构内部实现后测试全碎——即使行为完全没变。

```typescript
// src/sorter.ts
export function sortByName(items: { name: string }[]): { name: string }[] {
  return [...items].sort((a, b) => a.name.localeCompare(b.name))
}
```

```typescript
// ❌ 依赖了内部调用方式
it('使用 localeCompare 排序', () => {
  const spy = vi.spyOn(String.prototype, 'localeCompare')
  sortByName([{ name: 'Bob' }, { name: 'Alice' }])
  expect(spy).toHaveBeenCalled()
  spy.mockRestore()
})
```

如果改用其他排序方式，测试会失败但功能完全正确。

```typescript
// ✅ 测试行为，不测实现
it('按名称字母顺序排序', () => {
  const result = sortByName([{ name: 'Bob' }, { name: 'Alice' }])
  expect(result.map(i => i.name)).toEqual(['Alice', 'Bob'])
})
```

**判断标准**：重构函数内部实现但行为不变时，测试不应该失败。

## 陷阱四：不验证边界值

```typescript
// src/pagination.ts
export function paginate<T>(items: T[], page: number, pageSize: number): T[] {
  const start = (page - 1) * pageSize
  return items.slice(start, start + pageSize)
}
```

```typescript
// ❌ 只测了正常情况，覆盖率 100% 但以下场景未测试：
// - 最后一页不满、超出范围的页码、page = 0

// ✅ 测试边界值
describe('paginate', () => {
  it('返回第一页', () => { expect(paginate([1, 2, 3, 4, 5], 1, 2)).toEqual([1, 2]) })
  it('最后一页不满时返回剩余元素', () => { expect(paginate([1, 2, 3, 4, 5], 3, 2)).toEqual([5]) })
  it('超出范围的页码返回空数组', () => { expect(paginate([1, 2, 3], 10, 2)).toEqual([]) })
  it('空数组返回空数组', () => { expect(paginate([], 1, 10)).toEqual([]) })
})
```

## 有效覆盖率 vs 无效覆盖率

```typescript
// src/validator.ts
export function isValidEmail(email: string): boolean {
  if (!email || email.length === 0) return false
  if (email.length > 254) return false
  const parts = email.split('@')
  if (parts.length !== 2) return false
  if (parts[0].length === 0) return false
  if (!parts[1].includes('.')) return false
  return true
}
```

```typescript
// ❌ 无效覆盖率：调用了但没断言
it('测试邮箱验证', () => {
  isValidEmail('test@example.com')
  isValidEmail('invalid')
  isValidEmail('')
  // 没有 expect，100% 覆盖率但零价值
})

// ✅ 有效覆盖率：每个分支都有断言
it('合法邮箱返回 true', () => { expect(isValidEmail('test@example.com')).toBe(true) })
it('空字符串返回 false', () => { expect(isValidEmail('')).toBe(false) })
it('超过 254 字符返回 false', () => {
  expect(isValidEmail('a'.repeat(250) + '@b.com')).toBe(false)
})
it('缺少 @ 返回 false', () => { expect(isValidEmail('testexample.com')).toBe(false) })
```

两组测试的覆盖率报告完全一样——都是 100%。但有效覆盖率那组真正验证了行为。

## 如何判断测试是否有价值

**问题一：测试失败时，你高兴还是沮丧？** 如果心想"太好了，抓到了 bug"——有价值。如果心想"改了实现又要改测试"——脆弱测试。

**问题二：删掉这个测试，你会不安吗？** 不安就保留，不不安就可能是冗余的。

**问题三：断言是否足够具体？**

```typescript
// 模糊断言——几乎任何值都能通过
expect(result).toBeDefined()
expect(result).toBeTruthy()

// 具体断言——只有一种正确结果能通过
expect(result).toEqual({ id: 1, name: 'Alice', status: 'active' })
```

## 常见误区

**误区一：把覆盖率当目标而非指标**——覆盖率是诊断工具，不是 KPI。刷数字会产出低质量测试。

**误区二：忽略测试的维护成本**——过度测试实现细节会产生大量维护负担。测试价值 = 防止的 bug 损失 - 维护成本。

**误区三：覆盖率可以"补"出来**——临上线前突击补测试，通常产出的都是假测试。

## 工程建议

1. **Code Review 关注测试质量，不只是覆盖率数字**
2. **用变异测试验证断言质量**——覆盖率告诉你代码被跑了，变异测试告诉你断言能不能抓住 bug
3. **定期清理脆弱测试**——那些因重构频繁碎掉的测试，很可能在验证实现细节
4. **团队达成共识"什么是好测试"**——比工具和阈值更重要

## 小结

- 100% 覆盖率不代表没有 bug，覆盖率只衡量"代码被执行了"
- 四种假测试模式：无断言、只测 happy path、过度测试实现细节、不验证边界值
- 判断测试价值：失败时高兴吗？删了不安吗？断言够具体吗？
- 覆盖率是诊断工具不是目标，配合变异测试才能全面评估测试质量

### 练习二：补充边界测试

为 `clamp(value, min, max)` 函数补充边界值测试，确保分支覆盖率 100%。

```typescript
function clamp(value: number, min: number, max: number): number {
  if (min > max) throw new Error('min 不能大于 max')
  if (value < min) return min
  if (value > max) return max
  return value
}
```

## 参考答案

### 练习一

- **"创建用户"**：假测试，完全没有 expect
- **"获取用户"**：半假测试，`expect(user).toBeDefined()` 太宽松

修复：

```typescript
it('创建用户', () => {
  const service = new UserService()
  const user = service.createUser({ name: 'Alice', email: 'alice@test.com' })
  expect(user).toMatchObject({ name: 'Alice', email: 'alice@test.com' })
  expect(user.id).toBeDefined()
})
it('获取用户', () => {
  const service = new UserService()
  const created = service.createUser({ name: 'Bob', email: 'bob@test.com' })
  const user = service.getUser(created.id)
  expect(user).toEqual(created)
})
```

### 练习二

```typescript
describe('clamp', () => {
  it('值在范围内时返回原值', () => { expect(clamp(5, 0, 10)).toBe(5) })
  it('值低于最小值时返回最小值', () => { expect(clamp(-5, 0, 10)).toBe(0) })
  it('值高于最大值时返回最大值', () => { expect(clamp(15, 0, 10)).toBe(10) })
  it('值等于边界值时返回边界值', () => {
    expect(clamp(0, 0, 10)).toBe(0)
    expect(clamp(10, 0, 10)).toBe(10)
  })
  it('min 大于 max 时抛出错误', () => {
    expect(() => clamp(5, 10, 0)).toThrow('min 不能大于 max')
  })
})
```
