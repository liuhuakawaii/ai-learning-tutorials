# 性能基准测试

## 场景引入

你优化了一个核心函数，本地跑起来"感觉快了"。上线后用户反馈"变慢了"。"感觉快了"不是工程结论，"快了 30%，P95 从 120ms 降到 84ms"才是。没有基准测试，你不知道优化有没有效果。

## 学习目标

- 掌握 Vitest bench API 的使用方法
- 学会编写有意义的基准测试
- 了解如何在 CI 中检测性能回归
- 避免微基准测试的常见噪声

## Vitest Bench API

Vitest 内置基准测试支持，基于 tinybench。

```typescript
// src/utils.bench.ts
import { bench, describe } from 'vitest'

describe('字符串拼接性能对比', () => {
  bench('模板字符串', () => {
    const name = 'Alice'
    const result = `Name: ${name}, Age: 30`
  })

  bench('字符串拼接', () => {
    const name = 'Alice'
    const result = 'Name: ' + name + ', Age: 30'
  })
})
```

运行：`npx vitest bench`

输出示例：

```
   name           hz     min    mean     p99    rme  samples
 · 模板字符串  12456789  0.0000  0.0001  0.0002  ±0.42%  6228395
 · 字符串拼接  11234567  0.0001  0.0001  0.0003  ±0.51%  5617284
```

- **hz**：每秒操作次数（越高越好）
- **mean**：平均耗时（毫秒）
- **p99**：99 分位耗时
- **rme**：相对误差幅度，越小越稳定

配置：

```typescript
// vitest.config.ts
import { defineConfig } from 'vitest/config'

export default defineConfig({
  test: {
    bench: {
      include: ['**/*.bench.ts'],
      reporters: ['default', 'json'],
      outputFile: { json: './bench-results/results.json' },
    },
  },
})
```

## 编写有意义的基准测试

### 避免死代码消除

编译器可能优化掉未使用的计算结果：

```typescript
// ❌ 结果未使用，可能被优化掉
bench('JSON parse', () => { JSON.parse('{"a":1}') })

// ✅ 返回结果防止死代码消除
bench('JSON parse', () => {
  const result = JSON.parse('{"a":1}')
  return result
})
```

### 测试不同规模

覆盖不同数据规模，观察性能随规模的变化：

```typescript
import { bench, describe } from 'vitest'

function linearSearch(arr: number[], target: number): number {
  for (let i = 0; i < arr.length; i++) {
    if (arr[i] === target) return i
  }
  return -1
}

function binarySearch(arr: number[], target: number): number {
  let left = 0, right = arr.length - 1
  while (left <= right) {
    const mid = Math.floor((left + right) / 2)
    if (arr[mid] === target) return mid
    if (arr[mid] < target) left = mid + 1
    else right = mid - 1
  }
  return -1
}

for (const size of [100, 1000, 10000, 100000]) {
  const sorted = Array.from({ length: size }, (_, i) => i)
  const target = size - 1

  describe(`数组大小 ${size}`, () => {
    bench('线性搜索', () => { linearSearch(sorted, target) })
    bench('二分搜索', () => { binarySearch(sorted, target) })
  })
}
```

## CI 中的性能回归检测

### 对比脚本

```typescript
// scripts/compare-benchmarks.ts
import { readFileSync } from 'fs'

interface BenchFile {
  testResults: Array<{
    fullName: string
    benchmarkResults: Array<{ name: string; hz: number }>
  }>
}

const THRESHOLD = 0.15
const current: BenchFile = JSON.parse(readFileSync('./bench-results/current.json', 'utf-8'))
const baseline: BenchFile = JSON.parse(readFileSync('./bench-results/baseline.json', 'utf-8'))
const regressions: string[] = []

for (const suite of current.testResults) {
  const baseSuite = baseline.testResults.find(b => b.fullName === suite.fullName)
  if (!baseSuite) continue
  for (const bench of suite.benchmarkResults) {
    const baseBench = baseSuite.benchmarkResults.find(b => b.name === bench.name)
    if (!baseBench) continue
    const change = (baseBench.hz - bench.hz) / baseBench.hz
    if (change > THRESHOLD) {
      regressions.push(`"${bench.name}": 下降 ${(change * 100).toFixed(1)}%`)
    }
  }
}

if (regressions.length > 0) {
  console.error('❌ 检测到性能回归：')
  regressions.forEach(r => console.error(`  - ${r}`))
  process.exit(1)
} else {
  console.log('✅ 未检测到性能回归')
}
```

### GitHub Actions

```yaml
# .github/workflows/benchmark.yml
name: Performance Benchmark
on:
  pull_request: { branches: [main] }

jobs:
  benchmark:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: npm ci

      - name: Download baseline
        uses: actions/download-artifact@v4
        with: { name: bench-baseline, path: ./bench-results/ }
        continue-on-error: true

      - name: Run benchmarks
        run: npx vitest bench --reporter=json --outputFile=./bench-results/results.json

      - name: Compare with baseline
        run: npx tsx scripts/compare-benchmarks.ts
        continue-on-error: true

      - name: Upload new baseline
        if: github.ref == 'refs/heads/main'
        uses: actions/upload-artifact@v4
        with: { name: bench-baseline, path: ./bench-results/results.json }
```

## 避免微基准测试的噪声

噪声来源：CPU 频率波动、垃圾回收、后台进程、JIT 编译、缓存效应。

```typescript
// ✅ 增加采样时间
bench('稳定测试', () => { /* ... */ }, { time: 2000, iterations: 1000 })

// ✅ 避免 I/O，只测 CPU 密集型操作
bench('parseContent', () => { parseContent(cachedContent) })
```

## 常见误区

**误区一：基准测试 = 正确性测试**——只关心性能，不关心结果对不对。

**误区二：只看平均值**——平均值被异常值拉偏，应关注 p99。

**误区三：在开发机上跑**——IDE、浏览器等干扰大，CI 环境更干净。

**误区四：过度优化**——不要为 1% 的提升花 1 天时间。

## 工程建议

1. **只对关键路径做基准测试**：聚焦性能敏感的核心逻辑
2. **CI 中保存基线并对比**：每次合入 main 时保存基线，PR 时对比
3. **设置合理的回归阈值**：10%-20% 的波动通常是噪声
4. **基准测试文件用 `.bench.ts` 命名**：不会和单元测试混淆
5. **关注 p75/p99 而非平均值**

## 小结

- 性能基准测试为优化提供量化依据，防止性能回归
- Vitest bench API 简单易用，支持预热、百分位统计、JSON 输出
- 有意义的基准测试要避免死代码消除、覆盖不同数据规模、隔离噪声
- CI 中通过基线对比自动检测性能回归

## 参考答案

### 练习一

```typescript
// src/dedup.bench.ts
import { bench, describe } from 'vitest'

function uniqueWithSet<T>(arr: T[]): T[] { return [...new Set(arr)] }
function uniqueWithFilter<T>(arr: T[]): T[] {
  return arr.filter((item, index) => arr.indexOf(item) === index)
}

for (const size of [100, 1000, 5000]) {
  const data = Array.from({ length: size }, () => Math.floor(Math.random() * (size / 2)))
  describe(`数组大小 ${size}`, () => {
    bench('Set 去重', () => { uniqueWithSet(data) })
    bench('filter + indexOf', () => { uniqueWithFilter(data) })
  })
}
```

Set 是 O(n)，filter+indexOf 是 O(n²)，规模增大后差距急剧拉大。
