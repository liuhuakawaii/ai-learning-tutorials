# 模糊测试

## 场景引入

你写了一个 JSON 解析器的包装函数，测试了正常 JSON、空对象、嵌套数组——覆盖率 95%。但上线后收到了一个诡异的输入导致函数崩溃。

传统测试是你想到什么测什么，模糊测试（Fuzz Testing）是让计算机帮你想——用大量随机、边界、畸形输入轰炸你的函数，找出你想不到的 bug。

## 学习目标

- 理解 property-based testing 的核心思想
- 掌握 fast-check 的 Arbitrary 生成器系统
- 学会定义属性（Property）——对任意输入都应满足的规则
- 理解 Shrinking 机制如何找到最小失败案例

## Property-Based Testing

传统测试是"例子驱动"：

```typescript
expect(add(1, 2)).toBe(3)
expect(add(0, 0)).toBe(0)
```

Property-based testing 是"属性驱动"——你定义规则，工具自动生成大量输入验证：

```typescript
import fc from 'fast-check'

fc.assert(
  fc.property(fc.integer(), fc.integer(), (a, b) => {
    expect(add(a, b)).toBe(a + b) // 对任意整数都应满足
  })
)
```

安装：

```bash
npm install -D fast-check
```

## Arbitrary 生成器

Arbitrary 描述了如何生成和缩小某一类型的随机值。

```typescript
import fc from 'fast-check'

// 基础类型
fc.integer()                              // 任意整数
fc.integer({ min: 0, max: 100 })          // 范围整数
fc.float({ min: 0, max: 1 })              // 浮点数
fc.string()                               // 任意字符串
fc.boolean()                              // true / false
fc.constantFrom('a', 'b', 'c')           // 从列表选

// 复合类型
fc.array(fc.integer(), { maxLength: 10 }) // 整数数组
fc.record({                               // 对象
  name: fc.string(),
  age: fc.integer({ min: 0, max: 150 }),
})
fc.tuple(fc.string(), fc.integer())       // 元组
fc.oneof(fc.constant(null), fc.integer()) // 联合类型

// 特殊类型
fc.date()                                 // 日期
fc.jsonValue()                            // JSON 值
fc.emailAddress()                         // 邮箱
fc.uuid()                                 // UUID
```

## 定义属性

### 往返属性（Round-trip）

encode 后 decode 应得到原始值：

```typescript
test('JSON 序列化往返', () => {
  fc.assert(
    fc.property(fc.jsonValue(), (value) => {
      expect(JSON.parse(JSON.stringify(value))).toEqual(value)
    })
  )
})
```

### 不变量属性（Invariant）

操作不应改变某些特征：

```typescript
test('排序不改变数组长度', () => {
  fc.assert(
    fc.property(fc.array(fc.integer()), (arr) => {
      expect([...arr].sort((a, b) => a - b)).toHaveLength(arr.length)
    })
  )
})
```

### 逆属性（Inverse）

互逆操作应互相抵消：

```typescript
test('编码和解码互逆', () => {
  fc.assert(
    fc.property(fc.string(), (s) => {
      expect(decodeURIComponent(encodeURIComponent(s))).toBe(s)
    })
  )
})
```

### 幂等属性（Idempotent）

重复操作结果不变：

```typescript
test('排序是幂等的', () => {
  fc.assert(
    fc.property(fc.array(fc.integer()), (arr) => {
      const once = [...arr].sort((a, b) => a - b)
      const twice = [...once].sort((a, b) => a - b)
      expect(twice).toEqual(once)
    })
  )
})
```

## Shrinking 机制

当测试失败时，fast-check 自动尝试找到最小的失败案例。

假设排序函数在包含负数时出错，fast-check 可能先生成 `[42, -7, 13, 0, -99, 56]`，测试失败后自动缩小到 `[-1, 0]` 这样的最小案例：

```
Property failed after 15 tests
Counterexample: [-1, 0]
Shrunk 12 time(s)
```

缩小后的最小案例让 bug 一目了然。大多数内置 Arbitrary 已自带缩小策略，无需额外配置。

## 实战：测试 JSON 解析器

```typescript
// src/safe-json.ts
export function safeParseJson<T>(input: string):
  { success: true; data: T } | { success: false; error: string } {
  try {
    return { success: true, data: JSON.parse(input) }
  } catch (e) {
    return { success: false, error: (e as Error).message }
  }
}
```

```typescript
// src/safe-json.test.ts
import { describe, test, expect } from 'vitest'
import fc from 'fast-check'
import { safeParseJson } from './safe-json'

describe('safeParseJson', () => {
  test('合法 JSON 总是解析成功', () => {
    fc.assert(
      fc.property(fc.jsonValue(), (value) => {
        const result = safeParseJson(JSON.stringify(value))
        expect(result.success).toBe(true)
        if (result.success) expect(result.data).toEqual(value)
      })
    )
  })

  test('非法 JSON 总是返回错误', () => {
    fc.assert(
      fc.property(
        fc.string().filter(s => {
          try { JSON.parse(s); return false } catch { return true }
        }),
        (invalidJson) => {
          expect(safeParseJson(invalidJson).success).toBe(false)
        }
      )
    )
  })
})
```

## 实战：测试排序函数

```typescript
// src/sort.ts
export function insertionSort(arr: number[]): number[] {
  const result = [...arr]
  for (let i = 1; i < result.length; i++) {
    const key = result[i]
    let j = i - 1
    while (j >= 0 && result[j] > key) {
      result[j + 1] = result[j]
      j--
    }
    result[j + 1] = key
  }
  return result
}
```

```typescript
// src/sort.test.ts
import { describe, test, expect } from 'vitest'
import fc from 'fast-check'
import { insertionSort } from './sort'

describe('insertionSort', () => {
  test('输出是有序的', () => {
    fc.assert(
      fc.property(fc.array(fc.integer()), (arr) => {
        const sorted = insertionSort(arr)
        for (let i = 1; i < sorted.length; i++) {
          expect(sorted[i]).toBeGreaterThanOrEqual(sorted[i - 1])
        }
      })
    )
  })

  test('输出是输入的排列', () => {
    fc.assert(
      fc.property(fc.array(fc.integer()), (arr) => {
        const sorted = insertionSort(arr)
        expect([...sorted].sort((a, b) => a - b))
          .toEqual([...arr].sort((a, b) => a - b))
      })
    )
  })

  test('不修改原数组', () => {
    fc.assert(
      fc.property(fc.array(fc.integer()), (arr) => {
        const original = [...arr]
        insertionSort(arr)
        expect(arr).toEqual(original)
      })
    )
  })
})
```

## 常见误区

**误区一：把 fast-check 当随机测试**——关键是定义有意义的属性，不是随便跑跑。

**误区二：属性太弱**——`expect(Array.isArray(result)).toBe(true)` 不算属性。

**误区三：忽略 Shrinking**——直接用原始反例调试，不利用缩小后的最小案例。

**误区四：替代传统测试**——两者互补。传统测试验证具体场景，property-based testing 发现边界情况。

## 工程建议

1. **从核心纯函数开始**：排序、序列化、编解码最适合
2. **属性要具体有业务含义**：不要写 `expect(result).toBeDefined()`
3. **利用 Shrinking 调试**：失败时直接用输出的最小案例
4. **CI 中增加测试次数**：本地 100 次够了，CI 中可以跑 500-1000 次
5. **保存失败的种子**：fast-check 输出的 seed 可以精确复现失败

## 小结

- Property-based testing 定义"对任意输入应满足的规则"，由工具自动生成大量用例
- fast-check 提供丰富的 Arbitrary 生成器，覆盖基础类型、复合类型、Web 相关类型
- Shrinking 机制在失败时自动找到最小案例，大幅降低调试成本
- 常见属性模式：往返、不变量、逆操作、幂等性
- 与传统测试互补，特别适合测试纯函数和数据处理逻辑

## 参考答案

### 练习一

```typescript
import fc from 'fast-check'

test('两次反转回到原值', () => {
  fc.assert(
    fc.property(fc.string(), (s) => {
      expect(reverseString(reverseString(s))).toBe(s)
    })
  )
})

test('输出长度等于输入长度', () => {
  fc.assert(
    fc.property(fc.string(), (s) => {
      expect(reverseString(s)).toHaveLength(s.length)
    })
  )
})

test('不改变字符集合', () => {
  fc.assert(
    fc.property(fc.string(), (s) => {
      expect(reverseString(s).split('').sort().join(''))
        .toBe(s.split('').sort().join(''))
    })
  )
})
```

"两次反转回到原值"是最强的属性——如果只有一个属性要测，选这个。

### 练习二

```typescript
import fc from 'fast-check'

test('encodeURIComponent/decodeURIComponent 往返', () => {
  fc.assert(
    fc.property(fc.string(), (s) => {
      expect(decodeURIComponent(encodeURIComponent(s))).toBe(s)
    })
  )
})

test('编码后不含 URI 特殊字符', () => {
  fc.assert(
    fc.property(fc.string(), (s) => {
      const encoded = encodeURIComponent(s)
      expect(encoded).not.toContain('#')
      expect(encoded).not.toContain('?')
      expect(encoded).not.toContain('&')
    })
  )
})
```
