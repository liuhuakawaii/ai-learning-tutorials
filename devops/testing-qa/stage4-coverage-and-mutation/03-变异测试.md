# 变异测试

## 场景引入

上一课我们知道了覆盖率 100% 不代表测试有效。那怎么衡量测试的"真正质量"？

答案是变异测试（Mutation Testing）：故意把源代码改坏（比如把 `+` 换成 `-`），然后看测试能不能发现。如果测试通过了，说明断言不够强；如果测试失败了，说明测试抓住了这个变异体。

覆盖率衡量"代码被跑了多少"，变异测试衡量"测试能抓住多少 bug"。

## 学习目标

- 理解变异测试的核心原理：变异算子、变异分数、存活变异体
- 掌握 Stryker Mutator 的安装与配置
- 学会解读变异测试报告并改进测试

## 变异测试原理

1. **生成变异体**：工具自动修改源代码中的一个位置
2. **运行测试**：对每个变异体运行完整测试套件
3. **分类结果**：
   - **被杀死（Killed）**：至少一个测试失败 → 测试有效
   - **存活（Survived）**：所有测试通过 → 测试有盲区
   - **超时（Timeout）**：变异导致死循环
   - **编译错误（Compile Error）**：变异导致语法错误

```typescript
// 原始代码
function add(a: number, b: number): number { return a + b }

// 变异体 1：+ → -    测试 expect(add(1,1)).toBe(2) → 失败 → 被杀死
// 变异体 2：+ → *    测试 expect(add(0,0)).toBe(0) → 通过 → 存活！
```

`add(0, 0)` 时 `0 + 0` 和 `0 * 0` 都等于 0，所以变异体存活。需要更强的断言。

### 变异分数（Mutation Score）

```
变异分数 = 被杀死的变异体 / (总变异体 - 等价变异体) × 100%
```

- **70% 以下**：测试质量堪忧
- **70%-85%**：基本合格
- **85% 以上**：测试质量较高

## Stryker Mutator 安装配置

### 安装

```bash
npm install -D @stryker-mutator/core @stryker-mutator/vitest-runner
```

### 配置

```javascript
// stryker.config.mjs
/** @type {import('@stryker-mutator/api/core').PartialStrykerOptions} */
const config = {
  packageManager: 'npm',
  reporters: ['html', 'clear-text', 'progress'],
  testRunner: 'vitest',
  testRunnerNodeArgs: ['--import=tsx'],
  coverageAnalysis: 'perTest',
  mutate: [
    'src/**/*.ts',
    '!src/**/*.test.ts',
    '!src/**/*.spec.ts',
    '!src/**/types.ts',
    '!src/**/index.ts',
  ],
  thresholds: {
    high: 85,
    low: 70,
    break: 60,
  },
  htmlReporter: {
    fileName: 'reports/mutation.html',
  },
}

export default config
```

### 运行

```bash
npx stryker run                    # 完整变异测试
npx stryker run --mutate 'src/calculator.ts'  # 只对特定文件
npx stryker run --incremental      # 增量模式，只测变更文件
```

## 常见变异算子

### 算术运算符变异

```typescript
// 原始: price * quantity
// 变异: price + quantity, price - quantity, price / quantity
```

### 条件表达式变异

```typescript
// 原始: if (age >= 18 && hasId)
// 变异: if (age > 18 && hasId)    // >= → >
//       if (age >= 18 || hasId)    // && → ||
//       if (age >= 18 && !hasId)   // hasId → !hasId
```

### 语句变异

```typescript
// 原始: saveToDatabase(order)
// 变异: // saveToDatabase(order) 被删除
```

### 返回值变异

```typescript
// 原始: return age >= 18
// 变异: return true
//       return false
```

## 改进测试：从存活变异体学习

假设报告指出变异体 `return price * (1 - rate)` → `return price * (1 + rate)` 存活了：

```typescript
// 当前测试：rate=0 时 1-0 和 1+0 都等于 1，变异体存活
it('计算折扣', () => {
  expect(calculateDiscount(100, 0)).toBe(100)
})

// 补充测试：rate ≠ 0 时能区分 + 和 -
it('计算折扣', () => {
  expect(calculateDiscount(100, 0)).toBe(100)
  expect(calculateDiscount(100, 0.2)).toBe(80)  // 1-0.2=0.8, 1+0.2=1.2
})
```

## 处理等价变异体

等价变异体是语法上不同但语义上等价的变异——无论怎么测都杀不死。

```typescript
// 原始: for (let i = 0; i < arr.length; i++)
// 变异: for (let i = 0; i <= arr.length - 1; i++)
// 这两个条件完全等价
```

处理策略：

```javascript
// stryker.config.mjs - 排除特定变异算子
const config = {
  mutator: {
    excludedMutations: ['StringLiteral'],
  },
}
```

```typescript
// 代码中用注释跳过特定变异
// Stryker disable next-block Mutation
function legacyCalc(x: number): number {
  return x + 0
}
// Stryker restore
```

## CI 集成

```yaml
# .github/workflows/mutation.yml
name: Mutation Testing

on:
  pull_request:
    branches: [main]

jobs:
  mutation:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - name: Run mutation tests
        run: npx stryker run --incremental
      - name: Upload report
        uses: actions/upload-artifact@v4
        with:
          name: mutation-report
          path: reports/mutation.html
```

变异测试较慢，建议 PR 时只跑增量模式，完整变异测试放到 nightly 构建。

## 常见误区

**误区一：变异测试要替代单元测试**——它是评估测试质量的工具，不是测试本身。

**误区二：追求 100% 变异分数**——等价变异体无法杀死，85%+ 已是很好水平。

**误区三：变异测试太慢所以不用**——增量模式 + CI 夜间构建可以解决。

## 工程建议

1. **先跑覆盖率，再跑变异测试**——覆盖率不达标时变异测试没意义
2. **从核心模块开始**——先对支付、权限等关键模块做变异测试
3. **增量模式日常用，全量模式周/月跑**
4. **存活变异体是测试改进的 TODO 列表**
5. **团队定期 Review 变异测试报告**

## 小结

- 变异测试通过修改源代码来验证测试的断言质量
- 变异分数 = 被杀死变异体 / 总变异体，85% 以上说明测试质量较高
- Stryker Mutator 支持增量模式和多种 reporter
- 存活变异体直接指向测试盲区，是改进测试的最佳指引

### 练习二

```typescript
describe('hasItems', () => {
  it('购物车为空时返回 false', () => {
    expect(hasItems({ items: [] })).toBe(false)
  })
  it('购物车有商品时返回 true', () => {
    expect(hasItems({ items: ['apple'] })).toBe(true)
  })
})
```

`items = []` 时 `length = 0`：原始代码 `0 > 0` → false，变异体 `0 >= 0` → true。测试期望 false，变异体返回 true → 被杀死。关键在于测试了 `count === 0` 这个边界值。
