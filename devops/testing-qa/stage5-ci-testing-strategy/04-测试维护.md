# 测试维护

## 场景引入

你的 CI 最近经常"随机失败"——同样的代码，跑一次过、跑一次不过。团队开始习惯性地点"Re-run jobs"，而不是去修测试。三个月后，CI 里有 20 个 flaky test，没有人信任 CI 结果，质量门禁形同虚设。

## 学习目标

1. 理解 Flaky Test 的成因和分类
2. 掌握隔离和修复 Flaky Test 的方法
3. 学会分类和治理测试债务
4. 建立测试维护的流程和工具

## Flaky Test 的成因

### 时序问题

最常见也最难定位的成因。

```typescript
// 错误：依赖固定的等待时间
test('should show notification', async () => {
  await page.click('.save-button')
  await page.waitForTimeout(1000)
  const notification = await page.textContent('.notification')
  expect(notification).toBe('Saved successfully')
})

// 正确：等待具体条件
test('should show notification', async () => {
  await page.click('.save-button')
  await page.waitForSelector('.notification', { state: 'visible' })
  const notification = await page.textContent('.notification')
  expect(notification).toBe('Saved successfully')
})
```

### 环境差异

```typescript
// 错误：依赖路径分隔符
expect(resolvePath('src', 'utils')).toBe('src/utils')  // Windows 上是 src\utils

// 正确：使用 path 模块
expect(resolvePath('src', 'utils')).toBe(path.join('src', 'utils'))
```

### 状态泄漏

```typescript
// 错误：共享全局状态
let counter = 0
test('A', () => { counter++; expect(counter).toBe(1) })
test('B', () => { counter++; expect(counter).toBe(1) })  // A 先运行时失败

// 正确：每个测试独立初始化
test('A', () => { const c = createCounter(); c.increment(); expect(c.getCount()).toBe(1) })
```

### 外部依赖和资源竞争

```typescript
// 错误：直接调用外部 API
const user = await fetch('https://api.example.com/users/1').then(r => r.json())

// 正确：mock 外部依赖
server.use(http.get('https://api.example.com/users/1', () => HttpResponse.json({ id: 1 })))

// 错误：固定端口（并行时冲突）
const server = await startServer(3000)

// 正确：随机端口
const server = await startServer(0)
```

## 隔离 Flaky Test 的方法

```typescript
// 标记为 skip，保留排查线索
test.skip('flaky: timeout in CI', async () => {
  // TODO: 等待 #1234 修复后重新启用
})

// 有依赖的测试串行执行
test.describe.serial('User workflow', () => {
  test('create account', async ({ page }) => { /* ... */ })
  test('login', async ({ page }) => { /* ... */ })
})
```

## 测试债务的分类和治理

| 类型 | 表现 | 严重程度 |
|------|------|---------|
| Flaky Test | 时而通过时而失败 | 高 |
| 慢测试 | 单个测试超过 10 秒 | 中 |
| 无断言测试 | 没有 expect/assert | 高 |
| 过度耦合测试 | 修改实现就必须改测试 | 中 |
| 死测试 | 测试的代码已删除 | 低 |

### 检测无断言测试

```typescript
// scripts/test-health-check.ts
import { readFileSync, readdirSync, statSync } from 'node:fs'
import { join } from 'node:path'

function findTestFiles(dir: string): string[] {
  const files: string[] = []
  for (const entry of readdirSync(dir)) {
    const path = join(dir, entry)
    if (statSync(path).isDirectory()) files.push(...findTestFiles(path))
    else if (/\.(test|spec)\.ts$/.test(entry)) files.push(path)
  }
  return files
}

const assertionPattern = /expect\s*\(|assert\.|\.toBe\(|\.toEqual\(/
let issues = 0

for (const file of findTestFiles('src')) {
  const content = readFileSync(file, 'utf-8')
  if (/waitForTimeout/.test(content)) {
    console.log(`⚠️  ${file}: contains waitForTimeout`)
    issues++
  }
  const itBlocks = content.match(/it\s*\([^,]+,\s*(?:async\s*)?\(\)\s*=>\s*\{[\s\S]*?\n\s*\}/g) || []
  for (const block of itBlocks) {
    if (!assertionPattern.test(block)) {
      console.log(`⚠️  ${file}: no assertion in test`)
      issues++
    }
  }
}

if (issues > 0) { console.log(`\nFound ${issues} issues`); process.exit(1) }
else console.log('✅ All tests look healthy')
```

## 测试重试策略

重试是权宜之计，必须配合追踪机制。

```typescript
// vitest.config.ts
export default defineConfig({ test: { retry: 2 } })

// playwright.config.ts
export default defineConfig({
  retries: process.env.CI ? 2 : 0,
  reporter: [['html', { open: 'never' }], ['json', { outputFile: 'results.json' }]],
})
```

分析哪些测试走了重试路径：

```typescript
// scripts/analyze-retries.ts
import { readFileSync } from 'node:fs'

const results = JSON.parse(readFileSync('results.json', 'utf-8'))

function findRetriedTests(suite: any, path: string[] = []): string[] {
  const retried: string[] = []
  const currentPath = [...path, suite.title]
  for (const test of suite.tests || []) {
    if (test.results.length > 1) retried.push([...currentPath, test.title].join(' > '))
  }
  for (const child of suite.suites || []) retried.push(...findRetriedTests(child, currentPath))
  return retried
}

const retried = findRetriedTests(results)
if (retried.length > 0) {
  console.log(`⚠️  ${retried.length} tests required retries:`)
  retried.forEach(t => console.log(`  - ${t}`))
  process.exit(1)
}
```

## 监控 Flaky Test

### 建立追踪表

```markdown
<!-- docs/flaky-tests.md -->
| 测试 | 失败频率 | 成因 | Issue | 状态 |
|------|---------|------|-------|------|
| dashboard loading | ~10% | API 超时 | #1234 | 修复中 |
| file upload | ~5% | 端口冲突 | #1235 | 待修复 |
```

### Playwright 快速验证

```bash
# 只运行上次失败的测试
npx playwright test --last-failed

# 快速验证 flaky test 是否修复
npx playwright test tests/flaky-test.spec.ts --repeat-each=10
```

## 常见误区

1. **用 `retry` 代替修复**：重试 3 次才通过就是 flaky test，应该修复
2. **删除 flaky test 而非修复**：应该隔离并修复，保留排查线索
3. **忽略偶尔失败的测试**：这是测试债务的起点
4. **在测试中使用 `setTimeout`**：几乎必然导致 flaky test
5. **测试之间有顺序依赖**：并行执行时顺序不确定

## 工程建议

1. **每周运行测试健康检查**：找出慢测试、无断言测试
2. **建立 flaky test 追踪机制**
3. **新测试通过 `--repeat-each=5` 验证稳定性**
4. **CI 配置 flaky test 检测**
5. **定期清理测试债务**

## 小结

- Flaky Test 主要成因：时序、环境差异、状态泄漏、外部依赖、资源竞争
- 隔离比删除更好——保留排查线索
- 测试债务分类治理：flaky > 慢 > 无断言 > 死测试
- 重试是权宜之计，必须配合追踪机制

## 参考答案

### 练习一

**答案**：`Promise.all` 不保证执行顺序，`results.push` 的顺序取决于完成时间。

```typescript
// 方案 1：不依赖顺序
test('should process all items', async () => {
  const results = await Promise.all([processItem(1), processItem(2), processItem(3)])
  expect(results).toEqual(expect.arrayContaining([1, 2, 3]))
  expect(results).toHaveLength(3)
})

// 方案 2：串行执行保证顺序
test('should process items in order', async () => {
  const results: number[] = []
  for (const id of [1, 2, 3]) results.push(await processItem(id))
  expect(results).toEqual([1, 2, 3])
})
```

### 练习二

### 练习三

**答案**：

```yaml
- name: Detect flaky tests
  uses: actions/github-script@v7
  with:
    script: |
      const results = JSON.parse(require('fs').readFileSync('results.json', 'utf8'))
      function findFlaky(suite, path = []) {
        const flaky = [], cp = [...path, suite.title]
        for (const t of suite.tests || []) {
          if (t.results.length > 1 && t.results[t.results.length - 1].status === 'passed') {
            flaky.push({ name: [...cp, t.title].join(' > '), retries: t.results.length - 1 })
          }
        }
        for (const c of suite.suites || []) flaky.push(...findFlaky(c, cp))
        return flaky
      }
      const flaky = findFlaky(results)
      if (flaky.length) {
        const body = ['## ⚠️ Flaky Tests', '| Test | Retries |', '|------|---------|',
          ...flaky.map(t => `| ${t.name} | ${t.retries} |`)].join('\n')
        await github.rest.issues.createComment({
          ...context.repo, issue_number: context.issue.number, body
        })
      }
```
