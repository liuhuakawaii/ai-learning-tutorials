# AI 辅助测试

## 场景引入

你写了一个复杂的排序函数，需要测试各种边界情况：空数组、单元素、重复值、负数、超大数组……手写这些测试用例既枯燥又容易遗漏。如果 AI 能帮你生成测试用例、分析覆盖率缺口、甚至自动修复 flaky test，测试效率能提升多少？

## 学习目标

1. 掌握用 AI（Copilot/Cursor）生成测试用例的提示词技巧
2. 了解智能回归测试和覆盖率分析的 AI 应用
3. 学会用 AI 辅助修复 flaky test 和生成测试数据
4. 理解 AI 测试的局限性，建立正确的使用预期

## 智能回归测试

不是每次代码变更都跑全部测试，而是分析变更内容，预测哪些测试最可能发现 bug。

```typescript
// scripts/smart-regression.ts
import { execSync } from 'node:child_process'

function getChangedFiles(): string[] {
  return execSync('git diff --name-only HEAD~1', { encoding: 'utf-8' })
    .trim().split('\n').filter(Boolean)
}

function findAffectedTests(changedFiles: string[]): Map<string, number> {
  const scores = new Map<string, number>()
  for (const changed of changedFiles) {
    const grepResult = execSync(
      `grep -rl "from.*${changed.replace(/\//g, '.')}" src/ --include="*.test.ts"`,
      { encoding: 'utf-8' }
    ).trim().split('\n').filter(Boolean)
    for (const testFile of grepResult) {
      scores.set(testFile, (scores.get(testFile) || 0) + 10)
    }
  }
  return scores
}

const changed = getChangedFiles()
const affected = findAffectedTests(changed)
console.log(`Changed ${changed.length} files, affecting ${affected.size} test files`)
```

## AI 分析覆盖率报告

```typescript
// scripts/coverage-analysis.ts
import { readFileSync } from 'node:fs'

const summary = JSON.parse(readFileSync('coverage/coverage-summary.json', 'utf-8'))
const files = Object.entries(summary)
  .filter(([path]) => path !== 'total')
  .map(([path, data]: [string, any]) => ({ path, lines: data.lines.pct, branches: data.branches.pct }))
  .sort((a, b) => a.lines - b.lines)
  .slice(0, 10)

console.log('| 文件 | 行覆盖率 | 分支覆盖率 |')
console.log('|------|---------|-----------|')
for (const f of files) console.log(`| ${f.path} | ${f.lines}% | ${f.branches}% |`)

console.log('\n## AI 提示词\n')
console.log('请为以下文件生成单元测试，目标覆盖率 90%：')
for (const f of files.slice(0, 5)) console.log(`- ${f.path} (当前: ${f.lines}%)`)
```

## AI 修复 Flaky Test

```typescript
// scripts/flaky-analyzer.ts
import { readFileSync, existsSync } from 'node:fs'

const patterns = [
  { pattern: /Timeout.*exceeded/i, cause: '测试超时', fix: '使用 waitForSelector 替代 waitForTimeout' },
  { pattern: /Element.*not found/i, cause: '元素未找到', fix: '等待元素出现后再操作' },
  { pattern: /ECONNREFUSED/i, cause: '网络连接失败', fix: 'mock 外部 API 或使用 MSW' },
  { pattern: /address already in use/i, cause: '端口冲突', fix: '使用随机端口（port 0）' },
]

function analyzeFlakyTest(logFile: string) {
  if (!existsSync(logFile)) return null
  const log = readFileSync(logFile, 'utf-8')
  for (const { pattern, cause, fix } of patterns) {
    if (pattern.test(log)) return { cause, fix }
  }
  return null
}

const analysis = analyzeFlakyTest('test-failure.log')
if (analysis) {
  console.log(`可能原因: ${analysis.cause}`)
  console.log(`建议修复: ${analysis.fix}`)
}
```

## AI 测试的局限性

1. **业务逻辑的正确性**：AI 不知道你的业务规则

```typescript
// AI 生成的测试——看起来合理，但业务逻辑是错的
test('should calculate discount', () => {
  expect(calculateDiscount(100, 20)).toBe(80)
  // 实际业务：满 100 减 20，不满 100 不减
  // calculateDiscount(80, 20) 应该返回 80，不是 60
})
```

2. **测试策略的合理性**：AI 可以生成大量测试，但不能判断哪些场景最值得测试
3. **非功能性测试**：性能、安全、可用性测试需要人类的专业判断

### 正确的使用方式

```
1. 人类：定义测试策略（测什么、不测什么）
2. AI：生成测试用例（草稿）
3. 人类：审查和调整测试（确保业务逻辑正确）
4. AI：分析覆盖率缺口（补充遗漏的测试）
5. 人类：维护测试（修复 flaky test、清理无用测试）
```

## 常见误区

1. **盲目信任 AI 生成的测试**：AI 不理解业务逻辑，断言可能是错的
2. **用 AI 替代测试策略思考**：先想清楚测什么，再让 AI 帮你写
3. **认为 AI 能发现所有 bug**：AI 基于模式匹配，创造性 bug 它很难发现
4. **忽略 AI 生成测试的维护成本**
5. **测试数据包含敏感信息**

## 工程建议

1. **AI 生成，人类审查**：把 AI 当作初级测试工程师
2. **先写测试描述，再让 AI 实现**
3. **用 AI 补充边界情况，而非定义核心逻辑**
4. **定期审查 AI 生成的测试**
5. **建立团队的 AI 测试规范**

## 小结

- AI 擅长生成测试 boilerplate、边界情况、测试数据
- 提示词技巧：先写描述/类型/JSDoc，再让 AI 填充实现
- 智能回归测试基于变更分析优先运行高价值测试
- AI 的局限：不理解业务逻辑、不能替代测试策略
- 正确的工作流：AI 辅助 + 人类判断

## 参考答案

### 练习一

**答案**：先定义测试意图（正常合并、嵌套合并、数组处理），再生成实现。

```typescript
describe('mergeObjects', () => {
  it('should merge two objects', () => {
    expect(mergeObjects({ a: 1, b: 2 }, { b: 3, c: 4 })).toEqual({ a: 1, b: 3, c: 4 })
  })
  it('should deep merge nested objects', () => {
    expect(mergeObjects({ config: { theme: 'dark' } }, { config: { lang: 'en' } }))
      .toEqual({ config: { theme: 'dark', lang: 'en' } })
  })
  it('should let later sources override', () => {
    expect(mergeObjects({}, { a: 1 }, { a: 2 })).toEqual({ a: 2 })
  })
  it('should handle empty sources', () => {
    expect(mergeObjects({ a: 1 })).toEqual({ a: 1 })
  })
  it('should not mutate target', () => {
    const t = { a: 1 }; mergeObjects(t, { b: 2 }); expect(t).toEqual({ a: 1 })
  })
})
```
