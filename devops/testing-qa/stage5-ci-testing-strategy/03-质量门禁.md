# 质量门禁

## 场景引入

团队规定"PR 必须有人 review 才能合并"，但 reviewer 往往只看代码逻辑，忽略了覆盖率、风格、类型安全。某天一个 PR 通过了 review，却引入了一个没有测试覆盖的 edge case，两周后在线上爆发了 bug。如果配置了质量门禁——测试不通过就不能合并——这种情况根本不会发生。

## 学习目标

1. 理解质量门禁（Gate）的概念和价值
2. 掌握 GitHub 分支保护规则的配置
3. 学会配置 PR 检查：Lint、测试、覆盖率阈值
4. 实现自动代码审查和测试报告评论

## 什么是质量门禁

质量门禁是代码合并前必须通过的一系列自动化检查：

```
开发者 push → CI 运行检查 → 全部通过 → 允许合并
                          → 有失败   → 阻止合并
```

| 门禁类型 | 检查内容 | 严格程度 |
|---------|---------|---------|
| Lint 检查 | 代码风格、潜在错误 | 必须通过 |
| 单元测试 | 函数级别的正确性 | 必须通过 |
| 覆盖率阈值 | 测试覆盖的广度 | 建议通过 |
| 安全扫描 | 依赖漏洞、敏感信息泄露 | 必须通过 |

## PR 检查配置

```yaml
# .github/workflows/pr-check.yml
name: PR Quality Check

on:
  pull_request:
    branches: [main, develop]
    types: [opened, synchronize, reopened]

jobs:
  lint:
    name: Lint & Format
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npm run lint
      - run: npm run format:check

  test:
    name: Unit Tests
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - name: Run tests with coverage
        run: npx vitest run --coverage
      - name: Check coverage threshold
        run: |
          COVERAGE=$(cat coverage/coverage-summary.json | jq '.total.lines.pct')
          echo "Line coverage: ${COVERAGE}%"
          if (( $(echo "$COVERAGE < 80" | bc -l) )); then
            echo "Coverage ${COVERAGE}% is below 80% threshold"
            exit 1
          fi
```

## 分支保护规则

### 通过 GitHub UI 配置

进入仓库 → Settings → Branches → Add branch protection rule：

- **Branch name pattern**: `main`
- **Require a pull request before merging**: ✅ → Require approvals: 1
- **Require status checks to pass before merging**: ✅ → 选择 `Lint & Format`, `Unit Tests`
- **Require branches to be up to date before merging**: ✅
- **Do not allow bypassing the above settings**: ✅

### 通过 GitHub API 配置

```bash
curl -X PUT \
  -H "Authorization: token $GITHUB_TOKEN" \
  -H "Accept: application/vnd.github.v3+json" \
  "https://api.github.com/repos/OWNER/REPO/branches/main/protection" \
  -d '{
    "required_status_checks": {
      "strict": true,
      "contexts": ["Lint & Format", "Unit Tests"]
    },
    "enforce_admins": true,
    "required_pull_request_reviews": {
      "required_approving_review_count": 1,
      "dismiss_stale_reviews": true
    },
    "restrictions": null
  }'
```

## 覆盖率阈值作为门禁

```typescript
// vitest.config.ts
import { defineConfig } from 'vitest/config'

export default defineConfig({
  test: {
    coverage: {
      provider: 'v8',
      reporter: ['text', 'json-summary', 'html'],
      thresholds: {
        lines: 80,
        branches: 75,
        functions: 80,
        statements: 80,
        'src/utils/**': {
          lines: 95,
          branches: 90,
        },
      },
    },
  },
})
```

## 测试报告自动评论到 PR

```yaml
- name: Comment test results on PR
  if: always()
  uses: actions/github-script@v7
  with:
    script: |
      const fs = require('fs')
      const results = JSON.parse(fs.readFileSync('test-results.json', 'utf8'))
      const coverage = JSON.parse(fs.readFileSync('coverage/coverage-summary.json', 'utf8'))

      const body = [
        '## Test Report',
        '',
        `| Metric | Value |`,
        `|--------|-------|`,
        `| Passed | ${results.numPassedTests} ✅ |`,
        `| Failed | ${results.numFailedTests} ❌ |`,
        `| Coverage | ${coverage.total.lines.pct}% |`,
      ].join('\n')

      const { data: comments } = await github.rest.issues.listComments({
        ...context.repo, issue_number: context.issue.number,
      })
      const existing = comments.find(c => c.body.includes('## Test Report'))

      if (existing) {
        await github.rest.issues.updateComment({ ...context.repo, comment_id: existing.id, body })
      } else {
        await github.rest.issues.createComment({ ...context.repo, issue_number: context.issue.number, body })
      }
```

## 完整质量门禁 Workflow

用汇总 job 简化 branch protection 配置：

```yaml
# .github/workflows/quality-gate.yml
name: Quality Gate

on:
  pull_request:
    branches: [main]

jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npm run lint

  type-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npx tsc --noEmit

  unit-test:
    needs: [lint]
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npx vitest run --coverage

  e2e:
    needs: [unit-test]
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npx playwright install --with-deps chromium
      - run: npx playwright test

  all-checks:
    needs: [lint, type-check, unit-test, e2e]
    runs-on: ubuntu-latest
    if: always()
    steps:
      - name: Check all jobs
        run: |
          if [ "${{ needs.lint.result }}" != "success" ] || \
             [ "${{ needs.type-check.result }}" != "success" ] || \
             [ "${{ needs.unit-test.result }}" != "success" ] || \
             [ "${{ needs.e2e.result }}" != "success" ]; then
            echo "Some checks failed"
            exit 1
          fi
          echo "All checks passed"
```

`all-checks` job 汇总所有检查结果，只需在 branch protection 中配置 `all-checks` 一个必需检查。

## 常见误区

1. **门禁太多太严**：每个 PR 都要跑 30 分钟 E2E，开发者等不及
2. **覆盖率阈值设太高**：100% 覆盖率不等于没有 bug，80% 是合理起点
3. **管理员绕过门禁**：`enforce_admins: false` 会让门禁形同虚设
4. **不更新分支保护的状态检查名称**：改了 job 名称后忘记更新
5. **所有检查都失败时没有明确错误信息**

## 工程建议

1. **用汇总 job 作为唯一的必需检查**
2. **PR 检查要快**：lint + 单元测试 < 5 分钟
3. **覆盖率阈值从低到高**：先设 60%，逐步提高到 80%
4. **门禁失败要有明确反馈**
5. **定期审查门禁规则**

## 小结

- 质量门禁是代码合并前的自动化检查，保护代码库质量
- 分支保护规则是实现门禁的核心机制
- 覆盖率阈值可以作为 Vitest 的内置门禁
- 用汇总 job 简化 branch protection 的维护

## 练习

### 练习一：配置分支保护

为一个 Next.js 项目配置 GitHub 分支保护规则，要求 PR 必须至少 1 人 review，Lint 和测试检查必须通过，管理员不能绕过规则。

### 练习二：覆盖率门禁

配置 Vitest 覆盖率阈值：全局行覆盖率 >= 80%，`src/utils/` 目录行覆盖率 >= 95%。覆盖率不达标时 CI 自动失败。

### 练习三：PR 自动评论

编写一个 GitHub Actions step，将测试结果（通过数、失败数、覆盖率）自动评论到 PR 上。如果已有评论则更新而非新建。
