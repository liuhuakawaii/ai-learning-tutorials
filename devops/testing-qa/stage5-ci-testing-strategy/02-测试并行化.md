# 测试并行化

## 场景引入

你的项目有 500 个单元测试和 80 个 E2E 测试。单线程跑完全部测试需要 12 分钟。如果能把测试并行化，12 分钟可以压缩到 3 分钟——开发效率提升 4 倍。

## 学习目标

1. 理解测试并行化的核心原理和收益
2. 掌握 Vitest 的线程池配置（pool 选项）
3. 掌握 Playwright 的并行执行和分片策略
4. 学会用 GitHub Actions matrix 实现跨机器并行

## 为什么要并行化

| 策略 | 耗时 | 加速比 |
|------|------|--------|
| 串行执行 | 10 分钟 | 1x |
| 4 线程并行 | ~3 分钟 | 3.3x |
| 4 台机器 × 2 线程 | ~1.5 分钟 | 6.7x |

## Vitest 的线程池

### pool 选项

```typescript
// vitest.config.ts
import { defineConfig } from 'vitest/config'

export default defineConfig({
  test: {
    pool: 'threads',  // 默认值：使用 worker_threads
    poolOptions: {
      threads: {
        minThreads: 1,
        maxThreads: 4,
        singleThread: false,
      },
    },
  },
})
```

**threads（默认）**：使用 `worker_threads`，启动快、内存共享。

**forks**：使用 `child_process.fork()`，内存隔离更好，但启动更慢。

**vmThreads**：使用 `worker_threads` + `vm` 模块，隔离性介于两者之间。

### 线程数的选择

经验法则：**线程数 = CPU 核心数 - 1**。

```typescript
import { cpus } from 'node:os'

const maxThreads = Math.max(1, cpus().length - 1)

export default defineConfig({
  test: {
    pool: 'threads',
    poolOptions: { threads: { maxThreads } },
  },
})
```

## Playwright 并行执行

### fullyParallel 配置

```typescript
// playwright.config.ts
import { defineConfig } from '@playwright/test'

export default defineConfig({
  fullyParallel: true,
  workers: process.env.CI ? 2 : undefined,
  timeout: 30_000,
})
```

### 测试隔离

```typescript
import { test as base } from '@playwright/test'

const test = base.extend<{ db: Database }>({
  db: async ({}, use) => {
    const schema = `test_${Date.now()}_${Math.random().toString(36).slice(2)}`
    await db.query(`CREATE SCHEMA ${schema}`)
    await use(new Database(schema))
    await db.query(`DROP SCHEMA ${schema} CASCADE`)
  },
})
```

### Sharding（分片）

```bash
npx playwright test --shard=1/3
npx playwright test --shard=2/3
npx playwright test --shard=3/3
```

分片基于测试文件的哈希值分配，每个分片生成独立报告，可以用 `playwright merge-reports` 合并。

## GitHub Actions 矩阵策略

```yaml
jobs:
  e2e:
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        shard: [1, 2, 3, 4]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npx playwright install --with-deps chromium
      - run: npx playwright test --shard=${{ matrix.shard }}/4
      - if: always()
        uses: actions/upload-artifact@v4
        with:
          name: blob-report-${{ matrix.shard }}
          path: blob-report/

  merge-reports:
    needs: [e2e]
    if: always()
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: npm ci
      - uses: actions/download-artifact@v4
        with:
          pattern: blob-report-*
          path: all-blob-reports
          merge-multiple: true
      - run: npx playwright merge-reports --reporter=html ./all-blob-reports
      - uses: actions/upload-artifact@v4
        with:
          name: playwright-report
          path: playwright-report/
```

### 分片数量的选择

| 测试总时间 | 推荐分片数 |
|-----------|-----------|
| < 3 分钟 | 1（不分片）|
| 3-10 分钟 | 2-3 |
| 10-30 分钟 | 4-6 |

## 依赖优化：只运行受影响的测试

```bash
# 只运行上次 commit 以来有变化的测试文件
npx vitest --changed

# 相对于某个分支的变化
npx vitest --changed=main
```

### CI 集成

```yaml
- name: Run affected tests only
  if: github.event_name == 'pull_request'
  run: npx vitest --changed=${{ github.event.pull_request.base.sha }}

- name: Run all tests
  if: github.event_name == 'push' && github.ref == 'refs/heads/main'
  run: npx vitest run
```

## 内存优化

```typescript
// vitest.config.ts
export default defineConfig({
  test: {
    pool: 'threads',
    poolOptions: {
      threads: {
        maxThreads: process.env.CI ? 2 : 4,
        memoryLimit: '512MB',
      },
    },
  },
})
```

## 常见误区

1. **盲目追求最大并行度**：线程数超过 CPU 核心数会导致上下文切换开销
2. **忽略测试隔离**：并行执行时共享数据库状态会导致测试间互相干扰
3. **分片数过多**：每个分片的启动开销会抵消并行收益
4. **忘记 `fail-fast: false`**：一个 shard 失败就取消其他 shard
5. **本地和 CI 用相同的并行度**：本地 16 核和 CI 2 核应该用不同配置

## 工程建议

1. **先测量，再优化**：用 `--reporter=verbose` 看每个测试文件的耗时
2. **按耗时均匀分片**
3. **PR 只跑受影响测试，main 跑全部**
4. **内存不够时降级到 forks**
5. **定期检查分片效果**

## 小结

- Vitest 通过 `pool: 'threads'|'forks'|'vmThreads'` 控制并行模式
- Playwright 通过 `fullyParallel` + `workers` + `shard` 实现多层并行
- GitHub Actions matrix strategy 是跨机器并行的基础
- 只运行受影响的测试能大幅减少 CI 时间

一个项目有 200 个测试文件，单线程跑完需要 8 分钟。请配置 Vitest 的并行策略，目标是将时间压缩到 3 分钟以内。需要考虑 CI 环境（2 核 CPU）。

一个 E2E 测试套件有 120 个测试，单机跑完需要 20 分钟。请设计 GitHub Actions 的分片策略，目标是 5 分钟内跑完。要求包含报告合并步骤。

## 参考答案

### 练习一

**答案**：CI 环境 2 核，线程数设为 2。200 个文件 / 2 线程 = 每线程 100 个文件，理论时间 4 分钟。要进一步压缩需要分片。

```typescript
// vitest.config.ts
import { defineConfig } from 'vitest/config'
import { cpus } from 'node:os'

export default defineConfig({
  test: {
    pool: 'threads',
    poolOptions: {
      threads: { maxThreads: process.env.CI ? 2 : cpus().length - 1 },
    },
  },
})
```

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        shard: [1, 2]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npx vitest run --shard=${{ matrix.shard }}/2
```

### 练习二

**答案**：20 分钟 / 5 分钟 = 4 片。每片启动开销约 2 分钟，实际执行约 5 分钟。

```yaml
jobs:
  e2e:
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        shard: [1, 2, 3, 4]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npx playwright install --with-deps chromium
      - run: npx playwright test --shard=${{ matrix.shard }}/4
      - if: always()
        uses: actions/upload-artifact@v4
        with:
          name: blob-${{ matrix.shard }}
          path: blob-report/

  report:
    needs: [e2e]
    if: always()
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: npm ci
      - uses: actions/download-artifact@v4
        with:
          pattern: blob-*
          path: blobs
          merge-multiple: true
      - run: npx playwright merge-reports --reporter=html ./blobs
      - uses: actions/upload-artifact@v4
        with:
          name: playwright-report
          path: playwright-report/
```
