# 阶段实战：完整 CI 测试流水线

## 场景引入

经过前面 5 节课的学习，你已掌握 GitHub Actions、并行化、质量门禁、测试维护和 AI 辅助测试。现在需要将这些知识整合为一套**生产级的 CI 测试流水线**：从代码提交到部署上线，每一步都有自动化的质量保障。

## 学习目标

1. 设计分层的 CI 流水线架构
2. 编写完整的 GitHub Actions workflow
3. 配置分支保护规则和 PR 模板

## CI 流水线架构

```
代码提交
  ↓
[阶段1] 代码质量检查（并行）
  ├── ESLint + Prettier
  └── TypeScript 类型检查
  ↓
[阶段2] 单元测试 + 覆盖率
  ↓
[阶段3] 集成测试（带数据库）
  ↓
[阶段4] E2E 测试（分片并行）
  ├── Shard 1/4 ~ 4/4
  ↓
[阶段5] 质量门禁汇总 → PR 评论
  ↓
[阶段6] 部署（仅 main 分支）
```

## 完整 GitHub Actions Workflow

```yaml
# .github/workflows/ci.yml
name: CI Pipeline

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

env:
  NODE_VERSION: 20

jobs:
  # ========== 阶段 1：代码质量 ==========
  lint:
    name: 代码风格
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npx eslint . --max-warnings 0
      - run: npx prettier --check .

  typecheck:
    name: 类型检查
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npx tsc --noEmit

  # ========== 阶段 2：单元测试 ==========
  unit-test:
    name: 单元测试
    runs-on: ubuntu-latest
    needs: [lint, typecheck]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npx vitest run --coverage
      - name: 检查覆盖率
        run: |
          COV=$(node -e "console.log(require('./coverage/coverage-summary.json').total.lines.pct)")
          echo "行覆盖率: ${COV}%"
          (( $(echo "$COV >= 80" | bc -l) )) || { echo "::error::覆盖率不足"; exit 1; }
      - if: always()
        uses: actions/upload-artifact@v4
        with: { name: coverage, path: coverage/ }

  # ========== 阶段 3：集成测试 ==========
  integration-test:
    name: 集成测试
    runs-on: ubuntu-latest
    needs: [unit-test]
    services:
      postgres:
        image: postgres:16
        env:
          POSTGRES_USER: test
          POSTGRES_PASSWORD: test
          POSTGRES_DB: testdb
        ports: ['5432:5432']
        options: --health-cmd pg_isready --health-interval 10s --health-timeout 5s --health-retries 5
    env:
      DATABASE_URL: postgres://test:test@localhost:5432/testdb
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npx prisma migrate deploy
      - run: npx vitest run --config vitest.integration.config.ts
      - if: always()
        uses: actions/upload-artifact@v4
        with: { name: integration-report, path: test-results/ }

  # ========== 阶段 4：E2E 测试 ==========
  e2e-test:
    name: E2E (Shard ${{ matrix.shard }})
    runs-on: ubuntu-latest
    needs: [integration-test]
    strategy:
      fail-fast: false
      matrix:
        shard: [1, 2, 3, 4]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - uses: actions/cache@v4
        id: pw
        with:
          path: ~/.cache/ms-playwright
          key: pw-${{ hashFiles('package-lock.json') }}
      - if: steps.pw.outputs.cache-hit != 'true'
        run: npx playwright install --with-deps chromium
      - run: npm run build
      - run: npx serve -s dist -l 3000 & npx wait-on http://localhost:3000 --timeout 30000
      - run: npx playwright test --shard=${{ matrix.shard }}/4 --retries=2
      - if: always()
        uses: actions/upload-artifact@v4
        with:
          name: e2e-report-${{ matrix.shard }}
          path: playwright-report/

  # ========== 阶段 5：质量门禁 ==========
  quality-gate:
    name: 质量门禁
    runs-on: ubuntu-latest
    needs: [unit-test, integration-test, e2e-test]
    if: always()
    permissions:
      pull-requests: write
    steps:
      - name: 检查结果
        run: |
          [ "${{ needs.unit-test.result }}" = "success" ] || { echo "❌ 单元测试失败"; exit 1; }
          [ "${{ needs.integration-test.result }}" = "success" ] || { echo "❌ 集成测试失败"; exit 1; }
          [ "${{ needs.e2e-test.result }}" = "success" ] || { echo "❌ E2E 失败"; exit 1; }
          echo "✅ 所有测试通过"
      - name: 评论到 PR
        if: github.event_name == 'pull_request'
        uses: actions/github-script@v7
        with:
          script: |
            const icon = '${{ needs.e2e-test.result }}' === 'success' ? '✅' : '❌'
            const body = `## ${icon} CI 测试报告\n\n`
              + `| 检查项 | 状态 |\n|--------|------|\n`
              + `| 代码风格 | ${{ needs.lint.result }} |\n`
              + `| 类型检查 | ${{ needs.typecheck.result }} |\n`
              + `| 单元测试 | ${{ needs.unit-test.result }} |\n`
              + `| 集成测试 | ${{ needs.integration-test.result }} |\n`
              + `| E2E 测试 | ${{ needs.e2e-test.result }} |\n`
            await github.rest.issues.createComment({
              owner: context.repo.owner, repo: context.repo.repo,
              issue_number: context.issue.number, body,
            })

  # ========== 阶段 6：部署 ==========
  deploy:
    name: 部署
    runs-on: ubuntu-latest
    needs: [quality-gate]
    if: github.ref == 'refs/heads/main' && needs.quality-gate.result == 'success'
    environment: production
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci && npm run build
      - run: echo "部署到生产环境..."
```

## 常见误区

1. **所有测试在一个 Job**：应分层执行，快速检查先跑
2. **忽略 concurrency**：同一 PR 多次 push 浪费资源
3. **PR 模板太复杂**：应简洁，关键项用 checkbox
4. **Job name 不稳定**：改名会导致分支保护失效

## 工程建议

1. **从简单开始**：先 lint + 单元测试，再逐步添加
2. **CI 配置要可读**：有意义的 Job name，添加注释
3. **监控 CI 性能**：追踪每个 Job 执行时间
4. **定期更新依赖**：GitHub Actions action 版本要定期更新

### 练习一

**思路**：按阶段组织 Job，E2E 使用矩阵分片，`fail-fast: false` 保证全部运行。

**答案**：

```yaml
name: CI
on:
  push: { branches: [main] }
  pull_request: { branches: [main] }
jobs:
  lint:
    name: Lint
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npx eslint . --max-warnings 0
  typecheck:
    name: TypeCheck
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npx tsc --noEmit
  unit-test:
    name: Unit Test
    runs-on: ubuntu-latest
    needs: [lint, typecheck]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npx vitest run --coverage
      - if: always()
        uses: actions/upload-artifact@v4
        with: { name: coverage, path: coverage/ }
  e2e-test:
    name: E2E (Shard ${{ matrix.shard }})
    runs-on: ubuntu-latest
    needs: [unit-test]
    strategy:
      fail-fast: false
      matrix: { shard: [1, 2] }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npx playwright install --with-deps chromium
      - run: npm run build
      - run: npx serve -s dist -l 3000 & npx wait-on http://localhost:3000
      - run: npx playwright test --shard=${{ matrix.shard }}/2
      - if: always()
        uses: actions/upload-artifact@v4
        with: { name: e2e-${{ matrix.shard }}, path: playwright-report/ }
```

**要点**：lint/typecheck 并行 → unit-test → E2E 分片；`fail-fast: false` 保证所有 shard 运行。
