# 阶段实战：完整 CI 测试流水线

## 目标

搭建一套生产级 CI 测试流水线：从代码提交到部署上线，每一步都有自动化的质量保障。

## 流水线架构

```
代码提交
  ↓
[阶段1] 代码质量检查（并行）
  ├── ESLint + Prettier
  └── TypeScript 类型检查
  ↓
[阶段2] 单元测试 + 覆盖率
  ↓
[阶段3] 集成测试（带数据库）
  ↓
[阶段4] E2E 测试（分片并行）
  ├── Shard 1/4 ~ 4/4
  ↓
[阶段5] 质量门禁汇总 → PR 评论
  ↓
[阶段6] 部署（仅 main 分支）
```

## 完整 GitHub Actions Workflow

```yaml
# .github/workflows/ci.yml
name: CI Pipeline

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

env:
  NODE_VERSION: 20

jobs:
  # ========== 阶段 1：代码质量 ==========
  lint:
    name: 代码风格
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npx eslint . --max-warnings 0
      - run: npx prettier --check .

  typecheck:
    name: 类型检查
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npx tsc --noEmit

  # ========== 阶段 2：单元测试 ==========
  unit-test:
    name: 单元测试
    runs-on: ubuntu-latest
    needs: [lint, typecheck]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npx vitest run --coverage
      - if: always()
        uses: actions/upload-artifact@v4
        with: { name: coverage, path: coverage/ }

  # ========== 阶段 3：集成测试 ==========
  integration-test:
    name: 集成测试
    runs-on: ubuntu-latest
    needs: [unit-test]
    services:
      postgres:
        image: postgres:16
        env:
          POSTGRES_USER: test
          POSTGRES_PASSWORD: test
          POSTGRES_DB: testdb
        ports: ['5432:5432']
        options: --health-cmd pg_isready --health-interval 10s
    env:
      DATABASE_URL: postgres://test:test@localhost:5432/testdb
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npx vitest run --config vitest.integration.config.ts

  # ========== 阶段 4：E2E 测试 ==========
  e2e-test:
    name: E2E (Shard ${{ matrix.shard }})
    runs-on: ubuntu-latest
    needs: [integration-test]
    strategy:
      fail-fast: false
      matrix:
        shard: [1, 2, 3, 4]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - uses: actions/cache@v4
        with:
          path: ~/.cache/ms-playwright
          key: pw-${{ hashFiles('package-lock.json') }}
      - run: npx playwright install --with-deps chromium
      - run: npm run build
      - run: npx serve -s dist -l 3000 & npx wait-on http://localhost:3000 --timeout 30000
      - run: npx playwright test --shard=${{ matrix.shard }}/4 --retries=2
      - if: always()
        uses: actions/upload-artifact@v4
        with:
          name: e2e-report-${{ matrix.shard }}
          path: playwright-report/

  # ========== 阶段 5：质量门禁 ==========
  quality-gate:
    name: 质量门禁
    runs-on: ubuntu-latest
    needs: [unit-test, integration-test, e2e-test]
    if: always()
    permissions:
      pull-requests: write
    steps:
      - name: 检查结果
        run: |
          [ "${{ needs.unit-test.result }}" = "success" ] || { echo "❌ 单元测试失败"; exit 1; }
          [ "${{ needs.integration-test.result }}" = "success" ] || { echo "❌ 集成测试失败"; exit 1; }
          [ "${{ needs.e2e-test.result }}" = "success" ] || { echo "❌ E2E 失败"; exit 1; }
          echo "✅ 所有测试通过"
      - name: 评论到 PR
        if: github.event_name == 'pull_request'
        uses: actions/github-script@v7
        with:
          script: |
            const icon = '${{ needs.e2e-test.result }}' === 'success' ? '✅' : '❌'
            const body = `## ${icon} CI 测试报告\n\n`
              + `| 检查项 | 状态 |\n|--------|------|\n`
              + `| 单元测试 | ${{ needs.unit-test.result }} |\n`
              + `| 集成测试 | ${{ needs.integration-test.result }} |\n`
              + `| E2E 测试 | ${{ needs.e2e-test.result }} |\n`
            await github.rest.issues.createComment({
              owner: context.repo.owner, repo: context.repo.repo,
              issue_number: context.issue.number, body,
            })

  # ========== 阶段 6：部署 ==========
  deploy:
    name: 部署
    runs-on: ubuntu-latest
    needs: [quality-gate]
    if: github.ref == 'refs/heads/main' && needs.quality-gate.result == 'success'
    steps:
      - uses: actions/checkout@v4
      - run: echo "部署到生产环境..."
```

## 关键设计决策

**`concurrency: cancel-in-progress: true`**：同一 PR 多次 push 只保留最新 CI 运行。

**`needs` 依赖链**：lint/typecheck 并行 → unit-test → integration-test → e2e-test → quality-gate → deploy。

**`fail-fast: false`**：E2E 分片中一个 shard 失败不影响其他 shard 运行。

**`if: always()`**：quality-gate 必须在所有依赖 job 完成后运行，无论成功失败。

**`if: always()` 上传报告**：测试失败时也有排查依据。

## 分支保护规则

```bash
gh api -X PUT repos/OWNER/REPO/branches/main/protection \
  -f '{"required_status_checks":{"strict":true,"contexts":["质量门禁"]},"enforce_admins":true}'
```

只需配置 quality-gate 一个必需检查，它会汇总所有测试结果。

## 练习

### 练习一：搭建 CI 流水线

为前端项目搭建 CI，包含：lint、类型检查、单元测试（覆盖率）、E2E（分 2 片）。写出完整 workflow YAML。

### 练习二：设计 PR 模板

设计 PR 模板，包含：变更描述、变更类型、测试情况、覆盖率、检查清单。确保简洁实用。
