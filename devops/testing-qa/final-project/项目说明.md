# 测试与质量保障 - 毕业项目

## 项目概述

为一个真实 Web 应用搭建完整的测试与质量保障体系，覆盖从单元测试到 CI 流水线的全链路。

## 项目目标

基于一个已有的 Todo 应用（包含前端 React + 后端 Express API + SQLite 数据库），为其搭建完整的测试体系：

1. **单元测试**：工具函数、业务逻辑
2. **集成测试**：API 接口、数据库交互
3. **组件测试**：React 组件的用户交互
4. **E2E 测试**：核心用户流程
5. **测试基础设施**：Mock、Fixture、覆盖率、CI 集成

## 阶段任务

### 阶段1：单元测试

- 为 `src/utils/` 下的工具函数编写单元测试
- 为 `src/services/` 下的业务逻辑编写单元测试
- 运行 `npm run test:unit`，覆盖率 ≥ 80%
- 使用 TDD 方式开发新的工具函数

### 阶段2：集成与 E2E

- 为 API 接口编写集成测试
- 为 React 组件编写测试
- 为核心用户流程编写 E2E 测试
- 运行 `npm run test:e2e`，所有测试通过

### 阶段3：Mock 与 Fixture

- 配置 MSW 拦截 API 请求
- 构建测试数据工厂
- 配置全局测试基础设施
- Mock 外部依赖（时间、随机数）

### 阶段4：覆盖率与变异测试

- 配置覆盖率报告，达到 ≥ 80% 覆盖率
- 运行变异测试，变异分数 ≥ 70%
- 添加属性测试覆盖边界情况
- 配置性能基准测试

### 阶段5：CI 测试策略

- 配置 GitHub Actions 流水线
- 测试并行化，CI 执行时间 < 5 分钟
- 配置质量门禁
- 测试报告自动生成

## 验证方式

运行验证脚本检查项目完成度：

```bash
node scripts/check.cjs
```

验证内容包括：
- 测试文件是否存在且命名规范
- 测试是否全部通过
- 覆盖率是否达标
- 配置文件是否完整
- 每个阶段的报告是否存在

## 交付物

1. 完整的测试代码（单元/集成/E2E）
2. 测试基础设施配置
3. CI 流水线配置
4. 5 份阶段报告
5. 验证脚本全部通过
