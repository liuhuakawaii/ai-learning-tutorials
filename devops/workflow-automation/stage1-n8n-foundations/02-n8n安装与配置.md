# 第二课：n8n 安装与配置

> **课程定位**：从零搭建 n8n 开发环境，理解部署架构和核心配置
> **前置知识**：了解 Docker 基本命令，有 PostgreSQL 基础
> **预计时长**：35 分钟

---

## 场景引入

你决定用 n8n 来构建自动化工作流。第一步是在本地跑起来。你不想用 n8n Cloud（数据在外部），也不想装一个桌面应用（不好团队协作）。你需要一个可以自己掌控的、能持久化数据的、方便后续迁移到生产的部署方案。

## 一、n8n 架构概览

### 1.1 核心组件

```
┌─────────────────────────────────────────────────┐
│                   n8n 实例                        │
│                                                  │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐       │
│  │  编辑器   │  │ 执行引擎  │  │  触发器   │       │
│  │ (Editor)  │  │ (Runner)  │  │ (Trigger) │       │
│  │          │  │          │  │          │       │
│  │ 可视化    │  │ 执行节点  │  │ 监听事件  │       │
│  │ 编排界面  │  │ 处理数据  │  │ 定时调度  │       │
│  └──────────┘  └──────────┘  └──────────┘       │
│         ↕              ↕              ↕          │
│  ┌──────────────────────────────────────┐       │
│  │           数据库 (SQLite/PG)          │       │
│  │  工作流定义、执行日志、凭证、凭证       │       │
│  └──────────────────────────────────────┘       │
└─────────────────────────────────────────────────┘
```

n8n 的核心组件：

- **编辑器**：Web 界面，用于创建和管理工作流
- **执行引擎**：运行工作流节点，处理数据流转
- **触发器**：监听外部事件（Webhook）或定时触发
- **数据库**：存储工作流定义、执行历史、凭证

### 1.2 部署方式对比

| 方式 | 适合场景 | 优点 | 缺点 |
|------|---------|------|------|
| n8n Cloud | 快速试用 | 零运维 | 数据在外部、有功能限制 |
| Docker | 开发和小团队 | 简单、可重复 | 需要 Docker 环境 |
| Docker Compose | 生产部署 | 完整控制、可扩展 | 需要运维能力 |
| Kubernetes | 大规模部署 | 高可用、自动扩缩 | 复杂度高 |

## 二、Docker 部署 n8n

### 2.1 最小化启动

最简单的启动方式，使用 SQLite 存储：

```bash
docker run -d \
  --name n8n \
  -p 5678:5678 \
  -v n8n_data:/home/node/.n8n \
  n8nio/n8n
```

启动后访问 `http://localhost:5678`，你会看到 n8n 的注册页面。

参数说明：

| 参数 | 作用 |
|------|------|
| `-d` | 后台运行 |
| `-p 5678:5678` | 映射端口 |
| `-v n8n_data:/home/node/.n8n` | 持久化数据（工作流、凭证、执行日志） |

### 2.2 Docker Compose 部署

推荐使用 Docker Compose，方便后续添加 PostgreSQL 和 Redis：

```yaml
# docker-compose.yml
version: '3.8'

services:
  n8n:
    image: n8nio/n8n
    restart: always
    ports:
      - "5678:5678"
    environment:
      - N8N_BASIC_AUTH_ACTIVE=true
      - N8N_BASIC_AUTH_USER=admin
      - N8N_BASIC_AUTH_PASSWORD=changeme
      - N8N_HOST=localhost
      - N8N_PORT=5678
      - N8N_PROTOCOL=http
      - WEBHOOK_URL=http://localhost:5678/
    volumes:
      - n8n_data:/home/node/.n8n

volumes:
  n8n_data:
```

启动：

```bash
docker compose up -d
```

### 2.3 带 PostgreSQL 的生产配置

SQLite 适合开发，但生产环境应该用 PostgreSQL：

```yaml
# docker-compose.prod.yml
version: '3.8'

services:
  n8n:
    image: n8nio/n8n
    restart: always
    ports:
      - "5678:5678"
    environment:
      - DB_TYPE=postgresdb
      - DB_POSTGRESDB_HOST=postgres
      - DB_POSTGRESDB_PORT=5432
      - DB_POSTGRESDB_DATABASE=n8n
      - DB_POSTGRESDB_USER=n8n
      - DB_POSTGRESDB_PASSWORD=${DB_PASSWORD}
      - N8N_BASIC_AUTH_ACTIVE=true
      - N8N_BASIC_AUTH_USER=${N8N_USER}
      - N8N_BASIC_AUTH_PASSWORD=${N8N_PASSWORD}
      - N8N_HOST=${N8N_HOST}
      - N8N_PORT=5678
      - N8N_PROTOCOL=https
      - WEBHOOK_URL=https://${N8N_HOST}/
      - N8N_ENCRYPTION_KEY=${ENCRYPTION_KEY}
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  postgres:
    image: postgres:15
    restart: always
    environment:
      - POSTGRES_DB=n8n
      - POSTGRES_USER=n8n
      - POSTGRES_PASSWORD=${DB_PASSWORD}
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  n8n_data:
  postgres_data:
```

配套的 `.env` 文件：

```bash
# .env
DB_PASSWORD=your-strong-password-here
N8N_USER=admin
N8N_PASSWORD=your-n8n-password
N8N_HOST=n8n.example.com
ENCRYPTION_KEY=your-32-char-encryption-key
```

## 三、核心环境变量

### 3.1 基础配置

| 变量 | 说明 | 示例 |
|------|------|------|
| `N8N_HOST` | 域名或 IP | `n8n.example.com` |
| `N8N_PORT` | 端口 | `5678` |
| `N8N_PROTOCOL` | 协议 | `http` 或 `https` |
| `WEBHOOK_URL` | Webhook 基础 URL | `https://n8n.example.com/` |
| `N8N_ENCRYPTION_KEY` | 凭证加密密钥 | 32 位随机字符串 |

### 3.2 认证配置

```bash
# 基础认证（最简单）
N8N_BASIC_AUTH_ACTIVE=true
N8N_BASIC_AUTH_USER=admin
N8N_BASIC_AUTH_PASSWORD=strong-password

# 或使用 JWT 认证（更安全）
N8N_AUTH_EXCLUDE_ENDPOINTS=/healthz
```

### 3.3 数据库配置

```bash
# SQLite（开发环境，无需额外配置）
# 数据存储在 /home/node/.n8n/database.sqlite

# PostgreSQL（生产环境）
DB_TYPE=postgresdb
DB_POSTGRESDB_HOST=postgres
DB_POSTGRESDB_PORT=5432
DB_POSTGRESDB_DATABASE=n8n
DB_POSTGRESDB_USER=n8n
DB_POSTGRESDB_PASSWORD=password
DB_POSTGRESDB_SCHEMA=public
DB_POSTGRESDB_SSL_CA=/path/to/ca-certificate.crt
DB_POSTGRESDB_SSL_REJECT_UNAUTHORIZED=true
```

### 3.4 执行配置

```bash
# 执行超时（秒）
EXECUTIONS_TIMEOUT=3600

# 最大并发执行数
EXECUTIONS_DATA_MAX_SIZE=128

# 执行数据保留策略
EXECUTIONS_DATA_SAVE_ON_ERROR=all
EXECUTIONS_DATA_SAVE_ON_SUCCESS=all
EXECUTIONS_DATA_SAVE_MANUAL_EXECUTIONS=true

# 清理旧执行记录
EXECUTIONS_DATA_PRUNE=true
EXECUTIONS_DATA_MAX_AGE=168
```

## 四、SQLite vs PostgreSQL

### 4.1 何时用 SQLite

```
开发环境
├─ 单人使用
├─ 工作流数量 < 50
├─ 执行量 < 1000/天
└─ 不需要高可用
```

SQLite 的优点是零配置，启动就能用。但它的并发性能有限，不适合生产环境。

### 4.2 何时用 PostgreSQL

```
生产环境
├─ 团队协作
├─ 工作流数量 > 50
├─ 执行量 > 1000/天
├─ 需要备份和恢复
└─ 需要高可用
```

PostgreSQL 支持并发读写、事务、备份恢复，是生产环境的标配。

### 4.3 迁移从 SQLite 到 PostgreSQL

n8n 提供了内置的迁移命令：

```bash
# 在 n8n 容器内执行
docker exec -it n8n n8n export:workflow --all --output=/tmp/workflows.json
docker exec -it n8n n8n export:credentials --all --output=/tmp/credentials.json

# 修改配置指向 PostgreSQL
# 重启 n8n

# 导入数据
docker exec -it n8n n8n import:workflow --input=/tmp/workflows.json
docker exec -it n8n n8n import:credentials --input=/tmp/credentials.json
```

## 常见误区

### 误区一："生产环境用 SQLite 就够了"

SQLite 在并发写入时会锁表，多个工作流同时执行时性能急剧下降。生产环境必须用 PostgreSQL。

### 误区二："不用配置 N8N_ENCRYPTION_KEY"

加密密钥用于加密存储的凭证（API Key、密码等）。如果不配置，n8n 会自动生成一个随机密钥。如果容器重建，这个密钥会丢失，所有凭证都无法解密。生产环境必须显式配置。

### 误区三："WEBHOOK_URL 不重要"

WEBHOOK_URL 决定了 Webhook 触发器生成的回调地址。如果配置错误，外部服务（如 GitHub、Stripe）的回调会发到错误的地址，导致工作流无法触发。

### 误区四："直接暴露 n8n 端口到公网"

n8n 的管理界面不应该直接暴露到公网。应该通过反向代理（Nginx/Caddy）加上 HTTPS 和额外的认证层。

---

## 工程建议

1. **开发环境用 SQLite，生产用 PostgreSQL**：SQLite 零配置上手快，但不适合并发场景。
2. **始终配置 N8N_ENCRYPTION_KEY**：用 `openssl rand -hex 32` 生成，保存到密码管理器。
3. **使用 .env 文件管理配置**：不要把密码写在 docker-compose.yml 里。
4. **配置数据备份**：PostgreSQL 定期备份，n8n 数据卷也要备份。
5. **使用反向代理**：生产环境通过 Nginx/Caddy 代理，加上 HTTPS 和基础认证。

---

## 小结

- n8n 由编辑器、执行引擎、触发器和数据库四部分组成
- 开发环境用 Docker + SQLite 快速启动，生产环境用 Docker Compose + PostgreSQL
- N8N_ENCRYPTION_KEY 和 WEBHOOK_URL 是最容易被忽略但最重要的配置
- SQLite 适合开发和测试，PostgreSQL 是生产环境的标配
- 始终通过 .env 文件管理敏感配置，不要硬编码

**答案**：

创建 `docker-compose.yml`：

```yaml
version: '3.8'
services:

    ports:

```

执行：

```bash

# 访问 http://localhost:5678，注册账号，创建工作流
docker compose down
docker compose up -d
# 再次访问，确认工作流仍在
```

**要点**：

- 不配置数据库环境变量时，默认使用 SQLite
- 注册的账号信息也存储在数据卷中

### 练习二

**思路**：添加 PostgreSQL 服务，修改 n8n 的数据库连接配置。

**答案**：

```yaml
version: '3.8'
services:
  n8n:
    image: n8nio/n8n
    restart: always
    ports:
      - "5678:5678"
    environment:
      - DB_TYPE=postgresdb
      - DB_POSTGRESDB_HOST=postgres
      - DB_POSTGRESDB_PORT=5432
      - DB_POSTGRESDB_DATABASE=n8n
      - DB_POSTGRESDB_USER=n8n
      - DB_POSTGRESDB_PASSWORD=n8n_password
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      - postgres

  postgres:
    image: postgres:15
    restart: always
    environment:
      - POSTGRES_DB=n8n
      - POSTGRES_USER=n8n
      - POSTGRES_PASSWORD=n8n_password
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  n8n_data:
  postgres_data:
```

**要点**：
- `depends_on` 确保 PostgreSQL 先启动
- 两个服务都需要持久化卷
- 生产环境应该用更强的密码并通过 .env 文件管理

### 练习三

**思路**：列出生产环境需要的所有敏感配置，并给出安全建议。

**答案**：

```bash
# .env - 生产环境配置

# 数据库
DB_PASSWORD=Xk9#mP2$vL7nQ4wR    # 至少 16 位，包含大小写字母、数字、特殊字符
POSTGRES_DB=n8n
POSTGRES_USER=n8n

# n8n 认证
N8N_USER=admin
N8N_PASSWORD=Yt5$hJ8#kM3pR6wQ   # 强密码，不要用 admin/123456

# 域名
N8N_HOST=n8n.yourcompany.com
N8N_PROTOCOL=https
WEBHOOK_URL=https://n8n.yourcompany.com/

# 加密密钥（32 位十六进制，用 openssl rand -hex 32 生成）
ENCRYPTION_KEY=a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6

# 执行配置
EXECUTIONS_TIMEOUT=3600
EXECUTIONS_DATA_MAX_SIZE=128
```

**要点**：
- 密码不要用字典词汇，建议用密码管理器生成
- ENCRYPTION_KEY 一旦配置不要更改，否则所有已保存的凭证失效
- WEBHOOK_URL 必须是外部可访问的地址
- .env 文件不要提交到版本控制，加入 .gitignore
