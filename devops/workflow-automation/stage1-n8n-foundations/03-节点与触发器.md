# 第三课：节点与触发器

> **课程定位**：掌握 n8n 的核心构建单元——节点和触发器，理解数据如何在工作流中流转
> **前置知识**：已完成 n8n 安装部署，了解 HTTP 和 Webhook 概念
> **预计时长**：35 分钟

---

## 场景引入

n8n 已经跑起来了，你打开编辑器，看到一个空白画布和左侧密密麻麻的节点列表。有几百个节点——HTTP Request、Slack、PostgreSQL、Code、IF、Set……你需要理解的是：这些节点是怎么工作的？数据是怎么从一个节点流到下一个节点的？触发器和普通节点有什么区别？

## 一、节点基础

### 1.1 节点是什么

节点是 n8n 工作流的基本单元。每个节点做一件事：接收数据、处理数据、输出数据。

```
┌─────────────┐
│   节点结构    │
│             │
│  输入项      │ ← 上一个节点的输出
│  （Input）   │
│     ↓       │
│  处理逻辑    │ ← 节点配置（URL、SQL、表达式等）
│  （Process） │
│     ↓       │
│  输出项      │ → 传递给下一个节点
│  （Output）  │
└─────────────┘
```

每个节点的输出是一个 JSON 数组，每个元素叫一个 **Item**：

```json
[
  {
    "json": {
      "name": "张三",
      "email": "zhangsan@example.com",
      "amount": 299
    },
    "binary": {}
  }
]
```

- `json`：结构化数据，大多数节点只处理这部分
- `binary`：二进制数据（文件、图片等），文件类节点会用到

### 1.2 节点配置

每个节点都有配置面板，通常包含：

| 配置项 | 说明 | 例子 |
|--------|------|------|
| Operation | 操作类型 | GET、POST、Create、Update |
| Resource | 操作对象 | Message、User、File |
| Parameters | 具体参数 | URL、Body、Headers |
| Options | 高级选项 | Timeout、Retry、Batch Size |

## 二、触发器节点

### 2.1 触发器的作用

触发器决定工作流**什么时候执行**。没有触发器的工作流只能手动执行。

```
触发器类型：
├── 手动触发    Manual Trigger（开发调试用）
├── Webhook     HTTP 请求触发（外部系统调用）
├── 定时触发    Schedule Trigger（Cron 表达式）
├── 事件触发    各种 SaaS 事件（新邮件、新行等）
└── 流式触发    Kafka、RabbitMQ 等消息队列
```

### 2.2 Webhook 触发器

Webhook 是最常用的触发方式。外部系统通过 HTTP 请求触发你的工作流。

```
外部系统 ──HTTP POST──→ n8n Webhook ──→ 工作流执行
```

配置 Webhook：

1. 添加 Webhook 节点
2. 设置 HTTP Method（GET/POST/PUT/DELETE）
3. 设置 Path（如 `/new-order`）
4. 保存后得到 Webhook URL：`http://localhost:5678/webhook/new-order`

Webhook 返回的数据：

```json
{
  "headers": {
    "content-type": "application/json",
    "user-agent": "PostmanRuntime/7.32.3"
  },
  "params": {},
  "query": {},
  "body": {
    "order_id": "ORD-001",
    "customer": "张三",
    "amount": 299
  }
}
```

Webhook 的两种模式：

| 模式 | 行为 | 适用场景 |
|------|------|---------|
| Immediately | 收到请求立即返回 200 | 不需要返回结果 |
| Last Node | 等工作流执行完，返回最后节点的输出 | 需要同步返回结果 |

### 2.3 Schedule Trigger（定时触发）

用 Cron 表达式设定工作流的执行时间。

```
常用 Cron 表达式：
├── 每天 9:00      → 0 9 * * *
├── 每周一 9:00    → 0 9 * * 1
├── 每小时执行      → 0 * * * *
├── 每 5 分钟      → */5 * * * *
└── 每月 1 号 0:00 → 0 0 1 * *
```

n8n 的 Schedule Trigger 提供了可视化配置，不需要手写 Cron：

- Every Hour：每小时
- Every Day：每天指定时间
- Every Week：每周指定天和时间
- Every Month：每月指定日期和时间
- Custom：自定义 Cron 表达式

### 2.4 事件触发器

n8n 内置了大量 SaaS 的事件触发器：

| 服务 | 触发事件 | 说明 |
|------|---------|------|
| GitHub | Pull Request、Issue、Push | 代码仓库事件 |
| Slack | New Message、Reaction | 消息和互动 |
| Google Sheets | New Row、Updated Row | 表格数据变化 |
| Stripe | Payment、Subscription | 支付事件 |
| Typeform | New Submission | 表单提交 |

事件触发器的工作原理：

```
n8n 注册 Webhook 到 SaaS 服务
         ↓
SaaS 在事件发生时回调 n8n
         ↓
n8n 触发工作流执行
```

## 三、常用动作节点

### 3.1 HTTP Request 节点

最通用的节点，可以调用任何 HTTP API。

```json
{
  "method": "POST",
  "url": "https://api.example.com/orders",
  "headers": {
    "Content-Type": "application/json",
    "Authorization": "Bearer {{$credentials.apiKey}}"
  },
  "body": {
    "order_id": "{{$json.order_id}}",
    "amount": "{{$json.amount}}"
  }
}
```

常用配置：

| 配置项 | 说明 |
|--------|------|
| Method | GET/POST/PUT/PATCH/DELETE |
| URL | 支持表达式动态拼接 |
| Headers | 请求头 |
| Body | 请求体（JSON/Form/Raw） |
| Authentication | 内置认证方式（Header Auth、OAuth2 等） |
| Options | 超时、重试、代理 |

### 3.2 Set 节点

用于创建或修改数据。常用于数据清洗和格式化。

```json
{
  "assignments": [
    {
      "name": "full_name",
      "value": "={{ $json.first_name }} {{ $json.last_name }}"
    },
    {
      "name": "order_total",
      "value": "={{ $json.price * $json.quantity }}"
    },
    {
      "name": "created_at",
      "value": "={{ $now.toISO() }}"
    }
  ]
}
```

Set 节点的三种模式：

| 模式 | 说明 |
|------|------|
| Manual Mapping | 手动定义字段 |
| JSON | 直接写 JSON 表达式 |
| Fixed Values | 固定值 |

### 3.3 IF 节点

条件分支，根据数据决定走哪条路径。

```json
{
  "conditions": {
    "string": [
      {
        "value1": "={{ $json.status }}",
        "operation": "equals",
        "value2": "paid"
      }
    ]
  }
}
```

IF 节点有两个输出：

- **True**：条件满足时走这条路
- **False**：条件不满足时走这条路

支持的条件类型：

| 类型 | 操作符 |
|------|--------|
| String | equals、not equals、contains、starts with、ends with、regex |
| Number | equals、not equals、gt、lt、gte、lte |
| Boolean | true、false |
| Array | is empty、is not empty、contains |
| DateTime | before、after、between |

### 3.4 Code 节点

当内置节点不够用时，可以用 Code 节点写 JavaScript 或 Python。

```javascript
// Code 节点示例：数据聚合
const items = $input.all();
const total = items.reduce((sum, item) => sum + item.json.amount, 0);
const count = items.length;

return [{
  json: {
    total_amount: total,
    order_count: count,
    average_order: Math.round(total / count)
  }
}];
```

Code 节点的输入和输出：

```javascript
// 获取所有输入项
const items = $input.all();

// 获取单个输入项
const firstItem = $input.first();

// 返回结果（必须是数组）
return [
  { json: { result: "success" } }
];
```

## 四、节点间的数据传递

### 4.1 数据引用

节点之间通过表达式引用数据。n8n 使用 `{{ }}` 语法：

```
引用上一个节点的输出：
{{ $json.field_name }}          → 当前项的字段
{{ $json.nested.field }}        → 嵌套字段
{{ $input.first().json.field }} → 明确指定输入

引用上上个节点的输出：
{{ $('NodeName').first().json.field }}  → 按节点名引用
```

### 4.2 多项数据处理

当一个节点输出多个 Item 时，下一个节点会**逐个处理**每个 Item：

```
节点 A 输出：[{name: "张三"}, {name: "李四"}, {name: "王五"}]
    ↓
节点 B（HTTP Request）：对每个 Item 分别发起请求
    → 请求 1：张三
    → 请求 2：李四
    → 请求 3：王五
```

如果你想**聚合**多个 Item 的数据，需要用 Code 节点或 Merge 节点。

### 4.3 表达式语法

n8n 的表达式基于 JavaScript：

```javascript
// 字符串拼接
{{ "Hello, " + $json.name }}

// 条件表达式
{{ $json.amount > 100 ? "high" : "low" }}

// 数组操作
{{ $json.items.map(item => item.name) }}

// 日期操作
{{ $now.format('yyyy-MM-dd') }}
{{ DateTime.fromISO($json.date).plus({days: 7}).toISO() }}

// 数学运算
{{ Math.round($json.price * 1.1) }}

// 空值处理
{{ $json.name ?? "未知" }}
```

## 五、构建第一个完整工作流

### 5.1 场景：新订单通知

当收到新订单 Webhook 时，提取订单信息，判断金额是否超过 1000 元，超过则发送 Slack 通知。

```
Webhook（/new-order）
    ↓
Set（提取订单信息）
    ↓
IF（amount > 1000?）
    ↓ True              ↓ False
Slack（通知）        NoOp（结束）
```

### 5.2 实现步骤

**Step 1：Webhook 触发器**

- 添加 Webhook 节点
- Method: POST
- Path: /new-order
- 复制生成的 Webhook URL

**Step 2：Set 节点提取数据**

```json
{
  "order_id": "={{ $json.body.order_id }}",
  "customer": "={{ $json.body.customer }}",
  "amount": "={{ $json.body.amount }}",
  "items": "={{ $json.body.items }}"
}
```

**Step 3：IF 节点判断金额**

```json
{
  "conditions": {
    "number": [
      {
        "value1": "={{ $json.amount }}",
        "operation": "gt",
        "value2": 1000
      }
    ]
  }
}
```

**Step 4：Slack 节点通知**

```json
{
  "channel": "#orders",
  "text": "大额订单！{{$json.customer}} 下了一笔 {{$json.amount}} 元的订单（{{$json.order_id}}）"
}
```

## 常见误区

### 误区一："所有节点都会自动处理多项数据"

大多数节点会逐个处理每个 Item，但有些节点（如 Aggregate、Summarize）是专门用来聚合的。如果你需要对所有数据做汇总，不要期望普通节点自动完成。

### 误区二："Webhook URL 是固定的"

Webhook URL 由 n8n 实例的地址 + 路径组成。如果改了 N8N_HOST 或 WEBHOOK_URL 环境变量，之前注册的 Webhook 地址会失效。

### 误区三："Code 节点可以做任何事"

Code 节点有执行时间限制和内存限制。大量数据处理应该用专用节点（如 PostgreSQL 节点的批量操作），而不是在 Code 节点里循环。

### 误区四："触发器只能有一个"

一个工作流只能有一个触发器，但你可以创建多个工作流来响应不同事件，或者用 Merge 节点合并多个触发源的数据。

---

## 工程建议

1. **先用 Manual Trigger 调试**：开发阶段先用手动触发，确认逻辑正确后再切换到 Webhook 或定时触发。
2. **Set 节点做数据清洗**：在传递给下游节点之前，先用 Set 节点提取和格式化数据。
3. **善用 IF 节点的默认路径**：IF 节点的 False 分支可以作为默认处理路径。
4. **Webhook 加签名校验**：生产环境的 Webhook 应该验证请求签名，防止伪造请求。
5. **为节点命名**：给每个节点一个有意义的名称（如"提取订单信息"而不是"Set"），方便后续维护。

---

## 小结

- 节点是 n8n 的基本单元，每个节点接收输入、处理数据、输出结果
- 触发器决定工作流何时执行：Webhook（外部调用）、Schedule（定时）、Event（SaaS 事件）
- 节点间通过 JSON Item 传递数据，用 `{{ }}` 表达式引用
- HTTP Request 是最通用的节点，Code 节点用于自定义逻辑
- 先用 Manual Trigger 调试，再切换到生产触发器

## 参考答案

### 练习一

**思路**：Webhook 接收数据 → Set 添加字段 → 返回结果。

**答案**：

节点配置：

1. **Webhook**：POST /process-user，Response Mode: Last Node
2. **Set**：
   ```json
   {
     "name": "={{ $json.body.name }}",
     "email": "={{ $json.body.email }}",
     "processed_at": "={{ $now.toISO() }}"
   }
   ```

测试：

```bash
curl -X POST http://localhost:5678/webhook/process-user \
  -H "Content-Type: application/json" \
  -d '{"name": "张三", "email": "zhangsan@example.com"}'
```

**要点**：
- Webhook 的 Response Mode 设为 Last Node 才能返回处理结果
- `$json.body` 是 Webhook 收到的请求体
- `$now.toISO()` 生成当前时间的 ISO 格式字符串

### 练习二

**思路**：Schedule Trigger 定时 → HTTP Request 调用 API → Set 提取字段。

**答案**：

1. **Schedule Trigger**：Every Hour
2. **HTTP Request**：GET https://api.github.com/repos/n8n-io/n8n
3. **Set**：
   ```json
   {
     "repo": "n8n-io/n8n",
     "stars": "={{ $json.stargazers_count }}",
     "forks": "={{ $json.forks_count }}",
     "checked_at": "={{ $now.toISO() }}"
   }
   ```

**要点**：
- GitHub API 不需要认证就能访问公开仓库的基本信息
- 定时触发的工作流在 n8n 启动后自动按计划执行
- 字段名用 `stargazers_count` 而不是 `stars`，需要查看 API 文档确认

### 练习三

**思路**：Webhook 接收 → IF 判断 → 分别输出不同格式。

**答案**：

1. **Webhook**：POST /check-score
2. **IF**：
   ```json
   {
     "conditions": {
       "number": [
         {
           "value1": "={{ $json.body.score }}",
           "operation": "gte",
           "value2": 60
         }
       ]
     }
   }
   ```
3. **True 分支 - Set**：
   ```json
   {
     "result": "及格",
     "score": "={{ $json.score }}",
     "message": "恭喜通过！"
   }
   ```
4. **False 分支 - Set**：
   ```json
   {
     "result": "不及格",
     "score": "={{ $json.score }}",
     "message": "继续努力！"
   }
   ```

**要点**：
- IF 节点的 `gte` 表示大于等于
- 两个分支可以输出不同结构的数据
- 分支上可以连接不同的后续节点（如及格发祝贺邮件，不及格发提醒）
