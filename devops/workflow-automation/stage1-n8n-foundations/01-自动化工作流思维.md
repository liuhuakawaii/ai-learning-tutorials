# 自动化工作流思维

## 从一个脚本事故说起

你的团队每周从 5 个渠道收集客户反馈：邮件、Slack、表单、社交媒体、客服系统。有人写了几个 Python 脚本来自动化汇总，脚本散落在不同服务器上。某天某个 API 改了，脚本静默失败了一周才被发现。

问题不在于"能不能写代码"，而在于这些分散的自动化缺乏统一的编排、监控和错误处理。

## 工作流的本质是编排

工作流是一系列按顺序或条件执行的步骤：

```
客户下单 → 检查库存 → 扣款 → 发货通知 → 更新 CRM
         ↓
      库存不足 → 通知采购 → 生成补货单
```

手动执行的问题：速度慢、易出错、不可追踪、难以扩展。

自动化工作流的核心价值：把确定性流程交给机器，让人专注于需要判断力的环节。

每个工作流都由四类组件构成：

```
┌─────────┐     ┌─────────┐     ┌─────────┐     ┌─────────┐
│  触发器  │ ──→ │  处理器  │ ──→ │  条件判断│ ──→ │  输出动作│
│ Trigger  │     │ Process  │     │ Condition│     │  Action  │
└─────────┘     └─────────┘     └─────────┘     └─────────┘
  新邮件到达      提取内容         是否紧急？       发 Slack
  定时触发        解析附件          ↓      ↓       更新数据库
  Webhook         格式转换        是      否       发送通知
                                 加急    普通
                                 通知    入队
```

## n8n 解决了什么

你完全可以用 Python 写自动化脚本。但当规模扩大后，纯代码方案会遇到这些问题：

```
无可视化：看不出流程全貌，新人接手困难
无重试：API 调用失败就静默跳过
无监控：脚本挂了没人知道
无版本：改了代码不知道改了什么
硬编码：凭证散落在代码里
难扩展：加一个步骤就要改代码、测试、部署
```

n8n 这类平台的核心价值不是"不用写代码"，而是提供了编排层——可视化流程、自动重试、执行日志、凭证管理、版本控制。

对比：

```
维度        写脚本              n8n
─────────────────────────────────────────
开发速度    快（小流程）        快（任何规模）
可视化      无                  完整流程图
错误处理    自己实现            内置重试、告警
监控        自己搭              内置执行日志
凭证管理    .env 文件           加密凭证库
协作        代码审查            可视化 + 导出 JSON
```

但工作流平台不是万能的。高性能计算、复杂算法、低延迟 API 仍然适合写代码。最佳实践是混合使用：用 n8n 编排流程，关键节点调用自定义代码服务。

## 三个工具的定位

```
Zapier：非技术用户，简单触发-动作，5000+ 集成，免费版 100 任务/月
Make：中级用户，可视化流程图，支持分支和循环，性价比高
n8n：开发者友好，开源可自部署，支持代码节点，数据隐私要求高
```

选型决策：

```
非技术用户 → 简单触发-动作 → Zapier
有一定技术背景 → 中等复杂度 → Make
开发者/团队 → 复杂逻辑 + 数据隐私 → n8n
```

## 什么流程值得自动化

不是所有流程都值得自动化。适合自动化的流程有这些特征：

```
重复性：同一流程每周执行 3 次以上
确定性：步骤固定，不需要人工判断
多系统：涉及 2 个以上系统的数据流转
时效性：需要快速响应
容错性：偶尔出错可以重试或人工补救
```

不适合自动化的：需要创造性判断的、流程频繁变化的、一次性任务、出错代价极高的。

ROI 评估：

```
自动化价值 = (手动耗时 × 频率 × 人力成本) - (开发时间 + 维护成本)

示例：
手动处理一次订单同步：15 分钟，每周 20 次，人力 100 元/小时
年度成本：15/60 × 20 × 52 × 100 = 26,000 元
开发 + 维护成本：28 小时 × 100 = 2,800 元
净收益：23,200 元/年
```

## 练习

### 练习一：识别自动化机会

列出你当前工作中 3 个重复性流程，评估每个流程的自动化 ROI（手动耗时、频率、涉及系统数量）。

### 练习二：工具选型

场景：当 GitHub 收到新 Issue 时，自动在 Jira 创建任务、在 Slack 通知团队、如果 Issue 带"urgent"标签则同时发邮件给负责人。选 Zapier、Make 还是 n8n？

### 练习三：用 n8n API 列出工作流

假设你本地运行了 n8n（http://localhost:5678），编写一个 shell 命令，使用 curl 调用 n8n REST API 列出所有工作流。API Key 通过环境变量 `$N8N_API_KEY` 传入。

## 参考答案

### 练习一

| 流程 | 手动耗时 | 频率/周 | 涉及系统 | 年度成本 | 自动化成本 | ROI |
|------|---------|---------|---------|---------|-----------|-----|
| 客户数据同步 | 30 分钟 | 10 次 | CRM + 数据库 | 26,000 元 | 3,000 元 | 高 |
| 周报生成 | 2 小时 | 1 次 | 数据库 + 邮件 | 10,400 元 | 2,000 元 | 高 |
| 发票审批 | 10 分钟 | 5 次 | 财务系统 + 邮件 | 4,333 元 | 4,000 元 | 低 |

优先自动化涉及多系统、手动步骤多的流程。

### 练习二

推荐 **n8n**。理由：
1. 需要条件分支（检查 urgent 标签），Zapier 多步 Zaps 费用高
2. 涉及 4 个系统集成
3. Webhook 触发 + 条件逻辑 + 多路输出，n8n 编排更清晰
4. 代码节点可以在需要时做自定义处理

### 练习三

```bash
curl -s http://localhost:5678/api/v1/workflows \
  -H "X-N8N-API-KEY: $N8N_API_KEY" | jq '.data[] | {id, name, active}'
```

如果还没有 API Key，在 n8n 设置中启用 Public API 并生成 Key。环境变量 `N8N_PUBLIC_API_DISABLED` 需要设为 `false`。
