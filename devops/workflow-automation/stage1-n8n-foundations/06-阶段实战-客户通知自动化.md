# 第六课：阶段实战——客户通知自动化

> **课程定位**：综合运用前 5 课知识，构建一个完整的客户通知自动化工作流
> **前置知识**：已完成 n8n 基础课程的前 5 课
> **预计时长**：45 分钟

---

## 场景引入

你的 SaaS 产品有三种客户事件需要自动处理：

1. **新客户注册**：发送欢迎邮件 + 创建 CRM 记录 + 通知销售团队
2. **客户升级套餐**：发送确认邮件 + 更新数据库 + 通知客户成功团队
3. **客户即将到期**：提前 7 天提醒续费 + 发送优惠券

目前这些流程由人工处理，经常遗漏，响应不及时。你需要用 n8n 实现全自动化。

---

## 学习目标

完成本课学习后，你将能够：

1. 设计包含多个触发源的统一工作流
2. 使用条件分支处理不同类型的事件
3. 实现完整的错误处理和告警机制
4. 构建一个可复用的通知自动化模板

## 一、工作流架构设计

### 1.1 整体架构

```
触发层：
├── Webhook: POST /webhook/new-customer
├── Webhook: POST /webhook/upgrade
└── Schedule: 每天 9:00 检查到期客户

处理层：
├── 数据验证和清洗
├── 条件分支（事件类型）
└── 并行处理（多渠道通知）

输出层：
├── 邮件通知
├── Slack 通知
└── 数据库更新

错误处理层：
└── Error Trigger → 告警 + 日志
```

### 1.2 数据流设计

```
Webhook（新客户）
    ↓
Set（统一数据格式）
    ↓
IF（事件类型判断）
    ├─ 新客户 → 并行处理
    │   ├─ Send Email（欢迎邮件）
    │   ├─ Slack（通知销售）
    │   └─ PostgreSQL（创建记录）
    ├─ 升级 → 并行处理
    │   ├─ Send Email（确认邮件）
    │   ├─ Slack（通知客户成功）
    │   └─ PostgreSQL（更新记录）
    └─ 到期提醒 → 并行处理
        ├─ Send Email（续费提醒 + 优惠券）
        └─ Slack（通知客服）
```

## 二、实现步骤

### 2.1 Step 1：创建 Webhook 触发器

创建两个 Webhook 节点作为入口：

**Webhook 1：新客户注册**
```
Method: POST
Path: /new-customer
Response Mode: Immediately
```

**Webhook 2：客户升级**
```
Method: POST
Path: /upgrade
Response Mode: Immediately
```

### 2.2 Step 2：数据标准化

用 Set 节点统一不同来源的数据格式：

```json
{
  "assignments": [
    {
      "name": "event_type",
      "value": "={{ $json.body?.event_type ?? 'new_customer' }}"
    },
    {
      "name": "customer_id",
      "value": "={{ $json.body.customer_id }}"
    },
    {
      "name": "customer_name",
      "value": "={{ $json.body.customer_name }}"
    },
    {
      "name": "customer_email",
      "value": "={{ $json.body.customer_email.toLowerCase().trim() }}"
    },
    {
      "name": "plan",
      "value": "={{ $json.body.plan ?? 'free' }}"
    },
    {
      "name": "expires_at",
      "value": "={{ $json.body.expires_at ?? '' }}"
    },
    {
      "name": "source",
      "value": "={{ $json.body.source ?? 'api' }}"
    },
    {
      "name": "processed_at",
      "value": "={{ $now.toISO() }}"
    }
  ]
}
```

### 2.3 Step 3：条件分支

用 IF 节点判断事件类型：

**IF 1：新客户 vs 其他**
```json
{
  "conditions": {
    "string": [
      {
        "value1": "={{ $json.event_type }}",
        "operation": "equals",
        "value2": "new_customer"
      }
    ]
  }
}
```

**IF 2：升级 vs 到期提醒**（接在 IF 1 的 False 分支）
```json
{
  "conditions": {
    "string": [
      {
        "value1": "={{ $json.event_type }}",
        "operation": "equals",
        "value2": "upgrade"
      }
    ]
  }
}
```

### 2.4 Step 4：新客户处理分支

**并行执行三个操作：**

**4a. 发送欢迎邮件**

```json
{
  "to": "={{ $json.customer_email }}",
  "subject": "欢迎加入 {{ $json.plan }} 套餐！",
  "body": "Hi {{ $json.customer_name }}，\n\n感谢您注册我们的服务！您已成功开通 {{ $json.plan }} 套餐。\n\n如有任何问题，请随时联系我们。\n\n祝好！"
}
```

**4b. Slack 通知销售团队**

```json
{
  "channel": "#sales",
  "text": "🆕 新客户注册！\n\n客户：{{ $json.customer_name }}\n邮箱：{{ $json.customer_email }}\n套餐：{{ $json.plan }}\n来源：{{ $json.source }}\n时间：{{ $json.processed_at }}"
}
```

**4c. 创建数据库记录**

```sql
INSERT INTO customers (customer_id, name, email, plan, source, status, created_at)
VALUES (
  '{{ $json.customer_id }}',
  '{{ $json.customer_name }}',
  '{{ $json.customer_email }}',
  '{{ $json.plan }}',
  '{{ $json.source }}',
  'active',
  NOW()
)
ON CONFLICT (customer_id) DO NOTHING;
```

### 2.5 Step 5：升级处理分支

```json
{
  "to": "={{ $json.customer_email }}",
  "subject": "套餐升级成功！",
  "body": "Hi {{ $json.customer_name }}，\n\n您的套餐已成功升级为 {{ $json.plan }}！\n\n新功能已解锁，立即体验吧。"
}
```

Slack 通知客户成功团队：

```json
{
  "channel": "#customer-success",
  "text": "⬆️ 客户升级！\n\n客户：{{ $json.customer_name }}\n新套餐：{{ $json.plan }}\n\n请及时跟进，确保客户顺利使用新功能。"
}
```

数据库更新：

```sql
UPDATE customers 
SET plan = '{{ $json.plan }}', updated_at = NOW()
WHERE customer_id = '{{ $json.customer_id }}';
```

### 2.6 Step 6：到期提醒（定时触发）

**Schedule Trigger**：每天 9:00

**PostgreSQL**：查询 7 天内到期的客户

```sql
SELECT customer_id, name, email, plan, expires_at
FROM customers
WHERE expires_at BETWEEN NOW() AND NOW() + INTERVAL '7 days'
AND status = 'active'
AND reminder_sent = false;
```

**Loop**：遍历到期客户

**对每个客户：**
- 发送续费提醒邮件（含优惠券代码）
- 更新 `reminder_sent` 标记
- 通知 Slack 客服频道

## 三、错误处理

### 3.1 添加 Error Trigger

在同一工作流中添加 Error Trigger：

```
Error Trigger
    ↓
Set（格式化错误信息）
    ↓
Slack（发送告警到 #alerts）
    ↓
PostgreSQL（记录错误日志）
```

### 3.2 节点级重试

为外部 API 调用配置重试：

| 节点 | 重试次数 | 间隔 | 策略 |
|------|---------|------|------|
| Send Email | 3 | 2s | Exponential |
| Slack | 3 | 1s | Fixed |
| PostgreSQL | 2 | 1s | Fixed |

### 3.3 关键节点的降级处理

邮件发送失败时的降级：

```
Send Email（主路径）
    ↓ 失败
Slack 通知客服（降级路径）
    "邮件发送失败，请手动联系客户"
```

## 五、优化与扩展

### 5.1 添加数据验证

在处理之前先验证数据：

```javascript
// Code 节点：数据验证
const data = $input.first().json;
const errors = [];

if (!data.customer_id) errors.push('缺少 customer_id');
if (!data.customer_name) errors.push('缺少 customer_name');
if (!data.customer_email || !data.customer_email.includes('@')) {
  errors.push('邮箱格式无效');
}

if (errors.length > 0) {
  return [{
    json: {
      valid: false,
      errors: errors,
      original_data: data
    }
  }];
}

return [{
  json: {
    valid: true,
    ...data
  }
}];
```

### 5.2 添加发送频率限制

避免短时间内发送过多邮件：

```javascript
// Code 节点：频率检查
const cacheKey = `email_sent_${$json.customer_email}`;
const staticData = $getWorkflowStaticData('global');
const lastSent = staticData[cacheKey];

if (lastSent) {
  const diff = Date.now() - lastSent;
  if (diff < 3600000) { // 1 小时内
    return [{
      json: {
        skip: true,
        reason: '发送频率限制',
        next_allowed: new Date(lastSent + 3600000).toISOString()
      }
    }];
  }
}

staticData[cacheKey] = Date.now();
return [{ json: { skip: false, ...$json } }];
```

### 5.3 添加执行统计

记录每次执行的统计信息：

```javascript
// Code 节点：统计
const staticData = $getWorkflowStaticData('global');

if (!staticData.stats) {
  staticData.stats = {
    total_processed: 0,
    new_customers: 0,
    upgrades: 0,
    reminders: 0,
    errors: 0
  };
}

staticData.stats.total_processed++;
staticData.stats[$json.event_type === 'new_customer' ? 'new_customers' : 
                 $json.event_type === 'upgrade' ? 'upgrades' : 'reminders']++;

return [{ json: { ...$json, stats: staticData.stats } }];
```

## 常见误区

### 误区一："一个工作流处理所有事情"

虽然本课演示了在一个工作流中处理多种事件，但在实际项目中，如果每种事件的处理逻辑差异很大，拆分成多个独立的工作流更好维护。

### 误区二："不需要数据验证"

Webhook 接收的数据不能信任。发送方可能传错格式、漏字段、甚至传恶意数据。必须在处理之前验证。

### 误区三："测试通过就上线了"

需要测试正常流程、异常流程、边界情况（空值、超长字符串、特殊字符）和并发场景。

---

## 工程建议

1. **先画流程图再实现**：用纸或工具画出完整的流程，包括正常和异常路径。
2. **每个节点都要有错误处理**：不要假设任何外部调用都会成功。
3. **日志要充分**：关键节点的输入输出都要记录，方便排查问题。
4. **环境变量管理配置**：邮件模板、Slack 频道、API 地址等都应该可配置。
5. **定期审查工作流**：业务变化后，工作流也需要更新。

## 小结

- 客户通知自动化涉及触发、处理、分支、并行和错误处理
- Webhook 接收外部事件，Schedule 处理定时任务
- 数据验证和格式化是处理的第一步
- 错误处理包括重试、降级和告警
- 测试要覆盖正常流程和各种异常情况

## 参考答案

### 练习一

**思路**：按照 Step 1-5 的顺序实现，重点是数据标准化和条件分支。

**答案**：

工作流结构：
```
Webhook（/new-customer）──┐
                          ├→ Set（统一格式）→ IF（事件类型）
Webhook（/upgrade）───────┘         ├─ 新客户 → Email + Slack + DB
                                    └─ 升级 → Email + Slack + DB

Error Trigger → Slack（告警）
```

关键配置：
- Webhook Response Mode 设为 Immediately（不阻塞调用方）
- Set 节点统一所有字段名和格式
- IF 节点用 event_type 字段判断分支
- 每个输出节点配置重试策略

**要点**：
- 立即响应模式适合不需要返回结果的场景
- 数据标准化让后续处理逻辑一致
- 并行执行可以减少总耗时

### 练习二

**思路**：添加 Schedule Trigger + PostgreSQL 查询 + Loop + 邮件发送。

**答案**：

新增工作流或在同一工作流中添加：

```
Schedule（每天 9:00）
    ↓
PostgreSQL（查询到期客户）
    ↓
Loop（遍历客户）
    ↓
Set（格式化邮件内容，含优惠券）
    ↓
Send Email（续费提醒）
    ↓
PostgreSQL（更新 reminder_sent）
```

SQL 查询：
```sql
SELECT * FROM customers
WHERE expires_at BETWEEN NOW() AND NOW() + INTERVAL '7 days'
AND status = 'active'
AND (reminder_sent IS NULL OR reminder_sent = false);
```

**要点**：
- 定时任务应该幂等，重复执行不会重复发送
- 用 `reminder_sent` 标记避免重复提醒
- 优惠券代码可以随机生成或从配置中读取

### 练习三

**思路**：在数据标准化之后、条件分支之前添加验证节点。

**答案**：

```javascript
// Code 节点：数据验证
const data = $input.first().json;
const errors = [];

// 必填字段检查
const requiredFields = ['customer_id', 'customer_name', 'customer_email'];
for (const field of requiredFields) {
  if (!data[field] || data[field].trim() === '') {
    errors.push(`缺少必填字段: ${field}`);
  }
}

// 邮箱格式验证
if (data.customer_email && !/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(data.customer_email)) {
  errors.push('邮箱格式无效');
}

// 客户 ID 唯一性检查（通过数据库查询）
// 这里简化为检查格式
if (data.customer_id && data.customer_id.length < 3) {
  errors.push('customer_id 长度不足');
}

if (errors.length > 0) {
  return [{
    json: {
      valid: false,
      errors: errors,
      original_data: data,
      validated_at: $now.toISO()
    }
  }];
}

return [{
  json: {
    valid: true,
    ...data,
    validated_at: $now.toISO()
  }
}];
```

后续连接 IF 节点判断 `valid` 字段，失败时记录日志并通知管理员。

**要点**：
- 验证逻辑应该在数据标准化之后、业务处理之前
- 错误信息要具体，方便定位问题
- 验证失败的数据不应该进入业务处理流程
