# 阶段实战：客户通知自动化

## 场景

SaaS 产品有三种客户事件需要自动处理：

1. **新客户注册**：发送欢迎邮件 + 创建 CRM 记录 + 通知销售团队
2. **客户升级套餐**：发送确认邮件 + 更新数据库 + 通知客户成功团队
3. **客户即将到期**：提前 7 天提醒续费 + 发送优惠券

目前人工处理，经常遗漏。用 n8n 实现全自动化。

## 工作流架构

```
触发层：
├── Webhook: POST /webhook/new-customer
├── Webhook: POST /webhook/upgrade
└── Schedule: 每天 9:00 检查到期客户

处理层：
├── 数据验证和清洗
├── 条件分支（事件类型）
└── 并行处理（多渠道通知）

输出层：
├── 邮件通知
├── Slack 通知
└── 数据库更新

错误处理层：
└── Error Trigger → 告警 + 日志
```

## 实现步骤

### Step 1：Webhook 触发器

```
Webhook 1：POST /new-customer, Response Mode: Immediately
Webhook 2：POST /upgrade, Response Mode: Immediately
```

### Step 2：数据标准化

用 Set 节点统一不同来源的数据格式：

```json
{
  "assignments": [
    { "name": "event_type", "value": "={{ $json.body?.event_type ?? 'new_customer' }}" },
    { "name": "customer_id", "value": "={{ $json.body.customer_id }}" },
    { "name": "customer_name", "value": "={{ $json.body.customer_name }}" },
    { "name": "customer_email", "value": "={{ $json.body.customer_email.toLowerCase().trim() }}" },
    { "name": "plan", "value": "={{ $json.body.plan ?? 'free' }}" },
    { "name": "processed_at", "value": "={{ $now.toISO() }}" }
  ]
}
```

### Step 3：条件分支

IF 节点判断 event_type：`new_customer` → 新客户分支，`upgrade` → 升级分支。

### Step 4：新客户分支（并行执行）

**发送欢迎邮件**：
```json
{
  "to": "={{ $json.customer_email }}",
  "subject": "欢迎加入 {{ $json.plan }} 套餐！",
  "body": "Hi {{ $json.customer_name }}，感谢您注册！"
}
```

**Slack 通知销售**：
```json
{
  "channel": "#sales",
  "text": "🆕 新客户！\n客户：{{ $json.customer_name }}\n套餐：{{ $json.plan }}"
}
```

**创建数据库记录**：
```sql
INSERT INTO customers (customer_id, name, email, plan, status, created_at)
VALUES ('{{ $json.customer_id }}', '{{ $json.customer_name }}', '{{ $json.customer_email }}', '{{ $json.plan }}', 'active', NOW())
ON CONFLICT (customer_id) DO NOTHING;
```

### Step 5：到期提醒（定时触发）

```
Schedule（每天 9:00）
    ↓
PostgreSQL（查询 7 天内到期客户）
    ↓
Loop（遍历客户）
    ↓
Send Email（续费提醒 + 优惠券）
    ↓
PostgreSQL（更新 reminder_sent 标记）
```

## 错误处理

```
Error Trigger
    ↓
Set（格式化错误信息）
    ↓
Slack（发送告警到 #alerts）
    ↓
PostgreSQL（记录错误日志）
```

为外部 API 调用配置重试：邮件 3 次（指数退避）、Slack 3 次（固定间隔）。

邮件发送失败时的降级：Slack 通知客服"邮件发送失败，请手动联系客户"。

## 数据验证

在处理之前先验证数据：

```javascript
const data = $input.first().json
const errors = []

if (!data.customer_id) errors.push('缺少 customer_id')
if (!data.customer_name) errors.push('缺少 customer_name')
if (!data.customer_email || !data.customer_email.includes('@')) errors.push('邮箱格式无效')

if (errors.length > 0) {
  return [{ json: { valid: false, errors, original_data: data } }]
}
return [{ json: { valid: true, ...data } }]
```

## 练习

### 练习一：完整工作流

从零构建完整的客户通知自动化工作流。至少包含新客户注册和客户升级两种事件。

### 练习二：添加到期提醒

添加定时触发的到期提醒。每天检查即将到期客户，发送提醒邮件。

### 练习三：添加频率限制

为邮件发送添加频率限制：同一邮箱 1 小时内不重复发送。使用 `$getWorkflowStaticData('global')` 存储发送记录。

## 参考答案

### 练习一

```
Webhook（/new-customer）──┐
                          ├→ Set（统一格式）→ IF（事件类型）
Webhook（/upgrade）───────┘       ├─ 新客户 → Email + Slack + DB
                                  └─ 升级 → Email + Slack + DB
Error Trigger → Slack（告警）
```

### 练习二

```
Schedule（每天 9:00）→ PostgreSQL（查询到期客户）→ Loop → Email + 更新 reminder_sent
```

SQL：`SELECT * FROM customers WHERE expires_at BETWEEN NOW() AND NOW() + INTERVAL '7 days' AND status = 'active' AND reminder_sent = false`

### 练习三

```javascript
const cacheKey = `email_sent_${$json.customer_email}`
const staticData = $getWorkflowStaticData('global')
const lastSent = staticData[cacheKey]

if (lastSent && Date.now() - lastSent < 3600000) {
  return [{ json: { skip: true, reason: '发送频率限制' } }]
}

staticData[cacheKey] = Date.now()
return [{ json: { skip: false, ...$json } }]
```
