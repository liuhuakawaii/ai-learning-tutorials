# 第一课：AI 节点集成

> **课程定位**：在 n8n 工作流中集成 LLM 能力，实现 AI 驱动的自动化
> **前置知识**：了解 OpenAI API 基础，有 Prompt 编写经验
> **预计时长**：35 分钟

---

## 场景引入

你的客服系统每天收到 200 条咨询，人工回复忙不过来。你想用 AI 自动回复常见问题，但复杂问题仍需转人工。你需要把 LLM 集成到工作流中，让它根据问题类型自动判断是直接回复还是转交人工。

## 一、OpenAI 节点

### 1.1 配置凭证

1. Credentials → Add Credential → OpenAI API
2. 填入 API Key
3. 可选：设置 Organization ID

### 1.2 基本调用

```json
{
  "resource": "chat",
  "operation": "complete",
  "model": "gpt-4o-mini",
  "messages": {
    "values": [
      {
        "role": "system",
        "content": "你是一个专业的客服助手。"
      },
      {
        "role": "user",
        "content": "={{ $json.question }}"
      }
    ]
  },
  "options": {
    "temperature": 0.7,
    "maxTokens": 500
  }
}
```

### 1.3 参数说明

| 参数 | 说明 | 建议值 |
|------|------|--------|
| model | 模型名称 | gpt-4o-mini（性价比高）、gpt-4o（高质量） |
| temperature | 创造性（0-1） | 0.3（确定性任务）、0.7（创意任务） |
| maxTokens | 最大输出长度 | 500-2000 |
| top_p | 核采样 | 1.0（默认） |

### 1.4 输出处理

LLM 的输出需要解析：

```javascript
// Code 节点：解析 AI 输出
const response = $input.first().json;
const content = response.choices[0].message.content;

// 尝试解析 JSON
let parsed;
try {
  parsed = JSON.parse(content);
} catch {
  parsed = { text: content };
}

return [{
  json: {
    answer: parsed.text || parsed.answer,
    category: parsed.category || 'general',
    confidence: parsed.confidence || 0.5,
    needs_human: parsed.needs_human || false,
    raw_response: content
  }
}];
```

## 二、Claude 节点

### 2.1 配置

使用 HTTP Request 节点调用 Claude API：

```json
{
  "method": "POST",
  "url": "https://api.anthropic.com/v1/messages",
  "headers": {
    "Content-Type": "application/json",
    "x-api-key": "={{ $credentials.claudeApiKey }}",
    "anthropic-version": "2023-06-01"
  },
  "body": {
    "model": "claude-sonnet-4-20250514",
    "max_tokens": 1000,
    "messages": [
      {
        "role": "user",
        "content": "={{ $json.prompt }}"
      }
    ]
  }
}
```

### 2.2 OpenAI vs Claude 选型

| 维度 | OpenAI GPT-4o | Claude Sonnet |
|------|---------------|---------------|
| 速度 | 快 | 中等 |
| 成本 | 中等 | 低 |
| 长文本 | 128K | 200K |
| 代码能力 | 强 | 强 |
| 指令遵循 | 好 | 很好 |

## 三、Prompt 模板设计

### 3.1 结构化 Prompt

```
角色：你是一个 {{ role }}。
任务：{{ task_description }}

输入数据：
{{ input_data }}

输出要求：
请以 JSON 格式返回，包含以下字段：
- result: 处理结果
- confidence: 置信度 (0-1)
- reasoning: 推理过程

注意：
{{ constraints }}
```

在 n8n 中实现：

```javascript
// Code 节点：构建 Prompt
const input = $input.first().json;

const prompt = `角色：你是一个专业的客服分类助手。
任务：分析客户问题，判断类别和处理方式。

客户问题：${input.question}

输出要求：
请以 JSON 格式返回：
{
  "category": "billing|technical|general|complaint",
  "urgency": "low|medium|high",
  "needs_human": true/false,
  "suggested_reply": "建议回复内容"
}`;

return [{ json: { prompt, original: input } }];
```

### 3.2 Few-shot 示例

```javascript
const prompt = `分析客户情绪，判断是否需要人工介入。

示例：
问题："你们的产品太垃圾了，我要退款！"
结果：{"sentiment": "negative", "urgency": "high", "needs_human": true}

问题："请问怎么修改密码？"
结果：{"sentiment": "neutral", "urgency": "low", "needs_human": false}

问题："我等了三天还没收到货，到底怎么回事？"
结果：{"sentiment": "negative", "urgency": "high", "needs_human": true}

现在请分析：
问题："${input.question}"
结果：`;
```

### 3.3 输出格式约束

强制 JSON 输出：

```json
{
  "response_format": { "type": "json_object" },
  "messages": [
    {
      "role": "system",
      "content": "你必须以 JSON 格式回复，不要包含任何其他文本。"
    },
    {
      "role": "user",
      "content": "分析这段文本的情感：{{ $json.text }}"
    }
  ]
}
```

## 四、实战：AI 客服分流

### 4.1 流程设计

```
Webhook（客户消息）
    ↓
Code（构建分类 Prompt）
    ↓
OpenAI（分类分析）
    ↓
Code（解析结果）
    ↓
Switch（按类别路由）
    ├─ billing   → 查询账单 API → 自动回复
    ├─ technical → 搜索知识库 → 自动回复
    ├─ complaint → 转人工 + 通知主管
    └─ general   → AI 生成回复 → 自动发送
```

### 4.2 实现

**分类 Prompt：**

```javascript
const message = $input.first().json;

return [{
  json: {
    prompt: `分析以下客户消息，返回 JSON 格式：
{
  "category": "billing|technical|complaint|general",
  "urgency": "low|medium|high",
  "needs_human": boolean,
  "key_topics": ["主题1", "主题2"],
  "suggested_action": "建议处理方式"
}

客户消息：${message.content}

JSON：`,
    customer_id: message.customer_id,
    message_id: message.message_id
  }
}];
```

**路由逻辑：**

```javascript
const aiResult = $input.first().json;
let parsed;

try {
  const content = aiResult.choices[0].message.content;
  parsed = JSON.parse(content);
} catch {
  // 解析失败默认转人工
  parsed = { category: 'general', needs_human: true };
}

return [{
  json: {
    ...aiResult,
    category: parsed.category,
    urgency: parsed.urgency,
    needs_human: parsed.needs_human,
    suggested_action: parsed.suggested_action
  }
}];
```

## 五、成本控制

### 5.1 Token 计算

```javascript
// 估算 Token 数量（粗略）
function estimateTokens(text) {
  return Math.ceil(text.length / 4);
}

// 成本计算
const inputTokens = estimateTokens(prompt);
const outputTokens = estimateTokens(response);
const costPer1k = 0.002; // gpt-4o-mini 的价格
const totalCost = (inputTokens + outputTokens) / 1000 * costPer1k;
```

### 5.2 省钱策略

| 策略 | 说明 |
|------|------|
| 用小模型 | gpt-4o-mini 处理简单任务 |
| 限制 max_tokens | 不要让 AI 输出过长 |
| 缓存结果 | 相同问题缓存 AI 回复 |
| 批量处理 | 合并多个请求成一个 |
| Prompt 精简 | 减少不必要的上下文 |

## 常见误区

### 误区一："AI 的输出总是可靠的"

LLM 可能产生幻觉或格式错误。必须验证输出，设置 fallback。

### 误区二："temperature 越高越好"

高 temperature 产生更多随机性。分类、提取等确定性任务应该用低 temperature（0.1-0.3）。

### 误区三："Prompt 越长越好"

Prompt 应该精炼。过长的 Prompt 增加成本，也可能让 AI 困惑。

---

## 工程建议

1. **输出必须可解析**：要求 JSON 输出时，用 `response_format: { type: "json_object" }`。
2. **设置超时**：LLM 调用可能很慢，设置合理的超时时间。
3. **错误要降级**：AI 调用失败时，走默认处理路径（如转人工）。
4. **记录 Token 使用**：监控成本，设置预算告警。
5. **A/B 测试 Prompt**：不同 Prompt 的效果差异很大，需要测试。

---

## 小结

- n8n 通过 OpenAI 节点或 HTTP Request 节点集成 LLM
- Prompt 模板应该结构化，包含角色、任务、输入和输出格式
- 强制 JSON 输出便于后续节点处理
- 成本控制包括模型选择、Token 限制和缓存
- AI 输出必须验证，失败时有降级方案
