## 场景引入

你的 SaaS 产品有 5000 个付费用户，每天收到 200+ 条客服消息。团队 3 个客服忙不过来，用户等待时间长。你想用 AI 处理 70% 的常见问题，只把复杂问题转给人工。系统需要：理解用户意图、检索知识库、生成回答、执行操作（查订单、改地址）、人工审核敏感操作。

## 一、系统架构

### 1.1 整体设计

```
用户消息入口：
├── Webhook（API 接入）
├── Slack（Slack 消息）
└── 邮件（IMAP 轮询）

处理层：
├── 意图识别（AI 分类）
├── 知识库检索（RAG）
├── 工具调用（Agent）
└── 回答生成（AI）

转接层：
├── 自动回复（AI 处理）
├── 人工转接（复杂问题）
└── 升级处理（投诉/紧急）

监控层：
├── 响应时间
├── 解决率
├── 满意度
└── AI 准确率
```

### 1.2 数据流

```
用户消息
    ↓
预处理（格式化、去重）
    ↓
意图识别
    ├─ 常见问题 → RAG 检索 → AI 回答
    ├─ 订单查询 → Agent 工具 → 返回结果
    ├─ 操作请求 → Agent 工具 → 人工确认 → 执行
    ├─ 投诉/紧急 → 立即转人工
    └─ 无法识别 → 转人工
    ↓
回答质量检查
    ├─ 通过 → 发送给用户
    └─ 不通过 → 转人工
    ↓
记录对话历史
```

## 二、意图识别

### 2.1 分类 Prompt

```javascript
const prompt = `分析客服消息，判断意图类别。

消息：${message}

类别：
- faq: 常见问题（产品功能、使用方法）
- order: 订单相关（查询、修改、取消）
- billing: 账单相关（付款、退款、发票）
- technical: 技术问题（故障、错误、兼容性）
- complaint: 投诉（不满、要求赔偿）
- greeting: 问候
- other: 其他

返回 JSON：
{
  "intent": "类别",
  "confidence": 0.9,
  "urgency": "low|medium|high",
  "needs_human": false,
  "summary": "一句话概括用户问题"
}`;
```

### 2.2 路由逻辑

```javascript
const classification = $input.first().json;

const routes = {
  faq: 'rag_answer',
  order: 'agent_tool',
  billing: 'agent_tool',
  technical: 'rag_answer',
  complaint: 'human_transfer',
  greeting: 'auto_reply',
  other: 'human_transfer'
};

const route = routes[classification.intent] || 'human_transfer';

// 紧急问题直接转人工
if (classification.urgency === 'high') {
  return [{ json: { ...classification, route: 'human_transfer', reason: '紧急问题' } }];
}

return [{ json: { ...classification, route } }];
```

## 三、RAG 知识库

### 3.1 知识库内容

| 类别 | 内容 | 更新频率 |
|------|------|---------|
| 产品文档 | 功能说明、操作指南 | 产品更新时 |
| FAQ | 常见问题和答案 | 每周 |
| 政策 | 退款、隐私、服务条款 | 政策变更时 |
| 故障排除 | 常见错误和解决方案 | 持续更新 |

### 3.2 检索流程

```
用户问题
    ↓
OpenAI Embedding（向量化）
    ↓
Pinecone（语义检索 Top 3）
    ↓
相关度过滤（score > 0.7）
    ├─ 有相关结果 → 组装 Prompt
    └─ 无相关结果 → 转人工
    ↓
OpenAI（生成回答）
```

### 3.3 RAG Prompt

```javascript
const prompt = `你是客服助手。基于以下知识库内容回答用户问题。

规则：
1. 只使用知识库中的信息回答
2. 如果知识库中没有相关信息，说"我需要转接人工客服为您处理"
3. 回答要简洁友好
4. 如果有操作步骤，列出清晰的步骤

知识库：
${context}

用户问题：${question}

回答：`;
```

## 五、人工转接

### 5.1 转接条件

| 条件 | 说明 |
|------|------|
| AI 置信度低 | < 0.6 |
| 用户要求转人工 | 明确说"转人工" |
| 投诉/紧急 | 情绪激动或紧急问题 |
| 敏感操作 | 退款、删除等不可逆操作 |
| 多轮未解决 | 3 轮对话未解决 |

### 5.2 转接流程

```
触发转接
    ↓
生成转接摘要（AI 总结对话）
    ↓
Slack 通知客服
    ↓
客服接管对话
```

转接摘要：

```javascript
const prompt = `总结以下客服对话，生成转接摘要供人工客服参考。

对话历史：
${history}

生成 JSON：
{
  "summary": "问题摘要",
  "customer_sentiment": "情绪",
  "attempted_solutions": ["已尝试的方案"],
  "pending_action": "待处理事项",
  "urgency": "优先级"
}`;
```

## 六、质量评估

### 6.1 自动评估

```javascript
const prompt = `评估客服回答的质量。

用户问题：${question}
AI 回答：${answer}
知识库内容：${context}

评估维度（1-10）：
1. 准确性：回答是否正确
2. 完整性：是否完整回答了问题
3. 友好度：语气是否友好专业
4. 有用性：是否真正帮助了用户

返回 JSON：
{
  "accuracy": 9,
  "completeness": 8,
  "friendliness": 9,
  "usefulness": 8,
  "overall": 8.5,
  "issues": []
}`;
```

### 6.2 用户满意度

```
对话结束后发送满意度调查：
"本次服务是否解决了您的问题？
😊 解决了
😐 部分解决
😞 未解决"
```

### 6.3 监控指标

| 指标 | 目标 | 计算方式 |
|------|------|---------|
| AI 解决率 | >= 70% | AI 直接解决 / 总对话 |
| 平均响应时间 | < 30 秒 | 从收到消息到发送回答 |
| 用户满意度 | >= 80% | 满意 / 总调查 |
| 转人工率 | <= 30% | 转人工 / 总对话 |

## 七、完整工作流

### 7.1 主流程

```
Webhook（用户消息）
    ↓
Code（预处理）
    ↓
OpenAI（意图识别）
    ↓
Code（路由判断）
    ↓
Switch（路由）
    ├─ rag_answer → RAG 检索 → AI 回答
    ├─ agent_tool → Agent 执行 → 返回结果
    ├─ auto_reply → 固定回复
    └─ human_transfer → 转人工
    ↓
Code（质量检查）
    ↓
IF（质量通过？）
    ├─ 是 → 发送回答
    └─ 否 → 转人工
    ↓
数据库（记录对话）
```

### 7.2 对话管理

```javascript
// 会话状态管理
const sessionId = $input.first().json.session_id;
const staticData = $getWorkflowStaticData('global');

if (!staticData.sessions) {
  staticData.sessions = {};
}

if (!staticData.sessions[sessionId]) {
  staticData.sessions[sessionId] = {
    messages: [],
    context: {},
    turn_count: 0
  };
}

const session = staticData.sessions[sessionId];
session.messages.push({
  role: 'user',
  content: $input.first().json.message,
  timestamp: new Date().toISOString()
});
session.turn_count++;

return [{
  json: {
    ...$input.first().json,
    history: session.messages.slice(-10), // 最近 10 条
    turn_count: session.turn_count
  }
}];
```

## 常见误区

### 误区一："AI 能处理所有问题"

AI 适合处理标准化、有明确答案的问题。复杂、个性化、情绪化的问题需要人工处理。

### 误区二："不需要监控 AI 回答质量"

AI 可能产生不准确或不恰当的回答。必须有质量检查和人工兜底。

### 误区三："转人工是失败"

智能转人工是系统设计的一部分。把正确的问题在正确的时间转给正确的人，是高效客服的关键。

---

## 工程建议

1. **渐进式上线**：先用 AI 处理最简单的问题，逐步扩大范围。
2. **持续优化知识库**：根据用户反馈更新 FAQ 和文档。
3. **监控 AI 表现**：跟踪准确率、解决率、满意度。
4. **保留人工兜底**：AI 处理不了的必须能快速转人工。
5. **保护用户隐私**：AI 处理的数据要脱敏，不要记录敏感信息。

---

## 小结

- AI 客服系统包括意图识别、RAG 检索、Agent 工具调用和人工转接
- 意图识别决定消息路由：自动回复、工具调用或转人工
- RAG 提供基于知识库的准确回答
- Agent 可以执行操作，但敏感操作需要人工确认
- 质量评估和监控是系统持续改进的关键
