# 第一课：条件分支与循环

> **课程定位**：掌握 n8n 的高级编排能力——条件判断、分支选择和循环处理
> **前置知识**：已完成 n8n 基础课程，了解 IF 节点和数据映射
> **预计时长**：35 分钟

---

## 场景引入

你的订单处理工作流需要根据订单金额走不同审批路径：1000 元以下自动通过，1000-5000 元需要经理审批，5000 元以上需要总监审批。同时，每个订单可能包含多个商品，需要逐个检查库存。一个简单的线性工作流已经无法满足需求，你需要条件分支和循环。

## 一、条件分支

### 1.1 IF 节点进阶

IF 节点支持多条件组合：

```json
{
  "conditions": {
    "combinator": "AND",
    "conditions": [
      {
        "leftValue": "={{ $json.amount }}",
        "rightValue": 1000,
        "operator": { "type": "number", "operation": "gt" }
      },
      {
        "leftValue": "={{ $json.status }}",
        "rightValue": "pending",
        "operator": { "type": "string", "operation": "equals" }
      }
    ]
  }
}
```

条件组合：

| 组合器 | 说明 | 例子 |
|--------|------|------|
| AND | 所有条件都满足 | 金额 > 1000 AND 状态 = pending |
| OR | 任一条件满足 | 金额 > 5000 OR 优先级 = high |

### 1.2 Switch 节点

当有多个分支时，用 Switch 比嵌套 IF 更清晰：

```
Switch（按 category 分支）
    ├─ electronics → 电子产品处理
    ├─ clothing   → 服装处理
    ├─ food       → 食品处理
    └─ default    → 默认处理
```

Switch 配置：

```json
{
  "dataType": "string",
  "value1": "={{ $json.category }}",
  "rules": {
    "rules": [
      { "value": "electronics", "output": 0 },
      { "value": "clothing", "output": 1 },
      { "value": "food", "output": 2 }
    ]
  },
  "fallbackOutput": 3
}
```

### 1.3 多级审批路由

实现金额分级审批：

```
Switch（按金额分级）
    ├─ < 1000    → 自动通过
    ├─ 1000-5000 → 经理审批
    ├─ > 5000    → 总监审批
    └─ default   → 人工审核
```

Code 节点实现分级逻辑：

```javascript
const amount = $input.first().json.amount;

let level;
if (amount < 1000) {
  level = 'auto_approve';
} else if (amount < 5000) {
  level = 'manager_review';
} else {
  level = 'director_review';
}

return [{
  json: {
    ...$input.first().json,
    approval_level: level,
    requires_review: level !== 'auto_approve'
  }
}];
```

## 二、循环处理

### 2.1 Loop 节点

Loop 节点逐个处理数组中的元素：

```
Input Array: [item1, item2, item3]
    ↓
Loop（逐个处理）
    ├─ 处理 item1 → 输出结果1
    ├─ 处理 item2 → 输出结果2
    └─ 处理 item3 → 输出结果3
    ↓
Output: [result1, result2, result3]
```

配置 Loop 节点：

1. 添加 Loop Over Items 节点
2. 设置 Batch Size（每批处理数量）
3. 在循环体内添加处理节点
4. 循环结束后自动聚合结果

### 2.2 批量处理 vs 逐条处理

| 方式 | 适用场景 | 优点 | 缺点 |
|------|---------|------|------|
| 逐条处理 | 需要独立错误处理 | 隔离性好 | 速度慢 |
| 批量处理 | 性能要求高 | 速度快 | 错误影响大 |
| 分批处理 | 大量数据 | 平衡速度和稳定性 | 配置复杂 |

### 2.3 循环中的错误处理

```javascript
// 在循环体内处理单条错误
const item = $input.first().json;

try {
  const result = await processItem(item);
  return [{ json: { success: true, ...result } }];
} catch (error) {
  return [{ json: { success: false, error: error.message, ...item } }];
}
```

## 三、Split 与 Merge

### 3.1 Split In Batches 节点

把大数据集拆分成小批次：

```
1000 条数据
    ↓
Split In Batches（每批 100 条）
    ↓
循环处理每批
    ├─ 批次 1（100 条）
    ├─ 批次 2（100 条）
    └─ ...
    ↓
聚合结果
```

### 3.2 Merge 节点

Merge 节点用于合并多个数据流：

**三种合并模式：**

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| Append | 简单拼接 | 合并同类数据 |
| Keep Key Matches | 按键匹配 | 关联两个数据源 |
| Merge By Index | 按索引合并 | 并行处理结果合并 |

**Append 模式：**
```
数据流 A: [a1, a2]
数据流 B: [b1, b2]
    ↓ Merge (Append)
结果: [a1, a2, b1, b2]
```

**Keep Key Matches 模式：**
```
数据流 A: [{id: 1, name: "张三"}, {id: 2, name: "李四"}]
数据流 B: [{id: 1, order: "ORD-001"}, {id: 3, order: "ORD-003"}]
    ↓ Merge (Keep Key Matches, key: id)
结果: [{id: 1, name: "张三", order: "ORD-001"}]
```

### 3.3 并行处理模式

使用 Split 和 Merge 实现并行处理：

```
输入数据
    ↓
Split（拆分成多个分支）
    ├─ 分支 A：处理类型 1
    ├─ 分支 B：处理类型 2
    └─ 分支 C：处理类型 3
    ↓
Merge（合并结果）
    ↓
后续处理
```

## 四、实战：订单审批路由

### 4.1 需求分析

```
订单输入
    ↓
数据验证
    ├─ 无效 → 拒绝
    ↓
库存检查
    ├─ 不足 → 通知采购 + 拒绝
    ↓
金额分级
    ├─ < 1000    → 自动通过 → 确认邮件
    ├─ 1000-5000 → 经理审批 → 等待 → 结果通知
    └─ > 5000    → 总监审批 → 等待 → 结果通知
    ↓
更新数据库
```

### 4.2 实现

**Step 1：Webhook 接收订单**

```json
{
  "order_id": "ORD-001",
  "customer": "张三",
  "items": [
    {"product": "笔记本电脑", "qty": 1, "price": 5999},
    {"product": "鼠标", "qty": 2, "price": 99}
  ],
  "total": 6197
}
```

**Step 2：Code 节点计算总额和分级**

```javascript
const order = $input.first().json;

const total = order.items.reduce((sum, item) => sum + (item.price * item.qty), 0);

let approval_level;
if (total < 1000) {
  approval_level = 'auto';
} else if (total < 5000) {
  approval_level = 'manager';
} else {
  approval_level = 'director';
}

return [{
  json: {
    ...order,
    calculated_total: total,
    approval_level: approval_level,
    item_count: order.items.length
  }
}];
```

**Step 3：Switch 按审批级别路由**

```
Switch（approval_level）
    ├─ auto     → 自动通过
    ├─ manager  → 发送经理审批请求
    └─ director → 发送总监审批请求
```

**Step 4：Loop 检查库存**

```
Loop Over Items（遍历订单项）
    ↓
HTTP Request（检查库存 API）
    ↓
IF（库存充足？）
    ├─ 允许 → 继续
    └─ 不足 → 标记缺货
```

## 五、高级模式

### 5.1 人工审批工作流

n8n 支持等待人工审批的模式：

```
发送审批请求
    ↓
Wait 节点（等待 Webhook 回调）
    ↓
处理审批结果
```

Wait 节点配置：

```json
{
  "resume": "webhook",
  "webhookPath": "approve/{{ $json.order_id }}",
  "responseMode": "responseNode"
}
```

审批链接：`http://localhost:5678/webhook/approve/ORD-001`

### 5.2 递归处理

处理树形结构数据：

```javascript
// 递归展开嵌套分类
function flattenCategories(categories, parent = '') {
  const result = [];
  for (const cat of categories) {
    result.push({
      id: cat.id,
      name: cat.name,
      parent: parent,
      path: parent ? `${parent}/${cat.name}` : cat.name
    });
    if (cat.children && cat.children.length > 0) {
      result.push(...flattenCategories(cat.children, cat.name));
    }
  }
  return result;
}

const flattened = flattenCategories($input.first().json.categories);
return flattened.map(item => ({ json: item }));
```

## 常见误区

### 误区一："Switch 节点的分支必须全部连接"

Switch 节点的分支可以不全部连接。未连接的分支会被跳过，不会报错。但建议用 fallback 分支处理未匹配的情况。

### 误区二："循环中不能异步操作"

n8n 的循环节点支持异步操作。在 Code 节点中可以使用 `await` 调用异步函数。

### 误区三："Merge 节点只能合并两个数据流"

Merge 节点可以连接多个输入。在编辑器中，点击 Merge 节点的输入端口可以添加更多连接。

---

## 工程建议

1. **Switch 优于嵌套 IF**：超过 3 个分支时，用 Switch 节点更清晰。
2. **循环中处理错误**：单条失败不应该影响整个批次。在循环体内捕获错误。
3. **大数组用分批处理**：超过 100 条数据时，用 Split In Batches 分批处理。
4. **并行处理提升性能**：独立的处理分支可以并行执行，减少总耗时。
5. **审批流程要有超时**：人工审批应该设置超时时间，避免流程卡住。

---

## 小结

- IF 节点适合二元判断，Switch 节点适合多分支路由
- Loop 节点逐个处理数组元素，Split In Batches 用于大数组分批
- Merge 节点支持 Append、Key Match 和 Index Match 三种合并模式
- 并行分支 + Merge 可以显著提升处理效率
- 人工审批通过 Wait 节点 + Webhook 回调实现

## 参考答案

### 练习一

**思路**：用 Switch 节点按分数范围路由。

**答案**：

1. **Webhook**：POST /check-grade
2. **Code 节点**：
   ```javascript
   const score = $input.first().json.score;
   let grade;
   if (score >= 90) grade = 'excellent';
   else if (score >= 60) grade = 'pass';
   else grade = 'fail';
   
   return [{ json: { ...$input.first().json, grade } }];
   ```
3. **Switch**：按 grade 分支
   - excellent → "🎉 优秀！得分：{score}"
   - pass → "✅ 及格。得分：{score}"
   - fail → "❌ 不及格。得分：{score}"

**要点**：
- Code 节点预处理数据，Switch 节点做路由
- fallback 分支处理异常值（如负数）

### 练习二

**思路**：用 Loop 节点遍历订单数组，Code 节点做计算和统计。

**答案**：

1. **Webhook**：接收订单数组
2. **Split In Batches**：Batch Size = 5
3. **Code 节点**（循环体内）：
   ```javascript
   const order = $input.first().json;
   const total = order.items.reduce((sum, item) => sum + item.price * item.qty, 0);
   return [{ json: { order_id: order.order_id, total, item_count: order.items.length } }];
   ```
4. **聚合后 Code 节点**：
   ```javascript
   const orders = $input.all();
   return [{
     json: {
       total_orders: orders.length,
       total_amount: orders.reduce((sum, o) => sum + o.json.total, 0),
       average_amount: orders.reduce((sum, o) => sum + o.json.total, 0) / orders.length
     }
   }];
   ```

### 练习三

**思路**：用两个 Webhook 分别接收数据，Merge 节点按 customer_id 关联。

**答案**：

1. **Webhook 1**：/customers → [{customer_id: 1, name: "张三"}, ...]
2. **Webhook 2**：/orders → [{customer_id: 1, order_id: "ORD-001"}, ...]
3. **Merge**：
   - Mode: Keep Key Matches
   - Join By: customer_id
4. **Set**：格式化输出

**要点**：
- Merge 的 Key Match 模式类似 SQL 的 INNER JOIN
- 只有关联键匹配的数据才会出现在输出中
