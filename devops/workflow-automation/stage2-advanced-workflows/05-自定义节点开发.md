# 第五课：自定义节点开发

> **课程定位**：当内置节点无法满足需求时，用 TypeScript 开发自定义 n8n 节点
> **前置知识**：了解 TypeScript 基础，有 npm 包开发经验
> **预计时长**：40 分钟

---

## 场景引入

你的工作流需要调用公司内部的 API，但 n8n 没有对应的内置节点。你用 HTTP Request 节点可以实现，但每次都要手动配置 URL、Headers、认证，而且不能复用。你想要一个像内置节点一样好用的自定义节点：有可视化配置面板、有认证支持、有错误处理。

---

## 学习目标

完成本课学习后，你将能够：

1. 理解 n8n 节点的架构和类型
2. 用 TypeScript 创建一个自定义节点
3. 定义节点的属性、操作和认证
4. 打包和部署自定义节点

## 一、n8n 节点架构

### 1.1 节点类型

| 类型 | 说明 | 例子 |
|------|------|------|
| Trigger | 触发器节点 | Webhook、Schedule |
| Action | 动作节点 | HTTP Request、Set |
| Cluster | 节点组 | AI Agent（包含多个子节点） |

### 1.2 节点结构

```
n8n-nodes-my-service/
├── package.json
├── tsconfig.json
├── credentials/
│   └── MyServiceApi.credentials.ts
├── nodes/
│   └── MyService/
│       ├── MyService.node.ts
│       └── myService.svg
└── index.ts
```

### 1.3 核心文件

| 文件 | 作用 |
|------|------|
| `*.node.ts` | 节点逻辑 |
| `*.credentials.ts` | 认证配置 |
| `package.json` | 包信息和 n8n 声明 |
| `*.svg` | 节点图标 |

```typescript
// src/credentials/MyServiceApi.credentials.ts
import {
  IAuthenticateGeneric,
  ICredentialType,
  INodeProperties,
} from 'n8n-workflow';

export class MyServiceApi implements ICredentialType {
  name = 'myServiceApi';
  displayName = 'My Service API';
  documentationUrl = 'https://docs.myservice.com/api';

  properties: INodeProperties[] = [
    {
      displayName: 'API Key',
      name: 'apiKey',
      type: 'string',
      typeOptions: { password: true },
      default: '',
      required: true,
    },
    {
      displayName: 'Base URL',
      name: 'baseUrl',
      type: 'string',
      default: 'https://api.myservice.com',
      description: 'API 基础地址',
    },
  ];

  authenticate: IAuthenticateGeneric = {
    type: 'generic',
    properties: {
      headers: {
        Authorization: '=Bearer {{$credentials.apiKey}}',
      },
    },
  };
}
```

## 四、实现节点逻辑

### 4.1 基本节点结构

```typescript
// src/nodes/MyService/MyService.node.ts
import {
  IExecuteFunctions,
  INodeExecutionData,
  INodeType,
  INodeTypeDescription,
  NodeOperationError,
} from 'n8n-workflow';

export class MyService implements INodeType {
  description: INodeTypeDescription = {
    displayName: 'My Service',
    name: 'myService',
    icon: 'file:myService.svg',
    group: ['transform'],
    version: 1,
    subtitle: '={{ $parameter["operation"] }}',
    description: '与 My Service API 交互',
    defaults: {
      name: 'My Service',
    },
    inputs: ['main'],
    outputs: ['main'],
    credentials: [
      {
        name: 'myServiceApi',
        required: true,
      },
    ],
    properties: [
      // 节点配置属性
      {
        displayName: 'Operation',
        name: 'operation',
        type: 'options',
        noDataExpression: true,
        options: [
          {
            name: 'Create',
            value: 'create',
            description: '创建记录',
            action: '创建记录',
          },
          {
            name: 'Get',
            value: 'get',
            description: '获取记录',
            action: '获取记录',
          },
          {
            name: 'Get Many',
            value: 'getAll',
            description: '获取多条记录',
            action: '获取多条记录',
          },
          {
            name: 'Update',
            value: 'update',
            description: '更新记录',
            action: '更新记录',
          },
        ],
        default: 'get',
      },
      {
        displayName: 'Resource',
        name: 'resource',
        type: 'options',
        noDataExpression: true,
        options: [
          { name: 'Customer', value: 'customer' },
          { name: 'Order', value: 'order' },
        ],
        default: 'customer',
      },
      {
        displayName: 'Customer ID',
        name: 'customerId',
        type: 'string',
        default: '',
        displayOptions: {
          show: {
            operation: ['get', 'update'],
            resource: ['customer'],
          },
        },
        required: true,
      },
    ],
  };

  async execute(this: IExecuteFunctions): Promise<INodeExecutionData[][]> {
    const items = this.getInputData();
    const results: INodeExecutionData[] = [];

    const credentials = await this.getCredentials('myServiceApi');
    const baseUrl = credentials.baseUrl as string;

    const operation = this.getNodeParameter('operation', 0) as string;
    const resource = this.getNodeParameter('resource', 0) as string;

    for (let i = 0; i < items.length; i++) {
      try {
        let response;

        if (resource === 'customer') {
          if (operation === 'get') {
            const customerId = this.getNodeParameter('customerId', i) as string;
            response = await this.helpers.httpRequest({
              method: 'GET',
              url: `${baseUrl}/customers/${customerId}`,
              headers: {
                Authorization: `Bearer ${credentials.apiKey}`,
              },
            });
          } else if (operation === 'create') {
            response = await this.helpers.httpRequest({
              method: 'POST',
              url: `${baseUrl}/customers`,
              body: items[i].json,
              headers: {
                Authorization: `Bearer ${credentials.apiKey}`,
              },
            });
          }
        }

        results.push({ json: response as object });
      } catch (error) {
        if (this.continueOnFail()) {
          results.push({
            json: { error: (error as Error).message },
          });
          continue;
        }
        throw new NodeOperationError(this.getNode(), error as Error, { itemIndex: i });
      }
    }

    return [results];
  }
}
```

## 常见误区

### 误区一："自定义节点比 HTTP Request 好"

自定义节点适合高频复用的场景。如果只是偶尔调用一个 API，HTTP Request 节点更简单。

### 误区二："节点发布后不能修改"

可以修改，但需要考虑向后兼容性。新增属性要有默认值，不能删除已有的属性。

### 误区三："自定义节点必须发布到 npm"

可以只在本地使用。通过 npm link 或直接放在 n8n 的 custom 目录中。

---

## 工程建议

1. **先用 HTTP Request 验证**：先用 HTTP Request 节点验证 API 能正常工作，再封装成自定义节点。
2. **文档要完善**：每个属性都要有 description，方便使用者理解。
3. **错误信息要友好**：抛出 NodeOperationError 时包含足够的上下文。
4. **支持批量操作**：用 for 循环处理多个输入项。
5. **考虑 continueOnFail**：在循环中检查 this.continueOnFail()，允许跳过失败的项。

## 小结

- 自定义节点由 TypeScript 实现，包含节点逻辑和凭证定义
- 节点通过 INodeTypeDescription 定义属性、操作和认证
- 支持 API Key 和 OAuth2 等多种认证方式
- 可以通过 npm 发布或本地链接部署
- 自定义节点适合高频复用的 API 集成
