## 一、性能瓶颈分析

### 1.1 常见瓶颈

| 瓶颈 | 表现 | 原因 |
|------|------|------|
| 外部 API | 执行时间长 | 网络延迟、API 限流 |
| 数据库 | 查询慢 | 缺少索引、查询复杂 |
| 大数据量 | 内存溢出 | 一次性加载过多数据 |
| 循环处理 | 逐条处理慢 | 没有批量操作 |

### 1.2 性能监控

```javascript
// Code 节点：记录执行时间
const start = Date.now();

// 执行逻辑
const result = await processData();

const duration = Date.now() - start;

return [{
  json: {
    ...result,
    performance: {
      duration_ms: duration,
      items_processed: result.count,
      items_per_second: Math.round(result.count / (duration / 1000))
    }
  }
}];
```

## 二、数据处理优化

### 2.1 批量操作

逐条 vs 批量：

```javascript
// 逐条插入（慢）
for (const item of items) {
  await db.query('INSERT INTO orders VALUES ($1, $2)', [item.id, item.amount]);
}

// 批量插入（快）
const values = items.map((item, i) => `($${i*2+1}, $${i*2+2})`).join(', ');
const params = items.flatMap(item => [item.id, item.amount]);
await db.query(`INSERT INTO orders VALUES ${values}`, params);
```

### 2.2 并行处理

```javascript
// 串行处理（慢）
for (const item of items) {
  await processItem(item);
}

// 并行处理（快）
const batchSize = 10;
for (let i = 0; i < items.length; i += batchSize) {
  const batch = items.slice(i, i + batchSize);
  await Promise.all(batch.map(item => processItem(item)));
}
```

### 2.3 流式处理

大数据量时不一次性加载到内存：

```javascript
// Code 节点：流式处理
const stream = await db.query('SELECT * FROM large_table');

for await (const row of stream) {
  // 逐行处理，不占用大量内存
  await processRow(row);
}
```

## 三、内存优化

### 3.1 避免大数组

```javascript
// 不好：一次性加载所有数据
const allData = await db.query('SELECT * FROM orders');
const results = allData.map(row => processRow(row));

// 好：分批处理
let offset = 0;
const limit = 100;
while (true) {
  const batch = await db.query('SELECT * FROM orders LIMIT $1 OFFSET $2', [limit, offset]);
  if (batch.length === 0) break;
  
  for (const row of batch) {
    await processRow(row);
  }
  
  offset += limit;
}
```

### 3.2 清理不需要的数据

```javascript
// Code 节点：只保留需要的字段
const items = $input.all();

return items.map(item => ({
  json: {
    id: item.json.id,
    amount: item.json.amount,
    status: item.json.status
    // 不传递不需要的字段
  }
}));
```

### 3.3 内存监控

```javascript
// Code 节点：监控内存使用
const memUsage = process.memoryUsage();

return [{
  json: {
    heap_used_mb: Math.round(memUsage.heapUsed / 1024 / 1024),
    heap_total_mb: Math.round(memUsage.heapTotal / 1024 / 1024),
    rss_mb: Math.round(memUsage.rss / 1024 / 1024)
  }
}];
```

## 四、并发控制

### 4.1 n8n 并发配置

```bash
# 环境变量
EXECUTIONS_PROCESS=main
EXECUTIONS_MODE=regular
N8N_CONCURRENCY_PRODUCTION=10
N8N_CONCURRENCY_DEVELOPMENT=1
```

### 4.2 工作流级并发

```javascript
// Code 节点：限制并发数
class ConcurrencyLimiter {
  constructor(limit) {
    this.limit = limit;
    this.running = 0;
    this.queue = [];
  }
  
  async run(fn) {
    if (this.running >= this.limit) {
      await new Promise(resolve => this.queue.push(resolve));
    }
    this.running++;
    try {
      return await fn();
    } finally {
      this.running--;
      if (this.queue.length > 0) {
        this.queue.shift()();
      }
    }
  }
}

const limiter = new ConcurrencyLimiter(5);
const items = $input.all();

const results = await Promise.all(
  items.map(item => limiter.run(() => processItem(item.json)))
);

return results.map(r => ({ json: r }));
```

### 4.3 API 限流

```javascript
// Code 节点：API 限流
const RATE_LIMIT = 10; // 每秒 10 次
const INTERVAL = 1000 / RATE_LIMIT;

const items = $input.all();
const results = [];

for (const item of items) {
  const start = Date.now();
  
  try {
    const result = await callAPI(item.json);
    results.push({ json: { success: true, ...result } });
  } catch (error) {
    if (error.status === 429) {
      // 限流，等待后重试
      await new Promise(r => setTimeout(r, 5000));
      // 重试逻辑...
    }
    results.push({ json: { success: false, error: error.message } });
  }
  
  // 频率控制
  const elapsed = Date.now() - start;
  if (elapsed < INTERVAL) {
    await new Promise(r => setTimeout(r, INTERVAL - elapsed));
  }
}

return results;
```

## 五、数据库优化

### 5.1 查询优化

```sql
-- 不好：全表扫描
SELECT * FROM orders WHERE status = 'pending';

-- 好：使用索引
CREATE INDEX idx_orders_status ON orders(status);
SELECT * FROM orders WHERE status = 'pending';

-- 不好：N+1 查询
for each customer:
  SELECT * FROM orders WHERE customer_id = ?;

-- 好：批量查询
SELECT * FROM orders WHERE customer_id IN (1, 2, 3, ...);
```

### 5.2 连接池

```javascript
// 使用连接池
const { Pool } = require('pg');

const pool = new Pool({
  host: 'localhost',
  database: 'mydb',
  max: 20, // 最大连接数
  idleTimeoutMillis: 30000
});

// 查询
const result = await pool.query('SELECT * FROM orders');
```

### 5.3 缓存

```javascript
// Code 节点：简单缓存
const staticData = $getWorkflowStaticData('global');

if (!staticData.cache) {
  staticData.cache = {};
}

const cacheKey = `query_${JSON.stringify(params)}`;
const cached = staticData.cache[cacheKey];

if (cached && Date.now() - cached.timestamp < 300000) { // 5 分钟缓存
  return cached.data;
}

const result = await db.query(query, params);
staticData.cache[cacheKey] = { data: result, timestamp: Date.now() };

return result;
```

## 六、实战：大数据量优化

### 6.1 优化前

```
10000 条记录 → 逐条处理 → 每条 100ms → 总计 1000 秒
```

### 6.2 优化后

```
10000 条记录 → 分批 100 条 → 并行 10 个 → 每批 100ms → 总计 100 秒
```

### 6.3 实现

```javascript
const items = $input.all();
const BATCH_SIZE = 100;
const CONCURRENCY = 10;

const results = [];

for (let i = 0; i < items.length; i += BATCH_SIZE * CONCURRENCY) {
  const batches = [];
  
  for (let j = 0; j < CONCURRENCY && i + j * BATCH_SIZE < items.length; j++) {
    const batch = items.slice(i + j * BATCH_SIZE, i + (j + 1) * BATCH_SIZE);
    batches.push(processBatch(batch));
  }
  
  const batchResults = await Promise.all(batches);
  results.push(...batchResults.flat());
}

return results;
```

## 常见误区

### 误区一："优化一次就够了"

性能会随着数据量增长而退化。需要持续监控和优化。

### 误区二："并行总是更快"

过多的并行会导致资源竞争和限流。需要找到合适的并发数。

### 误区三："缓存能解决所有问题"

缓存增加了复杂性，且可能导致数据不一致。只在读多写少的场景使用。

---

## 工程建议

1. **批量操作**：数据库和 API 操作尽量批量。
2. **监控性能**：记录每个工作流的执行时间。
3. **设置超时**：防止工作流无限执行。
4. **定期清理**：清理旧的执行日志和临时数据。
5. **压力测试**：上线前做性能压力测试。

---

## 小结

- 性能瓶颈通常在外部 API、数据库和大数据量处理
- 批量操作、并行处理、流式处理是主要优化手段
- 内存优化包括避免大数组、清理不需要的数据
- 并发控制防止资源耗尽和 API 限流
- 数据库优化包括索引、连接池和缓存
