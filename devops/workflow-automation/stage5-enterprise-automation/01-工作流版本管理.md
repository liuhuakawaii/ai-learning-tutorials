# 工作流版本管理

## 一个改不回去的事故

你的团队有 3 个人同时在修改工作流。有人改了一个通知模板，导致生产环境的客户收不到邮件。你想回滚到昨天的版本，但 n8n 没有内置版本控制系统。编辑器的撤销只在当前会话有效，关了浏览器就没了。

你需要一套手动的版本管理方案：用 n8n API 导入导出工作流，用 Git 追踪变更历史。

## n8n API：导入导出的基础

启用 API：

```bash
# 环境变量
N8N_PUBLIC_API_DISABLED=false
N8N_API_KEY=your-api-key
```

导出工作流：

```bash
# 列出所有工作流
curl http://localhost:5678/api/v1/workflows \
  -H "X-N8N-API-KEY: $N8N_API_KEY"

# 导出单个工作流
curl http://localhost:5678/api/v1/workflows/123 \
  -H "X-N8N-API-KEY: $N8N_API_KEY" \
  -o workflow-123.json
```

导入工作流：

```bash
# 创建新工作流
curl -X POST http://localhost:5678/api/v1/workflows \
  -H "X-N8N-API-KEY: $N8N_API_KEY" \
  -H "Content-Type: application/json" \
  -d @workflow-123.json

# 更新现有工作流
curl -X PUT http://localhost:5678/api/v1/workflows/123 \
  -H "X-N8N-API-KEY: $N8N_API_KEY" \
  -H "Content-Type: application/json" \
  -d @workflow-123.json
```

激活/停用：

```bash
curl -X PATCH http://localhost:5678/api/v1/workflows/123/activate \
  -H "X-N8N-API-KEY: $N8N_API_KEY"

curl -X PATCH http://localhost:5678/api/v1/workflows/123/deactivate \
  -H "X-N8N-API-KEY: $N8N_API_KEY"
```

## 自动导出脚本

```bash
#!/bin/bash
# scripts/export-workflows.sh

EXPORT_DIR="./workflows"
mkdir -p $EXPORT_DIR

WORKFLOWS=$(curl -s http://localhost:5678/api/v1/workflows \
  -H "X-N8N-API-KEY: $N8N_API_KEY" | jq -r '.data[].id')

for id in $WORKFLOWS; do
  curl -s "http://localhost:5678/api/v1/workflows/$id" \
    -H "X-N8N-API-KEY: $N8N_API_KEY" \
    | jq '.' > "$EXPORT_DIR/workflow-$id.json"
  echo "Exported workflow $id"
done

echo "Export complete: $(ls $EXPORT_DIR | wc -l) workflows"
```

## Git 版本控制

```bash
# 导出 + 提交
./scripts/export-workflows.sh
git add workflows/
git commit -m "feat: 更新工作流配置 $(date +%Y-%m-%d)"
git push
```

工作流 JSON 是纯文本，Git diff 能清晰看到节点配置的变化。

## 多环境管理

```
n8n-workflows/
├── environments/
│   ├── dev.json          # 开发环境配置
│   ├── staging.json      # 测试环境配置
│   └── prod.json         # 生产环境配置
├── workflows/
│   ├── workflow-1.json
│   └── workflow-2.json
└── scripts/
    ├── export.sh
    ├── import.sh
    └── deploy.sh
```

部署脚本做环境变量替换：

```bash
#!/bin/bash
# scripts/deploy.sh

ENV=$1  # dev, staging, prod
CONFIG=$(cat environments/$ENV.json)

for file in workflows/workflow-*.json; do
  sed -i "s|{{API_URL}}|$(echo $CONFIG | jq -r '.api_url')|g" "$file"
  sed -i "s|{{WEBHOOK_URL}}|$(echo $CONFIG | jq -r '.webhook_url')|g" "$file"
done

N8N_API_KEY=$(echo $CONFIG | jq -r '.api_key')
N8N_HOST=$(echo $CONFIG | jq -r '.host')
./scripts/import-workflows.sh
```

不同环境使用不同凭证，不要把生产 Key 提交到 Git。

## 回滚机制

```bash
#!/bin/bash
# scripts/rollback.sh

WORKFLOW_ID=$1
COMMIT_HASH=$2

# 从 Git 恢复
git checkout $COMMIT_HASH -- "workflows/workflow-$WORKFLOW_ID.json"

# 导入到 n8n
curl -X PUT "http://localhost:5678/api/v1/workflows/$WORKFLOW_ID" \
  -H "X-N8N-API-KEY: $N8N_API_KEY" \
  -H "Content-Type: application/json" \
  -d @"workflows/workflow-$WORKFLOW_ID.json"

echo "Rolled back workflow $WORKFLOW_ID to commit $COMMIT_HASH"
```

部署前先备份：

```bash
#!/bin/bash
BACKUP_DIR="./backups/$(date +%Y%m%d_%H%M%S)"
mkdir -p $BACKUP_DIR
./scripts/export-workflows.sh
cp -r workflows/ $BACKUP_DIR/
echo "Backup created at $BACKUP_DIR"
```

## CI/CD 集成

```yaml
# .github/workflows/deploy-n8n.yml
name: Deploy n8n Workflows
on:
  push:
    branches: [main]
    paths: ['workflows/**']

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Validate JSON
        run: |
          for file in workflows/workflow-*.json; do
            jq empty "$file" || exit 1
          done
      - name: Deploy to Production
        env:
          N8N_API_KEY: ${{ secrets.N8N_API_KEY }}
          N8N_HOST: ${{ secrets.N8N_HOST }}
        run: ./scripts/deploy.sh prod
```

## 练习

### 练习一：导出所有工作流

使用 n8n API 导出所有工作流，保存到 `./workflows/` 目录。写一个 bash 脚本，输出每个工作流的 ID、名称和是否激活。

### 练习二：Git 集成

初始化 Git 仓库，将导出的工作流纳入版本控制。修改一个工作流的节点配置，提交并查看 diff，确认 diff 可读。

### 练习三：回滚演练

修改一个工作流并部署到 n8n，然后用回滚脚本恢复到修改前的版本。验证 n8n 中的工作流已恢复。

## 参考答案

### 练习一

```bash
#!/bin/bash
export N8N_API_KEY="${N8N_API_KEY:-your-key}"

curl -s http://localhost:5678/api/v1/workflows \
  -H "X-N8N-API-KEY: $N8N_API_KEY" | \
  jq -r '.data[] | "\(.id)\t\(.name)\t\(.active)"'

# 导出
mkdir -p workflows
for id in $(curl -s http://localhost:5678/api/v1/workflows \
  -H "X-N8N-API-KEY: $N8N_API_KEY" | jq -r '.data[].id'); do
  curl -s "http://localhost:5678/api/v1/workflows/$id" \
    -H "X-N8N-API-KEY: $N8N_API_KEY" > "workflows/workflow-$id.json"
done
```

### 练习二

```bash
git init
git add workflows/
git commit -m "feat: 初始工作流配置"

# 在 n8n 编辑器中修改一个工作流
# 重新导出
./scripts/export-workflows.sh

# 查看变更
git diff workflows/
git commit -m "feat: 更新通知模板"
```

### 练习三

```bash
# 记录当前版本
git log --oneline workflows/ | head -1

# 在 n8n 中修改工作流
# 导出并提交
./scripts/export-workflows.sh
git add workflows/
git commit -m "feat: 新改动"

# 回滚到上一个版本
PREV_COMMIT=$(git log --oneline workflows/ | sed -n '2p' | cut -d' ' -f1)
./scripts/rollback.sh 123 $PREV_COMMIT
```
