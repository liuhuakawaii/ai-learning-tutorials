# 第一课：工作流版本管理

> **课程定位**：在 n8n 中实施工作流的版本控制、环境管理和回滚机制
> **前置知识**：了解 Git 基本操作
> **预计时长**：35 分钟

---

## 场景引入

你的团队有 3 个人同时在修改工作流。有人改了一个通知模板，导致生产环境的客户收不到邮件。你需要回滚到昨天的版本，但 n8n 没有内置的版本控制系统。你需要一套手动的版本管理方案。

## 一、n8n API

### 1.1 启用 API

```bash
# 环境变量
N8N_PUBLIC_API_DISABLED=false
N8N_API_KEY=your-api-key
```

### 1.2 导出工作流

```bash
# 列出所有工作流
curl http://localhost:5678/api/v1/workflows \
  -H "X-N8N-API-KEY: your-api-key"

# 导出单个工作流
curl http://localhost:5678/api/v1/workflows/123 \
  -H "X-N8N-API-KEY: your-api-key" \
  -o workflow-123.json
```

### 1.3 导入工作流

```bash
# 创建新工作流
curl -X POST http://localhost:5678/api/v1/workflows \
  -H "X-N8N-API-KEY: your-api-key" \
  -H "Content-Type: application/json" \
  -d @workflow-123.json

# 更新现有工作流
curl -X PUT http://localhost:5678/api/v1/workflows/123 \
  -H "X-N8N-API-KEY: your-api-key" \
  -H "Content-Type: application/json" \
  -d @workflow-123.json
```

### 1.4 激活/停用工作流

```bash
# 激活
curl -X PATCH http://localhost:5678/api/v1/workflows/123/activate \
  -H "X-N8N-API-KEY: your-api-key"

# 停用
curl -X PATCH http://localhost:5678/api/v1/workflows/123/deactivate \
  -H "X-N8N-API-KEY: your-api-key"
```

## 二、Git 版本控制

### 2.1 工作流导出脚本

```bash
#!/bin/bash
# scripts/export-workflows.sh

EXPORT_DIR="./workflows"
mkdir -p $EXPORT_DIR

# 获取所有工作流
WORKFLOWS=$(curl -s http://localhost:5678/api/v1/workflows \
  -H "X-N8N-API-KEY: $N8N_API_KEY" | jq -r '.data[].id')

for id in $WORKFLOWS; do
  curl -s "http://localhost:5678/api/v1/workflows/$id" \
    -H "X-N8N-API-KEY: $N8N_API_KEY" \
    | jq '.' > "$EXPORT_DIR/workflow-$id.json"
  echo "Exported workflow $id"
done

echo "Export complete: $(ls $EXPORT_DIR | wc -l) workflows"
```

### 2.2 Git 提交

```bash
# 导出工作流
./scripts/export-workflows.sh

# 提交到 Git
git add workflows/
git commit -m "feat: 更新工作流配置 $(date +%Y-%m-%d)"
git push
```

### 2.3 工作流导入脚本

```bash
#!/bin/bash
# scripts/import-workflows.sh

IMPORT_DIR="./workflows"

for file in $IMPORT_DIR/workflow-*.json; do
  id=$(jq -r '.id' "$file")
  
  # 检查工作流是否存在
  EXISTS=$(curl -s "http://localhost:5678/api/v1/workflows/$id" \
    -H "X-N8N-API-KEY: $N8N_API_KEY" | jq -r '.id')
  
  if [ "$EXISTS" = "$id" ]; then
    # 更新
    curl -X PUT "http://localhost:5678/api/v1/workflows/$id" \
      -H "X-N8N-API-KEY: $N8N_API_KEY" \
      -H "Content-Type: application/json" \
      -d @"$file"
    echo "Updated workflow $id"
  else
    # 创建
    curl -X POST "http://localhost:5678/api/v1/workflows" \
      -H "X-N8N-API-KEY: $N8N_API_KEY" \
      -H "Content-Type: application/json" \
      -d @"$file"
    echo "Created workflow from $file"
  fi
done
```

## 三、多环境管理

### 3.1 环境配置

```
n8n-workflows/
├── environments/
│   ├── dev.json          # 开发环境配置
│   ├── staging.json      # 测试环境配置
│   └── prod.json         # 生产环境配置
├── workflows/
│   ├── workflow-1.json
│   └── workflow-2.json
└── scripts/
    ├── export.sh
    ├── import.sh
    └── deploy.sh
```

### 3.2 环境变量替换

```bash
#!/bin/bash
# scripts/deploy.sh

ENV=$1  # dev, staging, prod

# 读取环境配置
CONFIG=$(cat environments/$ENV.json)

# 替换工作流中的环境变量
for file in workflows/workflow-*.json; do
  # 替换 API URL
  sed -i "s|{{API_URL}}|$(echo $CONFIG | jq -r '.api_url')|g" "$file"
  # 替换 Webhook URL
  sed -i "s|{{WEBHOOK_URL}}|$(echo $CONFIG | jq -r '.webhook_url')|g" "$file"
done

# 导入到目标环境
N8N_API_KEY=$(echo $CONFIG | jq -r '.api_key')
N8N_HOST=$(echo $CONFIG | jq -r '.host')
./scripts/import-workflows.sh
```

### 3.3 凭证管理

不同环境使用不同凭证：

```json
// environments/dev.json
{
  "api_url": "https://dev-api.example.com",
  "webhook_url": "https://dev-n8n.example.com/webhook",
  "api_key": "dev-key-xxxxx"
}

// environments/prod.json
{
  "api_url": "https://api.example.com",
  "webhook_url": "https://n8n.example.com/webhook",
  "api_key": "prod-key-xxxxx"
}
```

## 四、回滚机制

### 4.1 Git 回滚

```bash
# 查看历史版本
git log --oneline workflows/

# 回滚到指定版本
git checkout abc1234 -- workflows/workflow-1.json

# 重新导入
./scripts/import-workflows.sh
```

### 4.2 自动回滚脚本

```bash
#!/bin/bash
# scripts/rollback.sh

WORKFLOW_ID=$1
COMMIT_HASH=$2

# 从 Git 恢复工作流文件
git checkout $COMMIT_HASH -- "workflows/workflow-$WORKFLOW_ID.json"

# 导入到 n8n
curl -X PUT "http://localhost:5678/api/v1/workflows/$WORKFLOW_ID" \
  -H "X-N8N-API-KEY: $N8N_API_KEY" \
  -H "Content-Type: application/json" \
  -d @"workflows/workflow-$WORKFLOW_ID.json"

echo "Rolled back workflow $WORKFLOW_ID to commit $COMMIT_HASH"
```

### 4.3 回滚前备份

```bash
#!/bin/bash
# scripts/backup-before-deploy.sh

BACKUP_DIR="./backups/$(date +%Y%m%d_%H%M%S)"
mkdir -p $BACKUP_DIR

# 导出当前版本
./scripts/export-workflows.sh
cp -r workflows/ $BACKUP_DIR/

echo "Backup created at $BACKUP_DIR"
```

## 五、CI/CD 集成

### 5.1 GitHub Actions

```yaml
# .github/workflows/deploy-n8n.yml
name: Deploy n8n Workflows

on:
  push:
    branches: [main]
    paths:
      - 'workflows/**'

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Deploy to Production
        env:
          N8N_API_KEY: ${{ secrets.N8N_API_KEY }}
          N8N_HOST: ${{ secrets.N8N_HOST }}
        run: |
          ./scripts/deploy.sh prod
```

### 5.2 部署检查

```yaml
      - name: Validate Workflows
        run: |
          # 检查 JSON 格式
          for file in workflows/workflow-*.json; do
            jq empty "$file" || exit 1
          done
          echo "All workflows are valid JSON"
      
      - name: Run Tests
        run: |
          # 执行工作流测试
          ./scripts/test-workflows.sh
```

## 常见误区

### 误区一："n8n 的撤销功能够用了"

n8n 编辑器的撤销只在当前会话有效。关闭浏览器后撤销历史丢失。需要 Git 版本控制。

### 误区二："直接在生产环境修改工作流"

应该在开发环境修改、测试通过后再部署到生产环境。

### 误区三："不需要备份"

部署前必须备份当前版本，确保可以快速回滚。

## 工程建议

1. **每天自动导出**：用定时任务自动导出工作流到 Git。
2. **环境隔离**：开发、测试、生产使用不同的 n8n 实例。
3. **部署前备份**：每次部署前创建备份。
4. **代码审查**：工作流变更通过 PR 审查。
5. **回滚演练**：定期练习回滚操作。

- 多环境管理通过环境变量替换实现

```bash
git init

# 修改工作流后

```

### 练习三

**思路**：从 Git 历史恢复旧版本并导入。

**答案**：

```bash
# 查看历史
git log --oneline workflows/
# 回滚
git checkout HEAD~1 -- workflows/workflow-1.json
# 导入
curl -X PUT http://localhost:5678/api/v1/workflows/1 \
  -H "X-N8N-API-KEY: $N8N_API_KEY" \
  -d @workflows/workflow-1.json
```
