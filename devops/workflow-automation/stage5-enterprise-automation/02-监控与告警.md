## 一、n8n 执行监控

### 1.1 执行日志

n8n 自动记录每次执行的详细信息：

```bash
# 通过 API 查询执行记录
curl "http://localhost:5678/api/v1/executions?limit=100&status=error" \
  -H "X-N8N-API-KEY: your-api-key"
```

返回数据：

```json
{
  "data": [
    {
      "id": "exec_123",
      "workflowId": "wf_456",
      "status": "error",
      "startedAt": "2024-03-15T10:30:00Z",
      "stoppedAt": "2024-03-15T10:30:05Z",
      "mode": "trigger",
      "finished": true
    }
  ]
}
```

### 1.2 Error Trigger 监控

在每个关键工作流中添加 Error Trigger：

```
Error Trigger
    ↓
Code（格式化告警信息）
    ↓
Slack（发送告警）
    ↓
数据库（记录错误日志）
```

### 1.3 定期健康检查

```json
{
  "resource": "execution",
  "operation": "getAll",
  "filters": {
    "status": "error",
    "startedAfter": "={{ $now.minus({ minutes: 5 }).toISO() }}"
  }
}
```

## 二、告警通知

### 2.1 告警级别

| 级别 | 条件 | 通知方式 |
|------|------|---------|
| Critical | 核心工作流失败 | 立即电话/短信 |
| Error | 一般工作流失败 | Slack + 邮件 |
| Warning | 执行时间超标 | Slack |
| Info | 统计信息 | 每日汇总邮件 |

### 2.2 告警消息模板

```javascript
// Code 节点：格式化告警
const error = $input.first().json;

const level = error.workflow.critical ? '🔴 CRITICAL' : '🟠 ERROR';

const message = `${level} 工作流执行失败

工作流：${error.workflow.name}
节点：${error.error.node}
错误：${error.error.message}
时间：${DateTime.fromISO(error.startedAt).toFormat('yyyy-MM-dd HH:mm:ss')}
执行ID：${error.id}

查看详情：${process.env.N8N_HOST}/executions/${error.id}`;

return [{
  json: {
    text: message,
    channel: error.workflow.critical ? '#alerts-critical' : '#alerts'
  }
}];
```

### 2.3 告警去重

避免同一问题重复告警：

```javascript
// Code 节点：告警去重
const alert = $input.first().json;
const staticData = $getWorkflowStaticData('global');

if (!staticData.alerts) {
  staticData.alerts = {};
}

const key = `${alert.workflow_id}_${alert.error_type}`;
const lastAlert = staticData.alerts[key];

// 5 分钟内相同告警不重复发送
if (lastAlert && (Date.now() - lastAlert) < 300000) {
  return [{ json: { skip: true, reason: '重复告警' } }];
}

staticData.alerts[key] = Date.now();
return [{ json: { skip: false, ...alert } }];
```

## 三、SLA 监控

### 3.1 定义 SLA

| 工作流 | SLA 指标 | 目标 |
|--------|---------|------|
| 订单处理 | 处理延迟 | < 5 分钟 |
| 客服回复 | 响应时间 | < 30 秒 |
| 数据同步 | 成功率 | > 99% |
| 报表生成 | 完成时间 | < 10 分钟 |

### 3.2 延迟监控

```javascript
// Code 节点：检查执行延迟
const executions = $input.all();

const violations = executions.filter(exec => {
  const duration = new Date(exec.json.stoppedAt) - new Date(exec.json.startedAt);
  const sla = exec.json.workflow.sla_ms || 300000; // 默认 5 分钟
  return duration > sla;
});

return violations.map(exec => ({
  json: {
    workflow_name: exec.json.workflow.name,
    duration_ms: new Date(exec.json.stoppedAt) - new Date(exec.json.startedAt),
    sla_ms: exec.json.workflow.sla_ms,
    violation_ms: (new Date(exec.json.stoppedAt) - new Date(exec.json.startedAt)) - exec.json.workflow.sla_ms,
    execution_id: exec.json.id
  }
}));
```

### 3.3 成功率监控

```javascript
// Code 节点：计算成功率
const executions = $input.all();

const stats = {
  total: executions.length,
  success: executions.filter(e => e.json.status === 'success').length,
  error: executions.filter(e => e.json.status === 'error').length
};

stats.success_rate = (stats.success / stats.total * 100).toFixed(2) + '%';
stats.meets_sla = stats.success / stats.total >= 0.99;

return [{ json: stats }];
```

## 四、监控仪表板

### 4.1 关键指标

| 指标 | 说明 | 可视化 |
|------|------|--------|
| 执行总数 | 每小时/每天执行次数 | 折线图 |
| 成功率 | 成功/总执行 | 仪表盘 |
| 平均执行时间 | 执行耗时平均值 | 折线图 |
| 错误分布 | 按错误类型分类 | 饼图 |
| 活跃工作流 | 当前活跃的工作流数 | 数字 |

### 4.2 数据收集

```
Schedule（每小时）
    ↓
n8n API（查询执行统计）
    ↓
Code（计算指标）
    ↓
数据库（存储统计）
    ↓
Grafana/Google Sheets（展示）
```

### 4.3 自动报表

```javascript
// Code 节点：生成监控报表
const stats = $input.all();

const report = `# n8n 监控日报 - ${$now.toFormat('yyyy-MM-dd')}

## 执行统计
- 总执行次数：${stats.total_executions}
- 成功次数：${stats.success_count}
- 失败次数：${stats.error_count}
- 成功率：${stats.success_rate}

## 性能指标
- 平均执行时间：${stats.avg_duration_ms}ms
- 最长执行时间：${stats.max_duration_ms}ms
- SLA 违规次数：${stats.sla_violations}

## 错误 Top 5
${stats.top_errors.map((e, i) => `${i+1}. ${e.workflow}: ${e.count} 次`).join('\n')}

## 建议
${stats.suggestions.join('\n')}
`;

return [{ json: { report, date: $now.toFormat('yyyy-MM-dd') } }];
```

## 五、告警自动化

### 5.1 告警处理工作流

```
Error Trigger
    ↓
Code（分类告警）
    ↓
Switch（告警级别）
    ├─ Critical → 电话 + Slack + 创建工单
    ├─ Error → Slack + 邮件
    ├─ Warning → Slack
    └─ Info → 记录日志
    ↓
数据库（记录告警）
```

### 5.2 告警升级

```javascript
// Code 节点：告警升级逻辑
const alert = $input.first().json;
const staticData = $getWorkflowStaticData('global');

if (!staticData.escalation) {
  staticData.escalation = {};
}

const key = alert.workflow_id;
const now = Date.now();

if (!staticData.escalation[key]) {
  staticData.escalation[key] = { count: 0, first_alert: now };
}

staticData.escalation[key].count++;

// 同一工作流 10 分钟内失败 3 次以上，升级告警
const timeDiff = now - staticData.escalation[key].first_alert;
if (staticData.escalation[key].count >= 3 && timeDiff < 600000) {
  alert.level = 'critical';
  alert.message = `⚠️ 工作流 ${alert.workflow_name} 在 10 分钟内失败 ${staticData.escalation[key].count} 次，已升级为 CRITICAL`;
  staticData.escalation[key] = { count: 0, first_alert: now };
}

return [{ json: alert }];
```

## 常见误区

### 误区一："有告警就够了"

告警只是第一步。需要有明确的处理流程和责任人。

### 误区二："告警越多越好"

过多的告警会导致告警疲劳。需要分级和去重。

### 误区三："监控只关注失败"

执行时间超标、成功率下降也是重要指标。

---

## 工程建议

1. **分级告警**：不同级别的告警用不同渠道通知。
2. **告警去重**：避免同一问题重复告警。
3. **SLA 定义**：每个关键工作流都要定义 SLA。
4. **定期复盘**：每周复盘告警情况，优化监控策略。
5. **自动化处理**：能自动处理的告警不要人工介入。
