## 一、部署架构

### 1.1 单实例架构

```
用户 → Nginx → n8n 实例 → PostgreSQL
```

适合：小团队、工作流 < 50、执行量 < 1000/天

### 1.2 队列模式架构

```
用户 → Nginx → n8n 主实例（编辑器 + 触发器）
                    ↓
              Redis（队列）
                    ↓
           n8n Worker 1 → PostgreSQL
           n8n Worker 2
           n8n Worker N
```

适合：中大型团队、工作流 > 50、执行量 > 1000/天

### 1.3 高可用架构

```
用户 → Nginx（负载均衡）
          ├─ n8n 实例 1
          └─ n8n 实例 2
               ↓
          Redis Sentinel/Cluster
               ↓
          PostgreSQL 主从
```

## 二、Redis 队列配置

### 2.1 Docker Compose 配置

```yaml
version: '3.8'

services:
  n8n-editor:
    image: n8nio/n8n
    command: start --tunnel
    environment:
      - EXECUTIONS_MODE=queue
      - QUEUE_BULL_REDIS_HOST=redis
      - QUEUE_BULL_REDIS_PORT=6379
      - DB_TYPE=postgresdb
      - DB_POSTGRESDB_HOST=postgres
      - DB_POSTGRESDB_DATABASE=n8n
    ports:
      - "5678:5678"
    depends_on:
      - redis
      - postgres

  n8n-worker:
    image: n8nio/n8n
    command: worker
    environment:
      - EXECUTIONS_MODE=queue
      - QUEUE_BULL_REDIS_HOST=redis
      - QUEUE_BULL_REDIS_PORT=6379
      - DB_TYPE=postgresdb
      - DB_POSTGRESDB_HOST=postgres
      - DB_POSTGRESDB_DATABASE=n8n
    deploy:
      replicas: 3
    depends_on:
      - redis
      - postgres

  redis:
    image: redis:7-alpine
    volumes:
      - redis_data:/data

  postgres:
    image: postgres:15
    environment:
      - POSTGRES_DB=n8n
      - POSTGRES_USER=n8n
      - POSTGRES_PASSWORD=password
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  redis_data:
  postgres_data:
```

### 2.2 环境变量

```bash
# 队列模式
EXECUTIONS_MODE=queue

# Redis 配置
QUEUE_BULL_REDIS_HOST=redis
QUEUE_BULL_REDIS_PORT=6379
QUEUE_BULL_REDIS_PASSWORD=your-password
QUEUE_BULL_REDIS_DB=0

# Worker 配置
N8N_CONCURRENCY_PRODUCTION=10
N8N_CONCURRENCY_DEVELOPMENT=1
```

### 2.3 队列监控

```bash
# Redis CLI 监控队列
redis-cli LLEN bull:jobs:waiting
redis-cli LLEN bull:jobs:active
redis-cli LLEN bull:jobs:completed
redis-cli LLEN bull:jobs:failed
```

## 三、水平扩展

### 3.1 Worker 扩展

```yaml
# 增加 Worker 数量
n8n-worker:
  image: n8nio/n8n
  command: worker
  deploy:
    replicas: 5  # 从 3 增加到 5
```

### 3.2 自动扩缩容

使用 Kubernetes HPA：

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: n8n-worker
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: n8n-worker
  minReplicas: 2
  maxReplicas: 10
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70
```

### 3.3 负载均衡

Nginx 配置：

```nginx
upstream n8n {
    server n8n-1:5678;
    server n8n-2:5678;
}

server {
    listen 443 ssl;
    server_name n8n.example.com;
    
    location / {
        proxy_pass http://n8n;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
    
    location /webhook/ {
        # Webhook 请求可以路由到任意实例
        proxy_pass http://n8n;
    }
}
```

## 四、高可用设计

### 4.1 数据库高可用

PostgreSQL 主从配置：

```yaml
services:
  postgres-primary:
    image: postgres:15
    environment:
      - POSTGRES_REPLICATION_MODE=master
      - POSTGRES_REPLICATION_USER=replicator
    volumes:
      - postgres_primary:/var/lib/postgresql/data

  postgres-replica:
    image: postgres:15
    environment:
      - POSTGRES_REPLICATION_MODE=slave
      - POSTGRES_MASTER_HOST=postgres-primary
      - POSTGRES_REPLICATION_USER=replicator
    depends_on:
      - postgres-primary
```

### 4.2 Redis 高可用

Redis Sentinel 配置：

```yaml
services:
  redis-master:
    image: redis:7-alpine
    command: redis-server --requirepass password

  redis-sentinel:
    image: redis:7-alpine
    command: redis-sentinel /etc/redis/sentinel.conf
    volumes:
      - ./sentinel.conf:/etc/redis/sentinel.conf
```

### 4.3 n8n 实例高可用

```yaml
services:
  n8n:
    image: n8nio/n8n
    deploy:
      replicas: 2
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:5678/healthz"]
      interval: 30s
      timeout: 10s
      retries: 3
```

## 五、Kubernetes 部署

### 5.1 Deployment

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: n8n
spec:
  replicas: 3
  selector:
    matchLabels:
      app: n8n
  template:
    metadata:
      labels:
        app: n8n
    spec:
      containers:
        - name: n8n
          image: n8nio/n8n
          ports:
            - containerPort: 5678
          env:
            - name: EXECUTIONS_MODE
              value: "queue"
            - name: DB_TYPE
              value: "postgresdb"
            - name: DB_POSTGRESDB_HOST
              valueFrom:
                secretKeyRef:
                  name: n8n-secrets
                  key: db-host
```

### 5.2 Service

```yaml
apiVersion: v1
kind: Service
metadata:
  name: n8n
spec:
  selector:
    app: n8n
  ports:
    - port: 80
      targetPort: 5678
  type: ClusterIP
```

### 5.3 Ingress

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: n8n
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt
spec:
  tls:
    - hosts:
        - n8n.example.com
      secretName: n8n-tls
  rules:
    - host: n8n.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: n8n
                port:
                  number: 80
```

## 六、备份与恢复

### 6.1 数据库备份

```bash
#!/bin/bash
# scripts/backup-db.sh

BACKUP_DIR="/backups/$(date +%Y%m%d_%H%M%S)"
mkdir -p $BACKUP_DIR

# 备份 PostgreSQL
pg_dump -h $DB_HOST -U $DB_USER -d $DB_NAME > "$BACKUP_DIR/n8n.sql"

# 备份 n8n 数据
docker cp n8n:/home/node/.n8n "$BACKUP_DIR/n8n-data"

# 压缩
tar -czf "$BACKUP_DIR.tar.gz" $BACKUP_DIR
rm -rf $BACKUP_DIR

echo "Backup created: $BACKUP_DIR.tar.gz"
```

### 6.2 自动备份

```yaml
# CronJob for Kubernetes
apiVersion: batch/v1
kind: CronJob
metadata:
  name: n8n-backup
spec:
  schedule: "0 2 * * *"
  jobTemplate:
    spec:
      template:
        spec:
          containers:
            - name: backup
              image: postgres:15
              command: ["/bin/bash", "/scripts/backup-db.sh"]
              volumeMounts:
                - name: backup-scripts
                  mountPath: /scripts
          volumes:
            - name: backup-scripts
              configMap:
                name: backup-scripts
```

## 常见误区

### 误区一："单实例够用了"

当执行量超过 1000/天或工作流超过 50 个时，应该考虑队列模式。

### 误区二："扩展 Worker 就能解决所有问题"

Worker 扩展受限于数据库性能。数据库也需要优化和扩展。

### 误区三："不需要监控队列"

队列积压会导致执行延迟。需要监控队列长度和 Worker 状态。

---

## 工程建议

1. **从队列模式开始**：生产环境直接使用队列模式。
2. **监控队列状态**：队列长度、Worker 数量、执行延迟。
3. **自动备份**：每天自动备份数据库和 n8n 数据。
4. **健康检查**：配置健康检查和自动重启。
5. **渐进式扩展**：先优化单实例性能，再考虑扩展。

---

## 小结

- n8n 支持单实例和队列模式两种部署架构
- Redis 队列模式支持 Worker 水平扩展
- 高可用需要数据库、Redis 和 n8n 实例的冗余
- Kubernetes 部署支持自动扩缩容
- 备份和恢复是生产环境的必要措施
