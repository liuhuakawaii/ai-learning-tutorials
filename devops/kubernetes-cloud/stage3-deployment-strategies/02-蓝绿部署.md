# 蓝绿部署

## 场景引入

你用 Deployment 的滚动更新发布了新版本。但用户反馈说更新过程中部分请求返回了 500 错误。原因是滚动更新时新旧版本同时存在，如果新版本有兼容性问题（比如数据库 schema 变更），旧版本的 Pod 就会出错。

蓝绿部署（Blue-Green Deployment）是另一种发布策略：同时维护两个完整环境（蓝色=当前版本，绿色=新版本），新版本在绿色环境中验证通过后，一次性将流量从蓝色切换到绿色。如果新版本有问题，只需把流量切回蓝色。

## 学习目标

1. 理解蓝绿部署的原理和优势
2. 掌握在 K8s 中实现蓝绿部署的方法
3. 了解蓝绿部署的适用场景和局限性
4. 学会通过 Service 切换实现流量转移

## 蓝绿部署原理

```
切换前（蓝色活跃）：
                    ┌──────────┐
Client ────────────►│ Service  │
                    │ (blue)   │
                    └────┬─────┘
                         │ selector: version=blue
                    ┌────▼─────┐
                    │ Blue Pods│  ← 当前版本 v1.0
                    │ (v1.0)   │
                    └──────────┘

                    ┌──────────┐
                    │ Green    │  ← 新版本 v2.0（已就绪但无流量）
                    │ Pods     │
                    └──────────┘

切换后（绿色活跃）：
                    ┌──────────┐
Client ────────────►│ Service  │
                    │ (green)  │
                    └────┬─────┘
                         │ selector: version=green
                    ┌────▼─────┐
                    │ Green    │  ← 新版本 v2.0
                    │ Pods     │
                    └──────────┘

                    ┌──────────┐
                    │ Blue     │  ← 旧版本 v1.0（保留用于回滚）
                    │ Pods     │
                    └──────────┘
```

## K8s 实现蓝绿部署

### 部署蓝色环境（当前版本）

```yaml
# blue-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-blue
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web
      version: blue
  template:
    metadata:
      labels:
        app: web
        version: blue
    spec:
      containers:
        - name: web
          image: my-app:1.0.0
          ports:
            - containerPort: 8080
          readinessProbe:
            httpGet:
              path: /health
              port: 8080
            periodSeconds: 5
```

### 部署绿色环境（新版本）

```yaml
# green-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-green
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web
      version: green
  template:
    metadata:
      labels:
        app: web
        version: green
    spec:
      containers:
        - name: web
          image: my-app:2.0.0
          ports:
            - containerPort: 8080
          readinessProbe:
            httpGet:
              path: /health
              port: 8080
            periodSeconds: 5
```

### Service 切换流量

```yaml
# service.yaml — 当前指向蓝色
apiVersion: v1
kind: Service
metadata:
  name: web-svc
spec:
  selector:
    app: web
    version: blue    # ← 切换这个值实现蓝绿切换
  ports:
    - port: 80
      targetPort: 8080
```

### 执行切换

```bash
# 1. 部署蓝色环境
kubectl apply -f blue-deployment.yaml

# 2. 创建 Service 指向蓝色
kubectl apply -f service.yaml

# 3. 部署绿色环境（新版本）
kubectl apply -f green-deployment.yaml

# 4. 等待绿色环境就绪
kubectl wait --for=condition=Ready pods -l version=green --timeout=120s

# 5. 验证绿色环境
kubectl exec -it deploy/web-green -- curl localhost:8080/health

# 6. 切换流量到绿色
kubectl patch svc web-svc -p '{"spec":{"selector":{"version":"green"}}}'

# 7. 验证流量已切换
kubectl get endpoints web-svc
# 应该看到 green Pod 的 IP

# 8. 如果有问题，切回蓝色
kubectl patch svc web-svc -p '{"spec":{"selector":{"version":"blue"}}}'
```

## 使用 Helm 实现蓝绿

Helm 的 values 文件可以更优雅地管理蓝绿切换：

```yaml
# values.yaml
activeColor: blue

blue:
  enabled: true
  image:
    tag: "1.0.0"

green:
  enabled: false
  image:
    tag: "2.0.0"
```

```yaml
# templates/deployment-blue.yaml
{{- if .Values.blue.enabled }}
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ include "app.fullname" . }}-blue
spec:
  replicas: {{ .Values.replicaCount }}
  selector:
    matchLabels:
      app: {{ include "app.name" . }}
      version: blue
  template:
    metadata:
      labels:
        app: {{ include "app.name" . }}
        version: blue
    spec:
      containers:
        - name: {{ .Chart.Name }}
          image: "{{ .Values.image.repository }}:{{ .Values.blue.image.tag }}"
{{- end }}
```

```yaml
# templates/service.yaml
apiVersion: v1
kind: Service
metadata:
  name: {{ include "app.fullname" . }}
spec:
  selector:
    app: {{ include "app.name" . }}
    version: {{ .Values.activeColor }}
  ports:
    - port: 80
```

切换流程：
```bash
# 切换到绿色
helm upgrade my-app ./my-app \
  --set activeColor=green \
  --set green.enabled=true

# 回滚到蓝色
helm upgrade my-app ./my-app \
  --set activeColor=blue
```

## 验证新版本

在切换流量之前，应该先验证新版本是否正常：

```bash
# 通过端口转发直接访问绿色环境
kubectl port-forward deploy/web-green 8080:8080

# 运行自动化测试
curl http://localhost:8080/health
curl http://localhost:8080/api/test

# 检查日志
kubectl logs -l version=green --tail=100
```

## 蓝绿部署的优缺点

### 优点

- **零停机**：流量切换瞬间完成，用户无感知
- **快速回滚**：只需切换 Service selector，秒级回滚
- **完整验证**：新版本在接收流量前可以充分测试

### 缺点

- **资源翻倍**：两个完整环境同时运行，需要双倍资源
- **状态同步**：有状态服务（数据库）的蓝绿切换更复杂
- **长连接中断**：切换时已建立的连接会断开

## 适用场景

| 场景 | 是否适合蓝绿 |
|------|------------|
| 无状态 Web 服务 | 非常适合 |
| API 服务 | 适合 |
| 数据库 | 不适合（schema 变更复杂） |
| 长连接服务（WebSocket） | 不太适合（切换会断连） |
| 资源紧张的环境 | 不适合（需要双倍资源） |

## 常见误区

**误区一："蓝绿部署就是两个 Deployment"**

蓝绿部署的关键是 Service 的流量切换，而不是两个 Deployment。如果没有 Service 的快速切换能力，蓝绿部署就失去了意义。

**误区二："蓝绿部署不需要测试"**

新版本在接收流量之前必须经过验证（自动化测试、健康检查）。盲目切换流量可能把有问题的版本推给所有用户。

**误区三："蓝绿部署和滚动更新二选一"**

两者可以结合使用。比如大版本升级用蓝绿，小补丁用滚动更新。

## 工程建议

1. **切换前验证新版本**：运行健康检查和基本功能测试
2. **保留旧版本一段时间**：确认新版本稳定后再下线旧版本
3. **有状态服务需要特殊处理**：数据库 schema 变更要向后兼容
4. **监控切换后的错误率**：设置告警，异常时立即回滚
5. **自动化切换流程**：减少人工操作的风险

## 小结

- 蓝绿部署同时维护两个完整环境，通过 Service 切换实现瞬间发布
- 优点：零停机、快速回滚、完整验证
- 缺点：资源翻倍、状态同步复杂
- 实现关键：Service selector 切换流量
- 适合无状态服务，不适合有状态服务和长连接

## 参考答案

### 练习一

**答案**：

```bash
# 1. 部署蓝色
kubectl create deployment web-blue --image=nginx:1.25 --replicas=2
kubectl label deployment web-blue version=blue
kubectl label pods -l app=web-blue version=blue

# 2. 创建 Service
kubectl expose deployment web-blue --port=80 --name=web-svc
# 修改 selector 使其用 version=blue
kubectl patch svc web-svc -p '{"spec":{"selector":{"app":"web-blue","version":"blue"}}}'

# 3. 部署绿色
kubectl create deployment web-green --image=nginx:1.26 --replicas=2

# 4. 验证绿色
kubectl port-forward deploy/web-green 8080:80
# 另一个终端
curl http://localhost:8080

# 5. 切换到绿色
kubectl patch svc web-svc -p '{"spec":{"selector":{"app":"web-green"}}}'

# 6. 验证
kubectl get endpoints web-svc

# 7. 回滚
kubectl patch svc web-svc -p '{"spec":{"selector":{"app":"web-blue","version":"blue"}}}'
```

### 练习二

**答案**：

使用 `helm create` 创建 Chart，然后按本课描述的 Helm 蓝绿方案实现。关键点是 `activeColor` 值控制 Service 的 selector。

```bash
# 切换到绿色
helm upgrade my-app ./my-app --set activeColor=green --set green.enabled=true

# 回滚
helm upgrade my-app ./my-app --set activeColor=blue
```

**要点**：
- Helm 让蓝绿切换更可控，所有配置都在 values 中
- `helm rollback` 也可以回滚，但直接修改 activeColor 更直观
