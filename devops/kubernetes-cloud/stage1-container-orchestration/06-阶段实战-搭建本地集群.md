# 阶段实战：搭建本地集群

## 场景引入

前 5 课你学习了 K8s 的架构、核心概念和资源管理。但纸上得来终觉浅——你需要一个真实的集群来动手练习。生产环境的集群通常由云厂商托管（EKS、GKE、AKS），但在学习阶段，你需要一个本地集群来反复练习，不怕搞坏。

这个阶段实战的目标：用 Kind 或 Minikube 搭建一个多节点本地集群，配置好 kubectl，并部署一个完整的示例应用来验证集群功能。

## 学习目标

1. 使用 Kind 搭建多节点本地 K8s 集群
2. 理解 Kind 和 Minikube 的区别和适用场景
3. 配置 kubectl 连接本地集群
4. 部署示例应用验证集群功能
5. 学会集群的基本维护操作

## 方案选择：Kind vs Minikube

### Kind（Kubernetes in Docker）

Kind 用 Docker 容器模拟 K8s 节点，启动速度快，资源占用小。

```bash
# 安装 Kind
# macOS
brew install kind

# Linux
curl -Lo ./kind https://kind.sigs.k8s.io/dl/v0.20.0/kind-linux-amd64
chmod +x ./kind
sudo mv ./kind /usr/local/bin/kind

# Windows
choco install kind
```

### Minikube

Minikube 用虚拟机或 Docker 容器运行单节点集群，功能更完整但资源占用更大。

```bash
# 安装 Minikube
# macOS
brew install minikube

# Linux
curl -LO https://storage.googleapis.com/minikube/releases/latest/minikube-linux-amd64
sudo install minikube-linux-amd64 /usr/local/bin/minikube

# Windows
choco install minikube
```

### 选择建议

| 特性 | Kind | Minikube |
|------|------|----------|
| 启动速度 | 快（30 秒） | 慢（1-2 分钟） |
| 多节点 | 支持 | 有限支持 |
| 资源占用 | 低 | 中等 |
| Ingress 支持 | 需手动配置 | 内置 addon |
| 适用场景 | CI/CD、快速测试 | 本地开发、功能体验 |

本课程使用 Kind 作为主要方案，Minikube 作为备选。

## 使用 Kind 搭建集群

### 创建集群配置文件

```yaml
# kind-cluster.yaml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
  - role: control-plane
    kubeadmConfigPatches:
      - |
        kind: InitConfiguration
        nodeRegistration:
          kubeletExtraArgs:
            node-labels: "ingress-ready=true"
    extraPortMappings:
      - containerPort: 80
        hostPort: 80
        protocol: TCP
      - containerPort: 443
        hostPort: 443
        protocol: TCP
  - role: worker
  - role: worker
```

这个配置创建一个 3 节点集群：1 个 Control Plane + 2 个 Worker Node。

### 创建集群

```bash
# 创建集群
kind create cluster --config kind-cluster.yaml --name learning

# 验证集群
kubectl cluster-info --context kind-learning

# 查看节点
kubectl get nodes
# 应该看到 3 个节点，都是 Ready 状态
```

### 验证集群状态

```bash
# 查看所有命名空间的系统 Pod
kubectl get pods -n kube-system

# 应该看到以下组件正常运行：
# - coredns
# - etcd
# - kube-apiserver
# - kube-controller-manager
# - kube-proxy
# - kube-scheduler
# - kindnet

# 查看节点详细信息
kubectl describe node learning-control-plane
```

## 部署示例应用

### 创建命名空间

```yaml
# namespace.yaml
apiVersion: v1
kind: Namespace
metadata:
  name: demo
```

```bash
kubectl apply -f namespace.yaml
```

### 部署后端 API

```yaml
# backend-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: backend
  namespace: demo
spec:
  replicas: 2
  selector:
    matchLabels:
      app: backend
  template:
    metadata:
      labels:
        app: backend
    spec:
      containers:
        - name: api
          image: hashicorp/http-echo:latest
          args:
            - "-text=Hello from backend"
            - "-listen=:8080"
          ports:
            - containerPort: 8080
          resources:
            requests:
              cpu: "50m"
              memory: "64Mi"
            limits:
              cpu: "100m"
              memory: "128Mi"
          readinessProbe:
            httpGet:
              path: /
              port: 8080
            periodSeconds: 5
          livenessProbe:
            httpGet:
              path: /
              port: 8080
            periodSeconds: 10
---
apiVersion: v1
kind: Service
metadata:
  name: backend-svc
  namespace: demo
spec:
  selector:
    app: backend
  ports:
    - port: 80
      targetPort: 8080
  type: ClusterIP
```

### 部署前端

```yaml
# frontend-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: frontend
  namespace: demo
spec:
  replicas: 2
  selector:
    matchLabels:
      app: frontend
  template:
    metadata:
      labels:
        app: frontend
    spec:
      containers:
        - name: web
          image: nginx:1.25
          ports:
            - containerPort: 80
          resources:
            requests:
              cpu: "50m"
              memory: "64Mi"
            limits:
              cpu: "100m"
              memory: "128Mi"
          readinessProbe:
            httpGet:
              path: /
              port: 80
            periodSeconds: 5
---
apiVersion: v1
kind: Service
metadata:
  name: frontend-svc
  namespace: demo
spec:
  selector:
    app: frontend
  ports:
    - port: 80
      targetPort: 80
  type: NodePort
  nodePort: 30080
```

### 应用所有配置

```bash
kubectl apply -f namespace.yaml
kubectl apply -f backend-deployment.yaml
kubectl apply -f frontend-deployment.yaml

# 验证部署
kubectl get all -n demo
```

## 集群功能验证

### 验证 Pod 调度

```bash
# 查看 Pod 分布在哪些 Node 上
kubectl get pods -n demo -o wide

# 应该看到 Pod 分布在不同 Worker Node 上
```

### 验证 Service 发现

```bash
# 进入一个 Pod 测试 Service 访问
kubectl exec -it -n demo deploy/frontend -- /bin/sh

# 在容器内测试
curl http://backend-svc
# 应该返回 "Hello from backend"
```

### 验证资源限制

```bash
# 查看 Pod 的资源使用情况（需要 metrics-server）
kubectl top pods -n demo

# 如果没有 metrics-server，先安装
kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml
```

### 验证探针

```bash
# 查看 Pod 事件，确认探针正常工作
kubectl describe pod -n demo -l app=backend

# Events 中应该有类似信息：
# Normal  Pulling    Pulling image
# Normal  Pulled     Successfully pulled image
# Normal  Created    Created container
# Normal  Started    Started container
```

### 验证自愈能力

```bash
# 手动删除一个 Pod
kubectl delete pod -n demo -l app=backend --field-selector spec.nodeName=learning-worker

# 立即查看 Pod 状态
kubectl get pods -n demo -w

# 你会看到：
# 1. 被删除的 Pod 变为 Terminating
# 2. 新的 Pod 被创建
# 3. 新 Pod 变为 Running
# 这就是 Deployment 控制器的自愈能力
```

## 集群维护

### 查看集群状态

```bash
# 查看集群信息
kubectl cluster-info

# 查看组件健康状态
kubectl get componentstatuses  # 已废弃，但仍可用
kubectl get --raw='/readyz?verbose'

# 查看资源使用
kubectl top nodes
kubectl top pods -A
```

### 停止和重启集群

```bash
# 停止集群（保留数据）
kind stop --name learning

# 重启集群
kind start --name learning

# 删除集群
kind delete cluster --name learning

# 重新创建
kind create cluster --config kind-cluster.yaml --name learning
```

### 查看 Kind 集群的 Docker 容器

```bash
# Kind 用 Docker 容器模拟节点
docker ps | grep kind

# 你会看到 3 个容器：
# learning-control-plane
# learning-worker
# learning-worker2
```

## 常见问题排查

### Pod 一直处于 Pending 状态

```bash
kubectl describe pod <pod-name> -n demo
# 查看 Events 中的调度失败原因

# 常见原因：
# 1. 资源不足：Insufficient cpu/memory
# 2. nodeSelector 不匹配
# 3. PVC 未绑定
```

### 镜像拉取失败

```bash
# ImagePullBackOff：检查镜像名和网络
kubectl describe pod <pod-name> -n demo

# 解决方案：
# 1. 确认镜像名正确
# 2. 如果是私有镜像，需要创建 imagePullSecrets
# 3. 在 Kind 中预加载镜像：
docker pull nginx:1.25
kind load docker-image nginx:1.25 --name learning
```

### Service 访问不通

```bash
# 检查 Service 的 Endpoint
kubectl get endpoints backend-svc -n demo

# 如果 Endpoint 为空，说明 Pod 的 label 和 Service 的 selector 不匹配
# 检查 Pod 的 readinessProbe 是否通过
```

## 常见误区

**误区一："本地集群和生产环境一样"**

Kind 用容器模拟节点，网络和存储行为与真实环境有差异。本地学习时某些功能（如 LoadBalancer Service、持久化存储）需要额外配置。

**误区二："Minikube 比 Kind 好"**

两者各有优势。Kind 启动快、支持多节点，适合学习和 CI。Minikube 内置更多 addon，适合需要完整功能体验的场景。

**误区三："集群搭好就不管了"**

本地集群也需要维护：定期更新 Kind/Minikube 版本、清理不用的镜像和容器、监控资源使用。

## 工程建议

1. **用配置文件创建 Kind 集群**：把集群配置文件纳入版本控制，保证团队成员的环境一致
2. **预加载常用镜像**：用 `kind load docker-image` 预加载镜像，避免每次都从远程拉取
3. **使用命名空间隔离**：不同项目或实验用不同命名空间，避免资源混乱
4. **定期清理**：不用的集群及时删除，释放 Docker 资源

## 小结

- Kind 适合快速搭建多节点本地集群，Minikube 适合功能体验
- Kind 集群配置文件应该纳入版本控制
- 部署示例应用后要验证调度、Service 发现、资源限制、自愈等核心功能
- 定期维护和清理本地集群

## 参考答案

### 练习一

**答案**：

```bash
# 1. 安装 Kind（macOS 为例）
brew install kind

# 2. 创建配置文件
cat > kind-cluster.yaml << 'EOF'
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
  - role: control-plane
  - role: worker
  - role: worker
EOF

# 3. 创建集群
kind create cluster --config kind-cluster.yaml --name learning

# 4. 验证节点状态
kubectl get nodes
# NAME                      STATUS   ROLES           AGE   VERSION
# learning-control-plane    Ready    control-plane   1m    v1.27.3
# learning-worker           Ready    <none>          45s   v1.27.3
# learning-worker2          Ready    <none>          45s   v1.27.3

# 5. 查看系统 Pod
kubectl get pods -n kube-system
```

### 练习二

**答案**：

```bash
# 1. 创建命名空间
kubectl create namespace exercise

# 2. 部署 Nginx
kubectl create deployment nginx --image=nginx:1.25 --replicas=3 -n exercise

# 3. 创建 Service
kubectl expose deployment nginx --port=80 --type=NodePort -n exercise

# 4. 端口转发
kubectl port-forward svc/nginx 8080:80 -n exercise
# 浏览器访问 http://localhost:8080

# 5. 观察自愈
kubectl get pods -n exercise -w
# 在另一个终端执行：
kubectl delete pod -n exercise -l app=nginx
# 观察到 Pod 被删除后立即创建新 Pod

# 6. 查看资源使用
kubectl top pods -n exercise
# 如果提示 metrics 不可用，先安装 metrics-server
kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml
# 等待 1-2 分钟后重试
```

**要点**：
- NodePort 服务在 Kind 中通过 `localhost:<nodePort>` 访问
- Pod 自愈是 Deployment 控制器的核心能力
- metrics-server 需要单独安装，不是默认组件
