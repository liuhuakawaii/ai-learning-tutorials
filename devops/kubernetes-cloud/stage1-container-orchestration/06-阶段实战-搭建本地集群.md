# 阶段实战：搭建本地集群

> 前置知识：从 Docker 到编排、Kubernetes 架构、kubectl、Pod 深入、资源管理（第 1-5 课）

## 你的任务

用 Kind 搭建一个多节点本地 K8s 集群，配置 kubectl，部署一个示例应用，验证集群功能。

为什么用 Kind 而不是 Minikube？Kind 用 Docker 容器模拟 K8s 节点，启动快、资源占用小，适合学习和 CI 环境。Minikube 用虚拟机，功能更完整但更重。

## 第一步：安装 Kind 和 kubectl

```bash
# 安装 Kind
# macOS
brew install kind

# Linux
curl -Lo ./kind https://kind.sigs.k8s.io/dl/v0.20.0/kind-linux-amd64
chmod +x ./kind
sudo mv ./kind /usr/local/bin/kind

# 安装 kubectl
# macOS
brew install kubectl

# Linux
curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
chmod +x kubectl
sudo mv kubectl /usr/local/bin/
```

## 第二步：创建多节点集群

```yaml
# kind-config.yaml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
  - role: control-plane
  - role: worker
  - role: worker
```

```bash
# 创建集群
kind create cluster --config kind-config.yaml --name my-cluster

# 验证
kubectl cluster-info --context kind-my-cluster
kubectl get nodes
# 应该看到 3 个节点：1 个 control-plane，2 个 worker
```

## 第三步：部署示例应用

```yaml
# nginx-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
        - name: nginx
          image: nginx:1.25
          ports:
            - containerPort: 80
          resources:
            limits:
              memory: "128Mi"
              cpu: "250m"
```

```yaml
# nginx-service.yaml
apiVersion: v1
kind: Service
metadata:
  name: nginx
spec:
  selector:
    app: nginx
  ports:
    - port: 80
      targetPort: 80
  type: NodePort
```

```bash
# 部署
kubectl apply -f nginx-deployment.yaml
kubectl apply -f nginx-service.yaml

# 验证
kubectl get pods -o wide        # 3 个 Pod 分布在 2 个 worker 节点上
kubectl get services            # 看到 NodePort 端口
kubectl describe deployment nginx  # 查看部署详情
```

## 第四步：验证集群功能

```bash
# 测试服务发现
kubectl run test --image=curlimages/curl --rm -it -- curl http://nginx

# 测试自动恢复
kubectl get pods
# 找到一个 Pod 名称，删除它
kubectl delete pod <pod-name>
# 再看 Pods，K8s 自动创建了一个新的
kubectl get pods
# Pod 数量还是 3 个

# 测试滚动更新
kubectl set image deployment/nginx nginx=nginx:1.26
kubectl rollout status deployment/nginx
kubectl get pods -o wide
# 旧 Pod 被逐步替换为新 Pod

# 回滚
kubectl rollout undo deployment/nginx
```

## 可能遇到的问题

### 问题一：kubectl 连不上集群

```
The connection to the server localhost:8080 was refused
```

检查 kubeconfig 上下文：

```bash
kubectl config get-contexts
kubectl config use-context kind-my-cluster
```

### 问题二：Pod 一直处于 Pending 状态

```
kubectl describe pod <pod-name>
# 查看 Events 部分
```

常见原因：
- 资源不足：`limits` 设置太高，节点没有足够资源
- 节点有 taint：Kind 默认没有 taint，但如果你自定义了配置可能会遇到

### 问题三：NodePort 无法访问

Kind 运行在 Docker 容器内，NodePort 不能直接通过 `localhost` 访问。需要用端口转发：

```bash
kubectl port-forward service/nginx 8080:80
# 然后访问 http://localhost:8080
```

## 练习

### 练习一：多副本验证

部署一个 3 副本的 nginx Deployment，用 `kubectl get pods -o wide` 验证 Pod 分布在不同节点上。然后用 `kubectl scale` 扩容到 5 个副本，再缩容到 2 个。

### 练习二：故障恢复

删除一个 Pod，观察 K8s 的自动恢复行为。记录：从删除到新 Pod Running 需要多久？新 Pod 和旧 Pod 的 IP 是否相同？

### 练习三：资源限制

部署一个 `resources.limits.memory: "64Mi"` 的 Pod，然后在里面执行一个内存占用大的命令，观察 OOM Kill 行为。

## 参考答案

### 练习一

```bash
kubectl scale deployment/nginx --replicas=5
kubectl get pods -o wide   # 5 个 Pod
kubectl scale deployment/nginx --replicas=2
kubectl get pods -o wide   # 2 个 Pod，3 个被终止
```

### 练习二

```bash
kubectl get pods -o wide
kubectl delete pod <pod-name>
kubectl get pods -o wide   # 新 Pod 出现
# IP 一定不同——Pod 是临时的，IP 不应该被硬编码
# 恢复时间通常 2-5 秒
```

### 练习三

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: memory-test
spec:
  containers:
    - name: test
      image: busybox
      command: ["sh", "-c", "dd if=/dev/zero of=/dev/shm/fill bs=1M count=100"]
      resources:
        limits:
          memory: "64Mi"
```

```bash
kubectl apply -f memory-test.yaml
kubectl get pods   # 状态会变成 OOMKilled
kubectl describe pod memory-test   # 查看 Last State
```
