# 阶段实战：部署完整应用

## 场景引入

Stage 2 前 5 课你学习了 Deployment、Service、Ingress、ConfigMap/Secret、PersistentVolume。现在是时候把它们串起来了。这个实战的目标：将一个包含前端、后端 API 和数据库的完整应用部署到 K8s，让它从外部可以正常访问。

## 学习目标

1. 综合运用 Stage 2 所有核心资源对象
2. 理解多层应用在 K8s 中的部署架构
3. 掌握资源之间的依赖关系和创建顺序
4. 学会端到端验证应用是否正常工作

## 应用架构

```
外部请求
    │
    ▼
┌──────────┐
│ Ingress  │  app.local → 前端
│          │  app.local/api → 后端
└────┬─────┘
     │
  ┌──┴──────────────┐
  ▼                 ▼
┌─────┐          ┌─────┐
│前端  │          │后端  │
│Nginx│          │API  │
└─────┘          └──┬──┘
                    │
            ┌───────┴───────┐
            ▼               ▼
        ┌──────┐       ┌───────┐
        │Postgres│      │ Redis │
        └──────┘       └───────┘
```

## 部署步骤

### 第一步：创建命名空间和配置

```yaml
# 01-namespace.yaml
apiVersion: v1
kind: Namespace
metadata:
  name: demo-app
```

```yaml
# 02-configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
  namespace: demo-app
data:
  APP_ENV: "production"
  LOG_LEVEL: "info"
  DB_HOST: "postgres-service"
  DB_PORT: "5432"
  DB_NAME: "appdb"
  REDIS_HOST: "redis-service"
  REDIS_PORT: "6379"
  API_URL: "http://api-service:8080"
```

```yaml
# 03-secrets.yaml
apiVersion: v1
kind: Secret
metadata:
  name: app-secrets
  namespace: demo-app
type: Opaque
data:
  DB_USERNAME: YXBwdXNlcg==      # appuser
  DB_PASSWORD: YXBwU2VjcmV0ITEyMw==  # appSecret123
  REDIS_PASSWORD: cmVkaXNTZWNyZXQxMjM=  # redisSecret123
```

### 第二步：部署数据库

```yaml
# 04-postgres.yaml
apiVersion: v1
kind: Service
metadata:
  name: postgres-service
  namespace: demo-app
spec:
  clusterIP: None
  selector:
    app: postgres
  ports:
    - port: 5432
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: postgres
  namespace: demo-app
spec:
  serviceName: postgres-service
  replicas: 1
  selector:
    matchLabels:
      app: postgres
  template:
    metadata:
      labels:
        app: postgres
    spec:
      containers:
        - name: postgres
          image: postgres:15
          ports:
            - containerPort: 5432
          env:
            - name: POSTGRES_USER
              valueFrom:
                secretKeyRef:
                  name: app-secrets
                  key: DB_USERNAME
            - name: POSTGRES_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: app-secrets
                  key: DB_PASSWORD
            - name: POSTGRES_DB
              valueFrom:
                configMapKeyRef:
                  name: app-config
                  key: DB_NAME
          volumeMounts:
            - name: data
              mountPath: /var/lib/postgresql/data
          resources:
            requests:
              cpu: "100m"
              memory: "256Mi"
            limits:
              cpu: "500m"
              memory: "512Mi"
          readinessProbe:
            exec:
              command:
                - pg_isready
                - -U
                - appuser
                - -d
                - appdb
            periodSeconds: 5
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes:
          - ReadWriteOnce
        resources:
          requests:
            storage: 5Gi
```

### 第三步：部署 Redis

```yaml
# 05-redis.yaml
apiVersion: v1
kind: Service
metadata:
  name: redis-service
  namespace: demo-app
spec:
  selector:
    app: redis
  ports:
    - port: 6379
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: redis
  namespace: demo-app
spec:
  replicas: 1
  selector:
    matchLabels:
      app: redis
  template:
    metadata:
      labels:
        app: redis
    spec:
      containers:
        - name: redis
          image: redis:7-alpine
          command: ['redis-server', '--requirepass', '$(REDIS_PASSWORD)']
          env:
            - name: REDIS_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: app-secrets
                  key: REDIS_PASSWORD
          ports:
            - containerPort: 6379
          resources:
            requests:
              cpu: "50m"
              memory: "64Mi"
            limits:
              cpu: "200m"
              memory: "128Mi"
          readinessProbe:
            exec:
              command:
                - redis-cli
                - -a
                - $(REDIS_PASSWORD)
                - ping
            periodSeconds: 5
```

### 第四步：部署后端 API

```yaml
# 06-backend.yaml
apiVersion: v1
kind: Service
metadata:
  name: api-service
  namespace: demo-app
spec:
  selector:
    app: backend
  ports:
    - port: 8080
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: backend
  namespace: demo-app
spec:
  replicas: 2
  selector:
    matchLabels:
      app: backend
  template:
    metadata:
      labels:
        app: backend
    spec:
      initContainers:
        - name: wait-for-db
          image: busybox:1.36
          command:
            - sh
            - -c
            - |
              until nc -z postgres-service 5432; do
                echo "Waiting for PostgreSQL..."
                sleep 2
              done
      containers:
        - name: api
          image: hashicorp/http-echo:latest
          args:
            - "-text=Hello from Backend API"
            - "-listen=:8080"
          ports:
            - containerPort: 8080
          envFrom:
            - configMapRef:
                name: app-config
          env:
            - name: DB_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: app-secrets
                  key: DB_PASSWORD
          resources:
            requests:
              cpu: "100m"
              memory: "128Mi"
            limits:
              cpu: "500m"
              memory: "256Mi"
          readinessProbe:
            httpGet:
              path: /
              port: 8080
            periodSeconds: 5
          livenessProbe:
            httpGet:
              path: /
              port: 8080
            periodSeconds: 10
```

### 第六步：配置 Ingress

```yaml
# 08-ingress.yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: app-ingress
  namespace: demo-app
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /$2
spec:
  ingressClassName: nginx
  rules:
    - host: app.local
      http:
        paths:
          - path: /api(/|$)(.*)
            pathType: ImplementationSpecific
            backend:
              service:
                name: api-service
                port:
                  number: 8080
          - path: /(/|${'$'})(.*)
            pathType: ImplementationSpecific
            backend:
              service:
                name: frontend-service
                port:
                  number: 80
```

## 部署顺序依赖

正确的部署顺序很重要：

```
1. Namespace + ConfigMap + Secret    ← 无依赖
2. PostgreSQL + Redis                ← 依赖 Secret
3. Backend API                       ← 依赖 PostgreSQL + Redis
4. Frontend                          ← 依赖 Backend（可选）
5. Ingress                           ← 依赖 Service
```

initContainer 确保了依赖顺序：Backend 的 initContainer 会等待 PostgreSQL 就绪后才启动主容器。

## 常见问题

### Pod 一直 Pending

```bash
kubectl describe pod <pod-name> -n demo-app
# 常见原因：
# - PVC 绑定失败（没有可用的 PV 或 StorageClass）
# - 资源不足（Node 的 CPU/内存不够）
# - nodeSelector 不匹配
```

### ContainerCreating 状态

```bash
kubectl describe pod <pod-name> -n demo-app
# 常见原因：
# - 镜像拉取失败（ImagePullBackOff）
# - Secret 或 ConfigMap 不存在
# - 挂载的 Volume 有问题
```

### CrashLoopBackOff

```bash
# 查看日志
kubectl logs <pod-name> -n demo-app
# 查看前一次容器的日志
kubectl logs <pod-name> --previous -n demo-app
# 常见原因：
# - 应用启动失败（连接数据库失败、配置错误）
# - OOM Kill（内存不足）
# - 探针配置错误
```

## 常见误区

**误区一："一次性 apply 所有 YAML 就行了"**

有些资源有依赖关系（比如 Backend 依赖 PostgreSQL）。虽然 K8s 会重试，但合理安排部署顺序可以减少等待时间。

**误区二："Pod Running 就代表应用正常"**

Running 只表示容器在运行，不代表应用正常工作。需要检查 Readiness Probe、日志、以及实际请求是否正常。

## 工程建议

1. **按依赖顺序部署**：基础设施（数据库）→ 后端 → 前端 → Ingress
2. **使用 initContainer 处理依赖**：确保应用启动时依赖已就绪
3. **所有容器都配置资源限制**：防止某个容器耗尽 Node 资源
4. **所有容器都配置 Readiness Probe**：确保流量只转发到健康的 Pod
5. **敏感信息用 Secret**：数据库密码、API 密钥不要写在 ConfigMap 中

## 小结

- 多层应用部署需要：Namespace → Config/Secret → 数据库 → 后端 → 前端 → Ingress
- StatefulSet 适合数据库等有状态服务
- initContainer 处理启动依赖
- Ingress 提供统一的外部访问入口
- 端到端验证确保所有组件正常协作

### 练习二

**答案**：

```bash
# 1. 删除后端 Pod
kubectl delete pod -n demo-app -l app=backend
kubectl get pods -n demo-app -w
# 立即看到新 Pod 被创建

# 2. 删除 PostgreSQL Pod
kubectl delete pod -n demo-app -l app=postgres
kubectl get pods -n demo-app -w
# StatefulSet 重建 Pod，PVC 自动重新绑定
# 验证数据仍在
kubectl exec -n demo-app postgres-0 -- psql -U appuser -d appdb -c "SELECT 1;"

# 3. 更新 ConfigMap
kubectl edit configmap app-config -n demo-app
# 修改 LOG_LEVEL 为 "debug"
# 重启后端
kubectl rollout restart deployment backend -n demo-app
# 验证新配置
kubectl exec -n demo-app deploy/backend -- env | grep LOG_LEVEL
```

**要点**：
- Deployment 的 Pod 被删除后自动重建
- StatefulSet 的 Pod 重建后 PVC 数据不丢失
- 环境变量注入的配置需要重启 Pod 才能更新
