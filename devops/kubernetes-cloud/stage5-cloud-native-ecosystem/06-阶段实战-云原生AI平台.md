# 阶段实战：云原生 AI 平台

> 前置知识：Serverless、Service Mesh、GPU 调度、多集群管理、成本优化（Stage 5 第 1-5 课）

## 你要做什么

搭建一个云原生 AI 推理平台，支持 GPU 模型推理、自动扩缩容、多环境部署、监控告警。

这不是一个 demo——这是你在真实项目里要部署的 AI 服务平台。

## 平台架构

```
外部请求
    │
    ▼
┌──────────┐
│ Ingress  │
└──────────┘
    │
    ├──→ vLLM 推理服务（GPU Pod）
    │       ├── HPA 自动扩缩容
    │       └── Node Affinity → GPU 节点
    │
    ├──→ API Gateway
    │       ├── 认证鉴权
    │       └── 限流
    │
    └──→ 监控
            ├── Prometheus（GPU 使用率、推理延迟）
            └── Grafana Dashboard
```

## 第二步：vLLM 推理服务

```yaml
# vllm-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: vllm-server
  namespace: ai-platform
spec:
  replicas: 1
  selector:
    matchLabels:
      app: vllm
  template:
    metadata:
      labels:
        app: vllm
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/port: "8000"
    spec:
      containers:
        - name: vllm
          image: vllm/vllm-openai:latest
          command: ["python", "-m", "vllm.entrypoints.openai.api_server"]
          args:
            - "--model"
            - "meta-llama/Llama-2-7b-chat-hf"
            - "--tensor-parallel-size"
            - "1"
            - "--gpu-memory-utilization"
            - "0.9"
          ports:
            - containerPort: 8000
          resources:
            limits:
              nvidia.com/gpu: "1"
              memory: "16Gi"
              cpu: "4"
          readinessProbe:
            httpGet:
              path: /health
              port: 8000
            initialDelaySeconds: 60
            periodSeconds: 10
          livenessProbe:
            httpGet:
              path: /health
              port: 8000
            initialDelaySeconds: 120
            periodSeconds: 30
      nodeSelector:
        accelerator: nvidia-gpu
      tolerations:
        - key: nvidia.com/gpu
          operator: Exists
          effect: NoSchedule
```

## 第三步：自动扩缩容

```yaml
# hpa.yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: vllm-hpa
  namespace: ai-platform
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: vllm-server
  minReplicas: 1
  maxReplicas: 4
  metrics:
    - type: Pods
      pods:
        metric:
          name: vllm:num_requests_running
        target:
          type: AverageValue
          averageValue: "5"
  behavior:
    scaleUp:
      stabilizationWindowSeconds: 60
      policies:
        - type: Pods
          value: 1
          periodSeconds: 60
    scaleDown:
      stabilizationWindowSeconds: 300
      policies:
        - type: Pods
          value: 1
          periodSeconds: 120
```

扩缩容逻辑：当每个 Pod 平均处理超过 5 个请求时扩容，每次增加 1 个 Pod，60 秒后才能再次扩容。缩容更保守——300 秒稳定窗口，120 秒才能缩一次。

## 第四步：监控

```yaml
# ServiceMonitor for Prometheus
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: vllm-monitor
  namespace: ai-platform
spec:
  selector:
    matchLabels:
      app: vllm
  endpoints:
    - port: http
      path: /metrics
      interval: 15s
```

关键监控指标：

```promql
# GPU 使用率
nvidia_gpu_utilization_gpu

# 推理延迟 P99
histogram_quantile(0.99, rate(vllm:e2e_request_latency_seconds_bucket[5m]))

# 请求队列长度
vllm:num_requests_waiting

# 每秒请求数
rate(vllm:num_requests_total[5m])
```

## 练习

### 练习一：模型切换

将部署的模型从 Llama-2-7b 切换到另一个模型（如 Mistral-7B）。修改 Deployment 的 args，验证新模型能正常响应。

### 练习二：GPU 监控

在 Grafana 中创建 GPU Dashboard，展示：GPU 使用率、GPU 显存使用、推理延迟。用 `nvidia-smi` 对比 K8s 报告的 GPU 使用率和实际使用率。

### 练习三：成本优化

假设你的 GPU 节点每月 $500。设计一个成本优化方案：非高峰时段缩容到 1 个副本，高峰时段扩容到 4 个副本。用 CronJob 或 KEDA 实现。

## 参考答案

### 练习一

```bash
kubectl set image deployment/vllm-server vllm=vllm/vllm-openai:latest \
  --overrides='[{"op":"replace","path":"/spec/template/spec/containers/0/args/1","value":"mistralai/Mistral-7B-v0.1"}]'
```

或者直接修改 YAML 中的 `--model` 参数重新 apply。

### 练习二

Grafana PromQL 查询：

```promql
# GPU 使用率
nvidia_gpu_utilization_gpu{pod=~"vllm.*"}

# GPU 显存
nvidia_gpu_memory_used_bytes{pod=~"vllm.*"} / nvidia_gpu_memory_total_bytes{pod=~"vllm.*"} * 100

# 推理延迟
histogram_quantile(0.99, rate(vllm:e2e_request_latency_seconds_bucket{pod=~"vllm.*"}[5m]))
```

### 练习三

用 KEDA 实现基于 Cron 的自动扩缩容：

```yaml
apiVersion: keda.sh/v1alpha1
kind: ScaledObject
metadata:
  name: vllm-scaledobject
spec:
  scaleTargetRef:
    name: vllm-server
  minReplicaCount: 1
  maxReplicaCount: 4
  triggers:
    - type: cron
      metadata:
        timezone: Asia/Shanghai
        start: 0 8 * * *    # 每天早上 8 点开始
        end: 0 22 * * *      # 每天晚上 10 点结束
        desiredReplicas: "4"
```

非工作时间自动缩到 1 个副本，节省约 75% 的 GPU 成本。
