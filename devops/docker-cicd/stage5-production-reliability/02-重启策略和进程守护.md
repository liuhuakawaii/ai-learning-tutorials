## 场景引入

凌晨三点，你被告警叫醒：服务挂了。你 SSH 到服务器，发现 API 容器因为一个未捕获的异常退出了。你手动 `docker compose restart` 恢复了服务，然后回去睡觉。一小时后又挂了——同样的原因。你开始想：能不能让容器在异常退出时自动重启？能不能让进程在收到停止信号时优雅关闭，而不是直接被杀掉？

## 一、Docker 重启策略

```yaml
services:
  app:
    restart: no              # 不自动重启（默认）
    restart: always          # 总是重启
    restart: on-failure      # 只在非正常退出时重启
    restart: unless-stopped  # 除非手动停止，否则总是重启
```

```
策略选择：

  开发环境：no 或 on-failure
  生产环境：unless-stopped
  关键服务：always

  区别：
  - always：即使 docker stop 后，Docker 重启也会启动
  - unless-stopped：docker stop 后不会自动启动
```

## 二、使用 tini 作为 init 进程

### 2.1 为什么需要 tini

```
问题：Node.js 作为 PID 1 运行时

  PID 1 的职责：
  ├── 接收系统信号（SIGTERM、SIGINT）
  ├── 转发信号给子进程
  └── 回收僵尸进程

  Node.js 不会正确处理这些：
  ├── 不会转发信号给子进程
  ├── 子进程可能变成僵尸进程
  └── 优雅关闭可能不工作
```

### 2.2 在 Dockerfile 中使用 tini

```dockerfile
FROM node:18-alpine

# 安装 tini
RUN apk add --no-cache tini

# 使用 tini 作为入口
ENTRYPOINT ["/sbin/tini", "--"]

CMD ["node", "src/index.js"]
```

### 2.3 在 Docker run 中使用

```bash
docker run --init my-app
```

## 三、优雅关闭

```javascript
// 处理关闭信号
process.on('SIGTERM', () => {
  console.log('Received SIGTERM, shutting down gracefully...');
  
  // 停止接收新请求
  server.close(() => {
    // 关闭数据库连接
    pgPool.end();
    redisClient.quit();
    
    console.log('Shutdown complete');
    process.exit(0);
  });
  
  // 超时强制退出
  setTimeout(() => {
    console.log('Shutdown timeout, forcing exit');
    process.exit(1);
  }, 30000);
});
```

## 常见误区

- **"always 比 unless-stopped 好"**：`always` 会在 Docker 守护进程重启后自动启动所有容器，包括你手动停止的。`unless-stopped` 更符合预期——手动停止的不会自动启动。
- **"重启策略能解决所有崩溃问题"**：如果应用因为配置错误或代码 bug 每次启动都崩溃，无限重启只会浪费资源。应该配合 `on-failure:5` 限制重启次数。
- **"Node.js 不需要 tini"**：Node.js 作为 PID 1 运行时不会正确处理信号和回收僵尸进程。tini 是轻量级的 init 进程，解决这些问题，几乎零开销。
- **"优雅关闭只是调用 process.exit()"**：优雅关闭需要先停止接收新请求、等待正在处理的请求完成、关闭数据库连接，最后再退出。直接 exit 会导致请求中断。

---

## 工程建议

- **生产环境用 `unless-stopped`**：这是最符合预期的策略。服务崩溃自动重启，手动停止后不会自动启动。
- **用 tini 作为 init 进程**：`RUN apk add --no-cache tini` + `ENTRYPOINT ["/sbin/tini", "--"]`，让 Node.js 正确处理 SIGTERM 信号。
- **实现优雅关闭**：监听 SIGTERM 信号，停止接收新请求，等待正在处理的请求完成（设置超时），关闭数据库连接，最后退出。
- **限制重启次数**：`restart: on-failure:5` 防止无限重启。如果连续 5 次启动都失败，停止重启，需要人工介入。

---

## 小结

1. **重启策略**：生产环境使用 `unless-stopped`
2. **tini**：正确的 init 进程，处理信号和僵尸进程
3. **优雅关闭**：接收 SIGTERM 后清理资源再退出
4. **资源限制**：CPU 和内存限制，防止资源耗尽
