# 第四课：环境变量管理

> **课程定位**：学会安全地管理配置和密钥，这是生产环境的基本功
> **前置知识**：compose.yml 基础（第 1-3 课）
> **预计时长**：30 分钟

---

## 场景引入

你把项目推到 GitHub，CI 流水线跑起来了，但报错：`DATABASE_URL is not defined`。你一看，数据库连接字符串写在 compose.yml 里，但 CI 环境的数据库地址不一样。同事也抱怨：他本地的数据库密码和你的不同，每次 pull 代码都要手动改 compose.yml。你意识到：配置和代码必须分离，不同环境需要不同的配置。

---

## 学习目标

1. 掌握 Compose 中环境变量的三种传入方式
2. 理解 `.env` 文件的使用和安全边界
3. 知道哪些配置应该用环境变量，哪些不该

## 一、三种传入方式

### 1.1 直接定义

```yaml
services:
  app:
    environment:
      - NODE_ENV=production
      - PORT=3000
      - DATABASE_URL=postgres://user:pass@postgres:5432/db
```

```
优点：简单直接
缺点：敏感信息暴露在 compose.yml 中，不适合提交到 Git
适用：非敏感的固定配置
```

### 1.2 从 .env 文件读取

```yaml
services:
  app:
    env_file:
      - .env
```

```bash
# .env
NODE_ENV=production
PORT=3000
DATABASE_URL=postgres://user:secret@postgres:5432/mydb
REDIS_URL=redis://redis:6379
API_KEY=sk-1234567890
```

```
优点：敏感信息集中在 .env 文件
缺点：.env 文件可能被误提交到 Git
适用：本地开发环境
```

### 1.3 使用变量替换

```yaml
services:
  app:
    environment:
      - NODE_ENV=${NODE_ENV:-development}
      - DATABASE_URL=${DATABASE_URL}
```

```bash
# .env
NODE_ENV=production
DATABASE_URL=postgres://user:secret@postgres:5432/mydb
```

```
${VARIABLE}          → 使用变量值
${VARIABLE:-default} → 如果变量未设置，使用默认值
${VARIABLE:?error}   → 如果变量未设置，报错
```

## 二、.env 文件管理

### 2.1 推荐结构

```bash
# .env.example（提交到 Git，作为模板）
NODE_ENV=development
PORT=3000
DATABASE_URL=postgres://postgres:password@postgres:5432/mydb
REDIS_URL=redis://redis:6379

# .env（不提交到 Git，实际使用）
NODE_ENV=production
PORT=3000
DATABASE_URL=postgres://postgres:real_secret@postgres:5432/mydb
REDIS_URL=redis://redis:6379
API_KEY=sk-real-key-here
```

### 2.2 .gitignore 配置

```gitignore
# .gitignore
.env
.env.local
.env.*.local

# 保留模板文件
!.env.example
```

### 2.3 初始化流程

```bash
# 新同事入职：
git clone <repo>
cp .env.example .env        # 从模板创建
vim .env                    # 填入实际配置
docker compose up -d        # 启动
```

## 三、不同环境的配置策略

### 3.1 多环境文件

```
项目结构：
├── .env.example        # 模板（提交到 Git）
├── .env.development    # 开发配置（不提交）
├── .env.staging        # 测试配置（不提交）
├── .env.production     # 生产配置（不提交）
└── compose.yml
```

```yaml
# compose.yml
services:
  app:
    env_file:
      - .env.${NODE_ENV:-development}
```

```bash
# 开发环境
NODE_ENV=development docker compose up -d

# 测试环境
NODE_ENV=staging docker compose up -d
```

### 3.2 Compose 文件分离

```
├── compose.yml              # 基础配置
├── compose.override.yml     # 开发环境覆盖（自动加载）
├── compose.prod.yml         # 生产环境覆盖
```

```yaml
# compose.yml（基础）
services:
  app:
    build: .
    environment:
      DATABASE_URL: ${DATABASE_URL}

# compose.override.yml（开发环境，自动加载）
services:
  app:
    volumes:
      - ./src:/app/src
    environment:
      NODE_ENV: development

# compose.prod.yml（生产环境）
services:
  app:
    environment:
      NODE_ENV: production
    restart: unless-stopped
```

```bash
# 开发环境（自动加载 override）
docker compose up -d

# 生产环境
docker compose -f compose.yml -f compose.prod.yml up -d
```

## 四、安全最佳实践

### 4.1 不要做的事

```
❌ 在 compose.yml 中硬编码密码
   environment:
     DB_PASSWORD: mysecretpassword

❌ 在 Dockerfile 中写死密钥
   ENV API_KEY=sk-1234567890

❌ 把 .env 提交到 Git
   git add .env

❌ 在日志中打印敏感信息
   console.log(process.env.API_KEY)
```

### 4.2 应该做的事

```
✅ 使用 .env 文件，不提交到 Git
✅ 提供 .env.example 作为模板
✅ 运行时通过环境变量传入密钥
✅ 使用 Docker Secrets 管理敏感数据（Swarm 模式）
✅ 定期轮换密钥
```

```yaml
      - PORT=${PORT:-3000}
```

```bash
# 测试默认值
```

## 常见误区

- **".env 文件和 .env.example 内容一样"**：`.env.example` 是模板，用占位符或默认值（如 `password`），提交到 Git。`.env` 是实际配置，包含真实密码，绝不提交。
- **"环境变量设置后容器内就能用"**：Compose 中的 `environment` 和 `env_file` 只在容器启动时注入。如果应用在启动前就读取环境变量（如构建时），需要用 `ARG` 而非 `ENV`。
- **"所有配置都应该放环境变量"**：环境变量适合密钥、连接字符串等需要跨环境变化的配置。固定配置（如日志格式）直接写在代码或配置文件里更清晰。
- **"docker compose down -v 只是清理缓存"**：`-v` 会删除所有 Volume，包括数据库数据。这是不可逆操作，执行前必须确认。

---

## 工程建议

- **用 `${VARIABLE:-default}` 提供默认值**：让 compose.yml 在没有 `.env` 文件时也能跑，降低新人上手门槛。
- **在 CI/CD 中用平台的 secrets 管理**：GitHub Actions 用 Secrets，GitLab CI 用 Variables，不要把生产密码写在 `.env` 文件里提交。
- **用 Compose 文件分离管理多环境**：`compose.yml`（基础）+ `compose.override.yml`（开发覆盖，自动加载）+ `compose.prod.yml`（生产覆盖），比多份 `.env` 文件更清晰。
- **定期轮换密钥**：数据库密码、API Key 应该定期更换。用环境变量管理密钥，更换时只需要改配置，不需要改代码。

---

## 小结

1. **三种方式**：直接定义、env_file、变量替换
2. **.env 文件**：敏感配置集中管理，不提交到 Git
3. **.env.example**：作为模板提交到 Git，方便团队协作
4. **不同环境**：使用不同 .env 文件或 Compose 文件分离

## 参考答案

### 练习一

**思路**：创建 `.env.example` 模板文件和实际 `.env` 文件，在 compose.yml 中通过变量替换读取环境变量，验证不同配置在容器中生效。

**答案**：

```bash
# 1. 创建 .env.example（提交到 Git 的模板）
cat > .env.example << 'EOF'
NODE_ENV=development
PORT=3000
DATABASE_URL=postgres://postgres:password@postgres:5432/mydb
EOF

# 2. 创建 .env（实际使用，不提交到 Git）
cp .env.example .env
# 编辑 .env，将 password 改为实际密码
sed -i 's/password/real_secret/' .env
```

```yaml
# compose.yml
services:
  app:
    image: node:18-alpine
    command: sh -c "env | grep -E 'NODE_ENV|PORT|DATABASE_URL' && sleep 3600"
    environment:
      - NODE_ENV=${NODE_ENV}
      - PORT=${PORT}
      - DATABASE_URL=${DATABASE_URL}
```

```bash
# 3. 启动服务
docker compose up -d

# 4. 验证环境变量注入
docker compose exec app env | grep DATABASE_URL
# 预期输出包含 real_secret，而非 password

docker compose exec app env | grep NODE_ENV
# 预期输出：NODE_ENV=development

# 清理
docker compose down
```

**要点**：
- `.env.example` 用占位符密码（`password`），提交到 Git 作为模板
- `.env` 用真实密码，必须加入 `.gitignore`
- compose.yml 中 `${DATABASE_URL}` 从 `.env` 文件读取值
- 新同事入职流程：`cp .env.example .env` → 修改密码 → `docker compose up -d`

### 练习二

**思路**：使用 `${VARIABLE:-default}` 语法为环境变量设置默认值，验证默认值和自定义值两种情况。

**答案**：

```yaml
# compose.yml
services:
  app:
    image: node:18-alpine
    command: sh -c "echo NODE_ENV=$NODE_ENV PORT=$PORT && sleep 3600"
    environment:
      - NODE_ENV=${NODE_ENV:-development}
      - PORT=${PORT:-3000}
```

```bash
# 情况一：不设置任何环境变量，使用默认值
docker compose up -d
docker compose exec app sh -c "echo NODE_ENV=$NODE_ENV PORT=$PORT"
# 预期输出：NODE_ENV=development PORT=3000

docker compose down

# 情况二：通过命令行传入自定义值
NODE_ENV=staging PORT=8080 docker compose up -d
docker compose exec app sh -c "echo NODE_ENV=$NODE_ENV PORT=$PORT"
# 预期输出：NODE_ENV=staging PORT=8080

docker compose down

# 情况三：在 .env 文件中设置
echo -e "NODE_ENV=production\nPORT=4000" > .env
docker compose up -d
docker compose exec app sh -c "echo NODE_ENV=$NODE_ENV PORT=$PORT"
# 预期输出：NODE_ENV=production PORT=4000

docker compose down
rm .env
```

**要点**：
- `${NODE_ENV:-development}` 表示如果 `NODE_ENV` 未设置，则使用 `development` 作为默认值
- 环境变量优先级：命令行 > .env 文件 > 默认值
- 默认值让 compose.yml 在没有 `.env` 文件时也能正常运行
- `${VARIABLE:?error}` 会在变量未设置时报错，适合必须配置的变量（如数据库密码）
- 用字典格式 `environment:` 时，值必须加引号（`PORT: "${PORT:-3000}"`）
