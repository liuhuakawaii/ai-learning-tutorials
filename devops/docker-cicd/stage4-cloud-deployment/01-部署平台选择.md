# 第一课：部署平台选择

> **课程定位**：了解不同部署方案的优缺点，做出合理选择
> **前置知识**：Docker、Compose、CI/CD 基础（前三个阶段）
> **预计时长**：25 分钟

---

## 场景引入

你的项目在本地跑得很好，CI/CD 流水线也搭好了，现在需要部署到线上让用户访问。你打开云平台的控制台，看到 VPS、ECS、Cloud Run、Lambda、Vercel、Railway 十几种选择，价格从免费到几百美元不等。你开始纠结：选哪个？便宜的怕不稳定，贵的预算有限，简单的怕被锁定，复杂的怕学不会。

---

## 学习目标

1. 了解主流部署平台的特点
2. 理解不同场景下的最佳选择
3. 掌握成本和复杂度的权衡

## 二、方案对比

### 2.1 VPS（虚拟私有服务器）

```
代表：DigitalOcean、Linode、Vultr、阿里云 ECS

  ┌─────────────────────────────────────────────┐
  │  VPS                                         │
  │                                              │
  │  ✅ 完全控制                                  │
  │  ✅ 成本固定（$5-20/月）                      │
  │  ✅ 可以运行任何东西                          │
  │  ✅ 适合学习                                  │
  │                                              │
  │  ❌ 需要自己管理服务器                        │
  │  ❌ 需要自己配置安全                          │
  │  ❌ 扩展需要手动操作                          │
  └─────────────────────────────────────────────┘

  适合：个人项目、小团队、学习、预算有限
```

### 2.2 容器服务

```
代表：AWS ECS、Google Cloud Run、阿里云 AC

  ┌─────────────────────────────────────────────┐
  │  容器服务                                    │
  │                                              │
  │  ✅ 只需提供 Docker 镜像                      │
  │  ✅ 自动扩缩容                               │
  │  ✅ 不用管服务器                              │
  │                                              │
  │  ❌ 比 VPS 贵                                │
  │  ❌ 配置比 PaaS 复杂                          │
  └─────────────────────────────────────────────┘

  适合：中型项目、需要自动扩展
```

### 2.3 PaaS（平台即服务）

```
代表：Railway、Render、Fly.io、Vercel（前端）

  ┌─────────────────────────────────────────────┐
  │  PaaS                                        │
  │                                              │
  │  ✅ 最简单：git push 就部署                   │
  │  ✅ 自动 HTTPS、域名                          │
  │  ✅ 内置数据库、Redis                         │
  │  ✅ 适合快速启动                              │
  │                                              │
  │  ❌ 比 VPS 贵                                │
  │  ❌ 灵活性有限                                │
  │  ❌ 可能有供应商锁定                          │
  └─────────────────────────────────────────────┘

  适合：快速原型、个人项目、不想管服务器
```

### 2.4 Serverless

```
代表：AWS Lambda、Vercel Functions、Cloudflare Workers

  ┌─────────────────────────────────────────────┐
  │  Serverless                                  │
  │                                              │
  │  ✅ 按使用量付费                              │
  │  ✅ 自动扩缩容到零                            │
  │  ✅ 不用管服务器                              │
  │                                              │
  │  ❌ 冷启动延迟                               │
  │  ❌ 有执行时间限制                            │
  │  ❌ 不适合长连接                              │
  └─────────────────────────────────────────────┘

  适合：API、事件驱动、流量波动大
```

## 常见误区

- **"PaaS 比 VPS 好"**：PaaS 简单但贵，VPS 复杂但便宜且灵活。选择取决于项目阶段和团队能力。学习阶段用 VPS，快速验证用 PaaS。
- **"Serverless 最便宜"**：流量低时确实便宜，但流量突增时费用可能暴涨。而且冷启动延迟对用户体验有影响，不适合对响应时间敏感的 API。
- **"选了就不能换"**：用 Docker 容器化后，从一个平台迁移到另一个平台的成本很低。不要因为怕锁定就不做选择，先跑起来再说。
- **"云平台会自动帮你扩展"**：自动扩展需要正确配置，包括健康检查、资源限制、扩展策略。没有配置好就期望自动扩展，可能在流量高峰时反而挂掉。

---

## 工程建议

- **从 VPS 开始学习**：$5-10/月的 VPS 能让你理解完整的部署流程，包括服务器配置、反向代理、HTTPS、备份等。这些技能在任何平台都适用。
- **用 Docker 标准化部署**：无论选哪个平台，Docker 镜像都是标准的交付单元。先把项目容器化，再考虑部署到哪里。
- **前端静态站用 CDN**：Vercel、Netlify、Cloudflare Pages 提供免费的 CDN 和 HTTPS，比自己搭 Nginx 托管静态文件更快更稳定。
- **数据库用托管服务**：自建数据库的运维成本很高（备份、升级、监控）。预算允许的话，用云平台的托管数据库（RDS、PlanetScale）更省心。

---

## 小结

1. **VPS**：完全控制，成本低，需要自己管理
2. **PaaS**：最简单，git push 部署，成本较高
3. **容器服务**：平衡方案，适合中型项目
4. **本课程**：使用 VPS，学习价值最高
