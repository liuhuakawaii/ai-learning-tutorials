# CI/CD 流水线设计 — 课程毕业项目

## 项目目标

为一个真实项目（或课程提供的示例项目）设计并实现完整的 GitHub Actions CI/CD 流水线，覆盖代码检查、测试、构建、安全扫描、部署等阶段。项目覆盖 CI/CD 课程中的核心知识：工作流编排、矩阵构建、缓存策略、密钥管理、环境部署、制品管理等。

## 技术栈

- **CI/CD 平台**：GitHub Actions
- **示例项目**：Node.js Web 应用（Express + React）
- **容器化**：Docker
- **部署目标**：Docker Hub + 云服务器（或 GitHub Pages / Vercel）
- **安全扫描**：Trivy（容器镜像）、CodeQL（代码）、Dependabot（依赖）
- **测试**：Vitest（单元）、Playwright（E2E）

## 核心功能

### 模块一：代码质量流水线

- ESLint + Prettier 代码检查
- TypeScript 类型检查
- 提交信息规范检查（conventional commits）
- PR 标签自动打标（根据变更文件路径）

### 模块二：测试流水线

- 单元测试（Vitest），覆盖率报告上传
- E2E 测试（Playwright），失败时截图保存为 Artifact
- 矩阵测试：Node.js 18/20 × Ubuntu/macOS
- 测试结果在 PR 中以评论形式展示

### 模块三：构建与发布

- Docker 镜像构建，多平台（linux/amd64, linux/arm64）
- 语义化版本标签（基于 Git tag 或 conventional commits）
- Docker Hub 推送（仅 main 分支和 tag）
- 构建缓存策略（GitHub Actions Cache / registry cache）

### 模块四：安全扫描

- 容器镜像漏洞扫描（Trivy）
- 代码安全分析（CodeQL）
- 依赖漏洞检查（Dependabot alerts）
- Secret 扫描（检测硬编码的密钥/密码）
- 扫描结果在 Security tab 可见

### 模块五：部署流水线

- Staging 环境自动部署（push to main）
- Production 环境手动审批部署（GitHub Environments + required reviewers）
- 部署后健康检查
- 部署失败自动回滚（或手动触发回滚工作流）
- 环境变量和密钥通过 GitHub Secrets 管理

### 模块六：工作流复用

- 可复用的 Composite Action（如 setup-node-with-cache）
- 可复用的 Workflow（reusable workflow）
- Shared environment variables 管理

## 阶段交付物

| 阶段 | 交付物 | 路径 |
|------|--------|------|
| 阶段一 | 代码质量工作流 | `.github/workflows/lint.yml` |
| 阶段二 | 测试工作流 | `.github/workflows/test.yml` |
| 阶段三 | 构建与发布工作流 | `.github/workflows/build.yml` |
| 阶段四 | 安全扫描工作流 | `.github/workflows/security.yml` |
| 阶段五 | 部署工作流 | `.github/workflows/deploy.yml` + `reports/final-report.md` |

## 验收标准

- [ ] PR 提交时自动触发 lint 和 test 工作流
- [ ] 测试工作流支持矩阵构建（至少 2 个 Node.js 版本）
- [ ] main 分支合并后自动构建 Docker 镜像并推送到 Docker Hub
- [ ] 安全扫描工作流能检测容器漏洞和代码安全问题
- [ ] 部署工作流有 staging 自动部署和 production 手动审批
- [ ] 部署失败时有回滚机制或回滚工作流
- [ ] 工作流使用了缓存策略（npm cache、Docker layer cache）
- [ ] 密钥通过 GitHub Secrets 管理，不在代码中硬编码
- [ ] 有可复用的 Composite Action 或 Reusable Workflow
- [ ] 项目可通过 `node scripts/check.js` 验证结构完整性
