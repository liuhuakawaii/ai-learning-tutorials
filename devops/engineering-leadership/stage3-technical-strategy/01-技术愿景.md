# 技术愿景

> 前置知识：管理转型基础（阶段一），团队建设基础（阶段二）

## CEO 的一个问题

你刚被提拔为技术总监。CEO 在季度会上问你："我们明年的技术方向是什么？"

你张了张嘴，发现自己脑子里只有"重构那个老系统"和"上 K8s"。这些是战术动作，不是方向。CEO 需要的是一句话能说清楚的愿景——团队 50 个人每天写的代码，最终要把公司带向哪里。

技术愿景不是技术方案。它是技术方向的北极星。

## 什么是技术愿景

技术愿景回答一个核心问题：**未来 1-3 年，技术团队要为业务创造什么独特价值？**

```
不叫技术愿景的东西：
  ✗ "我们要上微服务"                    → 这是技术选型
  ✗ "我们要把测试覆盖率提到 80%"         → 这是质量目标
  ✗ "我们要用 Rust 重写后端"            → 这是技术决策

叫技术愿景的东西：
  ✓ "让新功能从代码提交到上线不超过 1 小时"  → 衡量的是业务价值
  ✓ "让任何工程师都能在 30 分钟内搭建新服务"  → 衡量的是开发体验
  ✓ "让系统能支撑 10 倍用户增长而不重构"     → 衡量的是业务容量
```

好的技术愿景有两个特征：**用业务语言描述**（不是技术术语），**可衡量**（有明确的完成标准）。

## 技术愿景的三个层次

```
Layer 1: 技术战略（1-3 年）
  "让系统能支撑 10 倍用户增长"
  └── 由技术总监/CTO 定义

Layer 2: 技术路线图（6-12 个月）
  "Q1 完成数据库读写分离，Q2 完成核心服务拆分"
  └── 由技术经理和架构师制定

Layer 3: 技术执行（每个 Sprint）
  "这个 Sprint 完成用户服务的 API 网关迁移"
  └── 由团队执行
```

技术愿景属于 Layer 1。它不规定具体怎么做，而是规定往哪个方向走。

## Now-Next-Later 框架

定义技术路线图的实用框架：

```
Now（0-3 个月）：当前正在做的、必须做的
  - 修复影响业务的技术债务
  - 完成在进行中的技术改造
  - 建立基本的工程规范

Next（3-6 个月）：计划中的、优先级高的
  - 支撑业务增长的技术改造
  - 提升开发效率的工具和流程
  - 关键系统的架构升级

Later（6-12 个月）：探索性的、需要条件成熟的
  - 新技术栈的试点
  - 大规模架构重构
  - 创新项目的技术准备
```

## 技术愿景与业务 OKR 对齐

技术愿景不能脱离业务。你需要把技术目标翻译成业务语言：

```
业务 OKR：
  O: 提升用户留存率到 85%
  KR1: 页面加载时间从 3s 降到 1s
  KR2: 接口成功率从 99.5% 提升到 99.9%

技术愿景对齐：
  技术行动 1: 前端性能优化（CDN、代码分割、SSR）
  技术行动 2: 接口稳定性治理（重试、熔断、降级）
  技术行动 3: 监控告警体系建设（快速发现和恢复）
```

对齐不是"被动响应业务需求"，而是"主动提出技术能为业务做什么"。

## 用非技术人员能理解的语言讲述

技术愿景最大的挑战不是定义，而是沟通。你需要让产品经理、销售、CEO 都能理解你在做什么。

```
不推荐（技术语言）：
  "我们要把单体应用拆成微服务，用 Kubernetes 编排，
   引入 Service Mesh 做流量管理。"

推荐（业务语言）：
  "目前改一个功能要重新部署整个系统，风险大、耗时长。
   我们计划把系统拆成独立的小模块，改哪个就只部署哪个。
   预计能把新功能上线时间从 2 周缩短到 2 天。"
```

## 练习

### 练习一：写技术愿景

为你当前的团队写一份技术愿景。要求：一句话能说清楚，用业务语言描述，有可衡量的标准。

### 练习二：Now-Next-Later

用 Now-Next-Later 框架，为你当前的团队制定技术路线图。每个阶段列出 3 个关键行动。

### 练习三：对齐业务

找一个你公司当前的业务 OKR，写出技术团队如何支撑这个 OKR 的具体行动。

---

## 参考答案

### 练习一

示例："在 6 个月内，让任何新功能从代码合并到上线的时间不超过 30 分钟，目前这个时间是 3 天。"

衡量标准：部署频率从每周 1 次提升到每天 3+ 次；部署失败率从 15% 降到 2%。

### 练习二

示例（电商后端团队）：

Now：修复订单系统的技术债务（每周分配 20% 容量）；建立 CI/CD 流水线；建立 Code Review 规范。

Next：数据库读写分离（支撑 10 倍流量）；订单系统拆分（独立扩缩容）；监控告警体系建设。

Later：多活架构探索；实时推荐系统技术预研；Serverless 试点。

### 练习三

业务 OKR："Q4 新用户注册转化率从 30% 提升到 45%"

技术行动：
1. 注册接口性能优化（P99 从 2s 降到 500ms）
2. 第三方登录集成（微信、Google）
3. 注册流程 A/B 测试框架
4. 短信验证码成功率监控和优化
