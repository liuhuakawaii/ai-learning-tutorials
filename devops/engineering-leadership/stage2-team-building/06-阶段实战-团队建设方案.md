# 阶段实战：团队建设方案

> 前置知识：招聘与面试、团队文化、绩效管理、人才培养、团队扩展（第 1-5 课）

## 你要做什么

你被任命为一家 B2B SaaS 公司的技术总监，团队 18 名工程师。前任因为管理风格问题离职，留下了一些问题：

- 人才盘点显示 3 人处于"待发展"状态，2 人有离职倾向
- 没有明确的绩效管理流程，年终评估全凭主观
- 过去半年入职的 4 名新人中 2 人已离职
- 产品 VP 抱怨"交付太慢"，工程师抱怨"需求总在变"

CEO 要求你在一个月内提交一份完整的团队建设方案。

你需要输出的不是理论框架，而是能直接执行的方案：诊断现状、制定计划、设计里程碑、预估资源。

## 第一步：团队诊断

用以下框架对团队进行评估：

```
团队健康度评估（每个维度 1-5 分）

人才密度：
  □ 高绩效工程师占比（目标 ≥ 30%）
  □ 关键岗位有备份人选
  □ 新人存活率（6 个月内 ≥ 80%）

流程成熟度：
  □ 有明确的开发流程（Code Review、CI/CD）
  □ 有可重复的发布流程
  □ 有技术债务管理机制

团队士气：
  □ 主动离职率（年度 ≤ 15%）
  □ 团队满意度调查得分
  □ 跨团队协作满意度

交付能力：
  □ 需求交付周期（从需求确认到上线）
  □ 线上事故频率和恢复时间
  □ 技术债务对交付速度的影响
```

## 第二步：制定方案

### 人才建设

| 问题 | 行动 | 时间线 | 成功标准 |
|------|------|--------|---------|
| 3 人待发展 | 制定个人发展计划，每月 review | 第 1 个月启动 | 6 个月内至少 2 人达标 |
| 2 人有离职倾向 | 1:1 了解原因，针对性解决 | 第 1 周 | 留住至少 1 人 |
| 新人存活率低 | 改进入职流程，指定 buddy | 第 2 周 | 6 个月存活率 ≥ 80% |
| 关键岗位无备份 | 知识分享 + 结对编程 | 持续 | 每个关键模块 ≥ 2 人熟悉 |

### 流程建设

| 问题 | 行动 | 时间线 | 成功标准 |
|------|------|--------|---------|
| 没有绩效流程 | 建立季度 OKR + 月度 1:1 | 第 1 个月 | 100% 覆盖率 |
| 交付慢 | 梳理需求流程，消除瓶颈 | 第 2 个月 | 交付周期缩短 30% |
| 技术债务 | 建立债务清单，每个 Sprint 分配 20% 容量 | 第 1 个月 | 债务不再增长 |

### 文化建设

| 问题 | 行动 | 时间线 | 成功标准 |
|------|------|--------|---------|
| 工程师抱怨需求总变 | 建立需求变更流程和影响评估 | 第 1 个月 | 变更导致的返工减少 50% |
| 跨团队协作差 | 建立跨团队同步机制 | 第 2 个月 | 协作满意度提升 |

## 第三步：实施路线图

```
第 1 周：紧急止血
  ├── 和 2 个有离职倾向的人 1:1
  ├── 和产品 VP 对齐需求流程
  └── 启动团队满意度调查

第 2-4 周：基础建设
  ├── 建立绩效管理流程
  ├── 改进入职流程
  ├── 建立 Code Review 规范
  └── 制定技术债务清单

第 2-3 月：能力提升
  ├── 为每人制定发展计划
  ├── 建立知识分享机制
  ├── 推动跨团队协作改进
  └── 启动技术债务清理

第 4-6 月：持续优化
  ├── 第一轮绩效 review
  ├── 评估方案效果并调整
  └── 向 CEO 汇报成果
```

## 练习

### 练习一：诊断你的团队

用团队健康度评估框架，为你当前的团队打分。找出最弱的两个维度，为每个维度制定一个可在一个月内见效的改进方案。

### 练习二：新人入职方案

设计一份新人入职方案（第一个月），包括：谁负责带、学什么、怎么验证、什么时候可以独立承担任务。

---

## 参考答案

### 练习一

没有标准答案。关键是诚实评估，不要给自己的团队"人情分"。最弱维度通常集中在"流程成熟度"或"团队士气"——这两个是管理者最能直接影响的。

### 练习二

```
新人入职方案（第一个月）

Week 1：环境与背景
  - Buddy 带领搭建开发环境
  - 阅读产品文档和架构文档
  - 完成一个小 bug fix 并提交 PR
  - 参加所有团队会议（旁听）

Week 2：上手核心模块
  - 和 buddy 结对开发一个功能
  - 学习 CI/CD 流程，自己提交一次部署
  - Code Review 3 个 PR（学习团队代码风格）

Week 3：独立开发
  - 独立完成一个小需求
  - 提交 PR 并通过 Code Review
  - 写一份"入职笔记"——记录遇到的问题和解决方案

Week 4：验证与反馈
  - 和经理 1:1，回顾第一个月
  - 收集 buddy 和同事的反馈
  - 制定第二个月的学习计划

成功标准：
  - 能独立完成小需求
  - 理解团队的开发流程
  - 和至少 3 个同事建立了工作关系
```
