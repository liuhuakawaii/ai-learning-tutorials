# 第二课：团队文化

## 场景引入

你加入一家快速发展的创业公司，担任技术VP。公司墙上贴着"创新、协作、客户第一"的价值观标语，但你很快发现现实和标语完全不一致：

技术方案讨论会上，一个初级工程师提出了一个不同的架构思路，资深工程师直接说"你才来多久，懂什么"，从此再也没有人在会上提反对意见。出了线上事故，第一反应不是复盘，而是找人背锅，导致大家宁愿藏着问题不报。

你意识到，文化不是贴在墙上的标语，而是团队在日常决策中真正体现出来的行为准则。

## 学习目标

完成本课学习后，你能够：

1. 理解价值观定义与落地的本质区别
2. 掌握心理安全的概念及其对团队绩效的影响
3. 运用具体方法建设团队的心理安全
4. 理解多样性与包容性对技术决策的价值
5. 应对远程团队文化建设的特殊挑战
6. 设计文化面试的评估方法

## 一、价值观：不是贴在墙上，而是体现在决策中

### 1.1 价值观的真正含义

价值观是**当面临两难选择时，你优先选择什么**。

如果公司声称"质量第一"，但每次上线前发现bug时都选择"先上再说"，那真正的价值观就是"速度优先"。判断一个团队的真实价值观，不要听他们说什么，要看他们**在冲突时怎么选**。

### 1.2 如何定义团队价值观

**第一步：收集真实故事**——找团队中公认做得好的人，问他们最骄傲的决策是什么。

**第二步：提炼3-5条核心价值观**——每条要有明确的行为定义和判断标准。

**第三步：在关键决策中验证**——每次做重大决策时，明确引用价值观作为依据。

### 1.3 价值观冲突的处理

明确优先级和边界条件：
```
1. 用户安全和数据安全（绝对不能妥协）
2. 代码质量和可维护性（正常情况下优先）
3. 交付速度（在1和2满足的前提下追求）
```

## 二、心理安全：Google发现了什么

### 2.1 Project Aristotle

2015年Google的Project Aristotle研究了180多个团队，发现**最重要的因素不是团队成员的个人能力，而是心理安全**。

心理安全：**团队成员相信，在团队中承担人际风险是安全的**。

什么是"人际风险"？提出不成熟的想法、承认犯了错误、承认不懂某个东西、提出不同观点、指出团队中存在的问题。

### 2.2 心理安全低的典型表现

```
产品经理说："这个需求下周必须上线。"
技术负责人心里觉得不可能，但嘴上说："好的，我们尽量。"
其他工程师互相对视，没人说话。
结果：加班两周，质量堪忧。
```

### 2.3 心理安全高的团队

```
技术负责人说："我理解业务压力，但下周上线意味着砍掉测试环节。
我的建议是下周先上核心功能，其余第二周上。大家怎么看？"
初级工程师说："我有一个想法，也许可以用XX方案简化实现……"
```

## 三、建设心理安全的具体方法

### 3.1 Leader先认错

```
"上周我在技术评审会上否定了小王的方案，但后来我自己尝试后
发现他的思路其实是对的。我在评审时过于武断了。"
```

### 3.2 鼓励提问，不惩罚提问

当有人提出"基础"问题时，不要说"你都不知道？"，而是说"这是个好问题"。作为leader，你也可以主动问"基础"问题来降低门槛。

### 3.3 不惩罚失败，但要求复盘

建立原则：犯错不是问题，藏着不报才是问题。所有线上事故都做无指责复盘（Blameless Postmortem）。

### 3.4 建立反馈文化

- 定期匿名满意度调查
- 1:1中主动问"我有什么做得不好的地方？"
- 收到反馈时公开感谢并展示改变
- 使用SBI模型给反馈：具体事例+行为+影响

## 四、多样性与包容性

### 4.1 为什么多样性重要

- **决策质量**：不同背景的人从不同角度看问题
- **创新能力**：创新往往来自不同领域的交叉
- **人才池扩大**：排除特定群体意味着排除80%以上的候选人

### 4.2 包容性的具体做法

**招聘层面**：去除JD偏见语言，面试团队有多样性，使用结构化面试。

**团队层面**：确保每个人有发言机会，采用"先写后说"方式，关注被频繁打断的人。

**决策层面**：主动寻找反对意见，建立"红队"机制，记录决策过程。

## 五、远程团队文化建设

### 5.1 特殊挑战

缺少非正式交流、沟通容易产生误解、新人融入困难、"看不见的人"容易被忽略。

### 5.2 具体做法

**建立沟通节奏**：每日站会（可异步）、每周团队周会、每月全员会议、每季度线下团建。

**创造非正式交流**：#random频道、virtual coffee配对、生日庆祝。

**文档化一切**：会议有记录、决策有文档、流程有指南、新人onboarding文档。

**关注"看不见的人"**：1:1不只聊工作，注意时区差异，定期做团队健康度调查。

## 六、文化面试

### 6.1 行为面试问题设计

**关于协作**：
```
"请描述一次你与同事产生技术分歧的经历。你们各自的观点是什么？
最终是怎么解决的？"
```

**关于失败**：
```
"请描述一次你在工作中犯的比较大的错误。你是怎么发现的？
采取了什么补救措施？从中学到了什么？"
```

**关于学习**：
```
"请描述一次你需要快速学习一个不熟悉的技术的经历。
你是怎么规划学习路径的？遇到了什么困难？"
```

### 6.2 评估标准

```
主动性（1-5分）：5分主动发现问题并推动解决，1分需要持续督促
协作习惯（1-5分）：5分善于倾听并协调达成共识，1分协作困难
学习意愿（1-5分）：5分有清晰学习计划并主动分享，1分不感兴趣
价值观匹配（1-5分）：5分多维度高度一致，1分核心价值观冲突
```

## 常见误区

### 误区一：文化就是团建和聚餐

真正的文化体现在日常决策中：业务压力大时选择牺牲质量还是砍需求？

### 误区二：文化可以快速建立

文化需要6-12个月持续践行才能看到明显变化。

### 误区三：所有人都要一样

文化一致不是性格一致。你需要价值观一致，但思维方式可以多样化。

### 误区四：远程团队没法建文化

可以建立，但需要更刻意的设计：更多文档化、更主动沟通、更有意识创造非正式交流。

## 工程建议

1. **文化审计**：每半年对比"我们说的文化"和"我们实际的文化"
2. **无指责复盘**：所有P0/P1事故做blameless postmortem
3. **定期pulse survey**：每月匿名调查，追踪心理安全趋势
4. **价值观考核**：绩效评估中加入价值观维度，占比20-30%
5. **新人onboarding**：安排团队文化专题分享
6. **记录决策**：重大决策记录在案，包括决策理由和备选方案

## 小结

团队文化不是口号，是行为。核心要点：

- 价值观要体现在冲突时的选择中
- 心理安全是团队效能的第一要素
- 建设心理安全从leader做起：先认错、鼓励提问、不惩罚失败
- 多样性有实实在在的业务价值
- 远程团队需要更有意识地设计文化建设机制
- 文化面试关注行为和价值观

## 练习

### 练习一：文化审计

你的团队声称"质量第一"，但你观察到：上季度有3次"先上线再说"、代码review经常被跳过、测试覆盖率从80%降到45%。团队的真实价值观是什么？你会采取哪些措施？

### 练习二：心理安全场景模拟

技术方案评审中，初级工程师小李提出方案被资深工程师老张直接否定："太天真了，你根本不了解我们的系统。"小李之后再也没发言。你会如何当场介入？事后分别和两人说什么？

### 练习三：设计文化面试问题

团队核心价值观之一是"持续学习"。请设计3个行为面试问题，并给出评估标准。

## 参考答案

### 练习一

**真实价值观分析**：团队的真实价值观是"速度优先"。证据："先上线再说"选择速度、跳过review选择进度、覆盖率下降无人关注。

**改进措施**：
1. 明确质量红线（安全模块100%测试覆盖、P0事故模块不允许跳过review）
2. "先上线"决策必须记录技术债，下个迭代优先偿还
3. 测试覆盖率和review通过率放入团队看板，每周review
4. leader在下一个"先上线"场景中坚持先做质量保障

### 练习二

**当场介入**：
```
"老张，我理解你看到了方案的风险。我们先听完小李的完整思路，
然后一起讨论。小李，请继续。"
```

**事后与小李**：确认他的表达是对的，鼓励继续提出不同观点，教他如何回应质疑。

**事后与老张**：肯定技术能力，但指出表达方式可能让新人不敢提意见，建议用"这个方案可能遇到XX问题"替代"太天真了"。

### 练习三

**问题一**："请描述一次你需要快速学习不熟悉技术的经历。你怎么规划学习路径的？"
评估：5分有清晰计划+边学边实践+主动分享；3分完成任务但被动学习；1分需要反复督促。

**问题二**："请描述一次你犯了技术错误的经历。怎么发现的？采取了什么措施？"
评估：5分坦诚面对+深入分析+应用教训；3分承认并改正但缺乏反思；1分归咎外部因素。

**问题三**："请描述一次你主动分享知识的经历。为什么决定分享？"
评估：5分有持续分享习惯且有深度；3分偶尔分享被要求才做；1分很少分享。
