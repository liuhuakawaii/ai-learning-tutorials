# 第三课：绩效管理

## 场景引入

又到了季度绩效评估的时候。你看着团队10个人的名单，陷入了沉思。

上个季度你用了一套简单的评分制（1-5分），结果引发了不少争议。小王觉得自己承担了最多的线上问题排查，应该拿高分；小李觉得自己主导了新架构的设计，也应该拿高分。更麻烦的是，你发现自己对最近两个月发生的事情印象更深刻，而季度初的事情已经记不太清了——这是典型的近因效应。

你还需要给一个绩效持续低于预期的工程师做沟通，但你不知道该怎么开口。上个季度你选择了"再给一次机会"，但这已经是连续第三个季度了。

## 学习目标

完成本课学习后，你能够：

1. 正确设定OKR，避免常见的写法错误
2. 设计和实施360度反馈与绩效校准会议
3. 处理低绩效情况，包括PIP的制定和沟通
4. 识别和减少绩效评估中的常见偏见
5. 使用SBI模型进行绩效沟通

## 一、OKR设定

### 1.1 什么是OKR

OKR（Objectives and Key Results）是一套目标管理框架：

- **Objective（目标）**：你想达成什么？应该是鼓舞人心的、定性的
- **Key Results（关键结果）**：怎么衡量你达成了？应该是可量化的、有时限的

```
Objective：打造高可用的订单系统，让用户下单体验丝滑流畅

Key Results：
KR1：订单系统P99延迟从500ms降到200ms
KR2：订单相关的P0事故从每季度3次降到0次
KR3：用户下单成功率从98.5%提升到99.5%
```

### 1.2 OKR的常见错误

**错误一：把任务当Key Results**

```
反例：
KR1：完成数据库分库分表改造
KR2：上线Redis缓存层
这些是任务（Task），不是结果（Result）。

正例：
KR1：订单查询P99延迟从800ms降到200ms
KR2：数据库CPU使用率峰值从90%降到60%
```

**错误二：Key Results太多**——一个Objective下面不要超过5个KR。

**错误三：OKR设定后就不管了**——需要定期review（通常每月一次）。

**错误四：把OKR和绩效考核直接挂钩**——如果直接挂钩，大家会倾向于设低目标来"保底"。

### 1.3 工程团队OKR示例

```
Objective：提升平台稳定性和可维护性

KR1：生产环境P0事故数从季度5次降到1次以内
KR2：MTTR（平均恢复时间）从2小时降到30分钟
KR3：核心服务测试覆盖率从55%提升到80%
```

## 二、绩效评估

### 2.1 360度反馈

360度反馈从多个来源收集评价：上级、同事、下属。

**实施要点**：
- 匿名收集，鼓励真实反馈
- 每人收到3-5人的反馈即可
- 反馈聚焦具体行为，不是泛泛评价
- 结果由直接主管综合整理后与被评估者沟通

### 2.2 绩效校准会议

校准会议的目的是**减少不同主管之间的评分差异**。流程：会前每位主管初步评分并准备事例 → 会中逐一讨论，其他主管提问 → 发现偏差则调整 → 会后一对一沟通结果。

### 2.3 绩效评分维度

```
业务结果（40%）：OKR完成情况、项目交付质量
技术贡献（30%）：代码质量、技术方案设计、技术债治理
团队协作（20%）：沟通能力、知识分享、跨团队合作
成长与影响力（10%）：技术学习、文化贡献、招聘面试
```

## 三、低绩效处理

### 3.1 PIP（绩效改进计划）

PIP不是"开除的前奏"，而是**给员工一个明确的改进机会和时间窗口**。

```
PIP模板：

一、绩效问题描述（具体、客观）
- 问题1：最近两个迭代中，3个需求都延期交付，平均延期5天
- 问题2：代码review中多次出现基础质量问题

二、期望改进的具体行为
- 行为1：每个需求开发前与产品经理确认验收标准
- 行为2：提交代码前自行完成checklist检查

三、支持措施
- 每周与主管30分钟1:1
- 安排资深工程师作为技术导师

四、评估标准
- 30天内：需求按时交付率达到80%
- 60天内：代码review通过率提升到90%

五、后果说明
如果PIP期满未达到标准，公司将考虑调整岗位或终止。
```

### 3.2 低绩效沟通技巧

```
第一步：直接但尊重地说明来意
"小王，今天我想和你聊聊最近的工作表现。"

第二步：用具体事例说明问题
"上个月的三个需求，平均延期了5天。"

第三步：倾听对方的解释
"我想先听听你的看法——你觉得是什么原因导致的？"

第四步：共同制定改进计划
"我们一起看看哪些支持措施对你最有帮助。"

第五步：明确后续安排
"接下来30天，我们每周做一次进度check-in。"
```

### 3.3 何时应该终止

PIP不是万能的。以下情况需要考虑终止：
- 员工能力与岗位要求差距过大，30-60天无法弥补
- 员工态度有问题，不愿意改进
- 与团队文化严重不匹配

长期容忍低绩效对团队伤害更大：高绩效员工会觉得"干好干坏一个样"。

## 四、绩效评估的常见偏见

### 4.1 近因效应

**表现**：对最近发生的事情印象更深刻，忽略整个评估周期。

**应对**：每周或每两周记录关键表现，评估前回顾整个周期的记录。

### 4.2 光环效应

**表现**：因为某方面特别突出，就认为所有方面都好。

**应对**：每个维度独立评估，使用360度反馈从不同角度获取信息。

### 4.3 刻板印象

**表现**：基于性别、年龄、学历等标签做出判断。

**应对**：评估时先看具体行为和数据，不看个人标签。

### 4.4 中间倾向

**表现**：为了避免冲突，给所有人都打中间分数（3/5）。

**应对**：校准会议上讨论评分差异，高绩效和低绩效都需要明确沟通。

## 五、绩效沟通的SBI模型

### 5.1 什么是SBI

- **S（Situation）**：什么场景下发生的
- **B（Behavior）**：具体的行为是什么
- **I（Impact）**：这个行为产生了什么影响

```
反例："你最近表现不太好，需要加油。"

正例：
"S：上周三的产品评审会上
B：你没有提前阅读PRD，在会上提出了几个PRD中已回答的问题
I：产品经理觉得准备工作没有被尊重，评审效率降低了"
```

### 5.2 SBI的使用场景

**正面反馈**：
```
"S：上个月的订单系统重构项目中
B：你主动梳理了所有技术风险点，并提前制定了回滚方案
I：项目上线非常顺利，零事故"
```

**改进反馈**：
```
"S：最近三个迭代中
B：你负责的需求都延期了2-3天
I：下游的测试和上线计划都被打乱，团队需要频繁调整排期"
```

### 5.3 SBI沟通注意事项

1. **描述行为，不要评判人格**："这段代码缺少空指针检查"而非"你不够细心"
2. **用数据说话**："最近三个需求平均交付12天，团队平均7天"
3. **及时反馈**：不要攒到季度考核才说
4. **双向沟通**：给完反馈后倾听对方的想法

## 常见误区

### 误区一：绩效考核就是打分

打分只是一个环节。完整的绩效管理包括：目标设定、过程辅导、绩效评估、结果应用。

### 误区二：PIP是开人的工具

PIP的本意是给员工明确的改进机会。把它当"走流程开人"的工具，团队信任度会急剧下降。

### 误区三：强制分布是万能的

强制分布在小团队中（<15人）可能不适用，更应该关注绝对标准而非相对排名。

## 工程建议

1. **持续反馈**：每周或每两周的1:1中就给出具体反馈
2. **记录关键事件**：用文档记录关键表现，评估时有据可依
3. **透明标准**：季度初就把评估标准和权重告诉团队
4. **校准会议**：每季度与其他主管做一次绩效校准
5. **PIP有温度**：明确支持措施，让员工感受到"公司在帮你改进"

## 小结

绩效管理不是"管人"，而是帮助团队聚焦目标、持续改进。核心要点：

- OKR要写结果而非任务，要定期review
- 360度反馈和校准会议能有效减少评估偏差
- 低绩效要及早介入，PIP是改进机会而非走流程开人
- 识别近因效应、光环效应、刻板印象等常见偏见
- SBI模型是绩效沟通的基本功：场景、行为、影响

## 参考答案

### 练习一

**思路**：检查OKR常见错误——把任务当KR、KR太多、缺少量化指标。

```
问题分析：
1. KR太多（7个），精力会分散
2. 大部分是任务而非结果
3. 缺少可量化的衡量标准

改进后：

Objective：建立系统化的技术深度和广度，成为团队技术骨干

KR1：主导完成一个架构优化项目，使目标模块P99延迟降低30%以上
KR2：在团队内完成3次技术分享，平均评分4/5以上
KR3：将Kubernetes应用到生产环境，完成至少2个服务容器化部署
```

### 练习二

**正面反馈**：
```
"S：这个季度的XX项目中
B：你独立完成了核心模块的架构设计，测试覆盖率达90%
I：项目提前一周上线，线上零事故"
```

**改进反馈**：
```
"S：最近几次团队会议和与产品经理的协作中
B：上周三需求评审会上你三次打断产品经理讲解；
   上周五讨论时语气比较激动，对方感觉被'怼'
I：产品经理现在不太愿意主动找你讨论方案，
   两位同事也减少了协作请求。我想听听你的看法？"
```

### 练习三

|------|--------|----------|----------|

| 沟通误解返工 | 2次/月 | 0次/月 | 0次/月 |

三、支持措施
- 每周主管30分钟1:1
