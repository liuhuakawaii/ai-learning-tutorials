# 一对一会议

## 场景引入

周一下午两点，新经理小陈和下属小赵进行第三次 1:1。小陈打开笔记本，开始逐条过任务："上个迭代的 API 优化做完了吗？这周的 bug 修复进度怎么样？那个技术方案评审安排了吗？"小赵一一回答，整个会议只用了 15 分钟。小陈觉得效率很高，但心里隐隐觉得哪里不对。

两周后，小赵提交了离职申请。在离职面谈中，小赵说："我觉得小陈不关心我，他只关心任务进度。我遇到的技术困惑、对职业发展的迷茫，从来没机会和他聊。"

小陈很震惊：我一直都在和他 1:1 啊？

问题出在哪里？**小陈把 1:1 当成了 status update，而不是建立信任和了解人的机会。** 1:1 不是问"任务做完了没"，而是问"你最近怎么样"。

## 学习目标

- 理解 1:1 的真正目的：建立信任、发现问题、辅导成长
- 掌握 1:1 的频率和时长设置，根据下属成熟度灵活调整
- 学会使用结构化的 1:1 模板，避免变成流水账
- 掌握 SBI 反馈模型，给出具体、可操作的反馈
- 掌握 GROW 辅导模型，帮助下属自己找到解决方案

## 1:1 的真正目的

很多新经理把 1:1 当成"进度同步会"，这是最大的误区。进度同步完全可以通过看板、站会、周报来完成，不需要占用两个人 30 分钟的独处时间。

1:1 的真正目的是：

```
1:1 的三层价值

  表层：了解工作状态（进度、障碍、优先级）
  中层：发现问题信号（情绪、动机、关系冲突）
  深层：建立信任关系（让下属觉得"这个人值得跟"）
```

**一个简单的检验标准：** 如果你的 1:1 只讨论了任务进度，那这次 1:1 是失败的。

## 频率与时长

1:1 的频率应该根据下属的成熟度和当前状态动态调整：

| 下属状态 | 频率 | 时长 | 原因 |
|----------|------|------|------|
| 新入职（0-3 个月） | 每周 | 30 分钟 | 需要高频建立信任，快速了解工作方式 |
| 初级工程师 | 每周 | 30 分钟 | 需要较多指导和反馈 |
| 高级工程师（成熟期） | 双周 | 30-45 分钟 | 自驱力强，但需要战略对齐 |
| 遇到困难的下属 | 每周 | 45-60 分钟 | 需要额外支持和关注 |
| 即将离职风险 | 每周 | 45 分钟 | 及时发现问题，尝试挽留 |

**关键原则：** 宁可频率高、时长短，不要频率低、时长长。每周 30 分钟远比每月 2 小时有效。

## 结构化 1:1 模板

一个好的 1:1 应该有结构，但不能太僵化。以下是推荐的四段式模板：

```
┌─────────────────────────────────────────┐
│           1:1 会议模板（30 分钟）          │
├─────────────────────────────────────────┤
│                                         │
│  1. 个人状态（5 分钟）                    │
│     "你最近怎么样？工作之外有什么           │
│      需要我帮忙的吗？"                     │
│     → 关注情绪、生活状态、工作满意度        │
│                                         │
│  2. 工作进展（10 分钟）                    │
│     "上周我们聊的几件事，进展如何？"         │
│     → 不是逐条过任务，而是讨论关键阻塞点     │
│     → 重点关注：什么在阻塞你？需要我做什么？  │
│                                         │
│  3. 障碍与支持（10 分钟）                  │
│     "目前最大的挑战是什么？"                │
│     → 技术障碍、人际冲突、资源不足          │
│     → Manager 承诺具体的帮助行动           │
│                                         │
│  4. 成长与发展（5 分钟）                   │
│     "你最近在学什么？对职业发展             │
│      有什么想法？"                         │
│     → 技术成长、职业路径、新挑战            │
│                                         │
└─────────────────────────────────────────┘
```

**一个重要提醒：** 1:1 的议程应该由下属主导。Manager 的角色是倾听、提问和帮助，而不是汇报和指挥。在 1:1 前一天，发一个简单的提醒："明天我们 1:1，你有什么想聊的吗？"

## SBI 反馈模型

在 1:1 中，你经常需要给下属反馈。反馈的质量直接决定了下属是否能从中受益。SBI 模型是最实用的反馈框架：

```
SBI 反馈模型

  S - Situation（情境）：具体的时间、地点、场景
  B - Behavior（行为）：你观察到的具体行为
  I - Impact（影响）：这个行为造成的影响

  完整示例：
  "上周三的技术评审会上（S），你直接否定了小王的方案，
   说'这个方案根本不可行'（B），导致小王后面全程没再
   发言，会议氛围变得很紧张（I）。"
```

**SBI 模型的三个关键点：**

1. **情境要具体**：不要说"上次开会"，要说"上周三下午的技术评审会"
2. **行为要客观**：不要说"你态度不好"，要说"你说了'这个方案根本不可行'"
3. **影响要真实**：不要说"这样不好"，要说"导致小王全程沉默，团队讨论质量下降"

**正面反馈同样用 SBI：**

```
正面反馈示例：
"昨天线上故障的时候（S），你主动承担了日志分析的工作，
 并且在 30 分钟内就定位到了根因（B），让整个故障恢复时间
 缩短了一半，客户几乎没有感知到问题（I）。非常棒。"
```

## GROW 辅导模型

当 1:1 中发现下属遇到困难时，不要直接给答案，而是用 GROW 模型帮助他自己找到解决方案：

```
GROW 辅导模型

  G - Goal（目标）：你想达到什么目标？
  R - Reality（现状）：现在的情况是什么？
  O - Options（选项）：你有哪些选择？
  W - Will（意愿）：你打算怎么做？

  对话示例：

  Manager：你提到对这个技术方案不太确定，你想达到什么效果？
  下属：我想设计一个能支撑 10 倍流量增长的方案，但不确定从哪里入手。
  （Goal 确认）

  Manager：现在系统的瓶颈在哪里？你做过什么分析？
  下属：数据库查询是主要瓶颈，目前 P99 延迟已经到了 500ms。
  （Reality 了解）

  Manager：针对数据库瓶颈，你考虑过哪些方案？
  下属：缓存、读写分离、分库分表，但我不确定哪个最合适。
  （Options 探索）

  Manager：如果先从缓存入手，你觉得最大的风险是什么？
  下属：缓存一致性问题，我们之前没有处理过。
  Manager：那我们先花一天做个缓存方案的 PoC，验证一致性方案，你觉得呢？
  下属：好，我明天先做这个。
  （Will 明确）
```

**GROW 的核心是提问，不是给答案。** 你的目标是让下属学会自己分析问题、评估选项、做出决策。如果你每次都直接给答案，下属永远学不会独立思考。

## 1:1 中的信号识别

1:1 最大的价值是**提前发现问题**。以下是需要警惕的信号：

| 信号 | 可能意味着 | 应对方式 |
|------|-----------|----------|
| 下属突然话变少了 | 不满、失望、或不信任 | 主动询问，用开放性问题打开话题 |
| 频繁提到"随便""都行" | 丧失主动性或对工作失去兴趣 | 了解根因，重新激发动机 |
| 反复抱怨同一个问题 | 问题没被解决，或者没被听到 | 具体承诺解决时间，跟进到底 |
| 不再提不同意见 | 可能之前提意见被否定过 | 主动征求意见，确保安全表达 |
| 频繁提到其他公司 | 可能在考虑跳槽 | 了解真实需求，评估挽留可能性 |

## 常见误区

1. **把 1:1 当成 status update**。最浪费 1:1 时间的做法就是"这周做了什么，下周打算做什么"。这些信息完全可以通过周报或看板获取，不需要占用 1:1 的宝贵时间。
2. **只聊工作不聊人**。1:1 不是项目同步会。如果你每次都只聊任务进度，下属会觉得你不关心他这个人，慢慢地就不会在 1:1 中敞开心扉。
3. **不做记录，每次从零开始**。如果你不记录 1:1 的关键信息，下次对话时完全忘记上次聊了什么，下属会觉得你不重视。
4. **取消 1:1 去处理"更重要的事"**。这是最常见的错误。1:1 是管理者最重要的会议，取消它等于告诉下属"你不重要"。
5. **在 1:1 中做绩效评估**。1:1 应该是一个安全的对话空间。如果突然变成绩效谈话，下属会变得防御性很强，再也不敢说真话。

## 工程建议

1. **1:1 是不可取消的会议**。除非你自己生病或有紧急事故，否则不要取消 1:1。取消 1:1 = 告诉下属"你不重要"。
2. **做记录，但不要当面记**。1:1 时全神贯注地倾听，结束后花 2 分钟记录关键信息。下次 1:1 开始时，先跟进上次的承诺。
3. **不要在 1:1 中做绩效评估**。1:1 是辅导和信任建立的场景，绩效评估会让下属防御性增强，不敢说真话。
4. **偶尔改变场景**。不要总是在会议室，可以一起喝杯咖啡、散步聊天。场景变化能让对话更自然。
5. **学会沉默**。问了一个问题后，给下属足够的时间思考。不要急着填补沉默，沉默往往是深度思考的开始。

## 小结

1:1 是管理者最重要的工具，没有之一。它的核心价值不在于同步进度，而在于：

1. **建立信任**：让下属觉得你关心他这个人，而不只是关心他的产出
2. **发现问题**：在问题变成危机之前，通过定期对话提前感知
3. **辅导成长**：通过 SBI 反馈和 GROW 辅导，帮助下属持续进步

好的 1:1 不是管理者在"管理"下属，而是两个人在**共同面对挑战**。

## 参考答案

### 练习一

**思路**：SBI 模型要求将模糊的反馈转化为具体的情境、行为和影响描述。

**答案**：

1. 低质量："你最近代码质量不太行。"
   SBI 改写："上周五你提交的订单模块 PR（S），有三个函数超过 200 行，缺少错误处理，并且没有写单元测试（B），导致 Code Review 花了额外两个小时，而且上线后出现了一个未捕获异常导致的线上告警（I）。"

2. 低质量："你开会的时候不太积极。"
   SBI 改写："昨天的技术方案评审会上（S），当小王提出用消息队列解耦的方案时，你直接说'没必要'，但没有给出具体的技术理由（B），这让讨论没有深入下去，最后大家只能搁置这个议题（I）。"

3. 低质量："你做得很好，继续保持。"
   SBI 改写："这周客户反馈的紧急 bug（S），你主动承担了排查工作，通过分析日志在两小时内定位到了根因，并且写了一份详细的故障分析报告（B），让团队对这类问题有了系统的认知，客户对响应速度也非常满意（I）。"

**要点**：
- 反馈必须具体到可观察的行为，不能是模糊的评价
- 影响要说明对团队、项目或他人的实际后果
- 正面反馈同样需要具体，"做得好"不如说清楚"好在哪里"

### 练习二

**思路**：用 GROW 模型逐步引导下属从模糊的想法走向具体的行动计划。

**答案**：

Manager：你想做技术分享，这个想法很好。你希望通过这次分享达到什么效果？（Goal）
小刘：主要是想提升自己在团队里的技术影响力，也希望能帮助大家解决一些实际问题。
Manager：那你觉得团队目前在技术上最常遇到的问题是什么？（Reality）
小刘：嗯...我觉得大家在性能优化方面比较薄弱，上次好几个 PR 都有 N+1 查询的问题。
Manager：性能优化是个好方向。除了数据库查询优化，你还想到哪些可以讲的主题？（Options）
小刘：前端渲染优化、缓存策略、性能监控工具这些也都可以。
Manager：这三个方向你最熟悉哪个？你觉得哪个对团队当下最有用？
小刘：缓存策略我最近正好研究过，而且团队确实在缓存使用上比较随意。
Manager：那我们就定缓存策略作为主题。你打算什么时候做这个分享？需要我帮你做什么？（Will）
小刘：我下周先把大纲写出来，给你看一下。两周后正式分享。
Manager：好，你写完大纲发我，我帮你看看结构和深度是否合适。另外分享前可以先在小范围试讲一次。

**要点**：
- Goal 阶段要让下属明确"为什么做"和"期望效果"
- Reality 阶段帮助下属连接自己的想法和团队的实际需求
- Options 阶段不要给答案，而是引导下属自己列举选项
- Will 阶段要落到具体的行动和时间节点

### 练习三

**思路**：从 1:1 的目的、结构、反馈方式和后续跟进四个维度诊断问题。

**答案**：

这个 1:1 有以下问题：

1. **变成了 status update**：整个对话都在过任务进度，没有讨论小刘的状态、感受、障碍和成长。应该加入"你最近怎么样"这样的开放性问题。

2. **Manager 直接给答案**："加 Redis 吧"——没有引导小刘自己思考方案。应该用 GROW 模型问："你考虑过哪些方案？各有什么优缺点？"让小刘自己做出判断。

3. **否定了下属的成长需求**："这个不急"——小刘主动提出想学 Kubernetes，这是一个很好的信号，说明他有成长意愿。Manager 应该积极探索，而不是一票否决。可以说："Kubernetes 是个好方向，我们聊聊你希望怎么学，我可以帮你规划一下。"

4. **缺乏结构**：对话没有章法，最后以"还有什么要聊的吗"草草收场。应该用结构化模板，确保覆盖个人状态、工作进展、障碍支持和成长发展四个维度。

5. **没有后续承诺**：Manager 没有承诺任何帮助行动，也没有设定下次跟进的时间点。1:1 应该以明确的下一步结束。

**要点**：
- 1:1 的核心是人，不是任务
- 管理者要学会提问而不是给答案
- 下属主动提出的成长需求，永远不要忽略
