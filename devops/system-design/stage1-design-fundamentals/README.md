# 阶段 1：设计基础

> 6 课时 | 掌握系统设计的基本方法论和核心组件

## 阶段概述

系统设计的第一步不是画架构图，而是搞清楚"要解决什么问题"。本阶段从需求分析和容量估算开始，逐步建立系统设计的基本功：API 设计、数据建模、缓存策略、负载均衡。最后通过一个短链服务实战项目，将所学知识串联起来。

这个阶段的核心目标是建立**设计思维**——面对一个模糊的业务需求，你知道该问什么问题、该做哪些估算、该从哪里开始设计。

## 学习目标

完成本阶段后，你将能够：

1. 将模糊的业务需求拆解为具体的功能需求和非功能需求
2. 根据业务量级进行容量估算（QPS、存储、带宽）
3. 设计清晰、一致、可演进的 RESTful API
4. 完成数据建模，理解范式与反范式的权衡
5. 选择合适的缓存策略，识别并解决常见缓存问题
6. 理解负载均衡的工作原理和适用场景

## 前置要求

- 熟悉 HTTP 协议和 RESTful API 的基本概念
- 了解关系型数据库的基本操作（建表、查询、索引）
- 有后端开发的基本经验

## 课时列表

| # | 标题 | 核心内容 |
|---|------|---------|
| 01 | 需求分析与估算 | 功能需求拆解、非功能需求量化（可用性/延迟/一致性）、容量估算方法论（QPS/存储/带宽）、估算实例演练 |
| 02 | API 设计 | RESTful 设计原则、资源命名规范、版本管理策略、错误码体系、分页与过滤、API 文档与 Mock |
| 03 | 数据建模 | ER 模型设计、三大范式与反范式权衡、索引策略设计、数据生命周期管理、建模案例分析 |
| 04 | 缓存策略 | 缓存分层架构（本地缓存/分布式缓存/CDN）、淘汰策略对比、缓存穿透/击穿/雪崩的识别与解决、缓存一致性方案 |
| 05 | 负载均衡 | L4 vs L7 负载均衡、常见算法（轮询/加权/一致性哈希）、健康检查机制、会话保持方案、高可用部署 |
| 06 | 实战：短链服务 | 从需求分析到架构设计，完成短链生成、跳转、统计的完整方案，综合运用 API 设计、数据建模、缓存、负载均衡 |

## 预计学习时间

约 12-15 小时（每课时 2-2.5 小时，含练习时间）
