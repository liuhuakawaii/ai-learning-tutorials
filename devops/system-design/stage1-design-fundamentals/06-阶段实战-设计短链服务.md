# 阶段实战：设计短链服务

## 为什么是短链服务

短链服务看起来简单——输入长链接，输出短链接。但它涵盖了需求分析、API 设计、数据建模、缓存策略、负载均衡的全部核心知识。更重要的是，它是系统设计面试的高频题，也是理解读密集型系统设计的最佳切入点。

本课不按固定模板走，而是像真实项目一样，从需求开始，一步步做出设计决策，每个决策都说明为什么。

## 需求确认

在动手之前，先和"产品方"对齐：

```
功能需求：
  - 长链接生成短链接（支持自定义短码，可选）
  - 短链接 302 重定向到原始链接
  - 查看点击次数和来源统计

非功能需求：
  - 可用性 99.99%（短链是入口服务，宕机影响所有下游）
  - 重定向延迟 P99 < 50ms
  - 读写比 100:1（创建少，访问多）
  - 短码不可被猜测（防止遍历攻击）

不做：
  - 用户注册登录（后续迭代）
  - 链接安全检测
  - 自定义域名
```

## 容量估算

```
日均创建短链：1000 万
读写比：100:1

写 QPS = 1000 万 / 86400 ≈ 116
读 QPS = 116 × 100 = 11600
峰值读 QPS = 11600 × 3 ≈ 35000

每条记录 ≈ 500 字节
5 年存储 = 500B × 1000 万 × 365 × 5 ≈ 9.1 TB

Base62 6 位 = 568 亿种组合，足够 5 年
```

9.1 TB 超出了单机 MySQL 的舒适区，但还没到必须分库分表的地步。第一版用单机 + 读写分离就够了。

## 第一个架构决策：301 还是 302

这是短链服务最经典的 tradeoff：

```
301 Moved Permanently：
  浏览器缓存重定向，后续访问不再经过短链服务
  → 减少服务器压力，但无法统计点击

302 Found：
  每次访问都经过短链服务
  → 可以统计点击，但服务器压力大
```

选择 302。统计数据是短链服务的核心价值之一。通过缓存策略减轻服务器压力。

## 短码生成：三种方案的取舍

### 方案一：哈希截取

对长链接 MD5/SHA256，取前 N 位做 Base62。同一长链接生成相同短码（可去重）。需要处理哈希冲突。

### 方案二：自增 ID + Base62

数据库自增 ID 转 Base62。无冲突，实现简单。但短码可预测，存在安全风险。

### 方案三：预生成 + 池化（推荐）

后台批量生成短码，随机打乱存入 Redis 队列。创建时 `LPOP` 取一个。队列不足时异步补充。

```
优点：短码不可预测、无冲突、创建速度 O(1)
缺点：需要维护预生成任务
```

选择方案三。安全性和性能都最优。

## 缓存策略：三级缓存

读 QPS 35000，单机 MySQL 扛不住。需要缓存：

```
重定向路径：
  1. Nginx proxy_cache（微秒级，命中率约 60%）
  2. Redis（毫秒级，命中率约 95%）
  3. MySQL（兜底）

缓存 Key：
  Redis: url:{short_code} → { long_url, expire_at }
  Nginx: proxy_cache_key $uri → 302 Location header
```

点击统计不能同步写数据库——会拖慢重定向。改为异步：

```
重定向同步返回（< 50ms）
点击事件发送到 Kafka
消费者批量写入 click_logs 表（每批 1000 条，每秒刷新）
```

## 数据库设计

```sql
CREATE TABLE urls (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    short_code  VARCHAR(10) NOT NULL UNIQUE,
    long_url    VARCHAR(2048) NOT NULL,
    user_id     BIGINT DEFAULT NULL,
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    expire_at   DATETIME DEFAULT NULL,
    click_count BIGINT NOT NULL DEFAULT 0,
    INDEX idx_short_code (short_code),
    INDEX idx_long_url (long_url(100)),
    INDEX idx_expire (expire_at)
);

CREATE TABLE click_logs (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    short_code  VARCHAR(10) NOT NULL,
    clicked_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    ip_address  VARCHAR(45),
    user_agent  VARCHAR(500),
    referer     VARCHAR(2048),
    INDEX idx_code_time (short_code, clicked_at)
);
```

click_logs 数据量大，需要按时间分表或归档（保留近 90 天明细，历史聚合到统计表）。

## 完整架构

```
用户 → CDN → Nginx(Master) ←VRRP→ Nginx(Backup)
                  │
         ┌────────┼────────┐
         ▼        ▼        ▼
      API-1    API-2    API-3   无状态应用服务器
         └────────┼────────┘
                  │
         ┌────────┼────────┐
         ▼        ▼        ▼
     Redis-1  Redis-2  Redis-3   Redis Cluster
                                    短码缓存+预生成队列

      MySQL(Master+Slave)     Kafka → 统计服务
      短链持久化存储            点击事件异步处理
```

## 这个设计的边界

**什么时候不够用**：
- DAU 到 5 亿级别 → 需要分库分表（按 short_code 哈希分片）
- 短码用完 → 扩展到 7 位（3.5 万亿组合）
- 需要自定义域名 → Nginx 泛域名解析 + DNS CNAME

**第一版不需要做的**：
- 不需要分表（9.1 TB 单机 MySQL 能撑）
- 不需要分布式 ID 生成器（预生成池化够用）
- 不需要 Flink 实时统计（Kafka + 批量写够用）

## 参考答案

### 练习一

```
读 QPS：5 亿 × 3 / 86400 ≈ 173611，峰值 ≈ 520833
写 QPS：173611 / 100 ≈ 1736，峰值 ≈ 5208
存储：1736 × 86400 × 500B × 365 × 5 ≈ 136.9 TB
带宽：520833 × 500B ≈ 260 MB/s ≈ 2 Gbps
```

5 亿 DAU 需要分布式数据库（TiDB）、多机房部署、CDN 加速重定向。

### 练习二

1. **创建 API 延迟飙升**：Redis 短码队列耗尽退化到实时生成，或 MySQL 写入慢。监控队列长度，检查慢查询日志。
2. **缓存命中率下降**：大量新链接缓存未预热，或 Redis 内存不足频繁淘汰。增加内存，优化淘汰策略。
3. **统计延迟**：Kafka 消费者积压，或 click_logs 表写入瓶颈。增加消费者实例，批量写入。

### 练习三

```typescript
const CHARS = 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789'

function generateShortCode(length: number = 6): string {
  if (length < 1 || length > 20) throw new Error('长度必须在 1-20 之间')
  let result = ''
  const array = new Uint32Array(length)
  crypto.getRandomValues(array)
  for (let i = 0; i < length; i++) {
    result += CHARS[array[i] % CHARS.length]
  }
  return result
}

function isValidShortCode(code: string): boolean {
  return /^[A-Za-z0-9]{6,10}$/.test(code)
}

describe('generateShortCode', () => {
  test('默认长度 6', () => {
    expect(generateShortCode()).toHaveLength(6)
  })
  test('自定义长度', () => {
    expect(generateShortCode(10)).toHaveLength(10)
  })
  test('只包含 Base62 字符', () => {
    expect(generateShortCode()).toMatch(/^[A-Za-z0-9]+$/)
  })
  test('连续生成不重复（概率性）', () => {
    const codes = new Set(Array.from({ length: 1000 }, () => generateShortCode()))
    expect(codes.size).toBe(1000)
  })
  test('长度为 0 抛出异常', () => {
    expect(() => generateShortCode(0)).toThrow()
  })
})

describe('isValidShortCode', () => {
  test('有效短码', () => { expect(isValidShortCode('abc123')).toBe(true) })
  test('太短', () => { expect(isValidShortCode('abc')).toBe(false) })
  test('包含特殊字符', () => { expect(isValidShortCode('abc-123')).toBe(false) })
  test('空字符串', () => { expect(isValidShortCode('')).toBe(false) })
})
```
