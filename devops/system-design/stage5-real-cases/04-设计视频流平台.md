# 设计视频流平台

## 场景引入

2010 年，YouTube 每分钟上传的视频时长约为 24 小时。到 2023 年，这个数字增长到 500 小时以上。与此同时，用户对播放体验的要求也在不断提高——从能看就行，到 1080p 流畅播放，再到 4K HDR 杜比音效。

视频流平台是系统设计中最复杂的场景之一。它涉及文件上传、视频转码、自适应码率、CDN 分发、推荐系统、弹幕系统、版权保护等多个子系统，每一个单独拿出来都是一个完整的系统设计题。

本节课将拆解视频流平台的核心架构，重点解决三个关键问题：如何高效处理海量视频上传与转码？如何保证全球用户都能流畅播放？如何在降低成本的同时提供优质体验？

## 学习目标

- 理解视频从上传到播放的完整处理流水线
- 掌握视频编码（H.264/H.265/AV1）和自适应码率（HLS/DASH）的工程取舍
- 设计分布式转码架构，理解任务拆分与并行处理策略
- 掌握 CDN 分发架构，理解边缘节点与回源策略
- 了解弹幕系统、DRM 版权保护等辅助系统的设计要点

## 视频处理流水线

视频从用户上传到最终可播放，需要经过一条复杂的处理流水线：

```
用户上传
    |
    v
+------------------+
|   上传服务       |  分片上传、断点续传、上传校验
+------------------+
    |
    v
+------------------+
|   消息队列       |  Kafka / SQS，解耦上传与处理
+------------------+
    |
    v
+------------------+     +------------------+
|   转码调度器     |---->|  转码工作节点集群  |
|  (任务拆分)      |     |  GPU/CPU 混合集群  |
+------------------+     +------------------+
    |                           |
    |    +----------------------+
    |    |
    v    v
+------------------+     +------------------+
|   存储服务       |     |  缩略图生成      |
|  S3 / OSS       |     |  关键帧提取      |
+------------------+     +------------------+
    |
    v
+------------------+
|   CDN 预热分发   |  推送到边缘节点
+------------------+
    |
    v
+------------------+
|   播放服务       |  自适应码率、DRM 解密
+------------------+
    |
    v
用户播放
```

## 视频编码：格式选择的工程取舍

视频编码是转码环节的核心。不同编码格式在压缩效率、编码速度、兼容性之间存在显著差异：

| 编码格式 | 压缩效率 | 编码速度 | 解码兼容性 | 适用场景 |
|---------|---------|---------|-----------|---------|
| H.264   | 基准    | 快      | 几乎 100% | 通用场景，兼容性优先 |
| H.265   | 提升 40-50% | 慢 3-5 倍 | 主流设备支持 | 4K/高分辨率内容 |
| AV1     | 提升 50-70% | 极慢 10-20 倍 | 逐步增长 | 长视频、头部内容 |

**工程决策**：大多数平台采用分层策略。H.264 作为基础编码保证兼容性，H.265 用于高分辨率内容，AV1 仅用于头部高流量内容（因为编码成本高，只有播放量足够大才能摊薄）。

```
编码策略决策树：

                视频时长 > 10 分钟？
                  /           \
                是              否
                |               |
          播放量预估？      默认 H.264
          /        \
       > 10万      < 10万
        |            |
   AV1 + H.265   H.265 + H.264
   (头部内容)    (中长尾内容)
```

## 自适应码率：HLS 与 DASH

自适应码率（ABR）是保证播放流畅的核心技术。原理是将视频切割成小片段（segment），每个片段提供多种码率版本，播放器根据网络状况动态切换。

```
原始视频
    |
    v
+-------------------------------+
|         转码器                |
+-------------------------------+
    |      |      |      |
    v      v      v      v
  4K     1080p  720p   480p    <- 多码率输出
  15Mbps  5Mbps  2Mbps  800Kbps
    |      |      |      |
    v      v      v      v
+-------------------------------+
|     切片器 (Segmenter)        |
|   每个片段 2-10 秒            |
+-------------------------------+
    |
    v
  .m3u8 (HLS) 或 .mpd (DASH)   <- 播放列表文件
```

**HLS vs DASH 对比**：

| 维度 | HLS | DASH |
|------|-----|------|
| 提出者 | Apple | ISO 标准 |
| 容器格式 | TS / fMP4 | MP4 |
| iOS 兼容 | 原生支持 | 需要第三方库 |
| 延迟 | 6-30 秒（常规） | 2-10 秒 |
| 生态成熟度 | 最成熟 | 快速增长 |

**工程建议**：优先选择 HLS，因为 iOS 原生支持且生态最成熟。如果需要低延迟直播，结合 LL-HLS（Low Latency HLS）或 WebRTC。

## CDN 分发架构

视频播放的带宽成本是平台最大的运营支出之一。CDN 分发架构直接影响用户体验和成本：

```
                    源站 (Origin)
                   +-----------------+
                   |  S3 / OSS       |
                   |  全量视频存储    |
                   +-----------------+
                          |
           +--------------+--------------+
           |              |              |
           v              v              v
    +-----------+   +-----------+   +-----------+
    | 区域中心  |   | 区域中心  |   | 区域中心  |
    | 北京     |   | 上海     |   | 新加坡    |
    +-----------+   +-----------+   +-----------+
       |    |         |    |         |    |
       v    v         v    v         v    v
    +----+ +----+  +----+ +----+  +----+ +----+
    |边缘| |边缘|  |边缘| |边缘|  |边缘| |边缘|
    |节点| |节点|  |节点| |节点|  |节点| |节点|
    +----+ +----+  +----+ +----+  +----+ +----+
```

**CDN 回源策略**：

1. **主动预热**：热门视频上传转码完成后，主动推送到边缘节点
2. **被动回源**：用户请求时边缘节点没有缓存，向上级节点或源站拉取
3. **分层缓存**：边缘节点 → 区域中心 → 源站，逐级回源

**成本优化**：长尾视频（播放量低）不预热，等用户请求时被动回源。热门视频主动预热到边缘节点。通过 P2P-CDN 混合架构进一步降低带宽成本。

## 分布式转码架构

一个 1080p 的 10 分钟视频，单机转码可能需要 20-60 分钟。面对每天数百万的上传量，必须采用分布式转码：

```
                +------------------+
                |   转码调度器      |
                |  1. 下载源文件    |
                |  2. 分析视频参数  |
                |  3. 拆分任务      |
                +------------------+
                         |
          +--------------+--------------+
          |              |              |
          v              v              v
    +-----------+  +-----------+  +-----------+
    | Worker 1  |  | Worker 2  |  | Worker 3  |
    | 片段 1-3  |  | 片段 4-6  |  | 片段 7-10 |
    | 4码率转码 |  | 4码率转码 |  | 4码率转码 |
    +-----------+  +-----------+  +-----------+
          |              |              |
          v              v              v
    +-----------------------------------------+
    |            合并服务                      |
    |  按码率合并片段 → 生成 HLS 切片          |
    +-----------------------------------------+
                    |
                    v
    +-----------------------------------------+
    |            存储 + CDN 预热               |
    +-----------------------------------------+
```

**关键设计点**：

1. **任务粒度**：按视频片段（segment）而非整个视频分配任务，避免长尾效应（一个大文件阻塞整个 Worker）
2. **幂等性**：转码任务必须幂等，失败后可安全重试
3. **优先级队列**：热门创作者的视频、付费内容优先转码
4. **资源调度**：GPU 节点处理 H.265/AV1 编码，CPU 节点处理 H.264 编码

## 缩略图生成与关键帧提取

缩略图直接影响视频的点击率。系统需要智能选择最具代表性的画面：

1. **均匀采样**：每隔 N 秒截取一帧，作为候选帧
2. **质量评分**：基于清晰度、人脸检测、色彩丰富度等维度打分
3. **多样性过滤**：避免选出的缩略图过于相似
4. **多尺寸生成**：为不同展示位生成不同尺寸的缩略图（列表页、详情页、分享卡片）

## 弹幕系统

弹幕是视频平台的特色功能，技术挑战在于高并发实时性：

```
用户发送弹幕
      |
      v
+------------------+
|  弹幕接入层      |  WebSocket 长连接
|  连接管理        |
+------------------+
      |
      v
+------------------+
|  弹幕处理层      |  敏感词过滤、去重、排序
+------------------+
      |
      v
+------------------+
|  弹幕分发层      |  按视频ID广播给所有观看者
+------------------+
      |
      v
+------------------+
|  弹幕存储层      |  写入持久化存储，支持回放
+------------------+
```

**弹幕存储策略**：热点视频的弹幕量极大（百万级），采用分层存储——最近的弹幕存 Redis，全量弹幕存 HBase/Cassandra，按时间范围分区。

## 版权保护（DRM）

DRM（Digital Rights Management）防止视频被非法下载和分发：

1. **加密方案**：Widevine（Android/Chrome）、FairPlay（Apple）、PlayReady（Windows）
2. **密钥管理**：视频切片使用不同的加密密钥，密钥通过许可证服务器按需下发
3. **安全等级**：L1（硬件级安全，4K 内容）、L3（软件级安全，标清内容）

```
播放流程：
  播放器请求视频 → 获取加密信息 → 向许可证服务器请求密钥
       → 验证用户权限 → 下发临时密钥 → 解密播放
```

## 常见误区

1. **所有视频都用最高质量转码**：不同内容类型对画质要求不同。用户生成内容（UGC）用标准转码配置即可，专业内容（PGC）才需要精细调参，盲目追求画质会导致转码成本暴涨。

2. **CDN 节点越多越好**：CDN 节点数量不是越多越好，关键在于节点与用户分布的匹配度。在用户稀少的地区部署过多节点，利用率低反而增加运维成本。

3. **弹幕实时推送到所有用户**：弹幕不需要严格的实时性，可以引入 1-2 秒的缓冲窗口进行批量推送，大幅降低服务端压力。

4. **忽略视频预处理**：上传后直接转码会遇到各种问题（损坏文件、格式不兼容、音视频不同步）。必须先做预处理校验，再进入转码流程。

5. **DRM 能完全防止盗版**：DRM 只能提高盗版门槛，不能完全防止。对于极高价值内容，还需要结合水印溯源等手段。

## 工程建议

1. **转码任务幂等设计**：每个转码任务关联唯一 ID，Worker 失败后重新调度不会产生重复产物。使用分布式锁或数据库唯一约束保证幂等性。

2. **码率阶梯自适应**：不要对所有视频使用固定的码率阶梯。根据视频内容复杂度（动作片 vs 谈话节目）动态调整码率配置，可以节省 20-30% 的存储和带宽成本。

3. **渐进式上传体验**：大文件上传时提供进度条、断点续传、后台上传能力。上传完成后立即返回，转码异步处理，通过通知告知用户转码完成。

4. **视频预取策略**：基于用户行为预测（观看历史、时间规律），提前将可能观看的视频推送到用户所在区域的边缘节点。

5. **监控指标体系**：重点关注首帧时间（用户从点击到看到画面的延迟）、卡顿率、码率切换频率、转码队列积压量。

## 小结

视频流平台的核心挑战在于处理海量视频的转码和分发。关键设计决策包括：采用分层编码策略平衡画质与成本；通过分布式转码提高处理吞吐；利用自适应码率和 CDN 分发保证播放体验；弹幕系统采用分层存储和批量推送降低实时性压力；DRM 保护版权但需结合水印溯源。每个子系统都有独立的扩展深度，面试时要根据考察重点选择深入方向。

## 练习

### 练习一：转码资源估算

某视频平台每天有 10 万个新视频上传，平均时长 5 分钟，需要转成 4 种码率（4K/1080p/720p/480p）。单台 GPU 转码服务器处理 1080p 的速度是实时速度的 5 倍（即 5 分钟视频需要 1 分钟）。请估算需要多少台转码服务器，假设每天的转码任务需要在 2 小时内完成。

### 练习二：CDN 成本优化

你的视频平台每月 CDN 带宽费用为 200 万元。分析发现 80% 的流量来自 5% 的热门视频。请设计一个 CDN 成本优化方案，目标是在不影响用户体验的前提下将带宽费用降低 40%。

---

## 参考答案

### 练习一

**思路**：先计算总转码工作量，再根据时间约束推算所需服务器数量。

**答案**：

总转码任务量计算：
- 每天 10 万个视频 × 4 种码率 = 40 万个转码任务
- 每个任务的平均处理时间：以 1080p 为例，5 分钟视频需要 1 分钟处理
- 但 4K 转码时间约为 1080p 的 4 倍，480p 约为 1080p 的 0.5 倍
- 加权平均处理时间 = (4 + 1 + 0.5 + 0.25) / 4 ≈ 1.44 分钟/任务
- 总工作量 = 40 万 × 1.44 = 57.6 万分钟

时间约束：
- 2 小时 = 120 分钟
- 所需服务器数 = 576,000 / 120 = 4,800 台

考虑服务器利用率（通常 70-80%）和故障冗余：
- 实际需要 4,800 / 0.75 ≈ 6,400 台

**要点**：
- 这是一个极端估算，实际可以利用弹性扩容（高峰期多开、低谷期释放）
- 可以通过优先级队列，让短视频优先转码，长视频延后处理
- 不同码率可以并行处理，进一步缩短时间

### 练习二

**思路**：针对热门视频和长尾视频采用不同的分发策略，最大化缓存命中率。

**答案**：

优化方案包含三个层面：

1. **热门视频主动预热**：将 5% 的热门视频主动推送到所有边缘节点，这部分覆盖 80% 流量，用户体验不受影响。预热成本远低于回源带宽成本。

2. **长尾视频 P2P 分发**：对长尾视频，同一区域内的用户之间通过 P2P 分享已下载的片段，减少 CDN 回源。WebRTC DataChannel 可以在浏览器间建立 P2P 连接。

3. **编码优化**：对热门视频启用 H.265/AV1 编码，在同等画质下码率降低 40-50%。虽然编码成本增加，但带宽节省更显著。

预期效果：
- 热门视频预热减少回源流量：约 60% 的 CDN 流量
- P2P 分发减少长尾流量：约 15-20%
- 编码优化降低码率：约 20%
- 综合节省可达 40-50%

**要点**：
- 成本优化需要从多个维度同时入手
- 热门/长尾内容需要不同的分发策略
- 编码格式的选择直接影响带宽成本
