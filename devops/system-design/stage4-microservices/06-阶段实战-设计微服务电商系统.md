# 阶段实战：设计微服务电商系统

## 目标

综合运用服务拆分、服务通信、API 网关、配置中心、链路追踪的知识，设计一个完整的微服务电商系统。

## 需求

```
功能：用户管理、商品管理、订单管理、库存管理、支付管理、购物车
非功能：DAU 100 万，峰值 5000 QPS，下单 P99 < 2s，可用性 99.95%
```

## 服务拆分

基于 DDD 限界上下文：

```
核心交易链路：
  用户服务（注册、登录、地址）
  商品服务（发布、SKU、搜索）
  订单服务（创建、状态流转、查询）
  支付服务（发起支付、回调、退款）

支撑服务：
  库存服务（查询、扣减、预占、回补）
  价格服务（价格计算、满减、会员价）
  购物车服务（增删改查，Redis 存储）
  促销服务（优惠券、满减、秒杀）

基础设施服务：
  搜索服务（ES 搜索、筛选排序）
  推荐服务（个性化推荐）
  通知服务（短信、邮件、推送）
```

每个服务拥有独立的数据库。

## 核心流程：下单

下单是最复杂的流程，涉及多个服务协作：

```
用户 → API 网关（JWT 认证 + 限流）
  → 订单服务
    → 用户服务（验证身份）
    → 库存服务（Redis 预扣减 → DB 扣减）
    → 价格服务（查询价格 + 应用优惠券）
    → 创建订单（状态：待支付）→ 发布 OrderCreated 事件
    → 支付服务（调用第三方支付 → 返回支付链接）

支付完成后：
  支付服务 → PaymentCompleted 事件
    → 订单服务（更新状态为已支付）
    → 通知服务（发送确认短信）
    → 积分服务（增加积分）
```

## 分布式事务：Saga 模式

为什么选 Saga 而不是 2PC：2PC 要求所有参与者同步阻塞等待，性能差且有协调者单点问题。电商场景订单量大，2PC 的性能瓶颈不可接受。

```
正向流程（T1 → T2 → T3）：
T1: 库存服务 - 预占库存
T2: 订单服务 - 创建订单
T3: 支付服务 - 发起支付

补偿流程（任一步骤失败时反向补偿）：
C3: 支付服务 - 取消支付
C2: 订单服务 - 取消订单
C1: 库存服务 - 释放库存
```

每个正向操作都必须有对应的补偿操作。补偿操作必须幂等。

## 库存超卖问题

两个用户同时购买最后一件商品，都显示库存充足——超卖。

解决方案：Redis 预扣减 + 数据库乐观锁。

```
第一步：Redis Lua 脚本原子预扣减（快速拦截无效请求）
  local stock = redis.call('GET', key)
  if stock >= quantity then
    redis.call('DECRBY', key, quantity)
    return 1
  else
    return 0
  end

第二步：数据库乐观锁扣减（持久化）
  UPDATE stock SET quantity = quantity - 1, version = version + 1
  WHERE sku_id = ? AND version = ? AND quantity >= 1

第三步：如果 DB 扣减失败，Redis 回补
  INCRBY stock:{sku_id} 1
```

Redis 单线程 + Lua 保证原子性，QPS 10 万+。数据库乐观锁作为最终一致性保障。

## 缓存与削峰

商品详情页多层缓存：CDN → 本地缓存（Caffeine, TTL 30s）→ Redis（TTL 5min）→ DB。

缓存更新用 Cache Aside Pattern：先更新 DB，再删除缓存（不是更新缓存）。

秒杀场景 MQ 削峰：

```
瞬间 10000 QPS → 订单服务快速校验 → 写入 Kafka（10000 QPS）
  → 库存服务按 1000 QPS 消费 → 用户端显示"排队中"
```

## 参考答案

### 练习一

```
正向：T1 支付服务发起退款 → T2 订单服务更新状态 → T3 库存服务回补 → T4 积分服务扣减
补偿：T1 失败直接返回失败；T2 失败 C1 取消退款；T3 失败 C2+C1；T4 失败 C3+C2+C1
```

关键：退款接口幂等（退款单号去重），积分不足时标记"待追回"。

### 练习二

五层过滤：前端限流（按钮置灰+验证码）→ API 网关限流（单 IP 每秒 1 次）→ Redis Lua 预扣减（原子检查+扣减+用户去重）→ Kafka 削峰（500 QPS 消费）→ DB 乐观锁兜底。用户 3 秒内看到结果。

### 练习三

```typescript
function preDeductStock(currentStock: number, requestedQty: number): number {
  if (!Number.isInteger(currentStock) || !Number.isInteger(requestedQty)) {
    throw new Error('必须为整数')
  }
  if (requestedQty < 0) throw new Error('扣减数量不能为负')
  if (currentStock < requestedQty) return -1
  return currentStock - requestedQty
}

describe('preDeductStock', () => {
  test('正常扣减', () => { expect(preDeductStock(10, 3)).toBe(7) })
  test('库存不足', () => { expect(preDeductStock(2, 3)).toBe(-1) })
  test('扣减到 0', () => { expect(preDeductStock(3, 3)).toBe(0) })
  test('负数扣减量抛异常', () => { expect(() => preDeductStock(10, -1)).toThrow() })
  test('非整数抛异常', () => { expect(() => preDeductStock(10.5, 1)).toThrow() })
})
```
