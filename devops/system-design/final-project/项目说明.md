# 分布式电商平台系统设计 — 毕业项目说明

## 一、项目背景与目标

### 1.1 项目背景

随着互联网电商行业的快速发展，单一架构的应用已经无法满足高并发、高可用的业务需求。分布式系统设计成为后端工程师和架构师的核心技能。本毕业项目要求学生综合运用系统设计课程中所学的全部知识，设计并实现一个**分布式电商平台**的核心模块，覆盖从需求分析到架构落地的完整链路。

### 1.2 项目目标

通过本项目，学生将掌握以下核心能力：

1. **需求分析能力**：能够从业务场景出发，拆解功能需求与非功能需求，进行合理的容量估算
2. **数据库设计能力**：能够根据业务特点选择合适的存储方案，设计高效的数据模型
3. **分布式设计能力**：能够设计分布式锁、分布式事务、消息队列等核心组件方案
4. **微服务架构能力**：能够将单体应用拆分为微服务，设计服务间通信与治理方案
5. **系统优化能力**：能够针对性能瓶颈进行优化，具备面试场景下的系统设计表达能力

### 1.3 项目定位

本项目不是简单的 CRUD 应用，而是一个**以设计文档和架构方案为核心交付物**的系统设计项目。重点在于：

- 设计决策的合理性与权衡分析
- 对分布式系统核心问题的理解深度
- 方案的可落地性与工程规范性

## 三、非功能需求

### 3.1 高可用

- **可用性目标**：99.95%（全年停机不超过 4.38 小时）
- **故障隔离**：服务级别故障不影响整体系统，通过熔断、降级、限流实现
- **数据可靠性**：核心数据（订单、支付）多副本存储，RPO < 1 分钟
- **灾备方案**：同城双活或异地灾备，RTO < 30 分钟

### 3.2 高性能

- **响应时间**：核心接口 P99 < 200ms，P95 < 100ms
- **吞吐量**：核心链路支持 10,000 QPS
- **缓存策略**：多级缓存（本地缓存 + Redis + DB），缓存命中率 > 95%
- **数据库性能**：读写分离，慢查询 < 0.1%

### 3.3 可扩展

- **水平扩展**：无状态服务支持水平扩缩容
- **数据分片**：支持按用户 ID 或订单 ID 进行分库分表
- **异步解耦**：核心链路与非核心链路通过消息队列解耦
- **插件化设计**：支付渠道、物流渠道支持插件式扩展

### 3.4 安全性

- **认证鉴权**：JWT + RBAC，敏感操作二次验证
- **数据安全**：敏感数据加密存储（手机号、身份证），传输全链路 HTTPS
- **防攻击**：防 SQL 注入、XSS、CSRF，接口限流防刷
- **审计日志**：关键操作全链路可追溯

## 四、容量估算

### 4.1 用户规模假设

| 指标 | 数值 |
|------|------|
| 注册用户数 | 1,000 万 |
| 日活用户（DAU） | 100 万 |
| 月活用户（MAU） | 500 万 |
| 峰值在线用户 | 50 万 |
| 日均订单量 | 20 万单 |
| 峰值订单量（大促） | 200 万单/天 |

### 4.2 QPS 估算

| 场景 | 日均 QPS | 峰值 QPS（3-5 倍） |
|------|----------|-------------------|
| 商品浏览 | 5,000 | 25,000 |
| 商品搜索 | 2,000 | 10,000 |
| 下单 | 500 | 5,000 |
| 支付 | 300 | 3,000 |
| 库存查询 | 3,000 | 15,000 |
| 用户登录 | 1,000 | 5,000 |

### 4.3 存储估算

| 数据类型 | 单条大小 | 总量（5 年） | 存储大小 |
|----------|----------|-------------|----------|
| 用户数据 | 2 KB | 1,000 万条 | 20 GB |
| 商品数据 | 5 KB | 100 万条 | 5 GB |
| 订单数据 | 3 KB | 3.65 亿条 | 1.1 TB |
| 支付流水 | 1 KB | 3.65 亿条 | 365 GB |
| 日志数据 | - | - | 5 TB |

### 4.4 带宽估算

- 商品列表页：每次请求返回约 50 KB 数据
- 峰值 QPS 25,000 × 50 KB = 1.25 GB/s ≈ 10 Gbps
- 图片/视频 CDN 分流后，API 带宽需求约 2-3 Gbps

### 阶段三：分布式方案设计（对应课程第 9-12 章）

**目标**：解决分布式系统的核心问题：一致性、可用性、容错性

**任务清单**：

- [ ] 3.1 分布式锁设计

  - 设计多层限流方案（网关层 + 服务层 + 数据层）

## 八、评分标准

### 8.1 评分维度

| 维度 | 权重 | 评分要点 |
|------|------|----------|
| 需求分析完整性 | 15% | 功能覆盖度、非功能需求合理性、容量估算准确性 |
| 数据库设计质量 | 20% | ER 模型合理性、索引设计、分库分表方案可行性 |

| 架构设计合理性 | 20% | 微服务拆分粒度、服务治理、可扩展性 |

### 8.2 评分等级

| 等级 | 分数 | 标准 |
|------|------|------|
| 优秀 | 90-100 | 各维度均达到高标准，方案有深度思考和创新 |
| 良好 | 80-89 | 核心维度达到要求，方案合理可行 |
| 中等 | 70-79 | 基本完成任务，部分维度需要加强 |
| 及格 | 60-69 | 完成基本要求，但深度和质量不足 |
| 不及格 | < 60 | 未完成核心任务或存在严重设计缺陷 |
