# 移动端适配：响应式设计与移动端预览

## 场景引入

你搭建的客户管理系统在 PC 端运行良好，但销售团队反馈：外出拜访客户时需要通过手机查看客户信息、记录跟进备注、审批合同，目前系统在手机上完全无法使用——表格横向溢出、表单按钮太小点不到、图表被压缩看不清。

企业应用的使用者不再局限于办公桌前，越来越多业务操作发生在移动场景中：仓库盘点、外勤签到、现场审批。低代码平台需要提供完整的移动端适配方案，而不是简单把 PC 页面缩小。本节课讲解响应式布局、移动端组件、触控交互和 PWA 基础。

## 学习目标

- 掌握响应式布局的三种策略：断点适配、流式布局、独立移动端页面
- 了解移动端专属组件的设计原则
- 学会触控交互的优化方法
- 理解 PWA 基本概念和移动端性能优化策略

## 常见误区

1. **简单缩小 PC 页面**：只是用 CSS 缩小比例，文字无法阅读，按钮无法点击。移动端需重新设计布局和交互
2. **忽略网络延迟**：移动端网络通常比 PC 差，所有请求都需有 loading 状态和超时处理，图片需压缩和懒加载
3. **大量使用 hover 交互**：移动端没有 hover 状态，依赖 hover 的内容需改为点击触发

## 工程建议

1. **移动优先设计**：先设计移动端布局再扩展到 PC，移动端受限更多，先解决移动端问题
2. **使用 CSS 变量管理断点**：断点值定义为 CSS 变量，便于统一修改，避免多处硬编码
3. **测试真机而非只用模拟器**：Chrome DevTools 无法完全模拟真机行为，关键页面必须真机测试

## 小结

- 响应式布局三种策略：断点适配、组件级响应式配置、独立移动端页面
- 移动端表格替换为卡片列表，搜索用全屏搜索页，筛选用底部抽屉
- 触控交互满足最小 44px 触控区域，支持左滑操作和下拉刷新
- PWA 提供离线访问和安装到桌面的能力，缓存策略根据数据更新频率选择

## 参考答案

### 练习一

**思路**：PC 端表格在移动端切换为 card-list，搜索触发全屏搜索页，筛选用底部抽屉，分页改无限滚动。

**答案**：

```typescript
const responsiveCustomerList = {
  desktop: {
    searchBar: {
      layout: 'inline',
      fields: [
        { key: 'keyword', type: 'input', placeholder: '搜索客户', width: 240 },
        { key: 'level', type: 'select', width: 140 },
        { key: 'createdAt', type: 'dateRange', width: 260 }
      ],
      actions: ['search', 'reset', 'export']
    },
    table: { mode: 'table', columns: ['name', 'level', 'industry', 'contactCount', 'createdAt', 'actions'],
      pagination: { type: 'server', pageSize: 20 } }
  },
  mobile: {
    searchBar: { mode: 'simple', placeholder: '搜索客户名称',
      onTap: { type: 'navigate', target: '/search/customer' } },
    filterDrawer: {
      position: 'bottom',
      fields: [
        { key: 'level', label: '等级', type: 'radio' },
        { key: 'industry', label: '行业', type: 'checkbox' }
      ],
      actions: ['reset', 'confirm']
    },
    list: {
      mode: 'card-list',
      primary: { field: 'name' },
      secondary: [{ field: 'level', format: 'status' }, { field: 'industry' }],
      swipeActions: {
        left: [{ label: '编辑', color: '#1890ff' }],
        right: [{ label: '跟进', color: '#52c41a' }, { label: '删除', color: '#ff4d4f' }]
      },
      infiniteScroll: { enabled: true, pageSize: 20 }
    },
    pullRefresh: true
  }
}
```

**要点**：
- 移动端搜索栏简化为输入框，点击跳转全屏搜索页
- 筛选用底部抽屉，radio（单选）和 checkbox（多选）更适合触控
- 卡片列表支持左滑操作，比 PC 端行按钮更适合单手操作
- 无限滚动替代分页器，减少点击操作

### 练习二

**思路**：移动端改单列布局，长文本用全屏编辑页，日期和选择器用原生组件，提交按钮固定底部。

**答案**：

```typescript
const responsiveFormConfig = {
  desktop: {
    layout: 'section', columns: 3,
    sections: [
      { title: '基本信息', fields: [
        { key: 'name', label: '姓名', type: 'input', span: 1 },
        { key: 'phone', label: '手机号', type: 'input', span: 1 },
        { key: 'email', label: '邮箱', type: 'input', span: 1 }
      ]}
    ],
    submit: { position: 'bottom', label: '保存' }
  },
  mobile: {
    layout: 'single-column',
    sections: [
      { title: '基本信息', fields: [
        { key: 'name', label: '姓名', type: 'input', required: true },
        { key: 'phone', label: '手机号', type: 'input', inputMode: 'tel',
          rules: [{ type: 'pattern', pattern: '^1[3-9]\\d{9}$', message: '请输入正确的手机号' }] },
        { key: 'email', label: '邮箱', type: 'input', inputMode: 'email' },
        { key: 'industry', label: '行业', type: 'select',
          mobilePicker: { type: 'bottom-sheet' } },
        { key: 'followDate', label: '跟进日期', type: 'datePicker',
          mobilePicker: { type: 'native-date' } },
        { key: 'content', label: '跟进内容', type: 'textarea',
          mobileEditor: { type: 'fullscreen', maxLength: 500 } }
      ]}
    ],
    submitBar: { position: 'fixed-bottom', safeArea: true,
      actions: [
        { label: '保存草稿', type: 'default' },
        { label: '提交', type: 'primary' }
      ] }
  }
}
```

**要点**：
- 所有字段改单列布局，每字段占满整行
- inputMode（tel、email）让移动端键盘自动切换类型
- 日期用原生选择器，选择器用底部弹出面板
- 长文本用全屏编辑页，避免小屏幕内写大段文字
- 提交按钮固定底部，safeArea 适配刘海屏
