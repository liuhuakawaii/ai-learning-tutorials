# 阶段实战：项目管理系统

## 场景引入

你的团队有 15 人，正在使用 Jira 管理项目，但管理层觉得 Jira 太重、费用高。公司决定用低代码平台搭建轻量级项目管理系统，核心功能包括：任务看板、甘特图、团队管理、活动动态和冲刺规划，要求两周内完成第一版。

这个需求覆盖了前面几节课的所有知识：Dashboard（项目概览）、列表与详情（任务列表与详情）、表单设计（任务创建）、报表（燃尽图）、移动端适配。本节课将这些知识整合起来，从零搭建完整的项目管理系统。

## 学习目标

- 理解项目管理系统的领域模型设计
- 掌握看板（Kanban）和甘特图（Gantt）两种视图的实现
- 学会活动时间线和通知系统的设计
- 完成包含完整 CRUD 和多视图的项目管理应用

## 领域模型设计

```typescript
interface Project {
  id: string; name: string; key: string; description: string
  status: 'active' | 'archived' | 'completed'
  owner: TeamMember; members: TeamMember[]
  sprintConfig: SprintConfig
}

interface Task {
  id: string; projectId: string; key: string; title: string
  type: 'story' | 'task' | 'bug' | 'epic'
  status: 'backlog' | 'todo' | 'in-progress' | 'review' | 'done'
  priority: 'critical' | 'high' | 'medium' | 'low'
  assignee: TeamMember | null; reporter: TeamMember
  sprint: string | null; epic: string | null; parent: string | null
  estimate: number; loggedHours: number; labels: string[]
  dueDate: string | null
}

interface Sprint {
  id: string; projectId: string; name: string; goal: string
  status: 'planning' | 'active' | 'completed'
  startDate: string; endDate: string; tasks: string[]
  capacity: number; velocity: number
}

interface TeamMember {
  id: string; name: string; email: string; avatar: string
  role: 'owner' | 'admin' | 'member' | 'viewer'
  workload: number
}
```

实体关系：Project 1──N Sprint，Project 1──N Task，Sprint 1──N Task，Task N──1 TeamMember。

## 常见误区

1. **过度设计领域模型**：一开始就设计几十个实体导致开发周期过长。应先实现核心实体，后续迭代再加高级功能
2. **看板列太多**：超过 7 列导致横向滚动体验差。通常 4-6 列最佳，过多应合并或使用子状态
3. **忽略权限控制**：所有成员都能执行所有操作。应在创建、修改、删除等操作上设置角色权限

## 工程建议

1. **先实现任务 CRUD，再做视图切换**：看板和甘特图基于同一数据源，先确保数据层完善再实现不同视图
2. **看板拖拽需要乐观更新**：拖拽后立即在 UI 更新状态，异步调用后端接口，失败再回滚并提示
3. **活动日志异步记录**：状态变更等活动日志在后端异步记录，不阻塞主业务流程

## 小结

- 领域模型核心是 Project、Task、Sprint、TeamMember 四个实体
- 看板通过列（状态）组织卡片，支持拖拽和 WIP 限制
- 甘特图展示任务时间安排和依赖关系，支持拖拽调整
- 活动时间线和通知系统是团队协作基础，应异步记录

### 练习二

**思路**：折线图配置两条系列。理想线从总点数线性下降到 0，实际线从 API 获取。条件填充色区分进度超前/落后。

**答案**：

```typescript
const burndownChart = {
  type: 'line',
  title: '冲刺燃尽图',
  xAxis: { field: 'date', type: 'time', format: 'MM-DD' },
  yAxis: { field: 'points', label: '剩余故事点', min: 0 },
  series: [
    { field: 'ideal', name: '理想线', color: '#999', lineStyle: 'dashed', showDot: false },
    { field: 'actual', name: '实际线', color: '#1890ff', lineWidth: 2, showDot: true,
      areaStyle: { condition: 'actual > ideal', aboveColor: 'rgba(255,77,79,0.1)', belowColor: 'rgba(82,196,26,0.1)' } }
  ],
  tooltip: { trigger: 'axis', formatter: '{date}<br/>{seriesName}: {value} 点' },
  legend: { show: true, position: 'top-right' }
}

function generateIdealBurndown(totalPoints: number, startDate: string, endDate: string) {
  const start = new Date(startDate)
  const end = new Date(endDate)
  const days = Math.ceil((end.getTime() - start.getTime()) / 86400000)
  const perDay = totalPoints / days
  const data = []
  for (let i = 0; i <= days; i++) {
    const date = new Date(start)
    date.setDate(date.getDate() + i)
    data.push({ date: date.toISOString().split('T')[0], ideal: Math.max(0, totalPoints - perDay * i) })
  }
  return data
}
```

**要点**：
- 理想线通过 generateIdealBurndown 计算，从总点数线性下降到 0
- 实际线由后端 API 返回的每日剩余点数绘制
- 实际线在理想线上方时填充红色（落后），下方填充绿色（超前）
- tooltip 显示日期和具体剩余点数
