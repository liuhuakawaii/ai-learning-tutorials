# 数据安全

## 场景引入

一家医疗行业的客户在使用低代码平台构建患者管理系统时，提出了严格的安全要求：患者个人信息必须加密存储，所有数据访问必须有审计日志，系统需要满足等保三级合规要求。安全团队在渗透测试中发现，平台存在几个高危问题：JWT 密钥硬编码在前端代码中、API 没有频率限制导致可被暴力破解、敏感字段（身份证号、手机号）在数据库中明文存储。

数据安全不是上线前"加一层"的事情，而是需要从架构设计之初就融入的系统工程。本课将从传输加密、存储加密、认证鉴权、审计日志、合规要求五个维度，讲解低代码平台的安全加固方案。

## 学习目标

- 掌握数据传输加密（TLS）和存储加密（AES-256）的实现方式
- 理解 JWT 认证的最佳实践与常见陷阱
- 学会设计审计日志系统，记录关键操作的"谁/什么/何时/何地"
- 了解 GDPR 等数据合规的基本要求

### 存储加密（AES-256）

敏感字段在写入数据库前必须加密，读取后解密。使用 AES-256-GCM 模式提供认证加密：

```typescript
// src/crypto.ts
import { createCipheriv, createDecipheriv, randomBytes } from 'crypto';

const ALGORITHM = 'aes-256-gcm';
const IV_LENGTH = 16;
const TAG_LENGTH = 16;
const KEY = Buffer.from(process.env.ENCRYPTION_KEY!, 'hex'); // 64 字符 hex = 32 字节

export function encrypt(plaintext: string): string {
  const iv = randomBytes(IV_LENGTH);
  const cipher = createCipheriv(ALGORITHM, KEY, iv);
  const encrypted = Buffer.concat([cipher.update(plaintext, 'utf8'), cipher.final()]);
  const tag = cipher.getAuthTag();
  // 格式: iv(16) + tag(16) + ciphertext
  return Buffer.concat([iv, tag, encrypted]).toString('base64');
}

export function decrypt(encoded: string): string {
  const data = Buffer.from(encoded, 'base64');
  const iv = data.subarray(0, IV_LENGTH);
  const tag = data.subarray(IV_LENGTH, IV_LENGTH + TAG_LENGTH);
  const ciphertext = data.subarray(IV_LENGTH + TAG_LENGTH);
  const decipher = createDecipheriv(ALGORITHM, KEY, iv);
  decipher.setAuthTag(tag);
  return decipher.update(ciphertext) + decipher.final('utf8');
}
```

### 敏感字段自动加解密中间件

```typescript
// src/middleware/encryption.ts
import { encrypt, decrypt } from '../crypto';

const SENSITIVE_FIELDS = ['idCard', 'phone', 'bankAccount', 'address'];

export function encryptRecord<T extends Record<string, any>>(record: T): T {
  const result = { ...record };
  for (const field of SENSITIVE_FIELDS) {
    if (result[field] && typeof result[field] === 'string') {
      result[field] = encrypt(result[field]);
    }
  }
  return result;
}

export function decryptRecord<T extends Record<string, any>>(record: T): T {
  const result = { ...record };
  for (const field of SENSITIVE_FIELDS) {
    if (result[field] && typeof result[field] === 'string') {
      try {
        result[field] = decrypt(result[field]);
      } catch {
        // 字段未加密的情况（如旧数据迁移）
      }
    }
  }
  return result;
}
```

## JWT 认证最佳实践

```typescript
// src/auth.ts
import jwt from 'jsonwebtoken';
import { randomBytes } from 'crypto';

// 密钥从环境变量读取，绝不硬编码
const JWT_SECRET = process.env.JWT_SECRET!;
const REFRESH_SECRET = randomBytes(64).toString('hex');

interface TokenPayload {
  userId: string;
  tenantId: string;
  roles: string[];
}

export function generateTokens(payload: TokenPayload) {
  const accessToken = jwt.sign(payload, JWT_SECRET, {
    expiresIn: '15m',        // 短有效期
    issuer: 'lowcode-platform',
    audience: 'lowcode-api',
  });

  const refreshToken = jwt.sign(
    { userId: payload.userId },
    REFRESH_SECRET,
    { expiresIn: '7d' }
  );

  return { accessToken, refreshToken };
}

export function verifyAccessToken(token: string): TokenPayload {
  return jwt.verify(token, JWT_SECRET, {
    issuer: 'lowcode-platform',
    audience: 'lowcode-api',
  }) as TokenPayload;
}
```

  duration: 1,

  return async (req: any, res: any, next: any) => {
    const key = req.ip || req.headers['x-forwarded-for'];
    try {
      await limiter.consume(key);
      next();

    }
  };
}

## 审计日志

审计日志需要回答四个问题：谁（Who）、做了什么（What）、何时做的（When）、在哪里做的（Where）。

```typescript
// src/audit/logger.ts
import { pool } from '../db';

interface AuditEvent {
  userId: string;
  tenantId: string;
  action: string;          // CREATE / UPDATE / DELETE / LOGIN / EXPORT
  resourceType: string;    // form / workflow / user / data
  resourceId: string;
  changes?: {
    before?: Record<string, any>;
    after?: Record<string, any>;
  };
  ip: string;
  userAgent: string;
}

export async function logAudit(event: AuditEvent): Promise<void> {
  await pool.query(
    `INSERT INTO audit_logs
      (user_id, tenant_id, action, resource_type, resource_id, changes, ip, user_agent, created_at)
     VALUES ($1, $2, $3, $4, $5, $6, $7, $8, NOW())`,
    [
      event.userId,
      event.tenantId,
      event.action,
      event.resourceType,
      event.resourceId,
      event.changes ? JSON.stringify(event.changes) : null,
      event.ip,
      event.userAgent,
    ]
  );
}

// 审计中间件：自动记录所有写操作
export function auditMiddleware(action: string, resourceType: string) {
  return (req: any, res: any, next: any) => {
    const originalSend = res.json.bind(res);
    res.json = (body: any) => {
      if (res.statusCode < 400) {
        logAudit({
          userId: req.user?.userId || 'anonymous',
          tenantId: req.user?.tenantId || 'system',
          action,
          resourceType,
          resourceId: req.params.id || body?.id || 'unknown',
          changes: { after: req.body },
          ip: req.ip,
          userAgent: req.headers['user-agent'] || '',
        });
      }
      return originalSend(body);
    };
    next();
  };
}
```

审计日志表结构：

```sql
CREATE TABLE audit_logs (
    id            BIGSERIAL PRIMARY KEY,
    user_id       VARCHAR(64) NOT NULL,
    tenant_id     VARCHAR(64) NOT NULL,
    action        VARCHAR(32) NOT NULL,
    resource_type VARCHAR(64) NOT NULL,
    resource_id   VARCHAR(128) NOT NULL,
    changes       JSONB,
    ip            VARCHAR(45),
    user_agent    TEXT,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_audit_tenant_time ON audit_logs(tenant_id, created_at DESC);
CREATE INDEX idx_audit_user ON audit_logs(user_id, created_at DESC);
```

## 敏感数据脱敏

在日志输出和 API 响应中，敏感字段需要脱敏处理：

```typescript
// src/utils/masking.ts
export function maskPhone(phone: string): string {
  return phone.replace(/(\d{3})\d{4}(\d{4})/, '$1****$2');
}

export function maskIdCard(idCard: string): string {
  return idCard.replace(/(\d{6})\d{8}(\d{4})/, '$1********$2');
}

export function maskEmail(email: string): string {
  const [name, domain] = email.split('@');
  const masked = name.length <= 2
    ? name[0] + '*'
    : name[0] + '*'.repeat(name.length - 2) + name[name.length - 1];
  return `${masked}@${domain}`;
}

// 通用脱敏器
export function maskSensitiveData(data: Record<string, any>): Record<string, any> {
  const result = { ...data };
  if (result.phone) result.phone = maskPhone(result.phone);
  if (result.idCard) result.idCard = maskIdCard(result.idCard);
  if (result.email) result.email = maskEmail(result.email);
  if (result.bankAccount) result.bankAccount = '****' + result.bankAccount.slice(-4);
  return result;
}
```

## 常见误区

1. **认为 HTTPS 就是安全的全部**：TLS 只保护传输过程，不保护存储数据。数据库被拖库后，明文存储的敏感数据依然会泄露
2. **JWT 不设过期时间或设置过长**：永不过期的 Token 一旦泄露，攻击者可以永久冒充用户。Access Token 应设 15 分钟，配合 Refresh Token 机制
3. **审计日志只记成功操作**：失败的登录尝试、越权访问尝试同样需要记录，这些是安全分析的重要数据源

## 工程建议

1. **加密密钥与数据分离存储**：密钥不应与加密数据存放在同一数据库中，建议使用 Vault、AWS KMS 等密钥管理服务
2. **最小权限原则贯穿始终**：数据库连接使用只读账号查询、API 按角色鉴权、文件存储限制访问路径
3. **定期进行安全审计和渗透测试**：不要等客户或监管机构发现问题，主动发现并修复安全漏洞

## 小结

- 数据安全需覆盖传输层（TLS）、存储层（AES-256）、应用层（认证鉴权）三个维度
- JWT 认证应使用短有效期 + Refresh Token 机制，密钥从环境变量读取
- 审计日志记录"谁/什么/何时/何地"，是合规和安全分析的基础
- 敏感数据在 API 响应和日志输出中必须脱敏
- 安全响应头（CSP/HSTS/Referrer-Policy）是防御 XSS 和信息泄露的基本手段

## 参考答案

### 练习一

**思路**：使用 Node.js 内置 crypto 模块，选择 AES-256-GCM 认证加密模式。每次加密生成随机 IV，将 IV + AuthTag + 密文拼接后 Base64 编码。

**答案**：
```typescript
import { createCipheriv, createDecipheriv, randomBytes } from 'crypto';

const KEY = Buffer.from(process.env.ENCRYPTION_KEY!, 'hex');

export function encrypt(plaintext: string): string {
  const iv = randomBytes(16);
  const cipher = createCipheriv('aes-256-gcm', KEY, iv);
  const enc = Buffer.concat([cipher.update(plaintext, 'utf8'), cipher.final()]);
  const tag = cipher.getAuthTag();
  return Buffer.concat([iv, tag, enc]).toString('base64');
}

export function decrypt(encoded: string): string {
  const buf = Buffer.from(encoded, 'base64');
  const iv = buf.subarray(0, 16);
  const tag = buf.subarray(16, 32);
  const data = buf.subarray(32);
  const decipher = createDecipheriv('aes-256-gcm', KEY, iv);
  decipher.setAuthTag(tag);
  return decipher.update(data) + decipher.final('utf8');
}
```

**要点**：
- ENCRYPTION_KEY 必须是 64 字符的十六进制字符串（32 字节）
- GCM 模式的 AuthTag 可防止密文被篡改
- 每次加密使用随机 IV，即使相同明文也会产生不同密文

### 练习二

**思路**：在中间件中拦截 res.json，判断响应状态码确定操作是否成功，从 req 对象提取用户信息和请求参数，写入审计日志表。

**答案**：
```typescript
import { Request, Response, NextFunction } from 'express';

export function auditLog(resourceType: string) {
  return (req: Request, res: Response, next: NextFunction) => {
    const originalJson = res.json.bind(res);
    const beforeData = (req as any).originalData;

    res.json = (body: any) => {
      if (res.statusCode < 400 && ['POST', 'PUT', 'PATCH', 'DELETE'].includes(req.method)) {
        const log = {
          userId: (req as any).user?.id,
          action: req.method,
          resourceType,
          resourceId: req.params.id || body?.id,
          before: beforeData || null,
          after: req.method !== 'DELETE' ? req.body : null,
          ip: req.ip,
          timestamp: new Date().toISOString(),
        };
        // 异步写入，不阻塞响应
        saveAuditLog(log).catch(console.error);
      }
      return originalJson(body);
    };
    next();
  };
}
```

**要点**：
- 使用 res.json 拦截而非 res.send，确保能获取结构化响应数据
- 审计日志写入应异步执行，避免影响接口响应时间
- DELETE 操作需要记录 before 而非 after
