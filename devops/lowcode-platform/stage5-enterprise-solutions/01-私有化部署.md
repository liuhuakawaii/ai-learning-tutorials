# 私有化部署

> 前置知识：低代码平台基础（阶段一至四）

## 为什么需要私有化部署

某中型制造企业采购了一套低代码平台，用于构建内部生产管理系统。IT 部门接到任务：将平台部署到公司自有机房的服务器上，而不是使用 SaaS 版本。

原因是生产数据涉及核心工艺参数，安全合规要求数据不出公司网络。

私有化部署看似只是"把代码跑起来"，实际涉及容器编排、网络配置、域名证书、持久化存储、监控告警等一系列工程问题。

## Docker Compose 部署（单机）

适合：小规模（50 人以下）、快速验证。

```yaml
services:
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/conf.d:/etc/nginx/conf.d:ro
      - ./ssl:/etc/nginx/ssl:ro
    depends_on:
      - api
      - frontend
    restart: unless-stopped

  frontend:
    image: my-lowcode-platform/frontend:latest
    restart: unless-stopped

  api:
    image: my-lowcode-platform/api:latest
    environment:
      DATABASE_URL: postgres://postgres:${DB_PASSWORD}@db:5432/lowcode
      REDIS_URL: redis://redis:6379
      STORAGE_ENDPOINT: http://minio:9000
      STORAGE_ACCESS_KEY: ${MINIO_ACCESS_KEY}
      STORAGE_SECRET_KEY: ${MINIO_SECRET_KEY}
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_started
    restart: unless-stopped

  db:
    image: postgres:14-alpine
    environment:
      POSTGRES_DB: lowcode
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      retries: 5
    restart: unless-stopped

  redis:
    image: redis:7-alpine
    volumes:
      - redis-data:/data
    restart: unless-stopped

  minio:
    image: minio/minio
    command: server /data --console-address ":9001"
    ports:
      - "9000:9000"
      - "9001:9001"
    environment:
      MINIO_ROOT_USER: ${MINIO_ACCESS_KEY}
      MINIO_ROOT_PASSWORD: ${MINIO_SECRET_KEY}
    volumes:
      - minio-data:/data
    restart: unless-stopped

volumes:
  pgdata:
  redis-data:
  minio-data:
```

## Kubernetes 部署（集群）

适合：大规模（100+ 人）、高可用要求。

```yaml
# values-production.yaml
api:
  replicaCount: 3
  resources:
    limits:
      memory: "512Mi"
      cpu: "500m"

frontend:
  replicaCount: 2

database:
  type: external
  host: pg-cluster.internal.company.com
  port: 5432

redis:
  type: external
  host: redis-cluster.internal.company.com

ingress:
  enabled: true
  host: lowcode.internal.company.com
  tls:
    secretName: lowcode-tls

monitoring:
  enabled: true
  serviceMonitor: true
```

```bash
helm install lowcode ./lowcode-chart -f values-production.yaml -n lowcode --create-namespace
```

## 域名与证书

```nginx
# nginx/conf.d/lowcode.conf
server {
    listen 80;
    server_name lowcode.internal.company.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name lowcode.internal.company.com;

    ssl_certificate /etc/nginx/ssl/lowcode.crt;
    ssl_certificate_key /etc/nginx/ssl/lowcode.key;

    location /api/ {
        proxy_pass http://api:3000/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    location / {
        proxy_pass http://frontend:3000;
    }

    location /files/ {
        proxy_pass http://minio:9000/;
    }
}
```

## 数据备份

```bash
#!/bin/bash
# backup.sh

BACKUP_DIR="/data/backups/lowcode"
TIMESTAMP=$(date +%Y%m%d_%H%M%S)

# 数据库备份
docker compose exec -T db pg_dump -U postgres lowcode | gzip > "$BACKUP_DIR/db_$TIMESTAMP.sql.gz"

# 文件存储备份
mc mirror minio/lowcode-files "$BACKUP_DIR/files_$TIMESTAMP/"

# 保留最近 30 天
find $BACKUP_DIR -mtime +30 -delete
```

## 练习

### 练习一：Docker Compose 部署

在本地用 Docker Compose 部署完整的低代码平台。配置 .env 文件管理所有密钥。

### 练习二：健康检查

为每个服务添加健康检查。模拟 API 服务崩溃，验证 Docker 自动重启。

### 练习三：升级方案

设计一个零停机升级方案：新版本镜像发布后，如何在不影响用户的情况下升级？

### 练习三

零停机升级方案：

```bash
#!/bin/bash
# upgrade.sh

NEW_TAG=$1

# 拉取新镜像
TAG=$NEW_TAG docker compose pull api frontend

# 滚动更新 API（先启动新实例）
docker compose up -d --no-deps --scale api=2 api

# 等待新实例健康
sleep 15

# 停止旧实例
docker compose up -d --no-deps --scale api=1 api

# 更新前端
docker compose up -d --no-deps frontend

echo "Upgrade to $NEW_TAG completed"
```
