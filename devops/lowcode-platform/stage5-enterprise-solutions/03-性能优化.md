# 性能优化

## 场景引入

某低代码平台上线后收到了大量性能投诉：首页加载需要 8 秒，表单设计器拖拽操作卡顿明显，大表单（50+ 字段）保存时接口超时。运维监控显示，高峰期 CPU 占用率持续超过 90%，数据库连接池经常耗尽。

性能问题往往不是单一原因造成的，而是前端资源体积过大、缺少缓存策略、数据库查询未优化、静态资源未使用 CDN 等多个问题叠加的结果。本课将从前端、后端、基础设施三个层面，系统讲解低代码平台的性能优化策略。

## 学习目标

- 掌握多级缓存策略的设计与实现（浏览器/CDN/Redis/应用层）
- 学会使用代码分割和懒加载优化前端加载性能
- 理解数据库查询优化的核心方法（索引/分页/连接池）
- 掌握打包分析和 Tree-shaking 技术减少前端包体积

## 浏览器缓存策略

合理配置 HTTP 缓存头，可以让浏览器直接使用本地缓存，避免重复请求。

```nginx
# Nginx 缓存配置
# HTML 文件：不缓存，始终从服务器获取最新版本
location ~* \.html$ {
    add_header Cache-Control "no-cache, must-revalidate";
}

# 带 hash 的静态资源：长期缓存（文件名变化则自动失效）
location ~* \.(js|css|woff2?)$ {
    expires 1y;
    add_header Cache-Control "public, immutable";
}

# 图片资源：中期缓存
location ~* \.(png|jpg|jpeg|gif|webp|svg)$ {
    expires 30d;
    add_header Cache-Control "public";
}

# API 响应：不缓存
location /api/ {
    add_header Cache-Control "no-store";
}
```

## Redis 多级缓存

```typescript
// src/cache/manager.ts
import { redis } from '../redis';

interface CacheOptions {
  ttl: number;           // 过期时间（秒）
  prefix: string;        // 缓存键前缀
}

export class CacheManager {
  private prefix: string;
  private defaultTtl: number;

  constructor(options: CacheOptions) {
    this.prefix = options.prefix;
    this.defaultTtl = options.ttl;
  }

  private buildKey(key: string): string {
    return `${this.prefix}:${key}`;
  }

  async get<T>(key: string): Promise<T | null> {
    const cached = await redis.get(this.buildKey(key));
    if (!cached) return null;
    try {
      return JSON.parse(cached) as T;
    } catch {
      return null;
    }
  }

  async set(key: string, value: any, ttl?: number): Promise<void> {
    await redis.setex(
      this.buildKey(key),
      ttl || this.defaultTtl,
      JSON.stringify(value)
    );
  }

  async invalidate(key: string): Promise<void> {
    await redis.del(this.buildKey(key));
  }

  async invalidatePattern(pattern: string): Promise<void> {
    const keys = await redis.keys(`${this.prefix}:${pattern}`);
    if (keys.length > 0) {
      await redis.del(...keys);
    }
  }
}

// 表单配置缓存：TTL 5 分钟
export const formCache = new CacheManager({ prefix: 'form', ttl: 300 });

// 用户权限缓存：TTL 10 分钟
export const permissionCache = new CacheManager({ prefix: 'perm', ttl: 600 });
```

### 缓存穿透防护

```typescript
// src/cache/protection.ts
import { redis } from '../redis';

// 布隆过滤器：防止缓存穿透
export async function getWithProtection<T>(
  key: string,
  fetchFn: () => Promise<T | null>,
  ttl: number = 300
): Promise<T | null> {
  // 1. 查缓存
  const cached = await redis.get(key);
  if (cached === 'NULL') return null; // 空值缓存
  if (cached) return JSON.parse(cached);

  // 2. 查数据库
  const data = await fetchFn();

  // 3. 写回缓存（空值也缓存，防止穿透）
  if (data === null) {
    await redis.setex(key, 60, 'NULL'); // 空值缓存 60 秒
  } else {
    await redis.setex(key, ttl, JSON.stringify(data));
  }

  return data;
}
```

// src/utils/imageOptimize.ts
// WebP 转换与响应式图片
export function getOptimizedImageUrl(
  originalUrl: string,
  options: { width?: number; quality?: number; format?: 'webp' | 'avif' } = {}
): string {
  const { width, quality = 80, format = 'webp' } = options;
  const params = new URLSearchParams();
  if (width) params.set('w', String(width));
  params.set('q', String(quality));
  params.set('fm', format);
  return `${originalUrl}?${params.toString()}`;
}

// 图片懒加载 Hook
import { useEffect, useRef, useState } from 'react';

export function useLazyImage(src: string) {
  const imgRef = useRef<HTMLImageElement>(null);
  const [loaded, setLoaded] = useState(false);

  useEffect(() => {
    const observer = new IntersectionObserver(
      ([entry]) => {
        if (entry.isIntersecting) {
          const img = imgRef.current;
          if (img) {
            img.src = src;
            img.onload = () => setLoaded(true);
            observer.unobserve(img);
          }
        }
      },
      { rootMargin: '200px' }
    );

    if (imgRef.current) observer.observe(imgRef.current);
    return () => observer.disconnect();
  }, [src]);

  return { imgRef, loaded };
}

### 分页查询优化

```typescript
// 传统 OFFSET 分页的问题：深分页性能差
// SELECT * FROM form_data ORDER BY id OFFSET 10000 LIMIT 20;
// 数据库需要扫描前 10020 行再丢弃前 10000 行

// 使用游标分页（Cursor-based Pagination）
export async function getFormDataPaginated(
  tenantId: string,
  formId: string,
  cursor?: string,  // 上一页最后一条记录的 ID
  limit: number = 20
) {
  const conditions = ['tenant_id = $1', 'form_id = $2'];
  const params: any[] = [tenantId, formId];

  if (cursor) {
    conditions.push('id < $3');
    params.push(cursor);
  }

  const query = `
    SELECT * FROM form_data
    WHERE ${conditions.join(' AND ')}
    ORDER BY id DESC
    LIMIT ${limit + 1}
  `;

  const result = await pool.query(query, params);
  const hasMore = result.rows.length > limit;
  const data = hasMore ? result.rows.slice(0, limit) : result.rows;
  const nextCursor = hasMore ? data[data.length - 1].id : null;

  return { data, nextCursor, hasMore };
}
```

## 常见误区

1. **过度使用缓存导致数据不一致**：缓存更新策略不当，用户修改数据后看到的仍是旧数据。写操作必须同步失效相关缓存
2. **懒加载粒度太细**：每个组件都做懒加载会产生大量小 chunk，增加 HTTP 请求数。应按路由或功能模块划分
3. **只看 SQL 不看执行计划**：加了索引不代表查询一定会用。使用 `EXPLAIN ANALYZE` 验证索引是否生效

## 工程建议

1. **先测量再优化**：使用 Lighthouse、Chrome DevTools Performance 面板定位真正的瓶颈，不要凭直觉优化
2. **缓存分层设计**：浏览器缓存 → CDN 缓存 → Redis 缓存 → 数据库，每一层解决不同粒度的性能问题
3. **建立性能基准和监控**：记录首次加载时间、API P99 延迟等指标，设置告警阈值，避免性能劣化无人知晓

## 小结

- 缓存是性能优化的第一手段，按浏览器/CDN/Redis/应用层分层设计，每层解决不同问题
- 代码分割和懒加载是减少首屏加载时间的关键技术，按路由和功能模块划分 chunk
- 数据库优化的核心是索引设计和分页策略，深分页场景使用游标分页替代 OFFSET
- 打包分析工具帮助发现冗余依赖，Tree-shaking 消除未使用的代码
- 性能优化必须以数据为驱动，先定位瓶颈再针对性优化

## 参考答案

### 练习一

**思路**：封装 Redis 操作为泛型类，构造函数接收前缀和 TTL。get 时反序列化，set 时序列化并设置过期时间，空值用特殊标记缓存。

**答案**：
```typescript
import { Redis } from 'ioredis';

export class CacheManager<T = any> {
  private redis: Redis;
  private prefix: string;
  private ttl: number;
  private NULL_MARKER = '__NULL__';

  constructor(redis: Redis, prefix: string, ttl: number = 300) {
    this.redis = redis;
    this.prefix = prefix;
    this.ttl = ttl;
  }

  private key(k: string): string {
    return `${this.prefix}:${k}`;
  }

  async get(key: string): Promise<T | null> {
    const val = await this.redis.get(this.key(key));
    if (val === this.NULL_MARKER) return null;
    return val ? JSON.parse(val) : null;
  }

  async set(key: string, value: T | null, ttl?: number): Promise<void> {
    const serialized = value === null ? this.NULL_MARKER : JSON.stringify(value);
    await this.redis.setex(this.key(key), ttl || this.ttl, serialized);
  }

  async invalidate(key: string): Promise<void> {
    await this.redis.del(this.key(key));
  }

  async getOrFetch(key: string, fetcher: () => Promise<T | null>): Promise<T | null> {
    const cached = await this.get(key);
    if (cached !== undefined) return cached;
    const fresh = await fetcher();
    await this.set(key, fresh);
    return fresh;
  }
}
```

**要点**：
- 空值缓存使用特殊标记（`__NULL__`）区分"未缓存"和"缓存了空值"
- getOrFetch 方法封装了"查缓存 → 查库 → 回填缓存"的标准流程
- TTL 应根据数据更新频率设置：用户权限 10 分钟，表单配置 5 分钟

### 练习二

**思路**：OFFSET 在深分页时需要扫描大量行再丢弃，游标分页利用上一页最后一条记录的 ID 作为起点，直接定位。

**答案**：
```sql
-- 传统 OFFSET（第 500 页，每页 20 条）
-- 需要扫描 10000 行再丢弃
SELECT * FROM form_data
WHERE tenant_id = 't1' AND form_id = 'f1'
ORDER BY id DESC
OFFSET 9980 LIMIT 20;

-- 游标分页（已知上一页最后一条 id = 12345）
-- 直接从 id < 12345 开始扫描
SELECT * FROM form_data
WHERE tenant_id = 't1' AND form_id = 'f1' AND id < 12345
ORDER BY id DESC
LIMIT 20;
```

```typescript
// 接口实现
async function getPage(cursor?: string, limit = 20) {
  let query = 'SELECT * FROM form_data WHERE tenant_id = $1';
  const params: any[] = [tenantId];

  if (cursor) {
    query += ' AND id < $2';
    params.push(cursor);
  }

  query += ` ORDER BY id DESC LIMIT ${limit + 1}`;
  const { rows } = await pool.query(query, params);

  return {
    data: rows.slice(0, limit),
    nextCursor: rows.length > limit ? rows[limit - 1].id : null,
  };
}
```

**要点**：
- 游标分页要求 ORDER BY 字段有索引，否则性能无提升
- 游标分页无法直接跳转到第 N 页，适合"无限滚动"场景
- 深分页性能差异：OFFSET 可能需要数秒，游标分页通常在 10ms 以内
