# AI 辅助建模：自然语言生成数据模型

## 场景引入

张伟是一家电商公司的产品经理，需要为售后管理系统设计数据模型。传统做法是写需求文档、交给架构师设计 ER 图、开发人员手动建表，通常需要 3-5 天。一旦需求理解有偏差，返工成本很高。

现在张伟打开低代码平台的 AI 建模助手，用中文描述："我需要一个售后工单系统，客户提交工单，客服分配处理，支持多轮沟通记录，工单有优先级和状态流转。"几秒钟后，AI 自动生成了完整的数据模型，字段类型、关联关系、枚举值都已推断完毕。

这就是 AI 辅助建模的核心价值：**将业务语言直接转化为技术实现**。

## 学习目标

- 理解自然语言到数据模型的转换原理与技术链路
- 掌握针对 Schema 生成的 Prompt Engineering 技巧
- 学会使用 LLM 推断字段类型、生成关联关系
- 能够实现完整的模型校验与迭代优化闭环

## 转换架构与数据结构

从自然语言到数据模型的链路：用户输入 → Prompt 构造 → LLM 推理 → 结构化 JSON → 校验修正 → 最终模型。

LLM 输出的中间格式是标准化 JSON Schema：

```typescript
interface FieldDefinition {
  name: string;
  type: 'string' | 'number' | 'boolean' | 'date' | 'enum' | 'relation';
  label: string;
  required: boolean;
  enumValues?: string[];
  relation?: {
    target: string;
    type: 'oneToOne' | 'oneToMany' | 'manyToMany';
    foreignKey: string;
  };
}

interface EntityDefinition {
  name: string;
  label: string;
  fields: FieldDefinition[];
}

interface DataModel {
  entities: EntityDefinition[];
  metadata: { generatedFrom: string; version: string; timestamp: string };
}
```

## Prompt Engineering for Schema 生成

### 基础 Prompt 模板

```typescript
const SCHEMA_PROMPT = `你是数据建模专家。根据业务描述生成数据模型 JSON。
规则：
1. 每个业务实体生成一个 EntityDefinition
2. 每个实体必须有 id（自增主键）和 createdAt、updatedAt
3. 字段类型：string/number/boolean/date/enum/relation
4. 外键用 relation 类型表示，枚举必须列出所有值
5. 字段名 camelCase，标签中文

用户描述：{{USER_INPUT}}
输出严格 JSON DataModel：`;

async function generateSchema(userInput: string): Promise<DataModel> {
  const response = await openai.chat.completions.create({
    model: 'gpt-4o',
    messages: [
      { role: 'system', content: '你只输出 JSON。' },
      { role: 'user', content: SCHEMA_PROMPT.replace('{{USER_INPUT}}', userInput) }
    ],
    temperature: 0.1,
    response_format: { type: 'json_object' }
  });
  return JSON.parse(response.choices[0].message.content) as DataModel;
}
```

### 上下文感知 Prompt

当系统中已有数据模型时，Prompt 需要感知已有上下文避免重复建模：

const CONTEXT_AWARE_PROMPT = `你是数据建模专家。用户已有以下模型：

## 字段类型推断与关系生成

LLM 结合语义理解和业务规则推断字段类型：

```typescript
async function inferFieldTypes(fields: FieldDefinition[], context: string): Promise<FieldDefinition[]> {
  const prompt = `根据业务上下文推断字段最佳类型。
上下文：${context}
字段列表：${fields.map(f => `- ${f.name} (${f.label})`).join('\n')}
返回 JSON 数组，每项含 name、type、enumValues（如适用）、confidence。`;

  const response = await openai.chat.completions.create({
    model: 'gpt-4o',
    messages: [{ role: 'user', content: prompt }],
    temperature: 0.1,
    response_format: { type: 'json_object' }
  });
  return mergeInferredTypes(fields, JSON.parse(response.choices[0].message.content).fields);
}
```

关系推断基于字段命名模式和业务语义：

```typescript
async function inferRelationships(entities: EntityDefinition[]): Promise<EntityDefinition[]> {
  const prompt = `分析以下实体间关系：${entities.map(e => `[${e.label}] ${e.fields.map(f => f.name).join(',')}`).join('\n')}
规则：字段名含另一实体名→oneToMany，中间表关联→manyToMany。
输出关系列表 JSON：source、target、type、foreignKey。`;

  const response = await openai.chat.completions.create({
    model: 'gpt-4o',
    messages: [{ role: 'user', content: prompt }],
    temperature: 0.1,
    response_format: { type: 'json_object' }
  });
  return applyRelations(entities, JSON.parse(response.choices[0].message.content).relations);
}
```

## 模型校验与迭代优化

### 校验层

```typescript
function validateModel(model: DataModel): ValidationResult {
  const errors: ValidationError[] = [];
  const warnings: ValidationWarning[] = [];

  for (const entity of model.entities) {
    if (!entity.fields.some(f => f.name === 'id')) {
      errors.push({ entity: entity.name, message: '缺少主键 id' });
    }
    for (const field of entity.fields) {
      if (field.type === 'enum' && (!field.enumValues?.length)) {
        errors.push({ entity: entity.name, field: field.name, message: '枚举必须提供 enumValues' });
      }
      if (field.type === 'relation' && !field.relation?.target) {
        errors.push({ entity: entity.name, field: field.name, message: '关系必须指定目标实体' });
      }
    }
    // 检查关系完整性
    for (const field of entity.fields.filter(f => f.type === 'relation')) {
      const targetExists = model.entities.some(e => e.name === field.relation!.target);
      if (!targetExists) {
        errors.push({ entity: entity.name, field: field.name, message: `关联实体 ${field.relation!.target} 不存在` });
      }
    }
  }
  return { valid: errors.length === 0, errors, warnings };
}
```

### 迭代修复闭环

```typescript
async function refineModel(model: DataModel, validation: ValidationResult, feedback?: string): Promise<DataModel> {
  const prompt = `修复以下数据模型问题。
模型：${JSON.stringify(model, null, 2)}
错误：${validation.errors.map(e => `- [${e.entity}] ${e.message}`).join('\n')}
${feedback ? `用户反馈：${feedback}` : ''}
输出修复后的 DataModel JSON。`;

  const response = await openai.chat.completions.create({
    model: 'gpt-4o',
    messages: [{ role: 'user', content: prompt }],
    temperature: 0.1,
    response_format: { type: 'json_object' }
  });
  const refined = JSON.parse(response.choices[0].message.content) as DataModel;
  const reCheck = validateModel(refined);
  return reCheck.valid ? refined : refineModel(refined, reCheck, feedback);
}
```

## 常见误区

1. **完全依赖 AI 输出不做校验**：LLM 可能遗漏必填字段或错误推断关联关系，必须将 AI 输出作为初稿经过校验层确认。
2. **Prompt 过于简短**：只写"帮我建一个订单系统"缺乏业务上下文，生成的模型过于通用。应提供具体业务流程、角色、状态流转。
3. **忽略已有模型复用**：每次从零生成导致同一概念存在多个版本，Prompt 中应注入已有模型信息。

## 工程建议

1. **分步生成**：复杂系统先生成核心实体，再逐步扩展子实体和关联关系，避免一次性生成导致关系遗漏。
2. **建立领域 Prompt 库**：针对电商、CRM、工单等常见场景积累专用模板，包含领域特有的字段规范。
3. **保留生成历史**：记录每次的原始 Prompt、AI 输出、人工修改，便于追溯和调优。

## 小结

- AI 辅助建模通过 LLM 将自然语言直接转化为结构化数据模型，核心链路为：输入 → Prompt → LLM → 校验 → 模型
- Prompt Engineering 是质量关键，需包含角色设定、输出格式约束、已有上下文注入
- 字段类型推断结合 LLM 语义理解和规则引擎，对枚举、日期、布尔等类型准确率高
- 模型校验层确保技术正确性，迭代闭环处理校验失败

### 练习一

**思路**：Prompt 应包含角色设定、业务场景、输出格式、命名规范，并明确列出需要的实体和关键字段。

**答案**：
```typescript
const LEAVE_PROMPT = `你是数据建模专家。为员工请假系统生成数据模型。
业务：员工信息管理（姓名、部门、职位、入职时间）、请假申请（类型：年假/事假/病假/调休，开始时间、结束时间、天数、事由）、审批记录（审批人、状态：待审批/已通过/已拒绝、意见、时间）。
命名：实体 PascalCase，字段 camelCase，标签中文，每实体含 id/createdAt/updatedAt。
输出严格 JSON DataModel。`;
```

**要点**：业务描述具体到字段级别减少猜测，命名规范在 Prompt 中明确声明。

### 练习二

**思路**：在校验函数中逐条添加检查逻辑，使用 Set 检测字段名重复。

**答案**：
```typescript
function validateModel(model: DataModel): ValidationResult {
  const errors: ValidationError[] = [];
  for (const entity of model.entities) {
    const fieldNames = new Set<string>();
    for (const field of entity.fields) {
      if (/^\d/.test(field.name)) {
        errors.push({ entity: entity.name, field: field.name, message: '字段名不能以数字开头' });
      }
      if (fieldNames.has(field.name)) {
        errors.push({ entity: entity.name, field: field.name, message: `字段名 ${field.name} 重复` });
      }
      fieldNames.add(field.name);
      if (field.type === 'relation' && field.relation) {
        const target = model.entities.find(e => e.name === field.relation!.target);
        if (target && !target.fields.some(f => f.name === field.relation!.foreignKey)) {
          errors.push({ entity: entity.name, field: field.name, message: `外键 ${field.relation.foreignKey} 在目标实体中不存在` });
        }
      }
    }
  }
  return { valid: errors.length === 0, errors, warnings: [] };
}
```

**要点**：Set 检测重复 O(n) 复杂度，外键校验需先找到目标实体再检查字段。
