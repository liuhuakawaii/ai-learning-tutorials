# AI 数据处理：自然语言查询与智能数据清洗

## 场景引入

王芳是数据分析师，每天需要从多个系统提取数据、清洗整理、生成报表。她的流程是：导出订单数据 → Excel 去重 → 手动分类 → 写 SQL 查询 → 制作图表，耗时 3-4 小时。

接入 AI 后，她只需描述："查询上个月各产品线销售额，按区域分组，去除测试订单"，AI 自动转为 SQL 并返回结果。数据清洗也不再手动操作——AI 自动识别重复记录、标准化地址格式、按规则分类标记。

- 掌握自然语言到 SQL/API 查询的转换技术

- 能够构建完整的数据转换管线

## 自然语言到 SQL 查询

### Schema-Aware Prompt

```typescript
interface TableSchema { name: string; label: string; columns: Array<{ name: string; type: string; label: string; description?: string }> }

const NL_TO_SQL_PROMPT = `你是 SQL 专家。根据用户查询和数据库结构生成 SQL。
数据库结构：{{SCHEMAS}}
规则：只用上述表和字段，标准 MySQL 8.0 语法，时间用 DATE_SUB/CURDATE()，金额用 DECIMAL。
输出：{ sql, explanation, confidence } JSON。`;

async function naturalLanguageToSQL(query: string, schemas: TableSchema[]): Promise<{ sql: string; explanation: string; confidence: number }> {
  const schemaText = schemas.map(s => `表 ${s.name} [${s.label}]:\n${s.columns.map(c => `  ${c.name} (${c.type}): ${c.label}`).join('\n')}`).join('\n\n');
  const response = await openai.chat.completions.create({
    model: 'gpt-4o',
    messages: [{ role: 'system', content: '只输出 JSON。' }, { role: 'user', content: NL_TO_SQL_PROMPT.replace('{{SCHEMAS}}', schemaText).replace('{{USER_QUERY}}', query) }],
    temperature: 0.1, response_format: { type: 'json_object' }
  });
  return JSON.parse(response.choices[0].message.content);
}
```

### SQL 安全校验

```typescript
function validateSQL(sql: string): { safe: boolean; reason?: string } {
  const upper = sql.trim().toUpperCase();
  const blocked = ['DROP', 'DELETE', 'TRUNCATE', 'ALTER', 'INSERT', 'UPDATE', 'GRANT', 'EXEC'];
  for (const kw of blocked) {
    if (upper.startsWith(kw) || upper.includes(`; ${kw}`)) return { safe: false, reason: `禁止 ${kw} 操作` };
  }
  if ((sql.match(/;/g) || []).length > 1) return { safe: false, reason: '禁止多语句' };
  if (upper.includes('--') || upper.includes('/*')) return { safe: false, reason: '禁止注释' };
  return { safe: true };
}
```

## AI 驱动的数据清洗

```typescript

async function standardizeData(data: Record<string, unknown>[], rules: Array<{ field: string; rule: string; example: { before: string; after: string } }>): Promise<Record<string, unknown>[]> {
```

## 数据转换管线

将多个处理步骤组合为可编排管线：

```typescript
type PipelineStep =
  | { type: 'deduplicate'; config: { fields: string[] } }
  | { type: 'standardize'; config: { rules: Array<{ field: string; rule: string }> } }
  | { type: 'categorize'; config: { field: string; categories: string[]; rules: string } };

class DataPipeline {
  private steps: PipelineStep[] = [];
  addStep(step: PipelineStep): this { this.steps.push(step); return this; }

  async execute(data: Record<string, unknown>[]): Promise<Record<string, unknown>[]> {
    let result = [...data];
    for (const step of this.steps) {
      switch (step.type) {
        case 'deduplicate':
          const dedup = await detectDuplicates(result, '');
          result = dedup.groups.map(g => g.mergedRecord);
          break;
        case 'standardize':
          result = await standardizeData(result, step.config.rules);
          break;
        case 'categorize':
          const cats = await categorizeData(result, step.config.field, step.config.categories, step.config.rules);
          result = result.map((row, i) => ({ ...row, [`${step.config.field}_category`]: cats.find(c => c.index === i)?.category }));
          break;
      }
    }
    return result;
  }
}
```

## 常见误区

1. **直接执行 AI 生成的 SQL**：必须先安全校验再沙箱执行验证结果。
2. **用 AI 逐行处理大数据**：百万级数据应让 AI 生成规则再用代码批量执行，平衡效果与成本。
3. **忽略数据隐私**：敏感信息（身份证、手机号）应先脱敏再调用外部 LLM API。

## 工程建议

1. **NL-to-SQL 结合 RAG**：复杂 Schema 用 RAG 检索相关表字段，只注入相关 Schema 避免超 Token。
2. **建立数据质量基线**：清洗前后记录完整性、一致性、准确性指标，量化 AI 清洗效果。
3. **人工确认环节**：AI 去重和分类结果应展示给用户确认，避免误操作导致数据丢失。

## 小结

- NL-to-SQL 通过 Schema-Aware Prompt 将用户意图转化为 SQL，安全校验层防止危险操作
- 文本到图表根据数据特征和意图推荐可视化方案
- AI 数据清洗包括重复检测、标准化、智能分类，管线编排组合复杂流程
- 大规模数据应将 AI 用于规则生成而非逐行处理

### 练习一

**思路**：构造 Schema 信息注入 Prompt，字段类型和中文标签帮助 LLM 理解。

**答案**：
```typescript
const schemas: TableSchema[] = [{
  name: 'orders', label: '订单表',
  columns: [
    { name: 'id', type: 'INT', label: '订单ID' },
    { name: 'customer_name', type: 'VARCHAR', label: '客户姓名' },
    { name: 'product', type: 'VARCHAR', label: '商品名称' },
    { name: 'amount', type: 'DECIMAL', label: '订单金额' },
    { name: 'status', type: 'VARCHAR', label: '状态', description: 'pending/shipped/delivered/cancelled' },
    { name: 'created_at', type: 'DATETIME', label: '创建时间' }
  ]
}];
// 预期生成：SELECT * FROM orders WHERE created_at >= DATE_SUB(CURDATE(), INTERVAL 1 MONTH) AND amount > 1000 AND status = 'shipped'
```

**要点**：description 字段帮助 LLM 理解枚举值，Prompt 要求用 DATE_SUB 处理时间。

### 练习二

**思路**：去重基于手机号（最稳定唯一标识），标准化针对地址和手机号格式，异常检测关注邮箱和手机号。

**答案**：
```typescript
const pipeline = new DataPipeline();
pipeline
  .addStep({ type: 'deduplicate', config: { fields: ['phone'] } })
  .addStep({ type: 'standardize', config: { rules: [
    { field: 'phone', rule: '去除空格横线，统一11位纯数字', example: { before: '138-1234-5678', after: '13812345678' } },
    { field: 'address', rule: '补全省市区前缀', example: { before: '朝阳区建国路88号', after: '北京市朝阳区建国路88号' } },
    { field: 'email', rule: '统一小写', example: { before: 'User@GMAIL.COM', after: 'user@gmail.com' } }

  .addStep({ type: 'categorize', config: { field: 'address', categories: ['华北','华东','华南','华中','西南','西北','东北'], rules: '根据省份判断区域' } });
```

**要点**：去重选最稳定字段，标准化在分类之前执行。
