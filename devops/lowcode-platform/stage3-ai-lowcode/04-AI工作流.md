# AI 工作流：AI 节点集成与智能审批

## 场景引入

陈刚是制造企业 IT 负责人，公司使用低代码平台搭建了采购审批流程。传统流程是：申请人提交 → 部门经理 → 财务 → 总经理。问题是 80% 的采购是常规小额采购，不需要总经理审批，但系统无法自动判断，导致总经理每天审批上百条申请。

引入 AI 后，系统自动分析采购申请的金额、供应商历史、品类风险，将申请分为"常规"和"高风险"两类。常规采购自动通过，高风险才升级到总经理。总经理工作量下降 70%，审批质量反而提高。

## 学习目标

- 理解 AI 节点在工作流引擎中的定位与集成方式
- 掌握基于 AI 的智能路由分类与分发机制
- 学会实现 AI 驱动的审批辅助（风险评估、情感分析）
- 能够构建包含 AI 节点的完整审批工作流

## AI 节点集成

### 节点类型扩展

```typescript
type NodeType = 'start' | 'end' | 'human' | 'auto' | 'condition' | 'ai';

interface WorkflowNode {
  id: string;
  type: NodeType;
  label: string;
  config: NodeConfig;
  next: Array<{ condition?: string; targetNodeId: string }>;
}

interface AINodeConfig {
  aiType: 'classify' | 'analyze' | 'generate' | 'extract' | 'decide';
  prompt: string;
  model?: string;
  inputMapping: Record<string, string>;
  outputMapping: Record<string, string>;
  fallbackAction?: 'skip' | 'retry' | 'manual';
  maxRetries?: number;
}
```

### AI 节点执行器

```typescript
class AIWorkflowExecutor {
  async executeAINode(node: WorkflowNode, context: Record<string, unknown>): Promise<Record<string, unknown>> {
    const config = node.config as AINodeConfig;
    let prompt = config.prompt;
    for (const [varKey, ctxKey] of Object.entries(config.inputMapping)) {
      prompt = prompt.replace(`{{${varKey}}}`, String(context[ctxKey]));
    }
    const response = await openai.chat.completions.create({
      model: config.model || 'gpt-4o',
      messages: [{ role: 'system', content: '只输出 JSON。' }, { role: 'user', content: prompt }],
      temperature: 0.1, response_format: { type: 'json_object' }
    });
    const result = JSON.parse(response.choices[0].message.content);
    const output: Record<string, unknown> = {};
    for (const [resKey, ctxKey] of Object.entries(config.outputMapping)) {
      output[ctxKey] = result[resKey];
    }
    return output;
  }
}
```

## 智能路由：分类与分发

### 分类节点

```typescript
const CLASSIFICATION_PROMPT = `将申请分类到以下类别：{{CATEGORIES}}
申请信息：申请人{{applicant}}，部门{{department}}，内容{{content}}，金额{{amount}}，紧急程度{{urgency}}
输出：{ category, confidence, reason, suggestedPriority }`;

function buildRouting(result: { category: string; confidence: number }): string {
  if (result.confidence < 0.7) return 'manual_review';
  const map: Record<string, string> = { routine: 'auto_approve', standard: 'manager_approve', high_risk: 'director_approve', urgent: 'expedited_flow' };
  return map[result.category] || 'manual_review';
}
```

## AI 驱动的审批辅助

### 风险评估节点

```typescript
const RISK_PROMPT = `分析审批申请的风险。
申请：{{DETAILS}}
历史：申请次数{{historyCount}}，通过率{{approvalRate}}，供应商记录{{supplierHistory}}，同类平均金额{{avgAmount}}
分析维度：金额风险、频率风险、供应商风险、合规风险
输出：{ riskLevel, riskScore(0-100), riskFactors: [{factor,score,detail}], recommendation, suggestion }`;

async function analyzeRisk(data: Record<string, unknown>): Promise<RiskAssessment> {
  let prompt = RISK_PROMPT;
  for (const [k, v] of Object.entries(data)) prompt = prompt.replace(`{{${k}}}`, String(v));
  const response = await openai.chat.completions.create({
    model: 'gpt-4o',
    messages: [{ role: 'system', content: '你是风控专家，只输出 JSON。' }, { role: 'user', content: prompt }],
    temperature: 0.1, response_format: { type: 'json_object' }
  });
  return JSON.parse(response.choices[0].message.content);
}
```

const WORKFLOW = {

    {

        aiType: 'classify', prompt: CLASSIFICATION_PROMPT,

        { condition: 'classification === "routine" && amount < 5000', targetNodeId: 'auto_approve' },
        { condition: 'classification === "high_risk" || amount >= 50000', targetNodeId: 'director_approve' },
        { condition: 'true', targetNodeId: 'manager_approve' }
      ]
    },
    { id: 'auto_approve', type: 'auto', label: '自动审批', config: { action: 'approve' }, next: [{ targetNodeId: 'ai_risk_check' }] },
    { id: 'ai_risk_check', type: 'ai', label: 'AI 风险检查', config: { aiType: 'analyze', prompt: RISK_PROMPT, inputMapping: { amount: 'formData.totalAmount' }, outputMapping: { riskLevel: 'riskLevel' } },
      next: [{ condition: 'riskLevel === "high" || riskLevel === "critical"', targetNodeId: 'director_approve' }, { condition: 'true', targetNodeId: 'end_approved' }] },
    { id: 'manager_approve', type: 'human', label: '部门经理审批', config: { approverRole: 'department_manager' },
      next: [{ condition: 'approved', targetNodeId: 'finance_approve' }, { condition: 'rejected', targetNodeId: 'end_rejected' }] },
    { id: 'finance_approve', type: 'human', label: '财务审批', config: { approverRole: 'finance_manager' },
      next: [{ condition: 'approved', targetNodeId: 'end_approved' }, { condition: 'rejected', targetNodeId: 'end_rejected' }] },
    { id: 'director_approve', type: 'human', label: '总经理审批', config: { approverRole: 'director', aiAssist: true },
      next: [{ condition: 'approved', targetNodeId: 'end_approved' }, { condition: 'rejected', targetNodeId: 'end_rejected' }] },
    { id: 'end_approved', type: 'end', label: '通过' },

  ]

## 常见误区

1. **AI 节点不做降级**：LLM API 超时时工作流会卡死，必须配置降级策略（跳过/重试/转人工）。
2. **AI 决策作为最终决策**：高风险场景必须保留人工确认，AI 仅辅助。
3. **未清洗的用户输入注入 Prompt**：可能触发 Prompt 攻击，输入必须转义过滤。

## 工程建议

1. **异步执行**：AI 节点设计为异步，不阻塞工作流引擎主线程。
2. **决策日志**：AI 节点的输入输出和置信度都需记录，便于审计追溯。
3. **A/B 测试 Prompt**：不同 Prompt 产生不同效果，应建立测试机制持续优化。

## 小结

- AI 节点通过 LLM 实现分类、分析、决策，是工作流引擎的新型自动节点
- 智能路由基于分类结果动态分发，减少人工审批工作量
- 风险评估和情感分析为审批人提供决策辅助，AI 不替代最终决策
- 生产环境 AI 节点必须有降级策略，高风险保留人工确认

## 参考答案

### 练习一

**思路**：请假分类考虑假期类型（年假更宽松）、天数（长假需高级别）、频率（频繁需关注）。

**答案**：
```typescript
const LEAVE_PROMPT = `将请假申请分类。
类别：auto_approve / manager_approve / hr_approve
规则：年假≤3天且近3月≤2次→auto_approve；年假>3天或病假>2天→manager_approve；近3月>4次→hr_approve；婚假/产假/丧假→hr_approve
信息：{{applicant}}，类型{{leaveType}}，天数{{days}}，近3月次数{{recentCount}}，事由{{reason}}
输出 JSON：{ category, confidence, reason }`;

const node: WorkflowNode = {
  id: 'ai_classify_leave', type: 'ai', label: 'AI 请假分类',
  config: {
    aiType: 'classify', prompt: LEAVE_PROMPT,
    inputMapping: { applicant: 'formData.employeeName', leaveType: 'formData.leaveType', days: 'formData.days', recentCount: 'statistics.recentLeaveCount', reason: 'formData.reason' },
    outputMapping: { category: 'classification', reason: 'classificationReason' },
    fallbackAction: 'manual', maxRetries: 2
  },
  next: [
    { condition: 'classification === "auto_approve"', targetNodeId: 'auto_approve' },
    { condition: 'classification === "hr_approve"', targetNodeId: 'hr_approve' },
    { condition: 'true', targetNodeId: 'manager_approve' }
  ]
};
```

**要点**：规则在 Prompt 中明确列出减少猜测，fallback 设为 manual 确保 AI 失败时转人工。

### 练习二

**思路**：检查超时原因后调用 AI 决定策略，try-catch 包裹 AI 调用确保异常有降级。

**答案**：
```typescript
async function handleEscalation(ticketId: string, context: Record<string, unknown>): Promise<{ action: string; message: string; notify: string[] }> {
  try {
    const decision = await determineEscalation({
      ticketId, currentApprover: context.currentApprover,
      waitHours: context.waitHours, urgency: context.urgency || 'medium',
      escalationReason: `超时 ${context.waitHours} 小时`
    });
    switch (decision.strategy) {
      case 'escalate_to_superior':
        return { action: 'reassign', message: `已转交上级 ${decision.targetApprover}`, notify: decision.notifyList };
      case 'parallel_approval':
        return { action: 'add_approver', message: `已增加并行审批人`, notify: decision.notifyList };
      case 'auto_approve':
        if (context.riskLevel === 'low') return { action: 'approve', message: '低风险超时自动通过', notify: [context.currentApprover as string] };
        return { action: 'reassign', message: '风险非低，已升级', notify: ['department_head'] };
      default:
        return { action: 'manual', message: 'AI 无法决定，请人工处理', notify: ['admin'] };
    }
  } catch (error) {
    return { action: 'manual', message: `升级异常: ${error.message}，请人工介入`, notify: ['admin', context.currentApprover as string] };
  }
}
```

**要点**：auto_approve 需额外校验风险等级，try-catch 确保异常有明确降级。
