# AI 生成页面：描述需求自动生成 UI

## 场景引入

李娜是运营人员，需要为促销活动快速搭建报名页面。她不懂前端开发，也不熟悉低代码平台的拖拽操作。但她会描述需求："顶部是活动 Banner，下面是活动介绍，然后是表单让用户填姓名、手机号、报名人数，底部有提交按钮。"

在集成 AI 能力的低代码平台中，她只需将描述输入 AI 助手，平台自动生成完整的页面组件树——Banner、富文本、表单组件都已配置完毕。李娜只需上传图片、修改文字即可发布。

这种"文本到 UI"的能力正在改变低代码平台的使用范式——从"拖拽搭建"进化为"描述生成"。

## 学习目标

- 理解文本到 UI 生成的技术架构与组件树映射原理
- 掌握不同类型页面的 Prompt 模板设计
- 学会实现 AI 生成组件树的代码管线
- 能够构建迭代式 UI 优化的交互机制

## 组件树数据结构

LLM 输出的核心结构是组件树（Component Tree）：

```typescript
interface ComponentNode {
  id: string;
  type: string;
  props: Record<string, unknown>;
  children?: ComponentNode[];
  layout?: { width?: string; padding?: string; display?: 'flex' | 'grid' | 'block'; flexDirection?: 'row' | 'column'; gap?: string };
  style?: Record<string, string>;
}

interface PageDefinition {
  title: string;
  root: ComponentNode;
  dataSource?: Array<{ id: string; type: 'api' | 'static'; config: Record<string, unknown> }>;
}
```

## 意图识别与 Prompt 路由

不同类型页面需要不同 Prompt，先识别类型再路由：

```typescript
type PageType = 'form' | 'list' | 'dashboard' | 'detail' | 'landing';

async function classifyPageType(input: string): Promise<PageType> {
  const response = await openai.chat.completions.create({
    model: 'gpt-4o',
    messages: [
      { role: 'system', content: '判断页面类型，只输出：form/list/dashboard/detail/landing。' },
      { role: 'user', content: input }
    ],
    temperature: 0, max_tokens: 20
  });
  return response.choices[0].message.content.trim() as PageType;
}
```

## 组件映射与布局计算

### 组件注册表

LLM 输出的组件类型需映射到平台实际实现：

```typescript
const REGISTRY: Record<string, ComponentConfig> = {
  Input: { package: '@lowcode/components', export: 'Input', propSchema: { label: { type: 'string', required: true }, placeholder: { type: 'string' }, required: { type: 'boolean' } } },
  DataTable: { package: '@lowcode/components', export: 'DataTable', propSchema: { columns: { type: 'array', required: true }, pagination: { type: 'object' } } },
  Chart: { package: '@lowcode/charts', export: 'Chart', propSchema: { type: { type: 'enum', values: ['line','bar','pie'], required: true }, title: { type: 'string' } } }

```

### 自动布局

```typescript
function autoLayout(node: ComponentNode): ComponentNode {
  const layouted = { ...node };
  if (node.type === 'FormContainer') {
    layouted.layout = { display: 'flex', flexDirection: 'column', gap: '16px', padding: '24px', maxWidth: '640px' };
  } else if (node.type === 'DashboardGrid') {
    layouted.layout = { display: 'grid', gridTemplateColumns: 'repeat(auto-fit, minmax(300px, 1fr))', gap: '16px', padding: '24px' };
  } else if (node.type === 'PageContainer') {
    layouted.layout = { display: 'flex', flexDirection: 'column', gap: '24px', padding: '24px' };
  }
  if (node.children) layouted.children = node.children.map(c => autoLayout(c));
  return layouted;
}
```

## 迭代式 UI 优化

用户对生成结果不满意时，通过自然语言描述修改：

```typescript
async function refinePage(current: PageDefinition, feedback: string): Promise<PageDefinition> {
  const prompt = `用户对当前页面有修改意见。
当前页面：${JSON.stringify(current, null, 2)}
反馈：${feedback}
规则：只修改用户提到的部分，保持其他不变。输出完整 PageDefinition JSON。`;

  const response = await openai.chat.completions.create({
    model: 'gpt-4o',
    messages: [{ role: 'system', content: '只输出 JSON。' }, { role: 'user', content: prompt }],
    temperature: 0.2, response_format: { type: 'json_object' }
  });
  return JSON.parse(response.choices[0].message.content) as PageDefinition;
}

class PageGenerationSession {
  private history: Array<{ role: string; content: string }> = [];
  private currentPage: PageDefinition | null = null;

  async processInput(input: string): Promise<PageDefinition> {
    this.history.push({ role: 'user', content: input });
    if (!this.currentPage) {
      const type = await classifyPageType(input);
      this.currentPage = await generateByType(type, input);
    } else {
      this.currentPage = await refinePage(this.currentPage, input);
    }
    return this.currentPage;
  }
}
```

## 常见误区

1. **生成后不做组件校验**：LLM 可能输出平台不支持的组件类型或无效 props，必须在映射阶段校验。
2. **忽略响应式布局**：AI 生成通常基于桌面端，需在布局计算阶段加入响应式断点。
3. **一次性生成复杂页面**：应拆分为多个区块分别生成再组合，避免丢失细节。

## 工程建议

1. **组件文档注入 System Prompt**：确保 LLM 只使用平台支持的组件。
2. **缓存高频页面模板**：CRUD 表单、数据列表等模板缓存后只需替换数据源。
3. **支持手动微调**：AI 生成的页面应可进入编辑器手动调整，形成"AI 生成 + 人工精调"工作流。

## 小结

- 文本到 UI 核心是将自然语言映射为组件树，经过意图识别、Prompt 路由、LLM 生成、组件映射、布局计算
- 不同页面类型需不同 Prompt 模板，模板中明确定义可用组件和输出格式
- 组件映射层确保生成结果可用，自动布局补充 LLM 未指定的布局信息
- 迭代优化通过对话式交互实现，维护生成上下文

### 练习二

**思路**：递归遍历组件树，检查类型是否注册、必填 props 是否存在、枚举值是否合法。

**答案**：
```typescript
function validateComponentTree(node: ComponentNode, registry: Record<string, ComponentConfig>): ValidationResult {
  const errors: ValidationError[] = [];
  function validate(n: ComponentNode, path: string) {
    const curPath = `${path}/${n.type}`;
    const config = registry[n.type];
    if (!config) { errors.push({ path: curPath, message: `未知组件: ${n.type}`, severity: 'error' }); return; }
    for (const [key, val] of Object.entries(n.props)) {
      const schema = config.propSchema[key];
      if (!schema) { errors.push({ path: curPath, message: `未知属性: ${key}`, severity: 'warning' }); continue; }
      if (schema.type === 'enum' && !schema.values.includes(val as string)) {
        errors.push({ path: curPath, message: `${key} 值无效: ${val}`, severity: 'error' });
      }
    }
    for (const [key, schema] of Object.entries(config.propSchema)) {
      if (schema.required && !(key in n.props)) errors.push({ path: curPath, message: `缺少必填: ${key}`, severity: 'error' });
    }
    n.children?.forEach((c, i) => validate(c, curPath));
  }
  validate(node, 'root');
  return { valid: errors.filter(e => e.severity === 'error').length === 0, errors };
}
```

**要点**：用 path 定位错误位置，区分 error/warning 级别。
