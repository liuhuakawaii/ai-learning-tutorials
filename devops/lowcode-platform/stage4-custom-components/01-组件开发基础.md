# 组件开发基础：规范、Props、事件与生命周期

> 前置知识：前端基础（HTML/CSS/JS），了解 React 或 Vue

## 平台组件不够用了

某企业低代码平台上线半年，内置的 30 多个基础组件已不够用——产品经理需要"进度条+标签+操作按钮"的复合组件，财务部门需要金额自动格式化的专用输入框。

平台团队面临选择：不断往核心包塞新组件，还是开放组件开发能力让业务团队自己扩展？

后者需要一套完善的组件规范，让第三方组件能安全、稳定地运行在平台中。

## 低代码组件 vs 传统前端组件

传统组件通过代码调用、props 传值。低代码组件需同时服务两个受众：**平台运行时**（渲染执行）和**配置者**（设计器中拖拽配置）。

因此除了 UI 逻辑，还需要**元数据描述**——告诉平台有哪些属性可配置、支持哪些事件、数据源怎么绑定。

```
传统组件：
  代码中使用 → <MyChart data={salesData} />

低代码组件：
  设计器中拖拽 → 配置面板设置属性 → 运行时渲染
```

## 组件清单文件

每个低代码组件需要一个 `manifest.json`：

```json
{
  "name": "progress-card",
  "version": "1.0.0",
  "displayName": "进度卡片",
  "description": "展示进度百分比和状态标签的复合组件",
  "icon": "进度",
  "category": "数据展示",
  "props": {
    "title": {
      "type": "string",
      "default": "进度",
      "label": "标题"
    },
    "value": {
      "type": "number",
      "default": 0,
      "min": 0,
      "max": 100,
      "label": "进度值"
    },
    "status": {
      "type": "select",
      "options": ["active", "success", "warning", "error"],
      "default": "active",
      "label": "状态"
    },
    "showLabel": {
      "type": "boolean",
      "default": true,
      "label": "显示百分比"
    }
  },
  "events": ["onClick", "onStatusChange"],
  "dataBinding": {
    "supported": true,
    "fields": ["value", "status", "title"]
  }
}
```

## Props 系统

### 类型定义

```typescript
interface PropDefinition {
  type: 'string' | 'number' | 'boolean' | 'select' | 'color' | 'json' | 'event';
  default?: any;
  label: string;
  description?: string;
  required?: boolean;
  // 类型特定属性
  min?: number;
  max?: number;
  options?: Array<{ label: string; value: any }>;
  placeholder?: string;
}
```

### Props 联动

一个 prop 的可选值依赖另一个 prop 的值：

```json
{
  "chartType": {
    "type": "select",
    "options": ["line", "bar", "pie"],
    "label": "图表类型"
  },
  "xAxis": {
    "type": "string",
    "label": "X 轴字段",
    "visible": "{{chartType !== 'pie'}}"
  },
  "seriesMode": {
    "type": "select",
    "options": ["single", "multi"],
    "label": "系列模式",
    "visible": "{{chartType === 'line' || chartType === 'bar'}}"
  }
}
```

当 `chartType` 为 `pie` 时，`xAxis` 字段在配置面板中隐藏。

## 事件模型

```typescript
interface EventDefinition {
  name: string;
  label: string;
  description: string;
  params?: Array<{
    name: string;
    type: string;
    description: string;
  }>;
}

// 组件内部触发事件
class ProgressCard extends Component {
  handleClick() {
    this.emit('onClick', {
      value: this.props.value,
      status: this.props.status,
    });
  }

  handleStatusChange(newStatus: string) {
    this.emit('onStatusChange', {
      oldStatus: this.props.status,
      newStatus,
    });
  }
}
```

## 生命周期

```
组件生命周期：

  初始化
    ↓
  onMount（组件挂载到 DOM）
    ↓
  onDataBind（数据源绑定完成）
    ↓
  onUpdate（props 或数据变化）
    ↓
  onUnmount（组件从 DOM 移除）
```

```typescript
class ProgressCard extends Component {
  onMount() {
    // 初始化：创建 DOM、绑定事件
    this.render();
  }

  onDataBind(data: any) {
    // 数据绑定完成：更新组件状态
    this.setState({ value: data.value, status: data.status });
  }

  onUpdate(prevProps: any) {
    // Props 变化：重新渲染
    if (prevProps.value !== this.props.value) {
      this.animateTo(this.props.value);
    }
  }

  onUnmount() {
    // 清理：取消定时器、解绑事件
    this.cleanup();
  }
}
```

    "type": "number",
    "default": 0,

    "visible": "{{chartType === 'pie'}}"

### 练习三

1. 拖拽组件 → `onMount()` 被调用，组件初始化并渲染
2. 配置数据源 → `onDataBind(data)` 被调用，组件用数据更新状态
3. 修改标题 → `onUpdate(prevProps)` 被调用，组件用新 props 重新渲染
4. 删除组件 → `onUnmount()` 被调用，组件清理资源
