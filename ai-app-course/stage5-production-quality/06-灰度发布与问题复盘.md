## 一、灰度发布流程

### 1.1 发布阶段

```
┌─────────────────────────────────────────────────────────────────┐
│                    灰度发布流程                                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  阶段 1：准备                                                    │
│  ├── 完成评估，指标达标                                          │
│  ├── 准备回滚方案                                                │
│  └── 通知相关人员                                                │
│                                                                 │
│  阶段 2：小流量（5%）                                            │
│  ├── 新版本接收 5% 流量                                          │
│  ├── 监控核心指标                                                │
│  ├── 观察 24 小时                                                │
│  └── 如果异常，立即回滚                                          │
│                                                                 │
│  阶段 3：扩大（20% → 50%）                                       │
│  ├── 指标正常，逐步扩大                                          │
│  ├── 每次扩大后观察                                              │
│  └── 收集用户反馈                                                │
│                                                                 │
│  阶段 4：全量（100%）                                            │
│  ├── 指标稳定，全量切换                                          │
│  ├── 保留旧版本 7 天                                             │
│  └── 确认无问题后清理                                            │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 二、问题复盘

### 2.1 复盘流程

```
┌─────────────────────────────────────────────────────────────────┐
│                    问题复盘流程                                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 发现问题                                                     │
│     ├── 监控告警                                                  │
│     ├── 用户反馈                                                  │
│     └── 人工发现                                                  │
│                                                                 │
│  2. 快速响应                                                     │
│     ├── 评估影响范围                                              │
│     ├── 决定是否回滚                                              │
│     └── 通知相关人员                                              │
│                                                                 │
│  3. 根因分析                                                     │
│     ├── 收集证据（日志、trace）                                   │
│     ├── 分析原因                                                  │
│     └── 确定根本原因                                              │
│                                                                 │
│  4. 制定改进                                                     │
│     ├── 短期：修复当前问题                                        │
│     ├── 中期：防止类似问题                                        │
│     └── 长期：改进流程                                            │
│                                                                 │
│  5. 跟踪落实                                                     │
│     ├── 创建改进任务                                              │
│     ├── 跟踪进度                                                  │
│     └── 验证效果                                                  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 复盘记录

```typescript
// lib/incident/types.ts
interface Incident {
  id: string
  title: string
  severity: 'low' | 'medium' | 'high' | 'critical'
  status: 'open' | 'investigating' | 'resolved' | 'closed'

  // 时间线
  discoveredAt: Date
  resolvedAt?: Date
  duration?: number

  // 影响
  impact: {
    usersAffected: number
    requestsAffected: number
    costImpact?: number
  }

  // 根因
  rootCause?: string
  contributingFactors: string[]

  // 改进
  shortTermFix?: string
  longTermImprovements: string[]
  actionItems: {
    description: string
    assignee: string
    dueDate: Date
    status: 'pending' | 'in_progress' | 'done'
  }[]

  // 复盘
  retrospective?: {
    whatHappened: string
    whatWentWell: string
    whatCouldImprove: string
    lessonsLearned: string[]
  }
}
```

---

## 小结

本课的核心要点：

1. **灰度发布**：小流量 → 扩大 → 全量，逐步验证
2. **发布检查清单**：质量、安全、性能、准备
3. **问题复盘**：发现 → 响应 → 分析 → 改进 → 跟踪
4. **持续改进**：监控 → 分析 → 改进 → 评估 → 发布
5. **经验教训**：每次问题都是学习机会
