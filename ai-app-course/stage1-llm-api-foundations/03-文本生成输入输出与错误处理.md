## 一、Messages：模型的输入格式

### 1.1 三种角色

```typescript
const response = await openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [
    // 1. system：系统指令，定义模型的角色和行为
    { role: 'system', content: '你是一个专业的技术文档翻译。' },

    // 2. user：用户输入
    { role: 'user', content: '把这句话翻译成英文：API 是软件之间的桥梁。' },

    // 3. assistant：模型之前的回答（用于多轮对话）
    // { role: 'assistant', content: '...' },
  ]
})
```

### 1.2 三种角色的职责

```
┌─────────────────────────────────────────────────────────────────┐
│                    Messages 的三种角色                            │
├─────────────┬───────────────────────────────────────────────────┤
│  角色        │  职责                                             │
├─────────────┼───────────────────────────────────────────────────┤
│  system     │  定义模型的身份、行为边界、输出格式                 │
│             │  用户通常看不到这个指令                             │
│             │  类比：给员工的岗位说明书                           │
├─────────────┼───────────────────────────────────────────────────┤
│  user       │  用户的实际输入                                    │
│             │  模型需要回答的问题或执行的任务                     │
│             │  类比：客户的需求                                   │
├─────────────┼───────────────────────────────────────────────────┤
│  assistant  │  模型之前的回答                                    │
│             │  用于维持多轮对话的上下文                           │
│             │  类比：之前的沟通记录                               │
└─────────────┴───────────────────────────────────────────────────┘
```

```
好的 System Prompt 结构：

  ┌─────────────────────────────────────────────┐
  │  1. 角色定义                                 │
  │     "你是一个产品经理助手"                    │
  │                                              │
  │  2. 能力范围                                 │
  │     "你可以分析需求、写 PRD、评估可行性"      │
  │                                              │
  │  3. 行为约束                                 │
  │     "不确定时说'我不确定'，不要编造"          │
  │                                              │
  │  4. 输出格式                                 │
  │     "回答使用 Markdown，重要结论加粗"         │
  │                                              │
  │  5. 示例（可选）                             │
  │     "用户问 X，你应该回答 Y"                  │
  └─────────────────────────────────────────────┘
```

const systemPrompt = `你是一个代码审查助手。

## 二、Temperature：控制输出的随机性

### 2.1 什么是 Temperature

```
Temperature 控制模型"选择下一个词"时的随机程度：

  temperature = 0（最确定）
    模型总是选择概率最高的词
    输出：每次几乎一样
    适合：代码生成、数据提取、格式转换

  temperature = 0.7（适中）
    模型在高概率词中随机选择
    输出：有变化但不离谱
    适合：日常对话、文案写作

  temperature = 1.0（最随机）
    模型更愿意选择低概率的词
    输出：每次可能很不一样
    适合：创意写作、头脑风暴
```

### 2.2 用代码体验

```typescript
// temperature 对比实验
async function temperatureDemo(prompt: string, temp: number) {
  const response = await openai.chat.completions.create({
    model: 'gpt-4o-mini',
    messages: [{ role: 'user', content: prompt }],
    temperature: temp,
    max_tokens: 100,
  })
  return response.choices[0].message.content
}

// 同一个 prompt，不同 temperature
const prompt = '写一个关于秋天的句子'

// temperature = 0：每次输出几乎一样
console.log('temp=0:', await temperatureDemo(prompt, 0))
console.log('temp=0:', await temperatureDemo(prompt, 0))
// 两次输出可能完全相同

// temperature = 1：每次输出不同
console.log('temp=1:', await temperatureDemo(prompt, 1))
console.log('temp=1:', await temperatureDemo(prompt, 1))
// 两次输出通常不同
```

### 2.3 Temperature 的选择指南

```
┌─────────────────────────────────────────────────────────────────┐
│                Temperature 选择指南                              │
├─────────────────────┬───────────────┬───────────────────────────┤
│  场景               │  推荐温度      │  原因                     │
├─────────────────────┼───────────────┼───────────────────────────┤
│  代码生成           │  0 - 0.2      │  代码必须准确              │
│  数据提取           │  0            │  不能有歧义               │
│  JSON 格式化        │  0            │  格式必须正确              │
│  分类任务           │  0            │  结果必须确定              │
│  翻译               │  0.3          │  准确但允许措辞变化        │
│  日常对话           │  0.7          │  自然、不重复              │
│  文案写作           │  0.7 - 0.9    │  需要创意但不失控          │
│  头脑风暴           │  0.9 - 1.0    │  需要多样性               │
└─────────────────────┴───────────────┴───────────────────────────┘
```

## 三、Max Tokens：控制输出长度

### 3.1 什么是 Token

```
Token 不等于字符，也不等于单词。

英文：
  "Hello world" → 2 个 token（Hello, world）
  "Don't" → 2 个 token（Don, 't）
  "transformer" → 1-2 个 token

中文：
  "你好世界" → 2-4 个 token（取决于分词方式）
  "人工智能" → 2 个 token

经验法则：
  英文：1 token ≈ 4 个字符 ≈ 0.75 个单词
  中文：1 token ≈ 1-2 个汉字
```

### 3.2 Max Tokens 的作用

```typescript
const response = await openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: '写一篇关于 AI 的文章' }],
  max_tokens: 100,  // 最多生成 100 个 token
})

// max_tokens = 100  → 大约 100-150 个英文单词，或 50-100 个中文字
// max_tokens = 500  → 大约 500-750 个英文单词
// max_tokens = 2000 → 大约 2000-3000 个英文单词
```

### 3.3 Max Tokens 与成本的关系

```
成本 = 输入 token 数 × 输入价格 + 输出 token 数 × 输出价格

GPT-4o-mini 的价格（示例）：
  输入：$0.15 / 1M tokens
  输出：$0.60 / 1M tokens

  输出价格是输入的 4 倍！

所以：
  - max_tokens 越大，成本越高
  - 输出比输入更贵
  - 合理设置 max_tokens 可以显著降低成本
```

### 3.4 何时设置 Max Tokens

```
┌─────────────────────────────────────────────────────────────────┐
│                 何时设置 max_tokens                               │
├─────────────────────┬───────────────────────────────────────────┤
│  场景               │  是否设置                                   │
├─────────────────────┼───────────────────────────────────────────┤
│  生成标题           │  ✅ 设置小值（50）                          │
│  生成摘要           │  ✅ 设置适中值（200）                       │
│  生成文章           │  ✅ 设置大值（2000）                        │
│  自由对话           │  ❌ 不设置，让模型自然结束                   │
│  结构化输出         │  ✅ 设置适中值，避免过长                     │
└─────────────────────┴───────────────────────────────────────────┘
```

## 四、输出处理

### 4.1 正常输出的处理

```typescript
const response = await openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: '你好' }]
})

const message = response.choices[0].message

// 检查 finish_reason
switch (message.finish_reason) {
  case 'stop':
    // 正常结束：模型主动停止生成
    console.log('正常回答:', message.content)
    break

  case 'length':
    // 被截断：达到了 max_tokens 限制
    console.warn('回答被截断，考虑增加 max_tokens')
    break

  case 'content_filter':
    // 内容过滤：触发了安全策略
    console.warn('回答被内容过滤器拦截')
    break

  default:
    console.log('其他原因:', message.finish_reason)
}
```

### 4.2 空输出的处理

```typescript
async function safeChat(userMessage: string) {
  const response = await openai.chat.completions.create({
    model: 'gpt-4o-mini',
    messages: [{ role: 'user', content: userMessage }]
  })

  const content = response.choices[0].message.content

  // 空输出检查
  if (!content || content.trim() === '') {
    return {
      success: false,
      error: '模型返回了空回答，请重试',
    }
  }

  return {
    success: true,
    answer: content,
    tokens: response.usage,
  }
}
```

### 4.3 输出长度的控制策略

```
如果你需要控制输出长度，有三种方式：

1. max_tokens（硬限制）
   直接限制最大 token 数
   风险：可能截断回答

2. 在 prompt 中指定（软限制）
   "用 100 字以内总结这篇文章"
   效果：模型通常会遵守，但不保证

3. 在 prompt 中指定格式
   "用 3 个要点回答，每个要点一句话"
   效果：比字数限制更可控

推荐：结合使用
   max_tokens 设一个安全上限
   prompt 中指定期望的长度和格式
```

## 五、错误处理详解

### 5.1 完整的错误处理

```typescript
import OpenAI from 'openai'

const openai = new OpenAI({
  apiKey: process.env.OPENAI_API_KEY,
  timeout: 30 * 1000,
  maxRetries: 2,
})

interface ChatResult {
  success: boolean
  answer?: string
  error?: string
  tokens?: { prompt: number; completion: number; total: number }
}

async function safeChat(userMessage: string): Promise<ChatResult> {
  try {
    const response = await openai.chat.completions.create({
      model: 'gpt-4o-mini',
      messages: [
        { role: 'system', content: '你是一个有帮助的助手。' },
        { role: 'user', content: userMessage }
      ],
      temperature: 0.7,
      max_tokens: 1000,
    })

    const content = response.choices[0].message.content

    if (!content) {
      return { success: false, error: '模型返回空回答' }
    }

    return {
      success: true,
      answer: content,
      tokens: {
        prompt: response.usage?.prompt_tokens ?? 0,
        completion: response.usage?.completion_tokens ?? 0,
        total: response.usage?.total_tokens ?? 0,
      },
    }

  } catch (error) {
    if (error instanceof OpenAI.AuthenticationError) {
      return { success: false, error: 'API Key 无效，请检查配置' }
    }

    if (error instanceof OpenAI.RateLimitError) {
      return { success: false, error: '请求太频繁，请稍后再试' }
    }

    if (error instanceof OpenAI.APIError) {
      return { success: false, error: `API 错误: ${error.message}` }
    }

    if (error instanceof OpenAI.APIConnectionError) {
      return { success: false, error: '无法连接到 API，请检查网络' }
    }

    return { success: false, error: `未知错误: ${error}` }
  }
}
```

### 5.2 错误类型速查表

```
┌─────────────────────────────────────────────────────────────────┐
│                    常见错误类型                                   │
├──────────────┬────────┬──────────────────────────────────────────┤
│  错误类型     │  状态码 │  原因与处理                              │
├──────────────┼────────┼──────────────────────────────────────────┤
│  认证错误     │  401   │  Key 无效 → 检查配置                     │
│  限流         │  429   │  请求太频繁 → 等待后重试                  │
│  服务器错误   │  500   │  服务端问题 → 重试                       │
│  超时         │  -     │  网络或模型太慢 → 增加 timeout           │
│  网络断开     │  -     │  网络问题 → 检查连接                     │
│  上下文过长   │  400   │  输入 token 超限 → 缩短输入              │
│  模型不存在   │  404   │  模型名错误 → 检查拼写                   │
│  配额用完     │  429   │  账户余额不足 → 充值                     │
└──────────────┴────────┴──────────────────────────────────────────┘
```

## 六、一个完整的文本生成示例

```typescript
// src/examples/text-generation.ts
import 'dotenv/config'
import OpenAI from 'openai'

const openai = new OpenAI()

interface GenerateOptions {
  systemPrompt?: string
  temperature?: number
  maxTokens?: number
}

async function generate(
  userMessage: string,
  options: GenerateOptions = {}
) {
  const {
    systemPrompt = '你是一个有帮助的助手。',
    temperature = 0.7,
    maxTokens = 1000,
  } = options

  const startTime = Date.now()

  const response = await openai.chat.completions.create({
    model: 'gpt-4o-mini',
    messages: [
      { role: 'system', content: systemPrompt },
      { role: 'user', content: userMessage },
    ],
    temperature,
    max_tokens: maxTokens,
  })

  const elapsed = Date.now() - startTime
  const content = response.choices[0].message.content ?? ''
  const usage = response.usage

  return {
    content,
    elapsed,
    tokens: {
      prompt: usage?.prompt_tokens ?? 0,
      completion: usage?.completion_tokens ?? 0,
      total: usage?.total_tokens ?? 0,
    },
    finishReason: response.choices[0].finish_reason,
  }
}

// 使用示例
async function main() {
  // 1. 代码生成（低温度）
  const code = await generate(
    '写一个 TypeScript 函数，计算数组的平均值',
    { temperature: 0, maxTokens: 200 }
  )
  console.log('代码生成:', code.content)
  console.log('耗时:', code.elapsed, 'ms')

  // 2. 文案写作（适中温度）
  const copy = await generate(
    '为一个 AI 编程助手写一段 50 字的广告语',
    { temperature: 0.8, maxTokens: 100 }
  )
  console.log('文案:', copy.content)

  // 3. 技术总结（指定格式）
  const summary = await generate(
    '用 3 个要点总结 React 的核心概念，每个要点一句话',
    {
      systemPrompt: '你是一个技术培训师，擅长简洁明了地解释概念。',
      temperature: 0.3,
      maxTokens: 300,
    }
  )
  console.log('总结:', summary.content)
}

main()
```

## 小结

本课的核心要点：

1. **Messages 三种角色**：system（指令）、user（输入）、assistant（历史回答）
2. **Temperature**：0 最确定，1 最随机；代码用 0，对话用 0.7，创意用 1
3. **Max Tokens**：控制输出长度和成本；输出比输入更贵
4. **finish_reason**：stop（正常）、length（截断）、content_filter（过滤）
5. **错误处理**：认证、限流、超时、网络——每种都需要不同的处理策略
