# 性能分析报告 — 课程毕业项目

## 项目目标

选择一个真实存在的 Web 项目（开源项目或自己参与的项目），使用 Chrome DevTools Performance、Memory、Lighthouse、Web Vitals 等工具完成一份完整的性能分析报告。项目覆盖性能分析课程中的核心知识：火焰图、内存快照、布局抖动、长任务、Web Vitals 指标、优化策略等。

## 项目选择

以下任选其一（或自选）：

- **React 官方 TodoMVC 示例**：https://todomvc.com/examples/react/
- **Next.js 官方示例**：create-next-app 默认模板
- **Vue 官方示例**：create-vue 默认模板
- **自己参与的项目**：需要提供可访问的 URL 或本地运行方式

## 核心功能

### 模块一：Performance 面板分析

- 录制页面加载和交互操作的性能 trace
- 分析火焰图，识别：
  - 长任务（> 50ms 的 Main thread task）
  - 频繁的 Layout / Paint 事件
  - JavaScript 执行热点函数
  - 事件处理函数耗时
- 生成时间线截图与标注

### 模块二：Memory 面板分析

- Heap Snapshot：拍摄堆快照，分析对象分布
- Allocation Timeline：追踪内存分配时间线
- 识别：
  - 内存占用最大的对象类型
  - 可能的内存泄漏（Detached DOM 节点、闭包持有）
  - 未被 GC 回收的对象
- 生成内存快照对比报告

### 模块三：Lighthouse 审计

- 运行 Lighthouse（Performance 类别）
- 记录并分析各项指标：
  - First Contentful Paint (FCP)
  - Largest Contentful Paint (LCP)
  - Total Blocking Time (TBT)
  - Cumulative Layout Shift (CLS)
  - Speed Index
- 分析 Lighthouse 给出的优化建议，逐条评估可行性

### 模块四：Web Vitals 实测

- 使用 `web-vitals` 库实测真实用户指标
- 记录 LCP、FID/INP、CLS 的实际值
- 与 Lighthouse 模拟值对比分析差异
- 多次测量取中位数

### 模块五：优化方案与验证

- 基于分析结果，提出至少 3 个具体优化方案
- 实施优化（如果是自己的项目）或撰写优化方案文档
- 优化后重新测量，对比前后数据
- 优化方案需说明：
  - 问题根因
  - 优化手段
  - 预期收益
  - 实际测量结果
  - 副作用或代价

## 验收标准

- [ ] Performance 报告包含火焰图截图，标注了至少 3 个性能问题
- [ ] Memory 报告包含堆快照截图，分析了对象分布和潜在泄漏
- [ ] Lighthouse 报告包含各项指标得分和优化建议分析
- [ ] Web Vitals 报告包含 LCP、FID/INP、CLS 的实测值
- [ ] 优化方案至少 3 个，每个有根因分析和预期收益
- [ ] 优化前后有数据对比（截图或表格）
- [ ] 报告格式清晰，截图完整，标注明确
- [ ] 项目可通过 `node scripts/check.js` 验证报告完整性
