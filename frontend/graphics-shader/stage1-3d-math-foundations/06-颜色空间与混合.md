# 第六课：颜色空间与混合

## 场景引入

你是否遇到过这样的问题：在 Photoshop 里精心调好的颜色，放到网页上就变得"不对劲"？或者在 shader 里做光照计算时，明明光源强度线性增加，画面却看起来非线性变亮？这些"颜色偏差"的根源在于颜色空间的选择。理解 RGB、HSV、线性空间、sRGB 空间的区别，是正确处理颜色的基础。

1. 理解 RGB 和 HSV/HSL 颜色模型的原理与适用场景
2. 掌握线性空间与 sRGB 空间的区别，理解 gamma 校正的必要性
3. 理解 Alpha 混合公式和预乘 Alpha 的原理

5. 能够在 TypeScript 和 GLSL 中实现颜色空间转换

## 一、RGB 颜色模型

RGB 是最常用的颜色模型，它用红（Red）、绿（Green）、蓝（Blue）三个通道的强度来表示颜色。

### 原理

```
            红 (R)
           / \
          /   \
         /     \
        / 白色  \
       / (1,1,1) \
      /           \
   品红 ---------- 黄色
(1,0,1)     |     (1,1,0)
      \     |     /
       \    |    /
        \   |   /
         \  |  /
    蓝 (0,0,1) --- 绿 (0,1,0)
         \  |  /
          \ | /
           \|/
           黑 (0,0,0)
```

- 每个通道取值范围：`[0, 1]` 或 `[0, 255]`
- 三个通道线性叠加，可以表示 1677 万种颜色
- 适合显示器、GPU 等硬件直接使用

### TypeScript 中的 RGB 操作

```typescript
/** RGB 颜色，每个分量范围 [0, 1] */
interface RGB {
    r: number;
    g: number;
    b: number;
}

/** 将 RGB 从 [0,255] 转换为 [0,1] */
function rgbFromBytes(r: number, g: number, b: number): RGB {
    return { r: r / 255, g: g / 255, b: b / 255 };
}

/** 颜色乘以标量（用于光照计算） */
function rgbScale(color: RGB, s: number): RGB {
    return { r: color.r * s, g: color.g * s, b: color.b * s };
}

/** 两个颜色逐通道相乘（用于材质贴图采样） */
function rgbMul(a: RGB, b: RGB): RGB {
    return { r: a.r * b.r, g: a.g * b.g, b: a.b * b.b };
}

/** 两个颜色相加（用于光照叠加） */
function rgbAdd(a: RGB, b: RGB): RGB {
    return { r: a.r + b.r, g: a.g + b.g, b: a.b + b.b };
}

/** 将 [0,1] 颜色钳制到有效范围 */
function rgbClamp(color: RGB): RGB {
    return {
        r: Math.min(1, Math.max(0, color.r)),
        g: Math.min(1, Math.max(0, color.g)),
        b: Math.min(1, Math.max(0, color.b)),
    };
}
```

RGB 模型直观且硬件友好，但它不符合人类对颜色的直觉认知——我们很难通过调整 R、G、B 三个数值来"调出一个更暖的红色"。

## 二、HSV/HSL 颜色模型

HSV（色相-饱和度-明度）和 HSL（色相-饱和度-亮度）是面向人类直觉的颜色模型。

### HSV 的三个分量

```
            亮度 (V)
            ^
            |   纯色 (H=0, S=1, V=1)
            |   *
            |  /|\
            | / | \
            |/  |  \
            +---+---+------> 饱和度 (S)
           /    |
          /     |
    色相 (H)    |
    0°=红       |
    120°=绿     |
    240°=蓝     |
```

- **H (Hue，色相)**：颜色的种类，用角度表示 `[0°, 360°]`，0° 是红色，120° 是绿色，240° 是蓝色
- **S (Saturation，饱和度)**：颜色的纯度，`[0, 1]`，0 是灰色，1 是纯色
- **V (Value，明度)**：颜色的亮度，`[0, 1]`，0 是黑色，1 是最亮

### RGB 转 HSV 算法

```typescript
/** RGB 转 HSV */
function rgbToHsv(rgb: RGB): { h: number; s: number; v: number } {
    const max = Math.max(rgb.r, rgb.g, rgb.b);
    const min = Math.min(rgb.r, rgb.g, rgb.b);
    const delta = max - min;

    // 色相计算
    let h = 0;
    if (delta > 0) {
        if (max === rgb.r) {
            h = 60 * (((rgb.g - rgb.b) / delta) % 6);
        } else if (max === rgb.g) {
            h = 60 * ((rgb.b - rgb.r) / delta + 2);
        } else {
            h = 60 * ((rgb.r - rgb.g) / delta + 4);
        }
    }
    if (h < 0) h += 360;

    // 饱和度计算
    const s = max === 0 ? 0 : delta / max;

    // 明度
    const v = max;

    return { h, s, v };
}

/** HSV 转 RGB */
function hsvToRgb(h: number, s: number, v: number): RGB {
    const c = v * s;
    const x = c * (1 - Math.abs((h / 60) % 2 - 1));
    const m = v - c;

    let r = 0, g = 0, b = 0;
    if (h < 60)       { r = c; g = x; }
    else if (h < 120) { r = x; g = c; }
    else if (h < 180) { g = c; b = x; }
    else if (h < 240) { g = x; b = c; }
    else if (h < 300) { r = x; b = c; }
    else              { r = c; b = x; }

    return { r: r + m, g: g + m, b: b + m };
}
```

HSV 模型在 UI 拾色器中广泛使用：用户先选色相（色轮），再调饱和度和明度，比直接调 RGB 直观得多。

## 三、线性空间与 sRGB 空间

这是最容易被忽视但最重要的颜色知识之一。

### 问题：为什么需要 gamma 校正？

显示器的亮度响应不是线性的。如果输入值为 0.5，显示器输出的亮度并不是"一半亮度"，而是大约 0.218（因为 `0.5^2.2 ≈ 0.218`）。

```
亮度
 ^
 |        实际显示器输出（幂函数曲线）
 |       /
 |      /
 |     /
 |    /
 |   /
 |  /
 | /
 |/____________> 输入值
```

这个非线性关系用数学表示为：`V_out = V_in ^ gamma`，其中 gamma 通常为 2.2。

### sRGB 与线性空间的区别

- **sRGB 空间**：人眼看到的颜色，显示器直接显示的值。大多数图片文件（PNG、JPEG）存储在 sRGB 空间
- **线性空间**：光线的真实物理行为。光照计算必须在线性空间中进行，否则叠加结果不正确

```
sRGB 图片 ──(sRGB → Linear 解码)──> 线性空间 ──> 光照计算 ──(Linear → sRGB 编码)──> 屏幕显示
```

**关键规则**：
1. 采样贴图时，从 sRGB 解码到线性空间
2. 光照计算在线性空间中进行
3. 最终输出时，从线性空间编码回 sRGB 空间

### GLSL 中的 Gamma 校正

```glsl
#version 300 es
precision highp float;

in vec2 v_texCoord;
uniform sampler2D u_texture;
out vec4 fragColor;

// sRGB → 线性空间（解码）
vec3 srgbToLinear(vec3 srgb) {
    return pow(srgb, vec3(2.2));
}

// 线性空间 → sRGB（编码）
vec3 linearToSrgb(vec3 linear) {
    return pow(linear, vec3(1.0 / 2.2));
}

void main() {
    // 采样纹理（sRGB 空间）
    vec4 texColor = texture(u_texture, v_texCoord);

    // 解码到线性空间
    vec3 linearColor = srgbToLinear(texColor.rgb);

    // 在线性空间中做光照计算（示例：乘以光照强度）
    float lightIntensity = 0.8;
    vec3 litColor = linearColor * lightIntensity;

    // 编码回 sRGB 空间后输出
    fragColor = vec4(linearToSrgb(litColor), texColor.a);
}
```

**近似优化**：`pow(x, 2.2)` 可以用 `x * x` 近似（gamma = 2.0），在移动端性能更好但精度略低。

## 四、Alpha 混合公式

Alpha 通道表示像素的不透明度：0 完全透明，1 完全不透明。

### 标准 Alpha 混合

```
C_result = C_src * A_src + C_dst * (1 - A_src)
```

- `C_src`：源颜色（前景）
- `A_src`：源 Alpha（前景不透明度）
- `C_dst`：目标颜色（背景）
- `C_result`：混合后的颜色

### GLSL 中的 Alpha 混合设置

```typescript
// WebGL 中启用 Alpha 混合
gl.enable(gl.BLEND);
gl.blendFunc(gl.SRC_ALPHA, gl.ONE_MINUS_SRC_ALPHA);
```

### 预乘 Alpha (Premultiplied Alpha)

标准 Alpha 混合在纹理滤波时会产生"黑边"问题。预乘 Alpha 是解决方案：

```
存储时：C_premultiplied = C_original * A
混合时：C_result = C_src + C_dst * (1 - A_src)
```

```typescript
// 预乘 Alpha 的混合设置
gl.blendFunc(gl.ONE, gl.ONE_MINUS_SRC_ALPHA);
```

**优势**：
1. 避免纹理过滤时的黑边伪影
2. 混合公式更简单（少一次乘法）
3. 支持 additive 混合和 alpha 混合统一处理

## 五、混合模式

混合模式决定了两个图层如何叠加。不同的混合模式产生不同的视觉效果。

### Add（加法混合）

```
C_result = C_src + C_dst
```

效果：颜色变亮，常用于火焰、光效等发光效果。

### Multiply（正片叠底）

```
C_result = C_src * C_dst
```

效果：颜色变暗，常用于阴影、暗角效果。

### Screen（滤色）

```
C_result = 1 - (1 - C_src) * (1 - C_dst)
```

效果：颜色变亮但不会过曝，常用于光晕、高光效果。

### GLSL 实现

```glsl
#version 300 es
precision highp float;

in vec2 v_texCoord;
uniform sampler2D u_srcTexture;  // 前景
uniform sampler2D u_dstTexture;  // 背景
uniform int u_blendMode;         // 0=Add, 1=Multiply, 2=Screen
out vec4 fragColor;

vec3 blendAdd(vec3 src, vec3 dst) {
    return min(src + dst, 1.0);
}

vec3 blendMultiply(vec3 src, vec3 dst) {
    return src * dst;
}

vec3 blendScreen(vec3 src, vec3 dst) {
    return 1.0 - (1.0 - src) * (1.0 - dst);
}

void main() {
    vec4 src = texture(u_srcTexture, v_texCoord);
    vec4 dst = texture(u_dstTexture, v_texCoord);

    vec3 result;
    if (u_blendMode == 0) {
        result = blendAdd(src.rgb, dst.rgb);
    } else if (u_blendMode == 1) {
        result = blendMultiply(src.rgb, dst.rgb);
    } else {
        result = blendScreen(src.rgb, dst.rgb);
    }

    // Alpha 通道取较大值
    float alpha = max(src.a, dst.a);
    fragColor = vec4(result, alpha);
}
```

## 常见误区

**1. 在 sRGB 空间中做光照计算**

这是最常见的错误。直接对 sRGB 颜色做加法和乘法，会导致光照结果偏暗或颜色不正确。正确做法是先解码到线性空间，计算完成后再编码回 sRGB。

**2. 忘记 Alpha 混合需要关闭深度写入**

半透明物体渲染时，如果深度写入开启，后绘制的半透明像素可能被深度测试剔除。正确做法是：先画不透明物体（开启深度写入），再按从远到近顺序画半透明物体（关闭深度写入）。

**3. 混淆预乘 Alpha 和非预乘 Alpha 的纹理**

如果纹理是预乘 Alpha 存储的，但混合模式设置为 `SRC_ALPHA, ONE_MINUS_SRC_ALPHA`，颜色会偏暗。需要确认纹理的存储方式并使用对应的混合设置。

**4. HSV 转 RGB 时忘记处理色相边界**

色相 H=360° 和 H=0° 表示同一种颜色（红色），在实现转换函数时要注意取模处理，否则会出现色相跳变。

## 工程建议

**1. 统一使用线性空间工作流**

在项目初期就建立线性空间工作流：所有贴图标记为 sRGB 格式让 GPU 自动解码，光照计算在线性空间进行，最终输出自动编码回 sRGB。WebGL2 中可以用 `gl.SRGB8_ALPHA8` 内部格式。

**2. 使用 GPU 内置的 sRGB 转换**

现代 GPU 支持硬件级 sRGB 转换，比在 shader 中手动 `pow(x, 2.2)` 更高效。在创建纹理时指定 sRGB 格式即可。

**3. 半透明物体排序**

Alpha 混合的结果与绘制顺序有关。对于半透明物体，需要按深度从远到近排序后再绘制，否则会出现穿透效果。

**4. 选择合适的颜色拾取方式**

UI 拾色器使用 HSV 模型，光照计算使用 RGB 线性空间，CSS 使用 HEX 或 RGB。在代码中保持统一的颜色表示，转换逻辑封装为工具函数。

## 小结

本课系统讲解了颜色的数学基础。RGB 是硬件友好的颜色模型，HSV 是人类友好的颜色模型，两者需要互相转换。线性空间与 sRGB 空间的区别是正确做光照计算的前提——所有光照计算必须在线性空间中进行。Alpha 混合和混合模式是实现半透明、发光等视觉效果的基础工具。

## 参考答案

### 练习一

**思路**：HSV 转 RGB 的关键是根据色相所在的 60° 区间确定哪个通道是最大值、中间值和最小值。

**答案**：

```typescript
function rgbToHsv(rgb: RGB): { h: number; s: number; v: number } {
    const max = Math.max(rgb.r, rgb.g, rgb.b);
    const min = Math.min(rgb.r, rgb.g, rgb.b);
    const delta = max - min;

    let h = 0;
    if (delta > 0) {
        if (max === rgb.r) h = 60 * (((rgb.g - rgb.b) / delta) % 6);
        else if (max === rgb.g) h = 60 * ((rgb.b - rgb.r) / delta + 2);
        else h = 60 * ((rgb.r - rgb.g) / delta + 4);
    }
    if (h < 0) h += 360;

    return { h, s: max === 0 ? 0 : delta / max, v: max };
}

function hsvToRgb(h: number, s: number, v: number): RGB {
    const c = v * s;
    const x = c * (1 - Math.abs((h / 60) % 2 - 1));
    const m = v - c;
    let r = 0, g = 0, b = 0;

    if (h < 60)       { r = c; g = x; }
    else if (h < 120) { r = x; g = c; }
    else if (h < 180) { g = c; b = x; }
    else if (h < 240) { g = x; b = c; }
    else if (h < 300) { r = x; b = c; }
    else              { r = c; b = x; }

    return { r: r + m, g: g + m, b: b + m };
}

// 测试
const original: RGB = { r: 0.6, g: 0.3, b: 0.8 };
const hsv = rgbToHsv(original);
const recovered = hsvToRgb(hsv.h, hsv.s, hsv.v);
console.log('误差:', Math.abs(recovered.r - original.r)); // 应接近 0
```

**要点**：
- 色相计算中 `% 6` 确保结果在 0-360 范围内
- 当 `delta = 0` 时（灰色），色相为 0 但饱和度也为 0，不影响最终颜色

### 练习二

**思路**：在 shader 中用 `gl_FragCoord.x` 判断像素在左半边还是右半边，分别应用不同的 gamma 处理。

**答案**：

```glsl
#version 300 es
precision highp float;

in vec2 v_texCoord;
uniform sampler2D u_texture;
uniform vec2 u_resolution;
out vec4 fragColor;

void main() {
    vec4 texColor = texture(u_texture, v_texCoord);
    float midX = u_resolution.x * 0.5;

    if (gl_FragCoord.x < midX) {
        // 左半边：直接输出 sRGB（未校正，看起来偏暗）
        fragColor = texColor;
    } else {
        // 右半边：正确 gamma 校正
        vec3 linear = pow(texColor.rgb, vec3(2.2));
        // 假设在线性空间做了相同的光照操作
        vec3 srgb = pow(linear, vec3(1.0 / 2.2));
        fragColor = vec4(srgb, texColor.a);
    }
}
```

**要点**：
- 未校正的画面会明显偏暗，因为 sRGB 值在线性空间中被当作线性值使用
- 这也是为什么很多新手觉得"光照太暗"的原因

### 练习三

**思路**：用 uniform 变量控制混合模式，在 shader 中根据模式值选择不同的计算公式。

**答案**：见上方"五、混合模式"中的完整 GLSL 实现。

**要点**：
