# 发布与分发

## 场景引入

你花了三个月开发了一款 MR 家具摆放应用，本地测试完美运行。然后你打开 Meta 开发者后台，发现：应用商店审核被拒了三次——第一次是因为性能不达标，第二次是因为权限说明不清晰，第三次是因为没有隐私政策。

发布与分发是空间计算开发的"最后一公里"，也是最容易被忽视的环节。不同于移动应用的成熟生态，空间计算平台的审核标准、分发渠道、用户获取方式都有独特规则。

本课将系统讲解主流 XR 平台的发布流程，以及如何通过 Web 分发降低用户获取门槛。

## 学习目标

1. 了解 Meta Quest Store、App Lab、SideQuest 的审核差异
2. 掌握 WebXR 应用的 Web 分发方案
3. 学会准备应用商店所需的元数据和素材
4. 理解空间计算应用的审核要点与常见拒绝原因
5. 能够制定完整的应用发布与分发策略

## 一、分发渠道概览

### 1.1 渠道矩阵

| 渠道 | 审核门槛 | 用户规模 | 分成比例 | 适用阶段 |
|------|---------|---------|---------|---------|
| Meta Quest Store | 高（邀请制） | 最大 | 30% | 成熟产品 |
| Meta App Lab | 中 | 大 | 0% | 早期验证 |
| SideQuest | 无 | 中 | 0% | 开发测试 |
| Apple Vision Pro App Store | 高 | 中 | 30% | 成熟产品 |
| Steam | 中 | 中 | 30% | PC VR |
| Web 分发 | 无 | 潜在最大 | 0% | 全阶段 |
| Pico Store | 中 | 小（国内） | 30% | 国内市场 |

### 1.2 发布路径选择

```
开发完成 → SideQuest 测试 → App Lab 验证 → Quest Store 正式上线
                ↓
            Web 分发同步上线（零门槛获取）
                ↓
            根据数据决定是否上 Vision Pro / Steam
```

### 2.3 性能要求

Quest Store 和 App Lab 有明确的性能标准：

```csharp
// 性能自检工具
public class QuestPerformanceValidator : MonoBehaviour
{
    private float[] frameTimes = new float[300]; // 5 秒数据
    private int frameIndex = 0;
    private float lastFrameTime;

    void Update()
    {
        float deltaTime = Time.unscaledDeltaTime;
        frameTimes[frameIndex % frameTimes.Length] = deltaTime;
        frameIndex++;
    }

    public PerformanceReport Validate()
    {
        var report = new PerformanceReport();

        // 计算统计数据
        float avgFrameTime = frameTimes.Average();
        float maxFrameTime = frameTimes.Max();
        float p95FrameTime = GetPercentile(frameTimes, 0.95f);

        // Quest 2 目标：72fps（13.9ms），Quest 3 目标：90fps（11.1ms）
        float targetFrameTime = 1f / 72f;

        report.averageFPS = 1f / avgFrameTime;
        report.p95FrameTime = p95FrameTime;
        report.droppedFrames = frameTimes.Count(t => t > targetFrameTime * 1.5f);
        report.passed = report.droppedFrames < frameTimes.Length * 0.05f; // <5% 掉帧

        // 内存检查
        long usedMemory = UnityEngine.Profiling.Profiler.GetTotalAllocatedMemoryLong();
        long maxMemory = 6L * 1024 * 1024 * 1024; // Quest 2: 6GB
        report.memoryUsageMB = usedMemory / (1024 * 1024);
        report.memoryPassed = usedMemory < maxMemory * 0.7f; // <70% 内存使用

        return report;
    }

    private float GetPercentile(float[] data, float percentile)
    {
        var sorted = data.OrderBy(x => x).ToArray();
        int index = (int)(sorted.Length * percentile);
        return sorted[Mathf.Clamp(index, 0, sorted.Length - 1)];
    }

    [System.Serializable]
    public struct PerformanceReport
    {
        public float averageFPS;
        public float p95FrameTime;
        public int droppedFrames;
        public long memoryUsageMB;
        public bool passed;
        public bool memoryPassed;
    }
}
```

## 四、WebXR Web 分发

Web 分发是零门槛获取用户的方式，适合早期验证和引流。

### 4.1 WebXR 应用部署

```javascript
// WebXR 应用入口
class SpatialWebApp {
  constructor(canvas) {
    this.canvas = canvas;
    this.gl = canvas.getContext('webgl2', {
      xrCompatible: true,
      antialias: true,
      alpha: false
    });
  }

  async init() {
    // 检查 WebXR 支持
    if (!navigator.xr) {
      this.showFallback('您的浏览器不支持 WebXR');
      return false;
    }

    // 检查 AR 支持
    const isSupported = await navigator.xr.isSessionSupported('immersive-ar');
    if (!isSupported) {
      this.showFallback('您的设备不支持 AR 功能');
      return false;
    }

    // 初始化渲染器
    this.renderer = new THREE.WebGLRenderer({
      canvas: this.canvas,
      context: this.gl
    });
    this.renderer.xr.enabled = true;

    // 设置 AR 会话按钮
    this.setupARButton();

    return true;
  }

  setupARButton() {
    const arButton = document.createElement('button');
    arButton.textContent = '进入 AR';
    arButton.className = 'ar-button';
    arButton.addEventListener('click', async () => {
      const session = await navigator.xr.requestSession('immersive-ar', {
        requiredFeatures: ['hit-test', 'local-floor'],
        optionalFeatures: ['hand-tracking', 'anchors', 'plane-detection']
      });

      this.renderer.xr.setSession(session);
      this.onSessionStarted(session);
    });

    document.body.appendChild(arButton);
  }

  onSessionStarted(session) {
    session.addEventListener('end', () => {
      this.onSessionEnded();
    });

    // 开始渲染循环
    this.renderer.setAnimationLoop((time, frame) => {
      this.render(time, frame);
    });
  }

  showFallback(message) {
    const fallback = document.createElement('div');
    fallback.className = 'fallback-message';
    fallback.innerHTML = `
      <h2>无法启动 AR 体验</h2>
      <p>${message}</p>
      <p>建议使用：</p>
      <ul>
        <li>iOS Safari 15+ (iPhone/iPad)</li>
        <li>Android Chrome 90+</li>
        <li>Meta Quest Browser</li>
      </ul>
    `;
    document.body.appendChild(fallback);
  }
}
```

## 五、审核要点与常见拒绝原因

### 5.1 审核要点

```markdown
## 审核通过清单

### 性能（权重：高）
- 帧率稳定（Quest: 72fps+，Vision Pro: 90fps+）
- 启动时间 < 15 秒
- 无明显卡顿和掉帧
- 内存使用合理

### 用户体验（权重：高）
- 新手引导清晰
- 交互符合平台规范
- 无眩晕诱导的移动方式
- 退出流程正常

### 安全与隐私（权重：高）
- 隐私政策完整且可访问
- 权限请求有明确说明
- 数据收集符合 GDPR/CCPA
- 无恶意行为

### 内容（权重：中）
- 无版权侵权内容
- 年龄分级准确
- 无误导性描述
- 截图与实际体验一致
```

### 5.2 常见拒绝原因与解决方案

| 拒绝原因 | 解决方案 |
|---------|---------|
| 帧率不达标 | 使用性能分析工具定位瓶颈，降低渲染复杂度 |
| 隐私政策缺失 | 创建完整的隐私政策页面，链接到应用描述中 |
| 权限说明不清晰 | 在权限请求弹窗前添加说明对话框 |
| 应用崩溃 | 在多设备上测试，处理所有边界情况 |
| 新手引导缺失 | 添加首次使用引导流程 |
| 截图与实际不符 | 使用真实运行截图，不要使用渲染效果图 |
| 移动方式导致眩晕 | 提供瞬移选项，避免强制平滑移动 |

## 常见误区

1. **"开发完再考虑发布"**：发布准备（隐私政策、截图、描述）应该在开发中期就开始准备
2. **"App Lab 不需要优化"**：App Lab 的数据直接影响能否上 Quest Store，必须认真对待
3. **"Web 版可以偷懒"**：WebXR 应用的体验直接影响品牌形象，不能因为是免费的就降低质量
4. **"一次发布就够了"**：空间计算平台更新频繁，需要持续维护和适配
5. **"审核被拒是平台问题"**：90% 的拒绝原因可以在提交前自检发现

## 工程建议

1. **建立发布检查清单**：每次提交前逐项检查，避免低级错误
2. **自动化构建和签名**：使用 CI/CD 流水线自动完成 APK 构建、签名、上传
3. **灰度发布**：先向 10% 用户推送新版本，观察数据再全量发布
4. **监控崩溃率**：崩溃率 > 1% 必须立即修复
5. **保留回滚能力**：每个版本都要能快速回滚到上一个稳定版本

## 小结

本课系统讲解了空间计算应用的发布与分发全流程：Meta App Lab 作为主要验证渠道、SideQuest 作为社区分发补充、WebXR Web 分发作为零门槛入口。重点强调了审核要点和常见拒绝原因，帮助你避免踩坑。

关键要点回顾：
- 分发路径：SideQuest 测试 → App Lab 验证 → Quest Store 正式上线
- 性能是审核的核心指标，必须在提交前自检
- WebXR 分发零门槛，适合早期验证和引流
- 隐私政策和权限说明是被拒最常见的原因

## 参考答案

### 练习一

**思路**：以 Meta 的 VRC（Virtual Reality Checklist）为标准逐项检查

**答案**：

以 Unity XR 示例项目为例，常见问题：

1. **性能问题**：
   - 未设置固定注视点渲染（Foveated Rendering）
   - 场景三角形数量超过 500K
   - 使用了实时光照而非烘焙光照
   - 未设置 LOD 组

2. **用户体验问题**：
   - 缺少新手引导流程
   - 退出按钮不可见或不直观
   - 没有提供舒适度选项（如瞬移 vs 平滑移动）
   - 加载画面缺失或过于简陋

3. **安全与隐私问题**：
   - AndroidManifest.xml 中声明了不必要的权限
   - 没有隐私政策链接
   - 相机权限使用但未说明用途

4. **技术问题**：
   - 应用在暂停/恢复后状态异常
   - 控制器/手部追踪切换不平滑
   - 边界系统（Guardian）处理不正确

**要点**：
- 使用 Meta 提供的 Performance Analyzer 工具自动检测性能问题
- 在 Quest 1/2/3 上分别测试，确保兼容性
- 邀请 5-10 个非开发者用户进行体验测试

### 练习三

**思路**：K-12 教育市场有独特的采购流程和决策链

**答案**：

**分发渠道选择**：
- 主渠道：Meta App Lab → Quest Store（学校采购 Quest 设备成本最低）
- 辅渠道：Web 版本（学校电脑浏览器直接访问，无需安装）
- 不优先：Vision Pro（价格过高，学校无采购能力）

**定价方案**：
- 学校许可证：$500/年/学校（不限学生数）
- 教师个人版：$9.99/月
- 学生家庭版：免费（通过学校账号激活）
- 试用期：30 天全功能免费

**推广计划**：
1. 与 3-5 所试点学校合作，免费使用 1 个学期
2. 收集教学效果数据（成绩提升、学生参与度）
3. 在教育科技展会（如 ISTE）展示案例
4. 通过教育 KOL 和教师社群推广
5. 提供教师培训和课程计划模板

**时间节点**：
- 第 1 个月：试点学校合作签约
- 第 2-3 个月：试点使用，收集数据
- 第 4 个月：App Lab 发布，开放申请
- 第 5-6 个月：根据反馈迭代
- 第 7 个月（开学季）：正式发布，大规模推广

**要点**：
- 教育市场的决策周期长（通常一个学期），需要耐心
- 教师是关键影响者，要提供易用的教学工具
- 学生数据隐私（FERPA 合规）是学校采购的硬性要求
