# 空间计算与 AI

## 场景引入

你走进一间客厅，戴上 MR 头显，眼前的虚拟助手立刻说："检测到您前方有一张沙发和一个茶几，茶几上有一个杯子。" 这不是预设的 3D 模型——设备从未见过这个房间。它靠的是**空间计算**与 **AI 感知**的结合：摄像头捕获真实环境，AI 模型实时理解场景语义，系统在理解的基础上叠加虚拟内容。

这就是空间计算的核心问题：**如何让设备理解真实世界？** 传统 XR 应用依赖预扫描的空间地图，而 AI 驱动的空间计算能让设备"看懂"环境——不只是几何形状，还有物体类别、功能属性和空间关系。

本课将从场景语义分割、物体识别、空间锚点三个维度，讲解如何让 XR 设备具备真正的环境理解能力。

## 学习目标

1. 理解空间计算中 AI 感知的核心流程：感知→理解→融合
2. 掌握语义分割在 XR 场景中的应用方法
3. 学会使用物体识别 API 实现环境中的物体检测
4. 理解空间锚点（Spatial Anchor）的原理与 AI 增强方案
5. 能够构建一个 AI 驱动的场景理解原型

## 一、空间感知的三层架构

空间计算的 AI 感知可以分为三层：

```
┌─────────────────────────────────┐
│  语义层：物体是什么？功能是什么？  │  ← AI 语义理解
├─────────────────────────────────┤
│  几何层：物体在哪里？形状如何？    │  ← SLAM / 深度估计
├─────────────────────────────────┤
│  传感层：摄像头、IMU、LiDAR 数据  │  ← 原始传感器
└─────────────────────────────────┘
```

传感层采集原始数据，几何层构建空间地图，语义层赋予地图"意义"。本课聚焦语义层的 AI 实现。

## 二、场景语义分割

### 2.1 什么是语义分割

语义分割是对图像中的**每个像素**分配一个类别标签（地面、墙壁、家具、天空等）。在 XR 中，语义分割用于：

- 识别可放置虚拟物体的平面类型（地面 vs 桌面）
- 遮挡处理（虚拟物体应被真实物体遮挡）
- 环境自适应（根据场景类型调整虚拟内容风格）

### 2.2 使用 ONNX Runtime 在 Unity 中运行语义分割

Unity 通过 `Unity.Sentis`（原 Barracuda）加载 ONNX 模型进行推理：

```csharp
using Unity.Sentis;
using UnityEngine;

public class SemanticSegmentation : MonoBehaviour
{
    [SerializeField] private ModelAsset modelAsset;
    [SerializeField] private Camera xrCamera;

    private Worker worker;
    private Texture2D cameraTexture;

    void Start()
    {
        var model = ModelLoader.Load(modelAsset);
        worker = new Worker(model, BackendType.GPUCompute);
        cameraTexture = new Texture2D(512, 512, TextureFormat.RGBA32, false);
    }

    void Update()
    {
        // 从 XR 摄像头获取当前帧
        RenderTexture.active = xrCamera.targetTexture;
        cameraTexture.ReadPixels(new Rect(0, 0, 512, 512), 0, 0);
        cameraTexture.Apply();

        // 预处理：归一化到 [0, 1]
        var inputTensor = TextureConverter.ToTensor(cameraTexture, 512, 512, 3);

        // 推理
        worker.Schedule(inputTensor);

        // 获取分割结果：每个像素的类别 ID
        var outputTensor = worker.PeekOutput() as Tensor<float>;
        outputTensor.ReadbackAndClone();
        ProcessSegmentation(outputTensor);

        inputTensor.Dispose();
    }

    private void ProcessSegmentation(Tensor<float> segmentationMap)
    {
        // 遍历分割图，提取特定类别区域
        // 类别定义：0=背景, 1=地面, 2=墙壁, 3=家具, 4=天花板
        int width = segmentationMap.shape[2];
        int height = segmentationMap.shape[3];

        for (int y = 0; y < height; y++)
        {
            for (int x = 0; x < width; x++)
            {
                int classId = (int)segmentationMap[0, 0, y, x];
                if (classId == 1) // 地面
                {
                    MarkAsFloorRegion(x, y);
                }
            }
        }
    }

    private void MarkAsFloorRegion(int pixelX, int pixelY)
    {
        // 将像素坐标转换为世界坐标，标记为可放置区域
        Ray ray = xrCamera.ScreenPointToRay(new Vector3(pixelX, pixelY, 0));
        if (Physics.Raycast(ray, out RaycastHit hit, 10f))
        {
            Debug.DrawLine(ray.origin, hit.point, Color.green);
        }
    }

    void OnDestroy()
    {
        worker?.Dispose();
    }
}
```

### 2.3 实时性优化

语义分割的推理延迟是 XR 应用的关键瓶颈。常用优化策略：

| 策略 | 效果 | 代价 |
|------|------|------|
| 降低输入分辨率（512→256） | 延迟降低约 60% | 边界精度下降 |
| 隔帧推理 | GPU 负载减半 | 语义更新有滞后 |
| 模型量化（FP32→INT8） | 推理速度提升 2-3x | 精度略有损失 |
| ROI 裁剪 | 只处理关注区域 | 需要预判关注区域 |

## 三、物体识别与空间标注

### 3.1 物体识别流程

物体识别在语义分割基础上更进一步：不仅知道"这是家具"，还知道"这是一把椅子，品牌是 IKEA 的 MARKUS"。

```
摄像头帧 → 目标检测（YOLOv8 / DETR）→ 3D 位姿估计 → 空间标注
```

### 3.2 使用 MediaPipe 实现物体检测

Google MediaPipe 提供了跨平台的物体检测方案，可通过 Android/iOS 原生插件集成到 Unity：

```csharp
using UnityEngine;
using System.Runtime.InteropServices;

public class MediaPipeObjectDetector : MonoBehaviour
{
    // 原生插件接口
    #if UNITY_ANDROID && !UNITY_EDITOR
    private AndroidJavaObject detector;

    void Start()
    {
        using var unityPlayer = new AndroidJavaClass("com.unity3d.player.UnityPlayer");
        var activity = unityPlayer.GetStatic<AndroidJavaObject>("currentActivity");
        detector = new AndroidJavaObject(
            "com.google.mediapipe.tasks.vision.objectdetector.ObjectDetector",
            activity,
            "efficientdet_lite0.tflite"
        );
    }

    public DetectionResult Detect(Texture2D image)
    {
        byte[] imageBytes = image.EncodeToJPG();
        var result = detector.Call<byte[]>("detect", imageBytes);
        return ParseDetectionResult(result);
    }
    #endif

    [System.Serializable]
    public struct BoundingBox
    {
        public float x, y, width, height;
        public string label;
        public float confidence;
    }

    [System.Serializable]
    public struct DetectionResult
    {
        public BoundingBox[] detections;
    }

    private DetectionResult ParseDetectionResult(byte[] data)
    {
        return JsonUtility.FromJson<DetectionResult>(System.Text.Encoding.UTF8.GetString(data));
    }
}
```

### 3.3 空间锚点与 AI 融合

空间锚点让虚拟内容"固定"在真实世界中。传统锚点依赖几何特征匹配，AI 增强方案则利用语义信息提升锚点的鲁棒性：

```csharp
public class AIEnhancedAnchor : MonoBehaviour
{
    private string semanticFingerprint;  // 语义指纹
    private Vector3 geometricPosition;   // 几何位置

    public void CreateAnchor(Pose pose, SemanticContext context)
    {
        geometricPosition = pose.position;

        // 生成语义指纹：周围物体的类别 + 相对位置关系
        semanticFingerprint = GenerateFingerprint(context);
    }

    private string GenerateFingerprint(SemanticContext ctx)
    {
        // 例如："sofa:left:1.2m,table:center:0.8m,tv:front:2.0m"
        var descriptors = new List<string>();
        foreach (var obj in ctx.NearbyObjects)
        {
            float distance = Vector3.Distance(geometricPosition, obj.Position);
            string direction = GetRelativeDirection(geometricPosition, obj.Position);
            descriptors.Add($"{obj.Label}:{direction}:{distance:F1}m");
        }
        descriptors.Sort();
        return string.Join(",", descriptors);
    }

    public bool Relocalize(SemanticContext currentContext)
    {
        // 当几何锚点丢失时，通过语义指纹重新定位
        string currentFingerprint = GenerateFingerprint(currentContext);
        float similarity = ComputeFingerprintSimilarity(
            semanticFingerprint, currentFingerprint
        );
        return similarity > 0.7f;
    }
}
```

语义指纹的核心思想：即使几何特征因光照、遮挡变化而失效，只要周围物体的语义关系稳定，锚点就能恢复。

## 四、AI 与空间计算的融合模式

在实际项目中，AI 与空间计算的融合有三种典型模式：

### 模式一：AI 辅助空间理解

AI 作为"感知增强器"，为已有的空间映射添加语义标签。适用于已有完善 SLAM 系统的场景。

### 模式二：AI 驱动空间交互

AI 直接驱动交互逻辑——手势识别、眼动预测、语音意图理解。用户无需控制器，自然交互。

### 模式三：AI 生成空间内容

AI 根据环境特征自动生成适配的虚拟内容。例如：检测到厨房环境，自动生成烹饪助手。

## 常见误区

1. **"语义分割精度越高越好"**：XR 场景下实时性比精度更重要，95% 精度但 30fps 远好于 99% 精度但 5fps
2. **"物体识别可以直接用 2D 检测结果"**：2D 检测结果必须转换到 3D 空间才有意义，需要深度信息辅助
3. **"空间锚点只靠几何匹配就够了"**：在纹理单一的环境中（白色墙壁），几何锚点极易丢失，语义增强是必要的补充
4. **"AI 模型越大越好"**：移动端 XR 设备的算力有限，模型大小和推理速度需要在项目初期就纳入约束
5. **"语义信息可以离线预计算"**：真实环境是动态的（家具移动、人员走动），语义理解必须在线实时进行

## 工程建议

1. **模型选型优先考虑移动端推理框架**：Unity Sentis、ONNX Runtime Mobile、TensorFlow Lite、Core ML
2. **建立语义缓存机制**：同一空间的语义信息变化缓慢，缓存推理结果可以大幅降低 GPU 负载
3. **分级处理策略**：静态物体（墙壁、地面）低频更新，动态物体（人、宠物）高频更新
4. **传感器融合**：不要只依赖摄像头，结合 LiDAR 深度数据可以显著提升 3D 理解精度
5. **隐私保护**：场景理解涉及大量环境图像数据，务必在设备端推理，避免上传原始图像

## 小结

本课讲解了空间计算中 AI 感知的三个核心环节：场景语义分割提供像素级环境理解，物体识别提供实例级目标检测，空间锚点的 AI 增强确保虚拟内容在真实世界中稳定存在。三者结合，构成了空间计算应用的感知基础。

关键技术点回顾：
- 语义分割使用 ONNX 模型在设备端实时推理，需平衡精度与延迟
- 物体识别通过目标检测 + 3D 位姿估计实现空间标注
- 语义指纹为空间锚点提供几何匹配之外的定位依据
- AI 与空间计算的融合有三种模式：辅助理解、驱动交互、生成内容

### 练习一

**思路**：分析推理延迟的瓶颈——模型计算量、数据传输、后处理——分别优化

**方案一：降低输入分辨率**
```csharp
// 将输入从 512x512 降到 256x256

```
预期效果：延迟降低约 60%（从 45ms 降到约 18ms）。适用条件：对边界精度要求不高的场景，如地面检测。

**方案二：隔帧推理 + 时间复用**
```csharp
private int frameCounter = 0;
private Tensor<float> lastSegmentationResult;

void Update()
{
    frameCounter++;
    if (frameCounter % 3 == 0) // 每 3 帧推理一次
    {
        lastSegmentationResult = RunInference();
    }
    // 使用 lastSegmentationResult 处理当前帧
}
```
预期效果：GPU 负载降低约 66%。适用条件：环境变化缓慢的场景。

**方案三：模型量化（FP32 → INT8）**
```csharp
// 在模型导出时进行 INT8 量化
// Python 端：onnxconverter_common.quantization.quantize_dynamic()
var model = ModelLoader.Load(quantizedModelAsset);
```
预期效果：推理速度提升 2-3x，精度损失约 1-2%。适用条件：对精度容忍度较高，且目标设备支持 INT8 加速。

**要点**：
- 三种方案可以组合使用
- 优先选择不影响用户体验的方案（如隔帧推理）
- 需要在目标设备上实测，模拟器数据不可靠

### 练习二

**思路**：利用深度图将 2D 像素坐标反投影到 3D 空间

**答案**：
```csharp
public struct Object3DAnnotation
{
    public Vector3 worldPosition;
    public Vector3 boundingBoxSize;
    public string label;
}

public Object3DAnnotation ProjectTo3D(
    BoundingBox bbox2D,
    float[,] depthMap,
    Matrix4x4 intrinsicMatrix,
    Transform cameraTransform)
{
    // 1. 取边界框中心点的深度值
    int centerX = (int)(bbox2D.x + bbox2D.width / 2);
    int centerY = (int)(bbox2D.y + bbox2D.height / 2);
    float depth = depthMap[centerY, centerX];

    // 2. 反投影到相机坐标系
    float fx = intrinsicMatrix[0, 0];
    float fy = intrinsicMatrix[1, 1];
    float cx = intrinsicMatrix[0, 2];
    float cy = intrinsicMatrix[1, 2];

    float x = (centerX - cx) * depth / fx;
    float y = (centerY - cy) * depth / fy;
    float z = depth;

    Vector3 cameraPos = new Vector3(x, y, z);

    // 3. 转换到世界坐标
    Vector3 worldPos = cameraTransform.TransformPoint(cameraPos);

    // 4. 估算 3D 包围盒尺寸
    int left = (int)bbox2D.x;
    int right = (int)(bbox2D.x + bbox2D.width);
    int top = (int)bbox2D.y;
    int bottom = (int)(bbox2D.y + bbox2D.height);

    float width3D = Mathf.Abs(
        ((right - cx) * depth / fx) - ((left - cx) * depth / fx)
    );
    float height3D = Mathf.Abs(
        ((bottom - cy) * depth / fy) - ((top - cy) * depth / fy)
    );
    // 深度方向尺寸：在边界框内采样多个深度点取范围
    float depthRange = EstimateDepthRange(depthMap, left, right, top, bottom);

    return new Object3DAnnotation
    {
        worldPosition = worldPos,
        boundingBoxSize = new Vector3(width3D, height3D, depthRange),
        label = bbox2D.label
    };
}
```

**要点**：
- 深度图可能存在空洞，需要插值填充
- 边界框边缘的深度值不可靠，应使用中心区域
- LiDAR 深度图的分辨率通常低于 RGB 图像，需要上采样对齐

### 练习三

**思路**：定义指纹相似度计算方法，分析单一变化和新增元素对结果的影响

**答案**：

原始指纹：`sofa:left:1.2m,table:center:0.8m`
当前指纹：`chair:center:1.0m,sofa:left:2.0m,table:center:0.8m`

逐项对比：
- `sofa:left:1.2m` → `sofa:left:2.0m`：类别和方向匹配，距离变化 0.8m，部分匹配（设距离容差为 0.5m，则此项为 0.5/1.0 = 0.5 分）
- `table:center:0.8m` → `table:center:0.8m`：完全匹配（1.0 分）
- `chair:center:1.0m`：新增项，无对应（0 分）

相似度 = (0.5 + 1.0) / 2 = **0.75**（以原始指纹长度为分母）

阈值分析：
- 阈值 0.7：通过重定位（当前 0.75 > 0.7）
- 阈值 0.8：重定位失败（当前 0.75 < 0.8）

系统行为影响：
- 阈值过低（如 0.5）：容易误匹配，在相似但不同的空间中错误重定位
- 阈值过高（如 0.9）：轻微环境变化就导致锚点丢失，用户体验差
- 推荐阈值 0.6-0.7，配合几何匹配做双重验证

**要点**：
- 相似度计算需要考虑语义类别权重（桌子比装饰画更稳定）
- 动态物体（人、宠物）不应纳入指纹
- 阈值应通过 A/B 测试在真实场景中调优
