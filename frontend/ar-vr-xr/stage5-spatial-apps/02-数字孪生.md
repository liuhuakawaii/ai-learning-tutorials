# 数字孪生

## 场景引入

一座工厂的控制室里，工程师戴上 MR 头显，眼前的虚拟工厂模型与真实产线完全同步运转。3 号传送带的转速降低 5%，虚拟模型上的对应部件立刻变色告警。工程师点击虚拟模型上的传感器节点，实时温度、振动频率、能耗数据浮现在空中。

这就是**数字孪生（Digital Twin）**：物理世界的高保真虚拟镜像，实时同步、双向联动。它不是简单的 3D 建模，而是一个"活"的系统——物理世界变化，虚拟世界跟着变；虚拟世界的操作，也能反馈到物理世界。

本课将讲解如何构建一个可运行的数字孪生系统，重点解决三个核心问题：实时数据同步、IoT 设备集成、空间映射与状态管理。

## 学习目标

1. 理解数字孪生的技术架构与核心组成
2. 掌握实时数据同步的协议选型与实现
3. 学会将 IoT 设备数据接入 XR 应用
4. 理解空间映射在数字孪生中的作用
5. 能够构建一个端到端的数字孪生原型

## 一、数字孪生架构

### 1.1 四层架构模型

```
┌─────────────────────────────────────┐
│  应用层：XR 可视化、交互、分析         │
├─────────────────────────────────────┤
│  模型层：3D 几何、物理仿真、语义模型    │
├─────────────────────────────────────┤
│  数据层：实时数据流、历史数据、事件总线  │
├─────────────────────────────────────┤
│  感知层：IoT 传感器、设备网关、边缘计算  │
└─────────────────────────────────────┘
```

### 1.2 数据流方向

```
物理世界 → 传感器 → 边缘网关 → MQTT Broker → 数据处理 → Unity/WebXR → 虚拟可视化
                                                                              ↓
物理执行 ← PLC/执行器 ← 指令网关 ← 命令队列 ← 交互逻辑 ← 用户操作 ← 虚拟交互
```

关键特征：**双向数据流**。不只是"看"，还能"控"。

## 二、实时数据同步

### 2.1 协议选型

| 协议 | 延迟 | 带宽 | 适用场景 |
|------|------|------|----------|
| MQTT | 低（~10ms） | 低 | IoT 设备数据、状态更新 |
| WebSocket | 低（~20ms） | 中 | WebXR 实时交互 |
| gRPC | 极低（~5ms） | 高 | 服务间高吞吐通信 |
| HTTP REST | 高（~100ms） | 高 | 配置管理、非实时查询 |

数字孪生推荐：**MQTT（设备层）+ WebSocket（应用层）** 的组合方案。

### 2.2 MQTT 数据接入

使用 MQTTnet 库在 Unity 中连接 MQTT Broker：

```csharp
using MQTTnet;
using MQTTnet.Client;
using System.Threading.Tasks;
using UnityEngine;

public class MqttDataBridge : MonoBehaviour
{
    [SerializeField] private string brokerAddress = "broker.example.com";
    [SerializeField] private int brokerPort = 1883;

    private IMqttClient mqttClient;

    public event System.Action<string, string> OnDataReceived;

    public async Task Connect()
    {
        var factory = new MqttFactory();
        mqttClient = factory.CreateMqttClient();

        var options = new MqttClientOptionsBuilder()
            .WithTcpServer(brokerAddress, brokerPort)
            .WithClientId($"xr-device-{SystemInfo.deviceUniqueIdentifier}")
            .WithCleanSession()
            .Build();

        mqttClient.ApplicationMessageReceivedAsync += e =>
        {
            string topic = e.ApplicationMessage.Topic;
            string payload = System.Text.Encoding.UTF8.GetString(
                e.ApplicationMessage.Payload
            );
            // 切换到主线程触发事件
            UnityMainThreadDispatcher.Instance.Enqueue(() =>
            {
                OnDataReceived?.Invoke(topic, payload);
            });
            return Task.CompletedTask;
        };

        await mqttClient.ConnectAsync(options);
        Debug.Log("MQTT 已连接");
    }

    public async Task SubscribeDevice(string deviceId)
    {
        var topic = $"factory/devices/{deviceId}/telemetry";
        await mqttClient.SubscribeAsync(topic);
        Debug.Log($"已订阅设备: {deviceId}");
    }

    public async Task SendCommand(string deviceId, string command)
    {
        var topic = $"factory/devices/{deviceId}/commands";
        var payload = System.Text.Encoding.UTF8.GetBytes(command);
        var message = new MqttApplicationMessageBuilder()
            .WithTopic(topic)
            .WithPayload(payload)
            .WithQualityOfServiceLevel(MQTTnet.Protocol.MqttQualityOfServiceLevel.AtLeastOnce)
            .Build();
        await mqttClient.PublishAsync(message);
    }

    void OnDestroy()
    {
        mqttClient?.DisconnectAsync().Wait();
    }
}
```

### 2.3 数据驱动的 3D 模型更新

```csharp
public class DeviceVisualizer : MonoBehaviour
{
    [SerializeField] private Renderer deviceRenderer;
    [SerializeField] private TextMesh statusLabel;

    private MqttDataBridge dataBridge;
    private string deviceId;
    private MaterialPropertyBlock propertyBlock;

    void Awake()
    {
        propertyBlock = new MaterialPropertyBlock();
    }

    public void Initialize(MqttDataBridge bridge, string id)
    {
        dataBridge = bridge;
        deviceId = id;
        dataBridge.OnDataReceived += HandleData;
    }

    private void HandleData(string topic, string payload)
    {
        if (!topic.Contains(deviceId)) return;

        var data = JsonUtility.FromJson<DeviceTelemetry>(payload);

        // 更新颜色：正常=绿，告警=黄，故障=红
        Color statusColor = data.status switch
        {
            "normal" => Color.green,
            "warning" => Color.yellow,
            "fault" => Color.red,
            _ => Color.white
        };
        propertyBlock.SetColor("_EmissionColor", statusColor * 0.5f);
        deviceRenderer.SetPropertyBlock(propertyBlock);

        // 更新标签
        statusLabel.text = $"{data.temperature:F1}°C\n{data.vibration:F2}mm/s";
    }

    [System.Serializable]
    public struct DeviceTelemetry
    {
        public string status;
        public float temperature;
        public float vibration;
        public float power;
        public long timestamp;
    }
}
```

## 三、IoT 设备集成

### 3.1 设备抽象层

不同厂商的 IoT 设备协议各异，需要一个统一的设备抽象层：

```csharp
public interface IIoTDevice
{
    string DeviceId { get; }
    string DeviceType { get; }
    Dictionary<string, object> CurrentState { get; }
    event System.Action<Dictionary<string, object>> OnStateChanged;
    Task SendCommand(string command, Dictionary<string, object> parameters);
}

public class ModbusDevice : IIoTDevice
{
    public string DeviceId { get; }
    public string DeviceType => "modbus";
    public Dictionary<string, object> CurrentState { get; private set; }
    public event System.Action<Dictionary<string, object>> OnStateChanged;

    private ModbusTcpClient modbusClient;
    private ushort startRegister;
    private ushort registerCount;

    public ModbusDevice(string deviceId, string ip, int port,
                        ushort startReg, ushort regCount)
    {
        DeviceId = deviceId;
        startRegister = startReg;
        registerCount = regCount;
        CurrentState = new Dictionary<string, object>();
        modbusClient = new ModbusTcpClient(ip, port);
    }

    public async Task PollData()
    {
        ushort[] registers = await modbusClient.ReadHoldingRegistersAsync(
            1, startRegister, registerCount
        );

        // 寄存器映射：假设 4 个寄存器分别表示温度、振动、功率、状态
        CurrentState["temperature"] = registers[0] / 10.0f;
        CurrentState["vibration"] = registers[1] / 100.0f;
        CurrentState["power"] = registers[2] / 10.0f;
        CurrentState["status"] = registers[3] == 0 ? "normal" : "fault";

        OnStateChanged?.Invoke(CurrentState);
    }

    public async Task SendCommand(string command, Dictionary<string, object> parameters)
    {
        ushort register = (ushort)parameters["register"];
        ushort value = (ushort)parameters["value"];
        await modbusClient.WriteSingleRegisterAsync(1, register, value);
    }
}
```

```csharp
    }
}
```

## 四、空间映射与虚实对齐

数字孪生的核心挑战之一是让虚拟模型与物理空间精确对齐。

### 4.1 坐标系对齐

```csharp
public class SpatialAlignment : MonoBehaviour
{
    [SerializeField] private Transform virtualFactoryRoot;
    [SerializeField] private List<AlignmentPoint> alignmentPoints;

    private Matrix4x4 alignmentMatrix;

    [System.Serializable]
    public struct AlignmentPoint
    {
        public Vector3 physicalPosition;  // 真实世界坐标（测量值）
        public Transform virtualPoint;    // 虚拟模型对应点
    }

    public void ComputeAlignment()
    {
        // 至少需要 3 个对应点
        if (alignmentPoints.Count < 3)
        {
            Debug.LogError("至少需要 3 个对齐点");
            return;
        }

        // 使用 Umeyama 算法计算最优刚体变换
        alignmentMatrix = ComputeRigidTransform(
            alignmentPoints.Select(p => p.physicalPosition).ToArray(),
            alignmentPoints.Select(p => p.virtualPoint.position).ToArray()
        );

        // 应用变换到虚拟工厂根节点
        virtualFactoryRoot.position = alignmentMatrix.GetPosition();
        virtualFactoryRoot.rotation = alignmentMatrix.rotation;
        virtualFactoryRoot.localScale = alignmentMatrix.lossyScale;
    }

    private Matrix4x4 ComputeRigidTransform(Vector3[] source, Vector3[] target)
    {
        // 简化的刚体变换计算（实际项目建议使用 MathNet.Numerics）
        Vector3 srcCentroid = source.Aggregate(Vector3.zero, (a, b) => a + b) / source.Length;
        Vector3 tgtCentroid = target.Aggregate(Vector3.zero, (a, b) => a + b) / target.Length;

        Vector3 translation = tgtCentroid - srcCentroid;

        // SVD 计算旋转矩阵（此处简化为直接使用 Quaternion）
        Quaternion rotation = Quaternion.FromToRotation(
            source[1] - source[0],
            target[1] - target[0]
        );

        return Matrix4x4.TRS(tgtCentroid, rotation, Vector3.one);
    }
}
```

## 五、状态管理与事件驱动

### 5.1 事件总线

数字孪生系统中，设备状态变化、用户操作、系统告警等事件需要统一管理：

```csharp
public class DigitalTwinEventBus
{
    public static DigitalTwinEventBus Instance { get; } = new();

    private Dictionary<System.Type, List<System.Delegate>> handlers = new();

    public void Subscribe<T>(System.Action<T> handler)
    {
        var type = typeof(T);
        if (!handlers.ContainsKey(type))
            handlers[type] = new List<System.Delegate>();
        handlers[type].Add(handler);
    }

    public void Publish<T>(T eventData)
    {
        if (handlers.TryGetValue(typeof(T), out var list))
        {
            foreach (var handler in list.Cast<System.Action<T>>())
            {
                handler.Invoke(eventData);
            }
        }
    }
}

// 事件定义
```

## 常见误区

1. **"数字孪生就是 3D 模型"**：3D 只是可视化层，核心是实时数据流和双向控制能力
2. **"所有数据都要实时同步"**：温度可以每秒更新，但设备位置可能每分钟更新一次就够了，要根据业务需求分级
3. **"坐标系对齐做一次就行"**：设备搬迁、环境变化后都需要重新对齐，需要设计快速重对齐流程
4. **"MQTT 比 WebSocket 好"**：它们解决不同层的问题，MQTT 适合设备层，WebSocket 适合应用层，不要混为一谈
5. **"数字孪生只用于工业"**：建筑、医疗、零售、城市规划都有成熟的数字孪生应用场景

## 工程建议

1. **数据分层处理**：原始传感器数据在边缘层处理，只有聚合后的状态数据才上传到云端和 XR 应用
2. **设计断线重连机制**：XR 设备可能因用户移动导致网络不稳定，MQTT 的 QoS 1/2 和自动重连是必须的
3. **3D 模型 LOD 策略**：数字孪生场景中设备数量可能很多，远距离设备使用低面数模型
4. **双向操作要有确认机制**：通过虚拟界面控制物理设备时，必须有二次确认和操作日志
5. **性能预算**：数字孪生应用的帧率目标不低于 72fps（VR）或 30fps（AR），数据更新不能阻塞渲染

## 小结

本课讲解了数字孪生系统的核心技术栈：MQTT + WebSocket 实现设备层到应用层的实时数据同步，IoT 设备抽象层统一不同协议的设备接入，空间映射实现虚实精确对齐，事件总线管理复杂的系统状态。

关键技术点回顾：
- 四层架构：感知层→数据层→模型层→应用层
- 设备抽象层统一 Modbus、OPC UA 等异构协议
- Umeyama 算法实现刚体变换的坐标系对齐
- 事件驱动架构解耦设备状态与可视化逻辑

## 参考答案

### 练习一

**思路**：Topic 结构应体现层级关系，QoS 选择取决于数据重要性

**答案**：
```
# Topic 结构
factory/{site_id}/devices/{device_id}/telemetry     # 设备遥测
factory/{site_id}/devices/{device_id}/commands       # 设备命令
factory/{site_id}/devices/{device_id}/status         # 设备状态（上下线）
factory/{site_id}/alerts/{device_id}                 # 告警事件
factory/{site_id}/system/heartbeat                   # 系统心跳
```

QoS 选择：
- `telemetry`：QoS 0（最多一次）。遥测数据频率高（每秒数次），丢失一条不影响整体趋势分析，QoS 0 延迟最低
- `commands`：QoS 1（至少一次）。控制指令必须送达，但应用层做了幂等处理，重复执行不会产生副作用
- `alerts`：QoS 2（恰好一次）。告警数据关系到安全，不能丢失也不能重复
- `heartbeat`：QoS 0。心跳用于检测设备在线状态，丢失一条通过超时机制补充判断

**要点**：
- QoS 等级越高，延迟和带宽开销越大
- 遥测数据可以在应用层做聚合补偿（丢失一条用前后值插值）
- 告警数据建议在边缘层做本地持久化，断网恢复后补传

### 练习二

**思路**：使用 RANSAC 或简单的残差分析剔除异常点

**答案**：
```csharp
public List<AlignmentPoint> FilterOutliers(List<AlignmentPoint> points, float threshold = 10f)
{
    var results = new List<AlignmentPoint>();

    // 方法：对每 3 个点的组合计算刚体变换，检查第 4 个点的残差
    for (int i = 0; i < points.Count; i++)
    {
        var subset = points.Where((_, idx) => idx != i).ToList();
        var transform = ComputeRigidTransform(
            subset.Select(p => p.physicalPosition).ToArray(),
            subset.Select(p => p.virtualPoint.position).ToArray()
        );

        // 计算被剔除点在该变换下的残差
        Vector3 predicted = transform.MultiplyPoint3x4(points[i].physicalPosition);
        float residual = Vector3.Distance(predicted, points[i].virtualPoint.position);

        if (residual < threshold)
        {
            results.Add(points[i]);
        }
        else
        {
            Debug.LogWarning($"对齐点 {i} 残差 {residual:F1}mm 超过阈值，已剔除");
        }
    }

    return results;
}
```

**要点**：
- 阈值应根据测量工具精度设定（激光测距仪通常 ±2mm）
- 如果所有点都被剔除，说明对齐点选取本身有问题
- 实际项目中建议使用 SVD 分解替代简化的 FromToRotation

### 练习三

**思路**：本地缓存 + 状态快照 + UI 指示器

**答案**：
```csharp
public class ResilientMqttBridge : MqttDataBridge
{
    private Queue<string> offlineAlertQueue = new();
    private Dictionary<string, string> latestDeviceStates = new();
    private bool isConnected = false;

    public System.Action<bool> OnConnectionChanged;

    protected override void HandleDisconnect()
    {
        isConnected = false;
        OnConnectionChanged?.Invoke(false);

        // 启动指数退避重连
        StartCoroutine(ReconnectWithBackoff());
    }

    private IEnumerator ReconnectWithBackoff()
    {
        float[] delays = { 1f, 2f, 4f, 8f, 16f, 30f };
        int attempt = 0;

        while (!isConnected)
        {
            float delay = attempt < delays.Length ? delays[attempt] : 30f;
            yield return new WaitForSeconds(delay);
            attempt++;

            try
            {
                Connect().Wait(5000);
                if (mqttClient.IsConnected)
                {
                    isConnected = true;
                    OnConnectionChanged?.Invoke(true);
                    // 恢复订阅
                    ResubscribeAll();
                    // 补发离线告警
                    FlushOfflineAlerts();
                    // 同步最新状态
                    SyncLatestStates();
                }
            }
            catch { /* 继续重试 */ }
        }
    }

    private void FlushOfflineAlerts()
    {
        while (offlineAlertQueue.Count > 0)
        {
            string alert = offlineAlertQueue.Dequeue();
            PublishAlert(alert);
        }
    }

    private void SyncLatestStates()
    {
        foreach (var (deviceId, state) in latestDeviceStates)
        {
            UnityMainThreadDispatcher.Instance.Enqueue(() =>
            {
                OnDataReceived?.Invoke(
                    $"factory/devices/{deviceId}/telemetry",
                    state
                );
            });
        }
    }
}
```

**要点**：
- 告警数据在本地持久化（PlayerPrefs 或 SQLite），防止应用退出丢失
- UI 上显示连接状态指示器（绿/黄/红）
- 重连成功后优先同步告警，再同步常规状态
