# AR 会话：命中检测、平面识别与锚点

## 场景引入

在上一课中，你学会了如何启动一个 WebXR 会话并获取相机位姿。但一个真正的 AR 应用远不止于此——当用户看到真实世界的地面时，如何让虚拟物体准确地「站」在地面上？当用户把一个虚拟花瓶放在桌上后，转一圈再回来，花瓶还在原处吗？

本课将解决三个核心问题：**命中检测**（Hit Testing）用于确定虚拟物体应该放在哪里，**平面检测**（Plane Detection）用于识别真实世界的表面，**锚点**（Anchors）用于让虚拟物体固定在真实世界的位置上。

## 学习目标

- 掌握 WebXR 命中检测 API 的使用方法
- 理解平面检测的工作原理和数据结构
- 掌握锚点的创建和管理
- 了解光照估计对 AR 真实感的作用
- 能实现完整的 AR 物体放置流程

## 命中检测（Hit Testing）

命中检测是 AR 应用最基础的功能。它回答了一个关键问题：用户屏幕上的某个像素点，在真实世界中对应的位置是什么？

### 工作原理

命中检测基于设备的深度感知能力（摄像头 + 深度传感器或算法推断）。当从相机位置向屏幕上的某个点发射一条射线时，系统会计算这条射线与真实世界表面的交点。

```
相机位置
    │
    │ 射线
    │
    ↓
──────────────── 真实世界表面（地面、桌面等）
    ↑
    命中点（返回的变换矩阵）
```

### 请求命中检测源

```typescript
// 命中检测必须在会话创建时声明
const sessionConfig: XRSessionInit = {
  requiredFeatures: ['local-floor'],
  optionalFeatures: ['hit-test'],
};

const session = await navigator.xr.requestSession('immersive-ar', sessionConfig);

// 请求命中检测源
// originSpace 定义射线起点的参考空间
// entityTypes 指定要检测的表面类型
const hitTestSource = await session.requestHitTestSource({
  space: referenceSpace,  // 用于将结果转换到该参考空间
  entityTypes: ['point', 'plane', 'mesh'],  // 检测的实体类型
  offsetRay: new XRRay({ x: 0, y: 0, z: 0 }, { x: 0, y: 0, z: -1 })
  // offsetRay 定义射线的起点和方向（相对于 viewer 空间）
  // 默认是从设备位置向前方发射
});
```

### 获取命中检测结果

命中检测在每帧中执行，返回当前帧命中的所有点：

```typescript
function onFrame(time: DOMHighResTimeStamp, frame: XRFrame): void {
  session.requestAnimationFrame(onFrame);

  const pose = frame.getViewerPose(referenceSpace);
  if (!pose) return;

  // 获取命中检测结果
  const hitResults = frame.getHitTestResults(hitTestSource);

  if (hitResults.length > 0) {
    // 取第一个命中结果
    const hit = hitResults[0];
    const hitPose = hit.getPose(referenceSpace);

    if (hitPose) {
      // hitPose.transform 包含命中点的位置和朝向
      const position = hitPose.transform.position;
      const orientation = hitPose.transform.orientation;

      // 在命中点放置一个指示器（如光标）
      updateReticlePosition(position, orientation);
    }
  }

  // 继续渲染...
}
```

### XRRay 与射线定制

默认的命中检测射线从设备位置向前方发射（沿 -Z 轴）。你可以自定义射线的起点和方向：

```typescript
// 从屏幕中心向下 15 度发射射线（模拟用户低头看地面的视线）
const customRay = new XRRay(
  { x: 0, y: 0, z: 0 },  // 起点：设备位置
  { x: 0, y: -0.2588, z: -0.9659 }  // 方向：向下 15 度的单位向量
);

const hitTestSource = await session.requestHitTestSource({
  space: referenceSpace,
  offsetRay: customRay,
});
```

### 瞬态命中检测源

对于不预先创建 `hitTestSource` 的场景（如用户点击屏幕时才做检测），可以使用瞬态命中检测源：

```typescript
// 瞬态命中检测源不需要预先创建，每帧都可以直接请求
function getTransientHitTest(frame: XRFrame, x: number, y: number): XRPose | null {
  // 注意：瞬态命中检测需要 'transient-pointer-hit-test' 特性
  const transientSource = frame.getHitTestResultsForTransientInput(
    { profile: 'generic-touchscreen' }
  );

  if (transientSource.length > 0) {
    const hit = transientSource[0].results[0];
    return hit.getPose(referenceSpace) ?? null;
  }
  return null;
}
```

## 平面检测（Plane Detection）

平面检测将真实世界的表面抽象为可供程序使用的几何数据。WebXR 通过 `XRPlane` 接口暴露检测到的平面信息。

### 启用平面检测

```typescript
const sessionConfig: XRSessionInit = {
  requiredFeatures: ['local-floor'],
  optionalFeatures: ['plane-detection'],
};

const session = await navigator.xr.requestSession('immersive-ar', sessionConfig);
```

### 获取平面数据

平面数据通过 `XRFrame.detectedPlanes` 获取。每帧返回当前检测到的所有平面：

```typescript
function onFrame(time: DOMHighResTimeStamp, frame: XRFrame): void {
  session.requestAnimationFrame(onFrame);

  // 获取当前帧检测到的所有平面
  const detectedPlanes = frame.detectedPlanes;

  // 遍历每个平面
  detectedPlanes.forEach((plane: XRPlane) => {
    // 平面的语义类型：floor, ceiling, wall, ...
    const planeType = plane.semanticLabel ?? 'unknown';

    // 平面的几何轮廓（相对于平面自身坐标系的多边形顶点）
    const polygon = plane.polygon;

    // 平面在参考空间中的位姿
    const planePose = plane.planeSpace;  // 这是一个 XRSpace
    // 注意：plane.planeSpace 不能直接获取 pose，需要通过 frame.getPose()

    // 获取平面在参考空间中的位姿
    const pose = frame.getPose(plane.planeSpace, referenceSpace);
    if (pose) {
      renderPlane(plane, pose);
    }
  });
}
```

### XRPlane 数据结构

每个 `XRPlane` 包含以下关键信息：

```typescript
interface XRPlane {
  // 平面在参考空间中的空间（用于获取位姿）
  planeSpace: XRSpace;

  // 平面的多边形轮廓顶点（相对于 planeSpace 的 2D/3D 坐标）
  polygon: DOMPointReadOnly[];

  // 平面的语义标签（如 'floor', 'wall', 'ceiling'）
  semanticLabel?: string;

  // 平面最后更新的时间戳
  lastChangedTime: DOMHighResTimeStamp;
}
```

### 渲染检测到的平面

```typescript
function renderPlane(plane: XRPlane, pose: XRPose): void {
  const polygon = plane.polygon;
  if (polygon.length < 3) return;  // 至少需要 3 个点构成多边形

  // 将平面多边形转换为 Three.js 几何体
  const shape = new THREE.Shape();
  shape.moveTo(polygon[0].x, polygon[0].z);
  for (let i = 1; i < polygon.length; i++) {
    shape.lineTo(polygon[i].x, polygon[i].z);
  }
  shape.closePath();

  const geometry = new THREE.ShapeGeometry(shape);
  const material = new THREE.MeshBasicMaterial({
    color: 0x00ff00,
    transparent: true,
    opacity: 0.3,
    side: THREE.DoubleSide,
  });

  const mesh = new THREE.Mesh(geometry, material);

  // 设置平面的位置和旋转
  const position = pose.transform.position;
  const orientation = pose.transform.orientation;
  mesh.position.set(position.x, position.y, position.z);
  mesh.quaternion.set(orientation.x, orientation.y, orientation.z, orientation.w);
}
```

## 锚点（Anchors）

锚点解决了一个关键问题：如何让虚拟物体固定在真实世界的某个位置，即使设备移动或追踪数据更新？

### 为什么需要锚点

WebXR 的参考空间可能会随着设备校准而发生偏移。如果直接把虚拟物体放在参考空间的某个坐标上，当参考空间偏移时，物体就会「漂移」。锚点通过与真实世界特征点绑定来解决这个问题。

```
没有锚点：
  设备移动 → 参考空间可能偏移 → 虚拟物体漂移

有锚点：
  设备移动 → 锚点自动修正 → 虚拟物体保持在原处
```

### 创建锚点

```typescript
// 方法一：从命中检测结果创建锚点
async function createAnchorFromHit(
  frame: XRFrame,
  hitResult: XRHitTestResult
): Promise<XRAnchor | null> {
  try {
    const anchor = await hitResult.createAnchor();
    return anchor;
  } catch (error) {
    console.error('创建锚点失败:', error);
    return null;
  }
}

// 方法二：从空间和位姿创建锚点
async function createAnchorAtPose(
  frame: XRFrame,
  space: XRSpace,
  pose: XRRigidTransform
): Promise<XRAnchor | null> {
  try {
    const anchor = await frame.createAnchor(pose, space);
    return anchor;
  } catch (error) {
    console.error('创建锚点失败:', error);
    return null;
  }
}
```

### 使用锚点定位物体

```typescript
class ARAnchorManager {
  private anchors: Map<string, { anchor: XRAnchor; object: THREE.Object3D }> = new Map();

  async placeObject(
    frame: XRFrame,
    hitResult: XRHitTestResult,
    object: THREE.Object3D
  ): Promise<void> {
    const anchor = await createAnchorFromHit(frame, hitResult);
    if (!anchor) return;

    const anchorId = crypto.randomUUID();
    this.anchors.set(anchorId, { anchor, object });
  }

  updateAnchors(frame: XRFrame, referenceSpace: XRReferenceSpace): void {
    this.anchors.forEach(({ anchor, object }) => {
      // 获取锚点在参考空间中的当前位姿
      const anchorSpace = anchor.anchorSpace;
      const pose = frame.getPose(anchorSpace, referenceSpace);

      if (pose) {
        // 更新物体位置
        const pos = pose.transform.position;
        const rot = pose.transform.orientation;
        object.position.set(pos.x, pos.y, pos.z);
        object.quaternion.set(rot.x, rot.y, rot.z, rot.w);
      }
    });
  }

  removeAnchor(id: string): void {
    const entry = this.anchors.get(id);
    if (entry) {
      entry.anchor.delete();  // 释放锚点资源
      this.anchors.delete(id);
    }
  }

  clear(): void {
    this.anchors.forEach(({ anchor }) => anchor.delete());
    this.anchors.clear();
  }
}
```

### 锚点删除的时机

锚点会占用系统资源，必须在不再需要时及时删除：

```typescript
// 当用户删除一个虚拟物体时，同时删除对应的锚点
function onObjectDeleted(anchorId: string): void {
  anchorManager.removeAnchor(anchorId);
}

// 会话结束时清理所有锚点
session.addEventListener('end', () => {
  anchorManager.clear();
});
```

## 光照估计（Light Estimation）

光照估计让虚拟物体的光照与真实环境一致，是 AR 真实感的关键因素。

```typescript
// 启用光照估计
const sessionConfig: XRSessionInit = {
  requiredFeatures: ['local-floor'],
  optionalFeatures: ['light-estimation'],
};

// 获取光照估计数据
function updateLightEstimation(frame: XRFrame, referenceSpace: XRReferenceSpace): void {
  // 注意：光照估计 API 的具体实现可能因浏览器版本而异
  // 以下为概念示例
  const lightEstimate = frame.getLightEstimate?.(referenceSpace);
  if (!lightEstimate) return;

  // lightEstimate 包含：
  // - primaryLightDirection: 主光源方向
  // - primaryLightIntensity: 主光源强度
  // - sphericalHarmonicsCoefficients: 球谐函数系数（环境光照）

  // 将光照数据应用到 Three.js 场景
  if (lightEstimate.primaryLightDirection) {
    directionalLight.position.set(
      -lightEstimate.primaryLightDirection.x,
      -lightEstimate.primaryLightDirection.y,
      -lightEstimate.primaryLightDirection.z
    );
  }
}
```

## 完整的 AR 物体放置流程

将以上所有概念整合为一个完整的 AR 物体放置流程：

```typescript
class ARPlacementApp {
  private session: XRSession | null = null;
  private hitTestSource: XRHitTestSource | null = null;
  private anchorManager = new ARAnchorManager();
  private reticle: THREE.Mesh;  // 命中点指示器

  async start(canvas: HTMLCanvasElement): Promise<void> {
    if (!navigator.xr) throw new Error('WebXR 不可用');

    this.session = await navigator.xr.requestSession('immersive-ar', {
      requiredFeatures: ['local-floor'],
      optionalFeatures: ['hit-test', 'anchors', 'plane-detection'],
    });

    const gl = canvas.getContext('webgl', { xrCompatible: true })!;
    const layer = new XRWebGLLayer(this.session, gl);
    this.session.updateRenderState({ baseLayer: layer });

    const referenceSpace = await this.session.requestReferenceSpace('local-floor');
    this.hitTestSource = await this.session.requestHitTestSource({
      space: referenceSpace,
    });

    this.session.addEventListener('end', () => this.cleanup());

    // 用户点击时放置物体
    canvas.addEventListener('select', () => this.onSelect());

    this.session.requestAnimationFrame((t, f) => this.onFrame(t, f, referenceSpace, layer, gl));
  }

  private onFrame(
    time: DOMHighResTimeStamp,
    frame: XRFrame,
    referenceSpace: XRReferenceSpace,
    layer: XRWebGLLayer,
    gl: WebGLRenderingContext
  ): void {
    this.session!.requestAnimationFrame((t, f) => this.onFrame(t, f, referenceSpace, layer, gl));

    const pose = frame.getViewerPose(referenceSpace);
    if (!pose) return;

    // 更新命中检测指示器
    if (this.hitTestSource) {
      const hits = frame.getHitTestResults(this.hitTestSource);
      if (hits.length > 0) {
        const hitPose = hits[0].getPose(referenceSpace);
        if (hitPose) {
          this.reticle.visible = true;
          this.reticle.position.set(
            hitPose.transform.position.x,
            hitPose.transform.position.y,
            hitPose.transform.position.z
          );
        }
      } else {
        this.reticle.visible = false;
      }
    }

    // 更新锚点物体
    this.anchorManager.updateAnchors(frame, referenceSpace);

    // 渲染
    gl.bindFramebuffer(gl.FRAMEBUFFER, layer.framebuffer);
    gl.clear(gl.COLOR_BUFFER_BIT | gl.DEPTH_BUFFER_BIT);

    for (const view of pose.views) {
      const viewport = layer.getViewport(view)!;
      gl.viewport(viewport.x, viewport.y, viewport.width, viewport.height);
      // Three.js 渲染逻辑
    }
  }

  private async onSelect(): Promise<void> {
    // 在命中点创建物体并锚定
    // 具体实现依赖 Three.js 集成，详见第 04 课
  }

  private cleanup(): void {
    this.anchorManager.clear();
    this.hitTestSource?.cancel();
    this.hitTestSource = null;
    this.session = null;
  }
}
```

## 常见误区

### 误区一：命中检测结果直接用作最终位置

命中检测返回的是射线与表面的交点，但这个交点可能不准确。应该使用锚点来固定物体位置，而不是每帧都用命中检测结果更新位置。

### 误区二：平面检测是即时的

平面检测需要时间。设备刚启动 AR 会话时，可能需要几秒甚至十几秒才能检测到第一个平面。应用应该有适当的加载状态提示。

### 误区三：忽略锚点的生命周期管理

每个锚点都占用系统资源。如果创建了锚点但从不删除，会导致内存泄漏和系统资源耗尽。

### 误区四：假设平面类型一定正确

`semanticLabel`（如 `'floor'`、`'wall'`）是系统推测的结果，不一定准确。对于关键功能，应该让用户确认或提供覆盖选项。

## 工程建议

1. **命中指示器**：始终显示一个命中指示器（reticle），让用户知道物体将被放在哪里
2. **锚点管理器**：使用集中式的锚点管理器跟踪所有锚点，确保资源被正确释放
3. **平面可视化**：在调试阶段可视化检测到的平面，帮助理解设备的识别能力
4. **延迟处理**：平面检测结果可能每帧都变化，应该使用 `lastChangedTime` 过滤掉频繁变化的平面
5. **特性降级**：如果设备不支持光照估计，使用默认光照方案，而不是让应用崩溃

## 小结

本课介绍了 AR 会话的三个核心能力：

- **命中检测**：通过射线与真实世界表面求交，确定虚拟物体的放置位置
- **平面检测**：识别真实世界的表面（地面、墙面等），提供几何和语义信息
- **锚点**：将虚拟物体固定在真实世界的位置上，防止漂移

这三个能力构成了 AR 物体放置的完整流程：检测平面 → 命中检测 → 创建锚点 → 渲染物体。

## 参考答案

### 练习一

**思路**：两次命中检测获取两个端点坐标，用欧氏距离公式计算。

**答案**：
```typescript
class ARuler {
  private points: DOMPointReadOnly[] = [];

  addPoint(hitPose: XRPose): void {
    const pos = hitPose.transform.position;
    this.points.push(new DOMPointReadOnly(pos.x, pos.y, pos.z));

    if (this.points.length === 2) {
      const distance = this.calculateDistance(this.points[0], this.points[1]);
      console.log(`测量距离: ${distance.toFixed(2)} 米`);
    }
  }

  private calculateDistance(a: DOMPointReadOnly, b: DOMPointReadOnly): number {
    const dx = b.x - a.x;
    const dy = b.y - a.y;
    const dz = b.z - a.z;
    return Math.sqrt(dx * dx + dy * dy + dz * dz);
  }

  reset(): void {
    this.points = [];
  }
}
```

**要点**：
- 两次独立的命中检测，通过用户交互（如点击）触发
- 距离计算使用三维欧氏距离公式
- 单位是米（WebXR 使用国际单位制）

### 练习二

**思路**：先用平面检测找到地板平面，然后在地板上做命中检测放置家具，用锚点固定。

**答案**：
1. 通过 `frame.detectedPlanes` 找到 `semanticLabel === 'floor'` 的平面
2. 在地板平面上做命中检测，获取放置位置
3. 从命中检测结果创建锚点
4. 将家具模型绑定到锚点上
5. 每帧通过 `frame.getPose(anchor.anchorSpace, referenceSpace)` 更新家具位置

**要点**：
- 平面检测是持续性的，新平面可能随时出现
- 锚点确保家具位置稳定，即使参考空间发生偏移
- 应该为每件家具维护独立的锚点

### 练习三

**思路**：光照不一致会破坏 AR 沉浸感。替代方案包括使用环境光探针或手动设置光照。

**答案**：光照估计的重要性：
- 真实世界的光照条件是变化的（室内/室外、白天/夜晚）
- 如果虚拟物体的光照与环境不一致，会产生明显的「贴图感」
- 光照估计让虚拟物体的阴影、高光与真实环境匹配

替代方案：
- 使用中性环境光（纯白色环境光 + 柔和的阴影）
- 使用球谐函数近似环境光（不需要实时数据）
- 允许用户手动调节光照强度和方向
- 在室外场景使用基于时间的太阳位置估算

**要点**：
- 光照估计不是所有设备都支持，必须有降级方案
- 即使是简单的方向光 + 环境光，也比完全不处理光照要好
