# 04 - 性能要求

## 场景引入

你在 PC 浏览器上开发了一个 Three.js 场景，跑在 60fps 很流畅。然后接入 WebXR，在 Quest 3 上运行——画面卡顿、头部追踪延迟、用户 5 分钟后开始头晕。

XR 的性能要求和传统 Web 应用**完全不同**。在 2D 网页上掉帧是"页面卡了一下"，在 XR 中掉帧是"用户生理不适"。

## 学习目标

- 理解 XR 为什么需要 90fps+ 的帧率
- 掌握 motion-to-photon latency 的延迟预算
- 了解渲染预算的分配方式
- 学会使用性能分析工具定位瓶颈

## 帧率要求：为什么是 90fps

在 2D 屏幕上 30fps "还行"，60fps "很流畅"。但 XR 中用户头部持续运动，低帧率导致**画面滞后于头部运动**，这是眩晕的最直接原因。

| 帧率 | 2D 体验 | XR 体验 |
|------|---------|---------|
| 30fps | 可接受 | 严重眩晕，不可用 |
| 60fps | 流畅 | 轻度不适，长时间会累 |
| 90fps | 非常流畅 | 舒适，XR 最低标准 |
| 120fps | 极致流畅 | 非常舒适，高端设备支持 |

### 双眼渲染的性能开销

XR 需要为左右眼分别渲染，渲染调用量翻倍。

```typescript
function calculateXRResolution(
  w: number, h: number, fps: number = 90
): { totalPixels: number; vsPC: string } {
  const total = w * 2 * h * fps // 双眼
  const pc1080 = 1920 * 1080 * 60
  return {
    totalPixels: total,
    vsPC: `是 1080p@60fps 的 ${(total / pc1080).toFixed(1)} 倍`
  }
}

// Quest 3: 单眼 2064×2208
const q3 = calculateXRResolution(2064, 2208)
console.log(`Quest 3 每秒像素量: ${q3.totalPixels.toLocaleString()}, ${q3.vsPC}`)
// 约为 1080p@60fps 的 6.4 倍
```

## 延迟预算：Motion-to-Photon Latency

Motion-to-photon latency（MTP）是从用户头部运动到屏幕显示对应画面的时间差。必须 **< 20ms**。

```
用户转头 → IMU 采样 → 数据传输 → CPU 处理 → GPU 渲染 → 显示刷新
|<--------------------- 必须 < 20ms -------------------->|
```

```typescript
const LATENCY_BUDGET = {
  sensorSampling: 1,   // IMU 采样
  dataTransfer: 1,     // 数据传输
  cpuProcessing: 3,    // CPU（应用逻辑、场景图更新）
  gpuRendering: 8,     // GPU 渲染（90fps = 11.1ms/帧，留余量）
  displayScan: 2,      // 显示器扫描
  buffer: 5,           // 安全余量
  total: 20
} as const
```

降低延迟的关键技术：
1. **Reprojection**：用最新头部数据重新投影上一帧，无需重新渲染
2. **CPU 优化**：复杂计算放 Worker 线程，主线程控制在 3ms 内
3. **GPU 优化**：减少 draw call、降低着色器复杂度、使用注视点渲染

## 渲染预算

### 帧时间预算

90fps 下每帧总时间 11.1ms，需要在 CPU 和 GPU 之间分配。

```typescript
const FRAME_BUDGET = {
  total: 11.1, // ms
  cpu: {
    sceneGraph: 1.0,      // 场景图更新
    animation: 0.5,       // 动画系统
    physics: 1.0,         // 物理模拟
    logic: 0.5,           // 应用逻辑
    drawCallSubmit: 1.0,  // 提交渲染命令
  },
  gpu: {
    vertex: 2.0,          // 顶点着色器
    rasterization: 1.0,   // 光栅化
    fragment: 3.0,        // 片段着色器
    postProcess: 1.0,     // 后处理
  }
} as const
```

### Draw Call 限制

每个 draw call 有 CPU 端提交开销，在 XR 中更敏感（CPU 预算仅 4ms）。

```typescript
import * as THREE from 'three'

// 不好：100 个独立立方体 = 100 个 draw call
for (let i = 0; i < 100; i++) {
  const cube = new THREE.Mesh(geometry, material)
  scene.add(cube)
}

// 好：实例化渲染 = 1 个 draw call
const instanced = new THREE.InstancedMesh(geometry, material, 100)
const matrix = new THREE.Matrix4()
for (let i = 0; i < 100; i++) {
  matrix.setPosition(Math.random() * 10, Math.random() * 3, Math.random() * 10)
  instanced.setMatrixAt(i, matrix)
}
instanced.instanceMatrix.needsUpdate = true
scene.add(instanced)
```

## 渲染优化技术

### 固定注视点渲染

人眼只有中心约 2° 视野是高分辨率的，外围分辨率低得多。

```typescript
function getLODLevel(
  screenPos: THREE.Vector2,
  center: THREE.Vector2,
  screenSize: THREE.Vector2
): 'high' | 'medium' | 'low' {
  const dx = (screenPos.x - center.x) / (screenSize.x / 2)
  const dy = (screenPos.y - center.y) / (screenSize.y / 2)
  const dist = Math.sqrt(dx * dx + dy * dy)
  if (dist < 0.3) return 'high'
  if (dist < 0.7) return 'medium'
  return 'low'
}
```

### 几何体合并

将多个使用相同材质的物体合并为一个 BufferGeometry，大幅减少 draw call。

```typescript
function mergeBoxes(positions: THREE.Vector3[], size: number): THREE.Mesh {
  const geo = new THREE.BoxGeometry(size, size, size)
  const merged = new THREE.BufferGeometry()
  const pos: number[] = [], norm: number[] = [], idx: number[] = []
  let offset = 0

  const posArr = geo.attributes.position.array
  const normArr = geo.attributes.normal.array
  const idxArr = geo.index!.array

  for (const p of positions) {
    for (let j = 0; j < posArr.length; j += 3) {
      pos.push(posArr[j] + p.x, posArr[j + 1] + p.y, posArr[j + 2] + p.z)
      norm.push(normArr[j], normArr[j + 1], normArr[j + 2])
    }
    for (let j = 0; j < idxArr.length; j++) idx.push(idxArr[j] + offset)
    offset += posArr.length / 3
  }

  merged.setAttribute('position', new THREE.Float32BufferAttribute(pos, 3))
  merged.setAttribute('normal', new THREE.Float32BufferAttribute(norm, 3))
  merged.setIndex(idx)

  return new THREE.Mesh(merged, new THREE.MeshStandardMaterial({ color: 0x00ff00 }))
}
```

## 性能监控

```typescript
class XRPerfMonitor {
  private times: number[] = []
  private last = 0

  beginFrame() { this.last = performance.now() }

  endFrame(renderer: THREE.WebGLRenderer) {
    const ft = performance.now() - this.last
    this.times.push(ft)
    if (this.times.length > 90) this.times.shift()

    const avg = this.times.reduce((a, b) => a + b) / this.times.length
    const fps = 1000 / avg
    const jank = this.times.filter(t => t > 11.1).length

    console.log(`FPS: ${fps.toFixed(1)} | 平均: ${avg.toFixed(1)}ms | 掉帧: ${jank} | Draw Calls: ${renderer.info.render.calls}`)
  }
}
```

## 常见误区

1. **"60fps 在 XR 中够用"** —— 不够。90fps 是最低标准，60fps 在 VR 中会导致明显画面滞后
2. **"优化只看 GPU"** —— CPU 预算同样紧张（仅 4ms），场景图遍历、动画、物理都在 CPU 上
3. **"先开发功能，最后再优化"** —— XR 的性能约束是硬性的，架构设计时就需考虑

## 工程建议

1. 从一开始就用真机测试，不要在 PC 模拟器上评估性能
2. 建立性能基准线，在项目初期定义目标帧率和延迟预算
3. 用 `renderer.info` 监控 draw call 和三角形数量
4. 优先优化片段着色器，这是 XR 渲染中最重的部分
5. 使用 LOD 和实例化渲染，减少 GPU 负载

## 小结

- **帧率**：90fps 是最低标准，双眼渲染使像素吞吐量翻倍
- **延迟**：Motion-to-photon latency 必须 < 20ms
- **渲染预算**：draw call < 150，三角形 < 50 万/眼（Quest 3）
- **优化技术**：注视点渲染、实例化渲染、几何体合并

## 参考答案

### 练习一

**答案**：
```typescript
const objects = 200
const trisPerObj = 5000
const totalTris = objects * trisPerObj // 1,000,000

// Quest 3 单眼预算 500,000，双眼各渲染一次
const singleEyeBudget = 500_000
const drawCallBudget = 150

console.log(`总三角形: ${totalTris.toLocaleString()}`)
console.log(`单眼: ${totalTris / 2} vs 预算 ${singleEyeBudget} → ${totalTris / 2 <= singleEyeBudget ? '✓' : '✗'}`)
console.log(`Draw Call: ${objects} vs 预算 ${drawCallBudget} → ${objects <= drawCallBudget ? '✓' : '✗'}`)
// 三角形刚好在预算边缘，draw call 超标
// 解决：用 InstancedMesh 合并
```

**要点**：三角形和 draw call 是独立指标，即使三角形合理，过多 draw call 也会导致 CPU 瓶颈。

### 练习二

**答案**：
```typescript
import * as THREE from 'three'

class PerfMonitor {
  private el: HTMLDivElement
  private times: number[] = []
  private last = 0

  constructor() {
    this.el = document.createElement('div')
    this.el.style.cssText = 'position:fixed;top:10px;right:10px;background:rgba(0,0,0,.7);color:#0f0;font:12px monospace;padding:8px;border-radius:4px;z-index:9999'
    document.body.appendChild(this.el)
  }

  beginFrame() { this.last = performance.now() }

  endFrame(renderer: THREE.WebGLRenderer) {
    this.times.push(performance.now() - this.last)
    if (this.times.length > 60) this.times.shift()
    const avg = this.times.reduce((a, b) => a + b) / this.times.length
    this.el.innerHTML = [
      `FPS: ${(1000 / avg).toFixed(0)}`,
      `帧时间: ${avg.toFixed(1)}ms`,
      `Draw Calls: ${renderer.info.render.calls}`,
      `三角形: ${renderer.info.render.triangles.toLocaleString()}`
    ].join('<br>')
  }
}

// 在渲染循环中使用
const monitor = new PerfMonitor()
function render() {
  monitor.beginFrame()
  renderer.render(scene, camera)
  monitor.endFrame(renderer)
}
```

**要点**：
- `renderer.info.render.calls` 返回 draw call 数量
- 帧时间取平均值，单帧波动太大
- 实际 XR 中这个面板应渲染为 3D HUD，因为 XR 没有 DOM

**常见错误写法**：每帧 `console.log` 性能数据。这会严重影响性能本身。
