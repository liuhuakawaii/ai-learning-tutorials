# 原生模块原理

## 场景引入

你的 App 需要调用设备的蓝牙传感器，但 JavaScript 层没有蓝牙 API。你找到了 `react-native-ble-plx`，装上就能用——但它是怎么让 JS 调用到 iOS 的 CoreBluetooth 和 Android 的 BLE API 的？理解原生模块原理，不仅能排查诡异崩溃，还能让你在现有库不满足需求时自己写一个原生模块。

## 学习目标

- 理解 React Native 架构从 Bridge 到 JSI 再到新架构的演进
- 掌握 Turbo Modules 和 Fabric 渲染器的核心机制
- 使用 Expo Modules API 开发一个自定义原生模块
- 理解 Native Module 的注册、调用和生命周期
- 识别 iOS 与 Android 平台差异对模块开发的影响

---

## 一、架构演进：从 Bridge 到新架构

### 1.1 旧架构：Bridge 模式

React Native 0.68 之前使用 Bridge 架构，JS 和 Native 之间通过 JSON 异步消息通信。每次调用都要序列化/反序列化，高频调用时性能瓶颈明显，且所有消息经过同一个 Bridge 队列。

### 1.2 新架构：JSI + Turbo Modules + Fabric

新架构用 JSI（JavaScript Interface）取代 Bridge，JS 引擎通过 C++ 直接持有 Native 对象引用，无需序列化。

| 对比维度 | Bridge（旧架构） | JSI（新架构） |
|---------|-----------------|--------------|
| 通信方式 | JSON 异步消息 | C++ 同步调用 |
| 序列化 | 需要 | 不需要 |
| 同步调用 | 不支持 | 原生支持 |
| 类型安全 | 运行时检查 | Codegen 编译时检查 |

**Turbo Modules** 支持懒加载和同步方法，通过 Codegen 从 TypeScript 规范生成 C++ 接口。**Fabric** 是新渲染器，支持 Concurrent Features，渲染流程可在任意线程执行。

## 二、Expo Modules API

Expo 提供了更易用的原生模块开发方案：

```swift
// Swift (iOS)
import ExpoModulesCore

public class BatteryModule: Module {
  public func definition() -> ModuleDefinition {
    Name("BatteryModule")
    AsyncFunction("getBatteryInfo") -> [String: Any] {
      let device = UIDevice.current
      return [
        "level": Double(device.batteryLevel),
        "isCharging": device.batteryState == .charging
      ]
    }
    Events("onBatteryChange")
  }
}
```

```kotlin
// Kotlin (Android)
import expo.modules.kotlin.modules.Module
import expo.modules.kotlin.modules.ModuleDefinition

class BatteryModule : Module() {
  override fun definition() = ModuleDefinition {
    Name("BatteryModule")
    AsyncFunction("getBatteryInfo") {
      mapOf("level" to 0.85, "isCharging" to false)
    }
    Events("onBatteryChange")
  }
}
```

Expo Modules API 优势：Swift/Kotlin 一等公民支持、声明式 API 定义、自动类型转换、内置事件机制。

## 三、开发一个自定义模块

### 3.1 TypeScript 接口

```typescript
import { requireNativeModule } from 'expo-modules-core'

export interface BatteryInfo {
  level: number
  isCharging: boolean
}

const BatteryModule = requireNativeModule('BatteryInfo')

export async function getBatteryInfo(): Promise<BatteryInfo> {
  return await BatteryModule.getBatteryInfo()
}

export function addBatteryListener(
  listener: (info: BatteryInfo) => void
): { remove: () => void } {
  return BatteryModule.addListener('onBatteryChange', listener)
}
```

### 3.2 iOS 实现要点

```swift
OnCreate {
  UIDevice.current.isBatteryMonitoringEnabled = true
}

OnStartObserving {
  NotificationCenter.default.addObserver(
    forName: UIDevice.batteryStateDidChangeNotification,
    object: nil, queue: .main
  ) { [weak self] _ in
    let device = UIDevice.current
    self?.sendEvent("onBatteryChange", [
      "level": Double(device.batteryLevel),
      "isCharging": device.batteryState == .charging
    ])
  }
}

OnStopObserving {
  NotificationCenter.default.removeObserver(
    self, name: UIDevice.batteryStateDidChangeNotification, object: nil
  )
}
```

### 3.3 使用模块

```typescript
import { useEffect, useState } from 'react'
import { View, Text } from 'react-native'
import { getBatteryInfo, addBatteryListener, BatteryInfo } from 'expo-battery-info'

export default function BatteryScreen() {
  const [battery, setBattery] = useState<BatteryInfo | null>(null)

  useEffect(() => {
    getBatteryInfo().then(setBattery)
    const subscription = addBatteryListener(setBattery)
    return () => subscription.remove()
  }, [])

  if (!battery) return <Text>加载中...</Text>
  return (
    <View style={{ flex: 1, justifyContent: 'center', alignItems: 'center' }}>
      <Text style={{ fontSize: 48 }}>{Math.round(battery.level * 100)}%</Text>
      <Text>{battery.isCharging ? '充电中' : '未充电'}</Text>
    </View>
  )
}
```

## 四、平台差异处理

| 差异点 | iOS | Android |
|-------|-----|---------|
| 语言 | Swift / Objective-C | Kotlin / Java |
| 构建系统 | CocoaPods | Gradle |
| 权限模型 | Info.plist 声明 | AndroidManifest.xml + 运行时请求 |
| 后台执行 | 严格限制 | 相对宽松 |

---

## 常见误区

1. **新架构等于性能全面碾压**：新架构在高频调用场景提升明显，简单页面渲染差异不大。
2. **Expo Modules 和 Turbo Modules 是同一个东西**：它们是独立的原生模块系统。
3. **同步调用一定比异步好**：同步调用会阻塞 JS 线程，IO 密集型操作仍应异步。
4. **写原生模块必须精通 Swift 和 Kotlin**：Expo Modules API 极大降低了门槛。

---

## 工程建议

1. **优先使用 Expo SDK 提供的模块**，除非有特殊需求否则不自己写。
2. **模块接口保持最小化**，复杂逻辑封装在 Native 层。
3. **错误处理要跨层传递**，包含错误码和可读描述。
4. **事件监听器注意清理**，避免内存泄漏。

---

## 小结

- React Native 架构从 Bridge 演进到 JSI，新架构通过 C++ 直接调用消除序列化开销
- Expo Modules API 使用 Swift/Kotlin 声明式定义模块，代码量少、类型安全
- 原生模块开发需注意 iOS/Android 的权限、生命周期和后台策略差异
- 优先使用现有 Expo SDK 模块，只在必要时自定义原生模块

### 练习二：事件机制

## 参考答案

### 练习一

**思路**：先定义数据类型，再定义模块接口函数。设备信息大多是只读的，用异步函数获取。

**答案**：

```typescript
export interface DeviceInfo {
  name: string
  systemVersion: string
  model: string
  isEmulator: boolean
  batteryLevel: number | null
}

import { requireNativeModule } from 'expo-modules-core'
const DeviceInfoModule = requireNativeModule('DeviceInfo')

export async function getDeviceInfo(): Promise<DeviceInfo> {
  return await DeviceInfoModule.getDeviceInfo()
}
```

**要点**：电池电量在模拟器上可能返回 null，类型应标注 `number | null`。

### 练习二

**思路**：Native 层监听电量变化，低于阈值时发射事件。

**答案**：

```swift
// iOS
OnStartObserving {
  Timer.scheduledTimer(withTimeInterval: 60, repeats: true) { [weak self] _ in
    let level = UIDevice.current.batteryLevel
    if level >= 0 && level < 0.2 {
      self?.sendEvent("onLowBattery", ["level": Double(level)])
    }
  }
}
```

```typescript
// 使用侧
useEffect(() => {
  const subscription = addBatteryListener((info) => {
    if (info.level < 0.2 && !info.isCharging) {
      Alert.alert('电量不足', `当前 ${Math.round(info.level * 100)}%`)
    }
  })
  return () => subscription.remove()
}, [])
```

**要点**：iOS 模拟器电量始终为 -1，需真机测试。Timer 间隔 60 秒足够。
