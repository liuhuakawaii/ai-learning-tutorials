## 监控告警配置

```typescript
// services/ReleaseMonitor.ts
import * as Sentry from '@sentry/react-native';

export class ReleaseMonitor {
  static recordRelease(version: string, buildNumber: string): void {
    Sentry.setTag('app_version', version);
    Sentry.setTag('build_number', buildNumber);
  }

  static checkCrashThreshold(
    crashCount: number,
    userCount: number,
    threshold = 0.01
  ): { healthy: boolean; crashRate: number } {
    const crashRate = userCount > 0 ? crashCount / userCount : 0;
    return { healthy: crashRate < threshold, crashRate };
  }
}
```

告警规则：

1. **崩溃率异常**：崩溃用户比例 > 1% → Slack + 邮件
2. **新错误激增**：15 分钟内 > 10 个新错误 → Slack
3. **API 错误率**：5 分钟内 > 5% → Slack
4. **启动时间退化**：P95 > 3 秒 → Slack

## 用户反馈处理

```typescript
// utils/feedbackPrioritizer.ts
type Priority = 'P0' | 'P1' | 'P2' | 'P3';

interface Analysis {
  priority: Priority;
  category: string;
  action: string;
}

export function analyzeFeedback(message: string): Analysis {
  const msg = message.toLowerCase();

  if (msg.includes('闪退') || msg.includes('崩溃') || msg.includes('打不开')) {
    return { priority: 'P0', category: 'crash', action: '立即排查崩溃日志，必要时回滚' };
  }
  if (msg.includes('无法登录') || msg.includes('支付失败') || msg.includes('数据丢失')) {
    return { priority: 'P1', category: 'core_function', action: '24 小时内修复并发布热更新' };
  }
  if (msg.includes('卡顿') || msg.includes('慢') || msg.includes('不好用')) {
    return { priority: 'P2', category: 'ux', action: '纳入下一版本优化计划' };
  }
  return { priority: 'P3', category: 'feature_request', action: '记录到需求池' };
}
```

发布 Checklist 分三个阶段：发版前（功能冻结、回归测试、性能基准）、发布中（构建、提交审核、配置灰度）、发布后（监控崩溃率、收集反馈、扩大比例）。每个任务指定负责人。

## 常见误区

1. **发布前不做回归测试**：新功能可能影响已有功能
2. **一次性全量发布**：没有灰度，问题影响所有用户
3. **忽略发布后监控**：发布不是终点，监控至少持续 7 天
4. **截图和描述过时**：应用更新后元数据也要同步
5. **版本号不规范**：随意的版本号让问题追溯困难
6. **没有回滚预案**：出问题时不知如何快速回滚

## 工程建议

1. **建立发布 SOP 文档**：标准化流程减少人为失误
2. **使用 CI/CD 自动化**：减少手动操作
3. **设置发布冻结期**：大版本发布前一周冻结新功能
4. **维护 CHANGELOG**：记录每个版本变更
5. **跨团队协同**：发布需要产品、设计、开发配合

### 练习二

```typescript
// scripts/release.ts
import { execSync } from 'child_process';
import fs from 'fs';
import path from 'path';

const appJsonPath = path.resolve(__dirname, '../app.json');

function run(cmd: string): string {
  console.log(`▶ ${cmd}`);
  return execSync(cmd, { encoding: 'utf-8', stdio: 'pipe' }).trim();
}

function fail(msg: string): never {
  console.error(`\n❌ ${msg}`);
  process.exit(1);
}

async function release(): Promise<void> {
  console.log('🚀 开始发布准备...\n');

  // 1. 检查工作区
  if (run('git status --porcelain')) fail('工作区不干净，请先提交');

  // 2. 运行测试
  try { run('npm test'); console.log('✅ 测试通过'); }
  catch { fail('测试失败'); }

  // 3. 运行 lint
  try { run('npm run lint'); console.log('✅ Lint 通过'); }
  catch { fail('Lint 失败'); }

  // 4. 检查环境变量
  for (const v of ['SENTRY_AUTH_TOKEN', 'EXPO_PUBLIC_API_URL']) {
    if (!process.env[v]) fail(`缺少环境变量: ${v}`);
  }

  // 5. 更新版本号
  const type = process.argv[2] || 'patch';
  if (!['major', 'minor', 'patch'].includes(type)) {
    fail('用法: npx ts-node release.ts <major|minor|patch>');
  }
  const appJson = JSON.parse(fs.readFileSync(appJsonPath, 'utf-8'));
  const parts = appJson.expo.version.split('.').map(Number);
  switch (type) {
    case 'major': parts[0]++; parts[1] = 0; parts[2] = 0; break;
    case 'minor': parts[1]++; parts[2] = 0; break;
    case 'patch': parts[2]++; break;
  }
  const newVersion = parts.join('.');
  appJson.expo.version = newVersion;
  fs.writeFileSync(appJsonPath, JSON.stringify(appJson, null, 2) + '\n');
  console.log(`✅ 版本: → ${newVersion}`);

  // 6. 更新 CHANGELOG
  const date = new Date().toISOString().split('T')[0];
  const clPath = path.resolve(__dirname, '../CHANGELOG.md');
  const entry = `\n## [${newVersion}] - ${date}\n\n- \n`;
  if (fs.existsSync(clPath)) {
    const existing = fs.readFileSync(clPath, 'utf-8');
    fs.writeFileSync(clPath, `# Changelog\n${entry}\n${existing.replace('# Changelog\n', '')}`);
  } else {
    fs.writeFileSync(clPath, `# Changelog\n${entry}`);
  }
  console.log('✅ CHANGELOG 已更新');

  console.log(`\n🎉 准备完成！版本 ${newVersion}`);
  console.log('请编辑 CHANGELOG.md 后提交并构建');
}

release().catch(console.error);
```

**要点**：每步失败立即中断；版本号自动递增；CHANGELOG 模板自动添加。
