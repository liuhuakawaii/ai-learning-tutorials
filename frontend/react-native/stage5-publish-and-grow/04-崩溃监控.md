# 崩溃监控

## 场景引入

应用上线后用户反馈「打开就闪退」，但你没有错误日志、不知道影响多少用户、不知道从哪个版本开始。这种被动等反馈的模式让你每次发版都焦虑。Sentry 是 React Native 生态中最成熟的崩溃监控平台，能自动捕获崩溃、记录堆栈、追踪受影响用户，支持 Source Map 还原混淆代码。

## 学习目标

1. 集成 Sentry 并完成基础配置
2. 上传 Source Map 还原混淆堆栈
3. 分析和分类崩溃报告
4. 配置性能监控和告警规则

### 初始化配置

```typescript
// config/sentry.ts
import * as Sentry from '@sentry/react-native';

export function initSentry(): void {
  Sentry.init({
    dsn: 'https://your-dsn@sentry.io/your-project-id',
    environment: __DEV__ ? 'development' : 'production',
    release: 'com.yourcompany.app@1.2.0+45',
    dist: '45',
    tracesSampleRate: 0.5,
    enabled: !__DEV__,
    beforeSend(event) {
      if (__DEV__) return null;
      if (event.exception?.values?.[0]?.type === 'NetworkError') return null;
      return event;
    },
    integrations: [
      new Sentry.ReactNativeTracing({
        routingInstrumentation: new Sentry.ReactNavigationInstrumentation(),
        traceFetch: true,
        traceXHR: true,
      }),
    ],
  });
}
```

### 手动上报

```typescript
// services/ErrorReporter.ts
import * as Sentry from '@sentry/react-native';

export class ErrorReporter {
  static captureError(error: Error, context?: Record<string, any>): void {
    Sentry.withScope((scope) => {
      if (context) Object.entries(context).forEach(([k, v]) => scope.setExtra(k, v));
      Sentry.captureException(error);
    });
  }
  static setUser(user: { id: string; email?: string }): void { Sentry.setUser(user); }
  static clearUser(): void { Sentry.setUser(null); }
  static addBreadcrumb(category: string, message: string): void {
    Sentry.addBreadcrumb({ category, message, level: 'info' });
  }
}
```

```typescript
// 使用示例：登录流程
import { ErrorReporter } from './ErrorReporter';

export async function login(email: string, password: string): Promise<User> {
  ErrorReporter.addBreadcrumb('auth', '用户尝试登录', { email });
  try {
    const { data } = await api.post('/auth/login', { email, password });
    ErrorReporter.setUser({ id: data.id, email: data.email });
    return data;
  } catch (error) {
    ErrorReporter.captureError(error as Error, { action: 'login', email });
    throw error;
  }
}
```

## 崩溃分析与分类

```typescript
// utils/errorClassifier.ts
import * as Sentry from '@sentry/react-native';

export enum ErrorCategory {
  CRASH = 'crash',
  UI_ERROR = 'ui_error',
  NETWORK_ERROR = 'network_error',
  BUSINESS_ERROR = 'business_error',
}

export function classifyError(error: Error): ErrorCategory {
  const msg = error.message.toLowerCase();
  if (msg.includes('network') || msg.includes('fetch')) return ErrorCategory.NETWORK_ERROR;
  if (error.stack?.toLowerCase().includes('render')) return ErrorCategory.UI_ERROR;
  return ErrorCategory.BUSINESS_ERROR;
}

export function reportClassifiedError(error: Error, category: ErrorCategory): void {
  Sentry.withScope((scope) => {
    scope.setTag('error_category', category);
    scope.setLevel(category === ErrorCategory.CRASH ? 'fatal' : 'error');
    Sentry.captureException(error);
  });
}
```

### 错误边界组件

```typescript
// components/ErrorBoundary.tsx
import { Component, ErrorInfo, ReactNode } from 'react';
import { View, Text, TouchableOpacity } from 'react-native';
import * as Sentry from '@sentry/react-native';

interface Props { children: ReactNode; }
interface State { hasError: boolean; error: Error | null; }

export class ErrorBoundary extends Component<Props, State> {
  state: State = { hasError: false, error: null };

  static getDerivedStateFromError(error: Error): State {
    return { hasError: true, error };
  }

  componentDidCatch(error: Error, info: ErrorInfo) {
    Sentry.withScope((scope) => {
      scope.setTag('error_boundary', true);
      scope.setExtra('component_stack', info.componentStack);
      Sentry.captureException(error);
    });
  }

  render() {
    if (this.state.hasError) {
      return (
        <View style={{ flex: 1, justifyContent: 'center', alignItems: 'center', padding: 24 }}>
          <Text style={{ fontSize: 20, fontWeight: 'bold', marginBottom: 12 }}>出现了一个错误</Text>
          <Text style={{ color: '#666', marginBottom: 24 }}>{this.state.error?.message}</Text>
          <TouchableOpacity onPress={() => this.setState({ hasError: false })}>
            <Text style={{ color: '#007AFF', fontWeight: '600' }}>重试</Text>
          </TouchableOpacity>
        </View>
      );
    }
    return this.props.children;
  }
}
```

## 性能监控（Transaction）

```typescript
// services/PerformanceMonitor.ts
import * as Sentry from '@sentry/react-native';

export class PerformanceMonitor {
  static startPageLoad(name: string): () => void {
    const tx = Sentry.startTransaction({ name, op: 'navigation' });
    Sentry.getCurrentHub().configureScope((s) => s.setSpan(tx));
    return () => tx.finish();
  }

  static async trackApiCall<T>(url: string, method: string, call: () => Promise<T>): Promise<T> {
    const tx = Sentry.getCurrentHub().getScope()?.getTransaction();
    const span = tx?.startChild({ op: 'http.client', description: `${method} ${url}` });
    try {
      const r = await call();
      span?.setStatus('ok');
      return r;
    } catch (e) { span?.setStatus('internal_error'); throw e; }
    finally { span?.finish(); }
  }
}
```

```typescript
// hooks/usePageTracking.ts
export function usePageTracking(name: string) {
  useEffect(() => {
    const finish = PerformanceMonitor.startPageLoad(name);
    return finish;
  }, [name]);
}
```

## 告警规则配置

在 Sentry Dashboard 中配置：

1. **崩溃率告警**：崩溃用户比例超过 1% 时触发
2. **新错误告警**：首次出现的新错误类型立即通知
3. **回归告警**：已修复的错误重新出现时触发
4. **性能告警**：页面加载时间超过阈值时触发

## 常见误区

1. **开发环境也开启 Sentry**：开发错误不应上报，会污染数据
2. **不上传 Source Map**：崩溃堆栈无法定位问题
3. **采样率设为 0**：完全不采集等于没有监控
4. **忽略面包屑配置**：面包屑是还原崩溃场景的关键
5. **不区分错误严重级别**：所有都标 fatal 导致告警疲劳
6. **不清理用户信息**：退出登录时必须清除 Sentry 用户数据

## 工程建议

1. **使用 `Sentry.wrap()` 包裹根组件**：捕获渲染异常
2. **为 Error Boundary 设置标签**：按页面维度分析崩溃
3. **CI 中验证 Source Map 上传**：确保每次构建都上传
4. **设置合理告警阈值**：避免告警疲劳
5. **结合版本号追踪**：使用 release + dist 精确关联构建

本节课完成了 Sentry 崩溃监控的完整集成。核心要点：入口初始化并配置采样率，上传 Source Map 确保堆栈可读，ErrorBoundary 捕获渲染异常，PerformanceMonitor 追踪性能指标。
