# 阶段实战：在线视频编辑器——排查视频处理性能问题

## 现象

你用 FFmpeg WASM 实现了一个在线视频编辑器，加载 30 秒的 1080p 视频后，应用卡死了 10 秒。Chrome DevTools 的 Performance 面板显示主线程被一个长任务阻塞了 8 秒。

这不是 bug——是架构问题。视频处理是 CPU 密集型操作，在主线程上执行必然卡死 UI。

## 排查过程

### 第一步：定位阻塞点

```javascript
// 用 Performance API 标记关键操作
performance.mark('ffmpeg-load-start')
await ffmpeg.load()
performance.mark('ffmpeg-load-end')
performance.measure('ffmpeg-load', 'ffmpeg-load-start', 'ffmpeg-load-end')

// 输出：ffmpeg-load: 3200ms
// 问题：加载 WASM 二进制文件 + 初始化
```

### 第二步：分析内存占用

```javascript
// 1080p 视频的原始帧数据
const frameSize = 1920 * 1080 * 4 // RGBA
console.log(`单帧: ${(frameSize / 1024 / 1024).toFixed(2)} MB`) // 7.91 MB
console.log(`30秒@30fps: ${(frameSize * 30 * 30 / 1024 / 1024).toFixed(2)} MB`) // 7119 MB

// 问题：把所有帧解码到内存中会直接 OOM
```

### 第三步：确认解决方案

```
问题 1：WASM 加载慢
  → 预加载 + 缓存（Service Worker Cache API）

问题 2：处理阻塞主线程
  → Web Worker 中运行 FFmpeg

问题 3：全帧解码 OOM
  → 流式处理，逐帧处理后立即释放
```

## 优化后的架构

```javascript
// worker.js - 在 Web Worker 中运行 FFmpeg
import { createFFmpeg } from '@ffmpeg/ffmpeg'

const ffmpeg = createFFmpeg({ log: true })

self.onmessage = async (e) => {
  const { type, data } = e.data

  switch (type) {
    case 'init':
      await ffmpeg.load()
      self.postMessage({ type: 'ready' })
      break

    case 'trim':
      // 流式处理：不加载全部帧到内存
      ffmpeg.FS('writeFile', 'input.mp4', data.input)
      await ffmpeg.run(
        '-i', 'input.mp4',
        '-ss', String(data.start),
        '-to', String(data.end),
        '-c', 'copy', // 不重新编码，直接复制
        'output.mp4'
      )
      const output = ffmpeg.FS('readFile', 'output.mp4')
      self.postMessage({ type: 'result', data: output })
      ffmpeg.FS('unlink', 'input.mp4')
      ffmpeg.FS('unlink', 'output.mp4')
      break
  }
}
```

```javascript
// main.js - 主线程
const worker = new Worker(new URL('./worker.js', import.meta.url), { type: 'module' })

worker.onmessage = (e) => {
  switch (e.data.type) {
    case 'ready':
      console.log('FFmpeg 就绪')
      break
    case 'result':
      const blob = new Blob([e.data.data], { type: 'video/mp4' })
      showResult(blob)
      break
    case 'progress':
      updateProgress(e.data.progress)
      break
  }
}

// 预加载
worker.postMessage({ type: 'init' })
```

## 性能优化技巧

### 1. 不重新编码

如果只是裁剪视频片段，用 `-c copy` 直接复制编码数据，速度极快：

```javascript
// 不重新编码（毫秒级）
await ffmpeg.run('-i', 'input.mp4', '-ss', '10', '-to', '20', '-c', 'copy', 'out.mp4')

// 重新编码（秒级）
await ffmpeg.run('-i', 'input.mp4', '-ss', '10', '-to', '20', '-c:v', 'libx264', 'out.mp4')
```

### 2. 降低预览分辨率

编辑预览不需要全分辨率：

```javascript
// 生成低分辨率预览
await ffmpeg.run(
  '-i', 'input.mp4',
  '-vf', 'scale=480:270', // 缩放到 480p
  '-r', '15',              // 降到 15fps
  'preview.mp4'
)
```

### 3. 分段处理大文件

```javascript
async function processInChunks(inputData, chunkDuration = 10) {
  const totalDuration = await getVideoDuration(inputData)
  const chunks = Math.ceil(totalDuration / chunkDuration)

  for (let i = 0; i < chunks; i++) {
    const start = i * chunkDuration
    const end = Math.min((i + 1) * chunkDuration, totalDuration)

    await ffmpeg.run(
      '-i', 'input.mp4',
      '-ss', String(start), '-to', String(end),
      '-c', 'copy',
      `chunk_${i}.mp4`
    )

    // 处理完一个 chunk 就发送进度
    self.postMessage({ type: 'progress', progress: (i + 1) / chunks })
  }
}
```

## 你可能踩的坑

**坑一：FFmpeg WASM 内存限制**

FFmpeg WASM 默认内存限制 256MB。处理大视频需要在初始化时指定更大的内存：

```javascript
const ffmpeg = createFFmpeg({
  log: true,
  corePath: '/ffmpeg-core.js',
  // 内存限制会在 wasm 初始化时设置
})
```

**坑二：不释放 FS 文件**

`ffmpeg.FS('writeFile', ...)` 写入的文件不会自动删除。处理完必须 `unlink`，否则内存持续增长。

**坑三：同步操作阻塞 Worker**

`ffmpeg.FS('readFile', ...)` 是同步的，对于大文件会阻塞 Worker。用完立即 `unlink`。

```javascript
async function convertToMP4(inputData) {

    data: {
      input: inputData,

      videoCodec: 'libx264',

// Worker 中处理
case 'convert':
  ffmpeg.FS('writeFile', 'input.webm', data.input)
  await ffmpeg.run(
    '-i', 'input.webm',
    '-c:v', data.videoCodec,
    '-preset', data.preset,
    '-c:a', data.audioCodec,
    'output.mp4'
  )
  break
```

### 练习二

```javascript
async function applyGrayscale(inputData) {
  ffmpeg.FS('writeFile', 'input.mp4', inputData)

  // 用 FFmpeg 的 colorchannelmixer 滤镜实现灰度
  await ffmpeg.run(
    '-i', 'input.mp4',
    '-vf', 'colorchannelmixer=.3:.4:.3:0:.3:.4:.3:0:.3:.4:.3:0',
    '-c:a', 'copy',
    'grayscale.mp4'
  )
}
```
