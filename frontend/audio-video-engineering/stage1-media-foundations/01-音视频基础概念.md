# 音视频基础概念：为什么你的 1080p 视频只有 200MB

## 现象

你打开一个 1080p 的视频文件，发现它只有 200MB。但算一下原始数据：

```
1920 × 1080 × 3 字节 × 30 帧 = 186 MB/秒
1 小时 = 670 GB
```

200MB 和 670GB 之间差了 3000 多倍。这个压缩是怎么做到的？理解这个过程，是所有音视频工程的起点。

## 编解码：有损压缩的原理

编码器的任务是用更少的数据表达"几乎相同"的信息。核心思路：**丢弃人眼不敏感的信息**。

```
原始数据 → [编码器] → 压缩文件 → [解码器] → 播放数据
```

关键区别：

```
无损压缩：解码后和原始数据完全一致
  典型：PNG、FLAC、ZIP
  压缩比：2:1 ~ 5:1
  场景：文本、代码、医学影像

有损压缩：解码后有差异，但人眼/人耳察觉不到
  典型：JPEG、MP3、H.264
  压缩比：10:1 ~ 100:1
  场景：音视频、图片
```

## 容器格式 ≠ 编码格式

这是初学者最常犯的错误。`.mp4` 只说明了**容器格式**，不说明视频用什么编码。

```
容器（MP4）
├── 视频轨道（H.264 / H.265 / AV1）
├── 音频轨道（AAC / Opus）
├── 字幕轨道
└── 元数据（时长、作者）
```

```javascript
// .mp4 文件可能用 H.264，也可能用 H.265
const video = document.createElement('video')
video.canPlayType('video/mp4; codecs="avc1.42E01E"') // H.264
video.canPlayType('video/mp4; codecs="hev1.1.6.L93.B0"') // H.265
```

同一个 MP4 文件可以装不同编码的视频流。判断实际编码要看 codec 信息，不能只看扩展名。

## 采样率与位深

声音是连续的模拟波形，计算机需要离散化：

```
采样率：每秒采集多少个样本
  8000 Hz  → 电话语音
  16000 Hz → 语音识别
  44100 Hz → CD 音质
  48000 Hz → 专业音频/视频

位深：每个样本的精度
  16 bit → 65536 个级别（CD 标准）
  24 bit → 1677 万个级别（录音棚）
```

根据奈奎斯特定理，采样率必须至少是信号最高频率的 2 倍。人耳上限 20kHz，所以 CD 标准是 44100Hz。

```javascript
// 计算音频文件大小
function calcAudioSize(sampleRate, bitDepth, channels, durationSec) {
  const bytes = sampleRate * (bitDepth / 8) * channels * durationSec
  return (bytes / 1024 / 1024).toFixed(2) + ' MB'
}

calcAudioSize(44100, 16, 2, 60)  // CD 1 分钟 ≈ 10.09 MB
calcAudioSize(8000, 16, 1, 60)   // 电话 1 分钟 ≈ 0.92 MB
```

## 帧率与码率

**帧率**：每秒画面数。24fps 有电影感，30fps 是网络视频标准，60fps 适合游戏和体育。

**码率**：每秒传输的数据量。码率越高画质越好，但存在边际递减效应：

```
质量 ↑
     │        ╭─────────── 趋于饱和
     │      ╭─╯
     │    ╭─╯
     │  ╭─╯
     │╭─╯
     ├──────────────────── 码率 →
```

720p 视频码率设到 50Mbps 不会比 5Mbps 有明显提升，因为画面信息量就那么多。

## CBR vs VBR

```
CBR（固定码率）：每秒数据量恒定
  优点：网络传输稳定
  缺点：简单场景浪费带宽，复杂场景质量不足

VBR（可变码率）：根据内容复杂度动态调整
  优点：质量更均匀，总体文件更小
  缺点：难以预测带宽需求
```

## Web 场景推荐参数

```javascript
const recommendations = {
  videoCall: {
    resolution: '720p', fps: 30,
    videoBitrate: '1-2 Mbps', audioBitrate: '64-128 kbps',
    codec: 'H.264', container: 'MP4 或 WebM'
  },
  videoOnDemand: {
    resolution: '1080p', fps: 30,
    videoBitrate: '4-8 Mbps', audioBitrate: '128-256 kbps',
    codec: 'H.264 (兼容) / H.265 (高效)', container: 'MP4'
  },
  voiceCall: {
    sampleRate: 16000, bitrate: '16-32 kbps',
    codec: 'Opus', container: 'WebM'
  }
}
```

Web 兼容性优先：MP4 + H.264 + AAC 是全平台兼容组合。

## 你大概率搞混的事

**容器格式 = 编码格式**：错。MP4 是容器，H.264 是编码，它们是独立的。

**码率越高画质越好**：存在上限。分辨率 > 编码器效率 > 码率设置，这个排序比"疯狂加码率"有用得多。

**帧率越高越好看**：60fps 比 30fps 流畅，但电影工业长期用 24fps 是因为轻微的运动模糊让画面更有质感。

### 练习一：计算文件大小

一段 CD 音质音频（44100Hz, 16bit, 立体声），时长 3 分 30 秒，计算未压缩原始数据大小（MB）。

### 练习二：浏览器编码检测

写一个函数，检测当前浏览器支持哪些视频编码组合（H.264、H.265、VP9、AV1），返回支持列表。

---

## 参考答案

### 练习一

```javascript
// 3分30秒 = 210秒
const bytes = 44100 * (16 / 8) * 2 * 210
const mb = bytes / 1024 / 1024
console.log(`${mb.toFixed(2)} MB`) // 约 35.28 MB
```

### 练习二

```javascript
function detectSupportedCodecs() {
  const video = document.createElement('video')
  const codecs = [
    { name: 'H.264', mime: 'video/mp4; codecs="avc1.42E01E"' },
    { name: 'H.265', mime: 'video/mp4; codecs="hev1.1.6.L93.B0"' },
    { name: 'VP9', mime: 'video/webm; codecs="vp9"' },
    { name: 'AV1', mime: 'video/mp4; codecs="av01.0.08M.08"' },
  ]

  return codecs.filter(c => {
    const support = video.canPlayType(c.mime)
    return support === 'probably' || support === 'maybe'
  }).map(c => c.name)
}
```
