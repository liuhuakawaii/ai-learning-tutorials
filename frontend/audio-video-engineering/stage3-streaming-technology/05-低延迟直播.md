# 第五课：低延迟直播

## 场景引入

在一场电商直播中，主播展示商品并喊出"3、2、1，上链接！"。如果延迟有 10 秒，观众看到的还是主播倒数之前的画面，等他们看到倒数时，商品可能已经被抢空了。

传统 HLS 直播的延迟在 10-30 秒，传统 RTMP 转 HLS 也有 3-6 秒。但对于互动直播（电商、拍卖、答题、连麦），延迟需要控制在 **1 秒以内**。

本课将学习 WebRTC、LL-HLS、QUIC 等低延迟技术方案，理解它们的原理和适用场景。

## 学习目标

完成本课学习后，你将能够：

1. 理解 WebRTC SFU 架构在直播中的应用
2. 掌握 LL-HLS（低延迟 HLS）的核心机制
3. 了解 QUIC/HTTP3 对视频传输的影响
4. 理解 WHEP/WHIP 协议的标准化意义
5. 根据业务场景选择合适的延迟方案

## 直播延迟的来源

要降低延迟，首先要理解延迟在哪里产生：

```
推流端延迟 ──→ 传输延迟 ──→ 服务端处理延迟 ──→ 分发延迟 ──→ 播放端延迟
   200ms        50-200ms      500-2000ms      100-500ms     500-2000ms

总延迟 = 1.5s ~ 5s（典型值）
```

| 延迟来源 | 原因 | 优化方向 |
|----------|------|----------|
| 推流端 | 编码缓冲、关键帧间隔 | 降低编码缓冲、缩小 GOP |
| 传输 | TCP 重传、网络抖动 | 使用 UDP（SRT/QUIC） |
| 服务端 | 转码缓冲、分片等待 | 减少分片时长 |
| 分发 | CDN 缓存、回源 | 边缘节点直推 |
| 播放端 | 分片缓冲、解码缓冲 | 减少播放缓冲 |

## WebRTC 直播

### WebRTC 为什么能低延迟

WebRTC 设计之初就是为了实时通信（视频通话），它使用 UDP 传输、内置拥塞控制、支持 NACK/FEC 丢包恢复，端到端延迟可以做到 **100-500ms**。

```
传统 HLS 直播：
推流端 ──RTMP──→ 服务器 ──HLS分片──→ CDN ──HTTP──→ 播放器
延迟：编码200ms + 传输100ms + 分片等待4000ms + CDN缓存2000ms + 播放缓冲2000ms ≈ 8s

WebRTC 直播：
推流端 ──WebRTC──→ SFU ──WebRTC──→ 播放器
延迟：编码100ms + 传输50ms + SFU转发10ms + 传输50ms + 解码100ms ≈ 300ms
```

### SFU 架构

对于大规模直播，不使用 P2P 全连接（Mesh），而是使用 **SFU（Selective Forwarding Unit）** 架构：

```
推流端（1路）
    │
    ↓
┌─────────────┐
│    SFU      │ ← 选择性转发，不做转码
│  ┌───────┐  │
│  │Router │  │
│  └───┬───┘  │
│      │      │
│  ┌───┼───┐  │
│  ↓   ↓   ↓  │
│ 观众1 观众2 观众3 │
└─────────────┘
```

SFU 只负责转发媒体包，不做编解码，所以：

- CPU 消耗低，单台服务器可支持数百路观看
- 延迟低，只增加一跳转发延迟（约 10ms）
- 可以对不同观众发送不同质量的流

### 使用 mediasoup 搭建 SFU

```javascript
const mediasoup = require('mediasoup');
const express = require('express');
const http = require('http');
const { Server } = require('socket.io');

const app = express();
const server = http.createServer(app);
const io = new Server(server, { cors: { origin: '*' } });

let worker;
let router;
let producerTransport;
let producer;

async function startMediasoup() {
  worker = await mediasoup.createWorker({
    rtcMinPort: 10000,
    rtcMaxPort: 10100,
  });

  worker.on('died', () => {
    console.error('mediasoup worker 异常退出，5秒后重启...');
    setTimeout(() => process.exit(1), 5000);
  });

  router = await worker.createRouter({
    mediaCodecs: [
      {
        kind: 'video',
        mimeType: 'video/VP8',
        clockRate: 90000,
        parameters: {},
      },
      {
        kind: 'video',
        mimeType: 'video/H264',
        clockRate: 90000,
        parameters: {
          'packetization-mode': 1,
          'profile-level-id': '42e01f',
        },
      },
      {
        kind: 'audio',
        mimeType: 'audio/opus',
        clockRate: 48000,
        channels: 2,
      },
    ],
  });

  console.log('mediasoup worker 已启动');
}

io.on('connection', (socket) => {
  console.log('客户端连接:', socket.id);

  // 推流端：创建 Producer Transport
  socket.on('createProducerTransport', async (callback) => {
    producerTransport = await router.createWebRtcTransport({
      listenIps: [{ ip: '0.0.0.0', announcedIp: null }],
      enableUdp: true,
      enableTcp: true,
      preferUdp: true,
    });

    producerTransport.on('dtlsstatechange', (state) => {
      if (state === 'closed') producerTransport.close();
    });

    callback({
      id: producerTransport.id,
      iceParameters: producerTransport.iceParameters,
      iceCandidates: producerTransport.iceCandidates,
      dtlsParameters: producerTransport.dtlsParameters,
    });
  });

  // 推流端：连接 Transport 并开始推流
  socket.on('connectProducerTransport', async ({ dtlsParameters }, callback) => {
    await producerTransport.connect({ dtlsParameters });
    callback();
  });

  socket.on('produce', async ({ kind, rtpParameters }, callback) => {
    producer = await producerTransport.produce({ kind, rtpParameters });
    console.log(`推流开始: ${kind}, producer id: ${producer.id}`);

    producer.on('transportclose', () => {
      console.log('推流 Transport 关闭');
    });

    callback({ id: producer.id });
  });

  // 观众端：创建 Consumer Transport
  socket.on('createConsumerTransport', async (callback) => {
    const transport = await router.createWebRtcTransport({
      listenIps: [{ ip: '0.0.0.0', announcedIp: null }],
      enableUdp: true,
      enableTcp: true,
      preferUdp: true,
    });

    // 保存到 socket 上，后续使用
    socket.consumerTransport = transport;

    transport.on('dtlsstatechange', (state) => {
      if (state === 'closed') transport.close();
    });

    callback({
      id: transport.id,
      iceParameters: transport.iceParameters,
      iceCandidates: transport.iceCandidates,
      dtlsParameters: transport.dtlsParameters,
    });
  });

  // 观众端：连接并消费
  socket.on('connectConsumerTransport', async ({ dtlsParameters }, callback) => {
    await socket.consumerTransport.connect({ dtlsParameters });
    callback();
  });

  socket.on('consume', async ({ rtpCapabilities }, callback) => {
    if (!producer) {
      callback({ error: '没有可用的推流' });
      return;
    }

    if (!router.canConsume({ producerId: producer.id, rtpCapabilities })) {
      callback({ error: '不能消费此流' });
      return;
    }

    const consumer = await socket.consumerTransport.consume({
      producerId: producer.id,
      rtpCapabilities,
      paused: true,
    });

    consumer.on('transportclose', () => console.log('消费 Transport 关闭'));
    consumer.on('producerclose', () => console.log('推流已关闭'));

    socket.consumer = consumer;

    callback({
      id: consumer.id,
      producerId: producer.id,
      kind: consumer.kind,
      rtpParameters: consumer.rtpParameters,
    });
  });

  socket.on('resumeConsumer', async (callback) => {
    await socket.consumer.resume();
    callback();
  });
});

startMediasoup().then(() => {
  server.listen(3000, () => {
    console.log('信令服务器运行在 http://localhost:3000');
  });
});
```

## LL-HLS（低延迟 HLS）

### 原理

LL-HLS 是苹果在 HLS 基础上的低延迟扩展，通过以下机制将延迟从分片时长的 3 倍降低到 2-4 秒：

1. **Partial Segments（部分分片）**：将一个完整分片（6 秒）切分为多个部分分片（0.5 秒），播放器可以逐个请求
2. **Preload Hints（预加载提示）**：服务端告知播放器下一个将要生成的部分分片 URL
3. **Blocking Playlist Reload**：播放器请求播放列表时，服务端阻塞响应直到有新内容

```
传统 HLS（6 秒分片）：
分片: [====6s====] [====6s====] [====6s====]
延迟: 至少 3 × 6 = 18 秒

LL-HLS（6 秒分片，0.5 秒部分分片）：
分片: [===6s===]
部分: [0.5][0.5][0.5][0.5][0.5][0.5][0.5][0.5][0.5][0.5][0.5][0.5]
播放器: ↓ 开始播放（下载完第 2 个部分分片即可）
延迟: ≈ 1-2 秒
```

### LL-HLS 播放列表

```m3u8
#EXTM3U
#EXT-X-VERSION:6
#EXT-X-TARGETDURATION:6
#EXT-X-SERVER-CONTROL:CAN-BLOCK-RELOAD=YES,CAN-SKIP-UNTIL=12
#EXT-X-PART-INF:PART-TARGET=0.5
#EXT-X-MEDIA-SEQUENCE:26

#EXTINF:6.0,
segment_26.ts

#EXTINF:6.0,
segment_27.ts

#EXT-X-PART:DURATION=0.5,URI="segment_28.1.ts"
#EXT-X-PART:DURATION=0.5,URI="segment_28.2.ts"
#EXT-X-PART:DURATION=0.5,URI="segment_28.3.ts"
#EXT-X-PART:DURATION=0.5,URI="segment_28.4.ts",INDEPENDENT=YES

#EXT-X-PRELOAD-HINT:TYPE=PART,URI="segment_28.5.ts"
```

关键标签：

| 标签 | 作用 |
|------|------|
| `#EXT-X-PART` | 定义部分分片 |
| `INDEPENDENT` | 标记可以从该部分开始独立解码 |
| `#EXT-X-PRELOAD-HINT` | 提示播放器预加载下一个部分分片 |
| `CAN-BLOCK-RELOAD` | 允许阻塞式播放列表请求 |
| `PART-TARGET` | 部分分片的目标时长 |

## QUIC/HTTP3

### QUIC 对视频传输的影响

**QUIC** 是基于 UDP 的传输协议，是 HTTP/3 的基础。它解决了 TCP 的几个关键问题：

| TCP 问题 | QUIC 解决方案 |
|----------|--------------|
| 队头阻塞 | 多路复用，流之间互不影响 |
| 握手延迟 | 0-RTT 连接建立 |
| 连接迁移 | 基于 Connection ID，IP 变化不断连 |
| 拥塞控制 | 可插拔，支持 BBR 等新算法 |

```
TCP 队头阻塞问题：
流1: [包1] [包2] [包3丢失] [包4] ← 包4必须等包3重传
流2: [包1] [包2] [包3]          ← 也被阻塞

QUIC 解决：
流1: [包1] [包2] [包3丢失] [包4] ← 包4 独立到达
流2: [包1] [包2] [包3]          ← 不受影响
```

### HTTP/3 与分片加载

```javascript
// 浏览器自动使用 HTTP/3（如果服务器支持）
// 不需要修改代码，只需要服务器开启 HTTP/3

// 检测当前连接是否使用了 HTTP/3
async function checkHTTP3(url) {
  const response = await fetch(url);
  // 在浏览器中无法直接获取协议版本
  // 但可以通过 Performance API 间接判断
  const entries = performance.getEntriesByName(url);
  if (entries.length > 0) {
    const entry = entries[0];
    // nextHopProtocol 在 HTTP/3 时为 "h3"
    console.log('协议:', entry.nextHopProtocol);
    return entry.nextHopProtocol === 'h3';
  }
  return false;
}
```

## WHEP/WHIP 协议

### 标准化的意义

WebRTC 虽然能低延迟传输，但缺乏标准化的信令协议。**WHEP（WebRTC-HTTP Egress Protocol）** 和 **WHIP（WebRTC-HTTP Ingestion Protocol）** 解决了这个问题：

| 协议 | 方向 | 用途 |
|------|------|------|
| WHIP | 推流端 → 服务器 | WebRTC 推流信令 |
| WHEP | 服务器 → 播放端 | WebRTC 播放信令 |

```
WHIP 推流流程：
推流端                          服务器
  │── POST /whip (SDP Offer) ──→│
  │←── 201 (SDP Answer) ────────│
  │                              │
  │   ICE 连接建立                │
  │   开始推流                    │

WHEP 播放流程：
播放端                          服务器
  │── POST /whep (SDP Offer) ──→│
  │←── 201 (SDP Answer) ────────│
  │                              │
  │   ICE 连接建立                │
  │   开始播放                    │
```

### WHIP 推流实现

```javascript
class WHIPPusher {
  constructor(whipEndpoint) {
    this.endpoint = whipEndpoint;
    this.peerConnection = null;
  }

  async startPush(mediaStream) {
    this.peerConnection = new RTCPeerConnection({
      iceServers: [{ urls: 'stun:stun.l.google.com:19302' }],
    });

    // 添加媒体轨道
    mediaStream.getTracks().forEach(track => {
      this.peerConnection.addTrack(track, mediaStream);
    });

    // 创建 Offer
    const offer = await this.peerConnection.createOffer();
    await this.peerConnection.setLocalDescription(offer);

    // 等待 ICE 候选收集完成
    await this.waitForICEGathering();

    // 发送 WHIP 请求
    const response = await fetch(this.endpoint, {
      method: 'POST',
      headers: { 'Content-Type': 'application/sdp' },
      body: this.peerConnection.localDescription.sdp,
    });

    if (!response.ok) {
      throw new Error(`WHIP 请求失败: ${response.status}`);
    }

    // 设置服务器的 SDP Answer
    const answerSdp = await response.text();
    await this.peerConnection.setRemoteDescription({
      type: 'answer',
      sdp: answerSdp,
    });

    console.log('WHIP 推流已建立');
  }

  waitForICEGathering() {
    return new Promise((resolve) => {
      if (this.peerConnection.iceGatheringState === 'complete') {
        resolve();
      } else {
        this.peerConnection.onicegatheringstatechange = () => {
          if (this.peerConnection.iceGatheringState === 'complete') {
            resolve();
          }
        };
      }
    });
  }

  stop() {
    if (this.peerConnection) {
      this.peerConnection.close();
      this.peerConnection = null;
    }
  }
}

// 使用
const pusher = new WHIPPusher('https://live.example.com/whip/stream-key');
const stream = await navigator.mediaDevices.getUserMedia({ video: true, audio: true });
await pusher.startPush(stream);
```

### WHEP 播放实现

```javascript
class WHEPPlayer {
  constructor(whepEndpoint, videoElement) {
    this.endpoint = whepEndpoint;
    this.video = videoElement;
    this.peerConnection = null;
  }

  async startPlayback() {
    this.peerConnection = new RTCPeerConnection({
      iceServers: [{ urls: 'stun:stun.l.google.com:19302' }],
    });

    // 接收媒体流
    this.peerConnection.ontrack = (event) => {
      this.video.srcObject = event.streams[0];
      this.video.play();
    };

    // 添加 transceiver 以接收音视频
    this.peerConnection.addTransceiver('video', { direction: 'recvonly' });
    this.peerConnection.addTransceiver('audio', { direction: 'recvonly' });

    // 创建 Offer
    const offer = await this.peerConnection.createOffer();
    await this.peerConnection.setLocalDescription(offer);

    await this.waitForICEGathering();

    // 发送 WHEP 请求
    const response = await fetch(this.endpoint, {
      method: 'POST',
      headers: { 'Content-Type': 'application/sdp' },
      body: this.peerConnection.localDescription.sdp,
    });

    if (!response.ok) {
      throw new Error(`WHEP 请求失败: ${response.status}`);
    }

    const answerSdp = await response.text();
    await this.peerConnection.setRemoteDescription({
      type: 'answer',
      sdp: answerSdp,
    });

    console.log('WHEP 播放已建立');
  }

  waitForICEGathering() {
    return new Promise((resolve) => {
      if (this.peerConnection.iceGatheringState === 'complete') {
        resolve();
      } else {
        this.peerConnection.onicegatheringstatechange = () => {
          if (this.peerConnection.iceGatheringState === 'complete') {
            resolve();
          }
        };
      }
    });
  }

  stop() {
    if (this.peerConnection) {
      this.peerConnection.close();
      this.peerConnection = null;
      this.video.srcObject = null;
    }
  }
}

// 使用
const player = new WHEPPlayer('https://live.example.com/whep/stream-key', videoElement);
await player.startPlayback();
```

## 延迟方案对比

| 方案 | 延迟 | 可靠性 | 规模 | 复杂度 | 适用场景 |
|------|------|--------|------|--------|----------|
| WebRTC (SFU) | 100-500ms | 中 | 中 | 高 | 互动直播、连麦、拍卖 |
| LL-HLS | 2-4s | 高 | 大 | 中 | 电商直播、赛事 |
| SRT | 0.5-2s | 高 | 中 | 中 | 专业推流、远程制作 |
| QUIC/HTTP3 | 1-3s | 高 | 大 | 中 | 通用直播（未来） |
| 传统 HLS | 6-30s | 高 | 极大 | 低 | 大型赛事、电视广播 |

## 常见误区

### 误区一：低延迟一定是更好的

低延迟意味着播放端缓冲更少，网络波动更容易导致卡顿。对于不需要实时互动的场景（如演唱会直播），适度延迟（5-10 秒）反而提供更稳定的观看体验。

### 误区二：WebRTC 只能用于小规模

通过 SFU 架构和级联（Cascading），WebRTC 可以支撑数万人同时观看。Twitch、Clubhouse 等平台已经证明了这一点。

### 误区三：LL-HLS 和传统 HLS 完全兼容

LL-HLS 需要服务端和客户端都支持。旧版播放器可能无法正确处理 Partial Segments 和 Preload Hints。需要提供回退方案。

### 误区四：0-RTT 没有安全风险

QUIC 的 0-RTT 存在重放攻击风险。对于敏感操作（如支付），不应使用 0-RTT。视频分片加载是幂等操作，可以安全使用。

## 工程建议

1. **根据场景选择延迟级别**：互动直播用 WebRTC（<1s），电商/赛事用 LL-HLS（2-4s），普通直播用 HLS（6-10s）
2. **WebRTC 需要 TURN 服务器**：NAT 穿透不是 100% 成功的，必须部署 TURN 作为后备
3. **LL-HLS 的分片时长不要低于 2 秒**：太短会增加请求开销和 CDN 压力
4. **监控关键延迟指标**：端到端延迟、首帧时间、卡顿率、码率切换频率
5. **提供回退方案**：WebRTC 失败时回退到 HLS，LL-HLS 不支持时回退到标准 HLS
6. **考虑边缘计算**：在 CDN 边缘节点部署 SFU，进一步降低传输延迟

## 小结

本课学习了多种低延迟直播技术：

- **WebRTC**：端到端 100-500ms 延迟，适合实时互动场景
- **LL-HLS**：通过 Partial Segments 和 Preload Hints 将 HLS 延迟降到 2-4 秒
- **QUIC/HTTP3**：解决 TCP 队头阻塞，支持 0-RTT 连接
- **WHEP/WHIP**：标准化 WebRTC 信令，降低集成复杂度
- **延迟 vs 可靠性**：延迟越低，对网络质量越敏感，需要根据场景权衡

```html
<!DOCTYPE html>
<html lang="zh">
<head>
  <meta charset="UTF-8">
  <title>WHEP 播放器</title>
  <style>
    body { background: #1a1a1a; display: flex; justify-content: center; align-items: center; height: 100vh; margin: 0; }
    video { max-width: 800px; border-radius: 8px; }
    #status { color: #0f0; font-family: monospace; text-align: center; margin-top: 10px; }
  </style>
</head>
<body>
  <div>
    <video id="video" autoplay muted playsinline></video>
    <div id="status">准备中...</div>
    <div style="text-align:center; margin-top:10px;">
      <input id="whepUrl" type="text" value="https://demo.example.com/whep/stream"
             style="width:400px; padding:5px;" placeholder="WHEP 端点 URL">
      <button id="playBtn" style="padding:5px 15px;">播放</button>
      <button id="stopBtn" style="padding:5px 15px;">停止</button>
    </div>
  </div>

  <script>
    const video = document.getElementById('video');
    const status = document.getElementById('status');
    const whepUrlInput = document.getElementById('whepUrl');
    const playBtn = document.getElementById('playBtn');
    const stopBtn = document.getElementById('stopBtn');

    let pc = null;

    async function startWHEP() {
      const whepUrl = whepUrlInput.value;
      if (!whepUrl) { status.textContent = '请输入 WHEP URL'; return; }

      status.textContent = '正在建立连接...';

      pc = new RTCPeerConnection({
        iceServers: [{ urls: 'stun:stun.l.google.com:19302' }],
      });

      pc.ontrack = (event) => {
        console.log('收到轨道:', event.track.kind);
        if (event.streams && event.streams[0]) {
          video.srcObject = event.streams[0];
        }
      };

      pc.oniceconnectionstatechange = () => {
        status.textContent = `ICE 状态: ${pc.iceConnectionState}`;
        if (pc.iceConnectionState === 'connected') {
          status.textContent = '已连接';
        } else if (pc.iceConnectionState === 'failed') {
          status.textContent = '连接失败';
        }
      };

      pc.addTransceiver('video', { direction: 'recvonly' });
      pc.addTransceiver('audio', { direction: 'recvonly' });

      const offer = await pc.createOffer();
      await pc.setLocalDescription(offer);

      // 等待 ICE 候选收集
      await new Promise((resolve) => {
        if (pc.iceGatheringState === 'complete') {
          resolve();
        } else {
          pc.onicegatheringstatechange = () => {
            if (pc.iceGatheringState === 'complete') resolve();
          };
          // 超时保护
          setTimeout(resolve, 3000);
        }
      });

      try {
        const response = await fetch(whepUrl, {
          method: 'POST',
          headers: { 'Content-Type': 'application/sdp' },
          body: pc.localDescription.sdp,
        });

        if (!response.ok) {
          throw new Error(`HTTP ${response.status}: ${await response.text()}`);
        }

        const answerSdp = await response.text();
        await pc.setRemoteDescription({ type: 'answer', sdp: answerSdp });

        status.textContent = 'WHEP 播放已建立';
      } catch (err) {
        status.textContent = `错误: ${err.message}`;
        console.error(err);
      }
    }

    function stopWHEP() {
      if (pc) {
        pc.close();
        pc = null;
      }
      video.srcObject = null;
      status.textContent = '已停止';
    }

    playBtn.addEventListener('click', startWHEP);
    stopBtn.addEventListener('click', stopWHEP);
  </script>
</body>
</html>
```

**要点**：
- `recvonly` transceiver 告诉服务器我们只接收不发送
- ICE 候选收集需要等待完成或超时后再发送 SDP Offer
- `playsinline` 和 `muted` 属性确保移动端不会自动全屏
- 必须处理 ICE 连接状态变化，给用户明确的反馈

### 练习二

**思路**：同时启动传统 HLS 和 LL-HLS 播放，在视频画面中放置一个同步的时钟，对比两个播放器显示时间与实际时间的差异。

**答案**：

```html
<!DOCTYPE html>
<html lang="zh">
<head>
  <meta charset="UTF-8">
  <title>延迟对比测试</title>
  <style>
    .container { display: flex; gap: 20px; padding: 20px; background: #1a1a1a; min-height: 100vh; }
    .player-box { flex: 1; }
    .player-box h3 { color: #fff; text-align: center; }
    .player-box video { width: 100%; }
    .latency { color: #0f0; font-family: monospace; text-align: center; font-size: 18px; }
    #clock { color: #ff0; font-family: monospace; text-align: center; font-size: 24px; margin: 10px 0; }
  </style>
</head>
<body>
  <div id="clock"></div>
  <div class="container">
    <div class="player-box">
      <h3>传统 HLS</h3>
      <video id="videoStandard" controls muted></video>
      <div class="latency" id="latencyStandard">延迟: --</div>
    </div>
    <div class="player-box">
      <h3>LL-HLS</h3>
      <video id="videoLowLatency" controls muted></video>
      <div class="latency" id="latencyLowLatency">延迟: --</div>
    </div>
  </div>

  <script src="https://cdn.jsdelivr.net/npm/hls.js@latest"></script>
  <script>
    const standardUrl = 'https://example.com/live/standard.m3u8';
    const llhlsUrl = 'https://example.com/live/llhls.m3u8';

    // 更新时钟
    setInterval(() => {
      document.getElementById('clock').textContent = new Date().toISOString();
    }, 100);

    function initPlayer(videoId, url, latencyId, lowLatencyMode) {
      const video = document.getElementById(videoId);
      const latencyDisplay = document.getElementById(latencyId);

      if (Hls.isSupported()) {
        const hls = new Hls({
          lowLatencyMode: lowLatencyMode,
          maxBufferLength: lowLatencyMode ? 2 : 10,
          backBufferLength: 30,
        });

        hls.loadSource(url);
        hls.attachMedia(video);

        hls.on(Hls.Events.MANIFEST_PARSED, () => {
          video.play().catch(() => {});
        });

        // 定期计算延迟
        setInterval(() => {
          if (video.buffered.length > 0) {
            const liveEdge = hls.liveSyncPosition || video.buffered.end(video.buffered.length - 1);
            const latency = liveEdge - video.currentTime;
            latencyDisplay.textContent = `延迟: ${latency.toFixed(1)}s`;
          }
        }, 500);
      }
    }

    initPlayer('videoStandard', standardUrl, 'latencyStandard', false);
    initPlayer('videoLowLatency', llhlsUrl, 'latencyLowLatency', true);
  </script>
</body>
</html>
```

**要点**：
- `hls.liveSyncPosition` 是直播边缘位置，减去 `currentTime` 即为当前延迟
- 两个播放器使用相同的 hls.js 版本，唯一变量是 `lowLatencyMode`
- `maxBufferLength` 在低延迟模式下设更小的值，减少缓冲带来的额外延迟
