# 阶段实战：直播平台搭建——排查推流延迟问题

## 现象

你搭建了一个直播平台，从 OBS 推流到服务器，浏览器端观看。延迟测试显示从主播说话到观众听到有 5-8 秒的延迟。老板要求降到 3 秒以内。

## 排查过程

### 第一步：分析延迟来源

```
直播延迟 = 编码延迟 + 推流延迟 + 服务器处理 + 分发延迟 + 播放器缓冲

典型值：
  编码延迟：200-500ms（取决于编码器配置）
  推流延迟：100-300ms（RTMP）
  服务器处理：100-200ms（转码、切片）
  分发延迟：200-500ms（CDN）
  播放器缓冲：3000-8000ms（HLS 默认缓冲 3 个片段）
```

播放器缓冲是最大的延迟来源。HLS 默认缓冲 3 个 6 秒的片段 = 18 秒。即使用 2 秒片段，也有 6 秒缓冲。

### 第二步：优化片段时长

```javascript
// FFmpeg 生成 HLS 时设置更短的片段
await ffmpeg.run(
  '-i', 'input.mp4',
  '-c:v', 'libx264',
  '-preset', 'ultrafast',  // 编码速度优先
  '-g', '60',              // GOP 大小 = 60 帧（2秒@30fps）
  '-hls_time', '2',        // 每个片段 2 秒
  '-hls_list_size', '5',   // 播放列表保留 5 个片段
  '-hls_flags', 'delete_segments+append_list',
  'stream.m3u8'
)
```

### 第三步：降低编码延迟

```javascript
// OBS 推流设置优化
const encoderSettings = {
  // x264 编码器参数
  x264Params: [
    'tune=zerolatency',    // 零延迟调优
    'preset=veryfast',     // 编码速度优先
    'keyint=60',           // 每 2 秒一个关键帧
    'min-keyint=60',       // 强制固定 GOP
    'no-mbtree',           // 禁用宏块树（减少延迟）
  ]
}
```

### 第四步：播放器优化

```javascript
const hls = new Hls({
  maxBufferLength: 2,           // 最大缓冲 2 秒
  maxMaxBufferLength: 4,        // 绝对上限 4 秒
  liveSyncDurationCount: 2,     // 直播同步缓冲 2 个片段
  liveMaxLatencyDurationCount: 4, // 最大延迟 4 个片段
  lowLatencyMode: true,         // 低延迟模式
  enableWorker: true,           // 解码用 Worker
})
```

### 第五步：使用低延迟 HLS（LL-HLS）

```
标准 HLS：每个片段完成后才发布 → 片段时长就是最小延迟
LL-HLS：片段可以分多个 part 发布 → 延迟可以降到 2-3 秒

LL-HLS 的关键：
  #EXT-X-PART:DURATION=0.5,URI="part1.ts"
  #EXT-X-PART:DURATION=0.5,URI="part2.ts"
  #EXT-X-PRELOAD-HINT:TYPE=PART,URI="part3.ts"

  播放器可以在片段完成前就开始下载 part
```

## 优化后的完整方案

```
主播端：
  编码器：x264, preset=veryfast, tune=zerolatency
  GOP：2 秒（60 帧 @ 30fps）
  推流协议：RTMP

服务器：
  切片：2 秒/片段
  LL-HLS：0.5 秒/part
  CDN 分发：边缘节点缓存

播放端：
  hls.js 低延迟模式
  最大缓冲 4 秒
  目标延迟 3 秒

预期延迟：2-3 秒
```

## 你可能踩的坑

**坑一：GOP 大小和片段时长不一致**

GOP 大小必须是片段时长的整数倍。GOP=2秒，片段=2秒。如果 GOP=3秒，片段=2秒，每个片段边界可能不在关键帧上，导致无法独立解码。

**坑二：CDN 缓存了旧片段**

CDN 边缘节点可能缓存了旧的播放列表。设置 `Cache-Control: no-cache` 或用版本号参数。

**坑三：hls.js 的低延迟模式需要服务端配合**

LL-HLS 需要服务端支持 `EXT-X-PART`。普通的 HLS 服务器不能直接用。

## 练习

### 练习一：延迟测量工具

实现一个延迟测量工具：在主播端显示一个不断更新的时间戳，观众端读取视频中的时间戳并计算差值。

### 练习二：自适应码率

在直播播放器中实现自适应码率切换：当缓冲区低于 2 秒时自动降低画质，高于 5 秒时自动提升画质。

## 参考答案

### 练习一

```javascript
// 主播端：在视频上叠加时间戳
function overlayTimestamp(canvas, ctx) {
  const now = Date.now()
  ctx.clearRect(0, 0, canvas.width, canvas.height)
  ctx.font = '24px monospace'
  ctx.fillStyle = 'white'
  ctx.fillText(`T: ${now}`, 20, 40)
  requestAnimationFrame(() => overlayTimestamp(canvas, ctx))
}

// 观众端：OCR 识别时间戳或用数据通道
// 更简单：用 WebSocket 同步时间
```

### 练习二

```javascript
hls.on(Hls.Events.FRAG_BUFFERED, () => {
  const buffer = hls.bufferController?.bufferLen ?? 0
  if (buffer < 2 && hls.currentLevel > 0) {
    hls.currentLevel-- // 降低画质
  } else if (buffer > 5 && hls.currentLevel < hls.levels.length - 1) {
    hls.currentLevel++ // 提升画质
  }
})
```
