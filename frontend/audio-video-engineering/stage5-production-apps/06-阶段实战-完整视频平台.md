# 阶段实战：完整视频平台——端到端质量保障

## 现象

你搭建了一个完整的视频平台：上传、转码、分发、播放。上线后收到投诉：某些视频播放时卡顿严重，某些视频颜色偏绿，某些视频音画不同步。

这些问题的根源各不相同，需要端到端的质量保障体系。

## 质量保障体系

```
上传阶段：
  ✓ 文件格式校验
  ✓ 编码参数检查
  ✓ 完整性验证

转码阶段：
  ✓ 转码后质量对比（PSNR/VMAF）
  ✓ 多分辨率测试
  ✓ 编码错误检测

分发阶段：
  ✓ CDN 缓存命中率
  ✓ 首帧时间监控
  ✓ 卡顿率监控

播放阶段：
  ✓ 自适应码率切换频率
  ✓ 缓冲区健康度
  ✓ 错误恢复能力
```

async function validateUpload(file: File): Promise<{ valid: boolean; errors: string[] }> {
  const errors: string[] = []

  // 文件格式
  const allowedTypes = ['video/mp4', 'video/webm', 'video/quicktime']
  if (!allowedTypes.includes(file.type)) {
    errors.push(`不支持的格式: ${file.type}`)
  }

  // 文件大小（最大 4GB）
  if (file.size > 4 * 1024 * 1024 * 1024) {
    errors.push(`文件太大: ${(file.size / 1024 / 1024 / 1024).toFixed(2)}GB`)
  }

  // 用 FFmpeg 检查编码参数
  const ffmpeg = createFFmpeg()
  await ffmpeg.load()
  ffmpeg.FS('writeFile', 'input', new Uint8Array(await file.arrayBuffer()))
  await ffmpeg.run('-i', 'input', '-f', 'null', '-')

  // 从日志中解析信息
  // 检查是否能正常解码

  return { valid: errors.length === 0, errors }
}

## 转码质量对比

```typescript
async function qualityCheck(original: Uint8Array, transcoded: Uint8Array) {
  const ffmpeg = createFFmpeg()
  await ffmpeg.load()

  ffmpeg.FS('writeFile', 'orig.mp4', original)
  ffmpeg.FS('writeFile', 'trans.mp4', transcoded)

  // 计算 PSNR
  await ffmpeg.run(
    '-i', 'orig.mp4', '-i', 'trans.mp4',
    '-lavfi', 'psnr=stats_file=psnr.txt',
    '-f', 'null', '-'
  )

  const psnrLog = ffmpeg.FS('readFile', 'psnr.txt')
  const avgPSNR = parsePSNR(psnrLog.toString())

  // PSNR > 35dB 通常认为质量可接受
  return { psnr: avgPSNR, acceptable: avgPSNR > 35 }
}
```

## 播放质量监控

```typescript
class PlaybackQualityMonitor {
  private metrics = {
    firstFrameTime: 0,
    stallCount: 0,
    stallDuration: 0,
    bitrateSwitches: 0,
    errors: [] as string[]
  }

  constructor(private video: HTMLVideoElement, private hls: Hls) {
    this.setupListeners()
  }

  private setupListeners() {
    const startTime = performance.now()

    this.video.addEventListener('playing', () => {
      this.metrics.firstFrameTime = performance.now() - startTime
    }, { once: true })

    this.video.addEventListener('waiting', () => {
      this.metrics.stallCount++
      this._stallStart = performance.now()
    })

    this.video.addEventListener('playing', () => {
      if (this._stallStart) {
        this.metrics.stallDuration += performance.now() - this._stallStart
        this._stallStart = null
      }
    })

    this.hls.on(Hls.Events.LEVEL_SWITCHED, () => {
      this.metrics.bitrateSwitches++
    })

    this.hls.on(Hls.Events.ERROR, (event, data) => {
      this.metrics.errors.push(`${data.type}: ${data.details}`)
    })
  }

  getQualityScore(): number {
    // 综合评分：首帧时间、卡顿率、错误数
    let score = 100
    score -= Math.min(30, this.metrics.firstFrameTime / 100) // 首帧
    score -= this.metrics.stallCount * 10 // 卡顿
    score -= this.metrics.errors.length * 5 // 错误
    return Math.max(0, score)
  }
}
```

  const results = []

  // 测试 1：首帧时间
  const fft = await measureFirstFrame(videoUrl)
  results.push({ test: '首帧时间', value: fft, pass: fft < 2000 })

  const stallRate = await measureStallRate(videoUrl, 60) // 播放 60 秒

  // 测试 3：画质切换
  const switches = await measureBitrateSwitches(videoUrl, 60)
  results.push({ test: '画质切换次数', value: switches, pass: switches < 10 })

  // 测试 4：错误恢复
  const recovery = await testErrorRecovery(videoUrl)
  results.push({ test: '错误恢复时间', value: recovery, pass: recovery < 3000 })

  return results
}

## 你可能踩的坑

**坑一：只测好网络不测差网络**

好网络下一切正常，差网络下问题百出。必须测试 3G、丢包、高延迟等场景。

**坑二：不测边界情况**

空文件、超大文件、损坏文件、只有音频没有视频的文件——这些都要测。

**坑三：监控数据不上报**

本地监控只有开发时有用。生产环境需要把质量数据上报到监控系统，才能发现真实用户的问题。
