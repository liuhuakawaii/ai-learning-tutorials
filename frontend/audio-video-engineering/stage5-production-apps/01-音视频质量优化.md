# 音视频质量优化：用户投诉视频模糊，但码率已经很高了

## 现象

用户投诉你的视频平台"画质差"。你检查了编码参数：1080p、8Mbps 码率、H.264，参数看起来没问题。但用户在手机上用 4G 看的时候确实很模糊。

问题不在编码器——在端到端的质量链路。

## 质量链路分析

```
拍摄 → 编码 → 上传 → 转码 → 分发 → 解码 → 渲染
  │      │      │      │      │      │      │
  ↓      ↓      ↓      ↓      ↓      ↓      ↓
 传感器  压缩   网络   二次   CDN    播放器  屏幕
  质量   损耗   丢包   压缩   缓冲   策略   色域
```

每个环节都可能引入质量损失。逐个排查。

## 编码质量优化

### CRF vs CBR

```
CBR（固定码率）：
  码率恒定，简单场景浪费带宽，复杂场景质量不足

CRF（恒定质量因子）：
  保持视觉质量恒定，码率随内容变化
  CRF 值越低质量越高（0-51，推荐 18-23）
```

```bash
# CRF 编码
ffmpeg -i input.mp4 -c:v libx264 -crf 20 -preset medium output.mp4

# 双 pass VBR（质量更稳定）
ffmpeg -i input.mp4 -c:v libx264 -b:v 5M -pass 1 -f null -
ffmpeg -i input.mp4 -c:v libx264 -b:v 5M -pass 2 output.mp4
```

### 编码器选择

```
H.264：兼容性最好，所有浏览器支持
H.265：压缩效率高 30-50%，但 Safari 才支持
VP9：  Chrome/Firefox 支持，YouTube 默认用这个
AV1：  最新一代，压缩效率比 H.265 高 30%，但编码慢
```

```javascript
function selectBestCodec() {
  const video = document.createElement('video')
  if (video.canPlayType('video/mp4; codecs="av01.0.08M.08"')) return 'av1'
  if (video.canPlayType('video/webm; codecs="vp9"')) return 'vp9'
  if (video.canPlayType('video/mp4; codecs="hev1.1.6.L93.B0"')) return 'h265'
  return 'h264'
}
```

## 网络传输优化

### 自适应码率（ABR）

播放器根据网络状况动态切换画质：

```typescript
class ABROptimizer {
  private bandwidthHistory: number[] = []
  private bufferTarget = 30 // 目标缓冲 30 秒

  onSegmentDownloaded(bytes: number, durationMs: number) {
    const bandwidth = (bytes * 8) / (durationMs / 1000)
    this.bandwidthHistory.push(bandwidth)
    if (this.bandwidthHistory.length > 10) this.bandwidthHistory.shift()
  }

  getEstimatedBandwidth(): number {
    // 使用中位数，避免异常值影响
    const sorted = [...this.bandwidthHistory].sort((a, b) => a - b)
    return sorted[Math.floor(sorted.length / 2)] ?? 0
  }

  selectLevel(levels: { bandwidth: number }[]): number {
    const estimated = this.getEstimatedBandwidth()
    // 选择不超过估算带宽 80% 的最高画质
    const safe = estimated * 0.8
    for (let i = levels.length - 1; i >= 0; i--) {
      if (levels[i].bandwidth <= safe) return i
    }
    return 0
  }
}
```

## 你可能踩的坑

**坑一：转码二次压缩**

如果源视频已经是 H.264，再用 H.264 转码会引入二次压缩损失。用 `-c copy` 直接复制编码数据。

**坑二：缩放算法质量差**

FFmpeg 默认的缩放算法可能产生锯齿。用 `lanczos` 算法：

```bash
-vf "scale=1280:720:flags=lanczos"
```

**坑三：音频码率太低**

视频码率 5Mbps 但音频只有 64kbps，用户会觉得"声音很薄"。至少 128kbps AAC。

## 练习

测量并优化视频首帧时间（从用户点击播放到第一个画面出现的时间）。目标：500ms 以内。
