# 第一课：音视频质量优化

## 场景引入

Netflix 拥有数万部影视内容，每部内容的画面复杂度差异巨大——动画片色彩均匀、细节简单，而动作电影充满高速运动和复杂纹理。如果对所有内容使用相同的编码参数，简单内容会浪费带宽，复杂内容则会画质崩塌。

Netflix 的解决方案是 **Per-Title Encoding（按标题编码）**：为每部影片生成专属的编码阶梯（Encoding Ladder），确保在最低码率下达到最优画质。这套方案使 Netflix 在保持画质的同时，带宽成本降低了 20% 以上。

质量优化不是"码率拉满"那么简单。它是一个涉及编码参数、质量评估、自适应策略的系统工程。本课将深入讲解音视频质量优化的核心方法论。

## 学习目标

完成本课学习后，你将能够：

1. 理解编码阶梯的概念，设计自适应码率方案
2. 掌握画质增强技术的基本原理（超分、降噪、锐化）
3. 使用客观质量指标（PSNR、SSIM、VMAF）评估视频质量
4. 实施主观质量评估方案（MOS、AB 测试）
5. 通过编码参数调优在质量和码率之间找到最优平衡

## 码率自适应

### 编码阶梯

**编码阶梯（Encoding Ladder）** 是一组预定义的分辨率+码率组合，播放器根据网络带宽自动切换。一个典型的编码阶梯如下：

```javascript
const encodingLadder = [
  { resolution: '1920x1080', bitrate: 5800, fps: 30, label: '1080p 高画质' },
  { resolution: '1920x1080', bitrate: 4300, fps: 30, label: '1080p 中画质' },
  { resolution: '1280x720',  bitrate: 2800, fps: 30, label: '720p 高画质' },
  { resolution: '1280x720',  bitrate: 1800, fps: 30, label: '720p 中画质' },
  { resolution: '960x540',   bitrate: 1100, fps: 30, label: '540p' },
  { resolution: '768x432',   bitrate: 700,  fps: 30, label: '432p' },
  { resolution: '640x360',   bitrate: 400,  fps: 30, label: '360p' },
  { resolution: '480x270',   bitrate: 200,  fps: 30, label: '270p' },
];
```

传统做法是所有内容共用同一套编码阶梯，但不同内容的复杂度差异巨大。一段静态 PPT 演示在 1Mbps 下就能达到优秀画质，而一段高速运动的游戏画面可能需要 8Mbps 才能达到同样水平。

### Per-Title Encoding

Per-Title Encoding 的核心思想是：**根据内容复杂度动态生成编码阶梯**。

```javascript
// Per-Title Encoding 的简化流程
async function generateEncodingLadder(videoSource) {
  // 第一步：分析内容复杂度
  const complexity = await analyzeComplexity(videoSource);

  // 第二步：根据复杂度调整码率
  const ladder = [];

  const resolutionTiers = [
    { width: 1920, height: 1080, baseBitrate: 5800 },
    { width: 1280, height: 720,  baseBitrate: 2800 },
    { width: 960,  height: 540,  baseBitrate: 1100 },
    { width: 640,  height: 360,  baseBitrate: 400 },
  ];

  for (const tier of resolutionTiers) {
    // 复杂度系数：0.5（简单内容）~ 2.0（高复杂度）
    const complexityFactor = complexity.score / 50;

    // 简单内容降低码率，复杂内容提高码率
    const adjustedBitrate = Math.round(tier.baseBitrate * complexityFactor);

    // 设置码率上下限，避免极端值
    const clampedBitrate = Math.max(
      tier.baseBitrate * 0.5,
      Math.min(tier.baseBitrate * 2.5, adjustedBitrate)
    );

    ladder.push({
      width: tier.width,
      height: tier.height,
      bitrate: clampedBitrate,
      fps: 30
    });
  }

  return ladder;
}

// 分析视频复杂度（简化版）
async function analyzeComplexity(videoSource) {
  // 实际实现会采样关键帧，分析：
  // 1. 运动向量的幅度（运动剧烈程度）
  // 2. 纹理复杂度（边缘密度）
  // 3. 场景切换频率
  return {
    score: 65,           // 0-100 复杂度评分
    motionLevel: 'high', // 运动等级
    textureDensity: 0.7, // 纹理密度
    sceneChanges: 12     // 每分钟场景切换数
  };
}
```

### 按场景编码

更精细的优化是 **按场景（Per-Shot）编码**——同一部影片中，静态对话场景和高速追逐场景使用不同的码率：

```javascript
// 场景检测与分段编码
async function perShotEncoding(videoSource) {
  // 第一步：检测场景边界
  const shots = await detectSceneChanges(videoSource);

  // 第二步：为每个场景生成独立的编码参数
  const encodingPlan = shots.map((shot, index) => {
    const duration = shot.endTime - shot.startTime;
    const complexity = shot.complexityScore;

    return {
      startTime: shot.startTime,
      endTime: shot.endTime,
      duration,
      // 根据场景复杂度选择码率倍率
      bitrateMultiplier: complexity > 70 ? 1.5 : complexity < 30 ? 0.6 : 1.0,
    };
  });

  return encodingPlan;
}

// 场景切换检测
async function detectSceneChanges(videoSource) {
  // 通过比较相邻帧的直方图差异来检测场景切换
  // 差异超过阈值则认为发生了场景切换
  const threshold = 0.4; // 直方图差异阈值
  const scenes = [];

  // 实际实现会逐帧比较，这里简化展示
  scenes.push(
    { startTime: 0, endTime: 45, complexityScore: 30 },   // 静态对话
    { startTime: 45, endTime: 90, complexityScore: 85 },   // 动作场景
    { startTime: 90, endTime: 120, complexityScore: 20 },  // 缓慢过渡
  );

  return scenes;
}
```

## 画质增强

### 超分辨率

**超分辨率（Super-Resolution）** 是将低分辨率图像放大并补充细节的技术。在音视频领域，它用于将低码率视频在播放端进行实时增强。

```javascript
// 使用 Canvas 实现简单的双线性插值放大
function upscaleWithBilinear(sourceCanvas, targetWidth, targetHeight) {
  const targetCanvas = document.createElement('canvas');
  targetCanvas.width = targetWidth;
  targetCanvas.height = targetHeight;
  const ctx = targetCanvas.getContext('2d');

  // 启用高质量缩放
  ctx.imageSmoothingEnabled = true;
  ctx.imageSmoothingQuality = 'high';

  ctx.drawImage(sourceCanvas, 0, 0, targetWidth, targetHeight);
  return targetCanvas;
}

// 基于 WebGL 的锐化增强
function createSharpenFilter() {
  // 3x3 锐化卷积核
  return {
    kernel: [
       0, -1,  0,
      -1,  5, -1,
       0, -1,  0
    ],
    divisor: 1
  };
}

// 应用卷积滤镜
function applyConvolution(imageData, kernel) {
  const { width, height, data } = imageData;
  const output = new Uint8ClampedArray(data.length);

  for (let y = 1; y < height - 1; y++) {
    for (let x = 1; x < width - 1; x++) {
      for (let c = 0; c < 3; c++) {
        let sum = 0;
        for (let ky = -1; ky <= 1; ky++) {
          for (let kx = -1; kx <= 1; kx++) {
            const idx = ((y + ky) * width + (x + kx)) * 4 + c;
            sum += data[idx] * kernel[(ky + 1) * 3 + (kx + 1)];
          }
        }
        output[(y * width + x) * 4 + c] = Math.max(0, Math.min(255, sum));
      }
      output[(y * width + x) * 4 + 3] = 255; // Alpha
    }
  }

  return new ImageData(output, width, height);
}
```

### 降噪处理

视频降噪的目标是去除压缩伪影（Blocking Artifacts）和随机噪声，同时保留细节：

```javascript
// 简单的时域降噪：利用前后帧的相似性
class TemporalDenoiser {
  constructor(strength = 0.3) {
    this.strength = strength;
    this.prevFrame = null;
  }

  process(currentFrame) {
    if (!this.prevFrame) {
      this.prevFrame = new Uint8ClampedArray(currentFrame.data);
      return currentFrame;
    }

    const output = new Uint8ClampedArray(currentFrame.data.length);

    for (let i = 0; i < currentFrame.data.length; i += 4) {
      // 对 RGB 通道进行时域混合
      for (let c = 0; c < 3; c++) {
        const current = currentFrame.data[i + c];
        const prev = this.prevFrame[i + c];
        // 混合当前帧和前一帧，减少随机噪声
        output[i + c] = Math.round(current * (1 - this.strength) + prev * this.strength);
      }
      output[i + 3] = 255;
    }

    this.prevFrame.set(output);
    return new ImageData(output, currentFrame.width, currentFrame.height);
  }
}
```

## 客观质量指标

### PSNR（峰值信噪比）

PSNR 是最简单的质量指标，计算原始信号与压缩信号之间的最大可能信号功率与噪声功率的比值：

```javascript
// 计算两帧之间的 PSNR
function calculatePSNR(original, compressed) {
  if (original.length !== compressed.length) {
    throw new Error('帧尺寸不一致');
  }

  let mse = 0;
  for (let i = 0; i < original.length; i += 4) {
    for (let c = 0; c < 3; c++) {
      const diff = original[i + c] - compressed[i + c];
      mse += diff * diff;
    }
  }

  // MSE = 均方误差，像素总数 = length / 4（RGBA）
  const pixelCount = original.length / 4;
  mse /= (pixelCount * 3);

  if (mse === 0) return Infinity; // 完全相同

  // PSNR = 10 * log10(MAX^2 / MSE)，MAX = 255
  const psnr = 10 * Math.log10((255 * 255) / mse);
  return psnr;
}

// PSNR 参考值：
// > 40 dB: 优秀，几乎无损
// 30-40 dB: 良好，轻微可感知差异
// 20-30 dB: 较差，明显画质损失
// < 20 dB: 严重失真
```

### SSIM（结构相似性）

SSIM 比 PSNR 更接近人眼感知，它从亮度、对比度、结构三个维度评估相似性：

```javascript
// SSIM 计算（简化版，基于 8x8 块）
function calculateSSIMBlock(block1, block2) {
  const n = block1.length;

  // 计算均值
  const mean1 = block1.reduce((a, b) => a + b, 0) / n;
  const mean2 = block2.reduce((a, b) => a + b, 0) / n;

  // 计算方差和协方差
  let var1 = 0, var2 = 0, covar = 0;
  for (let i = 0; i < n; i++) {
    var1 += (block1[i] - mean1) ** 2;
    var2 += (block2[i] - mean2) ** 2;
    covar += (block1[i] - mean1) * (block2[i] - mean2);
  }
  var1 /= n;
  var2 /= n;
  covar /= n;

  // SSIM 常数（防止分母为零）
  const L = 255; // 像素值范围
  const k1 = 0.01, k2 = 0.03;
  const C1 = (k1 * L) ** 2;
  const C2 = (k2 * L) ** 2;

  // SSIM 公式
  const luminance = (2 * mean1 * mean2 + C1) / (mean1 ** 2 + mean2 ** 2 + C1);
  const contrast = (2 * Math.sqrt(var1) * Math.sqrt(var2) + C2) / (var1 + var2 + C2);
  const structure = (covar + C2 / 2) / (Math.sqrt(var1) * Math.sqrt(var2) + C2 / 2);

  return luminance * contrast * structure;
}

// SSIM 取值范围：-1 到 1
// > 0.95: 优秀
// 0.90-0.95: 良好
// 0.80-0.90: 一般
// < 0.80: 较差
```

## 主观质量评估

### MOS（Mean Opinion Score）

MOS 是最权威的质量评估方法，通过让真实用户打分来评估质量：

```javascript
// MOS 评分系统
class MOSEvaluator {
  constructor() {
    // 5 分制评分标准
    this.scale = [
      { score: 5, label: '优秀', description: '察觉不到失真' },
      { score: 4, label: '良好', description: '察觉到失真但不影响观看' },
      { score: 3, label: '一般', description: '轻微影响观看体验' },
      { score: 2, label: '较差', description: '影响观看体验' },
      { score: 1, label: '很差', description: '严重影响观看体验' }
    ];
  }

  // 收集评分
  collectRatings(samples) {
    const results = [];

    for (const sample of samples) {
      // 每个样本至少需要 15 名评估者
      if (sample.ratings.length < 15) {
        console.warn(`样本 ${sample.id} 评估者不足，需要至少 15 人`);
        continue;
      }

      // 去掉最高分和最低分后取平均
      const sorted = [...sample.ratings].sort((a, b) => a - b);
      const trimmed = sorted.slice(1, -1);
      const mos = trimmed.reduce((a, b) => a + b, 0) / trimmed.length;

      // 计算 95% 置信区间
      const stdDev = Math.sqrt(
        trimmed.reduce((sum, r) => sum + (r - mos) ** 2, 0) / trimmed.length
      );
      const confidenceInterval = 1.96 * stdDev / Math.sqrt(trimmed.length);

      results.push({
        sampleId: sample.id,
        mos: mos.toFixed(2),
        confidenceInterval: confidenceInterval.toFixed(3),
        ratingCount: sample.ratings.length
      });
    }

    return results;
  }
}
```

### AB 测试

AB 测试用于比较两种编码方案的优劣：

```javascript
// AB 测试框架
class QualityABTest {
  constructor(config) {
    this.config = config;
    this.results = [];
  }

  // 生成测试用例
  generateTestCases(sourceVideo) {
    const variants = [
      { id: 'A', encoder: 'x264', preset: 'medium', crf: 23 },
      { id: 'B', encoder: 'x264', preset: 'slow', crf: 20 },
      { id: 'C', encoder: 'x265', preset: 'medium', crf: 28 },
    ];

    return variants.map(v => ({
      ...v,
      sourceVideo,
      // 随机化展示顺序，消除顺序偏差
      displayOrder: Math.random()
    })).sort((a, b) => a.displayOrder - b.displayOrder);
  }

  // 分析结果
  analyze(results) {
    const votes = { A: 0, B: 0, C: 0, noPreference: 0 };

    for (const result of results) {
      votes[result.preferred]++;
    }

    const total = results.length;
    return {
      winner: Object.entries(votes).reduce((a, b) => a[1] > b[1] ? a : b)[0],
      distribution: Object.fromEntries(
        Object.entries(votes).map(([k, v]) => [k, `${((v / total) * 100).toFixed(1)}%`])
      ),
      sampleSize: total
    };
  }
}
```

### Two-Pass 编码

Two-Pass 编码分两遍扫描视频：第一遍分析内容复杂度，第二遍根据分析结果分配码率：

```javascript
// Two-Pass 编码的 FFmpeg 命令生成
function generateTwoPassCommand(inputFile, outputFile, targetBitrate) {
  const pass1 = [
    'ffmpeg', '-i', inputFile,
    '-c:v', 'libx264',
    '-preset', 'slow',
    '-b:v', `${targetBitrate}k`,
    '-pass', '1',
    '-an',                    // 第一遍不需要编码音频
    '-f', 'null',             // 输出到空设备
    '/dev/null'               // Unix
  ].join(' ');

  const pass2 = [
    'ffmpeg', '-i', inputFile,
    '-c:v', 'libx264',
    '-preset', 'slow',
    '-b:v', `${targetBitrate}k`,
    '-pass', '2',
    '-c:a', 'aac',
    '-b:a', '128k',
    outputFile
  ].join(' ');

  return { pass1, pass2 };
}

// CRF 模式 vs Two-Pass 模式
// CRF: 适合单次编码，质量恒定，文件大小不可预测
// Two-Pass: 适合目标文件大小固定的场景，码率分配更合理
```

## 常见误区

### 误区一：分辨率越高画质越好

分辨率只决定画面的像素数量，不决定每个像素的质量。一个 1080p 视频在 1Mbps 码率下，画质远不如 720p 在 2Mbps 码率下的效果。低码率下高分辨率会导致宏块效应严重，反而不如低分辨率的清晰画面。

### 误区二：PSNR 高就代表画质好

PSNR 只衡量像素级别的数值差异，不考虑人眼的感知特性。两个 PSNR 相同的视频，可能一个看起来清晰自然，另一个有明显的压缩伪影。VMAF 和 SSIM 更接近主观感受，应优先使用。

### 误区三：码率分配可以一视同仁

不同帧的编码复杂度差异很大。I 帧（关键帧）包含完整图像信息，需要的码率远高于 P 帧和 B 帧。如果对所有帧使用相同的码率，会导致关键帧模糊、预测帧浪费。合理的码率分配是编码器自动完成的，但理解这一机制有助于调优参数。

### 误区四：超分辨率可以替代高码率

超分辨率技术可以在一定程度上补充细节，但它无法创造原始信号中不存在的信息。低码率导致的压缩伪影会被超分算法放大。超分辨率是锦上添花，不是雪中送炭。

```javascript
  preset: 'faster',

  // 启用 CRF 限制码率波动
  rateControl: 'CRF-CBR',
  crfValue: 23
};
```

## 小结

本课深入讲解了音视频质量优化的核心方法论：

- **码率自适应**：通过 Per-Title Encoding 和 Per-Shot Encoding 为不同内容分配最优码率
- **画质增强**：超分辨率、降噪、锐化等后处理技术可以提升观感
- **客观质量指标**：PSNR 简单快速，SSIM 更接近感知，VMAF 最接近主观评价
- **主观质量评估**：MOS 是金标准，AB 测试适合方案对比
- **编码调优**：Preset 选择和 Two-Pass 编码是实用的优化手段

质量优化的核心原则是**用最少的码率达到目标画质**，而非追求最高的码率或分辨率。

### 练习一

**思路**：创建两个 Canvas 元素，分别绘制原始帧和压缩帧，通过 getImageData 获取像素数据后计算 PSNR。

**答案**：

```html
<!DOCTYPE html>
<html>
<head>
  <title>画质对比工具</title>
  <style>
    .compare-container { display: flex; gap: 10px; }
    canvas { border: 1px solid #ccc; }
    #psnr-display { font-size: 24px; margin: 10px 0; }
  </style>
</head>
<body>
  <div class="compare-container">
    <div>
      <h3>原始视频</h3>
      <canvas id="canvas-original" width="640" height="360"></canvas>
    </div>
    <div>
      <h3>压缩视频</h3>
      <canvas id="canvas-compressed" width="640" height="360"></canvas>
    </div>
  </div>
  <div id="psnr-display">PSNR: --</div>
  <video id="video-original" src="original.mp4" crossorigin="anonymous" style="display:none"></video>
  <video id="video-compressed" src="compressed.mp4" crossorigin="anonymous" style="display:none"></video>

  <script>
    const canvasOrig = document.getElementById('canvas-original');
    const canvasComp = document.getElementById('canvas-compressed');
    const ctxOrig = canvasOrig.getContext('2d');
    const ctxComp = canvasComp.getContext('2d');
    const psnrDisplay = document.getElementById('psnr-display');

    const videoOrig = document.getElementById('video-original');
    const videoComp = document.getElementById('video-compressed');

    function calculatePSNR(data1, data2) {
      let mse = 0;
      const pixelCount = data1.length / 4;
      for (let i = 0; i < data1.length; i += 4) {
        for (let c = 0; c < 3; c++) {
          const diff = data1[i + c] - data2[i + c];
          mse += diff * diff;
        }
      }
      mse /= (pixelCount * 3);
      if (mse === 0) return Infinity;
      return 10 * Math.log10((255 * 255) / mse);
    }

    function renderFrame() {
      ctxOrig.drawImage(videoOrig, 0, 0, 640, 360);
      ctxComp.drawImage(videoComp, 0, 0, 640, 360);

      const dataOrig = ctxOrig.getImageData(0, 0, 640, 360).data;
      const dataComp = ctxComp.getImageData(0, 0, 640, 360).data;
      const psnr = calculatePSNR(dataOrig, dataComp);

      psnrDisplay.textContent = `PSNR: ${psnr.toFixed(2)} dB`;
      requestAnimationFrame(renderFrame);
    }

    videoOrig.addEventListener('play', renderFrame);
    videoComp.addEventListener('play', () => videoOrig.play());
    videoComp.load();
  </script>
</body>
</html>
```

**要点**：
- 两个视频需要同步播放，使用 `requestAnimationFrame` 逐帧对比
- PSNR 计算只使用 RGB 通道，忽略 Alpha 通道
- 实际使用时需要处理跨域问题（CORS）

### 练习二

**思路**：使用 MSE API 创建多个码率的 SourceBuffer，通过 `MediaSource` 的事件监听网络状态，动态切换码率。

**答案**：

```javascript
class AdaptiveBitratePlayer {
  constructor(videoElement) {
    this.video = videoElement;
    this.mediaSource = new MediaSource();
    this.video.src = URL.createObjectURL(this.mediaSource);
    this.sourceBuffer = null;

    this.ladder = [
      { quality: '1080p', bitrate: 5800, url: '/stream/1080p.m4s' },
      { quality: '720p',  bitrate: 2800, url: '/stream/720p.m4s' },
      { quality: '480p',  bitrate: 1100, url: '/stream/480p.m4s' },
      { quality: '360p',  bitrate: 400,  url: '/stream/360p.m4s' },
    ];

    this.currentLevel = 1;
    this.bandwidthHistory = [];

    this.mediaSource.addEventListener('sourceopen', () => this.onSourceOpen());
  }

  onSourceOpen() {
    const codec = 'video/mp4; codecs="avc1.42E01E"';
    this.sourceBuffer = this.mediaSource.addSourceBuffer(codec);
    this.startBandwidthMonitoring();
    this.loadSegment(0);
  }

  async loadSegment(segmentIndex) {
    const level = this.ladder[this.currentLevel];
    const startTime = performance.now();

    try {
      const response = await fetch(`${level.url}?segment=${segmentIndex}`);
      const data = await response.arrayBuffer();

      const duration = (performance.now() - startTime) / 1000;
      const bandwidth = (data.byteLength * 8) / duration / 1000; // kbps

      this.bandwidthHistory.push(bandwidth);
      if (this.bandwidthHistory.length > 5) this.bandwidthHistory.shift();

      this.sourceBuffer.appendBuffer(data);

      this.sourceBuffer.addEventListener('updateend', () => {
        this.evaluateBitrate(segmentIndex + 1);
      }, { once: true });
    } catch (error) {
      console.error('加载失败，降级到更低码率', error);
      this.currentLevel = Math.min(this.ladder.length - 1, this.currentLevel + 1);
      this.loadSegment(segmentIndex);
    }
  }

  evaluateBitrate(nextSegment) {
    const avgBandwidth = this.bandwidthHistory.reduce((a, b) => a + b, 0)
      / this.bandwidthHistory.length;

    // 选择可用带宽 70% 以下的最高码率（留 30% 余量）
    const safeBandwidth = avgBandwidth * 0.7;
    let newLevel = 0;

    for (let i = 0; i < this.ladder.length; i++) {
      if (this.ladder[i].bitrate <= safeBandwidth) {
        newLevel = i;
      }
    }

    if (newLevel !== this.currentLevel) {
      console.log(`码率切换: ${this.ladder[this.currentLevel].quality} → ${this.ladder[newLevel].quality}`);
      this.currentLevel = newLevel;
    }

    this.loadSegment(nextSegment);
  }

  startBandwidthMonitoring() {
    // 使用 Navigator.connection API 辅助判断（如果可用）
    if (navigator.connection) {
      navigator.connection.addEventListener('change', () => {
        const effectiveType = navigator.connection.effectiveType;
        const levelMap = { '4g': 1, '3g': 2, '2g': 3, 'slow-2g': 3 };
        this.currentLevel = levelMap[effectiveType] || 1;
      });
    }
  }
}
```

**要点**：
- 码率切换需要留出 30% 的带宽余量，避免频繁切换
- 使用滑动窗口（最近 5 个分片）计算平均带宽
- 加载失败时自动降级到更低码率
