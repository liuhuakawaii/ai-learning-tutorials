# 多方会议

## 场景引入

上一课实现了 1 对 1 视频通话。但现实中的视频会议往往是多人的——团队周会、在线课堂、远程面试，参与者可能是 3 人、10 人、甚至上百人。

问题来了：1 对 1 通话只需要一个 PeerConnection，但 10 个人的会议怎么办？每个浏览器都和其他 9 个浏览器建立 PeerConnection 吗？这样带宽和 CPU 消耗会怎样？

这就是多方会议架构要解决的核心问题。不同的架构方案在带宽、延迟、服务器成本、客户端复杂度之间做了不同的取舍。

## 学习目标

1. 理解三种多方会议架构：Mesh、SFU、MCU
2. 掌握各架构的优缺点和适用场景
3. 实现房间管理和参与者生命周期
4. 理解 SFU 的媒体路由逻辑
5. 学会根据需求选择合适的架构

## Mesh 架构

### 全连接模型

Mesh 是最直观的方案：每个参与者和其他所有参与者建立点对点连接。

```
      A ────────── B
      │ \        / │
      │  \      /  │
      │   \    /   │
      │    \  /    │
      └─────\/─────┘
             C

A ↔ B, A ↔ C, B ↔ C
3 人需要 3 个连接
N 人需要 N*(N-1)/2 个连接
```

```javascript
class MeshConference {
  constructor() {
    this.peers = new Map(); // userId -> RTCPeerConnection
    this.localStream = null;
  }

  async join(roomUsers) {
    this.localStream = await navigator.mediaDevices.getUserMedia({
      video: true, audio: true
    });

    // 为每个已有参与者创建 PeerConnection
    for (const userId of roomUsers) {
      await this.createPeerConnection(userId);
    }
  }

  async createPeerConnection(userId) {
    const pc = new RTCPeerConnection({
      iceServers: [{ urls: 'stun:stun.l.google.com:19302' }]
    });

    this.localStream.getTracks().forEach(track => {
      pc.addTrack(track, this.localStream);
    });

    pc.ontrack = (event) => {
      this.showRemoteVideo(userId, event.streams[0]);
    };

    pc.onicecandidate = (event) => {
      if (event.candidate) {
        signaling.send({
          type: 'candidate',
          target: userId,
          candidate: event.candidate.toJSON()
        });
      }
    };

    this.peers.set(userId, pc);
    return pc;
  }

  get connectionCount() {
    return this.peers.size;
  }
}
```

### Mesh 的问题

```
参与者数量:    3     5     10    20    50
连接数:        3    10    45   190  1225
上行流数:      2     4     9    19    49
下行流数:      2     4     9    19    49
```

每个参与者需要：
- **上行带宽**：同时发送 N-1 路视频（通常只能支持 3-5 路）
- **下行带宽**：同时接收 N-1 路视频
- **CPU**：编解码 N-1 路视频

Mesh 只适合 **3-4 人**的小规模会议。

## SFU 架构

### 选择性转发单元

SFU（Selective Forwarding Unit）是目前最主流的多方会议架构。每个参与者只上传一路流到 SFU，SFU 负责将流转发给其他参与者。

```
参与者 A ──上传──→ ┌─────────┐ ──转发──→ 参与者 B
参与者 B ──上传──→ │   SFU   │ ──转发──→ 参与者 C
参与者 C ──上传──→ │  服务器  │ ──转发──→ 参与者 A
                   └─────────┘
```

SFU 的核心特点：
- **不转码**：原样转发媒体包，服务器 CPU 消耗低
- **上传一路**：每个客户端只需上传一路流
- **选择性转发**：可以决定给谁转发什么质量的流

```javascript
// SFU 客户端逻辑
class SFUClient {
  constructor(signalingUrl) {
    this.ws = new WebSocket(signalingUrl);
    this.publishPC = null;   // 发布用的 PeerConnection
    this.subscribePC = null; // 订阅用的 PeerConnection
    this.participants = new Map();
  }

  async join(roomId) {
    this.localStream = await navigator.mediaDevices.getUserMedia({
      video: true, audio: true
    });

    // 创建发布连接（上传本地流）
    this.publishPC = new RTCPeerConnection({
      iceServers: [{ urls: 'stun:stun.l.google.com:19302' }]
    });

    this.localStream.getTracks().forEach(track => {
      this.publishPC.addTrack(track, this.localStream);
    });

    // 向 SFU 发布
    const offer = await this.publishPC.createOffer();
    await this.publishPC.setLocalDescription(offer);

    this.ws.send(JSON.stringify({
      type: 'publish',
      roomId,
      sdp: offer.sdp
    }));
  }

  handleSFUMessage(message) {
    switch (message.type) {
      case 'publish-answer':
        this.publishPC.setRemoteDescription({
          type: 'answer',
          sdp: message.sdp
        });
        break;

      case 'new-participant':
        this.subscribeToParticipant(message.participantId);
        break;

      case 'subscribe-offer':
        this.handleSubscribeOffer(message);
        break;

      case 'participant-left':
        this.removeParticipant(message.participantId);
        break;
    }
  }

  async subscribeToParticipant(participantId) {
    this.ws.send(JSON.stringify({
      type: 'subscribe',
      targetId: participantId
    }));
  }

  async handleSubscribeOffer(message) {
    // 为每个远程参与者创建订阅连接
    const pc = new RTCPeerConnection({
      iceServers: [{ urls: 'stun:stun.l.google.com:19302' }]
    });

    pc.ontrack = (event) => {
      this.showRemoteVideo(message.participantId, event.streams[0]);
    };

    await pc.setRemoteDescription({ type: 'offer', sdp: message.sdp });
    const answer = await pc.createAnswer();
    await pc.setLocalDescription(answer);

    this.ws.send(JSON.stringify({
      type: 'subscribe-answer',
      targetId: message.participantId,
      sdp: answer.sdp
    }));

    this.participants.set(message.participantId, pc);
  }
}
```

### Simulcast：多质量层

SFU 的一个强大特性是 Simulcast——客户端同时发送多个质量层的流，SFU 根据接收者的带宽选择合适的层转发。

```javascript
// 启用 Simulcast
const transceiver = pc.addTransceiver('video', {
  direction: 'sendonly',
  sendEncodings: [
    { rid: 'high', maxBitrate: 2500000, scaleResolutionDownBy: 1 },
    { rid: 'mid', maxBitrate: 800000, scaleResolutionDownBy: 2 },
    { rid: 'low', maxBitrate: 250000, scaleResolutionDownBy: 4 }
  ]
});
```

```
客户端发送:
  high: 1280x720 @ 2.5Mbps
  mid:  640x360  @ 800kbps
  low:  320x180  @ 250kbps

SFU 根据接收者带宽选择:
  带宽充足 → 转发 high
  带宽一般 → 转发 mid
  带宽紧张 → 转发 low
```

### SVC：可伸缩视频编码

VP9 和 AV1 支持 SVC（Scalable Video Coding），比 Simulcast 更高效：

```javascript
// VP9 SVC
const transceiver = pc.addTransceiver('video', {
  direction: 'sendonly',
  sendEncodings: [
    { scalabilityMode: 'L3T3' }  // 3 个时间层，3 个空间层
  ]
});
```

## MCU 架构

### 混合控制单元

MCU（Multipoint Control Unit）在服务器端将所有参与者的视频混合成一路，再发送给每个人。

```
参与者 A ──→ ┌─────────┐
参与者 B ──→ │   MCU   │ ──→ 混合后的一路视频 ──→ 每个参与者
参与者 C ──→ │  (混流)  │
             └─────────┘
```

MCU 的优点：
- 客户端只收一路流，带宽和 CPU 消耗最低
- 布局完全由服务器控制
- 对弱网客户端友好

MCU 的缺点：
- 服务器需要转码，CPU 消耗巨大
- 延迟增加（服务器需要解码、混合、再编码）
- 成本高

```javascript
// MCU 客户端代码非常简单
class MCUClient {
  constructor(signalingUrl) {
    this.ws = new WebSocket(signalingUrl);
    this.pc = null;
  }

  async join(roomId) {
    const localStream = await navigator.mediaDevices.getUserMedia({
      video: true, audio: true
    });

    this.pc = new RTCPeerConnection({
      iceServers: [{ urls: 'stun:stun.l.google.com:19302' }]
    });

    // 上传本地流
    localStream.getTracks().forEach(track => {
      this.pc.addTrack(track, localStream);
    });

    // MCU 只返回一路混合流
    this.pc.ontrack = (event) => {
      // 这一路流包含所有参与者的画面（MCU 混合后的）
      document.getElementById('mixedVideo').srcObject = event.streams[0];
    };

    const offer = await this.pc.createOffer();
    await this.pc.setLocalDescription(offer);

    this.ws.send(JSON.stringify({ type: 'join', roomId, sdp: offer.sdp }));
  }
}
```

## SFU vs MCU 对比

```
┌────────────────┬──────────────────┬──────────────────┐
│ 指标            │ SFU              │ MCU              │
├────────────────┼──────────────────┼──────────────────┤
│ 服务器 CPU      │ 低（只转发）     │ 高（需转码混流） │
│ 客户端上行      │ 1 路             │ 1 路             │
│ 客户端下行      │ N-1 路           │ 1 路             │
│ 延迟            │ 低               │ 中等             │
│ 布局控制        │ 客户端           │ 服务器           │
│ 弱网表现        │ 可选降级质量     │ 服务器适配       │
│ 扩展性          │ 高               │ 低               │
│ 实现复杂度      │ 中等             │ 高               │
│ 典型应用        │ Zoom, Teams      │ 传统视频会议     │
└────────────────┴──────────────────┴──────────────────┘
```

选择建议：
- **3-4 人**：Mesh 就够了，零服务器成本
- **5-50 人**：SFU 是最佳选择，平衡了成本和体验
- **弱网/低端设备多**：考虑 MCU 或 SFU + 选择性订阅
- **100+ 人**：SFU + 仅显示活跃发言人

## 房间管理

### 房间生命周期

```javascript
class RoomManager {
  constructor() {
    this.rooms = new Map();
  }

  createRoom(roomId, options = {}) {
    const room = {
      id: roomId,
      participants: new Map(),
      maxParticipants: options.maxParticipants || 50,
      createdAt: Date.now(),
      settings: {
        allowScreenShare: options.allowScreenShare !== false,
        allowChat: options.allowChat !== false,
        muteOnJoin: options.muteOnJoin || false
      }
    };
    this.rooms.set(roomId, room);
    return room;
  }

  joinRoom(roomId, userId, userInfo) {
    const room = this.rooms.get(roomId);
    if (!room) throw new Error('房间不存在');
    if (room.participants.size >= room.maxParticipants) {
      throw new Error('房间已满');
    }

    const participant = {
      userId,
      ...userInfo,
      joinedAt: Date.now(),
      isMuted: false,
      isCameraOff: false,
      isScreenSharing: false
    };

    room.participants.set(userId, participant);

    // 通知其他参与者
    this.broadcast(roomId, {
      type: 'participant-joined',
      participant
    }, userId);

    return participant;
  }

  leaveRoom(roomId, userId) {
    const room = this.rooms.get(roomId);
    if (!room) return;

    room.participants.delete(userId);

    this.broadcast(roomId, {
      type: 'participant-left',
      userId
    });

    // 房间为空时清理
    if (room.participants.size === 0) {
      this.rooms.delete(roomId);
    }
  }

  broadcast(roomId, message, excludeUserId) {
    const room = this.rooms.get(roomId);
    if (!room) return;

    for (const [userId, participant] of room.participants) {
      if (userId !== excludeUserId) {
        participant.connection?.send(JSON.stringify(message));
      }
    }
  }
}
```

### 参与者状态同步

```javascript
// SFU 服务器端：管理参与者状态
class SFUServer {
  constructor() {
    this.roomManager = new RoomManager();
    this.connections = new Map(); // userId -> { publishPC, subscribePCs }
  }

  handlePublish(userId, roomId, sdp) {
    // 创建 SFU 端的 PeerConnection 接收发布流
    const pc = new RTCPeerConnection(config);

    pc.ontrack = (event) => {
      // 收到发布者的流，准备转发给其他参与者
      this.forwardStream(roomId, userId, event.track, event.streams[0]);
    };

    // 返回 answer 给发布者
    return pc;
  }

  forwardStream(roomId, fromUserId, track, stream) {
    const room = this.roomManager.rooms.get(roomId);
    if (!room) return;

    for (const [toUserId, participant] of room.participants) {
      if (toUserId === fromUserId) continue;

      // 为每个订阅者创建转发
      const subscribePC = participant.subscribePC;
      subscribePC.addTrack(track, stream);
    }
  }

  handleSubscribe(userId, targetId) {
    // 为订阅者创建 PeerConnection
    const pc = new RTCPeerConnection(config);

    // 获取目标用户的流并添加
    const targetStream = this.connections.get(targetId)?.stream;
    if (targetStream) {
      targetStream.getTracks().forEach(track => {
        pc.addTrack(track, targetStream);
      });
    }

    return pc;
  }
}
```

### 发言人检测

在大型会议中，通常只显示正在说话的人：

```javascript
class ActiveSpeakerDetector {
  constructor() {
    this.audioLevels = new Map();
    this.activeSpeaker = null;
    this.onSpeakerChange = null;
  }

  addParticipant(userId, audioTrack) {
    const audioContext = new AudioContext();
    const source = audioContext.createMediaStreamSource(
      new MediaStream([audioTrack])
    );
    const analyser = audioContext.createAnalyser();
    analyser.fftSize = 256;
    source.connect(analyser);

    const dataArray = new Uint8Array(analyser.frequencyBinCount);

    const checkLevel = () => {
      analyser.getByteFrequencyData(dataArray);
      const average = dataArray.reduce((a, b) => a + b) / dataArray.length;
      this.audioLevels.set(userId, average);

      this.detectSpeaker();
      requestAnimationFrame(checkLevel);
    };

    checkLevel();
  }

  detectSpeaker() {
    let maxLevel = 0;
    let loudestUser = null;

    for (const [userId, level] of this.audioLevels) {
      if (level > maxLevel) {
        maxLevel = level;
        loudestUser = userId;
      }
    }

    // 需要超过阈值才算发言
    if (maxLevel > 30 && loudestUser !== this.activeSpeaker) {
      this.activeSpeaker = loudestUser;
      this.onSpeakerChange?.(loudestUser);
    }
  }
}
```

## 常见误区

### 误区一：SFU 总是比 MCU 好

SFU 的优势在于服务器成本低，但对客户端的要求更高。如果参会者的设备性能差、带宽低，SFU 需要接收多路流会给客户端带来压力。MCU 虽然服务器成本高，但客户端只需要收一路流，体验更稳定。

### 误区二：Mesh 架构完全不可用

对于 3-4 人的小团队视频通话，Mesh 是最简单的方案——不需要任何服务器（除了信令）。零成本、低延迟。不要因为"不高级"就放弃它。

### 误区三：Simulcast 在所有浏览器上都支持

Simulcast 的支持情况：
- Chrome/Edge：完整支持
- Safari：部分支持（H.264 simulcast 可能有问题）
- Firefox：支持但行为可能不一致

生产环境中要做好降级方案，不能假设 Simulcast 总是可用。

### 误区四：参与者越多越好

大型会议中，显示所有人的视频既不现实也没必要。更好的策略是：
- 始终显示发言人
- 显示最近活跃的几个人
- 其他人用头像+名字代替

## 工程建议

1. **根据规模选择架构**。小团队用 Mesh，中等规模用 SFU，特殊需求用 MCU。不要一开始就设计支持 1000 人的架构。

2. **SFU 要实现选择性订阅**。不是所有远程流都需要接收。可以：
   - 只订阅当前可见的参与者
   - 根据视口大小请求不同质量层
   - 用户静音时停止接收其音频

3. **处理参与者断连**。网络中断、浏览器关闭、页面刷新都会导致参与者突然消失。SFU 需要检测连接断开并通知其他参与者：

```javascript
pc.onconnectionstatechange = () => {
  if (pc.connectionState === 'disconnected') {
    // 等待一段时间看是否恢复
    setTimeout(() => {
      if (pc.connectionState !== 'connected') {
        this.handleParticipantDisconnect(userId);
      }
    }, 5000);
  }
};
```

4. **控制布局复杂度**。参与者数量不同，布局策略应该变化：
   - 1-4 人：等分网格
   - 5-9 人：发言人突出 + 其他人小窗
   - 10+ 人：分页或仅显示活跃参与者

## 小结

多方会议的三种架构各有取舍：

- **Mesh**：简单直接，适合 3-4 人，客户端负担重
- **SFU**：主流方案，服务器转发不转码，支持 Simulcast 和选择性订阅
- **MCU**：服务器混流，客户端最轻，但服务器成本高

房间管理是多方会议的基础，需要处理好参与者生命周期、状态同步和发言人检测。实际项目中，SFU + 选择性订阅 + 发言人检测是最常见的组合。

## 参考答案

### 练习一

**思路**：使用 Map 存储房间和参与者信息，每个操作返回统一格式的结果。权限检查要放在操作执行前。

**答案**：

```javascript
class RoomAPI {
  constructor() {
    this.rooms = new Map();
  }

  createRoom(roomId, creatorId, options = {}) {
    if (this.rooms.has(roomId)) {
      return { success: false, error: '房间已存在' };
    }

    const room = {
      id: roomId,
      ownerId: creatorId,
      participants: new Map(),
      maxParticipants: options.maxParticipants || 50,
      createdAt: Date.now(),
      settings: {
        allowScreenShare: options.allowScreenShare !== false,
        allowChat: options.allowChat !== false
      }
    };

    this.rooms.set(roomId, room);
    return { success: true, room: this.getRoomInfo(roomId) };
  }

  joinRoom(roomId, userId, userInfo) {
    const room = this.rooms.get(roomId);
    if (!room) return { success: false, error: '房间不存在' };
    if (room.participants.size >= room.maxParticipants) {
      return { success: false, error: '房间已满' };
    }
    if (room.participants.has(userId)) {
      return { success: false, error: '已在房间中' };
    }

    const participant = {
      userId,
      displayName: userInfo.displayName || userId,
      isMuted: false,
      isCameraOff: false,
      isScreenSharing: false,
      joinedAt: Date.now(),
      role: userId === room.ownerId ? 'owner' : 'member'
    };

    room.participants.set(userId, participant);
    return { success: true, participant, room: this.getRoomInfo(roomId) };
  }

  leaveRoom(roomId, userId) {
    const room = this.rooms.get(roomId);
    if (!room) return { success: false, error: '房间不存在' };
    if (!room.participants.has(userId)) {
      return { success: false, error: '不在房间中' };
    }

    room.participants.delete(userId);

    if (room.participants.size === 0) {
      this.rooms.delete(roomId);
      return { success: true, roomDeleted: true };
    }

    if (userId === room.ownerId) {
      const newOwner = room.participants.keys().next().value;
      room.ownerId = newOwner;
      room.participants.get(newOwner).role = 'owner';
    }

    return { success: true, newOwnerId: room.ownerId };
  }

  kickParticipant(roomId, operatorId, targetId) {
    const room = this.rooms.get(roomId);
    if (!room) return { success: false, error: '房间不存在' };

    const operator = room.participants.get(operatorId);
    if (!operator || operator.role !== 'owner') {
      return { success: false, error: '没有权限' };
    }

    if (!room.participants.has(targetId)) {
      return { success: false, error: '目标用户不在房间' };
    }

    room.participants.delete(targetId);
    return { success: true };
  }

  updateParticipantState(roomId, userId, updates) {
    const room = this.rooms.get(roomId);
    if (!room) return { success: false, error: '房间不存在' };

    const participant = room.participants.get(userId);
    if (!participant) return { success: false, error: '不在房间中' };

    const allowedFields = ['isMuted', 'isCameraOff', 'isScreenSharing'];
    for (const [key, value] of Object.entries(updates)) {
      if (allowedFields.includes(key)) {
        participant[key] = value;
      }
    }

    return { success: true, participant };
  }

  listRooms() {
    const result = [];
    for (const [id, room] of this.rooms) {
      result.push({
        id,
        participantCount: room.participants.size,
        maxParticipants: room.maxParticipants,
        createdAt: room.createdAt
      });
    }
    return result;
  }

  getRoomInfo(roomId) {
    const room = this.rooms.get(roomId);
    if (!room) return null;

    return {
      id: room.id,
      ownerId: room.ownerId,
      participants: Array.from(room.participants.values()),
      settings: room.settings,
      createdAt: room.createdAt
    };
  }
}
```

**要点**：
- 房主离开时自动转移房主权限
- 状态更新要限制可修改的字段
- 操作结果统一返回 `{ success, error? }` 格式

### 练习二

**思路**：用一个状态变量跟踪当前的大画面用户，监听发言人变化事件自动切换。参与者离开时检查是否需要更新视图。

**答案**：

```javascript
class GalleryView {
  constructor(container, options = {}) {
    this.container = container;
    this.pinnedUserId = null;       // 用户手动固定的
    this.activeSpeakerId = null;    // 当前发言人
    this.participants = new Map();  // userId -> { stream, element }
    this.autoSwitch = options.autoSwitch !== false;

    this.container.style.display = 'grid';
    this.container.style.gridTemplateColumns = '1fr';
    this.updateLayout();
  }

  addParticipant(userId, stream, displayName) {
    const videoEl = document.createElement('video');
    videoEl.srcObject = stream;
    videoEl.autoplay = true;
    videoEl.playsInline = true;
    videoEl.dataset.userId = userId;
    videoEl.onclick = () => this.togglePin(userId);

    const wrapper = document.createElement('div');
    wrapper.className = 'video-wrapper';
    wrapper.dataset.userId = userId;
    wrapper.appendChild(videoEl);

    const label = document.createElement('span');
    label.textContent = displayName || userId;
    label.className = 'participant-label';
    wrapper.appendChild(label);

    this.participants.set(userId, { stream, element: wrapper, displayName });
    this.container.appendChild(wrapper);
    this.updateLayout();
  }

  removeParticipant(userId) {
    const participant = this.participants.get(userId);
    if (!participant) return;

    participant.element.remove();
    this.participants.delete(userId);

    if (this.pinnedUserId === userId) {
      this.pinnedUserId = null;
    }
    if (this.activeSpeakerId === userId) {
      this.activeSpeakerId = this.pinnedUserId || this.getFirstParticipant();
    }

    this.updateLayout();
  }

  setActiveSpeaker(userId) {
    this.activeSpeakerId = userId;
    if (this.autoSwitch && !this.pinnedUserId) {
      this.updateLayout();
    }
  }

  togglePin(userId) {
    if (this.pinnedUserId === userId) {
      this.pinnedUserId = null;
    } else {
      this.pinnedUserId = userId;
    }
    this.updateLayout();
  }

  getFeaturedUserId() {
    return this.pinnedUserId || this.activeSpeakerId;
  }

  getFirstParticipant() {
    return this.participants.keys().next().value || null;
  }

  updateLayout() {
    const featuredId = this.getFeaturedUserId();
    const count = this.participants.size;

    if (count <= 1) {
      this.container.style.gridTemplateColumns = '1fr';
    } else if (featuredId && count > 2) {
      this.container.style.gridTemplateColumns = '2fr 1fr';
      this.container.style.gridTemplateRows = 'repeat(auto-fill, minmax(120px, 1fr))';
    } else {
      const cols = count <= 2 ? count : count <= 4 ? 2 : 3;
      this.container.style.gridTemplateColumns = `repeat(${cols}, 1fr)`;
    }

    for (const [userId, participant] of this.participants) {
      const el = participant.element;
      if (userId === featuredId && count > 2) {
        el.style.gridColumn = '1';
        el.style.gridRow = '1 / -1';
        el.classList.add('featured');
      } else {
        el.style.gridColumn = '';
        el.style.gridRow = '';
        el.classList.remove('featured');
      }
    }
  }
}
```

**要点**：
- 用户手动 pin 优先于自动切换
- 参与者离开时清理相关状态
- 布局根据参与者数量自动调整
