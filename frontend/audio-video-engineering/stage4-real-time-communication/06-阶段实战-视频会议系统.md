# 阶段实战：视频会议系统——排查音视频质量问题

## 现象

你搭建了一个视频会议系统，两人通话时视频经常卡顿、音频断断续续。Chrome 的 WebRTC Internals 页面显示丢包率 15%，抖动 50ms。

## 排查过程

### 第一步：获取实时统计

```typescript
async function diagnoseConnection(pc: RTCPeerConnection) {
  const stats = await pc.getStats()
  const report = {
    video: { packetsLost: 0, jitter: 0, bitrate: 0, fps: 0 },
    audio: { packetsLost: 0, jitter: 0, bitrate: 0 },
    candidatePair: { rtt: 0, availableBandwidth: 0 }
  }

  stats.forEach(s => {
    if (s.type === 'inbound-rtp' && s.kind === 'video') {
      report.video.packetsLost = s.packetsLost
      report.video.jitter = s.jitter
      report.video.fps = s.framesPerSecond
    }
    if (s.type === 'candidate-pair' && s.state === 'succeeded') {
      report.candidatePair.rtt = s.currentRoundTripTime
    }
  })

  return report
}
```

### 第二步：分析丢包原因

```
丢包 15% 的可能原因：
  1. 网络带宽不足 → 视频码率超过可用带宽
  2. 拥塞控制失效 → 编码码率没有及时降下来
  3. UDP 被限速 → 企业网络 QoS 限制
  4. WiFi 不稳定 → 无线网络抖动
```

### 第三步：优化编码参数

```typescript
// 动态调整编码码率
async function adaptBitrate(pc: RTCPeerConnection, targetBitrate: number) {
  const sender = pc.getSenders().find(s => s.track?.kind === 'video')
  if (!sender) return

  const params = sender.getParameters()
  if (!params.encodings || params.encodings.length === 0) {
    params.encodings = [{}]
  }

  params.encodings[0].maxBitrate = targetBitrate
  await sender.setParameters(params)
}

// 根据网络状况自适应
setInterval(async () => {
  const stats = await diagnoseConnection(pc)

  if (stats.video.packetsLost > 100 || stats.candidatePair.rtt > 0.3) {
    // 网络差，降低码率
    await adaptBitrate(pc, 500_000) // 500kbps
  } else if (stats.video.packetsLost < 10 && stats.candidatePair.rtt < 0.1) {
    // 网络好，提升码率
    await adaptBitrate(pc, 2_000_000) // 2Mbps
  }
}, 3000)
```

## 完整的会议系统

```typescript
class VideoConference {
  private pc: RTCPeerConnection
  private localStream: MediaStream

  async init(signalingUrl: string) {
    this.pc = new RTCPeerConnection({
      iceServers: [
        { urls: 'stun:stun.l.google.com:19302' },
        { urls: 'turn:your-server.com', username: 'u', credential: 'p' }
      ]
    })

    this.localStream = await navigator.mediaDevices.getUserMedia({
      video: { width: 1280, height: 720 },
      audio: { echoCancellation: true, noiseSuppression: true }
    })

    this.localStream.getTracks().forEach(t => this.pc.addTrack(t, this.localStream))

    this.pc.ontrack = (e) => {
      const video = document.createElement('video')
      video.srcObject = e.streams[0]
      video.autoplay = true
      document.getElementById('remote-videos')!.appendChild(video)
    }

    this.pc.onicecandidate = (e) => {
      if (e.candidate) this.sendSignal({ type: 'candidate', candidate: e.candidate })
    }

    this.startQualityMonitor()
  }

  private startQualityMonitor() {
    setInterval(async () => {
      const stats = await this.pc.getStats()
      this.updateQualityUI(stats)
    }, 2000)
  }

  private updateQualityUI(stats: RTCStatsReport) {
    stats.forEach(s => {
      if (s.type === 'inbound-rtp' && s.kind === 'video') {
        const indicator = document.getElementById('quality')
        if (s.packetsLost > 50) {
          indicator!.textContent = '🔴 网络差'
        } else if (s.packetsLost > 10) {
          indicator!.textContent = '🟡 网络一般'
        } else {
          indicator!.textContent = '🟢 网络好'
        }
      }
    })
  }
}
```

## 你可能踩的坑

**坑一：TURN 服务器带宽成本**

TURN 服务器转发所有数据。100 人会议如果都走 TURN，带宽成本很高。优先用 STUN + P2P。

**坑二：不处理 track ended 事件**

用户关闭摄像头时，track 会触发 `ended` 事件。不处理的话 UI 上会显示黑屏。

**坑三：回声消除需要正确的音频路由**

如果扬声器和麦克风同时开启，回声消除是必须的。但在耳机场景下，可以关闭回声消除降低 CPU 占用。

```typescript
async function shareScreen(pc: RTCPeerConnection) {
  const screenStream = await navigator.mediaDevices.getDisplayMedia({
    video: { cursor: 'always' }
  })

  const screenTrack = screenStream.getVideoTracks()[0]
  const sender = pc.getSenders().find(s => s.track?.kind === 'video')

  await sender!.replaceTrack(screenTrack)

  screenTrack.onended = () => {
    // 用户停止共享，恢复摄像头
    const cameraTrack = localStream.getVideoTracks()[0]
    sender!.replaceTrack(cameraTrack)
  }
}
```

```typescript
// 使用 MediaRecorder 录制远程流
function startRecording(stream: MediaStream) {
  const recorder = new MediaRecorder(stream, {
    mimeType: 'video/webm;codecs=vp8,opus'
  })
  const chunks: Blob[] = []

  recorder.ondataavailable = (e) => {
    if (e.data.size > 0) chunks.push(e.data)
  }

  recorder.onstop = () => {
    const blob = new Blob(chunks, { type: 'video/webm' })
    saveRecording(blob)
  }

  recorder.start(1000)
  return recorder
}
```
