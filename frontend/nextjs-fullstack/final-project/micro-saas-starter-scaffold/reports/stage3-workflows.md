# 第三阶段：业务流程报告

## 场景引入

前两个阶段完成了基础设施（路由、认证、数据库），现在需要构建用户实际使用的功能——Dashboard 布局、项目管理、团队管理、搜索筛选、审计日志。这些是 SaaS 产品的核心业务流程，用户通过它们完成创建项目、协作编辑、查看历史等日常操作。

- Dashboard：侧边栏导航、用户信息、退出登录
- 项目管理：CRUD + 搜索 + 状态筛选 + 分页
- 团队管理：成员列表、角色展示、套餐信息
- 邀请系统：UI 占位（需后续集成邮件服务）
- 审计日志：关键操作自动记录（project:create/delete），管理员表格展示

## 常见误区

1. **CRUD 操作不做分页**：数据量增长后，一次性加载所有记录会导致接口超时和前端卡顿。从一开始就用 `skip` + `take` 实现分页。

2. **搜索只做前端过滤**：前端过滤只能搜索已加载的数据。真正的搜索应该在数据库层面用 `WHERE name ILIKE '%keyword%'` 实现。

3. **审计日志用同步写入**：审计日志写入失败不应阻塞主业务流程。应该用异步方式（如 `Promise.allSettled`）写入日志。

4. **邀请系统只做 UI 没有后端**：邀请链接需要包含 token 并设置过期时间，后端需要验证 token 有效性、处理重复邀请、防止枚举攻击。

## 工程建议

1. **搜索使用 Prisma 的 `contains` + `mode: 'insensitive'`**：实现大小写不敏感的模糊搜索，同时对搜索字段加索引保证性能。

2. **分页使用 cursor-based 分页**：对于实时数据（如审计日志），cursor-based 分页比 offset-based 分页更高效，不会出现数据重复或遗漏。

3. **Dashboard 布局用 Server Component + 嵌套路由**：侧边栏导航放在 layout.tsx 中，页面内容通过 children 渲染，避免每次切换页面重新加载导航。

4. **项目列表用 `useOptimistic` 优化删除体验**：用户点击删除后立即从列表中移除项目，同时异步发送删除请求，失败时自动恢复。
