# 阶段实战：性能与安全审查

## 项目目标

对已完成的 SaaS 项目做全面的性能和安全审查，发现并修复问题。这不是新功能开发，而是工程化的重要环节。

## 审查清单

### 首屏性能

- [ ] FCP < 1.8s
- [ ] LCP < 2.5s
- [ ] CLS < 0.1
- [ ] TTI < 3.8s

### 安全

- [ ] CSRF 防护
- [ ] XSS 防护
- [ ] 权限绕过检查
- [ ] 输入验证

### 体验

- [ ] 无障碍（键盘操作、屏幕阅读器）
- [ ] 错误处理（友好的错误页面）
- [ ] 加载状态（骨架屏）

## 性能审查

### 1. 运行 Lighthouse

```bash
npx lighthouse http://localhost:3000 --output html --output-path ./lighthouse.html
```

### 2. 检查 Bundle 大小

```bash
npx @next/bundle-analyzer
```

查看哪些依赖占用了最多空间。常见问题：
- 引入了整个 lodash 而不是 `lodash/debounce`
- 引入了 moment.js（用 date-fns 替代）
- 未使用的 UI 库

### 3. 图片审计

```bash
# 检查未优化的图片
grep -r '<img' app/ --include="*.tsx"
```

所有 `<img>` 应该替换为 `next/image`。

### 4. 数据获取审计

检查是否有串行的数据请求可以并行：

```typescript
// ❌ 串行
const stats = await getStats()
const activities = await getActivities()

// ✅ 并行
const [stats, activities] = await Promise.all([
  getStats(),
  getActivities(),
])
```

## 安全审查

### 1. CSRF 防护

Server Actions 自动防护 CSRF，但 API Routes 需要手动检查：

```typescript
// app/api/transfer/route.ts
export async function POST(req: NextRequest) {
  const origin = req.headers.get('origin')
  if (origin !== process.env.NEXT_PUBLIC_APP_URL) {
    return NextResponse.json({ error: 'Invalid origin' }, { status: 403 })
  }
  // ...
}
```

### 2. XSS 防护

检查是否有 `dangerouslySetInnerHTML`：

```bash
grep -r 'dangerouslySetInnerHTML' app/ --include="*.tsx"
```

如果必须使用，确保内容经过消毒：

```typescript
import DOMPurify from 'isomorphic-dompurify'
<div dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(content) }} />
```

### 3. 权限绕过

检查所有 Server Action 和 API Route 是否有权限验证：

```bash
grep -r 'use server' app/ --include="*.ts"
# 对每个 Server Action 检查是否有 requireAuth() 或 requireProjectRole()
```

常见漏洞：
- 删除操作没有检查是否是 owner
- 更新操作没有检查是否有权限
- 直接用 `params.id` 查询没有验证当前用户是否有权访问

### 4. 输入验证

```typescript
// ❌ 直接使用用户输入
const name = formData.get('name') as string
await prisma.user.update({ where: { id: name }, data: { ... } })

// ✅ Zod 验证
const schema = z.object({ name: z.string().min(1).max(100) })
const result = schema.safeParse({ name: formData.get('name') })
if (!result.success) return { error: result.error.errors[0].message }
```

## 无障碍审查

### 1. 键盘操作

```bash
# 用 Tab 键遍历所有交互元素
# 检查：能否到达、顺序是否合理、是否有焦点样式
```

### 2. ARIA 标签

```tsx
// ❌ 没有标签
<button onClick={deleteItem}>删除</button>

// ✅ 有 ARIA 标签
<button onClick={deleteItem} aria-label="删除项目">删除</button>
```

### 3. 颜色对比度

文字和背景的对比度至少 4.5:1（WCAG AA）。用 Chrome DevTools 的 Accessibility 面板检查。

## 修复示例

### 修复 LCP

```tsx
// 之前：首屏大图没有优先加载
<img src="/hero.jpg" />

// 之后
<Image src="/hero.jpg" width={1200} height={600} priority />
```

### 修复 CLS

```tsx
// 之前：字体加载导致布局偏移
<html>

// 之后
import { Inter } from 'next/font/google'
const inter = Inter({ subsets: ['latin'] })
<html className={inter.className}>
```

### 修复权限漏洞

```typescript
// 之前
export async function deleteProject(projectId: string) {
  await prisma.project.delete({ where: { id: projectId } })
}

// 之后
export async function deleteProject(projectId: string) {
  await requireProjectRole(projectId, 'OWNER')  // 只有 owner 能删除
  await prisma.project.delete({ where: { id: projectId } })
  await logAction('project.delete', { projectId })
}
```

## 练习

### 练习一：Lighthouse 审计

对项目运行 Lighthouse，记录所有低于 90 分的指标，制定修复计划。

### 练习二：安全扫描

检查所有 Server Action 是否有权限验证，所有用户输入是否经过验证。

### 练习三：无障碍检查

用 Tab 键遍历所有页面，确保所有交互元素可达且有焦点样式。

## 参考答案

### 练习一

```bash
npx lighthouse http://localhost:3000 --output json --output-path ./report.json
```

常见修复：
- FCP 低 → 移除阻塞渲染的脚本
- LCP 低 → 给首屏图片加 `priority`
- CLS 高 → 给图片和字体设固定尺寸
- TTI 低 → 减少 JS bundle 大小

### 练习二

```bash
# 查找所有 Server Action
grep -rn "'use server'" app/ --include="*.ts"

# 对每个文件检查是否有权限验证
# 期望看到 requireAuth() 或 requireProjectRole()
```

### 练习三

```tsx
// 确保所有按钮有焦点样式
button:focus-visible {
  outline: 2px solid #3b82f6;
  outline-offset: 2px;
}

// 确保所有表单字段有 label
<label htmlFor="email">邮箱</label>
<input id="email" name="email" />
```
