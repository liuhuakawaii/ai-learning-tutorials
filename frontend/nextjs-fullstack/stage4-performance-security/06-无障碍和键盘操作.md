# 第六课：无障碍和键盘操作

## 场景引入

你的 SaaS 产品上线后收到一封用户邮件："我是视障用户，使用屏幕阅读器操作你们的网站，但按钮没有文字标签，图片没有描述，我完全无法完成注册流程。"你用 Lighthouse 的 Accessibility 审计跑了一下，得分只有 52 分——大量图片缺少 alt 属性，表单没有关联 label，自定义下拉菜单无法用键盘操作。无障碍不仅仅是"锦上添花"，在很多国家它甚至是法律要求。

## 学习目标

完成本课学习后，你将能够：

1. 理解无障碍的重要性
2. 实现基本的无障碍功能
3. 支持键盘导航
4. 使用 ARIA 属性
5. 测试无障碍性

## 一、为什么无障碍很重要

### 1.1 无障碍的范围

```
永久性障碍：
  → 失明、聋哑、肢体残疾

暂时性障碍：
  → 手臂骨折、眼睛感染

情境性障碍：
  → 强光下看屏幕、嘈杂环境听不到声音
  → 开车时不能看屏幕
```

### 1.2 商业价值

```
全球约 10 亿人有某种形式的残疾
  → 这是一个巨大的用户群体
  → 无障碍做得好 = 更多用户

法律要求：
  → 很多国家有无障碍法规
  → 不合规可能面临诉讼
```

## 二、语义化 HTML

### 2.1 使用正确的标签

```tsx
// ❌ 不好：全部用 div
<div className="header">
  <div className="nav">
    <div className="link">首页</div>
  </div>
</div>

// ✅ 好：使用语义化标签

  <nav>

  </nav>

```
页面结构：

  <table>      表格

## 三、键盘导航

### 3.1 焦点管理

```tsx
// 确保所有交互元素可聚焦
<button>点击</button>
<a href="/">链接</a>
<input type="text" />
<select>...</select>
<textarea>...</textarea>

// 自定义元素需要添加 tabIndex
<div
  tabIndex={0}
  role="button"
  onKeyDown={(e) => {
    if (e.key === 'Enter' || e.key === ' ') {
      handleClick()
    }
  }}
>
  自定义按钮
</div>
```

### 3.2 焦点顺序

```tsx
// 使用 tabIndex 控制焦点顺序
<input tabIndex={1} placeholder="第一个" />
<input tabIndex={2} placeholder="第二个" />
<input tabIndex={3} placeholder="第三个" />

// ⚠️ 避免使用正数 tabIndex
// 使用 0 或 -1
<div tabIndex={0}>可聚焦</div>
<div tabIndex={-1}>可通过代码聚焦</div>
```

### 3.3 跳过导航

```tsx
// app/layout.tsx
export default function Layout({ children }) {
  return (
    <html>
      <body>
        <a href="#main-content" className="sr-only focus:not-sr-only focus:absolute">
          跳过导航
        </a>
        <nav>...</nav>
        <main id="main-content">
          {children}
        </main>
      </body>
    </html>
  )
}
```

## 四、ARIA 属性

### 4.1 什么是 ARIA

> **ARIA（Accessible Rich Internet Applications）是一组属性，用于增强 HTML 的无障碍性。**

### 4.2 常用 ARIA 属性

```tsx
// 角色
<div role="button">按钮</div>
<div role="dialog">对话框</div>
<div role="alert">警告</div>
<nav role="navigation">导航</nav>

// 状态
<button aria-disabled="true">禁用</button>
<button aria-pressed="true">已按下</button>
<div aria-expanded="true">已展开</div>
<div aria-hidden="true">隐藏</div>

// 标签
<button aria-label="关闭">X</button>
<input aria-label="搜索" />
<div aria-labelledby="title">...</div>
<h2 id="title">标题</h2>

// 描述
<input aria-describedby="hint" />
<p id="hint">请输入有效的邮箱地址</p>
```

### 4.3 实际应用

```tsx
// 模态框
<div
  role="dialog"
  aria-modal="true"
  aria-labelledby="dialog-title"
  aria-describedby="dialog-desc"
>
  <h2 id="dialog-title">确认删除</h2>
  <p id="dialog-desc">确定要删除这篇文章吗？</p>
  <button>取消</button>
  <button>确认</button>
</div>

// 标签页
<div role="tablist">
  <button role="tab" aria-selected="true" aria-controls="panel-1">
    标签 1
  </button>
  <button role="tab" aria-selected="false" aria-controls="panel-2">
    标签 2
  </button>
</div>
<div role="tabpanel" id="panel-1">内容 1</div>
<div role="tabpanel" id="panel-2" hidden>内容 2</div>
```

## 五、表单无障碍

### 5.1 标签关联

```tsx
// ✅ 使用 label 和 htmlFor
<label htmlFor="email">邮箱</label>
<input id="email" type="email" />

// ✅ 使用 aria-label
<input aria-label="邮箱" type="email" />

// ✅ 使用 aria-labelledby
<span id="email-label">邮箱</span>
<input aria-labelledby="email-label" type="email" />
```

### 5.2 错误提示

```tsx
<div>
  <label htmlFor="email">邮箱</label>
  <input
    id="email"
    type="email"
    aria-invalid={hasError}
    aria-describedby={hasError ? 'email-error' : undefined}
  />
  {hasError && (
    <p id="email-error" role="alert">
      请输入有效的邮箱地址
    </p>
  )}
</div>
```

## 七、颜色和对比度

### 7.1 对比度要求

```
普通文本：
  → 对比度至少 4.5:1

大文本（18px+ 或 14px+ 粗体）：
  → 对比度至少 3:1

UI 组件和图形：
  → 对比度至少 3:1
```

### 7.2 不要只依赖颜色

```tsx
// ❌ 只用颜色表示状态
<span className="text-red-500">错误</span>
<span className="text-green-500">成功</span>

// ✅ 额外使用图标或文字
<span className="text-red-500">❌ 错误</span>
<span className="text-green-500">✅ 成功</span>
```

## 参考答案

### 练习 1：实现键盘导航

**思路**：使用原生语义化标签（`<button>`、`<a>`）自动获得键盘可访问性。对于自定义交互元素，添加 `tabIndex={0}` 使其可聚焦，并监听 `Enter` 和 `Space` 键事件。实现跳过导航链接方便键盘用户快速到达主内容。

**答案**：

```tsx
// components/custom-button.tsx
'use client'

interface CustomButtonProps {
  onClick: () => void
  children: React.ReactNode
  disabled?: boolean
}

export function CustomButton({ onClick, children, disabled }: CustomButtonProps) {
  return (
    <div
      role="button"
      tabIndex={disabled ? -1 : 0}
      aria-disabled={disabled}
      className="cursor-pointer rounded px-4 py-2 hover:bg-gray-100 focus:outline-none focus:ring-2 focus:ring-blue-500"
      onClick={disabled ? undefined : onClick}
      onKeyDown={(e) => {
        if (disabled) return
        if (e.key === 'Enter' || e.key === ' ') {
          e.preventDefault()
          onClick()
        }
      }}
    >
      {children}
    </div>
  )
}

// app/layout.tsx - 跳过导航
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="zh-CN">
      <body>
        <a
          href="#main-content"
          className="sr-only focus:not-sr-only focus:fixed focus:top-4 focus:left-4 focus:z-50 focus:rounded focus:bg-blue-600 focus:px-4 focus:py-2 focus:text-white"
        >
          跳过导航
        </a>
        <nav aria-label="主导航">
          <ul>
            <li><a href="/">首页</a></li>
            <li><a href="/dashboard">控制台</a></li>
            <li><a href="/settings">设置</a></li>
          </ul>
        </nav>
        <main id="main-content" tabIndex={-1}>
          {children}
        </main>
      </body>
    </html>
  )
}
```

**要点**：
- 优先使用原生 `<button>` 和 `<a>` 标签，它们天然支持键盘操作
- 自定义元素需要 `tabIndex={0}` 才能被 Tab 键聚焦，`tabIndex={-1}` 只能通过代码聚焦
- 跳过导航链接默认隐藏（`sr-only`），获得焦点时才显示
- 使用 `focus:ring` 提供清晰的焦点指示器

### 练习 2：添加 ARIA 属性

**思路**：为模态框添加 `role="dialog"` 和 `aria-modal="true"`，关联标题和描述。为标签页使用 `role="tablist"`、`role="tab"`、`role="tabpanel"` 的标准模式。为表单错误提示使用 `aria-invalid` 和 `aria-describedby`。

**答案**：

```tsx
// components/modal.tsx
'use client'

import { useEffect, useRef } from 'react'

interface ModalProps {
  isOpen: boolean
  onClose: () => void
  title: string
  description: string
  children: React.ReactNode
}

export function Modal({ isOpen, onClose, title, description, children }: ModalProps) {
  const closeRef = useRef<HTMLButtonElement>(null)

  useEffect(() => {
    if (isOpen) {
      closeRef.current?.focus()
    }
  }, [isOpen])

  useEffect(() => {
    function handleKeyDown(e: KeyboardEvent) {
      if (e.key === 'Escape') onClose()
    }
    if (isOpen) {
      document.addEventListener('keydown', handleKeyDown)
      return () => document.removeEventListener('keydown', handleKeyDown)
    }
  }, [isOpen, onClose])

  if (!isOpen) return null

  return (
    <div
      role="dialog"
      aria-modal="true"
      aria-labelledby="modal-title"
      aria-describedby="modal-desc"
      className="fixed inset-0 z-50 flex items-center justify-center bg-black/50"
    >
      <div className="rounded-lg bg-white p-6 shadow-xl">
        <h2 id="modal-title">{title}</h2>
        <p id="modal-desc">{description}</p>
        {children}
        <button ref={closeRef} onClick={onClose}>关闭</button>
      </div>
    </div>
  )
}

// components/tabs.tsx
'use client'

import { useState } from 'react'

interface Tab {
  id: string
  label: string
  content: React.ReactNode
}

export function Tabs({ tabs }: { tabs: Tab[] }) {
  const [activeId, setActiveId] = useState(tabs[0].id)

  return (
    <div>
      <div role="tablist" aria-label="内容标签页">
        {tabs.map(tab => (
          <button
            key={tab.id}
            role="tab"
            aria-selected={activeId === tab.id}
            aria-controls={`panel-${tab.id}`}
            id={`tab-${tab.id}`}
            tabIndex={activeId === tab.id ? 0 : -1}
            onClick={() => setActiveId(tab.id)}
          >
            {tab.label}
          </button>
        ))}
      </div>
      {tabs.map(tab => (
        <div
          key={tab.id}
          role="tabpanel"
          id={`panel-${tab.id}`}
          aria-labelledby={`tab-${tab.id}`}
          hidden={activeId !== tab.id}
          tabIndex={0}
        >
          {tab.content}
        </div>
      ))}
    </div>
  )
}

// components/form-field.tsx
export function FormField({ label, error, id }: {
  label: string
  error?: string
  id: string
}) {
  return (
    <div>
      <label htmlFor={id}>{label}</label>
      <input
        id={id}
        aria-invalid={!!error}
        aria-describedby={error ? `${id}-error` : undefined}
        className="border rounded px-3 py-2"
      />
      {error && (
        <p id={`${id}-error`} role="alert" className="text-red-500 text-sm">
          {error}
        </p>
      )}
    </div>
  )
}
```

**要点**：
- `aria-modal="true"` 告诉屏幕阅读器背景内容不可交互
- 标签页中非活跃的 tab 设置 `tabIndex={-1}`，只让活跃 tab 参与 Tab 键导航
- `aria-invalid` 和 `aria-describedby` 让屏幕阅读器自动读出错误信息
- `role="alert"` 会让屏幕阅读器立即宣布内容变化

## 十一、常见误区

1. **无障碍只是给盲人用的**：无障碍涵盖永久性障碍（失明）、暂时性障碍（手臂骨折）和情境性障碍（强光下看屏幕、嘈杂环境）。做好无障碍实际上提升了所有用户的体验。

2. **给所有元素加 `tabIndex={0}` 就是键盘可访问**：滥用 `tabIndex` 会导致 Tab 顺序混乱。原生的 `<button>`、`<a>`、`<input>` 本身就可以聚焦，不需要额外添加。只有自定义组件才需要 `tabIndex`。

3. **用 `aria-label` 替代可见的文字标签**：`aria-label` 只对屏幕阅读器可见，视力正常的用户看不到。优先使用 `<label>` 和可见文字，`aria-label` 只在视觉上已有暗示（如图标按钮）时使用。

4. **颜色对比度不重要，反正用户能看清**：WCAG 要求普通文本对比度至少 4.5:1，大文本至少 3:1。低对比度在强光、低亮度屏幕或色觉障碍用户面前会完全不可读。

## 十二、工程建议

1. **在 CI 中集成 axe-core 自动化测试**：使用 `@axe-core/react` 或 `cypress-axe` 在每次 PR 时自动检测无障碍问题，设置零违规阈值。

2. **使用 ESLint 插件 `eslint-plugin-jsx-a11y`**：在代码编写阶段就捕获常见的无障碍错误，如缺少 alt 属性、缺少 label 关联、不正确的 ARIA 角色。

3. **模态框实现焦点陷阱**：打开模态框后，Tab 键应该只在模态框内循环，不能跳到背景页面。关闭模态框后焦点应返回触发元素。

4. **所有动态内容使用 `aria-live` 区域**：表单提交结果、搜索结果更新、通知消息等动态内容变化，需要通过 `aria-live="polite"` 或 `role="alert"` 通知屏幕阅读器。
