# 第四课：套餐和用量限制

## 场景引入

你的 SaaS 产品开始有付费用户了，但问题也随之而来：免费版用户创建了 100 个项目占满了服务器资源，付费用户抱怨"我付了钱为什么和免费版一样"，财务要求按月统计每个团队的 API 调用次数来计费。你需要一套套餐系统——免费版限制 3 个项目、专业版 20 个、团队版 100 个——每次创建项目前检查用量限制，超额时提示用户升级。这不是简单的 if/else 判断，而是一套完整的用量追踪、限制检查和套餐管理机制。

## 学习目标

完成本课学习后，你将能够：

1. 设计订阅套餐系统
2. 实现用量追踪
3. 检查用量限制
4. 展示套餐信息和用量
5. 处理超额情况

## 二、获取团队套餐

```tsx
// lib/subscription.ts
import { prisma } from './prisma'
import { PLANS } from './plans'

export async function getTeamPlan(teamId: string) {
  const subscription = await prisma.subscription.findUnique({
    where: { teamId },
    include: { plan: true }
  })

  if (!subscription || subscription.status !== 'ACTIVE') {
    return PLANS.FREE
  }

  // 解析 plan 的 limits
  return {
    ...subscription.plan,
    limits: subscription.plan.limits as typeof PLANS.FREE.limits
  }
}

export async function getTeamUsage(teamId: string) {
  const now = new Date()
  const startOfMonth = new Date(now.getFullYear(), now.getMonth(), 1)

  // 获取本月用量
  const usage = await prisma.usageRecord.groupBy({
    by: ['action'],
    where: {
      teamId,
      createdAt: { gte: startOfMonth }
    },
    _sum: { quantity: true }
  })

  return usage.reduce((acc, item) => {
    acc[item.action] = item._sum.quantity || 0
    return acc
  }, {} as Record<string, number>)
}
```

## 三、用量检查

```tsx
// lib/limits.ts
import { getTeamPlan, getTeamUsage } from './subscription'
import { prisma } from './prisma'

export async function checkLimit(
  teamId: string,
  action: string,
  quantity = 1
): Promise<{ allowed: boolean; current: number; limit: number }> {
  const [plan, usage] = await Promise.all([
    getTeamPlan(teamId),
    getTeamUsage(teamId)
  ])

  const limit = plan.limits[action as keyof typeof plan.limits]
  const current = usage[action] || 0

  // -1 表示无限制
  if (limit === -1) {
    return { allowed: true, current, limit: -1 }
  }

  return {
    allowed: current + quantity <= limit,
    current,
    limit
  }
}

// 检查项目数量限制
export async function canCreateProject(teamId: string) {
  return checkLimit(teamId, 'projects')
}

// 检查成员数量限制
export async function canAddMember(teamId: string) {
  const [plan, memberCount] = await Promise.all([
    getTeamPlan(teamId),
    prisma.membership.count({ where: { teamId } })
  ])

  const limit = plan.limits.members

  return {
    allowed: limit === -1 || memberCount < limit,
    current: memberCount,
    limit
  }
}

// 记录用量
export async function recordUsage(
  teamId: string,
  action: string,
  quantity = 1
) {
  await prisma.usageRecord.create({
    data: {
      teamId,
      action,
      quantity
    }
  })
}
```

## 四、在 Server Actions 中使用

```tsx
// app/teams/[teamId]/projects/actions.ts
'use server'

import { canCreateProject, recordUsage } from '@/lib/limits'
import { prisma } from '@/lib/prisma'
import { requireTeamRole } from '@/lib/permissions'

export async function createProject(teamId: string, prevState: any, formData: FormData) {
  await requireTeamRole(teamId, 'MEMBER')

  // 检查用量限制
  const limitCheck = await canCreateProject(teamId)

  if (!limitCheck.allowed) {
    return {
      error: `已达项目数量上限（${limitCheck.limit}个），请升级套餐`
    }
  }

  // 创建项目
  const project = await prisma.project.create({
    data: {
      name: formData.get('name') as string,
      description: formData.get('description') as string,
      teamId,
      creatorId: await getCurrentUserId(),
    }
  })

  // 记录用量
  await recordUsage(teamId, 'projects')

  revalidatePath(`/teams/${teamId}/projects`)
  return { success: true }
}
```

### 5.1 用量卡片组件

```tsx
// components/UsageCard.tsx
interface UsageCardProps {
  title: string
  current: number
  limit: number
  icon?: string
}

export function UsageCard({ title, current, limit, icon }: UsageCardProps) {
  const unlimited = limit === -1
  const percentage = unlimited ? 0 : (current / limit) * 100
  const isWarning = percentage >= 80
  const isExceeded = percentage >= 100

  return (
    <div className="bg-white p-4 rounded-lg border">
      <div className="flex justify-between items-start mb-2">
        <span className="text-sm text-gray-500">{title}</span>
        {icon && <span>{icon}</span>}
      </div>
      <div className="text-2xl font-bold mb-2">
        {current}
        {!unlimited && <span className="text-sm text-gray-400 font-normal"> / {limit}</span>}
        {unlimited && <span className="text-sm text-gray-400 font-normal"> / 无限制</span>}
      </div>
      {!unlimited && (
        <div className="w-full bg-gray-200 rounded-full h-2">
          <div
            className={`h-2 rounded-full ${
              isExceeded ? 'bg-red-500' :
              isWarning ? 'bg-yellow-500' :
              'bg-blue-500'
            }`}
            style={{ width: `${Math.min(100, percentage)}%` }}
          />
        </div>
      )}
    </div>
  )
}
```

### 练习 2：实现用量追踪

**思路**：创建 UsageRecord 模型记录每次操作，通过 `action` 字段区分操作类型，按月统计时只查询当月记录。

**答案**：

```prisma
// prisma/schema.prisma（补充模型）
model UsageRecord {
  id        String   @id @default(cuid())
  action    String
  quantity  Int      @default(1)
  createdAt DateTime @default(now())

  team   Team   @relation(fields: [teamId], references: [id], onDelete: Cascade)
  teamId String

  @@index([teamId, action, createdAt])
}
```

```typescript
// lib/subscription.ts
import { prisma } from './prisma'

  const startOfMonth = new Date(now.getFullYear(), now.getMonth(), 1)

  const usage = await prisma.usageRecord.groupBy({

      createdAt: { gte: startOfMonth },
    },

    acc[item.action] = item._sum.quantity || 0
    return acc
  }, {} as Record<string, number>)
```

**要点**：
- UsageRecord 用 `@@index([teamId, action, createdAt])` 复合索引加速按月统计查询
- `getTeamUsage` 只统计当月记录，历史数据无需清理
- `recordUsage` 在每次操作成功后调用，与业务操作在同一个 Server Action 中执行

### 练习 3：实现用量检查

**思路**：先并行获取套餐信息和当前用量，再判断是否超额。检查逻辑要在 Server Action 中执行，前端只做展示优化。

**答案**：

```typescript
// lib/limits.ts
import { getTeamPlan, getTeamUsage } from './subscription'
import { prisma } from './prisma'

export async function checkLimit(
  teamId: string,
  action: string,
  quantity = 1
): Promise<{ allowed: boolean; current: number; limit: number }> {
  const [plan, usage] = await Promise.all([
    getTeamPlan(teamId),
    getTeamUsage(teamId),
  ])

  const limit = plan.limits[action as keyof typeof plan.limits]
  const current = usage[action] || 0

  if (limit === -1) {
    return { allowed: true, current, limit: -1 }
  }

  return {
    allowed: current + quantity <= limit,
    current,
    limit,
  }
}

export async function canCreateProject(teamId: string) {
  return checkLimit(teamId, 'projects')
}

export async function canAddMember(teamId: string) {
  const [plan, memberCount] = await Promise.all([
    getTeamPlan(teamId),
    prisma.membership.count({ where: { teamId } }),
  ])

  const limit = plan.limits.members

  return {
    allowed: limit === -1 || memberCount < limit,
    current: memberCount,
    limit,
  }
}

export async function canUploadFile(teamId: string, fileSize: number) {
  const result = await checkLimit(teamId, 'storage', fileSize)
  return result
}
```

**要点**：
- 用量检查和记录必须在同一个 Server Action 中完成：check → create → record
- `-1` 表示无限制，比用 `Infinity` 更清晰
- 前端在检查到超额时显示 `UpgradePrompt` 组件引导用户升级，但真正的拦截在服务端

## 常见误区

1. **"用量限制只在前端做"**：前端隐藏"创建项目"按钮只是 UI 优化，用户可以通过 API 直接创建。必须在 Server Action 中检查用量限制，前端只做展示。
2. **"项目删除后用量自动减少"**：用量记录是按操作类型累计的，删除项目不会自动减少 `projects` 的用量计数。你需要决定是按"当前存量"还是"累计创建量"计算，两种方案各有取舍。
3. **"套餐信息可以硬编码在前端"**：套餐配置（价格、限制）应该存在数据库中，通过 API 动态获取。硬编码在前端意味着每次调整套餐都要改代码重新部署。
4. **"用量检查不需要考虑并发"**：两个请求同时到达，都检查到"当前 2 个项目，限制 3 个"，都通过了检查，结果创建了 4 个项目。高并发场景需要用数据库的原子操作或事务来防止超卖。

## 工程建议

1. **用量检查和记录要在同一个 Server Action 中完成**：先 `checkLimit` 检查是否允许，再执行创建操作，再 `recordUsage` 记录用量。三步在同一个 Server Action 中顺序执行。
2. **用 `-1` 表示无限制**：`limits.apiCalls = -1` 表示不限制 API 调用次数，比用 `Infinity` 或 `999999` 更清晰。
3. **用量统计按月重置**：查询用量时只统计当月的 `UsageRecord`（`createdAt >= 月初`），不需要手动清理历史数据。
4. **超额时显示友好的升级提示**：不要只返回"已达上限"错误，要在 UI 中展示当前用量/限制的进度条和"升级套餐"按钮，引导用户付费。
