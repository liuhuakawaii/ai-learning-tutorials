# 第六课：审计日志

## 场景引入

某天你的 SaaS 产品出了一个事故：一个团队的所有项目突然被删除了。团队 Owner 说是"不知道谁干的"，管理员怀疑是某个成员误操作但没有证据。你开始排查，发现系统没有任何操作记录——谁在什么时间执行了什么操作，完全无从追溯。这让你意识到，一个生产级系统必须有审计日志：记录每一次关键操作（创建、删除、角色变更、设置修改），包括操作者、操作时间、操作内容和来源 IP。这不仅是问题排查的工具，更是合规要求和安全审计的基础。

## 学习目标

完成本课学习后，你将能够：

1. 理解审计日志的重要性
2. 设计审计日志的数据模型
3. 实现自动记录关键操作
4. 创建审计日志查看界面
5. 实现日志查询和筛选

## 一、为什么需要审计日志

### 1.1 审计日志的作用

```
安全审计：
  → 追踪谁在什么时候做了什么
  → 发现异常操作
  → 事故调查和取证

合规要求：
  → 满足法规要求（如 GDPR）
  → 提供操作证明
  → 数据变更追踪

问题排查：
  → 定位问题原因
  → 回溯操作历史
  → 恢复误操作
```

### 1.2 生活类比

```
银行交易记录：
  时间        操作        金额      余额
  2024-01-15  工资入账    +5000     15000
  2024-01-16  转账        -2000     13000
  2024-01-17  消费        -500      12500

审计日志：
  时间        用户        操作        目标        详情
  2024-01-15  张三        创建项目    项目A       {name: "项目A"}
  2024-01-16  李四        删除成员    王五        {role: "MEMBER"}
```

## 二、数据模型

### 2.1 审计日志表

```prisma
model AuditLog {
  id        String   @id @default(cuid())
  action    String   // 操作类型
  resource  String   // 资源类型
  resourceId String? // 资源 ID
  details   Json?    // 操作详情
  ipAddress String?  // IP 地址
  userAgent String?  // 浏览器标识

  user   User   @relation(fields: [userId], references: [id])

  // 所属团队（可选）

  teamId String?

  @@index([userId])
  @@index([teamId])
```

## 三、记录审计日志

### 3.1 核心记录函数

```tsx
// lib/audit.ts
import { prisma } from './prisma'
import { headers } from 'next/headers'

interface LogOptions {
  userId: string
  action: AuditAction
  resource: string
  resourceId?: string
  details?: Record<string, any>
  teamId?: string
}

export async function logAudit({
  userId,
  action,
  resource,
  resourceId,
  details,
  teamId,
}: LogOptions) {
  const headersList = await headers()

  await prisma.auditLog.create({
    data: {
      userId,
      action,
      resource,
      resourceId,
      details: details || undefined,
      teamId,
      ipAddress: headersList.get('x-forwarded-for') || headersList.get('x-real-ip'),
      userAgent: headersList.get('user-agent'),
    }
  })
}
```

## 四、审计日志查询

### 4.1 查询函数

```tsx
// lib/audit.ts
export async function getAuditLogs({
  teamId,
  userId,
  action,
  startDate,
  endDate,
  page = 1,
  pageSize = 50,
}: {
  teamId?: string
  userId?: string
  action?: string
  startDate?: Date
  endDate?: Date
  page?: number
  pageSize?: number
}) {
  const where = {
    AND: [
      teamId ? { teamId } : {},
      userId ? { userId } : {},
      action ? { action } : {},
      startDate || endDate ? {
        createdAt: {
          ...(startDate ? { gte: startDate } : {}),
          ...(endDate ? { lte: endDate } : {}),
        }
      } : {},
    ]
  }

  const [logs, total] = await Promise.all([
    prisma.auditLog.findMany({
      where,
      include: {
        user: {
          select: { id: true, name: true, email: true }
        }
      },
      orderBy: { createdAt: 'desc' },
      skip: (page - 1) * pageSize,
      take: pageSize,
    }),
    prisma.auditLog.count({ where }),
  ])

  return {
    logs,
    total,
    page,
    pageSize,
    totalPages: Math.ceil(total / pageSize),
  }
}
```

```tsx
'use client'

import { useRouter, useSearchParams } from 'next/navigation'

export function AuditLogFilters({ teamId }: { teamId: string }) {
  const router = useRouter()
  const searchParams = useSearchParams()

  function handleFilterChange(key: string, value: string) {
    const params = new URLSearchParams(searchParams.toString())

    if (value) {
      params.set(key, value)
    } else {
      params.delete(key)
    }

    params.delete('page')
    router.push(`?${params.toString()}`)
  }

  return (
    <div className="flex gap-4 mb-6">
      <select
        value={searchParams.get('action') || ''}
        onChange={e => handleFilterChange('action', e.target.value)}
        className="px-3 py-2 border rounded"
      >
        <option value="">所有操作</option>
        <option value="TEAM_CREATE">创建团队</option>

        <option value="MEMBER_REMOVE">移除成员</option>
```

### 练习 1：设计审计日志模型

**思路**：AuditLog 表需要记录操作者、操作类型、操作资源、操作详情和请求来源信息。通过复合索引覆盖常见查询场景。

**答案**：

```prisma
// prisma/schema.prisma
model AuditLog {
  id         String   @id @default(cuid())
  action     String
  resource   String
  resourceId String?
  details    Json?
  ipAddress  String?
  userAgent  String?
  createdAt  DateTime @default(now())

  user   User   @relation(fields: [userId], references: [id])
  userId String

  team   Team?  @relation(fields: [teamId], references: [id])
  teamId String?

  @@index([userId])
  @@index([teamId])
  @@index([action])
  @@index([createdAt])
  @@index([resource, resourceId])
}
```

- `details` 使用 JSON 类型，灵活存储不同操作的附加信息

### 练习 2：实现日志记录

**思路**：创建通用的 `logAudit` 函数，在各 Server Action 中调用。函数自动从请求头中提取 IP 和 User-Agent。

```typescript
// app/teams/[teamId]/actions.ts
'use server'

import { logAudit, AuditAction } from '@/lib/audit'
import { requireAuth } from '@/lib/auth'
import { requireTeamRole } from '@/lib/permissions'
import { prisma } from '@/lib/prisma'

export async function createTeam(prevState: any, formData: FormData) {
  const user = await requireAuth()

  const team = await prisma.team.create({
    data: {
      name: formData.get('name') as string,
      ownerId: user.id,
    },
  })

  await logAudit({
    userId: user.id,
    action: AuditAction.TEAM_CREATE,
    resource: 'team',
    resourceId: team.id,
    details: { name: team.name },
    teamId: team.id,
  })

  return { success: true }
}

export async function inviteMember(teamId: string, email: string) {
  const { userId } = await requireTeamRole(teamId, 'ADMIN')

  const invitation = await prisma.invitation.create({
    data: { email, teamId, role: 'MEMBER' },
  })

  await logAudit({
    userId,
    action: AuditAction.MEMBER_INVITE,
    resource: 'invitation',
    resourceId: invitation.id,
    details: { email, role: 'MEMBER' },
    teamId,
  })

  return { success: true }
}

export async function removeMember(teamId: string, memberId: string) {
  const { userId } = await requireTeamRole(teamId, 'ADMIN')

  await prisma.membership.delete({
    where: { id: memberId },
  })

  await logAudit({
    userId,
    action: AuditAction.MEMBER_REMOVE,
    resource: 'member',
    resourceId: memberId,
    details: { removedMemberId: memberId },
    teamId,
  })
}
```

**要点**：
- `logAudit` 通过 `headers()` 自动获取 IP 和 User-Agent，调用方无需手动传递
- 每个 Server Action 在业务逻辑成功后调用 `logAudit`，记录操作上下文
- `details` 记录操作的具体变更内容，便于事后审计

### 练习 3：实现日志查看

**思路**：创建日志列表页面，支持按操作类型和日期范围筛选，使用 Prisma 动态构建查询条件。

```typescript
  teamId,
  userId,
  action,
```

```typescript
                  </span>

                      {JSON.stringify(log.details, null, 2)}
                    </pre>
                  )}
                </td>
              </tr>
            ))}
          </tbody>
        </table>
      </div>

      {totalPages > 1 && (

          {Array.from({ length: totalPages }, (_, i) => (
            <a
              key={i}
              href={`?action=${action || ''}&page=${i + 1}`}

            >
              {i + 1}
            </a>
          ))}
        </div>
      )}
    </div>
  )
}
```

## 常见误区

1. **"审计日志就是 console.log"**：`console.log` 在服务器重启后就丢失了，无法持久化存储和查询。审计日志必须写入数据库，支持按时间、操作类型、用户筛选。
2. **"只记录失败的操作"**：成功的操作也需要记录——"谁删除了项目"比"谁尝试删除项目失败"更重要。审计日志要记录所有关键操作，无论成功还是失败。
3. **"审计日志可以修改和删除"**：审计日志的核心价值是不可篡改。日志记录只能追加，不能修改或删除。如果允许删除日志，审计就失去了意义。
4. **"所有操作都要记录"**：记录太多会让日志表膨胀，查询变慢。只记录关键操作（创建、删除、权限变更、设置修改），不需要记录每次页面访问。

## 工程建议

1. **用 `AuditAction` 枚举统一定义操作类型**：不要在代码中到处写字符串 `'CREATE_TEAM'`，定义一个 `AuditAction` 常量对象，避免拼写错误和不一致。
2. **记录 IP 地址和 User-Agent**：`headers().get('x-forwarded-for')` 获取客户端 IP，`headers().get('user-agent')` 获取浏览器标识。这些信息在安全事件调查时非常有用。
3. **审计日志表要加索引**：`@@index([userId])`、`@@index([teamId])`、`@@index([action])`、`@@index([createdAt])`——这四个索引覆盖了最常见的查询场景。
4. **日志查询支持分页和筛选**：管理后台的审计日志页面必须支持按操作类型筛选、按用户筛选、按时间范围筛选，并支持分页浏览。
