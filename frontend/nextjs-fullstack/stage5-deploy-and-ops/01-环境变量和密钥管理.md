# 第一课：环境变量和密钥管理

## 场景引入

你的 Next.js 项目在本地开发一切正常，推送到 GitHub 后同事 clone 下来却启动报错——原来你把数据库连接字符串写死在了代码里。更糟糕的是，你发现一个月前的一次提交中意外包含了 `.env.local` 文件，里面赫然写着生产环境的 SESSION_SECRET 和 SMTP 密码。即使你立刻删除了文件并重新提交，Git 历史中仍然保留着这条记录，任何人都能看到。密钥泄露是部署事故中最常见也最致命的问题之一。

## 学习目标

完成本课学习后，你将能够：

1. 理解环境变量的作用和分类
2. 正确配置 Next.js 环境变量
3. 安全地管理密钥
4. 避免常见的环境变量错误

---

## 一、环境变量基础

### 1.1 什么是环境变量

> **环境变量是运行时配置的一种方式，让你可以在不同环境（开发、测试、生产）使用不同的配置，而不需要修改代码。**

### 1.2 为什么需要环境变量

```
开发环境：
  DATABASE_URL = "postgresql://localhost:5432/mydb"
  API_URL = "http://localhost:3000"

生产环境：
  DATABASE_URL = "postgresql://prod-server:5432/mydb"
  API_URL = "https://myapp.com"

同样的代码，不同的配置
```

### 1.3 生活类比

```
环境变量 = 不同场合穿不同衣服

代码 = 你这个人
环境变量 = 你的衣服

在家：穿睡衣
上班：穿正装
运动：穿运动服

人是同一个人，但根据场合（环境）换不同的衣服（配置）
```

## 二、Next.js 环境变量

### 2.1 两种环境变量

```
服务端专用：
  → 只在服务端代码中可访问
  → 不会暴露给客户端
  → 用于：数据库连接、API 密钥

客户端可访问（NEXT_PUBLIC_ 前缀）：
  → 在客户端和服务端都可访问
  → 会被打包到客户端 JS 中
  → 用于：公开的 API URL、分析 ID
```

### 2.2 配置文件

```bash
# .env.local          本地环境变量（不提交到 git）
# .env.development    开发环境
# .env.production     生产环境
# .env                默认环境变量
```

### 2.3 优先级

```
.env.local（最高优先级）
  ↓
.env.development / .env.production
  ↓
.env（最低优先级）
```

## 三、配置示例

### 3.1 .env.local

```env
# 数据库
DATABASE_URL="postgresql://user:password@localhost:5432/mydb"

# Session
SESSION_SECRET="your-super-secret-key-at-least-32-chars"

# 邮件
SMTP_HOST="smtp.example.com"
SMTP_PORT="587"
SMTP_USER="your-email@example.com"
SMTP_PASS="your-email-password"

# 存储
S3_ACCESS_KEY="your-access-key"
S3_SECRET_KEY="your-secret-key"
S3_BUCKET="your-bucket"

# 客户端可访问
NEXT_PUBLIC_URL="http://localhost:3000"
NEXT_PUBLIC_GA_ID="G-XXXXXXXXXX"
```

### 3.2 类型安全

```tsx
// lib/env.ts
import { z } from 'zod'

const envSchema = z.object({
  DATABASE_URL: z.string().url(),
  SESSION_SECRET: z.string().min(32),
  SMTP_HOST: z.string(),
  SMTP_PORT: z.string().regex(/^\d+$/),
  NEXT_PUBLIC_URL: z.string().url(),
})

export const env = envSchema.parse(process.env)
```

## 四、安全最佳实践

### 4.1 不要提交敏感信息

```bash
# .gitignore
.env.local
.env.*.local
```

### 4.2 使用强密钥

```bash
# 生成强随机密钥
openssl rand -base64 32

# 或使用 Node.js
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

### 4.3 定期轮换密钥

```
密钥轮换计划：
  → Session Secret: 每 90 天
  → API Keys: 每 90 天
  → 数据库密码: 每 180 天
```

## 六、常见误区

### 6.1 客户端泄露密钥

```tsx
// ❌ 错误：在客户端代码中使用
const apiKey = process.env.API_KEY  // 客户端无法访问（正确行为）

// ❌ 危险：使用 NEXT_PUBLIC_ 前缀暴露密钥
const secretKey = process.env.NEXT_PUBLIC_SECRET_KEY  // 会暴露！

// ✅ 正确：服务端使用
// 在 Server Component 或 Server Action 中
const apiKey = process.env.API_KEY
```

### 6.2 环境变量未定义

```tsx
// ❌ 可能是 undefined
const dbUrl = process.env.DATABASE_URL

// ✅ 提供默认值或验证
const dbUrl = process.env.DATABASE_URL || 'postgresql://localhost:5432/dev'

// ✅ 或使用类型验证
const env = envSchema.parse(process.env)
```

## 参考答案

### 练习一：配置环境变量

**思路**：创建 `.env.local` 文件，按分类组织环境变量（数据库、认证、第三方服务、客户端公开），然后在代码中通过 `process.env` 引用。

**答案**：

```env
# .env.local

# 数据库
DATABASE_URL="postgresql://postgres:password@localhost:5432/myapp_dev"

# 认证
SESSION_SECRET="my-super-secret-key-at-least-32-characters-long"

# 邮件服务
SMTP_HOST="smtp.mailtrap.io"
SMTP_PORT="587"
SMTP_USER="your-mailtrap-user"
SMTP_PASS="your-mailtrap-pass"

# 客户端可访问
NEXT_PUBLIC_URL="http://localhost:3000"
NEXT_PUBLIC_GA_ID="G-XXXXXXXXXX"
```

```typescript
// lib/db.ts — 在服务端代码中使用
import { PrismaClient } from '@prisma/client'

const prisma = new PrismaClient({
  datasources: {
    db: {
      url: process.env.DATABASE_URL,
    },
  },
})

export default prisma
```

```typescript
// app/layout.tsx — 客户端可访问的变量
import Script from 'next/script'

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html>
      <body>
        {children}
        {process.env.NEXT_PUBLIC_GA_ID && (
          <Script
            src={`https://www.googletagmanager.com/gtag/js?id=${process.env.NEXT_PUBLIC_GA_ID}`}
            strategy="afterInteractive"
          />
        )}
      </body>
    </html>
  )
}
```

**要点**：
- `.env.local` 必须加入 `.gitignore`，绝不提交到版本控制
- `NEXT_PUBLIC_` 前缀的变量会被打包到客户端 JS 中，不要放密钥
- 建议同时维护一份 `.env.example`（提交到 Git），列出所有变量名但不含真实值

### 练习二：类型安全验证

**思路**：使用 Zod 定义环境变量的 Schema，在应用启动时校验所有必需变量，缺失或格式错误时立即报错，避免运行时才发现问题。

**答案**：

```typescript
// lib/env.ts
import { z } from 'zod'

const envSchema = z.object({
  DATABASE_URL: z.string().url('DATABASE_URL 必须是有效的 URL'),
  SESSION_SECRET: z.string().min(32, 'SESSION_SECRET 至少 32 个字符'),
  SMTP_HOST: z.string().min(1, 'SMTP_HOST 不能为空'),
  SMTP_PORT: z.string().regex(/^\d+$/, 'SMTP_PORT 必须是数字'),
  SMTP_USER: z.string().min(1, 'SMTP_USER 不能为空'),
  SMTP_PASS: z.string().min(1, 'SMTP_PASS 不能为空'),
  NEXT_PUBLIC_URL: z.string().url('NEXT_PUBLIC_URL 必须是有效的 URL'),
  NEXT_PUBLIC_GA_ID: z.string().optional(),
})

function validateEnv() {
  const parsed = envSchema.safeParse(process.env)

  if (!parsed.success) {
    console.error('❌ 环境变量校验失败：')
    for (const issue of parsed.error.issues) {
      console.error(`  - ${issue.path.join('.')}: ${issue.message}`)
    }
    process.exit(1)
  }

  return parsed.data
}

export const env = validateEnv()
```

```typescript
// app/api/health/route.ts — 使用校验后的 env 对象
import { env } from '@/lib/env'
import { NextResponse } from 'next/server'

export async function GET() {
  return NextResponse.json({
    status: 'ok',
    url: env.NEXT_PUBLIC_URL,
  })
}
```

**要点**：
- 在应用入口（如 `instrumentation.ts` 或首个 import）中触发校验，确保启动时就能发现问题
- `safeParse` 比 `parse` 更友好，可以收集所有错误一次性输出
- 使用 `process.exit(1)` 让部署平台（Vercel、Docker）感知到启动失败

### 练习三：部署配置

**思路**：在 Vercel Dashboard 中按环境（Production / Preview / Development）分别配置环境变量，然后验证敏感信息不会泄露到客户端。

**答案**：

```bash
# 通过 CLI 为不同环境添加变量
vercel env add DATABASE_URL production
vercel env add DATABASE_URL preview
vercel env add SESSION_SECRET production

# 拉取到本地查看（会写入 .env.local）
vercel env pull .env.local --environment development
```

```typescript
// 验证敏感信息未泄露：检查客户端 bundle
// 在浏览器控制台执行
console.log(process.env)  // 应该只看到 NEXT_PUBLIC_ 开头的变量

// 服务端验证：在 API 路由中检查
// app/api/debug/route.ts（仅开发环境使用）
import { NextResponse } from 'next/server'

export async function GET() {
  if (process.env.NODE_ENV === 'production') {
    return NextResponse.json({ error: 'Not available' }, { status: 404 })
  }

  return NextResponse.json({
    hasDatabaseUrl: !!process.env.DATABASE_URL,
    hasSessionSecret: !!process.env.SESSION_SECRET,
    publicUrl: process.env.NEXT_PUBLIC_URL,
    // 不要返回实际的密钥值，只检查是否存在
  })
}
```

**要点**：
- Vercel 的 Preview 环境应使用独立的测试数据库，避免影响生产数据
- 使用 `vercel env ls` 查看已配置的变量，确认每个环境都有完整配置
- 在浏览器 Network 面板中检查，确保没有密钥通过 API 响应或 JS bundle 泄露

## 七、工程建议

1. **启动时用 Zod 校验所有必需环境变量**：在应用入口文件中用 `z.object({}).parse(process.env)` 校验环境变量，缺失或格式错误时立即报错并退出，避免运行时才发现问题。

2. **为不同环境维护 `.env.example` 文件**：`.env.example` 提交到 Git，列出所有必需变量（不含真实值），新成员 clone 后只需填写自己的值即可启动。

3. **部署平台的环境变量按环境隔离**：Vercel 支持 Production / Preview / Development 三种环境分别配置变量。Preview 环境应该使用独立的测试数据库，避免影响生产数据。

4. **定期审计环境变量使用情况**：每季度检查一次是否有不再使用的变量、是否有意外使用 `NEXT_PUBLIC_` 前缀暴露的敏感信息。
