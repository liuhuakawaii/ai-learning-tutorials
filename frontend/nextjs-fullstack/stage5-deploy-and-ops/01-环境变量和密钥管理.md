# 环境变量和密钥管理

## 环境变量的分层

不同环境需要不同的配置：

```
开发环境 (.env.local)
├── DATABASE_URL=postgresql://localhost:5432/dev
├── NEXTAUTH_SECRET=dev-secret
└── STRIPE_KEY=sk_test_xxx

测试环境
├── DATABASE_URL=postgresql://test-db:5432/test
└── STRIPE_KEY=sk_test_xxx

生产环境
├── DATABASE_URL=postgresql://prod-db:5432/prod
└── STRIPE_KEY=sk_live_xxx
```

## Next.js 环境变量规则

| 文件 | 用途 | Git 提交 |
|------|------|----------|
| `.env` | 默认值 | 是 |
| `.env.local` | 本地覆盖 | 否 |
| `.env.development` | 开发环境 | 是 |
| `.env.production` | 生产环境 | 是 |

`.env.local` 优先级最高，不应该提交到 Git。

## 客户端 vs 服务端

```typescript
// 服务端变量：不会暴露给浏览器
DATABASE_URL=postgresql://...
NEXTAUTH_SECRET=xxx

// 客户端变量：必须以 NEXT_PUBLIC_ 开头
NEXT_PUBLIC_API_URL=https://api.example.com
NEXT_PUBLIC_GA_ID=G-XXXXXXXXXX
```

只有 `NEXT_PUBLIC_` 前缀的变量会打包到客户端 JS 中。

## 密钥管理原则

1. **永远不要提交密钥到 Git**
2. **生产环境密钥用环境变量注入**，不要写在代码里
3. **不同环境用不同密钥**
4. **定期轮换密钥**
5. **最小权限原则**——数据库用户只给需要的权限

## Vercel 环境变量

```bash
# 通过 CLI 设置
vercel env add DATABASE_URL production
vercel env add STRIPE_KEY production

# 通过 Dashboard 设置
# Project Settings → Environment Variables
```

## Docker 环境变量

```yaml
# docker-compose.yml
services:
  app:
    environment:
      - DATABASE_URL=${DATABASE_URL}
      - NEXTAUTH_SECRET=${NEXTAUTH_SECRET}
    env_file:
      - .env.production
```

### 练习三

```yaml
# docker-compose.yml
version: '3.8'
services:
  app:
    build: .
    ports:
      - "3000:3000"
    environment:
      - DATABASE_URL=${DATABASE_URL}
      - NEXTAUTH_SECRET=${NEXTAUTH_SECRET}
    depends_on:
      - db
  db:
    image: postgres:16
    environment:
      - POSTGRES_PASSWORD=${DB_PASSWORD}
      - POSTGRES_DB=${DB_NAME}
    volumes:
      - pgdata:/var/lib/postgresql/data
volumes:
  pgdata:
```
