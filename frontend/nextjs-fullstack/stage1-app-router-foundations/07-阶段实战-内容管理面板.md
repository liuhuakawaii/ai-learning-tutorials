# 第七课：阶段实战 — 内容管理面板

## 场景引入

你接到一个需求：为团队内部搭建一个简易的内容管理面板（CMS），用于管理博客文章。产品经理给了你一份清单——文章的增删改查、草稿和发布状态切换、列表的加载态和空状态、表单的错误提示——这些功能散落在前六课的知识点中。你需要把它们整合到一起，用 App Router 的路由和布局系统组织页面，用 Server Components 获取数据，用 Client Components 处理交互，用 Server Actions 处理表单提交，用 loading/error/empty 处理各种状态。这个实战项目就是对你第一阶段学习成果的全面检验。

## 学习目标

综合运用第一阶段所学知识，构建一个完整的内容管理面板（CMS），包含：

1. 文章列表、详情、创建、编辑和删除
2. 使用 App Router 的路由和布局系统
3. Server Components 和 Client Components 的正确组合
4. 完整的加载、错误和空状态处理
5. Server Actions 处理表单提交

## 二、数据模型

```tsx
// lib/db.ts
// 使用内存数据模拟数据库
export interface Post {
  id: string
  title: string
  content: string
  status: 'draft' | 'published'
  createdAt: string
  updatedAt: string
}

let posts: Post[] = [
  {
    id: '1',
    title: '第一篇文章',
    content: '这是第一篇文章的内容，介绍了这个 CMS 系统的功能。',
    status: 'published',
    createdAt: '2024-01-15T10:00:00Z',
    updatedAt: '2024-01-15T10:00:00Z',
  },
  {
    id: '2',
    title: '学习笔记：Next.js App Router',
    content: 'App Router 是 Next.js 13 引入的新路由系统...',
    status: 'draft',
    createdAt: '2024-01-16T14:30:00Z',
    updatedAt: '2024-01-16T14:30:00Z',
  },
]

export const db = {
  post: {
    findMany: async (options?: { status?: string }) => {
      await new Promise(resolve => setTimeout(resolve, 300)) // 模拟延迟
      if (options?.status) {
        return posts.filter(p => p.status === options.status)
      }
      return [...posts]
    },
    findUnique: async (id: string) => {
      await new Promise(resolve => setTimeout(resolve, 200))
      return posts.find(p => p.id === id) || null
    },
    create: async (data: Omit<Post, 'id' | 'createdAt' | 'updatedAt'>) => {
      const post: Post = {
        ...data,
        id: String(Date.now()),
        createdAt: new Date().toISOString(),
        updatedAt: new Date().toISOString(),
      }
      posts.push(post)
      return post
    },
    update: async (id: string, data: Partial<Post>) => {
      const index = posts.findIndex(p => p.id === id)
      if (index === -1) throw new Error('Post not found')
      posts[index] = {
        ...posts[index],
        ...data,
        updatedAt: new Date().toISOString(),
      }
      return posts[index]
    },
    delete: async (id: string) => {
      posts = posts.filter(p => p.id !== id)
    },
  },
}
```

## 八、Server Actions

```tsx
// app/(admin)/posts/actions.ts
'use server'

import { revalidatePath } from 'next/cache'
import { redirect } from 'next/navigation'
import { db } from '@/lib/db'

export async function createPost(formData: FormData) {
  const title = formData.get('title') as string
  const content = formData.get('content') as string
  const status = formData.get('status') as 'draft' | 'published'

  if (!title || title.length < 2) {
    return { error: '标题至少 2 个字' }
  }

  const post = await db.post.create({
    title,
    content: content || '',
    status: status || 'draft',
  })

  revalidatePath('/admin/posts')
  redirect(`/admin/posts/${post.id}`)
}

export async function updatePost(postId: string, formData: FormData) {
  const title = formData.get('title') as string
  const content = formData.get('content') as string
  const status = formData.get('status') as 'draft' | 'published'

  if (!title || title.length < 2) {
    return { error: '标题至少 2 个字' }
  }

  await db.post.update(postId, {
    title,
    content: content || '',
    status,
  })

  revalidatePath('/admin/posts')
  revalidatePath(`/admin/posts/${postId}`)
  redirect(`/admin/posts/${postId}`)
}

export async function deletePost(postId: string) {
  await db.post.delete(postId)
  revalidatePath('/admin/posts')
}
```

// components/PostForm.tsx
'use client'

import { useActionState } from 'react'

interface PostFormProps {
  post?: {
    title: string
    content: string
    status: string
  }
  action: (formData: FormData) => Promise<{ error?: string }>
}

export function PostForm({ post, action }: PostFormProps) {
  const [state, formAction, isPending] = useActionState(action, null)

  return (
    <form action={formAction} className="space-y-4">
      <div>
        <label htmlFor="title" className="block text-sm font-medium mb-1">
          标题
        </label>
        <input
          id="title"
          name="title"
          defaultValue={post?.title}
          required
          className="w-full px-3 py-2 border rounded"
        />
      </div>

      <div>
        <label htmlFor="content" className="block text-sm font-medium mb-1">
          内容
        </label>
        <textarea
          id="content"
          name="content"
          rows={10}
          defaultValue={post?.content}
          className="w-full px-3 py-2 border rounded"
        />
      </div>

      <div>
        <label htmlFor="status" className="block text-sm font-medium mb-1">
          状态
        </label>
        <select
          id="status"
          name="status"
          defaultValue={post?.status || 'draft'}
          className="w-full px-3 py-2 border rounded"
        >
          <option value="draft">草稿</option>
          <option value="published">发布</option>
        </select>
      </div>

      {state?.error && (
        <p className="text-red-500">{state.error}</p>
      )}

      <div className="flex gap-2">
        <button
          type="submit"
          disabled={isPending}
          className="px-4 py-2 bg-blue-500 text-white rounded hover:bg-blue-600 disabled:opacity-50"
        >
          {isPending ? '保存中...' : '保存'}
        </button>
      </div>

## 常见误区

1. **"把所有状态管理都放在 Client Component 里"**：文章列表的数据获取应该在 Server Component 中完成，只有搜索框、排序选择器等交互部分才需要 Client Component。不要为了方便把整个页面标记为 `'use client'`。
2. **"表单提交后不需要刷新缓存"**：Server Action 创建或更新文章后，必须调用 `revalidatePath('/admin/posts')` 来清除列表页的缓存，否则用户在列表页看不到最新数据。
3. **"确认删除用 `confirm()` 就够了"**：浏览器原生的 `confirm()` 弹窗样式丑陋且无法自定义。生产环境应该用自定义的 Modal 组件，提供更好的用户体验和一致的视觉风格。
4. **"数据模型用 `any` 类型就行"**：即使是演示项目，也应该为数据模型（如 Post）定义完整的 TypeScript 接口。这不仅提供类型安全，还能让 IDE 提供更好的自动补全。

## 工程建议

1. **先设计数据模型再写页面**：在动手写页面之前，先定义好 Post 的类型接口和模拟数据库（或 Prisma schema），这样页面的代码可以围绕真实数据结构来写。
2. **用路由分组隔离后台和前台**：`(admin)` 路由组放后台管理页面，用独立的 layout 包含侧边栏；未来扩展前台时用 `(public)` 路由组，两套布局互不影响。
3. **表单组件要支持"新建"和"编辑"两种模式**：通过 `post` prop 是否存在来判断模式，用 `defaultValue` 填充编辑数据，复用同一个 `PostForm` 组件。
4. **验收清单驱动开发**：按照课程提供的验收清单逐项检查，确保每种状态（加载、错误、空、正常）都有对应的 UI，每个操作（创建、编辑、删除）都有正确的反馈。
