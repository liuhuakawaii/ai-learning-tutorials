# 第四课：数据获取、缓存和重新验证

## 场景引入

你的 Dashboard 页面需要同时展示用户信息、最近文章和通知列表，三个数据源分别来自不同的 API。你发现每次刷新页面，三个请求都在串行执行——先等用户信息返回，再请求文章列表，最后拿通知——总耗时是三者之和。更糟糕的是，用户的头像和名称在每个页面都要显示，你却在每个 Server Component 里都查了一次数据库，导致数据库压力暴增。你需要理解 Next.js 的缓存机制和并行请求策略，才能让页面又快又省资源。

## 学习目标

完成本课学习后，你将能够：

1. 理解 Server Components 中的数据获取方式
2. 掌握 fetch 缓存和 React 缓存的区别
3. 学会使用 `revalidate` 控制缓存过期
4. 理解 `revalidatePath` 和 `revalidateTag` 的用法
5. 知道如何避免常见的数据获取陷阱

## 一、Server Components 中的数据获取

### 1.1 直接 async/await

在 Server Component 中，你可以直接使用 async/await 获取数据：

```tsx
// app/posts/page.tsx
export default async function PostsPage() {
  // 直接在组件中获取数据
  const posts = await db.post.findMany({
    orderBy: { createdAt: 'desc' }
  })

  return (
    <ul>
      {posts.map(post => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}
```

### 1.2 使用 fetch

```tsx
export default async function WeatherPage() {
  const res = await fetch('https://api.weather.com/today')
  const data = await res.json()

  return <div>今天温度: {data.temperature}°C</div>
}
```

### 1.3 并行数据获取

```tsx
// ❌ 串行获取（慢）
export default async function DashboardPage() {
  const user = await getUser()      // 等待 100ms
  const posts = await getPosts()    // 等待 200ms
  const stats = await getStats()    // 等待 150ms
  // 总耗时: 450ms
}

// ✅ 并行获取（快）
export default async function DashboardPage() {
  const [user, posts, stats] = await Promise.all([
    getUser(),    // 同时开始
    getPosts(),   // 同时开始
    getStats()    // 同时开始
  ])
  // 总耗时: 200ms（取最长的那个）
}
```

### 1.4 请求去重

Next.js 会自动对相同请求进行去重：

```tsx
// 这两个组件都请求同一个 API
async function UserHeader() {
  const user = await fetch('/api/user')  // 请求 A
  return <h1>{user.name}</h1>
}

async function UserAvatar() {
  const user = await fetch('/api/user')  // 请求 A（不会重复请求）
  return <img src={user.avatar} />
}

export default function Page() {
  return (
    <div>
      <UserHeader />
      <UserAvatar />
    </div>
  )
}
```

## 二、缓存机制

### 2.1 两层缓存

```
请求流程：

浏览器请求 /dashboard
  ↓
Next.js 检查第一层缓存：数据缓存（Data Cache）
  ↓ 命中 → 直接返回缓存的数据
  ↓ 未命中
执行 Server Component
  ↓
组件内的 fetch 请求
  ↓
Next.js 检查第二层缓存：完整路由缓存（Full Route Cache）
  ↓ 命中 → 返回缓存的 HTML
  ↓ 未命中
执行数据获取 → 渲染 HTML → 缓存 → 返回
```

### 2.2 fetch 缓存策略

默认情况下，`fetch` 请求会被缓存：

```tsx
// 默认会被缓存（STATIC）
const res = await fetch('https://api.example.com/data')

// 明确不缓存（DYNAMIC）
const res = await fetch('https://api.example.com/data', {
  cache: 'no-store'
})

// 设置缓存过期时间
const res = await fetch('https://api.example.com/data', {
  next: { revalidate: 60 }  // 60 秒后可以重新验证
})
```

### 2.3 三种缓存策略

```
策略              行为                          使用场景
──────────────────────────────────────────────────────────
force-cache      始终使用缓存                   静态数据，几乎不变
(default)        构建时获取一次，之后用缓存
no-store         每次请求都重新获取             用户特定数据、实时数据
revalidate: N    缓存 N 秒，过期后重新验证      偶尔变化的数据
```

## 三、重新验证

### 3.1 基于时间的重新验证（Time-based）

```tsx
// 每 60 秒可以重新验证一次
export const revalidate = 60

export default async function NewsPage() {
  const news = await fetch('https://api.news.com/latest', {
    next: { revalidate: 60 }
  })

  return <NewsList items={news} />
}
```

流程：

```
0:00 用户访问 → 获取最新数据 → 缓存
0:30 用户访问 → 返回缓存
1:00 用户访问 → 返回缓存（但标记为 stale）
1:01 用户访问 → 后台重新获取数据 → 更新缓存 → 返回新数据
```

### 3.2 基于标签的重新验证（Tag-based）

用标签标记缓存，然后按标签清除：

```tsx
// 获取数据时标记标签
async function getPosts() {
  return fetch('https://api.example.com/posts', {
    next: { tags: ['posts'] }
  })
}

// 在 Server Action 中按标签清除缓存
'use server'

import { revalidateTag } from 'next/cache'

export async function createPost(data) {
  await db.post.create({ data })
  revalidateTag('posts')  // 清除所有标记为 'posts' 的缓存
}
```

### 3.3 基于路径的重新验证（Path-based）

```tsx
'use server'

import { revalidatePath } from 'next/cache'

export async function updatePost(id, data) {
  await db.post.update({ where: { id }, data })

  // 重新验证特定路径
  revalidatePath('/posts')
  revalidatePath(`/posts/${id}`)
}
```

### 3.4 revalidateTag vs revalidatePath

```
revalidateTag('posts')
  → 清除所有标记为 'posts' 的缓存
  → 不管这些数据在哪个页面被使用
  → 适合：数据被多个页面引用

revalidatePath('/dashboard')
  → 重新验证整个 /dashboard 路由
  → 影响该路径下的所有数据
  → 适合：页面数据来自多个来源
```

## 四、动态函数

### 4.1 使路由变为动态

使用以下函数会让整个路由变为动态（不缓存）：

```tsx
import { cookies, headers } from 'next/headers'

export default async function Page() {
  // 使用 cookies() 会让路由变为动态
  const cookieStore = await cookies()
  const theme = cookieStore.get('theme')

  // 使用 headers() 会让路由变为动态
  const headersList = await headers()
  const userAgent = headersList.get('user-agent')

  return <div>...</div>
}
```

```
静态路由 vs 动态路由：

静态路由：
  → 构建时生成 HTML
  → 所有用户看到相同内容
  → 可以部署到 CDN

动态路由：
  → 每次请求时生成 HTML
  → 不同用户可能看到不同内容
  → 需要服务器运行
```

### 4.2 搜索参数使路由动态

```tsx
// 只要使用了 searchParams，路由就变成动态
export default async function Page({
  searchParams
}: {
  searchParams: Promise<{ query?: string }>
}) {
  const { query } = await searchParams

  return <div>搜索: {query}</div>
}
```

## 常见误区

### 6.1 陷阱：在 Client Component 中直接查数据库

```tsx
// ❌ 错误：Client Component 不能访问数据库
'use client'

export default function UserList() {
  const users = await db.user.findMany()  // 报错！
  return <ul>...</ul>
}
```

```tsx
// ✅ 正确：在 Server Component 中获取数据，传给 Client Component
// app/page.tsx
import UserList from './UserList'

export default async function Page() {
  const users = await db.user.findMany()
  return <UserList users={users} />
}

// app/UserList.tsx
'use client'
export default function UserList({ users }) {
  return <ul>...</ul>
}
```

### 6.2 陷阱：请求瀑布流

```tsx
// ❌ 瀑布流：每个 await 都要等前一个完成
export default async function Page() {
  const user = await getUser()           // 等 100ms
  const team = await getTeam(user.teamId) // 等 200ms（依赖 user）
  const projects = await getProjects(team.id) // 等 150ms（依赖 team）
  // 总耗时: 450ms
}

// ✅ 并行获取无依赖的数据
export default async function Page() {
  const user = await getUser()  // 必须先获取

  // 这两个可以并行
  const [team, recentPosts] = await Promise.all([
    getTeam(user.teamId),
    getRecentPosts(user.id)
  ])

  return <div>...</div>
}
```

### 6.3 陷阱：忘记缓存导致重复请求

```tsx
// ❌ 每次渲染都请求（没有缓存）
export default async function Page() {
  const data = await fetch('https://api.example.com/data')
  // ...
}

// ✅ 使用缓存
export default async function Page() {
  const data = await fetch('https://api.example.com/data', {
    next: { revalidate: 60 }
  })
  // ...
}
```

## 工程建议

1. **无依赖的数据用 `Promise.all` 并行获取**：Dashboard 页面通常需要多个数据源，把没有依赖关系的请求放在 `Promise.all` 中并行执行，总耗时取最长的那个，而不是所有请求之和。
2. **用户特定数据不要缓存**：用户头像、权限、个人设置等数据每次请求都应该重新获取（`cache: 'no-store'`），否则用户 A 可能看到用户 B 的数据。
3. **用 `revalidateTag` 做精确缓存失效**：比起 `revalidatePath`（重新验证整个路由），`revalidateTag` 可以只清除特定数据的缓存，适合数据被多个页面引用的场景。
4. **注意 `cookies()` 和 `headers()` 的隐式副作用**：在 Server Component 中调用 `cookies()` 或 `headers()` 会让整个路由变成动态渲染，即使你没有显式设置 `no-store`。如果只需要读取某个特定值，考虑用中间件提取。

## 参考答案

### 练习 1：实现带缓存的数据展示

**思路**：使用 `revalidate` 页面级配置控制缓存过期时间。设置为 300 秒（5 分钟），在缓存有效期内多次访问返回相同数据，过期后重新生成。

**答案**：

```tsx
// app/weather/page.tsx
export const revalidate = 300

async function getWeather() {
  // 模拟 API 调用
  await new Promise(resolve => setTimeout(resolve, 200))
  return {
    city: '北京',
    temperature: 22,
    condition: '晴',
    humidity: 45,
    updatedAt: new Date().toISOString(),
  }
}

export default async function WeatherPage() {
  const weather = await getWeather()

  return (
    <div style={{ padding: '20px' }}>
      <h1>{weather.city}天气</h1>
      <p>温度: {weather.temperature}°C</p>
      <p>天气: {weather.condition}</p>
      <p>湿度: {weather.humidity}%</p>
      <p style={{ color: '#666', fontSize: '14px' }}>
        数据更新时间: {weather.updatedAt}
      </p>
      <p style={{ color: '#999', fontSize: '12px' }}>
        缓存有效期: 5 分钟（300 秒）
      </p>
    </div>
  )
}
```

验证方法：连续刷新页面，5 分钟内 `updatedAt` 不会变化（命中缓存）；5 分钟后刷新，`updatedAt` 更新（缓存过期，重新渲染）。

**要点**：
- `export const revalidate = 300` 是页面级缓存配置，单位是秒
- 缓存有效期内，所有用户看到的是同一份缓存数据
- 缓存过期后，下一个请求会触发重新渲染，新数据替换旧缓存
- 适合不常变化但需要定期更新的数据，如天气、新闻列表

### 练习 2：并行数据获取

**思路**：使用 `Promise.all` 同时发起多个数据请求，总耗时等于最慢的那个请求，而不是所有请求之和。避免串行 `await` 导致的瀑布式请求。

**答案**：

```tsx
// app/dashboard/page.tsx
interface User {
  name: string
  avatar: string
}

interface Post {
  id: number
  title: string
}

interface Notification {
  id: number
  message: string
}

async function getUser(): Promise<User> {
  await new Promise(resolve => setTimeout(resolve, 100))
  return { name: '张三', avatar: '/avatar.png' }
}

async function getPosts(): Promise<Post[]> {
  await new Promise(resolve => setTimeout(resolve, 200))
  return [
    { id: 1, title: 'Next.js 入门指南' },
    { id: 2, title: 'React Server Components 详解' },
  ]
}

async function getNotifications(): Promise<Notification[]> {
  await new Promise(resolve => setTimeout(resolve, 150))
  return [
    { id: 1, message: '有人评论了你的文章' },
    { id: 2, message: '你的文章被收藏了' },
  ]
}

export default async function DashboardPage() {
  const [user, posts, notifications] = await Promise.all([
    getUser(),
    getPosts(),
    getNotifications(),
  ])

  return (
    <div style={{ padding: '20px' }}>
      <h1>欢迎，{user.name}</h1>
      <section>
        <h2>最新文章</h2>
        <ul>
          {posts.map(post => (
            <li key={post.id}>{post.title}</li>
          ))}
        </ul>
      </section>
      <section>
        <h2>通知</h2>
        <ul>
          {notifications.map(n => (
            <li key={n.id}>{n.message}</li>
          ))}
        </ul>
      </section>
    </div>
  )
}
```

**要点**：
- `Promise.all` 让三个请求同时发起，总耗时约 200ms（最慢的那个），而不是 450ms（串行之和）
- 如果某个请求失败，整个 `Promise.all` 会 reject，需要用 try/catch 或 `Promise.allSettled` 处理
- 每个数据获取函数独立定义，便于复用和测试
- Server Component 中可以直接 `await`，不需要 `useEffect`

### 练习 3：Server Action 重新验证

**思路**：使用 Server Action 处理表单提交，在服务端操作数据库后调用 `revalidatePath` 清除缓存，触发页面重新渲染，自动显示最新数据。

**答案**：

```tsx
// app/posts/page.tsx
import { createPost } from './actions'

interface Post {
  id: number
  title: string
  createdAt: string
}

// 模拟数据库
const posts: Post[] = [
  { id: 1, title: '第一篇文章', createdAt: '2024-01-01' },
  { id: 2, title: '第二篇文章', createdAt: '2024-01-02' },
]

async function getPosts(): Promise<Post[]> {
  await new Promise(resolve => setTimeout(resolve, 100))
  return [...posts]
}

export default async function PostsPage() {
  const posts = await getPosts()

  return (
    <div style={{ padding: '20px' }}>
      <h1>文章列表</h1>
      <form action={createPost} style={{ marginBottom: '20px' }}>
        <input
          name="title"
          placeholder="文章标题"
          required
          style={{ padding: '8px', marginRight: '8px' }}
        />
        <button type="submit" style={{ padding: '8px 16px' }}>
          创建
        </button>
      </form>
      <ul>
        {posts.map(post => (
          <li key={post.id}>
            {post.title} <span style={{ color: '#999' }}>({post.createdAt})</span>
          </li>
        ))}
      </ul>
    </div>
  )
}
```

```tsx
// app/posts/actions.ts
'use server'

import { revalidatePath } from 'next/cache'

// 模拟数据库操作
const posts = [
  { id: 1, title: '第一篇文章', createdAt: '2024-01-01' },
  { id: 2, title: '第二篇文章', createdAt: '2024-01-02' },
]

export async function createPost(formData: FormData) {
  const title = formData.get('title') as string
  if (!title || title.trim() === '') {
    return { error: '标题不能为空' }
  }

  posts.push({
    id: Date.now(),
    title: title.trim(),
    createdAt: new Date().toISOString().split('T')[0],
  })

  // 重新验证 /posts 路径的缓存，触发页面重新渲染
  revalidatePath('/posts')
}
```

**要点**：
- `'use server'` 标记的文件导出的函数会成为 Server Actions
- `revalidatePath('/posts')` 清除 `/posts` 路径的缓存，下次访问时重新渲染
- 表单提交后页面会自动刷新，不需要手动调用 `router.refresh()`
- Server Action 可以直接操作数据库，不需要额外的 API Route
- 记得验证输入，Server Action 暴露为 HTTP 端点，任何人都可以调用

## 八、小结

```
本课核心要点：

1. Server Component 可以直接用 async/await 获取数据
2. fetch 默认会被缓存，可以用 cache: 'no-store' 或 revalidate 控制
3. revalidate 基于时间，revalidateTag 基于标签，revalidatePath 基于路径
```
