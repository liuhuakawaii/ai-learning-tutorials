# 05 - 内存管理

## 场景引入

在 Stage 1 中，我们学习了 WASM 的线性内存模型——一块连续的字节数组，通过 `memory.grow` 扩展。现在用 Rust 开发 WASM，内存管理变成了编译器自动处理的事情。

但这并不意味着可以完全忽略内存。Rust 的所有权系统保证了编译期内存安全，但线性内存的分配策略、增长行为、内存泄漏的表现形式在 WASM 环境中都和原生环境不同。理解这些差异，才能写出体积小、性能高的 WASM 模块。

## 学习目标

- 理解 WASM 线性内存模型的工作原理
- 掌握 Rust 堆分配器在 WASM 中的行为
- 了解内存增长策略及其性能影响
- 学会检测和避免内存泄漏
- 掌握 wasm-opt 优化技巧

## WASM 线性内存模型

WASM 的内存是一块连续的、可增长的字节数组：

```
线性内存布局：
┌─────────────────────────────────────────────────┐
│ 静态数据区 │ 堆（→增长） │ ... │ 栈（←增长） │
└─────────────────────────────────────────────────┘
地址：0 ──────────────────────────────────── max
```

关键特性：
- 以 **64KB 页** 为单位增长，`memory.grow(1)` 增加 64KB
- 默认最大 4GB（2^32 字节）
- 线性内存是 WASM 实例私有的，JS 通过 `ArrayBuffer` 访问

```rust
use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub fn check_memory() {
    let memory = wasm_bindgen::memory();
    let size = memory.buffer().byte_length();
    web_sys::console::log_1(
        &format!("当前内存: {} 字节 ({} 页)", size, size / 65536).into()
    );
}
```

## Rust 堆分配器（Allocator）

WASM 没有操作系统提供 `malloc`/`free`。wasm-pack 自动切换到 `dlmalloc`（Doug Lea's malloc），这是纯 Rust 实现的通用分配器。

```
Rust 代码：let v = vec![1, 2, 3];
    ↓
调用 allocator.alloc(size, align)
    ↓
dlmalloc 在线性内存的堆区域分配空间
    ↓
返回指针（线性内存中的偏移量）
    ↓
drop(v) → allocator.dealloc(ptr, size, align)
```

| 分配器 | 代码体积 | 碎片率 | 速度 | 说明 |
|--------|---------|--------|------|------|
| dlmalloc（默认） | ~10KB | 中等 | 快 | 通用场景 |
| wee_alloc | ~1KB | 较高 | 较慢 | 已不推荐 |

## 内存增长策略

当堆分配请求超过当前剩余空间时，运行时调用 `memory.grow`：

```rust
#[wasm_bindgen]
pub fn demonstrate_growth() {
    let memory = wasm_bindgen::memory();
    let initial = memory.buffer().byte_length();

    // 分配大量数据触发增长
    let mut big_vec: Vec<u8> = Vec::new();
    for _ in 0..100 {
        big_vec.extend_from_slice(&[0u8; 10240]); // 每次 10KB
    }

    let final_size = memory.buffer().byte_length();
    web_sys::console::log_1(
        &format!("初始: {}KB → 最终: {}KB", initial / 1024, final_size / 1024).into()
    );
}
```

`memory.grow` 是昂贵操作：
1. 分配更大的 ArrayBuffer
2. 复制旧数据到新缓冲区
3. 更新所有引用

**最佳实践：预分配足够内存**：

```rust
#[wasm_bindgen]
pub fn preallocate_demo() {
    let mut buffer: Vec<u8> = Vec::with_capacity(1024 * 1024); // 预分配 1MB
    // 后续使用不超过 1MB 时不会触发 grow
    for i in 0..1000 {
        buffer.push(i as u8);
    }
}
```

## 内存泄漏在 WASM 中的表现

Rust 的所有权系统防止了大部分内存泄漏，但以下场景仍可能导致泄漏：

### 1. Closure::forget()

```rust
#[wasm_bindgen]
pub fn leaking_closure() {
    // 每次调用都泄漏一个闭包
    let closure = Closure::wrap(Box::new(move || {
        web_sys::console::log_1(&"永远不会释放".into());
    }) as Box<dyn FnMut()>);
    closure.forget(); // 阻止自动释放
}
```

### 2. 循环引用（Rc/Arc + RefCell）

```rust
use std::cell::RefCell;
use std::rc::Rc;

fn circular_reference() {
    let a: Rc<RefCell<Option<Rc<RefCell<i32>>>>> = Rc::new(RefCell::new(None));
    let b = Rc::new(RefCell::new(Some(a.clone())));
    *a.borrow_mut() = Some(b.clone()); // a→b→a 循环引用
}
```

### 3. 静态集合不断增长

```rust
use std::collections::HashMap;
use std::sync::Mutex;

static CACHE: Mutex<Option<HashMap<String, String>>> = Mutex::new(None);

fn cache_leak(key: &str, value: &str) {
    let mut cache = CACHE.lock().unwrap();
    if cache.is_none() { *cache = Some(HashMap::new()); }
    // 缓存无限增长，永不清理
    cache.as_mut().unwrap().insert(key.to_string(), value.to_string());
}
```

### 检测内存泄漏

```rust
#[wasm_bindgen]
pub fn monitor_memory() {
    let memory = wasm_bindgen::memory();
    let initial = memory.buffer().byte_length();

    // 执行待检测的操作
    for _ in 0..1000 {
        let _data = Box::new([0u8; 1024]); // Box 在此 drop，不会泄漏
    }

    let final_size = memory.buffer().byte_length();
    if final_size > initial {
        web_sys::console::warn_1(&"⚠️ 检测到内存增长".into());
    } else {
        web_sys::console::log_1(&"✅ 内存稳定".into());
    }
}
```

## wasm-opt 优化

`wasm-opt` 是 Binaryen 的优化器，能显著减小 WASM 体积：

```bash
# 体积优化（适合生产）
wasm-opt -Oz --strip-debug --strip-producers -o optimized.wasm input.wasm

# 速度优化（适合计算密集型）
wasm-opt -O4 --optimize-level 4 -o fast.wasm input.wasm

# 查看效果
ls -la input.wasm optimized.wasm
```

优化效果示例：

```
未优化:  156KB
-O2:     89KB  (-43%)
-Oz:     72KB  (-54%)
-Oz + strip: 65KB  (-58%)
```

wasm-pack 在 release 模式下自动调用 wasm-opt：

```bash
wasm-pack build --release  # 自动优化
wasm-pack build --dev      # 跳过优化（编译更快）
```

## 内存对齐与性能

WASM 内存访问遵循对齐规则。对齐的访问更快：

```rust
#[repr(C)]  // 自然对齐
struct AlignedStruct {
    a: u8,       // 偏移 0
    _pad: [u8; 3], // 填充
    b: u32,      // 偏移 4（对齐）
    c: u64,      // 偏移 8（对齐）
}
// 总大小: 16 字节

#[repr(packed)] // 紧凑布局
struct PackedStruct {
    a: u8,   // 偏移 0
    b: u32,  // 偏移 1（未对齐）
    c: u64,  // 偏移 5（未对齐）
}
// 总大小: 13 字节，但访问可能更慢
```

WASM 虚拟机通常能处理未对齐访问，但性能可能受影响。对于需要与 JS 共享的结构体，`repr(C)` 保证字段顺序可预测。

## 常见误区

### 1. 忽略 Vec 容量与长度区别

```rust
let mut v: Vec<u8> = Vec::with_capacity(1024);
// v.len() == 0，但已分配 1024 字节
```

`with_capacity` 只影响容量，不影响长度。

### 2. 过度 clone 导致内存峰值

```rust
let data = vec![0u8; 1_000_000]; // 1MB
let copy = data.clone();          // 再分配 1MB
// 此时内存中有 2MB
```

优先使用引用（`&[u8]`）而非 clone。

### 3. 认为 WASM 内存会自动收缩

`memory.grow` 只能增长，不能收缩。即使 Rust 释放了所有堆分配，页数不会减少。

### 4. 忘记 wasm-opt 优化

未优化的 WASM 通常比优化后大 30-50%。生产构建始终用 `--release`。

## 工程建议

1. **预分配避免频繁 grow**。使用 `Vec::with_capacity`、`String::with_capacity`。
2. **监控内存使用**。开发阶段定期检查 `memory.buffer().byte_length()`。
3. **谨慎使用 `forget()`**。对于一次性回调用 `Closure::once`。
4. **分块处理大数据**。不要一次性加载大文件，控制内存峰值。

## 小结

- **线性内存模型**：连续字节数组，按 64KB 页增长
- **分配器**：dlmalloc 自动管理堆分配
- **内存增长**：`memory.grow` 昂贵，应预分配减少触发
- **内存泄漏**：`forget()`、循环引用、静态集合是常见源
- **wasm-opt**：可减少 30-50% 的 WASM 体积
- **内存对齐**：`repr(C)` 保证可预测布局

## 参考答案

### 练习一

```rust
use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub fn allocate_and_check(size: u32) -> u32 {
    let _data: Vec<u8> = vec![0u8; size as usize];
    let memory = wasm_bindgen::memory();
    (memory.buffer().byte_length() / 65536) as u32
}
```

WASM 内存按 64KB 页增长。`_data` 在函数返回时 drop，但页数不减少。

### 练习二

```rust
use wasm_bindgen::prelude::*;
use js_sys::Date;

#[wasm_bindgen]
pub fn bench_no_capacity(n: u32) -> f64 {
    let start = Date::now();
    let mut v: Vec<u32> = Vec::new();
    for i in 0..n { v.push(i); }
    Date::now() - start
}

#[wasm_bindgen]
pub fn bench_with_capacity(n: u32) -> f64 {
    let start = Date::now();
    let mut v: Vec<u32> = Vec::with_capacity(n as usize);
    for i in 0..n { v.push(i); }
    Date::now() - start
}
```

无预分配时 Vec 每次容量不足会重新分配（2倍增长）并复制。n=1000000 时预分配通常快 2-5 倍。

### 练习三

```rust
use wasm_bindgen::prelude::*;
use js_sys::Date;

#[repr(C)]
struct Aligned { a: u8, b: u32, c: u64 }

#[repr(packed)]
struct Packed { a: u8, b: u32, c: u64 }

#[wasm_bindgen]
pub fn get_sizes() -> String {
    format!("Aligned: {} bytes, Packed: {} bytes",
        std::mem::size_of::<Aligned>(),
        std::mem::size_of::<Packed>())
}
```

`Aligned` 为 16 字节（含填充），`Packed` 为 13 字节。填充保证字段自然对齐，访问更快。
