# 05 - 密码学计算：浏览器端加密

## 场景引入

假设你正在开发一个端到端加密的即时通讯应用。消息在发送前必须在浏览器中加密，服务器只能看到密文。或者你在构建一个文件加密工具，需要在浏览器中对大文件进行 AES 加密。

浏览器提供了 SubtleCrypto API 进行基本的密码学操作，但它有一些限制：不支持某些算法、无法自定义实现、大数运算性能不佳。WASM 可以弥补这些不足，让你在浏览器中运行复杂的密码学算法。

本课将讲解浏览器端密码学的需求、SubtleCrypto API 的使用，以及如何用 WASM 实现高性能的密码学计算。

## 学习目标

- 理解浏览器端密码学的应用场景和安全模型
- 掌握 SubtleCrypto API 的基本使用
- 学会用 Rust/WASM 实现 SHA-256 哈希
- 了解 RSA/ECDSA 签名验证的实现
- 理解零知识证明的基本概念和 WASM 的性能优势

## 浏览器端密码学需求

### 典型应用场景

```
浏览器端密码学应用：
├── 端到端加密通讯（Signal Protocol）
├── 文件加密/解密（客户端加密后上传）
├── 密码哈希（PBKDF2/Argon2，防止明文传输）
├── 数字签名（验证文件完整性）
├── 零知识证明（身份验证、隐私计算）
└── 区块链钱包（密钥管理、交易签名）
```

### 安全模型

浏览器环境的安全特点：

1. **沙箱隔离**：JavaScript 无法直接访问文件系统或其他进程的内存
2. **同源策略**：不同源的代码不能互相访问数据
3. **无持久化密钥**：浏览器关闭后内存中的密钥会被清除
4. **可审计性**：所有代码都可以被用户检查（开源）

## SubtleCrypto API

### 基本用法

```javascript
// subtle-crypto-demo.js

// SHA-256 哈希
async function sha256(data) {
    const buffer = await crypto.subtle.digest('SHA-256', data);
    return new Uint8Array(buffer);
}

// AES-GCM 加密
async function aesEncrypt(key, plaintext, iv) {
    const cryptoKey = await crypto.subtle.importKey(
        'raw', key, { name: 'AES-GCM' }, false, ['encrypt']
    );

    const ciphertext = await crypto.subtle.encrypt(
        { name: 'AES-GCM', iv },
        cryptoKey,
        plaintext
    );

    return new Uint8Array(ciphertext);
}

// AES-GCM 解密
async function aesDecrypt(key, ciphertext, iv) {
    const cryptoKey = await crypto.subtle.importKey(
        'raw', key, { name: 'AES-GCM' }, false, ['decrypt']
    );

    const plaintext = await crypto.subtle.decrypt(
        { name: 'AES-GCM', iv },
        cryptoKey,
        ciphertext
    );

    return new Uint8Array(plaintext);
}
```

```javascript
// 从用户密码派生加密密钥
async function deriveKey(password, salt) {
    // 将密码转换为密钥材料
    const encoder = new TextEncoder();
    const keyMaterial = await crypto.subtle.importKey(
        'raw',
        encoder.encode(password),
        'PBKDF2',
        false,
        ['deriveKey']
    );

    // 派生 AES 密钥
    return crypto.subtle.deriveKey(
        {
            name: 'PBKDF2',
            salt: encoder.encode(salt),
            iterations: 100000,  // 迭代次数越高越安全
            hash: 'SHA-256'
        },
        keyMaterial,
        { name: 'AES-GCM', length: 256 },
        false,
        ['encrypt', 'decrypt']
    );
}
```

```rust
const H_INIT: [u32; 8] = [
    0x6a09e667, 0xbb67ae85, 0x3c6ef372, 0xa54ff53a,
    0x510e527f, 0x9b05688c, 0x1f83d9ab, 0x5be0cd19,
];

fn right_rotate(x: u32, n: u32) -> u32 {
    (x >> n) | (x << (32 - n))
}

/// SHA-256 哈希函数
#[wasm_bindgen]
pub fn sha256(data: &[u8]) -> Vec<u8> {
    // 预处理：填充消息
    let mut message = data.to_vec();
    let original_len = message.len();
    let bit_len = original_len as u64 * 8;

    // 添加 1 位
    message.push(0x80);

    // 填充到 512 位（64 字节）的倍数，减去 8 字节用于长度
    while (message.len() % 64) != 56 {
        message.push(0);
    }

    // 添加原始长度（64 位大端序）
    for i in (0..8).rev() {
        message.push((bit_len >> (i * 8)) as u8);
    }

    // 初始化哈希值
    let mut h = H_INIT;

    // 处理每个 512 位块
    for chunk in message.chunks(64) {
        // 准备消息调度数组
        let mut w = [0u32; 64];
        for i in 0..16 {
            w[i] = u32::from_be_bytes([
                chunk[i * 4],
                chunk[i * 4 + 1],
                chunk[i * 4 + 2],
                chunk[i * 4 + 3],
            ]);
        }

        for i in 16..64 {
            let s0 = right_rotate(w[i - 15], 7)
                    ^ right_rotate(w[i - 15], 18)
                    ^ (w[i - 15] >> 3);
            let s1 = right_rotate(w[i - 2], 17)
                    ^ right_rotate(w[i - 2], 19)
                    ^ (w[i - 2] >> 10);
            w[i] = w[i - 16]
                .wrapping_add(s0)
                .wrapping_add(w[i - 7])
                .wrapping_add(s1);
        }

        // 初始化工作变量
        let [mut a, mut b, mut c, mut d, mut e, mut f, mut g, mut hh] = h;

        // 主循环
        for i in 0..64 {
            let s1 = right_rotate(e, 6) ^ right_rotate(e, 11) ^ right_rotate(e, 25);
            let ch = (e & f) ^ ((!e) & g);
            let temp1 = hh
                .wrapping_add(s1)
                .wrapping_add(ch)
                .wrapping_add(K[i])
                .wrapping_add(w[i]);
            let s0 = right_rotate(a, 2) ^ right_rotate(a, 13) ^ right_rotate(a, 22);
            let maj = (a & b) ^ (a & c) ^ (b & c);
            let temp2 = s0.wrapping_add(maj);

            hh = g;
            g = f;
            f = e;
            e = d.wrapping_add(temp1);
            d = c;
            c = b;
            b = a;
            a = temp1.wrapping_add(temp2);
        }

        // 更新哈希值
        h[0] = h[0].wrapping_add(a);
        h[1] = h[1].wrapping_add(b);
        h[2] = h[2].wrapping_add(c);
        h[3] = h[3].wrapping_add(d);
        h[4] = h[4].wrapping_add(e);
        h[5] = h[5].wrapping_add(f);
        h[6] = h[6].wrapping_add(g);
        h[7] = h[7].wrapping_add(hh);
    }

    // 输出 256 位哈希值
    let mut result = Vec::with_capacity(32);
    for &word in &h {
        result.extend_from_slice(&word.to_be_bytes());
    }
    result
}
```

```rust
        // 2. 计算 u2 = r * s^(-1) mod n
        // 3. 计算点 R = u1*G + u2*Q
```

## 零知识证明基础

### 什么是零知识证明

零知识证明（Zero-Knowledge Proof, ZKP）允许证明者向验证者证明某个陈述为真，而不泄露任何额外信息。

```
经典例子：洞穴谜题
├── 证明者知道打开秘密门的咒语
├── 验证者在洞穴外等待
├── 证明者从洞穴的任意一侧出来
├── 验证者无法知道证明者走的是哪条路
└── 但多次重复后，验证者确信证明者确实知道咒语
```

### zk-SNARK 概念

zk-SNARK（Zero-Knowledge Succinct Non-Interactive Argument of Knowledge）是最常用的零知识证明类型：

```
zk-SNARK 特点：
├── 零知识：不泄露输入数据
├── 简洁：证明很小（几百字节）
├── 非交互：不需要来回通信
└── 可验证：验证速度很快
```

### WASM 在零知识证明中的作用

零知识证明涉及大量的大数运算和椭圆曲线运算，这些在 JavaScript 中非常慢。WASM 可以提供 10-100 倍的性能提升。

```javascript
// 使用 snarkjs 库（底层用 WASM）

    const verified = await groth16.verify(
        'verification_key.json',
        publicSignals,
        proof
    );

    return { proof, publicSignals, verified };
}
```

### 大数运算基准

```rust
// src/bigint.rs
use wasm_bindgen::prelude::*;

/// 简化的大数运算（256 位）
/// 生产环境应使用 num-bigint 或 rug 库
#[wasm_bindgen]
pub fn big_number_multiply(a: &[u8], b: &[u8]) -> Vec<u8> {
    // 将字节数组转换为 u64 数组进行运算
    let a_words = bytes_to_u64(a);
    let b_words = bytes_to_u64(b);

    // 执行乘法
    let result = mul_256x256(&a_words, &b_words);

    u64_to_bytes(&result)
}

fn bytes_to_u64(bytes: &[u8]) -> [u64; 4] {
    let mut result = [0u64; 4];
    for i in 0..4.min(bytes.len() / 8) {
        let start = i * 8;
        result[i] = u64::from_be_bytes(
            bytes[start..start + 8].try_into().unwrap()
        );
    }
    result
}

fn u64_to_bytes(words: &[u64; 4]) -> Vec<u8> {
    let mut result = Vec::with_capacity(32);
    for &word in words {
        result.extend_from_slice(&word.to_be_bytes());
    }
    result
}

fn mul_256x256(a: &[u64; 4], b: &[u64; 4]) -> [u64; 4] {
    // 简化的 256 位乘法
    // 实际实现需要处理进位
    let mut result = [0u64; 4];

    // 低位乘法（简化版）
    let (lo, carry) = a[0].overflowing_mul(b[0]);
    result[0] = lo;

    // 这里只是示意，完整的 256 位乘法需要更多步骤
    result
}
```

## 安全考虑：侧信道攻击

### 什么是侧信道攻击

侧信道攻击通过观察程序的物理特性（如执行时间、功耗、缓存行为）来推断秘密信息。

```
时间侧信道示例：
├── 比较两个字符串是否相等
├── 通常实现：逐字符比较，发现不同立即返回
├── 问题：比较时间泄露了匹配的字符数
└── 解决：常量时间比较
```

### 常量时间实现

```rust
// src/constant_time.rs
use wasm_bindgen::prelude::*;

/// 常量时间比较：不泄露两个字节序列的差异位置
#[wasm_bindgen]
pub fn constant_time_eq(a: &[u8], b: &[u8]) -> bool {
    if a.len() != b.len() {
        return false;
    }

    let mut diff = 0u8;
    for i in 0..a.len() {
        diff |= a[i] ^ b[i];
    }

    diff == 0
}

/// 常量时间条件选择
#[wasm_bindgen]
pub fn constant_time_select(condition: bool, a: &[u8], b: &[u8]) -> Vec<u8> {
    assert_eq!(a.len(), b.len());

    let mask = if condition { 0xFF } else { 0x00 };
    let mut result = Vec::with_capacity(a.len());

    for i in 0..a.len() {
        result.push((a[i] & mask) | (b[i] & !mask));
    }

    result
}
```

## 常见误区

**1. 自己实现密码学算法**

密码学算法的正确实现极其困难。即使是微小的错误（如时序泄露、内存未清零）也会导致严重的安全漏洞。生产环境必须使用经过审计的库。

**2. 认为浏览器环境是安全的**

浏览器环境有 XSS 攻击、恶意扩展等风险。敏感密钥不应长期存储在浏览器中，应考虑使用 Web Crypto API 的密钥管理功能。

**3. 忽略随机数质量**

密码学需要密码学安全的随机数。在浏览器中应使用 `crypto.getRandomValues()`，不要使用 `Math.random()`。

**4. 忽视内存安全**

WASM 的内存管理是手动的。使用后未清零的内存可能包含敏感数据。Rust 的 `zeroize` crate 可以帮助安全清零。

## 工程建议

1. **使用成熟的密码学库**：Rust 推荐 `ring`、`RustCrypto`；JavaScript 推荐 Web Crypto API
2. **常量时间实现**：所有涉及秘密数据的比较操作必须使用常量时间算法
3. **安全清零**：使用后立即清零包含密钥的内存
4. **验证实现**：使用测试向量验证密码学实现的正确性
5. **关注浏览器支持**：某些密码学 API 在旧浏览器中不可用，需要 polyfill 或回退方案

## 小结

浏览器端密码学是安全应用的基础：

- SubtleCrypto API 提供了基本的密码学操作
- WASM 可以实现 SubtleCrypto 不支持的算法，并提供更好的大数运算性能
- 零知识证明等高级密码学应用高度依赖 WASM 的性能
- 安全实现需要关注侧信道攻击、内存清零等问题
- 生产环境必须使用经过审计的密码学库

## 参考答案

### 练习一

**思路**：HMAC 使用两个不同的密钥派生内部和外部填充，然后进行两次哈希。

```rust
use wasm_bindgen::prelude::*;

// 引用本课实现的 sha256
pub fn sha256(data: &[u8]) -> Vec<u8> { /* 如前所述 */ }

/// HMAC-SHA256
#[wasm_bindgen]
pub fn hmac_sha256(key: &[u8], message: &[u8]) -> Vec<u8> {
    const BLOCK_SIZE: usize = 64; // SHA-256 的块大小

    // 如果密钥长度大于块大小，先哈希
    let actual_key = if key.len() > BLOCK_SIZE {
        sha256(key)
    } else {
        key.to_vec()
    };

    // 用零填充密钥到块大小
    let mut padded_key = vec![0u8; BLOCK_SIZE];
    padded_key[..actual_key.len()].copy_from_slice(&actual_key);

    // 计算内部和外部填充
    let mut ipad = vec![0x36u8; BLOCK_SIZE];
    let mut opad = vec![0x5cu8; BLOCK_SIZE];

    for i in 0..BLOCK_SIZE {
        ipad[i] ^= padded_key[i];
        opad[i] ^= padded_key[i];
    }

    // 内部哈希：H(ipad || message)
    let mut inner_data = ipad;
    inner_data.extend_from_slice(message);
    let inner_hash = sha256(&inner_data);

    // 外部哈希：H(opad || inner_hash)
    let mut outer_data = opad;
    outer_data.extend_from_slice(&inner_hash);
    sha256(&outer_data)
}
```

**要点**：
- HMAC 的核心是双重哈希，用不同的填充区分内部和外部
- 密钥超过块大小时需要先哈希
- iPad（0x36）和 oPad（0x5c）是标准定义的常量

### 练习二

**思路**：简单迭代哈希——对密码和盐重复哈希指定次数。

```rust
use wasm_bindgen::prelude::*;

/// 简化的密码哈希（迭代 SHA-256）
#[wasm_bindgen]
pub fn hash_password(password: &[u8], salt: &[u8], iterations: u32) -> Vec<u8> {
    // 合并密码和盐
    let mut data = Vec::with_capacity(password.len() + salt.len());
    data.extend_from_slice(password);
    data.extend_from_slice(salt);

    // 迭代哈希
    let mut hash = sha256(&data);
    for _ in 1..iterations {
        hash = sha256(&hash);
    }

    hash
}
```

**要点**：
- 迭代哈希增加暴力破解的计算成本
- 生产环境应使用 PBKDF2 或 Argon2，它们有更好的安全属性
- 盐（salt）防止彩虹表攻击
- 迭代次数应该足够高（PBKDF2 推荐 100000+）

### 练习三

**思路**：用不同大小的数据测试两个实现，记录处理时间。

```javascript
async function benchmarkSha256() {
    const wasm = await import('./pkg/wasm_crypto.js');

    const sizes = [
        { name: '1KB', size: 1024 },
        { name: '1MB', size: 1024 * 1024 },
        { name: '10MB', size: 10 * 1024 * 1024 },
    ];

    for (const { name, size } of sizes) {
        const data = new Uint8Array(size);
        crypto.getRandomValues(data);

        // WASM SHA-256
        const wasmStart = performance.now();
        for (let i = 0; i < 10; i++) {
            wasm.sha256(data);
        }
        const wasmTime = (performance.now() - wasmStart) / 10;

        // SubtleCrypto SHA-256
        const subtleStart = performance.now();
        for (let i = 0; i < 10; i++) {
            await crypto.subtle.digest('SHA-256', data);
        }
        const subtleTime = (performance.now() - subtleStart) / 10;

        console.log(`${name}:`);
        console.log(`  WASM:      ${wasmTime.toFixed(2)}ms`);
        console.log(`  SubtleCrypto: ${subtleTime.toFixed(2)}ms`);
        console.log(`  比率: ${((wasmTime / subtleTime) * 100).toFixed(0)}%`);
    }
}
```

**要点**：
- SubtleCrypto 是浏览器原生实现，通常比 WASM 更快（因为它可以利用硬件加速和优化的 C++ 代码）
- WASM 的优势在于 SubtleCrypto 不支持的算法
- 对于 SHA-256 等标准算法，优先使用 SubtleCrypto
- WASM 的优势在于可定制性和可移植性
