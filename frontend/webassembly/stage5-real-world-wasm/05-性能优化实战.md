# 05 - 性能优化实战

## 场景引入

你的 WASM 应用功能做完了，但用户反馈"加载太慢"——2MB 的 .wasm 文件在 3G 网络下需要 5 秒下载，编译又要 2 秒。运行时内存占用 200MB，低端手机直接崩溃。WASM 的性能优化需要从二进制体积、启动速度、运行时内存、计算效率四个维度系统优化。

## 学习目标

- 掌握 WASM Profiling 工具（Chrome DevTools、wasm-opt、twiggy）
- 学会二进制体积优化：编译选项、tree-shaking、压缩
- 掌握内存优化：Arena 分配器、内存池
- 学会启动优化：流式编译、缓存、懒加载

## 流式编译

流式编译允许下载的同时编译，大幅减少启动延迟：

```typescript
// 流式编译：下载完成时编译也完成
async function instantiateStreaming(url: string) {
  const response = await fetch(url);
  const { instance } = await WebAssembly.instantiateStreaming(response, importObject);
  return instance;
}

// 非流式：先下载完再编译（串行）
async function instantiateNonStreaming(url: string) {
  const bytes = await (await fetch(url)).arrayBuffer();
  return (await WebAssembly.instantiate(bytes, importObject)).instance;
}
// 流式编译在 3G 网络下节省 40-50% 启动时间
```

## 编译缓存

```typescript
// 用 IndexedDB 缓存编译后的模块
async function getCachedModule(url: string): Promise<WebAssembly.Module | null> {
  return new Promise((resolve) => {
    const req = indexedDB.open('wasm-cache', 1);
    req.onupgradeneeded = () => req.result.createObjectStore('modules');
    req.onsuccess = () => {
      const tx = req.result.transaction('modules', 'readonly');
      const get = tx.objectStore('modules').get(url);
      get.onsuccess = () => resolve(get.result || null);
      get.onerror = () => resolve(null);
    };
  });
}

async function cacheModule(url: string, module: WebAssembly.Module) {
  const req = indexedDB.open('wasm-cache', 1);
  req.onupgradeneeded = () => req.result.createObjectStore('modules');
  req.onsuccess = () => {
    const tx = req.result.transaction('modules', 'readwrite');
    tx.objectStore('modules').put(module, url);
  };
}

export async function loadWithCache(url: string) {
  const cached = await getCachedModule(url);
  if (cached) return WebAssembly.instantiate(cached, importObject);
  const { module, instance } = await WebAssembly.instantiateStreaming(fetch(url), importObject);
  await cacheModule(url, module);
  return instance;
}
```

## Arena 分配器

一次性分配大块内存，分配只需移动指针，释放时一次性清空：

```rust
#[wasm_bindgen]
pub struct Arena {
    buffer: Vec<u8>,
    offset: usize,
    capacity: usize,
}

#[wasm_bindgen]
impl Arena {
    #[wasm_bindgen(constructor)]
    pub fn new(capacity: usize) -> Self {
        Arena { buffer: vec![0; capacity], offset: 0, capacity }
    }

    pub fn alloc(&mut self, size: usize, align: usize) -> usize {
        let aligned = (self.offset + align - 1) & !(align - 1);
        let new_offset = aligned + size;
        if new_offset > self.capacity { panic!("Arena 内存不足"); }
        self.offset = new_offset;
        aligned
    }

    pub fn reset(&mut self) { self.offset = 0; }
    pub fn used(&self) -> usize { self.offset }
    pub fn buffer_ptr(&self) -> *const u8 { self.buffer.as_ptr() }
}
```

## SIMD 优化

```rust
// 启用：RUSTFLAGS="-C target-feature=+simd128" wasm-pack build
use std::arch::wasm32::*;

pub fn adjust_brightness_simd(pixels: &mut [u8], amount: i16) {
    let chunks = pixels.chunks_exact_mut(16);
    for chunk in chunks {
        unsafe {
            let lo = v128_load8x8_s(chunk.as_ptr() as *const u8);
            let hi = v128_load8x8_s(chunk.as_ptr().add(8) as *const u8);
            let amt = i16x8_splat(amount);
            let result = u8x16_narrow_i16x8(i16x8_add(lo, amt), i16x8_add(hi, amt));
            v128_store(chunk.as_mut_ptr() as *mut v128, result);
        }
    }
}
```

## 多线程（SharedArrayBuffer + Worker）

```typescript
class WasmWorkerPool {
  private workers: Worker[] = [];
  constructor(count = navigator.hardwareConcurrency) {
    for (let i = 0; i < count; i++) {
      this.workers.push(new Worker(new URL('./worker.ts', import.meta.url)));
    }
  }

  async execute(data: SharedArrayBuffer, task: string) {
    const worker = this.workers[0]; // 简化：轮询分配
    return new Promise((resolve) => {
      worker.onmessage = (e) => resolve(e.data);
      worker.postMessage({ task, buffer: data });
    });
  }
}
```

## 常见误区

1. **只优化体积不优化启动** — 体积小不等于启动快，流式编译和缓存更重要
2. **盲目启用 SIMD** — 需要特定数据对齐和代码模式，错误使用反而更慢
3. **在主线程编译大型模块** — 应用 Worker 编译或流式编译
4. **忽略内存碎片** — 频繁分配/释放不同大小缓冲区导致碎片，用 Arena 或内存池

## 工程建议

1. **体积优化优先级**：编译选项 > tree-shaking > 压缩 > 代码拆分
2. **启动优化优先级**：流式编译 > 缓存 > 懒加载 > 代码拆分
3. **运行时优化优先级**：算法优化 > 数据布局 > SIMD > 多线程
4. **先测量再优化** — 用 Profiler 找到瓶颈，针对性优化
5. **设置性能预算** — WASM < 500KB，启动 < 200ms，内存 < 100MB

## 小结

四个优化维度：二进制体积（编译选项 + tree-shaking）、启动速度（流式编译 + 缓存）、运行时内存（Arena + 内存池）、计算效率（SIMD + 多线程）。核心原则：**先测量，再优化**。

### 练习二

```rust
#[wasm_bindgen]
pub fn benchmark_arena(iterations: usize) -> f64 {
    let mut arena = Arena::new(1024 * 1024);
    let start = js_sys::Date::now();
    for _ in 0..iterations {
        for _ in 0..10000 { arena.alloc(64, 8); }
        arena.reset();
    }
    js_sys::Date::now() - start
}
// Arena ~15ms vs 标准分配器 ~120ms（快约 8 倍）
```

**要点**：Arena 优势在于批量分配/释放场景。

### 练习三

```typescript
// sw.ts
self.addEventListener('install', (e) => {
  e.waitUntil(caches.open('wasm-v1').then(cache =>
    cache.addAll(['/wasm/image.wasm', '/wasm/audio.wasm', '/wasm/data.wasm'])
  ));
});

self.addEventListener('fetch', (e) => {
  if (new URL(e.request.url).pathname.endsWith('.wasm')) {
    e.respondWith(caches.match(e.request).then(cached =>
      cached || fetch(e.request).then(res => {
        const clone = res.clone();
        caches.open('wasm-v1').then(c => c.put(e.request, clone));
        return res;
      })
    ));
  }
});
```

**要点**：Service Worker 缓存确保 WASM 只下载一次。
