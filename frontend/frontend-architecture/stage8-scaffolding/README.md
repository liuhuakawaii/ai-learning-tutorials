# stage8：脚手架与项目模板

> 脚手架不是"生成一堆文件"——它是团队工程规范的可执行表达

## 学习目标

完成本阶段后，你将能够：
- 理解脚手架工具的设计原则：约定优于配置、零配置理念、可扩展性
- 使用 Commander.js、Inquirer.js、Ora 开发交互式 CLI 工具
- 掌握模板引擎（EJS/Handlebars）进行项目生成和文件转换
- 使用 AST 操作实现代码生成器（组件、页面、路由模板自动生成）
- 设计配置管理与预设系统，支持远程预设拉取和配置校验
- 实现插件机制：钩子系统、插件加载、插件沙箱
- 编写脚手架的 E2E 测试和快照测试，制定版本升级策略
- 综合运用所学知识，开发一个企业级脚手架工具

## 前置要求

- 完成 stage1 工程化基础与 Monorepo
- 完成 stage3 构建工具链深度
- 熟悉 Node.js 基础 API（fs、path、child_process）
- 了解 npm/yarn/pnpm 的基本使用
- 有使用 Create React App、Vite、Vue CLI 等脚手架工具的经验

## 学习建议

1. **从使用体验出发**：先想想你用过的脚手架（create-react-app、vue cli、vite）哪些体验好、哪些让你困惑，带着这些感受来学
2. **每课都写代码**：脚手架是工具开发，光看概念没用。每节课的代码都要在本地跑通
3. **关注边界情况**：目录已存在怎么办？模板变量缺失怎么办？网络拉取失败怎么办？这些才是脚手架开发的核心难点
4. **先小后大**：先做一个能生成单文件的小工具，再逐步扩展为支持完整项目的脚手架
5. **测试驱动**：脚手架的输出是代码文件，非常适合用快照测试验证。从第一个版本就开始写测试

## 阶段项目

开发一个企业级脚手架工具，支持以下功能：

### 项目要求

**核心功能**：
- `my-cli create <project-name>`：创建新项目，支持选择模板（React/Vue/Node.js）
- `my-cli generate component <name>`：生成组件模板
- `my-cli generate page <name>`：生成页面模板（包含路由配置）
- `my-cli add <plugin>`：添加插件（如 ESLint、Prettier、Husky 配置）
- `my-cli preset list`：列出可用预设
- `my-cli preset use <name>`：切换预设

**技术要求**：
- 使用 Commander.js 构建 CLI
- 使用 Inquirer.js 实现交互式问答
- 使用 EJS 作为模板引擎
- 支持本地模板和远程模板（从 Git 仓库拉取）
- 配置文件支持 `.myclirc`（项目级）和 `~/.myclirc`（全局级）
- 提供插件接口，支持第三方插件扩展

### 验收标准

- `my-cli create my-app` 能正常创建项目，项目可直接运行
- `my-cli generate component Button` 能在正确目录生成组件文件
- 切换预设后，生成的代码风格和配置发生变化
- 远程模板拉取失败时有清晰的错误提示
- 插件能正常加载并执行钩子
- 核心功能有 E2E 测试覆盖

## 常见问题

### Q: 脚手架和模板仓库有什么区别？

A: 模板仓库只是一个静态的代码拷贝。脚手架能根据用户输入动态生成代码：选择不同的模板、填充不同的变量、根据选项添加或移除文件、自动安装依赖并初始化 Git。脚手架是"智能化的模板"。

### Q: 为什么不直接用 degit 或 git clone？

A: degit 和 git clone 只能做"下载"，不能做"定制"。脚手架的价值在于交互式问答：你用什么框架？要不要 TypeScript？要不要 ESLint？选什么 CSS 方案？然后根据答案动态组合出项目。这比维护 20 个模板仓库要灵活得多。

### Q: 脚手架需要支持插件吗？

A: 看规模。3 人团队的内部工具不需要插件系统。但如果你的脚手架要服务整个公司（前端、后端、移动端都用），插件系统能让各团队自己扩展能力，而不需要改脚手架核心代码。插件系统的复杂度很高，不要过早引入。

### Q: 如何处理脚手架本身的版本升级？

A: 脚手架发新版后，已生成的项目不需要也不应该被自动修改。但可以通过 `my-cli upgrade` 命令提供"配置升级"能力（比如更新 ESLint 规则、更新 CI 配置），同时保留用户自定义的部分。关键是区分"脚手架版本"和"生成项目的版本"。
