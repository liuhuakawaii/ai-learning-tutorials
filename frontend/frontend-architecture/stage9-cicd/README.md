## 学习建议

1. **从实际项目出发**：带着你现有的项目来学习，边学边实践
2. **理解原理**：不要只复制配置，要理解每一步的作用
3. **关注失败场景**：CI/CD 的价值往往体现在失败时如何处理
4. **渐进式实施**：先搭建基本流水线，再逐步完善
5. **团队协作**：CI/CD 是团队工程，需要考虑团队成员的使用体验

## 常见问题

### Q: CI 和 CD 有什么区别？

A: CI（持续集成）是频繁地将代码集成到主干，并通过自动化测试验证。CD 有两个含义：持续交付（Continuous Delivery）是让代码随时可以部署到生产环境；持续部署（Continuous Deployment）是自动将通过验证的代码部署到生产环境。

### Q: GitHub Actions 和 Jenkins 有什么区别？

A: GitHub Actions 是 GitHub 原生的 CI/CD 服务，配置简单，与 GitHub 集成紧密。Jenkins 是一个开源的自动化服务器，功能更强大，但配置更复杂，需要自己维护服务器。

### Q: 什么时候需要灰度发布？

A: 当你的应用影响范围大、用户基数多、或改动风险高时，灰度发布可以降低风险。小团队或内部工具可能不需要复杂的灰度机制。

### Q: 如何处理构建缓存？

A: 大多数 CI/CD 平台都支持缓存。GitHub Actions 可以使用 `actions/cache` 缓存 node_modules、构建产物等。合理的缓存策略可以显著缩短构建时间。
