# stage3：构建工具链深度

> 从"能跑就行"到"又快又稳"，掌握构建工具的原理与工程实践

## 学习目标

完成本阶段后，你将能够：
- 理解前端构建工具的演进逻辑和技术债
- 掌握 Vite 的核心原理（ESM、预构建、HMR、插件系统）
- 开发自定义 Vite 插件解决实际工程问题
- 对 Webpack 进行深度性能优化（持久化缓存、并行构建、Module Federation）
- 设计合理的代码分割策略
- 实施资源优化（图片、字体、SVG）
- 管理多环境构建配置
- 使用 Turborepo 编排多包构建流程
- 分析构建产物、验证 Tree Shaking、检测死代码
- 为组件库定制完整的构建流程

## 前置要求

- 完成 stage1 工程化基础与 Monorepo
- 了解基本的模块化概念（ESM、CJS）
- 有使用 Vite 或 Webpack 的项目经验
- 熟悉 npm scripts

## 学习建议

1. **理解演进逻辑**：构建工具的每个特性都是为了解决具体问题，先理解问题再学方案
2. **动手验证**：每节课的配置和代码都要在本地跑一遍，不要只看不练
3. **对比思考**：Vite 和 Webpack 不是对立的，理解各自适用场景
4. **关注性能数据**：优化不是凭感觉，要用数据说话（构建时间、产物体积）
5. **从小项目开始**：先在小项目中验证构建策略，再应用到大型项目

## 阶段项目

为一个 Monorepo 中的组件库定制完整的构建流程：

- 使用 Vite/Rollup 打包组件库
- 支持按需加载（Tree Shaking）
- 正确处理 externals 和 peerDependencies
- 生成 ESM 和 CJS 双格式产物
- 包含类型声明文件（.d.ts）
- 构建产物分析报告

**验收标准**：
- `pnpm build` 正常构建，产物结构清晰
- 产物支持 Tree Shaking（通过 bundle analyzer 验证）
- 外部依赖（react、vue 等）不被打包
- ESM 和 CJS 格式都能正确导入
- 构建时间在合理范围内（<30s）

## 常见问题

### Q: Vite 和 Webpack 该怎么选？

A: 新项目优先考虑 Vite，开发体验好、配置简单。已有 Webpack 项目不需要急着迁移，先优化现有配置。Webpack 在复杂场景（如 Module Federation、微前端）中仍然有优势。

### Q: 为什么 Vite 开发环境这么快？

A: Vite 开发环境利用浏览器原生 ESM，不需要打包，只在请求时按需编译。Webpack 需要把所有模块打包成 bundle 再启动开发服务器，模块越多越慢。

### Q: 构建优化的优先级是什么？

A: 先做代码分割（效果最明显），再做资源优化（图片压缩、字体子集化），最后做构建速度优化（缓存、并行）。产物体积优化对用户体验的影响大于构建速度优化对开发体验的影响。

### Q: 什么时候需要自定义构建流程？

A: 当现有工具链无法满足需求时：需要特殊的代码转换、需要定制产物格式、需要特殊的资源处理流程。不要为了"学习"而自定义，优先使用社区方案。
