# Chrome 应用商店上架：审核通过的关键

## 当前项目状态

你的扩展开发完成，要发布到 Chrome 应用商店。第一次提交被拒了——理由是"权限声明过大"和"隐私政策缺失"。这种问题很常见。

## 上架流程

```
1. 注册开发者账号（一次性 $5）
2. 准备素材：图标、截图、描述
3. 打包为 .zip
4. 提交审核
5. 等待审核（通常 1-3 个工作日）
6. 发布
```

## 审核常见拒绝原因

### 1. 权限过大

```
被拒：请求了 <all_urls> 权限但没有说明用途

解决：
- 能用 activeTab 就不用 host_permissions
- 在描述中说明为什么需要广泛权限
- 用 optional_permissions 动态请求
```

### 2. 缺少隐私政策

```
被拒：扩展收集用户数据但没有隐私政策

解决：
- 创建隐私政策页面（可以用 GitHub Pages 免费托管）
- 说明收集哪些数据、如何使用、是否分享给第三方
- 在 manifest 和商店 listing 中链接隐私政策
```

### 3. 远程代码

```
被拒：Manifest V3 禁止加载远程代码

解决：
- 所有 JS 必须打包在扩展内
- 不能用 eval() 或 new Function()
- CDN 引用的库必须打包到本地
```

### 4. 内容安全策略

```
被拒：内联脚本违反 CSP

解决：
- 不要在 HTML 中写 onclick="..."
- 不要用 <script> 标签内联代码
- 所有逻辑放在独立 .js 文件中
```

## 商店素材

```
图标：128×128 PNG（必需）
截图：1280×800 或 640×400（至少 1 张）
宣传图：1400×560（可选，但推荐）
描述：简洁说明功能和用途
类别：选择最匹配的类别
```

## 版本更新

```json
// 每次提交版本号必须递增
{
  "version": "1.0.0",  // 第一次提交
  "version": "1.0.1",  // bug 修复
  "version": "1.1.0",  // 新功能
  "version": "2.0.0"   // 大改版
}
```

## 你可能踩的坑

**坑一：审核时间不确定**

通常 1-3 天，但有时会拖到 1 周。不要在上线前一天才提交。

**坑二：更新也需要审核**

每次更新都要重新审核。紧急修复可能来不及。

**坑三：不同地区的审核标准不同**

某些地区对隐私政策的要求更严格。
