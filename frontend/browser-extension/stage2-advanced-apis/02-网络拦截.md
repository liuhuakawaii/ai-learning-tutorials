# 网络拦截

## 场景引入

广告拦截器、隐私保护工具、请求修改器——这些扩展的核心能力都依赖于拦截和修改浏览器的网络请求。Manifest V3 引入了 `declarativeNetRequest` API，取代了 V2 的阻塞式 `webRequest`，这是一个根本性的架构变化。

为什么要改？V2 的 `webRequest` 让扩展可以同步拦截和修改每一个网络请求，但这也意味着扩展可以看到用户的所有网络流量，存在严重的隐私和安全风险。V3 的 `declarativeNetRequest` 采用声明式规则，扩展只能声明"什么请求应该被怎样处理"，由浏览器执行规则，扩展不再直接接触请求内容。

## 学习目标

- 理解 declarativeNetRequest 的声明式规则模型
- 掌握静态规则和动态规则的使用
- 学会拦截、修改和重定向网络请求
- 了解 webRequest 的有限使用场景

## declarativeNetRequest 基础

### 声明式规则模型

`declarativeNetRequest` 的核心思想：扩展声明规则，浏览器执行规则。

```json
{
  "manifest_version": 3,
  "name": "请求拦截器",
  "permissions": ["declarativeNetRequest"],
  "host_permissions": ["<all_urls>"],
  "declarative_net_request": {
    "rule_resources": [
      {
        "id": "ruleset_1",
        "enabled": true,
        "path": "rules.json"
      }
    ]
  }
}
```

### 规则文件结构

```json
// rules.json
[
  {
    "id": 1,
    "priority": 1,
    "action": {
      "type": "block"
    },
    "condition": {
      "urlFilter": "||ads.example.com",
      "resourceTypes": ["script", "image"]
    }
  },
  {
    "id": 2,
    "priority": 1,
    "action": {
      "type": "redirect",
      "redirect": {
        "url": "https://example.com/blocked.html"
      }
    },
    "condition": {
      "urlFilter": "||tracking.com",
      "resourceTypes": ["main_frame"]
    }
  },
  {
    "id": 3,
    "priority": 1,
    "action": {
      "type": "modifyHeaders",
      "requestHeaders": [
        { "header": "Referer", "operation": "remove" }
      ],
      "responseHeaders": [
        { "header": "X-Frame-Options", "operation": "remove" }
      ]
    },
    "condition": {
      "urlFilter": "||example.com",
      "resourceTypes": ["main_frame"]
    }
  }
]
```

### 操作类型

| 类型 | 作用 |
|------|------|
| `block` | 阻止请求 |
| `redirect` | 重定向到其他 URL |
| `allow` | 允许请求（覆盖其他规则） |
| `allowAllRequests` | 允许所有子请求 |
| `modifyHeaders` | 修改请求/响应头 |
| `upgradeScheme` | 升级 HTTP 到 HTTPS |

### URL 过滤语法

```
||example.com     - 匹配 example.com 及其子域名
|https://example  - 匹配以 https://example 开头的 URL
example.com       - 匹配包含 example.com 的 URL
*/ads/*           - 匹配包含 /ads/ 的路径
```

## 动态规则

静态规则在打包时确定，动态规则可以在运行时添加。

```javascript
// 添加动态规则
await chrome.declarativeNetRequest.updateDynamicRules({
  addRules: [
    {
      id: 100,
      priority: 1,
      action: { type: 'block' },
      condition: {
        urlFilter: '||tracker.example.com',
        resourceTypes: ['script', 'image', 'xmlhttprequest']
      }
    }
  ],
  removeRuleIds: [100]  // 先移除同 ID 的旧规则
});

// 移除动态规则
await chrome.declarativeNetRequest.updateDynamicRules({
  removeRuleIds: [100, 101, 102]
});

// 查询当前生效的规则
const rules = await chrome.declarativeNetRequest.getDynamicRules();
console.log('当前动态规则:', rules);
```

### 动态规则限制

- 最大动态规则数：默认 5000（可通过 `MAX_NUMBER_OF_DYNAMIC_AND_SESSION_RULES` 查看）
- 会话规则（session rules）：类似动态规则，但浏览器关闭后自动清除

```javascript
// 会话规则（Chrome 120+）
await chrome.declarativeNetRequest.updateSessionRules({
  addRules: [{
    id: 200,
    priority: 1,
    action: { type: 'block' },
    condition: {
      urlFilter: '||temp-block.com',
      resourceTypes: ['main_frame']
    }
  }],
  removeRuleIds: []
});
```

## 重定向请求

将请求重定向到其他 URL：

```json
[
  {
    "id": 10,
    "priority": 1,
    "action": {
      "type": "redirect",
      "redirect": {
        "transform": {
          "scheme": "https"
        }
      }
    },
    "condition": {
      "urlFilter": "||example.com",
      "resourceTypes": ["main_frame"],
      "urlFilterIsCaseSensitive": false
    }
  },
  {
    "id": 11,
    "priority": 1,
    "action": {
      "type": "redirect",
      "redirect": {
        "regexSubstitution": "https://\\1.new-domain.com\\2"
      }
    },
    "condition": {
      "regexFilter": "https?://(old-domain)\\.com(/.*)",
      "resourceTypes": ["main_frame"]
    }
  }
]
```

## 修改请求头和响应头

```json
[
  {
    "id": 20,
    "priority": 1,
    "action": {
      "type": "modifyHeaders",
      "requestHeaders": [
        {
          "header": "Accept-Language",
          "operation": "set",
          "value": "zh-CN,zh;q=0.9"
        }
      ]
    },
    "condition": {
      "urlFilter": "||example.com",
      "resourceTypes": ["main_frame"]
    }
  },
  {
    "id": 21,
    "priority": 1,
    "action": {
      "type": "modifyHeaders",
      "responseHeaders": [
        {
          "header": "Content-Security-Policy",
          "operation": "remove"
        },
        {
          "header": "X-Frame-Options",
          "operation": "remove"
        }
      ]
    },
    "condition": {
      "urlFilter": "||example.com",
      "resourceTypes": ["main_frame"]
    }
  }
]
```

修改响应头的常见场景：
- 移除 CSP 以允许注入脚本
- 移除 X-Frame-Options 以允许 iframe 嵌入
- 添加 CORS 头以允许跨域请求

## webRequest（只读）

Manifest V3 中，`webRequest` 只能用于**观察**请求，不能阻塞或修改。它主要用于日志记录和分析。

```json
{
  "permissions": ["webRequest"]
}
```

```javascript
// background.js - 只能观察，不能修改
chrome.webRequest.onBeforeRequest.addListener(
  (details) => {
    console.log('请求:', details.url, details.type);
  },
  { urls: ['<all_urls>'] }
);

chrome.webRequest.onCompleted.addListener(
  (details) => {
    if (details.statusCode >= 400) {
      console.log('请求失败:', details.url, details.statusCode);
    }
  },
  { urls: ['<all_urls>'] }
);
```

## 规则优先级

多个规则可能匹配同一个请求，优先级由 `priority` 字段决定：

```javascript
// 规则 1：阻止所有 tracker.com 的请求
{
  "id": 1,
  "priority": 1,
  "action": { "type": "block" },
  "condition": { "urlFilter": "||tracker.com" }
}

// 规则 2：允许 tracker.com/analytics（更高优先级）
{
  "id": 2,
  "priority": 2,
  "action": { "type": "allow" },
  "condition": { "urlFilter": "||tracker.com/analytics" }
}
```

规则 2 优先级更高，所以 `tracker.com/analytics` 会被允许，其他 `tracker.com` 的请求被阻止。

## 常见误区

### 误区一：declarativeNetRequest 能看到请求内容

`declarativeNetRequest` 只基于 URL 和请求头做匹配，扩展无法看到请求体（POST data）或响应内容。

### 误区二：动态规则没有数量限制

动态规则默认最多 5000 条。超出限制时，添加规则的操作会失败。需要合理管理规则，及时清理不需要的规则。

### 误区三：webRequest 在 V3 中完全不能用

`webRequest` 仍然可以用于观察请求（只读），只是不能阻塞或修改。某些场景（如日志记录、性能分析）仍然需要它。

### 误区四：规则修改后立即生效

规则修改后需要等待一小段时间才能生效。不要在修改规则后立即检查结果。

## 工程建议

1. **静态规则为主**：已知的拦截规则用静态规则，减少运行时开销
2. **动态规则按需添加**：用户自定义的拦截规则用动态规则
3. **合理设置优先级**：允许规则的优先级应高于阻止规则
4. **定期清理规则**：移除不再需要的动态规则，避免达到上限
5. **测试规则效果**：使用 `chrome.declarativeNetRequest.testMatchOutcome` 测试规则匹配结果

## 小结

`declarativeNetRequest` 是 Manifest V3 中处理网络请求的声明式 API。它通过规则文件定义请求拦截、重定向和头修改策略，由浏览器负责执行，既保证了用户隐私，又提供了足够的灵活性。

### 练习二

**答案**：

```javascript
// background.js
chrome.runtime.onMessage.addListener((message, sender, sendResponse) => {
  if (message.type === 'ADD_REDIRECT') {
    addRedirectRule(message.from, message.to).then(sendResponse);
    return true;
  }
  if (message.type === 'REMOVE_REDIRECT') {
    removeRedirectRule(message.ruleId).then(sendResponse);
    return true;
  }
  if (message.type === 'GET_REDIRECTS') {
    chrome.declarativeNetRequest.getDynamicRules().then(rules => {
      sendResponse(rules.filter(r => r.action.type === 'redirect'));
    });
    return true;
  }
});

async function addRedirectRule(fromDomain, toUrl) {
  const ruleId = Date.now() % 100000;

  await chrome.declarativeNetRequest.updateDynamicRules({
    addRules: [{
      id: ruleId,
      priority: 1,
      action: {
        type: 'redirect',
        redirect: { url: toUrl }
      },
      condition: {
        urlFilter: `||${fromDomain}`,
        resourceTypes: ['main_frame']
      }
    }],
    removeRuleIds: []
  });

  return { success: true, ruleId };
}

async function removeRedirectRule(ruleId) {
  await chrome.declarativeNetRequest.updateDynamicRules({
    removeRuleIds: [ruleId]
  });
  return { success: true };
}
```
