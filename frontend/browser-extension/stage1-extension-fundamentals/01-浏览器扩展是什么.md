# 浏览器扩展是什么

## 场景引入

你每天都在使用浏览器扩展——广告拦截器、密码管理器、翻译插件、暗色模式切换器。这些小工具改变了浏览器的使用方式，但你有没有想过：一个扩展到底是怎么运行在浏览器里的？它和普通网页有什么区别？为什么有些扩展能拦截网络请求，有些能修改页面内容，有些只能在独立面板里显示？

要回答这些问题，需要从浏览器扩展的架构模型说起。

### 一个真实场景：从需求到扩展

假设你是一名前端开发者，团队有一个痛点：设计师在 Figma 中标注的颜色值，开发时需要手动复制粘贴到代码里。你决定开发一个"取色器"扩展，让用户在任意网页上按快捷键吸取颜色值，自动复制到剪贴板，并在 popup 中展示最近取过的颜色历史。

这个看似简单的需求，涉及了扩展架构的方方面面：

- **Content Script** 需要注入到任意网页中，监听鼠标点击事件，读取点击位置的像素颜色
- **Background Service Worker** 需要接收 Content Script 发来的颜色值，存入 `chrome.storage`
- **Popup** 需要从 storage 中读取颜色历史，展示给用户
- **manifest.json** 需要声明 `activeTab` 权限（因为只在用户触发时才操作页面）和 `storage` 权限
- 快捷键注册需要用到 `commands` 字段

一个功能完整的扩展，至少需要 5 个文件协同工作。如果你不清楚每个组件的职责边界和通信方式，代码很快就会变成一团乱麻。

接下来我们从架构层面拆解扩展的组成，然后在课程项目中一步步实现这个取色器。

## 学习目标

- 理解浏览器扩展的架构组成与运行机制
- 掌握 Manifest V3 的核心配置字段
- 理解扩展的权限模型与安全策略
- 能够手动搭建一个最小可运行的扩展

## 扩展的架构模型

浏览器扩展不是普通的网页应用。它由多个独立的组件构成，每个组件运行在不同的上下文中，拥有不同的能力边界。

### 核心组件

一个典型的扩展包含以下组件：

**1. Background Service Worker**

扩展的"大脑"，运行在独立的 JavaScript 上下文中，不直接访问任何网页 DOM。它负责监听浏览器事件、管理扩展状态、协调其他组件的工作。

**2. Content Script**

注入到网页中的脚本，可以直接访问和操作页面 DOM。它是扩展与网页内容之间的桥梁。

**3. Popup**

点击扩展图标时弹出的小窗口，本质是一个 HTML 页面。用于展示 UI 和接收用户输入。

**4. Options Page**

扩展的设置页面，用户可以在其中配置扩展的行为。

**5. Side Panel**

Chrome 114+ 支持的侧边栏面板，常驻在浏览器侧面，适合需要持续显示的内容。

这些组件各自运行在独立的上下文中，不能直接互相访问变量或函数。它们之间通过消息传递（Message Passing）进行通信。

### 运行上下文隔离

这是理解扩展架构最关键的一点：**每个组件运行在完全隔离的 JavaScript 上下文中**。

```
┌─────────────────────────────────────────────────┐
│                  浏览器进程                        │
│                                                   │
│  ┌──────────────┐  ┌──────────────────────────┐  │
│  │  Background   │  │      网页渲染进程          │  │
│  │  Service      │  │                          │  │
│  │  Worker       │  │  ┌────────────────────┐  │  │
│  │              │  │  │  Content Script     │  │  │
│  │  独立上下文    │  │  │  (注入到页面中)      │  │  │
│  │  无 DOM 访问  │  │  │  可操作 DOM          │  │  │
│  └──────┬───────┘  │  └────────────────────┘  │  │
│         │          │                          │  │
│         │          └──────────────────────────┘  │
│         │                                         │
│  ┌──────┴───────┐  ┌──────────────────────────┐  │
│  │  Popup        │  │  Options Page            │  │
│  │  (HTML页面)    │  │  (HTML页面)              │  │
│  │  独立上下文    │  │  独立上下文               │  │
│  └──────────────┘  └──────────────────────────┘  │
└─────────────────────────────────────────────────┘
```

这种隔离设计有两个原因：
- **安全**：网页脚本无法直接访问扩展的内部逻辑
- **稳定**：一个组件崩溃不会影响其他组件

## Manifest V3

每个扩展的根目录下必须有一个 `manifest.json` 文件，它是扩展的"身份证"，定义了扩展的名称、版本、权限、入口文件等所有元信息。

### 最小配置

```json
{
  "manifest_version": 3,
  "name": "My Extension",
  "version": "1.0.0",
  "description": "A simple browser extension"
}
```

这是一个合法但几乎无用的扩展——它没有任何功能。要让它做事情，需要声明组件入口。

### 完整配置示例

```json
{
  "manifest_version": 3,
  "name": "网页标注工具",
  "version": "1.0.0",
  "description": "在网页上高亮和标注重要内容",

  "permissions": [
    "activeTab",
    "storage",
    "contextMenus"
  ],

  "host_permissions": [
    "https://*/*",
    "http://*/*"
  ],

  "action": {
    "default_popup": "popup/popup.html",
    "default_icon": {
      "16": "icons/icon16.png",
      "48": "icons/icon48.png",
      "128": "icons/icon128.png"
    }
  },

  "background": {
    "service_worker": "background.js"
  },

  "content_scripts": [
    {
      "matches": ["<all_urls>"],
      "js": ["content.js"],
      "css": ["content.css"]
    }
  ],

  "icons": {
    "16": "icons/icon16.png",
    "48": "icons/icon48.png",
    "128": "icons/icon128.png"
  }
}
```

### 关键字段说明

| 字段 | 作用 |
|------|------|
| `manifest_version` | 必须为 3，表示使用 Manifest V3 规范 |
| `permissions` | 声明需要的 Chrome API 权限 |
| `host_permissions` | 声明可以访问的网页域名 |
| `action` | 定义扩展图标点击后的行为（popup） |
| `background` | 定义 Service Worker 入口 |
| `content_scripts` | 定义注入到网页中的脚本 |

### 更多实用字段

除了上面列出的核心字段，`manifest.json` 还支持许多实用配置：

```json
{
  "manifest_version": 3,
  "name": "高级网页工具",
  "version": "2.1.0",
  "description": "一个功能丰富的网页增强工具",

  "default_locale": "zh_CN",

  "permissions": [
    "storage",
    "activeTab",
    "commands",
    "alarms",
    "notifications"
  ],

  "action": {
    "default_popup": "popup.html",
    "default_title": "点击打开面板",
    "default_icon": {
      "16": "icons/icon16.png",
      "48": "icons/icon48.png",
      "128": "icons/icon128.png"
    }
  },

  "background": {
    "service_worker": "background.js",
    "type": "module"
  },

  "content_scripts": [
    {
      "matches": ["https://*.github.com/*"],
      "js": ["content-github.js"],
      "run_at": "document_idle"
    },
    {
      "matches": ["https://*.stackoverflow.com/*"],
      "js": ["content-stackoverflow.js"],
      "run_at": "document_end"
    }
  ],

  "commands": {
    "take-screenshot": {
      "suggested_key": {
        "default": "Ctrl+Shift+S",
        "mac": "Command+Shift+S"
      },
      "description": "截取当前页面"
    },
    "open-panel": {
      "suggested_key": {
        "default": "Ctrl+Shift+P"
      },
      "description": "打开侧边面板"
    }
  },

    {
      "resources": ["images/*.png", "fonts/*.woff2"],
      "matches": ["<all_urls>"]
    }
  ],

    "extension_pages": "script-src 'self'; object-src 'self'"
  },

    "16": "icons/icon16.png",
    "48": "icons/icon48.png",
    "128": "icons/icon128.png"
  }
}
```

**额外字段说明：**

| 字段 | 作用 |
|------|------|
| `default_locale` | 默认语言，配合 `_locales` 目录实现国际化 |
| `background.type` | 设为 `"module"` 可在 Service Worker 中使用 ES Module 语法 |
| `content_scripts.run_at` | 控制注入时机：`document_start`、`document_end`、`document_idle` |
| `commands` | 注册键盘快捷键，可为不同操作系统指定不同按键 |
| `web_accessible_resources` | 声明哪些资源可以被网页访问（如图片、字体） |
| `content_security_policy` | 自定义扩展页面的内容安全策略 |

### 完整最小扩展：从零搭建

下面是一个完整可运行的"页面字数统计"扩展，包含所有必要文件。你可以在任意空目录中创建这些文件，然后加载到浏览器中测试。

**文件结构：**

```
word-counter/
├── manifest.json
├── background.js
├── content.js
├── popup.html
├── popup.js
└── icons/
    └── icon128.png
```

**manifest.json：**

```json
{
  "manifest_version": 3,
  "name": "页面字数统计",
  "version": "1.0.0",
  "description": "统计当前网页的文本字数",
  "permissions": ["activeTab"],
  "action": {
    "default_popup": "popup.html",
    "default_icon": {
      "128": "icons/icon128.png"
    }
  },
  "background": {
    "service_worker": "background.js"
  },
  "content_scripts": [
    {
      "matches": ["<all_urls>"],
      "js": ["content.js"],
      "run_at": "document_idle"
    }
  ],
  "icons": {
    "128": "icons/icon128.png"
  }
}
```

**background.js：**

```javascript
chrome.runtime.onMessage.addListener((message, sender, sendResponse) => {
  if (message.type === 'WORD_COUNT') {
    chrome.storage.local.set({ wordCount: message.count });
    sendResponse({ status: 'ok' });
  }
  return true;
});
```

**content.js：**

```javascript
function countWords() {
  const text = document.body.innerText;
  const chineseChars = text.match(/[\u4e00-\u9fa5]/g) || [];
  const englishWords = text.match(/[a-zA-Z]+/g) || [];
  return chineseChars.length + englishWords.length;
}

chrome.runtime.onMessage.addListener((message, sender, sendResponse) => {
  if (message.type === 'GET_WORD_COUNT') {
    const count = countWords();
    sendResponse({ count });
  }
  return true;
});
```

**popup.html：**

```html
<!DOCTYPE html>
<html>
<head>
  <meta charset="UTF-8">
  <style>
    body { width: 250px; padding: 16px; font-family: sans-serif; }
    h2 { margin: 0 0 12px; font-size: 16px; }
    .count { font-size: 32px; font-weight: bold; color: #1a73e8; }
    .label { color: #666; font-size: 14px; }
    button { margin-top: 12px; padding: 8px 16px; background: #1a73e8;
             color: white; border: none; border-radius: 4px; cursor: pointer; }
    button:hover { background: #1557b0; }
  </style>
</head>
<body>
  <h2>页面字数统计</h2>
  <div class="count" id="count">--</div>
  <div class="label">个字符/单词</div>
  <button id="refresh">重新统计</button>
  <script src="popup.js"></script>
</body>
</html>
```

**popup.js：**

```javascript
async function refreshCount() {
  const [tab] = await chrome.tabs.query({ active: true, currentWindow: true });
  chrome.tabs.sendMessage(tab.id, { type: 'GET_WORD_COUNT' }, (response) => {
    if (response && response.count !== undefined) {
      document.getElementById('count').textContent = response.count.toLocaleString();
      chrome.runtime.sendMessage({ type: 'WORD_COUNT', count: response.count });
    }
  });
}

document.getElementById('refresh').addEventListener('click', refreshCount);
refreshCount();
```

**加载测试步骤：**

1. 打开 Chrome，地址栏输入 `chrome://extensions/`
2. 打开右上角"开发者模式"开关
3. 点击"加载已解压的扩展程序"，选择 `word-counter` 目录
4. 打开任意网页，点击扩展图标，即可看到字数统计结果

这个例子展示了扩展的核心工作流：Content Script 读取页面数据 → 通过消息发送给 Background → Background 存储数据 → Popup 从 Content Script 获取数据并展示。

## 权限模型

Manifest V3 采用**最小权限原则**：扩展必须显式声明需要的每项权限，浏览器会在安装时向用户展示权限列表。

### 权限分类

**1. API 权限**

控制扩展可以使用哪些 Chrome API：

```json
{
  "permissions": [
    "storage",        // chrome.storage API
    "tabs",           // chrome.tabs API
    "activeTab",      // 仅当用户点击扩展图标时获取当前标签页权限
    "contextMenus",   // 右键菜单
    "notifications",  // 系统通知
    "alarms"          // 定时器
  ]
}
```

**2. 主机权限**

控制扩展可以访问哪些网页的 URL：

```json
{
  "host_permissions": [
    "https://www.google.com/*",     // 仅 Google
    "https://*.github.com/*",       // GitHub 所有子域名
    "<all_urls>"                    // 所有网站（慎用）
  ]
}
```

**3. 可选权限**

运行时动态请求的权限，不需要在安装时就声明：

```json
{
  "optional_permissions": [
    "downloads"
  ],
  "optional_host_permissions": [
    "https://*/*"
  ]
}
```

在代码中动态请求可选权限：

```javascript
async function requestDownloadPermission() {
  const granted = await chrome.permissions.request({
    permissions: ['downloads'],
    origins: ['https://example.com/*']
  });

  if (granted) {
    console.log('权限已授予');
  } else {
    console.log('用户拒绝了权限请求');
  }
}
```

### activeTab vs host_permissions

`activeTab` 是一个特殊的权限：它不声明对所有网页的访问权，而是仅在用户主动点击扩展图标时，临时授予对当前标签页的访问权限。

```javascript
// 使用 activeTab 权限，用户点击图标后才能执行
chrome.action.onClicked.addListener(async (tab) => {
  // 此时可以对当前标签页执行脚本注入等操作
  await chrome.scripting.executeScript({
    target: { tabId: tab.id },
    files: ['content.js']
  });
});
```

**选择建议**：
- 只需要在用户主动触发时操作页面 → 用 `activeTab`
- 需要在后台持续监听页面事件 → 用 `host_permissions`
- 能用 `activeTab` 解决的场景，不要用 `host_permissions`

### 权限检查与移除

在代码中可以检查当前是否拥有某项权限，也可以主动释放不再需要的权限：

```javascript
// 检查是否拥有某项权限
async function checkPermission() {
  const hasPermission = await chrome.permissions.contains({
    permissions: ['downloads']
  });
  if (hasPermission) {
    console.log('已拥有下载权限');
  } else {
    console.log('未拥有下载权限，需要请求');
  }
}

// 主动释放权限（减少用户顾虑）
async function removePermission() {
  const removed = await chrome.permissions.remove({
    permissions: ['downloads']
  });
  if (removed) {
    console.log('权限已释放');
  }
}
```

## Manifest V2 到 V3 的变化

如果你看过较老的扩展教程，可能会遇到 Manifest V2。以下是关键差异：

| 特性 | V2 | V3 |
|------|-----|-----|
| Background | 持久化后台页面 | Service Worker（非持久） |
| 网络拦截 | webRequest（阻塞式） | declarativeNetRequest（声明式） |
| 远程代码 | 允许 eval 远程代码 | 禁止，必须打包到扩展内 |
| 内容安全策略 | 可自定义 CSP | 固定严格 CSP |

V3 的核心变化是将 Background 从持久化页面改为 Service Worker。这意味着 background 脚本会在空闲时被浏览器终止，你不能假设它一直运行。

## 扩展的生命周期

理解扩展从安装到运行的完整生命周期，有助于写出更健壮的代码。

### 安装阶段

当用户安装扩展时，浏览器会执行以下步骤：

1. **解析 manifest.json**：浏览器读取并验证配置文件的合法性
2. **注册权限**：根据 `permissions` 和 `host_permissions` 向用户展示权限请求
3. **加载 Service Worker**：注册 Background Service Worker，但不会立即激活
4. **注入 Content Script**：对所有匹配 `content_scripts.matches` 的已打开标签页，注入对应的脚本

```javascript
// 监听扩展安装事件
chrome.runtime.onInstalled.addListener((details) => {
  if (details.reason === 'install') {
    console.log('扩展首次安装');
    // 初始化默认设置
    chrome.storage.local.set({
      settings: { theme: 'light', autoRun: false }
    });
  } else if (details.reason === 'update') {
    console.log(`扩展从 ${details.previousVersion} 更新到新版本`);
    // 处理版本迁移逻辑
  }
});
```

### 运行阶段

扩展安装完成后进入运行阶段，各组件按需加载：

- **Service Worker**：由事件触发唤醒，处理完事件后约 30 秒内被终止。它不会一直驻留内存。
- **Content Script**：在匹配的标签页加载时自动注入，标签页关闭时销毁。
- **Popup**：用户点击图标时创建，关闭时销毁。每次打开都是全新的页面实例。
- **Options Page**：用户打开设置页面时加载，关闭时销毁。

```javascript
// Service Worker 被唤醒时执行的初始化逻辑
// 每次唤醒都需要重新注册事件监听器（顶层代码会在每次唤醒时执行）
chrome.alarms.onAlarm.addListener((alarm) => {
  if (alarm.name === 'periodic-check') {
    console.log('定时任务触发');
  }
});

// 在安装时创建定时器（定时器会保持注册状态，即使 Service Worker 被终止）
chrome.runtime.onInstalled.addListener(() => {
  chrome.alarms.create('periodic-check', { periodInMinutes: 60 });
});
```

### 更新阶段

当扩展的新版本发布后，浏览器会自动下载更新。更新过程：

1. 浏览器检测到新版本（通过 Chrome 应用商店或 `update_url`）
2. 下载新的扩展包
3. 终止当前运行的所有组件
4. 用新版本替换旧文件
5. 重新注册 Service Worker，触发 `onInstalled` 事件（`reason` 为 `'update'`）

```javascript
chrome.runtime.onInstalled.addListener((details) => {
  if (details.reason === 'update') {
    const previousVersion = details.previousVersion;
    // 版本迁移：从 1.x 升级到 2.x 时可能需要迁移存储数据
    if (previousVersion.startsWith('1.')) {
      migrateFromV1();
    }
  }
});
```

### 禁用与卸载

用户可以在 `chrome://extensions/` 页面禁用或卸载扩展：

- **禁用**：停止所有组件的运行，但保留扩展数据（`chrome.storage` 中的数据不会丢失）
- **卸载**：停止所有组件并清除扩展的本地数据

```javascript
// 监听扩展卸载（注意：这个事件在 Service Worker 中不一定能可靠触发）
// 更好的做法是提供卸载调查链接
chrome.runtime.setUninstallURL('https://example.com/uninstall-survey');
```

## 常见误区

### 误区一：扩展可以自由访问所有网页

扩展不能随意访问网页内容。必须声明 `host_permissions` 或使用 `activeTab` 权限。没有权限时，Content Script 无法注入，API 调用会被拒绝。

### 误区二：Background 脚本一直在运行

Manifest V3 的 Service Worker 会在空闲约 30 秒后被终止。需要持久化的状态必须存入 `chrome.storage`，不能依赖全局变量。

```javascript
// 错误：依赖全局变量存储状态
let count = 0;

// 正确：使用 chrome.storage 持久化状态
async function incrementCount() {
  const { count = 0 } = await chrome.storage.local.get('count');
  await chrome.storage.local.set({ count: count + 1 });
}
```

### 误区三：Content Script 和网页共享 JavaScript 上下文

Content Script 运行在"隔离世界"（Isolated World）中，它看到的 DOM 是同一个，但 JavaScript 全局对象是独立的。网页脚本无法访问 Content Script 的变量，反之亦然。

### 误区四：permissions 可以随便加

过多的权限会吓跑用户，也会导致 Chrome 应用商店审核更严格。只申请真正需要的权限，能用 `activeTab` 就不用 `host_permissions`。

## 工程建议

1. **从 Manifest V3 开始**：V2 已被 Chrome 废弃，新扩展必须使用 V3。如果在学习旧教程时看到 `manifest_version: 2`，直接转换为 V3 语法。

2. **权限最小化**：只声明真正需要的权限，优先使用 `activeTab`。在提交 Chrome 应用商店审核时，权限越少，通过率越高。如果确实需要广泛的主机权限，在扩展描述中清楚说明原因。

3. **Service Worker 无状态化**：不要在 background 中维护内存状态，所有状态存入 `chrome.storage`。Service Worker 随时可能被终止，每次唤醒时从 storage 恢复状态是唯一可靠的方式。

4. **图标尺寸齐全**：准备 16/48/128 三种尺寸的图标，否则在不同场景下会显示模糊或缺失。16px 用于扩展管理页面列表，48px 用于扩展管理页面详情，128px 用于 Chrome 应用商店和安装确认弹窗。

5. **版本号语义化**：使用 `major.minor.patch` 格式，便于管理和更新。Chrome 应用商店要求每次提交的版本号必须递增。

6. **消息传递使用 `sendResponse` 时返回 `true`**：在异步消息处理中，必须从 `onMessage` 监听器返回 `true`，否则消息通道会提前关闭，`sendResponse` 将无法发送。

7. **使用 `chrome.storage.session` 存储临时敏感数据**：`chrome.storage.session` 的数据仅存在于当前浏览器会话中，关闭浏览器后自动清除，适合存放 token 等敏感信息。

8. **调试技巧**：Service Worker 的日志在扩展管理页面的"查看视图"中查看；Content Script 的日志在网页的 DevTools Console 中查看；Popup 的日志在 Popup 窗口内右键选择"检查"后查看。

9. **Content Script 的 `run_at` 选择**：`document_start` 适合尽早注入（如拦截页面脚本），`document_end` 适合在 DOM 构建完成后操作，`document_idle` 适合不急于执行的脚本（默认值，对页面加载性能影响最小）。

10. **避免在 Content Script 中直接修改全局样式**：如果需要注入 CSS，通过 `content_scripts.css` 字段声明，而不是在 JS 中动态创建 `<style>` 标签。前者更可控，也更容易排查问题。

## 小结

浏览器扩展是由多个隔离组件构成的应用，通过 Manifest 文件声明自身的能力和权限。Manifest V3 用 Service Worker 替代了持久化后台页面，用声明式网络请求替代了阻塞式拦截，整体更加安全和高效。

理解架构模型和权限体系是开发扩展的第一步。下一课我们将动手创建第一个扩展，实际体验这些组件如何协同工作。

## 参考答案

### 练习一

**思路**：每个组件运行在独立的 JavaScript 上下文中，但可以通过消息传递进行通信。关键点是理解哪些 API 在哪些上下文中可用，以及 DOM 的可访问性差异。

**答案**：

```
Background Service Worker
├── 可访问：chrome.* API（storage, tabs, alarms 等）
├── 不可访问：网页 DOM
├── 生命周期：事件驱动，空闲时被终止
└── 通信：通过 chrome.runtime.sendMessage 与其他组件通信

Content Script（注入到网页中）
├── 可访问：网页 DOM（同一份 DOM 树）
├── 可访问：有限的 chrome.* API（storage, runtime 等）
├── 不可访问：chrome.tabs, chrome.cookies 等需要特殊权限的 API
├── 隔离：与网页脚本共享 DOM 但隔离 JavaScript 全局对象
└── 通信：通过 chrome.runtime.sendMessage 向 Background 发消息

Popup（独立 HTML 页面）
├── 可访问：chrome.* API（同 Background）
├── 不可访问：网页 DOM
├── 生命周期：打开时创建，关闭时销毁
└── 通信：可以向 Background 和 Content Script 发消息

Options Page（独立 HTML 页面）
├── 可访问：chrome.* API（同 Background）
├── 不可访问：网页 DOM
└── 生命周期：打开时创建，关闭时销毁

通信关系：
Background <──消息──> Content Script
Background <──消息──> Popup
Background <──消息──> Options Page
Content Script ──消息──> Background ──消息──> Popup
```

**关键理解**：Content Script 不能直接和 Popup 通信，必须经过 Background 中转。这是因为它们运行在不同的上下文中，只有 Background Service Worker 能同时接收来自两者的消息。

### 练习二

**思路**：截图功能需要使用 `chrome.tabs.captureVisibleTab` API，这个 API 需要当前标签页的权限。

**答案**：

```json
{
  "permissions": ["activeTab"],
  "action": {
    "default_popup": "popup.html"
  }
}
```

选择 `activeTab` 而非 `host_permissions` 的原因：
- 截图只在用户点击图标时触发，不需要后台持续访问
- `activeTab` 权限更小，用户安装时的顾虑更少
- `chrome.tabs.captureVisibleTab` 在 `activeTab` 权限下即可使用

如果需要截取整个页面（不仅仅是可见区域），可能还需要 `"<all_urls>"` 的主机权限，因为需要注入脚本来滚动页面并拼接截图。此时的配置变为：

```json
{
  "permissions": ["activeTab"],
  "host_permissions": ["<all_urls>"],
  "action": {
    "default_popup": "popup.html"
  }
}
```

注意：即使需要全页面截图，也应该先尝试 `activeTab` 方案，只在确实需要持续访问页面时才添加 `host_permissions`。

### 练习三

**思路**：按要求逐一映射到 Manifest V3 配置字段。"可以访问所有 HTTPS 网页"对应 `host_permissions` 中的 `https://*/*` 模式。

**答案**：

```json
{
  "manifest_version": 3,
  "name": "学习笔记",
  "version": "1.0.0",
  "description": "在网页上记录学习笔记",
  "permissions": ["storage"],
  "host_permissions": ["https://*/*"],
  "action": {
    "default_popup": "popup.html"
  }
}
```

**要点**：
- `manifest_version: 3` 是必须的
- `host_permissions` 中的 `https://*/*` 匹配所有 HTTPS 页面
- `storage` 权限用于保存笔记数据
- `action.default_popup` 定义了点击图标后的弹出页面

**补充说明**：这个配置声明了对所有 HTTPS 页面的访问权限。在实际项目中，应该尽量缩小范围，例如只声明 `https://*.notion.so/*` 和 `https://*.yuque.com/*`，这样用户安装时会更放心。如果你的笔记功能只在用户主动触发时才需要操作页面，考虑用 `activeTab` 替代 `host_permissions`。

## 常见问题 FAQ

### Q1：扩展和用户脚本（Tampermonkey/Greasemonkey）有什么区别？

用户脚本运行在特定的用户脚本管理器中，本质上是注入到网页的 JavaScript，能力受限于管理器提供的 API。浏览器扩展则拥有完整的 Chrome API 访问权限（在声明权限的前提下），可以创建独立的 UI（Popup、Options Page、Side Panel），可以注册 Service Worker 在后台运行，还可以通过 Chrome 应用商店分发。简单来说，用户脚本适合轻量的页面修改，扩展适合构建完整的应用。

### Q2：一个扩展可以有多少个 Content Script？

一个扩展可以声明多组 Content Script，每组有不同的 `matches` 模式和注入脚本。例如，你可以让一组脚本只在 GitHub 上注入，另一组只在 Stack Overflow 上注入。每组 Content Script 的 JavaScript 运行在同一个隔离世界中，但不同组之间的变量是隔离的。

```json
{
  "content_scripts": [
    {
      "matches": ["https://github.com/*"],
      "js": ["github-helper.js"],
      "run_at": "document_idle"
    },
    {
      "matches": ["https://stackoverflow.com/*"],
      "js": ["stackoverflow-enhancer.js"],
      "run_at": "document_end"
    }
  ]
}
```

### Q3：为什么我的 Service Worker 中的全局变量总是丢失？

这是 Manifest V3 的设计行为。Service Worker 不是持久运行的，它会在空闲约 30 秒后被浏览器终止。每次被事件唤醒时，Service Worker 会重新执行顶层代码，之前的全局变量不复存在。解决方案是将所有需要跨会话保持的状态存入 `chrome.storage.local` 或 `chrome.storage.session`。

### Q4：扩展能在手机浏览器上运行吗？

Chrome for Android 不支持扩展。但 Firefox for Android 支持部分扩展（需要通过 Firefox 附加组件审核）。如果需要在移动端实现类似功能，可以考虑开发为 PWA（渐进式 Web 应用）或使用 WebView 方案。桌面端的 Chrome、Edge、Firefox、Safari 都支持扩展，但各自的 API 和 manifest 字段支持程度略有差异。
