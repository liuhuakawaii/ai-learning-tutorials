# 浏览器扩展是什么：不只是"一个小插件"

## 一个真实场景

团队有个痛点：设计师在 Figma 标注的颜色值，开发要手动复制到代码里。你决定做一个"取色器"扩展——在任意网页上按快捷键吸取颜色值，自动复制到剪贴板，popup 展示颜色历史。

这个需求看起来简单，但它涉及了扩展架构的方方面面：Content Script 注入到网页读取像素、Background Service Worker 存储颜色历史、Popup 展示 UI、manifest.json 声明权限。

搞不清楚每个组件的职责和通信方式，代码很快就会变成一团乱麻。

## 扩展的架构模型

浏览器扩展不是普通网页。它由多个隔离组件构成，每个运行在不同的上下文中：

```
Background Service Worker
  扩展的"大脑"
  不能访问网页 DOM
  监听事件、管理状态、协调组件

Content Script
  注入到网页中
  可以操作 DOM
  与网页脚本隔离（独立的 JS 全局对象）

Popup
  点击图标弹出的窗口
  独立 HTML 页面
  可以调用 Chrome API

Options Page
  扩展设置页面
  独立 HTML 页面
```

关键：**每个组件运行在完全隔离的 JavaScript 上下文中**。它们之间通过消息传递通信。

```typescript
// Content Script → Background
chrome.runtime.sendMessage({ type: 'COLOR_PICKED', color: '#ff0000' })

// Background 接收
chrome.runtime.onMessage.addListener((msg, sender, sendResponse) => {
  if (msg.type === 'COLOR_PICKED') {
    chrome.storage.local.set({ lastColor: msg.color })
    sendResponse({ status: 'ok' })
  }
  return true // 保持消息通道开启（异步响应）
})
```

## Manifest V3

每个扩展必须有一个 `manifest.json`：

```json
{
  "manifest_version": 3,
  "name": "网页取色器",
  "version": "1.0.0",
  "description": "在任意网页上吸取颜色值",
  "permissions": ["activeTab", "storage"],
  "action": {
    "default_popup": "popup.html"
  },
  "background": {
    "service_worker": "background.js"
  },
  "content_scripts": [
    {
      "matches": ["<all_urls>"],
      "js": ["content.js"],
      "run_at": "document_idle"
    }
  ],
  "commands": {
    "pick-color": {
      "suggested_key": { "default": "Ctrl+Shift+C" },
      "description": "吸取颜色"
    }
  }
}
```

### 权限最小化

```json
// 不好：请求所有网站权限
"host_permissions": ["<all_urls>"]

// 好：只在用户触发时获取权限
"permissions": ["activeTab"]
```

`activeTab` 只在用户点击扩展图标时临时获取当前标签页权限。审核更容易通过，用户更放心。

## 最小可运行扩展

```javascript
// background.js
chrome.runtime.onMessage.addListener((msg, sender, sendResponse) => {
  if (msg.type === 'WORD_COUNT') {
    chrome.storage.local.set({ wordCount: msg.count })
    sendResponse({ status: 'ok' })
  }
  return true
})

// content.js
function countWords() {
  const text = document.body.innerText
  const chinese = (text.match(/[\u4e00-\u9fa5]/g) || []).length
  const english = (text.match(/[a-zA-Z]+/g) || []).length
  return chinese + english
}

chrome.runtime.onMessage.addListener((msg, sender, sendResponse) => {
  if (msg.type === 'GET_WORD_COUNT') {
    sendResponse({ count: countWords() })
  }
  return true
})

// popup.js
document.getElementById('refresh').addEventListener('click', async () => {
  const [tab] = await chrome.tabs.query({ active: true, currentWindow: true })
  chrome.tabs.sendMessage(tab.id, { type: 'GET_WORD_COUNT' }, (response) => {
    document.getElementById('count').textContent = response.count
  })
})
```

## Service Worker 生命周期

Manifest V3 的 Background 是 Service Worker，**不是持久运行的**：

```
事件触发 → 唤醒 Service Worker → 处理事件 → 约 30 秒后终止
```

```javascript
// 错误：依赖全局变量
let count = 0

// 正确：用 chrome.storage 持久化
async function incrementCount() {
  const { count = 0 } = await chrome.storage.local.get('count')
  await chrome.storage.local.set({ count: count + 1 })
}
```

## 你大概率会踩的坑

**坑一：Background 一直运行**

不会的。Service Worker 随时可能被终止。所有状态必须存 `chrome.storage`。

**坑二：Content Script 和网页共享 JS 上下文**

不共享。Content Script 看到的 DOM 是同一个，但 JS 全局对象是独立的。

**坑三：permissions 随便加**

过多权限吓跑用户，也影响 Chrome 商店审核。能用 `activeTab` 就不用 `host_permissions`。

## 参考答案

### 练习一

文件结构：
```
word-counter/
├── manifest.json
├── background.js
├── content.js
├── popup.html
└── popup.js
```

manifest.json 如上。各文件代码如上。加载步骤：
1. chrome://extensions/ → 开发者模式
2. 加载已解压的扩展程序 → 选择目录
3. 打开任意网页 → 点击图标

### 练习二

```json
{
  "permissions": ["activeTab"],
  "action": { "default_popup": "popup.html" }
}
```

用 `activeTab` 而非 `host_permissions`，因为截图只在用户点击时触发。`chrome.tabs.captureVisibleTab` 在 `activeTab` 下可用。如果需要全页面截图（滚动拼接），才需要 `host_permissions`。

### 练习三：消息传递

Content Script 不能直接和 Popup 通信。必须经过 Background 中转。这是因为它们运行在不同的上下文中。
