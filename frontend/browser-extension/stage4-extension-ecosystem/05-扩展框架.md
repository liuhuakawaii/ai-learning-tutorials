# 扩展框架

## 场景引入

从零搭建扩展项目意味着：手动配置 manifest.json、处理构建流程、管理多入口文件、处理 HMR 热重载、适配多浏览器……这些重复性工作消耗大量时间。

扩展框架（如 WXT、Plasmo、CRXJS）正是为了解决这些问题而生。它们提供了脚手架、构建系统、热重载和多浏览器支持，让开发者专注于业务逻辑。

本课将对比主流扩展框架，帮助你选择合适的工具。

## 学习目标

- 了解主流扩展框架的特点和适用场景
- 掌握 WXT 框架的核心用法
- 学会使用 Plasmo 构建扩展
- 理解框架的构建原理

## 框架对比

| 特性 | WXT | Plasmo | CRXJS |
|------|-----|--------|-------|
| 构建工具 | Vite | Parcel | Vite |
| TypeScript | 原生支持 | 原生支持 | 原生支持 |
| React 支持 | 支持 | 深度集成 | 支持 |
| Vue 支持 | 支持 | 不支持 | 支持 |
| 多浏览器 | 自动适配 | 自动适配 | Chrome 为主 |
| 热重载 | 支持 | 支持 | 支持 |
| 社区活跃度 | 高 | 高 | 中 |
| 学习曲线 | 低 | 中 | 低 |

## WXT

WXT 是目前最推荐的扩展框架，开箱即用、配置简单、多浏览器支持好。

### 创建项目

```bash
npx wxt@latest init my-extension
cd my-extension
npm install
```

### 项目结构

```
my-extension/
├── entrypoints/
│   ├── background.ts        # Service Worker
│   ├── content.ts           # Content Script
│   ├── popup/
│   │   ├── index.html
│   │   └── main.ts
│   └── options/
│       ├── index.html
│       └── main.ts
├── public/
│   └── icons/
├── wxt.config.ts
└── package.json
```

### wxt.config.ts

```typescript
import { defineWxtConfig } from 'wxt';

export default defineWxtConfig({
  manifest: {
    name: 'My Extension',
    description: 'A browser extension built with WXT',
    permissions: ['activeTab', 'storage'],
    action: {
      default_popup: 'popup'
    }
  },
  manifestVersion: 3
});
```

### Background 入口

```typescript
// entrypoints/background.ts
export default defineBackground(() => {
  console.log('Background service worker started');

  chrome.runtime.onInstalled.addListener(() => {
    console.log('Extension installed');
  });

  chrome.runtime.onMessage.addListener((message, sender, sendResponse) => {
    if (message.type === 'PING') {
      sendResponse({ pong: true });
    }
  });
});
```

```typescript
      this.showMenu(selection);
    }

    // ...
  }
```

```typescript
// entrypoints/popup/main.ts
import './style.css';

document.getElementById('app')!.innerHTML = `
  <h1>My Extension</h1>
  <button id="action-btn">Click me</button>
  <div id="result"></div>
`;

document.getElementById('action-btn')?.addEventListener('click', async () => {
  const [tab] = await chrome.tabs.query({ active: true, currentWindow: true });
  const response = await chrome.tabs.sendMessage(tab.id!, { type: 'GET_INFO' });
  document.getElementById('result')!.textContent = JSON.stringify(response);
});
```

### Popup（React）

```tsx
// src/popup.tsx
import { useState, useEffect } from "react";

function IndexPopup() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    chrome.storage.local.get("count").then(({ count = 0 }) => {
      setCount(count);
    });
  }, []);

  const increment = async () => {
    const newCount = count + 1;
    setCount(newCount);
    await chrome.storage.local.set({ count: newCount });
  };

  return (
    <div style={{ padding: 16, width: 300 }}>
      <h1>Count: {count}</h1>
      <button onClick={increment}>Increment</button>
    </div>
  );
}

export default IndexPopup;
```

## CRXJS

CRXJS 是基于 Vite 的轻量级方案，适合 Vue 项目。

### 配置

```javascript
// vite.config.js
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
import { crx } from '@crxjs/vite-plugin';
import manifest from './manifest.json';

export default defineConfig({
  plugins: [
    vue(),
    crx({ manifest })
  ]
});
```

### manifest.json

```json
{
  "manifest_version": 3,
  "name": "My Extension",
  "version": "1.0.0",
  "action": {
    "default_popup": "src/popup/index.html"
  },
  "background": {
    "service_worker": "src/background.ts"
  },
  "content_scripts": [
    {
      "matches": ["<all_urls>"],
      "js": ["src/content.ts"]
    }
  ]
}
```

## 框架选型建议

### 选择 WXT 如果：

- 需要多浏览器支持
- 使用 Vue 或原生 JS
- 想要开箱即用的体验
- 需要良好的 TypeScript 支持

### 选择 Plasmo 如果：

- 使用 React
- 需要丰富的功能（存储 API、消息传递等封装）
- 想要声明式的 Content Script 配置

### 选择 CRXJS 如果：

- 使用 Vue
- 已有 Vite 项目想改造为扩展
- 需要最轻量的方案

## 手动构建 vs 框架

### 手动构建

```javascript
// webpack.config.js 或 vite.config.js
module.exports = {
  entry: {
    background: './src/background.js',
    content: './src/content.js',
    popup: './src/popup/main.js'
  },
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: '[name].js'
  }
};
```

手动构建的优势：
- 完全控制构建流程
- 不依赖第三方框架
- 更理解扩展的底层结构

手动构建的劣势：
- 需要自己处理多入口
- 热重载需要自己实现
- 多浏览器适配需要手动配置

## 常见误区

### 误区一：框架会增加扩展体积

框架主要影响构建过程，不会显著增加运行时代码体积。WXT 和 Plasmo 的运行时开销很小。

### 误区二：框架锁定

大多数框架生成的标准扩展代码，可以随时脱离框架独立维护。

### 误区三：不需要理解底层

使用框架不意味着不需要理解 Manifest V3、Content Script、Service Worker 等概念。框架只是简化了配置，底层知识仍然重要。

## 工程建议

1. **新项目推荐 WXT**：开箱即用、多浏览器支持好
2. **React 项目考虑 Plasmo**：深度集成 React，开发体验好
3. **学习底层知识**：即使使用框架，也要理解扩展的底层结构
4. **定期更新框架**：框架会跟进浏览器 API 的变化
5. **评估框架成熟度**：选择活跃维护、社区大的框架

## 小结

扩展框架（WXT、Plasmo、CRXJS）大大简化了扩展开发流程，提供了脚手架、构建系统、热重载和多浏览器支持。选择合适的框架可以让开发效率提升数倍。

### 练习二

**答案**：

```tsx
// src/popup.tsx
import { useState } from "react";
import { useStorage } from "@plasmohq/storage/hook";

function IndexPopup() {
  const [theme, setTheme] = useStorage("theme", "light");
  const [count, setCount] = useStorage("count", 0);

  return (
    <div style={{ padding: 16, width: 300 }}>
      <h1>Theme: {theme}</h1>
      <button onClick={() => setTheme(theme === "light" ? "dark" : "light")}>
        Toggle Theme
      </button>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>Increment</button>
    </div>
  );
}

export default IndexPopup;
```

### 练习三

**答案**：

迁移步骤：
1. 初始化 WXT 项目
2. 将 background.js 移动到 entrypoints/background.ts
3. 将 content.js 移动到 entrypoints/content.ts
4. 将 popup 移动到 entrypoints/popup/
5. 将 manifest.json 中的配置迁移到 wxt.config.ts
6. 更新导入路径
7. 运行测试验证功能
