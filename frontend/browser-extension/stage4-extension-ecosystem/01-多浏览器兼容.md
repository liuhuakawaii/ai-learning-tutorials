# 多浏览器兼容

## 场景引入

你开发了一个 Chrome 扩展，用户问"Firefox 版本什么时候出？"，老板说"Edge 也要支持"。你以为改改配置就行了，结果发现：Firefox 用的是 `browser.*` API 而不是 `chrome.*`，某些 API 在 Edge 上不可用，Manifest V3 的支持程度各不相同……

多浏览器兼容是扩展开发中最容易被低估的挑战。本课将讲解如何用一套代码同时支持 Chrome、Firefox 和 Edge。

## 学习目标

- 理解三端浏览器扩展 API 的差异
- 掌握 WebExtensions Polyfill 的使用
- 学会条件编译和特性检测
- 构建跨浏览器兼容的扩展项目

## API 差异概览

| 特性 | Chrome | Firefox | Edge |
|------|--------|---------|------|
| API 命名空间 | `chrome.*` | `browser.*`（支持 `chrome.*`） | `chrome.*` |
| Promise 支持 | Chrome 99+ | 原生支持 | 同 Chrome |
| Manifest V3 | 支持 | 部分支持（MV2 仍可用） | 同 Chrome |
| Service Worker | 支持 | 不支持（使用 Event Pages） | 支持 |
| Side Panel | Chrome 114+ | 不支持 | 支持 |
| Declarative Net Request | 支持 | 支持 | 支持 |

### Firefox 的特殊之处

Firefox 使用 `browser.*` 命名空间，原生支持 Promise：

```javascript
// Chrome 风格
chrome.tabs.query({ active: true }, (tabs) => {
  console.log(tabs);
});

// Firefox 风格
const tabs = await browser.tabs.query({ active: true });
console.log(tabs);
```

Firefox 也支持 `chrome.*` 作为兼容层，但行为可能有细微差异。例如，`chrome.*` 的回调版本在 Firefox 中可能不会正确传递错误信息，而 `browser.*` 版本会在 Promise rejection 中包含详细错误。

### Edge 的特殊之处

Edge 基于 Chromium 内核，API 与 Chrome 高度一致，但仍有一些差异：

- Edge 不支持 `chrome.sidePanel` 的部分子 API（如 `setPanelOptions`）
- Edge 的 `chrome.runtime.getBrowserInfo()` 返回 `{ name: "Edge" }` 而非 Chrome 的 `{ name: "Chrome" }`
- Edge 某些版本对 `declarativeNetRequest` 的规则数量限制与 Chrome 不同

### API 行为差异对比

```javascript
// chrome.tabs.query 在三端的行为对比
// Chrome 和 Edge：必须传入 queryInfo 对象
chrome.tabs.query({ active: true, currentWindow: true }, (tabs) => {});

// Firefox：可以省略 queryInfo，返回所有标签页
browser.tabs.query().then((tabs) => {});

// webextension-polyfill 统一后的写法
import browser from 'webextension-polyfill';
const tabs = await browser.tabs.query({ active: true, currentWindow: true });
```

## WebExtensions Polyfill

`webextension-polyfill` 是 Mozilla 维护的 polyfill 库，让统一使用 `browser.*` API 并自动处理 Promise 化。

### 安装

```bash
npm install webextension-polyfill
```

### 使用

```javascript
import browser from 'webextension-polyfill';

// 统一使用 browser.* API
const tabs = await browser.tabs.query({ active: true, currentWindow: true });
const response = await browser.tabs.sendMessage(tabs[0].id, { type: 'PING' });

// 存储
await browser.storage.local.set({ key: 'value' });
const { key } = await browser.storage.local.get('key');

// 监听事件
browser.runtime.onMessage.addListener((message, sender) => {
  if (message.type === 'PING') {
    return Promise.resolve({ pong: true });
  }
});
```

### Polyfill 的工作原理

`webextension-polyfill` 在 Chrome 上会将 `chrome.*` 的回调式 API 包装为 Promise，同时暴露为 `browser.*` 命名空间。在 Firefox 上，它直接透传原生的 `browser.*` API（因为 Firefox 原生就返回 Promise）。核心逻辑可以简化为：

```javascript
// 简化的 polyfill 内部逻辑（非实际源码）
if (typeof browser === 'undefined' || !browser.runtime?.getBrowserInfo) {
  // 当前是 Chrome/Edge，需要包装
  globalThis.browser = wrapChromeAPIs(chrome);
} else {
  // 当前是 Firefox，直接使用原生 browser
  globalThis.browser = browser;
}
```

这意味着在 Chrome 上，`browser.storage.local.get()` 本质上还是调用 `chrome.storage.local.get()`，只是多了一层 Promise 包装。性能开销可以忽略不计。

### 在 Manifest 中引入

```json
{
  "background": {
    "scripts": ["polyfill.js", "background.js"]
  },
  "content_scripts": [
    {
      "matches": ["<all_urls>"],
      "js": ["polyfill.js", "content.js"]
    }
  ]
}
```

### Popup 和 Side Panel 中引入

```html
<script src="polyfill.js"></script>
<script src="popup.js"></script>
```

### TypeScript 类型支持

```bash
npm install -D @types/webextension-polyfill
```

```typescript
// 安装类型后，IDE 会提供完整的 API 提示
import browser from 'webextension-polyfill';

// 自动推导返回类型为 Tab[]

// 自动推导返回类型为 { [key: string]: any }

```

## Manifest 差异处理

Chrome 和 Firefox 的 Manifest 有一些差异：

```javascript
// build/manifest-adapter.js
function adaptManifest(manifest, browser) {
  const adapted = { ...manifest };

  if (browser === 'firefox') {
    // Firefox 不支持 side_panel
    delete adapted.side_panel;

    // Firefox 使用 browser_specific_settings
    adapted.browser_specific_settings = {
      gecko: {
        id: 'my-extension@example.com',
        strict_min_version: '109.0'
      }
    };

    // Firefox 的 background 使用 scripts 而非 service_worker
    if (adapted.background?.service_worker) {
      adapted.background = {
        scripts: [adapted.background.service_worker]
      };
    }
  }

  return adapted;
}
```

### 完整的 Manifest 适配示例

在实际项目中，Manifest 适配往往比上面的简单示例更复杂。以下是一个更完整的适配脚本，覆盖了常见的差异点：

```javascript
// build/manifest-adapter.js
import fs from 'fs';
import path from 'path';

/**
 * 根据目标浏览器适配 manifest.json
 * @param {object} baseManifest - 基础 manifest 对象
 * @param {'chrome' | 'firefox' | 'edge'} targetBrowser - 目标浏览器
 * @returns {object} 适配后的 manifest
 */
export function adaptManifest(baseManifest, targetBrowser) {
  // 深拷贝，避免修改原始对象
  const manifest = JSON.parse(JSON.stringify(baseManifest));

  switch (targetBrowser) {
    case 'firefox':
      return adaptForFirefox(manifest);
    case 'edge':
      return adaptForEdge(manifest);
    case 'chrome':
    default:
      return manifest;
  }
}

function adaptForFirefox(manifest) {
  // 1. 添加 Firefox 特有配置
  manifest.browser_specific_settings = {
    gecko: {
      id: manifest.name.replace(/\s+/g, '-').toLowerCase() + '@example.com',
      strict_min_version: '109.0'
    }
  };

  // 2. Service Worker → Event Pages（Firefox 不支持 SW）
  if (manifest.background?.service_worker) {
    manifest.background = {
      scripts: [manifest.background.service_worker],
      type: 'module' // 保持 ES Module 语法
    };
  }

  // 3. 移除 Firefox 不支持的字段
  delete manifest.side_panel;
  delete manifest.side_panel_default_path;

  // 4. action 统一处理（MV3 的 action 在 Firefox MV2 中是 browser_action）
  // 注意：Firefox 109+ 已支持 MV3 的 action 字段

  // 5. 移除 Chrome 特有的权限
  const chromeOnlyPermissions = ['sidePanel', 'offscreen'];
  if (manifest.permissions) {
    manifest.permissions = manifest.permissions.filter(
      (p) => !chromeOnlyPermissions.includes(p)
    );
  }

  return manifest;
}

function adaptForEdge(manifest) {
  // Edge 基于 Chromium，差异较小
  // Edge 不支持部分 side_panel 子功能，但字段本身不会报错
  // 通常可以直接使用 Chrome 的 manifest
  return manifest;
}

// 构建脚本中使用
const browser = process.argv[2] || 'chrome';
const rawManifest = JSON.parse(
  fs.readFileSync(path.resolve('src/manifest.json'), 'utf-8')
);
const adapted = adaptManifest(rawManifest, browser);

const outputDir = path.resolve(`dist/${browser}`);
fs.mkdirSync(outputDir, { recursive: true });
fs.writeFileSync(
  path.join(outputDir, 'manifest.json'),
  JSON.stringify(adapted, null, 2)
);
console.log(`✅ 已生成 ${browser} 的 manifest.json`);
```

## 特性检测

```javascript
// utils/feature-detect.js
export const features = {
  sidePanel: typeof chrome !== 'undefined' && !!chrome.sidePanel,

  offscreen: typeof chrome !== 'undefined' && !!chrome.offscreen,

  tabGroups: typeof chrome !== 'undefined' && !!chrome.tabGroups,

  declarativeNetRequest: typeof chrome !== 'undefined' && !!chrome.declarativeNetRequest,

  scripting: typeof chrome !== 'undefined' && !!chrome.scripting
};

export function requireFeature(featureName) {
  if (!features[featureName]) {
    throw new Error(`当前浏览器不支持 ${featureName} 功能`);
  }
}
```

```javascript
// 使用特性检测
import { features, requireFeature } from './utils/feature-detect';

if (features.sidePanel) {
  chrome.sidePanel.setPanelBehavior({ openPanelOnActionClick: true });
} else {
  // 降级方案：使用 popup
  chrome.action.setPopup({ popup: 'popup.html' });
}
```

## CSS 兼容性

扩展的 UI 页面（popup、sidepanel、options）运行在浏览器提供的渲染环境中，不同浏览器对 CSS 的支持存在差异。以下是常见的兼容性问题和解决方案：

```css
/* 使用 CSS 变量实现主题一致性 */
:root {
  --ext-primary: #1a73e8;
  --ext-bg: white;
  --ext-text: #333;
}

/* Firefox 和 Chrome 的滚动条差异 */
::-webkit-scrollbar {
  width: 8px;
}

/* Firefox */
* {
  scrollbar-width: thin;
  scrollbar-color: #ccc transparent;
}
```

### 表单元素样式重置

不同浏览器对表单元素（`<select>`、`<input>`、`<button>`）的默认样式差异很大。在扩展的 popup 和 options 页面中，建议做统一重置：

```css
/* 统一表单元素的基础样式 */
input, select, textarea, button {
  font-family: inherit;
  font-size: inherit;
  color: inherit;
  border: 1px solid #ccc;
  border-radius: 4px;
  padding: 6px 10px;
  background-color: var(--ext-bg);
  outline: none;
  box-sizing: border-box;
}

/* 聚焦态统一 */
input:focus, select:focus, textarea:focus {
  border-color: var(--ext-primary);
  box-shadow: 0 0 0 2px rgba(26, 115, 232, 0.2);
}

/* Firefox 的 select 下拉箭头需要单独处理 */
select {
  -moz-appearance: none;
  -webkit-appearance: none;
  appearance: none;
  background-image: url("data:image/svg+xml,..."); /* 自定义箭头图标 */
  background-repeat: no-repeat;
  background-position: right 8px center;
  padding-right: 28px;
}
```

### 弹出层定位差异

扩展的 popup 页面在不同浏览器中的尺寸计算可能不同：

```css
/* popup 页面基础样式 */
body {
  width: 350px;
  min-height: 200px;
  max-height: 600px;
  margin: 0;
  padding: 12px;
  overflow-y: auto;
  /* 避免内容溢出导致 popup 尺寸异常 */
}

/* Firefox 的 popup 高度由内容撑开，Chrome 有最大高度限制 */
/* 如果需要固定高度的滚动区域，用容器控制而非 body */
.scroll-container {
  max-height: 400px;
  overflow-y: auto;
}
```

## 实战：完整的跨浏览器构建流程

以下演示如何用 WXT 和 Vite 两种方案搭建一个完整的跨浏览器扩展项目。

### 方案一：使用 WXT 框架

WXT 是专为浏览器扩展设计的开发框架，内置跨浏览器构建支持。

**项目目录结构：**

├── package.json
├── tsconfig.json
├── entrypoints/

│   │   ├── main.ts            # Popup 逻辑
│   │   └── style.css          # Popup 样式
│   └── sidepanel/             # Side Panel（仅 Chrome/Edge）
│       ├── index.html
│       └── main.ts
├── utils/
│   ├── browser-detect.ts      # 浏览器检测
│   └── feature-detect.ts      # 特性检测

## 浏览器兼容性测试

跨浏览器扩展必须在目标浏览器上逐一验证。以下介绍手动测试和 CI 自动化测试的方法。

### 手动测试流程

**Chrome 测试：**

1. 打开 `chrome://extensions/`
2. 开启「开发者模式」
3. 点击「加载已解压的扩展程序」，选择 `dist/chrome/` 目录
4. 逐一验证：popup 打开、background 运行、content script 注入、storage 读写、消息通信

**Firefox 测试：**

1. 打开 `about:debugging#/runtime/this-firefox`
2. 点击「临时载入附加组件」，选择 `dist/firefox/manifest.json`
3. Firefox 的临时扩展在浏览器重启后会失效，需要重新加载
4. 重点关注：`browser_specific_settings` 是否正确、background 脚本是否正常运行、API 调用是否有兼容性警告

**Edge 测试：**

1. 打开 `edge://extensions/`
2. 开启「开发人员模式」
3. 点击「加载解压缩」，选择 `dist/edge/` 目录
4. Edge 的测试重点是 side panel 行为是否与 Chrome 一致

import puppeteer from 'puppeteer';
import path from 'path';

const EXTENSION_PATH = path.resolve('dist/chrome');

async function testExtension() {
  const browser = await puppeteer.launch({
    headless: false, // 扩展测试需要有头模式
    args: [
      `--disable-extensions-except=${EXTENSION_PATH}`,
      `--load-extension=${EXTENSION_PATH}`,

  const page = await browser.newPage();

  // 测试 popup 是否能正常打开

  if (!serviceWorkerTarget) {

    await browser.close();
    process.exit(1);
  }

  console.log('✅ Service Worker 已加载');

  // 测试 content script 注入
  await page.goto('https://example.com');
  const hasContentScript = await page.evaluate(() => {
    // 检查 content script 是否设置了标记
    return document.body.dataset.extensionLoaded === 'true';
  });

  if (hasContentScript) {
    console.log('✅ Content Script 已注入');
  } else {
    console.log('⚠️ Content Script 未检测到标记');
  }

  // 测试 storage 功能
  const storageResult = await page.evaluate(async () => {
    return new Promise((resolve) => {
      chrome.storage.local.set({ test: 'hello' }, () => {
        chrome.storage.local.get('test', (result) => {
          resolve(result);
        });
      });
    });
  });

  if (storageResult.test === 'hello') {
    console.log('✅ Storage 读写正常');
  } else {
    console.error('❌ Storage 读写失败');
  }

  await browser.close();
  console.log('\n所有测试完成');
}

testExtension().catch(console.error);

- [ ] 卸载后无残留数据
- [ ] 在目标最低版本浏览器上也能运行

## 常见误区

### 误区一：Chrome 扩展直接在 Firefox 上运行

即使使用 `chrome.*` 命名空间，某些 API 的行为可能不同。必须进行兼容性测试。

### 误区二：Polyfill 解决所有问题

`webextension-polyfill` 只处理 API 命名和 Promise 化。某些 API 在特定浏览器上完全不存在，polyfill 无法弥补。

### 误区三：不需要测试所有浏览器

Chrome 和 Edge 通常兼容性较好，但 Firefox 差异较大。每个版本发布前必须在三端测试。

### 误区四：只考虑最新版本

某些用户可能使用旧版本浏览器。使用 `minimum_chrome_version` 和 Firefox 的 `strict_min_version` 限制最低版本。

## 工程建议

1. **使用 Polyfill**：`webextension-polyfill` 是最成熟的跨浏览器方案
2. **构建分离**：为每个浏览器生成独立的构建产物
3. **特性检测**：不要假设所有 API 在所有浏览器上都可用
4. **CI/CD 测试**：在 CI 中配置三端自动化测试
5. **渐进增强**：核心功能在所有浏览器上可用，高级功能按浏览器降级

## 小结

多浏览器兼容的核心是统一 API 调用方式（Polyfill）、处理 Manifest 差异、特性检测和降级策略。通过合理的架构设计，可以用一套代码同时支持 Chrome、Firefox 和 Edge。

## 参考答案

### 练习一

**思路**：将所有 `chrome.*` 调用替换为 `browser.*`，利用 polyfill 自动处理 Promise 化。需要注意：引入 polyfill 后，事件监听器的返回值必须是 Promise（而非使用 `sendResponse` 回调）。

**答案**：

```javascript
// 改造前：Chrome 风格的 background.js
chrome.runtime.onMessage.addListener((message, sender, sendResponse) => {
  if (message.type === 'GET_TABS') {
    chrome.tabs.query({ active: true, currentWindow: true }, (tabs) => {
      sendResponse({ tabs });
    });
    return true; // 表示异步响应
  }
});

// 改造后：使用 webextension-polyfill
import browser from 'webextension-polyfill';

browser.runtime.onMessage.addListener((message, sender) => {
  if (message.type === 'GET_TABS') {
    // 直接返回 Promise，polyfill 会自动处理消息通道
    return browser.tabs.query({ active: true, currentWindow: true })
      .then((tabs) => ({ tabs }));
  }
});

// 调用端也需要改造
// 改造前
chrome.runtime.sendMessage({ type: 'GET_TABS' }, (response) => {
  console.log(response.tabs);
});

// 改造后
import browser from 'webextension-polyfill';

const response = await browser.runtime.sendMessage({ type: 'GET_TABS' });
console.log(response.tabs);
```

**要点**：
- 引入 polyfill 后，事件监听器中不再需要 `sendResponse` 回调和 `return true`
- 直接返回 Promise 即可，polyfill 会自动将结果传递给调用方
- Manifest 中需要在所有脚本之前加载 `polyfill.js`

### 练习二

**思路**：通过特性检测判断当前浏览器是否支持 `sidePanel` API，支持则使用 Side Panel，不支持则降级为 Popup。同时需要在 Manifest 适配层移除 Firefox 不支持的字段。

**答案**：

```javascript
// src/background/index.ts
import browser from 'webextension-polyfill';

// 特性检测
const supportsSidePanel = typeof chrome !== 'undefined' && !!chrome.sidePanel;

async function setupUI() {
  if (supportsSidePanel) {
    // Chrome / Edge：使用 Side Panel
    chrome.sidePanel.setPanelBehavior({ openPanelOnActionClick: true });
    // 可选：设置默认面板路径
    chrome.sidePanel.setOptions({
      path: 'sidepanel/index.html',
      enabled: true,
    });
  } else {
    // Firefox：降级为 Popup
    await browser.action.setPopup({ popup: 'popup/index.html' });
  }
}

// 点击图标时的降级处理
browser.action.onClicked.addListener(async (tab) => {
  if (supportsSidePanel) {
    // Side Panel 模式下，点击行为由 setPanelBehavior 控制
    // 这里可以添加额外逻辑，如传递当前页面信息
    await chrome.sidePanel.open({ tabId: tab.id });
  }
  // Popup 模式下，浏览器自动处理点击事件，无需额外代码
});

setupUI().catch(console.error);
```

```typescript
// build/manifest-adapter.ts（配合构建脚本）
function adaptForFirefox(manifest: any) {
  // 移除 side_panel 相关配置
  delete manifest.side_panel;
  delete manifest.side_panel_default_path;

  // 移除 sidePanel 权限
  manifest.permissions = (manifest.permissions || []).filter(
    (p: string) => p !== 'sidePanel'
  );

  return manifest;
}
```

**要点**：
- 特性检测应在运行时进行，不能依赖构建时的静态判断
- `chrome.sidePanel.open()` 是异步操作，需要 `await`
- Firefox 的 Manifest 中不能包含 `side_panel` 字段，否则加载报错

### 练习三

**思路**：使用环境变量区分目标浏览器，在构建脚本中读取环境变量并调用 manifest 适配函数。每个浏览器输出到独立目录，最后打包为 zip。

**答案**：

```json
{
  "scripts": {
    "build": "npm run build:chrome && npm run build:firefox && npm run build:edge",
    "build:chrome": "vite build --mode chrome",
    "build:firefox": "vite build --mode firefox",
    "build:edge": "vite build --mode edge",
    "package": "npm run build && node scripts/package.js"
  }
}
```

```javascript
// scripts/package.js
import fs from 'fs';
import path from 'path';
import { createWriteStream } from 'fs';
import archiver from 'archiver';

const browsers = ['chrome', 'firefox', 'edge'];

async function packageAll() {
  for (const browser of browsers) {
    const distDir = path.resolve(`dist/${browser}`);
    const outputPath = path.resolve(`dist/${browser}-extension.zip`);

    if (!fs.existsSync(distDir)) {
      console.warn(`⚠️ dist/${browser}/ 不存在，跳过打包`);
      continue;
    }

    await new Promise((resolve, reject) => {
      const output = createWriteStream(outputPath);
      const archive = archiver('zip', { zlib: { level: 9 } });

      output.on('close', () => {
        const sizeKB = (archive.pointer() / 1024).toFixed(1);
        console.log(`✅ ${browser}-extension.zip 打包完成 (${sizeKB} KB)`);
        resolve();
      });

      archive.on('error', reject);
      archive.pipe(output);
      archive.directory(distDir, false);
      archive.finalize();
    });
  }
}

packageAll().catch(console.error);
```
