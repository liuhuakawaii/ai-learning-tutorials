# 阶段实战：页面性能体检报告——用数据说话

## 现象

你刚加入新团队，领导让你评估核心产品的前端性能。你跑了一遍 Lighthouse 拿到 72 分，但不知道这意味着什么——哪些问题最严重？先修什么？

一份结构化的性能体检报告能把问题按影响排序，给出具体修复方案。

## 体检流程

```
Step 1: 选择目标页面（本课程用 slow.html）
Step 2: 运行 Lighthouse（Mobile + Desktop）
Step 3: 录制 Performance Trace
Step 4: 分析 Network 面板
Step 5: 记录每个问题（描述 + 证据 + 影响指标）
Step 6: 排定优先级（影响 × 修复难度）
Step 7: 输出报告
```

## 问题记录模板

```markdown
### 问题 1：[问题标题]
- **影响指标**：LCP / CLS / INP
- **问题描述**：具体是什么问题
- **证据**：截图或数据
- **根因分析**：为什么会有这个问题
- **影响程度**：高 / 中 / 低
- **建议修复方案**：具体怎么做
```

## 优先级矩阵

```
            修复难度
            低        中        高
影响  高  │ P0 立刻 │ P1 尽快 │ P2 规划 │
      中  │ P1 尽快 │ P2 规划 │ P3 有空 │
      低  │ P2 规划 │ P3 有空 │ P4 可能 │
```

## 完整报告示例

```markdown
# 性能体检报告 - slow.html

## 1. 基本信息
- 测试 URL：http://localhost:4173/slow.html
- 测试时间：2026-06-23
- 测试工具：Lighthouse 12.x, Chrome DevTools

## 2. Lighthouse 报告（Mobile）
| 指标 | 值 | 评级 |
|------|-----|------|
| Performance | 45 | ❌ Poor |
| LCP | 4.2s | ❌ Poor |
| TBT | 680ms | ❌ Poor |
| CLS | 0.22 | ⚠️ Needs Improvement |

## 3. 问题清单

### 问题 1：产品主图未压缩（3MB PNG）
- 影响指标：LCP
- 证据：Network 面板显示 hero.png 3MB
- 根因：原图直接使用，未压缩
- 影响程度：高
- 修复方案：转 WebP，压缩至 200KB，添加 preload

### 问题 2：首屏加载了不需要的 JS
- 影响指标：TBT, LCP
- 证据：analytics.js 180ms + chat.js 120ms 阻塞主线程
- 影响程度：高
- 修复方案：defer 或延迟加载

### 问题 3：图片没有设置尺寸
- 影响指标：CLS
- 证据：Layout Shift Regions 显示偏移 0.15
- 影响程度：中
- 修复方案：添加 width/height 或 aspect-ratio

## 4. 优先级排序
| 优先级 | 问题 | 预期效果 |
|--------|------|----------|
| P0 | 产品主图压缩 | LCP -2s |
| P0 | 延迟加载第三方脚本 | TBT -300ms |
| P1 | 图片设置尺寸 | CLS -0.15 |
```

## 你可能踩的坑

**坑一：报告只有数据没有分析**

LCP 是多少秒没意义，要说明 LCP 元素是什么、为什么慢、怎么修。

**坑二：问题不排序**

发现 20 个问题不知道先修哪个。用优先级矩阵排序。

**坑三：只用 Lab 数据**

Lighthouse 只反映实验室环境，用 PageSpeed Insights 补充 CrUX 真实用户数据。

## 参考答案

### 练习一

报告模板如上。关键步骤：
1. F12 → Lighthouse → Mobile → Analyze
2. F12 → Performance → Record → 刷新页面 → Stop
3. F12 → Network → 刷新 → 记录总大小和请求数
4. 记录每个问题的证据和修复方案

### 练习二

```
                slow.html    optimized.html    改善
LCP             4.2s         1.8s              -57%
TBT             680ms        120ms             -82%
CLS             0.22         0.05              -77%
JS 总量         1.2MB        320KB             -73%
图片总量         3.1MB        400KB             -87%
```

改善最大的是图片优化（WebP + 压缩）和脚本优化（defer + 移除不必要的第三方脚本）。
