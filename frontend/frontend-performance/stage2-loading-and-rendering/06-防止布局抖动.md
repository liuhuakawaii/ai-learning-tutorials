# 第6课：防止布局抖动

> **课程定位**：理解和消除 CLS（Cumulative Layout Shift），让页面视觉稳定
> **前置知识**：了解 Core Web Vitals 中的 CLS 指标
> **预计时长**：35 分钟

## 场景引入

用户正在手机上阅读一篇新闻，手指悬停在"分享"按钮上准备点击。突然一个广告 Banner 加载出来，整个页面往下推了 100 像素，用户的手指点到了旁边的广告链接。这不是用户手抖，而是布局抖动（Layout Shift）。这种体验在移动端尤其糟糕——屏幕小、内容密集，任何布局偏移都会导致误操作。CLS 不只是一个数字，它衡量的是用户对你页面的信任程度。

## 一、CLS 是什么

```
┌──────────────────────────────────────────────────────────────┐
│                    CLS 计算公式                               │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  布局偏移分数 = 影响分数 × 距离分数                            │
│                                                              │
│  影响分数：不稳定元素影响的可视区域比例                         │
│  距离分数：不稳定元素移动的最大距离比例                         │
│                                                              │
│  例：一个占屏幕 50% 的元素向下移动了 25%                       │
│      CLS = 0.5 × 0.25 = 0.125                               │
│                                                              │
│  好的 CLS：< 0.1                                             │
│  需要改进：0.1 ~ 0.25                                        │
│  差：> 0.25                                                  │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## 三、图片布局稳定

### 3.1 始终设置宽高

```html
<!-- ❌ 没有尺寸 → 加载前高度为 0 → 布局抖动 -->
<img src="/photo.jpg">

<!-- ✅ 设置 width 和 height → 浏览器预留空间 -->
<img src="/photo.jpg" width="800" height="600">

<!-- ✅ 响应式图片：用 CSS 控制实际显示尺寸 -->
<style>
  img {
    max-width: 100%;
    height: auto;
  }
</style>
<img src="/photo.jpg" width="800" height="600">
```

### 3.2 aspect-ratio

```css
/* 用 aspect-ratio 替代固定高度 */
.hero-image {
  width: 100%;
  aspect-ratio: 16 / 9;
  object-fit: cover;
}

/* 适用于不知道具体尺寸但知道比例的场景 */
.card-thumbnail {
  width: 100%;
  aspect-ratio: 3 / 2;
  background: #f0f0f0; /* 占位色 */
}
```

### 3.3 图片占位符

```javascript
// 方案 1：模糊占位图（BlurHash / LQIP）
<img src="/photo-blur.jpg" width="800" height="600">
// 加载完成后替换为高清图

// 方案 2：骨架屏
<div class="skeleton" style="width: 100%; aspect-ratio: 16/9;"></div>

// 方案 3：CSS 背景色占位
<img src="/photo.jpg" width="800" height="600"
     style="background: #e8e8e8;">
```

## 四、字体布局稳定

### 4.1 font-display 策略

```css
/* 推荐：swap — 立即显示后备字体，Web 字体加载后替换 */
@font-face {
  font-family: 'MyFont';
  src: url('/font.woff2') format('woff2');
  font-display: swap;
}

/* 如果后备字体和 Web 字体尺寸差异大，用 optional */
@font-face {
  font-family: 'MyFont';
  src: url('/font.woff2') format('woff2');
  font-display: optional; /* 只在加载够快时才使用 */
}
```

### 4.2 匹配后备字体尺寸

```css
/* 用 size-adjust 让后备字体和 Web 字体尺寸一致 */
@font-face {
  font-family: 'FallbackFont';
  src: local('Arial');
  size-adjust: 105%;
  ascent-override: 90%;
  descent-override: 20%;
  line-gap-override: 0%;
}

body {
  font-family: 'MyWebFont', 'FallbackFont', sans-serif;
}
```

### 4.3 字体预加载

```html
<!-- 提前加载关键字体，减少 FOUT 时间 -->
<link rel="preload" href="/font.woff2" as="font"
      type="font/woff2" crossorigin>
```

## 五、动态内容布局稳定

### 5.1 为动态内容预留空间

```html
<!-- ❌ 广告插入后把内容推下去 -->
<div id="content">...</div>
<script>insertAd('#content');</script>

<!-- ✅ 为广告预留空间 -->
<div id="ad-slot" style="min-height: 90px;">
  <!-- 广告加载后填充 -->
</div>
<div id="content">...</div>
```

### 5.2 固定位置的提示

```css
/* ❌ 在页面顶部插入提示 → 推动所有内容下移 */
.notification {
  position: relative;
  margin-top: 0;
}

/* ✅ 用 fixed 或 absolute 定位，不影响文档流 */
.notification {
  position: fixed;
  top: 0;
  left: 0;
  right: 0;
  z-index: 1000;
}

/* ✅ 或者用 transform 动画 */
.notification {
  transform: translateY(-100%);
  transition: transform 0.3s ease;
}
.notification.show {
  transform: translateY(0);
}
```

### 5.3 Skeleton 占位

```css
/* 在内容加载前显示骨架屏 */
.skeleton {
  background: linear-gradient(90deg, #f0f0f0 25%, #e0e0e0 50%, #f0f0f0 75%);
  background-size: 200% 100%;
  animation: shimmer 1.5s infinite;
  border-radius: 4px;
}

@keyframes shimmer {
  0% { background-position: 200% 0; }
  100% { background-position: -200% 0; }
}
```

## 六、避免强制同步布局

### 6.1 读写分离

```javascript
// ❌ 读写交替 → 强制同步布局（布局抖动）
elements.forEach(el => {
  const height = el.offsetHeight; // 读
  el.style.height = height * 2 + 'px'; // 写 → 触发布局
});

// ✅ 先批量读，再批量写
const heights = elements.map(el => el.offsetHeight); // 全部读
elements.forEach((el, i) => {
  el.style.height = heights[i] * 2 + 'px'; // 全部写
});
```

### 6.2 使用 requestAnimationFrame

```javascript
// ✅ 在下一帧统一处理写操作
requestAnimationFrame(() => {
  elements.forEach((el, i) => {
    el.style.height = heights[i] * 2 + 'px';
  });
});
```

```
操作步骤：
1. DevTools → Performance 面板
2. 勾选 "Web Vitals" 复选框
3. 录制页面加载过程

5. 点击标记 → 查看是哪个元素发生了偏移
```

### 7.2 Layout Shift Regions

```
1. DevTools → Performance 面板
2. 点击齿轮图标 → 勾选 "Layout Shift Regions"
3. 录制后，页面中偏移的区域会被蓝色高亮
```

### 7.3 CLS 调试代码

```javascript
// 监测所有布局偏移
const observer = new PerformanceObserver((list) => {
  list.getEntries().forEach((entry) => {
    if (!entry.hadRecentInput) {
      console.log('布局偏移：', {
        value: entry.value.toFixed(4),
        sources: entry.sources?.map(s => s.node),
        startTime: entry.startTime,
      });
    }
  });
});

observer.observe({ type: 'layout-shift', buffered: true });
```

## 常见误区

1. **只给首屏图片设置尺寸**：非首屏图片同样需要 width/height。虽然用户可能不会看到加载过程，但图片加载时的布局偏移会被 CLS 记录。
2. **认为 font-display: swap 会导致 CLS**：swap 确实会导致字体切换，但只要后备字体和 Web 字体的尺寸匹配（用 size-adjust），就不会产生布局偏移。问题不在于 swap，而在于字体尺寸不匹配。
3. **用 margin-top 插入通知栏**：在页面顶部用 margin 或文档流插入通知/横幅，会把所有内容往下推。应该用 position: fixed 或 transform 动画。
4. **忽视用户触发的布局偏移**：CLS 只计算非用户预期的偏移。用户点击按钮后展开的内容不算 CLS，但页面加载时自动弹出的横幅算。

## 工程建议

1. **图片统一使用 aspect-ratio**：在 CSS 中为不同用途的图片（产品图 1:1、Banner 16:9）设置固定的 aspect-ratio，比在 HTML 中写 width/height 更灵活。
2. **用 size-adjust 匹配后备字体**：这是消除字体 CLS 的最有效方案。用工具（如 fontaine）自动生成后备字体声明。
3. **动态内容用骨架屏占位**：在数据加载前用骨架屏预留空间，数据到达后替换，布局不会变化。
4. **读写分离布局属性**：先批量读取 offsetHeight/scrollTop 等布局属性，再批量修改样式，避免强制同步布局。

## 参考答案

### 练习一：复现 CLS 问题

**思路**：创建一个没有图片尺寸的页面，用 Performance 面板录制加载过程，观察 CLS 分数。

**答案**：

```html
<!-- cls-demo.html -->
<!DOCTYPE html>
<html>
<head>
  <style>
    body { font-family: sans-serif; max-width: 800px; margin: 0 auto; padding: 20px; }
    h1 { margin-bottom: 16px; }
    .content { line-height: 1.6; }
  </style>
</head>
<body>
  <h1>CLS 复现测试</h1>
  <!-- 问题图片：没有 width/height -->
  <img src="https://picsum.photos/800/400" alt="Hero image">
  <div class="content">
    <p>这是一段正文内容。图片加载完成后，这段文字会被推下去。</p>
    <p>用户正在阅读这段内容时，突然发生了位移，这就是 CLS。</p>
    <p>如果用户正要点击某个链接，布局抖动可能导致误点击。</p>
  </div>
</body>
</html>
```

```markdown
Performance 面板录制结果：

1. 打开 DevTools → Performance → 勾选 Web Vitals
2. 录制页面加载
3. 在 Experience 轨道中看到紫色/粉色标记 = 布局偏移
4. 点击标记查看详情

CLS 分数: 0.35 (Poor)
偏移元素: <img> 从 y=50px 移动到 y=450px
偏移原因: 图片加载前高度为 0，加载后撑开 400px
```

**要点**：
- 没有尺寸的图片是 CLS 最常见的来源
- Experience 轨道中的紫色标记就是布局偏移
- CLS > 0.25 就是 Poor，需要修复

### 练习二：修复图片 CLS

**思路**：给所有图片添加 width/height 和 aspect-ratio，对比修复前后的 CLS。

**答案**：

```html
<!-- 修复后 -->
<img src="https://picsum.photos/800/400" alt="Hero image"
     width="800" height="400"
     style="width: 100%; height: auto; aspect-ratio: 2/1;">
```

```css
/* 或者用 CSS 统一处理 */
img {
  max-width: 100%;
  height: auto;
  aspect-ratio: attr(width) / attr(height); /* 未来标准 */
}

/* 当前浏览器兼容方案 */
img.hero {
  width: 100%;
  aspect-ratio: 2 / 1; /* 800/400 = 2/1 */
  object-fit: cover;
}
```

```markdown
修复效果：

修复前 CLS: 0.35 (Poor)
修复后 CLS: 0.00 (Good)

原因：
- width/height 告诉浏览器图片的原始尺寸
- CSS 的 aspect-ratio 在图片加载前就预留了正确空间
- 图片加载时不需要撑开空间，布局不会偏移
```

**要点**：
- width/height 是 HTML 属性，告诉浏览器图片的原始尺寸
- aspect-ratio 是 CSS 属性，让图片在响应式布局中保持比例
- 两者配合使用效果最佳

### 练习三：字体布局稳定

**思路**：使用 Web 字体加载页面，观察 FOUT 导致的布局偏移，用 font-display: swap + size-adjust 修复。

**答案**：

```css
/* 修复前：字体加载导致布局偏移 */
@font-face {
  font-family: 'CustomFont';
  src: url('/fonts/custom.woff2') format('woff2');
  font-display: swap; /* 字体加载后切换 → CLS */
}

/* 修复后：匹配后备字体尺寸 */
@font-face {
  font-family: 'CustomFont-Fallback';
  src: local('Arial');
  size-adjust: 104%;        /* 整体缩放 */
  ascent-override: 90%;     /* 上升线 */
  descent-override: 22%;    /* 下降线 */
  line-gap-override: 0%;    /* 行间距 */
}

@font-face {
  font-family: 'CustomFont';
  src: url('/fonts/custom.woff2') format('woff2');
  font-display: swap;
}

body {
  font-family: 'CustomFont', 'CustomFont-Fallback', sans-serif;
}
```

```markdown
修复效果：

修复前：
- FOUT 发生时文字宽度变化 → 行数变化 → 布局偏移
- CLS: 0.08 (由字体切换引起)

修复后：
- 后备字体 Arial 的尺寸被调整为接近 CustomFont
- 字体切换时文字宽度几乎不变 → 无布局偏移
- CLS: 0.01 (Good)

验证方法：
1. 打开 Network 面板，搜索字体文件
2. 右键字体请求 → Block request URL
3. 刷新页面，强制使用后备字体
4. 对比后备字体和 Web 字体的布局是否一致
```

**要点**：
- font-display: swap 会导致 FOUT，但配合 size-adjust 可以消除 CLS
- fontaine 工具可以自动计算后备字体的调整值
- 后备字体必须和 Web 字体的尺寸接近，否则 swap 时会抖动

---

## 小结

1. **CLS 衡量视觉稳定性**：好的 CLS < 0.1
2. **图片必须有尺寸**：width/height + aspect-ratio 预留空间
3. **字体用 swap**：配合 size-adjust 匹配后备字体尺寸
4. **动态内容预留空间**：广告、通知、嵌入内容都需要
5. **读写分离**：避免强制同步布局
6. **用 DevTools**：Performance 面板的 Experience 轨道定位 CLS
