# 浏览器加载链路：从输入 URL 到页面呈现

## 现象

你优化了图片、压缩了 JS，但 LCP 仍然很慢。问题可能不在资源大小，而在加载链路——浏览器从收到 HTML 到渲染出内容的整个过程。

## 加载链路

```
用户输入 URL
    │
    ▼
DNS 解析 → TCP 连接 → TLS 握手 → HTTP 请求 → 服务器处理 → 响应到达
    │                                                              │
    ▼                                                              ▼
  TTFB（Time to First Byte）                                    开始解析 HTML
    │
    ▼
解析 HTML → 构建 DOM → 解析 CSS → 构建 CSSOM → 合并 → 布局 → 绘制 → 合成
    │
    ▼
  FCP（First Contentful Paint）—— 第一个内容出现
    │
    ▼
  LCP（Largest Contentful Paint）—— 最大内容出现
```

## 关键时间节点

```
TTFB（Time to First Byte）
  从请求发出到收到第一个字节
  影响因素：服务器响应速度、网络延迟、CDN
  标准：< 800ms 良好

FCP（First Contentful Paint）
  第一个内容（文字、图片）出现的时间
  影响因素：HTML 大小、阻塞资源
  标准：< 1.8s 良好

LCP（Largest Contentful Paint）
  最大内容块出现的时间
  影响因素：关键资源加载、服务器响应、CSS/JS 阻塞
  标准：< 2.5s 良好
```

## 阻塞渲染的资源

```
HTML 解析过程中遇到：

<link rel="stylesheet" href="style.css">
  → 阻塞渲染，直到 CSS 下载完成
  → 原因：浏览器需要 CSSOM 才能布局

<script src="app.js"></script>
  → 阻塞 HTML 解析
  → 原因：JS 可能修改 DOM

<script async src="analytics.js"></script>
  → 不阻塞 HTML 解析
  → 但下载完后立即执行，可能阻塞渲染

<script defer src="app.js"></script>
  → 不阻塞 HTML 解析
  → 在 HTML 解析完成后、DOMContentLoaded 前执行
  → 最佳选择
```

## 优化加载链路

### 减少 TTFB

```javascript
// 服务器端
// 1. 使用 CDN
// 2. 开启 HTTP/2 或 HTTP/3
// 3. 服务器缓存
// 4. 数据库查询优化

// 客户端
// 1. DNS 预解析
<link rel="dns-prefetch" href="//api.example.com">

// 2. 预连接
<link rel="preconnect" href="https://api.example.com">

// 3. Service Worker 缓存
self.addEventListener('fetch', (e) => {
  e.respondWith(caches.match(e.request) || fetch(e.request))
})
```

### 减少渲染阻塞

```html
<!-- 关键 CSS 内联 -->
<style>
  /* 首屏关键样式 */
  .hero { ... }
</style>

<!-- 非关键 CSS 异步加载 -->
<link rel="preload" href="non-critical.css" as="style" onload="this.onload=null;this.rel='stylesheet'">

<!-- JS 使用 defer -->
<script defer src="app.js"></script>

<!-- 非关键 JS 使用 async 或延迟加载 -->
<script async src="analytics.js"></script>
```

### 优化 LCP

```html
<!-- 预加载 LCP 资源 -->
<link rel="preload" href="/images/hero.webp" as="image" fetchpriority="high">

<!-- LCP 图片直接在 HTML 中，不要 lazy load -->
<img src="/images/hero.webp" width="1200" height="600" fetchpriority="high">
```

## 你可能踩的坑

**坑一：preload 了不需要的资源**

preload 会提前下载，如果资源没用到就浪费了带宽。

**坑二：defer 和 async 混淆**

defer 保持执行顺序，async 不保证。多个有依赖关系的脚本用 defer。

**坑三：关键 CSS 提取不完整**

内联的 CSS 如果漏了首屏样式，会导致 FOUC（Flash of Unstyled Content）。

## 练习

### 练习一：加载链路分析

用 Chrome DevTools 的 Network 面板分析一个页面的加载链路，标注每个关键时间节点。

### 练习二：阻塞资源优化

对 slow.html 的阻塞资源进行优化：将关键 CSS 内联，非关键 CSS 异步加载，JS 使用 defer。

### 练习一

```
加载链路分析：

DNS: 50ms
TCP: 80ms
TLS: 120ms
TTFB: 350ms
HTML 下载: 50ms
HTML 解析: 200ms
CSS 下载（阻塞）: 400ms
JS 下载（阻塞）: 350ms
LCP 资源下载: 600ms
LCP 渲染: 200ms

总 LCP: 2400ms
瓶颈：CSS 和 JS 阻塞渲染 + LCP 资源加载慢
```

### 练习二

```html
<!-- 优化前 -->
<link rel="stylesheet" href="style.css">
<script src="app.js"></script>

<!-- 优化后 -->
<style>/* 关键 CSS */</style>
<link rel="preload" href="style.css" as="style" onload="this.onload=null;this.rel='stylesheet'">
<script defer src="app.js"></script>
```
