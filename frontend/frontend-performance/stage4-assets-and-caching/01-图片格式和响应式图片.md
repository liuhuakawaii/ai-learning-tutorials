# 第1课：图片格式和响应式图片

> **课程定位**：选择合适的图片格式和尺寸，减少传输体积
> **前置知识**：了解 HTTP 基础和 HTML 图片标签
> **预计时长**：30 分钟

## 场景引入

你负责的电商首页有一张 2MB 的 Hero 大图，在手机 3G 网络下需要 6 秒才能加载完成，用户看到的是大片空白。产品同事说"那就压缩一下"，但你发现简单压缩后图片模糊得没法看。更棘手的是，桌面端需要横版构图，手机端需要竖版裁剪——同一张图根本无法兼顾。你需要找到一种方案，让不同设备加载最合适的图片格式和尺寸，而不是一刀切地传一张巨图。

## 二、响应式图片

### 2.1 srcset 和 sizes

```html
<!-- 浏览器根据屏幕宽度选择最合适的图片 -->
<img
  srcset="
    /photo-400.webp 400w,
    /photo-800.webp 800w,
    /photo-1200.webp 1200w,
    /photo-1600.webp 1600w
  "
  sizes="
    (max-width: 600px) 100vw,
    (max-width: 1200px) 50vw,
    33vw
  "
  src="/photo-800.webp"
  alt="Photo"
  width="800" height="600"
>
```

```
sizes 属性解释：
- (max-width: 600px) 100vw：屏幕 ≤ 600px 时，图片占满视口宽度
- (max-width: 1200px) 50vw：屏幕 600-1200px 时，图片占视口一半
- 33vw：更大屏幕时，图片占视口三分之一

浏览器根据 sizes 计算出实际需要的图片宽度
再从 srcset 中选择最接近的图片
```

### 2.2 picture 元素（格式降级）

```html
<!-- 现代格式优先，旧浏览器降级 -->
<picture>
  <!-- AVIF：最新浏览器 -->
  <source srcset="/photo.avif" type="image/avif">
  <!-- WebP：大多数现代浏览器 -->
  <source srcset="/photo.webp" type="image/webp">
  <!-- JPEG：兜底 -->
  <img src="/photo.jpg" alt="Photo" width="800" height="600">
</picture>

<!-- 不同场景用不同图片 -->
<picture>
  <!-- 暗色模式 -->
  <source srcset="/hero-dark.webp" media="(prefers-color-scheme: dark)">
  <!-- 小屏幕裁剪版 -->
  <source srcset="/hero-mobile.webp" media="(max-width: 768px)">
  <!-- 默认 -->
  <img src="/hero.webp" alt="Hero" width="1200" height="600">
</picture>
```

### 2.3 art direction（艺术指导）

```html
<!-- 不同屏幕使用不同裁剪/构图的图片 -->
<picture>
  <!-- 手机：竖构图，突出主体 -->
  <source
    srcset="/hero-portrait.webp"
    media="(max-width: 768px)"
    width="400" height="600"
  >
  <!-- 桌面：横构图，全景 -->
  <img
    src="/hero-landscape.webp"
    alt="Hero"
    width="1200" height="600"
  >
</picture>
```

## 参考答案

### 练习一：图片格式对比

**思路**：对同一张图片分别保存为 JPEG、PNG、WebP、AVIF 格式，对比文件大小和视觉质量。

**答案**：

```markdown
测试图片：一张 1200x800 的产品照片

格式      文件大小    压缩率    视觉质量    兼容性
JPEG      280KB      基准      良好        100%
PNG       1.2MB      +328%     无损        100%
WebP      95KB       -66%      良好        97%（Safari 14+）
AVIF      65KB       -77%      优秀        92%（Chrome 85+, Firefox 93+）

分析：
- WebP 比 JPEG 小 66%，视觉质量相当
- AVIF 比 WebP 再小 30%，但兼容性稍差
- PNG 适合图标和需要透明的图片，不适合照片

选择建议：
- 照片: AVIF（优先）→ WebP（降级）→ JPEG（兜底）
- 图标: SVG（优先）→ PNG（降级）
- 需要透明: WebP（优先）→ PNG（降级）
```

```html
<!-- 使用 <picture> 提供多种格式 -->
<picture>
  <source srcset="/images/product.avif" type="image/avif">
  <source srcset="/images/product.webp" type="image/webp">
  <img src="/images/product.jpg" alt="Product" width="1200" height="800">
</picture>
```

**要点**：
- WebP 是当前最佳的照片格式（压缩率 + 兼容性平衡）
- AVIF 压缩率最好但兼容性稍差
- 用 <picture> 提供格式降级，确保所有浏览器都能显示

### 练习二：响应式图片

**思路**：用 srcset 和 sizes 让浏览器根据视口大小选择合适的图片尺寸。

**答案**：

```html
<!-- 生成多种尺寸的图片 -->
<!-- 400w, 800w, 1200w, 1600w -->

<!-- 使用 srcset + sizes -->
<img
  srcset="
    /images/product-400.webp 400w,
    /images/product-800.webp 800w,
    /images/product-1200.webp 1200w,
    /images/product-1600.webp 1600w
  "
  sizes="(max-width: 640px) 100vw, (max-width: 1024px) 50vw, 33vw"
  src="/images/product-800.webp"
  alt="Product"
  width="1200"
  height="800"
  loading="lazy"
>
```

```markdown
浏览器行为：

视口宽度 375px（手机）：
→ sizes = 100vw = 375px
→ 选择 product-400.webp（400w，最接近 375px）
→ 传输: 30KB

视口宽度 768px（平板）：
→ sizes = 50vw = 384px
→ 选择 product-400.webp（400w，最接近 384px）
→ 传输: 30KB

视口宽度 1440px（桌面）：
→ sizes = 33vw = 475px
→ 选择 product-800.webp（800w，最接近 475px 的 2x 像素密度）
→ 传输: 80KB

对比不用 srcset：
→ 所有设备都下载 product-1600.webp
→ 传输: 200KB（手机浪费 85%）
```

**要点**：
- srcset 告诉浏览器有哪些尺寸可用
- sizes 告诉浏览器图片在不同视口下的显示宽度
- 浏览器自动选择最合适的尺寸，不需要 JS

### 练习三：构建脚本自动转换

**思路**：写一个构建脚本，自动把 images/ 目录下的图片转为 WebP 并生成多种尺寸。

**答案**：

```javascript
// scripts/optimize-images.js
const sharp = require('sharp');
const fs = require('fs');
const path = require('path');

const INPUT_DIR = './images';
const OUTPUT_DIR = './public/images';
const SIZES = [400, 800, 1200, 1600];
const FORMATS = ['webp', 'avif'];

async function optimizeImages() {
  const files = fs.readdirSync(INPUT_DIR).filter(f =>
    /\.(jpg|jpeg|png)$/i.test(f)
  );

  for (const file of files) {
    const inputPath = path.join(INPUT_DIR, file);
    const name = path.parse(file).name;

    for (const size of SIZES) {
      for (const format of FORMATS) {
        const outputPath = path.join(OUTPUT_DIR, `${name}-${size}.${format}`);

        await sharp(inputPath)
          .resize(size)
          .toFormat(format, { quality: format === 'avif' ? 50 : 75 })
          .toFile(outputPath);

        const stats = fs.statSync(outputPath);
        console.log(`${name}-${size}.${format}: ${(stats.size / 1024).toFixed(1)}KB`);
      }
    }
  }
}

optimizeImages();
```

```markdown
运行结果：

product-400.webp: 18.5KB
product-400.avif: 12.3KB
product-800.webp: 52.1KB
product-800.avif: 35.8KB
product-1200.webp: 98.4KB
product-1200.avif: 68.2KB
product-1600.webp: 145.6KB
product-1600.avif: 102.1KB

优化前: 1 张 JPEG 280KB
优化后: 8 个文件（4 尺寸 × 2 格式），最大的 145.6KB
每个设备只下载需要的尺寸和格式
```

**要点**：
- sharp 是 Node.js 中最快的图片处理库
- 构建时自动生成多格式多尺寸图片，不需要手动处理
- 配合 <picture> 和 srcset 实现自动化响应式

## 常见误区

1. **把所有图片都转成 WebP 就万事大吉**：WebP 虽好，但 Safari 14 以下不支持。如果不提供 `<picture>` 降级，旧浏览器用户会看到裂图。
2. **只压缩不改尺寸**：一张 4000×3000 的照片压缩到 200KB 仍然很大，因为像素数量决定了压缩下限。应该根据实际显示尺寸生成多套图片，用 srcset 按需加载。
3. **对所有图片一视同仁地 lazy load**：首屏 LCP 图片如果加了 `loading="lazy"`，反而会延迟加载，拖慢 LCP。首屏关键图片应该用 `fetchpriority="high"` 甚至 preload。
4. **忘记给图片设置 width/height**：不写尺寸属性，图片加载完成前浏览器不知道预留多大空间，导致布局偏移（CLS 飙升）。

## 工程建议

1. **构建时自动生成多格式多尺寸图片**：在 CI 中用 sharp 或 @squoosh/cli 批量生成 WebP/AVIF + 400/800/1200 多套尺寸，配合 `<picture>` 和 srcset 实现自动化响应式。
2. **用 CDN 实时转换替代预生成**：如果图片数量多且尺寸变化频繁，接入 Cloudflare Image Resizing 或 Cloudinary，按 URL 参数实时转换并缓存，省去构建时生成的复杂度。
3. **建立图片优化 Checklist**：PR Review 时检查是否有 width/height、是否首屏图片用了 preload、是否非首屏图片用了 lazy load，把检查项写进团队规范。
4. **监控 LCP 图片加载**：用 web-vitals 的 `onLCP` 回调检查 LCP 元素是否是图片，如果是，确认它的加载策略（preload、fetchpriority、格式、尺寸）是否合理。

## 小结

1. **格式选择**：照片用 AVIF/WebP，图标用 SVG，需要透明用 WebP/PNG
2. **响应式图片**：srcset + sizes 让浏览器选择合适的尺寸
3. **格式降级**：用 `<picture>` 提供多种格式
4. **工具**：sharp、Squoosh CLI、CDN 实时转换
5. **首屏图片**：fetchpriority="high" + preload
