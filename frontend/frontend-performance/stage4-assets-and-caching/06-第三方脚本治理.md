# 第6课：第三方脚本治理

> **课程定位**：管理广告、分析、聊天等第三方脚本的加载，减少对性能的影响
> **前置知识**：了解 JavaScript 加载机制和资源优先级
> **预计时长**：30 分钟

## 场景引入

你的页面 Lighthouse 性能分只有 45 分，但你自己写的代码并不大——排查后发现，Google Analytics、Google Tag Manager、Facebook Pixel、在线客服、广告脚本这些第三方脚本加起来有 400KB，同步加载阻塞主线程 1 秒多。你跟产品经理说"能不能去掉一些"，回答是"这些都是业务必须的"。你需要找到一种方案，在不砍掉这些脚本的前提下，尽量减少它们对页面性能的影响。

## 二、加载策略

### 2.1 defer / async

```html
<!-- defer：HTML 解析完成后执行，保持脚本顺序 -->
<script defer src="https://analytics.js"></script>

<!-- async：下载完就执行，不保证顺序 -->
<script async src="https://analytics.js"></script>

<!-- 推荐：分析脚本用 defer/async -->
<script defer src="https://www.googletagmanager.com/gtm.js"></script>
```

```
┌──────────────┬────────────────┬────────────────┬─────────────┐
│              │ 普通 script     │ async          │ defer       │
├──────────────┼────────────────┼────────────────┼─────────────┤
│ 阻塞 HTML    │ ✅ 是          │ ❌ 否          │ ❌ 否       │
│ 执行时机     │ 立即           │ 下载完即执行   │ HTML 解析后 │
│ 脚本顺序     │ 保持           │ 不保证         │ 保持        │
│ DOM 就绪     │ 不保证         │ 不保证         │ ✅ 保证     │
└──────────────┴────────────────┴────────────────┴─────────────┘
```

### 2.2 延迟加载

```html
<!-- 方案 1：页面加载完成后加载 -->
<script>
  window.addEventListener('load', () => {
    const script = document.createElement('script');
    script.src = 'https://chat-widget.js';
    document.body.appendChild(script);
  });
</script>

<!-- 方案 2：用户交互后加载 -->
<script>
  ['scroll', 'click', 'mousemove'].forEach(event => {
    window.addEventListener(event, () => {
      const script = document.createElement('script');
      script.src = 'https://analytics.js';
      document.body.appendChild(script);
    }, { once: true });
  });
</script>

<!-- 方案 3：空闲时加载 -->
<script>
  if ('requestIdleCallback' in window) {
    requestIdleCallback(() => {
      const script = document.createElement('script');
      script.src = 'https://analytics.js';
      document.body.appendChild(script);
    });
  }
</script>
```

### 2.3 按需加载

```javascript
// 聊天组件：只在用户点击时加载
function ChatButton() {
  const [loaded, setLoaded] = useState(false);

  const loadChat = () => {
    if (!loaded) {
      const script = document.createElement('script');
      script.src = 'https://chat-widget.js';
      script.onload = () => setLoaded(true);
      document.body.appendChild(script);
    }
  };

  return <button onClick={loadChat}>Open Chat</button>;
}
```

## 三、脚本审计

### 3.1 识别第三方脚本

```javascript
// 在 Console 中运行
const scripts = Array.from(document.querySelectorAll('script[src]'));
const thirdParty = scripts.filter(s => {
  try {
    const url = new URL(s.src);
    return url.hostname !== window.location.hostname;
  } catch {
    return false;
  }
});

console.table(thirdParty.map(s => ({
  src: s.src,
  async: s.async,
  defer: s.defer,
  blocking: !s.async && !s.defer,
})));
```

### 4.2 资源提示

```html
<!-- 预连接到第三方源 -->
<link rel="preconnect" href="https://www.googletagmanager.com">
<link rel="preconnect" href="https://www.google-analytics.com">

<!-- 预加载关键第三方资源 -->
<link rel="preload" href="https://cdn.example.com/critical.js" as="script">

<!-- DNS 预解析 -->
<link rel="dns-prefetch" href="//connect.facebook.net">
```

### 4.3 内容安全策略

```html
<!-- CSP 限制第三方脚本来源 -->
<meta http-equiv="Content-Security-Policy"
      content="script-src 'self' https://www.googletagmanager.com https://www.google-analytics.com">

<!-- 减少 XSS 风险 -->
```

## 五、Partytown（高级方案）

### 5.1 原理

```
┌──────────────────────────────────────────────────────────────┐
│              Partytown：把第三方脚本移到 Web Worker            │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  传统方式：                                                   │
│  主线程 → 第三方脚本执行 → 阻塞主线程 → 用户交互卡顿          │
│                                                              │
│  Partytown：                                                  │
│  主线程 → 正常运行                                            │
│  Web Worker → 第三方脚本执行 → 不阻塞主线程                   │
│                                                              │
│  原理：                                                       │
│  - 在 Web Worker 中运行第三方脚本                             │
│  - Worker 访问 DOM 通过 postMessage 代理                     │
│  - 对第三方脚本透明（不需要修改脚本）                         │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 5.2 使用

```bash
npm install @builder.io/partytown
```

```jsx
// Next.js
import { Partytown } from '@builder.io/partytown/react';

function Head() {
  return (
    <>
      <Partytown forward={['dataLayer.push']} />
      <script
        type="text/partytown"
        src="https://www.googletagmanager.com/gtm.js"
      />
    </>
  );
}
```

## 参考答案

### 练习一：审计第三方脚本

**思路**：打开一个真实网站，用 Performance 面板录制加载过程，列出所有第三方脚本的大小和阻塞时间。

**答案**：

```markdown
审计结果（以一个电商网站为例）：

第三方脚本                    大小      阻塞时间    必要性    优化建议
Google Tag Manager           45KB      120ms       高       defer 加载
Google Analytics (gtag)      35KB      80ms        高       defer 加载
Facebook Pixel               25KB      60ms        中       延迟加载
LiveChat 聊天工具            60KB      150ms       低       用户交互后加载
广告 SDK                     80KB      200ms       低       按需加载
Hotjar 热力图                30KB      70ms        低       延迟加载

总计: 275KB, 680ms 阻塞时间

问题分析：
- 广告 SDK 阻塞时间最长（200ms），但优先级最低
- LiveChat 60KB 但用户可能根本不用聊天功能
- 所有脚本都是同步加载，阻塞 HTML 解析

优化方案：
1. GTM + GA: 改为 defer 加载（保持执行顺序）
2. Facebook Pixel: 页面加载后延迟加载
3. LiveChat: 用户点击聊天按钮时才加载
4. 广告 SDK: 用户滚动到广告位时才加载
5. Hotjar: 页面加载后延迟加载
```

**要点**：
- Performance 面板可以精确看到每个脚本的阻塞时间
- 按优先级分级加载是治理第三方脚本的核心策略
- 定期审计，移除不再使用的脚本

### 练习二：优化加载策略

**思路**：把阻塞的第三方脚本改为 defer，把非关键脚本改为延迟加载，对比优化前后的 TBT。

**答案**：

```html
<!-- 优化前：同步加载 -->
<script src="https://www.googletagmanager.com/gtm.js"></script>
<script src="https://www.google-analytics.com/gtag.js"></script>
<script src="https://connect.facebook.net/fbevents.js"></script>
<script src="https://cdn.livechat.com/widget.js"></script>

<!-- 优化后：分级加载 -->
<!-- 高优先级：defer 加载 -->
<script defer src="https://www.googletagmanager.com/gtm.js"></script>
<script defer src="https://www.google-analytics.com/gtag.js"></script>

<!-- 中优先级：页面加载后延迟加载 -->
<script>
  window.addEventListener('load', () => {
    const fb = document.createElement('script');
    fb.src = 'https://connect.facebook.net/fbevents.js';
    document.head.appendChild(fb);
  });
</script>

<!-- 低优先级：用户交互后加载 -->
<script>
  // LiveChat：用户点击聊天按钮时才加载
  document.getElementById('chat-button').addEventListener('click', () => {
    const chat = document.createElement('script');
    chat.src = 'https://cdn.livechat.com/widget.js';
    document.head.appendChild(chat);
  }, { once: true });
</script>
```

```markdown
优化效果：

优化前：
- TBT: 680ms
- FCP: 2.8s

优化后：
- TBT: 200ms（减少 71%）
- FCP: 1.5s（减少 46%）
- 所有第三方脚本的功能正常工作

验证方法：
1. Performance 面板录制 → 确认无长任务阻塞
2. 检查 GTM/GA 数据正常上报
3. 检查 LiveChat 点击后正常弹出
```

**要点**：
- defer 不阻塞 HTML 解析，在 DOM 解析后执行
- 页面加载后（window.load）加载非关键脚本
- 用户交互后加载最低优先级的脚本

### 练习三：实现按需加载

**思路**：把聊天组件改为点击时才加载，把分析脚本改为用户交互后加载，验证功能是否正常工作。

**答案**：

```jsx
import { useState, useCallback, lazy, Suspense } from 'react';

// 懒加载聊天组件
const ChatWidget = lazy(() => import('./ChatWidget'));

function App() {
  const [showChat, setShowChat] = useState(false);

  const handleChatClick = useCallback(() => {
    setShowChat(true);
  }, []);

  return (
    <div>
      <main>{/* 页面内容 */}</main>

      {/* 聊天按钮 */}
      <button onClick={handleChatClick} className="chat-button">
        💬 联系客服
      </button>

      {/* 聊天组件：点击后才加载 */}
      {showChat && (
        <Suspense fallback={<div>加载聊天组件...</div>}>
          <ChatWidget />
        </Suspense>
      )}
    </div>
  );
}
```

```javascript
// 分析脚本：用户交互后加载
function loadAnalytics() {
  // 只在用户实际交互后加载分析脚本
  const events = ['click', 'scroll', 'keydown'];
  const handler = () => {
    // 移除监听器，只加载一次
    events.forEach(e => document.removeEventListener(e, handler));

    // 加载分析脚本
    const script = document.createElement('script');
    script.src = 'https://www.googletagmanager.com/gtag.js';
    script.async = true;
    document.head.appendChild(script);
  };

  events.forEach(e => document.addEventListener(e, handler, { once: true }));
}

// 页面加载后启动监听
window.addEventListener('load', loadAnalytics);
```

```markdown
功能验证：

1. 聊天组件：
   - 页面加载时：聊天组件未加载（节省 60KB）
   - 用户点击"联系客服"：聊天组件加载并显示
   - 功能正常：可以发送消息、接收回复

2. 分析脚本：
   - 页面加载时：分析脚本未加载
   - 用户点击/滚动/按键后：分析脚本加载
   - 数据正常上报：GA 后台可以看到访问数据

3. 性能影响：
   - 首屏 JS 减少 60KB（聊天组件）
   - TBT 减少 150ms（分析脚本延迟加载）
   - 用户体验无感知差异
```

**要点**：
- 按需加载的关键是找到"什么时候需要"
- 聊天组件：用户点击时需要
- 分析脚本：用户交互时需要（但不能太晚，否则丢失数据）
- 用 { once: true } 确保只加载一次

## 常见误区

1. **所有第三方脚本都用 async 加载**：async 不保证执行顺序，如果脚本之间有依赖关系（如 GTM 依赖 dataLayer），乱序执行会导致功能异常。有依赖关系的脚本应该用 defer 或手动控制加载顺序。
2. **把分析脚本延迟到页面完全加载后**：虽然减少了阻塞，但如果用户在页面加载完成前就离开了，你丢失了这部分用户的访问数据。分析脚本通常用 defer（HTML 解析后立即执行）而不是延迟到 load 事件后。
3. **不设置 CSP 限制脚本来源**：第三方脚本可能被注入恶意代码（供应链攻击）。设置 `Content-Security-Policy` 的 `script-src` 白名单，只允许已知域名加载脚本。
4. **只关注脚本大小，不关注执行时间**：一个 30KB 的脚本可能因为频繁 DOM 操作阻塞主线程 500ms。用 Performance 面板录制后看 Main 轨道，找到实际阻塞时间最长的脚本。

## 工程建议

1. **按优先级分级加载**：A/B 测试工具（影响首屏显示）→ 立即 defer 加载；分析工具 → defer 加载；聊天/客服/广告 → 用户交互后或空闲时加载。
2. **用 preconnect 提前建立连接**：对已知的第三方域名（如 `www.googletagmanager.com`）添加 `<link rel="preconnect">`，减少 DNS 解析和 TCP 握手时间。
3. **定期审计第三方脚本**：每季度用 WebPageTest 的 Request Map 或 DevTools 审计所有第三方脚本，移除不再使用的、替换体积过大的。
4. **考虑 Partytown 把第三方脚本移到 Web Worker**：对于无法优化的重型第三方脚本，用 Partytown 在 Web Worker 中执行，完全不阻塞主线程。

## 小结

1. **第三方脚本影响大**：可能增加 400KB+ 和 1 秒+ 阻塞
2. **优先级分级**：高→立即，中→defer，低→延迟
3. **defer / async**：避免阻塞 HTML 解析
4. **延迟加载**：页面加载后、用户交互后、空闲时
5. **Partytown**：把第三方脚本移到 Web Worker
6. **CSP**：限制脚本来源，提升安全性
