# 性能预算：把性能变成可执行的工程约束

## 现象

你花了两周优化性能，LCP 从 4 秒降到 1.8 秒。一个月后新功能上线，LCP 又回到了 3.5 秒。没有人故意搞坏性能——只是没有人负责。

性能预算就是把性能变成可执行的工程约束：超过预算就不能合并代码。

## 什么是性能预算

```
性能预算 = 一组可量化的性能指标阈值

示例：
  LCP ≤ 2.5 秒
  INP ≤ 200ms
  CLS ≤ 0.1
  JS 总量 ≤ 300KB
  图片总量 ≤ 500KB
  首屏请求数 ≤ 30
  TTFB ≤ 800ms
```

## 线上监控

```javascript
// 使用 web-vitals 库采集真实用户数据
import { onLCP, onINP, onCLS } from 'web-vitals'

function sendToAnalytics(metric) {
  const body = JSON.stringify({
    name: metric.name,
    value: metric.value,
    id: metric.id,
    page: window.location.pathname
  })

  // 用 Beacon API 发送，不阻塞页面卸载
  navigator.sendBeacon('/api/vitals', body)
}

onLCP(sendToAnalytics)
onINP(sendToAnalytics)
onCLS(sendToAnalytics)
```

## 性能回归分析

```javascript
// 检测性能回归
function detectRegression(current, baseline) {
  const regressions = []

  for (const [metric, value] of Object.entries(current)) {
    const base = baseline[metric]
    const change = (value - base) / base

    if (change > 0.1) { // 超过 10% 视为回归
      regressions.push({
        metric,
        baseline: base,
        current: value,
        change: `${(change * 100).toFixed(1)}%`
      })
    }
  }

  return regressions
}
```

## 你可能踩的坑

**坑一：预算太严**

每次提交都失败，开发者会忽略。预算应该有缓冲。

**坑二：只监控不处理**

监控到回归但没有告警机制，等于没监控。

**坑三：预算不更新**

业务增长后预算可能需要调整。定期 review。
