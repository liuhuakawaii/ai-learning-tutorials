# 第4课：慢交互日志

> **课程定位**：追踪和分析导致 INP 差的具体交互，定位性能瓶颈
> **前置知识**：了解 INP 指标和 web-vitals 库
> **预计时长**：30 分钟

## 场景引入

你的线上监控显示 INP（Interaction to Next Paint）P75 是 350ms，超过了 200ms 的"良好"阈值。但 INP 只是一个数字——你不知道是哪个交互导致的，是点击"加入购物车"按钮，还是在搜索框输入文字？是输入延迟大（主线程被占用），还是事件处理函数执行慢？你需要一套慢交互日志系统，把每次慢交互的类型、目标元素、时间分解都记录下来，才能定位和修复问题。

## 一、INP 的组成

```
┌──────────────────────────────────────────────────────────────┐
│              INP 的组成                                        │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  用户交互（click, keydown, etc.）                             │
│    ↓                                                         │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐       │
│  │ Input Delay  │→│ Process Time │→│Present Delay  │       │
│  │ 输入延迟      │  │ 处理时间     │  │ 呈现延迟      │       │
│  └──────────────┘  └──────────────┘  └──────────────┘       │
│                                                              │
│  Input Delay：从交互发生到事件处理开始的时间                  │
│  → 主线程被其他任务占用                                       │
│                                                              │
│  Process Time：事件处理函数执行时间                           │
│  → 事件处理器中的计算和 DOM 操作                              │
│                                                              │
│  Present Delay：从处理完成到浏览器绘制的时间                  │
│  → 样式计算、布局、绘制                                      │
│                                                              │
│  INP = max(所有交互的 Input Delay + Process Time + Present Delay)│
│  （取最慢的那次交互，通常是 P98）                             │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## 二、追踪慢交互

### 2.1 使用 web-vitals

```javascript
import { onINP } from 'web-vitals';

onINP((metric) => {
  const entry = metric.entries[0];
  if (!entry) return;

  console.log('INP 详情：', {
    // 交互类型
    interactionType: entry.interactionType, // 'pointer', 'keyboard'
    // 交互目标
    target: entry.target,
    // 时间分解
    inputDelay: entry.processingStart - entry.startTime,
    processTime: entry.processingEnd - entry.processingStart,
    presentDelay: entry.startTime + entry.duration - entry.processingEnd,
    // 总延迟
    duration: entry.duration,
  });
});
```

### 2.2 记录慢交互上下文

```javascript
import { onINP } from 'web-vitals';

onINP((metric) => {
  const entry = metric.entries[0];
  if (!entry) return;

  const context = {
    // 交互信息
    type: entry.interactionType,
    target: getSelector(entry.target), // CSS 选择器
    timestamp: entry.startTime,

    // 时间分解
    inputDelay: entry.processingStart - entry.startTime,
    processTime: entry.processingEnd - entry.processingStart,
    presentDelay: entry.startTime + entry.duration - entry.processingEnd,

    // 页面信息
    page: window.location.pathname,
    viewport: `${window.innerWidth}x${window.innerHeight}`,

    // 设备信息
    deviceMemory: navigator.deviceMemory,
    connection: navigator.connection?.effectiveType,

    // INP 值
    value: metric.value,
    rating: metric.rating,
  };

  sendToAnalytics(context);
});

function getSelector(element) {
  if (!element) return 'unknown';
  const parts = [];
  while (element && element !== document.body) {
    let selector = element.tagName.toLowerCase();
    if (element.id) {
      selector += `#${element.id}`;
    } else if (element.className) {
      selector += `.${element.className.split(' ')[0]}`;
    }
    parts.unshift(selector);
    element = element.parentElement;
  }
  return parts.join(' > ');
}
```

## 四、Long Animation Frames API

### 4.1 什么是 Long Animation Frames

```
┌──────────────────────────────────────────────────────────────┐
│              Long Animation Frames (LoAF)                     │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  LoAF 是 Long Tasks API 的升级版：                           │
│  - 更准确地追踪主线程阻塞                                    │
│  - 包含脚本执行的详细信息                                    │
│  - 关联到具体的用户交互                                      │
│                                                              │
│  一个 LoAF 包含：                                             │
│  - 开始和结束时间                                            │
│  - 执行的脚本列表                                            │
│  - 每个脚本的执行时间                                        │
│  - 渲染时间                                                  │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 4.2 使用 LoAF

```javascript
const observer = new PerformanceObserver((list) => {
  list.getEntries().forEach((frame) => {
    if (frame.duration > 50) {
      console.log(`Long Animation Frame: ${frame.duration.toFixed(1)}ms`, {
        startTime: frame.startTime,
        renderStart: frame.renderStart,
        styleAndLayoutStart: frame.styleAndLayoutStart,
        scripts: frame.scripts?.map(script => ({
          name: script.sourceURL,
          functionName: script.sourceFunctionName,
          duration: script.duration,
          executionStart: script.executionStart,
          windowAttribution: script.windowAttribution,
        })),
      });
    }
  });
});

observer.observe({ type: 'long-animation-frame', buffered: true });
```

### 4.3 关联交互和 LoAF

```javascript
// 记录交互发生时的 LoAF
let currentLoAF = null;

const loafObserver = new PerformanceObserver((list) => {
  const entries = list.getEntries();
  currentLoAF = entries[entries.length - 1];
});
loafObserver.observe({ type: 'long-animation-frame', buffered: true });

// 记录交互
const inpObserver = new PerformanceObserver((list) => {
  list.getEntries().forEach((entry) => {
    if (entry.interactionId && currentLoAF) {
      console.log('交互关联的 LoAF:', {
        interactionType: entry.interactionType,
        duration: entry.duration,
        loafDuration: currentLoAF.duration,
        loafScripts: currentLoAF.scripts,
      });
    }
  });
});
inpObserver.observe({ type: 'event', buffered: true, durationThreshold: 0 });
```

## 六、慢交互日志最佳实践

```javascript
// 完整的慢交互日志方案
import { onINP } from 'web-vitals';

function setupSlowInteractionLogging() {
  // 采集 INP
  onINP((metric) => {
    if (metric.rating !== 'good') {
      logSlowInteraction(metric);
    }
  });

  // 监控长任务
  const longTaskObserver = new PerformanceObserver((list) => {
    list.getEntries().forEach((entry) => {
      if (entry.duration > 100) {
        logLongTask(entry);
      }
    });
  });
  longTaskObserver.observe({ type: 'longtask', buffered: true });

  // 监控 LoAF（如果支持）
  if (PerformanceObserver.supportedEntryTypes?.includes('long-animation-frame')) {
    const loafObserver = new PerformanceObserver((list) => {
      list.getEntries().forEach((entry) => {
        if (entry.duration > 100) {
          logLoAF(entry);
        }
      });
    });
    loafObserver.observe({ type: 'long-animation-frame', buffered: true });
  }
}

function logSlowInteraction(metric) {
  const entry = metric.entries[0];
  sendToAnalytics({
    type: 'slow-interaction',
    interactionType: entry?.interactionType,
    target: getSelector(entry?.target),
    inputDelay: entry ? entry.processingStart - entry.startTime : null,
    processTime: entry ? entry.processingEnd - entry.processingStart : null,
    duration: metric.value,
    page: window.location.pathname,
  });
}
```

### 练习一：追踪慢交互

**思路**：在页面中添加 INP 日志，故意制造慢交互，观察日志中的时间分解。

**答案**：

```javascript
import { onINP } from 'web-vitals';

// 采集慢交互日志
onINP((metric) => {
  if (metric.rating !== 'good') {
    const entry = metric.entries[0];
    if (entry) {
      console.warn('🐌 慢交互检测:', {
        交互类型: entry.name,           // click, keydown, etc.
        目标元素: getSelector(entry.target),
        总延迟: `${metric.value.toFixed(1)}ms`,
        输入延迟: `${(entry.processingStart - entry.startTime).toFixed(1)}ms`,
        处理时间: `${(entry.processingEnd - entry.processingStart).toFixed(1)}ms`,
        呈现延迟: `${(entry.startTime + entry.duration - entry.processingEnd).toFixed(1)}ms`,
        评级: metric.rating,
      });
    }
  }
});

// 获取元素的 CSS 选择器
function getSelector(element) {
  if (!element) return 'unknown';
  if (element.id) return `#${element.id}`;
  if (element.className) return `.${element.className.split(' ').join('.')}`;
  return element.tagName.toLowerCase();
}
```

在页面中添加一个按钮，点击后执行 300ms 的计算：
<button id="slow-btn">点击测试</button>
document.getElementById('slow-btn').addEventListener('click', () => {
  const start = Date.now();

控制台输出：
🐌 慢交互检测: {
  交互类型: 'click',
  目标元素: '#slow-btn',

  输入延迟: '5.2ms',
  处理时间: '300.1ms',    ← 瓶颈在这里！
  呈现延迟: '15.2ms',
  评级: 'poor'
}

分析：
- 处理时间 300ms 是瓶颈 → 事件处理器本身太慢
- 输入延迟只有 5ms → 主线程没有被阻塞
- 优化方向：拆分计算任务或移到 Web Worker

- INP = 输入延迟 + 处理时间 + 呈现延迟

### 练习二：关联长任务

**思路**：同时监控 INP 和长任务，找到慢交互对应的长任务，分析调用栈。

**答案**：

```javascript
import { onINP } from 'web-vitals';

// 监控长任务
const longTaskEntries = [];
const longTaskObserver = new PerformanceObserver((list) => {
  list.getEntries().forEach((entry) => {
    longTaskEntries.push({
      startTime: entry.startTime,
      duration: entry.duration,
      attribution: entry.attribution,
    });
  });
});
longTaskObserver.observe({ type: 'longtask', buffered: true });

// 监控 INP 并关联长任务
onINP((metric) => {
  const entry = metric.entries[0];
  if (!entry) return;

  // 找到交互时间范围内的长任务
  const interactionStart = entry.startTime;
  const interactionEnd = entry.startTime + entry.duration;

  const relatedLongTasks = longTaskEntries.filter(
    lt => lt.startTime >= interactionStart && lt.startTime <= interactionEnd
  );

  if (relatedLongTasks.length > 0) {
    console.warn('🐌 慢交互 + 长任务关联:', {
      交互: `${entry.name} (${metric.value.toFixed(1)}ms)`,
      关联长任务: relatedLongTasks.map(lt => ({
        耗时: `${lt.duration.toFixed(1)}ms`,
        开始时间: lt.startTime.toFixed(1),
      })),
    });
  }
});
```

```markdown
关联分析结果：

🐌 慢交互 + 长任务关联: {
  交互: 'click (320.5ms)',
  关联长任务: [
    { 耗时: '280.3ms', 开始时间: '1234.5' }
  ]
}

分析：
- 点击交互期间有一个 280ms 的长任务
- 这个长任务就是事件处理器中的阻塞代码
- 用 Performance 面板录制可以查看这个长任务的调用栈
```

**要点**：
- Long Tasks API 可以监控主线程上的长任务
- 用时间范围关联 INP 和长任务
- LoAF API（Long Animation Frames）提供更精确的关联

### 练习三：优化慢交互

**思路**：找到一个慢交互，用 setTimeout 拆分任务，验证 INP 是否改善。

**答案**：

```javascript
// ❌ 优化前：同步处理 10000 项
function handleSearch(items, query) {
  const results = items.filter(item =>
    item.name.toLowerCase().includes(query.toLowerCase())
  );
  renderResults(results);
}

// ✅ 优化后：分批处理
async function handleSearchOptimized(items, query) {
  const results = [];
  const batchSize = 100;

  for (let i = 0; i < items.length; i += batchSize) {
    const batch = items.slice(i, i + batchSize);
    const filtered = batch.filter(item =>
      item.name.toLowerCase().includes(query.toLowerCase())
    );
    results.push(...filtered);

    // 每批处理后让出主线程
    if (i + batchSize < items.length) {
      await new Promise(resolve => setTimeout(resolve, 0));
    }
  }

  renderResults(results);
}
```

```markdown
对比结果：

优化前：
- 搜索 10000 项: 350ms（长任务）
- INP: 380ms (poor)
- 用户输入时明显卡顿

优化后：
- 搜索 10000 项: 总时间 400ms（但分成 100 个小任务）
- 每个小任务: < 5ms
- INP: 45ms (good)
- 用户输入流畅

注意：
- 总时间略长（400ms vs 350ms）因为有调度开销
- 但用户体验大幅改善，因为主线程不被长时间阻塞
- INP 从 380ms 降到 45ms（提升 8x）
```

**要点**：
- setTimeout 拆分任务会增加总时间，但改善用户体验
- 每个小任务应该 < 50ms（理想 < 20ms）
- scheduler.yield() 是更现代的方案

## 常见误区

1. **只关注 INP 数值，不分析时间分解**：INP = Input Delay + Process Time + Present Delay。如果 Input Delay 大，说明主线程被阻塞；如果 Process Time 大，说明事件处理器本身慢。不同的分解指向不同的优化方向。
2. **用 Long Tasks API 代替 INP 采集**：Long Tasks API 只能告诉你"有超过 50ms 的任务"，但无法关联到具体交互。INP 的 PerformanceEntry 才能告诉你"这次 click 交互花了多久"。
3. **记录所有交互的日志**：每次 click、keydown 都记录会产生海量数据。应该只记录 INP 超过阈值的交互（如 rating !== 'good'），或者只记录 P98 的慢交互。
4. **忽略 Present Delay**：很多人只关注 Input Delay 和 Process Time，但 Present Delay（从处理完成到浏览器绘制）也可能很大，比如一次事件处理器修改了大量 DOM，导致样式计算和布局时间很长。

## 工程建议

1. **用 getSelector 函数记录交互目标元素**：慢交互日志中最关键的信息是"用户操作了什么"。记录交互目标的 CSS 选择器（如 `button.add-to-cart`），方便在代码中定位。
2. **关联 LoAF（Long Animation Frames）获取脚本级细节**：LoAF API 能告诉你慢交互期间执行了哪些脚本、每个脚本耗时多久，比 Long Tasks API 更精确。用 `interactionId` 把交互和 LoAF 关联起来。
3. **按页面分组统计慢交互**：不同页面的交互模式不同。商品列表页的搜索框可能是 INP 瓶颈，而详情页的"加入购物车"可能是瓶颈。按页面分组才能找到重点优化目标。
4. **用 setTimeout 拆分长任务作为临时修复**：如果发现某个事件处理器有 200ms 的长任务，用 `setTimeout` 或 `scheduler.yield()` 把任务拆分成多个小块，让主线程有机会处理其他任务（如用户输入）。

## 小结

1. **INP 组成**：Input Delay + Process Time + Present Delay
2. **web-vitals**：采集 INP 并记录交互详情
3. **Long Tasks API**：监控主线程长任务
4. **LoAF API**：更准确地追踪主线程阻塞
5. **原因分析**：根据时间分解定位优化方向
