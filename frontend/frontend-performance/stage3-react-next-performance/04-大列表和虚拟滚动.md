# 第4课：大列表和虚拟滚动

> **课程定位**：处理大量列表数据时保持渲染性能
> **前置知识**：理解 React 渲染机制和 memo
> **预计时长**：35 分钟

## 场景引入

你的后台管理系统有一个订单列表页面，随着业务增长，订单数据从 200 条增长到了 5000 条。页面变得越来越卡：首次渲染需要 2 秒，每次筛选排序都会卡顿 500ms 以上，滚动列表时掉帧明显。用 Profiler 一看，渲染 5000 个列表项产生了 25000+ 个 DOM 节点，每次状态变化都要 Diff 这么多节点。你尝试用 memo 优化列表项，效果有限。根本解决方案不是优化每个列表项，而是根本不渲染视口外的列表项——这就是虚拟滚动。

┌──────────────────────────────────────────────────────────────┐
│              虚拟滚动原理                                      │
├──────────────────────────────────────────────────────────────┤
│                                                              │

## 三、使用 react-window

### 3.1 固定高度列表

```javascript
import { FixedSizeList } from 'react-window';

function VirtualList({ items }) {
  const Row = ({ index, style }) => (
    <div style={style} className="list-row">
      <span>{items[index].name}</span>
      <span>{items[index].email}</span>
    </div>
  );

  return (
    <FixedSizeList
      height={600}        // 容器高度
      width="100%"         // 容器宽度
      itemCount={items.length}
      itemSize={50}        // 每项高度（固定）
    >
      {Row}
    </FixedSizeList>
  );
}
```

### 3.2 可变高度列表

```javascript
import { VariableSizeList } from 'react-window';

function VariableVirtualList({ items }) {
  // 根据内容估算每项高度
  const getItemSize = (index) => {
    const item = items[index];
    // 简单估算：标题 20px + 每行内容 18px
    return 20 + Math.ceil(item.content.length / 50) * 18 + 20;
  };

  const Row = ({ index, style }) => (
    <div style={style}>
      <h3>{items[index].title}</h3>
      <p>{items[index].content}</p>
    </div>
  );

  return (
    <VariableSizeList
      height={600}
      width="100%"
      itemCount={items.length}
      itemSize={getItemSize}
    >
      {Row}
    </VariableSizeList>
  );
}
```

### 3.3 网格虚拟滚动

```javascript
import { FixedSizeGrid } from 'react-window';

function VirtualGrid({ items, columns = 4 }) {
  const Cell = ({ columnIndex, rowIndex, style }) => {
    const index = rowIndex * columns + columnIndex;
    if (index >= items.length) return null;

    return (
      <div style={style}>
        <ProductCard product={items[index]} />
      </div>
    );
  };

  return (
    <FixedSizeGrid
      height={600}
      width="100%"
      columnCount={columns}
      columnWidth={250}
      rowCount={Math.ceil(items.length / columns)}
      rowHeight={300}
    >
      {Cell}
    </FixedSizeGrid>
  );
}
```

## 四、使用 react-virtuoso

### 4.1 自动高度测量

```javascript
import { Virtuoso } from 'react-virtuoso';

// react-virtuoso 的优势：自动测量每项高度
function AutoHeightList({ items }) {
  return (
    <Virtuoso
      style={{ height: 600 }}
      totalCount={items.length}
      index={0}
      itemContent={(index) => (
        <div className="list-item">
          <h3>{items[index].title}</h3>
          <p>{items[index].content}</p>
          <span>{items[index].date}</span>
        </div>
      )}
    />
  );
}
```

### 4.2 无限加载

```javascript
import { Virtuoso } from 'react-virtuoso';

function InfiniteList() {
  const [items, setItems] = useState([]);
  const [loading, setLoading] = useState(false);

  const loadMore = useCallback(() => {
    if (loading) return;
    setLoading(true);

    fetch(`/api/items?offset=${items.length}&limit=50`)
      .then(res => res.json())
      .then(newItems => {
        setItems(prev => [...prev, ...newItems]);
        setLoading(false);
      });
  }, [items.length, loading]);

  return (
    <Virtuoso
      style={{ height: 600 }}
      totalCount={items.length}
      endReached={loadMore}
      itemContent={(index) => (
        <div>{items[index].name}</div>
      )}
      components={{
        Footer: () => loading ? <div>加载中...</div> : null,
      }}
    />
  );
}
```

### 4.3 分组列表

```javascript
import { GroupedVirtuoso } from 'react-virtuoso';

function GroupedList({ groups }) {
  // groups: [{ label: 'A', items: [...] }, { label: 'B', items: [...] }]

  const groupCounts = groups.map(g => g.items.length);

  return (
    <GroupedVirtuoso
      style={{ height: 600 }}
      groupCounts={groupCounts}
      groupContent={(index) => (
        <div className="group-header">{groups[index].label}</div>
      )}
      itemContent={(index, groupIndex) => {
        const item = groups[groupIndex].items[index];
        return <div>{item.name}</div>;
      }}
    />
  );
}
```

## 六、何时使用虚拟滚动

```
┌──────────────────────────────────────────────────────────────┐
│              何时使用虚拟滚动？                                │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  ✅ 使用：                                                    │
│  - 列表项 > 100 个                                           │
│  - 每个列表项包含复杂内容                                     │
│  - 需要无限滚动加载更多                                       │
│  - 数据表格（行数多）                                         │
│                                                              │
│  ❌ 不使用：                                                  │
│  - 列表项 < 50 个（用 memo 就够了）                           │
│  - 列表项高度不一致且无法估算                                  │
│  - 需要 Ctrl+F 搜索（虚拟滚动会破坏浏览器原生搜索）           │
│  - 列表项需要被搜索引擎索引                                   │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## 七、对比方案

```
┌──────────────┬──────────────┬──────────────┬────────────────┐
│ 方案          │ 适用数量      │ 高度要求      │ 依赖            │
├──────────────┼──────────────┼──────────────┼────────────────┤
│ 直接渲染      │ < 50         │ 不限          │ 无              │
│ 分页          │ 不限          │ 不限          │ 无              │
│ react-window │ 100-100000   │ 固定/可估算   │ ~3kB            │
│ react-virtuoso│ 100-100000  │ 自动测量      │ ~9kB            │
└──────────────┴──────────────┴──────────────┴────────────────┘
```

---

## 常见误区

1. **列表项少于 100 个就用虚拟滚动**：虚拟滚动有额外的复杂度（滚动位置计算、动态高度测量、键盘导航适配）。50 个以内的列表项用 memo 就够了。
2. **虚拟滚动后就不需要优化列表项**：即使只渲染 15 个可见项，如果每个列表项的渲染成本很高（复杂组件、大量 DOM），滚动时仍然会卡。列表项本身也要用 memo + 稳定回调。
3. **忽略虚拟滚动对无障碍的影响**：虚拟滚动会破坏浏览器原生的 Ctrl+F 搜索、屏幕阅读器的导航。如果列表需要被搜索引擎索引或支持无障碍访问，需要额外处理。
4. **react-window 和 react-virtuoso 混用**：两者解决同一类问题但 API 不同。固定高度用 react-window 更轻量（3KB），需要自动高度测量用 react-virtuoso（9KB）。

## 工程建议

1. **先用 memo + 分页试一试**：如果分页能满足业务需求，虚拟滚动可能不需要。虚拟滚动是"最后的手段"。
2. **react-virtuoso 适合内容高度不确定的场景**：它会自动测量每项高度，不需要你预估。但首次渲染时可能有轻微的跳动。
3. **虚拟列表的 Row 组件必须用 memo**：即使只渲染 15 个可见项，如果滚动时每个 Row 都重新渲染，仍然会掉帧。配合稳定的 onSelect 回调使用。
4. **大数据排序/过滤考虑用 Web Worker**：5000 条数据的排序可能产生长任务。把排序逻辑移到 Worker 中，主线程只负责渲染。

## 参考答案

### 练习一：实现固定高度虚拟列表

**思路**：用 react-window 的 FixedSizeList 渲染 10000 条数据，对比直接渲染的性能差异。

**答案**：

```jsx
import { FixedSizeList } from 'react-window';
import { memo, useCallback, useState, Profiler } from 'react';

// 列表项组件
const Row = memo(function Row({ index, style, data }) {
  const item = data[index];
  return (
    <div style={{ ...style, display: 'flex', alignItems: 'center', padding: '0 16px', borderBottom: '1px solid #eee' }}>
      <img src={item.avatar} alt="" width={32} height={32} style={{ borderRadius: '50%', marginRight: 12 }} />
      <div>
        <div style={{ fontWeight: 600 }}>{item.name}</div>
        <div style={{ color: '#666', fontSize: 14 }}>{item.email}</div>
      </div>
    </div>
  );
});

function VirtualList() {
  const items = Array.from({ length: 10000 }, (_, i) => ({
    id: i,
    name: `User ${i}`,
    email: `user${i}@example.com`,
    avatar: `https://i.pravatar.cc/32?u=${i}`,
  }));

  return (
    <Profiler id="VirtualList" onRender={(id, phase, duration) => {
      console.log(`${id} ${phase}: ${duration.toFixed(2)}ms`);
    }}>
      <FixedSizeList
        height={600}
        width={400}
        itemCount={items.length}
        itemSize={64}
        itemData={items}
      >
        {Row}
      </FixedSizeList>
    </Profiler>
  );
}
```

```markdown
性能对比：

直接渲染 10000 项：
- 首次渲染: 1200ms（长任务！）
- DOM 节点数: 50000+
- 内存占用: 高

虚拟滚动（FixedSizeList）：
- 首次渲染: 15ms
- DOM 节点数: 约 20 个（只渲染可见区域）
- 内存占用: 低
- 滚动时每次渲染: < 5ms

结论：
- 虚拟滚动把 10000 项的渲染从 1200ms 降到 15ms（提升 80x）
- DOM 节点从 50000+ 降到 20 个
- 滚动流畅，无掉帧
```

**要点**：
- FixedSizeList 适用于固定高度的列表项
- 只渲染可见区域的项，用 padding/定位模拟滚动
- 列表项组件必须用 memo，否则滚动时每个项都重新渲染

### 练习二：实现无限加载

**思路**：用 react-virtuoso 实现无限滚动，滚动到底部自动加载下一页。

**答案**：

```jsx
import { Virtuoso } from 'react-virtuoso';
import { useState, useCallback, useRef } from 'react';

function InfiniteList() {
  const [items, setItems] = useState([]);
  const [loading, setLoading] = useState(false);
  const pageRef = useRef(1);

  const loadMore = useCallback(async () => {
    if (loading) return;
    setLoading(true);

    // 模拟 API 请求
    const response = await fetch(`/api/items?page=${pageRef.current}&size=20`);
    const newItems = await response.json();

    setItems(prev => [...prev, ...newItems]);
    pageRef.current += 1;
    setLoading(false);
  }, [loading]);

  // 初始加载
  useState(() => { loadMore(); });

  return (
    <Virtuoso
      style={{ height: 600 }}
      totalCount={items.length}
      itemContent={(index) => (
        <div style={{ padding: 16, borderBottom: '1px solid #eee' }}>
          <strong>{items[index].name}</strong>
          <p>{items[index].description}</p>
        </div>
      )}
      endReached={loadMore}
      components={{
        Footer: () => loading ? (
          <div style={{ padding: 16, textAlign: 'center' }}>加载中...</div>
        ) : null,
      }}
    />
  );
}
```

```markdown
功能验证：

1. 初始加载：显示前 20 项
2. 滚动到底部：自动触发 loadMore，加载下一页
3. 加载中：底部显示"加载中..."指示器
4. 滚动流畅：虚拟滚动只渲染可见区域

注意事项：
- endReached 在距离底部 200px 时触发（可配置）
- loading 状态防止重复请求
- totalCount 必须正确设置，否则滚动位置计算错误
```

**要点**：
- react-virtuoso 的 endReached 属性在滚动到底部时触发
- 必须有 loading 状态防止重复请求
- totalCount 必须和实际数据量一致

### 练习三：优化列表项

**思路**：给列表项组件添加 memo，稳定传递给列表项的回调函数，用 Profiler 验证列表项不会不必要地渲染。

**答案**：

```jsx
import { memo, useCallback, useState, Profiler } from 'react';

// ❌ 不用 memo 的列表项
function BadListItem({ item, onSelect }) {
  console.log('BadListItem rendered:', item.id);
  return (
    <div onClick={() => onSelect(item.id)} style={{ padding: 12 }}>
      {item.name}
    </div>
  );
}

// ✅ 用 memo 的列表项
const GoodListItem = memo(function GoodListItem({ item, onSelect }) {
  console.log('GoodListItem rendered:', item.id);
  return (
    <div onClick={() => onSelect(item.id)} style={{ padding: 12 }}>
      {item.name}
    </div>
  );
});

function List() {
  const [selectedId, setSelectedId] = useState(null);
  const [filter, setFilter] = useState('');

  const items = Array.from({ length: 100 }, (_, i) => ({
    id: i,
    name: `Item ${i}`,
  }));

  // ✅ 稳定 onSelect 引用
  const handleSelect = useCallback((id) => {
    setSelectedId(id);
  }, []);

  return (
    <div>
      <input value={filter} onChange={e => setFilter(e.target.value)} />
      <Profiler id="List" onRender={(id, phase, duration) => {
        console.log(`${id} ${phase}: ${duration.toFixed(2)}ms`);
      }}>
        {items.map(item => (
          <GoodListItem key={item.id} item={item} onSelect={handleSelect} />
        ))}
      </Profiler>
    </div>
  );
}
```

```markdown
验证结果：

输入搜索关键词时：

BadListItem 方案：
- 100 个 BadListItem 全部渲染
- 渲染耗时: 45ms

GoodListItem 方案：
- 只有 GoodListItem 的父组件渲染
- GoodListItem 全部跳过（memo + 稳定 onSelect）
- 渲染耗时: 2ms

点击列表项时：
- GoodListItem 渲染被点击的那一项
- 其他 99 项跳过
```

**要点**：
- 列表项组件必须用 memo
- onSelect 等回调函数必须用 useCallback 稳定引用
- 列表项的 item 对象如果每次都是新引用，memo 也会失效

---

## 小结

1. **大列表问题**：DOM 节点多 → 渲染慢、内存高
2. **虚拟滚动原理**：只渲染可视区域，用 padding/定位模拟滚动
3. **react-window**：固定高度用 FixedSizeList，可变高度用 VariableSizeList
4. **react-virtuoso**：自动测量高度，支持无限加载和分组
5. **列表项也要优化**：用 memo + 稳定回调
