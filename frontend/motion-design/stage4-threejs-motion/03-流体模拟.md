# 流体模拟：粒子流体与 SPH 方法

## 场景引入

在产品可视化和创意互动中，流体效果越来越常见：化妆品广告中的水珠飞溅、汽车官网的油滴交互、游戏中的瀑布和海洋。这些效果的共同特点是：由大量粒子组成，每个粒子遵循流体力学规律运动。

浏览器端的流体模拟面临核心矛盾：真实的 Navier-Stokes 方程求解需要超级计算机级别的算力，而浏览器只有一个 CPU 核心。解决方法是使用粒子方法——SPH（Smoothed Particle Hydrodynamics），它用有限数量的粒子近似连续流体，在 Web 端可实现 1000-5000 粒子的实时模拟。

## 学习目标

1. 理解 SPH 方法的核心思想：用粒子近似连续流体
2. 掌握 SPH 的三大计算步骤：密度估算、压力计算、力积分
3. 能用 Three.js 的 InstancedMesh 渲染大量粒子
4. 掌握流体效果的性能优化策略
5. 理解网格法与粒子法的区别与适用场景
6. 掌握 WebGL 层面的粒子渲染优化技巧
7. 了解流体模拟中的内存管理策略

## SPH 核心原理

### 为什么用粒子而不是网格？

传统的流体模拟（如有限差分法）将空间划分为规则网格，每个格子存储密度、速度等物理量。这种方法在工程中非常成熟，但在浏览器中有两个致命问题：

1. **内存开销大**：三维网格的格子数量随分辨率立方增长。一个 100×100×100 的网格就有 100 万个格子，每个格子存储密度（1 float）、速度（3 floats）、压力（1 float），仅基础数据就需要 20MB。
2. **自适应困难**：水滴飞溅时，大部分空间是空气，只有少量区域有水。网格法会浪费大量算力计算空气区域，而粒子法天然只在有流体的地方存在粒子。

SPH 的思路反过来：不划分空间，而是让空间中漂浮着若干"小球"（粒子），每个小球携带质量、速度等物理量。想知道某个位置的密度？把附近所有小球的贡献加起来就行。

### 核函数：粒子之间如何"看见"对方

SPH 中最关键的数学工具是**核函数**（Kernel Function）。它的作用是：给定两个粒子之间的距离，返回一个权重值。距离越近，权重越大；距离超过一定范围（光滑半径 h），权重为零。

这就像一个"影响力范围"：每个粒子只能影响到它周围 h 范围内的其他粒子。超出范围的粒子，对它来说就像不存在一样。

想象你在泳池里扔了一块石头。水面上每个点受到的扰动，等于附近所有水分子扰动的加权平均——离得近的水分子影响大，离得远的影响小。核函数就是这个"影响大/小"的数学描述。

三个关键公式：

**密度估算**：`ρ_i = Σ_j m_j * W(r_i - r_j, h)`

这个公式的直觉是：粒子 i 的密度等于它周围所有粒子 j 的质量贡献之和。每个粒子 j 对 i 的贡献由核函数 W 决定——如果 j 离 i 很远，W 接近零，贡献可忽略。

**压力计算**：`p_i = k * (ρ_i - ρ_rest)`

密度高于静止密度的地方压力大（被"挤压"了），密度低于静止密度的地方压力小（被"拉伸"了）。压力差驱动流体从高压区流向低压区——这就是水往低处流的微观机制。

**加速度计算**：`a_i = -Σ_j m_j * (p_i/ρ_i² + p_j/ρ_j²) * ∇W(r_i - r_j, h)`

这是牛顿第二定律的 SPH 形式。粒子 i 的加速度来自周围粒子的压力梯度。注意 ∇W 是核函数的梯度（指向压力降低的方向），所以流体自然从高压区流向低压区。

其中 W 是核函数，h 是光滑半径，ρ_rest 是静止密度。

### 三种核函数

SPH 中常用的核函数有三种，各自负责不同的物理量计算：

| 核函数 | 用途 | 特点 |
|--------|------|------|
| Poly6 | 密度估算 | 各向同性，计算快，适合标量场 |
| Spiky | 压力梯度 | 在 r→0 时梯度不会发散，避免粒子聚集 |
| Viscosity | 粘性力 | 拉普拉斯算子，模拟流体粘性 |

为什么需要三种？因为密度是标量（只需要求和），压力梯度是矢量（需要方向），粘性力需要拉普拉斯算子。每种数学运算对核函数的要求不同。如果用同一个核函数处理所有计算，会导致数值不稳定（比如粒子"抱团"或"爆炸"）。

### 算法流程

SPH 的每一帧计算分为三个阶段：

1. **密度-压力阶段**：遍历所有粒子对，用 Poly6 核函数估算每个粒子的密度，然后通过状态方程计算压力。
2. **力计算阶段**：用 Spiky 核函数计算压力梯度力，用 Viscosity 核函数计算粘性力，加上重力得到总加速度。
3. **积分阶段**：用半隐式欧拉法更新速度和位置，处理边界碰撞。

这三个阶段必须严格按顺序执行——不能先算力再算密度，因为力的计算依赖于密度和压力的结果。

## 基础 SPH 实现

```javascript
class SPHParticle {
  constructor(x, y, z) {
    // 位置：三维空间中的坐标
    this.position = new THREE.Vector3(x, y, z)
    // 速度：每帧更新，决定粒子运动方向和快慢
    this.velocity = new THREE.Vector3()
    // 加速度：由压力、粘性、重力共同决定
    this.acceleration = new THREE.Vector3()
    // 密度：周围粒子的密集程度，影响压力
    this.density = 0
    // 压力：密度偏离静止密度的程度，驱动粒子运动
    this.pressure = 0
  }
}

class SPHSimulation {
  constructor(params = {}) {
    this.particles = []
    // 静止密度：流体在不受力时的自然密度（水约 1000 kg/m³）
    this.restDensity = params.restDensity || 1000
    // 刚度：压力对密度变化的敏感程度，太小流体太软，太大会爆炸
    this.stiffness = params.stiffness || 2000
    // 粘度：流体的"粘稠"程度，水约 1，蜂蜜约 3000
    this.viscosity = params.viscosity || 250
    // 粒子质量：影响密度计算的尺度
    this.particleMass = params.particleMass || 1
    // 光滑半径 h：核函数的影响范围，太小粒子看不见邻居，太大精度下降
    this.smoothingRadius = params.smoothingRadius || 0.1
    // 重力加速度
    this.gravity = new THREE.Vector3(0, -9.81, 0)
    // 时间步长：SPH 对步长非常敏感，通常需要 0.001-0.005
    this.timeStep = params.timeStep || 0.002
  }

  addParticle(x, y, z) {
    this.particles.push(new SPHParticle(x, y, z))
  }

  // Poly6 核函数：用于密度估算
  // 输入：r 为两粒子的位置差向量，h 为光滑半径
  // 输出：标量权重值，r 的长度 >= h 时返回 0
  poly6Kernel(r, h) {
    const rLen = r.length()
    if (rLen >= h) return 0
    // 常数 315/(64πh⁹) 确保核函数在影响范围内积分为 1
    return (315 / (64 * Math.PI * Math.pow(h, 9))) * Math.pow(h * h - rLen * rLen, 3)
  }

  // Spiky 核函数的梯度：用于压力梯度计算
  // 输出：矢量，方向指向压力降低的方向
  spikyGradient(r, h) {
    const rLen = r.length()
    if (rLen >= h || rLen === 0) return new THREE.Vector3()
    // 方向：从 j 指向 i（r 的方向），大小与距离成反比
    return r.clone().normalize().multiplyScalar(
      -45 / (Math.PI * Math.pow(h, 6)) * Math.pow(h - rLen, 2)
    )
  }

  // Viscosity 核函数的拉普拉斯算子：用于粘性力计算
  // 输出：标量，描述速度场的"光滑程度"
  viscosityLaplacian(r, h) {
    const rLen = r.length()
    return rLen >= h ? 0 : (45 / (Math.PI * Math.pow(h, 6))) * (h - rLen)
  }

  // 阶段一：计算所有粒子的密度和压力
  computeDensityAndPressure() {
    const h = this.smoothingRadius
    for (const pi of this.particles) {
      pi.density = 0
      // 遍历所有粒子，累加邻居的质量贡献
      for (const pj of this.particles) {
        if (pi === pj) continue
        // 只有在光滑半径内的粒子才会贡献密度
        pi.density += this.particleMass * this.poly6Kernel(
          pi.position.clone().sub(pj.position), h
        )
      }
      // 状态方程：密度越高压力越大
      // 负压力表示该区域密度低于静止密度（被拉伸）
      pi.pressure = this.stiffness * (pi.density - this.restDensity)
    }
  }

  // 阶段二：计算压力梯度力和粘性力
  computeForces() {
    const h = this.smoothingRadius
    for (const pi of this.particles) {
      // 压力梯度力：驱动粒子从高压区流向低压区
      const pressureForce = new THREE.Vector3()
      // 粘性力：模拟流体的内摩擦，使速度趋于一致
      const viscosityForce = new THREE.Vector3()

      for (const pj of this.particles) {
        if (pi === pj) continue
        const r = pi.position.clone().sub(pj.position)

        // 压力梯度力：使用 Spiky 核函数的梯度
        const gradW = this.spikyGradient(r, h)
        const pressureTerm = this.particleMass *
          -(pi.pressure / (pi.density ** 2) + pj.pressure / (pj.density ** 2))
        pressureForce.add(gradW.clone().multiplyScalar(pressureTerm))

        // 粘性力：使用 Viscosity 核函数的拉普拉斯算子
        const viscTerm = this.viscosity * this.particleMass *
          this.viscosityLaplacian(r, h) / pj.density
        viscosityForce.add(pj.velocity.clone().sub(pi.velocity).multiplyScalar(viscTerm))
      }

      // 总加速度 = 重力 + 压力梯度力/密度 + 粘性力/密度
      pi.acceleration.copy(this.gravity)
        .add(pressureForce.multiplyScalar(1 / pi.density))
        .add(viscosityForce.multiplyScalar(1 / pi.density))
    }
  }

  // 阶段三：时间积分（半隐式欧拉法）
  integrate() {
    const dt = this.timeStep
    // 碰撞阻尼系数：反弹时损失的能量比例
    const damping = 0.3

    for (const p of this.particles) {
      // 先更新速度（用新加速度），再更新位置（用新速度）
      // 这比显式欧拉法更稳定
      p.velocity.add(p.acceleration.clone().multiplyScalar(dt))
      p.position.add(p.velocity.clone().multiplyScalar(dt))

      // 边界条件：地面碰撞
      if (p.position.y < 0) {
        p.position.y = 0
        p.velocity.y *= -damping
      }
      // 边界条件：左右墙壁（x 方向 ±2）
      if (Math.abs(p.position.x) > 2) {
        p.position.x = Math.sign(p.position.x) * 2
        p.velocity.x *= -damping
      }
      // 边界条件：前后墙壁（z 方向 ±2）
      if (Math.abs(p.position.z) > 2) {
        p.position.z = Math.sign(p.position.z) * 2
        p.velocity.z *= -damping
      }
    }
  }

  // 模拟主循环：三个阶段依次执行
  step() {
    this.computeDensityAndPressure()
    this.computeForces()
    this.integrate()
  }
}
```

## 空间哈希加速

上面的实现是 O(n²) 复杂度——每对粒子都要互相检查是否在邻居范围内。当粒子数量超过 500 时，性能会急剧下降。

空间哈希的核心思想：把空间划分为边长等于光滑半径的网格。两个粒子如果不在相邻网格中，它们之间的距离一定超过光滑半径，不需要计算。这样每帧只需检查 27 个相邻格子（3×3×3）中的粒子，而不是所有粒子。

```javascript
class SpatialHash {
  constructor(cellSize) {
    // cellSize 应设为 smoothingRadius，确保不遗漏任何邻居
    this.cellSize = cellSize
    // 用 Map 存储每个格子中的粒子索引
    this.grid = new Map()
  }

  // 将三维坐标映射到网格的字符串键
  // 使用字符串键而非数字键，因为 Map 的数字键查找更快
  // 但字符串键更直观，且避免了三维坐标到一维的哈希冲突
  hash(x, y, z) {
    return `${Math.floor(x / this.cellSize)},${Math.floor(y / this.cellSize)},${Math.floor(z / this.cellSize)}`
  }

  // 每帧开始时清空网格，重新插入所有粒子
  clear() { this.grid.clear() }

  // 将粒子插入对应网格
  insert(particle, index) {
    const key = this.hash(particle.position.x, particle.position.y, particle.position.z)
    if (!this.grid.has(key)) this.grid.set(key, [])
    this.grid.get(key).push(index)
  }

  // 获取某粒子的所有邻居（来自 27 个相邻格子）
  getNeighbors(particle) {
    const cx = Math.floor(particle.position.x / this.cellSize)
    const cy = Math.floor(particle.position.y / this.cellSize)
    const cz = Math.floor(particle.position.z / this.cellSize)
    const neighbors = []

    // 遍历 3×3×3 的相邻格子
    for (let dx = -1; dx <= 1; dx++) {
      for (let dy = -1; dy <= 1; dy++) {
        for (let dz = -1; dz <= 1; dz++) {
          const cell = this.grid.get(`${cx + dx},${cy + dy},${cz + dz}`)
          if (cell) neighbors.push(...cell)
        }
      }
    }
    return neighbors
  }
}
```

使用空间哈希后，SPH 的每帧计算流程变为：

```javascript
const spatialHash = new SpatialHash(sph.smoothingRadius)

function optimizedStep() {
  // 1. 重建空间哈希（O(n)）
  spatialHash.clear()
  sph.particles.forEach((p, i) => spatialHash.insert(p, i))

  // 2. 密度和压力计算（O(n*k)，k 为平均邻居数）
  for (const pi of sph.particles) {
    pi.density = 0
    const neighbors = spatialHash.getNeighbors(pi)
    for (const j of neighbors) {
      const pj = sph.particles[j]
      if (pi === pj) continue
      pi.density += sph.particleMass * sph.poly6Kernel(
        pi.position.clone().sub(pj.position), sph.smoothingRadius
      )
    }
    pi.pressure = sph.stiffness * (pi.density - sph.restDensity)
  }

  // 3. 力计算（同样使用空间哈希查找邻居）
  sph.computeForces()
  sph.integrate()
}
```

实际性能对比（1000 粒子）：
- O(n²) 暴力搜索：约 200ms/帧
- 空间哈希：约 2ms/帧
- 提升约 100 倍，足以在浏览器中实现实时模拟

## Three.js 粒子渲染

### InstancedMesh 方式

使用 InstancedMesh 渲染粒子，比 Points 更灵活（支持光照、阴影、自定义形状）。

```javascript
// 创建 InstancedMesh：一个几何体 + 一个材质 + 实例数量
// 每个实例可以有独立的变换矩阵（位置、旋转、缩放）
const instancedMesh = new THREE.InstancedMesh(
  new THREE.SphereGeometry(0.02, 8, 8),  // 低面数球体，每粒子仅 128 三角形
  new THREE.MeshStandardMaterial({
    color: 0x3498db,    // 水蓝色
    metalness: 0.3,     // 轻微金属感
    roughness: 0.4      // 中等粗糙度
  }),
  2000  // 最大实例数
)
scene.add(instancedMesh)

// 用于计算每个实例的变换矩阵
const dummy = new THREE.Object3D()

function renderParticles(sph) {
  for (let i = 0; i < sph.particles.length; i++) {
    dummy.position.copy(sph.particles[i].position)
    // 可根据速度动态调整缩放，模拟粒子拉伸效果
    const speed = sph.particles[i].velocity.length()
    const stretch = 1 + speed * 0.1  // 速度越快，粒子越扁
    dummy.scale.set(1 / stretch, stretch, 1 / stretch)
    dummy.updateMatrix()
    instancedMesh.setMatrixAt(i, dummy.matrix)
  }
  instancedMesh.instanceMatrix.needsUpdate = true
}
```

### Points 方式（轻量级替代）

当粒子数量超过 5000 时，InstancedMesh 的 draw call 开销会成为瓶颈。此时可以用 Points 替代——每个粒子只是一个点，GPU 直接绘制，性能更好但没有光照。

```javascript
// 创建 BufferGeometry 存储粒子位置
const geometry = new THREE.BufferGeometry()
const positions = new Float32Array(maxParticles * 3)  // 每粒子 3 个 float
geometry.setAttribute('position', new THREE.BufferAttribute(positions, 3))

// 使用 PointsMaterial，支持大小衰减和纹理
const material = new THREE.PointsMaterial({
  size: 0.03,
  sizeAttenuation: true,  // 远处粒子更小
  color: 0x3498db,
  transparent: true,
  opacity: 0.8,
  // 可选：使用圆形纹理替代默认方块
  // map: circleTexture,
  depthWrite: false  // 透明粒子需要关闭深度写入
})

const points = new THREE.Points(geometry, material)
scene.add(points)

function renderPoints(sph) {
  const posArray = geometry.attributes.position.array
  for (let i = 0; i < sph.particles.length; i++) {
    const p = sph.particles[i]
    posArray[i * 3]     = p.position.x
    posArray[i * 3 + 1] = p.position.y
    posArray[i * 3 + 2] = p.position.z
  }
  geometry.attributes.position.needsUpdate = true
  // 设置实际绘制的粒子数（可能少于 maxParticles）
  geometry.setDrawRange(0, sph.particles.length)
}
```

## WebGL 粒子渲染

当粒子数量超过 10000 时，即使使用 Points，CPU 端每帧更新位置数组也会成为瓶颈。此时需要将粒子模拟搬到 GPU 上。

### GPU 粒子模拟思路

将粒子数据存储在纹理中，用全屏 Shader 执行物理计算（密度、力、积分），结果写回另一张纹理。渲染时直接从纹理读取位置，CPU 完全不参与粒子更新。

```
CPU 角色：初始化参数、设置边界条件、触发模拟
GPU 角色：执行每帧的密度/力/积分计算、渲染粒子
```

### Transform Feedback 方案

WebGL 2 提供了 Transform Feedback，允许顶点着色器的输出直接写入缓冲区，跳过光栅化阶段。这是 GPU 粒子模拟的常用方案。

```javascript
// 顶点着色器：执行粒子物理更新
const vertexShader = `#version 300 es
  // 输入：上一帧的位置和速度
  in vec3 aPosition;
  in vec3 aVelocity;

  // 输出：写入 Transform Feedback 缓冲区
  out vec3 vPosition;
  out vec3 vVelocity;

  uniform float uDeltaTime;
  uniform vec3 uGravity;

  void main() {
    // 简化的物理：重力 + 简单阻尼（完整 SPH 需要更复杂的 shader）
    vec3 accel = uGravity;
    vec3 newVelocity = aVelocity + accel * uDeltaTime;
    vec3 newPosition = aPosition + newVelocity * uDeltaTime;

    // 地面碰撞
    if (newPosition.y < 0.0) {
      newPosition.y = 0.0;
      newVelocity.y *= -0.3;
    }

    vPosition = newPosition;
    vVelocity = newVelocity;
  }
`

// 创建 Transform Feedback
const tf = gl.createTransformFeedback()
gl.bindTransformFeedback(gl.TRANSFORM_FEEDBACK, tf)

// 双缓冲：ping-pong 两个缓冲区交替读写
let readBuffer = createPositionBuffer(initialPositions)
let writeBuffer = createPositionBuffer(initialPositions)

// 每帧执行
function gpuStep() {
  gl.useProgram(program)
  gl.bindTransformFeedback(gl.TRANSFORM_FEEDBACK, tf)
  gl.bindBufferBase(gl.TRANSFORM_FEEDBACK_BUFFER, 0, writeBuffer)

  gl.beginTransformFeedback(gl.POINTS)
  gl.drawArrays(gl.POINTS, 0, particleCount)
  gl.endTransformFeedback()

  // 交换读写缓冲区
  ;[readBuffer, writeBuffer] = [writeBuffer, readBuffer]
}
```

### GPU 方案的适用场景

- 粒子数量 > 10000 时，GPU 方案性能优势明显
- 物理逻辑较简单（如重力 + 碰撞）时，Shader 编写容易
- 完整 SPH 的密度/力计算在 Shader 中实现复杂（需要邻居查找），通常需要预计算邻居列表或使用简化模型

## 网格法流体模拟

### 与粒子法的对比

除了 SPH 这种粒子方法，流体模拟还有另一大类：网格法（Grid-based）。两者的核心区别在于如何表示流体：

| 特性 | 粒子法（SPH） | 网格法（Eulerian） |
|------|--------------|-------------------|
| 流体表示 | 离散粒子 | 固定网格中的密度场 |
| 边界处理 | 粒子自然贴合边界 | 需要额外的边界条件 |
| 自适应 | 天然自适应（粒子密度随流体分布变化） | 需要自适应网格细分 |
| 内存 | 与粒子数量成正比 | 与网格分辨率成正比 |
| 适用场景 | 自由表面（飞溅、水花） | 大规模流体（海洋、烟雾） |

### 简化网格法实现

网格法的核心是将 Navier-Stokes 方程在固定网格上离散化。下面是一个简化的二维网格法实现，使用半拉格朗日法（Semi-Lagrangian）进行对流：

```javascript
class GridFluid {
  constructor(width, height, cellSize) {
    this.width = width
    this.height = height
    this.cellSize = cellSize
    // 网格数量
    this.cols = Math.ceil(width / cellSize)
    this.rows = Math.ceil(height / cellSize)

    // 每个格子存储：水平速度 u、垂直速度 v、密度
    // 使用一维数组模拟二维网格，索引 = y * cols + x
    this.u = new Float32Array(this.cols * this.rows)      // 水平速度
    this.v = new Float32Array(this.cols * this.rows)      // 垂直速度
    this.density = new Float32Array(this.cols * this.rows) // 密度（用于渲染）
    this.uNew = new Float32Array(this.cols * this.rows)   // 临时缓冲区
    this.vNew = new Float32Array(this.cols * this.rows)
  }

  // 获取某格子的一维索引
  idx(col, row) {
    return row * this.cols + col
  }

  // 在指定位置添加速度扰动（模拟注入流体）
  addVelocity(col, row, uAmount, vAmount) {
    if (col < 0 || col >= this.cols || row < 0 || row >= this.rows) return
    const i = this.idx(col, row)
    this.u[i] += uAmount
    this.v[i] += vAmount
  }

  // 在指定位置添加密度（模拟流体源头）
  addDensity(col, row, amount) {
    if (col < 0 || col >= this.cols || row < 0 || row >= this.rows) return
    this.density[this.idx(col, row)] += amount
  }

  // 对流步骤：半拉格朗日法
  // 核心思想：不是问"这个格子的速度会把流体带到哪里"
  // 而是问"这个格子的流体是从哪里来的"
  advect(dt) {
    for (let row = 0; row < this.rows; row++) {
      for (let col = 0; col < this.cols; col++) {
        const i = this.idx(col, row)

        // 沿速度方向回溯
        let srcX = col - this.u[i] * dt / this.cellSize
        let srcY = row - this.v[i] * dt / this.cellSize

        // 边界钳制
        srcX = Math.max(0.5, Math.min(this.cols - 1.5, srcX))
        srcY = Math.max(0.5, Math.min(this.rows - 1.5, srcY))

        // 双线性插值读取源位置的速度
        const c0 = Math.floor(srcX), r0 = Math.floor(srcY)
        const c1 = c0 + 1, r1 = r0 + 1
        const s = srcX - c0, t = srcY - r0

        this.uNew[i] = (1 - s) * ((1 - t) * this.u[this.idx(c0, r0)] + t * this.u[this.idx(c0, r1)])
                      + s * ((1 - t) * this.u[this.idx(c1, r0)] + t * this.u[this.idx(c1, r1)])
        this.vNew[i] = (1 - s) * ((1 - t) * this.v[this.idx(c0, r0)] + t * this.v[this.idx(c0, r1)])
                      + s * ((1 - t) * this.v[this.idx(c1, r0)] + t * this.v[this.idx(c1, r1)])
      }
    }
    // 交换缓冲区
    ;[this.u, this.uNew] = [this.uNew, this.u]
    ;[this.v, this.vNew] = [this.vNew, this.v]
  }

  // 扩散步骤：模拟粘性，使速度场趋于平滑
  diffuse(dt) {
    const visc = 0.0001  // 粘性系数
    const a = visc * dt / (this.cellSize * this.cellSize)

    // 用 Gauss-Seidel 迭代求解扩散方程
    for (let iter = 0; iter < 4; iter++) {
      for (let row = 1; row < this.rows - 1; row++) {
        for (let col = 1; col < this.cols - 1; col++) {
          const i = this.idx(col, row)
          this.uNew[i] = (this.u[i] + a * (
            this.uNew[this.idx(col - 1, row)] + this.uNew[this.idx(col + 1, row)] +
            this.uNew[this.idx(col, row - 1)] + this.uNew[this.idx(col, row + 1)]
          )) / (1 + 4 * a)
          this.vNew[i] = (this.v[i] + a * (
            this.vNew[this.idx(col - 1, row)] + this.vNew[this.idx(col + 1, row)] +
            this.vNew[this.idx(col, row - 1)] + this.vNew[this.idx(col, row + 1)]
          )) / (1 + 4 * a)
        }
      }
    }
    ;[this.u, this.uNew] = [this.uNew, this.u]
    ;[this.v, this.vNew] = [this.vNew, this.v]
  }

  // 投影步骤：确保速度场无散度（质量守恒）
  // 这是 Navier-Stokes 方程中最关键的一步
  project() {
    const div = new Float32Array(this.cols * this.rows)
    const p = new Float32Array(this.cols * this.rows)

    // 计算速度场的散度
    for (let row = 1; row < this.rows - 1; row++) {
      for (let col = 1; col < this.cols - 1; col++) {
        const i = this.idx(col, row)
        div[i] = -0.5 * this.cellSize * (
          this.u[this.idx(col + 1, row)] - this.u[this.idx(col - 1, row)] +
          this.v[this.idx(col, row + 1)] - this.v[this.idx(col, row - 1)]
        )
      }
    }

    // Gauss-Seidel 迭代求解压力泊松方程
    for (let iter = 0; iter < 4; iter++) {
      for (let row = 1; row < this.rows - 1; row++) {
        for (let col = 1; col < this.cols - 1; col++) {
          const i = this.idx(col, row)
          p[i] = (div[i] + p[this.idx(col - 1, row)] + p[this.idx(col + 1, row)]
                       + p[this.idx(col, row - 1)] + p[this.idx(col, row + 1)]) / 4
        }
      }
    }

    // 用压力梯度修正速度，使速度场无散度
    for (let row = 1; row < this.rows - 1; row++) {
      for (let col = 1; col < this.cols - 1; col++) {
        const i = this.idx(col, row)
        this.u[i] -= 0.5 * (p[this.idx(col + 1, row)] - p[this.idx(col - 1, row)]) / this.cellSize
        this.v[i] -= 0.5 * (p[this.idx(col, row + 1)] - p[this.idx(col, row - 1)]) / this.cellSize
      }
    }
  }

  // 模拟主循环
  step(dt) {
    this.advect(dt)
    this.diffuse(dt)
    this.project()
  }
}
```

## 流体与粒子的交互

在很多实际场景中，流体需要与其他粒子系统交互，例如：

- 水流冲击沙粒（流体驱动固体粒子）
- 风吹动布料（空气流场影响布料节点）
- 墨水滴入水中（两种流体混合）

### 流体对刚体的作用力

将流体粒子的动量传递给刚体，实现流体推动物体的效果：

```javascript
class FluidRigidBodyInteraction {
  constructor() {
    // 累积力和力矩
    this.force = new THREE.Vector3()
    this.torque = new THREE.Vector3()
  }

  // 计算流体对刚体的合力
  // 策略：遍历与刚体重叠的流体粒子，将它们的动量变化转为作用力
  computeForce(sphParticles, rigidBody) {
    this.force.set(0, 0, 0)
    this.torque.set(0, 0, 0)

    for (const p of sphParticles) {
      // 判断粒子是否在刚体的包围盒内
      const localPos = p.position.clone().sub(rigidBody.position)
      if (localPos.length() > rigidBody.boundingRadius) continue

      // 力 = 粒子动量变化率 ≈ 粒子质量 × 粒子加速度
      // 这里用压力梯度力代替总加速度（排除重力）
      const particleForce = p.acceleration.clone().sub(
        new THREE.Vector3(0, -9.81, 0)
      ).multiplyScalar(p.density * sph.particleMass)

      this.force.add(particleForce)

      // 力矩 = 位置叉乘力（用于旋转）
      this.torque.add(localPos.clone().cross(particleForce))
    }

    // 应用力和力矩到刚体
    rigidBody.velocity.add(this.force.clone().multiplyScalar(1 / rigidBody.mass))
    rigidBody.angularVelocity.add(this.torque.clone().multiplyScalar(1 / rigidBody.inertia))
  }
}
```

### 流体间的交互

两种不同流体（如油和水）的混合模拟，需要为每种流体维护独立的粒子属性：

```javascript
class MultiFluidParticle extends SPHParticle {
  constructor(x, y, z, fluidType) {
    super(x, y, z)
    // 流体类型：0 = 水，1 = 油
    this.fluidType = fluidType
    // 不同流体有不同物理属性
    this.localDensity = fluidType === 0 ? 1000 : 800     // 水比油重
    this.localViscosity = fluidType === 0 ? 100 : 500    // 油比水粘
    this.localStiffness = fluidType === 0 ? 2000 : 1500  // 水比油刚
  }
}

// 混合密度计算：同种流体的分子间作用力更强
function computeMixingDensity(particles) {
  for (const pi of particles) {
    pi.density = 0
    for (const pj of particles) {
      if (pi === pj) continue
      const r = pi.position.clone().sub(pj.position)
      const kernel = poly6Kernel(r, smoothingRadius)

      // 同种流体：正常权重
      // 异种流体：权重降低（油水不相溶）
      const affinity = pi.fluidType === pj.fluidType ? 1.0 : 0.7

      pi.density += pj.localDensity * kernel * affinity
    }
  }
}
```

## 内存管理

流体模拟涉及大量动态对象，内存管理不当会导致垃圾回收频繁触发，造成帧率抖动。

### 对象池模式

避免每帧创建临时对象，预先分配所有需要的 Vector3 和 Float32Array：

```javascript
class ParticlePool {
  constructor(maxParticles) {
    this.maxParticles = maxParticles
    this.activeCount = 0

    // 使用 Float32Array 打包存储所有粒子数据
    // 布局：[x0, y0, z0, vx0, vy0, vz0, density0, pressure0, ...]
    // 每粒子 8 个 float = 32 字节
    this.data = new Float32Array(maxParticles * 8)

    // 空闲索引列表，用于快速分配和回收
    this.freeIndices = []
    for (let i = maxParticles - 1; i >= 0; i--) {
      this.freeIndices.push(i)
    }

    // 预分配临时 Vector3，避免 GC
    this._tempVec = new THREE.Vector3()
    this._tempVec2 = new THREE.Vector3()
  }

  // 从池中分配一个粒子
  allocate() {
    if (this.freeIndices.length === 0) return -1
    const idx = this.freeIndices.pop()
    this.activeCount++
    // 初始化为零
    const offset = idx * 8
    this.data[offset] = 0;     this.data[offset + 1] = 0;   this.data[offset + 2] = 0
    this.data[offset + 3] = 0; this.data[offset + 4] = 0;   this.data[offset + 5] = 0
    this.data[offset + 6] = 0; this.data[offset + 7] = 0
    return idx
  }

  // 回收粒子
  free(index) {
    this.freeIndices.push(index)
    this.activeCount--
  }

  // 获取粒子位置（不创建新对象）
  getPosition(index, target) {
    const offset = index * 8
    target.set(this.data[offset], this.data[offset + 1], this.data[offset + 2])
    return target
  }

  // 设置粒子位置
  setPosition(index, x, y, z) {
    const offset = index * 8
    this.data[offset] = x; this.data[offset + 1] = y; this.data[offset + 2] = z
  }

  // 获取粒子速度
  getVelocity(index, target) {
    const offset = index * 8
    target.set(this.data[offset + 3], this.data[offset + 4], this.data[offset + 5])
    return target
  }
}
```

## 常见误区

1. **光滑半径 h 太小**：粒子之间"看不见"邻居，导致密度估算为零。h 应至少为粒子初始间距的 2-3 倍。

2. **时间步长太大**：SPH 对时间步长敏感，dt > 0.005 会导致模拟爆炸。CFL 条件要求 dt < h / max_velocity，即时间步长要小于粒子在光滑半径内运动所需的时间。

3. **忽略密度为零的粒子**：除以零密度会产生 NaN。必须在力计算中加入密度下限保护：`const safeDensity = Math.max(pi.density, 0.001)`。

4. **Marching Cubes 分辨率太高**：resolution > 64 时 CPU 端更新非常慢。建议 32-48，配合降采样渲染。

5. **粒子数量不加限制**：必须设置上限防止崩溃。使用环形缓冲区复用最老的粒子。

6. **空间哈希的 cellSize 设置错误**：cellSize 必须等于 smoothingRadius。如果 cellSize > smoothingRadius，会遗漏真实邻居；如果 cellSize < smoothingRadius，虽然结果正确但浪费性能。

7. **边界条件处理不当**：只处理了位置约束没有处理速度方向，会导致粒子"粘"在边界上。正确的碰撞反弹应该翻转速度分量并乘以阻尼系数。

8. **在每帧循环中创建临时对象**：Three.js 的 Vector3.clone()、sub() 等方法每次调用都创建新对象。在 1000 粒子的双重循环中，每帧会创建数百万个临时对象，导致 GC 卡顿。必须使用预分配的临时 Vector3 复用。

## 工程建议

1. **使用空间哈希将复杂度从 O(n²) 降到 O(n)**：1000 粒子性能提升约 100 倍。空间哈希的 cellSize 必须等于 smoothingRadius。

2. **渲染与物理使用不同的帧率**：物理用固定 60Hz（dt = 0.002），渲染可降频到 30Hz。用 requestAnimationFrame 的时间差累积物理步数，每帧执行 0-N 步物理计算。

3. **生产环境考虑使用现成库**：如 three-sph、picosim.js，避免从零实现 SPH 的数值稳定性问题。

4. **移动端粒子数量控制在 500 以内**：移动端 GPU 的实例化渲染能力有限，超过 500 个 InstancedMesh 实例可能导致帧率下降到 30fps 以下。

5. **使用 InstancedMesh 替代 Points**：当需要光照、阴影、自定义粒子形状时。Points 更适合纯视觉效果（无需物理交互的背景粒子）。

6. **监控内存使用**：每帧检查 `performance.memory.usedJSHeapSize`，如果持续增长说明存在内存泄漏。常见泄漏源：未回收的粒子对象、未清理的空间哈希 Map、事件监听器未移除。

7. **使用 Worker 分担物理计算**：将 SPH 的密度/力计算放到 Web Worker 中，主线程只负责渲染。需要使用 SharedArrayBuffer 在主线程和 Worker 之间共享粒子数据。注意：SharedArrayBuffer 需要服务器设置 `Cross-Origin-Opener-Policy` 和 `Cross-Origin-Embedder-Policy` 响应头。

8. **降级策略**：在低端设备上自动降低粒子数量、增大时间步长、禁用 Marching Cubes 表面渲染。可以通过 `navigator.hardwareConcurrency` 检测 CPU 核心数，通过 `renderer.capabilities` 检测 GPU 能力。

## 小结

流体模拟的核心是 SPH 方法——用粒子近似连续流体，通过密度估算、压力计算、力积分三个步骤驱动粒子运动。空间哈希是性能优化的关键。渲染方面，InstancedMesh 适合少量粒子，Marching Cubes 适合流体表面，网格法适合大规模流体效果。内存管理方面，对象池和缓冲区预分配是避免 GC 卡顿的基础手段。

### 练习一

**思路**：初始化 20 个粒子在容器顶部，使用 SPHSimulation 驱动运动，空间哈希加速密度计算。

**答案**：

```javascript

  restDensity: 1000,
  stiffness: 2000,
  viscosity: 100,
  smoothingRadius: 0.15,
  timeStep: 0.002
})
for (let i = 0; i < 20; i++) {
  sph.addParticle((Math.random() - 0.5), 2 + Math.random(), (Math.random() - 0.5))
}

const spatialHash = new SpatialHash(0.15)
function optimizedStep() {
  spatialHash.clear()
  sph.particles.forEach((p, i) => spatialHash.insert(p, i))
  for (const pi of sph.particles) {
    pi.density = 0
    for (const j of spatialHash.getNeighbors(pi)) {
      const pj = sph.particles[j]
      if (pi !== pj) {
        pi.density += sph.particleMass * sph.poly6Kernel(
          pi.position.clone().sub(pj.position), sph.smoothingRadius
        )
      }
    }
    pi.pressure = sph.stiffness * (pi.density - sph.restDensity)
  }
  sph.computeForces()
  sph.integrate()
}
```

**要点**：空间哈希的 cellSize 应等于 smoothingRadius；容器边界条件在 integrate 中处理。

### 练习二

**思路**：维护粒子环形缓冲区，鼠标点击时在对应 3D 位置生成新粒子，spawnAccumulator 控制生成速率。

**答案**：

```javascript
const maxParticles = 1000
const sph = new SPHSimulation({ timeStep: 0.003 })
const raycaster = new THREE.Raycaster()
const mouse = new THREE.Vector2()
for (let i = 0; i < maxParticles; i++) sph.addParticle(0, -10, 0)

let nextIndex = 0, isSpawning = false
const spawnPos = new THREE.Vector3()

renderer.domElement.addEventListener('pointerdown', (e) => {
  mouse.x = (e.clientX / innerWidth) * 2 - 1
  mouse.y = -(e.clientY / innerHeight) * 2 + 1
  raycaster.setFromCamera(mouse, camera)
  const hit = raycaster.intersectObject(groundMesh)[0]
  if (hit) {
    spawnPos.copy(hit.point).add(new THREE.Vector3(0, 3, 0))
    isSpawning = true
  }
})
renderer.domElement.addEventListener('pointerup', () => { isSpawning = false })

let spawnAcc = 0
function animate() {
  requestAnimationFrame(animate)
  if (isSpawning) {
    spawnAcc += clock.getDelta() * 50
    while (spawnAcc >= 1) {
      const p = sph.particles[nextIndex % maxParticles]
      p.position.copy(spawnPos).add(
        new THREE.Vector3((Math.random() - 0.5) * 0.2, 0, (Math.random() - 0.5) * 0.2)
      )
      p.velocity.set(0, 0, 0)
      p.acceleration.set(0, 0, 0)
      nextIndex++
      spawnAcc--
    }
  }
  optimizedStep()
  renderParticles(sph)
  renderer.render(scene, camera)
}
animate()
```

**要点**：环形缓冲区实现粒子复用，避免内存无限增长；spawnAccumulator 控制生成速率与帧率解耦。

### 练习三

**思路**：在渲染循环中读取每个粒子的密度值，映射到 HSL 色相（蓝色 240° → 红色 0°），然后设置到 InstancedMesh 的颜色属性。

**答案**：

```javascript
// 创建带颜色支持的 InstancedMesh
const instancedMesh = new THREE.InstancedMesh(
  new THREE.SphereGeometry(0.02, 8, 8),
  new THREE.MeshStandardMaterial({ vertexColors: true, metalness: 0.2, roughness: 0.5 }),
  2000
)
scene.add(instancedMesh)

const color = new THREE.Color()
const dummy = new THREE.Object3D()

function renderWithDensity(sph) {
  // 找出密度范围用于归一化
  let minDensity = Infinity, maxDensity = -Infinity
  for (const p of sph.particles) {
    minDensity = Math.min(minDensity, p.density)
    maxDensity = Math.max(maxDensity, p.density)
  }
  const densityRange = maxDensity - minDensity || 1

  for (let i = 0; i < sph.particles.length; i++) {
    const p = sph.particles[i]
    dummy.position.copy(p.position)
    dummy.updateMatrix()
    instancedMesh.setMatrixAt(i, dummy.matrix)

    // 密度映射到色相：低密度=蓝色(240°)，高密度=红色(0°)
    const t = (p.density - minDensity) / densityRange
    const hue = (1 - t) * 0.667  // 0.667 = 240/360（蓝色）
    color.setHSL(hue, 0.8, 0.5)
    instancedMesh.setColorAt(i, color)
  }
  instancedMesh.instanceMatrix.needsUpdate = true
  instancedMesh.instanceColor.needsUpdate = true
}
```

**要点**：HSL 色彩空间的色相从 0（红）到 0.667（蓝）线性映射密度；需要每帧更新 instanceColor。

### 练习四

**思路**：为水和油分别创建 SPH 粒子，初始位置分左右两侧。隔板移除后，两种粒子因密度差异产生自然分层——油（密度 800）会浮在水（密度 1000）上面。

**答案**：

```javascript
const sph = new SPHSimulation({
  restDensity: 900,  // 取两种流体密度的平均值
  stiffness: 2000,
  viscosity: 150,
  smoothingRadius: 0.12,
  timeStep: 0.002
})

// 创建带类型的粒子
class TypedParticle extends SPHParticle {
  constructor(x, y, z, type) {
    super(x, y, z)
    this.type = type  // 0 = 水，1 = 油
    this.localRestDensity = type === 0 ? 1000 : 800
    this.localViscosity = type === 0 ? 100 : 500
  }
}

// 水粒子在左侧
for (let i = 0; i < 50; i++) {
  const p = new TypedParticle(
    -1 + Math.random() * 0.5,
    Math.random() * 2,
    (Math.random() - 0.5),
    0
  )
  sph.particles.push(p)
}

// 油粒子在右侧
for (let i = 0; i < 50; i++) {
  const p = new TypedParticle(
    0.5 + Math.random() * 0.5,
    Math.random() * 2,
    (Math.random() - 0.5),
    1
  )
  sph.particles.push(p)
}

// 渲染时根据类型着色
function renderMultiFluid(sph) {
  for (let i = 0; i < sph.particles.length; i++) {
    const p = sph.particles[i]
    dummy.position.copy(p.position)
    dummy.updateMatrix()
    instancedMesh.setMatrixAt(i, dummy.matrix)

    // 水=蓝色，油=金黄色
    const color = p.type === 0 ? 0x3498db : 0xf39c12
    instancedMesh.setColorAt(i, new THREE.Color(color))
  }
  instancedMesh.instanceMatrix.needsUpdate = true
  instancedMesh.instanceColor.needsUpdate = true
}
```

**要点**：油水混合的关键是为每种流体设置不同的 restDensity 和 viscosity。密度差导致浮力分层，粘度差导致流动速度不同。
