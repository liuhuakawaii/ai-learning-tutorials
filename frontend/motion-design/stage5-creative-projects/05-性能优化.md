# 第五课：动画性能优化

## 场景引入

你精心设计了 200 个粒子的流动场动画，开发机上流畅运行。但手机上直接卡成幻灯片，桌面端运行几分钟后内存飙升、风扇狂转——你遇到了动画性能问题。

60fps 意味着每帧只有 16.67ms 预算。浏览器需要执行 JavaScript、计算样式、布局、绘制、合成——任何环节超时都会掉帧。

## 学习目标

1. 理解浏览器渲染管线的完整流程与性能瓶颈
2. 掌握 GPU 加速的原理与正确使用方式
3. 学会使用 Performance DevTools 定位性能问题
4. 能够为动画实现自适应降级策略
5. 掌握内存泄漏检测与 Web Worker 性能分离技巧

## 浏览器渲染管线

### 完整流程

浏览器渲染一帧的完整流程如下：

```
用户输入 / requestAnimationFrame / setTimeout 等触发
    │
    ▼
┌─────────────────────────────────────────────────────┐
│  1. JavaScript 执行                                  │
│     - 动画逻辑计算                                    │
│     - DOM 读写操作                                    │
│     - 样式修改（element.style.xxx = yyy）             │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│  2. Style（样式计算）                                 │
│     - 将 CSS 规则匹配到 DOM 节点                      │
│     - 计算每个元素的最终样式（层叠、继承、特异性）       │
│     - 输出：ComputedStyle 对象                        │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│  3. Layout（重排）                                    │
│     - 计算元素的几何信息（位置、尺寸）                  │
│     - 盒模型计算：margin → border → padding → content │
│     - 输出：每个元素的 x, y, width, height             │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│  4. Paint（重绘）                                     │
│     - 将元素绘制到多个合成层的位图上                    │
│     - 绘制顺序：background → border → text → shadow   │
│     - 输出：多个合成层的像素位图                       │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│  5. Composite（合成）                                 │
│     - GPU 将多个合成层按正确顺序叠加                   │
│     - 处理层的变换（transform、opacity）               │
│     - 输出：最终屏幕画面                              │
└─────────────────────────────────────────────────────┘
```

### 各阶段耗时对比

```
操作类型          | 触发阶段              | 相对耗时
──────────────────────────────────────────────────
transform        | Composite only        | 1x（最快）
opacity          | Composite only        | 1x
filter           | Composite + Paint     | 2-3x
color/background | Paint                 | 3-5x
width/height     | Layout + Paint + Comp | 5-10x（最慢）
box-shadow       | Paint                 | 4-8x
```

### 关键概念：合成层

当元素满足以下条件之一时，浏览器会为其创建独立的合成层：

1. 有 3D `transform`（`translateZ`、`rotate3d` 等）
2. 使用了 `will-change: transform` 或 `opacity`
3. 有 CSS `animation` 或 `transition` 且动画 `transform`/`opacity`
4. 是 `<video>`、`<canvas>`、`<iframe>` 等元素
5. 有 `position: fixed`

合成层的元素在 Paint 阶段单独绘制到位图，Composite 阶段由 GPU 合成——这意味着后续修改 `transform` 和 `opacity` 不会触发 Layout 和 Paint。

核心原则：**尽量只触发 Composite，避免 Layout 和 Paint。**

## 哪些 CSS 属性触发 Layout

```javascript
// 触发 Layout（最慢）
element.style.width = "200px";
element.style.left = "100px";
element.style.padding = "10px";
element.style.fontSize = "16px";

// 触发 Paint（中等）
element.style.backgroundColor = "red";
element.style.boxShadow = "0 2px 8px rgba(0,0,0,0.3)";
element.style.borderRadius = "8px";

// 只触发 Composite（最快）
element.style.transform = "translateX(100px)";
element.style.opacity = "0.5";
```

GSAP 默认使用 `transform` 和 `opacity`，这正是它性能优秀的原因。

## GPU 加速与 `will-change`

```javascript
// 动态添加和移除 will-change
function animateIn(element) {
  element.style.willChange = "transform, opacity";
  gsap.from(element, {
    y: 50, opacity: 0, duration: 0.6,
    onComplete: () => { element.style.willChange = "auto"; },
  });
}
```

`will-change` 只对即将动画的元素添加，动画结束后移除。过多合成层反而消耗 GPU 显存。

## Layout Thrashing

```javascript
// 错误：读写交替强制反复重排
boxes.forEach(box => {
  const height = box.offsetHeight; // 读：强制重排
  box.style.height = height * 2 + "px"; // 写
  const width = box.offsetWidth; // 读：再次重排
  box.style.width = width * 1.5 + "px";
});

// 正确：先批量读取，再批量修改
const measurements = Array.from(boxes).map(box => ({
  height: box.offsetHeight, width: box.offsetWidth,
}));
boxes.forEach((box, i) => {
  box.style.height = measurements[i].height * 2 + "px";
  box.style.width = measurements[i].width * 1.5 + "px";
});
```

## Canvas 性能优化

### 批量绘制

```javascript
// 低效：每个粒子一次绘制调用
particles.forEach(p => {
  ctx.beginPath();
  ctx.arc(p.x, p.y, p.radius, 0, Math.PI * 2);
  ctx.fillStyle = p.color;
  ctx.fill();
});

// 高效：批量绘制相同颜色的粒子
function drawParticlesBatched(particles) {
  const groups = {};
  particles.forEach(p => {
    if (!groups[p.color]) groups[p.color] = [];
    groups[p.color].push(p);
  });
  Object.entries(groups).forEach(([color, group]) => {
    ctx.fillStyle = color;
    ctx.beginPath();
    group.forEach(p => {
      ctx.moveTo(p.x + p.radius, p.y);
      ctx.arc(p.x, p.y, p.radius, 0, Math.PI * 2);
    });
    ctx.fill();
  });
}
```

### 避免不必要的状态切换

```javascript
// 低效：频繁切换 fillStyle
particles.forEach(p => {
  ctx.fillStyle = p.color;
  ctx.fillRect(p.x, p.y, 3, 3);
});

// 高效：按颜色分组后批量绘制
function drawGrouped(particles) {
  const colorMap = new Map();
  for (const p of particles) {
    if (!colorMap.has(p.color)) colorMap.set(p.color, []);
    colorMap.get(p.color).push(p);
  }
  for (const [color, group] of colorMap) {
    ctx.fillStyle = color;
    for (const p of group) {
      ctx.fillRect(p.x, p.y, 3, 3);
    }
  }
}
```

### 使用 `Path2D` 复用路径

```javascript
// 预定义形状路径，避免每帧重建
const starPath = new Path2D();
const spikes = 5, outerR = 10, innerR = 5;
for (let i = 0; i < spikes * 2; i++) {
  const r = i % 2 === 0 ? outerR : innerR;
  const angle = (Math.PI / spikes) * i - Math.PI / 2;
  const method = i === 0 ? "moveTo" : "lineTo";
  starPath[method](Math.cos(angle) * r, Math.sin(angle) * r);
}
starPath.closePath();

function drawStars(stars) {
  ctx.fillStyle = "#FFD700";
  for (const s of stars) {
    ctx.save();
    ctx.translate(s.x, s.y);
    ctx.rotate(s.rotation);
    ctx.fill(starPath);
    ctx.restore();
  }
}
```

## 自适应降级策略

```javascript
class AdaptiveRenderer {
  constructor() {
    this.quality = 1;
    this.particleCount = 300;
    this.frameTimes = [];
  }

  measureFPS() {
    const now = performance.now();
    this.frameTimes.push(now);
    if (this.frameTimes.length > 60) this.frameTimes.shift();
    if (this.frameTimes.length > 1) {
      const fps = (this.frameTimes.length / (now - this.frameTimes[0])) * 1000;
      if (fps < 30 && this.quality > 0.5) {
        this.quality -= 0.25;
        this.particleCount = Math.floor(this.particleCount * 0.7);
      } else if (fps > 55 && this.quality < 1) {
        this.quality += 0.25;
        this.particleCount = Math.min(300, Math.floor(this.particleCount * 1.3));
      }
    }
  }
}
```

```javascript
function setupVisibilityPause(canvas, animateFn) {
  let running = false;
  const observer = new IntersectionObserver(entries => {
    entries.forEach(entry => {
      if (entry.isIntersecting && !running) { running = true; animateFn(); }
      else if (!entry.isIntersecting) { running = false; }
    });
  }, { threshold: 0.1 });
  observer.observe(canvas);
}
```

## 内存分析与泄漏检测

### 动画中的常见内存泄漏源

动画场景尤其容易产生内存泄漏，因为动画循环会持续创建和积累对象。以下是典型泄漏模式：

```javascript
// 泄漏一：闭包持有 DOM 引用
function setupAnimation() {
  const canvas = document.getElementById("canvas");
  const particles = [];
  // animate 闭包持有 canvas 和 particles 的引用
  // 即使 canvas 从 DOM 移除，闭包仍然阻止 GC 回收
  function animate() {
    requestAnimationFrame(animate);
    // ... 使用 canvas 和 particles
  }
  animate();
}

// 修复：提供清理机制
function setupAnimation() {
  const canvas = document.getElementById("canvas");
  const particles = [];
  let rafId = null;

  function animate() {
    rafId = requestAnimationFrame(animate);
  }
  animate();

  return {
    destroy() {
      cancelAnimationFrame(rafId);
      particles.length = 0;
      rafId = null;
    },
  };
}
```

```javascript
// 泄漏二：事件监听器未清理
function bindResize(canvas, renderer) {
  window.addEventListener("resize", () => {
    canvas.width = window.innerWidth;
    canvas.height = window.innerHeight;
    renderer.resize(canvas.width, canvas.height);
  });
  // 移除 canvas 后，resize 监听器仍然持有 renderer 引用
}

// 修复：返回清理函数
function bindResize(canvas, renderer) {
  const handler = () => {
    canvas.width = window.innerWidth;
    canvas.height = window.innerHeight;
    renderer.resize(canvas.width, canvas.height);
  };
  window.addEventListener("resize", handler);
  return () => window.removeEventListener("resize", handler);
}
```

```javascript
// 泄漏三：对象池无限增长
class ParticlePool {
  constructor() {
    this.pool = [];
    this.active = [];
  }

  acquire() {
    // 错误：不断创建新对象但从不回收
    const p = { x: 0, y: 0, vx: 0, vy: 0 };
    this.active.push(p);
    return p;
  }

  release(p) {
    const idx = this.active.indexOf(p);
    if (idx !== -1) {
      this.active.splice(idx, 1);
      this.pool.push(p); // 回收到池中
    }
  }
}
```

### Chrome DevTools 内存分析流程

```
1. 打开 DevTools → Memory 面板
2. 选择 "Heap snapshot" → 点击 "Take snapshot"（快照 A）
3. 执行动画一段时间（触发泄漏场景）
4. 再次 "Take snapshot"（快照 B）
5. 在快照 B 的视图中选择 "Comparison" 模式，对比快照 A
6. 按 "#Delta" 列排序，找出对象数量持续增长的类型
7. 展开对象 → 在 "Object" 面板查看 "Retained by"（被谁持有）
8. 根据引用链定位泄漏的闭包或事件监听器
```

### 自动化内存泄漏检测

```javascript
class MemoryMonitor {
  constructor() {
    this.snapshots = [];
    this.interval = null;
  }

  start(intervalMs = 5000) {
    if (!performance.memory) {
      console.warn("performance.memory 不可用，需要 Chrome 启动参数 --enable-precise-memory-info");
      return;
    }
    this.interval = setInterval(() => {
      const { usedJSHeapSize, totalJSHeapSize, jsHeapSizeLimit } = performance.memory;
      this.snapshots.push({
        time: Date.now(),
        used: usedJSHeapSize,
        total: totalJSHeapSize,
        limit: jsHeapSizeLimit,
      });
      if (this.snapshots.length >= 3) {
        const first = this.snapshots[this.snapshots.length - 3];
        const last = this.snapshots[this.snapshots.length - 1];
        const growthRate = (last.used - first.used) / (last.time - first.time);
        if (growthRate > 1000) { // 每秒增长超过 1MB
          console.warn(`内存泄漏疑似：增长速率 ${(growthRate / 1024).toFixed(1)} KB/s`);
        }
      }
    }, intervalMs);
  }

  stop() {
    clearInterval(this.interval);
    this.interval = null;
  }

  report() {
    if (this.snapshots.length < 2) return null;
    const first = this.snapshots[0];
    const last = this.snapshots[this.snapshots.length - 1];
    return {
      duration: ((last.time - first.time) / 1000).toFixed(1) + "s",
      heapGrowth: ((last.used - first.used) / 1024 / 1024).toFixed(2) + " MB",
      currentHeap: (last.used / 1024 / 1024).toFixed(2) + " MB",
    };
  }
}
```

## Web Workers 与动画计算分离

### 为什么需要 Worker

动画逻辑中大量数学计算（粒子碰撞检测、物理模拟、噪声生成）会阻塞主线程，导致 UI 线程无法响应用户交互。Web Worker 可以将计算密集型任务移到后台线程。

### 基本架构

```
┌─────────────────────┐         ┌─────────────────────┐
│     主线程 (UI)       │         │    Worker 线程       │
│                     │         │                     │
│  Canvas 渲染         │  postMessage  物理计算         │
│  用户交互处理        │ ◄─────►  粒子更新             │
│  DOM 操作            │         │ 碰撞检测             │
│                     │         │ 噪声生成             │
└─────────────────────┘         └─────────────────────┘
         │                              │
         │  requestAnimationFrame       │  计算完成后
         │  读取最新粒子数据             │  发送新位置
         │  绘制到 Canvas               │
```

### Worker 实现粒子物理计算

```javascript
// particle-worker.js
const PARTICLE_COUNT = 1000;
const particles = new Float32Array(PARTICLE_COUNT * 4); // x, y, vx, vy

for (let i = 0; i < PARTICLE_COUNT; i++) {
  particles[i * 4] = Math.random() * 800;     // x
  particles[i * 4 + 1] = Math.random() * 600;  // y
  particles[i * 4 + 2] = (Math.random() - 0.5) * 4; // vx
  particles[i * 4 + 3] = (Math.random() - 0.5) * 4; // vy
}

let width = 800, height = 600;

self.onmessage = (e) => {
  if (e.data.type === "resize") {
    width = e.data.width;
    height = e.data.height;
    return;
  }

  const dt = e.data.dt || 16.67;
  const gravity = e.data.gravity || 0;

  for (let i = 0; i < PARTICLE_COUNT; i++) {
    const idx = i * 4;
    particles[idx + 3] += gravity * dt / 1000; // vy += gravity
    particles[idx] += particles[idx + 2];       // x += vx
    particles[idx + 1] += particles[idx + 3];   // y += vy

    // 边界反弹
    if (particles[idx] < 0 || particles[idx] > width) {
      particles[idx + 2] *= -0.9;
      particles[idx] = Math.max(0, Math.min(width, particles[idx]));
    }
    if (particles[idx + 1] < 0 || particles[idx + 1] > height) {
      particles[idx + 3] *= -0.9;
      particles[idx + 1] = Math.max(0, Math.min(height, particles[idx + 1]));
    }
  }

  // 使用 Transferable 避免拷贝
  const buffer = particles.buffer.slice(0);
  self.postMessage({ type: "frame", positions: buffer }, [buffer]);
};
```

### 主线程接收并渲染

```javascript
// 主线程
const worker = new Worker("particle-worker.js");
const canvas = document.getElementById("canvas");
const ctx = canvas.getContext("2d");
let currentPositions = null;

worker.onmessage = (e) => {
  if (e.data.type === "frame") {
    currentPositions = new Float32Array(e.data.positions);
  }
};

worker.postMessage({ type: "resize", width: canvas.width, height: canvas.height });

function animate() {
  requestAnimationFrame(animate);
  worker.postMessage({
    type: "update",
    dt: 16.67,
    gravity: 0.5,
  });

  if (!currentPositions) return;
  ctx.fillStyle = "rgba(0, 0, 0, 0.1)";
  ctx.fillRect(0, 0, canvas.width, canvas.height);
  ctx.fillStyle = "#4F46E5";

  const count = currentPositions.length / 4;
  for (let i = 0; i < count; i++) {
    ctx.fillRect(currentPositions[i * 4], currentPositions[i * 4 + 1], 3, 3);
  }
}
animate();
```

### 动画专项 Lighthouse 审计

Lighthouse 内置审计项中，以下与动画性能最相关：

- **Total Blocking Time (TBT)**：主线程被长任务阻塞的时间，直接影响动画流畅度
- **Cumulative Layout Shift (CLS)**：布局偏移，动画元素若触发布局会导致 CLS 值升高
- **Bootup Time**：JS 执行时间，包含动画初始化开销

对于动画密集型页面，建议在 Lighthouse 之外额外用 Puppeteer 跑帧率检测：

```javascript
const puppeteer = require("puppeteer");

async function measureAnimationFPS(url) {
  const browser = await puppeteer.launch();
  const page = await browser.newPage();
  await page.setViewport({ width: 1280, height: 720 });
  await page.goto(url);

  const metrics = await page.evaluate(async () => {
    return new Promise((resolve) => {
      const frames = [];
      let lastTime = performance.now();

      function measure() {
        const now = performance.now();
        frames.push(now - lastTime);
        lastTime = now;
        if (frames.length < 120) {
          requestAnimationFrame(measure);
        } else {
          const fps = 1000 / (frames.reduce((a, b) => a + b) / frames.length);
          const jank = frames.filter(t => t > 20).length;
          resolve({ fps: fps.toFixed(1), jankFrames: jank, totalFrames: frames.length });
        }
      }
      requestAnimationFrame(measure);
    });
  });

  console.log(`FPS: ${metrics.fps}, 卡顿帧: ${metrics.jankFrames}/${metrics.totalFrames}`);
  await browser.close();
  return metrics;
}
```

### 着色器编译缓存

WebGL 着色器编译是昂贵操作，应在初始化时完成，避免运行时重编译：

```javascript
class ShaderCache {
  constructor(gl) {
    this.gl = gl;
    this.cache = new Map();
  }

  compile(vertexSrc, fragmentSrc) {
    const key = vertexSrc + "\0" + fragmentSrc;
    if (this.cache.has(key)) return this.cache.get(key);

    const gl = this.gl;
    const vs = gl.createShader(gl.VERTEX_SHADER);
    gl.shaderSource(vs, vertexSrc);
    gl.compileShader(vs);
    if (!gl.getShaderParameter(vs, gl.COMPILE_STATUS)) {
      console.error("Vertex shader error:", gl.getShaderInfoLog(vs));
      gl.deleteShader(vs);
      return null;
    }

    const fs = gl.createShader(gl.FRAGMENT_SHADER);
    gl.shaderSource(fs, fragmentSrc);
    gl.compileShader(fs);
    if (!gl.getShaderParameter(fs, gl.COMPILE_STATUS)) {
      console.error("Fragment shader error:", gl.getShaderInfoLog(fs));
      gl.deleteShader(vs);
      gl.deleteShader(fs);
      return null;
    }

    const program = gl.createProgram();
    gl.attachShader(program, vs);
    gl.attachShader(program, fs);
    gl.linkProgram(program);
    if (!gl.getProgramParameter(program, gl.LINK_STATUS)) {
      console.error("Program link error:", gl.getProgramInfoLog(program));
      return null;
    }

    gl.deleteShader(vs);
    gl.deleteShader(fs);
    this.cache.set(key, program);
    return program;
  }
}
```

### 减少 `drawArrays`/`drawElements` 调用

每次 `drawArrays` 都是一次 GPU 提交，大量小批次调用是 WebGL 性能杀手：

```javascript
// 低效：每个粒子一次 drawArrays
particles.forEach(p => {
  gl.uniform2f(uPosition, p.x, p.y);
  gl.drawArrays(gl.TRIANGLES, 0, 6); // 每粒子一次提交

// 高效：合并到单次绘制
function buildParticleBuffer(particles) {
  const vertices = new Float32Array(particles.length * 12); // 2 三角形 × 3 顶点 × 2 坐标
  const colors = new Float32Array(particles.length * 24);   // 每顶点 4 分量 RGBA

  particles.forEach((p, i) => {
    const x = p.x, y = p.y, s = p.size;
    const vi = i * 12;
    // 两个三角形组成一个矩形
    vertices[vi]     = x - s; vertices[vi + 1]  = y - s;
    vertices[vi + 2] = x + s; vertices[vi + 3]  = y - s;
    vertices[vi + 4] = x - s; vertices[vi + 5]  = y + s;
    vertices[vi + 6] = x + s; vertices[vi + 7]  = y - s;
    vertices[vi + 8] = x + s; vertices[vi + 9]  = y + s;
    vertices[vi + 10] = x - s; vertices[vi + 11] = y + s;

    const ci = i * 24;
    for (let v = 0; v < 6; v++) {
      colors[ci + v * 4]     = p.r;
      colors[ci + v * 4 + 1] = p.g;
      colors[ci + v * 4 + 2] = p.b;
      colors[ci + v * 4 + 3] = 1.0;
    }
  });

  return { vertices, colors };
}

// 一次 drawArrays 绘制所有粒子
function drawAllParticles(gl, program, particles) {
  gl.useProgram(program);
  const { vertices, colors } = buildParticleBuffer(particles);

  const vbo = gl.createBuffer();
  gl.bindBuffer(gl.ARRAY_BUFFER, vbo);
  gl.bufferData(gl.ARRAY_BUFFER, vertices, gl.DYNAMIC_DRAW);
  gl.enableVertexAttribArray(aPosition);
  gl.vertexAttribPointer(aPosition, 2, gl.FLOAT, false, 0, 0);

  const cbo = gl.createBuffer();
  gl.bindBuffer(gl.ARRAY_BUFFER, cbo);
  gl.bufferData(gl.ARRAY_BUFFER, colors, gl.DYNAMIC_DRAW);
  gl.enableVertexAttribArray(aColor);
  gl.vertexAttribPointer(aColor, 4, gl.FLOAT, false, 0, 0);

  gl.drawArrays(gl.TRIANGLES, 0, particles.length * 6); // 单次调用
  gl.deleteBuffer(vbo);
  gl.deleteBuffer(cbo);
```

### 使用实例化渲染（Instanced Rendering）

对于大量相同几何体（如粒子是相同大小的四边形），实例化渲染效率最高：

```javascript
// 顶点着色器（使用实例化属性）
const vertexShader = `
  attribute vec2 aQuadVertex;     // 四边形顶点（4 个顶点）
  attribute vec2 aInstanceOffset; // 每实例位置
  attribute vec4 aInstanceColor;  // 每实例颜色
  varying vec4 vColor;
  uniform vec2 uResolution;

  void main() {
    vec2 pos = (aInstanceOffset + aQuadVertex) / uResolution * 2.0 - 1.0;
    pos.y *= -1.0;
    gl_Position = vec4(pos, 0.0, 1.0);
    vColor = aInstanceColor;

function setupInstancedRendering(gl, program) {
  // 四边形顶点（4 个点，组成 2 个三角形）
```

## 常见误区

**误区一：过度使用 `will-change`。** 给所有元素加 `will-change: transform` 消耗 GPU 显存。只在动画即将开始时添加，结束后立即移除。

**误区二：用 `setInterval` 代替 `requestAnimationFrame`。** `setInterval` 不与屏幕刷新率同步，可能在一帧内触发多次回调，浪费计算资源且导致视觉撕裂。

**误区三：动画循环中创建对象。** 每帧 `new Array()`、`{}` 或箭头函数都会产生临时对象，频繁触发垃圾回收（GC），导致周期性卡顿。应预分配对象并在循环中复用。

**误区四：忽略移动端热节流。** 手机温度过高时降低 CPU/GPU 频率，动画会变卡。需要更激进的降级策略和更低的粒子数上限。

**误区五：Canvas 2D 和 WebGL 混用。** 反复切换上下文会导致上下文丢失（context lost），所有 GPU 资源需要重建。

**误区六：在 `requestAnimationFrame` 回调中发起网络请求或读取大量数据。** RAF 回调的执行时间直接占用帧预算，异步操作应在帧外预加载。

**误区七：忽略 `transform-origin` 对合成层的影响。** 修改 `transform-origin` 可能触发重排，应在动画开始前设置好。

**误区八：使用 `getBoundingClientRect()` 进行碰撞检测。** 每次调用都可能触发重排，在动画循环中用简单的坐标计算替代。

## 工程建议

1. **建立性能预算。** 目标 60fps，JS 执行上限 10ms，留 6ms 给浏览器。将帧率监控集成到开发环境，超预算时自动告警。

2. **用 RAF 时间戳做帧率无关动画。** 不假设每帧 16.67ms。用 `deltaTime` 计算运动量，确保不同刷新率设备上动画速度一致。

3. **Canvas 用 OffscreenCanvas + Web Worker。** 渲染逻辑移到 Worker 线程，主线程只处理用户交互和 DOM 更新。

4. **CSS 动画优先于 JS 动画。** 纯 CSS 动画由合成器处理，不占主线程。适用于简单的进入/退出/循环动画。

5. **CI 中集成性能测试。** Lighthouse CI 检测性能回归，配合 Puppeteer 自定义帧率断言，防止动画性能退化。

6. **使用 TypedArray 管理大量粒子数据。** `Float32Array` 比普通数组内存连续，GC 压力小，且可直接传递给 Worker 和 WebGL。

7. **Canvas 绘制前调用 `beginPath()`。** 不调用会导致路径累积，`stroke()` 或 `fill()` 时绘制所有历史路径，帧率急剧下降。

8. **WebGL 中使用 `requestAnimationFrame` 而非自循环。** WebGL 的 `drawArrays` 同样受帧率约束，自循环会绕过浏览器的帧调度机制。

## 小结

动画性能优化的核心是理解渲染管线，尽量只触发 Composite。GPU 加速通过合成层实现，但合成层有成本。Canvas 优化关键是减少绘制调用和使用离屏缓存。自适应降级确保各种设备都有可接受表现。内存管理需要主动监控泄漏，Web Worker 可以将计算密集型动画逻辑从主线程剥离。WebGL 场景下，着色器缓存、实例化渲染和纹理图集是关键优化手段。

**思路**：每 60 帧计算平均 FPS，根据阈值动态调整粒子数。用对象池管理粒子。

**答案**：
```javascript
let fps = 60, frameCount = 0, lastTime = performance.now();
const frameTimes = [];
const pool = Array.from({ length: 600 }, () => ({
  x: 0, y: 0, vx: 0, vy: 0, active: false,
}));

function activate(p) {
  p.x = Math.random() * canvas.width;
  p.y = Math.random() * canvas.height;
  p.vx = (Math.random() - 0.5) * 2;
  p.vy = (Math.random() - 0.5) * 2;
  p.active = true;
}

function adjustParticles() {
  const activeCount = pool.filter(p => p.active).length;
  let target = activeCount;
  if (fps < 45) target = Math.max(50, Math.floor(activeCount * 0.8));
  else if (fps > 55) target = Math.min(500, Math.floor(activeCount * 1.1));

  while (pool.filter(p => p.active).length < target) {
    const p = pool.find(p => !p.active);
    if (p) activate(p);
  }
  pool.filter(p => p.active).slice(target).forEach(p => { p.active = false; });
}

function animate() {
  requestAnimationFrame(animate);
  const now = performance.now();
  frameTimes.push(now - lastTime);
  lastTime = now; frameCount++;
  if (frameCount % 60 === 0) {
    fps = 1000 / (frameTimes.reduce((a, b) => a + b) / frameTimes.length);
    frameTimes.length = 0;
    adjustParticles();
    document.querySelector("#info").textContent =
      `FPS: ${fps.toFixed(0)} | 粒子: ${pool.filter(p => p.active).length}`;
  }
  ctx.fillStyle = "rgba(0, 0, 0, 0.1)";
  ctx.fillRect(0, 0, canvas.width, canvas.height);
  pool.filter(p => p.active).forEach(p => {
    p.x += p.vx; p.y += p.vy;
    if (p.x < 0 || p.x > canvas.width) p.vx *= -1;
    if (p.y < 0 || p.y > canvas.height) p.vy *= -1;
    ctx.fillRect(p.x, p.y, 3, 3);
  });
}
```

**要点**：对象池避免频繁创建/销毁；每 60 帧评估避免频繁调整；减少 20% 增加 10% 确保稳定。

```javascript
  const canvas = document.createElement("canvas");

  canvas.height = 600;
  container.appendChild(canvas);
  const ctx = canvas.getContext("2d");

    rafId = requestAnimationFrame(animate);
    // ... 渲染逻辑
  }
  animate();

  const resizeHandler = () => {
    canvas.width = window.innerWidth;
    canvas.height = window.innerHeight;
  };
  window.addEventListener("resize", resizeHandler);

  // 帧历史：固定大小环形缓冲区
  const MAX_HISTORY = 120;
  const frameHistory = new Array(MAX_HISTORY);
  let frameIndex = 0;

  function recordFrame(data) {
    frameHistory[frameIndex % MAX_HISTORY] = new Float32Array(data);
    frameIndex++;
  }

  return {
    canvas,
    destroy() {
      cancelAnimationFrame(rafId);
      window.removeEventListener("resize", resizeHandler);
      particles.length = 0;
      frameHistory.fill(null);
      container.removeChild(canvas);
    },
  };
}

// 自动监控脚本
function monitorHeapGrowth(durationMs = 30000) {
  if (!performance.memory) {
    console.warn("需要 --enable-precise-memory-info 启动参数");
    return;
  }
  const samples = [];
  const intervalId = setInterval(() => {
    samples.push({
      time: performance.now(),
      heap: performance.memory.usedJSHeapSize,
    });
  }, 1000);

  setTimeout(() => {
    clearInterval(intervalId);
    if (samples.length < 2) return;
    const first = samples[0], last = samples[samples.length - 1];
    const growthMB = (last.heap - first.heap) / 1024 / 1024;
    const rateKBs = ((last.heap - first.heap) / (last.time - first.time)) * 1000 / 1024;
    console.log(`堆内存变化: ${growthMB.toFixed(2)} MB`);
    console.log(`增长速率: ${rateKBs.toFixed(1)} KB/s`);
    if (rateKBs > 100) {
      console.warn("⚠️ 疑似内存泄漏！增长速率超过 100 KB/s");
    } else {
      console.log("✅ 内存增长在正常范围内");
    }
  }, durationMs);
}

monitorHeapGrowth();
```

**要点**：
- 闭包泄漏：提供 `destroy()` 方法取消 RAF 并断开引用
- 监听器泄漏：保存引用并在清理时 `removeEventListener`
- 数据增长：使用固定大小的环形缓冲区或定期清理

### 练习五

**思路**：分两步——先实现 Worker 计算 + 主线程渲染，再升级为 OffscreenCanvas 完全离线渲染。

**答案**：

**步骤一：Worker 计算 + 主线程渲染**

```javascript
// particle-physics-worker.js
const COUNT = 2000;
const state = new Float32Array(COUNT * 5); // x, y, vx, vy, radius

function init(width, height) {
  for (let i = 0; i < COUNT; i++) {
    state[i * 5]     = Math.random() * width;          // x
    state[i * 5 + 1] = Math.random() * height;         // y
    state[i * 5 + 2] = (Math.random() - 0.5) * 4;     // vx
    state[i * 5 + 3] = (Math.random() - 0.5) * 4;     // vy
    state[i * 5 + 4] = 2 + Math.random() * 3;          // radius
  }
}

let width = 800, height = 600;

self.onmessage = (e) => {
  const { type } = e.data;
  if (type === "init") {
    width = e.data.width;
    height = e.data.height;
    init(width, height);
    return;
  }

  if (type === "resize") {
    width = e.data.width;
    height = e.data.height;
    return;
  }

  if (type === "tick") {
    const dt = e.data.dt / 1000;
    for (let i = 0; i < COUNT; i++) {
      const idx = i * 5;
      state[idx]     += state[idx + 2]; // x += vx
      state[idx + 1] += state[idx + 3]; // y += vy

      // 边界反弹
      if (state[idx] < state[idx + 4]) {
        state[idx] = state[idx + 4];
        state[idx + 2] *= -0.95;
      } else if (state[idx] > width - state[idx + 4]) {
        state[idx] = width - state[idx + 4];
        state[idx + 2] *= -0.95;
      }
      if (state[idx + 1] < state[idx + 4]) {
        state[idx + 1] = state[idx + 4];
        state[idx + 3] *= -0.95;
      } else if (state[idx + 1] > height - state[idx + 4]) {
        state[idx + 1] = height - state[idx + 4];
        state[idx + 3] *= -0.95;
      }
    }
    // Transfer 避免拷贝
    const copy = state.buffer.slice(0);
    self.postMessage({ type: "state", data: copy }, [copy]);
  }
};
```

```javascript
// 主线程
const canvas = document.getElementById("canvas");
const ctx = canvas.getContext("2d");
const worker = new Worker("particle-physics-worker.js");
let latestState = null;

worker.onmessage = (e) => {
  if (e.data.type === "state") {
    latestState = new Float32Array(e.data.data);
  }
};

worker.postMessage({ type: "init", width: canvas.width, height: canvas.height });

let lastFrameTime = performance.now();
function animate() {
  requestAnimationFrame(animate);
  const now = performance.now();
  const dt = now - lastFrameTime;
  lastFrameTime = now;

  worker.postMessage({ type: "tick", dt });

  if (!latestState) return;
  ctx.clearRect(0, 0, canvas.width, canvas.height);
  ctx.fillStyle = "#6366F1";
  const count = latestState.length / 5;
  for (let i = 0; i < count; i++) {
    const idx = i * 5;
    const r = latestState[idx + 4];
    ctx.beginPath();
    ctx.arc(latestState[idx], latestState[idx + 1], r, 0, Math.PI * 2);
    ctx.fill();
  }
}
animate();
```

**步骤二：OffscreenCanvas 完全离线渲染**

```javascript
// offscreen-render-worker.js
let canvas, ctx;
const COUNT = 3000;
const state = new Float32Array(COUNT * 5);

self.onmessage = (e) => {
  if (e.data.type === "init") {
    canvas = e.data.canvas;
    ctx = canvas.getContext("2d");
    const w = canvas.width, h = canvas.height;
    for (let i = 0; i < COUNT; i++) {
      state[i * 5]     = Math.random() * w;
      state[i * 5 + 1] = Math.random() * h;
      state[i * 5 + 2] = (Math.random() - 0.5) * 3;
      state[i * 5 + 3] = (Math.random() - 0.5) * 3;
      state[i * 5 + 4] = 2 + Math.random() * 3;
    }
    loop();
  }
};

function loop() {
  requestAnimationFrame(loop);
  const w = canvas.width, h = canvas.height;

  // 物理更新
  for (let i = 0; i < COUNT; i++) {
    const idx = i * 5;
    state[idx]     += state[idx + 2];
    state[idx + 1] += state[idx + 3];
    if (state[idx] < 0 || state[idx] > w) state[idx + 2] *= -1;
    if (state[idx + 1] < 0 || state[idx + 1] > h) state[idx + 3] *= -1;
  }

  // 渲染
  ctx.fillStyle = "rgba(0, 0, 0, 0.15)";
  ctx.fillRect(0, 0, w, h);
  ctx.fillStyle = "#34D399";
  for (let i = 0; i < COUNT; i++) {
    const idx = i * 5;
    ctx.beginPath();
    ctx.arc(state[idx], state[idx + 1], state[idx + 4], 0, Math.PI * 2);
    ctx.fill();
  }
}
```

```javascript
// 主线程：仅做 Canvas 控制权转移
const canvas = document.getElementById("canvas");
const offscreen = canvas.transferControlToOffscreen();
const worker = new Worker("offscreen-render-worker.js");
worker.postMessage({ type: "init", canvas: offscreen }, [offscreen]);
// 主线程完全空闲，可处理用户交互
```

**要点**：
- Worker 中使用 `Float32Array` 连续内存，比对象数组 GC 压力小
- `transferControlToOffscreen()` 将 Canvas 控制权完全交给 Worker，主线程零渲染开销
- `postMessage` 第二个参数 `[buffer]` 使用 Transferable 避免数据拷贝
- 两步方案：第一步适合需要主线程处理交互的场景；第二步适合纯展示型动画
