# 第二课：页面过渡动画

## 场景引入

你点击作品集网站的项目卡片，卡片没有消失，而是展开铺满屏幕，图片和文字从卡片内部"流"出来——页面之间的切换不再是"跳转"，而是"流动"。

传统多页面应用切换时存在"白屏瞬间"，SPA 的路由切换也往往是内容瞬间替换。页面过渡动画的核心目标是**消除断裂感**，让用户感觉始终在同一个连贯空间中移动。

## 学习目标

1. 理解页面过渡动画的设计原理与用户体验价值
2. 掌握 Barba.js 的核心概念与使用方法
3. 学会用 GSAP 实现多种页面过渡效果
4. 能够为 SPA 应用实现路由级别的过渡动画
5. 掌握 Next.js 中基于 framer-motion 的页面过渡方案
6. 理解 SVG morphing 过渡的实现原理

## Barba.js 基础

Barba.js 通过拦截链接点击、AJAX 加载新页面、在旧页面和新页面之间执行过渡动画实现无缝切换：

```javascript
import barba from "@barba/core";
import { gsap } from "gsap";

barba.init({
  transitions: [{
    name: "fade",
    leave(data) {
      return gsap.to(data.current.container, { opacity: 0, duration: 0.4, ease: "power2.in" });
    },
    enter(data) {
      return gsap.from(data.next.container, { opacity: 0, duration: 0.4, ease: "power2.out" });
    },
  }],
});
```

### Barba.js 生命周期详解

Barba.js 的生命周期是一条完整的事件链，理解每个阶段的职责是实现复杂过渡动画的前提：

```
请求发起 → before → beforeLeave → leave → afterLeave → beforeEnter → enter → afterEnter → after
```

**各阶段职责：**

| 钩子 | 时机 | 典型用途 |
|------|------|----------|
| `before` | 过渡开始前，最早触发 | 全局守卫、权限检查、取消过渡 |
| `beforeLeave` | leave 动画执行前 | 保存滚动位置、记录离开状态 |
| `leave` | 旧页面退出动画 | 执行退出动画，返回 Promise 控制时序 |
| `afterLeave` | leave 完成后 | 清理旧页面 DOM、释放资源 |
| `beforeEnter` | enter 动画执行前 | 设置新页面初始状态、插入共享元素 |
| `enter` | 新页面进入动画 | 执行进入动画，返回 Promise 控制时序 |
| `afterEnter` | enter 完成后 | 绑定事件、初始化组件、恢复滚动 |
| `after` | 整个过渡结束 | 全局清理、移除遮罩层 |

**`data` 对象结构：**

```javascript
{
  current: {
    namespace: "home",           // 旧页面的 data-barba-namespace
    container: HTMLElement,       // 旧页面容器 DOM
    url: { href, pathname, ... } // 旧页面 URL 信息
  },
  next: {
    namespace: "work",
    container: HTMLElement,       // 新页面容器 DOM（已插入文档）
    url: { href, pathname, ... }
  },
  trigger: HTMLElement | "popstate", // 触发来源：链接元素或浏览器后退
}
```

**关键细节：**

- `leave` 中返回的 Promise 决定过渡何时进入 `afterLeave`——如果不返回 Promise，Barba 会立即进入下一阶段
- `enter` 中 `data.next.container` 已经被插入 DOM，但默认是隐藏的（`visibility: hidden`）
- 过渡期间 Barba 自动阻止新的导航请求，避免动画冲突
- 通过 `data.trigger === "popstate"` 可以判断是否为浏览器后退/前进操作

```javascript
barba.init({
  transitions: [{
    name: "lifecycle-demo",
    before(data) {
      console.log("过渡即将开始", data.current.namespace, "→", data.next.namespace);
    },
    beforeLeave(data) {
      sessionStorage.setItem("scrollPos", window.scrollY);
    },
    leave(data) {
      return gsap.to(data.current.container, { opacity: 0, y: -50, duration: 0.4 });
    },
    afterLeave(data) {
      data.current.container.remove();
    },
    beforeEnter(data) {
      gsap.set(data.next.container, { opacity: 0, y: 50 });
    },
    enter(data) {
      return gsap.to(data.next.container, { opacity: 1, y: 0, duration: 0.4, ease: "power2.out" });
    },
    afterEnter(data) {
      window.scrollTo(0, parseInt(sessionStorage.getItem("scrollPos") || 0));
    },
    after() {
      console.log("过渡完成");
    },
  }],
});
```

### 命名空间与条件过渡

Barba.js 允许通过 `namespace` 控制不同页面之间的过渡行为。在 HTML 中为容器标记 `data-barba-namespace`，然后在 transition 中用 `from` / `to` 限定生效范围：

```html
<!-- home 页面 -->
<body>
  <div data-barba="wrapper">
    <div data-barba="container" data-barba-namespace="home">
      <!-- 页面内容 -->
    </div>
  </div>
</body>
```

```javascript
barba.init({
  transitions: [
    {
      name: "home-to-work",
      from: { namespace: ["home"] },
      to: { namespace: ["work"] },
      leave(data) {
        return gsap.to(data.current.container, { scale: 0.95, opacity: 0, duration: 0.4 });
      },
      enter(data) {
        return gsap.from(data.next.container, { scale: 1.05, opacity: 0, duration: 0.5 });
      },
    },
    {
      name: "default-fade",
      leave(data) {
        return gsap.to(data.current.container, { opacity: 0, duration: 0.3 });
      },
      enter(data) {
        return gsap.from(data.next.container, { opacity: 0, duration: 0.3 });
      },
    },
  ],
});
```

Barba 按数组顺序匹配，第一个匹配的 transition 生效。把具体规则放前面、通用兜底放后面。

## 遮罩层过渡

比简单滑动更优雅的做法——遮罩层从左向右覆盖旧页面，再从右向左收缩露出新页面：

```javascript
barba.init({
  transitions: [{
    name: "mask-reveal",
    async leave(data) {
      await gsap.to(".transition-mask", {
        scaleX: 1, duration: 0.5, ease: "power3.inOut",
      });
      data.current.container.remove();
    },
    async enter(data) {
      gsap.set(data.next.container, { opacity: 1 });
      await gsap.to(".transition-mask", {
        scaleX: 0, duration: 0.5, ease: "power3.inOut",
        transformOrigin: "right center",
      });
    },
  }],
});
```

### 双层遮罩增强效果

使用两层遮罩可以制造更丰富的视觉层次——第一层纯色快速铺满，第二层带纹理或渐变随后跟进：

```html
<div class="mask-primary" style="
  position: fixed; inset: 0; background: #0a0a0a;
  transform: scaleX(0); transform-origin: left; z-index: 9998;
"></div>
<div class="mask-secondary" style="
  position: fixed; inset: 0; background: linear-gradient(135deg, #1a1a2e, #16213e);
  transform: scaleX(0); transform-origin: left; z-index: 9999;
"></div>
```

```javascript
barba.init({
  transitions: [{
    name: "double-mask",
    async leave(data) {
      const tl = gsap.timeline();
      tl.to(".mask-primary", { scaleX: 1, duration: 0.4, ease: "power3.inOut" });
      tl.to(".mask-secondary", { scaleX: 1, duration: 0.35, ease: "power3.inOut" }, "-=0.15");
      await tl;
      data.current.container.remove();
    },
    async enter(data) {
      gsap.set(data.next.container, { opacity: 1 });
      const tl = gsap.timeline();
      tl.to(".mask-secondary", { scaleX: 0, duration: 0.35, ease: "power3.inOut", transformOrigin: "right center" });
      tl.to(".mask-primary", { scaleX: 0, duration: 0.4, ease: "power3.inOut", transformOrigin: "right center" }, "-=0.15");
      await tl;
    },
  }],
});
```

## 共享元素过渡

最令人印象深刻的效果——旧页面的某个元素在新页面中仍然存在，位置、大小平滑过渡：

```javascript
barba.init({
  transitions: [{
    name: "shared-element",
    leave(data) {
      const image = data.trigger.querySelector("img");
      const rect = image.getBoundingClientRect();
      const clone = image.cloneNode(true);
      clone.style.cssText = `
        position: fixed; top: ${rect.top}px; left: ${rect.left}px;
        width: ${rect.width}px; height: ${rect.height}px;
        z-index: 1000; object-fit: cover;
      `;
      document.body.appendChild(clone);
      gsap.to(image, { opacity: 0, duration: 0.2 });
      data.current.clone = clone;
      return gsap.timeline();
    },
    enter(data) {
      const clone = data.current.clone;
      const targetImage = data.next.container.querySelector(".hero-image img");
      const targetRect = targetImage.getBoundingClientRect();
      return gsap.to(clone, {
        top: targetRect.top, left: targetRect.left,
        width: targetRect.width, height: targetRect.height,
        duration: 0.6, ease: "power2.inOut",
        onComplete: () => { clone.remove(); gsap.set(targetImage, { opacity: 1 }); },
      });
    },
  }],
});
```

### 共享元素的精确对齐

共享元素过渡最常见的问题是"跳动"——克隆元素和目标位置之间存在微小偏差。根本原因通常是滚动偏移和边距计算：

```javascript
function getAbsolutePosition(el) {
  const rect = el.getBoundingClientRect();
  return {
    top: rect.top + window.scrollY,
    left: rect.left + window.scrollX,
    width: rect.width,
    height: rect.height,
  };
}

// 在 leave 阶段用固定定位记录视口坐标
// 在 enter 阶段重新查询目标元素的视口坐标
// 因为新页面可能有不同的滚动位置，必须在 enter 时实时查询
```

**注意：** 克隆元素使用 `position: fixed`，坐标基于视口；如果页面有滚动，leave 时的坐标在 enter 时可能已失效。解决方法是 `enter` 开始时 `window.scrollTo(0, 0)` 或在 enter 中重新计算目标位置。

## Vue Router 过渡动画

```vue
<template>
  <router-view v-slot="{ Component, route }">
    <Transition mode="out-in" @before-enter="onBeforeEnter" @enter="onEnter" @leave="onLeave">
      <component :is="Component" :key="route.path" />
    </Transition>
  </router-view>
</template>

<script setup>
import { gsap } from "gsap";

function onBeforeEnter(el) { gsap.set(el, { opacity: 0, y: 30 }); }
function onEnter(el, done) {
  gsap.to(el, { opacity: 1, y: 0, duration: 0.4, ease: "power2.out", onComplete: done });
}
function onLeave(el, done) {
  gsap.to(el, { opacity: 0, y: -30, duration: 0.3, ease: "power2.in", onComplete: done });
}
</script>
```

### 基于路由元信息的方向感知

Vue Router 的 `route.meta` 可以存储页面层级，实现方向感知过渡：

```vue
<template>
  <router-view v-slot="{ Component, route }">
    <Transition
      :name="transitionName"
      mode="out-in"
      @before-enter="onBeforeEnter"
      @enter="onEnter"
      @leave="onLeave"
    >
      <component :is="Component" :key="route.path" />
    </Transition>
  </router-view>
</template>

<script setup>
import { ref, watch } from "vue";
import { useRouter } from "vue-router";
import { gsap } from "gsap";

const transitionName = ref("slide-right");
const router = useRouter();

const routeOrder = { "/": 0, "/work": 1, "/about": 2, "/contact": 3 };

watch(() => router.currentRoute.value, (to, from) => {
  const toIndex = routeOrder[to.path] ?? 0;
  const fromIndex = routeOrder[from.path] ?? 0;
  transitionName.value = toIndex > fromIndex ? "slide-left" : "slide-right";
});

function onLeave(el, done) {
  const direction = transitionName.value === "slide-left" ? -1 : 1;
  gsap.to(el, {
    x: direction * -100 + "%", opacity: 0, duration: 0.35, ease: "power2.in",
    onComplete: done,
  });
}

function onBeforeEnter(el) {
  const direction = transitionName.value === "slide-left" ? 1 : -1;
  gsap.set(el, { x: direction * 100 + "%", opacity: 0 });
}

function onEnter(el, done) {
  gsap.to(el, {
    x: 0, opacity: 1, duration: 0.4, ease: "power2.out",
    onComplete: done,
  });
}
</script>
```

## Next.js 页面过渡动画

Next.js 的 App Router 使用 React Server Components，页面过渡需要在客户端用 `framer-motion` 配合 `AnimatePresence` 实现。

### 基础布局过渡

创建一个客户端包装组件处理路由切换动画：

```tsx
// components/PageTransition.tsx
"use client";

import { motion, AnimatePresence } from "framer-motion";
import { usePathname } from "next/navigation";
import { type ReactNode } from "react";

interface PageTransitionProps {
  children: ReactNode;
}

const pageVariants = {
  initial: { opacity: 0, y: 20 },
  animate: { opacity: 1, y: 0 },
  exit: { opacity: 0, y: -20 },
};

export function PageTransition({ children }: PageTransitionProps) {
  const pathname = usePathname();

  return (
    <AnimatePresence mode="wait">
      <motion.div
        key={pathname}
        variants={pageVariants}
        initial="initial"
        animate="animate"
        exit="exit"
        transition={{ duration: 0.3, ease: "easeInOut" }}
      >
        {children}
      </motion.div>
    </AnimatePresence>
  );
}
```

在 layout 中使用：

```tsx
// app/layout.tsx
import { PageTransition } from "@/components/PageTransition";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="zh">
      <body>
        <nav>{/* 导航栏 */}</nav>
        <PageTransition>
          <main>{children}</main>
        </PageTransition>
      </body>
    </html>
  );
}
```

### 带遮罩层的 Next.js 过渡

将 GSAP 的遮罩层思路移植到 framer-motion：

```tsx
// components/MaskTransition.tsx
"use client";

import { motion, AnimatePresence } from "framer-motion";
import { usePathname } from "next/navigation";
import { type ReactNode, useState, useEffect } from "react";

export function MaskTransition({ children }: { children: ReactNode }) {
  const pathname = usePathname();
  const [displayChildren, setDisplayChildren] = useState(children);
  const [isAnimating, setIsAnimating] = useState(false);

  useEffect(() => {
    if (children !== displayChildren) {
      setIsAnimating(true);
    }
  }, [children, displayChildren]);

  return (
    <div style={{ position: "relative" }}>
      <AnimatePresence mode="wait">
        {isAnimating && (
          <motion.div
            key="mask"
            style={{
              position: "fixed",
              inset: 0,
              background: "#0a0a0a",
              zIndex: 9999,
              transformOrigin: "left",
            }}
            initial={{ scaleX: 0 }}
            animate={{ scaleX: 1 }}
            exit={{ scaleX: 0, transformOrigin: "right" }}
            transition={{ duration: 0.4, ease: [0.76, 0, 0.24, 1] }}
            onAnimationComplete={() => {
              setDisplayChildren(children);
              setIsAnimating(false);
            }}
          />
        )}
      </AnimatePresence>
      <motion.div key={pathname}>
        {displayChildren}
      </motion.div>
    </div>
  );
}
```

### 共享元素过渡（Next.js + framer-motion LayoutId）

framer-motion 的 `layoutId` 属性可以声明式地实现共享元素过渡，无需手动计算坐标：

```tsx
// components/ProjectCard.tsx
"use client";

import { motion } from "framer-motion";
import Link from "next/link";

export function ProjectCard({ id, title, imageUrl }: {
  id: string; title: string; imageUrl: string;
}) {
  return (
    <Link href={`/work/${id}`}>
      <motion.div layoutId={`card-${id}`} style={{ borderRadius: 12, overflow: "hidden" }}>
        <motion.img
          layoutId={`image-${id}`}
          src={imageUrl}
          alt={title}
          style={{ width: "100%", height: 200, objectFit: "cover" }}
        />
        <motion.h3 layoutId={`title-${id}`}>{title}</motion.h3>
      </motion.div>
    </Link>
  );
}
```

```tsx
// app/work/[id]/page.tsx
"use client";

import { motion } from "framer-motion";

export default function ProjectDetail({ params }: { params: { id: string } }) {
  return (
    <div>
      <motion.div layoutId={`card-${params.id}`}>
        <motion.img
          layoutId={`image-${params.id}`}
          style={{ width: "100%", height: "60vh", objectFit: "cover" }}
        />
        <motion.h1 layoutId={`title-${params.id}`}>项目详情</motion.h1>
      </motion.div>
      <motion.div
        initial={{ opacity: 0, y: 20 }}
        animate={{ opacity: 1, y: 0 }}
        transition={{ delay: 0.2 }}
      >
        {/* 详情内容 */}
      </motion.div>
    </div>
  );
}
```

`layoutId` 相同的元素会自动计算位置和大小差异，并生成平滑过渡动画。这比 Barba.js 的手动克隆方案简洁得多，但仅限于客户端路由。

## SVG Morphing 过渡

SVG morphing 让两个不同形状之间产生平滑的形变过渡。在页面过渡中，可以用于图标变形、路径引导动画、品牌标识切换等场景。

### 基础路径 Morphing

SVG 的 `<path>` 的 `d` 属性如果控制点数量相同，可以通过插值实现平滑变形：

```html
<svg viewBox="0 0 100 100" width="100" height="100">
  <path id="morph-path" d="M10,50 Q50,10 90,50 Q50,90 10,50" fill="#1a1a2e" />
</svg>
```

```javascript
import { gsap } from "gsap";

// 从菱形变为圆形（控制点数量必须一致）
const diamondPath = "M50,10 L90,50 L50,90 L10,50 Z";
const circlePath = "M50,10 C72,10 90,28 90,50 C90,72 72,90 50,90 C28,90 10,72 10,50 C10,28 28,10 50,10 Z";

// 直接用 CSS path() 或 GSAP 的 MorphSVGPlugin（Club GreenSock 会员功能）
// 如果不用 MorphSVGPlugin，可以用 CSS 动画：
gsap.to("#morph-path", {
  attr: { d: circlePath },
  duration: 0.8,
  ease: "power2.inOut",
});
```

**注意：** GSAP 的 `attr` 插件可以直接对 `d` 属性做数值插值，但要求两个路径的命令数量和类型一致。如果不一致，需要先用工具（如 Flubber 库）做路径标准化。

### 使用 Flubber 做路径 Morphing

Flubber 是专门处理 SVG 路径变形的库，能自动处理控制点数量不一致的情况：

```javascript
import { interpolate } from "flubber";
import { gsap } from "gsap";

const pathEl = document.getElementById("morph-path");
const circleD = "M50,10 C72,10 90,28 90,50 C90,72 72,90 50,90 C28,90 10,72 10,50 C10,28 28,10 50,10 Z";
const starD = "M50,5 L61,35 L95,35 L68,57 L79,90 L50,70 L21,90 L32,57 L5,35 L39,35 Z";

// Flubber 生成插值函数，输入 0-1 输出路径字符串
const interpolator = interpolate(circleD, starD, { maxSegmentLength: 2 });

gsap.to({ t: 0 }, {
  t: 1,
  duration: 1,
  ease: "power2.inOut",
  onUpdate() {
    pathEl.setAttribute("d", interpolator(this.targets()[0].t));
  },
});
```

### 页面过渡中的 SVG 引导动画

用 SVG 路径作为视觉引导，让内容沿着路径运动进入页面：

```javascript
barba.init({
  transitions: [{
    name: "svg-path-reveal",
    beforeEnter(data) {
      // 在新页面容器中插入 SVG 路径
      const svg = document.createElementNS("http://www.w3.org/2000/svg", "svg");
      svg.setAttribute("viewBox", "0 0 100 100");
      svg.style.cssText = "position:fixed;inset:0;width:100%;height:100%;z-index:9998;pointer-events:none;";
      const path = document.createElementNS("http://www.w3.org/2000/svg", "path");
      path.setAttribute("d", "M0,50 C30,20 70,80 100,50");
      path.setAttribute("stroke", "#0a0a0a");
      path.setAttribute("stroke-width", "120");
      path.setAttribute("fill", "none");
      path.setAttribute("stroke-dasharray", "200");
      path.setAttribute("stroke-dashoffset", "200");
      svg.appendChild(path);
      document.body.appendChild(svg);
      data.svgPath = path;
    },
    async enter(data) {
      gsap.set(data.next.container, { opacity: 0 });
      await gsap.to(data.svgPath, {
        strokeDashoffset: 0, duration: 0.6, ease: "power2.inOut",
      });
      gsap.set(data.next.container, { opacity: 1 });
      await gsap.to(data.svgPath, {
        strokeDashoffset: -200, duration: 0.5, ease: "power2.in",
      });
      data.svgPath.closest("svg").remove();
    },
  }],
});
```

## 预加载策略

页面过渡的流畅度很大程度取决于新页面资源是否就绪。如果新页面需要加载图片或数据，过渡期间会出现空白或布局跳动。

### Barba.js 内置预加载

Barba.js 提供 `prefetch` 插件，在用户 hover 链接时就开始加载目标页面：

```javascript
import barba from "@barba/core";
import barbaPrefetch from "@barba/prefetch";

barba.use(barbaPrefetch);

barba.init({
  prefetchIgnore: ["/api/*", "/admin/*"],  // 排除不需要预加载的路径
  timeout: 5000,  // 请求超时时间
  requestError(trigger, action, url, response) {
    if (action === "click" && response.status === 404) {
      window.location.href = url;  // 降级为普通跳转
    }
  },
});
```

### 资源级预加载

对于已知的大型资源（如 Hero 图片），可以用 `<link rel="preload">` 或 Intersection Observer 提前加载：

```javascript
// 在 Barba beforeEnter 中预加载关键图片
barba.init({
  transitions: [{
    name: "preload-aware",
    async beforeEnter(data) {
      const images = data.next.container.querySelectorAll("img[data-preload]");

          if (img.complete) return resolve();

          img.onerror = resolve;  // 出错也继续，不阻塞过渡

        Promise.all(promises),
        new Promise(resolve => setTimeout(resolve, 2000)),  // 最多等 2 秒
      ]);
    },
    leave(data) {
      return gsap.to(data.current.container, { opacity: 0, duration: 0.3 });

    enter(data) {
      return gsap.from(data.next.container, { opacity: 0, duration: 0.4 });
    },
  }],
});
```

### Next.js 中的预加载

Next.js 的 `<Link>` 组件默认在视口内自动预加载页面。可以进一步用 `router.prefetch()` 手动控制：

## 加载状态管理

过渡动画期间的加载状态管理是一个容易被忽视但影响用户体验的关键环节。

### 带加载指示器的过渡

当新页面数据加载较慢时，过渡动画结束后应立即显示加载状态，而不是空白页面：

```javascript
barba.init({
  transitions: [{
    name: "loading-aware",
    leave(data) {
      return gsap.to(data.current.container, { opacity: 0, duration: 0.3 });
    },
    async enter(data) {
      const container = data.next.container;
      const loadingOverlay = document.createElement("div");
      loadingOverlay.className = "page-loading";
      loadingOverlay.innerHTML = `
        <div class="loading-spinner"></div>
        <p>加载中...</p>
      `;
      loadingOverlay.style.cssText = `
        position: absolute; inset: 0; display: flex;
        flex-direction: column; align-items: center; justify-content: center;
        background: rgba(255,255,255,0.9); z-index: 10;
      `;
      container.style.position = "relative";
      container.appendChild(loadingOverlay);

      gsap.from(container, { opacity: 0, duration: 0.4 });

      // 等待页面关键资源就绪
      await waitForCriticalResources(container);

      gsap.to(loadingOverlay, {
        opacity: 0, duration: 0.3,
        onComplete: () => loadingOverlay.remove(),
      });
    },
  }],
});

async function waitForCriticalResources(container) {
  const images = container.querySelectorAll("img");
  const promises = Array.from(images)
    .filter(img => !img.complete)
    .map(img => new Promise(resolve => {
      img.onload = resolve;
      img.onerror = resolve;
    }));
  await Promise.race([
    Promise.all(promises),
    new Promise(resolve => setTimeout(resolve, 3000)),
  ]);
}
```

### 骨架屏过渡

比加载指示器更好的方案是在过渡期间展示骨架屏，让用户对页面结构有预期：

```javascript
barba.init({
  transitions: [{
    name: "skeleton-transition",
    beforeLeave(data) {
      // 为新页面生成骨架屏
      const skeleton = createSkeleton(data.next.namespace);
      data.skeleton = skeleton;
    },
    leave(data) {
      document.body.appendChild(data.skeleton);
      return gsap.to(data.current.container, { opacity: 0, duration: 0.3 });
    },
    enter(data) {
      gsap.set(data.next.container, { opacity: 0 });
      // 骨架屏淡出，新页面淡入
      return gsap.timeline()
        .to(data.skeleton, { opacity: 0, duration: 0.3, delay: 0.2 })
        .to(data.next.container, { opacity: 1, duration: 0.4 }, "-=0.1")
        .add(() => data.skeleton.remove());
    },
  }],
});

function createSkeleton(namespace) {
  const div = document.createElement("div");
  div.className = "skeleton-screen";
  div.style.cssText = "position:fixed;inset:0;z-index:9990;background:#f5f5f5;";
  div.innerHTML = `
```

## 常见误区

**误区一：过渡动画太长。** 超过 0.8 秒会让用户不耐烦。建议控制在 0.3-0.6 秒。

**误区二：忘记处理浏览器后退按钮。** 自定义过渡逻辑需考虑"后退"方向，否则动画方向会反。

**误区三：过渡期间不禁止交互。** 用户再次点击会导致动画冲突、DOM 状态混乱。

**误区四：忽略页面资源加载。** 新页面图片没加载完就开始动画会出现布局跳动。

**误区五：克隆元素忘记清理。** 共享元素过渡中创建的克隆如果未在动画结束时移除，会残留在 DOM 中造成内存泄漏和视觉遮挡。务必在 `onComplete` 中调用 `clone.remove()`。

**误区六：固定定位在滚动页面上坐标偏移。** `position: fixed` 的坐标基于视口，但 `getBoundingClientRect` 返回的也是视口坐标——如果过渡期间触发了滚动（如 `scrollTo(0, 0)`），目标元素的位置会变化。应在 enter 阶段重新查询目标位置，而非复用 leave 阶段的快照。

**误区七：`out-in` 模式下忘记设置容器高度。** Vue 的 `<Transition mode="out-in">` 会在 leave 和 enter 之间有短暂的空档期，容器高度塌陷会导致页面跳动。解决方案是在过渡容器上设置 `min-height` 或用 `position: absolute` 将离开的元素脱离文档流。

**误区八：忽略 SEO 和无障碍。** 过渡动画完全依赖 JavaScript，搜索引擎爬虫和屏幕阅读器无法感知动画状态。确保页面内容在无 JS 时仍可访问（Barba.js 的 progressive enhancement 模式），并为动画添加 `aria-live` 通知。

## 工程建议

1. **用 `position: fixed` 隔离层级。** 旧页面和新页面可能同时存在于 DOM 中。
2. **预加载目标页面。** Barba.js 支持 `prefetch`，hover 链接时就开始预加载。
3. **用 CSS `contain` 优化性能。** 对过渡容器添加 `contain: layout style`。
4. **降级方案：直接跳转。** 低端设备或网络不佳时跳过过渡动画。
5. **保持过渡方向一致性。** 同类操作使用相同过渡方向，建立用户心智模型。
6. **用 `will-change` 提示浏览器。** 在动画开始前为过渡元素添加 `will-change: transform, opacity`，动画结束后移除，让浏览器提前创建合成层。
7. **过渡动画与页面滚动位置解耦。** 在 `leave` 开始时记录滚动位置，在 `afterEnter` 中恢复，避免新页面从错误位置开始。
8. **为过渡设置超时兜底。** 如果 Promise 因网络或脚本错误永远不 resolve，Barba 会卡在过渡中间。使用 `Promise.race` 加超时机制，确保任何情况下都能完成过渡。

```javascript
// 超时兜底示例
function withTimeout(promise, ms = 3000) {
  return Promise.race([
    promise,
    new Promise((_, reject) =>
      setTimeout(() => reject(new Error("Transition timeout")), ms)
    ),
  ]).catch(() => {
    console.warn("过渡超时，强制完成");
  });
}

barba.init({
  transitions: [{
    name: "safe-transition",
    async leave(data) {
      await withTimeout(
        gsap.to(data.current.container, { opacity: 0, duration: 0.5 })
      );
    },
    async enter(data) {
      await withTimeout(
        gsap.from(data.next.container, { opacity: 0, duration: 0.5 })
      );
    },
  }],
});
```

## 小结

页面过渡动画消除页面切换的"断裂感"。Barba.js 拦截导航行为，在旧页面退出和新页面进入之间插入动画序列。GSAP 负责时间编排和缓动控制。共享元素过渡需要精确计算元素位置。Vue 的 `<Transition>` 和 Next.js 客户端 hooks 可实现路由级别过渡。SVG morphing 为过渡动画提供了形状变形的视觉维度。预加载和加载状态管理是保证过渡流畅的关键基础设施。

```javascript
import barba from "@barba/core";

barba.init({
```

### 练习二

**思路**：leave 阶段获取卡片图片位置并创建克隆；enter 阶段将克隆过渡到新页面 Hero 图片位置。

**答案**：
```javascript
barba.init({
  transitions: [{
    name: "card-expand",
    leave(data) {
      const trigger = data.trigger.closest(".project-card");
      const img = trigger.querySelector("img");
      const rect = img.getBoundingClientRect();
      const clone = img.cloneNode(true);
      clone.style.cssText = `
        position: fixed; top: ${rect.top}px; left: ${rect.left}px;
        width: ${rect.width}px; height: ${rect.height}px;
        border-radius: 12px; z-index: 1000; object-fit: cover;
      `;
      document.body.appendChild(clone);
      gsap.to([trigger, img], { opacity: 0, duration: 0.2 });
      data.clone = clone;
      return gsap.to(clone, { borderRadius: 0, duration: 0.3, ease: "power2.in" });
    },
    enter(data) {
      const clone = data.clone;
      const heroImg = data.next.container.querySelector(".hero-image");
      return gsap.to(clone, {
        top: 0, left: 0, width: "100vw", height: "60vh",
        duration: 0.6, ease: "power2.inOut",
        onComplete: () => { clone.remove(); gsap.set(heroImg, { opacity: 1 }); },
      });
    },
  }],

```

**要点**：`getBoundingClientRect` 获取精确位置；克隆用 `position: fixed` 避免受滚动影响；`border-radius` 从圆角过渡到无圆角。

### 练习三

**思路**：通过路由层级数组定义页面顺序，根据索引差值判断方向。

**答案**：
```javascript
import barba from "@barba/core";
import { gsap } from "gsap";

const routeOrder = ["/", "/work", "/about", "/contact"];

function getDirection(currentUrl, nextUrl) {
  const ci = routeOrder.indexOf(currentUrl);
  const ni = routeOrder.indexOf(nextUrl);
  return ni > ci ? "forward" : "backward";
}

barba.init({
  transitions: [{
    name: "directional",
    leave(data) {
      const dir = getDirection(
        new URL(data.current.url.href).pathname,
        new URL(data.next.url.href).pathname
      );
      return gsap.to(data.current.container, {
        x: dir === "forward" ? "-30%" : "30%",
        opacity: 0, duration: 0.4, ease: "power2.in",
      });
    },
    enter(data) {
      const dir = getDirection(
        new URL(data.current.url.href).pathname,
        new URL(data.next.url.href).pathname
      );
      return gsap.from(data.next.container, {
        x: dir === "forward" ? "30%" : "-30%",
        opacity: 0, duration: 0.4, ease: "power2.out",
      });
    },
  }],
});
```

**要点**：前进时旧页面向左退、新页面从右进；后退则相反。方向由路由层级的索引差值决定。

### 练习四

**思路**：用两个遮罩元素分别覆盖左右半屏，通过 `scaleX` 和相反的 `transformOrigin` 实现对称展开。新页面在遮罩完全打开后淡入。

**答案**：
```html
<div class="curtain-left" style="
  position: fixed; top: 0; left: 0; width: 50%; height: 100%;
  background: #0a0a0a; transform: scaleX(0); transform-origin: right;
  z-index: 9999;
"></div>
<div class="curtain-right" style="
  position: fixed; top: 0; right: 0; width: 50%; height: 100%;
  background: #0a0a0a; transform: scaleX(0); transform-origin: left;
  z-index: 9999;
"></div>
```

```javascript
import barba from "@barba/core";
import { gsap } from "gsap";

barba.init({
  transitions: [{
    name: "curtain-reveal",
    async leave(data) {
      const tl = gsap.timeline();
      tl.to(".curtain-left", {
        scaleX: 1, duration: 0.5, ease: "power3.inOut",
      });
      tl.to(".curtain-right", {
        scaleX: 1, duration: 0.5, ease: "power3.inOut",
      }, "<");  // 与左侧同时开始
      await tl;
      data.current.container.remove();
    },
    async enter(data) {
      gsap.set(data.next.container, { opacity: 0 });

      // 窗帘打开
      const tl = gsap.timeline();
      tl.to(".curtain-left", {
        scaleX: 0, duration: 0.5, ease: "power3.inOut", transformOrigin: "left",
      });
      tl.to(".curtain-right", {
        scaleX: 0, duration: 0.5, ease: "power3.inOut", transformOrigin: "right",
      }, "<");
      tl.to(data.next.container, {
        opacity: 1, duration: 0.3, ease: "power2.out",
      }, "-=0.2");  // 在窗帘即将完全打开时开始淡入
      await tl;
    },
  }],
});
```

**要点**：
- 左右遮罩各占 50% 宽度，`transformOrigin` 相反——左侧遮罩从右向左展开，右侧从左向右展开
- `"<"` 让两个动画同时开始，形成对称的窗帘效果
- 新页面淡入时机提前于窗帘完全打开（`-=0.2`），避免完全打开后的空白帧
- 收缩时 `transformOrigin` 需要翻转：leave 时从外向内展开，enter 时从内向外收缩

### 练习五

**思路**：在 `beforeEnter` 中为新页面元素设置初始状态，在 `enter` 中用 GSAP timeline 的 stagger 参数实现交错进入。

**答案**：
```javascript
import barba from "@barba/core";
import { gsap } from "gsap";

barba.init({
  transitions: [{
    name: "staggered-reveal",
    async leave(data) {
      await gsap.to(data.current.container, {
        opacity: 0, duration: 0.3, ease: "power2.in",
      });
      data.current.container.remove();
    },
    beforeEnter(data) {
      const container = data.next.container;
      const title = container.querySelector(".page-title");
      const body = container.querySelector(".page-body");
      const image = container.querySelector(".page-image");
      const button = container.querySelector(".page-cta");

      gsap.set(title, { opacity: 0, y: 40 });
      gsap.set(body, { opacity: 0, x: -40 });
      gsap.set(image, { opacity: 0, x: 40, scale: 0.9 });
      gsap.set(button, { opacity: 0 });

      data.elements = [title, body, image, button].filter(Boolean);
    },
    async enter(data) {
      const tl = gsap.timeline({ defaults: { ease: "power2.out" } });

      tl.to(data.elements[0], {
        opacity: 1, y: 0, duration: 0.5,
      });

      tl.to(data.elements[1], {
        opacity: 1, x: 0, duration: 0.5,
      }, "-=0.35");  // 重叠 0.1 秒（0.5 - 0.35 = 0.15 间隔）

      tl.to(data.elements[2], {
        opacity: 1, x: 0, scale: 1, duration: 0.5,
      }, "-=0.35");

      tl.to(data.elements[3], {
        opacity: 1, duration: 0.4,
      }, "-=0.3");

      await tl;
    },
  }],
});
```

```css
/* 配合 CSS 确保元素可见性 */
[data-barba="container"] {
  visibility: visible !important;
}

.page-title, .page-body, .page-image, .page-cta {
  will-change: transform, opacity;
}
```

**要点**：
- `beforeEnter` 是设置初始状态的最佳时机——此时新页面 DOM 已插入但还未可见
- timeline 的 position 参数 `"-=0.35"` 让动画有重叠，形成自然的交错节奏而非生硬的串行
- `defaults` 对象避免每个动画重复写 `ease`
- 用 `filter(Boolean)` 处理可选元素，避免查询失败导致动画中断
- 在 CSS 中为参与动画的元素添加 `will-change` 提示浏览器优化
