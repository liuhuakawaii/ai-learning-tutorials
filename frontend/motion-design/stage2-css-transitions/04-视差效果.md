# 04 - 视差效果

## 场景引入

高端品牌官网中，向下滚动时背景图片以比前景文字更慢的速度移动，产生纵深感——这就是视差滚动。视差的本质：不同层级的元素以不同速度滚动，模拟人眼观察近处物体移动快、远处物体移动慢的视觉经验。

想象你坐在行驶的列车上：窗外的远山几乎不动，近处的电线杆飞速掠过。这种"近快远慢"的视觉差异就是视差。网页视差效果正是利用这一物理现象，在二维平面上创造出三维纵深感。

本课从最简单的双层视差开始，逐步构建多层视差场景，并讲解性能优化策略和实际项目中的工程实践。

## 学习目标

- 理解视差效果的物理原理和实现思路
- 掌握用 CSS `transform` 实现高性能视差
- 了解 `perspective` + `translateZ` 的 CSS 原生视差方案
- 掌握 `scroll-timeline` 纯 CSS 视差方案
- 能实现多层视差、滚动联动动画等效果
- 理解视差效果的性能瓶颈和优化策略
- 能在真实项目中合理使用视差并做好降级处理

## 一、视差原理

### 1.1 物理模型

视差效果的数学基础非常简单。假设屏幕是一个观察窗口，不同距离的物体在窗口中移动的速度不同：

```
元素位移 = 滚动距离 × 视差系数
```

系数的含义：
- **系数 = 0**：元素固定不动（贴在屏幕上，类似 `position: fixed`）
- **系数 = 0.3**：元素移动速度是正常滚动的 30%，产生"远处背景"的感觉
- **系数 = 1.0**：正常滚动，和页面其他内容同步
- **系数 = 1.5**：比正常滚动更快，产生"前景悬浮"的感觉

### 1.2 视觉直觉

用一个生活场景来理解：假设你站在铁轨旁，看一列火车驶过。

- **远处的山脉**（系数 ≈ 0.1）：几乎不动
- **中景的房屋**（系数 ≈ 0.4）：缓慢移动
- **近景的电线杆**（系数 ≈ 0.8）：快速掠过
- **前景的铁轨**（系数 = 1.0）：正常速度

网页视差正是模拟这一效果。通过给不同层级的元素设置不同的滚动速度系数，我们能在平面上营造出立体的空间感。

### 1.3 三种实现思路对比

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| JS + `transform` | 最灵活，可控性强 | 需要手动管理滚动事件 | 复杂交互、需要精确控制 |
| CSS `perspective` + `translateZ` | 纯 CSS，浏览器原生计算 | 兼容性要求较高，调试困难 | 标准视差页面 |
| `scroll-timeline` | 最简洁，零 JS | 兼容性最差（仅 Chrome 115+） | 现代浏览器项目 |

## 二、JavaScript + transform 方案

### 2.1 基础实现

这是最常见、兼容性最好的方案。核心思路：监听滚动事件，在 `requestAnimationFrame` 中用 `translate3d` 更新元素位置。

```javascript
function createParallax(element, speed = 0.5) {
  function update() {
    const offset = window.scrollY * speed
    element.style.transform = `translate3d(0, ${offset}px, 0)`
  }
  window.addEventListener('scroll', () => requestAnimationFrame(update))
}

document.querySelectorAll('[data-parallax]').forEach(el => {
  createParallax(el, parseFloat(el.dataset.parallax))
})
```

```html
<div class="parallax-section">
  <div class="parallax-layer" data-parallax="-0.3">背景层</div>
  <div class="parallax-layer" data-parallax="-0.1">中间层</div>
  <div class="parallax-content">前景内容</div>
</div>
```

```css
.parallax-section { position: relative; height: 100vh; overflow: hidden; }
.parallax-layer { position: absolute; inset: 0; will-change: transform; }
.parallax-content { position: relative; z-index: 10; }
```

**关键细节解析：**

- **负值的含义**：`data-parallax="-0.3"` 中的负号让元素向上移动（与滚动方向相反），产生"背景缓慢跟随"的效果。如果用正值，背景会跟着滚动方向跑，视觉上不合理。
- **`translate3d` 而非 `translateY`**：`translate3d` 会触发 GPU 加速，将元素提升为独立合成层，避免重排重绘。
- **`will-change: transform`**：提前告知浏览器这个元素的 transform 会频繁变化，浏览器会提前做优化准备。

### 2.3 滚动方向感知

实际项目中，我们常常需要知道用户是在向上还是向下滚动，以便做不同的动画响应：

```javascript
class ScrollDirectionTracker {
  constructor() {
    this.lastScrollY = window.scrollY
    this.direction = 'down'
    this.callbacks = []
  }

  onUpdate() {
    const currentY = window.scrollY
    this.direction = currentY > this.lastScrollY ? 'down' : 'up'
    this.lastScrollY = currentY
    this.callbacks.forEach(cb => cb(this.direction, currentY))
  }

  onChange(callback) {
    this.callbacks.push(callback)
  }
}

const tracker = new ScrollDirectionTracker()
window.addEventListener('scroll', () => requestAnimationFrame(() => tracker.onUpdate()))

tracker.onChange((direction, scrollY) => {
  // 根据滚动方向调整视差系数
  const factor = direction === 'down' ? 1 : -1
  document.querySelectorAll('[data-parallax]').forEach(el => {
    const speed = parseFloat(el.dataset.parallax)
    el.style.transform = `translate3d(0, ${scrollY * speed * factor}px, 0)`
  })
})
```

## 三、CSS 原生视差：perspective + translateZ

### 3.1 原理详解

这个方案利用 CSS 3D 变换的特性，让浏览器自动计算视差。核心思路：

1. 给滚动容器设置 `perspective: 1px`（定义观察者到 z=0 平面的距离）
2. 用 `translateZ` 将元素推到不同深度
3. 浏览器根据深度自动计算滚动时的视差位移

```html
<div class="parallax-container">
  <div class="parallax-group">
    <div class="layer back">背景层</div>
    <div class="layer mid">中间层</div>
    <div class="layer front">前景层</div>
  </div>
</div>
```

```css
.parallax-container {
  height: 100vh;
  overflow-x: hidden; overflow-y: auto;
  perspective: 1px;
}

.parallax-group {
  position: relative; height: 100vh;
  transform-style: preserve-3d;
}

.layer { position: absolute; inset: 0; }

.back {
  transform: translateZ(-2px) scale(3);
  background: #1e3a5f; color: white;
}

.mid {
  transform: translateZ(-1px) scale(2);
  background: rgba(59, 130, 246, 0.5);
}

.front {
  transform: translateZ(0);
  background: rgba(255, 255, 255, 0.9);
}
```

### 3.2 scale 的必要性

`translateZ(-2px) scale(3)` 中 `scale` 是必需的——元素被推远后视觉上会变小，`scale` 把它放大回来。

公式推导：

```
perspective = 1px（观察者到 z=0 的距离）
translateZ = -2px（元素在 z=0 后方 2px 处）
实际观察距离 = perspective + |translateZ| = 1 + 2 = 3px
缩放比 = 实际观察距离 / perspective = 3 / 1 = 3
所以 scale(3)
```

通用公式：**`scale = 1 + |translateZ| / perspective`**

### 3.4 常见陷阱

使用 `perspective` + `translateZ` 时容易踩的坑：

1. **`transform-origin` 设置错误**：默认是 `center center`，但视差层通常需要 `center top` 或 `center bottom`，否则缩放后元素位置会偏移。
2. **忘记 `transform-style: preserve-3d`**：没有这个属性，子元素的 `translateZ` 不会生效。
3. **滚动容器必须是 `perspective` 的拥有者**：`perspective` 必须设在实际发生滚动的元素上，不能设在祖先元素上。

## 四、scroll-timeline 纯 CSS 方案

### 4.1 基本用法

`scroll-timeline` 是 CSS 新特性，允许将动画进度绑定到滚动位置，完全不需要 JavaScript：

```css
.parallax-bg {
  animation: parallaxMove linear both;
  animation-timeline: scroll(root);
}

@keyframes parallaxMove {
  from { transform: translateY(0); }
  to { transform: translateY(-200px); }
}
```

### 4.2 多层视差

```css
.layer-sky {
  animation: skyMove linear both;
  animation-timeline: scroll(root);
}
@keyframes skyMove {
  from { transform: translateY(0); }
  to { transform: translateY(-50px); }
}

.layer-mountains {
  animation: mountainMove linear both;
  animation-timeline: scroll(root);
}
@keyframes mountainMove {
  from { transform: translateY(0); }
  to { transform: translateY(-150px); }
}

.layer-ground {
  animation: groundMove linear both;
  animation-timeline: scroll(root);
}
@keyframes groundMove {
  from { transform: translateY(0); }
  to { transform: translateY(-300px); }
}
```

不同层级设置不同的 `translateY` 终值，终值越小移动越慢，产生视差效果。

### 4.3 兼容性处理

`scroll-timeline` 目前兼容性有限（Chrome 115+、Edge 115+），需要做降级：

```css
/* 默认降级：无动画，元素正常显示 */
.parallax-bg {
  transform: translateY(0);
}

/* 支持 scroll-timeline 的浏览器启用视差 */
@supports (animation-timeline: scroll()) {
  .parallax-bg {
    animation: parallaxMove linear both;
    animation-timeline: scroll(root);
  }
}
```

## 五、多层视差实战

### 5.1 ParallaxScene 类

构建一个可复用的视差管理器，支持动态添加层、暂停/恢复、销毁：

```javascript
class ParallaxScene {
  constructor(container) {
    this.container = container
    this.layers = container.querySelectorAll('[data-speed]')
    this.ticking = false
    this.paused = false
    this.onScroll = this.onScroll.bind(this)
    window.addEventListener('scroll', this.onScroll, { passive: true })
  }

  onScroll() {
    if (this.paused) return
    if (!this.ticking) {
      requestAnimationFrame(() => {
        const scrolled = window.scrollY
        this.layers.forEach(layer => {
          const speed = parseFloat(layer.dataset.speed)
          layer.style.transform = `translate3d(0, ${-(scrolled * speed)}px, 0)`
        })
        this.ticking = false
      })
      this.ticking = true
    }
  }

  pause() { this.paused = true }
  resume() { this.paused = false }

  destroy() {
    window.removeEventListener('scroll', this.onScroll)
    this.layers.forEach(layer => {
      layer.style.transform = ''
    })
  }
}

new ParallaxScene(document.querySelector('.parallax-scene'))
```

```html
<section class="parallax-scene">
  <div class="sky" data-speed="0.1">天空</div>
  <div class="mountains" data-speed="0.3">山脉</div>
  <div class="ground" data-speed="0.6">前景</div>
  <div class="scene-content"><h1>山间小屋</h1></div>
</section>
```

**设计要点：**

- `{ passive: true }`：告诉浏览器这个滚动监听器不会调用 `preventDefault()`，允许浏览器优化滚动性能。
- `pause()` / `resume()`：页面切换或 Tab 不可见时暂停计算，节省性能。
- `destroy()`：SPA 路由切换时清理事件监听，防止内存泄漏。

### 5.2 容器感知视差

前面的方案都是基于 `window.scrollY`，但实际项目中视差元素可能在任意滚动容器内。改进方案使用 `IntersectionObserver` + 容器相对位置：

```javascript
class ContainerParallax {
  constructor(container) {
    this.container = container
    this.layers = container.querySelectorAll('[data-speed]')
    this.ticking = false

    this.observer = new IntersectionObserver(
      entries => {
        entries.forEach(entry => {
          if (entry.isIntersecting) {
            window.addEventListener('scroll', this.update.bind(this), { passive: true })
          } else {
            window.removeEventListener('scroll', this.update.bind(this))
          }
        })
      },
      { rootMargin: '200px 0px' }
    )

    this.observer.observe(container)
  }

  update() {
    if (this.ticking) return
    this.ticking = true
    requestAnimationFrame(() => {
      const rect = this.container.getBoundingClientRect()
      const progress = -rect.top / this.container.offsetHeight
      this.layers.forEach(layer => {
        const speed = parseFloat(layer.dataset.speed)
        const offset = progress * 100 * speed
        layer.style.transform = `translate3d(0, ${offset}px, 0)`
      })
      this.ticking = false
    })
  }
}
```

## 六、滚动联动动画

让滚动位置控制动画进度，实现"滚动到哪里，动画就播到哪里"的效果：

```javascript
function scrollLinkedAnimation(element, callback) {
  const observer = new IntersectionObserver((entries) => {
    entries.forEach(entry => {
      if (entry.isIntersecting) {
        window.addEventListener('scroll', onScroll)
      } else {
        window.removeEventListener('scroll', onScroll)
      }
    })
  })

  function onScroll() {
    const rect = element.getBoundingClientRect()
    const progress = Math.max(0, Math.min(1, 1 - rect.top / window.innerHeight))
    callback(progress)
  }

  observer.observe(element)
}

// 使用示例：滚动控制旋转角度
scrollLinkedAnimation(document.querySelector('.spin-box'), (progress) => {
  document.querySelector('.spin-box').style.transform = `rotate(${progress * 360}deg)`
})
```

### 6.1 进度映射工具函数

实际项目中，我们经常需要将滚动进度映射到不同的动画参数：

```javascript
function mapRange(value, inMin, inMax, outMin, outMax) {
  return outMin + (outMax - outMin) * Math.max(0, Math.min(1, (value - inMin) / (inMax - inMin)))
}

// 使用：滚动进度 0.2~0.8 映射到透明度 0~1
scrollLinkedAnimation(element, (progress) => {
  const opacity = mapRange(progress, 0.2, 0.8, 0, 1)
  const scale = mapRange(progress, 0.3, 0.7, 0.8, 1)
  element.style.opacity = opacity
  element.style.transform = `scale(${scale})`
})
```

## 七、移动端适配

### 7.1 为什么移动端要禁用视差

移动端存在几个问题：
1. **性能**：移动端 GPU 性能较弱，合成层过多会卡顿
2. **触摸滚动**：移动端的惯性滚动和视差计算可能冲突
3. **用户体验**：移动端屏幕小，视差效果不明显，反而可能造成眩晕

### 7.2 降级策略

```css
/* 移动端禁用视差 */
@media (max-width: 768px) {
  .parallax-layer {
    transform: none !important;
    will-change: auto;
  }
}

/* 尊重用户系统设置 */
@media (prefers-reduced-motion: reduce) {
  .parallax-layer { transform: none !important; }
}
```

### 7.3 JS 降级

```javascript
function shouldEnableParallax() {
  // 检查屏幕宽度
  if (window.innerWidth < 768) return false
  // 检查用户偏好
  if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) return false
  // 检查设备性能（简易判断）
  if (navigator.hardwareConcurrency && navigator.hardwareConcurrency < 4) return false
  return true
}

if (shouldEnableParallax()) {
  new ParallaxScene(document.querySelector('.parallax-scene'))
}
```

## 八、性能优化

### 8.1 性能瓶颈分析

视差效果的性能瓶颈主要在：
1. **滚动事件频率**：每秒触发 60+ 次
2. **样式计算**：每次都要计算 `translate3d` 的值
3. **合成层管理**：过多的合成层消耗显存

### 8.2 优化手段

| 优化手段 | 效果 | 实现方式 |
|----------|------|----------|
| `requestAnimationFrame` 节流 | 避免多次重排 | 每帧只更新一次 |
| `translate3d` GPU 加速 | 避免重排重绘 | 使用 3D transform |
| `will-change: transform` | 提前创建合成层 | CSS 属性 |
| `IntersectionObserver` | 只更新可见元素 | JS API |
| `passive: true` | 允许浏览器优化滚动 | 事件监听选项 |

### 8.3 合成层数量控制

每个 `will-change: transform` 的元素都会被提升为独立合成层，每个合成层消耗显存。控制建议：

```javascript
// 只对进入视口的元素提升合成层
const layerObserver = new IntersectionObserver((entries) => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      entry.target.style.willChange = 'transform'
    } else {
      entry.target.style.willChange = 'auto'
    }
  })
}, { rootMargin: '100px' })

document.querySelectorAll('.parallax-layer').forEach(el => layerObserver.observe(el))
```

## 九、真实项目场景

### 9.1 品牌官网英雄区

最常见的应用场景：品牌官网首屏，背景大图缓慢跟随，前景标题正常滚动，形成优雅的纵深感。

### 9.2 产品特性展示

滚动页面时，不同产品特性从不同方向飞入，每个特性层有不同的视差系数，形成"空间展示柜"效果。

### 9.3 故事叙述页面

新闻报道或品牌故事中，用视差控制不同叙事元素的出现节奏，配合文字讲述，增强沉浸感。

### 9.4 地图/时间线

地图页面中，背景地图缓慢移动，前景标注点正常滚动，帮助用户建立空间关系。

## 常见误区

1. **忘记 `will-change: transform`**：视差元素需要被提升为独立合成层，否则每次 transform 变化都会触发重排。
2. **不用 `requestAnimationFrame` 节流**：直接在 scroll 回调中修改样式会多次重排，帧率骤降。
3. **过度使用视差**：整个页面都是视差会让用户头晕，也影响性能。视差应该用在关键的视觉节点上。
4. **移动端不做降级**：触屏设备上视差可能导致卡顿，且触摸滚动体验不佳。
5. **忘记 `passive: true`**：滚动事件监听器如果不加 `passive`，浏览器需要等待回调完成才能滚动，造成延迟。
6. **视差系数设置过大**：系数超过 0.5 时，元素移动过快，反而破坏纵深感。
7. **忽略 `prefers-reduced-motion`**：部分用户对运动敏感，必须尊重系统设置。

## 工程建议

1. 优先用 `transform` 做视差，不要用 `top`/`margin` 等触发重排的属性。
2. 视差层控制在 3-4 层以内，过多合成层消耗显存。
3. 用 `prefers-reduced-motion` 媒体查询尊重用户设置。
4. 测试时用 Performance 面板确认帧率，目标稳定 60fps。
5. 用 `IntersectionObserver` 只对可见元素做视差计算。
6. SPA 项目中路由切换时要 `destroy()` 视差实例，防止内存泄漏。
7. 视差系数建议范围：背景 0.1-0.3，中景 0.3-0.5，前景 0.5-0.8。
8. 移动端考虑用 CSS `@supports` 做渐进增强，而不是直接禁用。

## 小结

本课学习了视差滚动的三种方案：JS + `transform`（最灵活）、CSS `perspective` + `translateZ`（最优雅）、`scroll-timeline`（最简洁）。关键在于分层和性能——用不同速度的层模拟纵深感，用 GPU 加速保证流畅度，移动端做降级处理。

视差效果是"少即是多"的典型：用在关键位置（英雄区、转场、重点内容）效果惊艳，到处用则适得其反。

### 练习一

**思路**：背景和文字分别用不同 `data-speed`，JS 滚动时用 `translate3d` 移动。背景用 `inset: -20%` 防止边缘露出。

```css
.hero { position: relative; height: 100vh; overflow: hidden; }

  position: absolute; inset: -20%;
  background: url('https://picsum.photos/1920/1080') center/cover;

  position: relative; z-index: 10;
```

```javascript
const layers = document.querySelectorAll('.hero [data-speed]')
let ticking = false

function update() {
  const scrolled = window.scrollY
  if (scrolled > window.innerHeight) return
  layers.forEach(layer => {
    const speed = parseFloat(layer.dataset.speed)
    layer.style.transform = `translate3d(0, ${scrolled * speed}px, 0)`
  })
  ticking = false
}

window.addEventListener('scroll', () => {
  if (!ticking) {
    requestAnimationFrame(update)
    ticking = true
  }
}, { passive: true })
```

**要点**：
- 背景 `inset: -20%` 避免视差移动时露出边缘。
- `scrolled > window.innerHeight` 时停止更新，英雄区滚出视口后不再计算。
- `{ passive: true }` 让浏览器可以优化滚动性能。

### 练习四

**思路**：用 `IntersectionObserver` 控制滚动监听的启停，在回调中计算进度并映射到旋转角度和透明度。

```html
<div style="height: 50vh;"></div>
<div class="spin-target" style="width:100px;height:100px;background:#3b82f6;border-radius:12px;margin:40px auto;"></div>
<div style="height: 150vh;"></div>
```

```javascript
const target = document.querySelector('.spin-target')

function mapRange(value, inMin, inMax, outMin, outMax) {
  return outMin + (outMax - outMin) * Math.max(0, Math.min(1, (value - inMin) / (inMax - inMin)))
}

function onScroll() {
  const rect = target.getBoundingClientRect()
  const progress = 1 - rect.top / window.innerHeight
  const rotation = mapRange(progress, 0, 1, 0, 360)
  const opacity = mapRange(progress, 0, 0.3, 0, 1)
  target.style.transform = `rotate(${rotation}deg)`
  target.style.opacity = opacity
}

const observer = new IntersectionObserver((entries) => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      window.addEventListener('scroll', onScroll, { passive: true })
    } else {
      window.removeEventListener('scroll', onScroll)
    }
  })
}, { rootMargin: '50px' })

observer.observe(target)
```

**要点**：
- `mapRange` 将滚动进度映射到不同范围，实现旋转和透明度的联动。
- `IntersectionObserver` 确保只在元素可见时监听滚动，节省性能。
- `rootMargin: '50px'` 提前 50px 开始计算，避免元素进入时动画才开始的突兀感。

### 练习五

**思路**：封装一个完整的视差管理器，支持增删层、暂停恢复、响应式降级、销毁清理。

```javascript
class ParallaxManager {
  constructor(container, options = {}) {
    this.container = container
    this.layers = new Map()
    this.ticking = false
    this.paused = false
    this breakpoint = options.breakpoint || 768

    this._onScroll = this._onScroll.bind(this)
    this._onResize = this._onResize.bind(this)

    window.addEventListener('scroll', this._onScroll, { passive: true })
    window.addEventListener('resize', this._onResize, { passive: true })

    this._checkResponsive()
  }

  addLayer(element, speed) {
    this.layers.set(element, { speed, originalTransform: element.style.transform })
    element.style.willChange = 'transform'
  }

  removeLayer(element) {
    const layer = this.layers.get(element)
    if (layer) {
      element.style.transform = layer.originalTransform
      element.style.willChange = 'auto'
      this.layers.delete(element)
    }
  }

  pause() { this.paused = true }

  resume() {
    this.paused = false
    this._update()
  }

  destroy() {
    window.removeEventListener('scroll', this._onScroll)
    window.removeEventListener('resize', this._onResize)
    this.layers.forEach((layer, element) => {
      element.style.transform = layer.originalTransform
      element.style.willChange = 'auto'
    })
    this.layers.clear()
  }

  _onScroll() {
    if (this.paused || !this._isEnabled) return
    if (!this.ticking) {
      requestAnimationFrame(() => {
        this._update()
        this.ticking = false
      })
      this.ticking = true
    }
  }

  _onResize() {
    this._checkResponsive()
  }

  _checkResponsive() {
    this._isEnabled = window.innerWidth >= this.breakpoint
    if (!this._isEnabled) {
      this.layers.forEach((layer, element) => {
        element.style.transform = 'none'
      })
    }
  }

  _update() {
    const scrolled = window.scrollY
    this.layers.forEach((layer, element) => {
      element.style.transform = `translate3d(0, ${-(scrolled * layer.speed)}px, 0)`
    })
  }
}

// 使用示例
const manager = new ParallaxManager(document.querySelector('.parallax-container'))
manager.addLayer(document.querySelector('.bg-layer'), 0.2)
manager.addLayer(document.querySelector('.mid-layer'), 0.4)
manager.addLayer(document.querySelector('.fg-layer'), 0.7)

// SPA 路由切换时
// manager.destroy()
```

**要点**：
- `Map` 存储层信息，支持动态增删。
- `_checkResponsive` 在窗口大小变化时自动检查是否需要禁用视差。
- `destroy()` 清理所有事件监听和样式修改，防止内存泄漏。
- `passive: true` 确保滚动性能。
