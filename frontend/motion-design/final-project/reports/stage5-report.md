# Stage 5 阶段报告：创意项目综合实战

## 学习目标

完成本阶段后，你应该能够：

1. **用动画讲述数据故事**
   - 不只是让图表"动起来"，而是通过动画引导观众的注意力
   - 按叙事顺序揭示数据的关键洞察，让复杂数据变得易于理解
   - 理解"认知负荷"理论在数据可视化中的应用

2. **实现流畅的页面过渡动画**
   - 使用 Barba.js 或 View Transitions API 在页面切换时创建连续的视觉体验
   - 处理好进入/离开动画的时序和 DOM 生命周期
   - 理解 SPA 和 MPA 中页面过渡的不同实现方式

3. **将音频数据转化为视觉效果**
   - 用 Web Audio API 获取音频的频率和波形数据
   - 将频率数据映射到图形的大小、颜色或形状
   - 创建有节奏感的音乐可视化效果

4. **用代码生成艺术作品**
   - 结合数学规则（分形、元胞自动机、L-system）和随机性
   - 用代码创造视觉艺术，理解生成式设计的美学原则
   - 掌握"种子随机"实现可复现的随机结果

5. **系统性优化动画性能**
   - 掌握 Chrome DevTools Performance 面板的使用
   - 能识别动画卡顿的根因（JS 执行、布局、绘制、合成）
   - 实现 GPU 加速和降级策略

6. **整合所有阶段技术完成创意作品**
   - 将 CSS 动画、GSAP、Three.js、Canvas 等技术融合到一个项目中
   - 做出有品质的动效作品，可放入作品集

## 核心概念速查

| 概念 | 一句话解释 |
|------|-----------|
| **数据叙事（Data Narrative）** | 用动画的时序控制引导观众按"发现问题 → 展示数据 → 揭示洞察"的路径理解数据。 |
| **View Transitions API** | 浏览器原生页面过渡方案，通过 `document.startViewTransition()` 捕获快照并支持自定义过渡动画。 |
| **Barba.js** | 轻量级页面过渡库，拦截路由变化，管理进入/离开动画的生命周期，适合 MPA 场景。 |
| **Web Audio API** | 浏览器音频处理框架，`AnalyserNode` 可实时获取音频的频率数据（FFT）和时域波形数据。 |
| **生成式艺术** | 用算法和规则创造视觉作品，强调"过程"而非"结果"，通常包含可控的随机性。 |
| **GPU 加速** | 将动画属性（transform、opacity）交给 GPU 合成层处理，绕过主线程的布局和绘制。 |
| **性能降级策略** | 根据设备能力（帧率检测、`navigator.hardwareConcurrency`）动态调整动画复杂度。 |
| **requestIdleCallback** | 在浏览器空闲时执行低优先级任务，避免阻塞动画和用户交互。 |

## 实践练习

### 练习一：数据叙事动画页面

选择一个真实数据集（如某城市的年度气温变化、全球 CO2 浓度趋势），创建一个滚动驱动的数据叙事页面。

**具体要求**：
- 页面分为 3-4 个"章节"，每个章节揭示数据的一个维度
- 图表动画有明确的叙事节奏（不是所有数据同时出现）
- 关键数据点有高亮动画引导注意力（如脉动、变色、标注弹出）
- 支持 `prefers-reduced-motion` 降级：动画跳过，直接显示终态
- 使用 GSAP ScrollTrigger 驱动滚动动画

**目标**：综合运用 GSAP ScrollTrigger、SVG/Canvas 图表和数据叙事技巧。

### 练习二：音频可视化 DJ 台

创建一个音乐可视化页面：加载一段音频，用 Web Audio API 的 `AnalyserNode` 获取频率数据，映射到不同的视觉元素上。

**具体要求**：
- 至少 3 种不同的可视化模式可切换（频率柱状图、波形线条、脉动圆形）
- 音频播放/暂停时可视化同步响应
- 视觉效果有合理的频率-视觉映射（低频对应大元素/暖色，高频对应小元素/冷色）
- 使用 `crossOrigin="anonymous"` 加载音频，避免 CORS 问题
- 可视化渲染使用 `requestAnimationFrame` 循环，不阻塞音频处理

**目标**：掌握 Web Audio API 的分析节点和音频数据驱动动画的思路。

### 练习三：完整创意作品

将前 4 个阶段学到的技术整合到一个完整的创意网站中。

**具体要求**：
- 一个 Three.js 3D 场景作为首页视觉（如粒子背景、3D Logo）
- GSAP 驱动的滚动叙事过渡（至少 3 个页面章节）
- 至少一个 SVG 动画元素（如 Logo 描边动画、图标动效）
- 响应式布局和移动端适配（移动端简化动画）
- 性能优化：GPU 加速、按需渲染、`prefers-reduced-motion` 降级
- 整体视觉风格统一，有设计感

**目标**：完成从技术学习到作品产出的跨越，构建可放入作品集的动效项目。

## 自测问题

1. 数据可视化中，为什么"先展示整体趋势，再聚焦细节"比"一次性展示所有数据"效果更好？从认知负荷的角度解释。
2. View Transitions API 和 Barba.js 各自的适用场景是什么？在 SPA 和 MPA 中的选择有何不同？
3. Web Audio API 的 `AnalyserNode` 返回的 `frequencyData` 数组中，每个索引对应什么物理含义？数组长度由什么决定？
4. 生成式艺术中，为什么完全随机的结果往往不好看？"受控随机"的含义是什么？
5. Chrome DevTools 的 Performance 面板中，如何判断一个动画卡顿是因为 JS 执行太慢还是因为布局/绘制太慢？各自的优化方向是什么？
6. 如何检测用户的设备性能，并据此决定是否启用 Three.js 3D 场景？

## 常见陷阱

- **数据叙事变成数据堆砌**：动画不是越多越好。每个动画都应该服务于一个叙事目的——引导注意力、揭示对比、强调关键数据。没有叙事目的的动画是噪音。
- **音频可视化的跨域问题**：加载跨域音频文件时，`AnalyserNode` 无法获取数据。必须在 `<audio>` 标签设置 `crossOrigin="anonymous"` 且服务器返回正确的 CORS 头。
- **View Transitions 兼容性**：View Transitions API 在 Safari 和 Firefox 中支持有限。生产环境需要准备 Barba.js 或自定义 JS 降级方案。
- **性能优化过度**：过早优化是万恶之源。先用 Performance 面板确认瓶颈在哪里，再针对性优化。不要凭直觉猜测。
- **忽略低端设备**：不是所有用户都有高端 GPU。`navigator.hardwareConcurrency` 和帧率检测可以帮助判断设备能力，动态降级动画复杂度。
- **Three.js 场景内存泄漏**：切换页面或销毁场景时，必须手动 `dispose()` 几何体、材质和纹理，否则 GPU 内存不会释放。
