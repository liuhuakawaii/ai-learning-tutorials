# Stage 4 阶段报告：Three.js 动态视觉

## 学习目标

完成本阶段后，你应该能够：

1. **用 Three.js 构建基础 3D 场景动画**
   - 掌握场景（Scene）、相机（Camera）、渲染器（Renderer）的三件套
   - 能用关键帧动画系统驱动 3D 对象的位移、旋转和缩放
   - 理解正交相机与透视相机的区别和适用场景

2. **理解骨骼动画与蒙皮**
   - 知道骨骼系统如何驱动网格变形
   - 能加载和播放 glTF 格式的角色动画
   - 理解骨骼层级与矩阵变换的关系
   - 掌握 `AnimationMixer`、`AnimationClip`、`AnimationAction` 的协作

3. **用物理引擎实现真实运动**
   - 集成 Cannon.js 或 Ammo.js，为 3D 对象添加重力、碰撞和约束
   - 理解刚体（RigidBody）的属性：质量、摩擦力、恢复系数
   - 实现物理驱动的动画效果

4. **用粒子系统模拟流体和烟雾**
   - 使用 Three.js 的 `Points` 或 `InstancedMesh` 构建大规模粒子系统
   - 理解噪声函数在流体模拟中的作用
   - 掌握粒子的生命周期管理

5. **用程序化动画生成有机运动**
   - 掌握 Perlin/Simplex 噪声的原理和应用
   - 用正弦波叠加和程序化生成技术创造自然运动
   - 理解"受控随机"在视觉设计中的价值

6. **实现鼠标驱动的 3D 交互**
   - 用 Raycaster 实现鼠标拾取
   - 将 2D 鼠标位置映射到 3D 空间
   - 构建响应式 3D 交互体验

## 核心概念速查

| 概念 | 一句话解释 |
|------|-----------|
| **Scene / Camera / Renderer** | Three.js 的核心三件套：Scene 是容器，Camera 定义视角，Renderer 负责绘制到 Canvas。 |
| **AnimationMixer** | Three.js 的动画混合器，管理一个对象的多个动画剪辑（AnimationClip），支持混合和过渡。 |
| **骨骼（Bone）与蒙皮（SkinnedMesh）** | 骨骼是层级变换链，蒙皮网格的顶点绑定到骨骼上，随骨骼运动产生形变。 |
| **glTF 格式** | 3D 资源的"JPEG"格式，支持模型、材质、动画、场景的完整打包，是 Web 3D 的标准格式。 |
| **物理引擎** | 模拟刚体动力学（重力、碰撞、摩擦力），让 3D 对象的运动遵循物理规律而非手动关键帧。 |
| **Simplex 噪声** | 一种连续的伪随机函数，输入坐标返回平滑变化的值；用于生成有机运动、地形和流体效果。 |
| **InstancedMesh** | 高效渲染大量相同几何体的技术，一次 draw call 绘制上万个实例，适合粒子系统。 |
| **Raycaster** | 从相机发射射线检测与 3D 对象的交点，是鼠标拾取和 3D 交互的基础。 |

## 实践练习

### 练习一：3D 产品旋转展示台

创建一个 3D 产品展示场景：一个几何体（如球体或加载的 glTF 模型）放置在展示台上，自动缓慢旋转。鼠标拖拽可控制旋转方向，松手后自动恢复缓慢旋转。

**具体要求**：
- 使用 OrbitControls 或自定义鼠标交互实现拖拽旋转
- 产品有环境光照（`AmbientLight`）和方向光（`DirectionalLight`）产生的阴影
- 自动旋转在鼠标交互时暂停，交互结束后平滑恢复（用 `lerp` 插值）
- 展示台有反射或半透明效果

**目标**：掌握 Three.js 场景搭建、光照阴影和鼠标交互的基本流程。

### 练习二：物理弹球实验场

搭建一个 3D 物理场景：一个平台上有多个球体，添加重力让球体自然下落并相互碰撞。用户可以点击屏幕"发射"新球体。

**具体要求**：
- 集成 Cannon.js 物理引擎
- 球体有真实的碰撞和反弹效果（配置 `restitution` 恢复系数）
- 不同大小的球体质量不同，碰撞效果有差异
- 平台有边界挡板，防止球体掉落
- 点击位置作为新球体的发射位置

**目标**：理解物理引擎的集成方式和刚体属性配置。

### 练习三：程序化噪声粒子场

创建一个由上万个粒子组成的 3D 粒子场，粒子的运动受 Simplex 噪声控制，形成类似流体或烟雾的有机运动效果。鼠标移动会影响周围粒子的运动方向。

**具体要求**：
- 使用 `InstancedMesh` 或 `Points` 实现高性能渲染
- 用 3D Simplex 噪声驱动粒子位置，形成连续流动的效果
- 鼠标位置作为噪声场的扰动源（在鼠标附近的粒子运动方向偏转）
- 粒子有生命周期：生成 → 运动 → 衰减 → 重生
- 目标帧率保持在 60fps（粒子数量可调整）

**目标**：掌握程序化动画和大规模粒子系统的性能优化。

## 自测问题

1. Three.js 的 `requestAnimationFrame` 渲染循环中，为什么要在每帧调用 `renderer.render(scene, camera)` 而不是只在场景变化时调用？什么情况下可以优化为按需渲染？
2. 骨骼动画中，一个顶点同时受多根骨骼影响时（多权重蒙皮），顶点的最终位置是如何计算的？权重值的含义是什么？
3. 物理引擎的"固定步长"（fixed timestep）是什么意思？为什么要用固定步长而不是跟随渲染帧率？
4. 为什么用 `InstancedMesh` 渲染 10000 个粒子比创建 10000 个 `Mesh` 对象快得多？性能瓶颈在哪里？
5. Raycaster 检测 3D 对象时，为什么对大量对象逐一检测会很慢？有什么优化策略？

## 常见陷阱

- **忘记调用 `mixer.update()`**：Three.js 的 `AnimationMixer` 不会自动更新，必须在渲染循环中手动调用 `mixer.update(deltaTime)`，否则动画不动。
- **物理引擎与渲染频率不同步**：物理引擎通常以固定频率（如 60Hz）更新，渲染帧率可能不同。需要在每帧中插值物理状态，否则物体会"抖动"。
- **阴影性能开销**：每个投射阴影的光源都会增加一个 shadow map 的渲染 pass。限制阴影投射的物体数量和 shadow map 分辨率。
- **噪声函数的计算成本**：3D Simplex 噪声的计算量比 2D 大很多。如果只需要 2D 效果（如地形），用 2D 噪声即可。
- **Raycaster 与 InstancedMesh**：默认 Raycaster 不能检测 `InstancedMesh` 的单个实例。需要自定义 `aycast` 逻辑或使用 BVH 加速。
- **模型加载后没有动画**：glTF 模型的动画存在 `animations` 数组中，需要手动创建 `AnimationMixer` 和 `AnimationAction` 才能播放。
