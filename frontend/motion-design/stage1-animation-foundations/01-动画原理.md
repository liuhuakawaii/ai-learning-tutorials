# 第一课：动画原理——帧、缓动与时间轴

## 场景引入

打开任意一个现代网站，页面上的元素平滑地滑入、淡出、缩放。这些流畅的视觉效果背后是一套严谨的动画原理。理解帧率、缓动函数和时间轴这三个核心概念，是从"会写动画"到"写好动画"的关键跨越。

很多开发者直接写 `transition: all 0.3s`，却说不清为什么选 0.3 秒，也不理解为什么 `ease-in-out` 比 `linear` 看起来更自然。本课将从根本上拆解动画的底层逻辑。

## 学习目标

- 理解帧率（FPS）与人眼感知的关系
- 掌握缓动函数的数学原理与视觉效果
- 学会用时间轴思维规划复杂动画序列
- 能够为不同场景选择合适的动画参数
- 掌握逐帧动画与补间动画的核心差异
- 理解浏览器渲染管线对动画性能的影响

## 一、帧动画基础

### 1.1 什么是帧

动画的本质是**快速切换静态画面**。当每秒切换的画面足够多时，人眼会将其感知为连续运动。这个现象被称为**视觉暂留**（Persistence of Vision），人眼会将前一帧的图像保留约 1/25 秒，当帧率超过 24 FPS 时，大脑就会将离散的画面"脑补"为连续运动。

| 帧率 | 场景 | 说明 |
|------|------|------|
| 24 FPS | 电影 | 胶片时代标准，带自然运动模糊 |
| 30 FPS | 视频 | 大部分网络视频和游戏主机 |
| 60 FPS | Web 动画 | 浏览器理想目标，每帧约 16.67ms |
| 120 FPS | 高刷屏 | 部分移动端和高端显示器 |

浏览器渲染管线每帧预算约 **16.67 毫秒**。超出则掉帧，用户感知到卡顿。注意：人眼对不同类型的运动敏感度不同——对位移变化比对颜色变化更敏感，因此位移动画的帧率要求更高。

### 1.2 浏览器渲染管线

理解帧率必须先理解浏览器如何将代码变成屏幕上的像素。每一帧经历以下阶段：

```
JavaScript → Style → Layout → Paint → Composite
  计算样式    计算布局   绘制像素   合成图层
```

- **JavaScript**：执行动画逻辑、修改 DOM 或样式
- **Style**：计算元素最终应用的 CSS 规则
- **Layout**：计算每个元素的几何位置和大小（位置、宽高）
- **Paint**：将元素绘制到图层上（颜色、边框、阴影）
- **Composite**：将多个图层合成最终画面（GPU 处理）

**关键性能原则**：动画越早进入管线后段，性能越好。`transform` 和 `opacity` 只触发 Composite，是最高效的动画属性。

```javascript
// 触发完整管线（最慢）
element.style.left = '100px'      // Layout → Paint → Composite

// 只触发 Paint（中等）
element.style.backgroundColor = 'red'  // Paint → Composite

// 只触发 Composite（最快）
element.style.transform = 'translateX(100px)'  // Composite only
element.style.opacity = '0.5'                  // Composite only
```

### 1.3 帧率检测与掉帧监控

实际开发中，需要工具来检测动画是否掉帧：

```javascript
let lastTime = performance.now()
let frameCount = 0
let fpsDisplay = null

function createFPSMonitor() {
  fpsDisplay = document.createElement('div')
  Object.assign(fpsDisplay.style, {
    position: 'fixed', top: '10px', left: '10px',
    background: 'rgba(0,0,0,0.7)', color: '#0f0',
    padding: '4px 8px', fontFamily: 'monospace', fontSize: '12px',
    zIndex: '9999', borderRadius: '4px'
  })
  document.body.appendChild(fpsDisplay)
}

function checkFrame(currentTime) {
  frameCount++
  const delta = currentTime - lastTime
  if (delta >= 1000) {
    const fps = Math.round(frameCount * 1000 / delta)
    if (fpsDisplay) {
      fpsDisplay.textContent = `FPS: ${fps}`
      fpsDisplay.style.color = fps >= 55 ? '#0f0' : fps >= 30 ? '#ff0' : '#f00'
    }
    frameCount = 0
    lastTime = currentTime
  }
  requestAnimationFrame(checkFrame)
}

createFPSMonitor()
requestAnimationFrame(checkFrame)
```

### 1.4 逐帧动画 vs 补间动画

**逐帧动画**（Frame-by-Frame Animation）：每帧手动绘制。像翻页动画书一样，每一页都是一幅完整的画面。优点是完全控制，缺点是工作量大、资源消耗高。

**补间动画**（Tween Animation）：只定义起始和结束状态，中间帧由计算生成。"Tween"来自"in-between"（中间）。Web 动画绝大多数是补间动画，因为浏览器可以高效地在两个值之间进行线性插值：

```javascript
// 补间动画的核心：线性插值
function lerp(start, end, progress) {
  return start + (end - start) * progress
}

// progress 从 0 到 1，值从 start 平滑过渡到 end
lerp(0, 200, 0)     // 0
lerp(0, 200, 0.25)  // 50
lerp(0, 200, 0.5)   // 100
lerp(0, 200, 0.75)  // 150
lerp(0, 200, 1)     // 200
```

在 Web 中，CSS `transition` 和 `animation` 都是补间动画。需要逐帧控制的场景（如 Canvas 游戏、粒子系统），则用 `requestAnimationFrame` 手动实现。

### 1.5 requestAnimationFrame 基础

`requestAnimationFrame`（简称 rAF）是浏览器提供的专用动画 API，它会在每一帧的开始前调用回调函数，确保与浏览器的刷新率同步：

```javascript
let startTime = null
const duration = 1000 // 1 秒

function animate(currentTime) {
  if (!startTime) startTime = currentTime
  const elapsed = currentTime - startTime
  const progress = Math.min(elapsed / duration, 1)

  // 应用动画：元素从左到右移动 200px
  const x = lerp(0, 200, progress)
  element.style.transform = `translateX(${x}px)`

  if (progress < 1) {
    requestAnimationFrame(animate)
  }
}

requestAnimationFrame(animate)
```

**与 setTimeout/setInterval 的区别**：

```javascript
// 差：不与刷新率同步，可能掉帧或浪费资源
setInterval(() => {
  element.style.transform = `translateX(${x}px)`
}, 16)

// 好：与浏览器刷新率同步，后台标签页自动暂停
requestAnimationFrame(() => {
  element.style.transform = `translateX(${x}px)`
})
```

`requestAnimationFrame` 的优势：
1. 自动匹配屏幕刷新率（60Hz 屏幕每 16.67ms 调用一次）
2. 后台标签页自动暂停，节省资源
3. 浏览器可以批量优化多个 rAF 回调

## 二、缓动函数

### 2.1 为什么线性动画看起来不自然

线性动画中物体从头到尾保持相同速度，但现实世界中物体受惯性影响，启动时加速、停止时减速。缓动函数是对这种自然运动的数学模拟。

想象一辆汽车：起步时需要加速（ease-in），行驶中匀速，刹车时减速（ease-out）。如果汽车瞬间达到最高速、又瞬间停下，这看起来会非常不自然——这就是 linear 动画的问题。

### 2.2 缓动函数的数学本质

缓动函数是一个将 `t ∈ [0, 1]` 映射到 `[0, 1]` 的函数。`t` 是线性进度，返回值是实际进度：

```javascript
// 输入 t 是线性时间进度（0 到 1）
// 输出是经过缓动处理后的实际进度（0 到 1）

function linear(t) { return t }
// 等价于 y = x，一条直线

function easeIn(t) { return t * t }
// 等价于 y = x²，抛物线，开始慢后来快

function easeOut(t) { return t * (2 - t) }
// 等价于 y = 2x - x²，倒抛物线，开始快后来慢

function easeInOut(t) {
  return t < 0.5 ? 2 * t * t : -1 + (4 - 2 * t) * t
}
// 前半段 easeIn，后半段 easeOut，S 形曲线
```

### 2.3 常见缓动类型详解

**Ease-In（加速）**：物体从静止开始加速。适合元素出场——离开时越来越快，符合"一去不复返"的感觉。

**Ease-Out（减速）**：物体从快速减速到停止。适合元素入场——快速出现然后减速停下，吸引注意力后平稳落地。

**Ease-In-Out（先加速后减速）**：两头慢中间快。适合位置变换——从 A 点到 B 点的平滑过渡。

```javascript
// 用 rAF 直观展示不同缓动效果
function demonstrateEasing() {
  const container = document.createElement('div')
  container.style.cssText = 'position:relative;height:200px;border:1px solid #ccc;margin:10px 0'
  document.body.appendChild(container)

  const easings = {
    'linear': t => t,
    'easeIn': t => t * t,
    'easeOut': t => t * (2 - t),
    'easeInOut': t => t < 0.5 ? 2 * t * t : -1 + (4 - 2 * t) * t
  }

  Object.entries(easings).forEach(([name, fn], index) => {
    const dot = document.createElement('div')
    dot.style.cssText = `
      position:absolute;top:${index * 45 + 10}px;left:0;
      width:20px;height:20px;border-radius:50%;background:#3498db;
      display:flex;align-items:center;justify-content:center;font-size:10px;color:#fff;
    `
    dot.textContent = name
    container.appendChild(dot)

    let startTime = null
    function animate(currentTime) {
      if (!startTime) startTime = currentTime
      const progress = Math.min((currentTime - startTime) / 2000, 1)
      const easedProgress = fn(progress)
      dot.style.transform = `translateX(${easedProgress * (container.offsetWidth - 20)}px)`
      if (progress < 1) requestAnimationFrame(animate)
    }
    requestAnimationFrame(animate)
  })
}
```

```css
.linear      { transition-timing-function: linear; }

```

### 2.5 贝塞尔曲线自定义缓动

CSS 的 `cubic-bezier(x1, y1, x2, y2)` 用两个控制点定义贝塞尔曲线，可以创建无限种缓动效果：

```css
/* 弹性效果：先超过目标再回弹 */
.bounce { transition-timing-function: cubic-bezier(0.34, 1.56, 0.64, 1); }

/* 极快开始，缓慢结束 */
.snappy { transition-timing-function: cubic-bezier(0.19, 1, 0.22, 1); }

/* 缓慢开始，极快结束 */
.sharp { transition-timing-function: cubic-bezier(0.33, 0, 0.67, 0); }
```

贝塞尔曲线的两个控制点坐标含义：
- `x1, y1`：第一个控制点。`x1` 控制时间，`y1` 控制进度
- `x2, y2`：第二个控制点。同上

**常用自定义缓动推荐**：

| 效果 | cubic-bezier 值 | 适用场景 |
|------|-----------------|----------|
| 弹性入场 | cubic-bezier(0.34, 1.56, 0.64, 1) | 按钮、卡片 |
| 快速响应 | cubic-bezier(0.19, 1, 0.22, 1) | 菜单展开 |
| 优雅出场 | cubic-bezier(0.55, 0, 1, 0.45) | 模态框关闭 |
| 平滑过渡 | cubic-bezier(0.25, 0.1, 0.25, 1) | 通用场景 |

```javascript
// 在 JS 中使用贝塞尔缓动
// CSS 会自动解析 cubic-bezier，但 JS 需要自己计算
function cubicBezier(p1x, p1y, p2x, p2y) {
  // 通过牛顿迭代法求解贝塞尔曲线上的点
  // 这里简化展示，实际实现需要数值求解
  return function(t) {
    // 简化版本：用近似公式
    const cx = 3 * p1x
    const bx = 3 * (p2x - p1x) - cx
    const ax = 1 - cx - bx
    const cy = 3 * p1y
    const by = 3 * (p2y - p1y) - cy
    const ay = 1 - cy - by

    function sampleX(tt) { return ((ax * tt + bx) * tt + cx) * tt }
    function sampleY(tt) { return ((ay * tt + by) * tt + cy) * tt }

    // 牛顿迭代求 t 对应的 x
    let guessT = t
    for (let i = 0; i < 8; i++) {
      const currentX = sampleX(guessT) - t
      if (Math.abs(currentX) < 1e-6) break
      const currentSlope = (3 * ax * guessT + 2 * bx) * guessT + cx
      if (Math.abs(currentSlope) < 1e-6) break
      guessT -= currentX / currentSlope
    }
    return sampleY(guessT)
  }
}

// 使用示例
const elasticEase = cubicBezier(0.34, 1.56, 0.64, 1)
console.log(elasticEase(0.5)) // 约 0.78（超过 0.5 表示回弹）
```

## 三、时间轴思维

### 3.1 什么是时间轴

复杂动画不是单一元素的运动，而是多个元素在不同时间点以不同方式运动的组合。时间轴（Timeline）是将这些动画按时间顺序编排的思维方式。

一个页面转场动画的时间轴示例：

```
时间轴：  0ms     200ms    400ms    600ms    800ms
标题：    [淡入滑入────────]
副标题：           [淡入滑入────────]
按钮：                    [淡入滑入────────]
背景：    [颜色渐变────────────────────────]
```

### 3.2 用 Promise 封装动画序列

```javascript
function animate(element, properties, duration, easing = 'ease') {
  return new Promise(resolve => {
    element.style.transition = Object.keys(properties)
      .map(prop => `${prop} ${duration}ms ${easing}`)
      .join(', ')
    const onEnd = () => {
      element.removeEventListener('transitionend', onEnd)
      resolve()
    }
    element.addEventListener('transitionend', onEnd)
    Object.entries(properties).forEach(([prop, value]) => {
      element.style[prop] = value
    })
  })
}

async function runSequence() {
  const box = document.querySelector('.box')
  await animate(box, { opacity: '1' }, 300)
  await animate(box, { transform: 'translateX(200px)' }, 500, 'ease-out')
  await animate(box, { opacity: '0' }, 300)
}
```

### 3.3 并行与串行编排

实际项目中，动画通常既有并行又有串行。用 `Promise.all` 实现并行，`await` 实现串行：

```javascript
function wait(ms) { return new Promise(r => setTimeout(r, ms)) }

async function pageEntrance() {
  const header = document.querySelector('.header')
  const sidebar = document.querySelector('.sidebar')
  const content = document.querySelector('.content')

  // 阶段 1：header 和 sidebar 同时入场（并行）
  await Promise.all([
    animate(header, { opacity: '1', transform: 'translateY(0)' }, 400, 'ease-out'),
    animate(sidebar, { opacity: '1', transform: 'translateX(0)' }, 400, 'ease-out')
  ])

  // 阶段 2：等待 100ms（间隔）
  await wait(100)

  // 阶段 3：内容区入场（串行）
  await animate(content, { opacity: '1' }, 300, 'ease-out')
}

// 使用交错延迟实现列表项依次入场
async function staggerEntrance(items, delay = 80) {
  const promises = items.map((item, index) => {
    return wait(index * delay).then(() => {
      return animate(item, { opacity: '1', transform: 'translateY(0)' }, 300, 'ease-out')
    })
  })
  await Promise.all(promises)
}
```

### 3.4 时间参数选择指南

| 元素类型 | 推荐时长 | 缓动函数 | 说明 |
|----------|----------|----------|------|
| 微交互（悬停） | 150-200ms | ease-out | 按钮、链接等快速反馈 |
| 状态切换 | 200-300ms | ease-in-out | Tab 切换、展开收起 |
| 页面转场 | 300-500ms | ease-in-out | 整页或大区域切换 |
| 元素入场 | 300-400ms | ease-out | 新内容出现 |
| 元素出场 | 200-300ms | ease-in | 内容消失，应比入场快 |
| 模态框 | 250-350ms | ease-out | 弹窗出现 |
| Toast 提示 | 200-300ms | ease-out | 轻量反馈 |

**为什么出场比入场快？** 入场时用户需要时间识别新内容，所以稍微慢一些；出场时用户已经知道它是什么，快速消失不打断注意力。

### 3.5 距离与时长的关系

动画时长应与运动距离成正比。一个元素移动 10px 用 300ms 会显得迟钝，移动 500px 用 150ms 会让人看不清。

经验公式：

```javascript
// 根据距离计算合适的动画时长
function calculateDuration(distance) {
  // 每 100px 约 200ms，最低 150ms，最高 500ms
  const base = 150
  const perHundredPx = 200
  const calculated = base + (Math.abs(distance) / 100) * perHundredPx
  return Math.max(150, Math.min(500, calculated))
}

// 10px 移动 → 170ms
// 50px 移动 → 250ms
// 200px 移动 → 500ms（上限）
```

## 四、动画的心理学基础

### 4.1 缓动与情感

不同的缓动函数传达不同的情感：

- **ease-out**（减速停下）：安全、稳定、可预期
- **ease-in**（加速离开）：紧迫、决绝、快速
- **ease-in-out**（平稳过渡）：优雅、从容、平衡
- **弹性缓动**（超过目标再回弹）：活泼、有趣、年轻
- **线性**：机械、精确、无情感

选择缓动函数时，不仅考虑物理真实性，还要考虑品牌调性和用户情感。

### 4.2 动画时长与感知

- **< 100ms**：用户几乎感知不到变化，适合即时反馈（如按钮按下）
- **100-200ms**：快速但可感知，适合微交互
- **200-500ms**：最佳区间，大部分 UI 动画在此范围
- **500ms-1s**：较长，适合大范围动画或转场
- **> 1s**：用户开始不耐烦，仅用于装饰性动画或加载状态

### 4.3 运动一致性

同一页面上的动画应保持一致的风格：

```css
/* 差：同一个页面三种缓动 */
.card { transition-timing-function: ease; }
.button { transition-timing-function: linear; }
.modal { transition-timing-function: cubic-bezier(0.68, -0.55, 0.27, 1.55); }

/* 好：统一风格 */
.card, .button, .modal {
  transition-timing-function: ease-out;
}
```

## 五、用 Canvas 实现逐帧动画

虽然 Web 动画大多用 CSS 或 WAAPI，但理解逐帧动画的实现方式对性能优化和特殊场景很有帮助：

```html
<canvas id="canvas" width="400" height="200"></canvas>
<script>
const canvas = document.getElementById('canvas')
const ctx = canvas.getContext('2d')

let x = 0
const speed = 2 // 每帧移动 2px

function draw() {
  ctx.clearRect(0, 0, canvas.width, canvas.height)

  // 绘制一个移动的方块
  ctx.fillStyle = '#3498db'
  ctx.fillRect(x, 80, 40, 40)

  // 边界检测：到达右边界后重置
  if (x > canvas.width) x = -40
  x += speed

  requestAnimationFrame(draw)
}

draw()
</script>
```

Canvas 逐帧动画的典型应用：
- 游戏角色移动和碰撞检测
- 粒子效果（烟花、雪花）
- 数据可视化动画
- 复杂的路径动画

## 常见误区

### 误区一：所有动画都用 0.3 秒

按钮悬停 0.3 秒太慢，页面转场 0.3 秒太快。应根据元素类型选择时长。0.3 秒（300ms）虽然是一个不错的默认值，但不应该成为"万金油"。

### 误区二：缓动函数无所谓

`linear` 和 `ease-out` 的视觉感受差距巨大。入场用 `linear` 显得机械，出场用 `ease-in-out` 显得拖沓。缓动函数是动画"看起来自然"的关键因素。

### 误区三：动画越炫越好

动画的目的是传递信息和引导注意力。无关紧要的动画会分散用户注意力，甚至引发前庭系统不适（vestibular disorders）。好的动画应该是用户几乎感觉不到它的存在，但缺少它会觉得不对劲。

### 误区四：忽略 16.67ms 预算

动画应尽可能只操作 `transform` 和 `opacity`，这两个属性由 GPU 合成层处理。操作 `width`、`height`、`left`、`top`、`margin` 等属性会触发 Layout，每次 Layout 可能耗时数毫秒，叠加起来很容易超过 16.67ms 的帧预算。

### 误区五：用 setTimeout 做动画

```javascript
// 差：不与刷新率同步，可能跳帧或浪费资源
setTimeout(animate, 16)

// 差：间隔不精确，且后台不会暂停
setInterval(animate, 16)

// 好：浏览器专用动画 API
requestAnimationFrame(animate)
```

## 工程建议

1. **入场用 ease-out，出场用 ease-in**。符合用户心理预期。
2. **时长与距离成正比**。短距离 150-200ms，长距离 300-500ms。
3. **用 100ms 作为基准单位**。低于 100ms 用户感知不到，高于 1000ms 会不耐烦。
4. **移动端适当缩短时长**。触摸交互的响应期望比鼠标更快。
5. **尊重 `prefers-reduced-motion`**。部分用户对动画敏感或会引发不适。

```css
@media (prefers-reduced-motion: reduce) {
  * {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

6. **建立动画规范**。在设计系统中定义统一的时长、缓动和间距，确保整站一致。
7. **用 Performance 面板调试**。Chrome DevTools 的 Performance 面板可以逐帧分析动画性能。
8. **避免同时动画过多元素**。同一帧内动画超过 10-15 个元素可能掉帧。

## 小结

- 动画本质是快速切换静态画面，Web 动画追求 60 FPS（每帧约 16.67ms）
- 浏览器渲染管线：JavaScript → Style → Layout → Paint → Composite，动画越早进入后段性能越好
- `requestAnimationFrame` 是浏览器专用动画 API，与刷新率同步且后台自动暂停
- 缓动函数模拟真实世界的运动规律，`ease-out` 是最常用的入场缓动
- `cubic-bezier` 可以自定义任意缓动曲线，实现弹性、回弹等效果
- 时间轴将多个动画按时间顺序编排，用 Promise 链式调用实现
- 动画时长和缓动函数需根据元素类型、距离和场景综合判断
- 尊重用户的运动偏好设置（`prefers-reduced-motion`）

### 练习一

**思路**：弹跳效果由多段抛物线拼接，每段高度递减。

```javascript
function bounceOut(t) {
  if (t < 1 / 2.75) return 7.5625 * t * t
  if (t < 2 / 2.75) { t -= 1.5 / 2.75; return 7.5625 * t * t + 0.75 }
  if (t < 2.5 / 2.75) { t -= 2.25 / 2.75; return 7.5625 * t * t + 0.9375 }
  t -= 2.625 / 2.75; return 7.5625 * t * t + 0.984375
}
```

**要点**：7.5625 是通过物理约束推导的系数，使曲线在衔接点连续。每段抛物线模拟一次弹跳，高度递减（100% → 75% → 93.75% → 98.4375%）。

### 练习二

**思路**：`Promise.all` 实现并行动画，`await` 串联顺序执行。

```javascript
function wait(ms) { return new Promise(r => setTimeout(r, ms)) }

async function entranceAnimation() {
  const title = document.querySelector('.title')
  const subtitle = document.querySelector('.subtitle')
  title.style.opacity = '0'
  title.style.transform = 'translateY(30px)'
  subtitle.style.opacity = '0'

  await Promise.all([
    animate(title, { opacity: '1' }, 400, 'ease-out'),
    animate(title, { transform: 'translateY(0)' }, 400, 'ease-out')
  ])
  await wait(500)
  await animate(subtitle, { opacity: '1' }, 300, 'ease-out')
}
```

**要点**：opacity 和 transform 可以并行动画。等待间隔用 `wait` 工具函数。subtitle 的入场应使用 `ease-out` 缓动。

### 练习三

**思路**：rAF 回调中检测帧间隔，计数器追踪连续掉帧次数。

```javascript
function createJankDetector() {
  let lastTime = performance.now()
  let consecutiveJank = 0
  let warning = null

  function check(currentTime) {
    const delta = currentTime - lastTime
    lastTime = currentTime
    if (delta > 20) {
      consecutiveJank++
      if (consecutiveJank >= 3 && !warning) {
        warning = document.createElement('div')
        warning.textContent = '⚠ 性能警告：检测到连续掉帧'
        Object.assign(warning.style, {
          position: 'fixed', top: '10px', right: '10px',
          background: '#e74c3c', color: '#fff',
          padding: '8px 16px', borderRadius: '4px', zIndex: '9999',
          fontSize: '14px', fontFamily: 'sans-serif'
        })
        document.body.appendChild(warning)
        setTimeout(() => {
          if (warning) { warning.remove(); warning = null }
          consecutiveJank = 0
        }, 3000)
      }
    } else {
      consecutiveJank = 0
    }
    requestAnimationFrame(check)
  }
  requestAnimationFrame(check)
}
```

**要点**：20ms 阈值对应约 50 FPS，低于此值用户可能感知卡顿。连续 3 次说明不是偶发。警告自动 3 秒后消失，避免永久遮挡。

### 练习四

**思路**：在 Canvas 上遍历 t 从 0 到 1，用不同缓动函数计算 y 值，绘制曲线。

```html

const canvas = document.getElementById('easing-canvas')
const ctx = canvas.getContext('2d')
const w = canvas.width
const h = canvas.height
const padding = 40

const easings = {
  'linear':    { fn: t => t,                              color: '#95a5a6' },
  'easeIn':    { fn: t => t * t,                           color: '#e74c3c' },
  'easeOut':   { fn: t => t * (2 - t),                     color: '#2ecc71' },
  'easeInOut': { fn: t => t < 0.5 ? 2*t*t : -1+(4-2*t)*t, color: '#3498db' }

ctx.lineWidth = 1
ctx.beginPath()
ctx.moveTo(padding, padding)
ctx.lineTo(padding, h - padding)
ctx.lineTo(w - padding, h - padding)
ctx.stroke()

Object.entries(easings).forEach(([name, { fn, color }]) => {
  ctx.beginPath()
  ctx.strokeStyle = color
  ctx.lineWidth = 2
  for (let i = 0; i <= 100; i++) {
    const t = i / 100
    const y = fn(t)
    const x = padding + t * (w - 2 * padding)
    const yPos = (h - padding) - y * (h - 2 * padding)
    if (i === 0) ctx.moveTo(x, yPos)

  ctx.fillRect(legendX, legendY, 15, 15)
```

**要点**：用 100 个采样点绘制平滑曲线。不同颜色区分四种缓动。坐标轴和图例帮助理解。

### 练习五

**思路**：遍历元素数组，每个元素等待 index * delay 后开始动画，所有动画完成后再 resolve。

```javascript
function staggerFadeIn(elements, options = {}) {
  const {
    delay = 80,
    distance = 20,
    duration = 300,
    easing = 'ease-out'
  } = options

  elements.forEach(el => {
    el.style.opacity = '0'
    el.style.transform = `translateY(${distance}px)`
  })

  const promises = Array.from(elements).map((el, index) => {
    return new Promise(resolve => {
      setTimeout(() => {
        el.style.transition = `opacity ${duration}ms ${easing}, transform ${duration}ms ${easing}`
        el.style.opacity = '1'
        el.style.transform = 'translateY(0)'
        setTimeout(resolve, duration)
      }, index * delay)
    })
  })

  return Promise.all(promises)
}

// 使用示例
const items = document.querySelectorAll('.list-item')
staggerFadeIn(items, { delay: 100, distance: 30 }).then(() => {
  console.log('所有元素入场完成')
})
```

**要点**：先将所有元素设为不可见，再通过 setTimeout 依次触发动画。返回 Promise 便于后续操作。`delay` 参数控制交错间隔，`distance` 控制滑入距离。
