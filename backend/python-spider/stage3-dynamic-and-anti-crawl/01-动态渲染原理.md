# 动态渲染原理

## requests 拿不到的数据

你已经用 requests 成功抓取了 quotes.toscrape.com，觉得爬虫不过如此。于是去抓一个电商网站的商品列表——结果 `response.text` 里只有一个空荡荡的 `<div id="app"></div>`。数据呢？盯着 Network 面板发呆，发现商品数据是 JavaScript 动态加载出来的，requests 根本拿不到。

原来网页分"静态"和"动态"两种。要搞定动态网页，先理解渲染原理。

## 静态 vs 动态

**静态网页**：服务器返回的 HTML 里直接包含所有内容。requests 一次请求就能拿到完整数据。

```python
# 静态页面：requests 直接能抓到
response = requests.get("https://quotes.toscrape.com")
html = response.text  # HTML 里包含所有名言数据
```

**动态网页**：服务器返回一个几乎空的 HTML，数据由 JavaScript 运行后生成。requests 只能拿到空壳。

```python
# 动态页面：requests 拿到的是空壳
response = requests.get("https://某个动态网站.com/products")
html = response.text
# <div id="app"></div>    ← 就一个空的挂载点
# 数据全靠 JS 加载，requests 执行不了 JS
```

| 对比项 | 静态网页 | 动态网页 |
|--------|---------|---------|
| 内容来源 | HTML 文件里直接写好 | JavaScript 运行后生成 |
| requests | 能直接拿到完整内容 | 只能拿到空壳 HTML |
| 技术栈 | 原生 HTML/CSS | React/Vue/Angular |
| 爬取难度 | ★★☆☆☆ | ★★★★☆ |

## SSR 与 CSR

**SSR（服务端渲染）**：服务器生成完整 HTML 返回。对爬虫友好，requests 直接搞定。

**CSR（客户端渲染）**：服务器返回空 HTML + JS 文件，浏览器执行 JS 后渲染页面。对爬虫不友好。

```
CSR 工作流程：
浏览器请求 URL → 服务器返回空壳 HTML → 浏览器执行 JS
→ JS 调 API 拿 JSON → JS 用数据渲染 DOM → 页面显示内容
```

## 如何判断页面类型

**方法一：查看源代码**

右键 → 查看网页源代码 → Ctrl+F 搜索你要的数据。找到了是静态页面，找不到可能是动态。

**方法二：检查 Network 面板的 XHR 请求**

F12 → Network → Fetch/XHR 过滤。如果有 XHR 请求返回 JSON，说明数据是动态加载的。这些 API 接口就是数据的真正来源。

**方法三：检查框架标识**

- React：`<div id="root">` 或 `<div id="app">`
- Vue：`<div id="app">` 带 `v-cloak` 等属性
- Angular：`<app-root>` 自定义标签

**方法四：禁用 JavaScript**

DevTools → Ctrl+Shift+P → "Disable JavaScript" → 刷新。页面空白说明是 CSR。

## 为什么 requests 拿不到动态内容

requests 只做一件事：发送 HTTP 请求，接收 HTTP 响应。它不会执行 JavaScript，不会渲染页面，不会发起后续请求。动态页面的数据要等 JS 执行后才会被"造"出来。

动态页面数据的三种藏身之处：

1. **XHR/Fetch API 请求中**（最常见）→ 可以直接用 requests 请求这个 API
2. **HTML 中 `<script>` 标签里的内嵌数据** → 用正则提取 JSON
3. **JavaScript 代码中硬编码** → 需要下载 JS 文件解析，比较麻烦

## 应对方案

**方案一：浏览器自动化**

用 Playwright 控制真实浏览器，等待 JS 执行完毕后获取渲染后的 DOM。最通用，但速度慢、资源占用大。

**方案二：API 拦截**

用 DevTools 分析 Network 面板，找到加载数据的 XHR 请求，用 requests 直接调这些 API。快速高效，但需要手动分析接口。

选择策略：先用 DevTools 分析。有清晰的 API → 直接请求 API。没有 → 用浏览器自动化。

```python
# 方案二示例：直接请求 API
import requests

# 通过 DevTools 发现了这个 API
api_url = "https://某网站.com/api/products"
params = {"page": 1, "size": 20}
headers = {"Accept": "application/json"}

response = requests.get(api_url, params=params, headers=headers)
data = response.json()
for product in data["products"]:
    print(f"{product['name']} - ¥{product['price']}")
```

## SPA 架构

SPA（Single Page Application）通过路由切换组件、通过 API 请求加载数据。你在前端写的 `useEffect(() => fetch('/api/products'), [])` 就是爬虫要拦截的目标。

从爬虫视角看：Network 面板里的 `GET /api/products?page=1` 返回 JSON，直接用 requests 请求这个 API 就行。

## 参考答案

### 练习一

```python
import requests
urls = [
    "https://quotes.toscrape.com",
    "https://spa5.scrape.center/",
    "https://quotes.toscrape.com/js/",
]
for url in urls:
    response = requests.get(url)
    found = "Quotes to Scrape" in response.text
    print(f"{url}: {'静态' if found else '动态'}")
```

### 练习二

```python
import requests
api_url = "https://spa5.scrape.center/api/book/"
params = {"limit": 18, "offset": 0}
response = requests.get(api_url, params=params)
data = response.json()
print(f"获取 {len(data.get('results', []))} 条数据")
```

### 练习三

```python
import requests
for label, url in [("SSR", "https://quotes.toscrape.com"), ("CSR", "https://spa5.scrape.center/")]:
    response = requests.get(url)
    print(f"{label}: HTML 长度 {len(response.text)} 字符")
```
