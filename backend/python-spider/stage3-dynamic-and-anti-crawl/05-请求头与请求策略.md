## 一、为什么请求头这么重要？

### 1.1 浏览器 vs 爬虫：一眼就能看出来

上一课我们知道了网站会检查请求头来判断请求来源。这一课我们实操——学会正确设置请求头，让程序明确表达自己的客户端能力，并避免因为默认请求头过于异常而被误判。

```
┌──────────────────────────────────────────────────────────┐
│  浏览器发送的请求 vs 爬虫发送的请求                         │
│                                                          │
│  浏览器发出的请求头（真实）：                               │
│  ┌──────────────────────────────────────────────┐        │
│  │  Host: example.com                           │        │
│  │  User-Agent: Mozilla/5.0 (Windows NT 10.0;   │        │
│  │    Win64; x64) AppleWebKit/537.36 Chrome/120  │        │
│  │  Accept: text/html,application/xhtml+xml,     │        │
│  │    application/xml;q=0.9,image/avif,image/webp│        │
│  │  Accept-Language: zh-CN,zh;q=0.9,en;q=0.8    │        │
│  │  Accept-Encoding: gzip, deflate, br           │        │
│  │  Referer: https://www.google.com/             │        │
│  │  Connection: keep-alive                       │        │
│  │  Cookie: session_id=abc123; token=xyz789      │        │
│  └──────────────────────────────────────────────┘        │
│                                                          │
│  requests 默认发出的请求头（信息过少）：                    │
│  ┌──────────────────────────────────────────────┐        │
│  │  Host: example.com                           │        │
│  │  User-Agent: python-requests/2.31.0           │        │
│  │  Accept-Encoding: gzip, deflate               │        │
│  │  Accept: */*                                  │        │
│  │  Connection: keep-alive                       │        │
│  └──────────────────────────────────────────────┘        │
│                                                          │
│  差别：缺少 Accept-Language、Referer，UA 信息不够明确      │
└──────────────────────────────────────────────────────────┘
```

**生活类比：** 请求头就像你去办业务时填写的基本信息。信息完整、格式正常，工作人员才能正确处理；信息缺失或明显异常，就很容易被要求补充说明。

### 1.2 关键请求头详解

```
┌──────────────────┬──────────────────────────────────────┐
│  请求头            │  作用                                │
├──────────────────┼──────────────────────────────────────┤
│  User-Agent       │  客户端能力与来源标识                  │
│  Accept           │  告诉服务器我能接收什么格式的响应      │
│  Accept-Language  │  我的语言偏好，中文/英文               │
│  Accept-Encoding  │  我支持的压缩格式（gzip 等）           │
│  Referer          │  我从哪个页面跳转过来的                 │
│  Connection       │  连接方式（keep-alive 复用连接）       │
│  Cookie           │  会话标识                             │
│  Host             │  目标主机名（requests 自动设置）        │
└──────────────────┴──────────────────────────────────────┘
```

## 二、手动设置请求头

### 2.1 一套完整的请求头模板

```python
import requests

# 从浏览器 DevTools 中复制的完整请求头
headers = {
    # 身份标识——最关键
    "User-Agent": (
        "Mozilla/5.0 (Windows NT 10.0; Win64; x64) "
        "AppleWebKit/537.36 (KHTML, like Gecko) "
        "Chrome/120.0.0.0 Safari/537.36"
    ),
    # 接受的响应格式
    "Accept": (
        "text/html,application/xhtml+xml,application/xml;"
        "q=0.9,image/avif,image/webp,image/apng,*/*;q=0.8"
    ),
    # 语言偏好
    "Accept-Language": "zh-CN,zh;q=0.9,en;q=0.8",
    # 压缩格式
    "Accept-Encoding": "gzip, deflate, br",
    # 连接方式
    "Connection": "keep-alive",
    # 来源页面（根据实际情况修改）
    "Referer": "https://www.google.com/",
}

response = requests.get("https://httpbin.org/headers", headers=headers)
print(response.json())
```

### 2.2 用 Session 统一管理请求头

```python
import requests

# ✅ 推荐：在 Session 上设置默认请求头
# 之后所有通过这个 Session 发出的请求都会自动带上
session = requests.Session()
session.headers.update({
    "User-Agent": (
        "Mozilla/5.0 (Windows NT 10.0; Win64; x64) "
        "AppleWebKit/537.36 Chrome/120.0.0.0 Safari/537.36"
    ),
    "Accept-Language": "zh-CN,zh;q=0.9",
    "Accept": "text/html,application/xhtml+xml,*/*;q=0.8",
})

# 用 Session 发请求——自动带上所有默认 headers
r1 = session.get("https://httpbin.org/headers")
print(r1.json()["headers"]["User-Agent"])
# Mozilla/5.0 (Windows NT 10.0; Win64; x64) ...

# 还可以在单次请求中添加额外的 headers（不会覆盖默认值）
r2 = session.get(
    "https://httpbin.org/headers",
    headers={"Referer": "https://example.com/list"}
)
# 实际发送的 headers = Session 默认 headers + 本次的 Referer
```

## 三、User-Agent 策略

### 3.1 为什么需要稳定、清晰的 UA？

User-Agent 不是“伪装成浏览器”的通行证，而是告诉服务端“这个请求来自谁、做什么、如何联系”。对正式采集任务，更推荐使用稳定、清晰、可联系的 UA；如果需要对比不同客户端标识，可以把随机 UA 当成测试工具，而不是生产默认策略。

```
┌──────────────────────────────────────────────────────────┐
│  UA 策略的思路                                            │
│                                                          │
│  ❌ 信息不足：                                             │
│  User-Agent: python-requests/2.31.0                       │
│  对方很难判断任务来源、用途和联系渠道                       │
│                                                          │
│  ✅ 清晰可审计：                                           │
│  User-Agent: MarketInsightCrawler/1.0                     │
│    (+mailto:data-team@example.com)                        │
│  说明产品、版本和联系人                                    │
└──────────────────────────────────────────────────────────┘
```

### 3.3 在爬虫中使用项目 UA

```python
import requests
import time
import random

PROJECT_UA = "MarketInsightCrawler/1.0 (+mailto:data-team@example.com)"

def get_headers():
    """生成清晰、稳定的请求头"""
    return {
        "User-Agent": PROJECT_UA,
        "Accept": "text/html,application/xhtml+xml,*/*;q=0.8",
        "Accept-Language": "zh-CN,zh;q=0.9,en;q=0.8",
    }

# 在爬虫循环中使用
urls = [
    "https://httpbin.org/headers",
    "https://httpbin.org/headers",
    "https://httpbin.org/headers",
]

for url in urls:
    headers = get_headers()
    print(f"使用 UA: {headers['User-Agent'][:50]}...")
    response = requests.get(url, headers=headers)
    print(f"状态码: {response.status_code}")
    time.sleep(random.uniform(1, 3))
```

### 3.4 多 UA 的测试写法

```python
from fake_useragent import UserAgent
import random

class UserAgentPool:
    """UA 样本池——用于学习不同客户端标识，不作为生产默认策略"""

    def __init__(self, count=20):
        ua = UserAgent()
        # 预生成一批 UA
        self._pool = list(set([ua.random for _ in range(count * 2)]))
        # 去重后取前 count 个
        self._pool = self._pool[:count]
        self._index = 0
        print(f"UA 池初始化完成，共 {len(self._pool)} 个 UA")

    def get_random(self):
        """随机返回一个 UA"""
        return random.choice(self._pool)

    def get_next(self):
        """轮询返回 UA（保证不连续重复）"""
        ua = self._pool[self._index]
        self._index = (self._index + 1) % len(self._pool)
        return ua

# 使用
ua_pool = UserAgentPool(count=15)
for i in range(5):
    print(f"请求 {i+1}: {ua_pool.get_random()[:60]}...")
```

**生活类比：** User-Agent 更像名片。正式拜访时，名片应该清楚写出你是谁、来自哪里、如何联系；测试不同名片格式可以帮助理解系统行为，但不应假装成不同的人反复访问。

## 四、代理 IP——理解请求转发链路

### 4.1 什么是代理 IP？

代理（Proxy）是一个"中间人"。你不是直接访问目标网站，而是先告诉代理"帮我访问这个网站"，代理去访问，然后把结果传回给你。

```
┌──────────────────────────────────────────────────────────┐
│  直连 vs 代理                                             │
│                                                          │
│  直连（没有代理）：                                        │
│  ┌──────┐    请求     ┌──────────┐                       │
│  │ 你   │ ──────────→ │ 目标网站  │                       │
│  │IP: A │ ←────────── │          │                       │
│  └──────┘    响应     └──────────┘                       │
│  网站看到的是你的 IP: A                                    │
│                                                          │
│  使用代理：                                                │
│  ┌──────┐   请求    ┌──────┐   请求    ┌──────────┐      │
│  │ 你   │ ────────→ │ 代理  │ ────────→ │ 目标网站  │      │
│  │IP: A │ ←──────── │IP: B │ ←──────── │          │      │
│  └──────┘   响应    └──────┘   响应    └──────────┘      │
│  网站看到的是代理出口 IP: B                                │
│                                                          │
│  好处：                                                    │
│  • 理解请求经过中间节点转发的过程                            │
│  • 适配公司内网、测试环境或授权代理服务                      │
│  • 在使用前确认目标站点规则和数据授权边界                    │
└──────────────────────────────────────────────────────────┘
```

**生活类比：** 代理 IP 更像公司的统一网络出口。它帮助团队在受控网络环境里访问资源、做测试或满足供应商授权要求，而不是用来隐藏真实目的。

### 4.2 代理的类型

```
┌────────────┬────────────────────────────────────────────┐
│  代理类型   │  说明                                      │
├────────────┼────────────────────────────────────────────┤
│  HTTP 代理  │  只转发 HTTP 请求（端口通常 80/8080）       │
│  HTTPS 代理 │  支持 HTTPS 加密请求（端口通常 443）        │
│  SOCKS 代理 │  更底层的代理，支持任意协议（端口 1080）    │
│            │  SOCKS5 是目前最常用的版本                   │
├────────────┼────────────────────────────────────────────┤
│  透明代理   │  目标网站知道你用了代理，也知道你的真实 IP    │
│  匿名代理   │  目标网站知道你用了代理，但不知道真实 IP      │
│  高匿代理   │  目标网站不知道你用了代理，也不知道真实 IP    │
│            │  → 不代表可以忽略授权和站点规则               │
└────────────┴────────────────────────────────────────────┘
```

## 五、代理使用与风险边界

### 5.1 什么是授权代理管理？

代理是一个中间转发节点。学习阶段了解代理配置，主要是为了理解网络请求链路、处理公司内网或测试环境访问限制，以及在合规授权场景下做稳定性测试。不要把代理当成绕过网站规则或规避封禁的工具。

```
┌──────────────────────────────────────────────────────────┐
│  授权代理管理工作原理                                      │
│                                                          │
│  ┌─────────────────────────────────┐                     │
│  │        授权代理列表               │                     │
│  │  ┌───┐ ┌───┐ ┌───┐ ┌───┐ ┌───┐ │                     │
│  │  │IP1│ │IP2│ │IP3│ │IP4│ │IP5│ │                     │
│  │  │✅ │ │✅ │ │❌ │ │✅ │ │❌ │ │                     │
│  │  └───┘ └───┘ └───┘ └───┘ └───┘ │                     │
│  └─────────────────────────────────┘                     │
│       │                   │                              │
│       ▼                   ▼                              │
│  取一个可用授权代理    网络失败的标记为不可用               │
│       │                                                   │
│       ▼                                                   │
│  发送请求 → 成功 → 继续用                                 │
│           → 代理连接失败 → 换另一个授权代理重试             │
│           → 403/429 → 降频、暂停或申请授权                 │
│                                                          │
│  定期检查：                                                │
│  验证授权代理可用性，删除失效的，补充新的                   │
└──────────────────────────────────────────────────────────┘
```

### 5.2 一个简单的代理管理器实现

```python
import requests
import random
import time
from threading import Lock


class ProxyPool:
    """简单的授权代理管理器，仅用于学习、内网和授权测试场景"""

    def __init__(self):
        self._proxies = []          # 存储所有代理
        self._valid_proxies = []    # 验证通过的代理
        self._lock = Lock()         # 线程锁（多线程安全）
        self._test_url = "https://httpbin.org/ip"
        self._timeout = 10

    def add(self, proxy: str):
        """添加代理到池中
        proxy 格式: "http://IP:端口" 或 "http://用户名:密码@IP:端口"
        """
        with self._lock:
            if proxy not in self._proxies:
                self._proxies.append(proxy)

    def add_batch(self, proxy_list: list):
        """批量添加代理"""
        for proxy in proxy_list:
            self.add(proxy)

    def get_random(self) -> str:
        """随机获取一个可用代理"""
        with self._lock:
            if not self._valid_proxies:
                raise Exception("代理列表为空，请先添加代理")
            return random.choice(self._valid_proxies)

    def remove(self, proxy: str):
        """移除失效的代理"""
        with self._lock:
            if proxy in self._valid_proxies:
                self._valid_proxies.remove(proxy)
            if proxy in self._proxies:
                self._proxies.remove(proxy)
            print(f"已移除代理: {proxy}")

    def validate_all(self):
        """验证所有代理的可用性"""
        print("开始验证代理...")
        self._valid_proxies = []

        for proxy in self._proxies:
            if self._check_proxy(proxy):
                self._valid_proxies.append(proxy)
                print(f"  ✅ 可用: {proxy}")
            else:
                print(f"  ❌ 不可用: {proxy}")

        print(f"验证完成: {len(self._valid_proxies)}/{len(self._proxies)} 个可用")

    def _check_proxy(self, proxy: str) -> bool:
        """检查单个代理是否可用"""
        try:
            proxies = {"http": proxy, "https": proxy}
            response = requests.get(
                self._test_url,
                proxies=proxies,
                timeout=self._timeout
            )
            return response.status_code == 200
        except Exception:
            return False

    def get_with_retry(self, url, max_retries=3, **kwargs):
        """使用授权代理发送请求，仅对代理连接故障重试"""
        for attempt in range(max_retries):
            try:
                proxy = self.get_random()
                proxies = {"http": proxy, "https": proxy}
                response = requests.get(
                    url,
                    proxies=proxies,
                    timeout=self._timeout,
                    **kwargs
                )
                if response.status_code in (403, 429):
                    print("目标站点拒绝访问或限流，请降频、暂停或申请授权")
                    return response
                return response
            except requests.exceptions.ProxyError:
                print(f"代理 {proxy} 连接失败，移除并重试")
                self.remove(proxy)
            except requests.exceptions.Timeout:
                print(f"代理 {proxy} 超时，换一个重试")
            except Exception as e:
                print(f"请求失败: {e}")

        print(f"重试 {max_retries} 次后仍然失败")
        return None

    @property
    def available_count(self):
        return len(self._valid_proxies)
```

## 六、授权代理选择策略

### 6.1 随机选择 vs 轮询选择

```
┌──────────────────────────────────────────────────────────┐
│  两种选择策略                                              │
│                                                          │
│  策略一：随机选择                                          │
│  ┌──────────────────────────────────────┐                │
│  │  授权代理: [A, B, C, D, E]           │                │
│  │                                      │                │
│  │  请求1 → random → C                  │                │
│  │  请求2 → random → A                  │                │
│  │  请求3 → random → C  ← 可能重复！    │                │
│  │  请求4 → random → E                  │                │
│  └──────────────────────────────────────┘                │
│  优点：简单，适合少量请求                                  │
│  缺点：可能连续使用同一个出口                                │
│                                                          │
│  策略二：轮询选择                                          │
│  ┌──────────────────────────────────────┐                │
│  │  授权代理: [A, B, C, D, E]           │                │
│  │                                      │                │
│  │  请求1 → A                            │                │
│  │  请求2 → B                            │                │
│  │  请求3 → C                            │                │
│  │  请求4 → D                            │                │
│  │  请求5 → E                            │                │
│  │  请求6 → A  ← 回到第一个              │                │
│  └──────────────────────────────────────┘                │
│  优点：负载更均匀，不会连续压同一个出口                    │
│  缺点：需要维护代理健康状态                                │
└──────────────────────────────────────────────────────────┘
```

```python
import random
import itertools


class AuthorizedProxySelector:
    """授权代理选择器——支持多种可用性选择策略"""

    def __init__(self, proxy_list):
        self._proxies = proxy_list
        self._cycle = itertools.cycle(proxy_list)  # 无限循环迭代器
        self._recent = []  # 记录最近使用的代理

    def random_pick(self):
        """策略一：随机选择"""
        return random.choice(self._proxies)

    def round_robin(self):
        """策略二：轮询选择"""
        return next(self._cycle)

    def avoid_repeat_pick(self):
        """策略三：避免连续重复的随机选择"""
        available = [p for p in self._proxies if p not in self._recent[-2:]]
        if not available:
            available = self._proxies
        proxy = random.choice(available)
        self._recent.append(proxy)
        if len(self._recent) > 5:
            self._recent.pop(0)
        return proxy


# 使用
proxies = [
    "http://1.1.1.1:8080",
    "http://2.2.2.2:8080",
    "http://3.3.3.3:8080",
]

selector = AuthorizedProxySelector(proxies)

print("随机选择：")
for _ in range(5):
    print(f"  {selector.random_pick()}")

print("\n避免重复：")
for _ in range(5):
    print(f"  {selector.avoid_repeat_pick()}")
```

## 七、请求延迟与随机间隔

### 7.1 为什么需要延迟？

没有延迟的爬虫会在短时间内给目标站点造成明显压力。合理的延迟可以降低峰值请求量，也方便你在被限流时主动收敛。

```
┌──────────────────────────────────────────────────────────┐
│  请求间隔对比                                              │
│                                                          │
│  ❌ 无间隔：                                               │
│  req → req → req → req → req → req → req                 │
│  每秒 10+ 个请求，明显是机器人                              │
│                                                          │
│  ❌ 固定间隔（1秒）：                                      │
│  req ──1s── req ──1s── req ──1s── req                    │
│  太规律了，机器人也可以做到                                  │
│                                                          │
│  ✅ 随机间隔（1~3秒）：                                    │
│  req ──1.3s── req ──2.7s── req ──1.8s── req              │
│  不固定，降低短时间集中请求压力                              │
│                                                          │
│  ✅✅ 更真实的模式：                                       │
│  req ──1.3s── req ──2.7s── req ──0.8s── req ──4.1s──     │
│  偶尔快一点，偶尔慢一点，甚至偶尔"休息"更久                  │
└──────────────────────────────────────────────────────────┘
```

### 7.2 实现随机延迟

```python
import time
import random


def random_delay(min_seconds=1, max_seconds=3):
    """随机等待一段时间"""
    delay = random.uniform(min_seconds, max_seconds)
    time.sleep(delay)
    return delay


def human_like_delay():
    """模拟人类行为的延迟——偶尔快，偶尔慢"""
    rand = random.random()

    if rand < 0.1:
        # 10% 的概率：快速请求（人在快速浏览）
        delay = random.uniform(0.3, 0.8)
    elif rand < 0.7:
        # 60% 的概率：正常速度
        delay = random.uniform(1.0, 2.5)
    elif rand < 0.9:
        # 20% 的概率：稍慢（人在看内容）
        delay = random.uniform(2.5, 5.0)
    else:
        # 10% 的概率：长时间停顿（人在思考、看手机等）
        delay = random.uniform(5.0, 15.0)

    time.sleep(delay)
    return delay
```

### 7.3 遇到错误时增加延迟

```python
import time
import requests


def fetch_with_backoff(url, headers, max_retries=3):
    """遇到错误时逐渐增加等待时间"""
    base_delay = 1  # 基础延迟 1 秒

    for attempt in range(max_retries):
        try:
            response = requests.get(url, headers=headers, timeout=10)

            if response.status_code == 200:
                return response

            if response.status_code == 429:
                # 被限流了，等待更久
                wait = base_delay * (2 ** attempt) + random.uniform(0, 1)
                print(f"被限流，等待 {wait:.1f} 秒后重试...")
                time.sleep(wait)
                continue

            if response.status_code == 403:
                print(f"被拒绝访问: {url}")
                return None

        except requests.exceptions.Timeout:
            wait = base_delay * (2 ** attempt)
            print(f"超时，等待 {wait} 秒后重试...")
            time.sleep(wait)
        except requests.exceptions.ConnectionError:
            wait = base_delay * (2 ** attempt)
            print(f"连接失败，等待 {wait} 秒后重试...")
            time.sleep(wait)

    print(f"重试 {max_retries} 次后放弃")
    return None
```

## 八、指数退避重试策略

### 8.1 什么是指数退避？

指数退避（Exponential Backoff）是一种重试策略：每次失败后，等待时间翻倍。第一次等 1 秒，第二次等 2 秒，第三次等 4 秒，第四次等 8 秒……

```
┌──────────────────────────────────────────────────────────┐
│  指数退避原理                                              │
│                                                          │
│  等待时间 = 基础延迟 × 2^重试次数 + 随机抖动               │
│                                                          │
│  第1次失败 → 等 1 秒  ± 随机                              │
│  第2次失败 → 等 2 秒  ± 随机                              │
│  第3次失败 → 等 4 秒  ± 随机                              │
│  第4次失败 → 等 8 秒  ± 随机                              │
│  第5次失败 → 等 16 秒 ± 随机                              │
│                                                          │
│  为什么要翻倍？                                            │
│  如果服务器正在过载，你越频繁重试，它越忙。                  │
│  逐渐拉长间隔，给服务器"喘息"的机会。                       │
│                                                          │
│  为什么要加随机抖动？                                      │
│  如果所有爬虫都用相同的退避策略，它们会同时重试，            │
│  造成"惊群效应"。加随机抖动可以让重试时间分散开。            │
└──────────────────────────────────────────────────────────┘
```

### 8.2 用 requests 内置的重试机制

```python
import requests
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry


def create_robust_session():
    """创建带指数退避重试的 Session"""
    session = requests.Session()

    # 定义重试策略
    retry_strategy = Retry(
        total=5,                          # 总共最多重试 5 次
        backoff_factor=1,                 # 退避因子（1秒 × 2^n）
        status_forcelist=[429, 500, 502, 503, 504],  # 这些状态码触发重试
        allowed_methods=["GET", "HEAD"],  # 只对这些方法重试
        raise_on_status=False,            # 不抛异常，让我们自己处理
    )

    # 创建适配器并挂载到 Session
    adapter = HTTPAdapter(max_retries=retry_strategy)
    session.mount("http://", adapter)
    session.mount("https://", adapter)

    # 设置默认请求头
    session.headers.update({
        "User-Agent": (
            "Mozilla/5.0 (Windows NT 10.0; Win64; x64) "
            "AppleWebKit/537.36 Chrome/120.0.0.0 Safari/537.36"
        ),
        "Accept-Language": "zh-CN,zh;q=0.9",
    })

    return session


# 使用
session = create_robust_session()
response = session.get("https://httpbin.org/status/503", timeout=10)
# 如果返回 503，urllib3 会自动重试并使用指数退避
print(response.status_code)
```

### 8.3 自定义更精细的重试逻辑

```python
import requests
import time
import random


class RetryHandler:
    """自定义重试处理器"""

    def __init__(self, max_retries=3, base_delay=1, max_delay=60):
        self.max_retries = max_retries
        self.base_delay = base_delay
        self.max_delay = max_delay

    def execute(self, func, *args, **kwargs):
        """执行函数，失败时自动重试"""
        last_exception = None

        for attempt in range(self.max_retries + 1):
            try:
                result = func(*args, **kwargs)

                # 检查 HTTP 状态码
                if hasattr(result, 'status_code'):
                    if result.status_code == 200:
                        return result
                    if result.status_code == 403:
                        print("被拒绝访问，不重试")
                        return result
                    if result.status_code == 429:
                        # 429 需要等待更久
                        retry_after = result.headers.get("Retry-After")
                        if retry_after:
                            wait = int(retry_after)
                        else:
                            wait = self._calculate_delay(attempt)
                        print(f"被限流，等待 {wait:.1f} 秒 ({attempt+1}/{self.max_retries})")
                        time.sleep(wait)
                        continue

                return result

            except requests.exceptions.Timeout as e:
                last_exception = e
                print(f"超时 ({attempt+1}/{self.max_retries})")
            except requests.exceptions.ConnectionError as e:
                last_exception = e
                print(f"连接失败 ({attempt+1}/{self.max_retries})")
            except requests.exceptions.ProxyError as e:
                last_exception = e
                print(f"代理错误 ({attempt+1}/{self.max_retries})")
                # 代理错误可能需要换代理，这里只做等待
            except Exception as e:
                last_exception = e
                print(f"未知错误: {e} ({attempt+1}/{self.max_retries})")

            if attempt < self.max_retries:
                wait = self._calculate_delay(attempt)
                print(f"等待 {wait:.1f} 秒后重试...")
                time.sleep(wait)

        print(f"重试 {self.max_retries} 次后放弃")
        raise last_exception

    def _calculate_delay(self, attempt):
        """计算退避时间：base × 2^attempt + 随机抖动"""
        delay = self.base_delay * (2 ** attempt)
        # 加随机抖动（±25%）
        jitter = delay * random.uniform(-0.25, 0.25)
        delay = max(0.5, delay + jitter)
        # 不超过最大延迟
        return min(delay, self.max_delay)


# 使用示例
retry_handler = RetryHandler(max_retries=3, base_delay=2)

def fetch_page(url):
    headers = {"User-Agent": "Mozilla/5.0 Chrome/120.0.0.0"}
    return requests.get(url, headers=headers, timeout=10)

try:
    response = retry_handler.execute(fetch_page, "https://httpbin.org/get")
    print(f"成功: {response.status_code}")
except Exception as e:
    print(f"最终失败: {e}")
```

```python
import requests
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry
import time
import random


class PoliteCrawler:
    """礼貌爬虫——集成项目 UA、可选授权代理、延迟、重试"""

    def __init__(self, authorized_proxies=None):
        self.user_agent = "MarketInsightCrawler/1.0 (+mailto:data-team@example.com)"
        self.proxies = authorized_proxies or []
        self._used_proxies = []

    def _create_session(self):
        """创建配置好的 Session"""
        session = requests.Session()

        # 设置清晰、稳定、可联系的项目 UA
        session.headers.update({
            "User-Agent": self.user_agent,
            "Accept": "text/html,application/xhtml+xml,*/*;q=0.8",
            "Accept-Language": "zh-CN,zh;q=0.9,en;q=0.8",
            "Accept-Encoding": "gzip, deflate, br",
        })

        # 设置重试策略
        retry = Retry(total=3, backoff_factor=1, status_forcelist=[500, 503])
        adapter = HTTPAdapter(max_retries=retry)
        session.mount("http://", adapter)
        session.mount("https://", adapter)

        return session

    def _get_proxy(self):
        """获取一个授权代理（如果有的话）"""
        if not self.proxies:
            return None
        # 避免连续压同一个授权出口
        available = [p for p in self.proxies if p not in self._used_proxies[-2:]]
        if not available:
            available = self.proxies
        proxy = random.choice(available)
        self._used_proxies.append(proxy)
        if len(self._used_proxies) > 10:
            self._used_proxies.pop(0)
        return proxy

    def _random_delay(self):
        """随机延迟"""
        delay = random.uniform(1, 3)
        time.sleep(delay)
        return delay

    def get(self, url, **kwargs):
        """发送 GET 请求"""
        session = self._create_session()

        # 设置代理
        proxy = self._get_proxy()
        if proxy:
            kwargs["proxies"] = {"http": proxy, "https": proxy}

        # 设置超时
        kwargs.setdefault("timeout", 10)

        try:
            response = session.get(url, **kwargs)
            print(f"[{response.status_code}] {url[:60]}... "
                  f"(UA: {session.headers['User-Agent'][:30]}...)")
            if response.status_code in (403, 429):
                print("  目标站点拒绝访问或限流，请降频、暂停或申请授权")
            return response
        except requests.exceptions.Timeout:
            print(f"[超时] {url[:60]}...")
        except requests.exceptions.ConnectionError:
            print(f"[连接失败] {url[:60]}...")
        except Exception as e:
            print(f"[错误] {url[:60]}... - {e}")

        return None

    def crawl(self, urls, callback=None):
        """批量爬取多个 URL"""
        results = []

        for i, url in enumerate(urls):
            response = self.get(url)

            if response and response.status_code == 200:
                if callback:
                    data = callback(response)
                    results.append(data)
                else:
                    results.append(response.text)

            # 随机延迟（最后一个不需要等）
            if i < len(urls) - 1:
                delay = self._random_delay()
                print(f"  等待 {delay:.1f} 秒...")

        return results


# 使用示例
def parse_page(response):
    """自定义解析函数"""
    # 这里用 BeautifulSoup 解析
    return {"url": response.url, "length": len(response.text)}

    authorized_proxies=["http://1.1.1.1:8080"]  # 可选，仅使用授权代理

    "https://httpbin.org/get",
    "https://httpbin.org/headers",
    "https://httpbin.org/ip",
]
```

### 练习三：综合礼貌爬虫

```python
"""
目标：编写一个完整的礼貌爬虫
要求：
1. 使用稳定、可联系的项目 UA
2. 使用 Session 管理
3. 每次请求间有 1~3 秒随机延迟
4. 遇到错误自动重试（最多 3 次，指数退避）
5. 爬取 https://httpbin.org/headers 的前 5 次请求
6. 打印每次使用的 UA 和状态码
"""
import requests
import time
import random

PROJECT_UA = "LearningScraper/1.0 (contact@example.com)"

def polite_fetch(url, max_retries=3):
    """礼貌地发送请求"""
    for attempt in range(max_retries):
        # 稳定、可联系的项目 UA
        headers = {"User-Agent": PROJECT_UA}

        try:
            with requests.Session() as session:
                session.headers.update(headers)
                response = session.get(url, timeout=10)

                if response.status_code == 200:
                    return response
                elif response.status_code == 429:
                    wait = 2 ** attempt + random.uniform(0, 1)
                    print(f"  被限流，等待 {wait:.1f} 秒...")
                    time.sleep(wait)
                elif response.status_code == 403:
                    print("  被拒绝访问，暂停任务并检查授权或访问规则")
                    return response
                else:
                    print(f"  状态码 {response.status_code}，重试...")
        except requests.exceptions.Timeout:
            print(f"  超时，重试...")
        except Exception as e:
            print(f"  错误: {e}")

        if attempt < max_retries - 1:
            time.sleep(2 ** attempt)

    return None

# 爬取 5 次
for i in range(5):
    print(f"\n请求 {i+1}:")
    result = polite_fetch("https://httpbin.org/headers")
    if result:
        used_ua = result.json()["headers"]["User-Agent"]
        print(f"  状态码: {result.status_code}")
        print(f"  使用的 UA: {used_ua[:50]}...")

    if i < 4:
        delay = random.uniform(1, 3)
        print(f"  等待 {delay:.1f} 秒...")
        time.sleep(delay)
```

## 常见误区

- **User-Agent 随机轮换能绕过一切检测**：频繁切换不同浏览器、不同系统的 UA 反而更可疑——同一个"用户"不可能一会儿是 iPhone 一会儿是 Windows PC。稳定、清晰、可联系的 UA 比随机 UA 更可靠。
- **加了代理就不会被封**：代理只改变了出口 IP，但如果你的请求频率太高、UA 不对、缺少 Cookie，换了 IP 一样会被封。代理是辅助手段，不是万能药。
- **固定间隔 1 秒就是"礼貌"了**：固定的 1 秒间隔太规律了，机器人特征明显。随机间隔（1-3 秒）才更接近人类行为模式，偶尔还可以插入更长的"休息"。
- **重试次数越多越好**：重试太多次会给服务器造成更大压力，也可能触发更严厉的封禁。一般 3-5 次重试足够，配合指数退避让间隔越来越长。

---

## 工程建议

- **用 Session 管理所有请求配置**：把 UA、Accept-Language、重试策略等配置集中在 Session 上，避免每个请求都重复设置，也方便统一修改。
- **用 urllib3 内置的 Retry 机制**：`HTTPAdapter` + `Retry` 组合能自动处理 429、500 等状态码的重试和退避，比手写重试循环更可靠。
- **被 403 时先排查再重试**：403 不是网络错误，重试大概率还是 403。应该先检查 UA、Cookie、Referer 等请求头是否正确，确认目标站点的访问规则后再继续。
- **给自己留"停止开关"**：在爬虫中设置最大请求数限制和日志记录，出了问题能快速定位和停止，避免失控的爬虫造成不可挽回的后果。

## 小结

本课的核心知识点：

1. **请求头设置是稳定采集的基础**——至少要设置 User-Agent、Accept、Accept-Language
2. **fake_useragent 库**可以方便地生成浏览器 UA，用于学习不同客户端标识的差异
3. **用 Session 管理请求头**，设置一次，所有请求自动携带
4. **代理 IP 是请求转发节点**——学习时用于理解网络链路，正式使用必须确认授权边界
5. **代理类型分 HTTP/HTTPS/SOCKS**，不同协议适合不同网络场景
6. **免费代理不稳定且有隐私风险**，不要用来访问登录态或敏感数据
7. **代理配置**仅用于学习、内网、测试或授权场景，使用前要确认目标站点规则
8. **随机延迟**（1~3 秒）降低请求压力，避免固定频率造成误判
9. **指数退避**在遇到错误时逐渐增加等待时间，避免给服务器施压
10. **礼貌爬虫 = 明确 UA + 合理延迟 + 智能重试 + 遵守规则**
