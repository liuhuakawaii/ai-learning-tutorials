# 为什么用 Python 写爬虫

## 一个前端开发者的困惑

产品经理丢过来一个需求："把竞品网站上 500 个商品的价格、评分、评论数全部抓下来，每天更新一次。"你打开 DevTools 看了看网络请求，数据是 HTML 渲染的，不是 API 返回的 JSON。手动复制粘贴？500 个商品每天一次，这不是人干的活。

你需要一个程序自动打开网页、读取内容、提取数据——这就是爬虫。但用什么语言写？Node.js 的 cheerio 也能做，Java 的 Jsoup 也行，为什么几乎所有爬虫教程都推荐 Python？

## 爬虫到底在做什么

爬虫的核心流程只有四步：

```
发送请求 → 获取响应 → 解析数据 → 存储数据
```

用前端开发者熟悉的话来说：

- **发送请求** → 就像在浏览器地址栏输入 URL 并回车
- **获取响应** → 就像 DevTools Network 面板里的 Response
- **解析数据** → 就像用 `document.querySelector()` 提取 DOM 节点
- **存储数据** → 就像把数据存进 localStorage，只不过爬虫通常存文件或数据库

浏览器是给人看的，爬虫是给程序用的。浏览器一次一页、手动操作；爬虫可以批量、并发、全自动。

## Python 的三个核心优势

**生态最强**。几乎所有需求都有成熟的库：

| Python 库 | 前端类比 | 作用 |
|---|---|---|
| `requests` | `fetch()` / `axios` | 发送 HTTP 请求 |
| `BeautifulSoup` | `document.querySelector()` | 解析和提取 HTML |
| `Scrapy` | 一套完整的爬虫框架 | 大规模结构化爬虫 |
| `Playwright` | Puppeteer | 控制真实浏览器 |
| `pandas` | lodash + Excel | 数据清洗和分析 |

**代码最短**。同一个爬虫逻辑，Python 版本最直观：

```python
import requests
from bs4 import BeautifulSoup

response = requests.get("https://example.com/books")
soup = BeautifulSoup(response.text, "html.parser")
for book in soup.select(".book-title"):
    print(book.text)
```

对比 Java 版本需要类定义、异常声明、import 一大堆，Python 四行搞定。

**社区最活跃**。Stack Overflow 上 Python 爬虫问题超过 10 万个，GitHub 上 Python 爬虫项目数量远超其他语言。遇到问题不怕找不到答案。

## 前端开发者的天然优势

你不是从零开始：

| 你已经会的 | 爬虫需要的 |
|---|---|
| HTML 结构 | 解析网页结构 |
| CSS 选择器 | 定位元素 |
| JavaScript | 理解异步请求、DOM 操作 |
| HTTP 协议 | 发送请求、处理响应 |
| 浏览器 DevTools | 分析网页、调试爬虫 |
| JSON 格式 | 处理 API 返回的数据 |

你只需要换一种语言来操作你已经熟悉的东西。

## 法律边界

三条底线：

1. **尊重 robots.txt**：每个网站根目录下的 `robots.txt` 告诉你哪些可以爬
2. **控制频率**：不要对网站发起过于频繁的请求
3. **不碰隐私**：个人身份信息、手机号、地址不要碰

公开可访问的数据通常可以爬；绕过验证码、破解加密、爬取个人隐私有违法风险。技术上能做到不等于法律上允许做。

## 参考答案

### 练习一

想象你是一个家长，想给孩子找最便宜的辅导书。跑了三家书店，每家翻一遍书架记下价格，最后回家对比。每天都去翻很累。爬虫就像雇了一个助手，告诉他"去这三家书店把价格抄回来"，他自动跑一趟就回来了。

四个步骤：出发去书店（发送请求）→ 看到书架上的书（获取响应）→ 找到价格标签（解析数据）→ 记在本子上（存储数据）。

### 练习二

1. **数据**：商品名称、当前价格、原价、评分、评论数、库存状态
2. **技术**：requests 发请求，BeautifulSoup 解析 HTML，cron 定时执行，pandas 做趋势分析
3. **困难**：反爬机制（验证码、IP 封禁）、页面结构改版、价格显示为图片

### 练习三

- **A**：通常可以爬。公开数据，遵守 robots.txt，控制频率。
- **B**：违法风险极高。绕过验证码属于突破安全防护。
- **C**：通常可以爬，但注意方式。遵守 robots.txt，不影响网站运行。
- **D**：违法风险极高。手机号属于个人隐私，批量采集违反个人信息保护法。
