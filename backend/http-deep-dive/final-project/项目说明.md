# HTTP 调试工具 — 课程毕业项目

## 项目目标

构建一个本地运行的 HTTP 调试工具，能够拦截、分析、重放 HTTP 请求，并支持缓存策略验证、CORS 配置检测、请求对比等工程场景。项目需要覆盖 HTTP 协议课程中讲到的核心知识点：报文结构、缓存机制、CORS、内容协商、连接管理、HTTPS 握手等。

## 技术栈

- **运行时**：Node.js 18+
- **HTTP 代理**：`http-proxy` 或自行实现 CONNECT/普通代理
- **前端界面**：React 或 Vue（可选，也可以是终端 TUI）
- **存储**：SQLite（请求日志）或 JSON 文件
- **TLS**：`node:tls`、自签名证书生成
- **测试**：Vitest 或 Jest

## 核心功能

### 模块一：请求拦截与抓包

- 启动本地代理服务器，浏览器配置后可拦截所有 HTTP/HTTPS 流量
- 记录每个请求的完整报文：方法、URL、请求头、请求体、状态码、响应头、响应体
- 支持 HTTPS MITM（中间人解密），需生成并信任本地 CA 证书
- 请求列表支持按域名、状态码、方法、大小筛选

### 模块二：请求重放与编辑

- 选中任意已捕获请求，修改参数后重新发送
- 支持修改 URL、方法、请求头、请求体
- 对比重放结果与原始响应的差异（状态码、响应头、响应体大小、耗时）

### 模块三：缓存策略测试

- 对同一资源发起多次请求，观察 `Cache-Control`、`ETag`、`Last-Modified` 的交互行为
- 支持强制刷新（`Cache-Control: no-cache`）与正常刷新的对比
- 可视化展示缓存命中/未命中状态，标注每次请求走的是强缓存、协商缓存还是源站
- 支持手动修改缓存头，验证不同策略的效果

### 模块四：CORS 检测

- 输入目标 URL，自动发送预检请求（OPTIONS），解析 `Access-Control-*` 头
- 检测常见 CORS 配置问题：
  - `Access-Control-Allow-Origin` 与实际 Origin 不匹配
  - 缺少 `Access-Control-Allow-Methods` 或 `Access-Control-Allow-Headers`
  - `Access-Control-Allow-Credentials` 与通配符 `*` 冲突
  - 预检请求未返回正确的状态码
- 输出 CORS 配置健康报告，标注问题与修复建议

### 模块五：连接与性能分析

- 展示每个请求的时间线：DNS 解析、TCP 连接、TLS 握手、首字节时间、内容下载
- 支持 HTTP/1.1 与 HTTP/2 的连接复用对比
- 统计请求数、总传输大小、缓存节省的带宽

## 阶段交付物

| 阶段 | 交付物 | 路径 |
|------|--------|------|
| 阶段一 | 代理服务器与请求捕获 | `http-debug-tool/src/proxy/` |
| 阶段二 | 请求重放与差异对比 | `http-debug-tool/src/replay/` |
| 阶段三 | 缓存策略测试模块 | `http-debug-tool/src/cache-tester/` |
| 阶段四 | CORS 检测模块 | `http-debug-tool/src/cors-checker/` |
| 阶段五 | 性能分析与完整报告 | `http-debug-tool/src/performance/` + `reports/final-report.md` |

## 验收标准

- [ ] 能够通过本地代理拦截 HTTP 和 HTTPS 请求，并完整记录报文
- [ ] HTTPS MITM 解密正常工作，能看到加密前的请求内容
- [ ] 能选中任意请求进行重放，修改后重新发送并看到结果差异
- [ ] 缓存测试模块能展示强缓存命中、协商缓存 304、缓存未命中三种状态
- [ ] CORS 检测能正确识别至少 4 种常见配置问题
- [ ] 请求时间线展示 DNS/TCP/TLS/TTFB/Download 各阶段耗时
- [ ] 所有核心模块有单元测试，覆盖主要路径
- [ ] 项目可通过 `npm run check` 验证结构完整性
