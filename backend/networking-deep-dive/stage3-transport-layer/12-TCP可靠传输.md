# TCP 可靠传输——序列号、确认号、重传机制

## TCP 如何保证可靠传输

IP 层是不可靠的：包可能丢失、乱序、重复。TCP 在 IP 之上构建了可靠传输机制：

1. **序列号**：每个字节都有编号，接收方可以检测乱序和重复
2. **确认号**：接收方告诉发送方"我收到了哪些数据"
3. **重传**：发送方在超时后重传未确认的数据
4. **校验和**：检测数据在传输中是否损坏

## 序列号和确认号

TCP 对每个字节进行编号。序列号（Seq）表示这个段中第一个字节的编号，确认号（Ack）表示"我期望收到的下一个字节的编号"。

```
发送方 → 接收方
Seq=1000, 数据长度=100  →  表示发送了字节 1000-1099
接收方 → 发送方
Ack=1100                →  表示"我已收到 1000-1099，期望收到 1100"
```

这种机制实现了累积确认：Ack=1100 表示 1100 之前的所有字节都已收到。

## 滑动窗口

TCP 使用滑动窗口来提高效率。发送方可以连续发送多个段，不需要等待每个段的确认。

```
发送窗口: [1000, 1500)
已发送未确认: [1000, 1200)
可发送: [1200, 1500)
不可发送: ≥1500
```

窗口大小由接收方通告（rwnd），表示接收方的缓冲区还能容纳多少数据。

## 超时重传

发送方为每个未确认的段设置定时器。如果超时未收到确认，重传该段。

超时时间（RTO）的计算：
1. 测量 RTT（往返时间）
2. 计算 SRTT（平滑 RTT）和 RTTVAR（RTT 变化）
3. RTO = SRTT + 4 × RTTVAR

RTO 会根据网络状况动态调整。如果网络延迟稳定，RTO 较小；如果延迟波动大，RTO 较大。

## 快速重传

如果发送方收到 3 个重复的 ACK，立即重传丢失的段，不等待超时。

```
发送方 → 段1 (Seq=1000) → 接收方
发送方 → 段2 (Seq=1100) → 丢失
发送方 → 段3 (Seq=1200) → 接收方 → Ack=1100（期望收到 1100）
发送方 → 段4 (Seq=1300) → 接收方 → Ack=1100（重复 ACK）
发送方 → 段5 (Seq=1400) → 接收方 → Ack=1100（重复 ACK）
发送方 → 收到 3 个重复 ACK → 立即重传段2
```

快速重传比超时重传快得多，通常在几十毫秒内触发。

## SACK（选择性确认）

标准 TCP 使用累积确认，发送方只能知道"1100 之前的数据都收到了"，不知道哪些具体段已收到。

SACK 允许接收方告诉发送方"我收到了哪些不连续的段"：

```
SACK: 1200-1300, 1400-1500
```

这样发送方只需要重传真正丢失的段（1100-1200），提高了重传效率。

## TCP 校验和

TCP 校验和覆盖 TCP 头部、数据和伪头部（源 IP、目的 IP、协议号、TCP 长度）。

如果校验和验证失败，接收方丢弃该段，不发送确认。发送方超时后重传。

```bash
# 在 Wireshark 中查看校验和
# 展开 TCP 层 → Checksum

# 如果校验和错误，Wireshark 会显示 "[TCP checksum error]"
```

## 参考答案

### 练习一

典型数据传输：
```
段1: Seq=1000, Ack=5000, 数据长度=1460
段2: Seq=2460, Ack=5000, 数据长度=1460
段3: Seq=3920, Ack=5000, 数据长度=1460
段4: Seq=5380, Ack=5000, 数据长度=1460
段5: Seq=6840, Ack=5000, 数据长度=1460
```

验证：Seq(n+1) = Seq(n) + 数据长度(n)

**关键点**：序列号按字节编号，不是按段编号。每个段的序列号是该段第一个字节的编号。

### 练习二

模拟丢包：
```bash
# 添加 5% 丢包
sudo tc qdisc add dev eth0 root netem loss 5%

# 下载文件
curl -o /dev/null http://example.com

# Wireshark 过滤重传
# tcp.analysis.retransmission

# 统计重传率
# 重传段数 / 总段数 × 100%
```

**常见错误**：以为丢包就一定导致重传。实际上 TCP 的快速重传机制可以在超时前重传，减少延迟。SACK 可以只重传丢失的部分，而不是整个窗口。

**工程意义**：了解重传机制有助于诊断网络性能问题。高重传率通常意味着网络质量差或拥塞。
