# 网络排查工具链——ping/traceroute/mtr/ss/tcpdump/nc

## 工具链概览

网络排查需要一套工具，从不同角度观察网络行为：

| 工具 | 用途 | 层级 |
|------|------|------|
| ping | 连通性和延迟 | ICMP |
| traceroute | 路径发现 | ICMP/UDP |
| mtr | 持续路径监控 | ICMP |
| ss | 连接状态 | TCP/UDP |
| tcpdump | 抓包分析 | 链路层-应用层 |
| nc | 端口测试 | TCP/UDP |

## ping：基础连通性测试

ping 发送 ICMP Echo Request，等待 ICMP Echo Reply。

```bash
# 基本 ping
ping 8.8.8.8

# 指定次数
ping -c 5 8.8.8.8

# 指定大小
ping -s 1000 8.8.8.8

# 指定间隔
ping -i 0.5 8.8.8.8

# 指定超时
ping -W 2 8.8.8.8
```

ping 的输出：
```
PING 8.8.8.8 (8.8.8.8) 56(84) bytes of data.
64 bytes from 8.8.8.8: icmp_seq=1 ttl=118 time=20.1 ms
64 bytes from 8.8.8.8: icmp_seq=2 ttl=118 time=20.2 ms
64 bytes from 8.8.8.8: icmp_seq=3 ttl=118 time=20.0 ms

--- 8.8.8.8 ping statistics ---
3 packets transmitted, 3 received, 0% packet loss, time 2003ms
rtt min/avg/max/mdev = 20.0/20.1/20.2/0.1 ms
```

关键指标：
- **time**：往返时间（RTT）
- **packet loss**：丢包率
- **ttl**：生存时间

## traceroute：路径发现

traceroute 显示到目标的完整路径。

```bash
# 基本 traceroute
traceroute 8.8.8.8

# 使用 TCP（绕过 ICMP 过滤）
traceroute -T 8.8.8.8

# 使用 UDP
traceroute -U 8.8.8.8

# 指定端口
traceroute -T -p 80 8.8.8.8

# 指定最大跳数
traceroute -m 15 8.8.8.8
```

输出解读：
```
traceroute to 8.8.8.8 (8.8.8.8), 30 hops max, 60 byte packets
 1  192.168.1.1  1.234 ms  1.123 ms  1.098 ms
 2  10.0.0.1  5.678 ms  5.567 ms  5.456 ms
 3  * * *
 4  8.8.8.8  20.123 ms  20.012 ms  19.901 ms
```

第 3 跳 `* * *` 表示没有响应（路由器配置了不返回 ICMP）。

## mtr：持续路径监控

mtr 结合了 ping 和 traceroute，持续监控路径变化。

```bash
# 基本 mtr
mtr 8.8.8.8

# 指定次数
mtr -c 100 8.8.8.8

# 报告模式
mtr -r -c 100 8.8.8.8

# 指定间隔
mtr -i 0.5 8.8.8.8
```

输出解读：
```
Host                   Loss%   Snt   Last   Avg  Best  Wrst StDev
1. 192.168.1.1          0.0%   100    1.1   1.2   1.0   1.5   0.1
2. 10.0.0.1             0.0%   100    5.5   5.6   5.4   5.8   0.1
3. 172.16.0.1           5.0%   100   12.3  12.4  12.1  12.8   0.2
4. ???
5. 8.8.8.8              0.0%   100   20.1  20.2  19.9  20.5   0.1
```

## ss：连接状态查看

ss 是 netstat 的替代品，显示 TCP/UDP 连接状态。

```bash
# 查看所有 TCP 连接
ss -t

# 查看所有 UDP 连接
ss -u

# 查看监听端口
ss -tln

# 查看所有连接（包括监听）
ss -tuna

# 按状态过滤
ss -t state established
ss -t state time-wait
ss -t state syn-recv

# 按端口过滤
ss -t dst :80

# 查看进程信息
ss -tlnp
```

输出解读：
```
State    Recv-Q    Send-Q       Local Address:Port       Peer Address:Port
LISTEN   0         128              0.0.0.0:22             0.0.0.0:*
ESTAB    0         0          192.168.1.100:22       192.168.1.1:54321
TIME-WAIT 0        0          192.168.1.100:80       93.184.216.34:443
```

## tcpdump：抓包分析

tcpdump 是命令行抓包工具。

```bash
# 基本抓包
sudo tcpdump -i eth0

# 指定接口
sudo tcpdump -i eth0

# 指定主机
sudo tcpdump -i eth0 host 8.8.8.8

# 指定端口
sudo tcpdump -i eth0 port 80

# 指定协议
sudo tcpdump -i eth0 tcp

# 组合过滤
sudo tcpdump -i eth0 host 8.8.8.8 and port 443

# 保存到文件
sudo tcpdump -i eth0 -w capture.pcap

# 读取文件
sudo tcpdump -r capture.pcap

# 显示详细信息
sudo tcpdump -i eth0 -v

# 显示十六进制
sudo tcpdump -i eth0 -X
```

常用过滤器：
```bash
# TCP SYN 包
tcpdump 'tcp[tcpflags] & (tcp-syn) != 0'

# TCP RST 包
tcpdump 'tcp[tcpflags] & (tcp-rst) != 0'

# HTTP GET 请求
tcpdump 'tcp dst port 80 and tcp[((tcp[12:1] & 0xf0) >> 2):4] = 0x47455420'
```

## nc：端口测试

nc（netcat）是网络调试工具。

```bash
# 测试 TCP 端口
nc -zv 8.8.8.8 80

# 测试 UDP 端口
nc -zvu 8.8.8.8 53

# 创建 TCP 服务器
nc -l 8080

# 创建 UDP 服务器
nc -lu 8080

# 发送数据
echo "hello" | nc 8.8.8.8 80

# 端口扫描
nc -zv 192.168.1.1 1-100
```

## 排查流程

### 第一步：检查连通性

```bash
ping 8.8.8.8
```

如果 ping 失败：
- 检查网线/Wi-Fi 连接
- 检查 IP 地址配置
- 检查路由表

### 第二步：检查路径

```bash
traceroute 8.8.8.8
```

如果某跳延迟高或丢包：
- 记录 IP 地址
- 联系网络管理员

### 第三步：检查端口

```bash
nc -zv 8.8.8.8 80
```

如果端口不通：
- 检查防火墙规则
- 检查服务是否运行
- 检查监听地址

### 第四步：抓包分析

```bash
sudo tcpdump -i eth0 host 8.8.8.8 and port 80 -w debug.pcap
```

分析抓包结果：
- 是否有 SYN 包
- 是否有 SYN-ACK 响应
- 是否有重传
- 是否有 RST 包

假设你无法访问 http://example.com，用工具链排查问题：
1. ping 测试连通性
2. traceroute 查看路径
3. nc 测试端口
4. tcpdump 抓包分析

1. ping 失败但 traceroute 成功，可能是什么原因？

3. ss 和 netstat 有什么区别？

## 参考答案

### 练习一

排查步骤：
```bash
# 1. ping 测试
ping -c 3 example.com
# 如果失败，检查 DNS 解析
dig example.com

# 2. traceroute 查看路径
traceroute example.com

# 3. 测试端口
nc -zv example.com 80

# 4. 抓包分析
sudo tcpdump -i eth0 host example.com and port 80 -w debug.pcap
```

### 练习二

1. **ping 失败但 traceroute 成功**：可能是目标服务器配置了禁止 ICMP，或者防火墙阻止了 ICMP。

2. **抓 TCP SYN 包**：
   ```bash
   sudo tcpdump 'tcp[tcpflags] & (tcp-syn) != 0'
   ```

3. **ss vs netstat**：ss 更快，信息更详细，支持更多过滤选项。netstat 已经不再维护。

**常见错误**：只用 ping 测试连通性。实际上 ping 只能测试 ICMP，不能测试 TCP/UDP 端口。
