# 网络性能分析——带宽 vs 延迟、BDP、窗口大小

## 带宽与延迟的区别

**带宽**：单位时间内可以传输的数据量（如 100 Mbps）。
**延迟**：数据从发送到接收的时间（如 50 ms）。

带宽是"管道的粗细"，延迟是"管道的长度"。

### 例子

- 光纤 1 Gbps，RTT 50 ms：高带宽低延迟
- 4G 10 Mbps，RTT 100 ms：中等带宽中等延迟
- 卫星 1 Mbps，RTT 600 ms：低带宽高延迟

## BDP（带宽延迟积）

BDP = 带宽 × 延迟

BDP 表示"在途数据的最大量"，也就是"管道的容量"。

### 计算例子

- 带宽 100 Mbps，RTT 50 ms
- BDP = 100 Mbps × 0.05 s = 5 Mbit = 625 KB

如果 TCP 窗口小于 625 KB，带宽利用不充分。

### 实际应用

```bash
# 计算 BDP
bandwidth_mbps=100
rtt_ms=50
bdp_bytes=$((bandwidth_mbps * rtt_ms * 1000 / 8))
echo "BDP: $bdp_bytes bytes"
```

## TCP 窗口大小

TCP 窗口大小决定发送方可以发送多少未确认的数据。

### 接收窗口（rwnd）

接收方通告的窗口大小，表示接收缓冲区还能容纳多少数据。

```bash
# 查看当前窗口大小
ss -t | grep "win:"

# 查看窗口缩放因子
ss -ti | grep "wscale"
```

### 拥塞窗口（cwnd）

发送方维护的窗口大小，根据网络状况调整。

```bash
# 查看拥塞窗口
ss -t | grep "cwnd:"
```

### 窗口大小对性能的影响

窗口大小 < BDP：带宽利用不充分
窗口大小 > BDP：增加延迟，可能导致丢包

最优窗口大小 ≈ BDP

## 实验：测量网络性能

### 用 iperf3 测量带宽

```bash
# 服务端
iperf3 -s

# 客户端
iperf3 -c <server_ip> -t 30

# 测量不同窗口大小
iperf3 -c <server_ip> -w 64K -t 30
iperf3 -c <server_ip> -w 256K -t 30
iperf3 -c <server_ip> -w 1M -t 30
```

### 用 ping 测量延迟

```bash
# 测量 RTT
ping -c 100 8.8.8.8

# 输出示例:
# rtt min/avg/max/mdev = 19.9/20.1/20.3/0.1 ms
```

### 用 mtr 测量路径延迟

```bash
# 持续监控
mtr -c 100 8.8.8.8
```

## 网络性能瓶颈分析

### 瓶颈类型

**带宽瓶颈**：数据传输速率受限于带宽。
- 症状：吞吐量接近带宽上限
- 解决：增加带宽

**延迟瓶颈**：数据传输受限于延迟。
- 症状：吞吐量远低于带宽上限
- 解决：减少延迟（CDN、就近部署）

**丢包瓶颈**：数据传输受限于丢包率。
- 症状：吞吐量不稳定，重传多
- 解决：改善网络质量

### 瓶颈判断方法

```bash
# 测量带宽
iperf3 -c <server_ip> -t 30

# 测量延迟
ping -c 100 <server_ip>

# 测量丢包
ping -c 1000 <server_ip> | tail -1

# 计算理论吞吐量
# 理论吞吐量 = BDP / RTT = 带宽
# 实际吞吐量 = 窗口大小 / RTT
```

## 实验：网络性能优化

### 优化 TCP 窗口大小

```bash
# 查看当前窗口大小
sysctl net.ipv4.tcp_rmem
sysctl net.ipv4.tcp_wmem

# 增大窗口大小
sudo sysctl -w net.ipv4.tcp_rmem="4096 87380 16777216"
sudo sysctl -w net.ipv4.tcp_wmem="4096 65536 16777216"
```

### 启用窗口缩放

```bash
# 查看窗口缩放
sysctl net.ipv4.tcp_window_scaling

# 启用窗口缩放
sudo sysctl -w net.ipv4.tcp_window_scaling=1
```

### 启用选择性确认（SACK）

```bash
# 查看 SACK
sysctl net.ipv4.tcp_sack

# 启用 SACK
sudo sysctl -w net.ipv4.tcp_sack=1
```

## 实验：对比不同网络条件

### 模拟不同网络条件

```bash
# 正常网络
iperf3 -c <server_ip> -t 30

# 高延迟网络
sudo tc qdisc add dev eth0 root netem delay 100ms
iperf3 -c <server_ip> -t 30
sudo tc qdisc del dev eth0 root

# 丢包网络
sudo tc qdisc add dev eth0 root netem loss 1%
iperf3 -c <server_ip> -t 30
sudo tc qdisc del dev eth0 root

# 带宽限制
sudo tc qdisc add dev eth0 root tbf rate 10mbit burst 32kbit latency 400ms
iperf3 -c <server_ip> -t 30
sudo tc qdisc del dev eth0 root
```

### 分析结果

| 条件 | 吞吐量 | 延迟 | 丢包 |
|------|--------|------|------|
| 正常 | 941 Mbps | 20 ms | 0% |
| 高延迟 | 500 Mbps | 120 ms | 0% |
| 丢包 | 200 Mbps | 20 ms | 1% |
| 带宽限制 | 10 Mbps | 20 ms | 0% |

## 练习

### 练习一：计算 BDP

给定以下网络参数，计算 BDP：
- 带宽：1 Gbps
- RTT：100 ms

如果 TCP 窗口大小是 64 KB，吞吐量是多少？

### 练习二：网络性能测试

1. 用 iperf3 测量你到不同目标的吞吐量
2. 用 ping 测量延迟
3. 计算 BDP 和实际吞吐量的差距
4. 分析瓶颈原因

---

## 参考答案

### 练习一

BDP = 1 Gbps × 0.1 s = 100 Mbit = 12.5 MB

如果窗口大小是 64 KB：
吞吐量 = 窗口大小 / RTT = 64 KB / 0.1 s = 640 KB/s = 5 Mbps

**关键点**：窗口大小只有 64 KB 时，吞吐量只有 5 Mbps，远低于 1 Gbps 带宽。需要增大窗口大小才能充分利用带宽。

### 练习二

```bash
# 测量到不同目标
iperf3 -c <server1> -t 30
iperf3 -c <server2> -t 30

# 测量延迟
ping -c 100 <server1>
ping -c 100 <server2>

# 计算 BDP
bandwidth_mbps=100
rtt_ms=50
bdp_bytes=$((bandwidth_mbps * rtt_ms * 1000 / 8))
echo "BDP: $bdp_bytes bytes"
```

**常见错误**：以为带宽越大吞吐量越高。实际上延迟和窗口大小也严重影响吞吐量。高延迟网络需要更大的窗口才能充分利用带宽。
