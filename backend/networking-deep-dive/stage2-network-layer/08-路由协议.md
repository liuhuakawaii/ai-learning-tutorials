# 路由协议——静态路由、OSPF、BGP 的直觉理解

## 路由器在做什么

路由器的工作很简单：收到一个 IP 包，查路由表，决定从哪个接口转发出去。

路由表的每一行包含：
- 目的网络（如 192.168.1.0/24）
- 下一跳地址（如 10.0.0.1）
- 出接口（如 eth0）
- 度量值（如 跳数、带宽、延迟）

路由器收到包后：
1. 提取目的 IP 地址
2. 查路由表，找到匹配的条目（最长前缀匹配）
3. 把包从对应接口转发出去
4. TTL 减 1

## 静态路由：手动配置

最简单的路由方式：管理员手动配置每条路由。

```bash
# Linux 添加静态路由
ip route add 192.168.2.0/24 via 10.0.0.1 dev eth0

# 查看路由表
ip route show
```

静态路由的优点：
- 配置简单，易于理解
- 不消耗带宽和 CPU
- 安全可控

静态路由的缺点：
- 网络拓扑变化时需要手动更新
- 无法自动绕过故障链路
- 不适合大规模网络

适合场景：小型网络、默认路由、特殊路由规则。

## 动态路由协议

大规模网络需要动态路由协议，让路由器自动学习和更新路由信息。

### RIP（Routing Information Protocol）

最简单的动态路由协议，使用跳数作为度量值。

```
路由器A: "我到 192.168.1.0/24 需要 1 跳"
路由器B: "我到 192.168.1.0/24 需要 2 跳（经过 A）"
```

RIP 的问题：
- 最大跳数 15，超过认为不可达
- 每 30 秒广播整个路由表
- 收敛慢，可能产生环路

现在基本不用了，只在小型网络或教学中出现。

### OSPF（Open Shortest Path First）

OSPF 是链路状态协议，每个路由器都知道整个网络的拓扑。

工作原理：
1. 每个路由器收集邻居信息（Hello 协议）
2. 构建链路状态数据库（LSDB）
3. 用 Dijkstra 算法计算到每个目的网络的最短路径
4. 更新路由表

OSPF 的优点：
- 收敛快（秒级）
- 支持多区域，适合大规模网络
- 支持等价多路径（ECMP）
- 没有跳数限制

OSPF 的缺点：
- 配置复杂
- 需要更多 CPU 和内存
- 需要规划区域

适合场景：企业内部网络、数据中心。

### BGP（Border Gateway Protocol）

BGP 是互联网的核心路由协议，用于自治系统（AS）之间的路由。

自治系统（AS）是互联网的基本单位：
- 一个 ISP 是一个 AS
- 一个大型企业可能是一个 AS
- 每个 AS 有唯一的编号（ASN）

BGP 的工作方式：
1. AS 之间建立邻居关系（TCP 连接）
2. 交换路由信息（NLRI）
3. 根据路径属性选择最佳路由
4. 把路由传播给其他邻居

BGP 的关键概念：
- **AS_PATH**：路由经过的 AS 列表，用于防环和路径选择
- **LOCAL_PREF**：本地优先级，影响出站流量
- **MED**：多出口鉴别器，影响入站流量
- **Community**：路由标记，用于策略控制

BGP 的特点：
- 基于策略的路由，不只是最短路径
- 支持复杂的路由策略
- 收敛慢（分钟级）
- 互联网路由表超过 100 万条

## 路由选择过程

当路由器收到多个路由更新时，按以下顺序选择：

1. 最长前缀匹配（/24 优先于 /16）
2. 管理距离（静态路由优先于 OSPF，OSPF 优先于 RIP）
3. 度量值（OSPF 的 cost，RIP 的跳数）
4. 如果都相同，负载均衡

## 实验：观察路由行为

### 查看路由表

```bash
# Linux
ip route show
route -n

# Windows
route print
```

### 添加静态路由

```bash
# Linux: 把 192.168.2.0/24 的流量发给 10.0.0.1
sudo ip route add 192.168.2.0/24 via 10.0.0.1

# 验证
ip route get 192.168.2.100
```

### 用 traceroute 观察路径

```bash
# 查看到 8.8.8.8 的路径
traceroute 8.8.8.8

# 用 mtr 持续观察
mtr 8.8.8.8
```

### 抓包观察 OSPF

```bash
# 抓取 OSPF Hello 包
sudo tcpdump -i eth0 ospf -nn

# OSPF 使用组播地址 224.0.0.5 和 224.0.0.6
```

## 练习

### 练习一：路由表分析

给定以下路由表：
```
192.168.1.0/24 via 10.0.0.1 dev eth0
192.168.0.0/16 via 10.0.0.2 dev eth1
0.0.0.0/0 via 10.0.0.3 dev eth0
```

目标地址 192.168.1.100 会从哪个接口转发？192.168.2.100 呢？8.8.8.8 呢？

### 练习二：回答问题

1. 为什么 BGP 使用 TCP 而不是 UDP？
2. OSPF 为什么需要划分区域？
3. 为什么互联网不使用单一的路由协议？

---

## 参考答案

### 练习一

- 192.168.1.100：匹配 /24（最长前缀），从 eth0 转发，下一跳 10.0.0.1
- 192.168.2.100：匹配 /16，从 eth1 转发，下一跳 10.0.0.2
- 8.8.8.8：匹配默认路由 0.0.0.0/0，从 eth0 转发，下一跳 10.0.0.3

**关键点**：最长前缀匹配。/24 比 /16 更具体，优先匹配。

### 练习二

1. **BGP 用 TCP**：BGP 需要可靠的路由信息传输，TCP 提供确认和重传。而且 BGP 邻居通常跨越多个 AS，UDP 无法保证送达。

2. **OSPF 划分区域**：减少链路状态数据库的大小，减少 SPF 计算次数，限制拓扑变化的影响范围。骨干区域 Area 0 连接其他区域。

3. **不使用单一协议**：互联网由多个自治系统组成，每个 AS 内部和 AS 之间的需求不同。IGP（如 OSPF）负责 AS 内部路由，BGP 负责 AS 之间路由。这种分层设计让每个 AS 可以独立管理内部网络。

**常见错误**：以为 BGP 是"更好"的路由协议。实际上 BGP 和 OSPF 解决不同的问题，BGP 解决的是策略路由和跨域路由，OSPF 解决的是域内最短路径。
