# 子网划分与 CIDR——从 /24 到 /16 的工程含义

## 为什么需要子网划分

假设你有一个 /24 的网络（192.168.1.0/24），里面有 254 台设备。现在公司有三个部门：开发部 100 人，市场部 50 人，财务部 30 人。

问题：
1. 所有设备在同一个广播域，广播流量会很多
2. 无法按部门实施不同的安全策略
3. IP 地址分配不灵活

解决方案：把 /24 划分成多个更小的子网。

## 子网掩码的工作原理

子网掩码决定 IP 地址中哪些位是网络部分，哪些位是主机部分。

```
IP 地址:    192.168.1.100  = 11000000.10101000.00000001.01100100
子网掩码:   255.255.255.0  = 11111111.11111111.11111111.00000000
                            网络部分                      主机部分
```

子网掩码中连续的 1 表示网络部分，连续的 0 表示主机部分。

用 CIDR 表示法：192.168.1.100/24 表示前 24 位是网络部分。

## 划分子网的计算

把 192.168.1.0/24 划分成 4 个子网：

```
原始网络: 192.168.1.0/24 (256 个地址)
    ↓ 借 2 位主机位
子网 1: 192.168.1.0/26   (64 个地址: .0 - .63)
子网 2: 192.168.1.64/26  (64 个地址: .64 - .127)
子网 3: 192.168.1.128/26 (64 个地址: .128 - .191)
子网 4: 192.168.1.192/26 (64 个地址: .192 - .255)
```

每个子网的可用主机数 = 2^主机位数 - 2（减去网络地址和广播地址）。

/26 的主机位数是 6 位，所以每个子网有 2^6 - 2 = 62 个可用地址。

## 子网划分的实际应用

### 场景一：公司网络

```
公司网络: 10.0.0.0/16
    开发部: 10.0.1.0/24  (254 台设备)
    市场部: 10.0.2.0/24  (254 台设备)
    财务部: 10.0.3.0/24  (254 台设备)
    服务器: 10.0.100.0/24 (254 台服务器)
```

### 场景二：云服务 VPC

```
VPC: 172.16.0.0/16
    公有子网: 172.16.1.0/24 (Web 服务器)
    私有子网: 172.16.2.0/24 (数据库)
    管理子网: 172.16.3.0/24 (跳板机)
```

### 场景三：数据中心

```
数据中心网络: 10.0.0.0/8
    机架 1: 10.1.0.0/16
        服务器 1-254: 10.1.1.0/24
        服务器 255-508: 10.1.2.0/24
    机架 2: 10.2.0.0/16
        ...
```

## CIDR 与路由聚合

CIDR 不仅用于子网划分，还用于路由聚合（supernetting）。

假设你有 4 个 /24 网络：
- 192.168.0.0/24
- 192.168.1.0/24
- 192.168.2.0/24
- 192.168.3.0/24

可以聚合成一个 /22：192.168.0.0/22

路由聚合的好处：
- 减少路由表条目
- 减少路由器的内存和计算负担
- 简化网络管理

| 地址范围 | 用途 |
|---------|------|
| 0.0.0.0/8 | 本网络 |
| 10.0.0.0/8 | 私有地址 |
| 127.0.0.0/8 | 回环地址 |
| 169.254.0.0/16 | 链路本地地址 |
| 172.16.0.0/12 | 私有地址 |
| 192.168.0.0/16 | 私有地址 |
| 224.0.0.0/4 | 组播地址 |
| 255.255.255.255 | 受限广播 |

私有地址不能在互联网上路由，需要通过 NAT 转换。

## 实验：子网计算

### 计算子网信息

给定 IP 地址和子网掩码，计算：
- 网络地址
- 广播地址
- 可用主机范围
- 可用主机数

```bash
# 用 ipcalc 工具
ipcalc 192.168.1.100/26

# 输出示例:
# Address:   192.168.1.100
# Netmask:   255.255.255.192 = 26
# Network:   192.168.1.64/26
# Broadcast: 192.168.1.127
# HostMin:   192.168.1.65
# HostMax:   192.168.1.126
# Hosts/Net: 62
```

### 手动计算

IP: 192.168.1.100
子网掩码: /26

1. 把 IP 转换成二进制：
   ```
   192.168.1.100 = 11000000.10101000.00000001.01100100
   ```

2. /26 表示前 26 位是网络部分：
   ```
   网络部分: 11000000.10101000.00000001.01
   主机部分: 100100
   ```

3. 网络地址：主机部分全 0
   ```
   11000000.10101000.00000001.01000000 = 192.168.1.64
   ```

4. 广播地址：主机部分全 1
   ```
   11000000.10101000.00000001.01111111 = 192.168.1.127
   ```

5. 可用主机范围：网络地址+1 到广播地址-1
   ```
   192.168.1.65 - 192.168.1.126
   ```

## 练习

### 练习一：子网划分

把 10.0.0.0/8 划分成至少 1000 个子网，每个子网至少 1000 台主机。应该怎么划分子网掩码？

### 练习二：路由聚合

把以下 4 个子网聚合成一个：
- 172.16.0.0/24
- 172.16.1.0/24
- 172.16.2.0/24
- 172.16.3.0/24

---

## 参考答案

### 练习一

/8 有 24 位主机位。要至少 1000 个子网，需要 10 位（2^10=1024）。要每个子网至少 1000 台主机，需要 10 位（2^10-2=1022）。

10+10=20 位，加上原来的 8 位网络部分，总共 28 位。但 /8 只有 8 位网络部分，所以需要从主机位借 20 位，得到 /28。

但 /28 的主机位只有 4 位，只能容纳 14 台主机，不够 1000 台。

正确答案：这是个陷阱题。/8 的地址空间总共只有 2^24=1677 万个地址。要 1000 个子网 × 1000 台主机 = 100 万个地址，理论上可行。但子网掩码必须是 /18（2^6=64 个子网，每个子网 2^10-2=1022 台主机），但 64 个子网不够 1000 个。

实际上，/8 无法同时满足 1000 个子网和每个子网 1000 台主机。需要使用更大的地址空间或重新规划。

### 练习二

观察这 4 个子网：
```
172.16.0.0 = 10101100.00010000.00000000.00000000
172.16.1.0 = 10101100.00010000.00000001.00000000
172.16.2.0 = 10101100.00010000.00000010.00000000
172.16.3.0 = 10101100.00010000.00000011.00000000
```

共同前缀：前 22 位相同（10101100.00010000.000000）

聚合结果：172.16.0.0/22

**常见错误**：以为子网划分和路由聚合是相反的操作。实际上路由聚合是把多个小网络合并成一个大网络，减少路由表条目。
