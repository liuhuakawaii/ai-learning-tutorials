# 阶段实战：用 traceroute/mtr 定位网络路径瓶颈

## 任务目标

在这个实战中，你要用 traceroute 和 mtr 工具分析网络路径，定位延迟和丢包的瓶颈，并理解路由路径的实际含义。

## traceroute 的工作原理

traceroute 利用 TTL（生存时间）字段来发现路径：

1. 发送 TTL=1 的 UDP 包，第一个路由器返回 ICMP 超时
2. 发送 TTL=2 的 UDP 包，第二个路由器返回 ICMP 超时
3. 重复直到到达目的地

每一跳的输出包含：
- 跳数
- 路由器的 IP 地址
- 三个 RTT（往返时间）

```
traceroute to 8.8.8.8 (8.8.8.8), 30 hops max, 60 byte packets
 1  192.168.1.1  1.234 ms  1.123 ms  1.098 ms
 2  10.0.0.1  5.678 ms  5.567 ms  5.456 ms
 3  172.16.0.1  12.345 ms  12.234 ms  12.123 ms
 4  * * *
 5  8.8.8.8  20.123 ms  20.012 ms  19.901 ms
```

第 4 跳显示 `* * *` 表示没有收到响应，可能是路由器配置了不返回 ICMP 超时。

## mtr：持续的 traceroute

mtr 是 traceroute 的增强版，持续发送包并统计结果。

```bash
# 安装 mtr
sudo apt install mtr  # Debian/Ubuntu
sudo yum install mtr  # CentOS/RHEL

# 运行 mtr
mtr 8.8.8.8
```

mtr 的输出包含：
- 跳数
- 路由器 IP 和主机名
- 丢包率（Loss%）
- 发送的包数（Snt）
- 平均/最佳/最差延迟（Avg/Best/Wrst）
- 最后一个包的延迟（Last）

```
Host                   Loss%   Snt   Last   Avg  Best  Wrst StDev
1. 192.168.1.1          0.0%   100    1.1   1.2   1.0   1.5   0.1
2. 10.0.0.1             0.0%   100    5.5   5.6   5.4   5.8   0.1
3. 172.16.0.1           5.0%   100   12.3  12.4  12.1  12.8   0.2
4. ???
5. 8.8.8.8              0.0%   100   20.1  20.2  19.9  20.5   0.1
```

## 如何解读结果

### 丢包分析

**中间跳丢包**：如果第 3 跳有 5% 丢包，但最终目标没有丢包，这通常不是问题。路由器可能优先处理转发流量，对 ICMP 超时响应较低优先级。

**最终跳丢包**：如果第 5 跳（目标）有丢包，这是真正的问题。

**逐跳增加丢包**：如果丢包率逐跳增加（0% → 5% → 15% → 30%），说明问题在那个方向。

### 延迟分析

**延迟突增**：如果第 2 跳延迟 5ms，第 3 跳延迟 50ms，说明第 2 跳到第 3 跳之间有瓶颈。

**延迟稳定**：如果延迟稳定在某个值附近，说明网络质量好。

**延迟波动**：如果延迟波动很大（标准差高），说明网络拥塞或不稳定。

## 实验：分析到不同目标的路径

### 实验一：分析到国内目标的路径

```bash
# 到百度
mtr -c 100 baidu.com

# 到阿里云
mtr -c 100 alibaba.com

# 记录每一跳的延迟和丢包
```

### 实验二：分析到国外目标的路径

```bash
# 到 Google
mtr -c 100 google.com

# 到 Cloudflare
mtr -c 100 cloudflare.com

# 观察国际链路的延迟
```

### 实验三：对比不同 ISP

如果你有多个网络接口（如 Wi-Fi 和有线），对比同一目标在不同网络下的路径。

```bash
# 通过 Wi-Fi
mtr -c 100 -i wlan0 8.8.8.8

# 通过有线
mtr -c 100 -i eth0 8.8.8.8
```

## 常见路径问题

### 问题一：某跳延迟突然增加

```
3. 172.16.0.1  12.3 ms
4. 10.0.0.1  150.5 ms  ← 延迟突增
5. 8.8.8.8  20.1 ms
```

可能原因：
- 路由器过载
- 跨运营商链路
- 国际链路
- 无线链路

### 问题二：某跳丢包

```
3. 172.16.0.1  12.3 ms
4. 10.0.0.1  50%  ← 丢包
5. 8.8.8.8  20.1 ms
```

如果最终目标没有丢包，通常是路由器配置问题。如果最终目标也有丢包，需要联系网络管理员。

### 问题三：路由环路

```
3. 10.0.0.1  5.5 ms
4. 10.0.0.2  12.3 ms
5. 10.0.0.1  15.5 ms  ← 回到第 3 跳
6. 10.0.0.2  18.3 ms
```

路由环路说明路由配置有误，包在两个路由器之间循环。

## 参考答案

### 练习一

示例分析：

```
到 baidu.com 的路径：
1. 192.168.1.1  1ms (本地网关)
2. 10.0.0.1  5ms (ISP 接入)
3. 172.16.0.1  15ms (ISP 骨干)
4. 220.181.0.1  25ms (百度 CDN)
5. baidu.com  30ms (目标)
```

延迟分析：
- 第 1-2 跳：4ms 增加，正常
- 第 2-3 跳：10ms 增加，可能是跨城域网
- 第 3-4 跳：10ms 增加，正常

### 练习二

1. **中间跳丢包但最终不丢包**：路由器可能对 ICMP 超时响应设置较低优先级，把 CPU 用于转发流量。这不是真正的问题。

2. **判断延迟瓶颈**：找到延迟增加最大的那一跳。如果第 3 跳到第 4 跳延迟增加 100ms，说明瓶颈在这两跳之间。

3. **路径不一致**：路由器可能使用等价多路径（ECMP），不同包走不同路径。或者路由表在变化。

**常见错误**：看到中间跳丢包就认为网络有问题。实际上中间跳的丢包可能是 ICMP 限速，不是真正的丢包。关注最终目标的丢包率。
