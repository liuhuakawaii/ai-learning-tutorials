# 以太网帧——MAC 地址、VLAN、ARP 协议

## 为什么需要 MAC 地址

IP 地址解决的是"数据包要去哪里"，MAC 地址解决的是"这一跳怎么送达"。

同一个 IP 包从源到目的地，经过每一跳时 MAC 地址都在变，但 IP 地址不变。这就是链路层和网络层的分工：

```
你的电脑 (MAC: AA) → 路由器 (MAC: BB) → 目标服务器 (MAC: CC)
IP: 192.168.1.100 → IP: 93.184.216.34

第一跳：帧的源MAC=AA, 目的MAC=BB（你的电脑发给路由器）
第二跳：帧的源MAC=BB, 目的MAC=CC（路由器发给服务器）
```

MAC 地址是 48 位，通常写成 6 组十六进制数。前 3 字节是 OUI（厂商标识），后 3 字节由厂商分配。理论上全球唯一，但虚拟化环境中经常是随机生成的。

## ARP：MAC 地址从哪里来

你的电脑知道目标 IP，但不知道目标 MAC。ARP 协议解决这个问题。

ARP 的工作方式是广播：

```
你的电脑: "谁是 192.168.1.1？请告诉 192.168.1.100"
    ↓ 广播到整个局域网
路由器:   "192.168.1.1 是我，我的 MAC 是 BB:BB:BB:BB:BB:BB"
    ↓ 单播回复
你的电脑: 记录到 ARP 缓存表
```

ARP 缓存有生存时间（通常 20 分钟），过期后需要重新查询。

## VLAN：逻辑隔离物理网络

交换机默认所有端口在同一个广播域。一个广播帧会被所有端口收到。当网络规模增大，广播流量会成为问题。

VLAN（虚拟局域网）把一个物理交换机逻辑上划分成多个独立的交换机：

- VLAN 10：端口 1-8（开发部）
- VLAN 20：端口 9-16（财务部）
- 不同 VLAN 之间默认不能通信

802.1Q 标准在以太网帧中插入 4 字节的 VLAN 标签：

```
原始帧: [DST MAC][SRC MAC][Type][Payload][FCS]
带VLAN: [DST MAC][SRC MAC][0x8100][VLAN ID][Type][Payload][FCS]
```

VLAN ID 是 12 位，范围 1-4094。其中 VLAN 1 是默认 VLAN，VLAN 4094 通常保留。

## Trunk 端口与 Access 端口

交换机端口有两种模式：

- **Access 端口**：连接终端设备（电脑、打印机），只属于一个 VLAN
- **Trunk 端口**：连接另一个交换机或路由器，可以承载多个 VLAN 的流量

Trunk 端口会在帧上打 VLAN 标签，对端设备根据标签判断帧属于哪个 VLAN。

## 广播风暴与 STP

如果交换机之间有多条链路形成环路，广播帧会无限循环：

```
交换机A → 交换机B → 交换机C → 交换机A → ...
```

STP（生成树协议）通过阻塞冗余端口来打破环路。它选举一个根交换机，其他交换机计算到根的最短路径，阻塞不在最短路径上的端口。

STP 的收敛时间通常需要 30-50 秒，这在现代网络中太慢了。RSTP（快速 STP）把收敛时间缩短到几秒。

## 实验：抓包观察 ARP 和 VLAN

### 观察 ARP 请求

```bash
# Linux: 抓取 ARP 包
sudo tcpdump -i eth0 arp -nn

# 在另一个终端触发 ARP 请求
ping 192.168.1.1
```

你会看到类似这样的输出：
```
ARP, Request who-has 192.168.1.1 tell 192.168.1.100, length 28
ARP, Reply 192.168.1.1 is-at aa:bb:cc:dd:ee:ff, length 28
```

### 查看 ARP 缓存

```bash
# Linux
arp -n
ip neigh show

# Windows
arp -a
```

### Wireshark 中观察 ARP

1. 开始抓包
2. 清除 ARP 缓存：`sudo ip neigh flush all`（Linux）或 `arp -d *`（Windows，管理员）
3. `ping` 同一局域网的设备
4. 在 Wireshark 中过滤 `arp`
5. 观察 ARP Request 和 ARP Reply 的帧结构

## 为什么 ARP 是安全隐患

ARP 协议没有任何认证机制。任何人都可以发送 ARP Reply 声称"我是 192.168.1.1"，即使他不是。

这就是 **ARP 欺骗**（ARP Spoofing）攻击的基础。攻击者可以：
1. 向受害者发送虚假 ARP Reply，声称自己是网关
2. 向网关发送虚假 ARP Reply，声称自己是受害者
3. 受害者的流量经过攻击者转发（中间人攻击）

防御方法：
- 静态 ARP 表（规模小的网络）
- 动态 ARP 检测（DAI，交换机功能）
- 802.1X 端口认证

## 参考答案

### 练习一

- ARP Request 是**广播**（目的 MAC: ff:ff:ff:ff:ff:ff）
- ARP Reply 是**单播**（目的 MAC: 请求者的 MAC）

ARP Reply 用单播是因为请求者已经在 Request 中包含了自己的 MAC 地址，Reply 不需要广播。

### 练习二

典型 VLAN 配置：
```
端口 1-8:   VLAN 10 (Access)
端口 9-16:  VLAN 20 (Access)
端口 24:    Trunk (允许 VLAN 10, 20)
```

**常见错误**：以为 VLAN 是"软件隔离"就一定安全。实际上 VLAN 只是在交换机层面隔离广播域，如果攻击者能物理访问 Trunk 端口，可以嗅探所有 VLAN 的流量。
