# 数据包的旅程——从网卡到交换机的二进制世界

## 一根网线里到底发生了什么

当你在浏览器里敲下 `curl example.com`，这个动作最终变成了一连串电信号，沿着网线以接近光速传播。但"电信号"这个说法太笼统了——实际发生的事情远比这复杂。

网卡把内存中的数据转换成电信号或光信号，通过物理介质发送出去。这个过程有几个关键步骤：

1. 应用层数据经过协议栈层层封装
2. 网卡驱动把帧数据从内核内存拷贝到网卡的发送缓冲区（DMA）
3. 网卡芯片把二进制数据编码成物理信号
4. 信号通过双绞线/光纤/无线电波发送

## 二进制如何变成电信号

以太网使用 **曼彻斯特编码**（10BASE-T）或 **PAM-5 编码**（1000BASE-T）把 0 和 1 变成电压变化。

曼彻斯特编码的规则很简单：
- 每个比特周期中间有一次电压跳变
- 从低到高跳变表示 1
- 从高到低跳变表示 0

这种编码的好处是接收方可以从信号本身恢复时钟——不需要单独的时钟线。代价是每个比特需要两个电压状态，所以信号频率是数据速率的两倍。

千兆以太网用 PAM-5 编码，每个符号周期传输 2 比特，用 5 个电压级别（-2, -1, 0, +1, +2）。这比曼彻斯特编码高效得多，但对信号质量要求更高。

## 交换机如何转发帧

交换机工作在链路层，它看到的是以太网帧，不是 IP 包。

交换机内部维护一个 **MAC 地址表**（CAM 表），记录每个端口连接了哪些 MAC 地址。当一个帧进入交换机：

1. 交换机读取帧的源 MAC 地址，记录到 MAC 表（学习）
2. 读取目的 MAC 地址，查表找到对应端口
3. 如果找到，从那个端口转发（单播）
4. 如果没找到，从所有端口泛洪（flood）

这个泛洪行为是早期网络中"广播风暴"的根源。如果网络中有环路，泛洪帧会无限循环，最终瘫痪整个网络。STP（生成树协议）就是为了解决这个问题。

## 从网卡到交换机：完整路径

假设你的电脑（MAC: AA:AA:AA:AA:AA:AA）要发一个帧给同一局域网的另一台电脑（MAC: BB:BB:BB:BB:BB:BB）：

```
你的电脑                              交换机                          目标电脑
   |                                   |                                |
   | 1. 网卡 DMA 发送帧                |                                |
   | --------------------------------> |                                |
   |                                   | 2. 学习源 MAC → 端口 1         |
   |                                   | 3. 查目的 MAC → 端口 2         |
   |                                   | 4. 从端口 2 转发               |
   |                                   | --------------------------------> |
   |                                   |                                | 5. 网卡接收帧
```

如果目标 MAC 不在同一局域网呢？帧会被发给网关（通常是路由器），路由器根据 IP 地址做转发。这就是链路层和网络层的分工：链路层解决"下一跳"，网络层解决"端到端"。

## 实验：观察网卡和交换机行为

在 Linux 上，你可以用 `ethtool` 查看网卡状态：

```bash
# 查看网卡链路状态和速率
ethtool eth0

# 查看网卡统计信息（丢包、错误等）
ethtool -S eth0

# 查看 MAC 地址表（需要交换机支持）
bridge fdb show
```

在 Windows 上：

```powershell
# 查看网卡信息
Get-NetAdapter | Select-Object Name, MacAddress, LinkSpeed, Status

# 查看 ARP 表
arp -a
```

用 Wireshark 抓包时，你会看到每个帧都有：
- 目的 MAC（6 字节）
- 源 MAC（6 字节）
- 类型字段（2 字节，如 0x0800 表示 IPv4）
- 有效载荷（46-1500 字节）
- FCS（4 字节，帧校验序列）

## 为什么理解物理层很重要

很多人觉得物理层"就是插网线"，不需要理解。但在工程中，物理层问题经常是网络故障的根源：

- 网线质量差导致 CRC 错误重传，表现为"网络慢"
- 交换机端口协商到半双工模式，吞吐量直接减半
- 光模块功率不足导致间歇性丢包
- 无线干扰导致 Wi-Fi 频繁重传

这些问题在应用层看起来都是"网络超时"，但根因在物理层。理解底层机制才能快速定位。

## 练习

### 练习一：查看你的网卡状态

在你的电脑上运行以下命令，记录结果：

```bash
# Linux
ethtool eth0 2>/dev/null || ethtool enp0s3
ip link show

# Windows
Get-NetAdapter | Format-Table Name, MacAddress, LinkSpeed, Status
ipconfig /all
```

记录：你的网卡 MAC 地址是什么？链路速率是多少？是全双工还是半双工？

### 练习二：用 Wireshark 观察以太网帧

1. 打开 Wireshark，选择你的网卡开始抓包
2. 在浏览器中访问 `http://example.com`
3. 停止抓包，找到一个 IPv4 帧
4. 记录目的 MAC、源 MAC、类型字段的值
5. 展开 Ethernet II 层，观察帧的完整结构

## 参考答案

### 练习一

典型输出示例（Linux）：

```
Settings for eth0:
    Speed: 1000Mb/s
    Duplex: Full
    Link detected: yes
```

MAC 地址格式：`xx:xx:xx:xx:xx:xx`，前 3 字节是 OUI（厂商标识），后 3 字节是设备唯一标识。

### 练习二

一个典型的 IPv4 帧：
- 目的 MAC：`ff:ff:ff:ff:ff:ff`（广播）或具体目标 MAC
- 源 MAC：你网卡的 MAC 地址
- 类型：`0x0800`（IPv4）或 `0x86dd`（IPv6）
- 有效载荷：IP 数据包

**常见错误**：把 MAC 地址和 IP 地址搞混。MAC 地址是链路层标识，只在局域网内有效；IP 地址是网络层标识，可以跨网络路由。
