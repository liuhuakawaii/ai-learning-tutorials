# 实验：用 Wireshark 抓取以太网帧并逐字节解读

## 为什么要做这个实验

Wireshark 是网络工程师的"显微镜"。但很多人打开 Wireshark 只会看 HTTP 请求，对链路层帧结构一无所知。

这个实验的目标是让你真正理解：一个以太网帧在网线上是什么样子的，每个字节代表什么。

## 准备工作

你需要：
- Wireshark（安装时勾选 Npcap/WinPcap）
- 一个可以抓包的网络环境（本机回环或局域网）

启动 Wireshark，选择你的网卡，开始抓包。

## 生成一个简单的帧

最简单的方式是 ping 同一局域网的设备：

```bash
# Linux/Mac
ping -c 3 192.168.1.1

# Windows
ping 192.168.1.1 -n 3
```

如果没有其他设备，ping 你的网关或路由器。

## 逐字节解读以太网帧

在 Wireshark 中找到一个 ICMP 包（ping 使用的协议），展开 Ethernet II 层。

一个标准的以太网帧结构：

```
字节偏移    长度    字段           说明
0-5         6       目的 MAC      接收方的物理地址
6-11        6       源 MAC        发送方的物理地址
12-13       2       类型          上层协议类型
14-...      46-1500 有效载荷      上层数据
最后4字节    4       FCS           帧校验序列
```

### 类型字段的含义

| 值 | 协议 |
|----|------|
| 0x0800 | IPv4 |
| 0x0806 | ARP |
| 0x86DD | IPv6 |
| 0x8100 | 802.1Q VLAN |

在 Wireshark 中，你会看到类似这样的解析：

```
Ethernet II, Src: aa:bb:cc:dd:ee:ff, Dst: 11:22:33:44:55:66
    Destination: 11:22:33:44:55:66
    Source: aa:bb:cc:dd:ee:ff
    Type: IPv4 (0x0800)
```

### 观察 ARP 帧

ARP 帧的类型字段是 0x0806，展开 ARP 层：

```
Ethernet II, Src: aa:bb:cc:dd:ee:ff, Dst: ff:ff:ff:ff:ff:ff
    Type: ARP (0x0806)
Address Resolution Protocol (request)
    Hardware type: Ethernet (1)
    Protocol type: IPv4 (0x0800)
    Hardware size: 6
    Protocol size: 4
    Opcode: request (1)
    Sender MAC address: aa:bb:cc:dd:ee:ff
    Sender IP address: 192.168.1.100
    Target MAC address: 00:00:00:00:00:00
    Target IP address: 192.168.1.1
```

注意：
- 目的 MAC 是广播地址（ff:ff:ff:ff:ff:ff）
- Target MAC 是全零（因为还不知道目标的 MAC）

## 用 Wireshark 过滤器定位帧

常用的过滤器：

```bash
# 按 MAC 地址过滤
eth.dst == aa:bb:cc:dd:ee:ff
eth.src == aa:bb:cc:dd:ee:ff

# 按协议类型过滤
eth.type == 0x0806  # ARP
eth.type == 0x0800  # IPv4

# 按 VLAN 过滤
vlan.id == 10

# 组合过滤
eth.dst == aa:bb:cc:dd:ee:ff && eth.type == 0x0800
```

## 观察帧的大小

以太网帧的有效载荷最小 46 字节，最大 1500 字节（MTU）。

如果上层数据小于 46 字节，以太网会填充（padding）到 46 字节。如果大于 1500 字节，会被分片。

在 Wireshark 中观察：
- 一个小 ping 包（ICMP payload 通常 32-64 字节）会被填充到 46 字节
- 一个 HTTP 响应可能超过 1500 字节，需要分片

## 实验：手动解析一个帧

从 Wireshark 的 Hex Dump 窗口，手动解析一个帧：

假设你看到这样的十六进制数据：

```
00 11 22 33 44 55  # 目的 MAC
aa bb cc dd ee ff  # 源 MAC
08 00              # 类型: IPv4
45 00 00 3c ...   # IPv4 头部开始
```

逐字节解读：
- `00 11 22 33 44 55`：目的 MAC 地址
- `aa bb cc dd ee ff`：源 MAC 地址
- `08 00`：类型字段，0x0800 表示 IPv4
- `45`：IPv4 版本（4）和头部长度（5×4=20 字节）

## 练习

### 练习一：抓取并解读三个不同类型的帧

1. 用 Wireshark 抓包
2. 找到一个 ARP 帧、一个 IPv4 帧、一个 IPv6 帧
3. 记录每个帧的目的 MAC、源 MAC、类型字段
4. 截图并标注关键字段

### 练习二：观察帧大小

1. 发送一个很小的 ping：`ping -s 1 192.168.1.1`（Linux）或 `ping -l 1 192.168.1.1`（Windows）
2. 在 Wireshark 中找到这个帧
3. 有效载荷是 1 字节还是被填充到了 46 字节？

---

## 参考答案

### 练习一

- ARP 帧：目的 MAC 是广播（ff:ff:ff:ff:ff:ff），类型 0x0806
- IPv4 帧：目的 MAC 是具体设备，类型 0x0800
- IPv6 帧：目的 MAC 可能是组播（33:33:xx:xx:xx:xx），类型 0x86DD

### 练习二

即使你只发送 1 字节的 ICMP 数据，以太网帧的有效载荷也会被填充到 46 字节。这是因为以太网规范要求最小帧长 64 字节（6+6+2+46+4），小于这个长度的帧会被接收方忽略。

**常见错误**：以为 ping 的大小直接决定帧的大小。实际上帧的大小 = 以太网头部（14 字节）+ 有效载荷 + FCS（4 字节），而有效载荷至少 46 字节。
