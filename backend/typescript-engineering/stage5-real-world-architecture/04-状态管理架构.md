# 04 状态管理架构

## 场景引入

你正在开发一个订单支付页面，状态逻辑非常复杂：初始状态下显示支付按钮；点击后进入加载态，按钮禁用并显示 spinner；支付成功跳转到成功页；支付失败显示重试按钮；重试三次后显示"联系客服"；用户还可以在支付过程中取消。用 `useState` 管理这些状态，代码里充斥着 `if (isLoading && !isRetrying && hasError)` 这样的条件判断，状态之间的转换关系完全隐含在代码逻辑中，任何一个新需求都可能引入状态冲突的 bug。

## 学习目标

- 理解有限状态机的核心概念：状态、事件、转换
- 使用 XState 用 TypeScript 定义类型安全的状态机
- 用 Zustand 构建类型安全的全局状态管理
- 掌握状态建模方法，将复杂业务逻辑转化为状态图
- 理解状态机与状态管理库的适用场景

## 一、有限状态机基础

有限状态机（FSM）的核心思想：**系统在任意时刻只能处于有限个状态中的一个，状态之间的转换由事件触发，转换规则是预先定义好的。**

```typescript
// 传统方式：用多个布尔值管理状态
interface PaymentState {
  isLoading: boolean
  isError: boolean
  isRetrying: boolean
  isCancelled: boolean
  retryCount: number
}

// 问题：状态组合爆炸
// isLoading=true, isError=true 合法吗？isLoading=false, isRetrying=true 呢？
// 4 个布尔值有 16 种组合，但大部分是非法状态

// 状态机方式：用明确的状态替代布尔值
type PaymentStatus =
  | 'idle'
  | 'processing'
  | 'success'
  | 'failed'
  | 'retrying'
  | 'cancelled'

interface PaymentContext {
  retryCount: number
  orderId: string | null
  errorMessage: string | null
}

type PaymentEvent =
  | { type: 'PAY'; orderId: string }
  | { type: 'SUCCESS' }
  | { type: 'FAIL'; message: string }
  | { type: 'RETRY' }
  | { type: 'CANCEL' }

// 状态转换表：明确定义每个状态下可以响应哪些事件
const transitions: Record<PaymentStatus, Partial<Record<PaymentEvent['type'], PaymentStatus>>> = {
  idle:       { PAY: 'processing' },
  processing: { SUCCESS: 'success', FAIL: 'failed', CANCEL: 'cancelled' },
  success:    {},
  failed:     { RETRY: 'retrying', CANCEL: 'cancelled' },
  retrying:   { SUCCESS: 'success', FAIL: 'failed' },
  cancelled:  {},
}
```

## 二、XState：类型安全的状态机

XState 是 TypeScript 生态中最成熟的状态机库，提供了完整的类型支持：

```typescript
import { createMachine, assign, setup } from 'xstate'

// 用 setup() 获得完整的类型推导
const paymentMachine = setup({
  types: {} as {
    context: {
      retryCount: number
      orderId: string | null
      errorMessage: string | null
    }
    events:
      | { type: 'PAY'; orderId: string }
      | { type: 'SUCCESS' }
      | { type: 'FAIL'; message: string }
      | { type: 'RETRY' }
      | { type: 'CANCEL' }
  },
  guards: {
    canRetry: ({ context }) => context.retryCount < 3,
    maxRetriesReached: ({ context }) => context.retryCount >= 3,
  },
  actions: {
    setOrderId: assign({
      orderId: ({ event }) => event.type === 'PAY' ? event.orderId : null,
    }),
    incrementRetry: assign({
      retryCount: ({ context }) => context.retryCount + 1,
    }),
    setErrorMessage: assign({
      errorMessage: ({ event }) => event.type === 'FAIL' ? event.message : null,
    }),
    clearError: assign({ errorMessage: null }),
  },
}).createMachine({
  id: 'payment',
  initial: 'idle',
  context: {
    retryCount: 0,
    orderId: null,
    errorMessage: null,
  },
  states: {
    idle: {
      on: {
        PAY: {
          target: 'processing',
          actions: ['setOrderId'],
        },
      },
    },
    processing: {
      on: {
        SUCCESS: { target: 'success' },
        FAIL: {
          target: 'failed',
          actions: ['setErrorMessage'],
        },
        CANCEL: { target: 'cancelled' },
      },
    },
    success: { type: 'final' },
    failed: {
      on: {
        RETRY: {
          target: 'retrying',
          guard: 'canRetry',
          actions: ['incrementRetry', 'clearError'],
        },
        CANCEL: { target: 'cancelled' },
      },
    },
    retrying: {
      on: {
        SUCCESS: { target: 'success' },
        FAIL: [
          {
            guard: 'canRetry',
            target: 'retrying',
            actions: ['incrementRetry', 'setErrorMessage'],
          },
          {
            guard: 'maxRetriesReached',
            target: 'failed',
            actions: ['setErrorMessage'],
          },
        ],
      },
    },
    cancelled: { type: 'final' },
  },
})

// 在 React 中使用
import { useMachine } from '@xstate/react'

function PaymentButton({ orderId }: { orderId: string }) {
  const [snapshot, send] = useMachine(paymentMachine)
  
  // snapshot.value 是当前状态，TypeScript 知道它的类型
  // snapshot.context 是上下文数据
  switch (snapshot.value) {
    case 'idle':
      return <button onClick={() => send({ type: 'PAY', orderId })}>Pay</button>
    case 'processing':
      return <Spinner />
    case 'success':
      return <div>Payment successful!</div>
    case 'failed':
      return (
        <div>
          <p>{snapshot.context.errorMessage}</p>
          {snapshot.context.retryCount < 3 && (
            <button onClick={() => send({ type: 'RETRY' })}>Retry</button>
          )}
        </div>
      )
    case 'cancelled':
      return <div>Payment cancelled</div>
  }
}
```

## 三、Zustand：类型安全的状态管理

Zustand 是轻量级状态管理库，适合管理不需要状态机的全局状态：

```typescript
import { create } from 'zustand'
import { devtools, persist } from 'zustand/middleware'
import { immer } from 'zustand/middleware/immer'

// 定义完整的 Store 类型
interface CartStore {
  // 状态
  items: CartItem[]
  coupon: Coupon | null
  
  // 操作
  addItem: (product: Product, quantity: number) => void
  removeItem: (productId: string) => void
  updateQuantity: (productId: string, quantity: number) => void
  applyCoupon: (code: string) => Promise<void>
  clearCart: () => void
  
  // 派生状态（计算属性）
  totalPrice: () => number
  itemCount: () => number
}

interface CartItem {
  productId: string
  name: string
  price: number
  quantity: number
}

// 用 immer 中间件处理不可变更新
const useCartStore = create<CartStore>()(
  devtools(
    persist(
      immer((set, get) => ({
        items: [],
        coupon: null,
        
        addItem: (product, quantity) => set((state) => {
          const existing = state.items.find(i => i.productId === product.id)
          if (existing) {
            existing.quantity += quantity
          } else {
            state.items.push({
              productId: product.id,
              name: product.name,
              price: product.price,
              quantity,
            })
          }
        }),
        
        removeItem: (productId) => set((state) => {
          state.items = state.items.filter(i => i.productId !== productId)
        }),
        
        updateQuantity: (productId, quantity) => set((state) => {
          const item = state.items.find(i => i.productId === productId)
          if (item) {
            if (quantity <= 0) {
              state.items = state.items.filter(i => i.productId !== productId)
            } else {
              item.quantity = quantity
            }
          }
        }),
        
        applyCoupon: async (code) => {
          const coupon = await api.validateCoupon(code)
          set({ coupon })
        },
        
        clearCart: () => set({ items: [], coupon: null }),
        
        totalPrice: () => {
          const { items, coupon } = get()
          const subtotal = items.reduce((sum, item) => sum + item.price * item.quantity, 0)
          if (!coupon) return subtotal
          return coupon.type === 'percent'
            ? subtotal * (1 - coupon.value / 100)
            : subtotal - coupon.value
        },
        
        itemCount: () => {
          return get().items.reduce((sum, item) => sum + item.quantity, 0)
        },
      })),
      { name: 'cart-storage' }
    )
  )
)
```

## 四、状态建模方法

将业务需求转化为状态机的关键步骤：

```typescript
// 步骤 1：识别所有可能的状态
// 一个文档编辑器的状态
type EditorStatus =
  | 'loading'      // 正在加载文档
  | 'editing'      // 正在编辑
  | 'saving'       // 正在保存
  | 'saved'        // 已保存
  | 'conflict'     // 有冲突（多人编辑）
  | 'error'        // 加载或保存失败

// 步骤 2：列出触发状态转换的事件
type EditorEvent =
  | { type: 'LOAD'; documentId: string }
  | { type: 'LOADED'; document: Document }
  | { type: 'EDIT' }
  | { type: 'SAVE' }
  | { type: 'SAVED' }
  | { type: 'CONFLICT'; remoteVersion: Document }
  | { type: 'ERROR'; message: string }
  | { type: 'RETRY' }

// 步骤 3：画出转换图（代码即文档）
const editorMachine = setup({
  types: {} as {
    context: { document: Document | null; error: string | null }
    events: EditorEvent
  },
}).createMachine({
  id: 'editor',
  initial: 'loading',
  context: { document: null, error: null },
  states: {
    loading: {
      on: {
        LOADED: { target: 'editing' },
        ERROR: { target: 'error' },
      },
    },
    editing: {
      on: {
        SAVE: { target: 'saving' },
      },
    },
    saving: {
      on: {
        SAVED: { target: 'saved' },
        CONFLICT: { target: 'conflict' },
        ERROR: { target: 'error' },
      },
    },
    saved: {
      after: {
        2000: { target: 'editing' }, // 2 秒后自动回到编辑态
      },
      on: {
        EDIT: { target: 'editing' },
      },
    },
    conflict: {
      on: {
        SAVE: { target: 'saving' }, // 强制保存
        EDIT: { target: 'editing' }, // 放弃远程修改
      },
    },
    error: {
      on: {
        RETRY: { target: 'loading' },
      },
    },
  },
})
```

## 五、状态机与 Zustand 配合

复杂项目中，状态机和 Zustand 各司其职：

```typescript
import { createActor } from 'xstate'

// 用 Zustand 管理全局数据
interface AppStore {
  user: User | null
  theme: 'light' | 'dark'
  setUser: (user: User | null) => void
  toggleTheme: () => void
}

const useAppStore = create<AppStore>((set) => ({
  user: null,
  theme: 'light',
  setUser: (user) => set({ user }),
  toggleTheme: () => set((state) => ({
    theme: state.theme === 'light' ? 'dark' : 'light',
  })),
}))

// 用状态机管理复杂流程
// 比如登录流程：idle -> submitting -> success | failed
// 状态机不存储用户数据，只管理流程状态
const loginMachine = setup({
  types: {} as {
    context: { error: string | null }
    events:
      | { type: 'SUBMIT'; email: string; password: string }
      | { type: 'SUCCESS'; user: User }
      | { type: 'FAIL'; message: string }
  },
}).createMachine({
  id: 'login',
  initial: 'idle',
  context: { error: null },
  states: {
    idle: {
      on: { SUBMIT: { target: 'submitting' } },
    },
    submitting: {
      on: {
        SUCCESS: { target: 'success' },
        FAIL: { target: 'failed' },
      },
    },
    success: { type: 'final' },
    failed: {
      on: { SUBMIT: { target: 'submitting' } },
    },
  },
})

// 组合使用
function LoginPage() {
  const [snapshot, send] = useMachine(loginMachine)
  const setUser = useAppStore((state) => state.setUser)
  
  const handleSubmit = async (email: string, password: string) => {
    send({ type: 'SUBMIT', email, password })
    try {
      const user = await api.login(email, password)
      setUser(user) // 更新全局状态
      send({ type: 'SUCCESS', user })
    } catch (error) {
      send({ type: 'FAIL', message: String(error) })
    }
  }
  
  if (snapshot.value === 'success') return <Navigate to="/dashboard" />
  
  return (
    <form onSubmit={(e) => {
      e.preventDefault()
      handleSubmit(email, password)
    }}>
      {snapshot.value === 'failed' && <p>{snapshot.context.error}</p>}
      <button disabled={snapshot.value === 'submitting'}>
        {snapshot.value === 'submitting' ? 'Logging in...' : 'Login'}
      </button>
    </form>
  )
}
```

## 常见误区

1. **所有状态都用状态机**：简单的 toggle（dark/light mode）不需要状态机，过度使用反而增加复杂度
2. **状态机中放业务逻辑**：状态机只负责"能不能做"，不负责"怎么做"，具体操作放在 action 或外部函数中
3. **Zustand store 过于庞大**：一个 store 管理所有状态，应该按领域拆分（userStore、cartStore、uiStore）
4. **忽略状态的序列化**：用 persist 中间件时，函数和 Symbol 不能被序列化，需要自定义 storage

## 工程建议

1. **先画状态图再写代码**：用 XState 的可视化工具（stately.ai/viz）画出状态转换图，团队评审后再实现
2. **状态机用于流程，Zustand 用于数据**：登录、支付、表单向导用状态机，购物车、用户信息、主题用 Zustand
3. **用 immer 中间件简化 Zustand 更新**：避免手动展开运算符，减少不可变更新的 bug
4. **类型定义放在独立文件**：Store 类型、状态机类型定义放在 `types/` 目录，方便多个组件引用

## 小结

本课介绍了有限状态机的核心概念及其在 TypeScript 中的实现，重点展示了 XState 如何用类型系统确保状态转换的安全性，以及 Zustand 如何提供类型安全的全局状态管理。核心理念：**用类型消除非法状态，让编译器帮你检查状态转换的正确性**。

## 参考答案

### 练习一

**思路**：先列出所有状态和事件，再定义每个状态下允许的事件和目标状态。

**答案**：
```typescript
import { setup, assign } from 'xstate'

const uploadMachine = setup({
  types: {} as {
    context: {
      file: File | null
      progress: number
      fileUrl: string | null
      error: string | null
    }
    events:
      | { type: 'SELECT'; file: File }
      | { type: 'UPLOAD' }
      | { type: 'PROGRESS'; percent: number }
      | { type: 'COMPLETE'; url: string }
      | { type: 'FAIL'; message: string }
      | { type: 'RETRY' }
      | { type: 'CANCEL' }
  },
}).createMachine({
  id: 'upload',
  initial: 'idle',
  context: { file: null, progress: 0, fileUrl: null, error: null },
  states: {
    idle: {
      on: {
        SELECT: {
          target: 'idle',
          actions: assign({
            file: ({ event }) => event.type === 'SELECT' ? event.file : null,
          }),
        },
        UPLOAD: { target: 'uploading', guard: ({ context }) => context.file !== null },
      },
    },
    uploading: {
      on: {
        PROGRESS: {
          target: 'uploading',
          actions: assign({
            progress: ({ event }) => event.type === 'PROGRESS' ? event.percent : 0,
          }),
        },
        COMPLETE: { target: 'processing' },
        FAIL: { target: 'failed' },
        CANCEL: { target: 'idle' },
      },
    },
    processing: {
      on: {
        COMPLETE: {
          target: 'complete',
          actions: assign({
            fileUrl: ({ event }) => event.type === 'COMPLETE' ? event.url : null,
          }),
        },
        FAIL: { target: 'failed' },
      },
    },
    complete: { type: 'final' },
    failed: {
      on: {
        RETRY: { target: 'uploading' },
        SELECT: {
          target: 'idle',
          actions: assign({
            file: ({ event }) => event.type === 'SELECT' ? event.file : null,
          }),
        },
      },
    },
  },
})
```

**要点**：
- SELECT 事件在 idle 状态下可以重复触发，用于重新选择文件
- UPLOAD 有 guard 条件：必须先选择文件才能上传
- COMPLETE 事件在 uploading 和 processing 两个状态下都可能出现

### 练习二

**思路**：用 Zustand 的 immer 中间件管理通知列表，每个通知带 id 和定时器。

**答案**：
```typescript
import { create } from 'zustand'
import { immer } from 'zustand/middleware/immer'

interface Notification {
  id: string
  type: 'success' | 'error' | 'warning' | 'info'
  message: string
}

interface NotificationStore {
  notifications: Notification[]
  add: (type: Notification['type'], message: string, duration?: number) => void
  remove: (id: string) => void
  clear: () => void
  getByType: (type: Notification['type']) => Notification[]
}

const useNotificationStore = create<NotificationStore>()(
  immer((set, get) => ({
    notifications: [],
    
    add: (type, message, duration = 5000) => {
      const id = crypto.randomUUID()
      set((state) => {
        state.notifications.push({ id, type, message })
      })
      
      if (duration > 0) {
        setTimeout(() => get().remove(id), duration)
      }
    },
    
    remove: (id) => set((state) => {
      state.notifications = state.notifications.filter(n => n.id !== id)
    }),
    
    clear: () => set({ notifications: [] }),
    
    getByType: (type) => {
      return get().notifications.filter(n => n.type === type)
    },
  }))
)
```

**要点**：
- `add` 方法自动生成 id，不需要调用方传入
- `duration` 参数控制自动消失，默认 5 秒，传 0 表示不自动消失
- `getByType` 是派生查询，不修改状态

### 练习三

**思路**：三个状态（idle、loading、loaded、failed）替代三个布尔值，事件驱动状态转换。

**答案**：
```typescript
import { setup, assign } from 'xstate'

const dataFetchMachine = setup({
  types: {} as {
    context: { data: unknown | null; error: string | null }
    events:
      | { type: 'FETCH' }
      | { type: 'SUCCESS'; data: unknown }
      | { type: 'FAIL'; message: string }
  },
}).createMachine({
  id: 'dataFetch',
  initial: 'idle',
  context: { data: null, error: null },
  states: {
    idle: {
      on: { FETCH: { target: 'loading' } },
    },
    loading: {
      entry: assign({ error: null }),
      on: {
        SUCCESS: {
          target: 'loaded',
          actions: assign({ data: ({ event }) => event.type === 'SUCCESS' ? event.data : null }),
        },
        FAIL: {
          target: 'failed',
          actions: assign({ error: ({ event }) => event.type === 'FAIL' ? event.message : null }),
        },
      },
    },
    loaded: {
      on: { FETCH: { target: 'loading' } },
    },
    failed: {
      on: { FETCH: { target: 'loading' } },
    },
  },
})

// 使用
function DataComponent() {
  const [snapshot, send] = useMachine(dataFetchMachine)
  
  useEffect(() => { send({ type: 'FETCH' }) }, [])
  
  if (snapshot.value === 'loading') return <Spinner />
  if (snapshot.value === 'failed') return (
    <div>
      <p>{snapshot.context.error}</p>
      <button onClick={() => send({ type: 'FETCH' })}>Retry</button>
    </div>
  )
  return <DataView data={snapshot.context.data} />
}
```

**要点**：
- loading 状态的 `entry` 事件清除之前的错误，避免重试时还显示旧错误
- loaded 和 failed 都可以响应 FETCH 事件，支持刷新和重试
- 不再需要 `finally { setLoading(false) }`，状态转换自动处理
