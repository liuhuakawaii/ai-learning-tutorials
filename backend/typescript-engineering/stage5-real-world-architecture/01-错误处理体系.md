# 01 错误处理体系

线上事故：用户付了钱，订单显示失败。排查发现，数据库写入失败时 `catch` 块只打了 `console.log`，支付成功但订单没创建。这不是偶发 bug，而是整个错误处理方式从根上就错了。

## try/catch 的问题

```typescript
// 函数签名不告诉你它会抛错
function parseConfig(raw: string): AppConfig {
  return JSON.parse(raw) // 调用者完全不知道这里可能炸
}

// catch 拿到的类型是 unknown，不处理也没人管你
try {
  const config = parseConfig(input)
} catch (error) {
  // error 是 unknown，你忘了处理？编译器不在乎
}
```

核心矛盾：**异常是隐式的**。编译器不知道函数会失败，调用者可以假装失败不存在。在小脚本里无所谓，在支付链路上就是定时炸弹。

## Result 模式：让失败变成类型

把"成功或失败"编码进返回类型，编译器强制你处理两种情况：

```typescript
type Result<T, E> =
  | { ok: true; value: T }
  | { ok: false; error: E }

function parseConfig(raw: string): Result<AppConfig, SyntaxError> {
  try {
    return { ok: true, value: JSON.parse(raw) as AppConfig }
  } catch (e) {
    return { ok: false, error: e instanceof SyntaxError ? e : new SyntaxError('parse failed') }
  }
}

const result = parseConfig(input)
if (result.ok) {
  console.log(result.value.port) // 类型窄化后安全访问
} else {
  console.error(result.error.message) // 必须处理错误
}
```

好处是**把运行时 bug 提前到编译时**。新加一个可能失败的步骤，忘记处理 error 分支，TypeScript 直接报红。

### 链式组合

真实业务里一个操作要经过好几步，每步都可能失败：

```typescript
function flatMap<T, U, E>(result: Result<T, E>, fn: (value: T) => Result<U, E>): Result<U, E> {
  if (!result.ok) return result
  return fn(result.value)
}

function createOrder(rawBody: string, userId: string): Result<Order, AppError> {
  return flatMap(
    parseBody(rawBody),
    (body) => flatMap(
      validateItems(body.items),
      (items) => saveOrder(userId, items)
    )
  )
  // 任何一步失败，后面的步骤都不会执行，错误直接冒泡
}
```

## 自定义错误层级

不同错误需要不同的处理策略。TransientError 该重试，ValidationError 该返回给用户，NotFoundError 该返回 404。如果所有错误都是同一个类型，你只能写 `if (error.message.includes('...'))`，那跟没有类型系统没区别。

```typescript
class AppError extends Error {
  constructor(
    message: string,
    public readonly code: string,
    public readonly statusCode: number = 500,
    public readonly context?: Record<string, unknown>
  ) {
    super(message)
    this.name = this.constructor.name
  }
}

class TransientError extends AppError {
  constructor(message: string, context?: Record<string, unknown>) {
    super(message, 'TRANSIENT_ERROR', 503, context)
  }
}

class ValidationError extends AppError {
  constructor(message: string, public readonly fields: Record<string, string>) {
    super(message, 'VALIDATION_ERROR', 400, { fields })
  }
}

class NotFoundError extends AppError {
  constructor(resource: string, id: string) {
    super(`${resource} not found: ${id}`, 'NOT_FOUND', 404, { resource, id })
  }
}
```

每个错误类应该携带排查所需的上下文——资源 ID、操作类型、请求参数。但注意脱敏，不要把用户密码塞进错误日志。

## neverthrow

手写 Result 工具函数容易出错，neverthrow 提供了完整的 API：

```typescript
import { ok, err, ResultAsync, combine } from 'neverthrow'

// 批量操作：任何一个失败，整体失败
function processBatch(ids: string[]): Result<Order[], AppError> {
  return combine(ids.map(id => getOrder(id)))
}

// 异步操作：数据库查询、外部 API
function fetchUser(id: string): ResultAsync<User, AppError> {
  return ResultAsync.fromPromise(
    db.users.findById(id),
    (error) => new DatabaseError(`Failed to fetch user ${id}`, { cause: error })
  ).andThen(user => user ? ok(user) : err(new NotFoundError('User', id)))
}
```

`ResultAsync.fromPromise` 的第二个参数是关键——它把 unknown 类的错误转成你定义的具体错误类型。

## 错误边界

错误边界不是代码层面的技巧，而是架构层面的决策：**错误在传播链的哪一层被终结**。

```typescript
// 边界 1：API 路由层 —— 业务错误转 HTTP 响应
function withErrorHandling(handler: RequestHandler): RequestHandler {
  return async (req, res, next) => {
    try {
      await handler(req, res, next)
    } catch (error) {
      if (error instanceof ValidationError) {
        res.status(400).json({ code: error.code, fields: error.fields })
      } else if (error instanceof NotFoundError) {
        res.status(404).json({ code: error.code, message: error.message })
      } else if (error instanceof AppError) {
        res.status(error.statusCode).json({ code: error.code, message: error.message })
      } else {
        logger.fatal({ err: error })
        res.status(500).json({ code: 'INTERNAL_ERROR', message: 'Something went wrong' })
      }
    }
  }
}

// 边界 2：后台任务 —— 决定重试还是放弃
async function processJob(job: Job): Promise<void> {
  const result = await executeJob(job)
  result.match(
    () => logger.info({ jobId: job.id }, 'Job completed'),
    (error) => {
      if (error instanceof TransientError && job.retryCount < 3) {
        queue.retry(job)
      } else {
        queue.moveToDeadLetter(job)
      }
    }
  )
}
```

没有错误边界，错误会一路冒泡到最顶层，要么让进程崩溃，要么被通用 `catch` 吞掉。

## 容易踩的坑

**到处用 Result**。IO 边界用 Result，内部纯函数用异常就行。过度使用 Result 让代码变臃肿。

**错误类型太粗**。只定义一个 `AppError`，所有错误长得一样，调用方没法区分处理。

**混合异常和 Result**。函数内部抛异常但返回 Result，调用方既要看类型又要 try/catch。

**丢失错误上下文**。`catch(e) { return err(e) }` 没有附加任何信息，排查时不知道是哪一步出了问题。

### 练习一

```typescript
function all<T, E>(results: Result<T, E>[]): Result<T[], E> {
  const values: T[] = []
  for (const result of results) {
    if (!result.ok) return result
    values.push(result.value)
  }
  return ok(values)
}
```

### 练习三

```typescript
import { ResultAsync, err, ok } from 'neverthrow'

async function transferMoney(
  fromId: string, toId: string, amount: number
): ResultAsync<{ from: number; to: number }, AppError> {
  const fromResult = await ResultAsync.fromPromise(
    db.accounts.findById(fromId),
    () => new DatabaseError('Failed to fetch source account')
  ).andThen(account => account ? ok(account) : err(new NotFoundError('Account', fromId)))

  return fromResult.asyncAndThen(async (from) => {
    const toResult = await ResultAsync.fromPromise(
      db.accounts.findById(toId),
      () => new DatabaseError('Failed to fetch target account')
    ).andThen(account => account ? ok(account) : err(new NotFoundError('Account', toId)))

    return toResult.asyncAndThen(async (to) => {
      if (from.balance < amount) return err(new ValidationError('Insufficient funds', { balance: String(from.balance) }))
      from.balance -= amount
      to.balance += amount
      const saveResult = await ResultAsync.fromPromise(
        Promise.all([db.accounts.update(from), db.accounts.update(to)]),
        () => new DatabaseError('Failed to update accounts')
      )
      return saveResult.map(() => ({ from: from.balance, to: to.balance }))
    })
  })
}
```
