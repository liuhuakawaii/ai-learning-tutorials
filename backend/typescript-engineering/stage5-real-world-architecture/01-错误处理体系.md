# 01 错误处理体系

## 场景引入

你的团队刚上线了一个订单服务，运行两周后收到用户投诉："我付了钱但订单显示失败。"排查后发现，数据库写入失败时代码用 `try/catch` 捕获了异常，但 `catch` 块里只打了一个 `console.log`，然后继续执行后续逻辑，导致支付成功但订单未创建。这不是偶发 bug，而是错误处理体系缺失的系统性问题。

## 学习目标

- 理解 `try/catch` 在复杂业务中的局限性
- 掌握 Result 模式，用类型系统显式表达成功与失败
- 设计自定义错误层级，让错误携带足够的上下文信息
- 使用 neverthrow 库在生产项目中落地 Result 模式
- 建立错误边界思维，在架构层面规划错误传播路径

## 一、try/catch 的真实问题

`try/catch` 是 JavaScript 处错误的基本机制，但在工程实践中存在几个致命缺陷：

```typescript
// 问题一：无法从函数签名得知是否会抛错
function parseConfig(raw: string): AppConfig {
  // 调用者无法感知这里可能抛出异常
  return JSON.parse(raw)
}

// 问题二：catch 捕获的类型是 unknown，容易被忽略
try {
  const config = parseConfig(input)
} catch (error) {
  // error 是 unknown，不处理也没人强制你处理
}

// 问题三：异步错误容易丢失
async function loadUser(id: string) {
  const res = await fetch(`/api/users/${id}`)
  const data = await res.json() // 这里可能抛错
  return data
  // 调用者如果不 await，错误就静默消失了
}
```

核心问题：**异常是隐式的**。函数签名不告诉你它会失败，编译器不强制你处理失败，调用者可以完全忽略错误的存在。

## 二、Result 模式：用类型显式表达失败

Result 模式的核心思想：**把"成功或失败"编码为类型**，让编译器强制你处理两种情况。

```typescript
type Result<T, E> =
  | { ok: true; value: T }
  | { ok: false; error: E }

function parseConfig(raw: string): Result<AppConfig, SyntaxError> {
  try {
    const config = JSON.parse(raw) as AppConfig
    return { ok: true, value: config }
  } catch (e) {
    return { ok: false, error: e instanceof SyntaxError ? e : new SyntaxError('Unknown parse error') }
  }
}

// 调用者必须处理两种情况
const result = parseConfig(input)
if (result.ok) {
  console.log(result.value.port) // 类型窄化后可以安全访问
} else {
  console.error(result.error.message) // 必须处理错误
}
```

### 链式操作：map 与 flatMap

Result 模式的威力在于可以像 Promise 一样链式组合：

```typescript
function map<T, U, E>(result: Result<T, E>, fn: (value: T) => U): Result<U, E> {
  if (!result.ok) return result
  return { ok: true, value: fn(result.value) }
}

function flatMap<T, U, E>(
  result: Result<T, E>,
  fn: (value: T) => Result<U, E>
): Result<U, E> {
  if (!result.ok) return result
  return fn(result.value)
}

// 使用示例：多步操作的错误传播
function createOrder(rawBody: string, userId: string): Result<Order, AppError> {
  return flatMap(
    parseBody(rawBody),           // Result<ParsedBody, ValidationError>
    (body) => flatMap(
      validateItems(body.items),  // Result<CartItem[], ValidationError>
      (items) => map(
        saveOrder(userId, items), // Result<Order, DatabaseError>
        (order) => order          // 成功时直接返回
      )
    )
  )
}
```

## 三、自定义错误层级

生产项目需要结构化的错误类型，让调用方根据错误类型决定处理策略：

```typescript
// 基础错误类，所有业务错误的根
class AppError extends Error {
  constructor(
    message: string,
    public readonly code: string,
    public readonly statusCode: number = 500,
    public readonly context?: Record<string, unknown>
  ) {
    super(message)
    this.name = this.constructor.name
  }
}

// 可恢复错误：调用方可以重试
class TransientError extends AppError {
  constructor(message: string, context?: Record<string, unknown>) {
    super(message, 'TRANSIENT_ERROR', 503, context)
  }
}

// 验证错误：用户输入有问题
class ValidationError extends AppError {
  constructor(message: string, public readonly fields: Record<string, string>) {
    super(message, 'VALIDATION_ERROR', 400, { fields })
  }
}

// 资源不存在
class NotFoundError extends AppError {
  constructor(resource: string, id: string) {
    super(`${resource} not found: ${id}`, 'NOT_FOUND', 404, { resource, id })
  }
}

// 权限不足
class ForbiddenError extends AppError {
  constructor(action: string, resource: string) {
    super(`Cannot ${action} ${resource}`, 'FORBIDDEN', 403, { action, resource })
  }
}

// 使用示例
function getOrder(id: string): Result<Order, NotFoundError | DatabaseError> {
  const order = db.orders.findById(id)
  if (!order) {
    return { ok: false, error: new NotFoundError('Order', id) }
  }
  return { ok: true, value: order }
}
```

## 四、neverthrow：生产级 Result 库

手写 Result 工具函数容易出错，neverthrow 提供了完整的 Result API：

```typescript
import { Result, ok, err, ResultAsync } from 'neverthrow'

// 基本用法
function divide(a: number, b: number): Result<number, string> {
  if (b === 0) return err('Division by zero')
  return ok(a / b)
}

// 链式操作
const result = divide(10, 2)
  .map(n => n * 100)           // ok(500)
  .map(n => `Result: ${n}`)    // ok('Result: 500')

// 组合多个可能失败的操作
import { combine } from 'neverthrow'

function processBatch(ids: string[]): Result<Order[], AppError> {
  const results = ids.map(id => getOrder(id))
  return combine(results) // 任何一个失败，整体失败
}

// 异步 Result
function fetchUser(id: string): ResultAsync<User, AppError> {
  return ResultAsync.fromPromise(
    db.users.findById(id),
    (error) => new DatabaseError(`Failed to fetch user ${id}`, { cause: error })
  ).andThen(user =>
    user ? ok(user) : err(new NotFoundError('User', id))
  )
}

// 在 API 路由中使用
app.get('/orders/:id', async (req, res) => {
  const result = await getOrder(req.params.id)
  
  result.match(
    (order) => res.json(order),
    (error) => {
      if (error instanceof NotFoundError) {
        res.status(404).json({ error: error.message })
      } else {
        res.status(500).json({ error: 'Internal server error' })
      }
    }
  )
})
```

## 五、错误边界：架构层面的错误处理

错误边界不是代码层面的 `try/catch`，而是架构层面定义"错误在哪里被终结"：

```typescript
// 错误边界 1：API 路由层 —— 将业务错误转为 HTTP 响应
function withErrorHandling(handler: RequestHandler): RequestHandler {
  return async (req, res, next) => {
    try {
      await handler(req, res, next)
    } catch (error) {
      if (error instanceof ValidationError) {
        res.status(400).json({ code: error.code, fields: error.fields })
      } else if (error instanceof NotFoundError) {
        res.status(404).json({ code: error.code, message: error.message })
      } else if (error instanceof AppError) {
        res.status(error.statusCode).json({ code: error.code, message: error.message })
      } else {
        // 未知错误：记录详细信息，返回通用消息
        logger.fatal({ err: error, req: { method: req.method, url: req.url } })
        res.status(500).json({ code: 'INTERNAL_ERROR', message: 'Something went wrong' })
      }
    }
  }
}

// 错误边界 2：后台任务层 —— 决定重试还是放弃
async function processJob(job: Job): Promise<void> {
  const result = await executeJob(job)
  
  result.match(
    () => logger.info({ jobId: job.id }, 'Job completed'),
    (error) => {
      if (error instanceof TransientError && job.retryCount < 3) {
        logger.warn({ jobId: job.id, retry: job.retryCount + 1 }, 'Retrying job')
        queue.retry(job)
      } else {
        logger.error({ jobId: job.id, err: error }, 'Job failed permanently')
        queue.moveToDeadLetter(job)
      }
    }
  )
}
```

## 常见误区

1. **到处使用 Result**：IO 边界（数据库、网络）用 Result，内部纯函数用异常即可，过度使用 Result 会让代码变臃肿
2. **错误类型太粗粒度**：只定义一个 `AppError`，所有错误都是同一个类型，调用方无法区分处理
3. **丢失错误上下文**：`catch(e) { return err(e) }` 没有附加任何上下文，排查时不知道是哪一步出了问题
4. **混合使用异常和 Result**：函数内部抛异常但返回 Result，调用方既要看类型又要 try/catch

## 工程建议

1. **在 IO 边界统一收口**：数据库操作、外部 API 调用统一返回 Result，业务逻辑层用 Result 组合，API 层用 match 终结
2. **错误携带上下文**：自定义错误类应包含足够的调试信息（资源 ID、操作类型、请求参数），但注意脱敏
3. **为错误定义恢复策略**：TransientError 可重试、ValidationError 返回用户、NotFoundError 返回 404，避免一刀切返回 500
4. **用 TypeScript 严格模式**：`strict: true` + `useUnknownInCatchVariables: true` 强制团队正确处理错误

## 小结

本课从 `try/catch` 的局限性出发，介绍了 Result 模式如何用类型系统显式表达失败。通过自定义错误层级、neverthrow 库和错误边界设计，建立了一套从数据层到 API 层的完整错误处理体系。核心原则：**让编译器帮你检查是否处理了所有错误情况**。

## 参考答案

### 练习一

**思路**：遍历数组，遇到第一个 `err` 就返回，全部是 `ok` 就收集所有 value。

**答案**：
```typescript
function all<T, E>(results: Result<T, E>[]): Result<T[], E> {
  const values: T[] = []
  for (const result of results) {
    if (!result.ok) return result
    values.push(result.value)
  }
  return ok(values)
}
```

**要点**：
- 短路返回第一个错误，不做"收集所有错误"
- 如果需要收集所有错误，函数名应改为 `allErrors`，语义不同

### 练习二

**思路**：每种错误对应一个具体场景，字段应包含排查所需的上下文。

**答案**：
```typescript
class InsufficientStockError extends AppError {
  constructor(productId: string, requested: number, available: number) {
    super(
      `Insufficient stock for ${productId}: requested ${requested}, available ${available}`,
      'INSUFFICIENT_STOCK',
      409,
      { productId, requested, available }
    )
  }
}

class CouponExpiredError extends AppError {
  constructor(couponCode: string, expiredAt: Date) {
    super(
      `Coupon ${couponCode} expired at ${expiredAt.toISOString()}`,
      'COUPON_EXPIRED',
      400,
      { couponCode, expiredAt }
    )
  }
}

class PaymentFailedError extends AppError {
  constructor(orderId: string, provider: string, reason: string) {
    super(
      `Payment failed for order ${orderId}: ${reason}`,
      'PAYMENT_FAILED',
      402,
      { orderId, provider, reason }
    )
  }
}

class InvalidAddressError extends ValidationError {
  constructor(fields: Record<string, string>) {
    super('Invalid shipping address', fields)
  }
}
```

**要点**：
- 字段选择标准：**排查问题时需要哪些信息**
- 包含可变参数（productId、requested）而非静态描述
- HTTP 状态码遵循语义：409 冲突、400 参数错误、402 支付失败

### 练习三

**思路**：每个可能失败的操作用 `ResultAsync.fromPromise` 包裹，业务校验用 `err`，最后用 `andThen` 链式组合。

**答案**：
```typescript
import { ResultAsync, err, ok } from 'neverthrow'

class AccountNotFoundError extends AppError {
  constructor(id: string) {
    super(`Account ${id} not found`, 'ACCOUNT_NOT_FOUND', 404, { id })
  }
}

class InsufficientFundsError extends AppError {
  constructor(balance: number, amount: number) {
    super(`Balance ${balance} < amount ${amount}`, 'INSUFFICIENT_FUNDS', 400, { balance, amount })
  }
}

async function transferMoney(
  fromId: string,
  toId: string,
  amount: number
): ResultAsync<{ from: number; to: number }, AppError> {
  const fromResult = await ResultAsync.fromPromise(
    db.accounts.findById(fromId),
    () => new DatabaseError('Failed to fetch source account')
  ).andThen(account =>
    account ? ok(account) : err(new AccountNotFoundError(fromId))
  )

  return fromResult.asyncAndThen(async (from) => {
    const toResult = await ResultAsync.fromPromise(
      db.accounts.findById(toId),
      () => new DatabaseError('Failed to fetch target account')
    ).andThen(account =>
      account ? ok(account) : err(new AccountNotFoundError(toId))
    )

    return toResult.asyncAndThen(async (to) => {
      if (from.balance < amount) {
        return err(new InsufficientFundsError(from.balance, amount))
      }

      from.balance -= amount
      to.balance += amount

      const saveResult = await ResultAsync.fromPromise(
        Promise.all([
          db.accounts.update(from),
          db.accounts.update(to),
        ]),
        () => new DatabaseError('Failed to update accounts')
      )

      return saveResult.map(() => ({ from: from.balance, to: to.balance }))
    })
  })
}
```

**要点**：
- 每个异步操作都用 `ResultAsync.fromPromise` 包裹，第二个参数将未知错误转为已知类型
- `andThen` 只在前一步成功时执行，失败自动跳过
- `asyncAndThen` 用于内部也是异步操作的场景
