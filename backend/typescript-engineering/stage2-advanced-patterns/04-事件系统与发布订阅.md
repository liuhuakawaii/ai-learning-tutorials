# 04 - 事件系统与发布订阅

## 场景引入

你的电商系统在用户下单后需要：扣减库存、发送确认邮件、更新统计报表、通知物流系统。如果在下单逻辑里直接调用这些服务，下单方法会变成一个巨大的耦合点。有没有办法让下单逻辑只负责"发布一个事件"，其他服务各自监听并响应？

## 学习目标

- 理解 EventEmitter 的局限性及其类型安全问题
- 实现类型安全的事件系统，事件载荷在编译期可检查
- 掌握泛型约束事件注册与触发的技巧
- 构建支持通配符的应用事件总线

## 一、传统 EventEmitter 的问题

Node.js 的 EventEmitter 用字符串标识事件，载荷类型无法约束：

```typescript
import { EventEmitter } from 'events'

const emitter = new EventEmitter()

// 问题1：事件名是任意字符串，拼错无提示
emitter.on('orderCreated', (data) => {
  console.log(data.orderId) // data 是 any，没有类型提示
})

emitter.emit('orderCraeted', { orderId: '123' }) // 拼错了，运行时静默失败

// 问题2：载荷类型无法约束
emitter.emit('orderCreated', { wrong: 'field' }) // 编译通过，运行时出错
```

## 二、类型安全的事件系统

用映射类型定义事件名和载荷的对应关系：

```typescript
interface EventMap {
  'user:registered': { userId: string; email: string; name: string }
  'user:login': { userId: string; ip: string; timestamp: Date }
  'order:created': { orderId: string; userId: string; items: string[] }
  'order:paid': { orderId: string; amount: number; paidAt: Date }
  'order:shipped': { orderId: string; trackingNo: string }
}

type EventHandler<T> = (payload: T) => void | Promise<void>

class TypedEventEmitter<Events extends Record<string, unknown>> {
  private handlers = new Map<keyof Events, Set<EventHandler<any>>>()

  on<K extends keyof Events>(event: K, handler: EventHandler<Events[K]>): () => void {
    if (!this.handlers.has(event)) this.handlers.set(event, new Set())
    this.handlers.get(event)!.add(handler)
    return () => { this.handlers.get(event)?.delete(handler) }
  }

  once<K extends keyof Events>(event: K, handler: EventHandler<Events[K]>): () => void {
    const wrapper: EventHandler<Events[K]> = (payload) => { handler(payload); unsubscribe() }
    const unsubscribe = this.on(event, wrapper)
    return unsubscribe
  }

  async emit<K extends keyof Events>(event: K, payload: Events[K]): Promise<void> {
    const handlers = this.handlers.get(event)
    if (!handlers) return
    await Promise.all(Array.from(handlers).map(h => Promise.resolve(h(payload))))
  }

  off<K extends keyof Events>(event: K): void { this.handlers.delete(event) }
  clear(): void { this.handlers.clear() }
}

const events = new TypedEventEmitter<EventMap>()

// ✅ 正确：事件名和载荷类型匹配
events.on('order:created', (payload) => {
  console.log(`新订单: ${payload.orderId}, ${payload.items.length} 件商品`)
})

// ❌ 编译错误：载荷类型不匹配
events.emit('order:created', { orderId: '1', wrong: 'field' })

// ❌ 编译错误：事件名不存在
events.emit('order:cancel', { orderId: '1' })

// 触发事件
await events.emit('order:created', {
  orderId: 'order_001', userId: 'user_1', items: ['商品A', '商品B'],
})
```

## 三、应用事件总线

在真实应用中，事件总线需要支持通配符、事件优先级、错误隔离：

```typescript
type EventPriority = 'high' | 'normal' | 'low'

interface HandlerRegistration<T> {
  handler: EventHandler<T>
  priority: EventPriority
  once: boolean
}

class ApplicationEventBus<Events extends Record<string, unknown>> {
  private handlers = new Map<keyof Events, HandlerRegistration<any>[]>()
  private wildcardHandlers: HandlerRegistration<any>[] = []

  on<K extends keyof Events>(
    event: K | '*', handler: EventHandler<Events[K]>, priority: EventPriority = 'normal'
  ): () => void {
    const reg: HandlerRegistration<Events[K]> = { handler, priority, once: false }

    if (event === '*') {
      this.wildcardHandlers.push(reg)
      this.sortHandlers(this.wildcardHandlers)
      return () => { const i = this.wildcardHandlers.indexOf(reg); if (i >= 0) this.wildcardHandlers.splice(i, 1) }
    }

    if (!this.handlers.has(event)) this.handlers.set(event, [])
    const list = this.handlers.get(event)!
    list.push(reg)
    this.sortHandlers(list)
    return () => { const i = list.indexOf(reg); if (i >= 0) list.splice(i, 1) }
  }

  once<K extends keyof Events>(
    event: K | '*', handler: EventHandler<Events[K]>, priority: EventPriority = 'normal'
  ): () => void {
    const reg: HandlerRegistration<Events[K]> = { handler, priority, once: true }
    if (event === '*') { this.wildcardHandlers.push(reg); return () => {} }
    if (!this.handlers.has(event)) this.handlers.set(event, [])
    this.handlers.get(event)!.push(reg)
    return () => {}
  }

  async emit<K extends keyof Events>(event: K, payload: Events[K]): Promise<void> {
    const specific = this.handlers.get(event) ?? []
    for (const reg of [...specific, ...this.wildcardHandlers]) {
      try { await Promise.resolve(reg.handler(payload)) }
      catch (error) { console.error(`事件处理器错误 [${String(event)}]:`, error) }
    }
  }

  private sortHandlers(list: HandlerRegistration<any>[]) {
    const order = { high: 0, normal: 1, low: 2 }
    list.sort((a, b) => order[a.priority] - order[b.priority])
  }
}

// 使用
const bus = new ApplicationEventBus<EventMap>()

bus.on('order:created', async (payload) => {
  console.log(`[库存] 扣减 ${payload.items.length} 件商品`)
}, 'high')

bus.on('order:created', async (payload) => {
  console.log(`[邮件] 发送订单确认给 ${payload.userId}`)
}, 'normal')

bus.on('*', (payload) => {
  console.log(`[日志] 事件触发:`, payload)
}, 'low')

await bus.emit('order:created', {
  orderId: 'order_001', userId: 'user_1', items: ['商品A'],
})
// 输出顺序：库存 → 邮件 → 日志
```

## 常见误区

1. **事件名用魔术字符串**：应集中在 `EventMap` 中定义，避免拼写错误
2. **忘记取消订阅**：组件销毁时应取消事件监听，否则造成内存泄漏
3. **事件处理器抛异常导致整个链中断**：每个处理器应独立 try-catch
4. **滥用事件总线**：同步的、有明确调用关系的逻辑不需要走事件

## 工程建议

1. **事件载荷用接口定义而非内联类型**：便于复用和文档化
2. **提供 `once` 方法**：某些事件只需要响应一次
3. **优先级机制很重要**：扣减库存必须在发送邮件之前执行
4. **事件总线配合中间件使用**：在事件触发前后插入日志、监控、重试等横切逻辑

## 小结

类型安全的事件系统用映射类型约束事件名和载荷的对应关系。应用事件总线在此基础上增加优先级、通配符、错误隔离等能力。关键是平衡解耦与可追踪性——事件让模块独立，但过度使用会让调用链难以调试。

## 参考答案

### 练习一

**思路**：中间件函数接收事件名、载荷和 `next` 函数，决定是否继续执行。

**答案**：

```typescript
type EventMiddleware<Events> = <K extends keyof Events>(
  event: K, payload: Events[K], next: () => void | Promise<void>
) => void | Promise<void>

class EmitterWithMiddleware<Events extends Record<string, unknown>> {
  private handlers = new Map<keyof Events, Set<EventHandler<any>>>()
  private middlewares: EventMiddleware<Events>[] = []

  use(middleware: EventMiddleware<Events>) { this.middlewares.push(middleware) }

  on<K extends keyof Events>(event: K, handler: EventHandler<Events[K]>) {
    if (!this.handlers.has(event)) this.handlers.set(event, new Set())
    this.handlers.get(event)!.add(handler)
  }

  async emit<K extends keyof Events>(event: K, payload: Events[K]) {
    const runHandlers = async () => {
      const handlers = this.handlers.get(event)
      if (handlers) await Promise.all(Array.from(handlers).map(h => Promise.resolve(h(payload))))
    }

    let idx = 0
    const next = async (): Promise<void> => {
      if (idx < this.middlewares.length) {
        await this.middlewares[idx++](event, payload, next)
      } else {
        await runHandlers()
      }
    }
    await next()
  }
}

const emitter = new EmitterWithMiddleware<EventMap>()
emitter.use(async (event, payload, next) => {
  console.log(`[LOG] 触发事件: ${String(event)}`)
  await next()
  console.log(`[LOG] 事件处理完成: ${String(event)}`)
})
```

**要点**：中间件通过 `next()` 控制执行流，类似 Koa 的洋葱模型。

### 练习二

**思路**：解析事件名命名空间，按 `:` 分割，支持前缀通配符。

**答案**：

```typescript
class NamespacedEmitter<Events extends Record<string, unknown>> {
  private handlers = new Map<string, Set<EventHandler<any>>>()

  on<K extends keyof Events>(event: K, handler: EventHandler<Events[K]>) {
    const key = event as string
    if (!this.handlers.has(key)) this.handlers.set(key, new Set())
    this.handlers.get(key)!.add(handler)
  }

  async emit<K extends keyof Events>(event: K, payload: Events[K]) {
    const eventStr = event as string
    const matched: EventHandler<any>[] = []
    for (const [key, handlers] of this.handlers) {
      if (key === eventStr || (key.endsWith('*') && eventStr.startsWith(key.slice(0, -1)))) {
        matched.push(...handlers)
      }
    }
    await Promise.all(matched.map(h => Promise.resolve(h(payload))))
  }
}

const ns = new NamespacedEmitter<EventMap>()
ns.on('order:*' as keyof EventMap, (payload) => console.log('[订单模块]', payload))
ns.on('order:created', (payload) => console.log(`新订单: ${payload.orderId}`))
await ns.emit('order:created', { orderId: '1', userId: 'u1', items: [] })
```

**要点**：通配符处理器和精确处理器都会被触发。

### 练习三

**思路**：为事件映射添加请求-响应类型，`request` 方法返回 `Promise`。

**答案**：

```typescript
interface RequestEventMap {
  'user:get': { request: { userId: string }; response: { name: string; email: string } }
  'order:total': { request: { orderId: string }; response: { total: number } }
}

class RequestBus<Events extends Record<string, { request: unknown; response: unknown }>> {
  private handlers = new Map<string, (req: any) => any>()

  handle<K extends keyof Events & string>(
    event: K, handler: (req: Events[K]['request']) => Events[K]['response'] | Promise<Events[K]['response']>
  ) { this.handlers.set(event, handler) }

  async request<K extends keyof Events & string>(event: K, payload: Events[K]['request']): Promise<Events[K]['response']> {
    const handler = this.handlers.get(event)
    if (!handler) throw new Error(`未注册处理器: ${event}`)
    return Promise.resolve(handler(payload))
  }
}

const reqBus = new RequestBus<RequestEventMap>()
reqBus.handle('user:get', async () => ({ name: '张三', email: 'zhangsan@example.com' }))
const user = await reqBus.request('user:get', { userId: 'u1' })
console.log(user.name) // '张三'
```

**要点**：返回类型根据事件名自动推导，无需类型断言。
