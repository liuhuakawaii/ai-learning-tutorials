# 02 - 类型测试

## 场景引入

你写了一个复杂的泛型工具库，发布了新版本后收到用户反馈：某个重载函数的返回类型变了，导致下游项目编译失败。运行时测试全部通过——因为测试只验证了值，没有验证类型。TypeScript 的类型系统足够强大，但如果你不测试它，它就会成为质量盲区。

## 学习目标

- 理解为什么运行时测试无法覆盖类型正确性
- 掌握 vitest 的 expectTypeOf 进行类型断言
- 学会使用 tsd 工具进行独立的类型测试
- 能够测试复杂类型推断、条件类型、函数重载

## 一、为什么运行时测试不够

TypeScript 的类型在编译后被擦除，运行时测试无法验证类型是否正确：

```typescript
type InputType = { name: string; age: number }
type OutputType = { fullName: string; isAdult: boolean }

function transform(input: InputType): OutputType {
  return { fullName: input.name, isAdult: input.age >= 18 }
}

// 运行时测试——通过，但没有验证类型
describe('transform', () => {
  it('应正确转换数据', () => {
    const result = transform({ name: '张三', age: 25 })
    expect(result.fullName).toBe('张三') // 只验证了值
  })
})
```

如果有人把返回类型改成 `any`，或者把字段名拼错，运行时测试不会报错。类型测试就是为了解决这个问题。

## 二、expectTypeOf：Vitest 内置类型断言

Vitest 提供了 `expectTypeOf` API，可以在测试中进行类型级别的断言：

```typescript
import { describe, it, expectTypeOf } from 'vitest'

function createId(prefix: string): `${string}_${number}` {
  return `${prefix}_${Date.now()}`
}

function pick<T, K extends keyof T>(obj: T, keys: K[]): Pick<T, K> {
  const result = {} as Pick<T, K>
  for (const key of keys) { result[key] = obj[key] }
  return result
}

describe('类型测试', () => {
  it('createId 应返回模板字面量类型', () => {
    expectTypeOf(createId).parameter(0).toBeString()
    expectTypeOf(createId).returns.toMatchTypeOf<string>()
  })

  it('pick 应正确约束泛型', () => {
    const obj = { a: 1, b: 'hello', c: true }
    const result = pick(obj, ['a', 'c'])
    expectTypeOf(result).toEqualTypeOf<{ a: number; c: boolean }>()
  })
})
```

核心方法：`toEqualTypeOf`（严格类型相等）、`toMatchTypeOf`（类型兼容）、`parameter(n)`（检查参数类型）、`returns`（检查返回类型）。

## 三、tsd：独立的类型测试工具

tsd 是专门用于类型测试的工具，适合独立的类型库项目：

```bash
npm install -D tsd
```

```typescript
// src/index.ts
export function merge<T extends object, U extends object>(target: T, source: U): T & U {
  return { ...target, ...source }
}

export type DeepPartial<T> = T extends object
  ? { [P in keyof T]?: DeepPartial<T[P]> }
  : T
```

```typescript
// index.test-d.ts — tsd 类型测试文件
import { expectType, expectError } from 'tsd'
import { merge, DeepPartial } from '.'

const merged = merge({ a: 1 }, { b: 'hello' })
expectType<{ a: number; b: string }>(merged)

type Original = { a: { b: { c: number } } }
type Partial = DeepPartial<Original>
const partial: Partial = { a: { b: {} } }
expectType<Partial>(partial)

expectError(merge(123, 'hello'))
```

在 `package.json` 中添加：`"test:types": "tsd"`，`"tsd": { "directory": "src" }`。

## 四、测试类型推断

复杂泛型的类型推断是 TypeScript 的高级特性，也是最容易出错的地方：

```typescript
import { describe, it, expectTypeOf } from 'vitest'

type InferArray<T> = T extends (infer U)[] ? U : never
type InferPromise<T> = T extends Promise<infer U> ? U : never
type ExtractParams<T extends string> =
  T extends `${string}:${infer Param}/${infer Rest}`
    ? Param | ExtractParams<Rest>
    : T extends `${string}:${infer Param}` ? Param : never

describe('类型推断测试', () => {
  it('InferArray 应提取数组元素类型', () => {
    expectTypeOf<InferArray<string[]>>().toEqualTypeOf<string>()
    expectTypeOf<InferArray<number[]>>().toEqualTypeOf<number>()
  })

  it('InferPromise 应提取 Promise 内部类型', () => {
    expectTypeOf<InferPromise<Promise<string>>>().toEqualTypeOf<string>()
  })

  it('ExtractParams 应提取路由参数', () => {
    type Params = ExtractParams<'/users/:userId/posts/:postId'>
    expectTypeOf<Params>().toEqualTypeOf<'userId' | 'postId'>()
  })
})
```

## 五、条件类型与重载测试

条件类型和函数重载是类型系统中最复杂的部分：

```typescript
import { describe, it, expectTypeOf } from 'vitest'

type IsString<T> = T extends string ? true : false

function processValue(value: string): { type: 'string'; length: number }
function processValue(value: number): { type: 'number'; doubled: number }
function processValue(value: string | number) {
  if (typeof value === 'string') return { type: 'string', length: value.length }
  return { type: 'number', doubled: value * 2 }
}

type ReadonlyDeep<T> = T extends object
  ? { readonly [K in keyof T]: ReadonlyDeep<T[K]> }
  : T

describe('条件类型测试', () => {
  it('IsString 应正确判断类型', () => {
    expectTypeOf<IsString<string>>().toEqualTypeOf<true>()
    expectTypeOf<IsString<number>>().toEqualTypeOf<false>()
  })

  it('ReadonlyDeep 应递归添加 readonly', () => {
    type Input = { a: number; b: { c: string } }
    type Expected = { readonly a: number; readonly b: { readonly c: string } }
    expectTypeOf<ReadonlyDeep<Input>>().toEqualTypeOf<Expected>()
  })
})

describe('函数重载测试', () => {
  it('字符串输入应返回 length', () => {
    expectTypeOf(processValue('hello')).toEqualTypeOf<{ type: 'string'; length: number }>()
  })
  it('数字输入应返回 doubled', () => {
    expectTypeOf(processValue(42)).toEqualTypeOf<{ type: 'number'; doubled: number }>()
  })
})
```

## 常见误区

1. **用运行时断言测试类型**：`expect(typeof result).toBe('object')` 无法验证 TypeScript 类型。类型测试应该在编译阶段进行。

2. **测试过于宽泛的类型**：`expectTypeOf(result).toBeAny()` 没有实际意义。类型测试的价值在于验证精确的类型推断。

3. **忽略类型测试文件的组织**：类型测试文件应该和被测代码放在一起，命名为 `*.type-test.ts`。散落各处的类型测试难以维护。

4. **只测试正向路径**：类型测试不仅要验证"应该是什么类型"，还要验证"不应该接受什么类型"。使用 `expectError` 测试类型约束。

## 工程建议

1. **类型测试放在 CI 中**：将类型测试作为 CI 流水线的一部分，确保类型变更不会破坏下游消费者。

2. **优先测试公共 API 的类型**：库的公共 API 类型是最需要测试的，因为它们影响所有使用者。

3. **结合文档测试**：类型测试可以作为类型文档的补充。一个好的类型测试用例比注释更能说明类型的预期行为。

4. **渐进式引入**：不需要为每个类型都写测试。优先为复杂的泛型、条件类型、重载函数编写类型测试。

## 小结

类型测试弥补了运行时测试无法覆盖的类型正确性盲区。通过 `expectTypeOf` 和 `tsd`，你可以在测试中验证类型推断、条件类型、函数重载等复杂场景。将类型测试融入 CI 流水线，是保障 TypeScript 项目类型安全的重要手段。

## 参考答案

### 练习一

**思路**：测试 PickByType 和 OmitByType 的过滤效果。

**答案**：

```typescript
import { describe, it, expectTypeOf } from 'vitest'

type PickByType<T, U> = { [K in keyof T as T[K] extends U ? K : never]: T[K] }
type OmitByType<T, U> = { [K in keyof T as T[K] extends U ? never : K]: T[K] }

interface MixedTypes { name: string; age: number; active: boolean; score: number }

describe('PickByType', () => {
  it('应提取指定类型的属性', () => {
    expectTypeOf<PickByType<MixedTypes, number>>().toEqualTypeOf<{ age: number; score: number }>()
  })
  it('无匹配时应返回空对象类型', () => {
    expectTypeOf<PickByType<{ a: number }, string>>().toEqualTypeOf<{}>()
  })
})

describe('OmitByType', () => {
  it('应排除指定类型的属性', () => {
    expectTypeOf<OmitByType<MixedTypes, number>>().toEqualTypeOf<{ name: string; active: boolean }>()
  })
})
```

**要点**：Key remapping（`as` 语法）是核心；空对象类型断言验证"无匹配"边界。

### 练习二

**思路**：验证泛型函数在不同输入下的类型推断是否正确。

**答案**：

```typescript
import { describe, it, expectTypeOf } from 'vitest'

function groupBy<T, K extends keyof T>(array: T[], key: K): Record<string, T[]> {
  return array.reduce((groups, item) => {
    const groupKey = String(item[key])
    groups[groupKey] = groups[groupKey] || []
    groups[groupKey].push(item)
    return groups
  }, {} as Record<string, T[]>)
}

function zip<A, B>(a: A[], b: B[]): [A, B][] {
  const length = Math.min(a.length, b.length)
  return Array.from({ length }, (_, i) => [a[i], b[i]])
}

describe('groupBy 类型测试', () => {
  it('应正确推断分组后的类型', () => {
    interface User { id: number; role: string }
    const users: User[] = []
    expectTypeOf(groupBy(users, 'role')).toEqualTypeOf<Record<string, User[]>>()
  })
})

describe('zip 类型测试', () => {
  it('应正确推断元组类型', () => {
    expectTypeOf(zip([1, 2], ['a', 'b'])).toEqualTypeOf<[number, string][]>()
  })
})
```

**要点**：groupBy 的泛型约束 `K extends keyof T` 确保 key 必须是 T 的属性；zip 返回元组数组。

### 练习三

**思路**：测试递归条件类型的深层解包。

**答案**：

```typescript
import { describe, it, expectTypeOf } from 'vitest'

type UnwrapPromise<T> = T extends Promise<infer U> ? UnwrapPromise<U> : T

describe('UnwrapPromise', () => {
  it('应解包单层 Promise', () => {
    expectTypeOf<UnwrapPromise<Promise<string>>>().toEqualTypeOf<string>()
  })
  it('应解包嵌套 Promise', () => {
    expectTypeOf<UnwrapPromise<Promise<Promise<Promise<number>>>>>().toEqualTypeOf<number>()
  })
  it('非 Promise 类型应原样返回', () => {
    expectTypeOf<UnwrapPromise<string>>().toEqualTypeOf<string>()
  })
})
```

**要点**：`infer` 关键字是条件类型推断的核心；递归实现深层解包；非匹配情况原样返回。
