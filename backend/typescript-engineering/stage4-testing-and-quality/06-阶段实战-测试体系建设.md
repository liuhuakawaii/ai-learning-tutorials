# 阶段实战：测试体系建设

你的项目代码量不小，测试覆盖率接近零。团队决定引入测试，但没人知道从哪开始。你需要一套能落地的方案：测试怎么分层、工具怎么配、CI 怎么跑。

不是要一步到位，是要先跑起来再迭代。

## 测试分层

```
单元测试 (70%)  → 单个函数/类，全部 Mock 外部依赖，< 100ms
集成测试 (20%)  → 多个模块协作，真实数据库，< 1s
契约测试 (5%)   → 服务间接口，验证请求/响应格式，< 500ms
E2E 测试 (5%)   → 完整用户流程，完整环境，< 30s
```

核心原则：快的多跑，慢的少跑，每层测自己的职责。

## 测试辅助工具

```typescript
// tests/helpers/mock.ts
import { vi } from "vitest"

export function createMockService<T>(methods: Record<keyof T, unknown>): T {
  const service = {} as T
  for (const [key, impl] of Object.entries(methods)) {
    ;(service as any)[key] = typeof impl === "function" ? vi.fn(impl) : vi.fn()
  }
  return service
}
```

```typescript
// tests/helpers/fixture.ts
import { faker } from "@faker-js/faker/locale/zh_CN"

export function createUser(overrides: Record<string, unknown> = {}) {
  return {
    id: faker.string.uuid(), name: faker.person.fullName(),
    email: faker.internet.email(), role: "user" as const,
    createdAt: faker.date.recent().toISOString(), ...overrides,
  }
}

export function createOrder(overrides: Record<string, unknown> = {}) {
  return {
    id: faker.string.uuid(), userId: faker.string.uuid(),
    items: [{ productId: faker.string.uuid(), quantity: 1, price: 9900 }],
    status: "pending" as const, totalAmount: 9900,
    createdAt: faker.date.recent().toISOString(), ...overrides,
  }
}
```

随机数据每次不同，能暴露硬编码测试数据发现不了的边界问题。

```typescript
// tests/helpers/database.ts
export function createTestDatabase() {
  const tables: Record<string, unknown[]> = {}
  return {
    async seed(data: Record<string, unknown[]>) { Object.assign(tables, data) },
    async cleanup() { for (const key of Object.keys(tables)) { tables[key] = [] } },
  }
}
```

## 分层测试实践

### 单元测试

只验证被测函数的逻辑，外部依赖全部 Mock：

```typescript
import { describe, it, expect, vi, beforeEach } from "vitest"
import { OrderService } from "./order.service"

describe("OrderService", () => {
  let service: OrderService
  let mockRepo: { save: any; findById: any }

  beforeEach(() => {
    mockRepo = { save: vi.fn().mockImplementation(async (o: any) => o), findById: vi.fn() }
    service = new OrderService(mockRepo as any)
  })

  it("下单金额应正确计算", async () => {
    const order = await service.createOrder("user_001", [{ price: 10000, quantity: 2 }])
    expect(order.totalAmount).toBe(20000)
  })

  it("订单不存在时应抛出错误", async () => {
    mockRepo.findById.mockResolvedValue(null)
    await expect(service.getOrderById("nonexistent")).rejects.toThrow("Order not found")
  })
})
```

### 集成测试

用真实依赖，验证模块之间的协作：

```typescript
import { OrderRepository } from "./order.repository"
import { createTestDatabase } from "@tests/helpers/database"

describe("OrderService 集成测试", () => {
  let service: OrderService
  let db: ReturnType<typeof createTestDatabase>

  beforeAll(async () => {
    db = createTestDatabase(); await db.seed({ orders: [] })
    service = new OrderService(new OrderRepository(db))
  })
  afterAll(async () => { await db.cleanup() })

  it("完整下单流程：创建 → 查询", async () => {
    const order = await service.createOrder("user_001", [{ price: 10000, quantity: 1 }])
    expect(order.id).toBeDefined()
    const found = await service.getOrderById(order.id)
    expect(found.totalAmount).toBe(10000)
  })
})
```

单元测试 `expect(mockRepo.save).toHaveBeenCalledWith(...)` 验证"调用了什么"；集成测试 `const found = await repo.findById(id)` 验证"数据存对了没有"。

## CI 流水线

分层跑，快速检查先跑，慢的后跑：

```yaml
# .github/workflows/test-pipeline.yml
name: 测试流水线
on:
  push: { branches: [main] }
  pull_request: { branches: [main] }

jobs:
  fast-checks:
    name: 快速检查
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: "20", cache: "npm" }
      - run: npm ci
      - run: npm run lint:check
      - run: npm run typecheck

  unit-tests:
    name: 单元测试
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: "20", cache: "npm" }
      - run: npm ci
      - run: npm run test:run -- --coverage

  integration-tests:
    name: 集成测试
    needs: fast-checks
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:15
        env: { POSTGRES_PASSWORD: test }
        options: --health-cmd pg_isready --health-interval 10s --health-timeout 5s --health-retries 5
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: "20", cache: "npm" }
      - run: npm ci
      - run: npm run test:integration
        env: { DATABASE_URL: postgresql://postgres:test@localhost:5432/test }
```

设计决策：fast-checks 最先跑，几秒出结果，快速拦截低级错误。unit-tests 并行跑。integration-tests 等 fast-checks 通过后再跑，避免浪费 CI 资源。

## 练习

### 练习一：搭建测试基础设施

为一个现有项目搭建 vitest.config.ts、tests/setup.ts、tests/helpers/mock.ts、tests/helpers/fixture.ts。要求类型安全，fixture 支持 overrides。

### 练习二：为一个模块写三层测试

选一个有外部依赖的核心模块，分别写单元测试（Mock 所有外部依赖）、集成测试（真实数据库）、契约测试（Zod schema 验证）。

### 练习三：配置 CI 流水线

写 GitHub Actions 配置：lint/typecheck 先跑，单元测试并行跑，集成测试带 PostgreSQL 服务。

---

## 参考答案

### 练习一

核心：配置文件定义测试行为，mock.ts 提供类型安全的 Mock 工厂，fixture.ts 用 faker 生成数据。fixture 必须接受 overrides 参数：`createUser(overrides: Partial<User> = {})`，展开 overrides 覆盖默认值。

### 练习二

单元测试：`mockRepo.findById.mockResolvedValue(null)` → 期望抛出错误。集成测试：真实数据库 → 创建 → 查询 → 验证数据。契约测试：`z.object({...}).safeParse(response)` 期望 success 为 true。

### 练习三

流水线设计：fast-checks（lint + typecheck）→ unit-tests（并行）→ integration-tests（需要 PostgreSQL service）。集成测试用 `services.postgres` 启动容器，通过 `DATABASE_URL` 环境变量传连接串。
