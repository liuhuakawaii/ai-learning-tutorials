# 阶段四：测试与质量

## 阶段简介

建立完整的 TypeScript 测试体系，从单元测试到类型测试、契约测试，再到静态分析与代码审查自动化。本阶段不是简单地介绍测试框架的 API，而是围绕"如何在真实项目中建立可持续的质量保障体系"这一核心问题展开。每一课都从真实工程场景出发，解决具体的质量痛点。

## 学习目标

完成本阶段后，你将能够：

1. 使用 Vitest 搭建完整的单元测试体系，掌握 Mock、快照、异步测试等核心技巧
2. 理解类型测试的必要性，使用 expectTypeOf 和 tsd 验证复杂类型推断的正确性
3. 设计契约测试，确保服务间接口的一致性，使用 Zod 进行运行时 schema 验证
4. 配置 typescript-eslint，利用类型感知 linting 规则在编码阶段捕获潜在问题
5. 搭建代码审查自动化流水线，将质量检查融入 CI/CD 流程

## 本阶段项目

### 搭建完整测试体系

为一个中型 TypeScript 项目搭建完整的测试基础设施，包括：

- 单元测试框架配置与核心测试用例
- 类型测试保障复杂泛型的正确性
- 契约测试确保 API 接口一致性
- ESLint 静态分析配置
- CI 流水线中的自动化质量检查

项目代码位于 `final-project/` 目录。

## 学习建议

1. **动手为主**：每课的练习题必须完成，测试能力只能通过实践获得
2. **从实际项目出发**：尝试将本阶段学到的测试策略应用到你自己的项目中
3. **理解测试哲学**：不要只学 API，理解"测什么"比"怎么测"更重要
4. **渐进式引入**：在真实项目中引入测试时，从最脆弱、最高风险的模块开始
5. **关注测试金字塔**：单元测试占 70%、集成测试占 20%、E2E 测试占 10%，保持合理比例
6. **测试代码也是代码**：测试代码同样需要可读性、可维护性，不要写"一次性测试"
