# 毕业项目：TypeScript 全栈工具平台

## 项目概述

构建一个类型安全的全栈工具平台，综合运用本课程五个阶段所学的全部知识。平台采用 Monorepo 架构，包含共享类型库、后端 API、前端 Web 应用、CLI 工具和统一配置五个子包，展示从类型系统到生产级架构的完整工程能力。

## 功能模块

| 模块 | 对应阶段 | 核心内容 |
|------|----------|----------|
| 模块一：类型系统 | 阶段一 | shared-types 包：泛型工具类型、条件类型、模板字面量类型、类型守卫 |
| 模块二：设计模式 | 阶段二 | api 包：Builder 模式构建查询、Strategy 模式处理策略、依赖注入容器 |
| 模块三：工具链 | 阶段三 | config 包 + 根配置：ESLint flat config、Turborepo 任务编排、Git hooks |
| 模块四：测试 | 阶段四 | 全包测试：单元测试、集成测试、类型测试、覆盖率报告 |
| 模块五：架构 | 阶段五 | 完整部署：错误处理、日志、CI/CD、Docker、性能优化 |

## 验收标准

### 阶段一：类型系统（shared-types 包）

- [ ] 至少定义 10 个领域模型类型（用户、工具、分类等）
- [ ] 实现至少 5 个泛型工具类型（如 `PickByType`、`DeepPartial`、`RequiredKeys`）
- [ ] 使用条件类型实现至少 3 个类型推导
- [ ] 使用模板字面量类型实现 API 路径类型
- [ ] 编写类型测试，验证类型推导正确性

### 阶段二：设计模式（api 包）

- [ ] 使用 Builder 模式构建复杂查询条件
- [ ] 使用 Strategy 模式处理不同工具的执行策略
- [ ] 实现依赖注入容器管理服务实例
- [ ] tRPC 路由至少 5 个过程（procedure）
- [ ] Zod schema 与 TypeScript 类型保持一致

### 阶段三：工具链（config 包 + 根配置）

- [ ] ESLint flat config 支持 TypeScript + React 规则
- [ ] Turborepo 配置 build、lint、test 任务依赖
- [ ] 配置 Husky + lint-staged 实现提交前检查
- [ ] pnpm workspace 正确管理五个子包依赖
- [ ] 所有包的 TypeScript 配置继承自根配置

### 阶段四：测试（全包）

- [ ] 每个包至少 10 个单元测试用例
- [ ] api 包至少 3 个集成测试（tRPC 端到端调用）
- [ ] shared-types 包包含类型推导测试
- [ ] 总体行覆盖率 ≥ 80%
- [ ] 测试通过 Vitest 正确运行，`pnpm test` 无报错

### 阶段五：生产级架构

- [ ] 统一错误处理中间件，包含错误码体系
- [ ] 结构化日志输出（JSON 格式）
- [ ] Dockerfile + docker-compose 可一键启动
- [ ] GitHub Actions CI 流水线（lint → test → build）
- [ ] API 响应时间 < 200ms（简单查询）

## 提交规范

### Commit 格式

```
<type>(<scope>): <description>

[可选正文]
[可选脚注]
```

### Type 类型

| 类型 | 说明 |
|------|------|
| feat | 新功能 |
| fix | 修复缺陷 |
| docs | 文档更新 |
| style | 代码格式（不影响逻辑） |
| refactor | 重构（既不修复缺陷也不添加功能） |
| test | 测试相关 |
| chore | 构建、工具、配置变更 |

### 示例

```
feat(shared-types): 添加工具类型 PickByType
fix(api): 修复 tRPC 路由类型推断错误
test(cli): 补充命令行解析的单元测试
```

### PR 模板

每个 PR 需包含：

1. **变更说明**：做了什么，为什么做
2. **影响范围**：涉及哪些子包
3. **测试情况**：新增/修改了哪些测试
4. **自检清单**：lint 通过、测试通过、类型检查通过
