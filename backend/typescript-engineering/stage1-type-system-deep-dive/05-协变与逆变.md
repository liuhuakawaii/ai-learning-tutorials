# 05 - 协变与逆变

## 场景引入

你在设计一个事件系统，定义了 `Handler<T>` 类型表示处理 T 类型事件的回调函数。你发现，把一个 `Handler<MouseEvent>` 传给期望 `Handler<Event>` 的地方会报错，但反过来却能通过。这个反直觉的行为背后，就是协变与逆变在起作用。

## 学习目标

- 理解协变（covariance）和逆变（contravariance）的概念
- 掌握函数参数逆变和返回值协变的规则
- 理解 `strictFunctionTypes` 编译选项的实际影响
- 能在实际项目中正确设计回调函数的类型

## 一、什么是协变与逆变

假设 `Dog` 是 `Animal` 的子类型：

- **协变**：`Container<Dog>` 是 `Container<Animal>` 的子类型（方向一致）
- **逆变**：`Container<Animal>` 是 `Container<Dog>` 的子类型（方向相反）
- **不变**：两者之间没有子类型关系

```typescript
class Animal { name: string = "" }
class Dog extends Animal { bark() {} }

// 数组是协变的（不安全）
const dogs: Dog[] = [new Dog()]
const animals: Animal[] = dogs // OK
// 但可以往 Animal[] 里放 Cat，破坏原始数组
```

## 二、函数参数逆变

函数参数的位置是逆变的：

```typescript
type Handler<T> = (event: T) => void

// 逆变：Handler<Event> 是 Handler<MouseEvent> 的子类型
// 因为能处理所有 Event 的函数，一定能处理 MouseEvent

const handleEvent: Handler<Event> = (event) => {
  console.log(event.type)
}

const handleMouse: Handler<MouseEvent> = handleEvent // OK
// const handleEvent2: EventHandler = handleMouse // 报错
```

### 实际场景

```typescript
class EventEmitter<T> {
  private handlers: Array<(event: T) => void> = []

  on(handler: (event: T) => void): void {
    this.handlers.push(handler)
  }

  emit(event: T): void {
    for (const handler of this.handlers) handler(event)
  }
}

const mouseEmitter = new EventEmitter<MouseEvent>()

// 能处理所有 Event 的处理器，可以注册到 mouseEmitter
mouseEmitter.on((event: Event) => {
  console.log(event.type)
}) // OK，参数逆变
```

## 三、返回值协变

函数返回值的位置是协变的：

```typescript
type Factory<T> = () => T

// 协变：Factory<Dog> 是 Factory<Animal> 的子类型
// 因为返回 Dog 的函数一定返回 Animal

const createDog: Factory<Dog> = () => new Dog()
const createAnimal: Factory<Animal> = createDog // OK
// const createDog2: Factory<Dog> = createAnimal // 报错
```

### 参数逆变 + 返回值协变

```typescript
type Converter<TInput, TOutput> = (input: TInput) => TOutput

// Converter<Animal, Dog> 是 Converter<Dog, Animal> 的子类型
// 参数：Animal 逆变 → 满足
// 返回值：Dog 协变 → 满足

declare const a: Converter<Animal, Dog>
declare const b: Converter<Dog, Animal>

const c: typeof b = a // OK
// const d: typeof a = b // 报错
```

## 四、strictFunctionTypes

TypeScript 2.6 引入的编译选项（`strict: true` 下默认开启），强制函数参数遵循逆变规则。

### 关闭时（不安全）

```typescript
// strictFunctionTypes: false
const handleMouse: Handler<MouseEvent> = (event) => {
  console.log(event.button)
}
const handleEvent: Handler<Event> = handleMouse // 不报错，但不安全
```

### 开启时（安全）

```typescript
// strictFunctionTypes: true
const handleMouse: Handler<MouseEvent> = (event) => {
  console.log(event.button)
}
// const handleEvent: Handler<Event> = handleMouse // 报错
```

### 方法声明的特殊规则

```typescript
interface EventHandler<T> {
  // 方法声明：双变（不安全但实用）
  handle(event: T): void
}

interface EventHandlerFn<T> {
  // 函数属性：逆变（安全）
  handle: (event: T) => void
}
```

TypeScript 做这个区分是因为方法声明通常用于描述对象的行为（鸭子类型），而函数属性更强调类型安全。

## 五、实际应用：类型安全的事件系统

```typescript
type EventMap = {
  click: { x: number; y: number }
  keydown: { key: string; code: string }
}

class TypedEventEmitter<Events extends Record<string, unknown>> {
  private handlers = new Map<string, Set<Function>>()

  on<K extends keyof Events>(
    event: K,
    handler: (payload: Events[K]) => void
  ): () => void {
    const set = this.handlers.get(event as string) ?? new Set()
    set.add(handler)
    this.handlers.set(event as string, set)
    return () => set.delete(handler)
  }

  emit<K extends keyof Events>(event: K, payload: Events[K]): void {
    const set = this.handlers.get(event as string)
    if (set) {
      for (const handler of set) {
        ;(handler as (p: Events[K]) => void)(payload)
      }
    }
  }
}

const emitter = new TypedEventEmitter<EventMap>()

emitter.on("click", (payload) => {
  console.log(payload.x, payload.y) // 类型安全
})
```

## 常见误区

1. **混淆方法声明和函数属性的协变性**：方法声明是双变的，函数属性是逆变的。
2. **不理解回调参数为什么是逆变的**：回调参数由调用方提供，你的回调期望更具体类型时，调用方提供更宽泛类型会出错。
3. **认为数组协变是安全的**：`Dog[]` 可赋值给 `Animal[]`，但可以往里放 `Cat`。`ReadonlyArray` 才是真正安全的。
4. **忽略 `strictFunctionTypes` 的影响**：关闭它会隐藏类型不安全的赋值。

## 工程建议

1. **回调函数的参数类型要尽可能宽泛**：让调用方可以传入更具体的处理器。
2. **用 `ReadonlyArray` 替代 `Array` 作为函数参数**：真正协变且安全。
3. **开启 `strictFunctionTypes`**：发现潜在的类型不安全问题。
4. **接口中的回调用函数属性而非方法声明**：除非你明确需要双变行为。

## 小结

函数参数逆变保证了"能处理更宽泛类型的能力可以安全地替代处理更具体类型的能力"，返回值协变保证了"返回更具体类型的能力可以安全地替代返回更宽泛类型的能力"。

## 练习

### 练习一：判断协变逆变

对于 `type Box<T> = { get(): T; set(value: T): void }`，判断 Box 对 T 是协变、逆变还是不变的。

### 练习二：设计类型安全的 Comparator

设计 `Comparator<T>` 类型，要求 `Comparator<Dog>` 可以赋值给 `Comparator<Animal>`。

### 练习三：修复不安全的事件处理器

以下代码在 `strictFunctionTypes` 下会报错，修复它：
```typescript
type Handler<T> = (event: T) => void
const handleEvent: Handler<Event> = (e) => console.log(e.type)
const handleMouse: Handler<MouseEvent> = handleEvent // 报错
```

---

## 参考答案

### 练习一

**思路**：分析 T 出现的位置——get() 返回值（协变）和 set() 参数（逆变）。

**答案**：

```typescript
type Box<T> = { get(): T; set(value: T): void }

// Box<T> 对 T 是不变的（invariant）
// get(): T — 协变
// set(value: T): void — 逆变
// 同时包含协变和逆变位置 → 不变
```

**要点**：当类型参数同时出现在协变和逆变位置时，整体是不变的。只读容器协变，只写容器逆变，读写容器不变。

### 练习二

**思路**：Comparator 的参数在逆变位置，所以 `Comparator<Animal>` 是 `Comparator<Dog>` 的子类型。

**答案**：

```typescript
type Comparator<T> = (a: T, b: T) => number

function sort<T>(items: T[], comparator: Comparator<T>): T[] {
  return [...items].sort(comparator)
}

class Animal { constructor(public name: string) {} }
class Dog extends Animal { constructor(name: string, public breed: string) { super(name) } }

const compareAnimals: Comparator<Animal> = (a, b) => a.name.localeCompare(b.name)

const dogs = [new Dog("Buddy", "Golden"), new Dog("Max", "Labrador")]
const sorted = sort(dogs, compareAnimals) // OK
```

**要点**：能比较任意 Animal 的比较器可以安全地用于比较 Dog。参数逆变保证了这一点。

### 练习三

**思路**：让回调参数类型更宽泛，或使用泛型约束。

**答案**：

```typescript
type Handler<T> = (event: T) => void

// 方案一：使用泛型约束
function createHandler<T extends Event>(
  handler: (event: T) => void
): Handler<T> {
  return handler
}

const clickHandler = createHandler<MouseEvent>((e) => {
  console.log(e.button)
})

// 方案二：让 handler 接受更宽泛的类型
const handleEvent: Handler<Event> = (e) => console.log(e.type)
// 不要把 Handler<Event> 赋值给 Handler<MouseEvent>
// 而是直接使用 handleEvent，或者创建专门的 MouseEvent handler
```

**要点**：类型安全的根本解决方案是让回调参数类型与事件源匹配。`as` 类型断言可以绕过检查，但会牺牲类型安全。
