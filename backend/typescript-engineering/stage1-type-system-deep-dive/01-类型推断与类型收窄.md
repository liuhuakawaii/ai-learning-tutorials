# 01 - 类型推断与类型收窄

## 场景引入

你在维护一个后端接口，函数接收一个参数，可能是字符串 ID、数字 ID 或完整的用户对象。你需要根据参数类型执行不同的查询逻辑。TypeScript 的类型推断和收窄机制，就是为了解决这类问题——让编译器帮你精确判断每个分支里的类型。

## 学习目标

- 理解 TypeScript 类型推断的三种机制：基础推断、最佳公共类型、上下文类型推断
- 掌握所有内置类型收窄方式：typeof、instanceof、in、相等性判断
- 能编写自定义类型守卫函数（type predicates）
- 理解判别联合（discriminated unions）的设计模式
- 掌握 const assertions 和 satisfies 操作符的工程用途

## 一、类型推断机制

### 1.1 基础推断

```typescript
let name = "张三"        // 推断为 string
let age = 25             // 推断为 number
const userId = "abc-123" // 推断为 "abc-123"（字面量类型）
```

`const` 推断为字面量类型，`let` 推断为宽泛类型，因为 `const` 声明的变量不能重新赋值。

### 1.2 最佳公共类型

```typescript
const items = [0, 1, "hello", true]
// 推断为 (string | number | boolean)[]

class Animal {}
class Dog extends Animal { bark() {} }
class Cat extends Animal { meow() {} }

const pets = [new Dog(), new Cat()]
// 推断为 (Dog | Cat)[]
```

### 1.3 上下文类型推断

```typescript
window.onmousedown = function (mouseEvent) {
  // mouseEvent 被推断为 MouseEvent
  console.log(mouseEvent.button)
}

type EventHandler = (event: { type: string; payload: unknown }) => void
const handler: EventHandler = (event) => {
  // event 自动推断为 { type: string; payload: unknown }
  console.log(event.type, event.payload)
}
```

## 二、类型收窄

### 2.1 typeof 守卫

```typescript
function formatInput(input: string | number): string {
  if (typeof input === "string") {
    return input.toUpperCase()
  }
  return input.toFixed(2)
}
```

### 2.2 instanceof 守卫

```typescript
class ApiError {
  constructor(public statusCode: number, public message: string) {}
}
class NetworkError {
  constructor(public url: string) {}
}

function handleError(error: ApiError | NetworkError) {
  if (error instanceof ApiError) {
    console.log(`API 错误 ${error.statusCode}: ${error.message}`)
  } else {
    console.log(`网络错误: 无法访问 ${error.url}`)
  }
}
```

### 2.3 in 操作符

```typescript
interface Bird { fly(): void; layEggs(): void }
interface Fish { swim(): void; layEggs(): void }

function move(animal: Bird | Fish) {
  if ("fly" in animal) {
    animal.fly()
  } else {
    animal.swim()
  }
}
```

### 2.4 自定义类型守卫

```typescript
interface User {
  id: string
  name: string
  email?: string
}

function isUser(value: unknown): value is User {
  return (
    typeof value === "object" &&
    value !== null &&
    "id" in value &&
    "name" in value &&
    typeof (value as User).id === "string" &&
    typeof (value as User).name === "string"
  )
}

function processInput(input: unknown) {
  if (isUser(input)) {
    console.log(input.name.toUpperCase())
  }
}
```

类型谓词 `value is User` 是关键，它告诉 TypeScript：当函数返回 `true` 时，参数的类型就是 `User`。

### 2.5 判别联合

```typescript
type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "rectangle"; width: number; height: number }
  | { kind: "triangle"; base: number; height: number }

function assertNever(value: never): never {
  throw new Error(`未处理的类型: ${JSON.stringify(value)}`)
}

function describeShape(shape: Shape): string {
  switch (shape.kind) {
    case "circle":
      return `圆形，半径 ${shape.radius}`
    case "rectangle":
      return `矩形，宽 ${shape.width} 高 ${shape.height}`
    case "triangle":
      return `三角形，底 ${shape.base} 高 ${shape.height}`
    default:
      return assertNever(shape)
  }
}
```

如果后续给 `Shape` 添加新变体但忘记更新函数，TypeScript 会在编译时报错。

## 三、类型拓宽与约束

### 3.1 const 断言

```typescript
const STATUS = {
  ACTIVE: "active",
  INACTIVE: "inactive",
  PENDING: "pending",
} as const

type Status = (typeof STATUS)[keyof typeof STATUS]
// "active" | "inactive" | "pending"
```

### 3.2 satisfies 操作符

```typescript
type Config = { port: number; host: string; debug?: boolean }

const config = {
  port: 3000,
  host: "localhost",
} satisfies Config
// config.port 的类型是 3000（字面量类型保留）

const routes = {
  home: { path: "/", auth: false },
  profile: { path: "/profile", auth: true },
} satisfies Record<string, { path: string; auth: boolean }>

console.log(routes.home.path)    // 类型安全
console.log(routes.profile.auth) // 类型安全
```

## 常见误区

1. **typeof 只能判断基础类型**：`typeof null === "object"` 是历史包袱。对于数组和自定义对象，`typeof` 返回 `"object"`，要用 `Array.isArray()` 或 `instanceof`。

2. **类型守卫函数不加类型谓词**：判断函数返回类型是 `boolean` 时，调用方无法收窄类型，必须使用 `param is Type` 语法。

3. **在异步函数中使用类型守卫**：类型守卫只在同步代码中有效，`await` 后不能假设类型仍然收窄。

4. **混淆 `as` 断言和类型收窄**：`as` 是告诉编译器"相信我"，类型收窄是让编译器"自己判断"。

## 工程建议

1. **优先使用判别联合而不是类型断言**：设计数据结构时加上 `kind` 或 `type` 标签字段。
2. **为关键判断函数编写类型守卫**：使用 `value is Type` 谓词。
3. **用 `satisfies` 替代大部分类型注解**：保证类型安全又保留精度。
4. **用 `as const` 定义常量集合**：状态码、错误码等自动生成联合类型。

## 小结

类型推断和收窄是 TypeScript 类型系统的核心机制。推断让你少写类型注解，收窄让你在运行时精确判断类型。判别联合是最实用的收窄模式，`satisfies` 和 `as const` 是保持类型精度的关键工具。

## 参考答案

### 练习一

**思路**：类型谓词 `value is NonNullable<T>` 告诉 TypeScript 当函数返回 true 时，参数已排除 null 和 undefined。

**答案**：

```typescript
function isNonNullable<T>(value: T): value is NonNullable<T> {
  return value !== null && value !== undefined
}

const mixed = [1, null, "hello", undefined, 42, null]
const filtered = mixed.filter(isNonNullable)
// filtered 的类型是 (string | number)[]
```

**要点**：`filter(isNonNullable)` 可以直接传入类型守卫函数。不用类型守卫时，`filter(x => x != null)` 的结果类型仍包含 null。

### 练习二

**思路**：用判别联合定义 Success 和 Failure，用 `kind` 字段区分，`match` 接收两个回调分别处理。

**答案**：

```typescript
type Result<T, E = Error> =
  | { kind: "success"; value: T }
  | { kind: "failure"; error: E }

function success<T>(value: T): Result<T, never> {
  return { kind: "success", value }
}

function failure<E>(error: E): Result<never, E> {
  return { kind: "failure", error }
}

function match<T, E, U>(
  result: Result<T, E>,
  onSuccess: (value: T) => U,
  onFailure: (error: E) => U
): U {
  switch (result.kind) {
    case "success": return onSuccess(result.value)
    case "failure": return onFailure(result.error)
    default: {
      const _: never = result
      throw new Error(`未处理的变体: ${JSON.stringify(_)}`)
    }
  }
}
```

**要点**：`success` 返回 `Result<T, never>`，`failure` 返回 `Result<never, E>`，让泛型推断更精确。

### 练习三

**思路**：用 `satisfies` 验证整体结构符合 `RouteConfig` 类型，同时保留每个路由的精确类型。

**答案**：

```typescript
type HttpMethod = "GET" | "POST" | "PUT" | "DELETE"

type RouteEntry = {
  method: HttpMethod
  path: string
  auth?: boolean
}

const routes = {
  getUsers: { method: "GET", path: "/api/users", auth: true },
  createUser: { method: "POST", path: "/api/users", auth: true },
  healthCheck: { method: "GET", path: "/health", auth: false },
} satisfies Record<string, RouteEntry>

console.log(routes.getUsers.method) // 类型是 "GET"，不是 string
console.log(routes.healthCheck.auth) // 类型是 false，不是 boolean | undefined
```

**要点**：`satisfies` 不改变变量的推断类型，只是在赋值时做兼容性检查，相比 `as` 保留了每个字段的字面量类型。
