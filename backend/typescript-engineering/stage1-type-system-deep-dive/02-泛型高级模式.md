# 02 - 泛型高级模式

## 场景引入

你在开发一个数据获取库，需要支持不同的 API 端点。每个端点返回的数据结构不同，你希望调用方传入端点名称时，返回值类型能自动推断出来——传 `"/users"` 返回 `User[]`，传 `"/posts"` 返回 `Post[]`。这种"根据输入推断输出类型"的能力，就是泛型高级模式的核心应用。

## 学习目标

- 掌握条件类型的语法和使用场景
- 熟练使用 `infer` 关键字从复杂类型中提取信息
- 理解映射类型的原理，能自定义 `Partial`、`Required` 等工具类型
- 掌握模板字面量类型，实现类型安全的字符串操作
- 了解类型递归的基本用法和限制

## 一、条件类型

条件类型是类型层面的三元表达式，语法为 `T extends U ? X : Y`：

```typescript
type IsString<T> = T extends string ? true : false

type A = IsString<string>   // true
type B = IsString<number>   // false
type C = IsString<"hello">  // true
```

条件类型在泛型中特别有用：

```typescript
type ApiResponse<T> = T extends "user"
  ? { id: string; name: string; email: string }
  : T extends "post"
    ? { id: string; title: string; content: string }
    : never

function fetchData<T extends "user" | "post">(endpoint: T): Promise<ApiResponse<T>> {
  return fetch(`/api/${endpoint}`).then((r) => r.json()) as Promise<ApiResponse<T>>
}

const user = await fetchData("user")
// 类型是 { id: string; name: string; email: string }
```

### 分布式条件类型

当 `T` 是联合类型时，条件类型会自动分发：

```typescript
type ToArray<T> = T extends any ? T[] : never
type Result = ToArray<string | number>
// string[] | number[]，不是 (string | number)[]

// 阻止分发：用方括号包裹
type ToArrayNonDist<T> = [T] extends [any] ? T[] : never
type Result2 = ToArrayNonDist<string | number>
// (string | number)[]
```

## 二、infer 关键字

`infer` 用于在条件类型中声明待推断的类型变量。

```typescript
// 提取函数返回类型
type ReturnTypeOf<T> = T extends (...args: any[]) => infer R ? R : never
type A = ReturnTypeOf<() => string>  // string

// 提取函数参数类型
type ParametersOf<T> = T extends (...args: infer P) => any ? P : never
type B = ParametersOf<(a: string, b: number) => void>
// [a: string, b: number]

// 提取 Promise 内部类型
type UnwrapPromise<T> = T extends Promise<infer U> ? U : T
type C = UnwrapPromise<Promise<string>>  // string

// 提取数组元素类型
type ElementOf<T> = T extends (infer E)[] ? E : never
type D = ElementOf<string[]>  // string

// 递归提取深层嵌套类型
type DeepUnwrap<T> = T extends Promise<infer U> ? DeepUnwrap<U> : T
type E = DeepUnwrap<Promise<Promise<Promise<string>>>>  // string
```

## 三、映射类型

映射类型通过遍历类型的键来生成新类型：

```typescript
type Mutable<T> = { -readonly [K in keyof T]: T[K] }
type Readonly2<T> = { readonly [K in keyof T]: T[K] }
type Partial2<T> = { [K in keyof T]?: T[K] }
type Required2<T> = { [K in keyof T]-?: T[K] }
```

### 键重映射

```typescript
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K]
}

interface User { id: string; name: string; email: string }
type UserGetters = Getters<User>
// { getId: () => string; getName: () => string; getEmail: () => string }
```

### 过滤键

```typescript
type OnlyStringValues<T> = {
  [K in keyof T as T[K] extends string ? K : never]: T[K]
}

interface Mixed { name: string; age: number; email: string; active: boolean }
type StringFields = OnlyStringValues<Mixed>
// { name: string; email: string }
```

## 四、模板字面量类型

```typescript
type Greeting = `hello ${"world" | "typescript"}`
// "hello world" | "hello typescript"

type EventName = "click" | "scroll" | "keypress"
type HandlerName = `on${Capitalize<EventName>}`
// "onClick" | "onScroll" | "onKeypress"

type CssProperty = "margin" | "padding"
type CssDirection = "top" | "right" | "bottom" | "left"
type CssKeys = `${CssProperty}-${CssDirection}`
// "margin-top" | "margin-right" | ... | "padding-left"
```

### 类型安全的事件系统

```typescript
type EventMap = {
  user: { id: string; name: string }
  post: { id: string; title: string }
}

type EventHandlers<T> = {
  [K in keyof T as `on${Capitalize<string & K>}Change`]?: (value: T[K]) => void
}

type UserEventHandlers = EventHandlers<EventMap>
// { onUserChange?: ...; onPostChange?: ... }
```

## 常见误区

1. **在不需要泛型的地方使用泛型**：如果参数和返回值之间没有类型关系，不需要泛型。`function process<T>(x: T): string` 不是好用法。

2. **条件类型分发导致意外结果**：`T extends string ? A : B` 当 T 是联合类型时会分发。不需要分发时用 `[T] extends [string]` 包裹。

3. **infer 只能在条件类型的 extends 子句中使用**：不能在其他地方使用。

4. **过度复杂的类型体操**：如果一个类型定义需要 20 行才能理解，考虑拆分。

## 工程建议

1. **优先使用内置工具类型**：`Partial`、`Required`、`Pick`、`Omit`、`ReturnType`、`Parameters` 等已覆盖大部分场景。
2. **用条件类型实现 API 类型自动推断**：让调用方传入字符串字面量，返回值类型自动推断。
3. **映射类型配合键重映射**：`Getters<T>`、`EventHandlers<T>` 等模式可以自动生成样板代码的类型。
4. **模板字面量类型用于事件和 CSS 属性**：自动生成事件处理器名称和 CSS 属性名。

## 小结

条件类型是类型层面的 if-else，infer 是类型提取的核心工具，映射类型通过遍历键生成新类型，模板字面量类型在类型层面操作字符串。这四个特性组合起来，可以实现高度自动化的类型推断。

## 练习

### 练习一：实现 Flatten 类型

使用条件类型和 infer 实现 `Flatten<T>`，将嵌套数组展平一层：`Flatten<number[][]>` 应得到 `number[]`。

### 练习二：实现路径参数提取

使用模板字面量类型和递归，从路径字符串中提取参数：`ExtractParams<"/users/:id/posts/:postId">` 应得到 `{ id: string; postId: string }`。

### 练习三：实现类型安全的 EventEmitter

设计一个 `EventEmitter<T>` 类，T 是事件映射类型 `{ eventName: payloadType }`，`on`、`emit` 方法都有完整的类型推断。

## 参考答案

### 练习一

**思路**：用 `infer` 提取数组元素类型。

**答案**：

```typescript
type Flatten<T> = T extends Array<infer U> ? U : T

type A = Flatten<number[]>      // number
type B = Flatten<string[][]>    // string[]
type C = Flatten<number[][][]>  // number[][]（只展平一层）

// 任意层级展平
type DeepFlatten<T> = T extends Array<infer U> ? DeepFlatten<U> : T
type D = DeepFlatten<number[][][]>  // number
```

**要点**：`T extends Array<infer U>` 匹配数组类型并提取元素类型。DeepFlatten 通过递归实现任意层级展平。

### 练习二

**思路**：用模板字面量类型匹配 `:param` 模式，递归处理剩余路径。

**答案**：

```typescript
type ExtractParams<T extends string> =
  T extends `${string}:${infer Param}/${infer Rest}`
    ? { [K in Param | keyof ExtractParams<Rest>]: string }
    : T extends `${string}:${infer Param}`
      ? { [K in Param]: string }
      : {}

type A = ExtractParams<"/users/:id">  // { id: string }
type B = ExtractParams<"/users/:id/posts/:postId">  // { id: string; postId: string }
type C = ExtractParams<"/health">  // {}
```

**要点**：第一个分支匹配 `:param/rest` 模式并递归，第二个分支匹配末尾 `:param`，第三个处理无参数路径。

### 练习三

**思路**：用映射类型定义事件映射，`on` 和 `emit` 的参数类型根据事件名自动推断。

**答案**：

```typescript
class EventEmitter<T extends Record<string, unknown[]>> {
  private handlers = new Map<string, Function[]>()

  on<K extends keyof T>(event: K, handler: (...args: T[K]) => void): void {
    const list = this.handlers.get(event as string) ?? []
    list.push(handler)
    this.handlers.set(event as string, list)
  }

  emit<K extends keyof T>(event: K, ...args: T[K]): void {
    const list = this.handlers.get(event as string) ?? []
    for (const handler of list) handler(...args)
  }
}

interface MyEvents {
  login: [user: { id: string; name: string }]
  logout: []
  error: [error: Error, context: string]
}

const emitter = new EventEmitter<MyEvents>()

emitter.on("login", (user) => {
  console.log(user.name)  // 自动推断
})

emitter.emit("login", { id: "1", name: "张三" })
```

**要点**：`T extends Record<string, unknown[]>` 约束事件映射的值必须是数组。`K extends keyof T` 确保事件名必须是已注册的事件。
