# 04 - 声明文件与类型增强

## 场景引入

你引入了一个第三方库来处理日期，但它的类型定义不完整——缺少你项目中扩展的方法。或者你使用了一个全局变量注入的 SDK（比如微信 JSSDK），它在运行时存在于 `window` 上，但 TypeScript 不知道它的类型。你需要编写声明文件来告诉 TypeScript 这些外部代码的类型信息。

## 学习目标

- 掌握 `.d.ts` 声明文件的编写规范和最佳实践
- 理解模块增强（module augmentation）的原理和使用场景
- 能进行全局类型扩展，为 `window`、`process.env` 等添加自定义类型
- 了解 ambient 声明与具体实现的区别
- 掌握第三方库类型缺失时的解决方案

## 一、声明文件基础

### 1.1 声明全局变量

```typescript
// global.d.ts
declare const __APP_VERSION__: string
declare const __DEV__: boolean
declare function gtag(command: string, ...params: unknown[]): void
```

使用时 TypeScript 不会报错：

```typescript
console.log(`版本: ${__APP_VERSION__}`)
if (__DEV__) console.log("开发模式")
```

### 1.2 声明模块

为没有类型定义的 npm 包创建声明：

```typescript
// types/lodash-id.d.ts
declare module "lodash-id" {
  import { Collection } from "lodash"
  interface LoDashIdExtensions<T> {
    insert(doc: T): T
    upsert(doc: T): T
    getById(id: string | number): T | undefined
  }
  const lodashId: {
    configure(collection: Collection<any>, options?: object): void
  }
  export default lodashId
}
```

在 `tsconfig.json` 中配置类型目录：

```json
{
  "compilerOptions": {
    "typeRoots": ["./types", "./node_modules/@types"]
  }
}
```

## 二、模块增强

模块增强让你在已有模块上添加新的类型声明：

```typescript
// types/express.d.ts
import "express"

declare module "express" {
  interface Request {
    user: {
      id: string
      role: "admin" | "user"
    }
    requestId: string
  }

  interface Response {
    success(data: unknown): void
    error(message: string, statusCode?: number): void
  }
}
```

`import "express"` 让文件成为模块增强，接口会与原始声明合并。

### 扩展第三方库的方法

```typescript
// types/date-extend.d.ts
import dayjs from "dayjs"

declare module "dayjs" {
  interface Dayjs {
    toRelativeNow(): string
    isBusinessDay(): boolean
  }
}
```

## 三、全局类型扩展

### 3.1 扩展 Window 对象

```typescript
// types/global.d.ts
declare global {
  interface Window {
    __APP_CONFIG__: {
      apiUrl: string
      env: "development" | "staging" | "production"
    }
    gtag: (
      command: "config" | "event" | "set",
      targetId: string,
      config?: Record<string, unknown>
    ) => void
  }
}

export {}
```

`export {}` 确保文件被当作模块处理，`declare global` 才能正确扩展。

### 3.2 扩展 process.env

```typescript
// types/env.d.ts
declare global {
  namespace NodeJS {
    interface ProcessEnv {
      NODE_ENV: "development" | "production" | "test"
      PORT: string
      DATABASE_URL: string
      JWT_SECRET: string
      REDIS_URL?: string
      LOG_LEVEL?: "debug" | "info" | "warn" | "error"
    }
  }
}

export {}
```

使用时获得完整类型提示：

```typescript
const dbUrl = process.env.DATABASE_URL   // string
const redisUrl = process.env.REDIS_URL   // string | undefined
```

### 3.3 扩展 ImportMeta（Vite）

```typescript
// types/vite.d.ts
interface ImportMetaEnv {
  readonly VITE_API_URL: string
  readonly VITE_APP_TITLE: string
}

interface ImportMeta {
  readonly env: ImportMetaEnv
}
```

## 四、Ambient 声明

### 4.1 Ambient 模块

```typescript
// types/assets.d.ts
declare module "*.md" {
  const content: string
  export default content
}

declare module "*.svg" {
  import { ComponentType, SVGProps } from "react"
  const ReactComponent: ComponentType<SVGProps<SVGSVGElement>>
  export default ReactComponent
}

declare module "*.css" {
  const classes: Record<string, string>
  export default classes
}
```

### 4.2 品牌类型（Branded Types）

```typescript
// types/branded.d.ts
declare const __brand: unique symbol

type Brand<T, B extends string> = T & { readonly [__brand]: B }

type UserId = Brand<string, "UserId">
type OrderId = Brand<string, "OrderId">

function getUser(id: UserId): User { /* ... */ }

declare const userId: UserId
declare const orderId: OrderId

getUser(userId)   // OK
// getUser(orderId) // 编译报错
```

## 常见误区

1. **在 .d.ts 文件中写运行时代码**：声明文件只包含类型信息，任何运行时代码都会导致编译错误或被忽略。

2. **忘记 `export {}` 使文件成为模块**：在全局类型扩展文件中，没有 `export {}` 时 `declare global` 不会生效。

3. **模块增强路径错误**：`declare module "express"` 的路径必须与 `import` 语句的路径完全一致。

4. **过度使用 `any` 在声明文件中**：声明文件中的 `any` 会污染所有使用该类型的代码，用 `unknown` 替代。

## 工程建议

1. **优先使用 `@types` 包**：DefinitelyTyped 提供了大部分流行库的类型定义。
2. **把全局类型扩展放在专门的目录**：`types/` 目录下按职责拆分（`global.d.ts`、`express.d.ts`、`env.d.ts`）。
3. **用模块增强扩展框架类型**：Express 中间件、Vue 插件、React Context 等场景，模块增强是标准做法。
4. **声明文件也该有测试**：用 `tsd` 或 `expect-type` 测试声明文件的正确性。

## 小结

声明文件是 TypeScript 与 JavaScript 生态的桥梁。`.d.ts` 文件为无类型代码提供类型，模块增强扩展已有类型，全局声明扩展运行时环境。掌握这些机制，你就能让 TypeScript 理解任何 JavaScript 代码的类型。

## 参考答案

### 练习一

**思路**：在 `NodeJS.ProcessEnv` 接口中添加项目需要的环境变量。

**答案**：

```typescript
// types/env.d.ts
declare global {
  namespace NodeJS {
    interface ProcessEnv {
      NODE_ENV: "development" | "production" | "test"
      PORT: string
      DATABASE_URL: string
      JWT_SECRET: string
      REDIS_URL?: string
      LOG_LEVEL?: "debug" | "info" | "warn" | "error"
    }
  }
}

export {}
```

**要点**：`declare global` + `export {}` 是扩展全局类型的标准模式。枚举值用字面量联合类型限制。

### 练习二

**思路**：使用模块增强扩展 Express 的 Request 和 Response 接口。

**答案**：

```typescript
// types/express.d.ts
import "express"

declare module "express" {
  interface Request {
    user: { id: string; email: string; role: "admin" | "user" }
    requestId: string
  }

  interface Response {
    success(data: unknown, statusCode?: number): void
    error(message: string, statusCode?: number): void
  }
}
```

**要点**：`import "express"` 是必需的，它让文件成为模块增强。接口合并是声明文件的核心特性。

### 练习三

**思路**：使用通配符模块声明匹配所有 `.module.css` 文件的导入。

**答案**：

```typescript
// types/css-modules.d.ts
declare module "*.module.css" {
  const classes: Record<string, string>
  export default classes
}

declare module "*.module.scss" {
  const classes: Record<string, string>
  export default classes
}
```

**要点**：`declare module "*.module.css"` 使用通配符 `*` 匹配任意文件名。同时声明 `.scss`、`.less` 以支持不同预处理器。
