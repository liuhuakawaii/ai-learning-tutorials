# 脚本打包与分发

## 场景引入

你写了一个好用的命令行工具，同事也想用。但他没装 Python，或者版本不对，装依赖总出问题。你不能每次都手把手教安装。

需要把脚本打包成**无需 Python 环境就能运行**的可执行文件，或通过标准化工具分发，一键安装、开箱即用。

## 学习目标

- 掌握 PyInstaller 打包为可执行文件
- 学会使用 pipx 分发命令行工具
- 了解 Docker 容器化部署
- 理解 setuptools/poetry 发布到 PyPI

## PyInstaller 打包

### 基础用法

```bash
pip install pyinstaller

pyinstaller --onefile main.py              # 单文件
pyinstaller --onedir main.py               # 目录（启动快）
pyinstaller --onefile --icon=app.ico main.py  # 带图标
pyinstaller --onefile --noconsole app.py   # 无控制台（GUI）
pyinstaller --onefile --name mytool main.py   # 指定名称
```

### spec 文件

```python
# mytool.spec
a = Analysis(
    ["main.py"],
    datas=[("config/*.yaml", "config"), ("templates/*", "templates")],
    hiddenimports=["yaml", "requests"],
    excludes=["tkinter", "matplotlib"],
)
pyz = PYZ(a.pure)
exe = EXE(pyz, a.scripts, a.binaries, a.datas,
    name="mytool", console=True, icon="assets/icon.ico", upx=True)
```

### 资源文件定位

```python
import sys
from pathlib import Path


def get_resource(relative: str) -> Path:
    """兼容开发环境和打包环境"""
    if getattr(sys, "frozen", False):
        return Path(sys._MEIPASS) / relative
    return Path(__file__).parent / relative


config = get_resource("config/settings.yaml")
template = get_resource("templates/report.html")
```

### 自动化打包

```python
# build_exe.py
import PyInstaller.__main__
from version_manager import load_version, to_string


def build():
    ver = to_string(load_version())
    PyInstaller.__main__.run([
        "main.py", "--onefile",
        "--name", f"mytool-{ver}",
        "--add-data", "config;config",
        "--clean", "--noconfirm",
    ])
    print(f"✓ 构建完成: dist/mytool-{ver}.exe")
```

## pipx 分发 CLI 工具

pipx 每个工具装在独立虚拟环境中，避免依赖冲突：

```bash
pip install pipx
pipx ensurepath

pipx install httpie          # 安装 CLI 工具
pipx install .               # 安装本地包
pipx run pycowsay "hello"    # 一次性运行
pipx list                    # 列出已安装
pipx upgrade httpie          # 升级
```

### 让项目支持 pipx

```toml
# pyproject.toml
[project]
name = "mytool"
version = "1.0.0"
dependencies = ["click>=8.0", "requests>=2.28"]

[project.scripts]
mytool = "mytool.cli:main"
```

```python
# src/mytool/cli.py
import click


@click.group()
def main():
    """一个实用的命令行工具"""
    pass


@main.command()
@click.argument("name")
def hello(name):
    click.echo(f"你好, {name}!")
```

## Docker 容器化

```dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY src/ ./src/
ENTRYPOINT ["python", "-m", "mytool"]
```

```bash
docker build -t mytool:latest .
docker run --rm mytool:latest hello "World"
docker run --rm -v ./config:/app/config mytool:latest process data.csv
```

## 分发方式对比

| 方式 | 需要 Python | 安装难度 | 体积 | 更新方式 | 适用场景 |
|------|------------|---------|------|---------|---------|
| PyInstaller | 不需要 | 最简单 | 大(50MB+) | 重新下载 | 非开发者 |
| pipx | 需要 | 简单 | 小 | pipx upgrade | CLI 工具 |
| Docker | 不需要 | 中等 | 中等 | 拉新镜像 | 服务器 |
| PyPI+pip | 需要 | 简单 | 小 | pip install -U | 开源项目 |

## 常见误区

1. **打包后太大**：没排除不需要的模块，用 `--exclude-module` 减小体积
2. **资源文件找不到**：打包后路径不同，必须用 `sys._MEIPASS`
3. **杀毒误报**：PyInstaller 经常被误报，需对可执行文件签名
4. **不测试打包结果**：只在开发环境测试，打包后才发现缺依赖
5. **版本号硬编码**：散落多处，应统一管理

## 工程建议

- 打包前在干净虚拟环境测试，确保依赖声明完整
- CI/CD 自动化打包，避免手动出错
- 为可执行文件加版本号和数字签名
- 优先 pipx 或 PyPI，只有目标无 Python 时才用 PyInstaller

## 小结

本课学习了多种打包分发方式：PyInstaller 独立可执行文件、pipx CLI 工具管理、Docker 容器化、setuptools/poetry 发布 PyPI。选择取决于目标用户和环境。

将 CLI 工具打包为可执行文件：单文件模式、包含配置文件、打包后能正确读取配置、文件名含版本号。

```python
import click, yaml
from pathlib import Path

def load_config():
    p = Path(__file__).parent / "config.yaml"
    if not p.exists(): return {"debug": False}
    with open(p) as f: return yaml.safe_load(f)

@click.group()
def cli(): pass

@cli.command()
@click.argument("text")
def echo(text):
    cfg = load_config()
    click.echo(f"[{'DEBUG' if cfg.get('debug') else 'INFO'}] {text}")
```

## 参考答案

### 练习一

**思路**：用 `sys._MEIPASS` 定位资源，spec 文件配置 datas。

**答案**：

```python
import sys, click
from pathlib import Path

def get_base() -> Path:
    if getattr(sys, "frozen", False): return Path(sys._MEIPASS)
    return Path(__file__).parent

def load_config() -> dict:
    import yaml
    p = get_base() / "config" / "config.yaml"
    if not p.exists(): return {"debug": False}
    with open(p, encoding="utf-8") as f: return yaml.safe_load(f)

# main.py
@click.group()
def cli(): pass

@cli.command()
@click.argument("text")
def echo(text):
    cfg = load_config()
    click.echo(f"[{'DEBUG' if cfg.get('debug') else 'INFO'}] {text}")

if __name__ == "__main__": cli()
```

```python
# build.py
import PyInstaller.__main__
from version_manager import load_version, to_string

def build():
    ver = to_string(load_version())
    PyInstaller.__main__.run(["main.py", "--onefile", "--name", f"mytool-{ver}",
                              "--add-data", "config;config", "--clean", "--noconfirm"])

if __name__ == "__main__": build()
```

**要点**：`sys._MEIPASS` 是解压临时路径，`--add-data` 分隔符 Windows 用 `;`，Linux 用 `:`。

### 练习二

**思路**：`pyproject.toml` 统一配置，多阶段 Dockerfile，GitHub Actions 自动发布。

```toml
[tool.poetry.scripts]
mytool = "mytool.cli:main"
```

```dockerfile
FROM python:3.11-slim AS builder
WORKDIR /app
COPY pyproject.toml poetry.lock ./
RUN pip install poetry && poetry export -f requirements.txt -o requirements.txt

FROM python:3.11-slim
WORKDIR /app
COPY --from=builder /app/requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY src/ ./src/
ENTRYPOINT ["python", "-m", "mytool"]
```

```yaml
# .github/workflows/release.yml - tag 触发发布
# jobs: test → publish (twine upload dist/*)
```

**要点**：`[tool.poetry.scripts]` 同时满足 pip 和 pipx，多阶段构建减小镜像体积，tag 触发发布。
