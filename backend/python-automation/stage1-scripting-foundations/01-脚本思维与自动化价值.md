# 脚本思维与自动化价值

## 场景引入

小王是团队里的运营专员，每周一早上要花 2 小时做同一件事：从 5 个 Excel 文件中提取数据、汇总到一张表、按规则重命名、发邮件给领导。他做了两年，从未觉得有什么问题——直到有一天，新来的实习生用 Python 写了一个 40 行的脚本，整个流程 30 秒跑完。

这不是个例。在软件工程领域，大量重复性工作被手动执行，不是因为技术上做不到自动化，而是因为执行者没有建立"脚本思维"——一种识别重复劳动、评估自动化价值、用代码替代人力的思维方式。

本课的目标不是教你写复杂的程序，而是帮你建立这种思维方式：**什么时候该写脚本，什么时候不该写，以及如何衡量自动化的价值。**

## 学习目标

- 理解脚本思维的核心逻辑
- 学会判断哪些任务值得自动化
- 掌握 ROI 计算方法
- 建立"重复即浪费"的工程意识

### 一、脚本思维的核心逻辑

脚本思维可以用四个步骤概括：

```
识别重复 → 评估价值 → 编写脚本 → 验证效果
```

**识别重复**：任何需要执行两次以上的手动操作，都值得被记录下来。关键判断标准不是"这个操作难不难"，而是"这个操作会不会再次发生"。

**评估价值**：不是所有重复都值得自动化。你需要计算投入产出比——花 8 小时写脚本来省掉一个每周 5 分钟的任务，可能并不划算。

**编写脚本**：用最简单的方式实现。脚本不需要优雅，不需要可复用，它只需要正确地完成任务。

**验证效果**：脚本跑完后，检查结果是否与手动操作一致。自动化最大的风险不是脚本报错，而是脚本"静默地给出错误结果"。

### 二、什么值得自动化

判断一个任务是否值得自动化，可以用下面这个框架：

| 维度 | 倾向自动化 | 倾向手动 |
|------|-----------|---------|
| 执行频率 | 每天/每周 | 每年一次 |
| 单次耗时 | 超过 10 分钟 | 不到 1 分钟 |
| 出错代价 | 高（如删除文件、发送通知） | 低（如查看状态） |
| 操作复杂度 | 步骤多但逻辑固定 | 步骤少但需要判断 |
| 一致性要求 | 必须完全一致 | 允许有差异 |

举个具体例子：批量重命名 1000 个文件。

手动操作：
- 打开文件管理器
- 逐个右键重命名
- 预计耗时：1000 × 3 秒 = 50 分钟
- 出错率：手滑改错文件名，大约 5% 的概率

Python 脚本：

```python
import os
from pathlib import Path

def batch_rename(directory: str, old_pattern: str, new_pattern: str) -> int:
    """批量重命名文件，返回成功数量。"""
    target_dir = Path(directory)
    if not target_dir.exists():
        raise FileNotFoundError(f"目录不存在: {directory}")

    renamed_count = 0
    for file_path in target_dir.iterdir():
        if file_path.is_file() and old_pattern in file_path.name:
            new_name = file_path.name.replace(old_pattern, new_pattern)
            new_path = file_path.parent / new_name
            file_path.rename(new_path)
            renamed_count += 1
            print(f"  {file_path.name} → {new_name}")

    return renamed_count

if __name__ == "__main__":
    count = batch_rename("./photos", "IMG_", "旅行_")
    print(f"\n完成，共重命名 {count} 个文件")
```

脚本执行时间：不到 3 秒。出错率：只要逻辑正确，0%。

### 三、ROI 计算

ROI（投资回报率）是决定是否自动化的核心指标。公式很简单：

```
ROI = (节省的时间 × 执行次数 - 开发时间) / 开发时间
```

**实例一：每周汇总报表**

- 手动耗时：每次 2 小时
- 执行频率：每周一次，一年 50 次
- 脚本开发时间：4 小时
- 年节省时间：2 × 50 - 4 = 96 小时
- ROI = 96 / 4 = 2400%

结论：强烈值得自动化。

**实例二：年度证书生成**

- 手动耗时：每次 4 小时
- 执行频率：每年一次
- 脚本开发时间：8 小时
- 年节省时间：4 - 8 = -4 小时

结论：不值得自动化，除非你能预估未来几年还会继续做。

**实例三：临界点分析**

有些任务单独看不值得自动化，但如果多个类似任务可以共用一套脚本框架，整体 ROI 就上去了：

```python
def calculate_roi(
    manual_minutes: float,
    frequency_per_year: int,
    development_hours: float,
    years: int = 1
) -> dict:
    """计算自动化 ROI。"""
    manual_hours_per_year = (manual_minutes / 60) * frequency_per_year
    total_manual_hours = manual_hours_per_year * years
    saved_hours = total_manual_hours - development_hours
    roi = (saved_hours / development_hours) * 100 if development_hours > 0 else float("inf")

    return {
        "每年手动耗时_小时": round(manual_hours_per_year, 1),
        f"{years}年总节省_小时": round(saved_hours, 1),
        "ROI_百分比": round(roi, 1),
        "值得自动化": saved_hours > 0,
    }

# 每周汇总报表
result = calculate_roi(manual_minutes=120, frequency_per_year=50, development_hours=4)
print(result)
# {'每年手动耗时_小时': 100.0, '1年总节省_小时': 96.0, 'ROI_百分比': 2400.0, '值得自动化': True}
```

### 四、真实场景：文件整理自动化

假设你有一个下载目录，里面堆满了各种文件。你想按文件类型自动归类：

```python
import shutil
from pathlib import Path

FILE_CATEGORIES = {
    "图片": [".jpg", ".jpeg", ".png", ".gif", ".webp", ".svg"],
    "文档": [".pdf", ".docx", ".xlsx", ".pptx", ".txt", ".md"],
    "视频": [".mp4", ".avi", ".mkv", ".mov"],
    "音频": [".mp3", ".wav", ".flac", ".aac"],
    "压缩包": [".zip", ".rar", ".7z", ".tar", ".gz"],
    "代码": [".py", ".js", ".ts", ".java", ".go", ".rs"],
}

def organize_downloads(source_dir: str, dry_run: bool = True) -> dict:
    """整理下载目录，按文件类型分类。dry_run=True 时只预览不执行。"""
    source = Path(source_dir)
    if not source.exists():
        raise FileNotFoundError(f"目录不存在: {source_dir}")

    extension_map = {}
    for category, extensions in FILE_CATEGORIES.items():
        for ext in extensions:
            extension_map[ext.lower()] = category

    result = {"moved": 0, "skipped": 0, "actions": []}

    for file_path in source.iterdir():
        if not file_path.is_file():
            continue

        ext = file_path.suffix.lower()
        category = extension_map.get(ext, "其他")
        target_dir = source / category
        target_path = target_dir / file_path.name

        if target_path.exists():
            result["skipped"] += 1
            result["actions"].append(f"跳过(已存在): {file_path.name}")
            continue

        if not dry_run:
            target_dir.mkdir(exist_ok=True)
            shutil.move(str(file_path), str(target_path))

        result["moved"] += 1
        result["actions"].append(f"移动: {file_path.name} → {category}/")

    return result

if __name__ == "__main__":
    # 先预览
    preview = organize_downloads("D:/Downloads", dry_run=True)
    print(f"预览: 将移动 {preview['moved']} 个文件，跳过 {preview['skipped']} 个")
    for action in preview["actions"][:10]:
        print(f"  {action}")

    # 确认后执行
    confirm = input("\n确认执行? (y/n): ")
    if confirm.lower() == "y":
        result = organize_downloads("D:/Downloads", dry_run=False)
        print(f"完成: 移动了 {result['moved']} 个文件")
```

注意 `dry_run` 参数——这是自动化脚本的重要模式。先预览再执行，避免误操作。

## 常见误区

**误区一：追求"完美"脚本**

很多初学者花大量时间把脚本写得优雅、可复用、有完善的错误处理。但如果你的脚本只需要跑一次，能用就行。一个 20 行能跑通的脚本，比一个花 3 天写出来的"完美"框架更实用。

**误区二：所有重复都要自动化**

有些操作虽然重复，但每次执行时需要大量人工判断（比如代码审查）。这种任务可以自动化其中的一部分（比如自动跑 linter），但不能完全替代人工。

**误区三：忽略维护成本**

脚本不是写完就完了。如果脚本依赖的外部系统变了（API 改了、文件格式变了），你需要花时间维护。在计算 ROI 时，要把维护成本考虑进去。

**误区四：自动化错误的流程**

如果一个流程本身就不合理，自动化它只会让错误发生得更快。先优化流程，再自动化。

## 工程建议

1. **从小处开始**：先自动化一个 5 分钟的任务，感受成功的正反馈，再逐步扩大范围
2. **记录重复操作**：每次发现自己在做重复工作，记下来。周末花 1 小时批量自动化
3. **脚本要有 dry-run 模式**：特别是涉及文件操作、数据库修改、网络请求的脚本
4. **脚本要有日志**：即使是临时脚本，至少用 `print()` 记录关键步骤，方便出错时排查
5. **把脚本当工具，不是产品**：脚本不需要单元测试、不需要 CI/CD、不需要考虑扩展性——除非它要给团队用

## 小结

- 脚本思维的核心是**识别重复 → 评估价值 → 编写脚本 → 验证效果**
- 用 ROI 公式量化自动化的价值：`ROI = (节省时间 × 频次 - 开发时间) / 开发时间`
- 不是所有重复都值得自动化，关键是看频率、耗时和出错代价
- 先预览再执行（dry-run 模式）是自动化脚本的基本安全规范
- 自动化错误的流程比不自动化更危险

### 练习一

**思路**：套用 ROI 公式，代入手动耗时、频率和开发时间。

```python
def calculate_roi(manual_minutes, frequency_per_year, development_hours, years=1):
    manual_hours_per_year = (manual_minutes / 60) * frequency_per_year

```

- 每年手动耗时：45/60 × 12 = 9 小时
- 年节省时间：9 - 6 = 3 小时
- ROI = 3/6 × 100 = 800%

**要点**：虽然 ROI 看起来很高，但实际节省只有 3 小时。如果脚本的维护成本低，值得做；如果环境经常变化导致脚本频繁修改，可能不划算。

### 练习二

**思路**：添加 `dry_run` 参数，控制是否真正执行删除操作。

**答案**：

```python
import os

def delete_temp_files(directory: str, dry_run: bool = True):
    """删除目录下所有 .tmp 文件。dry_run=True 时只预览不删除。"""
    deleted_count = 0
    for filename in os.listdir(directory):
        if filename.endswith(".tmp"):
            filepath = os.path.join(directory, filename)
            if dry_run:
                print(f"[预览] 将删除: {filename}")
            else:
                os.remove(filepath)
                print(f"已删除: {filename}")
            deleted_count += 1

    mode = "预览" if dry_run else "执行"
    print(f"\n{mode}完成，共 {deleted_count} 个文件")
    return deleted_count
```

**要点**：dry-run 模式应该和真实执行走同样的逻辑分支，只是跳过实际修改操作。这样可以确保预览结果和真实执行一致。

### 练习三

**思路**：遍历文件、获取修改时间、格式化为年月目录名、移动文件。

**答案**：

```python
import os
import shutil
from datetime import datetime

def organize_by_date(directory: str, dry_run: bool = True):
    """按修改日期将文件归类到年月子目录。"""
    if not os.path.exists(directory):
        raise FileNotFoundError(f"目录不存在: {directory}")

    stats = {"moved": 0, "skipped": 0}

    for filename in os.listdir(directory):
        filepath = os.path.join(directory, filename)
        if not os.path.isfile(filepath):
            continue

        mtime = os.path.getmtime(filepath)
        date_str = datetime.fromtimestamp(mtime).strftime("%Y-%m")
        target_dir = os.path.join(directory, date_str)
        target_path = os.path.join(target_dir, filename)

        if os.path.exists(target_path):
            stats["skipped"] += 1
            continue

        if dry_run:
            print(f"[预览] {filename} → {date_str}/")
        else:
            os.makedirs(target_dir, exist_ok=True)
            shutil.move(filepath, target_path)
            print(f"移动: {filename} → {date_str}/")

        stats["moved"] += 1

    print(f"\n{'预览' if dry_run else '执行'}完成: 移动 {stats['moved']} 个，跳过 {stats['skipped']} 个")
    return stats

if __name__ == "__main__":
    organize_by_date("./downloads", dry_run=True)
```

**要点**：使用 `os.makedirs(exist_ok=True)` 避免目录已存在时报错。跳过已存在于目标位置的同名文件，防止覆盖。
