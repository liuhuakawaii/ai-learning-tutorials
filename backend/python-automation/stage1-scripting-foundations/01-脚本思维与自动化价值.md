# 脚本思维与自动化价值

## 什么值得写脚本

你每周一早上要做同一件事：从 5 个 Excel 里提数据、汇总、重命名、发邮件。每次 2 小时，做了两年。直到某天你看到同事用 40 行 Python 把同样的事 30 秒跑完。

这不是个例。大量重复性工作被手动执行，不是因为技术做不到，而是执行者没建立"脚本思维"——识别重复劳动、评估自动化价值、用代码替代人力的思维方式。

## 判断框架

不是所有重复都值得自动化。判断标准：

| 维度 | 倾向自动化 | 倾向手动 |
|------|-----------|---------|
| 执行频率 | 每天/每周 | 每年一次 |
| 单次耗时 | 超过 10 分钟 | 不到 1 分钟 |
| 出错代价 | 高（删文件、发通知） | 低（查看状态） |
| 操作复杂度 | 步骤多但逻辑固定 | 步骤少但需要判断 |

ROI 公式：

```
ROI = (节省的时间 × 执行次数 - 开发时间) / 开发时间
```

每周汇总报表：手动 2 小时 × 50 次/年 - 开发 4 小时 = 年省 96 小时，ROI 2400%。值得做。

年度证书生成：手动 4 小时 × 1 次/年 - 开发 8 小时 = 负 4 小时。不值得做，除非能复用。

## 脚本思维四步

```
识别重复 → 评估价值 → 编写脚本 → 验证效果
```

识别：任何执行两次以上的手动操作都值得记录。判断标准不是"难不难"，而是"会不会再次发生"。

编写：用最简单的方式实现。脚本不需要优雅、不需要可复用，只需要正确完成任务。

验证：脚本跑完后检查结果是否与手动操作一致。自动化最大的风险不是报错，而是"静默地给出错误结果"。

## dry-run 模式

涉及文件操作、数据库修改、网络请求的脚本，必须支持"先预览再执行"：

```python
import shutil
from pathlib import Path

FILE_CATEGORIES = {
    "图片": [".jpg", ".jpeg", ".png", ".gif", ".webp"],
    "文档": [".pdf", ".docx", ".xlsx", ".pptx", ".txt"],
    "视频": [".mp4", ".avi", ".mkv", ".mov"],
    "压缩包": [".zip", ".rar", ".7z", ".tar", ".gz"],
}

def organize_downloads(source_dir: str, dry_run: bool = True) -> dict:
    """整理下载目录，按文件类型分类。dry_run=True 时只预览不执行。"""
    source = Path(source_dir)
    extension_map = {}
    for category, extensions in FILE_CATEGORIES.items():
        for ext in extensions:
            extension_map[ext.lower()] = category

    result = {"moved": 0, "skipped": 0, "actions": []}

    for file_path in source.iterdir():
        if not file_path.is_file():
            continue
        ext = file_path.suffix.lower()
        category = extension_map.get(ext, "其他")
        target_dir = source / category
        target_path = target_dir / file_path.name

        if target_path.exists():
            result["skipped"] += 1
            continue

        if not dry_run:
            target_dir.mkdir(exist_ok=True)
            shutil.move(str(file_path), str(target_path))

        result["moved"] += 1
        result["actions"].append(f"{file_path.name} → {category}/")

    return result

if __name__ == "__main__":
    preview = organize_downloads("D:/Downloads", dry_run=True)
    print(f"预览: 将移动 {preview['moved']} 个文件")
    for action in preview["actions"][:10]:
        print(f"  {action}")

    confirm = input("\n确认执行? (y/n): ")
    if confirm.lower() == "y":
        result = organize_downloads("D:/Downloads", dry_run=False)
        print(f"完成: 移动了 {result['moved']} 个文件")
```

`dry_run` 参数是自动化脚本的基本安全规范。预览和执行走同样的逻辑分支，只是跳过实际修改，确保预览结果和真实执行一致。

## 常见误判

**追求"完美"脚本**：一个 20 行能跑通的脚本，比花 3 天写出来的"完美"框架更实用。脚本只需要正确完成任务。

**所有重复都要自动化**：有些操作每次需要大量人工判断（如代码审查）。可以自动化其中一部分（自动跑 linter），但不能完全替代。

**自动化错误的流程**：如果流程本身不合理，自动化只会让错误发生得更快。先优化流程，再自动化。

**忽略维护成本**：脚本依赖的外部系统变了（API 改了、文件格式变了），需要维护。ROI 计算要把维护成本算进去。

### 练习二

```python
import os

def delete_temp_files(directory: str, dry_run: bool = True):
    deleted = 0
    for filename in os.listdir(directory):
        if filename.endswith(".tmp"):
            filepath = os.path.join(directory, filename)
            if dry_run:
                print(f"[预览] 将删除: {filename}")
            else:
                os.remove(filepath)
                print(f"已删除: {filename}")
            deleted += 1
    mode = "预览" if dry_run else "执行"
    print(f"{mode}完成，共 {deleted} 个文件")
```

关键：dry-run 和真实执行走同样的判断逻辑，只是跳过 `os.remove`。

### 练习三

```python
import os
import shutil
from datetime import datetime

def organize_by_date(directory: str, dry_run: bool = True):
    stats = {"moved": 0, "skipped": 0}
    for filename in os.listdir(directory):
        filepath = os.path.join(directory, filename)
        if not os.path.isfile(filepath):
            continue
        mtime = os.path.getmtime(filepath)
        date_str = datetime.fromtimestamp(mtime).strftime("%Y-%m")
        target_dir = os.path.join(directory, date_str)
        target_path = os.path.join(target_dir, filename)
        if os.path.exists(target_path):
            stats["skipped"] += 1
            continue
        if dry_run:
            print(f"[预览] {filename} → {date_str}/")
        else:
            os.makedirs(target_dir, exist_ok=True)
            shutil.move(filepath, target_path)
        stats["moved"] += 1
    print(f"{'预览' if dry_run else '执行'}完成: 移动 {stats['moved']}，跳过 {stats['skipped']}")
```
