# 定时任务

## 场景引入

你的团队需要每天凌晨 2 点备份数据库、每小时同步一次外部数据、每周一生成周报。手动执行不现实，你需要一个可靠的定时任务调度系统。Python 有多个调度方案：简单的 `schedule` 库、功能完整的 `APScheduler`，以及系统级的 `crontab`。

## 学习目标

- 掌握 `schedule` 库实现简单定时调度
- 掌握 `APScheduler` 的间隔调度、定时调度和 cron 表达式
- 理解任务持久化和分布式调度的实现方式
- 能根据场景选择合适的调度方案

## schedule — 轻量级调度

```python
import schedule, time

def job_backup():
    print(f"[{time.strftime('%H:%M:%S')}] 执行数据库备份...")

def job_sync():
    print(f"[{time.strftime('%H:%M:%S')}] 同步外部数据...")

schedule.every().day.at("02:00").do(job_backup)
schedule.every(30).minutes.do(job_sync)
schedule.every().monday.at("09:00").do(lambda: print("生成周报"))

while True:
    schedule.run_pending()
    time.sleep(1)
```

`schedule` 语法简洁，适合单进程内少量定时任务，但不支持持久化和分布式。

## APScheduler — 生产级调度

### 间隔调度

```python
from apscheduler.schedulers.blocking import BlockingScheduler
from apscheduler.triggers.interval import IntervalTrigger

scheduler = BlockingScheduler()

def sync_data():
    print("同步外部数据...")

scheduler.add_job(sync_data, IntervalTrigger(minutes=30), id="sync_data")
scheduler.start()
```

### Cron 表达式调度

```python
from apscheduler.schedulers.background import BackgroundScheduler
from apscheduler.triggers.cron import CronTrigger

scheduler = BackgroundScheduler()

scheduler.add_job(lambda: print("凌晨2点备份"), CronTrigger(hour=2, minute=0))
scheduler.add_job(lambda: print("每小时报告"), CronTrigger(minute=0))
scheduler.add_job(lambda: print("周一9点周报"), CronTrigger(day_of_week="mon", hour=9))
scheduler.add_job(lambda: print("工作日18点提醒"), CronTrigger(day_of_week="mon-fri", hour=18))

scheduler.start()
```

### 任务持久化

```python
from apscheduler.jobstores.sqlalchemy import SQLAlchemyJobStore
from apscheduler.executors.pool import ThreadPoolExecutor

jobstores = {"default": SQLAlchemyJobStore(url="sqlite:///jobs.sqlite")}
executors = {"default": ThreadPoolExecutor(max_workers=5)}
job_defaults = {"coalesce": True, "max_instances": 1, "misfire_grace_time": 300}

scheduler = BlockingScheduler(
    jobstores=jobstores, executors=executors, job_defaults=job_defaults
)
scheduler.add_job(lambda: print("持久化任务"), "cron", hour=3, id="important")
scheduler.start()
```

`coalesce=True` 解决宕机后错过的任务合并为一次执行，避免集中爆发。

## 分布式调度

多台服务器运行调度器时，需要避免任务重复执行：

```python
import redis

class RedisLock:
    def __init__(self, redis_client: redis.Redis, key: str, ttl: int = 60):
        self.redis = redis_client
        self.key = f"lock:{key}"
        self.ttl = ttl

    def acquire(self) -> bool:
        return self.redis.set(self.key, "1", nx=True, ex=self.ttl)

    def release(self):
        self.redis.delete(self.key)

# 在任务执行前获取锁
r = redis.Redis()
lock = RedisLock(r, "daily_backup")
if lock.acquire():
    try:
        # 执行任务
        pass
    finally:
        lock.release()
```

## 调度方案对比

| 特性 | schedule | APScheduler | crontab |
|------|----------|------------|---------|
| 复杂度 | 极简 | 中等 | 系统级 |
| Cron 表达式 | 不支持 | 支持 | 支持 |
| 持久化 | 不支持 | 支持 | 系统持久化 |
| 分布式 | 不支持 | 需自行实现 | 每台独立 |
| 适用场景 | 简单脚本 | 应用内调度 | 系统级定时 |

## 完整示例：定时数据同步调度器

```python
import logging, sqlite3
from datetime import datetime
from apscheduler.schedulers.blocking import BlockingScheduler
from apscheduler.triggers.cron import CronTrigger
from apscheduler.triggers.interval import IntervalTrigger

logging.basicConfig(level=logging.INFO, format="%(asctime)s [%(levelname)s] %(message)s")
logger = logging.getLogger(__name__)

DB_PATH = "sync_scheduler.db"

def init_db():
    conn = sqlite3.connect(DB_PATH)
    conn.execute("""CREATE TABLE IF NOT EXISTS sync_log (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        task_name TEXT, status TEXT, message TEXT,
        started_at TEXT, finished_at TEXT
    )""")
    conn.commit(); conn.close()

def log_task(task_name: str, status: str, message: str, started_at: str):
    conn = sqlite3.connect(DB_PATH)
    conn.execute("INSERT INTO sync_log (task_name,status,message,started_at,finished_at) VALUES (?,?,?,?,?)",
                 (task_name, status, message, started_at, datetime.now().isoformat()))
    conn.commit(); conn.close()

def run_task(task_name: str, func):
    started_at = datetime.now().isoformat()
    logger.info(f"开始执行: {task_name}")
    try:
        func()
        log_task(task_name, "success", "", started_at)
    except Exception as e:
        log_task(task_name, "failed", str(e), started_at)
        logger.error(f"失败: {task_name} - {e}")

def sync_users(): logger.info("同步用户数据...")
def sync_orders(): logger.info("同步订单数据...")

def daily_cleanup():
    conn = sqlite3.connect(DB_PATH)
    conn.execute("DELETE FROM sync_log WHERE started_at < datetime('now','-30 days')")
    conn.commit(); conn.close()

if __name__ == "__main__":
    init_db()
    scheduler = BlockingScheduler()
    scheduler.add_job(run_task, IntervalTrigger(minutes=30), args=["用户同步", sync_users])
    scheduler.add_job(run_task, IntervalTrigger(hours=2), args=["订单同步", sync_orders])
    scheduler.add_job(run_task, CronTrigger(hour=3, minute=0), args=["日志清理", daily_cleanup])
    logger.info("调度器已启动")
    try:
        scheduler.start()
    except (KeyboardInterrupt, SystemExit):
        logger.info("调度器已停止")
```

## 常见误区

1. **调度器阻塞主线程**：`BlockingScheduler` 会阻塞，需要非阻塞用 `BackgroundScheduler`。
2. **任务重叠**：执行时间超过调度间隔时会重叠，设置 `max_instances=1`。
3. **错过执行集中爆发**：服务宕机恢复后，设置 `coalesce=True` 和 `misfire_grace_time`。
4. **调度任务里做耗时操作**：默认线程池执行，长时间阻塞会耗尽线程。
5. **依赖系统时间**：多台服务器时间不同步会导致调度混乱，确保 NTP 同步。

## 工程建议

1. **简单场景用 `schedule`**：几条规则、单进程运行、不需要持久化时最轻量。
2. **生产环境用 `APScheduler`**：需要持久化、cron 表达式、任务管理 API 时选它。
3. **系统级任务用 `crontab`**：与应用无关的系统维护任务用系统 cron。
4. **分布式部署加锁**：多实例部署时用 Redis 锁保证任务只执行一次。

## 参考答案

### 练习一

**思路**：包装任务函数，内部实现重试逻辑，失败后 `time.sleep` 等待。

**答案**：

```python
import schedule, time, logging

logging.basicConfig(level=logging.INFO, format="%(asctime)s %(message)s")

def retry_task(name: str, func, max_retries=3, interval=5):
    for attempt in range(1, max_retries + 1):
        try:
            func()
            logging.info(f"[{name}] 第 {attempt} 次成功")
            return
        except Exception as e:
            logging.warning(f"[{name}] 第 {attempt} 次失败: {e}")
            if attempt < max_retries:
                time.sleep(interval)
    logging.error(f"[{name}] 重试 {max_retries} 次后失败")

def flaky_api():
    import random
    if random.random() < 0.7:
        raise ConnectionError("API 超时")
    print("API 成功")

schedule.every(10).minutes.do(retry_task, "数据同步", flaky_api)
while True:
    schedule.run_pending()
    time.sleep(1)
```

**要点**：`retry_task` 是通用包装器，任何任务函数都能复用。

### 练习二

**思路**：用 `BackgroundScheduler` 保持非阻塞，配合命令行交互循环。

**答案**：

```python
from apscheduler.schedulers.background import BackgroundScheduler
from apscheduler.triggers.interval import IntervalTrigger

scheduler = BackgroundScheduler()
scheduler.start()

def add_task(name: str, seconds: int):
    scheduler.add_job(lambda: print(f"执行: {name}"),
                      IntervalTrigger(seconds=seconds), id=name, replace_existing=True)
    print(f"已添加: {name} (每 {seconds} 秒)")

def remove_task(name: str):
    try:
        scheduler.remove_job(name)
        print(f"已删除: {name}")
    except Exception:
        print(f"任务不存在: {name}")

print("命令: add <name> <seconds> | remove <name> | list | quit")
while True:
    parts = input("> ").strip().split()
    if not parts: continue
    if parts[0] == "add" and len(parts) == 3:
        add_task(parts[1], int(parts[2]))
    elif parts[0] == "remove" and len(parts) == 2:
        remove_task(parts[1])
    elif parts[0] == "list":
        for j in scheduler.get_jobs():
            print(f"  {j.id}: 下次 {j.next_run_time}")
    elif parts[0] == "quit":
        scheduler.shutdown(); break
```

**要点**：`replace_existing=True` 允许同名任务重新添加。
