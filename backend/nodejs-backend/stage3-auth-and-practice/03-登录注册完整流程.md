# 第三课：登录注册完整流程

## 场景引入

你已经学会了密码加密和 JWT 的原理，但当你真正动手实现注册接口时，会发现事情远比想象中复杂：用户提交的邮箱格式不对怎么办？密码强度不够怎么提示？两次密码不一致如何处理？邮箱已被注册是返回"邮箱不存在"还是"密码错误"？登录失败时应该告诉用户"邮箱不存在"还是"密码错误"（答案是：都不能说，否则攻击者可以枚举有效邮箱）。这些细节处理的好坏，直接决定了系统的安全性和用户体验。本课将带你从零实现一套生产级别的登录注册流程，覆盖输入验证、错误处理、三层架构等工程实践。

## 学习目标

完成本课学习后，你将能够：

1. 完整实现用户注册流程（输入验证 → 密码加密 → 创建用户 → 返回 Token）
2. 完整实现用户登录流程（查找用户 → 验证密码 → 生成 Token → 返回响应）
3. 实现获取当前用户信息接口
4. 掌握输入验证的最佳实践
5. 处理各种错误场景（用户已存在、密码错误等）
6. 按照 Controller → Service → Routes 三层架构组织代码

```typescript
  })
```

```typescript
  res: Response,
  data: T[],
  total: number,
  page: number,
  pageSize: number
) {
  return res.status(200).json({
    success: true,

    data: {
      items: data,

        total,
        page,
        pageSize,
        totalPages: Math.ceil(total / pageSize)

    }
  })
```

```typescript
import { Request, Response, NextFunction } from 'express'
import { AppError, ValidationError } from '../utils/errors'

export function errorHandler(err: Error, req: Request, res: Response, next: NextFunction) {
  // 如果是已知的应用错误
  if (err instanceof ValidationError) {
    return res.status(err.statusCode).json({
      success: false,
      message: err.message,
      errors: err.errors
    })
  }

  if (err instanceof AppError) {
    return res.status(err.statusCode).json({
      success: false,
      message: err.message
    })
  }

  // 未知错误
  console.error('Unexpected error:', err)
  return res.status(500).json({
    success: false,
    message: process.env.NODE_ENV === 'development'
      ? err.message
      : '服务器内部错误'
  })
}
```

### 3.2 验证中间件

```typescript
// src/middleware/validate.ts
import { Request, Response, NextFunction } from 'express'
import { AnyZodObject, ZodError } from 'zod'

/**
 * 通用输入验证中间件工厂函数
 * @param schema - Zod 验证 Schema
 * @param source - 验证数据来源（body / query / params）
 */
export function validate(
  schema: AnyZodObject,
  source: 'body' | 'query' | 'params' = 'body'
) {
  return (req: Request, res: Response, next: NextFunction) => {
    try {
      // 验证并替换请求数据（会进行类型转换和默认值处理）
      const validated = schema.parse(req[source])
      req[source] = validated
      next()
    } catch (error) {
      if (error instanceof ZodError) {
        // 将 Zod 错误转换为友好的格式
        const errors: Record<string, string> = {}
        error.errors.forEach((err) => {
          const field = err.path.join('.')
          errors[field] = err.message
        })

        return res.status(422).json({
          success: false,
          message: '输入验证失败',
          errors
        })
      }
      next(error)
    }
  }
}
```

```typescript
// src/utils/auth.ts
import bcrypt from 'bcryptjs'
import jwt, { JwtPayload } from 'jsonwebtoken'
import { env } from '../config/env'

// ==================== 密码 ====================

export async function hashPassword(password: string): Promise<string> {
  return bcrypt.hash(password, 10)
}

export async function comparePassword(password: string, hash: string): Promise<boolean> {
  return bcrypt.compare(password, hash)
}

// ==================== JWT ====================

export interface TokenPayload {
  userId: number
  email: string
  role: string
}

export interface TokenPair {
  accessToken: string
  refreshToken: string
}

export function generateTokenPair(payload: TokenPayload): TokenPair {
  const accessToken = jwt.sign(payload, env.JWT_ACCESS_SECRET, {
    expiresIn: env.JWT_ACCESS_EXPIRES
  })

  const refreshToken = jwt.sign(
    { userId: payload.userId },
    env.JWT_REFRESH_SECRET,
    { expiresIn: env.JWT_REFRESH_EXPIRES }
  )

  return { accessToken, refreshToken }
}

export function verifyAccessToken(token: string): TokenPayload {
  try {
    const payload = jwt.verify(token, env.JWT_ACCESS_SECRET) as TokenPayload & JwtPayload
    return {
      userId: payload.userId,
      email: payload.email,
      role: payload.role
    }
  } catch (error) {
    if (error instanceof jwt.TokenExpiredError) {
      throw new Error('ACCESS_TOKEN_EXPIRED')
    }
    throw new Error('ACCESS_TOKEN_INVALID')
  }
}

export function verifyRefreshToken(token: string): { userId: number } {
  try {
    const payload = jwt.verify(token, env.JWT_REFRESH_SECRET) as JwtPayload
    return { userId: payload.userId }
  } catch (error) {
    if (error instanceof jwt.TokenExpiredError) {
      throw new Error('REFRESH_TOKEN_EXPIRED')
    }
    throw new Error('REFRESH_TOKEN_INVALID')
  }
}

export function extractToken(authHeader: string | undefined): string | null {
  if (!authHeader || !authHeader.startsWith('Bearer ')) {
    return null
  }
  return authHeader.split(' ')[1]
}
```

## 五、认证服务层（核心业务逻辑）

```typescript
// src/services/auth.service.ts
import { prisma } from '../config/database'
import {
  hashPassword,
  comparePassword,
  generateTokenPair,
  verifyRefreshToken,
  TokenPayload,
  TokenPair
} from '../utils/auth'
import { AppError, ConflictError, AuthError, NotFoundError } from '../utils/errors'
import { RegisterInput, LoginInput } from '../validators/auth.validator'

// 用户信息类型（不包含密码）
type SafeUser = {
  id: number
  email: string
  username: string
  role: string
  avatar: string | null
  bio: string | null
  createdAt: Date
}

/**
 * 认证服务
 * 包含所有与认证相关的业务逻辑
 */
export class AuthService {
  /**
   * 用户注册
   */
  async register(input: RegisterInput): Promise<{ user: SafeUser; tokens: TokenPair }> {
    const { email, username, password } = input

    // 1. 检查邮箱是否已注册
    const existingEmail = await prisma.user.findUnique({
      where: { email }
    })
    if (existingEmail) {
      throw new ConflictError('该邮箱已被注册')
    }

    // 2. 检查用户名是否已被使用
    const existingUsername = await prisma.user.findUnique({
      where: { username }
    })
    if (existingUsername) {
      throw new ConflictError('该用户名已被使用')
    }

    // 3. 密码加密
    const hashedPassword = await hashPassword(password)

    // 4. 创建用户
    const user = await prisma.user.create({
      data: {
        email,
        username,
        password: hashedPassword,
        role: 'USER'
      }
    })

    // 5. 生成 Token
    const tokenPayload: TokenPayload = {
      userId: user.id,
      email: user.email,
      role: user.role
    }
    const tokens = generateTokenPair(tokenPayload)

    // 6. 返回用户信息（不含密码）和 Token
    const safeUser = this.toSafeUser(user)
    return { user: safeUser, tokens }
  }

  /**
   * 用户登录
   */
  async login(input: LoginInput): Promise<{ user: SafeUser; tokens: TokenPair }> {
    const { email, password } = input

    // 1. 查找用户
    const user = await prisma.user.findUnique({
      where: { email }
    })

    // 安全提示：不要明确告诉用户是"邮箱不存在"还是"密码错误"
    // 统一返回"邮箱或密码不正确"
    if (!user) {
      throw new AuthError('邮箱或密码不正确')
    }

    // 2. 验证密码
    const isPasswordValid = await comparePassword(password, user.password)
    if (!isPasswordValid) {
      throw new AuthError('邮箱或密码不正确')
    }

    // 3. 生成 Token
    const tokenPayload: TokenPayload = {
      userId: user.id,
      email: user.email,
      role: user.role
    }
    const tokens = generateTokenPair(tokenPayload)

    // 4. 返回用户信息和 Token
    const safeUser = this.toSafeUser(user)
    return { user: safeUser, tokens }
  }

  /**
   * 获取当前用户信息
   */
  async getCurrentUser(userId: number): Promise<SafeUser> {
    const user = await prisma.user.findUnique({
      where: { id: userId }
    })

    if (!user) {
      throw new NotFoundError('用户不存在')
    }

    return this.toSafeUser(user)
  }

  /**
   * 刷新 Token
   */
  async refreshToken(refreshToken: string): Promise<TokenPair> {
    // 1. 验证 Refresh Token
    const { userId } = verifyRefreshToken(refreshToken)

    // 2. 查找用户（确保用户仍然存在）
    const user = await prisma.user.findUnique({
      where: { id: userId }
    })

    if (!user) {
      throw new AuthError('用户不存在')
    }

    // 3. 生成新的 Token 对
    const tokenPayload: TokenPayload = {
      userId: user.id,
      email: user.email,
      role: user.role
    }
    return generateTokenPair(tokenPayload)
  }

  /**
   * 更新个人资料
   */
  async updateProfile(userId: number, data: { username?: string; bio?: string }): Promise<SafeUser> {
    // 如果要更新用户名，检查是否已被使用
    if (data.username) {
      const existing = await prisma.user.findFirst({
        where: {
          username: data.username,
          id: { not: userId }
        }
      })
      if (existing) {
        throw new ConflictError('该用户名已被使用')
      }
    }

    const user = await prisma.user.update({
      where: { id: userId },
      data
    })

    return this.toSafeUser(user)
  }

  /**
   * 修改密码
   */
  async changePassword(
    userId: number,
    oldPassword: string,
    newPassword: string
  ): Promise<void> {
    const user = await prisma.user.findUnique({
      where: { id: userId }
    })

    if (!user) {
      throw new NotFoundError('用户不存在')
    }

    // 验证旧密码
    const isOldPasswordValid = await comparePassword(oldPassword, user.password)
    if (!isOldPasswordValid) {
      throw new AuthError('旧密码不正确')
    }

    // 加密新密码并更新
    const hashedNewPassword = await hashPassword(newPassword)
    await prisma.user.update({
      where: { id: userId },
      data: { password: hashedNewPassword }
    })
  }

  /**
   * 将用户对象转换为安全格式（去除密码等敏感字段）
   */
  private toSafeUser(user: any): SafeUser {
    const { password, ...safeUser } = user
    return safeUser as SafeUser
  }
}

// 导出单例
export const authService = new AuthService()
```

```typescript
// src/controllers/auth.controller.ts
import { Request, Response, NextFunction } from 'express'
import { authService } from '../services/auth.service'
import { sendSuccess, sendCreated } from '../utils/response'

/**
 * 认证控制器
 * 负责接收请求、调用服务、返回响应
 */
export class AuthController {
  /**
   * POST /api/auth/register
   * 用户注册
   */
  async register(req: Request, res: Response, next: NextFunction) {
    try {
      const result = await authService.register(req.body)

      return sendCreated(res, {
        user: result.user,
        accessToken: result.tokens.accessToken,
        refreshToken: result.tokens.refreshToken
      }, '注册成功')
    } catch (error) {
      next(error)
    }
  }

  /**
   * POST /api/auth/login
   * 用户登录
   */
  async login(req: Request, res: Response, next: NextFunction) {
    try {
      const result = await authService.login(req.body)

      return sendSuccess(res, {
        user: result.user,
        accessToken: result.tokens.accessToken,
        refreshToken: result.tokens.refreshToken
      }, '登录成功')
    } catch (error) {
      next(error)
    }
  }

  /**
   * GET /api/auth/me
   * 获取当前登录用户信息
   */
  async getMe(req: Request, res: Response, next: NextFunction) {
    try {
      const userId = req.user!.userId
      const user = await authService.getCurrentUser(userId)

      return sendSuccess(res, { user })
    } catch (error) {
      next(error)
    }
  }

  /**
   * POST /api/auth/refresh
   * 刷新 Token
   */
  async refresh(req: Request, res: Response, next: NextFunction) {
    try {
      const { refreshToken } = req.body

      if (!refreshToken) {
        return res.status(400).json({
          success: false,
          message: 'Refresh Token 不能为空'
        })
      }

      const tokens = await authService.refreshToken(refreshToken)

      return sendSuccess(res, {
        accessToken: tokens.accessToken,
        refreshToken: tokens.refreshToken
      }, 'Token 刷新成功')
    } catch (error) {
      next(error)
    }
  }

  /**
   * PUT /api/auth/profile
   * 更新个人资料
   */
  async updateProfile(req: Request, res: Response, next: NextFunction) {
    try {
      const userId = req.user!.userId
      const user = await authService.updateProfile(userId, req.body)

      return sendSuccess(res, { user }, '个人资料更新成功')
    } catch (error) {
      next(error)
    }
  }

  /**

  async changePassword(req: Request, res: Response, next: NextFunction) {

      const { oldPassword, newPassword } = req.body

      await authService.changePassword(userId, oldPassword, newPassword)

      return sendSuccess(res, null, '密码修改成功')
```

## 八、认证中间件（预览，下节课详解）

```typescript
// src/middleware/authenticate.ts
import { Request, Response, NextFunction } from 'express'
import { extractToken, verifyAccessToken, TokenPayload } from '../utils/auth'

// 扩展 Express Request 类型
declare global {
  namespace Express {
    interface Request {
      user?: TokenPayload
    }
  }
}

/**
 * 认证中间件
 * 从请求头中提取并验证 JWT Token
 */
export function authenticate(req: Request, res: Response, next: NextFunction) {
  try {
    // 1. 从 Authorization header 提取 Token
    const token = extractToken(req.headers.authorization)

    if (!token) {
      return res.status(401).json({
        success: false,
        message: '未提供认证 Token，请先登录'
      })
    }

    // 2. 验证 Token
    const payload = verifyAccessToken(token)

    // 3. 将用户信息挂载到 req 对象
    req.user = payload

    next()
  } catch (error) {
    if (error instanceof Error) {
      if (error.message === 'ACCESS_TOKEN_EXPIRED') {
        return res.status(401).json({
          success: false,
          message: 'Token 已过期，请刷新或重新登录',
          code: 'TOKEN_EXPIRED'
        })
      }

      if (error.message === 'ACCESS_TOKEN_INVALID') {
        return res.status(401).json({
          success: false,
          message: 'Token 无效，请重新登录'
        })
      }
    }

    return res.status(401).json({
      success: false,
      message: '认证失败'
    })
  }
}

/**
 * 可选认证中间件
 * 有 Token 则验证，没有 Token 也放行
 */
export function optionalAuth(req: Request, res: Response, next: NextFunction) {
  const token = extractToken(req.headers.authorization)

  if (token) {
    try {
      const payload = verifyAccessToken(token)
      req.user = payload
    } catch {
      // Token 无效也放行，只是 req.user 为 undefined
    }
  }

  next()
}
```

## 参考答案

### 练习 1：实现注册接口

**思路**：注册流程的六个步骤必须严格按顺序执行：输入验证 → 唯一性检查 → 密码加密 → 创建用户 → 生成 Token → 返回响应。唯一性检查和密码加密可以并行，但创建用户必须在检查之后。使用 Zod 做验证，bcrypt 加密密码，Prisma 操作数据库。

**答案**：
```typescript
// src/services/auth.service.ts
import { prisma } from '../config/database'
import { hashPassword, generateTokenPair } from '../utils/auth'
import { ConflictError } from '../utils/errors'
import { RegisterInput } from '../validators/auth.validator'

export class AuthService {
  async register(input: RegisterInput) {
    const { email, username, password } = input

    // 1. 检查邮箱唯一性
    const existingEmail = await prisma.user.findUnique({ where: { email } })
    if (existingEmail) {
      throw new ConflictError('该邮箱已被注册')
    }

    // 2. 检查用户名唯一性
    const existingUsername = await prisma.user.findUnique({ where: { username } })
    if (existingUsername) {
      throw new ConflictError('该用户名已被使用')
    }

    // 3. 加密密码
    const hashedPassword = await hashPassword(password)

    // 4. 创建用户
    const user = await prisma.user.create({
      data: { email, username, password: hashedPassword, role: 'USER' }
    })

    // 5. 生成 Token 对
    const tokens = generateTokenPair({
      userId: user.id,
      email: user.email,
      role: user.role
    })

    // 6. 返回安全的用户信息（不含密码）
    const { password: _, ...safeUser } = user
    return { user: safeUser, tokens }
  }
}

// src/controllers/auth.controller.ts
import { Request, Response, NextFunction } from 'express'
import { AuthService } from '../services/auth.service'
import { sendCreated } from '../utils/response'

const authService = new AuthService()

export async function register(req: Request, res: Response, next: NextFunction) {
  try {
    const result = await authService.register(req.body)
    return sendCreated(res, {
      user: result.user,
      accessToken: result.tokens.accessToken,
      refreshToken: result.tokens.refreshToken
    }, '注册成功')
  } catch (error) {
    next(error)
  }
}

// src/routes/auth.routes.ts
import { Router } from 'express'
import { validate } from '../middleware/validate'
import { registerSchema } from '../validators/auth.validator'
import { register } from '../controllers/auth.controller'

const router = Router()
router.post('/register', validate(registerSchema), register)

export default router
```

**要点**：
- 唯一性检查必须在创建用户之前，否则 Prisma 会抛出数据库约束错误（500 而非 409）
- 返回用户信息时必须排除密码字段（`const { password: _, ...safeUser } = user`）
- 使用 `ConflictError`（409）表示资源冲突，而非通用的 400 错误

### 练习 2：实现登录接口

**思路**：登录流程的关键是安全性——无论用户不存在还是密码错误，都返回相同的错误消息"邮箱或密码不正确"，防止攻击者枚举有效邮箱。使用 bcrypt.compare 验证密码，不要用 `===` 直接比较。

**答案**：
```typescript
// src/services/auth.service.ts（续）
import { comparePassword, generateTokenPair } from '../utils/auth'
import { AuthError } from '../utils/errors'
import { LoginInput } from '../validators/auth.validator'

export class AuthService {
  async login(input: LoginInput) {
    const { email, password } = input

    // 1. 查找用户
    const user = await prisma.user.findUnique({ where: { email } })

    // 2. 统一错误消息，不暴露用户是否存在
    if (!user) {
      throw new AuthError('邮箱或密码不正确')
    }

    // 3. 验证密码
    const isPasswordValid = await comparePassword(password, user.password)
    if (!isPasswordValid) {
      throw new AuthError('邮箱或密码不正确')  // 与用户不存在时消息相同
    }

    // 4. 生成 Token
    const tokens = generateTokenPair({
      userId: user.id,
      email: user.email,
      role: user.role
    })

    // 5. 返回用户信息和 Token
    const { password: _, ...safeUser } = user
    return { user: safeUser, tokens }
  }
}

// src/controllers/auth.controller.ts（续）
export async function login(req: Request, res: Response, next: NextFunction) {
  try {
    const result = await authService.login(req.body)
    return sendSuccess(res, {
      user: result.user,
      accessToken: result.tokens.accessToken,
      refreshToken: result.tokens.refreshToken
    }, '登录成功')
  } catch (error) {
    next(error)
  }
}
```

**要点**：
- 用户不存在和密码错误返回完全相同的消息和状态码（401），防止邮箱枚举攻击
- 使用 `bcrypt.compare` 而非 `===` 比较密码，因为数据库中存的是哈希值
- 登录成功后返回 Token 对，前端需要存储 accessToken 和 refreshToken

```bash
  -d '{
    "email": "test@example.com",
    "username": "testuser",
    "password": "TestPassword123",
    "confirmPassword": "TestPassword123"
  }'
# 预期: 201 Created, 返回 user + accessToken + refreshToken

# 2. 登录
curl -X POST http://localhost:3000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "test@example.com",
    "password": "TestPassword123"
  }'
# 预期: 200 OK, 返回 user + accessToken + refreshToken

# 3. 获取当前用户（替换 YOUR_ACCESS_TOKEN 为上一步返回的 accessToken）
curl -X GET http://localhost:3000/api/auth/me \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
# 预期: 200 OK, 返回 user 信息

# 4. 刷新 Token（替换 YOUR_REFRESH_TOKEN 为上一步返回的 refreshToken）
curl -X POST http://localhost:3000/api/auth/refresh \
  -H "Content-Type: application/json" \
  -d '{
    "refreshToken": "YOUR_REFRESH_TOKEN"
  }'
# 预期: 200 OK, 返回新的 accessToken + refreshToken
```

**要点**：
- 每一步都要保存返回的 Token，用于下一步的请求
- 注册和登录返回的 Token 格式相同，前端可以统一处理
- 刷新 Token 后旧的 Refresh Token 应该失效（如果实现了 Token 轮转）

### 练习 4：测试错误场景

**思路**：测试各种边界情况，确保系统返回正确的状态码和安全的错误消息。重点关注：重复注册返回 409、密码错误返回 401 且消息不泄露信息、无效输入返回 422。

**答案**：
```bash
# 1. 重复注册（应返回 409 Conflict）
curl -X POST http://localhost:3000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "email": "test@example.com",
    "username": "testuser",
    "password": "TestPassword123",
    "confirmPassword": "TestPassword123"
  }'
# 预期: 409, "该邮箱已被注册"

# 2. 密码错误（应返回 401 Unauthorized）
curl -X POST http://localhost:3000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "test@example.com",
    "password": "WrongPassword123"
  }'
# 预期: 401, "邮箱或密码不正确"（不说是密码错还是邮箱错）

# 3. 无效邮箱格式（应返回 422 Unprocessable Entity）
curl -X POST http://localhost:3000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "email": "not-an-email",
    "username": "testuser2",
    "password": "TestPassword123",
    "confirmPassword": "TestPassword123"
  }'
# 预期: 422, errors: { email: "邮箱格式不正确" }

# 4. 密码强度不够（应返回 422）
curl -X POST http://localhost:3000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "email": "test2@example.com",
    "username": "testuser2",
    "password": "123",
    "confirmPassword": "123"
  }'
# 预期: 422, errors: { password: "密码长度至少 8 个字符" }

# 5. 无 Token 访问受保护路由（应返回 401）
curl -X GET http://localhost:3000/api/auth/me
# 预期: 401, "未提供认证 Token，请先登录"
```

**要点**：
- 重复注册的 409 和密码错误的 401 必须区分清楚，不能混用
- 登录失败的消息不能区分"邮箱不存在"和"密码错误"，统一返回"邮箱或密码不正确"
- 422 用于输入格式正确但不满足业务规则的场景（如密码太弱）
- 401 用于未认证（无 Token 或 Token 无效），403 用于已认证但无权限

---

## 常见误区

1. **登录失败时区分"邮箱不存在"和"密码错误"**：这看起来是友好的提示，实际上给了攻击者枚举有效邮箱的机会。正确做法是统一返回"邮箱或密码不正确"，让攻击者无法判断哪个字段错了。

2. **注册时不检查密码强度**：允许用户设置 `123456` 作为密码，等于给攻击者开了后门。至少要求 8 位、包含大小写字母和数字，这不需要复杂的正则，Zod 的 `.regex()` 就能搞定。

3. **Controller 层包含业务逻辑**：把密码加密、Token 生成、数据库查询都写在 Controller 里，导致 Controller 文件动辄 200+ 行。Controller 应该只做三件事：接收请求参数、调用 Service、返回响应。

4. **错误响应泄露内部信息**：返回 `"error": "PrismaClientKnownRequestError: Unique constraint failed on the fields: (`email`)"` 这样的错误信息，直接暴露了你用的 ORM 和数据库结构。生产环境必须用自定义错误类包装。

---

## 工程建议

1. **用 Zod 做输入验证**：不要手写 `if (!email)` 这种验证逻辑。Zod 的 Schema 定义即文档，验证失败自动返回友好的错误信息，还能从 Schema 推导 TypeScript 类型。

2. **三层架构（Controller → Service → Routes）**：Controller 处理 HTTP 交互，Service 处理业务逻辑，Routes 定义路由映射。这样每个文件职责单一，便于测试和维护。

3. **统一响应格式**：所有接口返回 `{ success: boolean, message: string, data: any }` 结构。前端不需要猜每个接口的返回格式，统一的错误处理也更简单。

4. **用 curl 写冒烟测试**：每个接口写完后，用 curl 手动测试一遍正常流程和错误流程。这比写测试用例快，但能覆盖 80% 的边界情况。把 curl 命令保存在项目文档中，新人可以直接复制使用。

## 小结

本课我们完成了登录注册的完整实现：

| 模块 | 内容 | 关键技术 |
|------|------|---------|
| **输入验证** | 邮箱、用户名、密码格式验证 | Zod Schema |
| **注册流程** | 验证 → 唯一性检查 → 加密 → 创建 → Token | bcrypt + Prisma + JWT |
| **登录流程** | 查找 → 验证密码 → 生成 Token | bcrypt.compare + JWT |
| **获取用户** | 验证 Token → 查询用户 → 返回信息 | authenticate 中间件 |
| **刷新 Token** | 验证 Refresh Token → 生成新 Token 对 | 双 Token 机制 |
| **错误处理** | 统一格式、安全的错误消息 | AppError + errorHandler |
| **代码架构** | Controller → Service → Routes 三层分离 | 关注点分离 |

关键设计决策：

1. **错误消息安全**：登录失败不暴露用户是否存在
2. **密码强度要求**：至少 8 位，包含大小写和数字
3. **三层架构**：Controller 接收请求，Service 处理逻辑，Routes 定义路由
4. **统一响应格式**：所有接口返回 `{ success, message, data }` 结构
