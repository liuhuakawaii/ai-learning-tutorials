# 第七课：日志与监控

## 场景引入

凌晨三点，你被告警叫醒：线上博客 API 报 500 错误，用户无法登录。你打开服务器，发现一片寂静——没有任何日志。你不知道是数据库挂了、代码抛了异常、还是第三方服务超时了。你只能一行行翻代码猜问题在哪。这就是没有日志系统的代价。在开发阶段，`console.log` 足够应付，但到了生产环境，你需要：按级别过滤日志（error/warn/info）、日志持久化到文件、按日期轮转避免磁盘爆满、每个请求带上唯一 ID 方便追踪、慢请求自动告警。本课将用 Winston + Morgan 构建一套生产级日志系统，并实现简单的健康检查和监控。

## 学习目标

完成本课学习后，你将能够：

1. 理解为什么需要日志系统（调试、审计、安全分析）
2. 使用 Winston 实现结构化日志
3. 配置日志级别、输出格式、传输器
4. 使用 Morgan 记录 HTTP 请求日志
5. 实现日志文件轮转
6. 创建健康检查端点
7. 实现简单的响应时间统计和错误率监控

## 一、为什么需要日志

### 1.1 console.log 的局限性

```typescript
// 开发时我们经常这样做：
app.post('/api/auth/login', (req, res) => {
  console.log('登录请求:', req.body)
  console.log('用户邮箱:', req.body.email)
  // ... 处理登录
  console.log('登录成功')
})
```

```
console.log 的问题：

  ❌ 没有级别（error、warn、info、debug 都混在一起）
  ❌ 没有持久化（服务器重启后日志就没了）
  ❌ 没有格式（不方便搜索和分析）
  ❌ 没有上下文（不知道是哪个请求、哪个用户）
  ❌ 性能差（同步输出，阻塞事件循环）
  ❌ 无法控制输出目标（只能输出到控制台）
```

### 1.2 日志的作用

```
日志的三大用途：

  1. 调试（Debugging）
     程序出错了，日志告诉你发生了什么
     例：Error: 用户 ID 不存在 at line 42

  2. 审计（Auditing）
     记录谁在什么时候做了什么
     例：用户 zhangsan 于 2024-01-01 12:00:00 删除了文章 #123

  3. 安全分析（Security）
     检测异常行为和攻击
     例：IP 192.168.1.100 在 1 分钟内尝试登录失败 50 次
```

### 1.3 日志级别

```
日志级别从低到高：

  error  → 错误，需要立即关注（数据库连接失败、未捕获异常）
  warn   → 警告，可能有问题但不影响运行（磁盘空间不足、请求超时）
  info   → 信息，正常操作记录（服务器启动、用户登录、API 调用）
  http   → HTTP 请求日志（每个请求的详细信息）
  debug  → 调试信息，开发时使用（变量值、函数调用）

级别过滤：
  生产环境：error + warn + info（默认）
  开发环境：error + warn + info + http + debug

  设置级别为 info 时：
    ✅ error 会被记录
    ✅ warn 会被记录
    ✅ info 会被记录
    ❌ http 不会被记录
    ❌ debug 不会被记录
```

## 二、Winston 日志库详解

### 2.1 安装

```bash
npm install winston
npm install winston-daily-rotate-file  # 日志文件轮转
```

### 2.2 基本配置

```typescript
// src/config/logger.ts
import winston from 'winston'

const { combine, timestamp, printf, colorize, json } = winston.format

// 自定义日志格式
const consoleFormat = printf(({ level, message, timestamp, ...meta }) => {
  let metaStr = ''
  if (Object.keys(meta).length > 0) {
    metaStr = '\n' + JSON.stringify(meta, null, 2)
  }
  return `${timestamp} [${level}]: ${message}${metaStr}`
})

// 创建 Logger 实例
export const logger = winston.createLogger({
  // 日志级别
  level: process.env.NODE_ENV === 'production' ? 'info' : 'debug',

  // 默认格式
  format: combine(
    timestamp({ format: 'YYYY-MM-DD HH:mm:ss' }),
    json()
  ),

  // 传输器（输出到哪里）
  transports: [
    // 控制台输出
    new winston.transports.Console({
      format: combine(
        colorize(),
        timestamp({ format: 'YYYY-MM-DD HH:mm:ss' }),
        consoleFormat
      )
    }),

    // 错误日志文件
    new winston.transports.File({
      filename: 'logs/error.log',
      level: 'error',
      maxsize: 5 * 1024 * 1024,  // 5MB
      maxFiles: 5
    }),

    // 所有日志文件
    new winston.transports.File({
      filename: 'logs/combined.log',
      maxsize: 10 * 1024 * 1024,  // 10MB
      maxFiles: 10
    })
  ]
})
```

### 2.3 使用 Logger

### 2.4 日志文件轮转

```typescript
// src/config/logger.ts（带轮转版本）
import winston from 'winston'
import DailyRotateFile from 'winston-daily-rotate-file'

const { combine, timestamp, printf, colorize, json } = winston.format

const consoleFormat = printf(({ level, message, timestamp, ...meta }) => {
  let metaStr = ''
  if (Object.keys(meta).length > 0) {
    metaStr = '\n' + JSON.stringify(meta, null, 2)
  }
  return `${timestamp} [${level}]: ${message}${metaStr}`
})

// 错误日志轮转
const errorRotateTransport = new DailyRotateFile({
  filename: 'logs/error-%DATE%.log',
  datePattern: 'YYYY-MM-DD',
  level: 'error',
  maxSize: '20m',      // 单个文件最大 20MB
  maxFiles: '14d',      // 保留 14 天
  zippedArchive: true   // 压缩旧日志
})

// 所有日志轮转
const combinedRotateTransport = new DailyRotateFile({
  filename: 'logs/combined-%DATE%.log',
  datePattern: 'YYYY-MM-DD',
  maxSize: '50m',
  maxFiles: '30d',
  zippedArchive: true
})

// 监听轮转事件
errorRotateTransport.on('rotate', (oldFilename, newFilename) => {
  console.log(`日志轮转: ${oldFilename} → ${newFilename}`)
})

export const logger = winston.createLogger({
  level: process.env.NODE_ENV === 'production' ? 'info' : 'debug',
  format: combine(
    timestamp({ format: 'YYYY-MM-DD HH:mm:ss' }),
    json()
  ),
  transports: [
    new winston.transports.Console({
      format: combine(
        colorize(),
        timestamp({ format: 'YYYY-MM-DD HH:mm:ss' }),
        consoleFormat
      )
    }),
    errorRotateTransport,
    combinedRotateTransport
  ]
})
```


### 3.2 基本配置

```typescript
// src/middleware/requestLogger.ts
import morgan from 'morgan'
import { logger } from '../config/logger'

// 自定义 Morgan 流，将日志输出到 Winston
const stream = {
  write: (message: string) => {
    logger.http(message.trim())
  }
}

// 自定义日志格式
const format = ':method :url :status :res[content-length] - :response-time ms'

// 开发环境：带颜色的简洁格式
export const devLogger = morgan('dev')

// 生产环境：详细格式，输出到文件
export const prodLogger = morgan(format, { stream })

// 自定义格式：包含更多信息
export const detailedLogger = morgan(
  (tokens, req, res) => {
    return JSON.stringify({
      method: tokens.method(req, res),
      url: tokens.url(req, res),
      status: tokens.status(req, res),
      contentLength: tokens.res(req, res, 'content-length'),
      responseTime: tokens['response-time'](req, res) + 'ms',
      userAgent: tokens['user-agent'](req, res),
      ip: req.ip,
      userId: (req as any).user?.userId || null
    })
  },
  { stream }
)
```

### 3.3 在 app.ts 中使用

```typescript
// src/app.ts
import { devLogger, prodLogger } from './middleware/requestLogger'

// 根据环境选择日志格式
if (process.env.NODE_ENV === 'production') {
  app.use(prodLogger)
} else {
  app.use(devLogger)
}
```

## 四、结构化日志

### 4.1 什么是结构化日志

```
非结构化日志（难以分析）：
  "2024-01-01 12:00:00 INFO: 用户 zhangsan 登录成功"

结构化日志（JSON 格式，方便搜索和分析）：
  {
    "timestamp": "2024-01-01T12:00:00.000Z",
    "level": "info",
    "message": "用户登录成功",
    "userId": 1,
    "email": "zhangsan@example.com",
    "ip": "192.168.1.100",
    "userAgent": "Mozilla/5.0...",
    "requestId": "abc-123"
  }

优势：
  ✅ 可以按字段搜索（userId=1）
  ✅ 可以聚合统计（每小时登录次数）
  ✅ 可以导入 ELK Stack 等日志系统
  ✅ 可以设置告警（error 级别超过阈值）
```

### 4.2 请求 ID 中间件

```typescript
// src/middleware/requestId.ts
import { Request, Response, NextFunction } from 'express'
import crypto from 'crypto'

declare global {
  namespace Express {
    interface Request {
      requestId?: string
    }
  }
}

/**
 * 为每个请求生成唯一 ID
 * 用于日志追踪，方便关联同一个请求的所有日志
 */
export function requestId(req: Request, res: Response, next: NextFunction) {
  // 优先使用客户端传来的 X-Request-ID
  const id = (req.headers['x-request-id'] as string) || crypto.randomUUID()

  req.requestId = id
  res.setHeader('X-Request-ID', id)

  next()
}
```

### 4.3 封装日志工具

```typescript
// src/utils/logger.ts
import { logger } from '../config/logger'
import { Request } from 'express'

/**
 * 创建带请求上下文的 Logger
 */
export function createRequestLogger(req: Request) {
  return {
    error: (message: string, meta: Record<string, any> = {}) => {
      logger.error(message, {
        requestId: req.requestId,
        method: req.method,
        url: req.originalUrl,
        userId: req.user?.userId,
        ...meta
      })
    },
    warn: (message: string, meta: Record<string, any> = {}) => {
      logger.warn(message, {
        requestId: req.requestId,
        method: req.method,
        url: req.originalUrl,
        userId: req.user?.userId,
        ...meta
      })
    },
    info: (message: string, meta: Record<string, any> = {}) => {
      logger.info(message, {
        requestId: req.requestId,
        method: req.method,
        url: req.originalUrl,
        userId: req.user?.userId,
        ...meta
      })
    },
    debug: (message: string, meta: Record<string, any> = {}) => {
      logger.debug(message, {
        requestId: req.requestId,
        method: req.method,
        url: req.originalUrl,
        userId: req.user?.userId,
        ...meta
      })
    }
  }
}
```

## 五、错误日志与堆栈追踪

### 5.1 错误处理中间件增强

```typescript
// src/middleware/errorHandler.ts
import { Request, Response, NextFunction } from 'express'
import { AppError, ValidationError } from '../utils/errors'
import { logger } from '../config/logger'

export function errorHandler(err: Error, req: Request, res: Response, next: NextFunction) {
  // 记录错误日志
  const errorLog = {
    message: err.message,
    stack: err.stack,
    method: req.method,
    url: req.originalUrl,
    ip: req.ip,
    userId: req.user?.userId,
    requestId: req.requestId,
    body: req.body,
    query: req.query,
    params: req.params
  }

  // 已知的业务错误用 warn 级别
  if (err instanceof AppError) {
    logger.warn('业务错误', errorLog)

    if (err instanceof ValidationError) {
      return res.status(err.statusCode).json({
        success: false,
        message: err.message,
        errors: err.errors
      })
    }

    return res.status(err.statusCode).json({
      success: false,
      message: err.message
    })
  }

  // 未知错误用 error 级别，包含完整堆栈
  logger.error('未预期的错误', errorLog)

  // 生产环境不暴露错误细节
  return res.status(500).json({
    success: false,
    message: process.env.NODE_ENV === 'production'
      ? '服务器内部错误'
      : err.message
  })
}
```

```typescript
// src/server.ts
import { logger } from './config/logger'
import app from './app'
import { prisma } from './config/database'

async function main() {
  try {
    await prisma.$connect()
    logger.info('数据库连接成功')

    app.listen(env.PORT, () => {
      logger.info(`服务器已启动`, { port: env.PORT, env: env.NODE_ENV })
    })

    logger.error('服务器启动失败', { error })
    process.exit(1)

process.on('unhandledRejection', (reason: any, promise: Promise<any>) => {
  logger.error('未处理的 Promise 拒绝', {
    reason: reason?.message || reason,
    stack: reason?.stack
  })
})

// 未捕获的同步异常
process.on('uncaughtException', (error: Error) => {
  logger.error('未捕获的异常', {
    message: error.message,
    stack: error.stack
  })
  // 优雅关闭
  process.exit(1)
})

// 优雅关闭
process.on('SIGINT', async () => {
  logger.info('收到 SIGINT 信号，正在优雅关闭...')
  await prisma.$disconnect()
  process.exit(0)
})

process.on('SIGTERM', async () => {
  logger.info('收到 SIGTERM 信号，正在优雅关闭...')
  await prisma.$disconnect()
  process.exit(0)
})

main()
```

```typescript
})

 *         description: 服务未就绪

  try {
    await prisma.$queryRaw`SELECT 1`
    res.json({ status: 'ready' })
  } catch {
    res.status(503).json({ status: 'not ready' })
  }
})

/**
 * @swagger
```

## 七、简单监控

### 7.1 响应时间统计中间件

```typescript
// src/middleware/metrics.ts
import { Request, Response, NextFunction } from 'express'
import { logger } from '../config/logger'

// 简单的指标收集器
class MetricsCollector {
  private requestCount = 0
  private errorCount = 0
  private responseTimes: number[] = []
  private statusCodes: Record<string, number> = {}
  private endpoints: Record<string, { count: number; totalTime: number }> = {}

  recordRequest(duration: number, statusCode: number, endpoint: string) {
    this.requestCount++
    this.responseTimes.push(duration)

    // 状态码统计
    const statusGroup = `${Math.floor(statusCode / 100)}xx`
    this.statusCodes[statusGroup] = (this.statusCodes[statusGroup] || 0) + 1

    if (statusCode >= 400) {
      this.errorCount++
    }

    // 端点统计
    if (!this.endpoints[endpoint]) {
      this.endpoints[endpoint] = { count: 0, totalTime: 0 }
    }
    this.endpoints[endpoint].count++
    this.endpoints[endpoint].totalTime += duration
  }

  getStats() {
    const sortedTimes = [...this.responseTimes].sort((a, b) => a - b)
    const len = sortedTimes.length

    return {
      requests: {
        total: this.requestCount,
        errors: this.errorCount,
        errorRate: this.requestCount > 0
          ? ((this.errorCount / this.requestCount) * 100).toFixed(2) + '%'
          : '0%'
      },
      responseTime: {
        avg: len > 0 ? (sortedTimes.reduce((a, b) => a + b, 0) / len).toFixed(2) + 'ms' : '0ms',
        p50: len > 0 ? sortedTimes[Math.floor(len * 0.5)].toFixed(2) + 'ms' : '0ms',
        p95: len > 0 ? sortedTimes[Math.floor(len * 0.95)].toFixed(2) + 'ms' : '0ms',
        p99: len > 0 ? sortedTimes[Math.floor(len * 0.99)].toFixed(2) + 'ms' : '0ms',
        max: len > 0 ? sortedTimes[len - 1].toFixed(2) + 'ms' : '0ms'
      },
      statusCodes: this.statusCodes,
      topEndpoints: Object.entries(this.endpoints)
        .sort((a, b) => b[1].count - a[1].count)
        .slice(0, 10)
        .map(([endpoint, data]) => ({
          endpoint,
          count: data.count,
          avgTime: (data.totalTime / data.count).toFixed(2) + 'ms'
        }))
    }
  }

  reset() {
    this.requestCount = 0
    this.errorCount = 0
    this.responseTimes = []
    this.statusCodes = {}
    this.endpoints = {}
  }
}

export const metrics = new MetricsCollector()

/**
 * 响应时间统计中间件
 */
export function responseTimeMiddleware(req: Request, res: Response, next: NextFunction) {
  const start = Date.now()

  // 响应结束时记录
  res.on('finish', () => {
    const duration = Date.now() - start
    const endpoint = `${req.method} ${req.route?.path || req.path}`

    metrics.recordRequest(duration, res.statusCode, endpoint)

    // 慢请求警告（超过 1 秒）
    if (duration > 1000) {
      logger.warn('慢请求检测', {
        method: req.method,
        url: req.originalUrl,
        duration: duration + 'ms',
        statusCode: res.statusCode
      })
    }
  })

  next()
}
```

## 参考答案

### 练习 1：配置 Winston Logger

**思路**：使用 Winston 创建一个分级日志系统，通过 `combine` 组合多种格式化器（颜色、时间戳、JSON），使用 `DailyRotateFile` 实现日志轮转，根据 `NODE_ENV` 环境变量切换日志级别。

**答案**：
```typescript
// src/config/logger.ts
import winston from 'winston'
import DailyRotateFile from 'winston-daily-rotate-file'
import path from 'path'

const { combine, timestamp, printf, colorize, json, errors } = winston.format

// 日志级别定义
const LOG_LEVELS = {
  error: 0,
  warn: 1,
  info: 2,
  http: 3,
  debug: 4
}

// 日志颜色（开发环境用）
const LOG_COLORS = {
  error: 'red',
  warn: 'yellow',
  info: 'green',
  http: 'magenta',
  debug: 'cyan'
}

winston.addColors(LOG_COLORS)

// 控制台格式（开发环境）
const consoleFormat = combine(
  colorize({ all: true }),
  timestamp({ format: 'YYYY-MM-DD HH:mm:ss.SSS' }),
  printf(({ level, message, timestamp, requestId, ...meta }) => {
    const reqIdStr = requestId ? `[${requestId}] ` : ''
    const metaStr = Object.keys(meta).length > 0
      ? '\n' + JSON.stringify(meta, null, 2)
      : ''
    return `${timestamp} ${level}: ${reqIdStr}${message}${metaStr}`
  })
)

// 文件格式（生产环境，JSON 结构化）
const fileFormat = combine(
  errors({ stack: true }),
  timestamp({ format: 'YYYY-MM-DD HH:mm:ss.SSS' }),
  json()
)

// 错误日志文件轮转
const errorRotateTransport = new DailyRotateFile({
  filename: path.join('logs', 'error-%DATE%.log'),
  datePattern: 'YYYY-MM-DD',
  level: 'error',
  maxSize: '20m',
  maxFiles: '14d',
  zippedArchive: true
})

// 所有日志文件轮转
const combinedRotateTransport = new DailyRotateFile({
  filename: path.join('logs', 'combined-%DATE%.log'),
  datePattern: 'YYYY-MM-DD',
  maxSize: '50m',
  maxFiles: '30d',
  zippedArchive: true
})

// 创建 Logger 实例
const isProduction = process.env.NODE_ENV === 'production'

export const logger = winston.createLogger({
  level: isProduction ? 'info' : 'debug',
  levels: LOG_LEVELS,
  format: fileFormat,
  defaultMeta: { service: 'blog-api' },
  transports: [
    // 生产环境写文件
    ...(isProduction ? [errorRotateTransport, combinedRotateTransport] : []),
    // 开发环境输出到控制台
    ...(!isProduction ? [
      new winston.transports.Console({ format: consoleFormat })
    ] : [])
  ]
})

// 生产环境也输出到控制台（方便容器日志收集）
if (isProduction) {
  logger.add(new winston.transports.Console({
    format: fileFormat
  }))
}
```

**要点**：
- 开发环境用彩色控制台输出，方便阅读；生产环境用 JSON 格式，方便导入 ELK 等日志系统
- `DailyRotateFile` 按日期分割日志文件，`maxFiles: '14d'` 自动清理 14 天前的日志
- 错误日志单独存储（`error-%DATE%.log`），方便快速定位问题
- 生产环境日志级别设为 `info`，避免 `debug` 日志淹没真正重要的信息

### 练习 2：实现请求日志中间件

**思路**：在 `res.on('finish')` 回调中记录请求完成时的信息，计算响应时间，对慢请求（>1秒）使用 `warn` 级别记录，正常请求用 `info` 级别。

**答案**：
```typescript
// src/middleware/requestLogger.ts
import { Request, Response, NextFunction } from 'express'
import { logger } from '../config/logger'

export function requestLogger(req: Request, res: Response, next: NextFunction) {
  const start = Date.now()

  res.on('finish', () => {
    const duration = Date.now() - start
    const logData = {
      method: req.method,
      url: req.originalUrl,
      statusCode: res.statusCode,
      duration: `${duration}ms`,
      userId: req.user?.userId,
      ip: req.ip,
      userAgent: req.get('user-agent'),
      requestId: req.requestId
    }

    if (duration > 1000) {
      // 超过 1 秒的请求用 warn 级别
      logger.warn('慢请求检测', logData)
    } else if (res.statusCode >= 500) {
      // 服务器错误用 error 级别
      logger.error('服务器错误', logData)
    } else if (res.statusCode >= 400) {
      // 客户端错误用 warn 级别
      logger.warn('客户端错误', logData)
    } else {
      // 正常请求用 info 级别
      logger.info('请求完成', logData)
    }
  })

  next()
}

// Express Request 类型扩展
declare global {
  namespace Express {
    interface Request {
      requestId?: string
      user?: {
        userId: string
        email: string
        role: string
      }
    }
  }
}
```

**要点**：
- 使用 `res.on('finish')` 而不是在 `next()` 之前记录，这样才能拿到状态码和响应时间
- 慢请求阈值设为 1 秒是业界常见做法，超过此值通常意味着有性能问题
- 记录 `requestId` 可以将日志串联起来，方便排查单个请求的完整链路
- 记录 `userId` 便于追踪用户行为，但注意不要记录敏感信息（密码、Token）

### 练习 3：为登录接口添加日志

**思路**：在登录流程的关键节点添加日志：登录尝试（记录 email 和 IP）、登录成功（记录 userId）、登录失败（记录原因）。同时实现登录失败次数统计，超过阈值时触发安全告警。

**答案**：
```typescript
// src/controllers/auth.controller.ts
import { Request, Response, NextFunction } from 'express'
import { createRequestLogger } from '../utils/logger'
import { logger } from '../config/logger'
import { authService } from '../services/auth.service'
import { sendSuccess } from '../utils/response'

// 简单的登录失败次数记录（生产环境建议用 Redis）
const loginAttempts = new Map<string, { count: number; lastAttempt: number }>()
const MAX_ATTEMPTS = 5
const LOCKOUT_DURATION = 15 * 60 * 1000 // 15 分钟

function getAttemptKey(email: string, ip: string) {
  return `${email}:${ip}`
}

function checkRateLimit(email: string, ip: string): boolean {
  const key = getAttemptKey(email, ip)
  const attempt = loginAttempts.get(key)

  if (!attempt) return true

  // 锁定时间已过，重置计数
  if (Date.now() - attempt.lastAttempt > LOCKOUT_DURATION) {
    loginAttempts.delete(key)
    return true
  }

  return attempt.count < MAX_ATTEMPTS
}

function recordAttempt(email: string, ip: string) {
  const key = getAttemptKey(email, ip)
  const attempt = loginAttempts.get(key)

  if (attempt) {
    attempt.count++
    attempt.lastAttempt = Date.now()
  } else {
    loginAttempts.set(key, { count: 1, lastAttempt: Date.now() })
  }
}

function clearAttempts(email: string, ip: string) {
  loginAttempts.delete(getAttemptKey(email, ip))
}

export class AuthController {
  async login(req: Request, res: Response, next: NextFunction) {
    const reqLogger = createRequestLogger(req)
    const { email } = req.body
    const ip = req.ip || 'unknown'

    try {
      // 检查是否被锁定
      if (!checkRateLimit(email, ip)) {
        reqLogger.warn('登录失败次数过多，账号已临时锁定', {
          email,
          ip,
          maxAttempts: MAX_ATTEMPTS,
          lockoutDuration: `${LOCKOUT_DURATION / 60000}分钟`
        })

        // 安全告警
        logger.warn('安全告警：登录失败次数过多', {
          email,
          ip,
          userAgent: req.get('user-agent'),
          type: 'SECURITY_ALERT'
        })

        return res.status(429).json({
          success: false,
          message: `登录失败次数过多，请 ${LOCKOUT_DURATION / 60000} 分钟后再试`
        })
      }

      // 记录登录尝试
      reqLogger.info('登录尝试', { email, ip })

      const result = await authService.login(req.body)

      // 登录成功
      reqLogger.info('登录成功', {
        userId: result.user.id,
        email: result.user.email,
        ip
      })

      // 清除失败计数
      clearAttempts(email, ip)

      return sendSuccess(res, {
        user: result.user,
        accessToken: result.tokens.accessToken,
        refreshToken: result.tokens.refreshToken
      }, '登录成功')
    } catch (error) {
      // 记录失败尝试
      recordAttempt(email, ip)

      const attempt = loginAttempts.get(getAttemptKey(email, ip))
      const remainingAttempts = MAX_ATTEMPTS - (attempt?.count || 0)

      reqLogger.warn('登录失败', {
        email,
        ip,
        reason: error instanceof Error ? error.message : '未知错误',
        remainingAttempts
      })

      // 接近锁定阈值时发出告警
      if (remainingAttempts <= 2 && remainingAttempts > 0) {
        logger.warn('安全告警：登录失败次数接近阈值', {
          email,
          ip,
          remainingAttempts,
          type: 'SECURITY_WARNING'
        })
      }

      next(error)
    }
  }
}
```

**要点**：
- 登录尝试必须记录 email 和 IP，用于追踪暴力破解攻击
- 失败次数统计是安全关键功能，生产环境建议用 Redis 替代内存 Map（进程重启会丢失计数）
- 接近锁定阈值时提前告警，让运维人员有时间响应
- 登录失败的具体原因（密码错误、用户不存在）对外统一返回"邮箱或密码不正确"，防止枚举攻击

## 常见误区

1. **生产环境还在用 `console.log`**：`console.log` 没有级别区分、没有持久化、没有格式化、没有上下文。生产环境出问题时，你翻遍控制台也找不到有用的信息。必须用 Winston 等专业日志库。

2. **日志中打印敏感信息**：在日志中输出 `console.log('用户密码:', password)` 或 `console.log('Token:', token)`，一旦日志文件泄露，用户数据就全暴露了。日志必须脱敏处理。

3. **所有日志都用同一个级别**：把正常请求、业务警告、系统错误全部用 `info` 级别输出，导致日志中 99% 是噪音，真正的错误被淹没。应该严格区分 error/warn/info/debug 级别。

4. **日志文件不轮转**：日志文件无限增长，一个月后磁盘满了，服务器直接宕机。必须配置日志轮转（按日期或大小），自动清理旧日志。

## 工程建议

1. **为每个请求生成唯一 ID**：用 `crypto.randomUUID()` 生成 `X-Request-ID`，贯穿整个请求链路（中间件 → Controller → Service → 错误处理）。出问题时用一个 ID 就能查到该请求的所有日志。

2. **慢请求自动告警**：在响应时间中间件中设置阈值（如 1 秒），超过阈值用 `warn` 级别记录。这样你不需要翻所有日志，只看 warn 就能发现性能问题。

3. **健康检查端点是必须的**：`GET /health` 返回服务状态（包括数据库连接、内存使用、运行时间）。配合 Kubernetes 或负载均衡器，可以自动摘除不健康的节点。

4. **开发和生产用不同的日志格式**：开发环境用彩色、简洁的控制台格式；生产环境用 JSON 格式（方便导入 ELK Stack 等日志系统）。用 `NODE_ENV` 环境变量切换。
