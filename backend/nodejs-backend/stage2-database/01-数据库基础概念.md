# 数据库基础概念

你的博客 API 用数组存数据，重启就没了。你试过写 JSON 文件，但两个请求同时写的时候文件会坏掉。搜一篇特定文章，得遍历整个数组。这些都不是靠"优化代码"能解决的——你需要数据库。

## 数据库解决了什么问题

把你的博客 API 换成数据库，能解决三个具体问题：

1. **持久化**：服务器重启，数据不会丢
2. **并发安全**：多个请求同时读写，不会互相覆盖
3. **高效查询**：10 万篇文章里找一篇，不需要遍历

数据库不是什么神秘的东西，它就是一个专门用来存数据、查数据的程序。你告诉它"我要什么"，它帮你找出来。

## 关系型 vs 非关系型

市面上数据库分两大类，区别在于数据的组织方式：

```
关系型（PostgreSQL, MySQL, SQLite）
  数据存在"表"里，表之间可以建立关系
  用 SQL 语言操作
  适合：结构化数据、需要事务保证的场景

非关系型（MongoDB, Redis, DynamoDB）
  数据存法灵活（文档、键值、图...）
  操作方式各不相同
  适合：数据结构不固定、需要极高读写性能的场景
```

对于博客这类业务——用户、文章、评论之间有明确的关系——关系型数据库是更自然的选择。一个用户有多篇文章，一篇文章有多条评论，这种"一对多"关系用关系型数据库表达最直接。

## 表、行、列

关系型数据库的核心结构：

```
users 表
┌────┬────────┬─────────────────────┬─────────────────────┐
│ id │ name   │ email               │ created_at          │
├────┼────────┼─────────────────────┼─────────────────────┤
│ 1  │ 张三   │ zhangsan@example.com│ 2024-01-15 10:30:00 │
│ 2  │ 李四   │ lisi@example.com    │ 2024-02-20 14:00:00 │
│ 3  │ 王五   │ wangwu@example.com  │ 2024-03-10 09:15:00 │
└────┴────────┴─────────────────────┴─────────────────────┘

  表（Table）= 一类数据的集合，比如"所有用户"
  行（Row）  = 一条具体的记录，比如"张三这个用户"
  列（Column）= 记录的某个属性，比如"邮箱"
```

每张表有一个**主键**（Primary Key），通常是 `id` 列，用来唯一标识每一行。就像身份证号——通过它能找到唯一一个人。

## 表之间的关系

博客系统有三张表，它们之间的关系：

```
users (用户表)
  │
  │ 1 : N (一个用户有多篇文章)
  ▼
posts (文章表)
  │
  │ 1 : N (一篇文章有多条评论)
  ▼
comments (评论表)
```

关系通过**外键**（Foreign Key）实现。`posts` 表里有一个 `author_id` 列，存的是 `users` 表的 `id`：

```
posts 表
┌────┬──────────┬───────────┬─────────────────────┐
│ id │ title    │ author_id │ created_at          │
├────┼──────────┼───────────┼─────────────────────┤
│ 1  │ 第一篇   │ 1         │ 2024-03-01 10:00:00 │
│ 2  │ 第二篇   │ 1         │ 2024-03-05 16:30:00 │
│ 3  │ 学习笔记 │ 2         │ 2024-03-10 09:00:00 │
└────┴──────────┴───────────┴─────────────────────┘
  author_id = 1 → 指向 users 表的 id=1（张三）
```

这样就能做关联查询：给定一篇文章，查出它的作者是谁；给定一个用户，查出他写的所有文章。

## SQL：和数据库对话的语言

SQL 就是你发给数据库的指令。增删改查四种操作：

```sql
-- 查：找所有已发布的文章
SELECT id, title, author_id FROM posts WHERE status = 'published';

-- 增：插入一条新用户
INSERT INTO users (name, email) VALUES ('赵六', 'zhaoliu@example.com');

-- 改：修改文章标题
UPDATE posts SET title = '新标题' WHERE id = 1;

-- 删：删除一条评论
DELETE FROM comments WHERE id = 5;
```

SQL 语法接近英语，读起来像在说一句话。这些操作在下一课会详细练。

## 为什么不直接用 JSON 文件

你可能会想：我用 `fs.readFile` + `JSON.parse` 也能持久化啊？问题在于：

```
JSON 文件方案的问题：

  并发写入 → 两个请求同时 writeFile，后写的覆盖先写的
  查询效率 → 找一篇文章，得读整个文件再遍历
  数据量   → 文件大了，每次读写都慢
  关联查询 → 查"张三的所有文章的评论"，得手动拼三次遍历
  数据完整性 → 写到一半断电，文件可能损坏
```

数据库专门处理这些问题。它的内部有锁机制、索引、事务日志、查询优化器——这些不是你在应用层自己写能轻松搞定的。

## 动手体验

装好 PostgreSQL（下一课会详细讲安装），试试直接和数据库对话：

```bash
# 连接到数据库
psql -U postgres

# 创建博客数据库
CREATE DATABASE blog_db;

# 切换到博客数据库
\c blog_db

# 创建 users 表
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(255) UNIQUE NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

# 插入数据
INSERT INTO users (name, email) VALUES ('张三', 'zhangsan@example.com');
INSERT INTO users (name, email) VALUES ('李四', 'lisi@example.com');

# 查询
SELECT * FROM users;
SELECT * FROM users WHERE name = '张三';
```

你会看到数据被存下来了。关掉终端再连进去，数据还在。这就是数据库的基本价值。

## 练习

### 练习一：设计 posts 表

在 `blog_db` 里创建 `posts` 表，要求：
- `id`：自增主键
- `title`：不能为空
- `content`：文本类型
- `status`：只能是 'draft' 或 'published'
- `author_id`：外键，关联 users 表
- `created_at`：默认当前时间

### 练习二：用 SQL 完成以下操作

假设表里已有数据：
1. 插入两篇文章，分别属于不同的作者
2. 查询张三写的所有文章
3. 把第一篇文章的状态改为 'published'
4. 统计每个作者写了多少篇文章

### 练习三：思考 comments 表

自己设计 `comments` 表的结构，并写出"查询某篇文章的所有评论"的 SQL。

## 参考答案

### 练习一

```sql
CREATE TABLE posts (
  id SERIAL PRIMARY KEY,
  title VARCHAR(255) NOT NULL,
  content TEXT,
  status VARCHAR(20) CHECK (status IN ('draft', 'published')) DEFAULT 'draft',
  author_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

`REFERENCES users(id)` 就是外键约束——`author_id` 的值必须在 `users` 表里存在。`ON DELETE CASCADE` 表示如果用户被删，他写的文章也自动删除。

### 练习二

```sql
-- 插入文章
INSERT INTO posts (title, content, author_id, status) VALUES
  ('第一篇', '内容一', 1, 'draft'),
  ('学习笔记', '今天学了 SQL', 2, 'published');

-- 张三的文章
SELECT * FROM posts WHERE author_id = (SELECT id FROM users WHERE name = '张三');

-- 修改状态
UPDATE posts SET status = 'published' WHERE id = 1;

-- 统计每个作者的文章数
SELECT author_id, COUNT(*) as post_count FROM posts GROUP BY author_id;
```

### 练习三

```sql
CREATE TABLE comments (
  id SERIAL PRIMARY KEY,
  post_id INTEGER REFERENCES posts(id) ON DELETE CASCADE,
  author_id INTEGER REFERENCES users(id),
  content TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 查询某篇文章的评论
SELECT * FROM comments WHERE post_id = 1 ORDER BY created_at;
```
