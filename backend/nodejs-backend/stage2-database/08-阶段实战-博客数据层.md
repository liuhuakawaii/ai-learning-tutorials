# 阶段实战：博客数据层

上个阶段你用内存数组做了博客 API。现在学了数据库和 Prisma，是时候把数组换成真正的数据库了。

这节课的目标：用 Prisma + PostgreSQL 替换掉所有内存数据操作，同时引入 Repository 模式，让数据访问逻辑和路由逻辑分离。

## 为什么要分层

上个阶段的代码里，路由函数直接操作 `store.posts.push(...)`。这在小项目里能用，但随着业务变复杂，问题会暴露：

- 路由函数又长又杂，既要处理 HTTP 又要操作数据
- 换数据库（比如从内存换成 PostgreSQL）得改每个路由
- 单元测试没法单独测数据操作

分层后：

```
路由层（routes）    → 只管 HTTP 请求和响应
服务层（services）  → 处理业务逻辑
数据层（repositories）→ 只管数据库操作
```

## 初始化 Prisma

在上个阶段的 blog-api 项目基础上操作：

```bash
npm install prisma @prisma/client
npx prisma init
```

这会创建 `prisma/schema.prisma` 文件。

## 定义 Schema

把你的博客数据模型写成 Prisma Schema：

```prisma
// prisma/schema.prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model User {
  id        Int       @id @default(autoincrement())
  name      String    @db.VarChar(100)
  email     String    @unique @db.VarChar(255)
  createdAt DateTime  @default(now()) @map("created_at")
  posts     Post[]
  comments  Comment[]

  @@map("users")
}

model Post {
  id        Int       @id @default(autoincrement())
  title     String    @db.VarChar(255)
  content   String?
  status    String    @default("draft") @db.VarChar(20)
  authorId  Int       @map("author_id")
  createdAt DateTime  @default(now()) @map("created_at")
  author    User      @relation(fields: [authorId], references: [id], onDelete: Cascade)
  comments  Comment[]

  @@map("posts")
}

model Comment {
  id        Int      @id @default(autoincrement())
  postId    Int      @map("post_id")
  authorId  Int      @map("author_id")
  content   String
  createdAt DateTime @default(now()) @map("created_at")
  post      Post     @relation(fields: [postId], references: [id], onDelete: Cascade)
  author    User     @relation(fields: [authorId], references: [id])

  @@map("comments")
}
```

`@map("users")` 让 Prisma 用蛇形命名存数据库表，但代码里用驼峰 `user.createdAt` 访问。这样数据库规范和 TypeScript 风格都能兼顾。

创建数据库并执行迁移：

```bash
createdb blog_db
npx prisma migrate dev --name init
```

## Prisma Client 单例

开发环境下 Next.js / nodemon 会热重载，每次都 `new PrismaClient()` 会撑爆数据库连接数。用一个单例文件解决：

```js
// src/lib/prisma.js
const { PrismaClient } = require('@prisma/client')

let prisma

if (!global.__prisma) {
  global.__prisma = new PrismaClient()
}

prisma = global.__prisma

module.exports = prisma
```

整个项目里都从这个文件引入 `prisma`。

## Repository 层

Repository 的职责是：封装所有数据库操作，对外暴露简洁的方法。

```js
// src/repositories/userRepository.js
const prisma = require('../lib/prisma')

const userRepository = {
  async findAll() {
    return prisma.user.findMany({ orderBy: { createdAt: 'desc' } })
  },

  async findById(id) {
    return prisma.user.findUnique({ where: { id } })
  },

  async findByEmail(email) {
    return prisma.user.findUnique({ where: { email } })
  },

  async create(data) {
    return prisma.user.create({ data })
  },

  async update(id, data) {
    return prisma.user.update({ where: { id }, data })
  },

  async delete(id) {
    return prisma.user.delete({ where: { id } })
  },
}

module.exports = userRepository
```

Post Repository 稍微复杂一点，因为需要关联查询：

```js
// src/repositories/postRepository.js
const prisma = require('../lib/prisma')

const postRepository = {
  async findAll(filters = {}) {
    const where = {}
    if (filters.status) where.status = filters.status
    if (filters.authorId) where.authorId = filters.authorId

    return prisma.post.findMany({
      where,
      include: {
        author: { select: { id: true, name: true, email: true } },
        _count: { select: { comments: true } },
      },
      orderBy: { createdAt: 'desc' },
    })
  },

  async findById(id) {
    return prisma.post.findUnique({
      where: { id },
      include: {
        author: { select: { id: true, name: true, email: true } },
        comments: {
          include: { author: { select: { id: true, name: true } } },
          orderBy: { createdAt: 'desc' },
        },
      },
    })
  },

  async create(data) {
    return prisma.post.create({
      data,
      include: { author: { select: { id: true, name: true, email: true } } },
    })
  },

  async update(id, data) {
    return prisma.post.update({ where: { id }, data })
  },

  async delete(id) {
    return prisma.post.delete({ where: { id } })
  },
}

module.exports = postRepository
```

## 路由层改造

路由函数不再直接操作数组，改为调用 Repository：

```js
// src/routes/posts.js
const { Router } = require('express')
const { z } = require('zod')
const postRepository = require('../repositories/postRepository')
const validate = require('../middleware/validate')

const router = Router()

const createPostSchema = z.object({
  title: z.string().min(1),
  content: z.string().optional(),
  authorId: z.number().int().positive(),
  status: z.enum(['draft', 'published']).default('draft'),
})

router.get('/', async (req, res, next) => {
  try {
    const posts = await postRepository.findAll({
      status: req.query.status,
      authorId: req.query.authorId ? Number(req.query.authorId) : undefined,
    })
    res.json({ success: true, data: posts })
  } catch (err) {
    next(err)
  }
})

router.get('/:id', async (req, res, next) => {
  try {
    const post = await postRepository.findById(Number(req.params.id))
    if (!post) {
      const err = new Error('文章不存在')
      err.statusCode = 404
      return next(err)
    }
    res.json({ success: true, data: post })
  } catch (err) {
    next(err)
  }
})

router.post('/', validate(createPostSchema), async (req, res, next) => {
  try {
    const post = await postRepository.create(req.body)
    res.status(201).json({ success: true, data: post })
  } catch (err) {
    next(err)
  }
})

module.exports = router
```

注意每个路由都有 `try/catch` + `next(err)`。Prisma 抛出的异常会被全局错误处理中间件捕获。

## Prisma 错误处理

Prisma 抛出的错误有特定类型，可以在全局错误处理里区分：

```js
const { Prisma } = require('@prisma/client')

function errorHandler(err, req, res, next) {
  // Prisma 唯一约束冲突（比如 email 重复）
  if (err instanceof Prisma.PrismaClientKnownRequestError) {
    if (err.code === 'P2002') {
      return res.status(409).json({
        success: false,
        error: `${err.meta.target} 已存在`,
      })
    }
    // 外键约束失败（比如引用了不存在的用户）
    if (err.code === 'P2003') {
      return res.status(400).json({
        success: false,
        error: '关联数据不存在',
      })
    }
  }

  const statusCode = err.statusCode || 500
  res.status(statusCode).json({
    success: false,
    error: err.message || '服务器内部错误',
  })
}
```

## 练习

### 练习一：完成 Comment Repository

实现 `src/repositories/commentRepository.js`，包含：
- `findByPostId(postId)` —— 查询某篇文章的所有评论，包含评论作者信息
- `create(data)` —— 创建评论
- `delete(id)` —— 删除评论
- `countByPostId(postId)` —— 统计某篇文章的评论数

### 练习二：事务操作

实现一个"删除用户"的功能，要求：删除用户时，先删除该用户的所有评论，再删除该用户的所有文章，最后删除用户。用 Prisma 的 `$transaction` 保证这三个操作要么全部成功，要么全部回滚。

### 练习三：分页查询

给 `postRepository.findAll` 加分页支持：接收 `page` 和 `pageSize` 参数，返回 `{ data, total, page, pageSize, totalPages }`。

### 练习二要点

```js
async function deleteUser(userId) {
  await prisma.$transaction([
    prisma.comment.deleteMany({ where: { authorId: userId } }),
    prisma.post.deleteMany({ where: { authorId: userId } }),
    prisma.user.delete({ where: { id: userId } }),
  ])
}
```

### 练习三要点

```js
async findAll(filters = {}) {
  const { page = 1, pageSize = 10, ...whereFilters } = filters
  const where = {}
  if (whereFilters.status) where.status = whereFilters.status

  const [data, total] = await prisma.$transaction([
    prisma.post.findMany({
      where,
      skip: (page - 1) * pageSize,
      take: pageSize,
      orderBy: { createdAt: 'desc' },
      include: { author: { select: { id: true, name: true } } },
    }),
    prisma.post.count({ where }),
  ])

  return {
    data,
    total,
    page,
    pageSize,
    totalPages: Math.ceil(total / pageSize),
  }
}
```
