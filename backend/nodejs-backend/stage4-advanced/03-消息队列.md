# 第四阶段 · 第3课：消息队列

## 场景引入

用户在你的博客平台注册了账号，API 需要依次完成以下操作：保存用户数据到数据库、发送欢迎邮件、生成头像缩略图、更新注册统计。其中发邮件需要 2 秒，生成缩略图需要 1 秒，用户盯着屏幕等了 3 秒多才看到"注册成功"。更糟糕的是，如果邮件服务临时挂了，整个注册流程直接失败，用户连账号都创建不了。问题的根源是：所有操作都是同步串行的。消息队列的核心思想是"异步处理"——把耗时的操作放进队列，API 立刻返回响应，后台 Worker 慢慢处理。这样既提升了用户体验，又实现了服务解耦。本课将用 BullMQ 为博客 API 实现异步邮件、摘要生成和定时清理任务。

## 学习目标

完成本课学习后，你将能够：

1. 理解消息队列的核心概念和使用场景
2. 掌握 BullMQ 的基本用法（Producer、Worker、重试、延迟、定时任务）
3. 为博客 API 实现异步任务处理（邮件、摘要、统计、清理）
4. 理解生产者-消费者模式和任务生命周期

## 一、什么是消息队列？

### 1.1 生活类比：餐厅的叫号系统

```
没有叫号系统（同步处理）：

顾客 → 排队 → 点餐 → 等在窗口 → 取餐 → 用餐
              ↓
        厨师做菜时，顾客只能干等
        下一个顾客也只能等
        窗口前排起长队...


有叫号系统（异步处理）：

顾客 → 点餐 → 拿号码牌 → 找座位坐下 → 等叫号 → 取餐
              ↓
        厨师按顺序做菜
        顾客可以先做别的事（聊天、看手机）
        窗口不会堵塞
```

在后端系统中：

```
同步处理（没有消息队列）：

用户注册 → 保存数据库 → 发送欢迎邮件 → 生成头像缩略图 → 返回响应
                          ↑                ↑
                       耗时 2 秒         耗时 1 秒
                       用户必须等待 3 秒才能看到 "注册成功"


异步处理（有消息队列）：

用户注册 → 保存数据库 → 把任务放入队列 → 返回响应（50ms 内）
                          ↓
                   队列（等待处理）
                   ├── [发邮件] → Worker 1 处理
                   └── [生成缩略图] → Worker 2 处理
                   
                   用户立刻看到 "注册成功"，邮件稍后发出
```

### 1.2 为什么需要消息队列？

```
┌─────────────────────────────────────────────────────────┐
│                  消息队列解决的三大问题                     │
│                                                          │
│  1. 异步处理（Async Processing）                          │
│     ┌────────┐    ┌──────┐    ┌────────┐                │
│     │  API   │───►│ 队列  │───►│ Worker │                │
│     │ 快速响应│    │      │    │ 后台处理│                │
│     └────────┘    └──────┘    └────────┘                │
│     不需要等任务完成，立刻返回响应给用户                     │
│                                                          │
│  2. 解耦（Decoupling）                                    │
│     ┌────────┐    ┌──────┐    ┌────────┐                │
│     │ 用户服务│───►│ 队列  │───►│ 邮件服务│                │
│     └────────┘    └──────┘    └────────┘                │
│     用户服务不关心邮件怎么发，只管往队列里扔任务              │
│     邮件服务挂了？没关系，任务还在队列里，恢复后继续处理      │
│                                                          │
│  3. 削峰（Load Leveling）                                 │
│     请求量：1000/s ──► ┌──────┐ ──► 处理能力：100/s      │
│                        │  队列  │                          │
│                        │ 900等待│   先存起来，慢慢处理      │
│                        └──────┘                          │
│     突然涌入大量请求，不会直接打崩数据库                     │
└─────────────────────────────────────────────────────────┘
```

### 1.3 什么时候用消息队列？

```
适合用消息队列：                 不适合用消息队列：

✅ 发送邮件/短信                 ❌ 需要同步返回结果的操作
✅ 生成报表/摘要                 ❌ 简单的 CRUD 操作
✅ 图片/视频处理                 ❌ 实时性要求极高的操作
✅ 更新统计数据                  ❌ 事务性操作（需要立即确认）
✅ 推送通知
✅ 定时清理任务
✅ 日志处理
```

## 二、消息队列基本概念

### 2.1 核心术语

```
消息队列的基本模型：

┌──────────┐    发送消息     ┌──────────┐    消费消息     ┌──────────┐
│ Producer │ ─────────────►│  Queue   │ ─────────────►│ Consumer │
│ (生产者)  │               │  (队列)   │               │ (消费者)  │
│          │               │          │               │          │
│ 发送任务  │               │ 存储任务  │               │ 处理任务  │
└──────────┘               └──────────┘               └──────────┘

类比：

Producer = 顾客（下单点餐）
Queue    = 叫号系统（排队等待）
Consumer = 厨师（做菜出餐）
```

| 术语 | 英文 | 含义 | 类比 |
|------|------|------|------|
| 生产者 | Producer | 发送消息的一方 | 顾客 |
| 消费者 | Consumer | 处理消息的一方 | 厨师 |
| 队列 | Queue | 存储消息的地方 | 叫号系统 |
| 消息 | Message/Job | 要处理的任务 | 订单 |

### 2.2 消息的生命周期

```
消息状态流转：

   ┌─────────┐     添加     ┌─────────┐     获取     ┌──────────┐
   │ (创建)   │ ──────────►│ Waiting │ ──────────►│  Active  │
   │         │            │ (等待中)  │            │ (处理中)  │
   └─────────┘            └─────────┘            └────┬─────┘
                                                      │
                                         ┌────────────┼────────────┐
                                         ▼            ▼            ▼
                                   ┌──────────┐ ┌──────────┐ ┌──────────┐
                                   │Completed │ │  Failed  │ │  Delayed │
                                   │ (已完成)  │ │ (失败)    │ │ (延迟)   │
                                   └──────────┘ └────┬─────┘ └──────────┘
                                                      │
                                                      │ 重试
                                                      ▼
                                                ┌──────────┐
                                                │ Waiting  │
                                                │ (重新等待) │
                                                └──────────┘
```

## 三、BullMQ 简介

### 3.1 什么是 BullMQ？

**BullMQ** 是基于 **Redis** 的 Node.js 消息队列库，是 Bull 的升级版本。

```
为什么选择 BullMQ？

┌───────────────────────────────────────────────┐
│                BullMQ 特性                     │
│                                               │
│  ✅ 基于 Redis ── 高性能、持久化、分布式        │
│  ✅ TypeScript 原生支持                        │
│  ✅ 自动重试 ── 失败自动重试，支持指数退避       │
│  ✅ 延迟任务 ── 支持定时执行                    │
│  ✅ 定时任务 ── 支持 Cron 表达式                │
│  ✅ 优先级 ── 重要任务优先处理                  │
│  ✅ 并发控制 ── 限制 Worker 数量               │
│  ✅ 仪表盘 ── 有配套的 Web UI（Bull Board）    │
└───────────────────────────────────────────────┘
```

### 3.2 安装与配置

```bash
# 安装 BullMQ（需要 Redis 已安装并运行）
```

### 4.2 添加任务

```typescript
// src/services/email-queue.service.ts
import { emailQueue } from '../queues';

/**
 * 发送欢迎邮件（异步）
 *
 * 用户注册后调用，不需要等待邮件发送完成
 */
export async function sendWelcomeEmailJob(userId: number, email: string, name: string) {
  const job = await emailQueue.add(
    'welcome',          // 任务名称（一个队列可以有多种任务）
    {                   // 任务数据
      userId,
      email,
      name,
      template: 'welcome',
    },
    {                   // 任务选项
      attempts: 3,      // 最多重试 3 次
      backoff: {
        type: 'exponential',  // 指数退避
        delay: 1000,          // 第 1 次重试等 1 秒，第 2 次等 2 秒，第 3 次等 4 秒
      },
      removeOnComplete: 100,  // 保留最近 100 个已完成任务（清理旧数据）
      removeOnFail: 500,      // 保留最近 500 个失败任务（方便排查问题）
    }
  );

  console.log(`📧 欢迎邮件任务已入队: Job ID=${job.id}, 用户=${name}`);
  return job;
}

/**
 * 发送密码重置邮件
 */
export async function sendPasswordResetJob(email: string, token: string) {
  const job = await emailQueue.add(
    'password-reset',
    { email, token, template: 'password-reset' },
    {
      attempts: 3,
      priority: 1,       // 优先级（数字越小越优先）
    }
  );

  console.log(`📧 密码重置邮件任务已入队: Job ID=${job.id}`);
  return job;
}

/**
 * 发送评论通知邮件
 */
export async function sendCommentNotificationJob(
  recipientEmail: string,
  data: {
    postTitle: string;
    commenterName: string;
    commentContent: string;
    postId: number;
  }
) {
  const job = await emailQueue.add(
    'comment-notification',
    {
      email: recipientEmail,
      ...data,
      template: 'comment-notification',
    },
    {
      attempts: 2,
      delay: 5000,       // 延迟 5 秒发送（避免评论撤回后还发通知）
    }
  );

  console.log(`📧 评论通知任务已入队: Job ID=${job.id}`);
  return job;
}
```

### 4.3 在业务代码中使用

```typescript
// src/routes/auth.routes.ts
import { Router, Request, Response } from 'express';
import { PrismaClient } from '@prisma/client';
import bcrypt from 'bcrypt';
import { sendWelcomeEmailJob } from '../services/email-queue.service';

const router = Router();
const prisma = new PrismaClient();

/**
 * POST /api/auth/register
 * 用户注册（异步发送欢迎邮件）
 */
router.post('/register', async (req: Request, res: Response) => {
  try {
    const { email, password, name } = req.body;

    // 验证输入
    if (!email || !password || !name) {
      return res.status(400).json({ error: '邮箱、密码和用户名不能为空' });
    }

    // 检查邮箱是否已注册
    const existingUser = await prisma.user.findUnique({ where: { email } });
    if (existingUser) {
      return res.status(409).json({ error: '该邮箱已注册' });
    }

    // 密码加密
    const hashedPassword = await bcrypt.hash(password, 10);

    // 保存用户
    const user = await prisma.user.create({
      data: { email, password: hashedPassword, name },
      select: { id: true, email: true, name: true, createdAt: true },
    });

    // ⭐ 异步发送欢迎邮件（不等待完成，立刻返回响应）
    await sendWelcomeEmailJob(user.id, user.email, user.name);

    res.status(201).json({
      message: '注册成功',
      user,
    });
  } catch (error) {
    console.error('注册失败:', error);
    res.status(500).json({ error: '服务器内部错误' });
  }
});

export default router;
```

## 五、Worker：处理消息

### 5.1 创建 Worker

Worker 是实际处理任务的进程，它从队列中取出任务并执行。

```typescript
// src/workers/email.worker.ts
import { Worker, Job } from 'bullmq';
import { connection } from '../lib/queue';

/**
 * 邮件任务数据类型
 */
interface EmailJobData {
  userId?: number;
  email: string;
  name?: string;
  template: string;
  token?: string;
  postTitle?: string;
  commenterName?: string;
  commentContent?: string;
  postId?: number;
}

/**
 * 邮件 Worker
 *
 * Worker 会自动从队列中获取任务并执行
 * 多个 Worker 可以并行处理（通过 concurrency 控制）
 */
const emailWorker = new Worker<EmailJobData>(
  'email',                    // 队列名称（必须和 Queue 一致）
  async (job: Job<EmailJobData>) => {
    const { template, email } = job.data;

    console.log(`📧 开始处理邮件任务: ${template} → ${email}`);

    // 根据模板类型分发处理
    switch (template) {
      case 'welcome':
        return await handleWelcomeEmail(job);
      case 'password-reset':
        return await handlePasswordResetEmail(job);
      case 'comment-notification':
        return await handleCommentNotification(job);
      default:
        throw new Error(`未知的邮件模板: ${template}`);
    }
  },
  {
    connection,
    concurrency: 5,           // 同时处理 5 个任务
    limiter: {
      max: 100,               // 每个时间窗口最多处理 100 个任务
      duration: 60000,        // 时间窗口：60 秒
    },
  }
);

// ==================== 任务处理器 ====================

/**
 * 处理欢迎邮件
 */
async function handleWelcomeEmail(job: Job<EmailJobData>) {
  const { email, name } = job.data;

  // 更新进度
  await job.updateProgress(10);

  // 模拟发送邮件（实际项目中用 nodemailer 等库）
  console.log(`📨 发送欢迎邮件到: ${email}`);

  // 模拟耗时操作
  await new Promise(resolve => setTimeout(resolve, 1000));

  await job.updateProgress(50);

  // 模拟邮件服务调用
  // await transporter.sendMail({
  //   from: 'noreply@blog.com',
  //   to: email,
  //   subject: `欢迎加入博客平台，${name}！`,
  //   html: `<h1>你好，${name}！</h1><p>欢迎注册我们的博客平台...</p>`,
  // });

  await job.updateProgress(100);

  return { success: true, sentAt: new Date().toISOString() };
}

/**
 * 处理密码重置邮件
 */
async function handlePasswordResetEmail(job: Job<EmailJobData>) {
  const { email, token } = job.data;

  console.log(`📨 发送密码重置邮件到: ${email}`);
  await new Promise(resolve => setTimeout(resolve, 500));

  // await transporter.sendMail({...});

  return { success: true };
}

/**
 * 处理评论通知邮件
 */
async function handleCommentNotification(job: Job<EmailJobData>) {
  const { email, postTitle, commenterName, commentContent } = job.data;

  console.log(`📨 发送评论通知到: ${email}`);
  console.log(`   文章: ${postTitle}`);
  console.log(`   评论者: ${commenterName}`);
  console.log(`   内容: ${commentContent}`);

  await new Promise(resolve => setTimeout(resolve, 500));

  return { success: true };
}

// ==================== Worker 事件监听 ====================

emailWorker.on('completed', (job) => {
  console.log(`✅ 邮件任务完成: ${job.id} (${job.data.template})`);
});

emailWorker.on('failed', (job, err) => {
  console.error(`❌ 邮件任务失败: ${job?.id} (${job?.data.template})`, err.message);
});

emailWorker.on('error', (err) => {
  console.error('⚠️ Worker 错误:', err.message);
});

export default emailWorker;
```

### 5.3 任务生命周期管理

```typescript
// src/services/queue-monitor.service.ts
import { emailQueue, summaryQueue, statsQueue, cleanupQueue } from '../queues';

/**
 * 队列监控服务
 * 查看队列状态和任务统计
 */
export async function getQueueStats() {
  const queues = [
    { name: 'email', queue: emailQueue },
    { name: 'summary', queue: summaryQueue },
    { name: 'stats', queue: statsQueue },
    { name: 'cleanup', queue: cleanupQueue },
  ];

  const stats = await Promise.all(
    queues.map(async ({ name, queue }) => {
      const [waiting, active, completed, failed, delayed] = await Promise.all([
        queue.getWaitingCount(),
        queue.getActiveCount(),
        queue.getCompletedCount(),
        queue.getFailedCount(),
        queue.getDelayedCount(),
      ]);

      return {
        name,
        waiting,
        active,
        completed,
        failed,
        delayed,
        total: waiting + active + completed + failed + delayed,
      };
    })
  );

  return stats;
}

/**
 * 获取指定队列的最近任务
 */
export async function getRecentJobs(queueName: string, status: string, limit = 20) {
  const queueMap: Record<string, typeof emailQueue> = {
    email: emailQueue,
    summary: summaryQueue,
    stats: statsQueue,
    cleanup: cleanupQueue,
  };

  const queue = queueMap[queueName];
  if (!queue) throw new Error(`未知的队列: ${queueName}`);

  let jobs;
  switch (status) {
    case 'waiting':
      jobs = await queue.getWaiting(0, limit - 1);
      break;
    case 'active':
      jobs = await queue.getActive(0, limit - 1);
      break;
    case 'completed':
      jobs = await queue.getCompleted(0, limit - 1);
      break;
    case 'failed':
      jobs = await queue.getFailed(0, limit - 1);
      break;
    case 'delayed':
      jobs = await queue.getDelayed(0, limit - 1);
      break;
    default:
      throw new Error(`未知的状态: ${status}`);
  }

  return jobs.map(job => ({
    id: job.id,
    name: job.name,
    data: job.data,
    progress: job.progress,
    attemptsMade: job.attemptsMade,
    failedReason: job.failedReason,
    timestamp: job.timestamp,
    processedOn: job.processedOn,
    finishedOn: job.finishedOn,
  }));
}

/**
 * 重试失败的任务
 */
export async function retryFailedJob(queueName: string, jobId: string) {
  const queueMap: Record<string, typeof emailQueue> = {
    email: emailQueue,
    summary: summaryQueue,
    stats: statsQueue,
    cleanup: cleanupQueue,
  };

  const queue = queueMap[queueName];
  if (!queue) throw new Error(`未知的队列: ${queueName}`);

  const job = await queue.getJob(jobId);
  if (!job) throw new Error(`任务不存在: ${jobId}`);

  await job.retry();
  console.log(`🔄 任务已重试: ${queueName}/${jobId}`);
}

/**
 * 清理已完成的任务
 */
export async function cleanQueue(queueName: string, grace = 3600000) {
  const queueMap: Record<string, typeof emailQueue> = {
    email: emailQueue,
    summary: summaryQueue,
    stats: statsQueue,
    cleanup: cleanupQueue,
  };

  const queue = queueMap[queueName];
  if (!queue) throw new Error(`未知的队列: ${queueName}`);

  const cleaned = await queue.clean(grace, 1000, 'completed');
  console.log(`🧹 清理了 ${cleaned.length} 个已完成任务`);
  return cleaned.length;
}
```

## 六、延迟任务与定时任务

### 6.1 延迟任务（Delayed Jobs）

```
延迟任务 = 指定时间后才执行

类比：设定闹钟

现在（10:00）  设定 2 小时后提醒
    ↓
    ┌───────────────────────────┐
    │  队列（任务等待中...）      │
    │  "12:00 发送提醒"         │
    └───────────┬───────────────┘
                │ 到 12:00 了
                ▼
        Worker 开始处理
```

```typescript
// src/services/summary-queue.service.ts
import { summaryQueue, statsQueue, cleanupQueue } from '../queues';

/**
 * 延迟生成文章摘要
 *
 * 文章发布后延迟 30 秒再生成摘要
 * （给作者修改文章的缓冲时间）
 */
export async function scheduleGenerateSummary(postId: number) {
  const job = await summaryQueue.add(
    'generate-summary',
    { postId },
    {
      delay: 30000,       // 30 秒后执行
      attempts: 3,
      backoff: {
        type: 'exponential',
        delay: 2000,
      },
    }
  );

  console.log(`📝 文章摘要任务已入队: Job ID=${job.id}, 文章ID=${postId}`);
  return job;
}

/**
 * 延迟更新阅读统计
 *
 * 用户阅读文章后，延迟 10 秒再更新统计
 * （避免快速刷新导致重复计数）
 */
export async function scheduleUpdateReadStats(postId: number, userId?: number) {
  const job = await statsQueue.add(
    'update-read-stats',
    { postId, userId },
    {
      delay: 10000,       // 10 秒后执行
      jobId: `read:${postId}:${userId || 'anonymous'}:${Date.now()}`,
      // 用 jobId 去重（相同 ID 的任务不会重复添加）
    }
  );

  return job;
}
```

### 6.2 定时任务（Cron Jobs）

```
定时任务 = 按照固定时间规律重复执行

类比：每天早上 7 点的闹钟

┌──────────────────────────────────┐
│        Cron 表达式               │
│                                  │
│  ┌──── 分钟 (0-59)               │
│  │ ┌── 小时 (0-23)               │
│  │ │ ┌ 日 (1-31)                 │
│  │ │ │ ┌ 月 (1-12)               │
│  │ │ │ │ ┌ 星期 (0-6, 0=周日)    │
│  │ │ │ │ │                       │
│  * * * * *                       │
│                                  │
│  常用示例：                       │
│  0 0 * * *    → 每天凌晨 0 点     │
│  */5 * * * *  → 每 5 分钟         │
│  0 9 * * 1    → 每周一上午 9 点   │
│  0 0 1 * *    → 每月 1 号凌晨     │
└──────────────────────────────────┘
```

```typescript
// src/services/cleanup-queue.service.ts
import { cleanupQueue } from '../queues';

/**
 * 注册定时清理任务
 *
 * 这些任务在应用启动时添加一次，之后会自动重复执行
 */
export async function setupCronJobs() {
  // 1. 每天凌晨 2 点清理过期草稿
  await cleanupQueue.add(
    'clean-expired-drafts',
    {},
    {
      repeat: {
        pattern: '0 2 * * *',    // Cron 表达式：每天凌晨 2 点
      },
      removeOnComplete: 10,       // 保留最近 10 个执行记录
      removeOnFail: 50,
    }
  );

  // 2. 每小时清理过期 Session
  await cleanupQueue.add(
    'clean-expired-sessions',
    {},
    {
      repeat: {
        pattern: '0 * * * *',    // 每小时整点
      },
      removeOnComplete: 24,       // 保留最近 24 个（一天的量）
    }
  );

  // 3. 每天凌晨 3 点生成日报统计
  await cleanupQueue.add(
    'generate-daily-report',
    {},
    {
      repeat: {
        pattern: '0 3 * * *',    // 每天凌晨 3 点
      },
      removeOnComplete: 7,        // 保留最近 7 天
    }
  );

  // 4. 每 5 分钟检查并重试失败的邮件
  await cleanupQueue.add(
    'retry-failed-emails',
    {},
    {
      repeat: {
        every: 5 * 60 * 1000,    // 每 5 分钟
      },
      removeOnComplete: 100,
    }
  );

  console.log('⏰ 定时任务已注册');
}
```

### 6.3 清理任务 Worker

```typescript
// src/workers/cleanup.worker.ts
import { Worker, Job } from 'bullmq';
import { connection } from '../lib/queue';
import { PrismaClient } from '@prisma/client';
import redis from '../lib/redis';

const prisma = new PrismaClient();

const cleanupWorker = new Worker(
  'cleanup',
  async (job: Job) => {
    console.log(`🧹 执行清理任务: ${job.name}`);

    switch (job.name) {
      case 'clean-expired-drafts':
        return await cleanExpiredDrafts();
      case 'clean-expired-sessions':
        return await cleanExpiredSessions();
      case 'generate-daily-report':
        return await generateDailyReport();
      case 'retry-failed-emails':
        return await retryFailedEmails();
      default:
        throw new Error(`未知的清理任务: ${job.name}`);
    }
  },
  { connection, concurrency: 2 }
);

/**
 * 清理过期草稿
 */
async function cleanExpiredDrafts() {
  const expiredDate = new Date();
  expiredDate.setDate(expiredDate.getDate() - 30); // 30 天前

  const result = await prisma.post.deleteMany({
    where: {
      status: 'DRAFT',
      updatedAt: { lt: expiredDate },
    },
  });

  console.log(`🗑️ 清理了 ${result.count} 个过期草稿`);
  return { deletedCount: result.count };
}

/**
 * 清理过期 Session
 */
async function cleanExpiredSessions() {
  // 从 Redis 中清理过期的 Session
  const keys = await redis.keys('sess:*');
  let cleanedCount = 0;

  for (const key of keys) {
    const ttl = await redis.ttl(key);
    if (ttl === -1) {
      // 没有设置过期时间的 Session，可能是异常数据
      await redis.del(key);
      cleanedCount++;
    }
  }

  console.log(`🗑️ 清理了 ${cleanedCount} 个异常 Session`);
  return { cleanedCount };
}

/**
 * 生成每日统计报告
 */
async function generateDailyReport() {
  const yesterday = new Date();
  yesterday.setDate(yesterday.getDate() - 1);
  yesterday.setHours(0, 0, 0, 0);

  const today = new Date();
  today.setHours(0, 0, 0, 0);

  const [newUsers, newPosts, newComments] = await Promise.all([
    prisma.user.count({
      where: { createdAt: { gte: yesterday, lt: today } },
    }),
    prisma.post.count({
      where: { createdAt: { gte: yesterday, lt: today } },
    }),
    prisma.comment.count({
      where: { createdAt: { gte: yesterday, lt: today } },
    }),
  ]);

  const report = {
    date: yesterday.toISOString().split('T')[0],
    newUsers,
    newPosts,
    newComments,
    generatedAt: new Date().toISOString(),
  };

  // 存储报告（可以存到数据库或 Redis）
  await redis.set(
    `report:daily:${report.date}`,
    JSON.stringify(report),
    'EX',
    86400 * 30 // 保留 30 天
  );

  console.log(`📊 日报已生成:`, report);
  return report;
}

/**
 * 重试失败的邮件
 */
async function retryFailedEmails() {
  const { emailQueue } = await import('../queues');
  const failedJobs = await emailQueue.getFailed(0, 19);

  let retriedCount = 0;
  for (const job of failedJobs) {
    // 只重试最近 1 小时内失败的任务
    const oneHourAgo = Date.now() - 3600000;
    if (job.timestamp > oneHourAgo && job.attemptsMade < 3) {
      await job.retry();
      retriedCount++;
    }
  }

  console.log(`🔄 重试了 ${retriedCount} 个失败的邮件任务`);
  return { retriedCount };
}

cleanupWorker.on('completed', (job) => {
  console.log(`✅ 清理任务完成: ${job.name}`);
});

cleanupWorker.on('failed', (job, err) => {
  console.error(`❌ 清理任务失败: ${job?.name}`, err.message);
});

export default cleanupWorker;
```

```typescript
// src/workers/summary.worker.ts
import { Worker, Job } from 'bullmq';
import { connection } from '../lib/queue';
import { PrismaClient } from '@prisma/client';
import { cache } from '../lib/cache';

const prisma = new PrismaClient();

interface SummaryJobData {
  postId: number;
}

/**
 * 文章摘要 Worker
 * 发布文章后自动生成摘要
 */
const summaryWorker = new Worker<SummaryJobData>(
  'summary',
  async (job: Job<SummaryJobData>) => {
    const { postId } = job.data;

    console.log(`📝 开始生成文章摘要: 文章ID=${postId}`);

    // 1. 获取文章内容
    const post = await prisma.post.findUnique({
      where: { id: postId },
      select: { id: true, title: true, content: true },
    });

    if (!post) {
      throw new Error(`文章不存在: ${postId}`);
    }

    // 2. 生成摘要（简单实现：取前 200 字符）
    // 实际项目中可以用 AI API（如 Claude API）生成更好的摘要
    await job.updateProgress(30);

    const summary = generateSimpleSummary(post.content, 200);

    await job.updateProgress(60);

    // 3. 更新数据库
    await prisma.post.update({
      where: { id: postId },
      data: { summary },
    });

    await job.updateProgress(80);

    // 4. 清除相关缓存
    await cache.del(`post:${postId}`);
    await cache.delPattern('posts:list:*');

    await job.updateProgress(100);

    console.log(`✅ 文章摘要已生成: 文章ID=${postId}`);
    return { postId, summaryLength: summary.length };
  },
  { connection, concurrency: 3 }
);

/**
 * 生成简单摘要
 * 取内容的前 N 个字符，在句子结束处截断
 */
function generateSimpleSummary(content: string, maxLength: number): string {
  if (content.length <= maxLength) return content;

  // 截取到 maxLength
  let summary = content.substring(0, maxLength);

  // 在最后一个句号、问号或感叹号处截断
  const lastPunctuation = Math.max(
    summary.lastIndexOf('。'),
    summary.lastIndexOf('！'),
    summary.lastIndexOf('？'),
    summary.lastIndexOf('.'),
    summary.lastIndexOf('!'),
    summary.lastIndexOf('?')
  );

  if (lastPunctuation > maxLength * 0.5) {
    summary = summary.substring(0, lastPunctuation + 1);
  } else {
    summary += '...';
  }

  return summary;
}

summaryWorker.on('completed', (job) => {
  console.log(`✅ 摘要任务完成: ${job.id}`);
});

summaryWorker.on('failed', (job, err) => {
  console.error(`❌ 摘要任务失败: ${job?.id}`, err.message);
});

export default summaryWorker;
```

### 练习 1：图片处理队列

**思路**：创建独立的 `imageQueue`，Worker 使用 `sharp` 库生成三种尺寸的缩略图。任务失败自动重试 3 次，生成完成后更新数据库并通过 Socket.IO 通知用户。

**答案**：

```typescript

import { Queue } from 'bullmq';
```

```typescript
// src/workers/image.worker.ts
import { Worker, Job } from 'bullmq';
import { connection } from '../lib/queue';
import { PrismaClient } from '@prisma/client';
import { getIO } from '../lib/socket';
import sharp from 'sharp';
import path from 'path';
import fs from 'fs/promises';

const prisma = new PrismaClient();

interface ImageJobData {
  userId: number;
  originalPath: string;  // 原始头像路径
}

const THUMB_SIZES = [
  { name: 'small', width: 64, height: 64 },
  { name: 'medium', width: 128, height: 128 },
  { name: 'large', width: 256, height: 256 },
];

const imageWorker = new Worker<ImageJobData>(
  'image',
  async (job: Job<ImageJobData>) => {
    const { userId, originalPath } = job.data;

    console.log(`🖼️ 开始处理用户 ${userId} 的头像缩略图`);

    const uploadDir = path.dirname(originalPath);
    const thumbPaths: Record<string, string> = {};

    // 生成三种尺寸的缩略图
    for (let i = 0; i < THUMB_SIZES.length; i++) {
      const size = THUMB_SIZES[i];
      const outputPath = path.join(uploadDir, `avatar_${size.name}_${userId}.webp`);

      await sharp(originalPath)
        .resize(size.width, size.height, { fit: 'cover' })
        .webp({ quality: 80 })
        .toFile(outputPath);

      thumbPaths[size.name] = outputPath;

      // 更新任务进度
      await job.updateProgress(Math.floor(((i + 1) / THUMB_SIZES.length) * 100));

      console.log(`  ✅ ${size.name} (${size.width}x${size.height}) 已生成`);
    }

    // 更新数据库
    await prisma.user.update({
      where: { id: userId },
      data: {
        avatarThumbSmall: thumbPaths.small,
        avatarThumbMedium: thumbPaths.medium,
        avatarThumbLarge: thumbPaths.large,
      },
    });

    // 通过 Socket.IO 通知用户
    const io = getIO();
    io.to(`user:${userId}`).emit('avatar:updated', {
      userId,
      thumbnails: thumbPaths,
      message: '头像缩略图已生成完成',
    });

    console.log(`✅ 用户 ${userId} 的头像缩略图处理完成`);

    return { userId, thumbnails: thumbPaths };
  },
  {
    connection,
    concurrency: 3,       // 最多同时处理 3 个图片任务
    limiter: {
      max: 10,            // 每分钟最多处理 10 个
      duration: 60000,
    },
  }
);

imageWorker.on('completed', (job) => {
  console.log(`✅ 图片任务完成: ${job.id}`);
});

imageWorker.on('failed', (job, err) => {
  console.error(`❌ 图片任务失败: ${job?.id}`, err.message);
});

export default imageWorker;
```

### 练习 2：通知聚合

**思路**：收到第一个点赞通知时，用 Redis Hash 存储待聚合数据并添加一个延迟任务。1 分钟内新的同类通知追加到 Hash 中。延迟任务到期后，读取聚合并发送最终通知。

**答案**：

```typescript
// src/services/notification-aggregator.service.ts
import redis from '../lib/redis';
import { getIO } from '../lib/socket';
import { PrismaClient } from '@prisma/client';

const prisma = new PrismaClient();

const AGGREGATE_WINDOW = 60 * 1000; // 1 分钟聚合窗口

/**
 * 添加待聚合的通知
 * 收到点赞/评论等事件时调用
 */
export async function addNotificationForAggregation(data: {
  userId: number;         // 通知接收者
  postId: number;         // 相关文章
  type: 'like' | 'comment';
  actorId: number;        // 触发者 ID
  actorName: string;      // 触发者名称
}): Promise<void> {
  const { userId, postId, type, actorId, actorName } = data;
  const hashKey = `notification:aggregate:${userId}:${postId}:${type}`;

  // 1. 将触发者信息存入 Redis Hash
  // HSET notification:aggregate:1:2:like actors "张三,李四" count "2"
  const existing = await redis.hgetall(hashKey);

  if (existing.count) {
    // 已有聚合记录，追加
    const actors = existing.actors ? existing.actors.split(',') : [];
    if (!actors.includes(actorName)) {
      actors.push(actorName);
    }
    await redis.hset(hashKey, 'actors', actors.join(','));
    await redis.hincrby(hashKey, 'count', 1);
  } else {
    // 第一条通知，初始化
    await redis.hmset(hashKey, {
      actors: actorName,
      count: '1',
      type,
      postId: postId.toString(),
      userId: userId.toString(),
      firstAt: Date.now().toString(),
    });
  }

  // 设置过期时间（防止泄漏）
  await redis.expire(hashKey, 120); // 2 分钟后自动清理

  // 2. 检查是否已有待执行的延迟任务
  const taskKey = `notification:task:${userId}:${postId}:${type}`;
  const hasTask = await redis.exists(taskKey);

  if (!hasTask) {
    // 标记已有待执行任务
    await redis.set(taskKey, '1', 'EX', AGGREGATE_WINDOW / 1000 + 5);

    // 添加延迟任务（1 分钟后执行）
    const { notificationQueue } = await import('../queues');
    await notificationQueue.add(
      'send-aggregated',
      { userId, postId, type },
      {
        delay: AGGREGATE_WINDOW,
        jobId: `agg:${userId}:${postId}:${type}:${Date.now()}`,
        removeOnComplete: true,
      }
    );

    console.log(`⏰ 通知聚合任务已创建: 用户${userId}, 文章${postId}, 类型${type}`);
  }
}

/**
 * 发送聚合通知（延迟任务到期后调用）
 */
export async function sendAggregatedNotification(data: {
  userId: number;
  postId: number;
  type: string;
}): Promise<void> {
  const { userId, postId, type } = data;
  const hashKey = `notification:aggregate:${userId}:${postId}:${type}`;

  // 1. 读取聚合数据
  const aggregated = await redis.hgetall(hashKey);
  if (!aggregated.count) {
    console.log('聚合数据已过期，跳过');
    return;
  }

  const actors = aggregated.actors?.split(',') || [];
  const count = parseInt(aggregated.count);

  // 2. 生成聚合消息
  let message: string;
  if (count === 1) {
    message = type === 'like'
      ? `${actors[0]} 赞了你的文章`
      : `${actors[0]} 评论了你的文章`;
  } else if (count <= 3) {
    message = type === 'like'
      ? `${actors.join('、')} 赞了你的文章`
      : `${actors.join('、')} 评论了你的文章`;
  } else {
    message = type === 'like'
      ? `${actors[0]}等 ${count} 人赞了你的文章`
      : `${actors[0]}等 ${count} 人评论了你的文章`;
  }

  // 3. 获取文章标题
  const post = await prisma.post.findUnique({
    where: { id: postId },
    select: { title: true },
  });

  // 4. 发送通知
  const notification = {
    id: `agg-${type}-${postId}-${userId}-${Date.now()}`,
    type,
    title: type === 'like' ? '收到新点赞' : '收到新评论',
    message,
    link: `/posts/${postId}`,
    count,
    createdAt: new Date().toISOString(),
  };

  // 通过 Socket.IO 推送
  const io = getIO();
  const targetSockets = await io.in(`user:${userId}`).fetchSockets();

  if (targetSockets.length > 0) {
    io.to(`user:${userId}`).emit('notification:new', notification);
    console.log(`📢 聚合通知已发送: ${message}`);
  } else {
    // 用户离线，缓存通知
    await redis.lpush(
      `offline:notifications:${userId}`,
      JSON.stringify(notification)
    );
    await redis.expire(`offline:notifications:${userId}`, 86400 * 7);
  }

  // 5. 清理聚合数据
  await redis.del(hashKey);
}
```

**要点**：
- Redis Hash 存储聚合数据，`HINCRBY` 原子递增计数，`HMSET` 批量写入字段
- 用 `notification:task:*` 键做去重，同一用户同一文章同一类型只创建一个延迟任务
- 聚合消息根据数量智能生成：1 人显示名字，3 人以内显示所有名字，3 人以上显示"等 N 人"
- 聚合窗口结束后自动清理 Hash 数据，避免 Redis 内存泄漏

**思路**：使用 BullMQ 的 Flow 功能（父子任务）实现任务链。每个子任务完成后自动触发下一个，通过父任务统一管理生命周期。

```typescript
// src/services/publish-pipeline.service.ts
import { flowProducer } from '../queues/publish-pipeline.queue';

/**
 * 启动文章发布管道
 * 文章发布后调用，依次执行：摘要 → 关键词 → SEO → 通知
 */
export async function startPublishPipeline(postId: number, authorId: number) {
  // 使用 Flow 创建父子任务链
  // 子任务按顺序执行，前一个完成后再延迟执行下一个
  const flow = await flowProducer.add({
    name: 'generate-summary',
    queueName: 'pipeline',
    data: { postId, authorId, stage: 'summary' },
    opts: {
      delay: 30000,       // 30 秒后开始
      attempts: 3,
      backoff: { type: 'exponential', delay: 2000 },
    },
    children: [
      {
        name: 'extract-keywords',
        queueName: 'pipeline',
        data: { postId, authorId, stage: 'keyword' },
        opts: {
          delay: 30000,   // 摘要完成后再等 30 秒
          attempts: 3,
          backoff: { type: 'exponential', delay: 2000 },
        },
        children: [
          {
            name: 'generate-seo',
            queueName: 'pipeline',
            data: { postId, authorId, stage: 'seo' },
            opts: {
              delay: 30000,  // 关键词完成后再等 30 秒
              attempts: 3,
              backoff: { type: 'exponential', delay: 2000 },
            },
            children: [
              {
                name: 'notify-followers',
                queueName: 'pipeline',
                data: { postId, authorId, stage: 'notify' },
                opts: {
                  delay: 30000,  // SEO 完成后再等 30 秒
                  attempts: 3,
                },
              },
            ],
          },
        ],
      },
    ],
  });

  console.log(`🚀 文章发布管道已启动: 文章ID=${postId}, Flow ID=${flow.job.id}`);
  return flow;
}
```

```typescript
// src/workers/pipeline.worker.ts
import { Worker, Job } from 'bullmq';
import { connection } from '../lib/queue';
import { PrismaClient } from '@prisma/client';
import { cache } from '../lib/cache';
import { getIO } from '../lib/socket';

const prisma = new PrismaClient();

interface PipelineJobData {
  postId: number;
  authorId: number;
  stage: 'summary' | 'keyword' | 'seo' | 'notify';
}

const pipelineWorker = new Worker<PipelineJobData>(
  'pipeline',
  async (job: Job<PipelineJobData>) => {
    const { postId, authorId, stage } = job.data;

    console.log(`🔄 管道阶段 [${stage}] 开始: 文章ID=${postId}`);

    switch (stage) {
      case 'summary':
        return await generateSummary(postId);
      case 'keyword':
        return await extractKeywords(postId);
      case 'seo':
        return await generateSEO(postId);
      case 'notify':
        return await notifyFollowers(postId, authorId);
      default:
        throw new Error(`未知的管道阶段: ${stage}`);
    }
  },
  { connection, concurrency: 2 }
);

/**
 * 阶段 1：生成摘要
 */
async function generateSummary(postId: number) {
  const post = await prisma.post.findUnique({
    where: { id: postId },
    select: { id: true, title: true, content: true },
  });
  if (!post) throw new Error(`文章不存在: ${postId}`);

  // 简单摘要：取前 200 字符，在句子边界截断
  let summary = post.content.substring(0, 200);
  const lastPunct = Math.max(
    summary.lastIndexOf('。'), summary.lastIndexOf('！'),
    summary.lastIndexOf('？'), summary.lastIndexOf('.')
  );
  if (lastPunct > 100) summary = summary.substring(0, lastPunct + 1);
  else summary += '...';

  await prisma.post.update({
    where: { id: postId },
    data: { summary },
  });

  await cache.del(`post:${postId}`);
  console.log(`  ✅ 摘要已生成: ${summary.substring(0, 50)}...`);
  return { summary };
}

/**
 * 阶段 2：提取关键词
 */
async function extractKeywords(postId: number) {
  const post = await prisma.post.findUnique({
    where: { id: postId },
    select: { content: true },
  });
  if (!post) throw new Error(`文章不存在: ${postId}`);

  // 简单实现：提取出现频率最高的 5 个词
  // 实际项目中可以用 NLP 库或 AI API
  const words = post.content
    .replace(/[^\u4e00-\u9fa5a-zA-Z0-9]/g, ' ')
    .split(/\s+/)
    .filter(w => w.length >= 2);

  const freq: Record<string, number> = {};
  for (const word of words) {
    freq[word] = (freq[word] || 0) + 1;
  }

  const keywords = Object.entries(freq)
    .sort((a, b) => b[1] - a[1])
    .slice(0, 5)
    .map(([word]) => word);

  // 可以存入数据库或缓存
  await redis.set(`post:${postId}:keywords`, JSON.stringify(keywords), 'EX', 86400);
  console.log(`  ✅ 关键词已提取: ${keywords.join(', ')}`);
  return { keywords };
}

/**
 * 阶段 3：生成 SEO 元数据
 */
async function generateSEO(postId: number) {
  const post = await prisma.post.findUnique({
    where: { id: postId },
    select: { title: true, summary: true },
  });
  if (!post) throw new Error(`文章不存在: ${postId}`);

  const seoMeta = {
    title: `${post.title} | 博客`,
    description: post.summary?.substring(0, 160) || '',
    ogType: 'article',
  };

  await redis.set(`post:${postId}:seo`, JSON.stringify(seoMeta), 'EX', 86400 * 30);
  console.log(`  ✅ SEO 元数据已生成`);
  return { seoMeta };
}

/**
 * 阶段 4：通知关注者
 */
async function notifyFollowers(postId: number, authorId: number) {
  // 获取作者的关注者
  const followers = await prisma.follow.findMany({
    where: { followingId: authorId },
    select: { followerId: true },
  });

  const post = await prisma.post.findUnique({
    where: { id: postId },
    select: { title: true },
  });

  const io = getIO();
  let notifiedCount = 0;

  for (const follower of followers) {
    const sockets = await io.in(`user:${follower.followerId}`).fetchSockets();
    if (sockets.length > 0) {
      io.to(`user:${follower.followerId}`).emit('notification:new', {
        id: `new-post-${postId}`,
        type: 'system',
        title: '关注的人发布了新文章',
        message: `你关注的作者发布了《${post?.title}》`,
        link: `/posts/${postId}`,
        createdAt: new Date().toISOString(),
      });
      notifiedCount++;
    }
  }

  console.log(`  ✅ 已通知 ${notifiedCount} 位关注者`);
  return { notifiedCount };
}

pipelineWorker.on('completed', (job) => {
  const { stage } = job.data;
  console.log(`✅ 管道阶段完成: [${stage}], Job ID=${job.id}`);
});

pipelineWorker.on('failed', (job, err) => {
  const { stage } = job?.data || {};
  console.error(`❌ 管道阶段失败: [${stage}], Job ID=${job?.id}`, err.message);
});

export default pipelineWorker;
```

**要点**：
- Flow 的父子任务保证执行顺序：父任务完成后子任务才会开始，配合 `delay` 控制间隔
- 每个阶段独立处理，失败不影响其他阶段（重试由 `attempts` 和 `backoff` 控制）
- 任务数据只传 `postId` 和 `authorId`，Worker 自行从数据库查完整数据
- 管道启动后立即返回，不阻塞文章发布接口的响应

---

## 常见误区

1. **把所有操作都放进队列**：简单的数据库更新也发一个队列任务，增加了不必要的复杂度和延迟。消息队列适合耗时、可异步的操作（发邮件、生成报表、图片处理），不适合需要立即返回结果的操作。

2. **任务数据太大**：把整篇文章内容放进任务数据中，导致 Redis 内存膨胀。应该只传文章 ID，Worker 自己从数据库查。任务数据越小，队列性能越好。

3. **不做重试策略**：任务失败后无限重试，导致 Worker 一直在处理同一个失败的任务。必须设置最大重试次数和指数退避策略（第 1 次等 1 秒，第 2 次等 2 秒，第 3 次等 4 秒）。

4. **不清理已完成的任务**：任务完成后不删除，Redis 中积累了数百万条历史任务记录，内存持续增长。用 `removeOnComplete` 和 `removeOnFail` 自动清理。

---

## 工程建议

1. **API 服务器和 Worker 分开部署**：API 服务器处理请求，Worker 处理任务，两者互不影响。Worker 挂了不影响 API 响应，API 挂了 Worker 继续处理积压的任务。

2. **用 `jobId` 去重**：对于相同操作（如同一篇文章的阅读统计），用业务 ID 作为 `jobId`，相同 ID 的任务不会重复添加。避免短时间内重复处理。

3. **定时任务用 Cron 表达式**：`0 2 * * *` 表示每天凌晨 2 点，`*/5 * * * *` 表示每 5 分钟。BullMQ 的 `repeat.pattern` 直接支持 Cron 表达式，不需要额外的定时器库。

4. **监控队列状态**：提供 `/api/admin/queues` 接口查看各队列的 waiting/active/completed/failed 任务数。如果 waiting 持续增长，说明 Worker 处理能力不足，需要增加并发数或 Worker 实例。

## 小结

本课我们学习了：

1. **消息队列的核心价值**：异步处理、解耦、削峰
2. **BullMQ 基础**：基于 Redis 的 Node.js 消息队列，支持重试、延迟、定时任务
3. **Producer（生产者）**：往队列中添加任务（add job）
4. **Worker（消费者）**：从队列中获取并处理任务（process job）
5. **任务状态**：waiting → active → completed / failed
6. **重试机制**：失败自动重试，支持指数退避
7. **延迟任务**：指定时间后才执行
8. **定时任务**：Cron 表达式，定期重复执行
9. **队列监控**：查看任务状态、重试失败任务、清理旧任务
