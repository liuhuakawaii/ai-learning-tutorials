# 性能优化与安全加固

你的博客 API 功能都做完了，本地测试也没问题。但上线前跑了一次压测：100 并发请求，响应时间从 50ms 飙到 2 秒，数据库 CPU 跑满。同时安全扫描报告了 CORS 配置宽松、缺少安全头、输入未消毒等问题。

这节课从这两个具体问题出发，逐个排查和修复。

## 问题一：压测发现慢

先跑一次基准测试，拿到原始数据：

```bash
npm install -D autocannon
npx autocannon -c 100 -d 10 http://localhost:3000/api/posts
```

```
结果示例（修复前）：
  并发连接：100
  持续时间：10 秒
  总请求数：523
  平均延迟：1892ms
  RPS（每秒请求数）：52
```

52 RPS，平均快 2 秒。这不行。开始排查。

### 排查 1：N+1 查询

查看文章列表接口的 Prisma 查询。如果代码是这样的：

```js
// 错误写法
const posts = await prisma.post.findMany()
for (const post of posts) {
  post.author = await prisma.user.findUnique({ where: { id: post.authorId } })
  post.comments = await prisma.comment.findMany({ where: { postId: post.id } })
}
```

查 10 篇文章 = 1 + 10 + 10 = 21 次数据库查询。这就是 N+1 问题。

修复：用 `include` 一次查出来。

```js
// 正确写法
const posts = await prisma.post.findMany({
  include: {
    author: { select: { id: true, name: true } },
    _count: { select: { comments: true } },
  },
  orderBy: { createdAt: 'desc' },
})
```

1 次查询，搞定。

### 排查 2：缺少数据库索引

如果文章表有几万条数据，按 `status` 筛选会全表扫描。加索引：

```prisma
model Post {
  // ...
  @@index([status])
  @@index([authorId])
  @@index([createdAt])
}
```

```bash
npx prisma migrate dev --name add-post-indexes
```

### 排查 3：没有分页

如果 `findAll` 返回所有文章，几万条数据一次性查出来，数据库和网络都扛不住。

```js
const posts = await prisma.post.findMany({
  skip: (page - 1) * pageSize,
  take: pageSize,
  // ...
})
```

### 修复后压测

```bash
npx autocannon -c 100 -d 10 http://localhost:3000/api/posts
```

```
结果示例（修复后）：
  平均延迟：45ms
  RPS：2180
```

从 52 RPS 到 2180 RPS，提升 40 倍。代价是代码复杂度几乎没有增加——只是正确使用了 Prisma 的 `include` 和数据库索引。

## 问题二：安全扫描报告漏洞

安全扫描工具（比如 `npm audit`、OWASP ZAP）常见报告：

### 漏洞 1：CORS 配置过松

```js
// 危险：允许任何来源
app.use(cors())  // 等于 cors({ origin: '*' })

// 正确：只允许你的前端域名
app.use(cors({
  origin: ['https://yourblog.com', 'http://localhost:5173'],
  credentials: true,
}))
```

### 漏洞 2：缺少安全头

用 Helmet 一行搞定：

```bash
npm install helmet
```

```js
const helmet = require('helmet')
app.use(helmet())
```

Helmet 会自动设置这些 HTTP 头：
- `X-Content-Type-Options: nosniff` —— 防止浏览器猜测 MIME 类型
- `X-Frame-Options: DENY` —— 防止被嵌入 iframe
- `Strict-Transport-Security` —— 强制 HTTPS
- `X-XSS-Protection` —— XSS 过滤

### 漏洞 3：用户输入未消毒

用户提交的内容如果直接渲染到页面，会有 XSS 风险。在 API 层，主要做两件事：

```js
// 1. 用 Zod 严格限制输入格式
const createPostSchema = z.object({
  title: z.string().max(200),
  content: z.string().max(50000),
  // 不允许额外字段
}).strict()

// 2. 存储时不要信任任何用户输入
// 数据库里存原始内容，渲染时由前端做转义
// 如果必须在后端消毒：
const sanitizeHtml = require('sanitize-html')
const cleanContent = sanitizeHtml(userInput, {
  allowedTags: ['b', 'i', 'em', 'strong', 'a', 'p', 'br'],
  allowedAttributes: { 'a': ['href'] },
})
```

### 漏洞 4：日志泄露敏感信息

```js
// 错误：日志里打了密码
console.log('登录请求:', req.body)
// → { email: 'test@test.com', password: '123456' }

// 正确：过滤敏感字段
function sanitizeLog(body) {
  const { password, token, ...rest } = body
  return rest
}
console.log('登录请求:', sanitizeLog(req.body))
```

### 漏洞 5：依赖库已知漏洞

```bash
npm audit
npm audit fix
```

`npm audit fix` 能自动修复的就自动修复。不能的，需要手动升级或寻找替代库。别忽略它——攻击者也在用同样的工具扫描你的 `package-lock.json`。

## 响应压缩

安装压缩中间件，减少传输体积：

```bash
npm install compression
```

```js
const compression = require('compression')
app.use(compression({
  threshold: 1024,  // 大于 1KB 的响应才压缩
}))
```

对于 JSON 响应，压缩通常能减少 60-80% 的体积。代价是 CPU 要做压缩计算——在 I/O 密集型的 Node.js 应用里，这个代价通常可以接受。

## 集群模式：利用多核 CPU

Node.js 是单线程的，一个进程只能用一个 CPU 核心。如果你的服务器有 4 核，用 PM2 的集群模式可以启动 4 个进程：

```bash
npm install -g pm2
pm2 start src/server.js -i max  --name blog-api
```

```
┌────┬──────────┬───────┬────────┬───────┬──────────┐
│ id │ name     │ mode  │ status │ cpu   │ memory   │
├────┼──────────┼───────┼────────┼───────┼──────────┤
│ 0  │ blog-api │ cluster │ online │ 0%   │ 45 MB    │
│ 1  │ blog-api │ cluster │ online │ 0%   │ 42 MB    │
│ 2  │ blog-api │ cluster │ online │ 0%   │ 43 MB    │
│ 3  │ blog-api │ cluster │ online │ 0%   │ 44 MB    │
└────┴──────────┴───────┴────────┴───────┴──────────┘
```

PM2 会自动在进程间做负载均衡。但要注意：内存缓存（比如 `Map`、`global.__prisma`）在进程间不共享。如果用了进程内缓存，需要换成 Redis。

2. `GET /api/posts/:id`（单篇文章）
3. `POST /api/auth/login`（登录）

记录修复前后的 RPS 和平均延迟。

### 练习三：实现输入消毒

给 `POST /api/posts` 的 `content` 字段加 HTML 消毒：只允许基础的格式标签（`<b>`、`<i>`、`<p>`、`<a>`），不允许 `<script>`、`<iframe>` 等危险标签。

## 参考答案

### 练习一

在 Prisma 日志里，如果你看到一个请求触发了多条 SQL，那就是 N+1。修复方式是在 `findMany` 里加 `include`。常见位置：文章列表（要带作者信息）、评论列表（要带评论者信息）。

### 练习三

```js
const sanitizeHtml = require('sanitize-html')

function sanitizeContent(html) {
  return sanitizeHtml(html, {
    allowedTags: ['b', 'i', 'em', 'strong', 'a', 'p', 'br', 'ul', 'ol', 'li', 'code', 'pre'],
    allowedAttributes: { 'a': ['href', 'target'] },
  })
}

// 在创建/更新文章时调用
router.post('/', authenticate, validate(createPostSchema), async (req, res, next) => {
  const data = { ...req.body, content: sanitizeContent(req.body.content) }
  const post = await postRepository.create(data)
  res.status(201).json({ success: true, data: post })
})
```
