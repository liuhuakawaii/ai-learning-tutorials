# 第5课：数据字典设计

> **课程定位**：学会设计数据字典，让数据可理解、可维护、可追溯
> **前置知识**：第4课（数据采集协议）
> **预计时长**：45 分钟

---

## 场景引入

你接手了一个数据项目，打开数据库一看，字段名全是缩写：`amt`、`dt`、`st`、`tp`。问了三个人才知道 `amt` 是金额（单位是分还是元？）、`dt` 是日期（格式是 YYYY-MM-DD 还是 YYYYMMDD？）、`st` 是状态（0 和 1 分别代表什么？）。你花了两天时间才搞清楚这些字段的含义，而这些信息本来应该在项目第一天就写成数据字典。没有数据字典，每个新人加入团队都要重复这个痛苦的过程。

---

## 学习目标

完成本课学习后，你将能够：

1. 理解数据字典的作用和重要性
2. 为每个字段定义完整的元数据
3. 设计一份规范的数据字典文档
4. 处理字段类型、单位、枚举值等常见问题
5. 建立数据字典的维护机制

## 一、什么是数据字典？

### 1.1 从一个反面案例说起

```
场景：小王拿到一份数据文件，字段名是这样的：

columns = ["id", "name", "price", "date", "status", "type"]

问题：
├── price 是美元还是人民币？
├── date 是订单日期还是发货日期？格式是什么？
├── status 的 0、1、2 分别代表什么？
├── type 的 A、B、C 是什么意思？
└── id 是自增主键还是业务 ID？

没有数据字典，这些都要猜或者问原作者。
```

### 1.2 数据字典的定义

**数据字典**是描述数据字段含义、类型、单位、来源等元信息的文档。

```
┌──────────────────────────────────────────────────────────────┐
│                    数据字典的作用                              │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  对开发者：                                                   │
│  ├── 快速理解字段含义                                        │
│  ├── 正确使用数据类型                                        │
│  └── 避免误解导致的 bug                                      │
│                                                              │
│  对业务人员：                                                 │
│  ├── 理解指标计算逻辑                                        │
│  ├── 确认数据口径                                            │
│  └── 便于沟通和对齐                                          │
│                                                              │
│  对数据产品：                                                 │
│  ├── 展示字段说明                                            │
│  ├── 提供单位信息                                            │
│  └── 支持数据校验                                            │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## 三、常见字段类型设计

### 3.1 字符串类型

```
┌──────────────────────────────────────────────────────────────┐
│                    字符串类型选择                              │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  VARCHAR(n)                                                   │
│  ├── 用途：长度可变的短文本                                   │
│  ├── 示例：名称、标题、编码                                  │
│  └── 注意：n 是最大长度，实际存储按需分配                     │
│                                                              │
│  TEXT                                                          │
│  ├── 用途：长文本内容                                        │
│  ├── 示例：描述、文章内容、备注                              │
│  └── 注意：不能建索引（或索引需指定长度）                     │
│                                                              │
│  ENUM                                                          │
│  ├── 用途：固定的枚举值                                      │
│  ├── 示例：状态、类型、等级                                  │
│  └── 注意：修改枚举需要 ALTER TABLE                          │
│                                                              │
│  建议：                                                       │
│  ├── 短文本用 VARCHAR(50) ~ VARCHAR(500)                     │
│  ├── 长文本用 TEXT                                           │
│  └── 固定值用 VARCHAR + 枚举值说明                           │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

from dataclasses import dataclass
from typing import Optional
from datetime import date, datetime
from decimal import Decimal

@dataclass
class JobData:

    # 基本信息

    salary_max: Decimal = Decimal("0")   # 最高薪资

    # 要求信息

### 6.3 自动化验证

```python
def validate_data_against_dict(data: dict, schema: dict) -> list:
    """根据数据字典验证数据"""
    errors = []
    
    for field_name, field_schema in schema.items():
        value = data.get(field_name)
        
        # 检查必填字段
        if not field_schema.get("nullable", True) and value is None:
            errors.append(f"字段 {field_name} 不能为空")
            continue
        
        if value is None:
            continue
        
        # 检查枚举值
        enum_values = field_schema.get("enum")
        if enum_values and value not in enum_values:
            errors.append(f"字段 {field_name} 值 '{value}' 不在枚举范围内: {enum_values}")
        
        # 检查数值范围
        if "min" in field_schema and value < field_schema["min"]:
            errors.append(f"字段 {field_name} 值 {value} 小于最小值 {field_schema['min']}")
        
        if "max" in field_schema and value > field_schema["max"]:
            errors.append(f"字段 {field_name} 值 {value} 大于最大值 {field_schema['max']}")
    
    return errors

# 使用示例
job_schema = {
    "city": {"type": "string", "nullable": False},
    "experience": {"type": "string", "enum": ["1-3年", "3-5年", "5-10年", "不限"]},
    "salary_min": {"type": "decimal", "min": 0, "max": 1000000},
}

job_data = {"city": "北京", "experience": "3年", "salary_min": -1000}
errors = validate_data_against_dict(job_data, job_schema)
# ['字段 experience 值 \'3年\' 不在枚举范围内', '字段 salary_min 值 -1000 小于最小值 0']
```

### 7.1 在 Dashboard 中展示字段说明

```typescript
// 前端组件中使用数据字典
interface FieldMeta {
  name: string;
  label: string;
  type: string;
  unit?: string;
  description?: string;
}

const fieldMetas: Record<string, FieldMeta> = {
  salary_avg: {
    name: "salary_avg",
    label: "平均薪资",
    type: "decimal",
    unit: "元/月",
    description: "岗位薪资范围的中位数"
  },
  job_count: {
    name: "job_count",
    label: "岗位数量",
    type: "integer",
    unit: "个",
    description: "符合条件的岗位总数"
  }
};

// 展示时带上单位
function formatValue(fieldName: string, value: number): string {
  const meta = fieldMetas[fieldName];
  if (meta?.unit) {
    return `${value.toLocaleString()} ${meta.unit}`;
  }
  return value.toLocaleString();
}

// 结果："27,500 元/月"
formatValue("salary_avg", 27500);
```

## 常见误区

- **数据字典是"一次性文档"**：很多人在项目初期写一份数据字典，之后再也没更新过。字段加了、类型改了、枚举值变了，字典还是旧的。过时的字典比没有字典更危险，因为它会误导人。
- **枚举值只写当前用到的**：设计 `status` 字段时只列了 `0:下架, 1:上架`，后来业务加了"预售"状态，但字典里没有记录，新人拿到数据看到 `2` 完全不知道什么意思。枚举值要预留扩展空间。
- **过度设计数据字典**：字段只有 5 个的临时分析表，不需要写一份包含 20 列元数据的完整字典。字典的详细程度应该匹配项目的规模和生命周期。
- **忽略示例值的作用**：只写字段名和类型，不给示例。新人看到 `experience: VARCHAR(50)` 还是不知道该填"3-5年"还是"3~5年"还是"3到5年"。示例值能消除歧义。

---

## 工程建议

- **数据字典和代码放在一起管理**：把字典放在项目的 `docs/` 目录下，纳入 Git 版本控制。字段变更时同步更新字典，就像更新代码一样自然。
- **用自动化脚本校验字典一致性**：写一个脚本，对比数据库实际字段和数据字典定义，检查类型、是否可空、枚举值是否匹配。定期运行，发现问题及时修复。
- **枚举值用代码定义而非数据库 ENUM**：数据库 ENUM 类型修改需要 ALTER TABLE，成本高且有锁表风险。用 VARCHAR 存储值，用代码（Python Enum 或常量字典）定义可选值和含义，更灵活。
- **在 API 文档中嵌入数据字典信息**：用 Pydantic 的 `Field(description=..., examples=...)` 或 FastAPI 的自动生成文档，让用户在查 API 时就能看到字段说明，不需要另外找字典文档。

## 小结

本课的核心要点：

1. **数据字典**是描述字段元信息的文档，让数据可理解
2. **字段元数据**包含：名称、类型、单位、枚举值、来源、示例
3. **类型选择**要根据实际需求：字符串、数值、日期、布尔
4. **枚举值**要明确列出所有可选值
5. **维护原则**：同步更新、版本管理、变更记录、定期审查

### 练习三

**思路**：根据 schema 定义逐项验证每条数据——检查必填字段、枚举值、数值范围。

**答案**：

```python
from typing import Any

def validate_data(data: dict, schema: dict) -> list:
    """根据数据字典验证单条数据"""
    errors = []

    for field_name, rules in schema.items():
        value = data.get(field_name)

        # 1. 必填字段检查
        if not rules.get("nullable", True) and (value is None or value == ""):
            errors.append(f"字段 '{field_name}' 不能为空")
            continue

        if value is None:
            continue

        # 2. 类型检查
        expected_type = rules.get("type")
        if expected_type == "string" and not isinstance(value, str):
            errors.append(f"字段 '{field_name}' 应为字符串，实际为 {type(value).__name__}")
        elif expected_type == "integer" and not isinstance(value, int):
            errors.append(f"字段 '{field_name}' 应为整数，实际为 {type(value).__name__}")
        elif expected_type == "decimal" and not isinstance(value, (int, float)):
            errors.append(f"字段 '{field_name}' 应为数值，实际为 {type(value).__name__}")

        # 3. 字符串长度检查
        if "max_length" in rules and isinstance(value, str):
            if len(value) > rules["max_length"]:
                errors.append(
                    f"字段 '{field_name}' 长度 {len(value)} 超过最大值 {rules['max_length']}"
                )

        # 4. 枚举值检查
        if "enum" in rules and value not in rules["enum"]:
            errors.append(
                f"字段 '{field_name}' 值 '{value}' 不在允许范围内: {rules['enum']}"
            )

        # 5. 数值范围检查
        if isinstance(value, (int, float)):
            if "min" in rules and value < rules["min"]:
                errors.append(
                    f"字段 '{field_name}' 值 {value} 小于最小值 {rules['min']}"
                )
            if "max" in rules and value > rules["max"]:
                errors.append(
                    f"字段 '{field_name}' 值 {value} 大于最大值 {rules['max']}"
                )

    return errors


# 数据字典定义
schema = {
    "product_name": {"type": "string", "nullable": False, "max_length": 200},
    "price": {"type": "decimal", "min": 0, "max": 999999},
    "status": {"type": "string", "enum": ["active", "inactive", "deleted"]},
    "stock": {"type": "integer", "min": 0}
}

# 测试数据
test_data = [
    {"product_name": "iPhone", "price": 7999, "status": "active", "stock": 100},
    {"product_name": "", "price": -100, "status": "unknown", "stock": -1},
]

# 执行验证
for i, item in enumerate(test_data):
    errors = validate_data(item, schema)
    if errors:
        print(f"第 {i + 1} 条数据有 {len(errors)} 个错误：")
        for error in errors:
            print(f"  - {error}")
    else:
        print(f"第 {i + 1} 条数据验证通过")
```

- 验证顺序很重要——先检查必填，字段为空时跳过后续检查
