周一早上你打开 Dashboard，发现上周五的招聘数据采集任务失败了，整个周末的数据都是空的。没有人知道——因为没有告警。你补数据补了一上午，然后下定决心：必须给系统加上告警机制。但告警怎么设计？任务失败要告警，数据量异常要不要告警？告警发到哪里？发多了大家会忽略，发少了又会漏掉关键问题。

## 二、告警规则实现

```python
from dataclasses import dataclass
from typing import Callable, Any

@dataclass
class AlertRule:
    """告警规则"""
    name: str
    condition: Callable[[dict], bool]
    severity: str  # info, warning, critical
    message_template: str

class AlertManager:
    """告警管理器"""
    
    def __init__(self):
        self.rules = []
        self.notifiers = []
    
    def add_rule(self, rule: AlertRule):
        self.rules.append(rule)
    
    def check(self, metrics: dict):
        """检查告警"""
        for rule in self.rules:
            if rule.condition(metrics):
                self.send_alert(rule, metrics)
    
    def send_alert(self, rule: AlertRule, metrics: dict):
        """发送告警"""
        message = rule.message_template.format(**metrics)
        for notifier in self.notifiers:
            notifier.send(message, rule.severity)

# 定义告警规则
alert_manager = AlertManager()

# 任务失败告警
alert_manager.add_rule(AlertRule(
    name="task_failed",
    condition=lambda m: m.get("task_status") == "failed",
    severity="critical",
    message_template="任务 {task_id} 执行失败: {error}"
))

# 数据量异常告警
alert_manager.add_rule(AlertRule(
    name="data_volume_anomaly",
    condition=lambda m: m.get("record_count", 0) < m.get("expected_count", 100) * 0.5,
    severity="warning",
    message_template="数据量异常: 期望 {expected_count}，实际 {record_count}"
))
```

## 常见误区

- **告警发太多**：把每个日志都当告警发，团队很快会产生"告警疲劳"，真正的问题被淹没在噪音里。告警应该是需要人介入的异常，不是普通日志。
- **告警只看任务失败**：任务成功了但数据量只有平时的 1%，这种情况比任务失败更危险——因为表面上"没问题"。数据质量告警同样重要。
- **告警没有分级**：所有告警都发到同一个渠道、用同样的紧急程度，导致无法区分"需要立即处理"和"明天看看就行"。
- **告警规则写死在代码里**：每次调整告警阈值都要改代码、重新部署。应该把规则配置化，支持动态调整。

---

## 工程建议

1. **告警分级对应响应时效**：`critical` 立即通知（电话/短信），`warning` 10 分钟内通知（钉钉/Slack），`info` 每日汇总（邮件）。分级能让团队建立正确的响应预期。
2. **设置告警静默期**：同一个告警在 N 分钟内只触发一次，避免因持续异常导致的消息轰炸。
3. **告警消息要可操作**：不要只写"任务失败了"，要包含任务 ID、失败原因、影响范围和建议操作，让收到告警的人能快速定位问题。
4. **定期回顾告警有效性**：每月检查一次告警规则，删掉从未触发的（可能条件写错了），调整频繁触发但没人处理的（可能阈值不合理）。

## 参考答案

### 练习一

**思路**：设计三类告警规则——任务告警、数据质量告警、系统告警。每类包含多个具体规则，用 `AlertRule` dataclass 定义条件函数、严重级别和消息模板。告警管理器统一检查所有规则，支持静默期防止消息轰炸。

**答案**：

```python
from dataclasses import dataclass, field
from typing import Callable
from datetime import datetime, timedelta

@dataclass
class AlertRule:
    name: str
    condition: Callable[[dict], bool]
    severity: str
    message_template: str
    cooldown_minutes: int = 5

class AlertManager:
    def __init__(self):
        self.rules: list[AlertRule] = []
        self.notifiers = []
        self._last_triggered: dict[str, datetime] = {}

    def add_rule(self, rule: AlertRule):
        self.rules.append(rule)

    def add_notifier(self, notifier):
        self.notifiers.append(notifier)

    def check(self, metrics: dict):
        for rule in self.rules:
            if not rule.condition(metrics):
                continue
            last = self._last_triggered.get(rule.name)
            if last and datetime.now() - last < timedelta(minutes=rule.cooldown_minutes):
                continue
            message = rule.message_template.format(**metrics)
            for notifier in self.notifiers:
                notifier.send(message, rule.severity)
            self._last_triggered[rule.name] = datetime.now()

alert_manager = AlertManager()

# ── 任务告警 ──
alert_manager.add_rule(AlertRule(
    name="task_failed",
    condition=lambda m: m.get("task_status") == "failed",
    severity="critical",
    message_template="🔴 任务 {task_id} 执行失败: {error}",
    cooldown_minutes=0,
))

alert_manager.add_rule(AlertRule(
    name="task_timeout",
    condition=lambda m: m.get("duration_sec", 0) > m.get("timeout_sec", 3600),
    severity="warning",
    message_template="⚠️ 任务 {task_id} 执行超时，已运行 {duration_sec}s，阈值 {timeout_sec}s",
))

alert_manager.add_rule(AlertRule(
    name="task_retry_exhausted",
    condition=lambda m: m.get("retry_count", 0) >= 3,
    severity="critical",
    message_template="🔴 任务 {task_id} 重试次数耗尽 ({retry_count}次)，需人工介入",
))

# ── 数据质量告警 ──
alert_manager.add_rule(AlertRule(
    name="data_volume_drop",
    condition=lambda m: m.get("record_count", 0) < m.get("expected_count", 100) * 0.5,
    severity="warning",
    message_template="⚠️ 数据量异常下降: 期望 {expected_count} 条，实际 {record_count} 条",
))

alert_manager.add_rule(AlertRule(
    name="data_volume_spike",
    condition=lambda m: m.get("record_count", 0) > m.get("expected_count", 100) * 3,
    severity="warning",
    message_template="⚠️ 数据量异常激增: 期望 {expected_count} 条，实际 {record_count} 条，可能存在重复采集",
))

alert_manager.add_rule(AlertRule(
    name="quality_failures_high",
    condition=lambda m: m.get("quality_fail_rate", 0) > 0.1,
    severity="critical",
    message_template="🔴 数据质量规则失败率过高: {quality_fail_rate:.1%}，超过 10% 阈值",
))

# ── 系统告警 ──
alert_manager.add_rule(AlertRule(
    name="db_connection_failed",
    condition=lambda m: m.get("db_connected") is False,
    severity="critical",
    message_template="🔴 数据库连接失败: {db_error}",
    cooldown_minutes=0,
))

alert_manager.add_rule(AlertRule(
    name="api_slow_response",
    condition=lambda m: m.get("api_response_ms", 0) > 5000,
    severity="warning",
    message_template="⚠️ API 响应缓慢: {api_response_ms}ms，超过 5000ms 阈值",
))

alert_manager.add_rule(AlertRule(
    name="disk_space_low",
    condition=lambda m: m.get("disk_usage_percent", 0) > 90,
    severity="critical",
    message_template="🔴 磁盘空间不足: 已使用 {disk_usage_percent}%，请及时清理",
))

# 使用示例
alert_manager.check({
    "task_id": "crawl_001",
    "task_status": "failed",
    "error": "连接超时",
    "record_count": 30,
    "expected_count": 100,
    "db_connected": True,
    "disk_usage_percent": 95,
})
```

**要点**：
- 每条规则都有 `cooldown_minutes` 静默期，避免持续异常导致消息轰炸
- 三类告警覆盖了实际场景中最常见的问题：任务本身出错、数据质量异常、基础设施故障
- 条件函数用 lambda 实现，支持复杂的阈值比较和多字段组合判断

### 练习二

**思路**：实现钉钉和 Slack 的 Webhook 通知器，继承 `Notifier` 基类。钉钉使用自定义机器人 Webhook，Slack 使用 Incoming Webhook。两者都是发送 HTTP POST 请求，区别在于请求体格式不同。

**答案**：

```python
import json
import hmac
import hashlib
import base64
import time
import urllib.parse
from abc import ABC, abstractmethod
import requests

class Notifier(ABC):
    @abstractmethod
    def send(self, message: str, severity: str):
        pass

class DingTalkNotifier(Notifier):
    """钉钉机器人通知"""

    SEVERITY_EMOJI = {"info": "ℹ️", "warning": "⚠️", "critical": "🔴"}

    def __init__(self, webhook_url: str, secret: str = None):
        self.webhook_url = webhook_url
        self.secret = secret

    def _sign_url(self) -> str:
        if not self.secret:
            return self.webhook_url
        timestamp = str(round(time.time() * 1000))
        string_to_sign = f"{timestamp}\n{self.secret}"
        hmac_code = hmac.new(
            self.secret.encode("utf-8"),
            string_to_sign.encode("utf-8"),
            digestmod=hashlib.sha256,
        ).digest()
        sign = urllib.parse.quote_plus(base64.b64encode(hmac_code))
        return f"{self.webhook_url}&timestamp={timestamp}&sign={sign}"

    def send(self, message: str, severity: str):
        emoji = self.SEVERITY_EMOJI.get(severity, "")
        payload = {
            "msgtype": "markdown",
            "markdown": {
                "title": f"{emoji} 数据产品告警",
                "text": f"### {emoji} 告警通知\n\n**级别**: {severity}\n\n{message}\n\n---\n*来自数据产品告警系统*",
            },
        }
        url = self._sign_url()
        resp = requests.post(url, json=payload, timeout=10)
        resp.raise_for_status()
        result = resp.json()
        if result.get("errcode") != 0:
            print(f"钉钉发送失败: {result}")

class SlackNotifier(Notifier):
    """Slack Incoming Webhook 通知"""

    SEVERITY_COLOR = {"info": "#36a64f", "warning": "#ff9900", "critical": "#ff0000"}

    def __init__(self, webhook_url: str):
        self.webhook_url = webhook_url

    def send(self, message: str, severity: str):
        color = self.SEVERITY_COLOR.get(severity, "#cccccc")
        payload = {
            "attachments": [
                {
                    "color": color,
                    "title": f"数据产品告警 [{severity.upper()}]",
                    "text": message,
                    "footer": "数据产品告警系统",
                    "ts": int(time.time()),
                }
            ]
        }
        resp = requests.post(self.webhook_url, json=payload, timeout=10)
        resp.raise_for_status()

# 注册通知器
dingtalk = DingTalkNotifier(
    webhook_url="https://oapi.dingtalk.com/robot/send?access_token=YOUR_TOKEN",
    secret="SEC_YOUR_SECRET",
)
slack = SlackNotifier(
    webhook_url="https://hooks.slack.com/services/T00/B00/XXXX",
)

alert_manager.add_notifier(dingtalk)
alert_manager.add_notifier(slack)

# 触发告警检查
alert_manager.check({
    "task_id": "crawl_002",
    "task_status": "failed",
    "error": "目标网站返回 403",
})
```

**要点**：
- 钉钉机器人支持签名验证（加签模式），通过 HMAC-SHA256 生成签名参数，防止 Webhook 被滥用
- Slack 使用 `attachments` 格式，通过 `color` 字段区分告警级别，视觉上更直观
- 两个通知器都设置了 10 秒超时，避免告警发送阻塞主流程
