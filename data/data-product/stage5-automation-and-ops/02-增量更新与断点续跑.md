## 一、增量更新

### 1.1 增量策略

```
┌──────────────────────────────────────────────────────────────┐
│                    增量更新策略                                │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  时间戳增量                                                   │
│  ├── 记录上次更新时间                                        │
│  ├── 只获取新数据                                            │
│  └── 适用：有时间字段的数据                                  │
│                                                              │
│  ID 增量                                                      │
│  ├── 记录上次最大 ID                                         │
│  ├── 只获取 ID > last_id 的数据                              │
│  └── 适用：自增 ID 的数据                                    │
│                                                              │
│  状态增量                                                     │
│  ├── 标记已处理的数据                                        │
│  ├── 只处理未标记的数据                                      │
│  └── 适用：需要批量处理的场景                                │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 1.2 实现代码

```python
class IncrementalUpdater:
    """增量更新器"""
    
    def __init__(self, engine):
        self.engine = engine
    
    def get_last_update_time(self, source: str) -> datetime:
        """获取上次更新时间"""
        query = """
            SELECT MAX(crawl_time) as last_time
            FROM raw_jobs
            WHERE source = :source
        """
        with self.engine.connect() as conn:
            result = conn.execute(text(query), {"source": source}).fetchone()
            return result[0] if result[0] else datetime.min
    
    def incremental_crawl(self, source: str):
        """增量采集"""
        last_time = self.get_last_update_time(source)
        
        # 只采集新数据
        new_data = crawl_since(last_time)
        
        if new_data:
            save_to_database(new_data)
        
        return len(new_data)
```

## 二、断点续跑

### 2.1 设计思路

```
┌──────────────────────────────────────────────────────────────┐
│                    断点续跑                                    │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  1. 记录进度                                                  │
│     ├── 已处理的页码                                         │
│     ├── 已处理的 ID 范围                                     │
│     └── 保存到数据库或文件                                   │
│                                                              │
│  2. 恢复执行                                                  │
│     ├── 读取上次进度                                         │
│     ├── 从断点继续                                           │
│     └── 避免重复处理                                         │
│                                                              │
│  3. 处理失败                                                  │
│     ├── 记录失败位置                                         │
│     ├── 支持重试                                             │
│     └── 人工介入                                             │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 实现代码

```python
class CheckpointManager:
    """断点管理器"""
    
    def __init__(self, engine):
        self.engine = engine
    
    def save_checkpoint(self, task_id: str, checkpoint: dict):
        """保存断点"""
        query = """
            INSERT INTO task_checkpoint (task_id, checkpoint_data, updated_at)
            VALUES (:task_id, :data, NOW())
            ON CONFLICT (task_id)
            DO UPDATE SET checkpoint_data = :data, updated_at = NOW()
        """
        with self.engine.connect() as conn:
            conn.execute(text(query), {
                "task_id": task_id,
                "data": json.dumps(checkpoint)
            })
            conn.commit()
    
    def load_checkpoint(self, task_id: str) -> dict:
        """加载断点"""
        query = "SELECT checkpoint_data FROM task_checkpoint WHERE task_id = :task_id"
        with self.engine.connect() as conn:
            result = conn.execute(text(query), {"task_id": task_id}).fetchone()
            return json.loads(result[0]) if result else {}
```

## 常见误区

- **增量更新不需要校验**：增量采集的数据可能和已有数据存在冲突（如字段更新），必须有去重和合并逻辑，不能简单 INSERT。
- **断点保存太频繁**：每处理一条数据就写一次断点会严重影响性能。应该按批次（如每 100 条或每页）保存断点。
- **断点数据存在内存里**：进程一挂，断点就丢了。断点必须持久化到数据库或文件系统。
- **忽略时间精度问题**：用 `datetime.now()` 作为增量标记，可能因为时区、精度差异漏掉边界数据。建议用数据库的 `MAX(id)` 或 `MAX(updated_at)` 作为游标。

---

## 工程建议

1. **增量字段加索引**：不管是时间戳还是 ID，增量查询的 WHERE 条件字段必须有索引，否则数据量大了查询会很慢。
2. **断点与业务数据分离**：断点信息存在独立的 `task_checkpoint` 表，不要混在业务数据表里，方便管理和清理。
3. **设计补偿机制**：增量更新可能漏掉数据（如源端延迟写入），定期跑一次全量校验来兜底。
4. **断点续跑要支持幂等**：从断点恢复时，上一次中断那批数据可能已经部分写入，恢复逻辑需要能处理重复数据。

## 参考答案

### 练习一

**思路**：实现一个 `IncrementalCrawler` 类，基于时间戳增量策略。核心是先从数据库查出上次采集的最大时间戳，然后只请求该时间戳之后的新数据。采集完成后更新游标，并处理去重合并。

**答案**：

```python
from datetime import datetime
from sqlalchemy import text
import json

class IncrementalCrawler:
    """增量采集器"""

    def __init__(self, engine, source: str):
        self.engine = engine
        self.source = source

    def get_cursor(self) -> dict:
        """获取增量游标"""
        query = """
            SELECT last_crawl_time, last_id, total_crawled
            FROM crawl_cursor
            WHERE source = :source
        """
        with self.engine.connect() as conn:
            row = conn.execute(text(query), {"source": self.source}).fetchone()
            if row:
                return {"last_time": row[0], "last_id": row[1], "total": row[2]}
            return {"last_time": datetime.min, "last_id": 0, "total": 0}

    def update_cursor(self, last_time: datetime, last_id: int, new_count: int):
        """更新增量游标"""
        query = """
            INSERT INTO crawl_cursor (source, last_crawl_time, last_id, total_crawled, updated_at)
            VALUES (:source, :last_time, :last_id, :total, NOW())
            ON CONFLICT (source)
            DO UPDATE SET
                last_crawl_time = GREATEST(crawl_cursor.last_crawl_time, :last_time),
                last_id = GREATEST(crawl_cursor.last_id, :last_id),
                total_crawled = crawl_cursor.total_crawled + :new_count,
                updated_at = NOW()
        """
        with self.engine.connect() as conn:
            conn.execute(text(query), {
                "source": self.source,
                "last_time": last_time,
                "last_id": last_id,
                "total": new_count,
            })
            conn.commit()

    def crawl_incremental(self) -> int:
        """执行增量采集，返回新增条数"""
        cursor = self.get_cursor()
        last_time = cursor["last_time"]

        new_data = fetch_jobs_since(self.source, last_time)

        if not new_data:
            return 0

        new_data = self.deduplicate(new_data)
        save_to_database(new_data)

        max_time = max(item["crawl_time"] for item in new_data)
        max_id = max(item["id"] for item in new_data)
        self.update_cursor(max_time, max_id, len(new_data))

        return len(new_data)

    def deduplicate(self, data: list) -> list:
        """基于唯一键去重"""
        query = "SELECT job_id FROM raw_jobs WHERE job_id IN :ids AND source = :source"
        existing_ids = set()
        with self.engine.connect() as conn:
            ids = tuple(item["job_id"] for item in data)
            if ids:
                rows = conn.execute(text(query), {"ids": ids, "source": self.source}).fetchall()
                existing_ids = {row[0] for row in rows}
        return [item for item in data if item["job_id"] not in existing_ids]

# 使用示例
crawler = IncrementalCrawler(engine, source="boss")
new_count = crawler.crawl_incremental()
print(f"增量采集完成，新增 {new_count} 条")
```

**要点**：
- 游标用 `GREATEST` 确保只前进不后退，防止异常数据导致游标回退漏采
- 去重逻辑在入库前执行，先查数据库已有 ID，过滤掉已存在的记录
- 游标和业务数据分离存储在 `crawl_cursor` 表，不污染业务表

### 练习二

**思路**：实现 `ResumableRunner` 类，按批次处理数据，每完成一批就保存断点。任务中断后重新启动时，先读取断点，跳过已处理的批次，从上次中断位置继续。

**答案**：

```python
import json
from datetime import datetime
from sqlalchemy import text

class ResumableRunner:
    """支持断点续跑的任务执行器"""

    def __init__(self, engine, task_id: str, batch_size: int = 100):
        self.engine = engine
        self.task_id = task_id
        self.batch_size = batch_size

    def get_checkpoint(self) -> dict:
        """读取断点"""
        query = "SELECT checkpoint_data FROM task_checkpoint WHERE task_id = :task_id"
        with self.engine.connect() as conn:
            row = conn.execute(text(query), {"task_id": self.task_id}).fetchone()
            return json.loads(row[0]) if row else {}

    def save_checkpoint(self, checkpoint: dict):
        """保存断点"""
        query = """
            INSERT INTO task_checkpoint (task_id, checkpoint_data, updated_at)
            VALUES (:task_id, :data, NOW())
            ON CONFLICT (task_id)
            DO UPDATE SET checkpoint_data = :data, updated_at = NOW()
        """
        with self.engine.connect() as conn:
            conn.execute(text(query), {
                "task_id": self.task_id,
                "data": json.dumps(checkpoint, ensure_ascii=False),
            })
            conn.commit()

    def run(self, items: list, process_fn):
        """执行任务，支持断点续跑"""
        checkpoint = self.get_checkpoint()
        start_index = checkpoint.get("last_index", 0)
        processed = checkpoint.get("processed_count", 0)
        failed_items = checkpoint.get("failed_items", [])

        print(f"[{self.task_id}] 从索引 {start_index} 恢复，已处理 {processed} 条")

        for batch_start in range(start_index, len(items), self.batch_size):
            batch = items[batch_start: batch_start + self.batch_size]
            batch_failed = []

            for i, item in enumerate(batch):
                try:
                    process_fn(item)
                    processed += 1
                except Exception as e:
                    batch_failed.append({"index": batch_start + i, "error": str(e)})
                    print(f"[{self.task_id}] 处理失败 {batch_start + i}: {e}")

            self.save_checkpoint({
                "last_index": batch_start + len(batch),
                "processed_count": processed,
                "failed_items": failed_items + batch_failed,
                "updated_at": datetime.now().isoformat(),
            })

            print(f"[{self.task_id}] 批次 {batch_start}-{batch_start + len(batch)} 完成")

        return {"processed": processed, "failed": len(failed_items)}

# 建表 SQL
CHECKPOINT_TABLE_SQL = """
CREATE TABLE IF NOT EXISTS task_checkpoint (
    task_id         VARCHAR(100) PRIMARY KEY,
    checkpoint_data JSONB NOT NULL,
    updated_at      TIMESTAMP DEFAULT NOW()
);
"""

# 使用示例
def process_job(job):
    """处理单条招聘数据"""
    cleaned = clean_job_data(job)
    save_to_database(cleaned)

all_jobs = fetch_all_pending_jobs()
runner = ResumableRunner(engine, task_id="crawl_boss_20240115", batch_size=100)
result = runner.run(all_jobs, process_job)
print(f"处理完成: 成功 {result['processed']}，失败 {result['failed']}")
```

**要点**：
- 断点按批次保存而非逐条保存，避免频繁 IO 拖慢性能
- 断点数据用 JSON 格式存储，可扩展（如添加 `failed_items`、`updated_at` 等字段）
- 恢复时从 `last_index` 开始跳过已处理数据，但 `process_fn` 需要保证幂等性，因为中断那批数据可能部分已入库
