> **前置知识**：第四阶段全部课程
> **预计时长**：50 分钟

---

## 你生病了，数据断了

你负责的数据产品每天早上 8 点需要跑 ETL 管道：采集招聘数据、清洗入库、更新 Dashboard。目前都是你手动在终端里敲命令。某天你请假了，第二天回来发现：昨天的数据更新断了，Dashboard 停在前天，老板在群里问"数据怎么不对"。

数据产品如果依赖人工触发，就永远无法真正"上线"。你需要定时任务系统，让管道在无人值守的情况下自动运行，同时保留手动触发的能力。

---

## 方案选型：不是越强越好

**cron**（系统级）——零依赖、稳定可靠，但没有重试、没有状态追踪、日志只能写文件。适合"每天跑一次脚本"。

**APScheduler**（Python 库）——进程内调度，支持 cron 表达式和间隔触发，直接调用项目代码。缺点是调度器和应用耦合，进程挂了任务就停。适合单体 Python 应用。

**Celery**（分布式）——任务通过消息队列分发到 worker，支持分布式、重试、优先级。缺点是架构复杂，需要额外维护 Redis/RabbitMQ。适合大型项目。

**GitHub Actions**——免费、无需运维，但有 6 小时运行时间限制。适合开源项目或轻量采集。

判断标准：单体 Python 应用用 APScheduler，Docker + 微服务考虑 Celery，每天跑一个脚本用 cron。过早引入 Celery 是常见错误——花一周配置 Redis、worker、beat，最后发现每天只跑两个任务。

## APScheduler 基础用法

```python
from apscheduler.schedulers.background import BackgroundScheduler
from apscheduler.triggers.cron import CronTrigger
from apscheduler.triggers.interval import IntervalTrigger
from datetime import datetime

scheduler = BackgroundScheduler(timezone="Asia/Shanghai")

def crawl_jobs():
    print(f"[{datetime.now()}] 开始全量采集...")
    pipeline.run()

def incremental_update():
    print(f"[{datetime.now()}] 开始增量更新...")
    incremental_pipeline.run()

scheduler.add_job(crawl_jobs, CronTrigger(hour=8, minute=0),
    id="daily_crawl", name="每日全量采集", replace_existing=True, max_instances=1)

scheduler.add_job(incremental_update, IntervalTrigger(hours=1),
    id="hourly_incremental", name="每小时增量更新", replace_existing=True, max_instances=1)

scheduler.start()
```

需要注意的坑：

**时区**。APScheduler 默认 UTC，`CronTrigger(hour=8)` 在北京时间下午 4 点才执行。必须显式设置 `timezone="Asia/Shanghai"`。

**进程生命周期**。`BackgroundScheduler` 依附主进程，FastAPI 重启后调度器也重启。用 `lifespan` 事件在启动时注册任务。

**任务重叠**。增量更新需要 2 小时但间隔设 1 小时，会出现重叠。`max_instances=1` 会跳过重叠任务。

## 手动触发：同一个执行入口

手动和定时触发调用同一个函数，区别只在 `trigger_type`：

```python
from fastapi import APIRouter, BackgroundTasks
import uuid

router = APIRouter()

def generate_task_id() -> str:
    return f"task_{uuid.uuid4().hex[:12]}"

def run_task(task_type: str, task_id: str, trigger_type: str):
    """统一执行入口——定时和手动都走这里"""
    try:
        save_task_log(task_id, task_type, "running", trigger_type)
        if task_type == "crawl":
            crawl_jobs()
        elif task_type == "incremental":
            incremental_update()
        save_task_log(task_id, task_type, "completed", trigger_type)
    except Exception as e:
        save_task_log(task_id, task_type, "failed", trigger_type, error=str(e))

@router.post("/tasks/trigger/{task_type}")
async def trigger_task(task_type: str, background_tasks: BackgroundTasks):
    if task_type not in ("crawl", "incremental"):
        return {"error": f"不支持的任务类型: {task_type}"}
    task_id = generate_task_id()
    background_tasks.add_task(run_task, task_type, task_id, "manual")
    return {"task_id": task_id, "status": "queued", "trigger": "manual"}
```

好处：行为一致、日志格式一致、排查问题时不需要关心是谁触发的。

## 任务状态管理

完整生命周期：`queued → running → completed / failed`

```sql
CREATE TABLE task_log (
    id              SERIAL PRIMARY KEY,
    task_id         VARCHAR(50) UNIQUE NOT NULL,
    task_type       VARCHAR(50) NOT NULL,
    status          VARCHAR(20) NOT NULL,
    trigger_type    VARCHAR(20) NOT NULL,  -- scheduled / manual
    start_time      TIMESTAMP,
    end_time        TIMESTAMP,
    duration_sec    FLOAT,
    error_message   TEXT,
    created_at      TIMESTAMP DEFAULT NOW()
);
CREATE INDEX idx_task_log_status ON task_log(status);
CREATE INDEX idx_task_log_created ON task_log(created_at DESC);
```

状态更新函数：

```python
from sqlalchemy import text
from datetime import datetime

def save_task_log(task_id, task_type, status, trigger_type, error=None):
    now = datetime.now()
    if status == "running":
        query = text("""INSERT INTO task_log (task_id, task_type, status, trigger_type, start_time)
            VALUES (:task_id, :task_type, :status, :trigger_type, :now)
            ON CONFLICT (task_id) DO UPDATE SET status = :status, start_time = :now""")
    elif status in ("completed", "failed"):
        query = text("""UPDATE task_log SET status = :status, end_time = :now,
            error_message = :error, duration_sec = EXTRACT(EPOCH FROM (:now - start_time))
            WHERE task_id = :task_id""")
    else:
        return
    db.execute(query, {"task_id": task_id, "task_type": task_type,
        "status": status, "trigger_type": trigger_type, "now": now, "error": error})
    db.commit()
```

查询接口：

```python
@router.get("/tasks/{task_id}")
async def get_task_status(task_id: str):
    row = db.execute(text("SELECT * FROM task_log WHERE task_id = :task_id"),
                     {"task_id": task_id}).fetchone()
    return dict(row._mapping) if row else {"error": "任务不存在"}

@router.get("/tasks")
async def list_tasks(status: str = None, limit: int = 20):
    if status:
        rows = db.execute(text("SELECT * FROM task_log WHERE status = :s ORDER BY created_at DESC LIMIT :l"),
                          {"s": status, "l": limit}).fetchall()
    else:
        rows = db.execute(text("SELECT * FROM task_log ORDER BY created_at DESC LIMIT :l"),
                          {"l": limit}).fetchall()
    return [dict(r._mapping) for r in rows]
```

## 超时控制

没有超时控制的定时任务是定时炸弹。APScheduler 的 `max_instances` 限制并发，`misfire_grace_time` 控制错过触发后的容忍窗口：

```python
scheduler.add_job(crawl_jobs, CronTrigger(hour=8, minute=0),
    id="daily_crawl", max_instances=1, misfire_grace_time=300)
```

超时控制在任务内部实现：

```python
import signal

class TaskTimeout(Exception): pass

def run_with_timeout(func, timeout_sec):
    def handler(signum, frame):
        raise TaskTimeout(f"超时: {timeout_sec}秒")
    old = signal.signal(signal.SIGALRM, handler)
    signal.alarm(timeout_sec)
    try:
        func()
    finally:
        signal.alarm(0)
        signal.signal(signal.SIGALRM, old)
```

## 常见误区

- **只用 cron 就够了**——没有重试、没有状态追踪，任务变复杂后维护成本急剧上升
- **手动触发不需要记录**——没有记录就无法追溯问题，也无法统计手动触发频率
- **所有逻辑写在一个任务里**——采集、清洗、聚合应该拆分，失败时可以单独重试
- **忽略时区**——APScheduler 默认 UTC，国内必须设 `timezone="Asia/Shanghai"`

### 练习二

```python
from fastapi import APIRouter
from sqlalchemy import text
from datetime import date

router = APIRouter()

@router.get("/tasks/stats")
async def get_task_stats():
    row = db.execute(text("""
        SELECT
            COUNT(*) FILTER (WHERE status = 'completed') AS completed,
            COUNT(*) FILTER (WHERE status = 'failed') AS failed,
            COUNT(*) FILTER (WHERE status = 'running') AS running
        FROM task_log WHERE created_at::date = :today
    """), {"today": date.today()}).fetchone()
    return dict(row._mapping)
```
