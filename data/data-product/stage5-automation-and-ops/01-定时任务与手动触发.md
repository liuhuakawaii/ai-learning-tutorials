## 场景引入

你负责的数据产品每天早上需要采集招聘网站数据、跑 ETL 管道、更新 Dashboard。目前这一切都是你手动在终端里敲命令完成的。某天你请假了，结果当天的数据更新就断了。你意识到：数据产品如果依赖人工触发，就永远无法真正"上线"。你需要一套定时任务系统，让数据管道在无人值守的情况下自动运行，同时保留手动触发的能力以应对突发需求。

from apscheduler.schedulers.background import BackgroundScheduler

from datetime import datetime

scheduler = BackgroundScheduler()

def crawl_jobs():
    """采集任务"""
    print(f"[{datetime.now()}] 开始采集招聘数据...")
    # 执行 ETL 管道
    pipeline.run()

# 添加定时任务：每天早上 8 点
scheduler.add_job(
    crawl_jobs,
    CronTrigger(hour=8, minute=0),

## 二、手动触发

### 2.1 API 触发

```python
from fastapi import APIRouter, BackgroundTasks

router = APIRouter()

@router.post("/tasks/crawl")
async def trigger_crawl(background_tasks: BackgroundTasks):
    """手动触发采集任务"""
    task_id = generate_task_id()
    
    background_tasks.add_task(run_crawl_task, task_id)
    
    return {
        "task_id": task_id,
        "status": "queued",
        "message": "任务已加入队列"
    }

async def run_crawl_task(task_id: str):
    """执行采集任务"""
    try:
        update_task_status(task_id, "running")
        pipeline.run()
        update_task_status(task_id, "completed")
    except Exception as e:
        update_task_status(task_id, "failed", str(e))
```

## 常见误区

- **只用 cron 就够了**：cron 能处理简单定时，但没有重试、没有状态追踪、没有并发控制。当任务逻辑变复杂后，cron 会成为瓶颈。
- **手动触发不需要记录**：手动触发的任务同样需要记录状态和日志，否则出问题后无法追溯是定时还是手动触发的。
- **定时任务不需要超时控制**：如果一个采集任务卡住了，没有超时机制会导致后续任务排队等待，整个调度系统被阻塞。
- **把所有逻辑写在一个任务里**：采集、清洗、聚合应该拆分成独立任务，失败时可以单独重试，而不是每次都从头跑。

---

## 工程建议

1. **任务幂等性是底线**：定时任务可能被重复触发（手动 + 定时同时触发），确保同一任务跑两次不会产生重复数据。
2. **记录触发来源**：在 task_log 中区分 `scheduled` 和 `manual` 触发，方便排查问题和统计使用频率。
3. **任务超时与并发限制**：给每个任务设置最大执行时间和最大并发数，防止一个慢任务拖垮整个系统。
4. **先本地验证调度逻辑，再上生产**：用 APScheduler 在本地跑通调度逻辑，确认无误后再考虑分布式方案（如 Celery），避免过早引入复杂度。

## 参考答案

### 练习一

**思路**：使用 APScheduler 作为调度核心，创建一个 `TaskScheduler` 类统一管理定时任务和手动触发。定时任务用 CronTrigger 配置，手动触发通过 API 调用同一执行函数，两者共享任务状态记录。

**答案**：

```python
from apscheduler.schedulers.background import BackgroundScheduler
from apscheduler.triggers.cron import CronTrigger
from datetime import datetime
from fastapi import APIRouter, BackgroundTasks
import uuid

router = APIRouter()
scheduler = BackgroundScheduler()

def generate_task_id() -> str:
    return f"task_{uuid.uuid4().hex[:12]}"

def run_task(task_type: str, task_id: str, trigger_type: str):
    """统一的任务执行入口"""
    try:
        save_task_log(task_id, task_type, "running", trigger_type)
        if task_type == "crawl":
            crawl_pipeline.run()
        elif task_type == "incremental":
            incremental_pipeline.run()
        save_task_log(task_id, task_type, "completed", trigger_type)
    except Exception as e:
        save_task_log(task_id, task_type, "failed", trigger_type, str(e))

# 定时任务 1：每天早上 8 点全量采集
scheduler.add_job(
    lambda: run_task("crawl", generate_task_id(), "scheduled"),
    CronTrigger(hour=8, minute=0),
    id="daily_crawl",
    name="每日招聘数据采集",
    replace_existing=True,
)

# 定时任务 2：每小时增量更新
scheduler.add_job(
    lambda: run_task("incremental", generate_task_id(), "scheduled"),
    CronTrigger(minute=0),
    id="hourly_incremental",
    name="每小时增量更新",
    replace_existing=True,
)

scheduler.start()

# 手动触发接口
@router.post("/tasks/trigger/{task_type}")
async def trigger_task(task_type: str, background_tasks: BackgroundTasks):
    """手动触发任务，task_type 可选 crawl 或 incremental"""
    if task_type not in ("crawl", "incremental"):
        return {"error": "无效的任务类型"}
    task_id = generate_task_id()
    background_tasks.add_task(run_task, task_type, task_id, "manual")
    return {"task_id": task_id, "status": "queued", "trigger": "manual"}

def save_task_log(task_id, task_type, status, trigger_type, error=None):
    """保存任务日志到数据库"""
    query = """
        INSERT INTO task_log (task_id, task_type, status, trigger_type, start_time, end_time, error_message)
        VALUES (:task_id, :task_type, :status, :trigger_type, :start_time, :end_time, :error)
    """
    now = datetime.now()
    engine.execute(query, {
        "task_id": task_id, "task_type": task_type, "status": status,
        "trigger_type": trigger_type,
        "start_time": now if status == "running" else None,
        "end_time": now if status in ("completed", "failed") else None,
        "error": error,
    })
```

**要点**：
- 定时任务和手动触发共用同一个 `run_task` 函数，保证行为一致
- 通过 `trigger_type` 字段区分 `scheduled` 和 `manual`，方便排查问题
- 手动触发使用 FastAPI 的 `BackgroundTasks`，API 立即返回 task_id，任务在后台异步执行

### 练习二

**思路**：在 `task_log` 表基础上，实现任务生命周期的完整记录：创建 → 运行 → 完成/失败，并提供查询接口。重点是每次状态变更都写入数据库，而不是只存最新状态。

**答案**：

```python
from fastapi import APIRouter, HTTPException
from datetime import datetime
from enum import Enum

router = APIRouter()

class TaskStatus(Enum):
    QUEUED = "queued"
    RUNNING = "running"
    COMPLETED = "completed"
    FAILED = "failed"

# 建表 SQL
CREATE_TABLE_SQL = """
CREATE TABLE IF NOT EXISTS task_log (
    id              SERIAL PRIMARY KEY,
    task_id         VARCHAR(50) UNIQUE NOT NULL,
    task_type       VARCHAR(50) NOT NULL,
    status          VARCHAR(20) NOT NULL,
    trigger_type    VARCHAR(20) NOT NULL,
    start_time      TIMESTAMP,
    end_time        TIMESTAMP,
    duration_sec    FLOAT,
    error_message   TEXT,
    created_at      TIMESTAMP DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_task_log_status ON task_log(status);
CREATE INDEX IF NOT EXISTS idx_task_log_created ON task_log(created_at);
"""

@router.get("/tasks/{task_id}")
async def get_task_detail(task_id: str):
    """查询单个任务的完整生命周期"""
    query = "SELECT * FROM task_log WHERE task_id = :task_id"
    row = engine.execute(query, {"task_id": task_id}).fetchone()
    if not row:
        raise HTTPException(status_code=404, detail="任务不存在")
    return {
        "task_id": row.task_id,
        "task_type": row.task_type,
        "status": row.status,
        "trigger_type": row.trigger_type,
        "start_time": str(row.start_time) if row.start_time else None,
        "end_time": str(row.end_time) if row.end_time else None,
        "duration_sec": row.duration_sec,
        "error_message": row.error_message,
        "created_at": str(row.created_at),
    }

@router.get("/tasks")
async def list_tasks(status: str = None, limit: int = 20):
    """查询任务列表，支持按状态筛选"""
    if status:
        query = "SELECT * FROM task_log WHERE status = :status ORDER BY created_at DESC LIMIT :limit"
        rows = engine.execute(query, {"status": status, "limit": limit}).fetchall()
    else:
        query = "SELECT * FROM task_log ORDER BY created_at DESC LIMIT :limit"
        rows = engine.execute(query, {"limit": limit}).fetchall()
    return [dict(row) for row in rows]

def update_task_status(task_id: str, new_status: str, error: str = None):
    """更新任务状态并计算耗时"""
    now = datetime.now()
    if new_status == "running":
        query = "UPDATE task_log SET status = :status, start_time = :now WHERE task_id = :task_id"
        engine.execute(query, {"status": new_status, "now": now, "task_id": task_id})
    elif new_status in ("completed", "failed"):
        query = """
            UPDATE task_log
            SET status = :status, end_time = :now, error_message = :error,
                duration_sec = EXTRACT(EPOCH FROM (:now - start_time))
            WHERE task_id = :task_id
        """
        engine.execute(query, {"status": new_status, "now": now, "error": error, "task_id": task_id})
```

**要点**：
- 任务状态变更时记录 `start_time`、`end_time`、`duration_sec`，形成完整的时间线
- 查询接口支持按状态筛选，方便快速找到失败任务进行排查
- `duration_sec` 通过数据库的 `EXTRACT(EPOCH FROM ...)` 自动计算，避免应用层时钟偏差
