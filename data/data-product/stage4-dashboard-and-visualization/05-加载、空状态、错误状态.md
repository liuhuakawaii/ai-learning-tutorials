## 常见误区

- **加载状态用一个 Spinner 打天下**：不管加载多久、加载什么内容，都用同一个转圈动画。快速请求（<300ms）闪烁一下反而让用户觉得卡，应该区分瞬时加载和长时加载。
- **空状态只显示"暂无数据"**：没有任何引导，用户不知道为什么是空的、该怎么做。好的空状态应该告诉用户原因，并提供下一步操作建议。
- **错误状态暴露技术细节**：把后端报错信息（如 500 Internal Server Error、stack trace）直接展示给用户，用户看不懂还可能泄露系统信息。
- **骨架屏和实际内容布局不一致**：骨架屏的形状和真实内容差距太大，加载完成时页面会"跳一下"，造成布局偏移。

---

## 工程建议

1. **300ms 内的请求不显示加载状态**：快速请求直接渲染结果，避免闪烁。只有超过 300ms 的请求才展示骨架屏或 Loading 指示器。
2. **空状态提供操作引导**：不要只写"暂无数据"，要说明可能的原因（如"当前筛选条件没有匹配到数据"），并提供操作建议（如"试试调整筛选条件"）。
3. **错误状态分级处理**：网络超时提示用户检查网络，服务器错误提示用户稍后重试，权限不足提示用户联系管理员。不同错误给不同的提示文案和操作按钮。
4. **骨架屏用 CSS 动画而非图片**：用 `@keyframes` 实现骨架屏的闪烁动画，比用 GIF 图片更轻量、更灵活，也更容易适配不同布局。

## 参考答案

### 练习一

**思路**：分别实现三种状态的 UI 组件。加载状态区分快速请求（<300ms 不显示）和长时请求（骨架屏），空状态提供原因和操作引导，错误状态分级处理。

**答案**：

```tsx
import { useState, useEffect, ReactNode } from 'react';

// 加载状态：300ms 内不显示，避免闪烁
function useDelayedLoading(isLoading: boolean, delay = 300) {
  const [showLoading, setShowLoading] = useState(false);

  useEffect(() => {
    if (isLoading) {
      const timer = setTimeout(() => setShowLoading(true), delay);
      return () => clearTimeout(timer);
    } else {
      setShowLoading(false);
    }
  }, [isLoading, delay]);

  return showLoading;
}

// 骨架屏组件

// 空状态组件：提供原因和操作引导
interface EmptyStateProps {

  description: string;

// 错误状态组件：分级处理
interface ErrorStateProps {
  type: 'network' | 'server' | 'permission' | 'unknown';
  onRetry?: () => void;
}

function ErrorState({ type, onRetry }: ErrorStateProps) {
  const config = {
    network: {
      icon: '🔌',
      title: '网络连接失败',
      description: '请检查您的网络连接是否正常，然后重试。',
    },
    server: {
      icon: '⚠️',
      title: '服务器错误',
      description: '服务暂时不可用，请稍后重试。',
    },
    permission: {
      icon: '🔒',
      title: '权限不足',
      description: '您没有访问此数据的权限，请联系管理员。',
    },
    unknown: {
      icon: '❌',
      title: '加载失败',
      description: '发生了未知错误，请稍后重试。',
    },
  };

  const { icon, title, description } = config[type];

  return (
    <div className="flex flex-col items-center justify-center py-16 text-center">
      <div className="text-4xl mb-4">{icon}</div>
      <h3 className="text-lg font-semibold text-gray-700 mb-2">{title}</h3>
      <p className="text-sm text-gray-500 mb-4 max-w-md">{description}</p>
      {onRetry && (
        <button
          onClick={onRetry}
          className="px-4 py-2 bg-blue-500 text-white rounded hover:bg-blue-600"
        >
          重新加载
        </button>
      )}
    </div>
  );
}

// 统一状态管理 Hook
function useDataState<T>(fetcher: () => Promise<T>) {
  const [data, setData] = useState<T | null>(null);
  const [error, setError] = useState<ErrorStateProps['type'] | null>(null);
  const [isLoading, setIsLoading] = useState(true);
  const showLoading = useDelayedLoading(isLoading);

  const load = async () => {
    setIsLoading(true);
    setError(null);
    try {
      const result = await fetcher();
      setData(result);
    } catch (err: any) {
      if (!navigator.onLine) setError('network');
      else if (err.status >= 500) setError('server');
      else if (err.status === 403) setError('permission');
      else setError('unknown');
    } finally {
      setIsLoading(false);
    }
  };

  useEffect(() => { load(); }, []);

  return { data, error, isLoading, showLoading, retry: load };
}
```

**要点**：
- `useDelayedLoading` 在 300ms 内不显示 loading，避免快速请求时 UI 闪烁
- 骨架屏用 `animate-pulse` CSS 动画，形状和真实内容一致
- 空状态不只是"暂无数据"，要告诉用户原因和下一步操作
- 错误状态根据类型显示不同的文案和图标，网络错误提示检查网络，权限错误提示联系管理员

### 练习二

**思路**：从骨架屏一致性、错误重试、渐进加载三个方面优化。骨架屏布局和真实内容一致，错误状态支持重试，大数据量用渐进加载提升感知速度。

```tsx
// 优化2：错误状态支持自动重试（指数退避）
function useRetryableFetch<T>(fetcher: () => Promise<T>, maxRetries = 3) {
  const [retryCount, setRetryCount] = useState(0);

  const { data, error, isLoading, showLoading, retry } = useDataState(fetcher);

  useEffect(() => {
    if (error && retryCount < maxRetries) {
      const delay = Math.pow(2, retryCount) * 1000; // 1s, 2s, 4s
      const timer = setTimeout(() => {
        setRetryCount((c) => c + 1);
        retry();
      }, delay);
      return () => clearTimeout(timer);
    }
  }, [error, retryCount]);

  return { data, error, isLoading, showLoading, retry };
}

// 优化3：渐进加载 - 先显示指标卡，再显示图表
function DashboardPage() {
  return (
    <div className="space-y-6">
      {/* 指标卡优先加载 */}
      <Suspense fallback={<MetricCardSkeleton />}>
        <MetricCards />
      </Suspense>
      {/* 图表延迟加载 */}
      <Suspense fallback={<SkeletonChart />}>
        <TrendChart />
      </Suspense>
      <Suspense fallback={<SkeletonChart />}>
        <RankingTable />
      </Suspense>
    </div>
  );
}

// 优化4：全局错误边界
class ErrorBoundary extends React.Component<
  { children: ReactNode; fallback: ReactNode },
  { hasError: boolean }
> {
  state = { hasError: false };

  static getDerivedStateFromError() {
    return { hasError: true };
  }

  render() {
    if (this.state.hasError) {
      return this.props.fallback;
    }
    return this.props.children;
  }
}
```

**要点**：
- 骨架屏的每个元素尺寸和真实组件一致，避免加载完成时页面"跳一下"
- 自动重试用指数退避（1s → 2s → 4s），避免频繁重试压垮服务器
- 渐进加载让核心指标卡先展示，图表后展示，用户感知更快
- ErrorBoundary 捕获渲染崩溃，避免整个页面白屏
