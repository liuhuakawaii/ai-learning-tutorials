# 第1课：Dashboard 信息架构

> **课程定位**：设计 Dashboard 的整体结构和信息层次
> **前置知识**：第三阶段全部课程
> **预计时长**：45 分钟

---

## 场景引入

你刚接手一个招聘数据分析平台，产品经理丢过来一句话："老板想看个 Dashboard，一眼就能看到整体情况。"你打开竞品一看，满屏的图表堆在一起，指标卡、折线图、饼图、表格混杂排列，看了五分钟还是不知道该先看什么。这时候你意识到，问题不在图表本身，而在于信息架构——哪些信息放首页、哪些放二级页面、用户打开页面的第一秒应该看到什么，这些才是 Dashboard 设计的核心。

## 常见误区

- **把所有信息堆在一个页面**：总想让用户一眼看到所有数据，结果信息过载，用户反而什么都看不到。Dashboard 的核心是"分层"，不是"堆砌"。
- **忽略用户角色差异**：管理者和分析师的需求完全不同，用同一套信息架构服务所有人，结果谁都不满意。
- **先选图表再想结构**：看到竞品用了饼图就跟风用饼图，没有先想清楚这个页面要回答什么问题、用户最关心什么指标。
- **静态布局不考虑响应式**：在 27 寸显示器上设计得很好看，到了笔记本屏幕上全乱了。

---

## 工程建议

1. **用卡片分类法确定信息层次**：把所有指标写在便签上，让目标用户分组排序，根据排序结果决定哪些信息放首页、哪些放二级页面。
2. **首页指标卡控制在 4-6 个**：超过 6 个指标卡会让用户注意力分散，核心指标用最大字号和最显眼的位置。
3. **布局方案先画线框图再写代码**：用 Figma 或纸笔先把栅格布局画出来，确认信息密度合理后再用 Tailwind 栅格系统实现。
4. **URL 参数同步筛选状态**：筛选器的状态应该同步到 URL 参数中，这样用户刷新页面或分享链接时不会丢失筛选条件。

## 参考答案

### 练习一

**思路**：商品价格监控的核心用户是运营和采购人员，需要快速了解价格异常、竞品动态和价格趋势。按信息层次分为总览、分析、预警三个页面。

**答案**：

```
页面列表：
1. 价格总览（Overview）
2. 竞品分析（Analysis）
3. 价格预警（Alerts）

每个页面包含的组件：
页面1（价格总览）：
  - 指标卡（4个）：监控商品总数、今日价格变动数、平均价格、异常价格数
  - 趋势图：近30天整体价格走势折线图
  - 排名榜：价格波动最大的商品 TOP10
  - 分类分布：各品类商品数量饼图

页面2（竞品分析）：
  - 筛选器：品类、平台、价格区间、时间范围
  - 对比表格：同一商品在不同平台的价格对比
  - 价格走势图：选定商品的多平台价格趋势
  - 导出按钮：支持导出对比数据

页面3（价格预警）：
  - 预警规则列表：当前生效的预警条件
  - 触发记录：最近触发的预警事件
  - 异常商品列表：价格偏离均值超过阈值的商品
  - 告警设置：配置预警阈值和通知方式
```

**要点**：
- 总览页面向管理者，只放核心指标和趋势
- 分析页面向运营，提供筛选和下钻能力
- 预警页面向采购，聚焦异常和行动

### 练习三

**思路**：筛选器设计要考虑级联关系和性能优化。品类和平台是独立筛选器，价格区间和时间范围是范围筛选器。用防抖避免频繁请求，用 URL 同步状态。

**答案**：

```
筛选器列表：
1. 品类筛选（下拉单选/多选）
2. 平台筛选（下拉多选：淘宝、京东、拼多多等）
3. 价格区间（双滑块：最低价 - 最高价）
4. 时间范围（日期范围选择器）
5. 搜索框（按商品名称搜索）

联动方案：
- 品类变化 → 更新商品列表、更新价格区间范围、更新排名榜
- 平台变化 → 更新价格对比表、更新趋势图
- 价格区间变化 → 更新所有图表
- 时间范围变化 → 更新趋势图、更新统计指标
- 搜索框输入 → 300ms 防抖后更新商品列表

性能优化：
- 所有筛选器状态统一存入 URL query string
- 文本搜索加 300ms 防抖
- 品类变化时，先更新本地筛选选项再发请求
- 多个筛选条件变化时合并为一次请求（debounce 100ms）
- 图表数据启用 React Query 缓存，相同筛选条件不重复请求
```

**要点**：
- 筛选器之间有级联关系时，父级变化要清空子级的无效选项
- 防抖和请求合并是两个不同的优化手段，都需要实现
- URL 同步让用户可以分享带筛选条件的链接
