# 性能优化

## 场景引入

你的搜索服务已经上线，功能一切正常。但随着数据量增长到数千万条，用户反馈搜索越来越慢——P99 延迟从 200ms 飙升到 3 秒。你查看监控发现 CPU 使用率不高，但 IO 等待严重。问题出在哪里？

Elasticsearch 性能优化不是单点调整，而是需要从查询、索引、JVM、集群配置多个层面系统性地分析和优化。一个常见的误区是"哪里慢就优化哪里"，实际上瓶颈往往不在你直觉认为的地方。比如你看到查询慢，可能真正的瓶颈是 GC 导致的 STW（Stop-The-World）暂停，或者是段合并（segment merge）引发的 IO 争抢。

性能优化的第一步永远是**测量**。没有数据支撑的优化是盲目的。这门课会教你用正确的方法找到瓶颈，然后用正确的手段优化它。

## 学习目标

完成本课学习后，你将能够：

1. 理解和使用 ES 的三层缓存机制
2. 使用索引路由优化查询性能
3. 掌握索引层面的优化手段（段合并、translog、refresh）
4. 了解 JVM 调优的基本原则和 G1GC 配置
5. 用 Python 进行性能对比测试
6. 掌握慢查询分析和优化的完整流程
7. 理解写入优化和读取优化的 tradeoff

## 查询缓存机制

```
┌─────────────────────────────────────────────────────────────┐
│                    ES 缓存层次                                │
│                                                             │
│  Node Query Cache  ──  缓存 filter 查询结果，占堆 10%        │
│  Shard Request Cache ── 缓存整个搜索请求结果，默认关闭       │
│  Fielddata Cache  ──  缓存 text 字段 fielddata，消耗大       │
└─────────────────────────────────────────────────────────────┘
```

### Node Query Cache

只缓存 filter context 下的查询结果，不缓存 score 计算。这是一个 LRU 缓存，默认占用堆内存的 10%。

```bash
GET /products/_search
{
  "query": {
    "bool": {
      "must": [{ "match": { "name": "键盘" } }],
      "filter": [
        { "term": { "category": "electronics" } },
        { "range": { "price": { "gte": 100, "lte": 500 } } }
      ]
    }
  }
}

# 查看缓存统计
GET _nodes/stats/indices/query_cache
```

### Fielddata Cache

Fielddata 是 text 字段在内存中的列式存储，用于排序和聚合。**强烈建议不要对 text 字段排序/聚合**，使用 keyword 子字段替代。

```python
def check_fielddata_usage(es):
    """检查 fielddata 使用情况，找出内存大户"""
    stats = es.indices.stats(metric=["fielddata"])
    for index, index_data in stats["indices"].items():
        fielddata = index_data.get("primaries", {}).get("fielddata", {})
        if fielddata.get("memory_size_in_bytes", 0) > 0:
            print(f"索引 {index}: "
                  f"Fielddata 内存 {fielddata.get('memory_size', 'N/A')}, "
                  f"驱逐次数 {fielddata.get('evictions', 0)}")

check_fielddata_usage(es)
```

## 索引路由（Routing）

默认 ES 需要查询所有分片才能返回完整结果。通过自定义路由，相关文档集中在同一分片，查询时只访问目标分片。

```
┌─────────────────────────────────────────────────────────────┐
│  默认路由：查询所有 5 个分片                                  │
│  ┌──────┐┌──────┐┌──────┐┌──────┐┌──────┐                  │
│  │Shard0││Shard1││Shard2││Shard3││Shard4│                  │
│  │用户A ││用户B ││用户A ││用户C ││用户B │                  │
│  └──────┘└──────┘└──────┘└──────┘└──────┘                  │
│                                                             │
│  自定义路由（按用户ID）：只访问 1 个分片                       │
│  查询用户A订单 → 只访问 Shard0                               │
└─────────────────────────────────────────────────────────────┘
```

```bash
PUT /orders
{
  "settings": { "number_of_shards": 5 },
  "mappings": {
    "_routing": { "required": true },
    "properties": {
      "user_id": { "type": "keyword" },
      "product": { "type": "text" },
      "amount": { "type": "float" }
    }
  }
}

POST /orders/_doc?routing=user_001
{ "user_id": "user_001", "product": "机械键盘", "amount": 399 }

GET /orders/_search?routing=user_001
{ "query": { "term": { "user_id": "user_001" } } }
```

## 索引优化

### Force Merge

小的索引段会增加搜索 IO 开销。`force_merge` 将小段合并为大段。**只适用于不再写入的索引**。

```bash
POST /logs-2023-01/_forcemerge?max_num_segments=1
GET /logs-2023-01/_segments
```

用 Python 实现安全的段合并：

```python
from elasticsearch import Elasticsearch

es = Elasticsearch("http://localhost:9200")

def safe_force_merge(es, index, max_segments=1):
    """安全的段合并操作"""
    # 1. 检查索引是否还在写入
    index_stats = es.indices.stats(index=index)
    indexing = index_stats["indices"][index]["total"]["indexing"]
    if indexing.get("index_total", 0) > 0:
        recent_time = indexing.get("index_time_in_millis", 0)
        print(f"警告: 索引 {index} 最近有写入活动，不建议 force_merge")
        return False

    # 2. 检查当前段数量
    segments = es.indices.segments(index=index)
    shard_segments = segments["indices"][index]["shards"]
    total_segments = sum(
        len(shard_data[0].get("segments", {}))
        for shard_data in shard_segments.values()
    )
    print(f"当前段数量: {total_segments}")

    if total_segments <= max_segments:
        print("段数量已在目标范围内，跳过合并")
        return True

    # 3. 执行合并
    print(f"开始合并到 {max_segments} 个段...")
    es.indices.forcemerge(index=index, max_num_segments=max_segments)

    # 4. 验证结果
    segments = es.indices.segments(index=index)
    shard_segments = segments["indices"][index]["shards"]
    new_total = sum(
        len(shard_data[0].get("segments", {}))
        for shard_data in shard_segments.values()
    )
    print(f"合并后段数量: {new_total}")
    return True

safe_force_merge(es, "logs-2024-01")
```

### 批量写入优化

```python
from elasticsearch import Elasticsearch
from elasticsearch.helpers import bulk, parallel_bulk

es = Elasticsearch("http://localhost:9200")

def bulk_import(es, index, documents, batch_size=1000):
    actions = [{"_index": index, "_id": doc["id"], "_source": doc} for doc in documents]
    success, failed = bulk(es, actions, chunk_size=batch_size, request_timeout=60)
    print(f"成功: {success}, 失败: {failed}")
```

### 并行写入

```python
def parallel_bulk_import(es, index, documents, thread_count=4):
    """使用并行 bulk 写入"""
    actions = [{"_index": index, "_source": doc} for doc in documents]

    success_count = 0
    error_count = 0

    for ok, result in parallel_bulk(
        es, actions,
        thread_count=thread_count,
        chunk_size=500,
        raise_on_error=False
    ):
        if ok:
            success_count += 1
        else:
            error_count += 1
            if error_count <= 5:  # 只打印前 5 个错误
                print(f"写入失败: {result}")

    print(f"完成: 成功 {success_count}, 失败 {error_count}")
    return success_count, error_count
```

### 完整的批量导入流程

```python
from elasticsearch import Elasticsearch
from elasticsearch.helpers import bulk
import time

es = Elasticsearch("http://localhost:9200")

def optimized_bulk_import(es, index, documents, batch_size=1000):
    """优化的批量导入流程"""
    # 1. 关闭自动 refresh 和副本
    original_settings = es.indices.get_settings(index=index)
    original_refresh = original_settings[index]["settings"]["index"].get("refresh_interval", "1s")
    original_replicas = original_settings[index]["settings"]["index"].get("number_of_replicas", "1")

    print("优化索引设置...")
    es.indices.put_settings(index=index, body={
        "index.refresh_interval": "-1",
        "index.number_of_replicas": 0
    })

    # 2. 执行批量写入
    actions = [{"_index": index, "_source": doc} for doc in documents]
    start_time = time.time()
    success, failed = bulk(es, actions, chunk_size=batch_size, request_timeout=120)
    elapsed = time.time() - start_time

    print(f"写入完成: {success} 条, 耗时 {elapsed:.1f} 秒, "
          f"速率 {success/elapsed:.0f} 条/秒")

    # 3. 恢复设置
    print("恢复索引设置...")
    es.indices.put_settings(index=index, body={
        "index.refresh_interval": original_refresh,
        "index.number_of_replicas": original_replicas
    })

    # 4. 等待恢复完成
    es.indices.refresh(index=index)
    es.cluster.health(index=index, wait_for_status="yellow")

    print("导入完成!")
    return success, failed

# 使用示例
documents = [{"id": i, "name": f"商品{i}", "price": i * 10} for i in range(10000)]
optimized_bulk_import(es, "products", documents)
```

## JVM 调优

```bash
# jvm.options: 物理内存的 50%，不超过 32GB
-Xms16g
-Xmx16g
```

为什么不超过 32GB？超过后 JVM 无法使用压缩指针（compressed oops），内存效率反而下降。

Old Generation 存放长期存活对象（segment、fielddata、缓存），Young Generation 存放新建对象。GC 频率过高时增加堆内存，GC 暂停过长时使用 G1GC。

```bash
# G1GC 配置（大堆推荐）
-XX:+UseG1GC
-XX:G1HeapRegionSize=4m
-XX:MaxGCPauseMillis=200
```

### GC 监控

```python
from elasticsearch import Elasticsearch

es = Elasticsearch("http://localhost:9200")

def check_gc_health(es):
    """检查 GC 健康状态"""
    nodes_stats = es.nodes.stats(metric=["jvm"])
    for node_id, node_data in nodes_stats["nodes"].items():
        node_name = node_data["name"]
        jvm = node_data.get("jvm", {})
        gc = jvm.get("gc", {})

        # Young GC
        young_collectors = gc.get("collectors", [{}])
        young_gc = young_collectors[0] if young_collectors else {}

        # Old GC
        old_gc = young_collectors[1] if len(young_collectors) > 1 else {}

        heap_used = jvm.get("mem", {}).get("heap_used_percent", 0)
        heap_max = jvm.get("mem", {}).get("heap_max", "N/A")

        print(f"节点: {node_name}")
        print(f"  堆使用率: {heap_used}%")
        print(f"  堆最大值: {heap_max}")
        print(f"  Young GC: 次数 {young_gc.get('collection_count', 0)}, "
              f"耗时 {young_gc.get('collection_time_in_millis', 0)}ms")
        print(f"  Old GC: 次数 {old_gc.get('collection_count', 0)}, "
              f"耗时 {old_gc.get('collection_time_in_millis', 0)}ms")

        if heap_used > 80:
            print(f"  警告: 堆使用率过高 ({heap_used}%)")
        if old_gc.get("collection_count", 0) > 100:
            print(f"  警告: Old GC 频繁，可能存在内存泄漏")

check_gc_health(es)
```

### JVM 内存分配建议

| 集群规模 | 堆内存建议 | 说明 |
|----------|-----------|------|
| 小型（< 100GB 数据） | 4-8GB | 留一半给 OS 缓存 |
| 中型（100GB - 1TB） | 16GB | 常见生产配置 |
| 大型（> 1TB） | 31GB | 接近但不超过 32GB |
| 超大型 | 多节点 × 31GB | 水平扩展而非加大堆 |

### 避免深度分页

```python
def optimized_pagination(es, index, query, page_size=20):
    """使用 search_after 替代深度分页"""
    sort_fields = [{"_id": "asc"}]
    search_after = None
    page_num = 0

    while True:
        body = {
            "query": query,
            "size": page_size,
            "sort": sort_fields
        }
        if search_after:
            body["search_after"] = search_after

        response = es.search(index=index, body=body)
        hits = response["hits"]["hits"]
        if not hits:
            break

        page_num += 1
        yield hits

        search_after = hits[-1]["sort"]

# 使用生成器按需加载
for page in optimized_pagination(es, "products", {"match_all": {}}):
    process_page(page)
```

## Python 性能对比测试

```python
from elasticsearch import Elasticsearch
import time

es = Elasticsearch("http://localhost:9200")

def benchmark_query(es, index, query, iterations=100):
    times = []
    for _ in range(iterations):
        start = time.time()
        es.search(index=index, body=query)
        times.append(time.time() - start)
    times.sort()
    return {"avg_ms": round(sum(times)/len(times)*1000, 2),

# 对比 filter vs query
```

### 完整的性能测试框架

```python
from elasticsearch import Elasticsearch
import time
import statistics

es = Elasticsearch("http://localhost:9200")

class ESPerformanceTester:
    def __init__(self, es_host, index):
        self.es = Elasticsearch(es_host)
        self.index = index

    def warmup(self, query, iterations=10):
        """预热，确保缓存生效"""
        for _ in range(iterations):
            self.es.search(index=self.index, body=query)

    def test_query(self, name, query, iterations=100, warmup=True):
        """测试单个查询的性能"""
        if warmup:
            self.warmup(query)

        times = []
        for _ in range(iterations):
            start = time.perf_counter()
            response = self.es.search(index=self.index, body=query)
            elapsed = (time.perf_counter() - start) * 1000
            times.append(elapsed)

        times.sort()
        return {
            "name": name,
            "iterations": iterations,
            "avg_ms": round(statistics.mean(times), 2),
            "median_ms": round(statistics.median(times), 2),
            "p95_ms": round(times[int(len(times) * 0.95)], 2),
            "p99_ms": round(times[int(len(times) * 0.99)], 2),
            "min_ms": round(min(times), 2),
            "max_ms": round(max(times), 2),
            "total_hits": response["hits"]["total"]["value"]
        }

    def compare_queries(self, queries):
        """对比多个查询的性能"""
        results = []
        for name, query in queries.items():
            result = self.test_query(name, query)
            results.append(result)

        # 打印对比表
        print(f"{'查询名称':<20} {'平均(ms)':<10} {'P95(ms)':<10} {'P99(ms)':<10}")
        print("-" * 55)
        for r in results:
            print(f"{r['name']:<20} {r['avg_ms']:<10} {r['p95_ms']:<10} {r['p99_ms']:<10}")

        return results

# 使用示例
tester = ESPerformanceTester("http://localhost:9200", "products")

queries = {
    "match_all": {"query": {"match_all": {}}, "size": 10},
    "term_filter": {"query": {"bool": {"filter": [{"term": {"category": "electronics"}}]}}, "size": 10},
    "match_query": {"query": {"match": {"name": "手机"}}, "size": 10},
    "bool_combined": {
        "query": {
            "bool": {
                "must": [{"match": {"name": "手机"}}],
                "filter": [
                    {"term": {"category": "electronics"}},
                    {"range": {"price": {"gte": 1000, "lte": 5000}}}
                ]
            }
        },
        "size": 10
    }
}

results = tester.compare_queries(queries)
```

## 慢查询分析

```python
from elasticsearch import Elasticsearch
import json

es = Elasticsearch("http://localhost:9200")

def analyze_slow_query(es, index, query_body):
    """分析慢查询的详细执行过程"""
    # 1. 使用 profile 分析
    profile_response = es.search(
        index=index,
        body={"profile": True, **query_body}
    )

    print("=== 查询 Profile 分析 ===")
    print(f"总耗时: {profile_response['took']}ms")

    for shard in profile_response.get("profile", {}).get("shards", []):
        shard_id = shard["id"]
        for search in shard.get("searches", []):
            for query in search.get("query", []):
                print(f"  分片 {shard_id}:")
                print(f"    查询类型: {query['type']}")
                print(f"    描述: {query['description']}")
                print(f"    耗时: {query['time_in_nanos'] / 1_000_000:.2f}ms")
                for child in query.get("children", []):
                    print(f"      子查询: {child['type']} ({child['time_in_nanos'] / 1_000_000:.2f}ms)")

    # 2. 检查分片负载均衡
    shard_times = []
    for shard in profile_response.get("profile", {}).get("shards", []):
        total_time = sum(
            q["time_in_nanos"]
            for s in shard.get("searches", [])
            for q in s.get("query", [])
        )
        shard_times.append({"shard": shard["id"], "time_ms": total_time / 1_000_000})

    if shard_times:
        max_time = max(s["time_ms"] for s in shard_times)
        min_time = min(s["time_ms"] for s in shard_times)
        if min_time > 0 and max_time / min_time > 3:
            print(f"\n警告: 分片间性能差异过大 ({max_time:.0f}ms vs {min_time:.0f}ms)")

    return profile_response

# 分析慢查询
analyze_slow_query(es, "products", {
    "query": {"match": {"name": "机械键盘"}},
    "size": 10
})
```

## 常见误区

1. **盲目增加副本提升性能**：副本消耗额外写入资源。读多写少可增加，写密集应谨慎。

2. **分片越小搜索越快**：过小分片增加汇聚开销。单个分片建议 10-50GB。

3. **JVM 堆越大越好**：超过 32GB 压缩指针失效。留一半内存给 OS 文件系统缓存。

4. **force_merge 是常规操作**：非常消耗 IO，只适用于不再写入的索引。

5. **忽略 OS 缓存**：ES 依赖操作系统文件系统缓存加速 segment 读取。堆内存占用过多会挤压 OS 缓存。

6. **过度使用脚本排序**：script-based sorting 无法利用索引结构，性能远差于字段排序。

7. **忽略分片数据倾斜**：某个分片数据过多会导致查询变慢，定期检查分片分布。

```python
def setup_ilm_policy(es):

    es.ilm.put_lifecycle(name="product_policy", body={
        "policy": {
            "phases": {
                "hot": {
                    "min_age": "0ms",
                    "actions": {
                        "rollover": {
                            "max_size": "50gb",
                            "max_age": "7d"
                        },
                        "set_priority": {"priority": 100}
                    }
                },
                "warm": {
                    "min_age": "30d",
                    "actions": {
                        "shrink": {"number_of_shards": 1},
                        "forcemerge": {"max_num_segments": 1},
                        "set_priority": {"priority": 50}
                    }
                },
                "cold": {
                    "min_age": "90d",
                    "actions": {
                        "set_priority": {"priority": 0}
                    }
                },
                "delete": {
                    "min_age": "365d",
                    "actions": {
                        "delete": {}
                    }
                }
            }
        }
    })
    print("ILM 策略创建成功")

setup_ilm_policy(es)
```

7. **使用异步搜索处理大查询**：ES 7.x 支持异步搜索，避免长时间阻塞客户端。

```python
def async_search(es, index, query_body):
    """异步搜索"""
    # 提交异步搜索
    response = es.async_search.submit(
        index=index,
        body=query_body,
        wait_for_completion_timeout="5s",
        keep_alive="5m"
    )
    search_id = response["id"]

    # 检查是否已完成
    if response.get("is_running"):
        print("搜索仍在运行，稍后获取结果...")
        import time
        time.sleep(2)
        response = es.async_search.get(id=search_id)

    # 清理异步搜索上下文
    es.async_search.delete(id=search_id)

    return response["response"]
```

## 小结

ES 性能优化需要从多个层面系统性地进行：查询层面善用 filter 缓存和 search_after；索引层面合理设置 refresh interval、使用 bulk 批量写入、对冷数据 force_merge；JVM 层面控制堆内存不超过 32GB、使用 G1GC；集群层面使用路由减少扫描分片。性能优化是一个持续的过程，需要通过监控和基准测试来验证每次调整的效果。记住：先测量，再优化。没有数据支撑的优化是盲目的。

**答案**：

```python
from elasticsearch import Elasticsearch
import time

def compare_routing(es_host, index, user_id, iterations=50):
    es = Elasticsearch(es_host)
    query = {"query": {"term": {"user_id": user_id}}}
    times_no = [time.time() for _ in range(iterations)]
    for i in range(iterations):
        es.search(index=index, body=query)
        times_no[i] = time.time() - times_no[i]
    times_yes = [time.time() for _ in range(iterations)]
    for i in range(iterations):
        es.search(index=index, body=query, routing=user_id)
        times_yes[i] = time.time() - times_yes[i]
    avg_no = sum(times_no)/len(times_no)*1000
    avg_yes = sum(times_yes)/len(times_yes)*1000
    print(f"无路由: {avg_no:.2f}ms, 有路由: {avg_yes:.2f}ms, 提升: {(avg_no/avg_yes-1)*100:.0f}%")
```

**要点**：无路由向所有分片发送查询，有路由只向 1 个分片发送。

**答案**：

```python
from elasticsearch import Elasticsearch
from elasticsearch.helpers import bulk
import time

def benchmark_write(es_host, index, docs):
    es = Elasticsearch(es_host)
    actions = [{"_index": index, "_source": d} for d in docs]
    # 方案1: 单条写入
    es.indices.delete(index=index, ignore=[404])
    es.indices.create(index=index, ignore=[400])
    start = time.time()
    for d in docs: es.index(index=index, document=d)
    t1 = time.time() - start
    # 方案2: bulk
    es.indices.delete(index=index, ignore=[404])
    es.indices.create(index=index, ignore=[400])
    start = time.time()
    bulk(es, actions, chunk_size=500)
    t2 = time.time() - start
    # 方案3: bulk + 关闭 refresh
    es.indices.delete(index=index, ignore=[404])
    es.indices.create(index=index, body={"settings": {"refresh_interval": "-1"}}, ignore=[400])
    start = time.time()
    bulk(es, actions, chunk_size=500)
    t3 = time.time() - start
    print(f"单条: {t1:.2f}s, bulk: {t2:.2f}s({t1/t2:.1f}x), bulk+关refresh: {t3:.2f}s({t1/t3:.1f}x)")
```

**要点**：bulk+关refresh 通常比单条写入快 10-50 倍。

**思路**：分析查询的每个部分，找出性能瓶颈。

**答案**：

优化前的问题：
1. `from: 1980, size: 20` 深度分页，协调节点需要从每个分片收集 2000 条结果
2. 按价格排序需要加载 fielddata 或 doc_values

```python
# 方案1: 使用 search_after 替代深度分页
# 问题: 不支持跳页
response = es.search(index="products", body={
    "query": {"match": {"name": "手机"}},
    "sort": [{"price": "asc"}, {"_id": "asc"}],
    "size": 20,
    "search_after": [last_price, last_id]
})

# 方案2: 使用 routing 减少扫描分片
# 问题: 需要知道品牌对应的路由值
response = es.search(index="products", body={...}, routing="苹果")

# 方案3: 组合优化
response = es.search(index="products", body={
    "query": {
        "bool": {
            "must": [{"match": {"name": "手机"}}],
            "filter": [{"term": {"category": "electronics"}}]  # filter 可缓存
        }
    },
    "sort": [{"price": "asc"}, {"_id": "asc"}],
    "size": 20,
    "search_after": [last_price, last_id],
    "_source": ["name", "price", "brand"]  # 只返回需要的字段
})
```

**要点**：深度分页的根本解决方案是 search_after；filter 比 must 更高效；限制返回字段减少网络传输。

### 练习五

**思路**：使用 ES 的 stats API 采集指标，设置阈值告警。

**答案**：

```python
from elasticsearch import Elasticsearch
import time

es = Elasticsearch("http://localhost:9200")

def performance_monitor(es, alert_callback=None):
    """集群性能监控"""
    alerts = []

    # 1. 集群健康
    health = es.cluster.health()
    if health["status"] != "green":
        alerts.append(f"集群状态异常: {health['status']}, 未分配分片: {health['unassigned_shards']}")

    # 2. 节点性能
    nodes_stats = es.nodes.stats(metric=["jvm", "indices", "os"])
    for node_id, node_data in nodes_stats["nodes"].items():
        node_name = node_data["name"]

        # 堆使用率
        heap_percent = node_data["jvm"]["mem"]["heap_used_percent"]
        if heap_percent > 80:
            alerts.append(f"节点 {node_name} 堆使用率过高: {heap_percent}%")

        # CPU
        cpu_percent = node_data.get("os", {}).get("cpu", {}).get("percent", 0)
        if cpu_percent > 80:
            alerts.append(f"节点 {node_name} CPU 使用率过高: {cpu_percent}%")

        # 查询延迟
        search_stats = node_data["indices"]["search"]
        query_total = search_stats.get("query_total", 0)
        query_time = search_stats.get("query_time_in_millis", 0)
        if query_total > 0:
            avg_query_time = query_time / query_total
            if avg_query_time > 100:
                alerts.append(f"节点 {node_name} 平均查询延迟过高: {avg_query_time:.0f}ms")

        # 缓存命中率
        query_cache = search_stats.get("query_cache", {})
        cache_hit = query_cache.get("hit_count", 0)
        cache_miss = query_cache.get("miss_count", 0)
        if cache_hit + cache_miss > 0:
            hit_rate = cache_hit / (cache_hit + cache_miss) * 100
            if hit_rate < 50:
                alerts.append(f"节点 {node_name} 缓存命中率低: {hit_rate:.1f}%")

    # 3. 磁盘使用率
    allocation = es.cat.allocation(format="json")
    for node in allocation:
        disk_percent = int(node.get("disk.percent", "0").replace("%", ""))
        if disk_percent > 85:
            alerts.append(f"节点 {node.get('node', 'unknown')} 磁盘使用率过高: {disk_percent}%")

    # 输出告警
    if alerts:
        print("=== 告警 ===")
        for alert in alerts:
            print(f"  ⚠ {alert}")
        if alert_callback:
            alert_callback(alerts)
    else:
        print("所有指标正常")

    return alerts

# 使用示例
alerts = performance_monitor(es)
```

**要点**：监控应覆盖集群健康、节点性能、缓存命中率、磁盘使用率等多个维度。
