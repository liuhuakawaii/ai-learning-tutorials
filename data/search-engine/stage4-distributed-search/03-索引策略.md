# 索引策略

## 场景引入

你的电商搜索上线后，用户反馈搜索"iPhone"找不到"苹果手机"，搜"笔记本"找不到"laptop"。更糟的是，搜索"华为 Mate 60"返回的结果相关性很差。问题出在哪里？

答案在于索引策略——分词器决定了文本如何被切分成词项，Mapping 决定了每个字段如何被存储和索引。

索引策略的好坏直接决定了搜索体验。搜索引擎的核心是倒排索引，而分词器决定了倒排索引中的词项是什么。如果分词器把"华为 Mate 60"切成"华""为""m""a""t""e""6""0"，那用户搜"华为手机"自然找不到它。如果切成"华为""mate""60"，搜索效果就好得多。这就是索引策略的核心价值——它决定了搜索引擎"理解"文本的方式。

## 学习目标

完成本课学习后，你将能够：

1. 配置自定义分词器（analyzer、tokenizer、filter）
2. 设计合理的 Mapping（字段类型、doc_values、norms）
3. 使用索引模板和别名管理索引生命周期
4. 用 Python 实现完整的索引管理流程
5. 掌握中文搜索场景下的分词策略最佳实践
6. 理解 Mapping 设计对查询性能和存储空间的影响

## 分词器配置

一个分词器（Analyzer）由三部分组成：字符过滤器、分词器（Tokenizer）、词项过滤器（Token Filter）。

```
┌─────────────────────────────────────────────────────────────┐
│                    分词器处理流程                              │
│                                                             │
│  原始文本 ──→ Character Filter ──→ Tokenizer ──→ Token Filter│
│  "华为Mate60"   去除特殊字符        分词         小写化       │
│                                   拆分         同义词替换    │
│  输出: ["华为", "mate", "60"]                                │
└─────────────────────────────────────────────────────────────┘
```

### 内置分词器对比

```bash
# standard 分词器：中文逐字分
POST _analyze
{"tokenizer": "standard", "text": "Elasticsearch 是最好的搜索引擎"}
# 输出: ["elasticsearch", "是", "最", "好", "的", "搜", "索", "引", "擎"]

# icu 分词器：基于 ICU 算法，支持中文
POST _analyze
{"analyzer": "icu_analyzer", "text": "Elasticsearch 是最好的搜索引擎"}
# 输出: ["elasticsearch", "是", "最", "好", "的", "搜索引擎", "搜索", "引擎"]
```

用 Python 对比不同分词器的输出：

```python
from elasticsearch import Elasticsearch

es = Elasticsearch("http://localhost:9200")

def compare_analyzers(es, text, analyzers):
    """对比多个分词器的输出"""
    results = {}
    for analyzer in analyzers:
        response = es.indices.analyze(body={
            "analyzer": analyzer,
            "text": text
        })
        tokens = [t["token"] for t in response["tokens"]]
        results[analyzer] = tokens
        print(f"{analyzer}: {tokens}")
    return results

text = "华为Mate60 Pro是目前最好的智能手机之一"
analyzers = ["standard", "simple", "whitespace", "keyword"]
compare_analyzers(es, text, analyzers)
```

### 中文分词器选择

中文分词是搜索引擎面临的核心挑战之一。英文有天然的空格分隔，中文则需要依赖词典和统计模型。

```bash
# ik_smart: 粗粒度分词
POST _analyze
{"analyzer": "ik_smart", "text": "中华人民共和国国歌"}
# 输出: ["中华人民共和国", "国歌"]

# ik_max_word: 细粒度分词（索引时推荐）
POST _analyze
{"analyzer": "ik_max_word", "text": "中华人民共和国国歌"}
# 输出: ["中华人民共和国", "中华人民", "中华", "人民共和国", "人民", "共和国", "共和", "国歌"]
```

**分词器选择决策**：

| 分词器 | 特点 | 适用场景 |
|--------|------|----------|
| standard | 英文按空格，中文逐字 | 纯英文内容 |
| ik_smart | 粗粒度，最少切分 | 搜索查询（提高精确度） |
| ik_max_word | 细粒度，最多切分 | 索引时（提高召回率） |
| icu_analyzer | 基于 Unicode 规则 | 多语言混合内容 |
| jieba | 基于 jieba 分词 | 中文自然语言处理 |
| pinyin | 拼音分词 | 拼音搜索 |

### 自定义分词器

```bash
PUT /products
{
  "settings": {
    "analysis": {
      "filter": {
        "my_synonym": {
          "type": "synonym",
          "synonyms": [
            "手机,移动电话,智能机",
            "笔记本,笔记本电脑,laptop",
            "机械键盘,mechanical keyboard"
          ]
        },
        "my_pinyin": {
          "type": "pinyin",
          "keep_full_pinyin": true,
          "keep_joined_full_pinyin": true,
          "keep_original": true
        }
      },
      "analyzer": {
        "my_index_analyzer": {
          "type": "custom",
          "tokenizer": "ik_max_word",
          "filter": ["lowercase", "my_synonym"]
        },
        "my_search_analyzer": {
          "type": "custom",
          "tokenizer": "ik_smart",
          "filter": ["lowercase"]
        },
        "my_pinyin_analyzer": {
          "type": "custom",
          "tokenizer": "ik_max_word",
          "filter": ["lowercase", "my_pinyin"]
        }
      }
    }
  }
}
```

索引时用细粒度（ik_max_word）保证召回率，搜索时用粗粒度（ik_smart）保证精确度。

## Mapping 设计

### 字段类型选择

```bash
PUT /products
{
  "mappings": {
    "properties": {
      "name": {
        "type": "text",
        "analyzer": "my_index_analyzer",
        "search_analyzer": "my_search_analyzer",
        "fields": { "keyword": { "type": "keyword", "ignore_above": 256 } }
      },
      "price": { "type": "float" },
      "category": { "type": "keyword" },
      "tags": { "type": "keyword" },
      "description": { "type": "text", "analyzer": "my_index_analyzer" },
      "created_at": { "type": "date", "format": "yyyy-MM-dd HH:mm:ss||yyyy-MM-dd||epoch_millis" },
      "in_stock": { "type": "boolean" },
      "location": { "type": "geo_point" }
    }
  }
}
```

### text vs keyword 决策树

```
┌─────────────┐
│ 需要全文搜索？│
└──────┬──────┘
   ┌───┴───┐
   Yes     No
   │       │
   ▼       ▼
  text    keyword
   │
   ▼
  也需要精确匹配/聚合？
  ┌─┴──┐
  Yes  No
  │    │
  ▼    ▼
text  text
+.keyword
```

- **text**：会被分词，用于全文搜索。"华为 Mate 60" → ["华为", "mate", "60"]
- **keyword**：不分词，作为一个整体存储。用于精确匹配、排序、聚合。

用 Python 设计 Mapping 的完整示例：

```python

                "filter": {

                        "synonyms": [
                            "手机,移动电话,智能机",
                            "笔记本,笔记本电脑,laptop",

                    "product_search_analyzer": {
                        "type": "custom",
                        "tokenizer": "ik_smart",
                        "filter": ["lowercase"]
                    }
                }
            }
        },
        "mappings": {
            "properties": {
                "name": {
                    "type": "text",
                    "analyzer": "product_index_analyzer",
                    "search_analyzer": "product_search_analyzer",
                    "fields": {
                        "keyword": {"type": "keyword", "ignore_above": 256}
                    },
                    "copy_to": "search_all"
                },
                "description": {
                    "type": "text",
                    "analyzer": "product_index_analyzer",
                    "doc_values": False,
                    "copy_to": "search_all"
                },
                "brand": {
                    "type": "keyword",
                    "copy_to": "search_all"
                },
                "category": {
                    "type": "keyword"
                },
                "price": {
                    "type": "float"
                },
                "original_price": {
                    "type": "float"
                },
                "stock": {

                },
                "sales_count": {
                    "type": "integer"

                "rating": {
                    "type": "float"

                "tags": {
                    "type": "keyword"
                },
                "sku_id": {
                    "type": "keyword"
                },
                "created_at": {
                    "type": "date",
                    "format": "yyyy-MM-dd HH:mm:ss||yyyy-MM-dd||epoch_millis"
                },
                "updated_at": {
                    "type": "date",
```

### doc_values 和 norms

**doc_values** 是面向列的存储结构，用于排序和聚合。默认对 keyword、numeric、date 类型开启。不需要排序/聚合的字段可关闭。

**norms** 存储文档长度归一化因子，用于 BM25 评分。不需要评分的字段可关闭节省内存。

```bash
PUT /products
{
  "mappings": {
    "properties": {
      "description": { "type": "text", "doc_values": false },
      "status": { "type": "keyword", "norms": false }
    }
  }
}
```

```python
def analyze_field_storage(es, index):
    """分析索引中各字段的存储配置"""
    mapping = es.indices.get_mapping(index=index)
    props = mapping[index]["mappings"]["properties"]

    print(f"索引 {index} 字段存储分析:")
    print(f"{'字段名':<20} {'类型':<10} {'doc_values':<12} {'norms':<10}")
    print("-" * 55)

    for field_name, field_config in props.items():
        field_type = field_config.get("type", "object")
        doc_values = field_config.get("doc_values", "默认开启" if field_type in ["keyword", "integer", "float", "date"] else "默认关闭")
        norms = field_config.get("norms", "默认开启" if field_type == "text" else "默认关闭")
        print(f"{field_name:<20} {field_type:<10} {str(doc_values):<12} {str(norms):<10}")

analyze_field_storage(es, "products")
```

## 索引模板

索引模板在创建匹配的索引时自动应用预设的 settings 和 mappings。适合日志等按时间滚动的索引。

```bash
PUT _index_template/logs_template
{
  "index_patterns": ["logs-*"],
  "priority": 100,
  "template": {
    "settings": {
      "number_of_shards": 3,
      "number_of_replicas": 1,
      "refresh_interval": "30s"
    },
    "mappings": {
      "properties": {
        "timestamp": { "type": "date" },
        "level": { "type": "keyword" },
        "message": { "type": "text" },
        "service": { "type": "keyword" }
      }
    }
  }
}
```

用 Python 创建和管理索引模板：

```python
from elasticsearch import Elasticsearch

es = Elasticsearch("http://localhost:9200")

def create_log_template(es):
    """创建日志索引模板"""
    template_body = {
        "index_patterns": ["logs-*"],
        "priority": 100,
        "template": {
            "settings": {
                "number_of_shards": 3,
                "number_of_replicas": 1,
                "refresh_interval": "30s",
                "codec": "best_compression",  # 日志场景优先压缩率
                "analysis": {
                    "analyzer": {
                        "log_analyzer": {
                            "type": "custom",
                            "tokenizer": "standard",
                            "filter": ["lowercase"]
                        }
                    }
                }
            },
            "mappings": {
                "properties": {
                    "timestamp": {"type": "date", "format": "strict_date_optional_time||epoch_millis"},
                    "level": {"type": "keyword"},
                    "message": {"type": "text", "analyzer": "log_analyzer"},
                    "service": {"type": "keyword"},
                    "host": {"type": "keyword"},
                    "trace_id": {"type": "keyword"},
                    "duration_ms": {"type": "float"}
                }
            }
        }
    }

    es.indices.put_index_template(name="logs_template", body=template_body)
    print("日志模板创建成功")

create_log_template(es)

# 验证模板生效
response = es.indices.simulate_index(name="logs-2024-01-15")
```

## 索引别名

别名（Alias）是一个指向一个或多个索引的虚拟名称，支持零停机索引切换。

```bash
# 零停机重建索引流程
POST _aliases
{
  "actions": [
    { "remove": { "index": "products_v1", "alias": "products" } },
    { "add": { "index": "products_v2", "alias": "products" } }
  ]
}
```

### 别名路由

```bash
POST _aliases
{
  "actions": [
    {
      "add": {
        "index": "products_electronics",
        "alias": "products",
        "filter": { "term": { "category": "electronics" } },
        "routing": "electronics"
      }
    },
    {
      "add": {
        "index": "products_clothing",
        "alias": "products",
        "filter": { "term": { "category": "clothing" } },
        "routing": "clothing"
      }
    }
  ]
}
```

### 别名过滤

通过别名实现数据隔离，例如多租户场景：

```python
from elasticsearch import Elasticsearch

es = Elasticsearch("http://localhost:9200")

def setup_tenant_aliases(es):
    """为多租户场景设置带过滤条件的别名"""
    tenants = ["tenant_a", "tenant_b", "tenant_c"]

    for tenant in tenants:
        es.indices.update_aliases(body={
            "actions": [{
                "add": {
                    "index": "shared_data",
                    "alias": f"data_{tenant}",
                    "filter": {"term": {"tenant_id": tenant}}
                }
            }]
        })
        print(f"别名 data_{tenant} 创建成功")

# tenant_a 查询自己的数据
response = es.search(
    index="data_tenant_a",  # 使用别名
    body={"query": {"match_all": {}}, "size": 10}
)
```

### 完整的索引重建流程

```python
from elasticsearch import Elasticsearch
import time

es = Elasticsearch("http://localhost:9200")

def rebuild_index(es, alias_name, new_mapping, batch_size=1000):
    """零停机索引重建

    Args:
        es: Elasticsearch 客户端
        alias_name: 别名名称
        new_mapping: 新索引的 settings + mappings
        batch_size: reindex 批量大小
    """
    # 1. 获取当前索引
    alias_info = es.indices.get_alias(name=alias_name)
    old_index = list(alias_info.keys())[0]

    # 2. 生成新索引名
    version = 1
    while es.indices.exists(index=f"{alias_name}_v{version}"):
        version += 1
    new_index = f"{alias_name}_v{version}"

    print(f"重建索引: {old_index} → {new_index}")

    # 3. 创建新索引
    es.indices.create(index=new_index, body=new_mapping)
    print(f"新索引 {new_index} 创建成功")

    # 4. 迁移数据
    print("开始迁移数据...")
    start_time = time.time()
    es.reindex(
        body={
            "source": {"index": old_index},
            "dest": {"index": new_index}
        },
        wait_for_completion=True,
        requests_per_second=1000  # 限速，避免影响线上
    )
    elapsed = time.time() - start_time
    print(f"数据迁移完成，耗时 {elapsed:.1f} 秒")

    # 5. 验证数据完整性
    old_count = es.count(index=old_index)["count"]
    new_count = es.count(index=new_index)["count"]
    if old_count != new_count:
        raise RuntimeError(f"数据不一致: {old_count} vs {new_count}")
    print(f"数据验证通过: {new_count} 条")

    # 6. 原子切换别名
    es.indices.update_aliases(body={
        "actions": [
            {"remove": {"index": old_index, "alias": alias_name}},
            {"add": {"index": new_index, "alias": alias_name}}
        ]
    })
    print(f"别名 {alias_name} 已切换到 {new_index}")

    # 7. 保留旧索引（可选：延迟删除）
    print(f"旧索引 {old_index} 保留用于回滚，建议 7 天后删除")
    return new_index

# 使用示例
new_mapping = {
    "settings": {
        "number_of_shards": 3,
        "number_of_replicas": 1,
        "analysis": {
            "analyzer": {
                "product_analyzer": {
                    "type": "custom",
                    "tokenizer": "ik_max_word",
                    "filter": ["lowercase"]
                }
            }
        }
    },
    "mappings": {
        "properties": {
            "name": {
                "type": "text",
                "analyzer": "product_analyzer",
                "fields": {"keyword": {"type": "keyword"}}
            },
            "price": {"type": "float"},
            "category": {"type": "keyword"},
            "brand": {"type": "keyword"}
        }
    }
}

rebuild_index(es, "products", new_mapping)
```

## 常见误区

1. **不设置 Mapping 就写入数据**：ES 自动推断的类型往往不理想，如 "12345" 被识别为 long 而非 keyword。

2. **所有字段都用 text 类型**：keyword 在精确匹配、排序、聚合时性能远好于 text。

3. **忽略多字段（fields）**：同时需要全文搜索和精确匹配时，用 `text` + `.keyword` 子字段。

4. **分词器选型不当**：索引和查询应使用不同分词器。索引时细粒度保证召回，查询时粗粒度保证精确。

5. **硬编码索引名**：不使用别名和模板，直接硬编码索引名会让索引重建变得困难。

6. **忽略 ignore_above 参数**：keyword 字段默认 ignore_above 为 256，超过此长度的值不会被索引，但也不会报错。

7. **同义词更新后不重建索引**：同义词在索引时生效，修改同义词配置需要重建索引才能影响已索引的数据。

8. **过度使用 copy_to**：copy_to 会增加索引大小和写入时间，只在真正需要跨字段搜索时使用。

---

## 工程建议

1. **先设计 Mapping，再写入数据**：修改字段类型需要 Reindex，项目初期就设计好。

2. **索引 + 搜索分词器组合**：索引时 `ik_max_word`，搜索时 `ik_smart`，中文搜索经典组合。

3. **使用索引别名**：所有查询代码只使用别名，为索引重建提供灵活性。

4. **合理使用 doc_values 和 norms**：按需关闭，节省磁盘和内存。

5. **模板管理日志索引**：时序数据使用 `index_patterns` + 模板自动应用配置。

6. **动态 Mapping 策略**：生产环境应设置 `dynamic: strict` 禁止自动添加字段，避免意外的类型推断。

```python
# 严格模式禁止自动添加字段
strict_mapping = {
    "mappings": {
        "dynamic": "strict",
        "properties": {
            "name": {"type": "text"},
            "price": {"type": "float"}
        }
    }
}

# 写入未知字段时会报错
try:
    es.index(index="strict_index", document={"name": "test", "unknown_field": "value"})
except Exception as e:
    print(f"预期错误: {e}")
```

7. **使用 _meta 存储 Mapping 版本信息**：

```python
# 在 Mapping 中记录版本信息
mapping_with_meta = {
    "mappings": {
        "_meta": {
            "version": "2.1",
            "updated_at": "2024-01-15",
            "author": "search-team",
            "description": "添加 brand 字段支持品牌筛选"
        },
        "properties": {
            "name": {"type": "text"},
            "brand": {"type": "keyword"}
        }
    }
}
```

## 小结

索引策略是搜索质量的基础。分词器决定了文本如何被切分成词项，Mapping 决定了字段如何被存储和索引。中文搜索需要选择合适的分词器（如 IK），并为索引和查询配置不同的分词策略。索引模板和别名提供了灵活的索引管理能力，支持零停机索引重建和滚动切分。Mapping 设计需要综合考虑搜索需求、排序聚合需求、存储成本和查询性能。使用 copy_to 实现跨字段搜索，合理配置 doc_values 和 norms 优化存储。在生产环境中，应使用严格模式禁止自动添加字段，使用 _meta 记录 Mapping 版本信息。

### 练习三

**答案**：

```python
from elasticsearch import Elasticsearch

def rebuild_index(es_host, old_index, new_mapping, alias_name=None):
    es = Elasticsearch(es_host)
    new_index = f"{old_index}_v2"
    es.indices.create(index=new_index, body=new_mapping)
    es.reindex(
        body={"source": {"index": old_index}, "dest": {"index": new_index}},
        wait_for_completion=True, requests_per_second=1000
    )
    alias = alias_name or old_index
    actions = []
    if es.indices.exists_alias(name=alias):
        actions.append({"remove": {"index": old_index, "alias": alias}})
    actions.append({"add": {"index": new_index, "alias": alias}})
    es.indices.update_aliases(body={"actions": actions})
```

**要点**：reindex 可设置 `requests_per_second` 限速；别名切换是原子操作；完成后保留旧索引用于回滚。

### 练习五

**思路**：对比新旧 Mapping 的字段类型、配置差异。

**答案**：

```python
from elasticsearch import Elasticsearch

def check_mapping_compatibility(es, index, new_mapping):
    """检查新旧 Mapping 兼容性"""
    old_mapping = es.indices.get_mapping(index=index)
    old_props = old_mapping[index]["mappings"]["properties"]
    new_props = new_mapping.get("mappings", {}).get("properties", {})

    report = {
        "compatible": True,
        "added_fields": [],
        "removed_fields": [],
        "type_changes": [],
        "warnings": []
    }

    # 检查新增字段
    for field in new_props:
        if field not in old_props:
            report["added_fields"].append(field)

    # 检查删除字段
    for field in old_props:
        if field not in new_props:
            report["removed_fields"].append(field)
            report["warnings"].append(f"删除字段 {field} 可能导致已有数据不可搜索")

    # 检查类型变更
    for field in new_props:
        if field in old_props:
            old_type = old_props[field].get("type")
            new_type = new_props[field].get("type")
            if old_type and new_type and old_type != new_type:
                report["type_changes"].append({
                    "field": field,
                    "old_type": old_type,
                    "new_type": new_type
                })
                report["compatible"] = False
                report["warnings"].append(
                    f"字段 {field} 类型从 {old_type} 变为 {new_type}，需要重建索引"
                )

    # 检查 analyzer 变更
    for field in new_props:
        if field in old_props:
            old_analyzer = old_props[field].get("analyzer")
            new_analyzer = new_props[field].get("analyzer")
            if old_analyzer and new_analyzer and old_analyzer != new_analyzer:
                report["warnings"].append(
                    f"字段 {field} 分词器变更，需要重建索引"
                )

    return report

# 使用示例
new_mapping = {
    "mappings": {
        "properties": {
            "name": {"type": "text"},
            "price": {"type": "float"},
            "brand": {"type": "keyword"}  # 新增字段
        }
    }
}

report = check_mapping_compatibility(es, "products", new_mapping)
print(f"兼容: {report['compatible']}")
print(f"新增字段: {report['added_fields']}")
print(f"删除字段: {report['removed_fields']}")
print(f"类型变更: {report['type_changes']}")
for w in report['warnings']:
    print(f"警告: {w}")
```

**要点**：字段类型变更必须重建索引；新增字段是兼容的；删除字段需谨慎。
