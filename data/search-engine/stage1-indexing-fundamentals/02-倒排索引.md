# 倒排索引

## 场景引入

上节课我们搭建了搜索引擎的骨架，其中最关键的数据结构就是倒排索引。但上节课的实现非常粗糙——我们只记录了"某个词出现在哪些文档中"，没有记录出现的位置、出现的次数，也没有对索引进行压缩。

在真实的搜索引擎中，倒排索引需要支撑数十亿文档的存储和查询。Google 的索引规模超过 100PB。如果不做压缩，仅存储文档 ID 列表就需要 TB 级别的内存。本节课深入倒排索引的内部结构，理解它为什么高效，以及如何用压缩技术做得更紧凑。

### 倒排索引的历史

倒排索引并不是搜索引擎的发明。早在计算机出现之前，图书馆的**倒排目录卡**就是按作者、主题索引到书架位置的映射。1960 年代，倒排索引被引入计算机信息检索系统，用于学术文献检索（如 MEDLINE 医学文献数据库）。

1998 年 Google 的论文《The Anatomy of a Large-Scale Hypertextual Web Search Engine》详细描述了如何用倒排索引支撑大规模网页搜索。今天，倒排索引不仅是搜索引擎的基础，也是 Elasticsearch、Solr、Lucene 等工具的核心数据结构。据统计，超过 80% 的企业搜索场景使用 Lucene/Elasticsearch 作为底层引擎，而它们的核心就是倒排索引。

## 倒排索引的结构

倒排索引由两部分组成：

```
词典 (Dictionary)          倒排列表 (Posting Lists)
┌──────────┐              ┌─────────────────────────────────┐
│ 搜索     │──────────────│ [doc1, tf=3, pos=[0,12,45]]    │
│          │              │ [doc5, tf=1, pos=[7]]           │
├──────────┤              └─────────────────────────────────┘
│ 引擎     │──────────────│ [doc1, tf=2, pos=[1,13]]       │
│          │              │ [doc3, tf=4, pos=[0,5,20,31]]   │
├──────────┤              └─────────────────────────────────┤
│ 学习     │──────────────│ [doc1, tf=1, pos=[5]]          │
│          │              │ [doc9, tf=3, pos=[1,8,22]]     │
└──────────┘              └─────────────────────────────────┘
```

每条 Posting 包含三个关键字段：**doc_id**（文档编号）、**term_frequency**（词项在文档中出现的次数）、**positions**（出现位置列表，用于短语查询和高亮）。

## 构建倒排索引

```python
from collections import defaultdict
from dataclasses import dataclass, field


@dataclass
class Posting:
    doc_id: int
    term_freq: int = 0
    positions: list[int] = field(default_factory=list)


class InvertedIndex:
    """支持位置信息的倒排索引"""

    def __init__(self):
        self.index: dict[str, list[Posting]] = defaultdict(list)
        self.doc_store: dict[int, dict] = {}
        self.doc_count: int = 0

    def add_document(self, doc_id: int, terms: list[str], metadata: dict = None):
        self.doc_store[doc_id] = metadata or {}
        self.doc_count += 1
        term_positions: dict[str, list[int]] = defaultdict(list)
        for pos, term in enumerate(terms):
            term_positions[term].append(pos)
        for term, positions in term_positions.items():
            self.index[term].append(Posting(
                doc_id=doc_id, term_freq=len(positions), positions=positions,
            ))

    def get_postings(self, term: str) -> list[Posting]:
        return self.index.get(term, [])

    def document_frequency(self, term: str) -> int:
        return len(self.index.get(term, []))

    def collection_frequency(self, term: str) -> int:
        return sum(p.term_freq for p in self.index.get(term, []))
```

## 正排索引与倒排索引的配合

搜索引擎同时需要两种索引结构，它们互补而非替代：

```
正排索引 (Forward Index)         倒排索引 (Inverted Index)
┌────────┬──────────────┐       ┌────────┬──────────────┐
│ doc_id │ 内容/元数据    │       │  term  │ posting list  │
├────────┼──────────────┤       ├────────┼──────────────┤
│   0    │ {title, body}│       │ 搜索   │ [0, 1, 2]    │
│   1    │ {title, body}│       │ 引擎   │ [0, 1, 2]    │
│   2    │ {title, body}│       │ Python │ [2]          │
└────────┴──────────────┘       └────────┴──────────────┘
```

- **倒排索引**用于查询：给定词项，快速找到包含它的文档列表
- **正排索引**用于展示：给定文档 ID，取出正文、标题、URL 等元数据，用于生成搜索结果摘要和高亮

两者缺一不可。没有正排索引，搜索引擎虽然能找到相关文档，但无法展示标题和摘要；没有倒排索引，搜索引擎只能逐个扫描文档，查询延迟不可接受。

```python
class ForwardIndex:
    """正排索引：doc_id -> 文档完整内容"""

    def __init__(self):
        self.store: dict[int, dict] = {}

    def add(self, doc_id: int, title: str, body: str, url: str = ""):
        self.store[doc_id] = {"title": title, "body": body, "url": url}

    def get(self, doc_id: int) -> dict | None:
        return self.store.get(doc_id)

    def get_snippet(self, doc_id: int, query_terms: list[str], max_length: int = 200) -> str:
        """根据查询词生成摘要：找到包含最多查询词的片段"""
        doc = self.store.get(doc_id)
        if not doc:
            return ""
        body = doc["body"]
        best_start = 0
        best_score = 0
        window_size = max_length

        for start in range(0, len(body), 20):
            end = min(start + window_size, len(body))
            window = body[start:end]
            score = sum(1 for t in query_terms if t in window)
            if score > best_score:
                best_score = score
                best_start = start

        snippet = body[best_start:best_start + window_size]
        for term in query_terms:
            snippet = snippet.replace(term, f"**{term}**")
        return snippet + "..." if best_start + window_size < len(body) else snippet
```

正排索引的存储通常比倒排索引大得多，因为它需要存储完整正文。生产环境中，正排索引一般存在磁盘或 KV 数据库中（如 RocksDB），而倒排索引的词典部分尽量放在内存中以加速查询。

## Posting List 的压缩编码

倒排索引的存储瓶颈在于 Posting List。以 10 亿文档为例，一个热门词可能出现在 5 亿篇文档中，每个 doc_id 用 4 字节存储，仅这一个词项就需要 2GB。

压缩的核心思路：**差值编码（Delta Encoding）**。Posting List 按 doc_id 排序后，相邻差值通常很小，用变长编码可以大幅节省空间。

```
原始 doc_id:     [82001, 82005, 82007, 82015, 82020]
差值编码:        [82001,     4,     2,     8,     5]
```

### Variable Byte 编码（VByte）

每个字节的最高位作为"继续位"：1 表示后面还有字节，0 表示这是最后一个字节。

```python
def vbyte_encode(number: int) -> bytes:
    if number < 0:
        raise ValueError("仅支持非负整数")
    if number == 0:
        return b'\x00'
    result = bytearray()
    while number > 0:
        result.append(number & 0x7F)
        number >>= 7
    result.reverse()
    for i in range(len(result) - 1):
        result[i] |= 0x80
    return bytes(result)


def vbyte_decode(data: bytes) -> int:
    result = 0
    for byte in data:
        result = (result << 7) | (byte & 0x7F)
        if not (byte & 0x80):
            break
    return result


def vbyte_encode_list(numbers: list[int]) -> bytes:
    result = bytearray()
    for num in numbers:
        result.extend(vbyte_encode(num))
    return bytes(result)


def vbyte_decode_list(data: bytes) -> list[int]:
    result = []
    i = 0
    while i < len(data):
        value = 0
        while True:
            byte = data[i]
            value = (value << 7) | (byte & 0x7F)
            i += 1
            if not (byte & 0x80):
                break
        result.append(value)
    return result


# 对比原始存储和压缩存储
doc_ids = [82001, 82005, 82007, 82015, 82020]
deltas = [doc_ids[0]] + [doc_ids[i] - doc_ids[i-1] for i in range(1, len(doc_ids))]
print(f"差值序列: {deltas}")  # [82001, 4, 2, 8, 5]

original_size = len(doc_ids) * 4
encoded = vbyte_encode_list(deltas)
print(f"原始大小: {original_size} 字节")      # 20
print(f"压缩后大小: {len(encoded)} 字节")       # 7
print(f"压缩率: {len(encoded)/original_size:.1%}")
```

### PForDelta 编码

PForDelta 利用"大部分差值都很小"这一特性：选择阈值 b，用 b 位表示 90% 的差值，异常值单独存储。

```python
def pfordelta_encode(numbers: list[int], b: int = 8) -> tuple[bytes, list[tuple[int, int]]]:
    max_normal = (1 << b) - 1
    exceptions = []
    normal_values = []
    for i, num in enumerate(numbers):
        if num <= max_normal:
            normal_values.append(num)
        else:
            normal_values.append(0)
            exceptions.append((i, num))

    total_bits = len(normal_values) * b
    total_bytes = (total_bits + 7) // 8
    packed = bytearray(total_bytes)
    bit_offset = 0
    for val in normal_values:
        byte_pos = bit_offset // 8
        bit_pos = bit_offset % 8
        packed[byte_pos] |= (val << bit_pos) & 0xFF
        if bit_pos + b > 8 and byte_pos + 1 < total_bytes:
            packed[byte_pos + 1] |= (val >> (8 - bit_pos)) & 0xFF
        bit_offset += b
    return bytes(packed), exceptions
```

### 压缩算法对比

| 算法 | 压缩率 | 解码速度 | 适用场景 |
|------|--------|---------|---------|
| VByte | 中等 | 快 | 通用场景，实现简单 |
| PForDelta | 高 | 极快（SIMD友好） | 大规模搜索引擎 |
| Simple-9 | 高 | 快 | 内存受限场景 |

## 跳表加速查询

当 Posting List 很长时，AND 操作需要遍历两个列表。跳表可以在 Posting List 上建立多层索引，加速查找。

```python
class PostingWithSkip:
    def __init__(self, postings: list[int], skip_interval: int = 3):
        self.postings = postings
        self.skip_interval = skip_interval
        self.skip_pointers = {}
        for i in range(0, len(postings), skip_interval):
            next_idx = min(i + skip_interval, len(postings) - 1)
            self.skip_pointers[i] = next_idx

    def advance_with_skip(self, current_pos: int, target: int) -> int:
        if current_pos >= len(self.postings):
            return current_pos
        while current_pos in self.skip_pointers:
            skip_target = self.skip_pointers[current_pos]
            if self.postings[skip_target] < target:
                current_pos = skip_target
            else:
                break
        while current_pos < len(self.postings) and self.postings[current_pos] < target:
            current_pos += 1
        return current_pos


pl = PostingWithSkip([1, 3, 5, 7, 9, 12, 15, 18, 21, 25, 30, 35, 40])
pos = pl.advance_with_skip(0, 15)
print(f"跳转到15: 位置{pos}, doc_id={pl.postings[pos]}")  # 位置6, doc_id=15
```

## 词典数据结构

词典（Dictionary）存储了所有唯一词项，需要支持两种核心操作：**精确查找**（某个词是否存在）和**前缀查找**（以某个前缀开头的所有词）。不同的数据结构在这两个操作上有不同的性能特征。

### 哈希表词典

最简单的词典实现，O(1) 精确查找，但不支持前缀查询。

```python
class HashDictionary:
    """基于哈希表的词典"""

    def __init__(self):
        self.table: dict[str, int] = {}  # term -> posting list offset

    def insert(self, term: str, offset: int):
        self.table[term] = offset

    def lookup(self, term: str) -> int | None:
        """精确查找：O(1)"""
        return self.table.get(term)

    def prefix_search(self, prefix: str) -> list[str]:
        """前缀查找：O(n)，需要遍历所有词项"""
        return [t for t in self.table if t.startswith(prefix)]
```

### Trie 词典

Trie（前缀树）天然支持前缀查询，是搜索引擎词典的经典选择。

```python
class TrieNode:
    def __init__(self):
        self.children: dict[str, TrieNode] = {}
        self.is_end: bool = False
        self.posting_offset: int = -1


class TrieDictionary:
    """基于 Trie 的词典，支持前缀查询"""

    def __init__(self):
        self.root = TrieNode()

    def insert(self, term: str, offset: int = 0):
        node = self.root
        for char in term:
            if char not in node.children:
                node.children[char] = TrieNode()
            node = node.children[char]
        node.is_end = True
        node.posting_offset = offset

    def lookup(self, term: str) -> int | None:
        """精确查找：O(m)，m 为词项长度"""
        node = self._find_node(term)
        if node and node.is_end:
            return node.posting_offset
        return None

    def prefix_search(self, prefix: str) -> list[str]:
        """前缀查找：O(m + k)，k 为结果数量"""
        node = self._find_node(prefix)
        if not node:
            return []
        results = []
        self._collect(node, prefix, results)
        return results

    def _find_node(self, term: str) -> TrieNode | None:
        node = self.root
        for char in term:
            if char not in node.children:
                return None
            node = node.children[char]
        return node

    def _collect(self, node: TrieNode, prefix: str, results: list[str]):
        if node.is_end:
            results.append(prefix)
        for char, child in node.children.items():
            self._collect(child, prefix + char, results)


# 使用示例
trie = TrieDictionary()
trie.insert("搜索引擎", 0)
trie.insert("搜索", 1)
trie.insert("算法", 2)
trie.insert("数据结构", 3)

print("精确查找 '搜索':", trie.lookup("搜索"))      # 1
print("前缀查找 '搜':", trie.prefix_search("搜"))    # ['搜索', '搜索引擎']
```

### Lucene 的 FST

Lucene 使用 **FST（Finite State Transducer，有限状态转换器）** 作为词典数据结构。FST 是一种压缩的 Trie 变体，它将所有词项编码为一个有向无环图（DAG），既支持前缀查询，又大幅节省内存。一个包含百万词项的词典，FST 只需要几十 MB 内存。FST 的构建时间较长（需要排序后的词项），但一旦构建完成，查询速度极快且内存占用极低。这是 Lucene/Elasticsearch 在词典层面的核心优化。

## 常见误区

1. **混淆倒排索引和正排索引**：正排索引是 doc_id → 内容，倒排索引是 term → doc_id 列表。两者互补。
2. **忽略位置信息的作用**：没有位置信息就无法支持短语查询。
3. **认为压缩会降低查询速度**：现代压缩算法解码极快，压缩后数据量更小，反而减少 I/O。
4. **对所有词项使用相同的编码策略**：高频词和低频词应使用不同的压缩方案。
5. **不区分内存和磁盘存储**：词典必须在内存中才能快速查询，而 Posting List 可以存在磁盘上按需加载。初学者常把整个倒排索引都放在内存里，导致内存不足。
6. **忽略 Posting List 交集优化**：多个词项的 AND 查询应该从最短的 Posting List 开始交集，这样中间结果最小，后续操作最快。不考虑这一点会导致不必要的遍历。
7. **混淆文档频率和词频**：文档频率（DF）是包含某词的文档数，词频（TF）是某词在一篇文档中的出现次数。DF 用于衡量词的区分度，TF 用于衡量词对文档的重要性。

## 工程建议

1. **先用差值编码再压缩**：直接对 doc_id 编码效果差，差值编码是压缩的前提。
2. **Posting List 要保持有序**：有序才能支持高效的 AND/OR 操作和差值编码。
3. **高频词要特殊处理**：停用词的 Posting List 极长，考虑在索引时直接过滤。
4. **监控索引大小和查询延迟**：压缩率和解码速度是两个需要平衡的指标。
5. **使用 Roaring Bitmap 替代稠密列表**：当 Posting List 非常稠密（如停用词出现在 90% 的文档中）时，位图（Bitmap）比文档 ID 列表更高效。Roaring Bitmap 是一种自适应数据结构，稀疏区域用数组，稠密区域用位图，是 Elasticsearch 和 Lucene 的默认选择。
6. **Segment 架构是关键**：不要把所有文档放在一个巨大的倒排索引中。Lucene 的做法是将索引分成多个 Segment，每个 Segment 是一个独立的小索引。这样增量更新只需重建一个 Segment，删除操作只需标记删除。
7. **索引预热**：搜索引擎重启后，词典和热查询的 Posting List 需要从磁盘加载到内存。上线前用历史查询做预热，避免冷启动延迟飙升。

## 小结

本节课深入学习了倒排索引的内部结构：

- **词典**存储所有唯一词项，**倒排列表**存储每个词项的出现信息
- 每条 Posting 包含 doc_id、词频、位置信息
- **差值编码**将 Posting List 转化为小整数序列，适合压缩
- **VByte** 和 **PForDelta** 是两种主流压缩编码
- **跳表**可以加速 Posting List 上的查找操作

5. 当容器大小 < 4096 时使用有序数组，否则使用位图

### 练习一

**思路**：分别获取每个词项的 Posting List，通过位置信息判断词项是否在文档中连续出现。

```python
def search_phrase(self, phrase: str) -> list[int]:
    terms = phrase.split()
    if not terms:
        return []
    first_postings = {p.doc_id: p for p in self.get_postings(terms[0])}
    result_doc_ids = []
    for doc_id, first_p in first_postings.items():
        valid_positions = list(first_p.positions)
        for i in range(1, len(terms)):
            next_postings = {p.doc_id: p for p in self.get_postings(terms[i])}
            if doc_id not in next_postings:
                valid_positions = []
                break
            next_positions = next_postings[doc_id].positions
            valid_positions = [pos for pos in valid_positions if (pos + 1) in next_positions]
        if valid_positions:
            result_doc_ids.append(doc_id)
    return result_doc_ids
```

**要点**：短语查询必须依赖位置信息；逐步过滤位置，时间复杂度与短语长度成正比。

def compute_compression_ratio(doc_ids: list[int]) -> dict:

### 练习三

**思路**：Trie 的删除需要递归清理空节点，前缀统计和自动补全都基于 DFS 遍历。

**答案**：

```python
class EnhancedTrieDictionary(TrieDictionary):

    def delete(self, term: str) -> bool:
        """删除词项，返回是否成功"""
        def _delete(node: TrieNode, depth: int) -> bool:
            if depth == len(term):
                if not node.is_end:
                    return False
                node.is_end = False
                return len(node.children) == 0
            char = term[depth]
            if char not in node.children:
                return False
            should_delete = _delete(node.children[char], depth + 1)
            if should_delete:
                del node.children[char]
                return not node.is_end and len(node.children) == 0
            return False

        return _delete(self.root, 0)

    def count_prefix(self, prefix: str) -> int:
        """统计以 prefix 开头的词项数量"""
        node = self._find_node(prefix)
        if not node:
            return 0
        count = 0
        stack = [node]
        while stack:
            curr = stack.pop()
            if curr.is_end:
                count += 1
            for child in curr.children.values():
                stack.append(child)
        return count

    def auto_complete(self, prefix: str, top_k: int = 5) -> list[str]:
        """前缀自动补全，返回最多 top_k 个结果"""
        node = self._find_node(prefix)
        if not node:
            return []
        results = []
        self._collect(node, prefix, results)
        return results[:top_k]
```

**要点**：
- 删除操作需要递归向上清理空节点，避免留下无用的中间节点
- `count_prefix` 用栈代替递归，避免深层 Trie 导致栈溢出
- 生产环境中自动补全通常会结合词频排序，优先返回热门词

### 练习四

**思路**：先按 Posting List 长度排序，用最短的列表初始化结果集，逐步与更长的列表求交集。

**答案**：

```python
def optimized_and_query(index: InvertedIndex, terms: list[str]) -> list[int]:
    """优化的多词 AND 查询"""
    if not terms:
        return []

    # 按 Posting List 长度排序（短的优先）
    term_postings = [(t, index.get_postings(t)) for t in terms]
    term_postings.sort(key=lambda x: len(x[1]))

    # 从最短的列表开始
    result_ids = {p.doc_id for p in term_postings[0][1]}

    # 逐步求交集
    for _, postings in term_postings[1:]:
        if not result_ids:
            break
        current_ids = {p.doc_id for p in postings}
        result_ids &= current_ids

    return sorted(result_ids)


# 对比朴素实现
def naive_and_query(index: InvertedIndex, terms: list[str]) -> list[int]:
    """朴素的多词 AND 查询"""
    if not terms:
        return []
    sets = [set(p.doc_id for p in index.get_postings(t)) for t in terms]
    return sorted(set.intersection(*sets))
```

**要点**：
- 先交集最短列表可以尽早缩小候选集，减少后续操作的元素数量
- 在真实系统中，还会结合跳表进一步加速：当结果集中的某个 ID 小于当前 Posting 的最小值时，可以直接跳过

### 练习五

**思路**：将 16 位整数空间分为 2^16 个容器，每个容器根据密度选择数组或位图存储。

**答案**：

```python
class SimpleRoaringBitmap:
    """简化的 Roaring Bitmap 实现"""

    ARRAY_THRESHOLD = 4096

    def __init__(self):
        self.containers: dict[int, list[int] | bytearray] = {}

    def _get_container_key(self, doc_id: int) -> int:
        return doc_id >> 16

    def _get_offset(self, doc_id: int) -> int:
        return doc_id & 0xFFFF

    def add(self, doc_id: int):
        key = self._get_container_key(doc_id)
        offset = self._get_offset(doc_id)
        if key not in self.containers:
            self.containers[key] = []
        container = self.containers[key]
        if isinstance(container, list):
            if offset not in container:
                container.append(offset)
                container.sort()
                if len(container) >= self.ARRAY_THRESHOLD:
                    self._convert_to_bitmap(key)
        else:
            container[offset // 8] |= 1 << (offset % 8)

    def _convert_to_bitmap(self, key: int):
        arr = self.containers[key]
        bitmap = bytearray(8192)  # 65536 / 8
        for val in arr:
            bitmap[val // 8] |= 1 << (val % 8)
        self.containers[key] = bitmap

    def contains(self, doc_id: int) -> bool:
        key = self._get_container_key(doc_id)
        offset = self._get_offset(doc_id)
        if key not in self.containers:
            return False
        container = self.containers[key]
        if isinstance(container, list):
            return offset in container
        return bool(container[offset // 8] & (1 << (offset % 8)))

    def intersection(self, other: 'SimpleRoaringBitmap') -> 'SimpleRoaringBitmap':
        result = SimpleRoaringBitmap()
        for key in set(self.containers.keys()) & set(other.containers.keys()):
            c1, c2 = self.containers[key], other.containers[key]
            if isinstance(c1, list) and isinstance(c2, list):
                result.containers[key] = sorted(set(c1) & set(c2))
            else:
                b1 = self._to_bitmap(c1)
                b2 = self._to_bitmap(c2)
                result.containers[key] = bytearray(a & b for a, b in zip(b1, b2))
        return result

    def _to_bitmap(self, container) -> bytearray:
        if isinstance(container, bytearray):
            return container
        bitmap = bytearray(8192)
        for val in container:
            bitmap[val // 8] |= 1 << (val % 8)
        return bitmap
```

**要点**：
- Roaring Bitmap 的核心思想是自适应：稀疏区域用数组（节省空间），稠密区域用位图（加速操作）
- 4096 是经验值：当数组大小超过 4096 时，位图的 8KB 固定大小反而更小
- Elasticsearch 和 Lucene 都使用 Roaring Bitmap 作为默认的 Posting List 实现
