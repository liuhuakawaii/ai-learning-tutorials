### 模块职责划分

- **Tokenizer**：负责文本的分词、大小写归一化、停用词过滤。它是索引和查询的共同入口，保证索引和查询使用相同的分词逻辑。
- **InvertedIndex**：核心数据结构，存储词项到 Posting List 的映射。每个 Posting 记录文档 ID、词频和位置信息。
- **BooleanRetriever**：基于倒排索引执行布尔查询。支持 AND、OR、NOT 三种操作，以及短语查询。
- **QueryParser**：将用户输入的查询字符串解析为结构化的查询对象。支持关键词、排除词、短语等语法。
- **IndexStore**：负责索引的持久化存储和加载。支持 JSON 格式的序列化和反序列化。

### 设计原则

1. **单一职责**：每个模块只负责一件事，模块间通过清晰的接口交互
2. **可测试性**：每个模块可以独立测试，不依赖其他模块的实现细节
3. **可扩展性**：新增功能（如 BM25 排序、向量检索）不需要修改现有模块
4. **分词一致性**：索引和查询必须使用同一个分词器，否则会出现"索引时分词为 A，查询时分词为 B"的不匹配问题

### 模块一：分词器

```python
import re
import json
import os
from collections import defaultdict
from dataclasses import dataclass, field


DEFAULT_STOPWORDS = {
    "的", "了", "是", "在", "我", "有", "和", "就", "不", "人", "都", "一", "一个", "上", "也",
    "很", "到", "说", "要", "去", "你", "会", "着", "没有", "好", "自己", "这", "他", "她", "它",
    "the", "a", "an", "is", "are", "was", "were", "in", "on", "at", "to", "for", "of", "with",
}


class Tokenizer:
    def __init__(self, stopwords: set[str] = None, custom_words: list[str] = None):
        self.stopwords = stopwords or DEFAULT_STOPWORDS
        try:
            import jieba
            self.jieba = jieba
            for word in (custom_words or []): jieba.add_word(word)
        except ImportError:
            self.jieba = None

    def tokenize(self, text: str) -> list[str]:
        tokens = self.jieba.cut_for_search(text) if self.jieba else re.findall(r"[\u4e00-\u9fff]+|[a-zA-Z0-9]+", text)
        return [t.strip().lower() for t in tokens if t.strip() and t.strip().lower() not in self.stopwords]
```

### 分词器的设计考量

分词器看似简单，但设计时需要考虑几个关键问题：

1. **大小写归一化**：`Python` 和 `python` 应该被视为同一个词项。通过 `.lower()` 统一转为小写。
2. **停用词过滤**：停用词（如"的"、"是"、"the"）在几乎所有文档中都出现，对检索没有区分度，过滤掉可以减小索引体积。
3. **自定义词典**：领域专有名词（如"机器学习"、"深度学习"）可能被分词器错误切分，需要添加到自定义词典。
4. **分词模式选择**：jieba 提供精确模式和搜索引擎模式。搜索引擎模式会进一步切分长词，提高召回率。

### 模块二：倒排索引

```python
@dataclass
class Posting:
    doc_id: int
    term_freq: int = 0
    positions: list[int] = field(default_factory=list)


class InvertedIndex:
    def __init__(self):
        self.index: dict[str, list[Posting]] = defaultdict(list)
        self.doc_store: dict[int, dict] = {}
        self.doc_count: int = 0
        self.doc_lengths: dict[int, int] = {}

    def add_document(self, doc_id: int, terms: list[str], metadata: dict = None):
        self.doc_store[doc_id] = metadata or {}
        self.doc_count += 1
        self.doc_lengths[doc_id] = len(terms)
        term_positions = defaultdict(list)
        for pos, term in enumerate(terms): term_positions[term].append(pos)
        for term, positions in term_positions.items():
            self.index[term].append(Posting(doc_id=doc_id, term_freq=len(positions), positions=positions))

    def get_postings(self, term: str) -> list[Posting]: return self.index.get(term, [])
    def document_frequency(self, term: str) -> int: return len(self.index.get(term, []))
```

### Posting 数据结构的设计

Posting 是倒排索引的基本单元，包含三个关键信息：

- **doc_id**：文档的唯一标识符，用于在查询结果中定位文档
- **term_freq (tf)**：词项在文档中出现的次数，后续 BM25 排序会用到
- **positions**：词项在文档中的位置列表，短语查询会用到

为什么需要位置信息？考虑查询 `"机器学习入门"`：
- 没有位置信息：只能找到同时包含"机器"、"学习"、"入门"的文档，但三个词可能分散在不同段落
- 有位置信息：可以精确找到三个词连续出现的文档，这就是短语查询的基础

### 模块三：布尔查询引擎

```python
class BooleanRetriever:
    def __init__(self, index: InvertedIndex):
        self.index = index

    def search_and(self, terms: list[str]) -> list[int]:
        if not terms: return []
        posting_lists = [sorted(p.doc_id for p in self.index.get_postings(t)) for t in terms]
        if any(not pl for pl in posting_lists): return []
        result = posting_lists[0]
        for pl in posting_lists[1:]:
            result = self._merge_and(result, pl)
            if not result: break
        return result

    def search_or(self, terms: list[str]) -> list[int]:
        all_ids = set()
        for term in terms:
            for p in self.index.get_postings(term): all_ids.add(p.doc_id)
        return sorted(all_ids)

    def search_not(self, exclude_terms: list[str], base_ids: list[int] = None) -> list[int]:
        if base_ids is None: base_ids = list(self.index.doc_store.keys())
        exclude_ids = {p.doc_id for t in exclude_terms for p in self.index.get_postings(t)}
        return [did for did in base_ids if did not in exclude_ids]

    def _merge_and(self, list_a: list[int], list_b: list[int]) -> list[int]:
        result, i, j = [], 0, 0
        while i < len(list_a) and j < len(list_b):
            if list_a[i] == list_b[j]: result.append(list_a[i]); i += 1; j += 1
            elif list_a[i] < list_b[j]: i += 1
            else: j += 1
        return result
```

### 布尔查询的执行流程

以查询 `Python -数据分析` 为例：

1. **解析**：QueryParser 将查询解析为 `include=["python"]`, `exclude=["数据", "分析"]`
2. **AND 查询**：对 include 中的词项执行 AND 操作，找到包含 "python" 的文档
3. **NOT 过滤**：从 AND 结果中排除包含 "数据" 或 "分析" 的文档
4. **返回结果**：返回最终的文档列表

这个流程体现了布尔查询的核心思想：**逐步缩小候选集**。AND 缩小到包含所有词项的文档，NOT 进一步排除不需要的文档。

### 模块四：查询解析器

```python
class QueryParser:
    def __init__(self, tokenizer: Tokenizer):
        self.tokenizer = tokenizer

    def parse(self, query: str) -> dict:
        include_terms, exclude_terms = [], []
        phrases = re.findall(r'"([^"]+)"', query)
        remaining = re.sub(r'"[^"]*"', '', query)
        for token in remaining.split():
            if token.startswith("-") and len(token) > 1:
                exclude_terms.extend(self.tokenizer.tokenize(token[1:]))
            elif token.upper() != "OR":
                include_terms.extend(self.tokenizer.tokenize(token))
        for phrase in phrases:
            include_terms.extend(self.tokenizer.tokenize(phrase))
        return {"include": include_terms, "exclude": exclude_terms, "phrases": phrases}
```

### 查询语法设计

我们的查询语法支持以下特性：

- **关键词查询**：`Python 机器学习` — 默认 AND 语义，返回同时包含两个词的文档
- **排除词**：`Python -数据分析` — 排除包含"数据分析"的文档
- **短语查询**：`"机器学习入门"` — 要求三个词连续出现
- **OR 查询**：`Python OR Java` — 返回包含任一词的文档

查询语法的设计要平衡**表达能力**和**易用性**。过于复杂的语法（如嵌套括号）用户难以记忆，过于简单的语法又无法表达复杂需求。

### 模块五：搜索引擎主类

```python
class SearchEngine:
    def __init__(self, stopwords: set[str] = None, custom_words: list[str] = None):
        self.tokenizer = Tokenizer(stopwords, custom_words)
        self.index = InvertedIndex()
        self.retriever = BooleanRetriever(self.index)
        self.parser = QueryParser(self.tokenizer)

    def add_document(self, doc_id: int, title: str, body: str):
        terms = self.tokenizer.tokenize(f"{title} {body}")
        self.index.add_document(doc_id, terms, {"title": title, "body": body})

    def search(self, query: str) -> list[dict]:
        parsed = self.parser.parse(query)
        include, exclude = parsed["include"], parsed["exclude"]
        if not include and not exclude: return []
        doc_ids = self.retriever.search_and(include) if include else list(self.index.doc_store.keys())
        if exclude: doc_ids = self.retriever.search_not(exclude, doc_ids)
        return [{"doc_id": did, "title": self.index.doc_store[did].get("title", ""),
                 "snippet": self.index.doc_store[did].get("body", "")[:100]} for did in doc_ids]

    def save(self, path: str):
        data = {"doc_count": self.index.doc_count,
                "index": {t: [{"doc_id": p.doc_id, "tf": p.term_freq, "pos": p.positions}
                              for p in ps] for t, ps in self.index.index.items()},
                "doc_store": {str(k): v for k, v in self.index.doc_store.items()},
                "doc_lengths": {str(k): v for k, v in self.index.doc_lengths.items()}}
        with open(path, "w", encoding="utf-8") as f:
            json.dump(data, f, ensure_ascii=False, indent=2)

    @classmethod
    def load(cls, path: str, stopwords: set[str] = None) -> "SearchEngine":
        engine = cls(stopwords)
        with open(path, "r", encoding="utf-8") as f:
            data = json.load(f)
        engine.index.doc_count = data["doc_count"]
        for term, postings in data["index"].items():
            engine.index.index[term] = [Posting(doc_id=p["doc_id"], term_freq=p["tf"], positions=p["pos"]) for p in postings]
        engine.index.doc_store = {int(k): v for k, v in data["doc_store"].items()}
        engine.index.doc_lengths = {int(k): v for k, v in data.get("doc_lengths", {}).items()}
        return engine
```

### 主类的设计权衡

SearchEngine 作为主入口，将所有模块组合在一起。设计时有几个权衡：

1. **title + body 拼接**：将标题和正文拼接后统一索引，简化了索引逻辑，但丢失了"只在标题中搜索"的能力。如果需要字段级搜索，需要为每个字段单独建索引。
2. **snippet 截取**：返回结果时截取正文前 100 字作为摘要。实际系统中应该根据查询词的位置截取最相关的片段。
3. **JSON 持久化**：使用 JSON 格式便于调试，但大规模数据应使用二进制格式。

### 扩展一：BM25 排序

布尔查询只返回"包含/不包含"的结果，没有排序。BM25 是最常用的排序算法，它综合考虑词频（TF）和逆文档频率（IDF）来评估文档与查询的相关性。

```python
import math

def bm25_score(
    query_terms: list[str],
    doc_id: int,
    index: InvertedIndex,
    k1: float = 1.5,
    b: float = 0.75
) -> float:
    """计算文档的 BM25 分数"""
    score = 0.0
    avg_doc_length = sum(index.doc_lengths.values()) / index.doc_count
    doc_length = index.doc_lengths.get(doc_id, 0)

    for term in query_terms:
        postings = index.get_postings(term)
        tf = 0
        for p in postings:
            if p.doc_id == doc_id:
                tf = p.term_freq
                break
        if tf == 0:
            continue

        df = len(postings)
        idf = math.log((index.doc_count - df + 0.5) / (df + 0.5) + 1)
        tf_normalized = (tf * (k1 + 1)) / (tf + k1 * (1 - b + b * doc_length / avg_doc_length))
        score += idf * tf_normalized

    return score


class RankedSearchEngine(SearchEngine):
    def search(self, query: str, top_k: int = 10) -> list[dict]:
        parsed = self.parser.parse(query)
        include, exclude = parsed["include"], parsed["exclude"]
        if not include and not exclude:
            return []

        doc_ids = self.retriever.search_and(include) if include else list(self.index.doc_store.keys())
        if exclude:
            doc_ids = self.retriever.search_not(exclude, doc_ids)

        # 计算 BM25 分数并排序
        scored_results = []
        for did in doc_ids:
            score = bm25_score(include, did, self.index)
            scored_results.append({
                "doc_id": did,
                "score": score,
                "title": self.index.doc_store[did].get("title", ""),
                "snippet": self.index.doc_store[did].get("body", "")[:100],
            })

        scored_results.sort(key=lambda x: -x["score"])
        return scored_results[:top_k]
```

### 扩展二：短语查询

利用 positions 信息，可以支持精确的短语查询。短语查询要求多个词项在文档中连续出现。

```python
class PhraseRetriever(BooleanRetriever):
    def search_phrase(self, phrase_tokens: list[str]) -> list[int]:
        """短语查询：要求 phrase_tokens 中的词项在文档中连续出现"""
        if not phrase_tokens:
            return []

        # 获取第一个词项的所有 Posting
        first_postings = {}
        for p in self.index.get_postings(phrase_tokens[0]):
            first_postings[p.doc_id] = p.positions

        result = []
        for doc_id, positions in first_postings.items():
            for start_pos in positions:
                match = True
                for offset in range(1, len(phrase_tokens)):
                    term_postings = {}
                    for p in self.index.get_postings(phrase_tokens[offset]):
                        term_postings[p.doc_id] = p.positions
                    if doc_id not in term_postings:
                        match = False
                        break
                    if (start_pos + offset) not in term_postings[doc_id]:
                        match = False
                        break
                if match:
                    result.append(doc_id)
                    break  # 找到一个匹配就够了

        return sorted(result)
```

### 扩展三：结果高亮

在搜索结果中高亮显示匹配的关键词，帮助用户快速定位相关信息。

```python
def highlight_snippet(text: str, query_terms: list[str], max_length: int = 200) -> str:
    """在文本中高亮显示查询词"""
    # 找到查询词在文本中的位置
    highlights = []
    text_lower = text.lower()
    for term in query_terms:
        term_lower = term.lower()
        start = 0
        while True:
            pos = text_lower.find(term_lower, start)
            if pos == -1:
                break
            highlights.append((pos, pos + len(term)))
            start = pos + 1

    if not highlights:
        return text[:max_length]

    # 按位置排序，合并重叠区间
    highlights.sort()
    merged = [highlights[0]]
    for start, end in highlights[1:]:
        if start <= merged[-1][1]:
            merged[-1] = (merged[-1][0], max(merged[-1][1], end))
        else:
            merged.append((start, end))

    # 截取包含高亮的片段
    center = merged[0][0]
    snippet_start = max(0, center - max_length // 2)
    snippet_end = min(len(text), snippet_start + max_length)
    snippet = text[snippet_start:snippet_end]

    # 调整高亮位置
    offset = snippet_start
    for start, end in merged:
        if start >= snippet_start and end <= snippet_end:
            # 用 ** 包裹高亮词（Markdown 格式）
            snippet = snippet[:start - offset] + f"**{snippet[start - offset:end - offset]}**" + snippet[end - offset:]

    return snippet
```

## 常见误区

1. **忽视测试的重要性**：搜索引擎的正确性很难通过肉眼判断，必须有完整测试。一个分词器的微小改动可能导致索引不匹配，查询结果完全不同。
2. **混淆分词和索引阶段**：分词器的选择直接影响索引质量。如果索引时使用 jieba 分词，查询时使用简单正则分词，会导致"索引中有'机器学习'，但查询'机器学习'时找不到"的问题。
3. **忽略边界情况**：空查询、单字查询、全部被停用词过滤等情况都需要处理。如果查询词全是停用词（如"的了是"），应该返回空结果而非报错。
4. **过早优化**：先保证功能正确，再考虑性能。过早引入缓存、压缩等优化会增加代码复杂度，影响调试。
5. **忽略分词一致性**：索引和查询必须使用同一个分词器实例（或至少配置相同）。这是搜索引擎最常见的 bug 来源。
6. **忘记处理空 Posting List**：当查询词不在索引中时，get_postings 返回空列表。AND 操作遇到空列表应立即返回空结果，OR 操作遇到空列表应跳过。

## 工程建议

1. **模块化设计**：分词器、索引器、查询引擎、持久化模块要解耦。这样可以独立替换任何一个模块（如将 JSON 持久化替换为二进制持久化）而不影响其他模块。
2. **日志和监控**：记录索引耗时、查询耗时，便于定位瓶颈。在生产环境中，查询延迟的 P99 是核心指标。
3. **测试驱动**：先写测试用例，再实现功能。测试用例应该覆盖正常路径和边界情况。
4. **从小规模开始验证**：先用 10 篇文档验证功能，再扩展到 10 万篇验证性能。不要一上来就用百万级数据测试，那样出了 bug 很难定位。
5. **分词器配置外置**：停用词表、自定义词典应该通过配置文件加载，而非硬编码在代码中。不同业务场景需要不同的分词配置。
6. **索引版本管理**：当索引格式发生变化时（如新增字段），需要有版本号和迁移机制，避免旧索引无法加载。

### 练习一

**思路**：遍历第一个词项的 Posting List，检查后续词项是否在对应位置连续出现。

```python
def search_phrase(self, phrase_tokens: list[str]) -> list[int]:
    if not phrase_tokens:
        return []
    first_postings = {p.doc_id: p.positions for p in self.index.get_postings(phrase_tokens[0])}
    result = []
    for doc_id, positions in first_postings.items():
        for start_pos in positions:
            match = True
            for offset in range(1, len(phrase_tokens)):
                term_postings = {p.doc_id: p.positions for p in self.index.get_postings(phrase_tokens[offset])}
                if doc_id not in term_postings or (start_pos + offset) not in term_postings[doc_id]:
                    match = False; break
            if match:
                result.append(doc_id); break
    return sorted(result)
```

**要点**：先用第一个词项缩小候选范围；短语查询可和 AND 查询结合使用。如果查询是 `"机器学习" AND 深度`，先用短语查询找到包含"机器学习"的文档，再用 AND 过滤出同时包含"深度"的文档。

```python
import math

def compute_tfidf_score(self, query_terms: list[str], doc_id: int) -> float:
    score = 0.0
    doc_length = self.index.doc_lengths.get(doc_id, 1)
    for term in query_terms:
        postings = self.index.get_postings(term)
        tf = 0
        for p in postings:
            if p.doc_id == doc_id:
                tf = p.term_freq; break
        if tf == 0:
            continue
        df = len(postings)
        idf = math.log(self.index.doc_count / (df + 1)) + 1
        score += (tf / doc_length) * idf
    return score

```

**要点**：TF 使用归一化词频避免长文档不公平；IDF 使用平滑避免除零；这是 BM25 的简化版本。完整的 BM25 还包含参数 k1 和 b 来调节词频饱和度和文档长度归一化程度。

### 练习三

**思路**：计算查询词与索引中所有词项的编辑距离，返回距离最小的词项。

```python
def levenshtein_distance(s1: str, s2: str) -> int:
    """计算两个字符串的编辑距离"""
    if len(s1) < len(s2):
        return levenshtein_distance(s2, s1)

    if len(s2) == 0:
        return len(s1)

    previous_row = range(len(s2) + 1)
    for i, c1 in enumerate(s1):
        current_row = [i + 1]
        for j, c2 in enumerate(s2):
            insertions = previous_row[j + 1] + 1
            deletions = current_row[j] + 1
            substitutions = previous_row[j] + (c1 != c2)
            current_row.append(min(insertions, deletions, substitutions))
        previous_row = current_row

    return previous_row[-1]


def suggest_corrections(self, query_term: str, max_suggestions: int = 3) -> list[str]:
    """推荐与 query_term 相似的词项"""
    if query_term in self.index.index:
        return [query_term]  # 词项已存在，无需推荐

    # 计算与所有词项的编辑距离
    distances = []
    for term in self.index.index:
        # 只考虑长度相近的词项，减少计算量
        if abs(len(term) - len(query_term)) > 2:
            continue
        dist = levenshtein_distance(query_term, term)
        if dist <= 2:  # 只推荐距离 ≤ 2 的词项
            distances.append((dist, term))

    distances.sort()
    return [term for _, term in distances[:max_suggestions]]
```

**要点**：编辑距离计算的时间复杂度为 O(n × m)，对大规模词典需要优化。实际系统中可以使用 SymSpell 或 Norvig 的拼写纠正算法，通过预计算将查找时间降低到 O(1)。

### 练习五

**思路**：为每个字段维护独立的倒排索引，查询时按字段路由。

```python
class MultiFieldSearchEngine:
    def __init__(self, fields: list[str] = None, stopwords: set[str] = None):
        self.fields = fields or ["title", "body"]
        self.tokenizer = Tokenizer(stopwords)
        self.field_indexes: dict[str, InvertedIndex] = {f: InvertedIndex() for f in self.fields}
        self.doc_store: dict[int, dict] = {}

    def add_document(self, doc_id: int, field_values: dict[str, str]):
        self.doc_store[doc_id] = field_values
        for field_name, text in field_values.items():
            if field_name in self.field_indexes:
                terms = self.tokenizer.tokenize(text)
                self.field_indexes[field_name].add_document(doc_id, terms)

    def search(self, query: str) -> list[dict]:
        # 解析字段查询，如 "title:Python AND body:机器学习"
        field_queries = re.findall(r'(\w+):(\S+)', query)
        if not field_queries:
            # 没有字段指定，搜索所有字段
            all_ids = set()
            for field_index in self.field_indexes.values():
                terms = self.tokenizer.tokenize(query)
                for term in terms:
                    for p in field_index.get_postings(term):
                        all_ids.add(p.doc_id)
            return [{"doc_id": did, **self.doc_store.get(did, {})} for did in sorted(all_ids)]

        # 按字段分别查询，取交集
        result_sets = []
        for field_name, term_text in field_queries:
            if field_name not in self.field_indexes:
                continue
            terms = self.tokenizer.tokenize(term_text)
            field_ids = set()
            for term in terms:
                for p in self.field_indexes[field_name].get_postings(term):
                    field_ids.add(p.doc_id)
            result_sets.append(field_ids)

        if not result_sets:
            return []

        common_ids = set.intersection(*result_sets)
        return [{"doc_id": did, **self.doc_store.get(did, {})} for did in sorted(common_ids)]
```

**要点**：多字段索引是 Elasticsearch 等分布式搜索引擎的核心特性。字段级搜索可以让用户精确控制搜索范围，如"只在标题中搜索 Python"或"在标签中搜索 机器学习"。实现时需要注意字段间的查询是 AND 语义还是 OR 语义。
