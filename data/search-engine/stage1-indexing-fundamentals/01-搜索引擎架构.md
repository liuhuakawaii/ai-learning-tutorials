# 搜索引擎架构

## 场景引入

当你在搜索引擎中输入"如何学习 Python"，不到一秒就拿到了数十亿网页中最相关的十条结果。这背后发生了什么？

一个最朴素的想法是：把互联网上所有网页都下载下来，用户搜索时逐个扫描。假设网页总数为 100 亿，每篇 1KB，扫描一遍需要读取约 10TB 数据——即使用 NVMe SSD（读取速度 3GB/s），也需要约 55 分钟。用户不可能等这么久。

搜索引擎的核心思路是**提前建好索引**，就像书本的目录一样。用户查询时不用翻遍全书，只需查目录就能定位到相关章节。这就是**倒排索引**的由来，也是整个搜索引擎架构的核心。

### 搜索引擎简史

理解搜索引擎架构，有必要回顾它的发展历程：

- **1990 年 Archie**：第一个互联网搜索工具，只索引 FTP 文件名，不索引内容。核心思路已经是对文件名建立索引而非逐个扫描。
- **1994 年 WebCrawler**：第一个全文索引的搜索引擎，开始抓取并索引网页正文。此时网页数量只有几万，单机就能搞定。
- **1998 年 Google**：Larry Page 和 Sergey Brin 提出 PageRank，用链接关系衡量网页权威性。这是排序层从"关键词匹配"到"质量评估"的飞跃。同时引入 MapReduce 做大规模索引构建，奠定了现代搜索引擎的分布式架构。
- **2010s Elasticsearch/Lucene**：开源搜索引擎走向成熟，倒排索引 + Segment 架构成为标准。Elasticsearch 的分布式设计让中小团队也能搭建搜索引擎。
- **2020s 向量检索兴起**：随着 BERT 等模型的出现，语义检索（向量近邻搜索）开始与传统关键词检索融合，形成混合检索架构。

从 Archie 到今天，搜索引擎的核心架构始终是：**离线建索引 → 在线查索引 → 排序返回**。变化的是规模、排序算法和检索方式，不变的是"用离线计算换在线速度"这个根本思想。

## 搜索引擎整体架构

一个完整的搜索引擎可以拆分为四个核心阶段：

```
┌─────────────────────────────────────────────────────────┐
│                    用户查询 (Query)                       │
│                        │                                │
│                        ▼                                │
│              ┌─────────────────┐                        │
│              │   查询解析器     │  分词、纠错、扩展        │
│              └────────┬────────┘                        │
│                       ▼                                 │
│              ┌─────────────────┐                        │
│              │    检索层        │  从倒排索引中召回文档     │
│              └────────┬────────┘                        │
│                       ▼                                 │
│              ┌─────────────────┐                        │
│              │    排序层        │  精排、重排序            │
│              └────────┬────────┘                        │
│                       ▼                                 │
│              ┌─────────────────┐                        │
│              │    结果展示      │  摘要、高亮、分页        │
│              └─────────────────┘                        │
└─────────────────────────────────────────────────────────┘
```

数据离线处理流程（建索引）：

```
 互联网网页                                    倒排索引
    │                                            ▲
    ▼                                            │
┌────────┐   ┌────────┐   ┌────────┐   ┌────────────┐
│ 爬虫   │──▶│ 解析器  │──▶│ 分词器  │──▶│ 索引构建器  │
│ Crawler│   │ Parser │   │Tokenizer│   │ Indexer    │
└────────┘   └────────┘   └────────┘   └────────────┘
   抓取网页     提取正文     生成词项      写入索引
   去重过滤     清洗数据     去停用词      压缩存储
```

## 各组件职责

### 1. 爬虫（Crawler）

爬虫负责从互联网上自动抓取网页内容。核心挑战包括：

- **URL 调度**：决定先抓哪些页面，如何发现新链接
- **去重**：通过 URL 去重或内容指纹（SimHash）避免重复抓取
- **礼貌性**：遵守 robots.txt，控制对同一域名的抓取频率
- **增量更新**：识别已变化的页面，优先重新抓取

```python
import hashlib
from urllib.parse import urlparse


class SimpleCrawler:
    """最简爬虫骨架，演示核心流程"""

    def __init__(self):
        self.visited = set()       # 已访问URL集合
        self.url_queue = []        # 待抓取URL队列
        self.page_store = {}       # 页面存储

    def url_fingerprint(self, url: str) -> str:
        """URL去重：计算URL指纹"""
        normalized = url.strip().lower().rstrip("/")
        return hashlib.md5(normalized.encode()).hexdigest()

    def should_crawl(self, url: str) -> bool:
        """判断是否需要抓取该URL"""
        fp = self.url_fingerprint(url)
        if fp in self.visited:
            return False
        parsed = urlparse(url)
        if parsed.scheme not in ("http", "https"):
            return False
        return True

    def fetch_page(self, url: str) -> dict | None:
        """模拟抓取页面，返回页面数据"""
        if not self.should_crawl(url):
            return None
        fp = self.url_fingerprint(url)
        self.visited.add(fp)
        # 实际场景中这里会发起HTTP请求
        return {"url": url, "content": "", "title": "", "links": []}

    def add_to_queue(self, urls: list[str]):
        """将新发现的URL加入队列"""
        for url in urls:
            if self.url_fingerprint(url) not in self.visited:
                self.url_queue.append(url)
```

### 2. 解析器（Parser）

解析器将原始 HTML 转换为结构化数据：提取标题、正文、链接、发布时间等。

```python
from html.parser import HTMLParser


class SimpleHTMLParser(HTMLParser):
    """提取HTML中的文本内容"""

    def __init__(self):
        super().__init__()
        self.title = ""
        self.body_parts = []
        self._in_title = False
        self._skip_tags = {"script", "style", "nav", "footer"}
        self._current_tag = None

    def handle_starttag(self, tag, attrs):
        self._current_tag = tag
        if tag == "title":
            self._in_title = True

    def handle_endtag(self, tag):
        if tag == "title":
            self._in_title = False
        self._current_tag = None

    def handle_data(self, data):
        if self._in_title:
            self.title += data.strip()
        elif self._current_tag not in self._skip_tags:
            text = data.strip()
            if text:
                self.body_parts.append(text)

    def get_result(self) -> dict:
        return {
            "title": self.title,
            "body": " ".join(self.body_parts),
        }
```

### 3. 分词器（Tokenizer）

分词器将文本拆分为词项（terms），这是构建倒排索引的基础。中文需要专门的分词工具。

```python
def simple_tokenize(text: str) -> list[str]:
    """简单分词：按空格和标点切分（仅适用于英文）"""
    import re
    tokens = re.findall(r"[a-zA-Z0-9]+", text.lower())
    return tokens
```

### 4. 索引构建器（Indexer）

索引构建器将分词结果写入倒排索引，建立从词项到文档的映射。

```python
from collections import defaultdict


class SimpleIndexer:
    """最简索引构建器"""

    def __init__(self):
        self.inverted_index = defaultdict(list)  # term -> [doc_id, ...]
        self.doc_store = {}                       # doc_id -> 文档元数据

    def add_document(self, doc_id: int, terms: list[str], metadata: dict = None):
        """将文档加入索引"""
        self.doc_store[doc_id] = metadata or {}
        seen = set()
        for position, term in enumerate(terms):
            if term not in seen:
                self.inverted_index[term].append(doc_id)
                seen.add(term)

    def search(self, query_terms: list[str]) -> list[int]:
        """检索包含所有查询词项的文档"""
        if not query_terms:
            return []
        result_sets = [set(self.inverted_index.get(t, [])) for t in query_terms]
        if not result_sets:
            return []
        return list(set.intersection(*result_sets))
```

### 5. 查询解析器（Query Parser）

查询解析器负责理解用户意图，将原始查询转换为检索层能理解的结构化请求。这是搜索引擎中"最靠近用户"的组件，直接影响搜索体验。

```python
import re


class SimpleQueryParser:
    """查询解析器：分词 + 纠错 + 查询改写"""

    def __init__(self, vocabulary: set[str] = None):
        self.vocabulary = vocabulary or set()

    def parse(self, query: str) -> dict:
        """解析查询，返回结构化结果"""
        # 1. 基础清洗
        query = query.strip().lower()
        query = re.sub(r'[^\w\s\u4e00-\u9fff]', ' ', query)

        # 2. 分词
        tokens = self._tokenize(query)

        # 3. 纠错（简化版：编辑距离检查）
        corrected = []
        corrections = {}
        for token in tokens:
            suggestion = self._spell_check(token)
            if suggestion != token:
                corrections[token] = suggestion
            corrected.append(suggestion)

        # 4. 构建查询结构
        return {
            "original": query,
            "tokens": corrected,
            "corrections": corrections,
            "is_corrected": len(corrections) > 0,
        }

    def _tokenize(self, text: str) -> list[str]:
        """简单分词：按空格切分"""
        return [t for t in text.split() if t]

    def _spell_check(self, word: str) -> str:
        """基于编辑距离的拼写检查"""
        if word in self.vocabulary:
            return word
        # 查找编辑距离为1的最近词（简化实现）
        best_match = word
        best_dist = 2  # 只纠正编辑距离为1的错误
        for vocab_word in self.vocabulary:
            dist = self._edit_distance(word, vocab_word)
            if dist < best_dist:
                best_dist = dist
                best_match = vocab_word
        return best_match

    @staticmethod
    def _edit_distance(s1: str, s2: str) -> int:
        """计算两个字符串的编辑距离"""
        m, n = len(s1), len(s2)
        dp = [[0] * (n + 1) for _ in range(m + 1)]
        for i in range(m + 1):
            dp[i][0] = i
        for j in range(n + 1):
            dp[0][j] = j
        for i in range(1, m + 1):
            for j in range(1, n + 1):
                cost = 0 if s1[i-1] == s2[j-1] else 1
                dp[i][j] = min(dp[i-1][j] + 1, dp[i][j-1] + 1, dp[i-1][j-1] + cost)
        return dp[m][n]


# 使用示例
vocab = {"python", "java", "搜索引擎", "倒排索引", "编程", "教程"}
parser = SimpleQueryParser(vocabulary=vocab)
result = parser.parse("pythn 编程教程")
print(result)
# {'original': 'pythn 编程教程', 'tokens': ['python', '编程', '教程'], 'corrections': {'pythn': 'python'}, 'is_corrected': True}
```

查询解析器的设计权衡：纠错功能太激进会"好心办坏事"（用户搜 "Rust" 被纠正为 "dust"），太保守则体验差。生产环境通常会展示"你是不是想搜 XXX"而不是自动替换。

## 最小搜索引擎骨架

把以上组件串联起来，形成一个完整的搜索引擎：

```python
class MiniSearchEngine:
    """最小搜索引擎，演示完整pipeline"""

    def __init__(self):
        self.indexer = SimpleIndexer()
        self.next_doc_id = 0

    def index_document(self, title: str, body: str):
        """索引一篇文档"""
        doc_id = self.next_doc_id
        self.next_doc_id += 1
        text = f"{title} {body}"
        terms = simple_tokenize(text)
        self.indexer.add_document(doc_id, terms, {"title": title})
        return doc_id

    def search(self, query: str) -> list[dict]:
        """搜索并返回结果"""
        query_terms = simple_tokenize(query)
        doc_ids = self.indexer.search(query_terms)
        results = []
        for doc_id in doc_ids:
            meta = self.indexer.doc_store[doc_id]
            results.append({"doc_id": doc_id, "title": meta.get("title", "")})
        return results


# 使用示例
engine = MiniSearchEngine()
engine.index_document("Python入门教程", "Python是一种通用编程语言，适合初学者学习")
engine.index_document("Java高级编程", "Java是一种面向对象的编程语言，广泛用于企业开发")
engine.index_document("机器学习基础", "机器学习是人工智能的核心分支，Python是最常用的语言")

results = engine.search("Python 编程")
for r in results:
    print(f"文档{r['doc_id']}: {r['title']}")
```

输出：
```
文档0: Python入门教程
文档1: Java高级编程
文档2: 机器学习基础
```

## 在线查询服务

搜索引擎的在线服务需要在极低延迟下完成查询处理。一个典型的搜索请求需要经过以下步骤：

```
用户请求 → 负载均衡 → 查询解析 → 检索召回 → 排序 → 结果拼装 → 返回
            (1ms)      (5ms)      (20ms)     (50ms)   (5ms)     (1ms)
```

整个链路的 P99 延迟通常要求在 200ms 以内。这意味着每个环节都有严格的延迟预算。

```python
import time


class SearchService:
    """在线查询服务，演示延迟监控"""

    def __init__(self, engine: MiniSearchEngine):
        self.engine = engine
        self.query_cache = {}  # 简单的查询缓存

    def search(self, query: str) -> dict:
        start_total = time.perf_counter()

        # 1. 检查缓存
        cache_key = query.strip().lower()
        if cache_key in self.query_cache:
            return {
                "results": self.query_cache[cache_key],
                "latency_ms": (time.perf_counter() - start_total) * 1000,
                "cache_hit": True,
            }

        # 2. 查询解析
        start = time.perf_counter()
        query_terms = simple_tokenize(query)
        parse_ms = (time.perf_counter() - start) * 1000

        # 3. 检索
        start = time.perf_counter()
        doc_ids = self.engine.indexer.search(query_terms)
        retrieve_ms = (time.perf_counter() - start) * 1000

        # 4. 结果拼装
        start = time.perf_counter()
        results = []
        for doc_id in doc_ids:
            meta = self.engine.indexer.doc_store[doc_id]
            results.append({"doc_id": doc_id, "title": meta.get("title", "")})
        assemble_ms = (time.perf_counter() - start) * 1000

        # 5. 写入缓存
        self.query_cache[cache_key] = results

        total_ms = (time.perf_counter() - start_total) * 1000
        return {
            "results": results,
            "latency_ms": round(total_ms, 3),
            "breakdown": {
                "parse_ms": round(parse_ms, 3),
                "retrieve_ms": round(retrieve_ms, 3),
                "assemble_ms": round(assemble_ms, 3),
            },
            "cache_hit": False,
        }


# 使用示例
service = SearchService(engine)
response = service.search("Python 编程")
print(f"结果数: {len(response['results'])}")
print(f"总耗时: {response['latency_ms']}ms")
print(f"分阶段: {response['breakdown']}")
print(f"缓存命中: {response['cache_hit']}")

# 第二次查询命中缓存
response2 = service.search("Python 编程")
print(f"第二次耗时: {response2['latency_ms']}ms, 缓存命中: {response2['cache_hit']}")
```

延迟监控是搜索引擎运维的核心。在生产环境中，每个阶段的耗时都需要上报到监控系统（如 Prometheus），设置告警阈值。当某个阶段延迟突增时，需要快速定位是索引数据量增长、缓存失效还是机器负载过高。

## 各组件的工程挑战

| 组件 | 核心挑战 | 常见方案 |
|------|---------|---------|
| 爬虫 | 海量URL去重、增量抓取 | Bloom Filter、优先级队列 |
| 解析器 | 乱码处理、JS渲染页面 | BeautifulSoup、Playwright |
| 分词器 | 中文歧义切分、新词识别 | jieba、HanLP、BERT分词 |
| 索引构建 | 内存不足、构建速度 | BSBI/SPIMI、多路归并 |
| 检索层 | 查询延迟、召回率 | 倒排索引、缓存热查询 |
| 排序层 | 相关性、时效性、权威性 | BM25、Learning to Rank |

## 常见误区

1. **认为搜索引擎就是数据库查询**：数据库的 B+ 树索引适合精确匹配，而搜索引擎需要处理自然语言的模糊匹配、相关性排序。
2. **忽视离线处理的重要性**：搜索引擎 80% 的工作在离线索引构建阶段，而非在线查询阶段。
3. **认为分词只是按空格切分**：中文没有天然分隔符，需要专门的分词算法。
4. **混淆召回和排序**：检索层负责快速召回候选文档（追求高召回率），排序层负责精排（追求高精确率）。
5. **混淆召回率和精确率**：召回率是"该找到的都找到了吗"，精确率是"找到的都是对的吗"。搜索引擎通常先追求高召回（宁多勿漏），再通过排序提高精确率。
6. **过早引入分布式架构**：单机倒排索引可以支撑千万级文档查询。很多团队在数据量不到百万时就引入 Elasticsearch 集群，增加了运维复杂度却没带来实际收益。
7. **忽略缓存预热**：搜索引擎重启后，热查询缓存为空，大量请求直接打到索引层，可能导致延迟飙升甚至雪崩。上线前需要用历史查询做缓存预热。

## 工程建议

1. **先搭骨架再优化**：用最简单的实现跑通完整 pipeline，再逐步替换各组件为生产级方案。
2. **分离离线和在线**：索引构建是离线批处理，查询服务是在线低延迟，两者的工程要求完全不同。
3. **监控每个阶段的延迟**：在生产环境中，需要分别监控分词耗时、检索耗时、排序耗时，定位瓶颈。
4. **从单机开始，按需扩展**：单机倒排索引可以支撑千万级文档，不要过早引入分布式。
5. **建立 A/B 测试框架**：搜索引擎的优化（如新的排序算法、分词策略）必须通过 A/B 测试验证效果，不能凭感觉上线。核心指标包括：点击率（CTR）、无结果率、平均点击位置。
6. **容量规划要提前做**：索引大小通常比原始文档大 30%-50%（包含倒排索引 + 正排数据 + 元数据）。需要根据文档增长速度预估未来 6 个月的存储需求。
7. **设计降级策略**：当排序服务不可用时，能否退化为仅按 TF 排序？当缓存失效时，索引层能否承受全量请求？降级策略是生产系统的安全网。

## 小结

本节课我们从宏观视角了解了搜索引擎的四大核心组件：

- **爬虫**：负责从互联网获取原始数据
- **解析器**：将 HTML 转换为结构化文本
- **分词器**：将文本切分为词项
- **索引构建器**：建立词项到文档的倒排映射

在线查询阶段包含**查询解析 → 检索 → 排序 → 展示**四个步骤。整个系统的核心思想是：**用离线计算换取在线速度**。

### 练习一

**思路**：在索引构建时记录每个词项在每篇文档中的出现次数，搜索时根据 TF 排序。

**答案**：

```python
from collections import defaultdict, Counter


class TFSearchEngine:
    def __init__(self):
        self.inverted_index = defaultdict(list)
        self.doc_store = {}
        self.doc_tf = {}           # doc_id -> {term: count}
        self.next_doc_id = 0

    def index_document(self, title: str, body: str):
        doc_id = self.next_doc_id
        self.next_doc_id += 1
        text = f"{title} {body}"
        terms = simple_tokenize(text)
        tf = Counter(terms)
        self.doc_tf[doc_id] = tf
        self.doc_store[doc_id] = {"title": title}
        seen = set()
        for term in terms:
            if term not in seen:
                self.inverted_index[term].append(doc_id)
                seen.add(term)
        return doc_id

    def search(self, query: str) -> list[dict]:
        query_terms = simple_tokenize(query)
        if not query_terms:
            return []
        result_sets = [set(self.inverted_index.get(t, [])) for t in query_terms]
        doc_ids = set.intersection(*result_sets) if result_sets else set()
        results = []
        for doc_id in doc_ids:
            tf = self.doc_tf[doc_id]
            total_tf = sum(tf.get(t, 0) for t in query_terms)
            results.append({
                "doc_id": doc_id,
                "title": self.doc_store[doc_id]["title"],
                "total_tf": total_tf,
                "detail_tf": {t: tf.get(t, 0) for t in query_terms},
            })
        results.sort(key=lambda x: x["total_tf"], reverse=True)
        return results
```

**要点**：
- 使用 `Counter` 统计词频，存储开销很小
- 搜索时对查询词项的 TF 求和作为排序依据
- 这只是最简单的相关性模型，后续课程会学习 BM25 等更精确的公式

### 练习二

**思路**：采用"双索引 + 切换"策略，将离线构建和在线服务解耦。

**答案**：

增量索引更新方案：

1. **内存缓冲区**：新文章先写入内存中的增量索引（RAM Buffer），支持实时查询
2. **定时全量重建**：每隔一段时间（如 5 分钟），将增量索引合并到主索引中
3. **原子切换**：新索引构建完成后，通过原子指针切换将查询路由到新索引，旧索引随后释放

```
新文章 ──▶ 增量索引(RAM) ──▶ 定时合并 ──▶ 新磁盘索引
                                              │
查询请求 ──▶ 路由层 ──▶ 主索引(磁盘) ◀── 原子切换
                        └──▶ 增量索引(RAM) 作为补充
```

组件改动：
- **索引构建器**：支持增量写入和合并操作
- **查询路由**：同时查询主索引和增量索引，合并结果去重
- **调度器**：定时触发索引合并和切换

**要点**：
- 增量索引保证新文章快速可搜，全量重建保证索引质量
- 原子切换避免查询中断，这是 Lucene 的 Segment 策略的核心思想
- 被修改的文章需要在主索引中标记为删除（Tombstone），在增量索引中重新索引

### 练习三

**思路**：按规则逐步规范化 URL 的各个部分。

**答案**：

```python
from urllib.parse import urlparse, urlunparse, urlencode, parse_qs


def normalize_url(url: str) -> str:
    parsed = urlparse(url)

    # 统一协议为 https
    scheme = "https"

    # 去除默认端口
    netloc = parsed.netloc
    if netloc.endswith(":443"):
        netloc = netloc[:-4]
    elif netloc.endswith(":80"):
        netloc = netloc[:-3]

    # 去除尾部斜杠
    path = parsed.path.rstrip("/") or "/"

    # 查询参数按字母排序
    query_params = parse_qs(parsed.query, keep_blank_values=True)
    sorted_query = urlencode(sorted(query_params.items()), doseq=True)

    # 去除 fragment
    return urlunparse((scheme, netloc, path, "", sorted_query, ""))


# 测试
print(normalize_url("http://Example.COM:443/path/?b=2&a=1#section"))
# https://example.com/path?a=1&b=2
```

**要点**：
- URL 规范化是去重的前提，同一个页面可能有多种 URL 表示
- 生产环境中还需要处理 URL 编码、大小写统一、参数白名单过滤等

### 练习四

**思路**：使用 `OrderedDict` 实现 LRU 缓存，利用其维护插入顺序的特性。

**答案**：

```python
from collections import OrderedDict


class LRUCache:
    def __init__(self, capacity: int = 1000):
        self.capacity = capacity
        self.cache = OrderedDict()

    def get(self, key: str):
        if key in self.cache:
            self.cache.move_to_end(key)
            return self.cache[key]
        return None

    def put(self, key: str, value):
        if key in self.cache:
            self.cache.move_to_end(key)
        self.cache[key] = value
        if len(self.cache) > self.capacity:
            self.cache.popitem(last=False)


# 集成到 SearchService
class CachedSearchService:
    def __init__(self, engine: MiniSearchEngine, cache_size: int = 1000):
        self.engine = engine
        self.cache = LRUCache(capacity=cache_size)

    def search(self, query: str) -> dict:
        cache_key = query.strip().lower()
        cached = self.cache.get(cache_key)
        if cached is not None:
            return {"results": cached, "cache_hit": True}

        query_terms = simple_tokenize(query)
        doc_ids = self.engine.indexer.search(query_terms)
        results = [{"doc_id": did, "title": self.engine.indexer.doc_store[did].get("title", "")} for did in doc_ids]
        self.cache.put(cache_key, results)
        return {"results": results, "cache_hit": False}
```

**要点**：
- `OrderedDict` 的 `move_to_end` 和 `popitem(last=False)` 是 LRU 的标准实现方式
- 缓存 key 需要规范化（去空格、转小写），避免相同查询因大小写不同而重复缓存

### 练习五

**思路**：用滑动窗口找到包含最多查询词的文本片段。

**答案**：

```python
def generate_snippet(query_terms: list[str], text: str, max_length: int = 200) -> str:
    """生成搜索结果摘要，高亮匹配的查询词"""
    sentences = text.replace("。", "。\n").replace("！", "！\n").replace("？", "？\n").split("\n")
    sentences = [s.strip() for s in sentences if s.strip()]

    best_score = 0
    best_text = ""

    # 滑动窗口找最佳句子组合
    for i in range(len(sentences)):
        combined = ""
        score = 0
        for j in range(i, min(i + 3, len(sentences))):
            combined += sentences[j]
            for term in query_terms:
                if term in sentences[j]:
                    score += 1
            if len(combined) >= max_length:
                break
        if score > best_score:
            best_score = score
            best_text = combined

    # 截断到最大长度
    if len(best_text) > max_length:
        best_text = best_text[:max_length] + "..."

    # 高亮匹配词
    for term in query_terms:
        best_text = best_text.replace(term, f"**{term}**")

    return best_text


# 测试
text = "Python是一种通用编程语言。它广泛应用于Web开发、数据科学和人工智能领域。Python的语法简洁易学。"
print(generate_snippet(["Python", "人工智能"], text))
# Python是一种通用编程语言。它广泛应用于Web开发、数据科学和**人工智能**领域。
```

**要点**：
- 滑动窗口是一种简单有效的摘要策略，生产环境中通常用更精细的句子评分算法
- 高亮替换需要在截断之后进行，避免截断导致标记不完整
