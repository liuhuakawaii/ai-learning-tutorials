# 搜索引擎架构

一个搜索请求从输入到结果展示，背后经历了什么？这节课用 Python 搭出搜索引擎的最小骨架，跑通从"建索引"到"查索引"的完整链路。

## 核心问题：为什么不能逐个扫描

假设网页总数 100 亿，每篇 1KB，扫描一遍需要读取约 10TB 数据。即使用 NVMe SSD（3GB/s），也需要约 55 分钟。用户不可能等这么久。

搜索引擎的核心思路是**提前建好索引**——像书本的目录一样。用户查询时不用翻遍全书，只需查目录就能定位到相关章节。从 1990 年的 Archie 到今天的 Elasticsearch，核心架构始终是：**离线建索引 → 在线查索引 → 排序返回**。变化的是规模和排序算法，不变的是"用离线计算换在线速度"。

## 整体架构

```
离线（建索引）：
  爬虫 → 解析器 → 分词器 → 索引构建器 → 倒排索引

在线（查索引）：
  用户查询 → 查询解析 → 检索层 → 排序层 → 结果展示
```

四个核心组件各司其职：

| 组件 | 职责 | 核心挑战 |
|------|------|----------|
| 爬虫 | 抓取网页 | URL 去重、礼貌性、增量更新 |
| 解析器 | 提取正文 | 乱码处理、JS 渲染页面 |
| 分词器 | 文本切词 | 中文歧义切分、新词识别 |
| 索引构建器 | 建立倒排映射 | 内存不足、构建速度 |

## 实验：用 Python 搭建最小搜索引擎

下面的代码是一个可运行的搜索引擎骨架。它不做任何优化，目的是让你看到数据如何流过每个组件。

```python
import re
from collections import defaultdict


def tokenize(text: str) -> list[str]:
    return re.findall(r"[\u4e00-\u9fff]+|[a-zA-Z0-9]+", text.lower())


class MiniSearchEngine:
    def __init__(self):
        self.inverted_index = defaultdict(list)
        self.doc_store = {}
        self.next_id = 0

    def index(self, title: str, body: str) -> int:
        doc_id = self.next_id
        self.next_id += 1
        terms = tokenize(f"{title} {body}")
        self.doc_store[doc_id] = {"title": title, "body": body}
        seen = set()
        for term in terms:
            if term not in seen:
                self.inverted_index[term].append(doc_id)
                seen.add(term)
        return doc_id

    def search(self, query: str) -> list[dict]:
        terms = tokenize(query)
        if not terms:
            return []
        candidates = [set(self.inverted_index.get(t, [])) for t in terms]
        doc_ids = set.intersection(*candidates) if candidates else set()
        return [{"doc_id": did, "title": self.doc_store[did]["title"]}
                for did in sorted(doc_ids)]
```

## 实验：测量各阶段耗时

搜索引擎的在线服务需要在极低延迟下完成查询。一个典型搜索请求的延迟预算：

```
查询解析(5ms) → 检索(20ms) → 排序(50ms) → 结果拼装(5ms)
整个链路 P99 通常要求 200ms 以内
```

下面的代码为搜索引擎加上延迟监控：

```python
import time


class MonitoredSearchEngine(MiniSearchEngine):
    def search(self, query: str) -> dict:
        start = time.perf_counter()

        t0 = time.perf_counter()
        terms = tokenize(query)
        parse_ms = (time.perf_counter() - t0) * 1000

        t0 = time.perf_counter()
        candidates = [set(self.inverted_index.get(t, [])) for t in terms]
        doc_ids = set.intersection(*candidates) if candidates else set()
        retrieve_ms = (time.perf_counter() - t0) * 1000

        t0 = time.perf_counter()
        results = [{"doc_id": did, "title": self.doc_store[did]["title"]}
                   for did in sorted(doc_ids)]
        assemble_ms = (time.perf_counter() - t0) * 1000

        total_ms = (time.perf_counter() - start) * 1000
        return {
            "results": results,
            "latency_ms": round(total_ms, 3),
            "breakdown": {"parse": round(parse_ms, 3),
                          "retrieve": round(retrieve_ms, 3),
                          "assemble": round(assemble_ms, 3)},
        }
```

在生产环境中，每个阶段的耗时都需要上报到监控系统（如 Prometheus），设置告警阈值。当某个阶段延迟突增时，需要快速定位是索引数据量增长、缓存失效还是机器负载过高。

## 查询解析器：最靠近用户的组件

查询解析器负责理解用户意图。它的设计权衡很微妙：纠错功能太激进会"好心办坏事"（用户搜 "Rust" 被纠正为 "dust"），太保守则体验差。

```python
class SimpleQueryParser:
    def __init__(self, vocabulary: set[str]):
        self.vocab = vocabulary

    def parse(self, query: str) -> dict:
        query = query.strip().lower()
        tokens = tokenize(query)
        corrections = {}
        corrected = []
        for token in tokens:
            suggestion = self._spell_check(token)
            if suggestion != token:
                corrections[token] = suggestion
            corrected.append(suggestion)
        return {"tokens": corrected, "corrections": corrections}

    def _spell_check(self, word: str) -> str:
        if word in self.vocab:
            return word
        best, best_dist = word, 2
        for v in self.vocab:
            dist = self._edit_distance(word, v)
            if dist < best_dist:
                best, best_dist = v, dist
        return best

    @staticmethod
    def _edit_distance(s1: str, s2: str) -> int:
        m, n = len(s1), len(s2)
        dp = list(range(n + 1))
        for i in range(1, m + 1):
            prev, dp[0] = dp[0], i
            for j in range(1, n + 1):
                cost = 0 if s1[i-1] == s2[j-1] else 1
                prev, dp[j] = dp[j], min(dp[j] + 1, dp[j-1] + 1, prev + cost)
        return dp[n]
```

生产环境通常会展示"你是不是想搜 XXX"而不是自动替换。

## 搜索引擎简史：不变的架构思想

| 年代 | 代表 | 核心突破 |
|------|------|----------|
| 1990 | Archie | 第一个索引工具，只索引文件名 |
| 1994 | WebCrawler | 第一个全文索引搜索引擎 |
| 1998 | Google | PageRank：用链接关系衡量网页权威性 |
| 2010s | Elasticsearch | 倒排索引 + Segment 架构走向成熟 |
| 2020s | 向量检索兴起 | BERT 语义检索与关键词检索融合 |

从 Archie 到今天，搜索引擎的核心架构始终是：**离线建索引 → 在线查索引 → 排序返回**。

## 常见误区

**搜索引擎就是数据库查询。** 数据库的 B+ 树索引适合精确匹配，搜索引擎需要处理自然语言的模糊匹配和相关性排序。

**分词只是按空格切分。** 中文没有天然分隔符，需要专门的分词算法。"机器学习"不能被切成"机/器/学/习"。

**混淆召回和排序。** 检索层负责快速召回候选文档（追求高召回率），排序层负责精排（追求高精确率）。两者的工程要求完全不同。

**过早引入分布式。** 单机倒排索引可以支撑千万级文档查询。很多团队在数据量不到百万时就引入 Elasticsearch 集群，增加了运维复杂度却没带来实际收益。

### 练习二：实现 LRU 查询缓存

为搜索引擎实现一个 LRU 缓存，缓存最近 100 次查询的结果。用 `OrderedDict` 实现。

```python
from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity: int = 100):
        self.cache = OrderedDict()
        self.capacity = capacity

    def get(self, key: str):
        if key in self.cache:
            self.cache.move_to_end(key)
            return self.cache[key]
        return None

    def put(self, key: str, value):
        if key in self.cache:
            self.cache.move_to_end(key)
        self.cache[key] = value
        if len(self.cache) > self.capacity:
            self.cache.popitem(last=False)
```

### 练习一

```python
from collections import Counter

class TFSearchEngine(MiniSearchEngine):
    def __init__(self):
        super().__init__()
        self.doc_tf = {}

    def index(self, title: str, body: str) -> int:
        doc_id = super().index(title, body)
        terms = tokenize(f"{title} {body}")
        self.doc_tf[doc_id] = Counter(terms)
        return doc_id

    def search(self, query: str) -> list[dict]:
        terms = tokenize(query)
        if not terms:
            return []
        candidates = [set(self.inverted_index.get(t, [])) for t in terms]
        doc_ids = set.intersection(*candidates) if candidates else set()
        results = []
        for did in doc_ids:
            tf = self.doc_tf[did]
            total_tf = sum(tf.get(t, 0) for t in terms)
            results.append({"doc_id": did, "title": self.doc_store[did]["title"],
                            "total_tf": total_tf})
        results.sort(key=lambda x: x["total_tf"], reverse=True)
        return results
```

### 练习三

```python
def normalize_url(url: str) -> str:
    parsed = urlparse(url)
    scheme = "https"
    netloc = parsed.netloc
    if netloc.endswith(":443"):
        netloc = netloc[:-4]
    elif netloc.endswith(":80"):
        netloc = netloc[:-3]
    path = parsed.path.rstrip("/") or "/"
    query_params = parse_qs(parsed.query, keep_blank_values=True)
    sorted_query = urlencode(sorted(query_params.items()), doseq=True)
    return urlunparse((scheme, netloc, path, "", sorted_query, ""))
```
