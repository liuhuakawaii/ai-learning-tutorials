# 混合检索策略

## 场景引入

在实际生产环境中，单一检索策略很难满足所有场景。BM25 擅长精确关键词匹配（如搜商品编号"SKU-2024-001"），语义检索擅长模糊语义匹配（如搜"便宜好用的耳机"）。用户搜索行为是多样的，我们需要一种机制，让两种检索策略互补，取长补短。

混合检索（Hybrid Search）就是把多种检索策略的结果融合起来，输出一个统一的排序。它在 2022 年之后几乎成为所有生产级搜索系统的标配——Elasticsearch 8.x 引入了 kNN 搜索与 BM25 的融合，OpenAI 的 RAG 推荐也是 BM25 + 向量检索的组合。

混合检索的思想并非新事物。早在 2000 年代初，TREC（Text REtrieval Conference）评测中就有大量关于多策略融合的研究。Cormack 等人在 2009 年提出的 RRF 算法至今仍是工业界最常用的融合方法。真正推动混合检索普及的是两个因素：一是 Embedding 模型的成熟让语义检索变得实用，二是 RAG（检索增强生成）范式的兴起对检索质量提出了更高要求。

## 为什么单一检索不够

通过一个具体例子理解：

| 查询 | BM25 表现 | 语义检索表现 |
|------|-----------|-------------|
| "SKU-2024-001" | 精准命中 | 可能找不到（编码无语义） |
| "便宜好用的降噪耳机" | 只匹配"降噪""耳机" | 理解"便宜好用"的语义 |
| "苹果发布会" | 匹配"苹果""发布会" | 可能混淆水果和公司 |
| "如何学习编程" | 匹配"学习""编程" | 能匹配"入门教程""代码教学" |
| "李医生在哪" | 精确匹配"李医生" | 可能匹配"医生""医院" |

没有哪种策略在所有查询上都最优。混合检索的目标是：对每种策略的优势加权融合，让系统在各种查询下都有可接受的表现。

### 从信息检索理论看融合的必要性

从信息检索的"鲁棒性"角度看，单一检索策略存在系统性盲区：

- **词袋模型的盲区**：BM25 基于词频统计，无法处理同义词（"手机"和"移动电话"）和上下位词（"动物"和"猫"）。
- **稠密模型的盲区**：Embedding 模型对罕见词、专有名词、编号等低频实体的编码质量差，容易出现"语义漂移"。
- **互补性的来源**：两种策略的错误模式不同，融合后可以互相纠错。这在机器学习中称为"集成效应"——多样性越强的模型组合，融合效果越好。

## 分数归一化

不同检索策略输出的分数尺度不同。BM25 的分数可能是 0~25，余弦相似度是 0~1。直接相加会严重偏向分数范围大的策略。

常用的归一化方法：

**Min-Max 归一化**：将分数缩放到 [0, 1]

```
score_norm = (score - min_score) / (max_score - min_score)
```

优点：结果在固定区间，易于理解。
缺点：受异常值影响大。如果一个文档的 BM25 分数远高于其他，归一化后大多数文档分数会挤在接近 0 的位置。

**Z-Score 归一化**：将分数转为标准正态分布

```
score_norm = (score - mean) / std
```

优点：对异常值鲁棒，结果反映分数在整体分布中的位置。
缺点：结果无固定区间，可能出现负值。

**Sigmoid 归一化**：将分数映射到 (0, 1)

```
score_norm = 1 / (1 + exp(-(score - mean) / std))
```

优点：结合了 Z-Score 的鲁棒性和 Min-Max 的固定区间。
缺点：需要额外计算 sigmoid。

```python
import numpy as np

def min_max_normalize(scores: list[float]) -> list[float]:
    min_s, max_s = min(scores), max(scores)
    if max_s == min_s:
        return [0.5] * len(scores)
    return [(s - min_s) / (max_s - min_s) for s in scores]

def z_score_normalize(scores: list[float]) -> list[float]:
    arr = np.array(scores)
    mean, std = arr.mean(), arr.std()
    if std == 0:
        return [0.0] * len(scores)
    return ((arr - mean) / std).tolist()

def sigmoid_normalize(scores: list[float]) -> list[float]:
    arr = np.array(scores)
    mean, std = arr.mean(), arr.std()
    if std == 0:
        return [0.5] * len(scores)
    return (1 / (1 + np.exp(-(arr - mean) / std))).tolist()

scores = [12.5, 8.3, 15.1, 3.2, 9.7]
print(f"Min-Max:  {[f'{x:.3f}' for x in min_max_normalize(scores)]}")
print(f"Z-Score:  {[f'{x:.3f}' for x in z_score_normalize(scores)]}")
print(f"Sigmoid:  {[f'{x:.3f}' for x in sigmoid_normalize(scores)]}")
```

**工程选择**：大多数场景下 Min-Max 归一化足够，但如果分数分布有明显异常值（如某些查询的 BM25 分数远高于平均），Z-Score 或 Sigmoid 更稳健。

## RRF（Reciprocal Rank Fusion）

RRF 是一种简单但极其有效的融合方法，由 Cormack 等人在 2009 年提出。它不依赖原始分数，只依赖排名，因此完全避免了分数尺度不一致的问题。

RRF 公式：

```
RRF_score(d) = Σ 1 / (k + rank_i(d))
```

其中 k 是一个常数（通常取 60），rank_i(d) 是文档 d 在第 i 个检索策略中的排名。

```python
def reciprocal_rank_fusion(
    rankings: list[list[str]],
    k: int = 60,
) -> list[tuple[str, float]]:
    scores = {}
    for ranking in rankings:
        for rank, doc_id in enumerate(ranking, 1):
            if doc_id not in scores:
                scores[doc_id] = 0.0
            scores[doc_id] += 1.0 / (k + rank)
    return sorted(scores.items(), key=lambda x: -x[1])

bm25_ranking = ["doc_A", "doc_B", "doc_C", "doc_D", "doc_E"]
semantic_ranking = ["doc_B", "doc_D", "doc_A", "doc_F", "doc_C"]

fused = reciprocal_rank_fusion([bm25_ranking, semantic_ranking])
print("RRF 融合结果:")
for doc, score in fused:
    print(f"  {doc}: {score:.6f}")
```

RRF 的优势：不需要分数归一化、不需要调权重（各策略等权）、对异常分数鲁棒、计算简单延迟低。

### RRF 的数学直觉

为什么 k=60 效果好？可以这样理解：k 的作用是平滑排名差异。当 k 很小时，第 1 名和第 2 名的差距很大（1/1 vs 1/2 = 0.5）；当 k 很大时，排名差异被压缩（1/61 vs 1/62 ≈ 0.0003）。k=60 在排名 1~100 的范围内提供了合理的平滑程度——既保留了排名靠前的优势，又不会让排名稍后的文档完全失去竞争力。

## 加权混合检索

当不同策略的可靠性不同时，可以引入权重：

```python
def weighted_reciprocal_rank_fusion(
    rankings: list[list[str]],
    weights: list[float],
    k: int = 60,
) -> list[tuple[str, float]]:
    scores = {}
    for ranking, weight in zip(rankings, weights):
        for rank, doc_id in enumerate(ranking, 1):
            if doc_id not in scores:
                scores[doc_id] = 0.0
            scores[doc_id] += weight / (k + rank)
    return sorted(scores.items(), key=lambda x: -x[1])

fused = weighted_reciprocal_rank_fusion(
    [bm25_ranking, semantic_ranking],
    weights=[0.4, 0.6],
)
```

权重调优的方法：准备标注数据（查询-相关文档对），用网格搜索或贝叶斯优化找到最优权重组合，评估指标通常用 NDCG@10 或 MRR。

### 查询级自适应权重

固定权重无法适应所有查询。一种进阶方案是根据查询特征动态调整权重：

```python
def classify_query(query: str) -> str:
    """简单规则判断查询类型"""
    import re
    # 包含编号、型号等特殊字符 → 精确查询
    if re.search(r'[A-Z]+-\d+|SKU|型号|编号', query):
        return "exact"
    # 短查询（<=2 个词）→ 偏精确
    if len(query) <= 2:
        return "exact"
    # 长查询（>=5 个词）→ 偏语义
    if len(query) >= 5:
        return "semantic"
    return "mixed"

def get_adaptive_weights(query: str) -> tuple[float, float]:
    query_type = classify_query(query)
    if query_type == "exact":
        return (0.8, 0.2)  # 偏向 BM25
    elif query_type == "semantic":
        return (0.3, 0.7)  # 偏向语义
    return (0.5, 0.5)      # 平衡

# 示例
for q in ["SKU-2024-001", "如何入门人工智能", "降噪耳机推荐"]:
    w = get_adaptive_weights(q)
    print(f"'{q}' → BM25={w[0]}, Semantic={w[1]}")
```

## 分数级融合 vs 排名级融合

| 融合方式 | 方法 | 优点 | 缺点 |
|----------|------|------|------|
| 分数级 | 加权求和归一化后的分数 | 保留分数信息 | 需要归一化，权重敏感 |
| 排名级 | RRF | 无需归一化，鲁棒 | 丢失分数信息 |
| 混合级 | 先归一化再用 RRF | 平衡两者 | 参数更多 |

实际建议：先用 RRF 作为基线（零调参），如果效果不够再尝试分数级融合。

### 凸组合融合（Convex Combination）

凸组合是最直观的分数级融合方法：将归一化后的分数按权重加权求和，权重之和为 1：

```python
def convex_combination_fusion(
    bm25_scores: dict[str, float],
    semantic_scores: dict[str, float],
    alpha: float = 0.5,
) -> list[tuple[str, float]]:
    """
    alpha: BM25 权重 (0~1), 语义权重 = 1 - alpha
    """
    bm25_norm = dict(zip(bm25_scores.keys(), min_max_normalize(list(bm25_scores.values()))))
    sem_norm = dict(zip(semantic_scores.keys(), min_max_normalize(list(semantic_scores.values()))))

    all_docs = set(bm25_scores) | set(semantic_scores)
    fused = []
    for doc in all_docs:
        score = alpha * bm25_norm.get(doc, 0) + (1 - alpha) * sem_norm.get(doc, 0)
        fused.append((doc, score))
    return sorted(fused, key=lambda x: -x[1])
```

## 完整的混合检索系统

```python
from collections import defaultdict

class HybridSearchEngine:
    def __init__(self):
        self.bm25_engine = None
        self.semantic_engine = None
        self.raw_docs = []

    def index(self, documents: list[str], bm25_k1=1.5, bm25_b=0.75):
        self.raw_docs = documents
        tokenized = [list(doc) for doc in documents]
        self.bm25_engine = BM25(tokenized, k1=bm25_k1, b=bm25_b)
        self.semantic_engine = FAISSRetriever()
        self.semantic_engine.index_documents(documents)

    def search(
        self,
        query: str,
        top_k: int = 10,
        method: str = "rrf",
        bm25_weight: float = 0.5,
        semantic_weight: float = 0.5,
        rrf_k: int = 60,
    ) -> list[dict]:
        query_tokens = list(query)
        bm25_results = self.bm25_engine.search(query_tokens, top_k=top_k * 2)
        bm25_ranking = [self.raw_docs[idx] for idx, _ in bm25_results]
        bm25_scores = {self.raw_docs[idx]: score for idx, score in bm25_results}

        semantic_results = self.semantic_engine.search(query, top_k=top_k * 2)
        semantic_ranking = [doc for doc, _ in semantic_results]
        semantic_scores = {doc: score for doc, score in semantic_results}

        if method == "rrf":
            fused = reciprocal_rank_fusion([bm25_ranking, semantic_ranking], k=rrf_k)
        elif method == "weighted_rrf":
            fused = weighted_reciprocal_rank_fusion(
                [bm25_ranking, semantic_ranking],
                weights=[bm25_weight, semantic_weight], k=rrf_k,
            )
        elif method == "score_fusion":
            all_docs = set(bm25_ranking) | set(semantic_ranking)
            bm25_norm = dict(zip(bm25_scores.keys(), min_max_normalize(list(bm25_scores.values()))))
            sem_norm = dict(zip(semantic_scores.keys(), min_max_normalize(list(semantic_scores.values()))))
            fused = []
            for doc in all_docs:
                score = (bm25_weight * bm25_norm.get(doc, 0) +
                         semantic_weight * sem_norm.get(doc, 0))
                fused.append((doc, score))
            fused.sort(key=lambda x: -x[1])

        results = []
        for rank, (doc, score) in enumerate(fused[:top_k], 1):
            results.append({
                "rank": rank, "doc": doc, "fused_score": round(score, 6),
                "bm25_score": round(bm25_scores.get(doc, 0), 4),
                "semantic_score": round(semantic_scores.get(doc, 0), 4),
            })
        return results
```

## 权重调优策略

```python
def grid_search_weights(queries, ground_truth, engine, eval_fn):
    best_score, best_weights = 0, (0.5, 0.5)
    for bm25_w in [x / 10 for x in range(1, 10)]:
        semantic_w = 1.0 - bm25_w
        total = 0
        for query, relevant in zip(queries, ground_truth):
            results = engine.search(query, top_k=10, method="weighted_rrf",
                                    bm25_weight=bm25_w, semantic_weight=semantic_w)
            retrieved = {r["doc"] for r in results[:5]}
            total += eval_fn(retrieved, relevant)
        avg = total / len(queries)
        if avg > best_score:
            best_score, best_weights = avg, (bm25_w, semantic_w)
    print(f"最优: BM25={best_weights[0]}, Semantic={best_weights[1]}, Score={best_score:.4f}")
    return best_weights
```

## 常见误区

1. **认为混合检索只是"加权求和"**：RRF 是排名级融合，不依赖分数，比简单的分数加权更鲁棒。

2. **忽略归一化直接加分数**：BM25 分数 0~25，余弦相似度 0~1，直接相加会让 BM25 主导结果。

3. **用同一权重应对所有查询**：不同类型查询需要不同的策略权重。精确查询应偏向 BM25，模糊查询应偏向语义。

4. **认为 RRF 的 k=60 是最优的**：k=60 是论文推荐值，实际最优值取决于结果列表长度。建议在 10~100 之间调优。

5. **只融合两种策略**：可以融合更多策略，如不同参数的 BM25、不同模型的语义检索。多策略融合时 RRF 的优势更明显——不需要为每对策略调权重。

6. **忽略融合后的去重**：同一文档可能在多个策略中出现，融合计算时不需要去重（RRF 自然处理），但展示结果时需要去重。

7. **过度依赖离线评估**：离线指标（NDCG、MRR）的提升不一定转化为在线效果。权重调优后必须通过 A/B 测试验证。

## 工程建议

1. **从 RRF 开始**：零调参、效果好、实现简单。作为基线已经很强。

2. **用评估数据驱动调优**：准备 50~200 个标注查询，用 NDCG@10 作为指标调权重。

3. **日志记录各策略分数**：记录每个查询下 BM25 和语义检索的分数，便于分析和调优。

4. **考虑查询分类**：用规则或分类器判断查询类型（精确 vs 模糊），动态调整权重。

5. **缓存热门查询结果**：混合检索的延迟是两种策略之和，热门查询可以用缓存降低延迟。

6. **监控融合效果退化**：当文档集合变化（新增大量文档）或模型更新后，融合权重可能需要重新调优。

7. **考虑异步并行**：BM25 和语义检索可以并行执行，取两者结果后再融合，延迟取决于较慢的那个而非两者之和。

## 小结

- 混合检索融合多种策略的结果，取长补短，是生产级搜索系统的标准做法。
- 分数归一化是分数级融合的前提，常用 Min-Max、Z-Score 和 Sigmoid 方法。
- RRF 只依赖排名不依赖分数，简单鲁棒，是混合检索的首选融合方法。
- 权重调优需要用标注数据和评估指标驱动，不能凭感觉调参。
- 查询级自适应权重可以进一步提升混合检索效果。

## 参考答案

### 练习一

**思路**：分别获取 BM25 和语义检索的分数，各自做 Min-Max 归一化后加权求和。

**答案**：
```python
def score_fusion_search(query, bm25_engine, semantic_engine, docs, w=0.5, top_k=10):
    bm25_scores = {i: bm25_engine._score(list(query), i) for i in range(len(docs))}
    sem_results = semantic_engine.search(query, top_k=len(docs))
    sem_scores = {docs.index(d): s for d, s in sem_results}

    bm25_norm = dict(zip(bm25_scores.keys(), min_max_normalize(list(bm25_scores.values()))))
    sem_norm = dict(zip(sem_scores.keys(), min_max_normalize(list(sem_scores.values()))))

    all_idx = set(bm25_norm) | set(sem_norm)
    fused = [(i, w * bm25_norm.get(i, 0) + (1-w) * sem_norm.get(i, 0)) for i in all_idx]
    fused.sort(key=lambda x: -x[1])
    return [(docs[i], round(s, 4)) for i, s in fused[:top_k]]
```

**要点**：Min-Max 归一化确保两策略分数在同一尺度，与 RRF 对比可发现分数融合对归一化方式更敏感。

### 练习二

**思路**：固定查询集，改变 k 值，观察 Top-K 排序的变化程度。

**答案**：
```python
def rrf_sensitivity(rankings, k_values=[10, 30, 60, 100, 200]):
    for k in k_values:
        fused = reciprocal_rank_fusion(rankings, k=k)
        print(f"k={k}: {[d for d, _ in fused[:5]]}")

# k 值越小，排名靠前的文档权重越大
# k 值越大，排名差异被平滑
# k=60 在大多数场景下是合理的默认值
```

**要点**：k=60 是合理的默认值，但建议基于数据验证。短结果列表（Top-10）适合较小的 k，长结果列表适合较大的 k。

### 练习三

**思路**：用三路检索——BM25(k1=1.2)、BM25(k1=2.0)、语义检索，用 RRF 融合。

**答案**：
```python
def three_way_hybrid(query, docs, semantic_engine, top_k=10):
    tokens = list(query)
    bm25_a = BM25([list(d) for d in docs], k1=1.2, b=0.75)
    bm25_b = BM25([list(d) for d in docs], k1=2.0, b=0.75)

    r_a = [docs[i] for i, _ in bm25_a.search(tokens, top_k*2)]
    r_b = [docs[i] for i, _ in bm25_b.search(tokens, top_k*2)]
    r_s = [d for d, _ in semantic_engine.search(query, top_k*2)]

    fused_two = reciprocal_rank_fusion([r_a, r_s], k=60)
    fused_three = reciprocal_rank_fusion([r_a, r_b, r_s], k=60)

    print("两路:", [d[:20] for d, _ in fused_two[:3]])
    print("三路:", [d[:20] for d, _ in fused_three[:3]])
```

**要点**：不同参数的 BM25 提供不同排名视角，三路融合不一定优于两路，取决于第三路是否提供有效新信息。

### 练习四

**思路**：根据查询长度和是否包含特殊字符等特征，自动调整 BM25 和语义检索的权重。

**答案**：
```python
import re

def classify_query_type(query: str) -> str:
    if re.search(r'[A-Z]+-\d+|SKU|型号|编号|\d{4,}', query):
        return "exact"
    words = query.split()
    if len(words) <= 2:
        return "exact"
    if len(words) >= 5:
        return "semantic"
    return "mixed"

WEIGHT_MAP = {
    "exact": (0.75, 0.25),
    "mixed": (0.5, 0.5),
    "semantic": (0.3, 0.7),
}

def adaptive_hybrid_search(query, bm25_engine, semantic_engine, docs, top_k=10):
    qtype = classify_query_type(query)
    bm25_w, sem_w = WEIGHT_MAP[qtype]
    bm25_ranking = [docs[i] for i, _ in bm25_engine.search(list(query), top_k*2)]
    sem_ranking = [d for d, _ in semantic_engine.search(query, top_k*2)]
    fused = weighted_reciprocal_rank_fusion(
        [bm25_ranking, sem_ranking], weights=[bm25_w, sem_w], k=60
    )
    return fused[:top_k]

# 测试
test_queries = [
    ("SKU-2024-001", "exact"),
    ("如何入门人工智能", "semantic"),
    ("Python教程", "mixed"),
]
for query, expected in test_queries:
    actual = classify_query_type(query)
    print(f"'{query}' → 预期={expected}, 实际={actual}, 匹配={actual==expected}")
```

**要点**：规则分类器简单有效，可以作为基线。更复杂的方案可以训练一个轻量分类模型。

### 练习五

**思路**：用 asyncio 或 threading 实现 BM25 和语义检索的并行执行，对比串行和并行的延迟。

**答案**：
```python
import time
import concurrent.futures

def measure_latency(query, bm25_engine, semantic_engine, docs, top_k=10):
    # 串行
    t0 = time.time()
    bm25_ranking = [docs[i] for i, _ in bm25_engine.search(list(query), top_k*2)]
    sem_ranking = [d for d, _ in semantic_engine.search(query, top_k*2)]
    fused = reciprocal_rank_fusion([bm25_ranking, sem_ranking], k=60)
    serial_time = time.time() - t0

    # 并行
    t0 = time.time()
    with concurrent.futures.ThreadPoolExecutor(max_workers=2) as executor:
        f1 = executor.submit(lambda: [docs[i] for i, _ in bm25_engine.search(list(query), top_k*2)])
        f2 = executor.submit(lambda: [d for d, _ in semantic_engine.search(query, top_k*2)])
        bm25_r, sem_r = f1.result(), f2.result()
    fused = reciprocal_rank_fusion([bm25_r, sem_r], k=60)
    parallel_time = time.time() - t0

    print(f"串行: {serial_time*1000:.1f}ms, 并行: {parallel_time*1000:.1f}ms, "
          f"加速比: {serial_time/parallel_time:.2f}x")
    return serial_time, parallel_time

# 理论最大加速比为 2x（两路检索耗时相等时）
# 实际加速比取决于较慢的一路
```

**要点**：并行执行可以显著降低混合检索延迟，加速比取决于两路检索的耗时比例。当语义检索明显慢于 BM25 时，加速比接近 1x（瓶颈在语义检索）。
