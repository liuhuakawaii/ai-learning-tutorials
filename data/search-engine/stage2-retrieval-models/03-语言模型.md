# 检索语言模型

## 场景引入

前面我们从"匹配"和"向量空间"两个角度看待检索问题。现在换一个概率视角：假设每个文档背后有一个语言模型，它能生成文本。给定查询 q，我们要找的是**最有可能生成 q 的那个文档**。

这个思路来自统计语言模型：把文档看作一个概率分布，查询是这个分布生成的一个"样本"。如果文档 d 的语言模型生成查询 q 的概率 P(q|d) 最高，那么 d 就是最相关的文档。这就是查询似然模型（Query Likelihood Model）的核心思想。

## 学习目标

1. 理解查询似然模型的概率框架
2. 掌握 Jelinek-Mercer 平滑和 Dirichlet 先验平滑的原理与实现
3. 理解为什么平滑对语言模型检索至关重要
4. 能用 Python 实现基于语言模型的检索系统
5. 了解语言模型检索与其他方法的本质区别和适用场景

## 历史背景：从确定性到概率性

TF-IDF 和 BM25 都是**确定性**方法——给定查询和文档，分数是确定的。但语言模型方法引入了**概率性**思维：文档不再是一个静态的词袋，而是一个能"生成"文本的随机过程。

这个转变的学术根源可以追溯到 Claude Shannon 1948 年的信息论。Shannon 提出，语言可以用概率模型来描述——下一个词的出现概率取决于前面的词。1998 年，Ponte 和 Croft 在 SIGIR 会议上发表了开创性论文，将语言模型引入信息检索。他们的核心贡献是：不需要手工设计相似度函数，而是让概率论自动给出排序依据。

语言模型方法的另一个重要贡献是为"平滑"提供了理论基础。在 TF-IDF/BM25 中，平滑是一个工程技巧；在语言模型中，平滑有严格的概率解释——它是贝叶斯推断的自然结果。

## 查询似然模型

查询似然模型的核心公式：

```
score(q, d) = P(q | Md)
```

其中 Md 是文档 d 对应的语言模型。最简单的估计方式是最大似然估计（MLE），直接用文档中的词频：

```
P_MLE(w | d) = count(w, d) / |d|
```

其中 count(w, d) 是词 w 在文档 d 中的出现次数，|d| 是文档 d 的总词数。

假设查询中的词相互独立（朴素贝叶斯假设），则：

```
P(q | d) = ∏ P(wi | d)，对查询中的每个词 wi
```

实际计算时取对数避免下溢：

```
log P(q | d) = Σ log P(wi | d)
```

```python
import math
from collections import Counter

class QueryLikelihoodModel:
    def __init__(self, corpus: list[list[str]]):
        self.corpus = corpus
        self.doc_tf = [Counter(doc) for doc in corpus]
        self.doc_lens = [len(doc) for doc in corpus]

    def _mle_prob(self, word: str, doc_idx: int) -> float:
        return self.doc_tf[doc_idx].get(word, 0) / self.doc_lens[doc_idx]

    def search(self, query: list[str], top_k: int = 5) -> list[tuple[int, float]]:
        scores = []
        for i in range(len(self.corpus)):
            log_prob = 0.0
            for word in query:
                prob = self._mle_prob(word, i)
                if prob == 0:
                    log_prob = float('-inf')
                    break
                log_prob += math.log(prob)
            scores.append((i, log_prob))
        scores.sort(key=lambda x: -x[1])
        return scores[:top_k]

corpus = [
    ["信息", "检索", "是", "计算机", "科学", "的", "重要", "分支"],
    ["机器", "学习", "是", "人工智能", "的", "核心", "技术"],
    ["信息", "检索", "系统", "需要", "高效", "的", "索引", "结构"],
    ["深度", "学习", "在", "自然", "语言", "处理", "中", "应用", "广泛"],
    ["搜索引擎", "是", "信息", "检索", "的", "典型", "应用"],
]

model = QueryLikelihoodModel(corpus)
results = model.search(["信息", "检索"])
for idx, score in results:
    print(f"文档{idx}: logP={score:.4f}, 内容={''.join(corpus[idx])}")
```

## 零概率问题与平滑

上面的代码有一个严重问题：如果查询中有任何一个词不在文档中，概率就变成 0，整个乘积为 0（对数为负无穷）。这在实际检索中几乎必然发生——用户查询的词不可能出现在每个文档中。

这个问题叫**零概率问题**。解决方案是**平滑**（Smoothing）：给未在文档中出现的词分配一个很小但非零的概率。

直觉上，平滑做的事情是：从文档的词频分布中"借"一点概率质量，分配给文档中没有出现的词。具体怎么借，不同平滑方法有不同的策略。

**零概率问题的严重性：** 假设一个文档有 100 个词，词汇表有 10000 个词。文档中只出现了 50 个不同的词，剩下 9950 个词的概率都是 0。这意味着如果查询中有任何一个这 9950 个词之一，整个文档的概率就归零。在实际场景中，这几乎必然发生。

## Jelinek-Mercer 平滑

Jelinek-Mercer（JM）平滑是最简单的插值平滑方法。它用一个参数 λ 在文档模型和整个语料库模型之间做线性插值：

```
P_JM(w | d) = λ × P_MLE(w | d) + (1 - λ) × P_MLE(w | C)
```

其中 C 是整个语料库，P_MLE(w | C) = count(w, C) / |C| 是词在语料库中的相对频率。

- λ 接近 1：更信任文档本身
- λ 接近 0：更信任语料库全局统计

λ 的典型取值是 0.1~0.5。在短文档场景下，应使用较小的 λ（更多依赖全局模型）；长文档可以用较大的 λ。

**JM 平滑的直觉：** 想象你在猜测一篇文章的主题。如果文章很长（1000 词），你有很多证据，可以主要依赖文章本身的内容。如果文章很短（10 个词），证据不足，你需要参考整个领域的背景知识来补充判断。JM 平滑的 λ 就是控制"信任自己"和"信任背景"的比例。

```python
class JelinekMercerLM(QueryLikelihoodModel):
    def __init__(self, corpus: list[list[str]], lam: float = 0.2):
        super().__init__(corpus)
        self.lam = lam
        total_words = sum(self.doc_lens)
        self.collection_tf = Counter()
        for doc in corpus:
            self.collection_tf.update(doc)
        self.collection_len = total_words

    def _smoothed_prob(self, word: str, doc_idx: int) -> float:
        doc_prob = self._mle_prob(word, doc_idx)
        col_prob = self.collection_tf.get(word, 0) / self.collection_len
        return self.lam * doc_prob + (1 - self.lam) * col_prob

    def search(self, query: list[str], top_k: int = 5) -> list[tuple[int, float]]:
        scores = []
        for i in range(len(self.corpus)):
            log_prob = 0.0
            for word in query:
                prob = self._smoothed_prob(word, i)
                log_prob += math.log(prob)
            scores.append((i, log_prob))
        scores.sort(key=lambda x: -x[1])
        return scores[:top_k]

jm_model = JelinekMercerLM(corpus, lam=0.2)
results = jm_model.search(["信息", "检索"])
for idx, score in results:
    print(f"文档{idx}: logP={score:.4f}, 内容={''.join(corpus[idx])}")
```

## Dirichlet 先验平滑

Dirichlet 先验平滑（也叫贝叶斯平滑）是另一种常用的平滑方法，它的核心思想是：假设文档的词分布来自一个以语料库分布为先验的 Dirichlet 分布。

公式：

```
P_Dir(w | d) = (count(w, d) + μ × P_MLE(w | C)) / (|d| + μ)
```

其中 μ 是先验强度参数，通常取值 500~2000。

与 JM 平滑的关键区别：Dirichlet 平滑是**自适应**的。文档越短，|d| 越小，平滑项 μ × P_MLE(w | C) 的占比越大，越依赖全局模型；文档越长，|d| 越大，越信任文档本身。

**Dirichlet 平滑的贝叶斯解释：** Dirichlet 平滑不是凭空设计的，它有严格的贝叶斯推导。假设我们对文档的词分布有一个"先验信念"——认为它应该接近语料库的分布。当我们观察到文档的实际词频后，我们用贝叶斯公式更新信念。μ 越大，先验越强，越不容易被文档的实际数据"说服"。μ 越小，越信任数据。

```python
class DirichletLM(QueryLikelihoodModel):
    def __init__(self, corpus: list[list[str]], mu: float = 1000):
        super().__init__(corpus)
        self.mu = mu
        self.collection_tf = Counter()
        for doc in corpus:
            self.collection_tf.update(doc)
        self.collection_len = sum(self.doc_lens)

    def _smoothed_prob(self, word: str, doc_idx: int) -> float:
        doc_count = self.doc_tf[doc_idx].get(word, 0)
        col_prob = self.collection_tf.get(word, 0) / self.collection_len
        return (doc_count + self.mu * col_prob) / (self.doc_lens[doc_idx] + self.mu)

    def search(self, query: list[str], top_k: int = 5) -> list[tuple[int, float]]:
        scores = []
        for i in range(len(self.corpus)):
            log_prob = 0.0
            for word in query:
                prob = self._smoothed_prob(word, i)
                log_prob += math.log(prob)
            scores.append((i, log_prob))
        scores.sort(key=lambda x: -x[1])
        return scores[:top_k]

dir_model = DirichletLM(corpus, mu=1000)
results = dir_model.search(["信息", "检索"])
for idx, score in results:
    print(f"文档{idx}: logP={score:.4f}, 内容={''.join(corpus[idx])}")
```

## 三种方法对比

| 方法 | 公式 | 参数 | 自适应性 | 适用场景 |
|------|------|------|----------|----------|
| MLE | count(w,d)/\|d\| | 无 | 无 | 不实用（零概率问题） |
| JM 平滑 | λ×P_d + (1-λ)×P_C | λ=0.1~0.5 | 固定权重 | 短文本、社交媒体 |
| Dirichlet | (count+μ×P_C)/(\|d\|+μ) | μ=500~2000 | 自适应 | 通用场景，尤其长短混合 |

Dirichlet 平滑在大多数评测集上表现优于 JM 平滑，因为它能自动适应文档长度变化。

**JM vs Dirichlet 的选择指南：**

```python
def recommend_smoothing(doc_lengths: list[int]) -> str:
    """根据文档长度分布推荐平滑方法"""
    avg_len = sum(doc_lengths) / len(doc_lengths)
    max_len = max(doc_lengths)
    min_len = min(doc_lengths)
    length_ratio = max_len / min_len if min_len > 0 else float('inf')

    if length_ratio > 10:
        return "dirichlet (文档长度差异大，需要自适应平滑)"
    elif avg_len < 50:
        return "jm (短文本，固定权重足够，λ=0.1~0.3)"
    else:
        return "dirichlet (通用场景，μ=1000~1500)"

# 示例
short_docs = [10, 15, 20, 12, 8]
mixed_docs = [10, 500, 30, 1000, 50]
print(recommend_smoothing(short_docs))
print(recommend_smoothing(mixed_docs))
```

## 从概率到相关性：完整检索系统

```python
class LanguageModelSearchEngine:
    def __init__(self, method: str = "dirichlet", mu: float = 1000, lam: float = 0.2):
        self.method = method
        self.mu = mu
        self.lam = lam
        self.model = None

    def index(self, documents: list[str]):
        tokenized = [list(doc) for doc in documents]
        self.raw_docs = documents
        if self.method == "jm":
            self.model = JelinekMercerLM(tokenized, lam=self.lam)
        else:
            self.model = DirichletLM(tokenized, mu=self.mu)

    def search(self, query: str, top_k: int = 5) -> list[tuple[str, float]]:
        tokens = list(query)
        results = self.model.search(tokens, top_k)
        return [(self.raw_docs[idx], score) for idx, score in results]

docs = [
    "信息检索是计算机科学的重要分支",
    "机器学习是人工智能的核心技术",
    "信息检索系统需要高效的索引结构",
    "深度学习在自然语言处理中应用广泛",
    "搜索引擎是信息检索的典型应用",
]

for method in ["jm", "dirichlet"]:
    engine = LanguageModelSearchEngine(method=method)
    engine.index(docs)
    print(f"\n=== {method.upper()} ===")
    for doc, score in engine.search("信息检索"):
        print(f"[{score:.4f}] {doc}")
```

## 语言模型与 TF-IDF/BM25 的本质区别

语言模型方法和 TF-IDF/BM25 看似都在做同一件事——计算查询和文档的相关性分数，但它们的思维方式有本质不同：

| 维度 | TF-IDF/BM25 | 语言模型 |
|------|-------------|----------|
| 理论基础 | 启发式 + 概率检索模型 | 纯概率框架 |
| 分数含义 | 无明确概率解释 | log P(q\|d)，可解释为概率 |
| 参数调优 | 工程驱动（试错） | 理论驱动（贝叶斯推断） |
| 平滑来源 | 经验公式 | 概率分布的自然结果 |
| 扩展性 | 有限 | 易于融入更复杂的概率模型 |

语言模型方法的真正优势在于**可扩展性**。一旦建立了概率框架，你可以自然地引入：
- 查询扩展（relevance model）
- 伪相关反馈
- 主题模型
- 神经语言模型

这些扩展在 TF-IDF/BM25 的框架下很难优雅地实现。

## 常见误区

1. **忽略平滑直接用 MLE**：MLE 会导致零概率问题，任何包含未见词的查询都会返回无效结果。平滑不是可选项，是必需的。

2. **认为平滑只是"解决零概率"**：平滑还有另一个重要作用——调节短文档和长文档的权重平衡，直接影响排序质量。

3. **盲目使用默认参数**：JM 的 λ 和 Dirichlet 的 μ 对结果影响很大。μ=1000 是论文常用值，但短文本场景（如推特、评论）可能需要 μ=50~200。

4. **混淆文档语言模型和查询语言模型**：查询似然模型估计的是 P(q|d)，即"文档生成查询"的概率，不是"查询生成文档"的概率。

5. **认为语言模型只适合短查询**：虽然短查询更常见，但语言模型对长查询同样有效，只需注意独立性假设在长查询中更可能被违反。

6. **忽略对数空间计算的必要性**：概率值连乘会导致浮点下溢。必须在对数空间做加法，而不是在概率空间做乘法。

7. **在小语料库上期望语言模型优于 BM25**：语言模型依赖语料库统计量来估计平滑参数，小语料库的统计量不可靠，BM25 更稳健。

## 工程建议

1. **Dirichlet 平滑是安全的默认选择**：Dirichlet 平滑（μ=1000~1500）在大多数场景下表现稳健。

2. **预计算语料库统计**：P_MLE(w | C) 只依赖语料库全局统计，索引阶段计算一次，查询时直接查表。

3. **对数空间计算**：永远在对数空间做加法，不要在概率空间做乘法，避免浮点下溢。

4. **评估驱动参数调优**：准备标注数据，用 NDCG@10 或 MAP 作为指标，网格搜索最优参数。

5. **处理 OOV 词**：对于语料库中完全未出现的词（Out-of-Vocabulary），需要分配一个极小的兜底概率（如 1e-10），而不是直接跳过。

6. **与 BM25 混合使用**：语言模型和 BM25 各有优势。在实际系统中，可以将两者的分数加权组合，取长补短。

## 小结

- 查询似然模型把检索问题转化为概率估计：找最可能生成查询的文档的语言模型。
- 最大似然估计存在零概率问题，必须用平滑技术解决。
- Jelinek-Mercer 平滑用固定权重插值，Dirichlet 先验平滑能自适应文档长度。
- Dirichlet 平滑在大多数场景下是更优的默认选择，μ 的典型值为 1000~1500。
- 语言模型方法的真正优势在于其概率框架的可扩展性，为后续的神经检索模型奠定了理论基础。

## 参考答案

### 练习一

**思路**：绝对折扣平滑从每个非零词频中扣除固定值 δ，将节省的概率质量均匀分配给未出现的词。

**答案**：
```python
class AbsoluteDiscountLM(QueryLikelihoodModel):
    def __init__(self, corpus, delta=0.5):
        super().__init__(corpus)
        self.delta = delta
        self.collection_tf = Counter()
        for doc in corpus:
            self.collection_tf.update(doc)
        self.collection_len = sum(self.doc_lens)

    def _smoothed_prob(self, word, doc_idx):
        doc_count = self.doc_tf[doc_idx].get(word, 0)
        col_prob = self.collection_tf.get(word, 0) / self.collection_len
        unique = len(self.doc_tf[doc_idx])
        return max(doc_count - self.delta, 0) / self.doc_lens[doc_idx] + \
               self.delta * unique / self.doc_lens[doc_idx] * col_prob
```

**要点**：δ 典型值 0.1~0.7，高频词只扣除少量概率质量。Dirichlet 通常最优，绝对折扣在短文本场景有优势。

### 练习三

**思路**：对查询中的每个词做条件判断——出现在文档中用文档模型，否则用语料库模型。

**答案**：
```python
class MixedLM(QueryLikelihoodModel):
    def __init__(self, corpus, fallback_prob=1e-10):
        super().__init__(corpus)
        self.collection_tf = Counter()
        for doc in corpus:
            self.collection_tf.update(doc)
        self.collection_len = sum(self.doc_lens)
        self.fallback_prob = fallback_prob

    def search(self, query, top_k=5):
        scores = []
        for i in range(len(self.corpus)):
            log_prob = 0.0
            for word in query:
                if word in self.doc_tf[i]:
                    prob = self._mle_prob(word, i)
                else:
                    prob = self.collection_tf.get(word, 0) / self.collection_len
                    if prob == 0:
                        prob = self.fallback_prob
                log_prob += math.log(prob)
            scores.append((i, log_prob))
        scores.sort(key=lambda x: -x[1])
        return scores[:top_k]
```

```python
def compare_lm_bm25(corpus, queries):
    """对比语言模型和 BM25 的排序差异"""
    tokenized = [list(doc) for doc in corpus]
    lm = DirichletLM(tokenized, mu=1000)
    bm25 = BM25(tokenized, k1=1.5, b=0.75)

    agree, disagree = 0, 0
    for query in queries:
        query_tokens = list(query)
        lm_order = [idx for idx, _ in lm.search(query_tokens, len(corpus))]
        bm25_order = [idx for idx, _ in bm25.search(query_tokens, len(corpus))]
        if lm_order[0] == bm25_order[0]:
            agree += 1
        else:
            disagree += 1
            print(f"查询'{query}': LM={lm_order[0]}, BM25={bm25_order[0]}")

    print(f"\nTop1一致率: {agree}/{agree+disagree} = {agree/(agree+disagree):.1%}")

queries = ["信息检索", "机器学习", "搜索引擎", "自然语言处理", "深度学习"]
compare_lm_bm25(docs, queries)
```

**要点**：
- 在短文档语料上，两者排序通常比较一致
- 在长文档语料上，BM25 的文档长度归一化和 Dirichlet 的自适应平滑行为不同，导致排序差异
- 差异最大的是长度极端的文档（特别短或特别长）

### 练习五

**思路**：伪相关反馈（Pseudo-Relevance Feedback, PRF）的核心是"假设 Top-K 结果是相关的"，从中提取扩展词来丰富查询表示。

**答案**：
```python
class PRFSearchEngine:
    def __init__(self, mu=1000, top_k_fb=5, num_expansion_terms=10):
        self.mu = mu
        self.top_k_fb = top_k_fb
        self.num_expansion = num_expansion_terms
        self.model = None
        self.raw_docs = []

    def index(self, documents):
        self.raw_docs = documents
        tokenized = [list(doc) for doc in documents]
        self.model = DirichletLM(tokenized, mu=self.mu)

    def _expand_query(self, query, top_docs):
        """从反馈文档中提取扩展词"""
        feedback_tf = Counter()
        for doc_idx, _ in top_docs:
            feedback_tf.update(self.model.doc_tf[doc_idx])

        for word in query:
            feedback_tf.pop(word, None)

        expanded = [word for word, _ in feedback_tf.most_common(self.num_expansion)]
        return list(query) + expanded

    def search(self, query_str, top_k=5):
        query = list(query_str)

        first_pass = self.model.search(query, self.top_k_fb)
        expanded_query = self._expand_query(query, first_pass)
        print(f"原始查询: {query}")
        print(f"扩展查询: {expanded_query}")

        second_pass = self.model.search(expanded_query, top_k)
        return [(self.raw_docs[idx], score) for idx, score in second_pass]
```

**要点**：
- PRF 的核心假设是"Top-K 结果大致相关"，这个假设在大多数情况下成立
- 扩展词数量（num_expansion）通常取 5~20，太多会引入噪声
- PRF 对初始检索质量敏感——如果 Top-K 结果质量差，扩展词会偏离主题（query drift）
- 实际系统中常用 RM3（Relevance Model 3）作为 PRF 的标准实现
