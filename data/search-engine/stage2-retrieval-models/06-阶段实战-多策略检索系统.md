# 阶段实战：多策略检索系统

## 场景引入

经过前面 5 课的学习，我们已经掌握了 TF-IDF/BM25、向量空间模型、语言模型、语义检索和混合检索。现在是时候把它们整合到一个完整的系统中了。

本课的目标是构建一个多策略检索系统，支持三种检索模式：BM25 关键词检索、向量语义检索、混合检索。并通过对比实验验证各策略的效果差异。

这个实战项目的工程意义在于：真实生产环境中的搜索系统从来不是单一策略，而是多种策略的组合。Elasticsearch 8.x 的 kNN 搜索、Pinecone 的混合检索、甚至 OpenAI 的 RAG 推荐，底层都是类似架构。掌握多策略检索系统的设计，是从"会用工具"到"能建系统"的关键一步。

## 学习目标

1. 设计一个可扩展的多策略检索系统架构
2. 实现 BM25、语义检索、混合检索三种模式
3. 构建评估框架，对比各策略的检索质量
4. 掌握从原型到可运行系统的工程化过程
5. 理解策略解耦、统一接口、评估驱动等工程设计原则

## 系统架构设计

多策略检索系统的核心设计原则是**策略解耦**：每种检索策略独立实现，通过统一接口调用，融合层负责组合结果。

```
查询输入 → 路由分发 → [BM25] [语义检索] [混合策略] → 融合层(RRF) → 排序输出
```

### 为什么策略解耦很重要？

假设你把 BM25 的评分逻辑和语义检索的向量计算混在一起写，会发生什么？

1. **无法独立测试**：想单独评估 BM25 的效果？必须把语义检索的代码也跑一遍。
2. **无法独立优化**：想把 BM25 换成 BM25+？需要改融合层的代码。
3. **无法灵活组合**：想只用 BM25 做 A/B 测试？需要加 if-else 判断。

策略解耦后，每个策略是一个独立模块，通过统一接口暴露能力。融合层只关心接口，不关心实现细节。新增策略只需实现接口并注册，不改动已有代码。

### 接口设计的 tradeoff

统一接口返回 `list[tuple[str, float]]`（文档和分数），但不同策略的分数含义不同：BM25 分数是相关性评分，语义检索分数是余弦相似度。这在单一策略使用时没问题，但在融合时需要注意分数归一化。这是一个刻意的设计选择——接口简单，归一化交给融合层处理。

## 统一检索策略接口

```python
from abc import ABC, abstractmethod

class RetrievalStrategy(ABC):
    @abstractmethod
    def index(self, documents: list[str]) -> None:
        pass

    @abstractmethod
    def search(self, query: str, top_k: int = 10) -> list[tuple[str, float]]:
        pass
```

## BM25 策略实现

```python
import math
from collections import Counter

class BM25Strategy(RetrievalStrategy):
    def __init__(self, k1: float = 1.5, b: float = 0.75):
        self.k1, self.b = k1, b
        self.corpus, self.doc_tf, self.doc_lens = [], [], []
        self.doc_freqs, self.avgdl, self.doc_count = Counter(), 0, 0
        self.raw_docs = []

    def index(self, documents: list[str]) -> None:
        self.raw_docs = documents
        self.corpus = [list(doc) for doc in documents]
        self.doc_count = len(self.corpus)
        self.avgdl = sum(len(d) for d in self.corpus) / self.doc_count
        self.doc_lens = [len(d) for d in self.corpus]
        self.doc_tf, self.doc_freqs = [], Counter()
        for doc in self.corpus:
            tf = Counter(doc)
            self.doc_tf.append(tf)
            for word in set(doc):
                self.doc_freqs[word] += 1

    def _idf(self, word: str) -> float:
        df = self.doc_freqs.get(word, 0)
        return math.log((self.doc_count - df + 0.5) / (df + 0.5) + 1)

    def _score(self, query_tokens: list[str], doc_idx: int) -> float:
        score, tf, dl = 0.0, self.doc_tf[doc_idx], self.doc_lens[doc_idx]
        for word in query_tokens:
            if word not in tf:
                continue
            tf_val = tf[word]
            num = tf_val * (self.k1 + 1)
            den = tf_val + self.k1 * (1 - self.b + self.b * dl / self.avgdl)
            score += self._idf(word) * (num / den)
        return score

    def search(self, query: str, top_k: int = 10) -> list[tuple[str, float]]:
        tokens = list(query)
        scores = [(i, self._score(tokens, i)) for i in range(self.doc_count)]
        scores.sort(key=lambda x: -x[1])
        return [(self.raw_docs[idx], score) for idx, score in scores[:top_k]]
```

## 语义检索策略实现

```python
import numpy as np

class SemanticStrategy(RetrievalStrategy):
    def __init__(self):
        self.model, self.doc_vectors, self.raw_docs = None, None, []

    def index(self, documents: list[str]) -> None:
        from sentence_transformers import SentenceTransformer
        self.raw_docs = documents
        self.model = SentenceTransformer('all-MiniLM-L6-v2')
        self.doc_vectors = self.model.encode(documents, show_progress_bar=True).astype('float32')
        norms = np.linalg.norm(self.doc_vectors, axis=1, keepdims=True)
        norms[norms == 0] = 1
        self.doc_vectors = self.doc_vectors / norms

    def search(self, query: str, top_k: int = 10) -> list[tuple[str, float]]:
        query_vec = self.model.encode([query]).astype('float32')
        q_norm = np.linalg.norm(query_vec)
        if q_norm > 0:
            query_vec = query_vec / q_norm
        scores = (self.doc_vectors @ query_vec.T).flatten()
        top_idx = np.argsort(-scores)[:top_k]
        return [(self.raw_docs[i], float(scores[i])) for i in top_idx]
```

## 混合检索策略实现

```python
from collections import defaultdict

class HybridStrategy(RetrievalStrategy):
    def __init__(self, bm25: BM25Strategy, semantic: SemanticStrategy,
                 bm25_weight=0.4, semantic_weight=0.6, rrf_k=60):
        self.bm25, self.semantic = bm25, semantic
        self.bm25_w, self.semantic_w = bm25_weight, semantic_weight
        self.rrf_k = rrf_k

    def index(self, documents): self.raw_docs = documents

    def search(self, query: str, top_k: int = 10) -> list[tuple[str, float]]:
        k = top_k * 3
        bm25_ranking = [doc for doc, _ in self.bm25.search(query, top_k=k)]
        sem_ranking = [doc for doc, _ in self.semantic.search(query, top_k=k)]
        scores = defaultdict(float)
        for ranking, weight in [(bm25_ranking, self.bm25_w), (sem_ranking, self.semantic_w)]:
            for rank, doc in enumerate(ranking, 1):
                scores[doc] += weight / (self.rrf_k + rank)
        fused = sorted(scores.items(), key=lambda x: -x[1])
        return [(doc, score) for doc, score in fused[:top_k]]
```

## 评估框架

评估框架是检索系统的核心基础设施。没有评估，任何优化都是盲目的。

```python
def precision_at_k(retrieved: list[str], relevant: set[str], k: int) -> float:
    return sum(1 for d in retrieved[:k] if d in relevant) / k

def recall_at_k(retrieved: list[str], relevant: set[str], k: int) -> float:
    return sum(1 for d in retrieved[:k] if d in relevant) / len(relevant) if relevant else 0

def mrr(retrieved: list[str], relevant: set[str]) -> float:
    for rank, doc in enumerate(retrieved, 1):
        if doc in relevant:
            return 1.0 / rank
    return 0.0

def ndcg_at_k(retrieved: list[str], relevant: set[str], k: int) -> float:
    """归一化折损累积增益"""
    dcg = sum(1.0 / np.log2(i + 2) for i, doc in enumerate(retrieved[:k]) if doc in relevant)
    ideal = sum(1.0 / np.log2(i + 2) for i in range(min(len(relevant), k)))
    return dcg / ideal if ideal > 0 else 0.0

def evaluate_strategy(strategy, queries, ground_truth, k=5) -> dict:
    p_list, r_list, mrr_list, ndcg_list = [], [], [], []
    for query, relevant in zip(queries, ground_truth):
        retrieved = [doc for doc, _ in strategy.search(query, top_k=k)]
        p_list.append(precision_at_k(retrieved, relevant, k))
        r_list.append(recall_at_k(retrieved, relevant, k))
        mrr_list.append(mrr(retrieved, relevant))
        ndcg_list.append(ndcg_at_k(retrieved, relevant, k))
    return {
        "P@K": sum(p_list)/len(p_list),
        "R@K": sum(r_list)/len(r_list),
        "MRR": sum(mrr_list)/len(mrr_list),
        "NDCG@K": sum(ndcg_list)/len(ndcg_list),
    }
```

### 评估指标详解

| 指标 | 含义 | 关注点 |
|------|------|--------|
| P@K | Top-K 中相关文档比例 | 精度：返回的结果中有多少是好的 |
| R@K | 相关文档被找回的比例 | 召回：好的文档有多少被找到了 |
| MRR | 第一个相关结果排名的倒数 | 体验：用户找到第一个有用结果要翻多远 |
| NDCG@K | 归一化折损累积增益 | 排序质量：相关文档是否排在前面 |

**指标选择建议**：电商搜索关注 P@K（返回结果要精准），知识库搜索关注 R@K（不能遗漏），对话式搜索关注 MRR（第一个结果就要有用）。

```python
def per_query_analysis(query, strategies, relevant, k=5):
    print(f"\n查询: '{query}' (相关文档: {len(relevant)} 个)")
    print(f"  {'策略':<15} {'命中':<5} {'P@5':<8} {'首个排名':<10}")
    print(f"  {'-'*40}")
    for name, strategy in strategies.items():
        retrieved = [doc for doc, _ in strategy.search(query, top_k=k)]
        hits = sum(1 for d in retrieved if d in relevant)
        p = hits / k
        first_rank = 0
        for i, doc in enumerate(retrieved, 1):
            if doc in relevant:
                first_rank = i
                break
```

## 系统封装

```python
class MultiStrategySearchSystem:
    def __init__(self):
        self.strategies = {}

    def add_strategy(self, name: str, strategy: RetrievalStrategy) -> None:
        self.strategies[name] = strategy

    def build_index(self, documents: list[str]) -> None:
        for name, s in self.strategies.items():
            print(f"构建 {name} 索引...")
            s.index(documents)

    def search(self, query: str, strategy_name: str = "hybrid", top_k: int = 10) -> list[dict]:
        if strategy_name not in self.strategies:
            raise ValueError(f"未知策略 '{strategy_name}'，可用: {list(self.strategies.keys())}")
        results = self.strategies[strategy_name].search(query, top_k=top_k)
        return [{"rank": i+1, "doc": doc, "score": round(score, 4)} for i, (doc, score) in enumerate(results)]

    def compare(self, query: str, top_k: int = 5) -> dict:
        return {n: self.search(query, n, top_k) for n in self.strategies}

    def evaluate_all(self, queries, ground_truth, k=5) -> dict:
        """评估所有策略"""
        report = {}
        for name, strategy in self.strategies.items():
            report[name] = evaluate_strategy(strategy, queries, ground_truth, k)
        return report
```

## 常见误区

1. **过早优化索引性能**：先确保检索质量达标，再考虑性能优化。一个返回错误结果的系统再快也没有意义。

2. **评估数据量太小**：只有 5 个查询的评估结果波动大，生产级评估至少需要 100+ 标注查询。本课用 8 个查询仅做演示。

3. **混合权重不做调优**：直接用等权混合，实际最优权重比通常是 3:7 或 4:6。权重调优是混合检索效果的关键。

4. **忽略分词质量**：本例用逐字切分，实际必须用 jieba 等分词工具。分词质量直接影响 BM25 的效果。

5. **只看平均指标**：平均指标掩盖了查询间的差异。应该同时看逐查询分析，找出系统性弱点。

6. **评估集和训练集泄露**：如果用同一份文档做索引和评估，结果会过于乐观。生产环境应该用时间切分（用过去的数据索引，用未来的查询评估）。

## 工程建议

1. **策略注册机制**：用字典管理策略，新增策略只需实现接口并注册。

2. **渐进式上线**：先用 BM25 上线，收集数据后逐步引入语义检索和混合检索。每一步都要有评估数据支撑。

3. **A/B 测试**：混合检索权重应通过 A/B 测试验证，不要只看离线指标。在线指标（点击率、转化率）才是最终标准。

4. **日志与监控**：记录每次查询的各策略分数、融合结果、用户点击。这些数据是后续调优的基础。

5. **文档更新策略**：当文档集合变化时，需要重建索引。BM25 索引重建快（毫秒级），语义索引重建慢（需要编码，分钟级）。建议增量更新 BM25，定期全量重建语义索引。

6. **错误处理**：语义检索依赖外部模型，可能因模型加载失败、GPU 不可用等原因报错。系统应有降级策略——语义检索失败时自动回退到纯 BM25。

## 小结

- 多策略检索系统的核心是策略解耦和统一接口设计。
- BM25 擅长精确匹配，语义检索擅长模糊匹配，混合检索融合两者优势。
- RRF 是简单有效的融合方法，不需要分数归一化和复杂调参。
- 评估框架是检索系统的核心基础设施，必须同步建立。
- 逐查询分析比平均指标更能发现问题。
- 策略注册和配置化是系统可扩展的关键。

### 练习一

**思路**：用词共现矩阵找到与查询词高频共现的词，扩展查询后重新检索。

**答案**：
```python
class QueryExpansionStrategy(RetrievalStrategy):
    def __init__(self, base: BM25Strategy, top_cooccur=3):
        self.base, self.top_cooccur = base, top_cooccur
        self.cooccurrence = Counter()

    def index(self, documents):
        self.raw_docs = documents
        self.base.index(documents)
        for doc in self.base.corpus:
            words = set(doc)
            for w1 in words:
                for w2 in words:
                    if w1 != w2:
                        self.cooccurrence[(w1, w2)] += 1

    def search(self, query, top_k=10):
        expanded = list(query)
        for word in query:
            cands = sorted([(w2, c) for (w1, w2), c in self.cooccurrence.items()
                           if w1 == word and w2 not in query], key=lambda x: -x[1])
            expanded.extend(w for w, _ in cands[:self.top_cooccur])
        scores = [(i, self.base._score(expanded, i)) for i in range(len(self.raw_docs))]
        scores.sort(key=lambda x: -x[1])
        return [(self.raw_docs[i], s) for i, s in scores[:top_k]]
```

**要点**：共现词统计在索引阶段完成，top_cooccur 过大会引入噪声，对短查询效果提升明显。

```python
app = FastAPI(title="多策略检索系统")

    b, s = BM25Strategy(), SemanticStrategy()

@app.get("/compare")
```

### 练习三

**思路**：扩展评估查询到 30 个，运行三种策略，生成 Markdown 表格。

**答案**：
```python
def generate_eval_report(queries, ground_truth, strategies, k=5):
    lines = ["# 检索策略评估报告\n"]
    lines.append(f"评估查询数: {len(queries)}, Top-K: {k}\n")

    # 总体指标
    lines.append("## 总体指标\n")
    lines.append(f"| 策略 | P@{k} | R@{k} | MRR | NDCG@{k} |")
    lines.append("|------|-------|-------|-----|----------|")
    for name, strategy in strategies.items():
        m = evaluate_strategy(strategy, queries, ground_truth, k)
        lines.append(f"| {name} | {m['P@K']:.4f} | {m['R@K']:.4f} | {m['MRR']:.4f} | {m['NDCG@K']:.4f} |")

    # 逐查询分析
    lines.append("\n## 逐查询分析\n")
    for i, (query, relevant) in enumerate(zip(queries, ground_truth)):
        lines.append(f"### 查询 {i+1}: {query}\n")
        for name, strategy in strategies.items():
            retrieved = [doc[:30] for doc, _ in strategy.search(query, top_k=k)]
            hits = sum(1 for d in retrieved if any(r in d for r in relevant))
            lines.append(f"- **{name}**: 命中 {hits}/{k}, Top1={retrieved[0] if retrieved else 'N/A'}")
        lines.append("")

    report = "\n".join(lines)
    with open("eval_report.md", "w", encoding="utf-8") as f:
        f.write(report)
    print("报告已生成: eval_report.md")
    return report
```

**要点**：报告应包含总体指标和逐查询分析，便于发现系统性弱点。

### 练习四

**思路**：用装饰器或 try-except 包装语义检索，失败时回退到 BM25。

**答案**：
```python
class FallbackSemanticStrategy(RetrievalStrategy):
    def __init__(self, fallback: BM25Strategy):
        self.model = None
        self.doc_vectors = None
        self.raw_docs = []
        self.fallback = fallback
        self.is_healthy = False

    def index(self, documents: list[str]) -> None:
        self.raw_docs = documents
        try:
            from sentence_transformers import SentenceTransformer
            self.model = SentenceTransformer('all-MiniLM-L6-v2')
            self.doc_vectors = self.model.encode(documents).astype('float32')
            norms = np.linalg.norm(self.doc_vectors, axis=1, keepdims=True)
            norms[norms == 0] = 1
            self.doc_vectors = self.doc_vectors / norms
            self.is_healthy = True
        except Exception as e:
            print(f"语义模型加载失败，降级到 BM25: {e}")
            self.is_healthy = False
            self.fallback.index(documents)

    def search(self, query: str, top_k: int = 10) -> list[tuple[str, float]]:
        if not self.is_healthy:
            results = self.fallback.search(query, top_k)
            return [(doc, score * 0.8) for doc, score in results]  # 降级标记
        try:
            query_vec = self.model.encode([query]).astype('float32')
            q_norm = np.linalg.norm(query_vec)
            if q_norm > 0:
                query_vec = query_vec / q_norm
            scores = (self.doc_vectors @ query_vec.T).flatten()
            top_idx = np.argsort(-scores)[:top_k]
            return [(self.raw_docs[i], float(scores[i])) for i in top_idx]
        except Exception as e:
            print(f"语义检索出错，降级到 BM25: {e}")
            self.is_healthy = False
            return self.fallback.search(query, top_k)
```

**要点**：降级时在分数上做标记（如乘以 0.8），便于监控降级频率和影响。

### 练习五

**思路**：手动实现 NDCG，用简单例子验证正确性。

**答案**：
```python
import numpy as np

def dcg_at_k(retrieved: list, relevant: set, k: int) -> float:
    """折损累积增益"""
    dcg = 0.0
    for i, doc in enumerate(retrieved[:k]):
        if doc in relevant:
            dcg += 1.0 / np.log2(i + 2)  # log2(rank + 1), rank 从 1 开始
    return dcg

def ndcg_at_k(retrieved: list, relevant: set, k: int) -> float:
    """归一化折损累积增益"""
    dcg = dcg_at_k(retrieved, relevant, k)
    # 理想排序：所有相关文档排在最前面
    ideal_retrieved = list(relevant) + [d for d in retrieved if d not in relevant]
    idcg = dcg_at_k(ideal_retrieved, relevant, k)
    return dcg / idcg if idcg > 0 else 0.0

# 验证
relevant = {"doc_A", "doc_B", "doc_C"}

# 排序 1：相关文档排在前面
ranking1 = ["doc_A", "doc_B", "doc_C", "doc_D", "doc_E"]
# 排序 2：相关文档排在后面
ranking2 = ["doc_D", "doc_E", "doc_A", "doc_B", "doc_C"]

ndcg1 = ndcg_at_k(ranking1, relevant, k=5)
ndcg2 = ndcg_at_k(ranking2, relevant, k=5)

print(f"排序1 (相关在前): NDCG@5 = {ndcg1:.4f}")  # 1.0
print(f"排序2 (相关在后): NDCG@5 = {ndcg2:.4f}")  # < 1.0

# 验证：排序1 的 NDCG 应该为 1.0（完美排序）
assert abs(ndcg1 - 1.0) < 0.001, "完美排序的 NDCG 应为 1.0"
print("NDCG 实现验证通过")
```

**要点**：NDCG 的核心思想是——相关文档排得越靠前，得分越高。排序 1 是理想情况（NDCG=1.0），排序 2 因为相关文档被排到了后面，NDCG 明显更低。
