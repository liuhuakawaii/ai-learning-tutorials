# 语义检索

## 场景引入

前面学习的 TF-IDF、BM25 和语言模型都有一个根本局限：它们只做**字面匹配**。用户搜索"如何瘦下来"，系统无法匹配到"科学减脂方法"；搜索"苹果"，无法区分"苹果手机"和"苹果水果"。

语义检索的核心突破是：把文本映射到一个**稠密的低维向量空间**，在这个空间里，语义相近的文本距离更近。"如何瘦下来"和"科学减脂方法"虽然字面不同，但它们的向量表示会非常接近。这就是 Embedding 的力量。

这个思路的起源可以追溯到 2013 年 Word2Vec 的出现。Mikolov 等人发现，神经网络可以学到词的分布式表示，且这些表示具有惊人的语义算术性质——"king - man + woman ≈ queen"。这一发现彻底改变了 NLP 领域处理语义的方式。随后 2018 年 BERT 的出现将这一能力从词级扩展到了句子级和文档级，为语义检索奠定了技术基础。

## 学习目标

1. 理解 Embedding 的原理：从稀疏高维到稠密低维
2. 掌握 sentence-transformers 的基本用法
3. 理解向量数据库 FAISS 的索引类型与检索策略
4. 理解双塔模型的架构设计
5. 能用 Python + FAISS 实现完整的语义检索系统
6. 掌握 Embedding 模型选型和评估方法

## Embedding 原理

Embedding（嵌入）的核心思想：通过神经网络将文本映射到一个固定维度的稠密向量空间。在这个空间里：

- 语义相似的文本向量距离近
- 语义不同的文本向量距离远
- 向量的每一维不再对应某个具体词，而是某种"隐含语义特征"

与 TF-IDF 的关键区别：

| 特性 | TF-IDF 向量 | Embedding 向量 |
|------|-------------|----------------|
| 维度 | 词汇表大小（几万~几十万） | 固定（通常 384~1024） |
| 稀疏性 | 高度稀疏（>99% 为零） | 稠密（每个维度都有值） |
| 语义能力 | 无（仅字面匹配） | 有（同义词、近义词可匹配） |
| 训练方式 | 统计计算 | 神经网络训练 |
| 存储效率 | 低（稀疏向量占空间大） | 高（稠密向量可压缩） |
| 计算效率 | 高（倒排索引跳过零值） | 中（需矩阵运算） |

Embedding 的训练方式通常有三种：

1. **对比学习**：拉近相似样本的向量距离，推远不相似样本。sentence-transformers 主要用这种方式。
2. **掩码语言模型**：通过预测被遮盖的词学习语义表示，如 BERT 原始训练方式。
3. **知识蒸馏**：用大模型（如 GPT-4）的输出监督小模型，在保持效果的同时降低推理成本。

## 使用 sentence-transformers 生成 Embedding

sentence-transformers 是基于 BERT 的句子级 Embedding 库，开箱即用：

```python
from sentence_transformers import SentenceTransformer

model = SentenceTransformer('all-MiniLM-L6-v2')

sentences = [
    "如何科学减肥",
    "健康的瘦身方法推荐",
    "今天天气真好",
    "减肥食谱和运动计划",
]

embeddings = model.encode(sentences)
print(f"向量维度: {embeddings.shape}")  # (4, 384)

from numpy.linalg import norm
def cosine_sim(a, b):
    return (a @ b) / (norm(a) * norm(b))

print(f"'如何科学减肥' vs '健康的瘦身方法推荐': {cosine_sim(embeddings[0], embeddings[1]):.4f}")
print(f"'如何科学减肥' vs '今天天气真好': {cosine_sim(embeddings[0], embeddings[2]):.4f}")
```

中文场景推荐使用 `shibing624/text2vec-base-chinese` 或 `GanymedeNil/text2vec-large-chinese`。

### 向量距离度量选择

在语义检索中，选择合适的距离度量至关重要。不同度量方式适用于不同场景：

| 度量方式 | 公式 | 特点 | 适用场景 |
|----------|------|------|----------|
| 余弦相似度 | cos(a,b) | 仅关注方向，忽略模长 | 文本语义相似度（首选） |
| 内积 | a·b | 同时考虑方向和模长 | 已归一化的向量 |
| L2 距离 | ‖a-b‖ | 关注绝对位置差异 | 聚类、异常检测 |

```python
import numpy as np

def cosine_similarity(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

def inner_product(a, b):
    return np.dot(a, b)

def l2_distance(a, b):
    return np.linalg.norm(a - b)

# 对比三种度量
vec1 = np.array([0.3, 0.4, 0.5])
vec2 = np.array([0.6, 0.8, 1.0])  # vec1 的两倍，方向相同
vec3 = np.array([0.5, 0.3, 0.4])  # 不同方向

print(f"余弦相似度(vec1, vec2): {cosine_similarity(vec1, vec2):.4f}")  # 1.0（方向相同）
print(f"内积(vec1, vec2): {inner_product(vec1, vec2):.4f}")             # 0.86（模长不同）
print(f"L2距离(vec1, vec2): {l2_distance(vec1, vec2):.4f}")             # 0.7071（有距离）
print(f"余弦相似度(vec1, vec3): {cosine_similarity(vec1, vec3):.4f}")   # 0.9393
```

**工程建议**：大多数文本语义检索场景使用余弦相似度，因为它不受文本长度影响（长文本和短文本的向量模长差异很大，但方向可比）。FAISS 中使用 `IndexFlatIP` 时，需先将向量归一化，此时内积等价于余弦相似度。

## 双塔模型架构

语义检索通常采用**双塔模型**（Bi-Encoder）架构：

```
查询 → [Query Encoder] → 查询向量 (q)
                                    ↘
                                     余弦相似度 → 相关性分数
                                    ↗
文档 → [Doc Encoder]   → 文档向量 (d)
```

关键特点：
- 查询和文档分别通过独立的编码器生成向量
- 文档向量可以**离线预计算**并存储，查询时只需编码查询
- 检索阶段用向量相似度快速召回，排序阶段再用更精细的模型（Cross-Encoder）

### 为什么需要两个编码器？

在训练阶段，查询和文档的语义空间需要对齐——相关查询-文档对的向量距离应该近。两个编码器可以共享参数（大多数实现确实共享），也可以独立训练。共享参数的好处是减少模型大小和训练复杂度；独立参数的好处是允许查询和文档使用不同的表示策略。

```python
class BiEncoderRetriever:
    def __init__(self, model_name: str = 'all-MiniLM-L6-v2'):
        self.model = SentenceTransformer(model_name)
        self.doc_vectors = None
        self.raw_docs = []

    def index(self, documents: list[str]):
        self.raw_docs = documents
        self.doc_vectors = self.model.encode(documents, show_progress_bar=True)
        print(f"索引完成: {len(documents)} 个文档, 向量维度 {self.doc_vectors.shape[1]}")

    def search(self, query: str, top_k: int = 5) -> list[tuple[str, float]]:
        query_vec = self.model.encode([query])[0]
        scores = self.doc_vectors @ query_vec / (
            norm(self.doc_vectors, axis=1) * norm(query_vec)
        )
        top_indices = scores.argsort()[-top_k:][::-1]
        return [(self.raw_docs[i], float(scores[i])) for i in top_indices]
```

## FAISS：高效的向量检索

当文档量达到百万级时，逐一计算余弦相似度太慢。FAISS（Facebook AI Similarity Search）专门为大规模向量近似最近邻搜索优化。

FAISS 于 2017 年由 Facebook AI Research 发布，至今仍是工业界使用最广泛的向量检索库之一。它的核心优势是：充分利用 GPU 加速、支持多种近似索引、API 简洁高效。

核心索引类型：

| 索引类型 | 特点 | 适用规模 | 精度 |
|----------|------|----------|------|
| IndexFlatL2 | 暴力搜索，精确 | <10万 | 100% |
| IndexIVFFlat | 倒排文件，分区搜索 | 10万~1000万 | 95%+ |
| IndexHNSW | 层次化可导航小世界图 | 100万~1亿 | 98%+ |
| IndexIVFPQ | 倒排+乘积量化 | 1000万~10亿 | 90%+ |

### IVF 索引原理

IVF（Inverted File）索引的核心思想是**先聚类再搜索**：用 k-means 将所有向量分成若干簇（nlist），查询时只搜索最近的若干簇（nprobe），而非全部向量。nprobe 越大，精度越高但速度越慢。

```python
import faiss
import numpy as np

dim = 384
nlist = 100  # 聚类中心数
nprobe = 10  # 查询时搜索的聚类中心数

quantizer = faiss.IndexFlatIP(dim)
index = faiss.IndexIVFFlat(quantizer, dim, nlist, faiss.METRIC_INNER_PRODUCT)
index.nprobe = nprobe

# 必须先 train 再 add
vectors = np.random.randn(100000, dim).astype('float32')
faiss.normalize_L2(vectors)
index.train(vectors)
index.add(vectors)
print(f"索引大小: {index.ntotal} 个向量")
```

### HNSW 索引原理

HNSW（Hierarchical Navigable Small World）是一种基于图的索引结构。它构建一个多层图，上层稀疏（用于快速定位大致区域），下层稠密（用于精确搜索）。查询从上层开始，逐层向下精化，类似"先看地图找区域，再进小区找楼号"。

```python
import faiss
import numpy as np

dim = 384
M = 32  # 每个节点的连接数，越大精度越高但内存越大
efSearch = 64  # 搜索时的候选集大小，越大越精确但越慢
efConstruction = 100  # 构建时的候选集大小

index = faiss.IndexHNSWFlat(dim, M)
index.hnsw.efSearch = efSearch
index.hnsw.efConstruction = efConstruction

vectors = np.random.randn(100000, dim).astype('float32')
faiss.normalize_L2(vectors)
index.add(vectors)

# HNSW 不需要 train，直接 add 即可
query = np.random.randn(1, dim).astype('float32')
faiss.normalize_L2(query)
scores, indices = index.search(query, 10)
```

### PQ（乘积量化）原理

PQ 将高维向量分成若干子空间，每个子空间独立做 k-means 聚类，用聚类中心的编号替代原始向量值。这使得存储从 4 字节/维度降到 1 字节/子空间，压缩比极高。IVF+PQ 组合是亿级向量检索的标准方案。

```python
import faiss
import numpy as np

dim = 384
nlist = 100
m = 32       # 子空间数量，dim 必须能被 m 整除
nbits = 8    # 每个子空间的聚类中心数为 2^nbits

quantizer = faiss.IndexFlatIP(dim)
index = faiss.IndexIVFPQ(quantizer, dim, nlist, m, nbits, faiss.METRIC_INNER_PRODUCT)
index.nprobe = 10

vectors = np.random.randn(1000000, dim).astype('float32')
faiss.normalize_L2(vectors)
index.train(vectors)
index.add(vectors)

# 内存占用: 100万 * 384维 * 4字节 = 1.46GB (原始)
# PQ 压缩后: 100万 * 32字节 = 30.5MB (压缩比 ~48x)
print(f"索引大小: {index.ntotal}, PQ 压缩后每向量 {m} 字节")
```

## 完整的语义检索系统

将双塔模型和 FAISS 组合，构建完整的语义检索系统：

```python
import faiss
import numpy as np
from sentence_transformers import SentenceTransformer
from numpy.linalg import norm

class SemanticSearchEngine:
    def __init__(self, model_name='all-MiniLM-L6-v2', index_type='flat'):
        self.model = SentenceTransformer(model_name)
        self.index_type = index_type
        self.index = None
        self.raw_docs = []

    def build_index(self, documents: list[str]):
        self.raw_docs = documents
        print(f"正在编码 {len(documents)} 个文档...")
        vectors = self.model.encode(documents, batch_size=64, show_progress_bar=True)
        vectors = vectors.astype('float32')
        faiss.normalize_L2(vectors)
        dim = vectors.shape[1]

        if self.index_type == 'flat':
            self.index = faiss.IndexFlatIP(dim)
        elif self.index_type == 'hnsw':
            self.index = faiss.IndexHNSWFlat(dim, 32)
            self.index.hnsw.efSearch = 64
        elif self.index_type == 'ivf':
            nlist = min(100, len(documents) // 10)
            quantizer = faiss.IndexFlatIP(dim)
            self.index = faiss.IndexIVFFlat(quantizer, dim, nlist, faiss.METRIC_INNER_PRODUCT)
            self.index.nprobe = min(10, nlist)
            self.index.train(vectors)

        self.index.add(vectors)
        print(f"索引完成: {self.index.ntotal} 个文档, 维度={dim}")

    def search(self, query: str, top_k: int = 10) -> list[dict]:
        query_vec = self.model.encode([query]).astype('float32')
        faiss.normalize_L2(query_vec)
        scores, indices = self.index.search(query_vec, top_k)
        results = []
        for rank, (score, idx) in enumerate(zip(scores[0], indices[0])):
            if idx >= 0:
                results.append({
                    "rank": rank + 1,
                    "doc": self.raw_docs[idx],
                    "score": round(float(score), 4),
                })
        return results

documents = [
    "Python是一种广泛使用的高级编程语言",
    "机器学习算法包括决策树、随机森林和神经网络",
    "深度学习是机器学习的一个子领域",
    "自然语言处理涉及文本分析和语义理解",
    "计算机视觉用于图像识别和目标检测",
    "推荐系统通过用户行为数据进行个性化推荐",
    "搜索引擎使用倒排索引提高检索效率",
    "数据挖掘从大量数据中发现有价值的模式",
    "强化学习通过与环境交互学习最优策略",
    "知识图谱用于表示实体之间的关系",
]

engine = SemanticSearchEngine(index_type='flat')
engine.build_index(documents)

for query in ["AI技术", "文本处理"]:
    print(f"\n查询: {query}")
    for r in engine.search(query, top_k=3):
        print(f"  [{r['rank']}] {r['score']:.4f} | {r['doc']}")
```

### 批量编码与增量更新

生产环境中，文档不是一次性全部到齐的。需要支持增量添加新文档：

```python
import numpy as np
import faiss

class IncrementalSemanticEngine:
    def __init__(self, model, dim: int):
        self.model = model
        self.dim = dim
        self.index = faiss.IndexFlatIP(dim)
        self.raw_docs = []
        self.doc_vectors = []

    def add_documents(self, documents: list[str]):
        new_vecs = self.model.encode(documents, batch_size=64).astype('float32')
        faiss.normalize_L2(new_vecs)
        self.index.add(new_vecs)
        self.raw_docs.extend(documents)
        self.doc_vectors.append(new_vecs)
        print(f"新增 {len(documents)} 个文档, 总计 {self.index.ntotal}")

    def search(self, query: str, top_k: int = 10):
        q = self.model.encode([query]).astype('float32')
        faiss.normalize_L2(q)
        scores, ids = self.index.search(q, top_k)
        return [(self.raw_docs[i], float(s)) for s, i in zip(scores[0], ids[0]) if i >= 0]
```

**注意**：IVF 和 HNSW 索引不支持高效的增量添加。IVF 新增后聚心会过时，HNSW 的图结构需要重建。对于频繁增量场景，建议用 IndexFlatIP（小数据）或定期全量重建索引。

## 双塔 vs 交叉编码器

| 方案 | 速度 | 精度 | 用途 |
|------|------|------|------|
| Bi-Encoder（双塔） | 快（毫秒级） | 中等 | 召回阶段（从百万文档中找候选） |
| Cross-Encoder（交叉编码器） | 慢（秒级） | 高 | 排序阶段（对候选文档精排） |

典型的两阶段检索流程：
1. **召回**：Bi-Encoder + FAISS 从百万文档中快速找到 Top-100 候选
2. **排序**：Cross-Encoder 对 Top-100 精细打分，输出 Top-10

```python
from sentence_transformers import CrossEncoder

# Cross-Encoder 将查询和文档拼接后一起输入模型
cross_encoder = CrossEncoder('cross-encoder/ms-marco-MiniLM-L-6-v2')

query = "如何科学减肥"
candidates = [
    "健康饮食搭配适量运动是最有效的减肥方法",
    "今天股市行情不错，涨幅较大",
    "科学减脂需要控制热量摄入并增加有氧运动",
]

# Cross-Encoder 的输入是 (query, doc) 对
pairs = [[query, doc] for doc in candidates]
scores = cross_encoder.predict(pairs)

for doc, score in sorted(zip(candidates, scores), key=lambda x: -x[1]):
    print(f"  {score:.4f} | {doc}")
```

**为什么不在召回阶段也用 Cross-Encoder？** 因为 Cross-Encoder 需要对每个 (query, doc) 对独立推理，100 万个文档就需要 100 万次推理，延迟不可接受。Bi-Encoder 的优势在于文档向量可以离线预计算，查询时只需一次编码 + 向量检索。

## Embedding 模型选型指南

选择 Embedding 模型时需要考虑四个维度：

| 维度 | 考虑因素 |
|------|----------|
| 语言支持 | 中文场景选 text2vec、bge 系列；多语言选 paraphrase-multilingual |
| 向量维度 | 维度越高语义越精细，但存储和计算成本越大。384 维适合大部分场景 |
| 推理速度 | 小模型（MiniLM）比大模型（BERT-large）快 5~10 倍 |
| 领域适配 | 通用模型在医疗、法律等专业领域效果下降明显，需微调 |

```python
from sentence_transformers import SentenceTransformer
import time

models = {
    "MiniLM-L6": "all-MiniLM-L6-v2",          # 22M 参数, 384 维
    "base-chinese": "shibing624/text2vec-base-chinese",  # 102M 参数, 768 维
}

sentences = ["如何科学减肥"] * 100

for name, model_name in models.items():
    model = SentenceTransformer(model_name)
    start = time.time()
    vecs = model.encode(sentences, batch_size=32)
    elapsed = time.time() - start
    print(f"{name}: {elapsed:.2f}s, 维度={vecs.shape[1]}, "
          f"速度={len(sentences)/elapsed:.0f} 条/秒")
```

## 常见误区

1. **认为 Embedding 一定比 BM25 好**：在关键词精确匹配场景下（如商品编号、人名搜索），BM25 往往更准确。语义检索擅长模糊匹配和同义词扩展。

2. **忽略向量归一化**：FAISS 的内积搜索要求向量已归一化，否则结果不等价于余弦相似度。未归一化的内积受向量模长影响，长文本的向量模长通常更大，会导致检索偏向长文档。

3. **盲目使用大模型**：all-MiniLM-L6-v2（22M 参数）在很多场景下效果够用，且速度是大模型的 10 倍以上。先用小模型验证效果，再考虑升级。

4. **索引构建后不测试召回率**：不同 FAISS 索引类型有不同的精度损失，必须在构建后评估 Recall@K。IVF 索引的 nprobe 设置对召回率影响极大。

5. **忽略 Embedding 的领域迁移问题**：通用 Embedding 模型在特定领域（如医疗、法律）效果可能不佳，需要微调或使用领域专用模型。例如"感冒"和"上呼吸道感染"在通用模型中可能不够相似，但在医疗语义空间中应该很接近。

6. **过度依赖默认参数**：FAISS 索引的参数（nlist、nprobe、M、efSearch）对性能和精度影响很大，必须根据数据规模和业务需求调优。默认值往往不是最优的。

7. **忽略向量存储的内存开销**：100 万个 768 维 float32 向量需要约 2.9GB 内存。如果文档量大，需要考虑 PQ 压缩或使用磁盘索引。

## 工程建议

1. **先用暴力搜索验证效果**：数据量小于 10 万时，用 IndexFlatL2 暴力搜索，精确且简单。确认效果后再换近似索引。

2. **选择合适的索引类型**：10 万~100 万用 HNSW，100 万以上用 IVF+PQ。HNSW 在召回率和速度之间平衡最好。

3. **定期重建索引**：文档频繁增删时，IVF 类索引的聚心会过时，需要定期重建。建议设置定时任务，每周或每月全量重建。

4. **批量编码**：生成 Embedding 时用 batch_size=64~256 的批量编码，比逐条编码快 5~10 倍。GPU 环境下 batch_size 可以更大。

5. **存储原始向量**：FAISS 索引中的向量可能被量化压缩，保留原始向量用于后续增量更新和索引重建。

6. **监控检索质量**：在线上系统中，定期采样查询和结果，计算人工标注的 Precision@K，确保检索质量不退化。

7. **考虑多级索引**：对于超大规模数据（亿级），可以用 IVF 做粗召回，再用 HNSW 在子集中精搜，兼顾速度和精度。

## 小结

- Embedding 将文本映射到稠密低维向量空间，能捕捉语义相似性，突破字面匹配限制。
- sentence-transformers 提供开箱即用的句子级 Embedding，中文推荐 text2vec 系列模型。
- 双塔模型将查询和文档分别编码，文档向量可离线预计算，查询时只需编码查询。
- FAISS 提供多种索引类型，支持亿级向量的毫秒级近似最近邻搜索。
- 生产环境常用两阶段架构：Bi-Encoder 召回 + Cross-Encoder 排序。
- 选型时需权衡语言支持、向量维度、推理速度和领域适配四个维度。

## 参考答案

### 练习一

**思路**：用相同句子在两个模型上编码，计算相似度矩阵，观察同义句对的相似度差异。

**答案**：
```python
from sentence_transformers import SentenceTransformer
import numpy as np

sentences = ["如何科学减肥", "健康的瘦身方法", "Python编程入门",
             "学习Python语言基础", "今天股市行情不错", "股票市场今日上涨"]

for name, model_name in [("english", 'all-MiniLM-L6-v2'),
                          ("chinese", 'shibing624/text2vec-base-chinese')]:
    model = SentenceTransformer(model_name)
    vecs = model.encode(sentences)
    sim = np.zeros((6, 6))
    for i in range(6):
        for j in range(6):
            sim[i][j] = np.dot(vecs[i], vecs[j]) / (np.linalg.norm(vecs[i]) * np.linalg.norm(vecs[j]))
    print(f"{name}: 同义句(0,1)={sim[0][1]:.4f}, 无关句(0,2)={sim[0][2]:.4f}")
```

**要点**：中文模型对中文同义句区分度更高，选模型时先用少量样例测试。

### 练习二

**思路**：生成随机向量，分别构建三种索引，用暴力搜索结果计算 Recall@K。

**答案**：
```python
import faiss, numpy as np, time

dim, n = 128, 10000
vecs = np.random.randn(n, dim).astype('float32')
queries = np.random.randn(100, dim).astype('float32')
faiss.normalize_L2(vecs); faiss.normalize_L2(queries)

gt = faiss.IndexFlatIP(dim); gt.add(vecs)
_, gt_idx = gt.search(queries, 10)

for name, idx in [("Flat", faiss.IndexFlatIP(dim)),
                   ("IVF", faiss.IndexIVFFlat(faiss.IndexFlatIP(dim), dim, 100)),
                   ("HNSW", faiss.IndexHNSWFlat(dim, 32))]:
    if hasattr(idx, 'train'): idx.train(vecs)
    t0 = time.time(); idx.add(vecs); bt = time.time() - t0
    t0 = time.time(); _, pred = idx.search(queries, 10); st = time.time() - t0
    recall = np.mean([len(set(g) & set(p)) / 10 for g, p in zip(gt_idx, pred)])
    print(f"{name}: 构建={bt*1000:.0f}ms, 查询={st*1000:.1f}ms, Recall={recall:.2%}")
```

**要点**：FlatL2 精度 100% 但最慢，HNSW 速度和精度平衡最好，IVFFlat 需要先 train。

### 练习三

**思路**：分别用 BM25 和语义检索检索，计算 MRR（第一个相关结果的排名倒数的均值）。

**答案**：
```python
def compute_mrr(results, ground_truth):
    rr_sum = 0.0
    for retrieved, relevant in zip(results, ground_truth):
        for rank, doc in enumerate(retrieved, 1):
            if doc in relevant:
                rr_sum += 1.0 / rank
                break
    return rr_sum / len(results)

# bm25_mrr = compute_mrr(bm25_results, ground_truth)
# semantic_mrr = compute_mrr(semantic_results, ground_truth)
```

**要点**：MRR 衡量第一个正确结果出现得早晚，两者结合（混合检索）通常能取得最佳 MRR。

### 练习四

**思路**：先用 Bi-Encoder 召回 Top-20，再用 CrossEncoder 对这 20 个结果精排，对比精排前后的排序质量。

**答案**：
```python
from sentence_transformers import SentenceTransformer, CrossEncoder

bi_encoder = SentenceTransformer('all-MiniLM-L6-v2')
cross_encoder = CrossEncoder('cross-encoder/ms-marco-MiniLM-L-6-v2')

query = "如何科学减肥"
docs = ["健康饮食是减肥的基础", "股市今天大涨", "有氧运动帮助减脂",
        "Python编程入门教程", "控制热量摄入很重要"]

doc_vecs = bi_encoder.encode(docs)
q_vec = bi_encoder.encode([query])
scores_bi = (doc_vecs @ q_vec.T).flatten()

pairs = [[query, d] for d in docs]
scores_cross = cross_encoder.predict(pairs)

print("Bi-Encoder 排序:", [i for i in np.argsort(-scores_bi)])
print("Cross-Encoder 排序:", [i for i in np.argsort(-scores_cross)])
# Cross-Encoder 通常对语义相关性判断更准确
```

**要点**：Cross-Encoder 通过注意力机制捕捉查询和文档的交互信息，比 Bi-Encoder 的独立编码更精确，但速度慢得多。

### 练习五

**思路**：对同一个 Embedding 向量截取不同维度子集，对比检索精度变化。

**答案**：
```python
import numpy as np
from sentence_transformers import SentenceTransformer

model = SentenceTransformer('all-MiniLM-L6-v2')  # 384 维

docs = ["Python编程入门", "机器学习基础", "今天天气好", "深度学习神经网络"]
query = "如何学习编程"

full_vecs = model.encode(docs)
q_full = model.encode([query])

for dim in [64, 128, 256, 384]:
    vecs = full_vecs[:, :dim]
    q = q_full[:, :dim]
    scores = (vecs @ q.T).flatten()
    ranking = np.argsort(-scores)
    top1_score = scores[ranking[0]]
    print(f"dim={dim:>3}: Top1={docs[ranking[0]][:15]}, score={top1_score:.4f}")

# 维度越高语义越精细，但存储和计算成本越大
# 128~256 维在很多场景下已经够用
```

**要点**：维度截断会损失语义信息，但低维向量的存储和检索效率更高。实际项目中需要在精度和效率之间权衡。
