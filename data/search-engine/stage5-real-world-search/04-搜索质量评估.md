# 搜索质量评估：用数据驱动搜索优化

## 场景引入

你的搜索引擎上线一个月了，用户反馈"搜索不太准"。但"不太准"是一个模糊的描述——是召回率不够？排序有问题？还是特定查询类型表现差？

搜索质量评估就是将这种模糊感受转化为可量化的指标。通过离线评估（NDCG、MAP 等）和在线评估（点击率、跳出率），你能精确知道搜索引擎哪里好、哪里差。本节课将带你实现完整的搜索评估体系。

## 学习目标

1. 理解并实现 NDCG@k、MRR、MAP、Precision@k 等离线评估指标
2. 设计在线评估指标（点击率、跳出率、零结果率）
3. 实现 A/B 测试框架用于搜索引擎迭代
4. 掌握评估数据集的构建与管理方法

## 为什么搜索评估如此重要

搜索引擎是典型的"冰山系统"——用户只看到搜索框和结果列表，看不到背后的分词、索引、排序、过滤等复杂逻辑。任何一个环节出问题，用户感受到的都是"搜索不准"。

搜索评估的价值在于：**将主观感受转化为客观指标，将模糊问题定位到具体环节**。比如 NDCG 低说明排序有问题，Precision 低说明召回了太多不相关结果，CTR 低说明结果展示不够吸引人。

历史上，Google 的搜索质量团队从 2000 年代初就建立了严格的评估体系。他们有数千名"质量评估员"按照详细的指南对搜索结果打分。这些标注数据驱动了从 PageRank 到 BERT 的每一代排序算法升级。

## 标注数据集

离线评估基于人工标注的查询-文档相关性数据集：

### 标注数据集的构建方法

标注数据集的质量直接决定评估的可靠性。构建方法有几种：

```python
import random
import json
from datetime import datetime

class JudgmentDataset:
    def __init__(self):
        self.judgments = []
        self.metadata = {
            "created_at": datetime.utcnow().isoformat(),
            "version": "1.0",
            "labelers": [],
            "guidelines": ""
        }

    def add_judgment(self, query: str, doc_id: str, relevance: int,
                     labeler: str = None, confidence: int = 3):
        self.judgments.append({
            "query": query,
            "doc_id": doc_id,
            "relevance": relevance,
            "labeler": labeler,
            "confidence": confidence,
            "timestamp": datetime.utcnow().isoformat()
        })

    def get_query_judgments(self, query: str) -> list[dict]:
        return [j for j in self.judgments if j["query"] == query]

    def calculate_agreement(self, query: str) -> dict:
        """计算标注者之间的一致性（Kappa 系数）"""
        query_judgments = self.get_query_judgments(query)
        if len(query_judgments) < 2:
            return {"kappa": None, "message": "标注数据不足"}

        by_doc = {}
        for j in query_judgments:
            if j["doc_id"] not in by_doc:
                by_doc[j["doc_id"]] = []
            by_doc[j["doc_id"]].append(j["relevance"])

        agreements = 0
        total = 0
        for doc_id, scores in by_doc.items():
            if len(scores) >= 2:
                total += 1
                if len(set(scores)) == 1:
                    agreements += 1

        return {
            "agreement_rate": agreements / total if total > 0 else 0,
            "total_pairs": total,
            "agreed_pairs": agreements
        }

    def export_for_labeling(self, queries: list[str], results: dict,
                            max_docs_per_query: int = 10) -> list[dict]:
        """导出待标注数据"""
        tasks = []
        for query in queries:
            docs = results.get(query, [])[:max_docs_per_query]
            for doc_id in docs:
                tasks.append({
                    "query": query,
                    "doc_id": doc_id,
                    "relevance": None
                })
        return tasks

    def sample_for_review(self, n: int = 20) -> list[dict]:
        """随机抽样用于质量检查"""
        return random.sample(self.judgments, min(n, len(self.judgments)))
```

标注数据集的关键原则：

1. **查询选择**：评估集应覆盖高频查询、长尾查询和零结果查询，不能只选简单的。
2. **标注指南**：必须定义清晰的相关性等级标准（如 0=完全不相关、1=部分相关、2=高度相关）。
3. **多人标注**：同一查询-文档对至少两人标注，计算一致性（Kappa > 0.6 才可信）。
4. **定期更新**：搜索结果变化后，旧标注可能失效，需要定期更新。

## Precision@k 和 Recall@k

最基础的指标：前 k 个结果中有多少是相关的。

```python
def precision_at_k(query: str, k: int) -> float:
    results = SEARCH_RESULTS[query][:k]
    judgments = {j.doc_id: j.relevance for j in JUDGMENTS[query]}
    return sum(1 for d in results if judgments.get(d, 0) >= 1) / k

def recall_at_k(query: str, k: int) -> float:
    results = SEARCH_RESULTS[query][:k]
    judgments = {j.doc_id: j.relevance for j in JUDGMENTS[query]}
    total_relevant = sum(1 for j in JUDGMENTS[query] if j.relevance >= 1)
    if total_relevant == 0: return 0.0
    return sum(1 for d in results if judgments.get(d, 0) >= 1) / total_relevant
```

Precision@k 回答"前 k 个结果中相关文档的比例"，Recall@k 回答"所有相关文档中被找到的比例"。

### Precision 和 Recall 的 tradeoff

Precision 和 Recall 往往是此消彼长的关系：

- **提高 Precision**：提高匹配阈值，只返回最确定的结果。代价是可能漏掉一些相关文档（Recall 降低）。
- **提高 Recall**：降低匹配阈值，返回更多候选结果。代价是引入更多不相关结果（Precision 降低）。

不同场景对两者的侧重不同：

```python
# 电商搜索：Precision 更重要
# 用户不会翻到第 10 页，前 5 个结果必须精准
# 目标：Precision@5 > 0.8

# 法律检索：Recall 更重要
# 漏掉一个关键判例可能导致败诉
# 目标：Recall@100 > 0.95

# 通用搜索：F1 平衡
# 两个都不能太差
def f1_at_k(query: str, k: int) -> float:
    p = precision_at_k(query, k)
    r = recall_at_k(query, k)
    return 2 * p * r / (p + r) if (p + r) > 0 else 0.0
```

## Mean Reciprocal Rank (MRR)

MRR 衡量第一个相关结果出现的位置，适合"只有一个正确答案"的场景：

```python
def reciprocal_rank(query: str) -> float:
    judgments = {j.doc_id: j.relevance for j in JUDGMENTS[query]}
    for rank, doc_id in enumerate(SEARCH_RESULTS[query], start=1):
        if judgments.get(doc_id, 0) >= 1:
            return 1.0 / rank
    return 0.0

def mean_reciprocal_rank(queries: list[str]) -> float:
    return sum(reciprocal_rank(q) for q in queries) / len(queries)
```

如果第一个相关结果排在第 1 位，RR=1.0；排在第 2 位，RR=0.5。MRR 越高说明用户越快找到想要的内容。

### MRR 的适用场景

MRR 最适合"唯一正确答案"的场景，如：

- **导航型查询**：搜"淘宝登录"，期望淘宝官网排第一。
- **问答系统**：问"Python 怎么读文件"，期望最佳答案排第一。
- **商品搜索**：搜具体型号"iPhone 15 Pro Max 256GB"，期望目标商品排第一。

MRR 不适合需要多个结果的场景（如"推荐几本 Python 书"），因为它只关注第一个相关结果的位置。

## NDCG@k

NDCG 是搜索评估最重要的指标，考虑了相关性等级和位置衰减：

```python
import math

def dcg_at_k(query: str, k: int) -> float:
    results = SEARCH_RESULTS[query][:k]
    judgments = {j.doc_id: j.relevance for j in JUDGMENTS[query]}
    return sum(
        (2 ** judgments.get(doc_id, 0) - 1) / math.log2(rank + 2)
        for rank, doc_id in enumerate(results)
    )

def ndcg_at_k(query: str, k: int) -> float:
    dcg = dcg_at_k(query, k)
    relevances = sorted([j.relevance for j in JUDGMENTS[query]], reverse=True)[:k]
    idcg = sum((2 ** r - 1) / math.log2(i + 2) for i, r in enumerate(relevances))
    return dcg / idcg if idcg > 0 else 0.0
```

NDCG 的核心思想：高相关文档排在前面得分更高（`2^relevance - 1`），位置越靠后折扣越大（`log2(rank+2)`）。NDCG 是唯一能处理多级相关性的指标。

### NDCG 的数学直觉

理解 NDCG 需要理解三个概念：

1. **DCG（Discounted Cumulative Gain）**：累加每个位置的增益，但位置越靠后增益越小。增益用 `2^relevance - 1` 计算，相关性 2 的增益是 3，相关性 1 的增益是 1。
2. **IDCG（Ideal DCG）**：将所有相关文档按最佳顺序排列时的 DCG，作为归一化的基准。
3. **NDCG = DCG / IDCG**：实际排序的 DCG 除以理想排序的 IDCG，值域 [0, 1]。

```python
# 手动计算示例
# 查询："python入门"
# 标注：doc-1(相关性2), doc-2(相关性2), doc-3(相关性1), doc-4(相关性0), doc-5(相关性1)
# 搜索结果排序：doc-3, doc-1, doc-4, doc-2, doc-5

# DCG 计算：
# 位置1: doc-3, 相关性1, 增益 = (2^1-1)/log2(3) = 1/1.585 = 0.631
# 位置2: doc-1, 相关性2, 增益 = (2^2-1)/log2(4) = 3/2.0 = 1.5
# 位置3: doc-4, 相关性0, 增益 = (2^0-1)/log2(5) = 0/2.322 = 0
# 位置4: doc-2, 相关性2, 增益 = (2^2-1)/log2(6) = 3/2.585 = 1.161
# 位置5: doc-5, 相关性1, 增益 = (2^1-1)/log2(7) = 1/2.807 = 0.356
# DCG = 0.631 + 1.5 + 0 + 1.161 + 0.356 = 3.648

# IDCG 计算（最佳排序：相关性 2,2,1,1,0）：
# 位置1: 2, 增益 = 3/1.585 = 1.892
# 位置2: 2, 增益 = 3/2.0 = 1.5
# 位置3: 1, 增益 = 1/2.322 = 0.431
# 位置4: 1, 增益 = 1/2.585 = 0.387
# 位置5: 0, 增益 = 0
# IDCG = 1.892 + 1.5 + 0.431 + 0.387 + 0 = 4.21

# NDCG = 3.648 / 4.21 = 0.867
```

NDCG 为 0.867 说明当前排序与理想排序差距不大。如果 doc-1 和 doc-2（高相关）排在前两位，NDCG 会接近 1.0。

## Mean Average Precision (MAP)

MAP 综合考虑所有相关文档的排名位置：

```python
def average_precision(query: str) -> float:
    results = SEARCH_RESULTS[query]
    judgments = {j.doc_id: j.relevance for j in JUDGMENTS[query]}
    total_relevant = sum(1 for j in JUDGMENTS[query] if j.relevance >= 1)
    if total_relevant == 0: return 0.0

    precision_sum = 0.0
    found = 0
    for rank, doc_id in enumerate(results, start=1):
        if judgments.get(doc_id, 0) >= 1:
            found += 1
            precision_sum += found / rank
    return precision_sum / total_relevant

def mean_average_precision(queries: list[str]) -> float:
    return sum(average_precision(q) for q in queries) / len(queries)
```

如果两个相关文档分别排在第 1 和第 3 位，AP = (1/1 + 2/3) / 2 = 0.833。MAP 越高说明相关文档整体排名越靠前。

### MAP 与 NDCG 的区别

两者都是位置敏感的指标，但适用场景不同：

- **MAP**：适合二元相关性（相关/不相关），不支持多级相关性。
- **NDCG**：支持多级相关性（0/1/2/3），适合电商搜索等需要精细区分相关程度的场景。
- **MAP** 的计算中，每个相关文档的贡献是"该位置的 Precision"，关注的是"相关文档出现时的排名质量"。
- **NDCG** 的计算中，每个文档的贡献是"增益/折扣"，关注的是"高相关文档是否排在前面"。

实际使用中，NDCG 比 MAP 更常用，因为它能处理多级相关性。

## 在线评估指标

在线评估用真实用户行为衡量搜索质量：

```python
from collections import defaultdict

class OnlineMetrics:
    def __init__(self):
        self.events = []

    def log_event(self, query: str, event_type: str,
                  doc_id: str = None, session_id: str = ""):
        self.events.append({
            "query": query, "event_type": event_type,
            "doc_id": doc_id, "session_id": session_id
        })

    def click_through_rate(self, query: str = None) -> dict:
        filtered = [e for e in self.events if query is None or e["query"] == query]
        searches = sum(1 for e in filtered if e["event_type"] == "search")
        clicks = sum(1 for e in filtered if e["event_type"] == "click")
        return {"ctr": clicks / max(searches, 1), "searches": searches, "clicks": clicks}

    def bounce_rate(self, query: str = None) -> dict:
        sessions = defaultdict(list)
        for e in self.events:
            if query is None or e["query"] == query:
                sessions[e["session_id"]].append(e)
        total = len(sessions)
        bounced = sum(1 for evts in sessions.values()
                      if sum(1 for e in evts if e["event_type"] == "click") == 0)
        return {"bounce_rate": bounced / max(total, 1), "total": total, "bounced": bounced}

    def zero_result_rate(self) -> dict:
        searches = [e for e in self.events if e["event_type"] == "search"]
        zero = [e for e in searches if e.get("result_count", 1) == 0]
        return {
            "zero_result_rate": len(zero) / max(len(searches), 1),
            "total": len(searches),
            "zero_queries": [e["query"] for e in zero]
        }
```

CTR 低说明结果不吸引人，跳出率高说明用户找不到想要的，零结果率高说明索引覆盖不足。

### 更多在线指标

除了 CTR 和跳出率，还有几个重要的在线指标：

```python
class AdvancedOnlineMetrics(OnlineMetrics):
    def abandoned_search_rate(self) -> dict:
        """搜索放弃率：用户搜索后没有任何后续操作"""
        sessions = defaultdict(list)
        for e in self.events:
            sessions[e["session_id"]].append(e)

        total_searches = 0
        abandoned = 0
        for session_events in sessions.values():
            search_events = [e for e in session_events if e["event_type"] == "search"]
            click_events = [e for e in session_events if e["event_type"] == "click"]
            total_searches += len(search_events)
            if search_events and not click_events:
                abandoned += len(search_events)

        return {
            "abandon_rate": abandoned / max(total_searches, 1),
            "total_searches": total_searches,
            "abandoned": abandoned
        }

    def reformulation_rate(self) -> dict:
        """查询重写率：用户搜索后修改查询重新搜索"""
        sessions = defaultdict(list)
        for e in self.events:
            sessions[e["session_id"]].append(e)

        total_sessions = 0
        reformulated = 0
        for session_events in sessions.values():
            searches = [e for e in session_events if e["event_type"] == "search"]
            if len(searches) >= 2:
                total_sessions += 1
                queries = [s["query"] for s in searches]
                if len(set(queries)) > 1:
                    reformulated += 1

        return {
            "reformulation_rate": reformulated / max(total_sessions, 1),
            "total_sessions": total_sessions,
            "reformulated": reformulated
        }

    def time_to_click(self) -> dict:
        """搜索到点击的时间间隔"""
        sessions = defaultdict(list)
        for e in self.events:
            sessions[e["session_id"]].append(e)

        intervals = []
        for session_events in sessions.values():
            searches = [e for e in session_events if e["event_type"] == "search"]
            clicks = [e for e in session_events if e["event_type"] == "click"]
            if searches and clicks:
                from datetime import datetime
                search_time = datetime.fromisoformat(searches[0].get("timestamp", ""))
                click_time = datetime.fromisoformat(clicks[0].get("timestamp", ""))
                intervals.append((click_time - search_time).total_seconds())

        return {
            "avg_seconds": sum(intervals) / max(len(intervals), 1),
            "p50_seconds": sorted(intervals)[len(intervals) // 2] if intervals else 0,
            "sample_size": len(intervals)
        }
```

查询重写率高说明首次搜索结果不满意；搜索放弃率高说明结果完全没有吸引力；时间到点击长说明用户需要仔细浏览才能找到想要的结果。

## A/B 测试框架

搜索引擎的每次优化都需要通过 A/B 测试验证效果：

```python
import hashlib
import math
from scipy import stats

class ABTestFramework:
    def __init__(self):
        self.experiments = {}

    def create_experiment(self, name: str, variants: list[str]):
        self.experiments[name] = {
            "variants": variants,
            "results": {v: {"impressions": 0, "clicks": 0} for v in variants}
        }

    def assign_variant(self, experiment_name: str, user_id: str) -> str:
        exp = self.experiments[experiment_name]
        hash_val = hashlib.md5(f"{experiment_name}:{user_id}".encode()).hexdigest()
        idx = int(hash_val[:8], 16) % len(exp["variants"])
        return exp["variants"][idx]

    def log_impression(self, experiment_name: str, variant: str):
        self.experiments[experiment_name]["results"][variant]["impressions"] += 1

    def log_click(self, experiment_name: str, variant: str):
        self.experiments[experiment_name]["results"][variant]["clicks"] += 1

    def evaluate(self, experiment_name: str):
        exp = self.experiments[experiment_name]
        a, b = exp["variants"]
        a_data, b_data = exp["results"][a], exp["results"][b]
        a_rate = a_data["clicks"] / max(a_data["impressions"], 1)
        b_rate = b_data["clicks"] / max(b_data["impressions"], 1)

        p_pool = (a_data["clicks"] + b_data["clicks"]) / max(
            a_data["impressions"] + b_data["impressions"], 1)
        se = math.sqrt(p_pool * (1 - p_pool) * (
            1/max(a_data["impressions"], 1) + 1/max(b_data["impressions"], 1)))

        z_score = (b_rate - a_rate) / se if se > 0 else 0
        p_value = 2 * (1 - stats.norm.cdf(abs(z_score)))

        return {
            "a": {"name": a, "ctr": a_rate}, "b": {"name": b, "ctr": b_rate},
            "lift": (b_rate - a_rate) / max(a_rate, 0.001),
            "p_value": p_value,
            "is_significant": p_value < 0.05
        }
```

用户 ID 哈希保证同一用户始终看到同一变体。Z 检验判断两组 CTR 差异是否具有统计显著性。

### A/B 测试的样本量计算

在启动 A/B 测试之前，需要计算需要多少样本才能检测到预期的效果差异：

```python
def calculate_sample_size(baseline_rate: float, min_detectable_effect: float,
                          significance: float = 0.05, power: float = 0.8) -> int:
    """计算 A/B 测试所需的最小样本量"""
    from scipy import stats as sp_stats

    alpha = significance
    beta = 1 - power

    z_alpha = sp_stats.norm.ppf(1 - alpha / 2)
    z_beta = sp_stats.norm.ppf(power)

    p1 = baseline_rate
    p2 = baseline_rate * (1 + min_detectable_effect)
    p_avg = (p1 + p2) / 2

    n = ((z_alpha * math.sqrt(2 * p_avg * (1 - p_avg)) +
          z_beta * math.sqrt(p1 * (1 - p1) + p2 * (1 - p2))) ** 2) / (p2 - p1) ** 2

    return math.ceil(n)

# 示例：基线 CTR 5%，期望检测 10% 的相对提升
sample_size = calculate_sample_size(
    baseline_rate=0.05,
    min_detectable_effect=0.10,
    significance=0.05,
    power=0.8
)
print(f"每组需要至少 {sample_size} 次曝光")
```

如果基线 CTR 为 5%，想检测 10% 的相对提升（即新版本 CTR 达到 5.5%），每组大约需要 30 万次曝光。这就是为什么搜索引擎的 A/B 测试通常需要运行一到两周。

### A/B 测试的常见陷阱

```python
class ABTestValidator:
    def check_sample_ratio_mismatch(self, experiment_name: str) -> dict:
```

SRM（Sample Ratio Mismatch）指实验组和对照组的流量比例不符合预期，通常意味着分流逻辑有 bug。新奇效应指用户对新界面的好奇心导致初期 CTR 偏高，需要等待效应消退后再下结论。

## 综合评估报告

将所有指标整合成一份完整的评估报告：

```python
def generate_comprehensive_report(search_results: dict,
                                   online_metrics: OnlineMetrics) -> dict:
    report = {
        "offline_metrics": {},
        "online_metrics": {},
        "recommendations": []
    }

    # 离线指标
    all_ndcg, all_mrr, all_map = [], [], []
    for query, results in search_results.items():
        if query in JUDGMENTS:
            all_ndcg.append(ndcg_at_k(query, 5))
            all_mrr.append(reciprocal_rank(query))
            all_map.append(average_precision(query))

    n = len(all_ndcg)
    report["offline_metrics"] = {
        "ndcg_at_5": round(sum(all_ndcg) / n, 4) if n else 0,
        "mrr": round(sum(all_mrr) / n, 4) if n else 0,
        "map": round(sum(all_map) / n, 4) if n else 0,
        "sample_size": n
    }

    # 在线指标
    ctr_data = online_metrics.click_through_rate()
    bounce_data = online_metrics.bounce_rate()
    zero_data = online_metrics.zero_result_rate()

    report["online_metrics"] = {
        "click_through_rate": round(ctr_data["ctr"], 4),
        "bounce_rate": round(bounce_data["bounce_rate"], 4),
        "zero_result_rate": round(zero_data["zero_result_rate"], 4),
        "total_searches": ctr_data["searches"]
    }

    # 自动生成建议
    if report["offline_metrics"]["ndcg_at_5"] < 0.5:
        report["recommendations"].append("NDCG@5 偏低，建议优化排序算法")
    if report["online_metrics"]["zero_result_rate"] > 0.1:
        report["recommendations"].append("零结果率超过 10%，建议补充同义词和扩展索引")
    if report["online_metrics"]["bounce_rate"] > 0.5:
        report["recommendations"].append("跳出率过高，建议优化搜索结果展示和摘要")
    if zero_data["zero_queries"]:
        report["recommendations"].append(
            f"高频零结果查询：{', '.join(zero_data['zero_queries'][:5])}，建议优先处理")

    return report
```

## 常见误区

1. **只看单一指标**：CTR 高不代表搜索质量好，需要综合看 CTR、跳出率、停留时间。
2. **样本量不足就下结论**：A/B 测试每个变体至少需要数千次曝光才有统计意义。
3. **忽略查询频率分布**：应该优先优化高频查询，而非冷门查询。
4. **离线和在线指标脱节**：离线 NDCG 提升但在线 CTR 没变化，可能是评估集不具代表性。
5. **评估集不更新**：搜索结果变化后，旧的标注数据可能不再适用。
6. **忽视评估一致性**：不同标注者的标准不同会导致评估结果不可靠。
7. **过拟合评估集**：针对评估集做特殊优化，上线后效果反而变差。

## 工程建议

1. **建立评估数据集管理流程**：标注数据需要版本化管理。
2. **分层评估**：按查询类型分别计算指标，找到短板。
3. **自动化回归测试**：每次索引或排序变更后自动运行离线评估。
4. **设置指标告警**：当零结果率突增或 CTR 骤降时自动告警。
5. **长期追踪趋势**：建立指标仪表盘，追踪周度和月度趋势。
6. **评估数据集抽样**：从搜索日志中按频率分层抽样构建评估集。
7. **在线指标置信区间**：不只看指标的点估计，还要看置信区间。
8. **多维度切片分析**：按设备类型、地域、用户群体分别计算指标。

## 小结

搜索质量评估是搜索引擎优化的基础。离线指标（NDCG、MAP、MRR）用标注数据衡量排序质量，在线指标（CTR、跳出率）用真实行为衡量用户满意度。A/B 测试将优化效果量化为统计显著性。建立完整的评估体系，才能让搜索优化有据可依。

### 练习一

**思路**：ERR 基于级联浏览模型，用户在位置 r 点击的概率是 (2^relevance - 1) / 2^max_relevance，一旦点击就停止。

**答案**：

```python
def err_at_k(query: str, k: int, max_relevance: int = 2) -> float:
    results = SEARCH_RESULTS[query][:k]
    judgments = {j.doc_id: j.relevance for j in JUDGMENTS[query]}
    err = 0.0
    prob_not_stopped = 1.0
    for rank, doc_id in enumerate(results):
        relevance = judgments.get(doc_id, 0)
        click_prob = (2 ** relevance - 1) / (2 ** max_relevance)
        err += prob_not_stopped * click_prob / (rank + 1)
        prob_not_stopped *= (1 - click_prob)
    return err
```

**要点**：ERR 与 NDCG 的区别在于 ERR 假设用户一旦找到满意结果就停止，更符合真实浏览行为。

```python
QUERY_TYPES = {

def layered_evaluation():
    type_groups = defaultdict(list)
    for query in SEARCH_RESULTS:
        qtype = QUERY_TYPES.get(query, "informational")
        type_groups[qtype].append(query)

    report = {}
    for qtype, queries in type_groups.items():

        mrr_scores = [reciprocal_rank(q) for q in queries if q in JUDGMENTS]
        report[qtype] = {
            "query_count": len(queries),
            "ndcg_at_5": sum(ndcg_scores) / len(ndcg_scores) if ndcg_scores else 0,
            "mrr": sum(mrr_scores) / len(mrr_scores) if mrr_scores else 0,
        }
    return report
```

**要点**：分层评估能发现搜索引擎在不同类型查询上的短板。信息型查询需要更高 Recall，导航型查询需要更高 MRR。

```python
def generate_evaluation_report(search_results: dict):

    all_ndcg, all_mrr, all_map = [], [], []

    for query, results in search_results.items():
        if query not in JUDGMENTS: continue
        qm = {
            "ndcg@5": ndcg_at_k(query, 5),
            "precision@3": precision_at_k(query, 3),
            "mrr": reciprocal_rank(query),
            "ap": average_precision(query),
        }
        all_ndcg.append(qm["ndcg@5"])
        all_mrr.append(qm["mrr"])
        all_map.append(qm["ap"])

        if qm["ndcg@5"] < 0.5:
            report["recommendations"].append({"query": query, "issue": "NDCG@5 低于 0.5"})

        report["per_query"][query] = qm

    n = len(report["per_query"])
    report["summary"] = {
        "total_queries": n,
        "avg_ndcg@5": sum(all_ndcg) / n if n else 0,
        "mrr": sum(all_mrr) / n if n else 0,
        "map": sum(all_map) / n if n else 0,

    return report
```

**要点**：报告同时包含汇总指标和逐查询详情。自动标记 NDCG@5 低于阈值的查询，指导优化优先级。

### 练习四

**思路**：计算每个查询-文档对的标注者一致性，用 Cohen's Kappa 衡量。

**答案**：

```python
from collections import Counter

def calculate_kappa(annotations: list[dict]) -> dict:
    """计算两个标注者之间的 Cohen's Kappa"""
    by_query_doc = defaultdict(list)
    for ann in annotations:
        key = (ann["query"], ann["doc_id"])
        by_query_doc[key].append(ann["relevance"])

    agreements = 0
    total = 0
    label_counts = Counter()
    rater1_counts = Counter()
    rater2_counts = Counter()

    for key, labels in by_query_doc.items():
        if len(labels) < 2:
            continue
        total += 1
        r1, r2 = labels[0], labels[1]
        rater1_counts[r1] += 1
        rater2_counts[r2] += 1
        label_counts[(r1, r2)] += 1
        if r1 == r2:
            agreements += 1

    if total == 0:
        return {"kappa": None, "message": "数据不足"}

    observed_agreement = agreements / total

    expected_agreement = sum(
        (rater1_counts[label] / total) * (rater2_counts[label] / total)
        for label in set(list(rater1_counts.keys()) + list(rater2_counts.keys()))
    )

    kappa = (observed_agreement - expected_agreement) / (1 - expected_agreement) \
        if expected_agreement < 1 else 1.0

    low_agreement_queries = []
    for key, labels in by_query_doc.items():
        if len(labels) >= 2 and labels[0] != labels[1]:
            low_agreement_queries.append({"query": key[0], "doc_id": key[1],
                                           "labels": labels})

    return {
        "kappa": round(kappa, 4),
        "observed_agreement": round(observed_agreement, 4),
        "expected_agreement": round(expected_agreement, 4),
        "total_pairs": total,
        "low_agreement": low_agreement_queries,
        "quality": "good" if kappa >= 0.6 else "fair" if kappa >= 0.4 else "poor"
    }
```

**要点**：Cohen's Kappa > 0.6 表示标注质量可接受，0.4-0.6 表示一般，< 0.4 表示需要重新培训标注者或修改标注指南。
