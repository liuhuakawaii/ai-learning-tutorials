# 电商搜索：从商品上架到用户下单的搜索全链路

打开淘宝搜索"无线蓝牙耳机"，你会看到成千上万的商品按相关性排列，左侧有品牌、价格区间等筛选项。这背后是电商搜索引擎在工作：商品数据被建造成多维度索引，用户的每一次搜索、筛选、排序都在毫秒级完成。

## 商品索引设计

电商搜索的第一步是为商品建立结构化索引。不同字段需要不同的处理方式：

```python
from elasticsearch import Elasticsearch

es = Elasticsearch("http://localhost:9200")

product_mapping = {
    "settings": {
        "analysis": {
            "filter": {
                "product_synonyms": {
                    "type": "synonym",
                    "synonyms": ["手机,移动电话,智能机",
                                 "笔记本,笔记本电脑,laptop",
                                 "耳机,耳塞,earphone"]
                }
            },
            "analyzer": {
                "ik_with_synonyms": {
                    "tokenizer": "ik_max_word",
                    "filter": ["product_synonyms"]
                }
            }
        }
    },
    "mappings": {
        "properties": {
            "title": {"type": "text", "analyzer": "ik_with_synonyms",
                      "search_analyzer": "ik_smart"},
            "category": {"type": "keyword"},
            "brand": {"type": "keyword"},
            "price": {"type": "float"},
            "sales_count": {"type": "integer"},
            "rating": {"type": "float"},
            "attributes": {
                "type": "nested",
                "properties": {"name": {"type": "keyword"},
                               "value": {"type": "keyword"}}
            },
            "tags": {"type": "keyword"},
            "in_stock": {"type": "boolean"},
            "created_at": {"type": "date"}
        }
    }
}
```

### 关键设计决策

**索引时用 `ik_max_word`，搜索时用 `ik_smart`。** 这是召回率 vs 精确率的权衡。`ik_max_word` 会做最细粒度切分，"无线蓝牙耳机"切成"无线/蓝牙/耳机/无线蓝牙/蓝牙耳机"，用户搜"蓝牙"也能命中。`ik_smart` 只切出"无线蓝牙/耳机"，切分粗但精确。

**属性用 nested 类型。** 假设商品有两个属性：颜色=黑色，尺寸=XL。如果用普通 object 存储，ES 内部会把 name 和 value 分别展开为数组，查询"颜色=XL"也会匹配。nested 类型为每个数组元素创建独立的隐藏文档，保证 name 和 value 的一一对应。

## 实验：多字段搜索

用户搜索"苹果手机"时，需要同时匹配标题、品牌、类目等多个字段，但各字段权重不同：

```python
def search_products(query, filters=None, page=1, size=20):
    should_clauses = [
        {"match": {"title": {"query": query, "boost": 2.0}}},
        {"match": {"brand": {"query": query, "boost": 1.5}}},
        {"term": {"category": {"value": query, "boost": 1.0}}}
    ]
    filter_clauses = []
    if filters:
        if "price_min" in filters or "price_max" in filters:
            price_range = {}
            if "price_min" in filters:
                price_range["gte"] = filters["price_min"]
            if "price_max" in filters:
                price_range["lte"] = filters["price_max"]
            filter_clauses.append({"range": {"price": price_range}})
        if "brand" in filters:
            filter_clauses.append({"term": {"brand": filters["brand"]}})

    body = {
        "query": {"bool": {"should": should_clauses, "filter": filter_clauses,
                            "minimum_should_match": 1}},
        "from": (page - 1) * size, "size": size
    }
    return es.search(index="products", body=body)
```

`minimum_should_match: 1` 保证至少匹配一个 should 子句。价格过滤放在 `filter` 上下文不参与评分，性能更好。

### boost 值如何确定

不要拍脑袋定 boost。收集 100-500 个查询的标注数据，用不同 boost 组合跑评估集，计算 NDCG@10，选择最优组合。

## 分面搜索

分面搜索让用户通过点选快速缩小结果范围，是电商搜索的标配：

```python
def search_with_facets(query, selected_brand=None):
    body = {
        "query": {"match": {"title": query}},
        "aggs": {
            "brands": {"terms": {"field": "brand", "size": 20}},
            "price_ranges": {"range": {"field": "price", "ranges": [
                {"to": 100, "key": "100元以下"},
                {"from": 100, "to": 500, "key": "100-500元"},
                {"from": 500, "to": 1000, "key": "500-1000元"},
                {"from": 1000, "key": "1000元以上"}
            ]}},
            "categories": {"terms": {"field": "category", "size": 10}}
        },
        "size": 20
    }
    if selected_brand:
        body["post_filter"] = {"term": {"brand": selected_brand}}
    return es.search(index="products", body=body)
```

`post_filter` 在聚合计算完成后才过滤搜索结果，保证分面计数的准确性。这是电商搜索中最容易被忽略的细节——如果把品牌过滤放在 `query` 里，其他分面值的计数会变成"在当前品牌下的计数"，而不是"如果取消选择后的计数"。

## 实验：综合排序

电商搜索默认按相关性排序，但综合排序需要融合销量、评分、时间新鲜度：

```python
def comprehensive_sort(query, page=1, size=20):
    body = {
        "query": {
            "function_score": {
                "query": {"match": {"title": query}},
                "functions": [
                    {"field_value_factor": {"field": "sales_count",
                                            "modifier": "log1p", "factor": 0.3}},
                    {"field_value_factor": {"field": "rating",
                                            "modifier": "none", "factor": 0.3}},
                    {"gauss": {"created_at": {"origin": "now", "scale": "30d",
                                              "decay": 0.5}}}
                ],
                "score_mode": "sum", "boost_mode": "multiply"
            }
        },
        "from": (page - 1) * size, "size": size
    }
    return es.search(index="products", body=body)
```

### 为什么销量取对数

假设销量 1000 的商品得 1000 分，销量 100 的得 100 分，差距 900 分。用 log1p 后，前者得 6.9 分，后者得 4.6 分，差距缩小到 2.3 分。这样做的好处是避免爆款商品完全压倒新品和小众商品。

### 高斯衰减

`scale: "30d"` 意味着 30 天前的商品得分为原点的 50%，60 天前约为 25%。`offset: "7d"` 表示 7 天内的商品不衰减，适合新品保护。

## 搜索联想

搜索框需要实时给出联想词：

```python
def get_search_suggestions(prefix, size=10):
    result = es.search(index="products", body={
        "suggest": {"title_suggest": {
            "prefix": prefix,
            "completion": {"field": "title.suggest", "size": size,
                           "skip_duplicates": True,
                           "fuzzy": {"fuzziness": "AUTO"}}
        }}
    })
    return [{"text": opt["text"], "score": opt["_score"]}
            for opt in result["suggest"]["title_suggest"][0]["options"]]
```

联想词使用 ES 的 Completion Suggester，基于前缀匹配并支持模糊纠错。

## 语义搜索

传统关键词搜索无法处理"适合跑步的耳机"——只能匹配标题中包含"跑步"和"耳机"的商品，无法理解"运动耳挂式"也是相关结果。

```python
from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")

def hybrid_product_search(query, top_k=10):
    query_vector = model.encode(query).tolist()
    body = {
        "query": {"bool": {"should": [
            {"match": {"title": {"query": query, "boost": 1.0}}},
            {"match": {"brand": {"query": query, "boost": 0.5}}}
        ]}},
        "knn": {"field": "title_vector", "query_vector": query_vector,
                "k": top_k, "num_candidates": 100},
        "size": top_k
    }
    return es.search(index="products", body=body)
```

ES 8.x 原生支持混合查询。精确商品名搜索（如"iPhone 15 Pro Max 256GB"）关键词匹配更准确；模糊需求描述（如"送女朋友的礼物"）语义检索更有效。

## 常见误区

**只用 match 查询做电商搜索。** 单一 match 查询无法区分标题匹配和品牌匹配的重要性。

**分面数量不做限制。** 如果品牌字段有上万个值，terms 聚合会返回全部，必须设置 `size`。

**排序只看销量。** 纯销量排序会让新品永远排在后面，需要用时间衰减因子平衡。

**同义词配置过度。** 同义词扩展太激进会召回大量不相关商品，应按类目精细化管理。

## 工程建议

- 缓存热门查询：对高频搜索词的结果做缓存，设置 5 分钟 TTL
- 异步更新计数器：销量等频繁变化的字段用异步批量更新
- 监控慢查询：记录搜索耗时超过 200ms 的查询
- 搜索降级策略：当 ES 不可用时，降级到数据库模糊查询或返回热门商品

实现一个函数，输入一个商品 ID，返回同品类、价格区间相近的 5 个相关商品。

```python
def get_related_products(product_id, size=5):
    product = es.get(index="products", id=product_id)["_source"]
    body = {
        "query": {"bool": {
            "must": [{"term": {"category": product["category"]}}],
            "must_not": [{"term": {"_id": product_id}}],
            "should": [
                {"term": {"brand": product["brand"]}},
                {"range": {"price": {"gte": product["price"] * 0.7,
                                     "lte": product["price"] * 1.3}}}
            ]
        }},
        "size": size
    }
    return es.search(index="products", body=body)
```
