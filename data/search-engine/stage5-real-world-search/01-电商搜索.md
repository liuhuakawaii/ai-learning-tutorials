# 电商搜索：从商品上架到用户下单的搜索全链路

## 场景引入

打开淘宝搜索"无线蓝牙耳机"，你会看到成千上万的商品按相关性排列。左侧有品牌、价格区间等筛选项，顶部可以按销量、价格排序。这背后是电商搜索引擎在工作：商品数据被建造成多维度索引，用户的每一次搜索、筛选、排序都在毫秒级完成。

电商搜索的核心挑战在于：如何在海量商品中快速找到用户真正想买的那一个？本节课将带你用 Python + Elasticsearch 构建一个完整的电商搜索服务。

## 学习目标

1. 设计电商商品的多字段索引结构
2. 实现基于相关性、销量、价格的多维排序
3. 构建分面搜索（faceted search）功能
4. 理解电商搜索的推荐与联想机制
5. 掌握电商搜索的工程化实践与性能优化

## 电商搜索的发展历程

电商搜索经历了三个阶段的演进。早期电商（2000 年代）使用简单的数据库 LIKE 查询，搜索"手机壳"只能匹配标题中完整包含这三个字的商品，无法理解"iPhone 15 保护套"也是同类需求。第二阶段（2010 年代）引入全文搜索引擎（如 Elasticsearch），支持分词、相关性评分和聚合，但排序仍以文本匹配为主。第三阶段（2020 年至今）融合了深度学习和用户行为数据，搜索结果不仅考虑文本相关性，还综合用户画像、点击行为、购买转化等因素。

理解这个演进过程很重要：本节课覆盖第二和第三阶段的核心技术，你需要知道每种技术的适用场景和局限性。

## 商品索引设计

电商搜索的第一步是为商品建立结构化索引。一个商品包含多种类型的字段，每种字段的处理方式不同：

```python
from elasticsearch import Elasticsearch

es = Elasticsearch("http://localhost:9200")

product_mapping = {
    "mappings": {
        "properties": {
            "title": {
                "type": "text",
                "analyzer": "ik_max_word",
                "search_analyzer": "ik_smart"
            },
            "category": {"type": "keyword"},
            "brand": {"type": "keyword"},
            "price": {"type": "float"},
            "sales_count": {"type": "integer"},
            "rating": {"type": "float"},
            "attributes": {
                "type": "nested",
                "properties": {
                    "name": {"type": "keyword"},
                    "value": {"type": "keyword"}
                }
            },
            "tags": {"type": "keyword"},
            "in_stock": {"type": "boolean"},
            "created_at": {"type": "date"}
        }
    }
}

es.indices.create(index="products", body=product_mapping)
```

字段设计的关键考量：标题使用 `ik_max_word` 做最细粒度分词以提高召回率，搜索时切换为 `ik_smart` 减少误匹配。类目和品牌用 `keyword` 类型精确匹配。属性用 `nested` 类型避免数组对象的字段交叉问题。

### analyzer 选择的 tradeoff

索引时用 `ik_max_word` 还是 `ik_smart`，是一个经典的召回率 vs 精确率的权衡。`ik_max_word` 会做最细粒度切分，"无线蓝牙耳机"会被切成"无线/蓝牙/耳机/无线蓝牙/蓝牙耳机"，这样用户搜"蓝牙"也能命中。`ik_smart` 只切出"无线蓝牙/耳机"，切分粒度粗，索引体积小但可能漏召回。

最佳实践是索引时用 `ik_max_word`（提高召回），搜索时用 `ik_smart`（提高精确率）。这个配置通过 mapping 中的 `analyzer` 和 `search_analyzer` 分别指定。

### 为什么属性用 nested 类型

假设一个商品有两个属性：颜色=黑色，尺寸=XL。如果用普通 object 存储：

```python
# 普通 object 存储（错误方式）
"attributes": [
    {"name": "颜色", "value": "黑色"},
    {"name": "尺寸", "value": "XL"}
]
# ES 内部展开为：
# attributes.name: ["颜色", "尺寸"]
# attributes.value: ["黑色", "XL"]
# 查询"颜色=XL"也会匹配！因为"XL"和"颜色"在同一个文档中
```

nested 类型为每个数组元素创建独立的隐藏文档，保证 name 和 value 的一一对应关系。代价是索引体积增大和查询复杂度增加，对于属性数量有限的商品来说这个代价是值得的。

### 多语言与同义词处理

跨境电商搜索还需要处理多语言和同义词问题：

```python
# 创建带同义词过滤器的自定义分析器
```

## 多字段搜索实现

用户搜索"苹果手机"时，需要同时匹配标题、品牌、类目等多个字段，但各字段的权重不同：

```python
def search_products(query: str, filters: dict = None, page: int = 1, size: int = 20):
    should_clauses = [
        {"match": {"title": {"query": query, "boost": 2.0}}},
        {"match": {"brand": {"query": query, "boost": 1.5}}},
        {"term": {"category": {"value": query, "boost": 1.0}}}
    ]

    filter_clauses = []
    if filters:
        if "price_min" in filters or "price_max" in filters:
            price_range = {}
            if "price_min" in filters:
                price_range["gte"] = filters["price_min"]
            if "price_max" in filters:
                price_range["lte"] = filters["price_max"]
            filter_clauses.append({"range": {"price": price_range}})
        if "brand" in filters:
            filter_clauses.append({"term": {"brand": filters["brand"]}})

    body = {
        "query": {
            "bool": {
                "should": should_clauses,
                "filter": filter_clauses,
                "minimum_should_match": 1
            }
        },
        "from": (page - 1) * size,
        "size": size
    }

    return es.search(index="products", body=body)
```

`minimum_should_match: 1` 保证至少匹配一个 should 子句。标题权重最高（2.0），因为用户搜索意图最直接体现在标题匹配上。价格过滤放在 `filter` 上下文不参与评分，性能更好。

### boost 值如何确定

boost 值不是拍脑袋定的，需要通过 A/B 测试和离线评估来调优。常见的调优方法：

1. **收集标注数据**：随机抽取 100-500 个查询，人工标注每个查询下各商品的相关性等级（0-3）。
2. **批量评估**：用不同的 boost 组合跑评估集，计算 NDCG@10。
3. **网格搜索**：标题 boost 在 1.5-4.0 之间、品牌在 1.0-2.5 之间、类目在 0.5-1.5 之间做组合测试。
4. **选择最优组合**：NDCG@10 最高的组合即为最优 boost 配置。

不要凭直觉设置 boost，也不要设置过大的 boost（如 10.0），这会让其他字段的匹配完全失效。

### 跨字段查询 vs 最佳字段查询

ES 的 `multi_match` 提供多种查询类型，适用于不同场景：

```python
# cross_fields: 将所有字段视为一个大字段，适合"品牌+商品名"分散在不同字段的情况
cross_fields_body = {
    "query": {
        "multi_match": {
            "query": "华为 Mate 60",
            "type": "cross_fields",
            "fields": ["title", "brand", "category"],
            "minimum_should_match": "75%"
        }
    }
}

# most_fields: 取所有字段中得分最高的，适合多维度匹配
most_fields_body = {
    "query": {
        "multi_match": {
            "query": "轻薄笔记本",
            "type": "most_fields",
            "fields": ["title^3", "description^1.5", "tags^2"],
            "tie_breaker": 0.3
        }
    }
}

# best_fields（默认）: 取得分最高的单个字段，适合精确匹配场景
best_fields_body = {
    "query": {
        "multi_match": {
            "query": "iPhone 15 Pro Max",
            "type": "best_fields",
            "fields": ["title^2", "brand"],
            "minimum_should_match": "50%"
        }
    }
}
```

电商搜索中 `cross_fields` 和 `most_fields` 用得最多。`cross_fields` 适合品牌名可能出现在标题或品牌字段中的情况；`most_fields` 适合需要综合多个字段信号的场景。

## 分面搜索（Facets）

分面搜索让用户通过点选快速缩小结果范围，是电商搜索的标配功能：

```python
def search_with_facets(query: str, page: int = 1, size: int = 20):
    body = {
        "query": {"match": {"title": query}},
        "aggs": {
            "brands": {"terms": {"field": "brand", "size": 20}},
            "price_ranges": {
                "range": {
                    "field": "price",
                    "ranges": [
                        {"to": 100, "key": "100元以下"},
                        {"from": 100, "to": 500, "key": "100-500元"},
                        {"from": 500, "to": 1000, "key": "500-1000元"},
                        {"from": 1000, "key": "1000元以上"}
                    ]
                }
            },
            "categories": {"terms": {"field": "category", "size": 10}}
        },
        "from": (page - 1) * size,
        "size": size
    }

    result = es.search(index="products", body=body)
    return {
        "hits": result["hits"],
        "facets": {
            "brands": [
                {"name": b["key"], "count": b["doc_count"]}
                for b in result["aggregations"]["brands"]["buckets"]
            ],
            "price_ranges": [
                {"range": b["key"], "count": b["doc_count"]}
                for b in result["aggregations"]["price_ranges"]["buckets"]
                if b["doc_count"] > 0
            ]
        }
    }
```

分面聚合和搜索在同一个请求中完成，ES 会在搜索结果的基础上计算各维度的文档数量。用户点击某个分面值后，将其作为过滤条件传入下一次搜索。

### 分面搜索的性能优化

分面聚合是 CPU 密集型操作，当商品量达到千万级时需要特别注意性能：

```python
# 优化1：对分面结果做缓存
from functools import lru_cache
import hashlib
import json

@lru_cache(maxsize=1000)
def get_cached_facets(query_hash: str, query: str):
    return search_with_facets(query)

def search_with_facets_cached(query: str, page: int = 1, size: int = 20):
    query_hash = hashlib.md5(query.encode()).hexdigest()
    return get_cached_facets(query_hash, query)

# 优化2：使用 composite 分页处理高基数字段
def get_all_brands_composite():
    brands = []
    body = {
        "size": 0,
        "aggs": {
            "brands_paginated": {
                "composite": {
                    "size": 1000,
                    "sources": [
                        {"brand": {"terms": {"field": "brand", "order": "asc"}}}
                    ]
                }
            }
        }
    }
    result = es.search(index="products", body=body)
    after_key = result["aggregations"]["brands_paginated"].get("after_key")
    brands.extend(result["aggregations"]["brands_paginated"]["buckets"])

    while after_key:
        body["aggs"]["brands_paginated"]["composite"]["after"] = after_key
        result = es.search(index="products", body=body)
        buckets = result["aggregations"]["brands_paginated"]["buckets"]
        if not buckets:
            break
        brands.extend(buckets)
        after_key = result["aggregations"]["brands_paginated"].get("after_key")

    return brands
```

分面缓存的关键是缓存粒度：同一查询的分面结果在短时间内变化不大，可以缓存 5-10 分钟。对于品牌这种高基数字段，`composite` 聚合支持分页遍历，避免单次返回过多桶。

### 分面计数的准确性问题

当用户选中某个分面值后，其他分面值的计数应该是"如果取消当前选择后的计数"，而不是"在当前选择下的计数"。这需要使用 `post_filter`：

```python
def search_with_post_filter(query: str, selected_brand: str = None):
    body = {
        "query": {"match": {"title": query}},
        "aggs": {
            "brands": {"terms": {"field": "brand", "size": 20}},
            "price_ranges": {
                "range": {
                    "field": "price",
                    "ranges": [
                        {"to": 100, "key": "100元以下"},
                        {"from": 100, "to": 500, "key": "100-500元"},
                        {"from": 500, "key": "500元以上"}
                    ]
                }
            }
        },
        "size": 20
    }

    if selected_brand:
        body["post_filter"] = {"term": {"brand": selected_brand}}

    result = es.search(index="products", body=body)
    return result
```

`post_filter` 在聚合计算完成后才过滤搜索结果，保证分面计数的准确性。这是电商搜索中最容易被忽略的细节之一。

## 多维排序策略

电商搜索默认按相关性排序，但用户经常切换到按销量或价格排序。综合排序用 `function_score` 将相关性得分与销量、评分、时间新鲜度融合：

```python
def comprehensive_sort(query: str, page: int = 1, size: int = 20):
    body = {
        "query": {
            "function_score": {
                "query": {"match": {"title": query}},
                "functions": [
                    {"field_value_factor": {
                        "field": "sales_count",
                        "modifier": "log1p",
                        "factor": 0.3
                    }},
                    {"field_value_factor": {
                        "field": "rating",
                        "modifier": "none",
                        "factor": 0.3
                    }},
                    {"gauss": {
                        "created_at": {
                            "origin": "now",
                            "scale": "30d",
                            "decay": 0.5
                        }
                    }}
                ],
                "score_mode": "sum",
                "boost_mode": "multiply"
            }
        },
        "from": (page - 1) * size,
        "size": size
    }
    return es.search(index="products", body=body)
```

销量取对数避免爆款商品垄断排名，高斯衰减让商品越新得分越高。

### 理解 function_score 的评分机制

`function_score` 的计算流程值得深入理解：

1. **基础查询得分**：`match` 查询计算文本相关性得分（BM25 分数）。
2. **函数得分**：每个 function 独立计算一个分数。
3. **score_mode**：决定多个函数分数如何合并。`sum` 是求和，`avg` 是求平均，`max` 取最大值，`multiply` 是相乘。
4. **boost_mode**：决定函数分数和基础查询分数如何合并。`multiply` 是相乘，`replace` 是替换。

上面的代码中 `score_mode=sum` 意味着三个函数的分数相加，`boost_mode=multiply` 意味着函数总分和基础查询分数相乘。最终分数 = BM25_score × (sales_score + rating_score + freshness_score)。

### 销量的 log1p 修饰符

`modifier: "log1p"` 等价于 `log(1 + x)`。为什么不用原始销量？假设销量 1000 的商品得 1000 分，销量 100 的得 100 分，差距是 900 分。用 log1p 后，前者得 6.9 分，后者得 4.6 分，差距缩小到 2.3 分。这样做的好处是：

- 避免爆款商品完全压倒新品和小众商品
- 保留销量的排序信号（销量高的仍然得分高）
- 1000 销量和 10000 销量的差距不再那么夸张

可选的 modifier 还有 `log`、`sqrt`、`square` 等，选择哪个取决于你希望销量对排序的影响有多大。

### 高斯衰减函数

`gauss` 衰减函数让越新的商品得分越高，但不会完全忽略老商品：

```python
# 高斯衰减参数解释
{
    "gauss": {
        "created_at": {
            "origin": "now",    # 原点：当前时间
            "scale": "30d",     # 衰减到 0.5 的时间跨度
            "decay": 0.5,       # scale 处的得分衰减到 0.5
            "offset": "7d"      # 7 天内不衰减（满分）
        }
    }
}
```

`scale: "30d"` 意味着 30 天前的商品得分为原点的 50%，60 天前约为 25%。`offset: "7d"` 表示 7 天内的商品不衰减，适合新品保护场景。衰减函数的形状是高斯曲线，比线性衰减更平滑，不会出现突然跌落。

## 搜索推荐与联想

搜索框需要实时给出联想词，帮助用户快速完成输入：

```python
def get_search_suggestions(prefix: str, size: int = 10):
    body = {
        "suggest": {
            "title_suggest": {
                "prefix": prefix,
                "completion": {
                    "field": "title.suggest",
                    "size": size,
                    "skip_duplicates": True,
                    "fuzzy": {"fuzziness": "AUTO"}
                }
            }
        }
    }
    result = es.search(index="products", body=body)
    return [
        {"text": opt["text"], "score": opt["_score"]}
        for opt in result["suggest"]["title_suggest"][0]["options"]
    ]
```

联想词使用 ES 的 Completion Suggester，基于前缀匹配并支持模糊纠错。

### 联想词的业务策略

纯文本匹配的联想词不够好，需要融合业务信号：

```python
def get_business_suggestions(prefix: str, size: int = 10):
    # 获取基础联想
    basic = get_search_suggestions(prefix, size=size * 2)

    # 补充搜索热度数据
    body = {
        "query": {
            "bool": {
                "must": [
                    {"prefix": {"query_text.keyword": prefix}}
                ]
            }
        },
        "sort": [
            {"search_count": {"order": "desc"}},
            {"conversion_rate": {"order": "desc"}}
        ],
        "size": size
    }
    result = es.search(index="search_queries", body=body)

    suggestions = []
    for hit in result["hits"]["hits"]:
        src = hit["_source"]
        suggestions.append({
            "text": src["query_text"],
            "search_count": src.get("search_count", 0),
            "conversion_rate": src.get("conversion_rate", 0)
        })

    return suggestions
```

好的联想词应该综合考虑：文本前缀匹配、搜索频率（热门词优先）、转化率（搜了就能买到的词优先）。有些电商平台还会在联想词中直接展示商品图片和价格，这需要联想接口返回商品数据而非仅仅是文字。

### 去重与多样性

联想词列表需要去重和保证多样性。"苹果手机"、"苹果手机壳"、"苹果手机膜"三个建议太相似，应该只保留一个，留出位置给其他品类的建议：

```python
def diverse_suggestions(prefix: str, size: int = 8):
    raw = get_search_suggestions(prefix, size=size * 3)

    diverse = []
    seen_categories = set()
    seen_prefixes = set()

    for item in raw:
        text = item["text"]
        # 去除完全重复
        if text in seen_prefixes:
            continue
        # 限制同一前缀的建议数量
        short = text[:4]
        if seen_prefixes and short in seen_categories and len(diverse) > 2:
            continue
        diverse.append(item)
        seen_prefixes.add(text)
        seen_categories.add(short)
        if len(diverse) >= size:
            break

    return diverse
```

## 电商搜索的语义理解

传统关键词搜索无法处理语义层面的查询。用户搜"适合跑步的耳机"，传统搜索只能匹配标题中包含"跑步"和"耳机"的商品，无法理解"运动耳挂式"、"防汗防水"等也是相关结果。

```python
from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")

def semantic_product_search(query: str, top_k: int = 10):
    query_vector = model.encode(query).tolist()

    body = {
        "knn": {
            "field": "title_vector",
            "query_vector": query_vector,
            "k": top_k,
            "num_candidates": 100
        },
        "size": top_k
    }
    return es.search(index="products", body=body)

def hybrid_product_search(query: str, top_k: int = 10):
    query_vector = model.encode(query).tolist()

    body = {
        "query": {
            "bool": {
                "should": [
                    {"match": {"title": {"query": query, "boost": 1.0}}},
                    {"match": {"brand": {"query": query, "boost": 0.5}}}
                ]
            }
        },
        "knn": {
            "field": "title_vector",
            "query_vector": query_vector,
            "k": top_k,
            "num_candidates": 100
        },
        "size": top_k
    }
    return es.search(index="products", body=body)
```

混合搜索同时使用 BM25 关键词匹配和向量语义检索，ES 8.x 原生支持这种混合查询。对于精确的商品名搜索（如"iPhone 15 Pro Max 256GB"），关键词匹配更准确；对于模糊的需求描述（如"送女朋友的礼物"），语义检索更有效。

## 常见误区

1. **只用 match 查询做电商搜索**：单一 match 查询无法区分标题匹配和品牌匹配的重要性，应使用多字段加权搜索。
2. **分面数量不做限制**：如果品牌字段有上万个值，terms 聚合会返回全部，必须设置 `size` 参数。
3. **排序只看销量**：纯销量排序会让新品永远排在后面，需要用时间衰减因子平衡。
4. **忽略 nested 类型**：商品属性如果用普通 object 存储，会出现字段交叉匹配的错误。
5. **搜索和分面用两次请求**：分面聚合应该和搜索放在同一个请求中。
6. **同义词配置过度**：同义词扩展太激进会导致召回大量不相关商品，需要按类目精细化管理。
7. **忽略搜索结果的多样性**：搜索结果第一页全是同一品牌或同一价位会影响用户体验。

## 工程建议

1. **索引分片策略**：商品索引按品类或时间分片，单个分片控制在 10-50GB。
2. **缓存热门查询**：对高频搜索词的结果做缓存，设置 5 分钟 TTL。
3. **异步更新计数器**：销量等频繁变化的字段用异步批量更新减少索引刷新频率。
4. **搜索结果去重**：同一商品的多个 SKU 搜索时需要按商品 ID 聚合去重。
5. **监控慢查询**：记录搜索耗时超过 200ms 的查询，定期分析优化。
6. **索引别名管理**：使用别名实现零停机索引切换，便于 mapping 变更和数据迁移。
7. **搜索降级策略**：当 ES 不可用时，降级到数据库模糊查询或返回热门商品。
8. **分层缓存**：热点查询结果用 Redis 缓存，分面结果用本地缓存。

## 小结

电商搜索的核心是多字段索引设计和多维度排序。标题、品牌、类目等字段需要不同的分词策略和权重配置。分面搜索让用户快速缩小范围，综合排序平衡相关性、销量和新鲜度。搜索推荐通过前缀匹配和商品关联提升转化率。语义搜索为模糊需求提供了新的解决思路。

**思路**：使用 ES 的 `collapse` 功能按商品 ID 字段去重。

**答案**：

```python
def search_with_dedup(query: str, page: int = 1, size: int = 20):
    body = {
        "query": {"match": {"title": query}},
        "collapse": {
            "field": "product_id",
            "inner_hits": {
                "name": "sku_variants",
                "size": 3,
                "sort": [{"sales_count": "desc"}]
            }
        },
        "from": (page - 1) * size,
        "size": size
    }
    result = es.search(index="products", body=body)

    for hit in result["hits"]["hits"]:
        variants = hit.get("inner_hits", {}).get("sku_variants", {}).get("hits", {}).get("hits", [])
        hit["_source"]["other_skus"] = [v["_source"] for v in variants]

    return result
```

**要点**：`collapse` 按 `product_id` 去重，每个商品只保留得分最高的 SKU。`inner_hits` 返回被折叠的其他 SKU，前端可以展示"还有 N 种颜色可选"。

### 练习五

**思路**：MMR 算法在每一步选择与查询最相关、同时与已选结果最不相似的文档。

**答案**：

```python
import numpy as np
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")

def mmr_search(query: str, lambda_param: float = 0.5, top_k: int = 10):
    candidates = search_products(query, size=50)["hits"]["hits"]

    query_vec = model.encode(query)
    doc_vecs = [model.encode(h["_source"]["title"]) for h in candidates]
    doc_scores = [h["_score"] for h in candidates]

    selected = []
    remaining = list(range(len(candidates)))

    for _ in range(top_k):
        if not remaining:
            break

        best_idx = None
        best_mmr = -float("inf")

        for idx in remaining:
            relevance = doc_scores[idx]

            if selected:
                sim_to_selected = max(
                    np.dot(doc_vecs[idx], doc_vecs[s]) /
                    (np.linalg.norm(doc_vecs[idx]) * np.linalg.norm(doc_vecs[s]))
                    for s in selected
                )
            else:
                sim_to_selected = 0

            mmr_score = lambda_param * relevance - (1 - lambda_param) * sim_to_selected

            if mmr_score > best_mmr:
                best_mmr = mmr_score
                best_idx = idx

        selected.append(best_idx)
        remaining.remove(best_idx)

    return [candidates[i] for i in selected]
```

**要点**：`lambda_param` 控制相关性与多样性的平衡。`lambda=1.0` 退化为纯相关性排序，`lambda=0.0` 退化为纯多样性选择。实际使用中 0.3-0.7 是常见范围。
