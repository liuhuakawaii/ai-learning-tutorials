# AI 搜索增强：让搜索引擎更懂用户意图

## 场景引入

用户在知识库中搜索"如何处理高并发"，传统搜索引擎返回一堆包含关键词的文档列表。而 AI 增强搜索能直接回答："高并发处理通常采用限流、缓存、异步队列三种策略……"，并附上相关文档链接。

这就是 RAG（Retrieval-Augmented Generation）的核心价值：先用搜索引擎找到相关文档，再用大语言模型生成精准回答。本节课将带你用 Python + OpenAI API 实现 RAG 搜索、查询扩展、重排序和摘要生成。

## 学习目标

1. 理解 RAG 的工作原理和架构设计
2. 实现基于 LLM 的查询扩展和重排序
3. 构建搜索结果摘要生成功能
4. 掌握 AI 增强搜索的工程化实践
5. 理解 RAG 系统的评估与优化方法

## RAG 的发展历程与动机

RAG 的出现源于 LLM 的两个核心缺陷：**知识截止**和**幻觉**。GPT-4 的训练数据截止到某个时间点，无法回答最新信息；即使在训练数据范围内，LLM 也可能"编造"看似合理但错误的答案。

2020 年 Facebook AI（现 Meta AI）在论文《Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks》中首次提出 RAG 概念。核心思想很简单：不要让 LLM 凭记忆回答，而是先从知识库中检索相关文档，把文档内容作为上下文喂给 LLM，让 LLM 基于真实文档生成回答。

这个思路的威力在于：知识库可以随时更新（不需要重新训练 LLM），回答有据可查（可以追溯到具体文档），幻觉率大幅降低（有原文约束）。

## RAG 基础架构

RAG 的核心流程是"检索-增强-生成"三步：

```python
from openai import OpenAI
from elasticsearch import Elasticsearch

client = OpenAI(api_key="your-api-key")
es = Elasticsearch("http://localhost:9200")

def rag_search(query: str, index: str = "knowledge_base", top_k: int = 5):
    # 第一步：检索
    search_body = {
        "query": {"multi_match": {"query": query, "fields": ["title^2", "content"]}},
        "size": top_k
    }
    search_result = es.search(index=index, body=search_body)

    # 第二步：构建上下文
    contexts = []
    sources = []
    for hit in search_result["hits"]["hits"]:
        contexts.append(hit["_source"]["content"])
        sources.append({"title": hit["_source"]["title"], "score": hit["_score"]})

    context_text = "\n\n---\n\n".join(contexts)

    # 第三步：生成回答
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "你是一个知识库助手。根据参考资料回答用户问题。回答时引用来源编号 [1] [2]。"},
            {"role": "user", "content": f"参考资料：\n{context_text}\n\n用户问题：{query}"}
        ],
        temperature=0.3, max_tokens=1000
    )

    return {
        "answer": response.choices[0].message.content,
        "sources": sources,
        "usage": {"prompt_tokens": response.usage.prompt_tokens,
                  "completion_tokens": response.usage.completion_tokens}
    }
```

RAG 的关键在于上下文构建：将检索到的文档拼接成 prompt，指导 LLM 生成基于事实的回答。`temperature=0.3` 让回答更稳定。引用来源编号让用户可以追溯原始文档。

### 上下文窗口的限制与处理

LLM 的上下文窗口是有限的（如 GPT-4o-mini 为 128K tokens），检索到的文档可能超出限制。需要做截断和优先级排序：

```python
import tiktoken

def count_tokens(text: str, model: str = "gpt-4o-mini") -> int:
    encoding = tiktoken.encoding_for_model(model)
    return len(encoding.encode(text))

def build_context_with_limit(documents: list[dict], max_tokens: int = 8000,
                              reserve_for_answer: int = 1000) -> str:
    available_tokens = max_tokens - reserve_for_answer
    context_parts = []
    total_tokens = 0

    for i, doc in enumerate(documents):
        content = doc.get("content", "")
        title = doc.get("title", f"文档{i+1}")
        block = f"[{title}]\n{content}"
        block_tokens = count_tokens(block)

        if total_tokens + block_tokens > available_tokens:
            remaining = available_tokens - total_tokens
            if remaining > 100:
                encoding = tiktoken.encoding_for_model("gpt-4o-mini")
                truncated = encoding.decode(encoding.encode(block)[:remaining])
                context_parts.append(truncated)
            break

        context_parts.append(block)
        total_tokens += block_tokens

    return "\n\n---\n\n".join(context_parts)
```

这个函数按优先级（排序靠前的文档优先）拼接上下文，超过 token 限制时截断最后一个文档。`reserve_for_answer` 预留了回答所需的 token 空间。

### RAG 的 prompt 工程

prompt 的质量直接影响 RAG 回答的质量：

```python
def build_rag_prompt(query: str, context: str, style: str = "default") -> list[dict]:
    prompts = {
        "default": {
            "system": (
                "你是一个知识库助手。根据参考资料回答用户问题。\n"
                "规则：\n"
                "1. 只根据参考资料回答，不要编造信息\n"
                "2. 回答时引用来源编号 [1] [2]\n"
                "3. 如果参考资料中没有相关信息，明确说明"我不知道"\n"
                "4. 回答要简洁准确，避免冗余"
            ),
            "user": f"参考资料：\n{context}\n\n用户问题：{query}"
        },
        "technical": {
            "system": (
                "你是一个技术文档助手。根据参考资料回答技术问题。\n"
                "规则：\n"
                "1. 回答要包含具体的代码示例或配置\n"
                "2. 说明适用场景和限制条件\n"
                "3. 引用来源编号\n"
                "4. 如有多种方案，说明各自的 tradeoff"
            ),
            "user": f"技术文档：\n{context}\n\n技术问题：{query}"
        },
        "concise": {
            "system": (
                "根据参考资料简要回答问题。只回答核心要点，不超过3句话。"
                "如果没有相关信息，回答"无相关信息"。"
            ),
            "user": f"参考资料：\n{context}\n\n问题：{query}"
        }
    }

    chosen = prompts.get(style, prompts["default"])
    return [
        {"role": "system", "content": chosen["system"]},
        {"role": "user", "content": chosen["user"]}
    ]
```

不同场景需要不同的 prompt 策略：技术文档需要详细和代码示例，FAQ 需要简洁直接，客服场景需要友好语气。prompt 工程是 RAG 系统中最容易被低估的环节。

## 查询扩展（Query Expansion）

用户输入往往简短模糊，查询扩展用 LLM 生成相关查询词，提高召回率：

```python
def expand_query(original_query: str) -> list[str]:
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "根据用户查询生成3-5个相关搜索词，每行一个，不要编号或解释。"},
            {"role": "user", "content": f"原始查询：{original_query}"}
        ],
        temperature=0.5, max_tokens=200
    )
    expanded = [q.strip() for q in response.choices[0].message.content.strip().split("\n") if q.strip()]
    return [original_query] + expanded

def search_with_expansion(query: str, index: str = "knowledge_base"):
    expanded_queries = expand_query(query)
    should_clauses = [
        {"match": {"content": {"query": q, "boost": 1.0 / (i + 1)}}}
        for i, q in enumerate(expanded_queries)
    ]
    body = {"query": {"bool": {"should": should_clauses, "minimum_should_match": 1}}, "size": 10}
    result = es.search(index=index, body=body)
    return {"original_query": query, "expanded_queries": expanded_queries, "results": result["hits"]["hits"]}
```

原始查询权重最高（1/1），扩展查询权重递减（1/2, 1/3...），保证相关性排序的合理性。

### 查询扩展的替代方案

LLM 查询扩展效果好但成本高、延迟大。还有其他扩展方式可选：

```python
# 方式1：同义词词典扩展（低成本、低延迟）
SYNONYM_MAP = {
    "高并发": ["并发处理", "高流量", "高负载", "并发控制"],
    "数据库": ["DB", "存储引擎", "数据存储"],
    "缓存": ["cache", "缓存层", "缓存系统"],
}

def expand_with_synonyms(query: str) -> list[str]:
    expanded = [query]
    for term, synonyms in SYNONYM_MAP.items():
        if term in query:
            expanded.extend(synonyms)
    return expanded

# 方式2：伪相关反馈（PRF）—— 从初始结果中提取扩展词
def expand_with_prf(query: str, index: str = "knowledge_base", top_k: int = 3) -> list[str]:
    initial = es.search(index=index, body={
        "query": {"match": {"content": query}},
        "size": top_k
    })

    top_terms = set()
    for hit in initial["hits"]["hits"]:
        content = hit["_source"]["content"]
        words = content.split()
        top_terms.update(words[:50])

    query_words = set(query.split())
    new_terms = [t for t in top_terms if t not in query_words and len(t) > 1][:5]

    return [query] + new_terms

# 方式3：ES 的内置同义词扩展（无需 LLM）
def setup_synonym_analyzer():
    settings = {
        "analysis": {
            "filter": {
                "search_synonyms": {
                    "type": "synonym_graph",
                    "synonyms": [
                        "高并发,并发处理,高流量,高负载",
                        "缓存,cache,缓冲",
                        "数据库,DB,存储引擎"
                    ]
                }
            },
            "analyzer": {
                "search_with_synonyms": {
                    "tokenizer": "ik_smart",
                    "filter": ["search_synonyms"]
                }
            }
        }
    }
    return settings
```

选择哪种方式取决于场景：同义词词典适合领域明确的垂直搜索（如电商），PRF 适合通用搜索，LLM 扩展适合查询理解和意图识别要求高的场景。

## LLM 重排序（Reranking）

初始检索按文本匹配排序，可能遗漏语义相关但词汇不同的文档。用 LLM 做重排序：

```python
import json

def rerank_with_llm(query: str, documents: list[dict], top_k: int = 5):
    doc_list = "\n\n".join([
        f"[文档{i+1}] {doc['title']}\n{doc['content'][:300]}"
        for i, doc in enumerate(documents)
    ])
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "根据查询相关性对文档排序，返回JSON数组：[{\"doc\": 1, \"score\": 8.5}, ...]"},
            {"role": "user", "content": f"查询：{query}\n\n文档列表：\n{doc_list}"}
        ],
        temperature=0, max_tokens=500, response_format={"type": "json_object"}
    )
    scores = json.loads(response.choices[0].message.content)
    for item in scores.get("rankings", scores.get("documents", [])):
        idx = item["doc"] - 1
        if 0 <= idx < len(documents):
            documents[idx]["rerank_score"] = item["score"]
    documents.sort(key=lambda x: x.get("rerank_score", 0), reverse=True)
    return documents[:top_k]
```

重排序的策略是"召回多、精排少"：先检索 20 个候选文档，LLM 精排后取 top 5。这比直接用 top 5 效果好得多。

### Cross-Encoder 重排序

除了 LLM 重排序，还可以使用专门的 Cross-Encoder 模型，延迟更低：

```python
from sentence_transformers import CrossEncoder

reranker = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2")

def rerank_with_cross_encoder(query: str, documents: list[dict], top_k: int = 5):
    pairs = [(query, doc.get("content", "")[:512]) for doc in documents]
    scores = reranker.predict(pairs)

    for i, score in enumerate(scores):
        documents[i]["rerank_score"] = float(score)

    documents.sort(key=lambda x: x.get("rerank_score", 0), reverse=True)
    return documents[:top_k]

# 混合重排序：Cross-Encoder 粗排 + LLM 精排
def hybrid_rerank(query: str, documents: list[dict], top_k: int = 5):
    # 第一步：Cross-Encoder 粗排，取 top 10
    coarse_ranked = rerank_with_cross_encoder(query, documents, top_k=10)

    # 第二步：LLM 精排，取 top 5
    fine_ranked = rerank_with_llm(query, coarse_ranked, top_k=top_k)

    return fine_ranked
```

Cross-Encoder 将 query 和 document 拼接后一起编码，比 Bi-Encoder（向量检索）的语义理解更深，但速度慢约 100 倍。所以通常用 Bi-Encoder 做初筛（100 → 20），Cross-Encoder 做精排（20 → 5），LLM 做最终排序（可选）。

### 重排序的评估

重排序是否有效需要量化评估：

```python
def evaluate_reranking(query: str, documents: list[dict],
                       ground_truth: dict, k: int = 5):
    import math

    def ndcg_at_k(ranked_ids: list[str], judgments: dict, k: int) -> float:
        dcg = sum(
            (2 ** judgments.get(doc_id, 0) - 1) / math.log2(rank + 2)
            for rank, doc_id in enumerate(ranked_ids[:k])
        )
        ideal = sorted(judgments.values(), reverse=True)[:k]
        idcg = sum((2 ** r - 1) / math.log2(i + 2) for i, r in enumerate(ideal))
        return dcg / idcg if idcg > 0 else 0.0

    # 原始排序的 NDCG
    original_ids = [doc["id"] for doc in documents]
    original_ndcg = ndcg_at_k(original_ids, ground_truth, k)

    # 重排序后的 NDCG
    reranked = rerank_with_llm(query, documents.copy(), top_k=len(documents))
    reranked_ids = [doc["id"] for doc in reranked]
    reranked_ndcg = ndcg_at_k(reranked_ids, ground_truth, k)

    return {
        "query": query,
        "original_ndcg": round(original_ndcg, 4),
        "reranked_ndcg": round(reranked_ndcg, 4),
        "improvement": round(reranked_ndcg - original_ndcg, 4),
        "is_effective": reranked_ndcg > original_ndcg
    }
```

如果重排序后的 NDCG 没有提升，说明要么检索质量已经够好，要么重排序模型不适合当前领域。

## 摘要生成

为搜索结果生成上下文相关的摘要，替代静态片段：

```python
def generate_snippet(query: str, document: dict, max_length: int = 150):
    content = document.get("content", "")
    if len(content) <= max_length * 2:
        return content
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": f"从文档中提取与查询最相关的部分，生成不超过{max_length}字的摘要。"},
            {"role": "user", "content": f"查询：{query}\n\n文档：{document['title']}\n{content[:2000]}"}
        ],
        temperature=0, max_tokens=300
    )
    return response.choices[0].message.content
```

AI 摘要根据用户的查询动态生成，同一个文档在不同查询下会展示不同的摘要。

### 摘要生成的成本优化

为每个搜索结果都调用 LLM 生成摘要成本太高。优化策略：

```python
import hashlib
import redis

redis_client = redis.Redis(host="localhost", port=6379, db=0)

def generate_snippet_cached(query: str, document: dict, max_length: int = 150):
    content = document.get("content", "")
    if len(content) <= max_length * 2:
        return content

    cache_key = f"snippet:{hashlib.md5(f'{query}:{document.get(\"id\", \"\")}'.encode()).hexdigest()}"
    cached = redis_client.get(cache_key)
    if cached:
        return cached.decode("utf-8")

    snippet = generate_snippet(query, document, max_length)
    redis_client.setex(cache_key, 3600, snippet)
    return snippet

def generate_snippets_async(query: str, documents: list[dict], top_n: int = 3):
    """只对 top N 结果生成 AI 摘要，其余使用 ES 高亮"""
    results = []
    for i, doc in enumerate(documents):
        if i < top_n:
            snippet = generate_snippet_cached(query, doc)
            results.append({"id": doc.get("id"), "snippet": snippet, "is_ai_generated": True})
        else:
            # 使用 ES 的高亮结果作为摘要
            highlight = doc.get("highlight", {})
            snippet = highlight.get("content", [doc.get("content", "")[:150]])[0]
            results.append({"id": doc.get("id"), "snippet": snippet, "is_ai_generated": False})

    return results
```

关键优化点：只对排名前 3 的结果生成 AI 摘要，其余用 ES 高亮替代；缓存相同查询+文档的摘要结果；异步生成不阻塞搜索响应。

## 完整 RAG Pipeline

将以上组件组合成完整的搜索增强管道：

```python
def enhanced_search(query: str, index: str = "knowledge_base",
                    use_expansion: bool = True, use_reranking: bool = True):
    # 查询扩展
    search_queries = expand_query(query) if use_expansion else [query]

    # 检索
    should_clauses = [
        {"match": {"content": {"query": q, "boost": 1.0 / (i + 1)}}}
        for i, q in enumerate(search_queries)
    ]
    body = {"query": {"bool": {"should": should_clauses, "minimum_should_match": 1}},
            "size": 20 if use_reranking else 10}
    result = es.search(index=index, body=body)
    candidates = [
        {"id": h["_id"], "title": h["_source"]["title"],
         "content": h["_source"]["content"], "retrieval_score": h["_score"]}
        for h in result["hits"]["hits"]
    ]

    # 重排序
    if use_reranking and len(candidates) > 5:
        candidates = rerank_with_llm(query, candidates, top_k=5)

    # RAG 回答
    context = "\n\n---\n\n".join([f"[{d['title']}]\n{d['content']}" for d in candidates[:5]])
    answer = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "根据参考资料回答问题，引用来源。"},
            {"role": "user", "content": f"参考资料：\n{context}\n\n问题：{query}"}
        ],
        temperature=0.3
    )
    return {"answer": answer.choices[0].message.content, "sources": candidates[:5]}
```

完整管道支持按需开关各组件。延迟敏感场景关闭 AI 摘要，精度要求高的场景开启重排序。

### 流式输出

RAG 回答通常较长，流式输出让用户更快看到结果：

```python
from typing import Generator

def rag_search_stream(query: str, index: str = "knowledge_base") -> Generator:
    search_body = {
        "query": {"multi_match": {"query": query, "fields": ["title^2", "content"]}},
        "size": 5
    }
    search_result = es.search(index=index, body=search_body)

    contexts = [h["_source"]["content"] for h in search_result["hits"]["hits"]]
    context_text = "\n\n---\n\n".join(contexts)

    stream = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "根据参考资料回答问题，引用来源。"},
            {"role": "user", "content": f"参考资料：\n{context_text}\n\n问题：{query}"}
        ],
        temperature=0.3,
        stream=True
    )

    for chunk in stream:
        if chunk.choices[0].delta.content:
            yield chunk.choices[0].delta.content
```

流式输出让用户在 LLM 生成第一个字时就能看到结果，大幅提升感知速度。FastAPI 可以用 `StreamingResponse` 将流式结果返回给前端。

### 降级策略

RAG 系统依赖多个外部服务（ES、LLM API），需要完善的降级策略：

```python
import time
from functools import wraps

def with_fallback(fallback_func):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            try:
                return func(*args, **kwargs)
            except Exception as e:
                print(f"主函数失败: {e}, 使用降级方案")
                return fallback_func(*args, **kwargs)
        return wrapper
    return decorator

def fallback_search(query: str, index: str = "knowledge_base"):
    """降级到纯 BM25 搜索"""
    result = es.search(index=index, body={
        "query": {"match": {"content": query}},
        "highlight": {"fields": {"content": {"fragment_size": 200}}},
        "size": 10
    })
    return {
        "answer": None,
        "sources": [
            {"title": h["_source"]["title"],
             "snippet": h.get("highlight", {}).get("content", [""])[0]}
            for h in result["hits"]["hits"]
        ],
        "is_fallback": True
    }

@with_fallback(fallback_search)
def rag_with_fallback(query: str, index: str = "knowledge_base"):
    return enhanced_search(query, index)
```

降级策略的核心思想：宁可返回不完美的结果，也不要返回错误或空白。当 LLM API 不可用时，降级到传统搜索+高亮摘要。

## RAG 系统的评估

RAG 系统的效果需要从多个维度评估：

```python
def evaluate_rag_system(test_cases: list[dict], index: str = "knowledge_base"):
    results = {
        "total": len(test_cases),
        "retrieval_hits": 0,
        "answer_correct": 0,
        "answer_grounded": 0,
        "avg_latency_ms": 0,
        "details": []
    }

    for case in test_cases:
        start = time.time()
        rag_result = rag_search(case["query"], index=index)
        latency = (time.time() - start) * 1000

        # 检索命中率：检索结果中是否包含标准答案的来源
        retrieved_ids = [s.get("id") for s in rag_result.get("sources", [])]
        retrieval_hit = any(sid in case.get("source_ids", []) for sid in retrieved_ids)

        # 回答准确性：LLM 生成的回答是否包含关键信息
        answer = rag_result.get("answer", "")
        key_info = case.get("key_info", [])
        answer_correct = all(info.lower() in answer.lower() for info in key_info)

        # 回答接地性：回答是否基于检索到的文档
        grounded = check_groundedness(answer, rag_result.get("sources", []))

        if retrieval_hit:
            results["retrieval_hits"] += 1
        if answer_correct:
            results["answer_correct"] += 1
        if grounded:
            results["answer_grounded"] += 1

        results["avg_latency_ms"] += latency
        results["details"].append({
            "query": case["query"],
            "retrieval_hit": retrieval_hit,
            "answer_correct": answer_correct,
            "grounded": grounded,
            "latency_ms": round(latency, 2)
        })

    n = results["total"]
    results["avg_latency_ms"] = round(results["avg_latency_ms"] / n, 2)
    results["retrieval_recall"] = round(results["retrieval_hits"] / n, 4)
    results["answer_accuracy"] = round(results["answer_correct"] / n, 4)
    results["groundedness_rate"] = round(results["answer_grounded"] / n, 4)

    return results

def check_groundedness(answer: str, sources: list[dict]) -> bool:
    """简单的接地性检查：回答中的关键句子是否能在来源中找到"""
    source_text = " ".join(s.get("content", "") for s in sources).lower()
    sentences = [s.strip() for s in answer.split("。") if len(s.strip()) > 10]

    grounded_count = 0
    for sentence in sentences:
        keywords = [w for w in sentence.split() if len(w) > 1]
        if any(kw.lower() in source_text for kw in keywords):
            grounded_count += 1

    return grounded_count / max(len(sentences), 1) > 0.5
```

三个核心指标：检索召回率（是否找到正确文档）、回答准确性（答案是否正确）、接地性（答案是否基于文档而非幻觉）。

## 常见误区

1. **RAG 不等于直接问 LLM**：不经过检索直接问 LLM 容易产生幻觉，RAG 的价值在于用真实文档约束生成。
2. **上下文塞太多文档**：塞太多文档会导致注意力分散，通常 5-10 篇足够。
3. **忽略检索质量**：RAG 的上限是检索质量。检索不到相关文档，LLM 再强也无法生成正确答案。
4. **不做引用溯源**：不标注来源的回答缺乏可信度。
5. **所有查询都走 RAG**：简单导航类查询直接返回即可，不需要 LLM 生成。
6. **忽略 token 成本**：RAG 的 token 消耗包括上下文和回答，高频场景成本可观。
7. **不做 A/B 测试**：RAG 的效果需要通过在线指标（用户满意度、点击率）验证。

## 工程建议

1. **缓存 LLM 响应**：相同查询和文档的 LLM 结果可以缓存，减少 API 调用成本。
2. **异步生成摘要**：AI 摘要可以在搜索结果返回后再异步加载。
3. **设置超时和降级**：LLM 调用可能超时，需要降级到传统搜索。
4. **监控 token 用量**：RAG 的 token 消耗包括上下文和回答，需要监控并设置预算。
5. **评估 RAG 效果**：定期用标注数据集评估准确率和幻觉率。
6. **流式输出**：对 RAG 回答使用流式输出，提升用户感知速度。
7. **分层缓存**：搜索结果用 ES 缓存，RAG 回答用 Redis 缓存，LLM 响应用语义缓存。
8. **成本控制**：对低频查询不使用 LLM 重排序和摘要生成。

## 小结

AI 搜索增强通过 RAG、查询扩展、重排序和摘要生成，让搜索引擎从"找文档"进化为"给答案"。RAG 用检索结果约束 LLM 生成，减少幻觉。查询扩展提高召回率，重排序提升精度。这些技术的组合使用，让搜索结果更精准、更有价值。工程化实践中的缓存、降级和成本控制同样重要。

### 练习一

**思路**：用 ES 的 BM25 做关键词检索，用向量模型做语义检索，然后用 RRF 合并排序。

**答案**：

```python
from sentence_transformers import SentenceTransformer
model = SentenceTransformer("all-MiniLM-L6-v2")

def hybrid_search(query: str, index: str = "knowledge_base"):
    bm25_body = {"query": {"multi_match": {"query": query, "fields": ["title^2", "content"]}}, "size": 20}
    bm25_ids = [h["_id"] for h in es.search(index=index, body=bm25_body)["hits"]["hits"]]

    query_vector = model.encode(query).tolist()
    vector_body = {"knn": {"field": "embedding", "query_vector": query_vector, "k": 20, "num_candidates": 50}, "size": 20}
    vector_ids = [h["_id"] for h in es.search(index=index, body=vector_body)["hits"]["hits"]]

    def rrf_score(doc_id, k=60):
        score = 0
        if doc_id in bm25_ids: score += 1 / (k + bm25_ids.index(doc_id) + 1)
        if doc_id in vector_ids: score += 1 / (k + vector_ids.index(doc_id) + 1)
        return score

    all_ids = list(set(bm25_ids + vector_ids))
    return sorted(all_ids, key=rrf_score, reverse=True)[:10]
```

**要点**：RRF 不依赖分数的绝对值，只看排名位置，天然融合不同量纲的检索结果。

### 练习二

**思路**：将历史对话拼接到 prompt 中，用代词解析让 LLM 理解上下文指代。

**答案**：

```python
def multi_turn_rag(query: str, history: list[dict], index: str = "knowledge_base"):
    history_text = " ".join([f"{m['role']}: {m['content']}" for m in history[-4:]])
    search_body = {"query": {"multi_match": {"query": f"{history_text} {query}", "fields": ["title^2", "content"]}}, "size": 5}
    result = es.search(index=index, body=search_body)
    context = "\n\n---\n\n".join([h["_source"]["content"] for h in result["hits"]["hits"]])

    messages = [{"role": "system", "content": "根据参考资料和对话历史回答问题，理解指代关系。"}]
    for msg in history[-6:]:
        messages.append({"role": msg["role"], "content": msg["content"]})
    messages.append({"role": "user", "content": f"参考资料：\n{context}\n\n当前问题：{query}"})

    response = client.chat.completions.create(model="gpt-4o-mini", messages=messages, temperature=0.3)
    return {"answer": response.choices[0].message.content}
```

**要点**：历史对话只取最近 6 条，搜索词融合了历史对话让检索能理解指代词。

### 练习三

**思路**：将 LLM 回答拆分为句子，逐一与原文对比，标记无法找到支撑证据的句子。

**答案**：

```python
def detect_hallucination(answer: str, sources: list[dict]):
    sentences = [s.strip() for s in answer.split("。") if s.strip()]
    source_text = " ".join([s["content"] for s in sources])

    results = []
    for sentence in sentences:
        response = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[
                {"role": "system", "content": "判断句子是否能从参考资料推导。只回答：SUPPORTED/PARTIAL/UNSUPPORTED"},
                {"role": "user", "content": f"参考资料：\n{source_text[:3000]}\n\n句子：{sentence}"}
            ],
            temperature=0, max_tokens=10
        )
        results.append({"sentence": sentence, "verdict": response.choices[0].message.content.strip()})

    unsupported = [r for r in results if r["verdict"] == "UNSUPPORTED"]
    return {
        "total": len(sentences),
        "supported": len([r for r in results if r["verdict"] == "SUPPORTED"]),
        "unsupported": len(unsupported),
        "hallucination_rate": len(unsupported) / len(sentences) if sentences else 0
    }
```

**要点**：hallucination_rate 越低说明 RAG 系统越可靠。这是评估 RAG 质量的重要指标。

### 练习四

**思路**：构建测试用例，分别评估检索和生成两个阶段。

**答案**：

```python
def rag_evaluation_framework(test_cases: list[dict], index: str = "knowledge_base"):
    report = {
        "summary": {},
        "retrieval_metrics": {},
        "generation_metrics": {},
        "per_query": []
    }

    retrieval_hits = 0
    answer_hits = 0
    total_latency = 0
    total_hallucination = 0

    for case in test_cases:
        start = time.time()
        result = rag_search(case["query"], index=index)
        latency = (time.time() - start) * 1000

        source_ids = [s.get("id") for s in result.get("sources", [])]
        expected_ids = case.get("relevant_doc_ids", [])
        hit = any(sid in expected_ids for sid in source_ids)
        if hit:
            retrieval_hits += 1

        answer = result.get("answer", "")
        key_points = case.get("key_points", [])
        correct = sum(1 for kp in key_points if kp.lower() in answer.lower())
        if correct == len(key_points):
            answer_hits += 1

        hallucination = detect_hallucination(answer, result.get("sources", []))
        total_hallucination += hallucination["hallucination_rate"]

        total_latency += latency

        report["per_query"].append({
            "query": case["query"],
            "retrieval_hit": hit,
            "answer_complete": correct == len(key_points),
            "hallucination_rate": hallucination["hallucination_rate"],
            "latency_ms": round(latency, 2)
        })

    n = len(test_cases)
    report["summary"] = {
        "total_queries": n,
        "avg_latency_ms": round(total_latency / n, 2)
    }
    report["retrieval_metrics"] = {
        "recall": round(retrieval_hits / n, 4)
    }
    report["generation_metrics"] = {
        "accuracy": round(answer_hits / n, 4),
        "avg_hallucination_rate": round(total_hallucination / n, 4)
    }

    return report
```

**要点**：评估框架覆盖检索、生成和幻觉三个维度。每个测试用例需要包含查询、相关文档 ID 和关键信息点。
