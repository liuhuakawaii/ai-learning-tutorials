# 搜索特征工程：从原始数据到排序信号

## 场景引入

上一课我们学习了 LambdaMART，知道它能自动学习特征到排序分数的映射。但模型效果高度依赖输入特征的质量——**垃圾进，垃圾出**。一个真实的搜索引擎可以从原始数据中提取数百个特征，搜索特征工程是 LTR 系统中投入工程量最大、对效果影响最显著的环节。

Google 的搜索排序系统使用数百个特征，Bing 的排序系统曾公开表示其特征数量超过 1000 个。这些特征涵盖了从简单的文本匹配到复杂的用户行为信号。在工业界，特征工程通常占据 LTR 项目 60%-80% 的工程量，而模型训练和调优只占 20%-40%。

为什么特征工程如此重要？因为模型只能从输入特征中学习模式。如果一个重要信号没有被编码为特征，模型就无法利用它。例如，如果不在特征中加入"查询是否完全出现在标题中"这个信号，模型就很难学会这个常识：标题精确匹配查询的文档通常更相关。

## 学习目标

1. 理解搜索排序中三大类特征的含义和作用
2. 掌握查询特征、文档特征、交互特征的提取方法
3. 构建一个完整的搜索特征 Pipeline
4. 理解特征归一化、缺失值处理等工程细节
5. 掌握特征重要性分析和特征选择方法

## 1. 特征分类体系

搜索排序特征分为三大类：**查询特征**（描述查询本身）、**文档特征**（描述文档本身）、**交互特征**（描述查询与文档的匹配关系）。交互特征通常最具区分力。

### 1.1 三大类特征的直觉理解

| 类别 | 含义 | 计算时机 | 缓存策略 |
|------|------|----------|----------|
| 查询特征 | 描述查询本身属性 | 查询到达时 | 查询级缓存 |
| 文档特征 | 描述文档本身属性 | 离线预计算 | 存入索引 |
| 交互特征 | 描述查询-文档匹配关系 | 在线实时计算 | 短时缓存 |

查询特征和文档特征可以离线计算并缓存，交互特征必须在线实时计算。这决定了特征系统的设计——交互特征的计算效率直接影响排序延迟。

### 1.2 特征数量的经验法则

- **小型搜索系统**：20-50 个特征足够
- **中型搜索系统**：50-200 个特征
- **大型搜索引擎**：200-1000+ 个特征

特征不是越多越好。过多的特征会增加计算开销、引入噪声、导致过拟合。关键是要有区分力的特征。

## 2. 查询特征提取

查询特征描述查询本身的属性，与具体文档无关。它们帮助模型理解查询的"难度"和"类型"。

```python
import math
from dataclasses import dataclass
from typing import Dict


@dataclass
class QueryInfo:
    query_id: str
    query_text: str
    query_log_freq: int
    has_quotes: bool
    avg_click_depth: float


def extract_query_features(query: QueryInfo) -> Dict[str, float]:
    """提取查询特征。

    返回一个字典，键为特征名，值为特征值。
    """
    terms = query.query_text.split()
    return {
        "query_term_count": len(terms),
        "query_char_count": len(query.query_text),
        "query_has_quotes": float(query.has_quotes),
        "query_log_freq_norm": math.log1p(query.query_log_freq),
        "query_is_navigational": 1.0 if any(
            ind in query.query_text.lower()
            for ind in [".com", ".cn", "官网", "首页"]
        ) else 0.0,
        "query_is_transactional": 1.0 if any(
            w in query.query_text for w in ["买", "价格", "优惠", "商城"]
        ) else 0.0,
        "query_avg_click_depth": query.avg_click_depth,
    }
```

### 2.1 查询频率的意义

查询频率是一个重要信号。高频查询通常是头部查询（如"天气"、"淘宝"），排序模型对这些查询有更多训练数据，排序效果通常更好。低频查询（长尾查询）训练数据少，排序更困难。

```python
def classify_query_frequency(log_freq: int) -> str:
    """将查询频率分为高频、中频、低频。"""
    if log_freq >= 10000:
        return "head"      # 头部查询，占查询日志的 ~10%，覆盖 ~50% 流量
    elif log_freq >= 100:
        return "torso"     # 躯干查询，占 ~30%，覆盖 ~35% 流量
    else:
        return "tail"      # 长尾查询，占 ~60%，覆盖 ~15% 流量
```

### 2.2 查询改写特征

实际搜索引擎中，用户查询通常会被改写（query rewriting）后再检索。查询改写特征描述原始查询和改写后查询的关系：

```python
def extract_query_rewrite_features(original_query: str, rewritten_query: str) -> Dict[str, float]:
    """提取查询改写特征。"""
    orig_terms = set(original_query.lower().split())
    rewrite_terms = set(rewritten_query.lower().split())

    return {
        "rewrite_term_added": len(rewrite_terms - orig_terms),
        "rewrite_term_removed": len(orig_terms - rewrite_terms),
        "rewrite_jaccard": len(orig_terms & rewrite_terms) / len(orig_terms | rewrite_terms)
                           if (orig_terms | rewrite_terms) else 0,
        "rewrite_length_ratio": len(rewritten_query) / max(len(original_query), 1),
    }
```

## 3. 文档特征提取

```python
@dataclass
class DocumentInfo:
    doc_id: str
    title: str
    body: str
    url: str
    publish_time_days_ago: float
    page_rank: float
    domain_authority: float
    content_quality_score: float


def extract_document_features(doc: DocumentInfo) -> Dict[str, float]:
    """提取文档特征。

    这些特征描述文档本身的属性，与查询无关。
    通常离线预计算并存入索引。
    """
    body_len = len(doc.body.split())
    return {
        "doc_page_rank": doc.page_rank,
        "doc_page_rank_norm": min(doc.page_rank / 10.0, 1.0),
        "doc_body_length_log": math.log1p(body_len),
        "doc_domain_authority": doc.domain_authority,
        "doc_content_quality": doc.content_quality_score,
        "doc_freshness": math.exp(-0.023 * doc.publish_time_days_ago),
        "doc_url_depth": doc.url.count("/") - 2,
        "doc_url_is_trusted": 1.0 if any(
            d in doc.url for d in [".edu", ".gov", ".org"]
        ) else 0.0,
    }
```

### 3.1 URL 特征的工程价值

URL 包含丰富的信号：

```python
def extract_url_features(url: str) -> Dict[str, float]:
    """从 URL 提取特征。"""
    parts = url.split("/")
    return {
        "url_depth": len(parts) - 3,                           # URL 层级深度
        "url_has_https": 1.0 if url.startswith("https") else 0.0,  # 是否 HTTPS
        "url_has_params": 1.0 if "?" in url else 0.0,         # 是否有查询参数
        "url_param_count": url.count("&") + (1 if "?" in url else 0),  # 参数数量
        "url_has_file_ext": 1.0 if any(
            url.endswith(ext) for ext in [".pdf", ".doc", ".html"]
        ) else 0.0,
        "url_domain_length": len(url.split("/")[2]) if len(url.split("/")) > 2 else 0,
    }
```

URL 深度大的页面通常是子页面，质量可能低于首页。HTTPS 是质量信号（正规网站更可能使用 HTTPS）。URL 参数多可能意味着动态生成的页面，内容质量可能不稳定。

### 3.2 文档结构特征

文档的结构也能反映质量：

```python
def extract_document_structure_features(title: str, body: str) -> Dict[str, float]:
    """提取文档结构特征。"""
    paragraphs = body.split("\n\n")
    sentences = body.split("。")
    return {
        "doc_title_length": len(title.split()),
        "doc_body_length": len(body.split()),
        "doc_paragraph_count": len(paragraphs),
        "doc_avg_paragraph_length": sum(len(p.split()) for p in paragraphs) / max(len(paragraphs), 1),
        "doc_sentence_count": len(sentences),
        "doc_has_numbered_list": 1.0 if any(
            line.strip().startswith(("1.", "2.", "①", "②"))
            for line in body.split("\n")
        ) else 0.0,
    }
```

## 4. 交互特征提取

交互特征是最具区分力的特征，因为它们直接衡量查询和文档的匹配程度。

```python
from collections import Counter


def extract_interaction_features(
    query: QueryInfo, doc: DocumentInfo,
    bm25_score: float = 0.0, historical_ctr: float = 0.0,
) -> Dict[str, float]:
    """提取交互特征。

    这些特征描述查询和文档的匹配关系，必须在线实时计算。
    """
    q_terms = set(query.query_text.lower().split())
    t_terms = set(doc.title.lower().split())
    b_terms = doc.body.lower().split()
    b_set = set(b_terms)

    intersection_title = len(q_terms & t_terms)
    union_title = len(q_terms | t_terms)

    return {
        "bm25_score": bm25_score,
        "title_query_jaccard": intersection_title / union_title if union_title else 0,
        "title_query_coverage": intersection_title / len(q_terms) if q_terms else 0,
        "body_query_coverage": len(q_terms & b_set) / len(q_terms) if q_terms else 0,
        "query_in_title": 1.0 if query.query_text.lower() in doc.title.lower() else 0.0,
        "query_term_freq_in_body": sum(Counter(b_terms).get(t, 0) for t in q_terms),
        "doc_historical_ctr": historical_ctr,
    }
```

### 4.1 关键交互特征解析

**Jaccard 系数**：衡量查询词集合和标题词集合的重叠程度。值为 1 表示完全匹配，值为 0 表示无重叠。

**覆盖率（Coverage）**：查询中有多少比例的词出现在文档中。覆盖率高意味着文档回答了查询的大部分内容。

**精确匹配（query_in_title）**：查询是否作为子串出现在标题中。这是非常强的信号——如果用户搜索"Python 教程"，标题恰好是"Python 教程"的文档几乎一定高度相关。

### 4.2 更多高级交互特征

```python
def extract_advanced_interaction_features(
    query: QueryInfo, doc: DocumentInfo
) -> Dict[str, float]:
    """提取高级交互特征。"""
    q_terms = query.query_text.lower().split()
    t_terms = doc.title.lower().split()
    b_terms = doc.body.lower().split()

    # 查询词在标题中的连续匹配
    max_consecutive = 0
    current = 0
    qi = 0
    for tt in t_terms:
        if qi < len(q_terms) and tt == q_terms[qi]:
            current += 1
            qi += 1
            max_consecutive = max(max_consecutive, current)
        else:
            current = 0
            qi = 0

    # 查询词在正文中的首次出现位置
    q_set = set(q_terms)
    first_pos = 1.0
    for i, bt in enumerate(b_terms):
        if bt in q_set:
            first_pos = i / max(len(b_terms), 1)
            break

    # BM25 在标题和正文中的比值
    title_bm25 = compute_field_bm25_simple(q_terms, t_terms)
    body_bm25 = compute_field_bm25_simple(q_terms, b_terms)

    return {
        "title_consecutive_match": max_consecutive,
        "first_occurrence_position": first_pos,
        "title_body_bm25_ratio": title_bm25 / (body_bm25 + 1e-10),
        "query_is_substring_of_title": 1.0 if query.query_text.lower() in doc.title.lower() else 0.0,
    }


def compute_field_bm25_simple(q_terms, d_terms, k1=1.2, b=0.75):
    """简化的 BM25 计算。"""
    dl = len(d_terms)
    cnt = Counter(d_terms)
    return sum(
        math.log(1000 / (1 + cnt.get(t, 0))) *
        (cnt.get(t, 0) * (k1 + 1)) /
        (cnt.get(t, 0) + k1 * (1 - b + b * dl / 200))
        for t in q_terms if cnt.get(t, 0) > 0
    )
```

**连续匹配**：如果查询的多个词在标题中连续出现，说明标题是一个短语匹配，比分散出现的词更有价值。

**首次出现位置**：查询词在正文中越早出现，通常说明文档越聚焦于该主题。

## 5. 完整特征 Pipeline

```python
from typing import List, Tuple
import numpy as np


class SearchFeaturePipeline:
    """搜索特征提取 Pipeline。

    支持单样本和批量提取，以及归一化和缺失值处理。
    """

    def __init__(self):
        self.feature_names: List[str] = []
        self._stats = {}

    def extract_single(self, query, doc, bm25=0.0, ctr=0.0) -> Dict[str, float]:
        """提取单个 (查询, 文档) 对的特征。"""
        feats = {}
        feats.update(extract_query_features(query))
        feats.update(extract_document_features(doc))
        feats.update(extract_interaction_features(query, doc, bm25, ctr))
        return feats

    def extract_batch(self, samples: List[Tuple]) -> np.ndarray:
        """批量提取特征，返回特征矩阵。"""
        all_feats = [self.extract_single(q, d, s.get("bm25", 0), s.get("ctr", 0))
                     for q, d, s in samples]
        if not self.feature_names:
            self.feature_names = sorted(all_feats[0].keys())
        return np.array([[f[n] for n in self.feature_names] for f in all_feats])

    def fit_normalizer(self, matrix: np.ndarray):
        """在训练集上拟合归一化参数。"""
        self._stats["mean"] = np.mean(matrix, axis=0)
        std = np.std(matrix, axis=0)
        std[std == 0] = 1.0
        self._stats["std"] = std

    def normalize(self, matrix: np.ndarray) -> np.ndarray:
        """用拟合的参数归一化特征矩阵。"""
        if "mean" not in self._stats:
            self.fit_normalizer(matrix)
        return (matrix - self._stats["mean"]) / self._stats["std"]

    def handle_missing(self, matrix: np.ndarray) -> np.ndarray:
        """处理缺失值，用中位数填充。"""
        for col in range(matrix.shape[1]):
            mask = np.isnan(matrix[:, col])
            if mask.any():
                matrix[mask, col] = np.nanmedian(matrix[:, col])
        return matrix
```

## 6. 特征重要性分析

```python
def analyze_feature_importance(model, feature_names, top_k=10):
    """分析并可视化特征重要性。"""
    importance = model.feature_importance(importance_type="gain")
    indices = np.argsort(-importance)[:top_k]
    for rank, idx in enumerate(indices, 1):
        bar = "█" * int(importance[idx] / importance[indices[0]] * 30)
        print(f"{rank:2d}. {feature_names[idx]:35s} {importance[idx]:8.1f} {bar}")
```

### 6.1 特征重要性的两种计算方式

LightGBM 支持两种特征重要性计算方式：

- **gain**：特征在所有分裂中带来的总增益。反映特征对模型预测的整体贡献。
- **split**：特征被用作分裂点的次数。反映特征的使用频率。

```python
def compare_importance_types(model, feature_names):
    """对比 gain 和 split 两种重要性计算方式。"""
    gain_imp = model.feature_importance(importance_type="gain")
    split_imp = model.feature_importance(importance_type="split")

    print(f"{'特征名':35s} {'Gain':>10s} {'Split':>10s} {'Gain排名':>8s} {'Split排名':>8s}")
    print("-" * 80)

    gain_rank = np.argsort(-gain_imp)
    split_rank = np.argsort(-split_imp)

    for i in range(min(15, len(feature_names))):
        g_idx = gain_rank[i]
        s_idx = split_rank[i]
        print(f"{feature_names[g_idx]:35s} {gain_imp[g_idx]:10.1f} {split_imp[g_idx]:10.1f} "
              f"{i+1:8d} {list(split_rank).index(g_idx)+1:8d}")
```

通常 gain 和 split 的排名会有差异。一个特征可能被频繁使用（split 高）但每次增益不大（gain 低），也可能很少使用但每次使用都带来很大增益。

### 6.2 特征选择方法

```python
def recursive_feature_elimination(X, y, groups, feature_names, min_features=5):
    """递归特征消除：逐步移除最不重要特征，找到最优子集。"""
    import lightgbm as lgb

    remaining = list(range(X.shape[1]))
    best_ndcg, best_subset = 0, list(remaining)
    history = []

    while len(remaining) >= min_features:
        # 训练模型
        split = len(groups) // 2
        train_size = sum(groups[:split])
        train_set = lgb.Dataset(X[:train_size, remaining], label=y[:train_size], group=groups[:split])
        val_set = lgb.Dataset(X[train_size:, remaining], label=y[train_size:], group=groups[split:])
        params = {"objective": "lambdarank", "metric": "ndcg", "ndcg_eval_at": [10], "verbose": -1}
        model = lgb.train(params, train_set, num_boost_round=100, valid_sets=[val_set])

        ndcg = model.best_score["valid_0"]["ndcg@10"]
        history.append((len(remaining), ndcg, [feature_names[i] for i in remaining]))

        if ndcg > best_ndcg:
            best_ndcg = ndcg
            best_subset = list(remaining)

        # 移除最不重要特征
        imp = model.feature_importance(importance_type="gain")
        worst_idx = np.argmin(imp)
        remaining.pop(worst_idx)

    return best_subset, best_ndcg, history
```

## 7. 特征工程中的陷阱

### 7.1 特征穿越

特征穿越（Feature Leakage）是指使用了线上无法获取的特征。这是 LTR 系统中最常见的错误之一。

```python
# ❌ 错误示例：使用了人工标注分数作为特征
def bad_features(query, doc, human_relevance_score):
    return {
        "bm25": compute_bm25(query, doc),
        "human_score": human_relevance_score,  # 线上无法获取！
    }

# ✅ 正确示例：只使用线上可获取的特征
def good_features(query, doc, historical_ctr):
    return {
        "bm25": compute_bm25(query, doc),
        "historical_ctr": historical_ctr,  # 可从历史数据获取
    }
```

### 7.2 时间穿越

时间穿越是指使用了预测时间点之后的数据。例如，用今天的 CTR 预测昨天的排序。

```python
def check_temporal_leakage(features, prediction_time):
    """检查特征是否存在时间穿越。"""
    warnings = []
    if "future_ctr" in features:
        warnings.append("使用了未来时间窗口的 CTR")
    if features.get("publish_time", float("inf")) > prediction_time:
        warnings.append("文档发布时间晚于预测时间")
    return warnings
```

### 7.3 特征分布不一致

训练集和线上数据的特征分布不一致会导致模型效果下降：

```python
def detect_distribution_shift(train_features, online_features, threshold=0.1):
    """检测训练集和线上数据的特征分布差异。"""
    warnings = []
    for col in range(train_features.shape[1]):
        train_mean = np.mean(train_features[:, col])
        online_mean = np.mean(online_features[:, col])
        if abs(train_mean - online_mean) > threshold:
            warnings.append(f"特征 {col}: 训练均值={train_mean:.4f}, 线上均值={online_mean:.4f}")
    return warnings
```

## 8. 常见误区

1. **特征越多越好**：冗余特征增加训练时间并引入噪声，应通过特征选择去重
2. **忽视特征归一化**：不同量纲的特征直接输入模型会降低效果
3. **用未来数据预测过去**：CTR 等统计特征必须使用预测时间点之前的数据
4. **特征穿越**：使用了线上无法获取的特征（如人工标注分数）
5. **忽视缺失值**：新文档没有历史 CTR，必须有合理的填充策略
6. **不做特征监控**：特征分布会随时间变化，不监控会导致模型效果悄悄衰退
7. **盲目添加特征**：每个新特征都要验证其对排序效果的贡献

## 9. 工程建议

1. **特征分层管理**：查询特征、文档特征、交互特征分开计算和缓存
2. **文档特征预计算**：PageRank、域名权威度等离线计算，存入索引
3. **特征版本化**：每次修改特征集都要记录版本，便于回溯
4. **监控特征分布**：定期检查特征值分布变化，发现数据漂移
5. **特征重要性驱动迭代**：优先优化重要性高的特征
6. **建立特征文档**：每个特征都要有文档说明其含义、计算方式和预期分布

## 小结

本课系统介绍了搜索特征工程的三大类特征：查询特征（长度、类型、频率）、文档特征（PageRank、时效性、质量）、交互特征（BM25、覆盖率、用户行为）。特征 Pipeline 包含提取、归一化、缺失值处理。好的特征能让简单模型胜过复杂模型。

### 练习一

**思路**：三个特征分别捕获短语匹配、文档内位置和拼写相似度。

```python
def longest_consecutive_match(query, title):
    """查询词在标题中的最长连续匹配长度。"""
    q, t = query.lower().split(), title.lower().split()
    max_c, cur, qi = 0, 0, 0
    for tt in t:
        if qi < len(q) and tt == q[qi]:
            cur += 1; qi += 1
            max_c = max(max_c, cur)
        else:
            cur, qi = (1, 1) if tt == q[0] else (0, 0)
    return max_c

def first_occurrence_position(query_terms, body_terms):
    """查询词在正文中的首次出现位置（归一化到 [0, 1]）。"""
    for i, t in enumerate(body_terms):
        if t in query_terms:
            return i / max(len(body_terms), 1)
    return 1.0

def edit_distance_norm(s1, s2):
    """归一化编辑距离，范围 [0, 1]。"""
    m, n = len(s1), len(s2)
    dp = [[0]*(n+1) for _ in range(m+1)]
    for i in range(m+1): dp[i][0] = i
    for j in range(n+1): dp[0][j] = j
    for i in range(1, m+1):
        for j in range(1, n+1):
            dp[i][j] = min(dp[i-1][j]+1, dp[i][j-1]+1,
                           dp[i-1][j-1]+(0 if s1[i-1]==s2[j-1] else 1))
    return dp[m][n] / max(m, n)
```

**要点**：连续匹配捕获短语级信号，首次出现位置反映相关性密度。编辑距离适合捕获拼写错误或近似匹配。

### 练习三

**思路**：用同类别文档的行为统计量作为默认值，加 `is_cold_start` 标记。

```python
def cold_start_defaults(doc, category_stats):
    """为冷启动文档生成默认特征值。

    Args:
        doc: 新文档
        category_stats: 各类别的历史统计量

    Returns:
        默认特征字典
    """
    cat = doc.url.split("/")[3] if len(doc.url.split("/")) > 3 else "default"
    stats = category_stats.get(cat, category_stats.get("default", {}))
    return {
        "historical_ctr": stats.get("avg_ctr", 0.05) + doc.content_quality_score * 0.02,
        "avg_dwell_time": stats.get("avg_dwell", 60.0),
        "bounce_rate": stats.get("avg_bounce", 0.5),
        "is_cold_start": 1.0,
    }
```

**要点**：同类文档比全局均值更有参考价值，高质量文档应获得稍高的默认 CTR。`is_cold_start` 标记让模型知道这些值是估计值而非真实值。

### 练习四

**思路**：定期计算特征统计量并与基线对比。

```python
def monitor_feature_distribution(baseline_stats, current_features, feature_names, threshold=2.0):
    """监控特征分布变化，超过阈值时告警。

    Args:
        baseline_stats: 基线统计量 {"mean": [...], "std": [...]}
        current_features: 当前特征矩阵
        feature_names: 特征名列表
        threshold: Z-Score 阈值，超过此值视为异常
    """
    alerts = []
    current_mean = np.mean(current_features, axis=0)
    current_std = np.std(current_features, axis=0)

    for i, name in enumerate(feature_names):
        if baseline_stats["std"][i] > 0:
            z_score = abs(current_mean[i] - baseline_stats["mean"][i]) / baseline_stats["std"][i]
            if z_score > threshold:
                alerts.append({
                    "feature": name,
                    "baseline_mean": baseline_stats["mean"][i],
                    "current_mean": current_mean[i],
                    "z_score": z_score,
                })

    return alerts
```

**要点**：特征分布漂移可能导致模型效果悄悄下降。建议每天运行一次监控，发现异常及时排查原因。

import time

def benchmark_feature_extraction(query, docs, n_iterations=100):
