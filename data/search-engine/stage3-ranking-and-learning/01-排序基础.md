# 排序基础：搜索相关性与规则调权

用户搜索"蓝牙耳机"，搜索引擎从倒排索引中召回了 500 个文档。哪些应该排在前面？超过 70% 的点击集中在前 3 条结果，一个糟糕的排序算法会让好内容被埋没。

本课聚焦排序的起点：如何用人工设计的规则和因子组合来构建一个可用的排序系统。

## BM25 只是排序的起点

BM25 只考虑了文本匹配，忽略了文档质量、时效性、用户偏好、点击反馈等重要因素：

- 搜索"如何减肥"，一篇标题为"科学瘦身指南"的高质量文章 BM25 分数可能很低
- 垃圾站堆砌关键词可以拿到高 BM25 分数
- 一篇 2010 年的"最新手机推荐"在 BM25 看来分数很高

排序需要综合多个维度的信号。

## 实验：多因子加权排序

手动调权的核心公式：

```
最终分数 = w1 × 文本相关性 + w2 × 文档质量 + w3 × 时效性 + w4 × 热度
```

```python
import math
import time
from dataclasses import dataclass
from typing import List


@dataclass
class Document:
    doc_id: str
    title: str
    body: str
    url: str
    publish_time: float
    page_rank: float = 0.0
    click_count: int = 0


FIELD_WEIGHTS = {"title": 3.0, "body": 1.0}


def compute_text_score(query: str, doc: Document) -> float:
    score = 0.0
    query_terms = query.lower().split()
    for field, weight in FIELD_WEIGHTS.items():
        text = getattr(doc, field, "").lower()
        doc_terms = text.split()
        for term in query_terms:
            tf = doc_terms.count(term)
            if tf > 0:
                score += weight * math.log(1 + tf)
    return score


def compute_quality_score(doc: Document) -> float:
    pr_score = min(doc.page_rank / 10.0, 1.0)
    trusted = [".edu", ".gov", ".org"]
    url_trust = 0.8 if any(d in doc.url for d in trusted) else 0.5
    return 0.7 * pr_score + 0.3 * url_trust


def compute_freshness_score(doc: Document, half_life_days: float = 30.0) -> float:
    age_days = (time.time() - doc.publish_time) / 86400.0
    return math.exp(-math.log(2) / half_life_days * age_days)


def compute_popularity_score(doc: Document) -> float:
    if doc.click_count <= 0:
        return 0.0
    return math.log(1 + doc.click_count) / math.log(1 + 100000)
```

### 字段权重的设计原则

标题出现查询词比正文中出现更能说明相关性。字段权重的比值比绝对值更重要：如果标题权重是 3.0 而正文是 1.0，意味着标题中出现一次查询词等价于正文中出现三次。

### 时效性模型的选择

| 模型 | 适用场景 |
|------|----------|
| 指数衰减 | 新闻搜索，内容快速过时 |
| 线性衰减 | 活动搜索，有明确截止日期 |
| 阶梯函数 | 知识搜索，内容长期有效 |

半衰期因场景而异：新闻搜索可能设为 1 天，商品搜索 90 天，知识搜索 365 天。

## 实验：分场景调权

不同搜索场景需要不同的权重配置：

```python
@dataclass
class RankingConfig:
    text_weight: float = 0.45
    quality_weight: float = 0.25
    freshness_weight: float = 0.15
    popularity_weight: float = 0.15


SCENARIO_CONFIGS = {
    "新闻搜索": RankingConfig(0.30, 0.20, 0.40, 0.10),
    "知识问答": RankingConfig(0.40, 0.40, 0.05, 0.15),
    "商品搜索": RankingConfig(0.35, 0.15, 0.10, 0.40),
}
```

**新闻搜索**：时效性权重最高（0.40）。昨天的新闻远比一周前的有价值。

**知识问答**：质量权重最高（0.40）。用户搜"如何配置 Nginx"需要准确可靠的教程。

**商品搜索**：热度权重最高（0.40）。销量高、评价多的商品通常更值得推荐。

## 综合排序

```python
def rank_documents(query: str, docs: List[Document],
                   config: RankingConfig = None) -> List[tuple]:
    config = config or RankingConfig()
    results = []
    for doc in docs:
        score = (
            config.text_weight * compute_text_score(query, doc)
            + config.quality_weight * compute_quality_score(doc)
            + config.freshness_weight * compute_freshness_score(doc)
            + config.popularity_weight * compute_popularity_score(doc))
        results.append((doc.doc_id, score))
    results.sort(key=lambda x: x[1], reverse=True)
    return results


# 测试
```

## 实验：分数归一化

不同因子的分数范围差异巨大（BM25 可能是 0-20，PageRank 是 0-10，CTR 是 0-1）。直接加权求和会导致范围大的因子主导结果。

```python
def min_max_normalize(scores: List[float]) -> List[float]:
    if not scores:
        return []
    min_s, max_s = min(scores), max(scores)
    if max_s == min_s:
        return [0.5] * len(scores)
    return [(s - min_s) / (max_s - min_s) for s in scores]

def zscore_normalize(scores: List[float]) -> List[float]:
    if not scores:
        return []
    mean = sum(scores) / len(scores)
    std = (sum((s - mean) ** 2 for s in scores) / len(scores)) ** 0.5
    if std == 0:
        return [0.0] * len(scores)
    return [(s - mean) / std for s in scores]

def sigmoid_normalize(scores: List[float], temperature: float = 1.0) -> List[float]:
    return [1.0 / (1.0 + math.exp(-s / temperature)) for s in scores]
```

- **Min-Max**：适合分数范围已知且稳定的场景
- **Z-Score**：适合分数分布接近正态的场景
- **Sigmoid**：适合分数范围未知或动态变化的场景

## NDCG：排序评估的核心指标

准确率和召回率只适用于二分类，不适合排序场景。NDCG（Normalized Discounted Cumulative Gain）是搜索引擎最常用的指标。

```python
def compute_ndcg(relevance_labels: list, k: int = 10) -> float:
    def dcg(rels):
        return sum((2**r - 1) / math.log2(i + 2) for i, r in enumerate(rels[:k]))
    actual_dcg = dcg(relevance_labels)
    ideal_dcg = dcg(sorted(relevance_labels, reverse=True))
    return actual_dcg / ideal_dcg if ideal_dcg > 0 else 0.0

# [4, 3, 0, 2, 1] 接近完美排序
print(f"NDCG@5 = {compute_ndcg([4, 3, 0, 2, 1], 5):.4f}")  # 0.8916
# [0, 1, 2, 3, 4] 完全倒序
print(f"NDCG@5 = {compute_ndcg([0, 1, 2, 3, 4], 5):.4f}")  # 0.5761
```

NDCG 的核心思想：相关文档排得越靠前，得分越高。第 1 位的高相关文档贡献的增益是第 10 位的 3.5 倍。

## 常见误区

**只关注文本匹配。** BM25 分数高不代表真正相关，需要综合质量、时效等信号。

**过度依赖点击量。** 点击量存在位置偏差——排在前面的文档天然获得更多点击。

**权重随意调整。** 每次只改一个因子，通过 A/B 测试验证效果。

**忽视归一化。** 不同因子的分数范围差异大，直接加权会导致范围大的因子隐性地获得更高权重。

## 工程建议

- 建立评估数据集：收集人工标注的查询-文档相关性判断，至少几百个查询
- 使用 NDCG 作为核心指标：比准确率/召回率更适合评估排序质量
- 为后续 LTR 铺路：手动调权的因子将成为 Learning-to-Rank 的特征
- 记录每次调权：记录权重变更、原因和效果，便于回溯

### 练习一：文档长度惩罚

设计一个函数，对过短或过长的文档进行分数惩罚（使用高斯函数，设定理想长度）。

```python
def compute_length_penalty(doc: Document, ideal_length=200.0, sigma=150.0) -> float:
    doc_length = len(doc.body.split())
    deviation = doc_length - ideal_length
    return math.exp(-(deviation ** 2) / (2 * sigma ** 2))
```

### 练习二：排序调试工具

实现一个排序调试工具：给定查询和文档，输出每个因子的分数、归一化后的分数、加权贡献和最终分数。

```python
def debug_ranking(query: str, doc: Document, config: RankingConfig = None):
    config = config or RankingConfig()
    factors = {
        "text": (compute_text_score(query, doc), config.text_weight),
        "quality": (compute_quality_score(doc), config.quality_weight),
        "freshness": (compute_freshness_score(doc), config.freshness_weight),
        "popularity": (compute_popularity_score(doc), config.popularity_weight),
    }
    print(f"查询: {query}  文档: {doc.title}")
    total = 0.0
    for name, (raw, weight) in factors.items():
        weighted = raw * weight
        total += weighted
        print(f"  {name:12s}  原始={raw:8.4f}  权重={weight:.2f}  贡献={weighted:8.4f}")
    print(f"  {'最终分数':12s}  {total:8.4f}")
```

### 练习三

```python
def rank_with_normalized_factors(query, docs, config=None):
    config = config or RankingConfig()
    text_scores = [compute_text_score(query, doc) for doc in docs]
    quality_scores = [compute_quality_score(doc) for doc in docs]
    freshness_scores = [compute_freshness_score(doc) for doc in docs]
    popularity_scores = [compute_popularity_score(doc) for doc in docs]

    text_norm = min_max_normalize(text_scores)
    quality_norm = min_max_normalize(quality_scores)
    freshness_norm = min_max_normalize(freshness_scores)
    popularity_norm = min_max_normalize(popularity_scores)

    results = []
    for i, doc in enumerate(docs):
        score = (config.text_weight * text_norm[i]
                 + config.quality_weight * quality_norm[i]
                 + config.freshness_weight * freshness_norm[i]
                 + config.popularity_weight * popularity_norm[i])
        results.append((doc.doc_id, score))
    results.sort(key=lambda x: x[1], reverse=True)
    return results
```

归一化后各因子范围统一为 [0, 1]，权重的含义更直观——直接表示该因子对最终分数的贡献比例。
