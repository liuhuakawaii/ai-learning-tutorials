# 排序基础：搜索相关性与规则调权

## 场景引入

用户搜索"蓝牙耳机"，搜索引擎从倒排索引中召回了 500 个文档。哪些应该排在前面？这就是排序要解决的核心问题：**在召回的候选文档中，按相关性从高到低排列，把最可能满足用户需求的结果放在最前面。**

研究表明，超过 70% 的点击集中在前 3 条结果。一个糟糕的排序算法会让好内容被埋没，最终导致用户流失。Google 早期的排序算法 PageRank 之所以能击败 AltaVista、Yahoo 等竞争对手，核心原因就是排序质量的显著提升——它利用网页之间的链接关系作为质量信号，而不仅仅依赖关键词匹配。

排序（Ranking）是搜索引擎中最核心的模块之一。如果说召回（Retrieval）决定了"有没有机会被看到"，那么排序就决定了"能不能被用户点到"。在工业级搜索系统中，排序通常分为两个阶段：粗排（用简单模型快速筛选）和精排（用复杂模型精确打分）。本课聚焦于排序的基础——如何用人工设计的规则和因子组合来构建一个可用的排序系统。

## 学习目标

1. 理解搜索排序的本质——相关性建模
2. 掌握手动调权规则的设计方法
3. 实现基于多因子加权的排序系统
4. 理解字段权重、文档质量、时效性等常见排序因子
5. 掌握 NDCG 等排序评估指标的计算方法

## 1. 相关性的本质

相关性（Relevance）衡量的是用户查询意图与文档内容之间的匹配程度。它不是固定的数学公式，而是多维度的综合判断：语义匹配、意图匹配、质量信号、时效信号。

BM25 只考虑了文本匹配，忽略了文档质量、时效性、用户偏好、点击反馈等重要因素。排序需要综合这些信号。

### 1.1 相关性的多维度拆解

一个文档与查询的相关性可以从以下维度来衡量：

| 维度 | 含义 | 典型信号 |
|------|------|----------|
| 文本匹配 | 查询词是否出现在文档中 | BM25、TF-IDF、字段覆盖率 |
| 语义匹配 | 文档是否讨论了查询的主题 | 词向量相似度、BERT 语义分数 |
| 意图匹配 | 文档类型是否满足用户意图 | 导航型/信息型/交易型匹配 |
| 文档质量 | 文档本身是否是高质量内容 | PageRank、域名权威度、内容完整度 |
| 时效性 | 文档内容是否过时 | 发布时间、最近更新时间 |
| 用户行为 | 用户是否真的觉得它有用 | CTR、停留时间、跳出率 |

在实际搜索引擎中，排序模型需要综合这些维度。手动调权就是人工为每个维度分配权重，这是理解排序的起点。

### 1.2 为什么需要超越 BM25

BM25 的局限性体现在：

1. **只看词频，不看语义**：搜索"如何减肥"时，一篇标题为"科学瘦身指南"的高质量文章可能 BM25 分数很低
2. **不考虑文档质量**：垃圾站堆砌关键词可以拿到高 BM25 分数
3. **不考虑时效性**：一篇 2010 年的"最新手机推荐"在 BM25 看来可能分数很高
4. **不考虑用户偏好**：不同用户对同一查询的需求可能完全不同

这些局限促使搜索引擎引入更多排序因子，用加权组合或机器学习模型来替代单一的 BM25 分数。

## 2. 手动调权规则系统

基于规则的排序系统采用多因子加权求和的形式：

```
最终分数 = w1 × 文本相关性 + w2 × 文档质量 + w3 × 时效性 + w4 × 热度
```

这种方法在 2000 年代是搜索引擎的主流做法。即使在 LTR 普及的今天，手动调权仍然是理解排序系统的第一步，而且在资源有限的场景（如垂直搜索、内部搜索）中依然实用。

### 2.1 字段权重与文本分数

搜索引擎的文档通常有多个字段：标题（title）、正文（body）、锚文本（anchor_text）、URL 等。不同字段的匹配信号强度不同——标题出现查询词比正文中出现更能说明相关性。

```python
import math
from dataclasses import dataclass
from typing import List


@dataclass
class Document:
    doc_id: str
    title: str
    body: str
    anchor_text: str
    url: str
    publish_time: float
    page_rank: float = 0.0
    click_count: int = 0


FIELD_WEIGHTS = {"title": 3.0, "anchor_text": 2.0, "body": 1.0}


def compute_field_bm25(query: str, doc: Document, field: str) -> float:
    """计算单个字段的 BM25 分数。

    Args:
        query: 用户查询字符串
        doc: 文档对象
        field: 要计算分数的字段名

    Returns:
        该字段的 BM25 分数
    """
    text = getattr(doc, field, "")
    query_terms = query.lower().split()
    doc_terms = text.lower().split()
    doc_len = len(doc_terms)
    k1, b = 1.2, 0.75
    score = 0.0
    for term in query_terms:
        tf = doc_terms.count(term)
        if tf == 0:
            continue
        idf = math.log(1000 / (1 + tf))
        tf_norm = (tf * (k1 + 1)) / (tf + k1 * (1 - b + b * doc_len / 100))
        score += idf * tf_norm
    return score


def compute_text_score(query: str, doc: Document) -> float:
    """计算文档的综合文本分数，按字段权重加权求和。"""
    return sum(
        w * compute_field_bm25(query, doc, f)
        for f, w in FIELD_WEIGHTS.items()
    )
```

**字段权重的设计原则**：

- **标题权重最高**（通常 2-5 倍）：标题是对文档内容的精炼概括，标题匹配查询是强相关信号
- **锚文本权重较高**（通常 1.5-3 倍）：其他网站用什么文字链接到这个页面，反映了页面的主题
- **正文权重最低**（基准 1.0）：正文内容长，词频容易虚高，需要更多折损

字段权重的比值比绝对值更重要。如果标题权重是 3.0 而正文是 1.0，意味着标题中出现一次查询词等价于正文中出现三次。

### 2.2 文档质量、时效性与热度

```python
def compute_quality_score(doc: Document) -> float:
    """计算文档质量分数，综合 PageRank 和域名可信度。

    PageRank 值归一化到 [0, 1]，可信域名（.edu, .gov, .org）获得额外加成。
    """
    pr_score = min(doc.page_rank / 10.0, 1.0)
    trusted = [".edu", ".gov", ".org"]
    url_trust = 0.8 if any(d in doc.url for d in trusted) else 0.5
    return 0.7 * pr_score + 0.3 * url_trust


def compute_freshness_score(doc: Document, half_life_days: float = 30.0) -> float:
    """计算文档时效性分数，使用指数衰减模型。

    Args:
        doc: 文档对象
        half_life_days: 半衰期，经过这么多天后分数降为一半

    Returns:
        时效性分数，范围 (0, 1]
    """
    import time
    age_days = (time.time() - doc.publish_time) / 86400.0
    return math.exp(-math.log(2) / half_life_days * age_days)


def compute_popularity_score(doc: Document) -> float:
    """计算文档热度分数，使用对数归一化。

    使用对数是因为点击量分布通常遵循幂律分布，少数文档占据大量点击。
    """
    if doc.click_count <= 0:
        return 0.0
    return math.log(1 + doc.click_count) / math.log(1 + 100000)
```

**时效性模型的选择**：

指数衰减是最常用的时效性模型，但并非唯一选择。不同场景适合不同模型：

| 模型 | 公式 | 适用场景 |
|------|------|----------|
| 指数衰减 | $e^{-\lambda t}$ | 新闻搜索，内容快速过时 |
| 线性衰减 | $\max(0, 1 - t/T)$ | 活动搜索，有明确截止日期 |
| 阶梯函数 | 分段常数 | 知识搜索，内容长期有效 |
| 对数衰减 | $1 / (1 + \log(1+t))$ | 博客搜索，缓慢过时 |

半衰期的选择也要因场景而异：新闻搜索可能设为 1 天，商品搜索可能设为 90 天，知识搜索可能设为 365 天。

**热度分数的幂律特性**：

点击量通常遵循幂律分布：少数热门文档占据绝大部分点击。直接使用原始点击量会导致热门文档过度主导排序。对数函数将这种幂律分布压缩到更均匀的范围，使得中等热度的文档也能获得合理的分数。

### 2.3 综合排序

```python
@dataclass
class RankingConfig:
    text_weight: float = 0.45
    quality_weight: float = 0.25
    freshness_weight: float = 0.15
    popularity_weight: float = 0.15


def rank_documents(query: str, docs: List[Document], config: RankingConfig = None) -> List[tuple]:
    """对文档列表进行排序。

    Args:
        query: 查询字符串
        docs: 候选文档列表
        config: 排序权重配置

    Returns:
        按分数降序排列的 (doc_id, score) 列表
    """
    config = config or RankingConfig()
    results = []
    for doc in docs:
        score = (
            config.text_weight * compute_text_score(query, doc)
            + config.quality_weight * compute_quality_score(doc)
            + config.freshness_weight * compute_freshness_score(doc)
            + config.popularity_weight * compute_popularity_score(doc)
        )
        results.append((doc.doc_id, score))
    results.sort(key=lambda x: x[1], reverse=True)
    return results
```

**权重设计的经验法则**：

- 所有权重之和应为 1.0（方便理解和调整）
- 文本相关性通常是最大权重（0.3-0.5），因为它是排序的基础
- 质量权重通常排第二（0.15-0.3），防止低质量内容上浮
- 时效性和热度根据场景调整，新闻类时效性权重高，电商类热度权重高

### 2.4 完整示例

```python
import time


def demo():
    docs = [
        Document("1", "蓝牙耳机推荐 2024", "蓝牙耳机市场近年来发展迅速...", "",
                 "https://tech.example.com/earbuds", time.time() - 86400*3, 7.5, 15000),
        Document("2", "蓝牙耳机的工作原理", "蓝牙耳机利用蓝牙协议进行...", "",
                 "https://wiki.example.org/bluetooth", time.time() - 86400*365, 8.0, 50000),
        Document("3", "蓝牙耳机 蓝牙耳机 蓝牙耳机", "蓝牙耳机蓝牙耳机买...", "",
                 "https://spam.example.com/earbuds", time.time() - 86400, 0.5, 100),
    ]
    for doc_id, score in rank_documents("蓝牙耳机", docs):
        print(f"文档 {doc_id}: 分数 = {score:.4f}")
```

运行结果分析：

- 文档 1 标题包含查询词、时效性高（3 天前发布）、有一定点击量，综合分数最高
- 文档 2 虽然 PageRank 高、点击量大，但已发布一年，时效性拉低了分数
- 文档 3 标题堆砌关键词、PageRank 极低、点击量少，虽然时效性高但质量分数很低

这个例子展示了多因子综合排序如何压制垃圾内容、提升优质内容。

## 3. 分场景调权

不同搜索场景需要不同的权重配置：

```python
SCENARIO_CONFIGS = {
    "新闻搜索": RankingConfig(text_weight=0.30, quality_weight=0.20,
                              freshness_weight=0.40, popularity_weight=0.10),
    "知识问答": RankingConfig(text_weight=0.40, quality_weight=0.40,
                              freshness_weight=0.05, popularity_weight=0.15),
    "商品搜索": RankingConfig(text_weight=0.35, quality_weight=0.15,
                              freshness_weight=0.10, popularity_weight=0.40),
}
```

### 3.1 场景权重设计的推理过程

**新闻搜索**：时效性权重最高（0.40）。一篇昨天的新闻远比一周前的有价值。质量权重适中（0.20）防止自媒体假新闻上浮。热度权重低（0.10）因为新闻热度变化快，昨天的热门今天可能已过时。

**知识问答**：质量权重最高（0.40）。用户搜"如何配置 Nginx"需要准确可靠的教程，质量比时效重要得多。时效性权重极低（0.05）因为技术知识相对稳定。

**商品搜索**：热度权重最高（0.40）。用户搜"蓝牙耳机"时，销量高、评价多的商品通常更值得推荐。质量权重低（0.15）因为商品页面质量差异不大。

### 3.2 查询类型自动识别

实际系统中，需要自动判断查询类型并选择对应的权重配置：

```python
def detect_query_type(query: str) -> str:
    """自动识别查询类型。

    导航型：用户想访问特定网站（如"淘宝官网"）
    信息型：用户想获取信息（如"如何学习编程"）
    交易型：用户想完成交易（如"买 iPhone 15"）
    """
    q = query.lower()

    # 导航型特征：包含域名、品牌名 + 官网
    nav_indicators = [".com", ".cn", ".net", "官网", "首页", "官方"]
    if any(ind in q for ind in nav_indicators):
        return "navigational"

    # 交易型特征：包含购买意图词
    trans_indicators = ["买", "购买", "价格", "优惠", "折扣", "商城", "下单", "多少钱"]
    if any(w in q for w in trans_indicators):
        return "transactional"

    # 信息型特征：包含疑问词
    info_indicators = ["怎么", "如何", "为什么", "什么是", "教程", "攻略", "方法"]
    if any(w in q for w in info_indicators):
        return "informational"

    return "informational"  # 默认为信息型


def get_scenario_config(query: str) -> RankingConfig:
    """根据查询类型返回对应的排序配置。"""
    qtype = detect_query_type(query)
    configs = {
        "navigational": RankingConfig(text_weight=0.60, quality_weight=0.25,
                                      freshness_weight=0.05, popularity_weight=0.10),
        "informational": RankingConfig(text_weight=0.40, quality_weight=0.35,
                                       freshness_weight=0.10, popularity_weight=0.15),
        "transactional": RankingConfig(text_weight=0.30, quality_weight=0.15,
                                       freshness_weight=0.10, popularity_weight=0.45),
    }
    return configs.get(qtype, RankingConfig())
```

导航型查询的文本权重最高（0.60），因为用户明确要找某个网站，精确匹配最重要。交易型查询的热度权重最高（0.45），因为用户要买东西，热销商品更值得推荐。

## 4. 排序分数的归一化与组合

在实际系统中，不同因子的分数范围可能差异巨大（BM25 可能是 0-20，PageRank 是 0-10，CTR 是 0-1）。直接加权求和会导致范围大的因子主导结果。

### 4.1 Min-Max 归一化

```python
def min_max_normalize(scores: List[float]) -> List[float]:
    """将分数归一化到 [0, 1] 范围。"""
    if not scores:
        return []
    min_s, max_s = min(scores), max(scores)
    if max_s == min_s:
        return [0.5] * len(scores)
    return [(s - min_s) / (max_s - min_s) for s in scores]
```

### 4.2 Z-Score 归一化

```python
def zscore_normalize(scores: List[float]) -> List[float]:
    """Z-Score 归一化，均值为 0，标准差为 1。"""
    if not scores:
        return []
    mean = sum(scores) / len(scores)
    std = (sum((s - mean) ** 2 for s in scores) / len(scores)) ** 0.5
    if std == 0:
        return [0.0] * len(scores)
    return [(s - mean) / std for s in scores]
```

### 4.3 Sigmoid 归一化

```python
def sigmoid_normalize(scores: List[float], temperature: float = 1.0) -> List[float]:
    """Sigmoid 归一化，将任意范围的分数映射到 (0, 1)。

    temperature 控制曲线的陡峭程度，值越大区分度越高。
    """
    return [1.0 / (1.0 + math.exp(-s / temperature)) for s in scores]
```

**选择哪种归一化方法？**

- **Min-Max**：适合分数范围已知且稳定的场景，简单直观
- **Z-Score**：适合分数分布接近正态的场景，对异常值敏感
- **Sigmoid**：适合分数范围未知或动态变化的场景，天然有界

## 5. 排序评估指标：NDCG 深入理解

在调整排序权重时，我们需要量化指标来衡量排序质量。准确率和召回率只适用于二分类，不适合排序场景。搜索引擎最常用的指标是 NDCG（Normalized Discounted Cumulative Gain）。

### 5.1 CG 与 DCG 的演进

**累积增益（CG）**：简单累加每个位置的相关性分数。

$$\text{CG@k} = \sum_{i=1}^{k} \text{rel}_i$$

CG 的问题：不考虑位置。一个排列 [3, 0, 0] 和 [0, 0, 3] 的 CG@3 相同，但前者显然更好。

**折扣累积增益（DCG）**：引入对数折损，位置越靠后增益越小。

$$\text{DCG@k} = \sum_{i=1}^{k} \frac{2^{\text{rel}_i} - 1}{\log_2(i + 1)}$$

对数折损的设计含义：第 1 位的折损系数为 1.0，第 2 位为 0.631，第 5 位为 0.387，第 10 位为 0.289。这意味着第 1 位的高相关文档贡献的增益是第 10 位的 3.5 倍。

**归一化折扣累积增益（NDCG）**：DCG 除以理想排序的 DCG，归一化到 [0, 1]。

$$\text{NDCG@k} = \frac{\text{DCG@k}}{\text{IDCG@k}}$$

```python
def compute_ndcg(relevance_labels: list, k: int = 10) -> float:
    """计算 NDCG@k。

    Args:
        relevance_labels: 按当前排序排列的相关性标签（0-4）
        k: 截断位置

    Returns:
        NDCG@k 值，范围 [0, 1]

    示例：
        >>> compute_ndcg([4, 3, 0, 2, 1], k=5)
        0.8916  # 接近完美排序
        >>> compute_ndcg([0, 1, 2, 3, 4], k=5)
        0.5761  # 完全倒序
    """
    def dcg(rels):
        return sum((2**r - 1) / math.log2(i + 2) for i, r in enumerate(rels[:k]))

    actual_dcg = dcg(relevance_labels)
    ideal_dcg = dcg(sorted(relevance_labels, reverse=True))
    return actual_dcg / ideal_dcg if ideal_dcg > 0 else 0.0
```

### 5.2 NDCG 与其他指标的对比

| 指标 | 适用场景 | 优点 | 缺点 |
|------|----------|------|------|
| NDCG | 多级相关性排序 | 考虑位置和相关性等级 | 需要多级标注 |
| MAP | 二元相关性 | 简单直观 | 只区分相关/不相关 |
| MRR | 第一个正确结果的位置 | 关注头部质量 | 忽略其他位置 |
| ERR | 级联模型 | 模拟用户浏览行为 | 计算较复杂 |

## 6. 常见误区

1. **只关注文本匹配**：BM25 分数高不代表真正相关，需要综合质量、时效等信号
2. **过度依赖点击量**：点击量存在位置偏差，排在前面的文档天然获得更多点击
3. **权重随意调整**：每次只改一个因子，通过 A/B 测试验证效果
4. **混淆相关性和质量**：高质量文档不一定与当前查询相关
5. **忽视归一化**：不同因子的分数范围差异大，直接加权会导致范围大的因子主导
6. **盲目照搬别人的权重**：不同业务场景、不同数据分布下的最优权重差异很大
7. **不做线上验证**：离线评估指标好不代表用户体验好，必须做 A/B 测试

## 7. 工程建议

1. **建立评估数据集**：收集人工标注的查询-文档相关性判断，作为调权基准。至少需要几百个查询，每个查询 10-20 个标注文档，标注者之间一致性（Cohen's Kappa）应达到 0.6 以上。
2. **使用 NDCG 作为核心指标**：比准确率/召回率更适合评估排序质量。NDCG@5 关注头部质量，NDCG@10 关注整体质量，建议同时监控两个指标。
3. **渐进式调整**：每次只调整一个权重，观察线上指标变化。权重调整的幅度建议从 ±0.05 开始，避免剧烈波动。
4. **为后续 LTR 铺路**：手动调权的因子将成为 Learning-to-Rank 的特征。在设计因子时就考虑好特征的可计算性和区分度。
5. **记录每次调权**：记录权重变更、原因和效果，便于回溯和复盘。建议使用版本控制管理权重配置。
6. **分场景调权**：不同查询类型、不同业务线使用不同权重配置。例如电商搜索中，商品类目不同权重也应该不同。
7. **监控排序质量**：定期抽样检查排序结果，发现退化及时回滚。建立排序质量看板，监控 NDCG、点击率、无结果率等指标。
8. **考虑计算成本**：每个因子都有计算开销。BM25 需要遍历倒排列表，PageRank 需要预计算。在线排序阶段要控制因子数量和计算复杂度，通常精排阶段使用 20-50 个因子。
9. **处理边界情况**：新文档没有点击数据和 PageRank，需要用默认值或内容质量信号替代。冷启动查询没有历史行为数据，需要依赖文本匹配和文档质量。
10. **A/B 测试框架**：每次排序策略变更都需要通过 A/B 测试验证。分流应基于用户维度而非查询维度，避免同一用户看到不一致的排序结果。

## 小结

本课介绍了搜索排序的基础：相关性是多维度概念，手动调权通过组合文本、质量、时效、热度等因子得到排序分数。手动调权的局限在于因子组合是线性的、权重靠人工经验，下一课我们将学习 Learning-to-Rank，让机器自动学习最优排序函数。

### 练习一

**思路**：使用高斯函数，设定理想长度 ideal_length，偏离越远惩罚越大。

```python
def compute_length_penalty(doc: Document, ideal_length=200.0, sigma=150.0) -> float:
    """计算文档长度惩罚因子。

    Args:
        doc: 文档对象
        ideal_length: 理想文档长度（词数）
        sigma: 高斯函数的标准差，控制惩罚的宽容度

    Returns:
        惩罚因子，范围 (0, 1]，越接近 1 表示越接近理想长度
    """
    doc_length = len(doc.body.split())
    deviation = doc_length - ideal_length
    return math.exp(-(deviation ** 2) / (2 * sigma ** 2))
```

**要点**：sigma 太小会过度惩罚正常文档，ideal_length 应从语料库统计得出。实际工程中，可以统计查询日志中被点击文档的长度分布，取中位数或均值作为 ideal_length。

### 练习二

**思路**：通过查询词模式判断类型——包含域名词为导航型，包含购买词为交易型，包含疑问词为信息型。

```python
def classify_query(query: str) -> str:
    """识别查询类型。

    返回值: "navigational"（导航型）、"transactional"（交易型）、"informational"（信息型）
    """
    q = query.lower()
    if any(ind in q for ind in [".com", ".cn", "官网", "首页"]):
        return "navigational"
    if any(w in q for w in ["买", "价格", "优惠", "商城"]):
        return "transactional"
    if any(w in q for w in ["怎么", "如何", "为什么", "教程"]):
        return "informational"
    return "informational"
```

**要点**：导航型查询最重要的是精确匹配（text_weight 最高），交易型受用户行为影响大。实际系统中，查询类型识别可以用机器学习模型来做，特征包括查询词、查询长度、是否包含 URL 等。

### 练习三

**思路**：DCG 使用对数折损，NDCG = DCG / IDCG（理想排序的 DCG）。

```python
def ndcg_at_k(relevance_scores, k=5):
    """计算 NDCG@k。

    Args:
        relevance_scores: 按排序结果排列的相关性标签列表
        k: 截断位置

    Returns:
        NDCG@k 值，范围 [0, 1]
    """
    def dcg(rels):
        return sum((2**r - 1) / math.log2(i + 2) for i, r in enumerate(rels[:k]))
    return dcg(relevance_scores) / dcg(sorted(relevance_scores, reverse=True))
```

**要点**：NDCG 归一化后在 0-1 之间，人工标注质量直接影响其可靠性。NDCG 是排序任务中最常用的指标，因为它既考虑了相关性等级（高相关文档的增益更大），又考虑了位置（排在后面的文档对数折损更大）。

### 练习四

**思路**：对每个因子独立做 Min-Max 归一化，然后加权求和。

```python
def rank_with_normalized_factors(query: str, docs: List[Document],
                                  config: RankingConfig = None) -> List[tuple]:
    """先归一化每个因子，再加权求和。"""
    config = config or RankingConfig()

    # 计算原始分数
    text_scores = [compute_text_score(query, doc) for doc in docs]
    quality_scores = [compute_quality_score(doc) for doc in docs]
    freshness_scores = [compute_freshness_score(doc) for doc in docs]
    popularity_scores = [compute_popularity_score(doc) for doc in docs]

    # 分别归一化
    text_norm = min_max_normalize(text_scores)
    quality_norm = min_max_normalize(quality_scores)
    freshness_norm = min_max_normalize(freshness_scores)
    popularity_norm = min_max_normalize(popularity_scores)

    # 加权求和
    results = []
    for i, doc in enumerate(docs):
        score = (
            config.text_weight * text_norm[i]
            + config.quality_weight * quality_norm[i]
            + config.freshness_weight * freshness_norm[i]
            + config.popularity_weight * popularity_norm[i]
        )
        results.append((doc.doc_id, score))
    results.sort(key=lambda x: x[1], reverse=True)
    return results
```

**要点**：归一化后各因子范围统一为 [0, 1]，权重的含义更直观——直接表示该因子对最终分数的贡献比例。不归一化时，范围大的因子会隐性地获得更高权重。

### 练习五

**思路**：计算并输出每个因子的详细信息，便于调试和理解。

```python
def debug_ranking(query: str, doc: Document, config: RankingConfig = None):
    """排序调试工具，输出每个因子的详细分数。"""
    config = config or RankingConfig()

    factors = {
        "text": (compute_text_score(query, doc), config.text_weight),
        "quality": (compute_quality_score(doc), config.quality_weight),
        "freshness": (compute_freshness_score(doc), config.freshness_weight),
        "popularity": (compute_popularity_score(doc), config.popularity_weight),
    }

    print(f"查询: {query}")
    print(f"文档: {doc.title}")
    print("-" * 50)
    total = 0.0
    for name, (raw, weight) in factors.items():
        weighted = raw * weight
        total += weighted
        print(f"  {name:12s}  原始={raw:8.4f}  权重={weight:.2f}  贡献={weighted:8.4f}")
    print("-" * 50)
    print(f"  {'最终分数':12s}  {total:8.4f}")

    return total
```

**要点**：调试工具对排查排序问题至关重要。线上系统通常会记录每个因子的分数，当用户投诉"为什么这个结果排在前面"时，可以通过因子分析定位原因。
