# 个性化排序：千人千面的搜索体验

## 场景引入

两个用户同时搜索"苹果"。用户 A 是果农，期望看到苹果种植技术；用户 B 是科技爱好者，期望看到 Apple 公司的产品。传统排序对这两个用户返回完全相同的结果，但他们的需求截然不同。

个性化排序的目标是：**根据用户的历史行为、兴趣偏好和当前上下文，为不同用户提供不同的排序结果。** 它是搜索引擎从"通用排序"进化到"千人千面"的关键技术。

个性化排序的研究始于 2000 年代初。早期的个性化方法主要基于用户搜索历史和点击历史，通过简单的关键词匹配来推断用户兴趣。随着深度学习的发展，现代个性化系统可以建模用户的长期兴趣、短期兴趣、上下文状态等多维度信息。

但个性化并非万能。Google 在 2010 年代的研究发现，只有约 30% 的搜索查询适合个性化处理。对于客观事实类查询（如"今天天气"、"美元汇率"），所有用户的需求是一致的，个性化反而可能引入噪声。个性化的核心价值在于处理歧义查询（如"苹果"）和偏好查询（如"好的编程教程"——初学者和专家的需求不同）。

## 学习目标

1. 理解个性化排序的核心挑战和基本框架
2. 掌握用户画像的构建方法
3. 实现基于行为序列的用户兴趣建模
4. 将协同过滤应用于搜索排序
5. 理解个性化的边界和伦理问题

## 1. 用户画像构建

用户画像是个性化排序的基础。它从用户的历史行为中提取兴趣特征，用于调整排序结果。

```python
from dataclasses import dataclass, field
from typing import List, Dict
from collections import defaultdict
import time, math


@dataclass
class UserProfile:
    """用户画像。"""
    user_id: str
    search_history: List[str] = field(default_factory=list)
    click_history: List[Dict] = field(default_factory=list)
    category_interests: Dict[str, float] = field(default_factory=dict)


CATEGORY_TAXONOMY = {
    "科技": ["编程", "Python", "AI", "人工智能", "机器学习", "代码", "算法", "深度学习"],
    "购物": ["买", "价格", "优惠", "推荐", "品牌", "评测", "性价比"],
    "美食": ["菜谱", "做法", "餐厅", "好吃", "美食", "烹饪", "食材"],
    "旅行": ["旅游", "攻略", "酒店", "机票", "景点", "签证", "自由行"],
    "健康": ["运动", "减肥", "养生", "医疗", "锻炼", "营养", "睡眠"],
    "娱乐": ["电影", "音乐", "游戏", "综艺", "小说", "动漫"],
    "教育": ["学习", "课程", "考试", "培训", "学历", "考研"],
}


def build_search_profile(user: UserProfile, taxonomy=CATEGORY_TAXONOMY) -> Dict[str, float]:
    """从搜索历史构建用户兴趣画像，使用时间衰减。

    越近期的搜索记录权重越高，使用指数衰减。
    """
    scores = defaultdict(float)
    n = len(user.search_history)
    for i, query in enumerate(user.search_history):
        recency = 0.9 ** (n - 1 - i)  # 指数衰减，越新的记录权重越高
        for cat, keywords in taxonomy.items():
            if any(kw in query for kw in keywords):
                scores[cat] += recency
    total = sum(scores.values())
    return {c: s / total for c, s in scores.items()} if total > 0 else dict(scores)
```

### 1.1 长期兴趣 vs 短期兴趣

用户兴趣可以分为长期兴趣和短期兴趣：

| 类型 | 特征 | 更新频率 | 示例 |
|------|------|----------|------|
| 长期兴趣 | 稳定、跨 session | 天/周 | 一个程序员对"编程"的持续关注 |
| 短期兴趣 | 波动、session 内 | 分钟/小时 | 用户最近在搜索"旅行攻略" |

```python
def build_long_term_profile(user: UserProfile, half_life_days=30) -> Dict[str, float]:
    """构建长期兴趣画像，使用较长的时间衰减。"""
    scores = defaultdict(float)
    now = time.time()
    for click in user.click_history:
        age_days = (now - click.get("timestamp", now)) / 86400.0
        weight = math.exp(-math.log(2) / half_life_days * age_days)
        cat = click.get("category")
        if cat:
            scores[cat] += weight
    total = sum(scores.values())
    return {c: s / total for c, s in scores.items()} if total > 0 else {}


def build_short_term_profile(user: UserProfile, window_minutes=30) -> Dict[str, float]:
    """构建短期兴趣画像，只考虑最近 window_minutes 分钟的行为。"""
    scores = defaultdict(float)
    now = time.time()
    cutoff = now - window_minutes * 60
    for click in user.click_history:
        if click.get("timestamp", now) >= cutoff:
            cat = click.get("category")
            if cat:
                scores[cat] += 1.0
    total = sum(scores.values())
    return {c: s / total for c, s in scores.items()} if total > 0 else {}
```

## 2. 行为序列建模

### 2.1 Session 意图识别

用户的搜索行为通常按 session 组织。一个 session 内的查询序列反映了用户的当前意图。

```python
def detect_session_intent(query_sequence, time_gaps, taxonomy, gap_threshold=300):
    """将查询序列分割为 session 并识别意图。

    Args:
        query_sequence: 用户的查询序列
        time_gaps: 相邻查询之间的时间间隔（秒）
        taxonomy: 类别关键词表
        gap_threshold: session 分割的时间阈值（秒），默认 5 分钟

    Returns:
        list of (session_queries, intent_category)
    """
    sessions, current = [], [query_sequence[0]]
    for i in range(1, len(query_sequence)):
        if i - 1 < len(time_gaps) and time_gaps[i - 1] > gap_threshold:
            sessions.append(current)
            current = [query_sequence[i]]
        else:
            current.append(query_sequence[i])
    sessions.append(current)

    results = []
    for session in sessions:
        counts = defaultdict(int)
        for q in session:
            for cat, kws in taxonomy.items():
                if any(kw in q for kw in kws):
                    counts[cat] += 1
        intent = max(counts, key=counts.get) if counts else "通用"
        results.append((" → ".join(session), intent))
    return results
```

### 2.2 查询细化模式识别

用户在 session 中的查询变化模式反映了不同的搜索策略：

```python
def detect_query_refinement_pattern(query_sequence):
    """识别查询细化模式。

    Returns:
        "specialization"（从泛到专）、"generalization"（从专到泛）、
        "lateral"（平级切换）、"reformulation"（重新表述）
    """
    if len(query_sequence) < 2:
        return "single_query"

    patterns = []
    for i in range(1, len(query_sequence)):
        prev_terms = set(query_sequence[i-1].lower().split())
        curr_terms = set(query_sequence[i].lower().split())

        if prev_terms < curr_terms:
            patterns.append("specialization")  # 新查询包含旧查询的所有词
        elif prev_terms > curr_terms:
            patterns.append("generalization")  # 新查询是旧查询的子集
        elif prev_terms & curr_terms:
            patterns.append("lateral")         # 有重叠但不是子集关系
        else:
            patterns.append("reformulation")   # 完全不同的表述

    # 返回最常见的模式
    from collections import Counter
    return Counter(patterns).most_common(1)[0][0]
```

### 2.3 短期兴趣

```python
def compute_short_term_interest(recent_clicks, doc_categories, window=10):
    """基于最近 N 次点击计算短期兴趣。"""
    scores = defaultdict(float)
    recent = recent_clicks[-window:]
    for i, click in enumerate(recent):
        cat = doc_categories.get(click["doc_id"])
        if cat:
            scores[cat] += (i + 1) / len(recent)  # 越新的点击权重越高
    total = sum(scores.values())
    return {c: s / total for c, s in scores.items()} if total > 0 else {}
```

## 3. 协同过滤

协同过滤利用"相似用户有相似兴趣"的假设，从其他用户的行为中推断目标用户的偏好。

```python
class CollaborativeFilter:
    """基于用户的协同过滤。"""

    def __init__(self):
        self.user_clicks = defaultdict(set)

    def add_click(self, user_id, doc_id):
        self.user_clicks[user_id].add(doc_id)

    def find_similar_users(self, target, top_k=10):
        """找到与目标用户最相似的用户。"""
        target_docs = self.user_clicks.get(target, set())
        if not target_docs:
            return []
        sims = []
        for other, other_docs in self.user_clicks.items():
            if other == target:
                continue
            inter = len(target_docs & other_docs)
            union = len(target_docs | other_docs)
            if union > 0:
                sims.append((other, inter / union))  # Jaccard 相似度
        return sorted(sims, key=lambda x: -x[1])[:top_k]

    def recommend_docs(self, target, top_k=20):
        """为目标用户推荐文档。"""
        similar = self.find_similar_users(target, 50)
        target_docs = self.user_clicks.get(target, set())
        scores = defaultdict(float)
        for user, sim in similar:
            for doc in self.user_clicks[user]:
                if doc not in target_docs:
                    scores[doc] += sim
        return sorted(scores.items(), key=lambda x: -x[1])[:top_k]
```

### 3.1 协同过滤的变体

```python
class ItemBasedCF:
    """基于物品的协同过滤。

    计算文档之间的相似度，然后用用户历史点击的文档推荐相似文档。
    """

    def __init__(self):
        self.user_clicks = defaultdict(set)
        self.doc_users = defaultdict(set)

    def add_click(self, user_id, doc_id):
        self.user_clicks[user_id].add(doc_id)
        self.doc_users[doc_id].add(user_id)

    def compute_doc_similarity(self, doc_a, doc_b):
        """计算两个文档的相似度（基于共同点击用户）。"""
        users_a = self.doc_users.get(doc_a, set())
        users_b = self.doc_users.get(doc_b, set())
        inter = len(users_a & users_b)
        union = len(users_a | users_b)
        return inter / union if union > 0 else 0

    def recommend_for_user(self, user_id, top_k=20):
        """基于用户历史推荐相似文档。"""
        user_docs = self.user_clicks.get(user_id, set())
        scores = defaultdict(float)
        for doc in self.doc_users:
            if doc in user_docs:
                continue
            for user_doc in user_docs:
                sim = self.compute_doc_similarity(doc, user_doc)
                scores[doc] += sim
        return sorted(scores.items(), key=lambda x: -x[1])[:top_k]
```

## 4. 完整个性化排序系统

```python
@dataclass
class PersonalizedRankingConfig:
    base_weight: float = 0.60      # 基础相关性权重
    profile_weight: float = 0.20   # 长期兴趣权重
    cf_weight: float = 0.10        # 协同过滤权重
    short_term_weight: float = 0.10  # 短期兴趣权重


class PersonalizedRanker:
    """个性化排序器，综合基础分数、用户画像、协同过滤和短期兴趣。"""

    def __init__(self, config=None):
        self.config = config or PersonalizedRankingConfig()
        self.cf = CollaborativeFilter()
        self.doc_categories = {}

    def rank(self, query, candidates, user, base_scores):
        """对候选文档进行个性化排序。

        Args:
            query: 查询字符串
            candidates: 候选文档 ID 列表
            user: 用户画像
            base_scores: 基础排序分数（如 BM25 + LTR 分数）

        Returns:
            按个性化分数降序排列的 (doc_id, score) 列表
        """
        profile = build_search_profile(user)
        short_term = compute_short_term_interest(user.click_history, self.doc_categories)

        cf_recs = dict(self.cf.recommend_docs(user.user_id))
        max_cf = max(cf_recs.values()) if cf_recs else 1.0

        cfg = self.config
        results = []
        for doc in candidates:
            cat = self.doc_categories.get(doc)
            final = (
                cfg.base_weight * base_scores.get(doc, 0)
                + cfg.profile_weight * profile.get(cat, 0)
                + cfg.cf_weight * (cf_recs.get(doc, 0) / max_cf if max_cf else 0)
                + cfg.short_term_weight * short_term.get(cat, 0)
            )
            results.append((doc, final))
        return sorted(results, key=lambda x: -x[1])
```

### 4.2 权重调整策略

不同查询类型需要不同的个性化权重：

```python
def get_personalization_weight(query_type: str, user_confidence: float) -> PersonalizedRankingConfig:
    """根据查询类型和用户置信度调整个性化权重。

    Args:
        query_type: 查询类型（"informational", "navigational", "transactional"）
        user_confidence: 用户画像置信度（0-1），取决于历史数据量

    Returns:
        个性化排序配置
    """
    # 基础配置
    configs = {
        "informational": PersonalizedRankingConfig(0.55, 0.25, 0.10, 0.10),
        "navigational": PersonalizedRankingConfig(0.80, 0.10, 0.05, 0.05),
        "transactional": PersonalizedRankingConfig(0.50, 0.20, 0.15, 0.15),
    }
    config = configs.get(query_type, PersonalizedRankingConfig())

    # 根据用户置信度缩放个性化权重
    if user_confidence < 0.3:
        # 新用户，减少个性化权重
        scale = user_confidence / 0.3
        config.profile_weight *= scale
        config.cf_weight *= scale
        config.short_term_weight *= scale
        config.base_weight = 1.0 - config.profile_weight - config.cf_weight - config.short_term_weight

    return config
```

### 5.1 信息茧房问题

信息茧房（Filter Bubble）是指个性化系统只展示用户已知领域的内容，限制了用户接触新信息的机会。

```python
def add_exploration_factor(ranked_results, exploration_ratio=0.1):
    """在排序结果中注入探索性内容。

    Args:
        ranked_results: 个性化排序结果
        exploration_ratio: 探索性内容的比例

    Returns:
        调整后的排序结果
    """
    n_explore = max(1, int(len(ranked_results) * exploration_ratio))
    # 从排名较低的结果中随机选择一些插入到中间位置
    explore_pool = ranked_results[int(len(ranked_results) * 0.5):]
    if len(explore_pool) < n_explore:
        return ranked_results

    import random
    explore_items = random.sample(explore_pool, n_explore)
    result = list(ranked_results[:len(ranked_results) - n_explore])

    # 均匀插入探索性内容
    interval = len(result) // (n_explore + 1)
    for i, item in enumerate(explore_items):
        insert_pos = interval * (i + 1)
        result.insert(insert_pos, item)

    return result
```

### 5.3 个性化开关

```python
class PersonalizationController:
    """个性化控制器，支持用户开关个性化。"""

    def __init__(self):
        self.disabled_users = set()

    def disable(self, user_id):
        self.disabled_users.add(user_id)

    def enable(self, user_id):
        self.disabled_users.discard(user_id)

    def is_enabled(self, user_id):
        return user_id not in self.disabled_users

    def rank(self, user_id, query, candidates, user, base_scores, ranker):
        """根据个性化开关决定是否应用个性化。"""
        if not self.is_enabled(user_id):
            # 退化为通用排序
            return sorted(candidates, key=lambda d: -base_scores.get(d, 0))
        return ranker.rank(query, candidates, user, base_scores)
```

## 6. 冷启动策略

新用户没有历史数据，是个性化排序的最大挑战之一。

```python
def cold_start_strategy(user, candidates, base_scores, doc_categories, taxonomy):
    """冷启动策略：根据可用信息逐步升级个性化程度。"""

    # 策略 1：完全通用排序
    if not user.search_history and not user.click_history:
        return sorted(candidates, key=lambda d: -base_scores.get(d, 0))

    # 策略 2：基于当前 session 的即时个性化
    if user.search_history and not user.click_history:
        intent = next(
            (c for c, kws in taxonomy.items()
             if any(k in user.search_history[-1] for k in kws)),
            None
        )
        if intent:
            return sorted(candidates, key=lambda d: -(
                base_scores.get(d, 0) + (0.15 if doc_categories.get(d) == intent else 0)
            ))

    # 策略 3：基于少量历史的轻量个性化
    profile = build_search_profile(user)
    return sorted(candidates, key=lambda d: -(
        0.8 * base_scores.get(d, 0) + 0.2 * profile.get(doc_categories.get(d, ""), 0)
    ))
```

## 7. 常见误区

1. **过度个性化**：不是所有查询都需要个性化，客观类查询应保持通用排序
2. **忽视短期兴趣**：只用长期画像会错过用户当前即时需求
3. **冷启动处理不当**：新用户应退化为通用排序，而非随机排序
4. **混淆相关性和个性化**：个性化是在相关性基础上的增强，不能替代相关性
5. **忽视隐私合规**：GDPR 等法规对用户数据使用有严格限制
6. **不做 A/B 测试**：个性化效果必须通过线上实验验证

## 8. 工程建议

1. **渐进式个性化**：先对高置信度兴趣做个性化，逐步扩大范围
2. **A/B 测试必不可少**：个性化效果必须通过线上实验验证
3. **画像实时更新**：用户即时兴趣变化快，画像需要流式更新
4. **设置个性化开关**：给用户关闭个性化的选项
5. **监控个性化覆盖率**：跟踪有多少查询应用了个性化，效果如何
6. **定期清理过期画像**：用户兴趣会变化，过期数据会引入噪声

## 小结

本课介绍了个性化排序：用户画像从搜索和点击历史中提取长期兴趣，行为序列建模捕获即时需求，协同过滤利用相似用户增强排序。个性化不是万能的，客观类查询不需要个性化，过度个性化会导致信息茧房。下一课我们将进入阶段实战。

### 练习一

**思路**：用带 TTL 的字典存储，get 时惰性清理过期条目。

```python
class UserProfileStore:
    """带 TTL 的用户画像存储。"""

    def __init__(self, default_ttl=86400*30):
        self._store = {}
        self.default_ttl = default_ttl

    def get(self, user_id):
        """读取用户画像，过期返回 None。"""
        entry = self._store.get(user_id)
        if entry and time.time() > entry[1]:
            del self._store[user_id]
            return None
        return entry[0] if entry else None

    def set(self, user_id, profile, ttl=None):
        """存储用户画像，设置过期时间。"""
        self._store[user_id] = (profile, time.time() + (ttl or self.default_ttl))

    def cleanup_expired(self):
        """清理所有过期条目，返回清理数量。"""
        now = time.time()
        expired = [uid for uid, (_, exp) in self._store.items() if now > exp]
        for uid in expired:
            del self._store[uid]
        return len(expired)

    def update(self, user_id, profile, ttl=None):
        """更新用户画像，重置过期时间。"""
        self.set(user_id, profile, ttl)
```

**要点**：TTL 防止存储无限增长，get 时惰性清理，cleanup_expired 适合定时任务。活跃用户的 TTL 应该比不活跃用户更长。

```python
def evaluate_personalization(users, ranker, base_scores, candidates):
    """用留一法评估个性化排序效果。"""
    p_hits = b_hits = total = 0
    for user in users:
        if len(user.click_history) < 2:
            continue
        test_doc = user.click_history[-1]["doc_id"]
        train_user = UserProfile(user.user_id, user.search_history, user.click_history[:-1])
        if test_doc not in candidates:
            continue
        p_rank = next((i for i, (d, _) in enumerate(
            ranker.rank(user.search_history[-1], candidates, train_user, base_scores)) if d == test_doc), 99)
        b_rank = next((i for i, (d, _) in enumerate(
            sorted(base_scores.items(), key=lambda x: -x[1])) if d == test_doc), 99)
        if p_rank < 5: p_hits += 1
        if b_rank < 5: b_hits += 1
        total += 1
    print(f"个性化: {p_hits/total:.4f}, 通用: {b_hits/total:.4f}")
```

**要点**：留一法是评估推荐系统的标准离线方法，最终需 A/B 测试验证。离线评估和在线评估可能不一致，因为离线评估无法捕获用户对新排序结果的反应。

### 练习三

**思路**：三种策略递进——通用排序最安全，注册信息有隐私风险，即时个性化最实时。

```python
def strategy_generic(candidates, base_scores):
    """策略 1：通用排序。"""
    return sorted(candidates, key=lambda d: -base_scores.get(d, 0))

def strategy_registered(user_reg, candidates, doc_cats, base_scores):
    """策略 2：基于注册信息的轻量个性化。"""
    boosts = {"北京": {"美食": 0.1}, "上海": {"购物": 0.1}}
    region = user_reg.get("region", "")
    return sorted(candidates, key=lambda d: -(base_scores.get(d, 0)
                  + boosts.get(region, {}).get(doc_cats.get(d, ""), 0)))

def strategy_instant(first_query, candidates, taxonomy, base_scores, doc_cats):
    """策略 3：基于当前查询的即时个性化。"""
    intent = next((c for c, kws in taxonomy.items() if any(k in first_query for k in kws)), None)
    return sorted(candidates, key=lambda d: -(base_scores.get(d, 0)
                  + (0.15 if intent and doc_cats.get(d) == intent else 0)))
```

**要点**：实际系统组合使用——策略 2 兜底，策略 3 微调，冷启动时逐步升级。

### 练习四

**思路**：根据用户历史数据量自动调整个性化权重。

```python
def adaptive_personalization_weight(user: UserProfile) -> float:
    """根据用户历史数据量自动调整个性化权重。

    数据量越多，个性化权重越高（上限 0.4）。
    """
    data_points = len(user.click_history) + len(user.search_history)
    # 用 sigmoid 函数平滑过渡
    weight = 0.4 / (1 + math.exp(-0.01 * (data_points - 50)))
    return weight
```

**要点**：权重应该平滑过渡，避免在阈值处突变。实际工程中还会考虑数据质量——高质量的点击数据比低质量的搜索历史更有价值。

### 练习五

**思路**：ε-greedy 策略在利用和探索之间平衡。

```python
def epsilon_greedy_ranking(ranked_results, epsilon=0.05):
    """ε-greedy 策略：以概率 ε 替换一个位置为随机文档。

    Args:
        ranked_results: 个性化排序结果
        epsilon: 探索概率

    Returns:
        调整后的排序结果
    """
    import random
    if random.random() < epsilon and len(ranked_results) > 3:
        # 随机选择一个位置（避免前 2 位）
        pos = random.randint(2, len(ranked_results) - 1)
        # 从后半部分随机选择一个文档
        pool = ranked_results[len(ranked_results) // 2:]
        if pool:
            explore_item = random.choice(pool)
            result = list(ranked_results)
            result.remove(explore_item)
            result.insert(pos, explore_item)
            return result
    return ranked_results
```

**要点**：ε 的选择是关键——太小则探索不足，太大则影响用户体验。实际工程中通常对不同用户群体使用不同的 ε 值。
