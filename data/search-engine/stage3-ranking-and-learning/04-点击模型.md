# 点击模型：从用户行为中学习排序

## 场景引入

用户搜索"机器学习"，看到 10 条结果，点击了第 1 条和第 3 条，跳过了第 2 条。这说明第 1 条和第 3 条更相关吗？**不一定。** 第 1 条被点击很可能只是因为它排在最前面。这就是**位置偏差（Position Bias）**：用户更倾向于点击排在前面的结果，无论它们是否真正相关。

点击数据是搜索引擎中最丰富的用户反馈信号，但充满了偏差。点击模型的核心任务是：**从充满偏差的点击日志中，还原用户对文档的真实相关性判断。**

位置偏差的研究可以追溯到 2000 年代初。Joachims 等人在 2005 年的经典论文中通过眼动实验证实：用户确实存在从上到下的浏览模式，排在第一位的结果获得的注意力远高于第十位。这一发现催生了大量点击模型研究，成为搜索引擎优化排序的重要工具。

在工业界，点击数据的价值在于：它是免费的、海量的、实时的。人工标注一个查询-文档对的成本约为 1-5 美元，而搜索引擎每天可以收集数亿次点击。如果能有效利用这些点击数据，就能大幅降低对人工标注的依赖。

## 1. 点击日志分析

```python
from dataclasses import dataclass
from typing import List
from collections import defaultdict
import random, math


@dataclass
class ClickLog:
    """一条点击日志记录。"""
    query: str
    session_id: str
    shown_docs: List[str]       # 展示给用户的文档列表（按位置排列）
    clicked_positions: List[int]  # 用户点击的位置
    clicked_docs: List[str]     # 用户点击的文档


def generate_click_logs(n=5000):
    """生成模拟点击日志。

    模拟真实场景：用户从上到下浏览，位置越靠后被查看的概率越低。
    """
    random.seed(42)
    queries = ["机器学习", "Python 教程", "深度学习", "神经网络"]
    docs_pool = [f"doc_{i}" for i in range(100)]
    logs = []
    for sid in range(n):
        query = random.choice(queries)
        shown = random.sample(docs_pool, 10)
        # 位置偏差：位置 0 的点击概率约 0.3，位置 9 约 0.04
        clicked = [p for p in range(10) if random.random() < 0.3 * (0.8 ** p)]
        logs.append(ClickLog(query, f"s_{sid}", shown, clicked, [shown[p] for p in clicked]))
    return logs


def analyze_position_ctr(logs):
    """分析各位置的 CTR，验证位置偏差的存在。"""
    shows, clicks = defaultdict(int), defaultdict(int)
    for log in logs:
        for pos in range(len(log.shown_docs)):
            shows[pos] += 1
        for pos in log.clicked_positions:
            clicks[pos] += 1
    for pos in sorted(shows):
        ctr = clicks[pos] / shows[pos]
        print(f"位置 {pos}: 展示={shows[pos]}, CTR={ctr:.4f}")
```

运行结果清楚显示位置 0 的 CTR 远高于位置 9，这就是位置偏差的直接证据。

### 1.1 位置偏差的来源

位置偏差的产生有多个原因：

1. **视觉注意力梯度**：用户从上到下浏览，注意力随位置递减
2. **信任偏差**：用户潜意识认为"搜索引擎把它排在前面，说明它更好"
3. **满足性偏差**：如果前面的结果已经满足需求，用户不会继续往下看
4. **疲劳效应**：浏览到后面时，用户的耐心和注意力都在下降

## 2. Position-Based Model（PBM）

PBM 将点击概率分解为两个独立因素：

```
P(click | query, doc, position) = P(examine | position) × P(attract | query, doc)
```

- **P(examine | position)**：用户是否查看了该位置，只与位置有关
- **P(attract | query, doc)**：文档是否吸引用户点击，只与查询和文档匹配度有关

PBM 的核心假设是：**查看和吸引是独立的**。也就是说，用户是否查看某个位置与该位置上放什么文档无关。这个假设在实际中并不完全成立（比如用户可能因为标题特别吸引人而倒回去看），但在大多数场景下是合理的近似。

### 2.1 EM 算法实现

```python
import numpy as np


class PositionBasedModel:
    """Position-Based Model 的 EM 算法实现。

    通过期望最大化算法同时估计位置查看概率和文档吸引概率。
    """

    def __init__(self, n_positions=10):
        self.n_positions = n_positions
        self.examine_prob = np.ones(n_positions) * 0.5  # 初始查看概率
        self.attract_prob = defaultdict(lambda: 0.3)    # 初始吸引概率

    def fit(self, logs, n_iterations=20):
        """用 EM 算法训练 PBM。

        Args:
            logs: 点击日志列表
            n_iterations: EM 迭代次数
        """
        for iteration in range(n_iterations):
            e_counts = np.zeros(self.n_positions)
            e_totals = np.zeros(self.n_positions)
            a_numer, a_denom = defaultdict(float), defaultdict(float)

            for log in logs:
                for pos, doc in enumerate(log.shown_docs):
                    if pos >= self.n_positions:
                        break
                    is_clicked = pos in log.clicked_positions
                    e, a = self.examine_prob[pos], self.attract_prob[doc]

                    if is_clicked:
                        # E 步：点击了，说明一定查看了
                        e_counts[pos] += 1.0
                        a_numer[doc] += 1.0
                    else:
                        # E 步：没点击，可能是没查看，也可能是查看了但不吸引
                        denom = e * (1 - a) + (1 - e)
                        e_counts[pos] += e * (1 - a) / denom if denom > 0 else 0

                    e_totals[pos] += 1
                    a_denom[doc] += 1

            # M 步：更新参数
            for pos in range(self.n_positions):
                if e_totals[pos] > 0:
                    self.examine_prob[pos] = e_counts[pos] / e_totals[pos]
            for doc in a_denom:
                if a_denom[doc] > 0:
                    self.attract_prob[doc] = a_numer[doc] / a_denom[doc]

            if (iteration + 1) % 5 == 0:
                ll = self._log_likelihood(logs)
                print(f"Iteration {iteration+1}: log-likelihood = {ll:.2f}")

    def _log_likelihood(self, logs):
        """计算对数似然，用于监控收敛。"""
        ll = 0.0
        for log in logs:
            for pos, doc in enumerate(log.shown_docs):
                if pos >= self.n_positions:
                    break
                e, a = self.examine_prob[pos], self.attract_prob[doc]
                if pos in log.clicked_positions:
                    ll += math.log(e * a + 1e-10)
                else:
                    ll += math.log(1 - e * a + 1e-10)
        return ll

    def get_relevance(self, doc_id):
        """获取文档的吸引概率（无偏相关性估计）。"""
        return self.attract_prob[doc_id]
```

### 2.2 EM 算法的直觉理解

**E 步（Expectation）**：根据当前参数，推断每个未点击事件的"隐藏状态"——用户是真的没查看（没看到），还是查看了但不感兴趣。

**M 步（Maximization）**：根据推断的隐藏状态，重新估计参数——每个位置的查看概率和每个文档的吸引概率。

迭代过程会收敛到一个局部最优解。查看概率会逐渐反映真实的位置注意力分布，吸引概率会逐渐反映文档的真实相关性。

## 3. 位置偏差修正

PBM 训练完成后，用吸引概率替代原始 CTR，得到无偏的相关性估计。

```python
def correct_position_bias(logs, model):
    """用 PBM 吸引概率修正位置偏差。

    对比原始 CTR 和修正后的相关性估计。
    """
    raw = defaultdict(lambda: {"clicks": 0, "shows": 0})
    for log in logs:
        for doc in log.shown_docs:
            raw[doc]["shows"] += 1
        for doc in log.clicked_docs:
            raw[doc]["clicks"] += 1

    print("文档       | 原始CTR | 修正CTR")
    print("-" * 35)
    for doc in sorted(model.attract_prob.keys())[:10]:
        r = raw[doc]
        raw_ctr = r["clicks"] / r["shows"] if r["shows"] > 0 else 0
        corrected = model.attract_prob[doc]
        print(f"{doc:10s} | {raw_ctr:.4f}  | {corrected:.4f}")
```

### 3.1 修正信号的使用方式

修正后的信号有两种使用方式：

```python
def use_corrected_as_label(model, docs):
    """方式一：将修正后的吸引概率作为 LTR 的训练标签。"""
    labels = []
    for doc in docs:
        attract = model.get_relevance(doc)
        # 将连续概率转化为离散等级
        if attract > 0.7:
            labels.append(4)
        elif attract > 0.5:
            labels.append(3)
        elif attract > 0.3:
            labels.append(2)
        elif attract > 0.1:
            labels.append(1)
        else:
            labels.append(0)
    return labels


def use_corrected_as_feature(model, docs):
    """方式二：将修正后的吸引概率作为 LTR 的特征。"""
    return {doc: model.get_relevance(doc) for doc in docs}
```

方式一适合标注数据稀缺的场景，方式二适合已有丰富特征的场景。实际工程中通常两者结合使用。

### 3.2 修正效果的评估

```python
def evaluate_bias_correction(model, logs, ground_truth_relevance):
    """评估位置偏差修正的效果。

    对比原始 CTR 排序和修正后排序与真实相关性的相关性。
    """
    from scipy.stats import spearmanr

    raw_ctr = defaultdict(float)
    shows = defaultdict(int)
    for log in logs:
        for doc in log.shown_docs:
            shows[doc] += 1
        for doc in log.clicked_docs:
            raw_ctr[doc] += 1

    for doc in raw_ctr:
        raw_ctr[doc] /= shows[doc]

    common_docs = set(ground_truth_relevance.keys()) & set(raw_ctr.keys())
    if len(common_docs) < 2:
        return {}

    true_rel = [ground_truth_relevance[d] for d in common_docs]
    raw_scores = [raw_ctr[d] for d in common_docs]
    corrected_scores = [model.get_relevance(d) for d in common_docs]

    raw_corr, _ = spearmanr(true_rel, raw_scores)
    corrected_corr, _ = spearmanr(true_rel, corrected_scores)

    print(f"原始 CTR 与真实相关性的 Spearman 相关系数: {raw_corr:.4f}")
    print(f"修正后与真实相关性的 Spearman 相关系数: {corrected_corr:.4f}")
    print(f"提升: {(corrected_corr - raw_corr):.4f}")

    return {"raw_corr": raw_corr, "corrected_corr": corrected_corr}
```

### 4.1 Cascade Model

Cascade Model 是最简单的点击模型，假设用户从位置 0 开始依次查看，点击后以概率 γ 继续查看下一个。

```python
class CascadeModel:
    """Cascade Model 实现。

    假设：用户从上到下依次查看，一旦点击后可能停止。
    参数：每个文档的吸引概率 + 用户继续浏览的概率 γ。
    """

    def __init__(self, n_positions=10):
        self.attract_prob = defaultdict(lambda: 0.3)
        self.continue_prob = 0.5  # 点击后继续查看的概率

    def fit(self, logs, n_iterations=20):
        for _ in range(n_iterations):
            a_num, a_den = defaultdict(float), defaultdict(float)
            c_num, c_den = 0.0, 0.0
            for log in logs:
                first_click = min(log.clicked_positions) if log.clicked_positions else None
                for pos, doc in enumerate(log.shown_docs):
                    if first_click is not None and pos <= first_click:
                        a_den[doc] += 1
                        if pos in log.clicked_positions:
                            a_num[doc] += 1
                            if pos < len(log.shown_docs) - 1:
                                c_den += 1
                                if pos != first_click or len(log.clicked_positions) > 1:
                                    c_num += 1
            for doc in a_den:
                if a_den[doc] > 0:
                    self.attract_prob[doc] = a_num[doc] / a_den[doc]
            if c_den > 0:
                self.continue_prob = c_num / c_den
```

**Cascade Model 的局限**：只能建模第一个点击之前的行为，无法处理同一 session 中的多次点击。假设太强，在实际中效果通常不如 PBM。

### 4.2 User Browsing Model（UBM）

UBM 扩展了 PBM，认为查看概率不仅取决于当前位置，还取决于上一次点击的位置：

```python
class UserBrowsingModel:
    """User Browsing Model 的简化实现。

    查看概率取决于当前位置和上一次点击位置之间的距离。
    """
    def __init__(self, n_positions=10):
        self.n_positions = n_positions
        self.examine_prob = {}  # (position, last_click_pos) -> probability
        self.attract_prob = defaultdict(lambda: 0.3)

    def get_examine_prob(self, pos, last_click_pos):
        """获取查看概率，取决于当前位置和上一次点击位置。"""
        key = (pos, last_click_pos)
        if key not in self.examine_prob:
            # 初始化：距离上次点击越远，查看概率越低
            distance = pos - last_click_pos if last_click_pos >= 0 else pos
            self.examine_prob[key] = max(0.1, 0.8 ** distance)
        return self.examine_prob[key]
```

UBM 的核心洞察：用户在点击一个结果后，会跳过紧跟着的几个结果（因为它们通常是相似的），然后重新开始浏览。这比 PBM 的"查看概率只与位置有关"更符合实际。

### 4.3 Dynamic Bayesian Network（DBN）

DBN 引入了"满意状态"概念：用户点击后可能满意并停止搜索，也可能不满意继续浏览。

```python
class DynamicBayesianNetwork:
    """Dynamic Bayesian Network 简化实现。

    引入满意概率：用户点击后有概率满意并停止搜索。
    """
    def __init__(self):
        self.attract_prob = defaultdict(lambda: 0.3)
        self.satisfy_prob = defaultdict(lambda: 0.5)  # 点击后满意的概率

    def fit(self, logs, n_iterations=20):
        for _ in range(n_iterations):
            a_num, a_den = defaultdict(float), defaultdict(float)
            s_num, s_den = defaultdict(float), defaultdict(float)

            for log in logs:
                last_click = None
                for pos, doc in enumerate(log.shown_docs):
                    if pos in log.clicked_positions:
                        a_num[doc] += 1
                        # 如果这是最后一次点击，可能是满意了
                        if pos == max(log.clicked_positions):
                            s_num[doc] += 1
                        last_click = pos
                    a_den[doc] += 1
                    s_den[doc] += 1

            for doc in a_den:
                if a_den[doc] > 0:
                    self.attract_prob[doc] = a_num[doc] / a_den[doc]
            for doc in s_den:
                if s_den[doc] > 0:
                    self.satisfy_prob[doc] = s_num[doc] / s_den[doc]
```

DBN 适合搜索场景，因为用户的搜索行为通常是"搜索 → 点击 → 阅读 → 满意/不满意 → 继续搜索"的循环。

## 5. 点击模型在排序中的应用

### 5.1 作为 LTR 训练标签

```python
def build_ltr_labels_from_clicks(click_model, docs, threshold=0.3):
    """用点击模型的吸引概率构建 LTR 训练标签。"""
    labels = {}
    for doc in docs:
        relevance = click_model.get_relevance(doc)
        if relevance > 0.6:
            labels[doc] = 4  # 高度相关
        elif relevance > threshold:
            labels[doc] = 3  # 相关
        elif relevance > 0.15:
            labels[doc] = 2  # 部分相关
        elif relevance > 0.05:
            labels[doc] = 1  # 边缘相关
        else:
            labels[doc] = 0  # 不相关
    return labels
```

### 5.2 作为排序特征

```python
def build_click_features(click_model, raw_ctr, doc):
    """构建基于点击的排序特征。"""
    return {
        "attract_prob": click_model.get_relevance(doc),  # 无偏吸引概率
        "raw_ctr": raw_ctr.get(doc, 0.0),                # 原始 CTR
        "ctr_correction": click_model.get_relevance(doc) - raw_ctr.get(doc, 0.0),  # 修正量
    }
```

### 5.3 点击数据的稀疏性处理

```python
def smooth_attract_prob(click_model, doc, global_mean=0.2, prior_count=5):
    """贝叶斯平滑：展示次数少的文档向全局均值收缩。

    Args:
        click_model: 训练好的点击模型
        doc: 文档 ID
        global_mean: 全局平均吸引概率
        prior_count: 先验等价展示次数
    """
    raw = click_model.get_relevance(doc)
    # 用 Beta 分布做贝叶斯平滑
    # 展示次数越多，越信任原始估计；展示次数越少，越向全局均值靠拢
    shows = click_model.attract_prob.get(doc, 0)  # 简化：用吸引概率近似
    weight = shows / (shows + prior_count)
    return weight * raw + (1 - weight) * global_mean
```

## 6. 常见误区

1. **直接用原始 CTR 作为相关性标签**：位置偏差导致排在前面的文档 CTR 虚高
2. **忽视展示次数**：低展示次数的 CTR 波动大，不可靠
3. **混淆因果和相关**：高 CTR 可能因为位置好，也可能因为真正相关
4. **用全局模型处理个性化查询**：不同查询类型的位置偏差模式不同
5. **忽视展示偏差**：标题和摘要的质量也会影响点击，这与文档本身的相关性无关
6. **过度信任点击数据**：点击数据有噪声，不能完全替代人工标注

## 7. 工程建议

1. **数据量是关键**：PBM 至少需要每个文档 5 次以上展示才能准确估计
2. **分层建模**：不同查询类型的位置偏差模式不同，分层训练效果更好
3. **与 LTR 结合**：修正后的 CTR 作为 LTR 的特征或标签，而非直接替代
4. **处理稀疏数据**：长尾查询用查询聚类或文档聚类共享统计量
5. **实时更新**：点击模型需要定期用新数据更新，反映用户行为变化
6. **A/B 验证**：点击模型的效果必须通过线上实验验证

## 小结

本课介绍了点击模型的核心概念：位置偏差是点击数据中最主要的偏差来源；PBM 将点击概率分解为查看概率和吸引概率，通过 EM 算法学习；修正后的信号可作为 LTR 的训练标签或特征。下一课我们将学习个性化排序。

## 参考答案

### 练习一

**思路**：Cascade Model 假设用户从位置 0 开始依次查看，点击后以概率 γ 继续。

```python
class CascadeModel:
    def __init__(self, n_positions=10):
        self.attract_prob = defaultdict(lambda: 0.3)
        self.continue_prob = 0.5

    def fit(self, logs, n_iterations=20):
        for _ in range(n_iterations):
            a_num, a_den = defaultdict(float), defaultdict(float)
            c_num, c_den = 0.0, 0.0
            for log in logs:
                first_click = min(log.clicked_positions) if log.clicked_positions else None
                for pos, doc in enumerate(log.shown_docs):
                    if first_click is not None and pos <= first_click:
                        a_den[doc] += 1
                        if pos in log.clicked_positions:
                            a_num[doc] += 1
                            if pos < len(log.shown_docs) - 1:
                                c_den += 1
                                if pos != first_click or len(log.clicked_positions) > 1:
                                    c_num += 1
            for doc in a_den:
                if a_den[doc] > 0:
                    self.attract_prob[doc] = a_num[doc] / a_den[doc]
            if c_den > 0:
                self.continue_prob = c_num / c_den
```

**要点**：Cascade Model 比 PBM 简单但假设更强，只能建模第一个点击之前的行为。PBM 可以处理多次点击，适用范围更广。

### 练习二

**思路**：贝叶斯收缩，展示次数越少越向全局均值靠拢。

```python
def smoothed_ctr(clicks, shows, prior_clicks, prior_shows):
    """贝叶斯平滑 CTR。

    使用 Beta-Binomial 先验：prior_clicks 和 prior_shows 定义先验分布。
    """
    return (clicks + prior_clicks) / (shows + prior_shows)

# 先验：全局 CTR × 10 次展示等价
mean_ctr = total_clicks / total_shows
prior_shows = 10.0
prior_clicks = mean_ctr * prior_shows
```

**要点**：展示次数足够多时平滑 CTR 接近原始 CTR，展示次数少时向均值收缩。先验强度（prior_shows）需要根据数据量调整。

### 练习三

**思路**：在 A/B 实验中随机化同一文档的位置，对比 CTR。

```python
def position_bias_experiment(logs, target_doc):
    """验证位置偏差：比较同一文档在不同位置的 CTR。"""
    pos0_shows = pos0_clicks = pos5_shows = pos5_clicks = 0
    for log in logs:
        if target_doc in log.shown_docs:
            p = log.shown_docs.index(target_doc)
            if p == 0:
                pos0_shows += 1
                if 0 in log.clicked_positions: pos0_clicks += 1
            elif p == 5:
                pos5_shows += 1
                if 5 in log.clicked_positions: pos5_clicks += 1
    ctr0 = pos0_clicks / pos0_shows if pos0_shows else 0
    ctr5 = pos5_clicks / pos5_shows if pos5_shows else 0
    print(f"位置 0 CTR: {ctr0:.4f}, 位置 5 CTR: {ctr5:.4f}, 偏差倍数: {ctr0/ctr5:.2f}x")
```

**要点**：真正的位置偏差实验需要在线随机化，离线数据只能近似估计。在线实验是验证位置偏差最可靠的方法。

### 练习四

**思路**：在 PBM 基础上增加标题吸引力因子。

```python
class ExtendedPBM:
    """扩展 PBM，增加标题吸引力因子。"""
    def __init__(self, n_positions=10):
        self.n_positions = n_positions
        self.examine_prob = np.ones(n_positions) * 0.5
        self.attract_prob = defaultdict(lambda: 0.3)
        self.title_appeal = defaultdict(lambda: 0.5)

    def fit(self, logs, n_iterations=20):
        for _ in range(n_iterations):
            e_counts = np.zeros(self.n_positions)
            e_totals = np.zeros(self.n_positions)
            a_num, a_den = defaultdict(float), defaultdict(float)
            t_num, t_den = defaultdict(float), defaultdict(float)

            for log in logs:
                for pos, doc in enumerate(log.shown_docs[:self.n_positions]):
                    is_clicked = pos in log.clicked_positions
                    e = self.examine_prob[pos]
                    a = self.attract_prob[doc]
                    t = self.title_appeal[doc]

                    if is_clicked:
                        e_counts[pos] += 1
                        a_num[doc] += 1
                        t_num[doc] += 1
                    else:
                        denom = e * (1 - a * t) + (1 - e)
                        e_counts[pos] += e * (1 - a * t) / denom if denom > 0 else 0

                    e_totals[pos] += 1
                    a_den[doc] += 1
                    t_den[doc] += 1

            for pos in range(self.n_positions):
                if e_totals[pos] > 0:
                    self.examine_prob[pos] = e_counts[pos] / e_totals[pos]
            for doc in a_den:
                if a_den[doc] > 0:
                    self.attract_prob[doc] = a_num[doc] / a_den[doc]
                if t_den[doc] > 0:
                    self.title_appeal[doc] = t_num[doc] / t_den[doc]
```

**要点**：标题吸引力和文档相关性是两个独立维度。一个标题党文档可能标题吸引力高但相关性低。分离这两个信号有助于更准确地估计真实相关性。

### 练习五

**思路**：在同一数据集上训练三种模型，用统一指标评估。

```python
def compare_click_models(logs):
    """对比三种点击模型的效果。"""
    # 训练 PBM
    pbm = PositionBasedModel(10)
    pbm.fit(logs, 20)

    # 训练 Cascade Model
    cm = CascadeModel(10)
    cm.fit(logs, 20)

    # 计算对数似然
    pbm_ll = pbm._log_likelihood(logs)
    cm_ll = sum(
        math.log(cm.attract_prob[doc] * cm.continue_prob + 1e-10)
        if pos in log.clicked_positions
        else math.log(1 - cm.attract_prob[doc] + 1e-10)
        for log in logs
        for pos, doc in enumerate(log.shown_docs[:10])
    )

    print(f"PBM 对数似然: {pbm_ll:.2f}")
    print(f"Cascade 对数似然: {cm_ll:.2f}")
    print(f"PBM 更好: {pbm_ll > cm_ll}")
```

**要点**：PBM 通常优于 Cascade Model，因为它能处理多次点击且假设更宽松。选择模型时要在效果和复杂度之间权衡。
