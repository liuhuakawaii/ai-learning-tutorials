## 2. WHAT/WHY/HOW 模式详解

### 2.1 三段式结构

```
┌──────────────────────────────────────────────────────┐
│              WHAT / WHY / HOW 模式                    │
│                                                      │
│  ┌──────────────────────────────────────────────┐    │
│  │ WHAT — 做什么                                │    │
│  │ 功能的精确描述：输入、输出、行为              │    │
│  │ "实现一个用户搜索 API，返回分页结果"          │    │
│  └──────────────────────────────────────────────┘    │
│                      ▼                               │
│  ┌──────────────────────────────────────────────┐    │
│  │ WHY — 为什么做                               │    │
│  │ 业务背景、使用场景、解决的问题                │    │
│  │ "管理后台的用户列表页需要按姓名/邮箱搜索"    │    │
│  └──────────────────────────────────────────────┘    │
│                      ▼                               │
│  ┌──────────────────────────────────────────────┐    │
│  │ HOW — 怎么做                                 │    │
│  │ 技术方案、约束条件、遵循的规范                │    │
│  │ "用 Prisma 模糊匹配，Zod 验证，分页默认20条" │    │
│  └──────────────────────────────────────────────┘    │
│                                                      │
└──────────────────────────────────────────────────────┘
```

### 2.2 各部分详细说明

| 部分 | 回答的问题 | 包含内容 | 常见遗漏 |
|------|-----------|---------|---------|
| WHAT | "做什么？" | 功能名称、输入/输出、核心行为 | 边界情况、异常行为 |
| WHY | "为什么做？" | 业务场景、用户角色、解决的痛点 | 性能需求、安全需求 |
| HOW | "怎么做？" | 技术栈、约束、规范、参考代码 | 错误处理策略、日志策略 |

## 3. 可复用模板：API 端点

### 3.1 API 端点模板

```markdown
## [WHAT] API 端点描述

**路由**：{METHOD} {路径}
**功能**：一句话描述
**请求参数**：
  - Query: {参数名}: {类型} — {说明} (必填/可选, 默认值)
  - Body: {字段名}: {类型} — {说明} (必填/可选)
**响应格式**：
  - 成功 (200): {结构描述}
  - 失败 (400/404/500): {错误格式}

## [WHY] 业务背景

**场景**：谁在什么场景下使用
**目的**：解决什么问题
**关联**：与哪些功能关联

## [HOW] 技术方案

**技术栈**：框架、ORM、验证库
**约束**：类型安全、错误处理、性能要求
**参考**：现有的类似实现路径
```

### 3.2 实际填充示例

**TypeScript + Express 示例**

```typescript
// ===== 填充后的 Prompt =====
// [WHAT]
// POST /api/orders — 创建新订单
// 请求 Body: { items: Array<{ productId: string; quantity: number }>; couponCode?: string }
// 响应 (201): { id: string; total: number; status: 'pending'; createdAt: string }
// 响应 (400): { error: string; details: ValidationError[] }
// 响应 (404): { error: string } — 商品不存在

// [WHY]
// 电商用户在购物车页面点击"下单"后，需要创建订单并扣减库存。
// 需要保证原子性：订单创建和库存扣减要么同时成功，要么同时失败。

// [HOW]
// Express + TypeScript + Prisma + Zod
// 使用 Prisma 事务保证原子性
// 不使用 any，错误用 AppError 类
// 库存不足时返回 409 Conflict

// ===== AI 生成的代码 =====
import { Router, Request, Response } from 'express';
import { PrismaClient, Prisma } from '@prisma/client';
import { z } from 'zod';
import { AppError } from '../errors/AppError';

const prisma = new PrismaClient();
const router = Router();

const createOrderSchema = z.object({
  items: z.array(z.object({
    productId: z.string().cuid(),
    quantity: z.number().int().positive(),
  })).min(1).max(50),
  couponCode: z.string().optional(),
});

router.post('/api/orders', async (req: Request, res: Response) => {
  const parsed = createOrderSchema.safeParse(req.body);
  if (!parsed.success) {
    res.status(400).json({ error: 'Validation failed', details: parsed.error.flatten() });
    return;
  }

  const { items, couponCode } = parsed.data;

  try {
    const order = await prisma.$transaction(async (tx) => {
      // 1. 验证所有商品存在且库存充足
      for (const item of items) {
        const product = await tx.product.findUnique({ where: { id: item.productId } });
        if (!product) {
          throw new AppError(`Product ${item.productId} not found`, 'PRODUCT_NOT_FOUND', 404);
        }
        if (product.stock < item.quantity) {
          throw new AppError(
            `Insufficient stock for ${product.name}: requested ${item.quantity}, available ${product.stock}`,
            'INSUFFICIENT_STOCK',
            409
          );
        }
      }

      // 2. 计算总价
      let total = 0;
      for (const item of items) {
        const product = await tx.product.findUnique({ where: { id: item.productId } });
        total += product!.price * item.quantity;
      }

      // 3. 应用优惠券（如果有）
      if (couponCode) {
        const coupon = await tx.coupon.findUnique({ where: { code: couponCode } });
        if (coupon && coupon.active) {
          total *= (1 - coupon.discount / 100);
        }
      }

      // 4. 创建订单
      const order = await tx.order.create({
        data: {
          total: Math.round(total * 100) / 100,
          status: 'pending',
          items: {
            create: items.map(item => ({
              productId: item.productId,
              quantity: item.quantity,
            })),
          },
        },
        include: { items: true },
      });

      // 5. 扣减库存
      for (const item of items) {
        await tx.product.update({
          where: { id: item.productId },
          data: { stock: { decrement: item.quantity } },
        });
      }

      return order;
    });

    res.status(201).json({
      id: order.id,
      total: order.total,
      status: order.status,
      createdAt: order.createdAt.toISOString(),
    });
  } catch (error) {
    if (error instanceof AppError) {
      res.status(error.statusCode).json({ error: error.message });
      return;
    }
    throw error;
  }
});

export default router;
```

## 4. 可复用模板：数据库 Schema

### 4.1 Schema 模板

```markdown
## [WHAT] 数据模型描述

**模型名**：{ModelName}
**用途**：一句话说明
**字段**：
  - {字段名}: {类型} — {说明} (约束)
**关系**：
  - {关系类型}: 与 {Model} 的关系 — {说明}
**索引**：{字段} — {原因}

## [WHY] 业务背景

**数据用途**：谁读写这些数据
**查询模式**：最常用的查询是什么
**数据量级**：预估数据量

## [HOW] 技术方案

**ORM**：Prisma / Drizzle / TypeORM
**数据库**：PostgreSQL / MySQL / SQLite
**特殊需求**：软删除、审计日志、多租户
```

### 4.2 实际填充示例

**Prisma Schema 示例**

```prisma
// ===== 填充后的 Prompt =====
// [WHAT] 博客系统的文章模型
// 字段：id, title, slug(唯一), content(长文本), status(draft/published/archived),
//       authorId(外键), publishedAt(可选), createdAt, updatedAt
// 关系：多对一 User(author), 多对多 Tag, 一对多 Comment
// 索引：slug(唯一), [status, publishedAt](列表查询), [authorId, status](作者文章列表)

// [WHY]
// 博客平台的核心数据模型。
// 主要查询：按状态列出文章、按作者查文章、按 slug 查单篇。
// 预计数据量：单作者 500-2000 篇，平台总计 10 万篇以内。

// [HOW]
// Prisma + PostgreSQL
// 需要软删除（用 status=archived 代替物理删除）
// slug 由 title 自动生成，保证唯一

// ===== AI 生成的 Schema =====
model Post {
  id          String      @id @default(cuid())
  title       String      @db.VarChar(200)
  slug        String      @unique @db.VarChar(200)
  content     String      @db.Text
  status      PostStatus  @default(DRAFT)
  publishedAt DateTime?

  authorId String
  author   User   @relation(fields: [authorId], references: [id])

  tags     Tag[]     @relation("PostTags")
  comments Comment[]

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@index([status, publishedAt])
  @@index([authorId, status])
}

enum PostStatus {
  DRAFT
  PUBLISHED
  ARCHIVED
}

model Tag {
  id    String @id @default(cuid())
  name  String @unique @db.VarChar(50)
  slug  String @unique @db.VarChar(50)
  posts Post[] @relation("PostTags")
}

model Comment {
  id        String   @id @default(cuid())
  content   String   @db.Text
  postId    String
  post      Post     @relation(fields: [postId], references: [id])
  authorId  String
  author    User     @relation(fields: [authorId], references: [id])
  createdAt DateTime @default(now())

  @@index([postId, createdAt])
}
```

### 5.1 组件模板

```markdown
## [WHAT] 组件描述

**组件名**：{ComponentName}
**功能**：一句话描述
**Props**：

**渲染结构**：简要描述 DOM 结构

**使用场景**：在哪些页面/流程中使用

**框架**：React / Vue / Svelte
```

### 5.2 实际填充示例

**React + TypeScript + Tailwind 示例**

```typescript
// ===== 填充后的 Prompt =====
// [WHAT] 通用确认对话框组件
// Props:
//   - isOpen: boolean — 控制显示/隐藏
//   - title: string — 对话框标题
//   - message: string — 确认内容
//   - confirmText?: string — 确认按钮文字 (默认 "确认")
//   - cancelText?: string — 取消按钮文字 (默认 "取消")
//   - variant?: 'danger' | 'warning' | 'info' — 视觉风格 (默认 'info')
//   - onConfirm: () => void — 点击确认回调
//   - onCancel: () => void — 点击取消/遮罩回调

// [WHY]
// 项目中多处需要二次确认：删除操作、退出编辑、批量操作等。
// 需要统一的确认体验，支持不同危险等级的视觉区分。

// [HOW]
// React + TypeScript + Tailwind CSS
// 使用 React Portal 渲染到 document.body
// 支持 ESC 键关闭、点击遮罩关闭
// 使用 Framer Motion 做进入/退出动画
// 不使用 any 类型

// ===== AI 生成的代码 =====
import { useEffect, useRef, type ReactNode } from 'react';
import { createPortal } from 'react-dom';
import { motion, AnimatePresence } from 'framer-motion';

interface ConfirmDialogProps {
  isOpen: boolean;
  title: string;
  message: string | ReactNode;
  confirmText?: string;
  cancelText?: string;
  variant?: 'danger' | 'warning' | 'info';
  onConfirm: () => void;
  onCancel: () => void;
}

const variantStyles = {
  danger: {
    icon: '⚠️',
    confirmBg: 'bg-red-600 hover:bg-red-700',
    ring: 'ring-red-500/20',
  },
  warning: {
    icon: '⚡',
    confirmBg: 'bg-amber-600 hover:bg-amber-700',
    ring: 'ring-amber-500/20',
  },
  info: {
    icon: 'ℹ️',
    confirmBg: 'bg-blue-600 hover:bg-blue-700',
    ring: 'ring-blue-500/20',
  },
} as const;

export function ConfirmDialog({
  isOpen,
  title,
  message,
  confirmText = '确认',
  cancelText = '取消',
  variant = 'info',
  onConfirm,
  onCancel,
}: ConfirmDialogProps) {
  const confirmRef = useRef<HTMLButtonElement>(null);
  const style = variantStyles[variant];

  useEffect(() => {
    if (!isOpen) return;

    const handleKeyDown = (e: KeyboardEvent) => {
      if (e.key === 'Escape') onCancel();
    };

    document.addEventListener('keydown', handleKeyDown);
    document.body.style.overflow = 'hidden';

    return () => {
      document.removeEventListener('keydown', handleKeyDown);
      document.body.style.overflow = '';
    };
  }, [isOpen, onCancel]);

  useEffect(() => {
    if (isOpen) {
      confirmRef.current?.focus();
    }
  }, [isOpen]);

  return createPortal(
    <AnimatePresence>
      {isOpen && (
        <motion.div
          className="fixed inset-0 z-50 flex items-center justify-center"
          initial={{ opacity: 0 }}
          animate={{ opacity: 1 }}
          exit={{ opacity: 0 }}
        >
          <motion.div
            className="absolute inset-0 bg-black/50"
            onClick={onCancel}
            initial={{ opacity: 0 }}
            animate={{ opacity: 1 }}
            exit={{ opacity: 0 }}
          />

          <motion.div
            className={`relative mx-4 w-full max-w-md rounded-xl bg-white p-6 shadow-2xl ring-1 ${style.ring}`}
            initial={{ scale: 0.95, opacity: 0 }}
            animate={{ scale: 1, opacity: 1 }}
            exit={{ scale: 0.95, opacity: 0 }}
            role="alertdialog"
            aria-labelledby="dialog-title"
            aria-describedby="dialog-description"
          >
            <div className="mb-4 flex items-center gap-3">
              <span className="text-2xl">{style.icon}</span>
              <h2 id="dialog-title" className="text-lg font-semibold text-gray-900">
                {title}
              </h2>
            </div>

            <div id="dialog-description" className="mb-6 text-sm text-gray-600">
              {message}
            </div>

            <div className="flex justify-end gap-3">
              <button
                onClick={onCancel}
                className="rounded-lg border border-gray-300 px-4 py-2 text-sm font-medium text-gray-700 hover:bg-gray-50"
              >
                {cancelText}
              </button>
              <button
                ref={confirmRef}
                onClick={onConfirm}
                className={`rounded-lg px-4 py-2 text-sm font-medium text-white ${style.confirmBg}`}
              >
                {confirmText}
              </button>
            </div>
          </motion.div>
        </motion.div>
      )}
    </AnimatePresence>,
    document.body
  );
}
```

## 6. 需求拆解技巧

### 6.1 大需求拆小需求

```
大需求："做一个完整的博客系统"
         │
         ▼
拆解为独立的小需求：

  ┌─────────────┐
  │ 数据模型    │ → "定义 Post, Tag, Comment 的 Prisma Schema"
  └──────┬──────┘
         ▼
  ┌─────────────┐
  │ 文章 CRUD   │ → "实现文章的增删改查 API"
  └──────┬──────┘
         ▼
  ┌─────────────┐
  │ 标签管理    │ → "实现标签的 CRUD 和文章-标签关联"
  └──────┬──────┘
         ▼
  ┌─────────────┐
  │ 评论系统    │ → "实现评论的创建、列表、删除"
  └──────┬──────┘
         ▼
  ┌─────────────┐
  │ 前端页面    │ → "文章列表页、详情页、编辑页"
  └─────────────┘
```

### 6.2 拆解原则

| 原则 | 说明 | 示例 |
|------|------|------|
| 单一职责 | 每个 Prompt 只做一件事 | "实现文章创建 API" 而非 "实现文章所有功能" |
| 可验证 | 完成后可以测试 | "实现 GET /api/posts，返回 Post[]" |
| 有依赖顺序 | 先模型后 API 再页面 | Schema → API → 前端 |
| 适当粒度 | 不太粗也不太细 | 一个路由文件而非一个函数 |

## 7. 常见错误

### ❌ 错误 1：缺少 WHY

```
"写一个 Redis 缓存层"
→ AI 不知道缓存什么、缓存策略是什么、TTL 设多少
```

**修复**：补充业务场景——"首页商品列表查询频繁（QPS 500+），需要用 Redis 缓存，TTL 5 分钟，缓存失效时回源数据库"。

### ❌ 错误 2：WHAT 和 HOW 混淆

```
"用 Prisma 写一个查询"
→ 这是 HOW，WHAT 是"查询什么、返回什么"
```

**修复**：WHAT 先说清楚要什么，HOW 再说用什么技术实现。

### ❌ 错误 3：忽略错误场景

```
只描述成功路径，不说失败时怎么办
→ AI 生成的代码缺少错误处理
```

**修复**：在 WHAT 中列出可能的错误场景（400 参数错误、404 不存在、409 冲突等）。

### ❌ 错误 4：模板过于僵硬

```
每次都完整填写模板所有字段，即使很多字段不适用
→ 浪费时间，Prompt 冗长
```

**修复**：只填写与当前需求相关的字段，省略不适用的部分。

### ❌ 错误 5：缺少参考代码

```
"按项目现有风格写"
→ AI 不知道你的风格是什么
```

**修复**：在 HOW 中贴一段现有的参考代码，或说明风格要点。

## 8. 总结

```
结构化模板的价值：

  模糊需求 ──▶ 结构化描述 ──▶ 精准代码
                │
                ├── WHAT: 明确做什么
                ├── WHY:  说明为什么
                └── HOW:  指定怎么做

  效果：减少 60-80% 的反复沟通
```

| 模板类型 | 适用场景 | 核心字段 |
|---------|---------|---------|
| API 端点 | 后端接口开发 | 路由、参数、响应、验证 |
| 数据库 Schema | 数据模型设计 | 模型名、字段、关系、索引 |
| UI 组件 | 前端组件开发 | Props、结构、交互、样式 |
| 通用模板 | 任何需求 | WHAT / WHY / HOW |

## 9. 动手练习

### 练习 1：用模板描述一个 API

选择以下任一场景，用 API 端点模板写一个结构化 Prompt：

- 用户登录 API（POST /api/auth/login）
- 文章搜索 API（GET /api/posts/search）
- 文件上传 API（POST /api/upload）

要求：WHAT/WHY/HOW 三部分都要有，至少包含 2 个错误场景。

### 练习 2：需求拆解

将以下大需求拆解为 5-8 个独立的小需求，并为每个小需求写一行结构化描述：

```
"做一个任务管理系统（类似 Trello），支持：
- 用户注册登录
- 创建看板和列表
- 创建、移动、归档任务
- 任务分配给用户
- 任务截止日期和提醒
- 标签和筛选"
```

### 练习 3：对比有无模板的差异

选一个你最近让 AI 帮你写的代码功能，先用你原来的 Prompt 方式，再用 WHAT/WHY/HOW 模板重新描述，对比两次生成的代码质量差异。记录：

- 原 Prompt 生成的代码需要几轮修改？
- 模板 Prompt 生成的代码需要几轮修改？
- 代码质量差异体现在哪些方面？
