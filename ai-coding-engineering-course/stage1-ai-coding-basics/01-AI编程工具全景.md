### 1.1 代码补全类（Inline Completion）

**核心特点**：在你编写代码时实时提供行级或块级建议，按下 Tab 即可接受。

- 干扰最小，融入现有工作流
- 延迟极低（通常 < 200ms）
- 依赖良好的上下文（函数名、类型、注释）

### 1.2 对话辅助类（Chat）

**核心特点**：通过自然语言对话与 AI 交互，完成代码解释、生成、调试等任务。

- 适合复杂问题的探索和讨论
- 可以提供详细的解释和推理过程
- 需要用户主动描述需求

### 1.3 Agent 类（Autonomous）

**核心特点**：AI 自主规划任务步骤，读取文件、执行命令、创建/修改多个文件。

- 能完成端到端的复杂任务
- 可能产生较大范围的代码变更
- 需要更仔细的人工审查

## 2. 主流工具详解

### 2.1 GitHub Copilot

**类型**：代码补全 + Chat + Agent（Copilot Workspace）

**技术基础**：基于 OpenAI Codex / GPT-4 系列模型

**核心功能**：
- 行级和块级代码补全
- Copilot Chat（IDE 内对话）
- Copilot Workspace（Agent 级任务规划）
- 多语言支持（Python、TypeScript、Go、Java 等）

**定价**：
| 计划 | 价格 | 特点 |
|------|------|------|
| Copilot Individual | $10/月 | 补全 + Chat |
| Copilot Business | $19/用户/月 | 管理控制 + 策略 |
| Copilot Enterprise | $39/用户/月 | 企业知识库 + 定制 |

**适用场景**：日常编码的行级补全、快速原型、代码解释

### 2.2 Cursor

**类型**：AI-Native IDE（补全 + Chat + Agent）

**技术基础**：多模型支持（GPT-4、Claude、自定义模型）

**核心功能**：
- Tab 补全（类似 Copilot）
- Cmd+K 内联编辑
- Chat 面板（支持 @file、@web 等上下文引用）
- Agent 模式（自主读写文件、执行命令）
- Composer 多文件编辑

**定价**：
| 计划 | 价格 | 特点 |
|------|------|------|
| Hobby | 免费 | 有限次数 |
| Pro | $20/月 | 500 次快速请求 |
| Business | $40/用户/月 | 管理 + 隐私模式 |

**适用场景**：AI 深度集成的编码体验、多文件重构、Agent 驱动开发

### 2.3 ChatGPT（OpenAI）

**类型**：通用对话 + Code Interpreter

**核心功能**：
- 自然语言生成代码
- 代码解释和调试
- Code Interpreter（运行 Python 代码）
- 文件上传和分析
- GPTs 定制化

**定价**：
| 计划 | 价格 | 特点 |
|------|------|------|
| Free | $0 | GPT-4o mini，有限制 |
| Plus | $20/月 | GPT-4o + 更高限额 |
| Pro | $200/月 | 无限制 + o1 |

**适用场景**：学习新概念、快速原型验证、非 IDE 内的编程问题

### 2.4 Claude（Anthropic）

**类型**：通用对话 + 代码生成

**核心功能**：
- 强大的代码理解和生成能力
- 长上下文支持（200K tokens）
- Artifacts（可视化代码运行结果）
- Projects（持久化项目上下文）

**定价**：
| 计划 | 价格 | 特点 |
|------|------|------|
| Free | $0 | 有限次数 |
| Pro | $20/月 | 5x 使用量 |
| Team | $30/用户/月 | 协作功能 |

**适用场景**：大型代码库分析、复杂逻辑讨论、长文档处理

### 2.5 Codeium / Windsurf

**类型**：代码补全 + Chat + Agent

**核心功能**：
- 免费的个人代码补全
- Windsurf（AI-Native IDE，原 Codeium 编辑器）
- Cascade Agent 模式
- 多 IDE 支持

**定价**：
| 计划 | 价格 | 特点 |
|------|------|------|
| Free | $0 | 无限补全 |
| Pro | $15/月 | 更快模型 + Chat |
| Enterprise | 定制 | 私有部署 |

**适用场景**：预算敏感的个人开发者、企业私有化部署

### 2.6 Tabnine

**类型**：代码补全 + Chat

**核心功能**：
- 本地模型运行（隐私优先）
- 团队模型训练（基于团队代码风格）
- 多 IDE 支持
- 全行补全

**定价**：
| 计划 | 价格 | 特点 |
|------|------|------|
| Basic | $0 | 基础补全 |
| Pro | $12/月 | 高级补全 + Chat |
| Enterprise | 定制 | 私有部署 + 定制模型 |

**适用场景**：对代码隐私要求高的企业、离线开发环境

### 2.7 Amazon CodeWhisperer（现 Amazon Q Developer）

**类型**：代码补全 + Chat + 安全扫描

**核心功能**：
- AWS 服务深度集成
- 安全漏洞扫描
- 代码引用追踪（显示开源来源）
- 多语言支持

**定价**：
| 计划 | 价格 | 特点 |
|------|------|------|
| Individual | $0 | 基础功能 |
| Pro | $19/用户/月 | 管理 + 安全扫描 |

**适用场景**：AWS 技术栈项目、需要安全合规的团队

## 4. 技术原理（高层概览）

### 4.1 代码补全的工作原理

```
┌─────────────────────────────────────────────────────────────┐
│                  代码补全流程                                 │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  你写的代码                    AI 处理                       │
│  ┌─────────────┐             ┌─────────────────┐            │
│  │ 函数签名     │             │                 │            │
│  │ 类型注解     │  ──────►    │  LLM 推理       │            │
│  │ 注释         │  上下文      │  (Transformer)  │            │
│  │ 前面的代码   │             │                 │            │
│  │ 其他文件引用 │             └────────┬────────┘            │
│  └─────────────┘                      │                     │
│                                       ▼                     │
│                              ┌─────────────────┐            │
│                              │  生成候选建议     │            │
│                              │  (1-3 个选项)    │            │
│                              └────────┬────────┘            │
│                                       │                     │
│                                       ▼                     │
│                              ┌─────────────────┐            │
│                              │  Tab 接受        │            │
│                              │  Esc 拒绝        │            │
│                              │  Alt+] 下一个    │            │
│                              └─────────────────┘            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 影响补全质量的因素

| 因素 | 影响程度 | 说明 |
|------|----------|------|
| 函数名 | ★★★★★ | 描述性的函数名是最好的提示 |
| 类型注解 | ★★★★☆ | TypeScript/Python 类型帮助 AI 理解意图 |
| 注释 | ★★★★☆ | 简短的功能描述注释 |
| 上下文文件 | ★★★☆☆ | import 的文件、相关类型定义 |
| 代码风格一致性 | ★★★☆☆ | 一致的编码风格让 AI 更容易预测 |

## 5. 真实场景示例

### 5.1 场景一：用 Copilot 快速生成 React 组件

```typescript
// 你写：
// 一个带有搜索和分页的用户列表组件

// Copilot 自动生成：
import React, { useState, useMemo } from 'react';

interface User {
  id: string;
  name: string;
  email: string;
  avatar?: string;
}

interface UserListProps {
  users: User[];
  pageSize?: number;
}

export function UserList({ users, pageSize = 10 }: UserListProps) {
  const [search, setSearch] = useState('');
  const [page, setPage] = useState(0);

  const filtered = useMemo(() =>
    users.filter(u =>
      u.name.toLowerCase().includes(search.toLowerCase()) ||
      u.email.toLowerCase().includes(search.toLowerCase())
    ),
    [users, search]
  );

  const totalPages = Math.ceil(filtered.length / pageSize);
  const paged = filtered.slice(page * pageSize, (page + 1) * pageSize);

  return (
    <div className="user-list">
      <input
        type="text"
        placeholder="搜索用户..."
        value={search}
        onChange={(e) => { setSearch(e.target.value); setPage(0); }}
      />
      <ul>
        {paged.map(user => (
          <li key={user.id}>
            {user.avatar && <img src={user.avatar} alt={user.name} />}
            <span>{user.name}</span>
            <span>{user.email}</span>
          </li>
        ))}
      </ul>
      <div className="pagination">
        <button disabled={page === 0} onClick={() => setPage(p => p - 1)}>
          上一页
        </button>
        <span>{page + 1} / {totalPages}</span>
        <button disabled={page >= totalPages - 1} onClick={() => setPage(p => p + 1)}>
          下一页
        </button>
      </div>
    </div>
  );
}
```

### 5.2 场景二：用 Cursor Agent 重构代码

```
你：@file src/utils/helpers.ts 把所有日期处理函数重构为
    使用 date-fns 库替代原生 Date 操作，保持函数签名不变

Cursor Agent 会：
1. 读取 helpers.ts 的完整内容
2. 识别所有使用 new Date() 的函数
3. 搜索项目中是否已安装 date-fns

5. 更新 import 语句

```

### 5.3 场景三：用 Claude 分析复杂错误

```
你：我遇到这个错误，帮我分析原因和解决方案

TypeError: Cannot read properties of undefined (reading 'map')
    at UserList (src/components/UserList.tsx:15:23)

Claude 回答：
这个错误说明 users 在组件渲染时可能是 undefined。
三个解决方案：
1. 给 props 设置默认值：users = []
2. 添加条件渲染：{users?.map(...)}
3. 在父组件添加 loading 状态检查

推荐方案 1，因为它是最小改动且符合 React 最佳实践。
```

## 6. 常见错误

| 错误 | 正确做法 |
|------|----------|
| 只用一个工具，不尝试其他选择 | 至少试用 2-3 个工具，找到最适合自己的 |
| 认为最贵的工具一定最好 | 免费工具（Codeium、Copilot Free）对很多场景足够 |
| 在所有场景用同一个工具 | 补全用 Copilot，复杂讨论用 Claude，学习用 ChatGPT |
| 忽视工具的隐私政策 | 企业项目务必了解代码是否被用于模型训练 |
| 期待工具能完全替代编程能力 | AI 工具是放大器，不是替代品——你需要编程基础 |
| 不更新工具版本 | AI 工具迭代极快，及时更新以获得最佳体验 |
| 用 ChatGPT 写代码但不用 IDE 插件 | IDE 内集成的体验远好于复制粘贴 |

## 7. 总结

本课要点：

1. **三大类别**：代码补全（Inline）、对话辅助（Chat）、Agent 自主完成
2. **工具选型**：根据需求（补全/对话/Agent）、预算、隐私要求选择
3. **技术原理**：LLM 基于上下文预测代码，函数名和类型是最好的提示
4. **组合使用**：不同场景用不同工具，而非押注单一工具
