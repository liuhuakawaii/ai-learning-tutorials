## 2. 规范编写指南

### 2.1 编写原则

| 原则 | 说明 | 示例 |
|------|------|------|
| 具体 | 避免模糊表述 | "使用 bcrypt" 而非 "安全地存储密码" |
| 可执行 | 每条规范可操作 | "ESLint 规则配置如下" |
| 可验证 | 能自动化检查 | "CI 中配置 gitleaks 扫描" |
| 适度 | 不过度约束 | "建议" 和 "必须" 区分使用 |

### 2.2 规范等级定义

```markdown
## 规范等级说明

- **MUST（必须）**: 强制执行，违反将阻断流程
- **SHOULD（应该）**: 强烈建议，违反需要说明理由
- **MAY（可以）**: 可选遵循，提供参考

在文档中使用以下标记：
- 🔴 MUST - 红色标记，CI 强制检查
- 🟡 SHOULD - 黄色标记，review 重点关注
- 🟢 MAY - 绿色标记，建议参考
```

| 工具 | 原因 |
|------|------|

    "env": false,
    "properties": false,
    "secrets": false
  }
}
\```

### 🔴 MUST - 排除敏感文件

\```yaml
# .copilotignore
*.env
*.env.*
secrets/
credentials/
*.pem
*.key
\```
```

# 编码规范

## AI 代码标注

### 🔴 MUST - 标注 AI 生成代码

所有 AI 生成或 AI 辅助编写的代码必须标注：

\```typescript
/**
 * @ai-assisted GitHub Copilot
 * @ai-reviewed-by @zhangsan
 * @ai-reviewed-at 2026-06-21
 * @ai-modifications 优化了错误处理逻辑
 */
\```

### 🟡 SHOULD - 提交信息标注

\```
feat(auth): 添加 OAuth2 认证支持

AI-Assisted: yes
AI-Tool: GitHub Copilot v2
AI-Reviewed: yes
\```

## 代码质量要求

### 🔴 MUST - 通过自动化检查

- ESLint: 0 errors, 0 warnings
- TypeScript: strict mode
- 测试覆盖率: ≥ 80%

### 🟡 SHOULD - 函数规范

- 函数长度: ≤ 50 行
- 参数数量: ≤ 5 个
- 圈复杂度: ≤ 10

## AI 代码审查清单

### 🔴 MUST - 人工审查要点

- [ ] 无硬编码密钥/密码
- [ ] 输入验证完整
- [ ] 错误处理正确
- [ ] 无 SQL 注入风险
- [ ] 敏感数据已加密
- [ ] 权限检查已实现
- [ ] 无 AI 幻觉（虚构 API）
```

# 代码审查流程

## 审查流程

\```
PR 提交
   │
   ▼
CI 自动检查 (ESLint + 安全扫描)
   │ 失败 → 修复后重新提交
   ▼
AI 自动审查
   │ 发现问题 → 添加评论
   ▼
人工 Review
   │ 需要修改 → 讨论 → 修改
   ▼
合并代码
\```

## Review 分配

### 🔴 MUST - AI 代码必须人工 Review

- AI 生成的代码必须至少 1 人 review
- 安全相关代码必须 2 人 review
- 架构变更必须 tech lead review

### 🟡 SHOULD - Review 者能力要求

- 熟悉 AI 编程工具
- 了解常见 AI 代码问题
- 掌握安全审查要点

## Review 检查清单

- [ ] AI 标注完整

- [ ] 测试覆盖充分

### 🟡 SHOULD - 检查项

```markdown
# 安全合规规范

## 安全红线

### 🔴 MUST NOT - 绝对禁止

1. 硬编码任何密钥、密码、Token
2. 将 .env 文件提交到仓库
3. 使用公共 API 发送敏感数据
4. AI 生成代码不审查直接上线
5. 使用未授权的 AI 工具

### 🔴 MUST - 必须执行

1. 使用 Gitleaks 扫描每次提交
2. 许可证合规检查
3. 依赖漏洞扫描
4. 敏感文件排除配置

## 合规检查

### 自动化检查

\```yaml
# CI 中必须配置的检查
- name: Secret Detection
  run: gitleaks detect

- name: License Check
  run: npx license-checker --failOn "GPL-3.0;AGPL-3.0"

- name: Dependency Audit
  run: npm audit --audit-level=high
\```

### 人工检查

- [ ] 安全敏感功能必须安全团队 review
- [ ] 数据处理必须符合隐私政策
- [ ] 第三方集成必须经过安全评估
```

## 6. 常见错误

### ❌ 锄误 1：规范过于复杂

```
问题：规范文档 100+ 页，没人愿意读

解决：
- 核心规范控制在 10 页以内
- 详细内容放附录
- 提供快速入门指南
- 使用检查清单替代长篇文字
```

### ❌ 错误 2：规范不更新

```
问题：规范写完就再也不更新

解决：
- 指定维护者
- 季度审查机制
- 变更必须走 PR
- 记录变更历史
```

### ❌ 错误 3：没有配套工具

```
问题：规范要求很多但没有工具支持

解决：
- CI 自动化检查
- IDE 插件辅助
- 模板和脚本支持
- 看板和报告自动化
```

### ❌ 错误 4：一刀切执行

```
问题：所有项目、所有人都用同一套标准

解决：
- 区分项目类型（生产/实验）
- 区分代码类型（核心/辅助）
- 灵活调整规范等级
- 提供例外申请流程
```

## 9. 练习

### 练习 1：编写完整规范（120 分钟）

根据本课模板，为你的团队编写一份完整的 AI 编程规范：

1. README.md - 规范概览
2. 至少 5 个章节文档
3. 至少 2 个配套模板
4. 落地检查清单

### 练习 2：规范评审（60 分钟）

与其他学员互相评审规范文档：

1. 检查完整性
2. 评估可执行性
3. 提出改进建议
