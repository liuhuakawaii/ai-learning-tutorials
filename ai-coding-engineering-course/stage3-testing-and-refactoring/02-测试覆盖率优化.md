## 1. 覆盖率指标详解

```
┌─────────────────────────────────────────────────────────────┐
│                    覆盖率指标体系                             │
├──────────────┬──────────────────────────────────────────────┤
│ 行覆盖率     │ 每一行可执行代码是否都被执行                   │
│ (Line)       │ 最直观，但可能遗漏分支                         │
├──────────────┼──────────────────────────────────────────────┤
│ 分支覆盖率   │ 每个 if/else、switch/case 分支是否都被覆盖     │
│ (Branch)     │ 最能发现遗漏的测试场景                         │
├──────────────┼──────────────────────────────────────────────┤
│ 函数覆盖率   │ 每个函数是否都被调用过                         │
│ (Function)   │ 发现"写了但从未测试"的函数                     │
├──────────────┼──────────────────────────────────────────────┤
│ 语句覆盖率   │ 每条语句是否都被执行                           │
│ (Statement)  │ 类似行覆盖率，但处理多语句一行的情况            │
└──────────────┴──────────────────────────────────────────────┘

优先级：分支覆盖率 > 行覆盖率 > 语句覆盖率 > 函数覆盖率
```

### 分支覆盖的重要性

```typescript
// 这个函数行覆盖率可能是 100%，但分支覆盖率只有 50%
function divide(a: number, b: number): number {
  if (b === 0) {          // ← 这个分支可能没测到
    throw new Error('Division by zero');
  }
  return a / b;            // ← 这行覆盖了
}

// 只测试了 divide(10, 2)，行覆盖率 100%，但 if 分支没覆盖！
```

## 3. AI 辅助覆盖率分析

### 3.1 Prompt：分析未覆盖代码

```
以下是函数代码和覆盖率报告中的 Missing 列。
请分析每个未覆盖行可能需要的测试场景。

代码文件：src/utils/validator.ts
未覆盖行：15, 22-25, 38-42

[粘贴完整代码]

请为每个未覆盖的行/分支生成补充测试用例。
```

### 3.2 实战示例

**被测代码：**

```typescript
// src/utils/validator.ts

export function validateAge(input: unknown): number {
  if (typeof input !== 'number' && typeof input !== 'string') {
    throw new TypeError('输入必须是数字或字符串');
  }

  const age = typeof input === 'string' ? parseInt(input, 10) : input;

  if (isNaN(age)) {
    throw new TypeError('年龄必须是有效数字');
  }

  if (age < 0) {
    throw new RangeError('年龄不能为负数');
  }

  if (age > 150) {
    throw new RangeError('年龄不能超过 150');
  }

  return Math.floor(age);
}
```

**覆盖率报告：**

```
validateAge  Branch: 60%  Missing: L15, L22-25, L38-42
```

**AI 分析结果：**

```
未覆盖的分支分析：

L15: typeof input !== 'number' && typeof input !== 'string'
     → 缺少测试：传入 boolean/null/undefined/object

L22-25: isNaN(age) 分支
     → 缺少测试：传入无法解析的字符串如 "abc"

L38-42: age > 150 分支
     → 缺少测试：传入超过 150 的值
```

**AI 生成的补充测试：**

```typescript
describe('validateAge - 补充覆盖', () => {
  // 覆盖 L15: 非数字/非字符串类型
  it('传入布尔值抛出 TypeError', () => {
    expect(() => validateAge(true)).toThrow(TypeError);
  });

  it('传入 null 抛出 TypeError', () => {
    expect(() => validateAge(null)).toThrow(TypeError);
  });

  it('传入 undefined 抛出 TypeError', () => {
    expect(() => validateAge(undefined)).toThrow(TypeError);
  });

  it('传入对象抛出 TypeError', () => {
    expect(() => validateAge({})).toThrow(TypeError);
  });

  // 覆盖 L22-25: NaN 分支
  it('传入不可解析字符串抛出 TypeError', () => {
    expect(() => validateAge('abc')).toThrow('有效数字');
  });

  it('传入空字符串抛出 TypeError', () => {
    expect(() => validateAge('')).toThrow('有效数字');
  });

  // 覆盖 L38-42: age > 150 分支
  it('传入 151 抛出 RangeError', () => {
    expect(() => validateAge(151)).toThrow('150');
  });

  it('传入 200 抛出 RangeError', () => {
    expect(() => validateAge(200)).toThrow('150');
  });
});
```

## 4. 边界值分析法

### 4.1 边界值分类

```
┌──────────────────────────────────────────────────────────────┐
│                    边界值分析法                                │
├────────────────┬─────────────────────────────────────────────┤
│ 数值边界       │ 0, -1, 1, MAX_VALUE, MIN_VALUE             │
├────────────────┼─────────────────────────────────────────────┤
│ 字符串边界     │ "", 单字符, 超长字符串, 特殊字符             │
├────────────────┼─────────────────────────────────────────────┤
│ 数组边界       │ [], 单元素, 大量元素                        │
├────────────────┼─────────────────────────────────────────────┤
│ 布尔边界       │ true, false, truthy, falsy                  │
├────────────────┼─────────────────────────────────────────────┤
│ null/undef     │ null, undefined, 0, "", false, NaN          │
├────────────────┼─────────────────────────────────────────────┤
│ 日期边界       │ 闰年/非闰年, 月末, 年末, 时区                │
├────────────────┼─────────────────────────────────────────────┤
│ 集合边界       │ 空集, 单元素集, 重复元素                    │
└────────────────┴─────────────────────────────────────────────┘
```

### 4.2 AI Prompt：边界值测试生成

```
请用边界值分析法为以下函数生成测试。

规则：
1. 数值参数：测试 min-1, min, min+1, mid, max-1, max, max+1
2. 字符串参数：测试 "", "a", 正常值, 超长值, 特殊字符
3. 数组参数：测试 [], [单元素], [多元素], null
4. 可选参数：测试提供和不提供两种情况

函数签名：
function paginate(items: any[], page: number, pageSize: number): {
  data: any[];
  total: number;
  totalPages: number;
  hasMore: boolean;
}
```

### 4.3 AI 生成的边界值测试

```typescript
describe('paginate 边界值测试', () => {
  const items = Array.from({ length: 100 }, (_, i) => `item-${i}`);

  describe('page 参数边界', () => {
    it('page 为 0 时返回第一页数据', () => {
      const result = paginate(items, 0, 10);
      expect(result.data).toHaveLength(10);
      expect(result.data[0]).toBe('item-0');
    });

    it('page 为 1 时返回第一页数据', () => {
      const result = paginate(items, 1, 10);
      expect(result.data[0]).toBe('item-0');
    });

    it('page 为负数时返回第一页数据', () => {
      const result = paginate(items, -1, 10);
      expect(result.data).toHaveLength(10);
    });

    it('page 超过总页数时返回空数组', () => {
      const result = paginate(items, 100, 10);
      expect(result.data).toHaveLength(0);
    });

    it('page 为小数时向下取整', () => {
      const result = paginate(items, 1.5, 10);
      expect(result.data[0]).toBe('item-0');
    });
  });

  describe('pageSize 参数边界', () => {
    it('pageSize 为 0 时返回空数组', () => {
      const result = paginate(items, 1, 0);
      expect(result.data).toHaveLength(0);
    });

    it('pageSize 为 1 时返回单个元素', () => {
      const result = paginate(items, 1, 1);
      expect(result.data).toHaveLength(1);
    });

    it('pageSize 大于总数时返回所有元素', () => {
      const result = paginate(items, 1, 200);
      expect(result.data).toHaveLength(100);
    });

    it('pageSize 为负数时返回空数组', () => {
      const result = paginate(items, 1, -5);
      expect(result.data).toHaveLength(0);
    });
  });

  describe('items 参数边界', () => {
    it('空数组返回空结果', () => {
      const result = paginate([], 1, 10);
      expect(result.data).toHaveLength(0);
      expect(result.total).toBe(0);
      expect(result.totalPages).toBe(0);
    });

    it('单元素数组正确分页', () => {
      const result = paginate(['only'], 1, 10);
      expect(result.data).toHaveLength(1);
      expect(result.totalPages).toBe(1);
    });
  });

  describe('返回值正确性', () => {
    it('total 等于原始数组长度', () => {
      const result = paginate(items, 1, 10);
      expect(result.total).toBe(100);
    });

    it('totalPages 向上取整', () => {
      const result = paginate(items, 1, 30);
      expect(result.totalPages).toBe(4); // 100/30 = 3.33 → 4
    });

    it('最后一页 hasMore 为 false', () => {
      const result = paginate(items, 10, 10);
      expect(result.hasMore).toBe(false);
    });

    it('非最后一页 hasMore 为 true', () => {
      const result = paginate(items, 1, 10);
      expect(result.hasMore).toBe(true);
    });
  });
});
```

## 5. 覆盖率提升策略

### 5.1 系统性提升流程

```
覆盖率提升工作流：

  ┌─────────────┐     ┌──────────────┐     ┌──────────────┐
  │ 1. 运行      │     │ 2. 分析      │     │ 3. 生成      │
  │ 覆盖率报告   │ ──→ │ 未覆盖行     │ ──→ │ 补充测试     │
  └─────────────┘     └──────────────┘     └──────────────┘
        │                    │                    │
        ▼                    ▼                    ▼
  得到 Missing 行号    识别分支/边界     AI 生成 + 人工审查

  ┌─────────────┐     ┌──────────────┐     ┌──────────────┐
  │ 4. 运行      │     │ 5. 验证      │     │ 6. 重复      │
  │ 补充测试     │ ──→ │ 覆盖率提升   │ ──→ │ 直到达标     │
  └─────────────┘     └──────────────┘     └──────────────┘
        │                    │                    │
        ▼                    ▼                    ▼
  确认全部通过        检查新 Missing     90%+ 则完成
```

### 5.2 常见遗漏场景

```typescript
// 场景 1：错误处理分支
try {
  await riskyOperation();
} catch (error) {        // ← 这个 catch 经常没测到
  handleError(error);
}

// 场景 2：可选参数默认值
function create(options?: Config) {
  const config = options ?? {};  // ← 不传参数的路径
}

// 场景 3：类型守卫
if (Array.isArray(data)) {  // ← 数组分支
  return data.map(transform);
} else {                    // ← 非数组分支
  return [transform(data)];
}

// 场景 4：链式调用中的空值
const result = user?.profile?.address?.city;  // ← 任一为 undefined 的路径
```

## 6. CI 覆盖率卡点

### 6.1 Jest 覆盖率阈值配置

```json
// jest.config.ts
export default {
  coverageThreshold: {
    global: {
      branches: 80,
      functions: 85,
      lines: 90,
      statements: 90,
    },
    // 特定文件更高要求
    './src/utils/': {
      branches: 90,
      functions: 95,
      lines: 95,
      statements: 95,
    },
  },
};
```

### 6.2 pytest 覆盖率配置

```toml
# pyproject.toml
[tool.pytest.ini_options]
addopts = "--cov=src --cov-fail-under=80"

[tool.coverage.run]
source = ["src"]
omit = ["tests/*", "*/migrations/*"]

[tool.coverage.report]
fail_under = 80
show_missing = true
exclude_lines = [
    "pragma: no cover",
    "if TYPE_CHECKING:",
    "if __name__ == .__main__.",
]
```

### 6.3 GitHub Actions 集成


## 常见误区

### 错误 1：盲目追求 100% 覆盖率

```typescript
// ❌ 为了 100% 覆盖率测试无意义的代码
it('getter 返回值', () => {
  const obj = new MyClass();
  expect(obj.name).toBeDefined(); // 这种测试没价值
});

// ✅ 覆盖率是手段不是目的
// 重点测试有业务逻辑的代码，自动生成的 getter/setter 可以跳过
```

### 错误 2：忽略覆盖率报告中的 Missing

```bash
# ❌ 看到 80% 就觉得够了
# ✅ 仔细看 Missing 列，找到关键遗漏
# src/auth.ts  72%  Missing: 30-35, 50-58
#                         ↑ 这些是安全相关的错误处理！
```

### 错误 3：测试通过但覆盖率不涨

```typescript
// ❌ 条件分支没走到
it('处理错误', async () => {
  // mock 了正常返回，catch 分支从未执行
  mockDb.find.mockResolvedValue({ id: 1 });
  const result = await getUser(1);
  expect(result.id).toBe(1);
});

// ✅ 需要单独测试异常路径
it('数据库错误时抛出异常', async () => {
  mockDb.find.mockRejectedValue(new Error('DB Error'));
  await expect(getUser(1)).rejects.toThrow('DB Error');
});
```

## 工程建议

1. **覆盖率阈值分级管理**：核心模块（支付、认证、数据处理）设 90%+ 门槛，工具函数 85%+，配置文件和入口文件可以放宽到 60%，避免一刀切浪费精力。
2. **用覆盖率报告驱动 Code Review**：PR 中附带覆盖率 diff 报告，重点审查新增/修改代码的分支覆盖情况，而非只看总体百分比是否达标。
3. **定期清理无效测试**：覆盖率高不等于测试质量高，定期用 mutation testing（如 Stryker）验证测试是否真的能捕获 Bug，清理那些"通过但无意义"的测试。
4. **分支覆盖率优先于行覆盖率**：配置 CI 卡点时，优先设置分支覆盖率阈值（如 80%），因为分支未覆盖往往意味着真正的测试盲区。

```typescript
function isValidPassword(password: string): {
  valid: boolean;
  errors: string[];
} {
  const errors: string[] = [];
  if (password.length < 8) errors.push('至少 8 位');
  if (password.length > 128) errors.push('最多 128 位');
  if (!/[A-Z]/.test(password)) errors.push('需要大写字母');
  if (!/[a-z]/.test(password)) errors.push('需要小写字母');
  if (!/[0-9]/.test(password)) errors.push('需要数字');
  return { valid: errors.length === 0, errors };
}
```
