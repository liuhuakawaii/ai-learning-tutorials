# 阶段三报告：输出安全

## 场景引入

某医疗问诊 AI 在回答用户咨询时，偶尔会输出完整的内部配置信息，包括数据库地址、API Key 以及调试日志中的患者记录片段。问题根源在于模型训练数据中混入了开发阶段的调试日志，且系统没有对输出内容做任何安全过滤。一次数据泄露事件后，团队紧急在输出层部署了多检测器管道，对敏感信息、有害内容和代码注入分别进行拦截，才将风险控制住。

## 常见误区

- 只关注输入端安全，认为"输入过滤做好了输出就安全"，忽略了模型本身的不可控行为
- 用正则表达式匹配所有敏感信息，误杀率极高，正常业务回答被频繁拦截
- 将输出检测做成硬拦截而非软拦截，导致用户体验严重下降，最终被业务方绕过
- 忽略上下文语义，只做关键词匹配，无法识别经过改写的敏感信息泄露

## 工程建议

- 构建检测器管道（Pipeline），按风险等级分层处理：先快速规则过滤，再做语义级深度检测
- 对检测结果进行分级处理：高风险直接拦截，中风险二次确认，低风险记录告警
- 建立误报反馈机制，持续用真实流量优化检测规则的精确率和召回率
- 在输出中自动脱敏而非直接拦截，例如将邮箱替换为 `[email protected]`，兼顾安全与可用性
