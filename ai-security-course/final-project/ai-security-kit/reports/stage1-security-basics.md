# 阶段一报告：AI 安全基础

## 场景引入

某金融科技公司的智能客服系统上线后，安全团队发现用户可以通过精心构造的提问，诱导模型泄露内部 API 密钥和数据库连接信息。团队在事故复盘时意识到，项目初期完全忽略了 AI 系统特有的威胁面——传统 Web 安全审计覆盖不到 Prompt 注入、训练数据泄露等新型攻击向量。这次事件促使团队从零开始建立 AI 系统的威胁模型，并引入自动化安全扫描工具，在开发阶段就拦截潜在风险。

## 常见误区

- 认为 AI 系统的安全问题可以完全由传统 WAF/防火墙覆盖，忽略了 Prompt 层面的攻击面
- 只关注模型本身的安全，忽略了上下游供应链（第三方 API、插件、向量数据库）带来的风险
- 将威胁模型分析当作一次性工作，没有在模型升级或功能迭代时重新评估
- 过度依赖单一安全扫描工具，忽视了工具误报和漏报的可能性

## 工程建议

- 在项目立项阶段就引入 STRIDE 或 OWASP Top 10 for LLM 做威胁建模，而非事后补救
- 将安全扫描集成到 CI/CD 流水线中，每次 Prompt 模板变更都自动触发检测
- 建立 AI 系统特有的资产清单，明确哪些数据经过模型、哪些接口暴露给用户
- 定期复盘安全事件，将经验沉淀为检测规则和应急预案
