# Micro SaaS Starter 项目说明

## 场景引入

你想做一个小型 SaaS 产品——比如一个 AI 内容工具站。用户注册后创建项目、上传资料、生成内容，按套餐付费使用。听起来不复杂，但真正动手时你会发现：登录注册只是冰山一角，你还需要团队管理、角色权限、表单验证、数据库迁移、安全防护、性能优化、部署上线、监控告警……每一个环节都有坑。这个毕业项目将带你从零搭建一个生产级的 SaaS 产品模板，把课程中所有知识点串联成一条完整的工程实践链路。

## 项目目标

构建一个小型 SaaS 产品模板。它要包含真实产品必备的账号、团队、权限、数据、支付思路、管理后台和部署流程。

## 内置 scaffold

课程提供一个项目骨架：

```

运行：

```

它包含 App Router 路由结构、Prisma schema、权限矩阵、审计日志页面和阶段报告模板。后续课程会逐步把 scaffold 扩展为完整可运行应用。

## 产品主题

默认主题：AI 内容工具站。用户可以创建项目、上传资料、生成内容、查看历史记录，并根据套餐限制使用额度。

## 验收标准

- 未登录用户不能访问 Dashboard
- 普通成员不能修改团队计费设置
- 表单提交有服务端校验
- 数据列表支持分页、搜索、筛选
- 至少 5 个关键页面通过移动端适配检查
- 生产环境能完成数据库迁移并正常启动
- 内置 scaffold 的 `npm run check` 通过

## 常见误区

1. **一上来就写代码，不做架构设计**：SaaS 产品涉及认证、权限、数据模型、部署等多个模块，不提前设计好数据模型和权限体系，后期返工成本极高。

2. **前端隐藏按钮就等于权限控制**：前端的条件渲染只是用户体验，真正的权限校验必须在 Server Action 和 API Route 中执行。任何绕过前端直接调用 API 的请求都应该被拒绝。

3. **所有组件都用 `'use client'`**：过度使用客户端组件会导致 JS bundle 过大、hydration 时间过长。Dashboard 的列表页、详情页等纯展示组件应该用 Server Component。

4. **忽略表单的服务端校验**：React Hook Form + Zod 的客户端校验只是体验优化，攻击者可以绕过。所有写操作必须在服务端重复校验。

## 工程建议

1. **先完成数据模型和权限矩阵再写功能代码**：Prisma schema 和权限矩阵是整个项目的骨架，先定义清楚 User、Team、Project 等模型的关系和权限规则，再逐步实现功能。

2. **每个阶段用 `npm run check` 验证交付物**：scaffold 提供的验证脚本会检查关键文件是否存在、结构是否正确，确保每个阶段的产出符合预期。

3. **使用 `lib/permissions.ts` 统一管理权限**：将 `can()` 函数作为所有 Server Action 的入口守卫，避免在每个操作中重复编写权限检查逻辑。

4. **部署前用 Docker 在本地模拟生产环境**：在提交部署前，用 `docker-compose up` 在本地运行完整环境（应用 + 数据库），提前发现环境相关的问题。
