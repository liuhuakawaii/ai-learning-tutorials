# 第二课：数据库迁移与种子数据

## 场景引入

你的团队有三个人同时在开发新功能。小 A 给 User 表加了 `avatar` 字段，小 B 给 User 表加了 `phone` 字段，两个人都在本地执行了 `ALTER TABLE`。当他们把代码合并到 main 分支并部署到生产环境时，数据库只有一半的字段——因为手动执行 SQL 没有版本控制，后执行的覆盖了先执行的。产品经理打开后台想测试，发现连管理员账号都没有，因为没有人统一初始化过测试数据。

完成本课学习后，你将能够：

## 一、什么是数据库迁移

### 1.1 迁移的概念

> **数据库迁移是将数据库结构从一个版本变更到另一个版本的过程。** 每次修改 Schema，都需要创建一个迁移来同步数据库。

### 1.2 为什么需要迁移

```
没有迁移：
  → 手动执行 SQL
  → 容易出错
  → 无法追踪历史
  → 团队协作困难

有迁移：
  → 自动生成 SQL
  → 版本控制
  → 可重复执行
  → 团队共享
```

### 1.3 生活类比

```
迁移 = 装修记录

第 1 次装修：添加了厨房
第 2 次装修：扩大了客厅
第 3 次装修：添加了阳台

每次装修都有记录
可以追溯历史
也可以恢复到某个状态
```

## 二、Prisma 迁移

### 2.1 创建迁移

```bash
# 修改 schema.prisma 后
npx prisma migrate dev --name 描述性名称

# 例如
npx prisma migrate dev --name add-user-avatar
```

### 2.2 迁移文件

```
prisma/
├── schema.prisma
└── migrations/
    ├── 20240115100000_init/
    │   └── migration.sql
    ├── 20240116120000_add_user_avatar/
    │   └── migration.sql
    └── migration_lock.toml
```

### 2.3 迁移 SQL 示例

```sql
-- 添加 avatar 字段
ALTER TABLE "User" ADD COLUMN "avatar" TEXT;

-- 创建索引
CREATE INDEX "User_email_idx" ON "User"("email");
```

## 三、迁移命令

### 3.1 开发环境

```bash
# 创建并应用迁移
npx prisma migrate dev

# 重置数据库（删除所有数据）
npx prisma migrate reset

# 查看迁移状态
npx prisma migrate status
```

### 3.2 生产环境

```bash
# 只应用迁移（不创建新的）
npx prisma migrate deploy
```

### 3.3 生成 Prisma Client

```bash
# 修改 schema 后重新生成
npx prisma generate
```

## 四、种子数据

### 4.1 什么是种子数据

> **种子数据是预先填充到数据库中的初始数据，用于开发、测试或初始化。**

### 4.2 创建种子文件

```tsx
// prisma/seed.ts
import { PrismaClient } from '@prisma/client'
import bcrypt from 'bcryptjs'

const prisma = new PrismaClient()

async function main() {
  // 创建管理员用户
  const adminPassword = await bcrypt.hash('admin123', 10)
  const admin = await prisma.user.create({
    data: {
      email: 'admin@example.com',
      name: '管理员',
      password: adminPassword,
      role: 'ADMIN',
    }
  })

  // 创建测试用户
  const userPassword = await bcrypt.hash('user123', 10)
  const user = await prisma.user.create({
    data: {
      email: 'user@example.com',
      name: '测试用户',
      password: userPassword,
    }
  })

  // 创建团队
  const team = await prisma.team.create({
    data: {
      name: '示例团队',
      slug: 'example-team',
      ownerId: admin.id,
      members: {
        create: [
          { userId: admin.id, role: 'OWNER' },
          { userId: user.id, role: 'MEMBER' },
        ]
      }
    }
  })

  // 创建项目
  await prisma.project.create({
    data: {
      name: '示例项目',
      description: '这是一个示例项目',
      teamId: team.id,
      creatorId: admin.id,
    }
  })

  // 创建套餐
  await prisma.plan.createMany({
    data: [
      {
        name: '免费版',
        price: 0,
        limits: JSON.stringify({
          projects: 3,
          members: 5,
          storage: 100 * 1024 * 1024,
        })
      },
      {
        name: '专业版',
        price: 9900,
        limits: JSON.stringify({
          projects: 20,
          members: 20,
          storage: 10 * 1024 * 1024 * 1024,
        })
      },
    ]
  })

  console.log('种子数据创建成功')
}

main()
  .catch(e => {
    console.error(e)
    process.exit(1)
  })
  .finally(async () => {
    await prisma.$disconnect()
  })
```

### 4.3 配置种子命令

```json
// package.json
{
  "prisma": {
    "seed": "ts-node --compiler-options {\"module\":\"CommonJS\"} prisma/seed.ts"
  }
}
```

```bash
# 运行种子
npx prisma db seed
```

## 五、生产环境迁移

### 5.1 迁移流程

```
1. 开发环境修改 schema
2. 创建迁移：npx prisma migrate dev
3. 测试迁移
4. 提交到 git
5. 生产环境部署时自动运行：npx prisma migrate deploy
```

### 5.2 CI/CD 集成

```yaml
# .github/workflows/deploy.yml
jobs:
  deploy:
    steps:
      - uses: actions/checkout@v3

      - name: Setup Node
        uses: actions/setup-node@v3
        with:
          node-version: '18'

      - name: Install dependencies
        run: npm ci

      - name: Run migrations
        run: npx prisma migrate deploy
        env:
          DATABASE_URL: ${{ secrets.DATABASE_URL }}

      - name: Deploy
        run: npm run build && npm run start
```

## 六、处理迁移问题

### 6.1 迁移冲突

```bash
# 如果团队成员创建了冲突的迁移
npx prisma migrate resolve --applied "迁移名称"

# 或重置
npx prisma migrate reset
```

### 6.2 数据迁移

```tsx
// 需要迁移数据时，创建自定义迁移
// prisma/migrations/20240117_data_migration/migration.sql

-- 示例：将 name 字段拆分为 firstName 和 lastName
-- 先添加新字段
ALTER TABLE "User" ADD COLUMN "firstName" TEXT;
ALTER TABLE "User" ADD COLUMN "lastName" TEXT;

-- 迁移数据
UPDATE "User" SET
  "firstName" = SPLIT_PART("name", ' ', 1),
  "lastName" = SPLIT_PART("name", ' ', 2);

-- 删除旧字段（在确认数据正确后）
-- ALTER TABLE "User" DROP COLUMN "name";
```

## 七、备份与恢复

### 7.1 数据库备份

```bash
# PostgreSQL 备份
pg_dump -U username -d dbname > backup.sql

# 恢复
psql -U username -d dbname < backup.sql
```

### 7.2 自动备份脚本

```bash
#!/bin/bash
# backup.sh

DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_DIR="/backups"

pg_dump -U $DB_USER -d $DB_NAME > "$BACKUP_DIR/backup_$DATE.sql"

# 保留最近 7 天的备份
find $BACKUP_DIR -name "backup_*.sql" -mtime +7 -delete
```

## 九、常见误区

1. **在生产环境用 `prisma migrate dev`**：`migrate dev` 会创建新的迁移文件并可能重置数据库，这在生产环境是灾难性的。生产环境应该只用 `prisma migrate deploy` 应用已有的迁移。

2. **迁移脚本直接删除或重命名字段**：直接 `DROP COLUMN` 或 `RENAME COLUMN` 会导致旧版本代码立即报错。应该分三步：先加新字段 → 部署新代码同时读写新旧字段 → 确认无问题后删除旧字段。

3. **种子数据中包含真实密码**：种子数据的测试账号密码（如 `admin123`）绝不应该出现在生产环境。种子脚本应该只在开发环境运行，生产环境的管理员账号通过安全流程创建。

4. **不备份就执行迁移**：任何数据库迁移前都应该先备份。如果迁移失败或数据丢失，备份是唯一的恢复手段。

## 十、工程建议

1. **迁移文件纳入 Git 版本控制**：`prisma/migrations/` 目录必须提交到 Git，确保团队成员和 CI/CD 环境使用完全相同的迁移历史。

2. **CI/CD 中在部署前自动运行迁移**：在 GitHub Actions 中将 `prisma migrate deploy` 作为部署前的必须步骤，确保数据库结构与代码版本匹配。

3. **种子数据使用 `upsert` 避免重复**：种子脚本用 `upsert` 代替 `create`，这样重复运行不会产生重复数据或报错。

4. **生产数据库配置自动备份**：使用 PostgreSQL 的 `pg_dump` 或云服务的自动备份功能，每天至少备份一次，并定期测试恢复流程。
