## 一、为什么需要日志

### 1.1 日志的作用

```
问题排查：
  → 发生错误时，查看日志定位原因
  → 重现问题现场

安全审计：
  → 追踪谁做了什么
  → 发现异常行为

性能分析：
  → 找出慢请求
  → 识别瓶颈

业务分析：
  → 用户行为统计
  → 功能使用情况
```

### 1.2 生活类比

```
日志 = 行车记录仪

记录内容：
  → 时间
  → 位置
  → 速度
  → 事件

用途：
  → 事故调查
  → 保险理赔
  → 行程回顾
```

## 二、日志级别

### 2.1 常用级别

```
ERROR  错误
  → 严重问题，需要立即处理
  → 例子：数据库连接失败、支付失败

WARN   警告
  → 潜在问题，需要关注
  → 例子：API 响应慢、磁盘空间不足

INFO   信息
  → 正常操作记录
  → 例子：用户登录、订单创建

DEBUG  调试
  → 详细的调试信息
  → 例子：函数参数、中间变量
```

## 三、结构化日志

### 3.1 安装日志库

```bash
npm install pino pino-pretty
```

### 3.2 创建日志工具

```tsx
// lib/logger.ts
import pino from 'pino'

const logger = pino({
  level: process.env.LOG_LEVEL || 'info',
  transport: process.env.NODE_ENV === 'development'
    ? { target: 'pino-pretty', options: { colorize: true } }
    : undefined,
  formatters: {
    level: (label) => {
      return { level: label.toUpperCase() }
    },
  },
  timestamp: () => `,"time":"${new Date().toISOString()}"`,
})

export default logger
```

### 3.3 使用日志

```tsx
import logger from '@/lib/logger'

// 基本用法
logger.info('用户登录成功')
logger.error('数据库连接失败')

// 带上下文
logger.info({
  userId: '123',
  action: 'login',
  ip: '192.168.1.1'
}, '用户登录成功')

// 错误日志
try {
  await riskyOperation()
} catch (error) {
  logger.error({
    err: error,
    operation: 'riskyOperation'
  }, '操作失败')
}
```

## 四、在 Next.js 中使用

### 4.1 API 路由日志

```tsx
// app/api/users/route.ts
import logger from '@/lib/logger'
import { NextResponse } from 'next/server'

export async function GET() {
  const startTime = Date.now()

  try {
    const users = await prisma.user.findMany()

    logger.info({
      method: 'GET',
      path: '/api/users',
      duration: Date.now() - startTime,
      count: users.length
    }, '获取用户列表')

    return NextResponse.json(users)
  } catch (error) {
    logger.error({
      err: error,
      method: 'GET',
      path: '/api/users',
      duration: Date.now() - startTime
    }, '获取用户列表失败')

    return NextResponse.json(
      { error: 'Internal Server Error' },
      { status: 500 }
    )
  }
}
```

### 4.2 Server Action 日志

```tsx
'use server'

import logger from '@/lib/logger'

export async function createPost(formData: FormData) {
  const startTime = Date.now()

  try {
    const post = await prisma.post.create({ data })

    logger.info({
      action: 'createPost',
      postId: post.id,
      userId: session.userId,
      duration: Date.now() - startTime
    }, '文章创建成功')

    return { success: true }
  } catch (error) {
    logger.error({
      err: error,
      action: 'createPost',
      userId: session.userId,
      duration: Date.now() - startTime
    }, '文章创建失败')

    return { error: '创建失败' }
  }
}
```

## 五、错误监控

### 5.1 使用 Sentry

```bash
npm install @sentry/nextjs
```

### 5.2 配置 Sentry

```tsx
// sentry.client.config.ts
import * as Sentry from '@sentry/nextjs'

Sentry.init({
  dsn: process.env.SENTRY_DSN,
  tracesSampleRate: 1.0,
  environment: process.env.NODE_ENV,
})
```

```tsx
// sentry.server.config.ts
import * as Sentry from '@sentry/nextjs'

Sentry.init({
  dsn: process.env.SENTRY_DSN,
  tracesSampleRate: 1.0,
  environment: process.env.NODE_ENV,
})
```

### 5.3 手动捕获错误

```tsx
import * as Sentry from '@sentry/nextjs'

try {
  await riskyOperation()
} catch (error) {
  Sentry.captureException(error, {
    tags: {
      component: 'UserProfile',
      action: 'updateProfile',
    },
    extra: {
      userId: user.id,
    },
  })

  throw error
}
```

## 六、日志最佳实践

### 6.1 记录什么

```
必须记录：
  ✅ 错误和异常
  ✅ 认证事件（登录、登出）
  ✅ 权限变更
  ✅ 数据修改操作
  ✅ 外部 API 调用

可选记录：
  → 请求和响应
  → 性能指标
  → 用户行为
```

### 6.2 不要记录什么

```
不要记录：
  ❌ 密码
  ❌ API 密钥
  ❌ 信用卡号
  ❌ 个人敏感信息
  ❌ 大量调试信息（生产环境）
```

### 6.3 日志格式

```json
{
  "level": "INFO",
  "time": "2024-01-15T10:30:00.000Z",
  "message": "用户登录成功",
  "context": {
    "userId": "123",
    "email": "user@example.com",
    "ip": "192.168.1.1"
  },
  "duration": 150
}
```

## 七、告警设置

### 7.1 告警规则

```
错误率告警：
  → 条件：5 分钟内错误率 > 5%
  → 通知：邮件 + 短信

响应时间告警：
  → 条件：平均响应时间 > 2 秒
  → 通知：邮件

服务可用性告警：
  → 条件：服务不可用 > 1 分钟
  → 通知：电话
```

### 7.2 Sentry 告警配置

```
1. 进入 Sentry 项目设置
2. 点击 "Alerts"
3. 创建告警规则：
   - 当新问题出现时
   - 当错误率超过阈值时
   - 当性能下降时
4. 配置通知渠道（邮件、Slack、PagerDuty）
```

## 八、日志分析

### 8.1 常用查询

```sql
-- 查找最近的错误
SELECT * FROM logs
WHERE level = 'ERROR'
  AND time > NOW() - INTERVAL '1 hour'
ORDER BY time DESC;

-- 统计错误数量
SELECT
  DATE_TRUNC('hour', time) as hour,
  COUNT(*) as error_count
FROM logs
WHERE level = 'ERROR'
GROUP BY hour
ORDER BY hour DESC;
```
