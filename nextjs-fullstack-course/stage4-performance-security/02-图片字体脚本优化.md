# 第二课：图片、字体、脚本优化

## 场景引入

你的项目首页有一张 3MB 的 Banner 图，直接用 `<img>` 标签加载，手机用户打开页面时白屏长达 5 秒。同时，页面通过 `<link>` 从 Google Fonts 加载中文字体，产生了额外的 DNS 查询和 HTTP 请求，字体加载完成前页面显示的是系统默认字体，加载完成后文字突然"闪一下"重新排版。此外，页面引入了完整的 lodash 和 FontAwesome 库，打包后 JS 体积超过 800KB，其中真正用到的不到 20%。

## 学习目标

完成本课学习后，你将能够：

1. 使用 Next.js Image 组件优化图片
2. 优化字体加载
3. 管理第三方脚本
4. 减少包体积

## 一、图片优化

### 1.1 使用 Image 组件

```tsx
import Image from 'next/image'

// 基础用法
<Image
  src="/hero.jpg"
  alt="Hero"
  width={800}
  height={400}
/>

// 填充容器
<Image
  src="/hero.jpg"
  alt="Hero"
  fill
  className="object-cover"
/>

// 外部图片
<Image
  src="https://example.com/image.jpg"
  alt="External"
  width={400}
  height={300}
/>
```

### 1.2 Image 组件的优势

```
自动优化：
  ✅ 自动调整大小
  ✅ 自动转换格式（WebP）
  ✅ 懒加载
  ✅ 防止 CLS（布局偏移）

性能提升：
  → 图片体积减少 30-50%
  → 按需加载，不阻塞首屏
  → 自动生成 srcset，适配不同屏幕
```

### 1.3 响应式图片

```tsx
<Image
  src="/hero.jpg"
  alt="Hero"
  fill
  sizes="(max-width: 768px) 100vw, (max-width: 1200px) 50vw, 33vw"
  className="object-cover"
/>
```

### 1.4 图片占位符

```tsx
// 模糊占位符
<Image
  src="/hero.jpg"
  alt="Hero"
  width={800}
  height={400}
  placeholder="blur"
  blurDataURL="data:image/jpeg;base64,/9j/4AAQ..."
/>

// 自动生成模糊占位符
import { getPlaiceholder } from 'plaiceholder'

const { base64 } = await getPlaiceholder(buffer)

<Image
  src={src}
  alt="..."
  placeholder="blur"
  blurDataURL={base64}
/>
```

## 二、字体优化

### 2.1 使用 next/font

```tsx
// app/layout.tsx
import { Inter, Noto_Sans_SC } from 'next/font/google'

const inter = Inter({
  subsets: ['latin'],
  display: 'swap',
})

const notoSansSC = Noto_Sans_SC({
  subsets: ['latin'],
  weight: ['400', '700'],
  display: 'swap',
})

export default function RootLayout({ children }) {
  return (
    <html lang="zh" className={notoSansSC.className}>
      <body className={inter.className}>
        {children}
      </body>
    </html>
  )
}
```

### 2.2 本地字体

```tsx
import localFont from 'next/font/local'

const myFont = localFont({
  src: './fonts/MyFont.woff2',
  display: 'swap',
})

export default function RootLayout({ children }) {
  return (
    <html className={myFont.className}>
      <body>{children}</body>
    </html>
  )
}
```

### 2.3 字体优化的好处

```
next/font 的优势：
  ✅ 零布局偏移（CLS）
  ✅ 无额外网络请求
  ✅ 自动子集化（只包含使用的字符）
  ✅ 内联到 CSS 中
```

## 三、第三方脚本

### 3.1 使用 next/script

```tsx
import Script from 'next/script'

export default function Page() {
  return (
    <>
      <Script
        src="https://example.com/analytics.js"
        strategy="afterInteractive"
      />
      <Script
        src="https://example.com/chat.js"
        strategy="lazyOnload"
      />
    </>
  )
}
```

### 3.2 加载策略

```
strategy 选项：

beforeInteractive
  → 在页面可交互之前加载
  → 用于：关键 polyfill

afterInteractive（默认）
  → 在页面可交互后立即加载
  → 用于：分析、聊天窗口

lazyOnload
  → 在浏览器空闲时加载
  → 用于：非关键脚本
```

### 3.3 Google Analytics 示例

```tsx
// app/layout.tsx
import Script from 'next/script'

export default function RootLayout({ children }) {
  return (
    <html>
      <head>
        <Script
          src={`https://www.googletagmanager.com/gtag/js?id=${process.env.NEXT_PUBLIC_GA_ID}`}
          strategy="afterInteractive"
        />
        <Script id="google-analytics" strategy="afterInteractive">
          {`
            window.dataLayer = window.dataLayer || [];
            function gtag(){dataLayer.push(arguments);}
            gtag('js', new Date());
            gtag('config', '${process.env.NEXT_PUBLIC_GA_ID}');
          `}
        </Script>
      </head>
      <body>{children}</body>
    </html>
  )
}
```

## 四、减少包体积

### 4.1 分析包大小

```bash
# 安装分析工具
npm install -D @next/bundle-analyzer

# next.config.js
const withBundleAnalyzer = require('@next/bundle-analyzer')({
  enabled: process.env.ANALYZE === 'true',
})

module.exports = withBundleAnalyzer({})

# 运行分析
ANALYZE=true npm run build
```

### 4.2 按需导入

```tsx
// ❌ 导入整个库
import _ from 'lodash'
_.debounce(fn, 300)

// ✅ 只导入需要的函数
import debounce from 'lodash/debounce'
debounce(fn, 300)

// ❌ 导入整个图标库
import { FaBeer, FaCoffee, ... } from 'react-icons/fa'

// ✅ 只导入使用的图标
import { FaBeer } from 'react-icons/fa'
```

### 4.3 动态导入

```tsx
// 不需要首屏的组件
const HeavyComponent = dynamic(() => import('./HeavyComponent'), {
  loading: () => <Skeleton />,
  ssr: false,
})
```

## 七、常见误区

1. **直接用 `<img>` 标签就完事了**：Next.js 的 `<Image>` 组件不只是换了标签名，它自动做格式转换（WebP）、响应式 srcset、懒加载和尺寸预留，这些是原生 `<img>` 无法提供的。

2. **字体加载用 `<link>` 引入 Google Fonts**：外部字体链接会产生额外的 DNS 查询、TCP 连接和 HTTP 请求，在慢网络下会导致长时间的 FOIT（不可见文本闪烁）或 FOUT（无样式文本闪烁）。`next/font` 将字体内联到 CSS 中，完全消除这些开销。

3. **用 `import _ from 'lodash'` 导入整个工具库**：lodash 完整包约 70KB gzipped，而你可能只用到了 `debounce` 一个函数（不到 1KB）。按需导入 `import debounce from 'lodash/debounce'` 可以大幅减少包体积。

4. **所有脚本都用默认的 `afterInteractive` 策略**：非关键脚本（如聊天窗口、热力图分析）应该用 `lazyOnload` 策略，在浏览器空闲时才加载，避免阻塞首屏交互。

## 八、工程建议

1. **为首屏图片设置 `priority` 属性**：LCP 元素通常是首屏大图或 Hero 区域，给它加上 `priority` 属性让 Next.js 跳过懒加载，优先预加载该图片。

2. **用 `@next/bundle-analyzer` 定期审计包体积**：在 CI 中运行 `ANALYZE=true npm run build`，检查是否有意外的大依赖被引入，设置包体积预算告警。

3. **中文字体使用 `next/font/google` 的子集化**：`Noto_Sans_SC` 等中文字体文件很大，`next/font` 会自动根据页面使用的字符进行子集化，只打包实际用到的字符。

4. **第三方脚本优先选择有 npm 包的方案**：比如分析服务优先用 `@vercel/analytics` 而非 `<script>` 标签引入，这样可以利用 Tree Shaking 和代码分割。
