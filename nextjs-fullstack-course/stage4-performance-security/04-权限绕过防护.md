1. 理解常见的权限绕过攻击
2. 实现服务端权限验证

4. 安全地处理资源访问

## 一、常见权限绕过

### 1.1 水平越权

```
攻击场景：
  用户 A 可以访问自己的数据
  用户 A 尝试访问用户 B 的数据

例子：
  GET /api/users/123/orders  → 用户 A 的订单
  GET /api/users/456/orders  → 用户 B 的订单（不应该允许）
```

### 1.2 垂直越权

```
攻击场景：
  普通用户尝试执行管理员操作

例子：
  POST /api/admin/users/delete  → 只有管理员能访问
  普通用户直接调用这个接口
```

### 1.3 生活类比

```
水平越权 = 进入别人的房间
  你有自己的房间钥匙
  但你尝试用它开邻居的门

垂直越权 = 冒充管理员
  你是普通员工
  但你尝试进入只有经理能进的区域
```

## 二、服务端验证

### 2.1 核心原则

```
永远不要信任客户端

❌ 错误做法：
  前端检查权限 → 显示/隐藏按钮
  用户可以绕过前端，直接调用 API

✅ 正确做法：
  前端检查权限 → 显示/隐藏按钮（用户体验）
  后端检查权限 → 拒绝未授权操作（安全保证）
```

### 2.2 在 Server Actions 中验证

```tsx
'use server'

export async function updatePost(postId: string, formData: FormData) {
  // 1. 获取当前用户
  const session = await getSession()
  if (!session.userId) {
    throw new Error('未登录')
  }

  // 2. 获取资源
  const post = await prisma.post.findUnique({
    where: { id: postId }
  })

  if (!post) {
    throw new Error('资源不存在')
  }

  // 3. 检查权限
  if (post.authorId !== session.userId) {
    throw new Error('没有权限')
  }

  // 4. 执行操作
  await prisma.post.update({
    where: { id: postId },
    data: { title: formData.get('title') as string }
  })
}
```

## 三、权限检查模式

### 3.1 资源所有权检查

```tsx
async function checkOwnership(
  resourceType: string,
  resourceId: string,
  userId: string
): Promise<boolean> {
  switch (resourceType) {
    case 'post':
      const post = await prisma.post.findUnique({
        where: { id: resourceId }
      })
      return post?.authorId === userId

    case 'project':
      const project = await prisma.project.findUnique({
        where: { id: resourceId }
      })
      return project?.creatorId === userId

    default:
      return false
  }
}
```

### 3.2 团队角色检查

```tsx
async function checkTeamPermission(
  teamId: string,
  userId: string,
  requiredRole: 'OWNER' | 'ADMIN' | 'MEMBER'
): Promise<boolean> {
  const membership = await prisma.membership.findUnique({
    where: {
      userId_teamId: { userId, teamId }
    }
  })

  if (!membership) return false

  const roleHierarchy = {
    OWNER: 3,
    ADMIN: 2,
    MEMBER: 1
  }

  return roleHierarchy[membership.role] >= roleHierarchy[requiredRole]
}
```

### 3.3 组合检查

```tsx
export async function requirePermission({
  teamId,
  resourceId,
  action
}: {
  teamId?: string
  resourceId?: string
  action: string
}) {
  const session = await getSession()
  if (!session.userId) {
    throw new Error('未登录')
  }

  const userId = session.userId

  // 检查团队权限
  if (teamId) {
    const hasTeamPermission = await checkTeamPermission(
      teamId,
      userId,
      getRequiredRole(action)
    )
    if (!hasTeamPermission) {
      throw new Error('团队权限不足')
    }
  }

  // 检查资源所有权
  if (resourceId) {
    const isOwner = await checkOwnership(
      getResourceType(action),
      resourceId,
      userId
    )
    if (!isOwner) {
      throw new Error('资源权限不足')
    }
  }

  return { userId }
}
```

## 四、安全的 API 设计

### 4.1 不要暴露内部 ID

```tsx
// ❌ 不好：暴露数据库 ID
GET /api/users/123

// ✅ 好：使用 UUID
GET /api/users/a1b2c3d4-e5f6-7890-abcd-ef1234567890
```

### 4.2 验证关联资源

```tsx
// ❌ 不好：只检查资源是否存在
export async function updateProject(projectId: string, data: any) {
  const project = await prisma.project.findUnique({
    where: { id: projectId }
  })
  if (!project) throw new Error('Not found')
  // 直接更新，没有检查用户是否有权限
}

// ✅ 好：检查用户是否有权限访问该资源
export async function updateProject(projectId: string, data: any) {
  const session = await getSession()
  const project = await prisma.project.findFirst({
    where: {
      id: projectId,
      team: {
        members: {
          some: { userId: session.userId }
        }
      }
    }
  })
  if (!project) throw new Error('Not found or no permission')
}
```

## 五、中间件防护

### 5.1 路由级防护

```tsx
// middleware.ts
import { NextResponse } from 'next/server'
import { getIronSession } from 'iron-session'

export async function middleware(request) {
  const session = await getIronSession(request, NextResponse.next(), sessionOptions)

  // 保护 Dashboard 路由
  if (request.nextUrl.pathname.startsWith('/dashboard')) {
    if (!session.userId) {
      return NextResponse.redirect(new URL('/login', request.url))
    }
  }

  // 保护 Admin 路由
  if (request.nextUrl.pathname.startsWith('/admin')) {
    if (!session.userId || session.role !== 'ADMIN') {
      return NextResponse.redirect(new URL('/dashboard', request.url))
    }
  }

  return NextResponse.next()
}
```

### 5.2 API 路由防护

```tsx
// app/api/admin/route.ts
import { NextResponse } from 'next/server'
import { getSession } from '@/lib/session'

export async function GET() {
  const session = await getSession()

  if (!session.userId) {
    return NextResponse.json({ error: 'Unauthorized' }, { status: 401 })
  }

  if (session.role !== 'ADMIN') {
    return NextResponse.json({ error: 'Forbidden' }, { status: 403 })
  }

  // 执行管理员操作
}
```

## 六、常见漏洞

### 6.1 IDOR（不安全的直接对象引用）

```tsx
// ❌ 漏洞：用户可以访问任何资源
const order = await prisma.order.findUnique({
  where: { id: orderId }  // orderId 来自用户输入
})

// ✅ 修复：添加用户条件
const order = await prisma.order.findFirst({
  where: {
    id: orderId,
    userId: session.userId  // 确保只能访问自己的订单
  }
})
```

### 6.2 批量赋值

```tsx
// ❌ 漏洞：用户可以修改任意字段
await prisma.user.update({
  where: { id: userId },
  data: req.body  // 可能包含 role: 'ADMIN'
})

// ✅ 修复：只允许修改特定字段
await prisma.user.update({
  where: { id: userId },
  data: {
    name: req.body.name,
    email: req.body.email,
    // 不包含 role 等敏感字段
  }
})
```

async function logSecurityEvent({

  action: string
  resource: string

## 九、小结

```
本课核心要点：

1. 永远不要信任客户端，所有权限检查在服务端执行
2. 水平越权：访问其他用户的资源
3. 垂直越权：执行超出权限的操作
4. 使用 findFirst 而不是 findUnique，添加用户条件
5. 记录安全事件用于审计
```
