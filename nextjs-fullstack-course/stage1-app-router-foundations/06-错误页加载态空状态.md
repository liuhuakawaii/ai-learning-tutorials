# 第六课：错误页、加载态、空状态

## 场景引入

你的 Dashboard 页面上线后收到大量用户反馈："页面打开后一直是白的，是不是挂了？"你排查发现，数据库查询偶尔会超时 3-5 秒，这段时间用户看到的是一片空白——没有加载提示，没有错误信息，什么都没有。更糟糕的是，当某个 API 真的报错时，整个页面直接崩溃，用户只能看到浏览器的默认错误页面。你需要为每一种异常状态（加载中、出错、无数据）都设计合理的 UI，让用户始终知道发生了什么、能做什么。

## 学习目标

完成本课学习后，你将能够：

1. 掌握 loading.tsx 的使用和最佳实践
2. 学会 error.tsx 的错误边界处理
3. 理解 not-found.tsx 的 404 处理
4. 设计良好的空状态 UI
5. 知道 Suspense 与这些特殊文件的关系

## 一、加载状态

### 1.1 loading.tsx 自动加载

当页面数据加载时，Next.js 会自动显示 `loading.tsx`：

```tsx
// app/dashboard/loading.tsx
export default function DashboardLoading() {
  return (
    <div className="animate-pulse space-y-4">
      <div className="h-8 bg-gray-200 rounded w-1/3"></div>
      <div className="h-4 bg-gray-200 rounded w-2/3"></div>
      <div className="h-4 bg-gray-200 rounded w-1/2"></div>
    </div>
  )
}
```

原理等价于：

```tsx
import { Suspense } from 'react'

export default function Layout({ children }) {
  return (
    <Suspense fallback={<DashboardLoading />}>
      {children}
    </Suspense>
  )
}
```

### 1.2 骨架屏设计原则

```tsx
// ❌ 不好的加载状态
<div>加载中...</div>  // 什么信息都没有

// ✅ 好的骨架屏
<div className="animate-pulse">
  {/* 模拟页面结构 */}
  <div className="h-8 bg-gray-200 rounded w-1/3 mb-4"></div>
  <div className="space-y-3">
    <div className="h-4 bg-gray-200 rounded"></div>
    <div className="h-4 bg-gray-200 rounded w-5/6"></div>
    <div className="h-4 bg-gray-200 rounded w-4/6"></div>
  </div>
</div>
```

骨架屏要和实际页面结构相似：

```tsx
// app/dashboard/loading.tsx
export default function Loading() {
  return (
    <div className="animate-pulse">
      {/* 模拟统计卡片 */}
      <div className="grid grid-cols-3 gap-4 mb-8">
        {[1, 2, 3].map(i => (
          <div key={i} className="h-24 bg-gray-200 rounded"></div>
        ))}
      </div>

      {/* 模拟表格 */}
      <div className="space-y-3">
        <div className="h-10 bg-gray-200 rounded"></div>
        {[1, 2, 3, 4, 5].map(i => (
          <div key={i} className="h-12 bg-gray-100 rounded"></div>
        ))}
      </div>
    </div>
  )
}
```

### 1.3 嵌套加载状态

不同层级可以有不同的 loading.tsx：

```
app/
├── layout.tsx
├── loading.tsx              ← 全局加载
├── dashboard/
│   ├── layout.tsx
│   ├── loading.tsx          ← Dashboard 加载
│   └── projects/
│       ├── page.tsx
│       └── loading.tsx      ← 项目列表加载
```

## 二、错误处理

### 2.1 error.tsx 必须是 Client Component

```tsx
// app/dashboard/error.tsx
'use client'

export default function DashboardError({
  error,
  reset
}: {
  error: Error & { digest?: string }
  reset: () => void
}) {
  return (
    <div className="text-center py-12">
      <h2 className="text-xl font-bold mb-4">出错了</h2>
      <p className="text-gray-600 mb-4">
        {error.message || '发生了未知错误'}
      </p>
      <button
        onClick={reset}
        className="px-4 py-2 bg-blue-500 text-white rounded"
      >
        重试
      </button>
    </div>
  )
}
```

### 2.2 错误边界的工作原理

```
组件树：

<RootLayout>
  <DashboardLayout>
    <DashboardPage />  ← 这里抛出错误
  </DashboardLayout>
</RootLayout>

错误处理：

<RootLayout>
  <DashboardLayout>
    <DashboardError />  ← 显示最近的 error.tsx
  </DashboardLayout>
</RootLayout>
```

**注意：** error.tsx 会捕获其**直接子级**的错误，不会捕获布局本身的错误。

### 2.3 不同层级的错误处理

```tsx
// app/error.tsx — 根级错误
'use client'

export default function RootError({ error, reset }) {
  return (
    <html>
      <body>
        <h1>网站出了点问题</h1>
        <p>{error.message}</p>
        <button onClick={reset}>重试</button>
      </body>
    </html>
  )
}

// app/dashboard/error.tsx — Dashboard 级错误
'use client'

export default function DashboardError({ error, reset }) {
  return (
    <div className="p-8">
      <h2>Dashboard 加载失败</h2>
      <p>{error.message}</p>
      <button onClick={reset}>重试</button>
      <a href="/">返回首页</a>
    </div>
  )
}
```

### 2.4 在 Server Component 中抛出错误

```tsx
// app/dashboard/page.tsx
export default async function DashboardPage() {
  try {
    const data = await fetchDashboardData()
    return <Dashboard data={data} />
  } catch (error) {
    // 抛出错误会被最近的 error.tsx 捕获
    throw new Error('获取数据失败')
  }
}
```

## 三、404 处理

### 3.1 not-found.tsx

```tsx
// app/not-found.tsx
export default function NotFound() {
  return (
    <div className="text-center py-20">
      <h1 className="text-6xl font-bold text-gray-300 mb-4">404</h1>
      <h2 className="text-2xl mb-4">页面未找到</h2>
      <p className="text-gray-600 mb-8">
        你要找的页面不存在或已被移除
      </p>
      <a
        href="/"
        className="px-6 py-3 bg-blue-500 text-white rounded"
      >
        返回首页
      </a>
    </div>
  )
}
```

### 3.2 主动触发 404

```tsx
import { notFound } from 'next/navigation'

export default async function BlogPost({ params }) {
  const post = await db.post.findUnique({
    where: { slug: params.slug }
  })

  if (!post) {
    notFound() // 显示最近的 not-found.tsx
  }

  return <article>{post.content}</article>
}
```

### 3.3 嵌套 404

```
app/
├── not-found.tsx           ← 全局 404
├── blog/
│   ├── not-found.tsx       ← 博客专用 404
│   └── [slug]/
│       └── page.tsx
```

```tsx
// app/blog/not-found.tsx
export default function BlogNotFound() {
  return (
    <div>
      <h2>文章不存在</h2>
      <p>这篇博客文章可能已被删除</p>
      <a href="/blog">返回博客列表</a>
    </div>
  )
}
```

## 四、空状态设计

### 4.1 什么是空状态

空状态是指页面没有数据时的展示方式。好的空状态能引导用户采取行动。

```
数据状态：

有数据 → 正常显示列表
无数据 → 空状态 UI
加载中 → 骨架屏
出错 → 错误提示
```

### 4.2 空状态组件

```tsx
// app/components/EmptyState.tsx
export function EmptyState({
  icon,
  title,
  description,
  action
}: {
  icon?: React.ReactNode
  title: string
  description: string
  action?: React.ReactNode
}) {
  return (
    <div className="text-center py-12">
      {icon && <div className="text-4xl mb-4">{icon}</div>}
      <h3 className="text-lg font-medium mb-2">{title}</h3>
      <p className="text-gray-500 mb-6">{description}</p>
      {action}
    </div>
  )
}
```

### 4.3 在页面中使用

```tsx
// app/projects/page.tsx
import { EmptyState } from '@/components/EmptyState'

export default async function ProjectsPage() {
  const projects = await db.project.findMany()

  if (projects.length === 0) {
    return (
      <EmptyState
        icon="📁"
        title="还没有项目"
        description="创建你的第一个项目开始使用"
        action={
          <a href="/projects/new" className="btn btn-primary">
            创建项目
          </a>
        }
      />
    )
  }

  return (
    <ul>
      {projects.map(project => (
        <li key={project.id}>{project.name}</li>
      ))}
    </ul>
  )
}
```

### 4.4 不同场景的空状态

```tsx
// 搜索无结果
<EmptyState
  icon="🔍"
  title="没有找到结果"
  description="试试其他关键词"
/>

// 通知为空
<EmptyState
  icon="🔔"
  title="没有新通知"
  description="有新消息时会在这里显示"
/>

// 收藏夹为空
<EmptyState
  icon="⭐"
  title="收藏夹为空"
  description="浏览内容时点击收藏按钮添加"
  action={<a href="/browse">去浏览</a>}
/>
```

```tsx
          <h2 className="text-lg font-medium mb-4">最近项目</h2>

              <li key={project.id} className="p-4 border rounded">
                {project.name}
              </li>
            ))}
          </ul>
        </div>
      )}
    </div>
  )
}
```

## 常见误区

1. **"loading.tsx 会自动处理所有加载状态"**：`loading.tsx` 只对 Server Component 的异步渲染生效（通过 Suspense）。如果你在 Client Component 中用 `useState` + `useEffect` 获取数据，loading.tsx 不会帮你处理。
2. **"error.tsx 可以捕获 Server Action 的错误"**：error.tsx 捕获的是组件渲染过程中的错误，不是 Server Action 返回的错误对象。Server Action 的错误应该通过 `useActionState` 的返回值在表单中展示。
3. **"空状态就是显示'暂无数据'"**：好的空状态应该引导用户采取行动——显示一个"创建项目"按钮、一段说明文字、或者一个引导流程。单纯的"暂无数据"会让用户不知所措。
4. **"骨架屏越简单越好"**：骨架屏应该尽量模拟真实页面的布局结构（相同的卡片数量、相似的尺寸），这样加载完成后页面不会出现明显的布局跳动。

## 工程建议

1. **按路由层级组织错误边界**：根级 `error.tsx` 处理全局错误，子级 `error.tsx` 处理局部错误。这样某个模块崩溃不会影响整个网站的导航和布局。
2. **error.tsx 中提供有意义的错误信息和重试按钮**：不要只显示"出错了"，展示 `error.message` 让用户知道原因，并提供 `reset()` 重试按钮让用户可以恢复。
3. **骨架屏用 Tailwind 的 `animate-pulse`**：Tailwind 内置的 `animate-pulse` 动画可以直接用在骨架屏的占位元素上，不需要额外写 CSS。
4. **为每种数据状态都设计 UI**：一个列表页面至少要处理四种状态——加载中（骨架屏）、加载失败（错误提示）、无数据（空状态引导）、有数据（正常列表），缺一不可。

## 七、小结

```
本课核心要点：

1. loading.tsx 自动处理加载状态，骨架屏要和实际页面结构相似
2. error.tsx 必须是 Client Component，提供 reset 函数让用户重试
3. not-found.tsx 处理 404，可以用 notFound() 主动触发
4. 空状态要引导用户行动，不只是显示"暂无数据"
5. 不同层级可以有不同的加载、错误和 404 处理
```
