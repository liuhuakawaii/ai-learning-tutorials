# 第二课：路由、布局、模板与页面组织

## 场景引入

你接手了一个已有的 Next.js 项目，发现路由文件夹嵌套了七八层，`layout.tsx` 层层套娃，导航到某个页面时侧边栏会闪烁重建，切换子页面时整个页面都在重新加载。更头疼的是，项目里 `_app.tsx` 和 `app/` 目录混用，路由配置散落在各处，新同事完全看不懂页面之间的层级关系。你需要重新梳理路由和布局的设计，让页面结构清晰、导航流畅、状态不丢失。

## 学习目标

完成本课学习后，你将能够：

1. 理解 App Router 基于文件系统的路由约定
2. 掌握 page.tsx、layout.tsx、template.tsx 的区别和用法
3. 学会使用 loading.tsx 和 error.tsx 处理状态
4. 理解路由分组和私有文件夹
5. 能设计出清晰的页面层级结构

## 一、文件系统路由

### 1.1 核心规则

App Router 的路由由文件夹结构决定。你不需要手动注册路由，创建文件夹就是创建路由。

```
app/
├── page.tsx              → /
├── about/
│   └── page.tsx          → /about
├── blog/
│   ├── page.tsx          → /blog
│   └── [slug]/
│       └── page.tsx      → /blog/hello-world
├── dashboard/
│   ├── page.tsx          → /dashboard
│   ├── settings/
│   │   └── page.tsx      → /dashboard/settings
│   └── projects/
│       └── page.tsx      → /dashboard/projects
└── api/
    └── users/
        └── route.ts      → /api/users
```

**规则：只有 `page.tsx` 文件会让路由可被访问。** 一个文件夹即使有很多文件，如果没有 `page.tsx`，用户就无法直接访问这个路由。

### 1.2 动态路由

用方括号 `[参数名]` 创建动态路由段：

```
app/
├── blog/
│   └── [slug]/
│       └── page.tsx      → /blog/hello-world, /blog/my-post
├── users/
│   └── [id]/
│       └── page.tsx      → /users/123, /users/abc
└── shop/
    └── [category]/
        └── [productId]/
            └── page.tsx  → /shop/shoes/456
```

在组件中获取参数：

```tsx
// app/blog/[slug]/page.tsx
export default async function BlogPost({
  params
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params

  return <h1>文章：{slug}</h1>
}
```

### 1.3 Catch-all 路由

用 `[...参数名]` 匹配多个路径段：

```
app/
└── docs/
    └── [...slug]/
        └── page.tsx

匹配：
  /docs/getting-started     → slug = ['getting-started']
  /docs/api/auth            → slug = ['api', 'auth']
  /docs/guide/intro/basic   → slug = ['guide', 'intro', 'basic']
```

```tsx
// app/docs/[...slug]/page.tsx
export default async function DocsPage({
  params
}: {
  params: Promise<{ slug: string[] }>
}) {
  const { slug } = await params

  return <p>文档路径: /{slug.join('/')}</p>
}
```

## 二、特殊文件约定

### 2.1 App Router 的特殊文件列表

```
文件名           作用                    是否必须
─────────────────────────────────────────────────
page.tsx         定义路由的页面内容        是（否则路由不可访问）
layout.tsx       定义布局，包裹子路由      否
template.tsx     类似 layout 但每次导航重建 否
loading.tsx      加载状态 UI              否
error.tsx        错误状态 UI              否
not-found.tsx    404 页面                 否
default.tsx      平行路由的默认 UI        否
```

### 2.2 page.tsx — 页面内容

每个路由的"最终内容"：

```tsx
// app/page.tsx → 首页
export default function HomePage() {
  return <h1>欢迎来到首页</h1>
}

// app/about/page.tsx → 关于页面
export default function AboutPage() {
  return <h1>关于我们</h1>
}
```

### 2.3 layout.tsx — 布局

布局是包裹页面的"外壳"，在导航时**不会重新渲染**。

```tsx
// app/layout.tsx — 根布局（必须存在）
export default function RootLayout({
  children
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="zh">
      <body>
        <header>网站导航</header>
        <main>{children}</main>
        <footer>版权信息</footer>
      </body>
    </html>
  )
}
```

嵌套布局：

```tsx
// app/dashboard/layout.tsx — Dashboard 布局
export default function DashboardLayout({
  children
}: {
  children: React.ReactNode
}) {
  return (
    <div className="flex">
      <aside className="w-64">
        <nav>
          <a href="/dashboard">概览</a>
          <a href="/dashboard/projects">项目</a>
          <a href="/dashboard/settings">设置</a>
        </nav>
      </aside>
      <div className="flex-1">{children}</div>
    </div>
  )
}
```

渲染结构：

```
访问 /dashboard/projects 时的组件嵌套：

<RootLayout>                    ← app/layout.tsx
  <DashboardLayout>             ← app/dashboard/layout.tsx
    <ProjectsPage />            ← app/dashboard/projects/page.tsx
  </DashboardLayout>
</RootLayout>
```

**关键特性：** 从 `/dashboard/projects` 导航到 `/dashboard/settings` 时，`DashboardLayout` 不会重新渲染，侧边栏保持状态。

### 2.4 template.tsx — 模板

模板和布局类似，但**每次导航都会重新渲染**：

```tsx
// app/dashboard/template.tsx
export default function DashboardTemplate({
  children
}: {
  children: React.ReactNode
}) {
  return (
    <div className="animate-fade-in">
      {children}
    </div>
  )
}
```

使用场景：

```
layout vs template：

layout（默认选择）：
  → 导航时不重新渲染
  → 适合：侧边栏、导航栏、保持滚动位置

template（特殊需求）：
  → 每次导航都重新渲染
  → 适合：进入/退出动画、重置状态、计数器
```

## 三、loading.tsx 和 error.tsx

### 3.1 loading.tsx — 加载状态

当页面数据加载时自动显示：

```tsx
// app/dashboard/loading.tsx
export default function DashboardLoading() {
  return (
    <div className="animate-pulse">
      <div className="h-8 bg-gray-200 rounded w-1/3 mb-4"></div>
      <div className="h-4 bg-gray-200 rounded w-2/3 mb-2"></div>
      <div className="h-4 bg-gray-200 rounded w-1/2"></div>
    </div>
  )
}
```

原理：

```
用户导航到 /dashboard
  → Next.js 开始渲染 DashboardPage
  → 因为数据获取需要时间，先显示 loading.tsx
  → 数据获取完成，替换为真正的页面内容
```

这等价于自动用 Suspense 包裹：

```tsx
// Next.js 内部自动做了这件事
<Suspense fallback={<DashboardLoading />}>
  <DashboardPage />
</Suspense>
```

### 3.2 error.tsx — 错误状态

必须是 Client Component：

```tsx
// app/dashboard/error.tsx
'use client'

export default function DashboardError({
  error,
  reset
}: {
  error: Error & { digest?: string }
  reset: () => void
}) {
  return (
    <div className="text-center py-12">
      <h2 className="text-xl font-bold mb-4">出错了</h2>
      <p className="text-gray-600 mb-4">{error.message}</p>
      <button
        onClick={reset}
        className="px-4 py-2 bg-blue-500 text-white rounded"
      >
        重试
      </button>
    </div>
  )
}
```

### 3.3 not-found.tsx — 404 页面

```tsx
// app/not-found.tsx
export default function NotFound() {
  return (
    <div className="text-center py-12">
      <h2 className="text-2xl font-bold mb-4">404</h2>
      <p>你要找的页面不存在</p>
      <a href="/" className="text-blue-500">返回首页</a>
    </div>
  )
}
```

在代码中触发 404：

```tsx
import { notFound } from 'next/navigation'

export default async function BlogPost({ params }) {
  const post = await getPost(params.slug)

  if (!post) {
    notFound() // 显示最近的 not-found.tsx
  }

  return <article>{post.content}</article>
}
```

## 四、路由分组

### 4.1 问题：如何让不同路由使用不同布局？

假设你有这些页面：

```
/ → 用公开布局（有导航栏）
/about → 用公开布局
/login → 用公开布局
/dashboard → 用后台布局（有侧边栏）
/dashboard/settings → 用后台布局
```

### 4.2 解决方案：用圆括号创建路由分组

```
app/
├── (public)/                  ← 路由分组，不影响 URL
│   ├── layout.tsx             ← 公开布局
│   ├── page.tsx               → /
│   ├── about/
│   │   └── page.tsx           → /about
│   └── login/
│       └── page.tsx           → /login
└── (dashboard)/               ← 另一个路由分组
    ├── layout.tsx             ← 后台布局
    ├── page.tsx               → /dashboard
    └── settings/
        └── page.tsx           → /dashboard/settings
```

**圆括号 `()` 创建的文件夹不会出现在 URL 中**，它只是一个逻辑分组。

```tsx
// app/(public)/layout.tsx
export default function PublicLayout({ children }) {
  return (
    <div>
      <nav>公开导航栏</nav>
      <main>{children}</main>
    </div>
  )
}

// app/(dashboard)/layout.tsx
export default function DashboardLayout({ children }) {
  return (
    <div className="flex">
      <aside>侧边栏</aside>
      <main>{children}</main>
    </div>
  )
}
```

## 五、私有文件夹

### 5.1 用下划线前缀排除路由

以 `_` 开头的文件夹不会被路由系统处理：

```
app/
├── _lib/                      ← 不会被当作路由
│   ├── utils.ts
│   └── constants.ts
├── _components/               ← 不会被当作路由
│   └── Header.tsx
└── page.tsx
```

这是放置工具函数、共享组件的好地方：

```tsx
// app/_lib/utils.ts
export function formatDate(date: Date) {
  return date.toLocaleDateString('zh-CN')
}

// app/page.tsx
import { formatDate } from './_lib/utils'
```

## 常见误区

1. **"layout 和 template 可以互换"**：layout 在导航时保持状态不重新渲染，template 每次导航都重建。如果你的侧边栏有展开/收起状态，用 layout；如果需要每次进入页面都播放入场动画，用 template。
2. **"路由分组会影响 URL"**：圆括号 `(groupName)` 创建的文件夹不会出现在 URL 中，它只是逻辑分组。`(dashboard)/settings/page.tsx` 对应的 URL 是 `/settings`，不是 `/dashboard/settings`。
3. **"error.tsx 可以捕获所有错误"**：error.tsx 只能捕获其直接子级组件渲染过程中的错误，不能捕获事件处理器中的错误（需要 try/catch），也不能捕获自身组件的错误。
4. **"动态路由的 params 不需要 await"**：在 Next.js 15+ 中，`params` 是一个 Promise，必须用 `await params` 解构后才能使用，直接访问 `params.slug` 会得到 undefined。

## 工程建议

1. **按功能模块组织路由**：把相关的页面放在同一个路由分组下，每个分组可以有独立的 layout、loading 和 error 处理，保持模块内聚。
2. **根布局保持最小化**：`app/layout.tsx` 只放 `<html>`、`<body>` 和全局字体，不要在里面加载用户数据或做权限检查，这些应该放在对应的子布局中。
3. **善用 `_lib` 和 `_components` 私有文件夹**：以 `_` 开头的文件夹不会被路由处理，是放置工具函数和共享组件的理想位置。
4. **loading.tsx 要模拟真实布局**：骨架屏的结构应该和实际页面布局一致（相同的网格、卡片数量），这样加载完成后页面不会出现明显的布局跳动。

## 八、小结

```
本课核心要点：

1. App Router 用文件夹结构定义路由，page.tsx 使路由可访问
2. layout.tsx 在导航时保持状态，template.tsx 每次重新渲染
3. loading.tsx 和 error.tsx 自动处理加载和错误状态
4. 圆括号 () 创建路由分组，不影响 URL
5. 下划线 _ 前缀的文件夹不会被路由处理
6. 设计页面结构时，按功能模块分组，每个组可以有独立布局
```
