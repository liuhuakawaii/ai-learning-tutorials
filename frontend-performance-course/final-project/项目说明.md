# Performance Rescue 项目说明

## 项目目标

对一个真实风格页面做性能改造，完整走完诊断、定位、优化、复测、监控和性能预算闭环。最终交付的不只是一个更快的页面，还要有能说服团队的证据链。

## 内置项目

课程已经提供可运行 demo：

```text
frontend-performance-course/final-project/performance-rescue-demo
```

页面分工：

| 页面 | 用途 |
|------|------|
| `slow.html` | 慢速基线，只用于测量和对照 |
| `work.html` | 学员练习页，从慢速状态开始优化 |
| `optimized.html` | 优化参考答案，用于对比思路和结果 |
| `monitor.html` | 本地 Web Vitals 与慢交互指标查看页 |

运行方式：

```bash
cd frontend-performance-course/final-project/performance-rescue-demo
pnpm install
pnpm start
```

打开：

- http://localhost:4173/slow.html
- http://localhost:4173/work.html
- http://localhost:4173/optimized.html
- http://localhost:4173/monitor.html

## 内置问题

`slow.html` 和初始 `work.html` 故意包含这些问题：

| 问题 | 影响指标 | 主要位置 |
|------|----------|----------|
| Hero 大图通过 CSS 背景加载，资源发现较晚 | LCP | `styles/slow.css`、`styles/work.css` |
| 同步第三方脚本阻塞解析和主线程 | TBT、INP | `third-party/analytics.js` |
| Web 字体使用 `font-display: block` | LCP、CLS | `styles/slow.css`、`styles/work.css` |
| 一次性渲染 2000 个商品卡片 | TBT、INP | `src/slow.js`、`src/work.js` |
| 搜索输入每次按键都全量过滤和重绘 | INP | `src/slow.js`、`src/work.js` |
| 加入购物车一次性执行重计算 | INP、Long Task | `src/slow.js`、`src/work.js` |
| 异步促销内容插入未预留空间 | CLS | `slow.html`、`work.html` |

## 阶段任务

### 第一阶段：性能体检

使用 `slow.html` 建立基线，记录 Lighthouse、Performance trace、Network waterfall、LCP 元素、CLS 来源和长任务。

交付：`reports/stage1-audit.md`

### 第二阶段：加载与渲染优化

在 `work.html` 上处理首屏问题：关键图片、阻塞脚本、字体策略、布局稳定性和主线程长任务。用 `optimized.html` 对照实现方向。

交付：`reports/stage2-loading-before-after.md`

### 第三阶段：交互优化

优化搜索、排序、加入购物车和商品列表渲染。重点说明哪些操作从同步大任务改成了防抖、窗口化渲染、分片执行或低优先级执行。

交付：`reports/stage3-interaction-before-after.md`

### 第四阶段：资源与缓存

统计图片、脚本、字体和第三方资源体积，定义资源预算。说明哪些资源进入首屏，哪些资源延迟、按需或缓存。

交付：`reports/stage4-assets-budget.md`

### 第五阶段：监控与预算

使用 `src/vitals.js`、`monitor.html` 和 `lighthouserc.js` 建立本地 RUM 采集和 Lighthouse CI 检查。记录指标采集结果和预算超标处理策略。

交付：`reports/stage5-monitoring-report.md`

## 验收标准

- LCP、INP、CLS、TBT 都有优化前后数据
- 至少定位 5 个性能问题，每个问题都有证据和根因
- 首屏 LCP 元素明确，关键图片加载策略合理
- 无明显布局抖动，CLS 目标值小于 0.1
- 搜索、排序、加入购物车没有可感知卡顿
- 图片、脚本、字体和第三方资源都有预算说明
- `pnpm check` 通过
- 能运行 `pnpm lhci` 生成 Lighthouse CI 报告，预算断言至少能给出 warning
- 最终 README 或报告能解释每个优化决策，而不是只贴分数

## 可选真实项目

如果你想用自己的业务页面替代内置 demo，也可以任选一个：

- 电商商品列表 + 商品详情
- SaaS Dashboard
- 内容站首页 + 文章页
- AI 工具站工作台

但真实项目仍需按同一套交付物验收：基线报告、优化记录、资源预算、监控采集和回归策略。

## React / Next 进阶要求

第三阶段讲的是 React / Next 性能，但内置 demo 使用原生 Web 技术复现核心问题。这样做是为了降低运行门槛，并让你直接看到浏览器主线程、DOM 数量和资源优先级的影响。

如果你希望完成框架版最终项目，可以把商品列表迁移成 React / Next 页面，并额外补充：

- React DevTools Profiler 截图或记录
- 状态下沉、memo、useMemo、useCallback 的使用理由
- 大列表窗口化方案
- Next 图片、字体、路由缓存或 Server Components 的取舍说明
