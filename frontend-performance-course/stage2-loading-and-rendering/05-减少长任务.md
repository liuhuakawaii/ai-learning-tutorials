# 第5课：减少长任务

> **课程定位**：识别和拆分长任务，释放主线程，让交互更及时响应
> **前置知识**：了解浏览器加载链路和关键渲染路径
> **预计时长**：35 分钟

## 场景引入

你的电商网站搜索功能有个问题：用户在搜索框输入"手机"两个字，页面卡了将近 1 秒。用 DevTools Performance 面板录制才发现，每次按键触发的搜索过滤函数遍历了 5000 条商品数据，耗时 400ms，形成了一个长任务。在这 400ms 内，用户输入第二个字的事件被排在队列里等待，导致明显的输入延迟。把过滤操作改成分批处理后，每次按键的处理时间降到 10ms 以内，用户再也感受不到卡顿。

## 一、什么是长任务

```
┌──────────────────────────────────────────────────────────────┐
│                     主线程时间线                               │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  ┌──────────┐  ┌──────────────────────────┐  ┌───────────┐  │
│  │ 任务 A   │  │       任务 B（长任务）      │  │  任务 C   │  │
│  │  5ms     │  │        200ms              │  │   8ms     │  │
│  └──────────┘  └──────────────────────────┘  └───────────┘  │
│                                                              │
│                ↑ 用户在这 200ms 内点击 → 无法响应              │
│                                                              │
│  长任务：执行时间 > 50ms 的任务                                │
│  浏览器在任务执行期间无法响应用户输入                           │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

**长任务直接影响 INP（Interaction to Next Paint）**：
- 用户点击 → 浏览器要等当前长任务结束 → 才能处理点击 → 才能更新画面
- 长任务越多、越长，INP 越差

### 2.3 Long Tasks API

```javascript

  list.getEntries().forEach((entry) => {
    console.warn(`长任务：${entry.duration.toFixed(1)}ms`, entry);
```

## 四、拆分长任务

### 4.1 setTimeout 拆分

```javascript
// ❌ 一次处理 10000 项（长任务）
function processAll(items) {
  items.forEach(item => process(item));
}

// ✅ 分批处理，每批让出主线程
function processInBatches(items, batchSize = 100) {
  let index = 0;

  function processBatch() {
    const end = Math.min(index + batchSize, items.length);
    for (; index < end; index++) {
      process(items[index]);
    }

    if (index < items.length) {
      // 让出主线程，下一批稍后执行
      setTimeout(processBatch, 0);
    }
  }

  processBatch();
}
```

### 4.2 requestIdleCallback

```javascript
// 在浏览器空闲时执行低优先级工作
function processWhenIdle(items) {
  let index = 0;

  function process(deadline) {
    // 还有空闲时间 && 还有任务
    while (deadline.timeRemaining() > 0 && index < items.length) {
      process(items[index]);
      index++;
    }

    if (index < items.length) {
      requestIdleCallback(process);
    }
  }

  requestIdleCallback(process);
}
```

### 4.3 scheduler.yield（现代方案）

```javascript
// Scheduler API — 让出主线程，等浏览器处理完待处理的输入后继续
async function processWithYield(items) {
  for (let i = 0; i < items.length; i++) {
    process(items[i]);

    // 每处理 100 项让出一次主线程
    if (i % 100 === 0) {
      await scheduler.yield();
    }
  }
}

// 兼容性降级
async function yieldToMain() {
  if (typeof scheduler !== 'undefined' && scheduler.yield) {
    await scheduler.yield();
  } else {
    return new Promise(resolve => setTimeout(resolve, 0));
  }
}
```

### 4.4 对比

```
┌─────────────────────┬────────────────────────────────────────┐
│ 方法                 │ 特点                                    │
├─────────────────────┼────────────────────────────────────────┤
│ setTimeout(fn, 0)   │ 最简单，但优先级低，可能被延迟           │
│ requestIdleCallback │ 只在空闲时执行，适合低优先级任务         │
│ scheduler.yield     │ 现代方案，优先处理待处理输入              │
│ MessageChannel      │ 比 setTimeout 更快触发                   │
└─────────────────────┴────────────────────────────────────────┘
```

## 五、Web Worker

### 5.1 适用场景

```
┌──────────────────────────────────────────────────────────────┐
│              Web Worker 适用 vs 不适用                        │
├───────────────────────────┬──────────────────────────────────┤
│  适用                      │  不适用                          │
├───────────────────────────┼──────────────────────────────────┤
│  大数据计算                │  DOM 操作                        │
│  JSON 解析/序列化          │  访问 window/document            │
│  图片处理                  │  样式计算                        │
│  搜索/排序/过滤            │  Canvas 2D/WebGL 上下文          │
│  加密/解密                 │  React 状态更新                  │
└───────────────────────────┴──────────────────────────────────┘
```

### 5.2 基本用法

```javascript
// worker.js
self.addEventListener('message', (e) => {
  const { data, type } = e.data;

  if (type === 'sort') {
    const sorted = data.sort((a, b) => a - b);
    self.postMessage({ type: 'sorted', data: sorted });
  }
});

// main.js
const worker = new Worker('/worker.js');

worker.postMessage({ type: 'sort', data: largeArray });

worker.addEventListener('message', (e) => {
  if (e.data.type === 'sorted') {
    updateUI(e.data.data);
  }
});
```

### 5.3 React 中使用 Worker

```javascript
// useWorker.js
import { useEffect, useRef, useCallback } from 'react';

export function useWorker(workerPath) {
  const workerRef = useRef(null);

  useEffect(() => {
    workerRef.current = new Worker(workerPath);
    return () => workerRef.current?.terminate();
  }, [workerPath]);

  const postMessage = useCallback((message) => {
    return new Promise((resolve) => {
      const handler = (e) => {
        workerRef.current.removeEventListener('message', handler);
        resolve(e.data);
      };
      workerRef.current.addEventListener('message', handler);
      workerRef.current.postMessage(message);
    });
  }, []);

  return postMessage;
}

// 使用
function DataProcessor({ rawData }) {
  const postMessage = useWorker('/data-worker.js');

  useEffect(() => {
    postMessage({ type: 'process', data: rawData })
      .then(result => setProcessed(result));
  }, [rawData]);
}
```

```javascript
function SearchBox({ items }) {
```

### 6.2 虚拟列表（只渲染可见项）

```javascript
// 只渲染视口内的 20 项，而不是 10000 项
function VirtualList({ items, itemHeight }) {
  const [scrollTop, setScrollTop] = useState(0);
  const viewportHeight = 600;

  const startIndex = Math.floor(scrollTop / itemHeight);
  const endIndex = Math.ceil((scrollTop + viewportHeight) / itemHeight);
  const visibleItems = items.slice(startIndex, endIndex);

  return (
    <div onScroll={e => setScrollTop(e.target.scrollTop)}
         style={{ height: viewportHeight, overflow: 'auto' }}>
      <div style={{ height: items.length * itemHeight }}>
        <div style={{ transform: `translateY(${startIndex * itemHeight}px)` }}>
          {visibleItems.map(item => <Item key={item.id} {...item} />)}
        </div>
      </div>
    </div>
  );
}
```

## 常见误区

1. **把所有任务都拆分成 setTimeout(fn, 0)**：过度拆分会导致大量微任务排队，反而增加调度开销。只拆分真正超过 50ms 的长任务。
2. **认为 Web Worker 能解决所有长任务问题**：Web Worker 不能访问 DOM，不能操作 UI。它只适合计算密集型任务（排序、过滤、加密），不适合 DOM 操作相关的长任务。
3. **只在开发环境关注长任务**：开发环境的高性能设备上长任务可能不明显，但在低端设备上同样的代码可能变成 500ms 的超长任务。必须在节流环境下测试。
4. **忽视长任务对 INP 的影响**：长任务不只影响加载速度，更直接影响交互响应。用户点击时如果主线程被长任务阻塞，INP 就会变差。

## 工程建议

1. **优先使用 scheduler.yield()**：这是现代浏览器提供的原生方案，能正确地让出主线程并优先处理待处理的用户输入。
2. **用 Long Tasks API 线上监控**：在生产环境中用 PerformanceObserver 监测长任务，上报长任务的频率和持续时间。
3. **虚拟列表是大列表的终极方案**：当列表项超过 100 个时，与其优化渲染逻辑，不如直接用虚拟滚动只渲染可见区域。
4. **搜索输入必须防抖**：用户输入搜索关键词时，不要每次按键都触发搜索。300ms 的防抖能减少 90% 的无效计算。

## 小结

1. **长任务 > 50ms** 会阻塞主线程，直接影响 INP
2. **用 DevTools** 识别长任务：红色三角形标记
3. **拆分任务**：setTimeout、requestIdleCallback、scheduler.yield
4. **Web Worker**：把计算密集型工作移到后台线程
5. **虚拟列表**：只渲染可见区域，避免大量 DOM 操作
