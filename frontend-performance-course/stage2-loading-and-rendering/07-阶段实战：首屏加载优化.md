# 第7课：阶段实战——首屏加载优化

> **课程定位**：综合运用第二阶段全部知识，对一个真实页面进行首屏加载优化
> **前置知识**：浏览器加载链路、关键渲染路径、CSS/JS 阻塞、资源优先级、长任务、布局抖动
> **预计时长**：60 分钟

## 场景引入

你拿到了一个电商首页的性能体检报告：LCP 4.2 秒、CLS 0.35、TBT 800ms。报告列出了 8 个问题，但你不知道从哪里下手。是先压缩那张 3MB 的 Hero 图片？还是先处理阻塞渲染的 CSS？或者先拆分那个 800ms 的长任务？首屏优化不是修修补补，而是一套系统化的流程：先找到影响最大的瓶颈，用最低成本的手段修复，再验证效果。这一课你将用真实页面走完这个完整流程。

## 学习目标

1. 对一个真实页面完成完整的首屏性能诊断
2. 识别并修复 LCP 和 CLS 问题
3. 优化资源加载顺序和优先级
4. 拆分阻塞主线程的长任务
5. 记录优化前后的数据对比

### 2.2 识别 LCP 元素

```javascript
// 在 Console 中运行
new PerformanceObserver((list) => {
  const entries = list.getEntries();
  const lastEntry = entries[entries.length - 1];
  console.log('LCP 元素：', lastEntry.element);
  console.log('LCP 时间：', lastEntry.startTime.toFixed(0) + 'ms');
}).observe({ type: 'largest-contentful-paint', buffered: true });
```

### 2.3 识别布局偏移源

new PerformanceObserver((list) => {

        element: s.node,
        currentRect: s.currentRect,
        previousRect: s.previousRect,
      })));
    }
  });

## 三、优化步骤

### 步骤 1：优化 LCP 图片

```html
<!-- 之前：Hero 图片在 CSS 背景中，发现很晚 -->
<div class="hero" style="background-image: url('/images/hero.jpg')"></div>

<!-- 之后：直接用 <img> + preload + fetchpriority -->
<link rel="preload" as="image" href="/images/hero.webp" fetchpriority="high">

<img src="/images/hero.webp"
     alt="促销活动"
     width="1200" height="600"
     fetchpriority="high"
     decoding="async">
```

```bash
# 转换图片格式（在构建流程中）
npx @squoosh/cli --webp '{"quality":80}' images/hero.jpg
```

### 步骤 2：内联关键 CSS

```html
<!-- 之前：外部 CSS 阻塞渲染 -->
<link rel="stylesheet" href="/style.css">

<!-- 之后：关键 CSS 内联，非关键 CSS 异步加载 -->
<style>
  /* 首屏关键样式（手动提取或用 critters 工具） */
  * { margin: 0; padding: 0; box-sizing: border-box; }
  .hero { width: 100%; aspect-ratio: 2/1; }
  .hero img { width: 100%; height: 100%; object-fit: cover; }
  .header { display: flex; align-items: center; padding: 16px; }
</style>

<!-- 非关键 CSS 异步加载 -->
<link rel="preload" href="/style.css" as="style" onload="this.onload=null;this.rel='stylesheet'">
<noscript><link rel="stylesheet" href="/style.css"></noscript>
```

### 步骤 3：延迟第三方脚本

```html
<!-- 之前：同步阻塞 -->
<script src="/third-party/analytics.js"></script>
<script src="/third-party/chat-widget.js"></script>
<script src="/third-party/ad-loader.js"></script>

<!-- 之后：分析脚本用 defer，聊天和广告延迟加载 -->
<script defer src="/third-party/analytics.js"></script>

<!-- 聊天组件：用户交互后才加载 -->
<script>
  // 空闲时预加载，但不执行
  const chatLink = document.createElement('link');
  chatLink.rel = 'prefetch';
  chatLink.href = '/third-party/chat-widget.js';
  document.head.appendChild(chatLink);

  // 用户滚动或点击时才真正加载
  ['scroll', 'click'].forEach(event => {
    window.addEventListener(event, () => {
      const script = document.createElement('script');
      script.src = '/third-party/chat-widget.js';
      document.body.appendChild(script);
    }, { once: true });
  });
</script>
```

### 步骤 4：修复图片 CLS

```html
<!-- 之前：商品图没有尺寸 -->
<img src="/images/product-1.jpg" alt="商品1">

<!-- 之后：添加尺寸 + aspect-ratio -->
<img src="/images/product-1.jpg" alt="商品1"
     width="300" height="300" loading="lazy">
```

```css
/* 之前：轮播图没有预留高度 */
.carousel { overflow: hidden; }

/* 之后：预留轮播图高度 */
.carousel {
  overflow: hidden;
  aspect-ratio: 16 / 9;
}

/* 商品图片统一比例 */
.product-image {
  width: 100%;
  aspect-ratio: 1 / 1;
  object-fit: cover;
  background: #f5f5f5;
}
```

### 步骤 5：修复字体 CLS

```css
/* 之前：默认 font-display 导致 FOIT */
@font-face {
  font-family: 'CustomFont';
  src: url('/fonts/custom-font.woff2') format('woff2');
}

/* 之后：swap + 匹配后备字体 */
@font-face {
  font-family: 'CustomFont';
  src: url('/fonts/custom-font.woff2') format('woff2');
  font-display: swap;
}

/* 匹配后备字体尺寸 */
@font-face {
  font-family: 'CustomFont-Fallback';
  src: local('Arial');
  size-adjust: 102%;
  ascent-override: 92%;
}

body {
  font-family: 'CustomFont', 'CustomFont-Fallback', sans-serif;
}
```

```html
<!-- 预加载关键字体 -->
<link rel="preload" href="/fonts/custom-font.woff2" as="font"
      type="font/woff2" crossorigin>
```

### 步骤 6：修复 Cookie 横幅 CLS

```css
/* 之前：在文档流中插入 → 推动内容下移 */
.cookie-banner {
  position: relative;
  background: #333;
  color: #fff;
  padding: 12px;
}

/* 之后：fixed 定位，不影响文档流 */
.cookie-banner {
  position: fixed;
  bottom: 0;
  left: 0;
  right: 0;
  z-index: 9999;
  background: #333;
  color: #fff;
  padding: 12px;
  transform: translateY(100%);
  transition: transform 0.3s ease;
}

.cookie-banner.show {
  transform: translateY(0);
}
```

### 步骤 7：拆分长任务

```javascript
// 之前："加入购物车" 一次性更新大量 DOM
function addToCart(product) {
  cart.push(product);
  updateCartCount();      // 更新角标
  updateCartSidebar();    // 更新侧边栏（大量 DOM）
  updateCartTotal();      // 更新总价
  animateAddToCart();     // 动画效果
  trackEvent('add_to_cart'); // 上报
}

// 之后：分优先级处理
async function addToCart(product) {
  // 立即响应用户：更新角标和动画
  cart.push(product);
  updateCartCount();
  animateAddToCart();

  // 让出主线程后再处理
  await yieldToMain();
  updateCartTotal();

  await yieldToMain();
  updateCartSidebar(); // 最耗时的部分

  // 低优先级：空闲时上报
  requestIdleCallback(() => trackEvent('add_to_cart'));
}

function yieldToMain() {
  return new Promise(resolve => setTimeout(resolve, 0));
}
```

### 步骤 8：搜索防抖

```javascript
// 之前：每次按键都触发搜索
input.addEventListener('input', (e) => {
  searchProducts(e.target.value); // 每次都搜索 + 渲染
});

// 之后：防抖 + 虚拟列表
let debounceTimer;
input.addEventListener('input', (e) => {
  clearTimeout(debounceTimer);
  debounceTimer = setTimeout(() => {
    searchProducts(e.target.value);
  }, 300);
});
```

## 常见误区

1. **按报告顺序逐个修复**：Lighthouse Opportunities 按预计节省时间排序是对的，但你还要考虑修复难度。影响大且容易修复的应该优先做。
2. **优化后不记录 before/after 数据**：没有对比数据，你无法证明优化效果，也无法在团队中建立性能优化的正向循环。
3. **只优化 LCP 忽视 CLS 和 INP**：LCP 最容易量化，但 CLS 和 INP 同样影响用户体验和搜索排名。三个指标要并行关注。
4. **优化完就不管了**：没有持续监控，性能会在后续迭代中慢慢退化。要把性能检测集成到 CI/CD 流程中。

## 工程建议

1. **Hero 图片用 preload + fetchpriority="high" + WebP 格式**：三管齐下，通常能把 LCP 降低 50% 以上。
2. **首屏关键 CSS 内联，非关键 CSS 异步加载**：用 critters 工具自动化这个过程，不需要手动维护关键 CSS。
3. **第三方脚本分优先级处理**：分析脚本用 defer，聊天/广告脚本延迟到用户交互后加载。
4. **每次优化都要有 before/after 对比**：用 Lighthouse 或 DevTools 记录优化前后的数据，量化优化效果。

## 小结

1. **先诊断再优化**：用 Lighthouse 和 DevTools 找到真正的问题
2. **LCP 优化三板斧**：preload 关键资源、内联关键 CSS、延迟非关键脚本
3. **CLS 优化三板斧**：图片设尺寸、字体用 swap、动态内容预留空间
4. **INP 优化**：拆分长任务、防抖用户输入
5. **记录数据**：每次优化都要有 before/after 对比
