# 第2课：关键渲染路径

> **课程定位**：深入理解浏览器渲染机制，掌握 Critical Rendering Path 优化思路
> **前置知识**：了解浏览器加载链路（第1课）
> **预计时长**：40 分钟

## 场景引入

你的页面 HTML 只有 20KB，但首屏渲染要等 3 秒。用 DevTools 一看，Network 面板里 CSS 文件 200KB、JS 文件 500KB，全都排在 HTML 后面串行加载，直到 CSS 和 JS 都下载完才开始渲染。更糟糕的是，JS 是同步加载的，在下载和执行期间 DOM 解析完全暂停。这就是关键渲染路径（Critical Rendering Path）没优化的典型表现：不是 HTML 太大，而是 CSS 和 JS 阻塞了从字节到像素的转换过程。

完成本课学习后，你将能够：

4. 分析 JavaScript 和 CSS 如何阻塞渲染

## 一、关键渲染路径全景

```
  HTML 字节 → DOM 树 ─┐
                      ├→ Render Tree → Layout → Paint → Composite → 屏幕
  CSS 字节  → CSSOM 树─┘

  ┌────────┐    ┌────────┐    ┌────────┐    ┌────────┐    ┌────────┐
  │  HTML  │    │  DOM   │    │ Render │    │        │    │        │
  │  字节  │ ──→│  树    │ ──→│  树    │ ──→│ Layout │ ──→│ Paint  │
  └────────┘    └────────┘    └────────┘    └────────┘    └────────┘
                    ↑                            │
               ┌────────┐                       ▼
               │ CSSOM  │                  ┌──────────┐
               │  树    │                  │Composite │
               └────────┘                  └──────────┘
                    ↑
               ┌────────┐
               │  CSS   │
               │  字节  │
               └────────┘
```

## 二、DOM 和 CSSOM 的构建

### 2.1 DOM 构建

```
HTML 字节 → 词法分析（Tokenization）→ 语法分析 → DOM 树

  <html>
    <head><title>示例</title></head>
    <body><h1>你好</h1></body>
  </html>

  变成：

  Document
    └── html
        ├── head
        │   └── title → "示例"
        └── body
            └── h1 → "你好"
```

### 2.2 CSSOM 构建

```css
body { font-size: 16px; }
h1 { color: red; }
```

变成：

```
Document
  └── body { font-size: 16px }
      └── h1 { color: red; font-size: 16px (继承) }
```

### 2.3 Render Tree

```
DOM + CSSOM → Render Tree

  规则：
  - display: none 的元素不出现在 Render Tree 中
  - visibility: hidden 的元素出现在 Render Tree 中（占空间但不可见）
  - CSS 属性会向下继承
```

## 三、Layout、Paint、Composite

### 3.1 Layout（回流）

```
计算每个元素的精确位置和尺寸：

  Render Tree 节点 → 计算 x, y, width, height

  触发回流的操作：
  - 修改 width/height/position/display
  - 增删 DOM 节点
  - 读取 offsetWidth/getBoundingClientRect（强制同步回流）
```

### 3.2 Paint（重绘）

```
将计算好的几何信息填充为像素：

  绘制文字、背景、边框、阴影、图片

  重绘 vs 回流：
  - 回流 = 几何信息变了（代价高）
  - 重绘 = 视觉样式变了（代价中等）
  - 回流一定触发重绘，重绘不一定触发回流
```

### 3.3 Composite（合成）

```
将多个图层合并为最终画面（GPU 执行）：

  ┌──────────────────────┐
  │     最终画面          │
  │  ┌────┐ ┌────┐       │
  │  │ L1 │ │ L2 │       │  ← GPU 将图层叠在一起
  │  └────┘ └────┘       │
  └──────────────────────┘

  独立图层的创建条件：
  - transform: translateZ(0)
  - will-change: transform
  - position: fixed
  - CSS 动画中的 opacity/transform
  - overflow: auto 的容器

  优化策略：尽量只触发 Composite（transform/opacity），避免 Layout 和 Paint
```

## 四、CSS 的阻塞行为

```
CSS 是渲染阻塞资源：

  浏览器遇到 <link rel="stylesheet">
    → 发起 CSS 请求（不阻塞 DOM 解析）
    → 等待 CSS 下载完成
    → 解析 CSS 构建 CSSOM
    → 在 CSSOM 构建完成前，不渲染任何像素 ← 渲染阻塞！

  原因：浏览器不想先渲染无样式的内容（避免 FOUC）
```

### 优化方法

```html
<!-- 方法 1：用 media 属性标记非关键 CSS -->
<link rel="stylesheet" href="print.css" media="print">
<link rel="stylesheet" href="desktop.css" media="(min-width: 1024px)">

<!-- 方法 2：内联关键 CSS -->
<style>
  /* 只包含首屏必需的样式（< 10KB） */
  body { margin: 0; font-family: sans-serif; }
  .header { ... }
  .hero { ... }
</style>

<!-- 方法 3：异步加载非关键 CSS -->
<link rel="preload" href="full.css" as="style"
      onload="this.onload=null;this.rel='stylesheet'">
```

## 五、JavaScript 的阻塞行为

```
JavaScript 是解析阻塞资源：

  浏览器遇到 <script src>
    → 暂停 DOM 解析
    → 下载 JS（如果是外部脚本）
    → 执行 JS
    → 恢复 DOM 解析

  原因：JS 可能修改 DOM（document.write, appendChild 等）
```

### 三种加载策略

```html
<!-- 普通：阻塞解析，下载完立即执行 -->
<script src="app.js"></script>

<!-- async：不阻塞解析，下载完立即执行（不保证顺序） -->
<script async src="analytics.js"></script>

<!-- defer：不阻塞解析，DOM 解析完成后执行（保证顺序） -->
<script defer src="app.js"></script>

<!-- module：默认 defer 行为 -->
<script type="module" src="app.mjs"></script>
```

```
时间轴对比：

  普通 script:  ░░░░████████████████░░░░░░░░░░░░░░
                下载      执行
  async:        ░░░░░░░░░░░░░░░░░░██░░░░░░░░░░░░░░
                      下载(后台)   执行
  defer:        ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░██
                      下载(后台)            DOM后执行
```

## 六、CRP 优化三原则

```
┌───────────────────────────────────────────────────────────┐
│              CRP 优化的三个维度                             │
├───────────────────────────────────────────────────────────┤
│                                                           │
│  1. 减少关键资源数量                                       │
│     ├── 将非关键 CSS 标记为非阻塞（media 属性）            │
│     ├── 将 JS 改为 async/defer                            │
│     └── 目标：让首屏渲染尽可能少地被阻塞                   │
│                                                           │
│  2. 减少关键字节数                                         │
│     ├── 压缩 HTML/CSS/JS                                  │
│     ├── 移除未使用的代码                                   │
│     └── 目标：传输量更小                                   │
│                                                           │
│  3. 缩短关键路径长度                                       │
│     ├── 预加载关键资源（preload）                          │
│     ├── 减少网络往返（CDN、HTTP/2）                        │
│     └── 目标：从 HTML 到首次渲染的等待时间最短             │
│                                                           │
└───────────────────────────────────────────────────────────┘
```

## 常见误区

1. **把 defer 和 async 混为一谈**：defer 保证执行顺序且在 DOM 解析完成后执行，async 下载完立即执行且不保证顺序。应用主脚本应该用 defer，独立的分析脚本才用 async。
2. **认为 CSS 不阻塞 DOM 解析所以不重要**：CSS 确实不阻塞 DOM 解析，但它阻塞渲染。CSSOM 构建完成前，浏览器不会渲染任何像素，用户看到的就是白屏。
3. **过度使用 transform: translateZ(0) 创建图层**：虽然独立图层可以避免回流和重绘，但每个图层都消耗 GPU 内存。过多图层反而导致合成阶段变慢。
4. **忽视关键渲染路径的长度**：优化不只是减少资源大小，还要缩短从 HTML 到首次渲染的路径长度——减少网络往返、预加载关键资源同样重要。

## 工程建议

1. **内联首屏关键 CSS（< 10KB）**：把首屏必需的样式直接写在 `<style>` 标签里，消除 CSS 的渲染阻塞。
2. **所有非首屏脚本使用 defer**：除非脚本是独立的分析/广告脚本（用 async），否则一律用 defer 保持执行顺序。
3. **用 Coverage 面板检查代码使用率**：Chrome DevTools 的 Coverage 面板能告诉你每个 CSS/JS 文件有多少字节是首屏用不到的，指导你做代码拆分。
4. **动画优先使用 transform 和 opacity**：这两个属性只触发 Composite，由 GPU 处理，不触发 Layout 和 Paint。

## 小结

1. **CRP 六步**：字节 → DOM → CSSOM → Render Tree → Layout → Paint → Composite
2. **CSS 是渲染阻塞**：不阻塞 DOM 解析，但阻塞渲染
3. **JS 是解析阻塞**：暂停 DOM 构建，用 defer/async 解决
4. **Composite 最高效**：transform/opacity 由 GPU 合成
5. **优化三原则**：减少关键资源、减少关键字节、缩短关键路径
