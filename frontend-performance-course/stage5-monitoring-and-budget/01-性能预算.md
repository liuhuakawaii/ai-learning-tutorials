# 第1课：性能预算

> **课程定位**：建立性能预算，让性能优化有量化目标和可执行标准
> **前置知识**：了解 Core Web Vitals 和资源优化
> **预计时长**：30 分钟

---

## 学习目标

1. 理解什么是性能预算以及为什么需要它
2. 掌握性能预算的类型和设定方法
3. 学会在项目中实施性能预算
4. 了解性能预算的工具和集成方式

---

## 一、什么是性能预算

```
┌──────────────────────────────────────────────────────────────┐
│              性能预算                                          │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  定义：为页面性能指标和资源大小设定可量化的上限               │
│                                                              │
│  类比：                                                       │
│  - 财务预算：支出不能超过收入                                 │
│  - 性能预算：资源大小/加载时间不能超过阈值                    │
│                                                              │
│  作用：                                                       │
│  - 给团队明确的性能目标                                       │
│  - 在开发过程中及时发现性能退化                               │
│  - 防止"功能越来越多，页面越来越慢"                          │
│  - 让性能优化成为持续的工程实践                               │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## 二、性能预算类型

### 2.1 基于指标的预算

```
┌──────────────────────┬──────────────┬──────────────────────┐
│ 指标                  │ 预算          │ 说明                  │
├──────────────────────┼──────────────┼──────────────────────┤
│ LCP                  │ ≤ 2.5s       │ 最大内容绘制          │
│ INP                  │ ≤ 200ms      │ 交互到下次绘制        │
│ CLS                  │ ≤ 0.1        │ 累积布局偏移          │
│ FCP                  │ ≤ 1.8s       │ 首次内容绘制          │
│ TTFB                 │ ≤ 800ms      │ 首字节时间            │
│ TBT                  │ ≤ 200ms      │ 总阻塞时间            │
│ Speed Index          │ ≤ 3.0s       │ 速度指数              │
└──────────────────────┴──────────────┴──────────────────────┘
```

### 2.2 基于资源的预算

```
┌──────────────────────┬──────────────┬──────────────────────┐
│ 资源类型              │ 预算          │ 说明                  │
├──────────────────────┼──────────────┼──────────────────────┤
│ 总传输大小            │ ≤ 500KB      │ 所有资源 gzip 后      │
│ JavaScript           │ ≤ 200KB      │ gzip 后               │
│ CSS                  │ ≤ 50KB       │ gzip 后               │
│ 图片                 │ ≤ 200KB      │ 首屏图片总大小        │
│ 字体                 │ ≤ 100KB      │ 所有字体文件          │
│ 首屏请求数            │ ≤ 20         │ 首屏加载的请求数      │
│ 第三方脚本            │ ≤ 100KB      │ 所有第三方脚本        │
└──────────────────────┴──────────────┴──────────────────────┘
```

### 2.3 基于数量的预算

```
┌──────────────────────┬──────────────┬──────────────────────┐
│ 类型                  │ 预算          │ 说明                  │
├──────────────────────┼──────────────┼──────────────────────┤
│ JS 文件数             │ ≤ 10         │ 首屏加载的 JS 文件    │
│ CSS 文件数            │ ≤ 3          │ 首屏加载的 CSS 文件   │
│ 图片数量              │ ≤ 20         │ 首屏图片数            │
│ 第三方域名            │ ≤ 5          │ 第三方请求数          │
│ Web 字体              │ ≤ 3          │ 字体文件数            │
└──────────────────────┴──────────────┴──────────────────────┘
```

## 三、如何设定预算

### 3.1 基于现状

```
步骤：
1. 测量当前页面性能
2. 记录各项指标和资源大小
3. 设定合理的改进目标

例：
当前 LCP: 3.5s → 预算: 2.5s（目标 Good）
当前 JS: 400KB → 预算: 200KB（减少 50%）
```

### 3.2 基于竞品

```
步骤：
1. 测量竞品页面的性能
2. 以竞品的中位数作为基准
3. 设定略优于竞品的预算

例：
竞品 LCP 中位数: 2.8s → 预算: 2.5s
竞品 JS 中位数: 250KB → 预算: 200KB
```

### 3.3 基于最佳实践

```
直接采用行业标准：

Core Web Vitals：
- LCP ≤ 2.5s（Google Good 标准）
- INP ≤ 200ms（Google Good 标准）
- CLS ≤ 0.1（Google Good 标准）

资源大小：
- 首屏 JS ≤ 200KB（HTTP Archive 中位数）
- 首屏 CSS ≤ 50KB
- 首屏图片 ≤ 200KB
```

## 四、实施性能预算

### 4.1 在 CI 中检查

```javascript
// budget.json
{
  "resourceSizes": [
    { "resourceType": "total", "budget": 500 },
    { "resourceType": "script", "budget": 200 },
    { "resourceType": "stylesheet", "budget": 50 },
    { "resourceType": "image", "budget": 200 },
    { "resourceType": "font", "budget": 100 }
  ],
  "resourceCounts": [
    { "resourceType": "script", "budget": 10 },
    { "resourceType": "stylesheet", "budget": 3 },
    { "resourceType": "image", "budget": 20 }
  ],
  "timings": [
    { "metric": "largest-contentful-paint", "budget": 2500 },
    { "metric": "cumulative-layout-shift", "budget": 0.1 },
    { "metric": "total-blocking-time", "budget": 200 }
  ]
}
```

### 4.2 使用 bundlesize

```json
// package.json
{
  "bundlesize": [
    {
      "path": "./build/static/js/main.*.js",
      "maxSize": "50 kB",
      "compression": "gzip"
    },
    {
      "path": "./build/static/css/main.*.css",
      "maxSize": "20 kB",
      "compression": "gzip"
    }
  ]
}
```

```bash
# CI 中运行
npx bundlesize
```

### 4.3 使用 size-limit

```json
// package.json
{
  "size-limit": [
    {
      "path": "dist/index.js",
      "limit": "10 KB",
      "import": "{ createStore }"
    },
    {
      "path": "dist/index.js",
      "limit": "30 KB"
    }
  ]
}
```

```bash
npx size-limit
```

## 五、预算超了怎么办

```
┌──────────────────────────────────────────────────────────────┐
│              预算超标的处理流程                                │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  1. 分析原因                                                  │
│     - 新增了什么功能/依赖？                                   │
│     - 哪个资源增长最多？                                      │
│                                                              │
│  2. 优先级排序                                                │
│     - 该功能是否必须？                                        │
│     - 能否延迟加载？                                          │
│     - 能否替换为更轻量的方案？                                │
│                                                              │
│  3. 优化                                                      │
│     - 代码分割、Tree Shaking                                 │
│     - 替换大型依赖                                            │
│     - 图片/字体优化                                           │
│                                                              │
│  4. 调整预算（最后手段）                                      │
│     - 如果确实需要新功能                                      │
│     - 记录调整原因                                            │
│     - 设定新的优化目标                                        │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## 动手练习

### 练习一：设定性能预算

1. 测量当前项目的各项性能指标
2. 设定合理的性能预算
3. 写成 budget.json 文件

### 练习二：集成 CI 检查

1. 用 bundlesize 或 size-limit 配置资源大小检查
2. 在 CI 中运行检查
3. 测试预算超标时的行为

### 练习三：预算超标的优化

1. 故意引入一个大型依赖
2. 触发预算超标
3. 实施优化使预算达标

---

## 小结

1. **性能预算**：为指标和资源设定可量化的上限
2. **三类预算**：基于指标、基于资源、基于数量
3. **设定方法**：基于现状、基于竞品、基于最佳实践
4. **CI 集成**：自动化检查，超标时失败
5. **预算超标**：分析原因 → 优先级排序 → 优化 → 调整预算
