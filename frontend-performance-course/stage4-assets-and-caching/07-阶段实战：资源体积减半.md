# 第7课：阶段实战——资源体积减半

> **课程定位**：综合运用第四阶段全部知识，对一个资源过重的页面进行优化
> **前置知识**：图片格式、字体加载、代码分割、HTTP 缓存、API 缓存、第三方脚本
> **预计时长**：60 分钟

## 场景引入

你的项目已经上线半年，随着功能迭代，页面总传输体积从最初的 1MB 膨胀到了 5MB。用户抱怨"打开你们的网站要等好久"，产品经理也注意到跳出率在上升。领导给了你一个目标：把首屏传输体积减半。你需要用前 6 课学到的所有技术——图片优化、字体子集化、代码分割、缓存策略、第三方脚本治理——系统性地对页面进行瘦身。

---

## 学习目标

1. 分析页面的资源组成和体积
2. 优化图片、字体、JS、CSS 体积
3. 配置合理的缓存策略
4. 治理第三方脚本
5. 记录优化前后的数据对比

## 二、优化步骤

### 步骤 1：图片优化

```bash
# 1. 批量转换为 WebP
npx @squoosh/cli --webp '{"quality":80}' public/images/*.jpg public/images/*.png

# 2. 生成响应式尺寸
npx responsive-images --input public/images/hero.jpg \
  --output public/images/ \
  --sizes 400 800 1200 1600 \
  --formats webp
```

```html
<!-- 3. 使用响应式图片 -->
<picture>
  <source srcset="/images/hero-400.webp 400w,
                  /images/hero-800.webp 800w,
                  /images/hero-1200.webp 1200w"
          sizes="(max-width: 768px) 100vw, 50vw"
          type="image/webp">
  <img src="/images/hero-800.jpg" alt="Hero"
       width="800" height="600"
       fetchpriority="high">
</picture>

<!-- 4. 非首屏图片懒加载 -->
<img src="/images/content-1.webp" alt=""
     width="600" height="400" loading="lazy">
```

```
图片优化效果：
优化前：3.5MB (25 张)
优化后：800KB (WebP + 响应式 + 懒加载)
减少：77%
```

### 步骤 2：字体优化

```bash
# 1. 子集化中文字体（只保留常用字）
npx glyphhanger --subset=public/fonts/chinese.woff2 \
  --text="的一是不了人我在有他这为之大来以个中上们到说国和地也子时道出会三要于下得可你年生"
```

```css
/* 2. 只加载需要的字重 */
@font-face {
  font-family: 'BodyFont';
  src: url('/fonts/body-400.woff2') format('woff2');
  weight: 400;
  font-display: swap;
}

@font-face {
  font-family: 'BodyFont';
  src: url('/fonts/body-700.woff2') format('woff2');
  weight: 700;
  font-display: swap;
}

/* 3. unicode-range 按需加载 */
@font-face {
  font-family: 'BodyFont';
  src: url('/fonts/body-latin.woff2') format('woff2');
  unicode-range: U+0000-00FF;
  font-display: swap;
}

@font-face {
  font-family: 'BodyFont';
  src: url('/fonts/body-chinese-subset.woff2') format('woff2');
  unicode-range: U+4E00-9FFF;
  font-display: swap;
}
```

```html
<!-- 4. 预加载关键字体 -->
<link rel="preload" href="/fonts/body-400.woff2" as="font"
      type="font/woff2" crossorigin>
```

```
字体优化效果：
优化前：600KB (4 个文件，含完整中文字体)
优化后：80KB (子集化 + 只加载需要的字重)
减少：87%
```

### 步骤 3：JavaScript 优化

```javascript
// 1. 替换 moment.js 为 date-fns
// 之前
import moment from 'moment';
moment(date).format('YYYY-MM-DD');

// 之后
import { format } from 'date-fns';
format(date, 'yyyy-MM-dd');
```

```jsx
// 2. 代码分割：按路由和功能分割
const Home = lazy(() => import('./pages/Home'));
const Article = lazy(() => import('./pages/Article'));

// 3. 按需加载非首屏功能
const Comments = lazy(() => import('./components/Comments'));
const ShareButtons = lazy(() => import('./components/ShareButtons'));
const CodeHighlight = lazy(() => import('./components/CodeHighlight'));

function ArticlePage({ article }) {
  return (
    <div>
      <Article content={article.content} />

      <Suspense fallback={<CommentsSkeleton />}>
        <Comments articleId={article.id} />
      </Suspense>

      <Suspense fallback={null}>
        <ShareButtons url={article.url} />
      </Suspense>
    </div>
  );
}
```

```
JS 优化效果：
优化前：800KB (1 个文件，含 moment.js)
优化后：180KB (首屏 50KB + 按需加载)
减少：78%
```

### 步骤 4：第三方脚本优化

```html
<!-- 之前：6 个脚本全部同步加载 -->
<script src="https://analytics.js"></script>
<script src="https://gtm.js"></script>
<script src="https://facebook-pixel.js"></script>
<script src="https://chat-widget.js"></script>
<script src="https://ad-script.js"></script>
<script src="https://support-widget.js"></script>

<!-- 之后：分级加载 -->
<!-- 高优先级：defer -->
<script defer src="https://gtm.js"></script>

<!-- 中优先级：用户交互后加载 -->
<script>
  ['scroll', 'click'].forEach(event => {
    window.addEventListener(event, () => {
      const script = document.createElement('script');
      script.src = 'https://analytics.js';
      document.body.appendChild(script);
    }, { once: true, passive: true });
  });
</script>

<!-- 低优先级：按需加载 -->
<!-- 聊天、客服、广告 → 用户点击时才加载 -->
```

```
第三方脚本优化效果：
优化前：350KB, 800ms 阻塞
优化后：75KB (defer) + 按需加载
减少：78% 体积，阻塞时间降至 150ms
```

### 步骤 5：缓存策略

```nginx
# Nginx 配置

# 带 hash 的静态资源：缓存 1 年
location /_next/static/ {
  add_header Cache-Control "public, max-age=31536000, immutable";
}

# 图片：缓存 1 年
location /images/ {
  add_header Cache-Control "public, max-age=31536000, immutable";
}

# HTML：不缓存，每次验证
location / {
  add_header Cache-Control "no-cache";
}
```

```javascript
// Next.js 配置
module.exports = {
  async headers() {
    return [
      {
        source: '/_next/static/:path*',
        headers: [{
          key: 'Cache-Control',
          value: 'public, max-age=31536000, immutable',
        }],
      },
    ];
  },
};
```

## 常见误区

1. **只优化图片，忽略 JS 体积**：图片优化收益大（通常能减 70%+），但如果 JS 有 800KB，光优化图片不够。需要同时做代码分割、替换大型库、Tree Shaking。
2. **优化完不建立预算**：一次性优化后体积确实降下来了，但没有建立资源体积预算和 CI 检查，下次迭代又会悄悄膨胀。优化必须配合预算和自动化才能持续。
3. **缓存策略配错导致更新不生效**：静态资源缓存 1 年但文件名没带 hash，或者 HTML 也设了强缓存，导致用户看不到更新。缓存策略必须和构建工具的 hash 机制配合。
4. **优化后不验证功能**：图片压缩过度会模糊、代码分割后路由跳转可能白屏、字体子集化可能漏字。优化后必须做功能回归测试。

## 工程建议

1. **按收益排序优化**：图片 > 字体 > JS > 第三方脚本 > CSS。通常图片优化收益最大，应该优先处理。
2. **建立自动化优化流水线**：构建时自动压缩图片、生成响应式图片、子集化字体、分析 JS 体积，把优化变成构建流程的一部分而非手动操作。
3. **用 Lighthouse CI 作为优化验收标准**：优化前后各跑一次 Lighthouse，对比 LCP、TBT、CLS 的变化，用数据说话而不是"感觉快了"。
4. **记录优化前后的详细数据**：把每种资源的优化前体积、优化后体积、减少比例记录下来，形成报告。这既是验收证据，也是后续迭代的基线。

## 小结

1. **先分析**：用 DevTools Network 面板查看资源组成
2. **图片优化收益最大**：WebP + 响应式通常能减少 70%+
3. **字体必须子集化**：中文字体子集化后减少 90%+
4. **JS 按需加载**：首屏只加载必需的代码
5. **第三方脚本分级**：高→立即，中→defer，低→按需
6. **缓存策略**：静态资源长缓存 + hash 文件名
