## 一、状态位置影响渲染范围

```
┌──────────────────────────────────────────────────────────────┐
│              状态位置 → 渲染范围                               │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  ❌ 状态放在顶层                                              │
│  ┌─ App (state: { theme, user, notifications }) ─┐           │
│  │  ├─ Header (只用 theme)                        │           │
│  │  ├─ Sidebar (只用 user)                        │           │
│  │  └─ Content (只用 notifications)               │           │
│  └───────────────────────────────────────────────┘           │
│  → 任何状态变化 → 全部组件重渲染                              │
│                                                              │
│  ✅ 状态下沉到需要的组件                                      │
│  ┌─ App ───────────────────────────────────────┐             │
│  │  ├─ Header (state: theme)                    │             │
│  │  ├─ Sidebar (state: user)                    │             │
│  │  └─ Content (state: notifications)           │             │
│  └─────────────────────────────────────────────┘             │
│  → 通知变化 → 只有 Content 渲染                               │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 1.1 状态下沉示例

```javascript
// ❌ 状态在父组件 → 输入时整个表单重渲染
function Form() {
  const [name, setName] = useState('');
  const [email, setEmail] = useState('');

  return (
    <div>
      <NameInput value={name} onChange={setName} />
      <EmailInput value={email} onChange={setEmail} />
      <ExpensivePreview /> {/* 不依赖 name/email，但也渲染了 */}
    </div>
  );
}

// ✅ 把不相关的组件移出
function Form() {
  return (
    <div>
      <NameSection />
      <EmailSection />
      <ExpensivePreview />
    </div>
  );
}

function NameSection() {
  const [name, setName] = useState('');
  return <input value={name} onChange={e => setName(e.target.value)} />;
}
```

## 二、状态拆分

### 2.1 避免把不相关的状态捆绑在一起

```javascript
// ❌ 所有状态捆绑 → 改主题也触发用户列表渲染
const [state, setState] = useState({
  theme: 'light',
  user: null,
  products: [],
  cart: [],
  notifications: [],
});

// ✅ 拆分为独立状态
const [theme, setTheme] = useState('light');
const [user, setUser] = useState(null);
const [products, setProducts] = useState([]);
const [cart, setCart] = useState([]);
const [notifications, setNotifications] = useState([]);
```

### 2.2 状态合并的例外

```javascript
// 如果多个状态总是一起更新，合并反而更好
// ❌ 分开 → 两次渲染
const [firstName, setFirstName] = useState('');
const [lastName, setLastName] = useState('');

function handleNameChange(e) {
  setFirstName(e.target.value.split(' ')[0]);
  setLastName(e.target.value.split(' ')[1]);
}

// ✅ 合并 → 一次渲染
const [name, setName] = useState({ first: '', last: '' });

function handleNameChange(e) {
  const [first, last] = e.target.value.split(' ');
  setName({ first, last });
}
```

## 三、组件拆分策略

### 3.1 将频繁变化的部分隔离

```javascript
// ❌ 频繁变化的输入和不频繁变化的列表在同一个组件
function SearchPage() {
  const [query, setQuery] = useState('');
  const [results, setResults] = useState([]);

  return (
    <div>
      {/* 输入框每次按键都触发整个 SearchPage 渲染 */}
      <input value={query} onChange={e => setQuery(e.target.value)} />
      {/* 结果列表也被带动渲染 */}
      <ResultList items={results} />
      <ExpensiveFilters />
    </div>
  );
}

// ✅ 拆分：输入框独立，不影响其他部分
function SearchPage() {
  return (
    <div>
      <SearchInput />
      <ResultList />
      <ExpensiveFilters />
    </div>
  );
}

function SearchInput() {
  const [query, setQuery] = useState('');
  // 只有输入框组件渲染
  return <input value={query} onChange={e => setQuery(e.target.value)} />;
}
```

### 3.2 children 模式

```javascript
// ❌ children 在父组件内部 → 父组件渲染带动 children 渲染
function Container() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <button onClick={() => setCount(c => c + 1)}>Count: {count}</button>
      {/* 这些 children 被带动渲染 */}
      <ExpensiveComponentA />
      <ExpensiveComponentB />
    </div>
  );
}

// ✅ children 作为 props 传入 → 不受父组件渲染影响
function Container({ children }) {
  const [count, setCount] = useState(0);

  return (
    <div>
      <button onClick={() => setCount(c => c + 1)}>Count: {count}</button>
      {children} {/* children 的渲染由父级控制 */}
    </div>
  );
}

// 使用
<Container>
  <ExpensiveComponentA />  {/* 不会因为 Container 内部状态变化而渲染 */}
  <ExpensiveComponentB />
</Container>
```

## 四、React 18 自动批处理

```
┌──────────────────────────────────────────────────────────────┐
│                React 18 自动批处理                            │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  React 18 之前：                                              │
│  - 事件处理函数中：批处理（一次渲染）                          │
│  - setTimeout/Promise 中：不批处理（多次渲染）                │
│                                                              │
│  React 18：                                                   │
│  - 所有场景都自动批处理                                       │
│  - setTimeout、Promise、原生事件 → 都合并为一次渲染            │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

```javascript
// React 18 中，这只会触发一次渲染
function handleClick() {
  // 在 React 18 中，即使在 setTimeout 中也是批处理的
  setTimeout(() => {
    setCount(c => c + 1);  // 不会立即渲染
    setName('Alice');       // 不会立即渲染
    setAge(30);             // 不会立即渲染
    // → 三个更新合并为一次渲染
  }, 100);
}

// 如果需要强制同步更新（极少场景）
import { flushSync } from 'react-dom';

function handleClick() {
  flushSync(() => {
    setCount(c => c + 1);
  });
  // 这里 DOM 已经更新了
  flushSync(() => {
    setName('Alice');
  });
  // 这里 DOM 也更新了
  // → 两次渲染，但保证了同步性
}
```

## 五、派生状态避免重复计算

```javascript
// ❌ 用 state 存储可以从其他 state 推导的值
const [items, setItems] = useState([]);
const [total, setTotal] = useState(0); // 可以从 items 推导

function addItem(item) {
  setItems([...items, item]);
  setTotal(total + item.price); // 容易出 bug（两次状态不同步）
}

// ✅ 用 useMemo 计算派生值
const [items, setItems] = useState([]);
const total = useMemo(() => items.reduce((sum, i) => sum + i.price, 0), [items]);

function addItem(item) {
  setItems([...items, item]);
  // total 自动更新，不需要额外 state
}
```

## 动手练习

1. 创建一个搜索页面：输入框 + 结果列表 + 过滤器

3. 拆分组件，隔离渲染范围

### 练习三：children 模式

1. 创建一个可折叠面板组件，内部有频繁变化的状态
2. 把面板内容作为 children 传入
3. 验证面板折叠时，children 不会重渲染

---

## 小结

1. **状态下沉**：把状态放到使用它的最低层级
2. **状态拆分**：不相关的状态不要捆绑在一起
3. **组件拆分**：频繁变化的部分隔离出来
4. **children 模式**：把不依赖父组件状态的内容作为 props 传入
5. **React 18 自动批处理**：多次 setState 合并为一次渲染
6. **派生状态用 useMemo**：不要用 useState 存储可推导的值
