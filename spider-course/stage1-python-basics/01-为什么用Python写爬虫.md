## 一、什么是爬虫？

### 1.1 从餐厅菜单说起

想象你走进一家餐厅，服务员递上菜单，你从头到尾看了一遍，记下了想吃的菜。

这个过程，换成互联网的语境就是：

```
┌─────────────┐         HTTP 请求（翻开菜单）        ┌─────────────┐
│             │ ───────────────────────────────────→ │             │
│   你的程序   │                                      │   目标网站   │
│  （你本人）  │ ←─────────────────────────────────── │  （餐厅）    │
│             │         HTML 响应（菜单内容）          │             │
└─────────────┘                                      └─────────────┘
        │
        ▼
┌─────────────┐
│  提取有用信息  │  ← 把你感兴趣的菜名、价格记下来
│ （解析数据）   │
└─────────────┘
```

**爬虫（Web Crawler / Web Scraper）** 就是一个自动化的"翻菜单"程序——它代替你打开网页、读取内容、提取你需要的数据。

### 1.2 爬虫的工作流程

爬虫的核心流程其实非常简单，只有四步：

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  1. 发送  │    │  2. 获取  │    │  3. 解析  │    │  4. 存储  │
│  请求     │ ──→│  响应     │ ──→│  数据     │ ──→│  数据     │
│          │    │          │    │          │    │          │
│ 打开网页  │    │ 拿到网页  │    │ 提取想要  │    │ 保存到    │
│ 的动作    │    │ 的内容    │    │ 的信息    │    │ 本地      │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
  GET /index      <html>...       标题、价格       CSV / 数据库
```

用前端开发者熟悉的话来说：

- **发送请求** → 就像你在浏览器地址栏输入 URL 并回车
- **获取响应** → 就像 DevTools Network 面板里看到的 Response
- **解析数据** → 就像用 `document.querySelector()` 提取 DOM 节点
- **存储数据** → 就像把数据存进 localStorage，只不过爬虫通常存文件或数据库

### 1.3 爬虫 vs 浏览器：有什么区别？

你可能会想："我直接用浏览器看不就行了？" 区别在于：

```
┌────────────────────────────────────────────────────────────┐
│                    浏览器 vs 爬虫                           │
├────────────────┬───────────────────────────────────────────┤
│                │  浏览器              爬虫                  │
├────────────────┼───────────────────────────────────────────┤
│ 渲染页面       │  ✅ 完整渲染          ❌ 只拿原始数据       │
│ 速度           │  一次一页            可以批量、并发         │
│ 自动化         │  需要手动操作         全自动运行            │
│ 数据提取       │  用眼睛看            程序化提取            │
│ 可扩展性       │  低                  高                   │
└────────────────┴───────────────────────────────────────────┘
```

简单来说：浏览器是给人看的，爬虫是给程序用的。

作为前端开发者，你可以这样理解这些库的角色：

| Python 库 | 前端类比 | 作用 |
|---|---|---|
| `requests` | `fetch()` / `axios` | 发送 HTTP 请求 |
| `BeautifulSoup` | `document.querySelector()` | 解析和提取 HTML |
| `lxml` | 更快的 `querySelector` | 高性能 HTML/XML 解析 |
| `Scrapy` | 一套完整的爬虫框架 | 大规模、结构化的爬虫项目 |
| `Playwright` | Puppeteer | 控制真实浏览器 |
| `pandas` | lodash + Excel | 数据清洗和分析 |

### 2.2 可读性：写起来像 pseudocode

Python 最大的特点就是——代码读起来像人话。来看同一个爬虫逻辑的对比：

**Python 版本：**

```python
import requests
from bs4 import BeautifulSoup

# 发送请求，获取网页内容
response = requests.get("https://example.com/books")

# 解析 HTML
soup = BeautifulSoup(response.text, "html.parser")

# 提取所有书名
for book in soup.select(".book-title"):
    print(book.text)
```

**Node.js 版本：**

```javascript
const axios = require('axios');
const cheerio = require('cheerio');

(async () => {
  const response = await axios.get('https://example.com/books');
  const $ = cheerio.load(response.data);
  $('.book-title').each((i, el) => {
    console.log($(el).text());
  });
})();
```

**Java 版本：**

```java
import org.jsoup.Jsoup;
import org.jsoup.nodes.Document;
import org.jsoup.nodes.Element;
import org.jsoup.select.Elements;
import java.io.IOException;

public class BookScraper {
    public static void main(String[] args) throws IOException {
        Document doc = Jsoup.connect("https://example.com/books").get();
        Elements books = doc.select(".book-title");
        for (Element book : books) {
            System.out.println(book.text());
        }
    }
}
```

差距一目了然——Python 版本最短、最直观。

## 五、法律与道德：爬虫的边界

### 5.1 哪些可以爬？

```
┌─────────────────────────────────────────────────────────────┐
│                    爬虫的合法边界                            │
├──────────────┬──────────────────────────────────────────────┤
│  ✅ 通常合法  │  公开可访问的网页数据                         │
│              │  政府公开信息                                 │
│              │  新闻网站公开文章                             │
│              │  有明确 API 且允许抓取的数据                   │
├──────────────┼──────────────────────────────────────────────┤
│  ⚠️ 灰色地带  │  需要登录才能访问的数据                       │
│              │  未明确禁止但 robots.txt 禁止的内容            │
│              │  高频访问影响服务器正常运行                     │
├──────────────┼──────────────────────────────────────────────┤
│  ❌ 违法风险  │  破解加密/反爬机制获取非公开数据               │
│              │  爬取个人隐私信息并传播                        │
│              │  绕过付费墙获取付费内容                        │
│              │  对网站造成 DDoS 级别的访问压力                 │
└──────────────┴──────────────────────────────────────────────┘
```

### 5.2 三条基本原则

1. **尊重 robots.txt**：每个网站根目录下的 `robots.txt` 文件告诉你哪些可以爬、哪些不行
2. **控制频率**：不要对网站发起过于频繁的请求，加合理的延迟
3. **不碰隐私**：个人身份信息、手机号、地址等敏感数据不要碰

> 我们会在后续课程中详细讲解爬虫的法律风险和合规实践。这里先记住一句话：**技术无罪，但使用技术的人要有底线。**

## 常见误区

- **"Python 能搞定所有爬虫需求"**：Python 生态确实最强，但不是万能的。有些场景（比如需要高性能并发的实时数据采集）可能 Go 或 Java 更合适。选择技术栈要看具体需求，不要盲目信仰某一种语言。
- **"爬虫就是循环发请求"**：写一个能跑的爬虫很容易，写一个能稳定运行的爬虫很难。反爬对抗、数据清洗、并发控制、异常重试、断点续爬……这些工程化问题才是爬虫开发的真正难点。
- **"前端经验对爬虫没用"**：恰恰相反，你已经具备的 HTML/CSS/JS/HTTP 知识是爬虫开发的核心前置技能。CSS 选择器、DOM 结构、网络请求、JSON 解析——这些你每天都在用的东西，爬虫里天天用。
- **"爬虫不需要考虑法律问题"**：技术无罪，但使用技术的人要负责任。在开始写爬虫之前，先了解目标网站的 robots.txt、服务条款和相关法律法规，避免踩红线。

## 工程建议

- **根据场景选择爬虫工具**：静态页面用 requests + BeautifulSoup 即可；需要 JavaScript 渲染的页面用 Playwright；大规模、结构化的爬虫项目用 Scrapy 框架。不要用 Playwright 去爬一个纯静态页面，杀鸡不需要牛刀。
- **先学好 Python 基础再写爬虫**：变量、数据结构、函数、文件操作、异常处理——这些基础不扎实，写爬虫时会处处碰壁。花一两天打好基础，比边写边查文档高效得多。
- **善用前端优势降低学习曲线**：CSS 选择器直接迁移到 BeautifulSoup，HTTP 知识直接用于 requests，JSON 处理经验直接用于 API 爬取。你不是从零开始，而是带着一半的武器来的。
- **从简单项目开始，逐步增加复杂度**：先爬一个纯静态的书籍列表页面，再爬需要翻页的网站，再爬需要登录的页面，最后爬需要处理反爬的目标。循序渐进比一步到位更靠谱。

## 小结

本课的核心要点：

1. **爬虫本质**：自动化地获取网页数据的程序，流程是"请求 -> 响应 -> 解析 -> 存储"
2. **Python 优势**：生态最强（requests、BS4、Scrapy、Playwright）、代码简洁、社区活跃
3. **前端优势**：你已有的 HTML/CSS/JS/HTTP 知识可以直接迁移到爬虫领域
4. **法律边界**：爬公开数据、控频率、不碰隐私——记住这三条底线
