## 一、静态网页 vs 动态网页——印刷菜单 vs 现场烹饪

### 1.1 什么是静态网页？

```
静态网页的工作方式：

  用户输入 URL
       │
       ▼
  ┌─────────────┐        HTTP 请求        ┌─────────────┐
  │   浏览器     │ ─────────────────────→  │   服务器     │
  │             │                          │             │
  │             │ ←────────────────────── │  返回完整    │
  │  渲染 HTML  │   一整份 HTML 文档        │  的 HTML    │
  └─────────────┘                          └─────────────┘
       │
       ▼
  页面直接显示，不需要额外操作
```

**生活类比：** 静态网页就像餐厅的印刷菜单——你拿到手的时候，菜品、价格、图片都已经印好了。你不需要等厨师做菜，打开就能看到全部内容。

```python
# 用 requests 抓静态网页——一次请求就能拿到所有内容
import requests

response = requests.get("https://quotes.toscrape.com")
html = response.text  # 这个 HTML 里包含了页面上所有可见的文字
# 直接用 BeautifulSoup 解析就行，数据都在里面
```

### 1.2 什么是动态网页？

```
动态网页的工作方式：

  用户输入 URL
       │
       ▼
  ┌─────────────┐   ① 请求     ┌─────────────┐
  │   浏览器     │ ──────────→ │   服务器     │
  │             │              │             │
  │             │  ② 返回一个  │  返回几乎    │
  │  收到空壳    │ ←────────── │  空的 HTML   │
  │  HTML       │   空的 HTML  │  （只有骨架） │
  └──────┬──────┘              └─────────────┘
         │
         │  ③ 浏览器执行 JavaScript
         ▼
  ┌─────────────┐   ④ JS 发请求  ┌─────────────┐
  │  JS 引擎    │ ─────────────→ │  API 服务器  │
  │  开始工作    │               │             │
  │             │  ⑤ 返回 JSON   │             │
  │             │ ←──────────── │  返回数据    │
  └──────┬──────┘   数据         └─────────────┘
         │
         │  ⑥ JS 用数据渲染页面
         ▼
  ┌─────────────┐
  │  页面终于    │
  │  显示内容！  │
  └─────────────┘
```

**生活类比：** 动态网页就像现场烹饪的料理节目——你先拿到一个空盘子（空 HTML），然后厨师（JavaScript）现场制作（发 API 请求拿数据），最后才把菜端上来（渲染到页面）。你看到的"菜"不是提前准备好的，而是现场做出来的。

```python
# ❌ 用 requests 抓动态网页——拿到的几乎是个空壳
import requests

response = requests.get("https://某个动态网站.com/products")
html = response.text
print(html)
# 输出可能是：
# <div id="app"></div>    ← 就一个空的挂载点，什么数据都没有！
# <script src="/js/app.js"></script>
# 数据全靠 JS 加载，requests 根本执行不了 JS
```

### 1.3 一张表看懂区别

```
┌──────────────┬────────────────────────┬────────────────────────┐
│   对比项      │   静态网页              │   动态网页              │
├──────────────┼────────────────────────┼────────────────────────┤
│  内容来源     │  HTML 文件里直接写好     │  JavaScript 运行后生成  │
│  数据加载     │  页面打开就有           │  需要额外的 API 请求    │
│  requests    │  能直接拿到完整内容      │  只能拿到空壳 HTML      │
│  技术栈       │  原生 HTML/CSS          │  React/Vue/Angular 等  │
│  生活类比     │  印刷菜单               │  现场烹饪节目           │
│  爬取难度     │  ★★☆☆☆                │  ★★★★☆               │
└──────────────┴────────────────────────┴────────────────────────┘
```

## 二、SSR 与 CSR——两种渲染哲学

### 2.1 SSR（Server-Side Rendering）服务端渲染

```
SSR 工作流程：

  浏览器请求 URL
       │
       ▼
  ┌─────────────┐
  │   服务器     │
  │             │
  │  ① 取数据   │  ← 数据库 / API
  │  ② 填模板   │  ← 把数据塞进 HTML 模板
  │  ③ 生成完整  │  ← 返回包含全部内容的 HTML
  │    HTML     │
  └──────┬──────┘
         │
         ▼
  浏览器收到完整的 HTML → 直接显示

  结论：requests 能直接拿到完整内容 ✅
```

**生活类比：** SSR 就像外卖——厨师在厨房做好（服务端渲染），送到你手上的是一份完整的饭菜（完整 HTML），你打开就能吃。

```python
# SSR 页面：requests 直接能抓到完整内容
import requests
from bs4 import BeautifulSoup

response = requests.get("https://news.ycombinator.com")
soup = BeautifulSoup(response.text, "html.parser")

# 标题列表直接就在 HTML 里，不需要执行 JS
titles = soup.select(".titleline > a")
for t in titles:
    print(t.text)
```

### 2.2 CSR（Client-Side Rendering）客户端渲染

```
CSR 工作流程：

  浏览器请求 URL
       │
       ▼
  ┌─────────────┐
  │   服务器     │
  │             │
  │  返回一个    │  ← 几乎空的 HTML + 一个 JS 文件链接
  │  "空壳" HTML │
  └──────┬──────┘
         │
         ▼
  浏览器下载并执行 JavaScript
         │
         ▼
  ┌─────────────┐
  │  JavaScript  │
  │             │
  │  ① 调 API   │  ← fetch / axios 请求后端接口
  │  ② 拿到 JSON │  ← {"products": [...]}
  │  ③ 渲染 DOM  │  ← 用 JS 把数据插到页面上
  └──────┬──────┘
         │
         ▼
  页面终于显示内容

  结论：requests 只能拿到空壳，需要额外手段 ❌
```

**生活类比：** CSR 就像自热火锅——商家只给你原材料和加热包（空 HTML + JS），你需要自己动手加热（执行 JS），等它"煮"好了才能吃（页面渲染完成）。

### 2.3 SSR vs CSR 对比

```
┌──────────────┬───────────────────────┬───────────────────────┐
│   对比项      │   SSR 服务端渲染       │   CSR 客户端渲染       │
├──────────────┼───────────────────────┼───────────────────────┤
│  首屏加载     │  快（HTML 直接有内容）  │  慢（要等 JS 执行完）  │
│  SEO 友好    │  好（爬虫直接读 HTML）  │  差（爬虫看到空壳）    │
│  服务器压力   │  大（每次都要渲染）     │  小（只返回静态文件）   │
│  用户体验     │  每次跳转都白屏        │  跳转流畅（SPA）       │
│  爬虫抓取     │  requests 直接搞定     │  需要浏览器自动化      │
│  典型框架     │  Next.js、Nuxt.js     │  Create React App     │
└──────────────┴───────────────────────┴───────────────────────┘
```

> **前端开发者注意：** 如果你用过 Next.js 或 Nuxt.js，你已经同时接触过 SSR 和 CSR 了。Next.js 的 `getServerSideProps` 就是 SSR，而普通的 `useEffect` + `fetch` 就是 CSR。爬虫视角下，SSR 页面友好得多。

## 三、如何判断页面是静态还是动态？

### 3.1 方法一：查看网页源代码

```
操作步骤：

  ① 在浏览器中打开目标网页
  ② 右键 → "查看网页源代码"（或 Ctrl+U）
  ③ Ctrl+F 搜索你要抓的数据

  ┌─────────────────────────────────────────────┐
  │  搜索结果分析                                 │
  ├─────────────────────────────────────────────┤
  │                                             │
  │  找到了你要的数据？                           │
  │       │                                     │
  │       ├── 是 → 静态页面，requests 直接抓     │
  │       │                                     │
  │       └── 没找到 → 可能是动态页面，继续排查   │
  │                                             │
  └─────────────────────────────────────────────┘
```

```python
# 实际操作示例
import requests

# 假设你要抓某个商品的价格
response = requests.get("https://某电商网站.com/product/123")

# 在 response.text 中搜索价格，比如 "¥99.9"
if "99.9" in response.text:
    print("找到了！这是静态页面，可以直接解析")
else:
    print("没找到！很可能是动态渲染的，需要其他手段")
```

```
操作步骤：

  ① F12 打开 DevTools

  ③ 勾选 "Preserve log"（保留日志）
  ④ 刷新页面
  ⑤ 在过滤器中点击 "Fetch/XHR"

  ┌─────────────────────────────────────────────────────┐
  │  Network 面板 · Fetch/XHR 过滤                        │
  ├─────────────────────────────────────────────────────┤
  │                                                     │
  │  Name              Status   Type    Size   Time     │
  │  ─────────────────────────────────────────────────  │
  │  /api/products      200     xhr     12.3K  234ms    │ ← 数据接口！
  │  /api/categories    200     xhr     2.1K   89ms     │ ← 数据接口！

  │  这些 API 接口就是数据的真正来源！                    │

  └─────────────────────────────────────────────────────┘
```

**生活类比：** XHR 请求就像餐厅的"后厨传送带"——你在前台看到的菜品（页面内容），其实是通过后厨传送带（XHR/fetch）送过来的。Network 面板让你能看到这些传送带在运什么。

```
  ├─────────────┼───────────────────────────────────────┤

  │             │  开发者工具提示 Vue detected            │

  │  Angular     │  <app-root> 自定义标签                 │
  │             │  带有 ng-version 属性                   │
  ├─────────────┼───────────────────────────────────────┤
  │  Next.js     │  <script id="__NEXT_DATA__">          │
  │             │  内嵌 JSON 数据（SSR + CSR 混合）       │
  └─────────────┴───────────────────────────────────────┘

  如果你看到了这些特征 → 页面大概率是 CSR，需要用特殊手段抓取
```

## 四、为什么 requests 拿不到动态内容？

### 4.1 requests 的本质限制

```python
# requests 只做了一件事：发送 HTTP 请求，接收 HTTP 响应
# 它不会执行 JavaScript，不会渲染页面，不会发起后续请求

import requests

response = requests.get("https://某动态网站.com")
print(response.text)

# 你拿到的 HTML 可能只有这些：
# <html>
#   <head><title>某网站</title></head>
#   <body>
#     <div id="root"></div>                    ← 空的！
#     <script src="/static/js/bundle.js"></script>  ← JS 文件链接
#   </body>
# </html>
#
# 页面上的商品列表、价格、评论……全部不在这个 HTML 里！
# 它们要等 JavaScript 执行后才会被"造"出来。
```

**生活类比：** `requests` 就像一个只能拍照的相机——你对着餐厅拍一张照片（发请求），照片里只有餐厅的装修（HTML 骨架），但菜单上的菜（数据）是厨师现场做的（JS 渲染），照片拍不到还没做好的菜。

### 4.2 动态页面的数据到底在哪里？

```
动态页面数据的三种藏身之处：

  ┌──────────────────────────────────────────────────────┐
  │                                                      │
  │  位置 1：XHR/Fetch API 请求中（最常见！）             │
  │  ───────────────────────────────────────────────     │
  │  JS 代码调用 /api/products → 返回 JSON 数据          │
  │  在 Network 面板的 Fetch/XHR 里能看到                 │
  │  ✅ 可以直接用 requests 请求这个 API！                │
  │                                                      │
  │  位置 2：HTML 中的 <script> 标签里的内嵌数据          │
  │  ───────────────────────────────────────────────     │
  │  有些 SSR 框架会把初始数据塞进 <script> 标签          │
  │  例如 Next.js 的 __NEXT_DATA__                       │
  │  ✅ 可以用正则从 HTML 中提取 JSON                     │
  │                                                      │
  │  位置 3：JavaScript 代码中硬编码                      │
  │  ───────────────────────────────────────────────     │
  │  少数网站把数据写死在 JS 文件里                        │
  │  ❌ 需要下载 JS 文件并解析，比较麻烦                   │
  │                                                      │
  └──────────────────────────────────────────────────────┘
```

## 五、SPA 架构——前端开发者最熟悉的世界

### 5.1 什么是 SPA？

```
SPA（Single Page Application，单页面应用）架构：

  ┌─────────────────────────────────────────────────┐
  │  浏览器                                          │
  │                                                 │
  │  ┌───────────────────────────────────────────┐  │
  │  │  单个 HTML 页面（壳）                      │  │
  │  │                                           │  │
  │  │  ┌─────────────────────────────────────┐  │  │
  │  │  │  /home → 显示首页组件               │  │  │
  │  │  │  /about → 切换为关于页组件           │  │  │
  │  │  │  /products → 切换为商品列表组件      │  │  │
  │  │  │                                     │  │  │
  │  │  │  URL 变化了，但页面没有真正"跳转"    │  │  │
  │  │  │  只是 JS 在同一个页面里切换组件       │  │  │
  │  │  └─────────────────────────────────────┘  │  │
  │  │                                           │  │
  │  └───────────────────────────────────────────┘  │
  │                                                 │
  │  JS 运行时会做的事情：                            │
  │  ① 监听 URL 变化（History API / Hash）           │
  │  ② 根据路由加载对应组件                          │
  │  ③ 组件内发 API 请求获取数据                     │
  │  ④ 用数据渲染 DOM                               │
  │                                                 │
  └─────────────────────────────────────────────────┘
```

**生活类比：** SPA 就像一个大型商场里的"全息投影导航"——你站在原地不动（单页面），但投影内容会根据你的选择不断切换（路由切换），每次切换时还需要去后台取新的展示素材（API 请求）。

### 5.2 前端开发者视角的 SPA 数据流

```
你在前端开发中写过的代码：               爬虫工程师看到的现象：

  // React 组件中                       Network 面板里：
  useEffect(() => {                    GET /api/products?page=1
    fetch('/api/products')               → 200 OK, JSON 数据
      .then(res => res.json())
      .then(data => setProducts(data))   页面上：
  }, []);                                商品列表正常显示

  ────────────────────────────────────────────────────────

  // 你的组件渲染                       但用 requests 抓：
  return (                             response.text → 空壳 HTML
    <div>                              数据根本不在 HTML 里！
      {products.map(p =>               因为 fetch() 是在浏览器中
        <ProductCard key={p.id} .../>  执行的，requests 不会执行 JS
      )}
    </div>
  )
```

### 5.3 常见 SPA 框架一览

```
┌──────────────┬─────────────────────────────────────────────┐
│  框架        │  特点与爬虫相关事项                            │
├──────────────┼─────────────────────────────────────────────┤
│  React       │  最流行的前端框架                              │
│             │  通常配合 Next.js（SSR）或 CRA（纯 CSR）       │
│             │  数据通常通过 API 接口加载                      │
├──────────────┼─────────────────────────────────────────────┤
│  Vue         │  国内使用极广                                  │
│             │  通常配合 Nuxt.js（SSR）或 Vite（纯 CSR）      │
│             │  Vue 2 有 __vue__ 标识，Vue 3 有 __vue_app__  │
├──────────────┼─────────────────────────────────────────────┤
│  Angular     │  Google 维护的框架                             │
│             │  用 TypeScript，自定义标签如 <app-root>        │
│             │  通常用 HttpClient 发 API 请求                 │
├──────────────┼─────────────────────────────────────────────┤
│  Svelte      │  编译时框架，生成原生 JS                       │
│             │  没有虚拟 DOM，运行时开销小                     │
│             │  爬虫视角和 React/Vue 类似                     │
└──────────────┴─────────────────────────────────────────────┘
```

## 六、应对动态页面的两大方案

### 6.1 方案一：浏览器自动化

```
浏览器自动化的工作方式：

  ┌───────────────────────────────────────────────┐
  │  Python 控制真实浏览器（无头/有头）              │
  │                                               │
  │  ① 启动 Chromium 浏览器                       │
  │  ② 访问目标 URL                               │
  │  ③ 等待 JavaScript 执行完毕                    │
  │  ④ 获取渲染后的完整 DOM                        │
  │  ⑤ 提取数据                                    │
  │  ⑥ 关闭浏览器                                  │
  │                                               │
  │  工具：Playwright（推荐）、Selenium             │
  └───────────────────────────────────────────────┘

  优点：最通用，什么动态页面都能搞定
  缺点：速度慢（要启动浏览器）、资源占用大
```

**生活类比：** 浏览器自动化就像雇了一个"真人助手"帮你操作电脑——他打开浏览器、访问网页、等页面加载完、把内容抄下来给你。最可靠，但也最慢。

### 6.2 方案二：API 拦截

```
API 拦截的工作方式：

  ┌───────────────────────────────────────────────┐
  │                                               │
  │  ① 用 DevTools 分析 Network 面板              │
  │  ② 找到加载数据的 XHR/Fetch 请求               │
  │  ③ 分析 API 地址、参数、请求头                  │
  │  ④ 用 requests 直接调用这些 API                │
  │  ⑤ 解析返回的 JSON 数据                        │
  │                                               │
  │  工具：requests（或 httpx）                     │
  └───────────────────────────────────────────────┘

  优点：速度快、资源占用小、代码简单
  缺点：需要手动分析 API，接口可能有签名验证
```

**生活类比：** API 拦截就像不走正门，而是直接去后厨拿菜——你不需要经过"菜单→点菜→等待→上菜"的完整流程，直接找到后厨的传送带（API 接口），从上面拿数据。

### 6.3 两种方案的选择

```
                    需要抓动态页面
```

## 七、AJAX 与 Fetch——前端开发者的"老朋友"

### 7.1 回顾 AJAX 的本质

```
AJAX（Asynchronous JavaScript And XML）的核心思想：

  ┌─────────────┐                    ┌─────────────┐
  │   浏览器     │                    │   服务器     │
  │             │                    │             │
  │  页面已加载  │                    │             │
  │  用户操作    │                    │             │
  │    │        │                    │             │
  │    ▼        │                    │             │
  │  JS 发起    │   异步请求（不阻塞）  │             │
  │  XHR/Fetch  │ ────────────────→  │  处理请求    │
  │  请求       │                    │             │
  │    │        │   返回 JSON 数据    │             │
  │    │        │ ←────────────────  │             │
  │    ▼        │                    └─────────────┘
  │  回调函数    │
  │  更新 DOM   │
  └─────────────┘

  关键点：请求是"偷偷"发的，不刷新整个页面
```

### 7.2 你在前端写的代码 vs 爬虫视角

### 7.3 常见的 API 请求模式

```
你在前端项目中常见的 API 模式：

  ┌──────────────────────────────────────────────────────┐
  │  模式 1：RESTful API                                 │
  │  GET    /api/products        → 商品列表              │
  │  GET    /api/products/123    → 商品详情              │
  │  POST   /api/products        → 创建商品              │
  │  PUT    /api/products/123    → 更新商品              │
  │  DELETE /api/products/123    → 删除商品              │

  │  模式 2：GraphQL                                     │
  │  POST   /graphql             → 灵活查询              │

  │  返回指定字段的 JSON                                  │
  │  爬虫需要构造查询语句                                 │
  ├──────────────────────────────────────────────────────┤
  │  模式 3：分页加载                                    │
  │  GET /api/items?page=1&size=20                       │

  │  爬虫需要循环翻页                                     │
  ├──────────────────────────────────────────────────────┤
  │  模式 4：无限滚动                                    │
  │  GET /api/items?offset=0&limit=20                    │
  │  GET /api/items?offset=20&limit=20                   │
  │  GET /api/items?offset=40&limit=20                   │
  │  爬虫需要不断增加 offset 直到没有新数据               │
  └──────────────────────────────────────────────────────┘
```

## 八、动手练习

### 练习 1：判断目标网站的渲染方式

```python
"""
目标：练习判断一个网页是静态还是动态渲染
步骤：
1. 用 requests 请求以下三个网站：
   - https://quotes.toscrape.com          （静态示例）
   - https://spa5.scrape.center/           （动态示例）
   - https://quotes.toscrape.com/js/      （JS 版静态站）
2. 在返回的 HTML 中搜索特定内容（如 "Quotes to Scrape"）
3. 记录哪些网站能在 HTML 中直接找到内容
"""
import requests

urls = [
    "https://quotes.toscrape.com",
    "https://spa5.scrape.center/",
    "https://quotes.toscrape.com/js/",
]

target_text = "Quotes to Scrape"

for url in urls:
    response = requests.get(url)
    found = target_text in response.text
    status = "静态内容，可以直接抓" if found else "动态渲染，需要其他手段"
    print(f"{url}")
    print(f"  找到 '{target_text}': {found} → {status}\n")
```

### 练习 3：对比 SSR 和 CSR 页面的 HTML 差异

```python
"""
目标：直观感受 SSR 和 CSR 页面的 HTML 内容差异
步骤：
1. 分别请求一个 SSR 页面和一个 CSR 页面
2. 对比 HTML 的长度和内容密度

import requests

# SSR 页面（内容在 HTML 中）

    html = response.text
    print(f"=== {label} 页面 ===")
    print(f"  HTML 长度: {len(html)} 字符")
    print(f"  包含 <script: {html.count('<script')} 个")
    print(f"  包含 'class=\"el-': {'el-' in html}")  # Element UI 特征
    print()
```

## 小结

本课的核心知识点：

1. **静态网页的内容在 HTML 中直接可见**，requests 一次请求就能拿到所有数据
2. **动态网页的内容由 JavaScript 运行后生成**，requests 只能拿到空壳 HTML
3. **SSR（服务端渲染）** 在服务端生成完整 HTML，对爬虫友好；**CSR（客户端渲染）** 在浏览器端用 JS 渲染，对爬虫不友好
4. **判断页面类型的方法**：查看源代码搜索内容、检查 Network 面板的 XHR 请求、识别前端框架标识、禁用 JS 测试
5. **SPA 应用** 通过路由切换组件、通过 API 请求加载数据，数据通常以 JSON 格式返回
6. **应对动态页面的两大方案**：浏览器自动化（Playwright）通用但慢，API 拦截（requests）快速但需要手动分析
7. **作为前端开发者**，你已经理解了 SPA 的数据流——现在只需要转换视角，把 Network 面板里的 API 请求当作爬虫的目标

> **前端开发者的优势：** 你每天都在和动态网页打交道。你知道 `fetch()` 怎么调 API、组件怎么渲染数据、路由怎么切换页面。这些知识让你在分析动态网页时比纯后端开发者更有直觉——你只需要把视角从"构建页面"切换到"提取数据"。
