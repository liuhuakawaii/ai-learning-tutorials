## 一、验证码——网站的"门卫"

### 1.1 什么是验证码？

验证码（CAPTCHA）的全称是"全自动区分计算机和人类的公共图灵测试"。简单来说，它就是网站用来判断"你是真人还是机器人"的测试。

**生活类比：** 想象你去一个高档小区找朋友。门口有个保安（网站），他不认识你（不确定你是真人还是爬虫）。保安会让你做一个测试——回答问题、识别图片、或者滑动滑块。通过了才能进去。

```
  验证码的工作流程：

  ┌──────────┐     ┌──────────────┐     ┌──────────────┐
  │  你发送   │────→│  网站返回     │────→│  你完成验证   │
  │  请求     │     │  验证码挑战   │     │  提交答案    │
  └──────────┘     └──────────────┘     └──────┬───────┘
                                                ▼
                    ┌──────────────┐     ┌──────────────┐
                    │  验证失败     │←────│  网站判断     │
                    │  重新挑战     │     │  答案是否正确  │
                    └──────────────┘     └──────┬───────┘
                                                │ 正确
                                                ▼
                                        ┌──────────────┐
                                        │  放行，允许    │
                                        │  访问目标页面  │
                                        └──────────────┘
```

### 1.2 常见验证码类型

```
  ┌──────────────┬──────────────────────────────────────────┐
  │   类型        │   描述与特征                              │
  ├──────────────┼──────────────────────────────────────────┤
  │   文字验证码  │   显示扭曲的文字，要求输入正确字符         │
  │              │   例：显示 "aX7k2"，让你输入               │
  ├──────────────┼──────────────────────────────────────────┤
  │   图片验证码  │   选择包含特定物体的图片                   │
  │              │   例："点击所有包含红绿灯的图片"            │
  ├──────────────┼──────────────────────────────────────────┤
  │   滑块验证码  │   拖动滑块到指定位置                       │
  │              │   例：将拼图碎片拖到缺口处                  │
  ├──────────────┼──────────────────────────────────────────┤
  │   reCAPTCHA  │   Google 的验证系统，v2 打勾/v3 静默评分   │
  │              │   "我不是机器人" 复选框                     │
  ├──────────────┼──────────────────────────────────────────┤
  │   短信/邮箱   │   发送一次性验证码到手机或邮箱             │
  │   验证码      │   例：输入你手机收到的 6 位数字            │
  └──────────────┴──────────────────────────────────────────┘
```

### 1.3 各类型的技术难度

```
  文字验证码        ★★☆☆☆   OCR 可以识别简单字体
  图片选择验证码    ★★★★☆   需要图像识别模型
  滑块验证码        ★★★★☆   需要计算缺口位置 + 模拟轨迹
  reCAPTCHA v2     ★★★★★   Google 的反爬非常强
  reCAPTCHA v3     ★★★★★   基于行为评分，几乎无法绕过
  短信验证码        ★★★★★   需要手机号，涉及隐私和法律
```

**重要提醒：** 验证码处理的重点不是"如何破解"，而是"如何在遇到验证码时优雅地处理"——暂停采集、切换策略、或者直接告知用户需要手动介入。

## 二、登录态——从"陌生人"变成"自己人"

### 2.1 为什么需要登录态？

很多网站的核心数据藏在登录之后。爬虫默认是"未登录"状态，需要模拟登录才能获取这些数据。

**生活类比：** 登录就像去公司打卡。你（爬虫）走到公司门口（网站），刷了工卡（提交账号密码），前台确认你是员工（验证通过），给你一个访客贴纸（Cookie/Session）。之后你在公司里走动，别人看到贴纸就知道你是"已验证的人"。

### 2.2 Session 与 Cookie 的关系

```
  ┌──────────────────────────────────────────────────────────┐
  │  Cookie：存在浏览器端的小块数据（键值对）                  │
  │    → 像你口袋里的访客贴纸，每次请求时自动带上              │
  │                                                          │
  │  Session：存在服务器端的会话数据                           │
  │    → 像前台登记簿里你的那条记录，通过 Cookie 关联          │
  │                                                          │
  │  爬虫 → 带 Cookie 请求 → 服务器根据 Cookie 找到 Session   │
  │       → 确认你是谁 → 返回对应数据                          │
  └──────────────────────────────────────────────────────────┘
```

## 三、使用 Session 对象维持登录态

### 3.1 requests.Session 的魔力

`requests.Session()` 会自动帮你管理 Cookie。登录后服务器返回的 Cookie 会被 Session 自动保存，后续请求会自动带上。

```python
import requests

# ❌ 错误：用普通 requests.get，每次请求都是"新面孔"
response1 = requests.post('https://example.com/login', data={'user': 'xx', 'pass': 'xx'})
response2 = requests.get('https://example.com/profile')  # 没有登录态！

# ✅ 正确：用 Session 对象，自动管理 Cookie
session = requests.Session()
response1 = session.post('https://example.com/login', data={'user': 'xx', 'pass': 'xx'})
response2 = session.get('https://example.com/profile')  # 自动带上 Cookie！
```

### 3.2 模拟登录的基本步骤

```python
import requests
from bs4 import BeautifulSoup

# 第一步：创建 Session 并设置请求头
session = requests.Session()
session.headers.update({
    'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) '
                  'AppleWebKit/537.36 (KHTML, like Gecko) '
                  'Chrome/120.0.0.0 Safari/537.36'
})

# 第二步：访问登录页面（获取可能的隐藏字段）
login_page = session.get('https://example.com/login')
soup = BeautifulSoup(login_page.text, 'html.parser')

# 第三步：准备并提交登录数据
login_data = {
    'username': 'your_username',
    'password': 'your_password',
}
response = session.post('https://example.com/login', data=login_data)

# 第四步：检查是否登录成功
if response.url != 'https://example.com/login':
    print('登录成功！Session 已保存 Cookie')
    profile = session.get('https://example.com/profile')
else:
    print('登录失败，请检查账号密码')
```

  │  创建 Session │
  └──────┬───────┘
         ▼
  ┌──────────────┐

## 四、Cookie 管理详解

### 4.1 查看和设置 Cookie

```python
import requests

session = requests.Session()

# 访问网站，服务器设置 Cookie
session.get('https://httpbin.org/cookies/set/name/hello')
session.get('https://httpbin.org/cookies/set/token/abc123')

# 查看所有 Cookie
for cookie in session.cookies:
    print(f'{cookie.name} = {cookie.value} (域名: {cookie.domain})')

# 手动设置 Cookie
session.cookies.set('session_id', 'abc123xyz')
session.cookies.update({'lang': 'zh-CN', 'theme': 'dark'})
```

### 4.2 保存和加载 Cookie

```python
import json
import requests

def save_cookies(session, filepath):
    """将 Session 的 Cookie 保存为 JSON 文件"""
    cookies_dict = {}
    for cookie in session.cookies:
        cookies_dict[cookie.name] = {
            'value': cookie.value,
            'domain': cookie.domain,
            'path': cookie.path,
        }
    with open(filepath, 'w', encoding='utf-8') as f:
        json.dump(cookies_dict, f, ensure_ascii=False, indent=2)
    print(f'Cookie 已保存: {filepath}（{len(cookies_dict)} 个）')


def load_cookies(session, filepath):
    """从 JSON 文件加载 Cookie 到 Session"""
    with open(filepath, 'r', encoding='utf-8') as f:
        cookies_dict = json.load(f)
    for name, info in cookies_dict.items():
        session.cookies.set(name, info['value'],
                           domain=info.get('domain', ''))
    print(f'Cookie 已加载: {filepath}（{len(cookies_dict)} 个）')
```

### 4.3 用 Cookie 文件跳过重复登录

```python
import os

COOKIE_FILE = 'cookies.json'

def get_session(login_url, login_data, test_url):
    """获取带登录态的 Session，优先使用已保存的 Cookie"""
    session = requests.Session()
    session.headers.update({
        'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) '
                      'AppleWebKit/537.36 (KHTML, like Gecko) '
                      'Chrome/120.0.0.0 Safari/537.36'
    })

    if os.path.exists(COOKIE_FILE):
        load_cookies(session, COOKIE_FILE)
        test = session.get(test_url)
        if test.status_code == 200 and 'login' not in test.url:
            print('Cookie 仍然有效，无需重新登录')
            return session
        print('Cookie 已过期，需要重新登录')

    resp = session.post(login_url, data=login_data)
    if 'login' not in resp.url:
        save_cookies(session, COOKIE_FILE)
        print('登录成功，Cookie 已保存')
    else:
        print('登录失败')
    return session
```

```
  Cookie 持久化流程：

  ┌──────────────┐
  │  程序启动     │
  └──────┬───────┘
         ▼
  ┌──────────────┐     是     ┌──────────────┐
  │  cookies.json ├───────────→│  加载 Cookie  │
  │  文件存在？   │            │  验证有效性   │
  └──────┬───────┘            └──────┬───────┘
         │ 否                        ▼
         ▼                    ┌──────────────┐
  ┌──────────────┐           │  Cookie 有效  │
  │  执行登录     │           │  直接使用     │
  │  保存 Cookie  │           └──────────────┘
  └──────────────┘
```

## 五、CSRF Token 处理

### 5.1 什么是 CSRF Token？

CSRF Token 是网站用来防止恶意请求的安全机制。通常是一个隐藏在表单中的随机字符串，每次访问登录页面都会生成新的。

**生活类比：** 你去银行办业务，柜员先给你一张排号纸（CSRF Token）。办业务时必须出示这张纸，柜员验证号码对了才给你办。

### 5.2 提取并使用 CSRF Token

```python
from bs4 import BeautifulSoup

session = requests.Session()

# 访问登录页面，提取 CSRF Token
login_page = session.get('https://example.com/login')
soup = BeautifulSoup(login_page.text, 'html.parser')

# 从隐藏的 input 字段中提取
csrf_token = soup.select_one('input[name="csrf_token"]')['value']
print(f'CSRF Token: {csrf_token}')

# 在登录请求中带上 Token
login_data = {
    'username': 'your_username',
    'password': 'your_password',
    'csrf_token': csrf_token,
}
session.headers['Referer'] = 'https://example.com/login'
response = session.post('https://example.com/login', data=login_data)
```

```
  CSRF Token 处理流程：

  ┌──────────────┐
  │  GET 登录页面 │
  └──────┬───────┘
         ▼
  ┌──────────────┐
  │  解析 HTML    │ ← 从 <input type="hidden"> 提取 Token
  │  提取 Token   │
  └──────┬───────┘
         ▼
  ┌──────────────┐
  │  POST 登录    │ ← 用户名 + 密码 + CSRF Token
  └──────────────┘
```

## 六、用 Selenium 处理复杂登录

### 6.1 什么时候需要用 Selenium？

有些登录流程不适合用 requests：登录页面大量 JS 渲染、需要拖动滑块、需要点击图形验证码、登录过程有多步交互。

### 6.2 Selenium 自动登录并导出 Cookie

```python
from selenium import webdriver
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC
import json

def selenium_login():
    """用 Selenium 执行登录并导出 Cookie"""
    driver = webdriver.Chrome()
    try:
        driver.get('https://example.com/login')
        wait = WebDriverWait(driver, 10)

        # 等待输入框出现，填写账号密码
        username_input = wait.until(
            EC.presence_of_element_located((By.NAME, 'username'))
        )
        username_input.send_keys('your_username')
        driver.find_element(By.NAME, 'password').send_keys('your_password')

        # 点击登录按钮
        driver.find_element(By.CSS_SELECTOR, 'button[type="submit"]').click()

        # 等待登录完成
        wait.until(EC.url_changes('https://example.com/login'))
        print('Selenium 登录成功！')

        # 导出 Cookie 给 requests 使用
        return driver.get_cookies()
    finally:
        driver.quit()


def transfer_cookies(session, selenium_cookies):
    """将 Selenium 的 Cookie 转移到 requests Session"""
    for cookie in selenium_cookies:
        session.cookies.set(cookie['name'], cookie['value'],
                           domain=cookie.get('domain', ''))
    print(f'已转移 {len(selenium_cookies)} 个 Cookie')
```

### 6.3 两步验证的应对

```python
# 两步验证通常需要手动介入
# 最佳实践：Selenium 自动填写密码 → 暂停等你手动输入验证码 → 保存 Cookie

def manual_2fa_login():
    driver = webdriver.Chrome()
    driver.get('https://example.com/login')

    # 自动填写账号密码
    driver.find_element(By.NAME, 'username').send_keys('your_user')
    driver.find_element(By.NAME, 'password').send_keys('your_pass')
    driver.find_element(By.CSS_SELECTOR, 'button[type="submit"]').click()

    # 暂停，等你手动输入验证码
    print('请在浏览器中手动输入验证码，完成后按回车继续...')
    input()

    # 保存 Cookie
    cookies = driver.get_cookies()
    with open('cookies.json', 'w') as f:
        json.dump(cookies, f)
    driver.quit()
    print('Cookie 已保存，后续可用 requests 直接加载')
```

## 七、伦理边界——什么时候该停下来？

```
  ┌──────────────────────────────────────────────────────────┐
  │  以下行为可能违法或违反道德，请勿尝试：                     │
  │                                                          │
  │  ✗ 破解他人账号密码                                       │
  │  ✗ 绕过验证码批量注册虚假账号                              │
  │  ✗ 自动化登录后进行欺诈、刷单等行为                        │
  │  ✗ 绕过付费墙获取受版权保护的内容                          │
  │  ✗ 大量请求导致服务器过载                                  │
  │  ✗ 窃取他人个人信息并传播                                  │
  │                                                          │
  │  这些行为可能触犯《网络安全法》《个人信息保护法》等法律。   │
  ├──────────────────────────────────────────────────────────┤
  │  正确做法：                                               │
  │                                                          │
  │  ✓ 只爬取公开可访问的数据                                  │
  │  ✓ 遵守网站的 robots.txt 规则                             │
  │  ✓ 控制请求频率，不给服务器造成压力                        │
  │  ✓ 遇到验证码时优先考虑人工介入                            │
  │  ✓ 尊重数据所有者的权利                                    │
  └──────────────────────────────────────────────────────────┘
```

**生活类比：** 爬虫技术就像一把菜刀。你可以用它做饭（正当数据采集），但不能用它伤人（恶意攻击）。技术本身没有对错，关键在于你怎么用它。
