## 一、为什么要限速？——做一个有礼貌的爬虫

### 1.1 爬虫的"社交礼仪"

想象一下：你去朋友家做客，每秒钟按 100 次门铃。朋友不开门还好，开门了绝对把你拉黑。网站也是一样——你请求太频繁，服务器扛不住，管理员就会封你 IP。

```
┌──────────────────────────────────────────────────────────────┐
│  不限速的爬虫 vs 限速的爬虫                                    │
│                                                              │
│  ❌ 不限速：                                                  │
│  ┌─────────┐    ┌──────────────────────────┐                 │
│  │  爬虫   │──→ │  服务器                   │                 │
│  │         │──→ │  "救命！每秒 100 个请求！"│                 │
│  │         │──→ │  → 封 IP！               │                 │
│  │         │──→ │  → 返回 429/403          │                 │
│  └─────────┘    └──────────────────────────┘                 │
│                                                              │
│  ✅ 限速：                                                    │
│  ┌─────────┐    ┌──────────────────────────┐                 │
│  │  爬虫   │ ─→ │  服务器                   │                 │
│  │  (等2秒)│ ─→ │  "嗯，请求频率正常"       │                 │
│  │  (等2秒)│ ─→ │  → 正常响应 200           │                 │
│  └─────────┘    └──────────────────────────┘                 │
└──────────────────────────────────────────────────────────────┘
```

**生活类比：** 限速就像排队买奶茶。没人管的时候大家一拥而上（不限速），店员手忙脚乱。有了排队线（限速），每个人间隔几秒上前，店员从容应对，大家都买到奶茶。

### 1.2 DOWNLOAD_DELAY：最基本的限速

在 `settings.py` 中设置请求之间的延迟（单位：秒）：

```python
# settings.py

# 每次请求之间等待 2 秒
DOWNLOAD_DELAY = 2

# ❌ 错误：设置为 0，等于不限速
# DOWNLOAD_DELAY = 0

# ❌ 错误：设置太大，爬取效率太低（除非网站特别严格）
# DOWNLOAD_DELAY = 30
```

设置 `DOWNLOAD_DELAY = 2` 后，Scrapy 的行为是：

```
时间线：
0s      2s      4s      6s      8s
│       │       │       │       │
请求1   请求2   请求3   请求4   请求5
  ↓       ↓       ↓       ↓       ↓
 响应1   响应2   响应3   响应4   响应5
```

### 1.3 RANDOMIZE_DOWNLOAD_DELAY：让节奏更自然

固定间隔的请求模式太规律了，反而像机器人。`RANDOMIZE_DOWNLOAD_DELAY` 让延迟在一定范围内随机波动：

```python
# settings.py

DOWNLOAD_DELAY = 2
RANDOMIZE_DOWNLOAD_DELAY = True  # 默认就是 True

# 实际延迟 = DOWNLOAD_DELAY * (0.5 ~ 1.5)
# 也就是 1 秒 ~ 3 秒之间的随机值
```

```
固定延迟（太规律，像机器人）：
1s    2s    3s    4s    5s    6s    7s    8s
│     │     │     │     │     │     │     │
req   req   req   req   req   req   req   req

随机延迟（更自然，像真人）：
1s  2s    3s  4s      5s  6s  7s      8s
│   │     │   │       │   │   │       │
req  req   req  req    req  req  req   req
```

**生活类比：** 你刷手机看新闻，不会每隔 2 秒精确地滑一下。有时候看得快，有时候看得慢。随机延迟就是在模拟这种真人行为。

## 二、并发控制：同时派出几个"侦察兵"？

### 2.1 CONCURRENT_REQUESTS：全局并发数

```python
# settings.py

# Scrapy 下载器同时处理的最大请求数（默认 16）
CONCURRENT_REQUESTS = 8

# ❌ 错误：设置太大，你的网络和目标服务器都扛不住
# CONCURRENT_REQUESTS = 100

# ❌ 错误：设置为 1，完全串行，效率太低
# CONCURRENT_REQUESTS = 1
```

### 2.2 CONCURRENT_REQUESTS_PER_DOMAIN：单域名并发数

```python
# settings.py

# 对单个域名同时发起的最大请求数（默认 8）
CONCURRENT_REQUESTS_PER_DOMAIN = 4
```

```
┌──────────────────────────────────────────────────────────┐
│  并发控制示意图                                            │
│                                                          │
│  CONCURRENT_REQUESTS = 8（全局最多 8 个请求）              │
│  CONCURRENT_REQUESTS_PER_DOMAIN = 4（单域名最多 4 个）    │
│                                                          │
│  ┌─────────┐                                             │
│  │  爬虫   │                                             │
│  └────┬────┘                                             │
│       │                                                  │
│       ├──── 请求1 ──→ news.a.com  ✅                     │
│       ├──── 请求2 ──→ news.a.com  ✅                     │
│       ├──── 请求3 ──→ news.a.com  ✅                     │
│       ├──── 请求4 ──→ news.a.com  ✅                     │
│       ├──── 请求5 ──→ news.a.com  ❌ 达到域名限制         │
│       ├──── 请求6 ──→ news.b.com  ✅                     │
│       ├──── 请求7 ──→ news.b.com  ✅                     │
│       └──── 请求8 ──→ news.b.com  ✅                     │
│                                                          │
│  同时活跃请求：news.a.com 4个 + news.b.com 3个 = 7个     │
│  没超过全局限制 8，所以都 OK                               │
└──────────────────────────────────────────────────────────┘
```

**生活类比：** 你同时最多处理 8 件事（全局并发），但对同一个部门最多同时处理 4 件事（单域名并发）。这样不会因为一个部门的事太多而忽略了其他部门。

## 三、AutoThrottle：智能限速的"自动驾驶"

### 3.1 为什么需要 AutoThrottle？

手动设置 `DOWNLOAD_DELAY` 有个问题：你不知道网站什么时候忙、什么时候闲。AutoThrottle 就像汽车的自适应巡航——网站快就加速，网站慢就减速。

```
┌──────────────────────────────────────────────────────────┐
│  AutoThrottle 自适应限速原理                               │
│                                                          │
│  网站响应快（延迟低）                                      │
│  ┌─────┐  200  200  200  200                             │
│  │爬虫 │ ←─── ←─── ←─── ←───  "网站很闲，可以加速"       │
│  └─────┘  → 加快请求频率                                  │
│                                                          │
│  网站响应慢（延迟高）                                      │
│  ┌─────┐  ............  ............                     │
│  │爬虫 │ ←───────────── ←─────────────  "网站忙，减速"   │
│  └─────┘  → 降低请求频率                                  │
│                                                          │
│  网站开始报错（429/503）                                   │
│  ┌─────┐  429  503  429                                  │
│  │爬虫 │ ←─── ←─── ←───  "网站扛不住了，大幅减速！"      │
│  └─────┘  → 大幅降低请求频率                              │
└──────────────────────────────────────────────────────────┘
```

### 3.2 启用和配置 AutoThrottle

```python
# settings.py

# 启用 AutoThrottle 扩展（默认关闭）
AUTOTHROTTLE_ENABLED = True

# 起始下载延迟（初始速度）
AUTOTHROTTLE_START_DELAY = 1

# 最大下载延迟（最慢不超过这个值）
AUTOTHROTTLE_MAX_DELAY = 10

# 目标并发数：AutoThrottle 试图保持的每域名并发请求数
AUTOTHROTTLE_TARGET_CONCURRENCY = 2.0

# 对所有响应启用限速（不只是 2xx 响应）
# 如果设为 False，只有 2xx 响应才计入延迟计算
AUTOTHROTTLE_DEBUG = False
```

```
┌──────────────────────────────────────────────────────────┐
│  AutoThrottle 配置参数一览                                 │
├────────────────────────────┬─────────────────────────────┤
│  参数                       │  说明                       │
├────────────────────────────┼─────────────────────────────┤
│  AUTOTHROTTLE_ENABLED      │  是否启用，默认 False        │
│  AUTOTHROTTLE_START_DELAY  │  起始延迟秒数               │
│  AUTOTHROTTLE_MAX_DELAY    │  最大延迟秒数               │
│  AUTOTHROTTLE_TARGET_      │  目标并发数（默认 1.0）      │
│    CONCURRENCY             │                             │
│  AUTOTHROTTLE_DEBUG        │  调试模式，输出详细信息      │
└────────────────────────────┴─────────────────────────────┘
```

**生活类比：** AutoThrottle 就像开车时的自适应巡航。前面车多（网站响应慢）自动减速，前面没车（网站响应快）自动加速，始终和前车保持安全距离（目标并发数）。

### 3.3 手动限速 vs AutoThrottle 怎么选？

```
┌──────────────────────────────────────────────────────────┐
│  选择建议                                                 │
│                                                          │
│  场景                          →  推荐方案                │
│  ──────────────────────────────────────────────────────  │
│  爬取少量页面（< 100）          →  手动 DOWNLOAD_DELAY    │
│  爬取中等规模（100-1000）       →  AutoThrottle           │
│  爬取大规模（> 1000）           →  AutoThrottle           │
│  目标网站特别严格               →  手动 + AutoThrottle    │
│  不确定目标网站承受能力         →  AutoThrottle（最安全）  │
└──────────────────────────────────────────────────────────┘
```

## 四、重试机制：失败了再来一次

### 4.1 RetryMiddleware：Scrapy 内置的重试中间件

网络请求难免失败。Scrapy 自带 `RetryMiddleware`，遇到特定状态码会自动重试。

```python
# settings.py

# 最大重试次数（默认 2 次）
RETRY_TIMES = 3

# 哪些状态码需要重试（默认列表）
RETRY_HTTP_CODES = [500, 502, 503, 504, 408, 429]

# ❌ 错误：重试次数太多，可能陷入死循环
# RETRY_TIMES = 100

# ❌ 错误：把 404 加入重试列表，页面不存在重试也没用
# RETRY_HTTP_CODES = [404, 500, 502]
```

```
┌──────────────────────────────────────────────────────────┐
│  重试流程示意                                              │
│                                                          │
│  ┌─────────┐     ┌──────────┐     ┌──────────┐          │
│  │  爬虫   │────→│  下载器  │────→│  服务器   │          │
│  └─────────┘     └────┬─────┘     └──────────┘          │
│                       │                                   │
│              500 错误！│                                   │
│                       ▼                                   │
│                ┌──────────────┐                           │
│                │RetryMiddleware│                          │
│                │ 还能重试吗？  │                           │
│                └──────┬───────┘                           │
│                       │                                   │
│              ┌────────┴────────┐                          │
│              │                 │                          │
│         重试次数 < 3      重试次数 >= 3                    │
│              │                 │                          │
│              ▼                 ▼                          │
│         重新请求          放弃，交给                       │
│                          Spider 处理                      │
└──────────────────────────────────────────────────────────┘
```

### 4.2 常见可重试状态码说明

```
┌────────┬───────────────────────────┬──────────────────────┐
│  状态码 │  含义                      │  是否应该重试         │
├────────┼───────────────────────────┼──────────────────────┤
│  408   │  请求超时                   │  ✅ 重试，可能是网络  │
│  429   │  请求太频繁                 │  ✅ 重试，但要等久一点│
│  500   │  服务器内部错误             │  ✅ 重试，可能是临时  │
│  502   │  网关错误                   │  ✅ 重试             │
│  503   │  服务不可用                 │  ✅ 重试             │
│  504   │  网关超时                   │  ✅ 重试             │
│  403   │  禁止访问                   │  ❌ 重试也没用        │
│  404   │  页面不存在                 │  ❌ 重试也没用        │
└────────┴───────────────────────────┴──────────────────────┘
```

### 4.3 自定义重试逻辑

有时候内置的重试不够用。比如你希望遇到 403 时切换 User-Agent 再试，或者根据响应内容判断是否重试。

```python
# middlewares.py

from scrapy.downloadermiddlewares.retry import RetryMiddleware
from scrapy.utils.response import response_status_message


class SmartRetryMiddleware(RetryMiddleware):
    """智能重试中间件：根据不同的失败原因采取不同策略"""

    def process_response(self, request, response, spider):
        # 正常响应，直接返回
        if response.status == 200:
            # 额外检查：响应内容是否包含"验证"等关键词
            body = response.text
            if '请输入验证码' in body or 'Access Denied' in body:
                # 内容被拦截，需要重试
                reason = '检测到反爬拦截页面'
                return self._retry(request, reason, spider) or response
            return response

        # 403 错误：可能是 UA 被封，换个 UA 重试
        if response.status == 403:
            # 在请求的 meta 中标记需要更换 UA
            request.meta['change_ua'] = True
            reason = response_status_message(response.status)
            return self._retry(request, reason, spider) or response

        # 429 错误：请求太频繁，等待更久再重试
        if response.status == 429:
            spider.logger.warning('收到 429，等待 10 秒后重试...')
            import time
            time.sleep(10)
            reason = response_status_message(response.status)
            return self._retry(request, reason, spider) or response

        # 其他情况交给父类处理
        return super().process_response(request, response, spider)
```

在 `settings.py` 中启用自定义中间件：

```python
# settings.py

# 关闭默认的重试中间件
RETRY_ENABLED = False

# 启用自定义重试中间件（数字越小优先级越高）
DOWNLOADER_MIDDLEWARES = {
    'myproject.middlewares.SmartRetryMiddleware': 550,
}
```

## 五、增量爬取：只爬新数据

### 5.1 什么是增量爬取？

假设你要爬一个新闻网站，每天有 100 篇新文章。如果你每次把所有文章都重新爬一遍，既浪费时间又浪费带宽。增量爬取的意思就是：**只爬上次没爬过的数据**。

```
┌──────────────────────────────────────────────────────────┐
│  全量爬取 vs 增量爬取                                      │
│                                                          │
│  全量爬取（每次都爬全部）：                                 │
│  第1天：[新闻1] [新闻2] [新闻3]  →  爬了 3 篇              │
│  第2天：[新闻1] [新闻2] [新闻3] [新闻4] [新闻5]            │
│         → 爬了 5 篇（其中 3 篇是重复的！）                 │
│                                                          │
│  增量爬取（只爬新的）：                                    │
│  第1天：[新闻1] [新闻2] [新闻3]  →  爬了 3 篇              │
│  第2天：[新闻1] [新闻2] [新闻3] [新闻4] [新闻5]            │
│                            ↑新↑新                         │
│         → 只爬了 2 篇（跳过了已有的 3 篇）                 │
│                                                          │
│  效率提升：60%！                                           │
└──────────────────────────────────────────────────────────┘
```

**生活类比：** 增量爬取就像你每天查收邮件。你不会每次都从第一封邮件开始看，而是只看"未读"的。已读的跳过，新邮件才打开。

### 5.2 去重策略：怎么判断"这个数据爬过了"？

```
┌──────────────────────────────────────────────────────────┐
│  三种常用去重策略                                          │
│                                                          │
│  策略一：URL 去重                                          │
│  ┌────────────────────────────────────────────┐          │
│  │  判断依据：文章的 URL 是否已经存在           │          │
│  │  优点：简单高效                              │          │
│  │  缺点：同一 URL 内容更新了检测不到           │          │
│  │  适用：URL 唯一且内容不变的网站              │          │
│  └────────────────────────────────────────────┘          │
│                                                          │
│  策略二：日期去重                                          │
│  ┌────────────────────────────────────────────┐          │
│  │  判断依据：文章发布时间是否晚于上次爬取时间  │          │
│  │  优点：可以检测到内容更新                    │          │
│  │  缺点：需要网站提供可靠的发布时间            │          │
│  │  适用：新闻、博客等有明确时间戳的网站        │          │
│  └────────────────────────────────────────────┘          │
│                                                          │
│  策略三：数据库去重                                        │
│  ┌────────────────────────────────────────────┐          │
│  │  判断依据：查询数据库中是否已有该记录        │          │
│  │  优点：最可靠，支持复杂判断                  │          │
│  │  缺点：需要额外维护数据库                    │          │
│  │  适用：正式项目、大规模爬取                  │          │
│  └────────────────────────────────────────────┘          │
└──────────────────────────────────────────────────────────┘
```

### 5.3 实现 URL 去重的 Spider

```python
# spiders/news_spider.py

import scrapy
import json
import os


class NewsSpider(scrapy.Spider):
    """带增量支持的新闻爬虫"""
    name = 'news'
    start_urls = ['https://example.com/news']

    def __init__(self, *args, **kwargs):
        super().__init__(*args, **kwargs)
        # 加载已爬取的 URL 集合
        self.crawled_urls = self._load_crawled_urls()

    def _load_crawled_urls(self):
        """从文件加载已爬取的 URL 列表"""
        filepath = 'crawled_urls.json'
        if os.path.exists(filepath):
            with open(filepath, 'r', encoding='utf-8') as f:
                return set(json.load(f))
        return set()

    def _save_crawled_urls(self):
        """保存已爬取的 URL 列表到文件"""
        filepath = 'crawled_urls.json'
        with open(filepath, 'w', encoding='utf-8') as f:
            json.dump(list(self.crawled_urls), f, ensure_ascii=False)

    def parse(self, response):
        """解析新闻列表页"""
        for article in response.css('article'):
            url = article.css('a::attr(href)').get()

            # 增量判断：跳过已爬取的 URL
            if url in self.crawled_urls:
                self.logger.info(f'跳过已爬取: {url}')
                continue

            # 记录新 URL
            self.crawled_urls.add(url)
            yield scrapy.Request(url, callback=self.parse_article)

        # 爬取完成后保存 URL 列表
        self._save_crawled_urls()

    def parse_article(self, response):
        """解析文章详情页"""
        yield {
            'title': response.css('h1::text').get(),
            'content': response.css('article').get(),
            'url': response.url,
        }
```

## 六、CloseSpider：优雅地停下来

### 6.1 CloseSpider 扩展参数

爬虫不能一直跑下去。`CloseSpider` 扩展让你设置各种停止条件。

```python
# settings.py

# 方式一：爬取指定数量的 Item 后停止
CLOSESPIDER_ITEMCOUNT = 1000      # 爬到 1000 条数据就停

# 方式二：爬取指定页数后停止
CLOSESPIDER_PAGECOUNT = 100       # 爬了 100 个页面就停

# 方式三：运行指定时间后停止（单位：秒）
CLOSESPIDER_TIMEOUT = 3600        # 运行 1 小时就停

# 方式四：遇到指定数量的错误后停止
CLOSESPIDER_ERRORCOUNT = 50       # 出现 50 个错误就停
```

## 七、日志与统计：知道爬虫在干什么

### 7.1 Scrapy 日志系统

```python
# settings.py

# 日志级别：CRITICAL > ERROR > WARNING > INFO > DEBUG
LOG_LEVEL = 'INFO'

# 日志输出到文件（不设置则输出到终端）
LOG_FILE = 'spider.log'

# 日志格式
LOG_FORMAT = '%(asctime)s [%(name)s] %(levelname)s: %(message)s'
LOG_DATEFORMAT = '%Y-%m-%d %H:%M:%S'
```

```python
# 在 Spider 中使用日志

class MySpider(scrapy.Spider):
    name = 'my_spider'

    def parse(self, response):
        self.logger.debug('开始解析页面: %s', response.url)
        self.logger.info('成功获取页面，状态码: %d', response.status)
        self.logger.warning('页面缺少标题: %s', response.url)
        self.logger.error('解析失败: %s', response.url)
```

## 九、小结

本课我们学习了 Scrapy 的限速、重试和增量爬取机制：

```
┌──────────────────────────────────────────────────────────┐
│  本课知识图谱                                              │
│                                                          │
│  限速控制                                                 │
│  ├── DOWNLOAD_DELAY          基础延迟                     │
│  ├── RANDOMIZE_DOWNLOAD_DELAY 随机延迟                    │
│  ├── CONCURRENT_REQUESTS     全局并发                     │
│  ├── CONCURRENT_REQUESTS_PER_DOMAIN  域名并发             │
│  └── AutoThrottle            自适应限速                   │
│                                                          │
│  重试机制                                                 │
│  ├── RetryMiddleware         内置重试                     │
│  ├── RETRY_TIMES             重试次数                     │
│  ├── RETRY_HTTP_CODES        重试状态码                   │
│  └── 自定义重试中间件         智能重试                     │
│                                                          │
│  增量爬取                                                 │
│  ├── URL 去重                最常用                       │
│  ├── 日期去重                适合新闻                     │
│  └── 数据库去重              最可靠                       │
│                                                          │
│  辅助功能                                                 │
│  ├── CloseSpider             停止条件                     │
│  ├── 日志系统                记录运行信息                 │
│  └── 统计收集                量化爬取结果                 │
└──────────────────────────────────────────────────────────┘
```

**核心要点：**

1. **限速是基本礼貌**——不设限速的爬虫是"网络攻击"
2. **AutoThrottle 是最佳实践**——除非你有特殊需求，否则直接启用它
3. **重试要有限度**——别让爬虫陷入无限重试的死循环
4. **增量爬取节省资源**——只爬新数据，不重复劳动
5. **日志和统计是调试利器**——出了问题，日志是你最好的朋友
