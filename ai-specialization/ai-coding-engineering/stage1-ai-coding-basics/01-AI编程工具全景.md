# 01 - AI 编程工具全景

> **前置要求**：基本的编程经验（任意语言）
>
> **预计时长**：1.5 小时

---

## 这节课解决什么问题

你所在的团队决定引入 AI 编程工具，但面对 Copilot、Cursor、ChatGPT、Claude 等十几个工具，意见不一。有人推荐免费的 Codeium，有人坚持用付费的 Copilot，还有人觉得 ChatGPT 网页版就够了。你试了两三个，发现补全质量参差不齐。

到底该怎么选？不同工具的核心差异是什么？

---

## 三类工具的本质区别

AI 编程工具不是铁板一块。按交互模式分，就三类：

**代码补全类**（Copilot、Codeium、Tabnine）

在你写代码时实时给建议，按 Tab 接受。干扰最小，延迟通常低于 200ms。它依赖你已经写下的函数名、类型、注释来猜你要什么——你写得越清楚，它猜得越准。

**对话辅助类**（ChatGPT、Claude）

通过自然语言对话完成编码任务。适合复杂问题的探索、代码解释、架构讨论。但它需要你主动描述需求，描述得模糊，输出就模糊。

**Agent 类**（Cursor Agent、Copilot Workspace）

AI 自主规划步骤，读文件、执行命令、改多个文件。能完成端到端任务，但变更范围大，需要更仔细的审查。

理解这三类的区别，比记住某个工具的功能列表重要得多。功能会迭代，分类逻辑不会变。

## 怎么选：一个决策框架

别记功能列表，用这个决策树：

```
你的主要需求是什么？
│
├── 日常编码补全，融入现有工作流
│   ├── 预算充足 → GitHub Copilot
│   ├── 隐私优先 → Tabnine
│   └── 免费优先 → Codeium
│
├── 复杂问题讨论 + 多文件编辑
│   ├── 愿意换 IDE → Cursor
│   ├── 保持现有 IDE → Copilot Chat / Claude
│   └── 学习新概念 → ChatGPT / Claude
│
└── 企业级部署 + 安全合规
    ├── AWS 技术栈 → Amazon Q Developer
    ├── 私有化部署 → Tabnine Enterprise
    └── 团队管理 → Copilot Business
```

关键判断：不要把所有场景押在单一工具上。补全用 Copilot/Codeium，复杂架构讨论用 Claude，快速原型验证用 ChatGPT——每个工具在不同场景下各有优势。

## 补全质量的底层逻辑

很多人试了一两个工具就下结论"AI 补全不行"。但补全质量很大程度取决于你怎么写代码：

| 你写的 | AI 看到的 | 补全质量 |
|--------|----------|---------|
| `function f(a, b)` | 两个无名参数 | 差 |
| `function sortUsersByAge(users: User[]): User[]` | 明确的输入输出 | 好 |
| 没有注释 | 纯靠猜 | 一般 |
| `// Sort users by age, return new array` | 意图清晰 | 好 |
| 零散的代码片段 | 缺少上下文 | 差 |
| 完整的类型定义 + import | 上下文充足 | 好 |

函数名和类型注解是最好的 Prompt。这不是技巧，是工程习惯。

## 常见误判

**"最贵的工具一定最好"** — 不对。免费的 Codeium 对很多场景足够。工具的价值在于匹配你的场景，不是价格标签。

**"试了一个不好用，说明 AI 编程不行"** — 不同工具在不同技术栈上表现差异很大。至少试 2-3 个，用你最熟悉的技术栈做真实任务来评估。

**"ChatGPT 网页版就够了"** — IDE 内集成的体验（上下文感知、代码引用、一键应用）远好于复制粘贴。如果你在认真写代码，应该用 IDE 插件。

**"AI 工具能替代编程能力"** — AI 是放大器，不是替代品。你越懂编程，用 AI 的效果越好。

## 练习

### 练习一：工具试用对比（30 分钟）

选 3 个不同的 AI 编程工具（至少 1 个补全类、1 个 Chat 类），分别完成：

1. 补全类：新建一个 TypeScript 文件，写一个 `filterActiveUsers` 函数签名，观察补全质量
2. Chat 类：把下面这段正则发给 AI，让它解释：`/^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)[a-zA-Z\d]{8,}$/`
3. 记录每个工具的优缺点

### 练习二：补全触发实验（20 分钟）

在同一个文件中，分别用两种方式写函数，对比 AI 补全质量：

```typescript
// 方式 A：模糊命名
function process(data: any) {
  // 观察 AI 补全
}

// 方式 B：清晰命名 + 类型
function calculateOrderTotal(items: OrderItem[], discount: number): number {
  // 观察 AI 补全
}
```

记录对比结果，写 2-3 句话总结差异原因。

## 参考答案

### 练习一

预期发现：补全类工具（Copilot/Codeium）在写函数签名时补全最准，Chat 类工具（Claude/ChatGPT）在解释复杂逻辑时更深入。关键不是哪个"更好"，而是哪个更适合当前任务。

### 练习二

方式 A 的补全通常是泛化的 `return data` 或 `data.map(...)`，因为 AI 不知道 `data` 是什么。方式 B 的补全会基于 `OrderItem` 类型推断出 `item.price * item.quantity` 这类业务逻辑。差异的根本原因：类型信息和命名语义是 AI 理解意图的关键输入。

### 练习三

没有标准答案。但选择理由应该基于你实际完成的任务，而非广告宣传。如果理由是"朋友推荐"，建议重新评估——用你自己的技术栈做真实任务才是可靠的评估方式。
