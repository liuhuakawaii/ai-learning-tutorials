# 07 - 阶段实战：用 AI 完成完整功能

> **前置要求**：完成 01-06 课的学习
>
> **预计时长**：2.5 小时

---

## 你在做什么

学了工具选择、补全技巧、Chat 对话、上下文管理和代码审查方法，现在要用它们完成一个真实功能：用户认证模块。这是每个后端项目都绕不开的，涉及密码加密、JWT、中间件、数据库操作。

这个实战的目的不是让你背代码，而是体验"人机协作"的完整工作流——AI 负责写，你负责审。

---

## 项目结构

```
src/
├── auth/
│   ├── auth.routes.ts
│   ├── auth.controller.ts
│   ├── auth.service.ts
│   ├── auth.middleware.ts
│   └── auth.schema.ts
├── lib/
│   ├── prisma.ts
│   └── jwt.ts
└── types/
    └── express.d.ts
```

技术栈：Node.js 20 + TypeScript + Express + Prisma + PostgreSQL + Zod + bcrypt + JWT + Vitest

## 实战步骤

### 步骤 1：项目初始化

让 AI 生成 `package.json` 和 `tsconfig.json`。

**Prompt**：
```
帮我初始化一个 Express + TypeScript 项目，包含以下配置：
1. TypeScript 配置（target: ES2022，module: NodeNext）
2. 依赖：express, zod, jsonwebtoken, bcrypt, prisma, vitest
3. 脚本：dev, build, test, start
```

**审查要点**：检查依赖版本是否合理，TypeScript 配置是否符合项目需求。

### 步骤 2：数据库 Schema

```
#file:prisma/schema.prisma

帮我定义 User 模型：
- id: UUID，主键
- email: 唯一，不为空
- name: 不为空
- passwordHash: 不为空
- role: 枚举（USER, ADMIN），默认 USER
- createdAt / updatedAt: 自动时间戳
- @@map("users")
```

**审查要点**：字段命名是否符合项目规范？有没有遗漏的字段？

### 步骤 3：Zod 验证

```
创建 src/auth/auth.schema.ts，定义：
1. RegisterSchema — email 格式 + name 2-50 字符 + password 至少 8 位含大小写数字
2. LoginSchema — email 格式 + password 非空
导出 TypeScript 类型。
```

**审查要点**：密码规则是否足够严格？错误信息是否有帮助？

### 步骤 4：JWT 工具

```
创建 src/lib/jwt.ts：
1. generateToken(payload) — HS256，24h 过期，secret 从环境变量读取
2. verifyToken(token) — 验证并解码，无效时抛 AuthError
```

**审查要点**：secret 是否从环境变量读取？是否有算法指定防止混淆攻击？

### 步骤 5：认证服务层

```
创建 src/auth/auth.service.ts：
1. register(input) — 检查邮箱唯一性，bcrypt 加密（salt rounds: 12），
   创建用户，生成 JWT，返回用户信息（排除 passwordHash）和 token
2. login(input) — 根据邮箱查找，bcrypt 比较，生成 JWT
使用 Prisma，包含完整错误处理。
```

**审查要点**：这是安全审查的重点。逐行检查：
- 邮箱唯一性检查？
- bcrypt salt rounds 是否足够？
- 错误信息是否泄露敏感信息（应该统一"邮箱或密码错误"）？
- 返回时是否排除了 passwordHash？

### 步骤 6：Express 中间件

```
创建 src/auth/auth.middleware.ts：
1. authenticate — 从 Authorization header 提取 Bearer token，
   验证后附加到 req.user，无效返回 401
2. requireRole(...roles) — 检查 req.user.role，不满足返回 403
需要扩展 Express Request 类型。
```

### 步骤 7：路由

```
创建 src/auth/auth.routes.ts：
1. POST /auth/register — Zod 验证 → authService.register → 201
2. POST /auth/login — Zod 验证 → authService.login → 200
3. GET /auth/me — authenticate 中间件 → 返回当前用户
包含完整错误处理。
```

### 步骤 8：测试

```
为 auth.service.ts 编写 Vitest 单元测试：
1. register — 成功注册
2. register — 邮箱已存在时抛出错误
3. login — 成功登录
4. login — 密码错误时抛出错误
5. login — 用户不存在时抛出错误
使用 mock 隔离 Prisma 和 bcrypt。
```

## 关键经验

| 步骤 | AI 擅长的 | 你需要判断的 |
|------|----------|-------------|
| Schema | 字段定义、类型映射 | 业务字段是否遗漏 |
| Zod | 验证规则写法 | 密码强度是否合适 |
| JWT | 加密解密代码 | 安全配置是否正确 |
| Service | 业务逻辑骨架 | 错误信息是否泄露敏感数据 |
| 中间件 | Express 模式代码 | 类型扩展是否正确 |
| 路由 | CRUD 模板代码 | 错误格式是否统一 |
| 测试 | mock 和断言代码 | 测试用例是否覆盖关键路径 |

核心模式：分步骤生成，每步审查通过后再进入下一步。不要让 AI 一次性写完所有文件。

## 练习

### 练习一：完整复现（60 分钟）

按上面 8 个步骤，用 AI 完成整个用户认证模块。每步都按审查清单检查，运行测试确保通过。记录你发现的 AI 代码问题。

### 练习二：扩展功能（40 分钟）

在练习一基础上，用 AI 添加以下功能（每个功能按"生成→审查→测试"流程）：

1. **密码重置**：POST /auth/forgot-password + POST /auth/reset-password
2. **Token 刷新**：POST /auth/refresh
3. **登录日志**：记录 IP、设备、时间

Prompt 示例（密码重置）：
```
基于现有的 src/auth/ 模块，添加密码重置功能：
1. POST /auth/forgot-password — 生成重置 token（1h 有效期），用 Redis 存储
2. POST /auth/reset-password — 验证 token，更新密码
约束：不存在的邮箱也返回成功（防止邮箱枚举攻击）
```

### 练习三：代码质量审计（20 分钟）

对整个认证模块做一次审计，按优先级排序：

1. **安全**：SQL 注入？密码泄露？密钥硬编码？
2. **正确性**：边界情况处理？
3. **性能**：N+1 查询？
4. **风格**：命名、错误处理是否一致？

列出所有发现，逐一修复。

## 参考答案

### 练习一

预期问题分布：

| 步骤 | 常见问题 |
|------|---------|
| 项目初始化 | 依赖版本过旧，检查 Prisma/Express 最新稳定版 |
| Schema | 字段命名不符合项目规范，确认 passwordHash 而非 password |
| Zod | 密码规则不够严格，确认含大小写数字要求 |
| JWT | 通常质量最高，确认 secret 从环境变量读取 |
| Service | **最常出问题**——检查邮箱唯一性、密码加密、错误信息不泄露 |
| 中间件 | Express Request 类型扩展可能有问题 |
| 路由 | 错误处理格式可能不统一 |
| 测试 | vi.mock 路径和方式可能过时 |

### 练习二

关键经验：扩展功能时，"基于现有的 src/auth/ 模块"比"写一个密码重置"效果好得多。安全细节要在 Prompt 中明确，如"不存在的邮箱也返回成功"防止邮箱枚举。

### 练习三

审计结果示例（按严重程度）：

- **严重**：rate limiting 缺失——攻击者可以暴力注册
- **中等**：登录端点未检查用户是否被禁用
- **轻微**：register 和 login 的 catch 块重复，可提取为统一错误中间件
