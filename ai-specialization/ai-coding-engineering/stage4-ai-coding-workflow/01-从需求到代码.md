> **前置要求**：完成 Stage 1-3
>
> **预计时长**：90 分钟

## 这节课解决什么问题

你接到一个新需求：做一个任务管理系统。产品经理给了你一段模糊的描述。传统做法是花两三天写需求文档、画架构图。但 AI 可以在每个环节提供加速——帮你把模糊需求结构化、生成 API 设计、搭建代码骨架。

关键问题：如何在每个环节正确地与 AI 协作？

## 阶段一：需求分析

用户原始需求：
> "我想做一个任务管理系统，能创建任务、分配给人、设置截止日期，还要能看进度。"

**Prompt**：
```
请将以下模糊需求转化为结构化需求文档：
1. 用户故事（As a... I want... So that...）
2. 功能需求列表（带优先级 P0/P1/P2）
3. 非功能需求
4. 验收标准
5. 可能遗漏的需求点
```

AI 输出节选：

| ID | 需求描述 | 优先级 |
|----|----------|--------|
| FR-001 | 创建任务（标题、描述、截止日期） | P0 |
| FR-002 | 分配任务给用户 | P0 |
| FR-003 | 更新任务状态 | P0 |
| FR-004 | 查询任务列表（按状态/负责人筛选） | P0 |
| FR-005 | 项目进度统计 | P1 |

AI 补充了你可能遗漏的：用户认证、软删除、分页排序。

## 阶段二：技术设计

**Prompt**：
```
基于以下需求设计 RESTful API：
- 任务的 CRUD、任务分配、按状态/负责人筛选、项目进度统计
- RESTful 风格，包含 TypeScript 类型定义，包含分页方案
```

数据库 Schema：

```sql
CREATE TABLE tasks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title VARCHAR(200) NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'todo'
        CHECK (status IN ('todo', 'in_progress', 'done')),
    priority VARCHAR(10) NOT NULL DEFAULT 'medium',
    assignee_id UUID REFERENCES users(id) ON DELETE SET NULL,
    due_date TIMESTAMP WITH TIME ZONE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

## 阶段三：编码实现

**Prompt**：
```
实现 taskService.ts：createTask、getTaskById、listTasks、updateTask、deleteTask、getProjectStats。
使用 Drizzle ORM，Zod 验证，完整错误处理。
```

AI 生成核心 Service（节选）：

```typescript
export const createTaskSchema = z.object({
  title: z.string().min(1).max(200),
  assigneeId: z.string().uuid().optional(),
  dueDate: z.string().datetime().optional(),
  priority: z.enum(['low', 'medium', 'high']).default('medium'),
});

export class TaskService {
  async createTask(data: z.infer<typeof createTaskSchema>) {
    const validated = createTaskSchema.parse(data);
    const [task] = await db.insert(tasks).values({
      ...validated,
      status: 'todo',
    }).returning();
    return task;
  }

  async getProjectStats() {
    const stats = await db.select({
      totalTasks: count(),
      completedTasks: count(sql`CASE WHEN ${tasks.status} = 'done' THEN 1 END`),
      overdueTasks: count(sql`CASE WHEN ${tasks.dueDate} < NOW() AND ${tasks.status} != 'done' THEN 1 END`),
    }).from(tasks);
    return { ...stats[0], completionRate: stats[0].completedTasks / stats[0].totalTasks };
  }
}
```

## 关键经验

- **分模块生成，逐步集成**：不要让 AI 一次性生成整个项目
- **审查优先级：安全 > 逻辑 > 风格**
- **保留架构决策记录**：AI 建议的技术方案用 ADR 记录决策理由

## 练习

### 练习一：需求结构化（30 分钟）

取一个你正在做的项目的真实需求，用本课 Prompt 模板结构化为用户故事 + 功能需求 + 验收标准。找出 AI 补充的你遗漏的需求点。

### 练习二：完整 CRUD 实现（45 分钟）

参考 TaskService，让 AI 实现一个 `CommentService`，包含创建评论、获取评论列表、删除评论（只能删自己的）。要求 Zod 验证、错误处理、单元测试。

### 练习三：端到端工作流（60 分钟）

选一个简单功能（如"用户收藏任务"），完整走一遍五个阶段。记录每个阶段的时间，对比传统方式的效率。

---

## 参考答案

### 练习一

AI 通常会补充"N+1 防护""级联删除""收藏数量限制"等容易遗漏的需求。结构化不是一次完成的——先列框架，再让 AI 补充，最后人工审核。

### 练习二

CommentService 遵循与 TaskService 相同的模式。`deleteComment` 需要权限检查（只能删除自己的评论），这是评论功能特有的业务规则。

### 练习三

效率参考：需求分析 12x、API 设计 6x、编码实现 9x、测试编写 12x。AI 提速最明显的是需求分析和测试，因为模式化程度最高。
