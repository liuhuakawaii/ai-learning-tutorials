# Lesson 06: 代码迁移 — AI 辅助的大规模代码重构

> **课程定位**: Stage 4 第 6 课 | **前置**: Lesson 05 | **预计时长**: 75 分钟

## 场景引入

项目已经运行了两年，代码库全是 JavaScript，没有类型检查。每次重构都像在走钢丝——改了一个函数的参数，调用方不会报错，直到上线后用户遇到 `undefined is not a function`。团队决定迁移到 TypeScript，但面对几百个 `.js` 文件，没人敢动手：一次改完怕出大问题，逐个改又太慢。更棘手的是，有些模块之间有复杂的依赖关系，改了底层工具函数，上层的服务和路由都得跟着变。代码迁移本质上是一个"在行驶的汽车上换轮胎"的问题——你需要在保证现有功能不中断的前提下，逐步把旧代码替换成新代码。AI 可以帮你分析迁移范围、自动转换代码、生成对比测试，但如何设计一个安全的渐进式迁移策略，仍然需要人的判断。

## 学习目标

1. 掌握 AI 辅助的 JavaScript 到 TypeScript 迁移
2. 学会用 AI 进行 API 风格迁移（REST 到 GraphQL）
3. 理解 React Class 组件到 Hooks 的迁移策略
4. 掌握代码迁移的安全策略和验证方法
5. 建立可回滚的迁移工作流

```javascript
// src/services/taskService.js
const { db } = require('../db');
const { tasks } = require('../db/schema');
const { eq, and, count } = require('drizzle-orm');

const STATUS_MAP = {
  TODO: 'todo',
  IN_PROGRESS: 'in_progress',
  DONE: 'done',
};

const PRIORITY_MAP = {
  LOW: 'low',
  MEDIUM: 'medium',
  HIGH: 'high',
};

async function createTask(data) {
  const { title, description, assigneeId, dueDate, priority, tags } = data;

  if (!title || title.length > 200) {
    throw new Error('Invalid title');
  }

  const [task] = await db
    .insert(tasks)
    .values({
      title,
      description: description || null,
      assigneeId: assigneeId || null,
      dueDate: dueDate ? new Date(dueDate) : null,
      priority: priority || PRIORITY_MAP.MEDIUM,
      tags: tags || [],
      status: STATUS_MAP.TODO,
    })
    .returning();

  return task;
}

async function listTasks(filters = {}) {
  const { status, assigneeId, page = 1, pageSize = 20 } = filters;
  const conditions = [];

  if (status) conditions.push(eq(tasks.status, status));
  if (assigneeId) conditions.push(eq(tasks.assigneeId, assigneeId));

  const where = conditions.length > 0 ? and(...conditions) : undefined;

  const [{ total }] = await db
    .select({ total: count() })
    .from(tasks)
    .where(where);

  const data = await db
    .select()
    .from(tasks)
    .where(where)
    .limit(pageSize)
    .offset((page - 1) * pageSize);

  return {
    data,
    pagination: { page, pageSize, total, totalPages: Math.ceil(total / pageSize) },
  };
}

module.exports = { createTask, listTasks, STATUS_MAP, PRIORITY_MAP };
```

```typescript
import { db } from '../db';
import { tasks } from '../db/schema';
import { eq, and, count, type SQL } from 'drizzle-orm';
import { z } from 'zod';

// ===== Enums =====
export enum TaskStatus {
  TODO = 'todo',
  IN_PROGRESS = 'in_progress',
  DONE = 'done',
}

export enum TaskPriority {
  LOW = 'low',
  MEDIUM = 'medium',
  HIGH = 'high',
}

// ===== Interfaces =====
export interface CreateTaskData {
  title: string;
  description?: string;
  assigneeId?: string;
  dueDate?: string;
  priority?: TaskPriority;
  tags?: string[];
}

export interface ListTasksFilters {
  status?: TaskStatus;
  assigneeId?: string;
  page?: number;
  pageSize?: number;
}

export interface PaginatedResponse<T> {
  data: T[];
  pagination: {
    page: number;
    pageSize: number;
    total: number;
    totalPages: number;
  };
}

export interface TaskRecord {
  id: string;
  title: string;
  description: string | null;
  status: TaskStatus;
  priority: TaskPriority;
  assigneeId: string | null;
  dueDate: Date | null;
  tags: string[];
  createdAt: Date;
  updatedAt: Date;
}

// ===== Validation Schemas =====
const createTaskSchema = z.object({
  title: z.string().min(1).max(200),
  description: z.string().optional(),
  assigneeId: z.string().uuid().optional(),
  dueDate: z.string().datetime().optional(),
  priority: z.nativeEnum(TaskPriority).default(TaskPriority.MEDIUM),
  tags: z.array(z.string()).default([]),
});

// ===== Service Functions =====
export async function createTask(data: CreateTaskData): Promise<TaskRecord> {
  const validated = createTaskSchema.parse(data);

  const [task] = await db
    .insert(tasks)
    .values({
      title: validated.title,
      description: validated.description ?? null,
      assigneeId: validated.assigneeId ?? null,
      dueDate: validated.dueDate ? new Date(validated.dueDate) : null,
      priority: validated.priority,
      tags: validated.tags,
      status: TaskStatus.TODO,
    })
    .returning();

  return task as TaskRecord;
}

export async function listTasks(
  filters: ListTasksFilters = {}
): Promise<PaginatedResponse<TaskRecord>> {
  const { status, assigneeId, page = 1, pageSize = 20 } = filters;

  const conditions: SQL[] = [];
  if (status) conditions.push(eq(tasks.status, status));
  if (assigneeId) conditions.push(eq(tasks.assigneeId, assigneeId));

  const where = conditions.length > 0 ? and(...conditions) : undefined;

  const [{ total }] = await db
    .select({ total: count() })
    .from(tasks)
    .where(where);

  const data = await db
    .select()
    .from(tasks)
    .where(where)
    .limit(pageSize)
    .offset((page - 1) * pageSize);

  return {
    data: data as TaskRecord[],
    pagination: {
      page,
      pageSize,
      total,
      totalPages: Math.ceil(total / pageSize),
    },
  };
}
```

```typescript
const SRC_DIR = './src';

function getJsFiles(dir: string): string[] {
  const files: string[] = [];
  for (const entry of readdirSync(dir, { withFileTypes: true })) {
    const fullPath = join(dir, entry.name);
    if (entry.isDirectory()) {
      files.push(...getJsFiles(fullPath));
    } else if (entry.name.endsWith('.js') && !entry.name.endsWith('.test.js')) {
```

### 4.3 迁移示例

**Class 组件**:
```jsx
class TaskList extends React.Component {
  constructor(props) {
    super(props);
    this.state = {
      tasks: [],
      loading: false,
      error: null,
      filters: { status: 'all', search: '' },
    };
  }

  componentDidMount() {
    this.fetchTasks();
  }

  componentDidUpdate(prevProps, prevState) {
    if (prevState.filters !== this.state.filters) {
      this.fetchTasks();
    }
  }

  fetchTasks = async () => {
    this.setState({ loading: true, error: null });
    try {
      const response = await fetch(`/api/tasks?${new URLSearchParams(this.state.filters)}`);
      if (!response.ok) throw new Error('Failed to fetch');
      const data = await response.json();
      this.setState({ tasks: data.data, loading: false });
    } catch (error) {
      this.setState({ error: error.message, loading: false });
    }
  };

  handleFilterChange = (key, value) => {
    this.setState(prev => ({
      filters: { ...prev.filters, [key]: value },
    }));
  };

  render() {
    const { tasks, loading, error, filters } = this.state;

    if (loading) return <Spinner />;
    if (error) return <ErrorMessage message={error} />;

    return (
      <div>
        <Filters value={filters} onChange={this.handleFilterChange} />
        <TaskItems tasks={tasks} />
      </div>
    );
  }
}
```

**Hooks 组件（AI 转换后）**:
```tsx
import { useState, useEffect, useCallback } from 'react';

interface TaskFilters {
  status: string;
  search: string;
}

interface Task {
  id: string;
  title: string;
  status: string;
  // ...
}

// 提取自定义 Hook
function useTasks(filters: TaskFilters) {
  const [tasks, setTasks] = useState<Task[]>([]);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState<string | null>(null);

  const fetchTasks = useCallback(async () => {
    setLoading(true);
    setError(null);
    try {
      const params = new URLSearchParams(filters);
      const response = await fetch(`/api/tasks?${params}`);
      if (!response.ok) throw new Error('Failed to fetch');
      const data = await response.json();
      setTasks(data.data);
    } catch (err) {
      setError(err instanceof Error ? err.message : 'Unknown error');
    } finally {
      setLoading(false);
    }
  }, [filters]);

  useEffect(() => {
    fetchTasks();
  }, [fetchTasks]);

  return { tasks, loading, error, refetch: fetchTasks };
}

// 主组件
function TaskList() {
  const [filters, setFilters] = useState<TaskFilters>({
    status: 'all',
    search: '',
  });

  const { tasks, loading, error } = useTasks(filters);

  const handleFilterChange = useCallback((key: string, value: string) => {
    setFilters(prev => ({ ...prev, [key]: value }));
  }, []);

  if (loading) return <Spinner />;
  if (error) return <ErrorMessage message={error} />;

  return (
    <div>
      <Filters value={filters} onChange={handleFilterChange} />
      <TaskItems tasks={tasks} />
    </div>
  );
}
```

```
□ 内存使用无异常增长
□ 数据库查询性能不变

代码质量:
□ TypeScript 无类型错误
□ ESLint 无警告
□ 测试覆盖率不低于迁移前
□ 代码可读性提升

部署验证:
□ CI/CD 流程正常
□ Docker 镜像构建正常
□ 生产环境部署成功
□ 监控指标正常
```

---

## 7. 常见误区

### ❌ 错误 1：一次性迁移所有代码
大规模迁移应渐进式进行。**分模块迁移，每步验证**。

### ❌ 错误 2：迁移前没有补充测试
没有测试就无法验证迁移是否正确。**先补测试再迁移**。

### ❌ 错误 3：完全信任 AI 的转换结果
AI 可能误解业务逻辑。**逐行审查转换后的代码**。

### ❌ 错误 4：忽略性能影响
新代码可能引入性能问题。**迁移前后做性能对比**。

### ❌ 错误 5：没有回滚计划
迁移失败时无法快速恢复。**始终保持可回滚状态**。

---

## 8. 工程建议

1. **迁移前先补齐测试**：没有测试覆盖的代码，迁移后你无法验证功能是否正确。在开始迁移之前，用 AI 为现有代码补充关键路径的测试，建立行为基线。

2. **从叶子模块开始，逐层向上**：先迁移没有被其他模块依赖的工具函数和类型定义，再迁移服务层，最后迁移路由层和入口文件。每迁移一层就运行测试，确保增量正确。

3. **始终保持可回滚状态**：迁移过程中，新旧代码应该能并行运行。使用特性开关或路由切换控制流量分配，发现问题时能立即切回旧代码，而不是被迫在一个已经改了一半的代码库里紧急修复。

4. **迁移后做性能基准对比**：TypeScript 类型注解不影响运行时性能，但 AI 转换代码时可能引入额外的类型断言或不必要的抽象层。迁移前后分别运行性能基准测试，确认没有退化。

## 9. 总结

本课学习了 AI 辅助的代码迁移策略：

1. **JS → TS** — 渐进式类型迁移，从叶子模块开始
2. **REST → GraphQL** — 并行运行，逐步迁移
3. **Class → Hooks** — 功能等价转换，提取自定义 Hooks
4. **安全策略** — 测试先行，渐进迁移，随时可回滚
5. **验证方法** — 功能、性能、代码质量三重验证

**核心原则**: 迁移是手段不是目的，确保每次迁移都带来实际价值。

### 练习 1：JS → TS 迁移

```javascript
const EMAIL_REGEX = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
```

AI 转换后的 TypeScript 代码：

```typescript
// src/utils/userValidator.ts
const EMAIL_REGEX = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
const PHONE_REGEX = /^1[3-9]\d{9}$/;

export enum UserStatus {
  ACTIVE = 'active',
  INACTIVE = 'inactive',
  BANNED = 'banned',
}

export interface ValidationResult {
  valid: boolean;
  error: string | null;
}

export interface UserInput {
  name: string;
  email: string;
  phone?: string;
  age?: number;
  status?: UserStatus;
}

export function validateEmail(email: unknown): ValidationResult {
  if (!email || typeof email !== 'string') {
    return { valid: false, error: '邮箱不能为空' };
  }
  if (!EMAIL_REGEX.test(email)) {
    return { valid: false, error: '邮箱格式不正确' };
  }
  return { valid: true, error: null };
}

export function validatePhone(phone: unknown): ValidationResult {
  if (!phone || typeof phone !== 'string') {
    return { valid: false, error: '手机号不能为空' };
  }
  if (!PHONE_REGEX.test(phone)) {
    return { valid: false, error: '手机号格式不正确' };
  }
  return { valid: true, error: null };
}

export function validateUser(user: UserInput): { valid: boolean; errors: string[] } {
  const errors: string[] = [];

  if (!user.name || user.name.length < 2) {
    errors.push('用户名至少 2 个字符');
  }

  const emailResult = validateEmail(user.email);
  if (!emailResult.valid) {
    errors.push(emailResult.error!);
  }

  if (user.phone) {
    const phoneResult = validatePhone(user.phone);
    if (!phoneResult.valid) {
      errors.push(phoneResult.error!);
    }
  }

  if (user.age !== undefined && (user.age < 0 || user.age > 150)) {
    errors.push('年龄必须在 0-150 之间');
  }

  return {
    valid: errors.length === 0,
    errors,
  };
}
```

**要点**：
- 将字符串常量 `USER_STATUS` 改为 TypeScript `enum`，提供类型安全和 IDE 自动补全
- 为函数参数和返回值添加完整类型定义，`unknown` 比 `any` 更安全
- 定义 `interface` 描述复杂对象结构，明确哪些字段必填、哪些可选
- 使用 `export` 替代 `module.exports`，与 ESModule 规范对齐

### 练习 2：Class → Hooks 迁移

**思路**：将 Class 组件的状态管理、生命周期方法逐一映射到 Hooks 等价物。重点是提取自定义 Hook 复用逻辑，并用 useCallback/useMemo 优化不必要的重渲染。

**答案**：

原始 Class 组件：

```jsx
class UserDashboard extends React.Component {
  constructor(props) {
    super(props);
    this.state = {
      user: null,
      notifications: [],
      loading: true,
      error: null,
    };
  }

  componentDidMount() {
    this.loadUser();
    this.loadNotifications();
    this.interval = setInterval(() => this.loadNotifications(), 30000);
  }

  componentWillUnmount() {
    clearInterval(this.interval);
  }

  componentDidUpdate(prevProps) {
    if (prevProps.userId !== this.props.userId) {
      this.loadUser();
      this.loadNotifications();
    }
  }

  loadUser = async () => {
    try {
      const res = await fetch(`/api/users/${this.props.userId}`);
      const data = await res.json();
      this.setState({ user: data, loading: false });
    } catch (err) {
      this.setState({ error: err.message, loading: false });
    }
  };

  loadNotifications = async () => {
    try {
      const res = await fetch(`/api/users/${this.props.userId}/notifications`);
      const data = await res.json();
      this.setState({ notifications: data });
    } catch (err) {
      console.error('Failed to load notifications:', err);
    }
  };

  markAsRead = async (notificationId) => {
    await fetch(`/api/notifications/${notificationId}/read`, { method: 'POST' });
    this.setState(prev => ({
      notifications: prev.notifications.map(n =>
        n.id === notificationId ? { ...n, read: true } : n
      ),
    }));
  };

  render() {
    const { user, notifications, loading, error } = this.state;

    if (loading) return <Spinner />;
    if (error) return <ErrorMessage message={error} />;

    const unreadCount = notifications.filter(n => !n.read).length;

    return (
      <div>
        <h1>Welcome, {user.name}</h1>
        <Badge count={unreadCount} />
        <NotificationList
          notifications={notifications}
          onMarkAsRead={this.markAsRead}
        />
      </div>
    );
  }
}
```

转换后的 Hooks 组件：

```tsx
import { useState, useEffect, useCallback, useRef } from 'react';

interface User {
  id: string;
  name: string;
  email: string;
}

interface Notification {
  id: string;
  message: string;
  read: boolean;
  createdAt: string;
}

function useUser(userId: string) {
  const [user, setUser] = useState<User | null>(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  const loadUser = useCallback(async () => {
    setLoading(true);
    setError(null);
    try {
      const res = await fetch(`/api/users/${userId}`);
      if (!res.ok) throw new Error('Failed to load user');
      const data = await res.json();
      setUser(data);
    } catch (err) {
      setError(err instanceof Error ? err.message : 'Unknown error');
    } finally {
      setLoading(false);
    }
  }, [userId]);

  useEffect(() => { loadUser(); }, [loadUser]);

  return { user, loading, error, refetch: loadUser };
}

function useNotifications(userId: string) {
  const [notifications, setNotifications] = useState<Notification[]>([]);

  const loadNotifications = useCallback(async () => {
    try {
      const res = await fetch(`/api/users/${userId}/notifications`);
      if (!res.ok) throw new Error('Failed to load notifications');
      const data = await res.json();
      setNotifications(data);
    } catch (err) {
      console.error('Failed to load notifications:', err);
    }
  }, [userId]);

  useEffect(() => {
    loadNotifications();
    const interval = setInterval(loadNotifications, 30000);
    return () => clearInterval(interval);
  }, [loadNotifications]);

  const markAsRead = useCallback(async (notificationId: string) => {
    await fetch(`/api/notifications/${notificationId}/read`, { method: 'POST' });
    setNotifications(prev =>
      prev.map(n => n.id === notificationId ? { ...n, read: true } : n)
    );
  }, []);

  return { notifications, markAsRead, refetch: loadNotifications };
}

function UserDashboard({ userId }: { userId: string }) {
  const { user, loading, error } = useUser(userId);
  const { notifications, markAsRead } = useNotifications(userId);

  if (loading) return <Spinner />;
  if (error) return <ErrorMessage message={error} />;

  const unreadCount = notifications.filter(n => !n.read).length;

  return (
    <div>
      <h1>Welcome, {user!.name}</h1>
      <Badge count={unreadCount} />
      <NotificationList
        notifications={notifications}
        onMarkAsRead={markAsRead}
      />
    </div>
  );
}
```

**要点**：
- `componentDidMount` + `componentWillUnmount` 组合映射为 `useEffect` 返回清理函数，定时器在卸载时自动清除
- 提取 `useUser` 和 `useNotifications` 两个自定义 Hook，使组件代码从 ~80 行降到 ~20 行
- `useCallback` 包裹异步函数，确保 `useEffect` 依赖稳定，避免无限循环
- `componentDidUpdate` 对 props 变化的监听通过 `useEffect` 的依赖数组 `[userId]` 自动实现

### 练习 3：迁移计划制定

**思路**：让 AI 生成一个 REST 到 GraphQL 的迁移计划，然后从可执行性、步骤合理性、风险覆盖三个维度评估。好的计划应该采用并行运行策略，分阶段迁移，而不是一次性切换。

**答案**：

AI 生成的迁移计划（评估版）：

```markdown
# Express REST API → GraphQL 迁移计划

## Phase 1: 基础设施搭建（第 1-2 周）
1. 安装 Apollo Server 和 graphql 依赖
2. 搭建 GraphQL 服务，与现有 Express 并行运行
3. 定义基础 Schema（类型、Query、Mutation）
4. 配置 GraphQL Playground 用于开发调试

## Phase 2: 核心类型迁移（第 3-4 周）
1. 将 REST 的数据模型转为 GraphQL Type
2. 实现 Resolver，复用现有 Service 层
3. 通过 /graphql 端点提供新 API
4. 编写 Schema 对比测试

## Phase 3: 客户端迁移（第 5-6 周）
1. 新功能统一使用 GraphQL
2. 逐步迁移现有 REST 端点的调用方
3. REST 端点标记 Deprecation Header
4. 监控 REST 端点调用量下降趋势

## Phase 4: 清理收尾（第 7-8 周）
1. 确认 REST 端点调用量为零
2. 移除 REST 路由代码
3. 更新 API 文档
4. 性能基准对比
```

**评估结果**：

| 维度 | 评分 | 分析 |

| 可执行性 | ⚠️ 7/10 | 缺少具体的技术细节，如 Schema 设计规范、N+1 问题的 DataLoader 方案 |

| 风险覆盖 | ⚠️ 6/10 | 未覆盖：缓存策略变化、文件上传处理、WebSocket 迁移、认证中间件适配 |

- 添加回滚方案：如果 GraphQL 出现严重问题，如何快速切回 REST
