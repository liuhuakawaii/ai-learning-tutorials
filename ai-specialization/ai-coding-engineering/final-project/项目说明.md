# 最终项目：AI Code Assistant Kit

> 构建一个实用的 AI 编程助手工具集 CLI，综合运用全课程所学

## 场景引入

你已经学完了 AI 编程工程的全部课程——从 Prompt 工程到代码审查，从安全合规到效果度量。现在是时候把这些知识串联起来了。想象你加入了一家新公司，团队需要一个内部工具来统一管理 Prompt 模板、自动审查 AI 生成的代码、并生成质量报告。这个工具就是你的毕业作品：一个真正可用的 AI 编程助手 CLI，证明你不仅理解了理论，还能把它变成工程实践。

## 项目概述

你将构建一个名为 `ai-code-assistant-kit` 的 CLI 工具，它是一个可扩展的 AI 编程助手工具集，集成代码审查、测试生成、Prompt 模板管理等核心功能。

## 常见误区

### ❌ 误区 1：只实现功能不管代码质量

```
问题：为了赶进度，跳过 TypeScript strict mode、不写测试、不做 ESLint 检查
结果：虽然功能能跑，但代码质量分拿不到，架构设计分也会受影响

解决：从项目第一天就开启 strict mode 和 ESLint，养成习惯
```

### ❌ 误区 2：Prompt 模板只做简单字符串替换

```
问题：Prompt 模板只是一个字符串，用 ${variable} 替换就完事
结果：没有元信息管理、没有版本控制、没有效果评估，和直接写 Prompt 没区别

解决：实现完整的模板引擎，包含元信息、变量校验、使用示例
```

### ❌ 误区 3：代码审查只做格式检查

```
问题：代码审查只检查缩进、命名等格式问题
结果：AI 生成的安全漏洞（SQL 注入、硬编码密钥）完全检测不到

解决：审查引擎要覆盖安全、性能、逻辑多个维度
```

### ❌ 误区 4：项目结构混乱，所有代码塞在一个文件

```
问题：CLI 入口、Prompt 引擎、审查逻辑全写在 index.ts 里
结果：代码超过 500 行后难以维护，无法独立测试各模块

解决：按功能拆分模块，每个模块职责单一，有独立的测试文件
```

## 工程建议

1. **先跑通核心流程再扩展功能**：先把 CLI 入口 + Prompt 模板管理 + 基础代码审查串联起来，确保端到端可用，再逐步添加测试生成、安全扫描等扩展功能。
2. **每个模块都要有独立的单元测试**：Prompt 引擎的变量替换、审查引擎的规则匹配、测试生成的模板渲染，每个核心模块都要有对应的测试文件，这既是质量保障也是评估得分的关键。
3. **用 TypeScript 接口定义模块契约**：在 `types.ts` 中定义好 `PromptTemplate`、`ReviewRule`、`TestCase` 等核心接口，让各模块通过接口协作，这样后续扩展插件系统时不需要重构核心代码。
4. **生成的报告要有实际价值**：不要为了交作业而生成报告，报告应该包含具体的审查发现、可操作的改进建议、以及量化的质量评分，让使用者真正觉得有用。
