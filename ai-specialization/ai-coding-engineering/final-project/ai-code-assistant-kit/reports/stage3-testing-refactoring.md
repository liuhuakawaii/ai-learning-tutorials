## 常见误区

1. **认为 AI 生成的测试等于充分测试**：AI 倾向于生成 happy path 的测试，容易忽略并发竞态、网络超时、资源耗尽等真实场景中的边界条件
2. **盲目接受 AI 的重构建议**：AI 可能将可读性良好的命令式代码重构成晦涩的函数式风格，或者引入不必要的抽象层
3. **用 AI 生成测试后不验证测试有效性**：不通过 mutation testing 验证测试是否真的能捕获 bug，导致测试套件存在虚假的安全感
4. **忽略重构后的回归风险**：AI 重构代码后不运行完整的测试套件，可能引入微妙的行为变化

## 工程建议

1. **AI 生成测试 + Mutation Testing 验证**：先用 AI 生成测试用例，再用 Stryker 等工具做变异测试，确保测试确实能捕获 bug
2. **重构前先补充测试覆盖**：在 AI 重构代码之前，先确保该代码有足够的测试覆盖，重构后用测试作为安全网
3. **小步重构，逐次验证**：让 AI 每次只重构一个函数或模块，立即运行测试验证，避免大规模重构导致难以定位的问题
4. **保留重构前后的 diff 审查**：AI 重构的代码必须经过人工 diff 审查，重点关注条件逻辑、边界处理和异常路径是否被改变
