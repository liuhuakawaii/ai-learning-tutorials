## 常见误区

1. **盲目信任 AI 生成的代码**：AI 生成的代码可能包含逻辑错误或安全漏洞，必须经过人工审查后才能使用
2. **认为 AI 工具适用于所有场景**：对于高度业务定制化的逻辑，AI 的补全质量会显著下降，不能替代领域知识
3. **忽略上下文窗口的限制**：在大型项目中，AI 工具无法看到完整的代码库，导致生成的代码与项目现有风格不一致
4. **只看功能实现不看代码质量**：AI 生成的代码可能功能正确但缺乏错误处理、类型安全和可维护性

## 工程建议

1. **建立 AI 工具评估矩阵**：从代码质量、响应速度、语言支持、IDE 集成度等维度量化对比，选择最适合团队技术栈的工具
2. **制定 AI 辅助编码规范**：明确哪些场景可以使用 AI 生成（如样板代码、测试用例），哪些场景需要人工主导（如安全模块、核心业务逻辑）
3. **将 AI 生成代码纳入 Code Review 流程**：AI 生成的代码应与人工编写的代码接受同等严格的审查标准
4. **持续跟踪工具更新**：AI 编程工具迭代速度快，定期评估新版本的功能改进，及时调整团队工具链
