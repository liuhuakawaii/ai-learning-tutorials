## 你在做什么

团队全面拥抱 AI 辅助开发，但一个月后代码库变成了"风格博物馆"——有人用 callback，有人用 async/await，错误处理五花八门。你需要一份统一的 AI 编程规范。

## 实战：逐章编写

### 技术栈声明

```markdown
| 类别 | 技术 | 版本 |
|------|------|------|
| 语言 | TypeScript | 5.4+ |
| 框架 | Express | 4.18+ |
| ORM | Prisma | 5.x |
| 校验 | Zod | 3.x |
| 测试 | Vitest | 1.x |

**AI 生成代码时必须遵循以上技术栈，不得引入其他框架。**
```

### Prompt 模板

```markdown
# 角色
你是一位资深 TypeScript 全栈开发工程师。

# 项目上下文
- 技术栈：TypeScript + Express + Prisma + PostgreSQL
- 错误处理：自定义 AppError 类 + 统一错误中间件
- 响应格式：{ code: number, data: T, message: string }

# 任务
{具体任务描述}

# 约束
- 使用 TypeScript 严格模式
- 不使用 any 类型
- 错误必须用 AppError 抛出
```

### 编码规范

```markdown
## AI 代码标注
```typescript
/**
 * @ai-assisted GitHub Copilot
 * @ai-reviewed-by @zhangsan
 * @ai-reviewed-at 2026-06-21
 * @ai-modifications 优化了错误处理逻辑
 */
```

## Git 提交信息
```
feat(auth): 添加 OAuth2 认证支持
AI-Assisted: yes
AI-Tool: GitHub Copilot v2
```
```

### 审查流程

```
PR 提交 → CI 自动检查 → 人工 Review → 合并
```

审查清单：
- [ ] 无硬编码密钥/密码
- [ ] 输入验证完整
- [ ] 错误处理正确
- [ ] 无 AI 幻觉（虚构 API）

### 安全规范

```markdown
## MUST NOT
1. 硬编码任何密钥、密码、Token
2. 将 .env 文件提交到仓库
3. 使用字符串拼接构建 SQL 查询
4. AI 生成代码不审查直接合并

## MUST
1. CI 配置 Gitleaks 密钥扫描
2. .copilotignore 排除敏感文件
```

## 上下文分层策略

```
L1: 系统上下文（必需）→ 写入 .cursorrules / CLAUDE.md
L2: 模块上下文（推荐）→ 每次对话开头提供
L3: 任务上下文（按需）→ 使用 #file 引用
```

`.cursorrules` 示例：

```markdown
## 项目信息
TypeScript + Express + Prisma 后端 API。

## 代码规范
- async/await，禁止回调
- 函数命名：camelCase
- 类/接口：PascalCase

## 错误处理
- 自定义 AppError 类
- Controller 层不 try-catch（统一错误中间件）

## 禁止事项
- 不使用 any 类型
- 不使用 console.log（使用 logger）
- 不在 Controller 中直接操作数据库
```

## 练习

### 练习一：技术栈声明（15 分钟）

为电商平台后端（TypeScript + Fastify + Drizzle ORM + PostgreSQL）编写技术栈声明，包括核心技术版本、开发工具、AI 使用限制。

### 练习二：Prompt 模板设计（30 分钟）

为 4 个场景设计可复用的 Prompt 模板：
1. 创建新的 API 端点
2. 编写数据库 Schema
3. 生成单元测试
4. 代码重构

### 练习三：完整规范文档（60 分钟）

编写完整 AI 编程规范，包含：技术栈、Prompt 模板库（至少 5 个）、上下文管理、代码质量标准、安全规范、审查流程。

---

## 参考答案

### 练习一

AI 使用限制要具体到"不得做什么"：不得引入 Express、Prisma、TypeORM；不得硬编码连接字符串；API 必须使用 Fastify Route Handler 模式。

### 练习二

每个模板包含：角色定义、上下文、任务、约束、输出格式。关键点是约束要具体到技术栈，避免 AI 自由发挥。

### 练习三

安全红线用 MUST NOT 明确禁止，每条可在 CI 中自动化检查。Review 流程分层：普通代码 1 人 Review，安全代码 2 人 Review。
