# 阶段实战——编写团队 AI 编程规范

> 课型：项目推进课
> 目标：综合前 5 课所学，输出一份完整、可落地的团队 AI 编程规范文档

## 当前卡点

你是团队的 Tech Lead，老板要求下周前拿出一份"团队 AI 编程规范"。你脑子里有很多零散的想法——工具要统一、代码要标注、安全要检查——但写不成一份结构清晰、可执行落地的文档。写得太简单怕流于形式，写得太复杂怕没人读。

## 编写原则

| 原则 | 说明 | 示例 |
|------|------|------|
| 具体 | 避免模糊表述 | "使用 bcrypt" 而非 "安全地存储密码" |
| 可执行 | 每条规范可操作 | "ESLint 规则配置如下" |
| 可验证 | 能自动化检查 | "CI 中配置 gitleaks 扫描" |
| 适度 | 不过度约束 | "建议" 和 "必须" 区分使用 |

规范等级：
- **MUST（必须）**：强制执行，违反将阻断流程
- **SHOULD（应该）**：强烈建议，违反需要说明理由
- **MAY（可以）**：可选遵循，提供参考

## 容易犯的错

**规范过于复杂**。100+ 页的文档没人读。核心规范控制在 10 页以内，详细内容放附录，用检查清单替代长篇文字。

**规范不更新**。写完就再也不更新。指定维护者，季度审查机制，变更必须走 PR。

**没有配套工具**。规范要求很多但没有工具支持。CI 自动化检查、IDE 配置团队共享设置、提供 Prompt 模板和 Review 检查清单，让规范"长在工具里"而不是"躺在文档里"。

**一刀切执行**。所有项目、所有人都用同一套标准。区分项目类型（生产/实验）、代码类型（核心/辅助），灵活调整规范等级。

## 参考答案

### 练习一

README.md 用"5 分钟速览"帮助新人快速了解核心要求，详细内容链接到各章节。安全红线 5 条 MUST NOT 全部可以在 CI 中自动化检查。违规处理有明确的升级机制，避免规范流于形式。

### 练习二

评审应从完整性、可执行性两个维度系统检查。"可执行性"是核心关注点：写得再好的规范，如果没有工具支撑，最终会流于形式。评审应提出具体的改进建议，而非泛泛的"建议完善"。

### 练习三

```python
import re
from pathlib import Path

def audit_project(project_dir: str) -> dict:
    violations = []
    project = Path(project_dir)

    # 硬编码密钥检测
    patterns = {
        "openai_key": r'sk-[a-zA-Z0-9]{20,}',
        "aws_key": r'AKIA[0-9A-Z]{16}',
        "generic_secret": r'(api_key|password|secret|token)\s*=\s*["\'][^"\']{8,}["\']',
    }

    for file in project.rglob("*.{py,js,ts,env,yaml,yml}"):
        if any(skip in str(file) for skip in [".git", "node_modules", "__pycache__"]):
            continue
        try:
            content = file.read_text(encoding="utf-8")
            for name, pattern in patterns.items():
                matches = re.findall(pattern, content)
                if matches:
                    violations.append({
                        "file": str(file.relative_to(project)),
                        "type": "hardcoded_secret",
                        "secret_type": name,
                        "count": len(matches),
                    })
        except (UnicodeDecodeError, PermissionError):
            continue

    # .env 检查
    gitignore = project / ".gitignore"
    if gitignore.exists():
        if ".env" not in gitignore.read_text():
            violations.append({"file": ".gitignore", "type": "missing_env_ignore"})
    else:
        violations.append({"file": ".gitignore", "type": "missing_gitignore"})

    # .copilotignore 检查
    if not (project / ".copilotignore").exists():
        violations.append({"file": ".copilotignore", "type": "missing_copilotignore"})

    score = max(0, 100 - len(violations) * 10)
    return {"violations": violations, "score": score, "total_issues": len(violations)}
```
