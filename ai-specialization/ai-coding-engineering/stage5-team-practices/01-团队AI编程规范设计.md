# 团队 AI 编程规范设计——从混乱到有序

> 课型：概念建模课
> 目标：理解团队 AI 编程规范的核心要素，能设计可落地的规范体系

## 从一个真实痛点开始

团队接入 AI 编程工具三个月后，问题开始浮现：
- 张三用 Cursor 写的代码风格和李四用 Copilot 生成的完全不同，review 时互相看不懂
- 王五把公司 API 密钥直接贴进了 Prompt，代码被提交到了公开仓库
- 每个人都摸索出了一套"好用的 Prompt"，但随着人员流动全部丢失

没有统一的 AI 编程规范，AI 工具不仅没有提效，反而在制造新的混乱。

## 规范化的收益

| 维度 | 无规范 | 有规范 |
|------|--------|--------|
| 代码质量 | 风格混乱，review 困难 | 统一标准，自动化检查 |
| 安全性 | 密钥泄露、漏洞引入 | 自动检测，合规保障 |
| 效率 | 重复造轮子 | Prompt 库复用 |
| 知识 | 散落在个人电脑 | 结构化团队资产 |

## 工具选型框架

选工具不是选"最好的"，而是选"最适合你团队的"。三个决策维度：

```
安全合规（硬约束）→ 预算与团队规模 → 技术栈与已有基础设施
```

| 团队类型 | 推荐工具 | 理由 |
|---------|---------|------|
| 5 人创业团队，预算有限 | Cursor / Continue.dev | 体验好、上手快、可免费 |
| 50 人金融公司，安全要求高 | 企业私有部署 + Continue.dev | 代码不离开企业网络 |
| 20 人互联网公司，已用 GitLab | GitLab Duo + Cursor | 原生集成，混合使用 |

安全合规是硬约束——不满足安全要求的工具直接排除，不看性价比。

## Prompt 库设计

Prompt 库不是"把 Prompt 存在聊天记录里"。它是团队资产，需要结构化管理：

```
prompts/
├── coding/
│   ├── function-generation.md
│   └── refactoring.md
├── review/
│   ├── code-review.md
│   └── security-check.md
├── testing/
│   └── unit-test.md
└── templates/
    └── prompt-template.md
```

Prompt 模板规范：

```markdown
# Prompt: {功能名称}

## 元信息
- **ID**: PROMPT-CODE-001
- **版本**: 1.2.0
- **作者**: @zhangsan
- **适用模型**: GPT-4o / Claude 3.5 Sonnet
- **最后更新**: 2026-06-15

## Prompt 内容
{prompt}

## 使用示例
**输入**: {example input}
**期望输出**: {example output}

## 效果评估
- 采纳率: 75%
- 平均质量: 4/5
```

版本管理：用 Git 管理 Prompt，每次修改走 PR review。淘汰采纳率 < 30% 的 Prompt。

## 安全红线

安全红线必须自动化——靠人工记住"不能把密钥提交到仓库"是不可靠的。

### MUST NOT - 绝对禁止

1. 硬编码任何密钥、密码、Token
2. 将 .env、secrets/ 文件提交到仓库
3. 使用公共 API 发送公司代码
4. AI 生成代码不审查直接合并到 main
5. 在 Prompt 中包含客户数据或内部 API 密钥

### MUST - 必须执行

1. CI 配置 Gitleaks 密钥扫描
2. .copilotignore 排除敏感文件
3. 许可证合规检查

```yaml
# CI 中必须配置的检查
- name: Secret Detection
  run: gitleaks detect

- name: License Check
  run: npx license-checker --failOn "GPL-3.0;AGPL-3.0"

- name: Dependency Audit
  run: npm audit --audit-level=high
```

**团队 1**：Cursor（$20/月/人）或 Continue.dev（免费）。小团队不需要企业级管理功能，Cursor 内置 AI 对话 + 代码编辑一体化体验。

### 练习二

关键点：元信息中的 ID、版本、作者便于检索和管理。变量用 `{{variable}}` 占位符标记。约束条件明确指定 OpenAPI 版本号。效果评估指标量化。

### 练习三

```python
import re
from pathlib import Path

def check_security_violations(project_dir: str) -> list[dict]:
    violations = []
    project = Path(project_dir)

    # 检查硬编码密钥
    key_patterns = [
        r'sk-[a-zA-Z0-9]{20,}',
        r'api_key\s*=\s*["\'][^"\']+["\']',
        r'password\s*=\s*["\'][^"\']+["\']',
    ]
    for file in project.rglob("*.{py,js,ts,json,yaml,yml}"):
        if ".git" in str(file) or "node_modules" in str(file):
            continue
        try:
            content = file.read_text(encoding="utf-8")
            for pattern in key_patterns:
                if re.search(pattern, content):
                    violations.append({"file": str(file), "type": "hardcoded_secret", "pattern": pattern})
        except (UnicodeDecodeError, PermissionError):
            continue

    # 检查 .env 是否在 .gitignore
    gitignore = project / ".gitignore"
    if gitignore.exists():
        content = gitignore.read_text()
        if ".env" not in content:
            violations.append({"file": ".gitignore", "type": "missing_env_ignore"})
    else:
        violations.append({"file": ".gitignore", "type": "missing_gitignore"})

    # 检查 .copilotignore
    if not (project / ".copilotignore").exists():
        violations.append({"file": ".copilotignore", "type": "missing_copilotignore"})

    return violations
```
