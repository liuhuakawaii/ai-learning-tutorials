# 01 - AI 生成单元测试

> **前置要求**：熟悉 TypeScript / Python 基础语法
>
> **预计时长**：60 分钟

---

## 从一个线上事故说起

你接手了一个没有测试的 Node.js 项目。某天重构了一个工具函数，部署后线上订单金额计算全部出错——回归验证全靠手动点击。老板问："能不能让 AI 帮我们把测试补上？"

你试了一下，AI 一口气生成了 50 个测试用例，但一半是"假通过"——断言的值本身就是错的。

这节课的核心问题：如何用 AI 高效生成**真正有用**的单元测试。

## 被测函数

```typescript
// src/utils/string.ts
export function slugify(text: string): string {
  return text.toLowerCase().trim()
    .replace(/[^\w\s-]/g, '')
    .replace(/[\s_]+/g, '-')
    .replace(/-+/g, '-')
    .replace(/^-+|-+$/g, '');
}

export function truncate(text: string, maxLength: number, suffix = '...'): string {
  if (text.length <= maxLength) return text;
  return text.slice(0, maxLength - suffix.length) + suffix;
}
```

## 用 AI 生成 Vitest 测试

**Prompt**：
```
请为以下 TypeScript 函数生成 Vitest 单元测试。
要求：覆盖正常输入、边界值、异常输入，测试名称用中文描述，每个函数至少 5 个用例。
```

AI 生成的结果：

```typescript
import { slugify, truncate } from '../string';

describe('slugify', () => {
  it('将普通文本转换为 slug', () => {
    expect(slugify('Hello World')).toBe('hello-world');
  });
  it('移除特殊字符', () => {
    expect(slugify('Hello, World! @2024')).toBe('hello-world-2024');
  });
  it('处理连续空格和连字符', () => {
    expect(slugify('  hello   --world  ')).toBe('hello-world');
  });
  it('处理空字符串', () => {
    expect(slugify('')).toBe('');
  });
  it('处理纯特殊字符', () => {
    expect(slugify('!@#$%^&*()')).toBe('');
  });
});

describe('truncate', () => {
  it('短文本不截断', () => {
    expect(truncate('hello', 10)).toBe('hello');
  });
  it('长文本截断并添加后缀', () => {
    expect(truncate('hello world foo bar', 11)).toBe('hello wo...');
  });
  it('maxLength 为 0 时返回后缀', () => {
    expect(truncate('hello', 0)).toBe('...');
  });
});
```

## AI 生成测试的常见问题

| 问题 | 表现 | 怎么发现 |
|------|------|---------|
| 测试太浅 | 只测 happy path | 检查是否有 `expect(...).toThrow()` |
| 断言太弱 | 只 `toBeTruthy()` | 看是否用 `toBe(true)` |
| 测试名称模糊 | "test1", "test2" | 失败时无法定位问题 |
| Mock 滥用 | Mock 了要测试的逻辑 | 测试变成验证 Mock 实现 |
| 忽略异步 | 未 await 异步函数 | 测试假通过 |

**改进前**：
```typescript
it('test1', () => {
  expect(validateEmail('test@example.com')).toBeTruthy();
});
```

**改进后**：
```typescript
it('标准邮箱格式返回 true', () => {
  expect(validateEmail('test@example.com')).toBe(true);
});
it('缺少 @ 符号返回 false', () => {
  expect(validateEmail('invalid')).toBe(false);
});
```

## 用 AI 生成 pytest 测试

```python
def slugify(text: str) -> str:
    text = text.lower().strip()
    text = re.sub(r"[^\w\s-]", "", text)
    text = re.sub(r"[\s_]+", "-", text)
    text = re.sub(r"-+", "-", text)
    return text.strip("-")
```

AI 生成：

```python
class TestSlugify:
    @pytest.mark.parametrize("input_text, expected", [
        ("Hello World", "hello-world"),
        ("  hello   --world  ", "hello-world"),
        ("", ""),
        ("!@#$%^&*()", ""),
        ("hello_world_test", "hello-world-test"),
    ])
    def test_slugify(self, input_text, expected):
        assert slugify(input_text) == expected
```

## 工程建议

1. **先写 2-3 个核心路径的测试**，再让 AI 基于你的风格生成剩余用例
2. **AI 生成的测试必须逐行 review**——重点看断言值是否正确
3. **测试文件与源文件同目录管理**，方便同步修改

## 练习

### 练习一：为工具函数生成测试（20 分钟）

为以下函数生成 Vitest 测试，至少 8 个用例：

```typescript
export function formatCurrency(
  amount: number, currency = 'CNY', locale = 'zh-CN'
): string {
  return new Intl.NumberFormat(locale, { style: 'currency', currency }).format(amount);
}
```

覆盖：不同币种、不同语言环境、正负数、零值、浮点精度。

### 练习二：为 Python 函数生成 pytest 测试（15 分钟）

```python
def merge_dicts(*dicts: dict) -> dict:
    result = {}
    for d in dicts:
        result.update(d)
    return result

def flatten(nested_list: list) -> list:
    result = []
    for item in nested_list:
        if isinstance(item, list):
            result.extend(flatten(item))
        else:
            result.append(item)
    return result
```

使用 `@pytest.mark.parametrize`，覆盖空输入、嵌套、混合类型。

### 练习三：审查并改进 AI 生成的测试（15 分钟）

找出至少 3 个问题并修正：

```typescript
describe('validateEmail', () => {
  it('test1', () => { expect(validateEmail('test@example.com')).toBeTruthy(); });
  it('test2', () => { expect(validateEmail('invalid')).toBeFalsy(); });
  it('test3', () => { expect(validateEmail('')).toBeFalsy(); });
});
```

---

## 参考答案

### 练习一

`Intl.NumberFormat` 输出格式因 Node.js 版本可能不同，断言用 `toContain` 而非精确匹配。浮点精度：`formatCurrency(0.1 + 0.2)` 应包含 `"0.3"`。

### 练习二

`merge_dicts` 是浅合并——嵌套字典会被完全覆盖。`flatten` 需处理任意深度嵌套，`[[[[1]]]]` 是极端边界。

### 练习三

3 个问题：
1. **命名模糊**：`test1/test2/test3` → 改为描述具体行为
2. **覆盖不全**：缺少特殊字符邮箱、多 @ 符号、null/undefined
3. **断言太弱**：`toBeTruthy/falsy` → `toBe(true/false)`
