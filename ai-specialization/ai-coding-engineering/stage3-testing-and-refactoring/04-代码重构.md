## 场景引入

你接手的项目里有一个 200 行的 `processOrder` 函数，里面混合了验证、查询、计算、扣减、通知等所有逻辑，每次改一个功能都要在密密麻麻的代码里找半天。同事说"这代码该重构了"，但你担心改着改着把功能改坏了——毕竟没有测试保护。AI 建议你用策略模式替代 switch-case，用值对象替代原始类型，但你不确定什么时候该用设计模式、什么时候反而是过度设计。这一课教你如何用 AI 安全地重构代码，在"改"和"不改"之间做出正确判断。

## 1. SOLID 原则速查

```
┌─────────────────────────────────────────────────────────────┐
│                     SOLID 原则                               │
├──────────┬──────────────────────────────────────────────────┤
│ S        │ 单一职责原则 (Single Responsibility)              │
│          │ 一个类只负责一件事                                 │
├──────────┼──────────────────────────────────────────────────┤
│ O        │ 开放封闭原则 (Open/Closed)                        │
│          │ 对扩展开放，对修改封闭                             │
├──────────┼──────────────────────────────────────────────────┤
│ L        │ 里氏替换原则 (Liskov Substitution)                │
│          │ 子类可以替换父类而不影响正确性                     │
├──────────┼──────────────────────────────────────────────────┤
│ I        │ 接口隔离原则 (Interface Segregation)              │
│          │ 不依赖不需要的接口                                 │
├──────────┼──────────────────────────────────────────────────┤
│ D        │ 依赖倒置原则 (Dependency Inversion)               │
│          │ 依赖抽象而非具体实现                               │
└──────────┴──────────────────────────────────────────────────┘
```

## 2. Code Smells → 重构手法

### 2.1 Code Smells 分类

```
┌──────────────────────────────────────────────────────────────┐
│                   Code Smells 分类                            │
├──────────────────┬───────────────────────────────────────────┤
│ Bloaters         │ 长方法、长参数列表、大类、原始类型偏执      │
├──────────────────┼───────────────────────────────────────────┤
│ OO Abusers       │ Switch 滨用、拒绝继承、散弹式修改          │
├──────────────────┼───────────────────────────────────────────┤
│ Change Preventers│ 发散式变化、平行继承、霰弹式修改            │
├──────────────────┼───────────────────────────────────────────┤
│ Dispensables     │ 重复代码、死代码、过度注释                  │
├──────────────────┼───────────────────────────────────────────┤
│ Couplers         │ 特性依恋、消息链、中间人                    │
└──────────────────┴───────────────────────────────────────────┘
```

### 2.2 重构手法映射

| Code Smell | 重构手法 | AI 辅助方式 |
|-----------|---------|------------|
| 长函数 | 提取方法 (Extract Method) | AI 识别可提取的代码块 |
| 长参数列表 | 引入参数对象 | AI 生成接口定义 |
| 重复代码 | 提取超类/委托 | AI 找出相似代码模式 |
| Switch 滥用 | 多态/策略模式 | AI 生成类层次结构 |
| 魔法数字 | 提取常量 | AI 批量替换 |
| 过深嵌套 | 卫语句/早返回 | AI 重构条件逻辑 |

## 3. Before/After 重构实战

### 3.1 长函数 → 提取方法

**Before（100+ 行的 God Function）：**

```typescript
// ❌ 一个函数做了太多事
async function handleUserRegistration(data: any) {
  // 验证 (20 行)
  if (!data.email) throw new Error('...');
  if (!data.password) throw new Error('...');
  if (data.password.length < 8) throw new Error('...');
  if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(data.email)) throw new Error('...');
  // ... 更多验证

  // 检查重复 (10 行)
  const existing = await db.user.findUnique({ where: { email: data.email } });
  if (existing) throw new Error('...');

  // 创建用户 (15 行)
  const hashedPassword = await bcrypt.hash(data.password, 10);
  const user = await db.user.create({
    data: { email: data.email, password: hashedPassword, name: data.name },
  });

  // 发送欢迎邮件 (10 行)
  await emailService.send({
    to: data.email,
    subject: 'Welcome!',
    template: 'welcome',
    data: { name: data.name },
  });

  // 生成 Token (5 行)
  const token = jwt.sign({ userId: user.id }, process.env.JWT_SECRET!);

  // 记录日志 (5 行)
  logger.info(`User registered: ${user.id}`);

  return { user, token };
}
```

**After（单一职责 + 提取方法）：**

```typescript
// ✅ 每个函数只做一件事

function validateRegistrationData(data: unknown): RegistrationData {
  const schema = z.object({
    email: z.string().email('邮箱格式不正确'),
    password: z.string().min(8, '密码至少 8 位'),
    name: z.string().min(1, '名称不能为空'),
  });
  return schema.parse(data);
}

async function ensureEmailNotTaken(email: string): Promise<void> {
  const existing = await db.user.findUnique({ where: { email } });
  if (existing) {
    throw new ConflictError('邮箱已注册');
  }
}

async function createUser(data: RegistrationData): Promise<User> {
  const hashedPassword = await bcrypt.hash(data.password, 10);
  return db.user.create({
    data: { email: data.email, password: hashedPassword, name: data.name },
  });
}

async function sendWelcomeEmail(email: string, name: string): Promise<void> {
  await emailService.send({
    to: email,
    subject: 'Welcome!',
    template: 'welcome',
    data: { name },
  });
}

function generateToken(userId: string): string {
  return jwt.sign({ userId }, process.env.JWT_SECRET!);
}

// 主函数：清晰的编排逻辑
async function handleUserRegistration(data: unknown) {
  const validated = validateRegistrationData(data);
  await ensureEmailNotTaken(validated.email);
  const user = await createUser(validated);
  
  // 欢迎邮件和 Token 生成可以并行
  const [, token] = await Promise.all([
    sendWelcomeEmail(validated.email, validated.name),
    Promise.resolve(generateToken(user.id)),
  ]);

  logger.info(`User registered: ${user.id}`);
  return { user, token };
}
```

### 3.2 Switch 滥用 → 策略模式

**Before（大量 if/else）：**

```typescript
// ❌ 每加一种通知方式就要改这个函数
function sendNotification(type: string, user: User, message: string) {
  if (type === 'email') {
    const transporter = createEmailTransporter();
    transporter.send({ to: user.email, subject: 'Notification', body: message });
  } else if (type === 'sms') {
    const client = createSmsClient();
    client.send({ to: user.phone, message });
  } else if (type === 'push') {
    const pushService = createPushService();
    pushService.send({ userId: user.id, title: 'Notification', body: message });
  } else if (type === 'wechat') {
    const wechatApi = createWechatApi();
    wechatApi.send({ openId: user.wechatId, content: message });
  } else {
    throw new Error(`Unknown notification type: ${type}`);
  }
}
```

**After（策略模式）：**

```typescript
// ✅ 每种通知方式独立实现，新增方式只需添加一个类

interface NotificationSender {
  send(user: User, message: string): Promise<void>;
}

class EmailNotification implements NotificationSender {
  async send(user: User, message: string): Promise<void> {
    const transporter = createEmailTransporter();
    await transporter.send({ to: user.email, subject: 'Notification', body: message });
  }
}

class SmsNotification implements NotificationSender {
  async send(user: User, message: string): Promise<void> {
    const client = createSmsClient();
    await client.send({ to: user.phone, message });
  }
}

class PushNotification implements NotificationSender {
  async send(user: User, message: string): Promise<void> {
    const pushService = createPushService();
    await pushService.send({ userId: user.id, title: 'Notification', body: message });
  }
}

// 注册表
const senders: Record<string, NotificationSender> = {
  email: new EmailNotification(),
  sms: new SmsNotification(),
  push: new PushNotification(),
};

function getNotificationSender(type: string): NotificationSender {
  const sender = senders[type];
  if (!sender) throw new Error(`Unknown notification type: ${type}`);
  return sender;
}

// 主函数简洁清晰
async function sendNotification(type: string, user: User, message: string) {
  const sender = getNotificationSender(type);
  await sender.send(user, message);
}
```

### 3.3 魔法数字 → 命名常量

**Before：**

```typescript
// ❌ 到处散落的魔法数字
function calculateDiscount(price: number, userType: string): number {
  if (userType === 'vip') return price * 0.8;
  if (userType === 'svip') return price * 0.6;
  if (price > 1000) return price * 0.95;
  if (price > 500) return price * 0.98;
  return price;
}

function isWorkingHour(date: Date): boolean {
  const hour = date.getHours();
  return hour >= 9 && hour < 18 && date.getDay() !== 0 && date.getDay() !== 6;
}
```

**After：**

```typescript
// ✅ 语义化的常量
const DISCOUNT_RATE = {
  VIP: 0.8,
  SVIP: 0.6,
  OVER_1000: 0.95,
  OVER_500: 0.98,
  NONE: 1,
} as const;

const PRICE_THRESHOLD = {
  TIER_1: 500,
  TIER_2: 1000,
} as const;

const WORKING_HOURS = {
  START: 9,
  END: 18,
} as const;

const WEEKEND_DAYS = [0, 6];

function calculateDiscount(price: number, userType: string): number {
  const userDiscount: Record<string, number> = {
    vip: DISCOUNT_RATE.VIP,
    svip: DISCOUNT_RATE.SVIP,
  };
  if (userType in userDiscount) return price * userDiscount[userType];
  if (price > PRICE_THRESHOLD.TIER_2) return price * DISCOUNT_RATE.OVER_1000;
  if (price > PRICE_THRESHOLD.TIER_1) return price * DISCOUNT_RATE.OVER_500;
  return price;
}

function isWorkingHour(date: Date): boolean {
  const hour = date.getHours();
  const day = date.getDay();
  return (
    hour >= WORKING_HOURS.START &&
    hour < WORKING_HOURS.END &&
    !WEEKEND_DAYS.includes(day)
  );
}
```

### 3.4 过深嵌套 → 卫语句

**Before：**

```typescript
// ❌ 嵌套 4 层
function getShippingCost(order: Order): number {
  if (order.user) {
    if (order.user.isVIP) {
      if (order.items.length > 0) {
        if (order.total > 100) {
          return 0;
        } else {
          return 10;
        }
      } else {
        return 0;
      }
    } else {
      return 20;
    }
  } else {
    throw new Error('User required');
  }
}
```

**After：**

```typescript
// ✅ 卫语句：提前返回，减少嵌套
function getShippingCost(order: Order): number {
  if (!order.user) {
    throw new Error('User required');
  }

  if (order.user.isVIP) {
    return 0;
  }

  if (order.items.length === 0) {
    return 0;
  }

  if (order.total > 100) {
    return 0;
  }

  return order.total > 50 ? 10 : 20;
}
```

### 3.5 原始类型偏执 → 值对象

**Before：**

```typescript
// ❌ 到处传递原始类型，缺乏语义
function createUser(
  email: string,
  password: string,
  age: number,
  phone: string
) {
  // 验证逻辑散落各处
  if (!email.includes('@')) throw new Error('Invalid email');
  if (password.length < 8) throw new Error('Weak password');
  if (age < 0 || age > 150) throw new Error('Invalid age');
  if (!/^1[3-9]\d{9}$/.test(phone)) throw new Error('Invalid phone');
  // ...
}
```

**After：**

```typescript
// ✅ 值对象封装验证逻辑
class Email {
  constructor(private readonly value: string) {
    if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value)) {
      throw new ValidationError('邮箱格式不正确');
    }
  }

  toString(): string {
    return this.value;
  }
}

class Password {
  constructor(private readonly value: string) {
    if (value.length < 8) throw new ValidationError('密码至少 8 位');
    if (value.length > 128) throw new ValidationError('密码最多 128 位');
  }

  async hash(): Promise<string> {
    return bcrypt.hash(this.value, 10);
  }
}

class Age {
  constructor(private readonly value: number) {
    if (!Number.isInteger(value)) throw new ValidationError('年龄必须是整数');
    if (value < 0 || value > 150) throw new ValidationError('年龄范围 0-150');
  }

  toNumber(): number {
    return this.value;
  }
}

class PhoneNumber {
  constructor(private readonly value: string) {
    if (!/^1[3-9]\d{9}$/.test(value)) {
      throw new ValidationError('手机号格式不正确');
    }
  }

  toString(): string {
    return this.value;
  }
}

// 使用：类型安全 + 自动验证
async function createUser(
  email: Email,
  password: Password,
  age: Age,
  phone: PhoneNumber
) {
  // 不需要额外验证，值对象已经保证了合法性
  const hashedPassword = await password.hash();
  return db.user.create({
    data: {
      email: email.toString(),
      password: hashedPassword,
      age: age.toNumber(),
      phone: phone.toString(),
    },
  });
}

// 调用时验证
const user = await createUser(
  new Email('test@example.com'),
  new Password('secure123'),
  new Age(25),
  new PhoneNumber('13800138000')
);
```

## 常见误区

### 错误 1：一次重构太多

```bash
# ❌ 一次重构 500 行，风险极高
# ✅ 小步重构：每次只改一小块，测试通过后再继续
# 重构节奏：改 10 行 → 测试 → 改 10 行 → 测试
```

### 错误 2：重构时添加新功能

```bash
# ❌ 重构的同时加功能，出了 Bug 分不清是重构还是新功能的问题
# ✅ 重构和新功能分开做
# 先重构（行为不变）→ 测试通过 → 再加新功能
```

## 工程建议

1. **重构前必须有测试保护**：如果目标代码没有测试，先用 AI 生成当前行为的测试用例，确认全部通过后再开始重构，这是你的安全网。
2. **每次重构只做一件事**：提取方法和引入设计模式不要在同一个 PR 里做，拆成多个小 PR，每个 PR 只改一种 Code Smell，方便 review 和回滚。
3. **用 Boy Scout Rule 渐进式重构**：每次修改文件时，顺手把当前文件的 Code Smell 修复一点，不需要专门安排"重构周"，积少成多效果更好。
4. **重构后运行完整的回归测试**：不仅跑单元测试，还要跑集成测试和 lint/typecheck，确保行为不变、类型安全、代码风格一致。

### 练习 1：重构长函数

**思路**：将 `generateReport` 的 5 个步骤提取为独立函数，主函数只做编排。每个子函数职责单一、可独立测试。

**答案**：

```typescript
interface ReportData {
  rawData: RawRecord[];
  cleanedData: CleanedRecord[];
  statistics: ReportStatistics;
  charts: ChartData[];
  pdfPath: string;
}

interface RawRecord {
  id: string;
  amount: number;
  date: string;
  status: string;
}

interface CleanedRecord extends RawRecord {
  normalizedDate: Date;
  category: string;
}

interface ReportStatistics {
  totalRevenue: number;
  orderCount: number;
  averageOrderValue: number;
  topCategories: Array<{ name: string; revenue: number }>;
}

interface ChartData {
  type: 'bar' | 'line' | 'pie';
  title: string;
  data: unknown;
}

// 步骤 1：查询数据
async function queryReportData(startDate: Date, endDate: Date): Promise<RawRecord[]> {
  const results = await db.order.findMany({
    where: {
      createdAt: { gte: startDate, lte: endDate },
      status: { in: ['completed', 'shipped'] },
    },
    select: { id: true, amount: true, date: true, status: true },
  });
  return results;
}

// 步骤 2：清洗数据
function cleanReportData(rawData: RawRecord[]): CleanedRecord[] {
  return rawData
    .filter((record) => record.amount > 0)
    .map((record) => ({
      ...record,
      normalizedDate: new Date(record.date),
      category: categorizeOrder(record),
    }));
}

// 步骤 3：计算统计
function calculateStatistics(data: CleanedRecord[]): ReportStatistics {
  const totalRevenue = data.reduce((sum, r) => sum + r.amount, 0);
  const orderCount = data.length;
  const averageOrderValue = orderCount > 0 ? totalRevenue / orderCount : 0;

  const categoryMap = new Map<string, number>();
  for (const record of data) {
    categoryMap.set(record.category, (categoryMap.get(record.category) ?? 0) + record.amount);
  }
  const topCategories = [...categoryMap.entries()]
    .map(([name, revenue]) => ({ name, revenue }))
    .sort((a, b) => b.revenue - a.revenue)
    .slice(0, 10);

  return { totalRevenue, orderCount, averageOrderValue, topCategories };
}

// 步骤 4：生成图表
function generateCharts(statistics: ReportStatistics): ChartData[] {
  return [
    {
      type: 'bar',
      title: 'Top Categories',
      data: statistics.topCategories,
    },
    {
      type: 'pie',
      title: 'Revenue Distribution',
      data: statistics.topCategories.map((c) => ({ label: c.name, value: c.revenue })),
    },
  ];
}

// 步骤 5：导出 PDF
async function exportReportPdf(
  statistics: ReportStatistics,
  charts: ChartData[],
  startDate: Date,
  endDate: Date
): Promise<string> {
  const pdfPath = `reports/report-${startDate.toISOString().slice(0, 10)}.pdf`;
  await pdfGenerator.generate({
    title: `Sales Report: ${startDate.toLocaleDateString()} - ${endDate.toLocaleDateString()}`,
    statistics,
    charts,
    outputPath: pdfPath,
  });
  return pdfPath;
}

// 主函数：清晰的编排逻辑
async function generateReport(startDate: Date, endDate: Date): Promise<string> {
  const rawData = await queryReportData(startDate, endDate);
  const cleanedData = cleanReportData(rawData);
  const statistics = calculateStatistics(cleanedData);
  const charts = generateCharts(statistics);
  const pdfPath = await exportReportPdf(statistics, charts, startDate, endDate);
  return pdfPath;
}
```

**要点**：
- 主函数从 100+ 行缩减到 6 行编排逻辑，每个步骤的意图一目了然
- 每个子函数可以独立测试——`calculateStatistics` 不需要数据库连接
- 提取方法时注意保持数据流：前一个函数的输出是后一个函数的输入

### 练习 2：应用策略模式

**思路**：将 `calculatePrice` 中的 if-else 分支重构为策略模式。定义 `DiscountStrategy` 接口，每种折扣策略独立实现，通过注册表查找。

**答案**：

```typescript
// 策略接口
interface DiscountStrategy {
  calculate(price: number): number;
}

// 具体策略
class PercentageDiscount implements DiscountStrategy {
  private rate = 0.8; // 8 折

  calculate(price: number): number {
    return price * this.rate;
  }
}

class FixedDiscount implements DiscountStrategy {
  private amount = 50;

  calculate(price: number): number {
    return Math.max(0, price - this.amount);
  }
}

class BuyOneGetOneDiscount implements DiscountStrategy {
  calculate(price: number): number {
    return price / 2;
  }
}

class TieredDiscount implements DiscountStrategy {
  private tiers = [
    { threshold: 1000, rate: 0.7 },
    { threshold: 500, rate: 0.8 },
    { threshold: 0, rate: 0.9 },
  ];

  calculate(price: number): number {
    for (const tier of this.tiers) {
      if (price > tier.threshold) {
        return price * tier.rate;
      }
    }
    return price;
  }
}

// 策略注册表
const discountStrategies: Record<string, DiscountStrategy> = {
  percentage: new PercentageDiscount(),
  fixed: new FixedDiscount(),
  bogo: new BuyOneGetOneDiscount(),
  tiered: new TieredDiscount(),
};

function getDiscountStrategy(type: string): DiscountStrategy {
  const strategy = discountStrategies[type];
  if (!strategy) {
    return { calculate: (price: number) => price }; // 无折扣
  }
  return strategy;
}

// 主函数：简洁清晰
function calculatePrice(price: number, discountType: string): number {
  const strategy = getDiscountStrategy(discountType);
  return strategy.calculate(price);
}

// 新增折扣类型时，只需添加一个新类并注册：
class FlashSaleDiscount implements DiscountStrategy {
  calculate(price: number): number {
    return price * 0.5;
  }
}
discountStrategies['flash-sale'] = new FlashSaleDiscount();
```

**要点**：
- 新增折扣类型只需：实现 `DiscountStrategy` 接口 + 注册到 `discountStrategies`，不修改 `calculatePrice`
- 符合开放封闭原则：对扩展开放（新增策略），对修改封闭（不改主函数）
- 如果折扣类型在编译时就确定且不会增加，直接 if-else 更简洁——策略模式适合"类型可能增加"的场景

### 练习 3：消除魔法数字

**思路**：找出 `validateInput` 中所有硬编码的数字（50, 0, 150, 500, 10, 0, 100），提取为语义化的命名常量。

**答案**：

```typescript
// 输入校验限制常量
const INPUT_LIMITS = {
  NAME_MAX_LENGTH: 50,
  AGE_MIN: 0,
  AGE_MAX: 150,
  BIO_MAX_LENGTH: 500,
  MAX_TAGS_COUNT: 10,
  SCORE_MIN: 0,
  SCORE_MAX: 100,
} as const;

function validateInput(data: {
  name: string;
  age: number;
  bio: string;
  tags: string[];
  score: number;
}): void {
  if (data.name.length > INPUT_LIMITS.NAME_MAX_LENGTH) {
    throw new Error(`Name too long (max ${INPUT_LIMITS.NAME_MAX_LENGTH} characters)`);
  }

  if (data.age < INPUT_LIMITS.AGE_MIN || data.age > INPUT_LIMITS.AGE_MAX) {
    throw new Error(`Invalid age (must be ${INPUT_LIMITS.AGE_MIN}-${INPUT_LIMITS.AGE_MAX})`);
  }

  if (data.bio.length > INPUT_LIMITS.BIO_MAX_LENGTH) {
    throw new Error(`Bio too long (max ${INPUT_LIMITS.BIO_MAX_LENGTH} characters)`);
  }

  if (data.tags.length > INPUT_LIMITS.MAX_TAGS_COUNT) {
    throw new Error(`Too many tags (max ${INPUT_LIMITS.MAX_TAGS_COUNT})`);
  }

  if (data.score < INPUT_LIMITS.SCORE_MIN || data.score > INPUT_LIMITS.SCORE_MAX) {
    throw new Error(`Invalid score (must be ${INPUT_LIMITS.SCORE_MIN}-${INPUT_LIMITS.SCORE_MAX})`);
  }
}
```

**改进说明：**

1. **7 个魔法数字**全部提取到 `INPUT_LIMITS` 常量对象中
2. 使用 `as const` 确保类型推导为字面量类型，防止意外修改
3. 错误信息中引用常量值，修改限制时不需要同步更新错误消息
4. 常量命名语义化：`NAME_MAX_LENGTH` 比 `50` 更能表达意图
5. 如果需要不同角色有不同限制，可以将 `INPUT_LIMITS` 改为工厂函数：

```typescript
function getInputLimits(role: 'user' | 'admin') {
  const base = { ...INPUT_LIMITS };
  if (role === 'admin') {
    return { ...base, NAME_MAX_LENGTH: 100, MAX_TAGS_COUNT: 50 };
  }
  return base;
}
```

**要点**：
- 魔法数字的危害：不知道 50 代表什么、修改时容易遗漏、无法复用
- `as const` 让常量对象的值在 TypeScript 中推导为字面量类型
- 错误信息中引用常量，避免"改了常量忘了改错误消息"的不一致
