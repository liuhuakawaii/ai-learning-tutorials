# 04 时序数据存储

## 场景引入

你的量化系统运行了 3 个月，数据管道每天稳定采集 5000 只 A 股的日线数据。但问题来了：

- PostgreSQL 的 `daily_prices` 表已经有 300 万行，查询一只股票 5 年数据需要 8 秒
- 你想要计算全市场的动量因子，需要同时读取 5000 只股票的 60 天数据——这个查询跑了 2 分钟
- 磁盘空间告急，1 年的日线数据就占了 50 GB（因为 PostgreSQL 的行存储效率太低）
- 你尝试用 CSV 文件存储，但跨股票查询几乎不可能

这不是你的代码写得烂，而是**存储架构选错了**。关系型数据库为 OLTP（在线事务处理）设计，擅长增删改查单行数据；但量化系统的核心需求是 OLAP（在线分析处理）——批量读取、聚合计算、时间范围查询。

本节课将带你理解时序数据库的核心原理，对比主流方案，并用 ClickHouse 搭建一个生产级的行情数据存储系统。

> **风险提示**：数据库选型应根据实际业务规模和团队能力决定。本课介绍的技术方案仅供教学参考，生产部署前请进行充分的性能测试和容量规划。

## 一、为什么关系型数据库不适合时序数据

### 1.1 存储模型不匹配

```
关系型数据库（行存储）：

  行 1: [日期, 股票, 开盘, 最高, 最低, 收盘, 成交量, 成交额, 换手率]
  行 2: [日期, 股票, 开盘, 最高, 最低, 收盘, 成交量, 成交额, 换手率]
  行 3: [日期, 股票, 开盘, 最高, 最低, 收盘, 成交量, 成交额, 换手率]

  查询"所有股票的收盘价"→ 需要读取每一行的全部字段
  实际只用了 1/9 的数据，浪费了 8/9 的 I/O

列式数据库（列存储）：

  日期列:  [2024-01-02, 2024-01-03, 2024-01-04, ...]
  股票列:  [000001,     000001,     000001,     ...]
  收盘列:  [10.50,      10.65,      10.72,      ...]
  成交量列: [15000000,   18000000,   12000000,   ...]

  查询"所有股票的收盘价"→ 只读取日期列和收盘列
  I/O 减少到 2/9，查询速度提升 4-5 倍
```

### 1.2 性能对比

```
测试场景：查询 5000 只股票 1 年的日线数据并计算 20 日均线

  PostgreSQL (行存储):
    数据量：5000 × 250 = 125 万行
    查询时间：~45 秒
    磁盘占用：~8 GB

  ClickHouse (列存储):
    数据量：同上
    查询时间：~1.5 秒
    磁盘占用：~0.8 GB

  性能差距：30 倍
  存储差距：10 倍
```

### 1.3 时序数据的特殊需求

```
金融时序数据的特征：

  1. 写入模式：追加为主，极少修改历史数据
  2. 查询模式：按时间范围 + 标的筛选，大范围扫描
  3. 数据量：日增 5000 行（日线），分钟线可达 120 万行/天
  4. 保留策略：日线保留 20 年，分钟线保留 2 年
  5. 查询特征：聚合计算（SUM、AVG、窗口函数）远多于单点查询

关系型数据库的优势（量化系统用不上）：
  - 事务支持（ACID）
  - 复杂 JOIN
  - 单行精确查询
  - 数据修改
```

## 二、时序数据库选型

### 2.1 主流方案对比

| 维度 | ClickHouse | TimescaleDB | QuestDB |
|------|------------|-------------|---------|
| 存储模型 | 列式 | 行式（基于 PostgreSQL） | 列式 |
| 查询语言 | SQL（扩展） | SQL（完全兼容 PG） | SQL（扩展） |
| 写入性能 | 极高（批量） | 高 | 极高 |
| 查询性能 | 极高（聚合） | 高 | 高 |
| 压缩比 | 10-20x | 2-5x | 8-15x |
| 部署复杂度 | 中 | 低（基于 PG） | 低 |
| 生态成熟度 | 高 | 高 | 中 |
| 社区活跃度 | 极高 | 高 | 中 |
| 适合场景 | 大规模分析 | 已有 PG 生态 | 快速原型 |

### 2.2 选型决策树

```
数据规模 > 10 亿行？
  ├── 是 → ClickHouse（唯一能高效处理这个量级的开源方案）
  └── 否 → 团队已有 PostgreSQL 经验？
               ├── 是 → TimescaleDB（无缝集成现有 PG 生态）
               └── 否 → 需要最快上手？
                         ├── 是 → QuestDB（最简单的部署和使用）
                         └── 否 → ClickHouse（学习曲线稍陡但功能最强）
```

### 2.3 为什么选择 ClickHouse

对于量化交易场景，ClickHouse 有几个关键优势：

1. **列式存储 + 向量化执行**：聚合查询性能碾压行式数据库
2. **极高的压缩比**：10-20 倍压缩，大幅降低存储成本
3. **MergeTree 引擎**：专为时序数据设计，支持分区、排序、TTL
4. **丰富的聚合函数**：内置 `argMin`、`argMax`、`quantile`、`rolling` 等
5. **成熟的生态**：Python 驱动、Grafana 集成、云服务支持

## 三、ClickHouse 核心概念

### 3.1 MergeTree 引擎

```
MergeTree 引擎的核心机制：

  写入流程：
    数据写入 → 内存缓冲区 → 后台合并为数据片段（Part）
    │
    ▼
  ┌─────────┐    ┌─────────┐    ┌─────────┐
  │ Part 1  │    │ Part 2  │    │ Part 3  │
  │ 10万行  │    │ 10万行  │    │ 10万行  │
  └─────────┘    └─────────┘    └─────────┘
        │              │              │
        └──────────────┼──────────────┘
                       │ 后台异步合并（Merge）
                       ▼
              ┌─────────────────┐
              │   Merged Part   │
              │     30万行      │
              │   (排序+压缩)    │
              └─────────────────┘

  查询流程：
    查询请求 → 扫描所有 Part → 合并结果 → 返回
    列式存储 + 索引 → 只读取需要的列和行
```

### 3.2 关键概念

```
分区（Partition）：
  - 按时间分区（如按月），查询时自动裁剪不需要的分区
  - 类似于按月份建子表

排序键（ORDER BY）：
  - 数据在磁盘上按排序键有序存储
  - 等价于聚簇索引，范围查询极快
  - 量化场景：(symbol, date) 或 (date, symbol)

主键（PRIMARY KEY）：
  - 默认与 ORDER BY 相同
  - 用于去重（ReplacingMergeTree）

TTL（Time To Live）：
  - 自动删除过期数据
  - 如：分钟线保留 2 年，日线保留 20 年
```

## 四、Schema 设计

### 4.1 日线行情表

```sql
-- A 股日线行情表
CREATE TABLE IF NOT EXISTS stock_daily
(
    date          Date,
    symbol        String,
    open          Float64,
    high          Float64,
    low           Float64,
    close         Float64,
    volume        UInt64,
    amount        Float64,
    turnover_rate Float64,
    pct_change    Float64,
    is_suspended  UInt8 DEFAULT 0,
    adj_factor    Float64 DEFAULT 1.0
)
ENGINE = MergeTree()
PARTITION BY toYYYYMM(date)
ORDER BY (symbol, date)
TTL date + INTERVAL 20 YEAR
SETTINGS index_granularity = 8192;
```

### 4.2 分钟线行情表

```sql
-- A 股分钟线行情表
CREATE TABLE IF NOT EXISTS stock_minute

    datetime      DateTime,

    high          Float64,
    low           Float64,

    volume        UInt64,
    amount        Float64

ENGINE = MergeTree()

ORDER BY (symbol, datetime)

```

### 4.3 因子值表

```sql
-- 因子值表（宽表设计）
CREATE TABLE IF NOT EXISTS factor_values
(
    date          Date,
    factor_name   String,
    symbol        String,
    value         Float64,
    rank_score    Float64,
    update_time   DateTime DEFAULT now()
)
ENGINE = ReplacingMergeTree(update_time)
PARTITION BY toYYYYMM(date)
ORDER BY (factor_name, symbol, date)
TTL date + INTERVAL 10 YEAR;
```

### 4.4 Schema 设计要点

```
设计原则：

  1. 分区键选择
     ├── 按月分区（toYYYYMM）：适合日线和分钟线
     ├── 按日分区：适合 Tick 数据（数据量极大）
     └── 不分区：数据量小时可以不分区

  2. 排序键设计
     ├── (symbol, date)：适合按股票查询（获取单只股票历史）
     ├── (date, symbol)：适合按日期查询（获取某天所有股票）
     └── (factor_name, symbol, date)：适合因子查询

  3. 数据类型选择
     ├── 价格：Float64（精度足够）
     ├── 成交量：UInt64（避免负数）
     ├── 日期：Date（精确到天）或 DateTime（精确到秒）
     ├── 股票代码：String（A 股代码含前导零）
     └── 布尔标记：UInt8（0/1）

  4. 压缩优化
     ├── 低基数列使用 LowCardinality(String)
     ├── 日期列使用 Date 而非 String
     └── 排序键列重复值越多，压缩比越高
```

"""
ClickHouse 数据存储模块
依赖安装：pip install clickhouse-connect pandas

import clickhouse_connect
import pandas as pd
import numpy as np
from datetime import datetime, timedelta
from typing import Optional
import logging
import time

logger = logging.getLogger(__name__)


class ClickHouseManager:
    """
    ClickHouse 数据库管理器
    封装连接管理、表操作、数据读写等功能
    """
    def __init__(
        self,
        host: str = "localhost",
        port: int = 8123,
        username: str = "default",
        password: str = "",
        database: str = "quant",
    ):
        self.host = host
        self.port = port
        self.username = username
        self.password = password
        self.database = database
        self.client: Optional[clickhouse_connect.driver.Client] = None

    def connect(self):
        """建立数据库连接"""
        self.client = clickhouse_connect.get_client(
            host=self.host,
            port=self.port,
            username=self.username,
            password=self.password,
            database=self.database,
        )
        # 测试连接
        result = self.client.command("SELECT 1")
        logger.info(f"已连接到 ClickHouse ({self.host}:{self.port})")

    def disconnect(self):
        """关闭数据库连接"""
        if self.client:
            self.client.close()
            logger.info("已断开 ClickHouse 连接")

    def __enter__(self):
        self.connect()
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        self.disconnect()

    def create_database(self, database: str):
        """创建数据库"""
        self.client.command(
            f"CREATE DATABASE IF NOT EXISTS {database}"
        )
        logger.info(f"数据库 '{database}' 已就绪")

    def create_tables(self):
        """创建所有必要的表"""
        # 日线行情表
        self.client.command("""
            CREATE TABLE IF NOT EXISTS stock_daily
            (
                date          Date,
                symbol        String,
                open          Float64,
                high          Float64,
                low           Float64,
                close         Float64,
                volume        UInt64,

                pct_change    Float64,
                is_suspended  UInt8 DEFAULT 0,
                adj_factor    Float64 DEFAULT 1.0
            )
            ENGINE = MergeTree()
            PARTITION BY toYYYYMM(date)
            ORDER BY (symbol, date)
            TTL date + INTERVAL 20 YEAR
        """)

        # 分钟线行情表

                open          Float64,
                high          Float64,

                close         Float64,

    def insert_daily_batch(
        self, df: pd.DataFrame, batch_size: int = 10000
    ):
        """
        批量写入日线数据

        Args:
            df: 包含日线数据的 DataFrame
            batch_size: 每批写入的行数
        """
        if self.client is None:
            raise RuntimeError("未连接到数据库")

        # 确保列名和数据类型正确
        df = self._prepare_daily_data(df)

        total_rows = len(df)
        start_time = time.time()

        for i in range(0, total_rows, batch_size):
            batch = df.iloc[i:i + batch_size]
            self.client.insert(
                "stock_daily",
                batch.values.tolist(),
                column_names=batch.columns.tolist(),
            )
            logger.debug(f"写入批次 {i // batch_size + 1}: {len(batch)} 行")

        elapsed = time.time() - start_time
        rate = total_rows / elapsed if elapsed > 0 else 0
        logger.info(
            f"日线数据写入完成: {total_rows} 行, "
            f"耗时 {elapsed:.2f} 秒, "
            f"速率 {rate:.0f} 行/秒"
        )

    def _prepare_daily_data(self, df: pd.DataFrame) -> pd.DataFrame:
        """准备日线数据，确保列名和类型正确"""
        df = df.copy()

        # 列名映射
        column_mapping = {
            "日期": "date", "开盘": "open", "最高": "high",
            "最低": "low", "收盘": "close", "成交量": "volume",
            "成交额": "amount", "换手率": "turnover_rate",
            "涨跌幅": "pct_change",
        }
        df = df.rename(columns=column_mapping)

        # 确保必需列存在
        required = ["date", "symbol", "open", "high", "low", "close", "volume"]
        for col in required:
            if col not in df.columns:
                raise ValueError(f"缺少必需列: {col}")

        # 类型转换
        df["date"] = pd.to_datetime(df["date"]).dt.date
        df["symbol"] = df["symbol"].astype(str)
        for col in ["open", "high", "low", "close", "amount", "turnover_rate", "pct_change"]:
            if col in df.columns:
                df[col] = pd.to_numeric(df[col], errors="coerce").fillna(0.0)
        if "volume" in df.columns:
            df["volume"] = pd.to_numeric(df["volume"], errors="coerce").fillna(0).astype(np.uint64)
        if "is_suspended" not in df.columns:
            df["is_suspended"] = 0
        if "adj_factor" not in df.columns:
            df["adj_factor"] = 1.0

        # 只保留需要的列
        target_cols = [
            "date", "symbol", "open", "high", "low", "close",
            "volume", "amount", "turnover_rate", "pct_change",
            "is_suspended", "adj_factor",
        ]
        df = df[[c for c in target_cols if c in df.columns]]

        return df

    def insert_factor_batch(
        self, df: pd.DataFrame, batch_size: int = 50000
    ):
        """批量写入因子值数据"""
        if self.client is None:
            raise RuntimeError("未连接到数据库")

        df = df.copy()
        df["date"] = pd.to_datetime(df["date"]).dt.date
        df["update_time"] = datetime.now()

        target_cols = ["date", "factor_name", "symbol", "value", "rank_score", "update_time"]
        df = df[[c for c in target_cols if c in df.columns]]

        total_rows = len(df)
        start_time = time.time()

        for i in range(0, total_rows, batch_size):
            batch = df.iloc[i:i + batch_size]
            self.client.insert(
                "factor_values",
                batch.values.tolist(),
                column_names=batch.columns.tolist(),
            )

        elapsed = time.time() - start_time
        logger.info(f"因子数据写入完成: {total_rows} 行, 耗时 {elapsed:.2f} 秒")

    def query_stock_daily(
        self,
        symbol: str,
        start_date: str,
        end_date: str,
        columns: Optional[list[str]] = None
    ) -> pd.DataFrame:
        """
        查询单只股票的日线数据

        Args:
            symbol: 股票代码
            start_date: 开始日期
            end_date: 结束日期
            columns: 需要的列（默认全部）

        Returns:
            查询结果 DataFrame
        """
        cols = ", ".join(columns) if columns else "*"
        query = f"""
            SELECT {cols}
            FROM stock_daily
            WHERE symbol = '{symbol}'
              AND date >= '{start_date}'
              AND date <= '{end_date}'
            ORDER BY date
        """
        result = self.client.query_df(query)
        return result

    def query_market_snapshot(
        self, date: str, columns: Optional[list[str]] = None
    ) -> pd.DataFrame:
        """
        查询某个交易日的全市场快照

        Args:
            date: 交易日期
            columns: 需要的列

        Returns:
            全市场当日数据
        """
        cols = ", ".join(columns) if columns else "*"
        query = f"""
            SELECT {cols}
            FROM stock_daily
            WHERE date = '{date}'
            ORDER BY symbol
        """
        return self.client.query_df(query)

    def query_multi_stock_panel(
        self,
        symbols: list[str],
        start_date: str,
        end_date: str,
        columns: Optional[list[str]] = None
    ) -> pd.DataFrame:
        """
        查询多只股票的面板数据

        Args:
            symbols: 股票代码列表
            start_date: 开始日期
            end_date: 结束日期
            columns: 需要的列

        Returns:
            面板数据 DataFrame
        """
        cols = ", ".join(columns) if columns else "*"
        symbols_str = ", ".join(f"'{s}'" for s in symbols)
        query = f"""
            SELECT {cols}
            FROM stock_daily
            WHERE symbol IN ({symbols_str})
              AND date >= '{start_date}'
              AND date <= '{end_date}'
            ORDER BY date, symbol
        """
        return self.client.query_df(query)

    def compute_market_stats(self, date: str) -> dict:
        """
        计算某天的市场统计指标
        利用 ClickHouse 的聚合函数高效计算
        """
        query = f"""
            SELECT
                count() as total_stocks,
                countIf(pct_change > 0) as up_count,
                countIf(pct_change < 0) as down_count,
                countIf(pct_change = 0) as flat_count,
                avg(pct_change) as avg_change,
                median(pct_change) as median_change,
                stddev(pct_change) as std_change,
                max(pct_change) as max_change,
                min(pct_change) as min_change,
                sum(volume) as total_volume,
                sum(amount) as total_amount
            FROM stock_daily
            WHERE date = '{date}'
              AND is_suspended = 0
        """
        result = self.client.query_df(query)
        return result.iloc[0].to_dict() if len(result) > 0 else {}

    def get_table_stats(self) -> pd.DataFrame:
        """获取所有表的统计信息"""
        query = """
            SELECT
                table,
                formatReadableSize(sum(bytes_on_disk)) as size,
                sum(rows) as total_rows,
                count() as part_count,
                min(min_date) as earliest_date,
                max(max_date) as latest_date
            FROM system.parts
            WHERE database = currentDatabase()
              AND active = 1
            GROUP BY table
            ORDER BY table
        """
        return self.client.query_df(query)

## 六、查询优化技巧

### 6.1 利用分区裁剪

```sql
-- 好：指定日期范围，ClickHouse 自动裁剪不需要的分区
SELECT * FROM stock_daily
WHERE date >= '2024-01-01' AND date <= '2024-01-31'
  AND symbol = '000001';

-- 差：不指定日期范围，扫描全部分区
SELECT * FROM stock_daily
WHERE symbol = '000001';
```

### 6.2 利用排序键加速

```sql
-- 好：查询条件与排序键 (symbol, date) 一致
-- ClickHouse 可以直接定位到目标数据块
SELECT close, volume FROM stock_daily
WHERE symbol = '000001' AND date >= '2024-01-01';

-- 差：只按 date 查询，需要扫描所有 symbol 的数据
SELECT close, volume FROM stock_daily
WHERE date = '2024-01-01';
-- 如果经常按日期查询，考虑使用 ORDER BY (date, symbol)
```

### 6.3 使用 PREWHERE 优化

```sql
-- PREWHERE 在读取数据时先过滤，减少后续处理的数据量
SELECT date, close, volume
FROM stock_daily
PREWHERE symbol = '000001'  -- 先过滤 symbol（高选择性）
WHERE date >= '2024-01-01'  -- 再过滤 date
```

### 6.4 批量聚合查询

```sql
-- 计算每只股票的年度统计
SELECT
    symbol,
    argMin(close, date) as year_start_price,
    argMax(close, date) as year_end_price,
    (year_end_price / year_start_price - 1) * 100 as annual_return,
    stddevSamp(pct_change) * sqrt(252) as annual_volatility,
    avg(turnover_rate) as avg_turnover
FROM stock_daily
WHERE date >= '2024-01-01' AND date <= '2024-12-31'
GROUP BY symbol
ORDER BY annual_return DESC
LIMIT 20;
```

## 七、常见误区

### 误区一："用 MySQL/PostgreSQL 存行情数据够了"

对于几百只股票的日线数据，关系型数据库确实能用。但当规模增长到几千只股票、分钟级数据时，性能会急剧下降。**时序数据库的列式存储和压缩算法是为这种场景专门优化的**。

### 误区二："数据存 CSV/Parquet 文件就够了"

文件存储的问题：
- 跨标的查询需要逐文件扫描
- 没有索引，查询效率低
- 并发访问困难
- 数据一致性难以保证

文件适合**归档和离线分析**，但不适合**在线查询和服务**。

### 误区三："ClickHouse 适合所有场景"

ClickHouse 的劣势：
- **不擅长单行更新/删除**：这是 OLAP 数据库的特点
- **事务支持有限**：不适合需要强一致性的业务
- **运维复杂度**：比单机 PostgreSQL 更复杂

如果数据量小（< 100 万行）、查询简单，PostgreSQL + TimescaleDB 可能是更好的选择。

### 误区四："排序键不重要"

排序键决定了数据在磁盘上的物理存储顺序。选错排序键会导致：
- 查询性能下降 10-100 倍
- 压缩比降低
- 索引失效

**原则：把最常用的查询条件放在排序键的前面**。

## 小结与练习

### 小结

本课讲解了时序数据库在量化交易中的应用：

- 列式存储比行式存储在聚合查询上快 10-30 倍
- ClickHouse 的 MergeTree 引擎专为时序数据优化
- Schema 设计需要考虑分区策略、排序键和压缩
- 批量写入和分区裁剪是关键的性能优化手段
