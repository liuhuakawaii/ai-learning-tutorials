# 混合检索：向量 + 关键词的对比实验

> Stage 2 · Lesson 1 | 前置：Stage 1 完成 | 时长：50 分钟

你的 RAG 系统用纯向量检索跑了一段时间，用户反馈"搜型号搜不准"。比如输入"RTX 4090"，返回的都是关于"显卡性能"的泛泛文章，而不是具体参数。输入错误码"ERR-0x80070005"，结果完全不着边际。

这不是 embedding 模型的 bug，而是向量检索的固有边界——它把一切都映射成语义空间，精确匹配不是它的强项。

这节课我们通过实验来验证：纯向量检索、纯关键词检索、混合检索，三种方式在不同类型查询上的表现差异。

## 你要验证的假设

- 向量检索在自然语言查询上表现好，但在精确术语上表现差
- 关键词检索反过来：精确匹配强，语义理解弱
- 混合检索能在两类查询上都取得可接受的结果

## 2. 实现三种检索方式

```python
# retrieval_methods.py
from rank_bm25 import BM25Okapi
import jieba

# === 方式一：纯向量检索 ===
def vector_search(query: str, collection: str = "test_docs", top_k: int = 3):
    response = client.embeddings.create(
        model="text-embedding-3-small",
        input=query
    )
    query_vector = response.data[0].embedding

    results = milvus.search(
        collection_name=collection,
        data=[query_vector],
        limit=top_k,
        output_fields=["text", "source"]
    )
    return [(hit["entity"]["text"], hit["distance"]) for hit in results[0]]

# === 方式二：纯 BM25 关键词检索 ===
class BM25Retriever:
    def __init__(self, docs: list[dict]):
        self.docs = docs
        # jieba 分词后构建 BM25 索引
        tokenized = [list(jieba.cut(doc["text"])) for doc in docs]
        self.bm25 = BM25Okapi(tokenized)

    def search(self, query: str, top_k: int = 3):
        tokenized_query = list(jieba.cut(query))
        scores = self.bm25.get_scores(tokenized_query)
        top_indices = scores.argsort()[-top_k:][::-1]
        return [(self.docs[i]["text"], scores[i]) for i in top_indices]

# === 方式三：混合检索 (RRF 融合) ===
def hybrid_search(query: str, bm25_retriever: BM25Retriever,
                  collection: str = "test_docs", top_k: int = 3, k: int = 60):
    """Reciprocal Rank Fusion 融合"""
    # 两路检索各取 top_k * 2
    vector_results = vector_search(query, collection, top_k=top_k * 2)
    bm25_results = bm25_retriever.search(query, top_k=top_k * 2)

    # RRF 评分
    scores = {}
    for rank, (text, _) in enumerate(vector_results):
        scores[text] = scores.get(text, 0) + 1 / (k + rank + 1)
    for rank, (text, _) in enumerate(bm25_results):
        scores[text] = scores.get(text, 0) + 1 / (k + rank + 1)

    # 按融合分数排序
    sorted_results = sorted(scores.items(), key=lambda x: x[1], reverse=True)
    return sorted_results[:top_k]
```

RRF（Reciprocal Rank Fusion）的公式是 `1 / (k + rank)`，其中 k 通常取 60。它不关心原始分数是多少，只关心排名。这避免了不同检索方式分数不可比的问题。

## 4. 分析：为什么向量检索搞不定精确术语

```python
# 看看 embedding 向量在做什么
response = client.embeddings.create(
    model="text-embedding-3-small",
    input=["RTX 4090", "RTX 4070", "显卡"]
)

# 计算余弦相似度
import numpy as np

vectors = [np.array(item.embedding) for item in response.data]
for i in range(len(vectors)):
    for j in range(i+1, len(vectors)):
        sim = np.dot(vectors[i], vectors[j]) / (np.linalg.norm(vectors[i]) * np.linalg.norm(vectors[j]))
        print(f"sim({i},{j}): {sim:.4f}")
```

你会发现 "RTX 4090" 和 "RTX 4070" 的相似度非常高（>0.9），甚至和"显卡"也很接近。embedding 模型认为它们"差不多"，但用户搜的是具体型号参数。

## 5. RRF 融合权重调优

RRF 的 k 参数影响融合倾向：

```python
# k 越小，越重视排名靠前的结果
# k 越大，排名差异的影响越小

for k in [10, 30, 60, 100]:
    results = hybrid_search("RTX 4090 CUDA 核心数", bm25_retriever, k=k)
    print(f"k={k}: {[r[0][:30] for r in results]}")
```

实际生产中，还可以给两路检索加不同权重：

```python
# 加权 RRF
scores[text] = 0.3 * (1 / (k + rank + 1))  # 向量检索权重 30%
scores[text] += 0.7 * (1 / (k + rank + 1))  # 关键词检索权重 70%
```

权重比例取决于你的查询分布。如果大部分查询是自然语言，给向量检索更高权重；如果大量精确查询，给关键词检索更高权重。

### 练习一

```python
import math
from collections import Counter

class SimpleTFIDF:
    def __init__(self, docs: list[str]):
        self.docs = docs
        self.tokenized = [list(jieba.cut(doc)) for doc in docs]

        # 计算 IDF
        doc_count = len(docs)
        df = Counter()  # 包含每个词的文档数
        for tokens in self.tokenized:
            for token in set(tokens):
                df[token] += 1
        self.idf = {word: math.log(doc_count / (count + 1)) for word, count in df.items()}

    def search(self, query: str, top_k: int = 3):
        query_tokens = list(jieba.cut(query))
        scores = []

        for i, tokens in enumerate(self.tokenized):
            tf = Counter(tokens)
            score = sum(
                tf.get(word, 0) * self.idf.get(word, 0)
                for word in query_tokens
            )
            scores.append((i, score))

        scores.sort(key=lambda x: x[1], reverse=True)
        return [(self.docs[i], score) for i, score in scores[:top_k]]
```

### 练习二

一个三种方式都可能失败的查询："开不了机咋整"（口语化 + 错别字风格）

- 向量检索：可能匹配到"电脑无法开机"，但口语化表述可能偏离向量空间
- BM25："咋整"不会匹配到"排查步骤"，"开不了机"和"无法开机"分词后不同
- 混合检索：两路都弱，融合也救不了
