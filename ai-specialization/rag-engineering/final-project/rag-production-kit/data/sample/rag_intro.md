# RAG 技术简介

## 场景引入

大语言模型虽然强大，但存在知识截止日期和幻觉问题——它可能会编造不存在的事实。当你的业务需要基于最新、准确的内部文档回答用户问题时，单纯依赖 LLM 的参数知识远远不够。RAG 技术通过将外部知识检索与 LLM 生成相结合，让模型"先查资料再回答"，从根本上解决知识准确性和时效性问题。

## 什么是 RAG?

RAG (Retrieval-Augmented Generation) 是一种结合信息检索和文本生成的 AI 技术范式。
它通过从外部知识库中检索相关文档，然后将这些文档作为上下文提供给大语言模型（LLM），
从而生成更准确、更有依据的回答。

## RAG 的核心流程

RAG 系统通常包含三个主要阶段：

1. **索引阶段 (Indexing)**：将文档解析、分块、向量化后存储到向量数据库
2. **检索阶段 (Retrieval)**：根据用户查询，从向量数据库中检索相关文档
3. **生成阶段 (Generation)**：将检索到的文档与用户查询一起输入 LLM 生成答案

## RAG 的优势

- **减少幻觉**：基于真实文档生成，减少 LLM 编造信息的概率
- **知识可更新**：只需更新知识库，无需重新训练模型
- **可追溯性**：可以追溯答案来源，提高可信度
- **成本效益**：相比微调大模型，RAG 的实施成本更低

## 常见应用场景

- 企业知识库问答
- 智能客服系统
- 技术文档助手
- 法律/医疗领域问答

## 常见误区

- 认为 RAG 可以完全替代微调——RAG 擅长知识注入，微调擅长风格和能力适配，两者互补而非替代
- 忽略文档质量对 RAG 效果的决定性影响——垃圾文档检索出来只会干扰生成质量
- 把 RAG 当作万能方案，对于不需要外部知识的简单任务（如文本改写、格式转换），直接用 LLM 更高效

## 工程建议

- RAG 系统的文档应经过清洗和去重，低质量文档宁可不收录也不要污染检索结果
- 知识库应定期更新，设置文档的过期时间，避免用过时信息回答用户问题
- 对于准确性要求极高的场景（医疗、法律），RAG 输出必须附带来源引用，便于人工审核
