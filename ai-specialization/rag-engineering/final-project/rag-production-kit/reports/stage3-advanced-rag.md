# 阶段三报告：高级 RAG

## 场景引入

即使用了混合检索和重排序，RAG 系统在某些场景下仍然表现不佳：对于需要多步推理的问题，单次检索无法覆盖所有相关信息；对于模糊查询，检索结果噪音太多干扰生成质量。Self-RAG、GraphRAG、Agentic RAG 等高级模式应运而生，但它们各自适用于什么场景？复杂度和收益如何权衡？本阶段深入探索这些前沿架构。

## 常见误区

- Self-RAG 的反思判断全靠 LLM 自评，没有引入外部验证（如事实核查），导致"自我感觉良好"的错误被放行
- GraphRAG 在知识图谱构建不完整时效果反而不如 Naive RAG，不要在数据稀疏的场景强行使用
- Agentic RAG 的 Agent 循环没有设置退出条件，遇到无法回答的问题时陷入无限检索-生成循环

## 工程建议

- Self-RAG 的反思步骤应引入外部信号（如检索结果的相关性评分），而非完全依赖 LLM 自我判断
- GraphRAG 适用于实体关系密集的领域（法律、医疗），通用知识库场景优先用 Naive RAG + 混合检索
- Agentic RAG 必须设置最大推理轮次（建议 3-5 轮），并在每轮加入"是否已有足够信息回答"的显式判断
