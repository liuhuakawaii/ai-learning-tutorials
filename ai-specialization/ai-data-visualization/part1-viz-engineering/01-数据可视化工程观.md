# 01 - 数据可视化工程观

> 可视化不是"画图"，而是把数据翻译成人类视觉系统能快速理解的语言。

## 这节课解决什么问题

你接到一个需求："在管理后台加一个销售数据看板。" 产品经理给了你一张截图，上面有折线图、柱状图、饼图、数字卡片。看起来很简单——找个图表库，调几个 API，绑上数据就完事了。

但当你真正开始做，问题接踵而来：数据从哪来？后端返回的 JSON 结构和图表需要的格式对不上。折线图的 X 轴是时间，但后端返回的时间戳格式不统一。饼图的"其他"类别怎么处理？管理者想要"点击某个省份下钻到城市"，这个交互怎么实现？数据量大了之后页面明显卡顿，怎么优化？

一个看似简单的"加几个图表"，实际上涉及数据处理、交互设计、性能优化、响应式适配等多个工程问题。

## 可视化工程的三个层次

我们可以把可视化工程拆成三个层次，每个层次有清晰的职责边界：

```
表现层：图表组件、交互逻辑、动画、响应式、主题
        技术栈：ECharts / D3 / AntV / Recharts
─────────────────────────────────────────────────
数据处理层：数据聚合、过滤、异常值处理、格式转换
            技术栈：D3-array / Lodash / 自研
─────────────────────────────────────────────────
数据接入层：API 对接、WebSocket、缓存、增量更新
            技术栈：SWR / React Query / 自研
```

大部分初学者只关注表现层——"这个图表库怎么用"。但在生产环境中，数据处理层和数据接入层往往占据 60% 以上的工作量。

## 技术选型：不是选最好的，而是选最合适的

主流图表库各有侧重：

| 库 | 定位 | 适合场景 | 学习成本 |
|---|---|---|---|
| ECharts | 配置驱动，开箱即用 | 业务报表、Dashboard | 低 |
| D3.js | 底层绑定，完全自由 | 定制可视化、数据艺术 | 高 |
| AntV G2 | 语法驱动，声明式 | 数据探索、分析工具 | 中 |
| Recharts | React 原生，组件式 | React 项目快速集成 | 低 |

选型的关键不是"哪个功能最强"，而是：

1. **你的项目用什么框架**：React 项目优先 Recharts/AntV，Vue 项目优先 ECharts
2. **你需要多大的定制空间**：标准图表选 ECharts，非标准可视化选 D3
3. **团队的熟悉程度**：一个你熟悉的库比一个"更好"的库更实用

## 从需求到交付的完整流程

一个真实的可视化项目不是"拿到数据就画图"。完整流程是：

```
需求分析 → 数据源确认 → 数据处理 → 图表选型 → 组件开发 → 交互实现 → 性能优化 → 响应式适配
```

每一步都可能遇到卡点。比如数据源确认阶段，你可能发现后端接口返回的数据粒度不对——你要的是按天聚合，它返回的是按小时的原始数据。这时候你需要在前端做聚合，或者推动后端改接口。这类判断贯穿整个项目。

## 用 React + ECharts 搭建一个图表页面

下面是一个最小但完整的例子，展示如何在 React 中使用 ECharts 渲染一个带交互的折线图：

```tsx
import { useRef, useEffect } from 'react'
import * as echarts from 'echarts'

interface SalesData {
  date: string
  revenue: number
  orders: number
}

function SalesTrendChart({ data }: { data: SalesData[] }) {
  const chartRef = useRef<HTMLDivElement>(null)
  const chartInstance = useRef<echarts.ECharts | null>(null)

  useEffect(() => {
    if (!chartRef.current) return
    chartInstance.current = echarts.init(chartRef.current)

    const option: echarts.EChartsOption = {
      tooltip: { trigger: 'axis' },
      legend: { data: ['营收', '订单量'] },
      xAxis: { type: 'category', data: data.map(d => d.date) },
      yAxis: [
        { type: 'value', name: '营收(万)', position: 'left' },
        { type: 'value', name: '订单量', position: 'right' },
      ],
      series: [
        {
          name: '营收',
          type: 'line',
          data: data.map(d => d.revenue),
          smooth: true,
          areaStyle: { opacity: 0.1 },
        },
        {
          name: '订单量',
          type: 'line',
          yAxisIndex: 1,
          data: data.map(d => d.orders),
          smooth: true,
        },
      ],
    }

    chartInstance.current.setOption(option)

    const handleResize = () => chartInstance.current?.resize()
    window.addEventListener('resize', handleResize)
    return () => {
      window.removeEventListener('resize', handleResize)
      chartInstance.current?.dispose()
    }
  }, [data])

  return <div ref={chartRef} style={{ width: '100%', height: 400 }} />
}
```

几个工程细节值得注意：

- **双 Y 轴**：营收和订单量量纲不同，不能共用一个轴
- **resize 监听**：窗口大小变化时图表要自适应
- **dispose 清理**：组件卸载时销毁 ECharts 实例，避免内存泄漏
- **smooth: true**：折线平滑处理，视觉上更友好

## 可视化系统的常见坑

**坑 1：数据格式不匹配。** 后端返回 `{ timestamp: 1685500800 }` 而图表需要 `'2023-05-31'`。不要在渲染时每次转换，而是在数据接入层统一处理。

**坑 2：大数据量卡顿。** 一万条数据点绑到折线图上，浏览器要渲染一万个 SVG 节点。解决方案：数据采样（LTTB 算法）、Canvas 渲染、或虚拟滚动。

**坑 3：图表闪烁。** 数据更新时 ECharts 会重新渲染整个图表。用 `setOption` 的 `notMerge: false` 做增量更新，而不是每次销毁重建。

**坑 4：移动端适配。** PC 端的交互（hover、点击、缩放）在移动端全部失效。需要为触屏设备设计专门的交互方案。


**常见错误**：
- 忘记在 `useEffect` cleanup 中 `dispose` 图表实例，导致内存泄漏
- 没有监听 `resize` 事件，窗口变化后图表尺寸不更新
- 双 Y 轴只配了一个 `yAxis`，导致两个系列共用同一轴刻度

### 练习二

```ts
import { useState, useEffect, useCallback, useRef } from 'react'

function useChartData<T>(
  fetcher: () => Promise<T[]>,
  transformer: (raw: T[]) => any,
  options?: { refetchInterval?: number; cacheKey?: string }
) {
  const [data, setData] = useState<any>(null)
  const [loading, setLoading] = useState(true)
  const [error, setError] = useState<Error | null>(null)
  const cache = useRef<Map<string, any>>(new Map())

  const load = useCallback(async () => {
    const key = options?.cacheKey
    if (key && cache.current.has(key)) {
      setData(cache.current.get(key))
      setLoading(false)
      return
    }
    setLoading(true)
    setError(null)
    try {
      const raw = await fetcher()
      const result = transformer(raw)
      if (key) cache.current.set(key, result)
      setData(result)
    } catch (e) {
      setError(e as Error)
    } finally {
      setLoading(false)
    }
  }, [fetcher, transformer, options?.cacheKey])

  useEffect(() => {
    load()
    if (options?.refetchInterval) {
      const timer = setInterval(load, options.refetchInterval)
      return () => clearInterval(timer)
    }
  }, [load, options?.refetchInterval])

  return { data, loading, error, refetch: load }
}
```

**常见错误**：
- `fetcher` 和 `transformer` 没有用 `useCallback` 包裹，导致 `useEffect` 每次渲染都重新执行
- 缓存没有失效机制，数据更新后还是旧值
- `refetchInterval` 的 `setInterval` 没有在 cleanup 中清除
