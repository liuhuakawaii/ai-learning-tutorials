## 场景引入

你交付的 BI 平台功能越来越完善：对话式查询、数据探索、可视化看板、权限控制。但产品经理带来了一个坏消息：客户的日活数据一直在下降。

你很困惑——功能明明越来越好，为什么用户不用了？答案出乎意料：**不是 BI 平台不好用，而是用户不愿意离开他们的 CRM 系统**。

销售团队每天的工作都在 CRM 里：管理客户、跟进商机、更新订单。要看销售数据，他们需要打开另一个系统（BI 平台），登录、找到对应的报表、调整筛选条件——这个上下文切换的成本太高了。很多销售代表宁愿每周等一封邮件周报，也不愿意主动去 BI 平台看数据。

嵌入式分析要解决的就是这个问题：**把数据分析能力以组件的形式嵌入到业务系统中，让用户在自己熟悉的工作环境里直接看到数据洞察**。

Gartner 的报告显示，到 2025 年，超过 60% 的数据分析消费发生在 BI 平台之外——嵌入在 CRM、ERP、OA 等业务系统中。这不只是一个技术趋势，而是数据分析产品的必然演进方向。

## 核心概念

### 一、嵌入式分析的产品形态

嵌入式分析有三种实现方式，各有明确的适用边界：

```
嵌入式分析三种形态
┌─────────────────────────────────────────────────────────┐
│                                                         │
│  ┌─────────────────────────────────────────────┐        │
│  │  形态 1: iframe 嵌入                          │        │
│  │                                               │        │
│  │  宿主页面 ┌─────────────────────────────┐    │        │
│  │           │  <iframe src="bi.com/embed">│    │        │
│  │           │                             │    │        │
│  │           │  BI 平台的完整界面            │    │        │
│  │           │  (独立运行，互不干扰)         │    │        │
│  │           └─────────────────────────────┘    │        │
│  │  优点: 隔离性好、部署简单、升级独立            │        │
│  │  缺点: 交互割裂、样式难统一、SEO 不友好        │        │
│  └─────────────────────────────────────────────┘        │
│                                                         │
│  ┌─────────────────────────────────────────────┐        │
│  │  形态 2: SDK 组件嵌入                         │        │
│  │                                               │        │
│  │  宿主页面 ┌─────────────────────────────┐    │        │
│  │           │  import { Chart } from 'bi-sdk'│   │        │
│  │           │  <Chart query="sales" />       │   │        │
│  │           │                             │    │        │
│  │           │  原生渲染在宿主 DOM 中         │    │        │
│  │           └─────────────────────────────┘    │        │
│  │  优点: 体验一致、深度集成、可编程              │        │
│  │  缺点: 版本耦合、需适配宿主技术栈              │        │
│  └─────────────────────────────────────────────┘        │
│                                                         │
│  ┌─────────────────────────────────────────────┐        │
│  │  形态 3: API + 自定义渲染                     │        │
│  │                                               │        │
│  │  宿主应用 → 调用 BI API → 获取数据            │        │
│  │  宿主应用 → 自行渲染图表                      │        │
│  │                                               │        │
│  │  优点: 完全控制、无前端依赖                    │        │
│  │  缺点: 开发量大、需自行实现可视化              │        │
│  └─────────────────────────────────────────────┘        │
└─────────────────────────────────────────────────────────┘
```

**选择决策树**：

- 宿主系统技术栈未知，或需要快速上线 → **iframe**
- 宿主系统是 React/Vue，需要深度集成 → **SDK**
- 只需要数据，不需要 BI 的可视化能力 → **API**

这三种形态不是互斥的。很多成熟的嵌入式分析产品同时提供三种方式，让客户根据自身情况选择。

### 二、白标与品牌定制

嵌入式分析必须"看起来像"宿主系统的一部分，而不是一个突兀的外挂。白标（White Label）的核心是让分析组件的品牌可定制：

```
品牌定制维度
┌──────────────────────────────────────────────────────┐
│  视觉层                                               │
│  ├── 主题色: primaryColor, backgroundColor            │
│  ├── 字体: fontFamily, fontSize                       │
│  ├── 圆角: borderRadius                               │
│  └── 阴影: boxShadow                                  │
│                                                       │
│  布局层                                               │
│  ├── 组件尺寸: 宽高、最小/最大尺寸                     │
│  ├── 内边距: padding                                  │
│  └── 响应式断点                                       │
│                                                       │
│  品牌层                                               │
│  ├── Logo: 替换为客户的 Logo                           │
│  ├── 水印: 移除或替换                                  │
│  └── 页脚: 自定义版权信息                              │
│                                                       │
│  交互层                                               │
│  ├── 语言: i18n 支持                                  │
│  ├── 日期格式: MM/DD/YYYY vs YYYY-MM-DD               │
│  └── 数字格式: 千分位、货币符号                        │
└──────────────────────────────────────────────────────┘
```

实现方式是**主题令牌（Design Token）**：把所有可定制的视觉属性抽象为一组键值对，通过配置注入。宿主系统传入自己的主题令牌，分析组件用这些令牌渲染。

### 三、安全沙箱与跨域策略

嵌入式分析面临的核心安全挑战：**如何在宿主页面中运行第三方内容，同时防止恶意访问？**

iframe 天然提供了进程级隔离，但仍需防范：

1. **点击劫持（Clickjacking）**：攻击者用透明 iframe 覆盖在诱骗按钮上。防御：`X-Frame-Options` + `Content-Security-Policy` 的 `frame-ancestors` 指令
2. **数据泄露**：嵌入的分析组件包含敏感数据，不应被宿主页面的 JavaScript 直接访问。防御：`sandbox` 属性限制 iframe 能力
3. **令牌安全**：嵌入式分析的认证令牌不应暴露在 URL 中（会被浏览器历史记录和 Referer 头泄露）。防御：使用 postMessage 传递令牌

```
安全策略分层
┌───────────────────────────────────────────────────────┐
│  传输层: HTTPS only, HSTS                              │
│  认证层: 短期令牌 (JWT, 有效期 15 分钟)                  │
│  授权层: 令牌中编码允许访问的数据范围                     │
│  沙箱层: iframe sandbox + CSP                          │
│  通信层: postMessage + origin 校验                     │
└───────────────────────────────────────────────────────┘
```

### 四、事件通信与状态同步

iframe 嵌入后，宿主页面和嵌入内容需要双向通信。浏览器原生的 `postMessage` 是唯一安全的跨域通信机制：

```
事件通信流程
┌────────────────┐                    ┌────────────────┐
│   宿主页面      │                    │  BI 嵌入组件    │
│                │                    │                │
│  用户选择日期   │ ── postMessage ──→ │  接收筛选条件   │
│  2025-03-01    │    {type:"filter", │  刷新图表数据   │
│                │     date:"2025-    │                │
│                │     03-01"}        │  数据加载完成   │
│  更新 URL 参数  │ ←─ postMessage ── │  {type:"ready",│
│                │    }               │   rows:1234}   │
└────────────────┘                    └────────────────┘
```

**关键设计原则**：

1. **单向数据流**：宿主 → 嵌入组件传递筛选条件，嵌入组件 → 宿主传递状态变化
2. **Origin 校验**：接收消息时必须校验 `event.origin`，防止恶意页面注入消息
3. **消息队列**：如果嵌入组件还未加载完成，宿主发送的消息会丢失。需要在嵌入组件内实现消息队列，加载完成后批量处理
4. **状态序列化**：postMessage 只能传递可序列化的数据（JSON），函数、DOM 节点等不能传递

### 五、多租户架构设计

嵌入式分析通常是 to B 产品，需要支持多个客户（租户）的数据隔离：

```
多租户数据隔离方案
┌───────────────────────────────────────────────────────┐
│  方案 A: 独立数据库 (每租户一个库)                        │
│  隔离性: ★★★★★  成本: ★★★★★  运维: ★★★★★            │
│  适用: 金融、医疗等强合规行业                             │
├───────────────────────────────────────────────────────┤
│  方案 B: 共享数据库, 独立 Schema (每租户一个 Schema)      │
│  隔离性: ★★★★   成本: ★★★    运维: ★★★★              │
│  适用: 中型企业客户                                     │
├───────────────────────────────────────────────────────┤
│  方案 C: 共享数据库, 共享 Schema (tenant_id 字段隔离)     │
│  隔离性: ★★★    成本: ★★     运维: ★★                 │
│  适用: SaaS 产品, 大量小客户                             │
└───────────────────────────────────────────────────────┘
```

**推荐策略**：大客户用方案 A 或 B（独立部署更安全），小客户用方案 C（共享降低成本）。在查询层自动注入 `tenant_id` 过滤条件，确保租户之间数据不可见。

### sdk/message-bus.py

```python
"""postMessage 通信层：安全的跨域消息传递。"""

import json
import time
from dataclasses import dataclass, field
from typing import Any, Callable, Optional


@dataclass
class Message:
    type: str
    payload: dict
    source: str
    timestamp: float = field(default_factory=time.time)


class MessageBus:
    """封装 postMessage 通信，提供类型安全的消息收发。"""

    def __init__(self, target_origin: str, source_id: str):
        self.target_origin = target_origin
        self.source_id = source_id
        self._handlers: dict[str, list[Callable]] = {}
        self._pending_queue: list[Message] = []
        self._ready = False

    def on(self, message_type: str, handler: Callable) -> None:
        if message_type not in self._handlers:
            self._handlers[message_type] = []
        self._handlers[message_type].append(handler)

    def send(self, target_window: Any, message_type: str, payload: dict) -> None:
        message = Message(type=message_type, payload=payload, source=self.source_id)
        if not self._ready:
            self._pending_queue.append(message)
            return
        target_window.postMessage(json.dumps({
            "type": message.type,
            "payload": message.payload,
            "source": message.source,
            "timestamp": message.timestamp,
        }), self.target_origin)

    def flush_queue(self, target_window: Any) -> None:
        for msg in self._pending_queue:
            target_window.postMessage(json.dumps({
                "type": msg.type,
                "payload": msg.payload,
                "source": msg.source,
            }), self.target_origin)
        self._pending_queue.clear()

    def mark_ready(self) -> None:
        self._ready = True

    def handle_event(self, event: Any) -> None:
        if not self._validate_origin(event.origin):
            return
        try:
            data = json.loads(event.data)
        except (json.JSONDecodeError, TypeError):
            return
        msg_type = data.get("type")
        if msg_type in self._handlers:
            for handler in self._handlers[msg_type]:
                handler(Message(type=msg_type, payload=data.get("payload", {}), source=data.get("source", "")))

    def _validate_origin(self, origin: str) -> bool:
        return origin == self.target_origin
```

"""主题令牌系统：支持白标品牌定制。"""

from dataclasses import dataclass, field
from typing import Optional


@dataclass
class ThemeTokens:
    primary_color: str = "#4f46e5"
    background_color: str = "#ffffff"
    text_color: str = "#1f2937"
    border_color: str = "#e5e7eb"
    font_family: str = "system-ui, -apple-system, sans-serif"
    font_size_base: str = "14px"
    border_radius: str = "8px"
    logo_url: Optional[str] = None
    watermark_text: Optional[str] = None

    def to_css_vars(self) -> dict[str, str]:
        return {
            "--embed-primary": self.primary_color,
            "--embed-bg": self.background_color,
            "--embed-text": self.text_color,
            "--embed-border": self.border_color,
            "--embed-font": self.font_family,
            "--embed-font-size": self.font_size_base,
            "--embed-radius": self.border_radius,
        }

    def to_css_string(self) -> str:
        return "\n".join(f"  {k}: {v};" for k, v in self.to_css_vars().items())

    @classmethod
    def from_dict(cls, data: dict) -> "ThemeTokens":
        valid_fields = {f.name for f in cls.__dataclass_fields__.values()}
        return cls(**{k: v for k, v in data.items() if k in valid_fields and v is not None})


DEFAULT_THEME = ThemeTokens()

### sdk/embed_client.py

```python
"""嵌入式分析 SDK 客户端：支持 iframe 和组件两种嵌入方式。"""

import json
import time
from dataclasses import dataclass
from typing import Optional

from message_bus import MessageBus
from theme import ThemeTokens


@dataclass
class EmbedConfig:
    dashboard_id: str
    base_url: str
    auth_token: str
    theme: ThemeTokens = ThemeTokens()
    filters: dict = None
    width: str = "100%"
    height: str = "600px"

    def __post_init__(self):
        if self.filters is None:
            self.filters = {}


class EmbedClient:
    """嵌入式分析客户端，管理 iframe 生命周期和通信。"""

    def __init__(self, config: EmbedConfig):
        self.config = config
        self.bus = MessageBus(target_origin=config.base_url, source_id="host")
        self._iframe = None
        self._ready = False
        self._on_ready_callbacks = []
        self._on_error_callbacks = []

    def create_iframe(self) -> str:
        embed_url = self._build_embed_url()
        return (
            f'<iframe '
            f'src="{embed_url}" '
            f'width="{self.config.width}" '
            f'height="{self.config.height}" '
            f'frameborder="0" '
            f'sandbox="allow-scripts allow-same-origin allow-popups" '
            f'style="border: none; border-radius: {self.config.theme.border_radius};" '
            f'></iframe>'
        )

    def _build_embed_url(self) -> str:
        params = {
            "dashboard": self.config.dashboard_id,
            "token": self.config.auth_token,
            "theme": json.dumps(self.config.theme.to_css_vars()),
        }
        if self.config.filters:
            params["filters"] = json.dumps(self.config.filters)
        query = "&".join(f"{k}={v}" for k, v in params.items())
        return f"{self.config.base_url}/embed?{query}"

    def set_filters(self, filters: dict) -> None:
        self.config.filters.update(filters)
        if self._iframe:
            self.bus.send(self._iframe, "filter", filters)

    def on_ready(self, callback) -> None:
        self._on_ready_callbacks.append(callback)
        if self._ready:
            callback()

    def on_error(self, callback) -> None:
        self._on_error_callbacks.append(callback)

    def destroy(self) -> None:
        if self._iframe:
            self._iframe = None
            self._ready = False

    def _handle_ready(self, message) -> None:
        self._ready = True
        self.bus.mark_ready()
        self.bus.flush_queue(self._iframe)
        for cb in self._on_ready_callbacks:
            cb(message.payload)


def create_embed_html(config: EmbedConfig) -> str:
    client = EmbedClient(config)
    iframe_html = client.create_iframe()
    return f"""<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <title>嵌入式分析</title>
  <style>
    :root {{
      {config.theme.to_css_string()}
    }}
    body {{ margin: 0; font-family: var(--embed-font); background: var(--embed-bg); }}
    .embed-container {{ padding: 16px; }}
  </style>
</head>
<body>
  <div class="embed-container">
    {iframe_html}
  </div>
</body>
</html>"""
```

### embed-app/index.html

```html
<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <title>嵌入式分析组件</title>
  <style>
    :root { --embed-primary: #4f46e5; --embed-bg: #fff; --embed-text: #1f2937; }
    * { margin: 0; padding: 0; box-sizing: border-box; }
    body { font-family: system-ui; background: var(--embed-bg); color: var(--embed-text); padding: 16px; }
    .header { display: flex; justify-content: space-between; align-items: center; margin-bottom: 12px; }
    .header h3 { font-size: 16px; }
    .chart-area { height: 300px; border: 1px solid #e5e7eb; border-radius: 8px; display: flex; align-items: center; justify-content: center; }
    .status { font-size: 12px; color: #6b7280; margin-top: 8px; }
  </style>
</head>
<body>
  <div class="header">
    <h3 id="title">销售趋势</h3>
    <span id="row-count"></span>
  </div>
  <div class="chart-area">
    <canvas id="chart" width="800" height="280"></canvas>
  </div>
  <div class="status" id="status">加载中...</div>

  <script>
    const params = new URLSearchParams(window.location.search);
    const allowedOrigin = window.location.origin;

    function postToHost(type, payload) {
      window.parent.postMessage(JSON.stringify({ type, payload, source: 'embed' }), allowedOrigin);
    }

    window.addEventListener('message', (event) => {
      if (event.origin !== allowedOrigin) return;
      try {
        const msg = JSON.parse(event.data);
        if (msg.type === 'filter') {
          document.getElementById('status').textContent = `筛选条件已更新: ${JSON.stringify(msg.payload)}`;
        }
      } catch (e) {}
    });

    function renderChart(data) {
      const canvas = document.getElementById('chart');
      const ctx = canvas.getContext('2d');
      ctx.clearRect(0, 0, canvas.width, canvas.height);
      if (!data.length) return;
      const values = data.map(d => d.value);
      const minV = Math.min(...values), maxV = Math.max(...values), range = maxV - minV || 1;
      ctx.strokeStyle = getComputedStyle(document.documentElement).getPropertyValue('--embed-primary').trim() || '#4f46e5';
      ctx.lineWidth = 2;
      ctx.beginPath();
      data.forEach((d, i) => {
        const x = (i / data.length) * canvas.width;
        const y = canvas.height - ((d.value - minV) / range) * (canvas.height - 20) - 10;
        i === 0 ? ctx.moveTo(x, y) : ctx.lineTo(x, y);
      });
      ctx.stroke();
    }

    const sampleData = Array.from({length: 30}, (_, i) => ({label: `Day ${i+1}`, value: Math.random() * 100 + 50}));
    renderChart(sampleData);
    document.getElementById('row-count').textContent = `${sampleData.length} 条数据`;
    document.getElementById('status').textContent = '就绪';
    postToHost('ready', { rows: sampleData.length, dashboard: params.get('dashboard') });
  </script>
</body>
</html>
```

## 常见误区

### 误区一：iframe 不安全，应该避免使用

很多开发者认为 iframe 是过时的、不安全的技术。实际上，iframe 是浏览器提供的最成熟的安全沙箱机制。配合 `sandbox` 属性、CSP 策略和 origin 校验，iframe 的安全性远高于直接在宿主页面中执行第三方 JavaScript。SDK 嵌入方式虽然体验更好，但如果 SDK 代码有漏洞，它能访问宿主页面的全部 DOM 和 JavaScript 上下文——风险反而更大。

### 误区二：嵌入式分析只是"换个地方展示图表"

嵌入式分析不是简单的 iframe 套一个 BI 页面。它需要考虑**上下文感知**：宿主系统的当前页面、选中的客户、正在进行的业务流程，都应该传递给分析组件，让数据展示与业务场景紧密结合。一个在 CRM 客户详情页嵌入的分析组件，应该自动展示该客户的分析数据，而不是让用户再手动选择一次。

### 误区三：多租户共享数据库就够了

共享数据库 + tenant_id 过滤是最常见的多租户方案，但它有一个致命隐患：**如果查询语句忘记加 tenant_id 条件，就会泄露其他租户的数据**。这不是假设——历史上多次出现因为 ORM 配置疏忽导致的数据泄露事件。

安全的做法是在查询层（而非业务层）自动注入 tenant_id：用数据库的 Row-Level Security（RLS）策略，或在 ORM 的全局 scope 中强制添加过滤条件。让"租户隔离"成为基础设施层的保证，而不是依赖每个开发者记住写 WHERE 条件。

### 误区四：主题定制就是改个颜色

白标不是改个主题色就完事了。真实的嵌入场景中，客户会要求：把 Logo 换成我们的、把字体换成我们的品牌字体、把日期格式改成我们的习惯、把"销售"改成"营收"（术语定制）、甚至把整个布局结构调整一下。

如果这些定制都需要改代码，嵌入式分析就变成了项目制交付，无法规模化。正确的做法是设计一套完整的**主题令牌 + 配置系统**，所有可定制的维度都通过配置驱动，不需要改代码。

## 小结与练习

### 小结

1. **三种嵌入形态**：iframe（隔离好、部署快）、SDK（体验好、深度集成）、API（完全控制），根据场景选择
2. **白标与品牌定制**：通过主题令牌系统实现视觉、布局、品牌、交互四个维度的可配置化
3. **安全沙箱**：iframe sandbox + CSP + origin 校验 + 短期令牌，四层防护保障嵌入安全
4. **事件通信**：postMessage 是唯一安全的跨域通信机制，需要实现消息队列处理加载时序问题
5. **多租户架构**：大客户独立部署，小客户共享 Schema + tenant_id 隔离，用 RLS 确保数据安全

#### 练习一：实现 iframe 安全令牌

## 参考答案

### 练习一

**思路**：JWT 令牌在服务端生成，包含租户信息和权限范围。客户端拿到令牌后拼入嵌入 URL。服务端在 iframe 加载时验证令牌有效性和权限范围。

**答案**：

```python
import jwt
import time
from dataclasses import dataclass


@dataclass
class EmbedToken:
    tenant_id: str
    dashboards: list[str]
    expires_in: int = 900
    filters: dict = None


class TokenService:
    def __init__(self, secret_key: str, algorithm: str = "HS256"):
        self.secret_key = secret_key
        self.algorithm = algorithm

    def generate_token(self, config: EmbedToken) -> str:
        now = int(time.time())
        payload = {
            "sub": config.tenant_id,
            "dashboards": config.dashboards,
            "iat": now,
            "exp": now + config.expires_in,
            "type": "embed",
        }
        if config.filters:
            payload["allowed_filters"] = config.filters
        return jwt.encode(payload, self.secret_key, algorithm=self.algorithm)

    def verify_token(self, token: str, dashboard_id: str) -> dict:
        try:
            payload = jwt.decode(token, self.secret_key, algorithms=[self.algorithm])
        except jwt.ExpiredSignatureError:
            raise ValueError("令牌已过期")
        except jwt.InvalidTokenError:
            raise ValueError("令牌无效")

        if dashboard_id not in payload.get("dashboards", []):
            raise ValueError(f"无权访问看板: {dashboard_id}")

        return payload


service = TokenService(secret_key="your-secret-key-here")
token = service.generate_token(EmbedToken(
    tenant_id="tenant-001",
    dashboards=["sales-trend", "customer-analysis"],
    expires_in=900,
))
print(f"嵌入令牌: {token[:50]}...")

decoded = service.verify_token(token, "sales-trend")
print(f"租户: {decoded['sub']}, 可用看板: {decoded['dashboards']}")
```

**要点**：
- 令牌有效期设为 15 分钟，减少泄露后的风险窗口
- dashboards 字段限制了令牌只能访问指定的看板
- 过期和无效的令牌需要分别处理，给用户明确的错误提示

### 练习二

**思路**：定义消息类型枚举和消息结构，实现一个 MessageBus 类管理消息收发。在嵌入组件端实现消息队列，加载完成后批量处理。

**答案**：

```python
import json
import time
from enum import Enum
from typing import Any, Callable
from dataclasses import dataclass, field


class MessageType(str, Enum):
    FILTER_UPDATE = "filter_update"
    DATA_LOADING = "data_loading"
    DATA_READY = "data_ready"
    ERROR = "error"
    READY = "ready"


@dataclass
class TypedMessage:
    type: MessageType
    payload: dict
    source: str
    request_id: str = ""
    timestamp: float = field(default_factory=time.time)


class TypedMessageBus:
    def __init__(self, allowed_origin: str, source_id: str):
        self.allowed_origin = allowed_origin
        self.source_id = source_id
        self._handlers: dict[MessageType, list[Callable]] = {}
        self._queue: list[TypedMessage] = []
        self._ready = False
        self._request_counter = 0

    def on(self, msg_type: MessageType, handler: Callable) -> None:
        if msg_type not in self._handlers:
            self._handlers[msg_type] = []
        self._handlers[msg_type].append(handler)

    def send(self, target: Any, msg_type: MessageType, payload: dict) -> str:
        self._request_counter += 1
        request_id = f"req-{self._request_counter}"
        message = TypedMessage(type=msg_type, payload=payload, source=self.source_id, request_id=request_id)
        if not self._ready:
            self._queue.append(message)
            return request_id
        self._post(target, message)
        return request_id

    def mark_ready(self, target: Any) -> None:
        self._ready = True
        for msg in self._queue:
            self._post(target, msg)
        self._queue.clear()

    def handle_event(self, event: Any) -> None:
        if event.origin != self.allowed_origin:
            return
        try:
            data = json.loads(event.data)
            msg_type = MessageType(data["type"])
        except (json.JSONDecodeError, KeyError, ValueError):
            return
        message = TypedMessage(type=msg_type, payload=data.get("payload", {}), source=data.get("source", ""))
        for handler in self._handlers.get(msg_type, []):
            handler(message)

    def _post(self, target: Any, message: TypedMessage) -> None:
        target.postMessage(json.dumps({
            "type": message.type.value,
            "payload": message.payload,
            "source": message.source,
            "request_id": message.request_id,
        }), self.allowed_origin)


bus = TypedMessageBus(allowed_origin="https://bi.example.com", source_id="crm-host")
bus.on(MessageType.READY, lambda msg: print(f"嵌入组件就绪: {msg.payload}"))
bus.on(MessageType.DATA_READY, lambda msg: print(f"数据加载完成: {msg.payload}"))
bus.on(MessageType.ERROR, lambda msg: print(f"错误: {msg.payload}"))
```

**要点**：
- 消息类型用枚举约束，避免字符串拼写错误
- 每条消息带 request_id，支持请求-响应配对
- 未就绪时消息入队，就绪后批量发送，解决加载时序问题

### 练习三

**思路**：用 Python 装饰器拦截数据库查询函数，在执行前自动注入 tenant_id 过滤条件。通过上下文变量存储当前租户信息，避免在每个函数间传递 tenant_id。

**答案**：

```python
import re
import functools
from contextvars import ContextVar
from typing import Optional, Any

current_tenant: ContextVar[Optional[str]] = ContextVar("current_tenant", default=None)


class TenantContext:
    def __init__(self, tenant_id: str):
        self.tenant_id = tenant_id
        self._token = None

    def __enter__(self):
        self._token = current_tenant.set(self.tenant_id)
        return self

    def __exit__(self, *args):
        current_tenant.reset(self._token)


def tenant_aware(func):
    @functools.wraps(func)
    def wrapper(sql: str, params: tuple = (), *args, **kwargs):
        tenant_id = current_tenant.get()
        if not tenant_id:
            raise RuntimeError("未设置租户上下文，请使用 TenantContext")
        if "tenant_id" not in sql.lower():
            if "where" in sql.lower():
                sql = re.sub(r"(WHERE\s+)", f"\\1 tenant_id = %s AND ", sql, count=1, flags=re.IGNORECASE)
            else:
                sql = re.sub(r"(ORDER\s+BY|LIMIT|$)", f" WHERE tenant_id = %s \\1", sql, count=1, flags=re.IGNORECASE)
            params = (tenant_id,) + tuple(params)
        return func(sql, params, *args, **kwargs)
    return wrapper


@tenant_aware
def execute_query(sql: str, params: tuple = ()) -> list[dict]:
    print(f"执行 SQL: {sql}")
    print(f"参数: {params}")
    return [{"result": "ok"}]


with TenantContext("tenant-001"):
    execute_query("SELECT * FROM orders WHERE amount > 100 ORDER BY date")
    execute_query("SELECT COUNT(*) FROM orders")

try:
    execute_query("SELECT * FROM orders")
except RuntimeError as e:
    print(f"预期错误: {e}")
```

**要点**：
- 用 ContextVar 存储当前租户，支持异步场景
- 装饰器自动在 WHERE 子句前注入 tenant_id 条件
- 如果 SQL 已包含 tenant_id 条件则不重复注入
- 没有设置租户上下文时直接报错，防止数据泄露
