## 场景引入

你正在开发一个企业级 BI 平台。客户 A 的订单数据在 MySQL，用户行为日志在 ClickHouse，财务数据在 PostgreSQL，而第三方物流数据只能通过 REST API 获取。产品经理要求：用户在看板上拖拽一个"订单分析"组件时，系统自动从 MySQL 拉取订单明细，从 ClickHouse 关联用户行为路径，从 API 获取物流状态——最终在一张图表上呈现。

如果你为每种数据源各写一套查询逻辑，代码会迅速膨胀：MySQL 用 `GROUP_CONCAT`，PostgreSQL 用 `STRING_AGG`，ClickHouse 用 `groupArray`；MySQL 的分页是 `LIMIT offset, count`，PostgreSQL 是 `LIMIT count OFFSET offset`；日期函数、类型转换、甚至引号规则都不一样。

本节课要解决的核心问题：**如何设计一个统一数据访问层，让上层业务代码不需要知道底层数据源的差异？**

## 学习目标

## 核心概念

### 一、多数据源接入的挑战

在理想世界里，所有数据库都说标准 SQL，所有 API 都返回相同格式的数据。现实远非如此：

```
挑战全景图
┌─────────────────────────────────────────────────────┐
│                   业务层 (看板/报表)                   │
│         "给我最近 30 天的订单转化率趋势"                │
└──────────────────────┬──────────────────────────────┘
                       │ 统一查询语言?
                       ▼
┌──────────────────────────────────────────────────────┐
│                  差异地狱 (Reality)                    │
│                                                      │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌─────────┐ │
│  │  MySQL   │ │PostgreSQL│ │ClickHouse│ │ REST API│ │
│  ├──────────┤ ├──────────┤ ├──────────┤ ├─────────┤ │
│  │GROUP_CONCAT│ │STRING_AGG│ │groupArray│ │ JSON    │ │
│  │LIMIT x,y │ │LIMIT x   │ │LIMIT x   │ │ 无SQL   │ │
│  │  OFFSET y│ │  OFFSET y│ │  OFFSET y│ │         │ │
│  │AUTO_INCR │ │SERIAL    │ │  无      │ │  无     │ │
│  │datetime  │ │timestamp │ │DateTime  │ │ ISO8601 │ │
│  └──────────┘ └──────────┘ └──────────┘ └─────────┘ │
└──────────────────────────────────────────────────────┘
```

核心挑战可以归纳为五类：

**1. SQL 方言差异**：每种数据库都有自己的方言扩展。`IFNULL` vs `COALESCE`，`DATE_FORMAT` vs `TO_CHAR`，`LIMIT offset, count` vs `LIMIT count OFFSET offset`。这些差异看似微小，但在复杂查询中会成为维护噩梦。

**2. 类型系统差异**：MySQL 的 `TINYINT(1)` 在 JDBC 中映射为 `BOOLEAN`，但在 ClickHouse 中 `UInt8` 才是布尔值。PostgreSQL 的 `JSONB` 类型在 MySQL 中不存在。日期时区处理更是重灾区。

**3. 性能特征差异**：MySQL 适合点查和简单聚合，ClickHouse 擅长列式分析查询，PostgreSQL 支持复杂窗口函数。同一条查询在不同引擎上可能需要完全不同的优化策略。

**4. 连接管理差异**：连接池配置、超时设置、SSL 参数、最大连接数限制各不相同。HTTP API 更是无状态的，需要不同的连接策略。

**5. 元数据差异**：表结构、索引信息、约束定义的获取方式完全不同。`INFORMATION_SCHEMA` 在 MySQL 和 PostgreSQL 中行为不完全一致，ClickHouse 用 `system.tables`。

### 二、统一数据访问层架构

解决方案的核心思想是**抽象与适配**：在业务代码和实际数据源之间插入一个统一层，屏蔽底层差异。

```
统一数据访问层架构
┌─────────────────────────────────────────────────┐
│                  业务查询层                       │
│    SELECT region, SUM(amount) FROM orders        │
│    WHERE order_date >= '2025-01-01'              │
│    GROUP BY region                               │
└───────────────────────┬─────────────────────────┘
                        │ 统一查询对象 (UnifiedQuery)
                        ▼
┌─────────────────────────────────────────────────┐
│              统一数据访问层 (DAL)                  │
│                                                  │
│  ┌─────────────┐  ┌──────────────┐              │
│  │ 查询解析器   │  │  方言转换器   │              │
│  │ Parser      │→ │ Dialect      │              │
│  │             │  │ Translator   │              │
│  └─────────────┘  └──────┬───────┘              │
│                          │                       │
│  ┌───────────────────────┴──────────────────┐   │
│  │          数据源路由 (Router)               │   │
│  │  根据表名/数据源配置选择目标适配器           │   │
│  └────┬──────────┬──────────┬───────────┬───┘   │
│       │          │          │           │       │
│  ┌────▼───┐ ┌────▼───┐ ┌───▼────┐ ┌───▼────┐  │
│  │ MySQL  │ │  PG    │ │  CH   │ │  API  │  │
│  │Adapter │ │Adapter │ │Adapter│ │Adapter│  │
│  └────────┘ └────────┘ └───────┘ └───────┘  │
└─────────────────────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────┐
│              元数据注册中心                       │
│  表名 → 数据源映射、字段类型、权限、缓存策略       │
└─────────────────────────────────────────────────┘
```

这个架构有三个关键设计决策：

**决策一：查询用统一 DSL 还是透传 SQL？**

透传 SQL（直接把用户写的 SQL 传给后端）实现简单但失去了方言转换能力。统一 DSL（用对象描述查询意图）灵活性最高但学习成本大。实践中，大多数 BI 平台采用折中方案：上层用可视化构建 DSL，底层生成特定方言的 SQL。本课采用这种方式。

**决策二：适配器是同步还是异步？**

Node.js 生态中，数据库驱动几乎都是异步的（基于回调或 Promise）。API 调用天然异步。因此整个适配层应该是异步设计，返回 Promise 或 AsyncIterable。

**决策三：连接池是每数据源独立还是全局共享？**

每种数据库的连接池实现不同（MySQL 用 `mysql2` 内置池，PostgreSQL 用 `pg.Pool`，ClickHouse 用 HTTP 连接池），应该让每个适配器管理自己的连接池，统一层只负责生命周期管理。

### 三、数据源适配器模式

适配器模式是这个场景的经典解法。每个数据源实现一个统一接口，上层代码只依赖接口而非具体实现。

```
适配器接口契约
┌────────────────────────────────────────────┐
│          DataSourceAdapter (接口)           │
├────────────────────────────────────────────┤
│ + connect(config): Promise<void>           │
│ + disconnect(): Promise<void>              │
│ + execute(sql): Promise<QueryResult>       │
│ + getMetadata(table): Promise<TableMeta>   │
│ + listTables(): Promise<string[]>          │
│ + testConnection(): Promise<boolean>       │
│ + translateDialect(sql, from, to): string  │
└────────────────────────────────────────────┘
        ▲            ▲           ▲
        │            │           │
   ┌────┴───┐  ┌─────┴──┐  ┌────┴────┐
   │ MySQL  │  │Postgres│  │ClickHse │
   │Adapter │  │ Adapter│  │ Adapter │
   └────────┘  └────────┘  └─────────┘
```

接口方法的设计不是随意的，每个方法都对应一个真实的业务需求：

- `connect`：应用启动时初始化连接池，需要支持重连
- `execute`：核心能力，执行查询并返回统一格式的结果
- `getMetadata`：自助分析场景下，需要知道表有哪些字段、字段是什么类型
- `listTables`：数据源管理界面需要列出所有可用表
- `testConnection`：数据源配置页面的"测试连接"按钮
- `translateDialect`：当查询需要跨数据源执行时，转换 SQL 方言

### 四、SQL 方言差异处理

SQL 方言差异是多数据源最头疼的问题。处理策略有三种：

**策略一：最低公约法**——只使用所有数据库都支持的标准 SQL 语法。优点是简单，缺点是丢失了各数据库的高级特性。

**策略二：方言翻译器**——维护一套中间 SQL 表示，运行时翻译为目标方言。优点是灵活，缺点是翻译器的维护成本高。

**策略三：查询构建器**——不用原始 SQL，而是用程序化 API 构建查询。优点是完全可控，缺点是复杂查询的表达能力受限。

实践中，BI 平台通常组合使用策略二和策略三：简单查询用查询构建器，复杂查询走方言翻译器。

常见的方言差异点：

| 特性 | MySQL | PostgreSQL | ClickHouse |
|------|-------|-----------|------------|
| 字符串连接 | `CONCAT(a, b)` | `a \|\| b` 或 `CONCAT` | `concat(a, b)` |
| 当前时间 | `NOW()` | `NOW()` 或 `CURRENT_TIMESTAMP` | `now()` |
| 日期格式化 | `DATE_FORMAT(col, '%Y-%m')` | `TO_CHAR(col, 'YYYY-MM')` | `formatDateTime(col, '%Y-%m')` |
| 条件表达式 | `IF(cond, a, b)` | `CASE WHEN` | `if(cond, a, b)` |
| 分页 | `LIMIT offset, count` | `LIMIT count OFFSET offset` | `LIMIT count OFFSET offset` |
| 引号 | 反引号 `` ` `` | 双引号 `"` | 反引号 `` ` `` |
| 布尔类型 | `TINYINT(1)` | `BOOLEAN` | `UInt8` |
| NULL 排序 | NULL 视为最小值 | NULLS LAST 可配置 | NULL 视为最小值 |

### 五、数据联邦查询

当一个查询需要跨多个数据源时，就进入了数据联邦（Data Federation）的领域。比如：订单在 MySQL，用户画像在 ClickHouse，需要做"按用户年龄段统计订单金额"。

```
联邦查询执行流程
┌──────────────────────────────────────────────────┐
│  原始查询:                                         │
│  SELECT age_group, SUM(order_amount)              │
│  FROM orders JOIN user_profiles                   │
│  GROUP BY age_group                               │
└──────────────────────┬───────────────────────────┘
                       │ 查询拆分器
                       ▼
┌──────────────────────────────────────────────────┐
│  Step 1: 拆分为两个子查询                           │
│  ┌────────────────────┐  ┌──────────────────────┐│
│  │ MySQL:             │  │ ClickHouse:           ││
│  │ SELECT user_id,    │  │ SELECT user_id,       ││
│  │   order_amount     │  │   age_group           ││
│  │ FROM orders        │  │ FROM user_profiles    ││
│  └─────────┬──────────┘  └──────────┬────────────┘│
│            │                        │              │
│            ▼                        ▼              │
│  Step 2: 在内存中 JOIN                              │
│  ┌────────────────────────────────────────────┐   │
│  │ 联邦引擎: 按 user_id 做哈希 JOIN              │   │
│  │ 结果: { age_group, order_amount }            │   │
│  └────────────────────────────────────────────┘   │
│            │                                       │
│            ▼                                       │
│  Step 3: 聚合计算                                   │
│  SELECT age_group, SUM(order_amount)              │
│  FROM federated_result GROUP BY age_group         │
└──────────────────────────────────────────────────┘
```

联邦查询的关键挑战是性能：数据需要从多个源拉取到中间层再做关联，网络开销和内存占用都很大。优化手段包括：

- **谓词下推**：把 WHERE 条件尽可能推到各数据源执行，减少传输数据量
- **投影下推**：只 SELECT 需要的字段，不要 `SELECT *`
- **小表广播**：如果一侧数据量小，先拉到内存，另一侧在源端过滤后再关联
- **缓存中间结果**：相同的子查询结果可以缓存复用

### 六、元数据管理

元数据是统一层的"地图"——它记录了每张表在哪个数据源、有哪些字段、字段是什么类型、数据量多大、更新频率如何。

```
元数据模型
┌─────────────────────────────────────────┐
│            DataSource (数据源)            │
│  id, name, type, config, status          │
└────────────────┬────────────────────────┘
                 │ 1:N
┌────────────────▼────────────────────────┐
│            Table (表)                    │
│  id, source_id, name, schema,            │
│  row_count, last_synced                  │
└────────────────┬────────────────────────┘
                 │ 1:N
┌────────────────▼────────────────────────┐
│           Column (字段)                  │
│  id, table_id, name, type,              │
│  is_nullable, is_primary, comment        │
└─────────────────────────────────────────┘
```

元数据的获取方式：

- **主动发现**：连接数据源后，查询 `INFORMATION_SCHEMA` 或系统表，自动同步表结构
- **被动注册**：用户手动配置表和字段的映射关系（用于 API 数据源）
- **增量同步**：定时检查表结构变化（新增字段、类型变更），触发告警

### 2. MySQL 适配器

```typescript
// src/adapters/mysql.adapter.ts
import mysql from 'mysql2/promise';
import { DataSourceAdapter, QueryResult, TableMeta, DataSourceConfig } from './base';

export class MysqlAdapter extends DataSourceAdapter {
  readonly sourceId: string;
  readonly sourceType = 'mysql';
  private pool: mysql.Pool | null = null;
  private config: DataSourceConfig;

  constructor(config: DataSourceConfig) {
    super();
    this.sourceId = config.id;
    this.config = config;
  }

  async connect(): Promise<void> {
    const cfg = this.config.config as {
      host: string; port: number; database: string;
      user: string; password: string; connectionLimit?: number;
    };
    this.pool = mysql.createPool({
      host: cfg.host,
      port: cfg.port || 3306,
      database: cfg.database,
      user: cfg.user,
      password: cfg.password,
      connectionLimit: cfg.connectionLimit || 10,
      waitForConnections: true,
      queueLimit: 0,
      enableKeepAlive: true,
      keepAliveInitialDelay: 10000,
    });
    await this.pool.getConnection();
  }

  async disconnect(): Promise<void> {
    if (this.pool) {
      await this.pool.end();
      this.pool = null;
    }
  }

  async execute(sql: string, params?: unknown[]): Promise<QueryResult> {
    if (!this.pool) throw new Error(`数据源 ${this.sourceId} 未连接`);

    const start = performance.now();
    const [rows, fields] = await this.pool.execute(sql, params);
    const elapsed = performance.now() - start;

    const columns = fields?.map((f: mysql.FieldPacket) => f.name) ?? [];
    const rowArray = Array.isArray(rows) ? rows : [];

    return {
      columns,
      rows: rowArray as Record<string, unknown>[],
      rowCount: rowArray.length,
      executionTimeMs: Math.round(elapsed),
      sourceId: this.sourceId,
    };
  }

  async listTables(): Promise<string[]> {
    const cfg = this.config.config as { database: string };
    const result = await this.execute(
      `SELECT TABLE_NAME FROM INFORMATION_SCHEMA.TABLES
       WHERE TABLE_SCHEMA = ? AND TABLE_TYPE = 'BASE TABLE'`,
      [cfg.database]
    );
    return result.rows.map((r) => r.TABLE_NAME as string);
  }

  async getTableMeta(tableName: string): Promise<TableMeta> {
    const cfg = this.config.config as { database: string };
    const result = await this.execute(
      `SELECT COLUMN_NAME, DATA_TYPE, IS_NULLABLE, COLUMN_KEY, COLUMN_COMMENT
       FROM INFORMATION_SCHEMA.COLUMNS
       WHERE TABLE_SCHEMA = ? AND TABLE_NAME = ?
       ORDER BY ORDINAL_POSITION`,
      [cfg.database, tableName]
    );

    const columns = result.rows.map((row) => ({
      name: row.COLUMN_NAME as string,
      type: row.DATA_TYPE as string,
      nullable: (row.IS_NULLABLE as string) === 'YES',
      isPrimaryKey: (row.COLUMN_KEY as string) === 'PRI',
      comment: (row.COLUMN_COMMENT as string) || undefined,
    }));

    const countResult = await this.execute(
      `SELECT COUNT(*) as cnt FROM \`${tableName}\``
    );

    return {
      tableName,
      columns,
      rowCount: Number(countResult.rows[0]?.cnt ?? 0),
      lastSynced: new Date(),
    };
  }

  async testConnection(): Promise<boolean> {
    try {
      const result = await this.execute('SELECT 1 as ok');
      return result.rows[0]?.ok === 1;
    } catch {
      return false;
    }
  }
}
```

### 3. PostgreSQL 适配器

```typescript
// src/adapters/postgres.adapter.ts
import { Pool } from 'pg';
import { DataSourceAdapter, QueryResult, TableMeta, DataSourceConfig } from './base';

export class PostgresAdapter extends DataSourceAdapter {
  readonly sourceId: string;
  readonly sourceType = 'postgres';
  private pool: Pool | null = null;
  private config: DataSourceConfig;

  constructor(config: DataSourceConfig) {
    super();
    this.sourceId = config.id;
    this.config = config;
  }

  async connect(): Promise<void> {
    const cfg = this.config.config as {
      host: string; port: number; database: string;
      user: string; password: string; max?: number;
    };
    this.pool = new Pool({
      host: cfg.host,
      port: cfg.port || 5432,
      database: cfg.database,
      user: cfg.user,
      password: cfg.password,
      max: cfg.max || 10,
      idleTimeoutMillis: 30000,
      connectionTimeoutMillis: 5000,
    });
    await this.pool.connect();
  }

  async disconnect(): Promise<void> {
    if (this.pool) {
      await this.pool.end();
      this.pool = null;
    }
  }

  async execute(sql: string, params?: unknown[]): Promise<QueryResult> {
    if (!this.pool) throw new Error(`数据源 ${this.sourceId} 未连接`);

    const start = performance.now();
    const pgResult = await this.pool.query(sql, params);
    const elapsed = performance.now() - start;

    const columns = pgResult.fields.map((f) => f.name);

    return {
      columns,
      rows: pgResult.rows,
      rowCount: pgResult.rowCount ?? pgResult.rows.length,
      executionTimeMs: Math.round(elapsed),
      sourceId: this.sourceId,
    };
  }

  async listTables(): Promise<string[]> {
    const result = await this.execute(
      `SELECT tablename FROM pg_tables
       WHERE schemaname = 'public'`
    );
    return result.rows.map((r) => r.tablename as string);
  }

  async getTableMeta(tableName: string): Promise<TableMeta> {
    const colResult = await this.execute(
      `SELECT c.column_name, c.data_type, c.is_nullable,
              CASE WHEN pk.column_name IS NOT NULL THEN true ELSE false END as is_primary,
              pgd.description as column_comment
       FROM information_schema.columns c
       LEFT JOIN (
         SELECT ku.column_name
         FROM information_schema.table_constraints tc
         JOIN information_schema.key_column_usage ku
           ON tc.constraint_name = ku.constraint_name
         WHERE tc.table_name = $1 AND tc.constraint_type = 'PRIMARY KEY'
       ) pk ON c.column_name = pk.column_name
       LEFT JOIN pg_catalog.pg_statio_all_tables st
         ON st.relname = c.table_name AND st.schemaname = c.table_schema
       LEFT JOIN pg_catalog.pg_description pgd
         ON pgd.objoid = st.relid AND pgd.objsubid = c.ordinal_position
       WHERE c.table_name = $1 AND c.table_schema = 'public'
       ORDER BY c.ordinal_position`,
      [tableName]
    );

    const columns = colResult.rows.map((row) => ({
      name: row.column_name as string,
      type: row.data_type as string,
      nullable: (row.is_nullable as string) === 'YES',
      isPrimaryKey: row.is_primary as boolean,
      comment: (row.column_comment as string) || undefined,
    }));

    const countResult = await this.execute(
      `SELECT COUNT(*) as cnt FROM "${tableName}"`
    );

    return {
      tableName,
      columns,
      rowCount: Number(countResult.rows[0]?.cnt ?? 0),
      lastSynced: new Date(),
    };
  }

  async testConnection(): Promise<boolean> {
    try {
      const result = await this.execute('SELECT 1 as ok');
      return result.rows[0]?.ok === 1;
    } catch {
      return false;
    }
  }
}
```

### 4. CSV 文件适配器

```typescript
// src/adapters/csv.adapter.ts
import fs from 'node:fs';
import path from 'node:path';
import { DataSourceAdapter, QueryResult, TableMeta, ColumnMeta, DataSourceConfig } from './base';

interface CsvRow {
  [key: string]: string;
}

export class CsvAdapter extends DataSourceAdapter {
  readonly sourceId: string;
  readonly sourceType = 'csv';
  private dataDir: string;
  private tableCache = new Map<string, CsvRow[]>();

  constructor(config: DataSourceConfig) {
    super();
    this.sourceId = config.id;
    this.dataDir = config.config.dataDir as string;
  }

  async connect(): Promise<void> {
    if (!fs.existsSync(this.dataDir)) {
      throw new Error(`CSV 数据目录不存在: ${this.dataDir}`);
    }
    await this.loadAllFiles();
  }

  async disconnect(): Promise<void> {
    this.tableCache.clear();
  }

  private async loadAllFiles(): Promise<void> {
    const files = fs.readdirSync(this.dataDir)
      .filter((f) => f.endsWith('.csv'));

    for (const file of files) {
      const tableName = path.basename(file, '.csv');
      const content = fs.readFileSync(path.join(this.dataDir, file), 'utf-8');
      const lines = content.trim().split('\n');
      if (lines.length === 0) continue;

      const headers = lines[0].split(',').map((h) => h.trim().replace(/^"|"$/g, ''));
      const rows: CsvRow[] = [];

      for (let i = 1; i < lines.length; i++) {
        const values = lines[i].split(',').map((v) => v.trim().replace(/^"|"$/g, ''));
        const row: CsvRow = {};
        headers.forEach((h, idx) => {
          row[h] = values[idx] ?? '';
        });
        rows.push(row);
      }

      this.tableCache.set(tableName, rows);
    }
  }

  async execute(sql: string): Promise<QueryResult> {
    const start = performance.now();
    const parsed = this.parseSimpleSql(sql);

    if (!this.tableCache.has(parsed.table)) {
      throw new Error(`表 ${parsed.table} 不存在于 CSV 数据源中`);
    }

    let rows = [...this.tableCache.get(parsed.table)!];

    if (parsed.where) {
      rows = rows.filter((row) => this.evaluateWhere(row, parsed.where!));
    }

    if (parsed.select !== '*') {
      const cols = parsed.select.split(',').map((c) => c.trim());
      rows = rows.map((row) => {
        const filtered: CsvRow = {};
        cols.forEach((c) => { filtered[c] = row[c]; });
        return filtered;
      });
    }

    if (parsed.limit) {
      rows = rows.slice(parsed.offset ?? 0, (parsed.offset ?? 0) + parsed.limit);
    }

    const columns = rows.length > 0 ? Object.keys(rows[0]) : [];
    const elapsed = performance.now() - start;

    return {
      columns,
      rows,
      rowCount: rows.length,
      executionTimeMs: Math.round(elapsed),
      sourceId: this.sourceId,
    };
  }

  private parseSimpleSql(sql: string): {
    select: string; table: string;
    where?: { field: string; op: string; value: string };
    limit?: number; offset?: number;
  } {
    const selectMatch = sql.match(/SELECT\s+(.+?)\s+FROM\s+(\S+)/i);
    if (!selectMatch) throw new Error(`CSV 适配器仅支持简单 SELECT 查询，无法解析: ${sql}`);

    const whereMatch = sql.match(/WHERE\s+(\w+)\s*(=|>|<|>=|<=|LIKE)\s*['"]?([^'"]+)['"]?/i);
    const limitMatch = sql.match(/LIMIT\s+(\d+)/i);
    const offsetMatch = sql.match(/OFFSET\s+(\d+)/i);

    return {
      select: selectMatch[1].trim(),
      table: selectMatch[2].trim(),
      where: whereMatch
        ? { field: whereMatch[1], op: whereMatch[2], value: whereMatch[3] }
        : undefined,
      limit: limitMatch ? parseInt(limitMatch[1]) : undefined,
      offset: offsetMatch ? parseInt(offsetMatch[1]) : undefined,
    };
  }

  private evaluateWhere(
    row: CsvRow,
    where: { field: string; op: string; value: string }
  ): boolean {
    const val = row[where.field];
    if (val === undefined) return false;

    switch (where.op) {
      case '=': return val === where.value;
      case '>': return Number(val) > Number(where.value);
      case '<': return Number(val) < Number(where.value);
      case '>=': return Number(val) >= Number(where.value);
      case '<=': return Number(val) <= Number(where.value);
      case 'LIKE': return val.toLowerCase().includes(where.value.toLowerCase().replace(/%/g, ''));
      default: return false;
    }
  }

  async listTables(): Promise<string[]> {
    return Array.from(this.tableCache.keys());
  }

  async getTableMeta(tableName: string): Promise<TableMeta> {
    const rows = this.tableCache.get(tableName);
    if (!rows || rows.length === 0) {
      throw new Error(`表 ${tableName} 不存在或为空`);
    }

    const columns: ColumnMeta[] = Object.keys(rows[0]).map((key) => {
      const sampleValues = rows.slice(0, 100).map((r) => r[key]);
      const isNumeric = sampleValues.every((v) => !isNaN(Number(v)) && v !== '');
      return {
        name: key,
        type: isNumeric ? 'DOUBLE' : 'VARCHAR',
        nullable: sampleValues.some((v) => v === '' || v === 'null'),
        isPrimaryKey: false,
      };
    });

    return {
      tableName,
      columns,
      rowCount: rows.length,
      lastSynced: new Date(),
    };
  }

  async testConnection(): Promise<boolean> {
    return fs.existsSync(this.dataDir);
  }
}
```

```typescript
// src/core/query-builder.ts

type DialectType = 'mysql' | 'postgres' | 'csv';

interface AggregateDef {
  field: string;
  function: 'SUM' | 'COUNT' | 'AVG' | 'MIN' | 'MAX';
  alias?: string;
}

interface FilterDef {
  field: string;
  operator: '=' | '!=' | '>' | '<' | '>=' | '<=' | 'LIKE' | 'IN' | 'BETWEEN';
  value: unknown;
}

interface SortDef {
  field: string;
  direction: 'ASC' | 'DESC';
}

export class UnifiedQueryBuilder {
  private tableName = '';
  private selectFields: string[] = ['*'];
  private aggregates: AggregateDef[] = [];
  private filters: FilterDef[] = [];
  private groupByFields: string[] = [];
  private sortFields: SortDef[] = [];
  private limitValue?: number;
  private offsetValue?: number;

  from(table: string): this {
    this.tableName = table;
    return this;
  }

  select(...fields: string[]): this {
    this.selectFields = fields;
    return this;
  }

  aggregate(def: AggregateDef): this {
    this.aggregates.push(def);
    return this;
  }

  where(field: string, operator: FilterDef['operator'], value: unknown): this {
    this.filters.push({ field, operator, value });
    return this;
  }

  groupBy(...fields: string[]): this {
    this.groupByFields = fields;
    return this;
  }

  orderBy(field: string, direction: 'ASC' | 'DESC' = 'ASC'): this {
    this.sortFields.push({ field, direction });
    return this;
  }

  limit(n: number): this {
    this.limitValue = n;
    return this;
  }

  offset(n: number): this {
    this.offsetValue = n;
    return this;
  }

  build(dialect: DialectType): string {
    if (!this.tableName) throw new Error('必须指定查询表名');

    const selectClause = this.buildSelectClause(dialect);
    const whereClause = this.buildWhereClause(dialect);
    const groupByClause = this.buildGroupByClause(dialect);
    const orderByClause = this.buildOrderByClause(dialect);
    const limitClause = this.buildLimitClause(dialect);

    const parts = [
      `SELECT ${selectClause}`,
      `FROM ${this.quoteIdentifier(this.tableName, dialect)}`,
      whereClause,
      groupByClause,
      orderByClause,
      limitClause,
    ].filter(Boolean);

    return parts.join(' ');
  }

  private buildSelectClause(dialect: DialectType): string {
    const parts: string[] = [];

    if (this.selectFields.length === 1 && this.selectFields[0] === '*') {
      parts.push('*');
    } else {
      parts.push(
        ...this.selectFields.map((f) => this.quoteIdentifier(f, dialect))
      );
    }

    for (const agg of this.aggregates) {
      const alias = agg.alias ?? `${agg.function.toLowerCase()}_${agg.field}`;
      const fn = agg.function;
      const quotedField = this.quoteIdentifier(agg.field, dialect);
      parts.push(`${fn}(${quotedField}) AS ${this.quoteIdentifier(alias, dialect)}`);
    }

    return parts.join(', ');
  }

  private buildWhereClause(dialect: DialectType): string {
    if (this.filters.length === 0) return '';

    const conditions = this.filters.map((f) => {
      const quoted = this.quoteIdentifier(f.field, dialect);
      switch (f.operator) {
        case 'IN': {
          const vals = Array.isArray(f.value) ? f.value : [f.value];
          const inList = vals.map((v) => this.formatValue(v)).join(', ');
          return `${quoted} IN (${inList})`;
        }
        case 'BETWEEN': {
          const [low, high] = Array.isArray(f.value) ? f.value : [f.value, f.value];
          return `${quoted} BETWEEN ${this.formatValue(low)} AND ${this.formatValue(high)}`;
        }
        case 'LIKE':
          return `${quoted} LIKE ${this.formatValue(f.value)}`;
        default:
          return `${quoted} ${f.operator} ${this.formatValue(f.value)}`;
      }
    });

    return `WHERE ${conditions.join(' AND ')}`;
  }

  private buildGroupByClause(dialect: DialectType): string {
    if (this.groupByFields.length === 0) return '';
    const quoted = this.groupByFields.map((f) => this.quoteIdentifier(f, dialect));
    return `GROUP BY ${quoted.join(', ')}`;
  }

  private buildOrderByClause(dialect: DialectType): string {
    if (this.sortFields.length === 0) return '';
    const parts = this.sortFields.map((s) => {
      const quoted = this.quoteIdentifier(s.field, dialect);
      return `${quoted} ${s.direction}`;
    });
    return `ORDER BY ${parts.join(', ')}`;
  }

  private buildLimitClause(dialect: DialectType): string {
    if (this.limitValue === undefined) return '';

    if (dialect === 'mysql') {
      const offset = this.offsetValue ?? 0;
      return `LIMIT ${offset}, ${this.limitValue}`;
    }

    let clause = `LIMIT ${this.limitValue}`;
    if (this.offsetValue !== undefined) {
      clause += ` OFFSET ${this.offsetValue}`;
    }
    return clause;
  }

  private quoteIdentifier(name: string, dialect: DialectType): string {
    if (name === '*') return name;
    switch (dialect) {
      case 'mysql':
        return `\`${name}\``;
      case 'postgres':
        return `"${name}"`;
      case 'csv':
        return name;
    }
  }

  private formatValue(value: unknown): string {
    if (value === null || value === undefined) return 'NULL';
    if (typeof value === 'number') return String(value);
    if (value instanceof Date) return `'${value.toISOString()}'`;
    return `'${String(value).replace(/'/g, "''")}'`;
  }
}
```

```typescript
// src/metadata/registry.ts
import { DataSourceAdapter, TableMeta, DataSourceConfig } from '../adapters/base';
import { MysqlAdapter } from '../adapters/mysql.adapter';
import { PostgresAdapter } from '../adapters/postgres.adapter';
import { CsvAdapter } from '../adapters/csv.adapter';

export class MetadataRegistry {
  private adapters = new Map<string, DataSourceAdapter>();
  private metadataCache = new Map<string, TableMeta>();

  async registerDataSource(config: DataSourceConfig): Promise<void> {
    const adapter = this.createAdapter(config);
    await adapter.connect();

    const isConnected = await adapter.testConnection();
    if (!isConnected) {
      throw new Error(`数据源 ${config.name} 连接测试失败`);
    }

    this.adapters.set(config.id, adapter);
    await this.syncMetadata(config.id);
  }

  async unregisterDataSource(sourceId: string): Promise<void> {
    const adapter = this.adapters.get(sourceId);
    if (adapter) {
      await adapter.disconnect();
      this.adapters.delete(sourceId);
      for (const key of this.metadataCache.keys()) {
        if (key.startsWith(`${sourceId}:`)) {
          this.metadataCache.delete(key);
        }
      }
    }
  }

  async syncMetadata(sourceId: string): Promise<void> {
    const adapter = this.adapters.get(sourceId);
    if (!adapter) throw new Error(`数据源 ${sourceId} 未注册`);

    const tables = await adapter.listTables();
    for (const table of tables) {
      const meta = await adapter.getTableMeta(table);
      this.metadataCache.set(`${sourceId}:${table}`, meta);
    }
  }

  getTableMeta(sourceId: string, tableName: string): TableMeta | undefined {
    return this.metadataCache.get(`${sourceId}:${tableName}`);
  }

  findTable(tableName: string): { sourceId: string; meta: TableMeta } | undefined {
    for (const [key, meta] of this.metadataCache) {
      if (key.endsWith(`:${tableName}`)) {
        const sourceId = key.split(':')[0];
        return { sourceId, meta };
      }
    }
    return undefined;
  }

  listAllTables(): Array<{ sourceId: string; tableName: string; rowCount?: number }> {
    const result: Array<{ sourceId: string; tableName: string; rowCount?: number }> = [];
    for (const [key, meta] of this.metadataCache) {
      const [sourceId] = key.split(':');
      result.push({ sourceId, tableName: meta.tableName, rowCount: meta.rowCount });
    }
    return result;
  }

  getAdapter(sourceId: string): DataSourceAdapter | undefined {
    return this.adapters.get(sourceId);
  }

  private createAdapter(config: DataSourceConfig): DataSourceAdapter {
    switch (config.type) {
      case 'mysql':
        return new MysqlAdapter(config);
      case 'postgres':
        return new PostgresAdapter(config);
      case 'csv':
        return new CsvAdapter(config);
      default:
        throw new Error(`不支持的数据源类型: ${config.type}`);
    }
  }
```

```typescript
    if (!adapter) throw new Error(`数据源 ${found.sourceId} 的适配器不可用`);

    const qb = new UnifiedQueryBuilder().from(tableName);
    const built = buildQuery(qb);
    const sql = built.build(adapter.sourceType as 'mysql' | 'postgres' | 'csv');

    console.log(`[${adapter.sourceType}] 执行查询: ${sql}`);
    return adapter.execute(sql);

    tables: string[],

  ): Promise<QueryResult[]> {
    const results = await Promise.all(
      tables.map((table) => this.query(table, buildQuery))
    );
    return results;
  }

  listAllData(): Array<{ sourceId: string; tableName: string; rowCount?: number }> {
    return this.registry.listAllTables();
```

## 常见误区

### 误区一：过度依赖 SQL 透传

很多开发者的第一反应是"直接把 SQL 透传给后端"。这在单数据源时没问题，但多数据源下会立刻碰壁——用户写的 `IFNULL` 在 PostgreSQL 上直接报错。统一查询构建器的额外开发成本，会在第三次遇到方言问题时收回。

### 误区二：忽略连接池生命周期

"连上了就不管了"是常见的生产事故来源。数据库连接是有限资源，每个适配器必须实现 `disconnect` 方法，应用关闭时要优雅地释放所有连接。使用 `process.on('SIGTERM', ...)` 做清理。

### 误区三：联邦查询不做数据量限制

联邦查询需要把数据拉到中间层再关联。如果两侧各有一百万行，内存会直接爆掉。必须设置联邦查询的数据量上限，并且在子查询中强制加 `LIMIT`。

### 误区四：元数据不同步

表结构会随业务迭代而变化（新增字段、类型变更）。如果元数据只在启动时同步一次，运行中途表结构变了就会导致查询失败。应该有定时同步机制或基于事件的变更通知。

### 误区五：CSV 适配器不考虑编码问题

CSV 文件的编码可能是 UTF-8、GBK、GB2312。直接用 `utf-8` 读取 GBK 文件会产生乱码。生产环境中应该支持编码配置，或使用 `chardet` 等库自动检测编码。

## 小结与练习

### 小结

本课我们从多数据源接入的真实痛点出发，设计并实现了一个统一数据访问层。核心要点：

1. **适配器模式**是屏蔽数据源差异的经典方案，每种数据源实现统一接口
2. **查询构建器**避免了直接拼接 SQL 的方言问题，是 BI 平台的标准做法
3. **联邦查询**通过拆分-执行-合并的策略实现跨数据源关联，但要注意数据量限制
4. **元数据管理**是自助分析的基础，需要自动发现和增量同步机制

### 练习一

**思路**：ClickHouse 的 Node.js 客户端使用 HTTP 协议，与 MySQL/PostgreSQL 的 TCP 连接不同。适配器需要处理 ClickHouse 特有的类型映射和 SQL 方言差异。

**答案**：

```typescript
import { createClient } from '@clickhouse/client';
import { DataSourceAdapter, QueryResult, TableMeta, ColumnMeta, DataSourceConfig } from './base';

export class ClickhouseAdapter extends DataSourceAdapter {
  readonly sourceId: string;
  readonly sourceType = 'clickhouse';
  private client: ReturnType<typeof createClient> | null = null;
  private config: DataSourceConfig;

  constructor(config: DataSourceConfig) {
    super();
    this.sourceId = config.id;
    this.config = config;
  }

  async connect(): Promise<void> {
    const cfg = this.config.config as {
      host: string; port: number; database: string;
      username: string; password: string;
    };
    this.client = createClient({
      host: `http://${cfg.host}:${cfg.port || 8123}`,
      database: cfg.database,
      username: cfg.username,
      password: cfg.password,
    });
  }

  async disconnect(): Promise<void> {
    if (this.client) {
      await this.client.close();
      this.client = null;
    }
  }

  async execute(sql: string, params?: unknown[]): Promise<QueryResult> {
    if (!this.client) throw new Error(`数据源 ${this.sourceId} 未连接`);

    const start = performance.now();
    const result = await this.client.query({
      query: sql,
      format: 'JSONEachRow',
      query_params: params as Record<string, unknown>,
    });
    const rows = await result.json<Record<string, unknown>[]>();
    const elapsed = performance.now() - start;

    const columns = rows.length > 0 ? Object.keys(rows[0]) : [];

    return {
      columns,
      rows,
      rowCount: rows.length,
      executionTimeMs: Math.round(elapsed),
      sourceId: this.sourceId,
    };
  }

  async listTables(): Promise<string[]> {
    const result = await this.execute(
      `SELECT name FROM system.tables WHERE database = currentDatabase() AND is_temporary = 0`
    );
    return result.rows.map((r) => r.name as string);
  }

  async getTableMeta(tableName: string): Promise<TableMeta> {
    const result = await this.execute(
      `SELECT name, type, comment
       FROM system.columns
       WHERE table = '${tableName}' AND database = currentDatabase()
       ORDER BY position`
    );

    const columns: ColumnMeta[] = result.rows.map((row) => ({
      name: row.name as string,
      type: row.type as string,
      nullable: (row.type as string).startsWith('Nullable'),
      isPrimaryKey: false,
      comment: (row.comment as string) || undefined,
    }));

    return { tableName, columns, lastSynced: new Date() };
  }

  async testConnection(): Promise<boolean> {
    try {
      const result = await this.execute('SELECT 1 as ok');
      return result.rows[0]?.ok === 1;
    } catch {
      return false;
    }
  }
}
```

**要点**：
- ClickHouse 的 Node.js 客户端基于 HTTP，不需要传统连接池
- 类型判断需要解析 `Nullable(...)` 包装
- ClickHouse 的 `system.columns` 表提供了丰富的元数据信息

### 练习二

**思路**：查询分析器需要解析 SQL 中的表名引用，然后在元数据注册中心查找每个表对应的数据源。如果涉及多个数据源，需要拆分查询并在内存中合并结果。

**答案**：

```typescript
// src/core/federated-engine.ts
import { MetadataRegistry } from '../metadata/registry';
import { UnifiedQueryBuilder } from './query-builder';
import { QueryResult } from '../adapters/base';

interface FederatedPlan {
  sourceId: string;
  tables: string[];
  sql: string;
}

export class FederatedEngine {
  constructor(private registry: MetadataRegistry) {}

  async executeFederated(
    sql: string,
    options: { maxRows?: number } = {}
  ): Promise<QueryResult> {
    const maxRows = options.maxRows ?? 10000;
    const tables = this.extractTableNames(sql);
    const sourceMap = this.groupBySource(tables);

    if (sourceMap.size <= 1) {
      const sourceId = sourceMap.keys().next().value;
      const adapter = this.registry.getAdapter(sourceId!);
      return adapter!.execute(sql);
    }

    const results = new Map<string, QueryResult>();
    const promises = Array.from(sourceMap.entries()).map(
      async ([sourceId, sourceTables]) => {
        const adapter = this.registry.getAdapter(sourceId);
        if (!adapter) throw new Error(`数据源 ${sourceId} 不可用`);

        for (const table of sourceTables) {
          const subQuery = `SELECT * FROM ${table} LIMIT ${maxRows}`;
          const result = await adapter.execute(subQuery);
          results.set(`${sourceId}:${table}`, result);
        }
      }
    );

    await Promise.all(promises);
    return this.mergeResults(results);
  }

  private extractTableNames(sql: string): string[] {
    const matches = sql.match(/FROM\s+(\w+)|JOIN\s+(\w+)/gi) ?? [];
    return matches
      .map((m) => m.replace(/FROM\s+|JOIN\s+/i, '').trim())
      .filter((t) => !t.startsWith('('));
  }

  private groupBySource(tables: string[]): Map<string, string[]> {
    const sourceMap = new Map<string, string[]>();
    for (const table of tables) {
      const found = this.registry.findTable(table);
      if (!found) throw new Error(`表 ${table} 未在任何数据源中找到`);

      const existing = sourceMap.get(found.sourceId) ?? [];
      existing.push(table);
      sourceMap.set(found.sourceId, existing);
    }
    return sourceMap;
  }

  private mergeResults(
    results: Map<string, QueryResult>
  ): QueryResult {
    const allColumns = new Set<string>();
    const allRows: Record<string, unknown>[] = [];

    for (const result of results.values()) {
      result.columns.forEach((c) => allColumns.add(c));
      allRows.push(...result.rows);
    }

    return {
      columns: Array.from(allColumns),
      rows: allRows,
      rowCount: allRows.length,
      executionTimeMs: Array.from(results.values())
        .reduce((sum, r) => sum + r.executionTimeMs, 0),
      sourceId: 'federated',
    };
  }
}
```

**要点**：
- 通过正则提取 SQL 中的表名，再在元数据中查找对应数据源
- 同一数据源的表走本地 JOIN，不同数据源的表分别查询后在内存合并
- `maxRows` 参数防止联邦查询拉取过多数据导致内存溢出
