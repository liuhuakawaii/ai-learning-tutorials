## 场景引入

你正在审阅一份季度报告，里面有一张柱状图展示了各产品线的营收对比。你想快速知道：哪个产品线增长最快？有没有异常波动？

传统做法：你需要仔细读图、对照图例、估算数值。如果图表没有数据标签，你甚至只能得到一个模糊的印象。

现在想象另一种场景：你把这张图表截图丢给 AI，它直接告诉你——"产品线 C 增长最快，同比增长 47%，但环比下降了 3%，可能存在季节性波动。"

这就是 Vision-Language（VL）模型在图表场景中的核心价值：**让 AI 像人一样"看"图表，并结合语言能力给出有洞察力的分析。**

但这条路上有很多技术难点：模型能否准确提取图表中的数据？能否理解图表的视觉编码（颜色、长度、角度）？能否将理解结果转化为结构化数据？本节课会深入探讨这些问题。

## 一、Vision-Language 模型概述

### 1.1 什么是 VL 模型？

传统的 AI 模型要么只处理文字（如 GPT-3），要么只处理图像（如 ResNet）。VL 模型的突破在于：**它能同时理解图像和语言，并在两者之间建立关联。**

```
传统模型 vs VL 模型：

┌─────────────────┐     ┌─────────────────┐
│  语言模型        │     │  视觉模型        │
│  输入: 文字      │     │  输入: 图片      │
│  输出: 文字      │     │  输出: 分类/标签  │
│  不理解图片      │     │  不理解文字      │
└─────────────────┘     └─────────────────┘

        VL 模型（Vision-Language）
┌─────────────────────────────────────┐
│  输入: 图片 + 文字（混合）           │
│  输出: 文字（基于视觉理解）           │
│  能理解"图片里的内容"并用语言描述     │
└─────────────────────────────────────┘
```

VL 模型的典型架构如下：

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  图像编码器   │    │  投影层       │    │  语言模型     │
│  (ViT/       │───→│  对齐视觉    │───→│  (LLM)       │
│   SigLIP)    │    │  与语言空间   │    │  生成文本     │
└──────────────┘    └──────────────┘    └──────────────┘
      ↑                                       ↑
   原始图片                              用户提问 / 指令
```

图像编码器将图片转为向量表示，投影层将视觉向量映射到语言模型能理解的空间，最后语言模型结合视觉信息和文字指令生成回答。

### 1.2 为什么图表理解对 VL 模型特别有挑战？

图表理解不同于一般的图像识别。一般的图像识别只需要"看到"物体（猫、狗、汽车），而图表理解需要**精确提取数值信息**。

举个例子：一张柱状图里有两根柱子，高度分别是 850 和 920。VL 模型需要：
1. 识别这是柱状图
2. 识别 X 轴对应的类别标签
3. 从柱子的高度反推数值
4. 考虑坐标轴的刻度和比例

这对模型的视觉精度要求极高。目前的 VL 模型在"大概对"的场景下表现不错，但在"精确到个位数"的场景下仍然会出错。

```
图表理解的精度层次：

Level 1: 识别图表类型          → "这是一张柱状图"           ✅ 准确率高
Level 2: 识别趋势方向          → "销售额在上升"             ✅ 准确率高
Level 3: 识别相对大小          → "A 比 B 高"               ✅ 准确率较高
Level 4: 提取精确数值          → "A 是 1200，B 是 980"     ⚠️ 准确率中等
Level 5: 提取复杂数据关系      → "A 的增长率是 B 的 2 倍"  ⚠️ 准确率较低
```

## 二、图表理解：从图片提取数据和信息

### 2.1 图表理解任务的分类

图表理解可以分解为几个子任务：

```
图表理解任务分解：

┌─────────────────────────────────────────────────────┐
│                    图表图片                          │
└──────────────────────┬──────────────────────────────┘
                       │
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
  ┌──────────┐  ┌──────────┐  ┌──────────┐
  │ 元素识别  │  │ 数据提取  │  │ 语义理解  │
  │          │  │          │  │          │
  │ ·图表类型 │  │ ·坐标轴  │  │ ·趋势    │
  │ ·标题    │  │ ·数据点  │  │ ·异常    │
  │ ·图例    │  │ ·数值    │  │ ·对比    │
  │ ·坐标轴  │  │ ·标签    │  │ ·洞察    │
  └──────────┘  └──────────┘  └──────────┘
```

**元素识别**是最基础的任务，VL 模型在这方面表现很好——识别图表类型、读取标题文字、提取图例信息，准确率通常在 90% 以上。

**数据提取**是核心难点。从柱状图的高度推算数值、从折线图的拐点读取数据、从饼图的角度估算比例，这些都需要模型具备精确的视觉推理能力。

**语义理解**是最高层次的任务，也是 VL 模型最擅长的。当数据被正确提取后，模型可以利用其语言能力给出专业的分析洞察。

### 2.2 Prompt 工程：如何让 VL 模型准确提取数据

与纯文本 LLM 类似，VL 模型的输出质量也高度依赖 Prompt 设计。但图表场景的 Prompt 有一些特殊技巧。

**技巧一：分步骤提问，而非一次性提问。**

不要直接问"请分析这张图表"，而是分步骤：

```
步骤 1: "这是什么类型的图表？X 轴和 Y 轴分别表示什么？"
步骤 2: "请列出图表中所有的类别和对应的数据值。"
步骤 3: "这些数据中有哪些明显的趋势或异常？"
```

分步骤的好处是：每一步的输出都可以被验证。如果步骤 2 提取的数据有误，我们可以在步骤 3 之前纠正。

**技巧二：要求结构化输出。**

```
请以 JSON 格式输出提取的数据：
{
  "chart_type": "柱状图",
  "title": "图表标题",
  "x_axis_label": "X轴标签",
  "y_axis_label": "Y轴标签",
  "data": [
    {"category": "类别名", "value": 数值}
  ]
}
```

结构化输出让后续的数据处理变得简单，也更容易检测模型是否"编造"了数据。

**技巧三：给出坐标轴刻度信息。**

如果你能从图表中识别出坐标轴的刻度范围（比如 Y 轴从 0 到 1000，每个刻度间隔 200），在 Prompt 中告诉模型，可以显著提高数值提取的准确性。

### 2.3 图表类型对提取难度的影响

不同图表类型的数据提取难度差异很大：

```
图表类型    数据提取难度    原因
──────────────────────────────────────────────────────
柱状图      ★★☆☆☆         长度是人类最容易感知的视觉编码
折线图      ★★★☆☆         需要定位拐点，插值估算
饼图        ★★★★☆         角度判断对人类和 AI 都不直观
散点图      ★★★☆☆         点密集时难以区分个别数据点
热力图      ★★★★★         颜色映射数值，精度依赖颜色感知
雷达图      ★★★★☆         多维度轴线，数值由距离中心的长度决定
桑基图      ★★★★★         流向和宽度的精确提取极其困难
```

这意味着：如果你的场景中 VL 模型需要处理多种图表类型，**应该针对不同图表类型设计不同的提取策略**。

## 三、图表生成：从数据直接生成图表图片

### 3.1 两种"生成"路径

当我们说"VL 模型生成图表"时，有两种理解：

```
路径 A: 数据 → VL 模型 → 图表图片（直接生成像素）
路径 B: 数据 → VL 模型 → 图表代码 → 渲染引擎 → 图表图片（间接生成）
```

**路径 A（直接生成图片）** 目前还不成熟。虽然 DALL-E 3、Midjourney 等图像生成模型可以画出"看起来像图表"的图片，但它们生成的图表往往有以下问题：

- 数值不精确：柱子高度与实际数据不符
- 标签是乱码：文字生成模型不擅长渲染精确的文字
- 布局不稳定：同样的数据每次生成的布局都不同

**路径 B（间接生成）** 是目前工程实践的主流方案。上节课讲的"代码生成式可视化"就是路径 B 的实现。VL 模型在其中的角色是理解用户意图、选择合适的图表类型、生成配置代码，最终由 ECharts/D3 等渲染引擎产出高质量的图表。

### 3.2 VL 模型在图表生成中的独特价值

既然路径 B 的核心是代码生成，VL 模型的价值在哪里？答案是：**它可以理解参考图片。**

场景：用户说"我要一个类似这样的图表"，然后发了一张参考图片。

纯文本 LLM 无法处理这张图片，它只能猜测"类似这样"是什么意思。但 VL 模型可以：

1. 识别参考图的图表类型、配色、布局
2. 分析参考图的数据结构和视觉编码方式
3. 将理解结果转化为代码生成的约束条件
4. 生成与参考图风格一致但数据不同的新图表

这就是"以图生图"在图表场景中的实现。

## 四、主流 VL 模型在图表场景的能力对比

### 4.1 闭源模型

**GPT-4V / GPT-4o（OpenAI）**

GPT-4o 是目前图表理解能力最强的模型之一。它在以下方面表现突出：
- 图表类型识别准确率极高（接近 100%）
- 能读取图表中的文字标签（包括中文）
- 能理解复合图表（如双 Y 轴、组合图）
- 数值提取精度在简单图表（柱状图、折线图）上可达 90%+

局限性：
- 复杂图表（热力图、桑基图）的数值提取仍然不够精确
- 对于需要精确计算的场景（如读取 Y 轴刻度后反推数值），偶尔会出现计算错误
- API 成本较高，不适合大规模批量处理

**Claude 3.5 Sonnet / Claude 3.5 Haiku（Anthropic）**

Claude Vision 在图表理解方面与 GPT-4V 不相上下，某些场景甚至更好：
- 对图表中的文字识别准确率高
- 结构化输出能力强（更容易生成规整的 JSON）
- 在长文档中的多图表场景下，上下文理解更好

### 4.2 开源模型

**Qwen-VL / Qwen2-VL（阿里）**

Qwen2-VL 是目前国内最强的开源 VL 模型之一：
- 支持中文图表理解（这对中文场景很重要）
- 在 ChartQA 等基准测试上表现优异
- 可以本地部署，数据不出境

**Llama 3.2 Vision（Meta）**

Meta 在 2024 年底发布的 Llama 3.2 Vision 系列：
- 11B 和 90B 两个版本
- 在图表理解基准测试上表现不错
- 开源可商用，社区生态活跃

**InternVL2（上海 AI Lab）**

InternVL2 系列在多项视觉理解基准上表现优异：
- 支持高分辨率图像输入
- 在中文图表理解场景下表现好
- 提供多种参数规模的选择

### 4.3 能力对比总结

```
────────────────────────────────────────────────────────────────

Claude 3.5 Sonnet ★★★★★      ★★★★☆      ★★★★★   高     否
```

#### 图表理解模块

```typescript
// src/chart-understander.ts

import OpenAI from "openai";
import * as fs from "fs";

interface ChartAnalysis {
  chartType: string;
  title: string;
  xAxis: { label: string; categories: string[] };
  yAxis: { label: string; unit: string };
  series: Array<{
    name: string;
    data: Array<{ category: string; value: number }>;
  }>;
  trends: string[];
  anomalies: string[];
  confidence: number;
}

class ChartUnderstander {
  private client: OpenAI;
  private model: string;

  constructor(apiKey: string, model = "gpt-4o") {
    this.client = new OpenAI({ apiKey });
    this.model = model;
  }

  async understandChart(imagePath: string): Promise<ChartAnalysis> {
    const imageBuffer = fs.readFileSync(imagePath);
    const base64Image = imageBuffer.toString("base64");
    const mimeType = imagePath.endsWith(".png") ? "image/png" : "image/jpeg";

    const step1Result = await this.identifyChartStructure(base64Image, mimeType);
    const step2Result = await this.extractPreciseData(base64Image, mimeType, step1Result);
    const step3Result = await this.analyzeInsights(step2Result);

    return {
      ...step2Result,
      ...step3Result,
      confidence: this.calculateConfidence(step2Result),
    };
  }

  private async identifyChartStructure(
    base64Image: string,
    mimeType: string
  ): Promise<Partial<ChartAnalysis>> {
    const response = await this.client.chat.completions.create({
      model: this.model,
      messages: [
        {
          role: "user",
          content: [
            {
              type: "text",
              text: `请仔细观察这张图表图片，识别以下信息：
1. 图表类型（柱状图/折线图/饼图/散点图/其他）
2. 图表标题
3. X 轴标签和所有类别名称
4. Y 轴标签和单位
5. 图例中的系列名称

请以 JSON 格式输出：
{
  "chart_type": "图表类型",
  "title": "标题",
  "x_axis_label": "X轴标签",
  "x_categories": ["类别1", "类别2"],
  "y_axis_label": "Y轴标签",
  "y_unit": "单位",
  "series_names": ["系列1", "系列2"]
}

只输出 JSON，不要其他内容。`,
            },
            {
              type: "image_url",
              image_url: { url: `data:${mimeType};base64,${base64Image}` },
            },
          ],
        },
      ],
      temperature: 0.1,
      max_tokens: 1000,
    });

    const content = response.choices[0]?.message?.content ?? "{}";
    return this.parseJSON(content);
  }

  private async extractPreciseData(
    base64Image: string,
    mimeType: string,
    structure: Partial<ChartAnalysis>
  ): Promise<ChartAnalysis> {
    const response = await this.client.chat.completions.create({
      model: this.model,
      messages: [
        {
          role: "user",
          content: [
            {
              type: "text",
              text: `请根据以下图表结构信息，精确提取图表中的数据值。

图表结构：
- 类型: ${structure.chartType}
- X 轴类别: ${structure.xAxis?.categories?.join(", ")}
- 系列: ${structure.series?.map((s) => s.name).join(", ")}

请仔细观察图表，提取每个类别对应每个系列的数值。
如果无法精确读取数值，请给出最佳估计。

以 JSON 格式输出：
{
  "data": [
    {
      "category": "类别名",
      "values": {
        "系列名1": 数值,
        "系列名2": 数值
      }
    }
  ]
}

只输出 JSON，不要其他内容。`,
            },
            {
              type: "image_url",
              image_url: { url: `data:${mimeType};base64,${base64Image}` },
            },
          ],
        },
      ],
      temperature: 0.1,
      max_tokens: 2000,
    });

    const content = response.choices[0]?.message?.content ?? "{}";
    const extractedData = this.parseJSON(content);

    return this.buildChartAnalysis(structure, extractedData);
  }

  private async analyzeInsights(
    analysis: ChartAnalysis
  ): Promise<{ trends: string[]; anomalies: string[] }> {
    const dataSummary = analysis.series
      .map(
        (s) =>
          `${s.name}: ${s.data.map((d) => `${d.category}=${d.value}`).join(", ")}`
      )
      .join("\n");

    const response = await this.client.chat.completions.create({
      model: this.model,
      messages: [
        {
          role: "user",
          content: `请分析以下图表数据，识别趋势和异常：

图表标题: ${analysis.title}
图表类型: ${analysis.chartType}
数据:
${dataSummary}

请以 JSON 格式输出：
{
  "trends": ["趋势1的描述", "趋势2的描述"],
  "anomalies": ["异常1的描述", "异常2的描述"]
}

如果没有明显异常，anomalies 可以为空数组。只输出 JSON。`,
        },
      ],
      temperature: 0.3,
      max_tokens: 500,
    });

    const content = response.choices[0]?.message?.content ?? '{"trends":[],"anomalies":[]}';
    return this.parseJSON(content);
  }

  private buildChartAnalysis(
    structure: Partial<ChartAnalysis>,
    extractedData: { data?: Array<{ category: string; values: Record<string, number> }> }
  ): ChartAnalysis {
    const seriesMap = new Map<string, Array<{ category: string; value: number }>>();

    for (const item of extractedData.data ?? []) {
      for (const [seriesName, value] of Object.entries(item.values ?? {})) {
        if (!seriesMap.has(seriesName)) {
          seriesMap.set(seriesName, []);
        }
        seriesMap.get(seriesName)!.push({ category: item.category, value });
      }
    }

    return {
      chartType: structure.chartType ?? "unknown",
      title: structure.title ?? "",
      xAxis: {
        label: structure.xAxis?.label ?? "",
        categories: structure.xAxis?.categories ?? [],
      },
      yAxis: {
        label: structure.yAxis?.label ?? "",
        unit: structure.yAxis?.unit ?? "",
      },
      series: Array.from(seriesMap.entries()).map(([name, data]) => ({
        name,
        data,
      })),
      trends: [],
      anomalies: [],
      confidence: 0,
    };
  }

  private calculateConfidence(analysis: ChartAnalysis): number {
    let score = 0.5;
    if (analysis.chartType !== "unknown") score += 0.15;
    if (analysis.xAxis.categories.length > 0) score += 0.15;
    if (analysis.series.length > 0) score += 0.1;
    if (analysis.series.every((s) => s.data.length > 0)) score += 0.1;
    return Math.min(score, 1);
  }

  private parseJSON(text: string): Record<string, unknown> {
    try {
      return JSON.parse(text);
    } catch {
      const match = text.match(/```(?:json)?\s*([\s\S]*?)```/);
      if (match) {
        try {
          return JSON.parse(match[1].trim());
        } catch {
          // ignore
        }
      }
      const firstBrace = text.indexOf("{");
      const lastBrace = text.lastIndexOf("}");
      if (firstBrace !== -1 && lastBrace > firstBrace) {
        try {
          return JSON.parse(text.slice(firstBrace, lastBrace + 1));
        } catch {
          return {};
        }
      }
      return {};
    }
  }
}
```

```typescript
interface StructuredDataset {
  metadata: {
    chartType: string;
    title: string;
    xAxisLabel: string;
    yAxisLabel: string;
    yAxisUnit: string;
  };
  categories: string[];
  series: Array<{
    name: string;
    values: number[];
  }>;
  statistics: {
    total: number;
    average: number;
    max: { category: string; value: number };
    min: { category: string; value: number };
  };
}

class DataStructurer {
  structure(analysis: ChartAnalysis): StructuredDataset {
    const categories = analysis.xAxis.categories;
    const series = analysis.series.map((s) => ({
      name: s.name,
      values: categories.map((cat) => {
        const item = s.data.find((d) => d.category === cat);
        return item?.value ?? 0;
      }),
    }));

    return {
      metadata: {
        chartType: analysis.chartType,
        title: analysis.title,
        xAxisLabel: analysis.xAxis.label,
        yAxisLabel: analysis.yAxis.label,
        yAxisUnit: analysis.yAxis.unit,
      },
      categories,
      series,
      statistics: this.calculateStatistics(series, categories),
    };
  }

  private calculateStatistics(
    series: Array<{ name: string; values: number[] }>,
    categories: string[]
  ) {
    const allValues = series.flatMap((s) => s.values);
    const total = allValues.reduce((sum, v) => sum + v, 0);
    const average = total / (allValues.length || 1);

    let maxValue = -Infinity;
    let maxCategory = "";
    let minValue = Infinity;
    let minCategory = "";

    for (const s of series) {
      for (let i = 0; i < s.values.length; i++) {
        if (s.values[i] > maxValue) {
          maxValue = s.values[i];
          maxCategory = `${categories[i]} (${s.name})`;
        }
        if (s.values[i] < minValue) {
          minValue = s.values[i];
          minCategory = `${categories[i]} (${s.name})`;
        }
      }
    }

    return {
      total,
      average: Math.round(average * 100) / 100,
      max: { category: maxCategory, value: maxValue },
      min: { category: minCategory, value: minValue },
    };
  }
}
```

```typescript
import { StructuredDataset } from "./data-structurer";

interface ValidationIssue {
  level: "error" | "warning" | "info";
  field: string;
  message: string;
  suggestion: string;
}

interface ValidationResult {
  valid: boolean;
  issues: ValidationIssue[];
  correctedDataset: StructuredDataset | null;
}

class DataValidator {
  validate(dataset: StructuredDataset): ValidationResult {
    const issues: ValidationIssue[] = [];

    // 检查 1: 数据完整性
    for (const series of dataset.series) {
      const missingCount = series.values.filter((v) => v === 0).length;
      if (missingCount > 0) {
        issues.push({
          level: "warning",
          field: `series.${series.name}`,
          message: `${series.name} 有 ${missingCount} 个零值，可能是数据缺失`,
          suggestion: "请核实原图中该位置是否有数据",
        });
      }
    }

    // 检查 2: 数值范围合理性
    for (const series of dataset.series) {
      const values = series.values.filter((v) => v !== 0);
      if (values.length === 0) continue;

      const avg = values.reduce((s, v) => s + v, 0) / values.length;
      for (let i = 0; i < series.values.length; i++) {
        if (series.values[i] > avg * 10 || series.values[i] < avg / 10) {
          issues.push({
            level: "warning",
            field: `series.${series.name}[${i}]`,
            message: `${dataset.categories[i]} 的值 (${series.values[i]}) 与平均值 (${avg.toFixed(0)}) 差异过大`,
            suggestion: "可能是视觉识别误差，请人工核实",
          });
        }
      }
    }

    // 检查 3: 类别名称是否包含乱码
    for (const category of dataset.categories) {
      if (/[□■◆◇○●]/.test(category) || category.length === 0) {
        issues.push({
          level: "error",
          field: "categories",
          message: `类别名 "${category}" 可能是乱码或识别错误`,
          suggestion: "请检查原图的 X 轴标签",
        });
      }
    }

    // 检查 4: 置信度相关
    if (dataset.series.length === 0) {
      issues.push({
        level: "error",
        field: "series",
        message: "未提取到任何数据系列",
        suggestion: "图片可能不是标准图表，或图表类型超出支持范围",
      });
    }

    return {
      valid: issues.filter((i) => i.level === "error").length === 0,
      issues,
      correctedDataset: dataset,
    };
  }
}
```

## 常见误区

### 误区一：认为 VL 模型能精确读取所有图表数据

VL 模型在"大致趋势"层面表现很好，但精确到个位数的数值提取仍然不可靠。对于需要精确数据的场景（如财务报告），应该将 VL 模型的输出作为初稿，人工校验后才能使用。

### 误区二：用同一个 Prompt 处理所有图表类型

柱状图、折线图、饼图的视觉编码方式完全不同。用同一个 Prompt 处理所有类型，会导致某些类型的提取精度下降。应该根据识别出的图表类型，选择针对性的提取策略。

### 误区三：忽略坐标轴刻度的提取

很多人关注数据点本身，却忽略了坐标轴的刻度信息。没有刻度信息，VL 模型只能给出相对大小，无法给出精确数值。在 Prompt 中要求模型先识别坐标轴刻度，再提取数据点，效果会好很多。

### 误区四：直接用 VL 模型生成图表图片

如前所述，VL 模型直接生成的图表图片质量不可控。正确的做法是让 VL 模型负责"理解"和"提取"，将生成环节交给专业的渲染引擎。

### 误区五：不校验直接使用提取结果

VL 模型可能会"幻觉"——它可能识别出一个图表中不存在的系列，或者把两个不同的类别合并成一个。数据校验环节是必须的，它能捕捉到大部分明显的错误。

## 小结与练习

### 本节要点回顾

1. **VL 模型**能同时理解图像和语言，在图表场景中可以"看图说话"
2. **图表理解**的核心难点是精确数值提取，不同图表类型的难度差异大
3. **分步 Prompt 策略**（结构识别→数据提取→洞察分析）比一次性提问效果更好
4. **主流 VL 模型**（GPT-4o、Claude 3.5、Qwen2-VL）在图表理解上各有优势
5. **端到端流水线**应包含：理解→结构化→校验→重新生成四个环节
6. **VL 模型负责理解，渲染引擎负责生成**，这是目前最可靠的架构

### 练习

#### 练习一：Prompt 优化实验

1. 图表类型识别的确定性
2. 数据提取结果的一致性（多次提取是否得到相同结果）
3. 数据的统计合理性（是否符合常识范围）

## 参考答案

### 练习一

**思路**：通过实际对比实验，理解分步 Prompt 的优势所在。关键观察点是：一次性提问时模型是否遗漏数据、数值是否准确；分步提问时每一步的输出质量。

**答案**：

策略 A（一次性提问）的典型问题：
- 可能只提取主要趋势数据，遗漏次要系列
- 数值精度不稳定，有些准确，有些偏差较大
- 输出格式不一致，有的系列有数据，有的没有

策略 B（分步提问）的优势：
- 第一步建立图表结构认知，后续步骤有明确的提取目标
- 可以在第二步之前验证第一步的结构识别是否正确
- 数据提取的完整性更高，因为有明确的类别和系列列表作为约束

改进方向：可以在第一步和第二步之间加入"人工确认"环节，让用户检查结构识别结果后再进行数据提取。

### 练习三

**思路**：置信度评估应该综合考虑多个维度，而不仅仅是"是否提取到了数据"。

**答案**：

```typescript
calculateConfidence(analysis: ChartAnalysis): number {
  let score = 0;
  let maxScore = 0;

  // 维度 1: 图表类型识别 (权重 20%)
  maxScore += 20;
  if (analysis.chartType !== "unknown") {
    score += 20;
  }

  // 维度 2: 结构完整性 (权重 25%)
  maxScore += 25;
  if (analysis.xAxis.categories.length > 0) score += 10;
  if (analysis.series.length > 0) score += 10;
  if (analysis.title.length > 0) score += 5;

  // 维度 3: 数据完整性 (权重 25%)
  maxScore += 25;
  const totalCells = analysis.series.length * analysis.xAxis.categories.length;
  const filledCells = analysis.series.reduce(
    (count, s) => count + s.data.filter((d) => d.value > 0).length, 0
  );
  const completeness = totalCells > 0 ? filledCells / totalCells : 0;
  score += completeness * 25;

  // 维度 4: 数据一致性 (权重 15%)
  maxScore += 15;
  let consistencyScore = 15;
  for (const series of analysis.series) {
    const values = series.data.map((d) => d.value).filter((v) => v > 0);
    if (values.length > 1) {
      const avg = values.reduce((s, v) => s + v, 0) / values.length;
      const hasOutlier = values.some((v) => v > avg * 5 || v < avg / 5);
      if (hasOutlier) consistencyScore -= 5;
    }
  }
  score += Math.max(0, consistencyScore);

  // 维度 5: 数值合理性 (权重 15%)
  maxScore += 15;
  let reasonablenessScore = 15;
  for (const series of analysis.series) {
    const values = series.data.map((d) => d.value);
    // 检查是否有负数（对于不应该有负数的图表类型）
    if (["bar", "pie"].includes(analysis.chartType)) {
      if (values.some((v) => v < 0)) {
        reasonablenessScore -= 5;
      }
    }
    // 检查数值是否过于分散
    const max = Math.max(...values);
    const min = Math.min(...values.filter((v) => v > 0));
    if (max / min > 1000) {
      reasonablenessScore -= 5;
    }
  }
  score += Math.max(0, reasonablenessScore);

  return Math.min(score / maxScore, 1);
}
```

**要点**：
- 图表类型识别是基础，权重不能太低
- 数据完整性用填充率来量化
- 一致性检查能发现模型"编造"的异常值
- 合理性检查针对不同图表类型有不同的标准
