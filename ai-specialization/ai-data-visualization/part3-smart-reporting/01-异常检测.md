## 场景引入

你是某电商平台的数据分析师。周一早上打开报表，发现上周五的 GMV（成交总额）突然暴跌 40%。你开始排查：是流量下降了？还是转化率出了问题？还是某个品类拖了后腿？

花了两个小时，你终于定位到原因——某支付渠道在周五下午出现了长达 3 小时的故障，导致大量订单无法完成支付。

这个场景暴露了一个核心问题：**异常已经发生了，但系统没有主动告警。** 如果在周五下午 2 点 GMV 开始偏离正常轨道时，系统就能自动检测到异常并发出预警，你本可以更快地介入处理。

这就是本课要解决的问题：如何让智能报表系统自动检测数据异常，并用人类能理解的方式解释异常原因。

## 核心概念

### 一、数据异常的三种类型

在讨论异常检测算法之前，我们需要先理解"异常"到底意味着什么。并非所有偏离均值的数据都是异常，也并非所有异常都长得一样。

```
异常类型分类：

┌─────────────────────────────────────────────────────┐
│                    数据异常                           │
├──────────────┬──────────────────┬───────────────────┤
│   点异常      │    上下文异常     │    集体异常        │
│ (Point)      │ (Contextual)     │ (Collective)      │
├──────────────┼──────────────────┼───────────────────┤
│ 单个数据点    │ 在特定上下文中    │ 一组数据点共同     │
│ 明显偏离      │ 偏离正常          │ 构成异常模式       │
├──────────────┼──────────────────┼───────────────────┤
│ 例：日销售额  │ 例：7月空调销量   │ 例：连续7天访问    │
│ 突然为0       │ 只卖了10台       │ 量呈锯齿状波动     │
│              │ (正常月份卖2000) │ (疑似刷量)         │
└──────────────┴──────────────────┴───────────────────┘
```

**点异常**是最直观的类型——单个数据点明显偏离了整体分布。比如日活突然从 10 万变成 100，或者接口响应时间从 200ms 飙到 5 秒。判断点异常的关键是定义"多远算远"，这需要我们理解数据的正常分布范围。

**上下文异常**则更微妙。同一个数值在不同上下文中可能正常也可能异常。日销量 100 单在平时可能偏低，但在大促预热期（用户等待大促开始不下单）可能是正常的。上下文异常要求我们不仅看数值本身，还要考虑时间、季节、业务周期等背景因素。

**集体异常**指的是单个数据点看起来正常，但一组数据点放在一起构成了异常模式。比如每个用户的单次访问时长都在 1-5 分钟的正常范围内，但如果某个用户在一天内访问了 200 次，每次都是 2 分钟——这种模式本身就很可疑（可能是爬虫）。

理解这三种类型很重要，因为不同的异常类型需要不同的检测方法。选错方法，要么漏检，要么误报。

### 二、时间序列异常检测

时间序列是报表数据最常见的形式：每天的销售额、每小时的访问量、每分钟的 API 调用次数。时间序列异常检测的核心思路是：**建立一个"正常值"的预测模型，当实际值偏离预测值超过阈值时，判定为异常。**

#### 2.1 移动平均法

移动平均是最简单的方法。基本思路是用过去 N 个时间点的平均值作为当前点的"正常期望值"。

```
原始数据:  [100, 102, 98, 101, 99, 300, 103, 100]
窗口=3 的移动平均:
  - 索引2: (100+102+98)/3 = 100
  - 索引3: (102+98+101)/3 = 100.3
  - 索引4: (98+101+99)/3  = 99.3
  - 索引5: (101+99+300)/3 = 166.7  ← 300拉高了均值

改进：用前N个点预测下一个点，偏差超过阈值即异常
  - 预测索引5: (102+98+101)/3 = 100.3
  - 实际值: 300
  - 偏差: |300 - 100.3| = 199.7 → 超过阈值 → 异常！
```

移动平均法的优点是实现简单、计算快，适合数据波动不大的场景。缺点是它对异常值本身也纳入了计算（导致"污染"），而且窗口大小的选择需要经验——窗口太小会漏检缓慢漂移，窗口太大会延迟检测。

#### 2.2 Z-Score 方法

Z-Score 衡量一个数据点偏离均值多少个标准差。公式为：

```
Z = (x - μ) / σ

其中：
  x = 当前数据点
  μ = 均值
  σ = 标准差

判定规则：
  |Z| > 2  → 可疑（约 5% 的正常数据会触发）
  |Z| > 3  → 高度异常（约 0.3% 的正常数据会触发）
  |Z| > 3.5 → 极端异常
```

Z-Score 的优势在于它给出了一个概率化的解释——Z=3 意味着在正态分布下，这个值出现的概率不到 0.3%。但前提是数据需要近似正态分布。如果你的数据是严重偏态的（比如收入分布），直接用 Z-Score 会产生大量误报。

对于偏态数据，可以用 Modified Z-Score（基于中位数和 MAD）来替代：

```
Modified Z-Score = 0.6745 * (x - median) / MAD

MAD = median(|x_i - median(x)|)

优点：对极端值更鲁棒，不依赖正态分布假设
```

#### 2.3 IQR 方法

IQR（四分位距）方法用数据的四分位数来定义"正常范围"，完全不依赖正态分布假设。

```
正常范围计算：

  Q1 (25分位)                Q3 (75分)
    │                          │
    ▼                          ▼
    ├──────────┤IQR├──────────┤
               │
         Q2 (中位数)

  下界 = Q1 - 1.5 * IQR
  上界 = Q3 + 1.5 * IQR

  低于下界或高于上界 → 异常

数值示例：
  数据: [10, 12, 14, 15, 16, 18, 19, 21, 100]
  Q1 = 13, Q3 = 19.5, IQR = 6.5
  下界 = 13 - 9.75 = 3.25
  上界 = 19.5 + 9.75 = 29.25
  100 > 29.25 → 异常！
```

IQR 方法的 1.5 倍系数是可以调整的。在金融风控等场景中，你可能需要更宽松的阈值（如 3 倍 IQR）来减少误报；在质量检测等场景中，可能需要更严格的阈值（如 1.0 倍 IQR）来确保不漏检。

### 三、维度异常：分类数据中的异常

前面讨论的方法主要针对数值型时间序列。但在实际报表中，大量数据是分类维度的——按地区、按产品类别、按用户渠道拆分的指标。维度异常指的是某个维度组合的指标值与其同类相比出现了显著偏差。

```
维度异常示例 - 各渠道转化率：

渠道          本周转化率    历史均值    偏差
─────────────────────────────────────────
自然搜索        3.2%        3.5%     -8.6%   ← 正常波动
付费推广        2.8%        3.0%     -6.7%   ← 正常波动
社交媒体        1.1%        3.2%    -65.6%   ← 异常！
直接访问        4.5%        4.2%     +7.1%   ← 正常波动
邮件营销        2.9%        3.1%     -6.5%   ← 正常波动

问题：社交媒体渠道转化率暴跌 65%，需要排查原因
可能原因：落地页改版、社交媒体平台算法变化、素材过期
```

维度异常检测的挑战在于"组合爆炸"——如果你有 10 个渠道、5 个地区、8 个产品线，全交叉就是 400 个组合。逐一检查不现实，需要用统计方法自动筛选出偏差最显著的维度组合。

常用方法是计算每个维度组合的**贡献度偏差**：

```
预期贡献 = 该维度历史占比 * 总量变化
实际贡献 = 该维度实际值
异常度 = |实际贡献 - 预期贡献| / 预期标准差
```

### 四、趋势变化检测（变点检测）

有时候数据没有明显的"尖峰"，但整体趋势发生了变化——比如用户增长率从每月 15% 下降到每月 5%，或者退货率从 2% 逐渐上升到 6%。这种缓慢的趋势变化用点异常检测方法很难捕捉，需要用**变点检测（Change Point Detection）**。

变点检测的核心思想是：在时间序列中找到一个或多个点，使得这些点前后的数据统计特征（均值、方差、趋势斜率）发生了显著变化。

```
变点检测示意：

用户增长率
  18% │ *
  15% │ * * *
  12% │       * *
   9% │           * *
   6% │               * * * *
   3% │                       * * * *
      └─────────────────────────────────
       1月  2月  3月  4月  5月  6月  7月
                           ↑
                        变点：增长趋势显著下降

检测方法：
  1. 滑动窗口对比：前后两个窗口的统计量差异
  2. CUSUM（累积和）：累积偏差超过阈值时触发
  3. 贝叶斯变点检测：计算每个点是变点的后验概率
```

**CUSUM（累积和控制图）**是工业界最常用的变点检测方法之一。它的思路是：如果数据发生均值偏移，累积偏差会逐渐增大，直到超过阈值。

```
CUSUM 基本原理：

  设目标均值为 μ₀，当前均值可能偏移到 μ₁
  偏移量 δ = μ₁ - μ₀

  正向累积和：S⁺ₜ = max(0, S⁺ₜ₋₁ + xₜ - μ₀ - δ/2)
  负向累积和：S⁻ₜ = max(0, S⁻ₜ₋₁ - xₜ + μ₀ - δ/2)

  当 S⁺ₜ > 阈值 h 或 S⁻ₜ > 阈值 h 时，报警

  直觉：如果数据持续偏高，S⁺ 会不断累积
        直到超过阈值，触发告警
```

### 五、LLM 辅助异常分析

检测到异常只是第一步——更重要的是解释异常原因。传统方法只能告诉你"指标 X 在时间 T 异常了"，但无法给出业务层面的解释。LLM 的出现改变了这一点。

```
异常检测 + LLM 解释流程：

  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
  │ 原始数据  │───▶│ 异常检测  │───▶│ 上下文    │───▶│ LLM     │
  │          │    │ 算法      │    │ 收集      │    │ 解释     │
  └──────────┘    └──────────┘    └──────────┘    └──────────┘
                       │                │               │
                   异常时间点        关联数据          自然语言
                   异常程度         外部事件          解释报告
                   受影响维度       历史模式          建议措施
```

LLM 在异常分析中的价值在于：

1. **关联多维信息**：将异常与运营事件、版本发布、节假日等关联
2. **生成假设**：基于领域知识提出可能的异常原因
3. **自然语言解释**：将技术指标异常翻译成业务语言
4. **建议行动**：基于异常类型给出处理建议

关键的 prompt 设计思路是给 LLM 提供足够的上下文——异常的具体数值、时间范围、受影响的维度、历史对比数据、以及已知的业务事件。没有这些上下文，LLM 只能给出泛泛的猜测。

### 核心检测引擎

```python
# detector.py
import numpy as np
import pandas as pd
from dataclasses import dataclass, field
from enum import Enum
from datetime import datetime


class AnomalyType(Enum):
    POINT = "point_anomaly"
    CONTEXTUAL = "contextual_anomaly"
    TREND_CHANGE = "trend_change"


class Severity(Enum):
    LOW = "low"
    MEDIUM = "medium"
    HIGH = "high"
    CRITICAL = "critical"


@dataclass
class AnomalyResult:
    timestamp: datetime
    value: float
    expected_value: float
    deviation: float
    anomaly_type: AnomalyType
    severity: Severity
    z_score: float
    method: str
    context: dict = field(default_factory=dict)


class AnomalyDetector:
    """时间序列异常检测引擎，支持多种检测方法。"""

    def __init__(self, sensitivity: float = 3.0):
        self.sensitivity = sensitivity

    def detect_point_anomalies(
        self, series: pd.Series, method: str = "zscore"
    ) -> list[AnomalyResult]:
        """检测点异常，支持 zscore、iqr、modified_zscore 三种方法。"""
        if method == "zscore":
            return self._zscore_detect(series)
        elif method == "iqr":
            return self._iqr_detect(series)
        elif method == "modified_zscore":
            return self._modified_zscore_detect(series)
        else:
            raise ValueError(f"不支持的检测方法: {method}")

    def _zscore_detect(self, series: pd.Series) -> list[AnomalyResult]:
        """基于 Z-Score 的点异常检测。"""
        mean = series.mean()
        std = series.std()
        if std == 0:
            return []

        anomalies = []
        for timestamp, value in series.items():
            z_score = abs((value - mean) / std)
            if z_score > self.sensitivity:
                severity = self._classify_severity(z_score)
                anomalies.append(AnomalyResult(
                    timestamp=timestamp,
                    value=value,
                    expected_value=round(mean, 2),
                    deviation=round(abs(value - mean), 2),
                    anomaly_type=AnomalyType.POINT,
                    severity=severity,
                    z_score=round(z_score, 3),
                    method="zscore",
                    context={"mean": mean, "std": std}
                ))
        return anomalies

    def _iqr_detect(self, series: pd.Series) -> list[AnomalyResult]:
        """基于 IQR 的点异常检测，对偏态数据更鲁棒。"""
        q1 = series.quantile(0.25)
        q3 = series.quantile(0.75)
        iqr = q3 - q1
        lower_bound = q1 - 1.5 * iqr
        upper_bound = q3 + 1.5 * iqr
        median = series.median()

        anomalies = []
        for timestamp, value in series.items():
            if value < lower_bound or value > upper_bound:
                deviation = min(abs(value - lower_bound), abs(value - upper_bound))
                z_score = deviation / (iqr if iqr > 0 else 1)
                severity = self._classify_severity(z_score)
                anomalies.append(AnomalyResult(
                    timestamp=timestamp,
                    value=value,
                    expected_value=round(median, 2),
                    deviation=round(deviation, 2),
                    anomaly_type=AnomalyType.POINT,
                    severity=severity,
                    z_score=round(z_score, 3),
                    method="iqr",
                    context={
                        "q1": q1, "q3": q3, "iqr": iqr,
                        "lower_bound": lower_bound,
                        "upper_bound": upper_bound
                    }
                ))
        return anomalies

    def _modified_zscore_detect(
        self, series: pd.Series
    ) -> list[AnomalyResult]:
        """基于 MAD 的 Modified Z-Score，对极端值更鲁棒。"""
        median = series.median()
        mad = np.median(np.abs(series - median))
        if mad == 0:
            return []

        anomalies = []
        for timestamp, value in series.items():
            modified_z = 0.6745 * abs(value - median) / mad
            if modified_z > self.sensitivity:
                severity = self._classify_severity(modified_z)
                anomalies.append(AnomalyResult(
                    timestamp=timestamp,
                    value=value,
                    expected_value=round(median, 2),
                    deviation=round(abs(value - median), 2),
                    anomaly_type=AnomalyType.POINT,
                    severity=severity,
                    z_score=round(modified_z, 3),
                    method="modified_zscore",
                    context={"median": median, "mad": mad}
                ))
        return anomalies

    def detect_trend_change(
        self, series: pd.Series, window: int = 7
    ) -> list[AnomalyResult]:
        """使用滑动窗口对比检测趋势变化点。"""
        if len(series) < window * 2:
            return []

        anomalies = []
        for i in range(window, len(series) - window):
            before = series.iloc[i - window:i]
            after = series.iloc[i:i + window]

            mean_diff = abs(after.mean() - before.mean())
            pooled_std = np.sqrt((before.var() + after.var()) / 2)

            if pooled_std == 0:
                continue

            z_score = mean_diff / pooled_std
            if z_score > self.sensitivity:
                severity = self._classify_severity(z_score)
                anomalies.append(AnomalyResult(
                    timestamp=series.index[i],
                    value=series.iloc[i],
                    expected_value=round(before.mean(), 2),
                    deviation=round(mean_diff, 2),
                    anomaly_type=AnomalyType.TREND_CHANGE,
                    severity=severity,
                    z_score=round(z_score, 3),
                    method="sliding_window",
                    context={
                        "before_mean": before.mean(),
                        "after_mean": after.mean(),
                        "window_size": window
                    }
                ))
        return anomalies

    def _classify_severity(self, z_score: float) -> Severity:
        """根据 Z-Score 值判定异常严重程度。"""
        if z_score > 5:
            return Severity.CRITICAL
        elif z_score > 4:
            return Severity.HIGH
        elif z_score > 3.5:
            return Severity.MEDIUM
        else:
            return Severity.LOW
```

### LLM 异常解释器

```python
# explainer.py
import json
from openai import OpenAI
from detector import AnomalyResult, AnomalyType, Severity


class AnomalyExplainer:
    """使用 LLM 对检测到的异常进行业务层面的解释。"""

    def __init__(self, api_key: str, base_url: str = None):
        client_kwargs = {"api_key": api_key}
        if base_url:
            client_kwargs["base_url"] = base_url
        self.client = OpenAI(**client_kwargs)

    def explain_anomaly(
        self,
        anomaly: AnomalyResult,
        metric_name: str,
        business_context: str = "",
        recent_events: list[str] = None
    ) -> str:
        """为单个异常生成业务解释。"""
        prompt = self._build_explanation_prompt(
            anomaly, metric_name, business_context, recent_events
        )

        response = self.client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[
                {
                    "role": "system",
                    "content": (
                        "你是一位资深数据分析师，擅长解释数据异常的业务原因。"
                        "请用简洁专业的语言分析异常原因，给出可能的解释和建议。"
                        "回答格式为 JSON，包含 cause、impact、suggestion 三个字段。"
                    )
                },
                {"role": "user", "content": prompt}
            ],
            temperature=0.3,
            response_format={"type": "json_object"}
        )

        return json.loads(response.choices[0].message.content)

    def explain_batch(
        self,
        anomalies: list[AnomalyResult],
        metric_name: str,
        business_context: str = "",
        recent_events: list[str] = None
    ) -> list[dict]:
        """批量解释多个异常，合并为一份分析报告。"""
        if not anomalies:
            return []

        summary_prompt = self._build_batch_prompt(
            anomalies, metric_name, business_context, recent_events
        )

        response = self.client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[
                {
                    "role": "system",
                    "content": (
                        "你是一位资深数据分析师。请分析以下异常数据集，"
                        "识别异常之间的关联性，给出整体分析结论。"
```

```python
    days: int = 90,

    noise_std: float = 500,
    inject_anomalies: bool = True

    weekly_pattern = 500 * np.sin(np.arange(days) * 2 * np.pi / 7)
    noise = np.random.normal(0, noise_std, days)
    values = base_value + trend + weekly_pattern + noise

    if inject_anomalies:
        values[15] = 2000      # 第16天：销售额暴跌（点异常）
        values[30] = 25000     # 第31天：销售额暴涨（点异常）
        values[55:62] -= 3000  # 第56-62天：连续下降（趋势变化）

    values = np.maximum(values, 0)
    return pd.Series(values, index=pd.DatetimeIndex(dates), name="daily_sales")


def generate_hourly_traffic(hours: int = 168) -> pd.Series:

    daily_pattern = 200 * np.sin(

    )
    daily_pattern = np.maximum(daily_pattern, 0)
    noise = np.random.normal(0, 30, hours)

    values[48] = 50    # 周三凌晨：流量骤降
    values[96] = 1500  # 周五中午：流量暴涨
```

## 常见误区

### 误区一：把所有偏离均值的数据都当作异常

很多初学者会设定一个固定的阈值（比如"偏离均值 20% 就是异常"），然后对所有指标统一套用。这种做法忽略了不同指标的波动特性——日活用户的正常波动可能是 ±10%，而 GMV 的正常波动可能是 ±30%。正确的做法是**为每个指标建立独立的基线**，用相对偏差（如 Z-Score）而非绝对阈值来判断。

### 误区二：忽略季节性和周期性

周一的流量通常比周末低，月初的销售额通常比月末高。如果你用全局均值作为基线，就会把所有周一都标记为"异常低"，把所有月初都标记为"异常高"。正确做法是在检测前**先去除季节性和周期性成分**（比如用 STL 分解），然后对残差做异常检测。

### 误区三：检测方法选错导致漏检或误报

Z-Score 假设数据近似正态分布，对偏态数据会产生大量误报；IQR 方法虽然不要求正态分布，但在数据量少时四分位数估计不稳定；移动平均法对突变敏感但对缓慢漂移不敏感。没有万能方法——**应该同时使用多种方法，取交集或加权投票**来提高检测的可靠性。

### 误区四：过度依赖 LLM 解释

LLM 生成的解释可能看起来很专业，但不一定准确。它可能会"编造"一个看似合理的解释，而实际上异常的原因是数据采集错误。LLM 的输出应该作为**辅助参考**，而非最终结论。所有 LLM 给出的假设都需要人工验证。

## 小结与练习

### 小结

本课介绍了数据异常检测的完整技术栈：

1. **异常分类**：点异常、上下文异常、集体异常，不同类型需要不同检测策略
2. **统计检测方法**：Z-Score（适合正态数据）、IQR（适合偏态数据）、Modified Z-Score（对极端值鲁棒）
3. **趋势变化检测**：滑动窗口对比、CUSUM 等方法用于发现缓慢的趋势偏移
4. **维度异常**：在分类维度中识别显著偏离同类的指标组合
5. **LLM 辅助解释**：将技术指标异常翻译成业务语言，提供原因假设和处理建议

核心原则是：**异常检测不是目的，异常理解和响应才是目的。**

## 参考答案

### 练习一

**思路**：将数据按星期几分组，对每组分别计算四分位数和 IQR，这样周一的低谷只和历史周一比较，不会被误判。

**答案**：

```python
def _iqr_detect_with_seasonality(
    self, series: pd.Series, period: str = "weekday"
) -> list[AnomalyResult]:
    """按周期分组的 IQR 异常检测。"""
    if period == "weekday":
        groups = series.groupby(series.index.dayofweek)
    elif period == "hour":
        groups = series.groupby(series.index.hour)
    else:
        return self._iqr_detect(series)

    anomalies = []
    for group_key, group_data in groups:
        if len(group_data) < 4:
            continue

        q1 = group_data.quantile(0.25)
        q3 = group_data.quantile(0.75)
        iqr = q3 - q1
        lower = q1 - 1.5 * iqr
        upper = q3 + 1.5 * iqr
        median = group_data.median()

        for timestamp, value in group_data.items():
            if value < lower or value > upper:
                deviation = min(abs(value - lower), abs(value - upper))
                z_score = deviation / (iqr if iqr > 0 else 1)
                anomalies.append(AnomalyResult(
                    timestamp=timestamp,
                    value=value,
                    expected_value=round(median, 2),
                    deviation=round(deviation, 2),
                    anomaly_type=AnomalyType.CONTEXTUAL,
                    severity=self._classify_severity(z_score),
                    z_score=round(z_score, 3),
                    method=f"iqr_seasonal_{period}",
                    context={"group": group_key, "iqr": iqr}
                ))

    return anomalies
```

**要点**：
- 按星期几分组后，每个组有自己的正常范围
- 异常类型标记为 `CONTEXTUAL`，因为是在特定上下文中偏离
- 分组数据量太少时（<4）跳过，避免四分位数估计不可靠

### 练习二

**思路**：CUSUM 的核心是累积偏差——如果数据持续偏高，正向累积和会不断增大，直到超过阈值。需要同时维护正向和负向两个累积和。

**答案**：

```python
def cusum_detect(
    series: pd.Series,
    target_mean: float = None,
    drift: float = None,
    threshold: float = 5.0
) -> list[AnomalyResult]:
    """CUSUM 变点检测。"""
    if target_mean is None:
        target_mean = series.mean()
    if drift is None:
        drift = series.std() * 0.5

    s_positive = 0.0
    s_negative = 0.0
    anomalies = []

    for timestamp, value in series.items():
        s_positive = max(0, s_positive + value - target_mean - drift / 2)
        s_negative = max(0, s_negative - value + target_mean - drift / 2)

        if s_positive > threshold:
            anomalies.append(AnomalyResult(
                timestamp=timestamp,
                value=value,
                expected_value=round(target_mean, 2),
                deviation=round(s_positive, 2),
                anomaly_type=AnomalyType.TREND_CHANGE,
                severity=Severity.HIGH,
                z_score=round(s_positive / drift, 3),
                method="cusum",
                context={"direction": "positive", "cusum": s_positive}
            ))
            s_positive = 0  # 重置以检测下一次偏移

        if s_negative > threshold:
            anomalies.append(AnomalyResult(
                timestamp=timestamp,
                value=value,
                expected_value=round(target_mean, 2),
                deviation=round(s_negative, 2),
                anomaly_type=AnomalyType.TREND_CHANGE,
                severity=Severity.HIGH,
                z_score=round(s_negative / drift, 3),
                method="cusum",
                context={"direction": "negative", "cusum": s_negative}
            ))
            s_negative = 0

    return anomalies
```

**要点**：
- `drift` 参数控制检测灵敏度——越小越灵敏，但误报也越多
- 检测到变点后要重置累积和，否则会连锁触发
- threshold 需要根据业务场景调参，没有通用默认值

### 练习三

**思路**：不同严重程度的告警需要不同的详细程度和格式。低级别只需要一行文字，高级别需要结构化报告。

**答案**：

```python
def generate_alert_message(
    self,
    anomaly: AnomalyResult,
    metric_name: str,
    format_type: str = "text"
) -> str:
    """根据异常严重程度和输出格式生成告警消息。"""

    if anomaly.severity in (Severity.LOW, Severity.MEDIUM):
        return self._brief_alert(anomaly, metric_name, format_type)
    else:
        return self._detailed_alert(anomaly, metric_name, format_type)


def _brief_alert(self, anomaly, metric_name, format_type):
    direction = "偏高" if anomaly.value > anomaly.expected_value else "偏低"
    if format_type == "text":
        return (
            f"[{anomaly.severity.value.upper()}] {metric_name} "
            f"在 {anomaly.timestamp} {direction}，"
            f"当前 {anomaly.value:.0f}，期望 {anomaly.expected_value}"
        )
    elif format_type == "markdown":
        icon = "🟡" if anomaly.severity == Severity.LOW else "🟠"
        return (
            f"{icon} **{metric_name} 异常**\n"
            f"- 时间: {anomaly.timestamp}\n"
            f"- 状态: {direction}\n"
            f"- 当前值: {anomaly.value:.0f} / 期望值: {anomaly.expected_value}"
        )
    return self._brief_alert(anomaly, metric_name, "text")


def _detailed_alert(self, anomaly, metric_name, format_type):
    explanation = self.explain_anomaly(anomaly, metric_name)

    if format_type == "markdown":
        return f"""## 🚨 {metric_name} 异常告警

| 项目 | 详情 |
|------|------|
| 严重程度 | {anomaly.severity.value.upper()} |
| 异常时间 | {anomaly.timestamp} |
| 当前值 | {anomaly.value:.2f} |
| 期望值 | {anomaly.expected_value} |
| 偏差幅度 | {anomaly.deviation:.2f} |
| Z-Score | {anomaly.z_score} |

### 原因分析
{explanation.get('cause', '待分析')}

### 业务影响
{explanation.get('impact', '待评估')}

### 处理建议
{suggestion}""".format(suggestion=explanation.get('suggestion', '待建议'))

    return (
        f"[{anomaly.severity.value.upper()}] {metric_name} 严重异常\n"
        f"时间: {anomaly.timestamp}\n"
        f"值: {anomaly.value} (期望: {anomaly.expected_value})\n"
        f"原因: {explanation.get('cause', '待分析')}\n"
        f"建议: {explanation.get('suggestion', '待建议')}"
    )
```

**要点**：
- 按严重程度分流——低级别生成简短通知，高级别生成详细报告
- 支持多种输出格式，便于集成到不同的通知渠道
- 高级别告警会调用 LLM 生成解释，低级别不调用以节省成本
