## 场景引入

你是一个数据团队的工程师。每周一早上 9 点，运营总监需要看到上周的核心指标周报；每天早上 8 点，各业务线负责人需要看到昨日的日报；当某个关键指标异常波动时，安全团队需要立刻收到告警推送。

手动做这些事情意味着：每周一早上 8 点你得手动跑查询、手动截图、手动发邮件。一旦你请假或者出差，报表就断了。更糟糕的是，当你在凌晨 3 点发现数据异常时，你不可能手动通知每个人。

这就是定时报表与推送系统要解决的问题：**让报表的生成和分发完全自动化，让人只在需要介入时才介入。**

## 核心概念

### 一、定时任务系统架构

一个生产级的定时报表系统，不是简单地写一个 `setInterval`。它需要解决三个核心问题：

1. **调度准确性**：任务必须在精确的时间点触发，不能漂移
2. **分布式一致性**：多实例部署时，同一个任务不能被重复执行
3. **失败恢复**：任务失败后能自动重试，而不是静默丢失

```
┌─────────────────────────────────────────────────────┐
│                  调度层 (Scheduler)                    │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐          │
│  │ Cron Job │  │ 事件触发  │  │ 条件触发  │          │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘          │
│       └──────────────┼──────────────┘                │
│                      ▼                               │
│            ┌─────────────────┐                       │
│            │   任务队列 (MQ)  │                       │
│            └────────┬────────┘                       │
│                     ▼                                │
│  ┌──────────────────────────────────────────┐       │
│  │           Worker 执行器集群                │       │
│  │  ┌─────────┐ ┌─────────┐ ┌─────────┐    │       │
│  │  │ Worker1 │ │ Worker2 │ │ Worker3 │    │       │
```

### 二、三种触发策略

不是所有报表都适合"每天早上 8 点"这种固定时间触发。不同的业务场景需要不同的触发策略：

**固定时间触发（Time-based）**

最常见的模式。适合日报、周报、月报等周期性报表。核心是 Cron 表达式：

```
┌───────────── 分钟 (0-59)
│ ┌─────────── 小时 (0-23)
│ │ ┌───────── 日 (1-31)
│ │ │ ┌─────── 月 (1-12)
│ │ │ │ ┌───── 星期 (0-7, 0和7都是周日)
│ │ │ │ │
* * * * *
```

常用表达式示例：
- `0 9 * * 1` — 每周一上午 9:00
- `0 8 * * *` — 每天上午 8:00
- `0 */4 * * *` — 每 4 小时
- `30 9 1 * *` — 每月 1 号上午 9:30

**事件驱动触发（Event-based）**

当某个事件发生时触发报表生成。比如：订单量突增、数据库写入完成、上游数据同步结束。这种模式需要事件总线（如 Redis Pub/Sub、Kafka、RabbitMQ）来传递事件信号。

**条件触发（Condition-based）**

持续监控某个指标，当指标满足条件时触发。比如：当转化率低于 5% 时发送告警报表、当库存低于安全水位时发送补货建议。这种模式需要指标采集器 + 条件评估引擎的配合。

```
┌─────────────── 触发策略对比 ───────────────────┐
│                                                 │
│  固定时间        事件驱动        条件触发        │
│  ┌─────┐       ┌─────┐       ┌─────┐          │
│  │ 时钟 │       │ 事件 │       │ 指标 │          │
│  └──┬──┘       └──┬──┘       └──┬──┘          │
│     │             │             │              │
│     ▼             ▼             ▼              │
│  周期性报表    实时报表      告警报表           │
│  日报/周报    数据变更通知   异常指标快报       │
│                                                 │
│  适用：可预测    适用：时效性高  适用：监控场景  │
│  实现：简单     实现：中等     实现：较复杂      │
└─────────────────────────────────────────────────┘
```

### 三、推送渠道集成

不同团队使用不同的协作工具。一个好的推送系统不应该强制所有人使用同一个渠道，而是应该支持多渠道并行推送。

每个渠道的集成方式不同，但核心流程一致：

```
┌──────────────────────────────────────────┐
│            推送分发流程                    │
│                                          │
│  报表内容 ──→ 内容适配 ──→ 渠道路由      │
│                              │           │
│              ┌───────────────┼───────┐   │
│              ▼               ▼       ▼   │
│          ┌──────┐      ┌──────┐ ┌──────┐│
│          │ SMTP │      │ 飞书 │ │ 钉钉 ││
│          │ 邮件 │      │ Webhook│ │Webhook│

│              │               │       │   │
│              ▼               ▼       ▼   │
│           发送结果收集与状态记录          │
└──────────────────────────────────────────┘
```

```typescript
// src/channels/email-channel.ts
import nodemailer from 'nodemailer'
import type { PushChannel, PushPayload, PushResult } from './types.js'

export interface EmailConfig {
  smtpHost: string
  smtpPort: number
  username: string
  password: string
  fromAddress: string
  fromName: string
}

export class EmailChannel implements PushChannel {
  name = 'email'
  private transporter: nodemailer.Transporter

  constructor(config: EmailConfig) {
    this.transporter = nodemailer.createTransport({
      host: config.smtpHost,
      port: config.smtpPort,
      secure: config.smtpPort === 465,
      auth: {
        user: config.username,
        pass: config.password,
      },
    })
  }

  async send(payload: PushPayload, recipients: string[]): Promise<PushResult> {
    try {
      const mailOptions: nodemailer.SendMailOptions = {
        from: `"${payload.title}" <报表系统>`,
        to: recipients.join(', '),
        subject: payload.title,
        html: payload.htmlContent,
        attachments: [] as nodemailer.SendMailOptions['attachments'],
      }

      if (payload.pdfBuffer) {
        mailOptions.attachments!.push({
          filename: `${payload.title}.pdf`,
          content: payload.pdfBuffer,
          contentType: 'application/pdf',
        })
      }

      if (payload.attachments) {
        mailOptions.attachments!.push(
          ...payload.attachments.map(att => ({
            filename: att.filename,
            content: att.content,
            contentType: att.contentType,
          }))
        )
      }

      const info = await this.transporter.sendMail(mailOptions)
      return {
        channel: this.name,
        success: true,
        messageId: info.messageId,
        timestamp: new Date(),
      }
    } catch (error) {
      return {
        channel: this.name,
        success: false,
        error: error instanceof Error ? error.message : '邮件发送失败',
        timestamp: new Date(),
      }
    }
  }
}
```

### 第三步：推送分发器

```typescript
// src/dispatcher.ts
import type { PushChannel, PushPayload, PushResult } from './channels/types.js'

export interface PushTask {
  channelName: string
  recipients: string[]
}

export interface DispatchResult {
  title: string
  results: PushResult[]
  totalChannels: number
  successCount: number
  failureCount: number
  timestamp: Date
}

export class PushDispatcher {
  private channels = new Map<string, PushChannel>()
  private retryAttempts = 3
  private retryDelayMs = 2000

  registerChannel(channel: PushChannel): void {
    this.channels.set(channel.name, channel)
  }

  async dispatch(
    payload: PushPayload,
    tasks: PushTask[]
  ): Promise<DispatchResult> {
    const results: PushResult[] = []

    for (const task of tasks) {
      const channel = this.channels.get(task.channelName)
      if (!channel) {
        results.push({
          channel: task.channelName,
          success: false,
          error: `渠道 "${task.channelName}" 未注册`,
          timestamp: new Date(),
        })
        continue
      }

      const result = await this.sendWithRetry(channel, payload, task.recipients)
      results.push(result)
    }

    const successCount = results.filter(r => r.success).length

    return {
      title: payload.title,
      results,
      totalChannels: tasks.length,
      successCount,
      failureCount: tasks.length - successCount,
      timestamp: new Date(),
    }
  }

  private async sendWithRetry(
    channel: PushChannel,
    payload: PushPayload,
    recipients: string[]
  ): Promise<PushResult> {
    let lastError: PushResult | null = null

    for (let attempt = 1; attempt <= this.retryAttempts; attempt++) {
      const result = await channel.send(payload, recipients)
      if (result.success) {
        return result
      }

      lastError = result
      console.warn(
        `[推送重试] ${channel.name} 第${attempt}次失败: ${result.error}`
      )

      if (attempt < this.retryAttempts) {
        await this.sleep(this.retryDelayMs * attempt)
      }
    }

    return lastError!
  }

  private sleep(ms: number): Promise<void> {
    return new Promise(resolve => setTimeout(resolve, ms))
  }
}
```

### 第四步：定时调度器

```typescript
// src/scheduler.ts
import cron from 'node-cron'

export interface ScheduleConfig {
  cronExpression: string
  timezone?: string
}

export interface ScheduledTask {
  id: string
  name: string
  schedule: ScheduleConfig
  handler: () => Promise<void>
  enabled: boolean
  lastRun?: Date
  lastStatus?: 'success' | 'failure'
  consecutiveFailures: number
}

export class ReportScheduler {
  private tasks = new Map<string, ScheduledTask>()
  private cronJobs = new Map<string, cron.ScheduledTask>()
  private maxConsecutiveFailures = 5
  private onFailure?: (task: ScheduledTask, error: Error) => void

  constructor(options?: {
    onFailure?: (task: ScheduledTask, error: Error) => void
  }) {
    this.onFailure = options?.onFailure
  }

  register(task: ScheduledTask): void {
    this.tasks.set(task.id, task)

    if (task.enabled) {
      this.startTask(task)
    }

    console.log(
      `[调度器] 注册任务: ${task.name} (${task.schedule.cronExpression})`
    )
  }

  startTask(task: ScheduledTask): void {
    const existing = this.cronJobs.get(task.id)
    if (existing) {
      existing.stop()
    }

    const job = cron.schedule(
      task.schedule.cronExpression,
      async () => {
        await this.executeTask(task)
      },
      {
        timezone: task.schedule.timezone || 'Asia/Shanghai',
      }
    )

    this.cronJobs.set(task.id, job)
  }

  stopTask(taskId: string): void {
    const job = this.cronJobs.get(taskId)
    if (job) {
      job.stop()
      this.cronJobs.delete(taskId)
    }
  }

  private async executeTask(task: ScheduledTask): Promise<void> {
    console.log(`[调度器] 执行任务: ${task.name} @ ${new Date().toISOString()}`)
    task.lastRun = new Date()

    try {
      await task.handler()
      task.lastStatus = 'success'
      task.consecutiveFailures = 0
    } catch (error) {
      task.lastStatus = 'failure'
      task.consecutiveFailures++

      const err = error instanceof Error ? error : new Error(String(error))
      console.error(`[调度器] 任务失败: ${task.name}`, err.message)

      if (task.consecutiveFailures >= this.maxConsecutiveFailures) {
        this.stopTask(task.id)
        console.error(
          `[调度器] 任务 ${task.name} 连续失败${this.maxConsecutiveFailures}次，已自动停止`
        )
      }

      this.onFailure?.(task, err)
    }
  }

  getTaskStatus(): Array<{
    id: string
    name: string
    enabled: boolean
    lastRun: string
    lastStatus: string
    consecutiveFailures: number
  }> {
    return Array.from(this.tasks.values()).map(task => ({
      id: task.id,
      name: task.name,
      enabled: task.enabled,
      lastRun: task.lastRun?.toISOString() || '从未执行',
      lastStatus: task.lastStatus || 'pending',
      consecutiveFailures: task.consecutiveFailures,
    }))
  }

  stopAll(): void {
    for (const [id, job] of this.cronJobs) {
      job.stop()
    }
    this.cronJobs.clear()
    console.log('[调度器] 所有任务已停止')
  }
}
```

## 常见误区

### 误区一：用 setInterval 替代 Cron 调度

很多人在原型阶段用 `setInterval(() => generateReport(), 24 * 60 * 60 * 1000)` 来实现"每天执行一次"。这有两个致命问题：

1. **时间漂移**：`setInterval` 的间隔从上一次执行结束开始计算，如果任务执行耗时 5 分钟，实际触发时间会每天推迟 5 分钟。
2. **进程重启后丢失**：进程一重启，定时器就没了。

**正确做法**：使用 `node-cron`、`Celery Beat`（Python）或操作系统级的 `crontab`。

### 误区二：推送失败后无感知

很多系统在推送失败后只是 `console.error` 了一下就结束了。用户根本不知道报表没有送达。这会导致严重的业务问题——运营总监以为看到了全部数据，实际上已经三天没收到报表了。

**正确做法**：推送失败必须有独立的告警通道（如短信、电话），且连续失败 N 次后自动升级告警等级。

### 误区三：Webhook URL 硬编码

把飞书/钉钉的 Webhook URL 直接写在代码里，一旦 URL 变更就需要改代码重新部署。

**正确做法**：所有渠道配置必须通过环境变量或配置中心管理，代码中不包含任何具体的 URL。

### 误区四：忽略时区问题

Cron 表达式如果不指定时区，在容器化部署时会使用 UTC 时间，导致"每天早上 8 点"实际上变成了北京时间下午 4 点。

**正确做法**：始终显式指定时区 `timezone: 'Asia/Shanghai'`。

### 练习一

**思路**：参照已有的 `DingtalkChannel` 实现，企业微信的 Webhook 接口与钉钉类似，区别在于请求格式和 endpoint。

**答案**：

```typescript
// src/channels/wecom-channel.ts
import axios from 'axios'
import type { PushChannel, PushPayload, PushResult } from './types.js'

export class WeComChannel implements PushChannel {
  name = 'wecom'
  private webhookUrl: string

  constructor(webhookUrl: string) {
    this.webhookUrl = webhookUrl
  }

  async send(payload: PushPayload, _recipients: string[]): Promise<PushResult> {
    try {
      const response = await axios.post(
        this.webhookUrl,
        {
          msgtype: 'markdown',
          markdown: {
            content: payload.markdownContent.slice(0, 4096),
          },
        },
        { headers: { 'Content-Type': 'application/json' }, timeout: 10000 }
      )

      if (response.data.errcode === 0) {
        return { channel: this.name, success: true, timestamp: new Date() }
      }

      return {
        channel: this.name,
        success: false,
        error: response.data.errmsg || '企业微信推送失败',
        timestamp: new Date(),
      }
    } catch (error) {
      return {
        channel: this.name,
        success: false,
        error: error instanceof Error ? error.message : '企业微信推送异常',
        timestamp: new Date(),
      }
    }
  }
}
```

**要点**：企业微信与钉钉的 Webhook 格式非常接近，主要区别在 URL 路径和错误码字段名（`errcode` vs `code`）。

### 练习二

**思路**：条件触发的核心挑战是"防抖"——避免在指标持续异常的每一分钟都发送告警。解决方案是引入告警冷却时间（cooldown），在冷却期内不重复告警。

**答案**：

```typescript
// src/condition-trigger.ts
export class ConditionTrigger {
  private lastAlertTime = new Map<string, number>()
  private cooldownMs: number

  constructor(cooldownMs = 30 * 60 * 1000) { // 默认30分钟冷却
    this.cooldownMs = cooldownMs
  }

  shouldAlert(conditionKey: string, isTriggered: boolean): boolean {
    if (!isTriggered) return false

    const lastTime = this.lastAlertTime.get(conditionKey) || 0
    const now = Date.now()

    if (now - lastTime < this.cooldownMs) {
      return false // 冷却期内，不重复告警
    }

    this.lastAlertTime.set(conditionKey, now)
    return true
  }
}

// 使用示例
const trigger = new ConditionTrigger(30 * 60 * 1000)

async function checkOrderVolume(): Promise<void> {
  const recentOrders = await queryRecentOrderCount(60) // 最近60分钟
  const threshold = 100

  if (trigger.shouldAlert('low-order-volume', recentOrders < threshold)) {
    await sendAlertReport(`订单量异常: 最近1小时仅 ${recentOrders} 单，低于阈值 ${threshold}`)
  }
}
```

**要点**：冷却时间的选择取决于业务容忍度。太短会导致告警风暴，太长会延迟问题发现。建议根据指标的重要程度设置不同的冷却时间。

### 练习三

**思路**：推送结果已经在 `DispatchResult` 中返回了，需要做的就是将其持久化到数据库，并提供查询接口。

**答案**：

```typescript
// src/push-log.ts
import { randomUUID } from 'node:crypto'

export interface PushLogEntry {
  id: string
  reportTitle: string
  channel: string
  recipients: string[]
  success: boolean
  errorMessage?: string
  sentAt: Date
}

export class PushLogStore {
  private logs: PushLogEntry[] = []

  async record(entry: Omit<PushLogEntry, 'id'>): Promise<void> {
    this.logs.push({ ...entry, id: randomUUID() })
  }

  async query(options?: {
    startDate?: Date
    endDate?: Date
    channel?: string
    successOnly?: boolean
  }): Promise<PushLogEntry[]> {
    return this.logs.filter(log => {
      if (options?.startDate && log.sentAt < options.startDate) return false
      if (options?.endDate && log.sentAt > options.endDate) return false
      if (options?.channel && log.channel !== options.channel) return false
      if (options?.successOnly && !log.success) return false
      return true
    })
  }

  async getSuccessRate(days = 7): Promise<{
    total: number
    success: number
    rate: number
  }> {
    const since = new Date(Date.now() - days * 86400000)
    const recent = this.logs.filter(l => l.sentAt >= since)
    const success = recent.filter(l => l.success).length
    return {
      total: recent.length,
      success,
      rate: recent.length > 0 ? success / recent.length : 0,
    }
  }
}
```

**要点**：生产环境中应该使用数据库（如 PostgreSQL、SQLite）而非内存存储。内存存储在进程重启后数据丢失。
