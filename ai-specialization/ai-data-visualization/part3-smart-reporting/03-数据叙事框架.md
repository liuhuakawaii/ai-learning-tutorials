## 场景引入

你花了三天做了一份详尽的季度数据分析报告：50 页 PPT，30 张图表，涵盖所有能想到的维度。你信心满满地在管理层会议上展示。

结果：CFO 在第 10 分钟开始看手机，CMO 在第 20 分钟问"所以结论是什么"，CEO 在结束时说"能不能给我一个三句话的总结？"

问题出在哪？不是数据分析不够深入，而是你没有把数据组织成一个**故事**。你展示的是"数据的堆砌"，而不是"数据的叙事"。

数据叙事（Data Storytelling）不是把图表串起来讲一遍，而是用一个有结构的故事线把关键洞察串联起来，让受众在最短时间内理解"发生了什么、为什么重要、应该怎么做"。

这跟上一课的"数据摘要"有什么区别？摘要是**压缩信息**——把一张大表变成一段话。叙事是**组织信息**——把零散的发现变成一条有逻辑的线。摘要是点，叙事是线。好的数据叙事，能让一个从未看过数据的人，在三分钟内理解整个业务现状并做出决策。

本课会介绍一套结构化的数据叙事方法论，并用 AI 来辅助叙事生成。

## 核心概念

### 一、数据叙事的三要素

数据叙事不等于"数据可视化 + 文字说明"。它是一种以数据为证据、以视觉为载体、以叙事为骨架的沟通方式。

```
数据叙事三角：

              叙事 (Narrative)
             /        \
            /   有效    \
           /   沟通     \
          /              \
         /________________\
    数据 (Data) ──── 视觉 (Visual)


数据：叙事的证据基础
  - 数据必须准确、完整、有代表性
  - 选择支持论点的数据，而非所有数据
  - 关键数字要精炼，不能让人淹没在数字里

视觉：叙事的呈现载体
  - 图表类型要匹配数据特征和叙事意图
  - 视觉层次要引导注意力到关键信息
  - 颜色、标注、注释都是叙事工具

叙事：数据和视觉的连接逻辑
  - 有明确的主线（要传达什么核心信息）
  - 有因果链条（为什么→所以→因此）
  - 有行动导向（看完之后该做什么）
```

很多数据分析师擅长前两个要素——数据处理和可视化制作，但在第三个要素"叙事"上往往力不从心。他们习惯用数据的逻辑（维度→指标→对比）来组织内容，而不是用故事的逻辑（问题→探索→发现→行动）来组织。

下面是一个对比，让你直观感受"数据展示"和"数据叙事"的区别：

```
数据展示（无效）：
  "Q1 GMV 为 4,500 万。
   环比增长 12%。
   华东区域占比 35%。
   新用户转化率 3.8%。
   退货率 2.1%。"
   → 听众反应：然后呢？

数据叙事（有效）：
  "Q1 我们实现了 4,500 万 GMV，增长主要来自华东区域。
   但有一个值得关注的信号：新用户转化率从 4.5% 降到了 3.8%，
   意味着每获取 100 个新用户，我们比上季度少转化了 7 个人。
   如果不改善获客渠道质量，Q2 的增长目标可能面临压力。"
   → 听众反应：明白了，我们需要排查渠道质量。
```

区别在哪里？数据展示是罗列事实，数据叙事是建立因果。前者让受众自己去连接点，后者直接帮受众把点连成线。

### 二、SCQA 叙事结构

在众多叙事框架中，SCQA 是最适合数据分析场景的结构。它由麦肯锡的芭芭拉·明托在《金字塔原理》中提出，包含四个部分：

```
SCQA 叙事结构：

  S - Situation（情境）
      "我们当前处于什么状态？"
      → 建立共识，让受众进入语境

  C - Complication（冲突）
      "出现了什么问题或变化？"
      → 制造张力，引起关注

  Q - Question（问题）
      "我们需要回答什么问题？"
      → 聚焦注意力，明确方向

  A - Answer（答案）
      "我们的分析结论和建议是什么？"
      → 给出价值，推动行动
```

为什么 SCQA 特别适合数据叙事？因为数据分析天然具备这四个要素——你有业务现状（S），你发现了异常或趋势（C），你需要解释原因（Q），你给出了结论和建议（A）。SCQA 不是硬套的框架，而是对数据分析过程的自然映射。

下面是一个完整的季度销售报告叙事示例：

```
S（情境）：
  "Q1 整体 GMV 达成 4,500 万，完成全年目标的 24%，
   略高于时间进度（25% 对应的季度目标是 4,687 万）。"

C（冲突）：
  "但增长结构不健康——老用户复购贡献了 78% 的增量，
   新用户获取量虽然增长 15%，转化率却从 4.5% 降至 3.8%。"

Q（问题）：
  "如果新用户转化率持续走低，Q2 的增长能否维持？
   我们需要在获客质量上做什么调整？"

A（答案）：
  "建议 Q2 将获客预算从广投放转移到精准投放，
   预计可将转化率回升至 4.2%，支撑 Q2 达成 5,200 万目标。"
```

SCQA 的优势在于它天然符合商业沟通的习惯——先说背景，再抛问题，最后给答案。它避免了两种常见的叙事失败：一是"没有冲突"——只报喜不报忧，受众觉得无聊；二是"没有答案"——只抛问题不给建议，受众觉得焦虑。

需要注意的是，SCQA 的四个部分不一定要严格按顺序出现。在实际叙事中，有时会先抛出冲突（C）来吸引注意力，再回头补充情境（S）。这种变体叫做 CSQA，适合受众对背景已经很熟悉的场景。

### 三、叙事节奏设计

有了 SCQA 框架，下一步是设计叙事节奏——在什么时候放数据、什么时候留白、什么时候给结论。

```
叙事节奏的"呼吸感"：

  信息密度
  高 │    ┌─┐         ┌─┐
     │    │ │    ┌─┐  │ │
     │ ┌─┐│ │ ┌─┐│ │  │ │    ┌─┐
     │ │ ││ │ │ ││ │  │ │ ┌─┐│ │
  低 │─┘ └┘ └─┘ └┘ └──┘ └─┘ └┘ └─
     └─────────────────────────────→ 时间
      开场  数据1 数据2 洞察  数据3 结论

  每个"呼吸周期"：
    数据铺垫（2-3 个数据点）→ 洞察总结（1 句话）→ 短暂停顿
```

好的叙事节奏像呼吸一样有张有弛。连续堆砌 5 个数据点会让受众窒息，连续 3 段没有数据的分析又会让人觉得空洞。一个实用的节奏模型是"**3+1**"：每 3 个数据点后，跟 1 句洞察总结。

具体到 SCQA 结构中，每个部分的信息密度应该不同：

```
各部分的信息密度分配：

  S（情境）：中等密度
    → 提供 2-3 个关键数字，建立共识
    → 不需要太多细节，够用就行

  C（冲突）：高密度
    → 这是叙事的核心，需要用数据支撑张力
    → 放最重要的 3-4 个数据发现
    → 用对比和反差制造冲击力

  Q（问题）：低密度
    → 这里应该留白，让受众自己思考
    → 最多用 1 个数据点来具象化问题

  A（答案）：中等密度
    → 给出结论和建议
    → 用 1-2 个预测数据支撑建议的合理性
```

### 四、受众分析与叙事适配

同一个数据发现，面对不同受众应该有不同的叙事策略。这不是"说不同的话"，而是"从不同的角度切入同一个真相"。

```
受众角色与叙事焦点：

角色          关注什么              叙事焦点           详略程度
──────────────────────────────────────────────────────────────
CEO           战略方向、ROI         结论和建议          极简
CFO           财务指标、成本        数字和趋势          精确
CMO           获客、品牌、渠道      渠道对比和归因      中等
运营总监      执行层面、具体问题    问题定位和行动方案   详细
数据团队      方法论、数据质量      技术细节和假设      最详细


示例：同一个发现（新用户转化率下降）对不同角色的表达：

对 CEO：
  "新用户转化率下滑影响 Q2 增长约 300 万，建议调整获客策略。"

对 CMO：
  "新用户转化率从 4.5% 降至 3.8%，主要由社交媒体渠道拖累。
   该渠道 ROI 已从 1:3.2 降至 1:2.1，建议缩减预算转投搜索渠道。"

对运营总监：
  "社交媒体渠道新用户转化率暴跌至 1.2%，排查发现落地页
   在 3 月 15 日改版后跳出率从 35% 升至 62%。
   建议本周回滚落地页，同时 A/B 测试新版本。"
```

受众分析的核心不是"说什么"，而是"不说什么"。给 CEO 的叙事要大胆砍掉细节，只留结论；给运营的叙事要砍掉宏观判断，只留可执行的细节。

### 五、LLM 辅助叙事生成

LLM 可以将数据分析结果转化为结构化叙事，但需要精心设计 prompt 来引导。自由发挥的 LLM 倾向于写成"报告体"——罗列数据、缺乏主线、没有节奏。

```
LLM 叙事生成的 Prompt 架构：

┌────────────────────────────────────────────┐
│ System Prompt（角色 + 叙事规则）             │
│  - 角色：资深数据叙事专家                    │
│  - 结构：SCQA 四段式                        │
│  - 风格：简洁、有因果逻辑、有行动导向         │
│  - 约束：数字必须准确，推断需标注             │
├────────────────────────────────────────────┤
│ User Prompt（数据 + 受众 + 约束）            │
│  - 关键发现列表（结构化 JSON）               │
│  - 目标受众（CEO / CMO / 运营）              │
│  - 篇幅限制（字数）                          │
│  - 输出格式（Markdown / 纯文本）             │
└────────────────────────────────────────────┘


关键 Prompt 技巧：
1. 给 LLM 明确的叙事模板，而非让它自由发挥
2. 提供数据发现列表时标注"正面/负面/中性"，帮助 LLM 构建冲突
3. 要求 LLM 在叙事中区分"事实"和"推断"，避免混淆
4. 限制篇幅——LLM 倾向于写长，但商业叙事需要精炼
```

一个实用的技巧是在 prompt 中给出**反面示例**——告诉 LLM "不要写成下面这样"，比只给正面示例更有效。比如："不要写成数据罗列体，不要逐个指标介绍，不要使用'值得注意的是'这类空话。"

```python
# data_context.py
from dataclasses import dataclass, field
from enum import Enum


class Sentiment(Enum):
    POSITIVE = "positive"
    NEGATIVE = "negative"
    NEUTRAL = "neutral"


@dataclass
class DataFinding:
    """一条数据发现，带有情感标签，供叙事引擎使用。"""
    metric: str
    current_value: float
    previous_value: float
    change_rate: float
    dimension: str
    sentiment: Sentiment
    description: str
    priority: float = 0.0


@dataclass
class DataContext:
    """叙事所需的数据上下文，包含所有发现和业务背景。"""
    report_period: str
    findings: list[DataFinding]
    business_context: str = ""
    key_metrics_summary: dict[str, float] = field(default_factory=dict)

    def get_positive_findings(self) -> list[DataFinding]:
        return [f for f in self.findings if f.sentiment == Sentiment.POSITIVE]

    def get_negative_findings(self) -> list[DataFinding]:
        return [f for f in self.findings if f.sentiment == Sentiment.NEGATIVE]

    def get_top_findings(self, n: int = 5) -> list[DataFinding]:
        sorted_findings = sorted(self.findings, key=lambda x: x.priority, reverse=True)
        return sorted_findings[:n]

    def to_structured_text(self) -> str:
        """将数据上下文转为 LLM 可理解的结构化文本。"""
        lines = [f"报告周期：{self.report_period}\n"]

        if self.business_context:
            lines.append(f"业务背景：{self.business_context}\n")

        lines.append("关键发现（按优先级排序）：")
        for i, f in enumerate(self.get_top_findings(10), 1):
            sentiment_label = {
                Sentiment.POSITIVE: "正面",
                Sentiment.NEGATIVE: "负面",
                Sentiment.NEUTRAL: "中性",
            }[f.sentiment]
            lines.append(
                f"  {i}. [{sentiment_label}] {f.dimension} - {f.metric}: "
                f"{f.change_rate:+.2%}（{f.description}）"
            )

        return "\n".join(lines)
```

### SCQA 叙事构建器

```python
# scqa_builder.py
from dataclasses import dataclass, field


@dataclass
class SCQASection:
    """SCQA 的一个组成部分。"""
    section_type: str       # situation / complication / question / answer
    content: str
    supporting_data: list[str] = field(default_factory=list)


@dataclass
class Narrative:
    """完整的数据叙事。"""
    title: str
    sections: list[SCQASection]
    audience: str
    summary: str = ""

    def to_markdown(self) -> str:
        parts = [f"# {self.title}\n"]
        section_labels = {
            "situation": "## 情境 (Situation)",
            "complication": "## 冲突 (Complication)",
            "question": "## 问题 (Question)",
            "answer": "## 答案 (Answer)",
        }
        for section in self.sections:
            label = section_labels.get(section.section_type, "")
            parts.append(f"{label}\n")
            parts.append(section.content)
            if section.supporting_data:
                parts.append("\n**支撑数据：**")
                for data in section.supporting_data:
                    parts.append(f"- {data}")
            parts.append("")
        return "\n".join(parts)

    def to_json(self) -> dict:
        return {
            "title": self.title,
            "audience": self.audience,
            "summary": self.summary,
            "sections": [
                {
                    "type": s.section_type,
                    "content": s.content,
                    "supporting_data": s.supporting_data,
                }
                for s in self.sections
            ],
        }


class SCQABuilder:
    """基于规则的 SCQA 叙事构建器，用于在不依赖 LLM 时生成基础叙事。"""

    def build(self, data_context) -> Narrative:
        from data_context import Sentiment

        sections = []

        # S: 情境 — 总结核心指标现状
        positive = data_context.get_positive_findings()
        negative = data_context.get_negative_findings()
        top = data_context.get_top_findings(3)

        situation_parts = []
        for f in top:
            direction = "增长" if f.change_rate > 0 else "下降"
            situation_parts.append(
                f"{f.dimension} {f.metric} 为 {f.current_value:,.0f}，"
                f"{direction} {abs(f.change_rate):.1%}"
            )
        sections.append(SCQASection(
            section_type="situation",
            content=data_context.report_period + "整体表现：" + "；".join(situation_parts) + "。",
            supporting_data=[f.description for f in top],
        ))

        # C: 冲突 — 突出负面发现
        if negative:
            conflict_findings = negative[:3]
            conflict_parts = [f.description for f in conflict_findings]
            sections.append(SCQASection(
                section_type="complication",
                content="但存在以下问题：" + "；".join(conflict_parts) + "。",
                supporting_data=[f.description for f in negative],
            ))
        else:
            sections.append(SCQASection(
                section_type="complication",
                content="整体表现稳健，未发现重大异常。",
            ))

        # Q: 问题 — 基于冲突引出核心问题
        if negative:
            primary_issue = negative[0]
            sections.append(SCQASection(
                section_type="question",
                content=(
                    f"核心问题：{primary_issue.dimension} 的 {primary_issue.metric} "
                    f"持续走低，是否会影响下一阶段的业务目标？"
                ),
            ))

        # A: 答案 — 行动建议
        suggestions = []
        for f in negative[:2]:
            suggestions.append(f"针对 {f.dimension} {f.metric} 的问题，建议深入排查原因并制定改善计划")
        if not suggestions:
            suggestions.append("保持当前策略，继续监控关键指标变化")
        sections.append(SCQASection(
            section_type="answer",
            content="建议行动：" + "；".join(suggestions) + "。",
        ))

        return Narrative(
            title=f"{data_context.report_period} 数据叙事报告",
            sections=sections,
            audience="管理层",
        )
```

```python
    }

    def get_profile(self, role: str) -> dict:
        return self.PROFILES.get(role, self.PROFILES["ceo"])

    def filter_findings_for_audience(
        self, context: DataContext, role: str
    ) -> DataContext:
        """根据受众角色筛选和排序发现。"""
        profile = self.get_profile(role)
        top_findings = context.get_top_findings(profile["top_n"])

        return DataContext(
            report_period=context.report_period,
            findings=top_findings,
            business_context=context.business_context,
            key_metrics_summary=context.key_metrics_summary,
        )
```

```python
# narrative_engine.py
import json
from openai import OpenAI
from data_context import DataContext
from audience_adapter import AudienceAdapter


class NarrativeEngine:
    """基于 LLM 的数据叙事引擎。"""

    BASE_SYSTEM_PROMPT = """你是一位资深数据叙事专家。你的任务是将数据分析结果转化为有说服力的叙事。

叙事结构要求：
1. 使用 SCQA 结构（情境-冲突-问题-答案）
2. 每个部分之间要有逻辑过渡
3. 数据数字必须与输入完全一致，不得修改
4. 区分"事实"和"推断"，推断需标注"基于趋势判断"
5. 避免空话套话，每句话都要有信息量

禁止的写法：
- 不要写"值得注意的是""需要指出的是"这类空话
- 不要逐个指标罗列，要有主线串联
- 不要写超过 3 个数据点而不给出洞察总结
"""

    def __init__(self, model: str = "gpt-4o-mini"):
        self.client = OpenAI()
        self.model = model
        self.adapter = AudienceAdapter()

    def generate_narrative(
        self,
        context: DataContext,
        audience: str = "ceo",
        output_format: str = "markdown",
    ) -> str:
        """生成数据叙事。"""
        profile = self.adapter.get_profile(audience)
        filtered_context = self.adapter.filter_findings_for_audience(context, audience)

        system_prompt = self.BASE_SYSTEM_PROMPT + f"\n{profile['system_suffix']}"
        system_prompt += f"\n输出字数限制：{profile['max_chars']} 字以内"

        format_instruction = {
            "markdown": "请以 Markdown 格式输出，使用 # 和 ## 标记层级。",
            "plain": "请以纯文本格式输出，不要使用任何 Markdown 语法。",
            "json": (
                "请以 JSON 格式输出，结构为 "
                '{"title": "...", "sections": [{"type": "situation|complication|question|answer", '
                '"content": "...", "supporting_data": ["..."]}], "summary": "..."}'
            ),
        }.get(output_format, "")

        user_prompt = f"""以下是数据分析结果，请为目标受众「{profile['label']}」生成数据叙事。

{filtered_context.to_structured_text()}

{format_instruction}"""

        response = self.client.chat.completions.create(
            model=self.model,
            messages=[
                {"role": "system", "content": system_prompt},
                {"role": "user", "content": user_prompt},
            ],
            temperature=0.3,
            max_tokens=1000,
        )
        return response.choices[0].message.content
```

## 常见误区

### 误区一：把"数据可视化 + 文字说明"当成数据叙事

很多人认为在图表下面加一段文字说明就是数据叙事。实际上，这只是数据展示。真正的数据叙事有一条贯穿始终的主线——所有图表和文字都在为同一个核心论点服务。如果你把任何一张图表拿掉，叙事仍然完整，那这张图表就不应该出现。

**正确做法**是先确定核心信息（"新用户转化率下降是 Q2 的最大风险"），再选择能支撑这个信息的数据和图表，最后用叙事线把它们串联起来。

### 误区二：SCQA 四个部分平均用力

初学者经常把 SCQA 的四个部分写成差不多长度，导致叙事没有重点。实际上，冲突（C）和答案（A）是最重要的部分——C 决定了受众是否愿意继续听，A 决定了受众是否觉得有价值。

**正确做法**是把 60% 的篇幅分配给 C 和 A。情境（S）只需要 1-2 句话建立共识，问题（Q）只需要 1 句话聚焦注意力。

### 误区三：对所有受众使用同一套叙事

给 CEO 和给运营总监用同一套叙事，是最常见的错误。CEO 需要的是"结论 + 建议"，运营需要的是"问题 + 原因 + 具体行动"。用同一套叙事会导致要么太抽象（对运营没用），要么太详细（CEO 没时间看）。

**正确做法**是为每种受众准备独立的叙事版本。可以通过 LLM 的 system prompt 来控制输出的详略程度和信息侧重点，而不需要手动改写。

### 误区四：只叙事不验证

LLM 生成的叙事可能包含错误的数字、错误的因果推断、或者过度自信的预测。把这些内容直接呈现给决策者，可能导致错误的商业决策。

**正确做法**是建立叙事验证机制：检查叙事中的数字是否与原始数据一致，检查因果推断是否有数据支撑，检查预测是否标注了不确定性。

## 小结与练习

### 小结

1. 数据叙事三要素——数据（证据）、视觉（载体）、叙事（骨架），缺一不可
2. SCQA 是最适合数据分析场景的叙事结构：情境建立共识，冲突制造张力，问题聚焦注意力，答案推动行动
3. 叙事节奏遵循"3+1"模式：每 3 个数据点后跟 1 句洞察总结，让受众有"呼吸"的空间
4. 受众分析的核心是"不说什么"——给 CEO 砍细节，给运营砍宏观判断
5. LLM 辅助叙事需要精心设计 prompt，关键是给明确的叙事模板、标注数据情感、限制篇幅

## 参考答案

### 练习一

**思路**：CSQA 结构的核心是先用冲突吸引注意力，再补充情境让受众理解全貌。适合受众已经知道"公司 GMV 在增长"这个背景，直接告诉他们"但有个大问题"更有冲击力。

**答案**：

```
C（冲突）：
  "华南区域 GMV 在 3 月暴跌 25%，从 1,200 万降至 900 万。
   原因是核心经销商在 3 月停止合作，导致区域分销网络出现缺口。"

S（情境）：
  "整体来看，Q1 GMV 仍保持增长态势，达到 5,200 万，环比增长 8%。
   但华南区域的暴跌拖累了整体增速约 3 个百分点。"

Q（问题）：
  "华南区域占整体 GMV 的 17%，如果经销商问题不能在 Q2 解决，
   全年目标可能面临 600-800 万的缺口。"

A（答案）：
  "建议立即启动华南区域直销渠道建设，预计需要 2-3 个月完成。
   在此期间，协调华东区域团队支援华南大客户维护，
   确保存量客户不流失。"
```

**要点**：
- 冲突放在最前面，直接告诉受众"出事了"
- 情境放在冲突之后，让受众知道"虽然整体还行，但这个问题很严重"
- 答案要有具体的时间线和措施，不能只说"建议关注"

### 练习二

**思路**：原句连续罗列了 8 个指标，没有任何洞察和过渡。优化的方法是按逻辑关系分组，每组 2-3 个指标后跟一句总结。

**答案**：

```
优化前（信息过载）：
  "Q1 GMV 4,500 万。订单量 120 万。客单价 375 元。新用户数 15 万。
   老用户复购率 42%。退货率 2.1%。平均配送时长 2.3 天。客户满意度 4.6 分。"

优化后（3+1 节奏）：
  "Q1 GMV 达成 4,500 万，对应 120 万笔订单、客单价 375 元，
   整体交易规模稳健。（3 个数据 + 1 句总结）

   用户侧，新用户 15 万，老用户复购率 42%，
   说明用户粘性较好，但新用户获取仍有提升空间。（2 个数据 + 1 句洞察）

   服务侧，退货率 2.1%，配送时长 2.3 天，客户满意度 4.6 分，
   三项指标均处于行业良好水平。（3 个数据 + 1 句总结）"
```

**要点**：
- 把 8 个指标按逻辑分成 3 组：交易指标、用户指标、服务指标
- 每组结尾有一句总结，给受众一个"落脚点"
- 总字数没有增加，但信息密度更合理，受众更容易吸收
