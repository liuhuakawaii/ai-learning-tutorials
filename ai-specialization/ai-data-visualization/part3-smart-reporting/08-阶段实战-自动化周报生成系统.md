## 场景引入

你的团队已经搭建了数据质量监控（第 6 课）和报表模板系统（第 7 课）。每周一早上，数据工程师手动跑 SQL、手动检查数据、手动把结果粘贴到模板里、手动发邮件。整个流程耗时 2 小时，而且每周都在重复。

运营总监问了一个很自然的问题："既然每一步都已经自动化了，为什么不能把它们串起来，让系统每周一早上自动生成周报？"

这个问题的本质是**流水线编排**。单独的模块（数据采集、质量检查、异常检测、图表生成、AI 摘要、模板渲染、推送）都已经存在，现在需要一个调度器把它们按正确的顺序、正确的依赖关系串联起来，并处理每一步可能出现的失败。

本课是 Part 3 的阶段实战。我们将构建一个完整的 MVP 周报系统，综合运用前七课的所有技术。这不是一个 demo，而是一个可以部署到生产环境的骨架——你只需要替换数据源和模板，就能在自己的业务中使用。

## 核心概念

### 一、系统架构总览

一个自动化周报系统由六个核心模块组成，它们按流水线方式协作。理解模块之间的数据流和依赖关系是设计系统的第一步。

```
┌──────────────────────────────────────────────────────────────────┐
│                    周报生成流水线                                  │
│                                                                  │
│  阶段 1: 数据准备                                                 │
│  ┌──────────┐    ┌──────────┐                                   │
│  │ 数据采集  │───→│ 质量检查  │                                   │
│  │ Collector │    │ Checker  │                                   │
│  └──────────┘    └────┬─────┘                                   │
│                       │                                          │
│                       ▼                                          │
│  阶段 2: 分析与生成                                               │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐                   │
│  │ 异常检测  │───→│ 图表生成  │───→│ AI 摘要  │                   │
│  │ Detector │    │ ChartGen │    │Summarizer│                   │
│  └──────────┘    └──────────┘    └────┬─────┘                   │
│                       │               │                          │
│                       ▼               ▼                          │
│  阶段 3: 组装与输出                                               │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │                    报表组装器 (Assembler)                  │   │
│  │  模板 + 数据 + 图表 + AI 文字 → 完整周报 HTML              │   │
│  └──────────────────────────┬───────────────────────────────┘   │
│                             │                                    │
│                             ▼                                    │
│  阶段 4: 审核与推送                                               │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐                   │
│  │ 人工审核  │───→│ 推送分发  │───→│ 历史存档  │                   │
│  │ Reviewer │    │ Notifier │    │ Archive  │                   │
│  └──────────┘    └──────────┘    └──────────┘                   │
└──────────────────────────────────────────────────────────────────┘
```

这个架构的关键设计决策是**阶段隔离**。每个阶段的输出是下一个阶段的输入，通过统一的数据结构传递。如果某个阶段失败，流水线可以从中断处恢复，而不需要从头开始。

### 二、流水线调度器设计

流水线调度器是系统的"大脑"。它负责决定每一步什么时候执行、失败了怎么办、超时了怎么处理。

```
┌──────────────────────────────────────────────────────────┐
│                  调度器状态机                              │
│                                                          │
│  PENDING ──→ RUNNING ──→ SUCCESS                        │
│                │                                         │
│                ├──→ FAILED ──→ RETRY (最多 N 次)         │
│                │              │                           │
│                │              └──→ DEAD (超过重试次数)    │
│                │                                         │
│                └──→ TIMEOUT ──→ CANCELLED                │
│                                                          │
│  每个步骤记录：                                           │
│  - 开始时间、结束时间、耗时                                │
│  - 输入数据的校验和（用于幂等判断）                         │
│  - 输出数据的快照（用于恢复和审计）                         │
│  - 错误堆栈（用于排查）                                   │
└──────────────────────────────────────────────────────────┘
```

调度器需要处理的边界情况比正常流程更多：数据库连接超时、LLM API 限流、模板渲染失败、推送渠道不可用。一个健壮的调度器不是"不会出错"，而是"出错后知道该怎么办"。

### 三、数据采集与质量把关

数据采集模块从多个数据源拉取原始数据，质量检查模块在数据进入分析流程之前验证其有效性。这两个模块必须紧密配合——采集到的数据如果质量不合格，后续所有分析都没有意义。

```
┌──────────────────────────────────────────────────────┐
│              数据采集 → 质量检查 流程                   │
│                                                      │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐          │
│  │ PostgreSQL│  │ API 接口  │  │ CSV 文件  │          │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘          │
│       │              │              │                │
│       └──────────────┼──────────────┘                │
│                      ▼                               │
│             ┌──────────────┐                         │
│             │  适配器层     │  每个数据源一个适配器     │
│             │  Adapter     │  统一输出 WeeklyMetrics  │
│             └──────┬───────┘                         │
│                    ▼                                 │
│  ┌──────────────────────────────────────────────┐   │
│  │  质量检查层                                    │   │
│  │  - 完整性: 关键字段是否为 NULL                 │   │
│  │  - 时效性: 数据是否在预期时间内更新             │   │
│  │  - 准确性: 数值是否在合理范围内                 │   │
│  │  - 唯一性: 是否存在重复记录                    │   │
│  └──────────────────────────────────────────────┘   │
│                      │                               │
│                      ▼                               │
│             ┌──────────────┐                         │
│             │ 质量报告      │                         │
│             │ pass / fail  │                         │
│             └──────────────┘                         │
└──────────────────────────────────────────────────────┘
```

质量检查失败时，系统有两个选择：阻断流水线（不生成周报），或者降级处理（生成周报但标注数据质量问题）。生产环境中，降级处理通常是更好的选择——一份带有"数据不完整"标注的周报，比完全没有周报更有价值。

### 四、AI 摘要与人工审核

LLM 负责将结构化数据转化为人类可读的分析文字。但 LLM 的输出不能直接发布——它可能产生事实错误、遗漏关键信息、或者语气不符合企业规范。因此需要一个人机协作的审核流程。

```
┌──────────────────────────────────────────────────┐
│              AI + 人工审核流程                     │
│                                                  │
│  数据输入 ──→ LLM 生成草稿                       │
│                  │                               │
│                  ▼                               │
│  ┌────────────────────────────────┐              │
│  │  自动校验                       │              │
│  │  - 数字是否与原始数据一致       │              │
│  │  - 是否包含禁止词               │              │
│  │  - 长度是否在合理范围           │              │
│  └──────────────┬─────────────────┘              │
│                  │                               │
│           ┌──────┴──────┐                        │
│           ▼             ▼                        │
│      校验通过       校验失败                      │
│           │             │                        │
│           ▼             ▼                        │
│  通知审核人        AI 重新生成                    │
│           │             │                        │
│     ┌─────┴─────┐       │                        │
│     ▼           ▼       │                        │
│  审核通过    需要修改    │                        │
│     │           │        │                        │
│     ▼           └────────┘                        │
│  推送发布       审核人提供反馈                     │
│                                                  │
└──────────────────────────────────────────────────┘
```

审核流程中最容易被忽视的环节是**超时处理**。如果审核人周一早上没有及时查看草稿，周报就一直卡在审核状态。系统需要一个升级机制：超过设定时间未审核，自动通知备选审核人，或者在标注"未经审核"的情况下自动发布。

### 五、模板渲染与多渠道推送

模板系统（第 7 课）负责将数据和文字组装成视觉上专业的报表。推送模块负责将渲染后的报表分发到不同渠道：邮件、飞书、钉钉、企业微信。

```
┌──────────────────────────────────────────────────┐
│              渲染 → 推送 流程                      │
│                                                  │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐   │
│  │ 模板引擎  │───→│ HTML 生成 │───→│ PDF 导出  │   │
│  │Handlebars│    │          │    │ (可选)    │   │
│  └──────────┘    └────┬─────┘    └──────────┘   │
│                       │                          │
│                       ▼                          │
│  ┌──────────────────────────────────────────┐   │
│  │  推送分发器 (Dispatcher)                   │   │
│  │                                          │   │
│  │  ┌────────┐ ┌────────┐ ┌────────┐       │   │
│  │  │  邮件   │ │  飞书   │ │  钉钉   │       │   │
│  │  │ SMTP   │ │ Webhook│ │ Webhook│       │   │
│  │  └────────┘ └────────┘ └────────┘       │   │
│  └──────────────────────────────────────────┘   │
│                                                  │
│  每个渠道的适配器负责：                            │
│  - 格式转换（HTML → 飞书卡片消息）                 │
│  - 内容截断（邮件可以长，IM 消息要精简）            │
│  - 发送失败重试                                   │
│  - 送达确认                                      │
└──────────────────────────────────────────────────┘
```

不同渠道对内容格式的要求差异很大。邮件支持完整的 HTML，飞书需要卡片消息的 JSON 格式，钉钉又是另一套格式。推送模块应该为每个渠道实现一个适配器，将统一的报表内容转换为目标格式。

```typescript
// src/pipeline/step-result.ts
import type { PipelineStepResult, PipelineStepStatus } from '../types.js'

export function createStepResult(stepName: string): PipelineStepResult {
  return {
    stepName,
    status: 'pending',
    startedAt: new Date().toISOString(),
  }
}

export function markRunning(result: PipelineStepResult): PipelineStepResult {
  return { ...result, status: 'running' as PipelineStepStatus, startedAt: new Date().toISOString() }
}

export function markSuccess(result: PipelineStepResult, output: unknown): PipelineStepResult {
  const now = new Date()
  return {
    ...result,
    status: 'success',
    finishedAt: now.toISOString(),
    durationMs: now.getTime() - new Date(result.startedAt).getTime(),
    output,
  }
}

export function markFailed(result: PipelineStepResult, error: Error): PipelineStepResult {
  const now = new Date()
  return {
    ...result,
    status: 'failed',
    finishedAt: now.toISOString(),
    durationMs: now.getTime() - new Date(result.startedAt).getTime(),
    error: error.message,
  }
}
```

```typescript
// src/pipeline/scheduler.ts
import type { PipelineStepResult } from '../types.js'
import { createStepResult, markRunning, markSuccess, markFailed } from './step-result.js'

export interface PipelineContext {
  reportId: string
  startDate: Date
  endDate: Date
  steps: PipelineStepResult[]
  data: Map<string, unknown>
}

type StepFunction = (ctx: PipelineContext) => Promise<unknown>

interface PipelineStep {
  name: string
  execute: StepFunction
  maxRetries: number
  timeoutMs: number
  continueOnFailure: boolean
}

export class PipelineScheduler {
  private steps: PipelineStep[] = []
  private onStepComplete?: (result: PipelineStepResult) => void

  addStep(config: PipelineStep): void {
    this.steps.push(config)
  }

  setOnStepComplete(callback: (result: PipelineStepResult) => void): void {
    this.onStepComplete = callback
  }

  async execute(ctx: PipelineContext): Promise<PipelineContext> {
    for (const step of this.steps) {
      let result = createStepResult(step.name)
      let lastError: Error | null = null

      for (let attempt = 0; attempt <= step.maxRetries; attempt++) {
        result = markRunning(result)

        try {
          const output = await this.withTimeout(
            step.execute(ctx),
            step.timeoutMs,
            step.name
          )
          result = markSuccess(result, output)
          ctx.data.set(step.name, output)
          lastError = null
          break
        } catch (err) {
          lastError = err instanceof Error ? err : new Error(String(err))
          if (attempt < step.maxRetries) {
            const delayMs = Math.min(1000 * Math.pow(2, attempt), 10000)
            console.log(`[调度器] 步骤 "${step.name}" 第 ${attempt + 1} 次失败，${delayMs}ms 后重试`)
            await new Promise(resolve => setTimeout(resolve, delayMs))
          }
        }
      }

      if (lastError) {
        result = markFailed(result, lastError)
        if (!step.continueOnFailure) {
          ctx.steps.push(result)
          this.onStepComplete?.(result)
          console.error(`[调度器] 步骤 "${step.name}" 失败，流水线中断: ${lastError.message}`)
          return ctx
        }
        console.warn(`[调度器] 步骤 "${step.name}" 失败，继续执行: ${lastError.message}`)
      }

      ctx.steps.push(result)
      this.onStepComplete?.(result)
      console.log(
        `[调度器] 步骤 "${step.name}" ${result.status} ` +
        `(${result.durationMs}ms)`
      )
    }

    return ctx
  }

  private withTimeout<T>(promise: Promise<T>, ms: number, label: string): Promise<T> {
    return new Promise<T>((resolve, reject) => {
      const timer = setTimeout(
        () => reject(new Error(`步骤 "${label}" 超时 (${ms}ms)`)),
        ms
      )
      promise.then(
        val => { clearTimeout(timer); resolve(val) },
        err => { clearTimeout(timer); reject(err) }
      )
    })
  }
}
```

### 第三步：数据采集器

```typescript
// src/data/collector.ts
import { Pool } from 'pg'
import type { WeeklyMetrics, MetricItem, DailyDataPoint, ProductItem, ChannelItem } from '../types.js'

export class WeeklyDataCollector {
  private pool: Pool

  constructor(databaseUrl: string) {
    this.pool = new Pool({ connectionString: databaseUrl })
  }

  async collect(startDate: Date, endDate: Date): Promise<WeeklyMetrics> {
    const prevStart = new Date(startDate.getTime() - (endDate.getTime() - startDate.getTime()))

    const [coreMetrics, dailyTrend, topProducts, channelBreakdown] = await Promise.all([
      this.fetchCoreMetrics(startDate, endDate, prevStart),
      this.fetchDailyTrend(startDate, endDate),
      this.fetchTopProducts(startDate, endDate),
      this.fetchChannelBreakdown(startDate, endDate),
    ])

    return {
      dateRange: {
        start: startDate.toISOString().slice(0, 10),
        end: endDate.toISOString().slice(0, 10),
      },
      coreMetrics,
      dailyTrend,
      topProducts,
      channelBreakdown,
      anomalies: [],
    }
  }

  private async fetchCoreMetrics(start: Date, end: Date, prevStart: Date): Promise<MetricItem[]> {
    const query = `
      SELECT
        COUNT(DISTINCT user_id) AS weekly_active_users,
        COUNT(*) AS order_count,
        COALESCE(SUM(amount), 0) AS gmv,
        COALESCE(AVG(amount), 0) AS avg_order_value
      FROM orders
      WHERE created_at >= $1 AND created_at < $2
    `

    const [current, previous] = await Promise.all([
      this.pool.query(query, [start, end]),
      this.pool.query(query, [prevStart, start]),
    ])

    const c = current.rows[0]
    const p = previous.rows[0]

    return [
      this.buildMetric('周活跃用户', Number(c.weekly_active_users), Number(p.weekly_active_users), '人'),
      this.buildMetric('订单量', Number(c.order_count), Number(p.order_count), '单'),
      this.buildMetric('GMV', Number(c.gmv), Number(p.gmv), '元'),
      this.buildMetric('平均客单价', Number(c.avg_order_value), Number(p.avg_order_value), '元'),
    ]
  }

  private async fetchDailyTrend(start: Date, end: Date): Promise<DailyDataPoint[]> {
    const query = `
      SELECT DATE(created_at) AS date, COUNT(*) AS orders, SUM(amount) AS gmv
      FROM orders
      WHERE created_at >= $1 AND created_at < $2
      GROUP BY DATE(created_at)
      ORDER BY date
    `
    const { rows } = await this.pool.query(query, [start, end])
    const trend: DailyDataPoint[] = []

    for (const row of rows) {
      const dateStr = row.date.toISOString().slice(0, 10)
      trend.push({ date: dateStr, value: Number(row.orders), metric: '订单量' })
      trend.push({ date: dateStr, value: Number(row.gmv), metric: 'GMV' })
    }

    return trend
  }

  private async fetchTopProducts(start: Date, end: Date): Promise<ProductItem[]> {
    const query = `
      SELECT p.name, COUNT(*) AS sales, SUM(o.amount) AS revenue
      FROM orders o JOIN products p ON o.product_id = p.id
      WHERE o.created_at >= $1 AND o.created_at < $2
      GROUP BY p.name ORDER BY revenue DESC LIMIT 10
    `
    const { rows } = await this.pool.query(query, [start, end])
    return rows.map((row, i) => ({
      rank: i + 1,
      name: row.name,
      sales: Number(row.sales),
      revenue: Number(row.revenue),
    }))
  }

  private async fetchChannelBreakdown(start: Date, end: Date): Promise<ChannelItem[]> {
    const query = `
      SELECT source_channel, COUNT(DISTINCT user_id) AS users,
        COUNT(*) AS orders, SUM(amount) AS revenue
      FROM orders
      WHERE created_at >= $1 AND created_at < $2
      GROUP BY source_channel ORDER BY revenue DESC
    `
    const { rows } = await this.pool.query(query, [start, end])
    return rows.map(row => ({
      channel: row.source_channel || '直接访问',
      users: Number(row.users),
      orders: Number(row.orders),
      revenue: Number(row.revenue),
      conversionRate: Number(row.orders) / Math.max(Number(row.users), 1) * 100,
    }))
  }

  private buildMetric(name: string, current: number, previous: number, unit: string): MetricItem {
    const change = previous > 0 ? ((current - previous) / previous) * 100 : 0
    return { name, current, previous, change: Math.round(change * 100) / 100, unit }
  }

  async close(): Promise<void> {
    await this.pool.end()
  }
}
```

```typescript
        }
      },

      name: '数值合理性',
      dimension: 'accuracy',
      check: (metrics) => {
        const negatives = metrics.coreMetrics.filter(m => m.current < 0 && m.name !== '客诉率')
        return {
          rule: '数值合理性',
          dimension: 'accuracy',
          passed: negatives.length === 0,

            ? '所有指标数值在合理范围内'
            : `以下指标出现负值: ${negatives.map(m => `${m.name}=${m.current}`).join(', ')}`,
        }
      },
    })

    this.rules.push({
      name: '数据时效性',
      dimension: 'timeliness',
      check: (metrics) => {
        const endDate = new Date(metrics.dateRange.end)
        const daysSinceEnd = (Date.now() - endDate.getTime()) / 86400000
        const passed = daysSinceEnd <= 3
        return {
          rule: '数据时效性',
          dimension: 'timeliness',
          passed,
          message: passed
            ? `数据截止日期在 ${Math.round(daysSinceEnd)} 天前，时效性良好`
            : `数据截止日期在 ${Math.round(daysSinceEnd)} 天前，可能过于陈旧`,
        }
      },
    })

    this.rules.push({
      name: '环比变化合理性',
      dimension: 'accuracy',
      check: (metrics) => {
        const extremeChanges = metrics.coreMetrics.filter(m => Math.abs(m.change) > 200)
        return {
          rule: '环比变化合理性',
          dimension: 'accuracy',
          passed: extremeChanges.length === 0,
          message: extremeChanges.length === 0
            ? '所有指标环比变化在正常范围内'
            : `以下指标环比变化超过 200%: ${extremeChanges.map(m => `${m.name} ${m.change}%`).join(', ')}`,
        }
      },
    })
  }

  check(metrics: WeeklyMetrics): QualityReport {
    const results = this.rules.map(rule => rule.check(metrics))
    const passedCount = results.filter(r => r.passed).length
    const score = Math.round((passedCount / results.length) * 100)
    const passed = results.every(r => r.passed) || score >= 80

    return {
      passed,
      checks: results,
      score,
      summary: passed
        ? `质量评分 ${score}/100，${passedCount}/${results.length} 项检查通过`
        : `质量评分 ${score}/100，${results.length - passedCount} 项检查未通过，建议排查后再生成报表`,
    }
  }
```

```typescript
import type { WeeklyMetrics, AnomalyItem, MetricItem } from '../types.js'

interface AnomalyRule {
  metricName: string
  maxChangePercent: number
  severity: 'low' | 'medium' | 'high'
}

export class AnomalyDetector {
  private rules: AnomalyRule[]

  constructor(rules?: AnomalyRule[]) {
    this.rules = rules || [
      { metricName: '周活跃用户', maxChangePercent: 30, severity: 'medium' },
      { metricName: '订单量', maxChangePercent: 50, severity: 'high' },
      { metricName: 'GMV', maxChangePercent: 50, severity: 'high' },
      { metricName: '平均客单价', maxChangePercent: 20, severity: 'medium' },
    ]
  }

  detect(metrics: WeeklyMetrics): AnomalyItem[] {
    const anomalies: AnomalyItem[] = []

    for (const metric of metrics.coreMetrics) {
      const rule = this.rules.find(r => r.metricName === metric.name)
      if (!rule) continue

      if (Math.abs(metric.change) > rule.maxChangePercent) {
        const direction = metric.change > 0 ? '上升' : '下降'
        anomalies.push({
          metric: metric.name,
          description: `${metric.name} 环比${direction} ${Math.abs(metric.change).toFixed(1)}%，超过阈值 ${rule.maxChangePercent}%`,
          severity: rule.severity,
          detectedAt: new Date().toISOString(),
        })
      }
    }

    anomalies.push(...this.detectDataGaps(metrics))
    anomalies.push(...this.detectZeroValues(metrics))

    return anomalies
  }

  private detectDataGaps(metrics: WeeklyMetrics): AnomalyItem[] {
    const anomalies: AnomalyItem[] = []
    const uniqueDates = new Set(metrics.dailyTrend.map(d => d.date))

    if (uniqueDates.size < 5) {
      anomalies.push({
        metric: '数据完整性',
        description: `本周仅有 ${uniqueDates.size} 天的数据，可能存在数据缺失`,
        severity: 'medium',
        detectedAt: new Date().toISOString(),
      })
    }

    return anomalies
  }

  private detectZeroValues(metrics: WeeklyMetrics): AnomalyItem[] {
    const anomalies: AnomalyItem[] = []

    for (const metric of metrics.coreMetrics) {
      if (metric.current === 0 && metric.previous > 0) {
        anomalies.push({
          metric: metric.name,
          description: `${metric.name} 本周为 0，上周为 ${metric.previous}，可能数据异常`,
          severity: 'high',
          detectedAt: new Date().toISOString(),
        })
      }
    }

    return anomalies
  }
}
```

```typescript
      '',
      '核心指标:',

        `  - ${m.name}: 本周 ${m.current}${m.unit}，上周 ${m.previous}${m.unit}，环比 ${m.change > 0 ? '+' : ''}${m.change}%`
      ),
      '',
      '渠道分布:',
      ...metrics.channelBreakdown.map(c =>
        `  - ${c.channel}: 用户 ${c.users}，订单 ${c.orders}，收入 ${c.revenue}，转化率 ${c.conversionRate.toFixed(1)}%`
      ),
    ]

    if (metrics.anomalies.length > 0) {
```

```typescript
// src/output/reviewer.ts
import type { WeeklyReport } from '../types.js'

export interface ReviewDecision {
  reportId: string
  decision: 'approve' | 'reject'
  comment?: string
  reviewer: string
  decidedAt: string
}

export class ReviewManager {
  private pendingReviews = new Map<string, WeeklyReport>()
  private timeoutMs: number
  private onTimeout?: (report: WeeklyReport) => void

  constructor(timeoutMs = 3600000) {
    this.timeoutMs = timeoutMs
  }

  setTimeoutHandler(handler: (report: WeeklyReport) => void): void {
    this.onTimeout = handler
  }

  submitForReview(report: WeeklyReport): void {
    report.status = 'pending_review'
    this.pendingReviews.set(report.id, report)
    console.log(`[审核] 周报 ${report.id} 已提交审核`)

    setTimeout(() => {
      if (this.pendingReviews.has(report.id)) {
        console.warn(`[审核] 周报 ${report.id} 审核超时，触发升级通知`)
        this.onTimeout?.(report)
      }
    }, this.timeoutMs)
  }

  review(decision: ReviewDecision): WeeklyReport | null {
    const report = this.pendingReviews.get(decision.reportId)
    if (!report) return null

    if (decision.decision === 'approve') {
      report.status = 'approved'
      report.publishedAt = new Date().toISOString()
      console.log(`[审核] 周报 ${decision.reportId} 已通过审核 (${decision.reviewer})`)
    } else {
      report.status = 'rejected'
      console.log(`[审核] 周报 ${decision.reportId} 被驳回: ${decision.comment}`)
    }

    this.pendingReviews.delete(decision.reportId)
    return report
  }

  getPendingReports(): WeeklyReport[] {
    return Array.from(this.pendingReviews.values())
  }
}
```

```typescript
    const filepath = join(this.archiveDir, `${reportId}.json`)
    if (!existsSync(filepath)) return null

    const content = readFileSync(filepath, 'utf-8')
    return JSON.parse(content) as WeeklyReport
  }

      .filter(f => f.endsWith('.json'))
      .sort()
      .reverse()
      .slice(0, count)

    return files.map(f => {
      const report = this.load(f.replace('.json', ''))
      return report ? {
        id: report.id,
        dateRange: `${report.dateRange.start} ~ ${report.dateRange.end}`,
        status: report.status,
        createdAt: report.createdAt,
      } : null
    }).filter(Boolean) as Array<{ id: string; dateRange: string; status: string; createdAt: string }>
  }
```

## 常见误区

### 误区一：所有步骤都失败才告警

很多团队只在流水线整体失败时才通知，但流水线中某个步骤失败后继续执行（`continueOnFailure`），最终也生成了周报——只是这份周报可能缺少异常检测或 AI 摘要。如果没人关注中间步骤的失败，用户拿到的是一份"看起来正常但其实不完整"的报表。

**正确做法**：每一步的执行结果都应该记录和通知。即使流水线继续执行了，也要在最终报表中标注"AI 摘要生成失败，使用默认文案"之类的信息，让使用者知道哪些部分是降级处理的。

### 误区二：AI 摘要直接发布不做校验

LLM 可能产生幻觉——在摘要中引用不存在的数据、把上周的数字说成是这周的、或者编造一个不存在的趋势。如果直接发布，会严重损害报表系统的可信度。

**正确做法**：AI 生成的摘要必须经过自动校验（数字是否与原始数据一致、是否遗漏关键指标）和人工审核两道关卡。自动校验可以拦截明显的事实错误，人工审核负责判断分析逻辑和语气是否合适。

### 误区三：流水线没有幂等设计

如果流水线执行到一半崩溃了，重启后从头开始执行——数据采集多跑了一遍，AI 摘要多调用了一次 API，报表存档多了一份。在定时调度场景下（比如每周一早上 8 点自动执行），这个问题会反复出现。

**正确做法**：每个步骤的输入应该包含一个可计算的校验和（比如日期范围 + 数据源标识）。调度器在执行前检查"这个输入是否已经处理过"，如果已处理则跳过。存档模块使用业务 ID（而非自增 ID）作为唯一标识，重复写入时覆盖而非新增。

### 误区四：审核超时没有兜底机制

周报提交审核后，如果审核人周一早上开会忘了审，周报就一直卡在"待审核"状态。到了周二，这份周报已经失去了时效性。

**正确做法**：设置审核超时时间（比如 2 小时），超时后自动升级通知备选审核人。如果仍然无人处理，在周报上标注"未经审核"后自动发布。一份有瑕疵的周报比没有周报更有价值。

### 小结

本课我们构建了一个完整的自动化周报生成系统：

1. **流水线架构**：将六个模块（采集、检查、检测、摘要、组装、推送）串联成一条可调度的流水线，每个模块独立可替换
2. **调度器设计**：实现了带重试、超时、降级策略的流水线调度器，能够优雅地处理各种失败场景
3. **数据质量把关**：在数据进入分析流程之前进行完整性、准确性、时效性检查，不合格数据触发告警
4. **异常检测**：基于阈值规则自动识别指标异常，支持数据完整性和零值检测
5. **AI 摘要**：使用 LLM 将结构化数据转化为专业分析文字，并设计了自动校验 + 人工审核的双重保障
6. **存档与审计**：每份周报都有完整的元数据记录，支持历史查询和版本追溯

#### 练习一：实现定时调度

基于 `node-cron` 或系统 crontab，实现每周一早上 8 点自动触发周报生成流水线。要求：
- 支持配置不同的执行时间
- 记录每次执行的开始时间、结束时间和结果状态

- 对比核心指标的绝对值和环比变化
- 识别"从异常恢复到正常"和"从正常变为异常"的指标
- 对比结果作为额外章节插入周报

## 参考答案

### 练习一

**思路**：定时调度的核心是可靠触发和防重叠。使用 `node-cron` 设置定时任务，用一个 `isRunning` 标志位防止重叠执行。每次执行记录日志，便于排查问题。

**答案**：

```typescript
// src/scheduler/cron-runner.ts
import cron from 'node-cron'
import { appendFileSync, existsSync, writeFileSync } from 'node:fs'

interface ScheduleConfig {
  cronExpression: string
  reportEndDate: () => Date
  logFile: string
}

interface ExecutionLog {
  startedAt: string
  finishedAt?: string
  status: 'running' | 'success' | 'failed' | 'skipped'
  error?: string
}

export class CronReportRunner {
  private isRunning = false
  private config: ScheduleConfig
  private generateFn: (endDate: Date) => Promise<unknown>

  constructor(config: ScheduleConfig, generateFn: (endDate: Date) => Promise<unknown>) {
    this.config = config
    this.generateFn = generateFn
  }

  start(): void {
    if (!cron.validate(this.config.cronExpression)) {
      throw new Error(`无效的 cron 表达式: ${this.config.cronExpression}`)
    }

    cron.schedule(this.config.cronExpression, async () => {
      if (this.isRunning) {
        this.log({ startedAt: new Date().toISOString(), status: 'skipped', error: '上一次执行尚未完成' })
        console.warn('[定时调度] 跳过本次执行：上一次尚未完成')
        return
      }

      this.isRunning = true
      const log: ExecutionLog = { startedAt: new Date().toISOString(), status: 'running' }
      this.log(log)

      try {
        const endDate = this.config.reportEndDate()
        await this.generateFn(endDate)
        log.status = 'success'
        log.finishedAt = new Date().toISOString()
      } catch (err) {
        log.status = 'failed'
        log.error = err instanceof Error ? err.message : String(err)
        log.finishedAt = new Date().toISOString()
      } finally {
        this.isRunning = false
        this.log(log)
      }
    })

    console.log(`[定时调度] 已启动，cron: ${this.config.cronExpression}`)
  }

  private log(entry: ExecutionLog): void {
    const line = JSON.stringify(entry) + '\n'
    appendFileSync(this.config.logFile, line, 'utf-8')
  }
}
```

### 练习二

**思路**：降级周报的核心是在 AI 摘要不可用时，用规则引擎根据数据特征生成模板化文案。通过判断核心指标的变化方向和幅度，从预定义的文案模板中选择合适的句子组合。

**答案**：

```typescript
// src/analysis/fallback-summarizer.ts
import type { WeeklyMetrics, AISummary } from '../types.js'

export class FallbackSummarizer {
  generate(metrics: WeeklyMetrics): AISummary {
    const executiveSummary = this.buildExecutiveSummary(metrics)
    const keyFindings = this.buildKeyFindings(metrics)
    const recommendations = this.buildRecommendations(metrics)
    const riskAlerts = this.buildRiskAlerts(metrics)

    return { executiveSummary, keyFindings, recommendations, riskAlerts }
  }

  private buildExecutiveSummary(metrics: WeeklyMetrics): string {
    const gmv = metrics.coreMetrics.find(m => m.name === 'GMV')
    const orders = metrics.coreMetrics.find(m => m.name === '订单量')

    if (!gmv || !orders) {
      return '本周业务数据已汇总，以下为核心指标概览。'
    }

    const gmvTrend = gmv.change > 0 ? '增长' : '下降'
    const orderTrend = orders.change > 0 ? '增长' : '下降'

    return `本周 GMV ${gmvTrend} ${Math.abs(gmv.change).toFixed(1)}%，` +
      `订单量${orderTrend} ${Math.abs(orders.change).toFixed(1)}%。` +
      `以下为详细数据分析。`
  }

  private buildKeyFindings(metrics: WeeklyMetrics): string[] {
    const findings: string[] = []

    for (const metric of metrics.coreMetrics) {
      if (Math.abs(metric.change) > 10) {
        const direction = metric.change > 0 ? '增长' : '下降'
        findings.push(
          `${metric.name}环比${direction} ${Math.abs(metric.change).toFixed(1)}%，` +
          `从 ${metric.previous.toLocaleString('zh-CN')} 变为 ${metric.current.toLocaleString('zh-CN')}`
        )
      }
    }

    if (metrics.topProducts.length > 0) {
      const top = metrics.topProducts[0]
      findings.push(`本周收入最高的商品是「${top.name}」，贡献收入 ¥${top.revenue.toLocaleString('zh-CN')}`)
    }

    if (findings.length === 0) {
      findings.push('本周各核心指标环比变化均在正常范围内，业务运行平稳')
    }

    return findings
  }

  private buildRecommendations(metrics: WeeklyMetrics): string[] {
    const recommendations: string[] = []
    const gmv = metrics.coreMetrics.find(m => m.name === 'GMV')

    if (gmv && gmv.change < -10) {
      recommendations.push('GMV 出现明显下降，建议排查主要渠道的流量和转化率变化')
    }

    const conversionMetrics = metrics.channelBreakdown.filter(c => c.conversionRate < 1)
    if (conversionMetrics.length > 0) {
      recommendations.push(
        `以下渠道转化率低于 1%: ${conversionMetrics.map(c => c.channel).join('、')}，建议优化投放策略`
      )
    }

    return recommendations
  }

  private buildRiskAlerts(metrics: WeeklyMetrics): string[] {
    const alerts: string[] = []

    for (const metric of metrics.coreMetrics) {
      if (metric.current === 0 && metric.previous > 0) {
        alerts.push(`⚠️ ${metric.name} 本周数据为 0，请核实数据采集是否正常`)
      }
    }

    return alerts
  }
}
```

**要点**：降级摘要的质量取决于预定义模板的覆盖度。建议持续收集 AI 摘要的常见句式，逐步丰富模板库。当降级摘要被人工修改后，可以将修改后的版本加入模板库，实现"越用越好"。

### 练习三

**思路**：周报对比需要保存每期周报的结构化数据（不仅仅是 HTML），然后逐指标比较。关键设计是识别"趋势反转"——从增长变为下降，或从下降变为增长。

**答案**：

```typescript
// src/output/comparator.ts'
import type { WeeklyReport, MetricItem } from '../types.js'

export interface MetricComparison {
  metricName: string
  thisWeek: number
  lastWeek: number
  thisWeekChange: number
  lastWeekChange: number
  trendReversal: boolean
  trendDirection: 'improving' | 'declining' | 'stable'
  commentary: string
}

export interface ComparisonReport {
  thisReportId: string
  lastReportId: string
  comparisons: MetricComparison[]
  summary: string
}

export class WeeklyComparator {
  compare(thisReport: WeeklyReport, lastReport: WeeklyReport): ComparisonReport {
    const comparisons: MetricComparison[] = []

    for (const thisMetric of thisReport.metrics.coreMetrics) {
      const lastMetric = lastReport.metrics.coreMetrics.find(m => m.name === thisMetric.name)
      if (!lastMetric) continue

      const trendReversal = this.isTrendReversal(thisMetric.change, lastMetric.change)
      const trendDirection = this.classifyTrend(thisMetric.change, lastMetric.change)

      comparisons.push({
        metricName: thisMetric.name,
        thisWeek: thisMetric.current,
        lastWeek: lastMetric.current,
        thisWeekChange: thisMetric.change,
        lastWeekChange: lastMetric.change,
        trendReversal,
        trendDirection,
        commentary: this.generateCommentary(thisMetric, lastMetric, trendReversal, trendDirection),
      })
    }

    const summary = this.buildSummary(comparisons)

    return {
      thisReportId: thisReport.id,
      lastReportId: lastReport.id,
      comparisons,
      summary,
    }
  }

  private isTrendReversal(thisChange: number, lastChange: number): boolean {
    return (thisChange > 0 && lastChange < 0) || (thisChange < 0 && lastChange > 0)
  }

  private classifyTrend(thisChange: number, lastChange: number): 'improving' | 'declining' | 'stable' {
    if (Math.abs(thisChange) < 2 && Math.abs(lastChange) < 2) return 'stable'
    if (thisChange > lastChange) return 'improving'
    return 'declining'
  }

  private generateCommentary(
    current: MetricItem,
    previous: MetricItem,
    isReversal: boolean,
    direction: 'improving' | 'declining' | 'stable'
  ): string {
    if (isReversal) {
      const from = previous.change > 0 ? '增长' : '下降'
      const to = current.change > 0 ? '增长' : '下降'
      return `${current.name} 趋势反转：上周${from} ${Math.abs(previous.change).toFixed(1)}%，本周转为${to} ${Math.abs(current.change).toFixed(1)}%`
    }

    if (direction === 'stable') {
      return `${current.name} 连续两周保持平稳`
    }

    if (direction === 'improving') {
      return `${current.name} 表现改善：上周环比 ${previous.change.toFixed(1)}%，本周环比 ${current.change.toFixed(1)}%`
    }

    return `${current.name} 表现走弱：上周环比 ${previous.change.toFixed(1)}%，本周环比 ${current.change.toFixed(1)}%`
  }

  private buildSummary(comparisons: MetricComparison[]): string {
    const reversals = comparisons.filter(c => c.trendReversal)
    const improving = comparisons.filter(c => c.trendDirection === 'improving')
    const declining = comparisons.filter(c => c.trendDirection === 'declining')

    const parts: string[] = []

    if (reversals.length > 0) {
      parts.push(`本周有 ${reversals.length} 个指标出现趋势反转: ${reversals.map(c => c.metricName).join('、')}`)
    }

    if (improving.length > 0) {
      parts.push(`${improving.length} 个指标表现改善`)
    }

    if (declining.length > 0) {
      parts.push(`${declining.length} 个指标表现走弱，需关注`)
    }

    return parts.join('。') || '本周各指标与上周基本持平'
  }
}
```

**要点**：趋势反转的识别对管理层特别有价值——它能提前预警"一直在变好的指标开始变差了"。建议在周报中将趋势反转的指标放在最显眼的位置。
