## 场景引入

每周五下午四点，数据分析师小林准时打开 BI 平台，导出本周的销售数据。接下来的一个多小时，他要做一件重复了无数次的事：把几十个指标的变化整理成一段管理层能看懂的文字，发到公司高管群里。

"本周 GMV 为 1,230 万，环比下降 3.2%，同比增长 15.8%。其中华东区域表现突出，贡献了 42% 的增量。但新用户转化率持续走低，从上周的 4.1% 降至 3.7%，需要关注获客渠道质量……"

这段话的信息全部来自数据表格。小林需要做的事情包括：从表格中挑选最重要的 5-8 个指标，计算同比环比，判断哪些变化值得关注，把数字组织成通顺的句子，最后加上自己的业务判断。整个过程耗时 1-2 小时，而且高度依赖个人经验——换个分析师来写，措辞和侧重点可能完全不同。

问题来了：**这个过程能否自动化？** 如果 AI 能直接读取数据表格，自动生成这样的摘要，每周就能省出一个多小时，而且输出质量更稳定。

这就是数据摘要生成（Data Summarization）要解决的问题：将结构化数据自动转化为人类可读的自然语言描述，并提炼出关键洞察。本课会从最简单的模板填充方法讲起，逐步演进到 LLM 驱动的智能摘要系统。

## 核心概念

### 一、数据摘要的三种粒度

数据摘要不是"把数字念一遍"。根据信息密度和分析深度，摘要可以分为三个层次：

```
数据摘要的三个层次：

┌─────────────────────────────────────────────────────────┐
│                                                         │
│   第一层：概要型摘要（What）                              │
│   "本周 GMV 为 1,230 万，环比下降 3.2%"                  │
│   → 适合：日报、数据看板顶部的文字说明                     │
│                                                         │
│   ┌─────────────────────────────────────────────────┐   │
│   │                                                 │   │
│   │   第二层：对比型摘要（How）                        │   │
│   │   "GMV 下降 3.2%，但华东逆势增长 8%，             │   │
│   │    华南持平，华北下降 12% 拖累整体"                │   │
│   │   → 适合：周报、月报、管理层例会                   │   │
│   │                                                 │   │
│   │   ┌─────────────────────────────────────────┐   │   │
│   │   │                                         │   │   │
│   │   │   第三层：解释型摘要（Why）                │   │   │
│   │   │   "GMV 下降主要由华北区域导致，            │   │   │
│   │   │    该区域大客户采购量减少 30%，            │   │   │
│   │   │    原因是竞品 X 在 3 月启动了              │   │   │
│   │   │    价格战，建议启动针对性促销"             │   │   │
│   │   │   → 适合：专题分析、决策建议               │   │   │
│   │   │                                         │   │   │
│   │   └─────────────────────────────────────────┘   │   │
│   └─────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
```

**概要型摘要**是最基础的层次，核心工作是"选数字 + 翻译成文字"。一张报表可能有上百个指标，但摘要只能覆盖 5-10 个关键点。这一层的难点不是语言生成，而是**信息选择**——哪些指标值得出现在摘要里？通常的策略是选取变化幅度最大的、绝对值最高的、或者与业务目标直接相关的指标。

**对比型摘要**在概要的基础上增加了维度拆解。不只是说"GMV 下降了"，而是告诉读者"下降来自哪里"。这需要对数据做分组聚合和交叉分析，把总体趋势拆解到区域、渠道、品类等维度上。

**解释型摘要**是最难的层次，它需要给出"为什么"。这不仅需要数据分析能力，还需要业务知识——竞品动作、季节因素、政策变化等外部信息。纯数据驱动的系统通常只能做到"指标 A 下降与指标 B 下降高度相关"，真正的因果解释往往需要 LLM 结合业务上下文来生成。

### 二、基于规则的摘要生成

最简单也最可靠的摘要方法是**模板填充**：预先定义一组语言模板，运行时根据数据选择合适的模板并填入数值。

```
模板填充的工作流程：

原始数据：                        语义分类：
  指标: GMV                       方向: 下降
  当前值: 1230万                   幅度: 小幅（<5%）
  上期值: 1270万                   语义标签: decline_slight
  变化率: -3.15%

模板库：                          生成结果：
  decline_slight:                  "GMV 为 1,230 万，
    "{指标}为{当前值}，                较上期小幅下降 3.15%"
     较上期小幅下降{幅度}"
    "{指标}达到{当前值}，
     环比略有回落，降幅{幅度}"
```

模板方法的关键是**语义分类的粒度**。你需要为每种组合准备模板：方向（上升/下降/持平）× 幅度（大幅/中幅/微幅）× 指标类型（金额/比率/数量）。一个覆盖 3 种方向、3 种幅度、5 种指标类型的模板库，就需要至少 45 个模板变体，才能避免生成的文字千篇一律。

模板方法有两个明显的优势。第一是**数字绝对准确**——所有数值都直接来自数据，不存在 LLM 幻觉的风险。第二是**生成速度极快**——只是字符串拼接，毫秒级完成。

但它也有一个根本限制：**只能描述单个指标的变化，无法生成跨指标的关联分析**。"GMV 下降的同时退货率上升，说明产品质量可能出了问题"——这种洞察需要理解指标之间的业务关系，纯模板无法胜任。

在实际工程中，模板方法和 LLM 方法通常结合使用：用模板保证关键数字的准确性，用 LLM 生成更有洞察力的分析性文字。

### 三、LLM 驱动的智能摘要

LLM 用于数据摘要有两种模式：端到端生成和增强式生成。它们的架构差异如下：

```
模式一：端到端生成
  数据表格 ──────────────────────▶ LLM ──▶ 摘要文本

  优点：实现简单，不需要预处理
  缺点：表格太大时会截断；LLM 可能算错数字

模式二：增强式生成（推荐）
  数据表格 ──▶ 预处理引擎 ──▶ 结构化发现 ──▶ LLM ──▶ 摘要文本
                 │                │
             异常检测          关键发现列表
             同比环比          趋势判断
             排名变化          维度归因

  优点：数字准确，LLM 专注于文字表达
  缺点：需要构建预处理引擎
```

端到端生成的最大问题是**数字准确性**。LLM 不擅长精确计算——你让它从表格中读取"华东区域 Q1 GMV 是 4,230 万"，它可能会说成"4,300 万"。这个偏差在正式报告中是不可接受的。

增强式生成的思路是：**让程序做计算，让 LLM 做表达。** 先用 Python 代码精确计算同比/环比、排名变化、异常检测等，把结果整理成结构化的"关键发现列表"，再交给 LLM 组织成通顺的文字。这样既保证了数字准确，又利用了 LLM 的语言能力。

设计 LLM 摘要的 prompt 时，有几个关键技巧：

1. **提供结构化输入**——不要把原始表格丢给 LLM，而是把预处理后的关键发现以 JSON 或列表形式提供
2. **明确输出格式**——要求 LLM 按照"总述 + 分维度 + 建议"的结构输出
3. **限制篇幅**——LLM 倾向于写长，但管理层摘要通常要求 150-300 字
4. **标注数据置信度**——对于预测性结论，要求 LLM 标注"基于历史趋势推断"等限定语

### 四、多维度数据的摘要压缩

当数据维度很多时（区域 × 渠道 × 品类 × 时间），摘要面临一个核心矛盾：**信息太多与篇幅太短**。一张包含 5 个区域、4 个渠道、10 个品类的交叉表，理论上可以产生 200 个数据点，但摘要只能覆盖 5-10 个关键信息。

解决这个矛盾需要一套**信息优先级排序**机制：

```
信息优先级排序算法：

输入：所有数据点的分析结果
输出：Top-N 最重要的发现

排序权重：
  变化幅度得分 = |变化率| × 0.35
  绝对值得分   = normalize(绝对值) × 0.25
  业务重要性   = 指标权重 × 0.25
  异常程度     = z_score × 0.15

示例：
  发现 1: GMV 下降 3.2%    → 得分 0.72（高权重指标，变化中等）
  发现 2: 华东增长 8%       → 得分 0.65（区域维度，变化较大）
  发现 3: 办公用品增长 150% → 得分 0.58（小品类，异常程度高）
  发现 4: 华北下降 12%      → 得分 0.55（区域维度，变化较大）
  ...

取 Top-5 输出到摘要
```

除了排序，还需要做**信息去重**。如果"GMV 下降"和"订单量下降"说的是同一件事（客单价不变的情况下），摘要只需要提一个。去重的方法是计算发现之间的相关性——当两个指标的变化方向和维度高度一致时，合并为一条更高级别的洞察。

### 五、摘要质量评估

生成的摘要是否合格？需要从三个维度系统评估：

```
摘要质量三角：

           准确性
          /      \
         /   ✓    \
        /          \
       /____________\
   完整性 ──────── 可读性


准确性（Accuracy）— 可自动验证：
  ✓ 数字是否与原始数据一致
  ✓ 同比/环比计算是否正确
  ✓ 趋势方向判断是否正确
  ✗ 错误示例："GMV 增长 5%"（实际是下降 5%）

完整性（Completeness）— 半自动评估：
  ✓ 是否覆盖了所有关键指标
  ✓ 是否指出了最重要的异常
  ✓ 是否包含对比基准
  ✗ 错误示例：只提了 GMV，漏掉了用户数暴跌 20%

可读性（Readability）— 需要 LLM 辅助评估：
  ✓ 语句是否通顺
  ✓ 是否避免了重复表达
  ✓ 信息密度是否合适
  ✗ 错误示例："GMV 是 1230 万。GMV 环比下降 3.2%。
              GMV 同比增长 15.8%。GMV…"（机械重复）
```

在工程实践中，准确性可以通过对比原始数据自动验证——把摘要中出现的数字提取出来，与数据源逐条比对。完整性和可读性则需要结合规则检查（是否包含预定义的关键指标）和 LLM 自评（让另一个 LLM 给摘要打分）来综合判断。

```python
# data_source.py
import pandas as pd
import numpy as np
from datetime import datetime, timedelta


def generate_sales_data(seed: int = 42) -> pd.DataFrame:
    """生成模拟的销售数据，包含区域、渠道、品类三个维度。"""
    rng = np.random.default_rng(seed)

    regions = ["华东", "华南", "华北", "西南", "华中"]
    channels = ["线上自营", "线下门店", "第三方平台", "企业客户"]
    categories = ["电子产品", "家居用品", "服饰鞋包", "食品饮料", "办公用品"]

    dates = pd.date_range(
        start=datetime(2025, 3, 1),
        end=datetime(2025, 3, 28),
        freq="D"
    )

    records = []
    for date in dates:
        for region in regions:
            for channel in channels:
                for category in categories:
                    base_amount = rng.normal(5000, 1500)
                    weekday_factor = 1.2 if date.weekday() >= 5 else 1.0
                    region_factor = {"华东": 1.3, "华南": 1.1, "华北": 0.9,
                                     "西南": 0.85, "华中": 1.0}[region]
                    channel_factor = {"线上自营": 1.2, "线下门店": 0.9,
                                      "第三方平台": 1.1, "企业客户": 0.8}[channel]

                    amount = max(0, base_amount * weekday_factor *
                                 region_factor * channel_factor)
                    order_count = max(1, int(amount / rng.uniform(80, 200)))
                    return_count = max(0, int(order_count * rng.uniform(0.01, 0.08)))

                    records.append({
                        "date": date,
                        "region": region,
                        "channel": channel,
                        "category": category,
                        "gmv": round(amount, 2),
                        "order_count": order_count,
                        "return_count": return_count,
                        "customer_count": max(1, int(order_count * 0.7)),
                    })

    df = pd.DataFrame(records)
    df["week"] = df["date"].dt.isocalendar().week.astype(int)
    return df


def get_current_and_previous_week(df: pd.DataFrame) -> tuple[pd.DataFrame, pd.DataFrame]:
    """将数据按周拆分为当前周和上一周。"""
    max_week = df["week"].max()
    current = df[df["week"] == max_week].copy()
    previous = df[df["week"] == max_week - 1].copy()
    return current, previous
```

### 数据分析引擎

```python
# analyzer.py
import pandas as pd
import numpy as np
from dataclasses import dataclass, field


@dataclass
class KeyFinding:
    """一条关键发现，包含指标名、数值、变化、方向和语义标签。"""
    metric: str
    current_value: float
    previous_value: float
    change_rate: float
    direction: str          # up / down / flat
    magnitude: str          # large / medium / slight
    dimension: str = ""     # 可选维度（如"华东区域"）
    finding_type: str = ""  # trend / anomaly / ranking
    priority_score: float = 0.0


class SalesAnalyzer:
    """销售数据分析器：从原始数据中提取关键发现。"""

    MAGNITUDE_THRESHOLDS = {"large": 0.20, "medium": 0.10, "slight": 0.0}
    METRIC_WEIGHTS = {"gmv": 1.0, "order_count": 0.8,
                      "return_count": 0.7, "customer_count": 0.6}

    def analyze_weekly(
        self,
        current_week: pd.DataFrame,
        previous_week: pd.DataFrame,
        metrics: list[str],
    ) -> list[KeyFinding]:
        """分析周度数据，提取关键发现列表。"""
        findings = []

        # 1) 总体趋势
        findings.extend(self._analyze_totals(current_week, previous_week, metrics))

        # 2) 区域维度拆解
        findings.extend(self._analyze_by_dimension(
            current_week, previous_week, metrics, "region"
        ))

        # 3) 渠道维度拆解
        findings.extend(self._analyze_by_dimension(
            current_week, previous_week, metrics, "channel"
        ))

        # 4) 异常检测
        findings.extend(self._detect_anomalies(current_week, previous_week, metrics))

        # 5) 计算优先级分数并排序
        for f in findings:
            f.priority_score = self._calc_priority(f)
        findings.sort(key=lambda x: x.priority_score, reverse=True)

        return findings

    def _analyze_totals(
        self, current: pd.DataFrame, previous: pd.DataFrame, metrics: list[str]
    ) -> list[KeyFinding]:
        findings = []
        for metric in metrics:
            curr_val = current[metric].sum()
            prev_val = previous[metric].sum()
            change = self._calc_change_rate(curr_val, prev_val)

            findings.append(KeyFinding(
                metric=metric,
                current_value=round(curr_val, 2),
                previous_value=round(prev_val, 2),
                change_rate=round(change, 4),
                direction=self._classify_direction(change),
                magnitude=self._classify_magnitude(change),
                dimension="总体",
                finding_type="trend",
            ))
        return findings

    def _analyze_by_dimension(
        self, current: pd.DataFrame, previous: pd.DataFrame,
        metrics: list[str], dim_col: str,
    ) -> list[KeyFinding]:
        findings = []
        for dim_value in current[dim_col].unique():
            curr_subset = current[current[dim_col] == dim_value]
            prev_subset = previous[previous[dim_col] == dim_value]

            for metric in metrics:
                curr_val = curr_subset[metric].sum()
                prev_val = prev_subset[metric].sum()
                change = self._calc_change_rate(curr_val, prev_val)

                findings.append(KeyFinding(
                    metric=metric,
                    current_value=round(curr_val, 2),
                    previous_value=round(prev_val, 2),
                    change_rate=round(change, 4),
                    direction=self._classify_direction(change),
                    magnitude=self._classify_magnitude(change),
                    dimension=dim_value,
                    finding_type="trend",
                ))
        return findings

    def _detect_anomalies(
        self, current: pd.DataFrame, previous: pd.DataFrame, metrics: list[str]
    ) -> list[KeyFinding]:
        """基于 Z-score 检测异常波动的维度组合。"""
        findings = []
        for dim_col in ["region", "channel", "category"]:
            for dim_value in current[dim_col].unique():
                curr_subset = current[current[dim_col] == dim_value]
                prev_subset = previous[previous[dim_col] == dim_value]

                for metric in metrics:
                    curr_val = curr_subset[metric].sum()
                    prev_val = prev_subset[metric].sum()
                    change = abs(self._calc_change_rate(curr_val, prev_val))

                    if change > 0.30:
                        findings.append(KeyFinding(
                            metric=metric,
                            current_value=round(curr_val, 2),
                            previous_value=round(prev_val, 2),
                            change_rate=round(
                                self._calc_change_rate(curr_val, prev_val), 4
                            ),
                            direction=self._classify_direction(
                                self._calc_change_rate(curr_val, prev_val)
                            ),
                            magnitude="large",
                            dimension=dim_value,
                            finding_type="anomaly",
                        ))
        return findings

    @staticmethod
    def _calc_change_rate(current: float, previous: float) -> float:
        if previous == 0:
            return 0.0
        return (current - previous) / abs(previous)

    @staticmethod
    def _classify_direction(change: float) -> str:
        if change > 0.02:
            return "up"
        elif change < -0.02:
            return "down"
        return "flat"

    def _classify_magnitude(self, change: float) -> str:
        abs_change = abs(change)
        if abs_change >= self.MAGNITUDE_THRESHOLDS["large"]:
            return "large"
        elif abs_change >= self.MAGNITUDE_THRESHOLDS["medium"]:
            return "medium"
        return "slight"

    def _calc_priority(self, finding: KeyFinding) -> float:
        metric_weight = self.METRIC_WEIGHTS.get(finding.metric, 0.5)
        magnitude_score = {"large": 1.0, "medium": 0.6, "slight": 0.3}
        type_score = {"anomaly": 1.0, "trend": 0.5}

        return (
            abs(finding.change_rate) * 0.35
            + magnitude_score.get(finding.magnitude, 0.3) * 0.25
            + metric_weight * 0.25
            + type_score.get(finding.finding_type, 0.5) * 0.15
        )
```

### 摘要质量评估器

```python
# evaluator.py
import re
from dataclasses import dataclass
from analyzer import KeyFinding


@dataclass
class EvalResult:
    """摘要评估结果。"""
    accuracy_score: float       # 0-1
    completeness_score: float   # 0-1
    readability_score: float    # 0-1
    total_score: float          # 加权总分
    issues: list[str]


class SummaryEvaluator:
    """摘要质量评估器：检查准确性、完整性、可读性。"""

    WEIGHTS = {"accuracy": 0.45, "completeness": 0.30, "readability": 0.25}

    def evaluate(
        self,
        summary: str,
        findings: list[KeyFinding],
        required_metrics: list[str] | None = None,
    ) -> EvalResult:
        issues = []

        accuracy = self._check_accuracy(summary, findings, issues)
        completeness = self._check_completeness(summary, findings, required_metrics, issues)
        readability = self._check_readability(summary, issues)

        total = (
            accuracy * self.WEIGHTS["accuracy"]
            + completeness * self.WEIGHTS["completeness"]
            + readability * self.WEIGHTS["readability"]
        )

        return EvalResult(
            accuracy_score=round(accuracy, 3),
            completeness_score=round(completeness, 3),
            readability_score=round(readability, 3),
            total_score=round(total, 3),
            issues=issues,
        )

    def _check_accuracy(
        self, summary: str, findings: list[KeyFinding], issues: list[str]
    ) -> float:
        """提取摘要中的数字，与关键发现比对。"""
        numbers_in_text = re.findall(r"[\d,]+\.?\d*", summary.replace(",", ""))
        numbers_in_text = [float(n) for n in numbers_in_text if n]

        finding_values = set()
        for f in findings:
            finding_values.add(round(f.current_value))
            finding_values.add(round(f.previous_value))

        if not numbers_in_text:
            issues.append("摘要中未包含任何数字")
            return 0.0

        matched = 0
        for num in numbers_in_text:
            for val in finding_values:
                if abs(num - val) / max(abs(val), 1) < 0.05:
                    matched += 1
                    break

        score = matched / len(numbers_in_text) if numbers_in_text else 0
        if score < 0.8:
            issues.append(f"数字准确性偏低：{matched}/{len(numbers_in_text)} 匹配")
        return min(score, 1.0)

    def _check_completeness(
        self,
        summary: str,
        findings: list[KeyFinding],
        required_metrics: list[str] | None,
        issues: list[str],
    ) -> float:
        """检查摘要是否覆盖了关键指标。"""
        if required_metrics is None:
            required_metrics = list({f.metric for f in findings[:5]})

        covered = sum(1 for m in required_metrics if m in summary)
        score = covered / len(required_metrics) if required_metrics else 1.0

        missing = [m for m in required_metrics if m not in summary]
        if missing:
            issues.append(f"未覆盖关键指标：{', '.join(missing)}")
        return score

    def _check_readability(self, summary: str, issues: list[str]) -> float:
        """基础可读性检查：句长、重复、字数。"""
        score = 1.0

        char_count = len(summary)
        if char_count < 50:
            issues.append("摘要过短，信息量不足")
            score -= 0.3
        elif char_count > 800:
            issues.append("摘要过长，管理层可能不会读完")
            score -= 0.2

        sentences = [s.strip() for s in re.split(r"[。！？.!?]", summary) if s.strip()]
        if sentences:
            avg_len = sum(len(s) for s in sentences) / len(sentences)
            if avg_len > 80:
                issues.append("句子平均长度过长，建议拆分")
                score -= 0.15

        return max(score, 0.0)
```

## 常见误区

### 误区一：把所有指标都塞进摘要

很多初学者认为摘要应该"全面"，恨不得把报表里每个指标都提一遍。但管理层的时间是稀缺资源——一份 500 字的摘要如果每个指标都提到，反而让人抓不住重点。

**正确做法**是先做信息筛选：只保留变化幅度最大、绝对值最高、或者与当前业务目标最相关的 5-8 个指标。其余指标可以放在附录或详情链接中，让有兴趣的读者自行查阅。

### 误区二：完全依赖 LLM 做数字计算

直接把原始表格丢给 LLM 让它算同比环比，是最常见的错误。LLM 的设计目标是语言理解和生成，不是精确计算。在实际测试中，GPT-4o 从表格中提取数字的准确率约为 85-90%，而正式报告要求 100%。

**正确做法**是用 Python 预先计算好所有数值，只让 LLM 负责把结构化的计算结果组织成自然语言。这就是"增强式生成"的核心思想——程序做计算，LLM 做表达。

### 误区三：忽略摘要的受众差异

给 CEO 的摘要和给运营经理的摘要应该是不同的。CEO 需要的是"结论 + 建议"，运营经理需要的是"问题 + 原因 + 具体行动"。用同一套模板生成所有受众的摘要，会导致要么太抽象（对运营没用），要么太详细（CEO 没时间看）。

**正确做法**是设计多套 prompt 模板，根据受众角色调整输出的详略程度和信息侧重点。

### 误区四：不验证生成结果的准确性

把 LLM 的输出直接发到管理层群里，不做任何验证，是非常危险的。LLM 可能产生幻觉——编造不存在的数据变化、把上升说成下降、混淆不同维度的数据。

**正确做法**是建立摘要质量评估流水线：用正则表达式提取摘要中的数字，与原始数据逐条比对；检查关键指标是否都被覆盖；评估语句的通顺程度。只有通过评估的摘要才能对外发送。

## 小结与练习

### 小结

1. 数据摘要按粒度分为三层：概要型（What）、对比型（How）、解释型（Why），层次越高对系统能力要求越高
2. 基于规则的模板方法数字准确但缺乏洞察力，适合做基础层；LLM 方法擅长生成有洞察力的文字但可能产生幻觉
3. 增强式生成是工程实践中的最佳方案：用程序做计算保证准确性，用 LLM 做表达保证可读性
4. 多维度数据的摘要压缩需要信息优先级排序机制，核心公式是 `得分 = 变化幅度 × 0.35 + 绝对值 × 0.25 + 业务重要性 × 0.25 + 异常程度 × 0.15`
5. 摘要质量从准确性、完整性、可读性三个维度评估，其中准确性可以通过自动化方式验证

### 练习一

**思路**：在现有模板库的基础上，增加趋势类和极值类语义标签。趋势需要引入历史数据（至少 3 周），极值需要维护历史极值记录。

**答案**：

```python
class ExtendedTemplateLibrary:
    """扩展模板库，支持趋势和极值描述。"""

    TREND_TEMPLATES = {
        "consecutive_up": [
            "{指标}已连续{weeks}周上涨，累计涨幅{total_change}",
            "{指标}保持{weeks}周连升态势，本期录得{current_value}",
        ],
        "consecutive_down": [
            "{指标}已连续{weeks}周下滑，累计降幅{total_change}",
            "{指标}连续{weeks}周走低，需要关注是否形成趋势",
        ],
        "all_time_high": [
            "{指标}达到{current_value}，创历史新高",
            "{指标}突破历史峰值，录得{current_value}",
        ],
        "all_time_low": [
            "{指标}降至{current_value}，创历史新低",
            "{指标}跌至历史最低水平，仅为{current_value}",
        ],
        "milestone": [
            "{指标}首次突破{milestone}大关，达到{current_value}",
            "{指标}实现里程碑式突破，达到{current_value}",
        ],
    }

    def detect_trend(self, metric_history: list[float]) -> str:
        """检测连续变化趋势。"""
        if len(metric_history) < 3:
            return "normal"

        recent = metric_history[-3:]
        if all(recent[i] > recent[i - 1] for i in range(1, len(recent))):
            return "consecutive_up"
        if all(recent[i] < recent[i - 1] for i in range(1, len(recent))):
            return "consecutive_down"
        return "normal"

    def detect_extremes(
        self, current_value: float, historical_values: list[float]
    ) -> str | None:
        """检测是否达到历史极值。"""
        if not historical_values:
            return None
        if current_value >= max(historical_values):
            return "all_time_high"
        if current_value <= min(historical_values):
            return "all_time_low"
        return None
```

**要点**：
- 趋势检测需要至少 3 周历史数据，避免短期波动误判为趋势
- 极值检测需要维护全局历史记录，而非仅对比上一周
- 里程碑阈值应该根据指标特性设定（如 GMV 突破 1000 万、转化率突破 5%）

### 练习二

**思路**：用皮尔逊相关系数衡量两条发现之间的变化相关性。当两个指标在相同维度上的变化方向和幅度高度一致时，视为冗余信息。

**答案**：

```python
from dataclasses import dataclass
from analyzer import KeyFinding


@dataclass
class MergedInsight:
    """合并后的洞察，可能包含多个指标。"""
    metrics: list[str]
    dimension: str
    direction: str
    description: str
    priority_score: float


class FindingDeduplicator:
    """关键发现去重器。"""

    CORRELATION_THRESHOLD = 0.85

    def deduplicate(self, findings: list[KeyFinding]) -> list[MergedInsight]:
        """合并高度相关的关键发现。"""
        insights: list[MergedInsight] = []
        used: set[int] = set()

        for i, finding_a in enumerate(findings):
            if i in used:
                continue

            group = [finding_a]
            for j, finding_b in enumerate(findings):
                if j <= i or j in used:
                    continue
                if self._is_redundant(finding_a, finding_b):
                    group.append(finding_b)
                    used.add(j)

            used.add(i)
            insights.append(self._merge_group(group))

        insights.sort(key=lambda x: x.priority_score, reverse=True)
        return insights

    def _is_redundant(self, a: KeyFinding, b: KeyFinding) -> bool:
        """判断两条发现是否冗余。"""
        if a.dimension != b.dimension:
            return False
        if a.direction != b.direction:
            return False
        # 变化幅度差异小于 10 个百分点视为一致
        if abs(a.change_rate - b.change_rate) < 0.10:
            return True
        return False

    def _merge_group(self, group: list[KeyFinding]) -> MergedInsight:
        """将一组相关发现合并为一条洞察。"""
        metrics = [f.metric for f in group]
        dimension = group[0].dimension
        direction = group[0].direction
        avg_change = sum(f.change_rate for f in group) / len(group)

        direction_label = {"up": "上升", "down": "下降", "flat": "持平"}
        if len(metrics) == 1:
            desc = f"{dimension} {metrics[0]} {direction_label[direction]} {avg_change:+.2%}"
        else:
            metric_str = "、".join(metrics)
            desc = (
                f"{dimension} {metric_str} 同步{direction_label[direction]}，"
                f"平均变化 {avg_change:+.2%}"
            )

        return MergedInsight(
            metrics=metrics,
            dimension=dimension,
            direction=direction,
            description=desc,
            priority_score=max(f.priority_score for f in group),
        )
```

**要点**：
- 去重只在相同维度内进行，不同维度的相似变化可能有不同原因
- 合并后的措辞应该体现"同步变化"的含义，而不是简单罗列
- 保留优先级最高的发现的分数作为合并后洞察的分数

### 练习三
