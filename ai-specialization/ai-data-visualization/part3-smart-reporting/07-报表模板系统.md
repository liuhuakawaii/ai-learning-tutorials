## 场景引入

你的报表系统已经能够自动生成和推送报表了。运营团队用了一个月后，开始提出新的需求："能不能把表格换成深色主题？""这个月的月报想加上一个环比趋势图。""不同事业部的报表格式不一样，能不能各自配置？"

如果你每次都通过改代码来满足这些需求，你会发现工程师变成了"报表美工"——每天的工作就是调整报表的布局和样式。这显然不可持续。

报表模板系统要解决的核心问题是：**将报表的结构、样式和数据分离，让非工程师也能通过配置文件来定义和修改报表的格式。**

## 核心概念

### 一、模板引擎的本质

模板引擎做的事情很简单：**把一份带有占位符的文本，替换成实际数据后输出。** 但在这个简单的定义背后，隐藏着几个需要解决的关键问题。

```
┌──────────────────────────────────────────────────────┐
│                模板引擎工作流程                         │
│                                                      │
│  模板文本              解析            数据            │
│  ┌──────────┐      ┌──────┐      ┌──────────┐      │
│  │ <h1>{{}} │      │      │      │ {        │      │
│  │ <table>  │─────→│ 解析器│─────→│  title,  │      │
│  │ {{#each}}│      │      │      │  rows[]  │      │
│  └──────────┘      └──┬───┘      │ }        │      │
│                       │          └──────────┘      │
│                       ▼                             │
│              ┌──────────────┐                       │
│              │  AST 抽象语法树│                       │
│              └──────┬───────┘                       │
│                     ▼                               │
│              ┌──────────────┐                       │
│              │  编译为渲染函数│                       │
│              └──────┬───────┘                       │
│                     ▼                               │
│              ┌──────────────┐                       │
│              │  输出 HTML    │                       │
│              └──────────────┘                       │
└──────────────────────────────────────────────────────┘
```

**为什么不用简单的字符串替换？**

简单的 `str.replace('{{name}}', data.name)` 只能处理最简单的场景。真实报表模板需要：

1. **条件渲染**：如果某个指标异常，显示红色高亮；否则显示正常样式
2. **循环渲染**：表格的行数取决于数据，不能预先知道有多少行
3. **嵌套结构**：一个表格单元格里可能包含子组件
4. **辅助函数**：数字格式化、日期格式化、条件判断等

这些需求将简单的字符串替换变成了一个完整的 DSL（领域特定语言）。

### 二、模板语法设计的取舍

市面上的模板引擎语法各异，但核心权衡是一样的：**表达力 vs 安全性 vs 学习成本。**

```
┌──────────────────────────────────────────────────────┐
│              模板语法设计的三角权衡                     │
│                                                      │
│                    表达力                             │
│                    /    \                            │
│                   /      \                           │
│                  /        \                          │
│                 /          \                         │
│              安全性 ────── 学习成本                    │
│                                                      │
│  Handlebars:  学习成本低，安全性高，表达力有限          │
│  JSX:         表达力强，学习成本高，安全性依赖转义      │
│  Nunjucks:    平衡三者，Python 生态友好               │
│  自研 DSL:    可精确控制，但维护成本高                  │
└──────────────────────────────────────────────────────┘
```

**推荐选择**：对于报表模板场景，Handlebars 或 Nunjucks 是最务实的选择。它们的语法足够覆盖报表渲染的需求，学习成本低，且内置了 HTML 转义等安全机制。

### 三、主题系统架构

主题不仅仅是"换个颜色"。一个完整的主题系统需要管理颜色、字体、间距、布局四个维度，并且要保证切换主题时所有组件的一致性。

```
┌──────────────────────────────────────────────────────┐
│                  主题系统分层架构                      │
│                                                      │
│  ┌────────────────────────────────────────────────┐  │
│  │              设计令牌 (Design Tokens)            │  │
│  │  颜色 │ 字体 │ 间距 │ 圆角 │ 阴影              │  │
│  └────────────────────┬───────────────────────────┘  │
│                       │                              │
│  ┌────────────────────┼───────────────────────────┐  │
│  │              组件样式映射                        │  │
│  │  表头背景 → primary.color                       │  │
│  │  表格边框 → border.color                        │  │
│  │  正文字体 → font.body                           │  │
│  └────────────────────┬───────────────────────────┘  │
│                       │                              │
│  ┌────────────────────┼───────────────────────────┐  │
│  │              主题预设                           │  │
│  │  亮色主题 │ 暗色主题 │ 品牌主题 A │ 品牌主题 B   │  │
│  └────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────┘
```

**设计令牌（Design Tokens）** 是主题系统的原子单位。每一条设计令牌是一个键值对，例如：

```json
{
  "color.primary": "#1a73e8",
  "color.background": "#ffffff",
  "font.body.family": "-apple-system, 'PingFang SC', sans-serif",
  "font.body.size": "14px",
  "spacing.section": "24px",
  "border.radius": "8px"
}
```

组件样式不直接引用颜色值，而是引用令牌名称。切换主题时，只需要替换令牌的值，所有引用该令牌的组件样式自动更新。

### 四、模板版本管理

模板和代码一样需要版本管理。当运营团队修改了一个报表模板后发现效果不好，需要能回滚到上一个版本。

```
┌──────────────────────────────────────────────────────┐
│                  模板版本生命周期                      │
│                                                      │
│  草稿 ──→ 审核 ──→ 发布 ──→ 生效                     │
│   │        │        │        │                      │
│   │        │        │        ▼                      │
│   │        │        │     使用中                     │
│   │        │        │        │                      │
│   │        │        │        ▼                      │
│   │        │        │     新版本 (草稿)              │
│   │        │        │                               │
│   ▼        ▼        ▼                               │
│  废弃     驳回     回滚到 v1                         │
└──────────────────────────────────────────────────────┘
```

```typescript
import type { DesignTokens } from './tokens.js'

export class ThemeEngine {
  private tokens: DesignTokens

  constructor(tokens: DesignTokens) {
    this.tokens = tokens
  }

  applyTheme(tokens: DesignTokens): void {
    this.tokens = tokens
  }

  getTokens(): DesignTokens {
    return this.tokens
  }

  toCSSVariables(): string {
    const flatten = (obj: Record<string, unknown>, prefix = ''): Array<[string, string]> => {
      const entries: Array<[string, string]> = []
      for (const [key, value] of Object.entries(obj)) {
        const cssKey = prefix ? `${prefix}-${key}` : key
        if (typeof value === 'object' && value !== null) {
          entries.push(...flatten(value as Record<string, unknown>, cssKey))
        } else {
          entries.push([cssKey, String(value)])
        }
      }
      return entries
    }

    const vars = flatten(this.tokens as unknown as Record<string, unknown>, 'report')
    return vars.map(([key, value]) => `  --${key}: ${value};`).join('\n')
```

```typescript
// src/template/renderer.ts
import Handlebars from 'handlebars'
import type { TemplateDefinition, TemplateMetadata } from './types.js'

export interface RenderContext {
  data: Record<string, unknown>
  theme?: string
  locale?: string
}

export class TemplateRenderer {
  private templates = new Map<string, Handlebars.TemplateDelegate>()
  private metadata = new Map<string, TemplateMetadata>()
  private compiledCache = new Map<string, { hash: string; template: Handlebars.TemplateDelegate }>()

  constructor() {
    this.registerBuiltinHelpers()
  }

  register(definition: TemplateDefinition): void {
    const { metadata, template, partials, helpers } = definition
    const key = `${metadata.id}@${metadata.version}`

    if (partials) {
      for (const [name, partialTemplate] of Object.entries(partials)) {
        Handlebars.registerPartial(name, partialTemplate)
      }
    }

    if (helpers) {
      for (const [name, fn] of Object.entries(helpers)) {
        Handlebars.registerHelper(name, fn)
      }
    }

    const compiled = Handlebars.compile(template, { noEscape: false })
    this.templates.set(key, compiled)
    this.metadata.set(key, metadata)

    console.log(`[模板注册] ${metadata.name} v${metadata.version} (${key})`)
  }

  render(templateId: string, version: string, context: RenderContext): string {
    const key = `${templateId}@${version}`
    const template = this.templates.get(key)

    if (!template) {
      throw new Error(`模板未找到: ${key}`)
    }

    const metadata = this.metadata.get(key)!
    this.validateVariables(metadata, context.data)

    return template(context.data)
  }

  listTemplates(): TemplateMetadata[] {
    return Array.from(this.metadata.values())
  }

  getTemplate(templateId: string, version?: string): TemplateDefinition | null {
    const key = version
      ? `${templateId}@${version}`
      : this.findLatestVersion(templateId)

    if (!key) return null

    return {
      metadata: this.metadata.get(key)!,
      template: this.templates.get(key)!.toString(),
    }
  }

  private findLatestVersion(templateId: string): string | null {
    const versions = Array.from(this.metadata.entries())
      .filter(([key]) => key.startsWith(`${templateId}@`))
      .sort((a, b) => b[1].version.localeCompare(a[1].version))

    return versions[0]?.[0] || null
  }

  private validateVariables(metadata: TemplateMetadata, data: Record<string, unknown>): void {
    for (const variable of metadata.variables) {
      if (variable.required && !(variable.name in data)) {
        throw new Error(`模板变量 "${variable.name}" 是必填项但未提供`)
      }
    }
  }

  private registerBuiltinHelpers(): void {
    Handlebars.registerHelper('formatNumber', (value: number, decimals = 0) => {
      if (typeof value !== 'number') return String(value)
      return value.toLocaleString('zh-CN', {
        minimumFractionDigits: decimals,
        maximumFractionDigits: decimals,
      })
    })

    Handlebars.registerHelper('formatCurrency', (value: number, currency = 'CNY') => {
      if (typeof value !== 'number') return String(value)
      const symbols: Record<string, string> = { CNY: '¥', USD: '$', EUR: '€' }
      return `${symbols[currency] || currency}${value.toLocaleString('zh-CN', { minimumFractionDigits: 2 })}`
    })

    Handlebars.registerHelper('formatPercent', (value: number) => {
      if (typeof value !== 'number') return String(value)
      const sign = value > 0 ? '+' : ''
      return `${sign}${value.toFixed(2)}%`
    })

    Handlebars.registerHelper('changeClass', (value: number) => {
      return value > 0 ? 'change-up' : 'change-down'
    })

    Handlebars.registerHelper('changeArrow', (value: number) => {
      return value > 0 ? '↑' : '↓'
    })

    Handlebars.registerHelper('eq', (a: unknown, b: unknown) => a === b)
    Handlebars.registerHelper('gt', (a: number, b: number) => a > b)
    Handlebars.registerHelper('lt', (a: number, b: number) => a < b)

    Handlebars.registerHelper('ifCond', function (this: unknown, v1: unknown, operator: string, v2: unknown, options: Handlebars.HelperOptions) {
      switch (operator) {
        case '==': return v1 == v2 ? options.fn(this) : options.inverse(this)
        case '===': return v1 === v2 ? options.fn(this) : options.inverse(this)
        case '>': return v1 > v2 ? options.fn(this) : options.inverse(this)
        case '<': return v1 < v2 ? options.fn(this) : options.inverse(this)
        default: return options.inverse(this)
      }
    })
  }
}
```

### 第五步：模板版本管理器

```typescript
// src/template/version-manager.ts
import type { TemplateDefinition, TemplateMetadata } from './types.js'

interface VersionEntry {
  version: string
  definition: TemplateDefinition
  createdAt: Date
  author: string
  changeNote: string
  status: 'draft' | 'published' | 'archived'
}

export class TemplateVersionManager {
  private versions = new Map<string, VersionEntry[]>()

  publish(definition: TemplateDefinition, author: string, changeNote: string): void {
    const { id, version } = definition.metadata
    const history = this.versions.get(id) || []

    const existing = history.find(v => v.version === version)
    if (existing) {
      throw new Error(`版本 ${version} 已存在，不能重复发布`)
    }

    for (const entry of history) {
      if (entry.status === 'published') {
        entry.status = 'archived'
      }
    }

    history.push({
      version,
      definition,
      createdAt: new Date(),
      author,
      changeNote,
      status: 'published',
    })

    this.versions.set(id, history)
    console.log(`[版本管理] 模板 "${id}" 发布版本 ${version}: ${changeNote}`)
  }

  getPublished(templateId: string): TemplateDefinition | null {
    const history = this.versions.get(templateId)
    if (!history) return null

    const published = history.find(v => v.status === 'published')
    return published?.definition || null
  }

  getVersion(templateId: string, version: string): TemplateDefinition | null {
    const history = this.versions.get(templateId)
    if (!history) return null

    const entry = history.find(v => v.version === version)
    return entry?.definition || null
  }

  getHistory(templateId: string): Array<{
    version: string
    author: string
    changeNote: string
    status: string
    createdAt: string
  }> {
    const history = this.versions.get(templateId) || []
    return history.map(v => ({
      version: v.version,
      author: v.author,
      changeNote: v.changeNote,
      status: v.status,
      createdAt: v.createdAt.toISOString(),
    }))
  }

  rollback(templateId: string, targetVersion: string): TemplateDefinition | null {
    const history = this.versions.get(templateId)
    if (!history) return null

    const target = history.find(v => v.version === targetVersion)
    if (!target) return null

    for (const entry of history) {
      if (entry.status === 'published') {
        entry.status = 'archived'
      }
    }

    target.status = 'published'
    console.log(`[版本管理] 模板 "${templateId}" 已回滚到版本 ${targetVersion}`)
    return target.definition
  }
}
```

## 常见误区

### 误区一：在模板中写业务逻辑

把复杂的计算、条件判断、数据转换都写在模板里。模板会变得难以维护和调试。

**正确做法**：模板只负责"展示"，所有数据处理在传入模板之前完成。模板中的逻辑应该仅限于展示相关的条件判断（如：如果值为负数，显示红色）。

### 误区二：不做 HTML 转义

直接将用户输入或数据库内容插入 HTML，会导致 XSS 攻击风险。即使报表系统是内部系统，恶意数据也可能通过数据同步进入系统。

**正确做法**：使用模板引擎的自动转义功能（Handlebars 默认开启），对确实需要输出原始 HTML 的场景，使用 `{{{triple-stache}}}` 语法并确保内容来源可信。

### 误区三：主题系统只管颜色

很多团队的主题系统只是定义了一组颜色变量，切换主题时只改变颜色。但深色主题和亮色主题的差异不仅仅是颜色——阴影、边框、对比度都需要调整。

**正确做法**：主题系统应该覆盖所有视觉属性（颜色、字体、间距、阴影、边框），并通过设计令牌统一管理。

### 误区四：模板没有版本管理

模板修改后直接覆盖，没有版本记录。当新模板出现渲染问题时，无法回滚到上一个正常版本。

**正确做法**：每次模板修改都应该创建新版本，保留历史版本，并支持一键回滚。

### 练习三

**思路**：模板市场本质上是一个带元数据的模板仓库。核心数据结构包括模板描述、版本、截图、评分等。

**答案**：

```typescript
// src/marketplace/types.ts
export interface MarketplaceEntry {
  templateId: string
  name: string
  description: string
  author: string
  category: string
  tags: string[]
  currentVersion: string
  screenshots: string[]
  rating: {
    average: number
    count: number
  }
  downloads: number
  publishedAt: string
  updatedAt: string
}

export interface MarketplaceReview {
  reviewId: string
  templateId: string
  userId: string
  rating: number
  comment: string
  createdAt: string
}

// src/marketplace/store.ts
export class TemplateMarketplace {
  private entries = new Map<string, MarketplaceEntry>()
  private reviews = new Map<string, MarketplaceReview[]>()

  publish(entry: MarketplaceEntry): void {
    this.entries.set(entry.templateId, {
      ...entry,
      downloads: 0,
      rating: { average: 0, count: 0 },
      publishedAt: new Date().toISOString(),
      updatedAt: new Date().toISOString(),
    })
  }

  search(query: {
    keyword?: string
    category?: string
    tags?: string[]
    sortBy?: 'downloads' | 'rating' | 'newest'
    limit?: number
  }): MarketplaceEntry[] {
    let results = Array.from(this.entries.values())

    if (query.keyword) {
      const kw = query.keyword.toLowerCase()
      results = results.filter(
        e => e.name.toLowerCase().includes(kw) || e.description.toLowerCase().includes(kw)
      )
    }

    if (query.category) {
      results = results.filter(e => e.category === query.category)
    }

    if (query.tags?.length) {
      results = results.filter(e => query.tags!.some(t => e.tags.includes(t)))
    }

    const sortBy = query.sortBy || 'downloads'
    results.sort((a, b) => {
      if (sortBy === 'rating') return b.rating.average - a.rating.average
      if (sortBy === 'newest') return b.publishedAt.localeCompare(a.publishedAt)
      return b.downloads - a.downloads
    })

    return results.slice(0, query.limit || 20)
  }

  install(templateId: string): MarketplaceEntry | null {
    const entry = this.entries.get(templateId)
    if (entry) {
      entry.downloads++
    }
    return entry || null
  }

  addReview(review: MarketplaceReview): void {
    const entry = this.entries.get(review.templateId)
    if (!entry) return

    const reviews = this.reviews.get(review.templateId) || []
    reviews.push(review)
    this.reviews.set(review.templateId, reviews)

    const totalRating = reviews.reduce((sum, r) => sum + r.rating, 0)
    entry.rating = {
      average: totalRating / reviews.length,
      count: reviews.length,
    }
  }

  getReviews(templateId: string): MarketplaceReview[] {
    return this.reviews.get(templateId) || []
  }
}
```

**要点**：模板市场的核心挑战不是技术实现，而是运营。需要考虑模板的质量审核机制、版本兼容性声明、以及防止恶意模板的安全策略。
