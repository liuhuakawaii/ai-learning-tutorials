## 场景引入

你精心搭建了自动化报表系统，每天早上 8 点准时推送给运营团队。某天早上，运营总监发来消息："这个日报里的 GMV 怎么是负数？"你排查后发现，上游支付系统的数据同步任务昨晚失败了，导致今天的 GMV 数据只同步了一半。更糟糕的是，这个错误数据已经被自动推送给了整个管理层。

这个场景暴露了一个核心问题：**报表系统只负责"展示"数据，但不负责"验证"数据。** 如果数据本身有问题，再漂亮的图表也只是在传播错误信息。

数据质量监控的目标就是：在数据进入报表之前，先过一道质量检查关卡。

## 核心概念

### 一、数据质量的五个维度

数据质量不是一个单一指标，而是多个维度的综合评估。我们需要理解每个维度的含义，才能设计出有针对性的检查规则。

```
┌─────────────────────────────────────────────────────┐
│              数据质量五维度模型                        │
│                                                     │
│                   ┌──────────┐                      │
│                   │ 完整性    │                      │
│                   │ Completeness                     │
│                   └────┬─────┘                      │
│                        │                            │
│         ┌──────────┐   │   ┌──────────┐            │
│         │ 一致性    │───┼───│ 准确性    │            │
│         │Consistency│   │   │ Accuracy  │            │
│         └──────────┘   │   └──────────┘            │
│                        │                            │
│         ┌──────────┐   │   ┌──────────┐            │
│         │ 唯一性    │───┴───│ 时效性    │            │
│         │ Uniqueness│       │ Timeliness│            │
│         └──────────┘       └──────────┘            │
└─────────────────────────────────────────────────────┘
```

**完整性（Completeness）**：数据是否存在缺失。例如：订单表中是否有 `NULL` 的用户 ID？报表中是否缺少了某个地区的数据？完整性问题通常是最容易检测的——直接检查 `NULL` 值和空字符串即可。

**准确性（Accuracy）**：数据是否反映真实情况。例如：用户填写的年龄是否在合理范围内？订单金额是否与支付记录一致？准确性问题需要参照物来验证，可能是另一张表、一个业务规则或者一个合理的数值范围。

**一致性（Consistency）**：同一数据在不同系统中是否一致。例如：用户在订单系统中的地址与 CRM 系统中的地址是否相同？MySQL 中的订单数与 Elasticsearch 中的索引数是否一致？一致性问题通常发生在数据同步场景中。

**时效性（Timeliness）**：数据是否及时更新。例如：T+1 的报表是否在每天早上 8 点之前生成完毕？实时数据流的延迟是否在可接受范围内？时效性问题需要结合时间戳来判断。

**唯一性（Uniqueness）**：数据是否存在重复。例如：同一个用户是否被注册了两次？同一个订单是否被重复计入统计？唯一性问题需要通过主键或业务唯一键来检测。

### 二、数据质量规则引擎

数据质量检查的核心是一个规则引擎。每条规则定义了"检查什么"和"怎么判断"。

```
┌───────────────────────────────────────────────────┐
│              规则引擎执行流程                        │
│                                                   │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    │
│  │ 规则定义  │───→│ 规则解析  │───→│ SQL 生成  │    │
│  │ (YAML)   │    │          │    │          │    │
│  └──────────┘    └──────────┘    └────┬─────┘    │
│                                       │          │
│                                       ▼          │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    │
│  │ 结果判定  │←───│ 指标计算  │←───│ 数据查询  │    │
│  │ 告警触发  │    │          │    │          │    │
│  └──────────┘    └──────────┘    └──────────┘    │
└───────────────────────────────────────────────────┘
```

规则应该用声明式的方式定义，而非硬编码在代码中。这样非工程师（如数据分析师）也能参与规则的维护。

### 三、数据血缘与根因分析

当数据质量出现问题时，最关键的问题不是"哪里出了问题"，而是"为什么出了问题"。数据血缘追踪可以帮助我们从异常报表指标出发，沿着数据链路向上追溯，找到问题的根源。

```
┌──────────────────────────────────────────────────────┐
│                  数据血链示例                          │
│                                                      │
│  数据源           ETL              数据仓库    报表    │
│  ┌─────┐       ┌─────┐          ┌─────┐   ┌─────┐  │
│  │ 支付 │──ETL──│ 清洗 │──LOAD───│ DWS │───│ GMV │  │
│  │ 系统 │       │ 转换 │          │ 汇总 │   │ 报表 │  │
│  └─────┘       └─────┘          └─────┘   └─────┘  │
│    │               │                │          │     │
│    ▼               ▼                ▼          ▼     │
│  数据同步失败  空值未处理      聚合错误   指标异常     │
│                                                      │
│  当 GMV 报表异常时，沿血链向上追溯：                   │
│  GMV异常 → DWS汇总 → ETL转换 → 支付系统数据同步      │
└──────────────────────────────────────────────────────┘
```

```yaml
name: 订单数据质量检查
description: 检查订单表的核心字段完整性和数值合理性
target_table: dw_order_daily
schedule: "0 7 * * *"

rules:
```

```typescript
// src/rules/types.ts
export type QualityDimension = 'completeness' | 'accuracy' | 'consistency' | 'timeliness' | 'uniqueness'
export type Severity = 'critical' | 'warning' | 'info'

export interface QualityCheck {
  column?: string
  null_threshold?: number
  min_value?: number
  max_value?: number
  outlier_std?: number
  unique_keys?: string[]
  duplicate_threshold?: number
  freshness_hours?: number
  timestamp_column?: string
}

export interface QualityRule {
  id: string
  name: string
  dimension: QualityDimension
  severity: Severity
  description: string
  checks: QualityCheck[]
}

export interface RuleSet {
  name: string
  description: string
  target_table: string
  schedule: string
  rules: QualityRule[]
}

export interface CheckResult {
  ruleId: string
  ruleName: string
  dimension: QualityDimension
  severity: Severity
  passed: boolean
  actualValue: number
  threshold: number
  message: string
  details?: Record<string, unknown>
  checkedAt: Date
}
```

```typescript
// src/rules/loader.ts
import { readFileSync, readdirSync } from 'node:fs'
import { join, extname } from 'node:path'
import YAML from 'yaml'
import type { RuleSet } from './types.js'

export function loadRuleSets(rulesDir: string): RuleSet[] {
  const files = readdirSync(rulesDir).filter(
    f => extname(f) === '.yaml' || extname(f) === '.yml'
  )

  return files.map(file => {
    const content = readFileSync(join(rulesDir, file), 'utf-8')
    const ruleSet = YAML.parse(content) as RuleSet
    return ruleSet
  })
}
```

### 第三步：质量检查执行器

```typescript
// src/checker.ts
import { Pool } from 'pg'
import type { QualityCheck, QualityRule, RuleSet, CheckResult } from './rules/types.js'

export class QualityChecker {
  private pool: Pool

  constructor(connectionString: string) {
    this.pool = new Pool({ connectionString })
  }

  async checkRuleSet(ruleSet: RuleSet): Promise<CheckResult[]> {
    const results: CheckResult[] = []

    for (const rule of ruleSet.rules) {
      for (const check of rule.checks) {
        const result = await this.executeCheck(ruleSet.target_table, rule, check)
        results.push(result)
      }
    }

    return results
  }

  private async executeCheck(
    table: string,
    rule: QualityRule,
    check: QualityCheck
  ): Promise<CheckResult> {
    switch (rule.dimension) {
      case 'completeness':
        return this.checkCompleteness(table, rule, check)
      case 'accuracy':
        return this.checkAccuracy(table, rule, check)
      case 'uniqueness':
        return this.checkUniqueness(table, rule, check)
      case 'timeliness':
        return this.checkTimeliness(table, rule, check)
      default:
        return {
          ruleId: rule.id,
          ruleName: rule.name,
          dimension: rule.dimension,
          severity: rule.severity,
          passed: false,
          actualValue: 0,
          threshold: 0,
          message: `不支持的检查维度: ${rule.dimension}`,
          checkedAt: new Date(),
        }
    }
  }

  private async checkCompleteness(
    table: string,
    rule: QualityRule,
    check: QualityCheck
  ): Promise<CheckResult> {
    const column = check.column!
    const threshold = check.null_threshold ?? 0

    const query = `
      SELECT
        COUNT(*) AS total_rows,
        COUNT(CASE WHEN ${column} IS NULL OR ${column} = '' THEN 1 END) AS null_rows
      FROM ${table}
    `

    const { rows } = await this.pool.query(query)
    const total = Number(rows[0].total_rows)
    const nulls = Number(rows[0].null_rows)
    const nullRate = total > 0 ? nulls / total : 0
    const passed = nullRate <= threshold

    return {
      ruleId: rule.id,
      ruleName: rule.name,
      dimension: rule.dimension,
      severity: rule.severity,
      passed,
      actualValue: nullRate,
      threshold,
      message: passed
        ? `列 "${column}" 空值率 ${(nullRate * 100).toFixed(2)}%，符合阈值 ${(threshold * 100).toFixed(2)}%`
        : `列 "${column}" 空值率 ${(nullRate * 100).toFixed(2)}% 超过阈值 ${(threshold * 100).toFixed(2)}%（${nulls}/${total}行为空）`,
      details: { column, totalRows: total, nullRows: nulls },
      checkedAt: new Date(),
    }
  }

  private async checkAccuracy(
    table: string,
    rule: QualityRule,
    check: QualityCheck
  ): Promise<CheckResult> {
    const column = check.column!
    const minVal = check.min_value ?? -Infinity
    const maxVal = check.max_value ?? Infinity

    const query = `
      SELECT
        COUNT(*) AS total_rows,
        COUNT(CASE WHEN ${column} < ${minVal} OR ${column} > ${maxVal} THEN 1 END) AS out_of_range
      FROM ${table}
      WHERE ${column} IS NOT NULL
    `

    const { rows } = await this.pool.query(query)
    const total = Number(rows[0].total_rows)
    const outOfRange = Number(rows[0].out_of_range)
    const outRate = total > 0 ? outOfRange / total : 0
    const passed = outOfRange === 0

    return {
      ruleId: rule.id,
      ruleName: rule.name,
      dimension: rule.dimension,
      severity: rule.severity,
      passed,
      actualValue: outRate,
      threshold: 0,
      message: passed
        ? `列 "${column}" 所有值在合理范围 [${minVal}, ${maxVal}] 内`
        : `列 "${column}" 有 ${outOfRange} 行超出范围 [${minVal}, ${maxVal}]`,
      details: { column, totalRows: total, outOfRangeRows: outOfRange },
      checkedAt: new Date(),
    }
  }

  private async checkUniqueness(
    table: string,
    rule: QualityRule,
    check: QualityCheck
  ): Promise<CheckResult> {
    const keys = check.unique_keys!
    const threshold = check.duplicate_threshold ?? 0
    const keyColumns = keys.join(', ')

    const query = `
      SELECT COUNT(*) AS duplicate_groups
      FROM (
        SELECT ${keyColumns}, COUNT(*) AS cnt
        FROM ${table}
        GROUP BY ${keyColumns}
        HAVING COUNT(*) > 1
      ) duplicates
    `

    const { rows } = await this.pool.query(query)
    const duplicateGroups = Number(rows[0].duplicate_groups)
    const passed = duplicateGroups <= threshold

    return {
      ruleId: rule.id,
      ruleName: rule.name,
      dimension: rule.dimension,
      severity: rule.severity,
      passed,
      actualValue: duplicateGroups,
      threshold,
      message: passed
        ? `唯一键 [${keyColumns}] 无重复`
        : `唯一键 [${keyColumns}] 存在 ${duplicateGroups} 组重复数据`,
      details: { uniqueKeys: keys, duplicateGroups },
      checkedAt: new Date(),
    }
  }

  private async checkTimeliness(
    table: string,
    rule: QualityRule,
    check: QualityCheck
  ): Promise<CheckResult> {
    const maxHours = check.freshness_hours ?? 24
    const tsColumn = check.timestamp_column ?? 'updated_at'

    const query = `
      SELECT EXTRACT(EPOCH FROM (NOW() - MAX(${tsColumn}))) / 3600 AS hours_since_update
      FROM ${table}
    `

    const { rows } = await this.pool.query(query)
    const hoursSince = Number(rows[0].hours_since_update)
    const passed = hoursSince <= maxHours

    return {
      ruleId: rule.id,
      ruleName: rule.name,
      dimension: rule.dimension,
      severity: rule.severity,
      passed,
      actualValue: hoursSince,
      threshold: maxHours,
      message: passed
        ? `数据最近 ${hoursSince.toFixed(1)} 小时内有更新，符合时效要求`
        : `数据已 ${hoursSince.toFixed(1)} 小时未更新，超过阈值 ${maxHours} 小时`,
      details: { hoursSinceUpdate: hoursSince, maxAllowedHours: maxHours },
      checkedAt: new Date(),
    }
  }

  async close(): Promise<void> {
    await this.pool.end()
  }
}
```

### 第四步：告警引擎

```typescript
// src/alerter.ts
import type { CheckResult, Severity } from './rules/types.js'

export interface AlertChannel {
  name: string
  send(alert: AlertMessage): Promise<void>
}

export interface AlertMessage {
  title: string
  level: Severity
  summary: string
  failedChecks: CheckResult[]
  timestamp: Date
}

export interface AlertPolicy {
  minSeverity: Severity
  cooldownMinutes: number
  escalateAfterFailures: number
}

const SEVERITY_ORDER: Record<Severity, number> = {
  info: 0,
  warning: 1,
  critical: 2,
}

export class AlertEngine {
  private channels: AlertChannel[] = []
  private lastAlertTime = new Map<string, number>()
  private consecutiveFailures = new Map<string, number>()
  private policy: AlertPolicy

  constructor(policy: AlertPolicy) {
    this.policy = policy
  }

  registerChannel(channel: AlertChannel): void {
    this.channels.push(channel)
  }

  async processResults(results: CheckResult[]): Promise<void> {
    const failures = results.filter(r => !r.passed)

    if (failures.length === 0) {
      console.log('[告警引擎] 所有检查通过，无需告警')
      return
    }

    const criticalFailures = failures.filter(
      f => SEVERITY_ORDER[f.severity] >= SEVERITY_ORDER[this.policy.minSeverity]
    )

    if (criticalFailures.length === 0) {
      console.log('[告警引擎] 存在低优先级问题，未达到告警阈值')
      return
    }

    const alertKey = criticalFailures.map(f => f.ruleId).sort().join(',')
    const now = Date.now()
    const lastTime = this.lastAlertTime.get(alertKey) || 0
    const cooldownMs = this.policy.cooldownMinutes * 60 * 1000

    const failures_count = (this.consecutiveFailures.get(alertKey) || 0) + 1
    this.consecutiveFailures.set(alertKey, failures_count)

    if (now - lastTime < cooldownMs && failures_count < this.policy.escalateAfterFailures) {
      console.log(`[告警引擎] 冷却期内，跳过告警 (${alertKey})`)
      return
    }

    this.lastAlertTime.set(alertKey, now)

    const maxSeverity = criticalFailures.reduce<Severity>((max, f) => {
      return SEVERITY_ORDER[f.severity] > SEVERITY_ORDER[max] ? f.severity : max
    }, 'info')

    const alert: AlertMessage = {
      title: `数据质量告警 - ${criticalFailures.length} 项检查未通过`,
      level: failures_count >= this.policy.escalateAfterFailures ? 'critical' : maxSeverity,
      summary: this.buildSummary(criticalFailures),
      failedChecks: criticalFailures,
      timestamp: new Date(),
    }

    console.log(`[告警引擎] 触发 ${this.channels.length} 个渠道的告警推送`)
    await Promise.all(this.channels.map(ch => ch.send(alert)))
  }

  private buildSummary(failures: CheckResult[]): string {
    return failures
      .map(f => `[${f.severity.toUpperCase()}] ${f.ruleName}: ${f.message}`)
      .join('\n')
  }

  resetConsecutiveFailures(alertKey: string): void {
    this.consecutiveFailures.delete(alertKey)
  }
}
```

### 第五步：LLM 辅助质量分析

```typescript
// src/llm-analyzer.ts
import OpenAI from 'openai'
import type { CheckResult } from './rules/types.js'

export interface QualityAnalysis {
  executiveSummary: string
  rootCauseHypotheses: string[]
  recommendedActions: string[]
  riskAssessment: string
}

export class LLMQualityAnalyzer {
  private client: OpenAI

  constructor(apiKey: string) {
    this.client = new OpenAI({ apiKey })
  }

  async analyze(results: CheckResult[]): Promise<QualityAnalysis> {
    const failures = results.filter(r => !r.passed)

    if (failures.length === 0) {
      return {
        executiveSummary: '所有数据质量检查均通过，数据状态健康。',
        rootCauseHypotheses: [],
        recommendedActions: [],
        riskAssessment: '低风险',
      }
    }

    const context = failures.map(f => ({
      rule: f.ruleName,
      dimension: f.dimension,
      severity: f.severity,
      actual: f.actualValue,
      threshold: f.threshold,
      message: f.message,
      details: f.details,
    }))

    const response = await this.client.chat.completions.create({
      model: 'gpt-4o-mini',
      messages: [
        {
          role: 'system',
          content: `你是一个数据质量分析专家。根据数据质量检查结果，生成结构化的诊断报告。
要求：
1. 执行摘要用 2-3 句话概括当前数据质量状况
2. 根因假设按可能性从高到低排列，每条说明为什么可能
3. 推荐措施要具体可执行，不要泛泛而谈
4. 风险评估要考虑对下游报表和业务决策的影响

返回 JSON 格式：
{
  "executiveSummary": "...",
  "rootCauseHypotheses": ["..."],
  "recommendedActions": ["..."],
  "riskAssessment": "..."
}`,
        },
        {
          role: 'user',
          content: `以下是本次数据质量检查的失败项：\n\n${JSON.stringify(context, null, 2)}`,
        },
      ],
      response_format: { type: 'json_object' },
      temperature: 0.3,
    })

    const content = response.choices[0].message.content || '{}'
    return JSON.parse(content) as QualityAnalysis
  }

  formatReport(analysis: QualityAnalysis, results: CheckResult[]): string {
    const passed = results.filter(r => r.passed).length
    const failed = results.filter(r => !r.passed).length
    const total = results.length

    return `# 数据质量检查报告

## 总览

- 检查时间: ${new Date().toLocaleString('zh-CN')}
- 总检查项: ${total}
- 通过: ${passed} ✅
- 未通过: ${failed} ❌
- 通过率: ${((passed / total) * 100).toFixed(1)}%

## AI 诊断摘要

${analysis.executiveSummary}

## 根因假设

${analysis.rootCauseHypotheses.map((h, i) => `${i + 1}. ${h}`).join('\n')}

## 推荐措施

${analysis.recommendedActions.map((a, i) => `${i + 1}. ${a}`).join('\n')}

## 风险评估

${analysis.riskAssessment}

## 详细检查结果

| 规则 | 维度 | 严重度 | 结果 | 实际值 | 阈值 | 说明 |
|------|------|--------|------|--------|------|------|
${results.map(r => `| ${r.ruleName} | ${r.dimension} | ${r.severity} | ${r.passed ? '✅' : '❌'} | ${r.actualValue} | ${r.threshold} | ${r.message} |`).join('\n')}
`
  }
}
```

## 常见误区

### 误区一：只检查数据格式，不检查业务逻辑

很多团队的数据质量检查只停留在"字段是否为空"、"类型是否正确"这种技术层面。但真正导致报表错误的往往是业务逻辑层面的问题：比如退款订单被计入了正向 GMV、某个渠道的数据被重复统计。

**正确做法**：技术检查是基础，业务规则检查才是核心。与业务方共同定义检查规则，而不是数据团队闭门造车。

### 误区二：所有规则都是 critical 级别

如果每条规则都设为 critical，告警渠道每天都会被轰炸，最终团队会对告警麻木（alert fatigue），真正严重的问题反而被忽略了。

**正确做法**：根据影响范围和紧急程度分级。只有会直接导致报表数据错误的问题才设为 critical，提示性问题设为 warning。

### 误区三：检查规则写死在代码里

把检查逻辑硬编码在 ETL 脚本中，修改规则需要改代码、测试、部署。这导致规则更新的周期很长，业务方提一个新规则可能要等一周才能上线。

**正确做法**：规则用 YAML/JSON 声明式定义，存储在配置文件或数据库中，修改后即时生效。

### 误区四：发现问题但不追踪修复

很多系统能做到"发现问题并告警"，但告警发出后就不管了。如果负责修复的人没有及时处理，问题可能会持续影响报表。

**正确做法**：告警应该生成工单，并有明确的负责人和 SLA。系统应能追踪问题的处理状态。

## 参考答案

### 练习一

**思路**：跨表一致性检查的核心是分别查询两个数据源的指标值，然后在应用层比较。需要处理数据源连接失败的情况。

**答案**：

```typescript
// src/checks/consistency-check.ts
import { Pool } from 'pg'

export interface ConsistencyCheckConfig {
  sourceA: { connectionString: string; query: string; label: string }
  sourceB: { connectionString: string; query: string; label: string }
  tolerancePercent: number
}

export class ConsistencyChecker {
  async check(config: ConsistencyCheckConfig): Promise<{
    passed: boolean
    valueA: number
    valueB: number
    diffPercent: number
    message: string
  }> {
    const poolA = new Pool({ connectionString: config.sourceA.connectionString })
    const poolB = new Pool({ connectionString: config.sourceB.connectionString })

    try {
      const [{ rows: rowsA }, { rows: rowsB }] = await Promise.all([
        poolA.query(config.sourceA.query),
        poolB.query(config.sourceB.query),
      ])

      const valueA = Number(Object.values(rowsA[0])[0])
      const valueB = Number(Object.values(rowsB[0])[0])
      const diffPercent = valueA > 0
        ? Math.abs(valueA - valueB) / valueA * 100
        : (valueB > 0 ? 100 : 0)

      const passed = diffPercent <= config.tolerancePercent

      return {
        passed,
        valueA,
        valueB,
        diffPercent,
        message: passed
          ? `${config.sourceA.label}(${valueA}) 与 ${config.sourceB.label}(${valueB}) 差异 ${diffPercent.toFixed(2)}%，在容忍范围内`
          : `${config.sourceA.label}(${valueA}) 与 ${config.sourceB.label}(${valueB}) 差异 ${diffPercent.toFixed(2)}%，超过容忍阈值 ${config.tolerancePercent}%`,
      }
    } finally {
      await poolA.end()
      await poolB.end()
    }
  }
}
```

**要点**：跨源一致性检查需要考虑两个数据源的时区差异和数据延迟。建议在两个数据源都完成更新后再执行检查。

### 练习二

**思路**：评分卡的核心是加权扣分模型。每个维度有一个基础分（满分），检查失败时按严重程度扣分。

**答案**：

```typescript
// src/scoring.ts
import type { CheckResult, QualityDimension, Severity } from './rules/types.js'

export interface DimensionWeight {
  dimension: QualityDimension
  weight: number
}

export interface QualityScore {
  totalScore: number
  dimensionScores: Record<QualityDimension, number>
  grade: 'A' | 'B' | 'C' | 'D' | 'F'
  timestamp: Date
}

const SEVERITY_PENALTY: Record<Severity, number> = {
  critical: 25,
  warning: 10,
  info: 3,
}

export function calculateQualityScore(
  results: CheckResult[],
  weights: DimensionWeight[]
): QualityScore {
  const dimensionScores: Partial<Record<QualityDimension, number>> = {}

  for (const { dimension, weight } of weights) {
    const dimResults = results.filter(r => r.dimension === dimension)
    if (dimResults.length === 0) {
      dimensionScores[dimension] = 100
      continue
    }

    let score = 100
    for (const result of dimResults) {
      if (!result.passed) {
        score -= SEVERITY_PENALTY[result.severity]
      }
    }
    dimensionScores[dimension] = Math.max(0, score)
  }

  const totalWeight = weights.reduce((sum, w) => sum + w.weight, 0)
  const totalScore = weights.reduce((sum, w) => {
    return sum + (dimensionScores[w.dimension] || 0) * (w.weight / totalWeight)
  }, 0)

  const roundedScore = Math.round(totalScore)
  let grade: QualityScore['grade']
  if (roundedScore >= 90) grade = 'A'
  else if (roundedScore >= 80) grade = 'B'
  else if (roundedScore >= 70) grade = 'C'
  else if (roundedScore >= 60) grade = 'D'
  else grade = 'F'

  return {
    totalScore: roundedScore,
    dimensionScores: dimensionScores as Record<QualityDimension, number>,
    grade,
    timestamp: new Date(),
  }
}
```

**要点**：权重应该反映业务优先级。例如，对于财务报表，准确性维度的权重应该最高；对于实时监控场景，时效性维度的权重应该最高。

### 练习三

**思路**：设计一个 REST API，返回最近 7 天的质量检查汇总数据。前端可以用这些数据渲染趋势图和统计卡片。

**答案**：

```typescript
// src/api.ts
import type { CheckResult } from './rules/types.js'

interface DailySummary {
  date: string
  totalChecks: number
  passedChecks: number
  failedChecks: number
  passRate: number
}

interface DimensionSummary {
  dimension: string
  totalChecks: number
  passedChecks: number
  passRate: number
}

interface TopFailedRule {
  ruleId: string
  ruleName: string
  failCount: number
  lastFailure: string
}

export class QualityDashboardAPI {
  private history: Array<{ date: string; results: CheckResult[] }> = []

  recordResults(date: string, results: CheckResult[]): void {
    this.history.push({ date, results })
    if (this.history.length > 30) {
      this.history.shift()
    }
  }

  getDailyTrend(days = 7): DailySummary[] {
    return this.history.slice(-days).map(entry => {
      const total = entry.results.length
      const passed = entry.results.filter(r => r.passed).length
      return {
        date: entry.date,
        totalChecks: total,
        passedChecks: passed,
        failedChecks: total - passed,
        passRate: total > 0 ? Math.round((passed / total) * 100) : 100,
      }
    })
  }

  getDimensionSummary(days = 7): DimensionSummary[] {
    const recent = this.history.slice(-days)
    const dimensionMap = new Map<string, { total: number; passed: number }>()

    for (const entry of recent) {
      for (const result of entry.results) {
        const current = dimensionMap.get(result.dimension) || { total: 0, passed: 0 }
        current.total++
        if (result.passed) current.passed++
        dimensionMap.set(result.dimension, current)
      }
    }

    return Array.from(dimensionMap.entries()).map(([dimension, stats]) => ({
      dimension,
      totalChecks: stats.total,
      passedChecks: stats.passed,
      passRate: Math.round((stats.passed / stats.total) * 100),
    }))
  }

  getTopFailedRules(limit = 5): TopFailedRule[] {
    const failMap = new Map<string, { name: string; count: number; lastDate: string }>()

    for (const entry of this.history) {
      for (const result of entry.results) {
        if (!result.passed) {
          const current = failMap.get(result.ruleId) || { name: result.ruleName, count: 0, lastDate: '' }
          current.count++
          current.lastDate = entry.date
          failMap.set(result.ruleId, current)
        }
      }
    }

    return Array.from(failMap.entries())
      .map(([ruleId, data]) => ({
        ruleId,
        ruleName: data.name,
        failCount: data.count,
        lastFailure: data.lastDate,
      }))
      .sort((a, b) => b.failCount - a.failCount)
      .slice(0, limit)
  }
}
```

**要点**：历史数据的存储周期取决于业务需求。建议至少保留 30 天，以便分析质量趋势。
