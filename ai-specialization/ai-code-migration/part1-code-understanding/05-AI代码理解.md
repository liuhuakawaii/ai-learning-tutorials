# 第五课：AI 驱动的代码理解

## 场景引入

你的团队接手了一个 15 万行的 Java 遗留系统，没有任何文档，原始开发者早已离职。你需要在两周内搞清楚：核心业务逻辑是什么？每个模块负责什么？哪些业务规则隐藏在代码中？

靠人工逐文件阅读？15 万行代码，就算一天读 5000 行，也需要一个月。这就是 AI 代码理解要解决的问题：**用大语言模型批量处理代码，生成结构化摘要、提取业务规则、构建领域模型**。人类负责提问和判断，AI 负责阅读和总结。

## 学习目标

1. 设计高效的代码分析 Prompt，让 LLM 准确理解代码意图
2. 构建批量化代码摘要生成流水线
3. 处理大代码库的分块策略（Chunking）
4. 从遗留代码中提取业务规则
5. 为无文档代码自动生成 API 文档
6. 比较 GPT-4、Claude、DeepSeek 在代码理解场景的表现

## 核心概念

### 一、LLM 代码理解的本质

LLM 理解代码的本质是**模式匹配 + 语义推理**：

```
输入：一段源代码 + 一个提问
  ↓
LLM 内部过程：
  1. 识别代码结构（函数签名、控制流、数据流）
  2. 匹配训练数据中见过的类似模式
  3. 结合提问，生成结构化回答
  ↓
输出：文本描述、JSON 结构、分类标签
```

| 擅长 | 不擅长 |
|------|--------|
| 总结函数/模块的功能 | 精确计算代码复杂度 |
| 识别设计模式 | 追踪跨文件的精确类型 |
| 提取业务规则 | 判断代码是否"正确" |
| 生成文档 | 替代单元测试 |

### 二、Prompt 设计三原则

**原则一：提供足够上下文，但不要超过必要范围。** "分析这段代码"太模糊；把整个项目发给 LLM 太浪费。应该明确指定分析维度。

**原则二：要求结构化输出。** 让 LLM 输出 JSON 而不是自由文本，便于程序化处理。结构化输出的关键是给出明确的 schema，让 LLM 知道每个字段的含义和取值范围。

**原则三：分层提问。** 不要一次分析整个项目。分三层：

```
第一层：文件级摘要 — 每个文件是干什么的？
第二层：模块级分析 — 这些文件怎么协作？
第三层：系统级理解 — 整个系统的架构和业务流程是什么？
```

### 三、大代码库的分块策略

GPT-4o 上下文 128K tokens，Claude 200K，DeepSeek 128K。一个中型项目可能几十万行。分块的核心是**按语义边界切分**：

```python
# ❌ 错误：每 100 行一块，可能把一个函数切成两半
chunks = [code[i:i+100] for i in range(0, len(code), 100)]

# ✅ 正确：按函数/类边界切分，每个块是完整的语义单元
chunks = extract_functions_and_classes(code)
```

### 四、分析流水线架构

```
┌─────────────┐     ┌──────────────┐     ┌───────────────┐
│  源码扫描    │────→│  AST 解析     │────→│  分块切分      │
└─────────────┘     └──────────────┘     └───────┬───────┘
                                                  ▼
┌─────────────┐     ┌──────────────┐     ┌───────────────┐
│  报告生成    │←────│  结果聚合     │←────│  LLM 批量分析  │
└─────────────┘     └──────────────┘     └───────────────┘
```

### 五、模型选择

| 维度 | GPT-4o | Claude 3.5 Sonnet | DeepSeek-V3 |
|------|--------|-------------------|-------------|
| 代码理解准确度 | 高 | 很高 | 高 |
| 长上下文 | 128K | 200K | 128K |
| 成本（每百万 token） | ~$2.5/10 | ~$3/15 | ~$0.27/$1.10 |
| 适合场景 | 英文代码库 | 深度推理 | 大批量、成本敏感 |

建议：关键模块用 GPT-4o 或 Claude，非关键文件用 DeepSeek 控制成本。

```typescript
// src/analyzer.ts
import OpenAI from "openai";
import { readFileSync } from "fs";
import { glob } from "glob";

interface FileAnalysis {
  filePath: string;
  summary: string;
  purpose: string;
  functions: { name: string; purpose: string; sideEffects: string[]; businessRules: string[] }[];
  businessRules: string[];
  sideEffects: string[];
  complexity: "low" | "medium" | "high";
}

const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

async function analyzeChunk(code: string, filePath: string): Promise<FileAnalysis> {
  const response = await openai.chat.completions.create({
    model: "gpt-4o",
    temperature: 0.1,
    response_format: { type: "json_object" },
    messages: [
      { role: "system", content: "你是代码分析专家。请以 JSON 格式回复，不要包含额外文本。" },
      {
        role: "user",
        content: `分析以下代码文件，提取结构化信息。

文件: ${filePath}

\`\`\`
${code}
\`\`\`

输出 JSON：
{
  "filePath": "${filePath}",
  "summary": "一句话总结",
  "purpose": "详细业务目的（2-3句话）",
  "functions": [{
    "name": "函数名",
    "purpose": "函数目的",
    "sideEffects": ["数据库操作/文件读写/网络请求等"],
    "businessRules": ["业务规则，如'订单金额不能为负'"]
  }],
  "businessRules": ["文件级业务规则"],
  "sideEffects": ["文件级副作用"],
  "complexity": "low/medium/high"
}

注意：businessRules 从业务角度描述，如"用户余额不能低于0"而非"检查 balance >= 0"`,
      },
    ],
  });
  return JSON.parse(response.choices[0].message.content ?? "{}");
}

function chunkFile(filePath: string): string[] {
  const content = readFileSync(filePath, "utf-8");
  const lines = content.split("\n");
  if (lines.length <= 200) return [content];

  const chunks: string[] = [];
  let current: string[] = [];
  let braceDepth = 0;
  for (const line of lines) {
    current.push(line);
    braceDepth += (line.match(/{/g) || []).length - (line.match(/}/g) || []).length;
    if (braceDepth === 0 && current.length >= 50) {
      chunks.push(current.join("\n"));
      current = [];
    }
  }
  if (current.length > 0) chunks.push(current.join("\n"));
  return chunks.length > 0 ? chunks : [content];
}

async function callWithRetry<T>(fn: () => Promise<T>, retries = 3): Promise<T> {
  for (let i = 0; i < retries; i++) {
    try { return await fn(); }
    catch (e: any) {
      if (e?.status === 429) { await new Promise((r) => setTimeout(r, 2 ** i * 1000)); continue; }
      throw e;
    }
  }
  throw new Error("超过最大重试次数");
}

function mergeAnalyses(analyses: FileAnalysis[], filePath: string): FileAnalysis {
  return {
    filePath,
    summary: analyses.map((a) => a.summary).join("; "),
    purpose: analyses[0].purpose,
    functions: analyses.flatMap((a) => a.functions),
    businessRules: [...new Set(analyses.flatMap((a) => a.businessRules))],
    sideEffects: [...new Set(analyses.flatMap((a) => a.sideEffects))],
    complexity: analyses.some((a) => a.complexity === "high") ? "high" : "medium",
  };
}

export async function analyzeProject(projectPath: string) {
  const sourceFiles = await glob(`${projectPath}/**/*.{ts,tsx,js,jsx,py}`, {
    ignore: ["**/node_modules/**", "**/dist/**", "**/__pycache__/**"],
  });
  console.log(`扫描到 ${sourceFiles.length} 个源文件`);

  const fileAnalyses: FileAnalysis[] = [];
  for (let i = 0; i < sourceFiles.length; i += 3) {
    const batch = sourceFiles.slice(i, i + 3);
    console.log(`进度: ${Math.min(i + 3, sourceFiles.length)} / ${sourceFiles.length}`);
    const results = await Promise.all(
      batch.map(async (fp) => {
        try {
          const chunks = chunkFile(fp);
          const analyses: FileAnalysis[] = [];
          for (const chunk of chunks) analyses.push(await callWithRetry(() => analyzeChunk(chunk, fp)));
          return analyses.length === 1 ? analyses[0] : mergeAnalyses(analyses, fp);
        } catch { return null; }
      })
    );
    fileAnalyses.push(...results.filter(Boolean) as FileAnalysis[]);
  }

  const summaries = fileAnalyses.map((f) => `- ${f.filePath.split("/").pop()}: ${f.summary}`).join("\n");
  const allRules = [...new Set(fileAnalyses.flatMap((f) => f.businessRules))];
  const sysResp = await callWithRetry(() =>
    openai.chat.completions.create({
      model: "gpt-4o", temperature: 0.1, response_format: { type: "json_object" },
      messages: [
        { role: "system", content: "你是系统架构分析专家，以 JSON 回复。" },
        { role: "user", content: `文件摘要:\n${summaries}\n\n业务规则:\n${allRules.map((r) => `- ${r}`).join("\n")}\n\n输出: {"businessDomain":"","architecturePattern":"","migrationRisks":[]}` },
      ],
    })
  );
  return { totalFiles: sourceFiles.length, analyzedFiles: fileAnalyses.length, fileAnalyses, ...JSON.parse(sysResp.choices[0].message.content ?? "{}") };
}
```

### 示例二：批量提取业务规则

```typescript
// src/business-rule-extractor.ts
import OpenAI from "openai";
import { readFileSync } from "fs";

interface BusinessRule {
  rule: string;
  sourceFile: string;
  category: "validation" | "calculation" | "permission" | "workflow" | "constraint";
  confidence: number;
}

const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

export async function extractBusinessRules(filePath: string): Promise<BusinessRule[]> {
  const code = readFileSync(filePath, "utf-8");
  const response = await openai.chat.completions.create({
    model: "gpt-4o", temperature: 0.1, response_format: { type: "json_object" },
    messages: [
      {
        role: "system",
        content: `你是业务规则提取专家。分类：
- validation: 输入验证（如"邮箱格式必须合法"）
- calculation: 计算规则（如"订单金额 = 单价 × 数量 - 折扣"）
- permission: 权限规则（如"只有管理员可以删除用户"）
- workflow: 流程规则（如"订单必须先付款才能发货"）
- constraint: 约束条件（如"库存不能为负数"）`,
      },
      {
        role: "user",
        content: `从以下代码提取所有业务规则。

文件: ${filePath}

\`\`\`
${code}
\`\`\`

输出 JSON: { "rules": [{ "rule": "自然语言描述", "category": "类型", "confidence": 0.9 }] }

要求：只提取真正的业务规则，不提取技术细节。`,
      },
    ],
  });
  const result = JSON.parse(response.choices[0].message.content ?? '{"rules":[]}');
  return result.rules.map((r: any) => ({ rule: r.rule, sourceFile: filePath, category: r.category, confidence: r.confidence }));
}
```

export function estimateCost(totalTokens: number, model: "gpt-4o" | "claude" | "deepseek"): number {
  const rates = { "gpt-4o": { i: 2.5, o: 10 }, "claude": { i: 3, o: 15 }, "deepseek": { i: 0.27, o: 1.1 } };
  const r = rates[model];
  return (totalTokens * 0.8 * r.i + totalTokens * 0.2 * r.o) / 1_000_000;
}

### 示例四：自动生成 API 文档

遗留系统往往没有 API 文档。用 LLM 从路由定义代码中自动提取端点信息：

```typescript
// src/doc-generator.ts
import OpenAI from "openai";
import { readFileSync } from "fs";

interface ApiEndpoint {
  method: string;
  path: string;
  description: string;
  parameters: { name: string; in: string; type: string; required: boolean; description: string }[];
  authentication: boolean;
}

const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

export async function generateApiDocs(filePath: string): Promise<ApiEndpoint[]> {
  const code = readFileSync(filePath, "utf-8");
  const response = await openai.chat.completions.create({
    model: "gpt-4o", temperature: 0.1, response_format: { type: "json_object" },
    messages: [
      { role: "system", content: "从路由代码中提取所有 API 端点。查找 Express 的 app.get/post 或 Flask 的 @app.route。" },
      { role: "user", content: `分析路由文件 ${filePath}:\n\`\`\`\n${code}\n\`\`\`\n\n输出: {"endpoints":[{"method":"GET/POST","path":"/api/xxx","description":"","parameters":[{"name":"","in":"path/query/body","type":"","required":true,"description":""}],"authentication":true}]}` },
    ],
  });
  return JSON.parse(response.choices[0].message.content ?? '{"endpoints":[]}').endpoints;
}

export function formatAsMarkdown(endpoints: ApiEndpoint[]): string {
  let md = "# API 文档\n\n> 由 AI 自动生成，请人工校验。\n\n";
  for (const ep of endpoints) {
    md += `## ${ep.method} ${ep.path}\n\n${ep.description}\n\n`;
    if (ep.authentication) md += "**需要认证** 🔒\n\n";
    if (ep.parameters.length > 0) {
      md += "| 参数名 | 位置 | 类型 | 必填 | 说明 |\n|--------|------|------|------|------|\n";
      for (const p of ep.parameters) md += `| ${p.name} | ${p.in} | ${p.type} | ${p.required ? "是" : "否"} | ${p.description} |\n`;
      md += "\n";
    }
    md += "---\n\n";
  }
  return md;
}
```

## 常见误区

### 误区一：把整个项目一次性扔给 LLM

即使上下文窗口够大，10 万行代码一次性发给 LLM 会导致输出质量大幅下降（"大海捞针"问题）。**正确做法**：分层分析——先逐文件生成摘要，再基于摘要生成模块级理解，最后综合出系统级认识。

### 误区二：完全信任 LLM 的分析结果

LLM 会产生"幻觉"——可能说一个函数"负责用户认证"，但实际上只是在做密码哈希。**正确做法**：把 LLM 输出当作"假设"而非"结论"，关键业务逻辑必须人工验证。建议在生成的文档中标注置信度，低置信度的部分标红提醒。

### 误区三：忽略注释和命名的价值

很多人分析遗留代码时先把注释当作"噪音"。但在 AI 分析中，这些恰恰是重要信号——即使注释过时了，也反映了开发者当时的意图。**正确做法**：把注释、变量名一起发给 LLM。如果注释和代码行为不一致，让 LLM 标记出来——这本身就是一个有价值的发现。

### 误区四：不做 Prompt 迭代

很多人写一次 Prompt 就大规模运行。**正确做法**：先用 5-10 个不同类型的文件测试，检查输出质量（结构化输出的稳定性、业务规则提取的准确性），调优后再批量运行。

## 小结与练习

### 小结

1. **LLM 代码理解的本质**是模式匹配加语义推理，擅长总结和提取，不擅长精确验证
2. **分层分析**是处理大代码库的关键：文件级 → 模块级 → 系统级，逐层聚合
3. **分块策略**应按语义边界（函数/类）切分，而非按行数
4. **结构化输出**（JSON）是让 LLM 输出可程序化处理的关键
5. **模型选择**要平衡质量与成本：关键模块用高端模型，非关键文件用低成本模型
6. AI 输出是"假设"不是"结论"，关键信息必须人工验证

#### 练习一：设计数据流向分析 Prompt

为以下 ETL 脚本设计 Prompt，要求 LLM 追踪数据从源头到目的地的完整流向：

```python
import pandas as pd
import sqlalchemy

def extract_from_mysql():
    engine = sqlalchemy.create_engine("mysql://user:pass@localhost/sales_db")
    return pd.read_sql("SELECT * FROM daily_sales WHERE date >= '2024-01-01'", engine)

def transform(df):
    df["revenue"] = df["quantity"] * df["unit_price"]
    df["region"] = df["store_id"].map(lambda x: {1:"华东",2:"华南",3:"华北"}.get(x,"未知"))
    return df.groupby("region").agg({"revenue":"sum","quantity":"mean"}).reset_index()

def load_to_warehouse(df):
    engine = sqlalchemy.create_engine("postgresql://user:pass@localhost/warehouse")
    df.to_sql("regional_sales", engine, if_exists="replace", index=False)

def run_pipeline():
    load_to_warehouse(transform(extract_from_mysql()))
```

## 参考答案

### 练习一

**思路**：Prompt 需引导 LLM 追踪数据生命周期——从数据源开始，经过每个处理步骤，最终到目的地。关键是让 LLM 识别每个函数的"输入来源"和"输出去向"，以及数据结构在每一步如何变化。

**答案**：

```
分析以下 Python ETL 脚本，追踪数据完整流向。

{代码内容}

输出 JSON:
{
  "dataFlows": [{
    "name": "数据流名称",
    "source": { "type": "database", "description": "来源", "location": "连接信息" },
    "transformations": [{
      "step": 1, "function": "函数名", "operation": "操作描述",
      "inputShape": "输入数据结构", "outputShape": "输出数据结构"
    }],
    "destination": { "type": "database", "description": "去向" },
    "dataContract": { "requiredColumns": ["字段列表"], "constraints": ["数据约束"] }
  }]
}
```

**要点**：
- `inputShape` 和 `outputShape` 帮助理解数据在每一步如何变化
- `dataContract` 提取隐含的数据质量要求（如"region 不能为空"）
- 如果发现数据质量问题（缺失值处理、类型转换），应在 constraints 中标注

### 练习二

**思路**：按质量要求分配模型。每文件约 2500 tokens（2000 输入 + 500 输出），总计 500K tokens。高质量任务用高端模型，低要求任务用低成本模型。

**答案**：

| 任务 | 文件范围 | 模型 | 理由 |
|------|---------|------|------|
| 代码摘要 | 全部 200 | GPT-4o | 摘要是基础，需高质量 |
| 业务规则 | 前 50 核心 | GPT-4o | 需深度语义理解 |
| 业务规则 | 其余 150 | DeepSeek | 规则提取在此类文件中价值较低 |
| API 文档 | ~30 路由文件 | DeepSeek | 主要是模式匹配 |

成本：GPT-4o（250 文件）≈ $1.56，DeepSeek（180 文件）≈ $0.12，**总计约 $1.68**。如果全用 GPT-4o 约 $1.25，差异不大，但混合方案分散了风险并为后续扩展留出预算。
