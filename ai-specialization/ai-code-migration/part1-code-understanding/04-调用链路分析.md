# 第四课：调用链路分析

## 场景引入

你接手了一个电商系统的遗留代码，用户反馈"下单接口偶尔超时"。你打开 `orderController.js`，发现 `createOrder` 函数只有 20 行，看起来很干净。但这 20 行背后调用了什么？

```
createOrder
  → validateInventory
    → queryWarehouse
      → fetchRemoteStock   ← 这里可能超时？
      → cacheLookup
  → calculatePrice
    → getPromotionRules
      → loadCouponConfig
        → readFileSync      ← 同步文件读取？！
  → processPayment
    → callPaymentGateway
```

一个 20 行的函数，背后可能延伸出 5 层、10 个函数调用。如果你只看 `createOrder` 本身，永远找不到超时的根因。**调用链路分析**（Call Chain Analysis）就是解决这个问题的核心手段：从一个入口函数出发，自动追踪它调用了哪些函数，直到最后一层——数据库操作、外部 API、文件 I/O。

## 学习目标

1. 理解调用图（Call Graph）、调用链（Call Chain）、入口点（Entry Point）的核心概念
2. 区分静态分析与动态追踪两种方式的适用场景
3. 使用 ts-morph（TypeScript）和 ast 模块（Python）从源码 AST 构建调用图
4. 识别不可达代码（Dead Code）和副作用函数（Side Effects）
5. 将调用链路可视化为可读的依赖图

## 核心概念

### 一、什么是调用图

调用图（Call Graph）是一种有向图：**节点**代表函数，**边**代表"函数 A 调用了函数 B"。

```
    ┌─────────────┐
    │ createOrder  │
    └──────┬──────┘
           │
    ┌──────┴──────┐
    │             │
    ▼             ▼
validate      calculate
Inventory     Price
    │             │
    ▼             ▼
query         getPromo
Warehouse     Rules
```

调用图可以是**静态的**（从源码分析得出）或**动态的**（从运行时 trace 得出）：

| 维度 | 静态分析 | 动态追踪 |
|------|---------|---------|
| 数据来源 | 源代码 AST | 运行时插桩/profiling |
| 覆盖范围 | 所有可能路径 | 实际执行路径 |
| 精确度 | 可能包含不可达路径 | 精确反映真实行为 |
| 性能开销 | 分析时一次性消耗 | 运行时持续开销 |
| 适用场景 | 代码迁移、重构、文档生成 | 性能优化、线上排查 |

在代码迁移场景中，我们主要依赖**静态分析**，因为遗留代码可能无法直接运行，但源码总是在的。

### 二、从 AST 构建调用图的思路

```
输入：源代码
  ↓
解析为 AST
  ↓
遍历 AST，找到所有函数定义 → 记录为节点
  ↓
遍历 AST，找到所有函数调用表达式 → 记录为边
  ↓
输出：调用图（邻接表）
```

关键 AST 节点：JavaScript 的 `FunctionDeclaration`、`ArrowFunctionExpression`（节点）和 `CallExpression`（边）；Python 的 `FunctionDef`/`AsyncFunctionDef`（节点）和 `Call`（边）。

### 三、入口点与 Dead Code

调用图可能很大，需要确定**入口点**：HTTP 路由处理函数、CLI 的 main 函数、定时任务的处理函数等。从入口点做图遍历（BFS/DFS），遍历结束后仍未访问的节点就是**不可达代码（Dead Code）**——在迁移中可以安全丢弃。

### 四、副作用函数

在调用链路中我们特别关注叶子节点里的**副作用函数**：数据库操作、文件 I/O、网络请求、消息发送。标记副作用函数能帮助我们理解每个调用链路的"最终影响"。

```typescript
// src/call-graph-builder.ts
import { Project, SourceFile, FunctionDeclaration, CallExpression, ArrowFunction, FunctionExpression, Node, SyntaxKind } from "ts-morph";

interface CallGraphNode {
  name: string;
  filePath: string;
  line: number;
  isAsync: boolean;
  callsTo: string[];
  calledBy: string[];
  sideEffects: string[];
}

interface CallGraph {
  nodes: Map<string, CallGraphNode>;
  entryPoints: string[];
  deadCode: string[];
}

const SIDE_EFFECT_PATTERNS: Record<string, RegExp[]> = {
  database: [/\.query\(/, /\.execute\(/, /\.insertOne\(/, /\.updateOne\(/],
  filesystem: [/fs\.\w+\(/, /readFile/, /writeFile/, /readFileSync/],
  network: [/fetch\(/, /axios\.\w+\(/, /http\.\w+\(/],
  messaging: [/\.emit\(/, /\.publish\(/, /\.send\(/],
};

function detectSideEffects(body: string): string[] {
  const effects: string[] = [];
  for (const [category, patterns] of Object.entries(SIDE_EFFECT_PATTERNS)) {
    for (const pattern of patterns) {
      if (pattern.test(body)) { effects.push(category); break; }
    }
  }
  return effects;
}

function resolveCalleeName(callExpr: CallExpression): string | null {
  const expression = callExpr.getExpression();
  if (Node.isIdentifier(expression)) return expression.getText();
  if (Node.isPropertyAccessExpression(expression)) {
    return `${expression.getExpression().getText()}.${expression.getName()}`;
  }
  return null;
}

export function buildCallGraph(projectPath: string, entryPatterns: string[]): CallGraph {
  const project = new Project({ compilerOptions: { allowJs: true, target: 99 } });
  project.addSourceFilesAtPaths(`${projectPath}/**/*.{ts,tsx,js,jsx}`);
  const graph: CallGraph = { nodes: new Map(), entryPoints: [], deadCode: [] };

  // 第一遍：收集所有函数定义作为节点
  for (const sourceFile of project.getSourceFiles()) {
    const filePath = sourceFile.getFilePath();
    sourceFile.forEachChild((node) => {
      if (Node.isFunctionDeclaration(node) && node.getName()) {
        const key = `${filePath}:${node.getName()}`;
        graph.nodes.set(key, {
          name: node.getName()!,
          filePath,
          line: node.getStartLineNumber(),
          isAsync: node.isAsync(),
          callsTo: [],
          calledBy: [],
          sideEffects: detectSideEffects(node.getBodyText?.() ?? ""),
        });
      }
      if (Node.isVariableStatement(node)) {
        node.getDeclarations().forEach((decl) => {
          const init = decl.getInitializer();
          if (init && (Node.isArrowFunction(init) || Node.isFunctionExpression(init))) {
            const key = `${filePath}:${decl.getName()}`;
            graph.nodes.set(key, {
              name: decl.getName(), filePath,
              line: decl.getStartLineNumber(),
              isAsync: init.isAsync?.() ?? false,
              callsTo: [], calledBy: [],
              sideEffects: detectSideEffects(init.getBodyText?.() ?? ""),
            });
          }
        });
      }
    });
  }

  // 第二遍：分析函数调用关系
  for (const sourceFile of project.getSourceFiles()) {
    const filePath = sourceFile.getFilePath();
    sourceFile.forEachChild((node) => {
      if (!Node.isFunctionDeclaration(node)) return;
      const callerKey = `${filePath}:${node.getName()}`;
      if (!graph.nodes.has(callerKey)) return;
      for (const callExpr of node.getDescendantsOfKind(SyntaxKind.CallExpression)) {
        const calleeName = resolveCalleeName(callExpr);
        if (!calleeName) continue;
        const calleeKey = `${filePath}:${calleeName}`;
        if (graph.nodes.has(calleeKey)) {
          graph.nodes.get(callerKey)!.callsTo.push(calleeKey);
          graph.nodes.get(calleeKey)!.calledBy.push(callerKey);
        }
      }
    });
  }

  // 第三遍：确定入口点并 BFS 找 Dead Code
  for (const [key, node] of graph.nodes) {
    if (entryPatterns.some((p) => node.name.includes(p))) graph.entryPoints.push(key);
  }
  const reachable = new Set<string>();
  const queue = [...graph.entryPoints];
  while (queue.length > 0) {
    const current = queue.shift()!;
    if (reachable.has(current)) continue;
    reachable.add(current);
    graph.nodes.get(current)?.callsTo.forEach((c) => { if (!reachable.has(c)) queue.push(c); });
  }
  graph.deadCode = [...graph.nodes.keys()].filter((k) => !reachable.has(k));
  return graph;
}

export function formatCallChain(graph: CallGraph, startKey: string, depth = 0, visited = new Set<string>()): string {
  if (visited.has(startKey)) return `${"  ".repeat(depth)}[循环: ${startKey.split(":").pop()}]\n`;
  visited.add(startKey);
  const node = graph.nodes.get(startKey);
  if (!node) return "";
  const indent = "  ".repeat(depth);
  const tag = node.sideEffects.length > 0 ? ` ⚡[${node.sideEffects.join(",")}]` : "";
  let result = `${indent}→ ${node.name} (${node.filePath.split("/").pop()}:${node.line})${tag}\n`;
  for (const callee of node.callsTo) result += formatCallChain(graph, callee, depth + 1, visited);
  return result;
}
```

### 示例二：使用 Python ast 模块构建调用图

```python
# call_graph_builder.py
import ast, os
from dataclasses import dataclass, field

SIDE_EFFECT_PATTERNS = {
    "database": [".query(", ".execute(", ".insert_one(", ".update_one("],
    "filesystem": ["open(", "read(", "write(", "os.path."],
    "network": ["requests.", "httpx.", "urllib.", "aiohttp."],
    "messaging": [".publish(", ".send(", ".emit("],
}

@dataclass
class FunctionNode:
    name: str
    file_path: str
    line: int
    is_async: bool
    calls_to: list = field(default_factory=list)
    called_by: list = field(default_factory=list)
    side_effects: list = field(default_factory=list)

@dataclass
class CallGraph:
    nodes: dict = field(default_factory=dict)
    entry_points: list = field(default_factory=list)
    dead_code: list = field(default_factory=list)

class FunctionCollector(ast.NodeVisitor):
    def __init__(self, file_path):
        self.file_path = file_path
        self.functions = []
    def visit_FunctionDef(self, node):
        self.functions.append((node.name, node))
        self.generic_visit(node)
    def visit_AsyncFunctionDef(self, node):
        self.functions.append((node.name, node))
        self.generic_visit(node)

class CallCollector(ast.NodeVisitor):
    def __init__(self):
        self.calls = []
    def visit_Call(self, node):
        callee = self._resolve(node.func)
        if callee: self.calls.append(callee)
        self.generic_visit(node)
    def _resolve(self, node):
        if isinstance(node, ast.Name): return node.id
        if isinstance(node, ast.Attribute):
            if isinstance(node.value, ast.Name): return f"{node.value.id}.{node.attr}"
        return None

def detect_side_effects(source):
    return [cat for cat, pats in SIDE_EFFECT_PATTERNS.items() if any(p in source for p in pats)]

def build_call_graph(project_path, entry_patterns):
    graph = CallGraph()
    py_files = [os.path.join(r, f) for r, _, fs in os.walk(project_path) for f in fs if f.endswith(".py")]
    ast_trees = {}
    for fpath in py_files:
        with open(fpath, "r", encoding="utf-8") as f: source = f.read()
        try: ast_trees[fpath] = ast.parse(source, filename=fpath)
        except SyntaxError: continue
        collector = FunctionCollector(fpath)
        collector.visit(ast_trees[fpath])
        for name, node in collector.functions:
            graph.nodes[f"{fpath}:{name}"] = FunctionNode(
                name=name, file_path=fpath, line=node.lineno,
                is_async=isinstance(node, ast.AsyncFunctionDef),
                side_effects=detect_side_effects(source),
            )
    for fpath, tree in ast_trees.items():
        collector = FunctionCollector(fpath)
        collector.visit(tree)
        for func_name, func_node in collector.functions:
            caller_key = f"{fpath}:{func_name}"
            cc = CallCollector()
            for child in ast.walk(func_node): cc.visit(child)
            for callee in cc.calls:
                callee_key = f"{fpath}:{callee}"
                if callee_key in graph.nodes:
                    graph.nodes[caller_key].calls_to.append(callee_key)
                    graph.nodes[callee_key].called_by.append(caller_key)
    for key, node in graph.nodes.items():
        if any(p in node.name for p in entry_patterns): graph.entry_points.append(key)
    reachable = set()
    queue = list(graph.entry_points)
    while queue:
        cur = queue.pop(0)
        if cur in reachable: continue
        reachable.add(cur)
        for c in graph.nodes.get(cur, FunctionNode("", "", 0, False)).calls_to:
            if c not in reachable: queue.append(c)
    graph.dead_code = [k for k in graph.nodes if k not in reachable]
    return graph

def format_call_chain(graph, start_key, depth=0, visited=None):
    if visited is None: visited = set()
    if start_key in visited: return f"{'  '*depth}[循环: {start_key.split(':')[-1]}]\n"
    visited.add(start_key)
    node = graph.nodes.get(start_key)
    if not node: return ""
    tag = f" ⚡[{','.join(node.side_effects)}]" if node.side_effects else ""
    result = f"{'  '*depth}→ {node.name} ({os.path.basename(node.file_path)}:{node.line}){tag}\n"
    for c in node.calls_to: result += format_call_chain(graph, c, depth+1, visited)
    return result
```

### 示例三：可视化为 Mermaid 和文本树

```typescript
// src/visualizer.ts
import { CallGraph } from "./call-graph-builder";

export function toMermaid(graph: CallGraph, entryKey: string, maxDepth = 4): string {
  const lines = ["graph TD"];
  const visited = new Set<string>();
  function walk(key: string, depth: number) {
    if (depth > maxDepth || visited.has(key)) return;
    visited.add(key);
    const node = graph.nodes.get(key);
    if (!node) return;
    const id = key.replace(/[^a-zA-Z0-9]/g, "_");
    const label = node.sideEffects.length > 0 ? `${node.name}\\n⚡` : node.name;
    lines.push(`    ${id}["${label}"]${node.sideEffects.length ? ":::sideEffect" : ""}`);
    for (const callee of node.callsTo) {
      const cNode = graph.nodes.get(callee);
      if (cNode) {
        lines.push(`    ${id} --> ${callee.replace(/[^a-zA-Z0-9]/g, "_")}`);
        walk(callee, depth + 1);
      }
    }
  }
  walk(entryKey, 0);
  lines.push("    classDef sideEffect fill:#ff6b6b,stroke:#333,color:#fff");
  return lines.join("\n");
}

export function toTextTree(graph: CallGraph, entryKey: string): string {
  const lines: string[] = [];
  const visited = new Set<string>();
  function walk(key: string, prefix: string, isLast: boolean) {
    const node = graph.nodes.get(key);
    if (!node) return;
    const conn = isLast ? "└── " : "├── ";
    const tag = node.sideEffects.length > 0 ? ` [${node.sideEffects.join(",")}]` : "";
    lines.push(`${prefix}${conn}${node.name}${tag}`);
    if (visited.has(key)) { lines.push(`${prefix}${isLast?"    ":"│   "}└── (已展开)`); return; }
    visited.add(key);
    const childPrefix = prefix + (isLast ? "    " : "│   ");
    const callees = node.callsTo.filter((c) => graph.nodes.has(c));
    callees.forEach((c, i) => walk(c, childPrefix, i === callees.length - 1));
  }
  const entry = graph.nodes.get(entryKey);
  if (entry) {
    lines.push(entry.name);
    visited.add(entryKey);
    const callees = entry.callsTo.filter((c) => graph.nodes.has(c));
    callees.forEach((c, i) => walk(c, "", i === callees.length - 1));
  }
  return lines.join("\n");
}
```

## 常见误区

### 误区一：只看当前函数就能理解其行为

很多人分析代码时只看函数本身，不追踪子函数。在遗留代码中尤其危险——一个看似简单的 `processOrder`，可能在三层之后调用了同步文件读取或远程 API。**正确做法**：至少追踪到第二层调用，关键业务流程追踪到叶子节点。

### 误区二：忽略动态调用

JavaScript 的 `func.call(this, arg)` 和 `func.apply(this, args)` 以及 Python 的 `getattr(obj, method_name)()` 在 AST 中不会被识别为普通调用。**正确做法**：对这些做特殊处理，标记为"动态调用，需人工确认"。

### 误区三：把 Dead Code 当作可安全删除的代码

从静态调用图中找出的"不可达代码"不一定真的是 Dead Code。如果代码通过字符串动态引用（事件名、插件名、路由表），静态分析无法追踪。**正确做法**：结合 `git log`、搜索字符串引用等方式交叉验证后再决定。

### 误区四：调用图太大时试图一次性可视化

500 个函数的完整调用图会变成一团乱麻。**正确做法**：只可视化从入口点出发的子图，限制深度 3-5 层。

## 小结与练习

### 小结

1. **调用图**是有向图，节点是函数，边是调用关系，是理解遗留代码结构的核心工具
2. **静态分析**从源码 AST 构建，覆盖所有路径，适合迁移场景；**动态追踪**从运行时获取，适合性能优化
3. 从入口点 BFS 遍历可自动识别 **Dead Code**
4. 标记叶子节点中的**副作用函数**是理解调用链路"最终影响"的关键
5. 动态调用、闭包、字符串引用等场景会降低静态分析准确性，需人工辅助

## 参考答案

### 练习一

**思路**：从路由处理函数出发，逐层追踪每个函数调用到叶子节点，特别关注数据库操作和网络请求。

**答案**：

```
匿名路由处理函数 (app.js)
├── validateOrder (validators.js) ← 纯函数，无副作用
├── createOrder (orderService.js)
│   ├── calculateTotal (pricingService.js) ← 需确认实现
│   ├── db.query ⚡[database]
│   └── sendNotification ⚡[messaging/network]
└── res.json() ⚡[network — HTTP 响应]
```

**要点**：
- `db.query("INSERT INTO orders ...")` 是数据库写入操作
- `sendNotification` 是推送通知，可能走消息队列或邮件
- `createOrder` 先写数据库再发通知——如果通知失败，订单已写入，这是潜在的一致性问题

### 练习二

**思路**：用 `ast.parse` 解析代码，第一遍收集 `FunctionDef`，第二遍在每个函数体内查找 `Call`，通过字符串匹配识别副作用。

**答案**：

```
入口点: initialize_app (由 __main__ 触发)

initialize_app (line 10)
├── load_config (line 4) ⚡[filesystem]
│   └── open() ⚡[filesystem]
├── parse_config (line 7) ← 纯函数
└── save_to_database (line 11) ⚡[database]
    └── conn.execute() ⚡[database]
```

Dead Code：`health_check` — 从入口点不可达。但它可能被框架的健康检查端点调用，删除前应搜索确认。
