# AI 代码迁移与遗留系统现代化

> 用 AI 加速代码理解、框架迁移和技术债清理——让遗留系统重获新生。

## 这门课解决什么问题

每个有一定历史的软件团队都面临同一个困境：遗留系统维护成本越来越高，但重写风险太大、迁移周期太长。一个典型场景：

- 公司有一个 5 年前写的 jQuery + PHP 系统，想迁移到 React + Node.js
- 手动迁移估计要 6 个月，期间还要维护老系统
- 业务逻辑散落在几千个文件里，没人能说清完整的业务流程
- 新功能不敢加在老系统上，但迁移又遥遥无期

AI 改变了这个等式。LLM 可以在几秒内理解一个函数的语义，AST 分析工具可以自动提取依赖关系，代码生成模型可以将一种语言翻译成另一种语言。但这不是简单的"把代码丢给 GPT 翻译"——企业级迁移需要：

- **代码理解**：自动提取业务逻辑、依赖关系、调用链路
- **渐进式迁移**：不是一次性切换，而是新老系统并行运行
- **自动化验证**：迁移后的代码必须通过等价性测试
- **风险控制**：每一步都能回滚，每个变更都有审计

## 前置要求

- 有维护过 2 年以上代码库的经验
- 了解 AST（抽象语法树）概念者更佳
- 熟悉至少一种前后端框架（React/Vue/Express/Django）

## 技术栈

| 类别 | 技术 | 说明 |
|------|------|------|
| 代码分析 | AST Parser (Babel / ts-morph / Python ast) | 代码结构解析 |

| 代码转换 | jscodeshift / ts-morph / 自研 Transformer | AST 级代码转换 |
| 测试验证 | Vitest / Playwright / 自研等价性测试 | 迁移后验证 |

| 前端迁移 | React / Vue 3 / TypeScript | 目标技术栈 |
| 后端迁移 | Node.js / FastAPI / Go | 目标后端框架 |
| CI/CD | GitHub Actions | 自动化迁移流水线 |

## 课程大纲

### Part 1：代码理解与分析（6 课时）

> 迁移的前提是理解——让 AI 帮你读懂遗留代码

1. 代码迁移的工程现实——为什么"重写"几乎总是错的
2. AST 基础——抽象语法树的原理与 JavaScript/Python AST 实战
3. 依赖关系图谱——自动提取模块依赖、循环依赖检测、影响分析
4. 调用链路分析——从入口函数到数据库操作的完整链路追踪
5. AI 代码理解——用 LLM 批量生成代码摘要、识别业务逻辑
6. **阶段实战：遗留代码智能分析工具**

### Part 2：AI 迁移工具链（8 课时）

> 构建自动化的代码迁移工具

7. AST 级代码转换——jscodeshift / ts-morph 实战
8. LLM 代码翻译——Prompt 工程与代码翻译的质量控制
9. 批量重构——变量重命名、函数拆分、模块重组的自动化
10. 依赖注入与接口抽象——让新老代码可以并行运行
11. API 兼容层——新系统兼容老 API 的适配器模式
12. 数据库迁移——Schema 迁移、数据回填、双写策略
13. 配置迁移——环境变量、Feature Flag、权限配置的迁移
14. **阶段实战：jQuery 到 React 的自动化迁移工具**

### Part 3：框架升级实战（8 课时）

> 真实场景的迁移工程

15. jQuery → React 迁移——事件处理、DOM 操作、状态管理的转换
16. Express → Fastify/NestJS 迁移——中间件、路由、错误处理的升级
17. Python 2 → Python 3 迁移——语法差异、库兼容、类型注解
18. Vue 2 → Vue 3 迁移——Options API → Composition API 的自动化
19. CSS 迁移——从 CSS/Less 到 Tailwind/CSS Modules 的转换
20. 模块系统迁移——CommonJS → ESM、AMD → ESM 的自动化
21. TypeScript 渐进式迁移——JavaScript 项目的类型安全改造
22. **阶段实战：Vue 2 到 Vue 3 的完整迁移**

### Part 4：企业级迁移工程（6 课时）

> 让迁移可控、可回滚、可验证

23. 渐进式迁移策略——Strangler Fig Pattern、Branch by Abstraction
24. 等价性测试——迁移前后行为一致性的自动化验证
25. 灰度切换——新老系统的流量切换与监控
26. 回滚机制——每一步都能安全回滚的工程实践
27. 迁移度量——代码覆盖率、迁移进度、质量指标的可视化
28. **阶段实战：迁移流水线与质量门禁**

### 毕业项目：遗留系统迁移工具链

整合全部所学，构建一套完整的遗留系统迁移工具：
- 代码分析器——自动提取依赖关系、调用链路、代码摘要
- 迁移规划器——AI 分析迁移难度、生成迁移计划、估算工作量
- 自动转换器——AST 级代码转换 + LLM 辅助翻译
- 测试生成器——自动生成迁移后的等价性测试
- 进度看板——迁移进度、质量指标、风险预警
- CI/CD 集成——自动化迁移流水线，每次提交自动验证

## 学习建议

1. **理解比转换更重要**。不要急着写转换脚本，先花时间理解遗留代码的业务逻辑
2. **渐进式优于一次性**。Strangler Fig Pattern 是最安全的迁移策略
3. **测试是安全网**。迁移前先补充测试，没有测试的迁移就是在裸奔
4. **AI 是加速器不是替代品**。LLM 生成的代码必须人工审查，尤其是边界条件
