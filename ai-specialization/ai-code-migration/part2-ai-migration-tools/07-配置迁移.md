# 配置迁移与环境管理

## 场景引入

你的团队要把一个 Node.js 单体应用拆成 5 个微服务。原来所有配置都写在一个 `.env` 文件里，有 120 多个环境变量，其中 30 个是密钥。现在每个微服务只需要自己的配置，但有些是共享的（Redis 地址、公共 API Key）。

更麻烦的是：开发环境用 `.env`，测试环境用 JSON，生产环境用 Kubernetes ConfigMap——格式完全不同。还有人把 `.env` 提交到了 Git 历史里，密钥可能已经泄露。

配置迁移看起来没有代码迁移那么"技术含量高"，但它出错的后果同样严重：一个配置项搞错，服务可能连上错误的数据库，或者把密钥泄露到日志里。

## 学习目标

完成本课学习后，你将能够：

1. 理解配置迁移的四个层次（格式、结构、语义、管理方式）
2. 实现配置格式转换工具（XML→YAML、JSON→TOML）
3. 用 12-Factor App 原则管理环境变量
4. 安全地迁移密钥和敏感配置
5. 用 Zod 实现配置 Schema 校验

## 核心概念

### 配置迁移的四个层次

很多人以为配置迁移就是格式转换。实际上有四个层次：

```
┌─────────────────────────────────────────┐
│            配置迁移的四个层次             │
├─────────────────────────────────────────┤
│  层次 1: 格式迁移                        │
│  XML → YAML, .env → JSON               │
├─────────────────────────────────────────┤
│  层次 2: 结构迁移                        │
│  扁平 db_host → 嵌套 database.host       │
├─────────────────────────────────────────┤
│  层次 3: 语义迁移                        │
│  timeout=30(秒) → timeout=30000(毫秒)   │
├─────────────────────────────────────────┤
│  层次 4: 管理方式迁移                    │
│  文件 → 环境变量/配置中心/密钥管理       │
└─────────────────────────────────────────┘
```

### 配置格式对比

| 格式 | 适用场景 | 优点 | 缺点 |
|------|---------|------|------|
| `.env` | 开发环境、简单项目 | 简单、Docker/K8s 原生支持 | 不支持嵌套、无类型 |
| JSON | API 配置 | 通用、有 Schema | 不支持注释、尾逗号 |
| YAML | Kubernetes、CI/CD | 可读性好、支持注释 | 缩进敏感、隐式类型转换 |
| TOML | Rust/Go 项目 | 语义清晰 | 不够流行 |
| XML | Java 企业项目 | 验证严格 | 冗长 |

### 12-Factor App 配置原则

核心思想：**配置与代码分离，用环境变量注入**。

```
代码仓库（不变）  +  环境变量（每个环境不同）  =  运行的应用
```

## 实战：配置格式转换工具

### XML 转 YAML

```javascript
// tools/xml-to-yaml.js
const fs = require('fs');
const { XMLParser } = require('fast-xml-parser');
const yaml = require('js-yaml');

function xmlToYaml(xmlContent) {
  const parser = new XMLParser({
    ignoreAttributes: false,
    attributeNamePrefix: '@_',
    textNodeName: '#text',
  });
  const parsed = parser.parse(xmlContent);
  return yaml.dump(parsed, { indent: 2, lineWidth: 120 });
}

function convertDirectory(inputDir, outputDir) {
  if (!fs.existsSync(outputDir)) fs.mkdirSync(outputDir, { recursive: true });
  const files = fs.readdirSync(inputDir).filter(f => f.endsWith('.xml'));

  for (const file of files) {
    const xmlContent = fs.readFileSync(`${inputDir}/${file}`, 'utf-8');
    const yamlContent = xmlToYaml(xmlContent);
    const outputFile = file.replace('.xml', '.yml');
    fs.writeFileSync(`${outputDir}/${outputFile}`, yamlContent);
    console.log(`转换完成: ${file} → ${outputFile}`);
  }
}

convertDirectory('./config-xml', './config-yaml');
```

### 环境变量拆分工具

把一个大 `.env` 文件拆分成多个微服务的配置：

```javascript
// tools/split-env.js
const fs = require('fs');

function splitEnvFile(envPath, serviceMapping) {
  const content = fs.readFileSync(envPath, 'utf-8');
  const lines = content.split('\n').filter(line => line.trim() && !line.startsWith('#'));
  const services = {};

  for (const line of lines) {
    const [key, ...valueParts] = line.split('=');
    const trimmedKey = key.trim();
    const value = valueParts.join('=').trim();
    const service = identifyService(trimmedKey, serviceMapping);
    if (!services[service]) services[service] = [];
    services[service].push(`${trimmedKey}=${value}`);
  }

  for (const [service, envLines] of Object.entries(services)) {
    fs.writeFileSync(`./config/${service}.env`, envLines.join('\n') + '\n');
    console.log(`${service}.env: ${envLines.length} 个配置项`);
  }
}

function identifyService(key, mapping) {
  for (const [service, patterns] of Object.entries(mapping)) {
    if (patterns.some(p => key.startsWith(p) || key.includes(p))) return service;
  }
  return 'shared';
}

splitEnvFile('.env', {
  'user-service': ['USER_', 'JWT_', 'AUTH_'],
  'order-service': ['ORDER_', 'PAYMENT_', 'CART_'],
  'product-service': ['PRODUCT_', 'INVENTORY_', 'CATEGORY_'],
  'notification-service': ['EMAIL_', 'SMS_', 'PUSH_'],
  'shared': ['REDIS_', 'DATABASE_URL', 'LOG_LEVEL'],
});
```

## 密钥和敏感配置的安全迁移

### 密钥泄露检测

首先检查 Git 历史中是否有泄露的密钥：

```bash
# 安装 gitleaks 并扫描
gitleaks detect --source . --verbose
gitleaks detect --source . --log-opts="--since=2024-01-01"
```

### 用 SOPS 加密敏感配置

SOPS 可以加密 YAML/JSON 文件中的特定字段：

```bash
# 生成加密密钥
age-keygen -o keys.txt

# 加密配置文件
sops --encrypt --age <public-key> secrets.yml > secrets.enc.yml

# 解密
sops --decrypt secrets.enc.yml
```

在代码中解密：

```javascript
const { execSync } = require('child_process');

function loadSecrets(encryptedPath) {
  try {
    const output = execSync(`sops --decrypt ${encryptedPath}`, {
      encoding: 'utf-8',
      env: { ...process.env, SOPS_AGE_KEY: process.env.SOPS_AGE_KEY },
    });
    return JSON.parse(output);
  } catch (error) {
    console.error('解密配置失败:', error.message);
    process.exit(1);
  }
}
```

### 用 Vault 管理密钥

对于大型团队，推荐用 HashiCorp Vault 集中管理：

```javascript
const axios = require('axios');

class VaultClient {
  constructor({ address, token }) {
    this.address = address;
    this.token = token;
    this.cache = new Map();
    this.cacheTTL = 5 * 60 * 1000;
  }

  async getSecret(path) {
    const cached = this.cache.get(path);
    if (cached && Date.now() - cached.timestamp < this.cacheTTL) return cached.data;

    const response = await axios.get(`${this.address}/v1/secret/data/${path}`, {
      headers: { 'X-Vault-Token': this.token },
    });
    const data = response.data.data.data;
    this.cache.set(path, { data, timestamp: Date.now() });
    return data;
  }
}
```

## 配置验证：用 Zod 做 Schema 校验

配置不验证是生产事故的常见原因。用 Zod 在启动时就发现配置错误：

```javascript
const { z } = require('zod');

const configSchema = z.object({
  NODE_ENV: z.enum(['development', 'test', 'staging', 'production']),
  PORT: z.string().regex(/^\d+$/).transform(Number).pipe(z.number().min(1024).max(65535)),
  DATABASE_URL: z.string().url(),
  REDIS_URL: z.string().url(),
  JWT_SECRET: z.string().min(32, 'JWT_SECRET 至少 32 个字符'),
  JWT_EXPIRES_IN: z.string().default('7d'),
  LOG_LEVEL: z.enum(['debug', 'info', 'warn', 'error']).default('info'),
  CORS_ORIGIN: z.string().default('*'),
  FEATURE_NEW_UI: z.string().transform(v => v === 'true').default('false'),
});

function validateConfig(env = process.env) {
  const result = configSchema.safeParse(env);
  if (!result.success) {
    console.error('配置验证失败:');
    for (const issue of result.error.issues) {
      console.error(`  ${issue.path.join('.')}: ${issue.message}`);
    }
    process.exit(1);
  }
  return result.data;
}

const config = validateConfig();
console.log(`应用启动: ${config.NODE_ENV} 环境, 端口 ${config.PORT}`);
```

### 配置热更新

支持配置文件变更后自动重载：

```javascript
const fs = require('fs');
const yaml = require('js-yaml');

function createConfigReloader(filePath, validator) {
  let currentConfig = null;
  const listeners = [];

  function loadConfig() {
    const content = fs.readFileSync(filePath, 'utf-8');
    const ext = filePath.split('.').pop();
    const parsed = ext === 'json' ? JSON.parse(content) : yaml.load(content);
    const result = validator.safeParse(parsed);
    return result.success ? result.data : currentConfig;
  }

  currentConfig = loadConfig();
  fs.watch(filePath, () => {
    const newConfig = loadConfig();
    if (newConfig !== currentConfig) {
      const old = currentConfig;
      currentConfig = newConfig;
      listeners.forEach(fn => fn(newConfig, old));
      console.log('配置已更新');
    }
  });

  return { get: () => currentConfig, onChange: (fn) => listeners.push(fn) };
}
```

## 多环境配置管理

### 配置分层架构

```
config/
├── base.yml          # 基础配置（所有环境共享）
├── development.yml   # 开发环境覆盖
├── staging.yml       # 预发布环境覆盖
├── production.yml    # 生产环境覆盖
└── secrets/
    ├── dev.enc.json  # 开发环境密钥（加密）
    └── prd.enc.json  # 生产环境密钥
```

```javascript
const fs = require('fs');
const yaml = require('js-yaml');
const path = require('path');

function loadConfig(env = process.env.NODE_ENV || 'development') {
  const configDir = path.join(__dirname, '../config');
  const base = yaml.load(fs.readFileSync(path.join(configDir, 'base.yml'), 'utf-8'));

  const envFile = path.join(configDir, `${env}.yml`);
  let envConfig = {};
  if (fs.existsSync(envFile)) {
    envConfig = yaml.load(fs.readFileSync(envFile, 'utf-8'));
  }

  const merged = deepMerge(base, envConfig);

  // 环境变量覆盖（优先级最高）
  for (const [key, value] of Object.entries(process.env)) {
    if (key.startsWith('APP_')) {
      setNestedValue(merged, key.slice(4).toLowerCase().replace(/_/g, '.'), value);
    }
  }

  return merged;
}

function deepMerge(target, source) {
  const result = { ...target };
  for (const key of Object.keys(source)) {
    if (source[key] && typeof source[key] === 'object' && !Array.isArray(source[key])) {
      result[key] = deepMerge(result[key] || {}, source[key]);
    } else {
      result[key] = source[key];
    }
  }
  return result;
}

function setNestedValue(obj, path, value) {
  const keys = path.split('.');
  let current = obj;
  for (let i = 0; i < keys.length - 1; i++) {
    if (!current[keys[i]]) current[keys[i]] = {};
    current = current[keys[i]];
  }
  current[keys[keys.length - 1]] = value;
}
```

## 常见误区

**误区一：把密钥提交到 Git。** 即使后来删除了，Git 历史中仍然存在。必须用 gitleaks 扫描历史，然后轮换所有泄露的密钥。

**误区二：不做配置验证。** 配置写错了服务启动后才报错，错误信息不明确。应该在启动时用 Zod 验证所有配置项。

**误区三：所有环境用同一份配置。** 开发环境和生产环境混在一起，导致本地连上生产数据库。必须严格隔离。

**误区四：配置变更没有审计。** 谁改了配置、什么时候改的、改了什么，完全没有记录。生产配置变更应有审批流程。

---

## 小结

- 配置迁移有四个层次：格式、结构、语义、管理方式
- 密钥迁移必须先扫描 Git 历史，然后轮换所有泄露的密钥
- 用 Zod 做配置 Schema 校验，启动时就能发现错误
- 多环境配置用分层架构：base + 环境覆盖 + 环境变量覆盖
- 敏感配置用 SOPS 或 Vault 管理，不能明文存储

## 参考答案

### 练习一

**思路**：用 fast-xml-parser 解析 XML，然后手动拼接带注释的 YAML。

**答案**：

```javascript
const { XMLParser } = require('fast-xml-parser');

function xmlToYamlWithComments(xmlContent) {
  const parser = new XMLParser({ ignoreAttributes: false, textNodeName: '#text' });
  const { configuration: c } = parser.parse(xmlContent);

  return [
    '# 数据库配置',
    'database:',
    `  host: ${c.database.host}      # 数据库地址`,
    `  port: ${c.database.port}      # 数据库端口`,
    `  name: ${c.database.name}      # 数据库名称`,
    '',
    '# Redis 配置',
    'redis:',
    `  host: ${c.redis.host}         # Redis 地址`,
    `  port: ${c.redis.port}         # Redis 端口`,
  ].join('\n');
}
```

**要点**：fast-xml-parser 将 XML 解析为 JS 对象；注释需要手动拼接因为 js-yaml 不支持保留注释。

### 练习二

**思路**：用 Zod 定义 Schema，处理类型转换、默认值、自定义验证规则。

**答案**：

```javascript
const { z } = require('zod');

const appConfigSchema = z.object({
  PORT: z.string().regex(/^\d+$/, 'PORT 必须是数字')
    .transform(Number).pipe(z.number().min(1024).max(65535)),
  DATABASE_URL: z.string().url('DATABASE_URL 必须是有效的 URL'),
  JWT_SECRET: z.string().min(32, 'JWT_SECRET 至少 32 个字符')
    .refine(s => /[A-Z]/.test(s) && /[0-9]/.test(s), { message: 'JWT_SECRET 必须包含大写字母和数字' }),
  LOG_LEVEL: z.enum(['debug', 'info', 'warn', 'error']).default('info'),
  CORS_ORIGIN: z.string().default('*'),
});

function validateAppConfig() {
  const result = appConfigSchema.safeParse(process.env);
  if (!result.success) {
    console.error('配置验证失败:');
    result.error.issues.forEach(i => console.error(`  ${i.path.join('.')}: ${i.message}`));
    process.exit(1);
  }
  return result.data;
}
```

**要点**：PORT 用 `transform` 从字符串转数字再用 `pipe` 做范围验证；JWT_SECRET 用 `refine` 做自定义复杂度验证；可选项用 `.default()` 设置默认值。
