# 数据库迁移策略与实践

## 场景引入

你的电商系统运行了三年，`users` 表有 2000 万行数据。现在要把 `phone` 字段从 `VARCHAR(11)` 改成 `VARCHAR(20)` 支持国际号码，同时把 `address` 字段从一个大文本拆成 `street`、`city`、`zip_code` 三个独立字段。你不能停服——每分钟都有订单产生。你也不能简单 `ALTER TABLE`——2000 万行执行 DDL 可能锁表几小时。

更要命的是，团队同时决定把数据库从 MySQL 迁到 PostgreSQL。这意味着不只是改字段，而是整个数据库引擎都换了。本课系统讲解数据库迁移的策略、工具和实战技巧。

## 学习目标

完成本课学习后，你将能够：

1. 理解数据库迁移的三个维度：Schema、数据、查询
2. 掌握 Schema 迁移工具（Prisma Migrate、Atlas）的使用
3. 实现全量迁移、增量迁移、双写三种数据迁移策略
4. 处理 MySQL→PostgreSQL 的 SQL 方言差异
5. 设计零停机迁移方案（影子表）
6. 实现迁移后的数据一致性验证

## 核心概念

### 数据库迁移的三个维度

数据库迁移不是一件事，而是三件事：

```
┌─────────────────────────────────────────────┐
│              数据库迁移                       │
├─────────────┬──────────────┬────────────────┤
│  Schema 迁移 │  数据迁移     │  查询迁移      │
│  (结构变)    │  (内容搬)     │  (语法改)      │
├─────────────┼──────────────┼────────────────┤
│ 改字段类型   │ 全量导出导入  │ SQL 方言差异   │
│ 加索引      │ 增量同步      │ ORM 换掉       │
│ 拆表        │ 双写保证一致  │ 存储过程重写   │
└─────────────┴──────────────┴────────────────┘
```

顺序很重要：先迁移 Schema，再迁移数据，最后迁移查询。

### 迁移策略全景图

```
旧数据库(MySQL)
    │
    ├── 阶段 1: Schema 迁移 → 创建影子表、应用 DDL、验证
    ├── 阶段 2: 数据迁移   → 全量搬 + 增量同步 + 双写
    ├── 阶段 3: 查询迁移   → 改写 SQL 方言、更新 ORM
    └── 阶段 4: 切换       → 灰度切读 → 全量切读 → 停双写 → 下线旧库
```

## 实战：Schema 迁移

### Prisma Migrate

```bash
mkdir db-migration-demo && cd db-migration-demo
npm init -y
npm install prisma @prisma/client
npx prisma init
```

定义新的 Schema：

```prisma
// prisma/schema.prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model User {
  id        Int      @id @default(autoincrement())
  name      String   @db.VarChar(100)
  email     String   @unique @db.VarChar(255)
  phone     String?  @db.VarChar(20)
  street    String?  @db.VarChar(200)
  city      String?  @db.VarChar(100)
  zipCode   String?  @db.VarChar(20)
  orders    Order[]
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}

model Order {
  id        Int      @id @default(autoincrement())
  userId    Int
  total     Decimal  @db.Decimal(10, 2)
  status    String   @db.VarChar(20)
  user      User     @relation(fields: [userId], references: [id])
  createdAt DateTime @default(now())
}
```

运行迁移：

```bash
npx prisma migrate dev --name init
```

Prisma 会生成 SQL 文件并执行，创建表、索引、外键约束。

### Atlas：声明式 Schema 迁移

Atlas 是 2024-2025 年崛起的工具，支持声明式——描述目标状态，它自动计算迁移步骤：

```bash
atlas schema apply \
  --url "mysql://root:pass@localhost:3306/mydb" \
  --to "file://schema.hcl" \
  --dev-url "docker://mysql/8/mydb"
```

Atlas 的优势是不需要手写迁移脚本，降低人为错误风险。

## 数据迁移策略

### 策略一：全量迁移

一次性搬所有数据，适用于数据量小（< 100 万行）或允许停服的场景：

```javascript
// scripts/full-migration.js
const mysql = require('mysql2/promise');
const { PrismaClient } = require('@prisma/client');

async function fullMigration() {
  const source = await mysql.createConnection({
    host: 'old-mysql-host', user: 'root', password: 'password', database: 'old_db',
  });
  const target = new PrismaClient();

  const batchSize = 1000;
  let offset = 0, totalMigrated = 0;

  while (true) {
    const [rows] = await source.execute('SELECT * FROM users LIMIT ? OFFSET ?', [batchSize, offset]);
    if (rows.length === 0) break;

    await target.user.createMany({
      data: rows.map(row => ({
        id: row.id,
        name: row.uname,
        email: row.email,
        phone: row.mobile || null,
        createdAt: new Date(row.created_at),
        updatedAt: new Date(row.updated_at || row.created_at),
      })),
      skipDuplicates: true,
    });

    totalMigrated += rows.length;
    offset += batchSize;
    console.log(`已迁移 ${totalMigrated} 条记录`);
  }

  console.log(`迁移完成，共 ${totalMigrated} 条`);
  await source.end();
  await target.$disconnect();
}

fullMigration().catch(console.error);
```

### 策略二：增量迁移（CDC）

用 Change Data Capture 持续同步增量数据，适用于大数据量且不能停服：

```
旧库(MySQL) ──binlog──> Debezium ──Kafka──> 消费者 ──> 新库(PG)
```

```javascript
// scripts/cdc-consumer.js
const { Kafka } = require('kafkajs');
const { PrismaClient } = require('@prisma/client');

const kafka = new Kafka({ brokers: ['localhost:9092'] });
const consumer = kafka.consumer({ groupId: 'migration-group' });
const prisma = new PrismaClient();

async function startCDCConsumer() {
  await consumer.connect();
  await consumer.subscribe({ topic: 'dbserver1.old_db.users' });

  await consumer.run({
    eachMessage: async ({ message }) => {
      const event = JSON.parse(message.value.toString());
      switch (event.op) {
        case 'c': // create
          await prisma.user.create({ data: transformUser(event.after) });
          break;
        case 'u': // update
          await prisma.user.update({ where: { id: event.after.id }, data: transformUser(event.after) });
          break;
        case 'd': // delete
          await prisma.user.delete({ where: { id: event.before.id } });
          break;
      }
    },
  });
}

function transformUser(row) {
  return { name: row.uname, email: row.email, phone: row.mobile || null, updatedAt: new Date() };
}

startCDCConsumer().catch(console.error);
```

### 策略三：双写

同时写入新旧两个数据库，适用于需要逐步迁移读流量的场景：

```javascript
// lib/dual-write.js
const mysql = require('mysql2/promise');
const { PrismaClient } = require('@prisma/client');

class DualWriteDB {
  constructor({ mysqlConfig, enableWriteOld = true, enableWriteNew = true }) {
    this.mysqlPool = null;
    this.prisma = new PrismaClient();
    this.mysqlConfig = mysqlConfig;
    this.enableWriteOld = enableWriteOld;
    this.enableWriteNew = enableWriteNew;
  }

  async init() { this.mysqlPool = await mysql.createPool(this.mysqlConfig); }

  async createUser(userData) {
    const results = {};

    if (this.enableWriteOld) {
      try {
        const [result] = await this.mysqlPool.execute(
          'INSERT INTO users (uname, email, mobile) VALUES (?, ?, ?)',
          [userData.name, userData.email, userData.phone]
        );
        results.old = { id: result.insertId, success: true };
      } catch (error) {
        results.old = { success: false, error: error.message };
      }
    }

    if (this.enableWriteNew) {
      try {
        const user = await this.prisma.user.create({ data: userData });
        results.new = { id: user.id, success: true };
      } catch (error) {
        results.new = { success: false, error: error.message };
      }
    }

    return results;
  }

  async readUser(userId) {
    // 默认从新库读，失败降级到旧库
    try { return await this.prisma.user.findUnique({ where: { id: userId } }); }
    catch { return (await this.mysqlPool.execute('SELECT * FROM users WHERE id = ?', [userId]))[0][0]; }
  }

  async close() { await this.mysqlPool?.end(); await this.prisma.$disconnect(); }
}

module.exports = { DualWriteDB };
```

## SQL 方言差异处理

MySQL 和 PostgreSQL 的 SQL 方言有很多差异：

```javascript
function transformSQL(mysqlSQL) {
  let pgSQL = mysqlSQL;

  // LIMIT offset, count → LIMIT count OFFSET offset
  pgSQL = pgSQL.replace(/LIMIT\s+(\d+)\s*,\s*(\d+)/gi, 'LIMIT $2 OFFSET $1');

  // 反引号 → 双引号
  pgSQL = pgSQL.replace(/`/g, '"');

  // IFNULL → COALESCE
  pgSQL = pgSQL.replace(/IFNULL\(/gi, 'COALESCE(');

  // GROUP_CONCAT → STRING_AGG
  pgSQL = pgSQL.replace(/GROUP_CONCAT\(([^)]+)\)/gi, "STRING_AGG($1, ',')");

  // AUTO_INCREMENT → SERIAL
  pgSQL = pgSQL.replace(/AUTO_INCREMENT/gi, 'SERIAL');

  return pgSQL;
}

module.exports = { transformSQL };
```

常见差异速查：

| MySQL | PostgreSQL | 说明 |
|-------|-----------|------|
| `LIMIT 10, 20` | `LIMIT 20 OFFSET 10` | 分页语法不同 |
| `IFNULL(a, b)` | `COALESCE(a, b)` | 空值处理 |
| `GROUP_CONCAT(col)` | `STRING_AGG(col, ',')` | 字符串聚合 |
| `` `table` `` | `"table"` | 标识符引用 |
| `AUTO_INCREMENT` | `SERIAL` | 自增主键 |
| `TINYINT` | `SMALLINT` | 布尔类型 |

## 零停机迁移：影子表

影子表是零停机迁移的核心技术：

```
阶段 1: 创建影子表 users_new（新结构）
阶段 2: 双写（新写入同时写两张表）+ 回填历史数据
阶段 3: 灰度切读流量到新表（1% → 10% → 100%）
阶段 4: 停旧表写入，重命名 users_new → users
```

```javascript
async function shadowTableMigration(pool) {
  // 创建影子表
  await pool.execute('CREATE TABLE IF NOT EXISTS users_new LIKE users');
  await pool.execute(`ALTER TABLE users_new
    ADD COLUMN street VARCHAR(200) DEFAULT NULL,
    ADD COLUMN city VARCHAR(100) DEFAULT NULL,
    ADD COLUMN zip_code VARCHAR(20) DEFAULT NULL`);

  // 创建触发器实现双写
  await pool.execute(`
    CREATE TRIGGER users_insert_trigger AFTER INSERT ON users FOR EACH ROW
    INSERT INTO users_new (id, uname, email, mobile, created_at)
    VALUES (NEW.id, NEW.uname, NEW.email, NEW.mobile, NEW.created_at)`);

  // 分批回填历史数据
  let offset = 0;
  const batchSize = 5000;
  while (true) {
    const [rows] = await pool.execute(
      `INSERT INTO users_new (id, uname, email, mobile, created_at)
       SELECT id, uname, email, mobile, created_at FROM users ORDER BY id LIMIT ? OFFSET ?`,
      [batchSize, offset]
    );
    if (rows.affectedRows === 0) break;
    offset += batchSize;
    console.log(`已回填 ${offset} 条记录`);
    await new Promise(r => setTimeout(r, 100)); // 减少对线上影响
  }
}
```

## 数据验证

迁移完成后必须验证数据一致性：

```javascript
async function verifyMigration() {
  const source = await mysql.createConnection({ /* 旧库配置 */ });
  const target = new PrismaClient();
  const errors = [];

  // 检查 1：记录数一致
  const [oldCount] = await source.execute('SELECT COUNT(*) as cnt FROM users');
  const newCount = await target.user.count();
  if (oldCount[0].cnt !== newCount) {
    errors.push(`记录数不一致: 旧=${oldCount[0].cnt}, 新=${newCount}`);
  }

  // 检查 2：抽样验证字段值
  const [samples] = await source.execute('SELECT id, uname, email, mobile FROM users ORDER BY RAND() LIMIT 1000');
  for (const old of samples) {
    const newRecord = await target.user.findUnique({ where: { id: old.id } });
    if (!newRecord) { errors.push(`ID ${old.id} 不存在于新库`); continue; }
    if (old.uname !== newRecord.name) errors.push(`ID ${old.id} name 不匹配`);
    if (old.email !== newRecord.email) errors.push(`ID ${old.id} email 不匹配`);
  }

  console.log(`验证完成: ${errors.length} 个错误`);
  errors.slice(0, 20).forEach(e => console.log(`  ✗ ${e}`));
  await source.end();
  await target.$disconnect();
}
```

## 常见误区

**误区一：只迁移 Schema，不迁移数据。** 新表建好了但历史数据没搬，导致查询结果不完整。

**误区二：忽略索引重建。** 大表加索引会锁表，应该用 `CREATE INDEX CONCURRENTLY`（PG）或 `pt-online-schema-change`（MySQL）。

**误区三：不做数据验证。** 上线后才发现数据丢失或字段值错误，至少抽样验证 1% 的数据。

**误区四：一次性迁移所有数据。** 2000 万行一次性迁移会内存溢出或超时，必须分批处理。

## 小结

- 数据库迁移有三个维度：Schema 迁移、数据迁移、查询迁移
- Schema 迁移用 Prisma Migrate 或 Atlas，声明式比手写 SQL 更安全
- 数据迁移三种策略：全量（小数据量）、增量/CDC（大数据量）、双写（零停机）
- MySQL→PostgreSQL 的 SQL 差异必须逐一处理
- 零停机迁移核心是影子表 + 双写 + 灰度切读流量
- 迁移后必须做数据一致性验证

## 参考答案

### 练习一

**思路**：500 万行不能停服，需要影子表 + 双写。价格转换是数学运算，category 需要先建映射表。

**答案**：

```
阶段 1: 创建 categories 表 + products_new 影子表（新结构）
阶段 2: 双写触发器 + 分批回填（price / 100.0, category → category_id）
阶段 3: 抽样验证价格和映射
阶段 4: 灰度切读 → 全量切读 → 停旧表 → 重命名
```

回填关键代码：

```javascript
async function backfillProducts(pool, categoryMap) {
  let lastId = 0;
  const batchSize = 5000;
  while (true) {
    const [rows] = await pool.execute(
      'SELECT id, price, category FROM products WHERE id > ? ORDER BY id LIMIT ?', [lastId, batchSize]
    );
    if (rows.length === 0) break;
    for (const row of rows) {
      await pool.execute(
        'UPDATE products_new SET price = ?, category_id = ? WHERE id = ?',
        [(row.price / 100).toFixed(2), categoryMap[row.category] || null, row.id]
      );
    }
    lastId = rows[rows.length - 1].id;
    await new Promise(r => setTimeout(r, 100));
  }
}
```

**要点**：价格用 `toFixed(2)` 避免浮点精度问题；category 映射失败要记录日志；回填进度要持久化。

### 练习二

**思路**：验证三个维度——数量、价格精度、映射正确性。

**答案**：

```javascript
async function verifyProductMigration() {
  const oldDb = await mysql.createConnection({ /* 旧库 */ });
  const newDb = new PrismaClient();
  const errors = [];

  // 记录数
  const [oldCount] = await oldDb.execute('SELECT COUNT(*) as cnt FROM products');
  const newCount = await newDb.product.count();
  if (oldCount[0].cnt !== newCount) errors.push(`记录数不一致: 旧=${oldCount[0].cnt}, 新=${newCount}`);

  // 抽样验证价格
  const [samples] = await oldDb.execute('SELECT id, price FROM products ORDER BY RAND() LIMIT 1000');
  for (const old of samples) {
    const p = await newDb.product.findUnique({ where: { id: old.id } });
    if (!p) { errors.push(`ID ${old.id} 不存在`); continue; }
    const expected = (old.price / 100).toFixed(2);
    if (p.price.toString() !== expected) errors.push(`ID ${old.id} 价格: 期望 ${expected}, 实际 ${p.price}`);
  }

  console.log(`验证完成: ${errors.length} 个错误`);
  errors.forEach(e => console.log(`  ✗ ${e}`));
}
```

**要点**：价格比较用字符串避免浮点问题；抽样至少 1000 条；错误信息包含 ID 便于定位。
