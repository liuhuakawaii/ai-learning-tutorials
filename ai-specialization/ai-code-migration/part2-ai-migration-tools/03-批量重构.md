# 批量重构

## 场景引入

你们团队的 API 服务层有 200 多个文件，其中大量函数使用了嵌套回调处理异步操作。一个典型的文件长这样：

```javascript
function processOrder(orderId, callback) {
  getOrder(orderId, (err, order) => {
    if (err) return callback(err);
    validateOrder(order, (err, validated) => {
      if (err) return callback(err);
      chargePayment(validated, (err, payment) => {
        if (err) return callback(err);
        sendNotification(payment, (err, result) => {
          if (err) return callback(err);
          callback(null, result);
        });
      });
    });
  });
}
```

这是经典的"回调地狱"。新来的工程师看这种代码直接劝退。团队决定全面迁移到 async/await，但 200 多个文件，每个文件 5-10 个这样的嵌套回调，手动改不现实。

用上一课学的 jscodeshift 写 codemod？可以，但嵌套回调的模式太多变——有的是 3 层嵌套，有的是 5 层；有的用 `if (err)` 检查错误，有的直接调用 `callback(err, null)`。写一个覆盖所有情况的 codemod 本身就是一个巨大的工程。

这就是本课要解决的问题：**如何用 AI 辅助的方式，安全、高效地进行大规模批量重构**。不是纯粹的 codemod，也不是纯粹的手动修改，而是结合 LLM 的理解能力和 codemod 的精确性的混合方案。

## 学习目标

完成本课学习后，你将能够：

1. 设计安全的批量重构工作流
2. 用 LLM 生成针对特定模式的 codemod 代码
3. 用 Git 进行变更追踪和安全回滚
4. 构建重构后的自动化验证 pipeline
5. 处理多文件同时修改的协调问题

## 核心概念

### 批量重构的安全金字塔

批量重构的风险随着修改范围的扩大而指数级上升。安全的做法是分层推进：

```
                    ┌─────────────┐
                    │   全量部署   │
                   ─┤             ├─
                  / └─────────────┘ \
                 /    人工审查 diff    \
                / ──────────────────── \
               /    自动化测试通过       \
              / ──────────────────────── \
             /    CI/CD 质量门禁           \
            / ───────────────────────────── \
           /    单文件/单模块验证              \
          / ────────────────────────────────── \
         /    备份与回滚机制                      \
        └─────────────────────────────────────────┘
```

每一层都是下一层的安全保障。跳过任何一层都可能把一个本应安全的重构变成线上事故。

### AI 辅助批量重构的工作流

传统批量重构是"写 codemod → 运行 → 修 bug"的线性流程。AI 辅助的工作流引入了两个关键环节：**模式识别**和 **codemod 生成**。

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│   模式识别   │───▶│  Codemod 生成 │───▶│  单文件验证   │
│  (LLM 分析)  │    │  (LLM 编写)  │    │  (自动化)     │
└──────────────┘    └──────────────┘    └──────────────┘
                                              │
                                              v
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│   全量部署   │◀───│  人工审查     │◀───│  批量执行     │
│  (CI/CD)     │    │  (diff 审查) │    │  (codemod)   │
└──────────────┘    └──────────────┘    └──────────────┘
```

关键区别在于：传统方式需要工程师手动分析所有代码模式，然后手动编写 codemod。AI 辅助方式让 LLM 先分析代码库，识别出所有变体模式，然后自动生成对应的 codemod。

### 用 LLM 生成 Codemod

这是 AI 辅助批量重构的核心创新：**让 LLM 写 codemod，而不是让 LLM 直接改代码**。

为什么这个策略更好？因为：

1. **codemod 是可测试的**：你可以用 fixture 文件验证 codemod 的正确性
2. **codemod 是可复用的**：一次生成，多次运行
3. **codemod 是确定性的**：相同的输入总是产生相同的输出
4. **codemod 是可审查的**：人工审查的是转换规则，不是每个文件的 diff

下面是一个完整的实现，用 LLM 分析代码模式并生成 jscodeshift codemod：

```typescript
// scripts/generate-codemod.ts
import OpenAI from 'openai';
import * as fs from 'fs/promises';
import * as path from 'path';

const client = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

interface CodePattern {
  description: string;
  examples: string[];
  frequency: number;
}

// 第一步：用 LLM 分析代码库中的模式
async function analyzePatterns(
  codeFiles: string[]
): Promise<CodePattern[]> {
  // 收集代码样本（每个文件取前 50 行作为样本）
  const samples = await Promise.all(
    codeFiles.slice(0, 20).map(async file => {
      const content = await fs.readFile(file, 'utf-8');
      const lines = content.split('\n').slice(0, 50).join('\n');
      return `// File: ${path.basename(file)}\n${lines}`;
    })
  );

  const analysisPrompt = `分析以下 JavaScript 代码样本，识别出可以批量重构的代码模式。

请找出：
1. 嵌套回调模式（回调地狱）
2. 过时的 API 使用（如 arguments 对象、with 语句）
3. 可以简化的条件表达式
4. 重复的错误处理模式
5. 可以用现代语法替换的旧写法

对每个模式，请提供：
- 模式描述
- 2-3 个具体代码示例
- 建议的转换方式

代码样本：
${samples.join('\n\n---\n\n')}`;

  const response = await client.chat.completions.create({
    model: 'gpt-4o',
    messages: [{ role: 'user', content: analysisPrompt }],
    temperature: 0.2,
  });

  const analysis = response.choices[0].message.content || '';

  // 解析 LLM 返回的模式（简化处理）
  const patterns: CodePattern[] = [];
  const patternBlocks = analysis.split(/\d+\.\s+/).filter(Boolean);

  for (const block of patternBlocks) {
    const lines = block.split('\n');
    patterns.push({
      description: lines[0]?.trim() || '',
      examples: lines.filter(l => l.includes('```') || l.startsWith('  ')),
      frequency: 0,
    });
  }

  return patterns;
}

// 第二步：用 LLM 生成 codemod
async function generateCodemod(
  pattern: CodePattern
): Promise<string> {
  const generationPrompt = `你是一个 jscodeshift codemod 专家。

## 任务
根据以下代码模式描述，生成一个完整的 jscodeshift transform。

## 模式描述
${pattern.description}

## 代码示例
${pattern.examples.join('\n')}

## 要求
1. 生成完整的 jscodeshift transform 函数
2. 处理所有边界情况（空值、类型不匹配等）
3. 添加详细的注释说明每一步的逻辑
4. transform 函数必须导出为 module.exports
5. 返回修改后的代码时使用 toSource({ quote: 'single' })

## 输出格式
只输出 JavaScript 代码，不要解释。

\`\`\`javascript
module.exports = function transformer(fileInfo, api) {
  // 你的实现
};
\`\`\``;

  const response = await client.chat.completions.create({
    model: 'gpt-4o',
    messages: [{ role: 'user', content: generationPrompt }],
    temperature: 0.1,
  });

  let codemod = response.choices[0].message.content || '';
  codemod = codemod.replace(/^```(?:javascript|js)?\n/, '');
  codemod = codemod.replace(/\n```$/, '');

  return codemod;
}

// 第三步：验证生成的 codemod
async function validateCodemod(
  codemodCode: string,
  testFiles: string[]
): Promise<{ passed: boolean; errors: string[] }> {
  const errors: string[] = [];

  // 写入临时文件
  const tempPath = 'temp-codemod.js';
  await fs.writeFile(tempPath, codemodCode);

  for (const testFile of testFiles) {
    try {
      // 使用 jscodeshift 的 dry run 模式测试
      const { execSync } = require('child_process');
      const output = execSync(
        `npx jscodeshift --dry --print -t ${tempPath} ${testFile}`,
        { encoding: 'utf-8', stdio: 'pipe' }
      );

      // 检查输出是否是有效的 JavaScript
      if (output.includes('Error') || output.includes('error')) {
        errors.push(`${testFile}: 输出包含错误`);
      }
    } catch (error: any) {
      errors.push(`${testFile}: ${error.message}`);
    }
  }

  // 清理
  await fs.unlink(tempPath);

  return { passed: errors.length === 0, errors };
}

// 主流程
async function batchRefactor(targetDir: string) {
  // 1. 收集所有待处理文件
  const files = await collectFiles(targetDir);
  console.log(`找到 ${files.length} 个文件`);

  // 2. 分析模式
  const patterns = await analyzePatterns(files);
  console.log(`识别出 ${patterns.length} 个重构模式`);

  // 3. 为每个模式生成 codemod
  for (const pattern of patterns) {
    console.log(`\n处理模式: ${pattern.description}`);

    const codemod = await generateCodemod(pattern);

    // 4. 用样本文件验证
    const testFiles = files.slice(0, 5);
    const validation = await validateCodemod(codemod, testFiles);

    if (!validation.passed) {
      console.log('Codemod 验证失败:');
      validation.errors.forEach(e => console.log(`  ${e}`));
      continue;
    }

    // 5. 保存 codemod
    const codemodPath = `codemods/${pattern.description.replace(/\s+/g, '-').toLowerCase()}.js`;
    await fs.mkdir('codemods', { recursive: true });
    await fs.writeFile(codemodPath, codemod);
    console.log(`Codemod 已保存: ${codemodPath}`);
  }
}

async function collectFiles(dir: string): Promise<string[]> {
  const { glob } = require('glob');
  return glob(`${dir}/**/*.{js,jsx,ts,tsx}`);
}

batchRefactor('./src');
```

## 安全的批量重构：Git 变更追踪

批量重构必须有完善的安全网。下面是一个基于 Git 的完整安全实践：

```typescript
// scripts/safe-batch-refactor.ts
import { execSync } from 'child_process';
import * as fs from 'fs/promises';

interface RefactorSession {
  branchName: string;
  codemodPath: string;
  targetFiles: string[];
  results: Map<string, { before: string; after: string; success: boolean }>;
}

// 创建独立的重构分支
function createRefactorBranch(): string {
  const timestamp = new Date().toISOString().replace(/[:.]/g, '-');
  const branchName = `refactor/batch-${timestamp}`;

  execSync(`git checkout -b ${branchName}`, { encoding: 'utf-8' });
  console.log(`创建重构分支: ${branchName}`);

  return branchName;
}

// 备份单个文件
async function backupFile(filePath: string): Promise<string> {
  const content = await fs.readFile(filePath, 'utf-8');
  const backupPath = `${filePath}.backup`;
  await fs.writeFile(backupPath, content);
  return backupPath;
}

// 恢复单个文件
async function restoreFile(filePath: string): Promise<void> {
  const backupPath = `${filePath}.backup`;
  const content = await fs.readFile(backupPath, 'utf-8');
  await fs.writeFile(filePath, content);
  await fs.unlink(backupPath);
}

// 运行 codemod 并捕获结果
async function runCodemodSafely(
  codemodPath: string,
  filePath: string
): Promise<{ success: boolean; output: string; error?: string }> {
  try {
    const output = execSync(
      `npx jscodeshift -t ${codemodPath} ${filePath} --dry --print`,
      { encoding: 'utf-8', stdio: 'pipe' }
    );
    return { success: true, output };
  } catch (error: any) {
    return {
      success: false,
      output: '',
      error: error.stderr || error.message,
    };
  }
}

// 批量执行重构
async function executeBatchRefactor(
  codemodPath: string,
  files: string[]
): Promise<RefactorSession> {
  const session: RefactorSession = {
    branchName: createRefactorBranch(),
    codemodPath,
    targetFiles: files,
    results: new Map(),
  };

  // 逐文件执行（不是并行，避免冲突）
  for (const file of files) {
    console.log(`处理: ${file}`);

    // 备份
    await backupFile(file);

    // 执行 codemod
    const result = await runCodemodSafely(codemodPath, file);

    if (result.success) {
      const before = await fs.readFile(file, 'utf-8');

      // 实际执行（去掉 --dry）
      execSync(`npx jscodeshift -t ${codemodPath} ${file}`, {
        encoding: 'utf-8',
      });

      const after = await fs.readFile(file, 'utf-8');

      session.results.set(file, {
        before,
        after,
        success: true,
      });

      // 清理备份
      await fs.unlink(`${file}.backup`);
    } else {
      console.log(`  失败: ${result.error}`);
      session.results.set(file, {
        before: '',
        after: '',
        success: false,
      });

      // 恢复备份
      await restoreFile(file);
    }
  }

  return session;
}

// 生成重构报告
function generateReport(session: RefactorSession): string {
  const total = session.results.size;
  const success = [...session.results.values()].filter(r => r.success).length;
  const failed = total - success;

  let report = `# 批量重构报告\n\n`;
  report += `- 分支: ${session.branchName}\n`;
  report += `- Codemod: ${session.codemodPath}\n`;
  report += `- 总文件数: ${total}\n`;
  report += `- 成功: ${success}\n`;
  report += `- 失败: ${failed}\n\n`;

  if (failed > 0) {
    report += `## 失败的文件\n\n`;
    for (const [file, result] of session.results) {
      if (!result.success) {
        report += `- ${file}\n`;
      }
    }
  }

  return report;
}
```

## 并行重构：多文件协调策略

当需要同时修改多个文件时（比如重命名一个被 50 个文件导入的函数），协调策略很重要：

```typescript
// scripts/parallel-refactor.ts
import * as fs from 'fs/promises';
import * as path from 'path';

interface RefactorTask {
  id: string;
  description: string;
  affectedFiles: string[];
  transform: (content: string) => string;
}

// 分析依赖关系，确定执行顺序
function analyzeDependencies(tasks: RefactorTask[]): RefactorTask[][] {
  // 构建文件→任务映射
  const fileToTasks = new Map<string, string[]>();
  for (const task of tasks) {
    for (const file of task.affectedFiles) {
      if (!fileToTasks.has(file)) fileToTasks.set(file, []);
      fileToTasks.get(file)!.push(task.id);
    }
  }

  // 找出没有文件冲突的任务组（可以并行执行）
  const groups: RefactorTask[][] = [];
  const processed = new Set<string>();

  for (const task of tasks) {
    if (processed.has(task.id)) continue;

    const group: RefactorTask[] = [task];
    processed.add(task.id);

    // 找出不与当前组冲突的任务
    for (const other of tasks) {
      if (processed.has(other.id)) continue;

      const hasConflict = task.affectedFiles.some(f =>
        other.affectedFiles.includes(f)
      );

      if (!hasConflict) {
        group.push(other);
        processed.add(other.id);
      }
    }

    groups.push(group);
  }

  return groups;
}

// 并行执行无冲突的任务组
async function executeParallelGroups(
  groups: RefactorTask[][],
  baseDir: string
): Promise<void> {
  for (let i = 0; i < groups.length; i++) {
    const group = groups[i];
    console.log(`\n执行任务组 ${i + 1}/${groups.length}（${group.length} 个并行任务）`);

    // 同一组内的任务可以并行
    await Promise.all(
      group.map(async task => {
        console.log(`  任务: ${task.description}`);

        for (const file of task.affectedFiles) {
          const filePath = path.join(baseDir, file);
          const content = await fs.readFile(filePath, 'utf-8');
          const transformed = task.transform(content);
          await fs.writeFile(filePath, transformed);
        }
      })
    );

    // 每组执行后验证
    console.log(`  验证中...`);
    const testResult = execSync('npm test', {
      encoding: 'utf-8',
      cwd: baseDir,
      stdio: 'pipe',
    }).toString();

    if (testResult.includes('FAIL')) {
      throw new Error(`任务组 ${i + 1} 执行后测试失败`);
    }
  }
}
```

## 常见误区

**误区一：不做备份就批量修改**

直接在 main 分支上运行 codemod，发现出问题后无法回滚。必须在独立分支上操作，每个文件都要有备份。

**误区二：并行修改有冲突的文件**

两个 codemod 同时修改同一个文件，结果是后运行的覆盖了先运行的修改。需要分析文件依赖关系，有冲突的任务必须串行执行。

**误区三：忽略测试覆盖率**

重构后只跑现有测试，不检查覆盖率。如果某些代码路径没有测试覆盖，重构可能引入了 bug 但测试通过了。

**误区四：一次重构太多文件**

一次修改 200 个文件，出了问题很难定位。应该分批次执行，每批 20-30 个文件，每批都验证通过后再继续。

## 小结

- 批量重构的核心是安全：备份、分支、测试、回滚
- AI 辅助的关键是让 LLM 生成 codemod，而不是让 LLM 直接改代码
- 多文件修改需要分析依赖关系，有冲突的必须串行执行
- 每次批量修改后都必须运行完整的测试和类型检查
- 分批次执行，每批验证通过后再继续

## 参考答案

### 练习一

**思路**：核心难点是判断 `var` 应该换成 `let` 还是 `const`。规则是：如果变量后续被重新赋值（`=`、`+=`、`++` 等），用 `let`；否则用 `const`。用 jscodeshift 的 scope 分析可以找到所有赋值位置。

**答案**：

```typescript
// scripts/var-to-let-const.ts
import * as fs from 'fs/promises';
import * as path from 'path';
import { execSync } from 'child_process';

interface VarAnalysis {
  filePath: string;
  line: number;
  varName: string;
  shouldBeConst: boolean;
  reason: string;
}

// 分析单个文件中的 var 声明
async function analyzeVarDeclarations(
  filePath: string
): Promise<VarAnalysis[]> {
  const content = await fs.readFile(filePath, 'utf-8');
  const analyses: VarAnalysis[] = [];

  // 使用 jscodeshift 分析（通过临时脚本）
  const analysisScript = `
    const j = require('jscodeshift');
    const fs = require('fs');
    const content = fs.readFileSync('${filePath}', 'utf-8');
    const root = j(content);

    const results = [];

    root.find(j.VariableDeclaration, { kind: 'var' }).forEach(path => {
      path.node.declarations.forEach(decl => {
        if (decl.id.type !== 'Identifier') return;

        const name = decl.id.name;
        const scope = path.scope;

        // 查找该变量的所有赋值
        const assignments = j(scope.scope)
          .find(j.AssignmentExpression)
          .filter(a => a.node.left.type === 'Identifier' && a.node.left.name === name);

        const updateExpressions = j(scope.scope)
          .find(j.UpdateExpression)
          .filter(u => u.node.argument.type === 'Identifier' && u.node.argument.name === name);

        const isReassigned = assignments.length > 0 || updateExpressions.length > 0;

        results.push({
          line: path.node.loc.start.line,
          varName: name,
          shouldBeConst: !isReassigned,
          reason: isReassigned ? '变量被重新赋值' : '变量未被重新赋值'
        });
      });
    });

    console.log(JSON.stringify(results));
  `;

  const tempScriptPath = 'temp-analysis.js';
  await fs.writeFile(tempScriptPath, analysisScript);

  try {
    const output = execSync(`node ${tempScriptPath}`, { encoding: 'utf-8' });
    const results = JSON.parse(output.trim().split('\n').pop() || '[]');

    for (const result of results) {
      analyses.push({
        filePath,
        ...result,
      });
    }
  } finally {
    await fs.unlink(tempScriptPath);
  }

  return analyses;
}

// 生成 codemod
function generateVarCodemod(analyses: VarAnalysis[]): string {
  const replacements = analyses.map(a => ({
    line: a.line,
    name: a.varName,
    replacement: a.shouldBeConst ? 'const' : 'let',
  }));

  return `
module.exports = function transformer(fileInfo, api) {
  const j = api.jscodeshift;
  const root = j(fileInfo.source);

  ${JSON.stringify(replacements)}.forEach(({ line, name, replacement }) => {
    root.find(j.VariableDeclaration, { kind: 'var' })
      .filter(path => path.node.loc.start.line === line)
      .forEach(path => {
        path.node.kind = replacement;
      });
  });

  return root.toSource({ quote: 'single' });
};
`;
}

// 批量执行
async function batchVarRefactor(
  dir: string,
  batchSize: number = 50
): Promise<void> {
  const { glob } = require('glob');
  const files = await glob(`${dir}/**/*.{js,ts,jsx,tsx}`);

  console.log(`共 ${files.length} 个文件`);

  for (let i = 0; i < files.length; i += batchSize) {
    const batch = files.slice(i, i + batchSize);
    console.log(`\n处理第 ${i / batchSize + 1} 批（${batch.length} 个文件）`);

    // 分析每批文件
    const allAnalyses: VarAnalysis[] = [];
    for (const file of batch) {
      const analyses = await analyzeVarDeclarations(file);
      allAnalyses.push(...analyses);
    }

    // 按文件分组生成 codemod
    const byFile = new Map<string, VarAnalysis[]>();
    for (const a of allAnalyses) {
      if (!byFile.has(a.filePath)) byFile.set(a.filePath, []);
      byFile.get(a.filePath)!.push(a);
    }

    // 逐文件执行
    for (const [file, analyses] of byFile) {
      const codemod = generateVarCodemod(analyses);
      const codemodPath = 'temp-codemod.js';
      await fs.writeFile(codemodPath, codemod);

      execSync(`npx jscodeshift -t ${codemodPath} ${file}`, {
        encoding: 'utf-8',
      });
    }

    // 验证
    try {
      execSync('npm test', { encoding: 'utf-8', stdio: 'pipe' });
      console.log('  测试通过');
    } catch {
      console.log('  测试失败，回滚本批次');
      execSync('git checkout -- .', { encoding: 'utf-8' });
      break;
    }
  }
}

batchVarRefactor('./src');
```

**要点**：
- 用 jscodeshift 的 scope 分析判断变量是否被重新赋值
- 分批执行，每批验证测试，失败则回滚
- `for...of` 循环而非 `Promise.all`，因为需要顺序执行

### 练习二

**思路**：构建文件→任务的映射，然后找出共享文件的任务对，将它们分组为串行任务组。没有共享文件的任务可以并行执行。

**答案**：

```typescript
interface Task {
  id: string;
  affectedFiles: string[];
}

interface TaskGroup {
  parallel: boolean;
  tasks: Task[];
}

function detectAndGroupTasks(tasks: Task[]): TaskGroup[] {
  // 构建文件→任务映射
  const fileToTasks = new Map<string, Set<string>>();
  const taskMap = new Map<string, Task>();

  for (const task of tasks) {
    taskMap.set(task.id, task);
    for (const file of task.affectedFiles) {
      if (!fileToTasks.has(file)) fileToTasks.set(file, new Set());
      fileToTasks.get(file)!.add(task.id);
    }
  }

  // 构建冲突图（邻接表）
  const conflicts = new Map<string, Set<string>>();
  for (const task of tasks) {
    if (!conflicts.has(task.id)) conflicts.set(task.id, new Set());
  }

  for (const [, taskIds] of fileToTasks) {
    const taskArray = [...taskIds];
    for (let i = 0; i < taskArray.length; i++) {
      for (let j = i + 1; j < taskArray.length; j++) {
        conflicts.get(taskArray[i])!.add(taskArray[j]);
        conflicts.get(taskArray[j])!.add(taskArray[i]);
      }
    }
  }

  // 贪心着色：给每个任务分配一个"时间槽"
  const colors = new Map<string, number>();
  let maxColor = 0;

  for (const task of tasks) {
    const usedColors = new Set<number>();
    for (const neighbor of conflicts.get(task.id) || []) {
      if (colors.has(neighbor)) {
        usedColors.add(colors.get(neighbor)!);
      }
    }

    // 找最小的可用颜色
    let color = 0;
    while (usedColors.has(color)) color++;
    colors.set(task.id, color);
    maxColor = Math.max(maxColor, color);
  }

  // 按颜色分组
  const groups: TaskGroup[] = [];
  for (let c = 0; c <= maxColor; c++) {
    const groupTasks = tasks.filter(t => colors.get(t.id) === c);
    if (groupTasks.length > 0) {
      groups.push({
        parallel: groupTasks.length > 1,
        tasks: groupTasks,
      });
    }
  }

  return groups;
}

// 使用示例
const tasks: Task[] = [
  { id: 'rename-api', affectedFiles: ['api.ts', 'types.ts'] },
  { id: 'update-auth', affectedFiles: ['auth.ts', 'middleware.ts'] },
  { id: 'fix-imports', affectedFiles: ['api.ts', 'utils.ts'] },
  { id: 'add-logging', affectedFiles: ['logger.ts'] },
];

const groups = detectAndGroupTasks(tasks);
// 结果：
// 组 1（并行）: rename-api, update-auth, add-logging（无文件冲突）
// 组 2（串行）: fix-imports（与 rename-api 冲突，需等组 1 完成）
```

**要点**：
- 用图着色算法解决任务调度问题
- 同一颜色的任务可以并行（无文件冲突）
- 不同颜色的任务必须串行（有文件冲突）
- 贪心着色不一定是最优解，但足够高效
