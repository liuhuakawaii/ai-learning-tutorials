# 06 - 阶段实战：迁移流水线与质量门禁

> **课程定位**：Part 4 综合实战，构建端到端的迁移流水线。
>
> **前置要求**：完成迁移策略、等价性测试课程
>
> **预计时长**：2 小时

---

团队正在将 Node.js + MongoDB API 服务迁移到 Go + PostgreSQL。60 个端点、日均 5000 万次请求。你需要一套流水线，让每次迁移变更都经过自动化验证，质量不达标就不能推进。

---

## 流水线架构

```
阶段 1: 代码质量门禁 → 阶段 2: 构建验证门禁 → 阶段 3: 等价测试门禁 → 阶段 4: 灰度发布门禁
  │ 类型检查              │ 单元测试              │ 双跑对比              │ 自动推进
  │ Lint                │ 集成测试              │ 性能对比              │ 监控告警
  │ 覆盖率              │ 构建产物              │ 数据校验              │ 自动回滚
```

## 流水线核心引擎

```typescript
interface PipelineStage { name: string; gates: QualityGate[]; execute: (ctx: PipelineContext) => Promise<StageResult>; }
interface QualityGate { name: string; check: (ctx: PipelineContext) => Promise<GateResult>; severity: 'blocking' | 'warning'; }
interface GateResult { passed: boolean; metric: number; threshold: number; message: string; }
interface StageResult { stage: string; passed: boolean; gateResults: GateResult[]; duration: number; }
interface PipelineContext { commitSha: string; branch: string; changedFiles: string[]; }

class MigrationPipeline {
  private stages: PipelineStage[] = [];
  addStage(stage: PipelineStage) { this.stages.push(stage); }

  async run(ctx: PipelineContext) {
    const start = Date.now();
    const results: StageResult[] = [];
    console.log(`\n🚀 迁移流水线启动: ${ctx.commitSha.slice(0, 8)}`);

    for (const stage of this.stages) {
      console.log(`\n📦 ${stage.name}`);
      const gateResults: GateResult[] = [];
      for (const gate of stage.gates) {
        const r = await gate.check(ctx);
        gateResults.push(r);
        if (!r.passed && gate.severity === 'blocking') {
          console.log(`❌ 门禁 "${gate.name}" 失败: ${r.message}`);
          return { success: false, stages: results, time: Date.now() - start };
        }
      }
      const stageResult = await stage.execute(ctx);
      results.push({ ...stageResult, stage: stage.name, gateResults });
      if (!stageResult.passed) return { success: false, stages: results, time: Date.now() - start };
      console.log(`✅ ${stage.name} 通过`);
    }
    return { success: true, stages: results, time: Date.now() - start };
  }
}
```

## 代码质量门禁

```typescript
function createCodeQualityGates(): QualityGate[] {
  return [
    { name: 'TypeScript 类型检查', severity: 'blocking',
      async check() { const r = await exec('npx tsc --noEmit'); return { passed: r.exitCode === 0, metric: r.exitCode, threshold: 0, message: r.exitCode === 0 ? '通过' : r.stderr }; } },
    { name: 'Lint 检查', severity: 'blocking',
      async check() { const r = await exec('npx eslint src --format json'); const errors = JSON.parse(r.stdout).reduce((s: number, f: any) => s + f.errorCount, 0); return { passed: errors === 0, metric: errors, threshold: 0, message: errors === 0 ? '通过' : `${errors} 个错误` }; } },
    { name: '测试覆盖率', severity: 'blocking',
      async check() { const r = await exec('npx vitest run --coverage --reporter=json'); const cov = JSON.parse(r.stdout).coverageMap?.total?.lines?.pct || 0; return { passed: cov >= 80, metric: cov, threshold: 80, message: `覆盖率: ${cov.toFixed(1)}%` }; } },
    { name: '新增 JS 文件检查', severity: 'blocking',
      async check(ctx) { const js = ctx.changedFiles.filter(f => (f.endsWith('.js') || f.endsWith('.jsx')) && !f.includes('test')); return { passed: js.length === 0, metric: js.length, threshold: 0, message: js.length === 0 ? '无新增 JS' : `${js.length} 个新增 JS 文件` }; } },
  ];
}
```

## GitHub Actions 集成

```yaml
name: Migration Pipeline
on:
  push: { branches: [main, migrate/*] }
  pull_request: { branches: [main] }

jobs:
  code-quality:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: npm ci
      - run: npx tsc --noEmit
      - run: npx eslint src --max-warnings 0

  build-and-test:
    needs: code-quality
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm ci
      - run: npx vitest run --coverage

  equivalence-test:
    needs: build-and-test
    runs-on: ubuntu-latest
    services:
      postgres: { image: postgres:16, env: { POSTGRES_PASSWORD: test }, ports: ['5432:5432'] }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with: { go-version: '1.22' }
      - run: npm start &
      - run: go run ./cmd/api &
      - run: sleep 10
      - run: npx tsx scripts/run-equivalence-tests.ts
      - run: |
          MATCH_RATE=$(jq '.matchRate' equivalence-report.json)
          if [ $(echo "$MATCH_RATE < 99.9" | bc) -eq 1 ]; then echo "❌ 匹配率不足"; exit 1; fi

  canary-deploy:
    needs: equivalence-test
    if: github.ref == 'refs/heads/main'
    environment: production
    steps:
      - run: kubectl set image deployment/api-new api-new=api-service:${{ github.sha }}
      - run: curl -X POST http://gateway/admin/canary -d '{"enabled":true,"percent":1}'
      - run: sleep 1800
      - run: npx tsx scripts/check-canary-metrics.ts
```

## 门禁阈值参考

| 指标 | 阈值 | 理由 |
|------|------|------|
| 等价性匹配率 | ≥ 99.9% | 每 1000 请求最多 1 个不匹配 |
| P99 延迟比值 | ≤ 1.1 | 允许 10% 性能退化 |
| 测试覆盖率 | ≥ 80% | 迁移阶段的合理平衡 |
| 错误率 | ≤ 0.01% | 与旧系统对齐 |
| 代码迁移覆盖率 | ≥ 95% | 核心逻辑 100%，留 5% 缓冲 |

## 参考答案

### 练习一

1. **代码质量**：cargo check（blocking）、Clippy（blocking）、新增 Python 文件检查（blocking）、cargo fmt --check（blocking）
2. **构建测试**：cargo test（blocking）、集成测试 docker-compose（blocking）、Miri 内存安全（blocking）
3. **等价测试**：匹配率 ≥ 99.9%（blocking）、P99 ≤ 0.5 即 Rust 应比 Python 快（blocking）、无内存泄漏（blocking）
4. **灰度发布**：1% 观察 1h、5% 观察 4h、20% 观察 24h，人工确认后推到 100%

### 练习二

见上方阈值参考表。核心原则：阈值根据业务风险设定，迁移阶段允许适度宽松，稳定后逐步收紧。
