# 第六课：阶段实战——迁移流水线与质量门禁

## 场景引入

前五课讲了迁移策略、等价性测试、灰度切换、回滚机制、迁移度量。本课把这些技术串在一起，构建一套完整的**迁移流水线**——从代码提交到全量切换的自动化流水线，以及每一步的质量门禁。

你所在的团队正在将一个 Node.js + MongoDB 的 API 服务迁移到 Go + PostgreSQL。服务有 60 个 API 端点、日均 5000 万次请求。你需要设计一套流水线，让每次迁移变更都经过自动化验证，质量不达标就不能推进。

这不是一个 CI/CD pipeline 那么简单。它需要覆盖：代码迁移质量检查、API 等价性验证、性能基准对比、灰度自动推进、回滚自动触发。本课将构建这个端到端的迁移流水线。

## 学习目标

完成本课学习后，你将能够：

1. 设计端到端的迁移流水线架构
2. 实现代码迁移质量的自动化检查
3. 集成等价性测试到 CI/CD 流程
4. 实现灰度推进的自动化决策
5. 建立迁移质量门禁体系

### 示例一：流水线核心引擎

```typescript
// pipeline/engine.ts
interface PipelineStage {
  name: string
  gates: QualityGate[]
  execute: (context: PipelineContext) => Promise<StageResult>
  onFail?: (context: PipelineContext, result: StageResult) => Promise<void>
}

interface QualityGate {
  name: string
  check: (context: PipelineContext) => Promise<GateResult>
  severity: 'blocking' | 'warning'
}

interface GateResult {
  passed: boolean
  metric: number
  threshold: number
  message: string
}

interface StageResult {
  stage: string
  passed: boolean
  gateResults: GateResult[]
  duration: number
  artifacts: string[]
}

interface PipelineContext {
  commitSha: string
  branch: string
  author: string
  changedFiles: string[]
  timestamp: Date
  metadata: Record<string, unknown>
}

class MigrationPipeline {
  private stages: PipelineStage[] = []
  private notificationService: NotificationService
  private metricsStore: MetricsStore

  constructor(notificationService: NotificationService, metricsStore: MetricsStore) {
    this.notificationService = notificationService
    this.metricsStore = metricsStore
  }

  addStage(stage: PipelineStage): void {
    this.stages.push(stage)
  }

  async run(context: PipelineContext): Promise<{
    success: boolean
    stages: StageResult[]
    totalTime: number
  }> {
    const startTime = Date.now()
    const results: StageResult[] = []

    console.log(`\n🚀 迁移流水线启动: ${context.commitSha.slice(0, 8)}`)

    for (const stage of this.stages) {
      console.log(`\n📦 阶段: ${stage.name}`)

      const stageResult = await this.executeStage(stage, context)
      results.push(stageResult)

      await this.metricsStore.recordStageResult(stageResult)

      if (!stageResult.passed) {
        console.log(`❌ 阶段 "${stage.name}" 失败`)
        if (stage.onFail) {
          await stage.onFail(context, stageResult)
        }
        await this.notificationService.notify({
          type: 'pipeline_failed',
          stage: stage.name,
          gateResults: stageResult.gateResults,
          commitSha: context.commitSha,
        })

        return {
          success: false,
          stages: results,
          totalTime: Date.now() - startTime,
        }
      }

      console.log(`✅ 阶段 "${stage.name}" 通过`)
    }

    await this.notificationService.notify({
      type: 'pipeline_passed',
      commitSha: context.commitSha,
      totalTime: Date.now() - startTime,
    })

    return {
      success: true,
      stages: results,
      totalTime: Date.now() - startTime,
    }
  }

  private async executeStage(
    stage: PipelineStage,
    context: PipelineContext
  ): Promise<StageResult> {
    const startTime = Date.now()
    const gateResults: GateResult[] = []

    for (const gate of stage.gates) {
      const result = await gate.check(context)
      gateResults.push(result)

      if (!result.passed && gate.severity === 'blocking') {
        return {
          stage: stage.name,
          passed: false,
          gateResults,
          duration: Date.now() - startTime,
          artifacts: [],
        }
      }
    }

    const stageResult = await stage.execute(context)
    return {
      ...stageResult,
      stage: stage.name,
      gateResults,
      duration: Date.now() - startTime,
    }
  }
}
```

// pipeline/gates/code-quality.ts
function createCodeQualityGates(): QualityGate[] {
  return [
    {
      name: 'TypeScript 类型检查',
      severity: 'blocking',
      async check(context) {
        const output = await exec('npx tsc --noEmit --pretty')
        return {
          passed: output.exitCode === 0,
          metric: output.exitCode,
          threshold: 0,
          message: output.exitCode === 0 ? '类型检查通过' : output.stderr,
        }
      },
    },
    {
      name: 'Lint 检查',
      severity: 'blocking',
      async check(context) {
        const output = await exec('npx eslint src --format json')
        const results = JSON.parse(output.stdout)
        const errorCount = results.reduce((sum: number, r: any) => sum + r.errorCount, 0)
        return {
          passed: errorCount === 0,
          metric: errorCount,
          threshold: 0,
          message: errorCount === 0 ? 'Lint 通过' : `${errorCount} 个 lint 错误`,
        }
      },
    },
    {
      name: '测试覆盖率',
      severity: 'blocking',
      async check(context) {
        const output = await exec('npx vitest run --coverage --reporter=json')
        const results = JSON.parse(output.stdout)
        const coverage = results.coverageMap?.total?.lines?.pct || 0
        return {
          passed: coverage >= 80,
          metric: coverage,
          threshold: 80,
          message: `测试覆盖率: ${coverage.toFixed(1)}%`,
        }
      },
    },
    {
      name: '新增 JS 文件检查',
      severity: 'blocking',
      async check(context) {
        const newJsFiles = context.changedFiles.filter(
          f => (f.endsWith('.js') || f.endsWith('.jsx')) && !f.includes('test')
        )
        return {
          passed: newJsFiles.length === 0,
          metric: newJsFiles.length,
          threshold: 0,
          message: newJsFiles.length === 0
            ? '无新增 JS 文件'
            : `发现 ${newJsFiles.length} 个新增 JS 文件: ${newJsFiles.join(', ')}`,
        }
      },
    },
    {
      name: '迁移覆盖率检查',
      severity: 'warning',
      async check(context) {
        const output = await exec('node scripts/migration-coverage.cjs')
        const report = JSON.parse(output.stdout)
        return {
          passed: report.percentage > 0,
          metric: report.percentage,
          threshold: 0,
          message: `当前迁移覆盖率: ${report.percentage.toFixed(1)}%`,
        }
      },
    },
  ]
}

### 示例三：等价性测试阶段

```typescript
// pipeline/stages/equivalence-test.ts
function createEquivalenceTestStage(): PipelineStage {
  return {
    name: '等价性测试',
    gates: [
      {
        name: '等价性匹配率',
        severity: 'blocking',
        async check(context) {
          const report = await readLatestEquivalenceReport()
          return {
            passed: report.matchRate >= 99.9,
            metric: report.matchRate,
            threshold: 99.9,
            message: `等价性匹配率: ${report.matchRate.toFixed(2)}%`,
          }
        },
      },
      {
        name: '性能回归检查',
        severity: 'blocking',
        async check(context) {
          const report = await readLatestEquivalenceReport()
          const ratio = report.latencyComparison.p99New / report.latencyComparison.p99Legacy
          return {
            passed: ratio <= 1.1,
            metric: ratio,
            threshold: 1.1,
            message: `P99 延迟比值: ${ratio.toFixed(2)}`,
          }
        },
      },
    ],

    async execute(context) {
      console.log('  运行等价性测试套件...')

      const testCases = await loadEquivalenceTestCases()
      const comparator = new EquivalenceComparator()
      const rules = createOrderApiRules()
      rules.forEach(r => comparator.addRule(r))

      const tester = new ShadowTester(comparator)
      let passed = 0
      let failed = 0

      for (const testCase of testCases) {
        const result = await tester.executeTest(
          testCase.id,
          testCase.path,
          testCase.request,
          testCase.legacyExecutor,
          testCase.newExecutor
        )

        if (result.matched) {
          passed++
        } else {
          failed++
          console.log(`  ⚠️ 不匹配: ${testCase.id}`)
          for (const diff of result.differences) {
            if (diff.severity === 'error') {
              console.log(`    ${diff.path}: ${JSON.stringify(diff.legacyValue)} vs ${JSON.stringify(diff.newValue)}`)
            }
          }
        }
      }

      const report = tester.generateReport()
      await saveEquivalenceReport(report)

      return {
        stage: '等价性测试',
        passed: failed === 0,
        gateResults: [],
        duration: 0,
        artifacts: ['equivalence-report.json'],
      }
    },

    async onFail(context, result) {
      console.log('  等价性测试失败，保存详细报告...')
      await saveFailureContext(context, result)
    },
  }
}

function createCanaryDeployStage(
  canaryRouter: CanaryRouter,
  autoPromoter: AutoPromoter
): PipelineStage {
  return {
    name: '灰度发布',
    gates: [
      {
        name: '前置条件检查',
        severity: 'blocking',
        async check(context) {
          const checks = await Promise.all([
            checkServiceHealth('new'),
            checkDatabaseConnections(),
            checkRollbackPlanReady(),
          ])
          const allPassed = checks.every(c => c.ok)
          return {
            passed: allPassed,
            metric: allPassed ? 1 : 0,
            threshold: 1,
            message: allPassed ? '前置检查通过' : checks.filter(c => !c.ok).map(c => c.reason).join('; '),
          }
        },
      },
    ],

    async execute(context) {
      console.log('  开始灰度部署...')

      canaryRouter.updateConfig({
        enabled: true,
        percent: 1,
      })

      console.log('  灰度 1%，观察 30 分钟...')
      await sleep(30 * 60 * 1000)

      const evaluation = await autoPromoter.evaluate()

      if (evaluation.action === 'rollback') {
        console.log(`  ❌ 自动回滚: ${evaluation.reason}`)
        return {
          stage: '灰度发布',
          passed: false,
          gateResults: [],
          duration: 0,
          artifacts: [],
        }
      }

      console.log(`  ✅ 灰度 1% 验证通过，${evaluation.reason}`)

      return {
        stage: '灰度发布',
        passed: true,
        gateResults: [],
        duration: 0,
        artifacts: ['canary-deploy-log.json'],
      }
    },
  }
}

// pipeline/config.ts
async function createMigrationPipeline(): Promise<MigrationPipeline> {
  const notificationService = new SlackNotificationService(
    process.env.SLACK_WEBHOOK_URL!
  )
  const metricsStore = new InfluxDBMetricsStore()

  const pipeline = new MigrationPipeline(notificationService, metricsStore)

  pipeline.addStage({
    name: '代码质量检查',
    gates: createCodeQualityGates(),
    async execute(context) {
      return {
        stage: '代码质量检查',
        passed: true,
        gateResults: [],
        duration: 0,
        artifacts: [],
      }
    },
  })

  pipeline.addStage({
    name: '构建与测试',
    gates: [
      {
        name: '单元测试',
        severity: 'blocking',
        async check(context) {
          const result = await exec('npx vitest run --reporter=json')
          const testResult = JSON.parse(result.stdout)
          return {
            passed: testResult.numFailedTests === 0,
            metric: testResult.numFailedTests,
            threshold: 0,
            message: `${testResult.numPassedTests} 通过, ${testResult.numFailedTests} 失败`,
          }
        },
      },
      {
        name: '集成测试',
        severity: 'blocking',
        async check(context) {
          const result = await exec('npx vitest run --config vitest.integration.config.ts')
          return {
            passed: result.exitCode === 0,
            metric: result.exitCode,
            threshold: 0,
            message: result.exitCode === 0 ? '集成测试通过' : '集成测试失败',
          }
        },
      },
    ],
    async execute(context) {
      await exec('docker build -t api-service:new .')
      return {
        stage: '构建与测试',
        passed: true,
        gateResults: [],
        duration: 0,
        artifacts: ['docker-image:new'],
      }
    },
  })

  pipeline.addStage(createEquivalenceTestStage())

  const canaryRouter = new CanaryRouter(new EtcdConfigCenter())
  const autoPromoter = new AutoPromoter(
    [
      { percent: 1, minDurationMinutes: 30, successCriteria: { maxErrorRateMultiplier: 1.5, maxLatencyMultiplier: 1.2, maxBusinessMetricDrop: 0.01 } },
      { percent: 5, minDurationMinutes: 60, successCriteria: { maxErrorRateMultiplier: 1.5, maxLatencyMultiplier: 1.2, maxBusinessMetricDrop: 0.01 } },
      { percent: 20, minDurationMinutes: 120, successCriteria: { maxErrorRateMultiplier: 1.3, maxLatencyMultiplier: 1.1, maxBusinessMetricDrop: 0.005 } },
    ],
    new MetricsCollector(),
    canaryRouter
  )
  pipeline.addStage(createCanaryDeployStage(canaryRouter, autoPromoter))

  return pipeline
}

## 常见误区

### 误区一：流水线太长导致反馈慢

如果流水线需要 2 小时才能跑完，开发者提交代码后要等 2 小时才知道结果。应该把快速检查（lint、类型检查）放在最前面，尽早失败。

### 误区二：门禁太严格导致流水线频繁失败

如果门禁设置为测试覆盖率 95%、零 lint 警告，可能大部分提交都过不了。门禁应该渐进式收紧——先 80%，稳定后再逐步提高。

### 误区三：灰度推进完全自动化

完全自动化的灰度推进听起来很酷，但在关键节点（如从 20% 到 50%）应该有人工确认。自动化处理常规情况，人工处理异常情况。

### 误区四：只监控新系统，不监控旧系统

灰度期间必须同时监控新旧系统。如果旧系统因为流量减少出现异常（如连接池配置不当），对比数据就没有意义。

### 误区五：流水线没有回滚步骤

流水线不仅要有正向流程（构建 → 测试 → 部署），还要有回滚步骤。当灰度失败时，流水线应该自动触发回滚。

## 小结

迁移流水线的核心组成：

1. **代码质量门禁**：类型检查、Lint、覆盖率、迁移规范
2. **构建验证门禁**：单元测试、集成测试、构建产物
3. **等价性测试门禁**：双跑对比、性能回归
4. **灰度发布门禁**：自动推进、指标监控、自动回滚
5. **监控与度量**：进度追踪、质量报告、风险评估

阶段 1：代码质量门禁
  - Rust 编译检查（cargo check）→ blocking
  - Clippy lint 检查 → blocking
  - 新增 Python 文件检查（不允许新增 .py 文件）→ blocking
  - Rust 代码格式化检查（cargo fmt --check）→ blocking

阶段 2：构建与测试门禁
  - 单元测试（cargo test）→ blocking
  - 集成测试（docker-compose up + pytest 对比）→ blocking
  - 内存安全检查（Miri 或 ASan）→ blocking
  - 构建产物大小检查 → warning

阶段 3：等价性测试门禁
  - API 等价性匹配率 ≥ 99.9% → blocking
  - P99 延迟比值 ≤ 0.5（Rust 应该比 Python 快）→ blocking
  - 内存使用 ≤ Python 的 30% → warning
  - 无内存泄漏（运行 1 小时后 RSS 稳定）→ blocking

阶段 4：灰度发布门禁
  - 1% 灰度观察 1 小时，错误率 ≤ 0.01% → blocking
  - 5% 灰度观察 4 小时，核心业务指标无退化 → blocking
  - 20% 灰度观察 24 小时，对账一致 → blocking
  - 人工确认后推进到 50% → 100%
```

### 练习二

**思路**：根据业务风险和技术特性设定合理的阈值。

**答案**：

| 指标 | 阈值 | 理由 |
|------|------|------|
| 等价性匹配率 | ≥ 99.9% | 100% 不现实（会有预期差异），但 99.9% 意味着每 1000 个请求最多 1 个不匹配 |
| P99 延迟比值 | ≤ 1.1 | 允许 10% 的性能退化（新系统可能有未优化的路径），但不能更多 |
| 测试覆盖率 | ≥ 80% | 迁移阶段 80% 是合理的平衡点，100% 会因为写测试而拖慢迁移进度 |
| 错误率 | ≤ 0.01% | 与旧系统的错误率对齐或更低 |
| 代码迁移覆盖率 | ≥ 95% | 留 5% 的缓冲给低优先级的辅助代码，但核心逻辑必须 100% 迁移 |
