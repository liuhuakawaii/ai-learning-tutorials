# 第二课：等价性测试——证明新系统和旧系统行为一致

## 场景引入

你的团队完成了核心交易系统从 Java 8 到 Java 17 的迁移，新系统看起来一切正常——功能测试全绿，UI 表现一致，测试环境跑了一周没问题。上线第二天，财务部门报告：某个客户的退款金额差了 0.01 元。

排查发现，旧系统用 `BigDecimal.ROUND_HALF_UP` 做四舍五入，新系统的 `MathContext` 默认行为是 `HALF_EVEN`（银行家舍入法）。这个差异在大多数场景下不可见，但在涉及金额恰好为 x.x5 时会产生 1 分钱的偏差。

这就是等价性测试要解决的问题：**不是"新系统能不能跑"，而是"新系统和旧系统的行为是否完全一致"**。功能测试验证"对不对"，等价性测试验证"一不一样"。

## 学习目标

完成本课学习后，你将能够：

1. 理解等价性测试与功能测试的区别
2. 设计覆盖输入、输出、副作用三个维度的等价性验证
3. 实现请求级别的双跑对比（Shadow Testing）
4. 处理允许的差异（时间戳、ID 生成等）
5. 建立自动化的等价性回归测试体系

## 核心概念

### 一、等价性测试的三个层次

```
等价性验证金字塔：

          ┌─────────────┐
          │  行为等价     │  ← 最难：状态转换、副作用、时序
          │  (Behavior)   │
          ├─────────────┤
          │  输出等价     │  ← 中等：结构对比、数值精度、排序
          │  (Output)     │
          ├─────────────┤
          │  输入等价     │  ← 最易：请求格式、参数解析
          │  (Input)      │
          └─────────────┘

层次 1 —— 输入等价：
  同一个请求发送到新旧系统，确认两者收到的输入完全相同
  关注：参数解析、编码处理、边界值

层次 2 —— 输出等价：
  同一个输入产生的输出（响应体、状态码、Header）完全相同
  关注：数值精度、排序、字段命名、null 处理

层次 3 —— 行为等价：
  同一个输入触发的副作用（数据库写入、消息发送、缓存更新）完全相同
  关注：写入顺序、事务边界、幂等性
```

### 二、差异分类

不是所有差异都代表 bug。等价性测试的关键是**区分"合理差异"和"真实差异"**。

```
差异分类：

┌─────────────────────────────────────────────────────────┐
│  类型 1：预期差异（Ignorable）                            │
│  时间戳、请求 ID、随机 token                              │
│  → 对比时忽略这些字段                                     │
├─────────────────────────────────────────────────────────┤
│  类型 2：可接受差异（Acceptable）                          │
│  字段排序不同、null vs 空字符串、时间格式差异               │
│  → 记录但不阻断，需要语义层面的对齐规则                     │
├─────────────────────────────────────────────────────────┤
│  类型 3：需修复差异（Actionable）                          │
│  数值精度不同、业务逻辑结果不同、缺失字段                   │
│  → 必须修复，是真正的 bug                                 │
├─────────────────────────────────────────────────────────┤
│  类型 4：已知改进（Intentional）                           │
│  新系统特意修复的旧系统 bug                               │
│  → 记录为预期差异，需要产品确认                            │
└─────────────────────────────────────────────────────────┘
```

### 三、Shadow Testing 的原理

Shadow Testing 是等价性测试的核心手段：将真实流量同时发送到新旧系统，只返回旧系统的响应给用户，新系统的响应用于对比。

```
Shadow Testing 流程：

  用户请求
     │
     ▼
  ┌──────────┐
  │  流量复制  │
  └────┬─────┘
       │
  ┌────┴────┐
  ▼         ▼
┌──────┐  ┌──────┐
│ 旧系统 │  │ 新系统 │
│ (主)  │  │ (影子) │
└──┬───┘  └──┬───┘
   │         │
   ▼         ▼
┌──────┐  ┌──────┐
│ 响应A │  │ 响应B │
│ → 用户 │  │ → 对比 │
└──────┘  └──┬───┘
              │
              ▼
         ┌────────┐
         │ 对比引擎 │
         └───┬────┘
             │
    ┌────────┼────────┐
    ▼        ▼        ▼
 [匹配]   [可接受]  [需修复]
  差异      差异      差异
```

### 四、对比规则的设计

对比不是简单的 `JSON.stringify(a) === JSON.stringify(b)`。需要一套灵活的规则引擎来处理不同字段的不同对比策略。

```
对比规则示例：

字段：response.timestamp
  策略：忽略（IGNORE）
  原因：时间戳每次都不同

字段：response.data.id
  策略：类型相同即可（TYPE_MATCH）
  原因：新系统可能用不同的 ID 生成策略

字段：response.data.amount
  策略：数值精度到分（PRECISION, 2）
  原因：金额精确到分即可

字段：response.data.items
  策略：忽略顺序，按 ID 关联后对比（SORT_BY_ID）
  原因：新系统可能用不同的排序方式

字段：response.data.status
  策略：精确匹配（EXACT）
  原因：状态值必须完全一致
```

## 完整代码示例

### 示例一：对比引擎核心实现

```typescript
// equivalence/comparator.ts
type ComparisonStrategy = 
  | 'EXACT'
  | 'IGNORE'
  | 'TYPE_MATCH'
  | { type: 'PRECISION'; decimals: number }
  | { type: 'SORT_BY_KEY'; key: string }
  | { type: 'REGEX'; pattern: string }
  | { type: 'TRANSFORM'; fn: (value: unknown) => unknown }

interface ComparisonRule {
  path: string
  strategy: ComparisonStrategy
  description: string
}

interface Difference {
  path: string
  legacyValue: unknown
  newValue: unknown
  rule: ComparisonStrategy
  severity: 'info' | 'warning' | 'error'
}

class EquivalenceComparator {
  private rules: ComparisonRule[] = []
  private ignorePaths: Set<string> = new Set()

  addRule(rule: ComparisonRule): void {
    this.rules.push(rule)
  }

  compare(legacy: unknown, current: unknown): Difference[] {
    return this.deepCompare(legacy, current, '$')
  }

  private deepCompare(
    legacy: unknown,
    current: unknown,
    path: string
  ): Difference[] {
    const rule = this.findRule(path)
    if (rule?.strategy === 'IGNORE') return []

    if (legacy === null && current === null) return []
    if (legacy === null || current === null) {
      return [{
        path,
        legacyValue: legacy,
        newValue: current,
        rule: rule?.strategy || 'EXACT',
        severity: 'warning',
      }]
    }

    if (typeof legacy !== typeof current) {
      if (rule?.strategy === 'TYPE_MATCH') return []
      return [{
        path,
        legacyValue: typeof legacy,
        newValue: typeof current,
        rule: rule?.strategy || 'EXACT',
        severity: 'error',
      }]
    }

    if (rule?.strategy && typeof rule.strategy === 'object') {
      if (rule.strategy.type === 'PRECISION') {
        return this.comparePrecision(
          legacy as number, current as number,
          path, rule.strategy.decimals
        )
      }
      if (rule.strategy.type === 'SORT_BY_KEY') {
        return this.compareSortedArrays(
          legacy as unknown[], current as unknown[],
          path, rule.strategy.key
        )
      }
    }

    if (Array.isArray(legacy) && Array.isArray(current)) {
      return this.compareArrays(legacy, current, path)
    }

    if (typeof legacy === 'object') {
      return this.compareObjects(
        legacy as Record<string, unknown>,
        current as Record<string, unknown>,
        path
      )
    }

    if (legacy !== current) {
      return [{
        path,
        legacyValue: legacy,
        newValue: current,
        rule: rule?.strategy || 'EXACT',
        severity: 'error',
      }]
    }

    return []
  }

  private comparePrecision(
    legacy: number, current: number,
    path: string, decimals: number
  ): Difference[] {
    const factor = Math.pow(10, decimals)
    const l = Math.round(legacy * factor) / factor
    const c = Math.round(current * factor) / factor

    if (l !== c) {
      return [{
        path,
        legacyValue: legacy,
        newValue: current,
        rule: { type: 'PRECISION', decimals },
        severity: 'error',
      }]
    }
    return []
  }

  private compareArrays(
    legacy: unknown[], current: unknown[],
    path: string
  ): Difference[] {
    const diffs: Difference[] = []
    if (legacy.length !== current.length) {
      diffs.push({
        path: `${path}.length`,
        legacyValue: legacy.length,
        newValue: current.length,
        rule: 'EXACT',
        severity: 'error',
      })
    }
    const minLen = Math.min(legacy.length, current.length)
    for (let i = 0; i < minLen; i++) {
      diffs.push(...this.deepCompare(legacy[i], current[i], `${path}[${i}]`))
    }
    return diffs
  }

  private compareSortedArrays(
    legacy: unknown[], current: unknown[],
    path: string, sortKey: string
  ): Difference[] {
    const sortByKey = (arr: unknown[]) =>
      [...arr].sort((a, b) => 
        String((a as any)[sortKey]).localeCompare(String((b as any)[sortKey]))
      )

    const sortedLegacy = sortByKey(legacy)
    const sortedCurrent = sortByKey(current)

    return this.compareArrays(sortedLegacy, sortedCurrent, path)
  }

  private compareObjects(
    legacy: Record<string, unknown>,
    current: Record<string, unknown>,
    path: string
  ): Difference[] {
    const diffs: Difference[] = []
    const allKeys = new Set([...Object.keys(legacy), ...Object.keys(current)])

    for (const key of allKeys) {
      const fieldPath = `${path}.${key}`
      if (this.ignorePaths.has(fieldPath)) continue

      if (!(key in legacy)) {
        diffs.push({
          path: fieldPath,
          legacyValue: undefined,
          newValue: current[key],
          rule: 'EXACT',
          severity: 'warning',
        })
        continue
      }
      if (!(key in current)) {
        diffs.push({
          path: fieldPath,
          legacyValue: legacy[key],
          newValue: undefined,
          rule: 'EXACT',
          severity: 'error',
        })
        continue
      }

      diffs.push(...this.deepCompare(legacy[key], current[key], fieldPath))
    }

    return diffs
  }

  private findRule(path: string): ComparisonRule | undefined {
    return this.rules.find(r => path === r.path || path.startsWith(r.path + '.'))
  }
}
```

### 示例二：Shadow Testing 执行器

```typescript
// equivalence/shadow-tester.ts
interface TestResult {
  requestId: string
  path: string
  matched: boolean
  differences: Difference[]
  legacyLatencyMs: number
  newLatencyMs: number
  timestamp: Date
}

class ShadowTester {
  private comparator: EquivalenceComparator
  private results: TestResult[] = []

  constructor(comparator: EquivalenceComparator) {
    this.comparator = comparator
  }

  async executeTest(
    requestId: string,
    path: string,
    request: ApiRequest,
    legacyExecutor: (req: ApiRequest) => Promise<ApiResponse>,
    newExecutor: (req: ApiRequest) => Promise<ApiResponse>
  ): Promise<TestResult> {
    const startTime = Date.now()

    const [legacyResult, newResult] = await Promise.allSettled([
      this.timedExecution(legacyExecutor, request),
      this.timedExecution(newExecutor, request),
    ])

    const legacyLatency = 
      legacyResult.status === 'fulfilled' ? legacyResult.value.latencyMs : -1
    const newLatency = 
      newResult.status === 'fulfilled' ? newResult.value.latencyMs : -1

    let differences: Difference[] = []

    if (legacyResult.status === 'rejected' && newResult.status === 'rejected') {
      differences = [{
        path: '$.error',
        legacyValue: legacyResult.reason?.message,
        newValue: newResult.reason?.message,
        rule: 'EXACT',
        severity: 'info',
      }]
    } else if (legacyResult.status === 'rejected') {
      differences = [{
        path: '$.error',
        legacyValue: 'REJECTED',
        newValue: 'OK',
        rule: 'EXACT',
        severity: 'error',
      }]
    } else if (newResult.status === 'rejected') {
      differences = [{
        path: '$.error',
        legacyValue: 'OK',
        newValue: 'REJECTED',
        rule: 'EXACT',
        severity: 'error',
      }]
    } else {
      differences = this.comparator.compare(
        legacyResult.value.response.data,
        newResult.value.response.data
      )
    }

    const result: TestResult = {
      requestId,
      path,
      matched: differences.filter(d => d.severity === 'error').length === 0,
      differences,
      legacyLatencyMs: legacyLatency,
      newLatencyMs: newLatency,
      timestamp: new Date(),
    }

    this.results.push(result)
    return result
  }

  private async timedExecution(
    executor: (req: ApiRequest) => Promise<ApiResponse>,
    request: ApiRequest
  ): Promise<{ response: ApiResponse; latencyMs: number }> {
    const start = Date.now()
    const response = await executor(request)
    return { response, latencyMs: Date.now() - start }
  }

  generateReport(): {
    total: number
    matched: number
    matchRate: number
    errorDifferences: Difference[]
    latencyComparison: {
      avgLegacy: number
      avgNew: number
      p99Legacy: number
      p99New: number
    }
  } {
    const errors = this.results
      .flatMap(r => r.differences)
      .filter(d => d.severity === 'error')

    const legacyLatencies = this.results
      .map(r => r.legacyLatencyMs)
      .filter(l => l >= 0)
      .sort((a, b) => a - b)

    const newLatencies = this.results
      .map(r => r.newLatencyMs)
      .filter(l => l >= 0)
      .sort((a, b) => a - b)

    return {
      total: this.results.length,
      matched: this.results.filter(r => r.matched).length,
      matchRate: this.results.length > 0
        ? (this.results.filter(r => r.matched).length / this.results.length) * 100
        : 100,
      errorDifferences: errors,
      latencyComparison: {
        avgLegacy: this.avg(legacyLatencies),
        avgNew: this.avg(newLatencies),
        p99Legacy: this.percentile(legacyLatencies, 99),
        p99New: this.percentile(newLatencies, 99),
      },
    }
  }

  private avg(arr: number[]): number {
    return arr.length > 0 ? arr.reduce((a, b) => a + b, 0) / arr.length : 0
  }

  private percentile(arr: number[], p: number): number {
    if (arr.length === 0) return 0
    const index = Math.ceil((p / 100) * arr.length) - 1
    return arr[Math.max(0, index)]
  }
}
```

## 常见误区

### 误区一：只对比 HTTP 响应体

等价性测试不仅要看响应，还要看**副作用**——数据库写入、消息队列发送、缓存更新。如果新系统响应正确但写入了错误的数据库字段，功能测试可能发现不了。

### 误区二：用简单的字符串对比

`JSON.stringify(a) === JSON.stringify(b)` 会因为字段顺序、空格、null vs undefined 等产生大量误报。必须使用结构化对比。

### 误区三：忽略性能等价

新系统功能正确但慢 10 倍，这也是不等价。Shadow Testing 应该同时记录新旧系统的延迟。

### 误区四：只做一次等价性测试

等价性测试应该是持续运行的。新代码提交后可能引入新的不等价。把它集成到 CI/CD 流水线中。

### 误区五：处理不了的差异就 `as any` 忽略

每个被忽略的差异都应该有明确的理由和记录。无法解释的差异可能隐藏着严重的 bug。

## 小结

等价性测试的核心方法：

1. **Shadow Testing**：真实流量同时发往新旧系统，对比结果
2. **三层验证**：输入等价、输出等价、行为等价
3. **差异分类**：区分预期差异、可接受差异、需修复差异
4. **规则引擎**：对不同字段使用不同的对比策略
5. **持续运行**：集成到 CI/CD，每次发布都做等价性验证

## 参考答案

### 练习一

**思路**：根据字段特性选择合适的对比策略。

**答案**：

```typescript
const searchApiRules: ComparisonRule[] = [
  // 分页信息精确匹配
  { path: '$.total', strategy: 'EXACT', description: '总数必须一致' },
  { path: '$.page', strategy: 'EXACT', description: '页码必须一致' },

  // 用户列表按 ID 排序后对比
  { path: '$.users', strategy: { type: 'SORT_BY_KEY', key: 'id' }, description: '用户列表排序' },

  // 单个用户字段
  { path: '$.users[].id', strategy: 'EXACT', description: '用户 ID 必须一致' },
  { path: '$.users[].name', strategy: 'EXACT', description: '用户名精确匹配' },
  { path: '$.users[].email', strategy: 'EXACT', description: '邮箱精确匹配' },
  { path: '$.users[].createdAt', strategy: 'IGNORE', description: '创建时间由数据库决定' },
  { path: '$.users[].score', strategy: { type: 'PRECISION', decimals: 2 }, description: '评分精度' },
]
```

**要点**：
- `total`、`page` 必须精确匹配，分页信息错误会导致前端分页组件异常
- `id`、`name`、`email` 精确匹配，这些是核心业务字段
- `createdAt` 忽略，因为新旧系统可能用不同的时间源
- `score` 精度到小数点后 2 位，避免浮点数精度差异

### 练习二

**思路**：根据差异的性质和影响判断分类。

**答案**：

1. `$.data.id`: "abc123" vs "xyz789"
   → **预期差异**（Ignorable）。ID 是系统生成的，新旧系统用不同的 ID 生成策略是合理的。对比规则应设置为 `TYPE_MATCH`。

2. `$.data.score`: 85.6 vs 85.59999999999999
   → **可接受差异**（Acceptable）。这是浮点数精度问题，85.6 和 85.59999999999999 在业务上等价。对比规则应设置为 `PRECISION, 2`。

3. `$.data.status`: "active" vs "inactive"
   → **需修复差异**（Actionable）。状态值不一致是业务逻辑错误，直接影响用户看到的数据。

4. `$.data.createdAt`: "2025-06-20T10:30:00Z" vs "2025-06-20T10:30:01Z"
   → **预期差异**（Ignorable）。1 秒的时间差是网络延迟导致的，对比时应忽略时间戳字段。

5. `$.data.items`: 数组长度 3 vs 2
   → **需修复差异**（Actionable）。返回的数据条数不同，说明查询逻辑有差异，可能是筛选条件或分页逻辑的问题。
