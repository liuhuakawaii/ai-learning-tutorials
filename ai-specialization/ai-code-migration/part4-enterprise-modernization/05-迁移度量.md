# 第五课：迁移度量——用数据驱动迁移决策

## 场景引入

你的团队已经完成了核心模块的迁移，灰度到 30% 运行了一周。CTO 问你："迁移进展如何？什么时候能全量切换？"你翻了翻 Jira 看了看任务完成情况，回答"差不多了"。

CTO 不满意这个答案。"差不多"不是数据。他需要的是：迁移覆盖率是多少？新系统的性能比旧系统好还是差？还有多少技术债没有处理？全量切换的风险评估是什么？

迁移度量是把"感觉差不多"变成"数据证明差不多"的工程实践。没有度量的迁移就像没有仪表盘的飞机——你可能在飞，但不知道飞向哪里。

## 学习目标

完成本课学习后，你将能够：

1. 定义迁移覆盖率、迁移质量、迁移风险三个维度的度量指标
2. 建立迁移进度的可视化仪表盘
3. 使用度量数据驱动迁移决策
4. 识别和追踪迁移过程中的技术债
5. 建立迁移完成的验收标准

## 核心概念

### 一、迁移度量的三个维度

```
迁移度量框架：

┌─────────────────────────────────────────────────────────┐
│                    迁移度量三维度                         │
│                                                         │
│  维度 1：覆盖率（Coverage）                              │
│  "迁移了多少？"                                         │
│  - 代码覆盖率：已迁移代码行数 / 总代码行数               │
│  - 模块覆盖率：已迁移模块数 / 总模块数                   │
│  - 流量覆盖率：新系统处理的请求占比                      │
│  - 用户覆盖率：使用新系统的用户占比                      │
│                                                         │
│  维度 2：质量（Quality）                                 │
│  "迁移得好不好？"                                       │
│  - 等价性匹配率：双跑对比的一致性百分比                  │
│  - 缺陷密度：新系统每千行代码的 bug 数                   │
│  - 性能比值：新系统延迟 / 旧系统延迟                     │
│  - 测试覆盖率：自动化测试覆盖的迁移代码百分比            │
│                                                         │
│  维度 3：风险（Risk）                                    │
│  "切换有多危险？"                                       │
│  - 未覆盖的边界场景数                                   │
│  - 依赖的未迁移模块数                                   │
│  - 已知技术债数量                                       │
│  - 回滚方案的就绪度                                     │
│                                                         │
└─────────────────────────────────────────────────────────┘
```


### 示例一：代码迁移覆盖率分析

```typescript
// metrics/coverage-analyzer.ts
import * as ts from 'typescript'
import * as fs from 'fs'
import * as path from 'path'

interface FileCoverage {
  filePath: string
  totalLines: number
  migratedLines: number
  isMigrated: boolean
  language: 'js' | 'ts' | 'jsx' | 'tsx'
  lastModified: Date
}

interface CoverageReport {
  totalFiles: number
  migratedFiles: number
  totalLines: number
  migratedLines: number
  fileCoverage: FileCoverage[]
  moduleCoverage: Array<{
    module: string
    totalFiles: number
    migratedFiles: number
    percentage: number
  }>
}

class MigrationCoverageAnalyzer {
  private srcDir: string

  constructor(srcDir: string) {
    this.srcDir = srcDir
  }

  analyze(): CoverageReport {
    const files = this.scanFiles()
    const fileCoverage = files.map(f => this.analyzeFile(f))

    const totalFiles = fileCoverage.length
    const migratedFiles = fileCoverage.filter(f => f.isMigrated).length
    const totalLines = fileCoverage.reduce((sum, f) => sum + f.totalLines, 0)
    const migratedLines = fileCoverage.reduce((sum, f) => sum + f.migratedLines, 0)

    const moduleCoverage = this.analyzeModuleCoverage(fileCoverage)

    return {
      totalFiles,
      migratedFiles,
      totalLines,
      migratedLines,
      fileCoverage,
      moduleCoverage,
    }
  }

  private scanFiles(): string[] {
    const files: string[] = []
    const extensions = ['.js', '.ts', '.jsx', '.tsx']

    const walk = (dir: string) => {
      for (const entry of fs.readdirSync(dir, { withFileTypes: true })) {
        const fullPath = path.join(dir, entry.name)
        if (entry.isDirectory() && entry.name !== 'node_modules' && entry.name !== 'dist') {
          walk(fullPath)
        } else if (entry.isFile() && extensions.some(ext => entry.name.endsWith(ext))) {
          files.push(fullPath)
        }
      }
    }

    walk(this.srcDir)
    return files
  }

  private analyzeFile(filePath: string): FileCoverage {
    const content = fs.readFileSync(filePath, 'utf-8')
    const lines = content.split('\n')
    const ext = path.extname(filePath)
    const language = ext.slice(1) as FileCoverage['language']
    const isTs = ['ts', 'tsx'].includes(language)

    const stats = fs.statSync(filePath)

    return {
      filePath: path.relative(this.srcDir, filePath),
      totalLines: lines.length,
      migratedLines: isTs ? lines.length : 0,
      isMigrated: isTs,
      language,
      lastModified: stats.mtime,
    }
  }

  private analyzeModuleCoverage(
    fileCoverage: FileCoverage[]
  ): CoverageReport['moduleCoverage'] {
    const modules = new Map<string, { total: number; migrated: number }>()

    for (const file of fileCoverage) {
      const module = file.filePath.split(path.sep)[0] || 'root'
      const current = modules.get(module) || { total: 0, migrated: 0 }
      current.total++
      if (file.isMigrated) current.migrated++
      modules.set(module, current)
    }

    return Array.from(modules.entries()).map(([module, data]) => ({
      module,
      totalFiles: data.total,
      migratedFiles: data.migrated,
      percentage: data.total > 0 ? (data.migrated / data.total) * 100 : 0,
    }))
  }
}
```

### 示例二：迁移仪表盘数据服务

```typescript
// metrics/dashboard-service.ts
interface DashboardData {
  overview: {
    codeCoveragePercent: number
    trafficPercentNew: number
    equivalenceMatchRate: number
    errorRateNew: number
    errorRateLegacy: number
    latencyRatioP99: number
  }
  progress: {
    modules: Array<{
      name: string
      status: string
      coverage: number
      trafficPercent: number
    }>
    timeline: Array<{
      date: string
      coveragePercent: number
      trafficPercent: number
    }>
  }
  quality: {
    testCoverage: number
    defectDensity: number
    openBugs: { p0: number; p1: number; p2: number; p3: number }
    equivalenceTestResults: {
      total: number
      passed: number
      failed: number
    }
  }
  risk: {
    score: number
    factors: Array<{
      name: string
      level: 'low' | 'medium' | 'high' | 'critical'
      description: string
    }>
    unmappedEdgeCases: number
    unmigratedDependencies: number
  }
}

class MigrationDashboardService {
  private coverageAnalyzer: MigrationCoverageAnalyzer
  private metricsCollector: MetricsCollector
  private tracker: MigrationTracker
  private bugTracker: BugTracker

  constructor(
    coverageAnalyzer: MigrationCoverageAnalyzer,
    metricsCollector: MetricsCollector,
    tracker: MigrationTracker,
    bugTracker: BugTracker
  ) {
    this.coverageAnalyzer = coverageAnalyzer
    this.metricsCollector = metricsCollector
    this.tracker = tracker
    this.bugTracker = bugTracker
  }

  async getDashboard(): Promise<DashboardData> {
    const coverage = this.coverageAnalyzer.analyze()
    const metrics = await this.metricsCollector.getCurrent()
    const progress = this.tracker.getOverallProgress()
    const bugs = await this.bugTracker.getOpenBugs()

    return {
      overview: {
        codeCoveragePercent: (coverage.migratedLines / coverage.totalLines) * 100,
        trafficPercentNew: metrics.trafficPercentNew,
        equivalenceMatchRate: metrics.equivalenceMatchRate,
        errorRateNew: metrics.errorRateNew,
        errorRateLegacy: metrics.errorRateLegacy,
        latencyRatioP99: metrics.latencyP99New / metrics.latencyP99Legacy,
      },
      progress: {
        modules: coverage.moduleCoverage.map(m => ({
          name: m.module,
          status: m.percentage === 100 ? 'completed' : m.percentage > 0 ? 'in_progress' : 'not_started',
          coverage: m.percentage,
          trafficPercent: 0,
        })),
        timeline: await this.getTimeline(),
      },
      quality: {
        testCoverage: metrics.testCoverage,
        defectDensity: bugs.total / (coverage.migratedLines / 1000),
        openBugs: bugs,
        equivalenceTestResults: metrics.equivalenceResults,
      },
      risk: this.calculateRisk(coverage, metrics, bugs),
    }
  }

  private calculateRisk(
    coverage: CoverageReport,
    metrics: RuntimeMetrics,
    bugs: OpenBugs
  ): DashboardData['risk'] {
    const factors: DashboardData['risk']['factors'] = []
    let score = 0

    if (coverage.migratedLines / coverage.totalLines < 0.95) {
      factors.push({
        name: '代码覆盖率不足',
        level: 'high',
        description: `当前 ${((coverage.migratedLines / coverage.totalLines) * 100).toFixed(1)}%，目标 95%`,
      })
      score += 30
    }

    if (metrics.equivalenceMatchRate < 99.9) {
      factors.push({
        name: '等价性匹配率不达标',
        level: 'critical',
        description: `当前 ${metrics.equivalenceMatchRate}%，目标 99.9%`,
      })
      score += 40
    }

    if (bugs.p0 > 0 || bugs.p1 > 0) {
      factors.push({
        name: '存在高优先级 bug',
        level: 'critical',
        description: `P0: ${bugs.p0}, P1: ${bugs.p1}`,
      })
      score += 50
    }

    if (metrics.latencyP99New > metrics.latencyP99Legacy * 1.1) {
      factors.push({
        name: '性能退化',
        level: 'medium',
        description: `P99 延迟比值: ${(metrics.latencyP99New / metrics.latencyP99Legacy).toFixed(2)}`,
      })
      score += 20
    }

    return {
      score: Math.min(100, score),
      factors,
      unmappedEdgeCases: metrics.unmappedEdgeCases,
      unmigratedDependencies: metrics.unmigratedDependencies,
    }
  }

  private async getTimeline(): Promise<Array<{ date: string; coveragePercent: number; trafficPercent: number }>> {
    return []
  }
}
```

### 示例三：生成迁移周报

```typescript
// metrics/weekly-report.ts
interface WeeklyReport {
  weekStart: string
  weekEnd: string
  summary: {
    coverageBefore: number
    coverageAfter: number
    trafficBefore: number
    trafficAfter: number
    newBugsFound: number
    bugsClosed: number
  }
  highlights: string[]
  blockers: string[]
  nextWeekPlan: string[]
  riskAssessment: 'low' | 'medium' | 'high'
}

class WeeklyReportGenerator {
  private dashboardService: MigrationDashboardService
  private historicalData: HistoricalDataStore

  async generate(): Promise<WeeklyReport> {
    const current = await this.dashboardService.getDashboard()
    const lastWeek = await this.historicalData.getOneWeekAgo()

    const highlights: string[] = []
    const blockers: string[] = []

    const coverageDelta = current.overview.codeCoveragePercent - (lastWeek?.overview.codeCoveragePercent || 0)
    if (coverageDelta > 0) {
      highlights.push(`代码覆盖率提升 ${coverageDelta.toFixed(1)}%`)
    }

    const trafficDelta = current.overview.trafficPercentNew - (lastWeek?.overview.trafficPercentNew || 0)
    if (trafficDelta > 0) {
      highlights.push(`新系统流量占比提升 ${trafficDelta.toFixed(1)}%`)
    }

    if (current.risk.factors.some(f => f.level === 'critical')) {
      blockers.push('存在 critical 级别风险，不宜推进灰度')
    }

    if (current.quality.openBugs.p0 > 0) {
      blockers.push(`仍有 ${current.quality.openBugs.p0} 个 P0 级 bug 未修复`)
    }

    const riskAssessment = current.risk.score > 60 ? 'high' :
      current.risk.score > 30 ? 'medium' : 'low'

    return {
      weekStart: new Date(Date.now() - 7 * 24 * 3600 * 1000).toISOString().slice(0, 10),
      weekEnd: new Date().toISOString().slice(0, 10),
      summary: {
        coverageBefore: lastWeek?.overview.codeCoveragePercent || 0,
        coverageAfter: current.overview.codeCoveragePercent,
        trafficBefore: lastWeek?.overview.trafficPercentNew || 0,
        trafficAfter: current.overview.trafficPercentNew,
        newBugsFound: current.quality.openBugs.p0 + current.quality.openBugs.p1 + current.quality.openBugs.p2,
        bugsClosed: 0,
      },
      highlights,
      blockers,
      nextWeekPlan: [],
      riskAssessment,
    }
  }

  formatMarkdown(report: WeeklyReport): string {
    return `# 迁移周报（${report.weekStart} ~ ${report.weekEnd}）

## 概览

| 指标 | 上周 | 本周 | 变化 |
|------|------|------|------|
| 代码覆盖率 | ${report.summary.coverageBefore.toFixed(1)}% | ${report.summary.coverageAfter.toFixed(1)}% | +${(report.summary.coverageAfter - report.summary.coverageBefore).toFixed(1)}% |
| 新系统流量 | ${report.summary.trafficBefore.toFixed(1)}% | ${report.summary.trafficAfter.toFixed(1)}% | +${(report.summary.trafficAfter - report.summary.trafficBefore).toFixed(1)}% |
| 新发现 Bug | - | ${report.summary.newBugsFound} | - |
| 关闭 Bug | - | ${report.summary.bugsClosed} | - |

## 风险评估：${report.riskAssessment === 'high' ? '⚠️ 高' : report.riskAssessment === 'medium' ? '🔶 中' : '✅ 低'}

## 本周亮点
${report.highlights.map(h => `- ${h}`).join('\n') || '- 无'}

## 阻塞项
${report.blockers.map(b => `- ❌ ${b}`).join('\n') || '- 无'}

## 下周计划
${report.nextWeekPlan.map(p => `- [ ] ${p}`).join('\n') || '- 待定'}
`
  }
}
```

## 常见误区

### 误区一：只关注代码覆盖率

代码覆盖率 100% 不代表迁移完成。流量覆盖率、等价性匹配率、测试覆盖率同样重要。一个代码迁移完了但只切了 1% 流量的系统，不能称为"迁移完成"。

### 误区二：度量指标太多

不需要追踪 50 个指标。5-8 个核心指标就够了。指标太多会分散注意力，让人不知道该关注什么。

### 误区三：度量数据不准确

手动统计的覆盖率数据一定不准确。度量数据应该通过工具自动采集，不能靠人工填写。

### 误区四：不做历史趋势分析

某一天的覆盖率数据没有意义，趋势才有意义。覆盖率从上周的 60% 涨到本周的 70%，这比"覆盖率 70%"更有信息量。

### 误区五：度量数据不透明

度量数据应该对全团队可见。如果只有负责人看得到仪表盘，团队成员就不知道整体进展和自己的贡献。

## 小结

迁移度量的核心方法：

1. **三维度**：覆盖率、质量、风险
2. **自动化采集**：通过工具而非人工收集数据
3. **可视化仪表盘**：让数据对所有人可见
4. **趋势分析**：关注变化而非快照
5. **Go/No-Go 标准**：用数据而非感觉做决策

## 参考答案

### 练习一

**思路**：Node.js 到 Go 的迁移关注性能和 API 兼容性。

**答案**：

| 指标名称 | 计算公式 | 目标值 | 采集方式 |
|---------|---------|--------|---------|
| API 迁移覆盖率 | 已迁移端点数 / 总端点数 | 100% | Git diff 分析路由文件 |
| 等价性匹配率 | 双跑对比通过数 / 总测试数 | ≥ 99.9% | Shadow Testing 自动收集 |
| P99 延迟比值 | Go P99 / Node.js P99 | ≤ 0.5（性能提升） | APM 工具自动采集 |
| Go 内存使用 | RSS 内存 | ≤ Node.js 的 50% | 容器监控 cAdvisor |
| 错误率 | 5xx 响应数 / 总请求数 | ≤ 0.01% | 负载均衡器日志分析 |

**要点**：
- Node.js 到 Go 的主要收益是性能和资源占用，所以关注延迟比值和内存使用
- API 兼容性通过等价性测试保证
- 覆盖率确保所有端点都迁移了
