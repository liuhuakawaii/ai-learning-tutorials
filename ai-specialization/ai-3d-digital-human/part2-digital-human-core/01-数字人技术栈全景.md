# 数字人技术栈全景

2025年初，某银行上线AI数字客服，人工转接率下降37%；深圳跨境电商用HeyGen生成20多个数字人主播，单月GMV突破50万美元；北京三甲医院试点"数字医生"，口型同步误差不超过60ms。

这三个案例覆盖金融、电商、医疗，但共享同一套底层技术栈。数字人不是算法问题，是**系统工程问题**——任何一环延迟或质量瓶颈，用户体验就崩塌。

## 四条技术路线

**2D数字人**：真人视频素材+语音驱动视频生成。效果逼真（本质是真人视频变形），但视角固定。代表：HeyGen、D-ID。适合短视频口播。

**3D写实数字人**：高精度3D扫描或MetaHuman建模，支持任意视角。技术门槛最高，自由度最大。适合金融客服、高端场景。

**3D卡通数字人**：参数化模型（VRM格式）或风格化建模。渲染开销低，VTuber主流方案。适合虚拟偶像、游戏NPC。

**NeRF-based数字人**：神经辐射场隐式表示头部，少量照片自动重建。结合3DGS加速后已突破实时渲染。适合个性化快速生成。

```
技术选型核心权衡：真实度 vs 延迟 vs 成本

短视频口播 → 2D（低成本、快速出片）
金融客服   → 3D写实（真实感、信任感）
虚拟偶像   → 3D卡通（实时互动、风格化）
个性化定制 → NeRF/3DGS（自动重建）
```

## 四层架构

```
用户输入（文本/语音/手势）
        │
        ▼
  交互层：ASR语音识别 · 意图理解 · 多轮对话
        │  输出：结构化意图 + 上下文
        ▼
  驱动层：TTS语音合成 · 音频驱动面部 · 全身动作生成
        │  输出：Blendshape权重序列 + 身体动作
        ▼
  建模层：3DMM/FLAME参数化 · NeRF · 3DGS
        │  输出：3D模型 + 材质 + 骨骼绑定
        ▼
  渲染层：实时光栅化 · 后处理 · 编码推流
        │  输出：视频帧 → 终端
        ▼
  终端（浏览器/APP/VR）
```

**建模层**是数字人的"身体"——决定长什么样、能做什么表情。**驱动层**是"灵魂"——将文本/音频转化为面部表情和身体动作。**渲染层**是"皮肤"——16.6ms内完成一帧（60fps）。**交互层**是"感官"——处理用户输入，端到端延迟控制在300ms内。

## 技术选型矩阵

| 场景 | 建模层 | 驱动层 | 渲染层 |
|------|--------|--------|--------|
| 短视频口播 | 2D视频生成 | SadTalker音频驱动 | 浏览器WebGL |
| 直播带货 | 2.5D伪3D/参数化3D | 实时音频驱动+手势模板 | 轻量引擎+低延迟推流 |

| 虚拟偶像 | 3D卡通VRM | VTubeStudio面捕+动捕 | Unity/Three.js实时渲染 |

## SadTalker跑通第一个数字人

给一张人脸照片+一段音频，生成说话视频。四步流程：预处理人脸→提取音频系数→渲染动画→输出视频。

```bash
conda create -n sadtalker python=3.10 -y && conda activate sadtalker
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121
git clone https://github.com/OpenTalker/SadTalker.git && cd SadTalker
pip install -r requirements.txt && bash scripts/download_models.sh
```

```python
from src.gradio_demo import SadTalker
import torch

device = "cuda" if torch.cuda.is_available() else "cpu"
sadtalker = SadTalker(lazy_dirs=None, device=device)

result = sadtalker.test(
    source_image="examples/source_image/full_body_1.png",
    driven_audio="examples/driven_audio/chinese_news.wav",
    result_dir="./results",
    pose_style=0,        # 头部姿态风格（0-45）
    exp_scale=1.0,       # 表情幅度（0.5含蓄，1.5夸张）
    still_mode=False,     # True则只有嘴部动
    preprocess="crop",
)
print(f"输出视频: {result}")
```

关键参数：`exp_scale=0.5, still_mode=True`适合新闻播报（稳重）；`exp_scale=1.5, pose_style=20`适合直播带货（活泼）。

## 产品化四维评估

| 指标 | 定义 | 合格线 | 优秀线 |
|------|------|--------|--------|
| 延迟 | 端到端响应 | <800ms | <300ms |
| 真实度 | MOS评分 | >3.5 | >4.2 |
| 可控性 | 表情/动作调节 | 支持预设切换 | 实时微调 |
| 成本 | 单路GPU成本 | <0.5元/分钟 | <0.1元/分钟 |

延迟是最关键的。用户说完话到看到数字人回复超过1秒，体验就严重下降。端到端延迟=网络传输+音频处理+模型推理+渲染+编码+推流，GPU推理可能只占30%。

## 练习

## 参考答案

### 练习一

| 维度 | 选型 | 理由 |
|------|------|------|
| 建模 | 2D/2.5D参数化 | 教师形象固定，不需要多视角 |
| 驱动 | SadTalker离线预渲染+实时TTS | 教案可预知，大部分提前渲染 |
| 渲染 | WebRTC+HLS推流 | 浏览器原生，无需插件 |
| 交互 | Whisper+LLM API | 学生语音问题识别+回答 |

预渲染部分一次性GPU成本约5000元。实时互动（假设5%并发=50路）约0.1元/分钟，月成本≈5000+52800，略超预算。优化：实时部分降级为2D方案可降60%成本。

### 练习二

总延迟=120+150+80+60+30+40=480ms，达标。LLM占比31.25%最大。优化LLM（流式输出、小模型）可省80-100ms。核心策略：流式LLM+流式TTS+流式驱动的管线并行，可压缩到300ms以内。
