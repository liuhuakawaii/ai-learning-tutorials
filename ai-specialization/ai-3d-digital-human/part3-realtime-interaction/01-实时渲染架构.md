# 实时渲染架构：WebGPU / Three.js

一个数字人客服需要以60帧/秒持续渲染，每帧预算16.6ms。在这16.6ms内，浏览器要完成场景遍历、骨骼动画、Blendshape混合、着色器计算、光照渲染。任何一环超预算，数字人就从"真人"变成"恐怖谷"。

本课讲清从JavaScript代码到屏幕像素的完整链路，以及数字人场景的渲染优化。

## WebGPU vs WebGL

WebGL（2011）所有GPU命令通过单线程串行提交，每次draw call都要做状态校验。数字人头部52个Blendshape，每帧数十次draw call，CPU端成为瓶颈。

WebGPU引入"命令编码器"：先在CPU端录制一组GPU命令，然后一次性提交。命令录制无锁，可在Worker线程并行；GPU驱动层可批量优化状态切换。

```
WebGL：JS → WebGL API → 驱动校验 → GPU执行（每次draw call都校验）
WebGPU：JS/Worker → Command Encoder → Command Buffer → GPU批量执行
```

实测：渲染52个Blendshape的数字人面部，WebGPU比WebGL减少约40% CPU端耗时。但简单场景差异不大，WebGPU的威力在复杂场景。

## Three.js Scene Graph

Three.js把3D场景组织为树：根节点是Scene，每个节点包含子节点。移动父节点时所有子节点自动跟随——数字人骨骼天然是层级结构。

```
Scene
├── AmbientLight
├── DirectionalLight
├── Camera
└── DigitalHuman (Group)
    ├── Body (SkinnedMesh)
    ├── Head (SkinnedMesh + Blendshape)
    │   ├── 面部
    │   ├── 眼睛
    │   └── 头发
    └── Armature (骨骼系统)
        ├── 头骨
        ├── 颈椎 → 左肩 → 左臂...
        └── 脊柱 → 骨盆...
```

渲染三阶段：场景更新（遍历Scene Graph计算世界矩阵）→ 排序批处理（按材质排序合并draw call）→ GPU提交。

## 数字人渲染三大难点

**Blendshape驱动**：ARKit 52个面部Blendshape，每个是目标形态的顶点偏移量。最终顶点位置=所有偏移量加权和。超过20个时GPU端计算（Vertex Shader）比CPU更高效。

**皮肤着色**：真实皮肤有次表面散射（SSS），产生"通透感"。实时渲染用预积分皮肤着色或屏幕空间SSS近似。Three.js的`MeshPhysicalMaterial`的`thickness`和`transmission`属性可模拟简单SSS。

**毛发渲染**：高质量头发数万根发丝，需要透明度排序、各向异性高光。实时方案：发片（Hair Card）+ Alpha Test + Kajiya-Kay着色模型。

## 优化决策树

```
渲染一帧
  │
  ├─ 在视锥内？ → 否 → 跳过
  │
  ├─ 距离远？ → 是 → 低模+少骨骼
  │
  ├─ 同模型多实例？ → 是 → InstancedMesh（一次draw call渲染所有）
  │
  └─ Blendshape > 20？ → 是 → GPU Skinning（着色器中计算蒙皮）
```

**Instancing**：场景中多个相同角色时，一次draw call渲染所有实例。Three.js用`InstancedMesh`。

**LOD**：根据距离切换精度。远景用低模（少骨骼、少Blendshape），近景用高模。

**GPU Skinning**：传统CPU蒙皮遍历所有顶点计算骨骼权重。Compute Shader可并行计算，性能提升5-10倍。

## 一帧的时间预算

```
┌──────────┐ ┌────┐ ┌──────┐ ┌──────┐ ┌───────────┐
│场景更新   │ │排序│ │GPU提交│ │等待  │ │空闲/JS逻辑│
│5ms       │ │1ms │ │8ms   │ │1ms   │ │1.6ms      │
└──────────┘ └────┘ └──────┘ └──────┘ └───────────┘
├────────────── 16.6ms 总预算 ──────────────────────┤

关键指标：draw calls < 100 | 三角形 < 200K | 纹理内存 < 512MB
```

import * as THREE from 'three';
import { OrbitControls } from 'https://unpkg.com/three@0.164.1/examples/jsm/controls/OrbitControls.js';

const scene = new THREE.Scene();
scene.background = new THREE.Color(0x1a1a2e);
const camera = new THREE.PerspectiveCamera(45, innerWidth/innerHeight, 0.1, 100);
camera.position.set(0, 1.5, 3);
const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(innerWidth, innerHeight);
renderer.setPixelRatio(Math.min(devicePixelRatio, 2));
renderer.toneMapping = THREE.ACESFilmicToneMapping;
document.body.appendChild(renderer.domElement);

const controls = new OrbitControls(camera, renderer.domElement);
controls.target.set(0, 1.5, 0); controls.enableDamping = true;
scene.add(new THREE.AmbientLight(0xffffff, 0.6));
scene.add(new THREE.DirectionalLight(0xfff5e6, 1.2).position.set(2, 3, 2));

// 构建带Blendshape的头部
const headGeo = new THREE.SphereGeometry(0.5, 64, 64);
headGeo.morphAttributes.position = [];
const pos = headGeo.attributes.position;
const base = pos.array.slice();
const mouthOpen = new Float32Array(base.length);
const smile = new Float32Array(base.length);
const blinkL = new Float32Array(base.length);
const blinkR = new Float32Array(base.length);

for (let i = 0; i < pos.count; i++) {
  const x = base[i*3], y = base[i*3+1], z = base[i*3+2];
  if (y < -0.1 && y > -0.35 && Math.abs(x) < 0.2 && z > 0.3) mouthOpen[i*3+1] = -0.08;
  if (y < 0.05 && y > -0.15 && Math.abs(x) > 0.15 && Math.abs(x) < 0.4 && z > 0.3) smile[i*3+1] = 0.03;
  if (y > 0.2 && y < 0.4 && z > 0.2) {
    if (Math.abs(x+0.2) < 0.12) blinkL[i*3+1] = -0.05;
    if (Math.abs(x-0.2) < 0.12) blinkR[i*3+1] = -0.05;
  }
}
headGeo.morphAttributes.position.push(
  new THREE.Float32BufferAttribute(mouthOpen, 3),
  new THREE.Float32BufferAttribute(smile, 3),
  new THREE.Float32BufferAttribute(blinkL, 3),
  new THREE.Float32BufferAttribute(blinkR, 3));

const head = new THREE.Mesh(headGeo, new THREE.MeshPhysicalMaterial({
  color: 0xf5d0a9, roughness: 0.6, thickness: 0.5, transmission: 0.05, morphTargets: true
}));
head.position.y = 1.5; head.morphTargetInfluences = [0, 0, 0, 0];
scene.add(head);

// 眼睛
const eyeMat = new THREE.MeshPhysicalMaterial({ color: 0x3a2010, roughness: 0.2 });
const eyeL = new THREE.Mesh(new THREE.SphereGeometry(0.06, 32, 32), eyeMat);
const eyeR = new THREE.Mesh(new THREE.SphereGeometry(0.06, 32, 32), eyeMat);
eyeL.position.set(-0.18, 1.58, 0.4); eyeR.position.set(0.18, 1.58, 0.4);
scene.add(eyeL, eyeR);

// 控制
const map = { mouth: 0, smile: 1, blink: 2 };
['mouth', 'smile', 'blink'].forEach(n => {
  document.getElementById(n).addEventListener('input', e => {
    const v = parseFloat(e.target.value) / 100;
    head.morphTargetInfluences[map[n]] = v;
    if (n === 'blink') head.morphTargetInfluences[3] = v;
  });
});

let frames = 0, lastTime = performance.now();
const clock = new THREE.Clock();
function animate() {
  requestAnimationFrame(animate);
  const t = clock.getElapsedTime();
  // 自动动画（用户未手动控制时）
  if (!document.getElementById('mouth').value || document.getElementById('mouth').value === '0')
    head.morphTargetInfluences[0] = (Math.sin(t*1.5)+1)/2*0.3;
  if (!document.getElementById('blink').value || document.getElementById('blink').value === '0')
    head.morphTargetInfluences[2] = head.morphTargetInfluences[3] = Math.pow(Math.sin(t*0.8), 20);
  controls.update(); renderer.render(scene, camera);
  frames++; const now = performance.now();
  if (now - lastTime >= 1000) { document.getElementById('fps').textContent = `FPS: ${frames}`; frames = 0; lastTime = now; }
}
animate();
</script>
</body>
</html>

## 练习

### 练习一：WebGPU命令编码器

解释WebGPU Command Encoder的三阶段工作流程（创建→录制→提交），分析它在数字人渲染中比WebGL的优势。

### 练习二：性能诊断

一个数字人场景帧率不达标，建立诊断流程：先确认瓶颈在CPU还是GPU（Chrome Performance面板），再分别查draw call数、纹理内存、着色器复杂度。

---

## 参考答案

### 练习一

1. 创建：`device.createCommandEncoder()`，此时GPU未收到指令
2. 录制：创建Render/Compute Pass，录制draw call。命令缓存在CPU端Command Buffer中
3. 提交：`device.queue.submit([encoder.finish()])`一次性提交

优势：数字人5-10个子网格各有不同材质。WebGL每次切换材质是昂贵状态变更；WebGPU将所有draw call录到一个Command Buffer，GPU驱动层可优化排序，减少实际状态变更。

### 练习二

1. **CPU vs GPU**：Chrome Performance面板录制一帧，看哪边耗时长
2. **CPU端**：`renderer.info.render.calls`（draw call数>100则需批处理）；`performance.mark()`分段计时
3. **GPU端**：`renderer.info.memory.textures`（>512MB则压缩纹理）；检查Fragment Shader复杂度
4. **针对性优化**：draw call多→Instancing；骨骼重→GPU Skinning；纹理大→KTX2压缩
