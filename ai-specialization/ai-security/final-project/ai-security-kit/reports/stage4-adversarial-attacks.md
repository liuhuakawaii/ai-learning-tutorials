# 阶段四报告：对抗攻击

## 场景引入

某 AI 安全公司在为客户做红队评估时，发现一个开源大模型可以通过特定的多轮对话策略被完全越狱：攻击者先用看似无害的角色扮演让模型进入"无限制模式"，再逐步引导其生成违禁内容。更严重的是，攻击者利用模型的 API 接口，通过大量精心构造的查询逆向还原了模型的部分训练数据。这类对抗攻击远比简单的 Prompt 注入复杂，需要系统性的红队测试才能发现和防御。

## 常见误区

- 认为越狱攻击只是"花式提问"，低估了攻击者利用模型内部机制的能力
- 红队测试只覆盖英文场景，忽略了中文和多语言环境下的攻击差异
- 将红队测试当作一次性验收，没有建立持续化的对抗测试机制
- 只关注单轮攻击，忽略了多轮对话中攻击者逐步构建上下文的渐进式攻击

## 工程建议

- 建立红队测试用例库，覆盖越狱、提取、投毒等主要攻击类别，并持续更新
- 将自动化红队测试集成到模型发布流程中，每次模型迭代都跑一轮对抗评估
- 对模型 API 设置速率限制和异常检测，及时发现批量探测行为
- 在模型部署前进行对抗样本鲁棒性测试，评估模型在边界输入下的表现
