# 阶段二报告：Prompt 注入

## 场景引入

一家电商平台的 AI 导购助手被恶意用户利用：攻击者在商品评价中嵌入隐藏指令，当助手读取这些评价生成推荐摘要时，会执行嵌入的指令，将所有用户的优惠券余额转入攻击者账户。这种"间接注入"攻击绕过了传统的输入过滤，因为恶意内容并非来自用户直接输入，而是来自系统检索到的外部数据。安全团队必须同时防御直接注入和间接注入两条攻击路径。

## 常见误区

- 只防御直接注入，忽略了通过外部数据源（网页、文档、数据库）注入的间接攻击
- 用简单的关键词黑名单做过滤，攻击者通过编码、拆分、同义替换即可绕过
- 认为加一层系统提示词就能完全防御，实际上提示词注入与系统指令之间没有硬隔离
- 防御措施上线后不再更新，攻击手法持续演进，静态规则很快失效

## 工程建议

- 采用多层防御策略：输入过滤 + 输出检测 + 权限最小化，任何单一措施都不够
- 对外部数据源执行与用户输入同等的安全审查，间接注入往往更隐蔽
- 建立注入 Payload 的测试集，每次防御规则更新后回归测试，防止误伤正常功能
- 在系统设计中将 LLM 的能力与执行能力分离，模型只生成文本，敏感操作由后端鉴权后执行
