## 一、理解留存

### 1.1 留存曲线

```
用户留存曲线（典型的 AI 工具产品）：

100% ┤ ●
     │  \
 80% ┤   \
     │    \
 60% ┤     \
     │      \
 40% ┤       \
     │        \___
 20% ┤            \___________________________
     │
  0% ┤─────────────────────────────────────────
     0    1    3    7   14   30   60   90  (天)

典型留存率：
  次日：40-60%（合格）
  7日：20-35%（合格）
  30日：10-20%（合格）

AI 工具产品通常比这个更低，因为：
  1. 用户尝鲜后发现不如预期
  2. 没有形成使用习惯
  3. 找不到持续使用的场景
```

## 三、留存干预机制

### 3.1 用户分群

```typescript
// lib/retention/segmentation.ts
export class UserSegmentation {
  async segmentUsers() {
    const users = await db.user.findMany({
      include: { events: { where: { createdAt: { gte: daysAgo(7) } } } },
    })

    return {
      // 活跃用户：过去 7 天有 3+ 次操作
      active: users.filter(u => u.events.length >= 3),

      // 沉默用户：过去 7 天没有操作
      dormant: users.filter(u => u.events.length === 0 && u.lastActiveAt > daysAgo(14)),

      // 流失风险用户：活跃度下降 50%+
      atRisk: users.filter(u => {
        const recentActivity = u.events.length
        const previousActivity = /* 上周的活跃度 */
        return recentActivity < previousActivity * 0.5
      }),

      // 已流失：超过 30 天未活跃
      churned: users.filter(u => u.lastActiveAt < daysAgo(30)),
    }
  }
}
```

```typescript
// 队列留存分析
async function getCohortData() {
  // 按注册日期分组
  const users = await db.user.findMany({
    orderBy: { createdAt: 'asc' },
    include: { events: true },
  })

  const cohorts = new Map<string, User[]>()

  for (const user of users) {
    const cohortMonth = user.createdAt.toISOString().slice(0, 7)
    if (!cohorts.has(cohortMonth)) cohorts.set(cohortMonth, [])
    cohorts.get(cohortMonth)!.push(user)
  }

  return cohorts
}
```

## 常见误区

### 误区一：只关注获取新用户

获取新用户的成本是留住老用户的 5-7 倍。如果你的留存率是 10%，你每个月需要获取 90% 的新用户来维持同样的活跃度——这不可持续。

### 误区二：用推送轰炸用户

过多的邮件和通知会让用户反感并退订。留存干预要精准、有价值，不是越多越好。

### 误区三：所有用户用同样的留存策略

不同用户群需要不同的策略。新用户需要 Onboarding，活跃用户需要深度功能，沉默用户需要召回。一刀切的效果很差。

### 误区四：留存率低就加功能

留存率低不一定是因为功能不够。可能是核心价值没传递清楚，或者是 Onboarding 太复杂。先找到根本原因，再决定解决方案。

---

## 工程建议

### 1. 找到你的 Aha Moment

分析高留存用户和流失用户的行为差异，找到高留存用户共有的关键行为——那就是你的 Aha Moment。然后设计 Onboarding 引导所有用户到达这个时刻。

### 2. 建立留存预警

当用户活跃度下降时自动触发干预。不要等到用户流失了才行动，要在流失之前就介入。

### 3. 持续优化 Onboarding

Onboarding 是留存的第一道关。每个季度审视一次 Onboarding 流程，看有没有可以简化的地方。

### 4. 收集流失原因

用户取消订阅时，问一个问题："你取消的原因是什么？"这些反馈是改进产品的金矿。

---

## 小结

留存是产品长期存活的关键。核心策略：优化 Onboarding 让用户快速到达 Aha Moment → 用邮件和推送培养使用习惯 → 用数据锁定和团队功能增加粘性 → 对沉默和流失用户进行精准干预。不解决留存问题，增长就是空谈。

### 练习一：Aha Moment 分析

**思路**：Aha Moment 是用户第一次真正感受到产品价值的时刻。分析方法是对比高留存用户和流失用户的行为差异，找到高留存用户共有的关键行为。

**答案**：

```typescript
// Aha Moment 分析方法
// 1. 定义高留存用户：注册后 30 天仍每周活跃的用户
// 2. 定义流失用户：注册后 7 天内再也没回来的用户
// 3. 对比两组用户在第一周的行为差异

const behaviorComparison = {
  // 高留存用户的行为特征（假设分析了 200 个高留存用户）
  highRetention: {
    avgQueriesInWeek1: 8.5,        // 第一周平均查询 8.5 次
    uploadedDocRate: 92%,           // 92% 上传了自己的文档
    usedFollowUpRate: 78%,         // 78% 使用过追问功能
    avgSessionDuration: '12 分钟',  // 平均每次使用 12 分钟
    invitedTeamMemberRate: 35%,    // 35% 邀请了团队成员
  },
  // 流失用户的行为特征（假设分析了 300 个流失用户）
  churnedUsers: {
    avgQueriesInWeek1: 1.2,        // 第一周只查了 1.2 次
    uploadedDocRate: 23%,           // 只有 23% 上传了文档
    usedFollowUpRate: 5%,          // 只有 5% 用过追问
    avgSessionDuration: '2 分钟',
    invitedTeamMemberRate: 0,
  },
};

// 结论：Aha Moment = 上传文档 + 完成 3 次以上查询
// 高留存用户的关键行为：
// 1. 上传了自己的文档（不是用示例文档）
// 2. 在第一周至少查询了 3 次
// 3. 使用过追问功能（说明体验到了多轮对话的价值）
```

- Aha Moment 要用数据验证，不能靠直觉猜测

- 找到 Aha Moment 后，Onboarding 的目标就是引导用户尽快到达它

### 练习三：留存预警

**思路**：留存预警的核心是识别用户即将流失的信号，在用户真正离开之前进行干预。关键指标是用户活跃度的变化趋势，而不是绝对值。

**答案**：

```typescript
// 留存预警机制实现
interface UserActivity {
  userId: string;
  lastActiveAt: Date;
  weeklyQueryCount: number;
  previousWeekQueryCount: number;
  isAlerted: boolean;
}

// 预警规则
const retentionAlertRules = [
  {
    name: '沉默预警',
    condition: (user: UserActivity) => {
      const daysSinceActive = Math.floor(
        (Date.now() - user.lastActiveAt.getTime()) / (1000 * 60 * 60 * 24)
      );
      return daysSinceActive >= 3 && !user.isAlerted;
    },
    action: '发送邮件提醒',
    emailTemplate: {
      subject: '你的文档还在等你回来',
      body: '你已经 3 天没来了，最近有什么新文档需要分析吗？',
      cta: '立即使用',
    },
  },
  {
    name: '活跃度下降预警',
    condition: (user: UserActivity) => {
      return (
        user.previousWeekQueryCount >= 5 &&
        user.weeklyQueryCount <= 1 &&
        !user.isAlerted
      );
    },
    action: '发送功能推荐邮件',
    emailTemplate: {
      subject: '发现你最近用得少了，这些功能你试过了吗？',
      body: '根据你的使用习惯，推荐你试试 XX 功能……',
      cta: '探索新功能',
    },
  },
];

// 每日执行的预警检查
async function runDailyRetentionCheck() {
  // 查询所有活跃用户（过去 30 天内有活动）
  const users = await db.query('SELECT * FROM users WHERE last_active_at > NOW() - INTERVAL 30 DAY');

  for (const user of users) {
    for (const rule of retentionAlertRules) {
      if (rule.condition(user)) {
        await sendAlert(user, rule);
        await db.query('UPDATE users SET is_alerted = true WHERE id = ?', [user.userId]);
      }
    }
  }
}
```

**要点**：
- 预警要趁早，3 天不活跃就开始干预，不要等到 30 天
- 邮件内容要有针对性，不能千篇一律
- 预警频率要有上限，避免骚扰用户（同一用户一周最多收到 1 次预警邮件）

**答案**：

```typescript
// 优先选择：曾经活跃但最近 14 天未登录的用户
// 避免选择：注册后从未使用的用户（他们没有体验过产品价值）
const targetUsers = await db.query(`
  SELECT * FROM users
  WHERE last_active_at BETWEEN NOW() - INTERVAL 30 DAY AND NOW() - INTERVAL 14 DAY
  AND total_queries > 5
  ORDER BY last_active_at DESC
  LIMIT 20
`);

// 第二步：发送调研邀请（邮件模板）
const surveyEmail = {
  subject: '能问你一个问题吗？',
  body: `你好，
我注意到你已经有一段时间没使用 [产品名] 了。
作为产品的负责人，我真的很想了解你的体验——
是什么让你决定不再使用的？

只需要 2 分钟回复这封邮件，你的反馈会直接影响产品的改进方向。
作为感谢，我们会给你一个月的免费 Pro 会员。

期待你的回复。`,
};

// 第三步：整理调研结果（预期的典型反馈分类）
const churnReasons = {
  quality: 'AI 回答质量不够好（30%）',
  price: '觉得太贵（25%）',
  alternative: '找到了更好的替代品（20%）',
  need: '需求变了，不再需要这类工具（15%）',
  experience: '产品体验不好（bug、速度慢）（10%）',
};
```

**要点**：
- 选择曾经活跃过的用户调研，他们有真实的使用体验
- 问题要开放，不要引导（"你为什么不用了？"而不是"是因为价格吗？"）
- 调研结果要分类统计，找到共性问题优先解决
