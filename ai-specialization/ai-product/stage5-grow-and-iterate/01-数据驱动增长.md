> **课程定位**：建立 AI 产品的核心指标体系，用数据指导产品决策

## 场景引入

你的 AI 产品上线一个月了，有 500 个注册用户。你打开后台，看到一堆数字：PV、UV、注册数、活跃数……但这些数字告诉你什么？用户在哪里流失？哪个功能最受欢迎？为什么付费转化率只有 2%？你缺的不是数据，而是解读数据的框架和用数据做决策的能力。

### 2.2 漏斗分析实现

```typescript
// lib/analytics/funnel.ts
export class FunnelAnalyzer {
  private db: Database

  constructor(db: Database) {
    this.db = db
  }

  async analyze(funnelSteps: FunnelStep[], dateRange: { from: Date; to: Date }) {
    const results: FunnelResult[] = []
    let previousCount = 0

    for (let i = 0; i < funnelSteps.length; i++) {
      const step = funnelSteps[i]

      // 统计完成此步骤的用户数
      const count = await this.db.events.count({
        where: {
          event: step.event,
          createdAt: { gte: dateRange.from, lte: dateRange.to },
          ...(step.filters || {}),
        },
        distinct: 'userId',
      })

      // 计算转化率
      const conversionFromPrevious = i === 0 ? 1 : count / previousCount
      const conversionFromFirst = count / (results[0]?.count || count)

      results.push({
        step: step.name,
        count,
        conversionFromPrevious,
        conversionFromFirst,
        dropoff: i === 0 ? 0 : previousCount - count,
      })

      previousCount = count
    }

    return results
  }
}

// 使用示例
const funnel = new FunnelAnalyzer(db)
const results = await funnel.analyze(conversionFunnel.steps, {
  from: new Date('2025-01-01'),
  to: new Date('2025-01-31'),
})
```

## 三、A/B 测试

### 3.1 A/B 测试框架

```typescript
// lib/ab-testing.ts
export class ABTest {
  private db: Database

  constructor(db: Database) {
    this.db = db
  }

  // 创建实验
  async createExperiment(config: {
    name: string
    variants: Array<{ name: string; weight: number }>
    metric: string
    minSampleSize: number
  }) {
    return this.db.experiment.create({
      data: {
        name: config.name,
        variants: config.variants,
        metric: config.metric,
        minSampleSize: config.minSampleSize,
        status: 'running',
      },
    })
  }

  // 为用户分配变体
  async assignVariant(experimentId: string, userId: string): Promise<string> {
    // 检查是否已分配
    const existing = await this.db.exposure.findFirst({
      where: { experimentId, userId },
    })

    if (existing) return existing.variant

    // 根据权重随机分配
    const experiment = await this.db.experiment.findUnique({
      where: { id: experimentId },
    })

    const variant = this.randomVariant(experiment.variants)

    await this.db.exposure.create({
      data: { experimentId, userId, variant },
    })

    return variant
  }

  // 记录转化事件
  async trackConversion(experimentId: string, userId: string, metric: string, value?: number) {
    await this.db.conversion.create({
      data: { experimentId, userId, metric, value },
    })
  }

  // 分析结果
  async analyze(experimentId: string) {
    const experiment = await this.db.experiment.findUnique({
      where: { id: experimentId },
    })

    const results = []

    for (const variant of experiment.variants) {
      const exposures = await this.db.exposure.count({
        where: { experimentId, variant: variant.name },
      })

      const conversions = await this.db.conversion.count({
        where: { experimentId, metric: experiment.metric },
      })

      results.push({
        variant: variant.name,
        exposures,
        conversions,
        conversionRate: conversions / exposures,
      })
    }

    // 计算统计显著性（简化版）
    const control = results[0]
    const treatment = results[1]
    const isSignificant = this.isStatisticallySignificant(control, treatment)

    return { results, isSignificant }
  }

  private randomVariant(variants: Array<{ name: string; weight: number }>): string {
    const random = Math.random()
    let cumulative = 0

    for (const variant of variants) {
      cumulative += variant.weight
      if (random <= cumulative) return variant.name
    }

    return variants[variants.length - 1].name
  }

  private isStatisticallySignificant(control: any, treatment: any): boolean {
    // 简化的显著性检验
    const pooledRate = (control.conversions + treatment.conversions) /
                       (control.exposures + treatment.exposures)

    const se = Math.sqrt(
      pooledRate * (1 - pooledRate) * (1/control.exposures + 1/treatment.exposures)
    )

    const z = (treatment.conversionRate - control.conversionRate) / se
    return Math.abs(z) > 1.96  // 95% 置信度
  }
}
```

## 常见误区

### 误区一：关注虚荣指标

注册总数、总访问量——这些数字好看但没用。真正有用的是趋势和转化率：注册增长率是多少？访问到注册的转化率是多少？

### 误区二：数据量不够就做决策

A/B 测试需要足够的样本量才能得出结论。100 个用户的差异可能是随机波动，不是真正的效果差异。至少需要 200+ 的样本量。

### 误区三：只看数据不看用户

数据告诉你"是什么"，但不告诉你"为什么"。转化率低了，为什么？数据看不出来，需要和用户聊。

### 误区四：一次测试太多变量

A/B 测试一次只测一个变量。如果你同时改了按钮颜色和文案，你不知道是哪个改动导致了效果变化。

## 工程建议

### 1. 从第一天就开始记录数据

数据的价值在于积累。产品上线第一天就开始记录关键事件，一个月后你才有足够的数据做分析。

### 2. 建立每周数据回顾的习惯

每周花 30 分钟看一次数据看板。关注趋势变化，而不是绝对数值。突然的变化往往意味着某个改动起了作用或出了问题。

### 3. 优先优化流失最大的环节

漏斗分析的最大价值是找到最大的流失点。如果注册→激活的转化率只有 20%，优化这个环节比优化付费转化更有价值。

### 4. 用假设驱动实验

不要随便改东西然后看效果。先提出假设（"简化注册流程可以提高转化率"），再设计实验验证。

---

## 小结

数据驱动增长的核心是：定义指标 → 漏斗分析 → 发现问题 → 提出假设 → A/B 测试验证 → 迭代改进。AI 产品的关键指标包括激活率、留存率、付费转化率和 AI 质量指标。从第一天就开始记录数据，建立每周回顾的习惯。

## 参考答案

### 练习一：指标定义

**思路**：北极星指标应该反映产品核心价值的交付频率，而不是虚荣指标（如总注册数）。选择时要考虑：它是否能代表用户获得了价值？团队能否直接影响它？增长是否可持续？

**答案**：

以 AI 文档问答产品为例：

```typescript
// 北极星指标：每周活跃查询用户数（WAQ）
// 计算方式：过去 7 天内至少发起过 1 次有效问答的独立用户数
// 为什么选它：直接反映用户是否在使用核心功能获得价值

// 5 个关键指标
const keyMetrics = {
  // 1. 激活率：注册后 24 小时内完成首次问答的用户比例
  activationRate: {
    formula: '完成首次问答的新用户数 / 当日注册用户数',
    target: '> 40%',
    optimization: '优化 Onboarding 流程，减少首次问答的步骤',
  },
  // 2. 7 日留存率：注册第 7 天仍活跃的用户比例
  day7Retention: {
    formula: '第 7 天活跃用户数 / 7 天前注册用户数',
    target: '> 25%',
    optimization: '提升回答质量，增加使用场景引导',
  },
  // 3. 周均查询次数：活跃用户每周平均发起的查询数
  weeklyQueriesPerUser: {
    formula: '本周总查询数 / 本周活跃用户数',
    target: '> 5 次',
    optimization: '优化查询体验，支持追问和多轮对话',
  },
  // 4. 付费转化率：从免费用户转化为付费用户的比例
  paidConversionRate: {
    formula: '付费用户数 / 累计注册用户数',
    target: '> 5%',
    optimization: '设计合理的免费额度，展示付费功能价值',
  },
  // 5. AI 回答满意率：用户对 AI 回答给出正面反馈的比例
  aiSatisfactionRate: {
    formula: '点赞次数 / (点赞 + 点踩) 次数',
    target: '> 75%',
    optimization: '改进 Prompt、优化检索质量、增加人工标注',
  },
};
```

**要点**：
- 北极星指标要能反映用户获得的核心价值，而不是表面数字
- 每个指标都要有明确的计算公式、目标值和优化方向
- AI 产品需要同时关注业务指标（留存、付费）和 AI 质量指标（满意率）

### 练习二：漏斗分析

**思路**：漏斗分析的关键是把用户从进入到产生价值的完整路径拆解成离散步骤，然后找出每一步的流失率。最大的流失环节就是最值得优化的地方。

**答案**：

以 AI 文档问答产品的核心转化漏斗为例：

```typescript
const funnel = {
  steps: [
    { name: '访问落地页', users: 10000, rate: '100%' },
    { name: '点击注册', users: 3000, rate: '30%' },       // 流失 70% — 落地页说服力不足
    { name: '完成注册', users: 2100, rate: '70%' },       // 流失 30% — 注册流程太复杂
    { name: '上传文档', users: 840, rate: '40%' },        // 流失 60% — 最大流失点！
    { name: '发起首次问答', users: 504, rate: '60%' },    // 流失 40%
    { name: '获得满意回答', users: 378, rate: '75%' },    // 流失 25%
    { name: '第二次使用', users: 189, rate: '50%' },      // 流失 50%
  ],
};

// 最大流失环节：注册 → 上传文档（流失 60%）
// 可能原因：
// 1. 用户不知道上传什么文档
// 2. 上传流程太复杂（格式限制、大小限制）
// 3. 用户担心隐私问题

// 优化方案：
// 1. 提供示例文档一键体验
// 2. 支持拖拽上传，放宽格式限制
// 3. 明确说明文档处理的隐私政策
```

**要点**：
- 漏斗的每一步都要对应一个用户行为，不能模糊
- 找到最大流失点后，要先分析原因再提出优化方案
- 优化时一次只改一个变量，才能知道什么有效

### 练习三：A/B 测试

**思路**：A/B 测试的核心是控制变量。一次只测试一个改动，确定样本量足够，设定明确的成功标准和运行时间。

**答案**：

假设最大的产品假设是："简化注册流程（去掉邮箱验证）可以提高注册完成率"。

```typescript
const abTest = {
  name: '简化注册流程',
  hypothesis: '去掉邮箱验证步骤，注册完成率可以从 70% 提升到 85%',
  control: {
    name: '原始流程',
    description: '邮箱 → 密码 → 邮箱验证 → 完成注册',
  },
  variant: {
    name: '简化流程',
    description: '邮箱 → 密码 → 直接进入产品（邮箱验证延后）',
  },
  primaryMetric: '注册完成率',
  secondaryMetrics: ['激活率', '7 日留存率'], // 确保简化不损害后续指标
  sampleSize: {
    calculation: '基线 70%，最小检测效应 15%，显著性 95%，统计功效 80%',
    perGroup: 350, // 每组需要约 350 个用户
  },
  duration: '14 天', // 覆盖工作日和周末
  successCriteria: '实验组注册完成率显著高于对照组（p < 0.05），且 7 日留存率不低于对照组',
};
```

**要点**：
- 永远同时监控次要指标，防止主指标提升但整体变差（如注册率提升但留存下降）
- 样本量要提前计算，不能"看感觉"决定何时结束
- 测试期间不要中途查看结果做决策，避免"偷看"偏差

### 练习四：数据看板

**思路**：数据看板要让人一眼看到最重要的信息。核心指标放最上面，趋势图放中间，明细数据放下面。看板的目标是"3 秒内知道产品是否健康"。

**答案**：

```typescript
// 数据看板结构设计
const dashboard = {
  // 顶部：核心指标卡片（实时/每日更新）
  topCards: [
    { label: '今日新增用户', value: 45, trend: '+12%', period: 'vs 昨日' },
    { label: '今日活跃用户', value: 312, trend: '+5%', period: 'vs 昨日' },
    { label: '今日查询次数', value: 1247, trend: '-3%', period: 'vs 昨日' },
    { label: '付费转化率', value: '4.2%', trend: '+0.3%', period: 'vs 上周' },
  ],

  // 中间：趋势图（每周更新）
  charts: [
    {
      title: '核心指标周趋势',
      type: 'line',
      metrics: ['新增用户', '活跃用户', '付费用户'],
      period: '过去 8 周',
    },
    {
      title: '转化漏斗',
      type: 'funnel',
      steps: ['访问', '注册', '激活', '留存', '付费'],
      period: '本周',
    },
  ],

  // 底部：明细表（每日更新）
  tables: [
    {
      title: '渠道来源分析',
      columns: ['渠道', '访问量', '注册数', '转化率', '成本'],
    },
    {
      title: '功能使用排行',
      columns: ['功能', '使用次数', '使用人数', '满意率'],
    },
  ],

  // 告警规则
  alerts: [
    { metric: '日活跃用户', condition: '连续 3 天下降超过 10%', channel: '飞书/Slack' },
    { metric: 'AI 回答满意率', condition: '低于 70%', channel: '邮件' },
  ],
};
```

**要点**：
- 看板要分层次：概览 → 趋势 → 明细，让人按需深入
- 设置异常告警，不要等人主动看数据才发现问题
- 看板是工具不是摆设，要建立每周回顾看板的习惯
