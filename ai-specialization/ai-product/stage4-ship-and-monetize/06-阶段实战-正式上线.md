# 阶段实战：正式上线

你已经完成了上线检查清单、支付集成、用户认证、定价设计和发布策略。现在走完从"本地开发"到"线上运营"的最后一公里：部署上线、验证支付链路、发布产品、获取首批付费用户。

目标很明确——让你的产品真正上线并收到第一笔钱。

## 生产环境部署


## 发布策略

第一周的节奏：

```
Day 1: 软发布
├── 发到 2-3 个目标用户群
├── 发到 V2EX / 少数派 / Product Hunt
└── 发一条朋友圈

Day 2-3: 收集反馈
├── 监控注册、激活、付费数据
├── 主动联系首批用户收集反馈
└── 记录所有 bug 和改进建议

Day 4-5: 快速修复
├── 修复阻塞性 bug
├── 优化 onboarding 流程
└── 调整文案和定价（如果有数据支撑）

Day 6-7: 复盘决策
├── 分析数据：注册数、激活率、付费率
├── 决策：继续推广 / 调整方向 / 暂停
└── 制定下周计划
```

## 练习

### 练习一：完成部署

把你的产品部署到生产环境。要求：
- 环境变量在平台中配置（不在代码中）
- 数据库已迁移
- 支付已配置（用 Stripe 测试模式）
- 错误监控已接入

记录部署过程中遇到的问题和解决方案。

### 练习二：验证完整链路

用测试账号走完从注册到付费的完整流程：
1. 注册新账号
2. 完成首次 AI 生成
3. 用 Stripe 测试卡完成付费
4. 确认付费后能访问高级功能
5. 检查 Stripe Dashboard 中的订单记录

记录每一步的结果和遇到的问题。

### 练习三：获取首批用户

用至少两种渠道获取 10 个以上的真实用户。记录：
- 每个渠道的投入（时间、金钱）
- 获得的用户数
- 激活率（完成首次 AI 生成的比例）
- 付费率

## 参考答案

### 练习一

部署过程中最常见的问题：
1. 环境变量漏配（解决：列一份清单，逐个检查）
2. 数据库连接失败（解决：检查 DATABASE_URL 格式和网络权限）
3. 构建失败（解决：本地先 `npm run build` 确保通过）

### 练习二

支付链路验证的关键是测试异常场景：
- 支付被拒绝时用户看到什么提示？
- 支付成功但 webhook 处理失败时怎么恢复？
- 用户取消订阅后是否正确降级？

### 练习三

首批用户的质量比数量重要。10 个精准的目标用户比 100 个随机用户更有价值。重点关注用户的反馈内容，而不是好评率。
