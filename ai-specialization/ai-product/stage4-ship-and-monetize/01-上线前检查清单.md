# 上线前检查清单：别把 API Key 推到 GitHub

你的 AI 产品在本地跑得很好，Demo 也很漂亮。你准备上线，朋友问："你的 API Key 写在代码里的吗？用户数据加密了吗？有隐私政策吗？页面加载要多久？"

你一检查——API Key 确实在前端代码里，数据库没有备份策略，隐私政策页面根本不存在。

上线不是把代码推到 Vercel 就完了。这节课给你一份上线前必须完成的检查清单。

## 安全检查

这是最容易被忽视也最致命的部分。

```typescript
// ❌ 错误：API Key 在前端代码中
const apiKey = "sk-xxxxxxxxxxxx";  // 推到 GitHub 后 5 分钟内就会被扫描到

// ✅ 正确：API Key 在环境变量中，只在服务端使用
// .env.local（不提交到 Git）
OPENAI_API_KEY=sk-xxxxxxxxxxxx

// next.config.js
const config = {
  env: {
    // 不要把 OPENAI_API_KEY 暴露到客户端
  },
};
```

安全检查清单：

```typescript
const securityChecklist = {
```

## 合规检查

面向用户的 AI 产品必须有这些东西：

```typescript
const complianceChecklist = {
  legal: [
    "隐私政策页面（说明收集什么数据、怎么用）",
    "用户协议（说明服务范围和免责条款）",
    "Cookie 同意弹窗（如果有用户追踪）",
  ],
  ai: [
    "AI 生成内容有标识（告知用户这是 AI 生成的）",
    "有内容审核机制（防止 AI 生成违规内容）",
    "有用户反馈和投诉渠道",
  ],
};
```

隐私政策不用请律师写，用模板生成器（如 [privacypolicygen](https://www.privacypolicygenerator.info/)）先出一版，后续再完善。但不能没有。


## 部署配置

```bash

vercel --prod

# 检查部署结果

vercel logs             # 查看运行日志
```

部署后立即测试：
1. 打开首页，确认能正常加载
2. 注册一个新账号，确认注册流程正常
3. 完成一次核心功能（AI 生成），确认输出正常
4. 查看浏览器控制台，确认没有报错
5. 查看服务端日志，确认没有异常

## 练习

### 练习一：安全审计

对你的项目做一次安全审计。用以下命令检查是否有敏感信息泄露：

```bash
# 检查 Git 历史中是否有 Key
git log --all --full-history -- "*.env*"
git log -p --all -S 'sk-' -- "*.ts" "*.js"

# 检查当前代码中是否有硬编码的 Key
grep -r "sk-" --include="*.ts" --include="*.js" .
grep -r "password" --include="*.ts" --include="*.js" .
```

如果有泄露，立即到 OpenAI 后台轮换 Key。

### 练习二：性能测试

用 Lighthouse 测试你的页面性能。目标：
- Performance > 80
- Accessibility > 90
- Best Practices > 90
- SEO > 80

针对得分最低的项做优化。

### 练习三：合规文档

为你的产品生成以下文档：
- 隐私政策（可以用模板生成器）
- 用户协议（简版即可）
- AI 生成内容标识（在页面上加一句"以上内容由 AI 生成，仅供参考"）

---

## 参考答案

### 练习一

最常见的泄露场景：
1. `.env` 文件被提交到 Git（解决：加到 `.gitignore`，用 `git filter-branch` 清理历史）
2. API Key 写在前端代码中（解决：移到服务端 API Route）
3. 部署日志中打印了环境变量（解决：日志脱敏）

### 练习二

前端性能优化的低垂果实：
- 图片用 Next.js 的 `<Image>` 组件
- 字体用 `next/font` 本地加载
- 不需要首屏的组件用 `dynamic()` 懒加载

### 练习三

AI 生成内容标识不仅是合规要求，也是用户信任的基础。在生成结果下方加一行小字："以上内容由 AI 生成，请核实后使用"。
