# 第1课：上线前检查清单

> **课程定位**：系统性地检查产品上线前的性能、安全、合规等关键环节
> **前置知识**：有基本的 Web 应用开发经验
> **预计时长**：35 分钟

---

## 场景引入

你的 AI 产品在本地跑得很好，Demo 也做得很漂亮。你准备上线，朋友问你："你的 API Key 是写在代码里的吗？用户数据加密了吗？有隐私政策吗？页面加载要多久？"你一检查，发现 API Key 确实在前端代码里，数据库没有备份策略，隐私政策页面根本不存在。上线不是把代码推到 Vercel 就完了——你还需要一份完整的上线检查清单。

### 2.2 API 认证中间件

```typescript
// lib/auth/middleware.ts
import { NextRequest, NextResponse } from 'next/server'
import { verifyToken } from './jwt'

export function withAuth(handler: Function) {
  return async (req: NextRequest) => {
    const token = req.headers.get('authorization')?.replace('Bearer ', '')

    if (!token) {
      return NextResponse.json({ error: '未登录' }, { status: 401 })
    }

    try {
      const userId = await verifyToken(token)
      req.headers.set('x-user-id', userId)
      return handler(req)
    } catch {
      return NextResponse.json({ error: 'Token 无效' }, { status: 401 })
    }
  }
}

// 使用示例
export const POST = withAuth(async (req: NextRequest) => {
  const userId = req.headers.get('x-user-id')
  // 业务逻辑...
})
```

### 2.3 Rate Limiting

```typescript
// lib/rate-limit.ts
import { Ratelimit } from '@upstash/ratelimit'
import { Redis } from '@upstash/redis'

const ratelimit = new Ratelimit({
  redis: Redis.fromEnv(),
  limiter: Ratelimit.slidingWindow(10, '60 s'),  // 60 秒内最多 10 次
  analytics: true,
})

export async function checkRateLimit(identifier: string) {
  const { success, limit, reset, remaining } = await ratelimit.limit(identifier)

  return {
    success,
    headers: {
      'X-RateLimit-Limit': limit.toString(),
      'X-RateLimit-Remaining': remaining.toString(),
      'X-RateLimit-Reset': reset.toString(),
    },
  }
}

// 在 API Route 中使用
export async function POST(req: NextRequest) {
  const userId = req.headers.get('x-user-id')!
  const { success, headers } = await checkRateLimit(userId)

  if (!success) {
    return NextResponse.json(
      { error: '请求过于频繁' },
      { status: 429, headers }
    )
  }

  // 继续处理请求...
}
```

```typescript
// app/api/user/data/route.ts
export async function GET(req: NextRequest) {
  const userId = req.headers.get('x-user-id')!

  // 导出用户所有数据
  const [user, documents, conversations, messages] = await Promise.all([
    db.users.findUnique({ where: { id: userId } }),
    db.documents.findMany({ where: { userId } }),
    db.conversations.findMany({ where: { userId } }),
    db.messages.findMany({
      where: { conversation: { userId } },
    }),
  ])

  const exportData = {
    user: { email: user?.email, createdAt: user?.createdAt },
    documents: documents.map(d => ({ filename: d.filename, createdAt: d.createdAt })),
    conversations: conversations.length,
    messages: messages.map(m => ({ role: m.role, content: m.content, date: m.createdAt })),
    exportedAt: new Date().toISOString(),
  }

  return new Response(JSON.stringify(exportData, null, 2), {
    headers: {
      'Content-Type': 'application/json',
      'Content-Disposition': 'attachment; filename="my-data.json"',
    },
  })
}

// 删除用户所有数据
export async function DELETE(req: NextRequest) {
  const userId = req.headers.get('x-user-id')!

  // 按依赖顺序删除
  await db.messages.deleteMany({ where: { conversation: { userId } } })
  await db.conversations.deleteMany({ where: { userId } })
  await db.documentChunks.deleteMany({ where: { document: { userId } } })
  await db.documents.deleteMany({ where: { userId } })
  await db.feedback.deleteMany({ where: { userId } })
  await db.users.delete({ where: { id: userId } })

  return Response.json({ success: true, message: '所有数据已删除' })
}
```

## 常见误区

### 误区一：上线后再考虑安全

安全问题上线后修复成本是上线前的 10 倍。API Key 泄露、数据库未加密、没有认证——这些都是上线前必须解决的问题。

### 误区二：隐私政策可以抄一个

隐私政策必须与你的实际数据处理方式一致。你用了 AI 处理用户文档，隐私政策里必须说明这一点。不一致的隐私政策比没有隐私政策更危险。

### 误区三：性能优化是后期的事

首屏加载 3 秒是用户留存的生死线。如果上线时加载要 8 秒，一半用户在看到你的产品之前就走了。

### 误区四：小产品不需要监控

错误追踪和日志不是大公司的专利。没有监控，你的产品出了问题你都不知道——直到用户来投诉。

## 工程建议

### 1. 用 Checklist 管理上线流程

把检查清单做成一个文档或 Notion 模板，每个项目上线前逐项打勾。不要依赖记忆。

### 2. 自动化安全检查

用 ESLint 插件检测硬编码的 API Key，用 `npm audit` 检查依赖漏洞，在 CI 中集成安全扫描。

### 3. 设置 Uptime 监控

用 UptimeRobot 或 Better Stack 监控你的服务是否在线。宕机时第一时间知道，而不是等用户告诉你。

### 4. 准备回滚方案

上线前确保能快速回滚到上一个版本。Vercel 的 Deployment 机制天然支持这一点，但你需要知道怎么操作。

---

## 小结

上线不是"推代码到生产环境"。安全（API Key、认证、限流）、性能（首屏加载、流式响应）、合规（隐私政策、数据删除）、SEO（Meta 标签、Sitemap）、监控（错误追踪、日志）——每一项都不能遗漏。用检查清单管理上线流程，确保没有遗漏。

---

## 练习

1. **安全审计**：检查你的项目代码，确保没有硬编码的 API Key 或敏感信息。
2. **性能测试**：用 Lighthouse 测试你的页面，找出性能瓶颈并优化到 90 分以上。
3. **隐私政策**：为你的产品撰写一份隐私政策页面，特别说明 AI 处理相关的内容。
4. **上线清单**：为你的产品制定一份完整的上线检查清单，按优先级排序。

### 练习一：安全审计

**思路**：用全局搜索排查硬编码密钥，再用自动化工具做二次校验。重点检查前端代码、配置文件、Git 历史。

**答案**：

```bash
# 1. 搜索硬编码的 API Key
grep -rn "sk-" --include="*.ts" --include="*.tsx" --include="*.js" --include="*.jsx" .
grep -rn "OPENAI_API_KEY\|STRIPE_SECRET_KEY\|DATABASE_URL" --include="*.ts" --include="*.tsx" .

# 2. 检查 .env 文件是否被 Git 追踪
git ls-files | grep -E "\.env"

# 3. 如果 .env 被追踪，需要从历史中移除
git rm --cached .env
echo ".env" >> .gitignore
git commit -m "fix: 移除被追踪的环境变量文件"

# 4. 用 ESLint 插件自动检测
npm install --save-dev eslint-plugin-no-secrets
```
