# 第五课：用户反馈收集

## 场景引入

你的 MVP 上线了，前 3 天有 20 个用户试用，生成了 50 条文案。你很高兴，但紧接着就困惑了：用户到底满不满意？他们觉得文案质量怎么样？他们会不会继续用？他们愿意付费吗？

你盯着 Vercel Analytics 的数据看——页面浏览量、停留时间、跳出率——但这些数据告诉你"发生了什么"，却不告诉你"为什么"。这一课，你会学到如何系统性地收集和分析用户反馈，把模糊的感觉变成可执行的决策。

## 学习目标

1. 掌握用户反馈收集的多种方法
2. 学会区分"用户说的"和"用户做的"
3. 能够从反馈中提取可执行的产品改进方向
4. 建立持续的反馈收集机制

## 一、反馈收集的三个层次

### 1.1 行为数据（What they do）

```
用户做了什么，比说了什么更真实。

关键行为指标：
- 生成次数：用户生成了几次文案？（反复生成 = 对质量不满意）
- 复制率：用户复制了多少生成的文案？（复制 = 认可质量）
- 回访率：用户第二天/第七天是否回来使用？（回访 = 产品有价值）
- 停留时间：用户在结果页停留多久？（太短 = 没看就走了，太长 = 可能在纠结）
```

### 1.2 直接反馈（What they say）

```
用户主动告诉你的信息。

收集方式：
- 产品内反馈按钮
- 微信/社群交流
- 用户访谈
- 问卷调查
- 应用商店评价
```

### 1.3 间接反馈（What they imply）

```
用户没有直接说，但通过行为暗示的信息。

示例：
- 用户反复修改输入才生成 → 输入表单设计不好
- 用户生成后没有复制 → 文案质量不达标
- 用户只用一种风格 → 其他风格不实用
- 用户在深夜使用 → 可能是下班后的个人时间
```

## 二、产品内反馈收集

### 2.1 轻量级反馈组件

```tsx
// src/components/Feedback.tsx
'use client';

import { useState } from 'react';

interface FeedbackProps {
  generationId: string;
}

export function Feedback({ generationId }: FeedbackProps) {
  const [submitted, setSubmitted] = useState(false);
  const [rating, setRating] = useState<number | null>(null);
  const [comment, setComment] = useState('');

  const handleRating = async (value: number) => {
    setRating(value);

    // 评分不需要确认，直接提交
    await fetch('/api/feedback', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        generationId,
        rating: value,
        type: 'quick',
      }),
    });

    setSubmitted(true);
  };

  const handleSubmitComment = async () => {
    await fetch('/api/feedback', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        generationId,
        rating,
        comment,
        type: 'detailed',
      }),
    });

    setSubmitted(true);
  };

  if (submitted) {
    return (
      <div className="text-center py-4 text-green-600">
        感谢你的反馈！
      </div>
    );
  }

  return (
    <div className="bg-gray-50 rounded-xl p-4">
      <p className="text-sm text-gray-600 mb-3">
        这个文案对你有帮助吗？
      </p>

      {/* 快速评分 */}
      <div className="flex gap-2 mb-4">
        {[1, 2, 3, 4, 5].map((value) => (
          <button
            key={value}
            onClick={() => handleRating(value)}
            className={`w-10 h-10 rounded-full text-sm font-medium transition-colors ${
              rating === value
                ? 'bg-orange-500 text-white'
                : 'bg-white text-gray-700 hover:bg-orange-100'
            }`}
          >
            {value}
          </button>
        ))}
      </div>

      {/* 详细反馈（可选） */}
      {rating !== null && rating <= 3 && (
        <div className="space-y-3">
          <textarea
            value={comment}
            onChange={(e) => setComment(e.target.value)}
            placeholder="请告诉我们哪里可以改进..."
            rows={2}
            className="w-full px-3 py-2 text-sm border border-gray-300 rounded-lg"
          />
          <button
            onClick={handleSubmitComment}
            className="w-full bg-orange-500 text-white py-2 rounded-lg text-sm hover:bg-orange-600"
          >
            提交反馈
          </button>
        </div>
      )}
    </div>
  );
}
```

import { NextRequest, NextResponse } from 'next/server';
import { sql } from '@vercel/postgres';

export async function POST(request: NextRequest) {
  try {
    const body = await request.json();
    const { generationId, rating, comment, type } = body;

    await sql`
      INSERT INTO feedback (generation_id, rating, comment, type)
      VALUES (${generationId}, ${rating}, ${comment || ''}, ${type})
    `;

    return NextResponse.json({ success: true });
  } catch (error) {
    console.error('保存反馈失败:', error);
    return NextResponse.json(
      { error: '提交失败' },
      { status: 500 }
    );
  }
}

## 三、用户访谈

### 3.1 访谈时机

```
MVP 上线后的访谈时间线：

Day 1-3：找 3-5 个早期用户深度访谈
- 目标：了解第一印象、核心功能体验
- 重点：他们理解产品是做什么的吗？用了什么功能？遇到什么问题？

```

## 四、问卷调查

### 4.1 问卷设计原则

```
原则一：简短（5 分钟内完成）
- 最多 10 个问题
- 多用选择题，少用开放题

原则二：具体（不问抽象问题）
❌ "你觉得产品怎么样？"
✅ "你上次使用产品生成文案花了多长时间？"

原则三：中立（不引导答案）
❌ "你是不是觉得 AI 生成的文案很好？"
✅ "你如何评价 AI 生成的文案质量？"
```

### 4.2 MVP 阶段的问卷模板

| # | 类型 | 问题 | 选项 |
|---|------|------|------|
| 1 | 单选 | 你是怎么知道这个产品的？ | 朋友推荐 / 社交媒体 / 搜索 / 其他 |
| 2 | 单选 | 你使用产品的频率是？ | 每天 / 每周2-3次 / 每周1次 / 偶尔 / 只用过一次 |
| 3 | 评分 | AI 生成的文案质量如何？ | 1-5 分 |
| 4 | 单选 | 你通常会直接使用生成的文案吗？ | 直接使用 / 稍作修改 / 大幅修改 / 很少使用 |
| 5 | 多选 | 你最常用的功能是？ | 种草风格 / 促销风格 / 日常风格 / 复制 / 重新生成 |
| 6 | 单选 | 如果每月收费 ¥49，你会继续使用吗？ | 肯定会 / 可能会 / 不确定 / 可能不会 / 肯定不会 |
| 7 | 开放 | 你最希望产品增加什么功能？ | — |
| 8 | 开放 | 你有什么建议或想说的话？ | — |

## 五、从反馈到行动

### 5.1 反馈分类框架

```typescript
interface FeedbackItem {
  content: string;
  source: 'behavior' | 'direct' | 'indirect';
  category: 'bug' | 'ux' | 'feature' | 'quality' | 'pricing';
  frequency: number;  // 多少人提到了
  impact: 'high' | 'medium' | 'low';
  effort: 'high' | 'medium' | 'low';
}

function prioritizeFeedback(items: FeedbackItem[]): FeedbackItem[] {
  // 优先级 = 频率 × 影响 / 实现成本
  const priorityMap = { high: 3, medium: 2, low: 1 };

  return items.sort((a, b) => {
    const scoreA = a.frequency * priorityMap[a.impact] / priorityMap[a.effort];
    const scoreB = b.frequency * priorityMap[b.impact] / priorityMap[b.effort];
    return scoreB - scoreA;
  });
}
```

### 5.2 反馈分析示例

假设收集了以下反馈，按优先级排序：

| 反馈内容 | 来源 | 频率 | 影响 | 成本 | 优先级 |
|---------|------|------|------|------|--------|
| 想要抖音风格的文案 | 直接 | 12 | 中 | 中 | P1 |
| 文案不够像小红书风格 | 直接 | 8 | 高 | 中 | P0 |
| 生成速度有点慢 | 直接 | 6 | 中 | 高 | P2 |
| 复制按钮不明显 | 行为 | 5 | 低 | 低 | P3 |

优先级公式：**频率 × 影响 / 成本**。P0 本周完成，P1 下周，P2 两周内，P3 有空再做。

### 5.3 产品迭代计划

基于反馈分析的迭代优先级：

- **P0（本周）**：优化 Prompt 提升小红书风格准确性 → 文案质量评分从 3.2 提升到 4.0
- **P1（下周）**：新增抖音风格文案 → 覆盖更多使用场景
- **P2（两周内）**：优化生成速度，使用流式输出 → 感知等待时间减少 50%
- **P3（有空再做）**：优化复制按钮位置 → 提升复制率

## 六、建立持续反馈机制

### 6.1 反馈飞轮

```
用户使用 → 自动收集行为数据 → 定期触发反馈问卷 → 分析反馈识别模式 → 制定迭代计划 → 开发发布改进 → 通知反馈用户 → 用户更满意 → 循环
```

### 6.2 反馈收集自动化

| 触发条件 | 动作 | 原因 |
|---------|------|------|
| 用户生成了第 5 次文案 | 弹出简短问卷 | 已足够了解产品，可给有价值反馈 |
| 用户连续 3 天使用 | 发送微信消息感谢并询问 | 高粘性用户，值得深度沟通 |
| 用户 7 天没有登录 | 发送邮件询问原因 | 流失预警，了解为什么不来了 |
| 用户提交了负面评分 | 立即显示详细反馈表单 | 负面体验需要立即捕获细节 |

## 七、反馈的常见陷阱

### 陷阱一：只听"声音最大"的用户

```
问题：最积极给你反馈的用户可能不代表大多数用户
解决：结合行为数据分析，不要只依赖口头反馈
```

### 陷阱二：把所有反馈都当需求

```
问题：用户说"我想要 X 功能"，你就做 X
解决：深挖背后的动机——用户真正想解决的问题是什么？
```

### 陷阱三：忽视沉默的大多数

```
问题：只有 10% 的用户会主动反馈
解决：通过行为数据了解另外 90% 用户的使用情况
```

### 陷阱四：反馈分析后不行动

```
问题：收集了很多反馈，分析了，但没有落实到开发
解决：每次收集反馈后，制定明确的迭代计划，设定完成时间
```

## 常见误区

### 误区一：过早收集大量反馈

MVP 阶段不需要几百份问卷。5-10 个深度用户的反馈比 100 个浅层反馈更有价值。

### 误区二：只收集不分析

收集反馈只是第一步。更重要的是分析反馈背后的模式，找到共性问题。

### 误区三：忽视行为数据

用户说的和做的可能不一样。有人说"我很喜欢这个产品"，但行为数据显示他们只用了一次就再也没来。

### 误区四：反馈收集影响用户体验

不要用弹窗、全屏问卷等方式打断用户。反馈收集应该是轻量级的、非侵入式的。

## 工程建议

### 1. 从 Day 1 就开始收集数据

在 MVP 代码中就加入基础的埋点和反馈收集。不要等"以后再加"。

### 2. 用现有工具降低开发成本

```
行为分析：Vercel Analytics、Mixpanel、Amplitude
问卷：Typeform、腾讯问卷
反馈收集：Canny、Featurebase
用户沟通：微信、Discord、Telegram
```

### 3. 建立反馈看板

用 Notion、飞书多维表格或简单的 Excel，建立一个反馈看板，记录每条反馈的来源、内容、分类、优先级和处理状态。

### 4. 定期回顾反馈

每周花 1 小时回顾收集到的反馈，更新优先级，调整迭代计划。不要让反馈"石沉大海"。

## 小结

- 反馈收集三个层次：行为数据、直接反馈、间接反馈
- 行为数据比口头反馈更真实，要从 Day 1 就开始收集
- 产品内反馈组件要轻量级，不打断用户体验
- 反馈分析用"频率 × 影响 / 成本"排序优先级
- 建立反馈飞轮：收集 → 分析 → 行动 → 通知 → 循环

## 练习

1. **埋点实现**：在你的 MVP 中实现基础的行为埋点，记录：生成次数、复制次数、重新生成次数。

2. **反馈组件**：在你的 MVP 中添加一个轻量级的反馈收集组件，支持评分和简短评论。

3. **用户访谈**：找 3 个使用过你 MVP 的用户，进行 15 分钟的访谈。用本课的访谈问题模板，记录并分析访谈结果。

4. **反馈分析**：整理你收集到的所有反馈（行为数据 + 访谈 + 问卷），用反馈分类框架排序优先级，制定一个 2 周的迭代计划。

## 参考答案

### 练习一：埋点实现

**思路**：在前端的关键交互点调用埋点函数，记录用户的生成、复制、重新生成行为。用一个简单的 API Route 接收埋点数据，存到数据库中。MVP 阶段不需要用第三方分析工具，自己实现最简单。

**答案**：

```typescript
// src/lib/tracking.ts - 埋点工具函数
export function track(event: string, properties: Record<string, any> = {}) {
  // 用 sendBeacon 保证页面关闭时也能发送
  const data = JSON.stringify({
    event,
    properties,
    timestamp: Date.now(),
    url: window.location.href,
  });

  if (navigator.sendBeacon) {
    navigator.sendBeacon('/api/track', data);
  } else {
    fetch('/api/track', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: data,
    });
  }
}
```

```typescript
// src/app/api/track/route.ts - 埋点 API
import { NextRequest, NextResponse } from 'next/server';
import { sql } from '@vercel/postgres';

export async function POST(request: NextRequest) {
  try {
    const body = await request.json();
    const { event, properties, timestamp, url } = body;

    await sql`
      INSERT INTO events (event_name, properties, timestamp, url)
      VALUES (${event}, ${JSON.stringify(properties)}, ${new Date(timestamp).toISOString()}, ${url || ''})
    `;

    return NextResponse.json({ success: true });
  } catch (error) {
    console.error('埋点保存失败:', error);
    return NextResponse.json({ error: '保存失败' }, { status: 500 });
  }
}
```

```sql
-- 埋点数据表
CREATE TABLE events (
  id SERIAL PRIMARY KEY,
  event_name VARCHAR(50) NOT NULL,
  properties JSONB,
  timestamp TIMESTAMP NOT NULL,
  url TEXT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 创建索引，方便按事件名查询
CREATE INDEX idx_events_name ON events(event_name);
CREATE INDEX idx_events_timestamp ON events(timestamp);
```

```tsx
// 在页面中使用埋点
import { track } from '@/lib/tracking';

// 生成文案时
const handleGenerate = async () => {
  track('generate_start', { dishName, style });
  // ... 调用 API
  track('generate_complete', { dishName, style, success: true });
};

// 复制文案时
const handleCopy = () => {
  track('copy', { dishName, style });
  navigator.clipboard.writeText(result);
};

// 重新生成时
const handleRegenerate = () => {
  track('regenerate', { dishName, style });
  handleGenerate();
};
```

```typescript
// 查询埋点数据的 SQL
-- 今日生成次数
SELECT COUNT(*) FROM events WHERE event_name = 'generate_complete' AND DATE(timestamp) = CURRENT_DATE;

-- 复制率 = 复制次数 / 生成次数
SELECT
  (SELECT COUNT(*) FROM events WHERE event_name = 'copy')::float /
  (SELECT COUNT(*) FROM events WHERE event_name = 'generate_complete') AS copy_rate;

-- 重新生成率
SELECT
  (SELECT COUNT(*) FROM events WHERE event_name = 'regenerate')::float /
  (SELECT COUNT(*) FROM events WHERE event_name = 'generate_complete') AS regenerate_rate;
```

**要点**：
- 用 `navigator.sendBeacon` 而不是 `fetch`，保证页面关闭时数据也能发送
- 埋点数据表要加索引，否则查询会很慢
- 只埋 3 个核心事件：generate、copy、regenerate，不要贪多
- 埋点代码要在 MVP 开发时就加，不要等"以后再加"

### 练习二：反馈组件

export function Feedback({ generationId }: FeedbackProps) {
  const [submitted, setSubmitted] = useState(false);
  const [rating, setRating] = useState<number | null>(null);
  const [comment, setComment] = useState('');

  const handleRating = async (value: number) => {
    setRating(value);
    await fetch('/api/feedback', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ generationId, rating: value, type: 'quick' }),
    });
    // 4-5 分直接显示感谢，不需要文本反馈
    if (value >= 4) setSubmitted(true);
  };

  const handleSubmitComment = async () => {
    await fetch('/api/feedback', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ generationId, rating, comment, type: 'detailed' }),
    });
    setSubmitted(true);
  };

  if (submitted) {
    return <p className="text-center py-3 text-sm text-green-600">感谢你的反馈！</p>;
  }

  return (
    <div className="bg-gray-50 rounded-xl p-4 mt-4">
      <p className="text-sm text-gray-600 mb-2">这个文案对你有帮助吗？</p>
      <div className="flex gap-2 mb-3">
        {[1, 2, 3, 4, 5].map((value) => (
          <button
            key={value}
            onClick={() => handleRating(value)}
            className={`w-9 h-9 rounded-full text-sm font-medium transition-colors ${
              rating === value
                ? 'bg-orange-500 text-white'
                : 'bg-white text-gray-700 hover:bg-orange-100 border'
            }`}
          >
            {value}
          </button>
        ))}
      </div>
      {rating !== null && rating <= 3 && (
        <div className="space-y-2">
          <textarea
            value={comment}
            onChange={(e) => setComment(e.target.value)}
            placeholder="请告诉我们哪里可以改进..."
            rows={2}
            className="w-full px-3 py-2 text-sm border rounded-lg"
          />
          <button
            onClick={handleSubmitComment}
            className="w-full bg-orange-500 text-white py-2 rounded-lg text-sm hover:bg-orange-600"
          >
            提交反馈
          </button>
        </div>
      )}
    </div>
  );
}

import { NextRequest, NextResponse } from 'next/server';
import { sql } from '@vercel/postgres';

export async function POST(request: NextRequest) {
  try {
    const { generationId, rating, comment, type } = await request.json();
    await sql`
      INSERT INTO feedback (generation_id, rating, comment, type)
      VALUES (${generationId}, ${rating}, ${comment || ''}, ${type})
    `;
    return NextResponse.json({ success: true });
  } catch (error) {
    console.error('保存反馈失败:', error);
    return NextResponse.json({ error: '提交失败' }, { status: 500 });
  }
}

### 练习四：反馈分析

**思路**：用"频率 × 影响 / 成本"公式对所有反馈排序，识别 P0（本周做）、P1（下周做）、P2（两周内）、P3（有空再做）。然后制定一个 2 周的迭代计划，每周有明确的交付物。

**答案**：

```markdown
## 反馈分析与迭代计划

### 反馈汇总

| # | 反馈内容 | 来源 | 频率 | 影响 | 成本 | 优先级 |
|---|---------|------|------|------|------|--------|
| 1 | 文案太长，小红书有字数限制 | 访谈 | 3 | 高 | 低 | P0 |
| 2 | 文案太"营销"，不像真人写的 | 访谈+评分 | 4 | 高 | 中 | P0 |
| 3 | 想要抖音风格的文案 | 访谈 | 2 | 中 | 中 | P1 |
| 4 | 复制按钮不明显 | 行为数据 | 3 | 低 | 低 | P2 |
| 5 | 生成速度有点慢 | 访谈 | 2 | 中 | 高 | P2 |
| 6 | 想要菜品分类模板 | 访谈 | 1 | 中 | 高 | P3 |

### 优先级计算

```
优先级 = 频率 × 影响 / 成本
影响：高=3, 中=2, 低=1
成本：高=3, 中=2, 低=1

#1: 3 × 3 / 1 = 9.0 → P0
#2: 4 × 3 / 2 = 6.0 → P0
#3: 2 × 2 / 2 = 2.0 → P1
#4: 3 × 1 / 1 = 3.0 → P2
#5: 2 × 2 / 3 = 1.3 → P2
#6: 1 × 2 / 3 = 0.7 → P3
```

### 2 周迭代计划

#### Week 1：提升文案质量
**目标**：文案质量评分从 3.2 提升到 4.0

| 任务 | 优先级 | 预计时间 | 交付物 |
|------|--------|---------|--------|
| 优化 Prompt，限制文案在 200 字以内 | P0 | 2 小时 | 更新后的 Prompt |
| 优化 Prompt，让文案更自然、更像真人 | P0 | 4 小时 | A/B 测试对比 |
| 优化复制按钮位置和样式 | P2 | 1 小时 | UI 更新 |

**验收标准**：
- 文案平均长度 < 200 字
- 用户反馈评分 ≥ 4.0
- 复制率提升 20%

#### Week 2：扩展功能
**目标**：新增抖音风格，覆盖更多场景

| 任务 | 优先级 | 预计时间 | 交付物 |
|------|--------|---------|--------|
| 新增抖音风格文案生成 | P1 | 4 小时 | 新风格选项 |
| 新增朋友圈风格文案生成 | P1 | 2 小时 | 新风格选项 |
| 使用流式输出优化生成速度 | P2 | 4 小时 | 流式输出功能 |

**验收标准**：
- 抖音风格文案可用
- 用户可以流式看到生成过程
- 生成感知等待时间减少 50%

### 反馈追踪

| 反馈 | 状态 | 预计完成 | 通知用户 |
|------|------|---------|---------|
| #1 文案太长 | 进行中 | Week 1 | U1, U3 |
| #2 太营销 | 进行中 | Week 1 | U1, U2, U3 |
| #3 抖音风格 | 计划中 | Week 2 | U3 |
| #4 复制按钮 | 计划中 | Week 1 | — |
| #5 生成速度 | 计划中 | Week 2 | U1 |
| #6 菜品分类 | 待定 | — | U3 |
```

**要点**：
- 反馈排序公式：频率 × 影响 / 成本，不是"谁声音大做谁的"
- P0 本周必须完成，P1 下周，P2 两周内，P3 有空再做
- 每周要有明确的交付物和验收标准
- 改进后要通知提出反馈的用户，这是反馈飞轮的关键一环
