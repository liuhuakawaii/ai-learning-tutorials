# 快速验证：不写代码就知道方向对不对

你写好了产品简报，对"AI 餐饮营销助手"充满信心。但心里有个声音：万一用户不买账怎么办？三个月开发、几万块投入——方向错了全白费。

好消息：你不需要写一行代码就能验证大部分核心假设。Landing Page、用户预售、假门测试——这些方法在 1 周内告诉你用户到底愿不愿意掏钱。

## 验证的本质

验证不是"确认你的想法是对的"，而是**尽早发现你的想法哪里错了**。

产品简报里写的所有东西都是假设，不是事实：

```typescript
// 这些全是假设
const assumptions = {
  problem: "餐饮老板有营销内容生成的需求",       // 假设 1
  willingness: "用户愿意为此付费",               // 假设 2
  aiCapability: "AI 能可靠地完成核心任务",       // 假设 3
  differentiation: "用户会选你而不是竞品",       // 假设 4
};
```

验证的目的就是把这些假设变成事实——或者推翻它们。越早推翻，代价越小。

## 三种验证方法

### 方法一：Landing Page 测试

**适用场景**：验证"用户是否有兴趣"

做一个产品介绍页面，看有多少人留下邮箱或点"预约体验"。

```typescript
// Landing Page 核心要素
const landingPage = {
  headline: "30 秒生成餐饮营销文案",           // 一句话说清价值
  subheadline: "小红书 + 抖音 + 朋友圈一键搞定", // 补充说明
  cta: "免费体验",                              // 行动按钮
  socialProof: "已有 200+ 餐饮老板使用",         // 社会证明（可以是假的先测）
  emailCapture: true,                           // 收集邮箱
};
```

**成功标准**：5% 以上的访客留下邮箱。低于 2% 说明方向有问题。

**成本**：¥100 以内（域名 + 托管），1 天搭建。

**局限**：留邮箱不等于付费。Landing Page 只能验证兴趣，不能验证付费意愿。

### 方法二：预售测试

**适用场景**：验证"用户是否愿意付费"

直接告诉用户价格，看有多少人真的掏钱。

```typescript
// 预售页面要素
const presalePage = {
  product: "AI 餐饮营销文案生成器",
  price: "¥69/月",
  offer: "前 100 名用户终身 ¥29/月",
  paymentMethod: "微信/支付宝扫码",
  guarantee: "7 天无理由退款",
};
```

**成功标准**：10 个体验过的人中，至少 2 个愿意付费。

**成本**：¥0（手动交付）。

**关键**：预售是最强的验证信号。用户愿意掏钱说明痛点真实存在。但要注意：朋友的支持不算数，要找陌生人。

### 方法三：假门测试（Wizard of Oz）

**适用场景**：验证"AI 能否完成核心任务"

不写代码，手动用 ChatGPT 模拟产品功能，看用户反馈。

```
用户输入菜品信息
    ↓
你手动调用 ChatGPT API 生成文案
    ↓
你手动把结果发给用户
    ↓
用户以为是"产品"生成的
    ↓
收集用户反馈：质量如何？愿意付费吗？
```

**成功标准**：60% 以上的用户认为"可以直接用或小幅修改后可用"。

**成本**：¥50（API 调用费），2-3 天。

**关键**：假门测试验证的是 AI 能力匹配度。如果手动用 ChatGPT 都生成不出好文案，你写的代码更不行。

## 设计验证实验

```typescript
interface ValidationExperiment {
  hypothesis: string;        // 要验证的假设
  method: "landing_page" | "presale" | "wizard_of_oz";
  metric: string;            // 衡量指标
  threshold: string;         // 成功阈值
  timeRequired: string;
  costRequired: string;
}

const experiments: ValidationExperiment[] = [
  {
    hypothesis: "餐饮老板对 AI 营销文案有兴趣",
    method: "landing_page",
    metric: "邮箱注册率",
    threshold: "> 5%",
    timeRequired: "1 天搭建 + 3 天投放",
    costRequired: "¥100",
  },
  {
    hypothesis: "用户愿意为 AI 营销文案付费",
    method: "presale",
    metric: "付费转化率",
    threshold: "> 20%（体验过的用户）",
    timeRequired: "1 周",
    costRequired: "¥0",
  },
  {
    hypothesis: "AI 能生成质量可用的营销文案",
    method: "wizard_of_oz",
    metric: "用户满意度",
    threshold: "> 60% 认为可直接使用",
    timeRequired: "2 天",
    costRequired: "¥50",
  },
];
```

## 验证结果的决策框架

```typescript
type Decision = "继续开发" | "调整方向" | "放弃";

function makeDecision(results: {
  landingPageConversion: number;  // Landing Page 转化率
  presaleConversion: number;      // 预售转化率
  aiSatisfaction: number;         // AI 输出满意度
}): Decision {
  // 核心假设都通过 → 继续
  if (results.landingPageConversion > 0.05 &&
      results.presaleConversion > 0.2 &&
      results.aiSatisfaction > 0.6) {
    return "继续开发";
  }

  // AI 能力不足 → 调整方向（换场景或等模型升级）
  if (results.aiSatisfaction < 0.4) {
    return "调整方向";
  }

  // 用户不感兴趣 → 放弃或大改
  if (results.landingPageConversion < 0.02 && results.presaleConversion < 0.05) {
    return "放弃";
  }

  // 部分通过 → 调整后重新验证
  return "调整方向";
}
```

## 常见的验证错误

**找朋友验证**。朋友会客气，陌生人不会。找目标用户和行业人士更有效。

**只验证"好不好用"，不验证"愿不愿意付钱"**。免费用都说好，一收费人都没了。

**验证时间太长**。给自己 1 周时间盒。超时还在"思考"，说明你在回避决策。

**成功标准定得太低**。"有 3 个人说不错"不算验证通过。数字要提前定好，避免事后自我说服。

## 练习

### 练习一：设计验证实验

为你上一课产出的产品简报，设计 3 个验证实验（Landing Page、预售、假门测试各一个）。要求：
- 每个实验有明确的假设、方法、成功标准
- 成功标准用具体数字，不用"还不错""很多"
- 写出 `ValidationExperiment` 数组

### 练习二：执行假门测试

用 ChatGPT 或 Claude 手动模拟你的产品核心功能，给 3 个目标用户试用。记录：
- 用户的输入是什么
- AI 的输出是什么
- 用户的反馈是什么
- 用户是否愿意付费

把结果整理成表格。
