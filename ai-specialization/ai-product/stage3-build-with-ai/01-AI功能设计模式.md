# AI 功能设计模式：Copilot、Autonomous、Chat 选哪个

你准备给产品加 AI 功能，打开竞品一看——有的是对话框让用户提问，有的是侧边栏自动给建议，有的完全不需要用户操作就在后台处理。你开始纠结：我的产品该用哪种交互形态？

选错了，要么用户觉得多余，要么觉得难用。答案不在技术层面，在设计模式层面。

## 三种模式

### Copilot 模式：AI 在旁边帮忙

用户在做主要工作，AI 在侧边栏提供辅助建议。用户保留完全的控制权。

```
适用场景：
- 代码编辑器中的 AI 补全（Copilot）
- 文档写作中的 AI 建议（Notion AI）
- 设计工具中的 AI 推荐（Figma AI）

核心特征：
- 用户主导，AI 辅助
- AI 的建议可以接受或忽略
- 不打断用户的工作流
```

### Autonomous 模式：AI 自己干活

用户只设定目标和约束，AI 自主完成全部工作。用户不需要参与过程。

```
适用场景：
- 邮件自动分类和回复建议
- 数据报表自动生成
- 代码审查自动标注问题

核心特征：
- AI 主导，用户审核结果
- 适合重复性高、规则明确的任务
- 需要可靠的兜底机制
```

### Chat 模式：用户和 AI 对话

用户通过自然语言对话获取信息或完成任务。

```
适用场景：
- 客服问答系统
- 知识库查询
- 复杂任务的多轮交互

核心特征：
- 最灵活，但也最不可控
- 用户需要学习如何提问
- 适合探索性任务
```

## 选型决策树

```typescript
function selectPattern(task: {
  frequency: "high" | "low";        // 使用频率
  complexity: "simple" | "complex";  // 任务复杂度
  userControl: "high" | "low";      // 用户需要多少控制权
}): "copilot" | "autonomous" | "chat" {
  // 高频 + 简单 + 用户要控制 → Copilot
  if (task.frequency === "high" && task.complexity === "simple" && task.userControl === "high") {
    return "copilot";
  }

  // 高频 + 简单 + 用户不在意控制 → Autonomous
  if (task.frequency === "high" && task.complexity === "simple" && task.userControl === "low") {
    return "autonomous";
  }

  // 低频 + 复杂 → Chat（需要多轮交互理解需求）
  if (task.frequency === "low" && task.complexity === "complex") {
    return "chat";
  }

  // 其他情况默认 Copilot（最安全的选择）
  return "copilot";
}
```

## 混合模式

实际产品中，三种模式经常混合使用。比如一个电商工具：

```
商品上架流程：
1. 用户上传商品照片
2. Autonomous 模式：AI 自动识别商品类别、提取特征
3. Copilot 模式：AI 建议标题和卖点，用户修改确认
4. Chat 模式：用户对不满意的部分用对话方式让 AI 重写
```

不要被"选一种"限制住。关键是每个环节用最合适的模式。

## 设计陷阱

**为了用 AI 而用 AI**。用户根本不需要 AI 辅助的功能，你硬加一个 AI 按钮，用户不点。

**过度自动化**。把本该用户决策的环节交给 AI 自动处理，用户失去控制感。

**Chat 模式滥用**。不是所有功能都适合对话交互。"帮我把这个表格的第三列改成大写"——用按钮比用对话高效 10 倍。

**忽视退出机制**。AI 建议不对时，用户怎么回到手动模式？没有退出机制的 AI 功能是单向门，用户一旦不满意就会离开。

## 参考答案

### 练习一

| 场景 | 模式 | 理由 |
|------|------|------|
| 合同审查 | Copilot | 律师需要逐条确认 AI 标注的风险点，不能自动处理 |
| 商品描述生成 | Autonomous + Chat | 初稿自动生成，不满意用对话调整 |
| 代码补全 | Copilot | 程序员在写代码，AI 在旁边建议，用户 Tab 接受或忽略 |
| 客服回复建议 | Copilot | 客服人员审核后发送，不能自动回复 |
| 数据查询 | Chat | 自然语言问问题比写 SQL 直觉，但需要多轮澄清 |
