# 阶段实战：核心 AI 功能开发

你已经学完了 AI 功能设计模式、多模型接入、RAG、Agent 工作流和输出质量保障。现在把这些串起来——为你的产品实现完整的 AI 核心功能。

这不是学新知识，是把知识变成可运行的产品。

## 整体架构

以"AI 商品详情页生成"为例，核心功能链路：

```
用户上传商品照片 + 填写基础信息
    ↓
AI 自动识别商品类别（Autonomous）
    ↓
从知识库检索同品类优秀文案作为参考（RAG）
    ↓
LLM 生成多平台文案初稿
    ↓
质量检查：敏感词、虚假宣传、格式规范
    ↓
用户审核修改（Copilot 模式）
    ↓
输出最终文案
```

```typescript
// 核心接口定义
interface GenerateRequest {
  productImages: string[];      // 商品图片 URL
  productName: string;
  price: number;
  category: string;
  platforms: ("taobao" | "douyin" | "pdd")[];
  style?: "professional" | "casual" | "luxury";
}

interface GenerateResult {
  platform: string;
  title: string;
  description: string;
  sellingPoints: string[];
  qualityScore: number;        // 质量评分
  warnings: string[];          // 质量问题警告
}
```

## 核心功能实现

```typescript
import { OpenAI } from "openai";

const openai = new OpenAI();

async function generateProductCopy(req: GenerateRequest): Promise<GenerateResult[]> {
  const results: GenerateResult[] = [];

  // 1. RAG：检索同品类优秀文案作为参考
  const references = await retrieveReferences(req.category, req.style);

  // 2. 为每个平台生成文案
  for (const platform of req.platforms) {
    const prompt = buildPrompt(req, platform, references);
    const response = await openai.chat.completions.create({
      model: "gpt-4",
      messages: [
        { role: "system", content: SYSTEM_PROMPT },
        { role: "user", content: prompt },
      ],
      temperature: 0.7,
    });

    const raw = parseResponse(response.choices[0].message.content);

    // 3. 质量检查
    const quality = checkQuality(raw, req);

    results.push({
      platform,
      title: raw.title,
      description: raw.description,
      sellingPoints: raw.sellingPoints,
      qualityScore: quality.score,
      warnings: quality.warnings,
    });
  }

  return results;
}

// RAG 检索同品类参考文案
async function retrieveReferences(category: string, style?: string) {
  const query = `${category} ${style || ""} 商品文案`;
  const embedding = await createEmbedding(query);
  const results = await vectorStore.similaritySearch(embedding, { topK: 3 });
  return results.map((r) => r.content);
}

// 质量检查
function checkQuality(copy: any, req: GenerateRequest) {
  const warnings: string[] = [];
  let score = 100;

  // 检查虚假宣传
  const bannedWords = ["最好", "第一", "绝对", "100%"];
  for (const word of bannedWords) {
    if (copy.description.includes(word)) {
      warnings.push(`包含绝对化用语"${word}"，可能违反广告法`);
      score -= 10;
    }
  }

  // 检查价格一致性
  if (copy.description.includes("¥") && !copy.description.includes(String(req.price))) {
    warnings.push("文案中的价格与实际价格不一致");
    score -= 20;
  }

  // 检查长度
  if (copy.description.length < 50) {
    warnings.push("文案过短，可能不够详细");
    score -= 10;
  }

  return { score: Math.max(0, score), warnings };
}
```

## 接入监控

AI 功能上线后必须监控的指标：

```typescript
interface AIMetrics {
  // 性能
  latencyMs: number;           // 生成延迟
  tokenUsage: number;          // Token 消耗

  // 质量
  qualityScore: number;        // 质量检查分数
  warningCount: number;        // 警告数量

  // 用户行为
  regenerationRate: number;    // 重新生成率（越高说明质量越差）
  editRate: number;            // 编辑率（用户修改了多少）
  copyRate: number;            // 复制率（直接使用的比例）
}

function logMetrics(metrics: AIMetrics) {
  // 发送到监控系统
  console.log(JSON.stringify({
    timestamp: new Date().toISOString(),
    ...metrics,
  }));
}
```

关键指标解读：
- **重新生成率 > 30%**：AI 输出质量需要优化
- **编辑率 > 50%**：AI 生成的内容和用户期望差距大
- **复制率 < 20%**：产品核心价值未被认可

## 练习

### 练习一：实现核心链路

为你选定的产品，实现从用户输入到 AI 输出的完整链路。要求：
- 有明确的接口定义（Request/Response 类型）
- 有 RAG 检索（用向量数据库或简单的相似度匹配）
- 有质量检查（至少检查 3 种问题）
- 有错误处理（API 调用失败时有兜底方案）

### 练习二：接入监控

在核心链路中接入监控，记录：
- 每次调用的延迟和 token 消耗
- 质量检查的结果
- 用户行为（重新生成、编辑、复制）

把监控数据写入日志文件或数据库。

### 练习三：端到端测试

写一个端到端测试，覆盖：
- 正常输入 → 正常输出
- 异常输入（空值、超长、特殊字符）→ 合理的错误提示
- API 调用失败 → 兜底方案触发

## 参考答案

### 练习一

核心链路的关键是把每个环节拆成独立函数，方便测试和替换。RAG 检索可以用简单的文本匹配先跑通，后续再换成向量数据库。质量检查要覆盖广告法合规、价格一致性和内容完整性。

### 练习二

监控数据建议用结构化日志（JSON 格式），方便后续用 ELK 或 PostHog 分析。不要只记录"成功/失败"，要记录具体的 qualityScore 和 warningCount，这样才能定位质量问题。

### 练习三

端到端测试要覆盖边界情况。AI 产品最容易出问题的不是正常输入，而是边缘输入：用户上传了非商品图片、输入了 emoji 作为商品名、要求生成 1000 字的文案等。
