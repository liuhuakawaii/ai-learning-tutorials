# 毕业项目：AI 产品从想法到上线

## 项目概述

完成一个 AI 产品的完整上线流程：从需求定义、原型设计、技术实现、测试验证到部署发布。产品必须是可实际使用的，不是 demo 或概念验证。

## 技术栈

根据产品类型自行选择，但需要覆盖：

- **前端**：React / Vue / Next.js 等
- **后端**：Node.js / Python / Go 等
- **AI 能力**：LLM API / 模型推理 / RAG 等
- **部署**：Docker + 云服务（Vercel / Railway / 阿里云等）
- **监控**：基础日志 + 错误追踪

## 核心功能

### 1. 产品定义文档

必须输出以下文档：

- **需求文档**：目标用户、核心痛点、解决方案假设
- **竞品分析**：至少 3 个竞品的优劣势对比
- **MVP 范围**：明确哪些做、哪些不做、为什么
- **成功指标**：可量化的北极星指标 + 护栏指标

### 2. 产品原型

- 线框图或高保真原型（Figma / 手绘均可）
- 核心用户流程图（至少 3 条关键路径）
- 异常流程处理（输入错误、服务不可用、超时）

### 3. 技术实现

MVP 必须包含的功能：

- 核心 AI 功能可正常工作
- 用户注册/登录（可用第三方如 Clerk、Auth.js）
- 数据持久化（数据库）
- 基础错误处理和降级方案
- 响应式设计（至少支持桌面和移动端）

### 4. AI 工程化

- Prompt 版本管理（不是硬编码在代码里）
- 输出质量评估（人工打分或自动评估）
- 成本控制（Token 用量监控、缓存策略）
- 失败处理（模型超时、返回异常的降级方案）

### 5. 测试与质量

- 核心功能的手动测试用例
- AI 输出的回归测试集（至少 20 个 case）
- 性能基线：首屏时间、API 响应时间
- 安全检查：输入验证、API Key 保护

### 6. 部署与监控

- 线上环境可访问（有真实 URL）
- 环境变量管理（不在代码中暴露密钥）
- 基础监控：错误日志、请求量、响应时间
- 用户反馈入口（表单或反馈按钮）

### 7. 上线复盘

- 技术决策复盘：为什么选这个方案
- 遇到的主要问题及解决方式
- 如果重新做，会改什么
- 下一步迭代计划

## 推荐产品方向

选一个方向深入，不要同时做多个：

| 方向 | 示例 |
|------|------|
| AI 写作助手 | 针对特定场景（如周报、邮件、文案） |
| 知识库问答 | 上传文档 → 对话式问答 |
| 数据分析助手 | 自然语言查数据库 |
| AI 翻译/改写 | 特定领域（法律、医学、技术） |
| 图像处理工具 | 背景移除、风格转换、批量处理 |
| 代码辅助 | Review、重构建议、文档生成 |
| 客服机器人 | 基于知识库的自动回复 |

## 验收标准

```bash
cd ai-specialization/ai-product/final-project
python scripts/check.py
```

验证项：

- [ ] 产品文档完整（需求、竞品、MVP 范围、指标）
- [ ] 原型或线框图存在
- [ ] 核心 AI 功能可正常运行
- [ ] 用户注册/登录可用
- [ ] 数据持久化正常
- [ ] 线上环境可访问
- [ ] Prompt 版本管理到位
- [ ] AI 输出评估用例 >= 20 个
- [ ] 上线复盘文档完成

## 开发周期

| 阶段 | 时间 | 目标 |
|------|------|------|
| 阶段 1 | 第 1 周 | 需求定义 + 竞品分析 + 原型 |
| 阶段 2 | 第 2 周 | 核心 AI 功能 + 后端 API |
| 阶段 3 | 第 3 周 | 前端 + 用户系统 + 数据库 |
| 阶段 4 | 第 4 周 | 测试 + 部署 + 监控 + 复盘 |
