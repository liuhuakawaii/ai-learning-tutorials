# 第五课：商业模式设计

## 场景引入

你的 AI 产品有了明确的方向和差异化定位，用户也开始试用了。然后问题来了：怎么赚钱？免费让用户用？按月收费？按使用量收费？免费增值？你看到竞品有的卖 ¥99/月，有的卖 ¥0.1/次调用，有的干脆免费靠融资活着。你应该怎么定价？

商业模式不是"做完产品再想"的事情，它应该在产品设计阶段就确定。因为定价策略会直接影响产品功能的设计、目标用户的选择、甚至技术架构的决策。这一课，你会学到 AI 产品常见的变现模式，以及如何选择适合你的模式。

## 学习目标

1. 了解 AI 产品常见的六种变现模式
2. 掌握定价策略的核心原则
3. 学会计算单位经济模型（Unit Economics）
4. 能够为自己的产品选择合适的商业模式

## 一、AI 产品的六种变现模式

### 1.1 订阅制（Subscription）

```
模式：用户按月/年付费，获得固定额度或无限制使用
典型：ChatGPT Plus（$20/月）、Jasper（$49/月）

适用场景：
✅ 用户高频使用（每周至少 2-3 次）
✅ 产品有持续价值（不是一次性的）
✅ 能形成使用习惯

不适用场景：
❌ 用户低频使用（每月才用一次）
❌ 一次性需求（如写一份简历）
❌ 用户对价格敏感且有免费替代品
```

### 1.2 按量计费（Usage-based）

```
模式：按实际使用量收费（API 调用次数、生成字数、处理文件数）
典型：OpenAI API、AWS、Google Cloud

适用场景：
✅ 用户使用量波动大
✅ 用户对成本敏感，想"用多少付多少"
✅ 产品是 API 或嵌入式服务

不适用场景：
❌ 用户无法预估使用量（会害怕"账单爆了"）
❌ 使用量与价值不成正比
❌ 需要稳定收入来覆盖固定成本
```

```typescript
// 按量计费定价模型
interface UsagePricing {
  metric: string;        // 计费指标
  freeQuota: number;     // 免费额度
  unitPrice: number;     // 单价
  unit: string;          // 单位
  tiers?: PriceTier[];   // 阶梯定价
}

interface PriceTier {
  upTo: number;
  pricePerUnit: number;
}

const usagePricing: UsagePricing = {
  metric: "AI 生成字数",
  freeQuota: 10000,
  unitPrice: 0.02,
  unit: "千字",
  tiers: [
    { upTo: 100000, pricePerUnit: 0.02 },    // 0-10万字：¥0.02/千字
    { upTo: 500000, pricePerUnit: 0.015 },   // 10-50万字：¥0.015/千字
    { upTo: Infinity, pricePerUnit: 0.01 }   // 50万字+：¥0.01/千字
  ]
};

// 计算月费
function calculateMonthlyCost(usage: number, pricing: UsagePricing): number {
  let cost = 0;
  let remaining = usage - pricing.freeQuota;

  if (remaining <= 0) return 0;

  for (const tier of pricing.tiers) {
    const tierUsage = Math.min(remaining, tier.upTo);
    cost += tierUsage * tier.pricePerUnit;
    remaining -= tierUsage;
    if (remaining <= 0) break;
  }

  return cost;
}
```

### 1.3 免费增值（Freemium）

```
模式：基础功能免费，高级功能付费
典型：Notion、Canva、Spotify

适用场景：
✅ 需要快速获取大量用户
✅ 产品有网络效应（用户越多越有价值）
✅ 免费用户能转化为付费用户（转化率通常 2-5%）

不适用场景：
❌ 每个用户都有显著的服务成本（AI API 调用费）
❌ 免费版已经能满足大部分用户需求
❌ 目标市场太小，需要每个用户都付费
```

### 1.4 按效果付费（Outcome-based）

```
模式：按 AI 带来的具体效果收费
典型：广告平台（按点击付费）、销售 AI（按成交付费）

适用场景：
✅ 效果可量化（点击、转化、节省的时间）
✅ 用户愿意为结果付费而非工具本身
✅ AI 的效果可以归因

不适用场景：
❌ 效果难以量化或归因
❌ 效果取决于太多非 AI 因素
❌ 用户可能"白嫖"效果后不付费
```

### 1.5 一次性付费（One-time）

```
模式：单次购买，永久使用（或按次付费）
典型：AI 头像生成（$9.99/次）、AI 论文降重（¥50/篇）

适用场景：
✅ 一次性需求（生成简历、修图、写特定文档）
✅ 单次价值高且明确
✅ 不需要持续更新或维护

不适用场景：
❌ 需要持续使用的产品
❌ 需要持续投入 AI 成本
❌ 用户期望持续更新
```

### 1.6 企业定制（Enterprise）

```
模式：为大企业定制解决方案，按项目或年付费
典型：企业级 RAG 系统、行业 AI 解决方案

适用场景：
✅ 目标客户是大企业
✅ 需要深度定制和集成
✅ 客单价高（¥10 万+/年）

不适用场景：
❌ 团队没有企业销售能力
❌ 产品标准化程度高，不需要定制
❌ 目标客户是个人或小企业
```

## 二、定价策略的核心原则

### 2.1 基于价值定价，不基于成本

```
错误思路：AI API 调用成本 ¥0.1/次 → 加价 50% → 定价 ¥0.15/次
正确思路：用户通过 AI 节省了 2 小时 → 时薪 ¥200 → 价值 ¥400 → 定价 ¥99/月

成本定价的问题：
- 你的利润被 API 成本锁死
- 竞品可能拿到更低的 API 价格
- 忽略了用户感知的价值

价值定价的优势：
- 利润空间更大
- 与用户价值绑定
- 有降价空间应对竞争
```

### 2.2 定价锚定

```typescript
// 利用价格锚定效应
const pricingPsychology = {
  // 方法一：三档定价，中间档是目标
  tiers: [

    { name: "企业版", price: 299, purpose: "锚定高价，让专业版显得便宜" }

    monthly: 99,  // 月付 ¥99

    // 年付的好处：锁定用户 + 改善现金流
  },

  // 方法三：对比参照物
  referencePoints: [
    "雇一个兼职文案：¥3000/月",
    "买一个营销课程：¥1999",
    "你的产品：¥99/月"
    // 让用户觉得 ¥99 是"便宜的"
  ]
};
```

### 2.3 预留提价空间

```
上线初期：定价偏低，快速获取用户
用户增长后：逐步提价，新用户新价格，老用户保持原价
功能增加后：推出更高档位

不要一开始就定太低，因为：
1. 提价比降价难得多
2. 太低的价格会让用户怀疑产品质量
3. 低价吸引的用户往往忠诚度最低
```

## 三、单位经济模型（Unit Economics）

### 3.1 核心指标

```typescript
interface UnitEconomics {
  // 收入端
  arpu: number;           // Average Revenue Per User（每用户平均收入）
  ltv: number;            // Lifetime Value（用户生命周期价值）

  // 成本端
  cac: number;            // Customer Acquisition Cost（获客成本）
  cogs: number;           // Cost of Goods Sold（服务成本，主要是 AI API 费）

  // 关键比率
  ltvCacRatio: number;    // LTV / CAC（应 > 3）
  grossMargin: number;    // 毛利率 = (ARPU - COGS) / ARPU
  paybackPeriod: number;  // CAC 回收周期（月）
}

function calculateUnitEconomics(
  monthlyRevenue: number,
  monthlyAICost: number,
  monthlyChurnRate: number,
  cac: number
): UnitEconomics {
  const arpu = monthlyRevenue;
  const cogs = monthlyAICost;
  const grossMargin = (arpu - cogs) / arpu;

  // LTV = ARPU / 月流失率
  const ltv = arpu / monthlyChurnRate;

  // LTV/CAC 比率
  const ltvCacRatio = ltv / cac;

  // CAC 回收周期
  const paybackPeriod = cac / (arpu - cogs);

  return { arpu, ltv, cac, cogs, ltvCacRatio, grossMargin, paybackPeriod };
}

// 示例计算
const example = calculateUnitEconomics(
  99,   // 月收入 ¥99
  15,   // AI API 成本 ¥15/月
  0.05, // 月流失率 5%（用户平均留存 20 个月）
  300   // 获客成本 ¥300
);
// LTV = 99 / 0.05 = ¥1980
// LTV/CAC = 1980 / 300 = 6.6 ✅（> 3 健康）
// 毛利率 = (99 - 15) / 99 = 84.9% ✅
// CAC 回收周期 = 300 / (99 - 15) = 3.6 个月 ✅
```

### 3.2 AI 产品的成本结构

```
AI 产品典型成本结构：

固定成本：
├── 服务器和基础设施：¥2,000-10,000/月
├── 团队人力：最大成本项
├── 第三方 SaaS 工具：¥1,000-5,000/月
└── 域名和基础服务：¥500/月

变动成本（与用户量相关）：
├── AI API 调用费：¥0.01-0.1/次（最大变动成本）
├── 数据库存储：¥0.5/GB/月
├── CDN 和带宽：按量计费
└── 客服支持：按工单数

关键：AI API 调用费是 AI 产品特有的成本项，
也是影响毛利率的最大因素。
```

### 3.3 盈亏平衡分析

```typescript
interface BreakEvenAnalysis {
  fixedCosts: number;      // 月固定成本
  pricePerUser: number;    // 每用户月收入
  costPerUser: number;     // 每用户月成本（AI API）
  breakEvenUsers: number;  // 盈亏平衡所需用户数
}

function calculateBreakEven(
  fixedCosts: number,
  pricePerUser: number,
  costPerUser: number
): BreakEvenAnalysis {
  const contributionMargin = pricePerUser - costPerUser;
  const breakEvenUsers = Math.ceil(fixedCosts / contributionMargin);

  return {
    fixedCosts,
    pricePerUser,
    costPerUser,
    breakEvenUsers
  };
}

// 示例：一个 AI 写作工具
const aiWritingTool = calculateBreakEven(
  20000,  // 月固定成本 ¥20,000（服务器 + 部分人力）
  99,     // 每用户月收入 ¥99
  15      // 每用户 AI 成本 ¥15
);
// 盈亏平衡 = 20000 / (99 - 15) = 239 个付费用户
```

## 四、选择适合你的商业模式

### 4.1 决策矩阵

```typescript
interface BusinessModelFit {
  model: string;
  fitScore: number;  // 0-10
  reasons: string[];
}

function evaluateModels(context: {
  userType: 'consumer' | 'smb' | 'enterprise';
  usageFrequency: 'daily' | 'weekly' | 'monthly' | 'rare';
  valueProp: 'time_saving' | 'quality_improvement' | 'capability_extension';
  marketSize: 'large' | 'medium' | 'small';
}): BusinessModelFit[] {
  const models: BusinessModelFit[] = [];

  // 订阅制适合高频、持续价值
  if (context.usageFrequency === 'daily' || context.usageFrequency === 'weekly') {
    models.push({
      model: "订阅制",
      fitScore: 8,
      reasons: ["高频使用支撑月费", "可预测的收入流"]
    });
  }

  // 按量计费适合波动大、API 型
  if (context.userType === 'enterprise' && context.usageFrequency === 'monthly') {
    models.push({
      model: "按量计费",
      fitScore: 7,
      reasons: ["企业可按需使用", "降低采购门槛"]
    });
  }

  // 免费增值适合大市场、网络效应
  if (context.marketSize === 'large') {
    models.push({
      model: "免费增值",
      fitScore: 8,
      reasons: ["大市场需要快速获客", "免费用户也有传播价值"]
    });
  }

  // 一次性付费适合一次性需求
  if (context.usageFrequency === 'rare') {
    models.push({
      model: "一次性付费",
      fitScore: 7,
      reasons: ["用户不愿为低频使用付月费"]
    });
  }

  return models.sort((a, b) => b.fitScore - a.fitScore);
}
```

### 4.2 混合模式

很多成功的 AI 产品采用混合模式：

```
免费版（获客）+ 订阅制（主要收入）+ 按量加购（增量收入）

示例：
- 免费版：5,000 字/月
- 专业版 ¥99/月：100,000 字/月
- 超出额度：¥0.02/千字（按量加购）
- 企业版：定制价格 + 专属支持

这样既降低了入门门槛，又有稳定的订阅收入，
还能通过按量计费覆盖重度用户的成本。
```

## 五、避免常见的定价陷阱

### 陷阱一：定价太低

```
症状：用户增长快但收入增长慢，无法覆盖成本
原因：害怕定价太高没人买，或用成本法定价
解决：基于价值定价，用 A/B 测试找到最优价格点
```

### 陷阱二：免费版太慷慨

```
症状：大量免费用户，极少转化成付费用户
原因：免费版已经满足了大部分用户需求
解决：限制免费版的使用量或功能，创造升级动力
```

### 陷阱三：忽视 AI 成本

```
症状：收入看着不错，但毛利率很低
原因：没有把 AI API 调用成本算清楚
解决：精确计算每用户的 AI 成本，确保毛利率 > 70%
```

### 陷阱四：定价结构太复杂

```
症状：用户看不懂定价页，转化率低
原因：太多档位、太多限制条件
解决：简化为 3 档，每档的核心差异一目了然
```

## 常见误区

### 误区一：照搬竞品定价

竞品的定价是基于他们的成本结构、目标用户和市场策略。你的产品和他们不同，定价也应该不同。

### 误区二：只看收入不看利润

月收入 ¥100,000 看起来不错，但如果 AI API 成本就占了 ¥70,000，毛利率只有 30%，这个生意很难持续。

### 误区三：定价一成不变

定价应该随着产品价值的提升、用户基数的增长、市场竞争的变化而调整。每 3-6 个月审视一次定价策略。

### 误区四：忽视支付意愿测试

"我觉得用户愿意付 ¥99"——你需要验证。最简单的方法是做 A/B 测试：一半用户看到 ¥79，一半看到 ¥99，看转化率差异。

## 工程建议

### 1. 先算清 AI 成本

在确定定价之前，精确计算每个用户每月的 AI API 调用成本。用真实数据测试，不要用理想情况估算。

### 2. 设计灵活的定价架构

代码层面要支持灵活的定价调整：套餐变更、额度修改、价格测试。不要把定价逻辑硬编码到业务代码中。

```typescript
// 定价配置应该外置，方便调整
interface PricingConfig {
  plans: PlanConfig[];
  overage: OverageConfig;
  trials: TrialConfig;
}

// 不要把价格写死在代码里
// const PRICE = 99; ❌
// 应该从配置或数据库读取 ✅
```

### 3. 监控关键指标

上线后持续监控：免费转付费率、月度流失率、ARPU、毛利率。这些指标会告诉你定价是否合理。

### 4. 为价格测试留出空间

实现 A/B 测试框架，支持不同用户看到不同的定价方案。用数据驱动定价决策。

## 小结

- AI 产品六种变现模式：订阅制、按量计费、免费增值、按效果付费、一次性付费、企业定制
- 基于价值定价，不基于成本；用参照物锚定价格
- 单位经济模型的核心：LTV/CAC > 3，毛利率 > 70%，CAC 回收 < 12 个月
- AI API 调用费是 AI 产品特有的成本项，必须精确计算
- 定价要持续测试和调整，不要一成不变

### 练习一：模式选择练习

**思路**：以"AI 自动生成营销文案"产品为例，用决策矩阵评估六种变现模式。

**答案**：

**决策矩阵**（1-10 分，评估维度：用户接受度、收入可预测性、实施难度）：

| 模式 | 用户接受度 | 收入可预测性 | 实施难度 | 总分 |
|------|-----------|-------------|----------|------|
| 订阅制 | 8 | 9 | 3 | 20 |
| 按量计费 | 7 | 5 | 5 | 17 |
| 免费增值 | 9 | 4 | 6 | 19 |
| 按效果付费 | 6 | 3 | 9 | 18 |
| 一次性付费 | 5 | 2 | 2 | 9 |
| 企业定制 | 3 | 7 | 9 | 19 |

**Top 2 选择**：
1. **订阅制**：收入可预测性强，用户习惯已形成（SaaS 订阅已成主流），适合标准化产品
2. **免费增值**：用户获取门槛低，适合早期冲量，通过免费版培养使用习惯后转化为付费用户

**要点**：
- 选择变现模式要考虑产品成熟度：早期用免费增值获客，成熟期转向订阅制
- 按效果付费听起来公平但实施复杂度极高，不建议早期使用
- B2C 优先免费增值，B2B 优先订阅制

### 练习二：定价方案设计

**思路**：用三档定价原则设计价格方案，确保中间档是主推档。

**答案**（以"AI 营销文案生成器"为例）：

| | 免费版 | 专业版（主推） | 企业版 |
|--|--------|--------------|--------|
| **价格** | ¥0/月 | ¥99/月 | ¥499/月 |
| **生成次数** | 20 次/月 | 500 次/月 | 无限 |
| **模板数量** | 5 个基础模板 | 50+ 行业模板 | 全部模板 + 自定义 |
| **多平台适配** | 仅微信 | 微信 + 小红书 + 抖音 | 全平台 + API |
| **品牌语调** | 不支持 | 支持自定义 | 多品牌管理 |
| **数据报告** | 无 | 基础报告 | 高级分析 + 导出 |
| **客服** | 社区 | 邮件 48h | 专属客服 |

**设计逻辑**：
- 免费版让用户体验核心功能，20 次/月足够感受到价值
- 专业版 ¥99/月定位在"比请一个兼职文案便宜 10 倍"
- 企业版 ¥499/月作为价格锚点，让专业版显得性价比高

**要点**：
- 三档定价的核心是"中间档是你想卖的"
- 免费版要有明确的限制（次数/功能），让用户自然感受到升级的必要
- 定价要找到参照物（"比 X 便宜"比"只要 Y 元"更有说服力）

### 练习三：单位经济计算

**思路**：逐项估算关键指标，验证商业模式是否健康。

**答案**（以"AI 营销文案生成器"专业版为例）：

**基础假设**：
- ARPU（月均每用户收入）：¥99
- AI API 成本/用户/月：¥15（按平均 200 次调用，每次 ¥0.075）
- 服务器 + 运维成本/用户/月：¥5
- 月流失率：5%
- 获客成本（CAC）：¥300

**计算**：

| 指标 | 计算过程 | 结果 | 健康标准 | 是否达标 |
|------|----------|------|----------|----------|
| 毛利率 | (99-15-5)/99 | 79.8% | >70% | ✅ |
| 用户生命周期 | 1/5% | 20 个月 | - | - |
| LTV | 99 × 20 | ¥1,980 | - | - |
| LTV/CAC | 1,980/300 | 6.6 | >3 | ✅ |
| CAC 回收周期 | 300/99 | 3 个月 | <12 个月 | ✅ |

**结论**：所有核心指标达标，商业模式健康。主要风险是月流失率，如果升到 10%，LTV/CAC 会降到 3.3，接近危险线。

**要点**：
- AI API 成本是 AI 产品特有的成本项，必须精确估算
- LTV/CAC > 3 是行业共识，但早期可以适当放宽
- 月流失率是杠杆最大的指标，每降低 1% 都能显著提升 LTV

### 练习四：竞品定价分析

**思路**：分析 3 个 AI 写作工具的定价页，提炼定价策略和可借鉴之处。

**答案**：

**竞品定价分析**：

**竞品 A：Jasper**
- 定价策略：三档定价（Creator $49/月、Pro $69/月、Business 联系销售）
- 价格锚定：Business 档作为锚点，让 Pro 显得合理
- 免费版限制：7 天免费试用，功能全开放但有时限
- 值得借鉴：用"限时全功能试用"让用户充分体验后再做决定

**竞品 B：Copy.ai**
- 定价策略：免费增值 + 两档付费（Pro $49/月、Enterprise 联系销售）
- 价格锚定：Enterprise 作为锚点
- 免费版限制：每月 2,000 字生成额度，无模板自定义
- 值得借鉴：用"字数限制"而非"功能限制"作为免费版边界，让用户先养成使用习惯

**竞品 C：Writesonic**
- 定价策略：按量计费 + 订阅制混合（按 credits 计费）
- 价格锚定：显示"每 credit 仅 ¥0.X"
- 免费版限制：每月 10,000 credits，部分高级功能锁定
- 值得借鉴：credits 机制让用户感知"用得越多越划算"，促进升级

**共同规律**：
1. 都有免费入口降低获客门槛
2. 都用最高档作为价格锚定
3. 都通过"使用量"而非"功能"驱动升级

**要点**：
- 定价页是产品的"第二首页"，值得花时间研究
- 关注免费版的限制方式，这决定了用户何时感受到付费的必要性
- 混合模式（订阅 + 按量）适合 AI 产品，兼顾收入稳定性和用量弹性
