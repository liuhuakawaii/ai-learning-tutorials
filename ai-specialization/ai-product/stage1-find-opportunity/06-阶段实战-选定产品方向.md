# 阶段实战：选定产品方向

前面五课你学了产品思维、需求发现、能力评估、竞品分析和商业模式。现在要把这些串起来，确定你要做的 AI 产品方向。

很多人在这一步卡住：想了十个方向，每个都"还行"，但没有一个让你觉得"就是它了"。这节课给你一个结构化的决策流程，从"一堆想法"收敛到"一个方向"，产出一份产品简报。

## 从十个想法到一个方向

### 第一步：列出所有想法

不要过早筛选。花 30 分钟写出所有能想到的 AI 产品方向，至少 10 个。

### 第二步：三维评分

对每个想法做三维评分（1-5 分）：

```typescript
interface IdeaScore {
  name: string;
  painLevel: number;        // 痛点强度：用户有多痛？
  aiFit: number;            // AI 适配度：AI 能可靠解决吗？
  marketOpportunity: number; // 市场机会：竞争、规模、时机
  dealbreakers: string[];   // 一票否决项
}

function totalScore(idea: IdeaScore): number {
  // 痛点权重最高，因为没痛点的产品活不下去
  return idea.painLevel * 0.4 + idea.aiFit * 0.3 + idea.marketOpportunity * 0.3;
}

const ideas: IdeaScore[] = [
  {
    name: "AI 餐饮营销助手",
    painLevel: 4, aiFit: 4, marketOpportunity: 4,
    dealbreakers: [],
  },
  {
    name: "AI 法律文书生成",
    painLevel: 5, aiFit: 2, marketOpportunity: 3,
    dealbreakers: ["AI 可靠性不足，法律文书出错后果严重"],
  },
  {
    name: "AI 会议纪要助手",
    painLevel: 3, aiFit: 4, marketOpportunity: 3,
    dealbreakers: ["飞书/钉钉已内置此功能"],
  },
];

// 排序后：餐饮营销助手 > 会议纪要助手 > 法律文书生成
// 法律文书被 dealbreaker 一票否决
```

### 第三步：深度评估 Top 3

对排名前三的想法做用户访谈和竞品调研：

```typescript
interface DeepEvaluation {
  ideaName: string;
  // 用户验证：找 5-10 个目标用户聊
  userInterviews: {
    count: number;
    painConfirmed: number;   // 确认痛点的人数
    wouldPay: number;        // 愿意付费的人数
  };
  // 竞品：直接和间接竞品都看
  competitors: {
    direct: string[];
    hasUnderservedNiche: boolean;
    differentiator: string;
  };
  // AI 能力：实际跑一遍核心任务
  aiCapability: {
    coreTask: string;
    reliability: "high" | "medium" | "low";
    worstCase: string;
  };
}
```

### 第四步：用决策问题做最终选择

四个问题帮你检验信心：

1. 如果这个产品失败了，你会后悔尝试吗？（好答案：不会，过程中学到的东西值得）
2. 你愿意为它每天工作 12 小时，持续 6 个月吗？
3. 你身边有没有至少 3 个人愿意成为第一批用户？
4. 核心价值能在 30 秒内说清楚吗？（"我帮餐饮老板 30 秒生成 3 个平台的营销文案"）

## 产品简报模板

做出决策后，用这个模板产出产品简报：

```markdown
# 产品简报：[产品名称]

## 一句话定位
为 [目标用户] 提供 [核心价值]，帮助他们 [解决什么问题]。

## 问题定义
- 目标用户画像：[行业、规模、角色]
- 核心痛点：[一句话]
- 现有方案：[用户现在怎么做]
- 痛点评分：频次 X/5 × 强度 X/5 × 支付意愿 X/5
- 用户访谈摘要：X 人确认痛点，Y 人愿意付费

## 解决方案
- 核心功能（不超过 3 个）：每个明确 AI 做什么、人做什么
- 用户流程：1→2→3→4

## 竞争分析
- 竞品矩阵（AI 质量、体验、集成、性价比、深度）
- 差异化：一句话说清为什么用户选你

## 商业模式
- 免费版限制、付费版定价
- 单位经济：ARPU、AI 成本、毛利率、LTV/CAC

## 风险与缓解
| 风险 | 概率 | 影响 | 缓解方案 |
|------|------|------|---------|

## 第一步计划（2 周内）
- 验证目标和成功标准
```

## 可逆决策 vs 不可逆决策

```typescript
const decisions = [
  { desc: "选择产品方向", reversible: true, cost: "2-4 周", approach: "快速验证，不行就换" },
  { desc: "选择技术栈", reversible: true, cost: "1-2 周重构", approach: "选最熟悉的" },
  { desc: "确定定价", reversible: true, cost: "可能流失部分用户", approach: "先测一个价格" },
  { desc: "辞职 all in", reversible: false, cost: "极高", approach: "先验证再决定" },

// 原则：可逆决策快速做，不可逆决策谨慎做
```

## 产品简报 Review 清单

提交前检查：

- 目标用户是否具体？（不是"所有人"）
- 痛点是否用用户语言描述？（不是技术术语）
- 核心功能是否不超过 3 个？
- 每个功能是否明确了 AI 和人的角色？
- 差异化点是否可验证、可感知？
- 定价是否基于价值而非成本？
- 是否识别了 Top 3 风险？
- 是否有 dealbreaker 级别的风险？

## 练习

### 练习一：三维评分

对你在上一课练习中列出的 5 个想法做三维评分，选出 Top 1。评分要有依据，不能拍脑袋——每个分数都写一句理由。

### 练习二：产品简报

为 Top 1 写一份完整的产品简报。要求：
- 让一个不了解这个领域的人能在 5 分钟内理解你的产品
- 风险部分要坦诚，不要回避

### 练习三：验证计划

为产品简报中的核心假设，设计一个 1 周内可以完成的最小验证方案。包括：验证什么、怎么验证、成功标准是什么。

要求用代码形式写出 `ValidationPlan` 数组，并实际执行其中至少一项。

## 参考答案

### 练习一

以"AI 商品详情页生成"为例的评分过程：

```typescript
const scored: IdeaScore = {
  name: "AI 商品详情页生成",
  painLevel: 4,  // 电商卖家每天要上架多个商品，写文案是最头疼的环节
  aiFit: 4,      // 文本生成是 LLM 强项，结构化输入→文案输出流程清晰
  marketOpportunity: 4, // 中国有千万级电商卖家，客单价低但量大
  dealbreakers: [],
};
// 总分 = 4×0.4 + 4×0.3 + 4×0.3 = 4.0
```

要点：乘法比加法更能拉开差距。如果三个维度都是 3 分，加法得 9 分看起来还行，但乘法只有 27 分（满分 125），差距一目了然。

### 练习二

产品简报的关键是让不了解领域的人也能快速理解。避免技术术语，用用户语言描述痛点。风险部分要坦诚——评审者最怕看到"没有风险"的产品。

### 练习三

验证的核心是"付费意愿"，不是"东西好不好用"。手动交付（Wizard of Oz）是不写代码验证的最佳方式：先用 ChatGPT 手动生成文案，给真实用户试用，观察他们的反应和付费意愿。成功标准要在验证前就定好，避免事后自我说服。
