# 第六课：阶段实战 — 选定产品方向

## 场景引入

前面五课，你学了产品思维、需求发现、能力评估、竞品分析和商业模式。现在是时候把这些知识串起来，确定你要做的 AI 产品方向了。这一课不是"纸上谈兵"，你需要产出一份完整的**产品简报**——它将成为后续所有课程的基础。

很多人在这一步卡住：想了十个方向，每个都觉得"还行"，但没有一个让你觉得"就是它了"。这一课会给你一个结构化的决策流程，帮你从"一堆想法"收敛到"一个方向"。

## 学习目标

1. 掌握从想法到产品方向的结构化决策流程
2. 产出一份完整的产品简报文档
3. 学会用"不可逆决策"和"可逆决策"的框架评估风险
4. 为后续的验证和 MVP 阶段做好准备

### 1.2 第二步：用三维评分快速筛选

对每个想法做三维评分（1-5 分）：

```typescript
interface IdeaScore {
  id: number;
  name: string;
  scores: {
    painLevel: number;       // 痛点强度：用户有多痛？
    aiFit: number;           // AI 适配度：AI 能可靠地解决吗？
    marketOpportunity: number; // 市场机会：竞争、规模、时机
  };
  totalScore: number;
  dealbreakers: string[];   // 一票否决项
}

function scoreIdea(idea: IdeaScore): IdeaScore {
  // 总分 = 痛点 × 40% + AI 适配 × 30% + 市场机会 × 30%
  idea.totalScore =
    idea.scores.painLevel * 0.4 +
    idea.scores.aiFit * 0.3 +
    idea.scores.marketOpportunity * 0.3;
  return idea;
}

// 评分示例
const scoredIdeas: IdeaScore[] = [
  {
    id: 1,
    name: "AI 餐饮营销助手",
    scores: { painLevel: 4, aiFit: 4, marketOpportunity: 4 },
    totalScore: 0,
    dealbreakers: []
  },
  {
    id: 4,
    name: "AI 法律文书生成",
    scores: { painLevel: 5, aiFit: 2, marketOpportunity: 3 },
    totalScore: 0,
    dealbreakers: ["AI 可靠性不足，法律文书出错后果严重"]
  },
  {
    id: 7,
    name: "AI 会议纪要助手",
    scores: { painLevel: 3, aiFit: 4, marketOpportunity: 3 },
    totalScore: 0,
    dealbreakers: ["飞书/钉钉已内置此功能，独立产品难存活"]
  }
].map(scoreIdea);

// 排序后：餐饮营销助手 > 会议纪要助手 > 法律文书生成
// 法律文书被 dealbreaker 一票否决
```

## 二、产品简报模板

做出决策后，用以下模板产出产品简报：

```markdown
# 产品简报：[产品名称]

## 一句话定位
为 [目标用户] 提供 [核心价值]，帮助他们 [解决什么问题]。

## 1. 问题定义
### 目标用户
- **画像**：[具体描述，包括行业、规模、角色]
- **核心痛点**：[一句话描述]
- **现有解决方案**：[用户现在怎么做的]
- **痛点评分**：频次 X/5 × 强度 X/5 × 支付意愿 X/5

### 用户访谈摘要
- 访谈人数：X 人
- 确认痛点：X/Y 人
- 愿意付费：X 人
- 关键发现：[最重要的 1-2 个发现]

## 2. 解决方案
### 核心功能
- **功能 1**：[描述] — AI 完成什么，人完成什么
- **功能 2**：[描述] — AI 完成什么，人完成什么
- **功能 3**：[描述] — AI 完成什么，人完成什么

### AI 能力评估
| 任务 | AI 可靠度 | 风险 | 策略 |
|------|----------|------|------|
| 任务 1 | 高 | 低 | 全自动 |
| 任务 2 | 中 | 中 | AI + 人确认 |

### 用户流程
1. 用户 [做什么]
2. AI [做什么]
3. 用户 [做什么]
4. 输出 [什么结果]

## 3. 竞争分析
### 竞品矩阵
| 竞品 | AI 质量 | 体验 | 集成 | 性价比 | 深度 |
|------|--------|------|------|--------|------|
| 竞品A | 4 | 4 | 5 | 2 | 2 |
| 竞品B | 3 | 4 | 3 | 3 | 2 |

### 差异化定位
- **一句话差异**：[为什么用户选你而不是竞品]
- **差异化策略**：垂直深耕 / 工作流集成 / 体验差异化 / 定价差异化
- **壁垒**：短期 [X]，中期 [Y]，长期 [Z]

## 4. 商业模式
### 收入模式
- 免费版：[限制]
- 付费版：¥X/月 [功能]
- 增量收入：[按量/增值服务]

### 单位经济
- 预估 ARPU：¥X/月
- 预估 AI 成本：¥Y/用户/月
- 预估毛利率：Z%
- 预估获客成本：¥W
- LTV/CAC：X

### 市场规模
- 目标用户数：X
- 年市场规模：¥Y

## 5. 风险与缓解
| 风险 | 概率 | 影响 | 缓解方案 |
|------|------|------|---------|
| AI 质量不达标 | 中 | 高 | 设计人工兜底方案 |
| 竞品快速跟进 | 高 | 中 | 聚焦垂直场景建立壁垒 |
| 获客成本过高 | 中 | 中 | 先用内容营销降低 CAC |

## 6. 第一步计划
### 验证目标（2 周内）
- [ ] 完成 X 人用户访谈
- [ ] 做 Landing Page 测试，收集 Y 个邮箱
- [ ] 用 AI API 做核心功能的 PoC

### 成功标准
- 访谈中 X% 的人确认痛点
- Landing Page 转化率 > Y%
- AI 在核心任务上的可靠度 > Z%
```

## 四、实战：产出你的产品简报

### 4.1 工作流程

```
第 1 天：
├── 上午：头脑风暴，列出 10+ 个产品想法
├── 下午：三维评分，筛选出 Top 3
└── 晚上：对 Top 3 做竞品初步调研

第 2 天：
├── 上午：对 Top 3 做 AI 能力评估
├── 下午：用决策问题做最终选择
└── 晚上：开始写产品简报

第 3 天：
├── 上午：完成产品简报的 1-3 节
├── 下午：完成产品简报的 4-6 节
└── 晚上：找 2-3 个人 review 产品简报

第 4-5 天：
├── 快速验证（Landing Page + 用户访谈）
└── 根据验证结果调整产品简报
```

## 五、从产品简报到下一步

产品简报完成后，下一步是什么？

```
产品简报（你在这里）
    ↓
阶段二：验证与 MVP
    ├── 01-快速验证方法：用 Landing Page 和访谈验证核心假设
    ├── 02-MVP 设计原则：砍掉 80% 功能，只做核心价值
    ├── 03-技术选型决策：选择合适的技术栈
    ├── 04-48 小时 MVP 搭建：快速做出可用的原型
    ├── 05-用户反馈收集：获取早期用户的真实反馈
    └── 06-阶段实战-MVP 上线：部署上线，获取第一批用户
```

产品简报不是一个"完美"的文档，它会随着验证和迭代不断更新。重要的是：你有了一个明确的方向，可以开始行动了。

## 常见误区

### 误区一：追求"完美"的产品方向

不存在完美的产品方向。每个方向都有风险和不确定性。重要的是选择一个方向，快速验证，不行就调整。犹豫不决比选错方向更浪费时间。

### 误区二：过早 all in

在产品方向还没有验证之前，不要辞职、不要投入大量资金。先用业余时间验证，等有了初步的用户反馈和数据支撑后再加大投入。

### 误区三：跳过验证直接开发

"我觉得这个方向肯定行"——然后花三个月开发，上线后发现没人用。验证的成本远低于开发的成本。先验证，再开发。

### 误区四：产品简报写完就束之高阁

产品简报是活文档，应该随着你的认知更新而更新。每次用户访谈、每次竞品分析、每次验证结果，都应该反映到产品简报中。

## 工程建议

### 1. 用 Git 管理产品简报

把产品简报放在 Git 仓库中，每次更新都 commit。这样你可以看到产品方向是如何演进的，也方便团队协作。

### 2. 设定明确的验证时间盒

不要无限期地"思考"。给自己一个明确的截止日期（比如 2 周），在截止日期前完成验证并做出决策。

### 3. 找一个"魔鬼代言人"

找一个会挑战你想法的人，让他/她 review 你的产品简报。他们的问题会帮你发现盲点。

### 4. 记录决策过程

不只是记录决策结果，还要记录决策过程：你考虑了哪些选项，为什么选了这个，否决了哪些。这些记录在以后复盘时非常有价值。

## 小结

- 用三维评分（痛点 × AI 适配 × 市场机会）从多个想法中筛选
- 用决策问题检验你对产品方向的热情和信心
- 产品简报是后续所有工作的基础，包含问题、方案、竞争、商业、风险五个维度
- 可逆决策快速做，不可逆决策谨慎做
- 先验证再开发，验证的成本远低于开发的成本

## 练习

1. **产品想法清单**：花 30 分钟头脑风暴，列出至少 10 个你想做的 AI 产品方向。不要过早筛选，尽量多写。

2. **三维评分**：对你列出的 10 个想法，用三维评分模型（痛点 × AI 适配 × 市场机会）打分，选出 Top 3。

3. **产品简报**：为 Top 3 中得分最高的想法，用产品简报模板写一份完整的产品简报。目标是让一个不了解这个领域的人能在 5 分钟内理解你的产品。

4. **验证计划**：为你产品简报中的核心假设，设计一个 1 周内可以完成的最小验证方案。包括：验证什么、怎么验证、成功标准是什么。

5. **Review**：把你的产品简报给 2-3 个人看（最好不是你的朋友），收集他们的反馈。他们理解你的产品吗？他们觉得这个方向有价值吗？他们有什么疑问？

### 练习三：产品简报

**思路**：为 Top 1（商品详情页生成）写一份完整的产品简报。

**答案**：

**产品简报：AI 商品详情页生成器**

**问题**：
- 中小电商卖家需要为每个商品写详情页文案，一个店铺可能有 100+ SKU
- 请专业文案成本高（200-500 元/篇），自己写质量差、耗时长
- 不同平台（淘宝、拼多多、抖音）的风格和格式要求不同，需要反复调整

**方案**：
- 用户上传商品图片 + 简单描述，AI 自动生成多平台适配的详情页文案
- 支持一键生成淘宝、拼多多、抖音三个版本
- 提供多种风格模板（专业测评风、种草风、直播话术风）

**竞争格局**：
- 竞品：有赞 AI 助手、微盟 AI、各类 AI 写作工具
- 差异化：专注电商详情页（非通用写作），多平台一键适配，中小商家定价友好

**商业模型**：
- 免费版：每月 5 篇详情页
- 专业版：¥69/月，100 篇 + 多平台适配
- 目标 LTV/CAC > 3，毛利率 > 75%

**关键风险**：
- AI 生成的文案可能包含虚假宣传，需要人工审核
- 大平台（淘宝）可能自己内置类似功能
- 依赖上游模型能力，成本可能波动

**要点**：
- 产品简报要覆盖问题、方案、竞争、商业、风险五个维度
- 让不了解领域的人也能在 5 分钟内理解
- 风险部分要坦诚，不要回避

### 练习四：验证计划

**思路**：为产品简报中的核心假设设计 1 周验证方案。

**答案**：

**核心假设**：中小电商卖家愿意为 AI 生成的详情页文案付费

**验证方案**：

**Day 1-2：搭建验证载体**
- 用 Figma 做一个产品原型（展示输入→输出的流程）
- 手动用 ChatGPT 生成 5 个真实商品的详情页文案作为"样品"

**Day 3-4：投放测试**
- 在 3 个电商卖家微信群发"免费帮你写详情页文案"的帖子
- 收集 10 个卖家的真实商品信息，手动用 AI 生成文案并交付
- 记录：卖家的反馈、修改意见、是否愿意付费

**Day 5-6：付费验证**
- 对体验过的卖家发问卷："如果这个工具 ¥69/月，你会买吗？"
- 提供限时优惠价 ¥29/月，观察实际转化率

**Day 7：汇总分析**
- 成功标准：
  - >60% 的体验者认为文案"可以直接用或小幅修改后可用"
  - >20% 的体验者愿意付费
  - 收集到 3 个以上的具体改进建议

**要点**：
- 验证的核心是"付费意愿"，不是"这个东西好不好用"
- 手动交付（Wizard of Oz）是不写代码验证的最佳方式
- 成功标准要在验证前就定好，避免事后自我说服

### 练习五：Review

**思路**：模拟产品简报的外部反馈收集过程。

**答案**：

**反馈收集方法**：
- 找 3 个不同背景的人：一个电商卖家、一个产品经理、一个不相关行业的朋友
- 让他们阅读产品简报后回答 3 个问题：
  1. 你能用一句话描述这个产品是做什么的吗？（测试理解度）
  2. 如果你是目标用户，你会用吗？为什么？（测试价值感）
  3. 你最大的疑问或担忧是什么？（发现盲点）

**模拟反馈汇总**：
- 电商卖家："我确实需要，但我担心生成的文案不够'接地气'，每个品类的卖点不一样"
- 产品经理："商业模式清晰，但大平台内置类似功能怎么办？壁垒是什么？"
- 路人朋友："所以就是 AI 帮你写广告？听起来挺方便的"

**反馈处理**：
- 电商卖家的反馈 → 需要做垂直行业适配（服装、食品、3C 的文案风格不同）
- 产品经理的反馈 → 需要思考壁垒策略（数据飞轮 vs 垂直深耕）
- 路人的反馈 → 一句话定位通过，"AI 帮你写广告"可以作为对外宣传语

**要点**：
- 不要只找朋友，朋友会客气；找目标用户和行业人士更有效
- 关注"疑问和担忧"，这比"好评"更有价值
- 反馈要形成行动项，不能只是收集了就完
