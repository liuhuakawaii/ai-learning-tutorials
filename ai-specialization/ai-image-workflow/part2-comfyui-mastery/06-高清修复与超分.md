# 第六课：高清修复与超分 —— 从模糊到清晰的工程方案

## 场景引入

你已经能在 ComfyUI 中生成构图精美的图像了。但当你把生成结果放到产品页面、打印成海报、或者投放到社交媒体时，问题暴露了：

- **电商运营**："生成的模特图在手机上看挺好，放到 PC 端商品详情页就糊了。"
- **设计师**："512×512 的生成图，客户要 A3 尺寸的印刷稿，怎么放大？"
- **短视频团队**："生成的素材要放到 4K 视频里，像素不够怎么办？"

直接用 Stable Diffusion 生成高分辨率图像有两个核心障碍：

1. **显存限制**：生成 2048×2048 的图像需要 24GB+ 显存，消费级显卡跑不动
2. **语义崩塌**：SD 在超过训练分辨率（512/1024）时，会出现重复对象、扭曲五官等问题

本课将系统讲解超分辨率和高清修复的技术方案，从像素空间放大到潜空间放大，从通用超分到面部专项修复，最终构建完整的 ComfyUI 高清修复工作流。

## 学习目标

完成本课后，你将能够：

1. 理解超分辨率模型的核心原理（ESRGAN、Real-ESRGAN、SwinIR）
2. 区分像素空间放大与潜空间放大（Hires Fix）的适用场景
3. 搭建包含面部修复（GFPGAN/CodeFormer）的完整高清工作流
4. 设计批量超分处理流程，计算时间和成本
5. 根据目标用途选择最优的放大策略

## 一、超分辨率基础概念

### 1.1 什么是超分辨率

超分辨率（Super-Resolution, SR）是指从低分辨率图像恢复出高分辨率图像的技术。本质上是一个"信息补全"问题——低分辨率图像丢失的高频细节（纹理、边缘、微小结构），需要被算法"猜测"出来。

```
超分辨率的本质：

  低分辨率 (512×512)          超分辨率算法           高分辨率 (2048×2048)
  ┌─────────────┐                              ┌─────────────────────────┐
  │             │                              │                         │
  │  模糊的细节  │ ──────────────────────────→  │  清晰的细节              │
  │  锯齿边缘    │    恢复/生成高频信息          │  平滑边缘                │
  │  丢失的纹理  │                              │  补全的纹理              │
  │             │                              │                         │
  └─────────────┘                              └─────────────────────────┘
        262,144 像素                                    4,194,304 像素

  关键问题：从 26 万像素到 400 万像素，多出来的 380 万像素从哪来？
  答案：从训练数据中学到的"先验知识"——模型见过足够多的高清图，
       知道"这种纹理放大后应该长什么样"。
```

### 1.2 评估超分质量的指标

| 指标 | 衡量什么 | 特点 |
|------|---------|------|
| PSNR | 像素级差异（峰值信噪比） | 数值越高越好，但不完全反映视觉质量 |
| SSIM | 结构相似性 | 比 PSNR 更接近人眼感知 |
| LPIPS | 感知相似度（深度特征距离） | 最接近人类主观评价 |
| FID | 生成质量分布 | 适合评估整体质量，不适合单图 |

**工程实践中**，最可靠的评估方式是人眼检查 + 下游任务验证（比如超分后的人脸能不能被识别系统正确识别）。

## 二、主流超分模型详解

### 2.1 ESRGAN 系列

ESRGAN（Enhanced Super-Resulution GAN）是超分领域的里程碑模型，其核心创新是 **Residual-in-Residual Dense Block (RRDB)**：

```
ESRGAN 架构：

  低分辨率图像 ──→ 特征提取 ──→ RRDB Blocks (堆叠) ──→ 上采样 ──→ 高分辨率图像
                        │              │
                        │     ┌────────┴────────┐
                        │     │  RRDB Block      │
                        │     │  ┌─────────────┐ │
                        │     │  │ Dense Block  │ │
                        │     │  │ ┌───┐ ┌───┐ │ │
                        │     │  │ │D1 │→│D2 │ │ │
                        │     │  │ └───┘ └───┘ │ │
                        │     │  │    ↓        │ │
                        │     │  │ ┌───┐ ┌───┐ │ │
                        │     │  │ │D3 │→│D4 │ │ │
                        │     │  │ └───┘ └───┘ │ │
                        │     │  └─────────────┘ │
                        │     │  + 残差连接        │
                        │     └──────────────────┘
                        │
                        └──→ 全局残差连接 (跳过整个网络)
```

**RRDB 的设计思想**：通过密集连接让梯度在深层网络中顺畅流动，通过残差连接让网络只学习"需要补充的细节"而不是"从零生成整张图"。

### 2.2 Real-ESRGAN —— 真实世界超分

ESRGAN 的训练数据是"双三次下采样"生成的低分辨率图对，但真实世界的模糊图像要复杂得多——包含噪声、压缩伪影、运动模糊等。Real-ESRGAN 的核心改进是引入 **高阶退化模型**：

```
Real-ESRGAN 的退化模型（训练时的数据增强流程）：

  高清原图 ──→ 模糊 (Blur) ──→ 下采样 (Resize) ──→ 噪声 (Noise)
                                    │                    │
                                    │                    │
                                    ▼                    ▼
                              JPEG 压缩伪影  ←────  再次模糊
                                    │
                                    ▼
                              最终低分辨率输入
                              (模拟真实世界的退化)

  对比 ESRGAN 的简单退化：
  高清原图 ──→ 双三次下采样 ──→ 低分辨率输入
  (过于理想化，真实图片不会这么"干净")
```

Real-ESRGAN 还引入了 **U-Net 判别器**（之前版本用的是 VGG 判别器），能够更好地感知全局结构。

Real-ESRGAN 的常用模型：

| 模型 | 缩放倍数 | 特点 | 适用场景 |
|------|---------|------|---------|
| RealESRGAN_x4plus | 4× | 通用超分 | 照片、插画、设计图 |
| RealESRGAN_x2plus | 2× | 轻量 | 不需要太大放大倍数 |
| RealESRGAN_x4plus_anime_6B | 4× | 动漫优化 | 动漫、插画、扁平设计 |
| realesr-animevideov3 | 4× | 视频优化 | 视频帧超分 |

### 2.3 SwinIR —— Transformer 架构的超分

SwinIR 使用 **Swin Transformer** 作为骨干网络，核心优势是能捕捉长距离依赖关系：

```
CNN (ESRGAN) vs Transformer (SwinIR) 的感受野：

  CNN：                    Transformer：
  ┌───┐                   ┌───────────────────┐
  │ █ │ 感受野 = 3×3       │                   │
  └───┘                   │   全局自注意力      │
  局部特征提取              │   感受野 = 整张图    │
  擅长纹理和边缘            │                   │
                          └───────────────────┘
                           擅长全局结构一致性
```

SwinIR 在保持纹理细节的同时，对大面积平滑区域（天空、墙壁）的处理更加自然，不会出现 ESRGAN 偶尔出现的"纹理溢出"。

### 2.4 如何选择超分模型

```
模型选择决策树：

  你的输入是什么类型的图像？
    │
    ├──→ 真实照片 ──→ Real-ESRGAN x4plus (首选)
    │                 SwinIR (备选，质量更高但更慢)
    │
    ├──→ 动漫/插画 ──→ RealESRGAN_x4plus_anime_6B
    │
    ├──→ 文字/线条图 ──→ 4x-UltraSharp (对锐利边缘效果好)
    │
    └──→ AI 生成图 ──→ 优先用 Hires Fix（潜空间放大）
                       如果已经生成完了，用 Real-ESRGAN 补救
```

## 三、放大策略：像素空间 vs 潜空间

### 3.1 两种放大路径

```
路径一：像素空间放大（后处理）

  SD 生成 512×512 ──→ VAE 解码 ──→ 像素图像 ──→ Real-ESRGAN ──→ 2048×2048
                                              (在像素空间操作)

  优点：不改变生成流程，可以对任意已有图像操作
  缺点：放大倍数有限，4倍以上质量下降明显


路径二：潜空间放大（Hires Fix，生成时）

  SD 生成 512×512 latent ──→ 潜空间放大到 1024×1024 latent
                             ──→ KSampler 继续去噪 ──→ VAE 解码 ──→ 1024×1024

  优点：放大过程由 SD 模型参与，语义一致性好
  缺点：只能在生成时使用，无法用于已有图像
```

### 3.2 Hires Fix 的工作原理

Hires Fix（高清修复）是 SD 社区最常用的放大方案，它的核心思想是：**先在低分辨率生成完整构图，再在高分辨率下补充细节**。

```
Hires Fix 两阶段流程：

  阶段一：基础生成
  ┌─────────────────────────────────────────────────┐
  │  Empty Latent (512×512)                          │
  │     ↓                                            │
  │  KSampler (steps=20, denoise=1.0)               │
  │     ↓                                            │
  │  得到 512×512 的 latent，构图已确定                │
  └─────────────────────────────────────────────────┘
                          │
                          ↓
  阶段二：高清重绘
  ┌─────────────────────────────────────────────────┐
  │  Latent 放大到 1024×1024 (bilinear/bicubic)      │
  │     ↓                                            │
  │  KSampler (steps=15, denoise=0.5)               │
  │     ↓                                            │
  │  得到 1024×1024 的 latent                        │
  │     ↓                                            │
  │  VAE Decode → 高清图像                            │
  └─────────────────────────────────────────────────┘

  关键：阶段二的 denoise 不能太高（<0.7），否则会改变构图
       也不能太低（<0.3），否则细节补充不够
```

**denoise 强度对结果的影响：**

```
denoise = 0.3  →  基本只是平滑放大，细节几乎没有改善
denoise = 0.5  →  适度补充细节，构图基本不变（推荐起点）
denoise = 0.6  →  细节明显改善，构图有轻微变化
denoise = 0.8  →  细节丰富，但构图可能明显改变
denoise = 1.0  →  等于重新生成，构图完全不可控
```

### 3.3 两种策略的结合

实践中，最优方案往往是两者的结合：

```
推荐的高清修复流程：

  SD 生成 (512×512) → Hires Fix (1024×1024) → Real-ESRGAN (4096×4096)
                         潜空间放大              像素空间放大
                      (补充语义一致的细节)       (补充高频纹理)

  为什么结合用：
  - Hires Fix 保证了 1024×1024 的语义一致性（五官不重复、构图不崩）
  - Real-ESRGAN 保证了 4096×4096 的纹理清晰度（毛孔、布料纹理）
  - 单独用任何一个都无法同时满足"语义正确"和"细节清晰"
```

## 四、面部修复专项

### 4.1 为什么需要面部修复

即使使用了 Hires Fix + 超分，AI 生成的人脸在放大后仍然可能出现：

- 五官比例微小偏差（眼睛大小不对称）
- 牙齿区域混乱
- 头发纹理不自然
- 皮肤质感过于光滑或过于粗糙

面部修复模型专门针对这些问题，对人脸区域进行**局部重绘**。

### 4.2 GFPGAN

GFPGAN（Generative Facial Prior GAN）的核心思想是利用预训练的人脸生成模型作为"先验知识"：

```
GFPGAN 工作流程：

  输入人脸 ──→ 人脸检测 ──→ 人脸对齐 ──→ 编码器 ──→ 潜空间特征
                                                         │
                                                         ▼
                                    预训练人脸 GAN 的先验 ←─ 融合
                                    (知道"正常人脸"应该长什么样)
                                                         │
                                                         ▼
                                    解码器 ──→ 修复后的人脸 ──→ 贴回原图
```

GFPGAN 的优势是修复速度快、效果稳定，但在极端模糊（如 8×8 像素的人脸）下效果有限。

### 4.3 CodeFormer

CodeFormer 是 GFPGAN 的升级版，核心创新是使用 **离散码本（Codebook）** 来表示人脸：

```
CodeFormer 的码本机制：

  输入人脸 ──→ 编码器 ──→ 连续特征 ──→ 量化 ──→ 离散码本索引
                                    (查表)
                                        │
                                        ▼
                              码本中存储了大量"标准人脸部件"
                              眼睛、鼻子、嘴巴、脸型的最优表示
                                        │
                                        ▼
                              解码器 ──→ 修复后的人脸
```

**fidelity_weight 参数**是 CodeFormer 的关键控制项：

```
fidelity_weight (保真度权重)：

  0.0  →  完全使用码本中的"标准人脸"，修复质量最高但可能不像原人
  0.5  →  平衡点，修复质量好且保持相似度
  0.7  →  推荐值，修复的同时高度忠实原图
  1.0  →  完全忠实原图，几乎不做修复
```

### 4.4 GFPGAN vs CodeFormer 选择

| 维度 | GFPGAN v1.4 | CodeFormer |
|------|------------|------------|
| 修复质量 | 好 | **更好** |
| 人脸相似度 | 中 | **高**（可调） |
| 处理速度 | **快** | 稍慢 |
| 极端退化 | 中 | **好** |
| 显存占用 | ~2GB | ~3GB |
| 推荐场景 | 快速预览、批量处理 | 最终输出、高质量要求 |

**工程建议：** 批量处理时用 GFPGAN 快速出图，最终精修用 CodeFormer。

## 五、ComfyUI 高清修复工作流

### 5.1 基础 Hires Fix 工作流

```python
# ComfyUI Hires Fix 基础工作流

workflow_hiresfix = {
    # === 阶段一：基础生成 ===
    "checkpoint": load("sd_xl_base_1.0.safetensors"),
    "positive": clip_encode("a portrait of a young woman, natural lighting, 4k uhd"),
    "negative": clip_encode("ugly, blurry, low quality, bad anatomy"),

    # 生成低分辨率 latent
    "base_latent": empty_latent(512, 768),
    "base_result": ksampler(
        model=checkpoint,
        positive=positive,
        negative=negative,
        latent=base_latent,
        steps=25,
        cfg=7.0,
        sampler="dpmpp_2m",
        seed=42
    ),
    # base_result 是 512×768 的 latent

    # === 阶段二：潜空间放大 + 重绘 ===
    # 在潜空间中放大 latent
    "upscaled_latent": latent_upscale(
        samples=base_result,
        width=1024,      # 2倍放大
        height=1536,
        upscale_method="bilinear"  # 双线性插值
    ),

    # 添加微量噪声（可选，有助于补充细节）
    "noisy_latent": latent_noise_inject(
        samples=upscaled_latent,
        noise_amount=0.05  # 微量噪声
    ),

    # 第二次采样：在高分辨率下补充细节
    "hires_result": ksampler(
        model=checkpoint,
        positive=positive,
        negative=negative,
        latent=noisy_latent,
        steps=20,
        cfg=7.0,
        sampler="dpmpp_2m",
        denoise=0.5,     # 关键：控制重绘强度
        start_at_step=10, # 从第 10 步开始（跳过构图阶段）
        seed=42
    ),

    # VAE 解码
    "final_image": vae_decode(hires_result)
}
```

### 5.2 完整高清修复工作流（Hires Fix + 超分 + 面部修复）

```python
# 完整的高清修复 Pipeline

workflow_full_hires = {
    # === 第一步：基础生成 ===
    "base_image": generate_base_image(
        prompt="a business woman giving a presentation, modern conference room",
        negative="blurry, low quality, deformed",
        width=512, height=768,
        steps=25, cfg=7.0
    ),

    # === 第二步：Hires Fix (潜空间 2× 放大) ===
    "hires_image": hires_fix(
        base=base_image,
        upscale_factor=2,        # 512→1024
        denoise=0.5,
        steps=18
    ),
    # 输出：1024×1536

    # === 第三步：Real-ESRGAN (像素空间 4× 放大) ===
    "upscaled_image": real_esrgan_upscale(
        image=hires_image,
        model="RealESRGAN_x4plus",
        scale=4
    ),
    # 输出：4096×6144

    # === 第四步：面部修复 (CodeFormer) ===
    "face_fixed": codeformer_enhance(
        image=upscaled_image,
        fidelity_weight=0.7,    # 保真度
        upscale=1,               # 不再放大，只修复
        face_upscale=True,       # 面部区域额外放大
    ),

    # === 第五步：最终锐化（可选） ===
    "sharpened": image_sharpen(
        image=face_fixed,
        amount=0.3,   # 轻微锐化
        radius=1.0
    )
}
```

### 5.3 放大倍数的选择

```
不同放大倍数的实际效果（从 512×512 开始）：

  2× (1024×1024)
  ├── Hires Fix 直接达到
  ├── 语义一致性最好
  └── 适合：社交媒体、网页展示

  4× (2048×2048)
  ├── Hires Fix 2× + Real-ESRGAN 2×
  ├── 或 Real-ESRGAN 直接 4×
  └── 适合：电商详情页、广告素材

  8× (4096×4096)
  ├── Hires Fix 2× + Real-ESRGAN 4×
  ├── 细节开始出现伪影，需要面部修复
  └── 适合：大幅印刷、户外广告

  16× (8192×8192)
  ├── Hires Fix 2× + Real-ESRGAN 4× + 二次超分 2×
  ├── 质量下降明显，需要人工精修
  └── 适合：高清印刷（配合人工后期）
```

## 六、批量超分处理

### 6.1 批量处理的工程挑战

当需要处理成百上千张图像时，逐张手动操作不现实。ComfyUI 提供了批处理机制：

```python
# 批量超分工作流

workflow_batch = {
    # 1. 读取输入目录的所有图片
    "image_list": load_images_from_directory(
        directory="./input_images/",
        pattern="*.png"
    ),

    # 2. 批量处理循环
    "batch_results": for_each(image_list, lambda img:
        pipeline(
            img,
            real_esrgan_upscale(scale=4),
            codeformer_enhance(fidelity=0.7),
            save_to("./output_images/")
        )
    ),

    # 3. 生成处理报告
    "report": generate_report(
        total=len(image_list),
        success=count(batch_results, status="success"),
        failed=count(batch_results, status="failed"),
        avg_time=average(batch_results, processing_time)
    )
}
```

### 6.2 性能优化策略

```
批量处理性能优化：

  ┌───────────────────────────────────────────────────────┐
  │  策略一：减少 I/O 次数                                  │
  │    - 批量读取图片（避免逐张读取）                        │
  │    - 处理完直接写入，不缓存中间结果                       │
  │    - 使用 SSD 存储输入输出                               │
  ├───────────────────────────────────────────────────────┤
  │  策略二：GPU 利用率优化                                  │
  │    - 增大 batch_size（显存允许的情况下）                   │
  │    - 预加载模型，避免重复加载                             │
  │    - 使用 FP16 半精度推理                                │
  ├───────────────────────────────────────────────────────┤
  │  策略三：流水线并行                                      │
  │    - CPU 线程负责图片读取和预处理                         │
  │    - GPU 线程负责模型推理                                │
  │    - CPU 线程负责后处理和保存                             │
  ├───────────────────────────────────────────────────────┤
  │  策略四：跳过不需要处理的图片                             │

  │    - 检查质量评分，只处理模糊的图片                        │
  └───────────────────────────────────────────────────────┘
```

## 七、常见误区

### 误区一：把超分当万能药

超分算法**不能无中生有**。如果原图是 64×64 的缩略图，4× 超分后得到的是 256×256，虽然尺寸变大了但信息量没有增加。超分算法只能在已有信息的基础上做合理的"猜测"，对于极度退化的图像效果有限。

### 误区二：Hires Fix 的 denoise 开太高

denoise > 0.7 时，第二次采样几乎等于重新生成，结果是：
- 构图可能完全改变
- 人物的五官可能变化
- 出现重复对象

正确做法：denoise 控制在 0.4-0.6，必要时降低 start_at_step（跳过前几步）。

### 误区三：面部修复用在非人脸上

GFPGAN 和 CodeFormer 会先做**人脸检测**，如果检测不到人脸就不会做任何处理。但有时候模型会把其他圆形物体误判为人脸（比如圆形灯饰、水果），导致出现诡异的人脸伪影。

解决方案：在面部修复前先验证人脸检测结果，或使用 ComfyUI 的 Face Detection 节点做前置过滤。

### 误区四：忽略色彩空间转换

超分模型通常在 sRGB 色彩空间工作。如果你的工作流中使用了 VAE 解码后色彩空间不一致的处理（比如某些色彩校正节点），可能导致超分后色彩偏差。建议在超分前后各加一个色彩空间检查节点。

## 八、小结

本课的核心知识点：

1. **超分模型选择**：Real-ESRGAN 通用，SwinIR 高质量，动漫用 anime 专用模型
2. **两种放大路径**：潜空间放大（Hires Fix）保证语义一致，像素空间放大（超分模型）补充高频细节
3. **最佳组合方案**：Hires Fix 2× → Real-ESRGAN 4× → CodeFormer 面部修复
4. **面部修复选择**：快速批量用 GFPGAN，高质量最终输出用 CodeFormer
5. **批量处理**：注意 I/O 优化、GPU 利用率、流水线并行

## 参考答案

### 练习一

**思路**：denoise 控制第二次采样对原图的修改程度，需要在细节补充和构图保持之间找平衡。

**答案**：

测试结果分析：

denoise=0.3：
- 构图完全不变，五官位置准确
- 细节几乎没有改善，看起来只是平滑放大了
- 适合场景：构图已经完美，只需要消除放大锯齿

denoise=0.5：
- 构图基本不变，五官有轻微变化
- 细节明显改善：皮肤纹理、头发丝、衣服褶皱
- 适合场景：绝大多数人像生成图的最佳起点

denoise=0.7：
- 构图有可见变化：五官比例可能偏移，发型可能改变
- 细节非常丰富，但可能出现不自然的纹理
- 适合场景：对构图不太敏感的创意图

受影响最大的区域：
- 五官（眼睛、嘴巴）：最容易在高 denoise 下改变
- 头发：纹理可能完全重绘
- 手指：如果有手的话，变化会很明显

**要点**：
- 人像场景推荐 denoise=0.45-0.55
- 固定 seed 可以对比不同 denoise 的效果差异
- start_at_step 也可以用来控制重绘强度

### 练习二

**思路**：两种模型的设计理念不同，适合的场景也不同。

**答案**：

预期对比结果：

处理速度：
- Real-ESRGAN：约 2-3 秒（4× 放大）
- SwinIR：约 6-10 秒（4× 放大）
- Real-ESRGAN 快 3-5 倍

纹理细节（头发、衣服）：
- Real-ESRGAN：纹理清晰，但可能出现过度锐化
- SwinIR：纹理自然，细节层次更丰富

平滑区域（天空、皮肤）：
- Real-ESRGAN：可能出现轻微的网格状纹理（checker artifact）
- SwinIR：平滑区域非常干净，没有伪影

边缘锐利度：
- Real-ESRGAN：边缘更锐利，适合文字和线条
- SwinIR：边缘自然，不会过度锐化

结论：
- 照片类（人像、风景）：SwinIR 更优
- 设计图类（产品图、海报）：Real-ESRGAN 更优
- 批量处理：Real-ESRGAN（速度快）

**要点**：
- SwinIR 的 Transformer 架构在长距离依赖上有优势
- Real-ESRGAN 的 GAN 训练方式在高频纹理上更激进
- 没有绝对的"更好"，取决于输入类型和质量要求

### 练习三

**思路**：电商场景需要兼顾人脸质量和商品细节，需要分区域处理。

**答案**：

完整工作流：

```
阶段一：Hires Fix (512→1024)
  checkpoint: sd_xl_base_1.0
  denoise: 0.5
  steps: 20
  输出：1024×1024 latent → 解码为像素图

阶段二：Real-ESRGAN (1024→4096)
  model: RealESRGAN_x4plus
  scale: 4
  输出：4096×4096

阶段三：面部修复
  model: CodeFormer
  fidelity_weight: 0.7
  只处理人脸区域，不改变商品和背景
  输出：4096×4096（人脸已修复）

阶段四：局部锐化
  对商品区域做轻微锐化 (amount=0.3)
  不对面部区域锐化（CodeFormer 已处理）
  输出：最终 4096×4096
```

节点连接：
1. KSampler (base) → Latent Upscale → KSampler (hires)
2. VAE Decode → Image Scale (如果需要精确尺寸)
3. Real-ESRGAN Upscale → CodeFormer → Image Sharpen → Save Image

参数说明：
- Hires denoise=0.5：平衡细节和构图
- CodeFormer fidelity=0.7：修复的同时保持人脸相似度
- 锐化 amount=0.3：轻微锐化，避免商品边缘过于生硬

**要点**：
- 电商图不能过度修复，客户需要看到真实的商品细节
- 面部修复只影响人脸，不会改变商品
- 建议在批量处理前先用 10 张样图调优参数
