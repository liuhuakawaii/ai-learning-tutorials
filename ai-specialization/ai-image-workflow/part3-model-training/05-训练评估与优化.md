## 场景引入

你花了三天时间训练了一个品牌风格 LoRA。训练过程看起来很顺利——loss 从 0.15 一路降到了 0.02，曲线平滑得像教科书里的示例。你兴奋地用这个模型生成了一组测试图片，结果发现：生成的图片确实"像"品牌风格，但所有图片都长得差不多，像是同一个模板换了不同的文字。

你试着换了一个 prompt，模型依然输出几乎相同的构图和色调。这说明模型过拟合了——它不是学会了品牌的"风格"，而是记住了训练集里的"具体图片"。

训练评估的核心问题是：**你怎么知道模型训练得好不好？** 仅靠 loss 曲线是不够的。你需要一套多维度的评估体系，结合自动化指标和人工判断，在训练过程中持续监控，并在发现问题时知道如何调整。

本课将建立这套评估体系，让你在训练结束前就能预判模型质量，并掌握常见的优化策略。

## 一、Loss 曲线分析

### 1.1 Loss 是什么

Loss（损失函数值）衡量的是模型预测与实际目标之间的差距。在扩散模型训练中，loss 通常是模型预测的噪声与实际添加的噪声之间的均方误差（MSE）。loss 越低，模型的预测越准确。

但"预测准确"不等于"生成质量好"。一个过拟合的模型在训练集上 loss 极低，但在新 prompt 下生成质量急剧下降。

**正常收敛**：loss 从高处快速下降，然后逐渐趋于平稳。拐点通常在总训练步数的 30%-50% 处出现。平稳后的 loss 值应该在 0.03-0.08 之间（取决于数据集大小和任务复杂度）。

**过拟合**：loss 下降到很低的值后继续缓慢下降，但验证集上的生成质量开始恶化。特征是训练后期 loss 曲线变得"过于平滑"——没有正常的微小波动。

**学习率过高**：loss 曲线出现剧烈震荡，甚至不降反升。模型在每次参数更新时"跨过"了最优解。

**欠拟合**：loss 始终在高位震荡，模型无法从数据中学习到有效特征。通常是学习率过低、数据质量差或训练步数不足。

### 1.3 用代码分析 Loss 曲线

```python
import json
import numpy as np
from pathlib import Path

def load_training_log(log_path: str) -> dict:
    """加载 kohya-ss 训练日志"""
    steps = []
    losses = []
    learning_rates = []
    
    with open(log_path, "r") as f:
        for line in f:
            entry = json.loads(line.strip())
            if "loss" in entry:
                steps.append(entry.get("step", len(steps)))
                losses.append(float(entry["loss"]))
                learning_rates.append(float(entry.get("lr", 0)))
    
    return {
        "steps": np.array(steps),
        "losses": np.array(losses),
        "learning_rates": np.array(learning_rates),
    }


def detect_overfitting(losses: np.ndarray, window: int = 50, threshold: float = 0.005) -> dict:
    """检测过拟合：比较前半段和后半段的 loss 变化趋势"""
    mid = len(losses) // 2
    first_half = losses[:mid]
    second_half = losses[mid:]
    
    first_half_mean = np.mean(first_half[-window:])
    second_half_mean = np.mean(second_half[-window:])
    first_half_std = np.std(first_half[-window:])
    second_half_std = np.std(second_half[-window:])
    
    loss_drop = first_half_mean - second_half_mean
    std_ratio = second_half_std / (first_half_std + 1e-8)
    
    is_overfitting = loss_drop < threshold and std_ratio < 0.5
    
    return {
        "is_overfitting": is_overfitting,
        "loss_drop": float(loss_drop),
        "first_half_std": float(first_half_std),
        "second_half_std": float(second_half_std),
        "std_ratio": float(std_ratio),
        "reason": (
            "后半段 loss 几乎无下降且波动极小，模型可能已过拟合"
            if is_overfitting
            else "模型仍在正常学习"
        ),
    }


def analyze_convergence(losses: np.ndarray, window: int = 100) -> dict:
    """分析收敛状态"""
    if len(losses) < window * 2:
        return {"status": "数据不足，需要更多训练步数"}
    
    recent = losses[-window:]
    earlier = losses[-window * 2 : -window]
    
    recent_mean = np.mean(recent)
    earlier_mean = np.mean(earlier)
    improvement = (earlier_mean - recent_mean) / earlier_mean
    
    recent_slope = np.polyfit(range(len(recent)), recent, 1)[0]
    
    if improvement < 0.01 and abs(recent_slope) < 1e-5:
        status = "已收敛"
    elif improvement < 0.05:
        status = "接近收敛"
    elif recent_slope > 0:
        status = "loss 上升，可能学习率过高或过拟合"
    else:
        status = "仍在学习中"
    
    return {
        "status": status,
        "recent_mean_loss": float(recent_mean),
        "improvement_rate": float(improvement),
        "recent_slope": float(recent_slope),
    }


if __name__ == "__main__":
    log_path = "training_logs.jsonl"
    
    if not Path(log_path).exists():
        print(f"日志文件不存在: {log_path}")
        print("请先运行训练并生成日志文件")
    else:
        data = load_training_log(log_path)
        print(f"加载了 {len(data['steps'])} 条训练记录")
        print(f"Loss 范围: {data['losses'].min():.4f} ~ {data['losses'].max():.4f}")
        
        convergence = analyze_convergence(data["losses"])
        print(f"\n收敛分析: {convergence}")
        
        overfitting = detect_overfitting(data["losses"])
        print(f"过拟合检测: {overfitting}")
```

### 1.4 Loss 曲线的常见陷阱

**陷阱一：只看最终 loss 值。** 一个 loss 为 0.01 的模型不一定比 loss 为 0.05 的模型好。如果前者过拟合了，它的实际生成质量可能更差。

**陷阱二：忽略 loss 的波动幅度。** 正常训练中 loss 会有小幅度波动（标准差约 0.005-0.02）。如果波动突然变大或消失，都是异常信号。

**陷阱三：不同数据集的 loss 不能直接比较。** 10 张图训练的 loss 和 50 张图训练的 loss 数值本身没有可比性，需要结合数据集规模来判断。

## 二、自动化评估指标

### 2.1 FID（Fréchet Inception Distance）

FID 是衡量生成图片质量的标准指标。它计算生成图片和真实图片在 Inception V3 特征空间中的分布距离。FID 越低，生成图片与真实图片越接近。

```
FID 计算流程：

真实图片集 ──► Inception V3 ──► 特征向量 ──► 均值μ₁, 协方差Σ₁
                                                    │
生成图片集 ──► Inception V3 ──► 特征向量 ──► 均值μ₂, 协方差Σ₂
                                                    │
                                                    ▼
                                        FID = ||μ₁-μ₂||² + Tr(Σ₁+Σ₂-2√(Σ₁Σ₂))
```

```python
import torch
import numpy as np
from PIL import Image
from pathlib import Path
from scipy import linalg
from torchvision import transforms, models


class FIDEvaluator:
    """计算生成图片与真实图片之间的 FID 分数"""
    
    def __init__(self, device: str = "cuda"):
        self.device = device
        self.model = models.inception_v3(pretrained=True, transform_input=False)
        self.model.fc = torch.nn.Identity()
        self.model.to(device).eval()
        
        self.transform = transforms.Compose([
            transforms.Resize((299, 299)),
            transforms.ToTensor(),
            transforms.Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225]),
        ])
    
    def extract_features(self, image_dir: str) -> np.ndarray:
        """提取目录中所有图片的 Inception 特征"""
        features = []
        image_paths = list(Path(image_dir).glob("*.png")) + list(Path(image_dir).glob("*.jpg"))
        
        for img_path in image_paths:
            img = Image.open(img_path).convert("RGB")
            img_tensor = self.transform(img).unsqueeze(0).to(self.device)
            
            with torch.no_grad():
                feature = self.model(img_tensor)
            
            features.append(feature.cpu().numpy().flatten())
        
        return np.array(features)
    
    @staticmethod
    def calculate_fid(real_features: np.ndarray, gen_features: np.ndarray) -> float:
        """计算两个特征分布之间的 FID"""
        mu_real = np.mean(real_features, axis=0)
        sigma_real = np.cov(real_features, rowvar=False)
        mu_gen = np.mean(gen_features, axis=0)
        sigma_gen = np.cov(gen_features, rowvar=False)
        
        diff = mu_real - mu_gen
        
        covmean = linalg.sqrtm(sigma_real.dot(sigma_gen))
        if np.iscomplexobj(covmean):
            covmean = covmean.real
        
        fid = float(diff.dot(diff) + np.trace(sigma_real + sigma_gen - 2 * covmean))
        return fid


def evaluate_lora_checkpoint(
    checkpoint_path: str,
    real_images_dir: str,
    generated_images_dir: str,
    device: str = "cuda",
) -> dict:
    """评估单个 LoRA checkpoint 的 FID"""
    evaluator = FIDEvaluator(device=device)
    
    real_features = evaluator.extract_features(real_images_dir)
    gen_features = evaluator.extract_features(generated_images_dir)
    
    fid_score = evaluator.calculate_fid(real_features, gen_features)
    
    return {
        "checkpoint": checkpoint_path,
        "fid_score": fid_score,
        "num_real_images": len(real_features),
        "num_generated_images": len(gen_features),
        "quality": "优秀" if fid_score < 30 else "良好" if fid_score < 100 else "需要改进",
    }
```

FID 的参考范围：
- FID < 30：生成质量优秀，与真实图片难以区分
- FID 30-100：质量良好，有明显的风格一致性
- FID > 100：质量较差，需要调整训练参数或数据

### 2.2 CLIP Score

CLIP Score 衡量生成图片与文本 prompt 的语义一致性。它使用 CLIP 模型计算图片和文本嵌入之间的余弦相似度。CLIP Score 越高，图片与 prompt 的匹配度越好。

```python
import torch
from PIL import Image
from transformers import CLIPProcessor, CLIPModel


class CLIPScoreEvaluator:
    """使用 CLIP 模型评估图片与文本的匹配度"""
    
    def __init__(self, model_name: str = "openai/clip-vit-large-patch14", device: str = "cuda"):
        self.device = device
        self.model = CLIPModel.from_pretrained(model_name).to(device).eval()
        self.processor = CLIPProcessor.from_pretrained(model_name)
    
    def score(self, image_path: str, text: str) -> float:
        """计算单张图片与文本的 CLIP Score"""
        image = Image.open(image_path).convert("RGB")
        inputs = self.processor(text=[text], images=image, return_tensors="pt", padding=True)
        inputs = {k: v.to(self.device) for k, v in inputs.items()}
        
        with torch.no_grad():
            outputs = self.model(**inputs)
        
        logits_per_image = outputs.logits_per_image
        clip_score = logits_per_image.item() / 100.0
        
        return clip_score
    
    def batch_score(self, image_dir: str, prompts: list[str]) -> list[dict]:
        """批量评估图片与对应 prompt 的匹配度"""
        results = []
        image_paths = sorted(Path(image_dir).glob("*.png"))
        
        for img_path, prompt in zip(image_paths, prompts):
            score = self.score(str(img_path), prompt)
            results.append({
                "image": img_path.name,
                "prompt": prompt,
                "clip_score": score,
            })
        
        return results


def run_clip_evaluation(image_dir: str, style_prompt: str) -> dict:
    """运行 CLIP Score 评估"""
    evaluator = CLIPScoreEvaluator()
    
    image_paths = list(Path(image_dir).glob("*.png"))
    scores = []
    
    for img_path in image_paths:
        score = evaluator.score(str(img_path), style_prompt)
        scores.append(score)
    
    scores_array = np.array(scores)
    
    return {
        "mean_clip_score": float(scores_array.mean()),
        "std_clip_score": float(scores_array.std()),
        "min_clip_score": float(scores_array.min()),
        "max_clip_score": float(scores_array.max()),
        "num_images": len(scores),
        "consistency": "高" if scores_array.std() < 0.05 else "中" if scores_array.std() < 0.1 else "低",
    }
```

CLIP Score 的参考范围：
- Score > 0.30：图片与 prompt 高度匹配
- Score 0.25-0.30：匹配度良好
- Score < 0.25：图片可能没有准确反映 prompt 内容

### 2.3 指标的局限性

FID 和 CLIP Score 是有用的参考，但它们有明确的局限性：

**FID 的问题**：需要大量样本（至少 50 张，最好 200 张以上）才能得到稳定结果；对图片的多样性敏感，但对风格一致性不敏感；计算开销大。

**CLIP Score 的问题**：CLIP 模型本身对"风格"的理解有限；高 CLIP Score 不意味着图片质量高，只意味着内容匹配；对抽象的风格描述（如"高级感""氛围感"）评分不可靠。

**结论**：自动化指标用于训练过程中的趋势监控（"这一轮比上一轮好还是差"），不能替代人工评估来判断最终质量。

## 三、人工评估流程

### 3.1 评估维度设计

人工评估需要标准化的维度，否则不同评估者的结果无法比较：

```
┌─────────────────────────────────────────────────────────┐

│                                                         │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐     │
```

### 3.2 评估表格模板

```python
import json
import random
from datetime import datetime
from pathlib import Path


class HumanEvaluationManager:
    """管理人工评估流程"""
    
    def __init__(self, output_dir: str):
        self.output_dir = Path(output_dir)
        self.output_dir.mkdir(parents=True, exist_ok=True)
    
    def create_evaluation_task(
        self,
        image_paths: list[str],
        reference_images: list[str],
        prompts: list[str],
        evaluator_name: str,
    ) -> str:
        """创建评估任务"""
        task_id = f"eval_{datetime.now().strftime('%Y%m%d_%H%M%S')}"
        
        items = []
        for i, (img, prompt) in enumerate(zip(image_paths, prompts)):
            items.append({
                "id": i,
                "image_path": img,
                "prompt": prompt,
                "scores": {
                    "style_consistency": None,
                    "image_quality": None,
                    "diversity": None,
                    "overall": None,
                },
                "comments": "",
            })
        
        task = {
            "task_id": task_id,
            "evaluator": evaluator_name,
            "created_at": datetime.now().isoformat(),
            "reference_images": reference_images,
            "items": items,
            "scoring_guide": {
                "style_consistency": "1-5分，与参考图风格的匹配程度",
                "image_quality": "1-5分，图片的清晰度、细节、无伪影程度",
                "diversity": "1-5分，生成结果的多样性",
                "overall": "1-5分，综合评价",
            },
        }
        
        task_path = self.output_dir / f"{task_id}.json"
        with open(task_path, "w", encoding="utf-8") as f:
            json.dump(task, f, ensure_ascii=False, indent=2)
        
        return str(task_path)
    
    def calculate_agreement(self, eval_paths: list[str]) -> dict:
        """计算多个评估者之间的一致性（Cohen's Kappa 简化版）"""
        all_scores = []
        
        for path in eval_paths:
            with open(path, "r", encoding="utf-8") as f:
                task = json.load(f)
            scores = [item["scores"]["overall"] for item in task["items"]]
            all_scores.append(scores)
        
        if len(all_scores) < 2:
            return {"agreement": "需要至少两个评估者"}
        
        num_items = len(all_scores[0])
        agreements = 0
        
        for i in range(num_items):
            item_scores = [scores[i] for scores in all_scores]
            if max(item_scores) - min(item_scores) <= 1:
                agreements += 1
        
        agreement_rate = agreements / num_items
        
        return {
            "agreement_rate": agreement_rate,
            "num_evaluators": len(all_scores),
            "num_items": num_items,
            "interpretation": (
                "高度一致" if agreement_rate > 0.8
                else "中等一致" if agreement_rate > 0.6
                else "需要讨论评分标准"
            ),
        }
    
    def generate_report(self, eval_path: str) -> dict:
        """生成评估报告"""
        with open(eval_path, "r", encoding="utf-8") as f:
            task = json.load(f)
        
        dimension_scores = {
            "style_consistency": [],
            "image_quality": [],
            "diversity": [],
            "overall": [],
        }
        
        for item in task["items"]:
            for dim, score in item["scores"].items():
                if score is not None:
                    dimension_scores[dim].append(score)
        
        report = {
            "task_id": task["task_id"],
            "evaluator": task["evaluator"],
            "num_items": len(task["items"]),
            "dimension_averages": {},
            "low_score_items": [],
        }
        
        for dim, scores in dimension_scores.items():
            if scores:
                avg = sum(scores) / len(scores)
                report["dimension_averages"][dim] = round(avg, 2)
        
        for item in task["items"]:
            if item["scores"]["overall"] is not None and item["scores"]["overall"] <= 2:
                report["low_score_items"].append({
                    "id": item["id"],
                    "overall_score": item["scores"]["overall"],
                    "comments": item["comments"],
                })
        
        return report
```

### 3.3 评估的最佳实践

**盲评原则**：评估者不应该知道哪张图来自哪个 checkpoint，避免心理暗示。

**多次评估**：同一批图片至少让两个人独立评估，计算评估者间一致性。一致性低于 60% 说明评分标准需要重新对齐。

**对比评估优于绝对评分**：与其让人给每张图打 1-5 分，不如让人在两张图中选更好的那张。相对判断更稳定、更容易达成一致。

## 四、过拟合检测与应对

### 4.1 过拟合的三个信号

```
信号一：Loss 曲线异常
──────────────────
训练 loss 持续下降，但验证 loss 开始上升
或训练 loss 下降到极低值（< 0.01）且波动消失

信号二：生成多样性下降
──────────────────
用不同 prompt 生成的图片越来越相似
固定 seed 时，不同 prompt 的输出几乎一样

信号三：风格记忆而非风格学习
──────────────────
```

## 五、学习率调度策略

### 5.1 为什么学习率调度很重要

学习率（Learning Rate）决定了每次参数更新的幅度。固定学习率是一种妥协——训练初期希望步子大一些快速接近最优解，训练后期希望步子小一些精细调整。

```
学习率调度对比：

学习率
 │
 │  固定学习率          Cosine Annealing
 │  ──────            ──────────────
0.001┤ ─────────────     ╲
     │                    ╲
0.0005┤                     ╲
     │                      ╲
0.0001┤                       ╲___
     │
0.0000┤──────────────────────────── Step
     0    500   1000  1500  2000
```

### 5.2 常用调度策略实现

```python
import math
import numpy as np


def cosine_schedule(
    current_step: int,
    total_steps: int,
    base_lr: float,
    min_lr_ratio: float = 0.1,
) -> float:
    """Cosine Annealing 学习率调度"""
    progress = current_step / total_steps
    lr = min_lr_ratio * base_lr + 0.5 * (base_lr - min_lr_ratio * base_lr) * (
        1 + math.cos(math.pi * progress)
    )
    return lr


def warmup_cosine_schedule(
    current_step: int,
    total_steps: int,
    base_lr: float,
    warmup_steps: int = 100,
    min_lr_ratio: float = 0.1,
) -> float:
    """带 Warmup 的 Cosine Annealing"""
    if current_step < warmup_steps:
        return base_lr * current_step / warmup_steps
    return cosine_schedule(current_step - warmup_steps, total_steps - warmup_steps, base_lr, min_lr_ratio)


def constant_with_warmup_schedule(
    current_step: int,
    total_steps: int,
    base_lr: float,
    warmup_steps: int = 100,
) -> float:
    """Warmup 后保持恒定学习率"""
    if current_step < warmup_steps:
        return base_lr * current_step / warmup_steps
    return base_lr


def get_recommended_schedule(
    dataset_size: int,
    num_epochs: int,
    batch_size: int = 1,
    base_lr: float = 1e-4,
) -> dict:
    """根据数据集大小推荐学习率调度策略"""
    steps_per_epoch = dataset_size // batch_size
    total_steps = steps_per_epoch * num_epochs
    warmup_steps = min(total_steps // 10, 200)
    
    if dataset_size <= 20:
        return {
            "schedule": "constant_with_warmup",
            "base_lr": 5e-5,
            "warmup_steps": warmup_steps,
            "reason": "小数据集使用较低的固定学习率，避免过度调整",
        }
    elif dataset_size <= 50:
        return {
            "schedule": "cosine",
            "base_lr": base_lr,
            "warmup_steps": warmup_steps,
            "min_lr_ratio": 0.1,
            "reason": "中等数据集使用 Cosine Annealing，在后期精细调整",
        }
    else:
        return {
            "schedule": "warmup_cosine",
            "base_lr": base_lr,
            "warmup_steps": warmup_steps,
            "min_lr_ratio": 0.05,
            "reason": "大数据集使用带 Warmup 的 Cosine，前期稳定训练后期精细调整",
        }
```

### 5.3 学习率选择的经验法则

LoRA 训练的学习率通常在 1e-5 到 5e-4 之间。以下是一些经验参考：

| 数据集大小 | 推荐学习率 | 推荐调度 |
|-----------|-----------|---------|
| 10-20 张 | 5e-5 | Constant + Warmup |
| 20-50 张 | 1e-4 | Cosine |
| 50-100 张 | 1e-4 ~ 2e-4 | Warmup + Cosine |
| 100+ 张 | 2e-4 | Warmup + Cosine |

学习率过高会导致 loss 震荡甚至发散，过低会导致训练缓慢且容易欠拟合。如果不确定，从 1e-4 开始，根据 loss 曲线调整。

## 常见误区

**误区一：Loss 越低越好。** Loss 低只说明模型在训练集上拟合得好，不代表生成质量高。一个严重过拟合的模型 loss 可能只有 0.005，但生成的图片完全没有多样性。

**误区二：FID 可以替代人工评估。** FID 对样本数量敏感，且无法评估风格一致性。50 张图算出的 FID 可能波动很大。人工评估仍然是判断风格匹配度的金标准。

**误区三：训练越多步越好。** 很多初学者会设置很高的训练步数，认为"多训练总比少训练好"。实际上，过度训练是 LoRA 最常见的失败原因。每张图 50-100 步是一个合理的起点。

**误区四：不需要验证集。** 有些人会把所有数据都用于训练，不留验证集。正确做法是留出 10-20% 的图片作为验证集，在训练过程中定期生成验证集的图片来监控质量。

**误区五：只关注最终 checkpoint。** 训练过程中每个 checkpoint 的质量可能差异很大。应该在训练过程中定期保存 checkpoint（如每 100 步保存一次），训练结束后逐一评估，选择最佳的那个。

## 小结

本课建立了训练评估与优化的完整体系：

1. **Loss 曲线分析**是最基本的评估手段，但不能单独依赖。正常收敛、过拟合、学习率过高、欠拟合各有典型的曲线形态。
2. **FID 和 CLIP Score** 提供自动化的量化评估。FID 衡量生成图片与真实图片的分布距离，CLIP Score 衡量图片与 prompt 的匹配度。两者都有局限性，用于趋势监控而非绝对判断。
3. **人工评估**是判断风格匹配度的金标准。需要标准化的评估维度、盲评流程和评估者间一致性检查。
4. **过拟合**是最常见的训练问题，通过减少训练步数、增加数据增强、降低 LoRA rank、增加 dropout 等方式应对。
5. **学习率调度**在训练的不同阶段使用不同的学习率。小数据集用恒定学习率，中大数据集用 Cosine Annealing。

### 练习一

**思路**：分段分析 loss 曲线的每个阶段，识别异常拐点

**答案**：

1000-1500 步 loss 平稳是正常的收敛后期表现。1500 步后 loss 上升是异常信号，可能原因：

1. **学习率调度问题**：如果使用了带 warmup 的调度，可能在某个点学习率突然增大
2. **数据顺序问题**：如果数据没有充分 shuffle，1500 步可能开始遍历到了异常样本
3. **数值不稳定**：梯度爆炸的早期信号

解决方案：
- 回退到 1000-1200 步的 checkpoint
- 检查学习率调度曲线，确认是否在 1500 步附近有异常
- 降低学习率 50% 重新训练后半段
- 启用梯度裁剪（gradient clipping = 1.0）

**要点**：
- loss 上升通常不是正常现象，需要排查原因
- 保留中间 checkpoint 可以在发现问题时回退

- Warmup 步数通常是总步数的 3-10%
