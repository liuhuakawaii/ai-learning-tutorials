# 训练数据准备：LoRA/DreamBooth 训练数据工程

## 场景引入

你花了两周时间学习 Stable Diffusion 的原理，终于决定训练自己的第一个 LoRA 模型——一个能生成你家猫咪"橘子"的专属模型。你拍了 20 张照片，兴冲冲地丢进 kohya-ss，跑了 2000 步，结果生成的图片要么是一团模糊的橘色色块，要么是一只完全不像"橘子"的猫。

问题出在哪里？不是训练参数，不是模型选择，而是**数据**。

训练数据的质量直接决定了微调模型的上限。一个用 30 张精心准备的数据集训练的 LoRA，效果往往远超用 200 张随意收集的图片训练的结果。这节课我们从工程角度系统讲解：如何准备一份高质量的训练数据集。

## 学习目标

完成本课后，你将能够：

1. 理解训练数据质量对微调效果的影响机制
2. 掌握图像收集、筛选、清洗的完整流程
3. 使用 BLIP 和 WD Tagger 进行自动标注
4. 组织符合 kohya-ss 规范的数据集目录结构
5. 理解正则化数据集的作用和准备方法
6. 合理使用数据增强策略提升训练效果

## 一、训练数据的质量要求

### 1.1 为什么数据质量比数量更重要

微调的本质是在预训练模型的参数空间中找到一个局部最优点。训练数据就是指引搜索方向的路标——路标越多、越准确，模型就越容易找到正确的位置。

```
预训练模型参数空间（数十亿维）
┌─────────────────────────────────────────┐
│                                         │
│    ★ 预训练分布中心                      │
│         ↘                               │
│           ↘  高质量数据引导               │
│             ↘   ↘                        │
│               ● ← 理想微调位置            │
│             ↗   ↗                        │
│           ↗  低质量数据误导               │
│         ↗                               │
│    ✗ 偏离目标位置                         │
│                                         │
└─────────────────────────────────────────┘
```

关键原则：**30 张高质量图片 > 200 张低质量图片**。

### 1.2 高质量数据的五个维度

| 维度 | 要求 | 反面案例 |
|------|------|----------|
| **清晰度** | 主体清晰，无明显模糊 | 手抖拍摄的糊图 |
| **多样性** | 多角度、多背景、多光照 | 20 张都是正面大头照 |
| **一致性** | 主体特征稳定一致 | 同一角色有时短发有时长发 |
| **标注准确** | 文本描述与图像内容匹配 | 标注写"坐着"实际是站着 |
| **无干扰** | 无水印、文字、边框覆盖 | 截图带网站水印 |

### 1.3 数据量的参考范围

不同训练目标需要的数据量差异很大：

```
训练目标              推荐数据量        说明
─────────────────────────────────────────────────
单一角色/人物 LoRA    15-50 张         多角度、多表情
特定风格 LoRA         50-200 张        风格一致性重要
单一物体 LoRA         10-30 张         物体变化少
概念组合 LoRA         30-100 张        每个概念需覆盖
DreamBooth 角色       5-20 张          但需精心筛选
Textual Inversion     5-20 张          最少但质量要求最高
```

## 二、图像收集和筛选策略

### 2.1 图像来源

合法且实用的图像来源：

**自拍/自绘（推荐）**
- 自己拍摄的照片，版权完全可控
- 自己绘制的作品，风格一致性高
- 手机拍摄即可，注意光线充足

**公开数据集**
- LAION-5B（大规模，需筛选）
- Unsplash、Pexels（高质量免版权图库）
- 特定领域数据集（如 FFHQ 人脸数据集）

**AI 辅助生成**
- 用现有模型生成初版数据
- 适合风格类 LoRA 的数据扩充
- 需注意避免模式坍塌（后面详述）

### 2.2 筛选流程

收集到原始图像后，需要经过系统化筛选：

```
原始图像池（100+ 张）
    │
    ▼
┌───────────────┐
│ 第一轮：肉眼筛选 │ ← 去除模糊、水印、无关内容
└───────┬───────┘
        │ 剩余 60-70 张
        ▼
┌───────────────┐
│ 第二轮：质量评估 │ ← 用 CLIP/IQA 评分过滤
└───────┬───────┘
        │ 剩余 40-50 张
        ▼
┌───────────────┐
│ 第三轮：多样性检查 │ ← 去除重复角度/姿势
└───────┬───────┘
        │ 最终 20-30 张
        ▼
    进入预处理流程
```

### 2.3 用 CLIP Score 辅助筛选

CLIP 模型可以衡量图像与文本描述的匹配度，帮助筛选出与目标概念最相关的图片：

```python
import torch
from PIL import Image
from transformers import CLIPProcessor, CLIPModel

def rank_images_by_relevance(image_paths: list[str], description: str, top_k: int = 20) -> list[tuple[str, float]]:
    """根据 CLIP 分数对图片进行排序，选出与描述最相关的 top_k 张。"""
    model = CLIPModel.from_pretrained("openai/clip-vit-base-patch32")
    processor = CLIPProcessor.from_pretrained("openai/clip-vit-base-patch32")

    scores = []
    for path in image_paths:
        image = Image.open(path).convert("RGB")
        inputs = processor(text=[description], images=image, return_tensors="pt", padding=True)
        with torch.no_grad():
            outputs = model(**inputs)
        score = outputs.logits_per_image.item()
        scores.append((path, score))

    scores.sort(key=lambda x: x[1], reverse=True)
    return scores[:top_k]


if __name__ == "__main__":
    import glob
    photos = glob.glob("./raw_photos/*.jpg")
    selected = rank_images_by_relevance(photos, "a photo of an orange tabby cat sitting on a sofa")
    for path, score in selected:
        print(f"{score:.2f}  {path}")
```

### 2.4 避免数据偏差

一个常见的训练失败原因是数据存在隐性偏差：

**反面案例**：训练"橘子"的 LoRA，但所有照片都是在沙发上拍的。模型会把"橘子"和"沙发"绑定在一起，生成时 Prompt 里没有沙发就效果很差。

**解决方案**：确保背景、光照、角度的多样性。可以用以下清单自查：

```
多样性自查清单：
□ 至少 3 种不同背景
□ 至少 3 种不同光照条件（自然光/室内光/逆光）
□ 至少 4 种不同角度（正面/侧面/背面/俯视）
□ 至少 2 种不同距离（特写/半身/全身）
□ 至少 3 种不同姿势或状态
```

## 三、图像预处理

### 3.1 统一分辨率

Stable Diffusion 训练要求输入图像具有统一的分辨率。SD 1.5 默认训练分辨率为 512×512，SDXL 为 1024×1024。

**错误做法**：直接拉伸图片到目标尺寸，会导致图像变形。

**正确做法**：先裁剪再缩放，保持原始比例：

```python
from PIL import Image

def smart_resize_to_target(image_path: str, target_size: int = 512) -> Image.Image:
    """智能裁剪并缩放图片到目标正方形尺寸。

    策略：先将短边缩放到 target_size，然后从中心裁剪长边。
    """
    img = Image.open(image_path).convert("RGB")
    width, height = img.size

    # 计算缩放比例，确保短边至少达到 target_size
    scale = target_size / min(width, height)
    new_width = int(width * scale)
    new_height = int(height * scale)
    img = img.resize((new_width, new_height), Image.LANCZOS)

    # 从中心裁剪到正方形
    left = (new_width - target_size) // 2
    top = (new_height - target_size) // 2
    img = img.crop((left, top, left + target_size, top + target_size))

    return img


def batch_resize(input_dir: str, output_dir: str, target_size: int = 512):
    """批量处理目录下所有图片。"""
    import os
    import glob

    os.makedirs(output_dir, exist_ok=True)
    image_extensions = ("*.jpg", "*.jpeg", "*.png", "*.webp")

    for ext in image_extensions:
        for img_path in glob.glob(os.path.join(input_dir, ext)):
            filename = os.path.basename(img_path)
            resized = smart_resize_to_target(img_path, target_size)
            save_path = os.path.join(output_dir, os.path.splitext(filename)[0] + ".png")
            resized.save(save_path, "PNG")
            print(f"Processed: {filename} -> {save_path}")


if __name__ == "__main__":
    batch_resize("./raw_photos", "./processed_photos", target_size=512)
```

### 3.2 Aspect Ratio Bucketing（宽高比分桶）

直接裁剪成正方形会丢失大量构图信息。kohya-ss 支持 Aspect Ratio Bucketing，允许训练时使用不同宽高比的图片：

```
原始图片（3:2 横幅）        裁剪成正方形（丢失两侧）
┌──────────────────┐       ┌──────────┐
│                  │       │          │
│   重要内容区域    │  -->  │  被裁掉   │
│                  │       │          │
└──────────────────┘       └──────────┘

使用 Bucketing（保留原始比例）
┌──────────────────┐
│                  │  分辨率：768×512
│   完整内容保留    │  总像素数 ≈ 512×512
│                  │
└──────────────────┘
```

Bucketing 的工作原理是：将训练图片按宽高比分组，同一 bucket 内的图片 batch 一起训练，不同 bucket 的总像素数近似相等。kohya-ss 的 `--enable_bucket` 参数会自动完成这个过程。

### 3.3 图片清洗

在正式标注之前，需要清除低质量图片：

```python
import os
from PIL import Image

def clean_dataset(input_dir: str, output_dir: str, min_size: int = 512):
    """清洗数据集：去除损坏文件、过小图片、非 RGB 图片。

    Args:
        input_dir: 原始图片目录
        output_dir: 清洗后输出目录
        min_size: 最小短边尺寸
    """
    os.makedirs(output_dir, exist_ok=True)
    removed_count = 0

    for filename in os.listdir(input_dir):
        filepath = os.path.join(input_dir, filename)
        try:
            img = Image.open(filepath)
            img.verify()  # 检查文件完整性

            img = Image.open(filepath).convert("RGB")
            width, height = img.size

            if min(width, height) < min_size:
                print(f"[移除] {filename}: 尺寸过小 ({width}x{height})")
                removed_count += 1
                continue

            # 保存为 PNG 格式（无损）
            save_path = os.path.join(output_dir, os.path.splitext(filename)[0] + ".png")
            img.save(save_path, "PNG")

        except Exception as e:
            print(f"[移除] {filename}: 无法打开 ({e})")
            removed_count += 1

    print(f"\n清洗完成：保留 {len(os.listdir(output_dir))} 张，移除 {removed_count} 张")


if __name__ == "__main__":
    clean_dataset("./processed_photos", "./cleaned_photos", min_size=512)
```

## 四、自动标注工具

标注（Caption）是训练数据的另一半。图像告诉模型"长什么样"，标注告诉模型"用什么词描述它"。

### 4.1 BLIP 自动标注

BLIP（Bootstrapping Language-Image Pre-training）是一个图像描述生成模型，适合生成自然语言风格的标注：

```python
import torch
from PIL import Image
from transformers import BlipProcessor, BlipForConditionalGeneration

def generate_caption_blip(image_path: str, prompt: str = "") -> str:
    """使用 BLIP 生成图片标注。

    Args:
        image_path: 图片路径
        prompt: 可选的引导提示，如 "a photo of"
    """
    processor = BlipProcessor.from_pretrained("Salesforce/blip-image-captioning-large")
    model = BlipForConditionalGeneration.from_pretrained("Salesforce/blip-image-captioning-large")

    image = Image.open(image_path).convert("RGB")

    if prompt:
        inputs = processor(image, prompt, return_tensors="pt")
    else:
        inputs = processor(image, return_tensors="pt")

    with torch.no_grad():
        output = model.generate(**inputs, max_length=75)

    caption = processor.decode(output[0], skip_special_tokens=True)
    return caption


def batch_caption(image_dir: str, output_dir: str):
    """批量为目录下所有图片生成标注文件。"""
    import os
    import glob

    os.makedirs(output_dir, exist_ok=True)

    for img_path in glob.glob(os.path.join(image_dir, "*.png")):
        caption = generate_caption_blip(img_path)
        filename = os.path.splitext(os.path.basename(img_path))[0]
        caption_path = os.path.join(output_dir, filename + ".txt")

        with open(caption_path, "w", encoding="utf-8") as f:
            f.write(caption)
        print(f"{filename}: {caption}")


if __name__ == "__main__":
    batch_caption("./cleaned_photos", "./captions")
```

BLIP 生成的是自然语言描述，例如：
- "a orange tabby cat sitting on a brown sofa looking at the camera"
- "a cat lying on a wooden floor in sunlight"

### 4.2 WD Tagger 自动标注

WD Tagger（Waifu Diffusion Tagger）基于 Danbooru 标签体系，生成逗号分隔的标签式标注，更适合 Stable Diffusion 训练：

```python
import torch
from PIL import Image
from transformers import AutoModelForImageClassification, AutoFeatureExtractor

def tag_with_wd(image_path: str, model_name: str = "SmilingWolf/wd-v1-4-vit-tagger-v2") -> list[str]:
    """使用 WD Tagger 为图片生成 Danbooru 风格标签。

    返回置信度高于阈值的标签列表。
    """
    from huggingface_hub import hf_hub_download
    import csv

    # 加载模型和处理器
    extractor = AutoFeatureExtractor.from_pretrained(model_name)
    model = AutoModelForImageClassification.from_pretrained(model_name)

    image = Image.open(image_path).convert("RGB")
    inputs = extractor(images=image, return_tensors="pt")

    with torch.no_grad():
        outputs = model(**inputs)
        probs = torch.sigmoid(outputs.logits)[0]

    # 加载标签映射
    label_path = hf_hub_download(repo_id=model_name, filename="selected_tags.csv")
    labels = []
    with open(label_path, "r", encoding="utf-8") as f:
        reader = csv.reader(f)
        next(reader)  # 跳过表头
        for row in reader:
            labels.append(row[1])

    # 过滤低置信度标签
    threshold = 0.35
    result_tags = []
    for i, prob in enumerate(probs.tolist()):
        if prob > threshold and i < len(labels):
            result_tags.append(labels[i])

    return result_tags


if __name__ == "__main__":
    tags = tag_with_wd("./cleaned_photos/orange_cat_01.png")
    print(", ".join(tags))
    # 输出示例: orange_tabby, cat, animal, sitting, sofa, indoors, looking_at_viewer
```

### 4.3 标注策略：自然语言 vs 标签式

两种标注风格各有适用场景：

```
标注风格          适用场景                  示例
──────────────────────────────────────────────────────────────
自然语言          写实风格、场景描述         "a photo of a cat sitting on a red
(BLIP)                                    sofa in a living room with warm lighting"

标签式            动漫/插画风格             "orange_tabby, cat, sitting, sofa,
(WD Tagger)                               indoors, warm_lighting, detailed_eyes"

混合式            通用推荐                  "a photo of an orange tabby cat,
(两者结合)                                orange_tabby, cat, sitting, sofa"
```

**推荐做法**：先用 BLIP 生成基础描述，再用 WD Tagger 补充细节标签，最后人工审核和修改。

### 4.4 触发词（Trigger Word）设计

对于角色类 LoRA，需要在标注中加入一个唯一的触发词：

```
正确标注示例：
"ohwx cat, orange tabby, sitting on sofa, warm lighting, detailed fur"

其中 "ohwx cat" 是触发词：
- "ohwx" 是一个随机生成的、在预训练模型中没有语义的 token
- "cat" 是类别词，帮助模型理解这是某种动物
- 后面的描述词帮助模型学习场景和属性
```

触发词选择原则：
- 使用模型词汇表中不存在的无意义组合词
- 避免使用常见英文单词（会被预训练语义干扰）
- 长度 3-8 个字符为宜
- 常见选择：`ohwx`、`sks`、`txl`、`qwpm`

## 五、数据集组织结构

### 5.1 kohya-ss 标准目录结构

kohya-ss 训练框架要求特定的数据集目录格式：

```
dataset/
├── 10_ohwx cat/          # 目录名格式：{重复次数}_{概念名}
│   ├── image001.png
│   ├── image001.txt      # 与图片同名的标注文件
│   ├── image002.png
│   ├── image002.txt
│   └── ...
├── 10_ohwx cat_reg/      # 正则化数据集（可选）
│   ├── reg001.png
│   ├── reg001.txt
│   └── ...
└── meta_lat.json         # 元数据文件（kohya-ss 自动生成）
```

目录名中的数字 `10` 表示每张图片在每个 epoch 中重复 10 次。重复次数用于平衡不同概念的训练权重。

### 5.2 标注文件格式

每个 `.txt` 文件包含对应图片的文本标注：

```
# image001.txt
ohwx cat, orange tabby, sitting on a brown leather sofa, looking at camera, 
warm indoor lighting, living room background, detailed fur texture, 
sharp focus, high quality
```

标注注意事项：
- 第一个词组应为触发词 + 类别词
- 描述应准确反映图片内容
- 避免使用否定词（"no tail" 会让模型更关注"tail"）
- 长度控制在 75 个 token 以内（超过会被截断）

## 六、正则化数据集

### 6.1 什么是正则化

正则化（Regularization）是防止模型"遗忘"预训练知识的技术。没有正则化时，模型可能会过度拟合训练数据，导致：

```
无正则化训练的问题：

Prompt: "a cat sitting on a bench"
预期：各种各样的猫坐在长椅上
实际：所有猫都长得像"橘子"（训练数据中的猫）

这就是"知识侵蚀"——模型忘记了"cat"的通用概念，
把它与训练数据中的特定猫绑定在一起。
```

### 6.2 正则化数据集的准备

正则化数据集是一组与训练概念同类但不包含目标特征的图片。例如训练"橘子"这只猫的 LoRA 时，正则化数据集应该是各种各样的猫的图片：

```python
def generate_regularization_images(concept_class: str, count: int, output_dir: str):
    """使用预训练模型生成正则化图片。

    原理：用基础 SD 模型（不包含你的微调）生成同类图片，
    作为训练时的"锚点"，防止模型忘记通用概念。
    """
    import os
    from diffusers import StableDiffusionPipeline

    os.makedirs(output_dir, exist_ok=True)

    pipe = StableDiffusionPipeline.from_pretrained(
        "runwayml/stable-diffusion-v1-5",
        torch_dtype=torch.float16
    )
    pipe = pipe.to("cuda")

    prompts = [
        f"a photo of a {concept_class}",
        f"a {concept_class} in various poses",
        f"a detailed photo of a {concept_class}",
        # 添加更多变体 prompt 增加多样性
    ]

    for i in range(count):
        prompt = prompts[i % len(prompts)]
        image = pipe(prompt, num_inference_steps=30).images[0]
        image.save(os.path.join(output_dir, f"reg_{i:04d}.png"))
        print(f"Generated regularization image {i+1}/{count}")


if __name__ == "__main__":
    generate_regularization_images("cat", 200, "./dataset/10_ohwx cat_reg")
```

### 6.3 正则化数据集的使用

在 kohya-ss 训练配置中启用正则化：

```toml
# 训练配置中添加
[training]
# 正则化数据集目录与训练数据集目录同级，以 _reg 结尾
# kohya-ss 会自动识别和使用
reg_data_dir = "./dataset/10_ohwx cat_reg"
prior_loss_weight = 1.0  # 正则化损失权重，通常设为 1.0
```

`prior_loss_weight` 控制正则化的强度：
- `1.0`：标准值，正则化损失与主损失权重相等
- `0.5`：较弱正则化，允许更多风格偏移
- `2.0`：较强正则化，更保守，不容易遗忘

## 七、数据增强

### 7.1 什么是数据增强

数据增强通过对现有图片施加变换来扩充数据集，提升模型的泛化能力：

```
原始图片 ──┬── 水平翻转 ──→ 新图片 1
           ├── 轻微旋转 ──→ 新图片 2
           ├── 色调调整 ──→ 新图片 3
           └── 裁剪偏移 ──→ 新图片 4

1 张图片 → 4 张额外训练数据
```

### 7.2 适合 Stable Diffusion 训练的增强策略

不是所有增强策略都适合生成模型训练。以下是有害和无害的增强对比：

```
✅ 推荐的增强策略：
- 水平翻转（最常用，几乎无副作用）
- 轻微色调/饱和度调整（±10%）
- 轻微对比度调整（±5%）

⚠️ 谨慎使用的策略：
- 随机裁剪（可能丢失关键信息）
- 模糊处理（降低图像质量）
- 噪声添加（干扰训练）

❌ 不推荐的策略：
- 垂直翻转（改变物理合理性）
- 大角度旋转（扭曲构图）
- 颜色反转（产生不自然图像）
```

### 7.3 kohya-ss 中的数据增强配置

kohya-ss 内置了部分数据增强功能：

```toml
[training]
# 随机裁剪偏移（center crop 的替代方案）
random_crop = false

# 颜色翻转增强
color_aug = true       # 启用颜色增强（色调/饱和度/对比度）

# 随机翻转
flip_aug = true        # 启用水平翻转增强

# 噪声增强
noise_aug = false      # 一般不推荐

# 分辨率微调（训练时随机微调分辨率）
resolution_rand = true
```

### 7.4 手动增强脚本

如果 kohya-ss 内置增强不够用，可以手动预处理：

```python
import os
from PIL import Image, ImageEnhance, ImageOps

def augment_dataset(input_dir: str, output_dir: str):
    """手动数据增强：为每张原始图片生成翻转和色调变体。"""
    os.makedirs(output_dir, exist_ok=True)

    for filename in os.listdir(input_dir):
        if not filename.lower().endswith((".png", ".jpg", ".jpeg")):
            continue

        img = Image.open(os.path.join(input_dir, filename)).convert("RGB")
        base_name = os.path.splitext(filename)[0]

        # 保存原图
        img.save(os.path.join(output_dir, f"{base_name}_original.png"))

        # 水平翻转
        flipped = ImageOps.mirror(img)
        flipped.save(os.path.join(output_dir, f"{base_name}_flip.png"))

        # 色调偏移（暖色调）
        warm = ImageEnhance.Color(img).enhance(1.1)
        warm = ImageEnhance.Brightness(warm).enhance(1.05)
        warm.save(os.path.join(output_dir, f"{base_name}_warm.png"))

        # 色调偏移（冷色调）
        cool = ImageEnhance.Color(img).enhance(0.9)
        cool = ImageEnhance.Brightness(cool).enhance(0.95)
        cool.save(os.path.join(output_dir, f"{base_name}_cool.png"))

    print(f"增强完成：原始 {len(os.listdir(input_dir))} 张 -> 增强后 {len(os.listdir(output_dir))} 张")


if __name__ == "__main__":
    augment_dataset("./cleaned_photos", "./augmented_photos")
```

## 八、完整数据准备流程总结

将以上所有步骤串联成一个完整的工程流程：

```
Step 1: 收集
  └─ 自拍/公开数据集/AI生成
      │
Step 2: 筛选
  └─ 肉眼筛选 → CLIP 评分 → 多样性检查
      │
Step 3: 预处理
  └─ 清洗 → 统一分辨率 → 裁剪/缩放
      │
Step 4: 标注
  └─ BLIP 生成描述 → WD Tagger 补充标签 → 人工审核 → 添加触发词
      │
Step 5: 组织
  └─ 按 kohya-ss 目录结构组织 → 创建正则化数据集
      │
Step 6: 增强
  └─ 翻转/色调调整 → 最终数据集
      │
Step 7: 验证
  └─ 检查文件完整性 → 预览标注质量 → 确认数据量
```

## 常见误区

### 误区一：数据越多越好

很多初学者认为收集几百张图片就能获得好效果。实际上，未经筛选的大量低质量图片反而会引入噪声，让训练结果变差。正确的做法是"少而精"——20 张精心准备的图片远胜于 200 张随手收集的图片。

### 误区二：标注可以随便写

标注是模型理解图像内容的唯一文本信号。一个标注写"cat sitting"的图片，模型就只学到"cat sitting"这个概念与图像的关联。如果标注不够详细，模型就无法学到图像中的丰富细节。建议标注长度至少 50 个 token。

### 误区三：不需要正则化数据集

对于 LoRA 训练，正则化数据集不是必须的，但强烈推荐。没有正则化，你的角色 LoRA 可能在任何 prompt 下都生成类似的角色特征——这被称为"概念泄漏"。使用 100-200 张正则化图片可以显著缓解这个问题。

### 误区四：数据增强会自动提升效果

过度的数据增强可能适得其反。例如对人脸数据做色调调整时，如果调整幅度过大，可能导致肤色失真，模型学到不自然的色彩分布。增强策略应保守使用，以水平翻转为主。

### 误区五：所有图片必须是正方形

这是过时的认知。kohya-ss 的 Aspect Ratio Bucketing 功能允许使用不同宽高比的图片。只要总像素数相近，不同尺寸的图片可以一起训练。这比强制裁剪为正方形能保留更多构图信息。

## 小结

本课的核心要点：

1. **数据质量决定训练上限**——精心筛选的少量数据优于随意收集的大量数据
2. **多样性是关键**——确保训练数据在角度、背景、光照等方面有足够变化
3. **标注质量与图片质量同等重要**——使用 BLIP + WD Tagger 组合，人工审核不可省略
4. **正则化防止知识侵蚀**——为角色类 LoRA 准备 100-200 张同类正则化图片
5. **数据增强需保守**——以水平翻转为主，避免过度变换

## 参考答案

### 练习一

**思路**：训练数据应覆盖目标物体的多角度、多场景，同时排除质量不佳和信息不完整的图片。

**答案**：

选择方案：
- 保留全部 5 张侧面照（角度多样，背景有变化）
- 保留全部 5 张细节照（特写有助于模型学习细节特征）
- 从 10 张正面照中选 5 张（去除背景完全相同的重复照片）

排除理由：
- 5 张骑行照：自行车被人遮挡，模型可能学到"自行车需要有人骑"的错误关联
- 5 张夜景照：光线不足导致细节丢失，噪声会干扰训练
- 5 张正面照（重复的）：背景和角度完全一致，属于冗余数据，增加其中 5 张不会带来新信息

**要点**：
- 多样性优先于数量
- 避免引入"自行车必须有人"或"自行车在车库"的隐性偏差
- 暗光/噪声图片会降低整体训练质量

### 练习二

**思路**：标注应以触发词开头，包含主体描述、场景信息、光照条件等关键细节，使用逗号分隔的标签式格式。

**答案**：

图片 1 标注：
```

bright lighting, side view, detailed frame, vintage style, high quality, 
sharp focus
```

图片 2 标注：
```

```

图片 3 标注：
```
ohwx bicycle, red bicycle, close-up, wheel spokes, brake system, 
detailed mechanical parts, metal texture, shallow depth of field, 
macro photography, high quality, sharp focus
```

**要点**：
- 触发词 `ohwx bicycle` 必须放在开头
- 使用自然语言描述 + 标签式关键词的混合风格
- 每条标注长度控制在 75 token 以内

### 练习三

**思路**：数据增强应保持角色核心特征不变，同时增加背景和构图的多样性。

**答案**：

推荐使用的增强：
- 水平翻转：增加左右朝向的多样性，不改变角色特征
- 轻微色调调整（±5%）：微小的色彩变化增加泛化能力，不会显著影响蓝发和红眼的识别

需要避免的增强：
- 大幅色调调整：可能改变蓝色头发的色调（变成紫色或绿色），破坏角色一致性
- 垂直翻转：动漫人物上下颠倒不符合视觉逻辑
- 大角度旋转：破坏构图，可能导致校服变形
- 模糊处理：动漫线条画的特点是清晰的轮廓线，模糊会破坏这种风格
- 对比度大幅调整：可能影响红眼的识别度

**要点**：
- 角色特征（发色、瞳色）是核心信息，增强不能破坏它们
- 动漫风格对线条清晰度要求高，避免模糊类增强
- 保守增强 + 更多原始高质量数据 是更好的策略
