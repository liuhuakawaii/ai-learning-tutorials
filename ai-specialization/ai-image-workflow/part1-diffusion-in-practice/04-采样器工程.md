# 第 4 课：采样器工程 — 速度与质量的博弈

## 场景引入

你已经理解了 Diffusion 的核心原理：从纯噪声一步步去噪，最终得到一张清晰的图像。但在实际使用中，你会发现一个关键问题——采样步数。

用 50 步采样，质量不错但要等 10 秒；用 20 步，速度快了一倍但细节糊了；有人说用 8 步就够了，但你试了一下，图像全是伪影。更让人困惑的是，ComfyUI 里有十几种采样器——Euler、DPM-Solver++、UniPC、DDIM……它们之间有什么区别？该选哪个？

本课将从工程角度拆解主流采样器的设计思路，帮你在速度和质量之间找到最佳平衡点。

## 一、采样问题的本质

### 1.1 为什么需要采样器

训练好的 Diffusion Model 本质上定义了一个从噪声到图像的"路径"。但这条路径有 1000 步（对应 T=1000 个时间步），每一步都需要调用一次 U-Net 推理。

```
完整采样（1000 步）：
  x_T → x_{T-1} → ... → x_1 → x_0
  │      │              │      │
  调用U-Net  调用U-Net    调用U-Net  调用U-Net
  ×1000 次

  时间成本 = 1000 × 单步推理时间
  RTX 3090 上约 150 秒——完全不可用
```

采样器的核心任务：**用尽可能少的步数，达到尽可能好的质量**。这本质上是一个数值求解微分方程的问题。

### 1.2 两种数学视角

```
┌─────────────────────────────────────────────────┐
│           采样的两种数学视角                        │
│                                                   │
│  ODE（常微分方程）视角：                             │
│    dx/dt = f(x, t)                                │
│    确定性路径，相同输入→相同输出                      │
│    Euler、DPM-Solver、UniPC 属于此类               │
│                                                   │
│  SDE（随机微分方程）视角：                           │
│    dx = f(x,t)dt + g(t)dw                         │
│    随机路径，相同输入→不同输出（有随机性）             │
│    DDPM、SDE-DPM-Solver 属于此类                   │
│                                                   │
│  工程直觉：                                        │
│    ODE → 确定性，适合需要一致性的场景（批量生产）     │
│    SDE → 随机性，适合需要多样性的场景（创意探索）     │
└─────────────────────────────────────────────────┘
```

## 二、主流采样器解析

### 2.1 Euler 采样器

Euler 方法是最简单的 ODE 求解器，本质是一阶欧拉法：

```python
import torch
import numpy as np

def euler_sampler(
    model,
    conditioning,
    num_steps=20,
    guidance_scale=7.5,
    device="cuda"
):
    """Euler 采样器的简化实现"""
    # 初始化纯噪声
    x = torch.randn(1, 4, 64, 64, device=device)

    # 时间步调度：从 T 到 0 均匀分割
    timesteps = torch.linspace(1.0, 0.0, num_steps + 1, device=device)

    for i in range(num_steps):
        t_curr = timesteps[i]
        t_next = timesteps[i + 1]
        dt = t_next - t_curr  # 负值（从高噪声到低噪声）

        # 模型预测（简化：预测噪声）
        noise_pred = model(x, t_curr, conditioning)

        # Classifier-Free Guidance
        noise_uncond = model(x, t_curr, None)
        noise_pred = noise_uncond + guidance_scale * (noise_pred - noise_uncond)

        # Euler 步：x_{t-1} = x_t + dt * f(x_t, t)
        # 其中 f(x_t, t) 是去噪方向
        x = x + dt * noise_pred

    return x
```

Euler 的特点：简单、快速，但在少步数时（<15 步）质量下降明显，因为一阶近似误差大。

### 2.2 DPM-Solver++ 系列

DPM-Solver（Denoising Probabilistic Model Solver）是专门为 Diffusion Model 设计的高阶求解器。它的核心思想是利用 Diffusion 过程的半线性结构，将 ODE 分解为两部分分别求解。

```
DPM-Solver++ 的核心思路：

  dx/dt = f(x, t)  →  分解为：
    线性部分：σ'(t)/σ(t) · x    （有解析解）
    非线性部分：ε_θ(x_t, t)      （需要近似）

  通过这种分解，可以用更少的步数达到更高的精度：
    Euler（一阶）：误差 O(h²)
    DPM-Solver++（二阶）：误差 O(h³)
    DPM-Solver++（三阶）：误差 O(h⁴)
```

    return x

### 2.3 UniPC：统一预测-校正框架

UniPC（Unified Predictor-Corrector）是 2023 年提出的采样器，核心创新是将预测器和校正器统一到一个框架中，在极少步数（5-8 步）下也能保持不错的质量。

```
UniPC 的工作流程：

  预测阶段（Predictor）：
    用多步历史信息做高阶外推，快速估计下一步
    ┌──────────────────────────────┐
    │ x_t → [多步外推] → x̂_{t-1}  │
    └──────────────────────────────┘

  校正阶段（Corrector）：
    用模型在 x̂_{t-1} 处的输出修正误差
    ┌──────────────────────────────┐
    │ x̂_{t-1} → [模型评估] → 修正  │
    └──────────────────────────────┘

  效果：5 步 UniPC ≈ 15 步 Euler 的质量
```

## 三、CFG Scale 与采样器的交互

### 3.1 Classifier-Free Guidance 的工作原理

```python
def apply_cfg(model, x, t, conditioning, guidance_scale):
    """Classifier-Free Guidance 的核心逻辑"""
    # 同时计算有条件和无条件预测
    # 实际实现中会 batch 在一起以节省计算
    noise_cond = model(x, t, conditioning)
    noise_uncond = model(x, t, null_conditioning)

    # CFG 公式：在有条件方向上做外推
    # guidance_scale > 1 时，增强条件控制
    noise_guided = noise_uncond + guidance_scale * (noise_cond - noise_uncond)

    return noise_guided
```

CFG Scale 的影响：

```
CFG Scale = 1.0：完全忽略文本条件，图像与 prompt 无关
CFG Scale = 3.0：轻微条件控制，色调柔和，细节丰富
CFG Scale = 7.0：标准值，平衡忠实度和多样性
CFG Scale = 12.0：强条件控制，颜色饱和、对比强烈
CFG Scale = 20.0：过度引导，出现伪影、过饱和

工程经验：
  - 写实照片：CFG 4-7
  - 插画/动漫：CFG 7-12
  - 概念艺术：CFG 7-10
  - 超高 CFG（>15）几乎总是产生伪影
```

### 3.2 Dynamic Thresholding

Stability AI 在 SD 2.1 中引入的技巧，允许使用更高的 CFG Scale 而不产生伪影：

```python
def dynamic_thresholding(noise_guided, percentile=0.995):
    """动态阈值：在高 CFG 下抑制过饱和"""
    # 将预测值的绝对值按百分位截断
    s = torch.quantile(
        noise_guided.abs().reshape(noise_guided.shape[0], -1),
        percentile,
        dim=-1
    )
    s = torch.clamp(s, min=1.0)
    noise_guided = noise_guided.clamp(-s, s) / s
    return noise_guided
```

## 四、工程实践：采样器调参

### 4.1 采样器 + 调度器组合

采样器和调度器（Scheduler）是两个独立的概念，经常被混淆：

```
采样器（Sampler）：决定"怎么走"（数值方法）
  Euler、DPM-Solver++、UniPC ...

调度器（Scheduler）：决定"走多大步"（时间步分配）
  Linear、Cosine、Karras、Exponential ...

常见组合：
  ┌────────────────────────────────────────────────┐
  │ 组合                          │ 效果            │
  ├────────────────────────────────────────────────┤
  │ DPM-Solver++ 2M + Karras      │ 最佳通用组合    │
  │ UniPC + Uniform               │ 少步数最优       │
  │ Euler + Karras                │ 快速预览         │
  │ DPM-Solver++ 3M + Exponential │ 高质量人像       │
  └────────────────────────────────────────────────┘
```

Karras 调度器的核心思想：在噪声变化最快的时间段（中间段）分配更密集的步数。

```python
def karras_schedule(num_steps, sigma_min=0.002, sigma_max=80.0, rho=7.0):
    """Karras 噪声调度：在中间区域分配更多步数"""
    # ρ 参数控制分布的"凸度"
    # ρ 越大，中间区域越密集
    ramp = torch.linspace(0, 1, num_steps)
    min_inv_rho = sigma_min ** (1 / rho)
    max_inv_rho = sigma_max ** (1 / rho)
    sigmas = (max_inv_rho + ramp * (min_inv_rho - max_inv_rho)) ** rho
    return sigmas
```

### 4.3 LCM / Turbo 模型：极速采样

2024 年出现的 LCM（Latent Consistency Models）和 Turbo 模型彻底改变了采样范式——它们通过特殊的蒸馏训练，将采样步数压缩到 4-8 步。

```
传统 Diffusion vs LCM/Turbo：

  传统模型：20-30 步，每步调用 U-Net
    推理时间 ≈ 2-3 秒

  LCM 蒸馏模型：4-8 步，跳步去噪
    推理时间 ≈ 0.3-0.5 秒

  SDXL Turbo：1-4 步，对抗蒸馏
    推理时间 ≈ 0.1-0.2 秒

  FLUX.1-schnell：4 步，引导蒸馏
    推理时间 ≈ 0.3 秒

工程影响：
  - 实时预览成为可能
  - 视频逐帧生成变得可行
  - 批量生产的成本大幅降低
```

## 五、常见误区

### 误区一：步数越多质量越好

步数存在边际收益递减。对于 DPM-Solver++ 2M，20 步和 50 步的差异肉眼几乎不可见，但时间差了一倍多。

### 误区二：换采样器不会影响画面风格

不同采样器在相同 seed 下会产生不同的图像。DPM-Solver++ 倾向于清晰锐利的细节，Euler Ancestral 倾向于更柔和的纹理。切换采样器时需要重新调整 prompt。

### 误区三：CFG Scale 和采样器无关

高 CFG Scale 会放大采样器的数值误差。Euler 在 CFG=15 时会出现明显伪影，而 DPM-Solver++ 在同样 CFG 下表现好得多。

### 误区四：所有模型都适合同一种采样器

SD 1.5 和 SDXL 的最优采样器配置不同。SDXL 对 DPM-Solver++ 2M + Karras 的适配最好；而 FLUX.1 模型推荐使用 Euler 或特殊的 FlowMatch 调度器。

## 六、小结

1. **采样器的本质**是用数值方法求解从噪声到图像的 ODE/SDE
2. **DPM-Solver++ 2M + Karras** 是当前最佳通用组合
3. **UniPC** 在极少步数（5-8 步）场景下表现最优
4. **CFG Scale** 需要根据内容类型和采样器联合调整
5. **LCM/Turbo** 模型将采样步数压缩到 4 步，适合实时场景

### 练习一

**思路**：固定所有变量（seed、prompt、model、CFG），只改变采样器和步数，用时间记录速度，用 CLIP Score 量化质量。

**答案**：

```python
import torch
from diffusers import StableDiffusionXLPipeline, EulerDiscreteScheduler
from diffusers import DPMSolverMultistepScheduler, UniPCMultistepScheduler
import time
from PIL import Image

def compare_samplers(prompt, num_inference_steps_list, seed=42):
    """采样器对比实验"""
    device = "cuda"
    pipe = StableDiffusionXLPipeline.from_pretrained(
        "stabilityai/stable-diffusion-xl-base-1.0",
        torch_dtype=torch.float16
    ).to(device)

    samplers = {
        "Euler": EulerDiscreteScheduler,
        "DPM++ 2M": DPMSolverMultistepScheduler,
        "UniPC": UniPCMultistepScheduler,
    }

    results = []

    for name, scheduler_cls in samplers.items():
        pipe.scheduler = scheduler_cls.from_config(pipe.scheduler.config)

        for steps in num_inference_steps_list:
            generator = torch.Generator(device).manual_seed(seed)

            start = time.time()
            image = pipe(
                prompt=prompt,
                num_inference_steps=steps,
                generator=generator,
                guidance_scale=7.0
            ).images[0]
            elapsed = time.time() - start

            image.save(f"output/{name}_{steps}steps.png")
            results.append({
                "sampler": name,
                "steps": steps,
                "time": round(elapsed, 2)
            })
            print(f"{name} | {steps} 步 | {elapsed:.2f}s")

    return results

prompt = "a ceramic vase on a wooden table, studio lighting, product photo"
compare_samplers(prompt, [10, 15, 20, 30])
```

**要点**：
- 每次切换采样器后要重新配置 scheduler
- 固定 seed 是公平对比的前提
- 记录时间的同时，保存图像用于主观评估

### 练习二

**思路**：实现 Linear 和 Karras 两种调度的 sigma 序列，用散点图可视化时间步分布。

**答案**：

```python
import torch
import matplotlib
matplotlib.use('Agg')
import matplotlib.pyplot as plt
import numpy as np

def linear_schedule(num_steps, sigma_min=0.002, sigma_max=80.0):
    """均匀调度：时间步等间距"""
    return torch.linspace(sigma_max, sigma_min, num_steps)

def karras_schedule(num_steps, sigma_min=0.002, sigma_max=80.0, rho=7.0):
    """Karras 调度：中间区域更密集"""
    ramp = torch.linspace(0, 1, num_steps)
    min_inv = sigma_min ** (1 / rho)
    max_inv = sigma_max ** (1 / rho)
    sigmas = (max_inv + ramp * (min_inv - max_inv)) ** rho
    return sigmas

def visualize_comparison(num_steps=20):
    linear_sigmas = linear_schedule(num_steps)
    karras_sigmas = karras_schedule(num_steps)

    fig, axes = plt.subplots(1, 2, figsize=(14, 5))

    # 左图：sigma 值对比
    axes[0].plot(linear_sigmas.numpy(), 'o-', label='Linear', linewidth=2)
    axes[0].plot(karras_sigmas.numpy(), 's-', label='Karras (ρ=7)', linewidth=2)
    axes[0].set_xlabel('步数索引')
    axes[0].set_ylabel('σ (噪声水平)')
    axes[0].set_title('噪声调度对比')
    axes[0].legend()
    axes[0].invert_yaxis()

    # 右图：步长（相邻 sigma 的差值）
    linear_diff = torch.abs(torch.diff(linear_sigmas))
    karras_diff = torch.abs(torch.diff(karras_sigmas))
    axes[1].bar(range(len(linear_diff)), linear_diff.numpy(), alpha=0.5, label='Linear')
    axes[1].bar(range(len(karras_diff)), karras_diff.numpy(), alpha=0.5, label='Karras')
    axes[1].set_xlabel('步数索引')
    axes[1].set_ylabel('步长 |Δσ|')
    axes[1].set_title('每步噪声变化量对比')
    axes[1].legend()

    plt.tight_layout()
    plt.savefig('sampler_schedule_comparison.png', dpi=150)
    plt.close()

    print("Karras 调度在中间区域（噪声变化最快）分配了更密集的步数")
    print("这意味着中间阶段的去噪精度更高，而首尾阶段可以粗略跳过")

visualize_comparison()
```

**要点**：
- Karras 的 ρ 参数控制分布的凸度，ρ=7 是论文推荐值
- 噪声变化最快的区域对应图像结构形成的阶段，需要更多步数
- Linear 调度在首尾浪费了步数（尾部噪声几乎为零，首部变化极小）
