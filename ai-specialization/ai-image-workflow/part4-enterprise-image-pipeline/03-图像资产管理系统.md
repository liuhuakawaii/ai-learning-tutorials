# 第三课：AI 图像资产管理系统

## 场景引入

某电商公司的设计团队每天产出 200+ 张产品图、Banner、营销素材。设计师小张需要找到上个月为"夏季促销"活动生成的一组粉色系主图，但他只记得"粉色""夏天""主图"这几个关键词。他在公司共享盘里翻了半小时，文件夹命名混乱、版本交错，最终找到的还是一个被覆盖过的旧版本。

与此同时，运营团队需要把同一张产品图裁剪成 5 种尺寸（主图、详情页、缩略图、移动端、社交分享），每次都要手动处理。市场部要做 A/B 测试，需要同一张图的 3 种色调变体，但找不到原始生成参数。

这些痛点指向同一个核心问题：**当 AI 图像生成成为日常工作流，企业需要的不只是"能生成图"，而是"能管好生成的图"。** 这就是图像资产管理系统（Image Asset Management System）要解决的问题。

传统 DAM（Digital Asset Management）系统面向设计师手动上传的少量素材，而 AI 时代的企业图像管线面临三个新挑战：

1. **量级爆炸**：AI 生成让图像产出从每天几张变成每天几百张
2. **元数据丰富**：每张图携带 prompt、模型、种子、LoRA 等生成参数，这些参数本身就是检索和复用的关键
3. **变体链路**：一张原图可能衍生出数十个裁剪、调色、风格化变体，需要追溯血缘关系

本课将从零构建一个面向 AI 生成图像的企业级资产管理系统，涵盖元数据管理、版本控制、语义搜索、存储策略和 API 设计。

## 学习目标

完成本课后，你将能够：

1. 设计面向 AI 图像的元数据 Schema，覆盖生成参数、业务标签、使用权限
2. 实现图像版本控制和变体管理，追溯任意图像的生成血缘
3. 构建基于 CLIP 的语义搜索系统，支持"以文搜图"和"以图搜图"
4. 设计对象存储 + CDN 的分层存储策略，平衡成本与访问速度
5. 设计 RESTful API 接口，支持图像资产的 CRUD、批量操作和权限控制

### 二、图像元数据管理

AI 生成图像的元数据远比传统图片丰富。一个完整的元数据 Schema 需要覆盖三个维度：

```
图像元数据
├── 基础信息
│   ├── asset_id        (UUID，全局唯一标识)
│   ├── filename        (原始文件名)
│   ├── format          (PNG/JPEG/WebP)
│   ├── width / height  (像素尺寸)
│   ├── file_size       (字节大小)
│   ├── checksum        (SHA-256，用于去重)
│   └── created_at      (入库时间)
│
├── AI 生成参数 (核心差异化)
│   ├── prompt          (正向提示词)
│   ├── negative_prompt (反向提示词)
│   ├── model           (模型名称，如 SDXL 1.0)
│   ├── sampler         (采样器，如 Euler a)
│   ├── steps           (采样步数)
│   ├── cfg_scale       (引导强度)
│   ├── seed            (随机种子)
│   ├── lora_weights    (LoRA 权重列表)
│   └── workflow_json   (ComfyUI 工作流 JSON)
│
└── 业务元数据
    ├── tags            (业务标签列表)
    ├── category        (业务分类)
    ├── project         (所属项目)
    ├── usage_rights    (使用权限)
    ├── expiry_date     (过期时间)
    └── created_by      (创建者)
```

下面实现元数据的核心数据模型：

```python
import uuid
import hashlib
from datetime import datetime
from dataclasses import dataclass, field
from typing import Optional


@dataclass
class AIGenerationParams:
    """AI 生成参数，记录从 prompt 到最终输出的完整生成链路"""
    prompt: str
    negative_prompt: str = ""
    model: str = "sdxl-1.0"
    sampler: str = "euler_a"
    steps: int = 30
    cfg_scale: float = 7.0
    seed: int = -1
    lora_weights: dict[str, float] = field(default_factory=dict)
    workflow_json: Optional[str] = None

    def to_prompt_signature(self) -> str:
        """生成用于去重的 prompt 签名：相同 prompt + 相同模型 + 相同种子 = 同一张图"""
        signature_parts = [self.prompt, self.model, str(self.seed)]
        return "|".join(signature_parts)


@dataclass
class ImageAsset:
    """图像资产的核心数据模型"""
    asset_id: str = field(default_factory=lambda: str(uuid.uuid4()))
    filename: str = ""
    format: str = "png"
    width: int = 0
    height: int = 0
    file_size: int = 0
    checksum: str = ""
    created_at: datetime = field(default_factory=datetime.now)

    generation_params: Optional[AIGenerationParams] = None
    tags: list[str] = field(default_factory=list)
    category: str = ""
    project: str = ""
    usage_rights: str = "internal"
    expiry_date: Optional[datetime] = None
    created_by: str = ""
    parent_id: Optional[str] = None

    def compute_checksum(self, file_bytes: bytes) -> str:
        """计算文件的 SHA-256 校验和，用于去重检测"""
        self.checksum = hashlib.sha256(file_bytes).hexdigest()
        return self.checksum

    def is_duplicate(self, other_checksum: str) -> bool:
        """通过校验和判断是否与已有资产重复"""
        return self.checksum != "" and self.checksum == other_checksum
```

**为什么用 SHA-256 而不是 MD5？** MD5 存在碰撞风险，当资产库规模达到百万级时，误判概率不可忽略。SHA-256 的碰撞概率在实际场景中可以忽略不计。

**为什么 `seed` 是去重签名的一部分？** 相同的 prompt 在相同模型和种子下会生成相同的图像（确定性生成）。但不同种子会产生不同图像，即使 prompt 完全一致。这个签名机制帮助运营人员识别"撞图"——不同设计师用相同 prompt 碰巧生成了相同结果。

### 三、版本控制和变体管理

AI 图像资产的生命周期不是"一次生成、永久使用"。一张产品主图可能经历：

```
原始图 (v1)
  ├── 调色变体 (v1-warm)
  │     └── 裁剪为移动端尺寸 (v1-warm-mobile)
  ├── 风格化变体 (v1-sketch)
  └── 文字叠加变体 (v1-with-text)
        ├── A 版本标题 (v1-with-text-a)
        └── B 版本标题 (v1-with-text-b)
```

这是一棵树结构。我们需要一个有向无环图（DAG）来追踪每个变体的来源：

```python
from enum import Enum
from datetime import datetime


class VariantType(str, Enum):
    REGENERATE = "regenerate"      # 重新生成（改变 seed 或 prompt）
    CROP = "crop"                  # 裁剪
    COLOR_ADJUST = "color_adjust"  # 调色
    STYLE_TRANSFER = "style"       # 风格迁移
    TEXT_OVERLAY = "text_overlay"  # 文字叠加
    UPSCALE = "upscale"            # 超分辨率
    FORMAT_CONVERT = "format"      # 格式转换


class VersionNode:
    """版本树中的一个节点，代表一个图像资产的一个版本或变体"""

    def __init__(self, asset_id: str, version_tag: str,
                 variant_type: VariantType = VariantType.REGENERATE,
                 parent_node: "VersionNode | None" = None):
        self.asset_id = asset_id
        self.version_tag = version_tag
        self.variant_type = variant_type
        self.parent_node = parent_node
        self.children: list["VersionNode"] = []
        self.created_at = datetime.now()
        self.change_description = ""

        if parent_node is not None:
            parent_node.children.append(self)

    def get_lineage(self) -> list[str]:
        """回溯完整的版本血缘链，从当前节点到根节点"""
        lineage = [self.version_tag]
        current = self.parent_node
        while current is not None:
            lineage.append(current.version_tag)
            current = current.parent_node
        lineage.reverse()
        return lineage

    def get_all_descendants(self) -> list["VersionNode"]:
        """获取所有后代节点（广度优先遍历）"""
        descendants = []
        queue = list(self.children)
        while queue:
            node = queue.pop(0)
            descendants.append(node)
            queue.extend(node.children)
        return descendants

    def find_by_variant_type(self, target_type: VariantType) -> list["VersionNode"]:
        """在后代中查找特定类型的变体"""
        return [d for d in self.get_all_descendants()
                if d.variant_type == target_type]


class VersionTree:
    """管理一个资产的完整版本树"""

    def __init__(self):
        self.roots: dict[str, VersionNode] = {}
        self.nodes: dict[str, VersionNode] = {}

    def add_version(self, asset_id: str, version_tag: str,
                    variant_type: VariantType = VariantType.REGENERATE,
                    parent_tag: str | None = None) -> VersionNode:
        """添加新版本节点。如果指定了 parent_tag，将其挂载为子节点"""
        parent_node = self.nodes.get(parent_tag) if parent_tag else None
        node = VersionNode(asset_id, version_tag, variant_type, parent_node)
        self.nodes[version_tag] = node

        if parent_node is None:
            self.roots[version_tag] = node
        return node

    def get_tree_visualization(self, root_tag: str) -> str:
        """以 ASCII 树形图展示版本结构"""
        root = self.nodes.get(root_tag)
        if root is None:
            return f"版本 {root_tag} 不存在"

        lines = []
        self._build_tree_lines(root, lines, prefix="", is_last=True)
        return "\n".join(lines)

    def _build_tree_lines(self, node: VersionNode, lines: list[str],
                          prefix: str, is_last: bool):
        """递归构建树形图的每一行"""
        connector = "└── " if is_last else "├── "
        label = f"{node.version_tag} [{node.variant_type.value}]"
        lines.append(f"{prefix}{connector}{label}")

        child_prefix = prefix + ("    " if is_last else "│   ")
        for i, child in enumerate(node.children):
            self._build_tree_lines(
                child, lines, child_prefix, i == len(node.children) - 1
            )


if __name__ == "__main__":
    tree = VersionTree()
    v1 = tree.add_version("img-001", "v1", VariantType.REGENERATE)
    v1_warm = tree.add_version(
        "img-002", "v1-warm", VariantType.COLOR_ADJUST, "v1"
    )
    v1_warm.change_description = "暖色调调整"
    v1_warm_mobile = tree.add_version(
        "img-003", "v1-warm-mobile", VariantType.CROP, "v1-warm"
    )
    v1_warm_mobile.change_description = "裁剪为 750x1334 移动端尺寸"
    v1_sketch = tree.add_version(
        "img-004", "v1-sketch", VariantType.STYLE_TRANSFER, "v1"
    )
    v1_text = tree.add_version(
        "img-005", "v1-with-text", VariantType.TEXT_OVERLAY, "v1"
    )
    tree.add_version("img-006", "v1-text-a", VariantType.TEXT_OVERLAY, "v1-with-text")
    tree.add_version("img-007", "v1-text-b", VariantType.TEXT_OVERLAY, "v1-with-text")

    print(tree.get_tree_visualization("v1"))
    print()
    print(f"v1-warm-mobile 的血缘链: {v1_warm_mobile.get_lineage()}")
    print(f"v1 下所有裁剪变体: {v1.find_by_variant_type(VariantType.CROP)}")
```

```
        └── v1-text-b [text_overlay]

```

### 四、标签和分类系统

标签系统是连接"AI 生成逻辑"和"业务使用逻辑"的桥梁。设计师按 prompt 思维找图（"赛博朋克风格的城市夜景"），运营按业务思维找图（"618 促销主图"）。好的标签系统需要同时服务两种思维模式。

```
标签体系
├── 视觉标签 (自动提取 + 人工校验)
│   ├── 色调：暖色 / 冷色 / 莫兰迪 / 高饱和
│   ├── 构图：居中 / 三分法 / 留白 / 满铺
│   ├── 风格：写实 / 插画 / 扁平 / 3D / 赛博朋克
│   └── 元素：人物 / 产品 / 场景 / 文字
│
├── 业务标签 (人工标注)
│   ├── 项目：618大促 / 品牌升级 / 新品上市
│   ├── 渠道：主图 / 详情页 / Banner / 社交媒体
│   ├── 状态：待审核 / 已通过 / 已发布 / 已过期
│   └── 优先级：核心素材 / 常规素材 / 备选素材
│
└── AI 标签 (模型自动标注)
    ├── 美学评分：0.0 ~ 1.0
    ├── 安全等级：safe / sensitive / unsafe
    └── 相似度簇：与其他资产的相似度分组
```

下面实现一个分层标签管理器：

```python
from dataclasses import dataclass, field
from enum import Enum


class TagCategory(str, Enum):
    VISUAL = "visual"
    BUSINESS = "business"
    AI = "ai"


@dataclass
class Tag:
    name: str
    category: TagCategory
    confidence: float = 1.0
    source: str = "manual"  # manual / auto / model


class TagManager:
    """分层标签管理器，支持自动标签和手动标签的混合管理"""

    # 预定义的视觉标签词表，用于标准化自动提取结果
    VISUAL_VOCABULARY = {
        "色调": ["暖色", "冷色", "莫兰迪", "高饱和", "低饱和", "黑白", "单色"],
        "构图": ["居中", "三分法", "留白", "满铺", "对角线", "对称"],
        "风格": ["写实", "插画", "扁平", "3D", "赛博朋克", "水彩", "油画", "极简"],
        "元素": ["人物", "产品", "场景", "文字", "图标", "纹理", "渐变"],
    }

    def __init__(self):
        self.tags: dict[str, list[Tag]] = {}
        self.inverted_index: dict[str, list[str]] = {}

    def add_tag(self, asset_id: str, tag: Tag) -> None:
        """为资产添加标签，并更新倒排索引"""
        if asset_id not in self.tags:
            self.tags[asset_id] = []
        self.tags[asset_id].append(tag)

        normalized_name = tag.name.lower()
        if normalized_name not in self.inverted_index:
            self.inverted_index[normalized_name] = []
        if asset_id not in self.inverted_index[normalized_name]:
            self.inverted_index[normalized_name].append(asset_id)

    def auto_tag_from_prompt(self, asset_id: str, prompt: str) -> list[Tag]:
        """从 prompt 中自动提取视觉标签。这是一个简化版本，
        生产环境中通常使用 NLP 模型或规则引擎进行更精确的提取"""
        generated_tags = []
        prompt_lower = prompt.lower()

        for category, keywords in self.VISUAL_VOCABULARY.items():
            for keyword in keywords:
                if keyword in prompt_lower:
                    tag = Tag(
                        name=keyword,
                        category=TagCategory.VISUAL,
                        confidence=0.8,
                        source="auto"
                    )
                    self.add_tag(asset_id, tag)
                    generated_tags.append(tag)

        return generated_tags

    def search_by_tags(self, tag_names: list[str],
                       match_all: bool = True) -> list[str]:
        """通过标签搜索资产。match_all=True 表示 AND 逻辑，False 表示 OR 逻辑"""
        if not tag_names:
            return []

        normalized_names = [name.lower() for name in tag_names]
        result_sets = [
            set(self.inverted_index.get(name, []))
            for name in normalized_names
        ]

        if match_all:
            return list(set.intersection(*result_sets)) if result_sets else []
        else:
            return list(set.union(*result_sets)) if result_sets else []

    def get_tag_statistics(self) -> dict[str, int]:
        """统计每个标签的使用频次，用于发现高频标签和清理低频标签"""
        stats: dict[str, int] = {}
        for asset_tags in self.tags.values():
            for tag in asset_tags:
                stats[tag.name] = stats.get(tag.name, 0) + 1
        return dict(sorted(stats.items(), key=lambda x: x[1], reverse=True))


if __name__ == "__main__":
    manager = TagManager()

    prompt1 = "a cyberpunk city at night, neon lights, high saturation"
    prompt2 = "minimalist product photo on white background, centered composition"
    prompt3 = "warm color palette cozy living room illustration"

    manager.auto_tag_from_prompt("asset-001", prompt1)
    manager.auto_tag_from_prompt("asset-002", prompt2)
    manager.auto_tag_from_prompt("asset-003", prompt3)

    manager.add_tag("asset-001", Tag("618大促", TagCategory.BUSINESS, source="manual"))
    manager.add_tag("asset-001", Tag("Banner", TagCategory.BUSINESS, source="manual"))
    manager.add_tag("asset-002", Tag("新品上市", TagCategory.BUSINESS, source="manual"))

    print("搜索赛博朋克风格的资产:", manager.search_by_tags(["赛博朋克"]))
    print("搜索 618 大促的 Banner:", manager.search_by_tags(["618大促", "Banner"]))
    print("搜索暖色或插画:", manager.search_by_tags(["暖色", "插画"], match_all=False))
    print("标签统计:", manager.get_tag_statistics())
```

### 五、基于 CLIP 的语义搜索

关键词搜索的局限性很明显：用户搜"一只橘猫在阳光下打盹"，但资产库里标记的是"猫咪""午后""温暖"。关键词匹配无法理解语义相似性。CLIP（Contrastive Language-Image Pre-training）模型将文本和图像映射到同一个向量空间，使得"以文搜图"和"以图搜图"成为可能。

```
语义搜索流程
                                                    ┌─────────────┐
                                                    │  向量数据库   │
                                                    │  (Milvus)    │
+----------+    +----------+    +----------+         │             │
| 用户查询  |--->| CLIP 编码 |--->| 查询向量  |-------->| 向量相似度  |
| "橘猫晒太阳"|   | (文本)   |    | [0.2, ...] |         | 检索 Top-K  |
+----------+    +----------+    +----------+         │             |
                                                      │  +--------+ |
+----------+    +----------+    +----------+         |  | 索引向量| |
| 入库图像  |--->| CLIP 编码 |--->| 存储向量  |-------->|  | [0.18..| |
| (批量)   |    | (图像)   |    | + 元数据  |         |  |  0.21..| |
+----------+    +----------+    +----------+         |  +--------+ |
                                                      └─────────────┘
```

下面实现一个完整的 CLIP 语义搜索引擎：

```python
import numpy as np
from dataclasses import dataclass, field
from typing import Optional


@dataclass
class SearchResult:
    """搜索结果，包含资产 ID、相似度分数和附加元数据"""
    asset_id: str
    score: float
    filename: str = ""
    tags: list[str] = field(default_factory=list)
    thumbnail_url: str = ""


class CLIPEmbeddingEngine:
    """CLIP 嵌入引擎的封装。生产环境使用真实的 CLIP 模型，
    此处用简化实现展示核心逻辑"""

    def __init__(self, embedding_dim: int = 512):
        self.embedding_dim = embedding_dim

    def encode_text(self, text: str) -> np.ndarray:
        """将文本编码为向量。真实实现调用 CLIP 的 text encoder"""
        seed = hash(text) % (2**31)
        rng = np.random.RandomState(seed)
        embedding = rng.randn(self.embedding_dim).astype(np.float32)
        embedding = embedding / np.linalg.norm(embedding)
        return embedding

    def encode_image(self, image_bytes: bytes) -> np.ndarray:
        """将图像编码为向量。真实实现调用 CLIP 的 vision encoder"""
        seed = hash(image_bytes[:64]) % (2**31)
        rng = np.random.RandomState(seed)
        embedding = rng.randn(self.embedding_dim).astype(np.float32)
        embedding = embedding / np.linalg.norm(embedding)
        return embedding


class VectorIndex:
    """简易向量索引。生产环境替换为 Milvus / Qdrant / Pinecone"""

    def __init__(self, dimension: int = 512):
        self.dimension = dimension
        self.vectors: dict[str, np.ndarray] = {}
        self.metadata: dict[str, dict] = {}

    def insert(self, asset_id: str, vector: np.ndarray,
               metadata: dict | None = None) -> None:
        """插入一条向量记录"""
        self.vectors[asset_id] = vector
        self.metadata[asset_id] = metadata or {}

    def batch_insert(self, entries: list[tuple[str, np.ndarray, dict]]) -> None:
        """批量插入向量记录，减少逐条插入的开销"""
        for asset_id, vector, metadata in entries:
            self.insert(asset_id, vector, metadata)

    def search(self, query_vector: np.ndarray, top_k: int = 10,
               threshold: float = 0.0) -> list[tuple[str, float]]:
        """使用余弦相似度进行最近邻搜索"""
        if not self.vectors:
            return []

        asset_ids = list(self.vectors.keys())
        matrix = np.stack([self.vectors[aid] for aid in asset_ids])
        similarities = matrix @ query_vector

        indexed_scores = list(enumerate(similarities))
        indexed_scores.sort(key=lambda x: x[1], reverse=True)

        results = []
        for idx, score in indexed_scores[:top_k]:
            if score >= threshold:
                results.append((asset_ids[idx], float(score)))
        return results

    def get_asset_count(self) -> int:
        return len(self.vectors)


class SemanticImageSearchEngine:
    """语义图像搜索引擎，整合 CLIP 编码和向量检索"""

    def __init__(self, embedding_dim: int = 512):
        self.clip_engine = CLIPEmbeddingEngine(embedding_dim)
        self.vector_index = VectorIndex(embedding_dim)
        self.asset_metadata: dict[str, dict] = {}

    def index_asset(self, asset_id: str, image_bytes: bytes,
                    filename: str = "", tags: list[str] | None = None,
                    extra_metadata: dict | None = None) -> None:
        """将一个图像资产索引到搜索引擎"""
        vector = self.clip_engine.encode_image(image_bytes)
        metadata = {
            "filename": filename,
            "tags": tags or [],
            **(extra_metadata or {}),
        }
        self.vector_index.insert(asset_id, vector, metadata)
        self.asset_metadata[asset_id] = metadata

    def search_by_text(self, query: str, top_k: int = 10,
                       threshold: float = 0.0) -> list[SearchResult]:
        """以文搜图：将文本查询编码后在向量空间中检索最近的图像"""
        query_vector = self.clip_engine.encode_text(query)
        raw_results = self.vector_index.search(query_vector, top_k, threshold)

        search_results = []
        for asset_id, score in raw_results:
            meta = self.asset_metadata.get(asset_id, {})
            search_results.append(SearchResult(
                asset_id=asset_id,
                score=score,
                filename=meta.get("filename", ""),
                tags=meta.get("tags", []),
            ))
        return search_results

    def search_by_image(self, image_bytes: bytes, top_k: int = 10,
                        threshold: float = 0.0) -> list[SearchResult]:
        """以图搜图：将查询图像编码后在向量空间中检索相似图像"""
        query_vector = self.clip_engine.encode_image(image_bytes)
        raw_results = self.vector_index.search(query_vector, top_k, threshold)

        search_results = []
        for asset_id, score in raw_results:
            meta = self.asset_metadata.get(asset_id, {})
            search_results.append(SearchResult(
                asset_id=asset_id,
                score=score,
                filename=meta.get("filename", ""),
                tags=meta.get("tags", []),
            ))
        return search_results

    def hybrid_search(self, text_query: str, tag_filter: list[str] | None = None,
                      top_k: int = 10) -> list[SearchResult]:
        """混合搜索：先通过语义检索获取候选集，再用标签过滤精排"""
        candidates = self.search_by_text(text_query, top_k=top_k * 3)

        if tag_filter:
            tag_set = set(tag_filter)
            candidates = [
                r for r in candidates
                if tag_set.intersection(set(r.tags))
            ]

        return candidates[:top_k]
```

### 六、存储策略：对象存储 + CDN

图像资产的存储需要在成本、访问速度和可用性之间取得平衡。不同生命周期阶段的图像应采用不同的存储层：

```
存储分层策略

  +------------------+     +------------------+     +------------------+
  |    热存储层       |     |    温存储层       |     |    冷存储层       |
  |  (SSD + CDN)     |     |  (标准对象存储)   |     |  (归档存储)       |
  +------------------+     +------------------+     +------------------+
  | 最近 30 天的     |     | 30-180 天的      |     | 180 天以上的      |
  | 高频访问素材     |     | 中频访问素材     |     | 低频访问素材      |
  +------------------+     +------------------+     +------------------+
  | 读延迟: <50ms    |     | 读延迟: <200ms   |     | 读延迟: 秒级      |
  | 存储成本: ¥1.5/GB|     | 存储成本: ¥0.12/GB|    | 存储成本: ¥0.03/GB|
  | CDN 加速: 是     |     | CDN 加速: 可选   |     | CDN 加速: 否      |
  +------------------+     +------------------+     +------------------+
```

下面实现存储策略管理器：

```python
import os
import shutil
from datetime import datetime, timedelta
from enum import Enum
from dataclasses import dataclass
from pathlib import Path
from typing import Optional


class StorageTier(str, Enum):
    HOT = "hot"        # 热存储：SSD 本地 + CDN 分发
    WARM = "warm"      # 温存储：标准对象存储
    COLD = "cold"      # 冷存储：归档存储


@dataclass
class StorageConfig:
    """存储层配置"""
    tier: StorageTier
    local_path: str
    max_size_gb: float
    cdn_enabled: bool
    cdn_base_url: str = ""
    lifecycle_days: int = 30  # 在此层停留的最大天数
    cost_per_gb_month: float = 0.0


class StoragePolicyEngine:
    """存储策略引擎：根据访问频率和资产生命周期自动管理存储层迁移"""

    TIER_CONFIGS = {
        StorageTier.HOT: StorageConfig(
            tier=StorageTier.HOT,
            local_path="./storage/hot",
            max_size_gb=50.0,
            cdn_enabled=True,
            cdn_base_url="https://cdn.example.com/hot/",
            lifecycle_days=30,
            cost_per_gb_month=1.5,
        ),
        StorageTier.WARM: StorageConfig(
            tier=StorageTier.WARM,
            local_path="./storage/warm",
            max_size_gb=500.0,
            cdn_enabled=False,
            lifecycle_days=180,
            cost_per_gb_month=0.12,
        ),
        StorageTier.COLD: StorageConfig(
            tier=StorageTier.COLD,
            local_path="./storage/cold",
            max_size_gb=5000.0,
            cdn_enabled=False,
            lifecycle_days=365 * 3,
            cost_per_gb_month=0.03,
        ),
    }

    def __init__(self, base_path: str = "./storage"):
        self.base_path = Path(base_path)
        self.asset_tier_map: dict[str, StorageTier] = {}
        self.asset_access_times: dict[str, datetime] = {}
        self.asset_upload_times: dict[str, datetime] = {}
        self.access_counts: dict[str, int] = {}

        for tier_config in self.TIER_CONFIGS.values():
            (self.base_path / tier_config.tier.value).mkdir(
                parents=True, exist_ok=True
            )

    def store_asset(self, asset_id: str, file_bytes: bytes,
                    filename: str) -> tuple[StorageTier, str]:
        """存储一个资产到热存储层，返回存储层和访问 URL"""
        tier = StorageTier.HOT
        tier_path = self.base_path / tier.value / filename
        tier_path.write_bytes(file_bytes)

        self.asset_tier_map[asset_id] = tier
        self.asset_upload_times[asset_id] = datetime.now()
        self.asset_access_times[asset_id] = datetime.now()
        self.access_counts[asset_id] = 1

        config = self.TIER_CONFIGS[tier]
        url = f"{config.cdn_base_url}{filename}" if config.cdn_enabled else str(tier_path)
        return tier, url

    def access_asset(self, asset_id: str, filename: str) -> tuple[str, str]:
        """访问一个资产，更新访问时间，并决定是否需要提升存储层"""
        self.asset_access_times[asset_id] = datetime.now()
        self.access_counts[asset_id] = self.access_counts.get(asset_id, 0) + 1

        current_tier = self.asset_tier_map.get(asset_id, StorageTier.COLD)
        new_tier = self._evaluate_tier_promotion(asset_id, current_tier)

        if new_tier != current_tier:
            self._migrate_asset(asset_id, filename, current_tier, new_tier)
            current_tier = new_tier

        config = self.TIER_CONFIGS[current_tier]
        file_path = self.base_path / current_tier.value / filename
        url = f"{config.cdn_base_url}{filename}" if config.cdn_enabled else str(file_path)
        return str(file_path), url

    def _evaluate_tier_promotion(self, asset_id: str,
                                 current_tier: StorageTier) -> StorageTier:
        """根据最近访问频率评估是否需要将资产提升到更热的存储层"""
        access_count = self.access_counts.get(asset_id, 0)
        last_access = self.asset_access_times.get(asset_id)

        if last_access is None:
            return current_tier

        days_since_access = (datetime.now() - last_access).days

        if current_tier == StorageTier.COLD and access_count > 5 and days_since_access < 7:
            return StorageTier.WARM
        if current_tier == StorageTier.WARM and access_count > 20 and days_since_access < 3:
            return StorageTier.HOT
        return current_tier

    def _migrate_asset(self, asset_id: str, filename: str,
                       from_tier: StorageTier, to_tier: StorageTier) -> None:
        """在存储层之间迁移资产文件"""
        src = self.base_path / from_tier.value / filename
        dst = self.base_path / to_tier.value / filename
        if src.exists():
            shutil.move(str(src), str(dst))
        self.asset_tier_map[asset_id] = to_tier

    def run_lifecycle_policy(self) -> dict[str, list[str]]:
        """执行生命周期策略：将长时间未访问的资产降级到更冷的存储层"""
        migration_plan: dict[str, list[str]] = {
            "hot_to_warm": [],
            "warm_to_cold": [],
        }
        now = datetime.now()

        for asset_id, tier in self.asset_tier_map.items():
            last_access = self.asset_access_times.get(asset_id, now)
            days_idle = (now - last_access).days

            if tier == StorageTier.HOT and days_idle > self.TIER_CONFIGS[StorageTier.HOT].lifecycle_days:
                migration_plan["hot_to_warm"].append(asset_id)
            elif tier == StorageTier.WARM and days_idle > self.TIER_CONFIGS[StorageTier.WARM].lifecycle_days:
                migration_plan["warm_to_cold"].append(asset_id)

        return migration_plan

    def get_storage_report(self) -> dict:
        """生成存储使用报告"""
        tier_counts: dict[str, int] = {t.value: 0 for t in StorageTier}
        for tier in self.asset_tier_map.values():
            tier_counts[tier.value] += 1

        total_monthly_cost = 0.0
        for tier, count in tier_counts.items():
            config = self.TIER_CONFIGS[StorageTier(tier)]
            total_monthly_cost += count * 0.01 * config.cost_per_gb_month

        return {
            "tier_distribution": tier_counts,
            "total_assets": len(self.asset_tier_map),
            "estimated_monthly_cost": round(total_monthly_cost, 2),
        }


if __name__ == "__main__":
    engine = StoragePolicyEngine()

    for i in range(5):
        asset_id = f"asset-{i:03d}"
        filename = f"image_{i:03d}.png"
        file_bytes = os.urandom(1024 * (i + 1))
        tier, url = engine.store_asset(asset_id, file_bytes, filename)
        print(f"存储 {asset_id} -> {tier.value} 层, URL: {url}")

    print("\n存储报告:", engine.get_storage_report())

    plan = engine.run_lifecycle_policy()
    print("\n生命周期迁移计划:", plan)
```

### 七、API 接口设计

资产管理系统对外暴露 RESTful API，核心设计原则：

1. **资源命名用复数**：`/assets` 而不是 `/asset`
2. **版本号在 URL 路径中**：`/api/v1/assets`
3. **批量操作用独立端点**：`/api/v1/assets/batch`
4. **搜索用 POST 而不是 GET**：搜索条件复杂，不适合放在 query string

下面是一个完整的 FastAPI 实现：

```python
@app.post("/api/v1/assets/batch")
async def batch_operation(request: BatchOperationRequest):
    """批量操作资产。支持的 operation: archive, tag, delete"""
    processed = []
    errors = []

    for asset_id in request.asset_ids:
        asset = _asset_store.get(asset_id)
        if not asset:
            errors.append({"asset_id": asset_id, "error": "不存在"})
            continue

        if request.operation == "archive":
            asset["status"] = AssetStatus.ARCHIVED.value
            processed.append(asset_id)
        elif request.operation == "tag":
            new_tags = request.params.get("tags", [])
            asset["tags"] = list(set(asset.get("tags", []) + new_tags))
            processed.append(asset_id)
        elif request.operation == "delete":
            del _asset_store[asset_id]
            processed.append(asset_id)
        else:
            errors.append({"asset_id": asset_id, "error": f"不支持的操作: {request.operation}"})

    return {
        "operation": request.operation,
        "processed_count": len(processed),
        "error_count": len(errors),
        "processed": processed,
        "errors": errors,
    }
```

**API 设计要点解析：**

1. **为什么搜索用 POST 而不是 GET？** 搜索条件包含数组（tag_filter）和嵌套对象，放在 query string 中会导致 URL 过长且难以解析。POST + JSON body 更清晰。

2. **为什么批量操作用独立端点？** 批量操作的语义和单个操作不同——它需要原子性保证（部分失败时如何处理）和不同的错误处理策略。独立端点让这些差异在 API 层面就体现出来。

3. **为什么 PATCH 而不是 PUT？** 资产更新通常只修改部分字段（如只更新标签），PATCH 的语义更准确。PUT 要求客户端发送完整资源表示，容易导致意外覆盖。

## 常见误区

### 误区一：用文件系统目录结构代替数据库管理元数据

很多团队初期用"项目名/日期/类型"的目录结构来组织图像资产。当资产规模超过几千张时，目录结构的局限性立刻暴露：一个资产无法同时属于多个分类，标签查询需要遍历文件系统，权限控制几乎不可能实现。

**正确做法：** 文件系统只负责物理存储，所有逻辑关系（分类、标签、权限、版本）都通过数据库管理。文件名用 UUID 命名，原始文件名作为元数据存储。

### 误区二：把所有元数据塞进一个字段

有些人设计数据库时用一个 JSON 字段存储所有元数据。这在小规模时可行，但当需要按"模型"筛选、按"seed"去重、按"prompt"做全文搜索时，JSON 字段的查询性能和索引能力远不如结构化列。

**正确做法：** 高频查询字段（model、seed、category、status）用独立列并建索引；低频或结构不固定的字段（workflow_json、自定义属性）才用 JSON 列。

### 误区三：语义搜索完全替代关键词搜索

CLIP 语义搜索很强大，但它不是万能的。搜"所有标记为 618 大促的素材"用关键词更精确；搜"温馨的家庭场景"用语义更自然。完全放弃关键词搜索会导致精确查询变慢变模糊。

**正确做法：** 语义搜索和关键词搜索并存，根据查询类型自动路由或由用户手动选择。混合检索（先语义粗筛，再关键词精排）通常是最佳方案。

### 误区四：所有图像都存 CDN

CDN 适合高频访问的热数据，但不适合所有图像。归档素材、历史版本、审核中素材的访问频率极低，放在 CDN 上只会增加成本。

**正确做法：** 按访问频率分层存储。只把最近 30 天内频繁访问的素材放在 CDN 加速层，其余放在标准对象存储或归档存储。

### 误区五：忽略图像去重

AI 生成图像时，相同 prompt + 相同 seed = 相同输出。不同设计师可能用相同参数生成相同图像并各自入库，导致存储浪费和管理混乱。

**正确做法：** 入库时计算文件 checksum（SHA-256），与已有记录比对。发现重复时提示用户，而不是静默存储两份。

## 小结与练习

### 小结

本课构建了一个面向 AI 生成图像的企业级资产管理系统，核心组件包括：

1. **元数据管理**：三层结构（基础信息 + AI 生成参数 + 业务元数据），用 SHA-256 去重
2. **版本控制**：DAG 结构的版本树，支持任意变体的血缘追溯
3. **标签系统**：三层标签（视觉 / 业务 / AI），支持自动提取和倒排索引检索
4. **语义搜索**：CLIP 编码 + 向量索引，支持以文搜图、以图搜图和混合检索
5. **存储策略**：三层分层（热 / 温 / 冷），基于访问频率自动迁移
6. **API 设计**：RESTful 风格，支持 CRUD、批量操作、语义搜索和血缘查询

**关键工程决策：**

- 元数据和文件存储分离，各自独立扩展
- 语义搜索和关键词搜索并存，不互相替代
- 存储分层是成本优化的核心手段，不是可选的"高级功能"
- 版本血缘追溯在 AI 时代比传统软件更重要，因为生成参数本身就是核心资产

#### 练习一：扩展元数据 Schema

当前的 `AIGenerationParams` 只覆盖了 Stable Diffusion 系列模型的参数。如果要支持 Midjourney（参数格式完全不同）和 DALL-E（只有 prompt，没有 seed/sampler），请设计一个可扩展的元数据方案。

**要求：**
- 不破坏现有代码结构
- 支持新增模型类型时最小化代码修改
- 每种模型的特有参数能被正确存储和查询

#### 练习二：实现访问频率衰减

当前的 `StoragePolicyEngine` 用简单的"最后访问时间"判断是否降级。但实际场景中，一个 3 个月前被密集访问了 100 次的素材，可能比一个昨天只被访问了 1 次的素材更有价值。

请实现一个带时间衰减的访问热度计算算法，公式参考：

```
heat_score = Σ (access_weight × decay_factor^(days_since_access / half_life))
```

其中 `half_life` 表示热度减半的天数（默认 30 天）。

**要求：**
- 至少支持 3 种角色：admin、editor、viewer
- 不同角色对资产的增删改查权限不同

### 练习一：扩展元数据 Schema

**思路：** 使用多态 + 注册表模式。定义一个基类 `GenerationParams`，每种模型实现自己的子类。通过模型名称查找对应的参数类。

```python
class ParamsRegistry:
    """生成参数注册表。新增模型只需注册，无需修改已有代码"""

    _registry: dict[str, type[GenerationParamsBase]] = {}

    @classmethod
    def register(cls, model_prefix: str, params_class: type[GenerationParamsBase]):
        cls._registry[model_prefix] = params_class

    @classmethod
    def create(cls, model_prefix: str, **kwargs) -> GenerationParamsBase:
        params_class = cls._registry.get(model_prefix)
        if params_class is None:
            raise ValueError(f"不支持的模型类型: {model_prefix}")
        return params_class(**kwargs)

    @classmethod
    def from_dict(cls, data: dict) -> GenerationParamsBase:
        model = data.get("model", data.get("version", "unknown"))
        for prefix, params_class in cls._registry.items():
            if prefix in model or model.startswith(prefix):
                filtered = {k: v for k, v in data.items()
                           if k in params_class.__dataclass_fields__}
                return params_class(**filtered)
        return StableDiffusionParams(**{k: v for k, v in data.items()
                                       if k in StableDiffusionParams.__dataclass_fields__})
```

### 练习二：实现访问频率衰减

**思路：** 用指数衰减模型计算热度分数。每次访问的贡献随时间指数衰减，half_life 控制衰减速度。热度分数高的资产保留在热存储层，分数低的逐步降级。

```python
import math
from datetime import datetime, timedelta
from dataclasses import dataclass, field


@dataclass
class AccessRecord:
    """单次访问记录"""
    timestamp: datetime
    weight: float = 1.0  # 访问权重，区分"浏览"和"下载"等不同操作


@dataclass
class AssetHeatProfile:
    """资产的热度画像"""
    asset_id: str
    access_history: list[AccessRecord] = field(default_factory=list)
    half_life_days: float = 30.0  # 热度减半周期

    def add_access(self, record: AccessRecord) -> None:
        self.access_history.append(record)

    def calculate_heat_score(self, now: datetime | None = None) -> float:
        """计算当前热度分数。使用指数衰减模型：
        heat = Σ (weight × 2^(-days_elapsed / half_life))
        """
        if now is None:
            now = datetime.now()

        total_heat = 0.0
        for record in self.access_history:
            days_elapsed = (now - record.timestamp).total_seconds() / 86400
            decay_factor = math.pow(2, -days_elapsed / self.half_life_days)
            total_heat += record.weight * decay_factor

        return total_heat

    def get_heat_breakdown(self, now: datetime | None = None) -> list[dict]:
        """返回每次访问对当前热度的贡献，用于调试和分析"""
        if now is None:
            now = datetime.now()

        breakdown = []
        for i, record in enumerate(self.access_history):
            days_elapsed = (now - record.timestamp).total_seconds() / 86400
            decay_factor = math.pow(2, -days_elapsed / self.half_life_days)
            contribution = record.weight * decay_factor
            breakdown.append({
                "access_index": i,
                "days_ago": round(days_elapsed, 1),
                "weight": record.weight,
                "decay_factor": round(decay_factor, 4),
                "contribution": round(contribution, 4),
            })
        return breakdown


class HeatBasedStoragePolicy:
    """基于热度的存储策略，替代简单的时间阈值策略"""

    TIER_THRESHOLDS = {
        "hot": 10.0,   # 热度 >= 10 存热层
        "warm": 2.0,   # 热度 >= 2 存温层
        "cold": 0.0,   # 其余存冷层
    }

    def __init__(self):
        self.profiles: dict[str, AssetHeatProfile] = {}

    def register_asset(self, asset_id: str, half_life_days: float = 30.0):
        self.profiles[asset_id] = AssetHeatProfile(asset_id=asset_id, half_life_days=half_life_days)

    def record_access(self, asset_id: str, weight: float = 1.0):
        if asset_id not in self.profiles:
            self.register_asset(asset_id)
        self.profiles[asset_id].add_access(AccessRecord(timestamp=datetime.now(), weight=weight))

    def determine_tier(self, asset_id: str) -> str:
        profile = self.profiles.get(asset_id)
        if profile is None:
            return "cold"

        heat = profile.calculate_heat_score()
        if heat >= self.TIER_THRESHOLDS["hot"]:
            return "hot"
        elif heat >= self.TIER_THRESHOLDS["warm"]:
            return "warm"
        return "cold"

    def get_all_tier_assignments(self) -> dict[str, dict]:
        assignments = {}
        for asset_id, profile in self.profiles.items():
            heat = profile.calculate_heat_score()
            tier = self.determine_tier(asset_id)
            assignments[asset_id] = {"heat_score": round(heat, 2), "tier": tier}
        return assignments
```

- `half_life` 参数让不同类型的资产可以有不同的衰减速度。热门活动素材衰减快（half_life=7），品牌素材衰减慢（half_life=30）

### 练习三：设计权限控制

**思路：** 使用 RBAC 模型，角色定义全局权限，项目级权限通过绑定关系实现。FastAPI 的依赖注入系统天然适合做权限校验。

```python
from enum import Enum
from dataclasses import dataclass, field
from fastapi import Depends, HTTPException, Header
from functools import wraps


class Permission(str, Enum):
    CREATE = "create"
    READ = "read"
    UPDATE = "update"
    DELETE = "delete"
    SEARCH = "search"
    MANAGE = "manage"  # 管理项目成员和权限


class Role(str, Enum):
    VIEWER = "viewer"
    EDITOR = "editor"
    ADMIN = "admin"


# 角色 -> 权限的映射
ROLE_PERMISSIONS: dict[Role, set[Permission]] = {
    Role.VIEWER: {Permission.READ, Permission.SEARCH},
    Role.EDITOR: {Permission.READ, Permission.SEARCH, Permission.CREATE, Permission.UPDATE},
    Role.ADMIN: {Permission.READ, Permission.SEARCH, Permission.CREATE,
                 Permission.UPDATE, Permission.DELETE, Permission.MANAGE},
}


@dataclass
class UserProjectBinding:
    """用户在某个项目中的角色绑定"""
    user_id: str
    project: str
    role: Role


class RBACManager:
    """基于角色的访问控制管理器"""

    def __init__(self):
        self.bindings: list[UserProjectBinding] = []
        self.global_roles: dict[str, Role] = {}  # 全局角色（如超级管理员）

    def assign_role(self, user_id: str, project: str, role: Role) -> None:
        """为用户分配项目角色。同一用户在同一项目中只有一个角色"""
        self.bindings = [
            b for b in self.bindings
            if not (b.user_id == user_id and b.project == project)
        ]
        self.bindings.append(UserProjectBinding(user_id, project, role))

    def set_global_role(self, user_id: str, role: Role) -> None:
        self.global_roles[user_id] = role

    def get_user_role(self, user_id: str, project: str) -> Role | None:
        """获取用户在指定项目中的角色"""
        global_role = self.global_roles.get(user_id)
        if global_role == Role.ADMIN:
            return Role.ADMIN

        for binding in self.bindings:
            if binding.user_id == user_id and binding.project == project:
                return binding.role
        return None

    def check_permission(self, user_id: str, project: str,
                         required_permission: Permission) -> bool:
        """检查用户在指定项目中是否拥有所需权限"""
        role = self.get_user_role(user_id, project)
        if role is None:
            return False
        return required_permission in ROLE_PERMISSIONS.get(role, set())

    def get_user_projects(self, user_id: str) -> list[dict]:
        """获取用户所有项目及对应角色"""
        projects = []
        if user_id in self.global_roles:
            projects.append({"project": "*", "role": self.global_roles[user_id].value})
        for binding in self.bindings:
            if binding.user_id == user_id:
                projects.append({"project": binding.project, "role": binding.role.value})
        return projects


# 全局 RBAC 实例
rbac = RBACManager()


def require_permission(permission: Permission, project_param: str = "project"):
    """FastAPI 依赖注入：校验请求是否拥有所需权限"""
    async def checker(
        x_user_id: str = Header(..., description="用户 ID"),
        x_project: str = Header(..., description="项目名称"),
    ):
        if not rbac.check_permission(x_user_id, x_project, permission):
            raise HTTPException(
                status_code=403,
                detail=f"权限不足: 用户 {x_user_id} 在项目 {x_project} 中"
                       f"缺少 {permission.value} 权限"
            )
        return x_user_id
    return Depends(checker)
```

**要点：**
- 全局管理员角色可以绕过项目级绑定，适合系统维护场景
- `require_permission` 返回 FastAPI 依赖，可以在路由声明时直接使用：
  ```python
  @app.delete("/api/v1/assets/{asset_id}")
  async def delete_asset(asset_id: str, user_id: str = require_permission(Permission.DELETE)):
      ...
  ```
- 同一用户在不同项目中可以有不同角色，实现了项目级隔离
- 权限校验失败返回 403 而不是 401：401 表示"未认证"，403 表示"已认证但权限不足"
