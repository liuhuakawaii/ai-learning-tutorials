# 第五课：数据库迁移

> **课程定位**：学会安全地更新数据库结构
> **前置知识**：Docker Compose、PostgreSQL 基础
> **预计时长**：25 分钟

## 学习目标

1. 理解数据库迁移的概念
2. 使用 Prisma 或 Knex 管理迁移
3. 在 Docker 环境中运行迁移

## 一、什么是数据库迁移

```
数据库迁移 = 版本控制数据库结构

  ┌─────────────────────────────────────────┐
  │           数据库版本历史                  │
  │                                          │
  │  001_create_users.sql                    │
  │  002_add_email_to_users.sql              │
  │  003_create_posts.sql                    │
  │  004_add_index_on_email.sql              │
  │                                          │
  │  每个迁移文件 = 数据库的一次变更           │
  │  可以前进（migrate）或回滚（rollback）    │
  └─────────────────────────────────────────┘
```

## 二、使用 Prisma 管理迁移

### 2.1 初始化 Prisma

```bash
npm install prisma @prisma/client
npx prisma init
```

### 2.2 定义 Schema

```prisma
// prisma/schema.prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model User {
  id    Int     @id @default(autoincrement())
  email String  @unique
  name  String?
  posts Post[]
}

model Post {
  id       Int    @id @default(autoincrement())
  title    String
  content  String?
  author   User   @relation(fields: [authorId], references: [id])
  authorId Int
}
```

### 2.3 创建迁移

```bash
# 创建迁移文件
npx prisma migrate dev --name init

# 生成 Prisma Client
npx prisma generate
```

### 2.4 在生产环境运行迁移

```bash
# 运行所有待执行的迁移
npx prisma migrate deploy
```

## 三、Docker Compose 集成

### 3.1 迁移作为启动步骤

```yaml
services:
  # 迁移服务
  db-migrate:
    build: .
    command: npx prisma migrate deploy
    environment:
      DATABASE_URL: postgres://postgres:secret@postgres:5432/mydb
    depends_on:
      postgres:
        condition: service_healthy

  # 应用服务
  app:
    build: .
    command: node dist/index.js
    environment:
      DATABASE_URL: postgres://postgres:secret@postgres:5432/mydb
    depends_on:
      db-migrate:
        condition: service_completed_successfully
      postgres:
        condition: service_healthy

  postgres:
    image: postgres:14
    environment:
      POSTGRES_DB: mydb
      POSTGRES_PASSWORD: secret
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      timeout: 5s
      retries: 5

volumes:
  pgdata:
```

### 3.2 在 Dockerfile 中包含迁移

```dockerfile
FROM node:18-alpine AS builder
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npx prisma generate
RUN npm run build

FROM node:18-alpine
WORKDIR /app
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/prisma ./prisma
COPY package.json ./
CMD ["sh", "-c", "npx prisma migrate deploy && node dist/index.js"]
```

## 四、迁移最佳实践

```
✅ 每次变更一个迁移文件
✅ 迁移文件提交到 Git
✅ 先备份再迁移（生产环境）
✅ 迁移要幂等（可重复执行）
✅ 测试环境先验证
❌ 不要手动修改生产数据库
❌ 不要删除已执行的迁移
```

## 五、回滚

```bash
# Prisma 不直接支持回滚，需要手动处理
# 选项：
# 1. 创建新的迁移来"撤销"变更
# 2. 从备份恢复

# Knex 支持回滚
npx knex migrate:rollback
```

## 小结

1. **数据库迁移**：版本控制数据库结构变更
2. **Prisma**：现代化的 ORM，内置迁移工具
3. **Docker 集成**：迁移作为启动步骤，确保应用启动前数据库就绪
4. **最佳实践**：每次一个迁移、先备份、先测试
