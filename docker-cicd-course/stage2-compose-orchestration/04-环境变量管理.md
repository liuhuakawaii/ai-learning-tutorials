> **课程定位**：学会安全地管理配置和密钥，这是生产环境的基本功

> **预计时长**：30 分钟

## 学习目标

1. 掌握 Compose 中环境变量的三种传入方式
2. 理解 `.env` 文件的使用和安全边界
3. 知道哪些配置应该用环境变量，哪些不该

## 一、三种传入方式

### 1.1 直接定义

```yaml
services:
  app:
    environment:
      - NODE_ENV=production
      - PORT=3000
      - DATABASE_URL=postgres://user:pass@postgres:5432/db
```

```
优点：简单直接
缺点：敏感信息暴露在 compose.yml 中，不适合提交到 Git
适用：非敏感的固定配置
```

### 1.2 从 .env 文件读取

```yaml
services:
  app:
    env_file:
      - .env
```

```bash
# .env
NODE_ENV=production
PORT=3000
DATABASE_URL=postgres://user:secret@postgres:5432/mydb
REDIS_URL=redis://redis:6379
API_KEY=sk-1234567890
```

```
优点：敏感信息集中在 .env 文件
缺点：.env 文件可能被误提交到 Git
适用：本地开发环境
```

### 1.3 使用变量替换

```yaml
services:
  app:
    environment:
      - NODE_ENV=${NODE_ENV:-development}
      - DATABASE_URL=${DATABASE_URL}
```

```bash
# .env
NODE_ENV=production
DATABASE_URL=postgres://user:secret@postgres:5432/mydb
```

```
${VARIABLE}          → 使用变量值
${VARIABLE:-default} → 如果变量未设置，使用默认值
${VARIABLE:?error}   → 如果变量未设置，报错
```

## 二、.env 文件管理

### 2.1 推荐结构

```bash
# .env.example（提交到 Git，作为模板）
NODE_ENV=development
PORT=3000
DATABASE_URL=postgres://postgres:password@postgres:5432/mydb
REDIS_URL=redis://redis:6379

# .env（不提交到 Git，实际使用）
NODE_ENV=production
PORT=3000
DATABASE_URL=postgres://postgres:real_secret@postgres:5432/mydb
REDIS_URL=redis://redis:6379
API_KEY=sk-real-key-here
```

### 2.2 .gitignore 配置

```gitignore
# .gitignore
.env
.env.local
.env.*.local

# 保留模板文件
!.env.example
```

### 2.3 初始化流程

```bash
# 新同事入职：
git clone <repo>
cp .env.example .env        # 从模板创建
vim .env                    # 填入实际配置
docker compose up -d        # 启动
```

## 三、不同环境的配置策略

### 3.1 多环境文件

```
项目结构：
├── .env.example        # 模板（提交到 Git）
├── .env.development    # 开发配置（不提交）
├── .env.staging        # 测试配置（不提交）
├── .env.production     # 生产配置（不提交）
└── compose.yml
```

```yaml
# compose.yml
services:
  app:
    env_file:
      - .env.${NODE_ENV:-development}
```

```bash
# 开发环境
NODE_ENV=development docker compose up -d

# 测试环境
NODE_ENV=staging docker compose up -d
```

### 3.2 Compose 文件分离

```
├── compose.yml              # 基础配置
├── compose.override.yml     # 开发环境覆盖（自动加载）
├── compose.prod.yml         # 生产环境覆盖
```

```yaml
# compose.yml（基础）
services:
  app:
    build: .
    environment:
      DATABASE_URL: ${DATABASE_URL}

# compose.override.yml（开发环境，自动加载）
services:
  app:
    volumes:
      - ./src:/app/src
    environment:
      NODE_ENV: development

# compose.prod.yml（生产环境）
services:
  app:
    environment:
      NODE_ENV: production
    restart: unless-stopped
```

```bash
# 开发环境（自动加载 override）
docker compose up -d

# 生产环境
docker compose -f compose.yml -f compose.prod.yml up -d
```

## 四、安全最佳实践

### 4.1 不要做的事

```
❌ 在 compose.yml 中硬编码密码
   environment:
     DB_PASSWORD: mysecretpassword

❌ 在 Dockerfile 中写死密钥
   ENV API_KEY=sk-1234567890

❌ 把 .env 提交到 Git
   git add .env

❌ 在日志中打印敏感信息
   console.log(process.env.API_KEY)
```

### 4.2 应该做的事

```
✅ 使用 .env 文件，不提交到 Git
✅ 提供 .env.example 作为模板
✅ 运行时通过环境变量传入密钥
✅ 使用 Docker Secrets 管理敏感数据（Swarm 模式）
✅ 定期轮换密钥
```

## 五、动手练习

### 练习一：多环境配置

```bash
# 1. 创建 .env.example
cat > .env.example << 'EOF'
NODE_ENV=development
PORT=3000
DATABASE_URL=postgres://postgres:password@postgres:5432/mydb
EOF

# 2. 创建 .env
cp .env.example .env
# 编辑 .env，修改密码

# 3. 在 compose.yml 中使用
# 4. 验证环境变量生效
docker compose up -d
docker compose exec app env | grep DATABASE_URL
```

### 练习二：变量替换和默认值

```yaml
# compose.yml
services:
  app:
    environment:
      - NODE_ENV=${NODE_ENV:-development}
      - PORT=${PORT:-3000}
```

```bash
# 测试默认值
docker compose up -d
docker compose exec app env | grep NODE_ENV

# 测试自定义值
NODE_ENV=staging PORT=8080 docker compose up -d
docker compose exec app env | grep NODE_ENV
```

## 小结

1. **三种方式**：直接定义、env_file、变量替换
2. **.env 文件**：敏感配置集中管理，不提交到 Git
3. **.env.example**：作为模板提交到 Git，方便团队协作
4. **不同环境**：使用不同 .env 文件或 Compose 文件分离
