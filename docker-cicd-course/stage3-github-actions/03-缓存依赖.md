## 一、为什么需要缓存

```
没有缓存的 CI：

  每次运行都要：
  1. 下载 Node.js
  2. npm install（下载所有依赖）
  3. 运行测试

  npm install 可能需要 1-3 分钟
  如果依赖没变，这是完全浪费的时间

有缓存的 CI：

  第一次：下载依赖 → 存入缓存
  后续：依赖没变 → 直接使用缓存（几秒钟）
```

## 二、使用 setup-node 内置缓存

```yaml
steps:
  - uses: actions/checkout@v4
  
  - uses: actions/setup-node@v4
    with:
      node-version: 18
      cache: npm               # 自动缓存 npm 依赖
```

```
这是最简单的方式：
  - 自动根据 package-lock.json 生成缓存键
  - 自动保存和恢复缓存
  - 几乎零配置
```

## 三、使用 actions/cache

### 3.1 基本用法

```yaml
steps:
  - uses: actions/checkout@v4
  
  # 恢复缓存
  - uses: actions/cache@v3
    id: cache
    with:
      path: node_modules
      key: ${{ runner.os }}-node-${{ hashFiles('**/package-lock.json') }}
      restore-keys: |
        ${{ runner.os }}-node-
  
  # 缓存未命中时才安装
  - if: steps.cache.outputs.cache-hit != 'true'
    run: npm ci
```

### 3.2 缓存键设计

```
缓存键的组成：

  ${{ runner.os }}-node-${{ hashFiles('**/package-lock.json') }}
         │                    │
         │                    └── package-lock.json 的哈希值
         └── 操作系统

  含义：
  - 同一 OS + 同一 package-lock.json → 使用缓存
  - package-lock.json 变了 → 缓存未命中，重新安装

  restore-keys：
  - 主键未命中时，尝试匹配的前缀
  - ${{ runner.os }}-node- → 匹配任何 node 缓存
```

### 3.3 缓存路径

```yaml
# npm 缓存路径
- uses: actions/cache@v3
  with:
    path: ~/.npm
    key: ${{ runner.os }}-npm-${{ hashFiles('**/package-lock.json') }}

# 或者缓存 node_modules
- uses: actions/cache@v3
  with:
    path: node_modules
    key: ${{ runner.os }}-modules-${{ hashFiles('**/package-lock.json') }}
```

```
两种方式的区别：

  缓存 ~/.npm（npm 缓存目录）：
  - 体积更小
  - npm ci 仍然需要执行，但速度快很多
  - 推荐

  缓存 node_modules：
  - 体积大
  - 可以跳过 npm ci
  - 可能有兼容性问题
```

## 四、其他包管理器

### 4.1 pnpm

```yaml
steps:
  - uses: actions/checkout@v4
  
  - uses: pnpm/action-setup@v2
    with:
      version: 8
  
  - uses: actions/setup-node@v4
    with:
      node-version: 18
      cache: pnpm
  
  - run: pnpm install --frozen-lockfile
  - run: pnpm test
```

## 五、Docker 构建缓存

```yaml
steps:
  - uses: actions/checkout@v4
  
  - uses: docker/setup-buildx-action@v3
  
  - uses: docker/build-push-action@v5
    with:
      context: .
      push: false
      cache-from: type=gha
      cache-to: type=gha,mode=max
```

```
GitHub Actions 缓存 Docker 层：
  - 使用 BuildKit 的 GHA 缓存后端
  - 自动缓存 Docker 构建层
  - 大幅加速重复构建
```

## 小结

1. **缓存**：避免每次都重新下载依赖
2. **setup-node 内置缓存**：最简单的方式，`cache: npm`
3. **actions/cache**：更灵活，可以缓存任何目录
4. **缓存键**：基于依赖文件的哈希值，依赖变化时自动失效
