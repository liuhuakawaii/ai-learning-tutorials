> **课程定位**：理解 Docker 的核心概念——镜像、容器和仓库
> **前置知识**：理解容器的价值（第一课）

## 场景引入

你在本地 `docker run` 起了一个 PostgreSQL 容器，往里面灌了一堆测试数据，调试了半天终于搞定。然后你顺手 `docker rm` 把容器删了——下一秒意识到：数据没了。你赶紧 `docker ps -a` 看了一眼，容器确实不在了。这时候你才开始琢磨：镜像和容器到底是什么关系？容器删了数据去哪了？`exit` 和 `docker rm` 有什么区别？

## 一、镜像（Image）

### 1.1 什么是镜像

> **镜像是一个只读的模板，包含了运行应用所需的一切：代码、运行时、库、环境变量和配置文件。**

```
类比：

  镜像 ≈ 一个安装光盘 / 系统镜像
    ├── 包含了所有需要的文件
    ├── 是只读的，不能直接修改
    └── 可以用它创建多个"运行实例"（容器）
```

### 1.2 镜像的分层结构

Docker 镜像不是一个巨大的单文件，而是由多个"层"（Layer）叠加而成：

```
┌─────────────────────────────────────────┐
│           镜像的分层结构                  │
│                                          │
│  ┌────────────────────────────────────┐ │
│  │  Layer 4: COPY app.js /app/        │ │  ← 你的应用代码
│  ├────────────────────────────────────┤ │
│  │  Layer 3: RUN npm install          │ │  ← 安装依赖
│  ├────────────────────────────────────┤ │
│  │  Layer 2: RUN apt-get install ...  │ │  ← 安装系统包
│  ├────────────────────────────────────┤ │
│  │  Layer 1: node:18-alpine           │ │  ← 基础镜像
│  └────────────────────────────────────┘ │
│                                          │
│  每一层都是只读的，层与层之间是叠加关系     │
└─────────────────────────────────────────┘
```

### 1.3 分层的好处

```
好处一：共享基础层

  镜像 A:  node:18-alpine + apt-get + npm install + App A
  镜像 B:  node:18-alpine + apt-get + npm install + App B
                     ↑
              这些层是共享的，只存一份

  10 个镜像都基于 node:18-alpine，这个基础层只存一份。

好处二：构建缓存

  修改了 app.js（Layer 4），只需要重新构建 Layer 4
  Layer 1-3 已经有缓存，不需要重新执行

  构建前：
    Layer 1: node:18-alpine    [缓存]
    Layer 2: apt-get install   [缓存]
    Layer 3: npm install       [缓存]
    Layer 4: COPY app.js       [需要重建] ← 只改了这里

  构建后：
    Layer 1: node:18-alpine    [缓存]     ← 不变
    Layer 2: apt-get install   [缓存]     ← 不变
    Layer 3: npm install       [缓存]     ← 不变
    Layer 4: COPY app.js       [新建]     ← 只重建这一层
```

### 1.4 查看镜像

```bash
# 列出本地所有镜像
docker images

# 输出示例：
# REPOSITORY   TAG          IMAGE ID       SIZE
# node         18-alpine    a1b2c3d4e5f6   170MB
# nginx        latest       f6e5d4c3b2a1   133MB

# 查看镜像的分层信息
docker history node:18-alpine

# 查看镜像的详细信息
docker inspect node:18-alpine
```

## 二、容器（Container）

### 2.1 什么是容器

> **容器是镜像的运行实例。你可以从同一个镜像启动多个容器，每个容器相互隔离。**

```
镜像 vs 容器：

  镜像（Image）                    容器（Container）
  ┌──────────────┐               ┌──────────────┐
  │  只读模板     │   docker run  │  运行中的实例  │
  │  静态的       │ ───────────→  │  动态的       │
  │  不会变化     │               │  可以修改     │
  │  可以共享     │               │  相互隔离     │
  └──────────────┘               └──────────────┘

  类比：
    镜像 = 类（Class）
    容器 = 实例（Instance）
```

### 2.2 容器的写时复制（Copy-on-Write）

容器在镜像的基础上加了一个"可写层"：

```
┌─────────────────────────────────────────┐
│           容器的结构                      │
│                                          │
│  ┌────────────────────────────────────┐ │
│  │  可写层（Container Layer）          │ │  ← 容器运行时的修改
│  ├────────────────────────────────────┤ │     （日志、临时文件等）
│  │  Layer 4: COPY app.js /app/        │ │
│  ├────────────────────────────────────┤ │
│  │  Layer 3: RUN npm install          │ │  ← 镜像层（只读）
│  ├────────────────────────────────────┤ │
│  │  Layer 2: RUN apt-get install ...  │ │
│  ├────────────────────────────────────┤ │
│  │  Layer 1: node:18-alpine           │ │
│  └────────────────────────────────────┘ │
└─────────────────────────────────────────┘

写时复制机制：
  - 读取文件 → 直接从镜像层读（快）
  - 修改文件 → 复制到可写层，然后修改（不影响镜像）
  - 删除文件 → 在可写层标记"已删除"（镜像层的文件还在）
```

### 2.3 容器的生命周期

```
容器的状态转换：

  ┌─────────┐   docker run    ┌─────────┐
  │  不存在   │ ──────────────→ │  运行中   │
  │ (None)   │                 │(Running) │
  └─────────┘                 └────┬────┘
       ↑                           │
       │ docker rm                 │ docker stop
       │                           ▼
  ┌─────────┐   docker start   ┌─────────┐
  │  已删除   │ ←────────────── │  已停止   │
  │(Removed) │                 │(Stopped) │
  └─────────┘                 └─────────┘
```

### 2.4 容器的常用操作

```bash
# 运行容器
# -d: 后台运行  --name: 命名  -p: 端口映射
docker run -d --name my-app -p 3000:3000 node:18-alpine

# 查看运行中的容器
docker ps

# 查看所有容器（包括已停止的）
docker ps -a

# 停止容器
docker stop my-app

# 启动已停止的容器
docker start my-app

# 进入容器内部
docker exec -it my-app /bin/sh

# 查看容器日志
docker logs my-app

# 实时查看日志
docker logs -f my-app

# 删除容器
docker rm my-app

# 强制删除运行中的容器
docker rm -f my-app
```

### 2.5 常见困惑：exit 之后发生了什么？

```
docker run -it node:18-alpine /bin/sh
# 在容器内操作...
exit

exit 之后：
  ├── 容器停止，但没有删除（docker ps -a 可以看到）
  ├── 可以 docker start 容器ID 重新启动
  └── 加 --rm 才会自动删除：docker run --rm -it ...

类比：
  容器像一个可以暂停的游戏存档
  exit  = 暂停游戏（存档还在）
  --rm  = 删掉存档
  docker start = 读取存档继续玩
```

| 命令 | 容器状态 | 容器数据 |
|------|---------|---------|
| `docker run` + exit | 停止，容器还在 | 数据保留 |
| `docker run --rm` + exit | 自动删除 | 数据丢失 |
| `docker stop` | 停止，容器还在 | 数据保留 |
| `docker rm` | 删除 | 数据丢失（可写层） |

## 三、仓库（Registry）

### 3.1 什么是仓库

> **仓库是存储和分发镜像的服务。** 最常用的公共仓库是 Docker Hub。

```
仓库的类比：

  Docker Hub    ≈  npm registry / GitHub
  镜像           ≈  npm 包 / Git 仓库
  标签（Tag）    ≈  版本号
```

### 3.2 镜像的命名规则

```
镜像的完整名称：

  registry/namespace/repository:tag

  示例：
  ┌─────────────────────────────────────────────────────┐
  │  docker.io/library/node:18-alpine                    │
  │  │       │       │    │                              │
  │  │       │       │    └── 标签（版本）                │
  │  │       │       └─────── 镜像名                     │
  │  │       └─────────────── 命名空间（用户/组织）        │
  │  └─────────────────────── 仓库地址                    │
  └─────────────────────────────────────────────────────┘

  简写规则：
  docker.io/library/node:18-alpine  = node:18-alpine
  docker.io/nginx:latest            = nginx:latest
  yourusername/myapp:v1.0           = docker.io/yourusername/myapp:v1.0
```

### 3.3 使用 Docker Hub

```bash
# 搜索镜像
docker search node

# 拉取镜像
docker pull node:18-alpine

# 登录 Docker Hub
docker login

# 给本地镜像打标签（准备推送）
docker tag my-app:latest yourusername/my-app:v1.0

# 推送镜像
docker push yourusername/my-app:v1.0

# 登出
docker logout
```

### 3.4 其他镜像仓库

```
┌──────────────────┬──────────────────────────────┐
│  仓库             │  说明                        │
├──────────────────┼──────────────────────────────┤
│  Docker Hub      │  最大的公共仓库，官方维护      │
│  GitHub CR       │  GitHub Container Registry   │
│  AWS ECR         │  Amazon Elastic Container    │
│  阿里云 ACR      │  国内访问快                   │
│  腾讯云 TCR      │  国内访问快                   │
│  私有仓库        │  自建 Harbor / Registry       │
└──────────────────┴──────────────────────────────┘
```

### 3.5 镜像存储在哪？生命周期是什么？

```
docker pull 把镜像下载到本地 Docker 引擎的存储层中。
不是当前目录，也不是你的 Docker Hub 账号。

┌──────────────┬────────────────────────────────┐
│  系统         │  存储路径                       │
├──────────────┼────────────────────────────────┤
│  Windows     │  WSL2 虚拟磁盘中               │
│  macOS       │  ~/Library/Containers/         │
│  Linux       │  /var/lib/docker/              │
└──────────────┴────────────────────────────────┘

生命周期：
  - docker pull 下载的镜像 → 永久留在本地，关机重启不丢
  - docker run 创建的容器 → exit 后停止但还在
  - 镜像删除：docker rmi 镜像名
  - 清理所有不用的：docker system prune

什么时候需要手动 pull？
  - 几乎不需要。docker build 和 docker run 会自动拉取依赖的镜像
  - 手动 pull 用于：提前下载、单独检查某个镜像
```

## 四、核心概念关系图

```
┌─────────────────────────────────────────────────────────────┐
│                    Docker 核心概念关系                        │
│                                                              │
│  Dockerfile ──build──→ 镜像(Image) ──run──→ 容器(Container) │
│                              │                    │          │
│                         push │ pull               │          │
│                              ▼                    │          │
│                        仓库(Registry)        数据卷 / 网络    │
│                        Docker Hub           （下节课讲）      │
│                                                              │
│  Dockerfile = 怎么构建（菜谱）                                │
│  镜像       = 构建好的模板（半成品菜）                         │
│  容器       = 镜像的运行实例（做好的菜）                       │
│  仓库       = 存储和分发镜像的地方（冰箱）                    │
└─────────────────────────────────────────────────────────────┘
```

## 五、动手练习

### 练习一：镜像基本操作

```bash
# 1. 拉取 node:18-alpine 镜像
docker pull node:18-alpine

# 2. 查看镜像信息
docker images
docker history node:18-alpine

# 3. 运行一个容器
docker run -it node:18-alpine /bin/sh

# 在容器内执行：
node -v
npm -v
echo "Hello from container!"
exit

# 4. 查看容器状态（exit 后容器还在吗？）
docker ps -a
```

### 练习二：容器生命周期

```bash
# 1. 运行容器
docker run -d --name test-lifecycle node:18-alpine sleep 3600

# 2. 查看状态
docker ps

# 3. 停止容器
docker stop test-lifecycle
docker ps -a  # 状态变成 Exited

# 4. 重新启动
docker start test-lifecycle
docker ps  # 又变成 Up 了

# 5. 删除
docker rm -f test-lifecycle
docker ps -a  # 没了
```

### 练习三：理解 --rm

```bash
# 不加 --rm：容器还在
docker run node:18-alpine echo "hello"
docker ps -a  # 能看到刚创建的容器

# 加 --rm：自动删除
docker run --rm node:18-alpine echo "hello"
docker ps -a  # 容器已自动清理

# 清理所有停止的容器
docker container prune
```

## 常见误区

- **"exit 就是删除容器"**：`exit` 只是退出容器内的主进程，容器本身还在（状态为 Exited）。只有 `docker rm` 才会真正删除容器，加 `--rm` 参数才能在退出时自动删除。
- **"镜像和容器是同一个东西"**：镜像是只读模板，容器是镜像的运行实例。一个镜像可以创建多个容器，修改容器不会影响镜像。
- **"docker pull 之后镜像存在项目目录里"**：镜像存储在 Docker 引擎的存储层中（Linux 在 `/var/lib/docker/`），不在当前目录，也不会随项目一起被 git 管理。
- **"latest 标签就是最新稳定版"**：`latest` 只是默认标签，不代表它是最新或最稳定的版本。生产环境应该用具体的版本号标签（如 `node:18.17.0-alpine`）。

---

## 工程建议

- **养成用 `--rm` 跑临时容器的习惯**：调试、测试等一次性操作用 `docker run --rm`，避免积累大量已停止的容器占用磁盘。
- **定期清理不用的镜像和容器**：用 `docker system prune` 清理悬空资源，但注意不要在生产环境随意执行。
- **给镜像打语义化标签**：不要只用 `latest`，用 `app:1.2.3` 这样的格式，方便回滚和排查问题。
- **理解分层存储对构建速度的影响**：合理利用构建缓存，把变化频率低的指令放前面，能显著加速镜像构建。

---

## 小结

1. **镜像**：只读模板，分层存储，共享基础层节省空间，构建缓存加速
2. **容器**：镜像的运行实例，有可写层，生命周期独立于镜像
3. **仓库**：存储和分发镜像的服务，Docker Hub 是最大的公共仓库
4. **镜像存储**：在本地 Docker 引擎中，永久保留直到手动删除
5. **exit 不等于删除**：exit 后容器停止但还在，--rm 才自动删除
