## 一、为什么需要多阶段构建

### 1.1 单阶段构建的问题

```
一个 Node.js 项目的构建过程：

  源代码 + package.json
       │
       ▼
  npm install          ← 安装所有依赖（包括 devDependencies）
       │
       ▼
  npm run build        ← 编译 TypeScript / 打包
       │
       ▼
  产物（dist/）
       │
       ▼
  node src/index.js    ← 运行只需要：node + 产物 + 生产依赖

  问题：构建工具（TypeScript、Webpack、Babel 等）也被打包进了最终镜像
```

```
单阶段构建的镜像内容：

  ┌─────────────────────────────────────┐
  │           最终镜像                   │
  │                                      │
  │  node:18-alpine         170MB       │
  │  node_modules/          50MB        │
  │  node_modules/.cache/   20MB        │  ← npm 缓存
  │  src/ (源代码)          5MB         │  ← 不需要
  │  tsconfig.json          1KB         │  ← 不需要
  │  TypeScript             30MB        │  ← 运行时不需要
  │  Webpack                20MB        │  ← 运行时不需要
  │                                      │
  │  总计：~295MB                        │
  │  实际需要：~230MB                    │
  └─────────────────────────────────────┘

  浪费了 ~65MB 的空间给构建工具和源代码
```

### 1.2 多阶段构建的思路

```
多阶段构建：

  阶段一（builder）：         阶段二（production）：
  ┌─────────────────┐       ┌─────────────────┐
  │ node:18-alpine  │       │ node:18-alpine  │
  │ + 源代码        │       │ + 产物（dist/）  │
  │ + 所有依赖      │  COPY │ + 生产依赖       │
  │ + 构建工具      │ ────→ │                  │
  │                 │       │                  │
  │ npm install     │       │ 只保留运行需要的  │
  │ npm run build   │       │                  │
  └─────────────────┘       └─────────────────┘
        ~295MB                   ~230MB

  关键：阶段一的构建工具不会进入阶段二
```

## 二、多阶段构建语法

### 2.1 基本语法

```dockerfile
# 阶段一：构建阶段
FROM node:18-alpine AS builder

WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build

# 阶段二：运行阶段
FROM node:18-alpine AS production

WORKDIR /app
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
COPY package.json ./

CMD ["node", "dist/index.js"]
```

```
关键语法：

  FROM node:18-alpine AS builder
                       ↑
                       给阶段起名字

  COPY --from=builder /app/dist ./dist
              ↑
              从指定阶段复制文件
```

### 2.2 执行流程

```
docker build 的执行流程：

  Step 1: FROM node:18-alpine AS builder    ← 开始阶段一
  Step 2: WORKDIR /app
  Step 3: COPY package.json package-lock.json ./
  Step 4: RUN npm ci
  Step 5: COPY . .
  Step 6: RUN npm run build
                                   ← 阶段一结束

  Step 7: FROM node:18-alpine AS production  ← 开始阶段二
  Step 8: WORKDIR /app
  Step 9: COPY --from=builder /app/dist ./dist  ← 从阶段一复制
  Step 10: COPY --from=builder /app/node_modules ./node_modules
  Step 11: COPY package.json ./
  Step 12: CMD ["node", "dist/index.js"]

  最终镜像只包含阶段二的内容
```

## 三、实战示例

### 3.1 Node.js API（TypeScript）

```dockerfile
# ---- 构建阶段 ----
FROM node:18-alpine AS builder

WORKDIR /app

# 安装依赖（包括 devDependencies）
COPY package.json package-lock.json ./
RUN npm ci

# 复制源代码
COPY tsconfig.json ./
COPY src/ ./src/

# 编译 TypeScript
RUN npm run build

# 清理 devDependencies
RUN npm prune --production

# ---- 运行阶段 ----
FROM node:18-alpine AS production

WORKDIR /app

# 创建非 root 用户
RUN addgroup -g 1001 -S nodejs \
    && adduser -S nodeuser -u 1001

# 从构建阶段复制产物
COPY --from=builder --chown=nodeuser:nodejs /app/dist ./dist
COPY --from=builder --chown=nodeuser:nodejs /app/node_modules ./node_modules
COPY --from=builder --chown=nodeuser:nodejs /app/package.json ./

# 切换用户
USER nodeuser

EXPOSE 3000

CMD ["node", "dist/index.js"]
```

### 3.2 Next.js 应用

```dockerfile
# ---- 依赖阶段 ----
FROM node:18-alpine AS deps

WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci

# ---- 构建阶段 ----
FROM node:18-alpine AS builder

WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .

# Next.js 构建
ENV NEXT_TELEMETRY_DISABLED=1
RUN npm run build

# ---- 运行阶段 ----
FROM node:18-alpine AS runner

WORKDIR /app

ENV NODE_ENV=production
ENV NEXT_TELEMETRY_DISABLED=1

# 创建非 root 用户
RUN addgroup -g 1001 -S nodejs \
    && adduser -S nextjs -u 1001

# 只复制必要的文件
COPY --from=builder /app/public ./public
COPY --from=builder --chown=nextjs:nodejs /app/.next/standalone ./
COPY --from=builder --chown=nextjs:nodejs /app/.next/static ./.next/static

USER nextjs

EXPOSE 3000

ENV PORT=3000
ENV HOSTNAME="0.0.0.0"

CMD ["node", "server.js"]
```

### 3.3 React / Vue 静态应用（Nginx）

```dockerfile
# ---- 构建阶段 ----
FROM node:18-alpine AS builder

WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build

# ---- 运行阶段 ----
FROM nginx:1.25-alpine AS production

# 复制自定义 Nginx 配置
COPY nginx.conf /etc/nginx/conf.d/default.conf

# 从构建阶段复制静态文件
COPY --from=builder /app/dist /usr/share/nginx/html

EXPOSE 80

CMD ["nginx", "-g", "daemon off;"]
```

对应的 `nginx.conf`：

```nginx
server {
    listen 80;
    server_name localhost;
    root /usr/share/nginx/html;
    index index.html;

    # SPA 路由支持
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 静态资源缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

## 四、构建目标（--target）

### 4.1 选择性构建

```bash
# 只构建到 builder 阶段（用于调试）
docker build --target builder -t my-app:builder .

# 只构建到 production 阶段（默认）
docker build --target production -t my-app:prod .

# 不指定 target，构建到最后一个阶段
docker build -t my-app .
```

### 4.2 调试构建过程

```bash
# 构建到 builder 阶段
docker build --target builder -t my-app:debug .

# 进入 builder 阶段的镜像，检查构建产物
docker run -it my-app:debug /bin/sh

# 在容器内检查
ls -la /app/dist/
ls -la /app/node_modules/
```

### 4.3 开发和生产共用一个 Dockerfile

```dockerfile
# ---- 基础阶段 ----
FROM node:18-alpine AS base
WORKDIR /app
COPY package.json package-lock.json ./

# ---- 依赖阶段 ----
FROM base AS deps
RUN npm ci

# ---- 开发阶段 ----
FROM base AS development
COPY --from=deps /app/node_modules ./node_modules
COPY . .
CMD ["npm", "run", "dev"]

# ---- 构建阶段 ----
FROM deps AS builder
COPY . .
RUN npm run build

# ---- 生产阶段 ----
FROM node:18-alpine AS production
WORKDIR /app
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
COPY package.json ./
CMD ["node", "dist/index.js"]
```

```bash
# 开发模式
docker build --target development -t my-app:dev .
docker run -d -p 3000:3000 -v $(pwd)/src:/app/src my-app:dev

# 生产模式
docker build --target production -t my-app:prod .
docker run -d -p 3000:3000 my-app:prod
```

## 六、最佳实践

### 6.1 层顺序优化

```dockerfile
# ✅ 好的顺序：变化频率从低到高

# 1. 基础镜像（几乎不变）
FROM node:18-alpine AS base

# 2. 系统依赖（很少变）
RUN apk add --no-cache tini

# 3. 依赖文件（偶尔变）
COPY package.json package-lock.json ./

# 4. 安装依赖（依赖文件变才变）
RUN npm ci

# 5. 配置文件（偶尔变）
COPY tsconfig.json ./

# 6. 源代码（经常变）
COPY src/ ./src/

# 7. 构建（源代码变才变）
RUN npm run build
```

### 6.2 使用 tini 作为 init 进程

```dockerfile
FROM node:18-alpine

# 安装 tini
RUN apk add --no-cache tini

# 使用 tini 作为入口
ENTRYPOINT ["/sbin/tini", "--"]

CMD ["node", "src/index.js"]
```

```
为什么用 tini？

  Node.js 在容器中作为 PID 1 运行时的问题：
  - 不会正确处理信号（SIGTERM）
  - 子进程可能变成僵尸进程
  - 优雅关闭可能不工作

  tini 解决这些问题，让 Node.js 正确响应容器停止信号
```

### 6.3 使用 npm ci 而不是 npm install

```dockerfile
# ❌ npm install：可能修改 package-lock.json
RUN npm install

# ✅ npm ci：严格按照 package-lock.json 安装
RUN npm ci
```

```
npm ci vs npm install：

  npm install：
  - 可能更新 package-lock.json
  - 安装结果可能不一致
  - 适合本地开发

  npm ci：
  - 严格按照 package-lock.json
  - 安装结果完全一致
  - 速度更快（跳过依赖解析）
  - 适合 CI/CD 和 Docker
```

## 小结

本课的核心要点：

1. **多阶段构建**把构建环境和运行环境分开，减小镜像体积
2. **语法**：`FROM ... AS name` 命名阶段，`COPY --from=name` 跨阶段复制
3. **`--target`** 可以选择性构建到某个阶段，方便调试
4. **一个 Dockerfile 可以同时用于开发和生产**，通过不同 target 切换
5. **层顺序**：变化频率低的放前面，利用缓存加速构建
