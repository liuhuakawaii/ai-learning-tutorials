## 一、镜像（Image）

### 1.1 什么是镜像

> **镜像是一个只读的模板，包含了运行应用所需的一切：代码、运行时、库、环境变量和配置文件。**

```
镜像的类比：

  镜像 ≈ 一个安装光盘 / 系统镜像
    ├── 包含了所有需要的文件
    ├── 是只读的，不能直接修改
    └── 可以用它创建多个"运行实例"（容器）
```

### 1.2 镜像的分层结构

Docker 镜像不是一个巨大的单文件，而是由多个"层"（Layer）叠加而成：

```
┌─────────────────────────────────────────┐
│           镜像的分层结构                  │
│                                          │
│  ┌────────────────────────────────────┐ │
│  │  Layer 4: COPY app.js /app/        │ │  ← 你的应用代码
│  ├────────────────────────────────────┤ │
│  │  Layer 3: RUN npm install          │ │  ← 安装依赖
│  ├────────────────────────────────────┤ │
│  │  Layer 2: RUN apt-get install ...  │ │  ← 安装系统包
│  ├────────────────────────────────────┤ │
│  │  Layer 1: node:18-alpine           │ │  ← 基础镜像
│  └────────────────────────────────────┘ │
│                                          │
│  每一层都是只读的，层与层之间是叠加关系     │
└─────────────────────────────────────────┘
```

### 1.3 分层的好处

```
好处一：共享基础层

  镜像 A:  node:18-alpine + apt-get + npm install + App A
  镜像 B:  node:18-alpine + apt-get + npm install + App B
                     ↑
              这些层是共享的，只存一份

  节省磁盘空间：如果 10 个镜像都基于 node:18-alpine，
  这个基础层只在磁盘上存一份。

好处二：构建缓存

  修改了 app.js（Layer 4），只需要重新构建 Layer 4
  Layer 1-3 已经有缓存，不需要重新执行

  构建前：
    Layer 1: node:18-alpine    [缓存]
    Layer 2: apt-get install   [缓存]
    Layer 3: npm install       [缓存]
    Layer 4: COPY app.js       [需要重建] ← 只改了这里

  构建后：
    Layer 1: node:18-alpine    [缓存]     ← 不变
    Layer 2: apt-get install   [缓存]     ← 不变
    Layer 3: npm install       [缓存]     ← 不变
    Layer 4: COPY app.js       [新建]     ← 只重建这一层
```

### 1.4 查看镜像

```bash
# 列出本地所有镜像
docker images

# 输出示例：
# REPOSITORY   TAG          IMAGE ID       SIZE
# node         18-alpine    a1b2c3d4e5f6   170MB
# nginx        latest       f6e5d4c3b2a1   133MB
# postgres     14           1a2b3c4d5e6f   370MB

# 查看镜像的分层信息
docker history node:18-alpine

# 查看镜像的详细信息
docker inspect node:18-alpine
```

## 二、容器（Container）

### 2.1 什么是容器

> **容器是镜像的运行实例。你可以从同一个镜像启动多个容器，每个容器相互隔离。**

```
镜像 vs 容器：

  镜像（Image）                    容器（Container）
  ┌──────────────┐               ┌──────────────┐
  │  只读模板     │   docker run  │  运行中的实例  │
  │  静态的       │ ───────────→  │  动态的       │
  │  不会变化     │               │  可以修改     │
  │  可以共享     │               │  相互隔离     │
  └──────────────┘               └──────────────┘

  类比：
    镜像 = 类（Class）
    容器 = 实例（Instance）
```

### 2.2 容器的写时复制（Copy-on-Write）

容器在镜像的基础上加了一个"可写层"：

```
┌─────────────────────────────────────────┐
│           容器的结构                      │
│                                          │
│  ┌────────────────────────────────────┐ │
│  │  可写层（Container Layer）          │ │  ← 容器运行时的修改
│  ├────────────────────────────────────┤ │     （日志、临时文件等）
│  │  Layer 4: COPY app.js /app/        │ │
│  ├────────────────────────────────────┤ │
│  │  Layer 3: RUN npm install          │ │  ← 镜像层（只读）
│  ├────────────────────────────────────┤ │
│  │  Layer 2: RUN apt-get install ...  │ │
│  ├────────────────────────────────────┤ │
│  │  Layer 1: node:18-alpine           │ │
│  └────────────────────────────────────┘ │
└─────────────────────────────────────────┘

写时复制机制：
  - 读取文件 → 直接从镜像层读（快）
  - 修改文件 → 复制到可写层，然后修改（不影响镜像）
  - 删除文件 → 在可写层标记"已删除"（镜像层的文件还在）
```

### 2.3 容器的生命周期

```
容器的状态转换：

  ┌─────────┐   docker run    ┌─────────┐
  │  不存在   │ ──────────────→ │  运行中   │
  │ (None)   │                 │(Running) │
  └─────────┘                 └────┬────┘
       ↑                           │
       │ docker rm                 │ docker stop
       │                           ▼
  ┌─────────┐   docker start   ┌─────────┐
  │  已删除   │ ←────────────── │  已停止   │
  │(Removed) │                 │(Stopped) │
  └─────────┘                 └─────────┘
```

### 2.4 容器的常用操作

```bash
# 运行容器
docker run -d --name my-app -p 3000:3000 node:18-alpine

# 查看运行中的容器
docker ps

# 查看所有容器（包括已停止的）
docker ps -a

# 停止容器
docker stop my-app

# 启动已停止的容器
docker start my-app

# 进入容器内部
docker exec -it my-app /bin/sh

# 查看容器日志
docker logs my-app

# 实时查看日志
docker logs -f my-app

# 删除容器
docker rm my-app

# 强制删除运行中的容器
docker rm -f my-app
```

## 三、仓库（Registry）

### 3.1 什么是仓库

> **仓库是存储和分发镜像的服务。** 最常用的公共仓库是 Docker Hub。

```
仓库的类比：

  Docker Hub    ≈  npm registry / GitHub
  镜像           ≈  npm 包 / Git 仓库
  标签（Tag）    ≈  版本号

  ┌─────────────────────────────────────────┐
  │              Docker Hub                  │
  │                                          │
  │  ┌──────────┐  ┌──────────┐             │
  │  │  node    │  │  nginx   │  ...        │
  │  │  tags:   │  │  tags:   │             │
  │  │  - 18    │  │  - latest│             │
  │  │  - 20    │  │  - 1.25  │             │
  │  │  - latest│  │  - 1.24  │             │
  │  └──────────┘  └──────────┘             │
  └─────────────────────────────────────────┘
```

### 3.2 镜像的命名规则

```
镜像的完整名称：

  registry/namespace/repository:tag

  示例：
  ┌─────────────────────────────────────────────────────┐
  │  docker.io/library/node:18-alpine                    │
  │  │       │       │    │                              │
  │  │       │       │    └── 标签（版本）                │
  │  │       │       └─────── 镜像名                     │
  │  │       └─────────────── 命名空间（用户/组织）        │
  │  └─────────────────────── 仓库地址                    │
  └─────────────────────────────────────────────────────┘

  简写规则：
  docker.io/library/node:18-alpine
  = node:18-alpine              ← 省略默认的 registry 和 namespace

  docker.io/nginx:latest
  = nginx:latest                ← library 是默认命名空间

  yourusername/myapp:v1.0
  = docker.io/yourusername/myapp:v1.0
```

### 3.3 使用 Docker Hub

```bash
# 搜索镜像
docker search node

# 拉取镜像
docker pull node:18-alpine

# 登录 Docker Hub
docker login

# 给本地镜像打标签
docker tag my-app:latest yourusername/my-app:v1.0

# 推送镜像
docker push yourusername/my-app:v1.0

# 登出
docker logout
```

### 3.4 其他镜像仓库

```
常见的镜像仓库：

  ┌──────────────────┬──────────────────────────────┐
  │  仓库             │  说明                        │
  ├──────────────────┼──────────────────────────────┤
  │  Docker Hub      │  最大的公共仓库，官方维护      │
  │  GitHub CR       │  GitHub Container Registry   │
  │  AWS ECR         │  Amazon Elastic Container    │
  │  阿里云 ACR      │  国内访问快                   │
  │  腾讯云 TCR      │  国内访问快                   │
  │  私有仓库        │  自建 Harbor / Registry       │
  └──────────────────┴──────────────────────────────┘
```

## 四、数据卷（Volume）

### 4.1 为什么需要 Volume

容器是临时的——容器删除后，里面的数据就没了。

```
问题：

  docker run postgres          ← 启动数据库
  ... 写入了一些数据 ...
  docker rm postgres           ← 容器没了
  ... 数据也没了 ...           ← 💀

  容器的可写层随容器生命周期，
  容器删除，数据丢失。
```

### 4.2 Volume 的两种方式

```
方式一：Named Volume（命名卷）

  ┌──────────────┐
  │   容器        │
  │  /var/lib/    │
  │  postgresql/  │──→ ┌──────────────────┐
  │              │    │  Named Volume     │
  └──────────────┘    │  (pgdata)         │
                      │  Docker 管理的目录  │
                      └──────────────────┘

  特点：
  - Docker 自动管理存储位置
  - 容器删除后数据保留
  - 适合数据库等有状态服务

方式二：Bind Mount（绑定挂载）

  ┌──────────────┐
  │   容器        │
  │  /app/        │──→ ┌──────────────────┐
  │              │    │  宿主机目录        │
  └──────────────┘    │  /home/user/code/ │
                      └──────────────────┘

  特点：
  - 直接映射宿主机的目录
  - 容器和宿主机实时同步
  - 适合开发时挂载源代码
```

### 4.3 Volume 的使用

```bash
# 创建命名卷
docker volume create pgdata

# 查看所有卷
docker volume ls

# 使用命名卷运行 PostgreSQL
docker run -d \
  --name postgres \
  -v pgdata:/var/lib/postgresql/data \
  -e POSTGRES_PASSWORD=mysecret \
  postgres:14

# 使用绑定挂载（开发模式）
docker run -d \
  --name my-app \
  -v $(pwd)/src:/app/src \
  -p 3000:3000 \
  node:18-alpine

# 删除卷
docker volume rm pgdata

# 清理未使用的卷
docker volume prune
```

## 五、网络（Network）

### 5.1 为什么需要自定义网络

```
默认网络的问题：

  ┌─────────────────────────────────────────┐
  │           默认 bridge 网络               │
  │                                          │
  │  ┌────────┐  ┌────────┐  ┌────────┐    │
  │  │ app    │  │ postgres│  │ redis  │    │
  │  │ 172.17 │  │ 172.17 │  │ 172.17 │    │
  │  │ .0.2   │  │ .0.3   │  │ .0.4   │    │
  │  └────────┘  └────────┘  └────────┘    │
  └─────────────────────────────────────────┘

  问题：
  - 容器 IP 是动态分配的，重启后会变
  - 只能用 IP 访问，不能用容器名
  - 所有容器都在同一个网络，不安全
```

### 5.2 自定义网络

```
自定义网络的优势：

  ┌─────────────────────────────────────────┐
  │           app-network                    │
  │                                          │
  │  ┌────────┐  ┌────────┐  ┌────────┐    │
  │  │ app    │  │ postgres│  │ redis  │    │
  │  │        │  │        │  │        │    │
  │  └────────┘  └────────┘  └────────┘    │
  │      │           │           │          │
  │      └───────────┼───────────┘          │
  │                  │                       │
  │         可以用容器名互相访问               │
  │         app → postgres:5432              │
  │         app → redis:6379                 │
  └─────────────────────────────────────────┘
```

### 5.3 网络操作

```bash
# 创建自定义网络
docker network create app-network

# 查看所有网络
docker network ls

# 将容器加入网络
docker run -d --name postgres --network app-network postgres:14

# 在同一网络中，容器可以用名称互相访问
docker run -d --name app --network app-network my-app

# 测试连通性
docker exec -it app ping postgres

# 查看网络详情
docker network inspect app-network

# 断开网络
docker network disconnect app-network postgres

# 删除网络
docker network rm app-network
```

## 七、动手练习

### 练习一：镜像基本操作

```bash
# 1. 拉取 node:18-alpine 镜像
docker pull node:18-alpine

# 2. 查看镜像信息
docker images
docker history node:18-alpine

# 3. 运行一个容器
docker run -it node:18-alpine /bin/sh

# 在容器内执行：
node -v
npm -v
echo "Hello from container!"
exit

# 4. 查看容器状态
docker ps -a
```

### 练习二：Volume 持久化

```bash
# 1. 创建一个命名卷
docker volume create test-data

# 2. 运行容器并挂载卷
docker run -d --name test-redis -v test-data:/data redis:7

# 3. 写入数据
docker exec -it test-redis redis-cli SET mykey "hello"

# 4. 删除容器
docker rm -f test-redis

# 5. 重新创建容器，验证数据是否还在
docker run -d --name test-redis-new -v test-data:/data redis:7
docker exec -it test-redis-new redis-cli GET mykey
# 应该输出 "hello"
```

### 练习三：网络通信

```bash
# 1. 创建自定义网络
docker network create demo-net

# 2. 启动 Redis 容器
docker run -d --name redis --network demo-net redis:7

# 3. 启动一个临时容器测试连通性
docker run --rm --network demo-net node:18-alpine \
  sh -c "echo 'Redis is reachable' && ping -c 2 redis"

# 4. 清理
docker rm -f redis
docker network rm demo-net
```

## 小结

本课的核心要点：

1. **镜像**：只读模板，分层存储，可以共享基础层节省空间
2. **容器**：镜像的运行实例，有可写层，生命周期独立于镜像
3. **仓库**：存储和分发镜像的服务，Docker Hub 是最大的公共仓库
4. **Volume**：解决容器数据持久化问题，分 Named Volume 和 Bind Mount
5. **Network**：解决容器间通信问题，自定义网络支持容器名访问
