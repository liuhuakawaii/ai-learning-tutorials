## 一、为什么要关注镜像体积

### 1.1 体积的影响

```
镜像体积的影响：

  ┌─────────────────────────────────────────────────────┐
  │  大镜像（500MB+）                                    │
  │  ├── 构建慢：每次构建传输和处理更多数据               │
  │  ├── 部署慢：拉取镜像耗时长                          │
  │  ├── 存储贵：镜像仓库存储成本高                      │
  │  ├── 启动慢：容器启动需要加载更多层                   │
  │  └── 攻击面大：包含更多不必要的工具和库               │
  ├─────────────────────────────────────────────────────┤
  │  小镜像（50-100MB）                                  │
  │  ├── 构建快                                         │
  │  ├── 部署快                                         │
  │  ├── 存储省                                         │
  │  ├── 启动快                                         │
  │  └── 攻击面小                                       │
  └─────────────────────────────────────────────────────┘
```

### 1.2 常见镜像的体积参考

```
Node.js 18 镜像体积对比：

  node:18              ~900MB   ← 完整版（Debian）
  node:18-slim         ~200MB   ← 精简版（Debian）
  node:18-alpine       ~170MB   ← Alpine 版

  Python 3.11 镜像体积对比：

  python:3.11          ~1GB     ← 完整版
  python:3.11-slim     ~130MB   ← 精简版
  python:3.11-alpine   ~50MB    ← Alpine 版

  结论：选择合适的基础镜像是最有效的优化
```

## 二、减小镜像体积的技巧

### 2.1 选择合适的基础镜像

```dockerfile
# ❌ 完整版：包含大量不需要的工具
FROM node:18

# ✅ Alpine 版：最小体积
FROM node:18-alpine

# ✅ Slim 版：兼容性好，体积适中
FROM node:18-slim
```

```
选择建议：

  Alpine：
  - 体积最小
  - 使用 musl libc（某些 npm 包可能不兼容）
  - 适合纯 Node.js 项目

  Slim：
  - 基于 Debian，兼容性好
  - 体积适中
  - 需要编译原生模块时推荐

  完整版：
  - 开发调试时使用
  - 生产环境不推荐
```

### 2.2 多阶段构建

```dockerfile
# 构建阶段：需要所有工具
FROM node:18-alpine AS builder
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build
RUN npm prune --production

# 运行阶段：只保留必要文件
FROM node:18-alpine AS production
WORKDIR /app
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
COPY package.json ./
CMD ["node", "dist/index.js"]
```

### 2.3 合并 RUN 指令并清理

```dockerfile
# ❌ 多层且不清理
RUN apt-get update
RUN apt-get install -y curl
RUN apt-get install -y wget

# ✅ 合并为一层并清理
RUN apt-get update \
    && apt-get install -y --no-install-recommends curl wget \
    && rm -rf /var/lib/apt/lists/*
```

```
清理技巧：

  Debian/Ubuntu：
    rm -rf /var/lib/apt/lists/*

  Alpine：
    apk add --no-cache package

  npm：
    npm cache clean --force

  pip：
    pip install --no-cache-dir package
```

### 2.4 使用 .dockerignore

```dockerignore
# 排除不需要的文件，减少构建上下文
node_modules
.git
*.md
docs
test
coverage
```

### 2.5 安装生产依赖 only

```dockerfile
# 安装所有依赖（包括 devDependencies）
RUN npm ci

# 只安装生产依赖
RUN npm ci --only=production

# 或者在构建后清理
RUN npm ci && npm run build && npm prune --production
```

## 三、安全基础

### 3.1 镜像安全扫描

```
镜像中可能存在的安全漏洞：

  ┌─────────────────────────────────────────────┐
  │           镜像安全扫描                        │
  │                                              │
  │  基础镜像中的系统库                           │
  │  ├── openssl 可能有已知漏洞                   │
  │  ├── curl 可能有已知漏洞                      │
  │  └── 其他系统包                              │
  │                                              │
  │  应用依赖中的 npm 包                          │
  │  ├── express 可能有已知漏洞                   │
  │  ├── lodash 可能有已知漏洞                    │
  │  └── 其他依赖                                │
  └─────────────────────────────────────────────┘
```

```bash
# 使用 Docker Scout 扫描（Docker Desktop 自带）
docker scout cves my-app:latest

# 使用 Trivy 扫描
trivy image my-app:latest

# 使用 Snyk 扫描
snyk container test my-app:latest
```

### 3.2 非 root 用户运行

```dockerfile
# ❌ 默认以 root 运行（危险）
FROM node:18-alpine
WORKDIR /app
COPY . .
CMD ["node", "src/index.js"]
# 容器内进程以 root 运行

# ✅ 创建专用用户（推荐）
FROM node:18-alpine

# 创建用户组和用户
RUN addgroup -g 1001 -S nodejs \
    && adduser -S nodeuser -u 1001 -G nodejs

WORKDIR /app

# 设置目录权限
COPY --chown=nodeuser:nodejs . .

# 切换到非 root 用户
USER nodeuser

CMD ["node", "src/index.js"]
```

```
为什么非 root 用户更安全？

  以 root 运行的风险：
  ├── 容器逃逸后获得宿主机 root 权限
  ├── 可以修改系统文件
  ├── 可以安装恶意软件
  └── 可以访问其他容器的资源

  以非 root 运行：
  ├── 即使被攻破，权限有限
  ├── 无法修改系统文件
  ├── 限制了攻击的影响范围
  └── 符合最小权限原则
```

### 3.3 只读文件系统

```bash
# 以只读模式运行容器
docker run --read-only my-app

# 如果需要写入临时文件，挂载 tmpfs
docker run --read-only --tmpfs /tmp my-app
```

### 3.4 限制资源

```bash
# 限制 CPU 和内存
docker run \
  --memory=512m \
  --cpus=1 \
  my-app

# 限制重启次数
docker run --restart=on-failure:3 my-app
```

## 四、安全反模式

### 4.1 常见错误

```dockerfile
# ❌ 错误 1：在镜像中硬编码密钥
ENV DB_PASSWORD=secret123
ENV API_KEY=sk-1234567890

# ❌ 错误 2：使用 latest 标签
FROM node:latest

# ❌ 错误 3：以 root 运行
# （没有 USER 指令）

# ❌ 错误 4：安装不需要的工具
RUN apt-get install -y vim nano curl wget git

# ❌ 错误 5：COPY 整个目录包括 .env
COPY . .
```

### 4.2 正确做法

```dockerfile
# ✅ 正确 1：运行时传入环境变量
# docker run -e DB_PASSWORD=secret my-app

# ✅ 正确 2：使用固定版本
FROM node:18.17.0-alpine

# ✅ 正确 3：非 root 用户
USER nodeuser

# ✅ 正确 4：只安装必要工具
RUN apk add --no-cache curl

# ✅ 正确 5：使用 .dockerignore
COPY --chown=nodeuser:nodejs . .
```

## 五、最佳实践清单

```
Dockerfile 安全与优化清单：

  基础镜像：
  ✅ 使用特定版本标签，不用 latest
  ✅ 优先选择 alpine 或 slim 版本
  ✅ 定期更新基础镜像以获取安全补丁

  构建：
  ✅ 使用多阶段构建
  ✅ 合并 RUN 指令并清理缓存
  ✅ 使用 .dockerignore 排除不需要的文件
  ✅ 只安装生产依赖

  安全：
  ✅ 以非 root 用户运行
  ✅ 不在镜像中硬编码密钥
  ✅ 定期扫描镜像漏洞
  ✅ 使用只读文件系统（如适用）

  运行：
  ✅ 限制 CPU 和内存
  ✅ 设置重启策略
  ✅ 使用健康检查
```

## 六、动手练习

### 练习一：优化镜像体积

```bash
# 1. 使用完整版基础镜像构建
cat > Dockerfile.full << 'EOF'
FROM node:18
WORKDIR /app
COPY . .
RUN npm install
CMD ["node", "src/index.js"]
EOF
docker build -f Dockerfile.full -t demo:full .

# 2. 使用多阶段 + Alpine 构建
cat > Dockerfile.optimized << 'EOF'
FROM node:18-alpine AS builder
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build
RUN npm prune --production

FROM node:18-alpine
RUN addgroup -g 1001 -S nodejs && adduser -S nodeuser -u 1001
WORKDIR /app
COPY --from=builder --chown=nodeuser:nodejs /app/dist ./dist
COPY --from=builder --chown=nodeuser:nodejs /app/node_modules ./node_modules
COPY --from=builder --chown=nodeuser:nodejs /app/package.json ./
USER nodeuser
CMD ["node", "dist/index.js"]
EOF
docker build -f Dockerfile.optimized -t demo:optimized .

# 3. 对比体积
docker images | grep demo
```

### 练习二：安全扫描

```bash
# 1. 构建一个镜像
docker build -t security-test .

# 2. 使用 Docker Scout 扫描
docker scout cves security-test

# 3. 查看漏洞报告，了解有哪些问题
```

### 练习三：非 root 用户

```bash
# 1. 以默认（root）用户运行
docker run -it --rm node:18-alpine whoami
# 输出：root

# 2. 以指定用户运行
docker run -it --rm --user 1001:1001 node:18-alpine whoami
# 输出：uid=1001

# 3. 在 Dockerfile 中设置 USER 指令，验证效果
```

## 小结

本课的核心要点：

1. **镜像体积影响**构建速度、部署速度、存储成本和安全攻击面
2. **减小体积**：选择 alpine/slim 基础镜像、多阶段构建、合并 RUN、清理缓存
3. **安全基础**：非 root 用户运行、不硬编码密钥、定期扫描漏洞
4. **使用 .dockerignore** 排除敏感文件和不需要的文件
5. **固定版本**：不用 `latest` 标签，确保构建可重复
