## 一、什么是灰度发布

```
灰度发布（Canary Release）：

  逐步将流量从旧版本切换到新版本

  ┌─────────────────────────────────────────┐
  │           灰度发布过程                    │
  │                                          │
  │  阶段 1：旧版本 100%，新版本 0%          │
  │  阶段 2：旧版本 90%，新版本 10%          │
  │  阶段 3：旧版本 50%，新版本 50%          │
  │  阶段 4：旧版本 0%，新版本 100%          │
  │                                          │
  │  如果新版本有问题，随时回滚              │
  └─────────────────────────────────────────┘
```

## 二、使用 Nginx 实现灰度

```nginx
# nginx/conf.d/default.conf
upstream app {
    # 旧版本（权重 9）
    server app-v1:3000 weight=9;
    # 新版本（权重 1）
    server app-v2:3000 weight=1;
}

server {
    listen 80;
    server_name my-app.com;

    location / {
        proxy_pass http://app;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

```yaml
# docker-compose.yml
services:
  app-v1:
    image: my-app:v1.0
    restart: unless-stopped

  app-v2:
    image: my-app:v2.0
    restart: unless-stopped

  nginx:
    image: nginx:1.25-alpine
    ports:
      - "80:80"
    volumes:
      - ./nginx/conf.d:/etc/nginx/conf.d:ro
    restart: unless-stopped
```

## 三、Docker 镜像回滚

### 3.1 使用 Git 标签

```bash
# 查看可用版本
git tag -l

# 回滚到指定版本
git checkout v1.0.0
docker compose -f docker-compose.prod.yml up -d --build
```

### 3.2 使用镜像标签

```bash
# 拉取旧版本镜像
docker pull ghcr.io/yourusername/yourrepo:v1.0.0

# 更新 compose.yml 使用旧版本
# 或者使用环境变量
export IMAGE_TAG=v1.0.0
docker compose up -d
```

### 3.3 回滚脚本

```bash
#!/bin/bash
# scripts/rollback.sh

VERSION=$1

if [ -z "$VERSION" ]; then
    echo "Usage: ./rollback.sh <version>"
    echo "Available versions:"
    docker images --format "table {{.Tag}}" my-app
    exit 1
fi

echo "Rolling back to version: $VERSION"

# 更新镜像版本
export IMAGE_TAG=$VERSION

# 拉取镜像
docker compose pull

# 重启服务
docker compose up -d

# 健康检查
sleep 10
curl -f http://localhost:3000/health || exit 1

echo "Rollback completed!"
```

## 四、回滚策略

```
回滚策略：

  自动回滚：
  ├── 健康检查失败 → 自动回滚
  ├── 错误率超过阈值 → 自动回滚
  └── 响应时间超过阈值 → 自动回滚

  手动回滚：
  ├── 监控告警 → 人工判断 → 手动回滚
  └── 用户反馈 → 人工判断 → 手动回滚

  最佳实践：
  ✅ 保留最近 3-5 个版本的镜像
  ✅ 回滚脚本要测试过
  ✅ 回滚后要通知团队
  ✅ 分析回滚原因，避免再次发生
```

## 五、蓝绿部署

```
蓝绿部署（Blue-Green）：

  ┌─────────────────────────────────────────┐
  │                                          │
  │  蓝色环境（当前生产）    绿色环境（新版本）│
  │  ┌──────────────┐      ┌──────────────┐ │
  │  │   App v1.0   │      │   App v2.0   │ │
  │  └──────────────┘      └──────────────┘ │
  │         ↑                     ↑          │
  │         │                     │          │
  │  ┌──────────────────────────────────┐   │
  │  │           Nginx / LB             │   │
  │  │    100% 流量 → 蓝色环境          │   │
  │  └──────────────────────────────────┘   │
  │                                          │
  │  切换流量：                              │
  │  100% 流量 → 绿色环境                   │
  │                                          │
  └─────────────────────────────────────────┘

  优势：切换快，回滚快
  劣势：需要双倍资源
```

## 小结

1. **灰度发布**：逐步将流量切换到新版本
2. **Nginx 权重**：简单的灰度实现方式
3. **回滚**：使用 Git 标签或镜像标签快速回滚
4. **回滚策略**：自动回滚 + 手动回滚
