## 一、健康检查的层次

```
健康检查的三个层次：

  ┌─────────────────────────────────────────┐
  │  Layer 1: 进程存活（Docker 自动检测）    │
  │  ├── 容器进程是否在运行                  │
  │  └── 不能反映服务是否真正可用            │
  │                                          │
  │  Layer 2: 端口可访问                     │
  │  ├── 服务是否在监听端口                  │
  │  └── 不能反映服务是否能处理请求          │
  │                                          │
  │  Layer 3: 应用健康（推荐）               │
  │  ├── 服务是否能处理请求                  │
  │  ├── 依赖（数据库、缓存）是否正常        │
  │  └── 真正反映服务状态                    │
  └─────────────────────────────────────────┘
```

## 二、健康检查端点设计

### 2.1 基本健康检查

```javascript
// GET /health
app.get('/health', (req, res) => {
  res.json({ status: 'ok', timestamp: new Date().toISOString() });
});
```

### 2.2 带依赖检查的健康检查

```javascript
// GET /health
app.get('/health', async (req, res) => {
  const checks = {
    status: 'ok',
    timestamp: new Date().toISOString(),
    uptime: process.uptime(),
    dependencies: {}
  };

  // 检查 PostgreSQL
  try {
    await pgPool.query('SELECT 1');
    checks.dependencies.postgres = 'ok';
  } catch (error) {
    checks.dependencies.postgres = 'error';
    checks.status = 'degraded';
  }

  // 检查 Redis
  try {
    await redisClient.ping();
    checks.dependencies.redis = 'ok';
  } catch (error) {
    checks.dependencies.redis = 'error';
    checks.status = 'degraded';
  }

  const statusCode = checks.status === 'ok' ? 200 : 503;
  res.status(statusCode).json(checks);
});
```

### 2.3 Liveness vs Readiness

```javascript
// Liveness: 进程是否存活（不检查依赖）
app.get('/healthz', (req, res) => {
  res.json({ status: 'alive' });
});

// Readiness: 是否准备好接收请求（检查依赖）
app.get('/readyz', async (req, res) => {
  try {
    await pgPool.query('SELECT 1');
    await redisClient.ping();
    res.json({ status: 'ready' });
  } catch (error) {
    res.status(503).json({ status: 'not ready', error: error.message });
  }
});
```

## 三、Docker 中的健康检查配置

> 基础的 Dockerfile HEALTHCHECK 和 Compose healthcheck 语法已在第二阶段第六课详细讲解。
> 本课聚焦于**设计原则**和**进阶用法**。

### 3.1 Liveness vs Readiness（核心区别）

```
很多开发者只写一个 /health 端点，但在生产环境中应该区分两种检查：

  Liveness（存活检查）：
  ├── 问题：进程还活着吗？
  ├── 检查：进程是否在运行
  ├── 失败时：重启容器
  └── 不检查依赖（数据库挂了不应该重启应用）

  Readiness（就绪检查）：
  ├── 问题：能处理请求吗？
  ├── 检查：进程 + 依赖（数据库、缓存）都正常
  ├── 失败时：从负载均衡中移除，不接收新请求
  └── 检查依赖（数据库挂了应该停止接收请求）
```

### 3.2 实现方式

```javascript
// Liveness：只检查进程本身（轻量，不查依赖）
app.get('/healthz', (req, res) => {
  res.json({ status: 'alive' });
});

// Readiness：检查所有依赖（数据库、缓存等）
app.get('/readyz', async (req, res) => {
  try {
    await pgPool.query('SELECT 1');
    await redisClient.ping();
    res.json({ status: 'ready' });
  } catch (error) {
    res.status(503).json({ status: 'not ready', error: error.message });
  }
});
```

### 3.3 在 Docker Compose 中配置

```yaml
services:
  app:
    healthcheck:
      # 用 readiness 端点作为 Docker 健康检查
      test: ["CMD", "curl", "-f", "http://localhost:3000/readyz"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 40s
    depends_on:
      postgres:
        condition: service_healthy
```

## 四、健康检查端点设计

### 4.1 带依赖检查的完整端点

```javascript
app.get('/health', async (req, res) => {
  const checks = {
    status: 'ok',
    timestamp: new Date().toISOString(),
    uptime: process.uptime(),
    dependencies: {}
  };

  // 检查 PostgreSQL
  try {
    await pgPool.query('SELECT 1');
    checks.dependencies.postgres = 'ok';
  } catch (error) {
    checks.dependencies.postgres = 'error';
    checks.status = 'degraded';
  }

  // 检查 Redis
  try {
    await redisClient.ping();
    checks.dependencies.redis = 'ok';
  } catch (error) {
    checks.dependencies.redis = 'error';
    checks.status = 'degraded';
  }

  const statusCode = checks.status === 'ok' ? 200 : 503;
  res.status(statusCode).json(checks);
});
```

### 4.2 常见服务的健康检查命令

| 服务 | 命令 | 说明 |
|------|------|------|
| PostgreSQL | `pg_isready -U postgres` | 检查连接就绪 |
| MySQL | `mysqladmin ping -h localhost` | 检查连接就绪 |
| Redis | `redis-cli ping` | 检查连接就绪 |
| MongoDB | `mongosh --eval "db.adminCommand('ping')"` | 检查连接就绪 |
| HTTP 服务 | `curl -f http://localhost:3000/health` | 检查 HTTP 响应 |

> 完整的 Compose 配置语法见第二阶段第六课。

## 五、最佳实践

```
健康检查最佳实践：

  ✅ 区分 liveness 和 readiness
  ✅ 检查关键依赖（数据库、缓存）
  ✅ 设置合理的超时和重试
  ✅ 使用 start_period 避免启动误判
  ✅ 健康检查要轻量，不要有副作用
  ❌ 不要在健康检查中执行重操作
  ❌ 不要忽略依赖检查
```

## 小结

1. **三层检查**：进程存活、端口可访问、应用健康
2. **Liveness vs Readiness**：存活检查不查依赖，就绪检查查依赖——生产环境必须区分
3. **健康端点设计**：返回依赖状态、使用合适的 HTTP 状态码
4. **配置语法**：见第二阶段第六课，本课聚焦设计原则
