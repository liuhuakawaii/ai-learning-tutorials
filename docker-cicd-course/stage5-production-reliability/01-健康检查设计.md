## 一、健康检查的层次

```
健康检查的三个层次：

  ┌─────────────────────────────────────────┐
  │  Layer 1: 进程存活（Docker 自动检测）    │
  │  ├── 容器进程是否在运行                  │
  │  └── 不能反映服务是否真正可用            │
  │                                          │
  │  Layer 2: 端口可访问                     │
  │  ├── 服务是否在监听端口                  │
  │  └── 不能反映服务是否能处理请求          │
  │                                          │
  │  Layer 3: 应用健康（推荐）               │
  │  ├── 服务是否能处理请求                  │
  │  ├── 依赖（数据库、缓存）是否正常        │
  │  └── 真正反映服务状态                    │
  └─────────────────────────────────────────┘
```

## 二、健康检查端点设计

### 2.1 基本健康检查

```javascript
// GET /health
app.get('/health', (req, res) => {
  res.json({ status: 'ok', timestamp: new Date().toISOString() });
});
```

### 2.2 带依赖检查的健康检查

```javascript
// GET /health
app.get('/health', async (req, res) => {
  const checks = {
    status: 'ok',
    timestamp: new Date().toISOString(),
    uptime: process.uptime(),
    dependencies: {}
  };

  // 检查 PostgreSQL
  try {
    await pgPool.query('SELECT 1');
    checks.dependencies.postgres = 'ok';
  } catch (error) {
    checks.dependencies.postgres = 'error';
    checks.status = 'degraded';
  }

  // 检查 Redis
  try {
    await redisClient.ping();
    checks.dependencies.redis = 'ok';
  } catch (error) {
    checks.dependencies.redis = 'error';
    checks.status = 'degraded';
  }

  const statusCode = checks.status === 'ok' ? 200 : 503;
  res.status(statusCode).json(checks);
});
```

### 2.3 Liveness vs Readiness

```javascript
// Liveness: 进程是否存活（不检查依赖）
app.get('/healthz', (req, res) => {
  res.json({ status: 'alive' });
});

// Readiness: 是否准备好接收请求（检查依赖）
app.get('/readyz', async (req, res) => {
  try {
    await pgPool.query('SELECT 1');
    await redisClient.ping();
    res.json({ status: 'ready' });
  } catch (error) {
    res.status(503).json({ status: 'not ready', error: error.message });
  }
});
```

## 三、Docker 健康检查配置

```dockerfile
# Dockerfile
HEALTHCHECK --interval=30s --timeout=3s --start-period=10s --retries=3 \
  CMD curl -f http://localhost:3000/health || exit 1
```

```yaml
# docker-compose.yml
services:
  app:
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:3000/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 40s
```

## 四、常见服务的健康检查

```yaml
# PostgreSQL
healthcheck:
  test: ["CMD-SHELL", "pg_isready -U postgres"]
  interval: 5s
  timeout: 5s
  retries: 5

# Redis
healthcheck:
  test: ["CMD", "redis-cli", "ping"]
  interval: 5s
  timeout: 5s
  retries: 5

# MySQL
healthcheck:
  test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
  interval: 5s
  timeout: 5s
  retries: 5
```

## 五、最佳实践

```
健康检查最佳实践：

  ✅ 区分 liveness 和 readiness
  ✅ 检查关键依赖（数据库、缓存）
  ✅ 设置合理的超时和重试
  ✅ 使用 start_period 避免启动误判
  ✅ 健康检查要轻量，不要有副作用
  ❌ 不要在健康检查中执行重操作
  ❌ 不要忽略依赖检查
```

## 小结

1. **三层检查**：进程存活、端口可访问、应用健康
2. **Liveness vs Readiness**：存活检查 vs 就绪检查
3. **依赖检查**：数据库、缓存等关键依赖
4. **配置**：Dockerfile 和 Compose 中的 HEALTHCHECK
