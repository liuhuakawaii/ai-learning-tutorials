## 一、监控的核心指标

```
四个黄金信号（Google SRE）：

  ┌─────────────────────────────────────────┐
  │  延迟（Latency）                         │
  │  └── 请求响应时间                        │
  │                                          │
  │  流量（Traffic）                         │
  │  └── 每秒请求数                          │
  │                                          │
  │  错误（Errors）                          │
  │  └── 错误率                              │
  │                                          │
  │  饱和度（Saturation）                    │
  │  └── CPU、内存、磁盘使用率               │
  └─────────────────────────────────────────┘
```

## 二、Docker 内置监控

```bash
# 实时资源使用
docker stats

# 输出示例：
# CONTAINER   CPU %   MEM USAGE / LIMIT   MEM %   NET I/O       BLOCK I/O
# app         0.50%   128MiB / 512MiB     25%     1.5kB / 2kB   0B / 0B
# postgres    1.20%   256MiB / 1GiB       25%     3kB / 4kB     10MB / 5MB
# redis       0.10%   32MiB / 256MiB      12%     1kB / 1kB     0B / 0B

# 查看容器日志
docker logs --tail=100 -f app

# 查看容器事件
docker events --filter container=app
```

## 三、轻量级监控方案

### 3.1 cAdvisor + Prometheus + Grafana

```yaml
# docker-compose.monitoring.yml
services:
  cadvisor:
    image: gcr.io/cadvisor/cadvisor:latest
    volumes:
      - /:/rootfs:ro
      - /var/run:/var/run:ro
      - /sys:/sys:ro
      - /var/lib/docker/:/var/lib/docker:ro
    ports:
      - "8080:8080"
    restart: unless-stopped

  prometheus:
    image: prom/prometheus:latest
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml
      - prometheus-data:/prometheus
    ports:
      - "9090:9090"
    restart: unless-stopped

  grafana:
    image: grafana/grafana:latest
    volumes:
      - grafana-data:/var/lib/grafana
    ports:
      - "3001:3000"
    environment:
      GF_SECURITY_ADMIN_PASSWORD: admin
    restart: unless-stopped

volumes:
  prometheus-data:
  grafana-data:
```

### 3.2 简单的健康检查脚本

```bash
#!/bin/bash
# scripts/health-check.sh

# 检查服务状态
check_service() {
    local service=$1
    local url=$2
    
    response=$(curl -s -o /dev/null -w "%{http_code}" "$url" 2>/dev/null)
    
    if [ "$response" = "200" ]; then
        echo "✅ $service: OK"
    else
        echo "❌ $service: FAILED (HTTP $response)"
        # 发送告警
        send_alert "$service" "$response"
    fi
}

send_alert() {
    local service=$1
    local status=$2
    
    # 发送到 Slack / 邮件 / 钉钉
    curl -X POST -H 'Content-type: application/json' \
        --data "{\"text\":\"⚠️ Service $service is down (HTTP $status)\"}" \
        "$SLACK_WEBHOOK_URL"
}

# 检查各个服务
check_service "App" "http://localhost:3000/health"
check_service "PostgreSQL" "http://localhost:5432"
check_service "Redis" "http://localhost:6379"
```

## 四、告警策略

```
告警级别：

  紧急（P0）：
  ├── 服务完全不可用
  ├── 数据丢失
  └── 安全事件

  严重（P1）：
  ├── 错误率 > 5%
  ├── 响应时间 > 5s
  └── 磁盘 > 90%

  警告（P2）：
  ├── 错误率 > 1%
  ├── 响应时间 > 2s
  └── 磁盘 > 80%

  通知方式：
  ├── P0：电话 + 短信 + Slack
  ├── P1：Slack + 邮件
  └── P2：Slack
```

## 五、日志管理

```yaml
services:
  app:
    logging:
      driver: json-file
      options:
        max-size: "10m"
        max-file: "3"
```

```bash
# 查看日志
docker logs --tail=100 app
docker logs --since=1h app
docker logs --since=2023-01-01T00:00:00 app

# 导出日志
docker logs app > app.log 2>&1
```
