# 最终项目：Production RAG System

> 将课程所学整合为一个完整的生产级 RAG 系统

## 项目概述

构建一个面向真实业务场景的生产级 RAG 系统，涵盖从文档摄入到评估优化的完整生命周期。

## 项目目标

1. **端到端 RAG 系统**：从文档解析到答案生成的完整流程
2. **生产级质量**：包含缓存、流式输出、安全防御、可观测性
3. **可评估**：内建评估体系，支持自动化质量度量
4. **可部署**：Docker 化部署，支持水平扩展

## 业务场景

选择以下场景之一（或自定义）：

| 场景 | 数据类型 | 挑战点 |
|------|----------|--------|
| 企业知识库 | 内部文档、Wiki、邮件 | 权限控制、多格式文档 |
| 客服系统 | FAQ、产品手册、工单 | 多轮对话、意图识别 |
| 法律助手 | 法规、判例、合同 | 精确引用、长文档 |
| 技术文档 | API 文档、SDK、教程 | 代码理解、版本管理 |
| 医疗问答 | 指南、论文、病例 | 准确性要求高、安全敏感 |

## 交付物

### 1. 核心系统 (rag-production-kit/)

```
rag-production-kit/
├── README.md              # 项目说明
├── requirements.txt       # 依赖
├── .gitignore
├── scripts/
│   └── check.py          # 项目检查脚本
├── src/
│   ├── ingest.py         # 文档摄入
│   ├── retrieve.py       # 检索模块
│   ├── generate.py       # 生成模块
│   └── evaluate.py       # 评估模块
├── data/
│   └── sample/           # 示例文档
├── reports/
│   └── templates/        # 评估报告模板
└── tests/                # 测试
```

### 2. 功能要求

#### 基础功能（必须）
- [ ] 文档解析：支持 PDF、Markdown、HTML
- [ ] 分块：至少实现 2 种分块策略
- [ ] 向量化：支持至少 2 种 Embedding 模型
- [ ] 检索：支持向量检索 + 关键词检索
- [ ] 生成：支持流式输出
- [ ] API：FastAPI 接口，包含健康检查

#### 进阶功能（加分）
- [ ] 混合检索 + 重排序
- [ ] 语义缓存
- [ ] 查询改写（HyDE / Multi-Query）
- [ ] Self-RAG 反思机制
- [ ] RAGAS 评估集成
- [ ] Prometheus 指标 + Grafana 看板
- [ ] Prompt Injection 防御
- [ ] A/B 测试框架

### 3. 质量要求

| 维度 | 要求 |
|------|------|
| 代码质量 | 通过 mypy 和 ruff 检查 |
| 测试覆盖 | 核心模块 >= 80% |
| 文档 | README 包含使用说明和架构图 |
| 评估 | 提供 RAGAS 评估报告 |
| 性能 | P95 延迟 < 5s（简单查询） |

## 评分标准

| 维度 | 权重 | 说明 |
|------|------|------|
| 系统设计 | 25% | 架构合理性、模块化程度 |
| 检索质量 | 25% | Recall@K、MRR 等指标 |
| 生成质量 | 20% | Faithfulness、Relevancy |
| 工程实践 | 20% | 缓存、安全、可观测性 |
| 代码规范 | 10% | 类型注解、测试、文档 |

## 时间建议

| 阶段 | 时间 | 内容 |
|------|------|------|
| 需求分析 | 1 天 | 确定场景、收集数据 |
| 核心开发 | 3 天 | 实现基础 RAG 流程 |
| 优化迭代 | 2 天 | 混合检索、重排序、缓存 |
| 生产化 | 2 天 | API、安全、监控、部署 |
| 评估优化 | 2 天 | 评估、调优、文档 |
| **总计** | **10 天** | |

1. 进入 `rag-production-kit/` 目录
2. 阅读 `README.md` 了解项目结构
3. 运行 `python scripts/check.py` 检查环境
4. 从 `src/ingest.py` 开始实现
