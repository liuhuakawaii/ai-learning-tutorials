## 常见误区

- 缓存策略只按查询文本做 key，忽略了同义词和表述差异导致缓存命中率极低
- 错误重试没有做指数退避，所有重试瞬间发出导致下游服务雪崩
- 日志只记录成功请求，失败请求没有详细上下文信息，排查问题时无从下手

## 工程建议

- 缓存 key 应基于查询的 Embedding 向量（语义缓存），而非原始文本，相似查询可以命中同一缓存
- 重试使用指数退避策略（1s → 2s → 4s），最多重试 3 次，并区分可重试错误（超时）和不可重试错误（参数错误）
- 日志必须包含：请求 ID、检索到的文档 ID 列表、Token 消耗、总延迟、错误堆栈，方便端到端追踪
