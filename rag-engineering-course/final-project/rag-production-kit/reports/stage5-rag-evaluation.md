# 阶段五报告：RAG 评估

## 场景引入

RAG 系统上线后，老板问"回答质量怎么样？"你却无法给出一个量化的答案。没有评估体系，你不知道改动是改善还是恶化，也无法向利益相关者证明系统的价值。RAGAS 等评估框架提供了多维度的量化指标，但如何构建评估数据集、如何解读评估结果、如何用评估驱动迭代？本阶段解决这些关键问题。

## 评估框架

- RAGAS 评估指标：
  - Faithfulness（忠实度）
  - Answer Relevancy（回答相关性）
  - Context Precision（上下文精确度）
  - Context Recall（上下文召回率）

## 常见误区

- 评估数据集只包含简单问题，没有覆盖多跳推理、模糊查询、否定问句等复杂场景
- 过度依赖 RAGAS 的单一分数，不拆解各维度指标，无法定位具体是检索还是生成的问题
- 评估只做一次就完事，没有建立持续评估机制，系统迭代后质量悄悄退步

## 工程建议

- 评估数据集应包含 4 类问题：简单事实、多跳推理、模糊查询、对抗性问题，每类至少 20 条
- 评估报告拆解看：Context Precision/Recall 低说明检索有问题，Faithfulness 低说明生成有问题，Relevancy 低说明查询理解有问题
- 建立 CI/CD 集成评估——每次 Prompt 或检索策略变更后自动运行评估，低于基线则阻断部署
