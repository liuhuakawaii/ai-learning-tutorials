# Stage 2 · L3: 查询改写与扩展

> **时长**: 50 分钟 | **前置**: L2 完成

## 场景引入

用户在你的 RAG 系统里输入"退款"两个字就点了搜索。系统返回了一堆关于退款的文档，但用户其实想问的是"微信支付的退款多久到账"。原始查询太短、太模糊，向量检索只能猜用户的意图。更棘手的是，有些用户会问"Python 和 Java 哪个好"这种需要多角度回答的问题，单次检索很难覆盖所有相关文档。查询改写和扩展就是让系统在检索之前先"想清楚"用户到底在问什么，甚至把一个问题拆成多个子查询来提高召回率。

## 学习目标

完成本课后，你将能够：

1. 理解 HyDE（假设性文档嵌入）的原理并实现
2. 使用 Multi-Query 扩展技术提升召回率
3. 运用 Step-Back Prompting 处理复杂问题
4. 构建查询路由器，根据问题类型选择最优检索策略
5. 对比不同查询改写策略的效果

## 2. HyDE：假设性文档嵌入

**HyDE (Hypothetical Document Embeddings)** 的核心思想：

```
┌─────────────────────────────────────────────────────────────────┐
│                    HyDE 工作流程                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  原始 Query: "Python 和 Java 哪个更适合后端开发"                   │
│       │                                                         │
│       ▼                                                         │
│  ┌─────────────────────────────────────┐                        │
│  │  Step 1: LLM 生成假设性回答          │                        │
│  │                                     │                        │
│  │  "Python 适合快速开发和原型验证，     │                        │
│  │   Django/Flask 框架生态成熟。         │                        │
│  │   Java 适合大型企业应用，             │                        │
│  │   Spring Boot 性能优异..."           │                        │
│  └──────────────┬──────────────────────┘                        │
│                 ▼                                                │
│  ┌─────────────────────────────────────┐                        │
│  │  Step 2: 对假设性回答做 Embedding    │                        │
│  │                                     │                        │
│  │  [0.12, -0.34, 0.56, ...]          │                        │
│  └──────────────┬──────────────────────┘                        │
│                 ▼                                                │
│  ┌─────────────────────────────────────┐                        │
│  │  Step 3: 用假设性向量检索真实文档     │                        │
│  └──────────────┬──────────────────────┘                        │
│                 ▼                                                │
│          返回最相关的真实文档                                      │
│                                                                 │
│  为什么有效?                                                     │
│  · 假设性回答包含了更多关键词和语义信息                             │
│  · 将"问题→文档"转化为"回答→文档"，语义更接近                      │
│  · 即使回答不正确，其语义方向通常也是对的                           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.1 HyDE 实现

```python
"""
HyDE (Hypothetical Document Embeddings) 实现
使用 LangChain 框架
"""
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain.prompts import ChatPromptTemplate
from langchain.schema import Document
from langchain_community.vectorstores import Chroma
from typing import List


class HyDERetriever:
    """HyDE 检索器"""

    def __init__(
        self,
        documents: List[Document],
        llm_model: str = "gpt-4o-mini",
        embedding_model: str = "text-embedding-3-small"
    ):
        self.llm = ChatOpenAI(model=llm_model, temperature=0)
        self.embeddings = OpenAIEmbeddings(model=embedding_model)

        # 构建向量数据库
        self.vectorstore = Chroma.from_documents(documents, self.embeddings)

        # 假设性文档生成提示词
        self.hyde_prompt = ChatPromptTemplate.from_template("""
你是一个知识库助手。请根据以下问题，生成一段可能的回答。
即使你不确定答案，也要尽量生成一段合理、详细的回答。
这段回答将用于检索相关文档，所以请包含与问题相关的关键词和概念。

问题: {question}

请生成一段 100-200 字的回答:
""")

    def _generate_hypothetical_document(self, query: str) -> str:
        """生成假设性文档"""
        chain = self.hyde_prompt | self.llm
        response = chain.invoke({"question": query})
        return response.content

    def retrieve(self, query: str, top_k: int = 5) -> List[Document]:
        """
        HyDE 检索流程

        Args:
            query: 用户查询
            top_k: 返回文档数

        Returns:
            检索到的文档列表
        """
        # Step 1: 生成假设性文档
        hypothetical_doc = self._generate_hypothetical_document(query)
        print(f"假设性文档:\n{hypothetical_doc}\n")

        # Step 2: 用假设性文档做检索
        results = self.vectorstore.similarity_search(
            hypothetical_doc, k=top_k
        )

        return results


# ========== 使用示例 ==========
if __name__ == "__main__":
    documents = [
        Document(page_content="Python 适合快速开发，Django 和 Flask 是最流行的 Web 框架"),
        Document(page_content="Java 在企业级应用中占据主导地位，Spring Boot 生态完善"),
        Document(page_content="Go 语言以高并发著称，适合微服务架构"),
        Document(page_content="Rust 注重内存安全，适合系统编程"),
        Document(page_content="TypeScript 为 JavaScript 添加了类型系统，提升开发体验"),
    ]

    retriever = HyDERetriever(documents)
    results = retriever.retrieve("Python 和 Java 哪个更适合后端开发")

    for i, doc in enumerate(results):
        print(f"[{i+1}] {doc.page_content}")
```

### 3.1 Multi-Query 实现

```python
"""
Multi-Query 检索器实现
"""
from langchain_openai import ChatOpenAI
from langchain.prompts import ChatPromptTemplate
from langchain.schema import Document
from langchain_community.vectorstores import Chroma
from langchain_openai import OpenAIEmbeddings
from typing import List, Set
import hashlib


class MultiQueryRetriever:
    """Multi-Query 检索器"""

    def __init__(
        self,
        documents: List[Document],
        num_queries: int = 3,
        llm_model: str = "gpt-4o-mini"
    ):
        self.num_queries = num_queries
        self.llm = ChatOpenAI(model=llm_model, temperature=0.7)
        self.embeddings = OpenAIEmbeddings()
        self.vectorstore = Chroma.from_documents(documents, self.embeddings)

        # 查询改写提示词
        self.rewrite_prompt = ChatPromptTemplate.from_template("""
你是一个查询改写专家。请将以下问题改写为 {num_queries} 个不同的表述方式，
每个表述都从不同角度提问，以便更好地检索相关文档。

原始问题: {question}

请输出 {num_queries} 个改写后的查询，每行一个:
""")

    def _generate_queries(self, query: str) -> List[str]:
        """生成多个变体查询"""
        chain = self.rewrite_prompt | self.llm
        response = chain.invoke({
            "question": query,
            "num_queries": self.num_queries
        })

        queries = [
            q.strip()
            for q in response.content.strip().split("\n")
            if q.strip()
        ]
        return queries

    def _deduplicate(self, docs: List[Document]) -> List[Document]:
        """基于内容去重"""
        seen: Set[str] = set()
        unique_docs = []
        for doc in docs:
            content_hash = hashlib.md5(doc.page_content.encode()).hexdigest()
            if content_hash not in seen:
                seen.add(content_hash)
                unique_docs.append(doc)
        return unique_docs

    def retrieve(self, query: str, top_k: int = 5) -> List[Document]:
        """
        Multi-Query 检索

        Args:
            query: 原始查询
            top_k: 最终返回文档数

        Returns:
            去重后的文档列表
        """
        # Step 1: 生成变体查询
        variant_queries = self._generate_queries(query)
        all_queries = [query] + variant_queries

        print(f"原始查询: {query}")
        print(f"变体查询:")
        for i, q in enumerate(variant_queries):
            print(f"  [{i+1}] {q}")

        # Step 2: 分别检索
        all_docs = []
        for q in all_queries:
            docs = self.vectorstore.similarity_search(q, k=top_k)
            all_docs.extend(docs)

        # Step 3: 去重
        unique_docs = self._deduplicate(all_docs)

        return unique_docs[:top_k]


# ========== 使用示例 ==========
if __name__ == "__main__":
    documents = [
        Document(page_content="RAG 系统优化：使用混合检索结合 BM25 和向量搜索"),
        Document(page_content="提升向量数据库召回率的方法：调整 embedding 模型"),
        Document(page_content="Cross-Encoder Reranking 可以显著提升检索精度"),
        Document(page_content="查询改写技术：HyDE、Multi-Query、Step-Back"),
        Document(page_content="Chunk 策略对检索质量的影响：大小、重叠、分隔符"),
    ]

    retriever = MultiQueryRetriever(documents, num_queries=3)
    results = retriever.retrieve("如何提升 RAG 系统的检索质量")

    print(f"\n最终结果:")
    for i, doc in enumerate(results):
        print(f"  [{i+1}] {doc.page_content}")
```

## 4. Step-Back Prompting

**Step-Back Prompting** 将具体问题退化为更抽象、更通用的问题：

```
┌─────────────────────────────────────────────────────────────────┐
│                 Step-Back Prompting 流程                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  原始问题 (具体):                                                │
│  "Transformer 中 Multi-Head Attention 的 QKV 矩阵如何初始化"     │
│       │                                                         │
│       ▼                                                         │
│  ┌─────────────────────────────────────┐                        │
│  │  Step-Back: 退化为更通用的问题       │                        │
│  │                                     │                        │
│  │  "Transformer 注意力机制的工作原理"   │                        │
│  └──────────────┬──────────────────────┘                        │
│                 ▼                                                │
│  ┌─────────────────────────────────────┐                        │
│  │  用通用问题检索，获取背景知识         │                        │
│  └──────────────┬──────────────────────┘                        │
│                 ▼                                                │
│  ┌─────────────────────────────────────┐                        │
│  │  结合背景知识 + 原始问题 → LLM 生成  │                        │
│  └─────────────────────────────────────┘                        │
│                                                                 │
│  为什么有效?                                                     │
│  · 过于具体的问题可能匹配不到文档                                  │
│  · 通用问题更容易找到相关背景知识                                  │
│  · 背景知识帮助 LLM 更好地回答具体问题                             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.1 Step-Back 实现

```python
"""
Step-Back Prompting 检索器
"""
from langchain_openai import ChatOpenAI
from langchain.prompts import ChatPromptTemplate
from langchain.schema import Document
from langchain_community.vectorstores import Chroma
from langchain_openai import OpenAIEmbeddings
from typing import List, Tuple


class StepBackRetriever:
    """Step-Back Prompting 检索器"""

    def __init__(
        self,
        documents: List[Document],
        llm_model: str = "gpt-4o-mini"
    ):
        self.llm = ChatOpenAI(model=llm_model, temperature=0)
        self.embeddings = OpenAIEmbeddings()
        self.vectorstore = Chroma.from_documents(documents, self.embeddings)

        # Step-Back 问题生成提示词
        self.stepback_prompt = ChatPromptTemplate.from_template("""
你是一个问题泛化专家。请将以下具体问题退化为一个更通用、更抽象的问题。
这个通用问题应该涵盖原始问题的背景知识领域。

具体问题: {question}

请输出一个更通用的问题（只输出问题，不要解释）:
""")

    def _generate_stepback_query(self, query: str) -> str:
        """生成 Step-Back 通用问题"""
        chain = self.stepback_prompt | self.llm
        response = chain.invoke({"question": query})
        return response.content.strip()

    def retrieve(
        self,
        query: str,
        top_k: int = 5,
        use_both: bool = True
    ) -> Tuple[List[Document], str]:
        """
        Step-Back 检索

        Args:
            query: 原始具体问题
            top_k: 返回文档数
            use_both: 是否同时用原始查询和 Step-Back 查询检索

        Returns:
            (检索到的文档列表, Step-Back 问题)
        """
        # Step 1: 生成 Step-Back 问题
        stepback_query = self._generate_stepback_query(query)
        print(f"原始问题: {query}")
        print(f"Step-Back 问题: {stepback_query}")

        # Step 2: 检索
        if use_both:
            # 同时用两个查询检索，合并结果
            docs_original = self.vectorstore.similarity_search(query, k=top_k)
            docs_stepback = self.vectorstore.similarity_search(stepback_query, k=top_k)

            # 合并去重
            seen = set()
            combined = []
            for doc in docs_original + docs_stepback:
                if doc.page_content not in seen:
                    seen.add(doc.page_content)
                    combined.append(doc)

            return combined[:top_k], stepback_query
        else:
            # 只用 Step-Back 问题检索
            docs = self.vectorstore.similarity_search(stepback_query, k=top_k)
            return docs, stepback_query


# ========== 使用示例 ==========
if __name__ == "__main__":
    documents = [
        Document(page_content="Transformer 架构由 Vaswani 等人在 2017 年提出"),
        Document(page_content="Multi-Head Attention 通过多个注意力头捕捉不同维度的信息"),
        Document(page_content="QKV 矩阵由输入嵌入通过线性变换得到"),
        Document(page_content="注意力分数通过 Q 和 K 的点积计算，再除以 sqrt(d_k)"),
        Document(page_content="BERT 和 GPT 都基于 Transformer 架构"),
    ]

    retriever = StepBackRetriever(documents)
    results, stepback_q = retriever.retrieve(
        "Transformer 中 QKV 矩阵如何初始化"
    )

    print(f"\n检索结果 (使用 Step-Back: '{stepback_q}'):")
    for i, doc in enumerate(results):
        print(f"  [{i+1}] {doc.page_content}")
```

### 5.1 查询路由器实现

```python
"""
查询路由器 - 根据问题类型选择检索策略
"""
from langchain_openai import ChatOpenAI
from langchain.prompts import ChatPromptTemplate
from langchain.schema import Document
from typing import List, Dict, Literal
from enum import Enum


class QueryType(str, Enum):
    FACTUAL = "factual"          # 具体事实问题
    CONCEPTUAL = "conceptual"    # 概念理解问题
    COMPARATIVE = "comparative"  # 对比分析问题
    PROCEDURAL = "procedural"    # 操作指南问题


class QueryRouter:
    """查询路由器"""

    def __init__(self, llm_model: str = "gpt-4o-mini"):
        self.llm = ChatOpenAI(model=llm_model, temperature=0)

        self.classify_prompt = ChatPromptTemplate.from_template("""
请将以下问题分类为以下四种类型之一:
- factual: 具体事实问题（如"XXX 的参数是多少"）
- conceptual: 概念理解问题（如"XXX 是什么"、"XXX 的原理"）
- comparative: 对比分析问题（如"XXX 和 YYY 哪个好"）
- procedural: 操作指南问题（如"如何做 XXX"、"XXX 的步骤"）

问题: {question}

请只输出类型名称（factual/conceptual/comparative/procedural）:
""")

    def classify(self, query: str) -> QueryType:
        """分类查询类型"""
        chain = self.classify_prompt | self.llm
        response = chain.invoke({"question": query})
        type_str = response.content.strip().lower()

        try:
            return QueryType(type_str)
        except ValueError:
            return QueryType.FACTUAL  # 默认类型

    def route(
        self,
        query: str,
        retrievers: Dict[QueryType, any]
    ) -> List[Document]:
        """
        路由查询到对应检索器

        Args:
            query: 用户查询
            retrievers: {QueryType: retriever_instance} 映射

        Returns:
            检索到的文档
        """
        query_type = self.classify(query)
        print(f"查询类型: {query_type.value}")

        retriever = retrievers.get(query_type)
        if retriever is None:
            # 回退到默认检索器
            retriever = list(retrievers.values())[0]

        return retriever.retrieve(query)


# ========== 使用示例 ==========
if __name__ == "__main__":
    # 测试分类
    router = QueryRouter()

    test_queries = [
        "iPhone 15 的电池容量是多少",
        "什么是 Transformer 架构",
        "Python 和 Java 哪个更适合后端",
        "如何搭建 RAG 系统",
    ]

    for q in test_queries:
        qtype = router.classify(q)
        print(f"  [{qtype.value:12s}] {q}")
```

## 6. 策略对比

| 策略 | 原理 | 优势 | 劣势 | 适用场景 |
|------|------|------|------|----------|
| **HyDE** | LLM 生成假设回答，用回答做检索 | 语义匹配更准、无需标注数据 | LLM 生成可能有幻觉、增加延迟 | 通用问答、模糊查询 |
| **Multi-Query** | 生成多个变体查询，分别检索合并 | 多角度召回、覆盖面广 | 多次检索增加延迟和成本 | 复杂问题、需要全面信息 |
| **Step-Back** | 将具体问题退化为通用问题 | 获取背景知识、处理细节问题 | 可能丢失具体信息 | 技术细节问题、专业术语 |
| **Query Router** | 分类后选择最优策略 | 针对性强、效率高 | 需要维护分类器 | 混合场景、生产系统 |

```
┌─────────────────────────────────────────────────────────────────┐
│                查询改写策略选型决策树                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  查询是否模糊 / 太短?                                            │
│  ├── 是 → HyDE (生成假设性文档)                                  │
│  └── 否 → 查询是否需要多角度信息?                                 │
│          ├── 是 → Multi-Query (多路扩展)                         │
│          └── 否 → 查询是否过于专业/具体?                          │
│                  ├── 是 → Step-Back (退化为通用问题)              │
│                  └── 否 → 直接检索即可                            │
│                                                                 │
│  生产环境建议:                                                    │
│  → 使用 Query Router 组合多种策略                                 │
│  → 根据查询特征自动选择最优策略                                    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 7. 常见误区

### ❌ 错误 1: HyDE 生成的假设文档质量差

```python
# 错误: 不约束 LLM 输出格式和长度
prompt = "根据问题生成一段回答"  # 太宽泛

# 正确: 明确约束输出长度、格式、风格
prompt = """
请生成一段 100-200 字的回答，包含与问题相关的关键术语。
即使不确定答案，也要生成合理的回答（用于检索，不是最终答案）。
"""
```

### ❌ 错误 2: Multi-Query 变体太少或太相似

```python
# 错误: 只生成 1 个变体，或变体与原始查询几乎一样
num_queries = 1
prompt = "请换个说法重写这个问题"  # 可能得到几乎相同的查询

# 正确: 生成 3-5 个变体，明确要求从不同角度
num_queries = 3
prompt = "请从 {num_queries} 个不同角度改写问题，每个变体使用不同的关键词和表述方式"
```

### ❌ 错误 3: Step-Back 问题退化过度

```python
# 错误: 退化后的问题太宽泛，失去检索价值
原始: "Python list comprehension 语法"
退化: "什么是编程"  # 太宽泛了！

# 正确: 保持一定的领域相关性
退化: "Python 列表操作的常用方法"  # 适度泛化
```

### ❌ 错误 4: Query Router 分类不稳定

```python
# 错误: 分类 prompt 不明确，导致分类结果不稳定
prompt = "分类这个问题"  # 没有给出类别定义

# 正确: 给出清晰的类别定义和示例
prompt = """
分类标准:
- factual: 询问具体数据/参数 (例: "XXX 的价格是多少")
- conceptual: 询问概念/原理 (例: "XXX 是什么")
- comparative: 对比两个事物 (例: "A 和 B 哪个好")
- procedural: 询问操作步骤 (例: "如何做 XXX")
"""
```

## 8. 工程建议

1. **Multi-Query 的生成数量控制在 3-5 个**：生成太多变体会增加 LLM 调用成本和检索延迟，而且后续的去重融合也会更复杂。3-5 个变体通常能覆盖 80% 以上的语义角度。
2. **HyDE 对知识库覆盖度要求高**：如果生成的假设文档与实际知识库内容差异较大，HyDE 反而会降低检索质量。建议先在小范围测试 HyDE 的效果，确认有效后再全量应用。
3. **Step-Back Prompting 配合路由使用效果更好**：不是所有问题都需要 Step-Back。用 LLM 先判断问题的复杂度，只有复杂问题才触发 Step-Back 改写，简单问题直接检索，避免不必要的延迟。
4. **查询改写的 LLM 调用要控制成本**：每次查询改写都会额外消耗一次 LLM 调用。在生产环境中建议使用小模型（如 gpt-4o-mini）做改写，大模型做最终生成，平衡效果和成本。
