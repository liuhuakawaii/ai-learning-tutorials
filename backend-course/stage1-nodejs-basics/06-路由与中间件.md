## 一、路由的概念

### 1.1 什么是路由

**路由（Routing）** 是将 HTTP 请求映射到处理函数的过程。

```
路由的基本概念：

  HTTP 请求                         处理函数
  ┌─────────────────┐             ┌─────────────────┐
  │ GET /api/users   │────────────►│ 获取所有用户      │
  └─────────────────┘             └─────────────────┘

  ┌─────────────────┐             ┌─────────────────┐
  │ POST /api/users  │────────────►│ 创建新用户        │
  └─────────────────┘             └─────────────────┘

  ┌─────────────────┐             ┌─────────────────┐
  │ GET /api/users/1 │────────────►│ 获取用户 1        │
  └─────────────────┘             └─────────────────┘

路由 = HTTP 方法 + URL 路径 → 处理函数
```

### 1.2 路由设计原则

```
好的路由设计：

  ✅ RESTful 风格
    GET    /api/users          获取用户列表
    POST   /api/users          创建用户
    GET    /api/users/:id      获取单个用户
    PUT    /api/users/:id      更新用户
    DELETE /api/users/:id      删除用户

  ✅ 使用名词，不用动词
    /api/users          ✅ 正确
    /api/getUsers       ❌ 错误（不要用动词）
    /api/createUser     ❌ 错误

  ✅ 使用复数形式
    /api/users          ✅ 正确
    /api/user           ❌ 错误（用复数）

  ✅ 层级关系清晰
    /api/users/1/posts       用户 1 的文章
    /api/users/1/posts/5     用户 1 的文章 5
```

## 二、Express Router

### 2.1 为什么需要路由模块化

```
问题：所有路由写在一个文件里

  app.js
  ├── 用户相关路由（200 行）
  ├── 文章相关路由（300 行）
  ├── 评论相关路由（150 行）
  ├── 认证相关路由（100 行）
  └── ...（800+ 行，难以维护）

解决方案：路由模块化

  app.js（20 行）
  └── 挂载路由模块

  routes/
  ├── users.js      （用户路由）
  ├── posts.js      （文章路由）
  ├── comments.js   （评论路由）
  └── auth.js       （认证路由）
```

### 2.2 创建路由模块

```javascript
// routes/users.js
const express = require('express');
const router = express.Router();

// 在 router 上定义路由，就像在 app 上定义一样
router.get('/', (req, res) => {
    res.json({ message: '获取所有用户' });
});

router.get('/:id', (req, res) => {
    res.json({ message: `获取用户 ${req.params.id}` });
});

router.post('/', (req, res) => {
    res.json({ message: '创建用户' });
});

router.put('/:id', (req, res) => {
    res.json({ message: `更新用户 ${req.params.id}` });
});

router.delete('/:id', (req, res) => {
    res.json({ message: `删除用户 ${req.params.id}` });
});

module.exports = router;
```

```javascript
// routes/posts.js
const express = require('express');
const router = express.Router();

router.get('/', (req, res) => {
    res.json({ message: '获取所有文章' });
});

router.get('/:id', (req, res) => {
    res.json({ message: `获取文章 ${req.params.id}` });
});

router.post('/', (req, res) => {
    res.json({ message: '创建文章' });
});

module.exports = router;
```

### 2.3 挂载路由模块

```javascript
// app.js
const express = require('express');
const app = express();

app.use(express.json());

// 挂载路由模块
const usersRouter = require('./routes/users');
const postsRouter = require('./routes/posts');

app.use('/api/users', usersRouter);    // 所有 /api/users/* 请求交给 usersRouter
app.use('/api/posts', postsRouter);    // 所有 /api/posts/* 请求交给 postsRouter

// 首页
app.get('/', (req, res) => {
    res.json({ message: 'API 服务运行中' });
});

app.listen(3000, () => {
    console.log('服务器运行在 http://localhost:3000');
});
```

```
路由映射关系：

  app.use('/api/users', usersRouter)

  GET  /api/users       → usersRouter.get('/')
  GET  /api/users/1     → usersRouter.get('/:id')
  POST /api/users       → usersRouter.post('/')
  PUT  /api/users/1     → usersRouter.put('/:id')

  注意：路由模块中的路径是相对于挂载点的
  router.get('/') 对应 /api/users/
  router.get('/:id') 对应 /api/users/:id
```

```javascript
const userPostsRouter = require('./user-posts');

```

```javascript
// routes/user-posts.js
const express = require('express');
const router = express.Router({ mergeParams: true });
// mergeParams: true 让子路由可以访问父路由的参数

    const { userId, postId } = req.params;
    res.json({ message: `获取用户 ${userId} 的文章 ${postId}` });
});

module.exports = router;
```

```javascript

// GET /api/users/1/posts       → 获取用户 1 的所有文章
// GET /api/users/1/posts/5     → 获取用户 1 的文章 5
```

## 三、路由参数与查询参数

### 3.1 路由参数（Route Parameters）

```javascript
// 路由参数用 : 标记，用于标识资源

// 单个参数
router.get('/:id', (req, res) => {
    const id = req.params.id;
    res.json({ id });
});

// 多个参数
router.get('/:userId/posts/:postId', (req, res) => {
    const { userId, postId } = req.params;
    res.json({ userId, postId });
});

// 可选参数
router.get('/:id?', (req, res) => {
    if (req.params.id) {
        res.json({ id: req.params.id });
    } else {
        res.json({ message: '没有指定 ID' });
    }
});

// 正则约束
router.get('/:id(\\d+)', (req, res) => {
    // 只匹配数字
    res.json({ id: req.params.id });
});
```

### 3.2 查询参数（Query Parameters）

```javascript
// 查询参数用于筛选、排序、分页

// GET /api/users?page=1&limit=10&sort=name&order=asc
router.get('/', (req, res) => {
    const {
        page = 1,
        limit = 10,
        sort = 'id',
        order = 'asc',
        search
    } = req.query;

    // 类型转换（查询参数都是字符串）
    const pageNum = parseInt(page);
    const limitNum = parseInt(limit);

    res.json({
        page: pageNum,
        limit: limitNum,
        sort,
        order,
        search
    });
});
```

### 3.3 两者的区别

```
路由参数 vs 查询参数：

  路由参数：标识资源（哪个资源）
    /api/users/1          → 用户 1
    /api/posts/5/comments → 文章 5 的评论

  查询参数：修饰请求（怎么获取）
    /api/users?page=1&limit=10  → 第 1 页，每页 10 条
    /api/posts?tag=nodejs       → 按标签筛选

  类比：
    路由参数 = 去哪栋楼哪个房间（地址）
    查询参数 = 走前门还是后门、几点去（方式）
```

## 四、中间件深度讲解

### 4.1 中间件的本质

```
中间件本质：一个函数

  (req, res, next) => {
      // 做一些事情
      next();  // 交给下一个中间件
  }

  参数说明：
    req  - 请求对象
    res  - 响应对象
    next - 函数，调用后将控制权交给下一个中间件

  类比：流水线上的工人
    每个工人（中间件）负责一件事：
    工人 A：检查原料质量
    工人 B：加工原料
    工人 C：包装成品
    next() = 把东西传给下一个工人
```

### 4.2 中间件的类型

```
Express 中间件的五种类型：

1. 应用级中间件
   app.use(fn)
   app.use('/path', fn)

2. 路由级中间件
   router.use(fn)

3. 错误处理中间件
   app.use((err, req, res, next) => { ... })

4. 内置中间件
   express.json()
   express.static()
   express.urlencoded()

5. 第三方中间件
   cors、helmet、morgan 等
```

### 4.3 中间件执行流程

```javascript
const express = require('express');
const app = express();

// 中间件 1：请求开始
app.use((req, res, next) => {
    req.startTime = Date.now();
    console.log(`[1] 请求开始: ${req.method} ${req.url}`);
    next();
    // next() 之后的代码在响应发送后执行
    console.log(`[1] 请求结束: ${Date.now() - req.startTime}ms`);
});

// 中间件 2：认证检查
app.use((req, res, next) => {
    console.log('[2] 检查认证...');
    const token = req.headers.authorization;

    if (!token && req.url.startsWith('/api/protected')) {
        return res.status(401).json({ error: '未授权' });
        // 注意：这里没有调用 next()，请求到此终止
    }

    next();
});

// 中间件 3：解析 JSON
app.use(express.json());

// 路由处理
app.get('/api/protected/data', (req, res) => {
    console.log('[3] 处理请求');
    res.json({ data: '机密数据' });
});

// 执行流程（未认证请求）：
// [1] 请求开始: GET /api/protected/data
// [2] 检查认证...
// [1] 请求结束: 2ms

// 执行流程（已认证请求）：
// [1] 请求开始: GET /api/protected/data
// [2] 检查认证...
// [3] 处理请求
// [1] 请求结束: 1ms
```

### 4.4 next() 的作用

```javascript
// ========== 情况一：调用 next() ==========
app.use((req, res, next) => {
    console.log('中间件 1');
    next();  // 继续执行下一个中间件
});

// ========== 情况二：不调用 next() ==========
app.use((req, res, next) => {
    console.log('中间件 1');
    res.json({ message: '请求在此结束' });
    // 没有调用 next()，请求到此终止
});

// ========== 情况三：调用 next(err) ==========
app.use((req, res, next) => {
    try {
        // 某些操作
    } catch (err) {
        next(err);  // 将错误传递给错误处理中间件
    }
});

// ========== 情况四：next('route') ==========
app.get('/api/users/:id', (req, res, next) => {
    if (req.params.id === '0') {
        next('route');  // 跳过当前路由的剩余处理函数
    } else {
        res.json({ id: req.params.id });
    }
});
```

## 五、内置中间件

### 5.1 express.json()

```javascript
// 解析 Content-Type: application/json 的请求体
app.use(express.json());

// 选项
app.use(express.json({
    limit: '10mb',           // 限制请求体大小

    type: 'application/json' // 自定义 Content-Type

// 使用
app.post('/api/data', (req, res) => {
    console.log(req.body);  // 解析后的 JSON 对象
    res.json({ received: req.body });
});
```

### 5.2 express.urlencoded()

```javascript
// 解析 Content-Type: application/x-www-form-urlencoded 的请求体
// （HTML 表单默认的编码方式）
app.use(express.urlencoded({ extended: true }));

// extended: true 使用 qs 库解析（支持嵌套对象）
// extended: false 使用 querystring 库解析（不支持嵌套）
```

### 5.3 express.static()

```javascript
// 提供静态文件服务
app.use(express.static('public'));

// 访问 http://localhost:3000/index.html
// 实际读取 public/index.html

// 带路径前缀
app.use('/static', express.static('public'));
// 访问 http://localhost:3000/static/style.css
// 实际读取 public/style.css

// 多个静态目录
app.use(express.static('public'));
app.use(express.static('uploads'));

// 使用绝对路径（推荐）
const path = require('path');
app.use(express.static(path.join(__dirname, 'public')));
```

## 六、自定义中间件

### 6.1 日志中间件

```javascript
// middleware/logger.js

/**
 * 请求日志中间件
 */
function logger(req, res, next) => {
    const start = Date.now();
    const timestamp = new Date().toISOString();

    // 响应结束时记录日志
    res.on('finish', () => {
        const duration = Date.now() - start;
        const log = {
            timestamp,
            method: req.method,
            url: req.originalUrl,
            status: res.statusCode,
            duration: `${duration}ms`,
            ip: req.ip,
            userAgent: req.get('User-Agent')
        };

        if (res.statusCode >= 400) {
            console.error('[ERROR]', JSON.stringify(log));
        } else {
            console.log('[INFO]', JSON.stringify(log));
        }
    });

    next();
}

module.exports = logger;
```

```javascript
// app.js
const logger = require('./middleware/logger');
app.use(logger);
```

### 6.2 认证中间件

```javascript
// middleware/auth.js

/**
 * 认证中间件
 */
function authenticate(req, res, next) {
    const authHeader = req.headers.authorization;

    if (!authHeader) {
        return res.status(401).json({
            error: '未提供认证令牌'
        });
    }

    const token = authHeader.replace('Bearer ', '');

    // 简单验证（实际项目中使用 JWT）
    if (token === 'valid-token') {
        req.user = { id: 1, name: '张三' };
        next();
    } else {
        res.status(401).json({
            error: '无效的认证令牌'
        });
    }
}

/**
 * 角色授权中间件
 */
function authorize(...roles) {
    return (req, res, next) => {
        if (!req.user) {
            return res.status(401).json({ error: '未认证' });
        }

        if (!roles.includes(req.user.role)) {
            return res.status(403).json({ error: '权限不足' });
        }

        next();
    };
}

module.exports = { authenticate, authorize };
```

```javascript
// 使用
const { authenticate, authorize } = require('./middleware/auth');

// 需要认证的路由
app.get('/api/profile', authenticate, (req, res) => {
    res.json({ user: req.user });
});

// 需要特定角色的路由
app.delete('/api/users/:id',
    authenticate,
    authorize('admin'),
    (req, res) => {
        res.json({ message: '用户已删除' });
    }
);
```

### 6.3 请求计时中间件

```javascript
// middleware/timer.js

/**
 * 请求计时中间件
 */
function timer(req, res, next) {
    req.startTime = Date.now();

    // 在 res 上添加方法
    res.getDuration = () => {
        return Date.now() - req.startTime;
    };

    next();
}

module.exports = timer;
```

### 6.4 验证中间件

```javascript
// middleware/validate.js

/**
 * 创建验证中间件
 * @param {Function} validateFn 验证函数
 */
function validate(validateFn) {
    return (req, res, next) => {
        const errors = validateFn(req.body);

        if (errors.length > 0) {
            return res.status(400).json({
                error: '验证失败',
                details: errors
            });
        }

        next();
    };
}

// 使用示例
const validateUser = validate((body) => {
    const errors = [];

    if (!body.name || body.name.trim() === '') {
        errors.push('姓名为必填项');
    }

    if (!body.email || !body.email.includes('@')) {
        errors.push('请提供有效的邮箱');
    }

    if (body.age && (body.age < 0 || body.age > 150)) {
        errors.push('年龄必须在 0-150 之间');
    }

    return errors;
});

// 在路由中使用
router.post('/', validateUser, (req, res) => {
    // 验证通过，处理请求
    res.json({ user: req.body });
});
```

## 七、中间件执行顺序

### 7.1 顺序很重要

```javascript
const express = require('express');
const app = express();

// ========== 正确的顺序 ==========

// 1. 首先：日志
app.use(logger);

// 2. 其次：CORS
app.use(cors);

// 3. 然后：解析请求体
app.use(express.json());

// 4. 然后：路由
app.use('/api/users', usersRouter);

// 5. 最后：错误处理
app.use(errorHandler);

// ========== 错误的顺序 ==========

// ❌ 错误：路由在 JSON 解析之前
app.use('/api/users', usersRouter);
app.use(express.json());
// 结果：req.body 是 undefined

// ❌ 错误：错误处理在路由之前
app.use(errorHandler);
app.use('/api/users', usersRouter);
// 结果：错误处理中间件永远不会被触发
```

### 7.2 常见的中间件顺序

```javascript
const express = require('express');
const app = express();

// 推荐的中间件顺序：

// 1. 请求日志
app.use(logger);

// 2. CORS
app.use(cors());

// 3. 安全相关
app.use(helmet());

// 4. 请求体解析
app.use(express.json());
app.use(express.urlencoded({ extended: true }));

// 5. Cookie 解析
app.use(cookieParser());

// 6. 会话管理
app.use(session({ ... }));

// 7. 认证
app.use(authenticate);

// 8. 静态文件
app.use(express.static('public'));

// 9. 路由
app.use('/api/users', usersRouter);
app.use('/api/posts', postsRouter);

// 10. 404 处理
app.use((req, res) => {
    res.status(404).json({ error: 'Not Found' });
});

// 11. 错误处理（必须放最后）
app.use(errorHandler);
```

## 八、错误处理中间件

### 8.1 错误处理中间件的特殊性

```javascript
// 错误处理中间件有 4 个参数
// Express 通过参数数量来区分普通中间件和错误处理中间件

// 普通中间件（3 个参数）
app.use((req, res, next) => {
    next();
});

// 错误处理中间件（4 个参数）
app.use((err, req, res, next) => {
    // err 是错误对象
    console.error(err);
    res.status(500).json({ error: '服务器错误' });
});
```

### 8.2 触发错误处理

```javascript
// 方式一：在中间件中调用 next(err)
app.use((req, res, next) => {
    try {
        // 某些操作
    } catch (err) {
        next(err);  // 传递给错误处理中间件
    }
});

// 方式二：在异步路由中抛出错误
app.get('/api/data', async (req, res, next) => {
    try {
        const data = await fetchData();
        res.json(data);
    } catch (err) {
        next(err);
    }
});

// 方式三：直接调用 next(new Error())
app.get('/api/data', (req, res, next) => {
    const data = null;
    if (!data) {
        return next(new Error('数据不存在'));
    }
    res.json(data);
});
```

### 8.3 完整的错误处理

```javascript
// middleware/errorHandler.js

/**
 * 404 错误处理
 */
function notFound(req, res, next) {
    const error = new Error(`路由不存在: ${req.method} ${req.url}`);
    error.status = 404;
    next(error);
}

/**
 * 全局错误处理
 */
function errorHandler(err, req, res, next) {
    const status = err.status || 500;
    const message = err.message || '服务器内部错误';

    // 记录错误
    console.error(`[ERROR] ${status} - ${message}`);
    console.error(err.stack);

    // 开发环境返回详细错误
    const response = {
        error: {
            message,
            status
        }
    };

    if (process.env.NODE_ENV === 'development') {
        response.error.stack = err.stack;
    }

    res.status(status).json(response);
}

module.exports = { notFound, errorHandler };
```

```javascript
// app.js
const { notFound, errorHandler } = require('./middleware/errorHandler');

// 路由
app.use('/api/users', usersRouter);
app.use('/api/posts', postsRouter);

// 404 处理（放在所有路由之后）
app.use(notFound);

// 错误处理（放在最后）
app.use(errorHandler);
```

## 九、实战：路由模块化

### 9.1 项目结构

```
blog-api/
├── src/
│   ├── index.js              ← 入口文件
│   ├── routes/
```

```javascript
// src/middleware/logger.js
function logger(req, res, next) {
    const start = Date.now();
    res.on('finish', () => {
        const duration = Date.now() - start;
        console.log(`${req.method} ${req.originalUrl} ${res.statusCode} ${duration}ms`);
    });
    next();
}

module.exports = logger;
```

```javascript
// src/middleware/errorHandler.js
function notFound(req, res, next) {
    const error = new Error(`路由不存在: ${req.method} ${req.url}`);
    error.status = 404;
    next(error);
}

function errorHandler(err, req, res, next) {
    const status = err.status || 500;
    res.status(status).json({
        error: {
            message: err.message,
            status
        }
    });
}

module.exports = { notFound, errorHandler };
```

```javascript
const express = require('express');
const router = express.Router();
const store = require('../data/store');

// 获取文章列表
router.get('/', (req, res) => {
    const { page = 1, limit = 10, tag, authorId } = req.query;
    let posts = [...store.posts];

    if (tag) {
        posts = posts.filter(p => p.tags.includes(tag));
    }
    if (authorId) {
        posts = posts.filter(p => p.authorId === parseInt(authorId));
    }

    const start = (parseInt(page) - 1) * parseInt(limit);
    const paginated = posts.slice(start, start + parseInt(limit));

    res.json({ data: paginated, total: posts.length });
});

// 获取单篇文章
router.get('/:id', (req, res) => {
    const post = store.posts.find(p => p.id === parseInt(req.params.id));
    if (!post) {
        return res.status(404).json({ error: '文章不存在' });
    }

    // 获取作者信息
    const author = store.users.find(u => u.id === post.authorId);
    const comments = store.comments.filter(c => c.postId === post.id);

    res.json({
        data: {
            ...post,
            author: author ? { id: author.id, name: author.name } : null,
            comments
        }
    });
});

// 创建文章
router.post('/', (req, res) => {
    const { title, content, authorId, tags = [] } = req.body;

    if (!title || !content || !authorId) {
        return res.status(400).json({ error: '标题、内容和作者为必填项' });
    }

    const newPost = {
        id: store.nextId.posts++,
        title,
        content,
        authorId: parseInt(authorId),
        tags,
        createdAt: new Date().toISOString()
    };

    store.posts.push(newPost);
    res.status(201).json({ data: newPost });
});
```

## 十一、小结

```
本课核心知识点：

✅ 路由 = HTTP 方法 + URL 路径 → 处由函数
✅ Express Router 实现路由模块化
✅ 路由参数（:id）标识资源，查询参数（?page=1）修饰请求
✅ 中间件本质是 (req, res, next) => {} 函数
✅ next() 传递控制权，next(err) 传递错误
✅ 内置中间件：express.json()、express.static()
✅ 错误处理中间件有 4 个参数：(err, req, res, next)
✅ 中间件的执行顺序很重要

关键记忆点：
  - 用 Router 拆分路由，保持代码组织清晰
  - 中间件按注册顺序执行
  - 错误处理中间件放在所有路由之后
  - 永远不要信任客户端输入

下一课预告：
  我们将学习 RESTful API 设计规范，设计博客平台的完整 API。
```

> **给前端开发者的话：** 中间件的概念你在前端也接触过——Redux 的 middleware、Axios 的 interceptor、Express 的中间件，它们的本质都是一样的：在请求/响应的处理链中插入自定义逻辑。理解了这个模式，你在前端和后端都能游刃有余。
