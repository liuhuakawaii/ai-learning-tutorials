## 场景引入

你的团队正在构建一个商品图片分析系统，需要同时完成图片分类、文字提取和商品描述生成。测试时发现：GPT-4o 的 OCR 能力很强但偶尔会"编造"图片中不存在的文字，Claude Vision 的推理能力出色但不支持图片生成，Gemini 声称支持视频但中文场景下表现一般。面对 GPT-4o、Claude、Gemini、Qwen-VL 四个模型，你该如何为每个子任务选择最合适的模型？选错了模型，轻则效果差、成本高，重则整个产品功能无法实现。

## 一、什么是多模态

```
模态（Modality）= 信息的类型

  文本模态：文字、代码、表格
  视觉模态：图片、视频、图表
  音频模态：语音、音乐、环境声
  文档模态：PDF、Word、扫描件

  单模态模型：只能处理一种类型
  多模态模型：能处理多种类型

  ┌─────────────────────────────────────────────────────────┐
  │                    多模态能力图谱                         │
  │                                                         │
  │  文本 ◄──────────────────────────────────────► 图片     │
  │    │          多模态大模型                    │         │
  │    │         ┌────────────┐                   │         │
  │    │         │  GPT-4o    │                   │         │
  │    │         │  Claude    │                   │         │

  │    │         │  Qwen-VL   │                   │         │
  │    │         └────────────┘                   │         │
  │    │                                          │         │

  │                                                         │

```

## 二、主流多模态模型详解

### 2.1 GPT-4o（OpenAI）

```
GPT-4o 能力矩阵：

  ┌──────────────┬────────┬──────────────────────────────────┐
  │  模态        │ 支持   │ 具体能力                          │
  ├──────────────┼────────┼──────────────────────────────────┤
  │  文本输入     │ ✓      │ 自然语言、代码、表格              │
  │  文本输出     │ ✓      │ 自然语言、代码、JSON              │
  │  图片输入     │ ✓      │ 图片理解、OCR、图表分析           │
  │  图片生成     │ ✓      │ DALL-E 3 集成                    │
  │  音频输入     │ ✓      │ Whisper 语音识别                  │
  │  音频输出     │ ✓      │ TTS 语音合成                     │
  │  视频输入     │ ✗      │ 不直接支持（需抽帧为图片）         │
  │  文件输入     │ ✓      │ PDF、Word 等文档解析              │
  └──────────────┴────────┴──────────────────────────────────┘

  特点：
  - 能力最全面，文本/图片/音频全覆盖
  - 响应速度快（o 版本优化了延迟）
  - 生态最成熟，文档和社区支持最好
  - 价格中等

  局限：
  - 视频不直接支持
  - 图片理解有时会"编造"细节
  - 中文能力不如专门的中文模型
```

## 五、成本估算

```
多模态 API 的成本构成：

  文本：按 token 计费（与普通 LLM 相同）
  图片：按图片尺寸和分辨率计费
  音频：按音频时长计费
  视频：按视频时长计费（Gemini）

  ┌──────────────────────────────────────────────────────────┐
  │  GPT-4o 价格参考（2024 年）                               │
  ├──────────────────────────────────────────────────────────┤
  │  文本输入：$2.50 / 1M tokens                              │
  │  文本输出：$10.00 / 1M tokens                             │
  │  图片输入：$3.825 / 1M tokens（约 $0.005 / 张低分辨率）   │
  │  音频输入：$0.06 / 分钟                                   │
  │  音频输出：$0.24 / 分钟                                   │
  └──────────────────────────────────────────────────────────┘

  成本优化建议：
  1. 图片先压缩再传（降低分辨率可大幅降低成本）
  2. 音频先裁剪静音段再传
  3. 简单任务用小模型（GPT-4o-mini 比 GPT-4o 便宜 10 倍）
  4. 缓存重复请求的结果
```

## 常见误区

```
误区 1：多模态模型能"看懂"所有图片
  事实：模型对图片的理解有局限，特别是细节、文字、数字
  建议：关键信息用 OCR 提取，不要完全依赖模型的"视觉"

误区 2：所有多模态模型都一样
  事实：不同模型在不同任务上差异很大
  建议：用你的真实数据做对比测试

误区 3：多模态 API 很便宜
  事实：图片和音频的 token 消耗远高于文本
  建议：做好成本预算，使用缓存和压缩

误区 4：多模态 = 万能
  事实：每个模型都有能力边界
  建议：了解模型的局限，设计合理的 fallback 策略
```

## 工程建议

1. **用真实数据做选型测试**：不要只看官方 benchmark，用你自己的业务数据（真实商品图、合同扫描件、中文语音）跑对比测试，不同模型在不同数据分布上表现差异很大。
2. **按子任务选模型，不要全局绑定**：图片分类用便宜的小模型，复杂推理用强模型，OCR 用专门优化的方案，混合搭配才能兼顾效果和成本。
3. **设计 fallback 策略**：主模型不可用或返回低置信度结果时，自动降级到备选模型，避免单点故障。
4. **从第一天就做成本监控**：多模态 API 的 token 消耗远高于纯文本，上线前必须估算月度成本并设置预算告警。

## 参考答案

### 练习一：对比题

**思路**：用同一张包含文字和图表的图片分别调用 GPT-4o 和 Claude，对比两者在文字识别准确度、图表趋势描述、细节捕捉方面的差异。

**答案**：
```python
import base64
from openai import OpenAI
import anthropic

openai_client = OpenAI()
claude_client = anthropic.Anthropic()


def analyze_with_gpt4o(image_path: str, question: str) -> str:
    """用 GPT-4o 分析图片"""
    with open(image_path, "rb") as f:
        image_base64 = base64.b64encode(f.read()).decode()
    
    response = openai_client.chat.completions.create(
        model="gpt-4o",
        messages=[{
            "role": "user",
            "content": [
                {"type": "text", "text": question},
                {"type": "image_url", "image_url": {"url": f"data:image/png;base64,{image_base64}"}}
            ]
        }]
    )
    return response.choices[0].message.content


def analyze_with_claude(image_path: str, question: str) -> str:
    """用 Claude 分析图片"""
    with open(image_path, "rb") as f:
        image_base64 = base64.b64encode(f.read()).decode()
    
    response = claude_client.messages.create(
        model="claude-sonnet-4-20250514",
        max_tokens=1024,
        messages=[{
            "role": "user",
            "content": [
                {"type": "image", "source": {"type": "base64", "media_type": "image/png", "data": image_base64}},
                {"type": "text", "text": question}
            ]
        }]
    )
    return response.content[0].text


def compare_vision_models(image_path: str):
    """对比 GPT-4o 和 Claude 的图片分析能力"""
    
    questions = [
        "请提取这张图片中的所有文字，保持原始格式",
        "请分析图片中的图表，描述趋势和关键数据点",
        "请详细描述这张图片的所有视觉元素"
    ]
    
    for q in questions:
        print(f"\n{'='*60}")
        print(f"问题: {q}\n")
        
        gpt4o_result = analyze_with_gpt4o(image_path, q)
        print(f"【GPT-4o】\n{gpt4o_result}\n")
        
        claude_result = analyze_with_claude(image_path, q)
        print(f"【Claude】\n{claude_result}\n")


if __name__ == "__main__":
    compare_vision_models("test_chart_with_text.png")
```

**要点**：
- 对比时必须用完全相同的图片和问题，控制变量
- GPT-4o 的 OCR 能力通常更强，但可能"编造"图片中不存在的文字
- Claude 的推理能力更出色，对复杂图表的趋势分析更准确
- 常见错误：用不同分辨率的图片测试两个模型，导致对比不公平

### 练习二：选型题

**思路**：根据三个子任务的模态需求、数据敏感度和性能要求，分别选择最合适的模型。

**答案**：
```
选型分析：

(a) 商品图片分析
   需求：图片分类、品牌识别、商品描述生成
   模态：图片输入 → 文本输出
   推荐：GPT-4o
   理由：
   - OCR 能力强，能准确识别品牌名和型号文字
   - 响应速度快（o 版本优化了延迟），适合用户实时交互
   - 支持 JSON 结构化输出，便于后续系统集成
   - 生态成熟，文档和社区支持好

(b) 用户语音输入
   需求：语音转文字、意图理解
   模态：音频输入 → 文本输出
   推荐：GPT-4o（Whisper 集成）
   理由：
   - 原生集成 Whisper 语音识别，无需额外服务
   - 中文语音识别准确率高
   - 一个 API 完成"语音→文字→理解"全链路
   备选：Gemini（如果需要更低成本）

(c) 合同 PDF 解析
   需求：文字提取、表格识别、关键信息结构化
   模态：文档输入 → 结构化文本输出
   推荐：Claude 3.5 Sonnet
   理由：
   - 200K 上下文窗口，能处理长合同
   - 推理能力强，能理解合同条款间的逻辑关系
   - 安全性高，适合处理敏感法律文档
   - 支持文件直接上传（PDF 解析）

综合方案：
   - 图片分析 → GPT-4o
   - 语音输入 → GPT-4o
   - 合同解析 → Claude
   - 非核心/降级场景 → Qwen-VL（低成本备选）
```

**要点**：
- 不要试图用一个模型解决所有问题，按子任务选型才能兼顾效果和成本
- 数据敏感度是关键约束：合同等敏感文档用 Claude（安全性最高），商品图片用 GPT-4o（性价比好）
- 要设计 fallback 策略：主模型不可用时自动降级到备选模型
- 常见错误：只看 benchmark 分数选型，忽略实际业务场景的特殊需求（如中文能力、长文本支持）

### 练习三：API 题

**思路**：使用 GPT-4o 的 Vision API，通过精心设计的 prompt 提取照片中的文字信息。

**答案**：
```python
import base64
import json
from openai import OpenAI

client = OpenAI()


def extract_text_from_photo(image_path: str) -> dict:
    """从照片中提取所有文字信息"""
    
    # 读取图片并编码为 base64
    with open(image_path, "rb") as f:
        image_base64 = base64.b64encode(f.read()).decode()
    
    # 根据图片类型选择合适的 prompt
    prompt = """请仔细识别并提取这张照片中的所有文字信息，包括：
1. 主要文字内容（标题、正文、标签等）
2. 辅助文字（水印、时间戳、Logo 文字等）
3. 背景中隐约可见的文字

请以 JSON 格式输出，结构如下：
{
  "main_text": ["主要文字1", "主要文字2"],
  "auxiliary_text": ["辅助文字1"],
  "background_text": ["背景文字1"],
  "text_layout": "描述文字在图片中的位置分布"
}

要求：
- 逐字准确提取，不要推测或补充
- 无法确认的文字用 [?] 标记
- 保持原始语言，不要翻译"""
    
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{
            "role": "user",
            "content": [
                {"type": "text", "text": prompt},
                {
                    "type": "image_url",
                    "image_url": {
                        "url": f"data:image/jpeg;base64,{image_base64}",
                        "detail": "high"  # 使用高分辨率以提高 OCR 准确率
                    }
                }
            ]
        }],
        response_format={"type": "json_object"}
    )
    
    result = json.loads(response.choices[0].message.content)
    
    # 输出结果
    print("=== 文字提取结果 ===\n")
    print(f"主要文字:")
    for text in result.get("main_text", []):
        print(f"  • {text}")
    print(f"\n辅助文字:")
    for text in result.get("auxiliary_text", []):
        print(f"  • {text}")
    print(f"\n文字布局: {result.get('text_layout', '未知')}")
    
    return result


if __name__ == "__main__":
    result = extract_text_from_photo("my_photo.jpg")
    
    # 保存结果
    with open("ocr_result.json", "w", encoding="utf-8") as f:
        json.dump(result, f, ensure_ascii=False, indent=2)
```

**要点**：
- 使用 `"detail": "high"` 可以提高 OCR 准确率，但 token 消耗会增加
- prompt 要明确要求"逐字准确提取，不要推测"，减少模型编造内容
- 使用 `response_format={"type": "json_object"}` 强制结构化输出
- 常见错误：不指定 detail 参数，默认使用低分辨率，导致小字无法识别
