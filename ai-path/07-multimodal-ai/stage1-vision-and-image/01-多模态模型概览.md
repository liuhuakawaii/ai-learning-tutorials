# 第 1 课：多模态模型概览——同一张图，四个模型看到的东西不一样

> **前置知识**：会调 LLM API（01-ai-app 课程水平）
> **本课目标**：建立"不同多模态模型有不同能力边界"的判断力，能为具体子任务选模型

## 从一个 bug 说起

你让 GPT-4o 看一张商品图，问"这件衣服的面料成分标签上写了什么"。它回复了"95% 棉，5% 氨纶"——但你放大图片一看，标签上的字根本看不清。GPT-4o 编了一个看起来合理的答案。

同样的图丢给 Claude，它说"标签模糊无法识别"。更诚实，但也没帮你解决问题。丢给 Gemini，它能识别标签但把品牌名拼错了。

这不是哪个模型"更好"的问题。它们的能力边界不同，擅长的事不同，犯的错也不同。选型不能靠感觉，得靠实验。

## 主流多模态模型，各自能干什么

把四种模态（文本、图片、音频、文档）丢给四个模型，结果差异很大：

```
能力            GPT-4o      Claude       Gemini       Qwen-VL
─────────────────────────────────────────────────────────────
图片理解         强          很强         好           好
OCR 文字提取     很强        好           好           好
图片生成         ✓(DALL-E)   ✗            ✓(Imagen)    ✗
音频处理         ✓(Whisper)  ✗            ✓            ✗
视频理解         ✗           ✗            ✓(原生)      △
文档解析         好          很强(200K)   好           好
中文能力         好          好           一般         很强
推理深度         很强        最强         好           一般
API 价格         中          高           低           低
```

几个关键差异值得注意：

- **Claude 不支持图片生成和音频**，但在复杂图表推理和长文档理解上经常是最准的
- **Gemini 是唯一原生支持视频理解的模型**，但中文场景表现不稳定
- **GPT-4o 的 OCR 能力很强但会"编造"**，遇到模糊文字它倾向于猜一个合理答案而不是说看不清
- **Qwen-VL 中文最好且开源可部署**，但英文和推理能力有差距

## 实验：同一张图，四个模型看到了什么

与其看表格，不如自己跑一遍。找一张包含文字、图表、商品的复杂图片，分别丢给四个模型，问同一个问题。

```python
import base64
from openai import OpenAI
import anthropic


def load_image_base64(image_path: str) -> str:
    with open(image_path, "rb") as f:
        return base64.b64encode(f.read()).decode()


def test_gpt4o(image_path: str, question: str) -> str:
    client = OpenAI()
    b64 = load_image_base64(image_path)
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{
            "role": "user",
            "content": [
                {"type": "text", "text": question},
                {"type": "image_url", "image_url": {"url": f"data:image/jpeg;base64,{b64}"}}
            ]
        }]
    )
    return response.choices[0].message.content


def test_claude(image_path: str, question: str) -> str:
    client = anthropic.Anthropic()
    b64 = load_image_base64(image_path)
    response = client.messages.create(
        model="claude-sonnet-4-20250514",
        max_tokens=1024,
        messages=[{
            "role": "user",
            "content": [
                {"type": "image", "source": {"type": "base64", "media_type": "image/jpeg", "data": b64}},
                {"type": "text", "text": question}
            ]
        }]
    )
    return response.content[0].text


def compare_models(image_path: str):
    questions = [
        "这张图片里有哪些文字？请逐字提取",
        "图片中有什么物体？描述它们的空间关系",
        "如果这张图是一个商品，它的卖点是什么",
    ]
    for q in questions:
        print(f"\n{'='*50}\n问题: {q}\n")
        print(f"【GPT-4o】\n{test_gpt4o(image_path, q)}\n")
        print(f"【Claude】\n{test_claude(image_path, q)}")


if __name__ == "__main__":
    compare_models("test_image.jpg")
```

跑完之后你会直观感受到：GPT-4o 倾向于给出丰富但可能包含编造细节的回答，Claude 更保守但更准确。这不是谁好谁差——如果你做商品信息提取，编造细节是灾难；如果你做图片创意描述，丰富反而有价值。

## 选型不是选一个模型，是选一个组合

真实项目里很少只用一个模型。更常见的做法是按子任务拆分：

```
商品分析系统：
  图片分类 → GPT-4o-mini（便宜、够用）
  文字提取 → GPT-4o（OCR 最准）
  营销文案 → Claude（推理深、文风可控）
  批量降级 → Qwen-VL（便宜、中文好）
```

选型决策的关键维度：

1. **你要处理什么模态**：需要音频？只有 Gemini 和 GPT-4o 支持。需要视频？只有 Gemini
2. **准确度要求多高**：合同解析不能有编造，用 Claude；商品描述可以有创意，用 GPT-4o
3. **成本预算多少**：GPT-4o 约 $2.5/1M 输入 token，Claude 更贵，Qwen-VL 开源免费
4. **数据能不能出公司**：敏感数据只能本地部署，Qwen-VL 是唯一开源选项

## API 调用：图片输入的基本模式

GPT-4o 和 Claude 的图片输入格式不同，但结构类似——都是在 messages 里嵌入图片：

```python
# GPT-4o：支持 URL 和 base64 两种方式
# URL 方式（图片必须公网可访问）
messages = [{
    "role": "user",
    "content": [
        {"type": "text", "text": "描述这张图"},
        {"type": "image_url", "image_url": {"url": "https://example.com/photo.jpg"}}
    ]
}]

# base64 方式（本地图片）
messages = [{
    "role": "user",
    "content": [
        {"type": "text", "text": "描述这张图"},
        {"type": "image_url", "image_url": {"url": f"data:image/jpeg;base64,{b64_string}"}}
    ]
}]

# Claude：只支持 base64，格式略有不同
messages = [{
    "role": "user",
    "content": [
        {"type": "image", "source": {"type": "base64", "media_type": "image/jpeg", "data": b64_string}},
        {"type": "text", "text": "描述这张图"}
    ]
}]
```

多图对比也很简单——在 content 数组里放多张图片就行。GPT-4o 单次最多传 20 张图，Claude 最多 20 张。

## 成本：图片比文本贵得多

一张 1024x1024 的图片，GPT-4o 按低分辨率算约 $0.005，高分辨率约 $0.02。如果你每天处理 1 万张图，光图片 token 就要 $50-200/天。

几个省钱的手段：
- 图片先压缩再传，低分辨率对大多数分类任务够用
- 简单任务用 GPT-4o-mini，比 GPT-4o 便宜 10 倍
- 缓存重复图片的分析结果
- 先用小模型做初筛，只把难的图送给大模型

## 本课小结

- 四个主流多模态模型各有能力边界，没有"最好的"，只有"最适合的"
- 选型按子任务拆：模态需求 → 准确度要求 → 成本约束 → 数据隐私
- OCR 场景 GPT-4o 最强但会编造，推理场景 Claude 最准，中文场景 Qwen-VL 最好
- 图片 API 比文本贵 10-100 倍，必须做成本控制

## 参考答案

### 练习一

跑完之后你会发现一个规律：GPT-4o 在 OCR 场景输出更多文字，但其中可能混入图片中不存在的内容；Claude 更保守，看不清就说看不清。这在信息提取场景是关键差异——你宁可少提取也不能提取错误信息。

### 练习二

```python
import base64
from openai import OpenAI


def compare_two_images(before_path: str, after_path: str) -> str:
    client = OpenAI()

    def load_b64(path):
        with open(path, "rb") as f:
            return base64.b64encode(f.read()).decode()

    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{
            "role": "user",
            "content": [
                {"type": "text", "text": "对比这两张图片，列出所有可见的差异。用 JSON 格式输出，每个差异包含 category（类别）、before（之前描述）、after（之后描述）"},
                {"type": "image_url", "image_url": {"url": f"data:image/jpeg;base64,{load_b64(before_path)}"}},
                {"type": "image_url", "image_url": {"url": f"data:image/jpeg;base64,{load_b64(after_path)}"}}
            ]
        }],
        response_format={"type": "json_object"}
    )
    return response.choices[0].message.content
```

### 练习三

```
商品图片分类 → GPT-4o-mini（便宜，分类任务不需要最强模型）
  降级：Qwen-VL（更便宜，中文分类够用）

用户语音搜索 → GPT-4o（集成 Whisper，一个 API 搞定语音转文字+理解）
```
