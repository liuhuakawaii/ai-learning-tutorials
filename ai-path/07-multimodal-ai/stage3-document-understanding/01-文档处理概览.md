## 从一份合同说起

你拿到一份 20 页的合同 PDF。看起来很简单——提取文字、解析表格、识别签章位置。

用 Python 的 PyPDF2 直接提取，发现：文字倒是提出来了，但表格变成了乱序的文字流，两列内容混在一起；页眉页脚的文字和正文混在一起；第 3 页是一张扫描件，提取出来是空的。

换 Unstructured 试一下，表格能识别了，但多列布局的文本顺序还是有问题。换 Docling，表格质量好了很多，但安装依赖花了半小时。

文档处理的核心困难不是"提取文字"——是怎么处理各种意外情况。

## 文档处理为什么难

```
文档处理的四个核心挑战：

1. 格式不统一
   原生 PDF（文字可选中） ← → 扫描件 PDF（本质是图片）
   Word / Excel / PPT       ← → 手机拍的照片
   每种格式需要完全不同的处理方式

2. 结构复杂
   多列布局、页眉页脚、脚注
   表格嵌套、合并单元格
   图文混排、公式、图表

3. 质量参差
   扫描件模糊、倾斜、有阴影
   手写字迹潦草
   低分辨率图片

4. 语言混杂
   中英混合、繁简混合
   专业术语、行业缩写
```

最常见的坑：**原生 PDF 和扫描件 PDF 的处理方式完全不同**。原生 PDF 可以直接提取文字（PyPDF2 就行），扫描件 PDF 本质是一张图片，必须用 OCR。如果你不分青红皂白直接提取，扫描件页面会返回空。

## 主流工具对比

```
工具                    开源   擅长什么               不擅长什么
────────────────────────────────────────────────────────────────
Unstructured            ✓      格式支持最全            表格质量一般
Docling (IBM)           ✓      表格和结构识别最好       安装依赖重
Marker                  ✓      PDF 专精，公式支持好     只支持 PDF
PyPDF2 / pdfplumber     ✓      轻量、快速              不支持 OCR
Azure Doc Intelligence  ✗      表格识别准确率最高       贵，数据出公司
```

选型逻辑：

- 文档类型多样（PDF + Word + 图片）→ Unstructured
- 主要是 PDF 且表格多 → Docling
- 只需要快速提取原生 PDF 文字 → pdfplumber
- 扫描件为主且要求高准确率 → Azure Document Intelligence
- 学术论文、含公式 → Marker

## 实验：同一份 PDF，不同工具的效果

```python
from unstructured.partition.pdf import partition_pdf


def analyze_pdf_with_unstructured(pdf_path: str) -> dict:
    """用 Unstructured 解析 PDF，查看它识别出了什么"""
    elements = partition_pdf(pdf_path, strategy="hi_res")

    type_counts = {}
    for el in elements:
        type_counts[el.category] = type_counts.get(el.category, 0) + 1

    print(f"共识别 {len(elements)} 个元素")
    print(f"类型分布: {type_counts}\n")

    # 打印前 10 个元素
    for i, el in enumerate(elements[:10]):
        text_preview = el.text[:80].replace("\n", " ") if el.text else "(空)"
        print(f"  [{el.category}] {text_preview}")

    return {"total": len(elements), "types": type_counts, "elements": elements}


if __name__ == "__main__":
    result = analyze_pdf_with_unstructured("sample.pdf")
```

跑完你会看到 Unstructured 把文档拆成了 Title、NarrativeText、Table、ListItem 等类型。但仔细检查会发现：
- 多列布局的文本可能顺序错乱
- 表格被识别为 Table 类型，但内容可能是纯文本而不是结构化的行列
- 页眉页脚可能混入正文

再用 pdfplumber 试同一份原生 PDF：

```python
import pdfplumber


def extract_with_pdfplumber(pdf_path: str):
    """用 pdfplumber 提取 PDF（只支持原生 PDF）"""
    with pdfplumber.open(pdf_path) as pdf:
        for i, page in enumerate(pdf.pages[:5]):
            text = page.extract_text()
            tables = page.extract_tables()

            print(f"\n--- 第 {i+1} 页 ---")
            if text:
                print(f"文字: {text[:200]}...")
            if tables:
                print(f"表格: {len(tables)} 个")
                for table in tables[:1]:
                    for row in table[:3]:
                        print(f"  {row}")
```

pdfplumber 对原生 PDF 的表格提取质量通常比 Unstructured 好，但它完全不支持 OCR——扫描件页面直接返回空。

## 处理流程：先判断再处理

不要上来就调工具。先判断文档类型，再选方案：

```python
def detect_pdf_type(pdf_path: str) -> str:
    """判断 PDF 是原生的还是扫描件"""
    import pdfplumber

    with pdfplumber.open(pdf_path) as pdf:
        total_chars = 0
        for page in pdf.pages[:3]:  # 只检查前 3 页
            text = page.extract_text() or ""
            total_chars += len(text.strip())

    if total_chars < 50:
        return "scanned"  # 前 3 页几乎没有文字 → 扫描件
    return "native"


def process_document(doc_path: str) -> dict:
    """根据文档类型选择处理方案"""
    doc_type = detect_pdf_type(doc_path)

    if doc_type == "scanned":
        # 扫描件 → 用 OCR 方案（Unstructured hi_res 或 Marker）
        elements = partition_pdf(doc_path, strategy="hi_res")
    else:
        # 原生 PDF → 直接提取（更快更准）
        elements = partition_pdf(doc_path, strategy="fast")

    return {
        "doc_type": doc_type,
        "elements": [{"type": el.category, "text": el.text} for el in elements],
    }
```

## 表格提取的坑

表格是文档处理里最难的部分。常见问题：

1. **合并单元格**：视觉上是一个单元格，提取出来变成多个空值
2. **跨页表格**：一个表格被分成两页，提取出来变成两个独立表格
3. **嵌套表格**：表格里套表格，大多数工具处理不了
4. **复杂表头**：多层表头、斜线表头，提取出来的列名完全错乱

pdfplumber 的表格提取比 Unstructured 好，但对复杂表格也不行。如果表格提取是你的核心需求，考虑 Azure Document Intelligence——它的表格识别准确率可以到 95%+。

## 本课要点

- 文档处理的核心困难是格式多样、结构复杂、质量不一
- 原生 PDF 和扫描件 PDF 需要完全不同的处理方式
- 选型逻辑：先看文档类型 → 再看质量要求 → 最后看成本
- 处理流程：先判断文档类型 → 再选对应方案
- 表格提取是最难的部分，复杂场景考虑 Azure

## 参考答案

### 练习一

```python
import pdfplumber


def classify_pdf(pdf_path: str, check_pages: int = 3) -> dict:
    with pdfplumber.open(pdf_path) as pdf:
        total_pages = len(pdf.pages)
        pages_to_check = min(check_pages, total_pages)
        total_chars = 0

        for page in pdf.pages[:pages_to_check]:
            text = page.extract_text() or ""
            total_chars += len(text.strip())

        avg_chars = total_chars / pages_to_check

        if avg_chars < 10:
            doc_type = "scanned"
        elif avg_chars < 50:
            doc_type = "mixed"
        else:
            doc_type = "native"

        return {
            "type": doc_type,
            "pages_checked": pages_to_check,
            "total_pages": total_pages,
            "total_chars": total_chars,
            "avg_chars_per_page": round(avg_chars, 1),
        }
```

```python
def compare_table_extraction(pdf_path: str):
    from unstructured.partition.pdf import partition_pdf
    import pdfplumber

    print("=== Unstructured ===")
    elements = partition_pdf(pdf_path, strategy="hi_res")
    tables = [el for el in elements if el.category == "Table"]
    print(f"识别到 {len(tables)} 个表格")
    for i, t in enumerate(tables[:2]):
        print(f"  表格 {i+1}: {t.text[:150]}...")

    print("\n=== pdfplumber ===")
    with pdfplumber.open(pdf_path) as pdf:
        for i, page in enumerate(pdf.pages[:5]):
            tables = page.extract_tables()
            if tables:
                print(f"第 {i+1} 页: {len(tables)} 个表格")
                for j, table in enumerate(tables[:2]):
                    print(f"  表格 {j+1}:")
                    for row in table[:3]:
                        print(f"    {row}")
```

你会发现 pdfplumber 对原生 PDF 的表格提取更准确（行列对齐更好），但 Unstructured 能处理更多格式。
