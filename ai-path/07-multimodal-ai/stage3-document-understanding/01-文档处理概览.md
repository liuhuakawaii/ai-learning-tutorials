# 01 文档处理概览——PDF / Word / 扫描件 / 表格的处理挑战

> 文档处理是企业 AI 应用的核心场景。

## 场景引入

你的公司法务部门每天处理大量合同和法律文件，这些文件格式各异——有 PDF 扫描件、Word 文档、Excel 表格，甚至还有手机拍的照片。法务团队需要从中提取关键条款、金额、日期等信息，手动处理不仅耗时，还容易遗漏。你接到任务要构建一个统一的文档处理系统，但调研后发现：不同格式需要完全不同的解析方案，扫描件需要 OCR 而原生 PDF 不需要，表格和图表的提取难度远超纯文本——文档处理的技术栈比想象中复杂得多。

## 常见误区

1. **认为所有 PDF 都是一样的**：原生 PDF（文字可选中）和扫描件 PDF（图片）需要完全不同的处理方式，用错方案会导致提取结果为空或乱码。
2. **忽略文档结构的复杂性**：多列布局、页眉页脚、脚注、水印等元素会干扰文本提取，不做结构分析直接提取会导致内容错乱。
3. **不做格式预判就调用 API**：先判断文档类型（原生/扫描/混合），再选择对应的处理方案，盲目调用通用方案效果差且浪费资源。
4. **忽略多语言文档的处理**：中英混合、繁简混合的文档需要特殊处理，单一语言的 OCR 或解析方案可能无法正确识别。

## 工程建议

1. **按文档类型建立处理分支**：原生 PDF → 直接解析；扫描件 PDF → OCR 后解析；Word → python-docx 解析；图片 → OCR，每种类型用最优方案。
2. **选择合适的开源工具**：Unstructured 最通用、Docling 质量最高、Marker 对 PDF 最专业，根据你的主要文档类型选择。
3. **建立文档预处理 Pipeline**：格式检测 → 格式转换 → 去噪 → 结构识别 → 内容提取，每步独立可测试。
4. **保留原始文档和解析结果**：存储时同时保存原始文档路径、解析中间结果和最终结构化数据，方便人工复核和模型迭代。

## 参考答案

### 练习一：安装并测试一个文档处理工具

**思路**：安装 Unstructured 库，用一份测试 PDF 验证解析能力，检查输出的元素类型和内容质量。

**答案**：

```python
"""安装并测试 Unstructured 文档解析工具。"""
from unstructured.partition.pdf import partition_pdf


def test_unstructured(pdf_path: str) -> dict:
    """测试 Unstructured 解析 PDF 的效果。"""
    elements = partition_pdf(pdf_path)

    # 统计元素类型
    type_counts = {}
    for el in elements:
        type_counts[el.category] = type_counts.get(el.category, 0) + 1

    # 提取内容
    parsed_content = []
    for el in elements:
        parsed_content.append({
            "type": el.category,
            "text": el.text[:200] if el.text else "",
        })

    return {
        "total_elements": len(elements),
        "type_distribution": type_counts,
        "sample_content": parsed_content[:10],
    }


if __name__ == "__main__":
    result = test_unstructured("sample.pdf")
    print(f"总元素数: {result['total_elements']}")
    print(f"类型分布: {result['type_distribution']}")
    print("\n前 10 个元素:")
    for item in result["sample_content"]:
        print(f"  [{item['type']}] {item['text'][:80]}...")
```

**要点**：
- Unstructured 安装时需要额外依赖：`pip install "unstructured[all-docs]"` 才能支持所有格式
- `strategy="hi_res"` 使用高精度模式（依赖 OCR），准确率更高但速度慢；`strategy="fast"` 速度快但可能丢失表格
- 解析结果的 `element.category` 包括 Title、NarrativeText、Table、ListItem 等，可用于后续结构化处理
- 常见错误：只安装基础包 `pip install unstructured` 就尝试解析 PDF，会因缺少 `pdf2image` 等依赖而报错

### 练习二：解析一个 PDF 文档

**思路**：解析一份真实 PDF，提取文本、标题、表格等结构化信息，输出为可读的格式。

**答案**：

```python
"""解析 PDF 文档并提取结构化信息。"""
from unstructured.partition.pdf import partition_pdf


def parse_pdf_structured(pdf_path: str) -> dict:
    """解析 PDF 并按元素类型分类提取。"""
    elements = partition_pdf(pdf_path, strategy="hi_res")

    result = {
        "title": "",
        "headings": [],
        "paragraphs": [],
        "tables": [],
        "list_items": [],
        "other": [],
    }

    for el in elements:
        text = el.text.strip() if el.text else ""
        if not text:
            continue

        if el.category == "Title":
            if not result["title"]:
                result["title"] = text
            result["headings"].append(text)
        elif el.category == "Table":
            result["tables"].append(text)
        elif el.category == "ListItem":
            result["list_items"].append(text)
        elif el.category == "NarrativeText":
            result["paragraphs"].append(text)
        else:
            result["other"].append({"type": el.category, "text": text})

    # 统计
    result["stats"] = {
        "headings": len(result["headings"]),
        "paragraphs": len(result["paragraphs"]),
        "tables": len(result["tables"]),
        "list_items": len(result["list_items"]),
    }

    return result


if __name__ == "__main__":
    result = parse_pdf_structured("contract.pdf")
    print(f"标题: {result['title']}")
    print(f"统计: {result['stats']}")
    if result["tables"]:
        print(f"\n表格内容:\n{result['tables'][0][:300]}")
```

**要点**：
- `strategy="hi_res"` 会调用 OCR 引擎处理扫描件，首次运行会下载模型，需要网络和磁盘空间
- 多列布局的 PDF 可能出现文本顺序错乱，Unstructured 的布局检测不完美，必要时需用 Docling 替代
- 表格内容提取出来可能是 Markdown 格式或纯文本，不一定是结构化的行列数据
- 常见错误：对扫描件 PDF 使用 `strategy="fast"`，结果为空，因为 fast 模式不支持 OCR

### 练习三：为你的场景选择合适的文档处理工具

**思路**：根据文档类型、质量要求、部署环境三个维度分析需求，对比主流工具的优劣，给出选型建议。

**答案**：

选型决策矩阵：

| 场景 | 主要文档类型 | 质量要求 | 推荐工具 | 理由 |
|------|------------|----------|----------|------|
| 企业知识库 | PDF + Word | 中等 | Unstructured | 格式支持最全，社区活跃 |
| 合同审阅 | 扫描件 PDF | 高 | Docling | 结构识别最准确，表格提取好 |
| 学术论文解析 | 原生 PDF | 高 | Marker | PDF 专精，公式和引用处理好 |
| 财务报表处理 | PDF 表格 | 很高 | Azure Document Intelligence | 表格识别准确率最高 |
| 通用文档问答 | 混合格式 | 中等 | Unstructured + LLM | 灵活度高，可自定义后处理 |

选型决策树：

```
文档是否主要是扫描件/图片？
├── 是 → 是否有企业预算？
│   ├── 是 → Azure Document Intelligence（OCR 最准）
│   └── 否 → Marker + Tesseract OCR（开源方案）
└── 否 → 是否需要高精度表格提取？
    ├── 是 → Docling（表格识别质量最高）
    └── 否 → 文档格式是否多样？
        ├── 是 → Unstructured（格式支持最全）
        └── 否 → 按具体格式选专用工具
```

**要点**：
- 没有万能工具，不同工具在不同文档类型上的表现差异很大，必须用真实文档做对比测试
- Unstructured 是"瑞士军刀"，什么都能做但不一定是最好的；Docling 在质量上更胜一筹但格式支持较少
- Azure Document Intelligence 的表格提取准确率可达 95%+，但成本高（$1.50/1000页）
- 常见错误：只看 GitHub star 数选工具，实际上 star 多不代表在你的文档类型上效果好
