# 阶段实战：合同/发票智能解析系统

> **项目类型**：项目推进课
> **前置**：完成 01-05 课
> **目标**：把文档解析、信息提取、结构化输出串成一个能处理合同和发票的自动化解析系统

## 当前卡点

你已经会用 Unstructured 解析 PDF、用 pdfplumber 提取表格、用 LLM 做信息提取。但真实需求是：法务每天丢 100 份合同进来，需要自动提取合同双方、金额、期限、违约条款；财务每天丢 200 张发票进来，需要自动识别号码、金额、税额。

卡在哪里：
- 合同和发票的结构完全不同，不能用同一个 prompt 处理
- LLM 返回的 JSON 字段经常缺失或格式错误，金额字段有时候返回字符串有时候返回数字
- OCR 的错误会传递到提取环节——"¥8,500" 被识别成 "¥8.500"，直接导致金额错误

## 系统设计

```
文档输入
  │
  ▼
[文档类型判断] ── 合同 or 发票？
  │
  ├── 合同 ──▶ [Unstructured 解析] ──▶ [合同提取 Prompt] ──▶ [Pydantic 校验]
  │
  └── 发票 ──▶ [pdfplumber 提取] ──▶ [发票提取 Prompt] ──▶ [Pydantic 校验]
                                                        │
                                                        ▼
                                                  结构化 JSON 输出
```

关键设计判断：
- **合同用 Unstructured**：合同是长文档，需要处理标题、段落、列表等多种元素
- **发票用 pdfplumber**：发票结构固定，表格提取质量更重要
- **每种文档用专用 Prompt**：不要试图用一个 prompt 处理所有文档类型
- **Pydantic 校验输出**：LLM 返回的 JSON 必须通过 schema 校验

## 核心实现

```python
import json
from pydantic import BaseModel, Field
from openai import OpenAI


class ContractInfo(BaseModel):
    party_a: str = Field(description="甲方名称")
    party_b: str = Field(description="乙方名称")
    amount: float = Field(description="合同金额（元）")
    start_date: str = Field(description="起始日期")
    end_date: str = Field(description="终止日期")
    payment_terms: str = Field(description="付款方式")
    penalty_clause: str = Field(description="违约条款摘要")


class InvoiceInfo(BaseModel):
    invoice_number: str = Field(description="发票号码")
    date: str = Field(description="开票日期")
    buyer: str = Field(description="购买方")
    seller: str = Field(description="销售方")
    amount: float = Field(description="金额（不含税）")
    tax: float = Field(description="税额")
    total: float = Field(description="价税合计")


CONTRACT_PROMPT = """从以下合同文本中提取关键信息，输出 JSON：
{
  "party_a": "甲方",
  "party_b": "乙方",
  "amount": 数字（元）,
  "start_date": "YYYY-MM-DD",
  "end_date": "YYYY-MM-DD",
  "payment_terms": "付款方式",
  "penalty_clause": "违约条款摘要，50字以内"
}
只输出 JSON，不要其他文字。金额必须是纯数字，不要包含逗号或货币符号。"""

INVOICE_PROMPT = """从以下发票文本中提取关键信息，输出 JSON：
{
  "invoice_number": "发票号码",
  "date": "YYYY-MM-DD",
  "buyer": "购买方名称",
  "seller": "销售方名称",
  "amount": 数字（不含税金额）,
  "tax": 数字（税额）,
  "total": 数字（价税合计）
}
只输出 JSON，不要其他文字。金额必须是纯数字。"""


class DocumentParser:
    def __init__(self, model: str = "gpt-4o"):
        self.client = OpenAI()
        self.model = model

    def parse_contract(self, doc_path: str) -> ContractInfo:
        text = self._extract_text(doc_path, doc_type="contract")
        raw = self._extract_with_llm(text, CONTRACT_PROMPT)
        return ContractInfo(**raw)

    def parse_invoice(self, doc_path: str) -> InvoiceInfo:
        text = self._extract_text(doc_path, doc_type="invoice")
        raw = self._extract_with_llm(text, INVOICE_PROMPT)
        return InvoiceInfo(**raw)

    def _extract_text(self, doc_path: str, doc_type: str) -> str:
        if doc_type == "invoice":
            # 发票用 pdfplumber，表格提取更准
            import pdfplumber
            with pdfplumber.open(doc_path) as pdf:
                parts = []
                for page in pdf.pages:
                    text = page.extract_text()
                    if text:
                        parts.append(text)
                    for table in page.extract_tables():
                        parts.append("\n".join(
                            " | ".join(str(cell) for cell in row if cell)
                            for row in table
                        ))
                return "\n".join(parts)
        else:
            # 合同用 Unstructured
            from unstructured.partition.pdf import partition_pdf
            elements = partition_pdf(doc_path, strategy="fast")
            return "\n".join(el.text for el in elements if el.text)

    def _extract_with_llm(self, text: str, prompt: str) -> dict:
        response = self.client.chat.completions.create(
            model=self.model,
            messages=[
                {"role": "system", "content": prompt},
                {"role": "user", "content": text[:8000]},  # 截断防超限
            ],
            response_format={"type": "json_object"},
        )
        return json.loads(response.choices[0].message.content)
```

几个设计判断说明：

- **`text[:8000]` 截断**：合同可能很长，但关键信息通常在前几页。截断可以避免 token 超限和成本过高
- **Pydantic 校验**：如果 LLM 返回的 JSON 字段类型不对（比如 amount 返回了字符串），Pydantic 会自动尝试转换或报错
- **`response_format={"type": "json_object"}`**：强制 LLM 输出合法 JSON，减少格式错误

## 处理金额格式的坑

OCR 经常把金额识别错。"¥8,500.00" 可能变成 "8.500.00" 或 "850000"。加一个金额清洗函数：

```python
import re


def clean_amount(raw: str | float | int) -> float:
    """清洗金额字段"""
    if isinstance(raw, (int, float)):
        return float(raw)

    # 去掉货币符号和空格
    cleaned = re.sub(r'[¥￥$€,\s]', '', str(raw))

    # 处理欧洲格式 "8.500.00" → "8500.00"
    parts = cleaned.split('.')
    if len(parts) == 3:
        # 可能是千分位误识别
        cleaned = parts[0] + parts[1] + '.' + parts[2]

    try:
        return float(cleaned)
    except ValueError:
        return 0.0
```

## 批量处理与质量监控

```python
from dataclasses import dataclass, field


@dataclass
class ParseResult:
    doc_path: str
    doc_type: str
    success: bool
    data: dict | None = None
    error: str | None = None
    warnings: list[str] = field(default_factory=list)


def batch_parse(doc_paths: list[str], doc_type: str) -> list[ParseResult]:
    parser = DocumentParser()
    results = []

    for path in doc_paths:
        try:
            if doc_type == "contract":
                data = parser.parse_contract(path)
            else:
                data = parser.parse_invoice(path)

            warnings = validate_result(data, doc_type)
            results.append(ParseResult(
                doc_path=path, doc_type=doc_type, success=True,
                data=data.model_dump(), warnings=warnings,
            ))
        except Exception as e:
            results.append(ParseResult(
                doc_path=path, doc_type=doc_type, success=False,
                error=str(e),
            ))

    return results


def validate_result(data, doc_type: str) -> list[str]:
    warnings = []
    if data.amount <= 0:
        warnings.append("金额为 0 或负数，可能提取错误")
    if doc_type == "contract":
        if data.start_date > data.end_date:
            warnings.append("起始日期晚于终止日期")
    return warnings
```

## 本课要点

- 合同和发票需要不同的解析策略：合同用 Unstructured（长文档），发票用 pdfplumber（表格）
- Pydantic 做输出校验，强制 LLM 返回符合 schema 的数据
- 金额字段需要单独清洗，OCR 错误会直接影响业务数据
- 关键文档（大额合同）的解析结果必须人工复核
