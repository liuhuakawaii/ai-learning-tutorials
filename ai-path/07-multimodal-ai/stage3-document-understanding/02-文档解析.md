# 02 文档解析——Unstructured / Docling 的文档拆分与结构化

> 文档解析是文档处理的基础能力。

## 场景引入

你正在为一个企业知识库系统构建文档解析模块，需要处理的文档类型包括：技术文档（PDF）、合同模板（Word）、财务报表（Excel）。这些文档包含大量结构化信息——标题层级、表格、列表、图表，简单的"全文提取"会丢失所有结构信息。你选择了 Unstructured 和 Docling 两个工具，但在实际测试中发现：同一份 PDF 用不同工具解析的结果差异很大，表格经常被识别为普通文本，多列布局的内容顺序错乱——文档解析的质量直接决定了下游 RAG 系统的效果。

## 学习目标

- 掌握文档解析的方法
- 理解文档拆分和结构化
- 学会处理各种文档格式

## 三、文档拆分

```python
def split_document(elements: list, chunk_size: int = 1000) -> list:
    """文档拆分"""
    chunks = []
    current_chunk = ""
    
    for element in elements:
        if len(current_chunk) + len(element.text) > chunk_size:
            chunks.append(current_chunk)
            current_chunk = element.text
        else:
            current_chunk += "\n" + element.text
    
    if current_chunk:
        chunks.append(current_chunk)
    
    return chunks
```

## 四、结构化提取

```python
def extract_structured_data(elements: list) -> dict:
    """结构化提取"""
    structured = {
        "title": "",
        "sections": [],
        "tables": [],
        "images": []
    }
    
    for element in elements:
        if element.category == "Title":
            structured["title"] = element.text
        elif element.category == "Table":
            structured["tables"].append(element.text)
        elif element.category == "Image":
            structured["images"].append(element.metadata.image_path)
        else:
            structured["sections"].append(element.text)
    
    return structured
```

## 五、多格式支持

```python
def parse_document(file_path: str) -> list:
    """解析文档"""
    ext = file_path.split(".")[-1].lower()
    
    if ext == "pdf":
        return partition_pdf(file_path)
    elif ext == "docx":
        return partition_docx(file_path)
    elif ext == "txt":
        with open(file_path, "r") as f:
            return [f.read()]
    else:
        raise ValueError(f"不支持的格式：{ext}")
```

## 常见误区

1. **不做解析质量评估就上线**：不同文档类型的解析质量差异很大，必须建立评估基准（人工标注的标准答案），量化评估解析准确率。
2. **分块大小设置不合理**：chunk_size 太大会超出模型上下文限制，太小会丢失语义完整性，需要根据文档类型和下游用途调优。
3. **忽略图片和表格的处理**：很多文档解析工具默认只提取文本，图片和表格被忽略或识别为无意义元素，需要专门配置提取策略。
4. **不做异常处理**：损坏的 PDF、加密的文档、超大文件等情况会导致解析失败，必须做完善的异常捕获和降级处理。

## 工程建议

1. **先做小规模对比测试**：用 10-20 份典型文档分别测试 Unstructured、Docling、Marker，对比解析质量和速度，用数据驱动选型。
2. **按元素类型分类处理**：标题、正文、表格、图片、列表分别提取和存储，保留文档结构信息，不要只提取纯文本。
3. **分块策略要与下游用途匹配**：RAG 检索场景用语义分块（按段落/章节），摘要场景用固定长度分块，不同用途需要不同的分块策略。
4. **建立解析结果的缓存机制**：同一文档多次查询时不必重复解析，缓存解析结果可大幅降低成本和延迟。

### 练习一：解析一个 PDF 文档

**思路**：分别用 Unstructured 和 Docling 解析同一份 PDF，对比输出质量差异。

**答案**：

```python
"""对比 Unstructured 和 Docling 的 PDF 解析效果。"""
from unstructured.partition.pdf import partition_pdf
from docling.document_converter import DocumentConverter


def compare_parsing(pdf_path: str) -> dict:
    """用两个工具解析同一份 PDF 并对比结果。"""
    # Unstructured 解析
    us_elements = partition_pdf(pdf_path, strategy="hi_res")
    us_result = {
        "element_count": len(us_elements),
        "types": {},
        "text_preview": "",
    }
    for el in us_elements:
        us_result["types"][el.category] = us_result["types"].get(el.category, 0) + 1
    us_result["text_preview"] = "\n".join(el.text for el in us_elements[:5] if el.text)

    # Docling 解析
    converter = DocumentConverter()
    doc_result = converter.convert(pdf_path)
    doc_markdown = doc_result.document.export_to_markdown()
    doc_result_parsed = {
        "markdown_length": len(doc_markdown),
        "text_preview": doc_markdown[:500],
    }

    return {
        "unstructured": us_result,
        "docling": doc_result_parsed,
    }


if __name__ == "__main__":
    result = compare_parsing("document.pdf")
    print("=== Unstructured ===")
    print(f"元素数: {result['unstructured']['element_count']}")
    print(f"类型分布: {result['unstructured']['types']}")
    print(f"预览:\n{result['unstructured']['text_preview'][:200]}")
    print("\n=== Docling ===")
    print(f"Markdown 长度: {result['docling']['markdown_length']}")
    print(f"预览:\n{result['docling']['text_preview'][:200]}")
```

**要点**：
- Unstructured 输出元素列表（Title/NarrativeText/Table 等），Docling 输出 Markdown，两者格式不同
- Docling 在表格和多列布局的识别上通常优于 Unstructured，但安装依赖更重
- 同一份 PDF 两个工具的解析结果可能差异 20-30%，必须用真实文档做对比
- 常见错误：只看解析速度不看质量，fast 模式解析很快但表格和图片内容全部丢失

### 练习二：实现文档拆分功能

**思路**：实现语义分块和滑动窗口分块两种策略，对比它们在保持语义完整性上的差异。

**答案**：

```python
"""文档拆分：语义分块 + 滑动窗口分块。"""
from unstructured.partition.pdf import partition_pdf


def semantic_chunking(elements: list, max_chunk_size: int = 1000) -> list:
    """按语义边界（元素）分块，保持段落完整性。"""
    chunks = []
    current_chunk = []
    current_size = 0

    for element in elements:
        text = element.text.strip() if element.text else ""
        if not text:
            continue

        element_size = len(text)

        # 当前元素加入后超出限制，先保存已有 chunk
        if current_size + element_size > max_chunk_size and current_chunk:
            chunks.append({
                "text": "\n".join(current_chunk),
                "char_count": current_size,
            })
            current_chunk = [text]
            current_size = element_size
        else:
            current_chunk.append(text)
            current_size += element_size

    if current_chunk:
        chunks.append({
            "text": "\n".join(current_chunk),
            "char_count": current_size,
        })

    return chunks


def sliding_window_chunking(text: str, chunk_size: int = 1000, overlap: int = 200) -> list:
    """滑动窗口分块，相邻 chunk 有重叠区域。"""
    if overlap >= chunk_size:
        raise ValueError("overlap 必须小于 chunk_size")

    chunks = []
    start = 0

    while start < len(text):
        end = start + chunk_size
        chunk_text = text[start:end]
        chunks.append({
            "text": chunk_text,
            "start_pos": start,
            "end_pos": min(end, len(text)),
        })
        start = end - overlap

    return chunks


if __name__ == "__main__":
    # 语义分块
    elements = partition_pdf("document.pdf")
    semantic_chunks = semantic_chunking(elements, max_chunk_size=800)
    print(f"语义分块: {len(semantic_chunks)} 个 chunk")
    for i, chunk in enumerate(semantic_chunks[:3]):
        print(f"  chunk {i}: {chunk['char_count']} 字")

    # 滑动窗口分块
    full_text = "\n".join(el.text for el in elements if el.text)
    window_chunks = sliding_window_chunking(full_text, chunk_size=800, overlap=150)
    print(f"\n滑动窗口分块: {len(window_chunks)} 个 chunk")
    for i, chunk in enumerate(window_chunks[:3]):
        print(f"  chunk {i}: 位置 {chunk['start_pos']}-{chunk['end_pos']}")
```

**要点**：
- 语义分块按文档自然边界（段落、标题）切分，比固定长度分块的语义完整性好得多
- 滑动窗口的 overlap 一般设为 chunk_size 的 10-20%，太大会导致重复内容过多增加存储和检索成本
- chunk_size 的选择取决于下游用途：RAG 检索通常 500-1000 字，LLM 上下文可更大
- 常见错误：分块时不保留元素类型信息（标题/正文/表格），导致检索时无法区分内容层级

### 练习三：提取文档的结构化数据

**思路**：从解析结果中按元素类型分类提取，输出为结构化 JSON，保留文档的层级关系。

**答案**：

```python
"""从文档中提取结构化数据。"""
from unstructured.partition.pdf import partition_pdf
import json


def extract_structured_data(pdf_path: str) -> dict:
    """解析 PDF 并提取结构化数据。"""
    elements = partition_pdf(pdf_path, strategy="hi_res")

    structured = {
        "metadata": {"source": pdf_path, "total_elements": len(elements)},
        "title": "",
        "outline": [],
        "content_sections": [],
        "tables": [],
        "list_items": [],
    }

    current_section = None

    for el in elements:
        text = el.text.strip() if el.text else ""
        if not text:
            continue

        if el.category == "Title":
            if not structured["title"]:
                structured["title"] = text
            structured["outline"].append(text)
            # 开启新章节
            if current_section:
                structured["content_sections"].append(current_section)
            current_section = {"heading": text, "content": []}

        elif el.category == "Table":
            structured["tables"].append({
                "content": text,
                "section": current_section["heading"] if current_section else None,
            })

        elif el.category == "ListItem":
            structured["list_items"].append(text)
            if current_section:
                current_section["content"].append({"type": "list_item", "text": text})

        elif el.category == "NarrativeText":
            if current_section:
                current_section["content"].append({"type": "paragraph", "text": text})

    if current_section:
        structured["content_sections"].append(current_section)

    return structured


if __name__ == "__main__":
    result = extract_structured_data("report.pdf")
    print(f"文档标题: {result['title']}")
    print(f"章节数: {len(result['content_sections'])}")
    print(f"表格数: {len(result['tables'])}")
    print(f"列表项: {len(result['list_items'])}")
    print(f"\n大纲: {result['outline']}")
    print(f"\n结构化数据:\n{json.dumps(result, ensure_ascii=False, indent=2)[:500]}...")
```

**要点**：
- 结构化提取要保留元素之间的层级关系（标题 → 正文 → 表格），不能只提取扁平文本列表
- 表格应该单独提取并标记所属章节，方便后续做表格检索和结构化查询
- 用 `section` 字段标记内容所属章节，后续 RAG 检索时可按章节过滤
- 常见错误：把所有元素混在一起输出为纯文本，丢失了文档的层级结构，导致下游系统无法做精确检索
