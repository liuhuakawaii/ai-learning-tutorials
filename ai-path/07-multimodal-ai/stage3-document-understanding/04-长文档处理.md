# 04 长文档处理——大文档的分块策略与上下文管理

> 长文档处理需要特殊的策略来管理上下文。

## 场景引入

你要构建一个合同审阅系统，用户上传一份 50 页的合同 PDF，系统需要回答"这份合同的违约金条款是什么？"这类具体问题。直接把整份合同扔给 GPT-4o 会超出上下文限制，简单按字数分块又会把一个完整的条款切成两半导致语义断裂。你需要设计一套智能分块策略，让每个 chunk 既不超过 token 限制，又能保持语义完整性——这是长文档处理的核心挑战。

## 学习目标

- 掌握长文档的分块策略
- 理解上下文管理的方法
- 学会处理超长文档

---

## 一、分块策略

```
分块策略：

1. 固定长度分块
   - 按字符数或 Token 数分块
   - 简单但可能破坏语义

2. 语义分块
   - 按段落、章节分块
   - 保持语义完整性

3. 递归分块
   - 先按大块分，再按小块分
   - 灵活性高

4. 滑动窗口
   - 重叠分块
   - 保持上下文连续性
```

## 二、实现

```python
def semantic_chunking(elements: list, max_chunk_size: int = 1000) -> list:
    """语义分块"""
    chunks = []
    current_chunk = []
    current_size = 0
    
    for element in elements:
        element_size = len(element.text)
        
        if current_size + element_size > max_chunk_size and current_chunk:
            chunks.append("\n".join([e.text for e in current_chunk]))
            current_chunk = [element]
            current_size = element_size
        else:
            current_chunk.append(element)
            current_size += element_size
    
    if current_chunk:
        chunks.append("\n".join([e.text for e in current_chunk]))
    
    return chunks

def sliding_window_chunking(text: str, chunk_size: int = 1000, overlap: int = 200) -> list:
    """滑动窗口分块"""
    chunks = []
    start = 0
    
    while start < len(text):
        end = start + chunk_size
        chunks.append(text[start:end])
        start = end - overlap
    
    return chunks
```

## 三、上下文管理

```python
class ContextManager:
    """上下文管理器"""
    
    def __init__(self, max_context_size: int = 4000):
        self.max_context_size = max_context_size
        self.context = []
    
    def add_context(self, text: str):
        """添加上下文"""
        self.context.append(text)
        
        # 裁剪上下文
        total_size = sum(len(t) for t in self.context)
        while total_size > self.max_context_size:
            removed = self.context.pop(0)
            total_size -= len(removed)
    
    def get_context(self) -> str:
        """获取上下文"""
        return "\n".join(self.context)
```

```python
def generate_document_summary(document_path: str) -> str:
    """生成文档摘要"""
    # 1. 解析文档
    elements = parse_document(document_path)
    
    # 2. 分块处理
    chunks = semantic_chunking(elements)
    
    # 3. 生成各块摘要
    chunk_summaries = []
    for chunk in chunks:
        summary = generate_summary(chunk)
        chunk_summaries.append(summary)
    
    # 4. 生成总摘要
    final_summary = generate_summary("\n".join(chunk_summaries))
    
    return final_summary
```

## 常见误区

1. **按固定字数简单分块**：按 1000 字切分会导致段落、表格、列表被切断，语义完整性被破坏，下游检索和问答效果很差。
2. **忽略分块之间的上下文关系**：相邻 chunk 之间通常有上下文关联，不做重叠或上下文传递会导致每个 chunk 缺乏背景信息。
3. **分块大小不做调优**：chunk_size 没有通用最优值，取决于文档类型、模型上下文长度、检索粒度，需要通过实验找到最佳参数。
4. **摘要生成只做一次**：长文档的单次摘要会丢失大量细节，分层摘要（先各块摘要再总摘要）能保留更多关键信息。

## 工程建议

1. **优先用语义分块**：按标题、段落、章节等自然边界分块，比固定长度分块的语义完整性好得多。
2. **相邻 chunk 保留 10-20% 重叠**：滑动窗口的重叠区域可传递上下文，避免信息在边界处丢失。
3. **分块后做质量检查**：检查每个 chunk 是否完整（是否有断句、是否有未闭合的括号/引号），过滤掉质量差的 chunk。
4. **上下文管理器做滑动窗口**：对话场景中用上下文管理器维护最近 N 轮对话的摘要，避免上下文超长导致成本飙升。

### 练习一：实现语义分块功能

**思路**：基于文档元素的自然边界（标题、段落）分块，保证每个 chunk 不超限且语义完整。

**答案**：

```python
"""语义分块：按文档自然边界切分，保持语义完整性。"""
from unstructured.partition.pdf import partition_pdf


def semantic_chunking(elements: list, max_chunk_size: int = 1000, min_chunk_size: int = 100) -> list:
    """按语义边界分块。

    Args:
        elements: Unstructured 解析出的元素列表
        max_chunk_size: 单个 chunk 最大字符数
        min_chunk_size: 单个 chunk 最小字符数（过小的 chunk 合并到前一个）

    Returns:
        chunk 列表，每个 chunk 包含文本和元信息
    """
    chunks = []
    current_texts = []
    current_size = 0

    for element in elements:
        text = element.text.strip() if element.text else ""
        if not text:
            continue

        element_size = len(text)

        # 遇到标题且当前 chunk 已有内容，开启新 chunk
        if element.category == "Title" and current_texts:
            chunks.append(_build_chunk(current_texts, current_size))
            current_texts = []
            current_size = 0

        # 当前元素加入后超出限制
        if current_size + element_size > max_chunk_size and current_texts:
            # 如果当前 chunk 太小，尝试合并
            if current_size < min_chunk_size:
                current_texts.append(text)
                current_size += element_size
                continue

            chunks.append(_build_chunk(current_texts, current_size))
            current_texts = [text]
            current_size = element_size
        else:
            current_texts.append(text)
            current_size += element_size

    if current_texts:
        # 最后一个 chunk 太小，合并到前一个
        if current_size < min_chunk_size and chunks:
            last_chunk = chunks[-1]
            last_chunk["text"] += "\n" + "\n".join(current_texts)
            last_chunk["char_count"] += current_size
        else:
            chunks.append(_build_chunk(current_texts, current_size))

    # 添加序号
    for i, chunk in enumerate(chunks):
        chunk["index"] = i

    return chunks


def _build_chunk(texts: list, char_count: int) -> dict:
    """构建 chunk 字典。"""
    return {
        "text": "\n".join(texts),
        "char_count": char_count,
        "element_count": len(texts),
    }


if __name__ == "__main__":
    elements = partition_pdf("long_contract.pdf")
    chunks = semantic_chunking(elements, max_chunk_size=800, min_chunk_size=100)

    print(f"共 {len(chunks)} 个 chunk")
    for chunk in chunks[:5]:
        preview = chunk["text"][:60].replace("\n", " ")
        print(f"  [{chunk['index']}] {chunk['char_count']} 字, {chunk['element_count']} 个元素: {preview}...")
```

**要点**：
- 标题是天然的分块边界，遇到标题应该开启新 chunk，而不是把标题和正文混在一起
- min_chunk_size 可防止出现只有几个字的碎片 chunk，过小的 chunk 缺乏上下文信息
- 分块后要检查每个 chunk 是否有断句（未闭合的引号、括号），质量差的 chunk 应该合并或丢弃
- 常见错误：只按 max_chunk_size 机械切分，把一个完整的表格或列表切成两半，导致语义断裂

### 练习二：实现上下文管理器

**思路**：实现滑动窗口式的上下文管理器，支持添加新上下文、自动裁剪超长历史、获取当前上下文。

**答案**：

```python
"""上下文管理器：维护对话历史，自动裁剪超长上下文。"""
from collections import deque
from dataclasses import dataclass, field
from typing import Optional


@dataclass
class ContextEntry:
    """上下文条目。"""
    text: str
    role: str = "user"
    token_estimate: int = 0

    def __post_init__(self):
        if self.token_estimate == 0:
            # 粗略估算：中文 1 字 ≈ 2 token，英文 1 词 ≈ 1.3 token
            self.token_estimate = len(self.text) * 2


class ContextManager:
    """上下文管理器，支持滑动窗口和摘要压缩。"""

    def __init__(self, max_tokens: int = 4000):
        self.max_tokens = max_tokens
        self.entries: deque[ContextEntry] = deque()
        self.total_tokens = 0
        self.summary: Optional[str] = None

    def add(self, text: str, role: str = "user"):
        """添加新的上下文条目。"""
        entry = ContextEntry(text=text, role=role)
        self.entries.append(entry)
        self.total_tokens += entry.token_estimate

        # 超出限制时裁剪最早的条目
        while self.total_tokens > self.max_tokens and len(self.entries) > 1:
            removed = self.entries.popleft()
            self.total_tokens -= removed.token_estimate

    def get_context(self, include_summary: bool = True) -> str:
        """获取当前上下文字符串。"""
        parts = []
        if include_summary and self.summary:
            parts.append(f"[历史摘要] {self.summary}")

        for entry in self.entries:
            parts.append(f"[{entry.role}] {entry.text}")

        return "\n\n".join(parts)

    def get_messages(self, system_prompt: str = "") -> list:
        """获取适合 LLM API 的 messages 格式。"""
        messages = []
        if system_prompt:
            messages.append({"role": "system", "content": system_prompt})

        if self.summary:
            messages.append({
                "role": "system",
                "content": f"之前的对话摘要：{self.summary}",
            })

        for entry in self.entries:
            messages.append({"role": entry.role, "content": entry.text})

        return messages

    def compress_with_summary(self, client, model: str = "gpt-4o-mini"):
        """用 LLM 压缩历史为摘要，释放上下文空间。"""
        if len(self.entries) < 3:
            return

        # 保留最近 2 条，其余压缩为摘要
        entries_to_compress = list(self.entries)[:-2]
        history_text = "\n".join(
            f"[{e.role}] {e.text}" for e in entries_to_compress
        )

        response = client.chat.completions.create(
            model=model,
            messages=[{
                "role": "user",
                "content": f"请将以下对话历史压缩为简短摘要（100字以内）：\n\n{history_text}",
            }],
        )

        new_summary = response.choices[0].message.content
        if self.summary:
            self.summary = f"{self.summary}\n{new_summary}"
        else:
            self.summary = new_summary

        # 移除已压缩的条目
        for _ in range(len(entries_to_compress)):
            removed = self.entries.popleft()
            self.total_tokens -= removed.token_estimate

    @property
    def current_token_count(self) -> int:
        return self.total_tokens

    @property
    def message_count(self) -> int:
        return len(self.entries)


if __name__ == "__main__":
    cm = ContextManager(max_tokens=2000)

    cm.add("我想了解一下公司的年假政策", role="user")
    cm.add("根据员工手册，工作满一年的员工享有 5 天年假。", role="assistant")
    cm.add("那试用期员工可以请假吗？", role="user")

    print(f"消息数: {cm.message_count}")
    print(f"估算 token: {cm.current_token_count}")
    print(f"\n上下文:\n{cm.get_context()}")
```

**要点**：
- token 估算是粗略的，中文每字约 1.5-2 token，精确计数需要用 tiktoken 库
- 压缩摘要会丢失细节，只适合对历史精度要求不高的对话场景
- deque 自动维护 FIFO 顺序，比 list 的 pop(0) 性能好（O(1) vs O(n)）
- 常见错误：只保留最近 N 轮而不做摘要压缩，重要但较早的上下文被完全丢弃

### 练习三：实现长文档问答

**思路**：解析文档 → 语义分块 → 向量化检索 → LLM 生成答案，实现完整的长文档 QA Pipeline。

**答案**：

```python
"""长文档问答系统。"""
from openai import OpenAI
from unstructured.partition.pdf import partition_pdf
import numpy as np


class LongDocumentQA:
    """长文档问答：分块 + 向量检索 + LLM 生成。"""

    def __init__(self, embedding_model: str = "text-embedding-3-small", llm_model: str = "gpt-4o"):
        self.client = OpenAI()
        self.embedding_model = embedding_model
        self.llm_model = llm_model
        self.chunks = []
        self.chunk_embeddings = []

    def load_document(self, pdf_path: str, chunk_size: int = 800):
        """加载并分块文档。"""
        elements = partition_pdf(pdf_path, strategy="hi_res")
        self.chunks = self._semantic_chunking(elements, chunk_size)

        # 批量向量化
        texts = [c["text"] for c in self.chunks]
        self.chunk_embeddings = self._batch_embed(texts)
        print(f"已加载 {len(self.chunks)} 个 chunk")

    def ask(self, question: str, top_k: int = 3) -> dict:
        """提问并返回答案和引用来源。"""
        # 1. 检索相关 chunk
        question_embedding = self._get_embedding(question)
        relevant_indices = self._retrieve(question_embedding, top_k)
        relevant_chunks = [self.chunks[i] for i in relevant_indices]

        # 2. 构建 prompt
        context = "\n\n---\n\n".join(
            f"[段落 {c['index'] + 1}]\n{c['text']}" for c in relevant_chunks
        )

        # 3. 生成答案
        response = self.client.chat.completions.create(
            model=self.llm_model,
            messages=[
                {
                    "role": "system",
                    "content": "你是一个文档问答助手。只根据提供的文档内容回答问题，如果文档中没有相关信息请明确说明。回答时标注引用来源的段落编号。",
                },
                {
                    "role": "user",
                    "content": f"文档内容：\n{context}\n\n问题：{question}",
                },
            ],
        )

        return {
            "answer": response.choices[0].message.content,
            "sources": [{"index": c["index"], "preview": c["text"][:100]} for c in relevant_chunks],
        }

    def _semantic_chunking(self, elements: list, max_size: int) -> list:
        """语义分块。"""
        chunks = []
        current_texts = []
        current_size = 0

        for el in elements:
            text = el.text.strip() if el.text else ""
            if not text:
                continue

            if current_size + len(text) > max_size and current_texts:
                chunks.append({"text": "\n".join(current_texts), "index": len(chunks)})
                current_texts = [text]
                current_size = len(text)
            else:
                current_texts.append(text)
                current_size += len(text)

        if current_texts:
            chunks.append({"text": "\n".join(current_texts), "index": len(chunks)})

        return chunks

    def _get_embedding(self, text: str) -> list:
        """获取文本向量。"""
        response = self.client.embeddings.create(model=self.embedding_model, input=text)
        return response.data[0].embedding

    def _batch_embed(self, texts: list) -> list:
        """批量向量化。"""
        response = self.client.embeddings.create(model=self.embedding_model, input=texts)
        return [item.embedding for item in response.data]

    def _retrieve(self, query_embedding: list, top_k: int) -> list:
        """余弦相似度检索。"""
        query_vec = np.array(query_embedding)
        similarities = []

        for i, emb in enumerate(self.chunk_embeddings):
            chunk_vec = np.array(emb)
            sim = np.dot(query_vec, chunk_vec) / (np.linalg.norm(query_vec) * np.linalg.norm(chunk_vec))
            similarities.append((sim, i))

        similarities.sort(reverse=True)
        return [i for _, i in similarities[:top_k]]


if __name__ == "__main__":
    qa = LongDocumentQA()
    qa.load_document("company_handbook.pdf")

    result = qa.ask("公司的年假政策是什么？")
    print(f"答案: {result['answer']}")
    print(f"引用来源: {result['sources']}")
```

**要点**：
- 向量检索用余弦相似度，OpenAI 的 embedding 已经归一化，点积即可
- top_k=3 是常用值，太少可能漏掉相关段落，太多会引入噪音增加 token 消耗
- prompt 中必须要求 LLM 只根据文档内容回答，否则会用自身知识"编造"答案
- 常见错误：不指定引用来源，用户无法验证答案的准确性，也无法发现检索错误
