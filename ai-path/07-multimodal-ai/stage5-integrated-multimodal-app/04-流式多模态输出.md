# 04 流式多模态输出——图文混排、语音流式输出的前端渲染

> 流式输出提升用户体验，多模态流式输出更复杂。

## 场景引入

你的多模态助手已经能处理文本、图片、语音、文档，但用户体验不好——每次点击"发送"后要等 5-8 秒才能看到完整回答，语音回答更是要等 10 秒以上。产品经理要求"边生成边显示"：文本逐字输出、图片嵌入到对应位置、语音流式播放。流式多模态输出的技术挑战在于：文本流、图片流、音频流三种不同类型的输出需要在前端协调渲染，任何一个流的延迟都会影响整体体验。

## 学习目标

- 掌握流式多模态输出的方法
- 理解图文混排的渲染
- 学会实现语音流式输出

## 一、流式文本输出

```python
async def stream_text_response(question: str):
    """流式文本输出"""
    stream = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": question}],
        stream=True
    )
    
    for chunk in stream:
        if chunk.choices[0].delta.content:
            yield chunk.choices[0].delta.content
```

async def stream_audio_response(text: str):

## 三、图文混排

```python
def render_multimodal_response(text: str, images: list) -> str:
    """渲染图文混排"""
    # Markdown 格式
    content = text
    
    for i, image in enumerate(images):
        content += f"\n\n![图片{i+1}]({image})"
    
    return content
```

## 常见误区

1. **只做文本流式输出不做多模态流式**：文本是流式的但图片和音频还是同步返回，用户体验仍然很差，需要三种流协调输出。
2. **不做流的同步和排序**：文本流、图片流、音频流各自独立输出，前端不知道图片应该插在哪里，需要统一的排序机制。
3. **忽略前端的渲染性能**：大量流式数据涌入会导致前端卡顿，需要做节流和批量渲染。
4. **不做流式输出的错误处理**：流式过程中某个环节失败（如图片生成失败），需要优雅降级而不是中断整个输出。

## 工程建议

1. **用 SSE 或 WebSocket 做流式传输**：SSE 适合单向推送，WebSocket 适合双向交互，根据场景选择合适的流式协议。
2. **定义统一的流式消息格式**：所有模态的流式输出用统一的消息格式（type, content, index, is_final），前端统一处理。
3. **前端做节流和批量渲染**：每 50-100ms 渲染一次，避免每次 chunk 都触发 DOM 更新导致卡顿。
4. **做流式中断和恢复**：用户可以随时中断流式输出，系统支持从断点恢复或重新生成。

## 参考答案

### 练习一：流式题——实现流式文本输出

**思路**：使用 OpenAI 的 stream 模式获取逐 chunk 的文本输出，通过 SSE（Server-Sent Events）推送到前端，实现"边生成边显示"的效果。

**答案**：
```python
from openai import OpenAI
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
import json

app = FastAPI()
client = OpenAI()

async def stream_text_generator(question: str):
    """流式文本生成器"""
    stream = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": question}],
        stream=True
    )

    for chunk in stream:
        if chunk.choices and chunk.choices[0].delta.content:
            content = chunk.choices[0].delta.content
            yield f"data: {json.dumps({'type': 'text', 'content': content})}\n\n"

    yield f"data: {json.dumps({'type': 'done'})}\n\n"

@app.post("/api/stream")
async def stream_endpoint(request: dict):
    """SSE 流式接口"""
    question = request.get("question", "")
    return StreamingResponse(
        stream_text_generator(question),
        media_type="text/event-stream",
        headers={"Cache-Control": "no-cache", "X-Accel-Buffering": "no"}
    )

# 前端 JavaScript
FRONTEND_CODE = """
async function streamChat(question) {
    const response = await fetch('/api/stream', {
        method: 'POST',
        headers: {'Content-Type': 'application/json'},
        body: JSON.stringify({ question })
    });

    const reader = response.body.getReader();
    const decoder = new TextDecoder();
    let fullText = '';

    while (true) {
        const { done, value } = await reader.read();
        if (done) break;

        const text = decoder.decode(value);
        const lines = text.split('\\n');

        for (const line of lines) {
            if (line.startsWith('data: ')) {
                const data = JSON.parse(line.slice(6));
                if (data.type === 'text') {
                    fullText += data.content;
                    document.getElementById('output').textContent = fullText;
                } else if (data.type === 'done') {
                    console.log('流式输出完成');
                }
            }
        }
    }
}
"""
```

**要点**：
- SSE 适合单向推送场景，比 WebSocket 更简单
- 前端需要逐行解析 `data:` 格式的消息，不能直接 `response.text()`
- 常见错误：不设置 `X-Accel-Buffering: no`，Nginx 会缓冲整个响应导致流式失效

### 练习二：语音题——实现流式语音输出

**思路**：先用 LLM 流式生成文本，再将文本 chunk 实时送入 TTS 引擎生成音频流，实现"边说边播"。

**答案**：
```python
import edge_tts
import asyncio
from fastapi import FastAPI
from fastapi.responses import StreamingResponse

app = FastAPI()

async def stream_audio_generator(text: str):
    """流式语音生成器"""
    communicate = edge_tts.Communicate(text, "zh-CN-XiaoxiaoNeural")

    async for chunk in communicate.stream():
        if chunk["type"] == "audio":
            yield chunk["data"]

async def stream_text_to_audio(question: str):
    """文本流式生成 + 实时转语音"""
    client = OpenAI()
    buffer = ""
    sentence_endings = {"。", "！", "？", "；", "\n"}

    stream = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": question}],
        stream=True
    )

    for chunk in stream:
        if chunk.choices and chunk.choices[0].delta.content:
            buffer += chunk.choices[0].delta.content

            # 遇到句号等断句符时生成一段语音
            if any(buffer.endswith(p) for p in sentence_endings):
                if buffer.strip():
                    async for audio_chunk in stream_audio_chunk(buffer.strip()):
                        yield audio_chunk
                    buffer = ""

    # 处理剩余文本
    if buffer.strip():
        async for audio_chunk in stream_audio_chunk(buffer.strip()):
            yield audio_chunk

async def stream_audio_chunk(text: str):
    """生成单段音频的字节流"""
    communicate = edge_tts.Communicate(text, "zh-CN-XiaoxiaoNeural")
    async for chunk in communicate.stream():
        if chunk["type"] == "audio":
            yield chunk["data"]

@app.post("/api/audio-stream")
async def audio_stream_endpoint(request: dict):
    """流式语音接口"""
    question = request.get("question", "")
    return StreamingResponse(
        stream_text_to_audio(question),
        media_type="audio/mpeg",
        headers={"Cache-Control": "no-cache"}
    )
```

**要点**：
- 按句子断句生成语音，避免把整段文本一次性送入 TTS 导致延迟过高
- edge-tts 是免费的云端 TTS，适合原型；生产环境可考虑本地 TTS（如 VITS）
- 常见错误：不对文本做断句处理，整段文本生成语音的延迟会非常高

### 练习三：界面题——创建多模态聊天界面

**思路**：使用 Gradio 快速搭建支持文本、图片、语音输入的多模态聊天界面，支持流式文本输出和语音播放。

**答案**：
```python
import gradio as gr
from openai import OpenAI

client = OpenAI()

def multimodal_chat(text, image, audio, history):
    """多模态聊天处理函数"""
    if history is None:
        history = []

    # 构建消息内容
    content = []
    if text:
        content.append({"type": "text", "text": text})

    if image:
        import base64
        with open(image, "rb") as f:
            img_base64 = base64.b64encode(f.read()).decode()
        content.append({
            "type": "image_url",
            "image_url": {"url": f"data:image/jpeg;base64,{img_base64}"}
        })

    if audio:
        import whisper
        model = whisper.load_model("base")
        result = model.transcribe(audio)
        content.append({"type": "text", "text": f"[语音内容] {result['text']}"})

    if not content:
        return history

    messages = [{"role": "system", "content": "你是一个多模态 AI 助手，可以理解文字、图片和语音。"}]
    for h in history:
        messages.append({"role": "user", "content": h[0]})
        messages.append({"role": "assistant", "content": h[1]})
    messages.append({"role": "user", "content": content})

    # 流式生成
    stream = client.chat.completions.create(
        model="gpt-4o",
        messages=messages,
        stream=True
    )

    history = history + [["", ""]]
    partial = ""
    for chunk in stream:
        if chunk.choices and chunk.choices[0].delta.content:
            partial += chunk.choices[0].delta.content
            history[-1] = [text or "(图片/语音输入)", partial]
            yield history

def build_interface():
    """构建 Gradio 界面"""
    with gr.Blocks(title="多模态 AI 助手") as demo:
        gr.Markdown("# 多模态 AI 助手")
        chatbot = gr.Chatbot(label="对话", height=400)

        with gr.Row():
            text_input = gr.Textbox(label="文字输入", placeholder="输入你的问题...", scale=3)
            image_input = gr.Image(label="图片上传", type="filepath", scale=1)
            audio_input = gr.Audio(label="语音输入", type="filepath", scale=1)

        submit_btn = gr.Button("发送", variant="primary")

        submit_btn.click(
            fn=multimodal_chat,
            inputs=[text_input, image_input, audio_input, chatbot],
            outputs=chatbot
        )

    return demo

demo = build_interface()
demo.launch(server_name="0.0.0.0", server_port=7860)
```

**要点**：
- Gradio 的 `yield` 机制天然支持流式更新，每次 yield 都会刷新界面
- 图片需要转为 base64 格式传给 OpenAI API，不能直接传文件路径
- 常见错误：历史消息格式不对（Gradio 要求 `[user, assistant]` 的二维数组），会导致界面渲染错误
