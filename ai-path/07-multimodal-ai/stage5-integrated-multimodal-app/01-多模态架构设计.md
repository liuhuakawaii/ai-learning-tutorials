# 多模态架构设计——统一输入层 / 模态路由 / 融合推理

> 课型：概念建模课
> 目标：理解多模态应用的架构分层，能设计可扩展的多模态系统

## 为什么需要架构设计

你要做一个支持文本、图片、语音、文档四种输入的 AI 助手。每种输入的处理方式完全不同：文本直接送 LLM，图片需要 Vision API，语音要先 ASR 再送 LLM，文档要先解析再提取。

如果为每种输入写一套独立的 if-else，代码会变成一团乱麻。如果设计一个统一架构，又要考虑扩展性——未来可能还要支持视频、3D 模型等新模态。

核心挑战：在统一性和灵活性之间找到平衡。

## 分层架构

```
输入层 → 模态识别 → 模态路由 → 模态处理 → 融合推理 → 输出层
```

每一层职责单一：
- **输入层**：接收各种格式的输入（文本、文件、URL、bytes）
- **模态识别**：判断输入是什么类型
- **模态路由**：把输入分发到对应的处理器
- **模态处理**：每种模态独立处理，输出标准化结果
- **融合推理**：综合多模态结果，生成最终回答

## 模态识别

识别输入类型不能只靠文件扩展名，要多层检测：

```python
def identify_modality(input_data) -> str:
    """多层检测输入模态"""
    # 第一层：类型检测
    if isinstance(input_data, str):
        if input_data.startswith(("http://", "https://")):
            # URL：检查扩展名
            ext = input_data.split(".")[-1].lower().split("?")[0]
            if ext in ("jpg", "jpeg", "png", "gif", "webp"):
                return "image_url"
            if ext in ("mp3", "wav", "m4a"):
                return "audio_url"
            return "url"
        return "text"

    if isinstance(input_data, bytes):
        # bytes：检查 magic bytes
        if input_data[:4] in (b'\xff\xd8\xff\xe0', b'\x89PNG'):
            return "image"
        if input_data[:4] == b'fLaC' or input_data[:3] == b'ID3':
            return "audio"
        return "bytes"

    if hasattr(input_data, "read"):
        # 文件对象：检查 content_type
        ct = getattr(input_data, "content_type", "")
        if "image" in ct:
            return "image"
        if "audio" in ct:
            return "audio"
        if "pdf" in ct:
            return "document"
        return "file"

    return "unknown"
```

## 模态路由：策略模式

不要用 if-else 硬编码所有模态逻辑。用策略模式，每种模态是一个独立的处理器，通过注册机制添加：

```python
from abc import ABC, abstractmethod


class ModalityHandler(ABC):
    @abstractmethod
    def can_handle(self, input_data) -> bool:
        pass

    @abstractmethod
    def process(self, input_data) -> dict:
        pass


class TextHandler(ModalityHandler):
    def can_handle(self, input_data):
        return isinstance(input_data, str) and not input_data.startswith("http")

    def process(self, input_data):
        return {"type": "text", "content": input_data, "tokens": len(input_data)}


class ImageHandler(ModalityHandler):
    def can_handle(self, input_data):
        if isinstance(input_data, str):
            return input_data.endswith((".jpg", ".jpeg", ".png", ".gif", ".webp"))
        return isinstance(input_data, bytes)

    def process(self, input_data):
        from PIL import Image
        if isinstance(input_data, str):
            image = Image.open(input_data).convert("RGB")
        else:
            import io
            image = Image.open(io.BytesIO(input_data)).convert("RGB")
        return {"type": "image", "data": image, "size": image.size}


class ModalityRouter:
    def __init__(self):
        self.handlers: list[ModalityHandler] = []

    def register(self, handler: ModalityHandler):
        self.handlers.append(handler)

    def route(self, input_data) -> dict:
        for handler in self.handlers:
            if handler.can_handle(input_data):
                return handler.process(input_data)
        raise ValueError(f"无法识别输入类型: {type(input_data)}")
```

新增模态只需写一个新的 Handler 并注册，核心代码不需要修改。

## 融合推理

多模态结果不能简单拼接。不同模态的置信度不同，可能给出矛盾信息：

```python
from openai import OpenAI


class FusionReasoner:
    def __init__(self):
        self.client = OpenAI()

    def fuse(self, modality_results: dict, question: str = "") -> dict:
        """融合多模态结果，处理冲突"""
        # 按置信度排序
        sorted_results = sorted(
            modality_results.items(),
            key=lambda x: x[1].get("confidence", 0.5),
            reverse=True,
        )

        context_parts = []
        for modality, result in sorted_results:
            confidence = result.get("confidence", 0.5)
            content = self._extract_content(result)
            context_parts.append(f"[{modality}] (置信度: {confidence:.2f}): {content}")

        context = "\n".join(context_parts)

        response = self.client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": f"""请融合以下多模态信息生成综合回答。

{f"问题：{question}" if question else ""}

多模态信息：
{context}

要求：
1. 优先采信置信度高的信息
2. 如果不同模态的信息存在冲突，以高置信度信息为准并说明冲突
3. 综合所有模态的信息给出完整回答"""}],
        )

        return {
            "answer": response.choices[0].message.content,
            "has_conflict": self._detect_conflict(modality_results),
        }

    def _extract_content(self, result: dict) -> str:
        if result["type"] == "text":
            return result.get("content", "")
        elif result["type"] == "audio":
            return f"[语音转文字] {result.get('transcript', '')}"
        elif result["type"] == "image":
            return f"[图片描述] {result.get('description', '已识别图片内容')}"
        return str(result)

    def _detect_conflict(self, results: dict) -> bool:
        """简单的冲突检测：文本和语音转写之间的一致性"""
        texts = []
        for _, r in results.items():
            if r["type"] in ("text", "audio"):
                texts.append(r.get("content", "") or r.get("transcript", ""))
        if len(texts) < 2:
            return False
        # 可以用 LLM 做更精确的一致性检测
        return False
```

## 可扩展性设计

```
扩展新模态的步骤：
1. 实现 ModalityHandler 子类
2. 在 Router 中注册
3. 在 FusionReasoner 中添加内容提取逻辑
4. 完成

不需要修改：输入层、模态识别层、核心路由逻辑
```

用插件化设计，每层都可以独立扩展。配置化路由（通过配置文件定义路由规则）比硬编码更灵活，但对小项目来说过度设计。5 种模态以内，直接注册就行。

## 容易犯的错

**用 if-else 硬编码所有模态逻辑**。每新增一种模态就要改多处代码，维护成本高且容易出错。用策略模式 + 注册机制。

**不做性能埋点**。多模态系统的链路长、延迟高，不做端到端的性能监控无法定位瓶颈。每层都要记录延迟。

**融合推理只是简单拼接**。把多模态结果简单拼接给 LLM，不做优先级排序和冲突处理，会导致生成质量下降。

## 参考答案

### 练习一

```python
class ModalityRouter:
    def __init__(self):
        self.handlers = []

    def register(self, handler):
        self.handlers.append(handler)

    def route(self, input_data):
        for handler in self.handlers:

```

注册顺序决定优先级——先注册的先匹配。如果需要更细粒度的优先级控制，可以给每个 Handler 加 `priority` 属性，按优先级排序后再匹配。

### 练习二

降级处理器不加载 CLIP 模型，只用 PIL 获取图片尺寸和格式。在 `ModalityRouter` 中，先尝试主处理器，捕获异常后尝试降级处理器。

### 练习三

用 `gpt-4o-mini` 做一致性检测（成本低、速度快）。Prompt 只需要问"以下两段信息是否一致"，返回 JSON `{"consistent": true/false}`。不一致时在最终回答中加一句"注意：语音输入和文本输入的信息存在差异"。
