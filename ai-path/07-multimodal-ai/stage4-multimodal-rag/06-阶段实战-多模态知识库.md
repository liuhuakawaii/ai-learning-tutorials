# 阶段实战——构建一个多模态知识库

> 课型：项目推进课
> 目标：把 CLIP Embedding、图文混合索引、跨模态检索、多模态 RAG 生成整合成一个完整的知识库系统

## 当前卡点

你要为公司构建一个多模态知识库：技术文档（纯文本）、产品手册（图文混排）、培训视频截图这三类内容需要统一入库，支持文字或图片查询。工程师上传一张报错截图，系统应该定位到故障排除手册的相关章节；产品经理搜"产品外观"，系统应该返回产品实拍图和设计说明。

卡在哪里：
- 不同类型文档的解析和索引策略完全不同
- 图文混合检索的排序逻辑比纯文本复杂得多
- LLM 生成回答时需要同时理解图片和文本上下文

## 系统设计

```
文档输入 → 类型判断 → 解析 → 图文分离 → 向量化 → 索引
                                              │
用户查询 → 向量化 → 混合检索 → RAG 生成 → 回答（含图片引用）
```

核心判断：
- **纯文本文档**：文本分块 → 文本 Embedding → 存入 Milvus
- **图文混排文档**：提取图片 + 附近文本 → 分别 Embedding → 存入 Milvus
- **视频截图**：OCR 提取文字 + 图片 Embedding → 存入 Milvus

## 文档入库

```python
from pathlib import Path
from pymilvus import MilvusClient
from openai import OpenAI

client = OpenAI()
milvus = MilvusClient(uri="http://localhost:19530")


def ingest_document(doc_path: str, doc_type: str):
    """将文档解析并入库"""
    if doc_type == "text":
        chunks = parse_text_document(doc_path)
        for i, chunk in enumerate(chunks):
            embedding = get_text_embedding(chunk["text"])
            milvus.insert("knowledge_base", [{
                "vector": embedding,
                "text": chunk["text"],
                "source": doc_path,
                "chunk_id": i,
                "content_type": "text",
            }])
    elif doc_type == "mixed":
        items = parse_mixed_document(doc_path)
        for item in items:
            if item["type"] == "text":
                embedding = get_text_embedding(item["text"])
            else:
                embedding = get_image_embedding(item["image_path"])
            milvus.insert("knowledge_base", [{
                "vector": embedding,
                "text": item.get("text", ""),
                "image_path": item.get("image_path", ""),
                "source": doc_path,
                "content_type": item["type"],
            }])
```

## 多模态检索

```python
import numpy as np
from transformers import CLIPProcessor, CLIPModel
from PIL import Image

clip_model = CLIPModel.from_pretrained("openai/clip-vit-base-patch32")
clip_processor = CLIPProcessor.from_pretrained("openai/clip-vit-base-patch32")


def get_text_embedding(text: str) -> list[float]:
    inputs = clip_processor(text=text, return_tensors="pt", padding=True, truncation=True)
    with __import__("torch").no_grad():
        features = clip_model.get_text_features(**inputs)
    features = features / features.norm(dim=-1, keepdim=True)
    return features.squeeze().numpy().tolist()


def get_image_embedding(image_path: str) -> list[float]:
    image = Image.open(image_path).convert("RGB")
    inputs = clip_processor(images=image, return_tensors="pt")
    with __import__("torch").no_grad():
        features = clip_model.get_image_features(**inputs)
    features = features / features.norm(dim=-1, keepdim=True)
    return features.squeeze().numpy().tolist()


def multimodal_search(query: str, query_type: str = "text", top_k: int = 5) -> list[dict]:
    """多模态检索：支持文本查询和图片查询"""
    if query_type == "text":
        query_vector = get_text_embedding(query)
    else:
        query_vector = get_image_embedding(query)

    results = milvus.search(
        collection_name="knowledge_base",
        data=[query_vector],
        limit=top_k,
        output_fields=["text", "image_path", "source", "content_type"],
    )
    return [r["entity"] for r in results[0]]
```

## RAG 生成

```python
def multimodal_rag(question: str) -> dict:
    """多模态 RAG：检索 + 生成"""
    # 检索
    results = multimodal_search(question, query_type="text", top_k=5)

    # 构建上下文
    context_parts = []
    image_refs = []
    for i, r in enumerate(results):
        if r["content_type"] == "text":
            context_parts.append(f"[文档 {i+1}] {r['text']}")
        else:
            context_parts.append(f"[图片 {i+1}] {r.get('text', '（图片内容）')}")
            image_refs.append(r.get("image_path", ""))

    context = "\n\n".join(context_parts)

    # 生成
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "system", "content": "基于以下检索到的文档回答问题。引用时标注文档编号。"},
            {"role": "user", "content": f"文档：\n{context}\n\n问题：{question}"},
        ],
    )

    return {
        "answer": response.choices[0].message.content,
        "sources": results,
        "image_refs": image_refs,
    }
```

## 增量更新

文档会更新，不能每次都全量重建索引：

```python
import hashlib


def get_content_hash(content: str) -> str:
    return hashlib.md5(content.encode()).hexdigest()


def incremental_ingest(doc_path: str, doc_type: str):
    """增量更新：只处理新增或变更的内容"""
    chunks = parse_text_document(doc_path) if doc_type == "text" else parse_mixed_document(doc_path)

    # 查询已有记录
    existing = milvus.query(
        collection_name="knowledge_base",
        filter=f'source == "{doc_path}"',
        output_fields=["chunk_id", "content_hash"],
    )
    existing_hashes = {r["chunk_id"]: r["content_hash"] for r in existing}

    for i, chunk in enumerate(chunks):
        content_hash = get_content_hash(chunk.get("text", ""))
        if existing_hashes.get(i) == content_hash:
            continue  # 未变更，跳过

        # 新增或更新
        embedding = get_text_embedding(chunk["text"]) if chunk.get("text") else get_image_embedding(chunk["image_path"])
        milvus.upsert("knowledge_base", [{
            "vector": embedding,
            "text": chunk.get("text", ""),
            "source": doc_path,
            "chunk_id": i,
            "content_hash": content_hash,
        }])
```

## 关键判断

**不同文档类型需要不同的解析策略**。纯文本用简单的分块就行，图文混排需要提取图片和附近文本的对应关系，视频截图需要 OCR。不要试图用一个统一的解析器处理所有类型。

**向量归一化是必须的**。CLIP 输出的向量必须 L2 归一化，否则相似度计算不准确。入库前归一化，查询时直接点积，比每次查询都算 norm 快得多。

**增量更新比全量重建重要**。文档会频繁更新，全量重建索引的时间和成本不可接受。用内容 hash 判断是否需要更新，只处理变更部分。

**图片引用比纯文本回答更有价值**。用户问"产品外观"时，返回一张产品图比返回 200 字描述更有用。RAG 生成时要把图片路径传递给前端。

## 参考答案

### 练习一

索引用 JSON 文件保存（{路径: 向量列表}），加载时转回 numpy 数组。图片格式只支持 jpg/png/webp/bmp，用 `Path.rglob` 遍历。每 50 张打印一次进度，方便排查大目录的索引问题。

### 练习二

英文查询的相似度通常比中文高 0.05-0.15，因为 CLIP 训练数据以英文为主。如果产品面向中文用户，用 Chinese-CLIP 或在查询时把中文翻译成英文再搜。

### 练习三

简单的规则路由：包含"图片""照片""外观""截图"→ image_search；包含"文档""说明""手册"→ text_search；其他 → qa。比用 LLM 判断快 100 倍，准确率在 80% 以上。不够准确时再升级为 LLM 路由。
