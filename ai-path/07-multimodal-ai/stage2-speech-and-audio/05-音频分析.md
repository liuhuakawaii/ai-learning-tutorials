# 05 音频分析——会议录音摘要、情感分析、说话人分离

> 音频分析让 AI 能理解和分析音频内容。

## 场景引入

你的公司每周有 50+ 场会议录音，管理层要求：自动提取每场会议的摘要和行动项、分析参会者的情绪倾向、识别不同说话人的发言内容。手动完成这些工作需要专人每场花 1-2 小时整理。你想用 AI 自动化，但发现：多人同时说话时语音识别效果很差、情绪分析的主观性强难以量化、说话人分离在音频质量差时错误率很高——音频分析比单纯的语音转文字复杂得多。

## 学习目标

- 掌握音频分析的方法
- 实现会议摘要、情感分析、说话人分离
- 学会处理各种音频场景

## 一、会议摘要

```python
def meeting_summary(audio_path: str) -> str:
    """会议摘要"""
    # 1. 语音识别
    transcript = transcribe_audio(audio_path)
    
    # 2. 生成摘要
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{
            "role": "user",
            "content": f"请为以下会议记录生成摘要，包括主要议题、决策和行动项：\n\n{transcript}"
        }]
    )
    return response.choices[0].message.content
```

## 三、说话人分离

```python
from pyannote.audio import Pipeline

def speaker_diarization(audio_path: str) -> list:
    """说话人分离"""
    # 加载模型
    pipeline = Pipeline.from_pretrained(
        "pyannote/speaker-diarization-3.1",
        use_auth_token="YOUR_TOKEN"
    )
    
    # 处理
    diarization = pipeline(audio_path)
    
    # 提取结果
    speakers = []
    for turn, _, speaker in diarization.itertracks(yield_label=True):
        speakers.append({
            "start": turn.start,
            "end": turn.end,
            "speaker": speaker
        })
    
    return speakers
```

## 常见误区

1. **把语音识别和音频分析混为一谈**：语音识别只是把语音转成文字，音频分析还需要在此基础上做摘要、情感分析、说话人分离等更高层的任务。
2. **忽略多人说话的场景**：会议录音通常有多人同时说话、交叉发言的情况，不做说话人分离直接识别会导致结果混乱。
3. **过度依赖情感分析的结果**：语音情感分析的准确率有限，语调、语速等特征受个人习惯影响大，结果只能作为参考而非决策依据。
4. **不做音频预处理就分析**：背景噪音、回声、音量不一致会严重影响分析质量，必须先做降噪和音量标准化。

## 工程建议

1. **Pipeline 化处理**：降噪 → 语音识别 → 说话人分离 → 文本分析（摘要/情感/关键词），每步独立可替换。
2. **说话人分离用专用模型**：pyannote.audio 是当前最好的开源说话人分离方案，比自己训练模型效果好且维护成本低。
3. **建立评估基准**：收集典型会议录音和人工标注的摘要/情感/说话人标签，量化评估每个环节的准确率。
4. **结果结构化存储**：将分析结果存为结构化数据（JSON），包含时间戳、说话人、情绪、关键词等字段，方便后续检索和统计。

## 参考答案

### 练习一：为一段会议录音生成摘要

**思路**：先用 Whisper 做语音转文字，再用 LLM 提取会议摘要、关键决策和行动项。

**答案**：

```python
"""会议录音摘要生成：ASR + LLM 两步 Pipeline。"""
import whisper
from openai import OpenAI


def generate_meeting_summary(audio_path: str) -> dict:
    """从会议录音生成结构化摘要。

    Returns:
        包含摘要、决策、行动项的字典
    """
    # 1. 语音识别
    model = whisper.load_model("base")
    result = model.transcribe(audio_path, language="zh")
    transcript = result["text"].strip()

    if not transcript:
        raise ValueError("音频中未检测到有效语音")

    # 2. 用 LLM 生成结构化摘要
    client = OpenAI()
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {
                "role": "system",
                "content": "你是一个专业的会议记录助手。请从会议记录中提取结构化信息。",
            },
            {
                "role": "user",
                "content": f"""请分析以下会议记录，输出 JSON 格式：

{{
  "summary": "会议摘要（100字以内）",
  "topics": ["议题1", "议题2"],
  "decisions": ["决策1", "决策2"],
  "action_items": [
    {{"task": "任务描述", "owner": "负责人", "deadline": "截止时间"}}
  ]
}}

会议记录：
{transcript}""",
            },
        ],
        response_format={"type": "json_object"},
        temperature=0.1,
    )

    import json
    summary = json.loads(response.choices[0].message.content)
    summary["transcript"] = transcript
    return summary


if __name__ == "__main__":
    result = generate_meeting_summary("meeting_recording.wav")
    print(f"摘要: {result['summary']}")
    print(f"议题: {result['topics']}")
    print(f"决策: {result['decisions']}")
    print(f"行动项: {result['action_items']}")
```

**要点**：
- prompt 中指定 JSON 输出格式，用 `response_format={"type": "json_object"}` 确保可解析
- `temperature=0.1` 让摘要结果更稳定，避免每次运行结果差异很大
- 长会议录音（>30分钟）需要先分段识别再拼接 transcript，否则 Whisper 可能丢失后半段内容
- 常见错误：不做 transcript 清洗就直接传给 LLM，识别错误会在摘要中被"合理化"，导致摘要包含不存在的内容

### 练习二：分析一段音频的情感

**思路**：先识别文字，再用 LLM 做文本情感分析，同时考虑语音特征（语速、音调）作为辅助信号。

**答案**：

```python
"""音频情感分析：结合文本和语音特征。"""
import whisper
import numpy as np
from openai import OpenAI


def analyze_audio_sentiment(audio_path: str) -> dict:
    """分析音频中的情感倾向。"""
    # 1. 语音识别
    model = whisper.load_model("base")
    result = model.transcribe(audio_path, language="zh")
    transcript = result["text"].strip()

    # 2. 提取语音特征（简化版：基于 segments 分析语速）
    segments = result["segments"]
    avg_duration = np.mean([s["end"] - s["start"] for s in segments]) if segments else 0
    avg_text_len = np.mean([len(s["text"]) for s in segments]) if segments else 0
    chars_per_second = avg_text_len / avg_duration if avg_duration > 0 else 0

    speech_rate = "正常"
    if chars_per_second > 5:
        speech_rate = "偏快（可能紧张或激动）"
    elif chars_per_second < 2:
        speech_rate = "偏慢（可能犹豫或低落）"

    # 3. 文本情感分析
    client = OpenAI()
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {
                "role": "user",
                "content": f"""请分析以下语音转写文本的情感，输出 JSON：

{{
  "overall_sentiment": "积极/消极/中性",
  "sentiment_score": 0到10的分数（10为最积极）,
  "emotions": ["检测到的情绪，如喜悦、愤怒、焦虑等"],
  "reasoning": "判断依据"

文本：{transcript}
语速特征：{speech_rate}（{chars_per_second:.1f} 字/秒）""",
            },
        ],
        response_format={"type": "json_object"},
        temperature=0.2,
    )

    import json
    sentiment = json.loads(response.choices[0].message.content)
    sentiment["transcript"] = transcript
    sentiment["speech_rate"] = speech_rate
    return sentiment


if __name__ == "__main__":
    result = analyze_audio_sentiment("sample_audio.wav")
    print(f"情感: {result['overall_sentiment']}")
    print(f"分数: {result['sentiment_score']}/10")
    print(f"情绪: {result['emotions']}")
    print(f"语速: {result['speech_rate']}")
    print(f"依据: {result['reasoning']}")
```

**要点**：
- 纯文本情感分析的准确率约 70-80%，加入语音特征（语速、停顿）可提升 5-10%
- 情感分析结果是主观判断，不能作为唯一决策依据，适合做初筛和辅助参考
- 中文情感表达含蓄，"还行吧"可能是积极也可能是消极，需要结合上下文判断
- 常见错误：把情感分析当作精确工具，对结果过度解读，实际上情感分析的 F1 分数通常只有 0.6-0.75

### 练习三：实现说话人分离

**思路**：使用 pyannote.audio 做说话人分离，将结果与 Whisper 识别结果对齐，生成每个说话人的发言内容。

**答案**：

```python
"""说话人分离 + 语音识别对齐。"""
import whisper
from pyannote.audio import Pipeline


def speaker_diarization_with_transcript(audio_path: str, hf_token: str) -> list:
    """说话人分离并与识别文本对齐。

    Args:
        audio_path: 音频文件路径
        hf_token: HuggingFace token（pyannote 模型需要授权）

    Returns:
        每个说话人片段的列表，包含时间、说话人和文字
    """
    # 1. 说话人分离
    diarization_pipeline = Pipeline.from_pretrained(
        "pyannote/speaker-diarization-3.1",
        use_auth_token=hf_token,
    )
    diarization = diarization_pipeline(audio_path)

    speaker_segments = []
    for turn, _, speaker in diarization.itertracks(yield_label=True):
        speaker_segments.append({
            "start": round(turn.start, 2),
            "end": round(turn.end, 2),
            "speaker": speaker,
        })

    # 2. 语音识别（带时间戳）
    model = whisper.load_model("base")
    result = model.transcribe(audio_path, language="zh", word_timestamps=True)

    # 3. 对齐：将识别文本分配到对应的说话人
    for whisper_seg in result["segments"]:
        seg_start = whisper_seg["start"]
        seg_end = whisper_seg["end"]
        seg_mid = (seg_start + seg_end) / 2

        # 找到包含这个时间点的说话人
        matched_speaker = "未知"
        for spk_seg in speaker_segments:
            if spk_seg["start"] <= seg_mid <= spk_seg["end"]:
                matched_speaker = spk_seg["speaker"]
                break

        whisper_seg["speaker"] = matched_speaker

    # 4. 汇总每个说话人的发言
    from collections import defaultdict
    speaker_texts = defaultdict(list)
    for seg in result["segments"]:
        speaker_texts[seg["speaker"]].append(seg["text"].strip())

    return {
        "segments": [
            {"speaker": s["speaker"], "start": s["start"], "end": s["end"], "text": s["text"]}
            for s in result["segments"]
        ],
        "speaker_summary": {
            speaker: " ".join(texts) for speaker, texts in speaker_texts.items()
        },
    }


if __name__ == "__main__":
    result = speaker_diarization_with_transcript(
        "meeting.wav",
        hf_token="YOUR_HUGGINGFACE_TOKEN",
    )

    print("=== 说话人发言汇总 ===")
    for speaker, text in result["speaker_summary"].items():
        print(f"\n[{speaker}]:")
        print(f"  {text[:100]}...")
```

**要点**：
- pyannote.audio 模型需要 HuggingFace 授权，必须先在 HuggingFace 上申请访问权限并获取 token
- 说话人分离和语音识别是两个独立的模型，对齐精度取决于时间戳的准确度
- 多人同时说话（overlapping speech）是最大的技术难点，当前所有方案的准确率都会显著下降
- 常见错误：不处理时间戳重叠的情况，导致同一段文字被分配给两个说话人
