## 从一段客服录音说起

你拿到一段 3 分钟的客服通话录音。普通话带点方言口音，背景有键盘声，中间有一段双方同时说话。

用 Whisper base 模型跑一遍，输出的文字里把"退款"识别成了"退换"，把客户说的"三天"识别成了"山田"。换成 Whisper large，准确率明显提升，但跑了 8 秒——如果这是实时对话场景，用户已经等得不耐烦了。

再试 SenseVoice，中文识别确实比同级别的 Whisper 好，但它对背景噪音更敏感。Azure Speech 的流式 API 延迟只有 200ms，但每月几千通录音的成本是 $500+。

没有完美的模型。选型要看你的场景里，什么错误能忍、什么不能忍。

## 主流 ASR 模型

```
模型            开源    中文    实时流式   延迟      适用场景
────────────────────────────────────────────────────────────
Whisper         ✓       好      ✗         慢(离线)  离线转写、字幕生成
SenseVoice      ✓       很好    ✓         快       中文实时交互
Azure Speech    ✗       好      ✓         很快     企业级实时场景
Google STT      ✗       好      ✓         很快     多语言实时场景
```

几个关键差异：

- **Whisper 不支持实时流式输入**。它是离线模型，必须等整段音频录完再处理。要实时场景，得用 Azure 或 SenseVoice
- **SenseVoice 是阿里开源的**，中文效果在同参数量下比 Whisper 好，而且支持实时流式
- **Azure/Google 是云服务**，准确率最高，但数据要出公司网络，而且按分钟计费
- **Whisper 模型大小影响巨大**：tiny 模型中文错误率可能 30%+，large 可以降到 10% 以内

## 实验：跑一遍对比

与其看参数表，不如拿你自己的音频跑一遍：

```python
import time
import json


def compare_whisper_models(audio_path: str):
    """对比不同大小的 Whisper 模型"""
    import whisper

    results = {}
    for model_name in ["tiny", "base", "medium"]:
        model = whisper.load_model(model_name)
        start = time.time()
        result = model.transcribe(audio_path, language="zh")
        elapsed = time.time() - start

        results[model_name] = {
            "text": result["text"],
            "time_seconds": round(elapsed, 2),
        }
        print(f"\n[{model_name}] 耗时 {elapsed:.1f}s")
        print(f"  {result['text'][:200]}")

    return results


def compare_with_api(audio_path: str):
    """对比 Whisper API（云端 large 模型）"""
    from openai import OpenAI

    client = OpenAI()
    start = time.time()
    with open(audio_path, "rb") as f:
        result = client.audio.transcriptions.create(
            model="whisper-1",
            file=f,
            language="zh",
            response_format="verbose_json",
        )
    elapsed = time.time() - start

    print(f"\n[Whisper API] 耗时 {elapsed:.1f}s")
    print(f"  {result.text[:200]}")
    print(f"  语言: {result.language}, 时长: {result.duration:.1f}s")
    return {"text": result.text, "time": elapsed}


if __name__ == "__main__":
    compare_whisper_models("test_audio.mp3")
    compare_with_api("test_audio.mp3")
```

跑完你会发现：
- tiny 和 base 的中文差距巨大，base 和 medium 的差距也不小
- API 版本（始终用 large 模型）质量最好，但要上传音频且按分钟计费
- 本地 large 模型需要 GPU，纯 CPU 会非常慢

## 选型决策

```
你的场景是什么？

离线转写（字幕、会议记录、客服分析）
  → Whisper large（本地部署，免费，质量好）
  → 音频量小且不想部署？→ Whisper API（$0.006/分钟）

实时交互（语音助手、实时字幕、同声传译）
  → 有预算？→ Azure Speech 流式 API（延迟 200ms，$1/小时）
  → 预算有限？→ SenseVoice（开源，中文实时优化）

中文为主 + 本地部署
  → SenseVoice（中文效果最好，支持实时）

多语言 + 不在乎延迟
  → Whisper large（语言支持最广）
```

## Whisper API 用法

最简单的集成方式，不需要 GPU：

```python
from openai import OpenAI

client = OpenAI()

with open("audio.mp3", "rb") as f:
    result = client.audio.transcriptions.create(
        model="whisper-1",
        file=f,
        language="zh",  # 指定语言避免误判
        response_format="verbose_json",  # 带时间戳
    )

print(result.text)
# 还可以拿到分段时间戳
for seg in result.segments:
    print(f"[{seg.start:.1f}s - {seg.end:.1f}s] {seg.text}")
```

注意 `language="zh"` 这个参数。不指定的话，中文音频偶尔会被误判为日文或韩文。指定了能避免这个问题。

## Whisper 本地部署

```python
import whisper

model = whisper.load_model("medium")  # base/medium/large-v3
result = model.transcribe("audio.mp3", language="zh", fp16=False)
print(result["text"])
```

模型大小选择：
- **tiny**：39M 参数，速度最快，中文很差，别用于生产
- **base**：74M 参数，中文勉强可用，适合实时性要求高的简单场景
- **medium**：769M 参数，中文不错，性价比最高
- **large-v3**：1550M 参数，中文最好，需要 GPU

## 本课要点

- 主流 ASR 四选一：Whisper（离线通用）、SenseVoice（中文实时）、Azure/Google（企业级实时）

- 实时场景 Whisper 不行，得用 SenseVoice 或 Azure
- API 调用务必指定 language 参数

## 参考答案

### 练习一

做完实验你会发现一个规律：tiny 模型的错误不是随机的——它倾向于把不认识的词替换成发音相似的常见词。这意味着错误是有模式的，理论上可以做后处理纠正。但更好的做法是直接用更大的模型。

### 练习二

```python
from openai import OpenAI


def transcribe_with_timestamps(audio_path: str) -> list[dict]:
    client = OpenAI()
    with open(audio_path, "rb") as f:
        result = client.audio.transcriptions.create(
            model="whisper-1",
            file=f,
            language="zh",
            response_format="verbose_json",
        )

    return [
        {"start": round(seg.start, 1), "end": round(seg.end, 1), "text": seg.text}
        for seg in result.segments
    ]
```

### 练习三

离线部署 + 方言 + 噪音 → Whisper large-v3 本地部署。

理由：
- 离线要求排除了所有云服务（Azure、Google、Whisper API）
- 方言场景需要大模型，tiny/base 的方言识别很差
- 噪音场景建议加一步音频预处理（降噪 + 音量标准化），再送 Whisper
- SenseVoice 中文更好但方言支持不一定比 Whisper large 好，需要实测

补充建议：在 Whisper 前加一个 VAD（Voice Activity Detection）步骤，去掉静音段和非人声段，可以提升识别准确率和速度。
