你的公司客服中心每天产生数千通录音，管理层希望从中提取关键信息：客户主要投诉哪些问题？哪些通话需要人工复核？平均通话时长是多少？你调研了 Whisper、SenseVoice、Azure Speech、Google Speech-to-Text 等方案，发现它们在中文识别准确率、实时处理能力、部署成本上差异巨大——选错方案可能导致识别错误率高达 20%，或者月度成本超出预算 10 倍。

## 常见误区

1. **认为 Whisper 对所有语言效果都一样好**：Whisper 在英文上表现优异，但中文识别效果取决于模型大小，tiny/base 模型的中文错误率较高，必须用 medium 或 large。
2. **忽略音频质量对识别结果的影响**：背景噪音、多人说话、麦克风质量差会大幅降低识别准确率，上线前必须在真实音频条件下测试。
3. **把实时识别和离线识别混为一谈**：Whisper 本身不支持实时流式识别，需要实时场景必须选择 Azure 或 Google 的流式 API。
4. **不做后处理直接使用识别结果**：语音识别的原始结果通常包含语气词、重复、断句错误，需要做清洗和标点修正后再使用。

## 工程建议

1. **按场景选择模型**：客服录音（中文为主）优先选 SenseVoice 或 Whisper large；多语言场景选 Whisper；实时交互选 Azure/Google 流式 API。
2. **建立音频预处理 Pipeline**：降噪 → 音量标准化 → 静音裁剪 → 格式转换，预处理质量直接影响识别准确率。
3. **做 A/B 测试量化对比**：用同一组真实音频测试不同模型，统计字符错误率（CER）和词错误率（WER），用数据驱动选型。
4. **预留模型升级接口**：语音识别模型迭代很快，抽象出统一的 ASR 接口，方便后续切换模型而不改动业务代码。

## 参考答案

### 练习一：对比不同语音识别模型

**思路**：从准确率、中文支持、实时识别能力、部署成本、适用场景五个维度进行横向对比，结合真实场景给出结论。

**答案**：

```python
"""
语音识别模型对比评估脚本
使用同一组音频文件测试不同模型的识别效果
"""
import time
import json


def compare_asr_models(audio_path: str) -> dict:
    """对比不同语音识别模型的识别结果和耗时。"""
    results = {}

    # 1. Whisper 本地（base 模型）
    import whisper
    model = whisper.load_model("base")
    start = time.time()
    whisper_result = model.transcribe(audio_path, language="zh")
    whisper_time = time.time() - start
    results["whisper_base"] = {
        "text": whisper_result["text"],
        "duration_seconds": round(whisper_time, 2),
        "language_detected": whisper_result["language"],
        "cost": "免费（本地 GPU）",
        "realtime_support": False,
    }

    # 2. Whisper API（云端 large 模型）
    from openai import OpenAI
    client = OpenAI()
    start = time.time()
    with open(audio_path, "rb") as f:
        api_result = client.audio.transcriptions.create(model="whisper-1", file=f)
    api_time = time.time() - start
    results["whisper_api"] = {
        "text": api_result.text,
        "duration_seconds": round(api_time, 2),
        "cost": "$0.006/分钟",
        "realtime_support": False,
    }

    # 3. 汇总对比
    comparison = {
        "results": results,
        "summary": {
            "whisper_base": "免费、离线可用，中文效果取决于模型大小",
            "whisper_api": "始终用 large 模型，质量最高，但需上传数据且按分钟计费",
        },
    }
    return comparison


if __name__ == "__main__":
    result = compare_asr_models("test_audio.mp3")
    print(json.dumps(result, ensure_ascii=False, indent=2))
```

**要点**：
- Whisper 在英文上 WER 约 5%，中文 WER 约 10-15%（large 模型），tiny/base 模型中文错误率可能超过 30%
- SenseVoice 中文优化效果好，但多语言支持不如 Whisper
- Azure/Google 的流式 API 延迟可控制在 200ms 以内，适合实时场景
- 常见错误：直接用 tiny 模型测试中文就下结论"Whisper 不行"，实际上 medium/large 的中文表现完全不同

### 练习二：使用 Whisper API 识别一段音频

**思路**：调用 OpenAI Whisper API 完成音频转文字，处理文件上传和结果解析。

**答案**：

```python
"""使用 Whisper API 识别音频文件。"""
from openai import OpenAI
from pathlib import Path


def transcribe_with_whisper_api(audio_path: str, language: str = "zh") -> dict:
    """调用 Whisper API 识别音频。

    Args:
        audio_path: 音频文件路径（支持 mp3/wav/m4a/webm 等格式）
        language: 音频语言代码，zh 表示中文

    Returns:
        包含识别文本和元信息的字典
    """
    client = OpenAI()
    audio_file = Path(audio_path)

    if not audio_file.exists():
        raise FileNotFoundError(f"音频文件不存在: {audio_path}")

    with open(audio_path, "rb") as f:
        response = client.audio.transcriptions.create(
            model="whisper-1",
            file=f,
            language=language,
            response_format="verbose_json",
        )

    return {
        "text": response.text,
        "language": response.language,
        "duration": response.duration,
        "segments": [
            {
                "start": seg.start,
                "end": seg.end,
                "text": seg.text,
            }
            for seg in response.segments
        ],
    }


if __name__ == "__main__":
    result = transcribe_with_whisper_api("test_audio.mp3")
    print(f"识别文本: {result['text']}")
    print(f"语言: {result['language']}")
    print(f"时长: {result['duration']:.1f} 秒")
    print(f"分段数: {len(result['segments'])}")
```

**要点**：
- 使用 `response_format="verbose_json"` 可获取时间戳和分段信息，比默认的纯文本更有用
- `language` 参数指定后可避免语言检测误判，中文音频务必指定 `language="zh"`
- API 文件大小限制 25MB，超大文件需要先压缩或分段
- 常见错误：不指定 language 参数导致中文音频被误识别为日文或韩文

### 练习三：为你的场景选择合适的语音识别模型

**思路**：根据业务场景的四个关键约束——数据隐私、实时性要求、预算、语言环境——逐步筛选，给出选型决策树。

**答案**：

选型决策分析：

| 场景 | 数据隐私 | 实时性 | 预算 | 推荐方案 |
|------|----------|--------|------|----------|
| 客服录音转文字（中文为主） | 敏感 | 不需要实时 | 有限 | Whisper large（本地部署） |
| 在线会议实时字幕 | 一般 | 必须实时 | 企业预算 | Azure Speech 流式 API |
| 多语言视频字幕生成 | 一般 | 不需要实时 | 有限 | Whisper medium（本地） |
| 嵌入式设备语音控制 | 敏感 | 必须实时 | 极低 | Whisper tiny（本地 CPU） |
| 中文语音助手 | 一般 | 需要实时 | 有限 | SenseVoice（本地部署） |

选型决策树：

```
是否需要实时识别？
├── 是 → 是否有企业预算？
│   ├── 是 → Azure Speech / Google STT 流式 API
│   └── 否 → SenseVoice（开源，中文实时优化）
└── 否 → 数据是否敏感？
    ├── 是 → Whisper 本地部署（medium 或 large）
    └── 否 → 音频量大吗？
        ├── 大 → Whisper 本地部署（避免 API 成本）
        └── 小 → Whisper API（快速集成，无需 GPU）
```

**要点**：
- 选型不能只看准确率，必须综合考虑隐私、延迟、成本三个约束
- 中文场景 SenseVoice 比同参数量的 Whisper 模型效果更好
- 实时场景的"实时"指的是流式处理能力，Whisper 本身不支持流式输入
- 常见错误：只在干净音频上做对比测试就选型，上线后遇到真实噪音环境准确率大幅下降
