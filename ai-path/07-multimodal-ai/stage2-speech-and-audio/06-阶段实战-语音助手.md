# 阶段实战：语音驱动的 AI 助手

> **项目类型**：项目推进课
> **前置**：完成 01-05 课
> **目标**：把 ASR（语音识别）、LLM（对话生成）、TTS（语音合成）串成一个能连续对话的语音助手

## 当前卡点

你会 Whisper 转写、会 LLM 对话、会 Edge-TTS 合成。但把三步串起来之后，问题来了：

**延迟**。用户说完一句话，Whisper 要 2-3 秒转写，LLM 要 1-2 秒生成，TTS 要 1 秒合成。用户等 5 秒才听到回复——这在对话场景里体验很差。

**对话连贯性**。用户说了"打开客厅灯"，助手回复"好的"。用户接着说"太暗了"，助手不知道"太暗了"是指刚才的灯，还是说别的东西。

**错误恢复**。Whisper 识别错了怎么办？用户说"把温度调到 26 度"，识别成了"把温度调到 20 度"，助手直接执行了。

这三个问题是把三个独立组件变成一个可用系统的核心工程挑战。

## 系统设计

```
用户说话
  │
  ▼
[Whisper ASR] ── 语音转文字（2-3s）
  │
  ▼
[对话管理] ── 维护上下文、纠错
  │
  ▼
[LLM 生成] ── 生成回复（1-2s）
  │
  ▼
[Edge-TTS] ── 文字转语音（1s）
  │
  ▼
语音播放
```

降低感知延迟的关键技巧：**不要等 LLM 全部生成完再 TTS**。LLM 流式输出第一个句子时就开始 TTS 合成，用户可以提前 1-2 秒听到回复的开头。

## 核心实现

```python
import asyncio
import whisper
import edge_tts
from openai import OpenAI
from pathlib import Path


class VoiceAssistant:
    def __init__(self, whisper_model: str = "base"):
        self.asr = whisper.load_model(whisper_model)
        self.llm = OpenAI()
        self.conversation: list[dict] = [
            {"role": "system", "content": "你是一个智能家居助手。回复要简短，口语化，不超过 3 句话。"}
        ]
        self.audio_dir = Path("audio_output")
        self.audio_dir.mkdir(exist_ok=True)

    async def process(self, audio_path: str) -> str:
        """完整处理流程：语音 → 文字 → 回复 → 语音"""
        # ASR
        user_text = self._transcribe(audio_path)
        if not user_text.strip():
            return ""

        # 对话管理
        self.conversation.append({"role": "user", "content": user_text})

        # LLM 生成
        reply = self._generate_reply()

        # TTS 合成
        output_path = str(self.audio_dir / "reply.mp3")
        await self._synthesize(reply, output_path)

        return reply

    def _transcribe(self, audio_path: str) -> str:
        result = self.asr.transcribe(audio_path, language="zh", fp16=False)
        return result["text"]

    def _generate_reply(self) -> str:
        response = self.llm.chat.completions.create(
            model="gpt-4o-mini",  # 对话用 mini 够了，省成本
            messages=self.conversation,
            max_tokens=200,  # 限制回复长度
        )
        reply = response.choices[0].message.content
        self.conversation.append({"role": "assistant", "content": reply})
        return reply

    async def _synthesize(self, text: str, output_path: str):
        communicate = edge_tts.Communicate(text, "zh-CN-XiaoxiaoNeural")
        await communicate.save(output_path)
```

几个设计判断：

- **对话用 gpt-4o-mini**：智能家居助手的回复不需要复杂推理，mini 够用，延迟更低、成本更低
- **max_tokens=200**：限制回复长度。语音助手的回复应该简短——用户不想听 30 秒的长篇大论
- **Whisper 用 base 模型**：实时场景优先速度。如果准确率不够再换 medium

## 对话管理：让助手记住上下文

简单对话不需要复杂状态管理，但要做两件事：

```python
def trim_conversation(self, max_turns: int = 10):
    """裁剪对话历史，防止 token 超限"""
    # 保留 system prompt + 最近 N 轮对话
    system = self.conversation[0]
    recent = self.conversation[-(max_turns * 2):]
    self.conversation = [system] + recent

def handle_clarification(self, user_text: str, asr_text: str) -> str:
    """当 ASR 识别结果不确定时，主动确认"""
    # Whisper 没有返回置信度，但可以通过特征判断
    # 比如：全是数字的识别结果通常比较可靠，包含生僻词的不太可靠
    if len(asr_text) < 2:
        return "抱歉，我没听清，能再说一遍吗？"
    return asr_text
```

## 用 Gradio 做 Web 界面

```python
import gradio as gr

assistant = VoiceAssistant()


async def voice_chat(audio_path):
    if audio_path is None:
        return None, "请先录音"

    reply = await assistant.process(audio_path)
    return str(assistant.audio_dir / "reply.mp3"), reply


demo = gr.Interface(
    fn=voice_chat,
    inputs=gr.Audio(sources="microphone", type="filepath"),
    outputs=[gr.Audio(type="filepath"), gr.Textbox(label="助手回复")],
    title="语音助手",
    description="按住录音，松开后助手会语音回复",
)

demo.launch()
```

## 降低延迟的几个手段

| 手段 | 效果 | 代价 |
|------|------|------|
| Whisper base → tiny | ASR 快 3 倍 | 准确率下降 |
| GPT-4o → GPT-4o-mini | LLM 快 2 倍 | 推理能力下降 |
| 限制 max_tokens | 生成更快 | 回复更短 |
| LLM 流式 + TTS 流式 | 感知延迟降 50% | 实现复杂度高 |
| 音频预裁剪静音 | ASR 快 30% | 需要 VAD 模块 |

最有效的组合：Whisper base + gpt-4o-mini + max_tokens=200 + 流式输出。端到端延迟可以控制在 3 秒以内。

## 本课要点

- ASR + LLM + TTS 串起来的核心挑战是延迟、对话连贯性、错误恢复
- 降低感知延迟的关键是流式处理——LLM 输出第一句就开始 TTS
- 对话管理不需要复杂框架，维护一个消息列表 + 定期裁剪就够了
- 语音助手的回复要简短，限制 max_tokens 比调模型更重要

```python
async def summarize_and_trim(self, max_turns: int = 10):
    """对话过长时压缩历史"""
    if len(self.conversation) <= max_turns * 2 + 1:
        return

    system = self.conversation[0]
    old_messages = self.conversation[1:-(max_turns * 2)]
    recent_messages = self.conversation[-(max_turns * 2):]

    # 用 mini 模型生成摘要
    summary_response = self.llm.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "把以下对话压缩成一段简洁的摘要，保留关键信息和用户偏好。"},
            {"role": "user", "content": str(old_messages)}
        ],
        max_tokens=200,
    )
    summary = summary_response.choices[0].message.content

    self.conversation = [
        system,
        {"role": "system", "content": f"之前的对话摘要：{summary}"},
        *recent_messages,
    ]
```
