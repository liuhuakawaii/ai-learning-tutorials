# 06 阶段实战——构建一个语音驱动的 AI 助手

## 场景引入

你接到任务要构建一个完整的语音驱动 AI 助手：用户可以用语音提问，系统用语音回答，支持连续对话。这个助手将用于一个智能家居场景——用户躺在床上用语音控制灯光、查询天气、设定闹钟。你需要把 Whisper（语音识别）、GPT-4o（对话生成）、Edge-TTS（语音合成）三个独立组件整合成一个流畅的端到端系统，同时处理好延迟、错误恢复和对话连贯性。

## 学习目标

- 构建语音驱动的 AI 助手
- 集成 ASR、LLM、TTS
- 输出一个可运行的语音对话系统

## 二、完整实现

```python
class VoiceAssistant:
    """语音助手"""
    
    def __init__(self):
        self.asr = whisper.load_model("base")
        self.llm = OpenAI()
        self.conversation = []
    
    def process(self, audio_path: str) -> str:
        """处理语音"""
        # ASR
        text = self.asr.transcribe(audio_path)["text"]
        
        # LLM
        self.conversation.append({"role": "user", "content": text})
        response = self.llm.chat.completions.create(
            model="gpt-4o",
            messages=self.conversation
        )
        reply = response.choices[0].message.content
        self.conversation.append({"role": "assistant", "content": reply})
        
        # TTS
        asyncio.run(self._synthesize(reply))
        
        return reply
    
    async def _synthesize(self, text: str):
        """语音合成"""
        await edge_tts.Communicate(text, "zh-CN-XiaoxiaoNeural").save("reply.mp3")
```

## 三、Web 界面

```python
import gradio as gr

def voice_chat(audio):
    assistant = VoiceAssistant()
    reply = assistant.process(audio)
    return "reply.mp3", reply

demo = gr.Interface(
    fn=voice_chat,
    inputs=gr.Audio(sources="microphone", type="filepath"),
    outputs=[gr.Audio(type="filepath"), gr.Textbox()]
)

demo.launch()
```

## 常见误区

1. **把三个组件简单串联就认为完成了**：ASR + LLM + TTS 的简单串联延迟会很高，需要做流式优化、并发处理、错误重试等工程化工作。
2. **不做异常处理**：Whisper 识别失败、GPT-4o 超时、Edge-TTS 网络异常等情况在生产环境很常见，必须做完善的异常处理和降级策略。
3. **忽略对话历史的管理**：对话历史越来越长会导致 LLM 延迟增加和成本上升，需要做历史裁剪和摘要压缩。
4. **不做唤醒词检测**：没有唤醒词的话系统会把所有声音都当成指令，导致误触发，生产环境必须集成唤醒词检测。

## 工程建议

1. **用异步架构设计系统**：ASR、LLM、TTS 三步用异步 Pipeline 串联，LLM 流式输出时就开始 TTS 合成，大幅降低感知延迟。
2. **实现优雅的错误恢复**：每个环节失败时给用户友好的提示（"抱歉没听清"、"我理解的是..."），而不是静默失败。
3. **做好对话状态管理**：维护对话上下文、用户偏好、当前任务状态，支持多轮对话和任务切换。
4. **建立端到端测试**：从语音输入到语音输出的完整链路测试，覆盖正常场景、异常场景、边界条件，确保系统稳定性。
