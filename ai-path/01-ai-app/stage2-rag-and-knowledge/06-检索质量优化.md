## 场景引入

你的 RAG 系统在测试时效果不错，但上线后用户反馈："我问'怎么退货'，结果检索出来的全是'退换货须知'的开头部分，真正的退货流程反而没出来。" 你去分析，发现两个问题：一是用户的问题太简短（"怎么退货"），和文档中的表述（"商品退货退款流程"）有语义鸿沟；二是向量检索虽然找到了大致相关的文档，但排序不对，最相关的排在了后面。这时候你需要 query rewrite 来扩展查询、rerank 来重排序——这就是检索质量优化要解决的问题。

## 一、检索质量为什么重要

### 1.1 垃圾进，垃圾出

```
检索质量 → 上下文质量 → 回答质量

  检索到无关内容 → 模型基于无关内容回答 → 回答不准确
  检索到相关内容 → 模型基于相关内容回答 → 回答准确

  RAG 的瓶颈往往在检索，不在模型。
```

## 二、Query Rewrite（查询改写）

### 2.1 什么是 Query Rewrite

```
原始查询："怎么退货？"

问题：
  - 太简短，缺少上下文
  - 可能匹配到"退货"但不匹配"退款"

改写后的查询：
  "如何申请商品退货退款，需要什么条件和流程"

优势：
  - 更完整，包含更多关键词
  - 更容易匹配到相关文档
```

### 2.2 使用模型改写查询

```typescript
// lib/query-rewrite.ts
import OpenAI from 'openai'

const openai = new OpenAI()

export async function rewriteQuery(originalQuery: string): Promise<string> {
  const response = await openai.responses.create({
    model: 'gpt-5.5',
    input: [
      {
        role: 'system',
        content: `你是一个搜索查询优化助手。请将用户的简短查询改写为更完整、更适合搜索的形式。

规则：
1. 保持原始意图不变
2. 添加相关同义词
3. 扩展为更完整的句子
4. 不要添加不存在的信息`
      },
      {
        role: 'user',
        content: `原始查询：${originalQuery}

请改写为更适合搜索的形式：`
      }
    ],
    temperature: 0.3,
    max_output_tokens: 100,
  })

  return response.output_text || originalQuery
}

// 使用
const originalQuery = "怎么退货"
const rewrittenQuery = await rewriteQuery(originalQuery)
// "如何申请商品退货退款，需要满足什么条件，具体流程是什么"
```

## 三、Rerank（重排序）

### 3.1 什么是 Rerank

```
初始检索（向量相似度）：
  结果 1: 相似度 0.85 - "退款政策..."
  结果 2: 相似度 0.82 - "退货流程..."
  结果 3: 相似度 0.80 - "购买须知..."
  结果 4: 相似度 0.78 - "售后服务..."
  结果 5: 相似度 0.75 - "联系我们..."

Rerank（更精细的相关性评估）：
  结果 1: 相关性 0.95 - "退货流程..."  ← 排名上升
  结果 2: 相关性 0.90 - "退款政策..."
  结果 3: 相关性 0.60 - "售后服务..."
  结果 4: 相关性 0.40 - "购买须知..."  ← 排名下降
  结果 5: 相关性 0.20 - "联系我们..."
```

### 3.2 使用模型 Rerank

```typescript
// lib/rerank.ts
import OpenAI from 'openai'

const openai = new OpenAI()

interface RerankResult {
  content: string
  metadata: any
  relevanceScore: number
}

export async function rerank(
  query: string,
  documents: { content: string; metadata: any }[],
  topK: number = 3
): Promise<RerankResult[]> {
  // 构建 rerank prompt
  const documentList = documents
    .map((doc, i) => `[${i + 1}] ${doc.content.slice(0, 300)}`)
    .join('\n\n')

  const response = await openai.responses.create({
    model: 'gpt-5.5',
    input: [
      {
        role: 'system',
        content: `你是一个文档相关性评估助手。请评估每个文档与查询的相关性。

输出 JSON 格式：
{
  "rankings": [
    {"index": 1, "relevance": 0.95},
    {"index": 2, "relevance": 0.80},
    ...
  ]
}

relevance 范围 0-1，1 表示完全相关。`
      },
      {
        role: 'user',
        content: `查询：${query}

文档列表：
${documentList}

请评估每个文档的相关性并排序。`
      }
    ],
    text: { format: { type: 'json_object' } },
    temperature: 0,
  })

  const result = JSON.parse(response.output_text || '{"rankings":[]}')
  const rankings = result.rankings || []

  // 按相关性排序并返回
  return rankings
    .sort((a: any, b: any) => b.relevance - a.relevance)
    .slice(0, topK)
    .map((r: any) => ({
      ...documents[r.index - 1],
      relevanceScore: r.relevance,
    }))
}
```

## 四、混合检索

### 4.1 向量检索 vs 关键词检索

```
┌─────────────────────────────────────────────────────────────────┐
│                向量检索 vs 关键词检索                             │
├─────────────────────┬──────────────────────┬────────────────────┤
│  维度                │  向量检索            │  关键词检索         │
├─────────────────────┼──────────────────────┼────────────────────┤
│  原理                │  语义相似度          │  关键词匹配         │
│  "退货" → "退款"     │  ✅ 能匹配           │  ❌ 不能匹配        │
│  "Python" → "Python" │  ✅ 能匹配           │  ✅ 能匹配          │
│  精确匹配            │  一般                │  好                 │
│  语义理解            │  好                  │  差                 │
└─────────────────────┴──────────────────────┴────────────────────┘

混合检索 = 向量检索 + 关键词检索
  兼顾语义理解和精确匹配
```

### 4.2 实现混合检索

```typescript
// lib/hybrid-search.ts
import { getEmbedding } from './embedding'
import { cosineSimilarity } from './similarity'

interface Document {
  id: string
  content: string
  embedding: number[]
  metadata: any
}

interface SearchResult {
  document: Document
  vectorScore: number
  keywordScore: number
  combinedScore: number
}

export async function hybridSearch(
  query: string,
  documents: Document[],
  options: {
    topK?: number
    vectorWeight?: number
    keywordWeight?: number
  } = {}
): Promise<SearchResult[]> {
  const {
    topK = 5,
    vectorWeight = 0.7,
    keywordWeight = 0.3,
  } = options

  // 1. 向量检索
  const queryEmbedding = await getEmbedding(query)
  const vectorResults = documents.map(doc => ({
    document: doc,
    vectorScore: cosineSimilarity(queryEmbedding, doc.embedding),
  }))

  // 2. 关键词检索（BM25 简化版）
  const queryTerms = query.toLowerCase().split(/\s+/)
  const keywordResults = documents.map(doc => {
    const content = doc.content.toLowerCase()
    let score = 0

    for (const term of queryTerms) {
      // 计算词频
      const regex = new RegExp(term, 'gi')
      const matches = content.match(regex)
      if (matches) {
        score += matches.length
      }
    }

    // 归一化
    score = score / (queryTerms.length * 10)

    return {
      document: doc,
      keywordScore: Math.min(score, 1),
    }
  })

  // 3. 合并分数
  const combined = vectorResults.map((vr, i) => ({
    document: vr.document,
    vectorScore: vr.vectorScore,
    keywordScore: keywordResults[i].keywordScore,
    combinedScore:
      vr.vectorScore * vectorWeight +
      keywordResults[i].keywordScore * keywordWeight,
  }))

  // 4. 排序并返回
  return combined
    .sort((a, b) => b.combinedScore - a.combinedScore)
    .slice(0, topK)
}
```

## 五、完整的优化检索流程

```typescript
// lib/optimized-retrieval.ts
import { rewriteQuery, generateSubQueries } from './query-rewrite'
import { rerank } from './rerank'
import { hybridSearch } from './hybrid-search'

export async function optimizedRetrieval(
  query: string,
  documents: any[],
  options: {
    useQueryRewrite?: boolean
    useRerank?: boolean
    useHybrid?: boolean
    topK?: number
  } = {}
) {
  const {
    useQueryRewrite = true,
    useRerank = true,
    useHybrid = true,
    topK = 5,
  } = options

  let searchQuery = query

  // 1. 查询改写
  if (useQueryRewrite) {
    searchQuery = await rewriteQuery(query)
  }

  // 2. 检索
  let results
  if (useHybrid) {
    results = await hybridSearch(searchQuery, documents, { topK: topK * 2 })
  } else {
    // 仅向量检索
    // ...
  }

  // 3. Rerank
  if (useRerank && results.length > topK) {
    results = await rerank(query, results, topK)
  }

  return results.slice(0, topK)
}
```

## 六、检索质量评估

### 6.1 评估指标

```typescript
interface RetrievalEvaluation {
  // 是否检索到了正确答案
  answerFound: boolean

  // 正确答案的排名
  answerRank: number

  // 检索结果的相关性
  relevanceScores: number[]
}

function evaluateRetrieval(
  query: string,
  expectedAnswer: string,
  searchResults: { content: string }[]
): RetrievalEvaluation {
  // 简单的关键词匹配评估
  const answerKeywords = expectedAnswer.toLowerCase().split(/\s+/)

  let answerFound = false
  let answerRank = -1
  const relevanceScores: number[] = []

  for (let i = 0; i < searchResults.length; i++) {
    const content = searchResults[i].content.toLowerCase()

    // 计算关键词匹配数
    const matchCount = answerKeywords.filter(kw => content.includes(kw)).length
    const relevance = matchCount / answerKeywords.length

    relevanceScores.push(relevance)

    if (relevance > 0.5 && !answerFound) {
      answerFound = true
      answerRank = i + 1
    }
  }

  return { answerFound, answerRank, relevanceScores }
}
```

### 6.2 A/B 测试

```typescript
// 对比不同检索策略的效果
async function compareRetrievalStrategies(
  testCases: { query: string; expectedAnswer: string }[]
) {
  const strategies = [
    { name: 'vector-only', useHybrid: false, useRerank: false },
    { name: 'hybrid', useHybrid: true, useRerank: false },
    { name: 'hybrid+rerank', useHybrid: true, useRerank: true },
  ]

  const results: Record<string, { found: number; avgRank: number }> = {}

  for (const strategy of strategies) {
    let found = 0
    let totalRank = 0

    for (const testCase of testCases) {
      const searchResults = await optimizedRetrieval(
        testCase.query,
        documents,
        strategy
      )

      const eval_ = evaluateRetrieval(
        testCase.query,
        testCase.expectedAnswer,
        searchResults
      )

      if (eval_.answerFound) {
        found++
        totalRank += eval_.answerRank
      }
    }

    results[strategy.name] = {
      found,
      avgRank: found > 0 ? totalRank / found : 0,
    }
  }

  return results
}
```

### 练习一

**思路**：Query Rewrite 的核心是把简短、模糊的用户查询扩展为更完整、包含同义词的查询，从而提高检索的召回率。用 LLM 改写查询，保持原始意图不变的同时补充语义相近的表述。

- 改写要保持原始意图不变，不能引入不相关的同义词

### 练习二

- 常见错误：直接用大模型做 Rerank 导致延迟和成本过高，应该先用向量检索缩小候选集

### 练习三

```typescript
  // 评测集
  const testCases = [
    { query: '怎么退货', expectedKeywords: ['退货', '退款', '流程'] },
    { query: 'Python 装包', expectedKeywords: ['pip', 'install', '包'] },
    { query: '数据库优化', expectedKeywords: ['索引', '查询', '优化'] },
    { query: 'React 状态管理', expectedKeywords: ['state', 'Redux', 'Zustand'] },
    { query: '部署项目', expectedKeywords: ['Docker', '部署', '服务器'] },
  ]

  const strategies = [
    { name: '纯向量检索', useHybrid: false, useRerank: false },
    { name: '混合检索', useHybrid: true, useRerank: false },
    { name: '混合检索+Rerank', useHybrid: true, useRerank: true },
  ]

  const results: Record<string, { hitRate: number; avgRank: number }> = {}

  for (const strategy of strategies) {
    let hits = 0
    let totalRank = 0

    for (const testCase of testCases) {
      // 执行检索（简化示意）
      const searchResults = await optimizedRetrieval(
        testCase.query,
        documents,
        strategy
      )

      // 检查期望关键词是否出现在 TopK 中
      let found = false
      for (let i = 0; i < searchResults.length; i++) {
        const content = searchResults[i].content.toLowerCase()
        const matchCount = testCase.expectedKeywords.filter(kw =>
          content.includes(kw.toLowerCase())
        ).length

        if (matchCount >= testCase.expectedKeywords.length * 0.5) {
          found = true
          totalRank += i + 1
          break
        }
      }

      if (found) hits++
    }

    results[strategy.name] = {
      hitRate: hits / testCases.length,
      avgRank: hits > 0 ? totalRank / hits : 0,
    }
  }

  // 输出对比结果
  console.log('=== 策略对比 ===')
  console.log('策略                | 命中率  | 平均排名')
  console.log('--------------------|---------|--------')
  for (const [name, stats] of Object.entries(results)) {
    console.log(`${name.padEnd(20)}| ${(stats.hitRate * 100).toFixed(0).padStart(5)}%  | ${stats.avgRank.toFixed(1)}`)
  }
}

compareStrategies()
```

预期输出示例：
```
策略                | 命中率  | 平均排名
--------------------|---------|--------
纯向量检索          |   60%   | 2.3
混合检索            |   80%   | 1.8
混合检索+Rerank     |   90%   | 1.2
```

**要点**：
- 混合检索兼顾语义理解和精确匹配，通常比纯向量检索效果好
- Rerank 在混合检索基础上进一步提升排序质量
- 常见错误：只凭感觉判断效果，不用数据说话；评测集太小（<10 条）导致结论不可靠

---

## 常见误区

1. **不区分优化目标就盲目加优化手段**：Query Rewrite 提高召回率，Rerank 提高精确率，混合检索兼顾两者。应该先用评测数据确定当前系统的瓶颈是召回不足还是精确率不够，再针对性地选择优化手段。

2. **Query Rewrite 引入过多噪声**：改写后的查询如果加入了不相关的同义词，反而会检索到无关内容。改写应该保持原始意图不变，只补充语义相近的表述，不要过度扩展。

3. **Rerank 用大模型成本太高**：用 GPT-4 做 Rerank 效果好但成本高、延迟大。对于高频查询，应该使用专用的 Rerank 模型（如 Cohere Rerank），成本低一个数量级，延迟也更可控。

4. **只看整体指标，不分析失败案例**：平均召回率 90% 看起来不错，但可能有 10% 的查询完全检索不到相关内容。应该逐条分析失败案例，找到共性问题（如特定类型的查询、特定领域的文档），针对性优化。

---

## 工程建议

1. **检索优化的优先级：先改 chunk 策略，再加 query rewrite，最后上 rerank**：chunk 策略是基础，如果 chunk 本身切得不好，后面加再多优化手段都是治标不治本。先确保 chunk 质量过关，再考虑检索层面的优化。

2. **Query Rewrite 和 Rerank 都会增加延迟**：每次查询额外调用 1-2 次 LLM，延迟可能增加 1-2 秒。对于实时问答场景，可以只在首次查询或低置信度查询时启用优化，高频问题走缓存。

3. **混合检索的权重需要实验调优**：向量检索和关键词检索的权重（如 0.7:0.3）没有万能值，取决于你的文档特点。如果文档中专有名词多（如产品名、错误码），关键词权重应该更高。

4. **建立评测驱动的优化循环**：准备 50-100 条评测样本，包含"应该检索到"和"不应该检索到"两类。每次调整策略后跑评测，用命中率、平均排名、误检率三个指标衡量效果。不要凭感觉调参。

---

## 小结

本课的核心要点：

1. **Query Rewrite**：扩展查询，添加同义词，提高召回率
2. **Rerank**：用更精细的模型重排序，提高精确率
3. **混合检索**：向量 + 关键词，兼顾语义和精确匹配
4. **质量评估**：A/B 测试不同策略，持续优化
5. **RAG 的瓶颈在检索**：优化检索是提升 RAG 质量的关键
