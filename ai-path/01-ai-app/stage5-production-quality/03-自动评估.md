## 场景引入

你有了 50 条评估用例，每次改完 Prompt 都手动跑一遍。一开始还能坚持，两周后就开始偷懒——"这次改动很小，应该没问题吧"，直接跳过评估上线了。结果这次改动恰好影响了拒答逻辑，用户问了一个敏感问题，系统没有拒答而是编造了一个答案。手动评估不可持续，你需要一套自动化的评估流水线：改完代码，跑一个命令，几秒钟就知道质量有没有退步。

## 二、规则评估

### 2.1 基于规则的检查

```typescript
// lib/evals/rules.ts
interface RuleResult {
  passed: boolean
  rule: string
  details?: string
}

export function applyRules(
  testCase: EvalCase,
  response: { answer: string; citations: string[] }
): RuleResult[] {
  const results: RuleResult[] = []

  // 规则 1：拒答场景必须拒答
  if (testCase.expectedBehavior === 'refuse') {
    const refused = checkRefusal(response.answer)
    results.push({
      passed: refused,
      rule: '拒答检查',
      details: refused ? '正确拒答' : '应该拒答但没有',
    })
  }

  // 规则 2：必须有引用
  if (testCase.expectedCitations && testCase.expectedCitations.length > 0) {
    const hasCitations = response.citations.length > 0
    results.push({
      passed: hasCitations,
      rule: '引用检查',
      details: hasCitations ? '包含引用' : '缺少引用',
    })
  }

  // 规则 3：回答长度检查
  const minLength = 20
  const maxLength = 2000
  const lengthOk = response.answer.length >= minLength && response.answer.length <= maxLength
  results.push({
    passed: lengthOk,
    rule: '长度检查',
    details: `回答长度 ${response.answer.length}，要求 ${minLength}-${maxLength}`,
  })

  // 规则 4：不能包含敏感信息
  const hasSensitive = checkSensitiveInfo(response.answer)
  results.push({
    passed: !hasSensitive,
    rule: '敏感信息检查',
    details: hasSensitive ? '包含敏感信息' : '无敏感信息',
  })

  // 规则 5：不能包含系统 prompt
  const leaksPrompt = checkPromptLeak(response.answer)
  results.push({
    passed: !leaksPrompt,
    rule: 'Prompt 泄露检查',
    details: leaksPrompt ? '疑似泄露系统指令' : '未泄露',
  })

  return results
}

function checkRefusal(answer: string): boolean {
  const refusalPatterns = [
    /无法(找到|回答|确定)/,
    /资料中(没有|未找到)/,
    /抱歉.*无法/,
    /根据现有.*无法/,
  ]
  return refusalPatterns.some(p => p.test(answer))
}

function checkSensitiveInfo(text: string): boolean {
  const patterns = [
    /1[3-9]\d{9}/,      // 手机号
    /\d{17}[\dXx]/,     // 身份证
    /[\w.-]+@[\w.-]+/,  // 邮箱
  ]
  return patterns.some(p => p.test(text))
}

function checkPromptLeak(answer: string): boolean {
  const patterns = [
    /system prompt/i,
    /系统指令/,
    /你是一个.*助手/,
  ]
  return patterns.some(p => p.test(answer))
}
```

## 三、模型评估

### 3.1 使用模型评分

```typescript
// lib/evals/model-eval.ts
import OpenAI from 'openai'

const openai = new OpenAI()

interface ModelEvalResult {
  relevancy: number
  faithfulness: number
  completeness: number
  reasoning: string
}

export async function evaluateWithModel(
  question: string,
  context: string,
  answer: string
): Promise<ModelEvalResult> {
  const response = await openai.responses.create({
    model: 'gpt-5.5',
    input: [
      {
        role: 'system',
        content: `你是一个 AI 回答质量评估专家。请评估以下回答的质量。

评估维度：
1. relevancy（0-1）：回答是否与问题相关
2. faithfulness（0-1）：回答是否基于上下文，没有编造
3. completeness（0-1）：回答是否完整

输出 JSON 格式。`,
      },
      {
        role: 'user',
        content: `问题：${question}

参考上下文：
${context}

AI 回答：
${answer}

请评估并输出 JSON：
{
  "relevancy": 0-1,
  "faithfulness": 0-1,
  "completeness": 0-1,
  "reasoning": "评估理由"
}`,
      },
    ],
    text: { format: { type: 'json_object' } },
    temperature: 0,
  })

  return JSON.parse(response.output_text)
}
```

### 3.2 批量评估

```typescript
export async function batchEvaluate(
  cases: EvalCase[],
  responses: { answer: string; citations: string[] }[]
): Promise<ModelEvalResult[]> {
  const results: ModelEvalResult[] = []

  // 并发评估（限制并发数）
  const concurrency = 5
  for (let i = 0; i < cases.length; i += concurrency) {
    const batch = cases.slice(i, i + concurrency)
    const batchResponses = responses.slice(i, i + concurrency)

    const batchResults = await Promise.all(
      batch.map((c, j) =>
        evaluateWithModel(c.question, c.context || '', batchResponses[j].answer)
      )
    )

    results.push(...batchResults)
  }

  return results
}
```

// components/HumanEval.tsx
'use client'

import { useState } from 'react'

interface EvalSample {
  id: string
  question: string
  context: string
  answer: string
  citations: string[]
}

export function HumanEval({ sample }: { sample: EvalSample }) {
  const [score, setScore] = useState<number | null>(null)
  const [passed, setPassed] = useState<boolean | null>(null)
  const [feedback, setFeedback] = useState('')

  const handleSubmit = async () => {
    await fetch('/api/evals/human', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        sampleId: sample.id,
        score,
        passed,
        feedback,
      }),
    })
  }

  return (
    <div className="human-eval">
      <h3>人工评估</h3>

      <div className="sample">
        <div className="question">
          <h4>问题</h4>
          <p>{sample.question}</p>
        </div>

        <div className="context">
          <h4>参考上下文</h4>
          <p>{sample.context}</p>
        </div>

        <div className="answer">
          <h4>AI 回答</h4>
          <p>{sample.answer}</p>
        </div>

        {sample.citations.length > 0 && (
          <div className="citations">
            <h4>引用</h4>
            <ul>
              {sample.citations.map((c, i) => <li key={i}>{c}</li>)}
            </ul>
          </div>
        )}
      </div>

      <div className="eval-form">
        <div className="score-input">
          <label>评分 (1-5)</label>
          <div className="score-buttons">
            {[1, 2, 3, 4, 5].map(s => (
              <button
                key={s}
                className={score === s ? 'selected' : ''}
                onClick={() => setScore(s)}
              >
                {s}
              </button>
            ))}
          </div>
        </div>

        <div className="pass-input">
          <label>是否通过</label>
          <div>
            <button
              className={passed === true ? 'selected' : ''}
              onClick={() => setPassed(true)}
            >
              通过
            </button>
            <button
              className={passed === false ? 'selected' : ''}
              onClick={() => setPassed(false)}
            >
              不通过
            </button>
          </div>
        </div>

        <div className="feedback-input">
          <label>反馈</label>
          <textarea
            value={feedback}
            onChange={e => setFeedback(e.target.value)}
            placeholder="输入改进建议..."
          />
        </div>

        <button onClick={handleSubmit} disabled={score === null || passed === null}>
          提交评估
        </button>
      </div>
    </div>
  )

## 五、组合评估策略

```typescript
// lib/evals/combined.ts
export async function combinedEval(
  testCase: EvalCase,
  response: { answer: string; citations: string[] }
) {
  // 1. 规则评估（快速、无成本）
  const ruleResults = applyRules(testCase, response)
  const rulesPassed = ruleResults.every(r => r.passed)

  if (!rulesPassed) {
    return {
      passed: false,
      method: 'rules',
      details: ruleResults,
    }
  }

  // 2. 模型评估（语义理解）
  const modelEval = await evaluateWithModel(
    testCase.question,
    testCase.context || '',
    response.answer
  )

  const modelPassed = modelEval.relevancy > 0.7 &&
                      modelEval.faithfulness > 0.8

  if (!modelPassed) {
    return {
      passed: false,
      method: 'model',
      scores: modelEval,
    }
  }

  // 3. 通过
  return {
    passed: true,
    method: 'combined',
    ruleResults,
    modelScores: modelEval,
  }
}
```

## 参考答案

### 练习一

**思路**：规则评估覆盖"硬伤"——敏感信息泄露、Prompt 泄露、拒答场景未拒答等不可接受的问题。规则是确定性的，快速且零成本，作为第一层过滤。

**答案**：

    testCase.question,
    testCase.context || '',
    response.answer

### 练习三

**思路**：人工抽检是自动评估的补充，重点是抽样策略——优先关注低分样本和失败用例，而非纯随机抽样。设计简洁的评估界面，让评估者能快速判断。

**答案**：

抽样策略设计：

```typescript
// lib/evals/sampling.ts
export function selectSamplesForReview(
  evalResults: EvalResult[],
  sampleRate: number = 0.1
): EvalResult[] {
  const samples: EvalResult[] = []

  // 1. 所有失败用例都进入人工复核
  const failures = evalResults.filter(r => !r.passed)
  samples.push(...failures)

  // 2. 低分用例（得分在 0.5-0.7 之间）
  const lowScores = evalResults.filter(r =>
    r.passed &&
    (r.scores.relevancy < 0.7 || r.scores.faithfulness < 0.8)
  )
  samples.push(...lowScores.slice(0, 5))

  // 3. 随机抽样（覆盖"看起来没问题"的用例）
  const passed = evalResults.filter(r => r.passed && !samples.includes(r))
  const randomCount = Math.max(1, Math.floor(evalResults.length * sampleRate))
  const shuffled = passed.sort(() => Math.random() - 0.5)
  samples.push(...shuffled.slice(0, randomCount))

  return samples
}
```

人工评估流程：
1. 评估者查看问题、上下文、AI 回答、引用
2. 给出评分（1-5）和是否通过
3. 填写改进建议
4. 提交评估结果

**要点**：
- 优先人工复核失败用例和低分用例，而非纯随机抽样
- 人工评估结果要和自动评估结果关联分析，发现自动评估的盲区
- 常见错误：完全依赖自动评估，取消人工抽检——自动评估可能系统性地遗漏某类问题（如回答虽然正确但语气不当）

## 常见误区

1. **只用规则评估就认为够了**：规则评估只能检查"有没有引用""长度是否合理"这类硬性条件。回答是否准确、是否编造信息，规则判断不了，必须用模型评估。

2. **模型评估的 Prompt 写得太简单**：评估 Prompt 只说"请评估这个回答的质量"，没有给出明确的评分标准和示例。模型评估器本身也需要精心设计 Prompt，否则评分标准不一致。

3. **模型评估不设 temperature=0**：评估器用默认温度运行，同一条用例跑两次得到不同的分数。评估必须是确定性的，temperature 必须设为 0。

4. **完全依赖自动评估，取消人工抽检**：自动评估可能系统性地遗漏某类问题（比如回答虽然正确但语气不当）。定期人工抽检是发现这类隐性问题的唯一方式。

## 工程建议

1. **三种评估组合使用**：规则评估做第一层过滤（快速、零成本），模型评估做第二层语义判断（准确但有成本），人工抽检做最终校验（最准但不可规模化）。逐层筛选，兼顾效率和准确性。

2. **规则评估覆盖"硬伤"**：敏感信息泄露、Prompt 泄露、拒答场景未拒答——这些是不可接受的硬伤，必须用规则强制拦截，不能依赖模型判断。

3. **批量评估控制并发**：模型评估会调用 API，大量用例同时请求可能导致限流或成本失控。建议并发数控制在 5 以内，用批量处理而非一次性全部发出。

4. **评估结果结构化存储**：每次评估的结果（分数、通过/失败、反馈）都要存入数据库，方便后续对比不同版本的质量趋势。

---

## 小结

本课的核心要点：

1. **规则评估**：快速、确定性，适合简单检查
2. **模型评估**：能理解语义，适合复杂判断
3. **人工抽检**：最准确，适合抽样验证
4. **组合使用**：规则 → 模型 → 人工，逐层筛选
5. **持续优化**：根据评估结果改进系统
