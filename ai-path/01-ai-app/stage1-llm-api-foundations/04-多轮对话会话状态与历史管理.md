# 第4课：多轮对话——给问答加上会话历史

> **前置知识**：第 3 课的问答调用
> **预计时长**：30 分钟

## 模型没有记忆

你和知识工作台对话："这个产品的登录流程是什么？"模型回答了。接着问："那安全方面呢？"模型回答："安全什么？请提供更多信息。"

它不是在装傻——它真的不知道你上一句问了什么。每次 API 调用都是独立的，模型不会保留任何历史。它之所以能"记住"对话，只有一个原因：你把历史消息一起发过去了。

这个认知很重要。多轮对话不是"模型的能力"，而是"你的实现"。

## 把历史装进 messages

```typescript
// src/lib/conversation.ts
import openai from './openai'

type Message = { role: 'system' | 'user' | 'assistant'; content: string }

export class Conversation {
  private messages: Message[]
  private systemPrompt: string

  constructor(systemPrompt: string) {
    this.systemPrompt = systemPrompt
    this.messages = [{ role: 'system', content: systemPrompt }]
  }

  async send(userMessage: string): Promise<string> {
    this.messages.push({ role: 'user', content: userMessage })

    const response = await openai.responses.create({
      model: 'gpt-5.5',
      input: this.messages,
      temperature: 0.3,
      max_output_tokens: 1000,
    })

    const answer = response.output_text ?? ''
    this.messages.push({ role: 'assistant', content: answer })
    return answer
  }

  getHistory(): Message[] {
    return [...this.messages]
  }

  clear(): void {
    this.messages = [{ role: 'system', content: this.systemPrompt }]
  }
}
```

每次调用 `send`，把用户消息加到历史末尾，发给模型，再把模型回答也加进去。下一次调用时，整个历史都会被发送。

这意味着第 1 轮发 2 条消息（system + user），第 10 轮发 21 条（system + 10 轮 × 2）。token 数线性增长，成本和延迟也在增长。

## 历史会膨胀，必须裁剪

聊到第 20 轮，messages 里有 41 条消息。假设每轮平均 500 token，光历史就 10000 token。再加上当前问题和 system prompt，可能接近模型的上下文窗口限制。

更实际的问题是：即使没超限，把 20 轮前的对话一起发给模型，大部分是噪声。模型需要从大量历史中找到相关上下文，反而可能降低回答质量。

什么时候该裁剪？这取决于你的场景。知识库问答通常只需要最近几轮上下文——用户问"那安全方面呢"，模型只需要知道上一句是关于登录流程的，不需要知道第 1 轮的寒暄。

## 两种裁剪策略

**按轮数裁剪**——最简单，保留最近 N 轮：

```typescript
function trimByRounds(messages: Message[], maxRounds: number): Message[] {
  const system = messages[0]
  const rest = messages.slice(1)
  const keep = maxRounds * 2  // 每轮 = user + assistant

  if (rest.length <= keep) return messages
  return [system, ...rest.slice(-keep)]
}
```

优点是实现简单。缺点是粗暴——如果用户在第 1 轮说了"我在做医疗行业项目"这个关键背景，5 轮后就被丢掉了。

**按 token 数裁剪**——更精确：

```typescript
function estimateTokens(text: string): number {
  const english = (text.match(/[a-zA-Z0-9 ]/g) || []).length
  const other = text.length - english
  return Math.ceil(english / 4 + other / 1.5)
}

function trimByTokens(messages: Message[], maxTokens: number): Message[] {
  const system = messages[0]
  const rest = messages.slice(1)

  let total = estimateTokens(system.content)
  const kept: Message[] = []

  // 从最新消息向前保留
  for (let i = rest.length - 1; i >= 0; i--) {
    const tokens = estimateTokens(rest[i].content)
    if (total + tokens > maxTokens) break
    total += tokens
    kept.unshift(rest[i])
  }

  return [system, ...kept]
}
```

从最新的消息开始往前数，超限就停。这样保证最近的上下文不丢，同时控制总 token 数。

实际项目中，`estimateTokens` 的粗略估算够用。如果需要精确计数，用 `tiktoken` 库。但注意：精确计数有额外开销，在高频调用场景下可能不值得。

## 给 Conversation 加上裁剪

```typescript
export class Conversation {
  private messages: Message[]
  private systemPrompt: string
  private maxHistoryTokens: number

  constructor(systemPrompt: string, maxHistoryTokens = 4000) {
    this.systemPrompt = systemPrompt
    this.messages = [{ role: 'system', content: systemPrompt }]
    this.maxHistoryTokens = maxHistoryTokens
  }

  async send(userMessage: string): Promise<string> {
    this.messages.push({ role: 'user', content: userMessage })

    // 发送前裁剪
    const trimmed = trimByTokens(this.messages, this.maxHistoryTokens)

    const response = await openai.responses.create({
      model: 'gpt-5.5',
      input: trimmed,
      temperature: 0.3,
      max_output_tokens: 1000,
    })

    const answer = response.output_text ?? ''
    this.messages.push({ role: 'assistant', content: answer })
    return answer
  }

  // ... 其他方法
}
```

注意：裁剪只影响发给模型的消息，不影响本地存储的历史。本地保留完整历史，发给模型时才裁剪。这样用户可以回看之前的对话，同时控制 API 调用的成本。

## 会话隔离

知识工作台可能同时有多个用户，或者同一个用户有多个独立的对话。每个对话需要独立的历史：

```typescript
const sessions = new Map<string, Conversation>()

export function getOrCreateSession(
  sessionId: string,
  systemPrompt: string
): Conversation {
  if (!sessions.has(sessionId)) {
    sessions.set(sessionId, new Conversation(systemPrompt))
  }
  return sessions.get(sessionId)!
}

export function deleteSession(sessionId: string): void {
  sessions.delete(sessionId)
}

export function listSessions(): string[] {
  return Array.from(sessions.keys())
}
```

用 `Map` 存在内存里，开发阶段够用。但服务器重启后所有会话都没了——生产环境需要持久化到 Redis 或数据库。这个话题留到后端工程阶段再展开。

## 把多轮对话接入 CLI

```typescript
// src/chat.ts
import 'dotenv/config'
import * as readline from 'readline'
import { Conversation } from './lib/conversation'

const conversation = new Conversation(
  `你是一个知识库问答助手。根据用户的问题回答，如果不确定就说明。用中文回答。`
)

const rl = readline.createInterface({
  input: process.stdin,
  output: process.stdout,
})

console.log('AI 知识工作台 - 对话模式')
console.log('输入 "clear" 清除历史，"exit" 退出\n')

function ask() {
  rl.question('你: ', async (input) => {
    if (input === 'exit') { rl.close(); return }
    if (input === 'clear') {
      conversation.clear()
      console.log('历史已清除\n')
      ask()
      return
    }

    const answer = await conversation.send(input)
    console.log(`AI: ${answer}\n`)
    ask()
  })
}

ask()
```

运行 `npx tsx src/chat.ts`，试试连续问几个相关问题，观察模型是否能保持上下文。然后问 `clear` 清除历史，再问同样的问题——模型应该"失忆"了。

## 参考答案

### 练习一

每轮大约增加 500-800 token（取决于问答长度）。按 600 token/轮估算，4000 token 的阈值大约在第 6-7 轮触发裁剪。实际值取决于 system prompt 长度和每轮的问答长度。

### 练习二

```typescript
async function compressOldHistory(messages: Message[]): Promise<Message[]> {
  const system = messages[0]
  const rest = messages.slice(1)
  const keepRecent = 8 // 保留最近 4 轮 = 8 条消息

  if (rest.length <= keepRecent) return messages

  const oldMessages = rest.slice(0, -keepRecent)
  const recentMessages = rest.slice(-keepRecent)

  const conversationText = oldMessages
    .map(m => `${m.role}: ${m.content}`)
    .join('\n')

  const response = await openai.responses.create({
    model: 'gpt-5.5',
    input: [
      { role: 'system', content: '用 3 句话总结以下对话的要点，保留关键信息和用户提到的背景。' },
      { role: 'user', content: conversationText }
    ],
    temperature: 0,
    max_output_tokens: 300,
  })

  const summary = response.output_text ?? ''

  return [
    system,
    { role: 'system', content: `之前的对话摘要：${summary}` },
    ...recentMessages,
  ]
}
```

摘要压缩能保留早期的关键背景信息（比如"用户是医疗行业的"），但多了一次 API 调用。对于知识库问答场景，如果对话通常不超过 10 轮，直接裁剪更简单；如果对话可能很长且包含重要背景，摘要压缩更可靠。
