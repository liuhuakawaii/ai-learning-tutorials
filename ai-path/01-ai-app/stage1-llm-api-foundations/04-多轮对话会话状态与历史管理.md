你做了一个 AI 客服机器人，用户反馈："我上一条消息说了我的订单号，它怎么又问我？"你检查代码，发现每条请求都是独立发送的，没有带上历史消息。你加上了历史消息，测试了 20 轮对话后发现请求越来越慢，最后直接报错"上下文长度超出限制"。你需要一种方式让模型"记住"之前的对话，同时不能让历史无限膨胀。

## 一、多轮对话的原理

### 1.1 模型没有"记忆"

```
一个关键认知：

  大模型没有记忆。每次请求都是独立的。

  你以为的对话：
    用户：我叫小明
    AI：你好小明！
    用户：我叫什么？        ← 你以为 AI 记得
    AI：你叫小明啊！        ← 其实是因为你把历史发过去了

  实际发生的事：
    第 1 次请求：["我叫小明"] → "你好小明！"
    第 2 次请求：["我叫小明", "你好小明！", "我叫什么？"] → "你叫小明啊！"
                     ↑ 历史消息被重新发送了
```

### 1.2 消息历史的传递

```typescript
// 多轮对话的核心：每次请求都带上完整的历史
const messages = [
  // 第 1 轮
  { role: 'user', content: '我叫小明' },
  { role: 'assistant', content: '你好小明！' },

  // 第 2 轮
  { role: 'user', content: '我叫什么？' },
  // 这条消息还没回答，是当前要发送的
]

const response = await openai.responses.create({
  model: 'gpt-5.5',
  messages,  // 把完整历史发给模型
})

// 模型的回答
const answer = response.output_text
// "你叫小明啊！"

// 把回答也加入历史，供下一轮使用
messages.push({ role: 'assistant', content: answer })
```

## 二、实现多轮对话

### 2.1 基础实现

```typescript
// src/examples/multi-turn.ts
import 'dotenv/config'
import OpenAI from 'openai'
import * as readline from 'readline'

const openai = new OpenAI()

// 消息历史
type Message = { role: 'system' | 'user' | 'assistant'; content: string }

const messages: Message[] = [
  { role: 'system', content: '你是一个有帮助的助手。用中文回答。' }
]

async function chat(userMessage: string): Promise<string> {
  // 添加用户消息到历史
  messages.push({ role: 'user', content: userMessage })

  // 调用 API（带上完整历史）
  const response = await openai.responses.create({
    model: 'gpt-5.5',
    input: messages,
  })

  const answer = response.output_text ?? ''

  // 把回答也加入历史
  messages.push({ role: 'assistant', content: answer })

  return answer
}

// 交互式对话
async function main() {
  const rl = readline.createInterface({
    input: process.stdin,
    output: process.stdout,
  })

  console.log('AI 助手已启动，输入 "exit" 退出\n')

  const ask = () => {
    rl.question('你: ', async (input) => {
      if (input.toLowerCase() === 'exit') {
        rl.close()
        return
      }

      const answer = await chat(input)
      console.log('AI:', answer)
      console.log(`(历史消息数: ${messages.length})\n`)
      ask()
    })
  }

  ask()
}

main()
```

### 2.2 会话管理：支持多个独立对话

```typescript
// src/lib/conversation.ts
import OpenAI from 'openai'

const openai = new OpenAI()

interface Conversation {
  id: string
  input: Message[]
  createdAt: Date
  updatedAt: Date
}

// 存储所有会话
const conversations = new Map<string, Conversation>()

// 创建新会话
export function createConversation(id: string): Conversation {
  const conversation: Conversation = {
    id,
    input: [
      { role: 'system', content: '你是一个有帮助的助手。' }
    ],
    createdAt: new Date(),
    updatedAt: new Date(),
  }
  conversations.set(id, conversation)
  return conversation
}

// 获取会话
export function getConversation(id: string): Conversation | undefined {
  return conversations.get(id)
}

// 发送消息
export async function sendMessage(
  conversationId: string,
  userMessage: string
): Promise<string> {
  let conversation = conversations.get(conversationId)

  if (!conversation) {
    conversation = createConversation(conversationId)
  }

  // 添加用户消息
  conversation.messages.push({ role: 'user', content: userMessage })

  // 调用 API
  const response = await openai.responses.create({
    model: 'gpt-5.5',
    input: conversation.messages,
  })

  const answer = response.output_text ?? ''

  // 添加回答
  conversation.messages.push({ role: 'assistant', content: answer })
  conversation.updatedAt = new Date()

  return answer
}

// 列出所有会话
export function listConversations(): Conversation[] {
  return Array.from(conversations.values())
    .sort((a, b) => b.updatedAt.getTime() - a.updatedAt.getTime())
}
```

## 三、上下文窗口问题

### 3.1 什么是上下文窗口

```
每个模型都有一个"上下文窗口"限制：

  gpt-5.5:  128K tokens
  GPT-4o:       128K tokens
  Claude 3.5:   200K tokens

上下文窗口 = 输入 + 输出 的总 token 数

┌─────────────────────────────────────────────────────────────────┐
│                    上下文窗口                                     │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                    128K tokens                           │   │
│  │  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌────────┐  │   │
│  │  │  system   │  │ messages │  │ messages │  │ output │  │   │
│  │  │  prompt   │  │  历史    │  │  当前    │  │ 生成的 │  │   │
│  │  └──────────┘  └──────────┘  └──────────┘  └────────┘  │   │
│  │                                                         │   │
│  │  总 token 数不能超过 128K                                │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 超出限制会怎样

```typescript
// 当消息历史太长时
try {
  const response = await openai.responses.create({
    model: 'gpt-5.5',
    input: veryLongMessages,  // 超过了 128K tokens
  })
} catch (error) {
  if (error instanceof OpenAI.BadRequestError) {
    // 错误信息：This model's maximum context length is 128000 tokens
    console.error('消息太长，超出了模型的上下文窗口')
  }
}
```

### 3.3 估算 token 数

```typescript
// 简单估算（不精确，但够用）
function estimateTokens(text: string): number {
  // 英文：1 token ≈ 4 字符
  // 中文：1 token ≈ 1.5 字符
  const englishChars = (text.match(/[a-zA-Z0-9 ]/g) || []).length
  const chineseChars = text.length - englishChars

  return Math.ceil(englishChars / 4 + chineseChars / 1.5)
}

// 更精确的方式：使用 tiktoken 库
// npm install tiktoken
import { encoding_for_model } from 'tiktoken'

function countTokens(text: string, model: string = 'gpt-5.5'): number {
  const enc = encoding_for_model(model as any)
  const tokens = enc.encode(text)
  enc.free()
  return tokens.length
}
```

## 四、历史裁剪策略

### 4.1 策略一：保留最近 N 轮

```typescript
// 最简单的策略：只保留最近的 N 轮对话
function trimHistory(
  input: Message[],
  maxRounds: number = 10
): Message[] {
  // 第一条是 system prompt，始终保留
  const systemMessage = messages[0]
  const otherMessages = messages.slice(1)

  // 每轮 = 1 条 user + 1 条 assistant = 2 条消息
  const maxMessages = maxRounds * 2

  if (otherMessages.length <= maxMessages) {
    return messages
  }

  // 保留 system + 最近的 N 轮
  return [
    systemMessage,
    ...otherMessages.slice(-maxMessages),
  ]
}

// 使用
const trimmed = trimHistory(messages, 10)  // 保留最近 10 轮
```

### 4.2 策略二：按 Token 数裁剪

```typescript
// 按 token 数裁剪，更精确
function trimByTokens(
  input: Message[],
  maxTokens: number = 4000
): Message[] {
  const systemMessage = messages[0]
  const otherMessages = messages.slice(1)

  let totalTokens = estimateTokens(systemMessage.content as string)
  const result: Message[] = []

  // 从最新的消息开始，向前保留
  for (let i = otherMessages.length - 1; i >= 0; i--) {
    const msg = otherMessages[i]
    const msgTokens = estimateTokens(msg.content as string)

    if (totalTokens + msgTokens > maxTokens) {
      break
    }

    totalTokens += msgTokens
    result.unshift(msg)
  }

  return [systemMessage, ...result]
}
```

### 4.3 策略三：摘要压缩

```typescript
// 用模型压缩历史对话
async function summarizeHistory(
  input: Message[]
): Promise<string> {
  const conversationText = messages
    .filter(m => m.role !== 'system')
    .map(m => `${m.role}: ${m.content}`)
    .join('\n')

  const response = await openai.responses.create({
    model: 'gpt-5.5',
    input: [
      {
        role: 'system',
        content: '请用 3-5 句话总结以下对话的要点，保留关键信息。'
      },
      { role: 'user', content: conversationText }
    ],
    temperature: 0,
    max_output_tokens: 300,
  })

  return response.output_text ?? ''
}

// 压缩后重建消息历史
async function compressHistory(
  input: Message[],
  keepRecent: number = 4
): Promise<Message[]> {
  const systemMessage = messages[0]
  const otherMessages = messages.slice(1)

  if (otherMessages.length <= keepRecent) {
    return messages
  }

  // 需要压缩的部分
  const toSummarize = otherMessages.slice(0, -keepRecent)
  const recent = otherMessages.slice(-keepRecent)

  // 生成摘要
  const summary = await summarizeHistory(toSummarize)

  return [
    systemMessage,
    { role: 'system', content: `之前的对话摘要：${summary}` },
    ...recent,
  ]
}
```

### 4.4 策略对比

```
┌─────────────────────────────────────────────────────────────────┐
│                    历史裁剪策略对比                               │
├──────────────┬──────────────┬──────────────┬────────────────────┤
│  策略         │  实现难度     │  精确度      │  适用场景           │
├──────────────┼──────────────┼──────────────┼────────────────────┤
│  保留最近 N 轮│  简单         │  低          │  快速原型           │
│  按 Token 裁剪│  中等         │  高          │  大多数场景         │
│  摘要压缩     │  复杂         │  中等        │  长对话、重要上下文  │
└──────────────┴──────────────┴──────────────┴────────────────────┘

推荐组合：
  1. 始终保留 system prompt
  2. 按 token 数裁剪（上限 4000）
  3. 超出时，压缩旧历史为摘要
  4. 保留最近 4-6 轮完整对话
```

## 五、完整的会话管理实现

```typescript
// src/lib/chat-manager.ts
import OpenAI from 'openai'

const openai = new OpenAI()

interface ChatSession {
  id: string
  input: Message[]
  totalTokens: number
}

const sessions = new Map<string, ChatSession>()

const MAX_HISTORY_TOKENS = 4000
const KEEP_RECENT_ROUNDS = 4

export function getOrCreateSession(id: string): ChatSession {
  if (!sessions.has(id)) {
    sessions.set(id, {
      id,
      input: [
        { role: 'system', content: '你是一个有帮助的助手。' }
      ],
      totalTokens: 0,
    })
  }
  return sessions.get(id)!
}

function estimateTokens(text: string): number {
  const english = (text.match(/[a-zA-Z0-9 ]/g) || []).length
  const other = text.length - english
  return Math.ceil(english / 4 + other / 1.5)
}

function trimMessages(
  input: Message[]
): Message[] {
  const system = messages[0]
  const rest = messages.slice(1)

  // 计算当前总 token
  let total = estimateTokens(system.content as string)
  for (const msg of rest) {
    total += estimateTokens(msg.content as string)
  }

  // 如果没超限，直接返回
  if (total <= MAX_HISTORY_TOKENS) {
    return messages
  }

  // 保留最近 N 轮
  const keepCount = KEEP_RECENT_ROUNDS * 2
  const recent = rest.slice(-keepCount)

  return [system, ...recent]
}

export async function chat(
  sessionId: string,
  userMessage: string
): Promise<{ answer: string; tokens: number }> {
  const session = getOrCreateSession(sessionId)

  // 添加用户消息
  session.messages.push({ role: 'user', content: userMessage })

  // 裁剪历史
  const trimmed = trimMessages(session.messages)

  // 调用 API
  const response = await openai.responses.create({
    model: 'gpt-5.5',
    input: trimmed,
  })

  const answer = response.output_text ?? ''
  const tokens = response.usage?.total_tokens ?? 0

  // 更新会话
  session.messages.push({ role: 'assistant', content: answer })
  session.totalTokens += tokens

  return { answer, tokens }
}

export function getSessionHistory(sessionId: string) {
  const session = sessions.get(sessionId)
  return session?.messages ?? []
}

export function deleteSession(sessionId: string) {
  sessions.delete(sessionId)
}
```

## 六、前端的会话状态管理

### 6.1 React 实现

```typescript
// features/chat/hooks/useChat.ts
import { useState, useCallback } from 'react'

interface Message {
  role: 'user' | 'assistant'
  content: string
  timestamp: Date
}

export function useChat(sessionId: string) {
  const [messages, setMessages] = useState<Message[]>([])
  const [isLoading, setIsLoading] = useState(false)
  const [error, setError] = useState<string | null>(null)

  const sendMessage = useCallback(async (content: string) => {
    setIsLoading(true)
    setError(null)

    // 添加用户消息
    const userMessage: Message = {
      role: 'user',
      content,
      timestamp: new Date(),
    }
    setMessages(prev => [...prev, userMessage])

    try {
      const response = await fetch('/api/chat', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          sessionId,
          message: content,
        }),
      })

      if (!response.ok) {
        throw new Error('请求失败')
      }

      const data = await response.json()

      // 添加 AI 回答
      const assistantMessage: Message = {
        role: 'assistant',
        content: data.answer,
        timestamp: new Date(),
      }
      setMessages(prev => [...prev, assistantMessage])

    } catch (err) {
      setError(err instanceof Error ? err.message : '未知错误')
    } finally {
      setIsLoading(false)
    }
  }, [sessionId])

  const clearHistory = useCallback(() => {
    setMessages([])
    // 同时通知后端清除
    fetch(`/api/chat/${sessionId}`, { method: 'DELETE' })
  }, [sessionId])

  return {
    input: messages,
    isLoading,
    error,
    sendMessage,
    clearHistory,
  }
}
```

## 参考答案

### 练习一

**思路**：多轮对话的核心是维护一个消息历史数组，每次请求都带上完整历史。命令行程序可以用 readline 实现交互式输入，用一个数组存储所有消息。

**答案**：

```typescript
import 'dotenv/config'
import OpenAI from 'openai'
import * as readline from 'readline'

const openai = new OpenAI()

type Message = { role: 'system' | 'user' | 'assistant'; content: string }

const messages: Message[] = [
  { role: 'system', content: '你是一个有帮助的助手。用中文回答。' }
]

async function chat(userMessage: string): Promise<string> {
  messages.push({ role: 'user', content: userMessage })

  const response = await openai.responses.create({
    model: 'gpt-5.5',
    input: messages,
  })

  const answer = response.output_text ?? ''
  messages.push({ role: 'assistant', content: answer })
  return answer
}

async function main() {
  const rl = readline.createInterface({
    input: process.stdin,
    output: process.stdout,
  })

  console.log('AI 助手已启动')
  console.log('- 输入消息进行对话')
  console.log('- 输入 "clear" 清除历史')
  console.log('- 输入 "history" 查看历史消息数')
  console.log('- 输入 "exit" 退出\n')

  const ask = () => {
    rl.question('你: ', async (input) => {
      if (input.toLowerCase() === 'exit') {
        rl.close()
        return
      }

      if (input.toLowerCase() === 'clear') {
        messages.length = 1  // 保留 system prompt
        console.log('历史已清除\n')
        ask()
        return
      }

      if (input.toLowerCase() === 'history') {
        console.log(`当前历史消息数: ${messages.length} (含 system prompt)\n`)
        ask()
        return
      }

      const answer = await chat(input)
      console.log('AI:', answer)
      console.log(`(历史消息数: ${messages.length})\n`)
      ask()
    })
  }

  ask()
}

main()
```

**要点**：
- 多轮对话的本质是每次请求都带上完整历史——模型没有记忆，它之所以"记得"之前的内容，是因为你把历史一起发过去了
- 常见错误：只发送当前用户消息，不带历史，导致模型每次都是"失忆"状态

### 练习二

**思路**：裁剪策略的核心问题是"历史无限增长"。通过对比裁剪前后的 token 使用量，可以直观看到裁剪的必要性。保留最近 N 轮是最简单的策略，但可能丢失早期的关键信息。

**答案**：

```typescript
import 'dotenv/config'
import OpenAI from 'openai'
import * as readline from 'readline'

const openai = new OpenAI()

type Message = { role: 'system' | 'user' | 'assistant'; content: string }

const messages: Message[] = [
  { role: 'system', content: '你是一个有帮助的助手。用中文回答。' }
]

function estimateTokens(text: string): number {
  const english = (text.match(/[a-zA-Z0-9 ]/g) || []).length
  const other = text.length - english
  return Math.ceil(english / 4 + other / 1.5)
}

function getHistoryTokens(): number {
  return messages.reduce((sum, msg) => {
    const content = typeof msg.content === 'string' ? msg.content : ''
    return sum + estimateTokens(content)
  }, 0)
}

// 策略：保留最近 N 轮
function trimHistory(maxRounds: number = 5): void {
  const systemMessage = messages[0]
  const otherMessages = messages.slice(1)
  const maxMessages = maxRounds * 2  // 每轮 = user + assistant

  if (otherMessages.length > maxMessages) {
    const trimmed = otherMessages.slice(-maxMessages)
    messages.length = 0
    messages.push(systemMessage, ...trimmed)
    console.log(`[裁剪] 历史从 ${otherMessages.length + 1} 条裁剪到 ${messages.length} 条`)
  }
}

async function chat(userMessage: string): Promise<string> {
  messages.push({ role: 'user', content: userMessage })
  trimHistory(5)  // 保留最近 5 轮

  const response = await openai.responses.create({
    model: 'gpt-5.5',
    input: messages,
  })

  const answer = response.output_text ?? ''
  messages.push({ role: 'assistant', content: answer })
  return answer
}

async function main() {
  const rl = readline.createInterface({
    input: process.stdin,
    output: process.stdout,
  })

  console.log('测试裁剪策略：连续对话 20 轮，观察 token 使用量\n')

  const ask = (round: number) => {
    if (round > 20) {
      console.log('\n20 轮对话完成')
      rl.close()
      return
    }

    rl.question(`第 ${round} 轮 - 你: `, async (input) => {
      if (input.toLowerCase() === 'exit') {
        rl.close()
        return
      }

      const tokensBefore = getHistoryTokens()
      const answer = await chat(input)
      const tokensAfter = getHistoryTokens()

      console.log(`AI: ${answer}`)
      console.log(`[统计] 裁剪前估算: ${tokensBefore} tokens, 裁剪后: ${tokensAfter} tokens, 消息数: ${messages.length}\n`)

      ask(round + 1)
    })
  }

  ask(1)
}

main()
```

**要点**：
- 不做裁剪的多轮对话是不可用的——20 轮对话后 token 数持续增长，成本和延迟都在飙升
- 按轮数裁剪简单但粗糙：第 1 轮用户说的关键信息（如"我在做医疗行业项目"）可能被丢掉。更精确的方式是按 token 数裁剪，或用摘要压缩保留关键信息
- 常见错误：只按轮数裁剪而不考虑 token 数——如果每轮对话很长（比如用户贴了大段代码），5 轮可能就超限了

### 练习三

**思路**：会话隔离的核心是用一个唯一的 session ID 来区分不同的对话。每个会话有独立的消息历史，互不干扰。可以用 Map 来存储多个会话。

**答案**：

```typescript
import 'dotenv/config'
import OpenAI from 'openai'
import * as readline from 'readline'

const openai = new OpenAI()

type Message = { role: 'system' | 'user' | 'assistant'; content: string }

interface Session {
  id: string
  messages: Message[]
  createdAt: Date
}

const sessions = new Map<string, Session>()
let currentSessionId = 'default'

function getOrCreateSession(id: string): Session {
  if (!sessions.has(id)) {
    sessions.set(id, {
      id,
      messages: [
        { role: 'system', content: `你是一个有帮助的助手。当前会话 ID: ${id}` }
      ],
      createdAt: new Date(),
    })
  }
  return sessions.get(id)!
}

async function chat(userMessage: string): Promise<string> {
  const session = getOrCreateSession(currentSessionId)
  session.messages.push({ role: 'user', content: userMessage })

  const response = await openai.responses.create({
    model: 'gpt-5.5',
    input: session.messages,
  })

  const answer = response.output_text ?? ''
  session.messages.push({ role: 'assistant', content: answer })
  return answer
}

async function main() {
  const rl = readline.createInterface({
    input: process.stdin,
    output: process.stdout,
  })

  console.log('多会话 AI 助手')
  console.log('- 输入消息进行对话')
  console.log('- 输入 "switch <id>" 切换会话')
  console.log('- 输入 "list" 列出所有会话')
  console.log('- 输入 "new <id>" 创建新会话')
  console.log('- 输入 "exit" 退出\n')

  const ask = () => {
    rl.question(`[${currentSessionId}] 你: `, async (input) => {
      if (input.toLowerCase() === 'exit') {
        rl.close()
        return
      }

      if (input.toLowerCase() === 'list') {
        console.log('\n所有会话:')
        sessions.forEach((session, id) => {
          const marker = id === currentSessionId ? ' ← 当前' : ''
          console.log(`  ${id} (${session.messages.length} 条消息, 创建于 ${session.createdAt.toLocaleTimeString()})${marker}`)
        })
        console.log()
        ask()
        return
      }

      if (input.toLowerCase().startsWith('switch ')) {
        const id = input.slice(7).trim()
        if (sessions.has(id)) {
          currentSessionId = id
          console.log(`已切换到会话: ${id}\n`)
        } else {
          console.log(`会话 ${id} 不存在，使用 "new ${id}" 创建\n`)
        }
        ask()
        return
      }

      if (input.toLowerCase().startsWith('new ')) {
        const id = input.slice(4).trim()
        currentSessionId = id
        getOrCreateSession(id)
        console.log(`已创建并切换到新会话: ${id}\n`)
        ask()
        return
      }

      const answer = await chat(input)
      console.log(`AI: ${answer}\n`)
      ask()
    })
  }

  ask()
}

main()
```

**要点**：
- 会话隔离的关键是每个 session 有独立的 messages 数组，不要把所有用户的对话混在一起
- 常见错误：用全局的 messages 数组存储所有会话，导致不同用户的对话互相干扰，甚至泄露其他用户的隐私信息

---

## 常见误区

1. **"把所有历史消息都发给模型就行"**：前 5 轮对话效果很好，到第 20 轮就开始变慢甚至报错。每轮对话增加 2 条消息，20 轮就是 40 条消息加上下文，token 数持续增长，成本和延迟都在飙升。不做裁剪的多轮对话是不可用的。

2. **"模型会自动记住之前的对话"**：大模型没有记忆。每次请求都是独立的，模型之所以"记得"你叫小明，是因为你把"我叫小明"这条历史消息一起发过去了。如果你不发历史，模型对之前的对话一无所知。

3. **"按轮数裁剪就够了"**：只保留最近 10 轮，但第 1 轮用户说的关键信息（如"我在做医疗行业项目"）被丢掉了，模型的回答开始偏离用户的真实需求。按轮数裁剪简单但粗糙，按 token 数裁剪更精确，摘要压缩能保留关键信息。

4. **"会话状态存内存就行"**：开发时用 `Map` 存会话没问题，但一重启服务器所有用户的对话历史都没了。生产环境需要把会话状态持久化到数据库（Redis、PostgreSQL 等），否则用户体验极差。

---

## 工程建议

1. **三层裁剪策略组合使用**：System Prompt 始终保留（它定义了模型的行为），按 token 数设置上限（如 4000 tokens），超出时先压缩旧历史为摘要，再保留最近 4-6 轮完整对话。这样既控制了成本，又不丢失关键上下文。

2. **token 估算用库而非猜**：用 `tiktoken` 库精确计算 token 数，而不是靠"1 个中文字 ≈ 1.5 个字符"的粗略估算。估算偏差可能导致你以为没超限，实际已经超了，或者过度裁剪导致上下文不足。

3. **会话隔离要设计好**：每个用户、每个对话主题都应该有独立的会话 ID。不要把所有用户的对话混在一起。会话 ID 可以用 UUID 或 `userId + timestamp` 的组合。

4. **前端状态和后端状态同步**：前端维护一份消息列表用于展示，后端维护一份用于发送给模型。用户清空历史时，前后端都要同步清除。不要只清前端不管后端——后端的会话还在继续消耗 token。

---

## 小结

本课的核心要点：

1. **模型没有记忆**：每次请求都是独立的，需要把历史消息一起发送
2. **消息历史增长**：每轮对话增加 2 条消息，token 数持续增长
3. **上下文窗口有限**：超出限制会报错，需要裁剪历史
4. **三种裁剪策略**：按轮数裁剪（简单）、按 token 裁剪（精确）、摘要压缩（保留关键信息）
5. **推荐组合**：system prompt 始终保留 + 按 token 裁剪 + 保留最近 N 轮
