## 一、Messages：模型的输入格式

### 1.1 三种角色

## 二、Temperature：控制输出的随机性

### 2.1 什么是 Temperature

```
Temperature 控制模型"选择下一个词"时的随机程度：

  temperature = 0（最确定）
    模型总是选择概率最高的词
    输出：每次几乎一样
    适合：代码生成、数据提取、格式转换

  temperature = 0.7（适中）
    模型在高概率词中随机选择
    输出：有变化但不离谱
    适合：日常对话、文案写作

  temperature = 1.0（最随机）
    模型更愿意选择低概率的词
    输出：每次可能很不一样
    适合：创意写作、头脑风暴
```

### 2.2 用代码体验

```typescript
// temperature 对比实验
async function temperatureDemo(prompt: string, temp: number) {
  const response = await openai.responses.create({
    model: 'gpt-5.5',
    input: [{ role: 'user', content: prompt }],
    temperature: temp,
    max_output_tokens: 100,
  })
  return response.output_text
}

// 同一个 prompt，不同 temperature
const prompt = '写一个关于秋天的句子'

// temperature = 0：每次输出几乎一样
console.log('temp=0:', await temperatureDemo(prompt, 0))
console.log('temp=0:', await temperatureDemo(prompt, 0))
// 两次输出可能完全相同

// temperature = 1：每次输出不同
console.log('temp=1:', await temperatureDemo(prompt, 1))
console.log('temp=1:', await temperatureDemo(prompt, 1))
// 两次输出通常不同
```

### 2.3 Temperature 的选择指南

```
┌─────────────────────────────────────────────────────────────────┐
│                Temperature 选择指南                              │
├─────────────────────┬───────────────┬───────────────────────────┤
│  场景               │  推荐温度      │  原因                     │
├─────────────────────┼───────────────┼───────────────────────────┤
│  代码生成           │  0 - 0.2      │  代码必须准确              │
│  数据提取           │  0            │  不能有歧义               │
│  JSON 格式化        │  0            │  格式必须正确              │
│  分类任务           │  0            │  结果必须确定              │
│  翻译               │  0.3          │  准确但允许措辞变化        │
│  日常对话           │  0.7          │  自然、不重复              │
│  文案写作           │  0.7 - 0.9    │  需要创意但不失控          │
│  头脑风暴           │  0.9 - 1.0    │  需要多样性               │
└─────────────────────┴───────────────┴───────────────────────────┘
```

## 三、Max Tokens：控制输出长度

### 3.1 什么是 Token

```
Token 不等于字符，也不等于单词。

英文：
  "Hello world" → 2 个 token（Hello, world）
  "Don't" → 2 个 token（Don, 't）
  "transformer" → 1-2 个 token

中文：
  "你好世界" → 2-4 个 token（取决于分词方式）
  "人工智能" → 2 个 token

经验法则：
  英文：1 token ≈ 4 个字符 ≈ 0.75 个单词
  中文：1 token ≈ 1-2 个汉字
```

### 3.2 Max Tokens 的作用

```typescript
const response = await openai.responses.create({
  model: 'gpt-5.5',
  input: [{ role: 'user', content: '写一篇关于 AI 的文章' }],
  max_output_tokens: 100,  // 最多生成 100 个 token
})

// max_output_tokens = 100  → 大约 100-150 个英文单词，或 50-100 个中文字
// max_output_tokens = 500  → 大约 500-750 个英文单词
// max_output_tokens = 2000 → 大约 2000-3000 个英文单词
```

### 3.3 Max Tokens 与成本的关系

```
成本 = 输入 token 数 × 输入价格 + 输出 token 数 × 输出价格

gpt-5.5 的价格（示例）：
  输入：$0.15 / 1M tokens
  输出：$0.60 / 1M tokens

  输出价格是输入的 4 倍！

所以：
  - max_output_tokens 越大，成本越高
  - 输出比输入更贵
  - 合理设置 max_output_tokens 可以显著降低成本
```

### 3.4 何时设置 Max Tokens

```
┌─────────────────────────────────────────────────────────────────┐
│                 何时设置 max_output_tokens                        │
├─────────────────────┬───────────────────────────────────────────┤
│  场景               │  是否设置                                   │
├─────────────────────┼───────────────────────────────────────────┤
│  生成标题           │  ✅ 设置小值（50）                          │
│  生成摘要           │  ✅ 设置适中值（200）                       │
│  生成文章           │  ✅ 设置大值（2000）                        │
│  自由对话           │  ❌ 不设置，让模型自然结束                   │
│  结构化输出         │  ✅ 设置适中值，避免过长                     │
└─────────────────────┴───────────────────────────────────────────┘
```

## 四、输出处理

### 4.1 正常输出的处理

```typescript
const response = await openai.responses.create({
  model: 'gpt-5.5',
  input: [{ role: 'user', content: '你好' }]
})

// 检查响应状态
switch (response.status) {
  case 'completed':
    console.log('正常回答:', response.output_text)
    break

  case 'incomplete':
    console.warn('回答未完整生成，检查 max_output_tokens 或安全策略')
    break

  default:
    console.log('其他状态:', response.status)
}
```

### 4.2 空输出的处理

```typescript
async function safeChat(userMessage: string) {
  const response = await openai.responses.create({
    model: 'gpt-5.5',
    input: [{ role: 'user', content: userMessage }]
  })

  const content = response.output_text

  // 空输出检查
  if (!content || content.trim() === '') {
    return {
      success: false,
      error: '模型返回了空回答，请重试',
    }
  }

  return {
    success: true,
    answer: content,
    tokens: response.usage,
  }
}
```

### 4.3 输出长度的控制策略

```
如果你需要控制输出长度，有三种方式：

1. max_output_tokens（硬限制）
   直接限制最大 token 数
   风险：可能截断回答

2. 在 prompt 中指定（软限制）
   "用 100 字以内总结这篇文章"
   效果：模型通常会遵守，但不保证

3. 在 prompt 中指定格式
   "用 3 个要点回答，每个要点一句话"
   效果：比字数限制更可控

推荐：结合使用
   max_output_tokens 设一个安全上限
   prompt 中指定期望的长度和格式
```

## 五、错误处理详解

### 5.1 完整的错误处理

```typescript
import OpenAI from 'openai'

const openai = new OpenAI({
  apiKey: process.env.OPENAI_API_KEY,
  timeout: 30 * 1000,
  maxRetries: 2,
})

interface ChatResult {
  success: boolean
  answer?: string
  error?: string
  tokens?: { prompt: number; completion: number; total: number }
}

async function safeChat(userMessage: string): Promise<ChatResult> {
  try {
    const response = await openai.responses.create({
      model: 'gpt-5.5',
      input: [
        { role: 'system', content: '你是一个有帮助的助手。' },
        { role: 'user', content: userMessage }
      ],
      temperature: 0.7,
      max_output_tokens: 1000,
    })

    const content = response.output_text

    if (!content) {
      return { success: false, error: '模型返回空回答' }
    }

    return {
      success: true,
      answer: content,
      tokens: {
        input: response.usage?.input_tokens ?? 0,
        output: response.usage?.output_tokens ?? 0,
        total: response.usage?.total_tokens ?? 0,
      },
    }

  } catch (error) {
    if (error instanceof OpenAI.AuthenticationError) {
      return { success: false, error: 'API Key 无效，请检查配置' }
    }

    if (error instanceof OpenAI.RateLimitError) {
      return { success: false, error: '请求太频繁，请稍后再试' }
    }

    if (error instanceof OpenAI.APIError) {
      return { success: false, error: `API 错误: ${error.message}` }
    }

    if (error instanceof OpenAI.APIConnectionError) {
      return { success: false, error: '无法连接到 API，请检查网络' }
    }

    return { success: false, error: `未知错误: ${error}` }
  }
}
```

### 5.2 错误类型速查表

```
┌─────────────────────────────────────────────────────────────────┐
│                    常见错误类型                                   │
├──────────────┬────────┬──────────────────────────────────────────┤
│  错误类型     │  状态码 │  原因与处理                              │
├──────────────┼────────┼──────────────────────────────────────────┤
│  认证错误     │  401   │  Key 无效 → 检查配置                     │

│  网络断开     │  -     │  网络问题 → 检查连接                     │
│  上下文过长   │  400   │  输入 token 超限 → 缩短输入              │
│  模型不存在   │  404   │  模型名错误 → 检查拼写                   │

└──────────────┴────────┴──────────────────────────────────────────┘
```

## 六、一个完整的文本生成示例

```typescript
// src/examples/text-generation.ts
import 'dotenv/config'
import OpenAI from 'openai'

const openai = new OpenAI()

interface GenerateOptions {
  systemPrompt?: string
  temperature?: number
  maxTokens?: number
}

async function generate(
  userMessage: string,
  options: GenerateOptions = {}
) {
  const {
    systemPrompt = '你是一个有帮助的助手。',
    temperature = 0.7,
    maxTokens = 1000,
  } = options

  const startTime = Date.now()

  const response = await openai.responses.create({
    model: 'gpt-5.5',
    input: [
      { role: 'system', content: systemPrompt },
      { role: 'user', content: userMessage },
    ],
    temperature,
    max_output_tokens: maxTokens,
  })

  const elapsed = Date.now() - startTime
  const content = response.output_text ?? ''
  const usage = response.usage

  return {
    content,
    elapsed,
    tokens: {
      input: usage?.input_tokens ?? 0,
      output: usage?.output_tokens ?? 0,
      total: usage?.total_tokens ?? 0,
    },
    finishReason: response.status,
  }
}

// 使用示例
async function main() {
  // 1. 代码生成（低温度）
  const code = await generate(
    '写一个 TypeScript 函数，计算数组的平均值',
    { temperature: 0, maxTokens: 200 }
  )
  console.log('代码生成:', code.content)
  console.log('耗时:', code.elapsed, 'ms')

  // 2. 文案写作（适中温度）
  const copy = await generate(
    '为一个 AI 编程助手写一段 50 字的广告语',
    { temperature: 0.8, maxTokens: 100 }
  )
  console.log('文案:', copy.content)

  // 3. 技术总结（指定格式）
  const summary = await generate(
    '用 3 个要点总结 React 的核心概念，每个要点一句话',
    {
      systemPrompt: '你是一个技术培训师，擅长简洁明了地解释概念。',
      temperature: 0.3,
      maxTokens: 300,
    }
  )
  console.log('总结:', summary.content)
}

main()
```

## 参考答案

### 练习一

**思路**：Temperature 的核心是控制"下一个词选择时的随机程度"。通过对比实验可以直观看到 temperature=0 时输出高度一致，temperature=1 时输出差异明显。关键是要理解：高温度不等于"更聪明"，只是"更随机"。

**答案**：

```typescript
import 'dotenv/config'
import OpenAI from 'openai'

const openai = new OpenAI()

async function temperatureExperiment(prompt: string, temp: number, times: number) {
  const results: string[] = []
  for (let i = 0; i < times; i++) {
    const response = await openai.responses.create({
      model: 'gpt-5.5',
      input: [{ role: 'user', content: prompt }],
      temperature: temp,
      max_output_tokens: 100,
    })
    results.push(response.output_text ?? '')
  }
  return results
}

async function main() {
  const prompt = '用一句话描述秋天的景色'

  console.log('=== Temperature = 0 ===')
  const lowTemp = await temperatureExperiment(prompt, 0, 5)
  lowTemp.forEach((r, i) => console.log(`第 ${i + 1} 次: ${r}`))

  console.log('\n=== Temperature = 1 ===')
  const highTemp = await temperatureExperiment(prompt, 1, 5)
  highTemp.forEach((r, i) => console.log(`第 ${i + 1} 次: ${r}`))

  console.log('\n观察结论：')
  console.log('- temp=0 时，5 次输出措辞高度相似甚至完全相同')
  console.log('- temp=1 时，5 次输出措辞差异明显')
}

main()
```

观察结果分析：
1. **temperature = 0 时**：5 次回答的措辞几乎相同或完全相同，因为模型总是选择概率最高的下一个词
2. **temperature = 1 时**：5 次回答的核心意思相同，但措辞、句式有明显差异
3. **适合低 temperature 的场景**：代码生成、数据提取、JSON 格式化、分类任务——这些场景要求输出确定性和准确性

**要点**：
- Temperature 控制的是随机性，不是智力水平。temperature=1 不会让模型"更有创意地思考"
- 常见错误：觉得"回答不够好就调高 temperature"——如果模型本身不理解你的问题，调高 temperature 只会让输出更随机、更不可靠

### 练习二

**思路**：好的 System Prompt 应该包含四个部分：角色定义、能力范围、行为约束、输出格式。每个场景的侧重点不同——约束型场景（只答 Python）要强调拒绝逻辑，转换型场景（翻译成 JSON）要强调格式规范，引导型场景（苏格拉底式）要强调交互方式。

**答案**：

**场景 1：只回答 Python 问题的助手**

```typescript
const pythonOnlyPrompt = `你是一个 Python 编程助手。

你的职责：
- 回答用户关于 Python 语言的问题
- 提供 Python 代码示例和最佳实践
- 帮助调试 Python 代码

行为约束：
- 只回答 Python 相关的问题
- 如果用户问其他语言（如 JavaScript、Java、C++），礼貌地拒绝并说明"我只能回答 Python 相关的问题"
- 不确定的问题说"建议查阅 Python 官方文档"

输出格式：
- 代码示例用 Markdown 代码块包裹，标注 python
- 关键概念加粗
- 回答简洁，不超过 300 字`
```

**场景 2：把用户输入翻译成 JSON 的助手**

**场景 3：苏格拉底式提问的导师**

```typescript
const socraticPrompt = `你是一个使用苏格拉底式教学法的导师。

你的职责：
- 不直接给出答案，而是通过提问引导用户自己思考
- 每次回答包含 1-2 个引导性问题
- 帮助用户一步步推导出答案

行为约束：
- 绝不直接告诉用户最终答案
- 如果用户坚持要直接答案，继续用提问引导
- 如果用户完全卡住了，给一个最小的提示，然后继续提问
- 保持鼓励和耐心的语气

输出格式：
- 每次回答以一个引导性问题开头
- 用 1-2 句话解释为什么这个问题重要
- 以另一个更深入的问题结尾`
```

**要点**：
- System Prompt 不是越长越好，而是要结构清晰——角色、能力、约束、格式四段话就够了
- 常见错误：把所有细节都塞进 System Prompt（几千字），结果模型反而变得呆板或忽略部分内容。应该只写核心约束，细节通过 few-shot 示例补充

### 练习三

**思路**：故意触发错误是学习错误处理的最佳实践。每种错误对应不同的 HTTP 状态码和错误类型，需要不同的处理策略。关键是区分"可以重试的错误"和"不能重试的错误"。

**答案**：

```typescript
import 'dotenv/config'
import OpenAI from 'openai'

async function testErrors() {
  // 测试 1：无效的 API Key
  try {
    const badClient = new OpenAI({ apiKey: 'sk-invalid-key-12345' })
    await badClient.responses.create({
      model: 'gpt-5.5',
      input: [{ role: 'user', content: '你好' }]
    })
  } catch (error) {
    if (error instanceof OpenAI.AuthenticationError) {
      console.log('测试 1 - 认证错误:', error.status, error.message)
      // 401: API Key 无效 → 检查配置，不重试
    }
  }

  // 测试 2：超过 token 限制的超长输入
  try {
    const longMessage = '请分析这段代码：' + 'x'.repeat(500000)
    await new OpenAI().responses.create({
      model: 'gpt-5.5',
      input: [{ role: 'user', content: longMessage }]
    })
  } catch (error) {
    if (error instanceof OpenAI.BadRequestError) {
      console.log('测试 2 - 输入过长:', error.status, error.message)
      // 400: 上下文过长 → 缩短输入或分段处理
    }
  }

  // 测试 3：不存在的模型名
  try {
    await new OpenAI().responses.create({
      model: 'gpt-99-does-not-exist',
      input: [{ role: 'user', content: '你好' }]
    })
  } catch (error) {
    if (error instanceof OpenAI.NotFoundError) {
      console.log('测试 3 - 模型不存在:', error.status, error.message)
      // 404: 模型名错误 → 检查拼写
    }
  }

  // 测试 4：无网络（需要手动断开网络后运行）
  try {
    await new OpenAI().responses.create({
      model: 'gpt-5.5',
      input: [{ role: 'user', content: '你好' }]
    })
  } catch (error) {
    if (error instanceof OpenAI.APIConnectionError) {
      console.log('测试 4 - 网络错误:', error.message)
      // 网络断开 → 检查连接，可以重试
    }
  }
}

testErrors()
```

**要点**：
- 错误处理的核心是区分错误类型：认证错误（401）不重试，限流（429）等待后重试，输入过长（400）缩短输入，网络错误检查连接后重试
- 常见错误：用一个笼统的 `catch (error) { console.log(error) }` 处理所有错误，不区分类型，导致无法针对性处理——用户看到"未知错误"完全不知道该怎么办

---

## 常见误区

1. **"Temperature 调高一点回答更聪明"**：Temperature 控制的是随机性，不是智力。Temperature=1 不会让模型"更有创意地思考"，它只是让模型更倾向于选择低概率的词。对于代码生成、数据提取这类任务，高 Temperature 只会让你的输出更不可靠。

2. **"不设 max_output_tokens，让模型自由发挥"**：不设上限意味着模型可能生成很长的回答，直接吃掉你的预算。一个"写篇文章"的请求可能消耗几千个 output token（输出价格是输入的 4 倍）。总是根据场景设置合理的上限。

3. **"System Prompt 写得越长越好"**：有人把 System Prompt 写成几千字的"岗位说明书"，结果模型反而变得呆板或忽略部分内容。好的 System Prompt 应该简洁明确——角色、能力范围、行为约束、输出格式，四段话就够了。

4. **"错误处理等上线再说"**：不处理 429（限流）错误，用户一多就全部报错；不处理超时，用户看着转圈不知道发生了什么；不处理空输出，前端渲染出 `undefined`。这些都应该在第一次写 API 调用时就处理好。

---

## 工程建议

1. **根据任务类型固定 Temperature**：代码生成和数据提取用 0-0.2，日常对话用 0.7，创意写作用 0.8-1.0。不要在每个请求里让用户自己选 Temperature——他们不知道这个参数是什么意思，也不应该知道。

2. **max_output_tokens 和 Prompt 配合使用**：硬限制（max_output_tokens）防止预算失控，软限制（Prompt 里说"用 100 字总结"）引导模型输出合理长度。两者结合效果最好。

3. **System Prompt 版本化管理**：把 System Prompt 存在代码仓库或数据库里，像管理代码一样管理它。每次修改都要有记录，出了问题可以回滚。不要把 Prompt 硬编码在每个 API 调用里。

4. **统一错误处理和用户提示**：封装一个 `safeChat` 函数，内部处理所有错误类型，对外只返回"成功 + 回答"或"失败 + 用户可理解的提示"。不要让前端直接处理 OpenAI 的错误码——用户不需要知道什么是 429。

---

## 小结

本课的核心要点：

1. **Messages 三种角色**：system（指令）、user（输入）、assistant（历史回答）
2. **Temperature**：0 最确定，1 最随机；代码用 0，对话用 0.7，创意用 1
3. **Max Tokens**：控制输出长度和成本；输出比输入更贵
4. **status**：completed（完成）、incomplete（未完整生成）、failed（失败）
5. **错误处理**：认证、限流、超时、网络——每种都需要不同的处理策略
