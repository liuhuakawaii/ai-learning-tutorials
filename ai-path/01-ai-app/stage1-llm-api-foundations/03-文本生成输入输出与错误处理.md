# 第3课：第一次真正的问答调用

> **前置知识**：第 2 课的项目配置和首次 API 调用
> **预计时长**：30 分钟

## 从"能调通"到"能用"

第 2 课我们跑通了 API 调用，模型返回了一段文字。但如果你把这个调用放到 AI Knowledge Workspace 里做问答，会遇到几个问题：

同一个问题问两遍，措辞完全不同。有时候回答太长，啰嗦一堆你不需要的内容。有时候回答太短，关键信息缺失。偶尔模型还会编造文档里不存在的东西。

这节课要解决的是：让模型的回答在真实问答场景里可控、可预期。

## 给模型一个身份

上节课的调用只发了一条 user 消息。模型不知道自己是谁，每次都在自由发挥。在真实应用里，你需要用 system 消息告诉模型它的角色和约束。

```typescript
// src/lib/chat.ts
import openai from './openai'

interface AskOptions {
  temperature?: number
  maxTokens?: number
}

export async function ask(
  question: string,
  context: string,
  options: AskOptions = {}
) {
  const { temperature = 0.3, maxTokens = 1000 } = options

  const response = await openai.responses.create({
    model: 'gpt-5.5',
    input: [
      {
        role: 'system',
        content: `你是一个知识库问答助手。根据提供的资料回答问题。

规则：
- 只基于提供的资料回答，不要编造
- 如果资料中没有相关信息，直接说"资料中没有相关信息"
- 引用时标注来源`
      },
      {
        role: 'user',
        content: `资料：
${context}

问题：${question}`
      }
    ],
    temperature,
    max_output_tokens: maxTokens,
  })

  return response.output_text ?? ''
}
```

system 消息做了几件事：定义角色（知识库问答助手）、约束行为（不编造、标注来源）、处理边界（资料不足时说不知道）。这不是装饰——没有它，模型可能把问题当成闲聊，或者自信地编造答案。

## temperature：什么时候要随机，什么时候要确定

temperature 控制模型选择下一个词时的随机程度。这个参数不是"越高越聪明"，而是"越高越随机"。

在 AI Knowledge Workspace 的问答场景里，我们想要的是可靠、准确的回答，不需要创意发挥。所以 temperature 应该设低（0.1-0.3）。

什么时候需要高 temperature？生成多个不同角度的摘要、头脑风暴式的笔记扩展、创意写作。这些场景需要多样性，可以设到 0.7-1.0。

一个常见的误判：觉得"回答太死板就调高 temperature"。如果模型回答死板，大概率是 prompt 的问题，不是 temperature 的问题。调高 temperature 只会让输出更随机，不会让它更"聪明"。

## max_output_tokens：控制成本的阀门

输出 token 的价格通常是输入的 4 倍。一个"写篇文章"的请求可能消耗 2000 个 output token，而你只需要一段摘要。

`max_output_tokens` 是硬限制——超过就截断。但光靠它不够，因为截断可能发生在句子中间，输出不完整。更好的做法是在 prompt 里说明期望的长度，再用 `max_output_tokens` 兜底：

```typescript
// 场景：生成摘要，期望 200 字以内
const response = await openai.responses.create({
  model: 'gpt-5.5',
  input: [
    {
      role: 'system',
      content: '用 200 字以内总结以下内容，保留关键信息。'
    },
    { role: 'user', content: documentText }
  ],
  max_output_tokens: 300,  // 留一些余量
  temperature: 0.3,
})
```

prompt 里的"200 字以内"是软限制，模型通常会遵守但不保证。`max_output_tokens: 300` 是硬限制，防止模型跑偏时烧钱。两者配合使用。

## 错误处理：第一次就要做

API 调用会失败。网络断开、Key 失效、请求太频繁、输入太长——这些不是"万一"，是"迟早"。

```typescript
import OpenAI from 'openai'

interface AskResult {
  success: boolean
  answer?: string
  error?: string
  tokens?: { input: number; output: number }
}

export async function safeAsk(
  question: string,
  context: string
): Promise<AskResult> {
  try {
    const response = await openai.responses.create({
      model: 'gpt-5.5',
      input: [
        { role: 'system', content: '你是一个知识库问答助手。只基于提供的资料回答。' },
        { role: 'user', content: `资料：\n${context}\n\n问题：${question}` }
      ],
      temperature: 0.3,
      max_output_tokens: 1000,
    })

    const answer = response.output_text
    if (!answer || answer.trim() === '') {
      return { success: false, error: '模型返回了空回答' }
    }

    return {
      success: true,
      answer,
      tokens: {
        input: response.usage?.input_tokens ?? 0,
        output: response.usage?.output_tokens ?? 0,
      },
    }
  } catch (error) {
    if (error instanceof OpenAI.AuthenticationError) {
      return { success: false, error: 'API Key 无效，请检查 .env 配置' }
    }
    if (error instanceof OpenAI.RateLimitError) {
      return { success: false, error: '请求太频繁，稍后再试' }
    }
    if (error instanceof OpenAI.BadRequestError) {
      return { success: false, error: '输入内容过长，尝试缩短上下文' }
    }
    if (error instanceof OpenAI.APIConnectionError) {
      return { success: false, error: '网络连接失败' }
    }
    return { success: false, error: `请求失败: ${error}` }
  }
}
```

关键判断：401（认证失败）不重试，Key 无效重试也没用。429（限流）可以等一下再试。400（输入过长）需要缩短内容。网络错误可以重试 1-2 次。

不要用一个笼统的 `catch (e) { console.log(e) }` 处理所有错误。用户看到"未知错误"完全不知道该怎么办，你排查问题时也无从下手。

## 把它接入知识工作台

现在把问答函数接入项目的 `ask` 命令。之前的版本只做关键词匹配和截取，现在加上真正的模型调用：

```typescript
// src/ask.ts
import 'dotenv/config'
import fs from 'node:fs/promises'
import path from 'node:path'
import { fileURLToPath } from 'node:url'
import { safeAsk } from './lib/chat'

const root = path.resolve(path.dirname(fileURLToPath(import.meta.url)), '..')
const indexFile = path.join(root, 'data', 'generated', 'index.json')
const query = process.argv.slice(2).join(' ').trim()

if (!query) {
  console.error('用法: npx tsx src/ask.ts "你的问题"')
  process.exit(1)
}

const index = JSON.parse(await fs.readFile(indexFile, 'utf8'))

// 简单关键词检索（后续阶段会用向量检索替代）
const queryTokens = query.toLowerCase().match(/[\p{Script=Han}|a-z0-9]+/gu) ?? []
const matches = index.chunks
  .map((chunk: any) => ({
    ...chunk,
    score: queryTokens.filter((t: string) => chunk.tokens.includes(t)).length,
  }))
  .filter((c: any) => c.score >= 2)
  .sort((a: any, b: any) => b.score - a.score)
  .slice(0, 3)

if (matches.length === 0) {
  console.log('资料中没有足够信息回答这个问题。')
  process.exit(0)
}

const context = matches
  .map((m: any) => `[来源: ${m.source}]\n${m.text}`)
  .join('\n\n---\n\n')

const result = await safeAsk(query, context)

if (result.success) {
  console.log(`\n问题：${query}`)
  console.log(`\n回答：${result.answer}`)
  console.log(`\n引用：`)
  for (const m of matches) {
    console.log(`  - ${m.source} / ${m.section}`)
  }
  console.log(`\n(token 使用：输入 ${result.tokens?.input}，输出 ${result.tokens?.output})`)
} else {
  console.error(`\n错误：${result.error}`)
}
```

对比之前的版本：现在回答不再是截取文档片段，而是模型基于检索到的资料生成的完整回答。system prompt 约束模型只基于资料回答，temperature 设低保证可靠性，max_output_tokens 控制成本。

## 练习

### 练习一：temperature 对比实验

用同一个问题（比如"这个产品的登录流程是什么"），分别以 temperature = 0 和 temperature = 1 各调用 3 次。记录每次的回答，观察：

- temperature = 0 时，3 次回答的措辞是否一致
- temperature = 1 时，3 次回答的差异有多大
- 哪种更适合知识库问答场景

### 练习二：为摘要生成设计参数

在 `src/lib/chat.ts` 中新增一个 `summarize` 函数，接收一段文档文本，返回 100 字以内的摘要。要求：

- system prompt 指定摘要风格和长度
- temperature 和 max_output_tokens 适合摘要场景
- 返回结果包含 token 使用量

### 练习三：触发并处理错误

写一个 `src/examples/error-test.ts`，分别触发以下错误并正确捕获：

- 使用无效 API Key（401）
- 使用不存在的模型名（404）
- 发送超长输入（400）

每种错误打印用户可理解的提示信息。

## 参考答案

### 练习一

temperature = 0 时，3 次回答措辞高度一致，有时完全相同。temperature = 1 时，核心信息相同但表达方式每次都不同。知识库问答适合 temperature = 0.1-0.3——需要准确，不需要多样性。

### 练习二

```typescript
export async function summarize(text: string) {
  const response = await openai.responses.create({
    model: 'gpt-5.5',
    input: [
      {
        role: 'system',
        content: '用 100 字以内总结以下内容。只保留关键信息，不要废话。'
      },
      { role: 'user', content: text }
    ],
    temperature: 0.3,
    max_output_tokens: 200,
  })

  return {
    summary: response.output_text ?? '',
    tokens: response.usage?.total_tokens ?? 0,
  }
}
```

### 练习三

```typescript
import 'dotenv/config'
import OpenAI from 'openai'

async function testErrors() {
  // 401: 无效 Key
  try {
    const bad = new OpenAI({ apiKey: 'sk-invalid' })
    await bad.responses.create({
      model: 'gpt-5.5',
      input: [{ role: 'user', content: '你好' }],
    })
  } catch (e) {
    if (e instanceof OpenAI.AuthenticationError) {
      console.log('401 认证失败:', e.message)
    }
  }

  // 404: 不存在的模型
  try {
    await new OpenAI().responses.create({
      model: 'gpt-99-does-not-exist',
      input: [{ role: 'user', content: '你好' }],
    })
  } catch (e) {
    if (e instanceof OpenAI.NotFoundError) {
      console.log('404 模型不存在:', e.message)
    }
  }

  // 400: 输入过长
  try {
    await new OpenAI().responses.create({
      model: 'gpt-5.5',
      input: [{ role: 'user', content: 'x'.repeat(500000) }],
    })
  } catch (e) {
    if (e instanceof OpenAI.BadRequestError) {
      console.log('400 输入过长:', e.message)
    }
  }
}

testErrors()
```
