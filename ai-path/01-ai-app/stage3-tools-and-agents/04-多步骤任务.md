# 第4课：多步骤任务——计划、执行、观察、修正

> **前置知识**：第 1-3 课的工具调用基础
> **预计时长**：35 分钟

## 为什么单步不够

用户对 AI 助手说："帮我查一下上周保存的笔记，整理成一份周报提纲，保存为新笔记。"

这个任务需要三步工具调用，而且步骤之间有依赖——不查到笔记就无法整理，没整理完就无法保存。模型一次性输出所有工具调用行不通，因为它不知道中间结果是什么。

解决方案：**走一步看一步**——先行动，观察结果，再决定下一步。这就是 ReAct 模式。

## ReAct 循环

```
用户："帮我查上周的笔记，整理成周报提纲，保存为新笔记"

第 1 轮：
  Thought: 需要先搜索上周的笔记
  Action:  search_notes({ query: "*", date_range: "last_week" })
  Observation: 找到 5 条笔记...

第 2 轮：
  Thought: 有了笔记内容，现在整理成周报提纲
  Action:  （模型直接生成提纲，不需要工具）
  Observation: 生成了提纲...

第 3 轮：
  Thought: 需要把提纲保存为新笔记
  Action:  save_note({ content: "周报提纲...", tags: ["周报"] })
  Observation: 保存成功，id: note-456

最终回答："已整理完成并保存为新笔记（note-456）。提纲包含 3 个重点..."
```

## 实现

```typescript
const MAX_ITERATIONS = 10

async function multiStepChat(userMessage: string) {
  const messages = [
    {
      role: 'system',
      content: `你可以调用多个工具完成任务。每次调用工具后，观察结果，然后决定下一步。任务完成时直接给出最终回答。`,
    },
    { role: 'user', content: userMessage },
  ]

  const steps: { toolCalls: any[]; result: any }[] = []

  for (let i = 0; i < MAX_ITERATIONS; i++) {
    const response = await openai.responses.create({
      model: 'gpt-5.5',
      input: messages,
      tools,
      tool_choice: 'auto',
    })

    const toolCalls = response.output.filter(item => item.type === 'function_call')

    // 没有工具调用 → 模型认为任务完成，直接回答
    if (toolCalls.length === 0) {
      return { answer: response.output_text, steps }
    }

    // 执行工具
    const toolResults = await executeToolCalls(toolCalls)
    steps.push({ toolCalls, result: toolResults })

    // 把工具结果加入上下文，继续下一轮
    messages.push(...response.output, ...toolResults)
  }

  return { answer: '达到最大迭代次数，任务未完成', steps }
}
```

核心逻辑：循环调用模型，每轮检查是否有工具调用。有就执行并继续，没有就认为任务完成。

## 最大迭代次数：防止死循环

`MAX_ITERATIONS = 10` 是安全阀。没有它，模型可能陷入无限循环——反复调用同一个工具、反复生成相同的内容。

为什么是 10？大多数真实任务 3-5 步就能完成。如果超过 10 步还没完成，大概率是模型理解错了任务或者陷入了循环。宁可停下来让任务失败，也不要无限跑下去消耗 token。

## 高风险操作必须停下来

有些工具不能自动执行——发送邮件、删除文件、支付、授权。这些操作一旦执行就无法撤回。

```typescript
const REQUIRES_CONFIRMATION = ['send_email', 'delete_file', 'make_payment']

async function executeToolCall(call: any, requireConfirmation: boolean = true) {
  if (requireConfirmation && REQUIRES_CONFIRMATION.includes(call.name)) {
    // 返回待确认状态，而不是直接执行
    return {
      type: 'function_call_output',
      call_id: call.call_id,
      output: JSON.stringify({
        status: 'pending_confirmation',
        message: `需要用户确认：即将执行 ${call.name}`,
        args: JSON.parse(call.arguments),
      }),
    }
  }

  // 直接执行
  return await executeToolCallDirect(call)
}
```

模型会看到"需要用户确认"的结果，然后告诉用户："我准备发送邮件给张三，确认吗？"用户确认后才真正执行。

## 参考答案

测试时观察每一轮的 Thought 和 Action 是否合理。如果模型在第 1 轮就尝试保存笔记（没有先搜索），说明 system prompt 需要引导模型先分析任务再行动。

**关键判断**：不要把所有工具都标记为高风险。搜索、查询是只读操作，可以自动执行。只有写入、删除、发送类操作才需要确认。确认太多会让用户体验变差。
