# 第1课：工具调用原理——模型为什么需要工具

> **前置知识**：阶段一的大模型 API 基础
> **预计时长**：25 分钟

## 模型的边界

你接到一个需求：让用户问 AI 助手"我上周保存了哪些笔记"。你用纯模型调用试了一下：

```
用户："我上周保存了哪些笔记？"
模型："抱歉，我无法访问你的笔记数据。"
```

或者更糟糕的情况——模型编造了一个答案：

```
模型："你上周保存了3条笔记，分别是..."
（实际上模型根本不知道，它在编造）
```

模型只能生成文本。它不能查数据库、不能读文件、不能调 API。要让它能"做事"，需要工具调用。

## 工具调用的三步流程

```
用户："帮我保存这条笔记：明天下午3点开会"

步骤 1：模型判断需要调用工具
  模型输出：{
    "tool": "save_note",
    "arguments": { "content": "明天下午3点开会", "tags": ["会议"] }
  }

步骤 2：系统执行工具
  调用保存笔记的函数 → 返回 { "id": "note-123", "saved": true }

步骤 3：模型基于工具结果生成回答
  模型输出："已保存。笔记编号 note-123。"
```

关键点：**模型不执行工具，它只决定调用哪个工具、传什么参数。** 真正的执行由你的代码完成。

## 在 Knowledge Workspace 中定义工具

这个项目需要的工具：

```typescript
const tools = [
  {
    type: 'function' as const,
    function: {
      name: 'save_note',
      description: '保存一条笔记。当用户要求记录信息、保存重要内容时使用。',
      parameters: {
        type: 'object',
        properties: {
          content: { type: 'string', description: '笔记内容' },
          tags: { type: 'array', items: { type: 'string' }, description: '标签' },
        },
        required: ['content'],
      },
    },
  },
  {
    type: 'function' as const,
    function: {
      name: 'create_task',
      description: '创建待办任务。当用户要求设置提醒、创建待办、生成行动项时使用。',
      parameters: {
        type: 'object',
        properties: {
          title: { type: 'string', description: '任务标题' },
          due_date: { type: 'string', description: '截止日期，ISO 8601 格式' },
          priority: { type: 'string', enum: ['low', 'medium', 'high'] },
        },
        required: ['title'],
      },
    },
  },
  {
    type: 'function' as const,
    function: {
      name: 'search_notes',
      description: '搜索历史笔记。当用户询问之前保存过什么、查找历史记录时使用。',
      parameters: {
        type: 'object',
        properties: {
          query: { type: 'string', description: '搜索关键词' },
          limit: { type: 'number', description: '返回数量，默认 10' },
        },
        required: ['query'],
      },
    },
  },
]
```

工具设计的核心原则：**单一职责**（每个工具只做一件事）、**清晰描述**（让模型知道何时使用）、**明确参数**（类型、必填、取值范围）。

## 完整的调用流程

```typescript
async function chatWithTools(userMessage: string) {
  const input = [{ role: 'user', content: userMessage }]

  // 第一步：发给模型
  const response = await openai.responses.create({
    model: 'gpt-5.5',
    input,
    tools,
    tool_choice: 'auto',
  })

  // 检查模型是否要求调用工具
  const toolCalls = response.output.filter(item => item.type === 'function_call')

  if (toolCalls.length > 0) {
    // 第二步：执行工具
    const toolResults = await executeToolCalls(toolCalls)

    // 第三步：把工具结果发回模型
    const finalResponse = await openai.responses.create({
      model: 'gpt-5.5',
      input: [...input, ...response.output, ...toolResults],
    })
    return finalResponse.output_text
  }

  return response.output_text
}

async function executeToolCalls(toolCalls: any[]) {
  const results = []
  for (const call of toolCalls) {
    const args = JSON.parse(call.arguments)
    let result

    if (call.name === 'save_note') {
      result = await saveNote(args)
    } else if (call.name === 'create_task') {
      result = await createTask(args)
    } else if (call.name === 'search_notes') {
      result = await searchNotes(args)
    }

    results.push({
      type: 'function_call_output',
      call_id: call.call_id,
      output: JSON.stringify(result),
    })
  }
  return results
}
```

## 工具失败怎么办

工具可能超时、返回错误、甚至不存在。如果不处理，整个对话流程会卡住。

```typescript
async function executeToolCall(call: any) {
  try {
    const args = JSON.parse(call.arguments)
    const result = await toolRegistry[call.name](args)
    return { type: 'function_call_output', call_id: call.call_id, output: JSON.stringify(result) }
  } catch (error) {
    return {
      type: 'function_call_output',
      call_id: call.call_id,
      output: JSON.stringify({ error: `工具执行失败: ${error.message}` }),
    }
  }
}
```

工具失败时返回有意义的错误信息，模型会基于这个错误信息告诉用户出了什么问题，而不是卡住不动。

## 什么时候需要工具

判断标准：**模型能否仅凭自身知识完成任务？**

- 需要工具：查询数据库、读写文件、调用 API、精确计算、获取实时数据
- 不需要工具：纯文本生成、知识问答、创意写作、格式转换

不要所有问题都调用工具——增加延迟和成本，纯文本生成任务直接让模型回答就好。

## 参考答案

工具名要用动词+名词的语义化命名（`save_note`），不能用 `func1`。description 要写清楚"什么时候用"而不只是"做什么"——模型靠 description 决定是否调用这个工具。

**关键判断**：工具数量控制在 10 个以内。工具越多，模型选择错误的概率越高。如果超过 10 个，考虑按场景分组动态加载。
