# 04 向量数据库实战

> 向量检索是 RAG 的核心——Embedding 质量和索引策略直接决定检索效果。

## 场景引入

RAG 系统上线后，用户反馈检索延迟高达 3 秒，而且搜出来的内容经常和问题不相关。排查发现，10 万条文档 chunk 没有创建向量索引，全量扫描导致性能极差；同时 Embedding 模型选型不当，中文语义相似度计算不准确。向量数据库的部署和优化是 RAG 系统的基石。

## 学习目标

- 部署和配置 pgvector
- 理解 Embedding 模型的选择和使用
- 实现高效的向量存储和检索
- 掌握索引优化策略

## 前置要求

- 已完成阶段 1 的 PostgreSQL 部署
- 理解向量和相似度的基本概念

## 为什么用 pgvector

| 方案 | 优点 | 缺点 |
|------|------|------|
| **pgvector** | 和 PostgreSQL 一体化、SQL 查询、事务安全 | 性能不如专用向量库 |
| Pinecone | 托管、简单 | 付费、数据在外部 |
| Milvus | 高性能 | 部署复杂、多一个组件 |
| Chroma | 轻量、简单 | 不适合生产 |

**pgvector 的核心优势**：不需要额外部署向量数据库，SQL 和向量查询在同一个数据库里，事务安全。

## pgvector 部署

Docker Compose 已经包含了 pgvector 镜像。启用扩展：

```sql
-- 在 PostgreSQL 中启用 pgvector 扩展
CREATE EXTENSION IF NOT EXISTS vector;
```

SQLAlchemy 中使用：

```python
# backend/app/models/document.py
from pgvector.sqlalchemy import Vector

class DocumentChunk(Base):
    __tablename__ = "document_chunks"
    
    id: Mapped[str] = mapped_column(String(36), primary_key=True)
    document_id: Mapped[str] = mapped_column(String(36), ForeignKey("documents.id"))
    content: Mapped[str] = mapped_column(Text)
    embedding = mapped_column(Vector(1536))  # OpenAI embedding 维度
    metadata_: Mapped[dict] = mapped_column("metadata", JSON, default=dict)
    chunk_index: Mapped[int] = mapped_column(Integer)
```

## Embedding 模型选择

| 模型 | 维度 | 价格 | 质量 | 适用 |
|------|------|------|------|------|
| text-embedding-3-small | 1536 | $0.02/1M tokens | 好 | 通用场景 |
| text-embedding-3-large | 3072 | $0.13/1M tokens | 很好 | 高精度需求 |
| BGE-M3 | 1024 | 免费（本地） | 好 | 中文场景、隐私要求 |
| GTE-large | 1024 | 免费（本地） | 好 | 中文场景 |

```python
# backend/app/services/embedding_service.py
from openai import AsyncOpenAI

class EmbeddingService:
    """Embedding 服务"""
    
    def __init__(self, provider: str = "openai", model: str = "text-embedding-3-small"):
        self.provider = provider
        self.model = model
        self.client = AsyncOpenAI() if provider == "openai" else None
    
    async def embed(self, text: str) -> list[float]:
        """生成单个文本的 Embedding"""
        if self.provider == "openai":
            response = await self.client.embeddings.create(
                model=self.model,
                input=text,
            )
            return response.data[0].embedding
        else:
            raise ValueError(f"Unknown provider: {self.provider}")
    
    async def batch_embed(self, texts: list[str]) -> list[list[float]]:
        """批量生成 Embedding（OpenAI 支持批量）"""
        if self.provider == "openai":
            # OpenAI 每次最多 2048 个文本
            all_embeddings = []
            for i in range(0, len(texts), 2048):
                batch = texts[i:i + 2048]
                response = await self.client.embeddings.create(
                    model=self.model,
                    input=batch,
                )
                embeddings = [item.embedding for item in response.data]
                all_embeddings.extend(embeddings)
            return all_embeddings
        else:
            return [await self.embed(text) for text in texts]
```

## 向量存储

```python
# backend/app/services/vector_store.py
from sqlalchemy.ext.asyncio import AsyncSession
from sqlalchemy import select, text
from pgvector.sqlalchemy import Vector

class VectorStore:
    """向量存储服务"""
    
    def __init__(self, db: AsyncSession, embedding_service: EmbeddingService):
        self.db = db
        self.embedding = embedding_service
    
    async def add_chunks(
        self,
        document_id: str,
        chunks: list[DocumentChunk],
    ):
        """添加文档切片到向量库"""
        # 批量生成 Embedding
        texts = [chunk.content for chunk in chunks]
        embeddings = await self.embedding.batch_embed(texts)
        
        # 存储到数据库
        for chunk, embedding in zip(chunks, embeddings):
            db_chunk = DocumentChunkORM(
                id=str(uuid.uuid4()),
                document_id=document_id,
                content=chunk.content,
                embedding=embedding,
                metadata=chunk.metadata,
                chunk_index=chunk.chunk_index,
            )
            self.db.add(db_chunk)
        
        await self.db.flush()
    
    async def search(
        self,
        query: str,
        knowledge_base_id: str | None = None,
        top_k: int = 5,
        score_threshold: float = 0.7,
    ) -> list[dict]:
        """向量检索"""
        # 生成查询的 Embedding
        query_embedding = await self.embedding.embed(query)
        
        # pgvector 余弦相似度查询
        query_sql = """
            SELECT 
                id,
                document_id,
                content,
                metadata,
                1 - (embedding <=> :query_embedding) AS score
            FROM document_chunks
            WHERE 1 - (embedding <=> :query_embedding) > :threshold
            ORDER BY embedding <=> :query_embedding
            LIMIT :top_k
        """
        
        if knowledge_base_id:
            query_sql = """
                SELECT 
                    dc.id,
                    dc.document_id,
                    dc.content,
                    dc.metadata,
                    1 - (dc.embedding <=> :query_embedding) AS score
                FROM document_chunks dc
                JOIN documents d ON dc.document_id = d.id
                WHERE d.knowledge_base_id = :kb_id
                  AND 1 - (dc.embedding <=> :query_embedding) > :threshold
                ORDER BY dc.embedding <=> :query_embedding
                LIMIT :top_k
            """
        
        result = await self.db.execute(
            text(query_sql),
            {
                "query_embedding": str(query_embedding),
                "threshold": score_threshold,
                "top_k": top_k,
                "kb_id": knowledge_base_id,
            }
        )
        
        return [
            {
                "id": row.id,
                "document_id": row.document_id,
                "content": row.content,
                "metadata": row.metadata,
                "score": float(row.score),
            }
            for row in result
        ]
```

## 索引优化

当文档量超过 10 万条时，需要创建向量索引：

```sql
-- HNSW 索引（推荐：查询快，构建慢）
CREATE INDEX ON document_chunks USING hnsw (embedding vector_cosine_ops)
WITH (m = 16, ef_construction = 64);

-- IVFFlat 索引（构建快，查询稍慢）
CREATE INDEX ON document_chunks USING ivfflat (embedding vector_cosine_ops)
WITH (lists = 100);
```

```python
# 在 VectorStore 中添加索引管理
async def create_index(self, index_type: str = "hnsw"):
    """创建向量索引"""
    if index_type == "hnsw":
        await self.db.execute(text("""
            CREATE INDEX IF NOT EXISTS idx_chunks_embedding_hnsw
            ON document_chunks USING hnsw (embedding vector_cosine_ops)
            WITH (m = 16, ef_construction = 64)
        """))
    elif index_type == "ivfflat":
        await self.db.execute(text("""
            CREATE INDEX IF NOT EXISTS idx_chunks_embedding_ivfflat
            ON document_chunks USING ivfflat (embedding vector_cosine_ops)
            WITH (lists = 100)
        """))
    
    await self.db.commit()
```

## 参考答案

### 练习 1

**思路**：调用 OpenAI Embedding API 生成向量，用余弦相似度验证语义关系。核心是理解 Embedding 的本质：语义相近的文本在向量空间中距离更近。

**答案**：

```python
import asyncio
import numpy as np
from openai import AsyncOpenAI

client = AsyncOpenAI()

TEXTS = [
    "星辰科技专业版定价 299 元/月",       # 价格相关
    "专业版每月收费 299 元",               # 价格相关（同义表达）
    "星辰科技成立于 2023 年",              # 公司信息
    "如何配置 SSO 单点登录",              # 技术问题
    "SSO 配置步骤详解",                   # 技术相关（同义表达）
    "退款流程是什么",                      # 售后问题
    "退货政策说明",                        # 售后相关
    "产品支持微信支付和支付宝",            # 支付方式
    "可以使用哪些付款方式",                # 支付相关（同义表达）
    "星辰科技总部位于深圳",                # 公司信息
]


async def get_embeddings(texts: list[str]) -> list[list[float]]:
    response = await client.embeddings.create(
        model="text-embedding-3-small",
        input=texts,
    )
    return [item.embedding for item in response.data]


def cosine_similarity(a, b):
    a, b = np.array(a), np.array(b)
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))


async def main():
    embeddings = await get_embeddings(TEXTS)

    # 验证语义相似的文本相似度更高
    pairs = [
        (0, 1, "价格相关：专业版定价 vs 专业版每月收费"),
        (3, 4, "技术相关：SSO 配置 vs SSO 配置步骤"),
        (5, 6, "售后相关：退款流程 vs 退货政策"),
        (0, 3, "不相关：价格 vs SSO 配置"),
        (0, 8, "不相关：价格 vs 付款方式"),
    ]

    for i, j, desc in pairs:
        sim = cosine_similarity(embeddings[i], embeddings[j])
        print(f"{desc}: 相似度={sim:.4f}")


asyncio.run(main())
```

**要点**：
- 语义相似的文本对（如"专业版定价"和"专业版每月收费"）相似度应 > 0.8
- 不相关的文本对（如"价格"和"SSO 配置"）相似度应 < 0.5
- 常见错误：用简单的字符串匹配代替语义相似度，无法处理同义词和近义词
- 注意 OpenAI API 的 rate limit，批量请求时做好分批处理

### 练习 2

**思路**：将文档 chunks 存入 pgvector，实现向量检索，并用一组测试问题验证检索相关性。

**答案**：

```python
import asyncio
from sqlalchemy.ext.asyncio import create_async_engine, AsyncSession
from sqlalchemy.orm import sessionmaker

DATABASE_URL = "postgresql+asyncpg://user:pass@localhost:5432/rag_db"

async def test_vector_store():
    engine = create_async_engine(DATABASE_URL)
    async_session = sessionmaker(engine, class_=AsyncSession)

    async with async_session() as db:
        embedding_service = EmbeddingService()
        vector_store = VectorStore(db, embedding_service)

        # 1. 添加文档 chunks
        chunks = [
            DocumentChunk(content="星辰科技专业版定价 299 元/月，支持 50 用户", metadata={"source": "pricing.pdf"}, chunk_index=0),
            DocumentChunk(content="基础版定价 99 元/月，支持 10 用户", metadata={"source": "pricing.pdf"}, chunk_index=1),
            DocumentChunk(content="SSO 配置需要在管理后台的安全设置中开启", metadata={"source": "admin_guide.pdf"}, chunk_index=2),
        ]
        await vector_store.add_chunks(document_id="doc1", chunks=chunks)
        await db.commit()

        # 2. 检索测试
        results = await vector_store.search("专业版多少钱", top_k=3)
        for r in results:
            print(f"score={r['score']:.4f}: {r['content'][:60]}")

        # 3. 验证相关性
        assert len(results) > 0, "检索结果为空"
        assert "299" in results[0]["content"], "最相关的结果应包含价格信息"
        print("检索相关性验证通过")


asyncio.run(test_vector_store())
```

**要点**：
- 存入前必须确保 pgvector 扩展已启用：`CREATE EXTENSION IF NOT EXISTS vector`
- Embedding 维度必须与表定义一致（text-embedding-3-small 是 1536 维）
- 常见错误：Embedding 模型和表定义的维度不匹配导致插入失败；score_threshold 设太高导致返回空结果

### 练习 3

**思路**：在 1 万条数据上对比无索引、HNSW、IVFFlat 的检索延迟和准确率，理解索引的 tradeoff。

**答案**：

```python
import asyncio
import time
import random

async def benchmark_indexes(db, embedding_service):
    # 准备 1 万条测试数据
    texts = [f"这是第 {i} 条测试文档，内容关于主题 {i % 100}" for i in range(10000)]
    embeddings = await embedding_service.batch_embed(texts)

    # 插入数据（假设已有 document_chunks 表）
    for i, (text, emb) in enumerate(zip(texts, embeddings)):
        await db.execute(
            text("INSERT INTO document_chunks (id, content, embedding) VALUES (:id, :content, :emb)"),
            {"id": str(uuid.uuid4()), "content": text, "emb": str(emb)},
        )
    await db.commit()

    query_embedding = await embedding_service.embed("关于主题 50 的内容")

    # 1. 无索引
    start = time.time()
    for _ in range(100):
        await db.execute(text("""
            SELECT content FROM document_chunks
            ORDER BY embedding <=> :q LIMIT 10
        """), {"q": str(query_embedding)})
    no_index_time = (time.time() - start) / 100

    # 2. 创建 HNSW 索引
    await db.execute(text("""
        CREATE INDEX ON document_chunks USING hnsw (embedding vector_cosine_ops)
        WITH (m = 16, ef_construction = 64)
    """))

    start = time.time()
    for _ in range(100):
        await db.execute(text("""
            SELECT content FROM document_chunks
            ORDER BY embedding <=> :q LIMIT 10
        """), {"q": str(query_embedding)})
    hnsw_time = (time.time() - start) / 100

    print(f"无索引平均延迟: {no_index_time*1000:.1f}ms")
    print(f"HNSW 平均延迟: {hnsw_time*1000:.1f}ms")
    print(f"加速比: {no_index_time/hnsw_time:.1f}x")
```

**要点**：
- 无索引：精确但慢（全量扫描），1 万条数据通常 100-500ms
- HNSW：查询快（< 10ms），但构建时间长，且是近似搜索（准确率可能略降）
- IVFFlat：构建快，查询稍慢于 HNSW，适合数据频繁更新的场景
- 常见错误：数据量小（< 1 万）时就建索引，反而增加了构建开销；应该在 10 万+ 时才考虑

## 工程建议

- Embedding 模型选定后不要轻易更换，切换模型意味着所有存量向量都要重新生成，成本巨大
- 文档量超过 10 万条时必须创建 HNSW 索引，构建时间虽长但查询性能提升一个数量级
- 批量 Embedding 时注意 API 限流（OpenAI 每分钟 token 限制），做好重试和分批处理
- 生产环境建议向量库和业务库分离部署，避免检索请求拖慢核心业务

## 本节要点

- pgvector 是企业级 RAG 的最佳选择：无需额外组件、SQL 兼容、事务安全
- Embedding 模型选择影响检索质量，中文场景考虑 BGE 或 GTE
- 向量索引在大数据量下必须创建，HNSW 是首选
- 批量 Embedding 能显著降低成本和延迟

## 常见误区

| 错误 | 原因 | 解决 |
|------|------|------|
| 检索结果为空 | score_threshold 太高 | 降低阈值到 0.5-0.7 |
| 检索延迟高 | 没有向量索引 | 创建 HNSW 索引 |
| Embedding 维度不匹配 | 不同模型维度不同 | 统一使用同一个模型 |
| 存储失败 | pgvector 扩展没启用 | `CREATE EXTENSION vector` |
