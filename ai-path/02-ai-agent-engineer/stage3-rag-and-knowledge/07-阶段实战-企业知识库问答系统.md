# 07 阶段实战：企业知识库问答系统

> 从文档上传到带引用的问答——RAG 的所有组件在这里组装成一个完整产品。

前面六节课分别学了 RAG 原理、文档解析、文本切分、向量数据库、检索策略和引用溯源。现在要组装成一个完整系统：用户上传文档，系统自动解析、切分、向化；用户提问，系统检索相关文档，LLM 基于文档生成带引用的回答。

这个知识库系统会直接接入毕业项目——后面 Agent 的工具调用、工作流的知识检索节点都会用到它。

## 文档处理 Pipeline

文档从上传到可检索，需要经过三步：解析、切分、向量化。

```python
# backend/app/workers/document_worker.py
async def process_document(payload: dict):
    document_id = payload["document_id"]
    file_path = payload["file_path"]
    
    # 1. 解析：PDF/Word/Markdown → 纯文本
    parser = DocumentParserFactory()
    parsed = await parser.parse(file_path)
    
    # 2. 切分：长文本 → 小 chunk
    splitter = RecursiveSplitter(chunk_size=500, chunk_overlap=50)
    chunks = splitter.split(parsed.content)
    
    # 3. 向量化：文本 → Embedding → 存入 pgvector
    embedding_service = EmbeddingService()
    vector_store = VectorStore(db, embedding_service)
    await vector_store.add_chunks(document_id, chunks)
    
    # 4. 更新文档状态
    document = await db.get(Document, document_id)
    document.status = "ready"
    document.chunk_count = len(chunks)
    await db.commit()
```

这三步必须异步执行。文档解析可能要几秒到几分钟（大 PDF），同步执行会阻塞 HTTP 请求。用消息队列把任务丢给 Worker，前端轮询状态。

## 检索策略

纯向量检索有时候不够——用户搜"退款流程"，向量检索可能匹配到语义相似但关键词不同的文档。混合检索（向量 + BM25）更稳：

```python
class RetrievalPipeline:
    async def retrieve(self, query: str, kb_id: str, top_k: int = 5) -> list[dict]:
        # 向量检索
        vector_results = await self.vector_store.search(query, kb_id, top_k=top_k * 2)
        
        # BM25 关键词检索
        bm25_results = await self.bm25_service.search(query, kb_id, top_k=top_k * 2)
        
        # 合并去重
        merged = self._merge_results(vector_results, bm25_results)
        
        # 重排序
        reranked = await self.reranker.rerank(query, merged, top_k=top_k)
        
        return reranked
```

混合检索的思路是：向量检索抓语义相似，BM25 抓关键词匹配，两者取并集后重排序。这比单一检索方式的召回率高 15-20%。

## RAG 问答 API

把检索和生成串起来，加上引用标注：

```python
CITATION_PROMPT = """请基于以下参考资料回答问题。

要求：
1. 回答必须基于参考资料，不要编造信息
2. 引用时标注来源，格式：[1][2]
3. 如果参考资料中没有相关信息，说"我找不到相关信息"

参考资料：
{contexts}

问题：{question}"""

@router.post("/sessions/{session_id}/messages/stream")
async def stream_rag_message(session_id, request, db, user):
    async def event_generator():
        # 1. 检索
        contexts = await retrieval_pipeline.retrieve(
            request.message, request.knowledge_base_id
        )
        
        # 2. 构建带引用的 Prompt
        formatted = "\n\n".join(
            f"[{i+1}] {c['content']}" for i, c in enumerate(contexts)
        )
        prompt = CITATION_PROMPT.format(contexts=formatted, question=request.message)
        
        # 3. 流式生成
        full_answer = ""
        async for chunk in llm.stream_chat([{"role": "user", "content": prompt}]):
            full_answer += chunk.content
            yield sse_event({"type": "chunk", "content": chunk.content})
        
        # 4. 发送引用信息
        yield sse_event({
            "type": "citations",
            "sources": [{"index": i+1, "content": c["content"][:200], "document": c["filename"]}
                       for i, c in enumerate(contexts)],
        })
        yield sse_event({"type": "done"})
    
    return StreamingResponse(event_generator(), media_type="text/event-stream")
```

引用标注的关键是在 Prompt 里要求 LLM 用 `[1][2]` 格式引用，然后前端把引用数字渲染成可点击的链接，点击跳转到原文。

## 前端：知识库管理

知识库管理页面需要支持：上传文档、查看处理状态、删除文档。

```vue
<template>

<script setup lang="ts">
const columns = [
  { title: '文件名', key: 'filename' },
```

文档上传后状态是 `processing`，Worker 处理完变成 `ready`。前端轮询状态，处理中显示进度条。

## 练习

### 练习 1：实现文档处理 Pipeline

1. 实现 `RecursiveSplitter`：按段落边界切分，chunk_size=500 字符，overlap=50 字符
2. 实现 `EmbeddingService`：调用 OpenAI text-embedding-3-small 生成向量
3. 实现 `VectorStore.add_chunks`：把 chunk 和向量存入 pgvector

### 练习 2：实现混合检索

1. 向量检索：用 pgvector 的余弦相似度
2. BM25 检索：用 `rank_bm25` 库
3. 合并去重 + 重排序

测试：上传几篇文档，问一个关键词匹配的问题（如"退款流程"），验证混合检索比纯向量检索召回率更高。

### 练习 3：引用溯源

1. 在 Prompt 中要求 LLM 用 `[1][2]` 格式引用
2. 解析回答中的引用数字
3. 前端把引用渲染成可点击的链接

## 验收标准

- 上传文档后自动完成解析、切分、向量化
- 问答回答有引用标注，点击引用可跳转原文
- 混合检索比纯向量检索召回率提升 > 15%
- 检索延迟 < 500ms
- 文档处理失败有错误提示
