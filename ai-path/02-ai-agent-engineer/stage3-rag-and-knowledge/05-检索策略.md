# 05 检索策略

> 纯向量检索只是起点——混合检索和重排序才是企业级 RAG 的标配。

## 场景引入

用户搜索"退款流程"，向量检索返回了语义相近但关键词不同的"退货政策"文档，而真正包含"退款流程"四个字的那份操作指南反而没被召回。纯向量检索理解语义但不擅长精确匹配，纯关键词检索又无法处理同义词和近义词。企业级 RAG 需要混合检索策略来兼顾两者。

## 学习目标

- 实现多种检索策略（向量、关键词、混合）
- 理解重排序（Rerank）的原理和实现
- 掌握多路召回和结果融合
- 优化检索质量的实用技巧

## 前置要求

- 已完成向量数据库搭建
- 理解相似度计算

## 检索策略对比

| 策略 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| 向量检索 | 语义相似度 | 理解语义 | 可能漏掉精确关键词 |
| 关键词检索 | BM25 算法 | 精确匹配 | 不理解同义词 |
| 混合检索 | 两者加权 | 综合优势 | 需要调权重 |
| 多路召回 | 多策略并行 | 召回率最高 | 复杂度高 |

## 关键词检索（BM25）

```python
# backend/app/services/bm25_search.py
from rank_bm25 import BM25Okapi
import jieba

class BM25SearchService:
    """BM25 关键词检索"""
    
    def __init__(self):
        self.corpus: list[str] = []
        self.metadata: list[dict] = []
        self.bm25: BM25Okapi | None = None
    
    def index(self, chunks: list[dict]):
        """建立 BM25 索引"""
        self.corpus = [chunk["content"] for chunk in chunks]
        self.metadata = [chunk["metadata"] for chunk in chunks]
        
        # 中文分词
        tokenized = [list(jieba.cut(text)) for text in self.corpus]
        self.bm25 = BM25Okapi(tokenized)
    
    def search(self, query: str, top_k: int = 5) -> list[dict]:
        """BM25 检索"""
        if not self.bm25:
            return []
        
        tokenized_query = list(jieba.cut(query))
        scores = self.bm25.get_scores(tokenized_query)
        
        # 取 top_k
        top_indices = scores.argsort()[-top_k:][::-1]
        
        results = []
        for idx in top_indices:
            if scores[idx] > 0:
                results.append({
                    "content": self.corpus[idx],
                    "metadata": self.metadata[idx],
                    "score": float(scores[idx]),
                    "source": "bm25",
                })
        
        return results
```

## 混合检索

```python
class HybridSearchService:
    """混合检索——向量 + BM25"""
    
    def __init__(
        self,
        vector_store: VectorStore,
        bm25_service: BM25SearchService,
        vector_weight: float = 0.7,
        bm25_weight: float = 0.3,
    ):
        self.vector_store = vector_store
        self.bm25 = bm25_service
        self.vector_weight = vector_weight
        self.bm25_weight = bm25_weight
    
    async def search(
        self,
        query: str,
        knowledge_base_id: str | None = None,
        top_k: int = 5,
    ) -> list[dict]:
        # 1. 向量检索
        vector_results = await self.vector_store.search(
            query, knowledge_base_id, top_k=top_k * 2
        )
        
        # 2. BM25 检索
        bm25_results = self.bm25.search(query, top_k=top_k * 2)
        
        # 3. 结果融合（RRF - Reciprocal Rank Fusion）
        merged = self._rrf_merge(vector_results, bm25_results)
        
        return merged[:top_k]
    
    def _rrf_merge(
        self,
        list1: list[dict],
        list2: list[dict],
        k: int = 60,
    ) -> list[dict]:
        """RRF 融合算法"""
        scores: dict[str, float] = {}
        contents: dict[str, dict] = {}
        
        # list1 的排名分数
        for rank, item in enumerate(list1):
            key = item["content"][:100]  # 用内容前 100 字符作为 key
            scores[key] = scores.get(key, 0) + 1 / (k + rank + 1)
            contents[key] = item
        
        # list2 的排名分数
        for rank, item in enumerate(list2):
            key = item["content"][:100]
            scores[key] = scores.get(key, 0) + 1 / (k + rank + 1)
            if key not in contents:
                contents[key] = item
        
        # 按融合分数排序
        sorted_keys = sorted(scores.keys(), key=lambda k: scores[k], reverse=True)
        
        results = []
        for key in sorted_keys:
            item = contents[key].copy()
            item["rrf_score"] = scores[key]
            results.append(item)
        
        return results
```

## 重排序（Rerank）

检索返回初步结果后，用更精确的模型重新排序：

```python
# backend/app/services/reranker.py
from sentence_transformers import CrossEncoder

class Reranker:
    """重排序服务"""
    
    def __init__(self, model_name: str = "BAAI/bge-reranker-base"):
        self.model = CrossEncoder(model_name)
    
    def rerank(
        self,
        query: str,
        documents: list[dict],
        top_k: int = 5,
    ) -> list[dict]:
        """重排序"""
        if not documents:
            return []
        
        # 构建 query-document 对
        pairs = [(query, doc["content"]) for doc in documents]
        
        # 计算相关性分数
        scores = self.model.predict(pairs)
        
        # 按分数排序
        scored_docs = list(zip(documents, scores))
        scored_docs.sort(key=lambda x: x[1], reverse=True)
        
        results = []
        for doc, score in scored_docs[:top_k]:
            doc_copy = doc.copy()
            doc_copy["rerank_score"] = float(score)
            results.append(doc_copy)
        
        return results
```

## 完整检索 Pipeline

```python
class RetrievalPipeline:
    """完整检索 Pipeline"""
    
    def __init__(
        self,
        hybrid_search: HybridSearchService,
        reranker: Reranker | None = None,
    ):
        self.hybrid_search = hybrid_search
        self.reranker = reranker
    
    async def retrieve(
        self,
        query: str,
        knowledge_base_id: str | None = None,
        top_k: int = 5,
        use_rerank: bool = True,
    ) -> list[dict]:
        # 1. 混合检索（召回更多候选）
        candidates = await self.hybrid_search.search(
            query, knowledge_base_id, top_k=top_k * 3
        )
        
        # 2. 重排序（精排）
        if use_rerank and self.reranker:
            results = self.reranker.rerank(query, candidates, top_k=top_k)
        else:
            results = candidates[:top_k]
        
        return results
```

## Query 优化

用户的问题可能不够精确，需要优化：

```python
class QueryOptimizer:
    """查询优化器"""
    
    def __init__(self, llm: LLMService):
        self.llm = llm
    
    async def rewrite(self, query: str, history: list[dict] | None = None) -> str:
        """重写查询——补全上下文、消除歧义"""
        prompt = f"""请将以下用户问题重写为更适合检索的形式：
        
原始问题：{query}

{"对话历史：" + chr(10).join(f"{m['role']}: {m['content']}" for m in (history or [])[-3:])}

重写要求：
1. 补全省略的上下文
2. 消除代词（它、这个、那个）
3. 保持原意
4. 输出一行文本，不要解释

重写后的查询："""
        
        response = await self.llm.chat(
            messages=[{"role": "user", "content": prompt}],
            model="gpt-4o-mini",
            temperature=0,
        )
        
        return response.content.strip()
    
    async def expand(self, query: str) -> list[str]:
        """查询扩展——生成多个相关查询"""
        prompt = f"""请为以下查询生成 3 个不同角度的相关查询，用于检索：

原始查询：{query}

要求：
1. 每个查询从不同角度描述同一需求
2. 包含同义词和相关概念
3. 每行一个查询

相关查询："""
        
        response = await self.llm.chat(
            messages=[{"role": "user", "content": prompt}],
            model="gpt-4o-mini",
            temperature=0.3,
        )
        
        queries = [q.strip() for q in response.content.strip().split("\n") if q.strip()]
        return [query] + queries[:3]
```

## 参考答案

### 练习 1

**思路**：分别测试向量检索、BM25 检索和混合检索，用一组包含精确关键词和语义相似的测试问题，对比三者的召回率和准确率。

**答案**：

```python
import asyncio

TEST_CASES = [
    {"query": "退款流程", "expected_keyword": "退款", "expected_semantic": "退货"},
    {"query": "怎么修改密码", "expected_keyword": "密码", "expected_semantic": "账户安全"},
    {"query": "产品价格", "expected_keyword": "价格", "expected_semantic": "定价"},
    {"query": "SSO 配置", "expected_keyword": "SSO", "expected_semantic": "单点登录"},
    {"query": "联系客服", "expected_keyword": "客服", "expected_semantic": "人工服务"},
]


async def compare_retrieval_strategies(vector_store, bm25_service, chunks):
    # 建立 BM25 索引
    bm25_service.index(chunks)

    hybrid = HybridSearchService(vector_store, bm25_service)

    for case in TEST_CASES:
        query = case["query"]

        # 向量检索
        vector_results = await vector_store.search(query, top_k=5)

        # BM25 检索
        bm25_results = bm25_service.search(query, top_k=5)

        # 混合检索
        hybrid_results = await hybrid.search(query, top_k=5)

        # 检查是否命中
        def hit(results, keyword):
            return any(keyword in r["content"] for r in results)

        print(f"\n查询：{query}")
        print(f"  向量检索命中关键词: {hit(vector_results, case['expected_keyword'])}")
        print(f"  BM25 命中关键词: {hit(bm25_results, case['expected_keyword'])}")
        print(f"  混合检索命中关键词: {hit(hybrid_results, case['expected_keyword'])}")


async def optimize_weights(vector_store, bm25_service, test_cases):
    best_score = 0
    best_weights = (0.5, 0.5)

    for vw in [0.3, 0.5, 0.7, 0.8]:
        bw = 1.0 - vw
        hybrid = HybridSearchService(vector_store, bm25_service, vector_weight=vw, bm25_weight=bw)

        score = 0
        for case in test_cases:
            results = await hybrid.search(case["query"], top_k=5)
            if any(case["expected_keyword"] in r["content"] for r in results):
                score += 1

        if score > best_score:
            best_score = score
            best_weights = (vw, bw)

    print(f"最佳权重: vector={best_weights[0]}, bm25={best_weights[1]}, 命中率={best_score/len(test_cases):.2f}")
```

**要点**：
- 向量检索擅长语义匹配（"退款"能匹配"退货"），但可能漏掉精确关键词
- BM25 擅长精确匹配（"退款流程"四个字必须出现），但不理解同义词
- 混合检索通过 RRF 融合两者优势，通常比单一策略高 15-30% 召回率
- 常见错误：两路分数没归一化就融合，导致分数量级大的一路完全主导结果

**思路**：用 CrossEncoder 模型对初步检索结果做精排，对比重排序前后的准确率变化。

**答案**：

```python
from sentence_transformers import CrossEncoder

async def test_reranking(hybrid_search, test_cases):
    reranker = Reranker(model_name="BAAI/bge-reranker-base")

    for case in test_cases:
        query = case["query"]

        # 混合检索（召回更多候选）
        candidates = await hybrid_search.search(query, top_k=10)

        # 重排序
        reranked = reranker.rerank(query, candidates, top_k=5)

        print(f"\n查询：{query}")
        print("  重排序前 Top-3:")
        for i, r in enumerate(candidates[:3]):
            print(f"    {i+1}. {r['content'][:60]} (score={r.get('rrf_score', 0):.4f})")
        print("  重排序后 Top-3:")
        for i, r in enumerate(reranked[:3]):
            print(f"    {i+1}. {r['content'][:60]} (rerank_score={r['rerank_score']:.4f})")
```

**要点**：
- CrossEncoder 比 BiEncoder（Embedding）精度更高，因为它直接对 query-document pair 打分
- 重排序的延迟较高（每对需要一次前向传播），所以只对 top 候选做精排
- 常见错误：对全部候选做重排序，延迟不可接受；应该先召回 20-30 个候选，再重排序取 top 5
- BGE-reranker 对中文效果好，但延迟较高；轻量级模型如 ms-marco-MiniLM 更快但精度稍差

### 练习 3

**思路**：实现查询重写（补全上下文、消除歧义）和多查询扩展（生成同义查询），对比优化前后的召回率。

**答案**：

```python
async def test_query_optimization(retrieval_pipeline, test_cases):
    optimizer = QueryOptimizer(llm=LLMService())

    for case in test_cases:
        original_query = case["query"]

        # 原始查询检索
        original_results = await retrieval_pipeline.retrieve(original_query, top_k=5)

        # 重写查询
        rewritten = await optimizer.rewrite(original_query)
        rewritten_results = await retrieval_pipeline.retrieve(rewritten, top_k=5)

        # 多查询扩展
        expanded_queries = await optimizer.expand(original_query)
        all_results = []
        for q in expanded_queries:
            results = await retrieval_pipeline.retrieve(q, top_k=3)
            all_results.extend(results)
        # 去重
        seen = set()
        expanded_results = []
        for r in all_results:
            key = r["content"][:100]
            if key not in seen:
                seen.add(key)
                expanded_results.append(r)

        print(f"\n原始查询：{original_query}")
        print(f"  重写后：{rewritten}")
        print(f"  扩展后：{expanded_queries}")
        print(f"  原始命中: {any(case['expected_keyword'] in r['content'] for r in original_results)}")
        print(f"  重写命中: {any(case['expected_keyword'] in r['content'] for r in rewritten_results)}")
        print(f"  扩展命中: {any(case['expected_keyword'] in r['content'] for r in expanded_results[:5])}")
```

**要点**：
- 查询重写适合处理省略和指代（如"它的价格"→"星辰科技专业版的价格"）
- 多查询扩展适合提高召回率（如"退款流程"扩展为"退款流程"、"退货政策"、"如何申请退款"）
- 扩展后需要去重，避免同一 chunk 被多次返回
- 常见错误：扩展太多查询导致延迟翻倍；建议扩展 2-3 个就够了

## 工程建议

- 生产环境必须用混合检索，单一检索策略无法覆盖所有查询场景
- 重排序模型选择要平衡精度和延迟——BGE-reranker 精度高但慢，轻量级模型延迟低但精度稍差
- RRF 融合时两路分数要先归一化，否则量级差异会导致某一路完全失效
- 建议缓存高频查询的检索结果，相同问题重复检索是巨大的资源浪费

## 本节要点

- 混合检索（向量 + BM25）比单一检索效果好 15-30%
- 重排序是提升精度的最后一道关
- Query 优化能显著改善用户"问得不好"时的检索效果
- 完整 Pipeline：Query 优化 → 混合检索 → 重排序 → Top-K

## 常见误区

| 错误 | 原因 | 解决 |
|------|------|------|
| 检索结果不相关 | 权重没调好 | 调整 vector_weight 和 bm25_weight |
| 重排序太慢 | 模型太大 | 用轻量级 reranker 或只对 top 结果重排 |
| BM25 中文效果差 | 分词不准确 | 用 jieba 自定义词典 |
| 混合检索反而变差 | 两路分数不在同一量级 | 先归一化再融合 |
