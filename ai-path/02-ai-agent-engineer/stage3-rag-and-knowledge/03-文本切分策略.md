# 03 文本切分策略

> 切分粒度太大，检索不精确；切分太小，丢失上下文。这个平衡是 RAG 的核心调优点。

## 场景引入

你把一份 50 页的产品技术文档按 2000 字符切分后存入向量库。用户问"如何配置 SSO"时，检索到的 chunk 里混杂了安装步骤、API 文档和版本说明，真正的 SSO 配置步骤反而被淹没了。切分粒度的选择，直接决定了检索结果是否精准。

## 学习目标

- 理解不同切分策略的适用场景
- 实现固定切分、语义切分、递归切分
- 掌握 chunk 大小和重叠的调优方法
- 设计元数据以提升检索质量

## 前置要求

- 已完成文档解析 Pipeline
- 理解 Embedding 的基本概念

## 切分的核心矛盾

- **chunk 太大**：检索结果包含太多无关信息，干扰 LLM
- **chunk 太小**：丢失上下文，LLM 无法理解
- **chunk 边界不对**：一个完整的概念被切成两半

## 固定大小切分

最简单，但最粗暴：

```python
class FixedSizeSplitter:
    """固定大小切分"""
    
    def __init__(self, chunk_size: int = 500, chunk_overlap: int = 50):
        self.chunk_size = chunk_size
        self.chunk_overlap = chunk_overlap
    
    def split(self, text: str) -> list[str]:
        chunks = []
        start = 0
        
        while start < len(text):
            end = start + self.chunk_size
            chunk = text[start:end]
            chunks.append(chunk)
            start = end - self.chunk_overlap
        
        return chunks
```

问题：可能在句子中间切断，破坏语义完整性。

## 递归切分

按分隔符层级递归切分，尽量保持语义完整：

```python
class RecursiveSplitter:
    """递归切分——按分隔符层级切分"""
    
    def __init__(
        self,
        chunk_size: int = 500,
        chunk_overlap: int = 50,
        separators: list[str] | None = None,
    ):
        self.chunk_size = chunk_size
        self.chunk_overlap = chunk_overlap
        self.separators = separators or ["\n\n", "\n", "。", "！", "？", ".", "!", "?", "；", ";", " "]
    
    def split(self, text: str) -> list[str]:
        return self._recursive_split(text, self.separators)
    
    def _recursive_split(self, text: str, separators: list[str]) -> list[str]:
        if len(text) <= self.chunk_size:
            return [text] if text.strip() else []
        
        # 找到第一个能用的分隔符
        separator = separators[0] if separators else ""
        remaining_separators = separators[1:] if len(separators) > 1 else []
        
        if not separator:
            # 没有分隔符了，硬切
            return self._hard_split(text)
        
        # 按分隔符切分
        splits = text.split(separator)
        
        # 合并小块
        chunks = []
        current = ""
        for split in splits:
            if len(current) + len(split) + len(separator) <= self.chunk_size:
                current += (separator if current else "") + split
            else:
                if current:
                    chunks.append(current)
                # 如果单个 split 就超了，递归切分
                if len(split) > self.chunk_size:
                    chunks.extend(self._recursive_split(split, remaining_separators))
                else:
                    current = split
        if current:
            chunks.append(current)
        
        # 添加重叠
        return self._add_overlap(chunks)
    
    def _add_overlap(self, chunks: list[str]) -> list[str]:
        """添加重叠"""
        if self.chunk_overlap <= 0 or len(chunks) <= 1:
            return chunks
        
        result = [chunks[0]]
        for i in range(1, len(chunks)):
            # 从上一个 chunk 取末尾作为当前 chunk 的开头
            prev_tail = chunks[i - 1][-self.chunk_overlap:]
            result.append(prev_tail + chunks[i])
        
        return result
```

## 语义切分

基于 Embedding 相似度判断切分点——语义变化大的地方就是最佳切分点：

```python
class SemanticSplitter:
    """语义切分——在语义变化处切分"""
    
    def __init__(
        self,
        embedding_service,
        threshold: float = 0.5,
        min_chunk_size: int = 100,
        max_chunk_size: int = 1000,
    ):
        self.embedding = embedding_service
        self.threshold = threshold
        self.min_chunk_size = min_chunk_size
        self.max_chunk_size = max_chunk_size
    
    async def split(self, text: str) -> list[str]:
        # 先按句子切分
        sentences = self._split_sentences(text)
        if len(sentences) <= 1:
            return [text]
        
        # 计算每个句子的 Embedding
        embeddings = await self.embedding.batch_embed(sentences)
        
        # 计算相邻句子的相似度
        similarities = []
        for i in range(len(embeddings) - 1):
            sim = self._cosine_similarity(embeddings[i], embeddings[i + 1])
            similarities.append(sim)
        
        # 在相似度低于阈值处切分
        chunks = []
        current_chunk = [sentences[0]]
        
        for i, sim in enumerate(similarities):
            current_text = " ".join(current_chunk + [sentences[i + 1]])
            
            if sim < self.threshold and len(current_text) >= self.min_chunk_size:
                # 语义变化大，切分
                chunks.append(" ".join(current_chunk))
                current_chunk = [sentences[i + 1]]
            elif len(current_text) > self.max_chunk_size:
                # 超过最大长度，强制切分
                chunks.append(" ".join(current_chunk))
                current_chunk = [sentences[i + 1]]
            else:
                current_chunk.append(sentences[i + 1])
        
        if current_chunk:
            chunks.append(" ".join(current_chunk))
        
        return chunks
    
    def _split_sentences(self, text: str) -> list[str]:
        """按句子切分"""
        import re
        sentences = re.split(r'(?<=[。！？.!?])\s*', text)
        return [s.strip() for s in sentences if s.strip()]
    
    def _cosine_similarity(self, a: list[float], b: list[float]) -> float:
        import numpy as np
        a, b = np.array(a), np.array(b)
        return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))
```

## 元数据设计

好的元数据能显著提升检索质量：

```python
@dataclass
class ChunkMetadata:
    """Chunk 元数据"""
    source: str           # 来源（文件名/URL）
    source_type: str      # 来源类型（pdf/word/web）
    page: int | None      # 页码
    section: str | None   # 章节标题
    chunk_index: int      # 在文档中的序号
    total_chunks: int     # 文档总 chunk 数
    created_at: str       # 创建时间
    
    # 用于过滤
    document_id: str      # 文档 ID
    knowledge_base_id: str # 知识库 ID
    
    # 用于排序
    relevance_score: float | None = None

def enrich_chunks(chunks: list[str], document: ParsedDocument) -> list[DocumentChunk]:
    """为 chunks 添加元数据"""
    enriched = []
    for i, chunk in enumerate(chunks):
        metadata = ChunkMetadata(
            source=document.metadata["source"],
            source_type=document.metadata["format"],
            page=_find_page(chunk, document),
            section=_find_section(chunk, document),
            chunk_index=i,
            total_chunks=len(chunks),
            created_at=datetime.utcnow().isoformat(),
            document_id=document.metadata.get("document_id", ""),
            knowledge_base_id=document.metadata.get("kb_id", ""),
        )
        enriched.append(DocumentChunk(
            content=chunk,
            metadata=metadata.__dict__,
            chunk_index=i,
        ))
    return enriched
```

## 切分策略选型

| 策略 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| 固定大小 | 简单、快 | 可能切断语义 | 快速原型 |
| 递归切分 | 保持语义完整 | 需要调参 | 通用场景 |
| 语义切分 | 最智能 | 慢、需要 Embedding | 高质量需求 |

## 参考答案

### 练习 1

**思路**：用同一份文档分别调用三种切分器，对比切分数量、每段语义完整性和检索效果。核心是理解每种策略的 tradeoff：固定切分最快但最粗暴，递归切分性价比最高，语义切分最智能但最慢。

**答案**：

```python
import asyncio
import time

SAMPLE_TEXT = """
# 产品安装指南

## 系统要求
本产品支持 Windows 10/11、macOS 12+、Ubuntu 20.04+。
最低配置：8GB 内存，50GB 磁盘空间。
推荐配置：16GB 内存，100GB SSD。

## 安装步骤
1. 下载安装包：访问官网下载对应系统的安装包。
2. 运行安装程序：双击安装包，按提示完成安装。
3. 配置环境变量：将安装路径添加到 PATH。
4. 验证安装：运行 `product --version` 确认安装成功。

## 常见问题
Q: 安装时提示"权限不足"怎么办？
A: 请以管理员身份运行安装程序。Windows 右键选择"以管理员身份运行"，macOS/Linux 使用 sudo。

Q: 安装后命令找不到？
A: 请检查 PATH 环境变量是否正确配置。重启终端后重试。
""".strip()


async def compare_splitters():
    # 1. 固定大小切分
    fixed = FixedSizeSplitter(chunk_size=200, chunk_overlap=20)
    fixed_chunks = fixed.split(SAMPLE_TEXT)

    # 2. 递归切分
    recursive = RecursiveSplitter(chunk_size=200, chunk_overlap=20)
    recursive_chunks = recursive.split(SAMPLE_TEXT)

    # 3. 语义切分（需要 Embedding 服务）
    embedding = EmbeddingService()
    semantic = SemanticSplitter(embedding, threshold=0.5, min_chunk_size=50, max_chunk_size=400)
    semantic_chunks = await semantic.split(SAMPLE_TEXT)

    print(f"固定切分：{len(fixed_chunks)} 个 chunk")
    print(f"递归切分：{len(recursive_chunks)} 个 chunk")
    print(f"语义切分：{len(semantic_chunks)} 个 chunk")

    # 检查语义完整性
    for i, chunk in enumerate(recursive_chunks):
        print(f"\n--- 递归 chunk {i+1} ---")
        print(chunk[:150])


asyncio.run(compare_splitters())
```

**要点**：
- 固定切分可能在句子中间切断（如"最低配置：8GB 内" | "存，50GB 磁盘"），破坏语义
- 递归切分按 `\n\n` → `\n` → `。` 层级切分，能保持段落和句子完整性
- 语义切分在话题转换处切分（如"系统要求"→"安装步骤"），效果最好但需要调用 Embedding API
- 常见错误：只对比 chunk 数量，不检查每段内容是否语义完整

### 练习 2

**思路**：用不同 chunk_size 切分同一份文档，用一组测试问题做检索，计算每种 size 的检索准确率（Recall@K），找到最优平衡点。

**答案**：

```python
async def optimize_chunk_size(document_text: str, test_cases: list[dict]):
    sizes = [200, 500, 1000, 2000]
    results = {}

    for size in sizes:
        splitter = RecursiveSplitter(chunk_size=size, chunk_overlap=int(size * 0.1))
        chunks = splitter.split(document_text)

        # 生成 Embedding
        embedding_service = EmbeddingService()
        embeddings = await embedding_service.batch_embed(chunks)

        # 测试检索
        correct = 0
        for case in test_cases:
            query_embedding = await embedding_service.embed(case["question"])
            # 计算相似度
            scores = [cosine_similarity(query_embedding, emb) for emb in embeddings]
            top_indices = sorted(range(len(scores)), key=lambda i: scores[i], reverse=True)[:5]
            top_chunks = [chunks[i] for i in top_indices]

            # 检查是否包含答案
            if any(case["answer_keyword"] in chunk for chunk in top_chunks):
                correct += 1

        recall = correct / len(test_cases)
        results[size] = {"recall": recall, "chunk_count": len(chunks)}
        print(f"chunk_size={size}: Recall@5={recall:.2f}, chunks={len(chunks)}")

    return results
```

**要点**：
- chunk_size 越小，检索越精确但上下文越少；越大，上下文越完整但噪声越多
- 中文场景建议从 500 字符开始测试，英文可以从 1000 开始
- overlap 建议为 chunk_size 的 10-20%，太少会丢失边界信息，太多会增加冗余
- 常见错误：只看检索"是否返回结果"，不检查返回结果是否真正包含答案

```python
# VectorStore.search 中实现 metadata_filter
async def search_with_filter(self, query, metadata_filter=None, top_k=5):
    query_embedding = await self.embedding.embed(query)
    sql = """
        SELECT id, content, metadata,
               1 - (embedding <=> :query_embedding) AS score
        FROM document_chunks
        WHERE 1 - (embedding <=> :query_embedding) > 0.5
    """
    params = {"query_embedding": str(query_embedding), "top_k": top_k}

    if metadata_filter:
        for key, value in metadata_filter.items():
            if isinstance(value, dict):
                for op, val in value.items():
                    sql += f" AND metadata->>'{key}' {op} :filter_{key}"
                    params[f"filter_{key}"] = val
            else:
                sql += f" AND metadata->>'{key}' = :filter_{key}"
                params[f"filter_{key}"] = value

    sql += " ORDER BY embedding <=> :query_embedding LIMIT :top_k"
    result = await self.db.execute(text(sql), params)
    return [dict(row) for row in result]
```

**要点**：
- 元数据过滤要在向量相似度计算之前执行，减少计算量
- JSON 字段查询用 `metadata->>'key'` 语法，注意 pgvector 的 SQL 注入防护
- 常见错误：元数据存了但查询时没用上，等于白存；应该在检索 Pipeline 中暴露过滤参数

## 工程建议

- 生产环境首选递归切分，chunk_size 建议 500-800 字符，overlap 10-20%，这是性价比最高的起点
- 表格、代码块等结构化内容要特殊处理——整体作为一个 chunk，不要按字符数硬切
- 建立切分质量评估集，用 Recall@K 指标量化不同切分策略的效果，不要靠主观感觉调参
- 切分后建议缓存 Embedding 结果，避免重复计算带来的成本和延迟

## 本节要点

- 切分是 RAG 质量的关键调优点，没有"最佳"只有"最适合"
- 递归切分是性价比最高的选择，语义切分是质量最高的选择
- chunk 大小通常 300-1000 字符，overlap 10-20%
- 元数据能显著提升检索精度，不要忽略

## 常见误区

| 错误 | 原因 | 解决 |
|------|------|------|
| chunk 切断了表格 | 表格没有特殊处理 | 先提取表格，整体作为一个 chunk |
| 检索结果不相关 | chunk 太大，噪声太多 | 减小 chunk size |
| 回答缺乏上下文 | chunk 太小 | 增大 chunk size 或 overlap |
| 语义切分太慢 | 每个句子都调 Embedding | 批量 Embedding + 缓存 |
