# 01 认证与授权

> 没有认证的系统是裸奔——没有授权的系统是无差别放行。

你的 AI Agent 平台上线第一天，两个问题同时爆发：用户反馈 Token 两小时就过期，正在编辑的 Agent 配置全丢了；有用户发现猜对 URL 就能访问别人的知识库——系统完全没有权限隔离。你需要一套既安全又不影响体验的认证授权体系。

## JWT 双 Token 机制

单 Token 的困境：有效期太短，用户频繁登录；有效期太长，泄露风险大。解决方案是双 Token：

- **access_token**：短命（2 小时），用于接口认证，无状态校验
- **refresh_token**：长命（30 天），用于续期，需要查库确认未被吊销

```python
class AuthService:
    def __init__(self, secret_key: str):
        self.secret_key = secret_key
        self.access_expire = timedelta(hours=2)
        self.refresh_expire = timedelta(days=30)
    
    def create_tokens(self, user_id: str, device_id: str = "web") -> dict:
        now = datetime.now(timezone.utc)
        access_token = jwt.encode(
            {"sub": user_id, "type": "access", "device": device_id, "exp": now + self.access_expire},
            self.secret_key, algorithm="HS256",
        )
        refresh_token = jwt.encode(
            {"sub": user_id, "type": "refresh", "device": device_id, "exp": now + self.refresh_expire},
            self.secret_key, algorithm="HS256",
        )
        return {"access_token": access_token, "refresh_token": refresh_token}
```

access_token 过期后，前端用 refresh_token 换新的。刷新时同时签发新的 refresh_token（滑动窗口），避免同一个 refresh_token 长期有效。

## Token 刷新流程

```python
@router.post("/refresh")
async def refresh_token(body: RefreshRequest, db=Depends(get_db)):
    payload = auth.decode_token(body.refresh_token)
    if not payload or payload.get("type") != "refresh":
        raise HTTPException(401, "refresh_token 无效")
    
    # 验证 refresh_token 未被吊销
    token_hash = hashlib.sha256(body.refresh_token.encode()).hexdigest()
    device = await db.query("user_devices", user_id=payload["sub"], refresh_token_hash=token_hash)
    if not device:
        raise HTTPException(401, "refresh_token 已被吊销")
    
    # 签发新 Token
    new_tokens = auth.create_tokens(payload["sub"], payload["device"])
    await db.update("user_devices", device["id"], {
        "refresh_token_hash": hashlib.sha256(new_tokens["refresh_token"].encode()).hexdigest(),
    })
    return new_tokens
```

关键：refresh_token 必须查库验证。如果只做无状态校验，一旦泄露就无法吊销——用户改密码后旧 token 仍然有效。

通过 FastAPI 依赖注入统一做权限检查：

```python
def require_permission(permission: str):
    async def checker(request: Request, user=Depends(get_current_user)):
        rbac = request.app.state.rbac
        if not await rbac.check_permission(user["id"], permission):
            raise HTTPException(403, f"权限不足，需要: {permission}")
        return user
    return checker

@router.post("/agents")
async def create_agent(body: CreateAgentRequest, user=Depends(require_permission("agent:write"))):
    return await db.insert("agents", {**body.dict(), "owner_id": user["id"]})
```

每个需要鉴权的接口注入一个 `require_permission("xxx")` 依赖。遗漏一个就是安全漏洞——用依赖注入比在每个接口里手动写 `if` 判断可靠得多。

## API Key 管理

外部系统接入平台需要 API Key。Key 只在创建时返回一次，之后只存 hash：

```python
class APIKeyService:
    async def create_key(self, user_id: str, name: str, permissions: list[str]) -> dict:
        key = f"sk-{secrets.token_hex(32)}"
        key_hash = hashlib.sha256(key.encode()).hexdigest()
        await db.execute(
            "INSERT INTO api_keys (user_id, name, key_hash, permissions) VALUES (...)",
            {"user_id": user_id, "name": name, "key_hash": key_hash, "permissions": json.dumps(permissions)},
        )
        return {"key": key, "name": name}
```

## 关键判断

- **access_token 无状态，refresh_token 有状态。** access_token 验签即可，refresh_token 必须查库确认未被吊销。
- **权限检查用依赖注入，不要在每个接口里手写。** 遗漏一个就是安全漏洞。
- **API Key 只存 hash，创建时返回一次明文。** 数据库泄露时攻击者拿不到可用的 Key。
- **Token 密钥必须从环境变量读取。** 硬编码在代码里提交到 Git 就是事故。
