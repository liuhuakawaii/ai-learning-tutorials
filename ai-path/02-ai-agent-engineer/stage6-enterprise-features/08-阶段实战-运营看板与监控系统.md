# 08 阶段实战：运营看板与监控系统

> 没有看板的系统是黑盒——有了看板才能看见、管好、优化。

平台运行了一个月，老板问"有多少活跃用户？每个模型花了多少钱？"你打开数据库手动跑 SQL，拼凑出大概数字。第二天又有人问同样的问题。你需要一个实时监控看板，让所有人自己看。

这个看板是毕业项目的运营核心——用量统计、成本分析、质量监控全在这里。

## 统计 API

后端提供三个维度的统计数据：总览、按时间、按模型。

```python
@router.get("/overview")
async def get_overview(db=Depends(get_db), user=Depends(get_current_user)):
    session_count = (await db.execute(select(func.count()).select_from(ChatSession))).scalar() or 0
    message_count = (await db.execute(select(func.count()).select_from(Message))).scalar() or 0
    
    token_result = await db.execute(
        select(
            func.coalesce(func.sum(Message.input_tokens), 0),
            func.coalesce(func.sum(Message.output_tokens), 0),
            func.coalesce(func.sum(Message.cost), 0.0),
        )
    )
    row = token_result.one()
    
    return {
        "sessions": session_count,
        "messages": message_count,
        "total_input_tokens": row[0],
        "total_output_tokens": row[1],
        "total_cost": round(float(row[2]), 4),
    }

@router.get("/usage")
async def get_usage_stats(days: int = 7, db=Depends(get_db)):
    cutoff = datetime.now(timezone.utc) - timedelta(days=days)
    result = await db.execute(
        select(
            func.date(Message.created_at).label("date"),
            func.count().label("count"),
            func.sum(Message.input_tokens + Message.output_tokens).label("tokens"),
        )
        .where(Message.created_at >= cutoff)
        .group_by(func.date(Message.created_at))
        .order_by(func.date(Message.created_at))
    )
    return {"daily": [{"date": str(r.date), "messages": r.count, "tokens": r.tokens} for r in result.all()]}
```

统计查询要做缓存——聚合 SQL 在数据量大时很慢，建议每 5 分钟刷新一次。

## Prometheus 指标

自定义 Prometheus 中间件，记录请求量、延迟、错误率：

```python
def setup_metrics(app: FastAPI):
    _metrics = {"requests_total": 0, "errors_total": 0, "durations": []}
    
    @app.middleware("http")
    async def metrics_middleware(request: Request, call_next):
        start = time.perf_counter()
        _metrics["requests_total"] += 1
        try:
            response = await call_next(request)
            _metrics["durations"].append(time.perf_counter() - start)
            return response
        except Exception:
            _metrics["errors_total"] += 1
            raise
    
    @app.get("/metrics")
    async def metrics():
        durations = _metrics["durations"]
        avg = sum(durations) / len(durations) if durations else 0
        p95 = sorted(durations)[int(len(durations) * 0.95)] if len(durations) > 1 else 0
        return Response(
            content=f"http_requests_total {_metrics['requests_total']}\n"
                    f"http_request_duration_avg {avg:.3f}\n"
                    f"http_request_duration_p95 {p95:.3f}\n"
                    f"http_errors_total {_metrics['errors_total']}",
            media_type="text/plain",
        )
```

带参数的路径要归一化——`/api/v1/agents/abc123` 和 `/api/v1/agents/def456` 应该归为 `/api/v1/agents/{id}`，否则指标量随用户增长爆炸。

## 告警规则

监控的价值在于告警——出了问题能第一时间知道：

```yaml
# prometheus/rules.yml
groups:
  - name: ai-platform
    rules:
      - alert: HighErrorRate
        expr: http_errors_total / http_requests_total > 0.05
        for: 5m
        annotations:
          summary: "错误率超过 5%"
      
      - alert: HighLatency
        expr: http_request_duration_p95 > 2
        for: 5m
        annotations:
          summary: "P95 延迟超过 2 秒"
      
      - alert: HighCost
        expr: increase(llm_cost_total[1h]) > 10
        annotations:
          summary: "过去 1 小时 LLM 成本超过 $10"
```

告警通知分级：P0（服务不可用）电话通知，P1（性能下降）企微/钉钉，P2（非紧急）邮件。所有告警走同一条通道会导致重要告警被淹没。

## 练习

### 练习 1：实现统计 API

1. 实现 overview 接口（会话数、消息数、token 总量、成本）
2. 实现 usage 接口（按天聚合）
3. 实现 models 接口（按模型聚合）

### 练习 2：Prometheus 指标

1. 实现 HTTP 中间件，记录请求量和延迟
2. 路径归一化（`/api/v1/agents/{id}`）
3. 配置 Grafana Dashboard

### 练习 3：告警配置

1. 配置错误率告警（> 5%）
2. 配置延迟告警（P95 > 2s）
3. 配置成本告警（每小时 > $10）

## 验收标准

- 运营看板数据正确，支持时间范围筛选
- Prometheus 指标端点可访问
- Grafana 显示系统指标（请求量、延迟、错误率）
- 告警规则配置完成，异常时能通知
