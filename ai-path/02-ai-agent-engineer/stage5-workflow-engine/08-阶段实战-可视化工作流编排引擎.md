# 08 阶段实战：可视化工作流编排引擎

> 从编辑到执行到监控——把所有模块串成一个端到端可工作的引擎。

前面几节课分别实现了 DAG 编辑器、执行引擎、条件分支、人工审批、并行执行和 Skill 体系。但这些模块各自独立——编辑器保存的数据格式和执行引擎期望的格式对不上，审批恢复后执行上下文丢失，条件分支的结果传不到汇聚节点。这个实战要把所有模块串起来。

这个工作流引擎是毕业项目的核心功能之一——业务人员通过拖拽节点就能编排 AI 任务，不需要写代码。

## 执行引擎

核心是拓扑排序 + 逐节点执行：

```python
class WorkflowEngine:
    def __init__(self):
        self.node_handlers: dict[str, callable] = {}

    def register_handler(self, node_type: str, handler: callable):
        self.node_handlers[node_type] = handler

    def _topological_sort(self, nodes: list[dict], edges: list[dict]) -> list[str]:
        adj = {n["id"]: [] for n in nodes}
        in_degree = {n["id"]: 0 for n in nodes}
        for edge in edges:
            adj[edge["source"]].append(edge["target"])
            in_degree[edge["target"]] += 1

        queue = [nid for nid, deg in in_degree.items() if deg == 0]
        order = []
        while queue:
            node_id = queue.pop(0)
            order.append(node_id)
            for neighbor in adj.get(node_id, []):
                in_degree[neighbor] -= 1
                if in_degree[neighbor] == 0:
                    queue.append(neighbor)

        if len(order) != len(nodes):
            raise ValueError("工作流存在循环依赖")
        return order

    async def execute(self, workflow_data: dict) -> dict:
        nodes = workflow_data["nodes"]
        edges = workflow_data["edges"]
        execution_order = self._topological_sort(nodes, edges)
        node_map = {n["id"]: n for n in nodes}
        context = {**workflow_data.get("variables", {})}
        executions = []

        for node_id in execution_order:
            node = node_map[node_id]
            node_type = node.get("type", "unknown")
            handler = self.node_handlers.get(node_type)

            exec_result = {"node_id": node_id, "type": node_type, "status": "running", "input": dict(context)}

            if handler:
                try:
                    output = await handler(node, context)
                    exec_result["output"] = output
                    exec_result["status"] = "completed"
                    context.update(output)
                except Exception as e:
                    exec_result["status"] = "failed"
                    exec_result["error"] = str(e)
            else:
                exec_result["status"] = "skipped"

            executions.append(exec_result)

        all_ok = all(e["status"] in ("completed", "skipped") for e in executions)
        return {"status": "completed" if all_ok else "failed", "executions": executions}
```

`context` 是节点间传递数据的载体。每个节点的输出会 `update` 到 context 里，下游节点可以从 context 中读取上游的结果。比如意图分类节点输出 `{"intent": "order_query"}`，条件节点就可以用 `context["intent"]` 做判断。

## 节点处理器

每种节点类型对应一个处理器函数：

```python
async def llm_node_handler(node: dict, context: dict) -> dict:
    config = node.get("config", {})
    prompt = config.get("prompt", "")
    # 用上下文变量替换模板中的 {{variable}}
    for key, value in context.items():
        prompt = prompt.replace(f"{{{{{key}}}}}", str(value))
    
    response = await llm.chat([{"role": "user", "content": prompt}], model=config.get("model", "gpt-4o"))
    return {"output": response.content}

async def condition_node_handler(node: dict, context: dict) -> dict:
    config = node.get("config", {})
    expression = config.get("expression", "true")
    # 安全的表达式求值——不用 eval()
    expr = expression
    for key, value in context.items():
        expr = expr.replace(f"{{{key}}}", repr(value))
    # 解析比较表达式（==, !=, >, <, >=, <=）
    result = safe_eval(expr)
    return {"condition_result": bool(result)}

async def tool_node_handler(node: dict, context: dict) -> dict:
    config = node.get("config", {})
    tool_name = config.get("tool_name")
    tool = tool_registry.get(tool_name)
    # 解析输入中的变量引用
    resolved_input = {}
    for key, value in config.get("input", {}).items():
        if isinstance(value, str) and value.startswith("{{"):
            resolved_input[key] = context.get(value.strip("{}"), value)
        else:
            resolved_input[key] = value
    result = await tool.execute(**resolved_input)
    return {"tool_output": result}
```

条件节点的表达式求值要特别注意安全——不能用 `eval()`，要用白名单匹配解析比较表达式。用户可以通过构造恶意表达式执行任意代码。

## 工作流 API

```python
router = APIRouter()
engine = WorkflowEngine()
for node_type, handler in get_all_handlers().items():
    engine.register_handler(node_type, handler)

@router.post("/{workflow_id}/execute")
async def execute_workflow(workflow_id: str, db=Depends(get_db), user=Depends(get_current_user)):
    workflow = await db.get(Workflow, workflow_id)
    if not workflow:
        raise HTTPException(404, "工作流不存在")
    
    result = await engine.execute({
        "nodes": workflow.nodes,
        "edges": workflow.edges,
        "variables": workflow.variables,
    })
    
    # 记录执行日志
    execution_log = WorkflowExecution(
        workflow_id=workflow_id,
        user_id=user.id,
        status=result["status"],
        executions=result["executions"],
    )
    db.add(execution_log)
    await db.commit()
    
    return {"execution_id": execution_log.id, **result}
```

## 练习

### 练习 1：跑通最小闭环

1. 在画布上拖入 INPUT → LLM → OUTPUT 三个节点
2. 连线，配置 LLM 节点的 prompt
3. 点击执行，验证能正确输出结果

### 练习 2：条件分支

1. 创建一个工作流：INPUT → 意图分类 → CONDITION → (产品咨询 / 订单查询 / 其他)
2. 配置条件表达式
3. 验证不同输入走不同分支

### 练习 3：执行日志

1. 执行工作流后，查看每个节点的输入、输出、耗时、状态
2. 实现执行日志的数据库存储
3. 前端展示执行日志面板

## 验收标准

- 可视化编辑器能拖拽、连线、配置
- 工作流按 DAG 顺序正确执行
- 条件分支根据结果选择路径
- 执行日志完整可查（每步输入输出、耗时、状态）
- 工作流定义能保存为 JSON 并加载
