# 05 前后端联调

> 前后端分开写都对，合在一起就报错——这是最常见的开发痛点。

## 场景引入

后端说"接口写好了，你调吧"，前端说"我调了，返回 422"。后端说"你字段名写错了，我用的是 snake_case"，前端说"你文档上写的 camelCase 啊"。这种场景每天都在发生。前后端联调的本质是两套独立系统之间的通信，出问题的永远是边界：数据格式不一致、错误处理不统一、超时配置不对、类型不同步。这些问题不系统性解决，联调就会变成无止境的扯皮。

## 学习目标

- 实现前后端完整联调流程
- 掌握 API 错误处理的前端最佳实践
- 理解加载状态、乐观更新、错误恢复
- 解决跨域、类型不一致、超时等常见问题

## 前置要求

- 已完成后端 API（阶段 1 第 2-3 课）
- 已完成前端工程搭建（阶段 1 第 4 课）

## 联调的核心问题

前后端联调的本质是**两套独立系统之间的通信**。出问题的永远是边界：

1. **数据格式不一致**：后端返回 `snake_case`，前端用 `camelCase`
2. **错误处理不统一**：后端抛 500，前端不知道怎么展示
3. **超时和重试**：LLM API 调用可能很慢，前端默认超时不够
4. **类型不安全**：后端改了字段，前端编译不报错

## API 错误处理体系

### 后端统一错误格式

```python
# backend/app/core/exceptions.py
from fastapi import Request
from fastapi.responses import JSONResponse

class AppError(Exception):
    def __init__(self, code: str, message: str, status_code: int = 400):
        self.code = code
        self.message = message
        self.status_code = status_code

async def app_error_handler(request: Request, exc: AppError):
    return JSONResponse(
        status_code=exc.status_code,
        content={
            "error": {
                "code": exc.code,
                "message": exc.message,
            }
        },
    )
```

注册到 FastAPI：

```python
# backend/app/main.py
from app.core.exceptions import AppError, app_error_handler

app.add_exception_handler(AppError, app_error_handler)
```

### 前端错误处理

```typescript
// frontend/src/api/client.ts
import axios, { type AxiosError } from 'axios'
import { useMessage } from 'naive-ui'

interface ApiErrorResponse {
  error: {
    code: string
    message: string
  }
}

const client = axios.create({
  baseURL: '/api/v1',
  timeout: 60000, // LLM API 可能很慢，给足超时
})

client.interceptors.response.use(
  (response) => response.data,
  (error: AxiosError<ApiErrorResponse>) => {
    const status = error.response?.status
    const apiError = error.response?.data?.error
    
    // 网络错误
    if (!error.response) {
      return Promise.reject(new AppError('NETWORK_ERROR', '网络连接失败，请检查网络'))
    }
    
    // 401 → 跳转登录
    if (status === 401) {
      localStorage.removeItem('token')
      window.location.href = '/login'
      return Promise.reject(new AppError('UNAUTHORIZED', '请重新登录'))
    }
    
    // 429 → 限流
    if (status === 429) {
      return Promise.reject(new AppError('RATE_LIMITED', '请求过于频繁，请稍后再试'))
    }
    
    // 其他错误
    const code = apiError?.code || 'UNKNOWN_ERROR'
    const message = apiError?.message || '未知错误'
    return Promise.reject(new AppError(code, message, status))
  }
)

export class AppError extends Error {
  constructor(
    public code: string,
    message: string,
    public status?: number,
  ) {
    super(message)
    this.name = 'AppError'
  }
}

export default client
```

### 全局错误提示

```typescript
// frontend/src/composables/useApiError.ts
import { useMessage } from 'naive-ui'
import { AppError } from '@/api/client'

export function useApiError() {
  const message = useMessage()

  function handleError(error: unknown) {
    if (error instanceof AppError) {
      // 已知错误，显示友好提示
      message.error(error.message)
    } else if (error instanceof Error) {
      // 未知错误
      message.error(`操作失败：${error.message}`)
    } else {
      message.error('未知错误')
    }
  }

  return { handleError }
}
```

在组件中使用：

```vue
<script setup lang="ts">
import { useApiError } from '@/composables/useApiError'
import { chatApi } from '@/api/chat'

const { handleError } = useApiError()

async function sendMessage(content: string) {
  try {
    await chatApi.sendMessage(sessionId.value, content)
  } catch (error) {
    handleError(error)
  }
}
</script>
```

## 加载状态管理

### 全局加载状态

```typescript
// frontend/src/stores/app.ts
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'

export const useAppStore = defineStore('app', () => {
  const loadingCount = ref(0)
  const isLoading = computed(() => loadingCount.value > 0)

  function startLoading() {
    loadingCount.value++
  }

  function stopLoading() {
    loadingCount.value = Math.max(0, loadingCount.value - 1)
  }

  return { isLoading, startLoading, stopLoading }
})
```

配合 axios 拦截器自动管理：

```typescript
client.interceptors.request.use((config) => {
  appStore.startLoading()
  return config
})

client.interceptors.response.use(
  (response) => {
    appStore.stopLoading()
    return response
  },
  (error) => {
    appStore.stopLoading()
    return Promise.reject(error)
  }
)
```

## 乐观更新

乐观更新的核心思想：先更新 UI，后发请求。如果请求失败，再回滚。

```typescript
// frontend/src/stores/chat.ts
async function sendMessage(sessionId: string, content: string) {
  // 1. 乐观更新：立即显示用户消息
  const tempMessage: Message = {
    id: `temp-${Date.now()}`,
    role: 'user',
    content,
    token_usage: 0,
    created_at: new Date().toISOString(),
  }
  messages.value.push(tempMessage)

  try {
    // 2. 发送请求
    const res = await chatApi.sendMessage(sessionId, content)
    
    // 3. 用真实数据替换临时消息
    const index = messages.value.findIndex((m) => m.id === tempMessage.id)
    if (index !== -1) {
      messages.value.splice(index, 1, res.message)
    }
    
    // 4. 添加 AI 回复
    messages.value.push(res.ai_message)
  } catch (error) {
    // 5. 失败回滚：移除临时消息
    const index = messages.value.findIndex((m) => m.id === tempMessage.id)
    if (index !== -1) {
      messages.value.splice(index, 1)
    }
    throw error
  }
}
```

## 类型共享策略

前后端共享类型定义，避免"后端改了字段，前端编译不报错"的问题。

### 方案一：共享 TypeScript 类型文件

```typescript
// frontend/src/types/api.ts

export interface ChatRequest {
  message: string
  session_id?: string
}

export interface ChatResponse {
  session_id: string
  message: Message
}
```

### 方案二：从后端自动生成（推荐）

用 `openapi-typescript` 从 FastAPI 的 OpenAPI 文档自动生成类型：



## 联调检查清单

### 后端检查

- [ ] 所有 API 都有正确的状态码
- [ ] 错误返回统一格式 `{ "error": { "code": "...", "message": "..." } }`
- [ ] CORS 配置正确（开发环境允许前端域名）

### 前端检查

- [ ] API 调用有超时设置（LLM API 用 60s+）
- [ ] 错误处理覆盖所有已知错误码
- [ ] 加载状态正确显示和隐藏
- [ ] 乐观更新有回滚机制
- [ ] 401 自动跳转登录页
- [ ] 网络断开有友好提示

## 参考答案

### 练习 1

**思路**：先确保后端 API 可用，然后前端依次对接登录、对话两个核心流程，重点处理各种错误情况。

**答案**：

```typescript
// frontend/src/views/Login.vue - 对接登录 API
<script setup lang="ts">
import { ref, reactive } from 'vue'
import { useRouter } from 'vue-router'
import { useMessage } from 'naive-ui'
import { useUserStore } from '@/stores/user'
import { AppError } from '@/api/client'

const router = useRouter()
const message = useMessage()
const userStore = useUserStore()
const loading = ref(false)

const formData = reactive({ email: '', password: '' })

async function handleLogin() {
  loading.value = true
  try {
    await userStore.login(formData.email, formData.password)
    message.success('登录成功')
    router.push('/chat')
  } catch (error) {
    if (error instanceof AppError) {
      if (error.code === 'UNAUTHORIZED') {
        message.error('邮箱或密码错误')
      } else {
        message.error(error.message)
      }
    } else {
      message.error('网络连接失败，请检查网络')
    }
  } finally {
    loading.value = false
  }
}
</script>
```

```typescript
// frontend/src/views/Chat.vue - 对接对话 API
<script setup lang="ts">
import { ref, onMounted } from 'vue'
import { useMessage } from 'naive-ui'
import { chatApi } from '@/api/chat'
import { AppError } from '@/api/client'
import type { ChatSession, Message } from '@/types/api'

const message = useMessage()
const sessions = ref<ChatSession[]>([])
const messages = ref<Message[]>([])
const currentSessionId = ref<string | null>(null)
const inputText = ref('')
const sending = ref(false)

onMounted(async () => {
  try {
    const res = await chatApi.listSessions()
    sessions.value = res.items
  } catch (error) {
    if (error instanceof AppError && error.status === 401) {
      // 401 已在拦截器中处理跳转
      return
    }
    message.error('加载会话列表失败')
  }
})

async function handleSend() {
  if (!inputText.value.trim() || sending.value) return
  const content = inputText.value
  inputText.value = ''
  sending.value = true

  try {
    if (!currentSessionId.value) {
      const res = await chatApi.createSession(content)
      currentSessionId.value = res.session_id
      messages.value.push(res.message)
      // 刷新会话列表
      const listRes = await chatApi.listSessions()
      sessions.value = listRes.items
    } else {
      // 乐观更新
      messages.value.push({
        id: `temp-${Date.now()}`,
        role: 'user',
        content,
        token_usage: 0,
        created_at: new Date().toISOString(),
      })
      const res = await chatApi.sendMessage(currentSessionId.value, content)
      messages.value.push(res.message)
    }
  } catch (error) {
    if (error instanceof AppError) {
      message.error(error.message)
    } else {
      message.error('发送失败，请重试')
    }
  } finally {
    sending.value = false
  }
}
</script>
```

**要点**：
- 登录成功后 `token` 存入 `localStorage`，后续请求由拦截器自动注入
- 401 错误由 axios 拦截器统一处理（清 token + 跳转登录页），组件内不需要重复处理
- 常见错误：只测了正常流程，没有测试 500、超时、断网等异常情况，上线后用户遇到错误就一脸懵

```typescript
import type { components } from '@/types/api-generated'

type ChatSession = components['schemas']['ChatSession']
type Message = components['schemas']['Message']
type SessionListResponse = components['schemas']['SessionListResponse']
```

- 常见错误：后端没启动就运行 `gen:api`，会连接失败；或者后端 Schema 中缺少 `response_model` 导致生成的类型不完整

### 练习 3

**思路**：后端创建测试端点返回各种错误码，前端逐个验证错误提示是否正确显示。

**答案**：

```python
# backend/app/api/v1/test_errors.py - 仅用于测试，生产环境删除
from fastapi import APIRouter

router = APIRouter(prefix="/api/v1/test", tags=["测试"])

@router.get("/error/{code}")
async def trigger_error(code: int):
    """返回指定状态码的错误"""
    from fastapi.responses import JSONResponse
    error_messages = {
        400: "请求参数错误",
        401: "未认证",
        403: "无权限",
        404: "资源不存在",
        429: "请求过于频繁",
        500: "服务器内部错误",
    }
    message = error_messages.get(code, "未知错误")
    return JSONResponse(status_code=code, content={"error": {"code": f"TEST_{code}", "message": message}})
```

- 每种错误码对应不同的前端处理策略：401 跳登录、429 显示"请稍后再试"、500 显示"服务器错误"

- 常见错误：所有错误都显示"网络错误"，没有区分错误类型，用户体验差

## 本节要点

- 统一错误格式是前后端协作的基础
- 加载状态要全局管理，不要每个组件各管各的
- 乐观更新提升体验，但必须有回滚机制
- 类型自动生成消除前后端类型不同步的问题

## 常见误区

| 错误 | 原因 | 解决 |
|------|------|------|
| CORS 错误 | 后端没配置允许前端域名 | 添加 CORSMiddleware |
| 422 前端发了请求但后端报错 | 请求体字段名不一致 | 检查 `snake_case` vs `camelCase` |
| 超时错误 | LLM API 调用很慢 | 增加 axios timeout 到 60-120s |
| token 过期后页面卡死 | 401 没有自动跳转登录 | 在拦截器中处理 401 |

## 工程建议

- 前后端统一错误格式要在项目第一天定好，后期改动成本极高——建议用 `{ "error": { "code": "...", "message": "..." } }` 格式
- 用 `openapi-typescript` 从后端 OpenAPI 文档自动生成 TypeScript 类型，消除手动维护类型的不同步问题
- LLM API 调用超时设置要充足（60 秒以上），同时前端要实现请求取消（AbortController）避免用户重复提交
- 联调阶段要系统性测试各种错误场景（400/401/403/500/超时/断网），不要只测正常流程
- 生产环境要记录 API 调用的请求 ID，方便前后端联合排查问题
