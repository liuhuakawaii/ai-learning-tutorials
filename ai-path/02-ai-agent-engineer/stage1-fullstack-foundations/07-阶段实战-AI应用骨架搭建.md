# 07 阶段实战：AI 应用骨架搭建

> 这不是练习——这是毕业项目的地基。后面所有阶段的代码都往这个骨架上加。

前面 6 课分别学了环境搭建、FastAPI 后端、数据库、Vue3 前端、前后端联调、Redis 缓存。现在要把它们拼成一个能跑的完整应用。毕业项目是一个 AI Agent 平台，这个骨架就是它的第一个版本：能注册登录、能创建会话、能发消息（暂时返回模拟回复）。

## 要搭什么

骨架包含三个核心模块：

**用户系统**：注册、登录、JWT 认证。用户注册后拿到 token，后续所有请求带着 token，后端验证身份。

**对话系统**：创建会话、发消息、消息历史。暂时不接 LLM，返回模拟回复——重点是把数据流走通。

**基础设施**：Docker Compose 一键启动、数据库迁移、Redis 缓存、API 文档。

## 后端：认证系统

认证的核心是 JWT。用户登录后签发 token，后续请求带着 token，后端解码验证身份。

```python
# backend/app/core/security.py
from datetime import datetime, timedelta
from jose import JWTError, jwt
from passlib.context import CryptContext
from app.core.config import settings

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

def hash_password(password: str) -> str:
    return pwd_context.hash(password)

def verify_password(plain: str, hashed: str) -> bool:
    return pwd_context.verify(plain, hashed)

def create_access_token(data: dict, expires_delta: timedelta | None = None) -> str:
    to_encode = data.copy()
    expire = datetime.utcnow() + (expires_delta or timedelta(hours=24))
    to_encode.update({"exp": expire})
    return jwt.encode(to_encode, settings.SECRET_KEY, algorithm="HS256")

def decode_token(token: str) -> dict | None:
    try:
        return jwt.decode(token, settings.SECRET_KEY, algorithms=["HS256"])
    except JWTError:
        return None
```

注册接口检查邮箱唯一性，创建用户后直接返回 token：

```python
# backend/app/api/v1/auth.py
@router.post("/register", response_model=TokenResponse, status_code=201)
async def register(request: RegisterRequest, db: AsyncSession = Depends(get_db)):
    existing = await db.execute(select(User).where(User.email == request.email))
    if existing.scalar_one_or_none():
        raise HTTPException(400, "邮箱已注册")
    
    user = User(
        email=request.email,
        username=request.username,
        hashed_password=hash_password(request.password),
    )
    db.add(user)
    await db.flush()
    
    token = create_access_token({"sub": user.id})
    return TokenResponse(access_token=token, user_id=user.id)
```

登录接口验证密码，返回 token。错误密码返回 401。

## 后端：对话 API

会话和消息是整个平台的核心数据模型。一个会话有多条消息，消息有 role（user/assistant）和 content。

```python
# backend/app/api/v1/chat.py
@router.post("/sessions/{session_id}/messages", response_model=MessageResponse)
async def send_message(
    session_id: str,
    request: SendMessageRequest,
    db: AsyncSession = Depends(get_db),
    user: User = Depends(get_current_user),
):
    # 验证会话存在且属于当前用户
    result = await db.execute(
        select(ChatSession).where(
            ChatSession.id == session_id,
            ChatSession.user_id == user.id,
        )
    )
    session = result.scalar_one_or_none()
    if not session:
        raise HTTPException(404, "会话不存在")
    
    # 保存用户消息
    user_msg = Message(
        id=str(uuid.uuid4()),
        session_id=session_id,
        role="user",
        content=request.message,
    )
    db.add(user_msg)
    
    # 模拟 AI 回复（阶段 2 接入真实 LLM）
    ai_msg = Message(
        id=str(uuid.uuid4()),
        session_id=session_id,
        role="assistant",
        content=f"收到：「{request.message}」（模拟回复）",
        model="mock",
        token_usage=0,
    )
    db.add(ai_msg)
    await db.flush()
    return MessageResponse.model_validate(ai_msg)
```

注意 `get_current_user` 依赖——它从请求头的 Authorization 字段解码 JWT，拿不到有效 token 就返回 401。所有需要登录的接口都注入这个依赖。

## 前端：对话界面

前端的核心是一个左右分栏布局：左边会话列表，右边消息区。

```vue
<!-- frontend/src/views/Chat.vue (核心逻辑) -->
<script setup lang="ts">
import { ref, onMounted, nextTick, watch } from 'vue'
import { useChatStore } from '@/stores/chat'

const chatStore = useChatStore()
const inputText = ref('')
const messagesRef = ref<HTMLElement>()

onMounted(() => chatStore.loadSessions())

// 消息变化时自动滚动到底部
watch(() => chatStore.messages.length, () => {
  nextTick(() => {
    if (messagesRef.value) {
      messagesRef.value.scrollTop = messagesRef.value.scrollHeight
    }
  })
})

async function handleSend() {
  if (!inputText.value.trim() || !chatStore.currentSessionId) return
  await chatStore.sendMessage(inputText.value)
  inputText.value = ''
}
</script>
```

Pinia store 封装所有 API 调用，组件只管调用 store 方法。这个模式后面会一直用——RAG、Agent、工作流的前端都是"组件 → store → API"三层。

```yaml

services:

      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      retries: 5

  backend:
    build: ./backend
    ports: ["8000:8000"]
    environment:
      DATABASE_URL: postgresql+asyncpg://agent:agent123@postgres:5432/agent_platform
      REDIS_URL: redis://redis:6379/0
      SECRET_KEY: ${SECRET_KEY:-dev-secret-key}
    depends_on:
      postgres: { condition: service_healthy }
      redis: { condition: service_healthy }
    volumes:
      - ./backend/app:/app/app  # 热重载

  frontend:
    build: ./frontend
    ports: ["3000:80"]
    depends_on: [backend]
```

`docker compose up` 一键启动四个服务。`depends_on` + `healthcheck` 确保后端启动时数据库已经就绪。

### 练习 2：实现会话列表 API

写一个 `GET /api/v1/chat/sessions` 接口，返回当前用户的所有会话，按更新时间倒序，支持分页。

```python
@router.get("/sessions", response_model=SessionListResponse)
async def list_sessions(
    page: int = 1,
    size: int = 20,
    db: AsyncSession = Depends(get_db),
    user: User = Depends(get_current_user),
):
    offset = (page - 1) * size
    count_result = await db.execute(
        select(func.count()).select_from(ChatSession).where(
            ChatSession.user_id == user.id
        )
    )
    total = count_result.scalar()
    
    result = await db.execute(
        select(ChatSession)
        .where(ChatSession.user_id == user.id)
        .order_by(ChatSession.updated_at.desc())
        .offset(offset).limit(size)
    )
    sessions = result.scalars().all()
    return SessionListResponse(
        items=[SessionResponse.model_validate(s) for s in sessions],
        total=total, page=page, size=size,
    )
```

### 练习 3：前端联调

在前端实现完整的对话流程：注册 → 登录 → 存 token → 创建会话 → 发消息 → 看到回复。重点处理：

## 验收标准

- `docker compose up` 一键启动所有服务
- 能注册、登录、拿到 JWT token
- 能创建会话、发消息、看到模拟回复
- 未登录访问对话页会跳转登录
- 后端 API 文档可访问 http://localhost:8000/docs

## 这个骨架的意义

阶段 2 会把模拟回复换成真实 LLM 调用，阶段 3 加 RAG 知识库，阶段 4 加 Agent 工具调用。每一步都是在这个骨架上叠加——所以这里的用户系统、对话模型、前后端联调必须稳定。如果骨架不稳，后面每加一个功能都要回头修。
