# 01 课程导览与环境搭建

> 选对技术栈，比多写 1000 行代码更重要。

你打算做一个 AI Agent 平台。前端选 Vue 还是 React？后端用 Django 还是 FastAPI？数据库用 MySQL 还是 PostgreSQL？这些选择看起来都是"都能用"，但选错了后面重构成本巨大。你需要一个清晰的技术选型逻辑，以及一套能跑起来的开发环境。

## 这门课要做什么

这门课要带你从零构建一个**企业级 AI Agent 平台**。最终产品长这样：

- 用户能创建和配置 Agent（设定角色、工具权限、System Prompt）
- Agent 能多轮对话、流式输出、调用工具
- 有 RAG 知识库，回答基于真实文档而非编造
- 有可视化工作流引擎，非开发人员也能编排 AI 任务
- 有运营看板，能看到用量、成本、质量

这不是 demo，是每个阶段的代码都往这个产品上加东西。阶段 1 搭骨架，阶段 2 接 LLM，阶段 3 加 RAG，阶段 4 做 Agent，阶段 5 做工作流，阶段 6 加企业级能力，阶段 7 部署上线。

## 技术选型：为什么是这些

### 后端选 FastAPI

Python 后端框架那么多，为什么是 FastAPI？因为 AI 应用后端有两个特殊需求：IO 密集（调 LLM API 要等几秒）和类型安全（前端传来的参数五花八门）。FastAPI 的 async 原生支持和 Pydantic 类型校验刚好命中这两个需求。

```python
# 这几行代码就有了完整的 API + 自动文档 + 类型校验
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class ChatRequest(BaseModel):
    message: str
    session_id: str | None = None

@app.post("/api/chat")
async def chat(request: ChatRequest):
    return {"reply": f"你说的是：{request.message}"}
```

Django 太重，Flask 缺类型校验，Tornado 生态太少。FastAPI 在这个场景下是当前最优解。

### 前端选 Vue 3 + Naive UI

企业级中后台应用，Vue 3 + Naive UI 是国内最主流的组合之一。组合式 API 适合复杂组件逻辑复用，TypeScript 支持好，Naive UI 的企业级组件（表格、表单、抽屉）开箱即用。如果你更熟悉 React，课程也提供 React 版代码。

### 数据库选 PostgreSQL

PostgreSQL 不只是关系型数据库——它原生支持 JSON（存 Agent 配置）、pgvector 扩展支持向量检索（RAG 知识库的核心）。一个数据库搞定结构化数据和向量检索，不用再单独部署 Milvus 或 Pinecone。

### 缓存选 Redis

Redis 在 AI 应用中不只是缓存：会话上下文缓存、API 限流、异步任务队列、SSE 实时推送，一个 Redis 全覆盖。

## 搭建开发环境

### 1. 安装基础工具

```bash
# 验证已安装的工具
git --version        # >= 2.40
node --version       # >= 20.x
python --version     # >= 3.12
docker --version     # >= 24.x
docker compose version  # >= 2.x
```

Windows 用户用 scoop 安装，macOS 用户用 Homebrew。没装过的先装包管理器。

### 2. 用 Docker Compose 启动基础设施

```yaml
# docker-compose.yml
services:
  postgres:
    image: pgvector/pgvector:pg16
    environment:
      POSTGRES_USER: agent
      POSTGRES_PASSWORD: agent123
      POSTGRES_DB: agent_platform
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"

volumes:
  pgdata:
```

```bash
docker compose up -d

# 验证
docker compose exec postgres psql -U agent -d agent_platform -c "SELECT version();"
docker compose exec redis redis-cli ping  # 应该返回 PONG
```

常见问题：端口 5432 被本地 PostgreSQL 占用。要么停掉本地服务，要么改端口映射。

### 3. 创建项目结构

```bash
mkdir ai-agent-platform && cd ai-agent-platform

# 后端
mkdir -p backend/app/{api,core,models,services,schemas}
touch backend/app/main.py backend/requirements.txt

# 前端
npm create vue@latest frontend -- --typescript --router --pinia
cd frontend && npm install naive-ui @vicons/ionicons5 axios && cd ..
```

### 4. 跑起来

```python
# backend/app/main.py
from fastapi import FastAPI

app = FastAPI(title="AI Agent Platform")

@app.get("/health")
async def health():
    return {"status": "ok"}
```

```bash
cd backend
pip install fastapi uvicorn
uvicorn app.main:app --reload --port 8000
```

访问 http://localhost:8000/docs 看到 Swagger 文档，说明后端跑通了。

## 练习

### 练习 1：验证基础设施

启动 Docker Compose，用 psql 连接 PostgreSQL，创建一张测试表并插入数据：

```sql
CREATE TABLE IF NOT EXISTS test_items (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    created_at TIMESTAMP DEFAULT NOW()
);
INSERT INTO test_items (name) VALUES ('hello'), ('world');
SELECT * FROM test_items;
```

用 Redis CLI 验证缓存：`SET test "hello"` 然后 `GET test`。

### 练习 2：写一个带 Pydantic 校验的 POST 接口

在 `main.py` 中添加一个 `/api/v1/echo` 接口，接收 JSON body（包含 `message: str` 和 `count: int`），返回 `count` 次重复的 `message`。

```python
from pydantic import BaseModel

class EchoRequest(BaseModel):
    message: str
    count: int = 1

@app.post("/api/v1/echo")
async def echo(req: EchoRequest):
    return {"result": req.message * req.count}
```

测试：传入 `{"message": "hi", "count": 3}` 应该返回 `{"result": "hihihi"}`。故意传入 `count: -1`，观察 FastAPI 的校验错误返回。

### 练习 3：前端骨架

用 `npm create vue@latest` 创建 Vue 3 项目，配置 Naive UI 全局引入，写一个首页展示项目名称和"开始对话"按钮。重点是确认 Node 20+、TypeScript、Router、Pinia 都配好了。

## 常见坑

- `docker compose up` 报端口占用 → 改端口映射或停掉本地服务
- FastAPI 启动报 `ModuleNotFoundError` → 没激活虚拟环境
- 前端 `npm install` 失败 → Node 版本低于 20
- pgvector 扩展不可用 → 确保用 `pgvector/pgvector:pg16` 镜像

## 这个阶段结束后

你的机器上应该有：PostgreSQL + Redis 在 Docker 里跑着，FastAPI 后端能返回 JSON，Vue 3 前端能显示页面。这就是后面所有阶段的地基——阶段 1 的实战会把它们拼成一个完整的应用骨架。
