# 07 阶段实战：生产级部署与上线清单

> 从 localhost 到生产环境——这一步看似简单，实则处处是坑。

你花了一个月开发的 AI Agent 平台要上线了。执行部署脚本，数据库迁移忘跑了导致 API 全部报错；修好后发现 HTTPS 没配，用户看到"不安全"警告直接关掉；再修好后发现监控没部署，半夜服务挂了没人知道。上线不是一条命令，而是一套需要逐项检查的系统工程。

## 部署脚本

```bash
#!/bin/bash
# deploy.sh
set -e

echo "开始部署..."

# 1. 拉取最新代码
git pull origin main

# 2. 构建镜像
docker compose build

# 3. 执行数据库迁移
docker compose run --rm backend alembic upgrade head

# 4. 启动服务
docker compose up -d

# 5. 等待健康检查
echo "等待服务启动..."
for i in $(seq 1 30); do
    if curl -sf http://localhost/health > /dev/null; then
        echo "服务启动成功"
        break
    fi
    sleep 2
done

# 6. 冒烟测试
curl -f http://localhost/health || { echo "健康检查失败"; exit 1; }

echo "部署完成！"
```

不要用 `sleep 30` 等固定时间——用健康检查轮询，服务就绪就立即继续。

## Docker Compose 生产配置

```yaml
# docker-compose.prod.yml
services:
  postgres:
    image: pgvector/pgvector:pg16
    environment:
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB}
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER}"]
      interval: 10s
      retries: 5

  redis:
    image: redis:7-alpine
    command: redis-server --requirepass ${REDIS_PASSWORD}
    volumes:
      - redisdata:/data

  backend:
    image: ${REGISTRY}/backend:${VERSION}
    environment:
      DATABASE_URL: postgresql+asyncpg://${POSTGRES_USER}:${POSTGRES_PASSWORD}@postgres:5432/${POSTGRES_DB}
      REDIS_URL: redis://:${REDIS_PASSWORD}@redis:6379/0
      SECRET_KEY: ${SECRET_KEY}
    depends_on:
      postgres: { condition: service_healthy }

  frontend:
    image: ${REGISTRY}/frontend:${VERSION}

  nginx:
    image: nginx:alpine
    ports: ["80:80", "443:443"]
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf
      - ./nginx/ssl:/etc/nginx/ssl
    depends_on: [backend, frontend]
```

生产环境所有密钥通过环境变量注入，不要硬编码在 compose 文件里。

## Nginx 反向代理

```nginx
# nginx/nginx.conf
server {
    listen 443 ssl http2;
    server_name your-domain.com;
    
    ssl_certificate /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;
    
    # 前端静态文件
    location / {
        root /usr/share/nginx/html;
        try_files $uri $uri/ /index.html;
    }
    
    # API 代理
    location /api/ {
        proxy_pass http://backend:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
    
    # SSE 流式响应代理
    location /api/v1/chat/sessions/ {
        proxy_pass http://backend:8000;
        proxy_buffering off;
        proxy_cache off;
        proxy_set_header Connection '';
        proxy_http_version 1.1;
        chunked_transfer_encoding off;
    }
}

server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$host$request_uri;
}
```

SSE 流式响应需要特殊配置：关闭 proxy_buffering，否则 Nginx 会攒一批数据再发给客户端，流式效果就没了。

## 上线检查清单

### 安全
- [ ] 所有密钥从环境变量注入，代码中无硬编码
- [ ] HTTPS 已配置，HTTP 自动重定向
- [ ] CORS 只允许指定域名
- [ ] 数据库不是默认密码
- [ ] Redis 已设置密码

### 性能
- [ ] 数据库索引已创建
- [ ] Redis 缓存已配置
- [ ] 前端资源已压缩
- [ ] API 响应时间 < 200ms（不含 LLM 调用）

### 可靠性
- [ ] 健康检查端点已配置
- [ ] 数据库备份已配置（定时任务）
- [ ] 日志聚合已配置
- [ ] 告警规则已配置

### 部署
- [ ] CI/CD 流水线正常
- [ ] 数据库迁移已执行
- [ ] 环境变量已配置
- [ ] 域名已解析

## 回滚脚本

```bash
#!/bin/bash
# rollback.sh
PREVIOUS_VERSION=$1
if [ -z "$PREVIOUS_VERSION" ]; then
    echo "Usage: ./rollback.sh <version>"
    exit 1
fi

echo "回滚到版本 $PREVIOUS_VERSION..."
export VERSION=$PREVIOUS_VERSION
docker compose -f docker-compose.prod.yml up -d
echo "回滚完成"
```

回滚脚本要在 staging 环境验证过——紧急回滚时没有时间调试脚本。

## 练习

### 练习 1：完整部署流程

1. 写 deploy.sh 脚本
2. 在本地用 Docker Compose 模拟生产环境
3. 验证：构建镜像 → 数据库迁移 → 启动服务 → 健康检查 → 冒烟测试

### 练习 2：CI/CD 流水线

```yaml
# .github/workflows/deploy.yml
name: Deploy
on:
  push:
    branches: [main]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: docker compose -f docker-compose.test.yml run --rm backend pytest
  
  deploy:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: docker compose build
      - run: docker compose push
      - run: ./deploy.sh
```

### 练习 3：监控集成

1. 配置 Prometheus + Grafana
2. 导入系统指标 Dashboard
3. 配置告警规则（错误率、延迟、成本）

## 验收标准

- `./deploy.sh` 一键部署成功
- 所有服务健康检查通过
- HTTPS 正常工作，SSE 流式响应正常
- 监控看板显示系统指标
- 回滚脚本在 staging 验证通过
