# 05 结构化输出

> 让 AI 返回 JSON，是把"聊天机器人"变成"应用组件"的关键一步。

## 场景引入

你的 AI 客服能和用户正常对话了，但后端代码没法用它——AI 返回的是自然语言："用户想要退款，订单号是 12345"，而你的代码需要结构化的数据：`{ "intent": "refund", "order_id": "12345" }`。你不能在代码里写正则去解析 AI 的自由文本，那太脆弱了。你需要让 AI 按照你定义的 JSON Schema 输出，用 Pydantic 校验结果，处理输出失败时的重试——这就是结构化输出要解决的问题。

## 学习目标

- 实现 LLM 的结构化输出（JSON Schema）
- 用 Pydantic 校验 AI 输出
- 处理结构化输出的失败和重试
- 理解不同模型的结构化输出能力差异

## 前置要求

- 已完成阶段 2 第 1-4 课
- 理解 JSON Schema 和 Pydantic

## 为什么需要结构化输出

AI 的自由文本输出适合聊天，但不适合应用。你的代码需要知道：

- 用户意图是什么？（分类）
- 提取了哪些实体？（字段）
- 评分是多少？（数字）
- 建议的操作是什么？（枚举）

```python
# 不好：自由文本
response = "用户想要退款，订单号是 12345，原因是商品质量问题"

# 好：结构化输出
response = {
    "intent": "refund_request",
    "order_id": "12345",
    "reason": "product_quality",
    "confidence": 0.95,
    "suggested_action": "transfer_to_refund_team"
}
```

## JSON Schema 定义

```python
# backend/app/schemas/structured.py
from pydantic import BaseModel, Field
from enum import Enum

class Intent(str, Enum):
    REFUND = "refund"
    INQUIRY = "inquiry"
    COMPLAINT = "complaint"
    ORDER_STATUS = "order_status"
    OTHER = "other"

class Sentiment(str, Enum):
    POSITIVE = "positive"
    NEUTRAL = "neutral"
    NEGATIVE = "negative"

class MessageAnalysis(BaseModel):
    """消息分析结果"""
    intent: Intent = Field(description="用户意图分类")
    sentiment: Sentiment = Field(description="用户情感")
    confidence: float = Field(ge=0, le=1, description="置信度")
    entities: dict[str, str] = Field(
        default_factory=dict,
        description="提取的实体，如 order_id, product_name",
    )
    summary: str = Field(max_length=200, description="一句话摘要")
    suggested_action: str = Field(description="建议的下一步操作")
```

## OpenAI 结构化输出

OpenAI 提供两种方式实现结构化输出：

### 方式 1：JSON Mode

```python
response = await client.chat.completions.create(
    model="gpt-4o",
    messages=[...],
    response_format={"type": "json_object"},
)
# 返回的是 JSON 字符串，需要手动解析
result = json.loads(response.choices[0].message.content)
```

### 方式 2：Structured Outputs（推荐）

```python
from openai.lib._pydantic import to_strict_json_schema

# 将 Pydantic 模型转为 JSON Schema
schema = to_strict_json_schema(MessageAnalysis)

response = await client.chat.completions.create(
    model="gpt-4o",
    messages=[...],
    response_format={
        "type": "json_schema",
        "json_schema": {
            "name": "message_analysis",
            "strict": True,
            "schema": schema,
        },
    },
)

# 直接解析为 Pydantic 模型
result = MessageAnalysis.model_validate_json(
    response.choices[0].message.content
)
```

### 方式 3：Function Calling 强制输出

```python
response = await client.chat.completions.create(
    model="gpt-4o",
    messages=[...],
    tools=[{
        "type": "function",
        "function": {
            "name": "analyze_message",
            "description": "分析用户消息",
            "parameters": to_strict_json_schema(MessageAnalysis),
        },
    }],
    tool_choice={"type": "function", "function": {"name": "analyze_message"}},
)

# 解析工具调用结果
tool_call = response.choices[0].message.tool_calls[0]
result = MessageAnalysis.model_validate_json(tool_call.function.arguments)
```

## 完整封装

```python
# backend/app/services/structured_service.py
from pydantic import BaseModel
from openai import AsyncOpenAI
from openai.lib._pydantic import to_strict_json_schema
import json

class StructuredLLMService:
    """结构化输出服务"""
    
    def __init__(self):
        self.client = AsyncOpenAI()
    
    async def extract[T: BaseModel](
        self,
        messages: list[dict],
        schema: type[T],
        model: str = "gpt-4o",
        max_retries: int = 3,
    ) -> T:
        """从 LLM 输出中提取结构化数据"""
        
        # 构建 schema
        json_schema = to_strict_json_schema(schema)
        
        for attempt in range(max_retries):
            try:
                response = await self.client.chat.completions.create(
                    model=model,
                    messages=messages,
                    response_format={
                        "type": "json_schema",
                        "json_schema": {
                            "name": schema.__name__,
                            "strict": True,
                            "schema": json_schema,
                        },
                    },
                )
                
                content = response.choices[0].message.content
                return schema.model_validate_json(content)
            
            except Exception as e:
                if attempt == max_retries - 1:
                    raise
                # 重试前在 Prompt 中加入错误信息
                messages.append({
                    "role": "assistant",
                    "content": content if 'content' in dir() else "",
                })
                messages.append({
                    "role": "user",
                    "content": f"输出格式错误：{e}。请重新输出正确的 JSON。",
                })
```

## 处理输出失败

LLM 的结构化输出不是 100% 可靠的。需要处理：

```python
async def safe_extract[T: BaseModel](
    messages: list[dict],
    schema: type[T],
    model: str = "gpt-4o",
    fallback: T | None = None,
) -> T | None:
    """安全的结构化提取，失败时返回 fallback"""
    try:
        return await structured_llm.extract(messages, schema, model)
    except Exception as e:
        logger.error(f"Structured extraction failed: {e}")
        
        # 尝试用更简单的 Prompt 重试
        try:
            simple_prompt = f"""
            请严格按以下 JSON 格式输出：
            {schema.model_json_schema()}
            
            用户输入：{messages[-1]['content']}
            """
            return await structured_llm.extract(
                [{"role": "user", "content": simple_prompt}],
                schema,
                model,
            )
        except Exception:
            return fallback
```

## 参考答案

### 练习 1

**思路**：定义 Pydantic 模型描述输出结构，用 OpenAI 的 Structured Outputs 强制 JSON 格式，失败时重试并附带错误信息。

**答案**：

```python
from pydantic import BaseModel, Field
from enum import Enum
from openai import AsyncOpenAI
from openai.lib._pydantic import to_strict_json_schema
import logging

logger = logging.getLogger(__name__)

class Intent(str, Enum):
    REFUND = "refund"
    INQUIRY = "inquiry"
    COMPLAINT = "complaint"
    ORDER_STATUS = "order_status"
    OTHER = "other"

class Sentiment(str, Enum):
    POSITIVE = "positive"
    NEUTRAL = "neutral"
    NEGATIVE = "negative"

class MessageAnalysis(BaseModel):
    intent: Intent = Field(description="用户意图分类")
    sentiment: Sentiment = Field(description="用户情感")
    confidence: float = Field(ge=0, le=1, description="置信度")
    entities: dict[str, str] = Field(default_factory=dict, description="提取的实体")
    summary: str = Field(max_length=200, description="一句话摘要")
    suggested_action: str = Field(description="建议的下一步操作")

class StructuredLLMService:
    def __init__(self):
        self.client = AsyncOpenAI()

    async def extract(
        self,
        messages: list[dict],
        schema: type[BaseModel],
        model: str = "gpt-4o",
        max_retries: int = 3,
    ) -> BaseModel:
        json_schema = to_strict_json_schema(schema)
        for attempt in range(max_retries):
            try:
                response = await self.client.chat.completions.create(
                    model=model,
                    messages=messages,
                    response_format={
                        "type": "json_schema",
                        "json_schema": {
                            "name": schema.__name__,
                            "strict": True,
                            "schema": json_schema,
                        },
                    },
                )
                content = response.choices[0].message.content
                return schema.model_validate_json(content)
            except Exception as e:
                logger.warning(f"Attempt {attempt + 1} failed: {e}")
                if attempt == max_retries - 1:
                    raise
                messages.append({"role": "assistant", "content": content if 'content' in dir() else ""})
                messages.append({"role": "user", "content": f"输出格式错误：{e}。请重新输出正确的 JSON。"})

async def analyze_message(user_message: str) -> MessageAnalysis:
    service = StructuredLLMService()
    return await service.extract(
        messages=[
            {"role": "system", "content": "分析用户消息，提取意图、情感和关键实体。"},
            {"role": "user", "content": user_message},
        ],
        schema=MessageAnalysis,
        model="gpt-4o-mini",
    )
```

**要点**：
- `to_strict_json_schema` 将 Pydantic 模型转为严格 JSON Schema，确保模型输出符合定义
- 重试时把上一次的错误信息追加到 messages 中，帮助模型修正输出
- 常见错误：用 `json_mode` 不指定 schema，模型输出的 JSON 字段名或类型可能不对

### 练习 2

**思路**：为每个场景定义专用的 Pydantic 模型，用 `Field(description=...)` 说明每个字段的含义。

**答案**：

```python
from pydantic import BaseModel, Field
from typing import Optional

# 场景 1：日程提取
class ScheduleItem(BaseModel):
    event: str = Field(description="事件名称")
    date: str = Field(description="日期，格式 YYYY-MM-DD")
    time: str = Field(description="时间，格式 HH:MM")
    location: Optional[str] = Field(None, description="地点")
    participants: list[str] = Field(default_factory=list, description="参与者")
    notes: Optional[str] = Field(None, description="备注")

# 场景 2：产品评价分析
class ReviewAnalysis(BaseModel):
    sentiment: str = Field(description="情感：positive/negative/neutral")
    rating: float = Field(ge=1, le=5, description="评分 1-5")
    key_points: list[str] = Field(description="关键观点")
    pros: list[str] = Field(default_factory=list, description="优点")
    cons: list[str] = Field(default_factory=list, description="缺点")
    summary: str = Field(max_length=100, description="一句话总结")

# 场景 3：代码审查
class CodeIssue(BaseModel):
    file: str = Field(description="文件名")
    line: int = Field(description="行号")
    severity: str = Field(description="严重程度：error/warning/info")
    category: str = Field(description="问题类型：bug/style/perf/security")
    description: str = Field(description="问题描述")
    suggestion: str = Field(description="修复建议")

class CodeReviewResult(BaseModel):
    issues: list[CodeIssue] = Field(description="发现的问题")
    overall_score: float = Field(ge=0, le=10, description="总体评分 0-10")
    summary: str = Field(description="审查总结")
```

```python
# 使用示例
async def extract_schedule(text: str) -> list[ScheduleItem]:
    service = StructuredLLMService()
    result = await service.extract(
        messages=[{"role": "user", "content": f"从以下文本中提取所有日程安排：\n{text}"}],
        schema=list[ScheduleItem],  # 注意：OpenAI 不直接支持 list 顶层 schema
        model="gpt-4o-mini",
    )
    return result

# 更好的做法：包装成对象
class ScheduleExtraction(BaseModel):
    items: list[ScheduleItem] = Field(description="提取的日程列表")
```

**要点**：
- `Field(description=...)` 会作为 JSON Schema 的一部分传给模型，帮助模型理解字段含义
- 用 `Optional[type]` 或 `type | None` 标记可选字段，模型不会因为缺少这些字段而报错
- 常见错误：Schema 字段太多或嵌套太深，模型输出准确率下降——尽量控制在 10 个字段以内

### 练习 3

**思路**：用 `csv` 模块读写文件，逐条调用结构化提取，用 `asyncio.Semaphore` 控制并发处理速率限制。

**答案**：

```python
import csv
import asyncio
from pathlib import Path
from dataclasses import dataclass, fields
from openai import AsyncOpenAI, RateLimitError
from openai.lib._pydantic import to_strict_json_schema
from pydantic import BaseModel, Field
import logging

logger = logging.getLogger(__name__)

class TextRecord(BaseModel):
    id: str = Field(description="记录 ID")
    title: str = Field(description="标题")
    category: str = Field(description="分类")
    sentiment: str = Field(description="情感")
    keywords: list[str] = Field(description="关键词")

class BatchProcessor:
    def __init__(self, max_concurrent: int = 5, max_retries: int = 3):
        self.client = AsyncOpenAI()
        self.semaphore = asyncio.Semaphore(max_concurrent)
        self.max_retries = max_retries

    async def extract_one(self, text_id: str, text: str) -> TextRecord | None:
        schema = to_strict_json_schema(TextRecord)
        for attempt in range(self.max_retries):
            try:
                async with self.semaphore:
                    response = await self.client.chat.completions.create(
                        model="gpt-4o-mini",
                        messages=[
                            {"role": "system", "content": "分析文本，提取标题、分类、情感和关键词。"},
                            {"role": "user", "content": f"ID: {text_id}\n文本: {text}"},
                        ],
                        response_format={
                            "type": "json_schema",
                            "json_schema": {"name": "TextRecord", "strict": True, "schema": schema},
                        },
                    )
                return TextRecord.model_validate_json(response.choices[0].message.content)
            except RateLimitError:
                wait = 2 ** attempt
                logger.warning(f"Rate limited, waiting {wait}s...")
                await asyncio.sleep(wait)
            except Exception as e:
                logger.error(f"Failed to extract {text_id}: {e}")
                if attempt == self.max_retries - 1:
                    return None
                await asyncio.sleep(1)
        return None

    async def process_csv(self, input_path: str, output_path: str):
        # 读取输入
        rows = []
        with open(input_path, "r", encoding="utf-8") as f:
            reader = csv.DictReader(f)
            for row in reader:
                rows.append(row)

        logger.info(f"Processing {len(rows)} rows...")

        # 并发处理
        tasks = [self.extract_one(row["id"], row["text"]) for row in rows]
        results = await asyncio.gather(*tasks)

        # 写入输出
        fieldnames = [f.name for f in fields(TextRecord)]
        with open(output_path, "w", encoding="utf-8", newline="") as f:
            writer = csv.DictWriter(f, fieldnames=fieldnames)
            writer.writeheader()
            for row, result in zip(rows, results):
                if result:
                    writer.writerow(result.model_dump())

        success = sum(1 for r in results if r is not None)
        logger.info(f"Done: {success}/{len(rows)} succeeded, output: {output_path}")

# 使用
async def main():
    processor = BatchProcessor(max_concurrent=5)
    await processor.process_csv("input.csv", "output.csv")

asyncio.run(main())
```

**要点**：
- `asyncio.Semaphore` 控制并发数，避免同时发起太多请求触发速率限制
- `asyncio.gather` 并发处理所有行，比逐行串行快很多
- 常见错误：不处理速率限制导致大量请求失败；应该用指数退避重试

## 本节要点

- 结构化输出是 AI 从"聊天"到"应用"的关键桥梁
- Pydantic + JSON Schema = 类型安全的 AI 输出
- 输出失败是常态，必须有重试和降级机制
- 不同场景选择不同模型（分类用便宜模型，复杂提取用强模型）

## 常见误区

| 错误 | 原因 | 解决 |
|------|------|------|
| JSON 解析失败 | LLM 输出了非 JSON 内容 | 用 `response_format` 强制 JSON |
| 字段类型错误 | LLM 返回了错误类型 | 用 `strict: True` 模式 |
| 漏字段 | LLM 没有输出所有字段 | 在 Prompt 中强调"必须包含所有字段" |
| 输出太慢 | 用了太大的模型做简单分类 | 分类任务用 `gpt-4o-mini` |

## 工程建议

- 结构化输出要有 fallback 机制：主方案用 Structured Outputs，失败后降级到 Function Calling，再失败用正则提取关键字段
- Pydantic 模型的 `Field(description=...)` 很重要，它会作为 JSON Schema 的一部分传给模型，帮助模型理解字段含义
- 简单分类任务用 gpt-4o-mini 即可，成本低且速度快；复杂提取任务再用 gpt-4o
- 结构化输出失败时，要在重试 Prompt 中附加上一次的错误信息，帮助模型修正输出
- 生产环境要监控结构化输出的成功率，持续低于 95% 时需要优化 Prompt 或调整 Schema
