# 02 编排模式概览——Supervisor / Sequential / Parallel / Hierarchical

> 多 Agent 的核心问题：谁来决定哪个 Agent 干什么？

## 场景引入

你已经决定用多个 Agent 来拆分任务，但接下来的问题是：这些 Agent 之间应该按什么顺序执行？谁来决定下一步该走哪条路？如果直接把所有 Agent 串成一条链，遇到需要并行处理的子任务就卡住了；如果全部并行，又无法处理有先后依赖的步骤。面对"顺序、并行、监督、层级"四种模式，你该如何选择？

- 掌握四种主流多 Agent 编排模式
- 理解每种模式的适用场景
- 学会根据任务特征选择合适的模式

## 一、四种编排模式

```
┌─────────────────────────────────────────────────────────────┐
│                    四种编排模式                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. Sequential（顺序执行）                                   │
│     Agent A → Agent B → Agent C                             │
│     适用：有明确先后依赖的任务                                │
│                                                             │
│  2. Parallel（并行执行）                                     │
│     Agent A ─┐                                              │
│     Agent B ─┼→ 汇总                                        │
│     Agent C ─┘                                              │
│     适用：无依赖、可并行的任务                                │
│                                                             │
│  3. Supervisor（监督者）                                     │
│           ┌─→ Agent A                                       │
│     监督者 ┼→ Agent B                                       │
│           └→ Agent C                                        │
│     适用：需要动态决策的复杂任务                              │
│                                                             │
│  4. Hierarchical（层级式）                                   │
│           ┌─→ 团队 1 ─┬→ Agent A                            │
│     总监 ─┼→ 团队 2 ─┼→ Agent B                            │
│           └→ 团队 3 ─┼→ Agent C                            │
│     适用：大型复杂项目                                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 二、模式实现

### 2.1 Sequential 模式

```python
class SequentialOrchestrator:
    """顺序执行编排器"""
    
    def __init__(self, agents: list):
        self.agents = agents
    
    def run(self, task: str) -> str:
        result = task
        for agent in self.agents:
            result = agent.execute(result)
        return result
```

### 2.2 Parallel 模式

```python
class ParallelOrchestrator:
    """并行执行编排器"""
    
    def __init__(self, agents: list, aggregator):
        self.agents = agents
        self.aggregator = aggregator
    
    def run(self, task: str) -> str:
        # 并行执行
        results = []
        with ThreadPoolExecutor() as executor:
            futures = [executor.submit(agent.execute, task) for agent in self.agents]
            results = [f.result() for f in futures]
        
        # 汇总结果
        return self.aggregator.aggregate(results)
```

### 2.3 Supervisor 模式

```python
class SupervisorOrchestrator:
    """监督者编排器"""
    
    def __init__(self, supervisor, agents: dict):
        self.supervisor = supervisor
        self.agents = agents
    
    def run(self, task: str) -> str:
        # 监督者决策
        decision = self.supervisor.decide(task)
        
        # 选择 Agent 执行
        agent = self.agents[decision["agent"]]
        result = agent.execute(decision["subtask"])
        
        # 监督者评估
        if self.supervisor.should_continue(result):
            return self.run(decision["next_task"])
        
        return result
```

## 三、模式选择

```
模式选择指南：

任务有明确顺序？
├── 是 → Sequential
└── 否 → 任务可并行？
    ├── 是 → Parallel
    └── 否 → 需要动态决策？
        ├── 是 → Supervisor
        └── 否 → 任务复杂度高？
            ├── 是 → Hierarchical
            └── 否 → Sequential
```

## 常见误区

1. **盲目选择 Supervisor 模式**：Supervisor 模式灵活但开销大——每次路由决策都需要一次 LLM 调用。对于有固定流程的任务，Sequential Pipeline 更简单高效。
2. **忽略模式的混合使用**：实际项目中，很少只用一种模式。一个系统可能在顶层用 Supervisor 路由，某个分支内部用 Parallel Fan-out。不要把模式当成互斥的选择。
3. **Hierarchical 模式过度设计**：层级式模式适合大型项目，但对于 3-5 个 Agent 的系统，扁平的 Supervisor 模式通常就够了。过早引入层级会增加不必要的复杂度。

---

## 工程建议

1. **从单 Agent 开始，按需演进**：先用单 Agent 验证核心逻辑，当遇到上下文瓶颈、能力稀释或需要并行处理时，再拆分为多 Agent。不要为了"看起来高级"而引入多 Agent 架构。
2. **为每个 Agent 定义清晰的职责边界**：每个 Agent 应该有单一、明确的职责（如"只负责搜索""只负责分析"），输入输出格式在设计阶段就确定下来，避免职责重叠和数据格式混乱。
3. **建立可观测性基础设施**：从第一版开始就为每个 Agent 添加结构化日志和追踪机制，记录输入、输出、耗时、错误。多 Agent 系统的调试难度远高于单 Agent，没有日志就是在"盲人摸象"。
4. **在关键决策节点加入人工审批**：涉及高风险操作（删除数据、发送消息、支付）和不可逆操作时，使用 Human-in-the-loop 机制暂停执行，等待人类确认后再继续。

## 小结

```
本课核心要点：

1. Sequential：简单、可预测、适合有依赖的任务
2. Parallel：高效、适合无依赖的任务
3. Supervisor：灵活、适合需要动态决策的任务
4. Hierarchical：适合大型复杂项目
```
