# 03 子图与嵌套——让 Agent 自身也是一个 LangGraph 图

> 复杂的 Agent 可能需要自己的内部逻辑。子图让你在图中嵌套图。

## 场景引入

你的多 Agent 系统中有一个"研究 Agent"，它内部需要先搜索、再总结、最后验证。如果把这些步骤全部展开在主图里，图会变得非常复杂。你需要一种方式把复杂 Agent 的内部逻辑封装起来，让主图保持简洁——这就是子图的价值。

## 一、子图概念

```
子图的用途：

1. 复杂 Agent 内部逻辑
   - 一个 Agent 可能需要多个步骤
   - 用子图封装 Agent 的内部流程

2. 可复用的 Agent 模块
   - 将通用 Agent 封装为子图
   - 在不同主图中复用

3. 层级化设计
   - 主图负责全局编排
   - 子图负责局部逻辑
```

## 二、子图实现

```python
from langgraph.graph import StateGraph, END

# 创建子图：研究 Agent
def create_research_subgraph():
    """创建研究子图"""
    
    class ResearchState(TypedDict):
        query: str
        sources: list
        summary: str
    
    def search_node(state: ResearchState) -> ResearchState:
        # 搜索逻辑
        return {**state, "sources": ["source1", "source2"]}
    
    def summarize_node(state: ResearchState) -> ResearchState:
        # 总结逻辑
        return {**state, "summary": f"基于{state['sources']}的总结"}
    
    subgraph = StateGraph(ResearchState)
    subgraph.add_node("search", search_node)
    subgraph.add_node("summarize", summarize_node)
    subgraph.set_entry_point("search")
    subgraph.add_edge("search", "summarize")
    subgraph.add_edge("summarize", END)
    
    return subgraph.compile()

# 在主图中使用子图
main_graph = StateGraph(MainState)

# 添加子图作为节点
research_agent = create_research_subgraph()
main_graph.add_node("researcher", research_agent)

# 其他节点...
main_graph.add_node("analyst", analyst_node)
main_graph.add_node("writer", writer_node)
```

## 三、子图状态映射

```python
def researcher_wrapper(state: MainState) -> MainState:
    """研究 Agent 包装器，处理状态映射"""
    
    # 从主状态提取子图需要的数据
    research_input = {
        "query": state["task"],
        "sources": [],
        "summary": ""
    }
    
    # 运行子图
    research_result = research_agent.invoke(research_input)
    
    # 将子图结果映射回主状态
    return {
        **state,
        "results": {**state.get("results", {}), "research": research_result["summary"]}
    }
```

## 四、设计模式

```
子图设计模式：

1. 封装模式
   将复杂 Agent 封装为子图
   对外暴露简单接口

2. 管道模式
   多个子图串联
   每个子图处理一个阶段

3. 并行模式
   多个子图并行执行
   汇总结果
```

## 常见误区

1. **子图状态和主图状态不一致**：子图有自己的 State 定义，主图也有自己的 State 定义。如果字段名或类型不匹配，数据传递会出错。需要一个明确的状态映射层。
2. **子图嵌套层级过深**：子图里再嵌套子图，调试时需要层层追踪。超过 2 层嵌套会让系统难以理解和维护。
3. **子图的错误向上传播**：子图内部出错后，错误信息没有正确传递到主图，导致主图继续执行后续节点。需要在子图的包装函数中捕获错误并更新主图状态。

## 工程建议

1. **从单 Agent 开始，按需演进**：先用单 Agent 验证核心逻辑，当遇到上下文瓶颈、能力稀释或需要并行处理时，再拆分为多 Agent。不要为了"看起来高级"而引入多 Agent 架构。
2. **为每个 Agent 定义清晰的职责边界**：每个 Agent 应该有单一、明确的职责（如"只负责搜索""只负责分析"），输入输出格式在设计阶段就确定下来，避免职责重叠和数据格式混乱。
3. **建立可观测性基础设施**：从第一版开始就为每个 Agent 添加结构化日志和追踪机制，记录输入、输出、耗时、错误。多 Agent 系统的调试难度远高于单 Agent，没有日志就是在"盲人摸象"。
4. **在关键决策节点加入人工审批**：涉及高风险操作（删除数据、发送消息、支付）和不可逆操作时，使用 Human-in-the-loop 机制暂停执行，等待人类确认后再继续。
