# 05 安全边界——Agent 权限隔离、输出审核、越权防护

> 多 Agent 系统的安全比单 Agent 更复杂。权限隔离是关键。

## 场景引入

你的多 Agent 系统中，搜索 Agent 被恶意输入注入了一段指令，导致它越权调用了删除数据的 API。单 Agent 的安全问题在多 Agent 系统中被放大了——每个 Agent 都可能成为攻击面。你需要权限隔离、输出审核和越权防护的完整安全体系。

## 一、权限隔离

```python
class AgentPermissions:
    """Agent 权限管理"""
    
    def __init__(self):
        self.permissions = {}
    
    def set_permissions(self, agent_name: str, permissions: list):
        """设置 Agent 权限"""
        self.permissions[agent_name] = permissions
    
    def check_permission(self, agent_name: str, action: str) -> bool:
        """检查权限"""
        agent_perms = self.permissions.get(agent_name, [])
        return action in agent_perms

# 使用示例
permissions = AgentPermissions()
permissions.set_permissions("researcher", ["search", "read"])
permissions.set_permissions("writer", ["read", "write"])
permissions.set_permissions("admin", ["search", "read", "write", "delete"])

# 检查权限
if permissions.check_permission("researcher", "delete"):
    # 执行删除
    pass
else:
    raise PermissionError("Agent 没有删除权限")
```

## 五、安全最佳实践

```
安全最佳实践：

1. 最小权限原则
   - 每个 Agent 只拥有必要的权限
   - 定期审查和调整权限

2. 输出审核
   - 所有输出都要经过安全审核
   - 高风险操作需要人工审核

3. 越权防护
   - 检查每个操作的权限
   - 记录所有越权尝试

4. 审计日志
   - 记录所有操作
   - 支持追溯和审计

5. 定期安全评估
   - 定期进行安全测试
   - 修复发现的安全漏洞
```

## 常见误区

1. **权限粒度太粗**：给所有 Agent 相同的权限，没有根据职责区分。搜索 Agent 不应该有删除数据的权限，写作 Agent 不应该有修改数据库的权限。遵循最小权限原则。
2. **输出审核只检查内容安全，不检查格式合规**：Agent 的输出可能包含有害内容，但也可能是格式错误（如 SQL 注入、XSS 攻击）。输出审核需要同时检查内容安全和格式合规。
3. **审计日志没有防篡改机制**：审计日志存储在本地文件中，可以被 Agent 或攻击者修改。审计日志应该写入不可变存储（如 append-only 数据库或区块链）。

## 工程建议

1. **从单 Agent 开始，按需演进**：先用单 Agent 验证核心逻辑，当遇到上下文瓶颈、能力稀释或需要并行处理时，再拆分为多 Agent。不要为了"看起来高级"而引入多 Agent 架构。
2. **为每个 Agent 定义清晰的职责边界**：每个 Agent 应该有单一、明确的职责（如"只负责搜索""只负责分析"），输入输出格式在设计阶段就确定下来，避免职责重叠和数据格式混乱。
3. **建立可观测性基础设施**：从第一版开始就为每个 Agent 添加结构化日志和追踪机制，记录输入、输出、耗时、错误。多 Agent 系统的调试难度远高于单 Agent，没有日志就是在"盲人摸象"。
4. **在关键决策节点加入人工审批**：涉及高风险操作（删除数据、发送消息、支付）和不可逆操作时，使用 Human-in-the-loop 机制暂停执行，等待人类确认后再继续。
