## 二、压力测试

```python
import asyncio
import aiohttp

class LoadTester:
    """压力测试器"""
    
    def __init__(self, base_url: str):
        self.base_url = base_url
        self.results = []
    
    async def run_test(self, concurrent_users: int, duration: int):
        """运行压力测试"""
        tasks = []
        
        for i in range(concurrent_users):
            task = asyncio.create_task(self._simulate_user(i, duration))
            tasks.append(task)
        
        await asyncio.gather(*tasks)
        
        return self._analyze_results()
    
    async def _simulate_user(self, user_id: int, duration: int):
        """模拟用户"""
        start_time = time.time()
        
        async with aiohttp.ClientSession() as session:
            while time.time() - start_time < duration:
                try:
                    response = await session.post(
                        f"{self.base_url}/api/task",
                        json={"task": f"测试任务 {user_id}"}
                    )
                    
                    self.results.append({
                        "user_id": user_id,
                        "status": response.status,
                        "duration": time.time() - start_time
                    })
                except Exception as e:
                    self.results.append({
                        "user_id": user_id,
                        "error": str(e)
                    })
                
                await asyncio.sleep(1)
    
    def _analyze_results(self) -> dict:
        """分析结果"""
        successful = [r for r in self.results if r.get("status") == 200]
        failed = [r for r in self.results if r.get("error")]
        
        return {
            "total_requests": len(self.results),
            "successful": len(successful),
            "failed": len(failed),
            "success_rate": len(successful) / len(self.results) if self.results else 0,
            "avg_duration": sum(r.get("duration", 0) for r in successful) / len(successful) if successful else 0
        }
```

## 常见误区

1. **压力测试场景过于单一**：只测试了"正常请求"的并发能力，没有测试"某个 Agent 超时""某个服务不可用"等异常场景。压力测试应该覆盖正常和异常两种情况。
2. **监控告警阈值设置不当**：告警太灵敏（CPU 超过 50% 就告警），导致告警风暴；告警太迟钝（错误率超过 50% 才告警），发现问题时已经造成大量用户影响。需要根据历史数据设置合理的阈值。
3. **没有制定回滚方案**：部署新版本后发现问题，但没有快速回滚的能力。每次部署都应该保留上一个版本的镜像，并准备好一键回滚的脚本。

## 工程建议

1. **从单 Agent 开始，按需演进**：先用单 Agent 验证核心逻辑，当遇到上下文瓶颈、能力稀释或需要并行处理时，再拆分为多 Agent。不要为了"看起来高级"而引入多 Agent 架构。
2. **为每个 Agent 定义清晰的职责边界**：每个 Agent 应该有单一、明确的职责（如"只负责搜索""只负责分析"），输入输出格式在设计阶段就确定下来，避免职责重叠和数据格式混乱。
3. **建立可观测性基础设施**：从第一版开始就为每个 Agent 添加结构化日志和追踪机制，记录输入、输出、耗时、错误。多 Agent 系统的调试难度远高于单 Agent，没有日志就是在"盲人摸象"。
4. **在关键决策节点加入人工审批**：涉及高风险操作（删除数据、发送消息、支付）和不可逆操作时，使用 Human-in-the-loop 机制暂停执行，等待人类确认后再继续。
