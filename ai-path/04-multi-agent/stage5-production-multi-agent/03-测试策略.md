# 03 测试策略——多 Agent 系统的单元测试 / 集成测试 / 端到端测试

> 多 Agent 系统的测试比单 Agent 更复杂。分层测试是关键。

## 场景引入

你重构了 Supervisor 的决策逻辑，跑了一遍"看起来没问题"就上线了。结果第二天用户反馈：Agent 之间的路由出了 bug，某些任务被无限循环。多 Agent 系统的测试比单 Agent 复杂得多——你需要单元测试、集成测试、端到端测试的完整策略。

import pytest

class TestAgent:
    """Agent 单元测试"""
    
    def test_researcher_agent(self):

        result = agent.execute("测试任务")
        assert result is not None
        assert len(result) > 0
    
    def test_analyst_agent(self):
        """测试分析 Agent"""
        agent = AnalystAgent("test", MockLLM())
        result = agent.execute("测试数据")
        assert "分析" in result
    
    def test_writer_agent(self):
        """测试写作 Agent"""
        agent = WriterAgent("test", MockLLM())
        result = agent.execute("测试主题")
        assert len(result) > 100

## 三、集成测试

```python
class TestMultiAgentIntegration:
    """多 Agent 集成测试"""
    
    def test_sequential_pipeline(self):
        """测试顺序流水线"""
        pipeline = AgentPipeline()
        pipeline.add_step("research", ResearchAgent("research", MockLLM()))
        pipeline.add_step("analysis", AnalystAgent("analysis", MockLLM()))
        pipeline.add_step("writing", WriterAgent("writing", MockLLM()))
        
        result = pipeline.run("测试任务")
        assert result["result"] is not None
    
    def test_supervisor_orchestration(self):
        """测试 Supervisor 编排"""
        supervisor = SupervisorOrchestrator(MockLLM(), {
            "researcher": ResearchAgent("researcher", MockLLM()),
            "analyst": AnalystAgent("analyst", MockLLM())
        })
        
        result = supervisor.run("测试任务")
        assert result["answer"] is not None
```

## 常见误区

1. **只做端到端测试，忽略单元测试**：端到端测试覆盖了完整流程，但无法精确定位是哪个 Agent 出了问题。单元测试能快速发现单个 Agent 的逻辑错误。
2. **Mock 对象过于简单**：MockLLM 永远返回"模拟回答"，无法测试 Agent 在不同输入下的行为。Mock 对象应该能根据输入返回不同的模拟输出。
3. **没有测试 Agent 间的边界情况**：Agent A 输出空字符串、Agent B 输出超长文本、Agent C 输出格式错误——这些边界情况在单元测试中很难覆盖，需要集成测试来验证。

---

## 工程建议

1. **从单 Agent 开始，按需演进**：先用单 Agent 验证核心逻辑，当遇到上下文瓶颈、能力稀释或需要并行处理时，再拆分为多 Agent。不要为了"看起来高级"而引入多 Agent 架构。
2. **为每个 Agent 定义清晰的职责边界**：每个 Agent 应该有单一、明确的职责（如"只负责搜索""只负责分析"），输入输出格式在设计阶段就确定下来，避免职责重叠和数据格式混乱。
3. **建立可观测性基础设施**：从第一版开始就为每个 Agent 添加结构化日志和追踪机制，记录输入、输出、耗时、错误。多 Agent 系统的调试难度远高于单 Agent，没有日志就是在"盲人摸象"。
4. **在关键决策节点加入人工审批**：涉及高风险操作（删除数据、发送消息、支付）和不可逆操作时，使用 Human-in-the-loop 机制暂停执行，等待人类确认后再继续。
