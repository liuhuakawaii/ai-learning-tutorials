# 02 性能优化——并发控制、Token 预算、调用限流

> 多 Agent 系统的性能优化：并发、成本、限流。

## 场景引入

你的多 Agent 系统上线后，用户抱怨"太慢了"。你发现 Supervisor 每次决策都要调用一次 LLM，五个 Agent 串行执行，总耗时是单 Agent 的五倍。更糟的是，Token 账单也在飙升。你需要在并发控制、Token 预算和调用限流之间找到平衡。

## 一、并发控制

```python
import asyncio
from asyncio import Semaphore

class ConcurrencyController:
    """并发控制器"""
    
    def __init__(self, max_concurrent: int = 5):
        self.semaphore = Semaphore(max_concurrent)
    
    async def execute_with_limit(self, coro):
        """限制并发执行"""
        async with self.semaphore:
            return await coro

# 使用示例
controller = ConcurrencyController(max_concurrent=3)

async def run_agents_concurrently(agents: list, task: str):
    """并发运行多个 Agent"""
    tasks = [controller.execute_with_limit(agent.execute(task)) for agent in agents]
    return await asyncio.gather(*tasks)
```

## 二、Token 预算

```python
class TokenBudget:
    """Token 预算"""
    
    def __init__(self, total_budget: int):
        self.total_budget = total_budget
        self.used = 0
    
    def check_budget(self, estimated_tokens: int) -> bool:
        """检查是否有足够预算"""
        return self.used + estimated_tokens <= self.total_budget
    
    def consume(self, tokens: int):
        """消耗 Token"""
        self.used += tokens
    
    def remaining(self) -> int:
        """剩余预算"""
        return self.total_budget - self.used

class BudgetAwareAgent:
    """预算感知 Agent"""
    
    def __init__(self, agent, budget: TokenBudget):
        self.agent = agent
        self.budget = budget
    
    def execute(self, task: str) -> str:
        # 估算 Token 消耗
        estimated = self._estimate_tokens(task)
        
        if not self.budget.check_budget(estimated):
            raise BudgetExceededError("Token 预算不足")
        
        result = self.agent.execute(task)
        
        # 记录实际消耗
        actual = self._count_tokens(result)
        self.budget.consume(actual)
        
        return result
```

## 三、调用限流

```python
from datetime import datetime, timedelta

class RateLimiter:
    """限流器"""
    
    def __init__(self, max_calls: int, time_window: int):
        self.max_calls = max_calls
        self.time_window = time_window  # 秒
        self.calls = []
    
    def can_call(self) -> bool:
        """检查是否可以调用"""
        now = datetime.now()
        cutoff = now - timedelta(seconds=self.time_window)
        
        # 清理过期记录
        self.calls = [c for c in self.calls if c > cutoff]
        
        return len(self.calls) < self.max_calls
    
    def record_call(self):
        """记录调用"""
        self.calls.append(datetime.now())

# 使用示例
limiter = RateLimiter(max_calls=10, time_window=60)  # 每分钟最多 10 次

class RateLimitedAgent:
    """限流 Agent"""
    
    def __init__(self, agent, limiter: RateLimiter):
        self.agent = agent
        self.limiter = limiter
    
    def execute(self, task: str) -> str:
        if not self.limiter.can_call():
            raise RateLimitExceeded("调用频率超限")
        
        self.limiter.record_call()
        return self.agent.execute(task)
```

## 四、缓存优化

```python
class AgentCache:
    """Agent 缓存"""
    
    def __init__(self, ttl: int = 3600):
        self.cache = {}
        self.ttl = ttl
    
    def get(self, key: str) -> str:
        """获取缓存"""
        if key in self.cache:
            entry = self.cache[key]
            if datetime.now() - entry["time"] < timedelta(seconds=self.ttl):
                return entry["value"]
        return None
    
    def set(self, key: str, value: str):
        """设置缓存"""
        self.cache[key] = {
            "value": value,
            "time": datetime.now()
        }

class CachedAgent:
    """缓存 Agent"""
    
    def __init__(self, agent, cache: AgentCache):
        self.agent = agent
        self.cache = cache
    
    def execute(self, task: str) -> str:
        # 检查缓存
        cached = self.cache.get(task)
        if cached:
            return cached
        
        # 执行并缓存
        result = self.agent.execute(task)
        self.cache.set(task, result)
        return result
```

## 常见误区

1. **并发数设置过高导致 API 限流**：把所有 Agent 的并发数都设为 10，但 LLM API 的限流是每分钟 60 次。并发请求过多触发限流，反而导致所有请求变慢。需要根据 API 限流策略设置合理的并发数。
2. **Token 预算没有分 Agent 管理**：所有 Agent 共享一个 Token 预算，某个 Agent 消耗过多会导致其他 Agent 预算不足。应该为每个 Agent 设置独立的 Token 预算。
3. **缓存策略过于激进**：把所有 LLM 调用结果都缓存，但有些任务（如实时数据分析）的结果是有时效性的。缓存策略需要区分"可缓存"和"不可缓存"的调用。

## 工程建议

1. **从单 Agent 开始，按需演进**：先用单 Agent 验证核心逻辑，当遇到上下文瓶颈、能力稀释或需要并行处理时，再拆分为多 Agent。不要为了"看起来高级"而引入多 Agent 架构。
2. **为每个 Agent 定义清晰的职责边界**：每个 Agent 应该有单一、明确的职责（如"只负责搜索""只负责分析"），输入输出格式在设计阶段就确定下来，避免职责重叠和数据格式混乱。
3. **建立可观测性基础设施**：从第一版开始就为每个 Agent 添加结构化日志和追踪机制，记录输入、输出、耗时、错误。多 Agent 系统的调试难度远高于单 Agent，没有日志就是在"盲人摸象"。
4. **在关键决策节点加入人工审批**：涉及高风险操作（删除数据、发送消息、支付）和不可逆操作时，使用 Human-in-the-loop 机制暂停执行，等待人类确认后再继续。
