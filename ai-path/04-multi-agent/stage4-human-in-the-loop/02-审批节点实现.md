# 02 审批节点实现——在 LangGraph 中添加人工审批 gate

> 在 LangGraph 中实现人工审批节点，让 Agent 在关键步骤停下来等待人类确认。

## 场景引入

你已经在理论上理解了 Human-in-the-loop 的价值，但在 LangGraph 中怎么实现？图执行到某个节点时如何"暂停"？人类审批后如何"恢复"？状态如何保存？这些工程细节决定了人机协作用能不能真正落地。

## 一、LangGraph 审批节点

```python
from langgraph.graph import StateGraph, END
from langgraph.checkpoint.memory import MemorySaver

class ApprovalState(TypedDict):
    messages: list
    task: str
    proposed_action: dict
    approval_status: str  # pending, approved, rejected
    result: str

def propose_action(state: ApprovalState) -> ApprovalState:
    """提出行动方案"""
    llm = ChatOpenAI(model="gpt-4o")
    
    prompt = f"""根据以下任务，提出一个行动方案。

任务：{state['task']}

请以 JSON 格式输出行动方案。"""
    
    response = llm.invoke(prompt)
    action = json.loads(response.content)
    
    return {**state, "proposed_action": action, "approval_status": "pending"}

def human_approval(state: ApprovalState) -> ApprovalState:
    """人工审批节点（中断点）"""
    # 这个节点会中断执行，等待人类输入
    # 人类通过 API 提供审批结果
    return state

def execute_action(state: ApprovalState) -> ApprovalState:
    """执行已批准的行动"""
    if state["approval_status"] == "approved":
        # 执行行动
        result = f"已执行：{state['proposed_action']}"
        return {**state, "result": result}
    else:
        return {**state, "result": "行动被拒绝"}

def should_execute(state: ApprovalState) -> str:
    """判断是否执行"""
    if state["approval_status"] == "approved":
        return "execute"
    elif state["approval_status"] == "rejected":
        return END
    else:
        return "wait"

# 构建图
graph = StateGraph(ApprovalState)
graph.add_node("propose", propose_action)
graph.add_node("approval", human_approval)
graph.add_node("execute", execute_action)

graph.set_entry_point("propose")
graph.add_edge("propose", "approval")
graph.add_conditional_edges("approval", should_execute)
graph.add_edge("execute", END)

# 使用 MemorySaver 支持中断和恢复
checkpointer = MemorySaver()
app = graph.compile(checkpointer=checkpointer, interrupt_before=["approval"])
```

## 二、中断和恢复

```python
# 运行到中断点
config = {"configurable": {"thread_id": "1"}}
result = app.invoke({"task": "删除用户数据", "approval_status": "pending"}, config)

# 检查中断状态
print(result)  # 会在 approval 节点中断

# 人类审批后恢复
app.update_state(config, {"approval_status": "approved"})
result = app.invoke(None, config)  # 继续执行

print(result)  # 执行结果
```

## 三、异步审批

```python
class AsyncApprovalManager:
    """异步审批管理器"""
    
    def __init__(self, app, checkpointer):
        self.app = app
        self.checkpointer = checkpointer
    
    async def submit_for_approval(self, task: str) -> str:
        """提交审批"""
        config = {"configurable": {"thread_id": str(uuid.uuid4())}}
        
        # 运行到中断点
        await self.app.ainvoke({"task": task}, config)
        
        return config["configurable"]["thread_id"]
    
    async def approve(self, thread_id: str):
        """批准"""
        config = {"configurable": {"thread_id": thread_id}}
        self.app.update_state(config, {"approval_status": "approved"})
        return await self.app.ainvoke(None, config)
    
    async def reject(self, thread_id: str, reason: str):
        """拒绝"""
        config = {"configurable": {"thread_id": thread_id}}
        self.app.update_state(config, {"approval_status": "rejected", "reason": reason})
        return await self.app.ainvoke(None, config)
```

## 四、审批 UI

```python
import streamlit as st

def approval_ui():
    """审批界面"""
    st.title("人工审批")
    
    # 获取待审批任务
    pending_tasks = get_pending_approvals()
    
    for task in pending_tasks:
        with st.expander(f"任务: {task['task'][:50]}..."):
            st.write(f"**任务**: {task['task']}")
            st.write(f"**方案**: {json.dumps(task['proposed_action'], ensure_ascii=False)}")
            
            col1, col2 = st.columns(2)
            with col1:
                if st.button("批准", key=f"approve_{task['id']}"):
                    approve_task(task['id'])
                    st.success("已批准")
            with col2:
                if st.button("拒绝", key=f"reject_{task['id']}"):
                    reject_task(task['id'], "不符合要求")
                    st.error("已拒绝")
```

## 常见误区

1. **中断点设置过多**：在每个节点前都设置 interrupt_before，导致图执行频繁中断。中断点应该只设置在真正需要人工判断的节点，而不是所有节点。
2. **恢复执行时状态不完整**：审批后恢复执行，但之前的一些上下文信息（如中间计算结果）丢失了。需要确保 MemorySaver 正确保存了完整的执行状态。
3. **没有处理审批拒绝后的流程**：审批被拒绝后，直接结束图执行。更好的做法是让 Supervisor 重新决策——可能是修改方案后重新提交，也可能是切换到备选方案。

---

## 工程建议

1. **从单 Agent 开始，按需演进**：先用单 Agent 验证核心逻辑，当遇到上下文瓶颈、能力稀释或需要并行处理时，再拆分为多 Agent。不要为了"看起来高级"而引入多 Agent 架构。
2. **为每个 Agent 定义清晰的职责边界**：每个 Agent 应该有单一、明确的职责（如"只负责搜索""只负责分析"），输入输出格式在设计阶段就确定下来，避免职责重叠和数据格式混乱。
3. **建立可观测性基础设施**：从第一版开始就为每个 Agent 添加结构化日志和追踪机制，记录输入、输出、耗时、错误。多 Agent 系统的调试难度远高于单 Agent，没有日志就是在"盲人摸象"。
4. **在关键决策节点加入人工审批**：涉及高风险操作（删除数据、发送消息、支付）和不可逆操作时，使用 Human-in-the-loop 机制暂停执行，等待人类确认后再继续。
