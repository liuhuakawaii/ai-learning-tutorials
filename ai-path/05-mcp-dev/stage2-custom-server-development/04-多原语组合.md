# 04 多原语组合——一个 Server 同时提供 Tool + Resource + Prompt

> 实际项目中，一个 MCP Server 通常会同时提供多种原语。

## 场景引入

你已经分别学会了 Tool、Resource、Prompt 的开发。现在要为公司做一个完整的数据库 MCP Server，需要同时提供三种能力：Tool 让 AI 执行查询，Resource 让 AI 浏览表结构，Prompt 让 AI 生成 SQL。问题是，这三种原语怎么组织在一个 Server 里？它们之间怎么协作？比如 Prompt 生成的 SQL 怎么传给 Tool 执行？Resource 返回的表结构怎么注入到 Prompt 里？

---

## 学习目标

- 掌握多原语组合的设计方法
- 理解原语间的协作关系
- 学会实现一个完整的 MCP Server

---

## 一、组合设计

```python
from mcp.server import Server
from mcp.types import Tool, Resource, Prompt, TextContent, PromptMessage

server = Server("database-server")

# Tool：执行查询
@server.tool()
async def query(sql: str) -> list[TextContent]:
    """执行 SQL 查询"""
    results = await execute_sql(sql)
    return [TextContent(type="text", text=json.dumps(results))]

# Resource：表结构
@server.resource("database://tables")
async def list_tables() -> list[TextContent]:
    """获取表列表"""
    tables = await get_tables()
    return [TextContent(type="text", text=json.dumps(tables))]

# Prompt：查询助手
@server.prompt()
async def query_assistant(table: str, question: str) -> list[PromptMessage]:
    """查询助手 Prompt"""
    schema = await get_table_schema(table)
    return [
        PromptMessage(
            role="user",
            content=TextContent(
                type="text",
                text=f"""表 {table} 的结构：
{json.dumps(schema)}

问题：{question}

请生成 SQL 查询。"""
            )
        )
    ]
```

---

## 二、原语协作

```
原语协作模式：

1. Resource → Tool
   Resource 提供数据描述
   Tool 执行具体操作

2. Prompt → Tool
   Prompt 生成查询
   Tool 执行查询

3. Tool → Resource
   Tool 修改数据
   Resource 提供数据视图
```

## 三、完整 Server 示例

```python
class DatabaseMCPServer:
    """数据库 MCP Server"""
    
    def __init__(self):
        self.server = Server("database-server")
        self._register_tools()
        self._register_resources()
        self._register_prompts()
    
    def _register_tools(self):
        """注册工具"""
        
        @self.server.tool()
        async def query(sql: str) -> list[TextContent]:
            results = await self._execute_sql(sql)
            return [TextContent(type="text", text=json.dumps(results))]
        
        @self.server.tool()
        async def insert(table: str, data: dict) -> list[TextContent]:
            result = await self._insert_data(table, data)
            return [TextContent(type="text", text=json.dumps(result))]
    
    def _register_resources(self):
        """注册资源"""
        
        @self.server.resource("database://tables")
        async def list_tables() -> list[TextContent]:
            tables = await self._get_tables()
            return [TextContent(type="text", text=json.dumps(tables))]
        
        @self.server.resource("database://tables/{table}")
        async def table_schema(table: str) -> list[TextContent]:
            schema = await self._get_schema(table)
            return [TextContent(type="text", text=json.dumps(schema))]
    
    def _register_prompts(self):
        """注册提示"""
        
        @self.server.prompt()
        async def query_helper(table: str, question: str) -> list[PromptMessage]:
            schema = await self._get_schema(table)
            return [
                PromptMessage(
                    role="user",
                    content=TextContent(
                        type="text",
                        text=f"表结构：{json.dumps(schema)}\n\n问题：{question}"
                    )
                )
            ]
```

## 四、Server 组织

```
Server 组织建议：

1. 按领域分组
   - 数据库相关：query, insert, update, delete
   - 文件相关：read, write, list
   - API 相关：get, post, put

2. 命名规范
   - Tool：动词_名词（query_database）
   - Resource：名词复数（tables, files）
   - Prompt：名词_helper（query_helper）

3. 文档
   - 每个原语都要有清晰的描述
   - 参数要说明类型和用途
   - 提供使用示例
```

## 常见误区

```
误区 1：一个 Server 只能提供一种原语
  MCP Server 可以同时提供 Tool、Resource、Prompt，数量不限。
  把相关能力放在同一个 Server 里，比分散到多个 Server 更容易管理。

误区 2：原语之间不需要协作
  原语协作是 MCP 的核心价值。Resource 提供数据描述，Prompt 生成查询，Tool 执行操作。
  设计时要画出原语之间的数据流，明确协作关系。

误区 3：命名可以随意
  Tool 用动词（query、insert），Resource 用名词（tables、schemas），Prompt 用名词_helper（query_helper）。
  一致的命名让 AI 更容易理解每个原语的用途。

误区 4：注册顺序无所谓
  注册顺序可能影响 tools/list 的返回顺序。
  把最常用的 Tool 放在前面，AI 更容易发现和使用。
```

---

## 工程建议

```
1. 按领域组织原语
  数据库相关的 Tool、Resource、Prompt 放在同一个 Server。
  文件操作的放在另一个 Server。按领域划分，职责清晰。

2. 原语之间通过 Server 内部函数协作
  Prompt 生成 SQL 时，直接调用 Server 内部的 get_table_schema 函数获取表结构。
  不要通过 MCP 协议回调自己，那会增加不必要的延迟。

3. 提供完整的使用文档
  在每个原语的 description 中说明与其他原语的关系。
  例如：Prompt 的 description 可以写"生成 SQL 后用 query Tool 执行"。

4. 用类封装 Server 逻辑
  把 Tool、Resource、Prompt 的注册逻辑放在一个类中。
  共享的数据库连接、配置等作为类的属性，避免全局变量。
```

---

## 小结

1. 一个 Server 可以同时提供 Tool、Resource、Prompt
2. 原语间可以协作完成复杂任务
3. 按领域组织原语，保持命名一致
4. 提供清晰的文档和使用示例

## 参考答案

### 练习一：实现多原语组合的 Server

**思路**：用类封装一个数据库 MCP Server，同时提供 Tool（执行查询）、Resource（浏览表结构）、Prompt（生成 SQL），三种原语通过内部函数协作。

**答案**：

```python
import json
from mcp.server import Server
from mcp.types import TextContent, PromptMessage


class DatabaseMCPServer:
    """数据库 MCP Server——同时提供 Tool、Resource、Prompt"""

    def __init__(self):
        self.server = Server("database-server")
        self._register_tools()
        self._register_resources()
        self._register_prompts()

    # ---- 内部共享函数 ----

    async def _get_tables(self) -> list[dict]:
        """获取所有表（内部函数，供多种原语复用）"""
        return [
            {"name": "users", "columns": ["id", "email", "name", "status"], "row_count": 1250},
            {"name": "orders", "columns": ["id", "user_id", "total", "status"], "row_count": 8432},
            {"name": "products", "columns": ["id", "name", "price", "stock"], "row_count": 356},
        ]

    async def _get_table_schema(self, table_name: str) -> dict | None:
        """获取表结构（内部函数）"""
        tables = await self._get_tables()
        for t in tables:
            if t["name"] == table_name:
                return t
        return None

    async def _execute_sql(self, sql: str) -> dict:
        """执行 SQL（内部函数）"""
        # 安全检查：只允许 SELECT
        if not sql.strip().upper().startswith("SELECT"):
            return {"error": "仅允许 SELECT 查询"}
        # 模拟执行
        return {"rows": [{"id": 1, "name": "Alice"}], "row_count": 1}

    # ---- Tool 注册 ----

    def _register_tools(self):
        @self.server.tool()
        async def query(sql: str) -> list[TextContent]:
            """执行 SQL 查询。仅允许 SELECT 语句。"""
            result = await self._execute_sql(sql)
            return [TextContent(type="text", text=json.dumps(result, ensure_ascii=False))]

        @self.server.tool()
        async def explain_sql(sql: str) -> list[TextContent]:
            """分析 SQL 语句的执行计划，不实际执行。"""
            if not sql.strip().upper().startswith("SELECT"):
                return [TextContent(type="text", text="仅支持 SELECT 语句的执行计划分析")]
            return [TextContent(type="text", text=json.dumps({
                "sql": sql,
                "plan": "Seq Scan on users (cost=0.00..35.50 rows=1250)",
                "estimated_rows": 1250
            }, ensure_ascii=False))]

    # ---- Resource 注册 ----

    def _register_resources(self):
        @self.server.resource("database://tables")
        async def list_tables() -> list[TextContent]:
            """获取所有表的概要信息"""
            tables = await self._get_tables()
            summary = {t["name"]: {"columns": t["columns"], "row_count": t["row_count"]} for t in tables}
            return [TextContent(type="text", text=json.dumps(summary, ensure_ascii=False, indent=2))]

        @self.server.resource("database://tables/{table_name}")
        async def table_schema(table_name: str) -> list[TextContent]:
            """获取指定表的结构"""
            schema = await self._get_table_schema(table_name)
            if not schema:
                return [TextContent(type="text", text=json.dumps({"error": f"表 '{table_name}' 不存在"}))]
            return [TextContent(type="text", text=json.dumps(schema, ensure_ascii=False, indent=2))]

    # ---- Prompt 注册 ----

    def _register_prompts(self):
        @self.server.prompt()
        async def query_helper(table: str, question: str) -> list[PromptMessage]:
            """SQL 查询助手。根据表结构和自然语言问题生成 SQL。"""
            schema = await self._get_table_schema(table)
            schema_text = json.dumps(schema, ensure_ascii=False, indent=2) if schema else "表结构未知"

            return [PromptMessage(
                role="user",
                content=TextContent(
                    type="text",
                    text=f"""表 {table} 的结构：
{schema_text}

用户问题：{question}

请生成一个 SQL SELECT 查询来回答这个问题。
要求：
1. 只生成 SELECT 语句
2. 使用 LIMIT 限制返回行数
3. 添加必要的 WHERE 条件"""
                )
            )]

    def run(self):
        """启动 Server"""
        import asyncio
        from mcp.server.stdio import stdio_server
        asyncio.run(self._run_async())

    async def _run_async(self):
        async with stdio_server() as (read_stream, write_stream):
            await self.server.run(read_stream, write_stream)


if __name__ == "__main__":
    server = DatabaseMCPServer()
    server.run()
```

**要点**：
- 内部共享函数（_get_tables, _execute_sql）供多种原语复用，避免重复代码
- Prompt 生成 SQL 时直接调用内部函数获取表结构，不需要通过 MCP 协议回调自己
- Tool 用动词命名（query, explain_sql），Resource 用名词命名（tables, table_schema）
- 常见错误：三种原语各自独立实现，没有共享内部函数，导致代码重复

### 练习二：设计原语间的协作流程

**思路**：画出 Prompt → Tool → Resource 的协作数据流，说明每个环节的输入输出。

**答案**：

```
原语协作流程（用户问"有多少活跃用户？"）：

┌─────────────────────────────────────────────────────────────┐
│  协作模式 1：Prompt → Tool（Prompt 生成查询，Tool 执行）      │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Step 1: Client 调用 prompts/get                            │
│    → Server 返回 query_helper Prompt                        │
│    → Prompt 中注入了表结构（来自内部函数 _get_table_schema） │
│                                                             │
│  Step 2: AI 模型根据 Prompt 生成 SQL                        │
│    → "SELECT COUNT(*) FROM users WHERE status = 'active'"   │
│                                                             │
│  Step 3: Client 调用 tools/call (query)                     │
│    → Server 执行 SQL（来自内部函数 _execute_sql）           │
│    → 返回 {"row_count": 1250}                               │
│                                                             │
│  Step 4: AI 模型生成自然语言回答                             │
│    → "数据库中有 1250 个活跃用户。"                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  协作模式 2：Resource → Tool（Resource 提供上下文，Tool 操作）│
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Step 1: Client 调用 resources/read (database://tables)     │
│    → Server 返回所有表的概要信息                             │
│    → AI 了解有哪些表、每张表有多少数据                       │
│                                                             │
│  Step 2: Client 调用 resources/read (database://tables/users)│
│    → Server 返回 users 表的完整结构                         │
│    → AI 了解列名、类型、约束                                │
│                                                             │
│  Step 3: Client 调用 tools/call (query)                     │
│    → AI 根据 Resource 提供的表结构生成准确的 SQL            │
│    → Server 执行并返回结果                                   │
│                                                             │
└─────────────────────────────────────────────────────────────┘

关键点：
  - Resource 是"看"（只读、幂等），Tool 是"做"（有副作用）
  - Prompt 是"问"（生成查询），Tool 是"执行"（运行查询）
  - 三种原语通过 Server 内部函数协作，不通过 MCP 协议回调
```

**要点**：
- Prompt 生成 SQL 时需要表结构，直接调用内部函数获取，不要通过 MCP 协议回调
- Resource 让 AI 在调用 Tool 前了解数据结构，减少无效调用
- 常见错误：Prompt 通过 MCP 协议回调自己的 Resource，增加不必要的延迟和复杂度

### 练习三：设计 Server 组织结构

**思路**：按领域划分 Server，每个 Server 内部按原语类型组织代码，用类封装共享状态。

**答案**：

```
Server 组织结构设计：

推荐目录结构：
  my-mcp-servers/
  ├── database-server/
  │   ├── __init__.py
  │   ├── server.py          # Server 入口，注册所有原语
  │   ├── tools/
  │   │   ├── __init__.py
  │   │   ├── query.py       # query Tool
  │   │   ├── insert.py      # insert Tool
  │   │   └── explain.py     # explain_sql Tool
  │   ├── resources/
  │   │   ├── __init__.py
  │   │   ├── tables.py      # 表列表、表结构 Resource
  │   │   └── stats.py       # 数据库统计 Resource
  │   ├── prompts/
  │   │   ├── __init__.py
  │   │   ├── query_helper.py    # SQL 生成 Prompt
  │   │   └── analysis_helper.py # 数据分析 Prompt
  │   └── shared/
  │       ├── __init__.py
  │       ├── db_client.py   # 数据库连接（Tool 和 Resource 共用）
  │       └── cache.py       # 缓存（Resource 订阅用）
  │
  └── file-server/
      ├── __init__.py
      ├── server.py
      ├── tools/
      │   ├── read.py
      │   ├── write.py
      │   └── search.py
      ├── resources/
      │   ├── directory.py
      │   └── file_content.py
      └── shared/
          ├── path_utils.py  # 路径安全检查（Tool 和 Resource 共用）
          └── watcher.py     # 文件变更监听

命名规范：
  ┌──────────────┬──────────────────────┬───────────────────┐
  │  原语类型     │  命名模式            │  示例              │
  ├──────────────┼──────────────────────┼───────────────────┤
  │  Tool        │  动词_名词           │  query_database    │
  │              │                      │  send_email        │
  │              │                      │  create_user       │
  ├──────────────┼──────────────────────┼───────────────────┤
  │  Resource    │  scheme://名词/名词  │  database://tables │
  │              │                      │  file:///path      │
  │              │                      │  config://settings │
  ├──────────────┼──────────────────────┼───────────────────┤
  │  Prompt      │  名词_helper         │  query_helper      │
  │              │                      │  review_helper     │
  └──────────────┴──────────────────────┴───────────────────┘

组织原则：
  1. 按领域划分 Server（数据库、文件、API 各一个 Server）
  2. Server 内部按原语类型分目录（tools/、resources/、prompts/）
  3. 共享逻辑放 shared/ 目录（数据库连接、路径校验、缓存）
  4. 每个原语一个文件，职责单一
  5. server.py 作为入口，负责注册所有原语
```

**要点**：
- 按领域划分 Server，不要把所有 Tool 放在一个 Server 里
- 共享逻辑（如数据库连接、路径校验）放 shared/ 目录，避免重复实现
- 常见错误：把所有原语都写在一个文件里，代码超过 1000 行后难以维护
