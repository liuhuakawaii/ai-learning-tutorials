# 05 错误处理——MCP Server 的异常处理、超时、降级策略

> MCP Server 的错误处理直接影响 AI 应用的稳定性。

## 场景引入

你的 MCP Server 在测试环境跑得好好的，上了生产环境后各种问题冒出来：数据库偶尔超时、外部 API 偶尔返回 500、用户传入的 SQL 语法错误。每次出错，Server 要么直接崩溃，要么返回一堆堆栈信息给 AI。AI 拿到堆栈信息也看不懂，只能告诉用户"出错了"。你需要一套完整的错误处理体系：超时要重试、崩溃要降级、错误要友好。

## 一、错误类型

```
MCP 错误类型：

1. 协议错误
   - 解析错误（-32700）
   - 无效请求（-32600）
   - 方法未找到（-32601）

2. 工具错误
   - 工具不存在
   - 参数错误
   - 执行失败

3. 资源错误
   - 资源不存在
   - 访问被拒绝
   - 资源不可用

4. 系统错误
   - 内部错误（-32603）
   - 超时
   - 网络错误
```

from mcp.server import Server
from mcp.types import TextContent

server = Server("my-server")

@server.tool()
async def safe_tool(param: str) -> list[TextContent]:
    """带错误处理的工具"""
    try:
        # 参数验证
        if not param:
            return [TextContent(
                type="text",
                text="错误：参数不能为空"
            )]
        
        # 执行操作
        result = await risky_operation(param)
        return [TextContent(type="text", text=result)]
    
    except TimeoutError:
        return [TextContent(
            type="text",
            text="错误：操作超时，请稍后重试"
        )]
    
    except Exception as e:
        return [TextContent(
            type="text",
            text=f"错误：{str(e)}"
        )]

## 三、超时处理

```python
import asyncio

class TimeoutHandler:
    """超时处理器"""
    
    def __init__(self, timeout: float = 30.0):
        self.timeout = timeout
    
    async def execute_with_timeout(self, coro):
        """带超时的执行"""
        try:
            return await asyncio.wait_for(coro, timeout=self.timeout)
        except asyncio.TimeoutError:
            raise TimeoutError(f"操作超时（{self.timeout}秒）")

# 使用示例
timeout_handler = TimeoutHandler(timeout=10.0)

@server.tool()
async def slow_operation(param: str) -> list[TextContent]:
    """可能很慢的操作"""
    try:
        result = await timeout_handler.execute_with_timeout(
            slow_database_query(param)
        )
        return [TextContent(type="text", text=result)]
    except TimeoutError as e:
        return [TextContent(type="text", text=str(e))]
```

## 四、降级策略

```python
class FallbackHandler:
    """降级处理器"""
    
    def __init__(self):
        self.cache = {}
    
    async def execute_with_fallback(self, primary_coro, fallback_coro, cache_key: str = None):
        """带降级的执行"""
        try:
            result = await primary_coro
            if cache_key:
                self.cache[cache_key] = result
            return result
        except Exception:
            if cache_key and cache_key in self.cache:
                return self.cache[cache_key]
            return await fallback_coro

# 使用示例
fallback = FallbackHandler()

@server.tool()
async def resilient_query(sql: str) -> list[TextContent]:
    """带降级的查询"""
    result = await fallback.execute_with_fallback(
        primary_coro=execute_sql(sql),
        fallback_coro=get_cached_result(sql),
        cache_key=sql
    )
    return [TextContent(type="text", text=json.dumps(result))]

## 五、重试机制

```python
class RetryHandler:
    """重试处理器"""
    
    def __init__(self, max_retries: int = 3, delay: float = 1.0):
        self.max_retries = max_retries
        self.delay = delay
    
    async def execute_with_retry(self, coro):
        """带重试的执行"""
        last_exception = None
        
        for attempt in range(self.max_retries):
            try:
                return await coro
            except Exception as e:
                last_exception = e
                if attempt < self.max_retries - 1:
                    await asyncio.sleep(self.delay * (attempt + 1))
        
        raise last_exception
```

## 常见误区

```
误区 1：所有异常都返回 Internal Error
  不同类型的错误应该用不同的错误码。参数错误用 -32602，
  方法不存在用 -32601，工具执行失败用 -32001。
  统一返回 -32603 会让 Client 无法做针对性处理。

误区 2：把异常堆栈直接返回给 Client
  堆栈信息包含内部实现细节（文件路径、数据库连接串），不应该暴露给用户。
  返回友好的错误信息，把堆栈记录到服务端日志。

误区 3：重试就是简单地再调一次
  重试要考虑：最大重试次数、退避策略（指数退避）、是否幂等。
  写操作不能盲目重试，可能导致重复执行。

误区 4：降级就是返回错误
  降级是用次优方案替代失败的主方案，比如返回缓存数据。
  只有在降级方案也失败时，才返回错误。
```

## 工程建议

```
1. 建立错误分类体系
  把错误分为四类：协议错误（MCP 定义）、业务错误（Tool 逻辑）、
  系统错误（网络、超时）、安全错误（权限、注入）。
  每类错误有对应的错误码范围和处理策略。

2. 超时要分级
  不同 Tool 设置不同的超时时间。简单查询 5 秒，复杂报表 60 秒。
  超时后返回部分结果比完全失败更好。

3. 熔断器保护下游服务
  当数据库连续失败 N 次后，自动熔断，直接返回缓存数据或友好提示。
  避免大量请求堆积在超时的下游服务上。

4. 错误信息要对 AI 友好
  AI 需要根据错误信息决定下一步操作。
  "SQL 语法错误：缺少 WHERE 子句"比"Error code 42P01"有用得多。
```

## 参考答案

### 练习一：实现带完整错误处理的 Tool

**思路**：实现一个数据库查询 Tool，涵盖参数验证、业务错误、系统错误三层处理，每层返回对 AI 友好的错误信息。

**答案**：

```python
import json
import re
from mcp.server import Server
from mcp.types import TextContent

server = Server("robust-db-server")


class DatabaseError(Exception):
    """数据库错误基类"""
    pass


class SQLSyntaxError(DatabaseError):
    """SQL 语法错误"""
    pass


class QueryTimeoutError(DatabaseError):
    """查询超时"""
    pass


class PermissionDeniedError(DatabaseError):
    """权限不足"""
    pass


def validate_sql(sql: str) -> str | None:
    """验证 SQL 安全性，返回错误信息或 None"""
    if not sql or not sql.strip():
        return "SQL 语句不能为空"

    sql_upper = sql.strip().upper()

    # 只允许 SELECT
    if not sql_upper.startswith("SELECT"):
        return "仅允许 SELECT 查询，不支持 INSERT/UPDATE/DELETE/DROP 等修改操作"

    # 禁止危险关键字
    dangerous_keywords = ["DROP", "TRUNCATE", "ALTER", "GRANT", "REVOKE"]
    for keyword in dangerous_keywords:
        if re.search(rf'\b{keyword}\b', sql_upper):
            return f"SQL 中不允许包含 {keyword} 关键字"

    # 检查是否有 WHERE 子句（防止全表扫描）
    if "WHERE" not in sql_upper and "LIMIT" not in sql_upper:
        return "全表查询必须包含 LIMIT 子句，防止返回过多数据"

    return None


async def execute_query(sql: str, timeout: float = 10.0) -> dict:
    """执行 SQL 查询（模拟）"""
    # 模拟各种错误
    if "syntax_error" in sql:
        raise SQLSyntaxError("SQL 语法错误：缺少 WHERE 子句")
    if "timeout" in sql:
        raise QueryTimeoutError(f"查询超时（超过 {timeout} 秒）")
    if "permission" in sql:
        raise PermissionDeniedError("当前用户没有访问该表的权限")

    # 正常返回
    return {"rows": [{"id": 1, "name": "Alice"}], "row_count": 1}


@server.tool()
async def query_database(sql: str, timeout: float = 10.0) -> list[TextContent]:
    """执行只读 SQL 查询。仅允许 SELECT 语句，自动添加安全限制。

    Args:
        sql: SQL SELECT 查询语句
        timeout: 查询超时时间（秒），默认 10 秒
    """
    # 第一层：参数验证
    validation_error = validate_sql(sql)
    if validation_error:
        return [TextContent(type="text", text=json.dumps({
            "error": validation_error,
            "error_type": "validation",
            "hint": "请检查 SQL 语句是否符合安全规范"
        }, ensure_ascii=False))]

    # 第二层：业务错误
    try:
        result = await execute_query(sql, timeout=timeout)
        return [TextContent(type="text", text=json.dumps(result, ensure_ascii=False))]

    except SQLSyntaxError as e:
        return [TextContent(type="text", text=json.dumps({
            "error": str(e),
            "error_type": "sql_syntax",
            "hint": "请检查 SQL 语法，可以使用 explain_sql Tool 先分析执行计划"
        }, ensure_ascii=False))]

    except QueryTimeoutError as e:
        return [TextContent(type="text", text=json.dumps({
            "error": str(e),
            "error_type": "timeout",
            "hint": "尝试添加 WHERE 条件缩小查询范围，或增加 timeout 参数"
        }, ensure_ascii=False))]

    except PermissionDeniedError as e:
        return [TextContent(type="text", text=json.dumps({
            "error": str(e),
            "error_type": "permission",
            "hint": "请联系管理员授予相应表的访问权限"
        }, ensure_ascii=False))]

    # 第三层：系统错误
    except ConnectionError:
        return [TextContent(type="text", text=json.dumps({
            "error": "数据库连接失败",
            "error_type": "system",
            "hint": "数据库服务可能暂时不可用，请稍后重试"
        }, ensure_ascii=False))]

    except Exception as e:
        # 未知错误：记录日志，返回友好信息
        print(f"[ERROR] 未知错误: {type(e).__name__}: {e}")
        return [TextContent(type="text", text=json.dumps({
            "error": "服务器内部错误",
            "error_type": "unknown",
            "hint": "请稍后重试，如果问题持续存在请联系管理员"
        }, ensure_ascii=False))]
```

**要点**：
- 错误分三层处理：参数验证（最轻）→ 业务错误（可预期）→ 系统错误（兜底）
- 每个错误都要包含 hint 字段，告诉 AI 下一步该怎么做
- 未知错误不暴露堆栈，只返回通用提示，同时记录日志
- 常见错误：所有异常都用同一个 catch 处理，返回模糊的"出错了"，AI 无法决定下一步

### 练习二：实现超时处理功能

**思路**：用 asyncio.wait_for 实现超时控制，支持不同 Tool 设置不同的超时时间，超时后返回部分结果或友好提示。

**答案**：

```python
import asyncio
from typing import Any, Callable, Awaitable
from mcp.server import Server
from mcp.types import TextContent
import json

server = Server("timeout-server")


class TimeoutManager:
    """超时管理器——支持分级超时和超时后降级"""

    def __init__(self):
        self._timeout_profiles = {
            "fast": 5.0,      # 简单查询
            "normal": 15.0,   # 普通操作
            "slow": 60.0,     # 复杂报表
            "batch": 300.0,   # 批量处理
        }

    async def execute(
        self,
        coro: Awaitable,
        timeout: float = 15.0,
        timeout_message: str = "操作超时",
        partial_result: Any = None,
    ) -> dict:
        """带超时的执行

        Args:
            coro: 要执行的协程
            timeout: 超时时间（秒）
            timeout_message: 超时提示信息
            partial_result: 超时时返回的部分结果（如果有的话）

        Returns:
            {"success": True, "result": ...} 或 {"success": False, "error": ...}
        """
        try:
            result = await asyncio.wait_for(coro, timeout=timeout)
            return {"success": True, "result": result}
        except asyncio.TimeoutError:
            response = {
                "success": False,
                "error": timeout_message,
                "error_type": "timeout",
                "timeout_seconds": timeout,
                "hint": f"操作在 {timeout} 秒内未完成。尝试缩小查询范围或增加 timeout 参数。",
            }
            if partial_result is not None:
                response["partial_result"] = partial_result
                response["hint"] += " 已返回部分结果。"
            return response

    def get_timeout(self, profile: str) -> float:
        """获取超时配置"""
        return self._timeout_profiles.get(profile, 15.0)


timeout_manager = TimeoutManager()


async def slow_database_query(sql: str, progress_callback=None) -> dict:
    """模拟慢查询（支持进度回调）"""
    total_steps = 10
    results = []
    for i in range(total_steps):
        await asyncio.sleep(0.5)  # 模拟每步耗时
        results.append({"batch": i + 1, "rows": [{"id": i * 10 + j} for j in range(10)]})
        if progress_callback:
            await progress_callback(i + 1, total_steps)
    return {"batches": results, "total_rows": total_steps * 10}


@server.tool()
async def query_with_timeout(sql: str, timeout: float = 15.0) -> list[TextContent]:
    """执行带超时控制的数据库查询。

    Args:
        sql: SQL 查询语句
        timeout: 超时时间（秒），默认 15 秒。简单查询建议 5 秒，复杂报表建议 60 秒。
    """
    # 超时后返回的部分结果
    partial_results = []

    async def progress_callback(current, total):
        partial_results.append({"progress": f"{current}/{total}"})

    # 执行查询
    result = await timeout_manager.execute(
        coro=slow_database_query(sql, progress_callback),
        timeout=timeout,
        timeout_message=f"查询超时（{timeout} 秒）",
        partial_result=partial_results if partial_results else None,
    )

    if result["success"]:
        return [TextContent(type="text", text=json.dumps(result["result"], ensure_ascii=False))]
    else:
        return [TextContent(type="text", text=json.dumps(result, ensure_ascii=False))]


@server.tool()
async def fast_query(sql: str) -> list[TextContent]:
    """执行快速查询（5 秒超时）。适用于简单查询。"""
    result = await timeout_manager.execute(
        coro=slow_database_query(sql),
        timeout=timeout_manager.get_timeout("fast"),
        timeout_message="简单查询超时（5 秒），请检查 SQL 是否合理",
    )

    if result["success"]:
        return [TextContent(type="text", text=json.dumps(result["result"], ensure_ascii=False))]
    return [TextContent(type="text", text=json.dumps(result, ensure_ascii=False))]
```

**要点**：
- 不同类型的查询设置不同的超时时间（fast/normal/slow/batch）
- 超时后如果有部分结果，一并返回，比完全失败更好
- 超时错误要包含 hint，告诉 AI 怎么调整（缩小范围、增加 timeout）
- 常见错误：所有 Tool 都用同一个超时时间，简单查询等 60 秒太浪费，复杂查询 5 秒太短

### 练习三：实现带降级策略的 Tool

**思路**：实现三层降级策略：主方案（实时查询）→ 缓存降级 → 默认值降级，确保在任何情况下都能返回有用的结果。

**答案**：

```python
import json
import asyncio
import time
from typing import Any
from mcp.server import Server
from mcp.types import TextContent

server = Server("resilient-server")


class ResilientExecutor:
    """弹性执行器——支持缓存降级和默认值降级"""

    def __init__(self):
        self._cache: dict[str, dict] = {}  # key → {value, timestamp, ttl}
        self._cache_ttl = 300  # 缓存 5 分钟

    def _get_cache(self, key: str) -> Any | None:
        """获取缓存（未过期才返回）"""
        entry = self._cache.get(key)
        if entry and time.time() - entry["timestamp"] < entry["ttl"]:
            return entry["value"]
        return None

    def _set_cache(self, key: str, value: Any, ttl: int = 300):
        """设置缓存"""
        self._cache[key] = {
            "value": value,
            "timestamp": time.time(),
            "ttl": ttl,
        }

    async def execute_with_fallback(
        self,
        primary_func,
        cache_key: str = None,
        default_value: Any = None,
        fallback_chain: list[str] = None,
    ) -> dict:
        """带降级的执行

        降级顺序：主方案 → 缓存 → 默认值

        Args:
            primary_func: 主方案协程
            cache_key: 缓存键（为 None 则不使用缓存降级）
            default_value: 最终降级的默认值
            fallback_chain: 降级链路记录（用于日志）

        Returns:
            {"result": ..., "source": "primary|cache|default", "fallback_chain": [...]}
        """
        chain = fallback_chain or []

        # 第一优先：主方案
        try:
            result = await primary_func
            if cache_key:
                self._set_cache(cache_key, result)
            chain.append("primary:success")
            return {"result": result, "source": "primary", "fallback_chain": chain}
        except Exception as e:
            chain.append(f"primary:failed({type(e).__name__}: {str(e)[:50]})")

        # 第二优先：缓存降级
        if cache_key:
            cached = self._get_cache(cache_key)
            if cached is not None:
                chain.append("cache:hit")
                return {
                    "result": cached,
                    "source": "cache",
                    "warning": "数据来自缓存，可能不是最新的",
                    "fallback_chain": chain,
                }
            chain.append("cache:miss")

        # 第三优先：默认值降级
        if default_value is not None:
            chain.append("default:used")
            return {
                "result": default_value,
                "source": "default",
                "warning": "数据来自默认值，仅供参考",
                "fallback_chain": chain,
            }

        # 所有降级方案都失败
        chain.append("all_failed")
        return {
            "result": None,
            "source": "none",
            "error": "所有降级方案都失败",
            "fallback_chain": chain,
        }


executor = ResilientExecutor()


async def query_from_database(sql: str) -> dict:
    """从数据库查询（可能失败）"""
    if "fail" in sql.lower():
        raise ConnectionError("数据库连接失败")
    await asyncio.sleep(0.1)
    return {"rows": [{"id": 1, "name": "Alice"}], "row_count": 1}


async def query_from_readonly_replica(sql: str) -> dict:
    """从只读副本查询（降级方案之一）"""
    if "fail_all" in sql.lower():
        raise ConnectionError("只读副本也不可用")
    await asyncio.sleep(0.1)
    return {"rows": [{"id": 1, "name": "Alice (from replica)"}], "row_count": 1, "source": "replica"}


@server.tool()
async def resilient_query(sql: str) -> list[TextContent]:
    """带降级策略的数据库查询。

    降级顺序：主数据库 → 只读副本 → 缓存 → 默认值

    Args:
        sql: SQL 查询语句
    """
    cache_key = f"query:{sql}"

    # 尝试主数据库
    result = await executor.execute_with_fallback(
        primary_func=query_from_database(sql),
        cache_key=cache_key,
    )

    # 如果主数据库失败且无缓存，尝试只读副本
    if result["source"] == "none":
        result = await executor.execute_with_fallback(
            primary_func=query_from_readonly_replica(sql),
            cache_key=cache_key,
            default_value={"rows": [], "row_count": 0, "note": "服务暂时不可用，请稍后重试"},
            fallback_chain=result["fallback_chain"],
        )

    response = {
        "data": result["result"],
        "source": result["source"],
        "fallback_chain": result["fallback_chain"],
    }
    if "warning" in result:
        response["warning"] = result["warning"]
    if "error" in result:
        response["error"] = result["error"]

    return [TextContent(type="text", text=json.dumps(response, ensure_ascii=False))]


@server.tool()
async def get_user_stats() -> list[TextContent]:
    """获取用户统计（带缓存降级）"""
    cache_key = "user_stats"

    result = await executor.execute_with_fallback(
        primary_func=query_user_stats_from_db(),
        cache_key=cache_key,
        default_value={
            "total_users": "未知",
            "active_users": "未知",
            "note": "服务暂时不可用，显示默认值",
        },
    )

    return [TextContent(type="text", text=json.dumps({
        "data": result["result"],
        "source": result["source"],
        "warning": result.get("warning"),
    }, ensure_ascii=False))]


async def query_user_stats_from_db() -> dict:
    """从数据库查询用户统计"""
    await asyncio.sleep(0.1)
    return {"total_users": 1250, "active_users": 890, "new_today": 15}
```

**要点**：
- 降级不是返回错误，而是用次优方案替代——缓存数据比"出错了"有用得多
- 每次主方案成功后更新缓存，保证缓存尽可能新鲜
- 返回结果要标注数据来源（primary/cache/default），让 AI 知道数据的可信度
- 常见错误：主方案失败后直接返回错误，没有尝试缓存或默认值降级
