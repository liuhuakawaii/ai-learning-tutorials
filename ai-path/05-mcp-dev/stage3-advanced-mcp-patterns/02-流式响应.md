# 02 流式响应——长时间运行 Tool 的进度通知与流式输出

> 有些 Tool 需要运行很长时间。流式响应让用户知道进度。

## 场景引入

你写了一个"分析大型 CSV 文件"的 Tool，处理 100MB 的文件需要 30 秒。用户调用后，等了 30 秒才看到结果——期间没有任何反馈，用户以为服务挂了，反复重试，结果 Server 被重复请求压垮。你需要让 Tool 在执行过程中实时报告进度，甚至可以流式输出中间结果，让用户知道任务正在正常进行。

## 一、进度通知

```python
from mcp.server import Server
from mcp.types import TextContent, ProgressToken

server = Server("my-server")

@server.tool()
async def long_running_task(
    task: str,
    progress_token: ProgressToken = None
) -> list[TextContent]:
    """长时间运行的任务"""
    
    steps = ["初始化", "处理中", "验证", "完成"]
    
    for i, step in enumerate(steps):
        # 发送进度通知
        if progress_token:
            await server.send_progress(
                progress_token,
                progress=i + 1,
                total=len(steps),
                message=f"步骤 {i+1}/{len(steps)}: {step}"
            )
        
        # 执行步骤
        await asyncio.sleep(2)  # 模拟耗时操作
    
    return [TextContent(type="text", text="任务完成")]
```

## 二、流式输出

@server.tool()
async def stream_data(query: str) -> list[TextContent]:

## 三、取消支持

```python
@server.tool()
async def cancellable_task(
    task: str,
    cancellation_token: CancellationToken = None
) -> list[TextContent]:
    """可取消的任务"""
    
    for i in range(100):
        # 检查是否取消
        if cancellation_token and cancellation_token.is_cancelled:
            return [TextContent(type="text", text="任务已取消")]
        
        # 执行步骤
        await asyncio.sleep(0.1)
    
    return [TextContent(type="text", text="任务完成")]
```

## 常见误区

```
误区 1：所有 Tool 都需要流式响应
  只有执行时间超过 5 秒的操作才需要进度通知。
  快速操作加进度通知反而增加不必要的协议开销。

误区 2：进度通知会阻塞主流程
  进度通知是异步的 Notification，不等待 Client 响应。
  发送进度通知不会阻塞 Tool 的执行逻辑。

误区 3：取消就是杀掉进程
  取消应该通过 CancellationToken 协作式取消，不是强制杀进程。
  Tool 在安全点检查取消标志，清理资源后优雅退出。

误区 4：流式输出就是多次返回 result
  流式输出用 Notification 推送中间结果，最终只返回一个完整的 result。
  不要把中间结果当作最终结果返回，Client 会混淆。
```

---

## 工程建议

```
1. 进度通知要包含预估剩余时间
  "处理中 3/10 步，预计还需 14 秒"比"处理中 3/10 步"更有用。
  AI 可以根据剩余时间决定是否等待或提示用户。

2. 长时间操作必须支持取消
  超过 30 秒的操作必须实现 CancellationToken。
  用户不想等了可以随时取消，避免资源浪费。

3. 流式输出用缓冲区控制频率
  不要每处理一行数据就发一次 Notification。
  用缓冲区攒够一定量（如 100 行或 1 秒）再推送，减少协议开销。

4. 超时和取消要配合使用
  设置合理的超时时间作为兜底，防止用户忘记取消。
  超时后自动触发取消逻辑，清理资源。
```

1. 进度通知让用户知道任务进度
2. 流式输出适合大数据量场景
3. 取消支持让用户可以终止任务
4. 用 progress_token 发送进度更新

## 参考答案

### 练习一：带进度通知的 Tool

**思路**：进度通知的关键是通过 `progress_token` 发送异步通知，不阻塞主流程。在每个步骤开始时发送当前进度（已步数/总步数），并附带人类可读的消息描述。进度通知是 Notification，不需要等待 Client 响应。

**答案**：
```python
import asyncio
from mcp.server import Server
from mcp.types import TextContent, ProgressToken

server = Server("progress-server")

@server.tool()
async def process_csv(
    file_path: str,
    progress_token: ProgressToken = None
) -> list[TextContent]:
    """处理大型 CSV 文件，带进度通知"""

    lines = read_csv_lines(file_path)
    total = len(lines)
    results = []

    for i, line in enumerate(lines):
        if progress_token:
            percent = int((i + 1) / total * 100)
            await server.send_progress(
                progress_token,
                progress=i + 1,
                total=total,
                message=f"处理进度 {percent}%（{i + 1}/{total}）"
            )

        processed = await process_line(line)
        results.append(processed)

    return [TextContent(type="text", text=json.dumps({
        "status": "完成",
        "processed_count": len(results),
        "results": results[:10]
    }))]

def read_csv_lines(path: str) -> list[str]:
    with open(path, "r", encoding="utf-8") as f:
        return f.readlines()[1:]

async def process_line(line: str) -> dict:
    await asyncio.sleep(0.01)
    fields = line.strip().split(",")
    return {"name": fields[0], "value": fields[1] if len(fields) > 1 else ""}
```

**要点**：
- 进度通知是异步 Notification，发送后立即继续执行，不会阻塞 Tool 主流程
- 进度消息应包含百分比和剩余量的预估，比单纯"处理中"更有用
- 常见错误：每处理一行就发一次通知，在高频场景下会产生大量协议开销；应按百分比或固定间隔发送（如每 10%）

### 练习二：流式输出的 Tool

**思路**：流式输出的核心是用 Notification 推送中间结果，最终只返回一个完整的 result。中间结果通过 `notifications/progress` 或自定义通知推送给 Client，最终返回汇总结果。不能把中间结果当作最终 result 多次返回。

**答案**：
```python
import asyncio
import json
from mcp.server import Server
from mcp.types import TextContent, ProgressToken

server = Server("stream-server")

@server.tool()
async def stream_query(
    database: str,
    sql: str,
    batch_size: int = 100,
    progress_token: ProgressToken = None
) -> list[TextContent]:
    """流式查询数据库，分批返回结果"""

    cursor = await execute_query(database, sql)
    all_results = []
    batch_count = 0

    while True:
        rows = await cursor.fetch(batch_size)
        if not rows:
            break

        all_results.extend(rows)
        batch_count += 1

        if progress_token:
            await server.send_progress(
                progress_token,
                progress=len(all_results),
                total=0,
                message=f"已获取 {len(all_results)} 条记录（第 {batch_count} 批）"
            )

    return [TextContent(type="text", text=json.dumps({
        "total": len(all_results),
        "data": all_results
    }, ensure_ascii=False))]

async def execute_query(database: str, sql: str):
    class MockCursor:
        def __init__(self):
            self._data = [{"id": i, "name": f"user_{i}"} for i in range(250)]
            self._pos = 0

        async def fetch(self, size):
            if self._pos >= len(self._data):
                return []
            batch = self._data[self._pos:self._pos + size]
            self._pos += size
            return batch

    return MockCursor()
```

**要点**：
- 流式输出用 Notification 推送中间结果，最终只返回一个完整的 result；不要把每次推送都当作独立的 result 返回
- 用缓冲区控制推送频率，避免每行数据都发一次 Notification 导致协议开销过大
- 常见错误：把流式输出理解为多次调用 `return`，实际上 Tool 函数只能 return 一次，中间结果只能通过通知推送

### 练习三：可取消的长时间任务

**思路**：取消必须是协作式的——Tool 在安全点检查取消标志，清理资源后优雅退出。不能用强制杀进程的方式，否则会导致事务未提交、连接未释放等资源泄漏问题。取消后应返回明确的状态信息，让 Client 知道任务已被终止。

**答案**：
```python
import asyncio
from mcp.server import Server
from mcp.types import TextContent, CancellationToken

server = Server("cancellable-server")

@server.tool()
async def train_model(
    dataset_path: str,
    epochs: int = 100,
    cancellation_token: CancellationToken = None
) -> list[TextContent]:
    """训练模型——支持取消，每个 epoch 结束时检查取消标志"""

    data = await load_dataset(dataset_path)
    model = initialize_model()
    losses = []

    for epoch in range(epochs):
        if cancellation_token and cancellation_token.is_cancelled:
            save_checkpoint(model, epoch)
            return [TextContent(type="text", text=json.dumps({
                "status": "cancelled",
                "completed_epochs": epoch,
                "last_loss": losses[-1] if losses else None,
                "checkpoint_saved": True
            }))]

        loss = await train_one_epoch(model, data)
        losses.append(loss)

    return [TextContent(type="text", text=json.dumps({
        "status": "completed",
        "total_epochs": epochs,
        "final_loss": losses[-1]
    }))]

async def load_dataset(path: str) -> list:
    return [{"x": i, "y": i * 2 + 1} for i in range(1000)]

def initialize_model():
    return {"weights": [0.0], "bias": 0.0}

async def train_one_epoch(model: dict, data: list) -> float:
    await asyncio.sleep(0.1)
    return 0.5

def save_checkpoint(model: dict, epoch: int):
    with open(f"checkpoint_epoch_{epoch}.json", "w") as f:
        json.dump(model, f)
```

**要点**：
- 取消检查点应放在步骤边界（如每个 epoch 结束时），不要放在循环体内部高频检查，否则影响性能
- 取消时必须清理资源：保存进度、关闭连接、释放锁；直接 return 不清理会导致资源泄漏
- 常见错误：用 `asyncio.cancel()` 强制取消任务，这会抛出 `CancelledError` 跳过清理逻辑；应使用 `CancellationToken` 协作式取消
