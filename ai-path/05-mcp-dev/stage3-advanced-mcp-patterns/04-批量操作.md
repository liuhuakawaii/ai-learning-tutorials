# 04 批量操作——高效处理批量请求的 MCP 模式

> 批量操作可以显著提高效率，减少网络开销。

## 场景引入

AI 助手需要一次性插入 500 条用户记录到数据库。如果每条记录调用一次 tools/call，就要 500 次网络往返，不仅慢，还可能触发速率限制。你希望能有一个批量插入的 Tool，一次传入所有记录，Server 内部用事务批量处理。但批量操作的部分失败怎么处理？100 条里有 3 条插入失败，是全部回滚还是只报告失败的？

## 一、批量操作概念

```
批量操作的优势：

1. 减少网络开销
   - 一次请求处理多个操作
   - 减少 HTTP 请求次数

2. 提高效率
   - 批量数据库操作
   - 批量文件处理

3. 原子性
   - 批量操作可以保证原子性
   - 要么全部成功，要么全部失败
```

## 二、实现

```python
from mcp.server import Server
from mcp.types import TextContent

server = Server("my-server")

# 白名单表名，防止 SQL 注入
ALLOWED_TABLES = {"users", "orders", "products"}

@server.tool()
async def batch_query(queries: list[str]) -> list[TextContent]:
    """批量查询——只允许 SELECT 语句，防止写操作"""
    results = []
    for sql in queries:
        if not sql.strip().upper().startswith("SELECT"):
            results.append({"error": "只允许 SELECT 查询"})
            continue
        result = await execute_sql(sql)
        results.append(result)
    return [TextContent(type="text", text=json.dumps(results))]

@server.tool()
async def batch_insert(table: str, records: list[dict]) -> list[TextContent]:
    """批量插入——表名白名单校验，字段参数化"""
    if table not in ALLOWED_TABLES:
        return [TextContent(type="text", text=json.dumps({"error": f"表 {table} 不在白名单中"}))]

    async with pool.acquire() as conn:
        async with conn.transaction():
            for record in records:
                columns = ", ".join(record.keys())
                placeholders = ", ".join(f"${i+1}" for i in range(len(record)))
                await conn.execute(
                    f"INSERT INTO {table} ({columns}) VALUES ({placeholders})",
                    *record.values()
                )
    
    return [TextContent(
        type="text",
        text=f"成功插入 {len(records)} 条记录"
    )]
```

## 三、并行批量

```python
import asyncio

@server.tool()
async def parallel_batch_query(queries: list[str]) -> list[TextContent]:
    """并行批量查询"""
    
    async def execute_one(sql):
        return await execute_sql(sql)
    
    # 并行执行
    tasks = [execute_one(sql) for sql in queries]
    results = await asyncio.gather(*tasks)
    
    return [TextContent(
        type="text",
        text=json.dumps(results)
    )]
```

@server.tool()

## 常见误区

```
误区 1：批量操作就是循环调用单次操作
  真正的批量操作应该在数据库层用批量 INSERT/UPDATE，不是循环调用单条 SQL。
  循环调用 500 次 INSERT 比一次 INSERT INTO ... VALUES (...),(...) 慢 10 倍。

误区 2：批量操作必须全部成功或全部失败
  要根据业务场景选择：金融操作用事务全部回滚，数据导入可以部分成功。
  在 Tool 的 description 中明确说明失败策略。

误区 3：并行一定比串行快
  并行批量要考虑数据库连接池大小、锁竞争、资源争用。
  小批量并行快，大批量串行更稳定。

误区 4：批量操作不需要限制数量
  必须设置批量大小上限（如 1000 条）。无限制的批量操作可能耗尽内存或超时。
```

---

## 工程建议

```
1. 批量大小要有上限
  在 inputSchema 中用 maxItems 限制数组长度。
  超过上限时提示用户分批处理。

2. 返回详细的执行报告
  "成功 497 条，失败 3 条"加上每条失败的原因和索引。
  让 AI 能精确告诉用户哪些数据有问题。

3. 大批量用分页 + 流式处理
  超过 1000 条的批量操作，Server 内部分页处理。
  每处理一批发送一次进度通知，避免超时。

4. 批量查询也要限制返回量
  batch_query 的每条 SQL 都要自动添加 LIMIT。
  防止一条 SQL 返回百万行数据拖慢整个批量操作。
```

## 参考答案

### 练习一：批量查询 Tool

**思路**：批量查询的核心是减少网络往返，一次请求执行多条 SQL。但必须限制：只允许 SELECT 语句（防止批量写入）、每条 SQL 自动添加 LIMIT（防止返回百万行）、设置批量大小上限。返回时要包含每条查询的结果或错误，让 AI 能精确定位问题。

**答案**：
```python
import json
from mcp.server import Server
from mcp.types import TextContent

ALLOWED_TABLES = {"users", "orders", "products", "logs"}
MAX_BATCH_SIZE = 50
MAX_LIMIT = 1000

server = Server("batch-server")

@server.tool()
async def batch_query(queries: list[str]) -> list[TextContent]:
    """批量查询——只允许 SELECT，自动添加 LIMIT，限制批量大小"""

    if len(queries) > MAX_BATCH_SIZE:
        return [TextContent(type="text", text=json.dumps({
            "error": f"批量大小超限：最多 {MAX_BATCH_SIZE} 条，当前 {len(queries)} 条"
        }))]

    results = []
    for i, sql in enumerate(queries):
        normalized = sql.strip().upper()
        if not normalized.startswith("SELECT"):
            results.append({"index": i, "error": "只允许 SELECT 查询", "sql": sql})
            continue

        if "LIMIT" not in normalized:
            sql = f"{sql.rstrip(';')} LIMIT {MAX_LIMIT}"

        try:
            result = await execute_sql(sql)
            results.append({"index": i, "data": result})
        except Exception as e:
            results.append({"index": i, "error": str(e), "sql": sql})

    return [TextContent(type="text", text=json.dumps(results, ensure_ascii=False))]

async def execute_sql(sql: str) -> list[dict]:
    return [{"id": 1, "name": "Alice"}, {"id": 2, "name": "Bob"}]
```

**要点**：
- 批量大小必须有上限（如 50 条），无限制的批量操作可能耗尽内存或超时
- 每条 SQL 自动添加 LIMIT 是防御性措施，防止一条 `SELECT *` 返回百万行拖慢整个批量操作
- 常见错误：把批量查询做成循环调用单条 SQL，失去了批量的意义；真正的批量应该在数据库层用连接池复用连接

### 练习二：并行批量处理

**思路**：并行批量用 `asyncio.gather` 同时执行多个操作，适合 IO 密集型任务。但要考虑：数据库连接池大小（并行数不能超过连接数）、异常处理（一条失败不应影响其他条）、结果顺序（gather 保持顺序）。

**答案**：
```python
import asyncio
import json
from mcp.server import Server
from mcp.types import TextContent

MAX_CONCURRENT = 10

server = Server("parallel-batch-server")

@server.tool()
async def parallel_batch_insert(table: str, records: list[dict]) -> list[TextContent]:
    """并行批量插入——用信号量控制并发数"""

    semaphore = asyncio.Semaphore(MAX_CONCURRENT)

    async def insert_one(index: int, record: dict) -> dict:
        async with semaphore:
            try:
                result = await do_insert(table, record)
                return {"index": index, "status": "success", "result": result}
            except Exception as e:
                return {"index": index, "status": "error", "error": str(e)}

    tasks = [insert_one(i, record) for i, record in enumerate(records)]
    results = await asyncio.gather(*tasks)

    success_count = sum(1 for r in results if r["status"] == "success")
    error_count = sum(1 for r in results if r["status"] == "error")
    errors = [r for r in results if r["status"] == "error"]

    return [TextContent(type="text", text=json.dumps({
        "total": len(records),
        "success": success_count,
        "failed": error_count,
        "errors": errors
    }, ensure_ascii=False))]

async def do_insert(table: str, record: dict) -> str:
    await asyncio.sleep(0.01)
    return f"inserted into {table}"
```

**要点**：
- 必须用信号量（Semaphore）控制并发数，否则 500 条记录同时请求数据库会耗尽连接池
- `asyncio.gather` 保持结果顺序与输入一致，不需要额外维护索引映射
- 常见错误：直接 `gather` 所有任务不设并发限制，在大批量场景下会压垮下游服务

### 练习三：批量操作中的部分失败

**思路**：部分失败的处理策略取决于业务场景：金融操作用事务全部回滚，数据导入可以部分成功。关键是返回详细的执行报告——成功数、失败数、每条失败的原因和索引——让 AI 能精确告诉用户哪些数据有问题。

**答案**：
```python
import json
from mcp.server import Server
from mcp.types import TextContent

server = Server("partial-fail-server")

@server.tool()
async def safe_batch_insert(table: str, records: list[dict]) -> list[TextContent]:
    """安全批量插入——逐条插入，记录部分失败"""

    success_count = 0
    errors = []
    inserted_ids = []

    for i, record in enumerate(records):
        try:
            record_id = await insert_record(table, record)
            success_count += 1
            inserted_ids.append(record_id)
        except DuplicateKeyError as e:
            errors.append({"index": i, "error": "重复键", "key": str(e.key), "record": record})
        except ValidationError as e:
            errors.append({"index": i, "error": f"校验失败：{e.message}", "record": record})
        except Exception as e:
            errors.append({"index": i, "error": str(e), "record": record})

    return [TextContent(type="text", text=json.dumps({
        "status": "completed",
        "total": len(records),
        "success": success_count,
        "failed": len(errors),
        "errors": errors,
        "inserted_ids": inserted_ids[:10]
    }, ensure_ascii=False))]

class DuplicateKeyError(Exception):
    def __init__(self, key):
        self.key = key
        super().__init__(f"重复键：{key}")

class ValidationError(Exception):
    def __init__(self, message):
        self.message = message
        super().__init__(message)

async def insert_record(table: str, record: dict) -> str:
    if not record.get("name"):
        raise ValidationError("缺少 name 字段")
    if record.get("name") == "duplicate":
        raise DuplicateKeyError(record["name"])
    return f"id_{hash(record['name']) % 10000}"
```

**要点**：
- 区分不同类型的错误（重复键、校验失败、网络异常），给出针对性的错误信息，让 AI 能指导用户修正数据
- 返回结果中必须包含失败记录的索引，让用户知道是第几条数据出了问题
- 常见错误：捕获异常后直接 `raise` 终止整个批量操作，导致已成功插入的数据无法回滚、未处理的数据被丢弃；应该记录错误继续处理剩余数据
