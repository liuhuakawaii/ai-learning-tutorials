# 03 嵌套调用——Tool 内部调用其他 Tool 的编排模式

> 有时候一个 Tool 需要调用其他 Tool 来完成复杂任务。

## 场景引入

用户对 AI 说"帮我查一下北京的天气，然后把结果发到 Slack 的 #weather 频道"。这需要两个步骤：调用天气 Tool 查询，再调用 Slack Tool 发送消息。如果让 AI 来编排这两个步骤，它需要先等天气结果返回，再构造 Slack 消息，中间还可能出错。你希望有一个"复合 Tool"能直接完成这个链式操作，内部自动调用其他 Tool。

---

## 学习目标

- 掌握 Tool 嵌套调用的方法
- 理解 Tool 间的协作模式
- 学会设计可组合的 Tool

---

## 一、嵌套调用概念

```
嵌套调用场景：

1. 复合操作
   - 一个操作需要多个步骤
   - 每个步骤可能是一个独立的 Tool

2. 数据转换
   - 获取数据 → 转换数据 → 存储数据
   - 每个步骤是一个 Tool

3. 编排模式
   - 顺序执行
   - 并行执行
   - 条件分支
```

## 二、实现

```python
from mcp.server import Server
from mcp.types import TextContent

server = Server("my-server")

@server.tool()
async def query_and_format(sql: str, format: str = "json") -> list[TextContent]:
    """查询并格式化"""
    
    # 调用查询 Tool
    query_result = await execute_query(sql)
    
    # 调用格式化 Tool
    formatted = await format_data(query_result, format)
    
    return [TextContent(type="text", text=formatted)]

@server.tool()
async def multi_step_operation(data: str) -> list[TextContent]:
    """多步骤操作"""
    
    # 步骤 1：验证
    validation = await validate_data(data)
    if not validation["valid"]:
        return [TextContent(type="text", text=f"验证失败：{validation['errors']}")]
    
    # 步骤 2：处理
    processed = await process_data(data)
    
    # 步骤 3：存储
    stored = await store_data(processed)
    
    return [TextContent(type="text", text=f"处理完成：{stored}")]
```

## 三、Tool 组合

```python
class ToolChain:
    """Tool 链"""
    
    def __init__(self):
        self.steps = []
    
    def add_step(self, tool_name: str, params: dict):
        """添加步骤"""
        self.steps.append({"tool": tool_name, "params": params})
    
    async def execute(self, server) -> list:
        """执行链"""
        results = []
        current_data = None
        
        for step in self.steps:
            # 调用 Tool
            result = await server.call_tool(step["tool"], step["params"])
            current_data = result
            results.append(result)
        
        return results
```

## 四、错误传播

```python
@server.tool()
async def resilient_chain(data: str) -> list[TextContent]:
    """带错误处理的链式调用"""
    
    try:
        # 步骤 1
        step1 = await step_one(data)
        
        # 步骤 2
        step2 = await step_two(step1)
        
        # 步骤 3
        step3 = await step_three(step2)
        
        return [TextContent(type="text", text=step3)]
    
    except Exception as e:
        # 返回部分结果或错误信息
        return [TextContent(type="text", text=f"处理失败：{str(e)}")]
```

## 常见误区

```
误区 1：嵌套调用就是递归调用自己
  嵌套调用是 Tool A 调用 Tool B，不是 Tool A 调用自己。
  递归调用没有终止条件会导致无限循环。

误区 2：嵌套调用的错误不需要特殊处理
  嵌套调用中任何一步失败，都需要决定是继续执行还是回滚。
  不处理错误会导致数据不一致。

误区 3：所有复合操作都应该做成嵌套调用
  如果复合操作的步骤是固定的，直接在一个 Tool 里实现更简单。
  嵌套调用适用于步骤可变、需要动态组合的场景。

误区 4：嵌套调用的权限和外层调用一样
  嵌套调用可能跨越不同的权限域。查询天气是公开操作，发送 Slack 消息需要写权限。
  每一层调用都要独立校验权限。
```

---

## 工程建议

```
1. 用 ToolChain 模式组织步骤
  把复合操作的步骤抽象为链，每个步骤是一个 Tool 调用。
  链支持顺序执行、条件分支、错误回滚。

2. 中间结果要类型安全
  Tool A 的输出是 Tool B 的输入。用类型系统确保数据格式兼容。
  不要依赖 JSON 字符串传递结构化数据。

3. 设置嵌套深度限制
  防止 A 调用 B、B 调用 C、C 又调用 A 的循环依赖。
  设置最大嵌套深度（如 5 层），超过直接报错。

4. 复合 Tool 的 description 要说明步骤
  "查询天气并发送到 Slack"比"天气 Slack"清晰得多。
  让 AI 知道这个 Tool 内部做了什么，避免重复调用子 Tool。
```

## 小结

1. 嵌套调用支持 Tool 间协作
2. 适用于复合操作、数据转换、编排场景
3. Tool 链实现顺序执行
4. 错误传播要妥善处理

## 参考答案

### 练习一：嵌套调用的 Tool

**思路**：嵌套调用的核心是一个复合 Tool 内部调用其他 Tool 完成链式操作。关键是中间结果要类型安全地传递，每一步失败时要有明确的错误处理策略（继续还是终止）。嵌套调用不是递归调用自己，而是 Tool A 调用 Tool B。

**答案**：
```python
import json
from mcp.server import Server
from mcp.types import TextContent

server = Server("nested-server")

@server.tool()
async def query_weather(city: str) -> list[TextContent]:
    """查询天气"""
    weather_data = {"北京": "晴天 25°C", "上海": "多云 28°C", "广州": "阵雨 32°C"}
    result = weather_data.get(city, f"未找到 {city} 的天气数据")
    return [TextContent(type="text", text=json.dumps({"city": city, "weather": result}, ensure_ascii=False))]

@server.tool()
async def send_slack_message(channel: str, message: str) -> list[TextContent]:
    """发送 Slack 消息"""
    return [TextContent(type="text", text=json.dumps({
        "status": "sent",
        "channel": channel,
        "message": message
    }, ensure_ascii=False))]

@server.tool()
async def weather_to_slack(city: str, channel: str) -> list[TextContent]:
    """查询天气并发送到 Slack——嵌套调用示例"""

    weather_result = await call_tool_on_self("query_weather", {"city": city})
    weather_data = json.loads(weather_result[0].text)

    if "error" in weather_data:
        return [TextContent(type="text", text=f"天气查询失败：{weather_data['error']}")]

    message = f"{city}天气：{weather_data['weather']}"
    slack_result = await call_tool_on_self("send_slack_message", {"channel": channel, "message": message})
    slack_data = json.loads(slack_result[0].text)

    return [TextContent(type="text", text=json.dumps({
        "weather": weather_data,
        "slack": slack_data,
        "status": "完成"
    }, ensure_ascii=False))]

async def call_tool_on_self(name: str, arguments: dict) -> list[TextContent]:
    tool_func = _tool_registry.get(name)
    if not tool_func:
        raise ValueError(f"工具 {name} 不存在")
    return await tool_func(**arguments)

_tool_registry = {
    "query_weather": query_weather,
    "send_slack_message": send_slack_message,
}
```

**要点**：
- 嵌套调用是 Tool A 调用 Tool B，不是递归调用自己；递归没有终止条件会导致无限循环
- 中间结果用结构化数据（dict）传递，不要用 JSON 字符串拼接，否则解析容易出错
- 常见错误：嵌套调用时直接调用函数而非通过 Tool 接口调用，绕过了权限校验和日志记录

### 练习二：Tool 链

**思路**：Tool 链把复合操作抽象为一系列步骤，每个步骤是一个 Tool 调用。链支持顺序执行，前一步的输出作为后一步的输入。关键是设计通用的 `execute` 方法，支持动态添加步骤和错误回滚。

**答案**：
```python
import json
from mcp.server import Server
from mcp.types import TextContent

class ToolChain:
    def __init__(self):
        self.steps: list[dict] = []
        self.results: list = []

    def add_step(self, tool_name: str, params_factory: callable = None):
        """添加步骤，params_factory 接收上一步结果返回本步参数"""
        self.steps.append({"tool": tool_name, "params_factory": params_factory})

    async def execute(self, tool_executor: callable) -> list:
        self.results = []
        current_data = None

        for i, step in enumerate(self.steps):
            if step["params_factory"]:
                params = step["params_factory"](current_data)
            else:
                params = {}

            try:
                result = await tool_executor(step["tool"], params)
                current_data = result
                self.results.append({"step": i, "tool": step["tool"], "result": result})
            except Exception as e:
                self.results.append({"step": i, "tool": step["tool"], "error": str(e)})
                raise

        return self.results

server = Server("chain-server")

@server.tool()
async def data_pipeline(source_query: str, output_format: str = "json") -> list[TextContent]:
    """数据管道——查询 → 清洗 → 格式化"""

    chain = ToolChain()

    chain.add_step("query_data", lambda _: {"sql": source_query})
    chain.add_step("clean_data", lambda prev: {"data": prev["result"]})
    chain.add_step("format_output", lambda prev: {"data": prev["result"], "format": output_format})

    async def tool_executor(name: str, params: dict):
        if name == "query_data":
            return [{"id": 1, "name": "Alice"}, {"id": 2, "name": "Bob"}]
        elif name == "clean_data":
            return [row for row in params["data"] if row.get("name")]
        elif name == "format_output":
            if params.get("format") == "csv":
                return "id,name\n1,Alice\n2,Bob"
            return json.dumps(params["data"], ensure_ascii=False)

    results = await chain.execute(tool_executor)
    final = results[-1]["result"]
    return [TextContent(type="text", text=str(final))]
```

**要点**：
- `params_factory` 是链式调用的关键，它让每一步能根据上一步的输出动态构造参数，实现数据流转
- 链执行失败时应保留已执行步骤的结果，便于调试和部分回滚
- 常见错误：把所有步骤的参数在创建链时就固定死，导致步骤间无法传递数据，失去了链式调用的意义

### 练习三：嵌套调用中的错误传播

**思路**：嵌套调用中任何一步失败都需要决定策略：立即终止并返回错误、跳过失败步骤继续执行、或回滚已完成的步骤。关键是根据业务场景选择合适的策略，并在错误信息中说明失败发生在哪一步。

**答案**：
```python
import json
from mcp.server import Server
from mcp.types import TextContent

class ChainError(Exception):
    def __init__(self, step: int, tool_name: str, message: str):
        self.step = step
        self.tool_name = tool_name
        super().__init__(f"步骤 {step}（{tool_name}）失败：{message}")

class ErrorStrategy:
    ABORT = "abort"
    SKIP = "skip"
    ROLLBACK = "rollback"

server = Server("error-chain-server")

@server.tool()
async def resilient_pipeline(
    records: list[dict],
    error_strategy: str = "skip"
) -> list[TextContent]:
    """带错误处理的数据处理管道"""

    success_records = []
    error_records = []
    processed_data = []

    for i, record in enumerate(records):
        try:
            validated = await validate_record(record)
            transformed = await transform_record(validated)
            stored = await store_record(transformed)
            processed_data.append(stored)
            success_records.append(i)
        except Exception as e:
            error_records.append({"index": i, "error": str(e), "record": record})

            if error_strategy == ErrorStrategy.ABORT:
                return [TextContent(type="text", text=json.dumps({
                    "status": "aborted",
                    "failed_at": i,
                    "error": str(e),
                    "processed_count": len(success_records)
                }, ensure_ascii=False))]

    return [TextContent(type="text", text=json.dumps({
        "status": "completed",
        "success_count": len(success_records),
        "error_count": len(error_records),
        "errors": error_records,
        "results": processed_data[:5]
    }, ensure_ascii=False))]

async def validate_record(record: dict) -> dict:
    if not record.get("name"):
        raise ValueError("缺少 name 字段")
    return record

async def transform_record(record: dict) -> dict:
    return {"name": record["name"].strip().upper(), "source": "pipeline"}

async def store_record(record: dict) -> dict:
    return {**record, "stored": True, "id": hash(record["name"]) % 10000}
```

**要点**：
- 错误策略必须在 Tool 的 description 中明确说明，让 AI 知道这个 Tool 是全部回滚还是部分成功
- 错误信息要包含失败步骤的索引和原因，让 AI 能精确告诉用户哪条数据出了问题
- 常见错误：捕获异常后只返回"处理失败"，不说明哪一步失败、为什么失败，导致用户无法定位问题
