# 03 安全模型——认证（OAuth 2.1）、授权、速率限制、输入校验

> MCP Server 暴露的是真实系统能力，安全设计不能跳过。

## 场景引入

你的 MCP Server 能执行 SQL 查询、读写文件、调用内部 API——这些都是真实系统的能力。如果任何人都能不经认证直接调用，等于把数据库和文件系统完全暴露了。你需要一套完整的安全体系：谁可以连接（认证）、可以用哪些工具（授权）、每分钟能调多少次（限流）、传入的参数是否合法（校验）。这不是可选的增强功能，是上线的前提条件。

## 一、认证

```python
from mcp.server import Server
from mcp.types import TextContent

class AuthMiddleware:
    """认证中间件"""
    
    def __init__(self, secret_key: str):
        self.secret_key = secret_key
    
    def verify_token(self, token: str) -> dict:
        """验证 Token"""
        try:
            payload = jwt.decode(token, self.secret_key, algorithms=["HS256"])
            return payload
        except jwt.InvalidTokenError:
            raise AuthenticationError("无效的 Token")

class SecureServer:
    """安全 Server"""
    
    def __init__(self):
        self.server = Server("secure-server")
        self.auth = AuthMiddleware("secret-key")
    
    def _verify_auth(self, request: dict) -> dict:
        """验证认证"""
        token = request.get("params", {}).get("_auth", {}).get("token")
        if not token:
            raise AuthenticationError("缺少认证 Token")
        return self.auth.verify_token(token)
```

## 三、速率限制

```python
class RateLimiter:
    """限流器"""
    
    def __init__(self, max_requests: int, time_window: int):
        self.max_requests = max_requests
        self.time_window = time_window
        self.requests = {}
    
    def check(self, user_id: str) -> bool:
        """检查是否超限"""
        now = time.time()
        user_requests = self.requests.get(user_id, [])
        
        # 清理过期请求
        user_requests = [r for r in user_requests if r > now - self.time_window]
        
        if len(user_requests) >= self.max_requests:
            return False
        
        user_requests.append(now)
        self.requests[user_id] = user_requests
        return True
```

## 四、输入校验

```python
from pydantic import BaseModel, validator

class SecureInput(BaseModel):
    """安全输入"""
    sql: str
    
    @validator("sql")
    def validate_sql(cls, v):
        """校验 SQL"""
        # 禁止危险操作
        dangerous_keywords = ["DROP", "DELETE", "TRUNCATE", "ALTER"]
        for keyword in dangerous_keywords:
            if keyword in v.upper():
                raise ValueError(f"禁止执行 {keyword} 操作")
        return v
```

## 五、安全最佳实践

```
安全最佳实践：

1. 认证
   - 使用 OAuth 2.1 或 API Key
   - Token 有过期时间
   - 支持 Token 刷新

2. 授权
   - 最小权限原则
   - 细粒度权限控制
   - 定期审查权限

3. 限流
   - 按用户限流
   - 按工具限流
   - 防止滥用

4. 输入校验
   - 验证所有输入
   - 防止注入攻击
   - 限制输入长度

5. 审计
   - 记录所有操作
   - 记录失败尝试
   - 支持追溯
```

## 常见误区

```
误区 1：MCP 是内部协议，不需要认证
  即使是内部系统，也需要认证。内部攻击、误配置、网络穿透都可能导致安全问题。
  认证是所有安全措施的基础。

误区 2：认证就是校验 API Key
  API Key 是最简单的认证方式，但不支持过期、刷新、细粒度权限。
  生产环境应该用 OAuth 2.1 或 JWT，支持 Token 过期和权限声明。

误区 3：限流会影响正常用户
  合理的限流策略不会影响正常用户。按用户、按 Tool、按时间窗口分别设置。
  正常用户的使用量远低于限流阈值。

误区 4：输入校验只在 Client 端做
  Client 端校验可以提升用户体验，但 Server 端必须独立校验。
  用户可能绕过 Client 直接发送 JSON-RPC 请求。
```

---

## 工程建议

```
1. 认证在 Host 层，授权在 Server 层
  Host 负责用户认证（验证身份），Server 负责权限校验（验证权限）。
  不要在每个 Tool 内部做认证，那是 Host 的职责。

2. 最小权限原则
  默认拒绝所有操作，只开放必要的权限。
  定期审查权限配置，移除不再需要的权限。

3. 审计日志要包含完整上下文
  记录：时间、用户、工具、参数、结果、耗时、来源 IP。
  审计日志是安全事件追溯的唯一依据。

4. SQL 注入防护必须在 Server 端
  用参数化查询（$1, $2）而不是字符串拼接。
  即使 Client 做了校验，Server 也要独立防护。
```

## 参考答案

### 练习一：Token 认证

**思路**：Token 认证的核心是：Host 层负责用户登录和 Token 签发，Server 层只负责验证 Token 的有效性。使用 JWT 可以在 Token 中嵌入用户信息（user_id、roles），避免每次请求都查数据库。关键是 Token 必须有过期时间，支持刷新机制。

**答案**：
```python
import json
import time
import hashlib
import hmac
import base64

class JWTManager:
    def __init__(self, secret_key: str, expire_seconds: int = 3600):
        self.secret_key = secret_key
        self.expire_seconds = expire_seconds

    def create_token(self, payload: dict) -> str:
        header = {"alg": "HS256", "typ": "JWT"}
        payload_with_exp = {**payload, "exp": int(time.time()) + self.expire_seconds, "iat": int(time.time())}

        header_b64 = base64.urlsafe_b64encode(json.dumps(header).encode()).decode().rstrip("=")
        payload_b64 = base64.urlsafe_b64encode(json.dumps(payload_with_exp).encode()).decode().rstrip("=")
        message = f"{header_b64}.{payload_b64}"
        signature = hmac.new(self.secret_key.encode(), message.encode(), hashlib.sha256).digest()
        sig_b64 = base64.urlsafe_b64encode(signature).decode().rstrip("=")
        return f"{message}.{sig_b64}"

    def verify_token(self, token: str) -> dict:
        parts = token.split(".")
        if len(parts) != 3:
            raise AuthenticationError("Token 格式无效")

        header_b64, payload_b64, sig_b64 = parts
        message = f"{header_b64}.{payload_b64}"
        expected_sig = hmac.new(self.secret_key.encode(), message.encode(), hashlib.sha256).digest()
        expected_b64 = base64.urlsafe_b64encode(expected_sig).decode().rstrip("=")

        if not hmac.compare_digest(sig_b64, expected_b64):
            raise AuthenticationError("Token 签名无效")

        padding = 4 - len(payload_b64) % 4
        payload_b64 += "=" * padding
        payload = json.loads(base64.urlsafe_b64decode(payload_b64))

        if payload.get("exp", 0) < time.time():
            raise AuthenticationError("Token 已过期")

        return payload

class AuthenticationError(Exception):
    pass

jwt_mgr = JWTManager("my-secret-key")

token = jwt_mgr.create_token({"user_id": "u123", "role": "admin"})
print(f"Token: {token}")

user = jwt_mgr.verify_token(token)
print(f"用户: {user}")
```

**要点**：
- JWT 签名用 HMAC-SHA256，验证时必须用 `hmac.compare_digest` 防止时序攻击
- Token 过期时间不宜过长（建议 1 小时），配合 refresh token 机制实现长期登录
- 常见错误：把密钥硬编码在代码中，应该从环境变量或配置中心读取

### 练习二：权限检查

**思路**：权限检查的核心是维护"用户→权限集合"的映射，每次工具调用前检查用户是否拥有所需权限。采用最小权限原则：默认拒绝，只开放必要权限。权限可以用 RBAC（角色→权限）简化管理。

**答案**：
```python
import json
from mcp.server import Server
from mcp.types import TextContent

class AuthorizationManager:
    def __init__(self):
        self.user_permissions: dict[str, set] = {}
        self.role_permissions: dict[str, set] = {}
        self.user_roles: dict[str, set] = {}

    def define_role(self, role: str, permissions: list[str]):
        self.role_permissions[role] = set(permissions)

    def assign_role(self, user_id: str, role: str):
        if user_id not in self.user_roles:
            self.user_roles[user_id] = set()
        self.user_roles[user_id].add(role)

    def grant_permission(self, user_id: str, permission: str):
        if user_id not in self.user_permissions:
            self.user_permissions[user_id] = set()
        self.user_permissions[user_id].add(permission)

    def get_user_permissions(self, user_id: str) -> set[str]:
        perms = set(self.user_permissions.get(user_id, set()))
        for role in self.user_roles.get(user_id, set()):
            perms.update(self.role_permissions.get(role, set()))
        return perms

    def check_permission(self, user_id: str, required_permission: str) -> bool:
        user_perms = self.get_user_permissions(user_id)
        return required_permission in user_perms

    def check_any_permission(self, user_id: str, permissions: list[str]) -> bool:
        user_perms = self.get_user_permissions(user_id)
        return any(p in user_perms for p in permissions)

auth_mgr = AuthorizationManager()

auth_mgr.define_role("viewer", ["read:data", "read:files"])
auth_mgr.define_role("editor", ["read:data", "read:files", "write:data"])
auth_mgr.define_role("admin", ["read:data", "read:files", "write:data", "delete:data", "manage:users"])

auth_mgr.assign_role("user_001", "viewer")
auth_mgr.assign_role("user_002", "admin")
auth_mgr.grant_permission("user_001", "write:own_data")

print(f"user_001 权限：{auth_mgr.get_user_permissions('user_001')}")
print(f"user_001 能否写数据：{auth_mgr.check_permission('user_001', 'write:data')}")
print(f"user_001 能否写自己的数据：{auth_mgr.check_permission('user_001', 'write:own_data')}")
print(f"user_002 能否删除数据：{auth_mgr.check_permission('user_002', 'delete:data')}")
```

**要点**：
- 权限检查必须在 Server 端执行，不能只依赖 Client 端的 UI 隐藏按钮
- 用 RBAC 管理权限，不要直接给用户分配权限——角色比权限更容易管理
- 常见错误：把所有权限硬编码在 if-else 中，新增权限时需要修改核心代码；应该用配置化的权限系统

### 练习三：速率限制

**思路**：速率限制的核心是滑动窗口算法——记录每个用户在最近 N 秒内的请求次数，超过阈值则拒绝。关键参数：最大请求数、时间窗口大小。实现时要注意：清理过期记录避免内存泄漏、按用户和按 Tool 分别限流。

**答案**：
```python
import time
import json
from collections import defaultdict
from mcp.server import Server
from mcp.types import TextContent

class SlidingWindowRateLimiter:
    def __init__(self, max_requests: int, window_seconds: int):
        self.max_requests = max_requests
        self.window_seconds = window_seconds
        self.user_requests: dict[str, list[float]] = defaultdict(list)
        self.tool_limits: dict[str, tuple[int, int]] = {}

    def set_tool_limit(self, tool_name: str, max_requests: int, window_seconds: int):
        self.tool_limits[tool_name] = (max_requests, window_seconds)

    def check(self, user_id: str, tool_name: str = None) -> tuple[bool, dict]:
        now = time.time()

        if tool_name and tool_name in self.tool_limits:
            limit, window = self.tool_limits[tool_name]
            key = f"{user_id}:{tool_name}"
        else:
            limit, window = self.max_requests, self.window_seconds
            key = user_id

        requests = self.user_requests[key]
        self.user_requests[key] = [r for r in requests if r > now - window]

        remaining = limit - len(self.user_requests[key])
        if remaining <= 0:
            retry_after = self.user_requests[key][0] + window - now
            return False, {
                "limit": limit,
                "remaining": 0,
                "retry_after": round(retry_after, 1)
            }

        self.user_requests[key].append(now)
        return True, {"limit": limit, "remaining": remaining - 1}

    def cleanup(self):
        now = time.time()
        expired_keys = []
        for key, requests in self.user_requests.items():
            self.user_requests[key] = [r for r in requests if r > now - self.window_seconds * 2]
            if not self.user_requests[key]:
                expired_keys.append(key)
        for key in expired_keys:
            del self.user_requests[key]

limiter = SlidingWindowRateLimiter(max_requests=60, window_seconds=60)
limiter.set_tool_limit("execute_sql", max_requests=10, window_seconds=60)
limiter.set_tool_limit("write_file", max_requests=5, window_seconds=60)

server = Server("rate-limited-server")

@server.tool()
async def execute_sql(sql: str, user_id: str = "anonymous") -> list[TextContent]:
    allowed, info = limiter.check(user_id, "execute_sql")
    if not allowed:
        return [TextContent(type="text", text=json.dumps({
            "error": "请求过于频繁",
            "retry_after": info["retry_after"],
            "message": f"请在 {info['retry_after']} 秒后重试"
        }))]
    return [TextContent(type="text", text=f"查询结果：{sql}")]
```

**要点**：
- 滑动窗口比固定窗口更平滑——固定窗口在窗口边界可能允许 2 倍的突发流量
- 必须按 Tool 分别限流，敏感操作（如 SQL 执行、文件写入）应该有更严格的限制
- 常见错误：只在内存中记录请求时间不清理，长时间运行后内存持续增长；需要定期清理过期记录
