> MCP 生态正在快速发展。学会使用和贡献开源 MCP Server。

你为公司开发了几个 MCP Server，但发现社区已经有现成的——GitHub Server、Slack Server、PostgreSQL Server 都有人做过了。直接用社区的版本省时省力，但你不确定哪些 Server 质量可靠、怎么评估安全性、怎么为社区贡献自己的 Server。MCP 生态的现状是什么？怎么参与其中？

# 使用
npx @modelcontextprotocol/server-filesystem /path/to/directory
```

```python
# Python 使用
from mcp import MCPClient
from mcp.transport.stdio import StdioServerTransport

# 连接到文件系统 Server
transport = StdioServerTransport("npx", ["@modelcontextprotocol/server-filesystem", "/tmp"])
client = MCPClient(transport)
await client.initialize()

# 使用工具
tools = await client.list_tools()
result = await client.call_tool("read_file", {"path": "/tmp/test.txt"})

## 五、最佳实践

```
开源 MCP Server 最佳实践：

1. 文档

   - 使用示例
   - API 文档

2. 测试
   - 单元测试
   - 集成测试

   - 语义化版本

## 常见误区

```
误区 1：开源 Server 可以直接用于生产
  开源 Server 需要经过安全审计、性能测试、兼容性验证才能用于生产。
  直接 npm install 就上线是不负责任的。

误区 2：社区 Server 都是官方维护的
  官方 Server（@modelcontextprotocol/server-*）和社区 Server 质量差异很大。
  使用前要检查维护状态、issue 处理速度、最近更新时间。

误区 3：贡献 Server 就是把代码推到 GitHub
  贡献还包括：清晰的 README、使用示例、API 文档、测试用例。
  没有文档的 Server 和没有一样。

误区 4：MCP 生态已经成熟
  MCP 生态还在早期阶段，很多 Server 功能不完善、API 可能变化。
  要做好 Server 升级 breaking change 的准备。
```

---

## 工程建议

```
1. 优先使用官方 Server
  官方 Server 经过严格测试，API 稳定。社区 Server 作为补充。
  使用前检查 GitHub star 数、最近提交时间、issue 数量。

2. Fork 而不是直接依赖
  对于关键业务依赖的社区 Server，fork 到公司仓库。
  避免上游 Server 突然废弃或引入 breaking change。

3. 贡献时遵循社区规范
  遵循 MCP Server 的命名规范、目录结构、文档格式。
  提交 PR 前先开 issue 讨论，避免做无用功。

4. 关注 MCP 协议的演进
  MCP 协议还在快速迭代，新的原语、传输方式、安全机制会不断加入。
  关注官方仓库的 RFC 和 changelog。
```

## 参考答案

### 练习一：使用一个开源 MCP Server

**思路**：使用开源 MCP Server 的流程是：安装包 → 配置连接参数 → 通过 Client 调用工具。关键是验证 Server 的可靠性：检查 GitHub star 数、最近提交时间、issue 处理速度。不要直接用于生产，先在隔离环境中测试。

**答案**：
```python
import asyncio
import json

async def use_filesystem_server():
    import subprocess

    process = await asyncio.create_subprocess_exec(
        "npx", "@modelcontextprotocol/server-filesystem", "/tmp/sandbox",
        stdin=asyncio.subprocess.PIPE,
        stdout=asyncio.subprocess.PIPE,
        stderr=asyncio.subprocess.PIPE
    )

    async def send_request(method: str, params: dict = None) -> dict:
        request = {"jsonrpc": "2.0", "id": 1, "method": method}
        if params:
            request["params"] = params
        message = json.dumps(request) + "\n"
        process.stdin.write(message.encode())
        await process.stdin.drain()
        line = await process.stdout.readline()
        return json.loads(line)

    init_result = await send_request("initialize", {
        "protocolVersion": "2024-11-05",
        "capabilities": {"tools": {}},
        "clientInfo": {"name": "demo-client", "version": "1.0.0"}
    })
    print(f"初始化：{json.dumps(init_result, indent=2)}")

    tools_result = await send_request("tools/list")
    tools = tools_result.get("result", {}).get("tools", [])
    print(f"可用工具：{[t['name'] for t in tools]}")

    write_result = await send_request("tools/call", {
        "name": "write_file",
        "arguments": {"path": "/tmp/sandbox/test.txt", "content": "Hello MCP!"}
    })
    print(f"写入：{json.dumps(write_result, indent=2)}")

    read_result = await send_request("tools/call", {
        "name": "read_file",
        "arguments": {"path": "/tmp/sandbox/test.txt"}
    })
    print(f"读取：{json.dumps(read_result, indent=2)}")

    process.terminate()

asyncio.run(use_filesystem_server())
```

**要点**：
- 使用开源 Server 前必须检查：GitHub 最近提交时间（3 个月内活跃）、issue 数量（未关闭 issue 少于 20）、有无安全审计
- 不要直接 `npm install` 就上线，需要在隔离环境中测试所有工具的功能和边界情况
- 常见错误：盲目信任社区 Server，不审查代码就接入生产环境，可能引入安全漏洞或数据泄漏

### 练习二：创建一个简单的 MCP Server 并发布

**思路**：发布一个 MCP Server 需要：实现 Server 代码、编写 README（安装方式、使用示例、API 文档）、添加测试、设置 pyproject.toml 或 package.json。遵循社区命名规范（Python: `mcp-server-*`，npm: `@modelcontextprotocol/server-*`）。

**答案**：
```python
# weather-mcp-server/server.py
import json
import httpx
from mcp.server import Server
from mcp.types import Tool, TextContent

server = Server("weather-server")

@server.tool()
async def get_weather(city: str) -> list[TextContent]:
    """获取指定城市的当前天气信息"""
    mock_data = {
        "北京": {"temp": 25, "condition": "晴", "humidity": 40},
        "上海": {"temp": 28, "condition": "多云", "humidity": 65},
        "广州": {"temp": 32, "condition": "阵雨", "humidity": 80},
    }
    weather = mock_data.get(city)
    if not weather:
        return [TextContent(type="text", text=json.dumps({"error": f"未找到城市：{city}"}))]
    return [TextContent(type="text", text=json.dumps({
        "city": city, "temperature": f"{weather['temp']}°C",
        "condition": weather["condition"], "humidity": f"{weather['humidity']}%"
    }, ensure_ascii=False))]

@server.tool()
async def get_forecast(city: str, days: int = 3) -> list[TextContent]:
    """获取未来几天的天气预报"""
    forecasts = []
    for i in range(min(days, 7)):
        forecasts.append({"day": i + 1, "city": city, "temp_high": 28 + i, "temp_low": 20 + i, "condition": "晴转多云"})
    return [TextContent(type="text", text=json.dumps({"city": city, "forecast": forecasts}, ensure_ascii=False))]

if __name__ == "__main__":
    import asyncio
    from mcp.server.stdio import stdio_server

    async def main():
        async with stdio_server() as (read_stream, write_stream):
            await server.run(read_stream, write_stream)

    asyncio.run(main())
```

```toml
# weather-mcp-server/pyproject.toml
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project]
name = "mcp-server-weather"
version = "0.1.0"
description = "MCP Server for weather data"
readme = "README.md"
requires-python = ">=3.10"
dependencies = ["mcp>=1.0.0", "httpx>=0.25.0"]

[project.scripts]
mcp-server-weather = "server:main"
```

**要点**：
- Tool 的 description 必须清晰描述功能和参数，让 AI 能正确选择和调用
- 发布前必须有单元测试和集成测试，没有测试的 Server 和没有一样
- 常见错误：Tool description 写得模糊（如"处理数据"），导致 AI 无法判断何时使用该工具

### 练习三：探索 MCP 社区目录

**思路**：MCP 社区资源主要在 GitHub 官方仓库（modelcontextprotocol/servers）和社区目录（mcp.so）。评估一个 Server 的标准：维护状态（最近提交、issue 处理）、文档质量（README、API 文档）、安全性（是否有敏感操作）、兼容性（协议版本）。

**答案**：
```
MCP 社区目录探索指南：

一、官方 Server（推荐优先使用）
   - filesystem：文件系统操作，Node.js 实现，API 稳定
   - github：GitHub API 集成，支持仓库/Issue/PR 管理
   - postgres：PostgreSQL 数据库操作，支持参数化查询
   - sqlite：SQLite 轻量级数据库，适合本地开发
   - slack：Slack 消息和频道管理

二、社区资源入口
   - 官方仓库：github.com/modelcontextprotocol/servers
   - 社区目录：mcp.so
   - npm 搜索：npm search @modelcontextprotocol/server-
   - PyPI 搜索：pip search mcp-server-

三、评估标准
   1. 维护状态
      - 最近提交时间 < 3 个月
      - 未关闭 issue < 20
      - 有持续的版本发布

   2. 文档质量
      - 有清晰的 README
      - 有使用示例代码
      - 有 API 文档

   3. 安全性
      - 不硬编码密钥
      - 有输入校验
      - 支持权限控制

   4. 兼容性
      - 支持最新 MCP 协议版本
      - 有明确的 Python/Node.js 版本要求

四、常见可用 Server
   - mcp-server-fetch：HTTP 请求代理
   - mcp-server-memory：知识图谱存储
   - mcp-server-puppeteer：浏览器自动化
   - mcp-server-brave-search：网络搜索

五、使用建议
   - 关键业务依赖的 Server 应 fork 到公司仓库
   - 定期检查上游更新和安全公告
   - 在隔离环境中测试后再接入生产
```

**要点**：
- 官方 Server 质量最高、API 最稳定，应优先使用；社区 Server 作为补充但需严格评估
- MCP 生态还在早期，很多 Server 的 API 可能有 breaking change，要做好升级兼容准备
- 常见错误：不关注上游更新，Server 废弃或出现安全漏洞时不知道，导致生产环境出问题
