# 03 消息格式详解——JSON-RPC 2.0 在 MCP 中的应用

> MCP 使用 JSON-RPC 2.0 作为消息格式。理解它是开发 MCP Server 的基础。

## 场景引入

你正在用 MCP Inspector 调试自己写的 Server，发现 Inspector 发过来的请求和你代码里解析的格式对不上。你不确定 tools/call 的参数应该放在 params 的哪一层，也不清楚 Server 返回错误时应该用 result 还是 error 字段。更困惑的是，有些消息带 id，有些不带——什么时候该响应，什么时候该忽略？不搞清楚 JSON-RPC 2.0 的消息格式，调试就像猜谜游戏。

## 一、JSON-RPC 2.0 基础

```
JSON-RPC 2.0 消息类型：

1. Request（请求）
   {
     "jsonrpc": "2.0",
     "id": 1,
     "method": "tools/call",
     "params": {...}
   }

2. Response（响应）
   {
     "jsonrpc": "2.0",
     "id": 1,
     "result": {...}
   }

3. Error（错误响应）
   {
     "jsonrpc": "2.0",
     "id": 1,
     "error": {
       "code": -32600,
       "message": "Invalid Request"
     }
   }

4. Notification（通知，无 id）
   {
     "jsonrpc": "2.0",
     "method": "notifications/progress",
     "params": {...}
   }
```

---

## 二、MCP 特定方法

```
MCP 方法：

初始化：
- initialize: 初始化连接

工具：
- tools/list: 获取工具列表
- tools/call: 调用工具

资源：
- resources/list: 获取资源列表
- resources/read: 读取资源
- resources/subscribe: 订阅资源变更

提示：
- prompts/list: 获取提示列表
- prompts/get: 获取提示内容
```

## 三、消息处理

```python
import json

class MCPMessageHandler:
    """MCP 消息处理器"""
    
    def handle_request(self, request: dict) -> dict:
        """处理请求"""
        method = request.get("method")
        params = request.get("params", {})
        request_id = request.get("id")
        
        if method == "tools/list":
            return self._handle_tools_list(request_id)
        elif method == "tools/call":
            return self._handle_tools_call(request_id, params)
        else:
            return self._error_response(request_id, -32601, "Method not found")
    
    def _handle_tools_list(self, request_id: int) -> dict:
        """处理工具列表请求"""
        return {
            "jsonrpc": "2.0",
            "id": request_id,
            "result": {
                "tools": [
                    {
                        "name": "database_query",
                        "description": "执行数据库查询",
                        "inputSchema": {
                            "type": "object",
                            "properties": {
                                "sql": {"type": "string"}
                            }
                        }
                    }
                ]
            }
        }
    
    def _error_response(self, request_id: int, code: int, message: str) -> dict:
        """错误响应"""
        return {
            "jsonrpc": "2.0",
            "id": request_id,
            "error": {
                "code": code,
                "message": message
            }
        }
```

## 四、错误码

```
标准错误码：

-32700: Parse error（解析错误）
-32600: Invalid Request（无效请求）
-32601: Method not found（方法未找到）
-32602: Invalid params（无效参数）
-32603: Internal error（内部错误）

MCP 特定错误码：
-32000: Tool not found
-32001: Tool execution failed
-32002: Resource not found
```

## 常见误区

```
误区 1：Notification 需要返回响应
  Notification 是没有 id 字段的消息，表示"我不需要你回复"。
  收到 Notification 后不应该返回 Response，否则会产生协议违规。

误区 2：错误码可以随便定义
  -32700 到 -32600 是 JSON-RPC 标准保留的错误码，含义固定。
  MCP 特定错误码从 -32000 开始。自定义错误码要在 -32000 以下的范围内选择。

误区 3：tools/call 的参数直接传给 Tool 函数
  tools/call 的 params 里包含 name 和 arguments 两层。
  name 是工具名，arguments 才是传给 Tool 函数的参数，不要搞混层级。

误区 4：所有方法都必须有 params
  params 是可选字段。像 tools/list 这样的方法不需要参数，可以省略 params。
  但如果省略了 id，就会被当作 Notification 处理。
```

## 工程建议

```
1. 用 JSON Schema 验证消息
   在 Server 入口处用 JSON Schema 验证每条消息的结构。
   这能在最早期发现格式问题，而不是等到业务逻辑报错。

2. 错误响应要包含足够的上下文
   error 对象的 message 字段是给开发者看的，要包含足够的排查信息。
   但不要暴露内部实现细节（如数据库连接字符串、文件路径）。

3. id 类型要保持一致
   JSON-RPC 的 id 可以是数字或字符串，但在同一个连接中要保持类型一致。
   建议统一用整数递增 id，方便匹配请求和响应。

4. 先处理未知方法，再扩展新方法
   在消息路由中，对未注册的方法返回 -32601 Method not found。
   这样新增方法时不会影响已有方法的处理逻辑。
```

## 参考答案

### 练习一：构造 tools/call 请求和响应

**思路**：按照 JSON-RPC 2.0 规范构造消息，注意 id 用于匹配请求和响应，params 包含 name 和 arguments 两层。

**答案**：

```json
// 请求：调用 query_database 工具查询用户列表
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "query_database",
    "arguments": {
      "sql": "SELECT id, name, email FROM users WHERE status = 'active' LIMIT 10"
    }
  }
}

// 成功响应
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "content": [
      {
        "type": "text",
        "text": "[{\"id\": 1, \"name\": \"Alice\", \"email\": \"alice@example.com\"}, {\"id\": 2, \"name\": \"Bob\", \"email\": \"bob@example.com\"}]"
      }
    ]
  }
}

// 错误响应：SQL 语法错误
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32001,
    "message": "Tool execution failed: SQL syntax error at position 15"
  }
}

// 错误响应：工具不存在
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32601,
    "message": "Method not found: query_database"
  }
}
```

**要点**：
- 请求 id 和响应 id 必须一致，用于关联请求和响应
- params.name 是工具名，params.arguments 才是传给工具的参数
- 成功用 result，失败用 error，两者互斥
- 常见错误：把参数直接放在 params 顶层，缺少 name/arguments 的嵌套

### 练习二：实现简单的消息处理器

**思路**：用 Python 实现一个 MCPMessageHandler 类，根据 method 字段路由到不同的处理函数，支持 Request 和 Notification 两种消息类型。

**答案**：

```python
import json
from typing import Any


class MCPMessageHandler:
    """MCP 消息处理器"""

    def __init__(self):
        self.request_id_counter = 0
        self._handlers = {}

    def register_handler(self, method: str, handler):
        """注册方法处理器"""
        self._handlers[method] = handler

    def handle_message(self, raw_message: str) -> str | None:
        """处理原始消息字符串，返回响应（Notification 返回 None）"""
        try:
            message = json.loads(raw_message)
        except json.JSONDecodeError:
            return json.dumps({
                "jsonrpc": "2.0",
                "id": None,
                "error": {"code": -32700, "message": "Parse error"}
            })

        # 判断是 Request 还是 Notification
        has_id = "id" in message
        method = message.get("method")
        params = message.get("params", {})

        if not method:
            return json.dumps({
                "jsonrpc": "2.0",
                "id": message.get("id"),
                "error": {"code": -32600, "message": "Invalid Request: missing method"}
            })

        # 路由到对应的处理器
        handler = self._handlers.get(method)
        if not handler:
            if has_id:
                return json.dumps({
                    "jsonrpc": "2.0",
                    "id": message["id"],
                    "error": {"code": -32601, "message": f"Method not found: {method}"}
                })
            return None  # Notification 不需要响应

        try:
            result = handler(params)
            if has_id:
                return json.dumps({
                    "jsonrpc": "2.0",
                    "id": message["id"],
                    "result": result
                })
            return None  # Notification 不返回响应
        except Exception as e:
            if has_id:
                return json.dumps({
                    "jsonrpc": "2.0",
                    "id": message["id"],
                    "error": {"code": -32603, "message": f"Internal error: {str(e)}"}
                })
            return None


# 使用示例
handler = MCPMessageHandler()

# 注册 tools/list 处理器
def handle_tools_list(params):
    return {
        "tools": [
            {
                "name": "query_database",
                "description": "执行只读 SQL 查询",
                "inputSchema": {
                    "type": "object",
                    "properties": {"sql": {"type": "string"}},
                    "required": ["sql"]
                }
            }
        ]
    }

# 注册 tools/call 处理器
def handle_tools_call(params):
    tool_name = params.get("name")
    arguments = params.get("arguments", {})
    if tool_name == "query_database":
        sql = arguments.get("sql", "")
        return {"content": [{"type": "text", "text": f"Query result for: {sql}"}]}
    raise ValueError(f"Tool not found: {tool_name}")

handler.register_handler("tools/list", handle_tools_list)
handler.register_handler("tools/call", handle_tools_call)

# 测试
request = json.dumps({"jsonrpc": "2.0", "id": 1, "method": "tools/list"})
print(handler.handle_message(request))
# {"jsonrpc": "2.0", "id": 1, "result": {"tools": [...]}}

notification = json.dumps({"jsonrpc": "2.0", "method": "notifications/progress", "params": {"progress": 50}})
print(handler.handle_message(notification))
# None（Notification 不需要响应）
```

**要点**：
- 有 id 的是 Request，必须返回 Response；没有 id 的是 Notification，不返回
- 未注册的方法返回 -32601 Method not found
- 处理器内部异常返回 -32603 Internal error
- 常见错误：对 Notification 也返回响应，导致协议违规

### 练习三：实现错误处理和错误码映射

**思路**：建立统一的错误类体系，将业务异常映射到 JSON-RPC 错误码，在消息处理器入口处统一捕获和转换。

**答案**：

```python
from enum import IntEnum
from typing import Any


class MCPErrorCode(IntEnum):
    """MCP 错误码定义"""
    # JSON-RPC 标准错误码
    PARSE_ERROR = -32700
    INVALID_REQUEST = -32600
    METHOD_NOT_FOUND = -32601
    INVALID_PARAMS = -32602
    INTERNAL_ERROR = -32603

    # MCP 特定错误码
    TOOL_NOT_FOUND = -32000
    TOOL_EXECUTION_FAILED = -32001
    RESOURCE_NOT_FOUND = -32002
    RESOURCE_ACCESS_DENIED = -32003


class MCPError(Exception):
    """MCP 错误基类"""
    def __init__(self, code: int, message: str, data: Any = None):
        self.code = code
        self.message = message
        self.data = data
        super().__init__(message)

    def to_response(self, request_id: int | None) -> dict:
        error = {"code": self.code, "message": self.message}
        if self.data:
            error["data"] = self.data
        return {"jsonrpc": "2.0", "id": request_id, "error": error}


class ParseError(MCPError):
    def __init__(self, detail: str = ""):
        super().__init__(MCPErrorCode.PARSE_ERROR, f"Parse error: {detail}")


class InvalidRequestError(MCPError):
    def __init__(self, detail: str = ""):
        super().__init__(MCPErrorCode.INVALID_REQUEST, f"Invalid request: {detail}")


class MethodNotFoundError(MCPError):
    def __init__(self, method: str):
        super().__init__(MCPErrorCode.METHOD_NOT_FOUND, f"Method not found: {method}")


class InvalidParamsError(MCPError):
    def __init__(self, detail: str = ""):
        super().__init__(MCPErrorCode.INVALID_PARAMS, f"Invalid params: {detail}")


class ToolNotFoundError(MCPError):
    def __init__(self, tool_name: str):
        super().__init__(MCPErrorCode.TOOL_NOT_FOUND, f"Tool not found: {tool_name}")


class ToolExecutionError(MCPError):
    def __init__(self, tool_name: str, detail: str):
        super().__init__(
            MCPErrorCode.TOOL_EXECUTION_FAILED,
            f"Tool '{tool_name}' execution failed: {detail}"
        )


class ResourceNotFoundError(MCPError):
    def __init__(self, uri: str):
        super().__init__(MCPErrorCode.RESOURCE_NOT_FOUND, f"Resource not found: {uri}")


def handle_with_error_mapping(request_id: int | None, method: str, params: dict) -> dict:
    """带完整错误映射的请求处理"""
    try:
        if method == "tools/call":
            tool_name = params.get("name")
            if not tool_name:
                raise InvalidParamsError("missing 'name' field")
            arguments = params.get("arguments", {})
            return execute_tool(tool_name, arguments)
        elif method == "tools/list":
            return list_tools()
        else:
            raise MethodNotFoundError(method)
    except MCPError as e:
        return e.to_response(request_id)
    except ValueError as e:
        return MCPError(MCPErrorCode.INVALID_PARAMS, str(e)).to_response(request_id)
    except Exception as e:
        # 不暴露内部堆栈，只返回通用错误
        return MCPError(MCPErrorCode.INTERNAL_ERROR, "Internal server error").to_response(request_id)
```

**要点**：
- 不同类型的错误要用对应的错误码，不要所有错误都返回 -32603
- 错误信息要对开发者友好（包含排查信息），但不要暴露内部实现细节
- 建立自定义异常类体系，让错误处理代码更清晰
- 常见错误：直接把 Exception.message 返回给用户，暴露了数据库连接串、文件路径等敏感信息
