# 05 能力协商——Client 与 Server 的能力发现与协商机制

> Client 和 Server 在连接时需要交换能力信息，确保双方理解对方支持的功能。

## 场景引入

你写了一个支持 Resource 订阅的 MCP Server，部署后发现某些 Client 连上来后直接调用 resources/subscribe 却报错了。排查后发现，这些 Client 在初始化时没有声明 subscribe 能力，Server 却没有检查就直接处理了请求。反过来，有些 Client 声明了 prompts 能力，但你的 Server 根本没实现 prompts——Client 发 prompts/list 请求时 Server 返回了 Method not found。能力协商到底该怎么正确实现？

## 一、能力协商流程

```
能力协商流程：

1. Client 发送初始化请求
   {
     "method": "initialize",
     "params": {
       "capabilities": {
         "tools": {},
         "resources": {"subscribe": true},
         "prompts": {}
       }
     }
   }

2. Server 返回能力
   {
     "result": {
       "capabilities": {
         "tools": {"listChanged": true},
         "resources": {"subscribe": true},
         "prompts": {}
       }
     }
   }

3. Client 发送初始化完成通知
   {
     "method": "notifications/initialized"
   }
```

class ServerCapabilities:
    """Server 能力"""
    
    def __init__(self):
        self.tools = {"listChanged": True}

class ClientCapabilities:

## 四、动态能力更新

```python
class DynamicCapabilities:
    """动态能力管理"""
    
    def __init__(self):
        self.capabilities = {}
        self.change_listeners = []
    
    def update(self, new_capabilities: dict):
        """更新能力"""
        self.capabilities = new_capabilities
        self._notify_change()
    
    def on_change(self, listener):
        """监听能力变更"""
        self.change_listeners.append(listener)
    
    def _notify_change(self):
        """通知变更"""
        for listener in self.change_listeners:
            listener(self.capabilities)
```

## 常见误区

```
误区 1：能力协商只是形式，可以跳过
  能力协商是 MCP 协议的必要步骤。跳过协商直接调用方法，
  会导致 Server 不支持的功能被调用，产生不可预期的错误。

误区 2：Server 必须支持 Client 声明的所有能力
  能力协商是"广告"机制，不是"承诺"机制。
  Server 只需要支持自己声明的能力，Client 声明的能力 Server 可以忽略。

误区 3：能力在初始化后就不能变了
  MCP 支持动态能力更新。Server 可以通过 notifications/tools/list_changed
  通知 Client 工具列表已变更，Client 应重新获取工具列表。

误区 4：能力字段为空表示不支持
  空对象 {} 通常表示"支持该能力但没有特殊配置"，
  完全不出现该字段才表示"不支持"。两者含义不同。
```

---

## 工程建议

```
1. 初始化时严格校验能力
   在 initialize 处理器中，检查 Client 声明的能力是否与 Server 匹配。
   对于不支持的能力，要在响应中明确不包含该字段。

2. 调用前检查能力可用性
   在处理 tools/call、resources/read 等请求之前，
   先检查对应的 capabilities 是否在初始化时协商通过。

3. 用 listChanged 支持热更新
   如果你的 Server 支持运行时增删 Tool，要在 capabilities 中声明 listChanged。
   Tool 列表变化时发送通知，让 Client 及时更新缓存。

4. 记录协商结果用于调试
   把初始化时的 Client/Server 能力交换记录到日志中。
   连接问题排查时，能力不匹配是最常见的原因之一。
```

---

## 小结

1. 能力协商在初始化时进行
2. Client 和 Server 交换支持的功能列表
3. 能力检查确保调用时功能可用
4. 支持动态能力更新和通知

### 练习一：实现能力协商流程

**思路**：实现完整的 initialize 握手流程：Client 发送能力声明 → Server 返回能力声明 → Client 发送 initialized 通知。Server 需要校验 Client 声明的能力是否与自己匹配。

**答案**：

```python
import json
from dataclasses import dataclass, field


@dataclass
class ServerCapabilities:
    """Server 能力声明"""
    tools: dict = field(default_factory=lambda: {"listChanged": True})
    resources: dict = field(default_factory=lambda: {"subscribe": True})
    prompts: dict = field(default_factory=dict)

    def to_dict(self) -> dict:
        result = {}
        if self.tools:
            result["tools"] = self.tools
        if self.resources:
            result["resources"] = self.resources
        if self.prompts:
            result["prompts"] = self.prompts
        return result


class CapabilityNegotiator:
    """能力协商器"""

    def __init__(self, server_capabilities: ServerCapabilities):
        self.server_capabilities = server_capabilities
        self.client_capabilities: dict = {}
        self.initialized = False

    def handle_initialize(self, request_id: int, params: dict) -> dict:
        """处理 initialize 请求"""
        client_caps = params.get("capabilities", {})
        self.client_capabilities = client_caps

        # 校验 Client 请求的能力是否 Server 支持
        negotiated = self._negotiate(client_caps)

        return {
            "jsonrpc": "2.0",
            "id": request_id,
            "result": {
                "protocolVersion": "2024-11-05",
                "capabilities": negotiated,
                "serverInfo": {
                    "name": "my-mcp-server",
                    "version": "1.0.0"
                }
            }
        }

    def handle_initialized(self) -> None:
        """处理 initialized 通知"""
        self.initialized = True
        print("能力协商完成，连接就绪")

    def _negotiate(self, client_caps: dict) -> dict:
        """协商能力：只返回 Server 支持且 Client 请求的能力"""
        server_dict = self.server_capabilities.to_dict()
        negotiated = {}

        for capability_name in ["tools", "resources", "prompts"]:
            if capability_name in client_caps and capability_name in server_dict:
                # 合并配置：Server 的配置 + Client 请求的选项
                merged = {**server_dict[capability_name]}
                client_config = client_caps[capability_name]
                if isinstance(client_config, dict):
                    # 如果 Client 请求了 subscribe，Server 也支持，则启用
                    if client_config.get("subscribe") and server_dict[capability_name].get("subscribe"):
                        merged["subscribe"] = True
                negotiated[capability_name] = merged

        return negotiated

    def is_capability_available(self, capability: str) -> bool:
        """检查某个能力是否在协商中达成一致"""
        return capability in self.client_capabilities and capability in self.server_capabilities.to_dict()


# 使用示例
negotiator = CapabilityNegotiator(ServerCapabilities())

# 模拟 Client 的 initialize 请求
init_request = {
    "jsonrpc": "2.0",
    "id": 1,
    "method": "initialize",
    "params": {
        "protocolVersion": "2024-11-05",
        "capabilities": {
            "tools": {},
            "resources": {"subscribe": True}
        },
        "clientInfo": {"name": "my-client", "version": "1.0.0"}
    }
}

response = negotiator.handle_initialize(init_request["id"], init_request["params"])
print(json.dumps(response, indent=2, ensure_ascii=False))
# 返回 Server 的能力声明，只包含双方都支持的能力

# 模拟 Client 的 initialized 通知
negotiator.handle_initialized()
```

**要点**：
- 协商是"取交集"：只返回 Server 支持且 Client 请求的能力
- 空对象 {} 表示"支持但没有特殊配置"，不出现该字段才表示"不支持"
- initialized 是 Notification，不需要返回响应
- 常见错误：Server 返回了自己不支持的能力，导致后续请求失败

### 练习二：实现能力检查功能

**思路**：在处理每个请求之前，先检查对应的能力是否在初始化时协商通过。未协商的能力被调用时，返回明确的错误信息。

**答案**：

```python
class CapabilityChecker:
    """能力检查器"""

    def __init__(self):
        self.negotiated_capabilities: dict = {}

    def set_negotiated(self, capabilities: dict):
        """设置协商后的能力"""
        self.negotiated_capabilities = capabilities

    def check_method(self, method: str) -> tuple[bool, str]:
        """检查方法是否可用，返回 (是否可用, 错误信息)"""
        # 方法到能力的映射
        method_capability_map = {
            "tools/list": "tools",
            "tools/call": "tools",
            "resources/list": "resources",
            "resources/read": "resources",
            "resources/subscribe": "resources",
            "prompts/list": "prompts",
            "prompts/get": "prompts",
        }

        required_capability = method_capability_map.get(method)
        if not required_capability:
            return True, ""  # 未知方法由方法路由处理

        if required_capability not in self.negotiated_capabilities:
            return False, (
                f"方法 '{method}' 需要 '{required_capability}' 能力，"
                f"但初始化时未协商该能力。"
                f"请在 initialize 请求的 capabilities 中声明 '{required_capability}'。"
            )

        return True, ""

    def check_resource_subscription(self) -> tuple[bool, str]:
        """检查资源订阅是否可用"""
        resources = self.negotiated_capabilities.get("resources", {})
        if not resources.get("subscribe"):
            return False, "Server 不支持资源订阅。初始化时 capabilities.resources.subscribe 未启用。"
        return True, ""

    def check_tool_list_changed(self) -> bool:
        """检查 Server 是否支持工具列表变更通知"""
        tools = self.negotiated_capabilities.get("tools", {})
        return tools.get("listChanged", False)


# 使用示例：在消息处理器中集成能力检查
class MCPMessageRouter:
    def __init__(self):
        self.checker = CapabilityChecker()

    def handle_request(self, request: dict) -> dict:
        method = request.get("method")
        request_id = request.get("id")

        # 先检查能力
        available, error_msg = self.checker.check_method(method)
        if not available:
            return {
                "jsonrpc": "2.0",
                "id": request_id,
                "error": {
                    "code": -32601,
                    "message": error_msg
                }
            }

        # 能力检查通过，路由到具体处理器
        return self._route(method, request_id, request.get("params", {}))

    def _route(self, method, request_id, params):
        # 具体路由逻辑...
        pass
```

**要点**：
- 每个 MCP 方法对应一个能力，调用前必须检查该能力是否协商通过
- 错误信息要说明缺什么能力、怎么修复
- 常见错误：跳过能力检查直接处理请求，导致 Server 不支持的功能被调用

### 练习三：实现动态能力更新机制

**思路**：Server 在运行时可能增删 Tool（如插件热加载），需要通过通知机制告知 Client 能力已变更，Client 收到通知后重新获取能力列表。

**答案**：

```python
import asyncio
from datetime import datetime
from typing import Callable


class DynamicCapabilityManager:
    """动态能力管理器"""

    def __init__(self):
        self._tools: dict[str, dict] = {}
        self._resources: dict[str, dict] = {}
        self._change_listeners: list[Callable] = []
        self._notification_queue: asyncio.Queue = asyncio.Queue()

    def register_tool(self, name: str, description: str, input_schema: dict):
        """注册新 Tool"""
        self._tools[name] = {
            "name": name,
            "description": description,
            "inputSchema": input_schema
        }
        asyncio.create_task(self._notify_change("tools"))

    def unregister_tool(self, name: str):
        """注销 Tool"""
        if name in self._tools:
            del self._tools[name]
            asyncio.create_task(self._notify_change("tools"))

    def register_resource(self, uri: str, name: str, description: str):
        """注册新 Resource"""
        self._resources[uri] = {
            "uri": uri,
            "name": name,
            "description": description
        }
        asyncio.create_task(self._notify_change("resources"))

    def unregister_resource(self, uri: str):
        """注销 Resource"""
        if uri in self._resources:
            del self._resources[uri]
            asyncio.create_task(self._notify_change("resources"))

    def list_tools(self) -> list[dict]:
        """获取当前工具列表"""
        return list(self._tools.values())

    def list_resources(self) -> list[dict]:
        """获取当前资源列表"""
        return list(self._resources.values())

    def on_change(self, listener: Callable):
        """注册变更监听器"""
        self._change_listeners.append(listener)

    async def _notify_change(self, capability_type: str):
        """通知能力变更"""
        notification = {
            "jsonrpc": "2.0",
            "method": f"notifications/{capability_type}/list_changed"
        }

        for listener in self._change_listeners:
            try:
                await listener(notification)
            except Exception as e:
                print(f"通知监听器失败: {e}")

    async def wait_for_change(self) -> dict:
        """等待能力变更通知（供 Client 轮询使用）"""
        return await self._notification_queue.get()


# 使用示例
async def main():
    manager = DynamicCapabilityManager()

    # 注册变更通知处理
    async def send_notification(notification: dict):
        print(f"[{datetime.now()}] 发送通知: {notification}")

    manager.on_change(send_notification)

    # 注册初始工具
    manager.register_tool("query_db", "查询数据库", {
        "type": "object",
        "properties": {"sql": {"type": "string"}}
    })

    await asyncio.sleep(0.1)

    # 运行时动态添加工具
    manager.register_tool("send_email", "发送邮件", {
        "type": "object",
        "properties": {"to": {"type": "string"}, "body": {"type": "string"}}
    })

    await asyncio.sleep(0.1)

    # 运行时动态移除工具
    manager.unregister_tool("send_email")

    await asyncio.sleep(0.1)

    # Client 收到 list_changed 通知后，重新获取工具列表
    tools = manager.list_tools()
    print(f"当前工具列表: {[t['name'] for t in tools]}")


if __name__ == "__main__":
    asyncio.run(main())
```

**要点**：
- Server 增删 Tool 后必须发送 notifications/tools/list_changed 通知
- Client 收到通知后应该重新调用 tools/list 获取最新列表，而不是依赖缓存
- 动态能力更新是"通知"机制，不是"同步"机制——Client 可能延迟收到
- 常见错误：Server 更新了工具列表但没有发通知，Client 一直在用旧的缓存列表
