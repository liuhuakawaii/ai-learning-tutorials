# 05 成本分析——API 调用 vs 本地部署的 TCO 对比与决策框架

> 选择 API 还是本地部署，成本是关键因素。

## 场景引入

你的微调模型已经部署上线，但月底一看账单：GPU 服务器月租 8000 元，电费 2000 元，运维人力成本另算。而如果直接用 GPT-4 API，同样的请求量只要 3000 元/月。本地部署真的比 API 划算吗？什么时候 API 更便宜？什么时候自建更省钱？你需要一个科学的成本分析框架来回答这些问题。

---

## 学习目标

- 掌握 TCO（总拥有成本）的计算方法
- 理解 API 和本地部署的成本结构
- 学会做出成本效益最优的决策

---

## 一、成本结构

```
API 调用成本：
- 按 Token 计费
- 无前期投入
- 成本随用量线性增长

本地部署成本：
- 硬件成本（GPU 服务器）
- 电力成本
- 运维成本
- 前期投入大，边际成本低
```

---

## 二、TCO 计算

```python
def calculate_api_cost(monthly_requests: int, avg_tokens: int, price_per_token: float) -> float:
    """计算 API 成本"""
    return monthly_requests * avg_tokens * price_per_token

def calculate_local_cost(
    hardware_cost: float,
    monthly_power_cost: float,
    monthly_maintenance_cost: float,
    months: int
) -> float:
    """计算本地部署成本"""
    return hardware_cost + (monthly_power_cost + monthly_maintenance_cost) * months
```

---

## 三、决策框架

```
决策框架：

月请求量 < 100K → API 调用
月请求量 100K-1M → 需要详细分析
月请求量 > 1M → 本地部署

其他因素：
- 数据隐私要求 → 倾向本地
- 延迟要求高 → 倾向本地
- 快速上线 → 倾向 API
- 预算有限 → 倾向 API
```

---

## 四、盈亏分析

```python
def breakeven_analysis(api_cost_per_month: float, local_cost_per_month: float) -> int:
    """盈亏平衡分析"""
    # 假设硬件成本
    hardware_cost = 10000  # $10,000
    
    # 计算多少个月后本地部署更划算
    monthly_savings = api_cost_per_month - local_cost_per_month
    
    if monthly_savings <= 0:
        return -1  # API 更划算
    
    return hardware_cost / monthly_savings
```

## 五、成本优化

```
成本优化策略：

API 调用：
- 使用更便宜的模型
- 优化 Prompt 减少 Token
- 缓存常见请求
- 批处理请求

本地部署：
- 使用量化模型
- 优化推理性能
- 合理规划资源
- 自动扩缩容
```

def generate_cost_report(api_cost: float, local_cost: float, breakeven_months: int) -> str:

## 常见误区

1. **只算 GPU 成本不算运维成本**：GPU 服务器需要人维护——监控、故障处理、版本升级、安全补丁。运维人力成本可能比 GPU 租金还高。

2. **用峰值成本做决策**：不应该按峰值请求量计算本地部署成本。低谷期 GPU 闲置也是成本。应该按平均利用率计算，或使用弹性伸缩。

3. **忽略数据传输成本**：API 调用的 Token 费用只是显性成本，网络带宽、数据存储、日志存储这些隐性成本也要计入。

4. **一次分析就做长期决策**：API 价格在持续下降，GPU 性能在持续提升。成本分析应该每季度更新一次，而不是一次决策用一年。

---

## 工程建议

1. **盈亏分析是决策的核心**：计算本地部署的固定成本（硬件）和可变成本（电力、运维），与 API 的按量费用对比，找到盈亏平衡点。

2. **低用量先用 API**：月请求量 < 100K 时，API 通常更划算。先用 API 验证业务可行性，等用量上来再考虑自建。

3. **混合方案是最优解**：核心业务用本地部署（保障数据隐私和低延迟），非核心业务用 API（降低成本和运维负担）。

4. **量化成本优化效果**：每次成本优化（如模型量化、Prompt 缩短、缓存命中率提升）都要量化节省的金额，用数据驱动优化决策。

## 参考答案

### 练习一：计算题

**思路**：分别计算 API 调用和本地部署的总拥有成本（TCO），包含所有显性和隐性成本。

**答案**：
```python
def calculate_api_tco(
    monthly_requests: int,
    avg_input_tokens: int,
    avg_output_tokens: int,
    input_price_per_token: float = 2.5 / 1_000_000,   # GPT-4o: $2.5/1M
    output_price_per_token: float = 10.0 / 1_000_000,  # GPT-4o: $10/1M
    months: int = 12
) -> dict:
    """计算 API 调用的 TCO"""
    
    # 每月 Token 费用
    monthly_input_cost = monthly_requests * avg_input_tokens * input_price_per_token
    monthly_output_cost = monthly_requests * avg_output_tokens * output_price_per_token
    monthly_api_cost = monthly_input_cost + monthly_output_cost
    
    # 隐性成本（带宽、日志存储、开发调试）
    monthly_bandwidth_cost = monthly_requests * 0.0001  # 约 $0.0001/请求
    monthly_storage_cost = 10  # 日志存储约 $10/月
    
    monthly_total = monthly_api_cost + monthly_bandwidth_cost + monthly_storage_cost
    
    return {
        "monthly_api_cost": monthly_api_cost,
        "monthly_total": monthly_total,
        "annual_total": monthly_total * months,
        "breakdown": {
            "input_tokens": monthly_input_cost,
            "output_tokens": monthly_output_cost,
            "bandwidth": monthly_bandwidth_cost,
            "storage": monthly_storage_cost
        }
    }


def calculate_local_tco(
    gpu_monthly_rent: float = 8000,      # A100 月租约 ¥8000
    monthly_power_cost: float = 2000,    # 电费约 ¥2000/月
    monthly_maintenance_cost: float = 3000,  # 运维人力 ¥3000/月
    setup_cost: float = 5000,            # 初始部署成本 ¥5000
    months: int = 12
) -> dict:
    """计算本地部署的 TCO"""
    
    monthly_hardware = gpu_monthly_rent
    monthly_total = monthly_hardware + monthly_power_cost + monthly_maintenance_cost
    
    return {
        "setup_cost": setup_cost,
        "monthly_hardware": monthly_hardware,
        "monthly_power": monthly_power_cost,
        "monthly_maintenance": monthly_maintenance_cost,
        "monthly_total": monthly_total,
        "annual_total": setup_cost + monthly_total * months
    }


def print_tco_comparison(api_tco: dict, local_tco: dict):
    """输出 TCO 对比"""
    
    print("=== TCO 对比分析 ===\n")
    print(f"{'项目':<20} {'API 调用':>15} {'本地部署':>15}")
    print("-" * 55)
    print(f"{'月度成本':<20} {'$' + f'{api_tco[\"monthly_total\"]:.2f}':>15} {'¥' + f'{local_tco[\"monthly_total\"]:.0f}':>15}")
    print(f"{'年度总成本':<20} {'$' + f'{api_tco[\"annual_total\"]:.2f}':>15} {'¥' + f'{local_tco[\"annual_total\"]:.0f}':>15}")
    
    # 假设汇率 1 USD = 7.2 CNY
    api_annual_cny = api_tco["annual_total"] * 7.2
    print(f"\nAPI 年度成本（人民币）: ¥{api_annual_cny:,.0f}")
    print(f"本地年度成本（人民币）: ¥{local_tco['annual_total']:,.0f}")
    
    if api_annual_cny < local_tco["annual_total"]:
        print(f"\n结论: API 更划算，每年节省 ¥{local_tco['annual_total'] - api_annual_cny:,.0f}")
    else:
        print(f"\n结论: 本地部署更划算，每年节省 ¥{api_annual_cny - local_tco['annual_total']:,.0f}")


if __name__ == "__main__":
    api_tco = calculate_api_tco(
        monthly_requests=50000,
        avg_input_tokens=500,
        avg_output_tokens=200
    )
    local_tco = calculate_local_tco()
    print_tco_comparison(api_tco, local_tco)
```

**要点**：
- TCO 必须包含隐性成本：运维人力、带宽、日志存储、故障恢复
- API 成本随用量线性增长，本地成本前期投入大但边际成本低
- 不同汇率和电价会影响结论，要根据实际地区调整
- 常见错误：只算 GPU 租金不算运维人力，严重低估本地部署成本

### 练习二：分析题

**思路**：通过盈亏平衡分析，找到 API 和本地部署成本相等的请求量临界点。

**答案**：
```python
def breakeven_analysis(
    api_cost_per_request: float,
    local_monthly_fixed_cost: float,
    local_cost_per_request: float = 0,  # 本地部署的边际成本
    setup_cost: float = 5000
) -> dict:
    """盈亏平衡分析"""
    
    if api_cost_per_request <= local_cost_per_request:
        return {
            "breakeven_requests": -1,
            "recommendation": "API 的单次成本低于本地，API 始终更划算"
        }
    
    # 每月节省 = (api_cost_per_request - local_cost_per_request) * requests - local_monthly_fixed_cost
    # 盈亏平衡时：累计节省 = setup_cost
    # (api_cost_per_request - local_cost_per_request) * requests * months - local_monthly_fixed_cost * months = setup_cost
    
    monthly_savings_per_request = api_cost_per_request - local_cost_per_request
    
    # 计算多少个月回本
    # 假设月请求量为 R
    # 每月节省 = R * monthly_savings_per_request - local_monthly_fixed_cost
    # 需要多少个月: setup_cost / monthly_savings
    
    # 反过来：给定月请求量，多少个月回本
    def months_to_breakeven(monthly_requests: int) -> float:
        monthly_savings = (monthly_requests * monthly_savings_per_request) - local_monthly_fixed_cost
        if monthly_savings <= 0:
            return float('inf')
        return setup_cost / monthly_savings
    
    # 不同请求量下的回本时间
    request_levels = [10000, 50000, 100000, 500000, 1000000]
    
    print("=== 盈亏平衡分析 ===\n")
    print(f"API 单次成本: ${api_cost_per_request:.6f}")
    print(f"本地月度固定成本: ${local_monthly_fixed_cost:.2f}")
    print(f"本地初始投入: ${setup_cost:.2f}\n")
    
    print(f"{'月请求量':>12} {'月节省':>12} {'回本月数':>10}")
    print("-" * 40)
    
    for req_count in request_levels:
        monthly_savings = (req_count * monthly_savings_per_request) - local_monthly_fixed_cost
        months = months_to_breakeven(req_count)
        months_str = f"{months:.1f}" if months != float('inf') else "永不回本"
        print(f"{req_count:>12,} ${monthly_savings:>10,.2f} {months_str:>10}")
    
    return {
        "breakeven_by_requests": {
            req: months_to_breakeven(req) for req in request_levels
        }
    }


if __name__ == "__main__":
    breakeven_analysis(
        api_cost_per_request=0.0035,      # 每次请求约 $0.0035
        local_monthly_fixed_cost=13000,    # 月度固定成本 $13000
        setup_cost=5000                    # 初始投入 $5000
    )
```

**要点**：
- 盈亏平衡点是决策的核心数据，低于临界点用 API，高于临界点用本地
- 要考虑请求量的增长趋势，如果请求量快速增长，即使当前 API 更划算，几个月后可能本地更优
- 本地部署的"回本月数"要结合业务确定性评估——如果业务不确定，长回本周期风险更高
- 常见错误：用峰值请求量计算盈亏平衡，导致高估本地部署的性价比

### 练习三：决策题

**思路**：综合 TCO、盈亏平衡、业务约束（数据隐私、延迟、上线时间）做出最终决策。

**答案**：
```python
def make_deployment_decision(
    monthly_requests: int,
    data_privacy_required: bool = False,
    latency_sensitive: bool = False,
    budget_monthly_limit: float = 15000,
    timeline_weeks: int = 4
) -> dict:
    """做出 API vs 本地部署的决策"""
    
    # 计算成本
    api_monthly = monthly_requests * 0.0035  # $0.0035/请求
    local_monthly = 13000  # 固定月度成本
    local_setup = 5000
    
    decision_factors = []
    scores = {"api": 0, "local": 0}
    
    # 1. 成本维度
    if api_monthly < local_monthly:
        decision_factors.append(f"成本: API 更便宜 (${api_monthly:.0f} vs ${local_monthly:.0f}/月)")
        scores["api"] += 2
    else:
        decision_factors.append(f"成本: 本地更便宜 (${local_monthly:.0f} vs ${api_monthly:.0f}/月)")
        scores["local"] += 2
    
    # 2. 数据隐私
    if data_privacy_required:
        decision_factors.append("数据隐私: 硬性要求，必须本地部署")
        scores["local"] += 5  # 一票否决
    else:
        decision_factors.append("数据隐私: 无硬性要求")
        scores["api"] += 1
    
    # 3. 延迟
    if latency_sensitive:
        decision_factors.append("延迟: 敏感场景，本地部署延迟更低")
        scores["local"] += 2
    else:
        decision_factors.append("延迟: 不敏感")
        scores["api"] += 1
    
    # 4. 预算
    if budget_monthly_limit < local_monthly:
        decision_factors.append(f"预算: 月预算 ${budget_monthly_limit} 不足以支撑本地部署")
        scores["api"] += 3
    else:
        decision_factors.append(f"预算: 月预算 ${budget_monthly_limit} 充足")
    
    # 5. 时间
    if timeline_weeks < 2:
        decision_factors.append("时间: 上线紧迫，API 可立即使用")
        scores["api"] += 3
    elif timeline_weeks < 4:
        decision_factors.append("时间: 时间紧张，API 风险更低")
        scores["api"] += 1
    else:
        decision_factors.append("时间: 充裕，可以部署本地方案")
        scores["local"] += 1
    
    # 混合方案判断
    if 50000 < monthly_requests < 500000 and not data_privacy_required:
        recommendation = "hybrid"
        reason = "中等用量且无隐私硬性要求，建议混合方案：核心业务本地部署，非核心用 API"
    elif scores["local"] > scores["api"]:
        recommendation = "local"
        reason = "综合评分本地部署更优"
    else:
        recommendation = "api"
        reason = "综合评分 API 更优"
    
    result = {
        "recommendation": recommendation,
        "reason": reason,
        "factors": decision_factors,
        "scores": scores
    }
    
    print("=== 部署决策分析 ===\n")
    print(f"月请求量: {monthly_requests:,}")
    print(f"API 月成本: ${api_monthly:,.0f}")
    print(f"本地月成本: ${local_monthly:,.0f}\n")
    
    print("决策因素:")
    for factor in decision_factors:
        print(f"  • {factor}")
    
    print(f"\n评分: API={scores['api']} vs 本地={scores['local']}")
    print(f"\n建议方案: {recommendation}")
    print(f"理由: {reason}")
    
    return result


if __name__ == "__main__":
    make_deployment_decision(
        monthly_requests=200000,
        data_privacy_required=False,
        latency_sensitive=True,
        budget_monthly_limit=20000,
        timeline_weeks=6
    )
```

**要点**：
- 决策不能只看成本，数据隐私、延迟、上线时间都是关键因素
- 混合方案（核心业务本地 + 非核心 API）往往是最优解
- 数据隐私如果是硬性要求，即使 API 更便宜也必须选择本地
- 常见错误：用一次分析做长期决策，API 价格和 GPU 成本都在变化，应每季度重新评估
