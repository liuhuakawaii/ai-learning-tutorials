# 01 通用基准评估——MMLU / HellaSwag / ARC 等基准测试

> 基准测试让你客观地评估模型能力。

## 场景引入

你微调完一个模型，用几个测试问题试了试，感觉"好像比之前好了一点"。但"感觉好一点"能写进报告吗？能说服老板继续投入资源吗？你需要一套客观的评估体系，用标准化的基准测试（MMLU、HumanEval、GSM8K）给出量化的分数，让微调效果不再是主观判断，而是可衡量、可对比的数据。

## 四、对比评估

```python
def compare_models(base_model_path: str, finetuned_model_path: str):
    """对比模型"""
    
    # 基线模型
    base_results = run_eval(base_model_path)
    
    # 微调模型
    finetuned_results = run_eval(finetuned_model_path)
    
    # 对比
    for task in base_results:
        base_score = base_results[task]
        finetuned_score = finetuned_results[task]
        improvement = finetuned_score - base_score
        
        print(f"{task}: {base_score:.2f} → {finetuned_score:.2f} ({improvement:+.2f})")
```

## 常见误区

1. **只看 MMLU 分数就下结论**：MMLU 评估的是知识广度，不代表模型在你的业务场景上表现好。一个 MMLU 80 分的模型在你的医疗问答任务上可能还不如 MMLU 70 分的模型。

2. **用基准分数直接对比不同架构的模型**：不同架构（Dense vs MoE）、不同训练数据的模型，基准分数的含义不同。MoE 模型参数多但激活参数少，直接比分数不公平。

3. **微调后基准分数下降就认为失败**：微调让模型专注于特定领域，通用能力略有下降是正常的"遗忘"现象。关键是领域任务的提升是否值得通用能力的下降。

4. **评估时用不同的 few-shot 数量**：few-shot 数量对基准分数影响很大（5-shot 比 0-shot 可能高 10 分）。对比不同模型时必须用相同的 few-shot 配置。

---

## 工程建议

1. **评估要覆盖多个维度**：至少跑 MMLU（知识）、HumanEval（代码）、GSM8K（推理）三个基准，全面了解模型能力。单一基准容易产生误导。

2. **用 lm-eval-harness 标准化评估**：lm-eval-harness 是社区标准的评估工具，支持 100+ 基准，结果可复现、可对比。不要自己写评估脚本。

3. **建立模型评估档案**：每次微调后记录基准分数变化，形成模型的"体检报告"。长期积累可以发现哪些配置对哪些能力影响最大。

4. **基准测试要在相同硬件上跑**：不同 GPU、不同量化级别的推理结果可能有差异。对比评估时确保所有模型在相同的硬件和配置下运行。

## 参考答案

### 练习一：评估题

**思路**：使用 lm-eval-harness 对微调后的模型运行 MMLU 基准测试，这是社区标准的评估工具，结果可复现、可对比。

**答案**：
```python
import subprocess
import json

def run_mmlu_evaluation(model_path: str, num_fewshot: int = 5, batch_size: int = 8) -> dict:
    """运行 MMLU 基准测试"""
    
    # 运行 lm-eval
    cmd = [
        "lm_eval", "--model", "hf",
        "--model_args", f"pretrained={model_path}",
        "--tasks", "mmlu",
        "--num_fewshot", str(num_fewshot),
        "--batch_size", str(batch_size),
        "--output_path", "./eval_results"
    ]
    
    result = subprocess.run(cmd, capture_output=True, text=True)
    
    if result.returncode != 0:
        raise RuntimeError(f"评估失败: {result.stderr}")
    
    # 解析结果
    with open("./eval_results/results.json", "r") as f:
        results = json.load(f)
    
    mmlu_score = results["results"]["mmlu"]["acc,none"]
    print(f"MMLU 分数: {mmlu_score:.2%}")
    
    return {"mmlu": mmlu_score}


def run_multi_benchmark(model_path: str) -> dict:
    """运行多个基准测试"""
    
    tasks = "mmlu,hellaswag,arc_challenge,gsm8k,humaneval"
    
    cmd = [
        "lm_eval", "--model", "hf",
        "--model_args", f"pretrained={model_path}",
        "--tasks", tasks,
        "--num_fewshot", "5",
        "--output_path", "./eval_results_multi"
    ]
    
    result = subprocess.run(cmd, capture_output=True, text=True)
    
    if result.returncode != 0:
        raise RuntimeError(f"评估失败: {result.stderr}")
    
    with open("./eval_results_multi/results.json", "r") as f:
        results = json.load(f)
    
    summary = {}
    for task_name, task_results in results["results"].items():
        for metric_name, value in task_results.items():
            if "acc" in metric_name:
                summary[task_name] = value
                print(f"{task_name}: {value:.2%}")
    
    return summary


if __name__ == "__main__":
    results = run_mmlu_evaluation("./merged_model", num_fewshot=5, batch_size=8)
```

**要点**：
- `--num_fewshot` 参数对结果影响很大，对比不同模型时必须保持一致
- `--batch_size` 根据 GPU 显存调整，太大会 OOM
- 评估结果保存到文件便于后续对比和归档
- 常见错误：不指定 `--num_fewshot` 导致使用默认值 0，与文档中的 5-shot 结果不可比

### 练习二：对比题

**思路**：分别对基座模型和微调模型运行相同的基准测试，计算分数差异，重点关注微调带来的提升和可能的通用能力下降。

**答案**：
```python
import json
from pathlib import Path

def compare_finetuned_vs_base(base_model_path: str, finetuned_model_path: str) -> dict:
    """对比微调前后的基准分数"""
    
    import subprocess
    
    tasks = "mmlu,hellaswag,arc_challenge,gsm8k"
    
    # 评估基座模型
    subprocess.run([
        "lm_eval", "--model", "hf",
        "--model_args", f"pretrained={base_model_path}",
        "--tasks", tasks, "--num_fewshot", "5",
        "--output_path", "./eval_base"
    ], check=True)
    
    # 评估微调模型
    subprocess.run([
        "lm_eval", "--model", "hf",
        "--model_args", f"pretrained={finetuned_model_path}",
        "--tasks", tasks, "--num_fewshot", "5",
        "--output_path", "./eval_finetuned"
    ], check=True)
    
    # 加载结果
    with open("./eval_base/results.json") as f:
        base_results = json.load(f)
    with open("./eval_finetuned/results.json") as f:
        ft_results = json.load(f)
    
    # 对比分析
    print(f"{'基准':<20} {'基座模型':>10} {'微调模型':>10} {'变化':>10}")
    print("-" * 55)
    
    comparison = {}
    for task in base_results["results"]:
        base_score = list(base_results["results"][task].values())[0]
        ft_score = list(ft_results["results"][task].values())[0]
        delta = ft_score - base_score
        
        comparison[task] = {
            "base": base_score,
            "finetuned": ft_score,
            "delta": delta
        }
        
        indicator = "↑" if delta > 0 else "↓" if delta < 0 else "="
        print(f"{task:<20} {base_score:>9.2%} {ft_score:>9.2%} {delta:>+9.2%} {indicator}")
    
    return comparison


if __name__ == "__main__":
    comparison = compare_finetuned_vs_base(
        "./base_model",
        "./merged_model"
    )
```

**要点**：
- 对比时必须用完全相同的 few-shot 配置、batch_size 和硬件环境
- 微调后 MMLU 下降 1-3 分是正常的"灾难性遗忘"，关键看目标任务是否提升
- 不要只看总分，要分学科/分维度分析变化
- 常见错误：用不同版本的 lm-eval-harness 跑两次评估，结果不可比

### 练习三：解读题

**思路**：从多个基准的分数中识别模型的优势和劣势维度，结合业务需求判断微调是否达标。

**答案**：
```python
def interpret_evaluation_results(results: dict) -> dict:
    """解读评估结果，分析模型优势和劣势"""
    
    # 分数等级定义
    thresholds = {
        "mmlu": {"优秀": 0.70, "良好": 0.60, "一般": 0.50},
        "hellaswag": {"优秀": 0.80, "良好": 0.70, "一般": 0.60},
        "arc_challenge": {"优秀": 0.70, "良好": 0.55, "一般": 0.45},
        "gsm8k": {"优秀": 0.70, "良好": 0.50, "一般": 0.30},
    }
    
    analysis = {
        "strengths": [],
        "weaknesses": [],
        "overall": "",
        "recommendations": []
    }
    
    for task, score in results.items():
        task_thresholds = thresholds.get(task, {"优秀": 0.75, "良好": 0.60, "一般": 0.45})
        
        if score >= task_thresholds["优秀"]:
            analysis["strengths"].append(f"{task}: {score:.2%} (优秀)")
        elif score < task_thresholds["一般"]:
            analysis["weaknesses"].append(f"{task}: {score:.2%} (需要改进)")
    
    # 综合判断
    avg_score = sum(results.values()) / len(results)
    if avg_score >= 0.70:
        analysis["overall"] = "模型整体能力优秀，可以投入使用"
    elif avg_score >= 0.55:
        analysis["overall"] = "模型整体能力良好，建议针对弱项优化"
    else:
        analysis["overall"] = "模型整体能力不足，需要重新审视训练策略"
    
    # 生成建议
    if results.get("mmlu", 0) < 0.55:
        analysis["recommendations"].append("知识广度不足，建议增加训练数据中的知识覆盖")
    if results.get("gsm8k", 0) < 0.40:
        analysis["recommendations"].append("数学推理能力弱，建议增加数学推理训练样本")
    if results.get("humaneval", 0) < 0.50:
        analysis["recommendations"].append("代码生成能力不足，建议增加代码训练数据")
    
    # 输出报告
    print("=== 评估结果解读 ===\n")
    print("【优势维度】")
    for s in analysis["strengths"]:
        print(f"  ✓ {s}")
    print("\n【劣势维度】")
    for w in analysis["weaknesses"]:
        print(f"  ✗ {w}")
    print(f"\n【综合评价】{analysis['overall']}")
    if analysis["recommendations"]:
        print("\n【改进建议】")
        for r in analysis["recommendations"]:
            print(f"  → {r}")
    
    return analysis


if __name__ == "__main__":
    sample_results = {
        "mmlu": 0.68,
        "hellaswag": 0.75,
        "arc_challenge": 0.52,
        "gsm8k": 0.45
    }
    analysis = interpret_evaluation_results(sample_results)
```

**要点**：
- 解读分数时要结合每个基准的评分标准，不同基准的"好"和"差"阈值不同
- 微调模型的通用能力下降是正常的，关键是领域任务的提升是否值得
- 不要只看数字，要分析分数背后的原因（训练数据分布、任务难度等）
- 常见错误：把不同基准的分数直接横向比较（MMLU 60 和 GSM8K 60 的含义完全不同）
