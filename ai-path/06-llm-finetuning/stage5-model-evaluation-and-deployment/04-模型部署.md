## 常见误区

1. **不设超时就上线**：没有请求超时的服务是不可靠的。一个异常的长请求可能占用 GPU 资源数分钟，影响其他用户的正常使用。

2. **只部署一个实例不做高可用**：单实例部署时，模型重启或更新就会导致服务中断。生产环境至少部署 2 个实例，通过负载均衡实现高可用。

3. **不做版本管理就部署**：每次更新模型直接覆盖旧版本，出问题无法回滚。模型部署应该像代码部署一样，支持版本管理和灰度发布。

4. **忽略安全防护**：模型 API 暴露在公网上没有认证和限流，容易被滥用。必须配置 API Key 认证、请求限流、输入过滤。

---

## 工程建议

1. **Docker 部署是标准做法**：用 Docker 容器化部署，配合 docker-compose 或 K8s 管理。确保开发、测试、生产环境一致。

2. **健康检查和监控不能少**：`/health` 端点做存活检查，`/metrics` 端点暴露 Prometheus 指标。配置 Grafana 仪表盘实时监控服务状态。

3. **灰度发布降低风险**：新版本先部署到 10% 的流量，观察 24 小时无异常后再全量切换。出问题可以快速回滚到旧版本。

4. **预热请求避免冷启动**：模型服务刚启动时第一个请求会很慢（模型加载到 GPU）。部署后先发几个预热请求，确保服务进入热状态。

### 练习一：部署题

**思路**：使用 vLLM 部署微调模型，配置合适的推理参数，提供 OpenAI 兼容的 API 接口。

**答案**：
```bash
# 1. 安装 vLLM
pip install vllm

# 2. 启动 vLLM 服务（OpenAI 兼容 API）
python -m vllm.entrypoints.openai.api_server \
  --model ./merged_model \
  --host 0.0.0.0 \
  --port 8000 \
  --max-model-len 4096 \
  --gpu-memory-utilization 0.9 \
  --dtype auto
```

```python
# 3. 验证部署是否成功
import requests
import json

def verify_deployment(base_url: str = "http://localhost:8000") -> bool:
    """验证模型部署是否成功"""
    
    # 健康检查
    health_response = requests.get(f"{base_url}/health")
    if health_response.status_code != 200:
        print(f"健康检查失败: {health_response.status_code}")
        return False
    print("✓ 健康检查通过")
    
    # 检查模型列表
    models_response = requests.get(f"{base_url}/v1/models")
    if models_response.status_code == 200:
        models = models_response.json()
        print(f"✓ 可用模型: {[m['id'] for m in models['data']]}")
    
    # 测试推理
    test_response = requests.post(
        f"{base_url}/v1/chat/completions",
        headers={"Content-Type": "application/json"},
        json={
            "model": "./merged_model",
            "messages": [{"role": "user", "content": "你好，请介绍一下你自己"}],
            "max_tokens": 100
        }
    )
    
    if test_response.status_code == 200:
        result = test_response.json()
        print(f"✓ 推理测试通过")
        print(f"  回复: {result['choices'][0]['message']['content'][:100]}")
        print(f"  Token 用量: {result['usage']}")
        return True
    else:
        print(f"✗ 推理测试失败: {test_response.status_code}")
        return False


if __name__ == "__main__":
    verify_deployment()
```

**要点**：
- `--gpu-memory-utilization 0.9` 留 10% 显存余量避免 OOM
- `--max-model-len` 根据实际需求设置，过大会占用更多显存
- 部署后必须做健康检查和推理测试，确认服务可用
- 常见错误：不设置 `--max-model-len` 导致默认值过大，显存不足启动失败

### 练习二：Docker 题

**思路**：将 vLLM 部署容器化，编写 Dockerfile 和 docker-compose.yml，确保环境一致性。

**答案**：
```dockerfile
# Dockerfile
FROM vllm/vllm-openai:latest

# 设置工作目录
WORKDIR /app

# 复制模型文件（或挂载卷）
COPY ./merged_model /model

# 暴露端口
EXPOSE 8000

# 启动命令
ENTRYPOINT ["python", "-m", "vllm.entrypoints.openai.api_server"]
CMD ["--model", "/model", "--host", "0.0.0.0", "--port", "8000", "--gpu-memory-utilization", "0.9"]
```

```yaml
# docker-compose.yml
version: '3.8'

services:
  model-server:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: llm-model-server
    ports:
      - "8000:8000"
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1
              capabilities: [gpu]
    volumes:
      - ./merged_model:/model:ro  # 只读挂载模型
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 60s  # 模型加载需要时间
    logging:
      driver: json-file
      options:
        max-size: "10m"
        max-file: "3"
```

```bash
# 构建并启动
docker-compose up -d --build

# 查看日志
docker-compose logs -f model-server

# 停止服务
docker-compose down
```

**要点**：
- 模型文件用 volume 挂载而非 COPY，避免镜像体积过大且便于更新模型
- `healthcheck` 的 `start_period` 要足够长，模型加载到 GPU 需要时间
- 设置 `restart: unless-stopped` 确保服务异常退出后自动重启
- 常见错误：把模型文件直接 COPY 到镜像里，导致镜像几十 GB，构建和分发都很慢

### 练习三：优化题

**思路**：通过量化、批处理、KV 缓存等手段优化推理性能，提高吞吐量并降低延迟。

**答案**：
```bash
# 1. 使用 AWQ 量化部署（减少显存占用，提高推理速度）
python -m vllm.entrypoints.openai.api_server \
  --model ./merged_model_awq \
  --host 0.0.0.0 \
  --port 8000 \
  --quantization awq \
  --gpu-memory-utilization 0.95 \
  --max-num-batched-tokens 8192 \
  --max-num-seqs 256
```

```python
# 2. 性能基准测试
import asyncio
import aiohttp
import time

async def send_request(session, url, payload):
    """发送单个请求"""
    start = time.time()
    async with session.post(url, json=payload) as resp:
        result = await resp.json()
        latency = time.time() - start
        return {
            "latency": latency,
            "tokens": result.get("usage", {}).get("total_tokens", 0)
        }

async def benchmark_performance(
    base_url: str = "http://localhost:8000",
    concurrency: int = 10,
    total_requests: int = 50
) -> dict:
    """并发性能测试"""
    
    url = f"{base_url}/v1/chat/completions"
    payload = {
        "model": "./merged_model",
        "messages": [{"role": "user", "content": "用一句话解释什么是机器学习"}],
        "max_tokens": 100
    }
    
    semaphore = asyncio.Semaphore(concurrency)
    results = []
    
    async def bounded_request(session):
        async with semaphore:
            return await send_request(session, url, payload)
    
    start_time = time.time()
    
    async with aiohttp.ClientSession() as session:
        tasks = [bounded_request(session) for _ in range(total_requests)]
        results = await asyncio.gather(*tasks)
    
    total_time = time.time() - start_time
    
    latencies = [r["latency"] for r in results]
    total_tokens = sum(r["tokens"] for r in results)
    
    report = {
        "total_requests": total_requests,
        "concurrency": concurrency,
        "total_time": total_time,
        "throughput_rps": total_requests / total_time,
        "avg_latency": sum(latencies) / len(latencies),
        "p50_latency": sorted(latencies)[len(latencies) // 2],
        "p95_latency": sorted(latencies)[int(len(latencies) * 0.95)],
        "p99_latency": sorted(latencies)[int(len(latencies) * 0.99)],
        "total_tokens": total_tokens,
        "tokens_per_second": total_tokens / total_time
    }
    
    print("=== 性能测试报告 ===")
    print(f"总请求数: {report['total_requests']}")
    print(f"并发数: {report['concurrency']}")
    print(f"吞吐量: {report['throughput_rps']:.2f} req/s")
    print(f"平均延迟: {report['avg_latency']:.3f}s")
    print(f"P95 延迟: {report['p95_latency']:.3f}s")
    print(f"Token 吞吐: {report['tokens_per_second']:.0f} tokens/s")
    
    return report


if __name__ == "__main__":
    asyncio.run(benchmark_performance(concurrency=10, total_requests=50))
```

**要点**:
- AWQ 量化可以在几乎不损失质量的前提下将显存占用降低 40-50%
- `--max-num-batched-tokens` 和 `--max-num-seqs` 控制批处理大小，需要根据显存和延迟要求调优
- 性能测试要测量 P95/P99 延迟，不能只看平均值
- 常见错误：只优化吞吐量忽略延迟，导致用户体验下降；或者只优化延迟忽略吞吐量，导致资源浪费
