# 01 环境搭建——从 CUDA 版本不匹配到第一次成功加载模型

> 正确的环境是微调的基础。环境问题是最常见的坑。

你按照教程写好了微调代码，一运行就报错：

```
RuntimeError: CUDA out of memory. Tried to allocate 2.00 GiB
```

或者：

```
ModuleNotFoundError: No module named 'peft'
```

或者更隐蔽的：

```python
>>> torch.cuda.is_available()
False
```

折腾了一整天，还没开始训练就被环境问题劝退了。

CUDA 版本和 PyTorch 版本不匹配、Transformers 和 PEFT 版本冲突、bitsandbytes 在 Windows 上编译失败——这些坑几乎每个新手都会踩。这节课不是给你一个安装命令列表，而是带你从一个报错开始，搞清楚每一步为什么这么装。

---

## 先搞清楚你的 GPU

装任何东西之前，先确认你有什么：

```bash
nvidia-smi
```

输出类似：

```
+-----------------------------------------------------------------------------+
| NVIDIA-SMI 535.104.05   Driver Version: 535.104.05   CUDA Version: 12.2     |
| GPU  Name        Persistence-M| Bus-Id        Disp.A | Volatile Uncorr. ECC |
| Fan  Temp  Perf  Pwr:Usage/Cap|         Memory-Usage | GPU-Util  Compute M. |
|===============================+======================+======================|
|   0  NVIDIA GeForce RTX 4090  |   00000000:01:00.0  |                  N/A |
| 30%   35C    P8    22W / 450W |    0MiB / 24564MiB   |      0%      Default |
+-------------------------------+----------------------+----------------------+
```

这里有两个关键信息：
- **Driver Version**：你的显卡驱动版本
- **CUDA Version**：驱动支持的最高 CUDA 版本（这里是 12.2）

注意：`CUDA Version` 不是你安装的 CUDA 版本，是驱动支持的最高版本。你实际安装的 CUDA 可以比这个低，但不能比这个高。

---

## PyTorch 和 CUDA 的关系

这是最容易搞混的地方。`nvidia-smi` 显示 CUDA 12.2，但你安装的 PyTorch 可能带的是 CUDA 11.8 或 12.1。这没关系——PyTorch 自带 CUDA 运行时，不需要你单独安装 CUDA toolkit。

```bash
# 安装 PyTorch（CUDA 12.1 版本）
# 关键：--index-url 中的 cu121 决定了 PyTorch 带的 CUDA 版本
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121
```

验证：

```python
import torch
print(torch.__version__)           # 2.x.x+cu121
print(torch.cuda.is_available())   # True
print(torch.cuda.get_device_name(0))  # NVIDIA GeForce RTX 4090
```

如果 `torch.cuda.is_available()` 返回 `False`：
1. 检查 `torch.__version__` 是否带 `+cuXXX`——不带说明装的是 CPU 版本
2. 检查 `cuXXX` 是否 ≤ 你的驱动支持的 CUDA 版本
3. 重新安装，确保 `--index-url` 正确

## Transformers 和 PEFT

```bash
pip install transformers datasets accelerate
pip install peft
```

这两个通常不会冲突。但如果你看到类似 `ImportError: cannot import name 'xxx' from 'transformers'`，大概率是版本不兼容：

```bash
# 查看当前版本
pip show transformers peft

# 如果版本太旧，升级
pip install --upgrade transformers peft

# 如果升级后其他包出问题，锁定版本
pip install transformers==4.44.0 peft==0.12.0
```

## bitsandbytes：Windows 上的大坑

bitsandbytes 是 QLoRA 量化的必需依赖。在 Linux 上 `pip install bitsandbytes` 就行，但在 Windows 上会编译失败。

**解决方案**：

```bash
# 方案 1：WSL2（推荐）
# 在 WSL2 的 Ubuntu 中，pip install bitsandbytes 直接可用

# 方案 2：Docker
docker run --gpus all -it nvidia/cuda:12.1.0-runtime-ubuntu22.04 bash
# 容器内 pip install bitsandbytes

# 方案 3：Windows 预编译 wheel
pip install bitsandbytes-windows
# 或从 GitHub releases 下载对应版本的 .whl 手动安装
```

如果你暂时不需要 QLoRA（只用 LoRA + FP16），可以先跳过 bitsandbytes。

## 环境检查脚本

把所有检查写成一个脚本，每次新建环境后跑一次：

```python
"""微调环境检查"""
import sys

def check():
    results = []

    # Python
    results.append(f"Python: {sys.version.split()[0]}")

    # PyTorch + CUDA
    try:
        import torch
        results.append(f"PyTorch: {torch.__version__}")
        results.append(f"CUDA available: {torch.cuda.is_available()}")
        if torch.cuda.is_available():
            results.append(f"GPU: {torch.cuda.get_device_name(0)}")
            mem = torch.cuda.get_device_properties(0).total_memory / 1024**3
            results.append(f"GPU Memory: {mem:.1f} GB")
        else:
            results.append("ERROR: CUDA 不可用")
    except ImportError:
        results.append("ERROR: PyTorch 未安装")

    # Transformers
    try:
        import transformers
        results.append(f"Transformers: {transformers.__version__}")
    except ImportError:
        results.append("ERROR: Transformers 未安装")

    # PEFT
    try:
        import peft
        results.append(f"PEFT: {peft.__version__}")
    except ImportError:
        results.append("ERROR: PEFT 未安装")

    # bitsandbytes
    try:
        import bitsandbytes
        results.append(f"bitsandbytes: {bitsandbytes.__version__}")
    except ImportError:
        results.append("WARNING: bitsandbytes 未安装（QLoRA 需要）")

    # 打印
    print("=" * 50)
    for r in results:
        print(f"  {r}")
    print("=" * 50)

    errors = [r for r in results if r.startswith("ERROR")]
    if errors:
        print(f"发现 {len(errors)} 个错误，请修复")
    else:
        print("环境检查通过")

check()
```

## 快速验证：加载一个模型

环境没问题后，试着加载一个小模型验证整个链路：

```python
from transformers import AutoTokenizer, AutoModelForCausalLM
from peft import LoraConfig, get_peft_model
import torch

# 加载一个小模型测试
model_name = "Qwen/Qwen2.5-1.5B-Instruct"  # 1.5B，显存友好
tokenizer = AutoTokenizer.from_pretrained(model_name, trust_remote_code=True)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    torch_dtype=torch.bfloat16,
    device_map="auto",
    trust_remote_code=True,
)

# 测试 LoRA 配置
lora_config = LoraConfig(
    r=8,
    lora_alpha=16,
    target_modules=["q_proj", "v_proj"],
    lora_dropout=0.05,
    task_type="CAUSAL_LM",
)
peft_model = get_peft_model(model, lora_config)
peft_model.print_trainable_parameters()
# 输出类似: trainable params: 1,835,008 || all params: 1,543,101,440 || trainable%: 0.1189

print("环境验证通过！可以开始微调了。")
```

如果这段代码能跑通，你的环境就 ready 了。

## Docker 环境（团队协作推荐）

```dockerfile
FROM nvidia/cuda:12.1.0-runtime-ubuntu22.04

RUN apt-get update && apt-get install -y python3 python3-pip git

RUN pip3 install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121
RUN pip3 install transformers datasets accelerate peft bitsandbytes

WORKDIR /app
COPY requirements.txt .
RUN pip3 install -r requirements.txt

COPY . .
```

```bash
docker build -t finetune-env .
docker run --gpus all -it -v ./data:/app/data finetune-env bash
```

Docker 的好处是环境可复现。你本地跑通的环境，同事拉同一个镜像就能用。

## 容易犯的错

**直接 `pip install torch` 不指定 `--index-url`**。默认装的是 CPU 版本，`torch.cuda.is_available()` 返回 `False`。

**nvidia-smi 显示 CUDA 12.2 就装 CUDA 12.2 的 PyTorch**。nvidia-smi 显示的是驱动支持的最高版本，你可以装更低版本的 CUDA。关键是 PyTorch 的 `cuXXX` 不能超过驱动支持的版本。

**不在虚拟环境中安装**。全局安装容易导致包版本冲突。每个微调项目都应该有独立的 venv 或 conda 环境。

**在 Windows 上硬编译 bitsandbytes**。浪费大量时间。直接用 WSL2 或 Docker。

## 练习

### 练习一：从零搭建环境

在一台新机器（或新的虚拟环境）上，从零搭建微调环境：

```bash
# 1. 创建虚拟环境
python -m venv finetune-env
source finetune-env/bin/activate  # Linux/macOS
# finetune-env\Scripts\activate   # Windows

# 2. 按顺序安装
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121
pip install transformers datasets accelerate
pip install peft bitsandbytes

# 3. 运行检查脚本
python check_env.py

# 4. 运行模型加载验证
python verify_load.py
```

记录每一步的输出，特别是版本号。

### 练习二：排查环境问题

故意制造一个环境问题，然后排查：

```python
# 问题 1：安装 CPU 版本的 PyTorch
pip install torch  # 不指定 --index-url
python -c "import torch; print(torch.cuda.is_available())"
# 预期输出: False

# 排查：
print(torch.__version__)  # 不带 +cuXXX
```

## 参考答案

### 练习一

成功标志：
- `torch.cuda.is_available()` 返回 `True`
- `torch.cuda.get_device_name(0)` 显示你的 GPU 型号
- `peft` 和 `bitsandbytes` 能正常 import
- 1.5B 模型能加载到 GPU 并完成推理

### 练习二

排查思路：
1. 看 `torch.__version__` 是否带 `+cuXXX`
2. 看 `cuXXX` 是否 ≤ 驱动支持的 CUDA 版本
3. 看 `torch.cuda.is_available()` 的返回值
4. 看报错信息中是否提到具体的 CUDA 库缺失

### 练习三

关键点：
- 基础镜像用 `nvidia/cuda:12.1.0-runtime-ubuntu22.04`，不要用 `latest`
- `docker run` 必须加 `--gpus all`，否则容器内看不到 GPU
- 常见错误：Docker 没有安装 NVIDIA Container Toolkit，`--gpus` 参数报错
