常见问题及解决：

1. CUDA 版本不匹配
   - 检查：nvidia-smi 和 nvcc --version

## 常见误区

1. **CUDA 和 PyTorch 版本不匹配**：nvidia-smi 显示的 CUDA 版本和 nvcc --version 不一致很常见。PyTorch 需要的 CUDA 版本由安装命令中的 `cuXXX` 决定，而不是 nvidia-smi 显示的版本。

2. **用 pip 安装 CUDA 相关包**：bitsandbytes 等包需要 CUDA 运行时支持，pip 安装可能找不到正确的 CUDA 库。Linux 上推荐用 conda 或直接从源码编译。

3. **不在虚拟环境中安装**：全局安装容易导致包版本冲突。每次微调项目都应该创建独立的虚拟环境（venv 或 conda），避免依赖地狱。

4. **忽略 Windows 兼容性问题**：bitsandbytes、flash-attention 等关键依赖在 Windows 上支持不佳。Windows 用户推荐使用 WSL2 或 Docker 进行微调。

---

## 工程建议

1. **用 Docker 一键搭建环境**：基于 `nvidia/cuda:12.1.0-runtime-ubuntu22.04` 构建 Docker 镜像，把所有依赖写进 Dockerfile，确保环境可复现。

2. **写环境检查脚本**：把 GPU 检查、CUDA 检查、PyTorch 检查、PEFT 检查写成一个脚本，每次新建环境后运行一次，5 秒内确认环境是否正常。

3. **锁定依赖版本**：用 `pip freeze > requirements.txt` 锁定所有依赖版本，避免不同时间安装导致版本不一致。

4. **准备离线安装包**：在有网络的环境提前下载好所有 wheel 包，打包到离线环境安装，避免在训练服务器上因网络问题卡住。

## 参考答案

### 练习一：搭建完整的微调环境

**思路**：按照课程的安装顺序（CUDA → PyTorch → Transformers → PEFT）逐步搭建，每步验证后再进行下一步。关键是确保 CUDA 版本和 PyTorch 版本匹配。

**答案**：
```bash
# 1. 检查 GPU 和 CUDA 驱动
nvidia-smi

# 2. 安装 PyTorch（根据 nvidia-smi 显示的 CUDA 版本选择对应的 PyTorch）
# 例如 CUDA 12.1：
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121

# 3. 验证 PyTorch + CUDA
python -c "import torch; print(f'CUDA: {torch.cuda.is_available()}'); print(f'GPU: {torch.cuda.get_device_name(0)}')"

# 4. 安装 Transformers 生态
pip install transformers datasets accelerate

# 5. 安装 PEFT 和量化依赖
pip install peft bitsandbytes

# 6. 创建 requirements.txt 锁定版本
pip freeze > requirements.txt

# 7. 综合验证
python -c "
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import LoraConfig
print(f'CUDA: {torch.cuda.is_available()}')
print(f'GPU: {torch.cuda.get_device_name(0)}')
print(f'PEFT: {LoraConfig(r=8, lora_alpha=16, target_modules=[\"q_proj\"])}')
print('环境搭建完成！')
"
```

**要点**：
- PyTorch 的 CUDA 版本由安装命令中的 `cuXXX` 决定，不是 nvidia-smi 显示的版本
- 必须在虚拟环境（venv 或 conva）中安装，避免全局依赖冲突
- 常见错误：直接 `pip install torch` 不指定 `--index-url`，安装的是 CPU 版本

### 练习二：运行环境检查脚本

**思路**：编写一个综合检查脚本，覆盖 GPU、CUDA、PyTorch、Transformers、PEFT 所有关键组件，一次运行确认环境状态。

**答案**：
```python
"""微调环境检查脚本"""
import sys

def check_environment():
    results = []
    
    # 1. 检查 Python 版本
    py_version = sys.version.split()[0]
    results.append(f"Python: {py_version}")
    
    # 2. 检查 PyTorch + CUDA
    try:
        import torch
        cuda_available = torch.cuda.is_available()
        results.append(f"PyTorch: {torch.__version__}")
        results.append(f"CUDA available: {cuda_available}")
        if cuda_available:
            gpu_name = torch.cuda.get_device_name(0)
            gpu_mem = torch.cuda.get_device_properties(0).total_memory / 1024**3
            results.append(f"GPU: {gpu_name}")
            results.append(f"GPU Memory: {gpu_mem:.1f} GB")
        else:
            results.append("WARNING: CUDA 不可用，无法进行 GPU 训练")
    except ImportError:
        results.append("ERROR: PyTorch 未安装")
    
    # 3. 检查 Transformers
    try:
        import transformers
        results.append(f"Transformers: {transformers.__version__}")
    except ImportError:
        results.append("ERROR: Transformers 未安装")
    
    # 4. 检查 PEFT
    try:
        import peft
        results.append(f"PEFT: {peft.__version__}")
    except ImportError:
        results.append("ERROR: PEFT 未安装")
    
    # 5. 检查 bitsandbytes
    try:
        import bitsandbytes
        results.append(f"bitsandbytes: {bitsandbytes.__version__}")
    except ImportError:
        results.append("WARNING: bitsandbytes 未安装（QLoRA 需要）")
    
    # 打印结果
    print("=" * 50)
    print("微调环境检查报告")
    print("=" * 50)
    for r in results:
        print(f"  {r}")
    print("=" * 50)
    
    errors = [r for r in results if r.startswith("ERROR")]
    if errors:
        print(f"发现 {len(errors)} 个错误，请修复后再开始训练")
    else:
        print("环境检查通过，可以开始训练")

if __name__ == "__main__":
    check_environment()
```

**要点**：
- 脚本应覆盖所有关键依赖，不能只检查 PyTorch
- bitsandbytes 缺失是 WARNING 而非 ERROR，因为只有 QLoRA 才需要
- 常见错误：只检查 `import torch` 不检查 `torch.cuda.is_available()`，以为装了 PyTorch 就有 GPU 支持

### 练习三：解决一个环境问题

**思路**：以最常见的 "bitsandbytes 在 Windows 上安装失败" 为例，展示排查思路和解决方案。关键是先定位问题根源，再选择合适的解决路径。

**答案**：
```bash
# 问题：pip install bitsandbytes 报错，提示编译失败
# 常见于 Windows 环境

# 排查步骤：

# 1. 确认操作系统
# Windows 上 bitsandbytes 官方支持不佳

# 2. 方案一：使用预编译的 Windows wheel
pip install bitsandbytes-windows
# 或从 GitHub releases 下载对应版本的 .whl 文件手动安装

# 3. 方案二：使用 WSL2（推荐）
# 在 WSL2 中安装 Ubuntu，然后按正常流程安装
wsl --install -d Ubuntu-22.04
# 进入 WSL2 后：
pip install bitsandbytes

# 4. 方案三：使用 Docker
docker run --gpus all -it nvidia/cuda:12.1.0-runtime-ubuntu22.04 bash
# 容器内安装
pip install bitsandbytes

# 5. 验证安装成功
python -c "import bitsandbytes; print(f'bitsandbytes: {bitsandbytes.__version__}')"
```

**要点**：
- Windows 上的环境问题，优先考虑 WSL2 或 Docker，而不是在 Windows 上硬编译
- 排查顺序：确认错误信息 → 搜索已知 issue → 选择最成熟的解决方案
- 常见错误：在 Windows 上反复尝试源码编译 bitsandbytes，浪费大量时间，不如直接用 WSL2
