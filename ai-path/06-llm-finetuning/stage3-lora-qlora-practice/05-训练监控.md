## 二、Loss 曲线解读

```
Loss 曲线解读：

1. 正常下降
   Loss 持续下降，最终趋于平稳
   → 训练正常

2. 震荡
   Loss 上下波动
   → 学习率太大，降低学习率

3. 不下降
   Loss 保持不变
   → 学习率太小，或数据有问题

4. 上升
   Loss 持续上升
   → 学习率太大，或梯度爆炸
```

## 三、过拟合检测

```python
def detect_overfitting(train_losses: list, eval_losses: list) -> bool:
    """检测过拟合"""
    if len(eval_losses) < 5:
        return False
    
    # 检查 eval loss 是否开始上升
    recent_eval = eval_losses[-5:]
    if all(recent_eval[i] <= recent_eval[i+1] for i in range(len(recent_eval)-1)):
        return True
    
    return False
```

## 六、告警机制

```python
class TrainingMonitor:
    """训练监控器"""
    
    def __init__(self):
        self.train_losses = []
        self.eval_losses = []
    
    def check(self, train_loss: float, eval_loss: float):
        """检查训练状态"""
        self.train_losses.append(train_loss)
        self.eval_losses.append(eval_loss)
        
        # 检查过拟合
        if self._detect_overfitting():
            self._alert("检测到过拟合！")
        
        # 检查 loss 异常
        if train_loss > 10:
            self._alert("Loss 异常高！")
    
    def _alert(self, message: str):
        """发送告警"""
        logger.warning(message)
```

## 常见误区

1. **只看 Loss 数值不看趋势**：Loss 从 2.3 降到 1.5 不代表效果好，关键是趋势——是否持续下降、是否趋于平稳、是否出现反弹。

2. **过拟合了就加更多数据**：过拟合的根因可能是数据量不足，但也可能是训练轮数太多或 dropout 太小。先尝试减少 epochs 和增加 dropout，而不是急着加数据。

3. **训练中断就从头开始**：Transformers Trainer 支持 `resume_from_checkpoint`，可以从最近的 checkpoint 恢复训练。定期保存 checkpoint 可以避免大量重复计算。

4. **不用 TensorBoard 等可视化工具**：纯看日志中的 Loss 数字很难发现趋势问题。TensorBoard 的曲线图能让你一眼看出过拟合、学习率问题等异常。

---

## 工程建议

1. **Loss 曲线是最基本的监控**：训练过程中实时查看 Loss 曲线，发现异常立即排查。正常曲线应该是先快速下降再缓慢趋于平稳。

2. **设置自动告警**：当 Loss 连续 N 步不下降、或 Loss 突然飙升、或 GPU 显存接近上限时，自动发送告警通知，避免白白浪费 GPU 时间。

3. **eval_loss 是过拟合的信号灯**：当 eval_loss 开始上升而 train_loss 继续下降时，就是过拟合的信号。此时应该停止训练或减少 epochs。

4. **保存最佳模型而非最后一个模型**：用 `load_best_model_at_end=True` 配合 `metric_for_best_model="eval_loss"`，确保最终保存的是验证集上表现最好的模型。

## 参考答案

### 练习一：使用 TensorBoard 监控训练过程

**思路**：配置 `report_to="tensorboard"` 让 Trainer 自动记录训练指标，启动 TensorBoard 服务查看实时曲线。关键是理解各指标的含义并能从曲线判断训练状态。

**答案**：
```python
"""配置 TensorBoard 监控"""
from transformers import TrainingArguments, SFTTrainer

training_args = TrainingArguments(
    output_dir="./output_tensorboard",
    num_train_epochs=3,
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,
    learning_rate=2e-4,
    warmup_ratio=0.1,
    fp16=True,
    logging_steps=10,              # 每 10 步记录一次
    eval_strategy="steps",         # 按步数评估
    eval_steps=50,                 # 每 50 步评估一次
    save_strategy="steps",
    save_steps=100,
    report_to="tensorboard",       # 输出到 TensorBoard
    logging_dir="./output_tensorboard/logs",  # TensorBoard 日志目录
)

# 训练
trainer = SFTTrainer(
    model=model, args=training_args,
    train_dataset=train_dataset,
    eval_dataset=eval_dataset,
    tokenizer=tokenizer, max_seq_length=512
)
trainer.train()
```

```bash
# 启动 TensorBoard（训练过程中或训练后均可）
tensorboard --logdir ./output_tensorboard/logs --port 6006

# 浏览器访问 http://localhost:6006
# 查看指标：
# - train/loss：训练 Loss 曲线
# - eval/loss：验证 Loss 曲线
# - train/learning_rate：学习率变化
# - train/global_step：训练步数
```

**要点**：
- `logging_steps` 太大（如 100）会错过关键变化，太小（如 1）会产生大量日志，10-20 是合理值
- 必须同时监控 eval_loss，只看 train_loss 无法发现过拟合
- 常见错误：忘记设置 `logging_dir`，TensorBoard 找不到日志文件

### 练习二：检测过拟合并调整策略

**思路**：过拟合的核心信号是 train_loss 持续下降但 eval_loss 开始上升。检测到过拟合后，可以减少 epochs、增加 dropout、或使用 Early Stopping。

**答案**：
```python
"""过拟合检测与应对"""
from transformers import TrainingArguments, SFTTrainer, EarlyStoppingCallback

# 方式一：使用 Early Stopping（推荐）
training_args = TrainingArguments(
    output_dir="./output_earlystop",
    num_train_epochs=10,              # 设置较多 epochs，由 Early Stopping 决定何时停
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,
    learning_rate=2e-4,
    warmup_ratio=0.1,
    fp16=True,
    logging_steps=10,
    eval_strategy="steps",
    eval_steps=50,
    save_strategy="steps",
    save_steps=50,
    load_best_model_at_end=True,      # 训练结束后加载最佳模型
    metric_for_best_model="eval_loss", # 以 eval_loss 为标准
    greater_is_better=False,           # eval_loss 越小越好
    save_total_limit=3,
    report_to="tensorboard",
)

trainer = SFTTrainer(
    model=model, args=training_args,
    train_dataset=train_dataset,
    eval_dataset=eval_dataset,
    tokenizer=tokenizer, max_seq_length=512,
    callbacks=[EarlyStoppingCallback(early_stopping_patience=3)]  # 连续 3 次不改善就停
)

trainer.train()

# 方式二：手动检测过拟合
def detect_overfitting(train_losses, eval_losses, window=5):
    """检测过拟合：eval_loss 连续 window 步上升"""
    if len(eval_losses) < window * 2:
        return False, "数据不足"
    
    recent = eval_losses[-window:]
    earlier = eval_losses[-window*2:-window]
    
    if sum(recent) / len(recent) > sum(earlier) / len(earlier):
        return True, f"eval_loss 在最近 {window} 步持续上升，疑似过拟合"
    return False, "训练正常"

# 使用示例
train_losses = [2.3, 2.1, 1.9, 1.7, 1.5, 1.3, 1.1, 0.9, 0.7, 0.5]
eval_losses =  [2.3, 2.1, 1.95, 1.85, 1.8, 1.82, 1.85, 1.9, 1.95, 2.0]
is_overfitting, msg = detect_overfitting(train_losses, eval_losses)
print(f"过拟合检测: {msg}")
```

**要点**：
- Early Stopping patience=3 是合理值，太小会过早停止（可能还没充分训练），太大会浪费时间
- `load_best_model_at_end=True` 确保最终保存的是验证集上最好的模型，而不是最后一个
- 常见错误：设了 Early Stopping 但没设 `metric_for_best_model`，导致保存的不是最佳模型

### 练习三：从检查点恢复训练

**思路**：训练中断后，通过 `resume_from_checkpoint` 从最近的 checkpoint 恢复，避免从头开始。关键是正确配置 checkpoint 保存策略，确保有足够的恢复点。

**答案**：
```python
"""训练中断恢复"""
from transformers import TrainingArguments, SFTTrainer

# 1. 配置自动保存 checkpoint
training_args = TrainingArguments(
    output_dir="./output_resume",
    num_train_epochs=3,
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,
    learning_rate=2e-4,
    fp16=True,
    logging_steps=10,
    save_strategy="steps",     # 按步数保存（而非 epoch）
    save_steps=100,            # 每 100 步保存一次
    save_total_limit=3,        # 最多保留 3 个 checkpoint，节省磁盘
)

trainer = SFTTrainer(
    model=model, args=training_args,
    train_dataset=dataset["train"],
    tokenizer=tokenizer, max_seq_length=2048
)

# 2. 首次训练（可能中途崩溃）
try:
    trainer.train()
except RuntimeError as e:
    if "CUDA" in str(e):
        print(f"训练中断: {e}")
        print("将从最近的 checkpoint 恢复")

# 3. 从最近 checkpoint 恢复
trainer.train(resume_from_checkpoint=True)
# 自动找到 output_resume/ 下最新的 checkpoint 目录

# 4. 从指定 checkpoint 恢复
trainer.train(resume_from_checkpoint="./output_resume/checkpoint-500")

# 5. 查看可用的 checkpoint
import os
output_dir = "./output_resume"
checkpoints = [d for d in os.listdir(output_dir) if d.startswith("checkpoint-")]
checkpoints.sort(key=lambda x: int(x.split("-")[1]))
print("可用 checkpoint:")
for ckpt in checkpoints:
    print(f"  {ckpt}")
```

**要点**：
- `save_strategy="steps"` 比 `"epoch"` 更灵活，可以更频繁地保存（特别是长 epoch 时）
- `save_total_limit=3` 只保留最近 3 个 checkpoint，避免磁盘被 checkpoint 撑满
- 常见错误：训练中断后直接 `trainer.train()` 从头开始，浪费之前的训练时间；或者 checkpoint 保存间隔太大（如 1000 步），中断后丢失大量进度
