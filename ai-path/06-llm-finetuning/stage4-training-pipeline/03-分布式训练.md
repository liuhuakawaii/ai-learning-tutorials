# 03 分布式训练——多 GPU 训练的配置与常见问题

> 多 GPU 训练能显著加速微调过程。

## 场景引入

你有 4 张 A100 GPU，想微调一个 14B 模型。单卡训练要跑 20 小时，你希望能缩短到 5 小时。但配置多 GPU 训练时遇到了各种问题：GPU 负载不均衡、通信瓶颈导致速度反而更慢、DeepSpeed 配置出错直接崩了。多 GPU 训练不是简单加卡就完事，需要理解分布式训练的原理和配置方法。

## 一、分布式训练方式

```
分布式训练方式：

1. Data Parallel（数据并行）
   - 每个 GPU 处理不同的数据
   - 同步梯度更新
   - 最常用的方式

2. Model Parallel（模型并行）
   - 模型分片到多个 GPU
   - 适合超大模型
   - 通信开销大

3. Pipeline Parallel（流水线并行）
   - 模型按层分片
   - 减少通信开销
   - 实现复杂
```

```python
from accelerate import Accelerator

accelerator = Accelerator()

model, optimizer, dataloader = accelerator.prepare(
    model, optimizer, dataloader
)

for batch in dataloader:
    outputs = model(**batch)
    loss = outputs.loss
    accelerator.backward(loss)
    optimizer.step()
    optimizer.zero_grad()
```

## 常见误区

1. **以为多卡就一定更快**：分布式训练有通信开销，如果模型太小或数据太少，通信开销可能超过并行收益。7B 模型用 2 卡通常就够了，4 卡反而可能更慢。

2. **学习率不随卡数调整**：数据并行时 effective batch_size 会翻倍，学习率通常也需要相应调整（如乘以卡数），否则训练效果可能变差。

3. **DeepSpeed Stage 3 用于 LoRA**：DeepSpeed ZeRO Stage 3 会分片模型参数，和 PEFT 的 LoRA 实现有兼容性问题。LoRA 微调用 Stage 2 就够了。

4. **忽略 GPU 间通信带宽**：NVLink 和 PCIe 的通信速度差距巨大。PCIe 连接的多卡训练效率通常只有 NVLink 的 60-70%。

---

## 工程建议

1. **Accelerate 是最简单的多卡方案**：对于 LoRA 微调，`accelerate launch train.py` 一行命令就能实现多卡训练，不需要复杂的 DeepSpeed 配置。

2. **先测单卡 baseline**：多卡训练前先在单卡上跑通完整流程，确认代码无误后再切换到多卡。多卡环境下的错误更难排查。

3. **监控 GPU 负载均衡**：用 `nvidia-smi` 或 `gpustat` 实时监控各 GPU 的利用率和显存占用，确保负载均衡。不均衡说明数据加载或模型分片有问题。

4. **gradient_accumulation 是更安全的"放大 batch"**：如果多卡通信开销太大，不如在单卡上用 gradient_accumulation 模拟大 batch_size，效果类似但没有通信开销。

## 参考答案

### 练习一：配置多 GPU 训练

**思路**：用 Accelerate 配置多 GPU 训练是最简单的方式。关键是理解 `accelerate config` 生成的配置文件，以及 `accelerate launch` 的启动参数。

**答案**：
```bash
# 方式一：交互式配置
accelerate config
# 按提示选择：
# - 训练环境：多 GPU
# - GPU 数量：你的 GPU 数量（如 2 或 4）
# - 混合精度：fp16
# - 其他默认

# 方式二：直接生成配置文件
cat > accelerate_config.yaml << 'EOF'
compute_environment: LOCAL_MACHINE
distributed_type: MULTI_GPU
num_machines: 1
num_processes: 4  # GPU 数量
gpu_ids: "0,1,2,3"
mixed_precision: "fp16"
use_cpu: false
EOF

# 启动训练
accelerate launch --config_file accelerate_config.yaml train.py
```

```python
"""使用 Accelerate 的训练代码"""
from accelerate import Accelerator
from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments
from peft import LoraConfig, get_peft_model
from trl import SFTTrainer
from datasets import load_dataset

# Accelerate 自动处理多 GPU
accelerator = Accelerator()

model_name = "Qwen/Qwen2.5-7B"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(
    model_name, torch_dtype=torch.float16, device_map="auto"
)
if tokenizer.pad_token is None:
    tokenizer.pad_token = tokenizer.eos_token

lora_config = LoraConfig(
    r=16, lora_alpha=32,
    target_modules=["q_proj", "v_proj", "k_proj", "o_proj"],
    lora_dropout=0.05, bias="none", task_type="CAUSAL_LM"
)
model = get_peft_model(model, lora_config)

dataset = load_dataset("json", data_files="training_data.json")

training_args = TrainingArguments(
    output_dir="./output_multigpu",
    num_train_epochs=3,
    per_device_train_batch_size=4,       # 每 GPU 的 batch_size
    gradient_accumulation_steps=4,
    learning_rate=2e-4,
    fp16=True,
    warmup_ratio=0.1,
    logging_steps=10,
    save_strategy="epoch",
    report_to="none",
    # 多 GPU 相关
    ddp_find_unused_parameters=False,    # 加速 DDP
)

trainer = SFTTrainer(
    model=model, args=training_args,
    train_dataset=dataset["train"],
    tokenizer=tokenizer, max_seq_length=2048
)

trainer.train()
```

**要点**：
- `per_device_train_batch_size` 是每 GPU 的 batch_size，总 batch_size = per_device * GPU数 * gradient_accumulation
- `ddp_find_unused_parameters=False` 可以加速 DDP，但如果有未使用的参数会报错
- 常见错误：不调整学习率，4 卡训练的 effective batch_size 翻 4 倍，学习率通常也需要相应调整

### 练习二：使用多 GPU 进行训练

**思路**：先在单卡上验证代码无误，再切换到多卡。重点对比单卡和多卡的训练速度差异，以及 effective batch_size 的计算。

**答案**：

```python
        num_train_epochs=1,
        per_device_train_batch_size=4,
        gradient_accumulation_steps=16,  # 单卡用更大累积
        learning_rate=2e-4,
        fp16=True,
        report_to="none",
    )
    # trainer = SFTTrainer(...)
    # start = time.time()
    # trainer.train()
    # single_time = time.time() - start
    return 3600  # 假设单卡 1 小时

def train_multi_gpu():
    """多卡训练"""
    training_args = TrainingArguments(
        output_dir="./output_multi",
        num_train_epochs=1,
        per_device_train_batch_size=4,
        gradient_accumulation_steps=4,   # 多卡不需要大累积
        learning_rate=2e-4,
        fp16=True,
        report_to="none",
        ddp_find_unused_parameters=False,
    )
    # accelerate launch train.py
    return 1200  # 假设 4 卡 20 分钟

# 对比
print("训练速度对比：")
print(f"  单卡 (batch=4, accum=16): ~60 分钟")
print(f"  4 卡 (batch=4, accum=4):  ~20 分钟")
print(f"  加速比: ~3x（理论 4x，通信开销约 25%）")
print(f"  effective batch_size 均为: 4 * 16 = 64")
```

**要点**：
- 多卡时减少 `gradient_accumulation_steps` 保持 effective batch_size 不变，而不是增大 per_device batch_size
- 加速比通常达不到理论值（线性加速），通信开销约 15-30%
- 常见错误：多卡训练时学习率不变，effective batch_size 翻倍导致训练不稳定

### 练习三：监控 GPU 使用情况

**思路**：实时监控各 GPU 的利用率和显存占用，确保负载均衡。不均衡说明数据加载或模型分片有问题。

**答案**：
```python
"""GPU 监控"""
import torch
import subprocess
import time

def get_gpu_info():
    """获取所有 GPU 的详细信息"""
    gpus = []
    for i in range(torch.cuda.device_count()):
        info = {
            "id": i,
            "name": torch.cuda.get_device_name(i),
            "total_mem": torch.cuda.get_device_properties(i).total_mem / 1024**3,
            "allocated_mem": torch.cuda.memory_allocated(i) / 1024**3,
            "cached_mem": torch.cuda.memory_reserved(i) / 1024**3,
            "utilization": torch.cuda.utilization(i) if hasattr(torch.cuda, 'utilization') else -1,
        }
        gpus.append(info)
    return gpus

def print_gpu_status():
    """打印 GPU 状态"""
    gpus = get_gpu_info()
    print("\nGPU 状态：")
    print("-" * 70)
    print(f"{'ID':<4} {'名称':<20} {'已用/总量(GB)':<15} {'缓存(GB)':<10} {'利用率':<10}")
    print("-" * 70)
    for gpu in gpus:
        mem_str = f"{gpu['allocated_mem']:.1f}/{gpu['total_mem']:.1f}"
        util_str = f"{gpu['utilization']}%" if gpu['utilization'] >= 0 else "N/A"
        print(f"{gpu['id']:<4} {gpu['name']:<20} {mem_str:<15} {gpu['cached_mem']:<10.1f} {util_str:<10}")
    
    # 检查负载均衡
    allocated = [g['allocated_mem'] for g in gpus]
    if max(allocated) - min(allocated) > 2.0:  # 差距超过 2GB
        print("\n⚠ 警告：GPU 负载不均衡！差距 > 2GB")
        print("  可能原因：数据加载不均匀、模型分片问题")

def monitor_training(interval: int = 5, duration: int = 60):
    """持续监控训练"""
    print(f"开始监控，每 {interval} 秒刷新，持续 {duration} 秒")
    end_time = time.time() + duration
    while time.time() < end_time:
        print_gpu_status()
        time.sleep(interval)

# 使用
print_gpu_status()
# monitor_training(interval=10, duration=300)  # 取消注释启动持续监控
```

**要点**：
- GPU 利用率不均衡（差距 > 2GB）通常说明数据加载或模型分片有问题
- `nvidia-smi` 只能看到总览，代码内监控可以获取更细粒度的信息（如每层的显存占用）
- 常见错误：只看 GPU 0 的显存就认为所有 GPU 都一样，实际上某些 GPU 可能空闲
