# 02 训练配置管理——用 YAML 配置文件管理实验参数

> 配置文件让实验可重复、可管理。

## 场景引入

你跑了一次效果不错的微调实验，想复现结果，却发现已经忘了当时的参数配置。学习率是多少？LoRA rank 用的几？数据集是哪个版本？代码里的硬编码被改了好几次，git log 也看不出当时的具体参数。你需要一种方式，把每次实验的完整配置保存下来，方便复现、对比和管理。

```yaml

  name: "Qwen/Qwen2.5-7B"
  dtype: "float16"
  device_map: "auto"

```

## 二、配置加载

```python
import yaml

def load_config(config_path: str) -> dict:
    """加载配置"""
    with open(config_path, "r") as f:
        return yaml.safe_load(f)

# 使用
config = load_config("config.yaml")
model_name = config["model"]["name"]
learning_rate = config["training"]["learning_rate"]
```

## 五、配置模板

```python
def create_experiment_config(experiment_name: str, **kwargs) -> dict:
    """创建实验配置"""
    base_config = load_config("base_config.yaml")
    
    # 覆盖参数
    for key, value in kwargs.items():
        keys = key.split(".")
        config = base_config
        for k in keys[:-1]:
            config = config[k]
        config[keys[-1]] = value
    
    # 保存
    save_config(f"experiments/{experiment_name}/config.yaml", base_config)
    
    return base_config
```

## 常见误区

1. **配置文件和代码不一致**：代码里硬编码了某些参数，配置文件里又写了一份，修改一个忘改另一个。所有参数都应该从配置文件读取，代码中不出现硬编码。

2. **配置文件不纳入版本管理**：配置文件是实验的核心记录，必须和代码一起提交到 Git。丢失配置文件意味着实验无法复现。

3. **配置验证只做格式检查**：只检查 YAML 语法正确不够，还要验证参数的业务合法性（如 learning_rate > 0、batch_size 是 2 的幂次）。

4. **所有实验用同一个配置文件**：每次实验的配置都应该独立保存，方便对比。修改配置时创建新文件而不是覆盖旧文件。

---

## 工程建议

1. **用 Pydantic 做配置验证**：Pydantic 不仅能验证类型，还能设置默认值、范围约束、自定义校验规则，在加载配置时就捕获错误。

2. **配置模板 + 覆盖机制**：维护一个基础配置模板，每次实验只覆盖需要修改的参数。减少配置冗余，降低出错概率。

3. **配置 diff 功能**：对比两次实验的配置差异，快速定位哪些参数变了。一个简单的 dict diff 函数就能实现。

4. **实验目录结构要规范**：每个实验一个目录，包含 config.yaml、output/、results.json、notes.md。统一的目录结构让实验管理更清晰。

### 练习一：创建一个训练配置文件

**思路**：设计结构化的 YAML 配置，按模块（model/lora/training/data/output）组织参数，每个参数有明确的业务语义。

**答案**：
```yaml
# config.yaml - Qwen2.5-7B LoRA 微调配置
model:
  name: "Qwen/Qwen2.5-7B"
  dtype: "float16"
  device_map: "auto"
  trust_remote_code: true

lora:
  r: 16
  alpha: 32
  target_modules: ["q_proj", "v_proj", "k_proj", "o_proj"]
  dropout: 0.05
  bias: "none"
  task_type: "CAUSAL_LM"

training:
  epochs: 3
  batch_size: 4
  gradient_accumulation: 4
  learning_rate: 2e-4
  warmup_ratio: 0.1
  weight_decay: 0.01
  max_seq_length: 2048
  fp16: true
  optim: "adamw_torch"
  gradient_checkpointing: false

data:
  path: "training_data.json"
  train_split: 0.9
  eval_split: 0.1
  max_samples: null  # null 表示使用全部数据

output:
  dir: "./output"
  save_strategy: "epoch"
  save_total_limit: 2
  logging_steps: 10
  report_to: "tensorboard"
```

```python
"""加载配置并启动训练"""
import yaml

def load_config(path: str) -> dict:
    with open(path, "r", encoding="utf-8") as f:
        return yaml.safe_load(f)

config = load_config("config.yaml")
print(f"模型: {config['model']['name']}")
print(f"LoRA rank: {config['lora']['r']}")
print(f"学习率: {config['training']['learning_rate']}")
```

**要点**：
- 配置文件应该自包含所有训练参数，代码中不出现硬编码的默认值
- `max_samples: null` 用 null 表示"使用全部"，比用 -1 或 0 更清晰
- 常见错误：配置文件只写部分参数，其他靠代码默认值，导致换环境后行为不一致

### 练习二：实现配置验证

**思路**：用 Pydantic 做类型验证 + 业务约束验证，在加载配置时就捕获错误，而不是训练到一半才报错。

**答案**：
```python
"""配置验证"""
from pydantic import BaseModel, field_validator
from typing import Optional
import yaml

class ModelConfig(BaseModel):
    name: str
    dtype: str = "float16"
    device_map: str = "auto"
    trust_remote_code: bool = True
    
    @field_validator("dtype")
    @classmethod
    def validate_dtype(cls, v):
        if v not in ["float16", "bfloat16", "float32"]:
            raise ValueError(f"dtype 必须是 float16/bfloat16/float32，收到: {v}")
        return v

class LoRAConfig(BaseModel):
    r: int
    alpha: int
    target_modules: list[str]
    dropout: float = 0.05
    bias: str = "none"
    task_type: str = "CAUSAL_LM"
    
    @field_validator("r")
    @classmethod
    def validate_r(cls, v):
        if v < 1 or v > 256:
            raise ValueError(f"LoRA rank 应在 1-256 之间，收到: {v}")
        return v
    
    @field_validator("dropout")
    @classmethod
    def validate_dropout(cls, v):
        if v < 0 or v > 1:
            raise ValueError(f"dropout 应在 0-1 之间，收到: {v}")
        return v

class TrainingConfig(BaseModel):
    epochs: int
    batch_size: int
    gradient_accumulation: int = 4
    learning_rate: float
    warmup_ratio: float = 0.1
    weight_decay: float = 0.01
    max_seq_length: int = 2048
    fp16: bool = True
    optim: str = "adamw_torch"
    gradient_checkpointing: bool = False
    
    @field_validator("learning_rate")
    @classmethod
    def validate_lr(cls, v):
        if v <= 0 or v > 1:
            raise ValueError(f"学习率应在 (0, 1] 之间，收到: {v}")
        return v
    
    @field_validator("batch_size")
    @classmethod
    def validate_batch_size(cls, v):
        if v < 1:
            raise ValueError(f"batch_size 必须 >= 1，收到: {v}")
        return v

class DataConfig(BaseModel):
    path: str
    train_split: float = 0.9
    eval_split: float = 0.1
    max_samples: Optional[int] = None

class OutputConfig(BaseModel):
    dir: str = "./output"
    save_strategy: str = "epoch"
    save_total_limit: int = 2
    logging_steps: int = 10
    report_to: str = "none"

class Config(BaseModel):
    model: ModelConfig
    lora: LoRAConfig
    training: TrainingConfig
    data: DataConfig
    output: OutputConfig

# 使用
with open("config.yaml", "r", encoding="utf-8") as f:
    raw = yaml.safe_load(f)

config = Config(**raw)
print(f"配置验证通过: {config.model.name}, lr={config.training.learning_rate}")

# 测试非法配置
try:
    bad_config = Config(**{**raw, "training": {**raw["training"], "learning_rate": -1}})
except Exception as e:
    print(f"验证失败（预期）: {e}")
```

**要点**：
- Pydantic 的 `field_validator` 可以做业务约束检查（如 lr 范围、r 的合理值），不只是类型检查
- 验证应该在训练启动前完成，而不是训练到一半才发现参数错误
- 常见错误：只用 `yaml.safe_load` 不做验证，配置文件写错参数名（如 `learing_rate`）导致静默使用默认值

### 练习三：管理多个实验配置

**思路**：用目录结构管理实验，每个实验有独立的配置和结果。支持配置模板 + 覆盖机制，以及实验结果对比功能。

**答案**：
```python
"""多实验管理"""
import os
import json
import yaml
import shutil
from datetime import datetime
from pathlib import Path

class ExperimentManager:
    def __init__(self, base_dir: str = "./experiments"):
        self.base_dir = Path(base_dir)
        self.base_dir.mkdir(exist_ok=True)
    
    def create_experiment(self, name: str, base_config_path: str, overrides: dict = None) -> str:
        """创建新实验"""
        exp_dir = self.base_dir / name
        exp_dir.mkdir(exist_ok=True)
        
        # 加载基础配置
        with open(base_config_path, "r", encoding="utf-8") as f:
            config = yaml.safe_load(f)
        
        # 应用覆盖
        if overrides:
            for key, value in overrides.items():
                keys = key.split(".")
                target = config
                for k in keys[:-1]:
                    target = target[k]
                target[keys[-1]] = value
        
        # 保存配置
        config_path = exp_dir / "config.yaml"
        with open(config_path, "w", encoding="utf-8") as f:
            yaml.dump(config, f, allow_unicode=True, default_flow_style=False)
        
        # 创建元数据
        metadata = {
            "name": name,
            "created_at": datetime.now().isoformat(),
            "base_config": base_config_path,
            "overrides": overrides or {}
        }
        with open(exp_dir / "metadata.json", "w", encoding="utf-8") as f:
            json.dump(metadata, f, ensure_ascii=False, indent=2)
        
        print(f"实验已创建: {exp_dir}")
        return str(exp_dir)
    
    def list_experiments(self) -> list[dict]:
        """列出所有实验"""
        experiments = []
        for exp_dir in sorted(self.base_dir.iterdir()):
            if exp_dir.is_dir():
                metadata_path = exp_dir / "metadata.json"
                if metadata_path.exists():
                    with open(metadata_path, "r", encoding="utf-8") as f:
                        metadata = json.load(f)
                    experiments.append(metadata)
        return experiments
    
    def compare_experiments(self, names: list[str]):
        """对比实验配置"""
        configs = {}
        for name in names:
            config_path = self.base_dir / name / "config.yaml"
            if config_path.exists():
                with open(config_path, "r", encoding="utf-8") as f:
                    configs[name] = yaml.safe_load(f)
        
        # 找出差异
        print("实验配置对比：")
        print("-" * 60)
        for section in ["training", "lora"]:
            print(f"\n[{section}]")
            for key in configs[names[0]].get(section, {}):
                values = {name: cfg.get(section, {}).get(key) for name, cfg in configs.items()}
                if len(set(str(v) for v in values.values())) > 1:
                    print(f"  {key}: {values}")

# 使用
manager = ExperimentManager("./experiments")

# 创建基准实验
manager.create_experiment("exp_baseline", "config.yaml")

# 创建学习率对比实验
manager.create_experiment("exp_lr_1e4", "config.yaml", {"training.learning_rate": 1e-4})
manager.create_experiment("exp_lr_3e4", "config.yaml", {"training.learning_rate": 3e-4})

# 创建 rank 对比实验
manager.create_experiment("exp_r_8", "config.yaml", {"lora.r": 8})
manager.create_experiment("exp_r_32", "config.yaml", {"lora.r": 32})

# 列出所有实验
print("\n所有实验：")
for exp in manager.list_experiments():
    print(f"  {exp['name']} - {exp['created_at']}")

# 对比实验
manager.compare_experiments(["exp_baseline", "exp_lr_1e4", "exp_lr_3e4"])
```

**要点**：
- 每次实验的配置独立保存，不覆盖旧配置，方便回溯和对比
- 用 `overrides` 机制只覆盖需要改的参数，减少配置冗余
- 常见错误：所有实验共用一个配置文件，修改后无法追溯之前的参数
