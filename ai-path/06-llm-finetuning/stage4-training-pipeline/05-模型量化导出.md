# 05 模型量化导出——将微调模型导出为 GGUF / GPTQ 格式

> 量化让模型更小、更快，适合部署到资源受限的环境。

## 场景引入

你的微调模型合并后有 14GB（FP16），要在边缘服务器上部署，但这台服务器只有 8GB 内存，没有 GPU。直接部署肯定不行。你需要把模型量化压缩到 4GB 以下，同时尽量保持质量不下降。GGUF、GPTQ、AWQ 这么多量化格式，哪个适合你的场景？量化级别 Q4_K_M 和 Q8_0 的差距到底有多大？

---

## 学习目标

- 掌握模型量化的方法和工具
- 理解不同量化格式的特点
- 学会导出量化模型

## 一、量化方法

```
量化方法：

1. GGUF
   - 用于 llama.cpp
   - 支持多种量化级别
   - 单文件格式

2. GPTQ
   - GPU 友好
   - 推理速度快
   - 需要校准数据

3. AWQ
   - 激活感知量化
   - 质量损失小
   - GPU 友好
```

## 二、GGUF 导出

```bash
# 转换为 GGUF
python convert_hf_to_gguf.py ./merged_model --outfile model-f16.gguf

# 量化为 Q4_K_M
./llama-quantize model-f16.gguf model-q4_k_m.gguf Q4_K_M

# 量化为 Q8_0
./llama-quantize model-f16.gguf model-q8_0.gguf Q8_0
```

## 三、GPTQ 量化

```python
from transformers import AutoModelForCausalLM, GPTQConfig

# GPTQ 量化配置
gptq_config = GPTQConfig(
    bits=4,
    dataset="c4",
    group_size=128
)

# 量化模型
model = AutoModelForCausalLM.from_pretrained(
    "./merged_model",
    quantization_config=gptq_config
)

# 保存
model.save_pretrained("./model-gptq")
```

---

## 四、AWQ 量化

```python
from awq import AutoAWQForCausalLM

# 加载模型
model = AutoAWQForCausalLM.from_pretrained("./merged_model")

# 量化
model.quantize(
    tokenizer,
    quant_config={"zero_point": True, "q_group_size": 128}
)

# 保存
model.save_pretrained("./model-awq")
```

## 六、部署选择

```
部署选择：

资源充足（GPU）→ GPTQ / AWQ
资源受限（CPU）→ GGUF Q4_K_M
边缘设备 → GGUF Q2_K / Q3_K_M
质量优先 → GGUF Q8_0 / FP16
```

---

## 常见误区

1. **量化后不测试直接部署**：量化会引入精度损失，在某些任务上可能退化严重。量化后必须在目标领域做质量回归测试，确认退化在可接受范围内。

2. **所有场景都用同一种量化格式**：GGUF 适合 CPU/边缘部署，GPTQ/AWQ 适合 GPU 部署。选错量化格式可能导致推理速度慢 10 倍。

3. **量化级别选最激进的**：Q2_K 虽然最小，但在推理任务上质量损失可能超过 10%。除非是极端资源受限的场景，否则不要低于 Q4_K_M。

4. **忽略校准数据对 GPTQ 的影响**：GPTQ 量化需要校准数据，校准数据的质量和分布直接影响量化后的模型质量。用随机数据做校准效果很差。

---

## 工程建议

1. **GPU 部署首选 AWQ**：AWQ 在推理速度和质量上通常优于 GPTQ，且 vLLM 原生支持。如果你的部署环境有 GPU，优先选择 AWQ。

2. **CPU/边缘部署首选 GGUF Q4_K_M**：这是体积、速度、质量的最佳平衡点。在大多数 CPU 设备上都能流畅运行，质量损失在 2% 以内。

3. **量化前后的 benchmark 要对比**：用 MMLU 或领域测试集分别评估量化前后的模型，量化出分数差异。差异超过 3% 就需要考虑更保守的量化级别。

4. **保留 FP16 原始模型**：量化模型是部署用的，FP16 模型是"母版"。如果需要重新量化（如换了量化工具或级别），FP16 模型是必需的。

## 参考答案

### 练习一：将模型导出为 GGUF 格式

**思路**：先将 HuggingFace 模型转为 GGUF FP16 格式（母版），再按目标部署场景选择量化级别。关键是理解不同量化级别的体积和质量权衡。

**答案**：
```bash
# 完整 GGUF 导出流程

# 1. 准备：确保已合并 LoRA 权重
# merged_model/ 目录应包含完整的 HuggingFace 模型文件

# 2. 转换为 GGUF FP16
python convert_hf_to_gguf.py ./merged_model \
    --outfile ./export/model-f16.gguf \
    --outtype f16

# 3. 按场景量化
# CPU/边缘部署（推荐）
./llama-quantize ./export/model-f16.gguf ./export/model-q4_k_m.gguf Q4_K_M

# 质量优先
./llama-quantize ./export/model-f16.gguf ./export/model-q8_0.gguf Q8_0

# 极端资源受限
./llama-quantize ./export/model-f16.gguf ./export/model-q3_k_m.gguf Q3_K_M

# 4. 验证量化模型
./llama-cli -m ./export/model-q4_k_m.gguf -p "什么是合同？" -n 100

# 5. 查看文件大小对比
ls -lh ./export/*.gguf
```

**要点**：
- Q4_K_M 是大多数 CPU 部署场景的最佳选择，体积约为 FP16 的 25-30%
- 量化应该从 FP16 母版开始，不要从已经量化的格式再次量化
- 常见错误：直接从 LoRA checkpoint 转换，忘记先 merge_and_unload

### 练习二：将模型量化为 GPTQ 格式

**思路**：GPTQ 量化需要校准数据，通过在校准数据上前向传播来确定最优的量化参数。关键是选择合适的校准数据集。

**答案**：
```python
"""GPTQ 量化"""
from transformers import AutoModelForCausalLM, AutoTokenizer, GPTQConfig
import torch

model_path = "./merged_model"
output_path = "./model-gptq"

# 1. 加载 tokenizer
tokenizer = AutoTokenizer.from_pretrained(model_path, trust_remote_code=True)

# 2. 配置 GPTQ 量化
gptq_config = GPTQConfig(
    bits=4,                    # 量化位数：4-bit
    dataset="c4",              # 校准数据集：c4 是常用选择
    group_size=128,            # 量化分组大小：128 是标准值
    desc_act=True,             # 按激活值降序排列，提升质量
    damp_percent=0.01,         # 阻尼百分比，防止数值不稳定
)

# 3. 量化并加载
print("开始 GPTQ 量化（可能需要 10-30 分钟）...")
model = AutoModelForCausalLM.from_pretrained(
    model_path,
    quantization_config=gptq_config,
    device_map="auto",
    trust_remote_code=True
)

# 4. 保存量化模型
model.save_pretrained(output_path)
tokenizer.save_pretrained(output_path)
print(f"GPTQ 模型已保存到: {output_path}")

# 5. 验证
from transformers import pipeline
pipe = pipeline("text-generation", model=output_path, tokenizer=tokenizer, device_map="auto")
result = pipe("什么是合同？", max_new_tokens=100)
print(f"测试输出: {result[0]['generated_text'][:100]}...")
```

**要点**：
- 校准数据集选择很重要：`c4` 是通用选择，如果微调了特定领域，用领域数据做校准效果更好
- `group_size=128` 是标准值，更小（如 64）质量更好但速度更慢
- 常见错误：用随机数据做校准，或者 `group_size` 设太大（如 1024）导致量化质量下降

### 练习三：对比不同量化方法的效果

**思路**：用相同的测试集分别评估 FP16、GGUF Q4_K_M、GPTQ 三个版本，对比输出质量、推理速度和文件大小。

**答案**：
```python
"""量化方法对比"""
import torch
import time
import os
from transformers import AutoModelForCausalLM, AutoTokenizer, GPTQConfig

test_prompts = [
    "什么是合同？",
    "什么是违约责任？",
    "什么是诉讼时效？",
    "什么是善意取得？",
    "什么是不当得利？",
]

def benchmark_model(model_path: str, model_name: str, is_gptq: bool = False):
    """测试模型性能"""
    tokenizer = AutoTokenizer.from_pretrained(model_path, trust_remote_code=True)
    
    if is_gptq:
        model = AutoModelForCausalLM.from_pretrained(
            model_path, device_map="auto", trust_remote_code=True
        )
    else:
        model = AutoModelForCausalLM.from_pretrained(
            model_path, torch_dtype=torch.float16, device_map="auto", trust_remote_code=True
        )
    
    # 测试推理速度和质量
    total_time = 0
    total_tokens = 0
    outputs = []
    
    for prompt in test_prompts:
        inputs = tokenizer(prompt, return_tensors="pt").to(model.device)
        
        start = time.time()
        with torch.no_grad():
            output = model.generate(**inputs, max_new_tokens=100, do_sample=False)
        elapsed = time.time() - start
        
        new_tokens = output.shape[1] - inputs["input_ids"].shape[1]
        total_time += elapsed
        total_tokens += new_tokens
        outputs.append(tokenizer.decode(output[0], skip_special_tokens=True))
    
    # 计算模型大小
    if os.path.isdir(model_path):
        size_gb = sum(
            os.path.getsize(os.path.join(model_path, f))
            for f in os.listdir(model_path)
            if f.endswith(('.bin', '.safetensors', '.gguf'))
        ) / 1024**3
    else:
        size_gb = os.path.getsize(model_path) / 1024**3
    
    return {
        "name": model_name,
        "size_gb": size_gb,
        "tokens_per_sec": total_tokens / total_time,
        "outputs": outputs
    }

# 对比测试
print("量化方法对比测试")
print("=" * 70)

results = []
results.append(benchmark_model("./merged_model", "FP16"))
results.append(benchmark_model("./model-gptq", "GPTQ-4bit", is_gptq=True))
# GGUF 需要用 llama.cpp 测试，这里只对比 HuggingFace 格式

# 打印对比表
print(f"\n{'方法':<15} {'大小(GB)':<12} {'速度(tokens/s)':<15}")
print("-" * 50)
for r in results:
    print(f"{r['name']:<15} {r['size_gb']:<12.1f} {r['tokens_per_sec']:<15.1f}")

print("\n质量对比（第一个测试用例）：")
for r in results:
    print(f"  [{r['name']}] {r['outputs'][0][:100]}...")

print("\n结论：")
print("  - FP16：质量最好，体积最大，适合 GPU 部署")
print("  - GPTQ-4bit：质量接近 FP16，推理最快，GPU 部署首选")
print("  - GGUF Q4_K_M：质量好，支持 CPU 部署，边缘设备首选")
```

**要点**：
- 对比必须用相同的测试用例和相同的评估指标（速度、质量、体积）
- 质量评估不能只看一个用例，至少 5-10 个才能有统计意义
- 常见错误：只对比体积和速度，忽略质量差异；或者用主观判断代替量化指标
