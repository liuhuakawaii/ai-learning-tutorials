# 04 模型合并——LoRA 权重与基础模型的合并导出

> 训练完成后，需要将 LoRA 权重合并到基础模型中。

## 场景引入

微调训练完成了，output 目录里有一堆 checkpoint 文件。你想用这个微调模型做推理，但加载时发现必须同时加载基座模型和 LoRA 权重，推理速度比原始模型慢了 20%。更麻烦的是，很多部署工具（如 Ollama、llama.cpp）根本不支持直接加载 LoRA 权重。你需要把 LoRA 权重合并到基础模型中，导出一个独立的、可以直接部署的模型文件。

---

- 掌握 LoRA 权重的合并方法

## 一、模型合并

```python
from peft import PeftModel
from transformers import AutoModelForCausalLM

# 加载基础模型
base_model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-7B",
    torch_dtype=torch.float16
)

# 加载 LoRA 权重
model = PeftModel.from_pretrained(
    base_model,
    "./output/checkpoint-1000"
)

# 合并权重
merged_model = model.merge_and_unload()

# 保存合并后的模型
merged_model.save_pretrained("./merged_model")
```

```
   - 最常用
   - 支持 Transformers
   - 目录结构：
     ├── config.json
     ├── pytorch_model.bin
     ├── tokenizer.json
     └── tokenizer_config.json

2. GGUF 格式
   - 用于 llama.cpp
   - 支持量化
   - 单文件

3. ONNX 格式
   - 跨平台
   - 推理优化
   - 需要转换
```

## 常见误区

1. **合并后不做推理测试**：合并操作可能因为精度问题导致模型输出异常。合并后必须用相同的测试用例验证效果，确保和合并前一致。

2. **直接用合并前的 tokenizer**：合并后的模型目录应该包含完整的 tokenizer 文件。如果 tokenizer 和模型不匹配，推理时会输出乱码。

3. **保留太多 checkpoint 浪费磁盘**：checkpoint 文件每个都有几 GB，保留太多会占满磁盘。用 `save_total_limit=2` 只保留最近的 2 个 checkpoint。

4. **合并时精度不匹配**：基座模型用 float16 加载，但 LoRA 权重是 float32 训练的，合并时可能出现精度问题。统一用 float16 加载和合并。

---

## 工程建议

1. **合并是部署的必经步骤**：无论是用 vLLM、Ollama 还是其他部署工具，都应该先合并 LoRA 权重。合并后的模型推理无额外开销，兼容性最好。

2. **合并后做量化测试**：合并后的模型如果需要量化部署（GGUF/GPTQ/AWQ），先量化再测试效果，确认量化后质量可接受。

3. **保留 LoRA 权重作为备份**：合并后不要删除 LoRA 权重文件。如果需要重新合并（如换了基座模型版本），LoRA 权重是必需的。

4. **模型版本管理用语义化版本号**：`v1.0.0`（初始版本）、`v1.1.0`（数据更新）、`v1.1.1`（bug 修复），让团队成员一目了然地知道模型的变化。

## 参考答案

### 练习一：将 LoRA 权重合并到基础模型

**思路**：加载基座模型 → 加载 LoRA 权重 → merge_and_unload → 保存。关键是加载时统一用 float16 精度，避免合并时精度不匹配。

**答案**：
```python
"""LoRA 权重合并"""
import torch
from peft import PeftModel
from transformers import AutoModelForCausalLM, AutoTokenizer

# 1. 加载基座模型（必须和训练时用的一致）
model_name = "Qwen/Qwen2.5-7B"
base_model = AutoModelForCausalLM.from_pretrained(
    model_name,
    torch_dtype=torch.float16,   # 统一用 float16
    device_map="auto",
    trust_remote_code=True
)

# 2. 加载 LoRA 权重
lora_path = "./output/final"  # 或某个 checkpoint 目录
model = PeftModel.from_pretrained(base_model, lora_path)

# 3. 合并权重
merged_model = model.merge_and_unload()

# 4. 保存合并后的模型
output_dir = "./merged_model"
merged_model.save_pretrained(output_dir)

# 5. 保存 tokenizer（很重要！）
tokenizer = AutoTokenizer.from_pretrained(model_name)
tokenizer.save_pretrained(output_dir)

print(f"合并模型已保存到: {output_dir}")

# 6. 验证文件完整性
import os
expected_files = ["config.json", "model.safetensors", "tokenizer.json", "tokenizer_config.json"]
for f in expected_files:
    path = os.path.join(output_dir, f)
    exists = os.path.exists(path)
    print(f"  {f}: {'✓' if exists else '✗ 缺失'}")
```

**要点**：
- 基座模型必须和训练时用的完全一致（同名同版本），否则合并会出错或效果异常
- 合并后必须保存 tokenizer，否则部署时无法正确分词
- 常见错误：合并后不保存 tokenizer，推理时加载其他 tokenizer 导致输出乱码

### 练习二：将模型导出为 GGUF 格式

**思路**：先转换为 GGUF 的 FP16 格式，再按需量化为 Q4_K_M 等压缩格式。关键是理解各量化级别的适用场景。

**答案**：
```bash
# 1. 克隆 llama.cpp（包含转换工具）
git clone https://github.com/ggerganov/llama.cpp.git
cd llama.cpp

# 2. 转换为 GGUF FP16 格式
python convert_hf_to_gguf.py ../merged_model --outfile model-f16.gguf --outtype f16

# 3. 量化为不同级别
# Q4_K_M：体积小，质量好，CPU 部署首选
./llama-quantize model-f16.gguf model-q4_k_m.gguf Q4_K_M

# Q8_0：质量最好，体积较大
./llama-quantize model-f16.gguf model-q8_0.gguf Q8_0

# Q5_K_M：平衡选择
./llama-quantize model-f16.gguf model-q5_k_m.gguf Q5_K_M

# 4. 查看文件大小
ls -lh model-*.gguf
```

```python
"""用 Python 脚本管理导出"""
import subprocess
import os

def export_to_gguf(merged_model_path: str, output_dir: str, quant_levels: list[str]):
    """批量导出 GGUF"""
    os.makedirs(output_dir, exist_ok=True)
    
    # 转换 FP16
    f16_path = os.path.join(output_dir, "model-f16.gguf")
    subprocess.run([
        "python", "convert_hf_to_gguf.py",
        merged_model_path,
        "--outfile", f16_path,
        "--outtype", "f16"
    ], check=True)
    
    # 量化
    for level in quant_levels:
        out_path = os.path.join(output_dir, f"model-{level.lower()}.gguf")
        subprocess.run([
            "./llama-quantize", f16_path, out_path, level
        ], check=True)
        size = os.path.getsize(out_path) / 1024**3
        print(f"  {level}: {size:.1f} GB")

# 使用
export_to_gguf("./merged_model", "./gguf_models", ["Q4_K_M", "Q8_0"])
```

**要点**：
- Q4_K_M 是 CPU/边缘部署的最佳平衡点（体积、速度、质量）
- FP16 GGUF 是"母版"，量化后如果需要换级别，从 FP16 重新量化，不要从 Q4 再量化
- 常见错误：直接从 LoRA checkpoint 转换 GGUF，忘记先合并权重

### 练习三：测试合并后的模型效果

**思路**：用相同的测试用例分别测试基座模型、LoRA 模型（合并前）、合并后模型，确认合并操作没有引入质量退化。

**答案**：
```python
"""合并后模型效果验证"""
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, pipeline
from peft import PeftModel

model_name = "Qwen/Qwen2.5-7B"
tokenizer = AutoTokenizer.from_pretrained(model_name, trust_remote_code=True)

# 测试用例
test_cases = [
    {"question": "什么是合同？", "keywords": ["协议", "民事", "设立"]},
    {"question": "什么是违约责任？", "keywords": ["不履行", "义务", "民事责任"]},
    {"question": "什么是诉讼时效？", "keywords": ["三年", "权利", "法院"]},
]

def test_model(model, model_name: str):
    """测试模型并评分"""
    print(f"\n测试 {model_name}:")
    print("-" * 50)
    
    for case in test_cases:
        inputs = tokenizer(case["question"], return_tensors="pt").to(model.device)
        with torch.no_grad():
            outputs = model.generate(**inputs, max_new_tokens=200, do_sample=False)
        answer = tokenizer.decode(outputs[0], skip_special_tokens=True)
        
        # 检查关键词命中
        hits = sum(1 for kw in case["keywords"] if kw in answer)
        score = hits / len(case["keywords"]) * 100
        
        print(f"Q: {case['question']}")
        print(f"A: {answer[:150]}...")
        print(f"关键词命中: {hits}/{len(case['keywords'])} ({score:.0f}%)")
        print()

# 1. 测试基座模型
base_model = AutoModelForCausalLM.from_pretrained(model_name, torch_dtype=torch.float16, device_map="auto")
test_model(base_model, "基座模型")
del base_model

# 2. 测试合并后模型
merged_model = AutoModelForCausalLM.from_pretrained("./merged_model", torch_dtype=torch.float16, device_map="auto")
test_model(merged_model, "合并后模型")

# 3. 对比结论
print("=" * 50)
print("对比结论：")
print("  - 合并后模型应保留微调学到的领域知识")
print("  - 合并操作不应引入质量退化")
print("  - 如果关键词命中率下降 > 10%，说明合并可能有问题")
```

**要点**：
- 测试用例必须包含领域内问题（验证微调效果）和通用问题（验证没有灾难性遗忘）
- 用 `do_sample=False` 确保测试结果可复现，不受随机采样影响
- 常见错误：只用一个测试用例验证，偶然性太大；或者只测领域问题不测通用问题，忽略灾难性遗忘
