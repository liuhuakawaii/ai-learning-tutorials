# 01 什么时候该微调——Prompt Engineering、RAG、Fine-tuning 的真实边界

> 不是所有问题都需要微调。选错方法就是白费力气。

你的老板说："这个通用大模型回答我们公司的产品问题总是胡说八道，微调一下就好了。"

你花了一周准备数据、租了 GPU、跑完微调，结果发现效果还不如在 Prompt 里加几句产品说明。

问题出在哪？不是微调本身有问题，而是你选错了方法。

---

## 三种方法，解决不同的问题

**Prompt Engineering**：通过提示词引导模型行为。
- 成本最低，改几行文字就行
- 效果有限——你没法让模型"学会"它不知道的东西
- 适合：调整输出格式、改变回答风格、添加约束条件

**RAG（检索增强生成）**：把外部知识塞进上下文。
- 成本中等，需要构建知识库
- 效果好——模型可以访问最新信息
- 适合：知识问答、文档检索、私有数据查询

**Fine-tuning（微调）**：用领域数据训练模型。
- 成本最高，需要数据和计算资源
- 效果好——可以改变模型的行为方式
- 适合：特定领域、特定风格、特定任务

关键区别：Prompt 管"怎么问"，RAG 管"给它看什么"，Fine-tuning 管"它变成什么"。

---

## 一个选错方法的真实案例

**场景**：公司要做一个客服机器人，能回答产品问题、处理退换货、保持品牌语气。

**错误做法**：直接微调。
- 花了一周准备数据
- 租了 GPU 跑训练
- 结果：模型学会了品牌语气，但产品信息还是错的（因为产品信息会更新，微调的知识是静态的）

**正确做法**：分阶段。

第一阶段（MVP，1-2 周）：
- Prompt Engineering：定义客服角色和回答规范
- RAG：接入产品知识库
- 成本低，快速验证需求

第二阶段（优化，第一阶段准确率 < 80% 时才进入）：
- Fine-tuning：用历史客服对话数据微调模型，学习品牌语气
- 保持 RAG 接入最新产品信息

---

## 决策树

```
你的需求是什么？
├── 调整输出格式/风格/约束 → Prompt Engineering
│   改 Prompt 就能解决，不需要训练
│
├── 需要访问最新/私有/专业知识 → RAG
│   产品信息会更新，微调的知识是静态的
│
├── 需要改变模型的行为方式 → Fine-tuning
│   比如：让模型学会特定的输出格式、专业术语、回答风格
│
└── 以上都需要 → 组合使用
    微调管"怎么说"，RAG 管"说什么"，Prompt 管"输出什么格式"
```

---

## 微调真正能改变什么

很多人对微调有误解。微调能做到的：

- 让模型稳定输出 JSON 格式（Prompt 也能做，但微调更稳定）
- 让模型学会特定的语气和风格（正式、口语、专业）
- 让模型在特定任务上准确率提升（如情感分类、实体提取）
- 让模型学会使用特定的工具调用格式

微调做不到的：

- 注入新知识（产品信息、最新新闻）→ 用 RAG
- 让小模型变成大模型（7B 微调不出 GPT-4 的能力）
- 解决模型的推理能力不足 → 这是模型本身的能力边界

## 组合使用的例子

```python
# 一个代码审查助手的架构
# Fine-tuning：学会代码审查的专业风格
# RAG：检索项目的编码规范和历史审查记录
# Prompt：控制输出格式和审查维度

class CodeReviewAssistant:
    def __init__(self, finetuned_model, knowledge_base):
        self.model = finetuned_model
        self.kb = knowledge_base

    def review(self, code: str, language: str) -> dict:
        # RAG：检索相关规范
        standards = self.kb.search(f"{language} coding standards")

        # Prompt：构造审查指令
        prompt = f"""请审查以下 {language} 代码。

项目编码规范：
{standards}

审查维度：
1. 潜在 Bug 和安全问题
2. 性能优化建议
3. 是否符合项目规范

代码：
```{language}
{code}
```

请以 JSON 格式输出审查结果。"""

        # Fine-tuned 模型生成审查意见
        return self.model.generate(prompt)
```

微调管"怎么说"（输出专业、结构化的审查意见），RAG 管"说什么"（符合项目规范），Prompt 管"输出什么格式"（JSON）。

## 量化微调的 ROI

微调不是免费的。在决定微调前，想清楚：

| 维度 | Prompt | RAG | Fine-tuning |
|------|--------|-----|-------------|
| 开发时间 | 1 小时 | 1-2 天 | 1-2 周 |
| 维护成本 | 低 | 中 | 高（数据更新需要重训） |
| 效果提升 | 有限 | 好 | 很好 |
| 灵活性 | 高 | 中 | 低 |

如果 Prompt + RAG 能达到 85% 的准确率，而微调能达到 92%，但微调需要两周时间和持续维护——值不值得？看业务场景。客服机器人可能够了，医疗诊断可能不够。

---

## 容易犯的错

**遇到效果不好就想微调**。先试 Prompt 优化，再试 RAG，最后才考虑微调。很多"效果不好"是 Prompt 写得不好，不是模型不行。

**认为微调能让模型"学会新知识"**。微调主要调整行为方式，不是注入知识。需要最新信息，用 RAG。

**只考虑效果不考虑维护成本**。微调需要持续维护——数据更新、模型重训、版本管理。如果团队没有持续投入的能力，RAG 更可持续。

**在需求还不明确时就做微调**。需求变化后微调模型需要重训。先用低成本方案验证需求。

### 练习二：Prompt vs RAG 对比

在同一个任务上分别用 Prompt Engineering 和 RAG 测试效果：

```python
from openai import OpenAI
client = OpenAI(base_url="http://localhost:11434/v1", api_key="not-needed")

test_text = "这款手机拍照很清晰，但电池续航太差了，用半天就没电。"

# 方法 1：纯 Prompt
prompt_v1 = f"对以下文本做情感分析，输出 JSON：{test_text}"
resp1 = client.chat.completions.create(
    model="qwen2.5:7b",
    messages=[{"role": "user", "content": prompt1}],
    response_format={"type": "json_object"},
)

# 方法 2：Prompt + Few-shot（模拟 RAG 的效果）
examples = [
    {"text": "屏幕显示效果很好，但系统经常卡顿",
     "output": {"sentiment": "mixed", "aspects": [{"aspect": "屏幕", "sentiment": "positive"}, {"aspect": "系统", "sentiment": "negative"}]}}
]
prompt_v2 = f"""参考以下情感分析案例：
{json.dumps(examples, ensure_ascii=False)}

请对以下文本进行同样的情感分析：
{test_text}"""
resp2 = client.chat.completions.create(
    model="qwen2.5:7b",
    messages=[{"role": "user", "content": prompt2}],
)

print("纯 Prompt:", resp1.choices[0].message.content)
print("Prompt + Few-shot:", resp2.choices[0].message.content)
```

对比：格式稳定性、准确率、输出质量。

## 参考答案

### 练习一

1. **固定 JSON 格式情感分析**：Prompt Engineering
   - 用 `response_format={"type": "json_object"}` 强制 JSON 输出
   - 如果格式不稳定，再考虑微调

2. **每周更新的技术文档**：RAG
   - 文档会更新，微调的知识是静态的
   - 用向量数据库存储文档，查询时检索相关段落

3. **公司特有的 API 调用格式**：Fine-tuning
   - API 格式是固定的行为模式，不是会变化的知识
   - 微调能让模型稳定输出正确的调用格式

### 练习二

预期结果：
- 纯 Prompt 可能输出非标准 JSON，或字段缺失
- Prompt + Few-shot 格式更稳定，因为模型有了参考样例
- 如果效果还是不够好，才需要微调

### 练习三

参考架构：
```
用户问题 → [Prompt: 意图识别] → 分类
├── 知识查询 → [RAG: 检索文档] → [Prompt: 生成回答]
├── 流程指引 → [Prompt: 模板匹配]
└── 专业术语解释 → [Fine-tuned 模型: 领域问答]
```

如果文档更新频率变成每小时：
- RAG 层需要支持增量更新（向量索引实时刷新）
- 不需要改微调模型（微调管的是回答风格，不是文档内容）
