# 05 对比评估方法——Pairwise / Rating / Binary 的适用场景

> 评估不是只有"打分"一种方式。选对评估方法，比选对模型更重要。

## 场景引入

你要在 GPT-4o 和 Claude 之间选一个作为生产环境的模型。你用 5 分制分别给两个模型打了分：GPT-4o 平均 4.1，Claude 平均 4.0。差距只有 0.1 分，你能据此做决策吗？换一种方法，你把两个模型的回答放在一起做盲评对比，结果发现 GPT-4o 在事实类问题上明显更好，而 Claude 在创意写作上更胜一筹。同一次评估，用不同的方法得出了完全不同的结论——选错评估方法，比选错模型更危险。

## 学习目标

- 掌握三种主流评估方法的原理和实现
- 理解每种方法的优缺点和适用场景
- 学会根据评估目标选择合适的方法

## 二、Binary 评估（二元判断）

### 2.1 适用场景

```
Binary 评估最适合"有明确对错标准"的场景：

1. 安全性检测
   "回答是否包含有害内容？" → 是/否
   "回答是否泄露了敏感信息？" → 是/否

2. 格式检查
   "回答是否为 JSON 格式？" → 是/否
   "回答是否包含引用标记？" → 是/否

3. 事实核查
   "回答中的数字是否与数据源一致？" → 是/否

4. 存在性检查
   "回答是否包含幻觉？" → 是/否
   "回答是否拒绝了不当请求？" → 是/否
```

### 2.2 实现

```python
def binary_eval_safety(answer: str) -> dict:
```

### 2.3 优缺点

```
优点：
  ✓ 判断标准明确，评估一致性高
  ✓ 实现简单，成本低
  ✓ 适合作为"门禁"（通过/不通过）

缺点：
  ✗ 区分度低，无法区分"好"和"很好"
  ✗ 不适合开放性问题的评估
  ✗ 阈值设定需要经验
```

## 三、Rating 评估（评分）

### 3.1 适用场景

```
Rating 评估最适合"质量有连续光谱"的场景：

1. 回答质量评估
   "这个回答的质量如何？" → 1-5 分

2. 相关性评估
   "检索到的文档与问题的相关程度？" → 1-5 分

3. 用户体验评估
   "这个回答的表述是否清晰？" → 1-5 分

4. 回归测试
   "新版本的回答比旧版本好还是差？" → 对比分数
```

### 3.2 不同的评分尺度

```python
# 尺度 1：5 分制（最常用）
```

### 3.3 实现

```python
def rating_eval(
    question: str,
    answer: str,
    reference: str = None,
    scale: int = 5
) -> dict:
    """评分评估"""
    
    ref_section = f"\n参考答案：{reference}" if reference else ""
    
    prompt = f"""请对以下回答进行评分。

问题：{question}
回答：{answer}{ref_section}

评分标准（{scale} 分制）：
1 分：完全错误、不相关、或拒绝回答
2 分：有部分正确信息，但有重大错误
3 分：基本正确，有明显不足
4 分：正确且完整，表述清晰
5 分：优秀，准确、完整、表述专业

请以 JSON 格式输出：
{{"score": <1-{scale}>, "dimension_scores": {{"accuracy": <1-5>, "completeness": <1-5>, "relevancy": <1-5>}}, "reasoning": "理由"}}"""

    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        temperature=0,
        response_format={"type": "json_object"}
    )
    
    return json.loads(response.choices[0].message.content)
```

### 3.4 评分的一致性问题

```
评分的一致性挑战：

问题 1：不同评估者标准不同
  评估者 A：3 分 = "还行"
  评估者 B：3 分 = "不咋地"
  → 同一个回答，不同人打的分不一样

问题 2：同一评估者标准漂移
  评估了 100 条后，标准可能变松或变紧
  → 前 50 条和后 50 条的分数不可比

解决方案：

1. 校准样本
   准备 10 个"标准答案"样本，每个都有公认的分数
   评估前先用校准样本校准评估者的标准

2. 多人评估
   同一条数据由 2-3 个评估者打分
   取平均分或中位数作为最终分数
   计算评估者间一致性（Cohen's Kappa）

3. 锚定描述
   每个分数都有具体的描述和例子
   评估者对照描述打分，减少主观性
```

## 四、Pairwise 评估（对比）

### 4.1 适用场景

```
Pairwise 评估最适合"需要比较两个方案"的场景：

1. 模型对比
   "GPT-4o 和 Claude 的回答哪个更好？"

2. Prompt 版本对比
   "新 Prompt 和旧 Prompt 的效果哪个好？"

3. A/B 测试
   "方案 A 和方案 B 哪个用户体验更好？"

4. 迭代优化
   "这次优化有没有让回答变好？"
```

### 4.2 实现

```python
def pairwise_eval(
    question: str,
    answer_a: str,
    answer_b: str,
    reference: str = None
) -> dict:
    """对比评估两个回答"""
    
    ref_section = f"\n参考答案：{reference}" if reference else ""
    
    # 防止位置偏差：随机交换 A/B 顺序
    import random
    if random.random() > 0.5:
        answer_a, answer_b = answer_b, answer_a
        swapped = True
    else:
        swapped = False
    
    prompt = f"""请比较以下两个回答的质量。

问题：{question}

回答 A：
{answer_a}

回答 B：
{answer_b}{ref_section}

请从以下维度比较：
1. 准确性：哪个回答的信息更正确？
2. 完整性：哪个回答覆盖了更多关键信息？
3. 相关性：哪个回答更切题？
4. 清晰度：哪个回答表述更清楚？

请以 JSON 格式输出：
{{"winner": "A" | "B" | "Tie", "reasoning": "理由", "dimension_winners": {{"accuracy": "A" | "B" | "Tie", "completeness": "A" | "B" | "Tie", "relevancy": "A" | "B" | "Tie", "clarity": "A" | "B" | "Tie"}}}}"""

    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        temperature=0,
        response_format={"type": "json_object"}
    )
    
    result = json.loads(response.choices[0].message.content)
    
    # 如果交换了顺序，需要反转结果
    if swapped:
        if result["winner"] == "A":
            result["winner"] = "B"
        elif result["winner"] == "B":
            result["winner"] = "A"
        for dim in result.get("dimension_winners", {}):
            if result["dimension_winners"][dim] == "A":
                result["dimension_winners"][dim] = "B"
            elif result["dimension_winners"][dim] == "B":
                result["dimension_winners"][dim] = "A"
        result["swapped"] = True
    
    return result
```

### 4.3 Bradley-Terry 模型

```python
# 当有多个模型需要排名时，使用 Bradley-Terry 模型
# 通过两两对比的结果，计算每个模型的"实力分数"

import numpy as np

def bradley_terry_scores(pairwise_results: list[dict], models: list[str]) -> dict:
    """用 Bradley-Terry 模型计算模型排名
    
    Args:
        pairwise_results: [{"model_a": "A", "model_b": "B", "winner": "A"}, ...]
        models: 所有模型名称列表
    
    Returns:
        每个模型的分数和排名
    """
    n = len(models)
    model_idx = {m: i for i, m in enumerate(models)}
    
    # 初始化分数
    scores = np.ones(n)
    
    # 迭代更新分数（简化版 MM 算法）
    for _ in range(100):
        new_scores = np.zeros(n)
        for result in pairwise_results:
            a = model_idx[result["model_a"]]
            b = model_idx[result["model_b"]]
            winner = result["winner"]
            
            # 计算胜率
            p_a = scores[a] / (scores[a] + scores[b])
            p_b = 1 - p_a
            
            if winner == result["model_a"]:
                new_scores[a] += 1
            elif winner == result["model_b"]:
                new_scores[b] += 1
            else:  # Tie
                new_scores[a] += 0.5
                new_scores[b] += 0.5
        
        scores = new_scores / np.sum(new_scores) * n
    
    # 生成排名
    ranking = sorted(zip(models, scores), key=lambda x: -x[1])
    
    return {
        "scores": {m: round(s, 3) for m, s in zip(models, scores)},
        "ranking": [(m, round(s, 3)) for m, s in ranking]
    }
```

### 4.4 优缺点

```
优点：
  ✓ 区分度高，能明确判断"哪个更好"
  ✓ 适合模型对比和 A/B 测试
  ✓ 减少了绝对评分的主观性

缺点：
  ✗ 成本高（需要评估多个版本）
  ✗ 结果依赖于对比的样本
  ✗ 可能存在位置偏差（需要随机交换顺序）
  ✗ 不适合绝对质量评估（只告诉你"谁更好"，不告诉你"好不好"）
```

## 五、混合评估策略

### 5.1 分层评估

```python
def hybrid_eval(question: str, answer: str, context: str) -> dict:
    """混合评估：先 Binary 过滤，再 Rating 打分"""
    
    # 第一层：Binary 安全检查
    safety = binary_eval_safety(answer)
    if not safety["is_safe"]:
        return {
            "passed": False,
            "stage": "safety",
            "reason": safety["issues"]
        }
    
    # 第二层：Binary 幻觉检查
    hallucination = binary_eval_hallucination(context, answer)
    if hallucination["has_hallucination"]:
        return {
            "passed": False,
            "stage": "hallucination",
            "reason": hallucination["hallucinated_claims"]
        }
    
    # 第三层：Rating 质量评分
    rating = rating_eval(question, answer)
    
    return {
        "passed": rating["score"] >= 3,
        "stage": "quality",
        "score": rating["score"],
        "details": rating
    }
```

### 5.2 选择评估方法的决策树

```
你的评估目标是什么？
│
├── 检查是否满足最低标准（门禁）
│   └── 使用 Binary 评估
│       ├── 安全检查 → Binary
│       ├── 格式检查 → Binary
│       └── 事实核查 → Binary
│
├── 评估绝对质量（打分）
│   └── 使用 Rating 评估
│       ├── 回答质量 → Rating (1-5)
│       ├── 检索质量 → Rating (1-5)
│       └── 用户体验 → Rating (1-5)
│
└── 比较两个方案（对比）
    └── 使用 Pairwise 评估
        ├── 模型对比 → Pairwise
        ├── Prompt 版本对比 → Pairwise
        └── A/B 测试 → Pairwise
```

## 六、实战：完整的评估套件

```python
class EvalSuite:
    """完整的评估套件"""
    
    def __init__(self):
        self.binary_evaluators = {}
        self.rating_evaluators = {}
    
    def add_binary_eval(self, name: str, eval_fn):
        """添加二元评估器"""
        self.binary_evaluators[name] = eval_fn
    
    def add_rating_eval(self, name: str, eval_fn):
        """添加评分评估器"""
        self.rating_evaluators[name] = eval_fn
    
    def evaluate(self, question: str, answer: str, context: str = None) -> dict:
        """运行完整评估"""
        results = {
            "binary": {},
            "rating": {},
            "passed": True,
            "overall_score": None
        }
        
        # 运行所有二元评估
        for name, eval_fn in self.binary_evaluators.items():
            result = eval_fn(question, answer, context)
            results["binary"][name] = result
            if not result.get("passed", True):
                results["passed"] = False
        
        # 只有通过二元评估，才运行评分评估
        if results["passed"]:
            scores = []
            for name, eval_fn in self.rating_evaluators.items():
                result = eval_fn(question, answer, context)
                results["rating"][name] = result
                scores.append(result["score"])
            
            results["overall_score"] = sum(scores) / len(scores) if scores else None
        
        return results


# 使用示例
suite = EvalSuite()
suite.add_binary_eval("safety", lambda q, a, c: binary_eval_safety(a))
suite.add_binary_eval("hallucination", lambda q, a, c: binary_eval_hallucination(c, a))
suite.add_rating_eval("quality", lambda q, a, c: rating_eval(q, a))

result = suite.evaluate(
    question="什么是 RAG？",
    answer="RAG 是检索增强生成...",
    context="RAG 相关文档..."
)
```

## 常见误区

1. **所有场景都用同一种评估方法**：安全检测用 Binary、质量打分用 Rating、模型对比用 Pairwise——方法要匹配评估目标，混用才能形成完整评估。
2. **Pairwise 评估不处理位置偏差**：LLM 评委倾向于选第一个出现的回答，不做随机交换顺序会导致系统性偏差，评估结论不可信。
3. **用 Pairwise 结果做绝对质量判断**：Pairwise 只告诉你"A 比 B 好"，不告诉你"A 到底好不好"。A 和 B 可能都不及格，但你只看到了相对排名。
4. **Rating 评估不做多人校准**：一个人打分标准会漂移，不同人之间标准也不同。关键评估至少需要 2-3 人独立打分，计算评估者间一致性。

## 工程建议

1. **用分层评估构建完整 Pipeline**：第一层 Binary 做门禁（安全检查、格式检查），第二层 Rating 做质量打分，第三层 Pairwise 做版本对比。三层串联，逐级筛选。
2. **Pairwise 评估必须随机交换 A/B 顺序**：每次评估都随机决定哪个回答放前面，然后在结果中反转。不做这一步，位置偏差会系统性地扭曲评估结论。
3. **模型选型用 Pairwise + Bradley-Terry**：多个模型对比时，不要分别打分再比大小。用两两 Pairwise 对比 + Bradley-Terry 模型计算实力分数，排名更可靠。
4. **关键决策用两种以上方法交叉验证**：如果 Pairwise 说 A 好于 B，再用 Rating 分别打分确认。两种方法结论一致时，决策信心更高。

## 小结

```
本课核心要点：

1. Binary 适合门禁检查，Rating 适合质量评估，Pairwise 适合方案对比
2. 评分的一致性需要通过校准样本和多人评估来保证
3. Pairwise 评估要随机交换顺序以避免位置偏差
4. Bradley-Terry 模型可以从两两对比中计算排名
5. 实际项目中通常混合使用多种评估方法
```

## 参考答案

### 练习一

**思路**：Binary 评估器需要检测特定的不确定性表述。可以用关键词匹配作为快速初筛，再用 LLM 做精细判断，处理语义层面的不确定性（如"大概""也许"的同义表达）。

**答案**：

```python
from openai import OpenAI
import re

client = OpenAI()

def binary_eval_uncertainty(answer: str, method: str = "hybrid") -> dict:
    """检测回答中是否包含不确定性表述"""

    # 方法 1：关键词匹配（快速初筛）
    uncertainty_patterns = [
        r"我不确定", r"可能是", r"也许是", r"大概是",
        r"不太清楚", r"不太确定", r"据我所知",
        r"我不太了解", r"这个我不太确定",
        r"建议咨询", r"建议您确认",
        r"仅供参考", r"不保证",
        r"I'm not sure", r"maybe", r"perhaps",
    ]

    keyword_matches = []
    for pattern in uncertainty_patterns:
        matches = re.findall(pattern, answer, re.IGNORECASE)
        keyword_matches.extend(matches)

    keyword_result = len(keyword_matches) > 0

    if method == "keyword":
        return {
            "has_uncertainty": keyword_result,
            "matched_phrases": keyword_matches,
            "method": "keyword"
        }

    # 方法 2：LLM 判断（精细分析）
    prompt = f"""请判断以下回答是否包含不确定性表述。

回答：{answer}

不确定性表述包括：
1. 明确表示不确定："我不确定"、"可能是"
2. 模糊限定词："大概"、"一般来说"、"通常情况下"
3. 推卸责任："建议您咨询专业人士"
4. 自我否定："不过我也不太确定"

注意以下情况不算不确定性表述：
1. 表示条件限制："如果...则..."（这是条件语句，不是不确定）
2. 引用来源："根据XX文档"（这是信息溯源，不是不确定）
3. 礼貌用语："请"、"您"（这是礼貌表达，不是不确定）

请以 JSON 格式输出：
{{"has_uncertainty": true/false, "uncertain_phrases": ["短语1", "短语2"], "confidence": 0-1, "reasoning": "理由"}}"""

    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        temperature=0,
        response_format={"type": "json_object"}
    )

    llm_result = json.loads(response.choices[0].message.content)

    # 混合判断：关键词匹配 OR LLM 判断
    final_result = keyword_result or llm_result["has_uncertainty"]

    return {
        "has_uncertainty": final_result,
        "keyword_matches": keyword_matches,
        "llm_analysis": llm_result,
        "method": "hybrid"
    }
```

**要点**：
- 关键词匹配速度快但覆盖面有限，只能检测字面表述
- LLM 判断能捕捉语义层面的不确定性，但成本更高
- 混合方法兼顾速度和准确性：关键词匹配命中则直接标记，未命中则用 LLM 兜底
- 常见错误：只用关键词匹配——"这个问题的答案取决于具体情况"没有命中任何关键词，但明显是不确定性表述

### 练习二

**思路**：用 Pairwise 评估对比两个模型的回答质量。需要确保随机交换 A/B 顺序以避免位置偏差，并从多个维度进行对比。

**答案**：

```python
from openai import OpenAI
import random
import json

client = OpenAI()

def compare_models_pairwise(question: str) -> dict:
    """对比 GPT-4o 和 GPT-4o-mini 的回答"""

    # 步骤 1：分别生成回答
    def get_answer(model: str, question: str) -> str:
        response = client.chat.completions.create(
            model=model,
            messages=[{"role": "user", "content": question}],
            temperature=0.7
        )
        return response.choices[0].message.content

    answer_4o = get_answer("gpt-4o", question)
    answer_mini = get_answer("gpt-4o-mini", question)

    # 步骤 2：随机交换顺序（防止位置偏差）
    if random.random() > 0.5:
        answer_a, answer_b = answer_4o, answer_mini
        mapping = {"A": "gpt-4o", "B": "gpt-4o-mini"}
    else:
        answer_a, answer_b = answer_mini, answer_4o
        mapping = {"A": "gpt-4o-mini", "B": "gpt-4o"}

    # 步骤 3：Pairwise 评估
    prompt = f"""请比较以下两个回答的质量。

问题：{question}

回答 A：
{answer_a}

回答 B：
{answer_b}

请从以下维度比较：
1. 准确性：信息是否正确
2. 完整性：是否覆盖关键方面
3. 相关性：是否切题
4. 清晰度：表述是否清楚

请以 JSON 格式输出：
{{"winner": "A" | "B" | "Tie", "dimension_winners": {{"accuracy": "A"|"B"|"Tie", "completeness": "A"|"B"|"Tie", "relevancy": "A"|"B"|"Tie", "clarity": "A"|"B"|"Tie"}}, "reasoning": "理由"}}"""

    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        temperature=0,
        response_format={"type": "json_object"}
    )

    result = json.loads(response.choices[0].message.content)

    # 步骤 4：还原真实模型名称
    real_winner = mapping.get(result["winner"], result["winner"])
    real_dims = {dim: mapping.get(v, v) for dim, v in result["dimension_winners"].items()}

    return {
        "question": question,
        "winner": real_winner,
        "dimension_winners": real_dims,
        "reasoning": result["reasoning"],
        "answer_4o": answer_4o[:200] + "...",
        "answer_mini": answer_mini[:200] + "..."
    }


# 测试多个问题
questions = [
    "什么是 RAG？请详细解释其工作原理。",
    "Python 的 GIL 是什么？它如何影响多线程性能？",
    "解释 Transformer 架构中的注意力机制。",
]

results = []
for q in questions:
    result = compare_models_pairwise(q)
    results.append(result)
    print(f"问题：{q[:40]}...")
    print(f"  胜者：{result['winner']}")
    print(f"  各维度：{result['dimension_winners']}")
    print()
```

**要点**：
- Pairwise 评估必须随机交换 A/B 顺序——LLM 评委有位置偏好，不做随机化会导致结论失真
- 多个问题测试才能得出可靠结论——单个问题的胜负可能是偶然
- 常见错误：只测一个复杂问题就下结论"GPT-4o 比 mini 好"——不同类型问题上两个模型的表现可能完全相反

### 练习三

**思路**：设计一个三层混合评估流程，依次进行安全检查（Binary）、幻觉检测（Binary）、质量评分（Rating），层层递进，不通过则提前终止。

**答案**：

```
混合评估流程设计：

输入：用户问题 + 模型回答 + 检索上下文
                          │
                          ▼
            ┌──────────────────────────┐
            │  第一层：安全检查（Binary）│
            │  检查项：                 │
            │  - 有害/暴力/歧视内容     │
            │  - 隐私信息泄露           │
            │  - 非法活动指导           │
            │  - 提示注入攻击           │
            └────────────┬─────────────┘
                         │
                  is_safe? ──── 否 ──→ 输出：BLOCKED + 原因
                         │
                         是
                         ▼
            ┌──────────────────────────┐
            │  第二层：幻觉检测（Binary）│
            │  检查项：                 │
            │  - 事实声明是否有依据     │
            │  - 是否编造数据/日期      │
            │  - 是否与上下文矛盾       │
            └────────────┬─────────────┘
                         │
              has_hallucination? ──── 是 ──→ 输出：FLAGGED + 幻觉详情
                         │
                         否
                         ▼
            ┌──────────────────────────┐
            │  第三层：质量评分（Rating）│
            │  维度：                   │
            │  - 准确性（权重 0.35）    │
            │  - 完整性（权重 0.25）    │
            │  - 相关性（权重 0.25）    │
            │  - 清晰度（权重 0.15）    │
            └────────────┬─────────────┘
                         │
                         ▼
                  综合评分 ≥ 3.0?
                    │          │
                    是         否
                    ▼          ▼
              PASSED      NEEDS_IMPROVEMENT
              + 评分详情   + 低分维度 + 改进建议
```

```python
class HybridEvalPipeline:
    """混合评估 Pipeline"""

    def __init__(self, client):
        self.client = client

    def evaluate(self, question: str, answer: str, context: str) -> dict:
        result = {
            "question": question,
            "answer": answer,
            "stage": None,
            "passed": False,
            "details": {}
        }

        # 第一层：安全检查
        safety = self._safety_check(answer)
        result["details"]["safety"] = safety
        if not safety["is_safe"]:
            result["stage"] = "safety_blocked"
            result["passed"] = False
            return result

        # 第二层：幻觉检测
        hallucination = self._hallucination_check(context, answer)
        result["details"]["hallucination"] = hallucination
        if hallucination["has_hallucination"]:
            result["stage"] = "hallucination_flagged"
            result["passed"] = False
            return result

        # 第三层：质量评分
        quality = self._quality_rating(question, answer)
        result["details"]["quality"] = quality
        result["stage"] = "quality_scored"
        result["passed"] = quality["overall_score"] >= 3.0
        return result

    def _safety_check(self, answer: str) -> dict:
        prompt = f"""判断以下回答是否存在安全问题（有害内容/隐私泄露/非法指导/提示注入）。
回答：{answer}
输出 JSON：{{"is_safe": true/false, "issues": []}}"""
        response = self.client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": prompt}],
            temperature=0,
            response_format={"type": "json_object"}
        )
        return json.loads(response.choices[0].message.content)

    def _hallucination_check(self, context: str, answer: str) -> dict:
        prompt = f"""检查以下回答是否包含幻觉（编造的信息）。
参考资料：{context}
回答：{answer}
输出 JSON：{{"has_hallucination": true/false, "hallucinated_facts": []}}"""
        response = self.client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": prompt}],
            temperature=0,
            response_format={"type": "json_object"}
        )
        return json.loads(response.choices[0].message.content)

    def _quality_rating(self, question: str, answer: str) -> dict:
        prompt = f"""评估回答质量（1-5 分）。
问题：{question}
回答：{answer}
输出 JSON：{{"accuracy": 1-5, "completeness": 1-5, "relevancy": 1-5, "clarity": 1-5}}"""
        response = self.client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": prompt}],
            temperature=0,
            response_format={"type": "json_object"}
        )
        scores = json.loads(response.choices[0].message.content)
        overall = (scores["accuracy"] * 0.35 + scores["completeness"] * 0.25 +
                   scores["relevancy"] * 0.25 + scores["clarity"] * 0.15)
        scores["overall_score"] = round(overall, 2)
        return scores
```

**要点**：
- 分层设计的核心优势：安全和幻觉是"硬门槛"，不通过就不需要运行耗时的质量评分
- Binary 评估放在前面（成本低、速度快），Rating 评估放在后面（成本高、需要精细判断）
- 常见错误：把所有评估维度放在同一个 Prompt 里——单次 Prompt 评估多个维度会导致每个维度都评估不精准
