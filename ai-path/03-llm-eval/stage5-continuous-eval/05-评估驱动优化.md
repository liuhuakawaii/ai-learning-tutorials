# 05 评估驱动优化——用评估数据指导 Prompt 工程和 RAG 调优

> 不是盲目调参，是用数据指导优化。评估驱动优化让每一步都有据可依。

## 场景引入

你的 RAG 应用评估报告显示忠实度 0.72、相关性 0.68、幻觉率 12%——三个指标都不达标。你决定优化，但面对这些数字完全不知道从哪里下手：是先改 Prompt？还是先调检索？还是换 embedding 模型？没有评估数据驱动的优化就像蒙眼开车，评估驱动优化的核心就是让每一步优化都有数据支撑、有明确方向。

## 学习目标

- 掌握用评估数据指导优化的方法
- 学会分析评估结果找到优化方向
- 建立"评估→优化→再评估"的闭环

## 一、优化决策框架

```
评估结果 → 问题诊断 → 优化策略 → 实施优化 → 重新评估

    └──────────────── 循环 ────────────────────┘
```

### 1.1 问题诊断矩阵

```python
def diagnose_issues(eval_results: dict) -> list[dict]:
    """根据评估结果诊断问题"""
    
    issues = []
    
    # 检查忠实度
    if eval_results.get("faithfulness", 1.0) < 0.8:
        issues.append({
            "type": "faithfulness",
            "severity": "high",
            "description": "回答不忠实于上下文",
            "optimization": "优化 Prompt，强调基于参考资料回答"
        })
    
    # 检查相关性
    if eval_results.get("relevancy", 1.0) < 0.7:
        issues.append({
            "type": "relevancy",
            "severity": "medium",
            "description": "回答不够切题",
            "optimization": "优化问题理解，添加 Few-shot 示例"
        })
    
    # 检查幻觉
    if eval_results.get("hallucination_rate", 0.0) > 0.1:
        issues.append({
            "type": "hallucination",
            "severity": "high",
            "description": "存在幻觉问题",
            "optimization": "强化'不要编造'指令，增加上下文约束"
        })
    
    # 检查检索质量
    if eval_results.get("context_precision", 1.0) < 0.6:
        issues.append({
            "type": "retrieval_precision",
            "severity": "medium",
            "description": "检索到了不相关的文档",
            "optimization": "优化检索策略，添加过滤条件"
        })
    
    if eval_results.get("context_recall", 1.0) < 0.6:
        issues.append({
            "type": "retrieval_recall",
            "severity": "medium",
            "description": "遗漏了相关文档",
            "optimization": "增加检索数量，优化 embedding"
        })
    
    return issues
```

```python
def optimize_retrieval(eval_results: dict) -> dict:
    """基于评估结果优化检索"""
    
    optimizations = {}
    
    # 精确率低 → 添加过滤
    if eval_results.get("context_precision", 1.0) < 0.6:
        optimizations["add_filter"] = True
        optimizations["filter_threshold"] = 0.7
    
    # 召回率低 → 增加检索数量
    if eval_results.get("context_recall", 1.0) < 0.6:
        optimizations["increase_top_k"] = True
        optimizations["new_top_k"] = 10
    
    # 添加 Reranker
    if eval_results.get("context_precision", 1.0) < 0.7:
        optimizations["add_reranker"] = True
    
    # 查询重写
    if eval_results.get("context_recall", 1.0) < 0.7:
        optimizations["add_query_rewrite"] = True
    
    return optimizations
```

## 四、优化闭环

```python
class OptimizationLoop:
    """优化闭环"""
    
    def __init__(self, eval_suite, pipeline):
        self.eval_suite = eval_suite
        self.pipeline = pipeline
        self.history = []
    
    def run_iteration(self, optimization_fn) -> dict:
        """运行一次优化迭代"""
        
        # 1. 运行评估
        eval_results = self.eval_suite.run()
        
        # 2. 诊断问题
        issues = diagnose_issues(eval_results)
        
        # 3. 生成优化方案
        optimizations = optimization_fn(eval_results, issues)
        
        # 4. 应用优化
        self.pipeline.apply_optimizations(optimizations)
        
        # 5. 重新评估
        new_eval_results = self.eval_suite.run()
        
        # 6. 记录结果
        iteration = {
            "before": eval_results,
            "after": new_eval_results,
            "issues": issues,
            "optimizations": optimizations,
            "improvement": new_eval_results["overall"] - eval_results["overall"]
        }
        self.history.append(iteration)
        
        return iteration
    
    def get_progress(self) -> dict:
        """获取优化进度"""
        if not self.history:
            return {}
        
        return {
            "iterations": len(self.history),
            "total_improvement": self.history[-1]["after"]["overall"] - self.history[0]["before"]["overall"],
            "best_score": max(h["after"]["overall"] for h in self.history)
        }
```

## 五、优化最佳实践

```
优化最佳实践：

1. 每次只改一个变量
   - 不要同时改 Prompt 和检索策略
   - 每次优化后重新评估，确认效果

2. 记录每次优化
   - 记录改了什么、为什么改、效果如何
   - 方便回滚和复盘

3. 关注退化案例
   - 优化可能改善大部分案例，但退化少数案例
   - 退化案例要重点分析

4. 设置优化目标
   - 不要无限优化
   - 达到目标就停止

5. 定期回顾
   - 每周回顾优化进度
   - 调整优化方向
```

## 常见误区

1. **看到指标低就急着改 Prompt**：忠实度低可能是检索问题而不是 Prompt 问题——如果检索到的文档本身就不对，再怎么优化 Prompt 也没用。先定位问题根源，再选择优化策略。

2. **一次优化改太多东西**：同时改了 Prompt、检索策略和 reranker，结果指标提升了，但不知道哪个改动起了作用。每次只改一个变量，用评估量化每一步的贡献。

3. **优化后不跑回归测试**：Prompt 优化让忠实度从 0.72 提升到 0.80，但相关性从 0.68 掉到了 0.60。优化必须配合回归测试，确保改善的是目标指标而不是拆东墙补西墙。

4. **追求单项指标极致而忽视整体平衡**：把幻觉率从 5% 压到 1% 的代价可能是回答变得过于保守、大量"无法回答"。优化要设定合理的目标区间，不是越极端越好。

## 工程建议

1. **建立问题诊断矩阵**：将评估指标与可能的根因和对应优化策略做成映射表。当指标不达标时，团队能快速定位方向，而不是每次都从零开始分析。

2. **用失败案例驱动优化而非指标数字**：指标低只是一个信号，真正指导优化的是失败的具体案例。每次优化前先花时间分析 10-20 个失败用例，找出共性模式后再制定策略。

3. **优化实验要有对照组**：即使不做正式的 A/B 测试，每次优化也要保留上一版的评估结果作为对照。没有对照就无法量化优化的真实效果，也无法区分改善和随机波动。

4. **设定优化收益递减的退出机制**：当连续两轮优化的指标提升都低于 1% 时，说明当前方向的收益已经很小，应该换思路或接受当前水平进入维护阶段，避免陷入无止境的微调。

### 练习三

**思路**：完整的优化闭环包括：评估→诊断→优化→重新评估→对比。关键是记录每一步的数据，形成可追溯的优化历史。

**答案**：

```python
import json
from datetime import datetime


class OptimizationLoop:
    """评估驱动的优化闭环"""

    def __init__(self):
        self.iterations = []

    def run_iteration(
        self,
        iteration_name: str,
        before_eval: dict,
        optimization_action: str,
        after_eval: dict,
    ) -> dict:
        """运行一次优化迭代"""

        # 计算各指标变化
        changes = {}
        for metric in before_eval:
            if metric in after_eval:
                delta = after_eval[metric] - before_eval[metric]
                changes[metric] = {
                    "before": before_eval[metric],
                    "after": after_eval[metric],
                    "delta": delta,
                    "improved": delta > 0 if metric != "hallucination_rate" else delta < 0,
                }

        iteration = {
            "name": iteration_name,
            "timestamp": datetime.now().isoformat(),
            "optimization": optimization_action,
            "changes": changes,
            "overall_improved": all(c["improved"] for c in changes.values()),
            "has_regression": any(not c["improved"] for c in changes.values()),
        }

        self.iterations.append(iteration)
        return iteration

    def get_progress_report(self) -> dict:
        if not self.iterations:
            return {"message": "无迭代记录"}

        first = self.iterations[0]
        last = self.iterations[-1]

        total_changes = {}
        for metric in first["changes"]:
            if metric in last["changes"]:
                total_changes[metric] = {
                    "start": first["changes"][metric]["before"],
                    "current": last["changes"][metric]["after"],
                    "total_delta": last["changes"][metric]["after"] - first["changes"][metric]["before"],
                }

        return {
            "total_iterations": len(self.iterations),
            "total_changes": total_changes,
            "regression_count": sum(1 for it in self.iterations if it["has_regression"]),
        }


# 运行完整的优化闭环
loop = OptimizationLoop()

# 迭代 1：优化 Prompt 降低幻觉率
iter1 = loop.run_iteration(
    iteration_name="v1.1 - 添加兜底指令",
    before_eval={"faithfulness": 0.72, "relevancy": 0.68, "hallucination_rate": 0.12},
    optimization_action="在 Prompt 中添加'无法回答'兜底指令",
    after_eval={"faithfulness": 0.80, "relevancy": 0.69, "hallucination_rate": 0.07},
)

print("=== 迭代 1 结果 ===")
for metric, change in iter1["changes"].items():
    icon = "✅" if change["improved"] else "❌"
    print(f"  {icon} {metric}: {change['before']:.2f} → {change['after']:.2f} ({change['delta']:+.2f})")

# 迭代 2：优化检索提升相关性
iter2 = loop.run_iteration(
    iteration_name="v1.2 - 添加 Reranker",
    before_eval={"faithfulness": 0.80, "relevancy": 0.69, "hallucination_rate": 0.07},
    optimization_action="添加 Reranker 提升检索精确率",
    after_eval={"faithfulness": 0.82, "relevancy": 0.78, "hallucination_rate": 0.06},
)

print("\n=== 迭代 2 结果 ===")
for metric, change in iter2["changes"].items():
    icon = "✅" if change["improved"] else "❌"
    print(f"  {icon} {metric}: {change['before']:.2f} → {change['after']:.2f} ({change['delta']:+.2f})")

# 总体进度
report = loop.get_progress_report()
print(f"\n=== 总体进度 ===")
print(f"迭代次数: {report['total_iterations']}")
print(f"回归次数: {report['regression_count']}")
for metric, progress in report["total_changes"].items():
    print(f"  {metric}: {progress['start']:.2f} → {progress['current']:.2f} ({progress['total_delta']:+.2f})")
```

**要点**：
- 每次迭代只改一个变量，用评估数据量化效果——这样才能知道"是 Reranker 提升了相关性还是 Prompt 降低了幻觉率"
- 如果某次迭代导致其他指标下降（回归），需要分析是否值得
- 常见错误：优化后不记录前后对比，导致无法知道哪些优化真正有效，也无法回滚失败的优化
