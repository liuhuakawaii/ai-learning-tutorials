# 02 工具调用评估——准确率、参数正确性、调用效率

> Agent 的能力上限取决于它的工具调用能力。工具调用评估是 Agent 评估的核心。

## 场景引入

你给 Agent 接入了 8 个工具：搜索、数据库查询、文件读写、API 调用等。在测试中发现，Agent 有 30% 的情况选错了工具——用户问"帮我查上周的销售数据"，它去调搜索工具而不是数据库查询工具；还有 20% 的情况选对了工具但参数填错——日期格式不对、表名拼写错误。更隐蔽的问题是，Agent 调用工具后拿到正确结果，却在解读时犯错，把"增长 15%"说成了"下降 15%"。你需要一套系统的方法来评估工具调用的每个环节。

## 学习目标

- 掌握工具调用的评估维度和方法
- 学会评估工具选择、参数生成、结果解读
- 建立工具调用的自动化评估流程

## 一、工具调用评估维度

### 1.1 工具选择评估

```python
def evaluate_tool_selection(
    available_tools: list[dict],
    user_query: str,
    selected_tool: str,
    expected_tool: str,
    client
) -> dict:
    """评估工具选择是否正确"""
    
    tools_desc = "\n".join([f"- {t['name']}: {t['description']}" for t in available_tools])
    
    prompt = f"""评估 Agent 的工具选择是否正确。

用户问题：{user_query}

可用工具：
{tools_desc}

Agent 选择的工具：{selected_tool}
应该选择的工具：{expected_tool}

请判断：
1. 选择是否正确？
2. 如果不正确，应该选择哪个？

请以 JSON 格式输出：
{{"correct": true/false, "expected": "正确工具", "reasoning": "理由"}}"""

    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        temperature=0,
        response_format={"type": "json_object"}
    )
    
    return json.loads(response.choices[0].message.content)
```

## 二、自动化评估流程

```python
class ToolCallEvaluator:
    """工具调用评估器"""
    
    def __init__(self, client):
        self.client = client
    
    def evaluate_tool_call(
        self,
        user_query: str,
        tool_call: dict,
        tool_output: str,
        agent_answer: str,
        expected: dict,
        available_tools: list[dict]
    ) -> dict:
        """评估单次工具调用"""
        
        results = {
            "tool_selection": {},
            "parameters": {},
            "interpretation": {},
            "overall_score": 0.0
        }
        
        # 1. 工具选择评估
        results["tool_selection"] = evaluate_tool_selection(
            available_tools,
            user_query,
            tool_call["tool"],
            expected["tool"],
            self.client
        )
        
        # 2. 参数评估
        if results["tool_selection"]["correct"]:
            results["parameters"] = evaluate_tool_parameters(
                tool_call["tool"],
                tool_call.get("schema", {}),
                tool_call.get("parameters", {}),
                expected.get("parameters", {}),
                self.client
            )
        
        # 3. 结果解读评估
        results["interpretation"] = evaluate_result_interpretation(
            tool_output,
            agent_answer,
            expected.get("answer", ""),
            self.client
        )
        
        # 综合评分
        selection_score = 1.0 if results["tool_selection"]["correct"] else 0.0
        param_score = results["parameters"].get("score", 0)
        interp_score = results["interpretation"].get("score", 0)
        
        results["overall_score"] = (
            selection_score * 0.4 +
            param_score * 0.3 +
            interp_score * 0.3
        )
        
        return results
```

## 三、批量评估与报告

```python
def batch_evaluate_tool_calls(evaluator: ToolCallEvaluator, dataset: list[dict]) -> dict:
    """批量评估工具调用"""
    results = []
    
    for item in dataset:
        result = evaluator.evaluate_tool_call(
            user_query=item["query"],
            tool_call=item["tool_call"],
            tool_output=item["tool_output"],
            agent_answer=item["agent_answer"],
            expected=item["expected"],
            available_tools=item["available_tools"]
        )
        results.append(result)
    
    # 统计
    avg_score = sum(r["overall_score"] for r in results) / len(results)
    selection_accuracy = sum(1 for r in results if r["tool_selection"]["correct"]) / len(results)
    
    return {
        "total": len(results),
        "avg_score": avg_score,
        "tool_selection_accuracy": selection_accuracy,
        "details": results
    }
```

## 常见误区

1. **只评估工具选择，忽略参数和解读**：选对工具但参数填错等于没选，拿到正确结果但解读错误等于白拿。三个维度缺一不可。
2. **用精确匹配判断参数正确性**：日期格式 `2024-01-01` 和 `2024/01/01` 可能都是对的，城市名"北京"和"Beijing"也可能等价。参数评估要考虑语义等价，不能只做字符串比对。
3. **忽略工具调用的上下文依赖**：单次工具调用可能正确，但在多步场景中，第二次调用依赖第一次的结果。孤立评估单次调用会漏掉链式错误。
4. **测试集只覆盖"happy path"**：只测了正常情况下的工具调用，没测工具返回异常、超时、空结果时 Agent 的行为。线上出问题往往就在这些边界情况。

## 工程建议

1. **为每个工具建立"正确调用"标注数据**：收集典型 query 和对应的正确工具/参数组合，作为评估的 ground truth。标注数据量不需要很大，但每个工具至少覆盖 5-10 个典型场景。
2. **参数评估用 schema 验证 + LLM 判断双重检查**：先用 JSON Schema 验证参数格式是否合法（类型、必填项、枚举值），再用 LLM 判断参数值是否语义合理。两层检查互补。
3. **工具调用评估要区分"硬错误"和"软错误"**：调用了完全错误的工具是硬错误，选对工具但参数日期差了一天是软错误。两种错误的严重程度和修复策略不同，评估报告要分开统计。
4. **监控线上工具调用的成功率和延迟**：评估不能只在测试环境做。线上采集工具调用的成功/失败率、平均延迟、错误类型分布，才能发现测试集没覆盖到的问题。

## 参考答案

### 练习一

**思路**：ToolCallEvaluator 需要覆盖三个维度——工具选择、参数正确性、结果解读。每个维度用 LLM-as-Judge 评估，最后加权汇总。关键是要用 schema 验证参数格式，再用 LLM 判断语义合理性。

**答案**：

```python
import json
from openai import OpenAI


class ToolCallEvaluator:
    """完整的工具调用评估器"""

    def __init__(self, client: OpenAI):
        self.client = client
        self.weights = {
            "selection": 0.4,
            "parameters": 0.3,
            "interpretation": 0.3,
        }

    def evaluate(
        self,
        user_query: str,
        available_tools: list[dict],
        selected_tool: str,
        generated_params: dict,
        tool_output: str,
        agent_answer: str,
        expected: dict,
    ) -> dict:
        results = {}

        # 1. 工具选择评估
        results["tool_selection"] = self._evaluate_selection(
            user_query, available_tools, selected_tool, expected["tool"]
        )

        # 2. 参数评估（仅在选择正确时才评估）
        if results["tool_selection"]["correct"]:
            results["parameters"] = self._evaluate_parameters(
                selected_tool,
                generated_params,
                expected.get("parameters", {}),
                expected.get("tool_schema", {}),
            )
        else:
            results["parameters"] = {"correct": False, "score": 0.0, "issues": ["工具选择错误，跳过参数评估"]}

        # 3. 结果解读评估
        results["interpretation"] = self._evaluate_interpretation(
            tool_output, agent_answer, expected.get("answer", "")
        )

        # 综合评分
        sel_score = 1.0 if results["tool_selection"]["correct"] else 0.0
        param_score = results["parameters"].get("score", 0)
        interp_score = results["interpretation"].get("score", 0)

        results["overall_score"] = (
            sel_score * self.weights["selection"]
            + param_score * self.weights["parameters"]
            + interp_score * self.weights["interpretation"]
        )

        return results

    def _evaluate_selection(self, query, tools, selected, expected) -> dict:
        tools_desc = "\n".join(f"- {t['name']}: {t['description']}" for t in tools)
        prompt = f"""评估工具选择是否正确。
用户问题：{query}
可用工具：
{tools_desc}
Agent 选择：{selected}
正确选择：{expected}
以 JSON 输出：{{"correct": bool, "reasoning": "理由"}}"""
        resp = self.client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": prompt}],
            temperature=0,
            response_format={"type": "json_object"},
        )
        return json.loads(resp.choices[0].message.content)

    def _evaluate_parameters(self, tool, generated, expected, schema) -> dict:
        # 先用 schema 做格式校验
        format_issues = []
        if schema:
            for param_name, param_spec in schema.items():
                if param_spec.get("required") and param_name not in generated:
                    format_issues.append(f"缺少必填参数: {param_name}")
                if param_name in generated and param_spec.get("type"):
                    if not isinstance(generated[param_name], eval(param_spec["type"])):
                        format_issues.append(f"参数 {param_name} 类型错误，期望 {param_spec['type']}")

        prompt = f"""评估工具参数是否正确。
工具：{tool}
生成的参数：{json.dumps(generated, ensure_ascii=False)}
期望的参数：{json.dumps(expected, ensure_ascii=False)}
格式校验问题：{format_issues}
以 JSON 输出：{{"correct": bool, "score": 0-1, "issues": ["问题1"]}}"""
        resp = self.client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": prompt}],
            temperature=0,
            response_format={"type": "json_object"},
        )
        result = json.loads(resp.choices[0].message.content)
        if format_issues:
            result["issues"] = result.get("issues", []) + format_issues
            result["score"] = max(0, result.get("score", 0) - 0.2 * len(format_issues))
        return result

    def _evaluate_interpretation(self, tool_output, agent_answer, expected) -> dict:
        prompt = f"""评估 Agent 是否正确解读了工具结果。
工具返回：{tool_output}
Agent 解读：{agent_answer}
期望解读：{expected}
以 JSON 输出：{{"correct": bool, "score": 0-1, "issues": ["问题1"]}}"""
        resp = self.client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": prompt}],
            temperature=0,
            response_format={"type": "json_object"},
        )
        return json.loads(resp.choices[0].message.content)
```

**要点**：
- 三个维度的权重可以根据业务场景调整，如客服场景可提高解读权重
- 参数评估应先做 schema 格式校验再做 LLM 语义校验，两层检查互补
- 常见错误：只评估工具选择是否正确，忽略参数和解读，导致选对了但用错了的情况被放过

### 练习三

**思路**：通过批量评估结果定位最常出错的步骤。根据经验，大多数 Agent 在"工具选择"这一步出错最多，尤其是当多个工具功能相近时。优化方向包括改进工具描述、添加 Few-shot 示例和使用路由分类器。

**答案**：

```python
def diagnose_and_optimize(evaluation_results: dict) -> dict:
    """诊断工具调用最常出错的步骤并给出优化方案"""

    details = evaluation_results.get("details", [])

    selection_errors = sum(1 for d in details if not d.get("tool_selection", {}).get("correct"))
    param_errors = sum(1 for d in details if d.get("parameters", {}).get("score", 1) < 0.7)
    interp_errors = sum(1 for d in details if d.get("interpretation", {}).get("score", 1) < 0.7)

    error_distribution = {
        "tool_selection": selection_errors,
        "parameters": param_errors,
        "interpretation": interp_errors,
    }

    weakest = max(error_distribution, key=error_distribution.get)

    optimization_plans = {
        "tool_selection": {
            "root_cause": "工具描述不清晰，Agent 难以区分相似工具",
            "actions": [
                "重写工具 description，突出每个工具的独特用途和适用场景",
                "在 System Prompt 中添加工具选择的 Few-shot 示例",
                "当工具数量 > 5 时，先用分类器路由到工具组，再在组内选择",
            ],
        },
        "parameters": {
            "root_cause": "参数格式要求不明确，Agent 容易填错类型或遗漏必填项",
            "actions": [
                "在工具 schema 中明确标注参数类型、格式示例和必填项",
                "添加参数校验层，在调用工具前拦截格式错误",
                "对日期、城市等易错参数提供标准化函数",
            ],
        },
        "interpretation": {
            "root_cause": "Agent 对工具返回数据的理解有偏差，尤其是数值和方向性信息",
            "actions": [
                "在 Prompt 中要求 Agent 逐字段引用工具返回的关键数据",
                "添加自检指令：'请确认你引用的数据与工具返回一致'",
                "对关键业务数据（金额、百分比）添加数值校验逻辑",
            ],
        },
    }

    return {
        "error_distribution": error_distribution,
        "weakest_step": weakest,
        "optimization": optimization_plans[weakest],
    }
```

**要点**：
- 三个步骤中最常出错的通常是"工具选择"——当工具描述相似时 Agent 容易混淆
- 优化工具选择的核心是让每个工具的 description 具有高区分度，而不是堆砌更多工具
- 常见错误：盲目增加工具数量而不优化描述，导致选择准确率进一步下降
