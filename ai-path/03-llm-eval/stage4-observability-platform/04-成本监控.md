# 04 成本监控——Token 消耗、API 调用次数、费用预警

> AI 应用的成本是"看不见的杀手"。不监控成本，月底账单会让你大吃一惊。

## 场景引入

你的 RAG 知识库应用上线一个月后，收到了 OpenAI 的账单：$2,300。你完全没有预料到这个数字。复盘后发现，某个用户的自动化脚本每天发起 5000 次请求，每次都把整个知识库上下文塞进 Prompt；另一个场景是模型升级后 output token 数翻倍，但没人注意到。如果有一个实时的成本监控面板，这些问题在第一天就能被发现，而不是月底才追悔莫及。

- 掌握 AI 应用成本监控的方法

## 一、成本监控架构

```python
class CostMonitor:
    """成本监控器"""
    
    def __init__(self, daily_limit: float, monthly_limit: float):
        self.daily_limit = daily_limit
        self.monthly_limit = monthly_limit
        self.daily_cost = 0.0
        self.monthly_cost = 0.0
        self.records = []
        
        # 模型定价
        self.pricing = {
            "gpt-4o": {"input": 2.50, "output": 10.00},
            "gpt-4o-mini": {"input": 0.15, "output": 0.60},
            "claude-3-5-sonnet": {"input": 3.00, "output": 15.00},
        }
    
    def record_usage(
        self,
        model: str,
        input_tokens: int,
        output_tokens: int,
        operation: str,
        user_id: str = None
    ):
        """记录使用量"""
        
        # 计算成本
        pricing = self.pricing.get(model, self.pricing["gpt-4o-mini"])
        cost = (
            input_tokens * pricing["input"] / 1_000_000 +
            output_tokens * pricing["output"] / 1_000_000
        )
        
        # 记录
        self.daily_cost += cost
        self.monthly_cost += cost
        self.records.append({
            "timestamp": datetime.now().isoformat(),
            "model": model,
            "input_tokens": input_tokens,
            "output_tokens": output_tokens,
            "cost": cost,
            "operation": operation,
            "user_id": user_id
        })
        
        # 检查预警
        self._check_alerts()
        
        return cost
    
    def _check_alerts(self):
        """检查预警"""
        # 日预算预警
        if self.daily_cost > self.daily_limit * 0.8:
            self._send_alert("daily", self.daily_cost, self.daily_limit)
        
        # 月预算预警
        if self.monthly_cost > self.monthly_limit * 0.8:
            self._send_alert("monthly", self.monthly_cost, self.monthly_limit)
    
    def _send_alert(self, period: str, current: float, limit: float):
        """发送预警"""
        print(f"⚠️ 成本预警 [{period}]：${current:.2f} / ${limit:.2f} ({current/limit:.0%})")
    
    def get_report(self) -> dict:
        """获取成本报告"""
        return {
            "daily_cost": self.daily_cost,
            "monthly_cost": self.monthly_cost,
            "daily_budget_remaining": self.daily_limit - self.daily_cost,
            "monthly_budget_remaining": self.monthly_limit - self.monthly_cost,
            "total_requests": len(self.records),
            "avg_cost_per_request": sum(r["cost"] for r in self.records) / len(self.records) if self.records else 0,
            "by_model": self._group_by_model(),
            "by_operation": self._group_by_operation()
        }
    
    def _group_by_model(self) -> dict:
        """按模型分组"""
        groups = {}
        for r in self.records:
            model = r["model"]
            if model not in groups:
                groups[model] = {"requests": 0, "cost": 0.0}
            groups[model]["requests"] += 1
            groups[model]["cost"] += r["cost"]
        return groups
    
    def _group_by_operation(self) -> dict:
        """按操作分组"""
        groups = {}
        for r in self.records:
            op = r["operation"]
            if op not in groups:
                groups[op] = {"requests": 0, "cost": 0.0}
            groups[op]["requests"] += 1
            groups[op]["cost"] += r["cost"]
        return groups
```

## 三、预算控制

```python
class BudgetController:
    """预算控制器"""
    
    def __init__(self, cost_monitor: CostMonitor):
        self.cost_monitor = cost_monitor
    
    def check_budget(self, user_id: str, operation: str) -> bool:
        """检查是否超出预算"""
        
        # 检查总预算
        if self.cost_monitor.daily_cost >= self.cost_monitor.daily_limit:
            raise BudgetExceededError("Daily budget exceeded")
        
        # 检查用户预算（可选）
        user_cost = self._get_user_daily_cost(user_id)
        user_limit = self._get_user_daily_limit(user_id)
        
        if user_cost >= user_limit:
            raise UserBudgetExceededError(f"User {user_id} daily budget exceeded")
        
        return True
    
    def _get_user_daily_cost(self, user_id: str) -> float:
        """获取用户当日成本"""
        today = datetime.now().date()
        return sum(
            r["cost"] for r in self.cost_monitor.records
            if r["user_id"] == user_id
            and datetime.fromisoformat(r["timestamp"]).date() == today
        )
    
    def _get_user_daily_limit(self, user_id: str) -> float:
        """获取用户每日限额"""
        # 可以从配置或数据库获取
        return 10.0  # 默认 $10/天
```

## 常见误区

1. **只监控 API 费用，忽略隐性成本**：LLM API 费用只是冰山一角，向量数据库查询、Embedding 生成、重排序模型调用、数据预处理管道都有成本。总拥有成本（TCO）才是真实的成本画像。

2. **预警阈值设得太晚**：日预算 80% 才预警，等收到告警时剩余预算可能撑不过当天的流量高峰。建议设置多级预警：50% 提醒、70% 警告、90% 限流。

3. **用"平均成本"衡量整体**：单次请求平均 $0.02 看起来很低，但可能 10% 的复杂请求占了 60% 的成本。应该按成本分位数（P50/P90/P99）和成本分布来分析，而不是只看均值。

4. **成本优化只盯着模型选择**：换更便宜的模型确实有效，但更大的成本杠杆往往是 Prompt 精简（减少 30% input token）和语义缓存（减少 40% 重复调用）。模型选择只是优化手段之一。

## 工程建议

1. **建立模型定价配置表并动态更新**：不要在代码里硬编码模型价格，而是维护一份独立的定价配置文件或数据库表。当供应商调价时只改配置不改代码，同时在定价变更时自动触发成本预估重算。

2. **按功能模块设置独立预算**：RAG 检索、对话生成、文档摘要等不同功能的成本特征完全不同。应该为每个功能模块设置独立的日/月预算，这样成本异常能精确定位到具体功能，而不是笼统的"整体超标"。

3. **实现用户级成本限额与熔断**：为每个用户设置每日调用上限（如 $5/天），接近上限时返回降级响应（如用更便宜的模型），超过上限时直接熔断。防止个别用户的异常调用拖垮整体预算。

4. **每周出一份成本归因报告**：按用户、功能、模型三个维度拆解成本构成，识别"20% 的使用场景消耗了 80% 成本"的情况。针对高成本场景做定向优化，效果远好于盲目压缩整体预算。

## 参考答案

### 练习一

**思路**：成本监控需要记录每次 LLM 调用的 token 消耗和对应费用，按用户、模型、操作三个维度聚合，并设置多级预警。关键是把成本计算封装到 LLM 调用的包装函数中，确保每次调用都被记录。

**答案**：

```python
import os
from datetime import datetime, date
from dataclasses import dataclass, field
from typing import Optional
from contextlib import contextmanager


PRICING = {
    "gpt-4o": {"input": 2.50, "output": 10.00},
    "gpt-4o-mini": {"input": 0.15, "output": 0.60},
    "claude-3-5-sonnet": {"input": 3.00, "output": 15.00},
}


@dataclass
class CostRecord:
    timestamp: str
    user_id: str
    model: str
    operation: str
    input_tokens: int
    output_tokens: int
    cost: float


class CostMonitor:
    """成本监控器"""

    def __init__(self, daily_limit: float = 100.0, monthly_limit: float = 2000.0):
        self.daily_limit = daily_limit
        self.monthly_limit = monthly_limit
        self.records: list[CostRecord] = []
        self.alerts_sent: list[dict] = []

    def record(
        self,
        user_id: str,
        model: str,
        operation: str,
        input_tokens: int,
        output_tokens: int,
    ) -> float:
        pricing = PRICING.get(model, PRICING["gpt-4o-mini"])
        cost = (
            input_tokens * pricing["input"] / 1_000_000
            + output_tokens * pricing["output"] / 1_000_000
        )
        record = CostRecord(
            timestamp=datetime.now().isoformat(),
            user_id=user_id,
            model=model,
            operation=operation,
            input_tokens=input_tokens,
            output_tokens=output_tokens,
            cost=cost,
        )
        self.records.append(record)
        self._check_alerts()
        return cost

    def _check_alerts(self):
        daily = self._get_daily_cost()
        monthly = self._get_monthly_cost()

        thresholds = [
            (daily, self.daily_limit, "daily", 0.5),
            (daily, self.daily_limit, "daily", 0.8),
            (daily, self.daily_limit, "daily", 0.95),
            (monthly, self.monthly_limit, "monthly", 0.5),
            (monthly, self.monthly_limit, "monthly", 0.8),
        ]

        for current, limit, period, ratio in thresholds:
            if current >= limit * ratio:
                alert_key = f"{period}_{ratio}"
                if alert_key not in [a["key"] for a in self.alerts_sent]:
                    self.alerts_sent.append({"key": alert_key, "time": datetime.now().isoformat()})
                    print(f"⚠️ [{period.upper()}] 成本预警: ${current:.2f} / ${limit:.2f} ({current/limit:.0%})")

    def _get_daily_cost(self) -> float:
        today = date.today()
        return sum(
            r.cost for r in self.records
            if datetime.fromisoformat(r.timestamp).date() == today
        )

    def _get_monthly_cost(self) -> float:
        return sum(r.cost for r in self.records)

    def get_report(self) -> dict:
        if not self.records:
            return {"message": "暂无数据"}

        by_model = {}
        by_user = {}
        by_operation = {}
        for r in self.records:
            by_model.setdefault(r.model, {"count": 0, "cost": 0})
            by_model[r.model]["count"] += 1
            by_model[r.model]["cost"] += r.cost

            by_user.setdefault(r.user_id, {"count": 0, "cost": 0})
            by_user[r.user_id]["count"] += 1
            by_user[r.user_id]["cost"] += r.cost

            by_operation.setdefault(r.operation, {"count": 0, "cost": 0})
            by_operation[r.operation]["count"] += 1
            by_operation[r.operation]["cost"] += r.cost

        return {
            "daily_cost": self._get_daily_cost(),
            "monthly_cost": self._get_monthly_cost(),
            "daily_remaining": self.daily_limit - self._get_daily_cost(),
            "total_requests": len(self.records),
            "avg_cost_per_request": sum(r.cost for r in self.records) / len(self.records),
            "by_model": by_model,
            "by_user": by_user,
            "by_operation": by_operation,
        }


# 使用示例
monitor = CostMonitor(daily_limit=50.0, monthly_limit=1000.0)

# 模拟请求
monitor.record("user_001", "gpt-4o", "rag_query", 1500, 400)
monitor.record("user_001", "gpt-4o", "rag_query", 2000, 500)
monitor.record("user_002", "gpt-4o-mini", "classify", 200, 50)

report = monitor.get_report()
print(f"\n日成本: ${report['daily_cost']:.4f}")
print(f"平均单次成本: ${report['avg_cost_per_request']:.4f}")
```

**要点**：
- 成本计算必须封装到 LLM 调用的包装函数中，确保每次调用都被自动记录
- 多级预警（50%/80%/95%）比单级预警更实用——50% 时提醒关注，80% 时需要采取行动，95% 时触发限流
- 常见错误：只记录了总成本，没有按用户/操作维度分组，导致无法定位"哪个用户或功能消耗最多"

### 练习二

**思路**：成本分布分析需要按用户、模型、操作三个维度拆解，找出"二八定律"——20% 的使用场景消耗了 80% 的成本。然后针对高成本场景做定向优化。

**答案**：

```python
def analyze_cost_distribution(monitor) -> dict:
    """分析成本分布，找出优化方向"""
    report = monitor.get_report()
    total_cost = report["daily_cost"]

    print("=== 成本分布分析 ===\n")

    # 按模型分布
    print("【按模型分布】")
    for model, stats in sorted(report["by_model"].items(), key=lambda x: x[1]["cost"], reverse=True):
        pct = stats["cost"] / total_cost * 100 if total_cost > 0 else 0
        print(f"  {model}: {stats['count']} 次, ${stats['cost']:.4f} ({pct:.1f}%)")

    # 按操作分布
    print("\n【按操作分布】")
    for op, stats in sorted(report["by_operation"].items(), key=lambda x: x[1]["cost"], reverse=True):
        pct = stats["cost"] / total_cost * 100 if total_cost > 0 else 0
        avg = stats["cost"] / stats["count"]
        print(f"  {op}: {stats['count']} 次, ${stats['cost']:.4f} ({pct:.1f}%), 均价 ${avg:.4f}")

    # 按用户分布
    print("\n【按用户分布】")
    for user, stats in sorted(report["by_user"].items(), key=lambda x: x[1]["cost"], reverse=True):
        pct = stats["cost"] / total_cost * 100 if total_cost > 0 else 0
        print(f"  {user}: {stats['count']} 次, ${stats['cost']:.4f} ({pct:.1f}%)")

    # 找出优化方向
    top_model = max(report["by_model"].items(), key=lambda x: x[1]["cost"])
    top_op = max(report["by_operation"].items(), key=lambda x: x[1]["cost"])

    recommendations = []
    if top_model[1]["cost"] / total_cost > 0.7:
        recommendations.append(f"模型 '{top_model[0]}' 占成本 {top_model[1]['cost']/total_cost:.0%}，考虑对部分场景降级到更便宜的模型")

    for op, stats in report["by_operation"].items():
        avg = stats["cost"] / stats["count"]
        if avg > 0.05:
            recommendations.append(f"操作 '{op}' 平均成本 ${avg:.4f} 偏高，建议精简 Prompt 或添加缓存")

    return {
        "top_cost_model": top_model[0],
        "top_cost_operation": top_op[0],
        "recommendations": recommendations,
    }


analysis = analyze_cost_distribution(monitor)
print(f"\n优化建议:")
for r in analysis["recommendations"]:
    print(f"  - {r}")
```

**要点**：
- 成本分布分析的核心是找出"二八定律"——20% 的场景消耗 80% 的成本
- 按用户分布分析能发现异常用户（如自动化脚本大量调用），是成本失控的常见原因
- 常见错误：只看总成本数字，不做维度拆解，导致"知道花了多少但不知道花在哪里"

### 练习三

**思路**：降低 30% 成本需要组合多种策略。按优先级排序：模型路由（最大杠杆）→ Prompt 精简 → 语义缓存 → 限流。每种策略估算节省金额，确保合计超过 30%。

**答案**：

```python
def design_cost_optimization(monitor) -> dict:
    """设计成本优化方案，目标降低 30%"""
    report = monitor.get_report()
    current_cost = report["daily_cost"]
    target_savings = current_cost * 0.3

    strategies = []

    # 策略 1：模型路由——简单任务用 gpt-4o-mini
    # 假设 40% 的查询是简单任务（分类、意图识别等）
    simple_task_ratio = 0.4
    gpt4o_cost = report["by_model"].get("gpt-4o", {}).get("cost", 0)
    model_routing_savings = gpt4o_cost * simple_task_ratio * (1 - 0.15 / 2.50)
    strategies.append({
        "name": "模型路由",
        "description": "简单任务（分类、重写）用 gpt-4o-mini，复杂任务用 gpt-4o",
        "estimated_savings": model_routing_savings,
        "implementation": "添加 query 复杂度分类器，自动路由到对应模型",
        "risk": "低",
    })

    # 策略 2：Prompt 精简
    total_input_tokens = sum(r.input_tokens for r in monitor.records)
    prompt_reduction_ratio = 0.25
    gpt4o_price = PRICING["gpt-4o"]["input"]
    prompt_savings = total_input_tokens * prompt_reduction_ratio * gpt4o_price / 1_000_000
    strategies.append({
        "name": "Prompt 精简",
        "description": "精简 System Prompt，去除冗余指令，预计减少 25% input token",
        "estimated_savings": prompt_savings,
        "implementation": "重写 System Prompt，用更简洁的指令替代冗长描述",
        "risk": "低",
    })

    # 策略 3：语义缓存
    total_requests = report["total_requests"]
    cache_hit_rate = 0.15
    avg_cost = report["avg_cost_per_request"]
    cache_savings = total_requests * cache_hit_rate * avg_cost
    strategies.append({
        "name": "语义缓存",
        "description": f"对相似查询缓存结果，预计命中率 {cache_hit_rate:.0%}",
        "estimated_savings": cache_savings,
        "implementation": "用 embedding 相似度匹配，相似度 > 0.95 时返回缓存",
        "risk": "中——需要合理的 TTL 策略避免过期数据",
    })

    # 策略 4：用户级限流
    per_user_limit_savings = current_cost * 0.05
    strategies.append({
        "name": "用户级限流",
        "description": "单用户每日调用上限 $5，防止异常调用",
        "estimated_savings": per_user_limit_savings,
        "implementation": "在请求入口检查用户当日累计成本",
        "risk": "低",
    })

    total_savings = sum(s["estimated_savings"] for s in strategies)

    print("=== 成本优化方案 ===\n")
    print(f"当前日成本: ${current_cost:.2f}")
    print(f"目标节省: ${target_savings:.2f} (30%)\n")

    for i, s in enumerate(strategies, 1):
        print(f"{i}. {s['name']}")
        print(f"   说明: {s['description']}")
        print(f"   预计节省: ${s['estimated_savings']:.4f}")
        print(f"   实现方式: {s['implementation']}")
        print(f"   风险: {s['risk']}\n")

    print(f"合计预计节省: ${total_savings:.4f}")
    print(f"目标达成: {'✅' if total_savings >= target_savings else '❌'}")

    return {
        "current_cost": current_cost,
        "target_savings": target_savings,
        "total_estimated_savings": total_savings,
        "strategies": strategies,
        "target_met": total_savings >= target_savings,
    }


design_cost_optimization(monitor)
```

**要点**：
- 模型路由是最大的成本杠杆——将 40% 的简单查询从 gpt-4o 降到 gpt-4o-mini 可节省约 38% 的模型成本
- 语义缓存的命中率取决于业务场景，个性化查询场景命中率可能不到 10%，此时应把精力放在其他策略上
- 常见错误：只用一种策略（如只换模型），不如组合多种策略效果好且风险分散
