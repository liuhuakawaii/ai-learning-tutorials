# 03 生成评估指标——Faithfulness / Answer Relevancy / Hallucination 检测

> 检索找到了正确的文档，但模型可能"视而不见"或"自由发挥"。生成质量评估就是抓这些问题。

## 场景引入

你的 RAG 系统检索到了正确的政策文档，但用户问"年假有几天"时，模型回答"年假为 10 天"，而文档里写的是"入职满一年后年假为 10 天"。模型省略了前提条件，生成了一个看似正确但实际不完整的回答。这类问题无法通过检索指标发现，必须在生成阶段单独评估忠实度和幻觉。

## 学习目标

- 深入理解三种生成评估指标的计算方法
- 掌握用 LLM-as-Judge 评估生成质量的技巧
- 学会设计高质量的评估 Prompt

## 一、Faithfulness（忠实度）

### 1.1 声明拆解法

```python
def extract_claims(answer: str, client) -> list[str]:
    """将回答拆解为独立的声明"""
    prompt = f"""请将以下回答拆解为独立的事实声明。

回答：{answer}

要求：
1. 每个声明应该是独立的、可验证的事实
2. 不要拆解主观判断或连接词
3. 保持声明的原始含义

请以 JSON 格式输出：
{{"claims": ["声明1", "声明2", ...]}}"""

    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        temperature=0,
        response_format={"type": "json_object"}
    )
    
    return json.loads(response.choices[0].message.content)["claims"]

def verify_claims(claims: list[str], contexts: list[str], client) -> dict:
    """验证每个声明是否有上下文支持"""
    context_text = "\n".join(contexts)
    
    prompt = f"""请检查以下声明是否能在参考资料中找到依据。

参考资料：
{context_text}

声明列表：
{json.dumps(claims, ensure_ascii=False)}

对每个声明，判断：
- "supported"：能在参考资料中找到直接依据
- "unsupported"：参考资料中没有相关信息
- "contradicted"：与参考资料矛盾

请以 JSON 格式输出：
{{"results": [{{"claim": "声明", "status": "supported/unsupported/contradicted", "evidence": "依据"}}]}}"""

    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        temperature=0,
        response_format={"type": "json_object"}
    )
    
    return json.loads(response.choices[0].message.content)

def compute_faithfulness(answer: str, contexts: list[str], client) -> dict:
    """计算忠实度"""
    claims = extract_claims(answer, client)
    verification = verify_claims(claims, contexts, client)
    
    supported = sum(1 for r in verification["results"] if r["status"] == "supported")
    total = len(verification["results"])
    
    return {
        "faithfulness_score": supported / total if total > 0 else 1.0,
        "total_claims": total,
        "supported": supported,
        "unsupported": total - supported,
        "details": verification["results"]
    }
```

## 二、Answer Relevancy（回答相关性）

### 2.1 反向问题生成法

```python
def answer_relevancy_by_regeneration(question: str, answer: str, client) -> dict:
    """通过反向生成问题评估相关性"""
    
    # 步骤 1：从回答中生成可能的问题
    prompt_gen = f"""根据以下回答，推测用户可能问了什么问题。

回答：{answer}

请生成 3 个最可能的问题。"""

    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt_gen}],
        temperature=0,
        response_format={"type": "json_object"}
    )
    generated_questions = json.loads(response.choices[0].message.content)["questions"]
    
    # 步骤 2：计算生成问题与原始问题的相似度
    prompt_sim = f"""请计算以下两个问题的语义相似度（0-1）。

问题 1：{question}
问题 2：{generated_questions[0]}

请只输出数字。"""

    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt_sim}],
        temperature=0
    )
    similarity = float(response.choices[0].message.content.strip())
    
    return {
        "relevancy_score": similarity,
        "generated_questions": generated_questions,
        "original_question": question
    }
```

## 四、综合评估框架

### 4.1 RAG 生成评估器

```python
class RAGGenerationEvaluator:
    """RAG 生成质量综合评估器"""
    
    def __init__(self, client):
        self.client = client
    
    def evaluate(
        self,
        question: str,
        answer: str,
        contexts: list[str]
    ) -> dict:
        """综合评估生成质量"""
        
        results = {
            "question": question,
            "answer": answer,
            "faithfulness": {},
            "relevancy": {},
            "hallucination": {},
            "overall_score": 0.0
        }
        
        # 1. 忠实度评估
        results["faithfulness"] = compute_faithfulness(answer, contexts, self.client)
        
        # 2. 相关性评估
        results["relevancy"] = direct_answer_relevancy(question, answer, self.client)
        
        # 3. 幻觉检测
        results["hallucination"] = detect_hallucination(contexts, answer, self.client)
        
        # 4. 综合评分
        faith_score = results["faithfulness"]["faithfulness_score"]
        relev_score = results["relevancy"]["score"]
        halluc_score = 1 - results["hallucination"]["hallucination_score"]
        
        results["overall_score"] = (
            faith_score * 0.4 +
            relev_score * 0.3 +
            halluc_score * 0.3
        )
        
        return results
    
    def batch_evaluate(self, dataset: list[dict]) -> list[dict]:
        """批量评估"""
        results = []
        for i, item in enumerate(dataset):
            print(f"评估 {i+1}/{len(dataset)}: {item['question'][:30]}...")
            result = self.evaluate(
                question=item["question"],
                answer=item["answer"],
                contexts=item.get("contexts", [])
            )
            results.append(result)
        return results
```

## 五、评估结果分析

### 5.1 问题诊断

```
生成质量问题诊断：

问题 1：Faithfulness 低
  现象：回答不忠实于上下文
  原因：
    - Prompt 没有强调"基于参考资料回答"
    - 模型倾向于"自由发挥"
    - 上下文信息不够明确
  优化：
    - 在 Prompt 中明确要求"只使用参考资料中的信息"
    - 增加上下文的详细程度
    - 使用更强的模型

问题 2：Relevancy 低
  现象：回答不切题
  原因：
    - 模型没有理解问题的核心
    - 回答包含了过多无关信息
  优化：
    - 优化 Prompt，明确问题要求
    - 添加"如果没有相关信息，请说明"

问题 3：Hallucination 高
  现象：回答包含编造信息
  原因：
    - 模型倾向于补充"看起来合理"的信息
    - 上下文信息不足，模型"填补空白"
  优化：
    - 强调"不要编造信息"
    - 提供更充分的上下文
    - 使用幻觉检测作为后处理
```

## 常见误区

1. **把忠实度等同于正确性**：Faithfulness 只检查回答是否基于上下文，不检查上下文本身是否正确。如果检索到了错误文档，高忠实度也可能输出错误答案。

2. **幻觉检测只看"有没有编造"，不看类型**：完全编造（fabrication）和轻微夸大（exaggeration）的严重程度完全不同，不能用同一个分数衡量。

3. **评估 Prompt 设计得太模糊**：让 LLM 判断"回答好不好"这种模糊指令，评估结果一致性很差。必须给出明确的评分标准和示例。

4. **忽略评估模型本身的偏差**：GPT-4o 倾向于给偏长的回答更高分，也倾向于认为"措辞专业"的回答更忠实。需要用多模型交叉验证。

## 工程建议

1. **声明拆解要控制粒度**：拆得太细会增加评估成本，拆得太粗会漏检。建议每个回答拆成 3-8 个声明。

2. **设计评估 Prompt 时加入 few-shot 示例**：给评估模型 2-3 个标注好的示例，能显著提升评分一致性。

3. **对幻觉类型做加权评分**：fabrication 和 contradiction 权重设为 1.0，exaggeration 设为 0.5，interpolation 设为 0.3。

4. **建立评估结果的置信度机制**：当三个指标之间存在矛盾时（如忠实度高但幻觉也高），标记为"需要人工复核"。

## 小结

```
本课核心要点：

1. Faithfulness 用声明拆解法：拆解 → 验证 → 计算比例
2. Answer Relevancy 用反向问题生成法或直接评估法
3. Hallucination 检测基于上下文对比
4. 三种指标综合使用，加权计算总分
5. 低分指标指向具体的优化方向
```

## 参考答案

### 练习一

**思路**：实现一个完整的 RAG 生成评估器，整合忠实度（声明拆解法）、回答相关性（反向问题生成法）、幻觉检测（基于上下文对比）三种指标，加权计算综合分。

**答案**：

```python
from openai import OpenAI
import json

client = OpenAI()

class RAGGenerationEvaluator:
    """RAG 生成质量综合评估器"""

    def evaluate(self, question: str, answer: str, contexts: list[str]) -> dict:
        results = {
            "question": question,
            "answer": answer,
            "faithfulness": self._eval_faithfulness(answer, contexts),
            "relevancy": self._eval_relevancy(question, answer),
            "hallucination": self._eval_hallucination(answer, contexts),
        }

        f_score = results["faithfulness"]["score"]
        r_score = results["relevancy"]["score"]
        h_score = 1 - results["hallucination"]["score"]

        results["overall"] = round(f_score * 0.4 + r_score * 0.3 + h_score * 0.3, 3)
        return results

    def _eval_faithfulness(self, answer: str, contexts: list[str]) -> dict:
        context_text = "\n".join(contexts)
        prompt = f"""请评估回答是否忠实于参考资料。

参考资料：
{context_text}

回答：
{answer}

请将回答拆解为独立的事实声明，检查每个声明是否有参考资料支持。

输出 JSON：{{"claims": ["声明1", "声明2"], "supported": ["有依据的"], "unsupported": ["无依据的"], "score": <0-1>}}"""

        response = client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": prompt}],
            temperature=0,
            response_format={"type": "json_object"}
        )
        return json.loads(response.choices[0].message.content)

    def _eval_relevancy(self, question: str, answer: str) -> dict:
        prompt = f"""评估回答与问题的相关性。

问题：{question}
回答：{answer}

检查：1) 是否直接回答了问题 2) 是否包含无关信息 3) 是否遗漏关键方面

输出 JSON：{{"score": <0-1>, "missing": [], "irrelevant": [], "reasoning": ""}}"""

        response = client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": prompt}],
            temperature=0,
            response_format={"type": "json_object"}
        )
        return json.loads(response.choices[0].message.content)

    def _eval_hallucination(self, answer: str, contexts: list[str]) -> dict:
        context_text = "\n".join(contexts)
        prompt = f"""检测回答中的幻觉。

参考资料：
{context_text}

回答：
{answer}

检查：是否有编造的数据、日期、数字或无中生有的信息。

输出 JSON：{{"score": <0-1, 0=无幻觉>, "hallucinated_facts": [], "reasoning": ""}}"""

        response = client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": prompt}],
            temperature=0,
            response_format={"type": "json_object"}
        )
        return json.loads(response.choices[0].message.content)


# 使用示例
evaluator = RAGGenerationEvaluator()
result = evaluator.evaluate(
    question="公司的年假政策是什么？",
    answer="员工入职满一年后享有 10 天带薪年假，满五年后增加到 15 天。",
    contexts=["年假政策：员工入职满一年后，每年享有 10 天带薪年假。工作满五年后，年假增加至 15 天。"]
)
print(f"忠实度：{result['faithfulness']['score']}")
print(f"相关性：{result['relevancy']['score']}")
print(f"幻觉率：{result['hallucination']['score']}")
print(f"综合分：{result['overall']}")
```

**要点**：
- 三种指标的评估 Prompt 要分开设计——单次 Prompt 评估多个维度会导致每个维度都不精准
- 权重分配：忠实度最高（0.4），因为 RAG 场景下忠实于上下文是核心要求
- 常见错误：把三种指标的计算混在一个函数里——拆分成独立方法便于单独调试和替换

### 练习二

**思路**：分析三个指标的含义和组合关系，定位最需要优化的指标。

**答案**：

**指标分析**：

| 指标 | 值 | 含义 |
|------|-----|------|
| Faithfulness | 0.6 | 40% 的声明缺乏上下文支持（忠实度偏低） |
| Relevancy | 0.8 | 回答与问题基本相关（切题度不错） |
| Hallucination | 0.3 | 30% 的内容是幻觉（幻觉率偏高） |

**诊断结论**：**Faithfulness 最需要优化**。

**分析逻辑**：
- Relevancy 0.8 说明模型理解了问题并给出了相关回答——问题不在"理解问题"层面
- Faithfulness 0.6 说明模型在回答中添加了很多上下文中没有的信息——这是幻觉的根源
- Hallucination 0.3 和 Faithfulness 0.6 是一致的——忠实度低直接导致幻觉率高
- 两者的关系：Faithfulness = 1 - Hallucination（在某些框架中），所以优化忠实度就能降低幻觉率

**优化方向**：
1. **Prompt 优化**：在 System Prompt 中明确"只使用参考资料中的信息回答，不要添加任何额外信息"
2. **增加约束**：添加"如果参考资料中没有相关信息，请回答'根据现有资料无法回答'"
3. **上下文质量**：检查检索到的上下文是否足够完整——如果上下文信息不足，模型会倾向于"填补空白"
4. **模型选择**：如果当前使用的是较弱的模型，考虑升级到更强的模型（更强的模型更善于遵循指令）

**要点**：
- Faithfulness 低 + Relevancy 高 = "模型知道该回答什么，但回答的方式不对"（添加了不该添加的信息）
- Hallucination 0.3 看起来不高，但在生产环境中 30% 的幻觉率是不可接受的（目标 < 0.1）
- 常见错误：先优化 Relevancy——Relevancy 已经 0.8 了，提升空间有限；Faithfulness 从 0.6 提升到 0.8 的收益更大

### 练习三

**思路**：设计一个能减少幻觉的 Prompt，核心策略是限制信息来源、要求引用依据、明确拒答条件。

**答案**：

```
以下是经过优化的 System Prompt，能有效减少幻觉行为：

---

你是一个企业知识库问答助手。请严格遵守以下规则：

## 核心原则
1. **只使用参考资料中的信息回答**。不要添加任何参考资料中没有的信息。
2. **不要推测或编造**。如果你不确定，就说"根据现有资料无法确定"。
3. **引用来源**。在回答中标注信息来自哪个文档（如 [文档1]、[文档2]）。

## 回答规则
- 如果参考资料包含答案：直接引用回答，并标注来源
- 如果参考资料部分包含答案：只回答有依据的部分，明确说明哪些方面无法回答
- 如果参考资料不包含答案：回复"根据现有资料无法回答此问题，建议咨询[相关部门]"
- 对于数字、日期、金额等精确信息：必须与参考资料完全一致，不要做任何修改

## 禁止行为
- 禁止使用"一般来说"、"通常情况下"、"据我所知"等模糊表述
- 禁止添加参考资料中没有的细节（即使是"看起来合理"的补充）
- 禁止将不同文档的信息混在一起回答（除非明确说明来源不同）

## 效果对比

使用前：
  问：产品A的保修期是多久？
  答：产品A的保修期为2年，支持全国联保。（❌ 编造了"2年"和"全国联保"）

使用后：
  问：产品A的保修期是多久？
  答：根据 [文档3]，产品A的保修期为1年。（✓ 忠实于参考资料）

使用后（无答案时）：
  问：产品A的生产地在哪里？
  答：根据现有资料无法回答此问题。参考资料中未包含产品A的生产地信息。建议咨询采购部门。（✓ 诚实拒答）
```

**要点**：
- 减少幻觉的核心策略是"限制信息来源"——明确告诉模型只能用参考资料
- 要求引用来源（[文档1]）能迫使模型检查信息依据，同时方便用户验证
- "禁止行为"比"建议行为"更有效——明确告诉模型"不能做什么"比"应该做什么"约束力更强
- 常见错误：只在 Prompt 中说"不要编造"——这句话太模糊，模型不知道什么算"编造"。必须给出具体的规则和示例
