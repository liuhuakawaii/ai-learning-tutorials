# 05 端到端评估——从用户提问到最终回答的全链路质量度量

> 分指标告诉你"哪里有问题"，端到端评估告诉你"用户满不满意"。

## 场景引入

你的 RAG 系统各项分指标都不错——检索精确率 0.85，忠实度 0.9，但用户留存率却在下降。深入分析后你发现，系统响应延迟高达 8 秒，且生成的回答冗长啰嗦，用户根本没耐心看完。分指标评估只覆盖了"质量"维度，而用户体验是质量、延迟、成本、表达方式的综合体现，需要端到端的评估视角。

## 学习目标

- 掌握端到端评估的设计方法
- 学会结合用户反馈进行评估
- 理解端到端评估与分指标评估的关系

## 一、端到端评估的设计

### 1.1 评估维度

```python
class E2EEvaluator:
    """端到端评估器"""
    
    def __init__(self, client):
        self.client = client
    
    def evaluate(
        self,
        question: str,
        answer: str,
        contexts: list[str],
        latency: float,
        token_count: int
    ) -> dict:
        """端到端评估"""
        
        # 1. 回答质量（综合评估）
        quality_prompt = f"""从用户视角评估以下回答的整体质量。

问题：{question}
回答：{answer}

评估标准：
- 是否解决了用户的问题？
- 回答是否准确、完整、易懂？
- 如果你是用户，满意吗？

请以 JSON 格式输出：
{{"user_satisfaction": <1-5>, "solves_problem": <true/false>, "reasoning": "理由"}}"""

        response = self.client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": quality_prompt}],
            temperature=0,
            response_format={"type": "json_object"}
        )
        quality = json.loads(response.choices[0].message.content)
        
        # 2. 效率评分
        efficiency_score = 1.0
        if latency > 5.0:
            efficiency_score *= 0.5
        if token_count > 10000:
            efficiency_score *= 0.8
        
        # 3. 综合评分
        overall = (
            quality["user_satisfaction"] / 5.0 * 0.6 +
            (1.0 if quality["solves_problem"] else 0.3) * 0.3 +
            efficiency_score * 0.1
        )
        
        return {
            "quality": quality,
            "efficiency": {
                "latency": latency,
                "token_count": token_count,
                "score": efficiency_score
            },
            "overall_score": overall
        }
```

## 三、综合评估报告

```python
def generate_e2e_report(
    eval_results: list[dict],
    feedback_stats: dict
) -> str:
    """生成端到端评估报告"""
    
    report = "# 端到端评估报告\n\n"
    
    # 质量统计
    avg_satisfaction = sum(r["quality"]["user_satisfaction"] for r in eval_results) / len(eval_results)
    solve_rate = sum(1 for r in eval_results if r["quality"]["solves_problem"]) / len(eval_results)
    
    report += "## 质量指标\n\n"
    report += f"- 平均用户满意度：{avg_satisfaction:.2f}/5.0\n"
    report += f"- 问题解决率：{solve_rate:.1%}\n"
    
    # 效率统计
    avg_latency = sum(r["efficiency"]["latency"] for r in eval_results) / len(eval_results)
    avg_tokens = sum(r["efficiency"]["token_count"] for r in eval_results) / len(eval_results)
    
    report += "\n## 效率指标\n\n"
    report += f"- 平均延迟：{avg_latency:.2f}s\n"
    report += f"- 平均 Token 消耗：{avg_tokens:.0f}\n"
    
    # 用户反馈
    if feedback_stats:
        report += "\n## 用户反馈\n\n"
        report += f"- 反馈总数：{feedback_stats['total_feedback']}\n"
        report += f"- 平均评分：{feedback_stats['avg_rating']:.2f}\n"
        report += f"- 好评率：{feedback_stats['positive_rate']:.1%}\n"
    
    return report
```

## 常见误区

1. **用 LLM 模拟用户满意度替代真实反馈**：LLM 评估的"用户满意度"和真实用户感受差距很大。自动评估只能作为参考，不能替代真实用户反馈。

2. **忽略延迟和成本的权衡**：追求高质量回答而使用最强模型，导致延迟 10 秒以上、单次调用成本超 1 元——用户等不了，公司也亏不起。

3. **只收集正面反馈**：很多系统只展示"点赞"按钮，没有"踩"的入口，导致反馈数据严重偏斜，无法发现真实问题。

4. **反馈分析只看数量不看内容**：100 条负面反馈可能集中在同一类问题上，但不做文本聚类分析就发现不了。

## 工程建议

1. **设计分层反馈机制**：简单的 👍/👎 降低用户参与门槛，可选的文字反馈框收集具体问题，定期用户访谈挖掘深层需求。

2. **建立延迟-质量的帕累托曲线**：测试不同模型和参数组合，找到"质量可接受、延迟最低"的最优配置。

3. **每周生成综合评估报告**：包含自动评估指标、用户反馈统计、低分案例 Top 5，发给产品和研发团队。

4. **对负面反馈做自动分类**：用 LLM 把负面反馈归类为"幻觉""不完整""不相关""延迟高"等类型，量化各类问题的占比。

### 练习一

**思路**：端到端评估方案需要覆盖自动评估（LLM-as-Judge）和用户反馈（显式+隐式）两个层面，同时考虑质量、效率、成本三个维度。

**答案**：

```
端到端评估方案设计：

一、自动评估层（每次代码变更触发）
├── 质量评估
│   ├── Faithfulness（忠实度）≥ 0.8
│   ├── Answer Relevancy（相关性）≥ 0.7
│   └── Hallucination Rate（幻觉率）≤ 0.1
├── 效率评估
│   ├── 平均延迟 ≤ 3 秒
│   ├── P95 延迟 ≤ 5 秒
│   └── 平均 Token 消耗 ≤ 3000
└── 安全评估
    ├── 安全性检查通过率 = 100%
    └── 提示注入抵抗通过率 = 100%

二、用户反馈层（线上持续收集）
├── 显式反馈
│   ├── 👍/👎 按钮（每次回答后展示）
│   └── 文字反馈框（可选，负面时引导填写）
├── 隐式反馈
│   ├── 用户是否采纳了回答（复制/点击链接）
│   ├── 用户是否重新提问（说明第一次没解决）
│   ├── 用户是否切换到人工客服（说明 AI 失败）
│   └── 会话时长（过长可能说明回答不清晰）
└── 定期调研
    ├── 每月 NPS 评分
    └── 每季度深度用户访谈（5-10 人）

三、评估报告（每周生成）
├── 自动评估趋势图（各指标本周 vs 上周）
├── 用户反馈统计（好评率、常见问题分类）
├── 低分案例 Top 5（附问题、回答、原因分析）
└── 优化建议（基于数据的具体改进方向）
```

**要点**：
- 自动评估是"底线保障"，用户反馈是"真实体验"——两者缺一不可
- 隐式反馈比显式反馈更客观——用户点👍👎有偏差，但"重新提问"和"切换人工"是真实行为
- 常见错误：只做自动评估不做用户反馈——自动评估分数很高但用户留存率下降，说明评估指标和用户需求脱节

### 练习二

**思路**：实现一个 FeedbackCollector，支持收集显式反馈（评分+评论）、统计分析（好评率、常见问题）、以及用 LLM 对负面反馈做自动分类。

**答案**：

```python
from datetime import datetime
from collections import Counter
import json

class FeedbackCollector:
    """用户反馈收集与分析器"""

    def __init__(self):
        self.feedback_data = []

    def add_feedback(
        self,
        session_id: str,
        question: str,
        answer: str,
        rating: int,
        feedback_type: str,
        comment: str = "",
        metadata: dict = None
    ):
        """添加用户反馈

        Args:
            rating: 1-5 评分
            feedback_type: "positive" / "negative" / "neutral"
            comment: 用户文字反馈
        """
        self.feedback_data.append({
            "session_id": session_id,
            "question": question,
            "answer": answer,
            "rating": rating,
            "feedback_type": feedback_type,
            "comment": comment,
            "metadata": metadata or {},
            "timestamp": datetime.now().isoformat()
        })

    def add_implicit_feedback(
        self,
        session_id: str,
        question: str,
        answer: str,
        action: str
    ):
        """添加隐式反馈

        Args:
            action: "adopted" / "reasked" / "escalated" / "abandoned"
        """
        self.feedback_data.append({
            "session_id": session_id,
            "question": question,
            "answer": answer,
            "feedback_type": "implicit",
            "action": action,
            "timestamp": datetime.now().isoformat()
        })

    def analyze(self) -> dict:
        """分析反馈数据"""
        if not self.feedback_data:
            return {"error": "无反馈数据"}

        df = pd.DataFrame(self.feedback_data)

        # 显式反馈统计
        explicit = df[df["feedback_type"].isin(["positive", "negative", "neutral"])]
        stats = {
            "total_feedback": len(df),
            "explicit_count": len(explicit),
            "avg_rating": explicit["rating"].mean() if not explicit.empty else 0,
            "positive_rate": len(explicit[explicit["feedback_type"] == "positive"]) / len(explicit) if not explicit.empty else 0,
            "negative_rate": len(explicit[explicit["feedback_type"] == "negative"]) / len(explicit) if not explicit.empty else 0,
        }

        # 隐式反馈统计
        implicit = df[df["feedback_type"] == "implicit"]
        if not implicit.empty:
            action_counts = implicit["action"].value_counts().to_dict()
            stats["implicit_actions"] = action_counts
            stats["escalation_rate"] = action_counts.get("escalated", 0) / len(implicit)

        # 负面反馈分类
        negative = explicit[explicit["feedback_type"] == "negative"]
        if not negative.empty and negative["comment"].any():
            stats["issue_categories"] = self._classify_issues(negative)

        return stats

    def _classify_issues(self, negative_df) -> dict:
        """用 LLM 对负面反馈做自动分类"""
        comments = negative_df["comment"].dropna().tolist()
        if not comments:
            return {}

        comments_text = "\n".join(f"- {c}" for c in comments[:20])

        prompt = f"""请将以下负面反馈归类。

反馈列表：
{comments_text}

分类标准：
- hallucination: 幻觉/编造信息
- incomplete: 回答不完整
- irrelevant: 回答不相关
- slow: 响应太慢
- unclear: 表述不清晰
- other: 其他

输出 JSON：{{"categories": {{"hallucination": 数量, "incomplete": 数量, ...}}, "top_issues": ["最严重的问题"]}}"""

        from openai import OpenAI
        client = OpenAI()
        response = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": prompt}],
            temperature=0,
            response_format={"type": "json_object"}
        )
        return json.loads(response.choices[0].message.content)

    def get_low_score_cases(self, limit: int = 5) -> list[dict]:
        """获取最低分的案例"""
        explicit = [f for f in self.feedback_data
                    if f.get("feedback_type") in ["positive", "negative", "neutral"]]
        sorted_by_rating = sorted(explicit, key=lambda x: x.get("rating", 5))
        return sorted_by_rating[:limit]

    def export(self, path: str):
        """导出反馈数据"""
        with open(path, "w", encoding="utf-8") as f:
            json.dump(self.feedback_data, f, ensure_ascii=False, indent=2)
        print(f"已导出 {len(self.feedback_data)} 条反馈到 {path}")
```

**要点**：
- 隐式反馈（重新提问、切换人工）比显式反馈更客观，应优先收集
- 负面反馈的文字评论是最有价值的——用 LLM 做自动分类能量化各类问题的占比
- 常见错误：只统计"好评率"不分析"差评内容"——100 条好评和 10 条差评，差评里可能藏着最关键的改进方向

def generate_e2e_report(
    auto_eval_results: list[dict],
    feedback_stats: dict,
    report_period: str = "2024-W25"
) -> str:
    """生成端到端评估报告"""

    report = f"""# RAG 系统端到端评估报告

**报告周期**：{report_period}
**评估样本量**：{len(auto_eval_results)} 条（自动评估）| {feedback_stats.get('total_feedback', 0)} 条（用户反馈）

---

## 一、质量指标

| 指标 | 本周均值 | 上周均值 | 变化 | 状态 |
|------|---------|---------|------|------|
"""

    # 计算自动评估统计
    import numpy as np
    faith_scores = [r["faithfulness"]["score"] for r in auto_eval_results]
    relev_scores = [r["relevancy"]["score"] for r in auto_eval_results]
    halluc_scores = [r["hallucination"]["score"] for r in auto_eval_results]

    metrics = [
        ("Faithfulness", np.mean(faith_scores), 0.8, "≥"),
        ("Answer Relevancy", np.mean(relev_scores), 0.7, "≥"),
        ("Hallucination Rate", np.mean(halluc_scores), 0.1, "≤"),
    ]

    for name, value, threshold, op in metrics:
        if op == "≥":
            status = "✅" if value >= threshold else "❌"
        else:
            status = "✅" if value <= threshold else "❌"
        report += f"| {name} | {value:.3f} | - | - | {status} |\n"

    report += f"""
### 质量诊断

- **Faithfulness 分布**：最低 {min(faith_scores):.3f}，最高 {max(faith_scores):.3f}，标准差 {np.std(faith_scores):.3f}
- **低分案例数**（Faithfulness < 0.6）：{sum(1 for s in faith_scores if s < 0.6)} 条

---

## 二、效率指标

| 指标 | 本周均值 | 目标 | 状态 |
|------|---------|------|------|
"""

    latencies = [r.get("latency", 0) for r in auto_eval_results]
    tokens = [r.get("token_count", 0) for r in auto_eval_results]

    avg_latency = np.mean(latencies) if latencies else 0
    avg_tokens = np.mean(tokens) if tokens else 0

    report += f"| 平均延迟 | {avg_latency:.2f}s | ≤ 3s | {'✅' if avg_latency <= 3 else '❌'} |\n"
    report += f"| P95 延迟 | {np.percentile(latencies, 95):.2f}s | ≤ 5s | {'✅' if np.percentile(latencies, 95) <= 5 else '❌'} |\n"
    report += f"| 平均 Token | {avg_tokens:.0f} | ≤ 3000 | {'✅' if avg_tokens <= 3000 else '❌'} |\n"

    report += f"""
---

## 三、用户反馈

| 指标 | 值 |
|------|-----|
| 反馈总数 | {feedback_stats.get('total_feedback', 0)} |
| 平均评分 | {feedback_stats.get('avg_rating', 0):.2f}/5.0 |
| 好评率 | {feedback_stats.get('positive_rate', 0):.1%} |
| 差评率 | {feedback_stats.get('negative_rate', 0):.1%} |
"""

    if "escalation_rate" in feedback_stats:
        report += f"| 转人工率 | {feedback_stats['escalation_rate']:.1%} |\n"

    if "issue_categories" in feedback_stats:
        report += "\n### 差评分类\n\n"
        cats = feedback_stats["issue_categories"].get("categories", {})
        for issue, count in sorted(cats.items(), key=lambda x: -x[1]):
            report += f"- **{issue}**：{count} 条\n"

    report += f"""
---

## 四、低分案例 Top 5

| # | 问题 | Faithfulness | 问题类型 |
|---|------|-------------|---------|
"""

    sorted_cases = sorted(auto_eval_results, key=lambda x: x["faithfulness"]["score"])
    for i, case in enumerate(sorted_cases[:5], 1):
        q = case["question"][:40] + "..."
        f = case["faithfulness"]["score"]
        report += f"| {i} | {q} | {f:.3f} | - |\n"

    report += """
---

## 五、优化建议

基于本周评估数据，建议优先处理以下问题：

1. **[高优先级]** 提升 Faithfulness：在 Prompt 中强化"只使用参考资料回答"的约束
2. **[中优先级]** 优化延迟：检查是否有不必要的 LLM 调用或过长的上下文
3. **[持续监控]** 收集更多用户反馈，验证自动评估与用户感知的一致性
"""

    return report
