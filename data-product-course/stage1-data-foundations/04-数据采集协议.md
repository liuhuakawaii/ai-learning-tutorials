## 三、全量采集 vs 增量采集

### 3.1 全量采集

```
┌──────────────────────────────────────────────────────────────┐
│                    全量采集                                    │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  定义：每次都采集所有数据                                     │
│                                                              │
│  优点：                                                       │
│  ├── 实现简单                                                │
│  ├── 数据完整性有保障                                        │
│  └── 不需要记录状态                                          │
│                                                              │
│  缺点：                                                       │
│  ├── 数据量大时耗时长                                        │
│  ├── 重复采集浪费资源                                        │
│  └── 对目标网站压力大                                        │
│                                                              │
│  适用场景：                                                   │
│  ├── 数据量小（< 1000 条）                                   │
│  ├── 数据变化频繁                                            │
│  ├── 无法判断哪些是新增                                      │
│  └── 首次采集                                                │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

**全量采集代码示例：**

```python
def full_crawl():
    """全量采集"""
    all_data = []
    page = 1
    
    while True:
        data = fetch_page(page)
        if not data:
            break
        all_data.extend(data)
        page += 1
    
    # 清空旧数据，写入新数据
    save_to_database(all_data, mode="replace")
    return len(all_data)
```

```
┌──────────────────────────────────────────────────────────────┐
│                    增量采集                                    │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  定义：只采集新增或变化的数据                                 │
│                                                              │
│  优点：                                                       │
│  ├── 数据量小，速度快                                        │
│  ├── 资源消耗少                                              │
│  └── 对目标网站压力小                                        │
│                                                              │
│  缺点：                                                       │
│  ├── 需要记录采集状态                                        │
│  ├── 可能遗漏数据                                            │
│  └── 实现复杂                                                │
│                                                              │
│  适用场景：                                                   │
│  ├── 数据量大（> 1000 条）                                   │
│  ├── 数据更新频率低                                          │
│  ├── 有明确的增量标识                                        │
│  └── 日常采集                                                │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

**增量采集代码示例：**

```python
from datetime import datetime, timedelta

def incremental_crawl():
    """增量采集：只采集最近更新的数据"""
    # 获取上次采集时间
    last_crawl_time = get_last_crawl_time("jobs")
    
    # 只采集新增数据
    new_data = fetch_data_since(last_crawl_time)
    
    if new_data:
        # 追加到数据库，不去重
        save_to_database(new_data, mode="append")
        update_last_crawl_time("jobs", datetime.now())
    
    return len(new_data)
```

## 四、失败重试机制

### 4.1 为什么需要重试？

```
常见失败原因：
├── 网络波动（临时连接超时）
├── 目标网站限流（返回 429）
├── 服务器临时错误（返回 500）
└── 并发过高（请求被拒绝）

这些问题通常是临时的，重试后可能成功。
```

### 4.2 重试策略设计

```
┌──────────────────────────────────────────────────────────────┐
│                    重试策略                                    │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  固定间隔重试                                                 │
│  ├── 每次重试间隔相同（如 5 秒）                             │
│  ├── 简单但可能造成请求堆积                                  │
│  └── 适用：网络波动                                         │
│                                                              │
│  指数退避重试                                                 │
│  ├── 每次重试间隔翻倍（1s → 2s → 4s → 8s）                 │
│  ├── 避免请求堆积                                            │
│  └── 适用：限流场景                                         │
│                                                              │
│  最大重试次数                                                 │
│  ├── 设置最大重试次数（如 3 次）                             │
│  ├── 超过次数后记录失败                                      │
│  └── 避免无限重试                                           │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 4.3 重试代码实现

```python
import time
import requests
from functools import wraps

def retry_with_backoff(max_retries=3, base_delay=1):
    """指数退避重试装饰器"""
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(max_retries):
                try:
                    return func(*args, **kwargs)
                except requests.RequestException as e:
                    if attempt == max_retries - 1:
                        raise e
                    
                    delay = base_delay * (2 ** attempt)
                    print(f"请求失败，{delay}秒后重试: {e}")
                    time.sleep(delay)
            
            return None
        return wrapper
    return decorator

@retry_with_backoff(max_retries=3, base_delay=2)
def fetch_page(url: str) -> dict:
    """带重试的请求"""
    response = requests.get(url, timeout=10)
    response.raise_for_status()
    return response.json()
```

```

│                    不同错误的处理                              │

│                                                              │
```

## 五、采集策略配置

### 5.1 并发控制

```python
import asyncio
import aiohttp
from asyncio import Semaphore

# 并发控制配置
MAX_CONCURRENT = 5  # 最大并发数
REQUEST_DELAY = 1   # 请求间隔（秒）

async def fetch_with_limit(url: str, sem: Semaphore):
    """带并发限制的请求"""
    async with sem:
        await asyncio.sleep(REQUEST_DELAY)
        async with aiohttp.ClientSession() as session:
            async with session.get(url) as response:
                return await response.json()

async def batch_fetch(urls: list):
    """批量请求"""
    sem = Semaphore(MAX_CONCURRENT)
    tasks = [fetch_with_limit(url, sem) for url in urls]
    return await asyncio.gather(*tasks, return_exceptions=True)
```

## 六、数据校验

### 6.1 采集后校验

```python
def validate_crawled_data(data: list) -> dict:
    """校验采集数据"""
    result = {
        "total": len(data),
        "valid": 0,
        "invalid": 0,
        "errors": []
    }
    
    for i, item in enumerate(data):
        try:
            # 检查必填字段
            assert "id" in item, "缺少 id 字段"
            assert "title" in item, "缺少 title 字段"
            
            # 检查数据类型
            assert isinstance(item["id"], (int, str)), "id 类型错误"
            
            # 检查数据范围
            if "price" in item:
                assert item["price"] >= 0, "价格不能为负"
            
            result["valid"] += 1
            
        except AssertionError as e:
            result["invalid"] += 1
            result["errors"].append({
                "index": i,
                "error": str(e),
                "data": item
            })
    
    return result
```

### 6.2 数据完整性检查

```python
def check_data_completeness(crawled_count: int, expected_count: int) -> dict:
    """检查数据完整性"""
    completeness = crawled_count / expected_count if expected_count > 0 else 0
    
    return {
        "crawled": crawled_count,
        "expected": expected_count,
        "completeness": f"{completeness:.2%}",
        "is_complete": completeness >= 0.95,  # 95% 以上认为完整
        "status": "OK" if completeness >= 0.95 else "WARNING"
    }
```

## 小结

本课的核心要点：

1. **采集协议**是数据采集的规范，包含频率、策略、重试、校验等
2. **频率设计**要考虑数据更新频率、业务需求、资源限制
3. **增量采集**比全量采集更高效，但需要记录状态
4. **重试机制**用指数退避，区分可重试和不可重试错误
5. **数据校验**在采集后立即进行，确保数据质量
