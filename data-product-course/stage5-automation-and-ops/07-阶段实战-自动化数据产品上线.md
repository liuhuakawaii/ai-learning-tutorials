## 二、自动化流程

```python
# scheduler.py
from apscheduler.schedulers.background import BackgroundScheduler

scheduler = BackgroundScheduler()

# 每天早上 8 点执行 ETL
@scheduler.scheduled_job('cron', hour=8, minute=0)
def daily_etl():
    """每日 ETL 任务"""
    pipeline.run()
    check_quality()
    aggregate_metrics()

# 每小时增量更新
@scheduler.scheduled_job('interval', hours=1)
def hourly_update():
    """每小时增量更新"""
    incremental_crawl()

scheduler.start()
```

## 常见误区

- **一步到位上生产**：把所有模块一次性部署到生产环境，出问题后不知道是哪个环节的问题。应该分阶段上线：先跑通 ETL，再加定时调度，最后加告警和权限。
- **只看功能不看可观测性**：系统能跑不等于系统健康。没有监控面板、没有日志收集、没有告警，出了问题只能靠用户反馈才知道。
- **忽略部署回滚方案**：部署新版本后发现有 bug，如果没有回滚方案就只能手动修复。Docker 镜像天然支持版本回退，一定要保留上一个稳定版本的镜像。
- **验收标准模糊**："系统能跑"不是验收标准。必须定义具体指标：任务成功率、数据新鲜度、告警响应时间等。

## 工程建议

1. **部署前跑一遍验收清单**：对照验收标准逐项检查，确认任务状态流转、失败重试、告警通知、手动触发等功能都正常后再上线。
2. **保留数据库备份再部署**：每次部署前执行一次 `pg_dump`，万一部署出问题可以快速恢复数据。
3. **监控面板放在首页**：把系统状态、任务概览、最近告警放在 Dashboard 首页，每天打开就能看到系统是否健康。
4. **写一份运维手册**：记录常见问题的排查步骤（如任务卡住怎么处理、数据库满了怎么清理），让不熟悉系统的人也能应急处理。
