你的数据查询 API 上线后，用户反馈"翻到第 10 页以后越来越慢"。你打开数据库监控，发现一个简单的分页查询居然扫描了 50 万行数据，耗时超过 3 秒。问题出在哪里？OFFSET 分页在深分页时会扫描并丢弃大量行，而你的索引设计也没有针对分页查询优化。你需要深入理解索引原理和分页方案，才能解决这个性能瓶颈。

## 一、索引深入

### 1.1 索引类型

```
┌──────────────────────────────────────────────────────────────┐
│                    PostgreSQL 索引类型                         │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  B-tree（默认）                                               │
│  ├── 最常用的索引类型                                        │
│  ├── 支持 =, <, >, <=, >=, BETWEEN, IN                       │
│  └── 适用：大多数查询场景                                    │
│                                                              │
│  Hash                                                          │
│  ├── 只支持等值查询 =                                        │
│  ├── 比 B-tree 更快（等值查询）                              │
│  └── 适用：精确匹配                                          │
│                                                              │
│  GiST（通用搜索树）                                           │
│  ├── 支持几何数据、全文搜索                                  │
│  └── 适用：空间数据、文本搜索                                │
│                                                              │
│  GIN（倒排索引）                                              │
│  ├── 支持数组、JSONB、全文搜索                               │
│  └── 适用：JSON 查询、数组包含                               │
│                                                              │
│  BRIN（块范围索引）                                           │
│  ├── 适合大表、数据有序                                      │
│  └── 适用：时间序列数据                                      │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 1.2 索引使用示例

```sql
-- B-tree 索引（默认）
CREATE INDEX idx_city ON clean_jobs(city);

-- GIN 索引（JSONB）
CREATE INDEX idx_raw_data ON raw_jobs USING GIN(raw_data);

-- 部分索引
CREATE INDEX idx_active_jobs ON clean_jobs(city) 
WHERE publish_date >= CURRENT_DATE - INTERVAL '30 days';

-- 覆盖索引（INCLUDE）
CREATE INDEX idx_city_salary ON clean_jobs(city) INCLUDE (salary_avg);

-- 表达式索引
CREATE INDEX idx_lower_city ON clean_jobs(LOWER(city));
```

### 1.3 查询计划分析

```sql
-- 使用 EXPLAIN 分析查询
EXPLAIN ANALYZE

WHERE city = '北京' AND salary_avg > 20000;
```

## 二、分页方案

### 2.1 常见分页方式

```
┌──────────────────────────────────────────────────────────────┐
│                    分页方式对比                                │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  OFFSET 分页                                                  │
│  ├── 语法：LIMIT n OFFSET m                                  │
│  ├── 优点：简单                                              │
│  ├── 缺点：深分页性能差                                      │
│  └── 适用：数据量小、页数少                                  │
│                                                              │
│  游标分页（Cursor）                                           │
│  ├── 语法：WHERE id > last_id LIMIT n                        │
│  ├── 优点：性能稳定                                          │
│  ├── 缺点：不能跳页                                          │
│  └── 适用：无限滚动、数据量大                                │
│                                                              │
│  键集分页（Keyset）                                           │
│  ├── 语法：WHERE (date, id) > (last_date, last_id)           │
│  ├── 优点：性能好、可排序                                    │
│  ├── 缺点：实现复杂                                          │
│  └── 适用：复杂排序场景                                      │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 分页实现

```python
from typing import List, Dict, Any, Optional
from sqlalchemy import create_engine, text

class Paginator:
    """分页器"""
    
    def __init__(self, engine):
        self.engine = engine
    
    def offset_paginate(
        self,
        table: str,
        page: int = 1,
        page_size: int = 20,
        where: str = "",
        order_by: str = "id"
    ) -> Dict[str, Any]:
        """OFFSET 分页"""
        
        offset = (page - 1) * page_size
        
        # 查询总数
        count_sql = f"SELECT COUNT(*) FROM {table}"
        if where:
            count_sql += f" WHERE {where}"
        
        # 查询数据
        data_sql = f"SELECT * FROM {table}"
        if where:
            data_sql += f" WHERE {where}"
        data_sql += f" ORDER BY {order_by} LIMIT :limit OFFSET :offset"
        
        with self.engine.connect() as conn:
            total = conn.execute(text(count_sql)).scalar()
            data = conn.execute(text(data_sql), {
                "limit": page_size,
                "offset": offset
            }).fetchall()
        
        return {
            "data": [dict(row._mapping) for row in data],
            "total": total,
            "page": page,
            "page_size": page_size,
            "total_pages": (total + page_size - 1) // page_size
        }
    
    def cursor_paginate(
        self,
        table: str,
        cursor: Optional[int] = None,
        page_size: int = 20,
        where: str = "",
        order_by: str = "id"
    ) -> Dict[str, Any]:
        """游标分页"""
        
        sql = f"SELECT * FROM {table}"
        params = {"limit": page_size}
        
        conditions = []
        if where:
            conditions.append(where)
        
        if cursor is not None:
            conditions.append(f"{order_by} > :cursor")
            params["cursor"] = cursor
        
        if conditions:
            sql += " WHERE " + " AND ".join(conditions)
        
        sql += f" ORDER BY {order_by} LIMIT :limit"
        
        with self.engine.connect() as conn:
            data = conn.execute(text(sql), params).fetchall()
        
        records = [dict(row._mapping) for row in data]
        next_cursor = records[-1]["id"] if records else None
        
        return {
            "data": records,
            "next_cursor": next_cursor,
            "has_more": len(records) == page_size
        }
```

## 三、查询优化

### 3.1 常见慢查询原因

```
┌──────────────────────────────────────────────────────────────┐
│                    常见慢查询原因                              │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  1. 缺少索引                                                  │
│     └── 全表扫描                                             │
│                                                              │
│  2. 索引失效                                                  │
│     ├── 对索引列使用函数                                     │
│     ├── 隐式类型转换                                         │
│     └── LIKE '%xxx'                                          │
│                                                              │
│  3. 返回数据过多                                              │
│     └── SELECT * 而不是需要的列                              │
│                                                              │
│  4. 子查询效率低                                              │
│     └── 可以改用 JOIN                                        │
│                                                              │
│  5. 排序和分组                                                │
│     └── 没有索引支持                                         │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 优化技巧

```sql
-- ❌ 索引失效
SELECT * FROM clean_jobs WHERE LOWER(city) = '北京';

-- ✅ 使用表达式索引
CREATE INDEX idx_lower_city ON clean_jobs(LOWER(city));
SELECT * FROM clean_jobs WHERE LOWER(city) = '北京';

-- ❌ 返回过多列
SELECT * FROM clean_jobs WHERE city = '北京';

-- ✅ 只返回需要的列
SELECT job_id, title, company, salary_avg FROM clean_jobs WHERE city = '北京';

-- ❌ 子查询
SELECT * FROM clean_jobs WHERE city IN (SELECT city FROM cities WHERE region = '华北');

-- ✅ JOIN
SELECT j.* FROM clean_jobs j JOIN cities c ON j.city = c.city WHERE c.region = '华北';

-- ❌ LIKE '%xxx'
SELECT * FROM clean_jobs WHERE title LIKE '%前端%';

-- ✅ 全文搜索
SELECT * FROM clean_jobs WHERE to_tsvector('chinese', title) @@ to_tsquery('前端');
```

## 四、查询缓存

### 4.1 缓存策略

```python
import redis
import json
from typing import Optional, Any
from datetime import timedelta

class QueryCache:
    """查询缓存"""
    
    def __init__(self, redis_url: str = "redis://localhost:6379"):
        self.redis = redis.from_url(redis_url)
        self.default_ttl = timedelta(minutes=5)
    
    def get(self, key: str) -> Optional[Any]:
        """获取缓存"""
        data = self.redis.get(key)
        if data:
            return json.loads(data)
        return None
    
    def set(self, key: str, value: Any, ttl: timedelta = None):
        """设置缓存"""
        ttl = ttl or self.default_ttl
        self.redis.setex(key, ttl, json.dumps(value, ensure_ascii=False))
    
    def delete(self, pattern: str):
        """删除缓存"""
        keys = self.redis.keys(pattern)
        if keys:
            self.redis.delete(*keys)
    
    def generate_key(self, query: str, params: dict) -> str:
        """生成缓存键"""
        import hashlib
        content = f"{query}:{json.dumps(params, sort_keys=True)}"
        return f"query:{hashlib.md5(content.encode()).hexdigest()}"
```

### 4.2 带缓存的查询

```python
class CachedQuery:
    """带缓存的查询"""
    
    def __init__(self, engine, cache: QueryCache):
        self.engine = engine
        self.cache = cache
    
    def query_with_cache(
        self,
        sql: str,
        params: dict = None,
        ttl: timedelta = None
    ) -> Any:
        """带缓存的查询"""
        
        # 生成缓存键
        cache_key = self.cache.generate_key(sql, params or {})
        
        # 尝试从缓存获取
        cached = self.cache.get(cache_key)
        if cached is not None:
            return cached
        
        # 执行查询
        with self.engine.connect() as conn:
            result = conn.execute(text(sql), params or {})
            data = [dict(row._mapping) for row in result.fetchall()]
        
        # 写入缓存
        self.cache.set(cache_key, data, ttl)
        
        return data
```

## 常见误区

- **给每个字段都建索引就能提升性能**：索引会占用存储空间并降低写入性能，应该只为高频查询字段建索引，定期清理未使用的索引
- **OFFSET 分页适用于所有场景**：OFFSET 在深分页时性能急剧下降（如 OFFSET 100000 需要扫描前 10 万行），大数据量场景应使用游标分页
- **EXPLAIN 显示用了索引就一定快**：索引可能只过滤了部分数据，剩余行仍需回表过滤，要关注 "Rows Removed by Filter" 指标
- **查询缓存可以替代索引优化**：缓存只能缓解热点查询的性能，根本问题还是要通过索引和查询优化来解决

---

## 工程建议

- 使用 EXPLAIN ANALYZE 分析慢查询，重点关注 Seq Scan（全表扫描）和高 Filter 行数，这是索引缺失的信号
- 对于 Dashboard 等高频查询，优先使用游标分页（WHERE id > last_id），性能稳定在 O(log n)，不受页码影响
- 组合索引遵循最左前缀原则，将选择性高的列放在前面（如 city 比 gender 选择性更高）
- 配置 PostgreSQL 的 log_min_duration_statement 参数，自动记录超过阈值的慢查询，便于持续优化
