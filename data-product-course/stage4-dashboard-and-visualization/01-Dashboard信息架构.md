# 第1课：Dashboard 信息架构

> **课程定位**：设计 Dashboard 的整体结构和信息层次
> **前置知识**：第三阶段全部课程
> **预计时长**：45 分钟

---

## 场景引入

你刚接手一个招聘数据分析平台，产品经理丢过来一句话："老板想看个 Dashboard，一眼就能看到整体情况。"你打开竞品一看，满屏的图表堆在一起，指标卡、折线图、饼图、表格混杂排列，看了五分钟还是不知道该先看什么。这时候你意识到，问题不在图表本身，而在于信息架构——哪些信息放首页、哪些放二级页面、用户打开页面的第一秒应该看到什么，这些才是 Dashboard 设计的核心。

---

1. 理解 Dashboard 的设计原则

## 一、Dashboard 设计原则

### 1.1 核心原则

```
┌──────────────────────────────────────────────────────────────┐
│                    Dashboard 设计原则                          │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  1. 信息层次清晰                                              │
│     ├── 核心指标放在最显眼的位置                             │
│     ├── 次要信息放在下方或次级页面                           │
│     └── 详情信息通过交互展开                                 │
│                                                              │
│  2. 一屏一主题                                                │
│     ├── 每个页面聚焦一个分析主题                             │
│     ├── 避免信息过载                                         │
│     └── 用户能快速找到所需信息                               │
│                                                              │
│  3. 数据可操作                                                │
│     ├── 图表支持筛选                                         │
│     ├── 数据支持导出                                         │
│     └── 异常支持告警                                         │
│                                                              │
│  4. 响应式设计                                                │
│     ├── 适配不同屏幕尺寸                                     │
│     └── 移动端友好                                           │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## 三、布局方案

### 3.1 栅格布局

```tsx
// 12 列栅格系统
<div className="grid grid-cols-12 gap-4">
  {/* 指标卡：一行 4 个 */}
  <div className="col-span-3">
    <MetricCard title="岗位总数" value="1,234" change="+5%" />
  </div>
  <div className="col-span-3">
    <MetricCard title="平均薪资" value="27,500" change="+2%" />
  </div>
  <div className="col-span-3">
    <MetricCard title="城市覆盖" value="32" change="+3" />
  </div>
  <div className="col-span-3">
    <MetricCard title="今日新增" value="156" change="-2%" />
  </div>
  
  {/* 趋势图：占 8 列 */}
  <div className="col-span-8">
    <LineChart title="岗位趋势" data={trendData} />
  </div>
  
  {/* 排名榜：占 4 列 */}
  <div className="col-span-4">
    <RankingList title="城市排名" data={cityRanking} />
  </div>
</div>
```

### 3.2 响应式布局

```tsx

// 平板：2 列
// 桌面：3-4 列

  <MetricCard />
  <MetricCard />
  <MetricCard />
  <MetricCard />
</div>
```

## 常见误区

- **把所有信息堆在一个页面**：总想让用户一眼看到所有数据，结果信息过载，用户反而什么都看不到。Dashboard 的核心是"分层"，不是"堆砌"。
- **忽略用户角色差异**：管理者和分析师的需求完全不同，用同一套信息架构服务所有人，结果谁都不满意。
- **先选图表再想结构**：看到竞品用了饼图就跟风用饼图，没有先想清楚这个页面要回答什么问题、用户最关心什么指标。
- **静态布局不考虑响应式**：在 27 寸显示器上设计得很好看，到了笔记本屏幕上全乱了。

---

## 工程建议

1. **用卡片分类法确定信息层次**：把所有指标写在便签上，让目标用户分组排序，根据排序结果决定哪些信息放首页、哪些放二级页面。
2. **首页指标卡控制在 4-6 个**：超过 6 个指标卡会让用户注意力分散，核心指标用最大字号和最显眼的位置。
3. **布局方案先画线框图再写代码**：用 Figma 或纸笔先把栅格布局画出来，确认信息密度合理后再用 Tailwind 栅格系统实现。
4. **URL 参数同步筛选状态**：筛选器的状态应该同步到 URL 参数中，这样用户刷新页面或分享链接时不会丢失筛选条件。
