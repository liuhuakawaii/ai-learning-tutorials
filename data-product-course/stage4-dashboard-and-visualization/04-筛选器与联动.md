## 常见误区

- **筛选器之间没有联动关系**：选了"北京市"之后，技能筛选器还显示全国的技能列表，用户选了一个不存在的组合，结果返回空数据。
- **每次筛选都触发全量请求**：改了一个筛选条件，所有图表都重新请求一遍 API，造成大量不必要的网络请求和页面闪烁。
- **筛选状态不持久化**：用户精心设置了一组筛选条件，切换页面后再回来，所有筛选都重置了，需要重新设置。
- **忽略防抖处理**：输入框筛选时每次按键都触发请求，造成大量无意义的 API 调用和页面抖动。

---

## 工程建议

1. **筛选器状态统一管理**：用 Context 或状态管理库维护筛选器状态，确保所有组件从同一个数据源读取筛选条件，避免状态不一致。
2. **关联筛选器要级联更新**：当父级筛选器（如城市）变化时，子级筛选器（如区域）应该自动清空或更新可选值，而不是保留无效选项。
3. **URL 参数同步筛选状态**：把筛选条件序列化到 URL query string 中，用户刷新页面或分享链接时能恢复筛选状态。
4. **文本输入筛选加 300ms 防抖**：搜索框输入时不要实时请求，等用户停止输入 300ms 后再触发请求，减少服务器压力。
